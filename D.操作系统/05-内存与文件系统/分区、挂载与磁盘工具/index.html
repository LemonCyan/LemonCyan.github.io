本篇讲一块新硬盘从插上机器到能被读写之间要做的全部动作：认盘、分区、格式化、挂载、写进 /etc/fstab。只讲终端里敲的那些命令和背后的取舍。内存布局看《C 程序的内存模型》，目录职能与 inode、软硬链接看《Linux 目录结构与 FHS 标准》，ext4 块组与一次 read 的路径看《文件系统类型与 IO 路径》，open/read/write 看《文件 IO 与描述符管理》。所有命令以 root 执行。设备名按 SATA 盘的 /dev/sdb 写，NVMe 盘换成 /dev/nvme0n1，分区加 p 后缀。

一、一块新硬盘要经历什么 #

盘插上去，内核先认设备，再读分区表。没有分区表就造一张，有了才有分区设备节点，分区上才谈得上建文件系统，建完才谈得上挂载。

bash
lsblk                                            # 1. 认盘，确认是 sdb 不是 sda
fdisk -l /dev/sdb                                # 2. 看分区表，空盘只报容量
parted /dev/sdb mklabel gpt                      # 3. 建分区表
parted /dev/sdb mkpart primary ext4 1MiB 100%    # 4. 切一个分区
partprobe /dev/sdb                               # 5. 让内核重读
mkfs.ext4 /dev/sdb1                              # 6. 建文件系统
mkdir -p /data1 && mount /dev/sdb1 /data1        # 7. 建挂载点并挂上
df -h /data1                                     # 8. 验收容量
blkid /dev/sdb1                                  # 9. 取 UUID，写 fstab 用

每一步都能毁掉下一步。分区表错了后续全废；mkfs 选错设备写掉的是别人的数据；fstab 写错重启进不去系统。分区与目录的关系四条：每个分区都要挂到目录树上的某个目录才能读写；目录是逻辑划分，分区是物理划分；根目录 / 自己也得挂一个分区；多个分区可以挂到同一棵树的任意位置，挂载点互不重叠。Windows 是几个盘符并列的几棵树，Linux 只有一棵。这是从 Windows 过来最容易卡住的地方：「D 盘满了」是硬件的事，「/var 满了」是文件系统的事，而 /var 在哪个盘上得看挂载点。

为什么要分区：

理由 说明 理由 说明
风险隔离 一个分区写满或坏掉，不牵连其他分区 快照与配额 LVM 快照、用户配额都按文件系统做
重装不动数据 重装 /，/home 挂回原分区即可 访问控制 /var、/tmp 单独挂载时能加 noexec、nosuid
检查代价 超大文件系统跑 fsck 很久，拆开省时间 多系统 分区是装第二个系统的前提

常被单独分出来的目录：

目录 理由 目录 理由
/boot 内核与 initrd，GRUB 要读到 /usr 只读的系统程序，可挂 ro
/home 用户数据，重装系统不动它 /tmp 挂 tmpfs 或独立分区，加 noexec,nosuid
/var 日志与数据库往上长，撑爆不该拖死 / swap 独立分区或 swap 文件，见第十章

二、识别磁盘：lsblk 与 fdisk -l #

插上盘别急着分区，先搞清楚内核给了它什么名字。

bash
$ lsblk
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda           8:0    0 465.8G  0 disk
├─sda1        8:1    0   512M  0 part /boot/efi
├─sda2        8:2    0     1G  0 part /boot
└─sda3        8:3    0 464.3G  0 part /
sdb           8:16   0   1.8T  0 disk
nvme0n1     259:0    0 931.5G  0 disk
└─nvme0n1p1 259:1    0 931.5G  0 part /data

七列怎么读：

列 含义 看什么
NAME 设备名 整盘无缩进，分区带 ├─/└─
MAJ:MIN 主次设备号 对应 /dev 下的设备节点

MOUNTPOINTS 挂载点 空着就是没挂

sdb 那行只有 disk，下面没有任何 part，这就是一块没分区的新盘。常用参数：

参数 作用 参数 作用

-o 自选列，如 -o NAME,SIZE,TYPE,FSTYPE -J 输出 JSON
-S 列 SCSI 设备，带 HCTL 号 -e 排除设备，如 -e 7 去掉 loop

查文件系统和 UUID，blkid 与 lsblk -f 等效，前者更快：

三、分区表：MBR 与 GPT #

分区表就是盘开头那张「哪块扇区到哪块扇区属于哪个分区」的账本。两种格式，选错白折腾。MBR 又叫 DOS 分区表、msdos。4 个表项，最多 4 个主分区。要更多，把一个主分区改成扩展分区，扩展分区内部再挂逻辑分区，编号从 5 开始。32 位扇区地址乘 512 字节，寻址上限 2 TiB。

text
偏移 0    446 字节   引导代码
偏移 446   64 字节   4 个分区表项，每项 16 字节
偏移 510    2 字节   签名 0x55AA

GPT 开头放一个保护性 MBR 占位，接着是 GPT 头，往后是分区项数组，盘尾还有一份完整备份。64 位 LBA 寻址，容量上限远不是 2 TiB 能比，每个分区带 GUID 类型、GUID 唯一标识和 UTF-16 分区名。

text
LBA 0       保护性 MBR（类型 0xEE，告诉老工具这盘被占了）
LBA 1       GPT 头：自身 CRC32、头大小、分区项数量与位置
LBA 2-33    128 个分区项 × 128 字节
LBA 34-...  第一个可用扇区起的分区数据
末尾 LBA     备份分区项数组 + 备份 GPT 头
维度 MBR（msdos） GPT
典型名字 dos、msdos gpt
占用空间 首扇区 512 字节 头 + 128 项 + 盘尾备份
主分区上限 4 个 128 个
扩展/逻辑分区 需要，逻辑编号从 5 起 不存在这回事
寻址 32 位 LBA，单盘上限 2 TiB 64 位 LBA
完整性校验 无 头和分区项各带 CRC32
损坏恢复 分区表一坏全丢 盘尾备份可救回
分区标识 1 字节类型码（83/82/8e…） 16 字节 GUID 类型
分区名 不支持 支持 UTF-16 名字
配合启动 BIOS + MBR UEFI + GPT，或 BIOS + GPT（需 bios_grub 分区）
适用 老机器、小盘、装机 U 盘 现在的默认选择

看盘上是哪种，parted print 的 Partition Table 直接给：

bash
# parted /dev/sdb print
Model: ATA ST2000DM008-2FR1 (scsi)
Disk /dev/sdb: 2000GB
Sector size (logical/physical): 512B/4096B
Partition Table: gpt
Disk Flags:

Number  Start   End     Size    File system  Name     Flags
 1      1049kB  2000GB  2000GB  ext4         primary

改分区表格式会清空旧表：parted /dev/sdb mklabel gpt 一敲，原有分区全部不可达。fdisk 交互界面里 g 建新 GPT、o 建新 MBR，同样把旧表扔掉。真要转换，先用 sgdisk --backup=/root/sdb-gpt.bak /dev/sdb 备份，转换失败再 --load-backup 灌回去。4K 对齐：物理扇区 4096 字节的盘，分区起点要落在 4096 的整数倍上，否则一次逻辑写跨两个物理扇区，写放大。现代工具默认从第 2048 扇区（1 MiB）起，天然对齐；老工具默认 63 扇区，那是不对齐的，手工 mkpart 时起点写 1MiB。GPT 在双系统里的额外要求：必须有 EFI 系统分区，类型 EF00、FAT32、300–500 MiB、挂 /boot/efi，否则 UEFI 固件找不到引导程序。

四、分区工具：fdisk 与 parted #

两把刀切不同的活。fdisk 交互式，一问一答；parted 支持一句话搞定，适合脚本和超过 2 TiB 的大盘。

bash
# fdisk /dev/sdb

Welcome to fdisk (util-linux 2.38.1).
Changes will remain in memory only, until you decide to write them.

Command (m for help): n
Partition number (1-128, default 1):
First sector (2048-3907029134, default 2048):
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-3907029134, default 3907029134): +200G

Created a new partition 1 of type 'Linux filesystem' and of size 200 GiB.

Command (m for help): p
Command (m for help): w
The partition table has been altered.
Calling ioctl() to re-read partition table.
Syncing disks.

n 之后的 First sector 直接回车，用默认 2048，对齐问题就没了。Last sector 给 +200G、+200M、+200K 这种相对写法，比算绝对扇区省事。w 之前所有操作只在内存里，q 退出等于全撤销。敲完 w 内核没立刻重读的话，用 partprobe /dev/sdb 或 partx -u /dev/sdb 补一下。fdisk 内部命令：

命令 作用 命令 作用
m 打印帮助 t 改分区类型
p 打印分区表 l 列出所有分区类型码
n 新建分区 a 切换可启动标志
d 删除分区 F 列出未分配空间
i 打印某个分区的详细信息 u 切换显示单位（扇区/柱面）
v 校验分区表 x 进入专家模式
g 新建空 GPT 分区表（清空） w 写盘退出
o 新建空 MBR 分区表（清空） q 不保存退出

t 改类型，MBR 用一位十六进制码，GPT 用 GUID 别名：

bash
Command (m for help): t
Selected partition 1
Hex code or alias (type L to list all): 8e
Changed type of partition 'Linux filesystem' to 'Linux LVM'
码 含义 码 含义
83 Linux 07 NTFS / exFAT
82 Linux swap 0b FAT32
8e Linux LVM 0c FAT32 (LBA)
fd Linux raid autodetect ef EFI System
05 扩展分区 ee GPT 保护分区

parted 的单位默认是 MB，写清 MiB 更保险：

bash
parted /dev/sdb mklabel gpt                              # 建 GPT 分区表
parted -s /dev/sdb mkpart primary ext4 1MiB 200GiB       # 切分区：类型 名字 起点 终点
parted -s /dev/sdb mkpart primary ext4 200GiB 100%
parted /dev/sdb print free                               # 连未分配空间一起列
parted /dev/sdb unit GiB print                           # 换单位
parted /dev/sdb rm 2                                     # 删第 2 个分区
parted /dev/sdb name 1 data                              # 改名字
parted /dev/sdb set 1 esp on                             # 设标志
parted /dev/sdb set 1 lvm on

print free 会额外列出每段未分配空间，切分区前先看，能避开空洞造成的浪费。sgdisk 是 GPT 专用帮手：sgdisk -p 打印、sgdisk -n 1:0:+200G -t 1:8300 建分区并指定类型码、sgdisk -c 1:"data" 起名字、sgdisk -Z 彻底清 GPT 与 MBR、sgdisk -v 校验。批量建分区用 sfdisk 管道喂：sfdisk -d /dev/sdb > /root/sdb.sfdisk 备份，sfdisk /dev/sdb < /root/sdb.sfdisk 还原。

工具 交互方式 分区表 适合 典型场景
fdisk 一问一答 MBR + GPT 手工操作、看清每一步 临时给新盘切分区
parted 命令行 / 交互 MBR + GPT 脚本化、大容量盘 一次 mkpart 切完
sfdisk 纯命令行 MBR + GPT 备份还原分区表 批量装机
sgdisk 纯命令行 仅 GPT GPT 高级操作 备份 GUID、改类型
gdisk 一问一答 仅 GPT GPT 的 fdisk 替代 GPT 专用交互

设备节点没出现，mkfs 会报 No such file or directory。别急着重启，先 partprobe /dev/sdb，再 lsblk /dev/sdb 确认。

/dev/sdb1、/dev/sdb2 是内核按分区表项位置生成的，删掉中间一个再建，编号会复用。真正稳定的是 UUID 和 PARTUUID：

bash
$ blkid
/dev/sdb1: UUID="a1b2c3d4-..." TYPE="ext4" PARTUUID="8b0e0f2c-01"

PARTUUID 末尾的 -01 是分区序号，GPT 下就是分区表里那 16 字节 GUID，跟盘绑定；UUID 是 mkfs 时写进超级块的，重新格式化就变。

五、格式化：创建文件系统 #

格式化就是在裸扇区上铺一层文件系统元数据：超级块、inode 表、块位图、日志。做完这块分区才有目录和文件的概念。

bash
# mkfs.ext4 /dev/sdb1
mke2fs 1.47.0 (5-Feb-2023)
Creating filesystem with 52428800 4k blocks and 13107200 inodes
Filesystem UUID: a1b2c3d4-1111-2222-3333-444455556666
Superblock backups stored on blocks:
        32768, 98304, 163840, 229376, 294912, 819200, 884736, 1605632, 2654208, 4096000

Allocating group tables: done
Writing inode tables: done
Creating journal (262144 blocks): done
Writing superblocks and filesystem accounting information: done
输出行 含义
52428800 4k blocks 总块数与块大小，块大小决定单文件上限
13107200 inodes inode 总数，等于能创建的文件与目录总数上限
Filesystem UUID 写进超级块的 UUID，fstab 里那个值就是它
Superblock backups stored on blocks 超级块备份位置，fsck 救援要靠它
Allocating group tables / Writing inode tables 块组描述符与 inode 表
Creating journal 日志区，掉电恢复靠它
Writing superblocks ... 超级块与记账信息收尾

mkfs 家族全在 /sbin 下，本质都是 mkfs.<类型>：

命令 文件系统 适用 命令 文件系统 适用
mkfs.ext4 ext4 数据盘默认选择 mkfs.vfat FAT32 UEFI 的 ESP、U 盘
mkfs.ext3 ext3 老系统兼容，带日志 mkfs.exfat exFAT 大容量 U 盘
mkfs.ext2 ext2 无日志，U 盘 mkfs.ntfs NTFS 跟 Windows 交换数据
mkfs.xfs XFS 大文件，只扩不缩 mkswap swap 交换分区
mkfs.btrfs Btrfs 快照、子卷、校验 mkfs -t — 前端，转调上面某个

ext4 常用参数：

参数 作用 参数 作用
-L 标签 设卷标，lsblk -f 的 LABEL 列 -I inode大小 128 到 4096，默认 256
-m 百分比 root 预留占比，默认 5，数据盘可给 1 -T 用法 预设 news/small/large/default
-b 块大小 1024/2048/4096，默认 4096 -O 特性 开关特性，如 ^has_journal
-i 字节数 每个 inode 覆盖多少字节，默认 16384 -E stride=,stripe_width= 配合 RAID 条带宽度
-N inode数 直接指定 inode 总数 -c / -F / -q / -n 坏块检查 / 强制 / 静默 / 只演练 
bash
mkfs.ext4 -L data -m 1 /dev/sdb1     # ext4 数据盘，root 预留降到 1%
mkfs.xfs -f -L data /dev/sdb1        # XFS，-f 覆盖已有签名
mkfs.vfat -F 32 -n BOOT /dev/sdb1    # ESP 或小 U 盘
mkfs.exfat -n DATA /dev/sdb1         # 大容量 U 盘
blkid /dev/sdb1 && dumpe2fs -h /dev/sdb1 | head -30   # 验证：签名 + 超级块摘要

XFS 建好只能扩不能缩，要缩小只能备份、重建、还原。FAT32 单文件上限 4 GiB，超过就换 exFAT。UEFI 的 ESP 必须 FAT32，300–500 MiB。dumpe2fs -h 只读超级块不扫全盘，秒出，看块大小、inode 总数、预留比例最快。xfs_info /dev/sdb1 对应 XFS。

格式化前必须确认设备，mkfs 没有任何撤销功能。四条都看一遍再敲回车：lsblk /dev/sdb、mount | grep sdb、grep sdb /etc/fstab、blkid /dev/sdb1。/dev/sdb1 和 /dev/sda1 差一个字母，代价是整个系统盘。

分区不是 mkfs 的前提，mkfs.ext4 /dev/sdb 整盘直接建文件系统也行。省事，代价是别的工具看到这块盘只能看到「裸盘」，装系统、做镜像、跟其他系统交换都不方便。除非专用数据盘，否则还是分区。

六、挂载：mount 的用法 #

挂载把一个文件系统的顶层目录接到目录树上的某个子目录。这个子目录叫挂载点。挂上之后原目录里本来就有的内容被遮住，直到卸载才重新看得见。

bash
mount [-fnrsvw] [-t vfstype] [-o options] device dir
参数 作用 参数 作用
-t 类型 指定类型，auto 自己探测 -f 假装挂载，只走流程，调试 fstab 用
-o 选项 挂载选项，逗号分隔 -s 容忍不认识的选项，不报错
-a 挂 fstab 里所有 auto 条目 -v 打印详细过程
-r / -w 只读（等同 -o ro）/ 读写 -l 挂载点里带上 LABEL
-n 不写 /etc/mtab，不通知 mount 守护进程 -L / -U 按卷标 / 按 UUID 挂载

五种等价写法，只给设备或只给挂载点，mount 会去 fstab 里查另一半：

bash
mount /dev/sdb1 /data1
mount -U a1b2c3d4-1111-2222-3333-444455556666 /data1
mount -L data /data1
mount /dev/sdb1              # 挂载点从 fstab 里找
mount /data1                 # 设备从 fstab 里找

不加参数看当前所有挂载，格式是 设备 on 挂载点 type 类型 (选项)：

bash
$ mount | head -3
proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)
/dev/sda3 on / type ext4 (rw,relatime)
/dev/sdb1 on /data1 type ext4 (rw,relatime)

findmnt 输出更整齐，支持树形和反查：findmnt /data1、findmnt -T /data1/sub/file.txt（反查某路径属于哪个挂载点）、findmnt -t ext4,xfs、findmnt -R /data1（连子挂载）。

-t 类型取值：

类型 说明 类型 说明
ext2/3/4 Linux 本地文件系统 iso9660 / udf 光盘 / DVD、蓝光
xfs RHEL 系默认，大文件强 nfs / nfs4 网络文件系统

-o 常用选项：

选项 含义 选项 含义
defaults 等于 rw,suid,dev,exec,auto,nouser,async owner 设备所有者才能挂载
ro / rw 只读 / 读写 auto / noauto 参与 / 不参与 mount -a
noexec / exec 禁止 / 允许执行二进制 _netdev 等网络就绪再挂，网络盘必加
nosuid / suid 忽略 / 尊重 setuid、setgid nofail 设备不在也不阻塞开机
nodev / dev 不解释 / 解释设备文件 discard 向 SSD 发 TRIM

bash
mount -o noatime,nodiratime /dev/sdb1 /data1                        # 数据盘，性能优先
mount -t tmpfs -o size=2G,noexec,nosuid,nodev tmpfs /tmp            # /tmp 放内存
mount -t vfat -o iocharset=utf8,codepage=936,umask=022 /dev/sdb1 /mnt/usb
mount -o loop -t iso9660 ubuntu.iso /mnt/iso                        # ISO 镜像
mount --bind /data1 /srv/data1                                      # 绑定子树
mount -o remount,rw /                                               # 救援时第一件事

挂载点必须先存在，mount 不会替你建目录。失败报错对照：

报错 原因 处理
mount point does not exist 挂载点目录没建 mkdir -p /data1
wrong fs type, bad option, bad superblock 没格式化、类型选错、设备选错 blkid 确认，mkfs 补上
unknown filesystem type 'ntfs' 内核或用户态工具没装 装 ntfs-3g，或用 -t ntfs3
already mounted 已挂在别处 findmnt /dev/sdb1 查

can't read superblock 超级块坏了 fsck 或 e2fsck -b 32768

NFS 也是挂载，客户端把远端目录接进本机目录树：

bash
mount -t nfs 192.168.1.10:/export/data /mnt/nfs
mount -t nfs4 -o rw,hard,intr,rsize=1048576,wsize=1048576 nfs.example.com:/data /mnt/nfs

hard 表示服务端无响应时一直重试，soft 会超时返回错误。数据库、代码仓库这类绝不能静默丢数据的场景用 hard。/etc/mtab 在现代系统上是指向 /proc/self/mounts 的符号链接，内核说了算，实际状态看 cat /proc/mounts 或 cat /proc/self/mountinfo。

七、fstab：开机自动挂载 #

手工 mount 重启就没了，要长期生效就写 /etc/fstab。这也是那个能让系统开不了机的文件，写错一行，机器卡在 emergency mode，图形界面进不去，SSH 也不通。动它之前先 cp /etc/fstab /etc/fstab.bak.$(date +%F)。

六个字段，一个都不能含糊：

text
<设备>  <挂载点>  <文件系统类型>  <挂载选项>  <dump>  <pass>

一个完整例子：

text
# <file system>        <mount point>  <type>  <options>               <dump> <pass>
UUID=a1b2c3d4-1111-2222-3333-444455556666  /data1  ext4  defaults,noatime  0  2
/dev/sdb2              /data2         xfs     defaults,nofail         0       0
/dev/sdb3              swap           swap    defaults                0       0
tmpfs                  /tmp           tmpfs   size=2G,noexec,nosuid,nodev  0  0
proc                   /proc          proc    defaults                0       0
none                   /dev/pts       devpts  gid=5,mode=620          0       0
/dev/cdrom             /mnt/cdrom     iso9660 noauto,ro,iocharset=utf8 0      0
//192.168.1.5/share    /mnt/smb       cifs    credentials=/etc/smb.cred,_netdev,nofail  0  0
序号 字段 写什么 常见错误
1 设备 /dev/sdb1、UUID=...、LABEL=...、PARTUUID=...，网络盘写 //host/share 或 host:/path 写 /dev/sdb1 后换盘或加盘，设备名变了，挂错或开不了机
2 挂载点 绝对路径目录，必须已存在 目录不存在，开机卡住进 emergency mode
3 文件系统类型 ext4、xfs、vfat、ntfs、swap、auto 与实际不符，报 wrong fs type
4 挂载选项 逗号分隔，defaults 起步 选项拼错，报 bad option 直接不挂
5 dump 0 或 1，给 dump 备份工具用 现在基本全写 0
6 pass 0 不检查；1 最先检查；2 之后检查 根分区必须 1，其他 2，不该检查的写 0

pass 的规矩：/ 写 1，fsck 第一个检查它；其他本地文件系统写 2，并行检查；swap、tmpfs、proc、网络盘、光盘写 0。全写 0 也行，代价是开机不做一致性检查，出事时才发现。dump 字段是老 Unix 时代 dump 备份工具靠它决定哪些文件系统要备份，1 备份、0 不备份，现在基本没人用，全写 0。第一字段优先写 UUID，因为 /dev/sdb1 这个名字取决于内核扫描顺序，加一块盘、换个 SATA 口、把 U 盘插上去，都能让它变成 /dev/sdc1：

bash
$ blkid /dev/sdb1
/dev/sdb1: UUID="a1b2c3d4-1111-2222-3333-444455556666" TYPE="ext4" PARTUUID="8b0e0f2c-01"
写法 稳定性 什么时候用
UUID= 高，跟文件系统绑定 本地数据盘首选
LABEL= 高，但要保证卷标唯一 卷标管理规范时
PARTUUID= 高，跟分区表绑定 分区 GUID 不变、盘要重格式化
/dev/disk/by-id/ata-... 高，带型号序列号 想从名字看出是哪块盘
/dev/sdb1 低，随扫描顺序变 只在临时测试里

选项里几个必加的：

选项 场景 原因 选项 场景 原因
nofail 数据盘、移动硬盘 设备不在时跳过，不卡开机 noatime 大写入量数据盘 少一次 inode 更新
_netdev NFS、CIFS 等网络就绪，否则必然失败 noexec /tmp、U 盘 防执行恶意二进制
noauto 光盘、U 盘 不参与 mount -a，插上才挂 x-systemd.automount 不常访问的网络盘 首次访问才挂

改完必须验证，不要直接重启：

bash
cp /etc/fstab /etc/fstab.bak.$(date +%F)   # 先备份
# 改完
mount -a                                   # 按 fstab 挂一遍，看有没有报错
findmnt --verify --verbose                 # systemd 的 fstab 自检，能报出字段数和选项问题
systemctl daemon-reload                    # 有 .mount 单元时刷新

mount -a 干净通过，才说明 fstab 至少语法和可达性没问题。有报错就改回去，别硬重启。

写错导致开机失败怎么救。看到 emergency mode 提示时输入 root 密码进维护 shell。输入不了就先在 GRUB 里救：停在要启动的条目上按 e，找到 linux 开头那行，行尾追加 rw init=/bin/bash，Ctrl+X 启动。这样直接给一个 root shell，不跑 systemd，fstab 根本不会被处理。

bash
mount -o remount,rw /                             # 根分区还是只读时，先挂成读写
cp /etc/fstab.bak.2026-11-17 /etc/fstab
mount -a                                          # 验证
reboot -f

只有 remount 成功，才写得进 /etc/fstab。要恢复正常启动流程而不重启，可以 mount -o remount,ro / 后 exec /sbin/init。在 systemd 的 emergency shell 里，如果确认是某个分区挂不上导致的，可以先把那一行注释掉再重启：

bash
sed -i 's|^UUID=a1b2c3d4|#UUID=a1b2c3d4|' /etc/fstab
systemctl daemon-reload
systemctl reboot

单用户模式也能救。RHEL 系给内核行加 rd.break，Debian 系加 single 或 init=/bin/bash，效果一样：进到只挂了根分区的 shell，改完 fstab 再重启。RHEL 系在 rd.break 里要先 mount -o remount,rw /sysroot，改的是 /sysroot/etc/fstab。

nofail 不是万能的，它只处理「设备不存在」，不处理「选项写错」。动 fstab 的规矩：先备份；只改一段，mount -a 通过再改下一段；远程机器上别直接 reboot；新加的盘先带 nofail 跑几天，稳定了再摘掉。

八、卸载与挂载点管理 #

卸载用 umount，不是 unmount。

bash
umount /data1
umount /dev/sdb1
参数 作用 参数 作用
-f 强制卸载，用于失联的网络文件系统 -n 不更新 /etc/mtab
-l lazy，立刻从目录树摘掉，等引用归零再清理 -v 打印过程
-r 卸不掉就改成只读重挂 -t 类型 只卸指定类型
-a 卸 /etc/mtab 里除 / 外全部 — —

target is busy 是最常见的失败。查谁占着：lsof +D /data1、fuser -vm /data1、fuser -km /data1（直接杀掉占用进程，慎用）。

原因 处理 原因 处理
shell 当前目录在挂载点里 cd / 再卸 有进程把该目录当工作目录 fuser -vm 看 PID
有进程打开了里面的文件 lsof +D 定位后退出或杀掉 里面还有别的挂载 先卸子挂载，findmnt -R /data1

挂载点的原内容被遮住，du 统计挂载点得到的是新文件系统的占用，看不到原来的，卸载之后才回来。要统计根分区真实占用得排除挂载点，用 du -x -sh /*，-x 表示不跨文件系统。移动挂载点用 mount --move /data1 /srv/data1。绑定挂载让同一个文件系统出现在两个位置：mount --bind /data1/logs /var/log/app 挂目录，mount --rbind /data1 /srv/data1 连子挂载一起。--bind 出来的挂载点单独出现在 findmnt 里，卸载它不影响源挂载点。挂载传播用 --make-shared、--make-private、--make-slave、--make-unbindable，shared 向外传播挂载事件，private 不传播，容器场景要用到。

挂载点规范 好处 挂载点规范 好处
用 /data1 而不是 /mnt/xxx 一眼看出是长期数据盘 名字里不带空格 脚本和 fstab 都好处理
/mnt 只放临时挂载 跟 FHS 的定位一致 目录权限按业务设 别默认 777
U 盘挂 /run/media/$USER/标签 systemd 的默认位置，不易冲突 挂之前 ls -A 确认空 卸载后不残留干扰

卸载后目录还在，只是里面恢复成挂载前的样子。不常访问的网络盘加 x-systemd.automount 和 x-systemd.idle-timeout=600，开机只注册自动挂载单元，首次访问才真正去挂，空闲 10 分钟自动卸载。

九、磁盘空间的查看：df 与 du #

两个命令回答两个不同的问题。df 问「这个文件系统还剩多少」，du 问「这个目录里堆了多少」。

bash
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda3       464G  180G  261G  41% /
/dev/sdb1       1.8T  1.2T  552G  69% /data1
tmpfs           3.8G  1.2M  3.8G   1% /run
/dev/sda2       1.0G  320M  705M  32% /boot
列 含义 列 含义
Filesystem 设备名或伪文件系统名 Avail 普通用户可用（已扣掉 root 预留）
Size 该文件系统总容量 Use% 已用百分比
Used 已用 Mounted on 挂载点

Size - Used 不等于 Avail，差的就是 mkfs 时 -m 5 给 root 留的那 5%。df 报 Use% 100% 但 Avail 还有几 G，就是这套机制在起作用：root 还能写，普通用户已经写不进去了。

df 参数 作用 df 参数 作用
-h / -H 1024 / 1000 进制，人类可读 -i 看 inode 使用率，不看块
-T 多一列文件系统类型 -a 连伪文件系统一起列
-t 类型 / -x 类型 只看 / 排除指定类型 -l 只看本地文件系统
--total 末尾加一行总计 -P POSIX 格式，行不换行

df -i 是常被忽略的坑。块没满但 inode 用光了，照样写不进文件，报 No space left on device：

bash
$ df -i /data1
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sdb1     13107200 13107180     20  100% /data1

小文件特别多（邮件队列、session 文件、日志切片）的场景，inode 比容量先耗尽。du 再怎么看都是「还有空间」，得用 df -i 才看得见。

du 参数 作用 du 参数 作用
-h 人类可读 -x 不跨文件系统
-s 只显示总计，不列子目录 -d N 只展开 N 层，同 --max-depth
-a 连文件一起列 --exclude=模式 排除匹配的路径
-c 末尾加总计行 --time 连带最后修改时间
-L / -P 跟随 / 不跟随符号链接 -k / -m / -b 按 KB / MB / 字节显示

按大小排序找占用大户，最实用的两条：

bash
du -h -d 1 /data1 | sort -h
du -h --max-depth=1 /data1 | sort -hr | head -10
维度 df du
数据来源 已挂载文件系统的超级块统计 遍历目录树，累加每个文件占用的块
速度 秒出 目录越大越慢
统计对象 整个文件系统 指定目录
跨挂载点 天然不跨 默认跨，-x 才不跨
看见已删除但被打开的文件 算在 Used 里 看不见
看见 inode 耗尽 -i 能看 看不出
典型用途 还剩多少空间 谁占的空间

两边数字对不上，就是这四种情况：

现象 原因 排查
df 满了，du 只统计出很少 有文件被删但进程还开着句柄 lsof +L1 找到，重启那个进程
df 满了，du 也统计不出来 inode 耗尽 df -i
du 比 df 大 目录里挂载了别的文件系统，重复统计 du -x
du 比 df 小很多 稀疏文件、快照、预留块 du --apparent-size，df 看 Use%

lsof +L1 是救援常用手段：日志文件被 rm 掉了，写日志的进程还开着 fd，那块空间就一直不释放，直到进程重启。磁盘 IO 与块层信息用 iostat -x 1 3、iotop -o、vmstat 1、cat /proc/diskstats。iostat -x 的 %util、await、aqu-sz 是判断盘是否吃满的三个数：%util 接近 100% 说明盘忙到头了，await 持续升高说明队列在堆积。

十、swap 分区 #

swap 是内存的后备。内存压力上来时内核把不活跃的匿名页换出去，腾出物理页给热的进程。它不是内存的平替，是一层缓冲。

形态 建立方式 特点
swap 分区 mkswap /dev/sdb3 独立分区，不参与文件系统，性能略好
swap 文件 dd 造文件 + mkswap 灵活调整大小，占的是某个文件系统的空间
zram zramctl + swapon 内存里压缩，不落盘，速度快、容量虚
zswap 内核参数开启 换出前先压缩，压缩失败才落盘

建 swap 分区：fdisk 切一个分区，t 改成 82（MBR）或 19（GPT swap），然后 mkswap /dev/sdb3 再 swapon /dev/sdb3。mkswap 输出会给出 UUID，记下来写 fstab：

bash
$ mkswap /dev/sdb3
Setting up swapspace version 1, size = 8 GiB (8589930496 bytes)
no label, UUID=7c9e6679-7425-40de-944b-e07fc1f90ae7

dd if=/dev/zero of=/swapfile bs=1M count=4096    # 建 swap 文件
chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile

chmod 600 不能省，权限过宽 swapon 会拒绝。fallocate -l 4G /swapfile 更快，但 XFS 上 fallocate 出来的文件有预分配的 extent，swapon 会报 Invalid argument，老老实实用 dd。

参数 作用 参数 作用
mkswap -L 标签 设卷标 swapon -s 列出当前 swap，等同 cat /proc/swaps
mkswap -U UUID 指定 UUID swapon --show 表格形式列出
mkswap -f 强制，覆盖已有签名 swapon -p 优先级 设优先级，高的先用
swapon -a 挂 fstab 里所有 swap swapoff -a / swapoff /dev/sdb3 全部关掉（内存要装得下）/ 关掉一个 
bash
$ swapon --show
NAME      TYPE       SIZE USED PRIO
/dev/sdb3 partition    8G   0B   -2
/swapfile file       4G   0B   -3

$ free -h
               total        used        free      shared  buff/cache   available
Mem:            15Gi       6.2Gi       2.1Gi       180Mi       7.0Gi       8.8Gi
Swap:           12Gi          0B        12Gi

fstab 里两种写法，挂载点字段写 none，类型 swap，选项 sw，pass 必须 0，别让 fsck 去检查 swap：

text
UUID=7c9e6679-7425-40de-944b-e07fc1f90ae7  none  swap  sw  0  0
/swapfile                                 none  swap  sw  0  0

swappiness 从 0 到 100，默认 60，数值越大越愿意换出匿名页。桌面和数据库服务器一般调到 10–20：

bash
cat /proc/sys/vm/swappiness
sysctl -w vm.swappiness=10
echo 'vm.swappiness=10' > /etc/sysctl.d/99-swap.conf

设成 0 不是「禁用 swap」，只是「除非真的没内存了否则不换出」。

内存 无休眠需求 需要休眠
≤ 2 GiB 2 × 内存 3 × 内存
2–8 GiB 等于内存 2 × 内存
8–64 GiB 至少 4 GiB 1.5 × 内存
> 64 GiB 至少 4 GiB，够用即可 不建议休眠

删 swap 分区之前先 swapoff，否则内核会报错。

十一、LVM 与 RAID 简介 #

单块盘切分区那套做法，遇到「空间不够要扩」「盘坏了不能丢数据」就伸不开手。LVM 和 RAID 是两套不同的解法，可以叠加用。

text
物理卷 PV   /dev/sdb1, /dev/sdc1        ← 每块盘或分区注册成 PV
    ↓
卷组 VG     vg_data                      ← 多个 PV 拼成一个池
    ↓
逻辑卷 LV   lv_home, lv_var, lv_data     ← 从池里切出来的逻辑块设备

LV 用起来跟普通分区没区别，mkfs.ext4 /dev/vg_data/lv_home 然后 mount 就行。

bash
pvcreate /dev/sdb1 /dev/sdc1                 # 1. 建 PV
vgcreate vg_data /dev/sdb1 /dev/sdc1         # 2. 建 VG，两个 PV 组成一个池
lvcreate -L 500G -n lv_home vg_data          # 3. 切 500G
lvcreate -l 100%FREE -n lv_data vg_data      #    剩下的全给 lv_data
mkfs.ext4 /dev/vg_data/lv_home
mount /dev/vg_data/lv_home /home

lvextend -L +100G /dev/vg_data/lv_home       # 4. 扩 LV
resize2fs /dev/vg_data/lv_home               #    ext4 在线扩
lvextend -r -L +100G /dev/vg_data/lv_home    #    一步到位，-r 自动调 resize
xfs_growfs /home                             #    XFS 用这个，且只能扩

pvcreate /dev/sdd1                           # 5. VG 不够大就加盘
vgextend vg_data /dev/sdd1
lvextend -r -l +100%FREE /dev/vg_data/lv_home

lvcreate -L 10G -s -n lv_home_snap /dev/vg_data/lv_home   # 6. 快照
mount /dev/vg_data/lv_home_snap /mnt/snap

缩容只有 ext4 能做，XFS 不行，而且必须卸载。顺序弄反了数据就废了：

bash
umount /home
e2fsck -f /dev/vg_data/lv_home
resize2fs /dev/vg_data/lv_home 400G     # 先缩文件系统
lvreduce -L 400G /dev/vg_data/lv_home   # 再缩 LV
mount /home

快照空间只存差异块，差异块超过给的大小快照会失效，容量要留够。用完 umount /mnt/snap 再 lvremove /dev/vg_data/lv_home_snap。

对象 创建 扩展 缩减 删除 查看
PV pvcreate — — pvremove pvs / pvdisplay
VG vgcreate vgextend vgreduce vgremove vgs / vgdisplay
LV lvcreate lvextend lvreduce lvremove lvs / lvdisplay

RAID 用 mdadm：

bash
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
cat /proc/mdstat
mkfs.ext4 /dev/md0
mdadm --detail /dev/md0
mdadm /dev/md0 --fail /dev/sdb1 --remove /dev/sdb1
mdadm /dev/md0 --add /dev/sdd1
级别 最少盘数 可用容量 容错 适合
RAID 0 2 全部 无，一块坏全丢 临时缓存、纯性能场景
RAID 1 2 一半 坏一块仍可用 系统盘、小容量高可靠
RAID 5 3 n-1 块 坏一块仍可用 读多写少的存储
RAID 6 4 n-2 块 坏两块仍可用 大盘阵列
RAID 10 4 一半 每组坏一块 数据库，性能与可靠兼顾

RAID 5 写惩罚重，重建时压力大，机械盘做大阵列要慎重，宁可 RAID 10 也不要大 RAID 5。/proc/mdstat 是状态面板：

bash
$ cat /proc/mdstat
Personalities : [raid1]
md0 : active raid1 sdc1[1] sdb1[0]
      1953382464 blocks super 1.2 [2/2] [UU]

[UU] 两块都在位，[U_] 表示第二块掉了，要换盘重建。硬 RAID 由阵列卡负责，系统里看到一块逻辑盘；软 RAID 由 mdadm 在内核里做，CPU 参与校验计算。前者性能稳、换卡有兼容风险，后者透明、可迁移，重建慢。两块盘的镜像，软 RAID 完全够用。

层次别乱套。LV 上再分区、RAID 上再套 LVM 再套 RAID，出问题时排查链路会长到让人崩溃。常见组合只有两种：RAID → LVM → 文件系统，或者 RAID → 文件系统。

十二、常见故障与救援 #

盘上的东西不动，多数故障都能救回来。关键是别在第一时间做错动作。fsck 是文件系统一致性检查，必须在卸载状态下跑。挂在读写状态上跑，等于一边改一边查，越修越乱。根分区只能在救援模式或 init=/bin/bash 下跑。

bash
umount /data1
fsck -f /dev/sdb1          # 强制检查
fsck.ext4 -p /dev/sdb1     # 预检，能自动修的都修掉
e2fsck -fy /dev/sdb1       # 所有提问答 yes
参数 作用 参数 作用
-f 强制检查，即使标记为干净 -C 显示进度条
-y / -n 提问全答 yes / 全答 no，只看不改 -v 详细输出
-p 预检模式，能自动修的都修掉 -b 块号 用指定备份超级块
-c 顺带做坏块扫描 -B 块大小 配合 -b 重建主超级块

超级块坏了用备份救，mkfs 时打印的 Superblock backups stored on blocks 那串数字就是救命名单：

bash
e2fsck -b 32768 /dev/sdb1
e2fsck -b 98304 /dev/sdb1
e2fsck -b 32768 -B 4096 /dev/sdb1     # 修好后重建主超级块

挨个试，哪个能用就用哪个，备份超级块不在同一位置。分区表丢了用 TestDisk 找回：testdisk /dev/sdb，Analyze → Quick Search → 找到分区 → Write 写回分区表。它只重建分区表，不动分区里的数据，前提是分区数据本身没被覆盖。只读文件系统写不进去。内核检测到 ext4 元数据不一致时会把文件系统切成只读：

bash
dmesg | grep -i 'ext4\|error'
mount -o remount,rw /data1

能 remount 成功就先备份数据，再 fsck。一直 remount 不成功说明错误没修，直接跑 fsck。设备不存在、/dev/sdb1 没了：

bash
lsblk
partprobe /dev/sdb
partx -u /dev/sdb
echo 1 > /sys/block/sdb/device/rescan

热插拔之后设备名会变，用 ls /dev/disk/by-id/ 认盘更稳。盘只读、写保护的话，SMART 自检发现坏块过多时，部分 SSD 会把自己切成只读模式保住现有数据：

bash
smartctl -a /dev/sdb
dmesg | grep -i 'read-only\|write protect'

SMART overall-health 里的 PASSED/FAILED 和 Reallocated_Sector_Ct 两个值最关键，FAILED 就是该换盘了，先拷数据。

系统进不去 emergency mode 的完整救援流程：

  1. GRUB 菜单按 e，内核行末尾加 rw init=/bin/bash，Ctrl+X 启动
  2. mount -o remount,rw /
  3. cat /etc/fstab 找到写错的那行，注释掉或改回去
  4. mount -a 验证
  5. reboot -f

systemd 进的是 emergency shell，不是 init=/bin/bash 那种裸 shell。两种都能改 fstab，区别是 emergency shell 里 systemd 的单元还在跑，mount -a 前要 systemctl daemon-reload。系统彻底起不来，用 U 盘启动一个 live 环境，把原系统 chroot 进来：

bash
lsblk
mount /dev/sda3 /mnt
mount --bind /dev /mnt/dev
mount --bind /proc /mnt/proc
mount --bind /sys /mnt/sys
chroot /mnt
# 现在在救援环境里改 fstab、重装 grub、跑 fsck
grub2-install /dev/sda
grub2-mkconfig -o /boot/grub2/grub.cfg

chroot 之后环境是原系统的，命令、配置文件全在，改完 exit 再重启。

磁盘满会导致连锁故障：/ 满了之后日志写不进、服务起不来、数据库拒绝连接。先腾空间：

bash
df -h
du -h -d 1 / | sort -h
journalctl --vacuum-size=200M
find /var/log -type f -size +100M
lsof +L1

journalctl --vacuum-size 是清理日志最安全的一条，它只删旧日志，不碰配置。误删分区表之后第一件事是停止往这块盘写任何东西，任何写入都会覆盖原来的分区数据。然后把盘接别的机器，或者用 live 环境只读挂载，跑 testdisk 或 photorec 扫。

十三、易错点速查 #

按踩坑频率排，从高到低。

坑 现象 正确做法
设备名认错 mkfs 写掉了系统盘 动手前 lsblk -o +MODEL,SERIAL，用 /dev/disk/by-id/ 确认
fstab 用 /dev/sdb1 加块盘后开机挂错或进不了系统 一律写 UUID= 或 LABEL=
fstab 挂载点目录不存在 开机卡在 emergency mode 先 mkdir -p，再写 fstab
根分区 pass 不是 1 开机不检查根分区，出错才发现 / 写 1，其他本地盘 2，非本地 0
fstab 里混进中文或空格 字段错位，整行失效 只用空格或 Tab 分隔，挂载点不带空格
改完 fstab 直接 reboot 远程机器失联 先 mount -a 加 findmnt --verify
新盘 fstab 没加 nofail 盘拔了系统起不来 非根盘一律带 nofail
网络盘没加 _netdev 开机必挂载失败 NFS/CIFS 必须加
在已挂载的文件系统上 fsck 越修越乱 先 umount，根分区进救援模式
swapon 报 Invalid argument swap 文件权限或 extent 问题 chmod 600，XFS 上用 dd 不用 fallocate
FAT32 拷不进大文件 单文件 4 GiB 上限 换 exFAT 或 NTFS
UEFI 下 ESP 格式不对 固件找不到引导程序 ESP 必须 FAT32，300–500 MiB，类型 EF00
分区起点 63 扇区 4K 盘写放大 起点用 1MiB 或默认 2048
2 TiB 以上的盘用 MBR 超出部分不可用 大盘用 GPT
parted 直接 mklabel 分区表被清空 先 sgdisk --backup 备份
df 满但 du 看不到 已删除文件仍有进程持有句柄 lsof +L1，重启那个进程
块没满却报 No space left inode 耗尽 df -i 查，重做文件系统时调 -i/-N
umount 报 target is busy 有进程占用 lsof +D 或 fuser -vm 定位
挂载点被覆盖后 du 统计出错 统计不到原内容 du -x，或先卸载再统计
格式化正在使用的盘 忘了先卸挂载 先 umount，lsblk 确认未挂载
缩 LV 前没缩文件系统 数据损坏 先 resize2fs，再 lvreduce
XFS 试图缩容 根本做不到 XFS 只扩不缩，缩容只能备份重建
RAID 5 大阵列重建期再坏一块 全盘数据丢失 重要数据用 RAID 10 或 RAID 6，并保留独立备份
swap 分区写进 pass=1 开机去检查 swap 报错 swap 的 pass 写 0
defaults 里含 async 掉电丢最近写入 关键数据用 data=journal 或单独挂 sync

最后一条最实在：动磁盘之前先备份 fstab，动分区之前先确认盘。这两条挡住的问题，比上面所有参数加起来都多。
