本篇只讲系统调用这一层的文件 IO：open/close/read/write/lseek/stat 怎么调、返回值怎么读、文件描述符是什么、fd 与打开文件表、inode 这三层怎么对上。不讲标准库 FILE * 的缓冲策略，也不碰内核里 struct file、dentry 的内部实现——那部分归 B.内核/04-文件系统。内存侧的概念（虚拟地址空间、栈与堆）看同目录《C 程序的内存模型》；路径与目录规范看《Linux 目录结构与 FHS 标准》；挂载与磁盘工具看《分区、挂载与磁盘工具》；文件系统类型与从 VFS 到块设备的整条 IO 路径看《文件系统类型与 IO 路径》。

一、文件 IO 的系统调用全景 #

用户态想动文件，只有一条路：进内核。进内核的手段就是系统调用。这一层没有缓冲、没有格式化、没有重试，你给它什么它做什么，出问题靠 errno 说话。

先把常用的几个摆出来，后面各章再逐个拆。

系统调用 原型要点 干什么 返回值关键
open int open(const char *path, int flags, mode_t mode) 按路径打开文件，拿到 fd 新 fd / -1
openat int openat(int dirfd, const char *path, int flags, mode_t mode) 以某个目录 fd 为基准打开 新 fd / -1
close int close(int fd) 释放 fd 与它持有的引用 0 / -1
read ssize_t read(int fd, void *buf, size_t count) 从当前偏移读最多 count 字节 实际字节数 / 0 / -1
write ssize_t write(int fd, const void *buf, size_t count) 从当前偏移写最多 count 字节 实际字节数 / -1
lseek off_t lseek(int fd, off_t off, int whence) 移动文件偏移 新偏移 / -1
pread ssize_t pread(int fd, void *buf, size_t count, off_t off) 带偏移读，不动当前偏移 同 read
pwrite ssize_t pwrite(int fd, const void *buf, size_t count, off_t off) 带偏移写，不动当前偏移 同 write
stat int stat(const char *path, struct stat *buf) 按路径取属性 0 / -1
fstat int fstat(int fd, struct stat *buf) 按 fd 取属性 0 / -1
lstat int lstat(const char *path, struct stat *buf) 取符号链接本身的信息 0 / -1
dup int dup(int oldfd) 复制一个 fd 到最小可用号 新 fd / -1
dup2 int dup2(int oldfd, int newfd) 复制到指定号，占用就顶掉 新 fd / -1
fcntl int fcntl(int fd, int cmd, ...) 改 fd 标志、改打开文件标志、复制 fd 视 cmd
fsync int fsync(int fd) 数据 + 元数据刷盘 0 / -1
ftruncate int ftruncate(int fd, off_t len) 按 fd 截断或扩展 0 / -1

三层结构要分清，不然后面全是糊的：

text
应用代码
  ↓  fopen / fread / fwrite / fprintf   ← 用户态缓冲，归 stdio
标准库 FILE *
  ↓  open / read / write / lseek        ← 本篇的范围，无用户态缓冲
系统调用接口
  ↓
VFS → 具体文件系统 → 块设备

我们的 read/write 每次调用都要从用户态切进内核态，一次搬一部分字节。fread/fwrite 之所以快，是因为它在用户态先攒一大块再一次性交给 read/write。两层的返回值语义完全不同：fread 返回的是「项数」，read 返回的是「字节数」。

三个绕不开的约定，先记住了：

  1. 失败统一返回 -1，具体原因看 errno。所以 if (ret < 0) 之后必须立刻读 errno，别插别的系统调用进去。
  2. 字节数用 ssize_t（有符号，能装下 -1），长度用 size_t（无符号）。把 read 的返回值塞进 size_t 再判负，永远判不出来。
  3. fd 只是一个整数句柄。整数本身不含任何文件信息，它的全部意义在进程的 fd 表里。

二、open 与 close #

c
#include <fcntl.h>

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);

pathname 是路径，可以是绝对路径也可以是相对路径（相对当前工作目录）。flags 是访问模式加行为标志的按位或。mode 只在 flags 里带 O_CREAT 或 O_TMPFILE 时才需要，其余情况被忽略。

成功时返回一个非负整数，这是本进程 fd 表里编号最小的空位。失败返回 -1，errno 告诉你原因。

errno 含义
ENOENT 路径不存在，或路径中间某级目录不存在
EACCES 权限不够，或路径中间某级目录缺执行（搜索）权限
EISDIR 想以写方式打开一个目录
ENOTDIR 路径中间某级不是目录
EMFILE 本进程 fd 用满了，撞到 RLIMIT_NOFILE
ENFILE 系统级打开文件总数到顶了，撞到 fs.file-max
ELOOP 符号链接绕成环了
ENAMETOOLONG 路径名超长
EEXIST 带了 `O_CREAT

EMFILE 和 ENFILE 要分开看：前者是「你这个进程开太多了」，调 ulimit -n；后者是「整台机器开太多了」，调 sysctl fs.file-max。搞错方向白折腾。

close 的原型就一行：

c
int close(int fd);

成功返回 0，失败返回 -1 并置 errno，最常见的是 EBADF（fd 不合法或已经关过了）。

close 有两个坑要提前说清：

  • 返回 -1 不代表 fd 没被释放。Linux 上 close 一旦返回，fd 就已经从进程 fd 表里摘掉了。所以不要重试 close，重试时抢到的会是被别人刚 open 拿走的同一个号码，一关就把别人的文件关了。
  • 被信号打断时 close 也会返回 -1 且 errno == EINTR，同样不重试。
  • 数据有没有落盘和 close 的返回值没有关系。要保证落盘就显式 fsync(fd)，然后才 close。

一段能直接用的骨架：

c
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>
#include <stdio.h>

int main(void) {
    const char *msg = "hello fd\n";
    int fd = open("/tmp/demo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) {
        fprintf(stderr, "open: %s\n", strerror(errno));
        return 1;
    }

    ssize_t n = write(fd, msg, strlen(msg));
    if (n < 0) {
        fprintf(stderr, "write: %s\n", strerror(errno));
        close(fd);
        return 1;
    }

    if (fsync(fd) < 0) {
        fprintf(stderr, "fsync: %s\n", strerror(errno));
    }
    if (close(fd) < 0) {
        fprintf(stderr, "close: %s\n", strerror(errno));
    }
    return 0;
}

三、open 的标志位组合 #

标志分两类：访问模式（互斥，三选一）和行为标志（可叠加）。

标志 值 作用 要记住的点
O_RDONLY 0 只读 值是 0，所以不能用 if (flags & O_RDONLY) 判断
O_WRONLY 1 只写 与下面两个互斥
O_RDWR 2 读写 想同时读改写就用它
O_ACCMODE 3 访问模式掩码 判断访问模式必须 flags & O_ACCMODE
O_CREAT 0100 不存在就创建 必须补 mode 参数
O_EXCL 0200 与 O_CREAT 合用，存在就报错 靠它做原子的「创建锁文件」
O_TRUNC 01000 打开即截断成 0 字节 只对可写打开有意义
O_APPEND 02000 每次写前把偏移移到末尾 定位与写在同一次系统调用里完成
O_NONBLOCK 04000 非阻塞模式 管道、FIFO、设备、socket 上才有意义
O_SYNC 04010000 写返回时数据与元数据都已落盘 慢，别乱用
O_DSYNC 010000 只保证数据落盘 比 O_SYNC 轻一点
O_CLOEXEC 02000000 执行 exec 时自动关闭 多线程程序打开文件时必带
O_NOFOLLOW 0400000 路径末段是符号链接就失败 防符号链接攻击
O_DIRECT 040000 绕过页缓存直接和块设备交互 对齐要求严格，写数据库才碰

数值是 Linux 上的取值，跨平台代码里别硬编码数字，写宏名。

O_RDONLY 等于 0，这是个经典陷阱。它一个位都没占，所以「按位与」永远得 0。想看一个 fd 是读还是写，只能：

c
int flags = fcntl(fd, F_GETFL);
switch (flags & O_ACCMODE) {
    case O_RDONLY: /* 只读 */ break;
    case O_WRONLY: /* 只写 */ break;
    case O_RDWR:   /* 读写 */ break;
}

常见组合对照：

组合 场景
O_WRONLY | O_CREAT | O_TRUNC 覆盖写，日志重开、配置文件重写
O_WRONLY | O_CREAT | O_APPEND 追加写，多进程共写一个日志
O_RDWR | O_CREAT 目标文件不一定存在，读写混合
O_RDWR | O_CREAT | O_EXCL 原子创建，抢锁文件、pid 文件
O_RDONLY | O_NONBLOCK 打开 FIFO 或串口，不想被卡住
O_RDONLY | O_CLOEXEC 库函数里打开文件，不想泄漏给子进程

mode 只在新文件真正被创建的那一刻生效，而且会被 umask 削一刀：

c
/* umask 是 0022 时，下面实际得到 0644 */
int fd = open("/tmp/x", O_CREAT | O_WRONLY, 0666);

新权限 = mode & ~umask。想让 mode 原样生效，就先 umask(0) 再建文件，建完再恢复——单进程可以用，多线程程序里别这么干，umask 是进程级全局状态。

O_APPEND 值得单独讲一句。它保证的是「定位到末尾」和「写入」在内核里合成一个原子动作。多个进程同时往一个文件追加，每次 write 的数据不会互相覆盖；但谁先谁后，仍由内核调度决定。想要严格顺序，得靠 flock/fcntl 加锁或单写者模型。

四、read 与 write 的返回值 #

c
#include <unistd.h>

ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);

一句话：count 是上限，返回值是实际搬动的字节数。它从来不是「成功/失败」二值。

read 的返回值：

返回值 含义 怎么办
> 0 实际读到的字节数，可以小于 count 按实际数处理，别假设读满
0 到达文件末尾（普通文件、管道写端全关） 结束循环
-1 + EINTR 读的过程中被信号打断 重试
-1 + EAGAIN/EWOULDBLOCK 非阻塞 fd 当前没数据 等 poll/select/epoll
-1 + EBADF fd 不可读（比如以只写打开的） 查 open 的 flags
-1 + EINVAL 参数不合法，或 fd 不支持读 查代码

write 的返回值：

返回值 含义 怎么办
> 0 实际写入的字节数，可以小于 count 剩下部分继续写
0 一个字节都没写进去，count 为 0 时会出现 检查 count
-1 + EINTR 被信号打断，什么都没写 重试
-1 + EAGAIN 非阻塞 fd 缓冲区满 等可写再写
-1 + EPIPE 对端已关闭，同时会收到 SIGPIPE 忽略信号或处理对端断开
-1 + ENOSPC 设备或文件系统没空间了 报错，别重试
-1 + EFBIG 超过文件大小上限 报错

read 返回 0 是「读完了」，write 返回 0 是「没写进去」。同一个数字，两种意思，别混。

检查返回值的最小写法：

c
ssize_t n = write(fd, buf, len);
if (n < 0) {
    if (errno == EINTR) {
        /* 重试 */
    } else {
        perror("write");
    }
} else if ((size_t)n < len) {
    /* 部分写，剩下的要自己补 */
}

两个容易踩的边界：

  • 单次 read/write 的 count 不要超过 SSIZE_MAX（64 位上是 2^63-1），超过就是未定义行为。实际代码里根本用不到这么大，但要拷大文件时用循环。
  • buf 必须是你真的能读写那么长的内存。内核不会替你检查越界，写超了就踩内存。

五、短读与短写怎么处理 #

返回值小于请求的 count，就叫短读或短写。这不是错误，是这一层的正常行为。谁假设「要多少给多少」，谁的程序就会在某天丢数据。

为什么会短：

场景 表现 原因
管道、FIFO read 返回小于 count 管道缓冲区里当下只有这么多
socket read 返回小于 count 网络包边界与你的 count 无关
读接近文件末尾 read 返回剩余字节数 剩下的不够 count
写管道/socket 缓冲区满 write 返回部分字节 内核缓冲装不下
被信号打断 已搬运的部分照常返回 中断不会回滚已完成的部分
磁盘写接近配额 write 返回部分或 -1 空间不足，前面写的部分已生效
频繁 write 小数据 每次只写一点 内核回写压力大

两个基础函数，先把它们刻进肌肉记忆：

c
#include <unistd.h>
#include <errno.h>

/* 读满 len 字节；返回实际读到的字节数，EOF 时小于 len，出错返回 -1 */
ssize_t read_full(int fd, void *buf, size_t len) {
    size_t got = 0;
    char *p = (char *)buf;
    while (got < len) {
        ssize_t n = read(fd, p + got, len - got);
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;              /* EAGAIN 也走这里，交给调用者 poll */
        }
        if (n == 0) break;           /* EOF */
        got += (size_t)n;
    }
    return (ssize_t)got;
}

c
/* 写满 len 字节；全部写完返回 len，出错返回 -1 */
ssize_t write_full(int fd, const void *buf, size_t len) {
    size_t done = 0;
    const char *p = (const char *)buf;
    while (done < len) {
        ssize_t n = write(fd, p + done, len - done);
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        if (n == 0) break;           /* 极端情况，避免死循环 */
        done += (size_t)n;
    }
    return (ssize_t)done;
}

几个必须说清的点：

  • 缓冲区满导致的 EAGAIN 不要在这里死循环重试，会烧满一个核。非阻塞 fd 的正确姿势是返回给事件循环，等 poll/epoll 报可读可写再来。
  • write_full 循环里 n == 0 一定要 break，否则 done 不增长，直接卡死。
  • 处理消息协议时，长度头和负载要分两次 read_full：先读固定长度的头，解出负载长度，再读负载。别指望一次 read 拿到整条消息。
  • 短读短写的判断依据是「累计字节数和预期是否相等」，不是「返回值是否为负」。

六、lseek 与文件偏移 #

c
#include <unistd.h>

off_t lseek(int fd, off_t offset, int whence);

whence 三选一：

whence 基准点 常见用法
SEEK_SET 文件开头 跳到指定位置
SEEK_CUR 当前偏移 相对当前位置前后移动
SEEK_END 文件末尾 求文件大小、追加定位

返回移动后的新偏移（从文件开头算的绝对值），失败返回 -1 并置 errno，其中 ESPIPE 表示这个 fd 根本不支持定位（管道、FIFO、socket、终端）。所以 ESPIPE 是可以合法出现的，不算异常。

求文件大小：

c
off_t size = lseek(fd, 0, SEEK_END);
if (size < 0) perror("lseek");

更省事的办法是 fstat(fd, &st) 读 st_size，不用动偏移。两者都能用，fstat 更适合「只想看看大小」的场合。

几个关键性质：

  • lseek 只改偏移，不读不写，不搬任何数据。偏移可以设到文件末尾之后，之后一写就在中间留出空洞，形成稀疏文件。空洞部分读出来是全 0，不占磁盘块。
  • 偏移可以设成负数（SEEK_SET 加负偏移），报 EINVAL。但 SEEK_END 配负偏移是合法的。
  • 偏移不是无限的，受 off_t 类型和文件系统上限约束。
  • 偏移存在打开文件表项里，不在 fd 里。这是第九章全部结论的源头。同一个打开文件表项被多个 fd 指向时，它们共用同一个偏移，谁动了一下，别人立刻看到。

两个文件之间的拷贝，用 lseek 做定位是经典写法：

c
off_t off = 0;
char buf[64 * 1024];
ssize_t n;
while ((n = pread(src, buf, sizeof buf, off)) > 0) {
    write_full(dst, buf, (size_t)n);
    off += n;
}

这里用 pread 而不用 read + lseek，原因是多线程同时读同一个 fd 时，read 和 lseek 之间会互相插队，读到错位的数据。pread/pwrite 把「定位 + 搬数据」做成一次原子操作，且完全不碰共享偏移。多线程读同一文件，一律用 pread。

七、文件描述符是什么 #

文件描述符（file descriptor，fd）是内核给「已被打开的文件」建的一个索引，形式是一个非负整数，int 类型，值偏小。

它的定义就这么多，剩下全是推论：

  • POSIX.1 要求每次 open 必须分配当前进程里最小的可用描述符号。所以同一个程序，打开顺序固定，fd 号就是固定的 0、1、2、3……
  • fd 是进程私有的。不同进程里出现同一个 fd 号，指向的东西没有任何关系。
  • 所有执行 IO 的系统调用都靠 fd 定位目标。read/write/lseek/fstat/fsync/ftruncate/close 的参数第一位全是 fd。
  • fd 不是文件。一个文件可以有多个 fd；一个 fd 也只指向一个打开文件。

验证最小可用这条规则：

c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    int a = open("/etc/hosts", O_RDONLY);   /* 3 */
    int b = open("/etc/hosts", O_RDONLY);   /* 4，同一个文件，两个 fd */
    int c = dup(a);                         /* 5 */
    printf("a=%d b=%d c=%d\n", a, b, c);
    close(a);
    int d = open("/etc/hosts", O_RDONLY);   /* 又回到 3 */
    printf("d=%d\n", d);
    close(b); close(c); close(d);
    return 0;
}

注意 a 和 b：同一个文件被 open 了两次，拿到两个不同的 fd，而且是两个不同的打开文件表项，各自有独立的偏移。c 是 a 的副本，和 a 共享同一个打开文件表项，偏移是同一份。这一点在第九章和第十章展开。

Linux 里「一切皆文件」落在这层就是：普通文件、目录、符号链接、字符设备、块设备、FIFO、socket、eventfd、timerfd，全都能给一个 fd。所以能用 read/write/close 处理的接口，一律能复用到别的对象上。这是这一层设计的实际价值。

八、三个标准描述符 #

进程一启动，fd 0、1、2 就已经被占好了：

fd 宏名 名称 默认指向 用途
0 STDIN_FILENO 标准输入 继承自父进程，一般是终端 读数据
1 STDOUT_FILENO 标准输出 继承自父进程，一般是终端 输出正常结果
2 STDERR_FILENO 标准错误 继承自父进程，一般是终端 输出错误与诊断

宏在 <unistd.h> 里。写代码用宏，别写裸数字，可读性差还容易和业务里的 fd 混。

所以「打开一个新文件，fd 会是 3」只是因为 0、1、2 都占着。一旦你 close(1)，下一个 open 就会拿到 1，此后的 printf 输出直接进文件，调试信息跑到别处去了，看起来像程序「不说话」。这就是素材里说的串话：fd 号被复用，你以为在写屏幕，实际在写别的对象。

> file、2>&1、< file 这些 shell 重定向，底层都是 dup2：

c
#include <fcntl.h>
#include <unistd.h>

/* 把标准输出重定向到文件，等价于 shell 的 > out.log */
int fd = open("out.log", O_WRONLY | O_CREAT | O_TRUNC, 0644);
if (fd < 0) return 1;
if (dup2(fd, STDOUT_FILENO) < 0) return 1;
close(fd);                    /* 原来那个号不再需要 */

printf("this goes to out.log\n");

dup2(fd, 1) 之后为什么要 close(fd)？因为 dup2 复制了一份引用，原 fd 还占着一个号。不关就浪费一个描述符，且在长跑进程里会累积。

还有两点：

  • 标准描述符可以被关闭。close(0) 之后 read(0, ...) 返回 -1 加 EBADF。
  • 后台服务常把 0、1、2 全重定向到 /dev/null，防止终端断开时被 SIGHUP 带走，也防止写满终端缓冲区。守护进程的标准做法。

九、fd 与打开文件表 #

这是本篇的核心。同一个文件可以同时被多个进程打开，也可以在同一进程里被多次打开，而 fd 号在不同进程里必然重复。只看 fd 号，什么结论都得不出来。要解释清楚，得看内核维护的三层结构。

层级 名字 作用域 每个条目存什么
第一层 进程级文件描述符表 每个进程一份 fd 标志（目前只定义了 close-on-exec）、指向打开文件表项的引用
第二层 系统级打开文件表（open file description table） 全系统一份 当前偏移、open 的 flags、访问模式、信号驱动设置、指向 inode 的引用、文件类型与权限、锁列表指针、文件属性（大小、时间戳）
第三层 inode 表（i-node table） 全系统一份 文件的真实元数据：设备号、inode 号、权限、硬链接数、所有者、大小、时间戳、数据块位置

第二层的条目，很多文档叫「打开文件句柄」（open file handle），也有叫「打开文件描述」的。名字不重要，重要的是它不是 fd，它是 fd 指向的对象。

三层串起来看：

text
进程 A                     系统级打开文件表              inode 表
┌──────────────┐          ┌──────────────────┐        ┌──────────────┐
│ fd 0 ────────┼─────────>│ 表项 #23         │───┐    │ inode 1976   │
│ fd 1 ────────┼─────────>│ 偏移=1024        │   │    │ 类型: 普通文件│
│ fd 2 ────────┼──┐       │ flags=O_RDWR     │   └───>│ 大小: 8192    │
│ fd 30 ───────┼──┼──────>│ 表项 #23（同一个）│        │ 权限: 0644    │
└──────────────┘  │       └──────────────────┘        └──────────────┘
                  │       ┌──────────────────┐               ↑
                  └──────>│ 表项 #73         │───────────────┘
                          └──────────────────┘
进程 B
┌──────────────┐          ┌──────────────────┐
│ fd 2 ────────┼─────────>│ 表项 #73（同一个）│
│ fd 3 ────────┼─────────>│ 表项 #91         │────> inode 1976（同一文件）
└──────────────┘          └──────────────────┘

按这张图把四种典型情形拆开：

情形 形成方式 fd 关系 打开文件表项 偏移 inode
进程 A 的 fd 1 和 fd 30 dup/dup2/fcntl 复制 不同号，同一进程 同一个（#23） 共享 同一个
进程 A fd 2 与进程 B fd 2 fork 继承，或 UNIX 域套接字传 fd 同号但不同进程 同一个（#73） 共享 同一个
进程 A fd 0 与进程 B fd 3 两个进程各自 open 同一文件 不同号，不同进程 不同（各一份） 各自独立 同一个（1976）
同进程两次 open 同一文件 代码里 open 了两次 不同号 不同 各自独立 同一个

四条结论，直接背下来：

  1. 进程级 fd 表的存在，使不同进程里出现相同的 fd 号。它们指向同一个文件，也指向完全不同的文件，别拿号当身份。
  2. 两个 fd 指向同一个打开文件表项时，共享同一个文件偏移。通过其中一个 fd 改了偏移（read、write、lseek 都会改），另一个 fd 立刻看到变化。无论两个 fd 在同一进程还是分属不同进程，都一样。
  3. 打开文件的状态标志（O_APPEND、O_NONBLOCK、O_ASYNC）也挂在打开文件表项上，用 fcntl 的 F_GETFL/F_SETFL 读写，作用范围与偏移那条一致：同一表项的 fd 全受影响。
  4. fd 标志（close-on-exec）挂在进程级 fd 表条目上，是进程和 fd 私有的。改它不影响同进程的其他 fd，也不影响其他进程。

这就是为什么用 dup2 做重定向之后，父子进程的偏移会互相牵动：它们指向同一个表项。想彻底独立，就得重新 open 一次，拿一个新的表项。

在多线程程序里，同一个 fd 被多个线程共用同一个表项，偏移是共享的。所以并发读写一定要么用 pread/pwrite，要么自己加锁，要么每个线程各开一个 fd。

十、dup 与 dup2：复制描述符 #

c
#include <unistd.h>

int dup(int oldfd);
int dup2(int oldfd, int newfd);
int dup3(int oldfd, int newfd, int flags);   /* Linux 扩展 */

dup 复制一个 fd，新号取最小可用。dup2 复制到指定的 newfd，如果 newfd 已经被占用，先把它关掉再占用。dup3 是 Linux 的扩展，多一个 flags 参数，只支持 O_CLOEXEC。

接口 新 fd 号 newfd 已打开时 原子性 可用标志
dup(fd) 最小可用 不涉及 单调用 无
dup2(fd, n) 等于 n 先隐式 close(n) 单调用原子完成 无
dup3(fd, n, O_CLOEXEC) 等于 n 先隐式 close(n) 单调用原子完成 可带 O_CLOEXEC
fcntl(fd, F_DUPFD, min) 大于等于 min 的最小可用 不涉及 单调用 无
fcntl(fd, F_DUPFD_CLOEXEC, min) 同上 不涉及 单调用 可带 O_CLOEXEC

dup 系列复制出来的新 fd 和原 fd 指向同一个打开文件表项，共享偏移、共享状态标志。这是它和 open 的根本区别。

c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    int fd = open("/tmp/dup.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) return 1;

    write(fd, "0123456789", 10);            /* 偏移到 10 */
    lseek(fd, 0, SEEK_SET);                 /* 偏移回 0 */

    int d = dup(fd);
    char c = 0;
    read(d, &c, 1);                          /* d 读 1 字节，偏移变 1 */
    printf("d read '%c'\n", c);              /* '0' */
    printf("fd offset = %lld\n",             /* 也是 1，共享 */
           (long long)lseek(fd, 0, SEEK_CUR));

    int d2 = dup(fd);                        /* 另一个副本 */
    lseek(d2, 5, SEEK_SET);                  /* 偏移变 5 */
    read(fd, &c, 1);                         /* fd 读到 '5' */
    printf("fd read '%c'\n", c);

    close(d); close(d2); close(fd);
    return 0;
}

输出会验证 d 和 fd 的偏移是同一份。

dup2 的原子性值得强调。下面两种写法的效果看着一样，实际不一样：

c
dup2(fd, STDOUT_FILENO);        /* 原子：close(1) 和占用 1 一起完成 */

close(STDOUT_FILENO);           /* 分两步，遇到信号会断在这里 */
dup(fd);                        /* 拿到的未必是 1 */

多线程程序里，分两步的写法有个窗口期：close(1) 之后、dup(fd) 之前，别的线程正好 open 了一个文件，它就会拿到 fd 1。你的重定向静默失败，还顺手劫持了别人的文件。所以重定向一律用 dup2。

打开文件时带 O_CLOEXEC，或者复制后用 fcntl(fd, F_SETFD, FD_CLOEXEC) 补上 close-on-exec，能避免 fd 泄漏到 exec 之后的子进程里。这是长跑服务和 CGI 类程序里反复出问题的地方。

十一、文件描述符的上限 #

写文件操作或网络通信的程序，迟早撞上 Too many open files。fd 是系统资源，不是无限的。限制分两层，调错层等于白调。

参数 说明 默认值 查询方式
nofile 单个进程的最大打开文件数 1024 ulimit -n 或 cat /proc/<pid>/limits
nr_open 单个进程可分配的最大 fd 数（RLIMIT_NOFILE 的硬上限） 1048576 cat /proc/sys/fs/nr_open
file-max 系统内核一共可以打开的文件数 199708，随内存变化 cat /proc/sys/fs/file-max

nofile 是对单个进程打开的文件句柄数量的限制，打开的套接字也算在里面。file-max 是全系统所有进程加起来一共能打开的文件数量；程序也可以通过 setrlimit 给自己设更紧的限制。

三者的包含关系：

text
fs.file-max（全系统总配额）
  └── fs.nr_open（单个进程 fd 数的硬上限）
        └── RLIMIT_NOFILE 软限制 / 硬限制（nofile）
              └── 进程实际打开的 fd 数量

所以 nofile 的硬限制不能超过 nr_open，nr_open 之和不能超过 file-max。调大 nofile 之前先把 nr_open 抬起来，否则 ulimit -Hn 会直接报错。

错误码要对上：本进程撞到 nofile 是 EMFILE，全系统撞到 file-max 是 ENFILE。

nofile 的临时修改 #

bash
ulimit -SHn 1024000

软硬限制的区别：-H 是硬限制，-S 是软限制。不加 -H/-S 时 ulimit 显示的是软限制，修改时两个一起改。

硬限制是实际的限制，软限制是给程序的告警阈值。普通进程可以把自己的软限制调到硬限制以内，但把硬限制往上抬需要特权。所以真正卡住你的是硬限制。

按进程号查当前值用 cat /proc/$$/limits | grep -i 'open files'，输出分 Soft Limit 和 Hard Limit 两列，比 ulimit -n 更直观。

nofile 的永久修改 #

改 /etc/security/limits.conf：

text
*    soft    nofile    1024000
*    hard    nofile    1024000

* 表示所有用户。也可以写成具体的用户名或 @组名。这是 PAM 的 pam_limits 模块读的文件，只对通过 PAM 登录的会话生效，systemd 服务不认这个文件，那类场景要改 unit 的 LimitNOFILE=。

或者在 /etc/profile 里追加：

bash
ulimit -SHn 128000

/etc/profile 在用户登录时执行，对所有用户生效，管的是 shell 及其子进程。它的局限同样明显：只覆盖登录 shell 的链路，非交互式启动的守护进程拿不到。

系统总限制的临时修改 #

bash
echo 1200000 > /proc/sys/fs/nr_open
echo 200000  > /proc/sys/fs/file-max

写 /proc/sys/ 是瞬时生效，重启就回默认值。顺序不能反：先把 nr_open 抬到 file-max 之下，再抬 file-max。

系统总限制的永久修改 #

写 /etc/sysctl.conf：

text
fs.nr_open=1200000
fs.file-max=200000

保存后执行 sysctl -p 即时生效，不用重启，这是推荐做法。直接往 /proc/sys/fs/nr_open、/proc/sys/fs/file-max 这两个文件里写配置再 reboot，也能生效，但改配置要重启机器，在线上环境里代价太大。

改完用 sysctl -a | grep fs.file-max、sysctl fs.nr_open、ulimit -n 三条验证。

查看各进程打开了多少 fd #

bash
lsof -n | awk '{print $2}' | sort | uniq -c | sort -nr

按进程号聚合，倒序排出 fd 占用最多的进程。-n 关掉 DNS 反解，不然会卡在网络上。

查单个进程用 lsof -p 696 | wc -l。更轻的办法是直接数 /proc 目录，不用起 lsof：

bash
ls /proc/696/fd | wc -l

/proc/<pid>/fd/ 下每个符号链接就是一个 fd，链接目标就是它指向的文件。ls -l 能直接看出哪个管道、哪个 socket 占着号。

十二、stat：获取文件信息 #

c
#include <sys/stat.h>
#include <unistd.h>

int stat(const char *restrict pathname, struct stat *restrict buf);
int fstat(int fd, struct stat *buf);
int lstat(const char *restrict pathname, struct stat *restrict buf);

给一个路径，内核把该文件的属性填进 buf。三兄弟的区别只在「怎么定位文件」：

函数 定位方式 遇到符号链接 适用场景
stat 路径 跟进去，返回目标文件的信息 文件尚未打开
fstat 已有的 fd 不涉及路径解析 文件已经打开，最可靠
lstat 路径 不跟进，返回链接本身的信息 需要看链接自身属性、遍历目录

返回值三者一致：成功返回 0，失败返回 -1 并置 errno。

最小示例：

c
#include <sys/stat.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    struct stat buf;
    if (stat("/etc/hosts", &buf) == 0) {
        printf("/etc/hosts file size = %lld\n", (long long)buf.st_size);
    } else {
        perror("stat failed");
    }
    return 0;
}

stat 的错误码：

errno 含义
ENOENT pathname 不存在
ENOTDIR 路径中某一部分存在，但不是目录
ELOOP 符号链接绕成环，内核解析上限为 16 层
EFAULT buf 是无效指针，指向无法访问的内存
EACCES 路径中某一级目录缺搜索权限，访问被拒
ENOMEM 内核内存不足
ENAMETOOLONG 路径名过长

想判断一个路径是不是目录，用 fstat + S_ISDIR 比字符串判断靠谱；想在遍历目录时不跟着符号链接跑出去，用 lstat。这也是 ls -l 和 ls -L 的差别所在：前者用 lstat，后者用 stat。

十三、stat 结构体的字段 #

c
struct stat {
    dev_t         st_dev;       /* 文件所在设备的编号 */
    ino_t         st_ino;       /* 文件的 inode 号 */
    mode_t        st_mode;      /* 文件类型和访问权限 */
    nlink_t       st_nlink;     /* 连接到该文件的硬链接数 */
    uid_t         st_uid;       /* 文件所有者的用户 ID */
    gid_t         st_gid;       /* 文件所有者的组 ID */
    dev_t         st_rdev;      /* 设备号，仅设备文件有意义 */
    off_t         st_size;      /* 文件的字节数 */
    blksize_t     st_blksize;   /* 文件系统偏好的 IO 块大小 */
    blkcnt_t      st_blocks;    /* 已分配的 512 字节块数量 */
    struct timespec st_atim;    /* 最后访问时间 */
    struct timespec st_mtim;    /* 内容最后修改时间 */
    struct timespec st_ctim;    /* 状态最后改变时间 */
};

字段含义与用途：

字段 含义 实际用途
st_dev 文件所在设备的编号 判断两个路径是否在同一文件系统上，跨设备 rename 会失败
st_ino inode 号，文件系统内唯一 配合 st_dev 唯一确定一个文件；硬链接的多个路径 st_ino 相同
st_mode 文件类型 + 权限位 S_ISREG 等宏判断类型，权限位判断读写的可行性
st_nlink 硬链接数量 为 0 表示文件已删但还有进程持有 fd
st_uid / st_gid 所有者的用户 ID / 组 ID 权限判定、审计
st_rdev 设备文件的设备号 只有字符设备和块设备有意义
st_size 普通文件的字节数 读文件前预分配缓冲；对目录无意义
st_blksize 文件系统实现推荐的 IO 块大小 决定 read/write 的缓冲大小，比随便定一个 4096 更贴合存储
st_blocks 已分配的 512 字节块数 与 st_size/512 对比可发现稀疏文件；st_blocks < st_size/512 说明有空洞
st_atim 最后访问时间 了解文件使用情况
st_mtim 内容最后修改时间 make 靠它判新旧
st_ctim inode 状态最后改变时间 改权限、改所有者、加硬链接都会刷新它，改内容也刷新

三个时间戳别搞混：mtime 只在内容变化时更新，ctime 只要 inode 有变化就更新（包括改权限、改名、改硬链接数），atime 是读的时候更新。所以改一个文件的权限，mtime 不动，ctime 会变。用 mtime 判「文件内容是否变过」是对的，用 ctime 判「文件是否被动过」才是对的。

关于结构体成员的名字，不同标准下有差异：老代码里写 st_atime、st_mtime、st_ctime，POSIX.1-2008 里正规的名字是 st_atim、st_mtim、st_ctim，配 st_atim.tv_nsec 拿纳秒。glibc 保留了旧名字做兼容，条件是不加严格的标准宏。新代码用带 nsec 的版本。

st_mode 的类型位：

宏 八进制值 含义
S_IFMT 0170000 文件类型位的掩码
S_IFSOCK 0140000 套接字
S_IFLNK 0120000 符号链接
S_IFREG 0100000 普通文件
S_IFBLK 0060000 块设备
S_IFDIR 0040000 目录
S_IFCHR 0020000 字符设备
S_IFIFO 0010000 先进先出（FIFO）

特殊权限位：

宏 八进制值 含义
S_ISUID 04000 执行时把 EUID 设为文件所有者
S_ISGID 02000 执行时把 EGID 设为文件所属组；对目录表示新建文件继承目录的组
S_ISVTX 01000 sticky 位

权限位：

宏 八进制值 含义 别名
S_IRUSR 00400 所有者可读 S_IREAD
S_IWUSR 00200 所有者可写 S_IWRITE
S_IXUSR 00100 所有者可执行 S_IEXEC
S_IRGRP 00040 同组可读
S_IWGRP 00020 同组可写
S_IXGRP 00010 同组可执行
S_IROTH 00004 其他用户可读
S_IWOTH 00002 其他用户可写
S_IXOTH 00001 其他用户可执行

POSIX 定义了类型判断宏，直接用，别自己拿 st_mode & S_IFMT 比：

宏 判断
S_ISLNK(m) 符号链接
S_ISREG(m) 普通文件
S_ISDIR(m) 目录
S_ISCHR(m) 字符设备
S_ISBLK(m) 块设备
S_ISSOCK(m) 套接字
S_ISFIFO(m) FIFO

目录上设了 sticky 位（S_ISVTX）之后，该目录下的文件只能由文件所有者、目录所有者或 root 删除与重命名。/tmp 就是这么配的，权限 1777：谁都能建文件，但只能删自己的。

一段完整的用法：

c
#include <sys/stat.h>
#include <stdio.h>
#include <time.h>

static const char *kind(mode_t m) {
    if (S_ISREG(m))  return "regular";
    if (S_ISDIR(m))  return "directory";
    if (S_ISLNK(m))  return "symlink";
    if (S_ISCHR(m))  return "chardev";
    if (S_ISBLK(m))  return "blockdev";
    if (S_ISFIFO(m)) return "fifo";
    if (S_ISSOCK(m)) return "socket";
    return "unknown";
}

int main(int argc, char **argv) {
    if (argc < 2) return 1;
    struct stat st;
    if (stat(argv[1], &st) < 0) { perror("stat"); return 1; }

    printf("type      : %s\n", kind(st.st_mode));
    printf("inode     : %llu\n", (unsigned long long)st.st_ino);
    printf("size      : %lld\n", (long long)st.st_size);
    printf("blocks    : %lld\n", (long long)st.st_blocks);
    printf("blksize   : %lld\n", (long long)st.st_blksize);
    printf("links     : %llu\n", (unsigned long long)st.st_nlink);
    printf("mode      : %04o\n", st.st_mode & 07777);
    printf("mtime     : %s", ctime(&st.st_mtim.tv_sec));
    return 0;
}

文件内容读完之后再 fstat 一次，能发现「读的过程中文件被改短了」这种并发问题：st_size 和实际读到的字节数对不上，就说明有人在动这个文件。

十四、其他属性查询接口 #

stat 只覆盖单个文件。要查文件系统整体、查权限、查链接目标，还有一组接口。

文件系统级别的信息用 statfs/fstatfs：

c
#include <sys/vfs.h>      /* Linux，statfs 与 struct statfs */

int statfs(const char *path, struct statfs *buf);
int fstatfs(int fd, struct statfs *buf);

struct statfs {
    long    f_type;          /* 文件系统类型 */
    long    f_bsize;         /* 块大小 */
    long    f_blocks;        /* 总块数 */
    long    f_bfree;         /* 空闲块数 */
    long    f_bavail;        /* 非特权用户可用的块数 */
    long    f_files;         /* 文件节点总数 */
    long    f_ffree;         /* 空闲文件节点数 */
    fsid_t  f_fsid;          /* 文件系统 ID */
    long    f_namelen;       /* 文件名最大长度 */
    long    f_spare[6];      /* 备用字段 */
};

f_bavail 和 f_bfree 要分开：df 报的「可用」用 f_bavail，因为 ext 系文件系统默认给 root 预留 5%，root 能用的比普通用户多。算「还能写多少」用 f_bavail * f_bsize。

f_files 和 f_ffree 管的是 inode 数量。磁盘还有空间但 inode 用完，照样报 ENOSPC，创建不了新文件——df -i 就是看这个。

其他常用接口：

接口 原型 作用
access int access(const char *path, int mode) 按真实 UID/GID 检查权限，R_OK/W_OK/X_OK/F_OK
faccessat int faccessat(int dirfd, const char *path, int mode, int flags) 同上，可指定基准目录、可带 AT_EACCESS 改用 EUID 判定
readlink ssize_t readlink(const char *path, char *buf, size_t len) 读符号链接指向的路径，不以 \0 结尾
readlinkat ssize_t readlinkat(int dirfd, const char *path, char *buf, size_t len) 同上，相对目录 fd
truncate int truncate(const char *path, off_t len) 按路径截断
ftruncate int ftruncate(int fd, off_t len) 按 fd 截断
chmod/fchmod int fchmod(int fd, mode_t mode) 改权限
chown/fchown int fchown(int fd, uid_t u, gid_t g) 改所有者
utimensat int utimensat(int dirfd, const char *path, const struct timespec ts[2], int flags) 精确改 atime/mtime，支持纳秒

access 有两个坑：它检查的是真实 UID/GID，而 open 判定权限用的是 EUID/EGID。setuid 程序里两者不同，access 说能写、open 却被拒，是这个原因。AT_EACCESS 就是为这个场景准备的。

readlink 的返回值是写入 buf 的字节数，但它不在末尾补 \0。所以必须自己补：

c
char buf[4096];
ssize_t n = readlink("/proc/self/exe", buf, sizeof buf - 1);
if (n < 0) { perror("readlink"); return 1; }
buf[n] = '\0';
printf("exe -> %s\n", buf);

buf 太小的时候，readlink 会截断并不报错，返回值就是 len。想确认有没有被截断，看返回值是否等于传入的 len。

access 加 F_OK 是最省事的「文件存在吗」检查，但要清楚它和随后 open 之间有竞态（TOCTOU）。安全相关的代码里，直接用 open 带 O_CREAT|O_EXCL 或 O_NOFOLLOW，别先检查再操作。

十五、易错点速查 #

症状 真实原因 正确做法
read 返回值存进 size_t 后判 < 0 永远为假 无符号类型装不下 -1 用 ssize_t 接返回值
拷大文件后内容缺了一截 忽略短读短写 循环读到 0 / 循环写到 done == len
多线程读同一 fd 数据错位 read 与 lseek 之间被抢 用 pread/pwrite
write 返回部分字节就当成功 只处理了 -1 判断 (size_t)n < len 并补写
close 返回 -1 后重试 fd 在返回前已释放 不重试，只记日志
重定向后输出跑丢 close(1) 后 fd 1 被别人抢走 用 dup2 一步完成
if (flags & O_RDONLY) 判断失败 O_RDONLY 的值是 0 用 flags & O_ACCMODE
建文件权限比 mode 少 umask 削掉了 新权限 = mode & ~umask
O_CREAT 没给 mode 缺第三个参数 补上 mode
报 EMFILE 却去调 fs.file-max 进程级限制当成了系统级 调 ulimit -n / nofile
报 ENFILE 却去调 ulimit -n 系统级限制当成了进程级 调 fs.file-max
被信号打断后 read 返回 -1 errno == EINTR 没重试 判断 EINTR 继续
非阻塞 fd 上死循环 EAGAIN 被当成错误重试 交给 poll/epoll 等事件
lseek 在管道上失败 ESPIPE 是预期结果 管道不可定位，改用带偏移的协议设计
stat 拿不到符号链接自身信息 用了 stat 跟进去了 用 lstat
st_blocks 远小于 st_size/512 稀疏文件，空洞不占块 正常现象，du 会报实际占用
磁盘有空间却创建不了文件 inode 耗尽 df -i 看 f_ffree
readlink 结果尾部有垃圾 未手动补 \0 buf[n] = '\0'
fd 泄漏，越跑越少 dup2 后没 close 原 fd；或没带 O_CLOEXEC 复制后关原 fd，打开时加 O_CLOEXEC
子进程继承了不该有的 fd 没设 close-on-exec open 带 O_CLOEXEC 或 fcntl(F_SETFD, FD_CLOEXEC)
两个 fd 偏移互相干扰 以为 dup 是独立副本 dup 共享表项；要独立偏移就重新 open

最后把判断的逻辑收成三条，遇到文件 IO 问题按顺序过一遍：

  1. 先看返回值类型和取值。-1、0、>0 三个分支都覆盖了吗？EINTR 处理了吗？
  2. 再看 fd 是谁的。它是本进程的号，指向哪个打开文件表项？这个表项还有谁在指？偏移和标志是谁共享的？
  3. 最后看权限与配额。是 EACCES（权限）、EMFILE（进程 fd 上限）还是 ENFILE（系统 fd 上限）？三者修法完全不同。
