一、进程是什么：程序与进程的差别 #

程序是磁盘上的一堆指令加一堆数据，躺着不动。进程是这堆东西被内核装进内存、拿到资源、能跑起来的那个实体。你开两个终端各跑一个 vim，磁盘上还是那一个文件，内存里是两个互不相干的进程。

对比项 程序 进程
存在形态 静态文件，二进制或脚本 动态实体，占内存与 CPU
数量关系 一份程序 可被多个进程同时跑，各自独立
生命周期 躺着不灭 创建、调度、阻塞、退出、回收
内核描述 无 task_struct + mm_struct + 页表

进程有四大要素，这套老教材口径在 Linux 上对得上：

要素 说明
执行的程序 具体代码与初始数据，多进程可跑同一份程序
独立的内核栈 每个进程一份，陷入内核时用，不共享
进程控制块 PCB Linux 里就是 task_struct，记状态、PID、优先级、mm、文件表
独立的存储空间 自己的用户态虚拟地址空间，别人看不见

线程只占前三个，第四个没有——这是后面所有差异的根。

教材说「进程既是资源分配单位也是调度单位」。后半句在 Linux 上不成立：真正上 CPU 的是线程，进程退化成线程组的容器。微内核系统（Mach、Windows NT）把这件事摆得更明白，进程只管资源，线程负责执行；Linux 反过来用一套 task_struct 描述两者，靠标志位区分。

按行为分三类，调度的难点就在同时伺候这三类：

类型 特征 典型代表 响应要求
交互式 Shell 拉起，频繁等输入 终端、编辑器、GUI 50~150ms 内响应
批处理 后台跑，没人盯 编译器、数据库查询、科学计算 不敏感
实时 有硬时限，不能被低优先级堵住 音视频处理、机器人控制 由调度策略保证

用户态能碰的是 nice 值，内核换算成 static_prio：

text
static_prio = 120 + nice        nice 取值 -20 .. +19
                            → static_prio 取值 100 .. 139

nice 越小优先级越高，默认 0 对应 static_prio 120。实时进程另用 rt_priority，取值 1~99（MAX_RT_PRIO 是 100，0 留给普通进程）。素材原文写「实时优先级值为 1000」，跟内核定义对不上，见文末勘误。

c
#include <unistd.h>
int nice(int inc);                                 /* 只能加，降不回去 */

#include <sys/resource.h>
int setpriority(int which, id_t who, int prio);    /* 可升可降，要权限 */
int getpriority(int which, id_t who);

nice() 只加不减是老坑：想把 nice 从 10 调回 0，nice(-10) 会失败，得用 setpriority()，非 root 还只能往低优先级调。看家底用 ps -eo pid,ppid,ni,stat,comm，NI 列就是 nice。PRI 列的映射规则各版本 procps 有差异，本篇不拍板。

O(1) 调度器时代还有一套动态优先级与时间片公式（bonus 随平均睡眠时间浮动，睡得多说明是 I/O 型，奖励先跑），2.6.23 换成 CFS 后整体作废，只剩历史意义：

text
动态优先级 = max(100, min(static_prio - bonus + 5, 139))     bonus ∈ [0, 10]
static_prio < 120 时：时间片(ms) = (140 - static_prio) * 20
static_prio >= 120 时：时间片(ms) = (140 - static_prio) * 5

二、进程的内存空间布局 #

32 位 Linux 把 4GB 虚拟地址一刀切两半：低 3GB 给用户，每个进程私有；高 1GB 给内核，所有进程共享同一份映射。

text
0xFFFFFFFF  +---------------------------+
            |   内核空间 (1GB)           |  所有进程共享
            |   0xC0000000 - 0xFFFFFFFF  |
0xC0000000  +---------------------------+
            |   用户空间 (3GB)           |  每个进程私有
            |   0x00000000 - 0xBFFFFFFF  |
0x00000000  +---------------------------+

x86-64 下用户态能寻址到 0x00007fffffffffff（四级页表，47 位地址位宽），内核映射在高半部 0xffff800000000000 往上。五级页表（LA57）从 4.14 起可选支持，把用户空间再抬 7 位，发行版默认是否开启未验证。

用户空间不是一整块，切成若干段，段之间留空洞，越界访问就落进空洞里触发异常：

text
高地址  +---------------------------+
        |  命令行参数 / 环境变量      |  argv, envp
        +---------------------------+
        |  栈 stack                  |  向下增长，局部变量、返回地址
        |            ↓               |
        |            ↑               |
        |  堆 heap                   |  向上增长，malloc 出来的
        +---------------------------+
        |  bss 段                    |  未初始化全局变量，启动时清零
        +---------------------------+
        |  data 段                   |  已初始化全局变量、静态变量
        +---------------------------+
低地址  |  text 段                   |  机器指令，只读可执行
        +---------------------------+

硬编码地址不可靠，ASLR 会把栈、堆、mmap 区随机化。要观察布局就打印变量地址：

c
#include <stdio.h>
#include <stdlib.h>

int g_init = 1;        /* data */
int g_zero;            /* bss  */

int main(void) {
    int local = 3;                 /* stack */
    int *heap = malloc(64);        /* heap  */
    printf("text %p data %p bss %p heap %p stack %p\n",
           (void *)main, (void *)&g_init, (void *)&g_zero,
           (void *)heap, (void *)&local);
    free(heap);
    return 0;
}

跑两遍，栈和堆地址每次都变，text 段受 PIE 影响也变。

可执行文件不会整个塞进物理内存。内核只把页表项建好，标成「存在但未加载」，访问到哪页才读哪页，这叫请求调页（demand paging）。malloc 同样套路：先挪堆顶指针或挂一个 vm_area_struct 描述这段虚拟区间，物理页一张不给。

text
进程访问虚拟地址 v
        ├── v 在当前进程地址空间内？
        │       ├── 是 → 分配物理页、填 PTE、需要时从文件或 swap 读入
        │       │        回到触发缺页的指令重试，正常往下跑
        │       └── 否 → 投递 SIGSEGV，进程收到「段错误 (core dumped)」
        └── 权限不对（写只读页）→ 也走 SIGSEGV，除非是 COW 页

「段错误」不是内核崩了，是你的进程访问了不该访问的地址，内核把它杀了。COW 页的写缺页是另一种情况，内核悄悄复制一份让写入方继续，进程完全无感。

三、进程的创建：fork 家族 #

c
#include <sys/types.h>
#include <unistd.h>

pid_t fork(void);

返回值有三种情况，这是最容易记混也最容易考的地方：

返回值 出现在哪里 含义
> 0 父进程 拿到新子进程的 PID
== 0 子进程 表示「你是复制出来的那个」
< 0 父进程 创建失败，errno 说明原因（EAGAIN 进程数超限、ENOMEM 内存不够）

子进程不需要靠返回值知道自己的 PID，getpid() 一调就有。返回值设计成 0，是为了让父进程能马上知道子进程是谁，好去 waitpid() 收尸。

c
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void) {
    int shared = 100;
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }

    if (pid == 0) {
        shared = 200;
        printf("[child]  pid=%d ppid=%d shared=%d\n", getpid(), getppid(), shared);
        _exit(0);
    }
    waitpid(pid, NULL, 0);
    printf("[parent] pid=%d child=%d shared=%d\n", getpid(), pid, shared);
    return 0;
}

子进程的 shared 是 200，父进程的还是 100：fork() 之后各有一份副本，改谁都不影响谁。父子谁先跑完全由调度器决定，代码里不能有任何依赖顺序的假设。

写时复制（COW） #

早期 UNIX 的 fork() 物理拷贝整个地址空间，进程一大就慢得没法看。现代 Linux 用写时复制：fork() 时不复制物理页，父子共享同一批物理页，页表项全改成只读；谁想写，谁触发只读缺页异常；内核此时才复制那一页的物理副本，重新映射给写的一方。代价从「整个地址空间」降到「实际被写的页」，所以 fork() 一个几百 MB 的进程只花几百微秒——只要它不写。COW 从 2.0 时代就有，具体引入版本未验证。

内核里的路径 #

fork() 对应 sys_fork，vfork() 对应 sys_vfork，clone() 对应 sys_clone，三个最终落到同一个 do_fork()，核心是 copy_process()：dup_task_struct() 复制 PCB，分配内核栈所在内存页，复制 thread_info，改新 PID 并挂进进程链表建立父子关系，再把系统调用现场的寄存器快照复制一份，把返回值 ax 显式置 0，把调度起点设成 ret_from_fork。

子进程被调度起来的第一条指令就是 ret_from_fork，从那里返回用户态，于是它在用户态看到的就是「fork() 返回了 0」。

text
copy_process()
  ├── dup_task_struct()                     复制 PCB，新 task_struct
  ├── alloc_thread_info_node()              分配内核栈所在的内存页
  ├── setup_thread_stack()                  复制 thread_info 相关数据
  ├── 修改副本：新 PID、进程链表、父子关系
  ├── *childregs = *current_pt_regs()       复制系统调用现场的寄存器
  ├── childregs->ax = 0                     子进程 fork 返回 0
  ├── p->thread.sp = childregs              子进程的内核栈顶
  └── p->thread.ip = ret_from_fork          子进程的第一条指令

⚠️ 这是 2.6 时代的写法。thread_info 后来被移进 task_struct（CONFIG_THREAD_INFO_IN_TASK，4.x 后期，具体版本未逐版核对），不再单独分配，alloc_thread_info_node/setup_thread_stack 这两个函数名在后来的内核里已经不存在。看新内核源码别按这段找。

vfork：不复制，但拖着父进程 #

c
#include <sys/types.h>
#include <unistd.h>
pid_t vfork(void);

vfork() 连 COW 都不做，子进程直接在父进程的地址空间里跑，数据段和堆栈段全共享，写一个变量父进程那边同步就变了。它有两个硬约束：子进程先跑，父进程被内核挂起直到子进程 exec 或 exit；子进程绝对不能 return，因为它用的是父进程的栈，return 会一路改掉父进程的栈帧。

c
/* 反面教材：子进程 return 了 */
pid_t pid = vfork();
if (pid == 0) {
    do_something();
    return 0;        /* ← 错。必须 _exit(0); 或 execl(...) */
}

违反第二条轻则栈数据错乱，重则父子互相等对方永久卡死。fork + 立刻 exec 的组合历史上用 vfork 能省掉整套页表复制，现代内核里 fork 已经是 COW，这个优势基本没了，vfork 只剩兼容价值。glibc 里 vfork() 的实现就是 clone(CLONE_VM | CLONE_VFORK | SIGCHLD)，具体封装未逐版本核对。

clone：能控到哪些资源共享 #

fork 和 vfork 都是 clone 的固定参数预置版。要精细控制共享范围就直接调：

c
#define _GNU_SOURCE
#include <sched.h>

int clone(int (*fn)(void *), void *child_stack, int flags, void *arg, ...);

fn 是子进程入口，不是从 clone 的下一条语句继续，而是从 fn 开始；child_stack 必须由调用者自己 malloc 出来，指向栈的高地址端；flags 决定共享哪些资源；arg 传给 fn。

标志 共享/新建什么
CLONE_VM 共享地址空间（mm_struct），线程的核心标志
CLONE_FS 共享文件系统信息（工作目录、根目录、umask）
CLONE_FILES 共享文件描述符表
CLONE_SIGHAND 共享信号处理函数表，用这个必须同时用 CLONE_VM
CLONE_THREAD 放进同一个线程组，新任务与调用者同 tgid（2.4 起）
CLONE_SETTLS 设置新的 TLS 描述符，线程局部存储靠它
CLONE_NEWPID 新建 PID namespace，里面的进程看到自己是 1 号
CLONE_NEWNS 新建 mount namespace
CLONE_NEWUTS 新建 UTS namespace（hostname 隔离）
CLONE_NEWIPC 新建 IPC namespace
CLONE_NEWNET 新建网络 namespace
CLONE_NEWUSER 新建 user namespace（2.6.23 起）
CLONE_NEWCGROUP 新建 cgroup namespace（4.6 起）
CLONE_NEWTIME 新建 time namespace（5.6 起）

NPTL 就是靠 clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD | CLONE_SETTLS | ...) 造出符合 POSIX 的线程。三个接口摆一张表：

维度 fork() vfork() clone()
地址空间 COW，写时才复制页 完全共享父进程的 看 CLONE_VM
文件描述符表 复制一份新的，指向同一个 file 对象 同 fork 看 CLONE_FILES
执行顺序 父子并发，谁先不确定 强制子先跑，父被挂起 看 CLONE_VFORK
子进程入口 fork() 下一行 vfork() 下一行 由 fn 指定
子进程栈 内核复制好的 借用父进程的 调用者自己提供
危险点 基本没有 子进程 return 会毁父进程栈 标志位配错会造出语义不明的进程
典型用途 通用建进程 历史包袱，兼容用 造线程、造 namespace

四、exec 族与程序替换 #

fork 只复制出一个自己。要让子进程跑别的程序，得用 exec 族把当前进程映像整个换掉：换代码段、数据段、堆、栈，也换页表映射；不换的是 PID、父进程关系、已打开的文件描述符（除非设了 FD_CLOEXEC）、真实用户 ID。所以 shell 里 ls 的 PID 不会因为执行了 ls 而变化——ls 就是在这个 PID 里跑的。

c
#include <unistd.h>

int execl (const char *path, const char *arg, ... /* (char *) NULL */);
int execv (const char *path, char *const argv[]);
int execle(const char *path, const char *arg, ... /*, char *const envp[] */);
int execve(const char *pathname, char *const argv[], char *const envp[]);
int execlp(const char *file, const char *arg, ... /* (char *) NULL */);
int execvp(const char *file, char *const argv[]);

后缀字母：l（list）参数一个个列出来，必须以 (char *)NULL 结尾；v（vector）参数打包成 argv[]；p（path）第一个参数只给文件名，自动按 $PATH 找；e（environment）自己传 envp[]，不继承当前环境。

函数 参数形式 找不找 PATH 传不传 envp
execl 列表 否，给完整路径 否，继承
execv 数组 否，给完整路径 否，继承
execlp 列表 是 否，继承
execvp 数组 是 否，继承
execle 列表 否 是
execve 数组 否 是

execve 是这一族里唯一的系统调用，其余五个都是 glibc 在它上面加的糖。返回值只有一种情况有意义：失败返回 -1，errno 说明原因，然后继续执行后面的代码。成功的话整个地址空间都被覆盖，调用点后面那些行根本不存在了。

c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("[main] 即将被 ps 顶替\n");
    fflush(stdout);                       /* exec 前冲刷，否则丢了 */

    char *args[] = {"ps", "-ef", NULL};
    execvp("ps", args);

    perror("execvp");                     /* 能走到这里说明失败了 */
    return 1;
}

跑完终端只看到 ps -ef 的输出，printf 那行也在——因为手动 fflush 了。不 flush 的话，缓冲区内容会跟着整个用户空间一起被丢弃。

shell 干活的标准姿势是 fork + exec，注意子进程 exec 失败后必须 _exit，不能让它继续跑父进程的代码：

c
pid_t pid = fork();
if (pid == 0) {
    execlp("ls", "ls", "-l", NULL);
    _exit(127);                /* exec 失败，用 127 告诉父进程 */
}
waitpid(pid, &status, 0);

退出码用 127 是 shell 的约定（command not found）。

system() 和 exec 不是一回事 #

c
#include <stdlib.h>
int system(const char *command);

system() 是 C 库函数，不是系统调用。它内部依次做三件事：fork() 一个子进程；子进程里 execl("/bin/sh", "sh", "-c", command, (char *)0) 把命令交给 shell 解释；父进程 waitpid() 等子进程结束并返回其状态。

维度 exec 族 system()
当前进程映像 被彻底覆盖，后面代码全没 原封不动
主进程状态 已经不存在了 阻塞挂起，等子进程跑完再继续
有没有 shell 没有，直接执行程序 有，/bin/sh -c 负责解析
开销 低，只换映射 高，fork + exec + waitpid + 起 shell

返回值：-1 表示 fork 失败，其余是子进程的 wait 状态，要用 WIFEXITED/WEXITSTATUS 拆。细节见 man 3 system。

五、进程的终止与回收：waitpid #

exit 和 _exit 差在缓冲区 #

两个函数都能结束进程，内核那边做的事一样：关掉文件描述符、释放内存、给父进程留个退出状态。区别全在用户态。

text
exit(3)  [glibc]
  ├── 1. 按注册逆序调用 atexit() / on_exit() 挂上的函数
  ├── 2. fflush 所有打开的 stdio 流，把缓冲区数据写完
  ├── 3. 关闭所有打开的流
  └── 4. 调 _exit(2) → 内核释放 mm、关闭 fd、留退出状态、留个僵尸壳子

_exit(2) [系统调用]
  └── 直接进内核，上面三步一件都不做

c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("Hello World");      /* 没换行，数据停在 stdout 缓冲区里 */
    _exit(0);                   /* 缓冲区被直接扔掉，终端一片空白 */
    /* 换成 exit(0) 就会打印出来 */
}

重定向到文件时这个坑更明显：终端是行缓冲，遇到换行就刷；文件是全缓冲，攒到 4KB 才刷。循环里 printf 一堆没换行的内容再 _exit，文件里什么都没有。铁律：子进程 exec 失败后退出用 _exit()，其余情况用 exit()。

wait 和 waitpid #

c
#include <sys/types.h>
#include <sys/wait.h>

pid_t wait(int *status);
pid_t waitpid(pid_t pid, int *status, int options);

wait() 阻塞到任意一个子进程结束，返回其 PID，状态写进 status。没有子进程立刻返回 -1，errno 是 ECHILD。waitpid() 把「等谁」和「怎么等」拆成两个参数。

pid 取值 等谁
> 0 只等 PID 等于它的那个子进程
== -1 等任意子进程，等同 wait()
== 0 等同一个进程组里的任意子进程
< -1 等进程组 ID 等于 pid 绝对值的任意子进程
options 取值 行为
0 阻塞等，子进程不退出就不返回
WNOHANG 非阻塞，没有已退出的子进程就立刻返回 0
WUNTRACED 子进程被 SIGSTOP/SIGTSTP 停下时也返回，默认不管
WCONTINUED 收到 SIGCONT 恢复的子进程也报告（2.6.10 起）

返回值：> 0 是收掉的子进程 PID，0 是 WNOHANG 下没有可收的，-1 是出错（ECHILD 没有子进程，EINTR 被信号打断）。WNOHANG 管「别堵着我」，WUNTRACED 管「停下的也算有结果」。

status 怎么拆 #

status 不是退出码，是一堆位，必须用宏拆，status >> 8 不规范：

宏 判断什么 配套宏
WIFEXITED(status) 是否正常退出 WEXITSTATUS(status) 取退出码低 8 位
WIFSIGNALED(status) 是否被信号杀掉 WTERMSIG(status)、WCOREDUMP(status)
WIFSTOPPED(status) 是否处于暂停态 WSTOPSIG(status) 取导致暂停的信号
WIFCONTINUED(status) 是否被 SIGCONT 恢复 无 
c
if (WIFEXITED(status))          printf("正常退出，码 %d\n", WEXITSTATUS(status));
else if (WIFSIGNALED(status))   printf("被信号 %d 干掉\n", WTERMSIG(status));
else if (WIFSTOPPED(status))    printf("被信号 %d 暂停\n", WSTOPSIG(status));

退出码只有低 8 位传给父进程，exit(256) 实际传出去的是 0。被信号杀掉时没有退出码，shell 里 $? 显示 128+N，那是 shell 自己算的，不是内核给的。

WNOHANG 轮询收尸 #

c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }

    if (pid == 0) {
        printf("[child] pid=%d，睡 3 秒\n", getpid());
        sleep(3);
        _exit(110);
    }

    int status;
    pid_t ret;
    while ((ret = waitpid(pid, &status, WNOHANG)) == 0) {
        printf("[parent] 子进程还在跑，父进程干点别的\n");
        sleep(1);
    }

    if (ret > 0) {
        if (WIFEXITED(status))
            printf("[parent] 收到 pid=%d，退出码=%d\n", ret, WEXITSTATUS(status));
        else
            printf("[parent] 子进程异常结束\n");
    } else {
        perror("waitpid");
    }
    return 0;
}

while 条件是 == 0。写成 != pid 会在出错时死循环，写成 if 只检查一次。

六、僵尸进程与孤儿进程 #

子进程退出后，内核把它的内存、文件、页表全收回，但 task_struct 留着——里面存着退出码和终止信号，父进程得靠它才知道孩子怎么死的。这个只剩壳子的状态就是僵尸。

父进程一直不来收，僵尸就一直占着那个 PID。PID 有上限（/proc/sys/kernel/pid_max，32 位默认 32768，64 位常见 4194304，具体以本机为准），僵尸堆满后 fork() 开始返回 EAGAIN，整台机器再也起不了新进程。

对比项 僵尸进程 孤儿进程
怎么来的 子进程死了，父进程没 wait 父进程先死了，子进程还活着
进程状态 Z，ps 里显示 <defunct> R/S/D 正常跑着
谁管它 等它的父进程 被 init（PID 1）或 systemd --user 收养
占不占资源 只占一个 PID 和一点内核内存 正常占资源
有没有害 有，堆积会耗尽 PID 没有，换个爹继续活
怎么处理 父进程 wait，或让父进程先死 不用处理

认僵尸用 ps -eo pid,ppid,stat,comm | awk '$3 ~ /^Z/'，STAT 列以 Z 开头、comm 后面跟 <defunct>。或者直接看 /proc/<pid>/status，State: 是 Z (zombie)，PPid 就是那个该收尸却没动手的父进程。

四招处理：

一、父进程老实 wait。 最简单也最该做，起几个子进程就收几次。

二、SIGCHLD 里收。 父进程有别的活要干，不能堵在 wait 上，就让内核在子进程死时通知它：

c
#include <signal.h>
#include <sys/wait.h>
#include <errno.h>

static void on_sigchld(int sig) {
    (void)sig;
    int saved = errno;
    int status;
    /* 必须循环，一次信号对应多个已退出的子进程 */
    while (waitpid(-1, &status, WNOHANG) > 0)
        ;
    errno = saved;
}

int main(void) {
    struct sigaction sa;
    sa.sa_handler = on_sigchld;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);
    return 0;
}

三处容易写错：while 不能换成 if；处理函数里必须保存并恢复 errno；SA_RESTART 决定被信号打断的系统调用要不要自动重启。

三、明确告诉内核别留僵尸。 signal(SIGCHLD, SIG_IGN); 或 sigaction 里设 SA_NOCLDWAIT，效果一样。⚠️ 这里 POSIX 与 Linux 之间有历史语义差异，不同 libc 和内核版本表现不完全一致（SA_NOCLDWAIT 从 2.6 起行为稳定）。生产代码优先用第二招。

四、双 fork。 让中间进程立刻退出，孙子被 init 收养，中间进程那个僵尸马上被 init 收掉：

c
pid_t pid = fork();
if (pid == 0) {
    if (fork() == 0) {
        do_the_real_work();     /* 孙进程：已是孤儿，init 收养 */
        _exit(0);
    }
    _exit(0);                   /* 中间进程立刻退出 */
}
waitpid(pid, NULL, 0);          /* 只收中间进程，很快 */

守护进程就是这么脱离终端的，细节见《守护进程》。

八、线程是什么：与进程的关系 #

传统多任务系统里，一个可独立调度的顺序执行流就是一个进程，每个程序加载到内存只对应一个执行流。这个模型有两个现实问题：进程切换要换地址空间和 task_struct，开销大；进程间不共享地址空间，协作全靠 IPC。于是有了轻量级进程（Lightweight Process, LWP），也就是线程：多个执行流共享同一个地址空间。

Linux 没为线程单独造数据结构，全盘复用进程那套：沿用 task_struct 描述每个线程；没单独定义线程 ID，复用 PID 字段；没单独的调度算法，还是那套调度器。ps -eLf 里的 LWP 列就是线程在内核眼里的 PID，NLWP 是线程数。

一个进程其实是「线程组」（thread group）。第一个线程是 group leader，它的 PID 成为整个线程组的标识 tgid。getpid() 返回 tgid，所以同进程所有线程调 getpid() 拿到同一个数；gettid() 返回各自的 tid（glibc 2.30 起有同名包装，更早要 syscall(SYS_gettid)）。

errno 私有这件事很多人不知道，glibc 把它做成了线程局部存储，所以一个线程里 perror 不会串到另一个线程。

Linux 走 1:1 模型：一个用户线程绑一个内核调度实体。所以 pthread_create 会真的进内核建任务，多核能用满，某个线程阻塞也不影响别人，代价是创建和切换比纯用户态线程贵。

LinuxThreads 1:1，但管理线程在用户态模拟 2.6 之前 getpid() 每线程返回值不同，信号处理混乱，不符合 POSIX

现在你在主流发行版上写的 pthread_* 都是 NPTL。网上说「Linux 线程的 getpid() 不一样」，那是 LinuxThreads 时代的事。NPTL 的同步原语底层用 futex，无竞争时完全不进内核，这条从 2.6 起成立；glibc 2.34 移除 LinuxThreads 的说法来自 glibc NEWS，未逐版复核源码。

共享地址空间带来便利，也带来代价：一个线程段错误，整个线程组一起死。内核没法只杀一个线程——地址空间是共享的，收到 SIGSEGV 时整个进程都得完。想限制损失只能靠进程隔离，或者 pthread_cancel 主动收掉出问题的线程（还得那个线程配合）。这是下一章比较的起点。

九、多进程还是多线程：怎么选 #

先破一个误解：Linux 上进程和线程的创建、切换开销差距没有想象中那么大。两者都由 task_struct 描述，都走内核调度器，差别在地址空间和资源表。

text
多进程                              多线程
+----------+  +----------+          +--------------------------------+
| 进程 A   |  | 进程 B   |          |            进程                |
| 用户空间 |  | 用户空间 |          | 代码段  数据段  堆（共享）     |
| 页表私有 |  | 页表私有 |          | +--------+  +--------+         |
+----------+  +----------+          | |线程A栈 |  |线程B栈 |（私有） |
      │            │                | +--------+  +--------+         |
      └─ 物理内存 ─┘                +--------------------------------+

多进程的三个好处：硬隔离，页表各管各的，一个进程野指针别的照跑；不用锁，数据物理隔离，没有共享就没有竞态；好横向扩，加机器加进程就涨吞吐。三个代价：传数据走 IPC，管道/共享内存/消息队列/socket 都要选型和编码；每进程一套 mm_struct、页表、文件表，几千个进程就吃不少内存；切换要换页表（写 CR3），TLB 大面积失效，切换后一段时间全是 miss。

多线程的三个好处：共享内存直接读写，传指针就行，没有 IPC；创建时不用新建页表和文件表，只切一块栈；同进程线程切换不换页表，TLB 不失效。三个代价：锁，共享内存必然要同步，锁粒度、锁顺序、死锁全自己管；一个线程段错误整组陪葬；32 位下地址空间是硬顶，3GB 用户空间除以默认 8MB 栈，理论上限只有几百个线程。

维度 多进程 多线程
地址空间 各自独立 共享，各有私有栈
创建开销 重，要建页表、文件表，COW 兜底 轻，只开一块栈
切换开销 大，换页表 + TLB 失效 小，不换页表
数据共享 难，必须 IPC 易，直接读写
同步 基本不用锁 锁竞争、死锁、竞态全在这
容错 一个崩了不影响别的 一个崩了全没
调试 相对好查 竞态难复现，gdb 也不顺手
典型代表 Nginx、PostgreSQL、Apache prefork 游戏逻辑服、多数 GUI

选型问三条：数据要不要高频共享？大量共享、传递频繁走线程，共享很少、靠消息通信走进程。崩一个能不能接受全挂？不能走进程。要不要跨机器扩？要走进程，天然能分布式。

实践里多数高性能服务器选的是「多进程 + 每进程少量线程」或者「多进程 + 事件循环」。纯多线程的服务端程序一旦有个线程野指针，整个服务重启，可用性归零。

十、线程的创建与回收 #

用户态线程接口是 POSIX 那套，头文件 <pthread.h>，链接加 -lpthread（glibc 2.34 起 libpthread 已并入 libc，-lpthread 保留为兼容空壳）。

pthread_create #

c
#include <pthread.h>

int pthread_create(pthread_t *thread,
                   const pthread_attr_t *attr,
                   void *(*start_routine)(void *),
                   void *arg);
参数 含义
thread 传出参数，成功后写入新线程的 ID
attr 线程属性，NULL 用默认属性
start_routine 入口函数，签名固定 void *(*)(void *)
arg 传给入口函数的唯一参数

返回值：成功返回 0，失败返回错误码——不是 -1，也不设 errno。所以判断写 if (rc != 0)，不能用 perror，要用 strerror(rc)。

四个必须知道的点：线程创建后不一定马上跑，要等调度器放上 CPU；pthread_create 返回后调用线程继续往下走，两个流交错执行，顺序由调度器定；arg 是 void *，传 int 要经 intptr_t 转换，直接 (void *)5 在 64 位上有告警；多个参数打包成结构体传指针，别传栈上局部变量的地址——函数一返回那块内存就废了。

c
#include <stdio.h>
#include <string.h>
#include <pthread.h>

struct task { int id; const char *name; };

static void *worker(void *arg) {
    struct task *t = (struct task *)arg;
    printf("[thread %d] name=%s tid=%lu\n",
           t->id, t->name, (unsigned long)pthread_self());
    return (void *)(long)(t->id * 10);
}

int main(void) {
    pthread_t tid;
    static struct task t = {7, "compress"};   /* static：活到线程用完 */
    void *ret;

    int rc = pthread_create(&tid, NULL, worker, &t);
    if (rc != 0) {
        fprintf(stderr, "create failed: %s\n", strerror(rc));
        return 1;
    }
    pthread_join(tid, &ret);
    printf("[main] thread 返回 %ld\n", (long)ret);
    return 0;
}

pthread_t 在 Linux 上是 unsigned long，不能直接 %d 打印。

线程 ID 有两个不同的东西，别混：

名字 谁给的 怎么拿 范围
pthread_t 线程库 pthread_self() / pthread_create 传出 进程内唯一，不保证是数字
内核 tid 内核 syscall(SYS_gettid)，glibc 2.30 起有 gettid() 系统内唯一，就是 ps -L 里的 LWP

日志里想跟 ps、perf 对上用 tid，想在 pthread_join 里用 pthread_t。

pthread_join：等它结束并收尸 #

c
int pthread_join(pthread_t thread, void **retval);

阻塞当前线程直到 thread 结束，目标线程已结束则立刻返回。成功返回 0，失败返回错误码（ESRCH 无此线程、EINVAL 不能 join 自己或该线程已 detached、EDEADLK 互相 join 成环）。retval 接收目标线程的返回值，不关心就传 NULL。每个 joinable 线程必须被 join 一次，否则它的栈和描述符不释放，等价于线程版僵尸。

c
static void *calc(void *arg) {
    (void)arg;
    return (void *)42;          /* 直接塞进指针，别返回局部变量地址 */
}

int main(void) {
    pthread_t tid;
    void *ret;
    pthread_create(&tid, NULL, calc, NULL);
    pthread_join(tid, &ret);
    printf("结果 %ld\n", (long)ret);
    return 0;
}

想把整数当返回值，用 (void *)(intptr_t)value 塞、(intptr_t)ret 取。返回指向局部变量的指针是最常见的错——那个栈帧早没了。

pthread_exit 与 return #

void pthread_exit(void *retval); 结束当前线程，把 retval 交给将来 join 它的人，其他线程照跑。在 start_routine 里 return x 和 pthread_exit(x) 效果一样，区别在嵌套调用：在入口函数调用的深层函数里想结束线程，return 只能一层层退，pthread_exit 一步到位。主线程调 pthread_exit 只结束主线程，其他线程继续；主线程调 exit() 或从 main return，整个进程结束。

pthread_detach：不用收尸 #

c
int pthread_detach(pthread_t thread);

把线程标成 detached，它结束时资源由系统自动回收，不能被 join。两种用法：

c
/* 方式一：创建后立刻分离 */
pthread_t tid;
pthread_create(&tid, NULL, worker, NULL);
pthread_detach(tid);

/* 方式二：创建时就设属性，避免 join/detach 之间的竞态 */
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid, &attr, worker, NULL);
pthread_attr_destroy(&attr);

对已 detached 的线程调 pthread_join 返回 EINVAL；对同一线程 detach 两次行为未定义。短命的后台任务（打日志、上报指标）用 detached 省事，要拿返回值的必须 joinable。

线程属性 #

pthread_attr_t 是不透明类型，只能用函数改：

属性 设置函数 说明
栈大小 pthread_attr_setstacksize 默认 8MB（受 ulimit -s 影响），小栈能开更多线程
栈地址 pthread_attr_setstack 自己提供栈，一般不用
分离状态 pthread_attr_setdetachstate PTHREAD_CREATE_JOINABLE / PTHREAD_CREATE_DETACHED
调度策略 pthread_attr_setschedpolicy SCHED_OTHER / SCHED_FIFO / SCHED_RR
调度参数 pthread_attr_setschedparam 里面有 sched_priority
继承调度 pthread_attr_setinheritsched 用属性里的策略还是继承创建者，默认继承
竞争范围 pthread_attr_setscope Linux 只支持 PTHREAD_SCOPE_SYSTEM，PROCESS 返回 ENOTSUP 
c
pthread_attr_t attr;
struct sched_param sp;

pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 1024 * 1024);        /* 1MB，默认 8MB 太奢侈 */
sp.sched_priority = 20;
pthread_attr_setschedpolicy(&attr, SCHED_RR);
pthread_attr_setschedparam(&attr, &sp);
pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED);   /* 关键 */

pthread_t tid;
pthread_create(&tid, &attr, worker, NULL);
pthread_attr_destroy(&attr);                           /* 创建完就能销毁 */

⚠️ PTHREAD_EXPLICIT_SCHED 最容易漏。默认是 PTHREAD_INHERIT_SCHED，属性里的优先级和策略会被忽略，线程默默继承创建者。设实时优先级还要求进程有 CAP_SYS_NICE（或 root），否则 pthread_create 返回 EPERM。

大栈不是越多越好：1000 个线程 × 8MB 默认栈 = 8GB 虚拟空间，32 位下直接爆。压到 256KB~1MB 是常规操作，代价是递归深了会栈溢出。

pthread_cancel：请求取消，不是杀死 #

c
int pthread_cancel(pthread_t thread);

它只发出一个取消请求，目标线程死不死、什么时候死，由目标线程自己的取消状态和取消类型决定。

函数 作用
pthread_setcancelstate PTHREAD_CANCEL_ENABLE / PTHREAD_CANCEL_DISABLE，默认 ENABLE
pthread_setcanceltype PTHREAD_CANCEL_DEFERRED（默认，到取消点才死）/ PTHREAD_CANCEL_ASYNCHRONOUS（随时死）
pthread_testcancel 在没有取消点的循环里手动插一个取消点

deferred 模式下只有到达取消点才会响应，read、write、sleep、pthread_cond_wait、pthread_join、sem_wait、pthread_testcancel 都是取消点。纯计算循环里没有取消点，pthread_cancel 发出去等于石沉大海。

c
static void *loop(void *arg) {
    (void)arg;
    while (1) {
        /* 干活 */
        pthread_testcancel();        /* 没有它，cancel 永远不生效 */
    }
    return NULL;
}

异步取消很危险：线程正好停在 malloc 内部时，取消后堆结构就坏了，只有确定代码不碰任何共享状态时才用。

被取消的线程会执行 pthread_cleanup_push 压进去的清理函数：

c
pthread_cleanup_push(free_buffer, buf);
/* ... 会被取消打断的代码 ... */
pthread_cleanup_pop(1);      /* 参数为 1：正常退出时也执行清理函数 */

push 和 pop 必须是同一函数体内的配对宏，中间不能 return、break、goto 跳出去，否则编译都过不去——这是宏实现留下的硬限制。

十一、用户态与内核态 #

CPU 把特权级分成 Ring 0 到 Ring 3，Linux 只用其中两级：

级别 名字 能干什么 不能干什么
Ring 0 内核态 直接操作硬件、改页表、访问全部物理内存、关中断 —
Ring 3 用户态 只能访问自己地址空间里标记为用户可访问的页 碰硬件、改 CR3、读写内核空间

x86-64 上还有 Ring 1 和 Ring 2，Linux 完全不用（Xen 用过 Ring 1 跑内核）。ARM 上对应 EL0/EL1，RISC-V 上对应 U/S 模式。

不是道德约束，是硬件强制的：in/out 指令、改控制寄存器、访问页表基址寄存器这些操作在 Ring 3 直接触发异常。用户程序想干这些事，唯一的合法通道是主动陷入内核。

三个概念很多人混着用，分开看：

概念 是什么 开销
模式切换（mode switch） 用户态 ↔ 内核态，同一个进程，不换页表 小，几十到几百纳秒
进程/线程切换 换执行流，保存恢复寄存器，跨进程时换页表 大，微秒级起
中断 硬件异步打断当前执行流 分上半部/下半部

系统调用只做第一种：进内核执行完就回来，进程还是那个进程，页表还是那张页表。账在第十四章算。

十二、进程上下文与中断上下文 #

上下文是程序执行时的完整环境，分三块：

层次 内容
用户级上下文 正文段、数据段、用户栈、共享存储区映射
寄存器上下文 通用寄存器、PC/IP、处理器状态字（EFLAGS/CPSR）、栈指针 SP
系统级上下文 task_struct、内存管理信息（mm_struct、vm_area_struct、页表）、内核栈

进程切换要把这三层全换掉，系统调用只换寄存器上下文的一部分。

进程上下文：进程执行系统调用或触发异常陷入内核，内核代表这个进程在内核空间跑。它用当前进程的内核栈，可以睡眠、可以阻塞（等磁盘 I/O、等信号量都行，内核知道该唤醒谁），current 指针有意义，指向当前进程的 task_struct。教材里的「上文/下文」是另一套说法：切进内核前保存用户态寄存器、进程状态、栈内容叫上文，切进去后执行的内核代码叫下文，理解上用没问题，内核源码里不这么叫。

中断上下文：硬件（网卡、磁盘、键盘、定时器）发中断，CPU 停下手上的活跳进注册好的处理程序，此时内核代表硬件在跑，跟任何进程都没关系。限制严得多：

禁止 原因
睡眠、阻塞 不属于任何进程，调度器没法把它换回来，睡下去永远醒不了，整机卡死
拿 mutex / 信号量 拿不到就会睡眠，同上
访问用户空间地址 被打断的进程是随机的，它的页表跟当前硬件环境不对应，访问多半是野地址
干耗时的活 中断处理期间常关本 CPU 中断，拖长了丢中断、增加时延
被抢占 中断上下文一直跑到结束

要干重活交给下半部（softirq、tasklet、workqueue）。workqueue 跑在进程上下文里，反而可以睡眠；softirq 和 tasklet 仍在中断上下文，不能睡。进程上下文能调 kmalloc(GFP_KERNEL)、能拿 mutex，中断上下文只能 GFP_ATOMIC、只能自旋锁。写内核模块时搞错这个，症状是「系统随机卡死，日志什么都没有」。

原子上下文：不可中断、不可抢占的状态，涵盖硬中断处理中、软中断/tasklet 中、持有自旋锁期间（自旋锁会关掉本 CPU 抢占）。四条铁律：不能睡眠、不能访问用户空间、不能拿 mutex（要用自旋锁）、不能干耗时活。内核用 in_irq()、in_softirq()、in_interrupt()、in_atomic() 判断，底层依据是 preempt_count 的位段划分（PREEMPT_MASK 记自旋锁深度、SOFTIRQ_MASK 记软中断嵌套、HARDIRQ_MASK 记硬中断嵌套，另有 PREEMPT_ACTIVE 标志）。

坑在这里：CONFIG_PREEMPT=n 的内核上 spin_lock() 不一定改 preempt_count，in_atomic() 会返回 0，明明持着锁却被判成「不在原子上下文」。别拿它当自旋锁睡眠的保险。实现细节归 C.驱动 与 B.内核，本篇只提醒你别踩。

十三、系统调用的入口 #

用户程序没法直接调内核函数——不在一个地址空间，权限也不够。唯一的合法入口是让 CPU 主动陷入内核，这条指令由体系结构规定：

架构 陷入指令 系统调用号放哪 参数寄存器
x86-64 syscall rax rdi rsi rdx r10 r8 r9
x86-32（现代） sysenter eax ebx ecx edx esi edi ebp
x86-32（传统） int 0x80 eax 同上
ARM64 svc #0 x8 x0~x5
RISC-V ecall a7 a0~a5

x86-64 用 syscall 不用 int 0x80，原因很直接：int 要走完整的中断门，硬件查 IDT、压栈、切栈，开销比 syscall 大好几倍。syscall 是 AMD 为 64 位加的专用快速通道，靠 MSR_LSTAR 里存的入口地址一步跳过去。

int 0x80 在 64 位进程里也能用，但它按 32 位 ABI 解释寄存器，参数得放 ebx/ecx 那套，系统调用号也是 32 位的表。混用会得到莫名其妙的 ENOSYS 或者调错函数。

glibc 包装层做了什么 #

你在 C 里写的 write(fd, buf, n) 不是系统调用，是 glibc 的函数。它按 ABI 把系统调用号（SYS_write，x86-64 上是 1）放进 rax、参数放进对应寄存器，执行 syscall 指令；内核返回后检查 rax：落在 [-4095, -1] 区间就是出错，把 rax 取负写进 errno、函数返回 -1，否则直接返回 rax。所以内核返回的是 -errno，你的 C 接口看到的是 -1，这个转换在包装层做，裸调 syscall() 时得自己判断。

c
#define _GNU_SOURCE
#include <unistd.h>
#include <sys/syscall.h>
#include <stdio.h>

int main(void) {
    long tid = syscall(SYS_gettid);       /* 拿内核 tid */
    printf("tid=%ld pid=%d\n", tid, getpid());
    return 0;
}

SYS_* 宏定义在 <sys/syscall.h> 里，各架构一套。查表用 ausyscall --dump（audit 包）。

进内核之后 #

text
用户态：  syscall 指令
              │  CPU 切到 Ring 0，加载内核入口地址
              ▼
内核入口： swapgs、切到内核栈、保存用户寄存器到 pt_regs
              │
              ├─ 按 rax 里的号查 sys_call_table，跳到对应处理函数
              │      （表在只读页里，5.x 起加了索引边界检查防提权）
              │
              ├─ 处理函数干活，返回值放回 pt_regs 的 ax
              ▼
内核出口： 检查 need_resched / 有没有待处理信号
              ▼
用户态：  sysret 指令返回，恢复寄存器，继续执行下一条

入口处保存的那份寄存器快照就是 pt_regs，fork 复制它、信号处理读它、ptrace 改它。返回路径上内核会检查有没有待处理的信号、要不要重新调度——这就是「从系统调用返回用户态时是调度时机」的来源。

vsyscall 与 vDSO：不进内核也能拿到时间 #

有几个高频调用根本不值得切内核，典型的是取当前时间。内核把一小段代码映射到每个进程的用户空间里，用户态直接调：

机制 出现 形态 现状
vsyscall 2.5.x 固定地址 0xffffffffff600000 的三页 只为兼容保留，性能差，可用 vsyscall=none 关掉
vDSO 2.6.13 起 随机地址的一小段 .so，由内核映射 现役，gettimeofday、clock_gettime、time、getcpu 走它

vDSO 的关键是那段代码能读到内核维护的时间数据（在共享页里），读的时候用「序号 + 重试」保证一致性，不需要陷入内核。所以 clock_gettime(CLOCK_MONOTONIC) 只要几十纳秒，而一个真系统调用要几百纳秒起。

验证一个调用到底走没走内核，用 strace：走 vDSO 的不会出现在 strace 输出里。strace -c 统计次数与耗时，ltrace 看库函数调用。

十四、上下文切换的代价 #

先把两件事分开，开销差一个数量级：

动作 换什么 不换什么 量级
模式切换 特权级、栈、寄存器快照 页表、task_struct、地址空间 几十到几百纳秒
进程切换 上面全部 + 页表基址 + mm_struct 内核代码映射（共享） 微秒级
线程切换 寄存器、栈指针、TLS 页表（同进程） 介于两者之间

系统调用只做模式切换，不换页表，TLB 里的用户态映射全都还在，回来接着用。

进程切换贵在五步：保存当前任务的寄存器现场到它的内核栈 / task_struct->thread；换内核栈（sp 指向新任务的内核栈）；换页表基址寄存器（x86 上 CR3 改指向新进程的 pgd）；CR3 一改 TLB 里的用户态映射大面积失效（PCID 特性可缓解，CR3 低位带 ASID 就不用整个刷）；新进程开始跑，每个没命中的页都要重新走页表。第 3、4 步是进程切换独有的，线程切换跳过它们，这就是线程切换更快的主因。

具体到多少纳秒跟 CPU 型号、PCID 开没开、工作集大小强相关。常见量级说法是进程切换 1~3 微秒、线程切换几百纳秒，差很大，未验证。

看数据用这几个命令：

bash
vmstat 1                          # cs 列：每秒上下文切换次数
pidstat -w 1                      # 每个进程的 cswch/s 和 nvcswch/s
grep ctxt /proc/<pid>/status

cswch/s（voluntary）是主动让出——等 I/O、等锁、sleep；nvcswch/s（nonvoluntary）是被抢——时间片用完、被更高优先级顶掉。

现象 说明
voluntary 高、nonvoluntary 低 I/O 型，等得多算得少
voluntary 低、nonvoluntary 高 CPU 型，一直在抢 CPU
两个都高 锁竞争严重，线程在锁上反复睡醒

第三种最常见于「加线程反而更慢」：线程数超过核数，锁竞争让 CPU 大量时间花在切换而不是计算上。迁移线程到别的核还有额外代价：目标核缓存里没有它的数据，全是 cache miss。这个话题在 04-调度与亲和性 展开。

十五、多线程的典型问题 #

四个词先分清，说错了后面全乱：

词 定义
临界资源 同一时刻只能被一个执行流占用的资源。打印机、共享变量、文件写指针都算
临界区 程序里访问临界资源的那段代码
互斥 同一时刻只允许一个访问者进临界区，保证唯一性和排他性，但不规定顺序
同步 在互斥基础上再约定访问顺序，让多个线程按约定节奏配合

竞态条件（race condition）就是没做互斥的后果：结果取决于调度顺序，同一份代码跑两次结果不同。

互斥锁 #

c
#include <pthread.h>

pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;   /* 静态初始化 */

int pthread_mutex_init(pthread_mutex_t *mutex, const pthread_mutexattr_t *attr);
int pthread_mutex_lock(pthread_mutex_t *mutex);
int pthread_mutex_trylock(pthread_mutex_t *mutex);
int pthread_mutex_unlock(pthread_mutex_t *mutex);
int pthread_mutex_destroy(pthread_mutex_t *mutex);

用法固定：临界区前 lock，临界区后 unlock，拿不到锁就阻塞。trylock 是非阻塞版，拿不到立刻返回 EBUSY，适合「拿不到就走另一条路」的场景。

四条规矩：加锁顺序全局统一，两个线程以相反顺序拿两把锁必然死锁；锁粒度尽量小，临界区里别做 I/O、别 malloc、别调会阻塞的函数；每个 lock 都必须有对应的 unlock，包括出错分支，用 goto err 集中清理比到处 return 安全；destroy 只能在没线程持有或等待锁时调。

死锁的四个必要条件（互斥、占有并等待、不可抢占、循环等待）破掉任意一个就行，实践里最容易做的是破循环等待：给所有锁编号，永远按编号从小到大拿。

条件变量 #

互斥锁解决「不许同时进」，条件变量解决「等某个条件成立再进」。

c
#include <pthread.h>

pthread_cond_t cond = PTHREAD_COND_INITIALIZER;    /* 静态初始化 */

int pthread_cond_init(pthread_cond_t *cond, const pthread_condattr_t *attr);
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
int pthread_cond_timedwait(pthread_cond_t *cond, pthread_mutex_t *mutex,
                           const struct timespec *abstime);
int pthread_cond_signal(pthread_cond_t *cond);
int pthread_cond_broadcast(pthread_cond_t *cond);
int pthread_cond_destroy(pthread_cond_t *cond);

语义要点：

  • pthread_cond_wait 必须持着 mutex 调，内部做三件事——解锁 mutex、阻塞、被唤醒后重新加锁再返回，三步是原子的，中间不留窗口。
  • 被唤醒不代表条件成立，有虚假唤醒，也有条件被别的线程抢走的情况。判断必须写在 while 里，不能写 if。
  • signal 唤醒至少一个等待者（POSIX 允许唤醒多于一个），broadcast 唤醒全部。没有等待者时 signal 是空操作，不会「存着」。
  • timedwait 用绝对时间（CLOCK_REALTIME 起点），超时返回 ETIMEDOUT。算绝对时间要用 clock_gettime 加偏移，别拿相对秒数直接填。
  • destroy 在有线程等待时返回 EBUSY。

pthread_condattr_t 在 LinuxThreads 时代不被支持，cond_attr 一律传 NULL；NPTL 支持了，用来设 CLOCK_MONOTONIC 这类属性，常规代码传 NULL 就够。

生产者-消费者 #

c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <unistd.h>

static pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
static int stop = 0;

struct node { int n; struct node *next; };
static struct node *head = NULL;

static void *consumer(void *arg) {
    (void)arg;
    for (;;) {
        pthread_mutex_lock(&mtx);
        while (head == NULL && !stop)
            pthread_cond_wait(&cond, &mtx);   /* 醒来后仍在锁内 */
        if (head == NULL && stop) {
            pthread_mutex_unlock(&mtx);
            break;
        }
        struct node *p = head;
        head = p->next;
        pthread_mutex_unlock(&mtx);           /* 出临界区再干活 */
        printf("[consumer] got %d\n", p->n);
        free(p);
    }
    return NULL;
}

int main(void) {
    pthread_t tid;
    pthread_create(&tid, NULL, consumer, NULL);

    for (int i = 0; i < 10; i++) {
        struct node *p = malloc(sizeof *p);
        p->n = i;
        pthread_mutex_lock(&mtx);
        p->next = head;
        head = p;
        pthread_cond_signal(&cond);
        pthread_mutex_unlock(&mtx);
        usleep(100000);
    }

    pthread_mutex_lock(&mtx);
    stop = 1;
    pthread_cond_signal(&cond);
    pthread_mutex_unlock(&mtx);

    pthread_join(tid, NULL);
    printf("[main] done\n");
    return 0;
}

三个细节决定这段代码对不对：while 而不是 if；printf 和 free 放在解锁之后；退出条件 stop 也要在锁内改并 signal 一次，否则消费者永远停在 cond_wait 上。

信号量 #

信号量管的是「资源还有几份」，不是「锁住一段代码」。

c
#include <semaphore.h>

int sem_init(sem_t *sem, int pshared, unsigned int value);
int sem_wait(sem_t *sem);        /* P 操作 */
int sem_trywait(sem_t *sem);
int sem_post(sem_t *sem);        /* V 操作 */
int sem_getvalue(sem_t *sem, int *sval);
int sem_destroy(sem_t *sem);
函数 语义 返回值
sem_init pshared=0 线程间用，非 0 进程间用（要放共享内存）；value 是初始可用量 成功 0，失败 -1
sem_wait 值 > 0 就减 1 继续；值为 0 就阻塞 成功 0，失败 -1
sem_trywait 值为 0 时立即返回 -1，errno=EAGAIN 同上
sem_post 值加 1；有等待者则唤醒一个 成功 0，失败 -1
sem_getvalue 取值写入 *sval 同上

互斥锁就是 value=1 的信号量特例。差别在于信号量可以在一个线程里 post、另一个线程里 wait，互斥锁必须同一个线程解锁；信号量还能表达「最多 3 个并发」这种计数语义。pshared 非 0 的匿名信号量要放在 mmap(MAP_SHARED) 出来的内存里，否则进程间看不见。

线程安全与可重入 #

概念 含义
线程安全 多线程同时调不破坏状态。靠锁、靠原子操作、靠线程局部存储
可重入 执行到一半被打断、换个线程重入同一函数也不出错。要求不用静态/全局变量
异步信号安全 在信号处理函数里调也不出问题。集合最小，只有 write、_exit 一小撮

可重入一定线程安全，线程安全不一定可重入（用了锁就不满足可重入）。strtok、localtime、gmtime、asctime、getpwnam、readdir 都不线程安全，它们返回指向静态缓冲区的指针，换成 strtok_r、localtime_r、getpwnam_r、readdir_r。

十六、易错点速查 #

# 坑 后果 正确做法
1 把 fork() 返回值当布尔值 父进程把 0 当成「失败」 三分支：<0 失败、==0 子进程、>0 父进程
2 fork() 后不加 wait 僵尸堆积，PID 耗尽，fork 返回 EAGAIN 收尸，或 SIGCHLD + WNOHANG 循环
3 SIGCHLD 处理函数用 if 而不是 while 收 多子进程同时退出时漏收，留僵尸 while (waitpid(-1, &st, WNOHANG) > 0);
4 SIGCHLD 处理函数不保存 errno 打断主流程的 errno，后续判断全乱 进函数存 saved，出函数还原
5 vfork() 子进程用 return 改坏父进程栈帧，父进程醒来就崩 子进程必须 _exit() 或 exec
6 exec 失败后不 _exit 子进程继续跑父进程代码，逻辑跑两遍 execlp(...); _exit(127);
7 exec 前没 fflush 缓冲区内容随地址空间一起被丢弃 fflush(NULL); 再 exec
8 execl 参数列表漏 NULL 收尾 变参函数一直往下读栈，随机崩溃 末尾补 (char *)NULL
9 子进程用 exit() 而不是 _exit() 父进程的 stdio 缓冲区被刷两次，输出重复 fork 出的子进程一律 _exit()
10 waitpid 返回值只判 != pid 出错时 -1 也进循环，死循环 判 == 0 表示还在跑，< 0 单独处理
11 直接 status >> 8 取退出码 被信号杀死时拿到垃圾值 WIFEXITED + WEXITSTATUS
12 以为 kill -9 能杀 D 状态进程 杀不掉，信号一直挂着 等 I/O 恢复，或修掉卡住的存储/NFS
13 把 pthread_create 的返回值当 -1 判断失效，错误被吞 返回的是错误码，!= 0 即失败，用 strerror(rc)
14 线程函数传栈上局部变量的地址 函数返回后线程拿到野指针 用 static、malloc，或等线程结束再退出作用域
15 joinable 线程既不 join 也不 detach 资源不回收，等价于线程版僵尸 二选一，必须选
16 线程函数 return 局部变量的地址 拿到已销毁的栈帧 返回值塞整型，或用 static/malloc
17 pthread_cond_wait 外面用 if 判断条件 虚假唤醒后条件其实不成立，直接踩空 一律 while (条件不成立) wait;
18 pthread_cond_wait 没先加锁 未定义行为，会永久丢失唤醒 先 mutex_lock，wait 返回后仍在锁内
19 设了 schedparam 但没设 PTHREAD_EXPLICIT_SCHED 优先级被静默忽略 补上 pthread_attr_setinheritsched
20 纯计算循环里不插 pthread_testcancel pthread_cancel 发了等于没发 循环体里加 pthread_testcancel()
21 异步取消正在 malloc 的线程 堆结构被破坏，后续 malloc 全崩 用默认的 DEFERRED，只在安全点取消
22 用 %d 打印 pthread_t 64 位上是 unsigned long，输出截断 (unsigned long)pthread_self() 配 %lu
23 以为 getpid() 在每个线程里不同 拿到的全是 tgid，一样 要内核 tid 用 syscall(SYS_gettid)
24 加锁顺序不统一 两个线程反向拿两把锁，必然死锁 所有锁全局编号，按编号升序获取
25 临界区里做 I/O 或 malloc 锁持有时间被拉长，吞吐掉光 临界区只留必须原子的几行
26 用 strtok / localtime 这类非线程安全函数 返回数据被别的线程覆盖 换 _r 版本
27 32 位下开上千个线程 8MB 默认栈 × N 吃掉地址空间 pthread_attr_setstacksize 压到 256KB~1MB
28 以为 system() 等价于 exec 主进程行为完全不同，还多起一个 shell 不需要 shell 就用 fork + exec
29 sleep() 被打断后不重睡 定时比预期短 while ((left = sleep(left)) > 0);
30 pthread_cond_signal 在没加锁时发 唤醒与条件判断之间有窗口，会丢唤醒 改条件的同时持锁，再 signal
