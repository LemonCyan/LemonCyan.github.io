一、什么是线程安全的服务器 #

线程安全不是形容词，是四条能逐条打勾的约束。

约束 不合格的样子 本篇对应章节
共享数据的每次访问都在同一把锁内 两线程并发自增全局计数，值对不上 六
线程私有数据不跨线程传递 把栈上变量的地址交给另一个线程 四、五
只调用可重入版本的库函数 inet_ntoa、strtok、localtime 在多线程下互相覆盖 十、十一
失败路径与取消路径也放锁 recv 返回 -1 直接 return，锁没解 八、九

麻烦来自三处。一是进程级共享资源：fd 表、堆、全局变量、stdout 缓冲区，线程之间只有一份，两线程同时 printf 输出会交错，同时对同一个 int 做 += 1 会丢更新。二是库函数内部的静态缓冲区：inet_ntoa 返回函数内一块 static char[16]，第二次调用把第一次的结果覆盖掉，而第一个调用者还握着那个指针。三是生命周期不由本线程掌握的内存：connfd 由主线程拿到、交给工作线程，工作线程 close 之后该 fd 号立刻被内核回收，下一次 accept 会拿到同一个号。

四种服务器模型，线程安全成本差很多：

模型 并发单位 隔离程度 主要成本
单线程 accept 循环 无 完全 一个慢客户端堵死所有人
每连接 fork 一进程 进程 强，地址空间独立 fork 开销、进程数上限、共享状态要自己做 IPC
每连接起一线程 线程 弱，堆与全局量共享 线程数随连接数上涨，同步全靠自己
固定线程池 + 任务队列 线程 弱 需要一个正确的队列和条件变量

本篇实例走第三条，然后在第六、七章补上第四条该怎么改。

二、程序的整体架构 #

两个文件，两段程序，一条自定义协议。

文件 产物 职责
srv.c srv 监听 1234 端口，每来一个连接开一个线程，收名字、收字符串、回显反转后的内容
cli.c cli 连服务器，先发名字，再循环读标准输入发字符串，收反转结果打印，Ctrl+D 退出

协议没有长度头，靠换行结束一条消息，这是 demo 级别的简化设计。

方向 内容 细节
客户端 → 服务器 客户名，带结尾换行 服务器把它当第一条 recv 的数据，砍掉最后一个字节
服务器 → 客户端 不回包 只在服务端 printf 出来
客户端 → 服务器 不超过 999 字节的字符串，带换行 每发一条，服务器回一条
服务器 → 客户端 反转后的字符串，不带换行 丢掉结尾换行再反转，所以 1234\n 回 4321
客户端 Ctrl+D fgets 返回 NULL 客户端 close 退出，服务器 recv 收到 0

数据流：

text
main 线程                          worker 线程（每个连接一个）
-----------                        ----------------------------
socket() -> listenfd
bind() listen()
loop:
  accept() -> connfd   -------------> process_cli(connfd, client)
  malloc(struct ARG)                   ├─ printf 客户 IP
  pthread_create(...)                  ├─ recv 客户名
  pthread_detach(tid)                  ├─ loop: recv 字符串
                                       │        savedata_r 累积到 cli_data
                                       │        reverse -> sendbuf
                                       │        send()
                                       └─ close(connfd) + printf 累积数据

客户端程序（cli.c）：

c
#include <stdio.h>
#include <unistd.h>
#include <strings.h>
#include <string.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <netdb.h>
#include <stdlib.h>
#define PORT 1234
#define MAXDATASIZE 100
void process(FILE *fp, int sockfd);
char *getMessage(char *sendline, int len, FILE *fp);
int main(int argc, char *argv[])
{
    int fd;
    struct hostent *he;
    struct sockaddr_in server;
    if (argc != 2) { printf("Usage :%s  <IP Address>\n", argv[0]); exit(1); }
    if ((he = gethostbyname(argv[1])) == NULL) { printf("gethostbyname() error.\n"); exit(1); }
    if ((fd = socket(AF_INET, SOCK_STREAM, 0)) == -1) { perror("socket() error"); exit(1); }
    bzero(&server, sizeof(server));
    server.sin_port = htons(PORT);
    server.sin_family = AF_INET;
    server.sin_addr = *((struct in_addr *)he->h_addr);
    if (connect(fd, (struct sockaddr *)&server, sizeof(struct sockaddr)) == -1) {
        perror("connect() error");
        exit(1);
    }
    process(stdin, fd);
    close(fd);
    return 0;
}
void process(FILE *fp, int sockfd)
{
    int numbytes;
    char recvline[MAXDATASIZE], sendline[MAXDATASIZE];
    printf("Connected to server.\n");
    printf("Input name :");
    if (fgets(sendline, MAXDATASIZE, fp) == NULL) { printf("\nExit.\n"); return; }
    send(sockfd, sendline, strlen(sendline), 0);
    while (getMessage(sendline, MAXDATASIZE, fp) != NULL) {
        send(sockfd, sendline, strlen(sendline), 0);
        if ((numbytes = recv(sockfd, recvline, MAXDATASIZE - 1, 0)) == 0) {
            printf("Server terminated.\n");
            return;
        }
        if (numbytes < 0) { perror("recv() error"); return; }
        recvline[numbytes] = '\0';
        printf("Server Message :%s\n", recvline);
    }
    printf("\nExit.\n");
}
char *getMessage(char *sendline, int len, FILE *fp)
{
    printf("Input string to server:");
    return fgets(sendline, len, fp);
}

客户端是单线程的，只有一个 fd，gethostbyname 虽然不可重入，但这里没第二个线程跟它抢。recv 长度传 MAXDATASIZE - 1，留一个字节给 '\0'。编译：

bash
[root@mylinux 2]# gcc -o srv srv.c -lpthread
[root@mylinux 2]# gcc -o cli cli.c

cli 没用到 pthread，不加 -lpthread 也能过。素材里那条 cli.c -lpthread12 是打字错，链接器找不到名为 pthread12 的库。

三、主线程与监听循环 #

文件头、常量和前置声明：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <strings.h>
#include <unistd.h>
#include <errno.h>
#include <signal.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <pthread.h>
#define PORT 1234
#define BACKLOG 5
#define MAXDATASIZE 1000
void process_cli(int connfd, struct sockaddr_in client);
void savedata_r(char *recvbuf, int len, char *cli_data, int *index);
struct ARG {
    int connfd;
    struct sockaddr_in client;
};
void *start_routine(void *arg);

BACKLOG 传 5 意味着已完成三次握手的连接队列最多排 5 个。高峰期 accept 稍慢一点，第 6 个客户端就收到 connect 超时。生产环境给到几百，或者直接用 SOMAXCONN。

主线程开头这半段只做接线，一次跑完，不进循环：

c
int main(void)
{
    int listenfd, connfd;
    pthread_t tid;
    struct ARG *arg;
    struct sockaddr_in server, client;
    socklen_t sin_size;
    signal(SIGPIPE, SIG_IGN);
    if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) == -1) { perror("Creating socket failed."); exit(1); }
    int opt = 1;
    if (setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt)) == -1) { perror("setsockopt"); exit(1); }
    bzero(&server, sizeof(server));
    server.sin_family = AF_INET;
    server.sin_port = htons(PORT);
    server.sin_addr.s_addr = htonl(INADDR_ANY);
    if (bind(listenfd, (struct sockaddr *)&server, sizeof(server)) == -1) { perror("Bind() error."); exit(1); }
    if (listen(listenfd, BACKLOG) == -1) { perror("listen() error"); exit(1); }

三个参数值得盯。SO_REUSEADDR 的实参是 int opt = 1，不是选项名本身；写成 int opt = SO_REUSEADDR 数值上等于 2，非零也能生效，但语义上把「选项编号」当成了「开关值」。INADDR_ANY 绑所有网卡，只收本机调试流量就换 inet_addr("127.0.0.1")，外网扫不到。sin_size 的类型是 socklen_t，素材写 int，在 64 位 glibc 上能过是因为 accept 只写 4 字节、指针强转没炸。

主线程到 listen 为止结束准备动作。后面它不进 recv、不碰 send，只做一件事：从 listenfd 上摘连接，把连接交给别人。

四、accept 与工作线程的创建 #

主线程的循环体只有三句实质操作：收连接、打包参数、起线程。

c
    while (1) {
        sin_size = sizeof(client);
        if ((connfd = accept(listenfd, (struct sockaddr *)&client, &sin_size)) == -1) {
            if (errno == EINTR) continue;
            perror("accept() error");
            continue;
        }
        arg = (struct ARG *)malloc(sizeof(struct ARG));
        if (arg == NULL) {
            perror("malloc() error");
            close(connfd);
            continue;
        }
        arg->connfd = connfd;
        memcpy(&arg->client, &client, sizeof(client));
        if (pthread_create(&tid, NULL, start_routine, (void *)arg)) {
            perror("pthread_create() error");
            free(arg);
            close(connfd);
            continue;
        }
        pthread_detach(tid);
    }
    close(listenfd);
    return 0;
}

sin_size 每轮重置成 sizeof(client)。accept 第三个参数是值-结果型，内核把实际写回的地址长度存进去，不复位的话第二轮传进去的是上一轮的「实际长度」，同族地址基本无差，但这是自己埋的坑。accept 出错时素材直接 exit(1)，一个客户端在三次握手最后一步断掉，accept 会返回 EINTR 或 ECONNABORTED，整台服务器跟着下线，所以改成 continue。

参数为什么必须 malloc：start_routine 拿到的是指针，pthread_create 返回后主线程立刻进下一轮循环，把栈上的 connfd、client 覆盖掉。放堆上，生命周期跟着 free 走。这是线程传参第一坑。memcpy 而不传 &client 同理，client 是主线程栈上的变量。tid 用完就丢，紧接着 pthread_detach。线程默认 joinable，退出后内核留住退出状态等别人 pthread_join。服务器从不去 join，这些残留就一直堆着，每来一个连接涨一点，跑一天下来内存里全是死线程的壳。

工作线程执行体：

c
void *start_routine(void *arg)
{
    struct ARG *info = (struct ARG *)arg;
    process_cli(info->connfd, info->client);
    free(arg);
    pthread_exit(NULL);
}

free(arg) 在 process_cli 之后，说明这块内存在整个连接期间都可用。工作线程自己管自己的参数，主线程完全不管。真正的活全在 process_cli 里：

c
void process_cli(int connfd, struct sockaddr_in client)
{
    int num;
    char cli_data[5000];
    char recvbuf[MAXDATASIZE], sendbuf[MAXDATASIZE], cli_name[MAXDATASIZE];
    char addr[INET_ADDRSTRLEN];
    int index = 0;
    memset(cli_data, 0, sizeof(cli_data));
    inet_ntop(AF_INET, &client.sin_addr, addr, sizeof(addr));
    printf("You got a connection from %s. ", addr);
    num = recv(connfd, cli_name, MAXDATASIZE - 1, 0);
    if (num <= 0) {
        close(connfd);
        printf("Client disconnected.\n");
        return;
    }
    cli_name[num] = '\0';
    if (cli_name[num - 1] == '\n') cli_name[num - 1] = '\0';
    printf("Client's name is %s.\n", cli_name);
    while ((num = recv(connfd, recvbuf, MAXDATASIZE - 1, 0)) > 0) {
        recvbuf[num] = '\0';
        printf("Received client( %s ) message: %s", cli_name, recvbuf);
        savedata_r(recvbuf, num, cli_data, &index);
        int i;
        for (i = 0; i < num - 1; i++) sendbuf[i] = recvbuf[num - i - 2];
        sendbuf[num - 1] = '\0';
        send(connfd, sendbuf, strlen(sendbuf), 0);
    }
    close(connfd);
    printf("Client (%s) closed connect. User's data: %s\n", cli_name, cli_data);
}

四个缓冲区全在 process_cli 的栈上：cli_data、recvbuf、sendbuf、cli_name。这是全篇最关键的事实——它们天然线程私有，不需要任何锁。每个线程有独立的栈，函数返回时栈帧消失。

cli_data 用 memset 清零。栈区会被复用，不清零的话这块内存里还留着上一个线程的残留字节，printf 一打印就把别人的数据带出来。

recv 长度传 MAXDATASIZE - 1，回填 recvbuf[num] = '\0' 才不越界。素材传的是 MAXDATASIZE，num 取到 1000 时 recvbuf[1000] 踩到相邻变量，不立刻崩，只让别的变量莫名变化。

cli_name[num - 1] 那处先判断是不是 '\n' 再砍。素材无条件写 '\0'，名字里带空格会被吞掉一字节。while (num = recv(...)) 把 -1 当成真，recv 出错时会进循环体，拿 recvbuf[-1] 当长度反转，条件得写 > 0。

反转那段索引 num - i - 2 是刻意少一个字节：recvbuf 第 num - 1 位是 '\n'，反转前跳过。客户端发 1234\n，num = 5，反转出 4321，sendbuf[4] = '\0'，send 长度 4。这就是客户端看到 Server Message :4321 的原因。

inet_ntop 替代 inet_ntoa，缓冲区 addr 在栈上，每线程一份。inet_ntoa 返回全局静态缓冲区，两线程同时打印会互相覆盖，第十、十一章展开。

五、共享数据的识别 #

写多线程程序，第一步不是加锁，是列出所有变量并标出归属。加错地方的锁比不加锁更糟，它给人「已经保护了」的错觉，却挡不住真正那条路径。

数据 存放位置 归属 需要锁吗
listenfd main 栈 主线程独占 不需要
connfd main 栈 → ARG 堆块 主线程写一次，交给工作线程后独享 不需要
struct ARG 堆块 堆，每次 malloc 一块 一个工作线程独占 不需要
cli_data[5000] process_cli 栈 单连接独占 不需要
recvbuf、sendbuf、cli_name process_cli 栈 单连接独占 不需要
addr[INET_ADDRSTRLEN] process_cli 栈 单连接独占 不需要
TSD 里的 DATA_THR 堆，靠 key 绑到线程 一个线程独占 不需要
key、once 静态存储区 所有线程共享，只初始化一次 靠 pthread_once
stdout 缓冲区 libc 内部 所有线程共享 libc 自己加锁
全局计数器 静态存储区 所有线程共享 必须加锁
连接注册表 静态存储区 所有线程共享 必须加锁

规律清楚：栈上的自动变量不用管，堆上每次 malloc 且只交给一个使用者的不用管，static 和全局的必须在设计阶段就定好保护方案。

stdout 是特例。printf 在 glibc 里对 FILE 加锁，一次调用的输出不会跟另一次交错。但两次 printf 之间没有原子性保证——printf("You got a connection from %s. ", addr) 和 printf("Client's name is %s.\n", cli_name) 是两次调用，两个客户端同时连进来时屏幕上会先出现两行 You got a connection from。想凑成一行，就自己 snprintf 拼好再一次 printf。

TSD 那部分补齐。它给每个线程挂一份自己的数据，靠一个 pthread_key_t 索引：

c
static pthread_key_t key;
static pthread_once_t once = PTHREAD_ONCE_INIT;
static void destructor(void *ptr) { free(ptr); }
static void getkey_once(void) { pthread_key_create(&key, destructor); }
typedef struct DATA_THR {
    int index;
} DATA_THR;

三个部件各管一段。key 是全局的，所有线程看到同一个 key，但每个线程往这个 key 上挂的指针各是各的——一个全局名字，N 份私有槽位。once 保证 pthread_key_create 只调一次，key 是进程级资源，对同一个 key 调两次，第二次返回 EEXIST 或覆盖掉第一次的槽位，已挂数据的线程全丢。destructor 是线程退出时的回调，pthread 库遍历该线程所有非 NULL 的 TSD 槽逐个调用，不挂它，calloc 出来的 DATA_THR 永久泄漏，每退一个线程漏 4 字节。真正的取用逻辑：

c
void savedata_r(char *recvbuf, int len, char *cli_data, int *index)
{
    DATA_THR *data;
    pthread_once(&once, getkey_once);
    if ((data = (DATA_THR *)pthread_getspecific(key)) == NULL) {
        data = (DATA_THR *)calloc(1, sizeof(DATA_THR));
        if (data == NULL) return;
        pthread_setspecific(key, data);
        data->index = 0;
    }
    int j;
    for (j = 0; j < len - 1; j++) cli_data[data->index++] = recvbuf[j];
    cli_data[data->index] = '\0';
}

pthread_once(&once, getkey_once) 每次进函数都调，但 getkey_once 只执行一次。懒汉写法比在 main 里手动初始化的好处是：谁先用谁负责初始化，不需要保证 main 与线程的先后顺序。

pthread_getspecific 返回本线程在这个 key 上的指针，没挂过就是 NULL。第一次进来必然 NULL，于是分配、挂上、index 归零。之后同一线程再进来都拿到同一个 data，index 接着上次的位置累加。for (j = 0; j < len - 1; j++) 又跳过最后一个字节——那是 recv 收回来的 '\n'。

这里有个隐蔽耦合：index 挂 TSD 上是线程级的，cli_data 是栈帧级的。一个线程服务一个连接时两者生命周期一致，能跑。改成线程池后同一线程先后服务多个连接，index 带着上一个连接的累加值继续往后写，写穿 cli_data。第七章修。

六、用互斥锁保护共享计数 #

加一个全局统计，看锁的边界怎么划。

c
struct server_stat {
    unsigned long total_conn;
    unsigned long total_bytes;
    int active_conn;
    pthread_mutex_t lock;
};
static struct server_stat g_stat = {
    .total_conn = 0, .total_bytes = 0, .active_conn = 0,
    .lock = PTHREAD_MUTEX_INITIALIZER
};

PTHREAD_MUTEX_INITIALIZER 是静态初始化器，编译期就把互斥量摆好，不需要运行时 pthread_mutex_init。前提是这块内存静态存在或来自 malloc，不能是栈上的自动变量。

关键在锁的粒度，三种写法对比：

写法 代码 问题
不锁 g_stat.total_conn++ ++ 是读-改-写三步，两线程并发必定丢一次
粗粒度 整个连接处理期间持有 lock 正确，但所有连接串行，退回单线程
只护计数 读改写前后加解锁 正确，并发照旧

正确写法是第三种，锁只覆盖共享变量本身，不覆盖 recv、send 这种会阻塞的调用：

c
static void stat_on_accept(const struct sockaddr_in *client)
{
    pthread_mutex_lock(&g_stat.lock);
    g_stat.total_conn++; g_stat.active_conn++;
    pthread_mutex_unlock(&g_stat.lock);
}
static void stat_on_bytes(unsigned long n)
{
    pthread_mutex_lock(&g_stat.lock);
    g_stat.total_bytes += n;
    pthread_mutex_unlock(&g_stat.lock);
}
static void stat_on_close(void)
{
    pthread_mutex_lock(&g_stat.lock);
    g_stat.active_conn--;
    pthread_mutex_unlock(&g_stat.lock);
}
static void stat_print(void)
{
    pthread_mutex_lock(&g_stat.lock);
    unsigned long c = g_stat.total_conn, b = g_stat.total_bytes;
    int a = g_stat.active_conn;
    pthread_mutex_unlock(&g_stat.lock);
    printf("conn=%lu active=%d bytes=%lu\n", c, a, b);
}

stat_print 单独起了个范式：锁内拷贝，锁外打印。锁内直接 printf，输出写终端或管道会阻塞，锁被一个慢速输出一直占着，别的线程想更新计数只能干等。锁的持有时间越短越好，遇到会阻塞的调用先出锁。active_conn 用 int 而不是无符号，因为它会被减——递减到 0 之后某条失败路径多减一次，无符号会变成巨大正数，int 只是负数，看日志一眼就能发现。统计挂进工作线程：

c
void *start_routine(void *arg)
{
    struct ARG *info = (struct ARG *)arg;
    stat_on_accept(&info->client);
    process_cli(info->connfd, info->client);
    stat_on_close();
    free(arg);
    pthread_exit(NULL);
}

stat_on_accept 放线程里而不是主线程里，让 active_conn++ 与线程真正开工在同一时刻。放主线程 accept 之后也行，差别只是「已建立连接」和「已开始服务」的定义。stat_on_close 必须覆盖所有退出路径。process_cli 有一条提前 return（收到名单就断开）和一条正常退出，两条都回到 start_routine，所以放 process_cli 之后能覆盖。但工作线程被 pthread_cancel 打断时这段根本不执行，取消路径要靠清理函数，第九章。改完的实测输出：

text
You got a connection from 127.0.0.1. Client's name is client1.
Received client( client1 ) message: 1234
You got a connection from 127.0.0.1. Client's name is client2.
Received client( client2 ) message: abc
Received client( client1 ) message: 5678
Client (client1) closed connect. User's data: 12345678
Received client( client2 ) message: defg
Client (client2) closed connect. User's data: abcdefg

两条连接的日志交错输出，谁先谁后由调度器和数据到达时刻决定。client1 的 12345678 是两次 recv 累积的结果，client2 的 abcdefg 同理。两段数据没有互相污染，说明每个线程的 cli_data 确实是独立的栈内存。

七、线程池的思路 #

每连接一线程在连接数不封顶时撑不住。开一个线程默认占 8MB 栈（虚拟地址，实际提交按需），1000 个连接就是 8GB 虚拟地址；再加上每次 pthread_create 陷入内核建任务、分配栈，几千 QPS 的连接建立速率下光创建销毁就吃掉可观 CPU。线程池把「线程」和「连接」解耦：固定 N 个线程，连接先进队列，谁空谁取。

c
#define POOL_SIZE 8
struct task {
    int connfd;
    struct sockaddr_in client;
    struct task *next;
};
struct task_queue {
    struct task *head, *tail;
    int count;
    int shutdown;
    pthread_mutex_t lock;
    pthread_cond_t not_empty;
};

队列是共享数据，锁护它；「队列非空」这个条件由条件变量通知，避免忙等。两个原语的配合范式是固定的：

c
static struct task *queue_pop(struct task_queue *q)
{
    pthread_mutex_lock(&q->lock);
    while (q->count == 0 && !q->shutdown) {
        pthread_cond_wait(&q->not_empty, &q->lock);
    }
    if (q->count == 0) {
        pthread_mutex_unlock(&q->lock);
        return NULL;
    }
    struct task *t = q->head;
    q->head = t->next;
    if (q->head == NULL) q->tail = NULL;
    q->count--;
    pthread_mutex_unlock(&q->lock);
    return t;
}

while (q->count == 0) 而不是 if。pthread_cond_wait 被唤醒不等于条件成立：另一个消费者先抢到锁把唯一的任务取走了，或者被信号打断提前返回。醒来必须重查条件，这是条件变量的核心纪律，写成 if 会在并发下丢任务或拿到空指针。

pthread_cond_wait 传 &q->lock 是它的契约：调用时原子地「释放锁 + 挂到等待队列」，返回时「重新拿到锁」。进 wait 前必须持锁，返回后也是持锁，unlock 放函数出口。生产者侧：

c
static void queue_push(struct task_queue *q, struct task *t)
{
    t->next = NULL;
    pthread_mutex_lock(&q->lock);
    if (q->tail == NULL) {
        q->head = q->tail = t;
    } else {
        q->tail->next = t;
        q->tail = t;
    }
    q->count++;
    pthread_cond_signal(&q->not_empty);
    pthread_mutex_unlock(&q->lock);
}

pthread_cond_signal 放锁内还是锁外都能工作。放锁内更简单，也避免「解锁之后才 signal」时消费者已经醒过一次又睡回去的边界情况。性能上被唤醒者要在 wait 返回时短暂等锁，这个代价不值一提。工作线程体：

c
static void *worker_routine(void *arg)
{
    struct task_queue *q = (struct task_queue *)arg;
    for (;;) {
        struct task *t = queue_pop(q);
        if (t == NULL) break;
        stat_on_accept(&t->client);
        process_cli(t->connfd, t->client);
        stat_on_close();
        free(t);
    }
    return NULL;
}

对比每连接一线程，三处变化：free(arg) 换成 free(t)；stat_on_accept 仍在线程里，对应的是任务而不是线程；线程不复存在，「线程私有」退化成了「任务私有」。TSD 那个设计在这里就破了。同一工作线程连续处理十个连接，data->index 跨连接累加，cli_data 是每轮新的栈帧（固定 5000），写到第 6 个连接左右越界。修法是把 index 从 TSD 挪进 process_cli 的局部变量：

c
void process_cli(int connfd, struct sockaddr_in client)
{
    char cli_data[5000];
    int index = 0;
    while ((num = recv(connfd, recvbuf, MAXDATASIZE - 1, 0)) > 0) {
        recvbuf[num] = '\0';
        savedata_r(recvbuf, num, cli_data, &index);
        /* ... */
    }
}

index 作为参数传进 savedata_r，这个函数就彻底无状态，TSD 和 pthread_once 都可以删。TSD 适合「每线程一份、线程生命周期内持续存在」的东西：线程自己的内存池、随机数种子、errno 副本。它不适合承载一次请求的临时状态，那是栈变量的活。顺带把栈大小管一下。默认 8MB 对 cli_data[5000] 这种用量是浪费，pthread_attr_setstacksize 设成 512KB 或 1MB，同样内存能开十几倍线程：

c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 512 * 1024);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid, &attr, start_routine, (void *)arg);
pthread_attr_destroy(&attr);

PTHREAD_CREATE_DETACHED 在创建时就定下，比创建后再 pthread_detach 少一个「这中间线程已经退了」的窗口。

八、连接的清理与资源回收 #

这类程序泄漏起来很安静：不崩、不报错，只是跑一夜之后 lsof 里几千个 CLOSE_WAIT。connfd 的生命周期三个节点，每个都不能漏：

节点 位置 失败后果
创建 accept 返回 —
移交 malloc + pthread_create 任一步失败则 fd 无人关
关闭 process_cli 末尾 close(connfd) fd 泄漏，到上限后 accept 报 EMFILE

pthread_create 失败这条路径最容易漏。线程没起来，arg 和 connfd 都成了孤儿，主线程已经进入下一轮循环，没人记得它们。第四章的代码补了 free(arg); close(connfd); continue;。资源账目：

资源 谁分配 谁释放 漏了会怎样
listenfd main main（循环外，实际跑不到） 进程退出时内核收走
connfd main 的 accept 工作线程 close fd 耗尽，accept 报 EMFILE
struct ARG main 的 malloc 工作线程 free 每连接 20 字节上下，慢速泄漏
DATA_THR savedata_r 的 calloc destructor 回调 每线程 4 字节，线程不退出就不释放
工作线程本体 pthread_create pthread_detach 后自动回收 死线程状态堆积
pthread_key_t pthread_key_create 进程退出回收 数量上限 PTHREAD_KEYS_MAX

close 有个细节：它只是把本进程的引用计数减一，TCP 连接真正拆除要靠四步挥手。工作线程 close 之后，如果对端还有没读走的数据，内核会发 RST 或者进入 TIME_WAIT。想确保对方收到你最后的 send，要么 shutdown(fd, SHUT_WR) 再等对方关，要么在协议层加确认。这个回显协议靠 Ctrl+D 关连接，客户端先关、服务器后 close，不会出现服务器单方面断连导致对方丢数据。

还有一个 SIGPIPE。服务器往一个已被对端关闭的连接上 send，内核发 SIGPIPE，默认动作是终止进程。一个客户端异常断开能把整台服务器打死。修法二选一：signal(SIGPIPE, SIG_IGN) 全局屏蔽，或者 send(fd, buf, len, MSG_NOSIGNAL) 只针对这一次调用。用哪个都行，不能都不做。这段放 main 开头，在所有网络调用之前。

九、有序退出：怎么让所有线程停下 #

素材的程序只有一个退出方式：Ctrl+C。默认动作终止整个进程，所有线程一起消失，close 不执行、free 不执行、destructor 不执行，cli_data 里攒的数据全丢。做服务不能只有这条路。

先给退出一个开关。volatile sig_atomic_t 是信号处理器与普通代码之间通信唯一可靠的类型，普通 int 优化后会被缓存在寄存器里，主循环永远看不到变化：

c
static volatile sig_atomic_t g_stop = 0;
static void on_signal(int sig)
{
    (void)sig;
    g_stop = 1;
}

accept 是阻塞的，光置标志它不会醒。信号到达会打断阻塞的系统调用，accept 返回 -1 并置 errno = EINTR，主循环正好借这个点检查标志：

c
signal(SIGINT, on_signal);
signal(SIGTERM, on_signal);
while (!g_stop) {
    sin_size = sizeof(client);
    connfd = accept(listenfd, (struct sockaddr *)&client, &sin_size);
    if (connfd == -1) {
        if (errno == EINTR) continue;
        perror("accept() error");
        continue;
    }
    /* 分发 ... */
}

主循环退出后，还有一堆工作线程各忙各的 recv，它们卡在阻塞读上不会自己停。两种处理：

策略 做法 代价
立即取消 pthread_cancel 每个线程 必须写好清理函数，否则锁和 fd 全泄漏
通知后等待 关闭连接 fd，让 recv 返回 0，线程自行退出 温和，但要能等到，且关 fd 与线程读同一 fd 有竞争

取消路径要配清理函数，逻辑是「进临界区前登记清理动作，出临界区前撤销」：

c
static void cleanup_unlock(void *arg)
{
    pthread_mutex_unlock((pthread_mutex_t *)arg);
}
static void stat_on_bytes_cancel_safe(unsigned long n)
{
    pthread_cleanup_push(cleanup_unlock, &g_stat.lock);
    pthread_mutex_lock(&g_stat.lock);
    g_stat.total_bytes += n;
    pthread_mutex_unlock(&g_stat.lock);
    pthread_cleanup_pop(0);
}

pthread_cleanup_push 和 pthread_cleanup_pop 必须成对出现在同一函数作用域内，它们在某些实现里是宏，展开成 { 和 }。少一个就编译不过，这是它们跟普通函数调用最大的区别。

线程池退出走条件变量那条路：置 shutdown，广播所有等待者，每个线程醒来发现队列空且已 shutdown 就退出。

c
static void queue_shutdown(struct task_queue *q)
{
    pthread_mutex_lock(&q->lock);
    q->shutdown = 1;
    pthread_cond_broadcast(&q->not_empty);
    pthread_mutex_unlock(&q->lock);
}

必须 broadcast 不是 signal。signal 只唤醒一个，其余线程永远停在 pthread_cond_wait 里，主线程 pthread_join 时挂死。完整收尾顺序：

c
close(listenfd);
queue_shutdown(&g_queue);
for (int i = 0; i < POOL_SIZE; i++) pthread_join(workers[i], NULL);
pthread_mutex_destroy(&g_queue.lock);
pthread_cond_destroy(&g_queue.not_empty);
pthread_mutex_destroy(&g_stat.lock);
stat_print();

顺序不能乱：先关监听（不再有新连接），再通知线程退出，再 join 等它们真退完，最后销毁锁和条件变量。还有线程在用锁时 pthread_mutex_destroy，行为未定义——什么都没发生，或者下次 lock 直接崩。destroy 只能在确认无人持有、无人等待时调。

十、线程安全与可重入的区别 #

这两个词常被当同义词，实际是两个不同维度。线程安全说的是「多个线程调它，结果正确」，实现上可以靠锁。可重入说的是「内部不依赖任何可变共享状态」，可以被打断再进入。用锁实现的线程安全函数不是可重入的——持锁期间被打断，第二次进入就死锁。

维度 线程安全 可重入
判据 多线程并发调用结果正确 执行中被打断后再进入仍正确
能否有静态缓冲区 可以有，加锁保护 不能有
能否有锁 可以 不能（持锁被打断即死锁）
能否调 malloc 可以 严格意义不行（内部有锁）
能否用 errno 可以，errno 是线程私有 可以，由 TLS 提供
典型实现 printf、malloc write、memcpy、strtok_r

可重入函数一定是线程安全的，线程安全函数不一定可重入。信号处理器里只能调可重入函数，因为信号会打断主流程正在持有的锁。常见配对关系：

不可重入版本 问题 可重入替代
inet_ntoa 返回 static char[16]，两次调用互相覆盖 inet_ntop（调用者给缓冲区）
gethostbyname 返回 static struct hostent getaddrinfo / gethostbyname_r
strtok 游标存在 static 变量里 strtok_r
localtime 返回 static struct tm localtime_r
asctime、ctime 返回 static char[] asctime_r、ctime_r
rand 种子与状态是全局的 rand_r，或自己维护状态

inet_ntoa 那处如果不改，第一次 printf 的实参是库内静态缓冲区的指针。printf 执行期间另一个线程也调了 inet_ntoa，同一块缓冲区被写入新地址，正在被读取的字符串就变了。更麻烦的是 printf 内部对 stdout 加了锁，而 inet_ntoa 的缓冲区没有锁——它自己是不是线程安全依赖 glibc 版本。改成 inet_ntop 之后缓冲区由调用者提供，落在 process_cli 的栈上，天然每线程一份：

c
char addr[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &client.sin_addr, addr, sizeof(addr));

INET_ADDRSTRLEN 是 16，够放 255.255.255.255\0。换 INET6_ADDRSTRLEN（46）就能同时装下 IPv6 地址，改协议族时不用重算缓冲区大小。「每次调用由调用者提供输出缓冲区」是可重入接口的通用做法。看 savedata_r 的签名能判断它属于哪一类：输出全写进 cli_data，自己不持有静态状态，所以可重入。TSD 那部分是例外——它是每线程一份的可变状态，savedata_r 因此不是严格可重入（同线程重入会共用 index），但它是线程安全的。

十一、常见的竞态场景复现 #

竞态的特点是：不加干预时不一定每次出现，加了 printf 调试就消失。下面五个场景都能在这台服务器上复现。

场景 触发条件 现象 定位手段
计数丢失 两线程同时 g_stat.total_conn++ 终值小于实际连接数 TSan、helgrind
参数被覆盖 把栈上 connfd 地址传给 pthread_create 两线程操作同一个 fd，或 fd 变乱值 代码审查第 4 参
静态缓冲区覆盖 两线程同调 inet_ntoa 打印出的 IP 变成别人的 换 inet_ntop
检查-使用分离 if (q->count > 0) t = q->head; 不加锁 t 是 NULL 或已被取走 检查与使用进同一临界区
锁内阻塞 持锁调 recv、printf 到慢终端 吞吐骤降，其他线程排队 缩小临界区

第一个场景的复现方式很直接。开 100 个线程各跑 10 万次自增，不加锁：

c
static long counter = 0;
void *bump(void *arg)
{
    for (long i = 0; i < 100000; i++) counter++;
    return NULL;
}

理论终值 10000000，实际每次都不一样，少几十万。原因是 counter++ 在 x86 上编译成三条指令：读进寄存器、寄存器加一、写回内存。两线程各读到 100，各加一，各写回 101，两次自增只留下一次效果。加锁版本终值稳定，代价是每次一次 lock cmpxchg 级别的原子操作。想保留性能又要正确，换 __atomic_fetch_add(&counter, 1, __ATOMIC_RELAXED)。第二个场景最阴。错误写法：

c
while (1) {
    connfd = accept(listenfd, ...);
    pthread_create(&tid, NULL, start_routine, &connfd);
}

&connfd 是 main 栈上那个变量的地址。线程拿到它时主线程已进下一轮 accept，把 connfd 改成新连接。两个线程于是操作同一个 fd，另一个 fd 无人处理。小流量下基本不出现，压测一上就炸。正确写法就是第四章那套 malloc 拷贝。第四个场景是检查与动作之间被插队：

c
if (q->count > 0) {          /* 检查 */
    t = q->head;             /* 使用，中间已被别的线程 pop 干净 */
    q->head = t->next;
    q->count--;
}

两次操作之间没有锁，另一个线程完全能把队列清空。修法是把检查和修改一起放进锁内。第五个场景在本篇代码里出现过一次：stat_print 若在锁内 printf，而 stdout 重定向到慢速管道或终端被 Ctrl+S 挂住，这把锁就被长期占用，所有要更新统计的线程都卡在 lock 上。工具上，编译期加 -fsanitize=thread 跑一遍比肉眼找更稳：

bash
gcc -g -O1 -fsanitize=thread -o srv_tsan srv.c -lpthread
./srv_tsan

TSan 在两个线程真的发生冲突访问时打印两侧调用栈。valgrind --tool=helgrind ./srv 是另一条路，慢得多，但也能报锁序问题。两个工具都要求代码真走到冲突路径上，所以并发客户端要一起跑起来。

十二、性能与扩展性考量 #

每连接一线程的模型下，连接数 N 上去，三个成本同时涨：

成本 量级 说明
线程栈虚拟地址 每线程 8MB 1000 连接 = 8GB 虚拟地址
线程创建销毁 每次几十微秒 短连接场景占比高
调度器压力 O(N) 就绪队列 线程数远超核数后，上下文切换吃掉 CPU

改线程池后前两项被摊平：线程数固定，栈开销固定，创建只发生一次。第三项仍在，但至少不随连接数涨。锁的竞争是另一个维度。g_stat 一把全局锁，所有连接都要在上面串一下。8 核机器上单次 lock/unlock 无竞争约 20ns，有竞争后随排队线性上升：8 线程时约 25ns，可忽略；64 线程时到 400ns，开始明显；256 线程时到数微秒，严重。缓解手段按成本从低到高：一是把统计从「每收一条消息更新一次」改成「每连接结束汇总一次」，锁次数从 O(消息数) 降到 O(连接数)；二是分片，开 16 个计数器，线程按下标取模挑一个，读时全加起来，冲突概率降 16 倍；三是用原子操作替掉互斥量，单个 unsigned long 的累加用 __atomic_fetch_add 就够，竞争时不睡眠而是空转重试，省掉上下文切换。

futex 的细节在《futex：用户态同步原语》里，这里只给结论：glibc 的 pthread_mutex_lock 在无竞争时完全不进内核，只在需要睡眠时才 futex(FUTEX_WAIT)。「加锁很慢」这个判断在无竞争场景下是错的，慢的是竞争。扩展到更多连接，模型本身要换：

模型 连接数上限 编程复杂度 适用
每连接一线程 几千 低 中小规模、内网
线程池 + 任务队列 几万 中 常规服务
epoll 单线程事件循环 十万以上 高 高并发网关
epoll + 线程池 十万以上 很高 通用高性能服务

epoll 那套要处理半包、缓冲区管理、非阻塞写未完成，本篇的回显协议换成 epoll 之后代码量至少翻三倍。学同步机制不必从 epoll 起步，每连接一线程的模型把锁、条件变量、TSD 全用上了，是更好的练手场。BACKLOG = 5 在压测时也会成为瓶颈，设成 SOMAXCONN 或 512，让内核自己排队。

十三、易错点速查 #

编号 易错点 正确做法
1 把栈变量地址传给 pthread_create malloc 一块拷贝进去，线程自己 free
2 创建线程后忘了 detach 或 join 创建时用 PTHREAD_CREATE_DETACHED，或显式 pthread_detach
3 accept 出错就 exit(1) 查 errno，EINTR 继续，其余记日志继续
4 忘了 SO_REUSEADDR setsockopt 传 &opt，opt 取 1
5 缓冲区按 MAXDATASIZE 收，回填 buf[num] 越界 收 MAXDATASIZE - 1，或先判 num < MAXDATASIZE
6 while (num = recv(...)) 把 -1 当真 条件写 > 0，出错单独处理
7 直接 cli_name[num - 1] = '\0' 先判断末尾是 '\n' 再砍
8 用 inet_ntoa 打印 IP 换 inet_ntop，缓冲区由调用者提供
9 用 gethostbyname 换 getaddrinfo，或 gethostbyname_r
10 共享计数裸 ++ 互斥量包住，或换 __atomic_fetch_add
11 锁内调 recv、send、printf 锁内只碰共享变量，阻塞调用放锁外
12 pthread_cond_wait 外层写 if 写 while，醒来重查条件
13 退出时用 pthread_cond_signal 多个等待者用 broadcast
14 提前 return 时不 close(connfd) 所有退出路径统一收尾，或用清理函数
15 pthread_create 失败后没关 fd 失败分支 free(arg) + close(connfd)
16 不处理 SIGPIPE signal(SIGPIPE, SIG_IGN) 或 MSG_NOSIGNAL
17 线程池里 TSD 跨请求累积 请求级状态放栈上，别挂 TSD
18 还有线程在跑就 pthread_mutex_destroy 先 join 全部线程，再销毁
19 pthread_cleanup_push 与 pop 不配对 同一函数作用域内成对出现
20 全局 volatile int 当退出标志 用 volatile sig_atomic_t

收尾就一句：先分清哪些内存是你的、哪些是大家的，再把锁的边界画在共享变量上，最后保证每条失败路径都把锁解了、fd 关了。跑通不算完，能让它在并发压测下不丢计数、不漏 fd、按 Ctrl+C 干净退出，才算把前面几篇的机制真正用上了。
