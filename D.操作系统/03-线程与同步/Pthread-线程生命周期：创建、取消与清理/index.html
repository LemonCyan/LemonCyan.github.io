一、线程是什么：与进程的边界 #

Linux 上聊线程，得从 clone() 说起。内核眼里没有「线程」，只有任务（task）。一个任务带上这些标志位去 clone，它就是别人口中的线程：

text
clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD, ...)

CLONE_VM 共享地址空间，CLONE_FILES 共享 fd 表，CLONE_SIGHAND 共享信号处理方式，CLONE_THREAD 让它落进同一个线程组、共享 PID。glibc 把这层封成符合 POSIX 的接口，就是 Pthread。每建一个 pthread 线程，内核里就多一个 task_struct，用户线程与内核任务一对一，这是 NPTL 的实现选择。

哪些共享、哪些私有，搞清楚了后面所有坑都能自己推出来。

资源 进程内多线程 说明
代码段 .text 共享 同一份机器指令
全局/静态数据 .data .bss 共享 一个线程改，全体可见
堆 malloc 区 共享 分配器内部有锁，你的数据结构没人替你保护
文件描述符表 共享 一个线程 close，别的线程手上的 fd 立刻失效
工作目录、umask 共享 chdir 影响全进程
信号处理函数（sigaction） 共享 装一次，全进程生效
线程 ID（pthread_t） 私有 每个线程一个
寄存器上下文（PC、SP） 私有 切换时内核保存恢复
栈 私有 每个线程一块，默认约 8 MiB
errno 私有 POSIX 强制，否则多线程没法写
信号掩码、sigprocmask 状态 私有 每个线程自己决定屏蔽谁
线程局部存储（TLS） 私有 __thread 与 pthread_key_*
调度策略、优先级 私有 可逐线程设置

表里最容易吃亏的是两行：fd 共享，errno 私有。前者让你在别的线程里 close 掉正在被读的 fd；后者让你在 Pthread 函数出错时去查 errno，查到一片空白 —— Pthread 函数不设置 errno，错误号直接当返回值给你。

c
int ret = pthread_create(&tid, NULL, worker, NULL);
if (ret != 0)
    fprintf(stderr, "pthread_create: %s\n", strerror(ret));
/* perror("pthread_create"); —— 错，它读 errno，这里没人写过 */

这条规矩贯穿全篇：所有 pthread_* 成功返回 0，失败返回正数错误码，用 strerror(ret) 翻成人话。别 perror，别查 errno。

本节接口语义由 POSIX.1-2001（IEEE Std 1003.1-2001）定义，后文再提标准版本时同理。

二、pthread 的创建 #

c
#include <pthread.h>

int pthread_create(pthread_t *thread,
                   const pthread_attr_t *attr,
                   void *(*start_routine)(void *),
                   void *arg);
参数 方向 含义
thread 传出 保存新线程的 pthread_t。不关心可传 NULL，但之后就找不回这个线程
attr 传入 线程属性。传 NULL 表示取默认值，默认是 joinable
start_routine 传入 入口函数，签名固定为 void *(*)(void *)
arg 传入 传给入口函数的唯一指针，原样透传，不做任何拷贝
返回值 — 成功 0，失败返回错误码

失败码记三个：EAGAIN 资源不够（线程数超限、内存不足）、EINVAL 属性非法、EPERM 调度策略没权限。编译链上 pthread，glibc 2.34 起符号已并入 libc，写不写都行：gcc -Wall -Wextra -O2 -o prog prog.c -lpthread。

最短的可用例子：

c
static void *worker(void *arg)
{
    printf("child sees %s\n", (char *)arg);
    return (void *)7;
}

int main(void)
{
    pthread_t tid;
    int ret = pthread_create(&tid, NULL, worker, "hello");
    if (ret != 0) {
        fprintf(stderr, "create: %s\n", strerror(ret));
        return 1;
    }
    pthread_join(tid, NULL);      /* 不 join，main 一返回就把子线程掐死 */
    return 0;
}

main 里直接 return 0 等于 exit(0)，进程整个退掉，子线程没跑完就被掐。要给子线程留活路就得 join，或者见第六章的 pthread_exit。

arg 只有一个指针位，传多个值要打包。地址透传，不拷贝：

c
struct job { int id; const char *path; };

static void *worker(void *arg)
{
    struct job *j = (struct job *)arg;
    printf("job %d: %s\n", j->id, j->path);
    return NULL;
}

/* 调用方 */
struct job j = { .id = 1, .path = "/etc/hosts" };
pthread_create(&tid, NULL, worker, &j);
pthread_join(tid, NULL);   /* 让 j 的生命周期盖住子线程的读取窗口 */

&j 在栈上，子线程拿到的是地址不是副本。这行 pthread_join 不是为收尸，是为让 j 别在子线程读之前就随栈帧消失。

小整数塞指针靠 intptr_t 保证宽度一致；循环里传局部变量地址则是经典错：

c
pthread_create(&tid, NULL, worker, (void *)(intptr_t)42);   /* 线程里转回 int */

for (int i = 0; i < 4; i++)
    pthread_create(&tid[i], NULL, worker, &i);   /* 错：四个线程共用一个 i */

后者的线程真跑起来时，i 早就是 4 或已销毁。换成数组，或用 (void *)(intptr_t)i。

三、线程 ID 与线程属性 #

pthread_t 是不透明类型。glibc 里它是 unsigned long，数值正好是线程 TID（能对上 /proc/<pid>/task/ 目录名），但这是实现细节。标准只保证它能喂给 pthread_*，比较必须用 pthread_equal()。

c
pthread_t pthread_self(void);
int pthread_equal(pthread_t t1, pthread_t t2);

pthread_self() 取自己的 ID，pthread_equal() 判等。别用 ==，别 printf("%lu")，换个平台 pthread_t 甚至是结构体。

属性对象先存在，创建线程时被读取一份拷贝进去，之后改属性不影响已创建的线程。这个拷贝语义记不住，就会出现「改了半天属性不生效」。

c
int pthread_attr_init(pthread_attr_t *attr);
int pthread_attr_destroy(pthread_attr_t *attr);

init 拿到全默认值，用完 destroy 释放内部资源。属性对象可复用，改一项建一个线程没问题。

设置函数 作用 常用取值
pthread_attr_setdetachstate 分离状态 PTHREAD_CREATE_JOINABLE（默认）/ PTHREAD_CREATE_DETACHED
pthread_attr_setstacksize 栈字节数 不小于 PTHREAD_STACK_MIN，默认跟 ulimit -s
pthread_attr_setguardsize 栈尾保护页 默认一页，设 0 关闭
pthread_attr_setschedpolicy 调度策略 SCHED_OTHER / SCHED_FIFO / SCHED_RR
pthread_attr_setschedparam 优先级 struct sched_param 的 sched_priority
pthread_attr_setinheritsched 继承还是显式 PTHREAD_INHERIT_SCHED（默认）/ PTHREAD_EXPLICIT_SCHED
pthread_attr_setscope 竞争范围 PTHREAD_SCOPE_SYSTEM（Linux 只支持这个）
pthread_attr_setstack 完全自定义栈 调用方自己 mmap 一块交出去

调度那两行有个陷阱：默认 PTHREAD_INHERIT_SCHED 时，你设的策略和优先级被忽略，线程照抄创建者。要显式设置生效，得先 setinheritsched(PTHREAD_EXPLICIT_SCHED)。设 SCHED_FIFO 需要 CAP_SYS_NICE，普通用户拿到 EPERM。

四、线程的分离与可连接 #

线程创建出来只有两种归宿：可连接（joinable）与分离（detached）。默认 joinable。

  • joinable：线程结束后内核保留退出状态和一部分资源，等着别人来 pthread_join 取走。没人来取，这块资源一直悬着，和僵尸进程一个道理。
  • detached：线程结束时内核立刻回收全部资源，包括退出状态。没人能拿到它的返回值。
c
int pthread_detach(pthread_t thread);

pthread_detach 把线程转成分离态，成功 0，失败 EINVAL（已经是分离态）或 ESRCH（找不到这个 ID）。转过去就回不来。

c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid, &attr, worker, NULL);   /* 出生即分离 */
pthread_attr_destroy(&attr);

/* 或者让线程自己转，这行放入口函数第一句 */
pthread_detach(pthread_self());

自我分离必须早。若线程在 pthread_detach 之前就 pthread_exit 掉，它永远是 joinable，然后泄漏。

对比项 PTHREAD_CREATE_JOINABLE PTHREAD_CREATE_DETACHED
是否默认 是 否
结束时资源回收 需 pthread_join 触发 内核立即回收
能否取返回值 能，join 的 retval 带出 不能
能否 pthread_join 能 不能，报 EINVAL
能否 pthread_detach 能，一次性转换 再调报 EINVAL
忘了处理会怎样 资源泄漏，等同僵尸线程 无事发生
适用场景 要结果、要确认它跑完 长期后台、fire-and-forget

选择逻辑就一句：要不要它的返回值，要不要确认它结束。要，就 joinable 加 join；不要，干脆分离，别给自己留一个没人处理的对象。

五、pthread_join 与返回值获取 #

c
int pthread_join(pthread_t thread, void **retval);
参数 方向 含义
thread 传入 目标线程 ID，必须 joinable 且没被别人 join 过
retval 传出 void **，接收子线程带回的 void *。不关心传 NULL
返回值 — EINVAL 不可 join；ESRCH 无此线程；EDEADLK 自己 join 自己

调用方阻塞，直到目标线程终止。返回时目标线程的内核资源（内核栈、task_struct）已回收，glibc 那边的线程栈也在此时释放。joinable 线程必须被 join 的原因就在这：不 join，栈和退出状态一直在。

retval 是二级指针，因为要传出的是子线程给的那个一级指针。子线程 return (void *)7 与 pthread_exit((void *)7) 等价，主线程统一收：

c
void *ret = NULL;
int rc = pthread_join(tid, &ret);
if (rc != 0) {
    fprintf(stderr, "join: %s\n", strerror(rc));
} else if (ret == PTHREAD_CANCELED) {
    printf("child was cancelled\n");     /* 被取消固定是这个值 */
} else {
    printf("child returned %ld\n", (long)ret);
}

PTHREAD_CANCELED 在 <pthread.h> 里定义为 ((void *) -1)，比较用这个宏，别自己写 -1。

retval 也可以交回堆上的指针，谁分配谁释放事先说清；交回栈上变量的地址就是悬空指针：

c
static void *ok(void *arg) {
    int *out = malloc(sizeof *out);   /* 主线程负责 free */
    if (!out) return NULL;
    *out = 42;
    return out;
}
static void *bad(void *arg) {
    int local = 42;
    return &local;                    /* 错：函数已返回，local 已失效 */
}

几条硬规矩：只能 join 一次，第二次行为未定义，glibc 给 EINVAL 或直接崩；不能 join 分离线程，EINVAL；不能 join 自己，EDEADLK，等自己等于死锁；别拿旧 ID 去 join，线程结束后 pthread_t 会被系统复用给新线程，你 join 到的就是别人。

pthread_join 没有超时版本。POSIX 只给了这个死等接口，要超时得上 GNU 扩展的 pthread_timedjoin_np()，abstime 是 CLOCK_REALTIME 的绝对时间，超时返回 ETIMEDOUT，此时线程还活着。

最省心的模式是「建 N 个，统一 join N 个」，join 顺序无所谓，谁先结束谁先返回。建到一半失败时，已经跑起来的那几个仍要 join，别直接 exit：

c
pthread_t tids[N];
for (int i = 0; i < N; i++)
    pthread_create(&tids[i], NULL, worker, (void *)(intptr_t)i);
for (int i = 0; i < N; i++)
    pthread_join(tids[i], NULL);

六、线程的退出方式 #

一个线程结束有四条路径，后果差别很大。

退出方式 作用范围 清理函数 其它线程 退出码
入口函数 return val 当前线程 不执行 继续跑 val
pthread_exit(val) 当前线程 执行 继续跑 val
被 pthread_cancel 取消 当前线程 执行 继续跑 PTHREAD_CANCELED
exit() / _exit() / 致命信号 整个进程 不执行 全灭 进程退出码 
c
void pthread_exit(void *retval);

它终止的是调用它的那个线程，不管它写在入口函数里还是被入口函数调了五层的子函数里。retval 通过 join 交回给回收者。返回类型 void，它不返回，后面的代码不执行。

return val 只在入口函数里等价于 pthread_exit(val)。同样的 return 写在线程调用的普通子函数里，只是从那个子函数返回到调用点，线程活得好好的：

c
static void helper(void) { return; }        /* 只返回 helper，线程继续 */

static void *worker(void *arg)
{
    helper();
    printf("still alive\n");
    return (void *)1;                       /* 这里才退出线程 */
}

exit() 是地雷。任何线程里调它，整个进程立刻终止，别的线程正在持锁、正在写文件、正在提交事务，全部戛然而止，清理函数一个不跑。只在线程里干活就用 pthread_exit；确实要结束进程才用 exit。_exit() 更狠，连 atexit 和 stdio 缓冲都不刷。

反方向的坑在主线程。main 里 return 0 等价于 exit(0)，进程结束，后台线程全灭。想让主线程先撤、子线程续命：

c
int main(void)
{
    pthread_t tid;
    pthread_create(&tid, NULL, daemon_worker, NULL);
    pthread_exit(NULL);     /* 主线程自己退出，进程继续存在 */
}

pthread_exit(NULL) 让主线程退出，地址空间、堆、fd 全保留，内核等到最后一个线程结束才真正销毁进程，那时才回收资源、冲刷 stdio。这就是「主线程先退、工作线程续命」的标准写法。

七、线程取消的三种模式 #

c
int pthread_cancel(pthread_t thread);

它向目标线程发一个取消请求，不是立刻把它杀掉。成功 0，失败 ESRCH。请求是否生效、何时生效，由目标线程自己的两个属性决定 —— 发送方没有话语权。它是协作式协议，不是强杀。目标线程被取消后，join 拿到的 retval 固定是 PTHREAD_CANCELED。

c
int pthread_setcancelstate(int state, int *oldstate);  /* 要不要接受取消请求 */
int pthread_setcanceltype(int type, int *oldtype);     /* 何时响应取消请求 */

两个函数都把旧值写进 oldstate / oldtype，不关心传 NULL。返回值是错误码，同样不是 errno。

模式 状态 类型 行为 用途
接受 + 延迟（默认） PTHREAD_CANCEL_ENABLE PTHREAD_CANCEL_DEFERRED 请求挂起，走到下一个取消点才退出 绝大多数场景的默认选择
接受 + 异步 PTHREAD_CANCEL_ENABLE PTHREAD_CANCEL_ASYNCHRONOUS 请求到达即刻退出，不等取消点 纯计算线程配 pthread_testcancel，风险高
屏蔽 PTHREAD_CANCEL_DISABLE 任意 请求被记住但不生效，线程照常跑 保护临界区、保护不可中断的事务

三者的精确语义：PTHREAD_CANCEL_ENABLE 是默认值，线程接受取消请求。

  • PTHREAD_CANCEL_DISABLE 屏蔽取消。请求不丢，只是挂起（pending）。等线程调回 ENABLE，这个挂起的请求立刻兑现 —— 前提是它随后走到一个取消点。所以「屏蔽期间请求被扔掉」是错的，它攒着。
  • PTHREAD_CANCEL_DEFERRED 是默认值。线程收到请求不立刻死，继续跑，直到执行到某个取消点，在那里被终结。
  • PTHREAD_CANCEL_ASYNCHRONOUS 立即取消。线程在任何机器指令处都会被终止，包括正在 malloc 内部、正在持锁、正在改链表指针的瞬间。锁会永远停在加锁状态，堆元数据处在不一致状态，进程进入不可预测状态。

异步取消唯一勉强站得住脚的场景，是完全不碰共享状态、不持锁、不调用库函数的纯计算循环，并且循环体里自觉放 pthread_testcancel()。就这，也不推荐。

关掉再开的基本形态：

c
static void *worker(void *arg)
{
    int old;
    pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, &old);   /* 进临界区 */

    /* 一段不容打断的操作：写文件、改共享结构 */

    pthread_setcancelstate(old, NULL);    /* 出临界区，还原旧状态 */
    sleep(1);   /* 走到这里，挂起的请求就在这个取消点兑现 */
    return NULL;
}

还原时存 oldstate 再写回，比硬写 ENABLE 严谨，嵌套调用也不会把状态搞错。屏蔽区要短。把整个工作循环套进 DISABLE，等于这个线程彻底不可取消，pthread_cancel 形同虚设。

八、取消点与清理函数 #

延迟取消依赖取消点。POSIX.1-2001 列了一批必须是取消点的函数，glibc 上常见的有：

类别 函数
睡眠/等待 sleep usleep nanosleep pause
IO read write open close recv send accept connect select poll
线程同步 pthread_join pthread_cond_wait pthread_cond_timedwait sem_wait sem_timedwait sigwait
进程等待 wait waitpid system
显式检测 pthread_testcancel()

纯计算代码里一个取消点都没有，请求就永远悬着。这种线程得自己在循环里插检测，接口是 int pthread_testcancel(void);。它干两件事：当前有挂起请求且状态是 ENABLE，就当场执行取消（走清理栈，退出码 PTHREAD_CANCELED）；没有请求就立刻返回。

c
static void *compute(void *arg)
{
    for (long i = 0; i < 1000000000L; i++) {
        if ((i & 0xFFFF) == 0)
            pthread_testcancel();   /* 每 65536 次迭代给取消一个机会 */
    }
    return NULL;
}

现在进正题：清理栈。线程在持有互斥锁、开着 fd、占着共享内存时被取消，这些东西谁来放？

c
void pthread_cleanup_push(void (*routine)(void *), void *arg);
void pthread_cleanup_pop(int execute);

push 把 routine 和 arg 压进当前线程的清理栈。pop 弹出一个：execute 为 0 只弹不执行，非 0 弹出并执行。清理函数按后进先出执行，标准栈语义。

这两个在 glibc 里是宏，push 展开成 { 加前置代码，pop 展开成后置代码加 }。所以它们在同一个函数内必须语法上配对，不能只 push，不能跨函数 pop，中间不能 goto 跳出去。否则编译器直接报括号不匹配。

c
static void unlock_cleanup(void *arg)
{
    pthread_mutex_unlock((pthread_mutex_t *)arg);
}

static void *worker(void *arg)
{
    pthread_mutex_lock((pthread_mutex_t *)arg);
    pthread_cleanup_push(unlock_cleanup, arg);  /* 展开处有一个 { */

    do_work();                                  /* 里面的取消点会终结线程 */

    pthread_cleanup_pop(1);                     /* 展开处有一个 }，执行解锁 */
    return NULL;
}

锁必须在 push 之前加、清理函数里解锁，顺序不能反。先 push 再加锁，中间那个窗口被取消，清理函数会去解一把没加的锁。

清理函数被自动触发只有三种时机：线程调用 pthread_exit() 退出；线程响应 pthread_cancel 被取消；线程调用 pthread_cleanup_pop(execute) 且 execute 非 0。

反过来，入口函数里直接 return 不触发任何清理函数。这是静默的泄漏源：代码看着对称，正常路径没事，一走进这条路径资源就漏。

c
static void *leaky(void *arg)
{
    pthread_cleanup_push(free_cleanup, arg);
    return NULL;             /* 错：清理函数不执行 */
    pthread_cleanup_pop(0);  /* 这行还让整个函数编译不过 */
}

上面这段连编译都过不去，因为 return 之后 pop 不可达但仍需配对 —— 编译器帮你拦住了。正确写法是把 return 换成 pthread_exit，正常路径则显式 pop(1)：

c
static void *correct(void *arg)
{
    pthread_cleanup_push(free_cleanup, arg);
    if (something_failed)
        pthread_exit((void *)-1);     /* 触发清理栈，资源被放掉 */
    pthread_cleanup_pop(1);           /* 正常路径：弹出并执行清理 */
    return NULL;
}

嵌套 push 就是标准栈行为，释放顺序反过来 —— 后申请的先放：

c
pthread_mutex_lock(&lock_a);
pthread_cleanup_push(unlock_a, &lock_a);
pthread_mutex_lock(&lock_b);
pthread_cleanup_push(unlock_b, &lock_b);

do_work();                 /* 被取消时先解 b，再解 a */

pthread_cleanup_pop(1);    /* 解 b */
pthread_cleanup_pop(1);    /* 解 a */

清理函数里别做会阻塞的事，别再去拿锁。它运行在线程被取消的那个上下文里，拿锁有死锁风险。只做释放、关闭、标记这类确定的收尾。

九、线程的栈与栈大小 #

每个线程一块私有栈。主线程的栈是进程启动时内核给的，大小由 ulimit -s 决定；子线程的栈由 glibc 在 pthread_create 时 mmap 出来，默认同样跟 ulimit -s 走，x86_64 上一般 8 MiB，ulimit -s 报 8192（单位 KiB）。

栈底那一页是保护页（guard page），mmap 时不映射，越过它就 SIGSEGV。别关它，关掉后栈溢出会静默踩坏相邻内存，症状比崩溃难查得多。

c
int pthread_attr_setstacksize(pthread_attr_t *attr, size_t stacksize);
int pthread_attr_getstacksize(const pthread_attr_t *attr, size_t *stacksize);
int pthread_attr_setguardsize(pthread_attr_t *attr, size_t guardsize);
int pthread_attr_setstack(pthread_attr_t *attr, void *stackaddr, size_t stacksize);
接口 用途 后果
setstacksize 设定栈字节数 小于 PTHREAD_STACK_MIN 返回 EINVAL
setguardsize 保护页大小 设 0 关闭保护，不推荐
setstack 完全自定义栈 调用方负责 mmap/munmap，分配释放全归你 
c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 256 * 1024);   /* 256 KiB */
pthread_attr_setguardsize(&attr, 4096);
pthread_create(&tid, &attr, worker, NULL);
pthread_attr_destroy(&attr);

栈调小是为了省内存、抬高线程数上限。默认 8 MiB 的话，1000 个线程要 8 GiB 虚拟地址空间，32 位进程直接不成立。压到 256 KiB，同等规模降到 256 MiB。

代价是栈溢出。递归深度、栈上大数组、alloca、变长数组都吃栈：

c
static void *worker(void *arg)
{
    char buf[512 * 1024];      /* 栈上 512 KiB，小栈直接崩 */
    return NULL;
}

这类缓冲改 malloc，或者改 static（前提是线程安全）。栈溢出表现为莫名其妙的 SIGSEGV，gdb 里看栈指针落在哪一页最快。查运行中线程的实际栈范围用 GNU 扩展 pthread_getattr_np() 加 pthread_attr_getstack()，_np 就是 not POSIX；没代码可改的现场，看 /proc/self/task/<tid>/maps 里的可读写匿名段也能定位。

分离线程结束时它的栈由内核一并放掉；joinable 线程的栈要等 join 才释放。这就是「建了不 join 也不 detach」等于持续泄漏虚拟内存的原因。

十、线程局部存储 #

要让一个变量每个线程各有一份，Pthread 给了两种手段。

第一种是编译器扩展 __thread，GCC/Clang 支持，写法最省事：

c
static __thread int  t_counter = 0;      /* 每个线程一份，带初值 */
static __thread char t_buf[256];         /* 也可以放数组 */

static void *worker(void *arg)
{
    t_counter++;                          /* 别的线程看不到 */
    snprintf(t_buf, sizeof t_buf, "tid=%lu", (unsigned long)pthread_self());
    return NULL;
}

__thread 只能修饰静态或全局变量，不能修饰函数内的局部变量，也不能修饰函数参数。初始化值必须是编译期常量，不能写 __thread int x = compute();。它靠 TLS 段和 %fs 寄存器寻址，访问开销和普通全局变量几乎一致，这是它最大的优势。

第二种是 POSIX 标准接口，跨平台、可动态创建：

c
int pthread_key_create(pthread_key_t *key, void (*destructor)(void *));
int pthread_setspecific(pthread_key_t key, const void *value);
void *pthread_getspecific(pthread_key_t key);
int pthread_key_delete(pthread_key_t key);

pthread_key_create 造一个键，全进程共用一个 pthread_key_t，但每个线程通过 pthread_setspecific 存进去的值互不干扰。destructor 是这个键的析构回调：线程退出时，内核按线程逐个调用它，把该线程绑在这个键上的值传进去。pthread_key_delete 只销毁键本身，不触发任何线程的析构函数。

c
static pthread_key_t tls_key;
static pthread_once_t once = PTHREAD_ONCE_INIT;

static void free_buf(void *p) { free(p); }
static void make_key(void) { pthread_key_create(&tls_key, free_buf); }

static void *worker(void *arg)
{
    pthread_once(&once, make_key);            /* 全进程只初始化一次 */
    char *buf = pthread_getspecific(tls_key);
    if (!buf) {
        buf = malloc(256);
        pthread_setspecific(tls_key, buf);    /* 绑定到当前线程 */
    }
    /* 线程退出时 free_buf(buf) 自动被调用 */
    return NULL;
}

pthread_once 保证 make_key 在多线程竞争下只执行一次，这是建键的正确姿势 —— 别以为在 main 里建完就万事大吉，库代码里没人在 main 给你让路。两种方式摆在一起看：

对比项 __thread pthread_key_create 系列
标准归属 GCC/Clang 扩展，非 POSIX POSIX.1-2001 标准
变量形态 静态/全局变量，编译期确定 运行期按 key 动态存取
初值 只能是编译期常量 由 pthread_setspecific 决定
访问方式 直接写变量名 getspecific / setspecific 函数调用
销毁 无回调 有 destructor 回调，可挂 free
数量限制 无 受 PTHREAD_KEYS_MAX 限制
动态库场景 每线程每模块一份 键全局唯一，跨模块共享

选择标准很直接：变量形态已知、只在本模块用、不需要析构回调，用 __thread；需要动态创建、要跨模块共享键、要靠回调收尾，用 pthread_key_create。

析构函数最多跑 PTHREAD_DESTRUCTOR_ITERATIONS（Linux 上是 4）轮。若析构函数里又给同一个键设了新值，它会再被调一次，直到值清空或轮数用尽。所以别在析构函数里反复 setspecific，会白白耗轮次并被丢弃。

十一、线程与信号 #

信号在多线程进程里的行为和你直觉不一样，这是排障时最费时间的部分。

概念 范围 说明
信号处理函数 进程级共享 任一 pthread_sigmask 都不影响别人看到同一份 handler
信号掩码 线程级私有 pthread_sigmask 只改调用线程
未决信号 区分来源 进程级信号一份，pthread_kill 定向的挂在线程上
递送目标 任意可接收线程 进程级信号由内核挑一个没屏蔽它的线程处理

kill(pid, sig) 发的进程级信号，内核从所有未屏蔽该信号的线程里挑一个递送。挑哪个？没保证。所以「我在主线程装了 SIGINT 处理器，就该主线程收到」这个想法是错的。

c
int pthread_kill(pthread_t thread, int sig);
int pthread_sigmask(int how, const sigset_t *set, sigset_t *oldset);

pthread_kill 定向发给某个线程，sig 传 0 可以用来探测线程是否还活着（返回 ESRCH 说明没了）。pthread_sigmask 改当前线程的掩码，how 取 SIG_BLOCK / SIG_UNBLOCK / SIG_SETMASK。

想统一收信号，标准做法是「全屏蔽 + 专线等」：

c
int main(void)
{
    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGINT);
    sigaddset(&set, SIGTERM);

    /* 主线程先屏蔽，再建工作线程，线程自动继承这个掩码 */
    pthread_sigmask(SIG_BLOCK, &set, NULL);

    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);

    /* 只有 sigwait 这个线程在等，信号一定落到它手上 */
    int sig;
    sigwait(&set, &sig);
    printf("got signal %d, shutting down\n", sig);

    pthread_cancel(tid);
    pthread_join(tid, NULL);
    return 0;
}

关键顺序：先屏蔽再建线程。掩码是继承的，工作线程生下来就带着屏蔽集，信号无处可去，只能落在 sigwait 上。如果先建线程再屏蔽，工作线程没带屏蔽，信号仍会被它抢走。

sigwait 本身是取消点，也是唯一能同步等信号的正确姿势。别用 signal handler 去改全局 volatile 标志然后靠轮询 —— 那套在单线程下能用，多线程下 flag 的可见性和竞争都得自己兜。

  • SIGFPE、SIGSEGV、SIGILL 这类同步信号由具体线程的非法操作产生，内核直接送给出错的那个线程，掩码挡不住，sigwait 也等不到。
  • 信号处理函数里只能调用 async-signal-safe 的函数。printf、malloc 都不在其列，处理函数里调它们，行为不可预测。

十二、线程的生命周期全景 #

把前十一章串起来，一个线程的状态迁移就这几步。

text
pthread_create
      |  分配栈与 task_struct，状态 JOINABLE
      v
    运行中 ---- pthread_detach / 属性 ----> 分离态（结束时立即回收）
      |                                        |
      | 入口 return                             |
      | pthread_exit                           |
      | 被取消（走清理栈）                       |
      v                                        v
  已终止（保留退出状态与栈）              已终止（资源已回收）
      |
      | pthread_join
      v
  资源全部回收，pthread_t 可被复用
阶段 谁在动作 内核里发生什么
创建 pthread_create clone 出新 task_struct，mmap 出线程栈
运行 调度器 上下文切换，寄存器与栈指针换人
分离 pthread_detach 或创建属性 标记 detachstate，不改调度行为
终止 return / pthread_exit / 取消 清理栈跑完，退出码存进线程控制块
回收 pthread_join，或分离线程无需回收 释放栈与 task_struct，pthread_t 归还系统

三句话记主线：出生默认 joinable；结束不等于回收；不 join 不 detach 就是泄漏。

十三、易错点速查 #

现象 根因 对策
出错信息是乱的，errno 为 0 Pthread 函数不设 errno，错误码在返回值里 判返回值，strerror(ret)
pthread_join 返回 EINVAL 目标已分离，或已被 join 过一次 分离线程别 join；join 只调一次
进程内存只涨不降 建了 joinable 线程却从不 join 要么 join，要么入口第一句自分离
资源在正常路径没漏、异常路径漏了 入口函数 return，清理栈不触发 改 pthread_exit，或 pop(1)
编译报括号不匹配 pthread_cleanup_push / pop 没配对 同函数内成对，中间不许跳出
取消后整个进程卡死 异步取消杀在持锁点，锁永不释放 用 DEFERRED，异步取消只在纯计算里用
栈小的线程莫名 SIGSEGV 栈上大数组 / 深递归越界 大缓冲改 malloc，或调大 stacksize
线程拿到的参数全是乱值 循环里传 &i 或传局部量地址 传数组元素，或 (void *)(intptr_t)i
主线程退出后子线程不干活 main 的 return 等于 exit 主线程改调 pthread_exit(NULL)
屏蔽了信号却还是被别处收走 掩码是线程私有，别的线程没屏蔽 先 pthread_sigmask 再建线程
pthread_t 比较结果不对 用 == 直接比，或用 %lu 打印 用 pthread_equal()，别假设它是指针
线程 ID 复用后 join 到别的线程 线程结束后 pthread_t 被系统回收重用 线程结束就立刻处理，别缓存 ID
