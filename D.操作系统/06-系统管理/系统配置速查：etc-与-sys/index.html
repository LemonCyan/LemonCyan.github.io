一、/etc 是什么：配置的集中地 #

FHS 把 /etc 定义成主机专属的配置。同一套程序装到两台机器上，二进制一模一样，区别全在这个目录里。它装的是文本，不是二进制——cat 能看、diff 能比、git 能管。

里面混着三类东西，先分清再看文件：

类别 例子 改法
单文件主配置 /etc/fstab、/etc/passwd 直接编辑，盯住字段格式
目录式配置 /etc/sysctl.d/、/etc/pam.d/、/etc/apt/sources.list.d/ 加片段文件，文件名数字前缀定加载顺序
运行时生成 /etc/mtab、/etc/resolv.conf 别手改，由 mount、NetworkManager 重写

权限分布很集中：多数是 644 root:root，少数是 600（/etc/shadow 就是），因为那里面是密码散列，全局可读等于把散列分发给所有人去跑字典。可写的基本只有 root。改之前先备份，一条命令的事：

bash
cp -a /etc/ssh/sshd_config /etc/ssh/sshd_config.bak

改完别急着 restart，先验语法：

bash
sshd -t                        # 只解析配置，不启动服务
nginx -t
visudo -cf /etc/sudoers

守护进程多在启动时读一次配置，之后只在内存里用。改文件不 reload，等于没改。重载走 systemctl reload <unit>，或者给进程发 HUP：kill -HUP $(cat /run/sshd.pid)。

/etc 的结构直接映射了「谁拥有这台机器的什么」：主机名在 sysconfig 里，DNS 在 resolv.conf 里，账号在 passwd 里，日志去哪在 syslog.conf 里。把下面 32 个文件过一遍，一台机器的骨架就清楚了。

二、系统与启动相关配置 #

/etc/fstab 是文件系统表。开机时 mount -a 和 systemd 的挂载单元都读它，六个字段：设备名、挂载点、文件系统类型、挂载选项、dump 标志、fsck 顺序。

text
# 设备名        MountPoint  FileSystem Type  加载选项   fsck标志
/dev/hda1      /           ext2             defaults   1  1
/dev/hda6      /home       ext2             defaults   1  2
/dev/hda3      /usr        ext2             defaults   1  2
/dev/hda5      /var        ext2             defaults   1  2
/dev/hda2      swap        swap             defaults   0  0

fsck 那两列，1 表示先查根分区，2 表示其余分区，0 表示根本不查（swap 和 XFS 都写 0）。改完先 mount -a 干跑一遍，报错就回滚。这文件写错，机器起不来，得进救援模式。

/etc/mtab 记录当前已挂载的文件系统，由 mount 动态更新。现在多半是 /proc/self/mounts 的符号链接，内容来自内核。要看挂载状态用 findmnt，别编辑这个文件。

/etc/lilo.conf 是 LILO 引导器的多重启动配置，写内核镜像路径、根设备、默认启动项。改完必须跑一次 lilo 把引导块重写，否则改动只躺在文件里。用 GRUB 的机器没有这个文件，对应的是 /boot/grub/grub.cfg 加 /etc/default/grub。

/etc/issue 和 /etc/motd 是两个登录横幅，位置分得很清：issue 在登录提示符之前打印，还没认证就能看到；motd 在登录成功之后打印。issue 里可以用 \r、\m、\n 这类转义，分别展开成系统版本、机器名、tty 名。因为 issue 未认证即可见，别往里塞主机指纹和内部 IP。

/etc/ld.so.conf 是动态链接库的搜索路径，一行一个目录，末尾 include ld.so.conf.d/*.conf 收片段。改完必须重建缓存：

bash
ldconfig
ldconfig -p | grep libssl        # 看缓存里有没有

不跑 ldconfig，新目录里的 .so 不会进缓存，程序照样报 cannot open shared object file。临时救急可以用 LD_LIBRARY_PATH=/opt/lib ./app，但那只是给单个进程用。

三、网络配置 #

/etc/hosts 是最原始的域名解析，格式 IPaddress hostname aliases。查主机名时它排在最前面，DNS 没通也能用名字访问机器：

text
127.0.0.1 localhost localhost.localdomain
202.118.66.81 helius.dlut.edu.cn helius

第一行把 localhost 指到本机回环，第二行把 helius 钉死在 202.118.66.81。把常用机器写进来能省一次 DNS 往返。坑在于 IP 写死了，机器换地址就失联，排查连接问题先看这里。

/etc/resolv.conf 是 DNS 客户端配置，格式：

text
domainname 域名
search 域名
nameserver 主DNS服务器IP
nameserver 备DNS服务器IP

实际内容长这样：

text
search dlut.edu.cn
nameserver 202.118.66.6
nameserver 202.118.66.7

search 让不完整的域名自动补全——ping helius 会先试 helius.dlut.edu.cn。nameserver 指定解析服务器，最多看前三个。现代发行版里这个文件由 NetworkManager 或 systemd-resolved 生成，手改会被覆盖；要持久化就改连接的 DNS 设置，或写 /etc/systemd/resolved.conf。

/etc/host.conf 管主机名查找顺序，默认内容够用：

text
order hosts, bind
multi on

order hosts, bind 表示先查 /etc/hosts，没命中再问 DNS；multi on 允许一个主机名挂多个地址，返回全部而不是只回第一个。glibc 现在看的是 /etc/nsswitch.conf 里的 hosts: 行，host.conf 是给老程序留的兼容层。

/etc/HOSTNAME 与 /etc/sysconfig/network 都存主机名。旧 RedHat 系在 sysconfig 里写一条：

bash
HOSTNAME=box01.example.com
GATEWAY=202.118.66.1
GATEWAYDEV=eth0

想知道某个发行版把主机名放在哪个文件，直接搜 init 脚本：

bash
egrep hostname /etc/rc.d/init.d/*
egrep hostname /etc/init.d/*

现在统一用 hostnamectl set-hostname box01，它写 /etc/hostname 并同步内核里的名字。改完把新名字加进 /etc/hosts，否则 sudo 卡在解析上，一等就是半分钟。

/etc/services 是服务名到端口和协议的映射，格式 服务名称 端口号/协议 服务别名：

text
ftp 21/tcp
telnet 23/tcp
smtp 25/tcp mail

它覆盖系统已知的全部网络服务，多数机器不用动。只有在要给未收录的服务起名字，或者从别的 Unix 迁过来时才手工加。改错了会让依赖 getservbyname 的程序找不到端口。

/etc/networks 和 /etc/netmasks 给网络段起名字，路由表就能用名字代替一串数字：

text
/etc/networks
dlrin 202.199.128.0

/etc/netmasks
202.199.128.0 255.255.240.0

/etc/defaultrouter 是 Solaris 2.x 放默认网关的位置，Linux 侧写在 sysconfig 的 GATEWAY 里。看当前路由表：

bash
netstat -rn
Kernel IP routing table
Destination     Gateway         Genmask         Flags   Iface
202.118.66.0    0.0.0.0         255.255.255.0   U       eth0
127.0.0.0       0.0.0.0         255.0.0.0       U       lo
0.0.0.0         202.118.66.1    0.0.0.0         UG      eth0

Destination 是目标网段，Gateway 是下一跳，最后一行的 0.0.0.0 配上 UG 标志就是默认路由。加静态路由：

bash
/sbin/route add -net 202.118.66.0 netmask 255.255.255.0 eth0
/sbin/route add -net 202.199.128.0 netmask 255.255.240.0 gw 202.118.66.254

有了 networks 里的名字，参数能短一截：

bash
/sbin/route add -net dlrin gw 202.118.66.254

新系统上 ip route add 是主接口，route 命令属于 net-tools，很多精简镜像已经不预装。

四、用户与认证配置 #

/etc/passwd 一行一个账号，七个字段用冒号隔开：用户名、密码占位、UID、GID、描述、主目录、登录 shell。全员可读，所以密码位只放一个 x。

text
alice:x:1001:1001:Alice Chen:/home/alice:/bin/bash

/etc/shadow 放真正的密码散列和期限策略：用户名、散列、最后修改天数、最小间隔、最大期限、警告天数、禁用天数。权限 600，只有 root 能读。两个文件靠用户名对齐，手改时 UID 和组 ID 必须能对上 /etc/group。

/etc/group 存组信息：组名、组密码占位、GID、成员列表。

text
sudo:x:27:alice,bob

id 和 groups 的输出源头就是 passwd 加 group。查账号优先用 getent，它走 NSS，能覆盖 LDAP、SSSD 这类后端，grep 文件则只能看到本地账号：

bash
getent passwd alice
getent group sudo

/etc/pam.d/login 是登录程序的 PAM 栈，认证、账户、密码、会话四组规则写在一个文件里。各发行版内容差别不小，改之前先 ls /etc/pam.d/ 看同名服务有没有拆开。PAM 配错会把所有人挡在门外，包括 root，所以动手时手上要留一个已登录的 root shell。

/etc/host.equiv 和 $HOME/.rhosts 是 r 系列服务（rlogin、rsh）的主机信任表：host.equiv 全局生效，.rhosts 按用户。这两份等于免密登录白名单，靠主机名和用户名信任，现在已弃用，ssh 那边对应 authorized_keys。还留着的机器建议清空。

/etc/security 是老式写法，指这个目录，其中 securetty 列出允许 root 登录的终端设备：

text
console
tty1
ttyS0

想让 root 只能从本地控制台进，就改这一份。远程 tty 不在表里，root 直接登不上。

/etc/nologin 在关机或维护时创建，里面的文字会打印给试图登录的用户，同时拦住所有非 root 登录。维护窗口用它比改 PAM 省事，deleting 掉就恢复。正常关机流程会在下次启动时自动清理。

五、服务与守护进程配置 #

/etc/inetd.conf 是 inetd 超级服务器（/usr/sbin/inetd）的服务表，每行一个服务：

text
ftp    stream tcp nowait root /usr/sbin/tcpd in.ftpd -l -a
telnet stream tcp nowait root /usr/sbin/tcpd in.telnetd

字段依次是服务名、套接字类型、协议、等待方式、运行身份、程序路径、参数。inetd 平时不动，收到连接才 fork 对应程序，省内存。r 系列（rsh、rlogin）直接注释掉，明文协议加主机信任是老式攻击面。安全要求高的机器换 xinetd，配置按服务拆到 /etc/xinetd.d/ 下，Debian 系预装。

/etc/hosts.allow 和 /etc/hosts.deny 是 tcpd 的访问控制，靠 inetd/xinetd 调用 tcpd 才生效：

text
# /etc/hosts.allow
All: 202.118.

All: 202.118. 放行所有以 202.118 开头的来源。匹配顺序是先 allow 后 deny，两条都不命中就放行——默认是通的，所以要在 deny 里显式写 All: ALL 才有白名单效果。语法细节看 man tcpd、man hosts.allow、man hosts.deny。这套只管走 tcpd 的服务，ssh 直连绕开它，别指望它挡 ssh。

/etc/sendmail.cf 是 Sendmail 的主配置，由 M4 从 .mc 文件生成，手改的后果是下次生成就被覆盖。本地主机名列表在同目录的 /etc/sendmail.cw。真改 Sendmail 走 .mc 加 make。

/etc/named.boot 是 BIND 4.9.x 的启动文件，指定工作目录和缓存文件位置。BIND 8 之后换成 named.conf，还在用 named.boot 说明系统很老。

/etc/smb.conf 是 Samba 的共享配置，把 Linux 目录共享给 Windows。改完先 testparm 验语法，再 smbcontrol all reload-config 让 smbd 重读。

/etc/exports 是 NFS 服务器的导出表，一行一个目录、允许的客户端、挂载选项。NFS 不带用户认证，靠 IP 和 UID 信任，安全模型比 Samba 和 SSHFS 弱得多，跨网段导出前先想清楚谁在同一个信任域里。

/etc/ftpaccess 控制 FTP 访问策略（wu-ftpd 系），管谁能连、能进哪个目录、能传什么。/etc/ftpusers 是禁止 FTP 登录的账号名单，默认带 root、uucp、bin。FTP 明文传密码，这份名单是底线不是防护。/etc/ftpconversions 和 /etc/ftpgroups 分别管后缀转换规则（按扩展名实时压缩解压）和组权限映射。

上面这几个 FTP 文件只在跑 FTP 服务时有用。没装 vsftpd/wu-ftpd 的机器，目录里没有它们是正常的。

六、日志与轮转配置 #

/etc/syslog.conf 是 syslogd 的规则表，一行「选择器 + 动作」：选择器写「设施.级别」，动作用路径或 @主机。

text
*.info;mail.none;authpriv.none    /var/log/messages
authpriv.*                        /var/log/secure
*.emerg                           *

左边 mail.none 是从 *.info 里挖掉 mail 设施，分号是「加上/减去」的意思。动作写 @loghost 就把日志甩到远端 syslog 服务器，本机不留。现役实现多是 rsyslog，读 /etc/rsyslog.conf 加 /etc/rsyslog.d/*.conf，语法兼容老写法；systemd 系还可以用 journalctl 直接看二进制日志，配置在 /etc/systemd/journald.conf，Storage=persistent 才会落盘到 /var/log/journal。

日志写满磁盘是运维最常见的一类事故。轮转规则在 /etc/logrotate.conf，具体服务拆到 /etc/logrotate.d/：

text
/var/log/nginx/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    sharedscripts
    postrotate
        systemctl reload nginx > /dev/null 2>&1 || true
    endscript
}

rotate 14 保留 14 份，compress 压旧的，delaycompress 让最新一份保持未压缩（进程还在往里写）。postrotate 里重载服务，否则进程手里还是旧 inode，新文件写不进去、磁盘照样涨。手动验一遍：

bash
logrotate -d /etc/logrotate.conf     # 干跑，只打印不执行
logrotate -f /etc/logrotate.d/nginx  # 强跑一次

七、包管理器配置 #

包管理器的源列表也放在 /etc，按发行版分家。

Debian 系看 /etc/apt/sources.list，新版本还可以拆到 /etc/apt/sources.list.d/*.sources：

text
deb http://deb.debian.org/debian bookworm main contrib non-free
deb http://security.debian.org/debian-security bookworm-security main

格式是「类型 + URL + 发行版代号 + 组件」。deb 是二进制包，deb-src 是源码包。改完 apt update 拉索引，报 NO_PUBKEY 就去补 GPG 密钥，别直接 --allow-unauthenticated 放行。

RedHat 系在 /etc/yum.repos.d/*.repo，一个文件一个源：

text
[baseos]
name=CentOS Stream $releasever - BaseOS
baseurl=http://mirror.example.com/centos/$releasever-stream/BaseOS/$basearch/os/
gpgcheck=1
enabled=1

gpgcheck=1 别关。dnf 的主配置在 /etc/dnf/dnf.conf，installonly_limit 控制留几个旧内核——这个值太小，回滚内核时就没得选。

Arch 系一份 /etc/pacman.conf 管全部仓库，[core]、[extra]、[multilib] 各一段，注释掉 [multilib] 就装不了 32 位库。openSUSE 在 /etc/zypp/repos.d/。

四个发行版的共同点是：源地址是文本，改完必须刷新元数据缓存（apt update / dnf makecache / pacman -Sy）。pacman -Sy 单独跑有风险，装包请用 pacman -Syu，别让本地库和远端索引错位。

八、shell 与终端配置 #

/etc/profile 是登录 shell 读的全局环境，登录时执行一次。PATH、umask、TERM 这类变量在这里定：

bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
umask 022
export TERM=${TERM:-xterm-256color}

/etc/profile.d/*.sh 是它的片段目录，装软件时加自己的环境变量走这里，别去动 profile 本体——升级时被覆盖，改动就没了。

/etc/bashrc（Debian 系叫 /etc/bash.bashrc）是交互式非登录 shell 读的，每次开新终端都执行一遍。所以别名、提示符、补全放这里，别放 profile：放 profile 里，图形界面开的终端拿不到。

/etc/csh.cshrc 和 /etc/csh.login 是对 csh/tcsh 用户的对应文件，前者每次启动读，后者只在登录时读。

登录 shell 和交互 shell 读的文件不是同一批，这张表能省很多「为什么变量没生效」的排查：

文件 登录 shell 交互非登录 shell 谁来读
/etc/profile 读 不读 所有登录会话
/etc/profile.d/*.sh 读 不读 被 profile 调用
/etc/bashrc 读 读 bash 每次启动
~/.bash_profile 读 不读 用户级登录
~/.bashrc 间接读 读 用户级每次

/etc/shells 是合法登录 shell 的清单，一行一个绝对路径：

text
/bin/sh
/bin/bash
/bin/zsh
/usr/bin/fish

chsh 会拿目标 shell 去这个文件里核对，不在清单里直接拒绝。它同时管 FTP 的 shell 可用性判断——早期 ftpd 靠这份清单决定账号能不能登录。加装 zsh 后忘了登记，用户就换不过去。

/etc/environment 是 PAM 模块 pam_env 读的键值对，不带 export、不做变量展开，写的是纯 KEY=value。桌面会话的变量常放这里，因为图形登录不经过 shell 的启动文件。/etc/inputrc 管 readline 的按键绑定，/etc/DIR_COLORS 管 ls --color 的配色。

16 /etc/ftpusers 禁止 FTP 登录的账号名单 FTP 守护进程、PAM
17 /etc/ftpconversions、/etc/ftpgroups 按扩展名的实时转换规则、组权限映射 wu-ftpd
19 /etc/sendmail.cf Sendmail 主配置；主机名在 sendmail.cw sendmail
21 /etc/named.boot BIND 4.9.x 的工作目录与缓存文件 named
27 /etc/smb.conf Samba 共享、用户映射、打印 smbd、nmbd
30 /etc/X11/* X 服务器配置：显示、输入设备、字体路径 Xorg

shell 与登录外观

# 文件 管什么 谁来读
14 /etc/bashrc、/etc/csh.cshrc、/etc/profile 默认环境变量：PATH、umask、TERM bash、csh、登录 shell
20 /etc/issue、/etc/motd 登录前横幅与登录后欢迎信息 agetty、login

表里有几处发行版差异，动手前先确认路径存在：/etc/HOSTNAME 是旧 RedHat 5.x 的叫法，现在用 /etc/hostname；/etc/defaultrouter 只在 Solaris 上；/etc/named.boot 在 BIND 8 之后换成 named.conf；/etc/ftp* 只在跑 wu-ftpd 时才有；/etc/X11/xorg.conf 现在多数机器根本不生成，靠内核模式设置加自动探测，要强制指定才手写一份。

/etc 里的东西再多，查法只有一条：先确认文件在不在、权限对不对，再确认是哪个进程读它，最后确认那个进程重载没有。

十、/sys 是什么：内核对象的窗口 #

先看它挂在哪、占多大：

bash
mount | grep sysfs
sysfs on /sys type sysfs (rw,nosuid,nodev,noexec,relatime)

df -h /sys
Filesystem      Size  Used Avail Use% Mounted on
sysfs              0     0     0    - /sys

Size 是 0。/sys 是sysfs，一个伪文件系统：目录树全部由内核在内存里生成，磁盘上不存在这些文件，也不占一个字节。你 ls 出来的每一项都对应内核里的一个对象——目录是 kobject，文件是它的属性（attribute）。

这个对应关系决定了它的读写语义，和 /etc 完全是两码事：

动作 在 /etc 里 在 /sys 里
cat 一个文件 读磁盘上的字节 内核现场把对象属性格式化成文本
echo x > 文件 覆盖磁盘内容 内核解析 x，调用该属性的 store 回调
touch 新文件 真的建了个空文件 报错，目录树由内核维护
改完何时生效 重载服务后 立刻
重启之后 改动还在 回到内核默认值

所以在 /sys 里写文件不是「存配置」，是「发指令」。写进去的那串字符会被内核当成参数解析，格式不对直接返回 EINVAL，值不合法就忽略。写完再 cat 一次，看到的是内核当前的真实状态，不是你以为写进去的东西——做嵌入式调试时这一点很省事，不用另找状态查询接口。

值基本都是纯文本：一个整数、一个字符串、或者一串空格分隔的列表。没有加密，没有二进制结构，cat 就够。

bash
cat /sys/class/net/lo/mtu
65536
cat /sys/block/sda/queue/scheduler
[mq-deadline] kyber none

mq-deadline 外面的方括号表示当前选中项——这是内核自己加的标记。往同一个文件里写 none，再读一次，方括号就挪过去了。这种「读出来自带上下文」的约定，在 /sys 里很常见。

十一、/sys 的目录结构 #

十一个顶层子目录，各有明确分工。认准这张表，找参数就不用乱翻：

目录 内容 干什么用
/sys/devices 全局设备树，所有总线上的物理设备按拓扑展开 设备管理的根结构，其他目录的符号链接最终都指到这里
/sys/class 按功能分类的设备类型，每类一个子目录 从「我要找网卡/输入设备」的角度切入
/sys/bus 每种子目录对应一种已注册的总线 看某条总线上挂了哪些设备、有哪些驱动
/sys/dev 按 主:次 设备号组织的符号链接（char/、block/） 从设备号反查设备对象
/sys/block 块设备列表，已过时 老脚本兼容，现等价于 /sys/class/block
/sys/fs 系统里所有文件系统及按类存放的挂载点 看 cgroup、ext4、btrfs、fuse 的运行状态
/sys/kernel 内核里可调的参数 调优、资源管理
/sys/module 所有模块的信息，含编进内核的内联模块和外部 .ko 看模块参数、引用计数、当前状态
/sys/firmware 固件对象与属性的操作接口 加载、更新固件，读 ACPI/EFI 表
/sys/hypervisor 与 Xen 这类虚拟化监视器相关的接口 虚拟机内部读 hypervisor 信息
/sys/power 电源管理选项，覆盖当前电源子系统 写属性文件控制休眠、关机、重启

逐个说清。

/sys/devices 是全局设备结构体系，注册在各个总线上的物理设备都在这里，按总线拓扑展示。有两个特例不挂总线：

  • platform devices：芯片内部高速或低速总线上的控制器和外设，CPU 能直接访问。嵌入式板子上的 GPIO 控制器就是这一类。
  • system devices：芯片内部的核心组件，CPU、定时器都属于它。这类没有独立驱动，由体系结构相关代码负责配置。

这一层是内核对所有设备的分层表达模型，也是整个 sysfs 里最重要的设备管理结构。别的地方都是它的视图。

/sys/dev 维护一批符号链接，按字符设备和块设备的主次设备号组织：

bash
ls -l /sys/dev/block/8:0
/sys/dev/block/8:0 -> ../../devices/pci0000:00/.../block/sda

知道 major:minor 就能定位到设备对象。lsblk 和 stat 给出的设备号，可以直接拿来在这里查。

/sys/class 按功能给设备分类，每个类型一个子目录，里面是指向具体设备的符号链接。输入设备不管接的是 USB、PS/2 还是别的，全都出现在 /sys/class/input 下。这是统一设备模型的关键一层——你的代码不需要知道设备挂在哪条总线上，只按功能找就行。

/sys/block 是块设备目录。按分类逻辑它该在 /sys/class 下，但历史上一直留在这里。Linux 2.6.22 起这个目录被标记为过时，只有开了 CONFIG_SYSFS_DEPRECATED 才存在；2.6.26 起内容迁到 /sys/class/block，/sys/block 里只剩指向真实设备的符号链接，纯粹为了向后兼容。新代码写 /sys/class/block。

/sys/bus 下每个子目录对应一种内核支持且已注册的总线类型。/sys/devices 里每个设备都连着某条总线。每条总线下面还有两个子目录：

  • devices：该总线上所有设备的符号链接，指向 /sys/devices 里的真实设备。
  • drivers：注册到这条总线的全部驱动。每个驱动子目录下有可读可改的参数。
bash
ls /sys/bus/pci/devices | head -3
ls /sys/bus/pci/drivers

/sys/fs 描述系统里所有文件系统，包括文件系统本身和按类别存放的已挂载点。/sys/fs/cgroup 是 cgroup v2 的挂载点，/sys/fs/ext4/sda1 是那块 ext4 的运行参数，/sys/fs/btrfs/<uuid> 是 btrfs 的。

/sys/kernel 放内核里所有可调参数，用于系统调优和资源管理。/sys/kernel/mm/transparent_hugepage/enabled 控制透明大页，/sys/kernel/debug（挂 debugfs 后）用于内核调试。

/sys/firmware 是固件对象和属性的操作接口，系统加载固件机制的用户空间入口。/sys/firmware/acpi/tables 能读原始 ACPI 表，/sys/firmware/efi/efivars 能读写 EFI 变量。

/sys/hypervisor 专供 Xen 这类虚拟化系统。Xen 是开源的虚拟机监视器，一台物理机上同时跑多个操作系统。物理机上这个目录是空的，虚拟机里才有内容。

/sys/module 含系统中所有模块的信息。模块可以是编进内核映像的内联模块，也可以是外部加载的 .ko。每个模块一个子目录：

bash
ls /sys/module/e1000e/parameters/
cat /sys/module/e1000e/parameters/watchdog

改驱动参数走这里。有些参数只在加载时可写，已经加载的模块改了不生效——那类参数得走 /etc/modprobe.d/*.conf 加 options 行，再重新加载模块。

/sys/power 描述电源选项，覆盖当前在用的电源子系统。里面有多个属性文件让你控制整机电源状态：

bash
cat /sys/power/state
freeze mem disk
echo mem > /sys/power/state

state 列出支持的目标状态：freeze 是浅休眠，mem 是挂起到内存，disk 是挂起到磁盘。往它写入某个词，机器立刻进入该状态——这条命令在 SSH 里敲，会话当场断掉。

十二、/sys/class 与 /sys/devices #

这两个目录最容易混。一句话分清：/sys/devices 是实体树的唯一真身，/sys/class 是按功能切的索引。

同一个网卡会同时出现在好几处，但只有一处是真实目录：

bash
ls -l /sys/class/net/eth0
lrwxrwxrwx 1 root root 0 Nov 17 10:00 /sys/class/net/eth0 -> ../../devices/pci0000:00/0000:00:1f.6/net/eth0

ls /sys/class/net/
eth0  lo  wlan0

符号链接的指向就是它在 /sys/devices 里的位置。cd /sys/class/net/eth0 会跟进链接，pwd 显示真实路径；cd -P 和 readlink -f 得到的是同一个答案。要判断某个路径是不是符号链接，用 ls -l 或 test -L，别猜。

四层视图的分工：

视图 目录 组织维度 典型用途
拓扑 /sys/devices 按总线挂载关系展开 定位设备的真实路径
功能 /sys/class 按设备类别 遍历同类设备，如所有网卡、所有背光
总线 /sys/bus 按总线类型 看驱动绑定状态、驱动参数
设备号 /sys/dev 按 major:minor 从设备号反查

按功能遍历是日常最常用的写法，通配符直接扫：

bash
for d in /sys/class/net/*; do
    echo "$(basename "$d") $(cat "$d/address")"
done

同一类设备有多块时，编号就是 eth0、eth1，sda、sdb。名字本身不稳定，重启后编号会变。要绑死设备，认 /sys/class/net/*/device 指向的 PCI 路径，或者 udev 的 ID_SERIAL。

驱动绑定状态在 /sys/bus/<bus>/drivers/<driver>/ 下：

bash
ls /sys/bus/pci/drivers/e1000e/
0000:00:1f.6  bind  module  new_id  remove_id  uevent  unbind

那串 PCI 地址是符号链接，指向设备。bind 和 unbind 是写接口——往 unbind 写设备地址，驱动就解绑：

bash
echo 0000:00:1f.6 > /sys/bus/pci/drivers/e1000e/unbind
echo 0000:00:1f.6 > /sys/bus/pci/drivers/e1000e/bind

这是远程操作里最容易把自己弄断网的一套命令：解绑的是你正在用的网卡，SSH 立刻断。所以这些写操作只在本地控制台做。

/sys/class 下还有一类不含设备的纯管理类，比如 /sys/class/thermal、/sys/class/power_supply、/sys/class/leds。它们同样是符号链接集合，只是指向的对象未必能在 /sys/devices 里一眼认出来。

十三、在 /sys 里调内核参数 #

模式固定：cat 读，echo 写。写之前先读，记住原值，出错好回退。

调背光亮度：

bash
cat /sys/class/backlight/intel_backlight/brightness
1200
cat /sys/class/backlight/intel_backlight/max_brightness
937
echo 300 > /sys/class/backlight/intel_backlight/brightness

brightness 的合法范围由 max_brightness 给出，超范围写进去返回 EINVAL，值不变。

调磁盘 I/O 调度器：

bash
cat /sys/block/sda/queue/scheduler
[mq-deadline] kyber none
echo kyber > /sys/block/sda/queue/scheduler

调 CPU 频率策略：

bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
powersave
echo performance > /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor

scaling_available_governors 列出这一代 CPU 支持的策略，只有列出来的才能写。笔记本插电和用电池时切策略，就是往这个文件写两次不同值。

调网卡 MTU：

bash
cat /sys/class/net/eth0/mtu
1500
echo 9000 > /sys/class/net/eth0/mtu

MTU 改大要求整条链路都支持巨型帧，中途有一台设备按 1500 转发，包就被丢。远程改这个参数，先确认跳数。

调透明大页：

bash
cat /sys/kernel/mm/transparent_hugepage/enabled
always [madvise] never
echo never > /sys/kernel/mm/transparent_hugepage/enabled

这是数据库服务器上的常规操作——THP 的延迟分配会拖慢内存密集型进程，很多 DBA 脚本第一件事就是关掉它。

读写权限的边界要清楚：

情况 表现
非 root 写入 Permission denied，只有 root 或有 CAP_SYS_ADMIN 的进程能写
属性只读 EACCES 或 EIO，ls -l 看权限位是 r--r--r--
值格式不对 EINVAL，写入被拒，原值不变
容器内 /sys 常以只读方式挂载，写了报 Read-only file system

写的时候别用 >>。追加对这类属性没有意义，内核按完整字符串解析，多一个换行或旧内容就会失败。用 >，或者更稳的：

bash
echo 300 | tee /sys/class/backlight/intel_backlight/brightness

tee 的好处是失败时能看到报错，而且不需要另起 shell。echo 在 sudo 环境下的重定向有个老坑：sudo echo 1 > /sys/... 里的重定向由当前 shell 执行，权限不够。写成 echo 1 | sudo tee /sys/... 才对。

十四、/proc 与 /sys 的分工 #

两者都是伪文件系统，都在内存里生成，都不占磁盘。区别在内容组织：/proc 以进程和杂项统计为主，/sys 以设备与内核对象模型为主。

维度 /proc /sys
主要用途 进程状态、内核统计、sysctl 开关 设备、驱动、总线、模块的结构化视图
典型内容 /proc/<pid>/、meminfo、cpuinfo、/proc/sys/ /sys/class/、/sys/devices/、/sys/bus/
数据结构 数字命名的进程目录加一堆平铺文件 分层对象树，符号链接交织
可写部分 /proc/sys/ 下的 sysctl 参数 各设备的属性文件
定位方式 按进程号或固定文件名 按设备类别、总线、设备号
挂载点 proc sysfs

/proc 的历史包袱重。它最早是进程信息接口，后来什么杂项都往里塞——内存、中断、文件系统、内核参数，全成了平铺文件。读 /proc 里的文件时，系统现场从内核取数据返回；进程状态这种信息本来就在变，所以每次 cat /proc/<pid>/status 拿到的都是当时那一刻的值。

/sys 是后来补的结构化方案。设备模型在 /proc 里没法表达（一台机器上几百个设备，平铺文件名的组合爆炸），sysfs 用对象树加符号链接解决了索引问题。所以现在分工很清晰：

  • 看进程 → /proc。/proc/<pid>/cmdline、status、fd/、maps。
  • 看设备 → /sys。分类、总线、驱动绑定、设备参数。
  • 改内核开关 → 先看 /proc/sys（sysctl 树），/sys 补剩下的。

/proc/sys 和 /sys/kernel 容易混。前者是 sysctl 的存储树，路径里的斜杠换成点就是 sysctl 的键名，sysctl 命令和 /etc/sysctl.conf 都只认它：

bash
cat /proc/sys/net/ipv4/ip_forward
sysctl net.ipv4.ip_forward

后者是内核对象的属性，没有对应的 sysctl 键名，只能用文件接口。所以「能不能写进 sysctl.conf」取决于参数在不在 /proc/sys 下——在 /sys 里的那些，得另找持久化办法。

十五、可调参数的持久化 #

/sys 和 /proc/sys 里的值全在内存里。重启之后内核用编译时的默认值重新生成整个树，你写进去的东西一个都不剩。这是伪文件系统的本质决定的，不是配置没保存。

分两种情况处理。

/proc/sys 下的参数走 sysctl：

bash
sysctl -w net.ipv4.ip_forward=1          # 临时，重启失效
echo 'net.ipv4.ip_forward = 1' >> /etc/sysctl.conf
sysctl -p                                # 立刻应用

现代发行版更推荐片段式，放 /etc/sysctl.d/ 下：

bash
cat > /etc/sysctl.d/99-tuning.conf <<'EOF'
net.ipv4.ip_forward = 1
net.core.somaxconn = 4096
vm.swappiness = 10
fs.file-max = 2097152
EOF
sysctl --system

文件名前缀是加载顺序，99- 排在后面，同键覆盖前面的。sysctl --system 依次读 /etc/sysctl.d/*.conf、/run/sysctl.d/*.conf、/usr/lib/sysctl.d/*.conf，最后才是 /etc/sysctl.conf。想看某个键从哪个文件来：

bash
sysctl -a --pattern 'net.ipv4.ip_forward'

/sys 下的参数没有 sysctl 入口，三条路可走。

第一条，udev 规则，适合跟设备绑定、设备一出现就要设的值：

text
# /etc/udev/rules.d/99-backlight.rules
ACTION=="add", SUBSYSTEM=="backlight", RUN+="/bin/sh -c 'echo 300 > /sys/class/backlight/%k/brightness'"

%k 是设备名，udev 会替换。改完 udevadm control --reload 再 udevadm trigger 让规则跑一遍。网卡 MTU 这类跟设备走的参数也放这里最好，设备重新插拔时自动重设。

第二条，systemd 服务单元，适合开机一次性执行：

text
# /etc/systemd/system/thp-off.service
[Unit]
Description=Disable transparent hugepage
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/bin/sh -c 'echo never > /sys/kernel/mm/transparent_hugepage/enabled'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target

bash
systemctl daemon-reload
systemctl enable --now thp-off.service

第三条，systemd-tmpfiles，适合单纯往文件里写一行：

text
# /etc/tmpfiles.d/thp.conf
w /sys/kernel/mm/transparent_hugepage/enabled - - - - never

bash
systemd-tmpfiles --create /etc/tmpfiles.d/thp.conf

w 是写入指令，末尾是内容。它开机时由 systemd-tmpfiles-setup.service 执行，比自建 unit 轻。

有些参数改内核命令行更稳妥，比如 transparent_hugepage=never 加进 GRUB 的 GRUB_CMDLINE_LINUX，内核启动时就按它初始化，从根上避免运行时再改。改完记得 update-grub 或 grub2-mkconfig。

最后一条原则：任何持久化都要重启验证一次。sysctl -p 成功不代表开机时会读那个文件——文件放错目录、权限不对、被后面的片段覆盖，都会让改动静默失效。

十六、易错点速查 #

现象 原因 处理
改了配置，服务行为没变 守护进程只在启动时读一次配置 systemctl reload，或发 HUP
改完 /sys 的值，重启又变回去 伪文件系统重新生成 写 sysctl.d、udev 规则或 systemd 单元
touch /sys/class/net/test 报错 目录树由内核维护 不做这件事，/sys 不是可写目录
echo 写入报 EINVAL 值超范围或格式不对 先 cat 同目录的可用值清单
sudo echo 1 > /sys/... 权限不足 重定向在非特权 shell 里执行 echo 1 | sudo tee /sys/...
用 vim 编辑 /sys 文件失败 编辑器靠临时文件加改名保存 用 echo 或 tee
/etc/mtab 手改后又被覆盖 由 mount 动态生成 看挂载用 findmnt 或 /proc/self/mounts
ldconfig 忘了跑，新库找不到 动态库缓存没更新 ldconfig 后确认 ldconfig -p
改 /etc/fstab 后系统起不来 挂载项写错，启动卡在 mount 先 mount -a 试跑，保留救援入口
改 /etc/pam.d/* 后所有人登不进 PAM 栈语法错误 动手前留一个已登录 root shell
/etc/resolv.conf 改完被还原 NetworkManager 或 resolved 重写了它 改连接配置或 resolved.conf
解绑网卡后 SSH 断线 /sys/bus/.../unbind 解绑了正在用的设备 只在本地控制台做这类操作
容器里写 /sys 报只读 容器以只读方式挂载 sysfs 宿主机上改，或在容器运行时放开
ls -l /sys/class/net/eth0 显示大小 4096 它是符号链接，大小无意义 看箭头指向的 ../.. 路径
主机名改了，sudo 卡半分钟 新名字不在 /etc/hosts 里，解析超时 补一行 127.0.1.1 box01

三个动作值得养成习惯：改任何 /etc 文件前 cp -a 备份一份；改完用对应的 -t 参数验语法；改 /sys 或 /proc/sys 前先 cat 记住原值，方便回退。

/etc 是持久的那一层，写下去就留在磁盘上，代价是必须重载进程才生效。/sys 是即时的那一层，写下去立刻作用到内核对象，代价是重启即散。把这两层的边界认清，配置问题就少一半——出了故障先问一句：这个设置是写在文件里没被读，还是写在内存里被重启冲掉了。
