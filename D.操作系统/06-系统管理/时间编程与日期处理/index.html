一、时间的两种表示：时间戳与结构体 #

时间编程的骨架就一句话：time_t 是绝对时间，struct tm 是分解后的日历时间，两者互转就是全部工作。

表示 类型 是什么 带时区吗 用在哪
日历时间 / 时间戳 time_t 自 1970-01-01 00:00:00 UTC 起经过的秒数 不带，全球同一个数 存储、比较、传输、日志
分解时间 struct tm 年、月、日、时、分、秒、星期、年内第几天、夏令时标志 带，localtime 填的是本地时区 显示、解析、日历运算

一条时间戳在东京和纽约是同一个数字；同一时刻的 struct tm 在两个地方长得完全不一样。分工就在这里。

转换方向只有四条，记住这张图就不会绕晕：

text
                 time()                localtime()
   内核时钟 ──────────────> time_t ──────────────────> struct tm
                              ^                          │
                              └──────── mktime() ────────┘

                 time()                gmtime()
   内核时钟 ──────────────> time_t ──────────────────> struct tm（UTC）

mktime 只往 localtime 方向走。反过来把 struct tm 按 UTC 还原成 time_t，POSIX 没有标准函数，只有 timegm 这类扩展。

UTC 和 GMT #

Coordinated Universal Time（UTC） 是世界标准时间，日常口语里的格林尼治标准时间（Greenwich Mean Time，GMT）说的是同一件事的两套叫法。严格讲 GMT 是英国那个时区的名字，UTC 是一把全球统一的尺子。代码和日志里只出现 UTC，别写 GMT。

Calendar Time（日历时间）：用一个标准时间点到此刻经过的秒数来表示时间。这个标准时间点就是 1970-01-01 00:00:00 UTC，叫纪元（epoch）。

这句定义落到 C 里要打个补丁：time_t 只是「算术类型」，POSIX 才把它钉成按秒计的整数。所以别对它的宽度做假设，后面会展开。

二、time_t 与纪元 #

time_t 的几条硬事实：

  • 起点固定为 1970-01-01 00:00:00 UTC，这个点全球统一，没有第二个
  • 有符号整数类型，宽度由实现决定：32 位平台上 4 字节，64 位 Linux 的 LP64 下 8 字节
  • 允许负数，表示 1970 年之前的时间
  • 单位是秒，不带小数部分，也不含闰秒
  • 不含任何时区信息，所以它才能跨机器直接比较

取当前时间就一个函数，素材里的原型是：

c
#include <time.h>

time_t time(time_t *tloc);

两种写法都合法：

c
#include <time.h>
#include <stdio.h>

int main(void) {
    time_t now = time(NULL);       /* 只要返回值，传 NULL */
    if (now == (time_t)-1) {
        perror("time");
        return 1;
    }
    printf("%lld\n", (long long)now);
    return 0;
}

打印 time_t 一律先强转 (long long) 配 %lld。直接 %ld 在 32 位平台上对、在别处不一定对，time_t 和 long 不是同一个东西。

三、struct tm 的九个字段 #

struct tm 是拆开的日历时间，九个字段，一个不多一个不少：

字段 含义 范围 坑在哪
tm_sec 秒 0-60 60 是给闰秒留的，实际几乎见不到
tm_min 分 0-59 无
tm_hour 时 0-23 23 点之后是 0 点，不是 24
tm_mday 日 1-31 月份里的第几天，从 1 开始
tm_mon 月 0-11 从 0 开始，1 月是 0，12 月是 11
tm_year 年份减 1900 从 1900 起算 2024 年存的是 124
tm_wday 星期 0-6，周日是 0 周一不是 0，周日才是
tm_yday 年内第几天 0-365，1 月 1 日是 0 从 0 开始，不是从 1
tm_isdst 夏令时标志 >0 是，0 否，<0 未知 换算时给 -1，让系统自己判断

定义原文照录：

c
struct tm {
    int tm_sec;    /* Seconds (0-60) */
    int tm_min;    /* Minutes (0-59) */
    int tm_hour;   /* Hours (0-23) */
    int tm_mday;   /* Day of the month (1-31) */
    int tm_mon;    /* Month (0-11) */
    int tm_year;   /* Year - 1900 */
    int tm_wday;   /* Day of the week (0-6, Sunday = 0) */
    int tm_yday;   /* Day in the year (0-365, 1 Jan = 0) */
    int tm_isdst;  /* Daylight saving time */
};

三个偏移必须刻在手上：月份 0 起、年份减 1900、星期天是 0。抄错任意一个，输出就会偏一个月、一百多年，或者整体错一天。

正确的打印姿势：

c
printf("%04d-%02d-%02d %02d:%02d:%02d\n",
       tm.tm_year + 1900, tm.tm_mon + 1, tm.tm_mday,
       tm.tm_hour, tm.tm_min, tm.tm_sec);

四、获取当前时间 #

拿「现在」有三个入口，精度差着三个数量级：

接口 头文件 精度 标准出处 现在怎么办
time() <time.h> 秒 C 标准 / POSIX 秒级够用就用它
gettimeofday() <sys/time.h> 微秒 POSIX.1-2001，在 POSIX.1-2008 里标为废弃 读老代码要认得
clock_gettime() <time.h> 纳秒 POSIX.1-2001 新代码用它

gettimeofday 的原型和配套结构体：

c
#include <sys/time.h>

int gettimeofday(struct timeval *tv, struct timezone *tz);

struct timeval {
    time_t      tv_sec;   /* seconds，秒数 */
    suseconds_t tv_usec;  /* microseconds，微秒 */
};

第二个参数 tz 是历史包袱，现代实现直接忽略，一律传 NULL。

它给的是「此刻」，不是「从凌晨到现在的差」。素材里说它常用来算事件耗时，做法是调两次相减：

c
#include <sys/time.h>
#include <stdio.h>

struct timeval a, b;
gettimeofday(&a, NULL);
do_work();
gettimeofday(&b, NULL);

double ms = (b.tv_sec  - a.tv_sec)  * 1000.0
          + (b.tv_usec - a.tv_usec) / 1000.0;
printf("%.3f ms\n", ms);

tv_usec 的取值是 0 到 999999，两次调用跨过整秒时，秒差为正、微秒差为负，两项合起来才是真实间隔。只拿 tv_usec 相减是初学者最常见的错。

两种亚秒结构体的对照：

结构体 头文件 秒字段 亚秒字段 单位
struct timeval <sys/time.h> tv_sec tv_usec 微秒，1e-6
struct timespec <time.h> tv_sec tv_nsec 纳秒，1e-9

clock_gettime 的细节放到第十章，那里连几种 clock 一起讲。

五、本地时间与世界时 #

time_t 到 struct tm 有两条路，区别只在时区：

c
#include <time.h>

struct tm *gmtime(const time_t *timep);     /* 转 UTC，也叫格林尼治标准时间 */
struct tm *localtime(const time_t *timep);  /* 转本地时区 */

两个都返回 struct tm *，又都不分配新内存——它们指向库内部一块静态缓冲区。这条比函数名重要得多：下一次调用会把上一次的结果覆盖掉。

c
time_t now = time(NULL);
struct tm *a = localtime(&now);
struct tm  save = *a;          /* 要留就得抄一份 */
struct tm *b = gmtime(&now);   /* 此刻 a 指向的内容已经变了 */

同样的道理让它们在多线程里直接不安全。POSIX 给了可重入版本，自己传缓冲区：

c
#include <time.h>

struct tm *gmtime_r(const time_t *timep, struct tm *result);
struct tm *localtime_r(const time_t *timep, struct tm *result);

c
struct tm tmv;
if (localtime_r(&now, &tmv) == NULL) {
    /* 失败，errno 有原因 */
}

写库代码、写多线程程序，只用带 _r 的。_r 是 POSIX 的东西，不是 C 标准，Windows 上对应的是 localtime_s，签名不一样，跨平台要包一层。

两条路读同一个瞬间，读出来的是不同相貌。北京时间（UTC+8）下两者差 8 小时，差多少不是常数，看你所在时区，还看当天有没有夏令时。

选择原则很干脆：

场景 用哪个
给人看的界面、日志抬头 localtime / localtime_r
存数据库、写文件、跨机器传 用 time_t 原值，或 UTC 字符串
算两个时刻的距离 直接用 time_t 相减，别过 struct tm
显示服务器统一时间线 gmtime / gmtime_r

六、时区是怎么算的 #

时区不是查表查出来的固定偏移，是规则算出来的。规则来自三样东西：

  • TZ 环境变量，是最高的优先级
  • /etc/localtime，指向 /usr/share/zoneinfo/ 下某个文件的副本或软链
  • /etc/timezone，Debian 系的文本记录，程序不直接读它

TZ 的几种写法：

bash
TZ=Asia/Shanghai date
TZ=UTC date
TZ=America/New_York date
TZ= date                      # 置空，强制 UTC
unset TZ                      # 回到系统默认

TZ 只影响当前进程和它派生的子进程，不动系统设置。临时跑个跨时区的脚本，这是最省事的手段。

进程内的改法：

c
#include <stdlib.h>
#include <time.h>

setenv("TZ", "Asia/Shanghai", 1);
tzset();                       /* 必须调，让库重新读 TZ */

time_t now = time(NULL);
struct tm lt;
localtime_r(&now, &lt);

改了 TZ 不调 tzset()，接下来拿到的还是旧时区的结果。

偏移量让 strftime 吐出来最稳：

c
char buf[64];
strftime(buf, sizeof buf, "%Y-%m-%d %H:%M:%S %z", &lt);
/* 输出形如 2024-05-01 12:00:00 +0800 */

tm_gmtoff 和 tm_zone 也能直接读偏移和时区名，但它们是 glibc 和 BSD 的扩展字段，不在 C 标准的九个字段里，严格模式下要开 _DEFAULT_SOURCE 或 _GNU_SOURCE 才可见。用 %z 不用操心这个。

时区偏移为什么必须按规则算，看两个例子就明白：

地点 冬季偏移 夏季偏移 说明
Asia/Shanghai +08:00 +08:00 中国不实行夏令时，全年一个偏移
America/New_York -05:00 -04:00 实行夏令时，切换日当天差一小时

北京时间的单一偏移是历史选择的结果，不是时区天然如此。同一套代码换个 TZ 就跑出另一个答案，这正说明偏移必须由库算，不能写死。

再补一条：跨时区存时间永远存 UTC 或 time_t。把本地时间字符串当唯一记录，遇到夏令时回拨那一小时会出现两个相同的本地时刻，谁先谁后分不出来。

七、mktime：结构体转时间戳 #

正向换完了，反向是 mktime：

c
#include <time.h>

time_t mktime(struct tm *tm);

int timelocal(struct tm *tm);    /* 历史上的别名，已废弃 */

它按本地时区把 struct tm 解释成 time_t，失败返回 (time_t)-1。

mktime 有几个别处没有的脾气，值得单列：

  • 传的是非 const 指针，函数会就地改你传进去的结构体
  • 入口会忽略并重算 tm_wday 和 tm_yday，你不用自己填对
  • tm_isdst 传 -1 表示「我不知道，你算」，传 0 表示标准时间，传正数表示夏令时
  • 传入的字段可以越界，它会帮你归一化：tm_mday = 32 会进位到下个月

最后一条常被当成技巧用。算「30 天后是几号」，不用管月末有几天：

c
#include <time.h>
#include <stdio.h>

time_t now = time(NULL);
struct tm t;
localtime_r(&now, &t);
t.tm_mday += 30;
t.tm_isdst = -1;
time_t later = mktime(&t);

字段越界后的归一化靠 mktime 完成，mktime 返回的 time_t 已经是正确时刻。再 localtime_r 一次就能拿到干净的日历字段。

一个完整可编译的例子：

c
#include <stdio.h>
#include <time.h>
#include <string.h>

int main(void) {
    struct tm t;
    memset(&t, 0, sizeof t);
    t.tm_year = 2024 - 1900;
    t.tm_mon  = 4 - 1;       /* 4 月 */
    t.tm_mday = 1;
    t.tm_hour = 12;
    t.tm_min  = 0;
    t.tm_sec  = 0;
    t.tm_isdst = -1;

    time_t ts = mktime(&t);
    if (ts == (time_t)-1) {
        fprintf(stderr, "mktime 失败\n");
        return 1;
    }
    printf("time_t = %lld\n", (long long)ts);
    printf("归一化后 = %04d-%02d-%02d %02d:%02d:%02d wday=%d yday=%d\n",
           t.tm_year + 1900, t.tm_mon + 1, t.tm_mday,
           t.tm_hour, t.tm_min, t.tm_sec, t.tm_wday, t.tm_yday);
    return 0;
}

注意 memset 清零。struct tm 里没填的字段如果是栈上的垃圾值，mktime 会照着垃圾算，结果五花八门。

mktime 失败返回 (time_t)-1，而这个值本身也是一个合法时刻（1969-12-31 23:59:59 UTC）。老代码里这个歧义无解，判失败前先置 errno = 0，返回后再看 errno 有没有被置。

timegm 是 mktime 的 UTC 版本，按 UTC 解释字段，不走本地时区。它来自扩展而非 POSIX，可移植性差一些。

八、strftime：格式化输出 #

asctime 和 ctime 是图省事的两个函数，格式写死：

c
#include <time.h>

char *asctime(const struct tm *tm);   /* 结构体转字符串，如 Sat Jul 30 08:43:03 2005 */
char *ctime(const time_t *timep);     /* 时间戳直接转本地时间字符串 */

c
time_t now = time(NULL);
printf("%s", ctime(&now));
/* 输出形如 Wed May  1 12:00:00 2024\n，末尾自带换行 */

它们的问题一样多：返回值指向静态缓冲区，不可重入，末尾带换行，格式没法改。真实代码里一律用 strftime。

原型：

c
#include <time.h>

size_t strftime(char *s, size_t max, const char *format, const struct tm *tm);

返回写进缓冲区的字节数，不含结尾的 \0；返回 0 表示结果放不下或者出错。所以缓冲区永远得留出一个字节，判断返回值 0 时要当成「太小了」，别当成成功。

常用的格式符：

格式符 输出 例子
%Y 四位年份 2024
%m 月份，补零 05
%d 日，补零 01
%H 小时，24 时制，补零 12
%M 分，补零 30
%S 秒，补零 05
%F 等价 %Y-%m-%d 2024-05-01
%T 等价 %H:%M:%S 12:30:05
%z 时区偏移 +0800
%Z 时区名 CST
%a 星期缩写 Wed
%A 星期全称 Wednesday
%b 月份缩写 May
%j 年内第几天，三位补零 122
%s 自纪元起的秒数 1714537805
%% 一个字面量百分号 %

一个把时间戳转成日志标准格式的函数：

c
#include <time.h>
#include <stdio.h>

void fmt_time(time_t ts, char *out, size_t n) {
    struct tm tmv;
    if (localtime_r(&ts, &tmv) == NULL) {
        snprintf(out, n, "invalid");
        return;
    }
    if (strftime(out, n, "%Y-%m-%d %H:%M:%S", &tmv) == 0)
        snprintf(out, n, "buffer too small");
}

要毫秒要自己拼，strftime 不管亚秒：

c
struct timespec tsp;
clock_gettime(CLOCK_REALTIME, &tsp);

struct tm tmv;
localtime_r(&tsp.tv_sec, &tmv);

char head[64];
strftime(head, sizeof head, "%Y-%m-%d %H:%M:%S", &tmv);
printf("%s.%03ld\n", head, tsp.tv_nsec / 1000000);

%N 这种纳秒格式符是 GNU date 的扩展，strftime 里没有，在 strftime 里写 %N 会原样输出或者行为未定义。

九、strptime：解析字符串 #

逆操作是 strptime：

c
#define _XOPEN_SOURCE          /* 要它才可见 */
#include <time.h>

char *strptime(const char *s, const char *format, struct tm *tm);

成功返回指向「第一个没被消费的字符」的指针，全部消费完就返回指向结尾 \0 的指针；失败返回 NULL。

关键点：strptime 只填 struct tm，不产出 time_t。拿到结构体还要再走一次 mktime：

c
#include <stdio.h>
#include <string.h>
#include <time.h>

int main(void) {
    const char *in = "2024-05-01 12:30:05";
    struct tm t;
    memset(&t, 0, sizeof t);

    char *end = strptime(in, "%Y-%m-%d %H:%M:%S", &t);
    if (end == NULL || *end != '\0') {
        fprintf(stderr, "格式不匹配，剩余：%s\n", end ? end : "(null)");
        return 1;
    }

    t.tm_isdst = -1;
    time_t ts = mktime(&t);
    if (ts == (time_t)-1) {
        fprintf(stderr, "mktime 失败\n");
        return 1;
    }
    printf("%lld\n", (long long)ts);
    return 0;
}

strptime 的坑集中在四处：

  • 只检查 end == NULL 不够，必须再看 *end 是不是 \0，否则「2024-05-01 后面还有一堆垃圾」会静默通过
  • 结构体要先清零，strptime 只填格式里出现的字段
  • tm_isdst 它不填，得自己给 -1
  • %Y 遇到两位年份的历史行为有歧义，写解析格式时用四位

strptime 是 XSI 扩展，在 glibc 里要定义 _XOPEN_SOURCE 或 _GNU_SOURCE，否则编译时找不到声明。

十、高精度时间：clock_gettime #

clock_gettime 走 POSIX.1-2001，是现在拿时间的正路：

c
#include <time.h>

int clock_gettime(clockid_t clk_id, struct timespec *tp);

struct timespec {
    time_t tv_sec;    /* 秒 */
    long   tv_nsec;   /* 纳秒，0 到 999999999 */
};

glibc 2.17 之前，clock_gettime 放在 librt 里，编译链接要加 -lrt；2.17 起并入了 libc，不用再加。老代码和老构建脚本里的 -lrt 就是为它留的，加上也无害。

bash
gcc -o t t.c              # glibc >= 2.17
gcc -o t t.c -lrt         # 老系统要这个

一个测耗时的标准写法：

c
#include <time.h>
#include <stdio.h>

static double diff_ms(struct timespec a, struct timespec b) {
    return (b.tv_sec  - a.tv_sec)  * 1000.0
         + (b.tv_nsec - a.tv_nsec) / 1e6;
}

int main(void) {
    struct timespec t0, t1;
    clock_gettime(CLOCK_MONOTONIC, &t0);
    do_work();
    clock_gettime(CLOCK_MONOTONIC, &t1);
    printf("%.3f ms\n", diff_ms(t0, t1));
    return 0;
}

测耗时用 CLOCK_MONOTONIC，不要用 CLOCK_REALTIME。这一点是硬规矩，理由在下一章。

tv_nsec 是纳秒，1 毫秒等于 1000000 纳秒。两个 timespec 相减时秒和纳秒分开减，跨整秒时纳秒差为负，合起来才是真值，写法和 timeval 一样。

十一、几种 clock 的区别 #

clock_gettime 的第一个参数决定读的是哪块表，选错比写错代码后果更严重。

clock 基准 会被系统时间调整影响吗 会随机器休眠停走吗 典型用途
CLOCK_REALTIME 1970-01-01 UTC 会 不会，持续走 取墙上时间、打时间戳
CLOCK_MONOTONIC 开机后的某个点，无固定起点 不会 会停 算耗时、超时判断
CLOCK_MONOTONIC_RAW 同单调钟，不校正 不会 会停 需要未校正硬件计数
CLOCK_BOOTTIME 含休眠时间 不会 不会停 需要算上休眠的总时长
CLOCK_PROCESS_CPUTIME_ID 本进程消耗的 CPU 时间 不会 不适用 性能剖析
CLOCK_THREAD_CPUTIME_ID 本线程消耗的 CPU 时间 不会 不适用 单线程剖析

两条不会错的规则：

  • 要「那一刻是几点」用 CLOCK_REALTIME
  • 要「过了多久」用 CLOCK_MONOTONIC

CLOCK_REALTIME 能被 settimeofday、NTP 校时、手动改时间直接往前或往后拨。用它算耗时，赶上一次向后校时，会得出负数间隔，或者一个离谱的大数。线上偶发的「耗时 -3 秒」日志，基本都是这个来源。

CLOCK_MONOTONIC 没有「1970 起算」的含义，绝对不能拿去 localtime 转日历。它只适合相减。

秒级和微秒级的睡眠，素材里的两个接口：

c
#include <unistd.h>

unsigned int sleep(unsigned int seconds);   /* 使程序睡眠 seconds 秒 */
int usleep(useconds_t usec);                /* 使程序睡眠 usec 微秒 */

sleep 被信号打断会提前返回，返回剩余的秒数，返回 0 表示睡满；usleep 失败返回 -1 并置 errno。usleep 在 POSIX.1-2008 里已标为废弃，新代码用 nanosleep，被打断时 rem 带回剩余时间，接着睡它就行。

十二、时间比较与间隔计算 #

比较两个 time_t 大小，直接比，不用转任何结构体：

c
if (a < b) {
    /* a 更早 */
}
double seconds = difftime(b, a);   /* 返回 double，正数表示 b 在后 */

difftime 是标准函数，返回 double，理由在溢出：两个 time_t 相减的结果有超出 time_t 本身范围的风险，走浮点更稳。

间隔计算按用途分三档：

c
#include <time.h>
#include <sys/time.h>

time_t t0 = time(NULL);            /* 秒级，够用在日志、粗粒度统计 */

struct timeval v0, v1;             /* 微秒级 */
gettimeofday(&v0, NULL);

struct timespec s0, s1;            /* 纳秒级，算性能用这个 */
clock_gettime(CLOCK_MONOTONIC, &s0);

秒级间隔不要用「天数乘 86400」还原。一天是不是 86400 秒要看当天有没有夏令时切换，切换日只有 82800 秒或 90000 秒。要算「隔了几天」这种日历差，把两端都转成 struct tm，比 tm_yday 和 tm_year，别拿秒数除。

十三、2038 问题 #

time_t 是 32 位有符号整数时，能表示的最大秒数是 2147483647，对应 2038-01-19 03:14:07 UTC。再过一秒就溢出，符号位翻成 1，时间瞬间跳到 1901 年。

按北京时间算，那一刻是 2038-01-19 11:14:07。

三种平台三种状态：

平台 sizeof(time_t) 状态
64 位 Linux（LP64） 8 已经解决，能表示到约 2922 亿年
32 位 Linux（i386、ARM32） 4 有风险，取决于内核和 libc
32 位系统 + 64 位 time_t 4 / 8 部分发行版已切到 64 位 time_t

32 位系统的应对路线有两条：把 time_t 整体换成 64 位（需要内核、libc、全部依赖一起换，牵扯 ABI），或者继续用 32 位 time_t 并回避 2038 之后的时间。前一条是主流做法，代价是全栈重新编译。

time_t 换成 64 位后有三个连带变化，写代码时要知道：

  • printf 的 %d 打 time_t 会截断，必须用 (long long) 配 %lld 或 PRId64
  • 二进制结构体里存 time_t 的格式（网络协议、文件头、共享内存）宽度变了，跨版本读写对不上
  • 用 int 中转 time_t 的地方全部成为隐患，编译器会警告，别把它静音掉

2038 问题不只影响 time_t 本身。文件系统的时间戳、归档格式、数据库的 INT 时间列，只要底层是 32 位秒计数，就在同一条时间线上。排查老系统时把它们列进同一张清单。

十四、命令行的日期工具 #

日常验证换算，date 一个工具够用。

bash
date                              # 当前本地时间
date -u                           # 当前 UTC
date +%s                          # 当前时间戳
date -d @1714537805               # 时间戳转可读时间
date -d @1714537805 -u            # 按 UTC 显示
date -d '2024-05-01 12:00:00' +%s # 可读时间转时间戳

跨时区看一眼：

bash
TZ=Asia/Shanghai date
TZ=America/New_York date
TZ=UTC date -d @0

时间运算，-d 支持相对描述：

bash
date -d '+30 days' +%F            # 30 天后
date -d '-1 hour' +%T             # 一小时前
date -d 'next monday' +%F         # 下周一

-d @时间戳 里的 @ 不能省，省了会被当成普通字符串解析。macOS 的 date 是 BSD 版本，不认 -d，要用 -r：

bash
date -r 1714537805                # macOS / BSD 把时间戳转可读时间

程序里要解析时间，别去拼 date 命令，直接调 strptime + mktime。命令行工具受 locale、时区、版本差异三重影响，不适合当接口。

十五、易错点速查 #

现象 原因 改法
年份打出来是 124 tm_year 存的是减 1900 的值 打印时 + 1900
月份整体偏一个月 tm_mon 从 0 开始 打印时 + 1，赋值时 - 1
星期算错一天 tm_wday 里周日是 0 别手算，让 mktime 填
时间在多线程里乱跳 localtime/gmtime 返回静态缓冲区 换 localtime_r/gmtime_r
上游调一次下游全变 同上，静态缓冲区被覆盖 立刻 struct tm save = *p;
耗时算出负数 用了 CLOCK_REALTIME，中途被校时 换 CLOCK_MONOTONIC
微秒差为负 两次 gettimeofday 跨了整秒 秒差与微秒差一起算
改了 TZ 不生效 没调 tzset() 改完立刻 tzset()
解析「成功」但值是错的 strptime 只检查了返回值非 NULL 再判断 *end == '\0'
strptime 编译报隐式声明 缺 _XOPEN_SOURCE 加 #define _XOPEN_SOURCE
结构体里字段是垃圾值 struct tm 没清零 用前 memset(&t, 0, sizeof t)
编译报 clock_gettime 未定义 glibc < 2.17 没链接 librt 编译加 -lrt
%z 输出空 传的是 gmtime 的结果 改用 localtime
闰秒让秒数对不上 time_t 不含闰秒 秒级对齐，别依赖闰秒
2038 后跳回 1901 32 位 time_t 溢出 换 64 位平台或 64 位 time_t

几条收尾的规矩：

  • 存储一律 time_t 或 UTC 字符串，展示时才转本地时间
  • 换算链条永远走「time_t ↔ struct tm」，不要中间塞字符串
  • 亚秒只在测量时用，别混进日历运算
  • struct tm 里的 tm_isdst，手工构造时一律给 -1

把 time_t 和 struct tm 的分工记住，再记住 localtime 带时区、gmtime 不带，剩下都是查表。
