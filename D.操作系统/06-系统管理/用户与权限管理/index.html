一、Linux 的多用户模型 #

Linux 从设计上就是多用户系统。同一台机器上，root、一堆服务账户、几个真人账户同时存在，各自跑各自的进程，各自能碰的文件范围不同。内核看一个进程，看的不是名字，是这组数字：

bash
vagrant@saltmaster:~$ id
uid=1000(vagrant) gid=1000(vagrant) groups=1000(vagrant),4(adm),27(sudo),110(lxd),997(sambashare)

每个进程带着 uid、gid 和一组附加组。打开文件时，内核拿这套数字去和文件的属主、属组比对，决定能不能读、能不能写、能不能执行。这套判断叫 DAC，自主访问控制。

判断分三个角色，顺序固定，命中一个就停：

  • 所有者（owner）：文件的 uid 和进程的 euid 相同。
  • 属组（group）：文件的 gid 命中进程的 egid 或任一附加组。
  • 其他人（other）：前两条都不成立。

root 是例外。uid 0 打开文件时直接跳过 DAC 检查（拆成 capabilities 之后是 CAP_DAC_OVERRIDE）。所以「root 什么都能干」不是权限位给的，是内核判身份时留的通行证。

bash
vagrant@saltmaster:~$ ls -l
total 256
-rw-r--r-- 1 root    root    256191 Nov 13 06:26 bootstrap-salt.sh
-rw-rw-r-- 1 vagrant vagrant      0 Nov 26 08:44 file_a
-rw-r--r-- 1 root    root       100 Nov 20 06:30 nettools.sls

七列：权限位、硬链接数、所有者、属组、字节数、最后修改时间、文件名。第二列那个 1 是硬链接计数，不是数字权限，新手常读错。file_a 属于 vagrant:vagrant，多一个组写位，同组的人也能改；bootstrap-salt.sh 属于 root:root，vagrant 改不动，因为 euid 是 1000 不是 0。

多用户模型解决三件事：隔离靠家目录 0700；共享靠建一个组再给目录组写权限；追溯靠进程和日志里记的 uid。

二、用户、组与 UID/GID #

这一节是全篇的地基，一句话：UID 是内核认的身份，用户名只是给人看的标签。

文件里根本不存用户名。inode 里只有一串数字。ls -l 之所以显示 vagrant，是因为它拿着这个数字去用户数据库查了一遍再打印。查的入口不是硬编码读 /etc/passwd，而是走 NSS，本地文件只是其中一个来源，LDAP、SSSD、systemd-homed 都挂在这条链上。

bash
vagrant@saltmaster:~$ ls -l /srv/data
total 8
-rw-r--r-- 1 1002 1002  0 Nov 26 09:10 orphan.txt
-rw-r--r-- 1 root root 4096 Nov 26 09:12 report.pdf

看到 1002 1002 而不是名字，结论只有一条：这套用户数据库里没有该 UID 的条目。要么是用户被 userdel 删了、文件还留着；要么是从另一台机器 rsync 过来的，对方 UID 在这台机器上不存在；要么是 NSS 少配了一个后端。反过来说，只要 /etc/passwd 里有一行 1002，同一个文件立刻显示成那个名字——名字本来就不存在文件里。

UID 的分配区间有约定：

范围 用途 说明
0 root 只有一个，出现第二个就是后门
1–999 系统账户 服务专用，CentOS 6 及更早是 1–499
1000–59999 普通用户 Ubuntu 与 CentOS 7+ 都从这里分配
65534 nobody / nogroup 「查不到对应账户」时的兜底

系统账户和普通账户的差别在用途不在权限大小：系统账户给守护进程用，nologin 收尾，密码字段锁死成 * 或 !。

进程身上有三个 uid：

名字 含义 谁改它
ruid 真实 uid，谁启动了进程 登录时确定，基本不变
euid 生效 uid，内核拿它做权限判断 su、sudo、SUID 程序
suid 保存的 uid，用来切回去 程序自己调 seteuid

su 和 sudo 改的就是 euid。普通用户跑 sudo cat /etc/shadow 时，ruid 还是 1000，euid 变成 0，内核按 0 放行。

从数字反查名字用 getent，它走 NSS，本地文件和 LDAP 一起查；grep /etc/passwd 只看本地，加域机器上会漏。getent passwd 1000 能拿到整行，getent passwd 1002 什么都不打印，返回码 2。

三、/etc/passwd 的七个字段 #

一行一个账户，冒号分隔，七个字段：

bash
vagrant@saltmaster:~$ cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
vagrant:x:1000:1000:Vagrant:/home/vagrant:/bin/bash
# 字段 例子 含义
1 用户名 root 登录名，区分大小写，上限 32 字符
2 口令占位 x 有 shadow 时固定是 x；空字段表示无密码
3 UID 0 内核认的数字身份
4 GID 0 初始组的 GID
5 注释 root GECOS 字段，全名、房间、电话，逗号分隔
6 主目录 /root 登录后的当前目录
7 登录 shell /bin/bash 登录后启动的程序

第 2 字段是历史残留。早年哈希直接写在这里，而 /etc/passwd 必须对所有人可读（登录要查），等于公开哈希。哈希搬到 /etc/shadow 后，这里只留 x 占位。

第 5 字段叫 GECOS，沿用早期通用电气操作系统的名字，现在就是放全名和备注，chfn 改它，可以有空格或留空。

第 7 字段决定登录后你看到什么：

text
/usr/sbin/nologin   打印 /etc/nologin.txt 后退出，返回码 1
/bin/false          静默失败，返回码 1
（空）              退回 /bin/sh，等于给人一个 shell

服务账户用 nologin 是标准做法：它要一个身份跑进程，不需要人登进去，shell 关掉就少一条入侵路径。

改这个文件不要手写，用 vipw：

bash
root@saltmaster:~# vipw
root@saltmaster:~# vipw -s

vipw 会加锁、做语法检查、写坏时拒绝落盘，-s 是改 /etc/shadow 的入口。直接 vi /etc/passwd 手滑删掉一个冒号，整个系统的登录就废了。

四、/etc/shadow 与密码存储 #

密码哈希在 /etc/shadow，权限 0640，属主 root，属组 shadow 或 root。普通用户读不到，这就是它存在的理由。

bash
vagrant@saltmaster:~$ sudo head -n 3 /etc/shadow
root:!:17466:0:99999:7:::
daemon:*:17379:0:99999:7:::

九个字段：

# 字段 上面的值 含义
1 用户名 root 与 /etc/passwd 对应
2 加密口令 ! !、*、!! 都是锁定；空表示无密码
3 最后修改 17466 距 1970-01-01 的天数，0 表示下次登录强制改
4 最小间隔 0 两次改密之间至少隔多少天
5 最大间隔 99999 多少天后过期，99999 等于永不过期
6 警告天数 7 过期前提前几天提醒
7 宽限天数 空 过期后还能登录几天，空表示过期即锁死
8 失效日期 空 账户作废的日期，同样是距 1970 的天数
9 保留 空 未使用，历史遗留

第 3 和第 8 字段是「天数」不是时间戳，17466 对应 2017-10-31，date -d @$((17466*86400)) +%F 就是它。

第 2 字段的前缀决定哈希算法：

前缀 算法 备注
$1$ MD5 老系统，能撞，别用
$5$ SHA-256
$6$ SHA-512 主流发行版用了很多年
$y$ yescrypt Debian 12、Ubuntu 22.04 起的默认
$2b$ bcrypt BSD 系常用

! 和 * 效果一样：这个账户不能用密码登录，但可以用 su、sudo、SSH 密钥登录（只要 shell 没关）。* 是永远匹配不上的占位串，! 是在原哈希前加锁标记。

bash
root@saltmaster:~# passwd tom
New password:
root@saltmaster:~# passwd -S tom
tom P 11/17/2026 0 99999 7 -1

普通用户改自己的密码必须输旧密码，root 改任何人的密码都不需要。passwd -S 第二列的 P 是密码可用、L 锁定、NP 无密码，后面依次是最后修改日期、最小/最大间隔、警告天数、宽限期。

chage 管的是同一批字段，视角是「到期规则」：

bash
root@saltmaster:~# chage -l tom
Last password change  : Nov 17, 2026
Account expires       : never
Minimum/Maximum days between password change : 0 / 99999
root@saltmaster:~# chage -M 90 -W 7 -I 14 tom

-M 最长 90 天、-W 提前 7 天提醒、-I 过期后 14 天宽限。-E 是账户失效日期，写 YYYY-MM-DD，chage 自动换算成天数。

锁账户有几种动作，别混：

命令 效果 能恢复吗
passwd -l tom 在哈希前加 ! passwd -u 解
usermod -L tom 同上 usermod -U 解
usermod -e 1 tom 失效日期设成过去 改回未来日期
chage -E 0 tom 账户立即失效 同上

锁只挡密码登录，失效挡所有登录方式。彻底停用一个账户，两个都上。

五、/etc/group 与附加组 #

组的存在理由是批量授权：给组设一次权限等于给组里所有人设，加人减人只动一个文件。

bash
vagrant@saltmaster:~$ cat /etc/group
root:x:0:
sudo:x:27:vagrant
adm:x:4:syslog,vagrant
# 字段 例子 含义
1 组名 sudo
2 组口令占位 x 有 gshadow 时是 x
3 GID 27 内核认的组身份
4 成员列表 vagrant 逗号分隔，不带空格

/etc/gshadow 存组口令和组管理员，四个字段：组名、加密后的组口令、组管理员列表、成员列表。第二个字段是 ! 或 * 时，这个组没设组口令也没组管理员，普通成员不能用 newgrp 免密切进去。

新手最容易卡的地方：/etc/passwd 里写着 tom:x:1001:1001:...，但 /etc/group 里找不到 tom 这个成员，看着像数据不一致。

不是。第 4 字段那个 GID 叫初始组（primary group），登录时内核直接把它设成进程的 egid，不走成员列表；成员列表只登记附加组（supplementary group）。

初始组 附加组
记在哪 /etc/passwd 第 4 字段 /etc/group 第 4 字段
数量 有且只有一个 任意多个
怎么进进程 登录时设成 egid initgroups 填进附加组集合
新建文件归属 无 SGID 时文件属组就是它 不影响文件归属

一个人登录后的权限是初始组加所有附加组的并集，文件权限判断时命中任意一个组就算命中「属组」那一档。

bash
vagrant@saltmaster:~$ groups
vagrant adm cdrom sudo dip plugdev lxd lpadmin sambashare
vagrant@saltmaster:~$ newgrp sudo
vagrant@saltmaster:~$ touch test_b
vagrant@saltmaster:~$ ll test_*
-rw-rw-r-- 1 vagrant adm  0 Nov 26 15:46 test_a
-rw-rw-r-- 1 vagrant sudo 0 Nov 26 15:47 test_b

第一个组是 egid，新建文件默认归到它。test_a 在原 shell 里建，属组是当时的 egid adm；test_b 在 newgrp 之后建，属组变成 sudo。文件没变，是进程的 egid 变了。newgrp 起一个新 shell，exit 退回原来的组；只跑一条命令用 sg，不开 shell。

组权限校验永远基于进程的生效组 ID，不是你脑子里记得的身份。

六、创建用户：useradd 与 adduser #

useradd 要写 /etc/passwd、/etc/shadow、/etc/group、/etc/gshadow，四个文件都要加锁，普通用户碰不了：

bash
vagrant@saltmaster:/home$ useradd tom
useradd: Permission denied.
useradd: cannot lock /etc/passwd; try again later.
vagrant@saltmaster:/home$ sudo useradd -m -s /bin/bash tom

报错说的就是锁文件：useradd 写之前要建 /etc/passwd.lock，权限不够直接退出。建完验证三处记录：

bash
root@saltmaster:/home# grep tom /etc/passwd
tom:x:1001:1001::/home/tom:/bin/bash
root@saltmaster:/home# grep tom /etc/shadow
tom:!:17496:0:99999:7:::
root@saltmaster:/home# grep tom /etc/group
tom:x:1001:

三行的 1001 是同一个号：useradd 从 UID 区间挑了个没被占用的号，同时建了同名组并把 GID 设成同一个数，这叫用户私有组（UPG），RHEL 和 Ubuntu 的默认行为。/etc/shadow 里那个 ! 说明还没设密码，此时密码登录一律失败，密钥也进不去。

常用选项：

选项 作用
-m 建家目录，从 /etc/skel 拷骨架文件
-M 不建家目录
-d /path 指定家目录路径，配合 -m 才真正创建
-s /bin/bash 登录 shell
-u 1500 指定 UID，被占用会报错
-g dev 初始组，写组名或 GID
-G dev,ops 附加组，逗号分隔，无空格
-c "Tom Lee" 注释（GECOS）字段
-e 2027-01-01 账户失效日期
-r 建系统账户，UID 取自系统区间
-D 查看或修改默认值

不带 -m 时 RHEL 家族的 useradd 不建家目录，登录会停在 /；Debian 家族的 adduser 默认建。默认值有两个来源，分工明确：

bash
root@saltmaster:~# grep -E '^(CREATE_HOME|UMASK|UID_MIN|UID_MAX)' /etc/login.defs
CREATE_HOME     yes
UMASK           022
UID_MIN         1000
root@saltmaster:~# useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
SHELL=/bin/sh
SKEL=/etc/skel

/etc/login.defs 管区间和密码策略（UID 范围、umask、到期规则），/etc/default/useradd 管策略（家目录位置、shell、邮件池）。改默认：useradd -D -s /bin/bash -m。

adduser 是另一个东西。Debian/Ubuntu 上它是个 Perl 脚本，交互式：

bash
root@saltmaster:~# adduser tom
Adding new group `tom' (1001) ...
Creating home directory `/home/tom' ...
New password:
root@saltmaster:~# adduser tom sudo

一步到位：建组、建家目录、拷骨架、设密码、填 GECOS，最后一条把 tom 加进 sudo 组。RHEL 家族上 adduser 只是 useradd 的符号链接，行为完全不同，脚本里写死 adduser 换到 CentOS 上会建出没有家目录的账户。

七、修改用户：usermod #

建完账户后的调整都归 usermod，它改的是那四个文件，不动家目录里的东西。

选项 作用 陷阱
-l newname 改用户名 家目录名不跟着变
-u 1500 改 UID 文件属主不跟着变
-g dev 改初始组 组必须已存在
-aG dev,ops 追加附加组 漏掉 -a 就是覆盖
-d /srv/tom -m 改家目录并搬文件 漏 -m 只改记录不动文件
-s /bin/zsh 改 shell shell 要在 /etc/shells 里
-L / -U 锁 / 解锁密码 只动密码字段
-e 2027-01-01 账户失效日期 -e "" 清空

最危险的是 -G。usermod -G docker tom 跑完看起来成功，实际把 tom 原有的附加组全清了，只剩 docker。正确写法是 usermod -aG docker tom，-a 是 append，只能和 -G 一起用。

bash
root@saltmaster:~# usermod -aG docker tom
root@saltmaster:~# id tom
uid=1001(tom) gid=1001(tom) groups=1001(tom),999(docker)

这条规则值得刻在脑子里，因为覆盖附加组会让用户突然失去 sudo 权限。

组生效需要重新登录。已登录会话里的附加组集合是登录那一刻 initgroups 填进去的快照，之后改 /etc/group 不会自动刷新，新开的终端才拿到新组。

改用户名：

bash
root@saltmaster:~# usermod -l tommy tom
root@saltmaster:~# ls -ld /home/tom
drwxr-xr-x 2 tom tom 4096 Nov 17 09:20 /home/tom

/etc/passwd 第 1 字段变成 tommy，家目录还是 /home/tom。要连带搬走用 usermod -l tommy -d /home/tommy -m tom。

改 UID 要补一步：

bash
root@saltmaster:~# usermod -u 1500 tom
root@saltmaster:~# find / -uid 1001 -not -path '/proc/*' -exec chown -h 1500 {} +

usermod -u 只改记录，文件 inode 里那个数字还是 1001，得靠 find 扫一遍改回来。漏掉这一步，用户登录后发现自己所有文件都成了别人的。

普通用户自己不用 root 也能改一部分属性：chsh -s /bin/zsh 改登录 shell，chfn 改 GECOS 备注，finger tom 查某个用户的公开信息。

八、删除用户：userdel #

userdel 干两件事：删 /etc/passwd、/etc/shadow、/etc/group 里的记录；加 -r 再删家目录和邮件池。

bash
root@saltmaster:~# userdel tom
root@saltmaster:~# ls -ld /home/tom
drwxr-xr-x 2 1001 1001 4096 Nov 17 09:20 /home/tom

不带 -r，家目录留着，属主变成数字 1001——记录没了，ls 查不到名字。这就是第二节那个现象最常见的成因。-r 也只删家目录和邮件池 /var/mail/tom，散在 /tmp、/srv、/opt 的文件一律不动，继续挂着不存在的 UID。

删除之前先做三件事：pgrep -u tom 看有没有活进程，find / -uid 1001 -not -path '/proc/*' 2>/dev/null 清点散落文件，crontab -u tom -l 看有没有定时任务。有进程在跑，userdel 会报 user tom is currently used by process 2345，杀掉再删，或者先 usermod -L 锁住。

如果这个 UID 之后被新账户复用，旧文件直接归新账户所有。这是真实的提权路径：删号时不清文件，新号拿到同一个 UID，白捡一堆文件权限。

留档比删号更稳的做法是先停用：usermod -L -e 1 tom。密码锁死、账户失效，登录全断，家目录和审计记录都在。等人走了、手续办完再 userdel -r。

九、组的管理 #

组的管理命令和用户一一对应：

用户侧 组侧 作用
useradd groupadd 建
usermod groupmod 改
userdel groupdel 删
passwd gpasswd 管口令和成员 
bash
root@saltmaster:~# groupadd dev
root@saltmaster:~# groupadd -g 2000 ops
root@saltmaster:~# groupadd -r sysapp
root@saltmaster:~# groupmod -n developers dev
root@saltmaster:~# groupmod -g 2001 developers
root@saltmaster:~# groupdel dev

-g 指定 GID，-r 建系统组。改 GID 和改 UID 一样，/etc/group 变了但文件的属组数字没变，要 find / -gid 2000 -exec chgrp 2001 {} + 补。组还是某个用户的初始组时，groupdel 拒绝执行：

text
groupdel: cannot remove the primary group of user 'tom'

先把那个用户的初始组换掉，再删组。

gpasswd 是组侧的 passwd：

bash
root@saltmaster:~# gpasswd -a tom dev
root@saltmaster:~# gpasswd -d tom dev
root@saltmaster:~# gpasswd -A tom dev

-a 加成员，-d 删成员，-A 设组管理员（组管理员能自己加人，不用 root）。这三条比 usermod -aG 更精准——gpasswd -a 只动一个组的成员列表，不碰用户的其他组。批量加人放循环里，groupadd -f dev 让组已存在时不报错，适合幂等脚本。

查组成员名单有两条路，结论会不一样：

bash
root@saltmaster:~# getent group dev
dev:x:2001:tom,jerry
root@saltmaster:~# groups tom
tom : tom dev

getent group 只读 /etc/group 的成员列表；groups tom 还会把「tom 的初始组是 dev」算进去。如果 tom 的初始组就是 dev，成员列表里根本不会有他，但 groups 会显示。别拿 getent group 的输出当完整名单。

十、切换用户：su 与 sudo #

两个命令都能换身份，思路不同：su 换整个会话，sudo 借一条命令。

bash
vagrant@saltmaster:~$ su root
vagrant@saltmaster:~$ su - root
vagrant@saltmaster:~$ su - root -c 'systemctl restart nginx'

不带横杠只换 uid 和组，环境变量（PATH、HOME、SHELL）全是原来那个用户的。HOME 还指着 /home/vagrant，PATH 里塞着原来的私有目录，su 完跑命令各种找不到，就是这个原因。带横杠等于完整登录：重设 HOME、SHELL、USER、LOGNAME，PATH 按目标用户重算，cd 到目标用户家目录，再执行登录脚本，等价于 su -l。切 root 一律用 su -。

su 需要目标用户的密码。要 root 密码这件事本身就是问题：一堆人都得有 root 密码才能干各自的活，root 密码一泄露全军覆没。

sudo 反过来，输的是自己的密码，权限由 /etc/sudoers 的规则决定，每条执行都记日志。

参数 作用
sudo -i 起一个 root 的登录 shell，等价 su -
sudo -s 起一个 root shell，保留当前环境
sudo -u www-data cmd 以指定用户身份执行
sudo -l 列出当前用户被授权的命令
sudo -k 清掉缓存的凭证

普通用户要连做几条 root 操作，sudo -s 进 root shell，做完 exit：

bash
vagrant@saltmaster:/home$ sudo -s
root@saltmaster:/home# useradd tom

sudo -i 和 sudo -s 的区别跟 su - 和 su 一样：-i 走登录流程，-s 保留环境变量。凭证默认缓存 15 分钟，跑完敏感操作想立刻失效用 sudo -k。

sudo -l 是排查权限问题的第一个动作，输出直接告出你能跑什么、以谁的身份跑：

bash
vagrant@saltmaster:~$ sudo -l
Matching Defaults entries for vagrant on saltmaster:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

User vagrant may run the following commands on saltmaster:
    (ALL : ALL) ALL

(ALL : ALL) 是「所有用户 : 所有组」。

su sudo
验证谁 目标用户的密码 自己的密码
授权在哪 无，知道密码就行 /etc/sudoers
粒度 全有或全无 可以只放行一条命令
审计 只记「谁 su 了」 每条命令都记
环境 默认继承，- 才重置 env_reset 默认清理

习惯：需要完整 root 会话用 sudo -i，需要一条命令用 sudo，只有在自己机器上、密码只有自己知道时才用 su -。

十一、sudoers 配置 #

/etc/sudoers 权限必须是 0440、属主 root:root。sudo 启动时检查这个权限，不对就直接拒绝：

text
sudo: /etc/sudoers is world writable
sudo: no valid sudoers sources found, quitting

所以永远不要直接 vi /etc/sudoers，用 visudo。它做三件事：加锁防止两人同时改；存盘前做语法检查，写错就提示并让你选择放弃；写临时文件再原子替换，中途崩溃不会留下半个文件。不动主文件、往 sudoers.d 里丢片段更好，主文件末尾那行 @includedir /etc/sudoers.d 会把目录里的文件全读进来，片段权限同样要 0440：

bash
root@saltmaster:~# visudo -f /etc/sudoers.d/devops

规则语法是四个字段：用户 主机=(可切换的身份) 可执行的命令。最宽的那条长这样：

text
root ALL=(ALL) ALL

root 是用户；第一个 ALL 是主机（多机共享一份 sudoers 时才用得上）；(ALL) 是能以哪些用户和组的身份执行；最后一个 ALL 是命令白名单。

组授权加 %：

text
%sudo   ALL=(ALL:ALL) ALL
%devops ALL=(ALL) /bin/systemctl restart nginx, /bin/systemctl status nginx

%sudo 是「sudo 组的所有成员」。Debian/Ubuntu 装系统时把第一个用户扔进 sudo 组，靠的就是这一行。

免密用 NOPASSWD:，冒号在它后面，不是等号：

text
%devops ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

这一条只对列出的命令免密。写成 NOPASSWD: ALL 等于无密码拿 root。更细的写法限定可切换的身份：

text
tom   ALL=(root) /usr/bin/apt update, /usr/bin/apt upgrade
jerry ALL=(www-data) /usr/bin/php /var/www/app/artisan

命令要写绝对路径。tom ALL=(root) /usr/bin/vi 看着只是给编辑器，实际 vi 里一个 :!sh 就是 root shell。同理 less、find、awk、tar、man 都能逃逸，给编辑器等于给全部权限。

sudoers 从上到下匹配、最后一个命中的赢，NOPASSWD 和 PASSWD 的覆盖关系还跟位置有关，容易踩坑。简单起法：同一个用户只在一个片段文件里写规则，改完必须检查语法：

bash
root@saltmaster:~# visudo -c
/etc/sudoers: parsed OK
/etc/sudoers.d/devops: parsed OK

真锁死了怎么办：开两个 root 会话，一个改一个试；或者重启进单用户 / rescue 模式改回来。这也是 visudo 存在的原因。

日志在 /var/log/auth.log（Debian）或 /var/log/secure（RHEL），每条都记了谁、在哪个终端、在哪个目录、以谁的身份、跑了什么：

bash
root@saltmaster:~# grep sudo /var/log/auth.log | tail -2
Nov 17 10:21:04 saltmaster sudo:  vagrant : TTY=pts/0 ; PWD=/home/vagrant ; USER=root ; COMMAND=/bin/systemctl restart nginx

十二、文件权限的九个位 #

ls -l 第一列那十个字符，第一个是文件类型，后九个是权限：

text
-rwxr-xr--  1 tom dev 4096 Nov 17 09:30 deploy.sh
│└┬┘└┬┘└┬┘
│ │  │  └── 其他人：r--
│ │  └───── 属组：  r-x
│ └──────── 所有者：rwx
└────────── 类型：- 普通文件

九个位切成三组，每组三位，顺序固定 r、w、x：

位置 角色 谁匹配
1–3 所有者 文件 uid == 进程 euid
4–6 属组 文件 gid 命中进程 egid 或附加组
7–9 其他人 前面都不匹配

三位的含义随对象变化，这是最容易搞错的一处：

位 对普通文件 对目录
r 读内容（cat） 列目录里的名字（ls）
w 改内容（echo >） 在目录里增删改名文件
x 当程序执行 进入目录（cd）、访问里面的文件

目录的 x 最容易被低估。r 只给你「看见名字」，x 才给你「走进去」：

bash
vagrant@saltmaster:~$ ls -ld /srv/inbox
drw-r--r-- 2 root root 4096 Nov 17 09:40 /srv/inbox
vagrant@saltmaster:~$ ls /srv/inbox
a.txt  b.txt
vagrant@saltmaster:~$ cat /srv/inbox/a.txt
cat: /srv/inbox/a.txt: Permission denied

只有 r 没有 x，ls 能列名字但读不了内容；只有 x 没有 r，ls 报错，但知道完整路径时能直接访问里面的文件。两种状态在实际环境里都见得到。

删除文件看的是父目录的 w，不是文件的 w。把目录设成 0555，里面文件即使是 0777 也删不掉。

文件类型位：- 普通文件、d 目录、l 符号链接、c 字符设备、b 块设备、p 命名管道、s 套接字。符号链接的权限位永远是 rwxrwxrwx，没有意义——内核检查的是它指向的目标，chmod 一个链接改的也是目标文件。

判断权限不能只看位，还要看路径。namei -l 把每一层目录的权限全列出来：

bash
vagrant@saltmaster:~$ namei -l /srv/data/report.pdf
f: /srv/data/report.pdf
drwxr-xr-x root root /
drwxr-xr-x root root srv
drwxrwx--- dev  dev  data
-rw-r----- dev  dev  report.pdf

文件本身是 640，但 data 目录对 vagrant 是 ---，cd 都进不去。路径上任何一层缺 x，后面的全都访问不到。

十三、chmod 的两种写法 #

符号模式由三段拼成：[角色][操作][权限]。角色 u 所有者、g 属组、o 其他人、a 全部（等价 ugo）；操作 + 加、- 减、= 直接赋值；权限 r、w、x，特殊位用 s、t。

bash
vagrant@saltmaster:~$ chmod u+x deploy.sh
vagrant@saltmaster:~$ chmod go-w deploy.sh
vagrant@saltmaster:~$ chmod a+r deploy.sh
vagrant@saltmaster:~$ chmod u=rwx,go=rx deploy.sh

+ 和 - 是在现有基础上加减，= 是把这一组直接覆盖：u=rw 会抹掉 u 位的 x，u-x 只去 x。改一两个位用符号模式快，一次性设定用数字模式清楚。

数字模式把三位当八进制数，r=4、w=2、x=1、-=0，每组三位相加。单个数对应：7=rwx、6=rw-、5=r-x、4=r--、3=-wx、2=-w-、1=--x、0=---。

权限 含义 典型场景
644 rw-r--r-- 普通文件默认值
600 rw------- 私钥、~/.ssh/id_rsa
755 rwxr-xr-x 可执行文件、目录默认值
700 rwx------ 家目录、私有目录
640 rw-r----- 属组可读的配置
664 rw-rw-r-- 组内协作文件
775 rwxrwxr-x 组内协作目录
777 rwxrwxrwx 谁都能改，出事只是时间问题 
bash
vagrant@saltmaster:~$ chmod 755 deploy.sh
vagrant@saltmaster:~$ chmod 600 ~/.ssh/id_rsa
vagrant@saltmaster:~$ chmod -R 750 /srv/app

数字模式是三段一起覆盖，chmod 644 对目录执行会把目录的 x 全抹掉，那个目录立刻进不去。改目录之前先 ls -ld 看一眼。

SSH 私钥的 600 是硬要求，权限宽了 ssh 直接拒绝：

text
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for '/home/vagrant/.ssh/id_rsa' are too open.

-R 递归要谨慎，给整个目录树放开等于把里面的脚本、密钥、配置一起放开。确实要递归时文件和目录分开设：

bash
vagrant@saltmaster:~$ find /srv/app -type d -exec chmod 755 {} +
vagrant@saltmaster:~$ find /srv/app -type f -exec chmod 644 {} +

十四、chown 与 chgrp #

chmod 改权限位，chown 改属主和属组。四种写法：

bash
root@saltmaster:~# chown tom report.pdf
root@saltmaster:~# chown tom:dev report.pdf
root@saltmaster:~# chown :dev report.pdf
root@saltmaster:~# chown tom: report.pdf

依次是：只改属主；属主和属组一起改；只改属组（冒号前留空）；把属组改成属主的初始组（冒号后留空）。只改属组还能用 chgrp dev report.pdf，递归加 -R。

chown 只有 root 能用。普通用户想把文件送给别人，内核直接拒绝：

text
chown: changing ownership of 'report.pdf': Operation not permitted

理由是安全：能送文件就能把自己的文件挂到 root 名下，配合 SUID 就是提权。普通用户能改的只有属组，而且只能改成自己所属的那些组。

bash
root@saltmaster:~# chown -R tom:tom /home/tom
root@saltmaster:~# chown -h tom:tom link

-R 递归时的默认行为是 -P：遇到符号链接只改链接自身，不进目标；要进目标得显式加 -L。非递归时用 -h 改链接自身。把别人的家目录整个 chown -R 给错人，是把那个人的所有配置和密钥一起送出去，动手前 ls -ld 确认路径。

组共享目录的标准做法：

bash
root@saltmaster:~# chown -R www-data:dev /var/www/app
root@saltmaster:~# find /var/www/app -type d -exec chmod 2775 {} +
root@saltmaster:~# find /var/www/app -type f -exec chmod 664 {} +

2775 前面那个 2 是 SGID，下一节说。

十五、特殊权限位：SUID、SGID、sticky #

九个位之外还有三个位，占的是原本 x 的位置：

位 数值 文件上显示 目录上显示
SUID 4000 -rwsr-xr-x 无意义
SGID 2000 -rwxr-sr-x drwxr-sr-x
sticky 1000 无 drwxrwxrwt

小写 s 表示底下的 x 还在，大写 S 表示 x 被拿掉、只剩特殊位，S 基本意味着配错了。

SUID：以文件所有者的身份运行。 普通程序执行时 euid 是你的 uid，带 SUID 的程序执行时 euid 变成文件属主的 uid。

bash
vagrant@saltmaster:~$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 68208 Feb  6  2024 /usr/bin/passwd

/etc/shadow 是 640 root:shadow，vagrant 读写都进不去，但改自己密码时能写，因为 /usr/bin/passwd 带 SUID，跑起来 euid 是 0。程序内部再检查「你只能改自己的密码字段」，把权限收回到业务需要的那一格。

这就是 SUID 的全部意义：把一个高权限操作拆成「程序有权限」+「程序内部判断谁能用」。代价是 SUID 程序写错一行就是提权漏洞。

bash
root@saltmaster:~# find / -perm -4000 -type f 2>/dev/null
/usr/bin/passwd
/usr/bin/sudo

这份名单是审计重点。出现 find、vim、python、bash、cp、tar 这类能执行任意命令的程序，基本就是留了后门。设 SUID 用 chmod u+s 或 chmod 4755。脚本上设 SUID 无效——内核对脚本直接忽略这一位，这是防注入的设计，要用 SUID 必须编译成二进制。

SGID：目录里新建的文件继承这个组。 在文件上它是运行时 egid 变成文件属组，用得很少；在目录上才是主战场。

bash
root@saltmaster:~# mkdir /srv/shared
root@saltmaster:~# chgrp dev /srv/shared
root@saltmaster:~# chmod 2775 /srv/shared
root@saltmaster:~# ls -ld /srv/shared
drwxrwsr-x 2 root dev 4096 Nov 17 09:50 /srv/shared

没有 SGID 的共享目录是什么下场：tom 在里面建文件，属组是 tom；jerry 的附加组里有 dev，但文件属组不是 dev，只能靠 o 位，组协作直接废掉。加了 SGID，所有人建的文件都归 dev 组，配合 2775 让组内可写，协作才成立。子目录也会继承 SGID 位，整棵树保持一致的组归属。

chmod g+s 和 chmod 2775 等价，去掉用 chmod g-s 或 chmod 0775。2775 拆开是「SGID + rwxrwxr-x」，组共享目录的标准答案。

sticky：只能删自己的文件。 目录里所有人都有 w，但只能删除或改名自己拥有的文件。最典型的地方是 /tmp：

bash
vagrant@saltmaster:~$ ls -ld /tmp
drwxrwxrwt 20 root root 4096 Nov 17 10:02 /tmp

最后那个 t 就是 sticky，/tmp 是 1777，谁都能建文件，谁都删不了别人的文件。

没有 sticky 会怎样：/tmp 是全员可写目录，谁都有一条 rm 能删掉别人的临时文件、锁文件、socket。加上之后删除权限被限定到文件属主。

大写 T（drwxrwxrwT）表示 sticky 设了但 o 位没有 x，那个目录别人进不去，等于白设。看到 T 就说明配错了。

位 前缀 作用对象 效果 风险
SUID 4xxx 文件 以属主身份运行 属主是 root 时等于提权入口
SGID 2xxx 目录 新建文件继承目录的组 组归属错了会扩大可写范围
sticky 1xxx 目录 只能删自己的文件 无，公共可写目录该加

按位查找时，-perm -4000 前面的减号意思是「这三位全都要有」；写成 -perm 4000 是精确匹配，要求只有 4000 一个位、其他全空，几乎查不到东西。

bash
root@saltmaster:~# find /srv -perm -2000 -type d 2>/dev/null
root@saltmaster:~# find / -perm -1000 -type d 2>/dev/null

十六、umask：默认权限从哪来 #

新建文件的权限不是你指定的，是内核上限减掉 umask。上限固定：普通文件 666，目录 777（文件不给 x，新建的文本文件不该默认可执行）。然后 umask 从上限里减掉对应位。

bash
vagrant@saltmaster:~$ umask
0022

0022 四个数字，第一位是特殊位，后三位是权限位。022 表示屏蔽「属组写」和「其他人写」：

umask 文件结果 目录结果 说明
022 644 755 常见默认值，别人只读
002 664 775 组内协作，属组可写
027 640 750 属组只读、其他人无权限
077 600 700 私有，别人一点都看不到
000 666 777 完全不屏蔽，危险

算法记成「从 666/777 里减掉 umask 的位」不会错：666 - 022 = 644，777 - 022 = 755，666 - 002 = 664，777 - 077 = 700。

umask 是进程属性，不是文件属性，随 shell 走。每个登录会话从 /etc/login.defs 或 PAM 模块初始化：

bash
root@saltmaster:~# grep UMASK /etc/login.defs
UMASK           022
vagrant@saltmaster:~$ umask 077
vagrant@saltmaster:~$ touch secret.txt
vagrant@saltmaster:~$ ls -l secret.txt
-rw------- 1 vagrant vagrant 0 Nov 17 10:10 secret.txt

umask 077 之后这个 shell 里建的所有文件都是 600、目录 700，包括你不知道的那些操作。要永久改就写进 ~/.bashrc：echo 'umask 027' >> ~/.bashrc。

umask 只在创建时生效，改 umask 不会改已有文件，已有文件得靠 chmod。

十七、ACL：超越九个位 #

九个位只能表达「所有者 / 一个组 / 其他人」。真实需求经常不是这个形状：给 tom 一个人读权限而不给整个组；给 dev 组写权限同时给 qa 组只读。ACL 就是补这个的，它给单个文件挂一张「用户 → 权限」的表。

先确认文件系统支持，用 mount | grep acl 看挂载选项：

bash
vagrant@saltmaster:~$ mount | grep ' / '
/dev/sda1 on / type ext4 (rw,relatime,errors=remount-ro)
vagrant@saltmaster:~$ mount | grep acl

ext4、xfs、btrfs 默认都带 ACL。mount 输出里显式出现 acl，说明是老内核或特意开的；新内核里这个选项已内置，看不到也不代表不支持。

bash
vagrant@saltmaster:~$ getfacl report.pdf
user::rw-
user:tom:r--
group::r--
mask::r--
other::r--

user:: 是所有者那三位，group:: 是属组，other:: 是其他人，带名字的 user:tom: 是额外条目。getfacl 输出顶部还会打印文件名、属主、属组三行注释。

bash
root@saltmaster:~# setfacl -m u:tom:rw report.pdf
root@saltmaster:~# setfacl -m g:qa:r report.pdf
root@saltmaster:~# setfacl -m o::- report.pdf
root@saltmaster:~# setfacl -x u:tom report.pdf
root@saltmaster:~# setfacl -b report.pdf

-m 是 modify，格式 u:用户名:权限 或 g:组名:权限，权限写 rw、r、rx 或数字都行。-x 删一条，-b 清空所有额外条目，回到纯九位。

目录上递归加，还要加默认 ACL：

bash
root@saltmaster:~# setfacl -R -m u:tom:rx /srv/data
root@saltmaster:~# setfacl -R -d -m u:tom:rx /srv/data

-d 是 default，设的是「以后在这个目录里新建的东西自动带这条 ACL」，不加 -d 只影响现有文件。

挂了 ACL 的文件，ls -l 权限位后面多一个 +：

bash
vagrant@saltmaster:~$ ls -l report.pdf
-rw-r--r--+ 1 root root 1234 Nov 17 10:20 report.pdf

看到 + 就知道光看九位会读错，真权限得 getfacl。

mask:: 是 ACL 里的关键，它限制所有具名条目和属组能拿到的最大权限。setfacl 会自动重算 mask，所以偶尔出现「我给了 rw 实际只有 r」，原因是 mask 被别的操作压低了。手工修正用 setfacl -m m::rwx report.pdf。

备份和恢复：

bash
root@saltmaster:~# getfacl -R /srv/data > /root/data.acl
root@saltmaster:~# setfacl --restore=/root/data.acl

cp -a 和 rsync -A 会保留 ACL，普通 cp 和 tar 不带 --acls 就丢。

十八、易错点速查 #

现象 真实原因 处理
ls -l 显示数字不是用户名 /etc/passwd 里没有这个 UID getent passwd <uid> 确认，补账户或 chown 给现有人
用户加了组不生效 会话里的附加组是登录时快照 重新登录，或 newgrp
usermod -G 后用户丢了 sudo 漏了 -a，附加组被覆盖 usermod -aG sudo,dev tom 重来
su root 后命令找不到 没带 -，PATH 还是原用户的 su - root
userdel 后家目录属主是数字 没加 -r，或文件在别处 find / -uid <旧uid> -exec chown -R ...
chmod 644 后目录进不去 目录被抹掉了 x chmod 755 <dir>
目录有 r 没 x 能列名字不能读内容 chmod +x <dir>
文件 777 还是删不掉 删除看父目录的 w 改父目录权限
/tmp 里删不掉别人的文件 sticky 在起作用 正常行为，不是故障
出现大写 S 或 T s/t 设了但底下没有 x 补 x 或去掉特殊位
新建文件权限不是预期 umask 不对 umask 查看，改 ~/.bashrc
sudo 报 sudoers 语法错 手改了 /etc/sudoers visudo -c，以后用 visudo 改
sudo 说 is world writable /etc/sudoers 不是 0440 chmod 440 /etc/sudoers
useradd 后没有家目录 发行版默认不建 useradd -m，或改 /etc/login.defs 的 CREATE_HOME
脚本设 SUID 没效果 内核对脚本忽略 SUID 编译成二进制
给了 ACL 权限不生效 mask 压低了，或没设默认 ACL 看 getfacl 的 mask::，递归用 -d
chown 报 Operation not permitted 普通用户不能送文件 加 sudo，或改属组
groupdel 拒绝执行 组还是某人的初始组 先 usermod -g 换掉

三条最容易出事，单独说：

usermod -G 漏 -a——覆盖附加组，用户会瞬间失去 sudo，而你多半在远程 SSH 上操作。先 usermod -aG，别用 -G。

chmod -R 777——遇到权限问题就递归放开，等于把目录树交给所有人。定位问题用 namei -l 和 ls -ld 逐层看，哪一层缺权限补哪一层。

删用户不清文件导致 UID 复用——新人拿到同一个 UID，自动继承旧人的所有残留文件。删号必配 find / -uid <uid> 清点，或者干脆只锁不删。

排查顺序固定，记住这个就不用猜：

bash
vagrant@saltmaster:~$ id
vagrant@saltmaster:~$ ls -ld /path/to/dir
vagrant@saltmaster:~$ namei -l /path/to/file
vagrant@saltmaster:~$ getfacl /path/to/file
vagrant@saltmaster:~$ lsattr /path/to/file

第一步确认自己是谁、有哪些组；第二步看目标本身的位；第三步查路径上每一层；第四步排除 ACL；第五步排除 chattr +i 这种不可变属性——它会让 root 都改不动，报错却只说 Operation not permitted。
