一、Linux 命令行的基本形态 #

命令行是基于文本的交互界面。你敲一行，shell 读入、解析、找到程序、执行、把结果打到屏幕上，没有别的环节。

提示符片段 含义
lemonade 当前用户名
ubuntu 主机名
~ 当前工作目录，~ 是家目录 /home/lemonade
$ 普通用户；同一位置是 # 则为 root 
text
lemonade@ubuntu:~$        # 普通用户
root@ubuntu:/etc#         # root
按键 作用
Ctrl+Alt+T 打开终端
Ctrl+Shift++ / Ctrl+- 放大 / 缩小字号
Tab 补全命令名与路径，连按两次列候选
Ctrl+C / Ctrl+D 结束前台程序 / 送 EOF
Ctrl+L / Ctrl+R 清屏 / 反向搜历史
Ctrl+U / Ctrl+W 删到行首 / 删前一个词

一行命令由三段拼成，命令名 [选项] [参数]：

bash
ls        -l         /etc
# 命令名    选项      参数

命令分两类，这个区别直接决定你该查哪本帮助：

类型 例子 特点
shell 内置 cd、echo、pwd、alias、export、history shell 自己执行，PATH 里没有对应文件
外部程序 ls、grep、tar、ps 磁盘上的可执行文件，which 定位得到

echo 既是内置也存在于 /bin/echo，行为接近但不完全一致。查内置用 help，查外部程序用 man。

二、命令、选项与参数 #

短选项单横线，长选项双横线，三种写法等价：

bash
ls -l -h /var/log
ls -lh /var/log
ls --human-readable --format=long /var/log

短选项能合并，合并时只有最后一个能带值，所以 tar -cvf pkg.tar dir/ 里的 f 必须紧挨文件名。-h 不保证是 help：ls -h 是 human-readable。看选项说明走两条路：ls --help、man ls。

选项解析遇到 -- 停下，后面全当参数：

bash
rm -- -rf          # 删掉名字叫 -rf 的文件

引号决定 shell 解不解释：

写法 行为
'原样' 单引号内一切原样，$、反引号、\ 都不解释
"解释变量" 双引号内解释 $变量 与 $(命令)，空格仍被保护
\ 转义单个字符，多用于含空格的文件名 
bash
echo '$HOME'                  # 输出 $HOME
echo "$HOME"                  # 输出 /home/lemonade
echo "今天 $(date +%F)"        # 命令替换，$( ) 能嵌套，反引号不能
# 变量与 shell 环境
MOVIE="life is beautiful"   # 赋值，等号两边不能有空格
echo $MOVIE
export MOVIE                # 导出为环境变量，子进程可见
unset MOVIE                 # 删除变量
readonly PATH               # 设为只读；readonly 单敲列出所有只读变量
set | less                  # 全部 shell 变量
env                         # 只看环境变量
echo $SHELL                 # 当前 shell
cat /etc/shells             # 系统装了哪些 shell

等号两边多敲一个空格，shell 就把整行当命令名去找，回一句 command not found，这是第一坑。

别名、子 shell、换 shell：

bash
alias                       # 列出已有别名
alias la="ls -a"            # 临时生效，关终端即失效
source ~/.bashrc            # 在当前 shell 执行，改动立即生效
sh 脚本名                    # 另起 shell 执行，改不了当前 shell 的变量
/bin/bash                   # 进子 shell；exit 退回上一层
chsh 用户名                  # 永久更换默认 shell，输入 /bin/zsh 之类
PS1='hello; '               # 改提示符
# 历史记录
history | less     # 翻历史
history -c         # 清空当前会话
!39                # 重跑第 39 条
!c                 # 重跑最近一条以 c 开头的命令
!!                 # 重跑上一条

三、文件与目录操作 #

四种路径写法先分清：

写法 含义
/etc/fstab 绝对路径，从根开始
logs/app.log 相对路径，相对当前目录
./run.sh 当前目录下的 run.sh；PATH 里没有 .，所以 ./ 不能省
../、../../ 上一层、上两层

定位与切换：

bash
pwd              # 我在哪
cd /var/log      # 换目录
cd ~             # 回家目录；只敲 cd 效果相同
cd -             # 回上一次待的目录
cd ..            # 上一层
cd ~用户名        # 去别人的家目录
cd -P /opt/link  # 按物理路径解析符号链接，不是建目录

建目录要建多级得加 -p，mkdir -p a/b/c 缺哪层补哪层。

列目录，ls 的选项组合覆盖九成场景：

bash
ls -a          # 含隐藏文件，以 . 开头
ls -l          # 长格式：权限、属主、大小、时间
ls -lh         # 长格式且大小带单位
ls -alrtF      # 隐藏、长格式、递归、按时间倒序、类型后缀
ls -i          # 带 inode
ls -d */       # 只列目录本身
选项 作用
-a / -A 显示隐藏文件 / 显示但不含 . 与 ..
-l / -h 长格式 / 人类可读大小，配 -l
-R / -d 递归子目录 / 只看目录本身
-t / -r 按修改时间排序 / 反序
-F 目录加 /，可执行加 *，链接加 @
-i 显示 inode

创建与删除：

bash
mkdir mydir
mkdir -p one/two/three
touch myfile              # 建空文件；已存在则刷新时间戳
rmdir empty_dir           # 只删空目录
rm file                   # 删文件
rm -r dir                 # 递归删目录
rm -rf dir                # 递归删且不再问

rm -rf 后面那个空格是事故源：rm -rf /var/log 与 rm -rf / var/log 是两个世界。敲之前先 pwd，再默念一遍路径。

复制、移动、改名，源在前、目标在后：

bash
cp source dest               # 复制文件
cp -r src_dir dest_dir       # 复制目录
cp -a src dst                # 归档复制，保留权限、时间、链接
cp /dev/cdrom linux4.iso     # 字符界面下把光盘做成 iso
mv src dest                  # 移动
mv old.txt new.txt           # 改名
mv file /tmp/                # 移到目录，保留原名

同一文件系统内 mv 只改目录项，瞬间完成；跨文件系统退化成复制加删除。

链接：

bash
ln -s /opt/app/run.sh /usr/local/bin/run   # 软链接，可跨文件系统
ln target link                             # 硬链接，同一 inode，不能跨分区

软链接存路径字符串，目标删了就悬空；硬链接共享数据，删掉其中一个另一个照常用。ls -l 里 l 打头并带 -> 的是软链接。

文件类型与时间戳：

bash
file run.sh               # ASCII text、shell script 还是 ELF
file /bin/ls              # 判断可执行文件是 ARM 还是 x86 架构
stat /etc/passwd          # 三个时间戳一起看
touch -a file             # 只动 atime
touch -m file             # 只动 mtime
touch -d "2024-01-01 08:00" file   # 指定时间
时间戳 含义 什么操作会动它
atime 最后访问时间 读文件
mtime 最后修改内容 写文件
ctime 最后改元数据 改权限、属主、改名

板子上跑不起来，第一件事是 file：架构不对，后面调什么都是白费。

通配符由 shell 展开，命令本身看不到 *：

模式 匹配
* / ? 任意长度 / 单个字符
[abc] / [a-z] 字符集之一 / 范围之一
{a,b} 花括号展开，bash 支持，dash 不支持 
bash
ls *.log
rm -f tmp_?.txt
mkdir -p project/{src,bin,doc}
# dd 按块搬数据，写盘、做镜像、造测试文件都靠它
dd if=/dev/zero of=560_file count=1 bs=560M
dd if=/dev/cdrom of=system.iso
dd if=/dev/sdb of=disk.img bs=1M status=progress
参数 含义
if= / of= 输入文件 / 输出文件，默认标准输入输出
bs= / count= 每块大小 / 复制几块
status=progress 打印进度

of= 打错一个字母就是整块盘被覆盖，dd 没有回收站。

四、查看文件内容 #

先按场景选工具：

场景 命令
文件小，一次看完 cat，cat -n 带行号
文件大，翻页 less、more
只看开头 / 结尾 N 行 head、tail
跟着日志跑 tail -f、tail -F
统计行数、词数、字节 wc 
bash
cat readme                # 看内容
cat -n readme             # 带行号
cat a.txt b.txt > all.txt # 拼接
cat > note.txt            # 从键盘写文件，Ctrl+D 结束
cat 路径/文件名 | grep 关键字

less 比 more 顺手：

按键 作用
空格 / b 下一页 / 上一页
g / G 首行 / 尾行
/关键字 向下搜，n 跳下一个
q 退出

more 两个实用参数：more -s testfile 把连续空行压成一行，more +20 testfile 从第 20 行开始。

bash
head file                  # 默认 10 行
head -n 5 file
head -n 1 /etc/issue       # 看发行版版本
tail -n 20 file
tail -f file               # 持续输出新追加的行
tail -F /var/log/syslog    # 文件被轮转后仍跟得住

bash
wc -l file            # 行数
wc -w file            # 单词数
wc -c file            # 字节数
wc < /etc/passwd      # 统计用户数

不加参数时 wc 从标准输入读，Ctrl+D 结束才出结果。

五、查找文件与内容 #

四个工具各有战场，选错就慢十倍：

工具 找什么 速度 数据来源
find 按属性找文件 慢，逐目录遍历 实时扫盘
locate 按名字找文件 快 updatedb 生成的数据库
grep 在文件内容里找字符串 看文件量 文件内容
which 找命令本体在哪 快 PATH 目录

find 的结构是「路径 + 条件 + 动作」：

bash
find /var/log -name "*.log"        # 按名字
find . -name "file*"               # 当前目录下以 file 开头
find . -type d -name "cache"       # 只找目录
find . -type f -size +50M          # 大于 50M
find . -type f -size -50k          # 小于 50k
find . -mtime -7                   # 7 天内改过
find . -mtime +30                  # 30 天前改过
find / -perm 777 -type f           # 权限正好 777
find . -nouser -o -nogroup         # 无属主或无属组
find . -name "*.tmp" -delete       # 找到就删
条件 作用
-name / -iname 按名字，区分 / 忽略大小写
-type f 文件、d 目录、l 链接、b 块设备、c 字符设备、p 管道、s 套接字
-size + 大于、- 小于，单位 c、k、M、G
-mtime / -atime / -ctime 内容修改 / 访问 / 元数据时间，-n n 天内、+n n 天前
-newer f1 比 f1 更新
-user / -group 按属主 / 属组
-perm 777 完全匹配，-777 包含即可
-nouser / -nogroup 属主 / 属组已不存在
-maxdepth / -prune 限制深度 / 排除目录
-exec 对结果执行命令，以 \; 结尾

-exec 里 {} 代表当前命中的文件：

bash
find . -name "*.log" -exec rm -f {} \;
find . -name "*.sh" -exec chmod +x {} \;
find /tmp -type f -mtime +7 -print          # 先打印确认再删
find . \( -name "*.c" -o -name "*.h" \) -exec grep -l main {} \;
find . -path ./node_modules -prune -o -name "*.js" -print   # 排除目录

-exec ... \; 每个文件起一次命令，文件多就慢；-exec ... + 攒成一批一次传，快得多。

locate 查数据库，秒回，但新文件还没进库，先 sudo updatedb 重建。

grep 在内容里找：

bash
grep pattern file
grep -n pattern file        # 带行号
grep -i pattern file        # 忽略大小写
grep -v pattern file        # 反向，只留不含关键词的行
grep -c pattern file        # 只输出命中行数
grep -r pattern dir/        # 递归
grep -rn pattern src/       # 递归 + 行号，改代码最常用
grep -a pattern binary      # 二进制当文本搜
command | grep pattern      # 从管道里筛
选项 作用 选项 作用
-i 忽略大小写 -n 显示行号
-v 反向选择 -c 只输出行数
-r 递归 -l 只输出文件名
-a 二进制当文本 -E 扩展正则，等同 egrep
-w 全词匹配 -A3 / -B3 命中行后 / 前各 3 行

定位命令本体：

bash
which ls           # PATH 里第一个匹配
which -a python3   # PATH 里所有匹配
whereis ls         # 可执行文件、源码、man 页一起找
type cd            # 内置还是外部程序

which cd 常常什么都不给，type cd 会明确告诉你 cd is a shell builtin。

六、文本处理三剑客之外 #

grep 之外，日常处理文本靠 cut、tr、sort、uniq、sed、awk 这一组，各管一件事。

cut 按列切，-d 指定单字符分隔符，-f 指定字段：

bash
cut -d: -f1 /etc/passwd      # 冒号分隔取第 1 列，即所有用户名
cut -d: -f1,3 /etc/passwd    # 取 1、3 列
cut -c1-10 file              # 取每行前 10 个字符

多空格对齐的列 cut 切不动，那种情况交给 awk。

tr 做字符级替换，只吃标准输入：

bash
cat a.txt | tr 'a-z' 'A-Z'     # 转大写
cat a.txt | tr -d '\r'         # 删掉 Windows 换行符
tr -s ' ' < file               # 连续空格压成一个
tr -d '\n' < file              # 删掉换行，合成一行
# sort 与 uniq 是一对，uniq 只处理相邻重复行，所以必须先 sort
sort file                 # 字典序
sort -n file              # 按数值
sort -r file              # 倒序
sort -u file              # 排序并去重
sort -k2 -n file          # 按第 2 列数值排
sort file | uniq -c       # 去重并计数
sort file | uniq -d       # 只留重复行

顺序错了结果就是错的，这一步没得商量。

sed 流编辑，改文本不做交互：

bash
sed 's/old/new/' file            # 每行替换第一个
sed 's/old/new/g' file           # 每行全部替换
sed -i 's/old/new/g' file        # 直接改文件
sed -n '10,20p' file             # 只打印 10 到 20 行
sed '/^#/d' file                 # 删掉以 # 开头的注释行
sed -i.bak 's/old/new/g' file    # 改文件并留 .bak 备份
# awk 按字段处理，报表类任务的主力
awk '{print $1}' file                 # 第 1 列
awk -F: '{print $1, $3}' /etc/passwd  # 指定分隔符取两列
awk '$3 > 1000 {print $1}' /etc/passwd
awk 'END {print NR}' file             # 总行数
awk '{sum += $1} END {print sum}' file
# diff 比差异、出补丁，patch 打补丁
diff a.txt b.txt              # 逐行比
diff --brief a.txt b.txt      # 只回答是否不同
diff -c a.txt b.txt           # 上下文格式
diff -u old.c new.c > a.patch # 生成补丁
diff -r dir1 dir2             # 递归比目录
patch -p1 < a.patch
patch -i a.patch filename

-p1 表示去掉路径第 1 层再定位文件，具体数字看补丁头里的路径层级。

拆分大文件，切出来是 filename.dump.aa、.ab 这样的顺序片段：

bash
split -b 1M filename filename.dump.
cat filename.dump.a*            # 拼回去
# expr 做整数与字符串的小计算；纯整数运算更常用 $(( ))
expr 3 + 4
expr length "abcdef"
expr substr "abcdef" 2 3
echo $((3 + 4))

七、管道与重定向 #

这是命令组合的地基。默认有三个标准流：

流 编号 默认去向
标准输入 0 键盘
标准输出 1 终端屏幕
标准错误 2 终端屏幕

重定向改的就是这三个流的方向：

符号 名字 行为
> 输出重定向 标准输出写进文件，原有内容被清空
>> 追加重定向 标准输出追加到文件末尾
< 输入重定向 从文件读数据当标准输入
2> / 2>> 错误重定向 / 追加 标准错误写进 / 追加到文件
&> 全部重定向 标准输出与标准错误一起写进文件
>&2 输出转错误 标准输出改道到标准错误
| 管道 前者标准输出接成后者标准输入

第一条差别，> 是覆盖，>> 是追加：

bash
ls > list.txt              # 写进 list.txt，原有内容没了
echo "新一行" >> list.txt   # 加到末尾，前面内容还在
cat a.txt > b.txt          # 复制，覆盖 b.txt
cat c.txt >> b.txt         # 追加到 b.txt 尾部
# 第二条差别：| 交给下一个程序算，> 落成文件，管道不落盘
ps aux > ps.txt                 # 结果存成文件
ps aux | grep nginx             # 结果交给 grep 筛
ps aux | grep nginx | wc -l     # 再交给 wc 数行数
# 管道只接标准输出，标准错误照样漏到屏幕上
command 2>&1 | grep error

2>&1 的意思是「把 2 号流指向 1 号流当前的目标」。顺序不能反：command 2>&1 > file 与 command > file 2>&1 结果完全不同，前者错误仍去屏幕。

常用组合：

bash
command 2> error.log             # 错误单独存
ls a.txt &> b.txt                # 输出和错误一起存
command > out.log 2>&1           # 同上，POSIX 写法
command < input.txt              # 从文件读输入
eval $(ssh-agent)                # 把命令输出当命令执行
cat /etc/passwd | wc -l          # 统计行数
mount | column -t                # 结果对齐成表
dmesg | grep -i usb              # 内核日志里筛
history | less                   # 历史翻页看
# tee 分叉，既落盘又留在管道里
make 2>&1 | tee build.log
make 2>&1 | tee -a build.log     # 追加而不是覆盖
# /dev/null 是黑洞，2>/dev/null 就是「错误别烦我」
command > /dev/null 2>&1            # 全部静音
find / -name "*.conf" 2>/dev/null   # 只留结果，屏蔽无权访问的报错

2> 必须紧贴数字，写成 2 > 就成了「参数 2 加输出重定向」，语义完全不同。

八、进程查看与控制 #

进程是运行中的程序实例，每个有 PID。查看分静态与动态两路。

bash
ps -aux        # BSD 风格，含用户、CPU、内存
ps -ef         # System V 风格，含 PPID 与完整命令
ps aux         # 同上，不带横线
ps -ef | grep nginx
列 含义 列 含义
USER 进程属主 PID 进程号
%CPU / %MEM CPU / 内存占用率 VSZ / RSS 虚拟内存 / 常驻内存，KB
TTY 所属终端，? 为无终端 STAT 进程状态
START 启动时间 TIME 累计占用 CPU 时间
COMMAND 命令名与参数

STAT 的取值决定进程死活：

状态 含义
R 运行中，或在运行队列里等 CPU
S 可中断睡眠，等事件或信号唤醒
D 不可中断睡眠，多数在等 I/O，kill 也送不进去
Z 僵死，已退出但描述符没被父进程回收
T 已停止，收到停止信号

D 卡着去看磁盘和 NFS，Z 越积越多去看父进程为什么不 wait。

top 是动态视图，top -p 1234 只看指定 PID。前五行各管一件事：

行 内容
1 系统时间、运行时长、登录终端数、1/5/15 分钟平均负载
2 进程总数、运行中、睡眠中、已停止、僵死
3 用户态、内核态、改过优先级的进程、空闲 CPU 占比
4 物理内存总量、已用、空闲、内核缓存
5 交换区总量、已用、空闲、已预加载

第 3 行的 97.1 id 表示 97.1% 的 CPU 空闲；第 5 行 swap 持续上涨说明物理内存不够。top 里 P 按 CPU 排序、M 按内存排序、k 输 PID 杀进程、1 展开每核、q 退出。

找 PID 与送信号：

bash
pidof nginx              # 按服务名找 PID，同一个服务会有多个
pgrep -a nginx           # 按进程名匹配，带命令行
ps -ef | grep nginx      # 最土也最通用
kill 1234                # 默认送 TERM，礼貌请求退出
kill -9 1234             # KILL，内核直接掐掉，不给清理机会
kill -l                  # 列出所有信号
killall nginx            # 按名字杀全部同名进程
pkill -f "python app.py" # 按完整命令行匹配
信号 编号 含义
HUP 1 挂起，很多守护进程用它重载配置
INT 2 中断，等同 Ctrl+C
KILL 9 强杀，进程无法捕获
TERM 15 终止，默认值，进程可以先清理
STOP / CONT 19 / 18 暂停 / 继续

顺序永远是先 TERM，等几秒，再 KILL。上来就 -9，文件容易写坏，socket 容易不释放。

十、压缩与打包 #

打包和压缩是两件事。tar 打包，把一堆文件收成一个 .tar；gzip、bzip2、xz 压单个文件。.tar.gz 是先打包再压缩。

tar 参数按「做什么 + 用什么压缩 + 处理哪个文件」三段记：

参数 作用 参数 作用
-c 创建归档 -x 解开归档
-t 只列内容不解 -v 显示过程
-z / -j / -J gzip / bzip2 / xz -f 指定归档名，必须紧跟文件名
-p 保留权限属性 -P 允许绝对路径
-C 解到指定目录 --exclude= 排除模式

高频组合背下来就够用：

bash
tar cf file.tar files          # 打包，不压缩
tar xf file.tar                # 解开，不压缩
tar czf file.tar.gz dir/       # 打包并 gzip 压缩
tar xzf file.tar.gz            # 解开 gzip 包
tar cjf file.tar.bz2 dir/      # bzip2 压缩，压缩率更高，慢一些
tar xjf file.tar.bz2           # 解开 bzip2 包
# 其余常用写法
tar tf 包名                       # 只看包里有什么
tar tvf 包名                      # 带详细信息列内容
tar xvf 包名                      # 解包并打印每个文件名
tar xvf 包名 -C /opt/target       # 解到指定目录
tar zxvf 包名 -C /opt/target      # 解 gzip 包到指定目录
tar czf backup.tar.gz --exclude=*.log dir/
tar cjf - logs/ | split -b 1m - logs.tar.bz2   # 打包压缩后切成 1M 一片
cat logs.tar.bz2.a* | tar xj                   # 反向合并并解压

-f 后面必须跟文件名，所以它多半放最后。写成 tar -fcz 会把 cz 当成文件名。管道里的 - 表示标准输入输出。

单文件压缩工具：

bash

gzip -d file.gz        # 解压
gzip -k file           # 保留原文件
gzip -9 file           # 最高压缩率
bzip2 file / bunzip2 file.bz2
xz -9 file / unxz file.xz      # 压缩率最高，最慢
compress -f source.dat         # 压成 source.dat.Z，解压 uncompress
zip -r pkg.zip dir/ / unzip pkg.zip -d /tmp

gzip 默认删掉原文件，这是它最常见的「事故」，要保留就加 -k。

十二、输入输出与权限位速查 #

流 编号 默认设备 重定向写法
标准输入 0 /dev/stdin <、0<
标准输出 1 /dev/stdout >、>>、1>
标准错误 2 /dev/stderr 2>、2>>
设备 含义
/dev/null 丢弃一切写入，读它立刻 EOF
/dev/zero 无限读出 0 字节
/dev/random / /dev/urandom 阻塞 / 非阻塞随机源
/dev/tty 当前终端
/dev/fd/N 第 N 号文件描述符

输入输出三条实战规则：重定向只改目标不改命令；多个重定向从左到右生效，后面的覆盖前面的（2>&1 > f 把错误指向了当时的标准输出，所以错误仍上屏幕，要一起进文件必须 > f 2>&1）；管道只有标准输出能过，标准错误得先 2>&1。

给所有登录终端广播一句话：

bash
wall "系统将在 5 分钟后重启"
wall < notice.txt        # 从文件读内容广播

权限位。ls -l 第一位是类型：

首字符 类型 首字符 类型
- 普通文件 d 目录
l 符号链接 c 字符设备，键盘、串口
b 块设备，磁盘 p 命名管道
s 套接字

后面九位按「属主 / 属组 / 其他人」三段排，每段 r、w、x：

位 数值 对文件 对目录
r 4 读内容 列出目录项
w 2 改内容 在目录内增删文件
x 1 执行 进入目录、访问其下文件 
text
-rwxr-xr--  1 root root 4096 Nov 17 12:00 run.sh
 │└┬┘└┬┘└┬┘
 │ │  │  └── 其他人 r--
 │ │  └───── 属组   r-x
 │ └──────── 属主   rwx
 └────────── 类型   普通文件

八进制就是把三位加起来：

八进制 权限 说明
777 rwxrwxrwx 所有人可读可写可执行，脚本临时用都嫌宽
755 rwxr-xr-x 可执行程序与目录的常见值
644 rw-r--r-- 普通文件常见值
600 rw------- 私钥、私密配置
700 rwx------ 私有目录
400 r-------- 只读保护 
bash
chmod u+r file         # 属主加读；g+x 属组加执行；a+w 所有人加写
chmod o-rwx file       # 其他人全部去掉
chmod u=rwx,g=rx,o= file
chmod -R 755 dir/      # 递归
chown user file        # 改属主
chown :group file      # 改属组
chown user:group file  # 一起改
chown -R user:group dir/
chgrp group file       # 只改属组
符号 对象 操作
u / g / o / a 属主 / 属组 / 其他人 / 所有人 + 加、- 减、= 直接设定

专用权限位，ls -l 里 x 位置变成 s 或 t：

位 数值 作用
SUID 4000 执行时以属主身份运行，如 passwd
SGID 2000 执行时以属组身份运行；对目录则新建文件继承属组
Sticky 1000 目录内文件只有属主能删，如 /tmp 
bash

chmod 1777 /tmp         # 加 Sticky
umask                   # 当前掩码，普通用户多为 0022
umask 027               # 改，只在当前 shell 生效

实际权限 = 默认值减 umask，0022 下新建目录是 755、新建文件是 644。ls -l 里的链接数不是文件数：对文件是硬链接数，对目录是子目录数，数文件用 ls -1 | wc -l 或 find . -maxdepth 1 -type f | wc -l。

这一章只做速查。用户、组、sudo 的成体系用法，以及权限模型里的取舍，见《用户与权限管理》。

十三、man 手册的使用 #

man 是 manual 的缩写，读的是系统里已装好的手册页，不联网。手边没网也能用，这是它最实在的地方。

bash
man ls             # 看 ls 的手册
man 1 ls           # 指定第 1 部分
man 2 open         # 系统调用 open
man 3 open         # 库函数 open
man 5 passwd       # passwd 文件的格式

手册页各段固定：

段落 内容
NAME 命令名与一行说明
SYNOPSIS 语法骨架
DESCRIPTION 详细说明，选项多半在这里
OPTIONS 选项逐条解释
FILES 相关文件
EXAMPLES 例子
SEE ALSO 相关命令与手册

SYNOPSIS 那套记号先看懂，它决定你会不会读：

text
ls [OPTION]... [FILE]...

方括号是可选，省略号是可重复多个，竖线是二选一。所以 ls 后面可以不带选项、不带文件，也可以带一串。

九个 section 是 man 的核心机制，同一个名字在不同 section 里是两回事：

编号 内容 例子
1 用户命令 ls、cp、grep
2 系统调用 open()、fork()、read()
3 库函数 printf()、malloc()、strlen()
4 特殊文件与设备 /dev/sda、tty
5 文件格式与约定 /etc/passwd、fstab
6 游戏 nethack
7 杂项与约定 signal、man-pages
8 系统管理命令 shutdown、useradd、mount
9 内核例程 内核内部接口

man 2 open 与 man 3 open 看到的东西完全不同：前者是内核提供的系统调用，讲 int open(const char *pathname, int flags) 与 errno；后者是 C 库里的同名封装，讲 FILE * 那一套。写应用层代码看 3，写驱动、调系统调用看 2。这就是为什么查 open 必须带数字。

不带数字时 man open 按 /etc/manpath.config 的顺序在 section 里找，命中最小的那个，多半是 1。确认某个名字存在于哪些 section：

bash
man -a open        # 依次翻遍所有 section 里的 open
man -w open        # 只显示手册页文件路径
whatis open        # 一句话说明；man -f open 等价
apropos 关键词     # 按关键词搜所有手册页的 NAME 段；man -k 等价

不知道命令名时从 apropos 进来，apropos "copy file" 比硬想 cp 的名字快。

翻页键与 less 一致：空格/b 翻页，g/G 首尾，/关键字 搜、n 跳下一个，q 退出。

手册里有些排版控制字符，管道接出去会变乱码，过一道 col 清掉：

bash
man ls | col -b | less
man ls | col -b > ls.txt
manpath                  # 当前搜索路径
echo $MANPATH            # 自己加的路径
ls /usr/share/man        # man1 到 man9 就在这下面
man -M /opt/app/man cmd  # 临时指定手册目录
man -L zh_CN ls          # 中文手册，装了才有

十四、help、info 与其他文档 #

man 查不到内置命令，help 才是内置命令的入口：

bash
help            # 列出所有内置命令
help cd         # 看 cd 的内置用法
help -m cd      # 用 man 风格排版输出
help -d cd      # 一句话说明
# --help 走另一条路，几乎所有外部程序都实现了，输出太长就接 less
ls --help
ls --help | less
tar --help

四条路的分工：

命令类型 该用什么
shell 内置（cd、echo、alias） help 命令名
外部程序（ls、tar、grep） man 命令名、命令名 --help
GNU 工具，需要完整文档 info 命令名
想知道文件属于哪个包 rpm -ql、dpkg -L

info 是 GNU 的超文本手册，比 man 详细，带节点跳转：

bash
info ls
info coreutils

info 里按键是另一套：n 下一个节点、p 上一个、u 上一层、l 后退、q 退出。嫌麻烦就 info ls | less。

更多文档藏在文件系统里：

bash
ls /usr/share/doc/            # 每个包的 README、示例配置、变更记录
ls /usr/share/doc/nginx/
cat /usr/share/doc/包名/README
zcat /usr/share/doc/包名/changelog.Debian.gz
ls /etc/                      # 配置文件本身就是最准的文档

man 页与 --help 都写不清楚时，去 EXAMPLES 段和 /usr/share/doc 里翻，多半比搜网页准。

十五、命令不存在时怎么查 #

command not found 不是错误，是诊断信息。按顺序走：

第一步，确认拼写与大小写，Linux 区分大小写，LS 和 ls 是两个东西。

第二步，确认它是不是内置：

bash
type cd
type -a ls

type cd 说 cd is a shell builtin，那它根本不在 PATH 里，which 找不到很正常。

第三步，确认装没装：

bash
which 命令名
whereis 命令名
ls /usr/bin/命令名 /usr/sbin/命令名
rpm -qf $(which 命令名)        # 属于哪个包
rpm -qa | grep 关键字          # 包是否已安装
# 第四步，确认 PATH 里有它所在的目录
echo $PATH
echo $PATH | tr ':' '\n'

第五步，确认文件存在且有执行权限：ls -l /usr/bin/命令名、file /usr/bin/命令名。

报错 原因 处理
command not found 没装，或不在 PATH 装包，或补 PATH
No such file or directory（文件明明在） 动态链接器缺失，或行尾多了 \r file 看架构，ldd 看依赖
Permission denied 没有执行位 chmod +x，或改用 sh 脚本名
Is a directory 把目录当命令敲了 检查路径
Text file busy 文件正在被某个进程执行 停掉进程再改
Too many arguments 通配符展开出几万个文件 用 find -exec ... + 或 xargs

补 PATH，以及脚本执行权限的两条路：

bash
export PATH=$PATH:/opt/app/bin        # 当前会话生效
export PATH=/opt/app/bin:$PATH        # 放前面优先命中，同名命令以它为准
echo 'export PATH=$PATH:/opt/app/bin' >> ~/.bashrc   # 永久
source ~/.bashrc
chmod +x run.sh && ./run.sh
sh run.sh                             # 不依赖执行位

板子上报 command not found 还有第三种原因：这个程序编进了别的架构，file 一看就知道。

十六、易错点速查 #

易错点 错在哪 正确做法
MOVIE = "x" 等号两边有空格，shell 当命令名 MOVIE="x"
rm -rf / var 空格把路径拆成两个参数 先 pwd，核对路径再回车
command 2 > f 2 被当成参数，重定向的是标准输出 command 2> f
command 2>&1 > f 错误指向了改道前的标准输出 command > f 2>&1
管道里错误丢了 | 只接标准输出 command 2>&1 | grep x
> 覆盖了旧日志 > 清空文件 追加用 >>
uniq 前没 sort uniq 只处理相邻重复 sort file | uniq -c
gzip 后原文件没了 默认删源 加 -k 保留
tar -fcz -f 后紧跟的被当成文件名 tar -czf 包名
cd -P a/b 以为是建目录 建目录用 mkdir -p a/b
./run.sh 写成 run.sh PATH 里没有 . 加 ./ 或补 PATH
chmod 777 图省事 所有人都能改 按最小必要给，脚本 755、私钥 600
kill -9 上来就用 进程来不及清理 先 TERM，等几秒再 KILL
Ctrl+Z 当退出用 只是挂起，进程还在 真结束用 Ctrl+C 或 kill
free 一列小就慌 缓存占的内存可回收 看 available 那一列
df 满而 du 加起来不够 文件已删但句柄没释放 lsof | grep deleted
ps aux 与 ps -ef 混着记 两种风格列名不同 认准一种，用 -ef 看 PPID
more 里退不出 不熟按键 用 less，q 退出
find 没限定范围 扫到 /proc、/sys 卡住 限定路径与 -maxdepth，错误丢 /dev/null
man open 看到的是命令 默认取最小 section 明确写 man 2 open 或 man 3 open
which cd 空输出 内置命令不在 PATH 用 type cd 或 help cd
脚本改了 PATH 却没生效 用 sh 脚本 另起了 shell source 脚本 在当前 shell 执行

留一条判断原则：命令行为不符合预期时，先用 type、which、file 把「它是谁」确认清楚，再谈参数。大部分「命令坏了」都停在第一步。
