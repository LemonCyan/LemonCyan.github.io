一、Linux 音频栈的分层 #

从按下播放到扬声器出声，数据走五段路。分层不是学术分类，它决定你在哪一层调、出错时看哪个日志。

层 具体东西 跑在哪 对应命令
硬件 HDA 声卡、HDMI/DP 音频、USB DAC、蓝牙耳机 — lspci -nn、lsusb
驱动 snd_hda_intel、snd_usb_audio、snd_soc_*、bluetooth 内核 lsmod、dmesg
内核接口 ALSA：/dev/snd/*、/proc/asound/ 内核 aplay、arecord、amixer
混音服务 PulseAudio、PipeWire、ALSA 的 dmix 插件 用户进程 pactl、wpctl、paplay
应用 播放器、浏览器、会议软件 用户进程 各自界面里的音量条

两条路径要分清，这是全篇的地基：

text
aplay file.wav  ─────────────────────► ALSA (/dev/snd/pcmC0D0p) ──► 声卡
                                          ▲
paplay file.wav ──► PulseAudio / PipeWire ┘   (经 alsa-plugins 的 pulse 插件)

直连 ALSA 时，一个进程占住 hw:0,0，第二个进程再打开就是 Device or resource busy。想让多个程序同时出声，只有两条路：走混音服务，或者让 ALSA 自己用 dmix 插件做软件混音。

混音服务做四件事：把各路流重采样成声卡认的率；把多路流混成一路写进同一个 PCM；按应用分别记音量；插拔设备时把流搬到新设备上不断音。

alsamixer 改的是 ALSA 的 control，也就是硬件增益和开关；pactl set-sink-volume 改的是混音服务里的软件增益。两个数相乘才是你听到的响度，它们不是同一个寄存器。

ALSA 还有一层插件，让老程序不改代码就走混音服务。装上 alsa-plugins-pulse（Debian/Ubuntu）或 alsa-plugins-pulseaudio（Fedora），在 /etc/asound.conf 里把 default 指向 pulse，aplay 就能和浏览器一起出声。很多发行版默认这么配，所以 aplay -L 的输出里带着 pulse。

二、ALSA：内核的声音接口 #

ALSA 在内核暴露两个界面：设备节点 /dev/snd/ 和 procfs 的 /proc/asound/。所有命令行工具都是这两个界面的包装。

设备节点的命名 #

节点 含义
controlC0 0 号声卡的 control 接口，amixer、alsamixer 用它
pcmC0D0p 0 号卡、0 号设备的播放 PCM
pcmC0D0c 同一个 PCM 的录制方向
pcmC0D3p 0 号卡、3 号设备的播放，HDMI 常落在这里
hwC0D0 原始硬件节点，绕开 PCM 层的工具用它
timer 定时器，给 MIDI 和音序器用
seq MIDI 音序器接口

命名规则是 pcmC<卡号>D<设备号><方向>，方向 p 是播放，c 是录制。ls -l /dev/snd/ 看节点，cat /proc/asound/devices 看已注册节点和次设备号：

text
  1: [ 0- 0]: control
  2: [ 0- 0]: digital audio playback
  3: [ 0- 0]: digital audio capture
  4: [ 0- 2]: digital audio playback
 33:        : timer

方括号里就是 卡-设备，和 hw:0,0、hw:0,2 对得上；hw: 后面那对数字就是这两个值，顺序不能颠倒。

hw 与 plughw 的差别 #

hw:0,0 的意思是原样交给声卡。-r 44100 而声卡只吃 48000，直接 Invalid argument；-c 1 而声卡只吃双声道，同样失败。它不重采样、不混音，占住就是独占。

plughw:0,0 是同一张卡、同一个设备，外面套了一层 plug 插件：自动重采样、自动换采样格式、自动做声道映射。代价是多一次转换，延迟和精度有损失，换来「扔什么进去都能响」。

判断标准看你要确定还是只要能响。测硬件极限、做 bit-perfect 输出用 hw:；参数不确定、只想听个响用 plughw:。

名字 走什么 会转换吗 独占 用在什么场合
hw:0,0 直达硬件 不转换 独占 测极限参数、直通输出
plughw:0,0 硬件加 plug 插件 自动转换 独占 参数不确定时首选
default 配置里的名字 看配置 看配置 日常播放
sysdefault:CARD=PCH 该卡自己的默认 看卡 看卡 default 被改乱时的后路
front:CARD=PCH,DEV=0 前置声道 不转换 独占 立体声直出
dmix:CARD=PCH,DEV=0 软件混音 有 共享 没混音服务时多程序共用
pulse PulseAudio/PipeWire 有 共享 老程序接混音服务
null 丢弃 有 共享 只测管线不出声

default 与 sysdefault 的差别 #

default 不是硬件设备，是一个名字，指向 /etc/asound.conf、~/.asoundrc 或发行版配置里的那条 pcm.!default。它指向 hw:0,0、dmix 或 pulse 中的哪一个，取决于那条配置。看到 default 不出声，先去看它到底指哪。

sysdefault:CARD=PCH 是声卡自己那套默认，绕过系统级配置。default 被改坏、或者 SSH 会话里 pulse 连不上时，用它直接落到卡上。

bash
aplay -D default test.wav
aplay -D sysdefault:CARD=PCH test.wav

/proc/asound 的布局 #

路径 内容
/proc/asound/cards 卡列表：编号、id、驱动、短名
/proc/asound/devices 已注册的 PCM 与 control 节点
/proc/asound/pcm 每个 PCM 的播放/录制能力
/proc/asound/modules 卡号与内核模块的对应关系
/proc/asound/card0/id 0 号卡的名字，hw: 里可用它替代编号
/proc/asound/card0/codec#0 HDA codec 的寄存器与 pin 配置
/proc/asound/card0/pcm0p/sub0/hw_params 当前流的真实参数，放音时才有内容
/proc/asound/timers 定时器列表

hw_params 是排查时的第一手材料。播放卡住或参数对不上时，一边放音一边看它，硬件实际吃进去的率、格式、声道、buffer 尺寸都在里面：

bash
cat /proc/asound/card0/pcm0p/sub0/hw_params

text
access: RW_INTERLEAVED
format: S16_LE
channels: 2
rate: 48000 (48000/1)
period_size: 1024
buffer_size: 16384

/sys/class/sound/ 是同一批对象的 sysfs 视图，udev 规则和脚本里用它更稳。

库调用看到的是同一套名字 #

c
snd_pcm_open(&handle, "default", SND_PCM_STREAM_PLAYBACK, 0);

第三个参数定方向。snd_pcm_set_params() 一次设格式（SND_PCM_FORMAT_S16_LE）、访问方式（SND_PCM_ACCESS_RW_INTERLEAVED）、声道、采样率、是否允许重采样、以及延迟，最后一个参数是缓冲时长，单位微秒，500000 就是 0.5 秒。之后 snd_pcm_writei() 推帧，snd_pcm_drain() 排空，snd_pcm_close() 收尾。

WAV 头里 8 位样本对 SND_PCM_FORMAT_S8，16 位对 SND_PCM_FORMAT_S16_LE，32 位对 SND_PCM_FORMAT_S32_LE。写代码按 bits_per_sample 分支，写命令行就是 -f S8、-f S16_LE、-f S32_LE。

命令行工具做同一件事：-D 是设备名，-f 是格式，-c 是声道，-r 是采样率，--buffer-time 是缓冲时长。参数不匹配时 snd_pcm_set_params() 返回负值，工具打印 Invalid argument、Sample format non available、Channels count non available。见到这三种，先换 plughw: 再试，能响说明是参数协商问题，不是硬件问题。

推帧返回负值要调 snd_pcm_recover() 处理 xrun。命令行工具也会遇到，表现是 underrun occurred 后继续播放，或者直接卡死。收尾的 snd_pcm_drain() 不能省：它把缓冲区里剩下的样本排空，跳过这一步，最后几十毫秒被直接丢弃，短提示音会听不全。

三、PulseAudio 与 PipeWire：用户态的混音层 #

ALSA 只保证一个流进一个 PCM。多程序同时出声、每个程序单独调音量、插耳机自动搬流，都在用户态服务里做。

PulseAudio 的几个事实：每个登录用户一个 daemon，不是系统级服务，root 跑 pactl 找不到你自己的 socket；客户端走 unix socket，默认 /run/user/1000/pulse/native；配置分 /etc/pulse/ 全局和 ~/.config/pulse/ 个人两层；能力靠 module 拼，module-alsa-card 接声卡，module-bluetooth-discover 接蓝牙，module-null-sink 造虚拟输出，module-echo-cancel 做回声消除，module-stream-restore 记每应用的音量和目标设备。

PipeWire 把音频、视频、屏幕共享收进同一张图。跑音频时是三件套：pipewire 管图，wireplumber 做会话与策略，pipewire-pulse 提供 PulseAudio 协议兼容层。它监听同一个 socket，PulseAudio 的客户端和 pactl 一行都不用改，所以 PipeWire 机器上 pactl info 的 Server Name 写着 PulseAudio (on PipeWire x.y.z)。

text
$ pactl info
Server String: /run/user/1000/pulse/native
Server Protocol Version: 35
Server Name: PulseAudio (on PipeWire 1.0.5)
Default Sink: alsa_output.pci-0000_00_1f.3.analog-stereo
Default Source: alsa_input.pci-0000_00_1f.3.analog-stereo

Server Name 只有 pulseaudio 就是原版；带 on PipeWire 就是 PipeWire 在冒充。

bash
systemctl --user status pipewire pipewire-pulse wireplumber
systemctl --user status pulseaudio
ps -eo comm | grep -E 'pipewire|pulseaudio'
维度 PulseAudio PipeWire
启动方式 socket 按需激活，pulseaudio --start systemctl --user 直接管
会话与策略 内置 拆给 WirePlumber
配置目录 /etc/pulse/、~/.config/pulse/ /etc/pipewire/、~/.config/pipewire/
客户端 pactl、pacmd pactl 兼容层、pw-cli、wpctl
蓝牙 module-bluetooth-discover libspa-0.2-bluetooth 加 WirePlumber
延迟调节 default-fragments、default-fragment-size-msec 图式调度，可设 quantum
ALSA 兼容 alsa-plugins-pulse pipewire-alsa

从 PulseAudio 换到 PipeWire：

bash
systemctl --user disable --now pulseaudio.socket pulseaudio.service
systemctl --user enable --now pipewire pipewire-pulse wireplumber
sudo apt install pipewire pipewire-pulse pipewire-audio-client-libraries wireplumber

pipewire-audio-client-libraries 提供 libasound_module_pcm_pipewire.so，纯 ALSA 程序也能走 PipeWire。只装 pipewire 不装它，aplay 还是直连 ALSA。

SSH 登进去打 pactl 报 Connection failure: Connection refused，原因是它找 $XDG_RUNTIME_DIR 下的 socket，SSH 会话没带那个变量，或者这个用户没跑服务。systemctl --user 同理，缺 DBUS_SESSION_BUS_ADDRESS。

bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
pactl info

加 sudo 打 pactl 必然失败：root 是另一个用户，没有那个 socket。改当前桌面的音量就回当前用户执行。

四、查看声卡与设备 #

排查音频问题第一步永远是列清单。别急着装驱动，先看系统认到了什么。

text
$ cat /proc/asound/cards
 0 [PCH    ]: HDA-Intel - HDA Intel PCH
 1 [HDMI   ]: HDA-Intel - HDA Intel HDMI
 2 [Device ]: USB-Audio - USB Audio Device

方括号里是卡的 id，也就是 hw: 里可替代编号的名字。hw:PCH 和 hw:0 指同一张卡。aplay -l 是同一份信息的另一种排版，多了设备号。

text
$ aplay -l
card 0: PCH [HDA Intel PCH], device 0: ALC892 Analog [ALC892 Analog]
  Subdevices: 1/1
card 0: PCH [HDA Intel PCH], device 3: HDMI 0 [HDMI 0]
  Subdevices: 1/1
card 2: Device [USB Audio Device], device 0: USB Audio [USB Audio]
  Subdevices: 1/1

读法：card 0: PCH 是卡，device 0 是设备，合起来 hw:0,0；device 3: HDMI 0 合起来 hw:0,3；USB 声卡是 hw:2,0。

Subdevices: 1/1 的第二个数字是总子流数。1/1 表示同时只允许一个流，第二个程序打开就 busy；4/4 能并四个。

三处信息互相印证卡号，/proc/asound/modules 给出卡号与模块的对应：

bash
cat /proc/asound/modules
lspci -nn | grep -i audio
dmesg | grep -iE 'snd|audio|hda' | tail -30

text
 0 snd_hda_intel
 1 snd_hda_intel
 2 snd_usb_audio

dmesg 里看到 no codecs found 说明 HDA 总线通了但 codec 没响应；看到 cannot take ownership 是驱动冲突；USB 声卡先看 lsusb 认不认得到。

aplay -L 列的是 PCM 名字，不是硬件设备，两者数量不等，因为一个硬件设备可以被多个插件名覆盖。-D 后面能接的名字全在这个列表里，带 CARD= 的是带参数的别名。

想确认 命令 看什么
有哪些卡 cat /proc/asound/cards 卡号、id、驱动名
每张卡有哪些设备 aplay -l device 号与类型
能写进 -D 的名字 aplay -L hw:、plughw:、default、别名
已注册的节点号 cat /proc/asound/devices 次设备号
卡号对应哪个模块 cat /proc/asound/modules 模块名
硬件层面有什么 lspci -nn、lsusb PCI/USB 描述符
当前流的真实参数 hw_params 率、格式、声道、buffer

混音服务这一层单独列：

bash
pactl list short sinks
pactl list short sources
wpctl status

五、播放音频：aplay 与 paplay #

两个命令的分岔点就是第一章那张图。aplay 说 ALSA 语言，paplay 说 PulseAudio 语言。

aplay 最小用法是 aplay test.wav，不带 -D 时用 default。要指定设备就把名字写进 -D：aplay -D hw:0,0 test.wav、aplay -D plughw:0,0 test.wav、aplay -D sysdefault:CARD=PCH test.wav。

WAV 以外的格式不支持，aplay 只吃 RIFF/WAVE 且必须带合法头。MP3 会报 audio open error: Invalid argument。

参数 作用
-D <name> 设备名
-l / -L 列播放设备 / 列全部 PCM 名
-f <fmt> 采样格式，如 S16_LE、S24_3LE、FLOAT_LE
-r <rate> 采样率
-c <n> 声道数
-t <type> 文件类型，raw 用于无头裸流
-d <n> 播 n 秒就停
-q / -v 静默 / 打印参数细节
-i 交互模式，读键盘改参数
--buffer-time=us 缓冲时长，微秒
--period-time=us 周期时长，微秒
-M / -N mmap 访问 / 非阻塞打开

WAV 里已写了率、格式、声道，正常不用手填。裸流必须全给：

bash
aplay -t raw -f S16_LE -r 48000 -c 2 -D hw:0,0 voice.pcm

参数写错的表现一一对应：

报错 原因 处理
audio open error: No such file or directory -D 名字不存在 aplay -L 核对
audio open error: Device or resource busy 设备被占 加 plughw 或走 pulse
Sample format non available 格式不支持 换 plughw:
Channels count non available 声道数不支持 换 plughw: 或改 -c
Invalid argument 率或格式不匹配 换 plughw:
underrun occurred 供数跟不上 加大 --buffer-time

speaker-test 是 ALSA 自带的测试音，确认左右声道接线对不对最直接：

bash
speaker-test -D plughw:0,0 -c 2 -t wav -l 1
speaker-test -D hw:0,0 -c 2 -t pink -l 0

-c 2 双声道轮流放人声报「left」「right」，-t sine 用正弦波，-t pink 是粉噪，-l 1 只跑一轮，-l 0 无限循环（Ctrl+C 停）。听不到就说明通道不通，别再纠结播放器。

paplay 走 PulseAudio 协议，不认 hw:0,0 这类 ALSA 名字。要指定出口用 --device，值必须是 sink 名：

bash
pactl list short sinks
paplay --device=alsa_output.pci-0000_00_1f.3.analog-stereo test.wav
paplay --raw --rate=48000 --format=s16le --channels=2 stream.pcm

sink 名格式是 alsa_output.<总线路径>.<profile>，analog-stereo 是模拟立体声，hdmi-stereo 是 HDMI，iec958-stereo 是光纤。格式支持比 aplay 宽：WAV、FLAC、Ogg Vorbis、MP3 都行，解码交给 libsndfile 和 gstreamer 插件，省掉一次转码。

参数 作用
--device=<sink> 指定出口 sink
--volume=<0..65536> 本次播放的音量，65536 是 100%
--channel-map=<map> 声道映射，如 front-left,front-right
--rate=<hz> / --format=<fmt> 重采样目标率 / 样本格式
--raw 读裸流，配合上一行参数用
-s <server> 指定服务器

两个命令怎么选：

场景 用哪个 理由
测硬件、测声道接线 aplay、speaker-test 绕开混音层，直击硬件
日常听歌、脚本提示音 paplay 不独占，能与其它程序共存
播放 FLAC/OGG paplay aplay 只认 WAV
需要 bit-perfect aplay -D hw: 不经过任何转换
桌面环境里 paplay 和音量控制、设备切换联动

用 system("play wind.mp3") 这类写法调外部播放器也能出声，但依赖 PATH 里的 play（来自 sox）或 mpg123，环境不干净时会静默失败。要可控就用上面两个命令，自己管参数和退出码。

gst-play-1.0 格式覆盖广：

bash
gst-play-1.0 wind.mp3
GST_AUDIO_SINK=alsasink gst-play-1.0 wind.mp3
GST_AUDIO_SINK=pulsesink gst-play-1.0 wind.mp3

它走 GStreamer 的 autoaudiosink，会自动挑一个可用 sink，PulseAudio 或 ALSA 直连都有。要固定出口就设 GST_AUDIO_SINK。

自己写程序时，Qt 这条路最短：.pro 里加 QT += multimedia，QSound::play("./wind.mp3") 一行出声。要控制进度、暂停、切流就用 QMediaPlayer，player->setMedia(QUrl::fromLocalFile(filePath)) 之后 player->play()。低延迟音效走 QSoundEffect，原始数据流走 QAudioOutput。它们底下仍然落在 ALSA 或 PulseAudio 上，设备选择还是本篇那套规则。

同一个播放器用 GStreamer 的 GstPlay 接口写，gst_play_new() 建实例，g_object_set 设 uri，gst_play_play() 起播，position-updated、state-changed、end-of-stream、error 这些信号驱动状态机，音量用 g_object_set 改 volume 属性（0.0 到 10.0）。命令行上对应 gst-play-1.0，参数是 --volume、--shuffle、--loop、--interactive、--playlist。

六、录制音频：arecord 与 parecord #

录制和播放是同一套接口的反方向，参数几乎对偶。录 5 秒 48k 双声道：

bash
arecord -D plughw:0,0 -f S16_LE -r 48000 -c 2 -d 5 out.wav
arecord -D plughw:0,0 -f S16_LE -r 48000 -c 2 -V stereo -d 5 test.wav

-d 5 是录 5 秒自动停，不加就等 Ctrl+C。列设备用 arecord -l 和 arecord -L。参数表与 aplay 一致，另有：

参数 作用
-V <mode> VU 表模式，stereo、mono、capture
-m 录成单声道
--max-file-time=<s> 到时切新文件

电平条一直不动，判断麦克风有没有信号：

电平条一直不动，说明采集端没信号：查麦克风静音开关、查 amixer 里的 Capture 增益、查那张卡的 pcm0c 选对没有。

USB 麦克风和板载模拟输入常是两张卡。arecord -l 里 card 1: Device [USB Audio Device] 就是 USB 那个，-D hw:1,0 指它。指错了录出来是静音而不是报错，这一点比播放更容易骗人。

录系统内部声音要先有 loopback：

bash
pactl load-module module-null-sink sink_name=virt
pactl list short sinks

virt 这个 null sink 是黑洞，把播放流指过去听不见但能录。要同时听和录，用 module-loopback 把 virt.monitor 接到真实 sink。

parecord 的 --device 要 source 名，用 pactl list short sources 查：

bash
parecord --device=alsa_input.pci-0000_00_1f.3.analog-stereo rec.wav
parecord --file-format=flac rec.flac

--channels、--rate、--format、--raw 与 paplay 对称，--latency-msec 控制块大小。

录完别直接信，用 soxi 或 file 看头对不对：

bash
file out.wav
soxi out.wav

soxi 打印声道、采样率、位深、时长。时长是 0、声道是 0，说明头写坏了，重录时把 -f、-c、-r 显式给全。

七、音量控制：alsamixer 与 amixer #

音量有三个层次：硬件增益（ALSA control）、混音服务的软件增益（sink volume）、应用自己的音量。任一为 0，你就听不见。

alsamixer 默认进第一个声卡，多卡用 alsamixer -c 1。界面键位：

键 作用
F1 / F2 帮助 / 系统信息
F3 / F4 播放界面 / 录制界面
F5 / F6 全部控件 / 选声卡
F7 / F9 减 / 加音量（也支持方向键）
M 静音切换
Esc / F10 退出

通道显示 MM 就是静音，00 是打开且为零，OO 是打开且非零。看到 MM 先按 M。alsamixer 改完立即写进声卡 control，不需要保存，重启也保留（由 alsactl 负责）。

amixer 是命令行版，适合脚本和 SSH：

bash
amixer scontrols
amixer sget Master
amixer sset Master 70%
amixer sset Master 10%+
amixer sset Master toggle
amixer sset Master unmute
amixer -c 1 sset Master 80%
pactl get-sink-volume @DEFAULT_SINK@
pactl set-sink-volume @DEFAULT_SINK@ +5%
pactl set-sink-mute @DEFAULT_SINK@ toggle
wpctl set-volume @DEFAULT_AUDIO_SINK@ 0.7
wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle

sset 的值写法：

写法 含义
70% 绝对百分比
10%+ / 10%- 在当前值上加 / 减 10%
toggle 静音开关
mute / unmute 直接静音 / 取消
65536 原始寄存器值，范围看 sget 输出

sget 的输出要会读：

text
Simple mixer control 'Master',0
  Capabilities: pvolume pswitch pswitch-joined
  Playback channels: Front Left - Front Right
  Limits: Playback 0 - 65536
  Front Left: Playback 65536 [100%] [0.00dB] [on]
  Front Right: Playback 65536 [100%] [0.00dB] [on]

Limits: 0 - 65536 是原始值范围，[100%] 是换算后的百分比，[on] 是开关状态。脚本判断有没有静音就看这个 [on]/[off]。

混音层的音量：

@DEFAULT_SINK@ 是占位符，等于当前默认 sink，也可以写具体名字或编号；PipeWire 上用 wpctl，音量是 0.0 到 1.0 的小数。

wpctl 的音量是 0.0 到 1.0 的小数，不是百分比，超过 1.0 会红字提示放大，别当错误。软件放大超过 100% 合法但会削顶失真。

层 工具 状态存在哪 影响谁
硬件增益 alsamixer、amixer 声卡寄存器，alsactl 落盘 所有流
混音服务 pactl、wpctl daemon 运行时 所有流
应用自身 播放器界面 应用进程 该应用

某一层静音了，别的层怎么加都没用。排查顺序：先 amixer sget Master 看 [on]，再 pactl get-sink-volume 看非 0，最后看应用里那条。

alsactl 管硬件混音状态的持久化：

bash
sudo alsactl store
sudo alsactl restore
systemctl status alsa-restore.service

状态文件在 /var/lib/alsa/asound.state。开机由 alsa-restore.service 或 alsa-state.service 调 alsactl restore 读回来。音量每次开机归零，就是这两个服务没跑。

amixer 底下是 ALSA 的 mixer API，自己写程序时按同一套顺序走：snd_mixer_open() 拿句柄，snd_mixer_attach() 接上卡（参数写 "default"），snd_mixer_selem_register() 注册，snd_mixer_load() 装载控件，然后 snd_mixer_selem_id_set_name() 指定 "Master"，snd_mixer_find_selem() 找到元素，snd_mixer_selem_get_playback_volume_range() 取到 min/max，最后 snd_mixer_selem_set_playback_volume_all() 按百分比换算写入，收尾 snd_mixer_close()。命令行的 amixer sset Master 70% 就是这条链的封装。

八、pactl：PulseAudio 的控制台 #

pactl 是这一层最实用的工具，PipeWire 上也能用，因为 pipewire-pulse 提供同一套协议。

bash
pactl info
pactl stat

info 给出 server 名、默认 sink/source、cookie 路径。stat 是统计：当前流数、内存块、采样缓存。排查「延迟突然变高」时 stat 里的 Sample Cache 有参考价值。

列对象都用 short 模式，只打编号、名字、驱动、状态四列，适合 grep 和脚本：

bash
pactl list short sinks
pactl list short sources
pactl list short sink-inputs
pactl list short source-outputs
pactl list short clients
pactl list short modules
pactl list short cards

去掉 short 是完整属性，含采样率、声道映射、延迟、profile。

对象 是什么 谁产生
sink 输出端，一个出口 声卡 profile、虚拟 sink
source 输入端，一个采集口 麦克风、monitor
sink-input 往 sink 里灌数据的流 每个在放声音的程序
source-output 从 source 取数据的流 每个在录声音的程序
card 声卡对象，管 profile module-alsa-card
module 已加载的模块 配置或 load-module

sink-input 是 pactl 最有用的能力：某个程序太吵不必全局调。

bash
pactl list short sink-inputs
pactl set-sink-input-volume 42 30%
pactl set-sink-input-mute 42 toggle
pactl move-sink-input 42 1
for i in $(pactl list short sink-inputs | cut -f1); do
  pactl set-sink-input-volume "$i" 50%
done

编号 42 来自 sink-inputs 的第一列。程序重启编号就变，脚本里要重新查；上面那段 for 把所有流的音量统一压一半。

一张声卡有多个 profile，模拟输出和 HDMI 输出就是不同 profile：

bash
pactl list short cards
pactl list cards | grep -A2 'Profiles:'
pactl set-card-profile 0 output:hdmi-stereo
pactl set-card-profile 0 output:analog-stereo+input:analog-stereo

profile 名带 + 的是输入输出组合。切换 profile 会重建 sink，正在播的流会被打断。

bash
pactl load-module module-null-sink sink_name=test
pactl unload-module 12
pactl load-module module-combine-sink sink_name=both slaves=alsa_output.pci-0000_00_1f.3.analog-stereo,alsa_output.pci-0000_00_1f.3.hdmi-stereo

load-module 返回模块编号，unload-module 用它卸载。重启 daemon 后手动加载的模块全部消失，要持久化就写进 default.pa 或 ~/.config/pulse/default.pa。

模块 作用
module-null-sink 虚拟输出，只进不出
module-loopback 把一路流接到另一处
module-echo-cancel 回声消除，会议场景
module-bluetooth-discover 发现蓝牙设备
module-remap-sink 虚拟重映射 sink
module-combine-sink 多出口同时出声
module-stream-restore 记忆每应用的音量与设备

slaves 里的名字来自 pactl list short sinks。两个出口采样率不同时，module-combine-sink 按主 sink 的率重采样，另一个出口容易出杂音。

bash
pactl set-sink-mute @DEFAULT_SINK@ 1
pactl suspend-sink @DEFAULT_SINK@ 1
pactl set-source-mute @DEFAULT_SOURCE@ 1
pactl play-sample bell
pactl subscribe

text
Event 'change' on sink #0
Event 'new' on sink-input #57
Event 'remove' on sink-input #57

pactl subscribe 持续打印事件流，插拔设备、切 profile、流进出都会打一行，调脚本时开着它就能看到状态变化的时间点。

九、输出设备的切换 #

换出口按层次分三种：改混音服务的默认 sink、把单个流搬过去、绕开服务直接指定 ALSA 设备。

bash
pactl list short sinks
pactl set-default-sink alsa_output.pci-0000_00_1f.3.hdmi-stereo
for i in $(pactl list short sink-inputs | cut -f1); do
  pactl move-sink-input "$i" alsa_output.pci-0000_00_1f.3.hdmi-stereo
done
wpctl status
wpctl set-default 42

改完对新的流生效，已在播的流不会自动搬，move-sink-input 那段就是补这一步，它的第二个参数可以是 sink 名也可以是编号。wpctl set-default 接节点编号，wpctl inspect 42 能看完整属性。

set-default 接的是节点编号，来自 wpctl status 里 sink 前面的数字。wpctl inspect 42 能看完整属性。

不走混音服务时，切换就是改 -D：

bash
aplay -D hw:1,0 music.wav
aplay -D hw:0,3 music.wav

hw:0,3 和 hw:0,0 常常是同一张卡的不同设备：前者 HDMI，后者模拟。这就是 aplay -l 里一张卡出现好几行的原因。

sink 都带一个 .monitor source，抓的是这个 sink 正在播的内容：

bash
pactl list short sources | grep monitor
parecord --device=alsa_output.pci-0000_00_1f.3.analog-stereo.monitor cap.wav

录屏配音、录会议声音都靠它。module-null-sink 造出来的 sink 同样有 monitor。

现象 原因 处理
切了默认 sink 还是从旧设备出声 旧流没搬 move-sink-input 逐个搬
切到 HDMI 没声音 口没接显示器，或显示器没喇叭 换回模拟；查该 sink 是否 SUSPENDED
切 profile 后所有程序断音 profile 重建了 sink 正常，重播即可
蓝牙切过去又跳回 链路断开自动回退 查 bluetoothctl 连接状态
新 sink 名字太长记不住 名字含 PCI 路径 用编号代替

十、默认设备怎么定 #

「默认」在三个地方各有一份定义，优先级不同。

层 存在哪 谁读它
内核/驱动 snd_hda_intel 的 index= 参数 ALSA，决定卡号
ALSA 配置 /etc/asound.conf、~/.asoundrc 的 pcm.!default 所有 ALSA 程序
混音服务 pactl set-default-sink 后写进 daemon 状态 PulseAudio/PipeWire 客户端

多张卡时卡号由加载顺序决定，重启后会变。hw:0 今天指板载、明天指 USB，脚本就崩了。两种稳法：用 id 代替编号，或把卡号钉死。id 来自 /proc/asound/cards 的方括号，aplay -D hw:PCH test.wav、aplay -D hw:Device test.wav 都指向固定的卡。钉死卡号写模块参数：

text
options snd_hda_intel index=0
options snd_usb_audio index=1

放 /etc/modprobe.d/snd.conf，改完 sudo update-initramfs -u 重启生效。

ALSA 的 default 系统级写 /etc/asound.conf，个人级写 ~/.asoundrc，后者优先。指到具体硬件：

text
# 指到具体硬件
pcm.!default {
    type hw
    card PCH
    device 0
}
ctl.!default {
    type hw
    card PCH
}

# 指到混音服务
pcm.!default {
    type pulse
}
ctl.!default {
    type pulse
}

# 指到软件混音
pcm.!default {
    type plug
    slave.pcm "dmix"
}

type pulse 需要 alsa-plugins-pulse（Debian/Ubuntu）或 alsa-plugins-pulseaudio（Fedora），插件缺失时报 Unknown PCM pulse。

混音服务的默认由 pactl set-default-sink 定，之后由 module-stream-restore 记住，重启 daemon 恢复。要一开机就是某个 sink，在 default.pa 末尾追加：

text
set-default-sink alsa_output.pci-0000_00_1f.3.analog-stereo
set-default-source alsa_input.pci-0000_00_1f.3.analog-stereo

PipeWire 上对应 ~/.config/pipewire/pipewire-pulse.conf.d/ 下的片段，或者用 WirePlumber 规则按设备属性设默认。

一个 ALSA 程序打开 default 时，发生的是：读 ~/.asoundrc → 没有就读 /etc/asound.conf → 都没有就用内置的 hw:0,0。如果配置写的是 type pulse，请求被转给混音服务，再由服务按它自己的默认 sink 决定落到哪张卡。所以「改了 pactl set-default-sink，aplay 还从旧设备出声」是正常现象：aplay 走的是 hw: 或配置里的固定设备，它根本不问混音服务。

十一、音频格式与采样率 #

格式和采样率对不上，是「有声音但难听」和「直接报错」的分界线。

参数 含义 常见值
采样率 每秒采多少个点 8000、16000、44100、48000、96000、192000
位深 每个点用几位存 8、16、24、32
声道 几路 1 单声道、2 立体声、6/8 环绕
编码 数据怎么排 PCM 裸流、S16_LE、S24_3LE、FLOAT_LE

ALSA 的格式名带字节序。S16_LE 是有符号 16 位小端，S16_BE 是大端，S24_3LE 是 24 位打包在 3 字节里，S32_LE 是 32 位容器，FLOAT_LE 是 32 位浮点，U8 是无符号 8 位。x86 和 ARM 小端机上 _LE 是常态，写 S16 也能解析成 S16_LE。

场景 率 位深 声道
电话语音 8000 16 1
语音识别输入 16000 16 1
CD 音质 44100 16 2
桌面默认 48000 16 或 24 2
高解析 96000 或 192000 24 或 32 2
蓝光环绕 48000 24 6 或 8

语音场景压到 8000 Hz 单声道，是为了文件小、传输省。用 ffmpeg 转，-acodec pcm_s16le 是 16 位 PCM 编码器，-ac 1 单声道，-ar 8000 采样率 8000 Hz：

bash
ffmpeg -i input.mp3 -acodec pcm_s16le -ac 1 -ar 8000 output.wav
ffmpeg -i input.m4a -acodec pcm_s16le -ac 1 -ar 8000 output.wav
ffmpeg -i input.wav -f s16le -ar 8000 -acodec pcm_s16le output.raw
ffmpeg -f s16le -ar 8000 -ac 1 -acodec pcm_s16le -i input.raw output.wav

-f s16le 指定容器为裸 16 位小端 PCM，没有头。裸流播放必须自己补齐参数：

bash
aplay -t raw -f S16_LE -r 8000 -c 1 output.raw

少了 -t raw，aplay 会把它当 WAV 去读 RIFF 头，报 Invalid argument。

看文件的真实参数：

bash
soxi input.wav
file input.wav
ffprobe -v error -show_entries stream=codec_name,sample_rate,channels,bits_per_sample -of default=nw=1 input.wav

plughw: 和混音服务都会自动重采样。44.1k 到 48k 的转换在音质上有代价，做测量时用 hw: 直通，避免转换污染。让 PipeWire 固定工作率：

bash
pw-metadata -n settings 0 clock.force-rate 48000

ALSA 直连时想指定重采样目标，用 plug 插件的 slave 参数：

text
pcm.!default {
    type plug
    slave.pcm "hw:0,0"
    slave.rate 48000
}
报错 含义
Sample format non available 声卡不吃这个格式
Sample rate non available 声卡不吃这个率
Channels count non available 声道数不支持
Invalid argument 参数组合非法，或裸流没给 -t raw
File format not recognized 头坏了，或 -t 给错

前三条换成 plughw: 或 default 就能过。第四条多半是裸流没给 -t raw。第五条检查文件本身。

十二、多声道与环绕 #

双声道之外最常见的是 5.1 和 7.1，走 HDMI 或 S/PDIF。

ALSA 的 5.1 顺序是 FL FR RL RR FC LFE，PulseAudio 的映射名对应 front-left,front-right,rear-left,rear-right,front-center,lfe。顺序错了会听到人声从后面出来。

bash
aplay -D hw:0,3 -c 6 -f S16_LE -r 48000 surround.wav
speaker-test -D hw:0,3 -c 6 -t wav -l 1

speaker-test 逐声道报位置是确认顺序最快的办法，依次说 front left、front right、rear left、rear right、front center、lfe。哪个方向听错就是接线或映射错了。

aplay -L 里的环绕名字是成系列的：

名字 声道
surround40:CARD=X,DEV=0 4.0
surround41:CARD=X,DEV=0 4.1
surround50:CARD=X,DEV=0 5.0
surround51:CARD=X,DEV=0 5.1
surround71:CARD=X,DEV=0 7.1

用这些名字时声道数已定，不要再给 -c，给错会冲突。

想让功放自己解码 Dolby/DTS，得走 passthrough 而不是 PCM 解码：

bash
aplay -D hdmi:CARD=HDMI,DEV=0 -f S16_LE --channels=2 ac3.spdif
pactl set-card-profile 1 output:iec958-stereo
cat /proc/asound/card0/pcm3p/sub0/hw_params
speaker-test -D plughw:0,3 -c 2 -t sine -l 1 -s 1
speaker-test -D plughw:0,3 -c 2 -t sine -l 1 -s 2

iec958 就是 S/PDIF 的数字输出格式，光纤和同轴都走它。

播多声道没声音，先看硬件吃几声道。channels: 2 说明这个 PCM 只开了双声道，多声道数据会被拒或截断。HDMI 的 PCM 设备按 sink 的 EDID 能力协商，显示器只报双声道时就只能双声道。单声道逐个测比放音乐管用，-s N 指定只测第 N 个声道。

十三、蓝牙音频 #

蓝牙音频在用户态有两个阶段：链路层由 BlueZ 管，音频路由由混音服务管。两边都不通就没声音。

text
$ bluetoothctl
power on
agent on
default-agent
scan on
pair AA:BB:CC:DD:EE:FF
trust AA:BB:CC:DD:EE:FF
connect AA:BB:CC:DD:EE:FF
$ bluetoothctl connect AA:BB:CC:DD:EE:FF
$ bluetoothctl info AA:BB:CC:DD:EE:FF
$ bluetoothctl devices Connected

trust 不能省。不信任的设备重连时会被拒绝，表现为「刚连上就断」。交互式连着敲、非交互一次性连，两种都在上面。

info 里的 Connected: yes 才是真连上，Paired: yes 只表示配对过。

蓝牙音频有三个 profile，音质和延迟正好相反：

profile 编码 音质 延迟 麦克风
HFP/HSP mSBC、CVSD 电话级，8k 或 16k 低 可用
A2DP SBC SBC 中等 中 不可用
A2DP AAC/aptX/LDAC 厂商编码 高 中到高 不可用

开会议软件时系统会自动从 A2DP 切到 HFP，因为 A2DP 不支持麦克风。切过去瞬间音质塌成电话音就是这个原因。会议结束不会自动切回，要手动：

bash
pactl list short cards | grep bluez
pactl list cards | grep -A30 bluez_card
pactl set-card-profile bluez_card.AA_BB_CC_DD_EE_FF a2dp-sink
pactl set-default-sink bluez_sink.AA_BB_CC_DD_EE_FF.a2dp_sink
pactl list short sinks | grep bluez

profile 名里的地址用下划线替换冒号。完整列表里 a2dp-sink、a2dp-sink-sbc、headset-head-unit 这些就是可选项。

sink 名和 card 名不同：card 是 bluez_card.<addr>，sink 是 bluez_sink.<addr>.<profile>。

现象 原因 处理
连上没声音 默认 sink 没切 pactl set-default-sink bluez_sink...
音质是电话音 落在 HFP profile 切 a2dp-sink
播放断续 2.4G 干扰、距离远 靠近，关掉同频 WiFi 的 2.4G
一配对就断 没 trust bluetoothctl trust <addr>
有设备没 sink 缺 module-bluetooth-discover pactl load-module module-bluetooth-discover
PipeWire 上蓝牙不工作 缺 libspa-0.2-bluetooth 装上并重启 wireplumber
麦克风不出声 A2DP 不支持麦克风 切 HFP/HSP profile

蓝牙服务本身没跑，先看：

bash
systemctl status bluetooth
rfkill list bluetooth

rfkill 里 Soft blocked: yes 就是被软件关了，rfkill unblock bluetooth 打开。

十四、常见故障与现象 #

故障排查按层往下走，不要跳步。每层先确认「系统看到的东西」，再谈参数。

完全没有声音，按顺序走：

bash
cat /proc/asound/cards
aplay -l
amixer sget Master
pactl info
pactl list short sinks
哪一步空 说明 下一步
cards 空 内核没认到声卡 lsmod、dmesg、lspci -nn
aplay -l 空但 cards 有 只有录制设备，或驱动异常 dmesg 看 probe 失败
sget 是 [off] 硬件静音 amixer sset Master unmute
pactl info 失败 混音服务没跑 systemctl --user status

有设备但打不开：

bash
fuser -v /dev/snd/pcmC0D0p
lsof /dev/snd/*

Device or resource busy 用 fuser 直接列出占用的 PID，杀掉或让它播完。另一个办法是绕到 dmix 或 pulse，让 ALSA 自己混音。

Permission denied 是当前用户不在 audio 组：

bash
id
sudo usermod -aG audio $USER

改完要重新登录才生效，newgrp audio 只在当前 shell 临时生效。

现象 常见原因 处理
每几秒卡一下 缓冲太小，调度抖动 加大 --buffer-time
负载高时爆音 实时优先级不足 检查 rtkit、pipewire 的 rt 权限
一直有底噪 模拟口增益过高 降 Master，用数字音量补
只有一边有声 声道映射或接线 speaker-test 逐声道测
开机后音量归零 alsa-restore 没跑 systemctl status alsa-restore

underrun occurred 是播放侧供数不足：

bash
aplay -D hw:0,0 --buffer-time=500000 test.wav

--buffer-time 单位微秒，500000 是 0.5 秒。缓冲越大越不容易断，代价是延迟变高。

报错 层 处理
audio open error: No such file or directory 设备名 aplay -L 核对名字
Unknown PCM pulse 插件缺失 装 alsa-plugins-pulse
Sample format non available 格式 换 plughw:
Channels count non available 声道 换 plughw: 或改 -c
Invalid argument 组合非法 换 plughw:，裸流补 -t raw
File format not recognized 文件 用 soxi 验证头

混音服务连不上：

bash
echo $XDG_RUNTIME_DIR
ls -l /run/user/$(id -u)/pulse/
pactl info

XDG_RUNTIME_DIR 空，或者目录里没有 native，就是服务没起或环境不对。SSH 里手动补：

bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
export DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus
systemctl --user start pipewire pipewire-pulse

systemctl --user 报 Failed to connect to bus 是缺 DBUS_SESSION_BUS_ADDRESS，补上就好。

只有某个程序没声音，先用 pactl list short sink-inputs 看它有没有流。没流说明它没在播或静音在应用侧；有流但听不见，单独看它的音量与静音：

bash
pactl list sink-inputs | grep -A5 'Sink Input #57'
pactl set-sink-input-volume 57 100%
pactl set-sink-input-mute 57 0
pactl move-sink-input 57 @DEFAULT_SINK@

流跑到错误的 sink 上（比如 null sink）就搬回来。浏览器和 Electron 应用常见这个问题：它们自己记了上次的设备名，设备不在了就落到 null sink 上静默丢音。

以上都排完还不行，把范围压到硬件：

bash
speaker-test -D plughw:0,0 -c 2 -t sine -l 1

能响说明软件栈没问题，问题在具体应用或混音配置。不响就换耳机孔、换 HDMI 口、换 USB 声卡，逐项排除。

alsamixer 里 F6 换卡，看有没有被隐藏的 Auto-Mute、Loopback Mixing、Headphone 开关。Auto-Mute Mode 打开时插耳机自动静音箱，这是设计行为不是故障。

十五、易错点速查 #

易错点 正确做法
以为 aplay 和 paplay 看同一份设备 aplay 走 ALSA，paplay 走混音服务，两套清单
用 hw:0,0 播任意格式 参数不确定就用 plughw:0,0
以为 default 就是硬件 default 是配置里的名字，指向 hw:、dmix 或 pulse
-D default 与 -D sysdefault 混用 default 走配置，sysdefault 绕过配置直达卡
多个程序抢 hw: 用混音服务，或配 dmix
用 sudo 跑 pactl 混音服务是每用户的，用当前用户跑
SSH 里直接 pactl 先补 XDG_RUNTIME_DIR 和 DBUS_SESSION_BUS_ADDRESS
改默认 sink 就以为所有程序跟着换 已存在的流要 move-sink-input
用固定卡号写脚本 用 hw:PCH 这类 id，或钉死 index=
以为 alsamixer 和 pactl 调同一个音量 硬件增益和软件增益分层，各自独立
以为 aplay 能播 MP3 只认 WAV，其它格式用 paplay 或先转
裸流不写 -t raw 必写，否则被当 WAV 解析头
蓝牙切到 HFP 后不切回 手动 set-card-profile ... a2dp-sink
只 pair 不 trust 蓝牙会反复断
以为 Subdevices: 1/1 能并发 那是独占，第二条流会 busy
wpctl 音量写 70 它要 0.0~1.0 的小数，写 0.7
多声道用 surround51: 又给 -c 名字已定声道，-c 会冲突
音量超 100% 当正常 软件放大会削顶，破音
不看 hw_params 就猜参数 放音时读它，硬件真实参数在里面
录完不验文件 soxi 看率、声道、时长
