为什么需要量化交易 #

量化交易比传统交易强多少？一句话：它能让你的交易效率提高百倍。量化交易之于传统交易方法，如同大型收割机之于锄头镰刀，机枪大炮之于刀剑棍棒。

也就是说，传统交易方法是这样的：一个人盯着屏幕，靠经验、靠盘感、靠手工记录，一只一只地翻股票，一笔一笔地手动下单。

而量化交易是这样的：你把自己的交易想法翻译成一段程序，交给计算机，计算机以人类不可能达到的速度，同时盯着全市场几千只股票，条件一满足就自动下单。

在金融最为发达的美国，量化交易已大行其道，占据了 70% 以上的股市成交量。可以说量化交易是未来的趋势。当然，只言片语不能解释清楚，接下来我们具体地介绍下量化交易。

需要提前说明的是，"效率高"不等于"一定赚钱"。计算机只是把你脑子里的逻辑执行得更快、更不知疲倦、更不带情绪，如果你的逻辑本身是错的，它只会让你错得更快。所以本连载后半程会花很多篇幅讲怎么评价一个策略、怎么识别一个"看起来很美"的假策略。

量化交易是做什么的 #

量化交易是指借助现代统计学和数学的方法，利用计算机技术来进行交易的证券投资方式。便于理解地说，量化交易主要是做这样的事：

  • 从一个灵感开始。
  • 把灵感细化成明确的可执行的交易策略。
  • 把策略转成程序。
  • 检验策略效果。
  • 根据结果改进，回到第一步。

下面逐步展开。

从一个灵感开始 #

灵感就是指那些你想验证的、可能会盈利的方法，比如「银行股可能是良好的投资品种」「一旦跨过 20 日均线后股价会继续涨」「流传许久的羊驼交易法」等等。灵感获取的方式可以是阅读、听人说、自己悟等等。

这里我们以一个简单的情况为例进行讲解。比如你的灵感是这样的：

  • 如果股价显著低于近几日的平均价，则买入。
  • 如果股价显著高于近几日的平均价，则卖出。

现在，你想知道这样操作究竟会不会赚钱？

注意这个问题的形态：它是一个可以被历史数据检验的问题。这正是量化交易的起点——灵感必须能被表述成"如果……则……"的形式，才有可能被验证。凡是无法表述成明确条件的想法，比如「这家公司很有前景」，都不能直接回测，只能先拆解。

把灵感细化成明确的可执行的交易策略 #

一般灵感都很模糊，需要将其细化成明确的可执行的策略，目的是为了能得到确定的结果，以及为后续程序化做准备。比如，你通过阅读了解到索罗斯的反身性概念，想将它应用到股市，这个反身性就很模糊，就需要明确什么条件下买卖、买卖什么品种、买卖多少量等，从而形成一个明确的交易策略，让不同人根据你的描述在相同情形下都能做出相同的操作。

"不同人根据你的描述在相同情形下都能做出相同的操作"是判断策略是否足够明确的黄金标准。如果两个人拿着同一份策略描述，在同一根 K 线上做出了不同动作，说明描述里还有模糊地带。

继续以之前那个关于平均价的灵感为例：

  • 如果股价显著低于近几日的平均价，则买入。
  • 如果股价显著高于近几日的平均价，则卖出。

显然它是不够明确的。比如多低叫显著低于？多高叫显著高于？近几日究竟是几日？买入卖出是买卖多少？我们把它细化：

  • 如果股价低于近 20 日平均价 10%，则用全部可用资金买入。
  • 如果股价高于近 20 日平均价 10%，则卖出全部所持的该股票。

还有一点不明确的地方，买卖哪个股票呢？我们认为这个交易方法盈利与否应该跟交易哪个股票关系不大，但 ST 股票除外（知道 ST 股票是一类风险特别大的股票就好，详情请自行搜索），所以股票的选择范围是除 ST 股外的国内 A 股的所有股票。所以我们进一步细化：

  • 每个交易日监测除 ST 股外的国内 A 股的所有股票的股价。
  • 如果股价低于近 20 日平均价 10%，则用全部可用资金买入该股票。
  • 如果股价高于近 20 日平均价 10%，则卖出全部所持有的该股票。

现在我们基本已经把之前的灵感细化成明确的可执行的交易策略。当然，可能还有些地方不够明确，也可能有些细节还不确定要改动，这些可以随时想到随时再改，不必一次做到完美。

值得留意的是，上面这个细化过程实际上同时补充了四个维度：买入条件、卖出条件、标的范围、下单数量。任何完整的策略都必须把这四件事说清楚，缺一项就无法回测。

把策略转成程序 #

就是把明确后的策略通过编程转成程序，好让计算机能根据历史数据模拟执行该策略，以及能根据实际行情进行反应并模拟交易或真实交易。

简言之，就是把刚刚的策略翻译成计算机可识别的代码语言，即把这个：

  • 每个交易日监测除 ST 股外的国内 A 股的所有股票的股价。
  • 如果股价低于近 20 日平均价 10%，则用全部可用资金买入该股票。
  • 如果股价高于近 20 日平均价 10%，则卖出全部所持有的该股票。

写成类似这样的代码（下面的代码并不完全符合，只是展示下大概的样子）：

python
def initialize(context):
    g.security = ['002043.XSHE', '002582.XSHE']


def handle_data(context, data):
    for i in g.security:
        last_price = data[i].close
        average_price = data[i].mavg(20, 'close')
        cash = context.portfolio.cash
        if last_price > average_price:
            order_value(i, cash)
        elif last_price < average_price:
            order_target(i, 0)

这样一来，就把刚才细化好的策略转成了代码程序，计算机就能运行了。这个过程你可以理解成用计算机能听懂的语言（代码），把你的策略告诉给计算机了。

检验策略效果 #

现在计算机理解了你的策略，你可以借助计算机的力量来验证你的策略了。基本的检验策略方法有回测和模拟交易两种方法。

回测是让计算机根据一段时间的历史数据模拟执行该策略，根据结果评价并改进策略。继续之前那个均价策略的例子：

设定初始的虚拟资产比如 500000 元、一个时期比如 20060101 到 20160101，把这一时期的各种数据如股票股价行情等发给计算机，计算机会利用这些数据模仿真实的市场，执行你刚才告诉它的策略程序。最后计算机会给你一份报告，根据这个报告你就会知道，在 20060101 的 500000 元，按照你的策略交易到 20160101，会怎样？一般包括盈亏情况、下单情况、持仓变化，以及一些统计指标等，从而你能据此评估交易策略的好坏。

如果结果不好，则需要分析原因并改进。如果结果不错，则可以考虑用模拟交易进一步验证。

模拟交易是让计算机根据实际行情模拟执行该策略一段时间，根据结果评价并改进策略。与回测不同，回测是用历史数据模拟，模拟交易是用实际的实时行情来模拟执行策略的。举例就是这样：

设定初始的虚拟资产比如 500000 元，选择开始执行模拟交易的时间点，比如明天。那么从明天开始，股市开始交易，真实的行情数据就会实时地发送到计算机，计算机会利用真实的数据模仿真实的市场，执行你的策略程序。同时，你会得到一份实时更新的报告。这报告类似于回测得到的报告，不同的是会根据实际行情变化更新。同样你能据此评估交易策略的好坏。

可见，回测是用历史数据模拟执行策略，模拟交易是用未来的实际行情模拟执行策略。

这两者的关系很关键：回测速度快、样本长，但你总能（有意或无意地）挑到一段"恰好表现好"的历史；模拟交易慢、样本短，但它在时间上是"往前走"的，不会偷看未来。所以标准做法是先用回测筛选，再用模拟交易验证。

量化交易的价值何在 #

量化交易的价值有很多，只提下最突出的几点。

可以利用大量历史数据检验策略，效率提升百倍 #

当我们想验证交易策略的时候，一个基本的想法是想知道它在历史上表现如何，这往往需要大量的历史数据与计算量。量化交易做一次回测可能几分钟就可以得到结果了，相比于传统人工做法，效率的提升是成百倍的。

更科学更客观地衡量交易策略的效果 #

比如一个关于某技术指标的策略，人工进行了 10 个交易日的验证，效果都不错，但这就能说明这指标不错吗？不，10 次太少了，你需要更多的验证，比如 1000 个交易日，人工验证不可行，量化交易则又快又准。而且量化交易还可以利用数学与统计学自动给出客观的结果，比如年化收益率、最大回撤率、夏普比率等。

这三类指标的具体含义会在第 9 篇详细讲，现在只需要知道：判断策略好坏不能只看赚了多少，还要看承担了多大风险、样本够不够多。

全市场实时捕捉交易机会 #

当你知道一个盈利条件，当股价一旦满足这条件，你就可以操作盈利。问题是，市场几千个股票，股价时时刻刻都在变动，你能盯住几个，你会错失多少个机会。但量化交易可以利用计算机全市场实时盯盘，可以不错过任何交易机会，加倍你的盈利能力。

更多的盈利机会 #

量化交易可以利用计算机对海量数据分析得到常人难以发现的盈利机会，而且有些机会只有量化交易才能利用。比如你发现一种交易方法，其特点是盈亏的额度相等，但盈利的概率是 55%，亏损概率 45%。首先这种小差距的概率规律，非量化交易不能发现；其次，要利用这个规律盈利需要大量次数的交易才能稳定盈利，这也非量化交易不可。

这个例子的启发是：优势可以非常小，小的优势只有靠大的样本量才能兑现。这也是为什么后文会反复强调"交易次数"这个指标。

做量化交易需要什么 #

通常一个投资者做量化交易所需要做的准备，就如同让一个农民自己去造一个大型收割机，而且还是从挖矿开始做起，极度困难。所以量化交易最初在金融与科技最为发达的美国由少数顶级精英发起。

要有各种数据 #

要有能方便使用的各种投资相关的数据。这要考虑到各种数据的收集、存储、清洗、更新，以及数据取用时的便捷、速度、稳定。

还要有一套量化交易的系统 #

要有能编写策略、执行策略、评测策略的系统。这要考虑到系统对各种策略编写的支持、系统进行回测与模拟的高仿真、系统执行策略的高速、系统评测策略的科学可靠全面。

可能有人会问，做投资之前难道要学当程序员吗？曾经是，但现在量化交易的门槛已大大降低。

三个常见误解 #

在进入技术细节之前，先把三个最常见的误解清掉。它们不影响你读后面的代码，但会影响你读后面代码时的心态。

误解一：量化交易等于高频交易 #

不是。高频交易只是量化交易里极小的一个分支，它拼的是硬件、网络延迟与撮合速度，门槛高到绝大多数机构都玩不起。本教程讲的策略，交易频率从每天一次到每月一次不等，靠的是"逻辑上有优势"而不是"手速更快"。

这个区分很重要，因为它决定了你该往哪个方向努力。如果量化是比快，那你就该去优化代码执行效率；而实际上对本教程的读者来说，比的是想法是否成立、检验是否诚实。

误解二：有了好策略就能一直赚钱 #

第 1 篇后面就会提到，策略是有时效的。市场环境变了、参与的人多了、制度调整了，原本有效的策略会失效。所以真实的工作不是"找到一个策略然后躺平"，而是"持续地发现、验证、淘汰策略"。

换句话说，你要建的是一条能不断产出策略的流水线，而不是一个策略本身。

误解三：需要很强的数学和编程才能开始 #

本教程就是反例。你会用到的编程知识，讲完只需要六七篇的篇幅；你会用到的数学，主要是加减乘除、百分比、平均值的概念。真正难的不是这些工具，而是把一个模糊想法变成可检验的假设——这个能力跟数学水平关系不大，跟思维的严谨程度关系很大。

当然，往后走，数学与编程的天花板确实存在。但那是"入门之后"的问题，不该成为"不开始"的理由。

这条连载该怎么读 #

最后交代一下阅读方式，能让这十篇发挥更大作用。

第一，按顺序读。 这十篇是有依赖关系的：第 3 到第 6 篇讲语言，第 7 篇讲数据，第 8 篇把前面全部合起来用。跳着读会在第 8 篇卡住。

第二，每篇都要动手。 代码是"看会"不了的，只能"写会"。每篇的自测题不是装饰，是这篇有没有学会的检验。

第三，允许自己看不懂。 第 2 篇那个完整策略，当时就明确说了"不要求逐行理解"。这是有意设计的：先建立整体印象，再逐步填充细节。所以第一次读到不懂的地方，标记一下继续往下读，往往读到后面对应篇章时就自然懂了。

第四，把报错当作路标。 第 2 篇会专门讲怎么读报错。整个连载里，报错信息出现的频率大概和你写代码的频率一样高。习惯它，甚至依赖它——报错是计算机在告诉你哪里想错了，这是它对你最诚实的时刻。
