起点 #

我们继续以如下这个简单的策略为例进行学习在策略中操作多个股票。

python
def initialize(context):
    run_daily(period, time='every_bar')
    g.security = '000001.XSHE'


def period(context):
    order(g.security, 100)

用 list 数据类型存储多个股票 #

事实上，根据前面的所学我们是可以写多个股票的策略的，无非是把原来单个股票的操作类似地再写几遍，比如下面这个策略就在操作两个股票。

python
def initialize(context):
    run_daily(period, time='every_bar')
    g.security1 = '000001.XSHE'
    g.security2 = '000002.XSHE'


def period(context):
    order(g.security1, 100)
    order(g.security2, 100)

显然的问题是，当股票比较多的时候，就要写很多遍，这样的写法就会很麻烦，看着也会比较乱。因此我们要学习其他的写法。首先我们先学习用 list 数据类型存储多个股票，如下：

python
def initialize(context):
    run_daily(period, time='every_bar')
    # 把两个股票代码作为 list 存入 g.security 中
    g.security = ['000001.XSHE', '000002.XSHE']

list 数据类型的用法前文有讲过，特点是各个元素用逗号隔开后，用中括号把所有元素包起来，比较简单，有疑问不妨去回顾下。接下来是重点内容——循环语句，用它可以方便地批量操作多个股票。

循环语句 #

for 循环可以遍历任何序列的项目，比如一个 list，一般用法如下：

python
# 含义是依次把序列中的元素赋值给 for 后的变量，并执行循环语句
for 变量 in 一个序列:
    要循环的语句，也叫循环体

说起来略复杂，其实不难，来看个使用 for 的例子：

python
for k in ['大卫', '查理曼', '凯撒', '亚历山大']:
    print(k)

# 执行后日志如下:
# 大卫
# 查理曼
# 凯撒
# 亚历山大

# 可见，for 语句的运行过程是：取出 list 中第一个元素'大卫'并将其赋值给 k，
# 然后执行 print(k) 即在日志中打印 k，此时 k 中是'大卫'；
# 之后，取出 list 中第二个元素'查理曼'并将其赋值给 k，然后执行 print(k)，
# 此时 k 中是'查理曼'；以此类推，直到'亚历山大'被打印。

用 for 语句时有一个常见一起使用的语句 range()，它的功能是生成等差数列的，用法如下：

python
range(首项, 上限, 步长)

# 首项 就是这个数列的第一项，可省略，省略后默认为 0
# 步长 就是数列的公差、间隔，可省略，省略后默认为 1
# 上限 是用来限制数列长度的，即数列不得大于或等于上限。不可省略。
# 另外，Python2 中 range 产生的是 list，但 Python3 中产生的不是 list，
# 但可以用 list() 这个语句把结果转成 list 类型，比如 list(range(1,7,2))。
# 我们策略编辑环境是 Python2。

# 一个例子
for j in range(1, 7, 2):
    print(j)
print(range(1, 7, 2))

# 执行后日志如下:
# 1
# 3
# 5
# [1, 3, 5]

这里最容易错的地方是"上限取不到"：range(1, 7, 2) 生成的是 1、3、5，不含 7。所以"循环 4 次"要写 range(4)（生成 0、1、2、3），而不是 range(1, 4)（只生成 1、2、3，只有 3 次）。

continue 与 break 是重要的修饰循环执行流程的语句，用法如下：

python
# break 的作用是写在循环体中用来跳出当前的整个循环过程
# continue 的作用是写在循环体中用来跳出当前的这一次的循环过程
# 通过一个例子应该就能明白两者的作用与区别

# 一个简单的循环例子
for t in range(4):
    print(t)

# 执行的结果是
# 0
# 1
# 2
# 3

# 在例子中使用 break。可以看到当循环到 2 的时候，打印 omg 后，执行 break，
# 终止了整个循环过程，不再继续循环 3 了，所以 omg 后就什么都没了。
for t in range(4):
    if t == 2:
        print('omg')
        break
    print(t)

# 执行的结果是
# 0
# 1
# omg

# 在例子中使用 continue。可以看到当循环到 2 的时候，打印 omg 后，执行 continue，
# 跳过了当前正循环的 t 为 2 这个循环过程的余下部分，不再继续执行之后的语句
# （即 print(t)，此时 t 等于 2），而继续循环 3 了，所以 omg 后有打印 3。
for t in range(4):
    if t == 2:
        print('omg')
        continue
    print(t)

# 执行的结果是
# 0
# 1
# omg
# 3

写一个简单多股票策略 #

用刚学的知识把之前简单的策略例子改写成多股票版本，如下。

python
def initialize(context):
    run_daily(period, time='every_bar')
    # 把两个股票代码作为 list 存入 g.security 中
    g.security = ['000001.XSHE', '000002.XSHE']


def period(context):
    # 每个股票买 100 股
    for stk in g.security:
        order(stk, 100)

注意 for stk in g.security: 这一行里，stk 是一个临时变量名，它在每一轮循环里被赋成 list 中的下一个股票代码。名字可以随便起（叫 s、叫 code 都行），但起一个有含义的名字会让代码好读很多——后面嵌套循环时，变量名混用是最容易出错的地方。

循环到底替你做了什么 #

把上面这段代码"手动展开"，它其实等价于下面这样：

python
def period(context):
    order('000001.XSHE', 100)
    order('000002.XSHE', 100)

也就是说，for 循环替你做的唯一一件事，是把循环体复制若干遍，每次把循环变量换成列表里的下一个值。它没有引入任何新能力，只是省掉了手写重复代码的力气。

理解这一点有实际好处：当你不确定一段 for 循环在干什么时，可以自己在纸上把它展开成两三轮，看看每轮里各个变量的值分别是什么。这个笨办法对排查循环 bug 极其有效，因为循环出问题时，几乎总是"某一轮里某个变量的值和你以为的不一样"。

反过来，当股票列表变长时，手写展开的成本是线性增长的，而循环的成本是固定的——这正是第 2 篇讲的"框架替你处理重复"那件事在微观层面的体现。

在多股票策略里加入止损 #

其实运用所学的知识已经可以进一步地加入很多东西了，比如在这个多股票的基础上再加入之前讲过的止损。不妨自己先尝试下再看下面的样例代码。样例代码如下。

python
def initialize(context):
    run_daily(period, time='every_bar')
    # 把两个股票代码作为 list 存入 g.security 中
    g.security = ['000001.XSHE', '000002.XSHE']


def period(context):
    for stk in g.security:
        order(stk, 100)
        # 获得股票持仓成本
        cost = context.portfolio.positions[stk].avg_cost
        # 获得股票现价
        price = context.portfolio.positions[stk].price
        # 计算收益率
        ret = price / cost - 1
        # 如果收益率小于-0.01，即亏损达到 1% 则卖出股票，幅度可以自己调，一般 10%
        if ret < -0.01:
            order_target(stk, 0)
            print('触发止损')

同上章，仅标的与参数不同。 这段止损代码与上一篇《读取 context 中的数据与条件判断》末尾那段是同一套逻辑，并非复制粘贴错误：上一篇处理的是单只写死的股票，本篇把"取成本、取现价、算收益率、判断是否清仓"这四步整体搬进了 for 循环，于是同一段逻辑会自动作用于 g.security 里的每一只股票。唯一的实质改动是把硬编码的 '000001.XSHE' 换成了循环变量 stk，并把止损幅度沿用为 1%。读到这里请留意：这就是循环的价值——把"对一只股票做一遍"升级成"对每只股票各做一遍"，而逻辑本身一个字都不用改。

这段代码仍然存在的两个问题 #

第一个问题和上一篇一样：它每一轮都先无条件买入 100 股，再判断是否止损。所以止损触发、清仓之后，下一个周期又会被重新买回来，止损等于白做。

第二个问题是新出现的：如果 g.security 里的某只股票当前没有持仓，那么 context.portfolio.positions[stk] 会直接抛 KeyError，因为这个字典里根本没有这个键。而这段代码是先 order 再取持仓，看起来好像"刚买过所以一定有"，但实际运行中下单未必立刻成交（比如涨停买不进、停牌等），此时取持仓就会报错。

这两个问题都指向同一个正确的写法顺序：先看现在持有什么，再决定是买还是卖。可以先把 positions 的键取出来判断：

python
def period(context):
    # 先遍历当前持仓，做止损判断
    for stk in context.portfolio.positions.keys():
        cost = context.portfolio.positions[stk].avg_cost
        price = context.portfolio.positions[stk].price
        ret = price / cost - 1
        if ret < -0.01:
            order_target(stk, 0)
            print('触发止损：%s' % stk)

    # 再遍历目标股票列表，对没有持仓的补仓
    for stk in g.security:
        if stk not in context.portfolio.positions:
            order(stk, 100)

stk not in context.portfolio.positions 这个写法利用了 Python 的一个便利特性：对字典做 in 判断，判断的是"键是否存在"。这个技巧在第 8 篇写选股策略时还会用到，那里用它来判断"持有的股票是否已经不在要买入的名单里"。

嵌套循环与命名习惯 #

第 6 篇的自测里有一道上机题，用的是两层 for 循环——外层遍历 i，内层遍历 j。嵌套循环在策略里其实很常见，比如"对每只股票、再对它最近 N 天的价格各算一次"。所以有必要在这里把几个习惯说清楚。

第一，内外层变量名不能用同一个。 写成外层 for i in ...、内层又 for i in ...，内层的 i 会把外层的 i 覆盖掉，外层循环立刻就乱了。这是嵌套循环最经典的事故。

第二，内层循环每轮都会从头开始。 外层走一步，内层就要完整跑一遍。所以两层循环的总执行次数是两个长度相乘，不是相加。当 g.security 有 300 只股票、每只再取 250 天数据时，循环体就要执行 75000 次——这就是第 9 篇讲的"运行过慢"的典型来源。

第三，能不在循环里做的计算，就别放进去。 比如某只股票的平均价，如果每轮循环都重新算一次而结果并不变，那就是纯粹的浪费。把这类不变量提到循环外面，往往能让策略快上几倍。

第四，善用 break 提前退出。 如果你的目的是"找到第一个满足条件的股票"，那么找到之后就 break，不要让循环白白跑完剩下的几百轮。这在第 9 篇讲的分钟级策略里是很实在的优化。

本篇小结 #

  • 用 list 存多个股票代码：g.security = ['000001.XSHE', '000002.XSHE']。
  • for 变量 in 序列: 遍历，range() 生成等差数列（上限取不到）。
  • break 跳出整个循环，continue 跳过本次循环的剩余部分。
  • 把单股票逻辑搬进循环，就自动变成多股票逻辑；只需把硬编码的代码换成循环变量。
  • 遍历持仓用 positions.keys()，判断是否持有用 stk in positions。

从单股票到多股票，改动清单 #

把这一篇的演进过程摊开看，从"操作一只股票"到"操作一组股票"，实际改动只有三处：

  1. g.security 的值从字符串变成 list。
  2. order(...) 外面套一层 for 循环。
  3. 原来写死的 '000001.XSHE' 全部替换成循环变量 stk。

除此之外一个字都不用改。这个"只改三处"的特性很值得体会：它说明代码的结构价值——如果当初把股票代码硬编码在十几个地方，这次改造就会变成十几个点的改动，每一点都可能漏掉或写错。

反过来说，写单股票策略时就该有意识地避免硬编码股票代码。哪怕当前只操作一只股票，也把它放进 list，用循环处理。这样将来扩成多股票时，改动量是零。这是从本篇能提炼出的最实用的一条编码习惯。

关于"循环里取持仓"的坑再强调一次 #

本篇中段指出过：context.portfolio.positions[stk] 在该股票没有持仓时会抛 KeyError。这个错误在实际写策略时出现频率极高，因为它不会在编译时被提示，只会在回测跑到某一天时突然中断。

它的成因需要理解清楚：positions 是一个字典，字典用 [] 取值时，键不存在就直接报错，不会返回"空"。这一点和第 3 篇讲字典取值时是一致的，只是当时没有持仓这种真实场景来演示。

所以凡是"按股票代码从 positions 里取东西"的地方，取之前都应该先确认这只股票确实在持仓里。判断方法有两个：一是先 if stk in context.portfolio.positions:，二是干脆遍历 positions.keys() 而不是遍历你的目标列表——后者天然保证了每只股票都在持仓里，这也是本篇末尾那段"先止损、再补仓"代码采用 positions.keys() 的原因。

把这两点记住，可以省下大量排查报错的时间。
