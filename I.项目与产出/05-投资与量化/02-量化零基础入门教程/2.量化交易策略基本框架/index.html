从一个非常简单的交易策略开始 #

通过前文对量化交易有了一个基本认识之后，我们开始学习做量化交易。毕竟就像学游泳，有些东西讲是讲不懂，做过就会懂。

由于本教程是基于聚宽量化投研平台（www.joinquant.com），所以为了后续的学习，最好去注册一个聚宽量化投研平台的账号。

先看一个非常简单的交易策略：

  • 每天买 100 股的平安银行。

就这么一句话。它已经具备了一个可回测策略的最低要求：买什么（平安银行）、买多少（100 股）、什么时候买（每天）。虽然简陋，但四个维度都齐了。

把策略装进框架 #

为了让这个策略能让计算机执行，首先，要使策略符合「初始化 + 周期循环」框架，像这样：

  • 初始化：选定要交易的股票为平安银行。
  • 每天循环：买 100 股的平安银行。

什么是「初始化 + 周期循环」框架 #

为了将投资灵感高效地转化成计算机可执行的量化策略，必须基于一种模式来写，框架就是指这种模式。而此框架包含两个部分，即初始化与周期循环。

初始化即指策略最开始运行前要做的事。比如，准备好要交易的股票。

周期循环即指策略开始后，随着时间一周期一周期地流逝时，每个周期要做的事。如例中，周期为天，周期循环的则是每天买 100 股的平安银行。

能帮助你理解这一框架的是：其实人本身日常做交易就是符合「初始化 + 周期循环」框架的。初始化就是已存在人脑的交易思想与知识，周期循环就是每天或每分钟地查看行情、判断、下单等行为。

这个类比值得多想一层：人做交易时，"知识"只需要准备一次（初始化），而"看盘下单"要重复无数次（周期循环）。代码把这两件事强行分开，好处是框架会自动帮你处理"重复"这件枯燥的事——它替你遍历每一个交易日或每一分钟，你只需要写清"这一个时刻该做什么"。

如何把策略变成计算机可执行的程序 #

通过编程将策略写成计算机可识别的代码。具体说，我们这里是用 Python 这门编程语言。

另外可以用聚宽的向导式策略生成器，这种方法是不需编程的，但灵活性上难免是远不如写代码的。

那么如何将策略写成代码？这并非三言两语就能说清，尤其是对于没有编程基础的人。所以我们将通过后续的内容逐步地介绍。首先我们将学习「初始化 + 周期循环」框架代码的写法。

写法一 #

python
def initialize(context):
    # 这里是用来写初始化代码的地方，例子中就是选定要交易的股票为平安银行
    pass


def handle_data(context, data):
    # 这里是用来写周期循环代码的地方，例子中就是买 100 股的平安银行
    pass

写法二 #

python
def initialize(context):
    run_daily(period, time='every_bar')
    # 这里是用来写初始化代码的地方，例子中就是选定要交易的股票为平安银行


def period(context):
    # 这里是用来写周期循环代码的地方，例子中就是买 100 股的平安银行
    pass

两种写法的差别在于：写法一里，周期循环的函数名是系统规定死的 handle_data；写法二里，你在 initialize 中通过 run_daily(period, time='every_bar') 自己声明"每隔一个 bar 就调用一次我写的 period 函数"。后者把"什么时候执行"从函数名里解放了出来，所以更灵活。

代码应该往哪里写 #

来到聚宽网站后，通过导航栏「我的策略」→「我的策略」进入策略列表，点击新建策略。进入策略编辑页，左侧就是策略代码编辑区域，初始会默认给你提供代码模板，全删除后写入我们的代码就好了。

两种写法用哪个好 #

写法一是从前的老写法，将逐步弃用；写法二是聚宽系统改进后的新写法，推荐使用写法二。

本连载后面所有代码都用写法二。如果你看到别处的教程用了写法一，知道那是旧写法即可，不必跟着改。

def、context 等都是什么意思 #

其实是在调用聚宽提供好的函数，展开讲很复杂，不理解的话先记住，后面的学习内容会让你理解。

具体来说：def 是 Python 里"定义函数"的关键字（第 4 篇详细讲），context 是系统自动传给你的一个对象，里面装着当前时间、持仓、资金等一切策略运行时的现场信息（第 5 篇详细讲）。现在这两样都只需要"认得这个词"，不需要会用。

补齐框架：一个完整的例子 #

框架写成代码了，那例子的完整的代码该怎么写呢？剩下的两行代码这么写。完全理解需要学习后续的内容，此处不要求理解。知道大概什么样子、往哪里写即可。

选定要交易的股票为平安银行：

python
g.security = '000001.XSHE'

买 100 股的平安银行（市价单写法）：

python
order(g.security, 100)

以写法二为例，把剩下的代码补上后，完整代码为：

python
def initialize(context):
    run_daily(period, time='every_bar')
    g.security = '000001.XSHE'


def period(context):
    order(g.security, 100)

逐行对照一下框架：

  • 第 1 行的 def initialize(context): 是初始化段的开头。
  • 第 2 行 run_daily(...) 声明"周期循环请调用名为 period 的函数"。
  • 第 3 行 g.security = ... 就是"选定要交易的股票"这件事，用 g. 开头的全局变量存起来。
  • 第 6 行的 def period(context): 是周期循环段的开头。
  • 第 7 行 order(g.security, 100) 就是"买 100 股"这件事。

现在这些代码就可以运行了吗 #

是的。以写法二为例，如图把代码写到策略编辑区，设置好初始资金与起止时间（比如初始资金 100000 元，起止时间 20160601-20161231），频率设置成天。点击编译运行，运行结束后就可以看到结果了。

可以看到，若你 20160601 有初始资金 100000 元，每个交易日尝试买 100 股的平安银行，到 20161231，你的收益曲线将如图中蓝线般增长。图中红线是基准收益（默认是沪深 300 指数，代表整个市场增长水平）。

接下来，点击运行回测，运行结束后就可以看到更为详细的结果，包括下单记录、持仓记录等。

这里有个容易被忽略的细节：这个策略每天买 100 股，半年下来会不断加仓，资金很快用完。所以它其实是一个"演示框架"的策略，不是一个赚钱的策略。写它的目的是让你确认框架能跑通，而不是确认它能盈利。

策略出错不能运行怎么办 #

策略不能运行时，日志中会报错并给出一定的提示信息。

首先注意，右上角的箭头按钮能展开运行日志。看到日志中，最后一行是错误的提示信息，例如：

text
SyntaxError: invalid syntax

汉义是「语法错误：不合法的语法」。

最后一行之前的是错误的位置信息，一般只看后面就行：

text
File "user_code.py", line 1
    def initialize(context)
                          ^

意思是文件 user_code.py（就是你的策略代码）的第一行，"^"符号指向的位置有错。你到代码中的这个位置看下，会发现少个冒号。

为了顺利运行策略，需要耐心解决错误，但错误的原因极度的复杂多样（所以日志的报错信息也多种多样，不止上面一种），故在此只针对例子讲下新手容易犯的错误。

三类新手常见错误 #

符号要用英文输入法。 代码里的冒号、括号、引号、逗号必须是英文半角的。中文的冒号看上去几乎一样，但系统不识别，会直接报语法错误。

拼写不要错。 比如 security 拼成 securiy，系统会告诉你这个名字没有被定义。这类错误的特点是名字越长越容易打错，写完一行不妨回看一眼。

缩进要对齐。 Python 用缩进表达"哪些语句属于同一个代码块"。缩进没对齐，报错信息可能是 IndentationError，也可能是看着莫名其妙的 SyntaxError。缩进可以用 Tab 键或四个空格，但一篇代码里不要混着用——混用时会报 TabError，这是新手最难自己看出原因的一类错误。

编程界往往把错误叫 bug，而不断调试去除错误的过程叫 debug，做量化时也是时常听到的说法，大家应该知道下。

而且 debug 通常就是要耗费不低于写代码的时间的，所以会 debug 是很重要的能力。大家平时 debug 的时候不妨多思考下，如何更有效率地 debug。当然，我们后续也会介绍些 debug 的技巧。

现阶段最有效的 debug 技巧只有一条：从日志的最后一行往上读，先看错误类型，再看行号，最后才看那行代码。新手常见的毛病是从报错日志第一行开始逐字读，然后被一堆系统内部信息吓住。

回测、编译运行、运行回测都是什么意思 #

像刚刚那样，用一段时间内的历史的真实行情数据，来验证一个确定的交易策略在这段时间表现如何，这个过程叫回测。

运行回测就是字面意思，让计算机运行这次回测，运行后会告诉你策略在这段时间表现情况，比如收益率、年化收益率、最大回撤、夏普比率等指标，而且一般也会包括下单记录、持仓记录等。

编译运行其实也是让计算机运行这次回测，不过相比于点击运行回测，编译运行的结果比运行回测要简单，只有收益率等指标，因此速度也更快。所以，当还不必要得到详细的结果时，或只是想调试下策略的代码、看是否无误可运行时，编译运行就比运行回测更方便。

三者的关系可以这样记：回测是"这件事本身"，编译运行和运行回测是"两种跑法"——前者快而粗略，用于调通代码；后者慢而详尽，用于研究结果。

周期循环具体是什么时候开始的呢 #

如果策略频率为天，是每个交易日开始生效，从 9:30 直到 15:00（从股市开市到收市），所以例子中是每个交易日 9:30 开市循环就开始，一天一次地循环执行买入股票的操作。

如果策略频率为分钟，是每个分钟开始时执行，所以例子中的买入股票的操作是每个交易日从 9:30:00 开始，然后 9:31:00，直到 14:59:00。接着下一天 9:30:00，如此一分钟一次地循环执行的。

虽然频率只有分钟和每天可选，但通过不同的代码可以实现按周按月进行周期循环，而且分钟级别里下单时间也是可以自己选的，不过代码的写法则与写法一和写法二那样略有不同，后面会讲到。

这个"频率"设置会在第 5、第 6 篇反复用到，因为它直接决定了 context.current_dt 里装的是哪一天或哪一分钟。现在只需要记住：频率决定周期循环被触发的粒度。

本篇小结 #

把这一篇的东西收拢一下，一共四件：

  1. 任何策略都可以拆成「初始化」（只做一次）和「周期循环」（反复做）两段。
  2. 写法二用 run_daily(period, time='every_bar') 把周期循环挂到一个自定义函数上，推荐使用。
  3. g. 开头的变量是全局变量，可以在初始化和周期循环之间共享。
  4. 报错先看最后一行；符号、拼写、缩进是三座大山。

为什么框架长成这样 #

把框架的两段再想深一层，会发现它不是聚宽的设计偏好，而是量化交易的必然结构。

初始化之所以必须存在，是因为有些准备工作很贵。 比如确定股票池、加载外部数据、设定参数，这些事情做一次就够，如果每个周期都重做一遍，回测能慢上几个数量级。更重要的是，如果"股票池"每个周期都变，你的策略就变成了一个每天都在换目标的策略，回测出来的结果根本无法解释。

周期循环之所以必须存在，是因为交易本身是重复的。 人做交易时，"看盘—判断—下单"这个动作要重复几千次；代码要做的就是把这几千次压缩成一段写一次的代码。所以周期循环里写的永远是"这一个时刻该做什么"，而不是"整个过程该做什么"。

这个抽象还有一个隐含好处：它天然防止了未来函数。因为周期循环只提供"当前时刻"的信息，你无法在代码里自然地引用明天的数据——除非你刻意用某些取数 API 去取，那属于第 9 篇要讲的坑。框架本身站在你这边的。

三层结构再对一遍 #

把第 2 篇和前后的内容串起来，一个策略代码在文件结构上通常是三层：

  • 最外层：import 语句与自定义函数（如果用了）。本教程的简单策略常常不需要这一层。
  • 初始化段：def initialize(context):，做一次性准备：启动周期循环、设定全局参数、准备股票池。
  • 周期循环段：def period(context): 或 def handle_data(context, data):，每个周期执行一次：取数据、做判断、下单。

后面第 5 篇的止损、第 6 篇的循环、第 8 篇的选股策略，全部是在第三层里做文章。而修改参数、调整周期，则是在第二层里做文章。分清楚"我现在改的是哪一层"，可以避免很多低级错误——比如把参数赋值写进周期循环里，导致每个周期都重置一次。

自测与自学 #

  • 按教程实践下：新建策略 → 粘贴写法二的完整代码 → 编译运行 → 看结果 → 运行回测 → 看下单记录。
  • 通过搜索自学 K 线、bug、debug 的含义。
  • 故意把代码里的英文冒号改成中文冒号，看看报错信息长什么样；再故意把缩进打乱一个空格，看看报错信息有什么不同。把两次的报错都记下来。
  • 思考题：如果把频率从"天"改成"分钟"，那个「每天买 100 股」的策略会变成什么行为？资金会在多久内用完？
