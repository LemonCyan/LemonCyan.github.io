灵感细化 #

之前也提到过策略灵感的来源多种多样，可能是通过阅读、通过与人交流、或是通过自己感悟与研究等等。灵感最初可能只是模糊的感觉或疑问，比如「感觉低市盈率的股票好像长期收益更好」「当股价一旦超过整百的时候会不会更容易继续涨一段」「这个股票和那个股票的股价数据看起来好像符合某种统计规律」等等。验证灵感的一个基本方法是把灵感细化，写成策略做回测。

现在你听说了这样一件事：小市值股票过去很长一段时间内收益特别好，但最近不太行了。你觉得这件事比较有价值，想要写成策略来回测验证下。请思考下，应该写一个什么样的策略来验证这件事呢？

为了验证灵感，我们把灵感细化成内容如下的这样一个策略。

text
每天找出市值排名最小的前10只股票作为要买入的股票。
若已持有的股票的市值已经不够小而不在要买入的股票中，则卖出这些股票。
买入要买入的股票，买入金额为当前可用资金的10分之一。

考虑到不一定要选 10 个股票，股票数量应该是个可以方便调节的变量，因此策略内容改成如下这样更好。

text
设定好要交易的股票数量stocksnum
每天找出市值排名最小的前stocksnum只股票作为要买入的股票。
若已持有的股票的市值已经不够小而不在要买入的股票中，则卖出这些股票。
买入要买入的股票，买入金额为当前可用资金的stocksnum分之一。

这三句话分别对应了策略的三个动作：选股、卖出、买入。后面写代码时，就是照着这三句话一句一句落地。注意这个细化过程没有引入任何新概念，用的全是第 1 篇讲的"明确化"功夫。

提示 #

  • 代码：设定好要交易的股票数量 stocksnum。这句非常简单，需要注意的是要用到之前讲过的全局变量。
  • 代码：找出市值排名最小的前 stocksnum 只股票作为要买入的股票。首先使用 get_all_securities 取其 index 得到股票列表。然后，使用获取财务数据的方法找出当前全市场股票中市值最小的前 stocksnum 个的股票代码。
  • 代码：若已持有的股票的市值已经不够小而不在要买入的股票中，则卖出这些股票。使用 context 数据获取当前持仓情况，用 for 循环语句与 if 判断语句判断股票是否在当前持仓中，用 in 判断是否一个元素在某 list 中，用下单 API 实现卖出操作。
  • 代码：买入要买入的股票，买入金额为可用资金的 stocksnum 分之一。使用 context 数据获取当前可用资金总量，用 for 循环与下单 API 实现买入每个要买入的股票。

把四条提示串起来看，这个策略的执行顺序其实是固定的：先算出买什么（选股）→ 再卖掉不该持有的（卖出）→ 最后买入该持有的（买入）。顺序不能颠倒，因为"卖出"释放出的资金要供"买入"使用，而"买入"的金额又取决于当前可用资金。

参考代码 #

python
def initialize(context):
    run_daily(period, time='every_bar')
    # 设定好要交易的股票数量stocksnum
    g.stocksnum = 10


def period(context):
    # 代码：找出市值排名最小的前stocksnum只股票作为要买入的股票
    # 获取当天的股票列表
    scu = get_all_securities(date=context.current_dt).index.tolist()
    # 选出在 scu 内的市值排名最小的前 stocksnum 只股票
    q = query(valuation.code
              ).filter(
                  valuation.code.in_(scu)
              ).order_by(
                  valuation.market_cap.asc()
              ).limit(g.stocksnum)
    df = get_fundamentals(q)
    # 选取股票代码并转为 list
    buylist = list(df['code'])

    # 代码：若已持有的股票的市值已经不够小而不在要买入的股票中，则卖出这些股票。
    # 对于每个当下持有的股票进行判断：现在是否已经不在 buylist 里，如果是则卖出
    for stock in context.portfolio.positions:
        if stock not in buylist:  # 如果 stock 不在 buylist
            order_target(stock, 0)  # 调整 stock 的持仓为 0，即卖出

    # 代码：买入要买入的股票，买入金额为可用资金的 stocksnum 分之一
    # 将资金分成 g.stocksnum 份
    position_per_stk = context.portfolio.cash / g.stocksnum
    # 用 position_per_stk 大小的 g.stocksnum 份资金去买 buylist 中的股票
    for stock in buylist:
        order_value(stock, position_per_stk)

这段参考代码里值得单独讲的几个点 #

get_all_securities(date=...).index.tolist() 这一长串是三个动作连起来的：get_all_securities 返回一个以股票代码为行索引的 DataFrame，.index 取出索引，.tolist() 把索引转成普通 list。之所以要显式转成 list，是因为后面 valuation.code.in_(scu) 需要的是一个真正的列表。

valuation.code.in_(scu) 是 query 里做"包含于"筛选的写法，含义是"股票代码在 scu 这个列表里"。第 7 篇讲的四个子句模板，这里用全了。

for stock in context.portfolio.positions: 直接遍历字典，拿到的是键，也就是股票代码。这是遍历持仓最简洁的写法。

if stock not in buylist: 就是第 6 篇末尾讲的那个技巧：用 in 判断元素是否在列表里。这里反过来问"不在"，于是完成了"持仓中已不符合选股条件的股票就卖掉"这件事。

context.portfolio.cash / g.stocksnum 是浮点除法，得到每份资金。这里能正确得到小数，靠的是 cash 本身是浮点数（回想第 3 篇讲的整数除法截断问题）。

调整与改进 #

至此这已经是一个完整可运行的策略了，你可以试试看，回测结果应该已经可以一定程度上验证灵感了。不过虽然策略完成，我们却发现现在策略是每天进行一次选股并交易，我们觉得这太频繁了，希望能实现通过一个变量 period 控制操作的周期，即每 period 天进行一次选股并交易。

依然建议先试着自己做下，提示如下，提示之后是参考代码。

  • 像 stocksnum 那样用全局变量的方式建立 period 变量。
  • 用一个变量记录策略运行天数。
  • 用取余运算配合 if 判断语句判断是否又经过 period 天。

参考代码 #

python
def initialize(context):
    run_daily(period, time='every_bar')
    # 设定好要交易的股票数量
    g.stocksnum = 7
    # 设定交易周期
    g.period = 13
    # 记录策略进行天数
    g.days = 0


def period(context):
    # 判断策略进行天数是否能被轮动频率整除余 1
    if g.days % g.period == 0:
        # 代码：找出市值排名最小的前 stocksnum 只股票作为要买入的股票
        # 获取当天的股票列表
        scu = get_all_securities(date=context.current_dt).index.tolist()
        # 选出在 scu 内的市值排名最小的前 stocksnum 只股票
        q = query(valuation.code
                  ).filter(
                      valuation.code.in_(scu)
                  ).order_by(
                      valuation.market_cap.asc()
                  ).limit(g.stocksnum)
        df = get_fundamentals(q)
        # 选取股票代码并转为 list
        buylist = list(df['code'])

        # 代码：若已持有的股票的市值已经不够小而不在要买入的股票中，则卖出这些股票。
        # 对于每个当下持有的股票进行判断：现在是否已经不在 buylist 里，如果是则卖出
        for stock in context.portfolio.positions:
            if stock not in buylist:  # 如果 stock 不在 buylist
                order_target(stock, 0)  # 调整 stock 的持仓为 0，即卖出

        # 代码：买入要买入的股票，买入金额为可用资金的 stocksnum 分之一
        # 将资金分成 g.stocksnum 份
        position_per_stk = context.portfolio.cash / g.stocksnum
        # 用 position_per_stk 大小的 g.stocksnum 份资金去买 buylist 中的股票
        for stock in buylist:
            order_value(stock, position_per_stk)
    # 策略进行天数增加 1
    g.days = g.days + 1

这里的缩进极容易出错 #

对比上一段参考代码，你会发现这次几乎整个策略体都被多缩进了一层，因为所有选股、卖出、买入的动作现在都落在了 if g.days % g.period == 0: 这个分支里面。而最后的 g.days = g.days + 1 必须回到与 if 同级的位置——它要每天执行，否则天数就不会增长，% 判断也就永远停在初始状态。

这是本篇最容易出错的地方，写的时候建议按这个顺序检查：先看 if 里面的代码是否整体多缩进一层，再看 g.days = g.days + 1 是否退回到了 if 外面。判断方法很简单：如果天数不涨，说明这行被误缩进到了 if 里面。

常见实现错误对照 #

把新手实现这段策略时最容易写错的地方列成一张表，方便自查：

错误写法 后果 正确写法
order(stock, 0) 是"卖 0 股"，什么都不会发生 order_target(stock, 0) 才是清仓
先买入再卖出 卖出时可用资金已被占用，买入金额算少了 先选股、再卖出、最后买入
for stock in buylist 里取 positions[stock] 新股票尚未持仓，抛 KeyError 先判断 stock in positions 再取
context.portfolio.available_cash 与 cash 混用 两者含义不同，回测金额对不上 判断可用资金统一用 available_cash
把 g.days + 1 写进 if 分支内 天数不增长，周期判断永远成立 放在 if 外面，每天都加
limit(g.stocksnum) 写成 limit(10) 参数改了不生效 用变量而非字面量

第三条尤其容易踩：因为选股结果是"当前市值最小的一批"，它们往往与你现在的持仓不完全重合，那些新出现的股票在 positions 里根本不存在。这就是第 6 篇强调过的 KeyError 陷阱，在真实策略里必然会被触发。

一个值得自己思考的问题 #

参考代码里，买入金额用的是 context.portfolio.cash / g.stocksnum，然后对 buylist 里的每只股票都下单这个金额。看起来"每只股票买到的钱一样多"，但请留意：cash 是在每次循环开始时取一次吗？还是每次 order_value 之后会变？

代码里只取了一次，算出一个 position_per_stk，之后循环里一直用这个固定值。这没问题。但如果有人写成在循环内部每次都重新取 context.portfolio.cash，那么每买一只股票后可用资金就减少，下一只买到的就更少，最终资金分配会严重失衡——第一只买最多，最后一只几乎买不到。

这就是自测题里"虽然每次都等资金的买入，为何各股票的持仓价值其实还是不同"的一部分答案：除了下单后价格波动导致的差异，代码里取 cash 的位置也会造成差异。这是个非常隐蔽的 bug，值得在纸上把两种写法的执行过程走一遍。

本篇小结 #

  • 从一个模糊灵感出发，先写成三到四句明确的文字规则，再逐句翻译成代码。
  • 执行顺序固定：先选股、再卖出、最后买入。
  • 常用套路：get_all_securities().index.tolist() 拿全市场代码，query().filter().order_by().limit() 选股，order_target(stock, 0) 清仓，order_value 按金额买入。
  • 加参数的通用做法：用 g. 全局变量存参数，用 if 天数 % 周期 == 0 控制执行频率。

这个策略还能怎么改 #

参考代码只是一个骨架，真实的研究会在这个骨架上不断加东西。列举几个方向，按实现难度从低到高排列，它们也正好是下一篇要提醒你的坑的来源。

一、换掉排序指标。 现在按 market_cap.asc()（市值从小到大）排序。把 market_cap 换成 pe_ratio（市盈率）、roe（净资产收益率）、circulating_market_cap（流通市值），只要换一个字段名，就得到一个新策略。这是最廉价的实验方式。

二、换掉股票池。 现在是 get_all_securities 取全市场。改成 get_index_stocks('000300.XSHG') 就变成在沪深 300 里选股，改成 get_index_stocks('000905.XSHG') 就是中证 500。第 7 篇讲的成分股 API 在这里派上用场。

三、加过滤条件。 在 query 里追加 filter 条件，比如排除 ST、排除市盈率为负、排除停牌。这一步会显著改变结果，也是第 9 篇"过拟合"风险的起点——每加一个条件，你就多了一个可以调的空间。

四、加风控。 用第 5、6 篇的止损逻辑，对持仓逐只判断收益率，超过阈值就清仓。这就是本章自测题的答案。

五、加调仓周期。 已经做了。再进一步可以让周期本身也变成动态的，比如市场波动大时缩短周期。

这五个方向里，前两个是"探索"，后三个是"打磨"。新手常犯的错是一上来就打磨——加一堆过滤条件和风控，结果参数越调越多，回测越来越漂亮，但已经不知道自己到底在验证什么了。合理的做法是：先做探索（改指标、改股票池）找出有希望的方向，再对那个方向做打磨。

自测与自学 #

  • 自己实现下本文策略。
  • 思考 g.period、g.stocksnum 各自设为多少效果比较好？
  • 思考此文中，虽然每次都等资金的买入，为何各股票的持仓价值其实还是不同，而且可能越差越大？
  • 在本文策略中加入止损或止盈。
  • 试着在本文策略中选股时排除 ST 股票、停牌股票、与涨停股票。这个问题可能会有些挑战，因为会涉及到简单但没讲过的内容，比较考察搜索与自学能力，但这是做投资交易最为重要的能力。
