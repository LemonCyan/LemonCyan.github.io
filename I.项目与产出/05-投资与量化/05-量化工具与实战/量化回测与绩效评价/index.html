回测是在历史市场数据上模拟和评估一个交易策略的过程。在量化金融和算法交易中，回测是一个关键步骤，用于评估交易策略在过去市场行为上的表现。通过回测，交易者可以了解其策略在不同市场条件下的表现，并进行优化和改进。

但回测也是最容易自欺欺人的环节。同一段历史数据，参数稍调一调就能从亏损变成年化 40%，再多加几个「只在事后才成立」的条件，收益率还能继续往上堆。这篇文章除了讲怎么写回测，更想讲清楚回测会在哪里骗你，以及怎么用标准的绩效指标把水分挤出来。

一、回测的六个标准步骤 #

  • 定义交易策略： 确定何时买入、卖出或持仓的规则。这可能涉及到技术指标、移动平均线策略、趋势跟踪、套利等各种策略。
  • 获取历史数据： 获取过去的市场数据，包括股票、期货、外汇等金融工具的价格、成交量等信息。
  • 模拟交易： 根据定义的策略，模拟在历史数据上执行交易。这包括确定何时买入或卖出，并计算每次交易的收益和损失。
  • 计算绩效指标： 根据回测结果，计算各种绩效指标，如年化收益率、最大回撤、夏普比率等，以评估策略的表现。
  • 优化策略： 如果回测结果不理想，交易者可以进行策略的优化，调整参数或修改规则，然后重新进行回测。
  • 未来性检验： 回测的一个关键问题是防止未来数据的泄漏。未来性检验是确保在设计和评估策略时只使用历史数据的一部分，以模拟实际交易中只能使用已知信息的情况。

最后一条最容易被跳过，也最致命。下面先把它讲透。

二、未来函数：回测里的头号杀手 #

未来函数（look-ahead bias）指的是：在计算第 T 天的交易决策时，用到了第 T 天收盘之后才知道的信息。

最典型的例子是「用当天收盘价决定当天买入」。听起来合理，但真实交易里你在收盘那一刻并不知道收盘价是多少——你只能在 14:57 挂单，而收盘价要到 15:00 集合竞价结束才产生。用 Close 算信号、又用 Close 成交，等于用未来信息交易，实盘必然打折。

更隐蔽的几种情况：用当日最高价、最低价做信号判断（这两个价格全天走完才知道）；用当天的财务数据做当天调仓（财报通常盘后或次日才公布）；用指数成分股名单回看历史（名单本身是事后修订的）；用 rolling().mean() 却忘了 center=False（居中窗口会用到未来数据）。

shift(1) 到底在做什么 #

shift(1) 把序列整体向下挪一行，也就是让今天的持仓由昨天的信号决定：

python
import pandas as pd

df = pd.DataFrame({"Close": [10.0, 11.0, 12.0, 13.0]})
df["Signal"] = (df["Close"] > df["Close"].shift(1)).astype(int)
df["Daily_Return"] = df["Close"].pct_change()
df["Strategy_Return"] = df["Signal"].shift(1) * df["Daily_Return"]
print(df)

输出：

text
   Close  Signal  Daily_Return  Strategy_Return
0   10.0       0           NaN              NaN
1   11.0       1      0.100000              NaN
2   12.0       1      0.090909         0.100000
3   13.0       1      0.083333         0.090909

第 1 行的 Signal = 1 表示「收盘后确认了上涨」。如果直接拿这一行的信号乘这一行的日收益，就是用今天收盘算出的信号赚今天全天的涨幅——不可能。加上 shift(1) 后，第 2 行的策略收益等于第 1 行的日收益，因为信号在第 1 行产生、第 2 行才生效。这才是可执行的时序：信号在 T 日收盘产生，T+1 日才成交。

顺带一个坑：shift(1) 之后第一行是 NaN，直接乘会得到 NaN，cumprod() 会把整条曲线污染成 NaN，所以后面一定要加 .fillna(0)。

自查清单 #

  1. 信号用到的最晚数据是不是 T 日收盘价？成交价用的是不是 T+1 日？
  2. 所有 rolling 是否都是 center=False？
  3. 财务/宏观数据是否按公告日而非报告期对齐？
  4. 有没有用 ffill() 把未来数据往回填的地方？
  5. 策略参数在样本外区间上是否也正常？

只要第 1 条过不了，后面的绩效指标再漂亮也没有参考价值。

三、五个必须算的绩效指标 #

先准备一组可复用的函数：

python
import numpy as np
import pandas as pd

TRADING_DAYS = 252


def cumulative_return(returns):
    """累计收益率：整段区间的总涨幅。"""
    return (1 + returns.fillna(0)).prod() - 1


def annualized_return(returns):
    """年化收益率：把总收益按几何平均摊到每年。"""
    n = returns.notna().sum()
    if n == 0:
        return np.nan
    return (1 + cumulative_return(returns)) ** (TRADING_DAYS / n) - 1


def max_drawdown(nav):
    """最大回撤：净值从历史最高点回落的最大幅度。"""
    return (nav / nav.cummax() - 1).min()


def sharpe_ratio(returns, risk_free=0.02):
    """夏普比率：年化超额收益 / 年化波动率。"""
    r = returns.dropna()
    if len(r) < 2 or r.std() == 0:
        return np.nan
    excess = r - risk_free / TRADING_DAYS
    return np.sqrt(TRADING_DAYS) * excess.mean() / r.std()


def win_rate(returns):
    """胜率：有交易的日子里赚钱的比例。"""
    active = returns[returns != 0].dropna()
    if len(active) == 0:
        return np.nan
    return (active > 0).sum() / len(active)

1. 累计收益率（Cumulative Return） #

定义： 从回测起点到终点，账户净值的总涨幅。

公式：

Rtotal​=t=1∏T​(1+rt​)−1

其中 rt​ 是第 $t$ 期的策略收益率。必须用连乘而不是算术求和：「先涨 50% 再跌 50%」等于亏 25%，而不是持平。

代码： 就是上面 cumulative_return 那一行 (1 + returns).prod() - 1。

2. 年化收益率（Annualized Return / CAGR） #

定义： 把不同长度的回测区间拉到同一把尺子上比较。三年翻倍和一年翻倍是两件事。

公式：

Rannual​=(1+Rtotal​)n252​−1

其中 $n$ 是回测区间的交易日数量，252 是一年约等于的交易日数（A 股约 244，差异通常可忽略）。

为什么用几何而非算术： 算术平均年化会系统性高估。假设第一年 +100%、第二年 -50%，总收益为 0，算术平均年化是 25%，几何年化是 0%——几何才对。

3. 最大回撤（Maximum Drawdown） #

定义： 净值曲线从任意历史高点回落到之后最低点的最大跌幅，衡量最坏情况下你要忍受多少痛苦。

公式：

MDD=tmin​(maxs≤t​Ns​Nt​​−1)

其中 Nt​ 是第 $t$ 期的净值。

为什么比波动率重要： 波动率把上涨和下跌一视同仁，而投资者只会因为下跌而赎回。年化 20%、最大回撤 60% 的策略绝大多数人拿不住——回撤 60% 需要涨 150% 才能回本。

代码： 先 peak = nav.cummax() 求历史最高，再 nav / peak - 1 得逐日回撤序列，取 min()。

4. 夏普比率（Sharpe Ratio） #

定义： 每承担一单位波动风险，能换来多少超额收益。它把收益和风险放进同一个数字。

公式：

SR=σr​rˉ−rf​​×252​

其中 rˉ 是日收益均值，rf​ 是无风险利率（常取 2%），σr​ 是日收益标准差，252​ 用于把日频指标年化。

经验刻度： SR < 1 不如买指数基金；1 ≤ SR < 2 可以接受；SR ≥ 2 优秀；SR 高到 5 以上，先怀疑有未来函数或成本没算。

代码注意点： 分子要用超额收益（减去无风险利率的日化值），分母是收益标准差而不是方差。

5. 胜率与盈亏比 #

胜率定义： 有持仓的日子里赚钱的天数占比。

WinRate=总交易期数盈利期数​

盈亏比定义： 平均每笔盈利与平均每笔亏损的比值。

PLR=平均亏损额平均盈利额​

为什么必须一起看： 胜率 90% 但盈亏比 0.1 的策略照样亏钱——赢九次每次赚 1 块，输一次亏 10 块。反过来，趋势跟踪策略胜率常只有 35%~40%，但盈亏比能到 3 以上，长期依然赚钱。单看胜率是典型的评价误区。

两者的乘积构成期望值 $E = WinRate \times AvgWin - (1 - WinRate) \times AvgLoss$。只要 $E > 0$ 且交易成本没吃掉它，策略在统计上就是正期望的。

四、交易成本：忽略它就等于自欺欺人 #

很多教程的收益率漂亮得不像话，一个重要原因是一分钱成本都没扣。真实交易的成本从三处漏走你的钱。

佣金（Commission）： 券商收取的手续费，A 股主流是万分之 2.5 到万分之 3，且有最低 5 元门槛。买 5000 元股票，万三应扣 1.5 元、实际扣 5 元，等效费率变成万十。

印花税（Stamp Duty）： A 股卖出单边征收（2023 年 8 月起由千分之一下调至万分之五），买入不收。港股双边千分之一，美股无印花税但有 SEC 费。这类税费必须按方向区分，统一按「双边万三」简化会失真。

滑点（Slippage）： 理论成交价与实际成交价的差距。成因包括盘口深度不足、大单冲击成本、涨跌停无法成交、开盘跳空。它最容易被忽略，影响又最大，做高频或小市值股票时滑点可能比佣金高一个数量级。

成本应该怎么建模 #

最简单可靠的做法是单边固定费率，把佣金、税费、滑点打包成一个数字：

python
def apply_costs(returns, turnover, cost_rate=0.0015):
    """按换手率扣减交易成本。

    returns  : 策略日收益（已 shift）
    turnover : 每日换手比例，全仓进出的策略取值 0 或 1 的切换
    cost_rate: 单边综合成本率，A 股经验值 0.001~0.002
    """
    return returns - turnover * cost_rate

只要策略平均每天换手一次、单边成本万十五，一年 252 个交易日就要扣掉 37.8% 的收益。这就是高换手策略纸面赚钱、实盘亏钱的原因——成本与换手次数线性相关，而收益不会。

市场 佣金 印花税 滑点估计 单边综合
A 股大盘股 万 2.5 卖出万 5 万 3~5 约万 5~8
A 股小盘股 万 2.5 卖出万 5 万 15~30 约万 20~35
美股 万 1 或免佣 无 万 1~3 约万 2~4

月频调仓的策略成本影响可能只有 1%~2%；日频调仓的策略成本能吞掉全部 alpha。所以先算清换手率，再决定要不要做这个策略。

五、基准对比：收益数字必须有个参照物 #

「年化 15%」本身没有意义。同期沪深 300 涨了 30%，你跑输 15 个百分点；同期指数跌了 10%，你非常优秀。

为什么要对比基准：

  1. 区分 alpha 与 beta。 2019—2020 年随便买个白马组合都能翻倍，那是指数给的 beta。真本事是扣掉 beta 之后还剩多少。
  2. 暴露策略的市场依赖。 牛市赚 50%、熊市亏 40% 的策略，本质是加了杠杆的指数跟踪器。
  3. 给回撤一个合理的心理锚。 自己回撤 30% 而基准回撤 35%，可以踏实；基准只跌 10%，就要反思策略是不是失效了。

常用基准：A 股用沪深 300（大盘）、中证 500（中盘）、中证 1000（小盘）、创业板指，选哪个取决于股票池的市值区间；美股用标普 500（^GSPC 或 SPY）、纳斯达克 100（^NDX）；多资产用 60/40 组合。

在 yfinance 里取基准很方便，对比时至少要看三个相对指标：

python
import numpy as np
import yfinance as yf

bench = yf.download("000300.SS", start="2019-01-01", end="2023-01-01", multi_level_index=False)
bench_return = bench["Close"].pct_change().fillna(0)


def excess_stats(strategy_returns, benchmark_returns):
    """计算相对基准的超额表现。"""
    excess = strategy_returns - benchmark_returns
    return {
        "annual_excess": annualized_return(strategy_returns) - annualized_return(benchmark_returns),
        "tracking_error": excess.std() * np.sqrt(252),
        "information_ratio": excess.mean() / excess.std() * np.sqrt(252)
        if excess.std() > 0 else np.nan,
    }

信息比率（IR） 是超额收益版的夏普比率：IR > 0.5 说明稳定跑赢基准，IR < 0 不如直接买指数。绝大多数主动策略长期 IR 都在 0 到 0.5 之间——回测算出来 IR > 2，先回去查未来函数。

六、一个能直接跑完的完整回测 #

把前面所有零件拼起来：yfinance 取茅台日线、跑 50/200 双均线策略、扣交易成本、和买入持有对比，最后打印全部绩效指标。

python
import numpy as np
import pandas as pd
import yfinance as yf

TRADING_DAYS = 252
COST_RATE = 0.0015  # 单边综合成本：佣金 + 印花税 + 滑点


# ---------- 1. 取数 ----------
def load_prices(symbol, start, end):
    df = yf.download(symbol, start=start, end=end,
                     auto_adjust=True, multi_level_index=False)
    return df[["Open", "High", "Low", "Close", "Volume"]].dropna()


# ---------- 2. 生成信号 ----------
def sma_crossover_signal(close, fast=50, slow=200):
    """双均线：快线在慢线上方持仓，下方空仓。返回 0/1 序列。"""
    sma_fast = close.rolling(fast).mean()
    sma_slow = close.rolling(slow).mean()
    signal = (sma_fast > sma_slow).astype(int)
    signal[sma_slow.isna()] = 0  # 慢线还没形成时不交易
    return signal


# ---------- 3. 回测主循环 ----------
def backtest(prices, fast=50, slow=200, cost_rate=COST_RATE):
    close = prices["Close"]
    signal = sma_crossover_signal(close, fast, slow)

    # 核心：shift(1) 让 T 日信号在 T+1 日才生效
    position = signal.shift(1).fillna(0)

    daily_return = close.pct_change().fillna(0)
    gross_return = position * daily_return

    # 换手率 = 仓位变化，用于扣成本
    turnover = position.diff().abs().fillna(0)
    net_return = gross_return - turnover * cost_rate

    result = pd.DataFrame({
        "Close": close,
        "Signal": signal,
        "Position": position,
        "Daily_Return": daily_return,
        "Gross_Return": gross_return,
        "Net_Return": net_return,
        "Turnover": turnover,
    })
    result["Strategy_NAV"] = (1 + net_return).cumprod()
    result["Benchmark_NAV"] = (1 + daily_return).cumprod()
    return result


# ---------- 4. 绩效指标 ----------
def cumulative_return(returns):
    return (1 + returns.fillna(0)).prod() - 1


def annualized_return(returns):
    n = returns.notna().sum()
    if n == 0:
        return np.nan
    return (1 + cumulative_return(returns)) ** (TRADING_DAYS / n) - 1


def max_drawdown(nav):
    return (nav / nav.cummax() - 1).min()


def sharpe_ratio(returns, risk_free=0.02):
    r = returns.dropna()
    if len(r) < 2 or r.std() == 0:
        return np.nan
    excess = r - risk_free / TRADING_DAYS
    return np.sqrt(TRADING_DAYS) * excess.mean() / r.std()


def win_rate(returns):
    active = returns[returns != 0].dropna()
    if len(active) == 0:
        return np.nan
    return (active > 0).sum() / len(active)


def profit_loss_ratio(returns):
    active = returns[returns != 0].dropna()
    wins = active[active > 0]
    losses = active[active < 0]
    if len(wins) == 0 or len(losses) == 0:
        return np.nan
    return wins.mean() / abs(losses.mean())


def summarize(result, label="Strategy"):
    net = result["Net_Return"]
    print(f"===== {label} =====")
    print(f"累计收益  : {cumulative_return(net):.2%}")
    print(f"年化收益  : {annualized_return(net):.2%}")
    print(f"最大回撤  : {max_drawdown(result['Strategy_NAV']):.2%}")
    print(f"夏普比率  : {sharpe_ratio(net):.2f}")
    print(f"胜率      : {win_rate(net):.2%}")
    print(f"盈亏比    : {profit_loss_ratio(net):.2f}")
    print(f"换手次数  : {int(result['Turnover'].sum())}")
    print(f"持股累计  : {cumulative_return(result['Daily_Return']):.2%}")
    print(f"年化超额  : {annualized_return(net) - annualized_return(result['Daily_Return']):.2%}")


# ---------- 5. 执行 ----------
if __name__ == "__main__":
    prices = load_prices("600519.SS", "2019-01-01", "2024-01-01")
    result = backtest(prices, fast=50, slow=200)
    summarize(result, "SMA 50/200 贵州茅台")

    # 净值曲线对比
    ax = result[["Strategy_NAV", "Benchmark_NAV"]].plot(
        figsize=(12, 6), title="SMA 50/200: Strategy vs Buy & Hold"
    )
    ax.set_xlabel("Date")
    ax.set_ylabel("NAV (start = 1.0)")

跑完之后应该看到两个现象：

  1. 双均线策略的最大回撤明显小于买入持有，但累计收益往往跑不赢。这是趋势跟踪的典型特征——它靠躲开大跌创造价值，而不是靠抓住大涨。
  2. 慢线是 200 日，前 200 个交易日几乎不交易，前面那段净值是一条水平线。回测区间只有一两年时，样本薄到不足以判断策略优劣。

最小骨架版本 #

如果只想要一个最朴素的骨架——没有成本、没有基准，只呈现「策略 vs 持股」的累计收益对比：

python
import yfinance as yf
import pandas as pd
import matplotlib.pyplot as plt

# 获取股票数据
symbol = "600519.SS"  # 茅台股票代码
start_date = "2019-01-01"
end_date = "2021-01-01"

data = yf.download(symbol, start=start_date, end=end_date)

# 计算移动平均
data["SMA_50"] = data["Close"].rolling(window=50).mean()
data["SMA_200"] = data["Close"].rolling(window=200).mean()

# 初始化交叉信号列
data["Signal"] = 0

# 计算交叉信号
data.loc[data["SMA_50"] > data["SMA_200"], "Signal"] = 1
data.loc[data["SMA_50"] < data["SMA_200"], "Signal"] = -1

# 计算每日收益率
data["Daily_Return"] = data["Close"].pct_change()

# 计算策略信号的收益率（shift(1) 是为了避免未来数据的偏差）
data["Strategy_Return"] = data["Signal"].shift(1) * data["Daily_Return"]

# 计算累计收益
data["Cumulative_Return"] = (1 + data["Strategy_Return"]).cumprod()

# 绘制累计收益曲线
plt.figure(figsize=(10, 6))
plt.plot(data["Cumulative_Return"], label="Strategy Cumulative Return", color="b")

zipline #

zipline 是一个用于量化金融研究和算法交易的开源框架。它由 Quantopian 公司开发，旨在为研究员和开发者提供一个方便的工具，用于构建、测试和执行量化交易策略。

它最重要的设计是事件驱动 + context 状态机：你把策略写成 initialize 和 handle_data 两个函数，框架负责在每个交易日按顺序调用它们，并自动处理数据对齐、订单撮合、组合估值。你不需要自己写 shift(1)，因为框架层面就已经隔绝了未来函数。

推荐用 conda 安装，避免后面出现奇奇怪怪的问题（这里使用 Anaconda）：

bash
conda install -c conda-forge zipline

接下来登录 quandl 官网注册，获得 api key：https://data.nasdaq.com/account/profile。设置好之后下载数据包，并用 zipline bundles 确认 ingest 成功（zipline 默认取最新的一份）：

bash
# Windows
set QUANDL_API_KEY=your_key
# macOS / Linux
export QUANDL_API_KEY=your_key-zZQN

zipline ingest -b quandl
zipline bundles

现在做一个简单的测试。以下是是一个简单的 Zipline 策略脚本：

python
from zipline.api import order, record, symbol


def initialize(context):
    pass


def handle_data(context, data):
    order(symbol("AAPL"), 10)
    record(AAPL=data.current(symbol("AAPL"), "price"))

以上是一个简单的策略：在每个交易日都以当前价格买入 10 股苹果公司的股票，并记录每个交易日的 AAPL 当前价格。

  • order(symbol('AAPL'), 10)：在每个交易日以当前价格购买 10 股苹果（AAPL）的股票，symbol('AAPL') 用于获取 AAPL 的股票符号。
  • record(AAPL=data.current(symbol('AAPL'), 'price'))：记录每个交易日 AAPL 的当前价格，data.current(...) 用于取当前股价。

然后执行：

bash
zipline run -f my_strategy.py --start 2016-1-1 --end 2018-1-1 -o buyapple_out.pickle --no-benchmark

执行成功后，会生成 buyapple_out.pickle 文件，可以使用 pickle 模块读取它。

命令说明：

  • zipline run： 启动 Zipline 运行回测。
  • -f my_strategy.py： 指定策略文件，即包含策略逻辑的 Python 文件。
  • --start 2016-1-1 和 --end 2018-1-1： 指定回测的起止日期。
  • -o buyapple_out.pickle： 指定输出文件名，文件包含交易记录、性能指标等回测结果。
  • --no-benchmark： 禁用基准（benchmark）。回测中有时会用某个基准来比较策略表现，这个选项表示不使用任何基准。

pickle 模块用于序列化和反序列化对象，可以方便地将对象保存到文件或从文件中加载对象。读取方式：

pyfolio #

pyfolio 是 zipline 的官方搭档，专门做绩效归因。create_full_tear_sheet() 一行代码就能输出十几张分析图：

python
import pandas as pd
import pyfolio as pf

# 从 zipline 结果中取出收益序列
returns = buyapple_out_data["returns"]
returns.index = pd.to_datetime(returns.index)

# 一行生成完整绩效报告
pf.create_full_tear_sheet(returns, benchmark_rets=None)

它生成的报告通常包括：累计收益与回撤叠加图（一眼看出收益是不是靠躲过大回撤换来的）、月度收益热力图（按年 × 月排布，能看出策略在哪些年月失效）、滚动夏普比率（3~6 个月窗口滚动，检验稳定性而非全期平均）、收益分布图（正偏还是负偏，决定尾部风险）、分位数与尾部统计（最差 1% 的日子到底有多惨）、换手率与持仓集中度（换手太高说明成本会吃掉收益）。

pyfolio 的价值不在画图好看，而在于强制你用多维度看同一个策略。只看一个总收益率，很容易被单一时段的运气骗过去。

八、怎么判断一次回测「值得相信」 #

指标算全之后还有一道关卡：这个结果能不能信。按下面的顺序自查：

  1. 样本外验证。 把数据切成训练段和测试段（比如 2015—2020 训练、2021—2024 测试），参数只用训练段调。测试段表现直接崩掉，说明参数过拟合。
  2. 参数敏感性。 把 fast 从 50 改成 45、55、60，看收益曲线是平滑变化还是断崖下跌。只有 50/200 好、其他都差，基本可以确定是曲线拟合。
  3. 成本压力测试。 把单边成本从万 15 提到万 30、万 50，看策略是否还能盈利。稳健的策略对成本变化有容忍度。
  4. 子区间稳定性。 分别统计牛市、熊市、震荡市的表现。只在单边行情赚钱的策略不是策略，是杠杆。
  5. 对照基准。 扣掉成本后跑不赢沪深 300，这个策略的存在意义就是负的——你还多付了精力和手续费。

一份回测报告如果没有说明复权方式、成交时点、成本假设、基准选择这四件事，那它给出的任何收益率数字都不具备参考价值。

九、小结 #

回测的目的不是造出一条漂亮的曲线，而是估算策略在真实约束下还能剩多少收益。约束包括：信息只能来自过去（shift(1)、center=False、公告日对齐）、每一笔交易都要付钱（佣金、印花税、滑点）、本金要承受得住回撤（最大回撤）、表现要放在参照系里看（基准、超额收益）。

把这几条守住，即使算出来的年化只有 8%，那 8% 也比虚高的 40% 有价值得多。数据获取和绘图的完整链路见《量化数据获取与图表绘制》，两者的衔接点是那张净值曲线图——它既是回测的终点，也是下一轮迭代的起点。
