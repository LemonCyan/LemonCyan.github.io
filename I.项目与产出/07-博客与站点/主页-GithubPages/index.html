GitHub Pages 提供免费的静态网页托管服务，适合用来部署 Hexo、Hugo 等静态博客。本文整理两种 Pages 模式的差异、仓库搭建流程、自定义域名与 DNS 解析配置，以及实际使用中的限制。

1. User Pages 与 Project Pages 的区别 #

GitHub Pages 区分两种站点类型，两者的仓库命名、分支规则与访问路径不同：

特性 User / Organization Pages（个人/组织主站） Project Pages（项目站点）
仓库命名格式 <username>.github.io（必须全小写） 任意项目名（如 my-project）
数量限制 每个 GitHub 账户只能创建 1 个 数量无限制
默认访问 URL https://<username>.github.io https://<username>.github.io/<project-name>
常用发布分支 main（或 master）根目录 gh-pages 分支或 main 分支下的 /docs 目录
自定义 404 支持 支持根目录下自定义 404.html 只有绑定了独立域名时才生效，否则走用户主站 404

实际规划时，通常用 User Pages 搭建个人博客主站，把具体开源项目的演示 Demo 或文档挂在 Project Pages。

2. 搭建 User Pages 托管仓库 #

2.1 创建仓库 #

在 GitHub 新建仓库，仓库名称必须严格对应你的 GitHub 用户名：

  • 仓库名：<username>.github.io（例如账号是 luhuaCyan，仓库名必须填 luhuaCyan.github.io）。
  • 权限属性：建议设为 Public。Private 仓库开通 GitHub Pages 需要 GitHub Pro / Team 付费计划。

2.2 开启 Pages 服务 #

  1. 进入仓库页面，点击 Settings -> Pages。
  2. 在 Build and deployment 下方的 Source 下拉框中：
    • 如果使用本地编译推送静态产物，选择 Deploy from a branch，分支选择 main，目录选择 / (root)，点击 Save。
    • 如果使用云端自动化构建，选择 GitHub Actions。

3. 自定义域名与 DNS 解析配置 #

把博客绑定到自己的独立域名（如 blog.example.com 或根域名 example.com），免受默认二级域名的限制。

flowchart LR
    Browser[访客浏览器] -->|DNS 查询| DNS[域名 DNS 解析服务]
    DNS -->|blog CNAME| GHNode[GitHub Pages 节点 username.github.io]
    DNS -->|Apex A 记录 / CF 扁平化| GHNode
    GHNode --> StaticSite[返回博客静态资源]

3.1 在 Hexo 源文件中持久化 CNAME #

如果直接在 GitHub 网页上添加自定义域名，下一次本地执行 hexo deploy 覆盖仓库后，GitHub 仓库根目录下的 CNAME 文件会被冲掉，导致域名解绑。

正确的做法：在 Hexo 源码目录的 source/ 下新建一个没有扩展名的文件 CNAME，里面只写你的域名：

text
blog.example.com

Hexo 执行构建时会把 source/CNAME 原样复制到 public/CNAME 并推送到仓库根目录，域名配置不会丢失。

3.2 DNS 解析记录配置 #

根据使用二级子域名还是顶级根域名，解析方式有所不同：

方案 A：二级域名（推荐，如 blog.example.com） #

在 DNS 控制台添加一条 CNAME 记录：

  • 主机记录：blog
  • 记录类型：CNAME
  • 记录值：<username>.github.io.（注意部分 DNS 服务商末尾需带句点）

方案 B：顶级根域名（Apex Domain，如 example.com） #

传统 DNS 规范（RFC 1034）不允许在根域名配置 CNAME 记录。两种解决方式：

  1. DNS 服务商支持 CNAME Flattening（如 Cloudflare、DNSPod）： 直接将根域名 @ CNAME 到 <username>.github.io，由解析商在底层自动转成 A 记录返回。
  2. 配置官方 A 记录： 在 DNS 控制台为根域名 @ 添加 4 条 A 记录，分别指向 GitHub 官方服务器 IP：
    text
    185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153

3.3 开启 HTTPS 强制跳转 #

进入发布仓库 Settings -> Pages -> Custom domain：

  1. 填入自定义域名并保存，GitHub 会自动启动 DNS 检查。
  2. 勾选 Enforce HTTPS。
  3. 证书签发由 Let's Encrypt 自动完成，通常耗时 5 到 30 分钟。在证书就绪前勾选框可能为灰色不可选状态，等待 DNS 解析在全球生效后再刷新勾选。

4. 平台配额与实际限制 #

GitHub Pages 适合展示静态内容，但存在明确的使用边界：

  • 单仓库容量限制：建议不超过 1GB，超过后可能会触发警示邮件。大图和音视频等资源应外置到图床或对象存储。
  • 流量限制：每月软性上限 100GB。个人技术博客很难跑满，但若遭受刷量需及时配合 Cloudflare 做缓存与限流。
  • 构建并发限制：每小时构建触发上限为 10 次。
  • 无服务端执行环境：不支持 PHP、Python、Node 等后端动态运行环境。表单、评论、全文检索均需依靠前端 API 或第三方微服务完成。
