静态博客缺乏后端数据库，早期多采用 Gitalk 或 Utterances 基于 GitHub Issues 充当评论存储。但随着博文增加，Issues 列表中充斥着读者留言，导致实际的代码缺陷跟踪与评论混杂。Giscus 将评论底层迁移至 GitHub Discussions，支持表情反应（Reactions）、盖楼回复以及深浅色主题自适应，且无需维护独立服务器。

1. Giscus 交互机制 #

Giscus 本质上是一个轻量的前端客户端，通过 GitHub GraphQL API 与仓库的 Discussions 板块交互：

sequenceDiagram
    autonumber
    actor Reader as 访客
    participant Blog as 博客文章页 (Giscus iframe)
    participant App as Giscus 服务 (giscus.app)
    participant Repo as GitHub Discussions (评论存储)

    Note over Blog: 滚动触发展示区域 (开启 lazyload)
    Blog->>App: 请求当前文章的评论数据 (传递 pathname / title)
    App->>Repo: 调用 GraphQL API 查询对应 Discussion 讨论串
    Repo-->>App: 返回讨论内容与楼层回复
    App-->>Blog: 渲染评论列表与回复输入框
    Reader->>Blog: OAuth 登录并提交评论 / 点赞
    Blog->>Repo: 写入对应 Discussion 讨论节点

2. GitHub 仓库准备工作 #

2.1 确认仓库权限 #

  • 挂载 Discussions 的 GitHub 仓库必须是 Public（公开）。Private 仓库的 Discussions 无法被访客匿名读取。

2.2 开启 Discussions 功能 #

  1. 打开博客公开托管仓库（如 your-username/your-username.github.io）的 Settings 页面。
  2. 在 General -> Features 区域中，勾选 Discussions。

2.3 规划分类权限 #

点击仓库顶部的 Discussions 标签页，默认存在 General、Ideas、Q&A、Announcements 等分类。

推荐选用 Announcements 分类：

  • 该分类在 GitHub 默认权限策略中，仅允许仓库 Owner 或 Maintainer 发起主讨论帖，普通访客仅能跟帖回复。
  • 这样可以避免访客直接在 GitHub 网页端的 Discussions 列表中随意建立混乱的主帖，保持板块整洁。

3. 安装与配置 Giscus #

3.1 安装 Giscus GitHub App #

  1. 访问 GitHub Apps - Giscus。
  2. 点击 Install。
  3. 授权范围选择 Only select repositories，选中用于存放评论的博客公开仓库，保存。

3.2 提取核心配置参数 #

打开 Giscus 配置工具（giscus.app/zh-CN）：

  1. 语言：选择 简体中文。
  2. 仓库：输入 your-username/your-username.github.io，检查下方是否显示「满足所有条件」。
  3. 页面与 Discussion 映射关系：
    • 选择 URL pathname（如 /posts/7a8b9c0d.html）。不要选 Title，避免日后微调文章标题导致原有的讨论串断开脱钩。
  4. Discussion 分类：选择 Announcements。
  5. 特性开关：
    • 勾选 启用 reactions (表情反应)。
    • 评论框位置：选择 顶部 (Top)。
    • 主题：选择 preferred_color_scheme，随访客浏览器的暗黑/浅色模式动态切换。
  6. 提取标识： 在页面下方自动生成的 script 标签中，复制两项关键 ID：
    • data-repo-id（格式如 R_kgDOHxxxxx）
    • data-category-id（格式如 DIC_kwDOHxxxxx）

4. Hexo 主题端配置接入 #

以 Stellar 主题为例，编辑 _config.theme.stellar.yml 或 themes/stellar/_config.yml 中的 comments 模块：

yaml
comments:
  service: giscus                          # 指定评论引擎
  comment_title: 讨论交流
  lazyload: true                           # 开启懒加载，进入视口时再加载 iframe
  
  giscus:
    src: https://giscus.app/client.js
    data-repo: your-username/your-username.github.io
    data-repo-id: R_kgDOHxxxxxx             # 填入提取的 repo-id
    data-category: Announcements
    data-category-id: DIC_kwDOHxxxxxx       # 填入提取的 category-id
    data-mapping: pathname                  # 映射规则严格保持与后台一致
    data-strict: 0
    data-reactions-enabled: 1
    data-emit-metadata: 0
    data-input-position: top
    data-theme: preferred_color_scheme
    data-lang: zh-CN
    data-loading: lazy
    crossorigin: anonymous

5. 单篇控制与常见问题 #

5.1 单独关闭指定文章的评论 #

如果某篇文章属于纯通知或归档内容，不想开放评论区，直接在 Markdown 文档顶部的 Front-matter 中显式声明：

markdown
---
title: 归档日志
date: 2026-03-01
comments: false
---

5.2 首次打开文章评论区空白 #

  • Giscus 的机制是：第一位访客在文章页提交首条评论前，GitHub 仓库并不会预先生成对应的 Discussion 帖子。首次加载只展示「暂无评论」与输入框。
  • 当首次有人发表评论或打点表情时，Giscus App 会自动以当前文章的 pathname 作为标题在仓库中创建一条 Discussion，后续访客便可在该帖下盖楼。

5.3 国内访问连通性 #

由于 Giscus 依赖 giscus.app 托管脚本与 GitHub GraphQL 接口，国内部分地区可能存在偶发连接延迟或无法完成 GitHub OAuth 授权的问题。如果站点的受众集中在国内网络，可在评论区上方添加提示，或在主题中预留备用的免登录评论服务（如 Waline 或 Twikoo）。
