创建新ARM工程

在 Eclipse 中手搓 ARM 裸机工程与 J-TAG 仿真调试指南 #

很多刚接触 ARM 裸机开发的人，习惯了 Keil 一键生成工程，换到 Eclipse 这种通用 IDE 就有点抓瞎。实际上，咱们通过手搓 Makefile、链接脚本（map.lds）和初始化脚本，能更加清晰地看懂程序是怎么在板子上跑起来的。

下面咱们以 Exynos 4412 开发板为例，完整走一遍新建工程、写汇编、编译和 GDB 调试流程。

一、 创建新 ARM 工程 #

直接使用 Eclipse 默认的 Empty Project 有时会遇到找不到 Makefile 而编译失败的玄学问题。所以咱们直接新建 Makefile Project，让所有的编译规则都归我们自己控制。

  1. 新建 C 工程：在 Eclipse 菜单选择 File -> New -> C Project。
  2. 选择项目类型：在弹出的对话框中，输入工程名，项目类型选择 Makefile Project 中的 Empty Project。
  3. 完成创建：点击 Finish。此时工程上可能会出现红色的差号，这是因为还没建 Makefile，别慌，待会儿写完 Makefile 编译一次差号就消失了。

二、 关键工程文件手搓 #

我们需要在工程根目录下，建立以下 4 个关键文件。通过 File -> New -> Other -> General -> File 新建它们：

  1. Makefile：编译规则定义。
  2. map.lds：链接脚本，控制代码段/数据段的内存排布。
  3. start.s：汇编启动文件，控制 LED 闪烁。
  4. Exynos4412.init GDB 初始化脚本。

1. 汇编源文件 (start.s) #

咱们手写一段简单的 LED 闪烁汇编，控制 GPF3 对应的 LED4：

.equ   GPF3CON,   0x114001E0 
.equ   GPF3DAT,   0x114001E4 

.text 
.globl _start 
_start: 
    LDR   R0, =GPF3CON 
    LDR   R1, =0x10000 
    STR   R1, [R0]           @ 写控制寄存器，设置 GPF3_4 引脚为输出模式 

LOOP: 
    LDR   R0, =GPF3DAT 
    MOV   R1, #0x10          @ 点亮 LED4 
    STR   R1, [R0] 
    LDR   R2, =0xFFFFFF      @ 软件延时 
LOOP1: 
    SUB   R2, R2, #1 
    CMP   R2, #0 
    BNE   LOOP1 

    MOV   R1, #0x0           @ 熄灭 LED4 
    STR   R1, [R0] 
    LDR   R2, =0xFFFFFF      @ 软件延时 
LOOP2: 
    SUB   R2, R2, #1 
    CMP   R2, #0 
    BNE   LOOP2 
    B     LOOP 
    
    .end

2. 链接脚本 (map.lds) #

控制生成的二进制文件在内存中的起始地址（这里定位到 0x40008000 内存处），并确保启动汇编 start.o 放在最开头。

OUTPUT_FORMAT("elf32-littlearm", "elf32-littlearm", "elf32-littlearm")
OUTPUT_ARCH(arm)
ENTRY(_start)
SECTIONS
{
    . = 0x40008000;
    . = ALIGN(4);
    .text :
    {
        start.o(.text)
        *(.text)
    }
    . = ALIGN(4);
    .rodata : 
    { *(.rodata) }
    . = ALIGN(4);
    .data : 
    { *(.data) }
    . = ALIGN(4);
    .bss :
    { *(.bss) }
}

3. 编译规则文件 (Makefile) #

这里调用交叉编译工具链 arm-none-eabi- 来编译、链接、剥离出二进制 bin，并生成反汇编 start.dis 用于调试。

⚠警告

Makefile 中的命令行开头必须使用 TAB 键缩进，复制下面内容时请注意别搞成空格了。

makefile
all: start.s
	arm-none-eabi-gcc-4.6.2 -O0 -g -c -o start.o start.s
	arm-none-eabi-ld start.o -Tmap.lds -o start.elf
	arm-none-eabi-objcopy -O binary -S start.elf start.bin
	arm-none-eabi-objdump -D start.elf > start.dis

clean:
	rm -f *.o *.elf *.bin *.dis

4. GDB 初始化文件 (Exynos4412.init) #

当 GDB 连接上仿真器时，自动暂停 CPU 并进行复位。

target remote localhost:3333
monitor halt reset

保存所有文件，点击主菜单中的 Project -> Build All 进行编译。如果配置没问题，控制台会输出编译成功信息，红叉消失，并生成 start.elf 和 start.bin。

三、 在线仿真调试工程 #

1. 配置 FS-JTAG 仿真工具 #

  1. 打开配套的 FS_JTAG 调试软件。
  2. 在 Target 选项中选择对应芯片：exynos4412。
  3. 将通信速率（TCK Speed）设置为 200kHz 左右。
  4. 点击 Connect 按钮。如果连接成功，该按钮将变成 Disconnect。
ℹ笔记

如果此时开发板上还没有跑程序，仿真器可能会弹一些错误报告，这属于正常现象，直接忽略。

2. 配置 Eclipse 调试选项 #

我们需要使用 Eclipse 的 Zylin Embedded debug (Native) 插件来接管调试：

  1. 在 Eclipse 菜单中选择 Run -> Debug Configurations。
  2. 鼠标双击或右键点击 Zylin Embedded debug (Native)，选择 New 新建一个配置。
  3. Main 选项卡：
    • Project：点击 Browse，选择咱们刚才建的 LED 工程。
    • C/C++ Application：选择生成的 ELF 可执行文件，比如 start.elf。
  4. Debugger 选项卡 -> Main 子卡：
    • GDB debugger：填入你本地的交叉编译 GDB 路径，例如 C:\Program Files\yagarto\bin\arm-none-eabi-gdb.exe。
    • GDB Command file：浏览并选中工程根目录下的 Exynos4412.init 文件。
  5. Commands 选项卡： 在 Command 窗口里怼入以下几行调试初始化命令，保证连上后加载程序并断在第一行：
    load
break _start
c
  6. 点击 Apply 存盘，然后点击 Debug 按钮开始联机调试。

四、 调试状态说明 #

启动后，Eclipse 会自动切换到 Debug 视图：

  • 程序会停在 _start 第一行断点处，你可以通过上方调试按钮进行 单步调试 (Step Into)、单步跳过 (Step Over) 或者 全速运行 (Resume)。
  • 查看变量：通过 Variables 窗口可以实时观察当前循环中变量的值。
  • 查看寄存器：通过 Registers 窗口可以查看到 ARM 核心的通用寄存器 R0 ~ R12，以及当前的状态寄存器 CPSR 状态。
  • 注意点：在 Debug 调试时，确保 Debug 面板里只保留当前这一个正在运行的调试项，如果有多余的，右键 Terminate 掉，避免通信冲突。
