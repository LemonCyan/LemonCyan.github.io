ARM 指令集 VS Thumb 指令集

ARM 指令集 VS Thumb 指令集：代码密度、寄存器访问与状态切换详解 #

在嵌入式底层开发和固件逆向中，咱们经常会遇到 ARM 和 Thumb 两种指令集状态的切换。搞清楚它们的设计动机和限制，能帮咱们更好地做代码体积优化和混合编程。

一、 核心概念与代码密度 #

1. 什么是代码密度？ #

代码密度是指单位存储空间中包含的指令个数。

  • ARM 指令：固定宽度为 32 位 (4 字节)。
  • Thumb 指令：固定宽度为 16 位 (2 字节)，可以看作是 ARM 指令集的压缩子集。
✦提示

直观对比：假设有 1KB 的存储空间，最多只能存放 256 条 ARM 指令；而如果使用 Thumb 指令，则可以塞进 512 条。对于 Flash 容量吃紧的低成本微控制器（MCU）来说，Thumb 指令集的代码密度优势非常明显。

2. Thumb 的定位与限制 #

Thumb 不是一个独立的处理器体系结构。Thumb 状态下只需要支持最通用的功能，在必要时，它必须依赖 ARM 指令集来完成底层操作：

  • 异常处理：ARM 架构规定，所有中断和异常发生时，处理器会自动切换进 ARM 状态执行对应的异常向量代码。
  • 缺失硬核功能：Thumb 状态下没有协处理器指令、没有信号量操作指令、无法直接访问 CPSR 或 SPSR 状态寄存器。

二、 Thumb 指令集与 ARM 指令集的具体区别 #

维度 ARM 指令集 Thumb 指令集
指令宽度 32-bit 16-bit
执行条件 几乎所有指令都可以条件执行（根据 CPSR 条件码） 只有跳转指令 B 允许条件执行，其他都是无条件执行
寄存器访问 可自由访问全部通用寄存器 R0 - R15 主要限制在低寄存器 R0 - R7
数据处理格式 3 地址格式（如 ADD R0, R1, R2） 大多数为 2 地址格式（如 ADD R0, R1，即 $R0 = R0 + R1$）
状态寄存器操作 支持 MRS / MSR 读写 CPSR/SPSR 不支持

1. 寄存器访问限制（R8 - R15 锁定） #

  • 通用限制：在 Thumb 状态下，单寄存器加载/存储（LDR / STR）以及批量压栈/出栈（LDM / STM）只能访问低寄存器 R0 - R7。
  • 高寄存器特例：只有 MOV 和 ADD 指令被允许访问高寄存器 R8 - R15（如 SP、LR、PC），但要注意：访问高寄存器的 MOV 和 ADD 指令不会更新 CPSR 状态标志位。

三、 混合编程与状态切换 #

为了在同一个工程中兼顾 ARM 指令的强大功能（如异常处理、复杂数学计算）和 Thumb 指令的体积优势，我们需要在两种状态间来回横跳。

1. 汇编伪指令声明 #

在汇编源码中，需要使用伪指令告知编译器后续代码的指令类型：

  • .code 32 (或 CODE32)：声明接下来的代码编译为 32 位 ARM 指令。
  • .code 16 (或 CODE16)：声明接下来的代码编译为 16 位 Thumb 指令。

2. 状态切换指令 BX / BLX #

处理器切换状态的唯一方法，是通过分支跳转指令的特殊行为来实现。

  • BX Rn (Branch and Exchange)： 跳转到通用寄存器 Rn 指定的地址处执行。
    • 切入 Thumb 状态：如果目标地址的第一位（LSB）为 1，处理器将 CPSR 中的 T 位（T-bit）置 1，强行切换进入 Thumb 状态。
    • 切入 ARM 状态：如果目标地址的第一位（LSB）为 0，则切换/保持在 ARM 状态。
; 汇编示例：ARM 状态跳转到 Thumb 状态执行
.code 32                ; 声明 ARM 代码
start_arm:
    ADR     R0, start_thumb + 1  ; 获取 Thumb 函数地址，并将最低位置 1
    BX      R0          ; 跳转并切换到 Thumb 状态

.code 16                ; 声明 Thumb 代码
start_thumb:
    ADD     R1, R1, #1  ; 此时跑在 16 位 Thumb 指令集下
    ; ...
