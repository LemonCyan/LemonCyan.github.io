嵌入式中的gsnap截屏

Linux 系统的 FrameBuffer 机制，会把屏幕上的每个点映射成一段线性内存空间，程序就可以通过改变这段内存的值来改变屏幕上某一点的颜色。屏幕色彩的原始数据保存在/dev/fb0 文件。

sh
 cat /dev/fb0 > fb.raw        #读取该文件获得数据
 cat fb_data.raw > /dev/fb0   #数据回显到 framebuffer

这种原始数据无法通过简单的工具直接查看，特别是在精简的嵌入式 Linux 系统上。因此，通过工具 gsnap。这个工具可以将 framebuffer 中的数据直接保存为 png 或者 jpeg 格式的图片。

打开 gsnap 的 Makefile 文件，该源码依赖 libpng、libjpeg、zlib、libmath 四种库。

交叉编译 libjpeg #

进入到源码目录，执行

cpp
./configure --host=arm-linux --prefix=./jpeg_install/

然后执行

cpp
make
make install

在安装目录 ./jpeg_install/ 得到交叉编译过的库。

交叉编译 zlib #

由于 zlib 中的 configure 并未提供--host 参数，因此需要为它手动指明交叉编译器：

cpp
export CC=arm-fsl-linux-gnueabi-gcc
./configure --prefix=./z_install/
make
make install

交叉编译 libpng #

zlib 是 libpng 的依赖，因此在交叉编译 libpng 之前，必须首先编译 zlib libpng 中提供有 Linux 平台下的 Makefile 例程，可以直接修改使用。进入到 libpng 的源码目录，执行拷贝 cp scripts/makefile.linux Makefile，打开 Makefile 修改，修改交叉编译器名称和依赖的 zlib 的路径。执行 make、makeinstall 得到头文件和库文件。

交叉编译 gsnap #

将上述得到的库文件和头文件分别集中拷贝到自行建立的 lib 和 includes 目录下，并修改 gsnap 的 Makefile。执行 make 后就能得到可执行文件 gsnap。

将得到的 gsnap 可执行文件拷贝到目标板的/usr/bin 目录下，执行截屏命令：

cpp
gsnap fb.jpg /dev/fb0
