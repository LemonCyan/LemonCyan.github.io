第三方驱动的移植 #

{//第三方驱动移植 {若该设备使用到设备树，需先修改设备数文件，将设备添加至设备树中 设备树与驱动的编译方式无关}

  1. 把led驱动放到内核源码顶层目录下的driver/char/目录下 {//方法1：直接修改driver/char目录下的Makefile 添加：obj-y += fs4412_led_drv.o 编译内核：make uImage cp uImage /tftpboot 交叉编译应用程序：arm-none-linux-gnueabi-gcc fs4412_led_app.c cp a.out /source/rootfs 在开发板上测试： 创建设备节点： mknod /dev/led c 500 0 //c:表示字符设备，500: 主设备号，表属于哪一类设备，0：次设备号，表示这类设备中的具体哪一个 ./a.out } {//方法2：通过make menuconfig进行选配，决定是否将驱动编译到内核中
  2. 修改driver/char目录Kconfig，增加一项菜单 添加： 11 config FS4412_LED //FS4412_LED不是菜单的名字，它是和Makefile进行关联的， //最终会做顶层目录下的.config增加一项 CONFIG_FS4412_LED=y/m 12 bool "FS4412 led device support" //FS4412 led device support是菜单的名字 bool：表示菜单有两种状态y/n [] tristat:表示菜单有三种状态y/n/m <> 13 default n //菜单的默认状态是不选中 14 help 15 support led device for FS4412 board make menuconfig 把led的驱动选上
  3. 修改Makefile obj-$(CONFIG_FS4412_LED) += fs4412_led_drv.o 然后Kconfig就和Makefile关联起来了 } {//方法3：把驱动编译成一个模块

make menuconfig 把led的驱动菜单选为M make uImage //cp 这个内核中没有灯的驱动 make modules //把led的驱动编译成了模块 drivers/char/fs4412_led_drv.ko 把驱动模块放到/source/rootfs目录下 在开发板上测试：

  1. 装驱动 insmod fs4412_led_drv.ko
  2. 创建设备节点： mknod /dev/led c 500 0
  3. ./a.out
  4. rmmod fs4412_led_drv } {//方式4：把驱动单独拿出来编译 需要一个Makefile MODNAME = fs4412_led_drv #KERDIR = /lib/modules/uname -r/build/ KERDIR = /home/linux/system/test-kernel/linux-3.14/

all: (MAKE)−C(KERDIR) M=$(shell pwd)

clean: rm -rf *.ko *.o mod Mod

obj-m = $(MODNAME).o 编译生成.ko } }
