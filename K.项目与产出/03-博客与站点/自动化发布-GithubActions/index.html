正在思考并提取文章核心…

使用 Hexo 搭建静态博客时，将 Markdown 源文件与编译生成的 HTML 产物放在同一分支容易导致仓库体积膨胀，且草稿与敏感配置容易泄漏。最清晰的方案是将「私有源码仓库」与「公开静态托管仓库」解耦，本地只推 Markdown，由 GitHub Actions 在云端完成编译并自动分发。

1. 架构设计与仓库分离 #

源码与产物分离的架构如下：

flowchart TD
    Local["本地编辑 (Obsidian / Markdown)"] -->|git push origin main| SourceRepo["私有源码仓 (BlogDeploy)"]
    
    SourceRepo -->|触发 push 事件| Runner["GitHub Actions Runner (Ubuntu)"]
    
    subgraph CI["CI/CD 构建环境"]
        Runner --> Step1["1. 全量拉取源码与历史 (fetch-depth: 0)"]
        Step1 --> Step2["2. 根据 Git log 恢复文件修改时间戳"]
        Step2 --> Step3["3. 安装 Node.js 20 与依赖 (npm ci)"]
        Step3 --> Step4["4. 注入主题配置并执行 hexo generate"]
    end
    
    Step4 -->|Deploy Key 推送 public/| TargetGH["公开托管仓 (username.github.io)"]
    Step4 -->|Webhook / Git 触发| TargetCF["Cloudflare Pages 边缘节点"]

职责划分 #

  • 私有源码仓（如 BlogDeploy）：存放站点原始配置 _config.yml、source/_posts/ 原稿、草稿 _drafts/、主题配置及 package.json。仓库设为 Private。
  • 公开托管仓（如 username.github.io）：仅存放 Hexo 编译输出的 public/ 静态网页。仓库设为 Public，供 GitHub Pages 渲染服务。

2. 跨仓库授权：配置 SSH Deploy Key #

GitHub Actions 在源码仓库运行，要向独立的静态托管仓推送编译产物，必须配置专用密钥对授权写权限。

2.1 在本地生成专用密钥对 #

bash
ssh-keygen -t ed25519 -C "deploy@github.com" -f ./github-deploy-key -N ""

执行后得到两个文件：

  • github-deploy-key.pub（公钥）
  • github-deploy-key（私钥）

2.2 公开托管仓添加公钥 #

  1. 打开发布仓 username.github.io -> Settings -> Deploy keys -> Add deploy key。
  2. Title 填 ACTIONS_DEPLOY_KEY。
  3. Key 粘贴 github-deploy-key.pub 内容。
  4. 勾选 Allow write access，保存。

2.3 私有源码仓添加私钥 #

  1. 打开源码仓 BlogDeploy -> Settings -> Secrets and variables -> Actions -> New repository secret。
  2. Name 填 ACTIONS_DEPLOY_KEY。
  3. Secret 粘贴 github-deploy-key（私钥的完整内容，包含头部和尾部的破折号声明）。

3. GitHub Actions 工作流实战配置 #

在源码仓库创建 .github/workflows/deploy.yml：

yaml
name: Deploy Hexo Site

on:
  push:
    branches:
      - main  # 监听 main 分支的提交

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true  # 连续推送时自动取消旧任务，避免竞争

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout source code
        uses: actions/checkout@v4
        with:
          # 必须设为 0（拉取完整 Git 历史），否则无法获取历史修改时间戳
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Restore File Modification Timestamps
        run: |
          # Git 默认不会还原文件的本地 mtime，导致 Hexo 的 updated 时间全部变成当次构建时间
          # 这里用 git log 遍历还原每个文件的最后一次提交时间
          git ls-files -z | while read -d '' path; do 
            touch -d "$(git log -1 --format="@%ct" "$path")" "$path"
          done

      - name: Install Dependencies
        run: |
          npm ci || npm install
          npm install -g hexo-cli
          # 若主题以 npm 形式引入
          npm install hexo-theme-stellar

      - name: Inject Theme Configurations
        run: |
          # 将源码根目录下的外部主题配置文件覆盖到 node_modules
          if [ -f "_config.theme.stellar.yml" ]; then
            cp _config.theme.stellar.yml node_modules/hexo-theme-stellar/_config.yml
          fi
          if [ -f "_config.theme.stellar.widgets.yml" ]; then
            cp _config.theme.stellar.widgets.yml node_modules/hexo-theme-stellar/_data/widgets.yml
          fi

      - name: Build Static Files
        run: |
          hexo clean
          hexo generate

      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          deploy_key: ${{ secrets.ACTIONS_DEPLOY_KEY }}
          external_repository: your-username/your-username.github.io
          publish_branch: main
          publish_dir: ./public
          user_name: 'github-actions[bot]'
          user_email: 'github-actions[bot]@users.noreply.github.com'
          commit_message: "Auto Deploy: ${{ github.sha }}"
❢重要

fetch-depth: 0 和文件时间戳还原极其关键。如果不做还原，GitHub Actions 每次检出代码都会将文件的 mtime 重置为当前时间，Hexo 会把全站所有文章的最后更新时间标记为「今天」，导致时间线混乱。

4. Cloudflare Pages 边缘双轨加速部署 #

除了 GitHub Pages，可以将同一个私有源码仓直接接入 Cloudflare Pages，借助其全球 Anycast 边缘网络提高国内与海外的访问稳定性。

配置步骤 #

  1. 登录 Cloudflare 控制台，进入 Workers & Pages -> Create application -> Pages -> Connect to Git。
  2. 授权选择私有源码仓库 BlogDeploy。
  3. 构建参数设置：
    • Framework preset：None
    • Build command：npm install && npm install -g hexo-cli && hexo generate
    • Build output directory：public
    • Environment variables：添加环境变量 NODE_VERSION = 20
  4. 点击 Save and Deploy。此后每次向源码仓 main 分支推代码，Cloudflare 会在云端独立构建并在数十秒内分发至边缘节点。

5. 自动化搜索引擎收录提交（SEO API 推送） #

新文章发布后，依靠搜索引擎爬虫自然抓取耗时较长。可以在 GitHub Actions 构建成功后，提取 public/sitemap.xml 中的 URL 列表，通过 API 主动推送到百度与 Bing。

在 deploy.yml 的 Deploy to GitHub Pages 步骤后追加：

yaml
      - name: Push URLs to Baidu & Bing IndexNow
        if: success()
        run: |
          # 提取 sitemap 中的全部文章链接
          grep -Eo 'https://[a-zA-Z0-9./?=_-]+' public/sitemap.xml | sort -u > urls.txt
          
          # 1. 提交到百度搜索资源平台
          if [ -n "${{ secrets.BAIDU_PUSH_TOKEN }}" ]; then
            curl -s -H 'Content-Type:text/plain' \
              --data-binary @urls.txt \
              "http://data.zz.baidu.com/urls?site=https://your-domain.com&token=${{ secrets.BAIDU_PUSH_TOKEN }}"
          fi

          # 2. 提交到 Bing IndexNow
          if [ -n "${{ secrets.INDEXNOW_KEY }}" ]; then
            URL_LIST_JSON=$(jq -R -s -c 'split("\n")[:-1]' urls.txt)
            PAYLOAD=$(jq -n \
              --arg host "your-domain.com" \
              --arg key "${{ secrets.INDEXNOW_KEY }}" \
              --argjson urlList "$URL_LIST_JSON" \
              '{host: $host, key: $key, keyLocation: "https://your-domain.com/\($key).txt", urlList: $urlList}')
            curl -s -X POST -H 'Content-Type: application/json' \
              -d "$PAYLOAD" \
              "https://api.indexnow.org/indexnow"
          fi

在 GitHub 仓库 Secrets 中补充添加 BAIDU_PUSH_TOKEN 和 INDEXNOW_KEY 即可生效。
