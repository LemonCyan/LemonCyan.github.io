C/C++ 面试题大汇总（全景精选版） #

本文汇总 C/C++ 语言核心高频面试题，包含嵌入式程序员必知的 0x10 个经典基础问题（预处理器、死循环、数据声明、static/const/volatile、位操作、内存访问、中断 ISR、内存分配）、核心编程实现题（标准库函数模拟、链表算法）以及高频代码找错与综合问答解析。

想成为嵌入式程序员应知道的 0x10 个基本问题 #

1. 预处理器（Preprocessor）：一年有多少秒 #

题目：用预处理指令 #define 声明一个常数，用以表明 1 年中有多少秒（忽略闰年问题）。

c
#define SECONDS_PER_YEAR (60UL * 60UL * 24UL * 365UL)

考核核心要点：

  1. #define 基本语法规范（宏名与括号间不带多余符号，结尾绝不能加分号）。
  2. 懂得预处理器在预编译期会自动计算常量表达式的值，直接写乘法表达式比手算出一个巨大魔数更清晰且无任何运行时开销。
  3. 必须意识到 $60 \times 60 \times 24 \times 365 = 31,536,000$，在 16 位整型机器上（最大 32767）必定发生整型溢出，因此必须使用长整型后缀 L 或无符号长整型后缀 UL。

2. 预处理器：写一个“标准”宏 MIN #

题目：写一个“标准”宏 MIN，输入两个参数并返回较小的一个。

c
#define MIN(A, B) (((A) <= (B)) ? (A) : (B))

考核核心要点：

  1. 宏中每个参数及整个三目表达式必须严格用括号括起来，防止运算符优先级陷阱。
  2. 注意宏调用的副作用：如 least = MIN(*p++, b); 时，指针 p 可能会自增两次，违背本意。

3. 预处理器：#error 的作用 #

#error 指令用于在预编译阶段由编译器输出一条自定义的错误提示信息，并立即终止编译。常用于检查编译器版本、宏配置依赖或平台架构（如检查是否定义了特定的 CPU 架构宏）。

4. 死循环（Infinite loops） #

在嵌入式系统中编写无限循环的常用方式：

c
// 方式一：while(1)
while (1)
{
    // 主事件循环
}

// 方式二：for(;;)
for (;;)
{
    // 很多编译器将其优化为最精简的无条件跳转汇编
}

// 方式三：goto
Loop:
    // ...
    goto Loop;

5. 数据声明（Data declarations） #

用变量 a 给出下面的定义：

c
int a;             // 一个整型数（An integer）
int *a;            // 一个指向整型数的指针（A pointer to an integer）
int **a;           // 一个指向指针的指针，它指向的指针指向整型数（A pointer to a pointer to an integer）
int a[10];         // 一个有 10 个整型数的数组（An array of 10 integers）
int *a[10];        // 指针数组：一个有 10 个指针的数组，每个指针指向一个整型数
int (*a)[10];      // 数组指针：一个指向包含 10 个整型数数组的指针
int (*a)(int);     // 函数指针：一个指向函数的指针，该函数有一个整型参数并返回一个整型数
int (*a[10])(int); // 函数指针数组：一个包含 10 个函数指针的数组，每个函数接受一个整型参数并返回整型数

6. 关键字 static 的作用 #

在 C 语言中，static 具有三大核心作用：

  1. 修饰局部变量：改变局部变量的生命周期，使其分配在静态存储区，从程序启动一直存活到程序结束，且仅初始化一次；但其作用域仍被限制在该函数或复合语句内。
  2. 修饰全局变量：限制该全局变量的作用域，仅在当前源文件（编译单元）内可见，不同源文件可以定义同名的 static 全局变量而不会发生命名冲突（内部链接属性）。
  3. 修饰函数：限制该函数的作用域，仅能在当前源文件内被调用，避免函数符号全局暴露（内部链接属性）。

在 C++ 中，static 额外新增了两大面向对象特性： 4. 修饰类静态数据成员：属于整个类而非某个具体对象，所有实例共享同一份内存拷贝。 5. 修饰类静态成员函数：没有隐藏的 this 指针，只能直接访问类的静态数据成员和静态成员函数，无需实例化对象即可通过 ClassName::func() 调用。

7. 关键字 const 的深刻含义 #

const 在 C/C++ 中意味着只读（Read-Only），而非绝对字面常量。

c
const int a;       // a 是只读整型数
int const a;       // 与上一条完全等价
const int *a;      // 常量指针：指针指向的值不能通过 *a 修改，但指针 a 本身可以指向其他地址
int * const a;     // 指针常量：指针 a 本身的值（地址）一旦初始化便不能修改，但指向的值可以修改
int const * a const; // 错误语法，正确形式为 const int * const a：指向常整型数的常指针，内容和指针均不可修改

为什么在工程中极度看重 const：

  1. 提供接口意图：向调用者明确传达该参数是输入参数还是输出参数，保护数据不被意外窜改。
  2. 协助优化器生成高效代码：告知编译器该内存区域在执行期间不会被修改。
  3. 编译期安全防护：违反只读契约的代码在编译期就会报错拦截，将 Bug 扼杀在萌芽期。

8. 关键字 volatile 的含义与典型场景 #

volatile 提醒编译器该变量的值可能在编译器检测不到的外部因素下被改变（如硬件中断、外部外设状态变化、其他并发线程等）。因此，优化器每次用到该变量时必须从真实的内存地址中重新读取，而不能使用保存在 CPU 寄存器里的缓存副本。

三大典型应用场景：

  1. 并行外设的硬件寄存器（如状态寄存器、串口数据寄存器）；
  2. 中断服务子程序（ISR）中访问到的被主程序循环检测的全局标志位；
  3. 多线程应用程序中被多个线程并发共享的标志或同步变量。

进阶考察：

  1. 一个参数既可以是 const 还可以是 volatile 吗？
    可以。典型例子是只读的状态寄存器。它是 volatile 因为它随时可能被外部硬件硬件异步修改；它是 const 因为软件程序不应当也不允许去显式写入它。
  2. 一个指针可以是 volatile 吗？
    可以。例如当中断服务子程序中修改一个指向缓冲区的指针本身时，该指针必须声明为 volatile。
  3. 函数中的 volatile 陷阱：
    c
    // 错误代码
int square(volatile int *ptr) {
    return *ptr * *ptr;
}
    由于 *ptr 是 volatile 的，编译器会生成两次独立的内存读取指令（a = *ptr; b = *ptr; return a * b;）。如果两次读取之间值被中断改变，返回的将不是正确的平方值！
    正确实现：
    c
    long square(volatile int *ptr) {
    int a = *ptr; // 仅读取一次到本地局部变量
    return (long)a * a;
}

9. 位操作（Bit manipulation） #

嵌入式系统要求对寄存器进行精确位操作。给定整型变量 a，设置 a 的 bit 3，清除 a 的 bit 3，保持其他位不变：

c
#define BIT3 (0x1 << 3)
static int a;

// 将 a 的第 3 位置 1
void set_bit3(void) 
{
    a |= BIT3;
}

// 将 a 的第 3 位清 0
void clear_bit3(void) 
{
    a &= ~BIT3;
}

c
// 标准标准写法
int *ptr;
ptr = (int *)0x67a9;
*ptr = 0xaa66;

// 单行直接写法

11. 评论中断服务子程序（ISR） #

c
__interrupt double compute_area (double radius)  
{ 
    double area = PI * radius * radius; 
    printf("\nArea = %f", area); 
    return area; 
}

严重错误分析：

  1. ISR 不能有返回值：中断由硬件异步触发，没有调用者能接收返回值；
  2. ISR 不能传递实参：硬件触发中断时不会传递参数；
  3. 不可在 ISR 中进行浮点运算：浮点运算通常不可重入，且在许多嵌入式架构下需要保护大量浮点寄存器，极大增加中断延迟；
  4. 不可在 ISR 中调用 printf()：printf 通常具有线程安全锁和重入问题，且执行速度缓慢，会严重破坏系统实时性。

12. 整数隐式转换陷阱 #

c
void foo(void) 
{ 
    unsigned int a = 6; 
    int b = -20; 
    (a + b > 6) ? puts("> 6") : puts("<= 6"); 
}

输出：> 6
原理解析：当表达式中同时存在有符号整型与无符号整型时，有符号整型会被自动提升转换为无符号整型。-20 转换为 32 位无符号数是 $4,294,967,276$，$6 + 4,294,967,276 = 4,294,967,282 > 6$。

14. 动态内存分配陷阱 #

c
char *ptr; 
if ((ptr = (char *)malloc(0)) == NULL)  
    puts("Got a null pointer"); 
else 
    puts("Got a valid pointer");

在标准 C 库中，malloc(0) 的行为是实现定义的（Implementation-defined），通常会返回一个非空的、合法但不可解引用的独立内存指针，或者返回 NULL。无论返回何种指针，都不应该对 malloc(0) 返回的指针进行解引用写入。

15. 多线程与并发设计原则 #

  1. 何时应使用多线程：
    • 耗时 I/O 或后台计算操作，避免阻塞 UI 界面响应；
    • 客户端/服务端高并发网络请求处理；
    • 多核 CPU 系统中充分利用多核硬件并行算力。
  2. 何时单线程效率更高：
    • 纯内存且执行极短的串行任务；使用多线程反而会因线程上下文切换、锁竞争与同步开销而大幅降低整体性能。
  3. 防止并发波峰导致系统崩溃：使用**线程池（Thread Pool）**对最大并发线程数进行硬性限流，超出容量的任务进入等待队列排队。

16. 网络核心协议与三次握手 #

TCP 三次握手过程 #

  1. 第一次握手：客户端向服务端发送 SYN 报文（序号 seq=x），进入 SYN_SENT 状态，等待服务端确认。
  2. 第二次握手：服务端收到 SYN 报文，回应 SYN+ACK 报文（确认号 ack=x+1，服务器初始序号 seq=y），服务端进入 SYN_RCVD 状态。
  3. 第三次握手：客户端收到 SYN+ACK，向服务端发送 ACK 报文（确认号 ack=y+1），双方进入 ESTABLISHED 状态，连接成功建立。

核心网络协议归属 #

  • ICMP（Internet Control Message Protocol）：网络层（IP 层）协议，用于探测网络连通性（如 ping）。
  • ARP（Address Resolution Protocol）：网络层协议，负责将逻辑 IP 地址解析为数据链路层物理 MAC 地址。

17. 字符串库函数手写实现：strcat #

c
// 不调用任何库函数实现 strcat
char *strcat_custom(char *dst, const char *src)
{
    char *cp = dst;
    while (*cp != '\0') // 寻找目标字符串的结尾 '\0'
    {
        cp++;
    }
    while ((*cp++ = *src++) != '\0') // 将源字符串逐字符复制到末尾，包含结尾 '\0'
        ;
    return dst; // 返回目标指针，以支持链式表达式调用
}

18. 字符串逆序手写实现与找错剖析 #

c
// 方法一：原地双指针双向对调（推荐：空间复杂度 O(1)）
#include <stdio.h>
#include <string.h>

char* reverse_str(char *str)
{
    if (str == NULL) return NULL;
    int len = strlen(str);
    for (int i = 0; i < len / 2; i++)
    {
        char temp = str[i];
        str[i] = str[len - 1 - i];
        str[len - 1 - i] = temp;
    }
    return str;
}

// 方法二：动态分配新缓冲区
char* reverse_copy(const char *src)
{
    if (src == NULL) return NULL;
    int len = strlen(src);
    char *dest = (char *)malloc(len + 1); // 必须分配 len + 1 个字节以存放 '\0'
    char *d = dest;
    const char *s = src + len - 1;        // 指向最后一个字符
    while (len-- > 0)
    {
        *d++ = *s--;
    }
    *d = '\0'; // 显式写入字符串终止符
    return dest;
}

20. 经典找错题集锦 #

找错题 1：多维数组遍历的局部性与 Cache 命中 #

c
int a[60][250][1000], i, j, k; 
for(k = 0; k <= 1000; k++) 
    for(j = 0; j < 250; j++) 
        for(i = 0; i < 60; i++) 
            a[i][j][k] = 0;

问题分析：

  1. 越界访问：k <= 1000 导致越界（最右维下标有效范围为 0 ~ 999）。
  2. 严重的 Cache 颠簸（Cache Thrashing）：C 语言多维数组在内存中按行主序（Row-major order）连续存放。最内层应遍历最右边的索引 k，最外层遍历最左边的索引 i。原代码以大跨步跳跃访问内存，导致 CPU 数据缓存命中率极度低下。 正确写法：
c
for (i = 0; i < 60; i++)
    for (j = 0; j < 250; j++)
        for (k = 0; k < 1000; k++)
            a[i][j][k] = 0;

找错题 2：无符号循环变量导致的死循环 #

c
#define Max_CB 500
void LmiQueryCSmd(struct MsgCB *pmsg) 
{ 
    unsigned char ucCmdNum; 
    for (ucCmdNum = 0; ucCmdNum < Max_CB; ucCmdNum++) 
    { 
        // 处理逻辑
    } 
}

问题分析：unsigned char 取值范围为 0 ~ 255。当 ucCmdNum 达到 255 时，再加 1 会溢出回绕为 0，永远无法达到 500，造成严重死循环。应将 ucCmdNum 改为 unsigned short 或 int。

找错题 3：宏展开的后置自增副作用 #

c
#define SQUARE(a) ((a) * (a)) 
int a = 5; 
int b = SQUARE(a++);

问题分析：宏展开后变为 ((a++) * (a++))。在未定义求值顺序的表达式中对同一变量进行多次自增，不仅结果不可预期（未定义行为），而且 a 会被自增两次。

找错题 4：动态内存申请参数校验顺序颠倒 #

c
int examply_fun(BYTE gt_len, BYTE *gt_code) 
{   
    BYTE *gt_buf = (BYTE *)malloc(Max_GT_Length); 
    if (gt_len > Max_GT_Length) 
    { 
        return GT_Length_ERROR; // 致命错误：直接 return 导致前面 malloc 的 gt_buf 发生内存泄漏！
    } 
    // ...
}

正确写法：必须先校验入参合法性，参数合法之后再进行内存分配；若分配后遇到错误返回，必须先调用 free(gt_buf) 释放堆内存。

21. 操作系统核心问答（进程、线程与虚拟内存） #

进程与线程的本质差异 #

比较维度 进程（Process） 线程（Thread）
定义与角色 操作系统资源分配与保护的独立单位 CPU 任务调度与执行的最小实体
地址空间 各进程拥有完全隔离的独立虚拟地址空间 同一进程内的所有线程共享该进程的地址空间与资源
上下文切换开销 大（需切换页表、清空/刷新 TLB 缓存、切换寄存器） 小（仅需切换少量线程私有寄存器与私有栈顶指针）
健壮性 一个进程崩溃通常不影响其他进程 一个线程发生段错误崩溃会导致整个进程退出

进程间通信（IPC）机制全景 #

  1. 管道（Pipe / FIFO）：半双工，基于内核缓冲区与文件描述符抽象；
  2. 消息队列（Message Queue）：按消息类型结构化存取；
  3. 共享内存（Shared Memory）：效率最高的 IPC，映射同一物理内存页，需配合信号量使用；
  4. 信号（Signal）：异步通知事件；
  5. 套接字（Socket / Unix Domain Socket）：可跨网络、跨主机通信。

22. 悬空指针（Dangling Pointer）与释放后访问 #

c
void GetMemory(char **p, int num)
{
    *p = (char *)malloc(num);
}
int main()
{
    char *str = NULL;
    GetMemory(&str, 100);
    strcpy(str, "hello");
    free(str); // 堆内存已归还给内存管理器
    
    if (str != NULL) // 陷阱：str 仍然指向被释放的内存地址！
    {
        strcpy(str, "world"); // 危险操作：Use-After-Free，未定义行为！
    }
    printf("str is %s\n", str);
    return 0;
}

深度原理剖析：

  1. free(str) 只是将堆内存块标记为空闲并归还给运行时堆管理器，并没有清空或修改 str 指针变量自身的值。
  2. 此时 str 沦为野指针/悬空指针（Dangling Pointer）。
  3. 随后再向 str 写入 "world" 属于典型的 Use-After-Free（释放后使用） 严重安全漏洞。虽然在部分测试环境下该内存尚未被其他线程立即复用而可能侥幸输出 "world"，但在并发或稍复杂的系统中极易造成内存踩踏（Heap Corruption）并导致程序直接崩溃。
  4. 防御规范：调用 free(p) 后，务必立即将指针显式置为 NULL：p = NULL;。

23. 字符串与数组计算要点 #

  • sizeof vs strlen： char aa[10];
    sizeof(aa) 在编译期确定，恒等于 10 字节；而 strlen(aa) 在未初始化时会沿着未初始化的栈内存一直向后搜寻直到偶遇 '\0' 为止，返回的值完全不确定。
  • 指针数组 vs 数组指针：
    • char (*str)[20];：数组指针，指向包含 20 个字符数组的指针；
    • char *str[20];：指针数组，包含 20 个 char* 指针的数组。

24. 递归反向输出字符串与文件逆序处理 #

递归反向输出字符串经典算法 #

c
#include <stdio.h>

void inverse_print(const char *p)
{
    if (*p == '\0') 
        return;
    inverse_print(p + 1); // 先递归向后深入到末尾
    putchar(*p);          // 栈回溯时从后向前逐字符打印
}

int main(void)
{
    inverse_print("Hello World!");
    putchar('\n');
    return 0;
}

动态可扩容数组实现文件内容倒序输出 #

c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int capacity = 16;
    int count = 0;
    int *arr = (int *)malloc(capacity * sizeof(int));
    if (!arr) return -1;
    
    FILE *fp_in = fopen("file1.txt", "r");
    if (!fp_in) { free(arr); return -1; }
    
    while (fscanf(fp_in, "%d", &arr[count]) == 1)
    {
        count++;
        if (count >= capacity)
        {
            capacity *= 2;
            int *new_arr = (int *)realloc(arr, capacity * sizeof(int));
            if (!new_arr) { free(arr); fclose(fp_in); return -1; }
            arr = new_arr;
        }
    }
    fclose(fp_in);
    
    FILE *fp_out = fopen("file2.txt", "w");
    if (fp_out)
    {
        for (int i = count - 1; i >= 0; i--)
        {
            fprintf(fp_out, "%d\n", arr[i]);
        }
        fclose(fp_out);
    }
    
    free(arr);
    return 0;
}

25. 输出和为给定整数的所有不重复正整数对 #

c
#include <stdio.h>

void find_sum_pairs(int sum)
{
    printf("和为 %d 的不重复正整数对为：\n", sum);
    for (int i = 1; i <= sum / 2; i++)
    {
        int j = sum - i;
        if (i != j) // 相加的两个数不重复
        {
            printf("%d = %d + %d\n", sum, i, j);
        }
    }
}

int main(void)
{
    find_sum_pairs(5); // 输出：5 = 1 + 4, 5 = 2 + 3
    return 0;
}
