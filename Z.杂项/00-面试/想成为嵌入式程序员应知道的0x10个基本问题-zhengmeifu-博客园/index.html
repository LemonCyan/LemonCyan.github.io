想成为嵌入式程序员应知道的 0x10 个基本问题 #

本文源自嵌入式领域经典面试题（Nigel Jones 所著《0x10 Questions for Embedded C Programmers》）。C 语言测试是招聘嵌入式系统程序员过程中必须且有效的方法，能够全面考察应试者对硬件底层、编译机制、指针与架构的真实掌握程度。

一、 预处理器（Preprocessor） #

1. 用预处理指令 #define 声明一个常数，用以表明 1 年中有多少秒（忽略闰年问题） #

c
#define SECONDS_PER_YEAR (60 * 60 * 24 * 365)UL

考核要点：

  1. #define 语法的基本知识（不能以分号结尾，括号的使用等）。
  2. 懂得预处理器将为你计算常数表达式的值，直接写出计算表达式比直接算出一个大数字更具可读性且零运行期代价。
  3. 意识到该数值会使 16 位整型数溢出，因此必须使用长整型修饰符。
  4. 使用 UL（表示无符号长整型）代表严谨的工程思维。

2. 写一个“标准”宏 MIN，输入两个参数并返回较小的一个 #

c
#define MIN(A, B) ((A) <= (B) ? (A) : (B))

考核要点：

  1. 宏定义中括号的使用：必须将每个参数以及整个表达式严格用括号括起来，防止运算符优先级产生副作用。
  2. 三重条件操作符（?:）的知识：在嵌入式编译中容易生成比 if-then-else 更高效的机器指令。
  3. 宏的副作用讨论：例如执行 least = MIN(*p++, b); 时，*p++ 会被展开求值两次，产生严重的逻辑隐患。

3. 预处理器标识 #error 的目的是什么？ #

解答： #error 指令用于在编译期生成指定的错误信息并停止编译过程。常用于在预处理阶段检查编译环境与宏配置是否符合要求。

典型应用示例：

c
#if !defined(VERSION) || (VERSION < 2)
#error "This driver requires VERSION 2 or higher!"
#endif

二、 无限循环（Infinite Loops） #

4. 嵌入式系统中经常要用到无限循环，你怎么样用 C 编写死循环？ #

常见方案：

  1. while(1) { ... } —— 最常见直观的写法。
  2. for(;;) { ... } —— 经典惯用法，许多编译优化器会将其直接等价于无条件跳转。
  3. goto 标签循环：
    c
    Loop:
    /* ... */
    goto Loop;
    说明：若应聘者提出该方案，通常表明其具备底层汇编编程思维。

三、 数据声明（Data Declarations） #

5. 用变量 a 给出下面的定义： #

  1. 一个整型数：
    c
    int a;
  2. 一个指向整型数的指针：
    c
    int *a;
  3. 一个指向指针的指针，它指向的指针是指向一个整型数：
    c
    int **a;
  4. 一个有 10 个整型数的数组：
    c
    int a[10];
  5. 一个有 10 个指针的数组，该指针是指向一个整型数的：
    c
    int *a[10];
  6. 一个指向有 10 个整型数数组的指针：
    c
    int (*a)[10];
  7. 一个指向函数的指针，该函数有一个整型参数并返回一个整型数：
    c
    int (*a)(int);
  8. 一个有 10 个指针的数组，该指针指向一个函数，该函数有一个整型参数并返回一个整型数：
    c
    int (*a[10])(int);

四、 核心关键字深入 #

6. 关键字 static 的作用是什么？ #

在 C 语言中，static 主要有以下三大核心作用：

  1. 在函数体内：修饰局部变量时，该变量只在程序初始化时分配一次内存（静态数据区），在整个程序运行期生命周期持续存在，并在多次函数调用间保持其值。
  2. 在模块内（函数体外）：修饰全局变量时，限制该变量的作用域仅在当前源文件（.c），对同一工程的其他模块不可见，实现模块级信息隐藏与命名隔离。
  3. 在模块内修饰函数：限制该函数仅在当前声明的文件内部被调用，外部文件无法通过链接访问该函数。

7. 关键字 const 有什么含意？ #

c
const int a;
int const a;
const int *a;
int * const a;
int const * a const;
  • 语义对比：
    • 前两个等价，表示 a 是一个只读常量整数。
    • const int *a 表示 a 是一个指向常量整数的指针（指针所指向的数据不可修改，但指针本身可以指向别处）。
    • int * const a 表示 a 是一个常指针（指针本身不可修改，但所指向的整型数据可以被修改）。
    • 最后一个表示 a 是一个指向常整数的常指针（指针本身及其指向的值均不可被修改）。
  • 工程价值：通过编译期强制检查防止意外修改重要数据，向函数调用者清晰传达参数设计意图，并为编译器指令优化提供依据。

8. 关键字 volatile 有什么含意？并给出三个不同的例子 #

核心含义： volatile 提醒编译器该变量的值可能在编译器未知的情况下被改变（例如硬件外设、中断或外部线程），因此编译器不得对该变量的读写操作进行缓存或寄存器优化，每次必须从内存物理地址中重新读取。

三个典型应用场景：

  1. 并行设备的硬件寄存器（如状态寄存器、控制寄存器映射的内存地址）。
  2. 一个中断服务子程序（ISR）中会访问到的非自动变量。
  3. 多线程并发任务中被几个任务共享的全局标志变量。

典型代码思考题：

c
int square(volatile int *ptr)
{
    return *ptr * *ptr;
}
  • 问题所在：编译器可能会将其编译为读取两次 *ptr 内存值并相乘。如果在这两次读取的微小时间间隔内硬件修改了该地址的值，最终得到的结果将不是平方值！
  • 正确写法：
    c
    int square(volatile int *ptr)
{
    int a = *ptr;
    return a * a;
}

五、 位操作（Bit Manipulation） #

9. 嵌入式系统总是要用户对变量或寄存器进行位操作。给定一个整型变量 a，写两段代码：第一个设置 a 的 bit 3，第二个清除 a 的 bit 3。在这两个操作中，要保持其它位不变。 #

c
#define BIT3 (0x1 << 3)

static int a;

// 设置 a 的 bit 3
void set_bit3(void)
{
    a |= BIT3;
}

// 清除 a 的 bit 3
void clear_bit3(void)
{
    a &= ~BIT3;
}

六、 访问绝对内存地址（Accessing Fixed Memory Locations） #

10. 在某工程中，要求设置一绝对地址为 0x67a9 的整型变量的值为 0xaa66 #

c
void write_memory(void)
{
    int *ptr = (int *)0x67a9;
    *ptr = 0xaa66;
}

// 更加紧凑的写法：
*(volatile int * const)0x67a9 = 0xaa66;

七、 中断服务例程（Interrupts） #

11. 中断是嵌入式系统中重要的组成部分，评价以下 ISR 代码： #

c
__interrupt double compute_area(double radius)
{
    double area = PI * radius * radius;
    printf(" Area = %f", area);
    return area;
}

该函数存在以下严重错误：

  1. ISR 不能有返回值：硬件触发中断时调用栈无法接收入口返回值。
  2. ISR 不能传递参数：硬件中断入口无法按普通函数传递形参。
  3. 浮点运算问题：在很多嵌入式架构中，浮点运算协处理器上下文未被压栈，浮点操作不可重入且耗时巨大。
  4. 不可重入与 I/O 阻塞：printf 内部通常有互斥锁或低速缓冲区 I/O 操作，具有重入和性能瓶颈问题，严禁在要求“短平快”的 ISR 中调用。

八、 代码例子与隐式类型转换 #

12. 下面的代码输出是什么，为什么？ #

c
void foo(void)
{
    unsigned int a = 6;
    int b = -20;
    (a + b > 6) ? puts("> 6") : puts("<= 6");
}
  • 输出结果：> 6
  • 原因分析：C 语言标准规定，当一个表达式中同时存在有符号整型和无符号整型时，有符号数将被自动隐式提升为无符号数。-20 在 32 位机器下对应的二进制补码为 0xFFFFFFEC（无符号数 $4294967276$），加上 6 后仍然远大于 6。

13. 评价下面的代码片断： #

c
unsigned int zero = 0;
unsigned int compzero = 0xFFFF; /* 1's complement of zero */
  • 评定：该代码对于 int 不是 16 位的处理器（如 32 位 ARM、64 位 x86）是不正确的，会导致高位补码缺失。
  • 正确写法：
    c
    unsigned int compzero = ~0;
    使用位反转操作符 ~0 具有平台无关性，能够自适应任意字长的处理器。

九、 动态内存分配（Dynamic Memory Allocation） #

14. 嵌入式系统中动态分配内存可能发生什么问题？ #

  1. 内存碎片（Memory Fragmentation）：长期运行后容易产生外部碎片，导致虽然总可用堆空间充足，却无法申请到大块连续内存。
  2. 内存泄漏与野指针：嵌入式系统通常要求 7x24 小时不间断运行，哪怕几字节的累积泄漏最终也会耗尽堆栈引发死机。
  3. 分配时间不确定性：大多数实时系统（RTOS）要求操作具有确定性（Deterministic Time），而 malloc 的搜索与分配时间因堆状态而异，无法满足硬实时要求。

延伸小题：下面的代码输出是什么？

c
char *ptr;
if ((ptr = (char *)malloc(0)) == NULL)
    puts("Got a null pointer");
else
    puts("Got a valid pointer");
  • 解答：C 标准规定 malloc(0) 的行为由实现定义：可能返回 NULL，也可能返回一个非空但不可解引用的有效指针。在许多标准 C 库中其输出为 "Got a valid pointer"。

十、 Typedef 与宏定义 #

15. 思考下面的定义哪种更好？ #

c
#define dPS struct s *
typedef struct s * tPS;

解答：typedef 远优于 #define。思考以下声明：

c
dPS p1, p2; // 宏展开后为: struct s * p1, p2; -> p1 是指针，p2 是结构体实体！
tPS p3, p4; // 严格定义 p3 和 p4 均为结构体指针类型

十一、 晦涩的语法 #

16. 下面的结构合法吗？如果合法它做些什么？ #

c
int a = 5, b = 7, c;
c = a+++b;

解答：完全合法。

  • 根据 C 语言词法分析的最长贪心匹配原则（Maximal Munch），编译器会将 +++ 贪婪解析为 ++ 后紧跟 +，即：
    c
    c = (a++) + b;
  • 执行后：a = 6, b = 7, c = 12。
