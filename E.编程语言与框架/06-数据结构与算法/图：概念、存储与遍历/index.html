一、图是什么：比树更一般的结构 #

线性表里，一个元素最多一个直接前驱、一个直接后继。树放宽了后半句：一个结点可以有多个孩子，但父只有一个。图把前半句也放宽——一个顶点可以有若干个直接前驱，也可以有若干个直接后继。教材把这种多对多的结构叫网状结构。

给个能落地的定义：

text
图 G = (V, E)
V——顶点（vertex）的非空有限集，|V| 叫图的阶
E——边（edge）的有限集，每条边关联 V 中的一对顶点

这里已经没有「结点」这个说法了，改叫顶点；也没有父子，改叫邻接。图不带根，不带层次。你在图上说「第几层」，只有先指定一个起点、把距离量出来之后才有意义，那是 BFS 算出来的副产品，不是结构自带的属性。

顶点和边代表什么，取决于你建模的对象：

  • 社交网络：顶点是人，边是关注关系
  • 地铁线路：顶点是站，边是相邻的两站区间
  • 工程编译：顶点是源文件，边是 include 依赖
  • 状态机：顶点是状态，边是一次转移

建模对象换了，算法一行不用改。变的只是你对顶点和边的解释，以及边带不带权。

拿线性表、树、图横向比一下，差别就三行：

结构 直接前驱 直接后继 会不会成环
线性表 至多 1 个 至多 1 个 不会
树 至多 1 个（根为 0） 任意多个 不会
图 任意多个 任意多个 会

所以判断一段代码该用哪种结构，问自己一句：一个元素会不会有多个来源？会，那就是图。

画个最小的例子，5 个顶点，6 条边：

text
        A
       / \
      B---C
      |   |
      D---E

V = {A, B, C, D, E}
E = {(A,B), (A,C), (B,C), (B,D), (C,E), (D,E)}

边上还可以标数字，比如两站之间的公里数、两个任务之间的天数，这时候叫带权图，第六章单独说。

写代码之前先定一个约定，后面所有实现都靠它：顶点一律用 0 到 n-1 的整数编号。名字是给人和输入输出看的，算法内部永远只碰下标。邻接矩阵的行列、邻接表的下标、并查集的数组，全都建立在这个约定上。

二、图的术语：顶点、边、度 #

术语不难，但混起来很要命——尤其「度」在有向图里被拆成两半。先把这一组钉死：

术语 含义 备注
顶点 图里的元素 也写作结点、节点
边 两个顶点之间的连线 无向用 (u,v)，有向用 <u,v>
邻接 两个顶点之间有边 有向图里还要区分方向
关联 边和它的端点之间的关系 一条边关联两个端点
度 与顶点相连的边数 记 TD(v)
入度 指向该顶点的弧数 记 ID(v)，只有有向图有
出度 从该顶点指出的弧数 记 OD(v)，只有有向图有
路径 顶点序列 v0,v1,…,vk，相邻两个有边 长度按边数算，带权按权和算
回路 首尾相同的路径 也叫环，Cycle
子图 顶点集和边集都是原图的子集 生成子图要求顶点集相同

度的公式一行写完：

text
有向图：D(v) = OD(v) + ID(v)
无向图：没有方向，只有 D(v) = TD(v)

由度能推出两条很实用的结论：

  • 无向图中，所有顶点的度之和等于边数的两倍，因为一条边给两端各贡献 1
  • 有向图中，所有顶点的出度之和等于入度之和，都等于弧数，因为一条弧贡献一个出度、一个入度

第二条的推论更常用：无向图里度为奇数的顶点一定是偶数个。你从文件里读进来一张图，数出 5 个奇度顶点，那不用怀疑，读入代码有问题或者输入本身坏了。

路径这一组术语，含混的地方全在限定词上——顶点不重复出现，才配叫简单路径：

  • 路径：顶点序列，相邻两个之间都有边
  • 简单路径：路径上顶点不重复
  • 回路：起点和终点是同一个顶点
  • 简单回路：除了起点终点相同，中间顶点不重复

非简单路径在算法里几乎没有用，因为只要路上有重复顶点，绕着那个圈多走一遍，路径只会更长。所以后面讲的 DFS、BFS、Dijkstra，路径天然都是简单的。

三、有向图与无向图 #

判断标准一句话：两个顶点之间的关系存在方向性，就是有向图，否则是无向图。

无向图的边是一对无序顶点，写 (u,v)，等价于 (v,u)。有向图的边叫弧，写 <u,v>，从 u 指向 v，u 叫弧尾，v 叫弧头，而且 <u,v> 和 <v,u> 是两条不同的弧。A 关注了 B，不代表 B 关注了 A，就这么简单。

对比项 无向图 有向图
边的记法 (u,v)，无序 <u,v>，有序
边的对称性 (u,v) 与 (v,u) 是同一条 <u,v> 与 <v,u> 是两条
度的概念 只有度 分出度、入度
邻接矩阵 一定对称 一般不对称
完全图边数 n(n-1)/2 n(n-1)
连通性说法 连通、连通分量 强连通、强连通分量
典型场景 好友、道路、设备连线 关注、依赖、单行道、状态转移

建图的时候一个无向边要在存储里落两次，一条 u 到 v，一条 v 到 u，漏了一边，图就变成「半个有向图」，遍历结果看起来像是丢了一半顶点。这个坑在第八章写邻接表时会再碰到一次。

还有两个要分清的概念：

  • 自环：一条边的两个端点相同，<u,u>
  • 多重图：两个顶点之间有多条边

不含自环也不含重边的图叫简单图。本篇代码默认输入是简单图。真遇到重边，两条路：输入阶段合并成一条（保留最小权），或者全留在邻接表里、只在需要时跳过重复。前者省事，后者信息全。

四、完全图、稠密图与稀疏图 #

完全图的边数是整篇里为数不多能精确算的量，公式也很干净：

text
有向完全图：任意两个顶点之间都有两条方向相反的弧，共 n(n-1) 条
无向完全图：任意两个顶点之间都有一条边，共 n(n-1)/2 条

代几个数进去，感受一下增长有多快：

顶点数 n 无向完全图边数 n(n-1)/2 有向完全图弧数 n(n-1)
2 1 2
3 3 6
4 6 12
5 10 20
10 45 90
100 4950 9900
1000 499500 999000

边数是顶点数的平方级。这一点决定了第七章那个邻接矩阵的空间开销，也决定了「用矩阵还是用表」不是一个风格问题，而是能不能跑起来的问题。

稠密图和稀疏图没有绝对阈值，看的是边数与顶点数的关系：

  • 稠密图：边数接近 n² 量级
  • 稀疏图：边数与 n 同量级，或者只比 n 大一点

工程上的判据更直接：把 |E| 和 |V|² 比一下。社交网络里几千万用户、人均几百个关注，|E| 远小于 |V|²，稀疏。一张城市路网、变电站接线图，一个顶点只连几条边，稀疏。完全图、小规模的状态转移图，稠密。

这个比值就是第十章选存储结构的唯一依据。记住它，后面不用再纠结。

五、连通图与生成树 #

无向图里，任意两个顶点之间都存在路径，这张图就叫连通图。判据只有这一条，没有别的附加条件。

不连通的无向图会散成几块，每一块内部连通、块与块之间没有边，每一块叫一个连通分量。它有三个性质，写代码时很管用：

  • 连通分量是极大连通子图，再往里加一个顶点就不连通了
  • 一个连通图的连通分量只有一个，就是它自己
  • 孤立顶点自己也算一个连通分量，别把它漏掉
text
A---B    D---E---F    G
     \  /
      C

三个连通分量：{A,B,C}、{D,E,F}、{G}

有向图的说法要加个「强」字。任意两个顶点 u、v 之间，既存在 u 到 v 的路径，又存在 v 到 u 的路径，才叫强连通。极大强连通子图叫强连通分量。有向图还有个中间状态：把方向全抹掉之后连通，叫弱连通。这三档名字容易记混，考试爱考。

生成树是连通图上的概念：一个连通图的生成树，是它的一个极小连通子图，包含全部 n 个顶点，但只有 n-1 条边。少一条就不连通，多一条就成环。这两句话互为因果——n 个顶点的树必然是 n-1 条边，n 个顶点 n-1 条边且连通必然是树。

非连通图没有生成树，只有生成森林：每个连通分量各取一棵生成树，凑起来就是森林。

一棵连通图的生成树不唯一。从不同顶点出发做 DFS 或 BFS，得到的树就不一样。边带权之后，这些生成树里总权最小的那棵，叫最小生成树，第十四章专门讲。

六、带权图 #

边上标一个数，这个数叫权（weight），带权的图叫网（network）。权可以是距离、时间、费用、容量、损耗，含义由你赋。

带权之后，「路径长度」的定义跟着变：无向无权图里路径长度是边的条数，带权图里是这条路上所有边权之和。这个改动看着小，但它是 Dijkstra 存在的前提——如果长度只按边数算，BFS 就够了，根本不需要 Dijkstra。

存带权图有一个必须提前定的约定：没有边用什么表示。两种写法：

  • 邻接矩阵里，用一个远大于任何真实路径的数，习惯写 0x3f3f3f3f。它的两倍还在 int 范围内，做加法不会溢出
  • 邻接表里，不存在边就是链表里压根没有这个结点，天然没有这个问题

不能用 0 表示「没有边」。0 会和「权值为 0 的边」撞车，也会让「最短路」和「没路」分不开。用无穷大，dist[i] == INF 一判就清楚。

还有一种更隐蔽的错：拿 INT_MAX 当无穷大，然后写 dist[u] + w。这一步直接溢出成负数，Dijkstra 会给出一个荒谬的答案。要么用 0x3f3f3f3f，要么加之前先判 dist[u] < INF。下面所有代码都按前一种写。

text
        A
    5 ／ ＼ 2
     B-----C
       1
邻接矩阵：  A   B   C
        A   0   5   2
        B   5   0   1
        C   2   1   0
对角线上是 0：自己到自己距离为 0，不是「没有边」

七、邻接矩阵 #

图的存储要解决的问题只有一个：怎么表示边。邻接矩阵的答案是——用一张 n×n 的表，第 i 行第 j 列的值就代表顶点 i 到顶点 j 这条边。

无向图里 edge[i][j] 和 edge[j][i] 必然相等，矩阵关于主对角线对称，实际只用了上三角，另一半是白存的。有向图没有这个性质，一条弧只落在它的起点那一行。

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAXV 100
#define INF  0x3f3f3f3f      /* 无穷大，表示两点之间没有边 */

typedef char VType;
typedef int  EType;

typedef struct {
    VType vex[MAXV];         /* 顶点表：下标 → 名字 */
    EType edge[MAXV][MAXV];  /* 边表：n×n 数组，值就是权 */
    int   vexnum, arcnum;
} MGraph;

/* 按名字查下标，查不到返回 -1 */
int locateVex(MGraph *G, VType v) {
    for (int i = 0; i < G->vexnum; i++)
        if (G->vex[i] == v) return i;
    return -1;
}

/* 初始化：铺成「对角线 0，其余 INF」的空图 */
void initMGraph(MGraph *G, const VType *vs, int n) {
    G->vexnum = n;
    G->arcnum = 0;
    for (int i = 0; i < n; i++)
        G->vex[i] = vs[i];
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            G->edge[i][j] = (i == j) ? 0 : INF;
}

/* 加一条边；directed 为 0 时两个方向都写 */
int addArc(MGraph *G, VType u, VType v, EType w, int directed) {
    int i = locateVex(G, u);
    int j = locateVex(G, v);
    if (i < 0 || j < 0 || i == j) return 0;   /* 名字错、或自环，都不收 */
    if (G->edge[i][j] == INF) G->arcnum++;
    G->edge[i][j] = w;
    if (!directed) G->edge[j][i] = w;
    return 1;
}

/* 无向图求度：一行里「非 0 且非 INF」的格子数 */
int degree(MGraph *G, int v) {
    int d = 0;
    for (int j = 0; j < G->vexnum; j++)
        if (G->edge[v][j] != 0 && G->edge[v][j] != INF) d++;
    return d;
}

/* 有向图求度：行和是出度，列和是入度 */
void outInDegree(MGraph *G, int v, int *od, int *id) {
    *od = 0;
    *id = 0;
    for (int j = 0; j < G->vexnum; j++) {
        if (G->edge[v][j] != 0 && G->edge[v][j] != INF) (*od)++;
        if (G->edge[j][v] != 0 && G->edge[j][v] != INF) (*id)++;
    }
}

建图和查事情的代价，一眼就能读出来：

  • 判断 u、v 之间有没有边：数组下标一取，O(1)
  • 取一条边的权：同样 O(1)
  • 找 v 的所有邻居：扫一整行，O(n)
  • 遍历整张图：每个顶点都要扫一行，O(n²)

后两条就是矩阵的软肋。图很稀疏的时候，你为了找到 v 那几个邻居，把 n 个格子全翻了一遍，其中绝大多数是 INF。

八、邻接表 #

邻接表换个答案：只存实际存在的边。每个顶点挂一条链表，链表里每个节点代表一条从这个顶点出去的边，节点里存「对面是谁」和「权」。

c
/* 一条边对应的链表节点 */
typedef struct ArcNode {
    int  adjvex;             /* 对面顶点的下标 */
    EType weight;            /* 权，无权图填 1 */
    struct ArcNode *nextarc; /* 同一个顶点的下一条边 */
} ArcNode;

/* 顶点节点：名字 + 链表头 */
typedef struct VNode {
    VType data;
    ArcNode *firstarc;
} VNode, AdjList[MAXV];

typedef struct {
    AdjList vertices;
    int vexnum, arcnum;
} ALGraph;

void initALGraph(ALGraph *G, const VType *vs, int n) {
    G->vexnum = n;
    G->arcnum = 0;
    for (int i = 0; i < n; i++) {
        G->vertices[i].data = vs[i];
        G->vertices[i].firstarc = NULL;
    }
}

int locateAL(ALGraph *G, VType v) {
    for (int i = 0; i < G->vexnum; i++)
        if (G->vertices[i].data == v) return i;
    return -1;
}

/* 头插法加边；无向图插两次，一条 u→v，一条 v→u */
int addArcAL(ALGraph *G, VType u, VType v, EType w, int directed) {
    int i = locateAL(G, u);
    int j = locateAL(G, v);
    if (i < 0 || j < 0 || i == j) return 0;
    ArcNode *p = (ArcNode *)malloc(sizeof(ArcNode));
    if (p == NULL) return 0;
    p->adjvex = j;
    p->weight = w;
    p->nextarc = G->vertices[i].firstarc;
    G->vertices[i].firstarc = p;
    if (!directed) {
        ArcNode *q = (ArcNode *)malloc(sizeof(ArcNode));
        if (q == NULL) return 0;
        q->adjvex = i;
        q->weight = w;
        q->nextarc = G->vertices[j].firstarc;
        G->vertices[j].firstarc = q;
    }
    G->arcnum++;
    return 1;
}

头插法写起来最省事，代价是链表中邻居的顺序和输入顺序相反。这一点会让遍历输出不唯一：同一张图，换个建图顺序，DFS 打印出来的序列就不一样。做题时如果要求「按顶点编号从小到大遍历」，得改成尾插，或者在遍历时先收集再排序。

邻接表的两面：

  • 空间是 O(n + e)，e 条边一条不浪费，稀疏图上这是决定性的优势
  • 出度好求，v 那条链表的长度就是出度
  • 求入度很难受，得把所有顶点的链表全扫一遍，数有多少节点指向 v

最后这条是有向图的老问题。两个补丁：建一张逆邻接表，也就是把每条弧反着存一遍；或者直接用第九章的十字链表。

九、十字链表与邻接多重表 #

前面两个结构各有一处别扭的地方：有向图求入度要全表扫，无向图一条边存两遍。两个变体专门补这两个洞。

十字链表针对有向图。每条弧只存一个结点，但这个结点同时挂在两条链上——按弧尾挂在起点的出链，按弧头挂在终点的入链。

c
/* 有向图的十字链表：一条弧一个结点，同时属于出链和入链 */
typedef struct OArcBox {
    int tailvex, headvex;      /* 弧尾下标、弧头下标 */
    struct OArcBox *hlink;     /* 弧头相同的下一条弧 */
    struct OArcBox *tlink;     /* 弧尾相同的下一条弧 */
    EType weight;
} OArcBox;

typedef struct OVexNode {
    VType data;
    OArcBox *firstin;          /* 入边链表头 */
    OArcBox *firstout;         /* 出边链表头 */
} OVexNode, OList[MAXV];

顺着 firstout 走一圈拿到全部出边，顺着 firstin 走一圈拿到全部入边，入度和出度都变成 O(出度) 和 O(入度)。代价是每个弧结点多一个指针，建图时要同时维护两套链，写起来比邻接表啰嗦。

邻接多重表针对无向图。无向图的一条边在邻接表里存了两个节点，删边时得两边都找一遍，很容易漏。邻接多重表让一条边只对应一个结点，这个结点的两个指针分别挂到两个端点的链上。

c
/* 无向图的邻接多重表：一条边一个结点，两个端点各挂一条链 */
typedef struct EBox {
    int mark;                  /* 访问标记，遍历时用 */
    int ivex, jvex;            /* 边的两个端点下标 */
    struct EBox *ilink;        /* 依附于 ivex 的下一条边 */
    struct EBox *jlink;        /* 依附于 jvex 的下一条边 */
    EType weight;
} EBox;

typedef struct EVexNode {
    VType data;
    EBox *firstedge;
} EVexNode, EList[MAXV];

边只有一个副本，删除、标记、染色的操作就都只有一处。教材里这两节经常配大量指针图，看得人头皮发麻，但你只要抓住一句话：十字链表让弧存一次，邻接多重表让无向边存一次。

实际工程里这两个结构用得不多。笔试题爱考，因为能手写出来说明你真的懂指针在指什么。面试问到「邻接表求入度怎么办」，答逆邻接表就够，答十字链表加分。

十、两种存储方式的对比 #

选型只看四个维度：顶点数、边数、常做的操作、内存余量。把矩阵和表摊开对比：

对比项 邻接矩阵 邻接表
空间 O(n²)，与边数无关 O(n + e)，只存存在的边
判断 (u,v) 是否有边 O(1)，直接取 O(出度)，要扫链表
取边权 O(1) O(出度)
找 v 的全部邻居 O(n)，扫一行 O(出度)，正好是要的东西
求无向图顶点度 O(n) O(出度)
求有向图出度 O(n) O(出度)
求有向图入度 O(n)，扫一列 O(n + e)，要全表扫
增删一条边 O(1) O(1) 头插，删要查找
适合的图 稠密图、小图 稀疏图、大图
典型用途 Floyd、Prim 的课本实现 DFS/BFS、Dijkstra、拓扑排序

一句话的选型规则：稠密用矩阵，稀疏用表。这句话不是风格偏好，是空间和时间的硬约束。n 等于 10 万时，矩阵要 10^10 个格子，任何机器都放不下，这时候只有邻接表可选。

还有一句要记住：不管你选哪种，都只是「怎么表示边」的不同答案。DFS、BFS、Prim、Dijkstra 这些算法的思路完全一样，换成另一种存储只需要改写「取 v 的邻居」那一个循环。所以真正要背的不是代码，是这层对应关系——矩阵里是「扫一行」，表里是「走链表」。

十一、深度优先遍历 DFS #

遍历图的定义和遍历树差不多：按某种顺序，把每个顶点访问一次且仅访问一次。换个说法更抓要害——把网状结构按某种规则顺序化的过程。

网状结构没有天然的起点，一旦要顺序化，第一件事就是选一个起点，第二件事是防止绕圈。防绕圈的办法很土但够用：给每个顶点设一个标志位，访问过就置 TRUE。

DFS 的走法是「一条路走到黑」。从 v 出发，找第一个没访问过的邻居，进去；在那个邻居身上继续找它的第一个没访问过的邻居，一直往下；走不动了再退回上一层，换下一个邻居。这个过程天然是递归的，递归调用栈就是它的栈。

c
int visited[MAXV];          /* 全局访问标志，0 未访问，1 已访问 */

/* 邻接矩阵上的 DFS */
void DFSMatrix(MGraph *G, int v) {
    visited[v] = 1;
    printf("%c ", G->vex[v]);
    for (int w = 0; w < G->vexnum; w++)
        if (!visited[w] && G->edge[v][w] != 0 && G->edge[v][w] != INF)
            DFSMatrix(G, w);
}

/* 邻接表上的 DFS */
void DFSList(ALGraph *G, int v) {
    visited[v] = 1;
    printf("%c ", G->vertices[v].data);
    for (ArcNode *p = G->vertices[v].firstarc; p != NULL; p = p->nextarc)
        if (!visited[p->adjvex])
            DFSList(G, p->adjvex);
}

两段代码的差别只有一处：找邻居的方式。矩阵版本要扫一整行 n 个格子，表版本顺着链表走，走几步取决于这个顶点有几条边。这也是第十章那句「换存储只改一个循环」的实证。

递归深度等于路径长度，图很深的时候（比如一条链上百万个顶点）会爆栈。改成显式栈：

c
/* 邻接表上的非递归 DFS，自己维护一个栈 */
void DFSListIter(ALGraph *G, int v) {
    int stack[MAXV * MAXV];   /* 入栈次数上限是边数 + 1，按这个量级开 */
    int top = -1;
    stack[++top] = v;
    while (top >= 0) {
        int u = stack[top--];
        if (visited[u]) continue;      /* 会被重复压栈，出栈时再判一次 */
        visited[u] = 1;
        printf("%c ", G->vertices[u].data);
        for (ArcNode *p = G->vertices[u].firstarc; p != NULL; p = p->nextarc)
            if (!visited[p->adjvex])
                stack[++top] = p->adjvex;
    }
}

这段的输出顺序和递归版本不一样。原因在头插法：链表里邻居是倒序的，压栈之后再弹出来，又倒了一次。想让两者一致，把邻接表改成尾插，或者压栈前先把邻居收进数组再逆序压。顺序不同不代表错，DFS 序列本来就不唯一。

复杂度这一块，记两个数就够：

存储结构 时间 空间
邻接矩阵 O(n²) O(n)，递归栈 + visited
邻接表 O(n + e) O(n)

矩阵的 O(n²) 不是因为算法慢，是因为它光找邻居就得翻 n² 个格子。稀疏图上这个差距会非常大。

DFS 顺带能产出两样东西，后面有用：

  • DFS 树/森林：把「第一次到达某个顶点」的那条边留下来，就是一棵树；连通图出一棵树，非连通图出一片森林
  • 时间戳：进入顶点时打一个 dfn，回溯完它的所有邻居时打一个 low，这是求割点、桥、强连通分量的基础

十二、广度优先遍历 BFS #

BFS 换了个走法：从起点出发，先把所有距离为 1 的顶点走完，再走距离为 2 的，一层一层往外扩。它靠的是队列——先进先出，保证「先发现的先展开」。

c
/* 邻接矩阵上的 BFS */
void BFSMatrix(MGraph *G, int v) {
    int queue[MAXV], front = 0, rear = 0;
    visited[v] = 1;
    printf("%c ", G->vex[v]);
    queue[rear++] = v;
    while (front < rear) {
        int u = queue[front++];                 /* 出队 */
        for (int w = 0; w < G->vexnum; w++) {
            if (!visited[w] && G->edge[u][w] != 0 && G->edge[u][w] != INF) {
                visited[w] = 1;                 /* 入队前就标记 */
                printf("%c ", G->vex[w]);
                queue[rear++] = w;
            }
        }
    }
}

/* 邻接表上的 BFS */
void BFSList(ALGraph *G, int v) {
    int queue[MAXV], front = 0, rear = 0;
    visited[v] = 1;
    printf("%c ", G->vertices[v].data);
    queue[rear++] = v;
    while (front < rear) {
        int u = queue[front++];
        for (ArcNode *p = G->vertices[u].firstarc; p != NULL; p = p->nextarc) {
            int w = p->adjvex;
            if (!visited[w]) {
                visited[w] = 1;
                printf("%c ", G->vertices[w].data);
                queue[rear++] = w;
            }
        }
    }
}

这里有一个必须踩对的点：顶点是在入队的时候标记，不是在出队的时候。改成出队时标记，同一个顶点会被它的多个邻居各压一次队列，队列里塞满重复项，遍历不再是 O(n+e)。

BFS 最实用的副产品是无权图的最短路径。因为 BFS 是按距离分层的，第一次到达某个顶点时的层数，就是从起点到它的最少边数。把 visited 换成一个 dist 数组，初值 -1，就同时承担了「是否访问过」和「距离多少」两个职责：

c
/* 无权图单源最短路径：每条边长度都是 1 */
void BFSShortest(ALGraph *G, int s, int dist[], int parent[]) {
    int queue[MAXV], front = 0, rear = 0;
    for (int i = 0; i < G->vexnum; i++) {
        dist[i] = -1;
        parent[i] = -1;
    }
    dist[s] = 0;
    queue[rear++] = s;
    while (front < rear) {
        int u = queue[front++];
        for (ArcNode *p = G->vertices[u].firstarc; p != NULL; p = p->nextarc) {
            int w = p->adjvex;
            if (dist[w] == -1) {               /* -1 就是「没访问过」 */
                dist[w] = dist[u] + 1;
                parent[w] = u;
                queue[rear++] = w;
            }
        }
    }
}

parent 数组存的是「从哪个顶点过来的」，从终点顺着 parent 一路往回走，就得到一条最短路径。这个技巧在 Dijkstra 和 Floyd 里会再出现一次。

带权图不能这么干。BFS 数的是边数，一条权值 100 的边和一条权值 1 的边在它眼里一样长，这时候就得上 Dijkstra。

两种遍历摆一起看：

对比项 DFS BFS
辅助结构 栈，递归调用栈也算 队列
走法 一条路走到黑，回退 一层一层往外扩
需要 visited 需要 需要
邻接矩阵复杂度 O(n²) O(n²)
邻接表复杂度 O(n + e) O(n + e)
产出 DFS 树、时间戳、回溯顺序 层次、无权最短路
适合解决 连通性、路径存在性、拓扑排序、割点、桥 最少步数、层次关系、二分图染色
空间瓶颈 递归深度，长链会爆栈 队列宽度，星形图会占满 n

两者本质上是同一件事的两种顺序：都是从一个点出发、沿边扩散、每个点只碰一次。区别只在「待访问集合」用栈还是用队列。

十三、遍历与连通分量 #

前面所有代码都假设图是连通的。真跑在非连通图上，DFS(v) 只走完 v 所在的那一块，剩下的顶点一个都不会被打印。所以遍历要包一层外层循环：

c
/* 遍历整张图，返回连通分量个数 */
int traverseAll(MGraph *G) {
    int cnt = 0;
    memset(visited, 0, sizeof(visited));
    for (int v = 0; v < G->vexnum; v++) {
        if (!visited[v]) {
            cnt++;
            printf("第 %d 个连通分量: ", cnt);
            DFSMatrix(G, v);
            printf("\n");
        }
    }
    return cnt;
}

外层循环的语义很直白：每找到一个没访问过的顶点，就意味着撞上了一个新的连通分量，从它开始遍历一次，把这一块吃干净。

由此得出一条可以拿来验算的结论：

  • 连通图调用一次 DFS，非连通图调用多次
  • 外层循环体被执行的次数，就是连通分量的个数
  • 图里有孤立顶点时，每个孤立顶点单独算一个分量，遍历时只会打印它自己

把 DFS 换成 BFS，分量个数不变，只是块的内部顺序变了。

遍历序列不唯一，这件事要一次说清，它有三个来源：

  1. 起点不同，序列就不同。非连通图上更是如此
  2. 存储顺序不同。邻接矩阵按编号扫，邻接表按链表走，而链表是头插的
  3. 同一份存储下，邻居的物理顺序取决于建图的先后顺序

所以做题时看到「写出 DFS 序列」，先确认题目的约定：从哪个顶点开始，邻居按什么顺序编号。这两条不一样，答案就不一样。

遍历还有一个用处：把「判断连通」变成「跑一遍就完事」。两种判断方式的差别只在复杂度上——矩阵 O(n²)，表 O(n+e)。

十四、最小生成树：Prim 与 Kruskal #

生成树有 n-1 条边，但一个连通图的生成树有很多棵。边带权之后，总权最小的那棵叫最小生成树（MST）。它回答的是这类问题：n 个城市之间铺光缆，怎么铺总长度最短；n 个机柜之间拉网线，怎么拉最省料。

两个算法都建立在同一句话上：把顶点分成两个集合，横跨这两个集合的所有边里，权最小的那条一定属于某棵最小生成树。这叫切分定理。Prim 和 Kruskal 的区别，只是怎么用这句话。

Prim 的思路是滚雪球：先随便挑一个顶点入树，然后每一步都把「离当前树最近的那个顶点」连进来，直到 n 个顶点全部入树。它维护两个数组：

  • lowcost[j]：顶点 j 到当前树的最小边权
  • parent[j]：这条最小边连的是树上哪个顶点
c
/* Prim：邻接矩阵，从 start 开始，打印每条被选中的边 */
void Prim(MGraph *G, int start) {
    int lowcost[MAXV];
    int parent[MAXV];
    int sum = 0, chosen = 0;
    int n = G->vexnum;

    for (int i = 0; i < n; i++) {
        lowcost[i] = G->edge[start][i];
        parent[i] = start;
    }
    lowcost[start] = 0;                 /* 用 0 标记「已经在树上」 */

    for (int k = 1; k < n; k++) {
        int minw = INF, v = -1;
        for (int i = 0; i < n; i++)
            if (lowcost[i] != 0 && lowcost[i] < minw) {
                minw = lowcost[i];
                v = i;
            }
        if (v == -1) {                  /* 剩下的顶点都不可达 */
            printf("图不连通，只有生成森林\n");
            return;
        }
        printf("选边 (%c,%c) 权 %d\n", G->vex[parent[v]], G->vex[v], minw);
        sum += minw;
        chosen++;
        lowcost[v] = 0;                 /* v 入树 */
        for (int i = 0; i < n; i++)
            if (lowcost[i] != 0 && G->edge[v][i] < lowcost[i]) {
                lowcost[i] = G->edge[v][i];
                parent[i] = v;
            }
    }
    printf("总权 %d，共 %d 条边\n", sum, chosen);
}

选最小值的那个循环是 O(n)，外面套 n 次，整体 O(n²)，和边数无关。所以 Prim 在稠密图上顺，稠密图的边多到没法排序，而 Prim 压根不看边数。把「找最小值」换成堆，代价能降下来，此时它更像 Dijkstra 的写法。

Kruskal 的思路是挑边：把所有边按权排序，从小到大一条条试，只要这条边的两端还不在同一个集合里，就收下它。判断「在不在同一个集合」用并查集。

c
typedef struct {
    int u, v, w;
} Edge;

int cmpEdge(const void *a, const void *b) {
    const Edge *x = (const Edge *)a;
    const Edge *y = (const Edge *)b;
    return x->w - y->w;
}

int uf[MAXV];

int findRoot(int x) {
    while (uf[x] != x) {
        uf[x] = uf[uf[x]];              /* 路径压缩 */
        x = uf[x];
    }
    return x;
}

/* 合并成功返回 1；返回 0 说明两端已经连通，收下就成环 */
int unionSet(int a, int b) {
    int ra = findRoot(a);
    int rb = findRoot(b);
    if (ra == rb) return 0;
    uf[ra] = rb;
    return 1;
}

void Kruskal(Edge *edges, int m, int n) {
    for (int i = 0; i < n; i++) uf[i] = i;
    qsort(edges, m, sizeof(Edge), cmpEdge);

    int cnt = 0, sum = 0;
    for (int i = 0; i < m && cnt < n - 1; i++) {
        if (unionSet(edges[i].u, edges[i].v)) {
            printf("选边 (%d,%d) 权 %d\n", edges[i].u, edges[i].v, edges[i].w);
            sum += edges[i].w;
            cnt++;
        }
    }
    if (cnt < n - 1) printf("图不连通，只有生成森林\n");
    else printf("总权 %d\n", sum);
}

cnt 到 n-1 就跳出，这是最小生成树边数的上界，也顺手省掉了剩下的边。图不连通时 cnt 走不满，输出的其实是各分量生成树拼起来的森林。

对比项 Prim Kruskal
思路 扩点，树往上涨 挑边，按权从小到大
辅助结构 两个数组，或一个堆 并查集 + 边排序
复杂度 O(n²)，堆优化可降 O(e log e)，排序是主导项
适合的图 稠密图 稀疏图
需要存什么 邻接矩阵 一张边表
提前终止 等 n 个点入树 cnt 到 n-1

两者给出的结果权值一定相同，选出来的边不一定相同。图里有等权的边时，最小生成树本来就不唯一，考试要写「一棵」而不是「唯一的那棵」。

十五、最短路径：Dijkstra 与 Floyd #

最短路径分两档问法：单源，求一个起点到所有顶点的最短路；全源，求任意两个顶点之间的最短路。Dijkstra 属于第一档：从网络里任意一个顶点出发，求它到其他各顶点的最短路径。很多个起点各跑一遍 Dijkstra，也能凑出全源答案，只是慢。

Dijkstra 是贪心。维护两个集合：已经确定最短距离的 S，和没确定的。每一步从 S 外挑一个 dist 最小的顶点 v，把它并进 S，然后用 v 去松弛它的邻居——如果走 v 中转更近，就更新邻居的 dist。

c
/* Dijkstra：邻接矩阵，单源最短路；dist 存距离，path 存前驱 */
void Dijkstra(MGraph *G, int start, int dist[], int path[]) {
    int S[MAXV] = {0};
    int n = G->vexnum;

    for (int i = 0; i < n; i++) {
        dist[i] = G->edge[start][i];
        path[i] = (i != start && dist[i] < INF) ? start : -1;
    }
    S[start] = 1;                       /* 起点自己距离是 0 */

    for (int k = 1; k < n; k++) {
        int minw = INF, v = -1;
        for (int i = 0; i < n; i++)
            if (!S[i] && dist[i] < minw) {
                minw = dist[i];
                v = i;
            }
        if (v == -1) break;             /* 剩下的都不可达，提前收工 */
        S[v] = 1;                       /* v 的最短距离就此定死 */
        for (int i = 0; i < n; i++)
            if (!S[i] && G->edge[v][i] < INF &&
                dist[v] + G->edge[v][i] < dist[i]) {
                dist[i] = dist[v] + G->edge[v][i];
                path[i] = v;
            }
    }
}

/* 顺着 path 倒推，打印 start 到 t 的路径 */
void printPath(int path[], int start, int t) {
    if (t == start) {
        printf("%d", start);
        return;
    }
    if (path[t] == -1) {
        printf("不可达");
        return;
    }
    printPath(path, start, path[t]);
    printf(" -> %d", t);
}

复杂度 O(n²)。用堆维护「S 外 dist 最小的顶点」，可以把挑最小值那一步压到对数级，总代价变成 O((n + e) log n) 量级。这也是「稠密用数组、稀疏用堆」的由来。

Dijkstra 有一个硬边界：它不能处理负权边。原因藏在 S[v] = 1 这一行——把 v 并进 S 的那一刻，它的 dist 就被当成最终答案，之后不再改。负权边会让「后来发现的路径更短」这件事成立，假设直接被推翻。

举个能跑出错误答案的例子：

text
A→B 权 1
A→C 权 2
C→B 权 -5

真值：A 到 B 走 A→C→B，长度 2 + (-5) = -3
Dijkstra：先定下 B 的距离为 1（比 C 的 2 小），B 进 S 不再改
结果给出 1，错了

跨过这条边界的算法是 Bellman-Ford：对所有边做 n-1 轮松弛，每轮都允许「绕远再变近」，负权也能收敛，复杂度 O(n·e)。再加一轮，如果还能松弛成功，说明图里有负权环——那个环可以无限绕，最短路径压根不存在。这是它比 Dijkstra 多出来的能力：判负环。

Floyd 解决全源问题，思路是动态规划：dist[i][j] 表示 i 到 j 的最短距离，每次允许用顶点 k 中转过一次。

c
/* Floyd：三重循环，dist 和 path 都是 n×n */
void Floyd(MGraph *G, int dist[][MAXV], int path[][MAXV]) {
    int n = G->vexnum;

    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) {
            dist[i][j] = G->edge[i][j];
            path[i][j] = (i != j && G->edge[i][j] < INF) ? i : -1;
        }

    for (int k = 0; k < n; k++)              /* 中转点必须在最外层 */
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (dist[i][k] < INF && dist[k][j] < INF &&
                    dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                    path[i][j] = path[k][j];
                }
}

三段循环必须按 k、i、j 的顺序摆，k 在最外。写反了不会崩，只是答案错，而且很难查——这是 Floyd 最出名的坑。

四种算法摆一起，选型就一目了然：

算法 解决的问题 负权 负环 复杂度 适合
BFS 无权图单源最短路 不涉及 不涉及 O(n + e) 边权全相同，求最少步数
Dijkstra 单源最短路 不支持 不检测 O(n²) 或 O((n+e)log n) 非负权，单起点
Bellman-Ford 单源最短路 支持 能检测 O(n·e) 有负权边
Floyd 全源最短路 支持 不能有 O(n³) 顶点数不大，要两两距离

一句话的记法：无权用 BFS，非负单源用 Dijkstra，有负权用 Bellman-Ford，要两两距离用 Floyd。

十六、拓扑排序 #

有向无环图有个专门的名字：DAG。有句话值得停一下：树一定是 DAG，但 DAG 不一定是树——树没有环、方向从根往外，所以它一定是 DAG；但 DAG 可以有多个入度为 0 的顶点，也可以有顶点入度大于 1，这都不是树。

拿 DAG 表示「活动之间的先后关系」，顶点是活动、弧是「必须先做」，这张图叫 AOV 网。拓扑排序就是把它排成一个线性序列：每条弧 <u,v> 里，u 都排在 v 前面。

Kahn 算法的做法很糙但管用：每次找一个入度为 0 的顶点，输出它，把它的出边全删掉（等价于邻居的入度各减 1），重复到没有入度为 0 的顶点。

c
/* 邻接表上的拓扑排序；返回 1 表示排完了（无环），0 表示有环 */
int TopoSort(ALGraph *G, int order[]) {
    int indeg[MAXV];
    int queue[MAXV], front = 0, rear = 0;
    int n = G->vexnum;

    for (int i = 0; i < n; i++) indeg[i] = 0;
    for (int i = 0; i < n; i++)
        for (ArcNode *p = G->vertices[i].firstarc; p != NULL; p = p->nextarc)
            indeg[p->adjvex]++;

    for (int i = 0; i < n; i++)
        if (indeg[i] == 0) queue[rear++] = i;

    int cnt = 0;
    while (front < rear) {
        int u = queue[front++];
        order[cnt++] = u;
        for (ArcNode *p = G->vertices[u].firstarc; p != NULL; p = p->nextarc) {
            int v = p->adjvex;
            if (--indeg[v] == 0) queue[rear++] = v;
        }
    }
    return cnt == n;
}

return cnt == n 这一行同时干了两件事：判断有没有排完，顺便判断有没有环。有环的时候，环上的顶点互相等着，入度永远降不到 0，cnt 就凑不满 n。想把环找出来，剩下的那些 indeg 还大于 0 的顶点就是环上或环下游的点。

还有一种写法用 DFS：跑一遍 DFS，按「顶点完成访问的先后」记录下来，最后整段反转。原理是 DAG 上不会出现「祖先比后代更晚完成」。两种写法都能用，Kahn 更好懂，DFS 版顺手能查出环的路径。

拓扑序不唯一。同时有多个入度为 0 的顶点时，先取谁都行。工程上想要稳定输出（比如让构建顺序可复现），就把队列换成按编号排序的优先队列。

这东西真在用：make 决定先编哪个文件，包管理器决定安装顺序，课程表排先修课。

十七、易错点速查 #

下面这些坑按踩到的频率排序，越靠前越常见：

坑 症状 改法
邻接矩阵用 0 表示没有边 「距离 0」和「没路」分不开，一片格子都算成了 0 对角线 0，其余用 INF
拿 INT_MAX 当无穷大 dist[u] + w 溢出成负数，结果离谱 用 0x3f3f3f3f，或加法前先判
无向图只加了一个方向 遍历漏掉一半顶点，度数算小 建图时两个方向都写
BFS 在出队时才标记 visited 队列堆满重复顶点，复杂度退化 入队前标记
Floyd 的 k 写在内层 不报错，答案错，极难查 k 放最外，三段循环顺序固定的
拿 Dijkstra 跑负权图 已定死的距离是错的 负权换 Bellman-Ford
Prim 用 0 标记已入树，图上恰有权 0 的边 那个顶点永远进不来，最后误判成图不连通 另开一个 inTree[] 标记
遍历只调一次 DFS 非连通图只打印一块 外层 for 扫所有顶点
拓扑排序只把第一个入度 0 的顶点入队 输出比顶点数少 初始化时把所有入度 0 的都入队
有向图用邻接表求入度 扫了出边，数目对不上 扫所有顶点的链表，或建逆邻接表
递归 DFS 跑长链 栈溢出，进程直接挂 改显式栈，或加大栈
顶点编号 1-based 和 0-based 混着用 数组越界，或者最后一个顶点没处理 全篇统一 0 到 n-1

再补三条不成表但更常见的错：

一是 malloc 之后不判空。小图看不出来，顶点上百万的时候才炸，那时候已经来不及定位。

二是 visited 数组忘了清零。跑第二遍遍历时结果是空的，因为所有顶点都还标着 1。每次遍历前 memset(visited, 0, sizeof(visited))，别省。

三是对「遍历序列」期望唯一。前面说过，起点、存储顺序、邻居顺序三者任一改变，序列就变。写测试用例的时候，比对集合而不是比对字符串。

图这一关，难的从来不是算法本身。DFS、BFS、Prim、Dijkstra、Floyd、拓扑排序，每一个拆开都只有十几行。真正卡人的是两件事：把一张图正确建进内存，以及在这些数组和链表之上不出下标错。把第七章到第十三章那几段代码自己敲一遍，编译通过、跑出正确输出，后面的算法就只是换一组数组的事。
