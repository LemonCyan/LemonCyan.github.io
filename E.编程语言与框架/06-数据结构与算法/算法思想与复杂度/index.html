一、算法是什么：五个特性 #

数据结构课的名字里只有「数据结构」，但翻开书全是算法。原因很简单：

text
数据结构 + 算法 = 程序

这个式子不是在凑对仗。数据结构与算法是依存关系。只谈数据结构不讲算法，数据是死的，没有活力；只谈算法不讲数据结构，算法没有可操作的对象，只是空谈。落到程序上，数据结构给它血肉骨骼，算法给它灵魂思想，缺一个都不成立。

算法（Algorithm）的定义：算法是解决特定问题求解步骤的描述，在计算机中表现为指令的有限序列，并且每条指令表示一个或多个动作。换成白话，算法是一组有穷的规则、语句与指令的集合，这些指令指明怎样一步步解决某个具体问题。

生活里的例子最容易对上号。冲一杯咖啡也是一串指令：一、烧水；二、冲泡咖啡粉；三、加牛奶。每一步都得写清楚——水烧到多少度，粉放几克，牛奶什么时候倒——含糊一步，最后那杯咖啡就不对。算法写代码是同一个道理，步骤模糊，结果就飘。

真正古老的例子是辗转相除法。它又名欧几里得算法（Euclidean algorithm），3000 年前由欧几里得写在《几何原本》里，是世界上已知最古老的算法。设两数为 a、b，且 a > b：

  1. 用 a 除以 b，得到商 q 与余数 r；
  2. 若 r = 0，最大公约数就是 b，算法结束；
  3. 若 r != 0，令 a = b，b = r；
  4. 回到步骤 1。
c
#include <stdio.h>

/* 辗转相除：求 m 与 n 的最大公约数 */
int euclid(int m, int n)
{
    int r;

    do {
        r = m % n;
        m = n;
        n = r;
    } while (r != 0);

    return m;
}

int main(void)
{
    printf("%d\n", euclid(319, 377));   /* 输出 29 */
    return 0;
}

代码比描述还短。注意循环里三行的顺序：先算余数，再把 n 挪给 m，最后把余数挪给 n。三行写反一行，结果就是错的。

同一个问题可以有多种算法。现实世界的问题千奇百怪，没有一种通用算法能解决全部问题，某些场景下「优秀」的算法还真不一定好用。典型例子是排序：数据量在一万以下时，快速排序的执行效率并没有比冒泡排序快上很多——快排的递归开销和常数因子在小规模上摊不薄，冒泡反而因为顺序访问对缓存友好而不吃亏。选算法先看数据规模，这句话在这一刻就成立了。

五个特性 #

任何算法要成立，都得同时满足五条：输入、输出、有穷性、确定性、可行性。

特性 要求 踩线的写法
输入 有 0 个或多个输入 什么都不传，全靠全局变量，输入来源不可控
输出 至少有 1 个输出 算完只打日志不返回，调用方拿不到结果
有穷性 有限步骤内自动结束，每步在可接受时间内完成 while (1) 里没有出口，或者每步要跑几分钟
确定性 每步含义唯一，无二义性；相同输入只有一条执行路径、唯一输出 依赖随机数或未初始化内存做分支判断
可行性 每步都能通过有限次执行完成 写「求出所有质数」却不给上界

逐条说清楚。

输入与输出：算法有 0 个或多个输入，至少有 1 个输出。输出的形式可以是对外打印，也可以是返回值、写回参数。没有输出的东西不叫算法，叫死循环。

有穷性：算法在执行有限的步骤之后自动结束，不出现无限循环，并且每个步骤都能在可接受的时间内完成。注意「可接受」三个字——穷举 2 的 64 次方步也算有穷，但没人等得起。

确定性：每一步都具有确定的含义，不出现二义性。算法在一定条件下只有一条执行路径，相同的输入只能得到唯一的输出。每一步都被精确定义、没有歧义。

可行性：每一步都可行，也就是每一步都能通过执行有限次数完成。可行性意味着算法可以转成上机程序并得到正确结果。写一句「用最优方法选出最优解」，不给最优的定义和判定方式，这一步就不可行。

好算法的四个指标 #

好的算法应该具备正确性、可读性、健壮性、高效率和低存储量。

正确性分四个层次：

  1. 程序没有语法错误；
  2. 程序对合法的输入能产生满足要求的输出；
  3. 程序对非法的输入能给出满足规格说明的信息；
  4. 程序对精心选择的、甚至刁难的测试数据也能给出满足要求的结果。

证明一个复杂算法在四个层次上全对，需要数学推导，代价非常昂贵。工程上的做法是把层次 3 当作「正确」的判定线：合法输入给对结果，非法输入给明确错误，剩下的靠测试用例兜。

可读性：算法设计的目的之一是方便阅读、理解和交流。晦涩的算法往往隐含错误，不易被发现，也难实现、难调试、难修改。为了追求「用最少的代码描述算法」而写出一段除了机器没人读得懂的代码，这个取舍不划算。可读性是算法好坏很重要的指标。

健壮性：输入数据不合法时，算法能做出相应处理，不产生异常，也不输出莫名其妙的结果。年龄、时间、工号、距离这些不能为负的量收到负数，程序就该报错，而不是继续算下去给个负数结果。

高效率与低存储量：时间上快，空间上省。这两条会打架，第八章之后会反复遇到。

这九种不是并列的九种工具，而是三个层次的划分。递推、递归、迭代讲的是「代码怎么组织」；穷举是兜底思路，任何问题都能穷举，代价是时间；贪心、分治、动规、回溯、分支限界讲的是「问题怎么拆」。本篇的主线就是后五种，第六章先把递归和递推讲透，第七章到第十二章依次展开。

二、时间复杂度：大 O 记号 #

评价算法好坏，有两条路。

事后统计法：写好测试程序和数据，用计时器跑不同算法的实现，比运行时间。这条路直观，但要求先把代码写出来，还得控制变量，换台机器结论就变。

事前分析估算法：在程序编写之前，用统计方法估出算法的量级。一个高级语言程序在机器上跑多久，取决于四个因素：

  1. 算法采用的策略与方法；
  2. 编译产生的代码质量；
  3. 问题的输入规模；
  4. 机器执行指令的速度。

第 1 条是算法好坏的根本，第 2 条取决于软件，第 4 条取决于硬件。第 3 条是我们唯一能自由控制的变量。所以复杂度分析只做一件事：把「运行时间」写成「问题规模 n 的函数」，然后看这个函数长得像什么。

语句频度 #

语句频度是指一条可执行语句在算法中被反复执行的次数。某条语句单次执行时间为 t，执行次数为 f，这条语句耗费的时间就是 t * f。把算法里所有可执行语句的频度加起来，得到总执行次数 T(n)。

拿两个 n 阶方阵相乘做例子：

c
void matrix_mul(int n, double a[n][n], double b[n][n], double c[n][n])
{
    int i, j, k;

    for (i = 0; i < n; i++)                    /* n + 1 次 */
        for (j = 0; j < n; j++) {              /* n * (n + 1) 次 */
            c[i][j] = 0.0;                     /* n * n 次 */
            for (k = 0; k < n; k++)            /* n * n * (n + 1) 次 */
                c[i][j] += a[i][k] * b[k][j];  /* n * n * n 次 */
        }
}

逐个语句数频度，结果如下：

语句 频度
for (i = 0; i < n; i++) n + 1
for (j = 0; j < n; j++) n * (n + 1)
c[i][j] = 0.0; n * n
for (k = 0; k < n; k++) n * n * (n + 1)
c[i][j] += a[i][k] * b[k][j]; n * n * n

这里有一条常被记错的规则：for 语句本身的频度是 n + 1 次，多出来的那一次是最后一次判断 i < n 失败、循环退出的那次；循环体内部的语句执行 n 次。数频度时把这两者混在一起，整个式子就崩了。

五项相加，得到：

text
T(n) = (n + 1) + n(n + 1) + n^2 + n^2(n + 1) + n^3 = 2n^3 + 3n^2 + 2n + 1

三步推出大 O #

已知 T(n)，推导大 O 阶只要三步：

  1. 用常数 1 取代 T(n) 中的所有加法常数；
  2. 只保留最高阶项；
  3. 最高阶项存在且系数不是 1 时，去掉与它相乘的常数。

对上面的例子走一遍：2n^3 + 3n^2 + 2n + 1 里的加法常数本来就是 1，第一步不用动；第二步保留最高阶项得 2n^3；第三步去掉系数得 n^3。所以 T(n) = O(n^3)。

用极限验证一遍。n 趋于无穷时 lim (T(n) / n^3) = 2，极限是个非零常数，说明 T(n) 与 n³ 是同阶无穷大，T(n) 与 n³ 成正比，量级为 n³。这就是 T(n) = O(n^3) 的数学来源。

定义写规范：算法的时间复杂度，指语句总执行次数 T(n) 是关于问题规模 n 的函数，分析 T(n) 随 n 的变化情况来确定它的数量级，记作 T(n) = O(f(n))。它表示随着 n 增大，算法执行时间的增长率与 f(n) 的增长率相同，称为渐进时间复杂度，简称时间复杂度。用 O() 体现复杂度的记法叫大 O 记法。它的含义是增长率的上限，也就是数据规模增大时所耗时间的最大增长率。

大 O 描述的是增长趋势，不是精确时间 #

这一条必须钉死，理解不了它，后面所有的复杂度分析都是白算。

大 O 不看常数，只看增长趋势。O(2n) 与 O(n) 是同一个量级，系数被忽略；O(n + 100) 与 O(n) 是同一个量级，加法常数被忽略；O(n^2 + n) 与 O(n^2) 是同一个量级，低阶项被忽略。

理由在定义里。O 刻画的是 n 趋于无穷时增长率的同阶关系，2n 和 n 的比值恒为 2，是个常数，同阶。既然只比较趋势，任何恒定倍数都不携带信息，扔掉。

推论有三条，写代码时天天用：

  • O(2n)、O(3n + 5)、O(n/2) 全写成 O(n)。三段代码跑起来差两三倍，但 n 翻十倍时一起翻十倍，量级判断上不必区分。
  • 两个 O(n) 的算法实测差 3 倍，那是常数因子的差别，靠改实现（循环展开、减少分支、提高缓存命中）去优化，不要指望换算法。
  • O(n) 与 O(n log n) 差得不多，O(n^2) 与 O(n) 差一个量级，O(2^n) 与 O(n^2) 差的是能不能跑完。真正决定生死的只有量级。

反过来说，大 O 给不出具体毫秒数。O(n log n) 的排序在 n = 10 时跑得比 O(n^2) 的冒泡慢，这完全正常，小规模下常数因子占了主导。判断「这段代码要跑几秒」，得回到实测；判断「数据涨十倍会不会崩」，看大 O。

一个练习 #

自定义一个一维数组，编写查找该数组中最大元素的算法，并分析时间复杂度。

c
int find_max(const int *a, int n)
{
    int i, max = a[0];

    for (i = 1; i < n; i++)
        if (a[i] > max)
            max = a[i];

    return max;
}

循环从 1 走到 n - 1，循环体执行 n - 1 次，比较 n - 1 次，赋值最多 n - 1 次。T(n) = 2(n - 1) + 1，保留最高阶项、去掉系数，得 O(n)。单趟扫描，没有嵌套，这就是线性阶的标准样子。

三、常见复杂度量级与大小关系 #

常用复杂度按耗时从小到大排：

text
O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!) < O(n^n)

小于号后面这几档，差距不是「慢一点」，是「换了个世界」。n = 60 时 O(2^n) 已经是 10 的 18 次方这个量级，一台机器跑不完；O(n!) 到 n = 20 就废了。

只保留最高阶项、去掉系数，这是大 O 的定义决定的，不是习惯问题。

四、空间复杂度 #

算法的空间复杂度通过计算算法所需的存储空间实现，记作 S(n) = O(f(n))，其中 n 为问题规模，f(n) 为语句关于 n 所占存储空间的函数。

一个程序运行时，除了存本身的指令、常数、变量与输入量，还要存对数据操作的辅助单元。复杂度只关心辅助单元那一块，因为指令、常数、输入这三样跟算法设计无关。

这里有个关键判定：算法执行时所需的辅助空间相对于输入量是个常数，就说这个算法原地工作，空间复杂度为 O(1)。

c
/* O(1)：数组原地逆置，只用了 i、j、t 三个变量 */
void reverse(int *a, int n)
{
    int i = 0, j = n - 1, t;

    while (i < j) {
        t = a[i]; a[i] = a[j]; a[j] = t;
        i++; j--;
    }
}

递归的空间开销容易被漏算。递归函数的调用栈要保存每一层的参数、局部变量与返回地址，空间复杂度等于递归深度乘以单帧大小。阶乘的递归写法是 O(n) 空间，二叉树的递归遍历是 O(h) 空间（h 为树高，最坏退化成链时 h = n），归并排序的递归是 O(log n) 层栈加一块 O(n) 的临时数组——第七章的 merge() 就是那块临时数组的去处。

顺序存储与链式存储在空间上的取舍，一张表说清：

维度 顺序表（数组） 单链表
存储分配 一段连续存储单元依次存放 任意存储单元，靠指针串联
空间开销 只有数据本身，另有预分配浪费 每个节点多一个指针域
扩容 满了得整块搬家，O(n) 按需 malloc，无搬家
空间碎片 要求连续大块，容易申请失败 小节点拼起来，碎片可用
容量判断 需预分配，估小了不够、估大了浪费 用多少申请多少

一句话：数组拿空间换访存速度（连续内存、缓存友好、下标 O(1)），链表拿指针换空间弹性（按需分配、插删 O(1)）。

还有一类「拿空间换时间」的常规操作：计数排序开一个值域大小的桶把 O(n log n) 压到 O(n)；散列表开一个桶数组把查找从 O(n) 压到 O(1) 平均；动规开一张表把指数级递归压成多项式。判断标准只有一条——多花的那块空间，换回来的时间量级降没降。降了就是赚，没降就是白花。

五、最好、最坏与平均情况 #

同样一段代码，换一组输入，跑的时间能差一个量级。复杂度只说「关于 n 的函数」还不够，得说清是在哪种输入下的函数。

拿在 n 个数据里查找一个值举例。顺序扫描：

c
int seq_search(const int *a, int n, int key)
{
    int i;

    for (i = 0; i < n; i++)
        if (a[i] == key)
            return i;

    return -1;
}
  • 最好情况：第一个元素就是目标，比较 1 次，O(1)；
  • 最坏情况：目标在最后一个位置，或者根本不在表里，比较 n 次，O(n)。

三种情况的定义：

情况 含义 用途
最好 最省时的输入，给出性能下限 说明「顺利时能多快」，参考价值有限
最坏 最费时的输入，给出性能上限保证 工程默认看这一档
平均 按输入的分布求期望 评估长期表现，要依赖概率假设

最坏情况运行时间是一种保证：运行时间不会比这更坏。没有特殊指定时，算法的时间复杂度默认指最坏情况下的时间复杂度。判断一段代码能不能扛住线上流量，看的正是这一档——流量峰值时数据恰好是最坏布局，这个概率不低。

平均情况从概率角度看。假定目标值出现在每个位置的概率相同、且一定在表里，则比较次数的期望是：

text
(1 + 2 + ... + n) / n = (n + 1) / 2

还是 O(n)，但系数减半。平均运行时间在所有情况里最有意义，因为它就是期望运行时间。麻烦在于平均分析要先假定输入分布，而现实中这个分布很难事前说准，只能靠跑一定量的实验数据去估算。

同一份分布假设，换个算法结论就不一样：

算法 最好 平均 最坏 辅助空间
顺序查找 O(1) O(n) O(n) O(1)
二分查找 O(1) O(log n) O(log n) O(1)
冒泡排序（带提前退出标记） O(n) O(n^2) O(n^2) O(1)
直接插入排序 O(n) O(n^2) O(n^2) O(1)
快速排序 O(n log n) O(n log n) O(n^2) O(log n) 栈
归并排序 O(n log n) O(n log n) O(n log n) O(n)
堆排序 O(n log n) O(n log n) O(n log n) O(1)

快速排序那一行值得盯住。它的最坏情况 O(n^2) 不是理论摆设：每次取首元素做基准，输入恰好已经有序，分区就退化成一边空一边 n-1，递归深度从 log n 变成 n。要压住这个风险，基准取随机或者三数取中。

插入排序那一行反过来看：输入基本有序时它是 O(n)，这是它的看家本领。数据规模小、局部有序的场合，插入排序比快排还合适——这就是「没有通用算法」的实证。

顺带记一个容易被忽略的概念：摊还复杂度。动态数组扩容一次要 O(n) 搬家，但容量翻倍策略下连续 n 次插入的总代价是 O(n)，摊到每次是 O(1)。它不依赖概率假设，只依赖操作序列的整体结构。

六、递归与递推 #

递归是函数直接或间接调用自身。写递归只要抓住两样东西：递归式（把 f(n) 化成 f(更小的 n)）和递归出口（最小的那个 n 直接返回什么）。缺出口就是死循环，缺递归式就没法往出口走。

阶乘是最小的例子：

c
long fact(int n)
{
    if (n <= 1)          /* 递归出口 */
        return 1;

    return n * fact(n - 1);   /* 递归式 */
}

每进一层，栈上压一帧，保存参数 n、返回地址与局部变量。递归深度为 n，所以空间复杂度 O(n)，时间复杂度 O(n)。改成从 2 乘到 n 的循环，空间就降到 O(1)。

斐波那契把递归的问题暴露得很彻底：

c
/* 朴素递归：O(2^n)，同一个子问题被反复算 */
long fib(int n)
{
    if (n <= 2)
        return 1;

    return fib(n - 1) + fib(n - 2);
}

/* 递推：自底向上，O(n) 时间、O(1) 空间 */
long fib_iter(int n)
{
    long a = 1, b = 1, t;
    int i;

    if (n <= 2)
        return 1;

    for (i = 3; i <= n; i++) {
        t = a + b;
        a = b;
        b = t;
    }

    return b;
}

朴素递归的调用树是一棵二叉树，fib(5) 会算两遍 fib(3)、三遍 fib(2)。重叠子问题让指数级的重复计算白白烧掉，这就是第十章要拿动规解决的问题。

汉诺塔是递归的经典形态，也是分治的经典形态：把 n 个盘从 A 借助 B 挪到 C，等于先把 n-1 个从 A 借助 C 挪到 B，再挪最大的那个，再把 n-1 个从 B 借助 A 挪到 C。照这三步写代码，函数体只有两次自调用加一次打印。步数满足 T(n) = 2T(n-1) + 1，解得 T(n) = 2^n - 1。传说是 64 个盘，那就要挪 2^64 - 1 次，按每秒一次算是 5849 亿年。

二叉树的递归建树是另一个典型。按数组下标建完全二叉树，根为 1 号，左孩子 2i，右孩子 2i + 1：

c
typedef struct tree {
    int data;
    struct tree *lchild, *rchild;
} bitree;

bitree *create_bitree(int i, int n)
{
    bitree *root = (bitree *)malloc(sizeof(bitree));
    if (root == NULL)
        return NULL;

    root->data = i;                     /* 节点数据即下标 */

    if (2 * i <= n)                     /* 左孩子存在 */
        root->lchild = create_bitree(2 * i, n);
    else
        root->lchild = NULL;

    if (2 * i + 1 <= n)                 /* 右孩子存在 */
        root->rchild = create_bitree(2 * i + 1, n);
    else
        root->rchild = NULL;

    return root;
}

两个坑：先 malloc 再判断孩子是否存在；不存在的孩子必须显式赋 NULL，否则叶子节点的指针是野值，后面遍历一读就崩。

递推与递归是同一件事的两个方向。递归是自顶向下，把 f(n) 一层层摊开；递推是自底向上，从已知的最小项一步步推到 f(n)。递归代码短、好读，代价是栈空间与函数调用开销；递推省栈，代码长一点，还得想清楚从哪一项开始。

约瑟夫环是递推的主场。33 个犯人围一圈，从第 1 个开始报数，报到 7 的出列，下一个重新从 1 报，直到剩最后一人。问最后剩下的是第几号。一圈一圈模拟要维护一整张表，反过来想：设 f(n) 为 n 个人时的幸存者编号（0 基），杀掉一个人之后，剩下 n-1 个人重新编号，等价于一个规模 n-1 的子问题平移了 m 位：

text
f(1) = 0
f(n) = (f(n - 1) + m) % n

c
int josephus(int n, int m)
{
    int f = 0, i;

    for (i = 2; i <= n; i++)
        f = (f + m) % n;

    return f;      /* 0 基编号 */
}

int main(void)
{
    printf("%d\n", josephus(33, 7) + 1);   /* 输出 12 */
    return 0;
}

n = 33、m = 7 时 f(33) = 11，0 基编号对应第 12 个位置。四行代码替代了整圈模拟，这就是递推的价值。

递归转递推只有两条路：一是记忆化，把算过的子问题存下来（第十章详讲）；二是显式栈，自己开一个数组模拟系统栈。工程上还有第三条——先写递归把逻辑跑通，再按数据规模决定要不要改写成迭代。

递归真正的风险是栈溢出。系统栈默认几 MB，一帧几十字节，递归深度到十万级就有危险；深度跟 n 成正比且 n 很大的场合（链表遍历、大数组快排、深度优先搜索），要么改成迭代，要么显式维护栈，要么限制深度。

七、分治法 #

分治法的思路一句话：把一个大问题分解成若干个规模较小、形式相同的子问题，分别解决，再合并结果。

三个要素，缺一不可：

要素 干什么 漏了会怎样
分解 把原问题划成若干规模更小的同类子问题 拆不出同类子问题，分治退化成穷举
解决 子问题规模足够小时直接求解，这是递归出口 没有出口，无限递归
合并 把子问题的解拼成原问题的解 拆得开拼不回，白拆

适用分治的问题要满足四条：问题缩小到一定规模就能容易解决；问题可以分解为若干规模较小的相同问题；子问题的解能合并成原问题的解；分解出的各个子问题相互独立。

最后一条最要紧——子问题必须独立，也就是同一个子问题不会在多个分支里重复出现。如果子问题之间有大量公共部分，分治会把公共部分算很多遍，这时候正确的选择是动态规划：同样拆子问题，但把结果存起来复用。这一条是分治与动规的分水岭，第十章还会再撞见它。

归并排序是分治的标准实现：分解成左右两半，分别排序，再合并两个有序段。

c
#include <stdlib.h>

static void merge(int *a, int lo, int mid, int hi, int *tmp)
{
    int i = lo, j = mid + 1, k = lo;

    while (i <= mid && j <= hi) {
        if (a[i] <= a[j])          /* 取等号，保证稳定 */
            tmp[k++] = a[i++];
        else
            tmp[k++] = a[j++];
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];

    for (i = lo; i <= hi; i++)
        a[i] = tmp[i];
}

static void msort(int *a, int lo, int hi, int *tmp)
{
    int mid;

    if (lo >= hi)                  /* 只剩 0 或 1 个元素，已经有序 */
        return;

    mid = lo + (hi - lo) / 2;      /* 这样写不会溢出 */
    msort(a, lo, mid, tmp);
    msort(a, mid + 1, hi, tmp);
    merge(a, lo, mid, hi, tmp);
}

void merge_sort(int *a, int n)
{
    int *tmp = (int *)malloc(sizeof(int) * n);
    if (tmp == NULL)
        return;

    msort(a, 0, n - 1, tmp);
    free(tmp);
}

复杂度：递归式 T(n) = 2T(n/2) + O(n)，递归 log n 层，每层合并总代价 O(n)，合起来 O(n log n)。空间上要一块 O(n) 的临时数组加 O(log n) 的栈。

快速排序走的是同一个套路，只是「合并」这一步什么都不用做——分区（partition）完成时基准已经在最终位置，两边各自有序就等于全体有序。分区函数很朴素：取末尾元素做基准，双指针从前扫一遍，把不大于基准的元素依次换到前面，最后把基准换到分界点，返回它的下标。

基准选末尾元素，最坏情况同样是 O(n^2)：输入有序或逆序时，每次分区只切掉一个元素，递归深度从 log n 退化成 n。想稳住 O(n log n) 的期望，基准换成随机下标或三数取中。两种排序的完整实现见《排序算法》，本篇只关心它们怎么体现「分解—解决—合并」。

分治与动规放在一起对照：

维度 分治 动态规划
子问题关系 相互独立，互不重叠 互相重叠，同一子问题反复出现
求解方向 自顶向下递归 自底向上递推（或自顶向下加备忘录）
是否存表 不存，算完就扔 必须存，存下来复用
典型复杂度 O(n log n) 状态数 × 单状态转移代价
代表题 归并排序、快排、汉诺塔、大整数乘法 背包、最长公共子序列、最短路径

判断口诀：拆出来的子问题互不相干，分治；拆出来的子问题反复撞车，动规。

八、二分思想 #

二分查找是最省事的 O(log n) 算法，前提只有一个：数据有序。

c
/* 在有序数组 a[0..n-1] 中找 key，找到返回下标，找不到返回 -1 */
int binary_search(const int *a, int n, int key)
{
    int lo = 0, hi = n - 1, mid;

    while (lo <= hi) {
        mid = lo + (hi - lo) / 2;      /* 防止 lo + hi 溢出 */

        if (a[mid] == key)
            return mid;
        else if (a[mid] < key)
            lo = mid + 1;
        else
            hi = mid - 1;
    }

    return -1;
}

过程就是「每次砍一半」：取中间元素比一下，相等就结束；目标更大就到右半边找，更小就到左半边找；范围空了就说明不存在。每一轮比较都让搜索区间减半，复杂度 O(log n)。

O(log n) 到底多快，用判定树算一遍最清楚。n 个元素最多比较 ⌊log2 n⌋ + 1 次。n = 1000 时最多 10 次，n = 100 万时最多 20 次。线性查找要 100 万次，二分 20 次，这就是量级差。

四个易错点，全在边界上：

c
/* 1. mid 用加法会溢出 */
mid = (lo + hi) / 2;          /* lo、hi 接近 INT_MAX 时是负数 */
mid = lo + (hi - lo) / 2;     /* 正确写法 */

/* 2. 区间开闭要统一，循环条件跟着变 */
/* 闭区间 [lo, hi]：while (lo <= hi)，收缩时 lo = mid + 1 / hi = mid - 1 */
/* 左闭右开 [lo, hi)：while (lo < hi)，收缩时 lo = mid + 1 / hi = mid */

/* 3. 找不到时的返回值要想清楚，-1 与「插入位置」是两回事 */
/* 4. 数据必须先有序；无序数组上二分，结论是随机的 */

二分不止用来查值。凡是「答案有单调性」的问题都能二分，这类题叫二分答案：把「求最小/最大值」变成「猜一个值，判断它行不行」。

c
/* 把 n 件物品装进容量为 cap 的桶，每件不可拆，求最少需要几个桶 */
/* 判定函数：容量为 cap 时桶数不超过 k 是否可行 */
static int can_fit(const int *w, int n, int cap, int k)
{
    int used = 1, cur = 0, i;

    for (i = 0; i < n; i++) {
        if (w[i] > cap)
            return 0;               /* 单件都装不下，直接否 */

        if (cur + w[i] <= cap) {
            cur += w[i];
        } else {
            used++;
            cur = w[i];
            if (used > k)
                return 0;
        }
    }

    return 1;
}

外层就在 [单件最大值, 总和] 这个区间上二分容量：判定可行，把上界收到 mid；判定不可行，把下界抬到 mid + 1；循环条件用 lo < hi。

收缩方式是这套写法的关键。可行时写 hi = mid 而不是 hi = mid - 1，因为 mid 本身就在候选里，减一会把它漏掉；循环条件写 lo < hi 而不是 lo <= hi，因为区间没有收缩时 lo <= hi 会死循环。二分答案把「最优化问题」转成「判定问题」，判定函数是 O(n)，二分是 O(log(值域))，总复杂度 O(n log(值域))。

二分与分治的关系要分清。二分是分治的一个特例——只分解成一份，另一份直接扔掉，所以只要 log n 层递归，不是 O(n log n)。分治是把问题拆成几份都留着算，二分是拆成两份只算一份。

九、贪心算法 #

贪心是每一步都取当前看起来最好的那个选择，取完就不回头。它指望一串局部最优能堆出全局最优。

贪心能用，得同时满足两条性质：

性质 含义 怎么验
贪心选择性质 整体最优解可由一系列局部最优选择达到，每步只看已做的选择，不看未做的 交换论证：把最优解里第一个与贪心不同的选择换掉，证不变差
最优子结构 原问题的最优解包含子问题的最优解 拆掉一步，剩下的仍是同类问题的最优解

活动安排是最好讲的例子：n 个活动各占 [s, e)，同一时刻只能做一个，求最多能安排几个。贪心策略是「按结束时间升序，能排就排」。

c
#include <stdlib.h>

typedef struct { int s, e; } Interval;

static int cmp_end(const void *x, const void *y)
{
    const Interval *a = x, *b = y;
    return (a->e > b->e) - (a->e < b->e);   /* 按结束时间升序 */
}

int max_activities(Interval *v, int n)
{
    int i, cnt = 1, last;

    if (n <= 0)
        return 0;

    qsort(v, n, sizeof(Interval), cmp_end);
    last = v[0].e;

    for (i = 1; i < n; i++)
        if (v[i].s >= last) {       /* 与上一个不冲突 */
            cnt++;
            last = v[i].e;          /* 结束得越早，后面越宽松 */
        }

    return cnt;
}

为什么按结束时间排而不按开始时间、也不按持续时间排？按开始时间早，会挑中一个很长的大活动，把后面全堵死；按持续时间短，同样堵不住。结束得越早，剩下的空间越大，这个选择不看后面，只依赖当前状态，正是贪心选择性质的形态。

贪心不是总对。下面两个反例要背下来。

反例一，0-1 背包。容量 10，物品 A 重 6 值 12、B 重 5 值 9、C 重 5 值 9。按单位价值贪心先拿 A（每单位 2，最高），剩下 4 的容量装不下 B 也装不下 C，总价值 12。最优是 B + C，价值 18。贪心在这里错，因为「拿 A」这个决定的代价要到后面才显现。

反例二，找零。币值 1、3、4，凑 6。贪心先取 4，再取两张 1，共 3 枚；最优是 3 + 3，2 枚。币值换成 1、5、10、25 时贪心又对了，因为大面值是小面值的倍数。贪心对不对取决于币值系统的结构，不取决于贪心本身。

0-1 背包不能贪心，可它的「允许拆分」版本——部分背包——贪心就是对的：按单位价值降序装，最后一件装不下就切一部分。同一个问题，能不能拆，决定贪心成不成立。

贪心在经典算法里的位置：

算法 贪心选择 用什么证明
赫夫曼编码 每次合并权值最小的两棵树 交换论证，合并顺序不影响最优性
Prim 最小生成树 每次取离当前树最近的顶点 切分性质
Kruskal 最小生成树 每次取权值最小且不成环的边 环性质
Dijkstra 单源最短路 每次取未确定顶点中距离最小的 非负权保证不会回头变短
活动安排 每次取结束最早且不冲突的 交换论证

贪心写起来最短，风险也最大：写错了不会报错，只会给出一个看着合理的次优解。手上没有证明，就把它当启发式，靠对拍和随机数据兜底。要证明，用交换论证或者归纳法；证不出来，先怀疑自己挑的指标不对。

十、动态规划 #

动态规划也拆子问题，区别在它把子问题的解存起来，同一个子问题只算一次。能用动规的问题要同时具备两条性质：最优子结构，以及子问题重叠。

子问题重叠是说，自顶向下递归求解时，每次产生的子问题并不总是新问题，有些会被重复计算很多次。动规正是利用这一点：每个子问题只算一次，结果存进表格，下次需要直接查表。子问题数目随输入规模指数增长的场合，这个优化把指数级压成多项式级。

四步写动规，顺序不能乱：

  1. 定义状态：dp[...] 里的每个下标代表什么，值代表什么，一句话说清；
  2. 写转移方程：当前状态从哪些更小的状态来，取最大还是最小还是求和；
  3. 定边界：最小的那些状态直接给值，这是递推的出口；
  4. 定顺序：保证算当前状态时，它依赖的状态已经算完。

0-1 背包是最标准的动规题：n 件物品，每件有重量与价值，背包容量 W，每件最多取一次，求最大总价值。

c
#include <stdlib.h>

/* weight[]、value[] 从 0 开始；返回最大总价值 */
int knapsack01(int n, int W, const int *weight, const int *value)
{
    int *dp = (int *)calloc(W + 1, sizeof(int));
    int i, w, best;

    if (dp == NULL)
        return -1;

    for (i = 0; i < n; i++)
        for (w = W; w >= weight[i]; w--)          /* 倒序！ */
            if (dp[w - weight[i]] + value[i] > dp[w])
                dp[w] = dp[w - weight[i]] + value[i];

    best = dp[W];
    free(dp);
    return best;
}

dp[w] 的定义是「容量为 w 时能装下的最大价值」。转移方程：

text
dp[w] = max(dp[w], dp[w - weight[i]] + value[i])

内层循环必须倒序。正序时 dp[w - weight[i]] 已被本轮更新过，等于同一件物品被取了多次，0-1 背包就变成了完全背包。这个坑每年都有人踩。

二维写法的转移更直白，状态是 dp[i][w]，前 i 件物品、容量 w：

text
dp[i][w] = dp[i-1][w]                                 不取第 i 件
dp[i][w] = max(上面, dp[i-1][w-wi] + vi)              取第 i 件（装得下时）

二维好理解，一维省空间，两者等价。复杂度都是 O(nW) 时间；二维 O(nW) 空间，一维压到 O(W)。

最长公共子序列（LCS）是另一类形态，状态是二维位置：

text
a[i] == b[j] 时：dp[i][j] = dp[i-1][j-1] + 1
a[i] != b[j] 时：dp[i][j] = max(dp[i-1][j], dp[i][j-1])

动规的复杂度有个通式：状态数乘以单个状态的转移代价。背包是 nW 个状态、每个 O(1) 转移，得 O(nW)；LCS 是 nm 个状态、O(1) 转移，得 O(nm)。算复杂度先数状态，再看转移，比背结论可靠。

自顶向下的写法叫备忘录法：还是递归，但进函数先查表，算完写表。它跟递推的差别只在方向，结果一样。递归写起来顺手、递推跑起来省栈，规模大了递推更稳。

贪心与动规的区别，一条一条对着看：

维度 贪心 动态规划
单步决策 每步取局部最优，取完不回退 每步保留全部候选，从子问题的解里挑最优
是否回退 不回退，选了就定了 能回退，靠比较不同子问题的解纠正早先的判断
保存什么 只保存当前状态 保存全部子问题解（或滚动的一层）
正确性 需要证明贪心选择性质，证不出就会错 只要最优子结构与重叠子问题成立，结果就对
复杂度 低得多，往往 O(n log n) 或 O(n) 高一些，O(状态数 × 转移代价)
失效场景 0-1 背包、非倍数币值找零 子问题不重叠时退化成普通递归，白存表
典型题 活动安排、赫夫曼、最小生成树 背包、LCS、编辑距离、最短路径

一句话记住分界：局部最优等于全局最优、并且能证明，用贪心；局部最优不保证全局最优、但子问题重复，用动规。

十一、回溯法 #

回溯法是带剪枝的深度优先搜索。它把问题的解表示成一棵解空间树，从根往下走，走不通就退回上一层换个分支。

三个概念对上手写：

概念 对应代码 说明
路径 已经做过的选择 记录当前走到哪，用于判断结束与冲突
选择列表 当前还能做的选择 每层循环遍历它
结束条件 到达叶子或满足目标 收集结果或返回

回溯的骨架是固定的：

text
void backtrack(路径, 选择列表)
{
    if (满足结束条件) {
        收集结果;
        return;
    }

    for (每个可选的选择) {
        if (不可行)  continue;      /* 剪枝 */
        做选择;
        backtrack(新路径, 新选择列表);
        撤销选择;                    /* 回到上一层，这就是「回溯」 */
    }
}

八皇后是最经典的例子：8×8 棋盘放 8 个皇后，同行同列同对角线不能有两个。

c
#include <stdio.h>
#include <stdlib.h>

#define N 8

static int col[N];        /* col[r] = 第 r 行皇后所在列 */
static int total = 0;

static int ok(int row, int c)
{
    int r;

    for (r = 0; r < row; r++)
        if (col[r] == c || abs(col[r] - c) == row - r)
            return 0;     /* 同列，或同一条对角线 */

    return 1;
}

static void place(int row)
{
    int c;

    if (row == N) {       /* 8 行都放好了 */
        total++;
        return;
    }

    for (c = 0; c < N; c++)
        if (ok(row, c)) {
            col[row] = c;         /* 做选择 */
            place(row + 1);       /* 进下一行 */
        }
}

place(row + 1) 返回之后不需要显式撤销：下一轮循环的 col[row] = c 会把旧值覆盖掉。这是回溯里最省事的一种形态——状态就是数组的一个位置，天然可撤销。要维护栈、动态数组、计数器的场合，就得老老实实写反向操作。

剪枝决定回溯能不能跑完。两类剪枝：

  • 可行性剪枝：当前选择已经违反约束，直接砍。八皇后的 ok()、数独的冲突检测都是这一类。
  • 最优性剪枝：当前代价已经超过已知最优解，砍掉——这一类在分支限界里用得更多。

八皇后只有 92 个解，不加剪枝要搜 8^8 = 1677 万次；加上行列对角线的即时判断，节点数掉到几千。回溯与穷举的差别就在这一点：穷举生成全部候选再验证，回溯边走边验，不合法的枝根本不往下走。

全排列、子集、组合、括号生成、数独、图的着色、子集和，都是同一副骨架。写的时候只问三件事：路径怎么记、选择列表怎么遍历、什么条件下停。

十二、分支限界 #

分支限界法在解空间树上做广度优先搜索（或者按代价优先的优先队列搜索），每到一个节点就估一个界，界不优于当前已知最好解的，整枝砍掉。

与回溯的差别是系统性的：

维度 回溯法 分支限界法
搜索方式 深度优先，一条路走到底 广度优先，或按界排序的优先队列
目标 找所有解，或任一可行解 找一个最优解
剪枝依据 约束条件（可行性） 界的比较（最优性）
存储 系统栈，O(深度) 活结点表，O(宽度)
典型题 八皇后、全排列、子集和 0-1 背包最优值、旅行商、任务分配

两种实现形态：

  • 队列式分支限界：活结点进 FIFO 队列，按层逐个扩展，就是标准 BFS。
  • 优先队列式分支限界：活结点按界的优先级排序，每次取最有希望的扩展，也叫最佳优先搜索。

限界函数是这套方法的核心。以 0-1 背包求最大价值为例：把物品按单位价值降序排好，对一个部分装入的方案，剩下的容量按顺序继续装、最后一件允许切分，算出的价值就是该节点的上界——因为允许拆分只会更宽松，真实的最优值不会超过它。搜索时维护一个当前最好解 best，任何上界不超过 best 的节点直接丢弃。

旅行商问题（TSP）同理，下界用「每个顶点最短两条边之和的一半」这类松弛估计，走的路径已经超过当前最优回路就直接剪。

十三、十种经典算法速览 #

前面把思想讲完了，这一节把「十大基础算法」按流程过一遍。它们是前面思想的具体化身，每一行都标出它属于哪种思想。

序号 算法 思想归属 复杂度 用途

2 堆排序 选择（堆结构） O(n log n) 大数据量、要求原地

快速排序：选一个基准（pivot），把比它小的放前面、比它大的放后面，这一步叫分区（partition）；分区完成后基准已经在最终位置；再对左右两段递归。递归最底层是规模为 0 或 1 的段，天然有序。虽然一直递归下去，但算法总会退出，因为每轮至少把一个元素摆到它最终的位置上。拿 [3, 6, 8, 10, 1, 2, 1] 选 3 做基准，分区后得到 [1, 2, 1, 3, 6, 8, 10]，再分别排 [1, 2, 1] 与 [6, 8, 10]。快排的常数因子小，内部循环在多数架构上高效，实际比同样 O(n log n) 的算法快。

堆排序：堆是近似完全二叉树，且每个父节点的键值总是不小于（或不大于）子节点。步骤是建一个最大堆，把堆首（最大值）与堆尾互换，堆尺寸减 1，再对根做下沉（shift_down）恢复堆性质，重复到堆尺寸为 1。全程 O(n log n)，原地，只要 O(1) 额外空间。

归并排序：申请一块大小为两个有序段之和的空间；两个指针分别指向两段开头；比较指针所指元素，取较小的放进合并空间并移动指针；某一段走完后，把另一段剩下的直接拷到尾部。这是分治「先分解、再合并」中合并一步的标准写法。

二分查找：从有序数组中间开始比，相等就结束；目标大就在右半边找，小就在左半边找；范围空了说明不存在。每比较一次搜索范围减半，O(log n)。在 [1, 2, 3, 4, 5] 里找 3，第一次就命中中间元素。

BFPRT：从 n 个元素里选第 k 大（或第 k 小），最坏情况仍保证线性时间。步骤是把 n 个元素每 5 个一组分成 ⌈n/5⌉ 组；每组内部排序（插入排序即可）取中位数；递归调用选择算法找出这些中位数的中位数 x（偶数个时取中间小的那个）；用 x 分割数组，设小于等于 x 的有 k 个，大于 x 的有 n-k 个；若要找的序号等于 k 就返回 x，小于就在左段递归，大于就在右段递归找第 i-k 小的。终止条件是 n = 1，返回的就是要找的元素。它与快排同源，差别在基准的选法——快排随机选会撞上最差情形，BFPRT 每次取中位数的中位数，保证划分比例不离谱。

DFS：从顶点 v 出发访问它，再依次从 v 的未访问邻接点出发做深度优先遍历，直到与 v 连通的顶点全被访问；若还有顶点未访问，换一个起点重复，直到全图访问完。走法细节：访问 v 后到邻接点 w1，从 w1 到 w2，一路深入，直到某个顶点 u 的所有邻接点都被访问过；这时退回一步到刚访问过的顶点，看它还有没有未访问的邻接点，有就继续，没有就再退一步。DFS 属于盲目搜索，一般用栈（或递归）辅助实现。它能生成拓扑排序表，用来解最大路径一类问题。

BFS：从根节点开始，沿宽度逐层遍历；根入队，取队头判断是否目标，是就结束，否则把未检验过的子节点全部入队，队列空说明整张图查完、找不到目标。BFS 同样属于盲目搜索，用队列辅助实现。无权图上 BFS 第一次到达某点就是最短路。

Dijkstra：在非负权有向图上求单源最短路径，用广度优先的方式逐步确定。初始令 S = {V0}，T = {其余顶点}，T 中顶点的距离值有弧就是弧上权值，没有就是无穷；从 T 中取距离值最小的顶点 W 加进 S；再修正 T 中其余顶点的距离值——若加入 W 作中间顶点能让 V0 到 Vi 变短就更新；重复到 S 含全部顶点。最终得到一棵最短路径树，常用在路由算法里，或作为其他图算法的子模块。对不含负权的有向图，它是已知最快的单源最短路算法。

动态规划：见第十章。经典题是背包，两条性质是最优子结构与子问题重叠。

朴素贝叶斯：基于贝叶斯定理的概率分类方法。基础是概率推理——各种条件不确定、只知道出现概率的情况下怎样完成推理与决策。它建立在独立假设上：样本的每个特征与其他特征都不相关，据此对每个特征的条件概率分别估计；再基于训练数据算出各类别的概率；最后比后验概率，取最大的那个类作为结果。参数估计多用最大似然估计，在有监督样本上分类效果不错，文本分类与垃圾邮件过滤是它的老本行。

十四、算法设计的选择 #

拿到一道题，先别写代码，按顺序问四个问题。

第一个问题：规模多大。n ≤ 20，指数级也能过，回溯、穷举都行；n ≤ 1000，O(n^2) 可以；n ≤ 10^5，得 O(n log n)；n 到了 10^7，只能 O(n) 或更低。

第二个问题：要一个最优解，还是所有解。要所有解，回溯；要一个最优解，看能不能用贪心或动规。

第三个问题：子问题重不重叠。拆出来的子问题互不相干，分治；反复撞车，动规。

第四个问题：局部最优能不能证明等于全局最优。能证明，贪心，最快；证不出来，动规。

五种思想的完整对照：

思想 核心动作 解的性质 空间代价 能解决什么 什么时候失效
分治 分解、解决、合并 精确 递归栈 + 合并缓冲 子问题独立的计算题 子问题重叠，重复计算爆炸
二分 每轮砍掉一半 精确 O(1) 有序表查找、答案单调的最优化 数据无序、答案无单调性
贪心 每步取局部最优 精确（需证明） O(1) 或 O(n) 区间调度、最小生成树、赫夫曼 局部最优不等于全局最优
动规 存子问题解，递推 精确 O(状态数) 背包、LCS、最短路径 子问题不重叠，存表白费
回溯 DFS + 撤销 + 剪枝 精确（可枚举全部） O(深度) 八皇后、全排列、数独 解空间太大、剪枝无效
分支限界 BFS/优先队列 + 界 最优解 O(宽度) 0-1 背包最优值、TSP 界估不准，退化成分支穷举

三条实战心得。

其一，先写对的，再写快的。暴力版本是对拍基准，没有它，优化后的版本对不对都说不清。

其二，规模决定上限。O(2^n) 的算法在 n = 30 时还能忍，n = 60 时再优化常数也没用，只能换思想。

其三，数据本身的特征经常比算法更值钱。基本有序的输入让插入排序变成 O(n)；值域很小的整数让计数排序变成 O(n)；只有几十个不同取值的状态让记忆化搜索直接落到多项式。先看数据，再挑算法。

回溯忘记撤销 多路搜索后状态被污染，后续结果全错 做选择与撤销成对出现，或让赋值天然覆盖
回溯不剪枝 八皇后搜 1677 万次 每步即时判冲突，不可行立刻 continue
分支限界界估错 上界估小了，把最优解剪掉 上界必须真上界（松弛后不会更小）
递归深度失控 链表十万节点递归遍历，栈溢出 改迭代、显式栈，或限制深度
数组越界 length - 1 与 length 混用 线性表长度是实际元素个数，末元素下标是 length - 1

最后收一句：复杂度分析只回答「数据涨十倍会不会崩」，不回答「这段代码跑几毫秒」。分治、贪心、动规、回溯、分支限界也不是五个并列的选项，而是五把不同量级的刀——先看清问题的形状，再决定动哪一把。
