一、受限的线性表 #

线性表是 n 个同类型元素的有限序列。数组是它的顺序存储，链表是它的链式存储。这两条路走完，元素的「位置关系」已经讲清楚了：谁在谁前面，怎么找下一个。

栈和队列在这之上只改一件事：允许插入和删除的位置被限定死了。

结构 插入位置 删除位置 访问特征 典型行为
线性表 任意位置 任意位置 随机 / 顺序 无约束
栈 只在一端（栈顶） 同一端（栈顶） 只能碰最新的 后进先出
队列 只在一端（队尾） 只在另一端（队头） 只能碰最老的 先进先出
双端队列 两端都可以 两端都可以 两端都能碰 栈与队列的并集

这张表是本篇的全部出发点。后面十几节，讲的都是这几行限制推出来的后果。

理解「受限」这两个字，要抓住一个反直觉的点：限制不是削减能力，是换来确定性。一个可以任意位置增删的线性表，你没法用它保证「最后进来的最先出去」；一旦把插入删除都压到一端，这个保证就不需要额外代码来维护了，它是结构自带的。

从抽象数据类型（ADT）的角度看，两者都只有寥寥几个操作，比线性表少得多。栈是初始化、销毁、清空、判空、取长度、取栈顶、进栈、出栈；队列把后四个换成取队头、入队、出队，其余一一对应。

操作少，不代表实现简单。真正的坑在存储层：顺序存储要处理下标越界和环绕，链式存储要处理指针失效和内存回收。结构 × 存储 = 四种实现：栈的顺序版是数组加 top 下标，链式版是单链表头插头删；队列的顺序版是数组加 front/rear 取模，链式版是单链表尾插头删。接下来四节把这四格一格一格填掉。

二、栈：后进先出 #

栈是限定仅在表的一端进行插入或删除操作的线性表。

  • 允许插入和删除的那一端，叫栈顶（top）。
  • 另一端叫栈底（bottom）。
  • 不含任何元素的栈，叫空栈。
  • 插入叫进栈 / 入栈 / 压栈（push）。
  • 删除叫出栈 / 弹栈（pop）。

栈又叫后进先出线性表，Last In First Out，简称 LIFO。

只有一个出入口，这就是 LIFO 的全部理由。想象一根底部封死的管子，球只能从上面放进去，也只能从上面拿出来。最先放进去的球压在最底下，最后才轮得到它。

text
        栈顶 top  ->  [ 4 ]   <- 最后进来，最先出去
                     [ 7 ]
                     [ 1 ]
        栈底 bottom-> [ 9 ]   <- 最先进来，最后出去

栈顶指针 top 有两种约定，写代码前必须选定一种，中途换会出 bug。

约定 空栈时 栈满时 进栈写法
top 指向栈顶元素 top == -1 top == maxlen - 1 data[++top] = x
top 指向栈顶的下一个空位 top == 0 top == maxlen data[top++] = x

本篇统一用第一种：top == -1 是空栈，top 就是栈顶元素的下标。理由是取栈顶元素时直接 data[top]，少一次减法，写起来顺手。

再看栈顶元素出栈的顺序问题。元素 1 2 3 依次进栈，出栈顺序只能是 3 2 1；如果允许进栈出栈交替进行，出栈序列就有多种形态。这个「合法出栈序列」的判断，第十二章会专门给判法。

栈的操作全部是常数时间。进栈、出栈、取栈顶，都是改一个下标或动一个指针，跟元素个数无关。这是栈能被塞进函数调用路径里的前提——调用一次函数才几十纳秒，栈操作不能拖后腿。

三、栈的顺序存储实现 #

顺序栈用一段连续数组存元素，再拿一个整型 top 记录栈顶位置。结构定义只有三个成员：数组指针、最大容量、栈顶下标。

c
typedef int data_t;

typedef struct {
    data_t *data;    /* 指向栈的存储空间 */
    int maxlen;      /* 栈的最大元素个数 */
    int top;         /* 栈顶元素的下标，-1 表示空栈 */
} seqstack_t;

下面是完整实现，一个文件就能编译跑起来。这套代码顺手修了几处硬伤：date_t 拼错、判空函数名写成 EmptySqstack、max_len 和 maxlen 两个字段名混用。这三处任何一处留着，编译器都过不去。

c
#include <stdio.h>
#include <stdlib.h>

#define OK      0
#define ERROR  -1

typedef int data_t;

typedef struct {
    data_t *data;
    int maxlen;
    int top;
} seqstack_t;

/* 创建空栈：max_len 必须为正 */
seqstack_t *CreateEmptyStack(int max_len)
{
    seqstack_t *stack;

    if (max_len <= 0)
        return NULL;

    stack = (seqstack_t *)malloc(sizeof(seqstack_t));
    if (stack == NULL)
        return NULL;

    stack->data = (data_t *)malloc(sizeof(data_t) * max_len);
    if (stack->data == NULL) {
        free(stack);
        return NULL;
    }

    stack->maxlen = max_len;
    stack->top = -1;
    return stack;
}

/* 销毁：先放数组，再放结构体，顺序反了就是野指针 */
void DestroyStack(seqstack_t *stack)
{
    if (stack == NULL)
        return;
    free(stack->data);
    free(stack);
}

/* 清空：只回退下标，不释放空间 */
void ClearStack(seqstack_t *stack)
{
    if (stack == NULL)
        return;
    stack->top = -1;
}

int EmptyStack(seqstack_t *stack)
{
    if (stack == NULL)
        return ERROR;
    return (stack->top == -1) ? 1 : 0;
}

int FullStack(seqstack_t *stack)
{
    if (stack == NULL)
        return ERROR;
    return (stack->top == stack->maxlen - 1) ? 1 : 0;
}

int StackLength(seqstack_t *stack)
{
    if (stack == NULL)
        return ERROR;
    return stack->top + 1;
}

int PushStack(seqstack_t *stack, data_t x)
{
    if (stack == NULL)
        return ERROR;
    if (FullStack(stack) == 1)
        return ERROR;              /* 栈满，拒绝写入，别覆盖 */

    stack->top++;
    stack->data[stack->top] = x;
    return OK;
}

int PopStack(seqstack_t *stack, data_t *x)
{
    if (stack == NULL)
        return ERROR;
    if (EmptyStack(stack) == 1)
        return ERROR;              /* 空栈出栈是非法操作 */

    if (x != NULL)
        *x = stack->data[stack->top];
    stack->top--;
    return OK;
}

int GetTop(seqstack_t *stack, data_t *x)
{
    if (stack == NULL)
        return ERROR;
    if (EmptyStack(stack) == 1)
        return ERROR;

    if (x != NULL)
        *x = stack->data[stack->top];
    return OK;
}

连压 5 个进容量 4 的栈再全部弹出，边界表现符合预期：

text
push 50 rejected, stack full    第 5 个被拒，前 4 个保留
top = 40, len = 4               只读不删
pop 40, left 3
pop 10, left 0
pop empty stack -> -1           空栈出栈返回 -1

顺序栈的账要算清楚。

指标 值 说明
进栈 O(1) 一次下标自增加一次赋值，不扩容
出栈 O(1) 一次读加一次下标自减
取栈顶 O(1) 直接读 data[top]
判空判满 O(1) 两次比较
空间 O(maxlen) 创建时就定死，后续不变

代价也很直接：容量固定。开小了溢出，开大了浪费。元素数量波动大的场景，就该换链式存储。

还有一处容易忽略：PopStack 只是把 top 减一，数组里那格数据没清。对 int 无所谓，但如果元素是指针，那格留下的旧指针会让调试器误判。要求严格的场合，出栈时顺手写个零。

四、栈的链式存储实现 #

元素数量变化范围大、事先说不清要存多少个，就该上链栈。链栈用单链表表示，插入和删除全在链表头部做——链表头就是栈顶，链表尾就是栈底。

方向的理由很直白。单链表找头是 O(1)，找尾是 O(n)。栈只看一端，把那一端放在头上，进栈出栈就都是 O(1)。反过来把栈顶放链表尾，每次操作都要从头走到尾，退化成 O(n)。

链栈有两种写法：带头结点和不带头结点。教材上两种都常见。本篇用带头结点，理由是空栈和非空栈的代码路径能统一——头结点永远存在，PushStack 不用特判「表头为空怎么办」。

c
typedef int data_t;

typedef struct node_t {
    data_t data;          /* 数据域，头结点的 data 不用 */
    struct node_t *next;  /* 链接指针 */
} linkstack_t;

完整实现：

c
#include <stdio.h>
#include <stdlib.h>

#define OK      0
#define ERROR  -1

typedef int data_t;

typedef struct node_t {
    data_t data;
    struct node_t *next;
} linkstack_t;

/* 头结点不存数据，它的 next 指向栈顶元素 */
linkstack_t *CreateEmptyLinkstack(void)
{
    linkstack_t *top = (linkstack_t *)malloc(sizeof(linkstack_t));
    if (top == NULL)
        return NULL;
    top->data = 0;
    top->next = NULL;
    return top;
}

int EmptyLinkstack(linkstack_t *stack)
{
    if (stack == NULL)
        return ERROR;
    return (stack->next == NULL) ? 1 : 0;
}

int PushStack(linkstack_t *stack, data_t x)
{
    linkstack_t *node;

    if (stack == NULL)
        return ERROR;

    node = (linkstack_t *)malloc(sizeof(linkstack_t));
    if (node == NULL)
        return ERROR;           /* 内存耗尽时要报错，不能直接解引用 */

    node->data = x;
    node->next = stack->next;   /* 新结点插在头结点之后，即栈顶 */
    stack->next = node;
    return OK;
}

int PopStack(linkstack_t *stack, data_t *x)
{
    linkstack_t *node;

    if (stack == NULL)
        return ERROR;
    if (stack->next == NULL)
        return ERROR;           /* 空栈 */

    node = stack->next;
    stack->next = node->next;

    if (x != NULL)
        *x = node->data;
    free(node);
    return OK;
}

int GetTop(linkstack_t *stack, data_t *x)
{
    if (stack == NULL || stack->next == NULL)
        return ERROR;
    if (x != NULL)
        *x = stack->next->data;
    return OK;
}

void ClearLinkstack(linkstack_t *stack)
{
    linkstack_t *node;

    if (stack == NULL)
        return;

    while (stack->next != NULL) {
        node = stack->next;
        stack->next = node->next;
        free(node);
    }
}

/* 销毁：先清空结点，再放头结点 */
void DestroyLinkstack(linkstack_t *stack)
{
    if (stack == NULL)
        return;
    ClearLinkstack(stack);
    free(stack);
}

注意 ClearLinkstack 和 DestroyLinkstack 的调用顺序。有一版流传很广的写法是先 free(stack) 再清链表，那是彻底的野指针。先清子结点，再放头，顺序不能反。

遍历就从头结点往后走，依次打印。入栈序列 1 2 3 打印出来是 {3, 2, 1}：3 后进，所以它在最前面。这个倒序就是「后进先出」最直观的证据。

两种栈摆在一条线上比。

维度 顺序栈 链栈
容量 创建时定死 按需增长，只受内存限制
进栈 均摊 O(1)，满了要扩容搬数据 O(1)，一次 malloc
出栈 O(1) O(1)，一次 free
空间开销 只有数据本身 每个元素多一个指针
内存连续性 连续，缓存友好 分散，跨结点访问有跳转
溢出风险 有，栈满即拒 无，内存耗尽才失败
适用场景 数量可预估、性能敏感 数量不可预估、反复伸缩

一句实操建议：压测前先估算最大深度。深度可控（括号匹配、表达式求值这类）就用顺序栈，省一次 malloc 就省一次 malloc。只有递归深度随输入变化、事先说不清的结构，才值得上链栈。

五、栈的应用：括号匹配 #

这是栈最容易讲明白的应用。给一段字符串，里面混着 ()、[]、{}，判断括号是否配对。

规则只有三条：

  1. 左括号一律进栈。
  2. 遇到右括号，取栈顶看是否同类型。同类型就弹出，不同类型直接判失败。
  3. 扫完整个字符串，栈必须为空。

第三条是很多人漏掉的。"(((" 这种输入，全程没有右括号触发检查，扫完栈里还剩三个左括号——不判空就会误判成合法。

完整实现：

c
#include <stdio.h>

#define MAX_BRACKET 128

typedef struct {
    char data[MAX_BRACKET];
    int top;
} bstack_t;

/* 返回 1 合法，0 非法 */
int BracketMatch(const char *expr)
{
    bstack_t s;
    int i;
    char c, t;

    s.top = -1;

    for (i = 0; expr[i] != '\0'; i++) {
        c = expr[i];

        if (c == '(' || c == '[' || c == '{') {
            if (s.top == MAX_BRACKET - 1)
                return 0;              /* 栈满，说明嵌套过深，直接拒 */
            s.data[++s.top] = c;
        } else if (c == ')' || c == ']' || c == '}') {
            if (s.top == -1)
                return 0;              /* 右括号多余，左边没东西可配 */
            t = s.data[s.top];
            if ((t == '(' && c == ')') ||
                (t == '[' && c == ']') ||
                (t == '{' && c == '}')) {
                s.top--;               /* 配对成功，弹出 */
            } else {
                return 0;              /* 类型错位，如 (] 或 {) */
            }
        }
        /* 其他字符忽略 */
    }

    return (s.top == -1) ? 1 : 0;      /* 栈空才算全配完 */
}

把这些用例逐个丢进去跑，结果如下。

输入 结果 原因
{[()]} OK 逐层配对
((())) OK 同类型嵌套
([)] FAIL 类型错位，栈顶是 [ 却来了 )
((( FAIL 左括号多余，扫完栈非空
))) FAIL 右括号多余，空栈上取栈顶
空串 OK 没有括号，天然配平

空串返回 OK，这是定义问题：没有任何括号的表达式当然算配平。要按业务改成返回 FAIL，加一行 if (expr[0] == '\0') return 0; 就行。

拿 ([)] 走一遍，看栈被怎么用：

text
读 '('  栈: (              左括号进栈
读 '['  栈: ( [            左括号进栈
读 ')'  栈顶是 '['，要的是 '('  -> 类型错位，FAIL

如果不用栈，这个判断会很难写。你会需要记录「当前最内层未闭合的是哪种括号」，而这个「最内层」恰好就是后进先出的语义：最后进来的未闭合左括号，才是下一个右括号该对上的那个。栈在这里不是数据结构选型，是问题本身的结构。

时间复杂度 O(n)，每个字符进出栈各一次。空间复杂度 O(n)，最坏情况全是左括号。

实际工程里，这段逻辑还管着另外两件事：编译器检查括号是否闭合（报错位置要精确到行列），以及 JSON/XML 这类格式解析器的配平检查。原理一样。

六、栈的应用：表达式求值 #

人写的是中缀表达式，运算符夹在操作数中间：9+(3-1)*3+10/2。计算机直接算中缀很别扭，因为要反复回退找优先级。两条路子：转成后缀再算，或者双栈直接算。先讲后缀，它是标准解法。

从后缀表达式说起 #

后缀表示法又叫逆波兰表示法（Reverse Polish Notation），运算符写在两个操作数之后。

写法 表达式
中缀 9+(3-1)*3+10/2
后缀 9 3 1 - 3 * + 10 2 / +
前缀 + + 9 * - 3 1 3 / 10 2

后缀的优点：没有括号，没有优先级，从左往右扫一遍就能算完。规则只有一条——

从左到右遍历，遇到数字就进栈，遇到运算符就弹出栈顶两个元素运算，结果再压回栈。

弹出来的顺序不能反。先弹出的是右操作数，后弹出的是左操作数。减法除法上反了，结果就全错。这是本节第一大坑。

拿 9 3 1 - 3 * + 10 2 / + 完整走一遍：

步骤 读到 动作 栈内（底→顶）
1 9 进栈 9
2 3 进栈 9 3
3 1 进栈 9 3 1
4 - 弹 1、3，算 3-1=2，压栈 9 2
5 3 进栈 9 2 3
6 * 弹 3、2，算 2*3=6，压栈 9 6
7 + 弹 6、9，算 9+6=15，压栈 15
8 10 进栈 15 10
9 2 进栈 15 10 2
10 / 弹 2、10，算 10/2=5，压栈 15 5
11 + 弹 5、15，算 15+5=20，压栈 20
12 结束 栈里剩一个数即结果 20

中缀转后缀 #

转换规则：从左到右扫中缀表达式。

  • 遇到数字，直接输出。
  • 遇到 (，进栈。
  • 遇到 )，把栈里元素依次弹出并输出，直到弹出 ( 为止，( 只弹不输出。
  • 遇到运算符，把栈里优先级大于或等于它的运算符依次弹出并输出，然后自己进栈。
  • 扫完，把栈里剩下的全弹出输出。

拿 9+(3-1)*3+10/2 走一遍：

步骤 读到 动作 输出 符号栈（底→顶）
1 9 数字，输出 9 空
2 + 栈空，进栈 9 +
3 ( 左括号，进栈 9 + (
4 3 数字，输出 9 3 + (
5 - 栈顶 ( 优先级最低，- 进栈 9 3 + ( -
6 1 数字，输出 9 3 1 + ( -
7 ) 弹到 ( 为止，输出 - 9 3 1 - +
8 * 栈顶 + 优先级低于 *，* 进栈 9 3 1 - + *
9 3 数字，输出 9 3 1 - 3 + *
10 + * 优先级高于 +，弹出 *；栈顶变 +，优先级相等也弹 9 3 1 - 3 * + 空
11 10 数字，输出 9 3 1 - 3 * + 10 +
12 / 栈顶 + 优先级低，/ 进栈 9 3 1 - 3 * + 10 + /
13 2 数字，输出 9 3 1 - 3 * + 10 2 + /
14 结束 全部弹出 9 3 1 - 3 * + 10 2 / + 空

第 10 步是重点：+ 遇到栈顶 +，同级也要弹。这是左结合性的体现，同级运算符左边的先算。如果写成「大于才弹」，1-2+3 会算成 1-(2+3) = -4，而正确答案是 2。

完整实现 #

c
#include <stdio.h>
#include <string.h>

#define MAX_EXPR  256
#define OK        0
#define ERROR    -1

typedef struct {
    char data[MAX_EXPR];
    int top;
} opstack_t;

/* 栈内优先级，'(' 给 0，保证它不被任何运算符弹掉 */
int Priority(char op)
{
    switch (op) {
    case '+':
    case '-':
        return 1;
    case '*':
    case '/':
        return 2;
    case '(':
        return 0;
    default:
        return -1;
    }
}

/* 中缀转后缀。返回后缀串长度，失败返回 -1 */
int InfixToPostfix(const char *infix, char *postfix)
{
    opstack_t s;
    int i = 0, k = 0;
    char c;

    s.top = -1;

    while (infix[i] != '\0') {
        c = infix[i];

        if (c == ' ') {
            i++;
            continue;
        }

        if (c >= '0' && c <= '9') {
            while (infix[i] >= '0' && infix[i] <= '9')
                postfix[k++] = infix[i++];
            postfix[k++] = ' ';      /* 用空格分隔操作数，避免 12 和 1 2 混淆 */
            continue;
        }

        if (c == '(') {
            if (s.top == MAX_EXPR - 1)
                return ERROR;
            s.data[++s.top] = c;
        } else if (c == ')') {
            while (s.top != -1 && s.data[s.top] != '(') {
                postfix[k++] = s.data[s.top--];
                postfix[k++] = ' ';
            }
            if (s.top == -1)
                return ERROR;        /* 右括号多余 */
            s.top--;                 /* 弹出 '('，不输出 */
        } else if (c == '+' || c == '-' || c == '*' || c == '/') {
            while (s.top != -1 && Priority(s.data[s.top]) >= Priority(c)) {
                postfix[k++] = s.data[s.top--];
                postfix[k++] = ' ';
            }
            if (s.top == MAX_EXPR - 1)
                return ERROR;
            s.data[++s.top] = c;
        } else {
            return ERROR;            /* 非法字符 */
        }

        i++;
    }

    while (s.top != -1) {
        if (s.data[s.top] == '(')
            return ERROR;            /* 左括号多余 */
        postfix[k++] = s.data[s.top--];
        postfix[k++] = ' ';
    }

    postfix[k] = '\0';
    return k;
}

/* 后缀求值 */
int EvalPostfix(const char *postfix, int *result)
{
    int stack[MAX_EXPR];
    int top = -1;
    int i = 0, a, b, num;

    while (postfix[i] != '\0') {
        if (postfix[i] == ' ') {
            i++;
            continue;
        }

        if (postfix[i] >= '0' && postfix[i] <= '9') {
            num = 0;
            while (postfix[i] >= '0' && postfix[i] <= '9') {
                num = num * 10 + (postfix[i] - '0');
                i++;
            }
            if (top == MAX_EXPR - 1)
                return ERROR;
            stack[++top] = num;
            continue;
        }

        if (top < 1)
            return ERROR;            /* 操作数不足 */

        b = stack[top--];            /* 先弹出的是右操作数 */
        a = stack[top--];            /* 后弹出的是左操作数 */

        switch (postfix[i]) {
        case '+':
            stack[++top] = a + b;
            break;
        case '-':
            stack[++top] = a - b;
            break;
        case '*':
            stack[++top] = a * b;
            break;
        case '/':
            if (b == 0)
                return ERROR;        /* 除零要拦 */
            stack[++top] = a / b;
            break;
        default:
            return ERROR;
        }
        i++;
    }

    if (top != 0)
        return ERROR;                /* 栈里必须只剩一个结果 */

    *result = stack[top];
    return OK;
}

五组表达式的实测结果（循环调 InfixToPostfix 再调 EvalPostfix）：

中缀 转出的后缀 结果
9+(3-1)*3+10/2 9 3 1 - 3 * + 10 2 / + 20
1-2+3 1 2 - 3 + 2
2*3+4*5 2 3 * 4 5 * + 26
(1+2)*(3+4) 1 2 + 3 4 + * 21
100/5/2 100 5 / 2 / 10

1-2+3 得 2，100/5/2 得 10，这两条就是在验证同级左结合写对了。要是得 -4 和 100，回去看 Priority 的比较符是不是写成了 >。

双栈直接求值 #

不转后缀，两个栈并排：一个存操作数，一个存运算符。思路和中缀转后缀一致，只是遇到运算符不输出，直接取两个操作数算掉；扫完把运算符栈弹到哨兵 # 为止。两条路的复杂度都是 O(n)——转换要扫两遍，双栈扫一遍。要缓存表达式就存后缀，只要结果就双栈。

七、栈的应用：函数调用与递归 #

前面讲过，栈的操作全是 O(1)，这是它能进调用路径的前提。现在看它到底在里面干什么。

递归为什么必须靠栈 #

先看递归的定义：函数在自身的函数体内直接或间接地调用自身。

递归要成立，两个条件缺一不可：

  • 递归出口：什么时候停，直接返回不再调用。
  • 递归逻辑：怎么把规模缩小，向出口靠近。

斐波那契数列的递归写法：

c
#include <stdio.h>

int Fbi(int i)
{
    if (i < 2)                       /* 递归出口 */
        return i == 0 ? 0 : 1;
    return Fbi(i - 1) + Fbi(i - 2);  /* 递归逻辑 */
}

int main(void)
{
    int i;
    for (i = 0; i < 40; i++)
        printf("%d ", Fbi(i));
    printf("\n");
    return 0;
}

少了出口就是死循环，栈会一路涨到爆。少了递归逻辑就是原地踏步，同样死循环。

递归能跑起来，靠的是一个物理事实：函数返回的顺序，是调用顺序的逆序。先调用的后返回。这个「先进后出」的形状，跟栈完全重合。

编译器就是用栈实现递归的。每次调用，压一帧（栈帧，stack frame）进去：

栈帧内容 作用
局部变量 本层独有的数据，各层互不干扰
函数参数 调用时传进来的值
返回地址 本层算完后该回到哪一行继续
上一层栈帧指针 恢复调用者的现场

调用阶段一路压栈，返回阶段一路弹栈。递归出口的作用，就是从「压栈」翻转到「弹栈」的那个开关。

拿 Fbi(3) 走一遍：压 Fbi(3) 帧，它要 Fbi(2) 和 Fbi(1)，先压 Fbi(2) 帧；Fbi(2) 又要 Fbi(1) 和 Fbi(0)，两个都是出口，压进去立刻返回、弹帧；回到 Fbi(2) 算出 1 弹帧，再算 Fbi(1) 得 1 弹帧，最后 Fbi(3) = 1 + 1 = 2 弹帧。压栈最深时有 3 层。

栈的最大深度就是递归的最大深度。这就是为什么递归写深了会「爆栈」——栈空间是有限的（Linux 默认 8 MB 左右），每帧几十到几百字节，深度上万就危险了。

递归和迭代怎么选 #

递归走分支结构，代码短、贴近数学定义，空间要 O(深度)；迭代走循环结构，代码长一点，空间只要 O(1)。两者的风险也不同：递归怕爆栈，迭代怕循环条件写错。时间上递归还有调用开销，斐波那契这类没做记忆化的还会重复计算。

斐波那契的递归版本是反面教材：Fbi(40) 要算几亿次，因为 Fbi(35) 这样的中间值被反复重算。改成迭代只留三个变量，a = 0、b = 1，循环里 t = a + b; a = b; b = t;，复杂度从指数级掉到 O(n)，辅助空间 O(1)。

实操上的判断标准：递归深度可控、逻辑天然分治（树的遍历、快排、归并），就用递归，代码清楚。深度随输入线性增长、且不保证有界（解析超长表达式、遍历未知深度的目录），就手动上显式栈，别赌系统栈够用。

把递归改写成显式栈，套路就一句话：把「编译器替你压的帧」自己压。手写一个结构体存当前状态，循环里压栈弹栈，效果等价，空间可控。

八、队列：先进先出 #

队列只允许在一端插入、在另一端删除。

  • 允许插入的一端叫队尾（rear）。
  • 允许删除的一端叫队头（front）。
  • 先进先出，First In First Out，简称 FIFO。
text
   出队 <- [ 9 ][ 7 ][ 1 ][ 4 ] <- 入队
            front           rear
        队头，最老的        队尾，最新的

和栈的区别只有一处：栈是一个口进出，队列是两个口，一头进一头出。就这一处差别，把 LIFO 换成了 FIFO。

队列的两端各管一件事，互不干扰。入队只动 rear，出队只动 front。这种分工在并发环境里有意义：一个生产者线程只碰 rear，一个消费者线程只碰 front，两边不抢同一块内存。这就是单生产者单消费者队列能做得极快的原因。

队列也有顺序和链式两种存储。顺序队列的坑比顺序栈多得多，多出来的那个坑叫假溢出。

九、队列的顺序存储与假溢出 #

最直白的顺序队列：数组下标 0 是队头，下标 n-1 是队尾。入队就往后面放，出队就把下标 0 的元素删掉。

问题立刻来了：删掉下标 0 之后，后面的元素怎么办？要保持「下标 0 恒为队头」，就得把剩下所有元素全部前移一格。出队一次 O(n)，这个代价没法接受。

改进：队头不再固定在下标 0，让 front 跟着往后走。两个动作各一行：

c
data[(*rear)++] = x;      /* 入队：只加不绕回 */
x = data[(*front)++];     /* 出队：只加不绕回 */

这版省掉了搬数据，但引出一个新毛病。

text
容量 5，先入队 A B C，再出队 A B，再入队 D E

下标      0     1     2     3     4
内容     [ ][ ] [ C ][ D ][ E ]
          ^                 ^
       空  空            rear=5（越界）

front=2, rear=5。队列里只有 3 个元素，容量是 5，
前面还空着 2 格，但 rear 已经顶到数组尽头。
再来一个 F，data[5] 就越界了 —— 这就是假溢出。

假溢出：数组还有空闲位置，但因为 rear 一路递增到了上界而无法继续入队。溢出是「假」的，因为空间并没有真的用完，浪费在前面被出队腾出来的地方。

真溢出是元素个数真的超过了容量，那没救，只能扩容或拒绝。假溢出纯属下标管理方式造成的浪费，必须解决。

解决办法只有一个思路：rear 走到头之后绕回开头。让队列首尾相接，变成一个环。

text
下标      0     1     2     3     4
        [ F ][ ] [ C ][ D ][ E ]
           ^     ^
        rear=1  front=2
F 放在了原来 A 的位置上，环起来了，空间复用。

这就是循环队列。

方案 出队代价 空间利用率 结论
队头固定在 0，出队搬数据 O(n) 100% 太慢，弃
front/rear 只增不绕 O(1) 越来越低 假溢出，弃
front/rear 取模绕回 O(1) 接近 100% 循环队列，用这个

十、循环队列 #

循环队列把数组当成一个环，rear 和 front 都用取模运算推进。

text
入队：rear = (rear + 1) % N
出队：front = (front + 1) % N

下标 4 再加一就回到 0，永远不越界。假溢出现象消失。

新问题马上冒出来：front == rear 到底是空还是满？

text
空队列：front=0, rear=0       两个指针指向同一点
满队列：绕一圈后 front=0, rear=0   两个指针还是指向同一点

两种情况的状态完全一样，靠 front 和 rear 本身区分不出来。这就是循环队列最常考的那个点。三条路可选。

方案 判空条件 判满条件 最大元素数 代价
一、牺牲一个单元 front == rear (rear + 1) % N == front N-1 永远空一格不用
二、加计数器 count == 0 count == N N 多维护一个变量，入队出队都要改
三、加标志位 front == rear && tag == 0 front == rear && tag == 1 N 多维护一个标志，出队置 0 入队置 1

方案一最常用，因为不需要额外字段，判断逻辑藏在取模里。代价是浪费一格——容量 100 的数组只能存 99 个元素。下面的实现就是这一种。

方案二多一个 count 字段：count == maxlen 即满，count == 0 即空，入队 count++、出队 count--。方案三多一个 tag 标志：front == rear && tag == 1 是满，front == rear && tag == 0 是空，出队置 0、入队置 1。

三种方案都要记住「为什么需要它」：front == rear 有歧义。考试问「循环队列如何区分队空队满」，答这三条中任意一条都算对，但要能说出代价。

循环队列的长度公式也要背下来：

text
length = (rear - front + N) % N

为什么加 N：rear 绕回到 front 左边时，rear - front 是负数，加 N 补回一圈。为什么不写成 if (rear > front) rear - front else rear - front + N：取模一行搞定，不用分支。

完整实现（方案一，牺牲一个单元）：

c
#include <stdio.h>
#include <stdlib.h>

#define OK      0
#define ERROR  -1

typedef int data_t;

typedef struct {
    data_t *data;
    int maxlen;          /* 数组容量，实际最多存 maxlen-1 个 */
    int front;           /* 队头元素的下标 */
    int rear;            /* 队尾元素的下一个位置 */
} sequeue_t;

sequeue_t *CreateEmptySequeue(int max_len)
{
    sequeue_t *q;

    if (max_len <= 1)
        return NULL;                  /* 容量 1 存不下任何元素 */

    q = (sequeue_t *)malloc(sizeof(sequeue_t));
    if (q == NULL)
        return NULL;

    q->data = (data_t *)malloc(sizeof(data_t) * max_len);
    if (q->data == NULL) {
        free(q);
        return NULL;
    }

    q->maxlen = max_len;
    q->front = q->rear = 0;           /* 初始化时两者相等，表示空 */
    return q;
}

void DestroySequeue(sequeue_t *q)
{
    if (q == NULL)
        return;
    free(q->data);
    free(q);
}

void ClearSequeue(sequeue_t *q)
{
    if (q == NULL)
        return;
    q->front = q->rear = 0;
}

int EmptySequeue(sequeue_t *q)
{
    if (q == NULL)
        return ERROR;
    return (q->front == q->rear) ? 1 : 0;
}

int FullSequeue(sequeue_t *q)
{
    if (q == NULL)
        return ERROR;
    return ((q->rear + 1) % q->maxlen == q->front) ? 1 : 0;
}

int SequeueLength(sequeue_t *q)
{
    if (q == NULL)
        return ERROR;
    return (q->rear - q->front + q->maxlen) % q->maxlen;
}

int EnQueue(sequeue_t *q, data_t x)
{
    if (q == NULL)
        return ERROR;
    if (FullSequeue(q) == 1)
        return ERROR;                 /* 满，含那个被牺牲的空格 */

    q->data[q->rear] = x;             /* 先写再移，注意顺序 */
    q->rear = (q->rear + 1) % q->maxlen;
    return OK;
}

int DeQueue(sequeue_t *q, data_t *x)
{
    if (q == NULL)
        return ERROR;
    if (EmptySequeue(q) == 1)
        return ERROR;

    if (x != NULL)
        *x = q->data[q->front];       /* 先读再移 */
    q->front = (q->front + 1) % q->maxlen;
    return OK;
}

拿容量 5 的队列跑一遍：连入队 5 个，再出队两个、入队两个，最后全部弹出。关键输出：

text
enqueue 5 rejected, queue full      容量 5 只能存 4 个
after wrap: front=2 rear=1 len=4    rear 从 4 绕回 1
dequeue 3, len=3
dequeue 4, len=2
dequeue 88, len=1
dequeue 99, len=0
empty=1 full=0 len=0

第二行是重点：rear 从 4 绕回到 1，front 是 2，长度算出来 (1 - 2 + 5) % 5 = 4，四个元素正好占满，环合上了。len=4 而不是 5，因为有一格是判满的牺牲位。

这里有两处顺序不能错：

  • 入队必须先写数据再移 rear。反了的话，rear 先指到下一格，数据写进去的位置就偏了一格。
  • 出队必须先取数据再移 front。反了的话，取出来的是下一个元素，队头那个永远读不到。

有一版常见写法把入队写成先 rear = (rear+1)%N 再写 data[rear]，那就是把 rear 定义成「队尾元素下标」而不是「队尾后一格」。两种约定都成立，但必须整篇统一：判满用 (rear+1)%N == front 意味着 rear 指向空位；判满用 rear == front 的其他变体则不然。混用必炸。

十一、队列的链式存储 #

链式队列从单链表改出来。最直接的想法是把链表头当队头、链表尾当队尾：出队在头部，O(1)；入队要走到尾部，O(n)。反过来把链表头当队尾，入队 O(1)，出队 O(n)。两头总有一头慢。

原因是单链表只有向后的指针，找尾必须遍历。改法很省事：把链表的「头结点」改成存两个指针，一个指向队头，一个指向队尾。

c
typedef int data_t;

typedef struct node_t {
    data_t data;
    struct node_t *next;
} linknode_t;

typedef struct {
    linknode_t *front;   /* 指向头结点（不存数据） */
    linknode_t *rear;    /* 指向队尾结点 */
} linkqueue_t;

这样入队动 rear，出队动 front，两边都是 O(1)。

c
linkqueue_t *CreateEmptyLinkqueue(void)
{
    linkqueue_t *q;

    q = (linkqueue_t *)malloc(sizeof(linkqueue_t));
    if (q == NULL)
        return NULL;

    q->front = (linknode_t *)malloc(sizeof(linknode_t));  /* 头结点 */
    if (q->front == NULL) {
        free(q);
        return NULL;
    }
    q->front->next = NULL;
    q->front->data = 0;
    q->rear = q->front;              /* 队空时 rear 和 front 同指头结点 */
    return q;
}

int EmptyLinkqueue(linkqueue_t *q)
{
    if (q == NULL)
        return ERROR;
    return (q->front->next == NULL) ? 1 : 0;
}

int EnQueueLink(linkqueue_t *q, data_t x)
{
    linknode_t *node;

    if (q == NULL)
        return ERROR;

    node = (linknode_t *)malloc(sizeof(linknode_t));
    if (node == NULL)
        return ERROR;

    node->data = x;
    node->next = NULL;

    q->rear->next = node;            /* 挂到队尾之后 */
    q->rear = node;                  /* 队尾指针跟上 */
    return OK;
}

int DeQueueLink(linkqueue_t *q, data_t *x)
{
    linknode_t *node;

    if (q == NULL)
        return ERROR;
    if (q->front->next == NULL)
        return ERROR;                /* 空队 */

    node = q->front->next;           /* 真正的队头结点 */
    q->front->next = node->next;

    if (q->rear == node)             /* 出的是最后一个元素 */
        q->rear = q->front;          /* rear 必须退回，否则悬空 */

    if (x != NULL)
        *x = node->data;
    free(node);
    return OK;
}

void DestroyLinkqueue(linkqueue_t *q)
{
    linknode_t *node;

    if (q == NULL)
        return;

    while (q->front != NULL) {
        node = q->front;
        q->front = node->next;
        free(node);
    }
    free(q);                         /* 头结点在循环里已释放，这里只放结构体 */
}

DeQueueLink 里那个 if (q->rear == node) 是链式队列最经典的 bug。删掉它，队列最后一个元素出队后 rear 还指着已释放的结点，下一次入队就往野指针上写。常见的两版写法里，一版漏了这行、一版把 rear 置成 NULL 而不是 q->front，后者会让下一次入队解引用空指针。正确做法是让 rear 回到头结点，保持「队空时 rear == front」这个不变量。

链式队列几乎不会「满」，只受内存限制。它不需要判满函数，不做那个操作。

维度 顺序循环队列 链式队列
容量 固定 N-1 只受内存限制
入队 O(1) O(1)，一次 malloc
出队 O(1) O(1)，一次 free
额外空间 一格牺牲位 每个结点一个指针加一个头结点
缓存表现 连续内存，好 分散，差
适用 定长缓冲、高频短操作 数量不可预估、允许频繁分配

选择标准和栈一样：数量能估准就用顺序的，估不准就上链式的。区别在于队列常常出现在高频路径上（日志缓冲、消息队列），每一次 malloc 都是真实的延迟，能预分配就别动态分配。

十二、双端队列 #

双端队列（deque，double-ended queue）两端都能进、两端都能出。栈和队列都是它的受限版本。

变体 插入端 删除端 等价于
双端队列 两端 两端 栈与队列的并集
输入受限 只一端 两端 半受限
输出受限 两端 只一端 半受限
栈 只一端 同一端 退化
队列 只一端 另一端 退化

循环数组实现双端队列，关键是两个方向的取模写法不同：

c
q->rear = (q->rear + 1) % N;          /* 尾部加：rear 后移 */
x = q->data[q->rear];
q->front = (q->front - 1 + N) % N;    /* 头部加：front 前移，少了 +N 就出负数下标 */
q->data[q->front] = x;
q->front = (q->front + 1) % N;        /* 头部删：front 后移 */

(front - 1 + N) % N 那处是 deque 的头号 bug。C 语言里 -1 % 5 等于 -1，不是 4，直接用就是越界读。

双端队列还有个考试用途：判断输出序列的合法性。输入序列固定为 1 2 3 4，问哪个输出序列凑不出来。

判法：按输入顺序逐个进队，进队后可以随时从两端出，看能否凑出目标序列。规矩只有一条——任何时刻，已经出队的元素之间不允许出现「后来的元素先出、中间的元素被夹住」的乱序。用栈时合法的出栈序列数目是卡特兰数 C(2n, n)/(n+1)，n=4 时有 14 种；队列只有 1 种，双端队列多于 14 种。

十三、队列的应用：任务调度与缓冲 #

队列在系统里出现的频率比栈高。凡是「先来的先处理」的地方，底下都是一个队列。

场景 队列里装什么 为什么必须是队列
打印任务 待打印文档 先提交先打印，不能插队
进程调度 就绪进程 PCB 时间片轮转，公平性
消息中间件 待消费消息 削峰，生产者快于消费者时缓冲
IO 缓冲 字节流 数据到达顺序必须保持
广度优先搜索 待访问结点 按层推进，见《图》一篇

环形缓冲区是循环队列最直接的工程形态：固定大小、两个指针、无锁单生产单消费。日志系统、串口收发、音视频采集都用它。

球钟问题是队列和栈的组合题，值得单独走一遍。规则：三个指示器分别存 1 分钟、5 分钟、1 小时，容量依次为 4、11、11（第 5、12、12 个球到来时触发进位）。每分钟从球队列队头取一个球压进分钟指示器；分钟满了，把 4 个球按相反顺序弹回队尾，第 5 个进五分钟指示器；五分钟满了同理；小时满了，11 个球倒回队尾，第 12 个也回队尾，回到初始状态。

核心循环只有几行：

c
while (1) {
    DeQueue(ballque, &data);
    PushStack(one_min, data);                 /* 进 1 分钟栈 */

    if (FullStack(one_min) == OK) {
        for (i = 0; i < one_min->maxlen - 1; i++)
            EnQueue(ballque, PopStack(one_min));  /* 4 个球倒回队尾 */
        PushStack(five_min, PopStack(one_min));   /* 第 5 个进 5 分钟栈 */
    }
    if (FullStack(five_min) == OK) {
        for (i = 0; i < five_min->maxlen - 1; i++)
            EnQueue(ballque, PopStack(five_min));
        PushStack(one_hour, PopStack(five_min));
    }
    if (FullStack(one_hour) == OK) {
        for (i = 0; i < one_hour->maxlen; i++)
            EnQueue(ballque, PopStack(one_hour));
    }
}

「倒回队尾」这个动作必须靠栈完成。栈弹出是逆向的，倒进队列后顺序恰好反过来，球钟才能从 11:59 回到 0:00。

问题的答案是 27 个球。算一下：任意时刻最多 26 个球压在三个栈里（4 + 11 + 11），队列里至少留 1 个供下一分钟取，合计 27。代码里队列数组开 28——因为循环队列牺牲一格，28 格的数组正好存 27 个球。这个数字对上了，说明判满条件没写错。

十四、栈与队列的对比 #

维度 栈 队列
插入位置 栈顶 队尾
删除位置 栈顶（同一端） 队头（另一端）
访问特征 后进先出 LIFO 先进先出 FIFO
唯一可读元素 栈顶 队头
顺序存储要点 top 单向递增 front/rear 双指针取模
核心坑 空栈出栈、栈满覆盖 假溢出、front==rear 歧义
典型应用 括号匹配、表达式求值、函数调用、撤销 任务调度、缓冲、BFS、消息队列
基本操作复杂度 全 O(1) 全 O(1)

两种结构能互相模拟，这也是面试常考点。

用两个栈实现队列：stack1 只负责入队，stack2 只负责出队。出队时若 stack2 空，把 stack1 全部倒过去，顺序反转后 stack2 的栈顶就是队头。

c
void appendTail(stack_t *s1, data_t x) { PushStack(s1, x); }

int deleteHead(stack_t *s1, stack_t *s2, data_t *x)
{
    data_t v;
    if (EmptyStack(s2) == 1)               /* s2 空才倒，非空直接取 */
        while (EmptyStack(s1) != 1) {
            PopStack(s1, &v);
            PushStack(s2, v);              /* 倒完队头浮到 s2 栈顶 */
        }
    if (EmptyStack(s2) == 1)
        return ERROR;                      /* 两个都空，队列才空 */
    return PopStack(s2, x);
}

s2 非空时不能倒，这是唯一的坑。倒了顺序就乱了。单次出队最坏 O(n)，但每个元素最多被搬两次，均摊下来还是 O(1)。

反过来的「两个队列实现栈」：入栈压进非空队列，出栈把该队列前 n-1 个元素搬到另一个队列，剩下那个就是栈顶。这个方案每次出栈都要搬 n-1 个元素，代价 O(n)，只适合面试演示，工程里不用。

从实现难度看，顺序栈最简单，循环队列的判空判满最绕，链式结构最考验指针。四条路走完，线性表这条线就走完整了。

十五、易错点速查 #

症状 原因 修法
空栈 Pop 后程序崩溃 没判空就 data[top--] 出栈前必判 top == -1
栈满 Push 覆盖旧数据 判满条件写成 > 或漏判 top == maxlen - 1 就拒绝
顺序栈扩容后数据错乱 只 realloc 数组没更新 maxlen 扩容后同步改容量字段
top 两种约定混用 一处 top=-1 空，另一处 top=0 空 全篇统一，写进注释

循环队列判满总差一格 忘了牺牲那一格 元素上限是 N-1，不是 N

这张表建议对着代码逐条过一遍。栈和队列的代码都不长，出错基本都在边界：空、满、最后一个、下标绕回。把这四类情形各写一个测试用例，八成 bug 能当场现形。

栈和队列到这里就讲完了。回到开头那句话：它们不是新结构，是给线性表加了两条位置限制。栈把进出锁在同一端，队列把进和出分到两端。限制带来确定性，确定性带来可预测的行为，剩下的应用都是这条逻辑的自然结果。
