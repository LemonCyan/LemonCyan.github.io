一、面试题考的是什么 #

面试官出题不是为了要一个数字。他要看你在信息不全、时间有限的情况下，怎么把问题拆开、怎么定位边界、怎么在几个方案之间做决定。

同一道题的不同解法，代价能差一个数量级。面试场合里，你能不能说出「我为什么选这个」，比你能不能秒答答案重要得多。

按题型分三类，看的东西不一样：

题型 面试官真正在看的 我们要给出的答案形状
手写代码题 边界意识、代码能不能一次编译过 结构定义 + 主逻辑 + 边界分支，一次说全
智力题 会不会被直觉骗、能不能把模糊描述变成方程 先复述约束，再给模型，最后报数字
设计题 取舍能力 给两个方案做对比，说清选哪个和为什么

再看同一批题目的解法落差，落差本身就是考点：

题目 直觉解法 更好的解法 差在哪
从尾到头打印链表 反转链表再打印 递归或显式栈 反转改了结构，用完得还原；栈则要 O(n) 额外空间
O(1) 时间删除结点 从头找前驱，O(n) 复制后继内容，O(1) 拿「结点身份」换时间，尾结点上直接失效
两数之和 双重循环 O(n²) 哈希表 O(n) 用 O(n) 空间砍掉一个数量级
合并两个有序链表 递归 迭代加哑结点 递归多吃 O(n) 栈空间，链表一长就爆栈
鸡蛋掉落 二分查找 等差递增试探 二分的隐含前提是鸡蛋无限，题目只给两个

这五行的东西，比答案本身值钱。背答案的人给不出最后一列。

给一条实操原则：先报暴力解和它的复杂度，再说哪一步是瓶颈，然后换数据结构或换遍历顺序，最后用一句话收尾「我选这个，因为它在什么规模下更稳」。这套话术在任何一道题上都成立。

二、链表类：从尾到头打印链表 #

题目：输入一个链表的头结点，从尾到头打印每个结点的值。要求不改变链表结构。

结点定义，后面几节都复用它：

c
typedef struct ListNode {
    int nKey;
    struct ListNode *pNext;
} ListNode;

要倒着输出，本质是要一个后进先出的容器。思路有三条，代价各不同。

第一条，显式用栈。先把所有结点指针压栈，再逐个弹出来打印。时间 O(n)，空间 O(n)。C 里没有现成的栈容器，用一个可增长的指针数组就够，别为这点事引入链表实现的栈，缓存不友好。

第二条，用递归。递归的调用栈本身就是那个栈，写法短到三行：

c
void PrintListRecursively(ListNode *pHead)
{
    if (pHead == NULL) {
        return;
    }
    PrintListRecursively(pHead->pNext);
    printf("%d ", pHead->nKey);
}

第三条，先反转链表，顺序打印，再反转回来。时间 O(n)，空间 O(1)，代价是中途链表结构变了。题目明确说不许改结构，所以这条只能在「允许改」的版本里用。

栈版本，一个文件里就能跑：

c
#include <stdio.h>
#include <stdlib.h>

void PrintListByStack(ListNode *pHead)
{
    int cap = 16;
    int top = 0;
    ListNode **stack = (ListNode **)malloc(cap * sizeof(ListNode *));
    if (stack == NULL) {
        return;
    }
    ListNode *pCur = pHead;
    while (pCur != NULL) {
        if (top == cap) {                 /* 栈满，容量翻倍 */
            cap *= 2;
            ListNode **tmp =
                (ListNode **)realloc(stack, cap * sizeof(ListNode *));
            if (tmp == NULL) {
                free(stack);
                return;
            }
            stack = tmp;
        }
        stack[top++] = pCur;
        pCur = pCur->pNext;
    }
    while (top > 0) {
        printf("%d ", stack[--top]->nKey);
    }
    printf("\n");
    free(stack);
}

反转链表单独抽出来，再加个入口把三段串起来：

c
ListNode *ReverseList(ListNode *pHead)
{
    ListNode *pPrev = NULL;
    ListNode *pCur = pHead;
    while (pCur != NULL) {
        ListNode *pNext = pCur->pNext;
        pCur->pNext = pPrev;
        pPrev = pCur;
        pCur = pNext;
    }
    return pPrev;                          /* 新的头结点 */
}

int main(void)
{
    /* 手工串一条 1 -> 2 -> 3 -> 4 -> 5，省掉输入逻辑 */
    ListNode node[5];
    for (int i = 0; i < 5; i++) {
        node[i].nKey = i + 1;
        node[i].pNext = (i == 4) ? NULL : &node[i + 1];
    }
    ListNode *pHead = node;
    printf("逆序输出（栈）：");
    PrintListByStack(pHead);
    printf("逆序输出（递归）：");
    PrintListRecursively(pHead);
    return 0;
}

四条路摆在一起看：

方法 时间 额外空间 改结构 风险点
显式栈 O(n) O(n) 否 要自己管扩容和释放
递归 O(n) O(n) 调用栈 否 深度等于结点数，长链表直接爆栈
反转再反转 O(n) O(1) 是 中途异常退出就留下被改坏的链表
先递归进数组再倒序 O(n) O(n) 否 多一次拷贝，没好处

递归那格的风险要当真。链表长度一万还能撑，十万就会段错误，而链表长度不可控是常态。白板上写完递归版，顺手补一句「生产代码我会换成显式栈，避免深度依赖输入」，这一句比代码本身加分。

三、链表类：O(1) 时间删除结点 #

题目：给定单向链表的头指针和一个结点指针，在 O(1) 时间内删除该结点。

c
void DeleteNode(ListNode **ppListHead, ListNode *pToBeDeleted);

前提：待删结点确定在链表里。

单链表只能往后走，拿不到前驱，想按常规思路「改前驱的 next」就得从头遍历，那是 O(n)。要做 O(1)，唯一的路是换一个思路：不去动前驱，而是让待删结点「变成」它的后继。

具体做法是把后继的 nKey 拷到当前结点，把当前的 next 指向后继的 next，然后释放后继。从外面看，值为 x 的那个结点消失了，链表的形状没变。被释放的是后继，不是待删结点本身。

分三种情况，缺一不可：

情况 做法 时间 备注
待删结点不是尾结点 复制后继内容，删后继 O(1) 主力路径
链表只有一个结点 释放后把头指针置空 O(1) 既是头也是尾，前一条不适用
待删结点是尾结点 从头遍历找前驱，前驱 next 置空 O(n) 复制法在这里失效

完整实现：

c
void DeleteNode(ListNode **ppListHead, ListNode *pToBeDeleted)
{
    if (ppListHead == NULL || pToBeDeleted == NULL || *ppListHead == NULL) {
        return;
    }
    if (pToBeDeleted->pNext != NULL) {        /* 情况一：不是尾结点 */
        ListNode *pNext = pToBeDeleted->pNext;
        pToBeDeleted->nKey = pNext->nKey;     /* 后继内容搬过来 */
        pToBeDeleted->pNext = pNext->pNext;   /* 从链上摘掉后继 */
        free(pNext);
        pNext = NULL;
    } else if (*ppListHead == pToBeDeleted) { /* 情况二：全链只剩一个 */
        free(pToBeDeleted);
        *ppListHead = NULL;
    } else {                                  /* 情况三：尾结点 */
        ListNode *pNode = *ppListHead;
        while (pNode->pNext != pToBeDeleted) {
            pNode = pNode->pNext;
        }
        pNode->pNext = NULL;
        free(pToBeDeleted);
    }
}

平均复杂度是 [(n-1)·O(1) + O(n)] / n = O(1)，因为尾结点只有一种，非尾结点有 n-1 种。这个算式面试时要写出来，它说明「平均 O(1)」不是嘴上说说。

边界条件必须点明：复制法删不掉尾结点。尾结点没有后继，没有内容可复制，也没有结点可以顶替它的位置。这时候只能退回遍历。所以这个方法严格讲是「除尾结点外 O(1)」，不是全场景 O(1)。

如果面试官追问「那我要真 O(1) 删尾结点呢」，正确答案是做不到。单链表没有前驱指针，尾结点的前驱只能靠遍历找。想做到 O(1)，要么换成双向链表，要么在结点结构里存前驱，要么用「带尾指针前驱」的变体结构。别硬编一个不存在的解法。

还有三个坑，都跟内存和指针语义有关。

第一，调用方手里的 pToBeDeleted 已经悬空。函数里走情况一时，我们释放的是后继，pToBeDeleted 指向的内存还没被释放，但它现在装的是后继的值。调用方如果还拿这个指针去读，读到的是别人的数据；如果拿它去 free，就是二次释放。接口文档要写清「调用返回后该指针不可再用」。

第二，情况二的判断顺序不能反。如果先判断 pNext 是否为 NULL 再判断是不是头，那么单结点的链表会掉进尾结点分支，从头遍历时 pNode->pNext != pToBeDeleted 永远不成立，直接死循环或者空指针解引用。

第三，free 之后要置空局部指针，但置空局部指针解决不了调用方的悬空问题。别把这两件事混为一谈。

顺手把一个相关的老题收掉：删除头结点。它跟上面是同一类麻烦，头指针的地址不能变，变了调用方就找不到链表。老练的写法是先把第一个元素的内容按值整体搬进头结点（*pHead = *p），再释放那个元素结点。注意这里释放的是第一个元素，不是头结点本身。代价是头结点从哑结点变成了真实数据结点，语义变了。工程里更干净的写法是传二级指针，直接改头指针。

删除指定位置和按值删除，容易翻车的是后者。朴素写法长这样：

c
/* 错误示范：free 之后还在用 p */
for (p = head->next; p; q = p, p = p->next) {
    if (p->nKey == value) {
        q->pNext = p->pNext;
        free(p);
        p = NULL;        /* 置空了，但下一轮 p = p->next 又去解引用 */
    }
}

第三段 p = p->next 会在 p 已被置空之后执行。正确写法是删完立刻把 p 挪到下一个待查结点，不要回到循环头的自增：

c
void DeleteAllByValue(ListNode **ppHead, int value)
{
    ListNode *pPrev = NULL;
    ListNode *pCur = *ppHead;
    while (pCur != NULL) {
        if (pCur->nKey == value) {
            ListNode *pNext = pCur->pNext;
            if (pPrev == NULL) {
                *ppHead = pNext;          /* 删的是头结点 */
            } else {
                pPrev->pNext = pNext;
            }
            free(pCur);
            pCur = pNext;                 /* 关键：不回到自增 */
        } else {
            pPrev = pCur;
            pCur = pCur->pNext;
        }
    }
}

连续两个相同值也不会漏删，因为删完之后 pCur 指向的仍是待检查的结点，循环继续判断它。

顺带把链表剩下的几道常规题补齐。它们的思路没有难度，翻车全在指针顺序上。插入分两种：往递增链表里插，先找到第一个比 value 大的结点，插在它前面，写判断条件时别漏掉「插在表尾」这一路，否则 p->next->data 直接空指针解引用；往指定位置插，走 pos−1 步到前驱，然后两行搞定，new->pNext = p->pNext 和 p->pNext = new，顺序不能反，反了后半条链就丢了。逆置也是同一类问题，用头插法边遍历边改 next，改之前先把 next 存下来。

双向链表的三道常规题（测长、删除结点、往递增链表里插）比单链表多一步：改 next 的同时要改 prev，删除时前后两个邻居的指针都得照顾到，少改一个就断链。测长沿着 next 走就行，别用 prev 反着绕，容易绕回哑结点。

四、链表类：合并两个有序链表 #

题目：输入两个递增排序的链表，合并成一个链表，新链表仍然递增。

递归版最好写。每一次比较两个头结点的值，小的那个当合并后的头，它的 next 指向「剩下部分合并的结果」：

c
ListNode *MergeSortedList(ListNode *pHead1, ListNode *pHead2)
{
    if (pHead1 == NULL) {
        return pHead2;
    }
    if (pHead2 == NULL) {
        return pHead1;
    }
    ListNode *pMergeHead = NULL;
    if (pHead1->nKey < pHead2->nKey) {
        pMergeHead = pHead1;
        /* 剩下的部分接着递归合并 */
        pMergeHead->pNext = MergeSortedList(pHead1->pNext, pHead2);
    } else {
        pMergeHead = pHead2;
        pMergeHead->pNext = MergeSortedList(pHead1, pHead2->pNext);
    }
    return pMergeHead;
}

递归的代价藏在栈里：递归深度等于两个链表长度之和，十万个结点就有一万层以上的调用，栈会先崩。工程代码用迭代加哑结点：

c
ListNode *MergeSortedListIter(ListNode *pHead1, ListNode *pHead2)
{
    ListNode dummy;                    /* 栈上的哑结点，不放真实数据 */
    ListNode *pTail = &dummy;
    dummy.pNext = NULL;
    while (pHead1 != NULL && pHead2 != NULL) {
        if (pHead1->nKey <= pHead2->nKey) {
            pTail->pNext = pHead1;
            pHead1 = pHead1->pNext;
        } else {
            pTail->pNext = pHead2;
            pHead2 = pHead2->pNext;
        }
        pTail = pTail->pNext;
    }
    pTail->pNext = (pHead1 != NULL) ? pHead1 : pHead2;
    return dummy.pNext;
}

哑结点这一招值得记住。它把「第一个结点要单独处理」这个特例消掉了，循环体里只剩一种情形。凡是「结果链表边建边追加」的题，都可以先摆一个哑结点，最后返回 dummy->next。

注意用 <= 而不是 <。两个链表有相同值时，<= 能保证合并结果稳定，前一个链表的元素排在前面。

链表三题的解法摊在一起看：

题目 核心思路 时间 额外空间 边界风险
从尾到头打印 借栈的后进先出，或借递归的调用栈 O(n) O(n) 递归深度等于结点数，长链表爆栈
O(1) 删除指定结点 复制后继内容，删后继 O(1) 平均 O(1) 尾结点失效，只能退化成 O(n)
合并两个有序链表 每次摘小的那个，递归或迭代 O(n+m) O(1) 迭代 / O(n+m) 递归 空链表、相同值、剩余段收尾

共同点是它们都在「指针操作」上做文章，共同的风险也都是边界：空链表、单结点、尾结点、头结点。

五、链表类：快慢指针找中点与判环 #

单链表没有下标，想定位就得靠两个指针跑出速度差。这一招能解一串题。

找中点。快指针每次走两步，慢指针每次走一步，快指针到头时慢指针在中间：

c
ListNode *FindMid(ListNode *pHead)
{
    ListNode *pSlow = pHead;
    ListNode *pFast = pHead;
    while (pFast != NULL && pFast->pNext != NULL) {
        pSlow = pSlow->pNext;
        pFast = pFast->pNext->pNext;
    }
    return pSlow;
}

结点数为偶数时，中点有两个，这段代码返回后半段的第一个。想返回前半段的最后一个，把初值改成 pSlow = pHead、pFast = pHead->pNext，或者把循环条件改成 pFast->pNext != NULL && pFast->pNext->pNext != NULL。面试时先说清「你要哪一个中点」，比默写代码重要。

循环条件里的两个判断都不能省。pFast != NULL 挡住空链表，pFast->pNext != NULL 挡住快指针最后一步踩空。

倒数第 m 个结点。让一个指针先走 m 步，两个指针再一起走，前面的到头时，后面的正好落在倒数第 m 个：

c
ListNode *FindLastM(ListNode *pHead, int m)
{
    if (pHead == NULL || m <= 0) {
        return NULL;
    }
    ListNode *pAhead = pHead;
    ListNode *pBehind = pHead;
    for (int i = 0; i < m; i++) {
        if (pAhead == NULL) {
            return NULL;               /* 链表长度不足 m */
        }
        pAhead = pAhead->pNext;
    }
    while (pAhead != NULL) {
        pAhead = pAhead->pNext;
        pBehind = pBehind->pNext;
    }
    return pBehind;
}

这样只遍历一遍，不用先测长度。素材里那个「先测长再走 n-m 步」的做法要遍历两遍，面试官问「能不能只走一遍」时就是考这个偏移技巧。

判环。还是快慢指针。没环时快指针先到 NULL；有环时快指针会在环里绕圈，最终从后面追上慢指针：

c
ListNode *DetectCycle(ListNode *pHead)
{
    ListNode *pSlow = pHead;
    ListNode *pFast = pHead;
    while (pFast != NULL && pFast->pNext != NULL) {
        pSlow = pSlow->pNext;
        pFast = pFast->pNext->pNext;
        if (pSlow == pFast) {           /* 相遇，确认有环 */
            ListNode *pMeet = pSlow;
            ListNode *pFromHead = pHead;
            while (pFromHead != pMeet) {
                pFromHead = pFromHead->pNext;
                pMeet = pMeet->pNext;
            }
            return pFromHead;           /* 环的入口 */
        }
    }
    return NULL;
}

找入口的那段推导值得背下来，因为面试官爱问「为什么」。设头到入口的距离为 a，入口到相遇点为 b，相遇点绕回入口为 c，环长 b+c。相遇时慢指针走了 a+b，快指针走了 a+b+(b+c)。快指针速度是两倍：

text
2(a + b) = a + b + b + c
        a = c

所以从头结点和从相遇点同时出发、同速前进，一定在入口相遇。

判环和「证明链表是循环链表」是同一件事。素材给的「两个指针以不同步长前进，若能再次指向同一结点则是循环链表」就是这套方法的口语版，严格讲要补一句：快指针必须真的能在环里追上一圈之内追上慢指针。环长为 L 时，两者距离每轮缩短 1，最多 L 轮必相遇，所以循环一定终止。

约瑟夫环。素材里的做法是用循环链表真去模拟：建环、找起点、每数到 m 个人就删一个、直到只剩一个。复杂度 O(nm)，n 大 m 大时很慢。数学版是 O(n)，一行递推就够：

text
f(1) = 0
f(i) = (f(i-1) + m) % i        结果换算成 1 起始编号时加 1

含义是：删掉一个人之后，剩下的人重新编号，问题缩成规模 i-1 的同一个问题，把编号映射回去只多一个位移。想听懂这段，拿 n=5、m=3 手推一遍，比看十遍公式强。

素材里还有一道「输出相邻两结点之和最大的前一个结点」，一个循环维护当前最大值即可，O(n)。这类题没有技巧，考的是你会不会写不带 bug 的单层循环。

六、数组类：两数之和与三数之和 #

两数之和：给一个数组和目标值，找出两个数使它们的和等于目标。三条路。

暴力双重循环 O(n²)，面试里只用来开场。排序加双指针 O(n log n)，但排序打乱了原下标，题目要求返回下标时不能直接用。哈希表 O(n)：扫一遍，对每个 x 查 target - x 在不在表里，不在就把 x 记进去。

选哪个取决于返回值要什么：

返回值要求 首选方案 时间 空间
只需回答存在与否 排序 + 双指针 O(n log n) O(1)
要返回原始下标 哈希表 O(n) O(n)
数组已排好序 双指针 O(n) O(1)

这就是「同一道题不同解法取舍」的典型：哈希更快，代价是空间；排序省空间，代价是丢掉下标。

三数之和：a + b + c = target。先排序，固定第一个数，剩下两个数用双指针从两端夹。整体 O(n²)，比三重循环的 O(n³) 好一个数量级：

c
#include <stdlib.h>

static int CmpInt(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

int ThreeSumCount(int *a, int n, int target)
{
    int count = 0;
    if (a == NULL || n < 3) {
        return 0;
    }
    qsort(a, n, sizeof(int), CmpInt);
    for (int i = 0; i + 2 < n; i++) {
        if (i > 0 && a[i] == a[i - 1]) {
            continue;                          /* 第一个数去重 */
        }
        int left = i + 1;
        int right = n - 1;
        while (left < right) {
            int sum = a[i] + a[left] + a[right];
            if (sum == target) {
                count++;
                while (left < right && a[left] == a[left + 1]) {
                    left++;                    /* 第二个数去重 */
                }
                while (left < right && a[right] == a[right - 1]) {
                    right--;                   /* 第三个数去重 */
                }
                left++;
                right--;
            } else if (sum < target) {
                left++;
            } else {
                right--;
            }
        }
    }
    return count;
}

三处去重是这道题唯一的难点，也是唯一会被扣分的地方。第一个数的去重在 for 循环里，后两个数的去重在命中之后。三处都漏一处，结果里就有重复三元组。

双指针能夹的前提是数组有序。有序才能保证「和太小就左指针右移，和太大就右指针左移」这个判断不会漏解。这个前提必须说出来，漏掉它就是背题。

七、字符串类：回文与字符统计 #

回文判断。首尾两个指针往中间夹，遇到不同就否掉：

c
#include <string.h>

int IsPalindrome(const char *s)
{
    if (s == NULL) {
        return 0;
    }
    int left = 0;
    int right = (int)strlen(s) - 1;
    while (left < right) {
        if (s[left] != s[right]) {
            return 0;
        }
        left++;
        right--;
    }
    return 1;
}

时间 O(n)，空间 O(1)。素材里常见的另一种写法是复制一份反转后比较，那是 O(n) 空间换代码更短，没必要。strlen 只调一次，别把它写进循环条件里，那样时间会退化成 O(n²)。

字符统计。字符集只有 256 个字节值时，数组就是最便宜的哈希表：

c
#include <string.h>

int FirstUniqueChar(const char *s)
{
    int cnt[256];
    if (s == NULL) {
        return -1;
    }
    memset(cnt, 0, sizeof(cnt));
    for (const unsigned char *p = (const unsigned char *)s; *p != '\0'; p++) {
        cnt[*p]++;
    }
    for (int i = 0; s[i] != '\0'; i++) {
        if (cnt[(unsigned char)s[i]] == 1) {
            return i;
        }
    }
    return -1;
}

两个细节。一是下标必须强制转成 unsigned char，char 在多数平台上是有符号的，遇到高位为 1 的字节会变成负数下标，直接越界。二是中文字符串按字节统计出来的不是字数，UTF-8 下一个汉字占三字节，要按字符统计得先做解码。

同一套桶还能顺手解决变位词判断：两个字符串各统计一遍，比较两个 256 长度的数组。时间 O(n)，比排序后比较的 O(n log n) 更快。

八、栈与队列类：两个栈实现队列 #

题目：用两个栈实现一个队列，支持入队和出队。

思路是分工。栈 A 只管入队，新元素直接压进去；栈 B 只管出队。出队时如果 B 空，就把 A 的全部元素倒进 B，再从 B 弹出。倒一次序，最上面的正好是最早进来的那个。

c
#define STACK_CAP 128

typedef struct {
    int in[STACK_CAP];
    int inTop;
    int out[STACK_CAP];
    int outTop;
} MyQueue;                              /* 初始化时把两个栈顶都置 0 */

int QueuePush(MyQueue *q, int v)
{
    if (q->inTop == STACK_CAP) {
        return 0;                      /* 简化处理：容量固定 */
    }
    q->in[q->inTop++] = v;
    return 1;
}

int QueuePop(MyQueue *q, int *pv)
{
    if (q->outTop == 0) {
        while (q->inTop > 0) {
            q->out[q->outTop++] = q->in[--q->inTop];
        }
    }
    if (q->outTop == 0) {
        return 0;                      /* 两个栈都空，队空 */
    }
    *pv = q->out[--q->outTop];
    return 1;
}

重点在复杂度。单次出队最坏是 O(n)，要倒整个 A。但每个元素一辈子只会被倒一次，n 次操作总共搬 n 次，摊还下来每次 O(1)。这个「摊还」二字要主动说出来，它才是这道题的考点，代码本身没什么难度。

反方向的题也常问：两个队列实现栈。入栈压到队列 A；出栈时把 A 的前 n-1 个元素挪到 B，剩下的那个就是栈顶，弹掉后再把 B 挪回来。这样出栈是 O(n)，而且省不掉，队列只能先进先出，没有栈的反序能力可以借。两组题放在一起看，能看出「用谁模拟谁」决定了复杂度上限。

九、二叉树类：深度、镜像与路径 #

树的题九成靠递归，剩下的一成靠显式栈。结点定义：

c
typedef struct TreeNode {
    int nValue;
    struct TreeNode *pLeft;
    struct TreeNode *pRight;
} TreeNode;

深度和镜像，两个最基础的递归。深度取左右子树较大的那个加一；镜像先换左右孩子，再递归处理两棵子树：

c
int TreeDepth(TreeNode *pRoot)
{
    if (pRoot == NULL) {
        return 0;
    }
    int left = TreeDepth(pRoot->pLeft);
    int right = TreeDepth(pRoot->pRight);
    return (left > right ? left : right) + 1;
}

void MirrorTree(TreeNode *pRoot)
{
    if (pRoot == NULL) {
        return;
    }
    TreeNode *tmp = pRoot->pLeft;
    pRoot->pLeft = pRoot->pRight;
    pRoot->pRight = tmp;
    MirrorTree(pRoot->pLeft);
    MirrorTree(pRoot->pRight);
}

镜像这道题的常见错误是只换了根的两个孩子就返回，忘了往下递归。判断两个树是否互为镜像，是同一种递归的变体：比较左边和右边，然后递归比较 a 的左与 b 的右、a 的右与 b 的左。

根到叶的路径，靠递归时带一个数组当路径栈：进入结点时压入，叶子结点时整个数组打印一遍，返回时长度自然回退。用全局变量存路径再手动弹出是同一个意思，只是要记得弹出。

最低公共祖先分两种树，解法完全不同。二叉搜索树靠值的大小决定往左还是往右，一次下行就够，O(h)：

c
TreeNode *LcaBst(TreeNode *pRoot, int a, int b)
{
    while (pRoot != NULL) {
        if (a < pRoot->nValue && b < pRoot->nValue) {
            pRoot = pRoot->pLeft;
        } else if (a > pRoot->nValue && b > pRoot->nValue) {
            pRoot = pRoot->pRight;
        } else {
            return pRoot;              /* 一个在左一个在右，当前就是答案 */
        }
    }
    return NULL;
}

普通二叉树没有大小关系可用，只能后序遍历：两个目标结点分别落在当前结点的两侧时，当前结点就是答案：

c
TreeNode *LcaBinaryTree(TreeNode *pRoot, TreeNode *pA, TreeNode *pB)
{
    if (pRoot == NULL || pRoot == pA || pRoot == pB) {
        return pRoot;
    }
    TreeNode *pLeft = LcaBinaryTree(pRoot->pLeft, pA, pB);
    TreeNode *pRight = LcaBinaryTree(pRoot->pRight, pA, pB);
    if (pLeft != NULL && pRight != NULL) {
        return pRoot;                  /* 两侧各找到一个，当前即分叉点 */
    }
    return (pLeft != NULL) ? pLeft : pRight;
}

平衡二叉树判断，素材给的定义是「左右子树都是平衡二叉树，且深度差不超过 1」。按字面直译会写出 O(n²)：每个结点都重算一次子树深度。带剪枝的后序只需一遍，函数返回子树深度，一旦发现某个结点不平衡就返回 -1 并一路上抛，父结点看到 -1 立刻收工，不再往下算。

O(n²) 到 O(n) 的差距，来源是「不重复计算同一棵子树」。这个思路能套到一大批树上题，凡是「每个结点都要求一次子树信息」的，先想能不能一次遍历把信息带上来。

前中后序遍历的递归版三行就写完，非递归版要自己维护栈。先序最简单，压栈时先压右再压左；中序要一路压左到底再弹出；后序最麻烦，需要一个 lastVisited 指针。这一块在《二叉树》里讲透了，这里只提一句：面试让你手写非递归遍历，写不出来比写错更常见，考前过一遍。

素材里还有一道设计题：给内存有限的手持设备做地址簿，选哈希表还是二叉搜索树。答案是二叉搜索树。理由不是查找速度，哈希表查找是 O(1)，比 BST 的 O(log n) 快。理由是地址簿要按名字顺序翻页浏览，BST 的中序遍历天然有序，哈希表要额外存一份排序结构，那才是多出来的内存。内存有限时，一份结构干两件事的方案赢。

十、排序类变体题 #

快速排序是手写率最高的一题，挖坑填数版最不容易写错：

c
static int Partition(int *a, int low, int high)
{
    int pivot = a[low];                /* 把枢轴挖出来，留一个坑 */
    while (low < high) {
        while (low < high && a[high] >= pivot) {
            high--;
        }
        a[low] = a[high];              /* 右边的填左边的坑 */
        while (low < high && a[low] <= pivot) {
            low++;
        }
        a[high] = a[low];              /* 左边的填右边的坑 */
    }
    a[low] = pivot;
    return low;
}

void QuickSort(int *a, int low, int high)
{
    if (low < high) {
        int mid = Partition(a, low, high);
        QuickSort(a, low, mid - 1);
        QuickSort(a, mid + 1, high);
    }
}

写成这样跑得对，但有两个坑。数组已经有序时，固定取首元素当枢轴会退化成 O(n²)，每次划分只砍掉一个元素；改法是随机选枢轴或三数取中。递归深度最坏是 O(n)，链表太长会爆栈，工程里对小分段切到插入排序、对深递归切到迭代。

九种排序的账要能张口报：

排序 平均 最坏 额外空间 稳定
直接插入 O(n²) O(n²) O(1) 稳定
希尔 O(n^1.3) O(n²) O(1) 不稳定
冒泡 O(n²) O(n²) O(1) 稳定
快速 O(n log n) O(n²) O(log n) 不稳定
直接选择 O(n²) O(n²) O(1) 不稳定
堆排序 O(n log n) O(n log n) O(1) 不稳定
归并 O(n log n) O(n log n) O(n) 稳定
计数 O(n+k) O(n+k) O(k) 稳定
基数 O(d(n+k)) O(d(n+k)) O(n+k) 稳定

稳定排序的判断标准是：相等元素排序前后的相对次序不变。稳定的一列是插入、冒泡、归并、计数、基数。选择排序不稳定，因为它在交换最小值时会把远处的相等元素甩到前面。快速排序不稳定，划分时的跳跃交换打乱了次序。

三个常见变体，思路都是拿排序当工具：

变体 做法 复杂度
求第 k 大 快排的划分只递归含目标的那一侧 平均 O(n)，最坏 O(n²)
求第 k 大（数据流） 维护大小为 k 的小顶堆 O(n log k)
统计逆序对 归并时统计「右边先出」的次数 O(n log n)

求第 k 大用不着全排。划分一次就能确定枢轴的最终位置，目标在左边就只递归左边。这就是快速选择，平均 O(n)，但最坏仍是 O(n²)，面试时要说清这个前提。

逆序对那题的价值在于它示范了一件事：排序过程本身能捎带出信息。归并时右边元素先于左边元素出队，说明左边剩余的所有元素都比它大，一次就能统计出多个逆序对。

顺带把一组老题答掉。heap 和 stack 的区别：stack 是栈，函数调用时由系统自动分配和释放，空间有限，放局部变量；heap 是堆，要手动 malloc 和 free，空间大，放动态申请的内存。两者跟数据结构里的「堆」和「栈」同名不同物，别混。栈的基本操作是入栈、出栈、判空、判满、清空。

十一、智力题：鸡蛋掉落问题 #

题目：一栋楼 100 层，鸡蛋从第 N 层及以上落下会摔破，从第 N 层以下落下不破。给你 2 个鸡蛋，设计方案找出 N，保证最坏情况下下落次数最少。鸡蛋没摔破可以重复用。

这道题的价值在于它能把三种思维层次分得很清楚。

第一种，二分法。从 50 层扔，碎了再 25 层，没碎就 75 层。听起来很对，复杂度还是 O(log n)。但二分只给了你一次机会：第一个鸡蛋在 50 层碎了，你只剩一个鸡蛋，而 N 就在 1 到 50 之间，只能从 1 层开始一层层往上试。最坏 50 次，比线性扫描还难看。二分的隐含前提是「每次探测都独立且代价相同」，这里碎一次就永久损失一个探测器，前提不成立。

第二种，均匀分组。把 100 层切成 10 组，每组 10 层。第一个鸡蛋在 10、20、30 层一路试探，找到 N 落在哪一组；第二个鸡蛋在那 10 层里线性找。这个思路来自「和一定时求极值」的直觉，比二分务实得多。但它的最坏次数不均衡：N 在第 1 组时，1 次试探加 9 次线性，共 10 次；N 在第 10 组时，10 次试探加 9 次线性，共 19 次。前面轻松，后面吃紧，最坏 19 次。素材原稿给的 18 次是把碎掉那一次和线性试探的最后一次重叠算了，按不同口径能差一次，思路不受影响。

第三种，让每一层的最坏次数相等。这是正解，也是这道题真正要考的东西。

设最坏情况下总次数为 x。第一次必须跳到第 x 层，理由是：如果在这层碎了，第二个鸡蛋要从 1 层线性试到 x-1 层，最坏 x-1 次，加上已经用掉的 1 次，正好是 x 次，刚好卡在预算内。如果第一次跳到比 x 更高的层，碎了之后线性试探就会超过预算。

第一次没碎，预算还剩 x-1 次。第二次往上跳的步长必须缩到 x-1 层，这样万一碎在这层，线性试探 x-2 层加上已用 2 次，还是 x 次。再往上，步长依次是 x-2、x-3，一路递减到 1。

把所有步长加起来要盖住 100 层：

text
x + (x-1) + (x-2) + ... + 1 >= 100
        x(x+1)/2 >= 100

解这个不等式。x=13 时是 91，不够；x=14 时是 105，够。答案是 14 次。

对应的试探序列是 14、27、39、50、60、69、77、84、90、95、99、100。步长从 13 递减到 1。举个例：第一个鸡蛋在 77 层碎，说明 N 在 70 到 77 之间，第二个鸡蛋从 70 层开始试 70、71、72、73、74、75、76，最多 7 次，加上前面 7 次试探（14、27、39、50、60、69、77），最坏 14 次。

三种方案摆一起：

方案 最坏次数 思路 能不能推广
二分 50 假设探测代价可重复 不能，前提不成立
均分 10 组 19 分组缩小范围，组内线性 能，但步长不均衡
等差递增 14 让每次的最坏剩余次数相等 能，是正解

这道题可泛化成 d 层楼、e 个鸡蛋。教科书解法是动态规划：设 f(e, t) 表示 e 个鸡蛋、t 次尝试最多能确定多少层。第一次扔下去，碎了就往下用 e-1 个蛋和 t-1 次，没碎就往上用 e 个蛋和 t-1 次，中间那层本身也被确定了：

text
f(e, t) = f(e-1, t-1) + f(e, t-1) + 1
f(1, t) = t
f(e, 0) = 0

于是只需找最小的 t 让 f(2, t) >= 100。把它展开，f(2, t) = f(2, t−1) + t，正好就是 t(t+1)/2：f(2,1)=1、f(2,2)=3、f(2,3)=6、f(2,4)=10，一路涨到 f(2,13)=91，还差 9 层；f(2,14)=105，够了。答案 14，跟前面的手推一致。

这个 DP 的方向是「给定次数问能测多少层」，比「给定楼层问最少几次」的那个 O(n²e) 版本省事，也很好写。两层的循环，外层加次数，内层加鸡蛋数。

面试时如果只答「14 次」而讲不出为什么步长要递减，这道题等于没答。反过来，讲清了「让每次的最坏剩余预算相等」，即使数字算错一位，面试官也知道你懂了。

十二、智力题：其他经典题型 #

先收一组短题。它们的共同套路是：别顺着题面的直觉走，先换个等价描述。

题目 答案 关键一步
两列火车对开，鸟在两车之间往返飞，鸟飞了多远 全程的 6/7 别算往返次数，鸟一直在飞，时间等于两车相遇时间
两罐子 50 红 50 蓝，怎么让摸到红球的概率最大 约 74.7% 一罐只放 1 个红球，另一罐放 49 红 50 蓝
四罐药丸，有一罐被污染，只称一次找出它 超重几单位就是几号罐 从 1 到 4 号罐分别取 1、2、3、4 粒一起称
三色果冻，闭眼抓几个保证有两个同色 4 个 抽屉原理，最坏前 3 个正好三色各一
100 盏灯全亮，第 i 轮拨 i 的倍数，最后哪些灭 1、4、9、16、25、36、49、64、81、100 被拨次数等于约数个数，只有完全平方数有奇数个约数
镜子里为什么左右颠倒，上下不颠倒 左右没有颠倒 镜面对称轴是人的中轴，上下本来就对称，是我们把「左右」定义反了
舞会黑帽，第三次关灯才有人打耳光 3 人 沉默也是信息，归纳出第 N 次关灯响 N 下
半径 2 和 1 的两个圆环，小圆自转几周 内侧 1 周，外侧 3 周 「圆心轨迹长度」不等于「滚动弧长」，公转要另算
20 元买汽水，2 空瓶换 1 瓶，最多喝几瓶 39 瓶，允许借瓶是 40 瓶 每换一次空瓶净减 1，瓶颈在最后 1 个换不动的空瓶

有三行值得单独说。

圆环那题，素材给的答案是「内外都两圈，小圆大圆经历的距离相等」。那是只按半径比 2:1 推出来的，漏了公转。小圆纯滚动时，滚过的弧长等于圆心走过的距离，而圆心轨迹的半径是 R±r：在内侧是 R−r，外侧是 R+r。代入 R=2、r=1，内侧自转 (2−1)/1 = 1 圈，外侧 (2+1)/1 = 3 圈。分不清「圆心轨迹」和「接触点走的弧长」，这类题必错。

汽水那题，39 和 40 都对，取决于约束。不借瓶：20 瓶喝完得 20 个空瓶，2 换 1 且喝完又得 1 个空瓶，所以每换一次空瓶净减 1，一路减到 1 个的时候换不动了，共换 19 次，喝 39 瓶。允许先借 1 个空瓶：凑成 2 个换掉，喝完把空瓶还回去，多喝 1 瓶，共 40 瓶。素材那句「相当于 1 元买 2 瓶」的直觉就来自借瓶版本。先问清能不能借，再答数。

帽子那题的归纳要讲完整。N=1 时，唯一的黑帽人看到别人全白，立刻知道自己黑，第一次关灯就该响。N=2 时，两个黑帽人各看到 1 顶，都想「如果我是白，他就是唯一的黑，他第一次就该打」，第一次没响，于是第二次两人同时打。第 N 次关灯响 N 下，所以观察到第三次才响，就是 3 人。这题的核心是「没人动」本身就是一条信息，能从沉默里读出别人的推理进度。

再收一组算法设计题，它们是智力题和数据结构的分界处：题面是应用，解法是标准套路。

循环赛日程表，n = 2^k 个选手，每人每天一场，共 n−1 天。分治的做法是把选手分成两半，先排左半的日程，右半照抄并加上 n/2 的偏移，再把两半交叉对填。填表的手法就三条：右上角照抄左上角再加 half，左下角照抄右上角，右下角照抄左上角。half 从 1 开始每次翻倍，翻到 n 为止。复杂度 O(n²) 正好等于输出规模，没有浪费。这块表在《算法思想》的分治一节里有完整代码，思路是同一套。

最长公共子序列，c[i][j] 表示 X 的前 i 个字符和 Y 的前 j 个字符的 LCS 长度：

text
c[i][j] = 0                               i=0 或 j=0
c[i][j] = c[i-1][j-1] + 1                 x[i] == y[j]
c[i][j] = max(c[i-1][j], c[i][j-1])       x[i] != y[j]

填完 c 表要回溯出具体序列，得再用一个 b 表记来源：等于 1 走左上，等于 2 走左，等于 3 走上，从 c[m][n] 倒推到边界，把走对角线时遇到的字符收集起来就是答案。只问长度就只填 c，问序列才需要 b。多开一个二维表的空间换可回溯，值不值看题目问什么。

0-1 背包，C[i][j] 表示前 i 个物品在容量 j 下的最大价值：

text
C[i][j] = C[i-1][j]                               j < w[i]
C[i][j] = max(C[i-1][j], C[i-1][j-w[i]] + v[i])   j >= w[i]

拿经典实例验一遍：n=4，w=[3,5,2,1]，v=[9,10,7,4]，容量 7。最优解是选 1、3、4 号物品，重量 3+2+1=6，价值 9+7+4=20；选 2、3 号重量正好 7，价值只有 17。放在一起比，20 更优。这题的价值在「容量有限时，轻而贵的东西往往比重的划算」，DP 只是把这个比较系统化。它的搜索树是一棵子集树，深度 4，用分支限界法剪枝时的界是 cp + rp > bestp，其中 cp 是当前价值、rp 是剩余物品价值上界。

旅行售货员问题，n 个城市各走一次再回到起点，求最短回路。解空间是一棵排列树，叶子有 (n−1)! 个，回溯法最坏要搜遍每个叶子，每次判限界 O(1)，每个叶子记最优解 O(n)，总时间是 O(n!)。这个量级说明它只能解小规模，城市数上到二十就撑不住，实际要靠近似算法。

图的 m 着色问题，用 m 种颜色给 n 个顶点染色，相邻顶点不同色。判断限界函数要 O(n)，最坏要检查的结点数是 1+m+m²+…+m^(n−1) = (m^n−1)/(m−1)，即 O(m^n)，叶子有 m^n 个，输出方案每个 O(n)，总时间 O(n·m^n)。

套路 什么时候用 本文的例子 典型代价

看出一道题该用哪一行，比会写其中任何一行的代码都难。

十三、解题的通用套路 #

白板前的流程固定成五步，别跳。

第一步，复述。把题目用自己的话讲一遍，把输入范围、返回值形式、有没有序、能不能改原数据问清楚。这一步能挡掉一半的错解。

第二步，举小例子。拿三五个元素在纸上跑一遍，边界自然浮出来。空输入、单元素、两元素、全相同、全逆序，这五个例子过一遍，后面的坑少一半。

第三步，说暴力解。别嫌它笨，它是你的下限，也是你后面优化的参照物。说完立刻报复杂度。

第四步，找瓶颈。O(n²) 慢在哪？如果是「每个元素都要扫一遍别人」，就上哈希表或双指针；如果是「重复算了同一棵子树」，就缓存或改后序；如果是「每次都要找最值」，就上堆。

第五步，报取舍。方案选定了，用一句话说清为什么：「我用迭代不用递归，因为链表长度不可控，栈深度会炸。」这句话是整场面试里最值钱的一句。

复杂度要跟规模对得上。n 到 10⁵ 时，O(n²) 就是 10¹⁰ 次操作，跑不完；O(n log n) 是 1.7×10⁶，轻松。面试官给的数据范围就是提示：他说 n ≤ 10⁵，你就别写 O(n²)；他说 n ≤ 20，那就是在暗示指数级搜索可以接受。

下面这些，都是白板上真会翻车的地方。

场景 错法 正确做法
链表删除结点 free 之后还用 p->next 先存 next，再 free

环问题 用浮点算圆心轨迹 内外侧半径是 R−r 和 R+r，不是 R

最后一条经验：写完代码先自己念一遍变量。指针题念 next，数组题念下标，递归题念终止条件。这三处念通了，白板上能翻的车基本翻不掉。

能力不在背了多少题，在于拿到一道没见过的问题时，你知道从哪一步开始拆。
