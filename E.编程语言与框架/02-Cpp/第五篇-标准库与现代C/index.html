第20章 标准库与 STL 速览 #

本章目标：了解 C++ 标准库（standard library）的组成，掌握 std::string 与 std::vector 的常用函数、容器（container）/迭代器（iterator）/算法三要素，以及日期时间、随机数与信号处理的基本用法。

20.1 引子：为什么需要这一章 #

前面的章节里，我们亲手写过字符数组、动态数组和排序循环。这些工作重复、易错，而它们恰好是标准库已经解决过的问题：标准库由经过严格测试的实现提供，正确性、执行效率与编程风格都有保障，直接复用可以把精力留给业务逻辑。本章先回答「有什么」，建立一张标准库的地图，再挑出最常用的 std::string、std::vector 和 STL 三要素展开，最后把日期时间、随机数与信号处理这些零散但常见的设施收拢进来。学习标准库不必逐页通读，先了解概貌，再在实践中逐步深入即可。

20.2 标准库的组成与常用头文件 #

C++ 标准库可分为两部分：一部分是继承自 C 语言、由通用且不属于任何类的函数组成的标准函数库；另一部分是类及其相关函数构成的面向对象类库，覆盖输入输出 I/O、字符串处理、数值处理、时间日期与本地化、动态分配等。标准库的内容定义在约 50 个标准头文件中，按功能分为十类：语言支持、流输入输出、诊断、通用工具、字符串处理、容器模板、迭代器、算法、数值操作与本地化。

标准库的头文件都没有扩展名，以 <cname> 形式提供；与宏相关的名字在全局作用域中定义，其余名字在 std 命名空间（namespace）中声明。C 风格的 name.h 形式也可以使用。

分类 代表头文件 主要内容
语言支持 <cstddef>、<limits>、<new>、<typeinfo>、<exception> size_t、ptrdiff_t、数值极值、动态内存分配、运行期类型标识、异常处理
流与输入输出 <iostream>、<iomanip>、<sstream>、<fstream>、<ios>、<streambuf> cin/cout/cerr/clog、格式操纵、字符串流与文件流、流缓冲
诊断 <stdexcept>、<cassert>、<cerrno> 标准异常、断言宏、C 风格错误信息
通用工具 <utility>、<functional>、<memory>、<ctime> pair、关系运算符、函数对象、内存分配器、系统时钟
字符串 <string>、<cctype>、<cstring> 字符串类型、字符类别、C 风格字符串与内存块操作
容器 <vector>、<list>、<deque>、<queue>、<stack>、<map>、<set>、<bitset> 各类序列容器、关联容器与容器适配器
迭代器与算法 <iterator>、<algorithm>、<numeric> 迭代器支持、约百个算法模板、序列上的数学运算
数值与本地化 <complex>、<valarray>、<cmath>、<locale>、<clocale> 复数、数值矢量、C 数学库、本地化与 C 样式本地化

20.3 STL 的三大件：容器、迭代器与算法 #

STL（Standard Template Library，标准模板库）最初由惠普实验室开发，被引入 C++ 标准后组织为 13 个头文件：<algorithm>、<deque>、<functional>、<iterator>、<vector>、<list>、<map>、<memory>、<numeric>、<queue>、<set>、<stack> 和 <utility>。其代码从广义上分为三类：容器、迭代器与算法，几乎全部采用模板类与模板函数，因而具备良好的代码复用能力。

容器负责存放数据。常用的序列容器与关联容器如下：

数据结构 说明 头文件
向量 vector 连续存储的元素，支持随机访问 <vector>
列表 list 由节点组成的双向链表，适合任意位置插入删除 <list>
双端队列 deque 支持在首尾高效插入删除 <deque>
集合 set / 多重集合 multiset 按次序存储唯一值 / 允许次序相等的值 <set>
映射 map / 多重映射 multimap 由键—值对组成，按键的次序排列 <map>
栈 stack 后进先出的值的排列 <stack>
队列 queue / 优先队列 priority_queue 先进先出 / 按谓词决定次序 <queue>
位集 bitset 固定长度的紧凑位序列 <bitset>

迭代器是算法与容器之间的间接层，用来把二者联系起来：几乎全部 STL 算法都通过迭代器存取元素序列，每个容器都定义自己专有的迭代器，begin() 指向首元素，end() 指向尾元素的下一位置，构成左闭右开区间 [begin, end)。迭代器部分主要由 <utility>、<iterator> 与 <memory> 支持，其中 <memory> 的主要部分是模板类 allocator，负责为容器中的元素分配存储空间。

算法是建立在迭代器上的模板函数。<algorithm> 是其中最大的一个，覆盖比较、交换、查找、遍历、复制、修改、移除、反转、排序与合并等操作；<numeric> 只含少量序列数学运算，如 accumulate 与 inner_product；<functional> 定义用于声明函数对象的模板类。熟悉这些算法后，许多手写循环可以简化为一两次调用。

20.4 std::string 常用函数 #

std::string 是标准库提供的字符串类型，使用时包含 <string>（不是 C 字符串的 <string.h>）。相比以 char* 表示的字符串，它不必担心内存是否足够与长度管理，可以直接用 = 赋值、== 比较、+ 串联。构造方式包括默认空字符串、拷贝构造、以 C 字符串初始化、以 n 个字符 c 初始化，以及以区间 [beg, end) 内的字符初始化；字符串过长时会抛出 length_error 异常。

下表按用途归纳常用成员函数：

类别 成员函数或运算符 说明
构造与赋值 assign()、=、swap() 赋以新值、交换两个字符串的内容
大小与容量 size()、length()、empty()、max_size()、capacity()、reserve()、resize() size() 与 length() 等效；不足时 max_size() 会抛出 length_error
元素存取 []、at() at() 提供范围检查，越界抛出 out_of_range；下标运算符 [] 不检查，越界为未定义行为
修改内容 +=、append()、push_back()、insert()、erase()、clear()、replace() 尾部添加、按位置插入删除、清空与替换
子串与连接 substr()、+ 提取子串、串联字符串
比较 ==、!=、<、<=、>、>=、compare() 按字典序逐字符比较；compare() 返回 0、正值或负值表示相等、大于、小于
查找 find()、rfind()、find_first_of()、find_last_of()、find_first_not_of()、find_last_not_of() 返回首个符合位置的索引，未找到返回 string::npos
C 字符串转换 c_str()、data()、copy() 转换为 C 风格字符序列，或复制到既有字符数组
迭代器 begin()、end()、rbegin()、rend() 提供与 STL 一致的迭代器支持
输入输出 >>、<<、getline() 从流读取、写入流、读取一行

注意：素材指出 data() 以字符数组形式返回内容但不添加结尾空字符，c_str() 返回以空字符结尾的字符序列，且二者由字符串拥有、为 const char*。调用只接受 char* 的旧接口时应先拷贝到可写缓冲，不要直接对返回值强制转换后写入。

20.5 std::vector 常用函数 #

std::vector 是大小可以重新设置的序列容器，内部以动态数组方式实现，支持随机访问，比普通数组更安全、更灵活，使用时包含 <vector>。常见初始化方式有五种：指定元素个数、指定个数与初值、用另一向量整体复制、用另一向量的区间 [b.begin(), b.begin()+3) 初始化，以及用数组的 [b, b+7) 区间初始化。

成员函数 作用
push_back(elem) / pop_back() 在尾部加入 / 删除一个元素
size() / capacity() / max_size() / empty() 元素个数、已分配容量、最大可容量、是否为空
resize(n) / resize(n, v) / reserve(n) 调整元素个数（多则删、少则补）/ 预分配容量
at(i) / operator[] / front() / back() 元素存取；at() 越界抛出 out_of_range
begin() / end() / rbegin() / rend() 正向与逆向迭代器
insert(pos, ...) / erase(pos) / erase(beg, end) 插入、按位置删除、按左闭右开区间删除
assign(...) / clear() / swap() 赋值、清空、与另一向量整体交换

size() 表示容器中有多少元素，capacity() 表示在已分配内存中总共可容纳多少元素；两者相等时下一次 insert 或 push_back 会引发重新分配。重新分配会重新申请更大的缓冲区并复制原有内容，同时使指向容器的迭代器、指针与引用失效。因此当预计要加入大量数据时，应尽早用 reserve() 把容量设到足够大；pop_back() 不会让 capacity() 下降。若要回收多余容量，可用 vector<int>(v).swap(v) 这一「交换技巧」，让临时副本只保留实际所需的容量。

注意：素材对 [] 与成员函数的称呼与全书约定不一致，本章统一写作「下标运算符」与「成员函数」；素材中的拼写笔误、行号以及转载水印、孤立数字已一并清除。

cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    vector<int> nums;
    nums.reserve(5);                       // 预分配容量，避免多次重新分配
    for (int i = 1; i <= 5; ++i) {
        nums.push_back(i * i);
    }

    // 用迭代器遍历，区间为 [begin, end)
    for (vector<int>::iterator it = nums.begin(); it != nums.end(); ++it) {
        cout << *it << " ";
    }
    cout << endl;

    reverse(nums.begin(), nums.end());      // 就地倒置
    cout << "首元素：" << nums.front() << endl;

    string s = "Hello, STL";
    s.append("!");
    cout << s.substr(7) << endl;            // 输出 STL!
    if (s.find("STL") != string::npos) {
        cout << "找到子串" << endl;
    }
    return 0;
}

20.6 日期与时间 #

C++ 标准库没有专门的日期类型，而是继承 C 语言用于日期与时间操作的结构和函数，使用时包含 <ctime>。与时间相关的类型有 clock_t、time_t、size_t 和 tm：前三者把系统时间和日期表示为某种整数；tm 以 C 结构形式保存日期和时间，成员包括 tm_sec（秒，0 至 59，允许至 61）、tm_min、tm_hour、tm_mday、tm_mon（0 至 11）、tm_year（自 1900 年起的年数）、tm_wday、tm_yday 与 tm_isdst。

函数 作用
time_t time(time_t *time) 返回当前日历时间，即自 1970 年 1 月 1 日以来经过的秒数
char *ctime(const time_t *time) 返回表示本地时间的可读字符串
struct tm *localtime(const time_t *time) 返回指向本地时间 tm 结构的指针
struct tm *gmtime(const time_t *time) 返回指向 UTC/GMT 时间 tm 结构的指针
char *asctime(const struct tm *time) 把 tm 结构转为可读字符串
time_t mktime(struct tm *time) 把 tm 结构转为日历时间
double difftime(time_t time2, time_t time1) 返回两个时间相差的秒数
clock_t clock(void) 返回程序执行起处理器时钟所用的时间
strftime() 按指定格式格式化日期与时间

20.7 随机数 #

素材给出 rand()、srand() 与 time() 三个函数：rand() 返回一个 0 至 RAND_MAX 之间的伪随机数，RAND_MAX 定义在 C 标准库头文件中；srand() 用来设置随机种子，配合 time() 传入当前时间可避免每次运行得到相同序列；对结果取模可把随机数限制在指定范围内。

注意：素材关于 srand 所在头文件的说法前后不一致（一处称「iostream 头文件中就有」，一处称 RAND_MAX 定义在 stdlib.h）。本章只依据素材给出的 rand()、srand()、time() 与 RAND_MAX 写示例，按常规包含 <cstdlib> 与 <ctime>，不据此推断其他标准细节。

cpp
#include <cstdlib>
#include <ctime>
#include <iostream>
using namespace std;

int main() {
    // 日期与时间
    time_t now = time(0);                 // 当前日历时间
    tm *local = localtime(&now);          // 转换为本地时间的 tm 结构
    cout << "年份：" << 1900 + local->tm_year << endl;
    cout << "月份：" << 1 + local->tm_mon << endl;
    cout << "本地时间：" << ctime(&now);

    // 随机数：用当前时间设置种子
    srand(static_cast<unsigned int>(now));
    cout << "0~99 的随机数：" << rand() % 100 << endl;
    return 0;
}

20.8 信号处理 #

信号是由操作系统传给进程的中断，会提早终止程序；在 UNIX、Linux、Mac OS X 或 Windows 上，按 Ctrl+C 即可产生中断。并非所有信号都能被捕获，素材列出的可捕获信号定义在 <csignal> 中：

信号 说明
SIGABRT 程序的异常终止，如调用 abort()
SIGFPE 错误的算术运算，如除以零或导致溢出的操作
SIGILL 检测到非法指令
SIGINT 接收到交互注意信号
SIGSEGV 非法访问内存
SIGTERM 发送到程序的终止请求

signal() 用来注册信号及其处理函数，其形式为 void (*signal(int sig, void (*func)(int)))(int)：第一个参数是信号编号，第二个参数是指向信号处理函数的指针。raise() 用于在程序内部产生信号，接收一个信号编号参数。素材列出的可捕获信号还包括 SIGHUP。

注意：素材的示例使用了 sleep() 并包含 unistd.h，属于 POSIX 平台接口。本章示例只使用 <csignal> 与 <cstdlib> 中的 signal()、raise() 与 exit()，不依赖该平台细节。

cpp
#include <csignal>
#include <cstdlib>
#include <iostream>
using namespace std;

void on_signal(int signum) {
    cout << "捕获信号 " << signum << endl;
    exit(signum);
}

int main() {
    signal(SIGINT, on_signal);   // 注册 SIGINT 的处理函数
    raise(SIGINT);                // 在程序内部产生该信号
    return 0;
}

20.9 小结 #

  • 标准库由标准函数库与面向对象类库组成，约 50 个无扩展名头文件按十类功能组织；<cname> 形式下非宏名字声明在 std 命名空间。
  • STL 由容器、迭代器与算法三部分构成，13 个头文件几乎全部基于模板；迭代器以 [begin, end) 区间把算法与容器连接起来。
  • std::string 提供赋值、存取、修改、查找、比较、子串与输入输出等成员函数；at() 越界抛异常，下标运算符不检查。
  • std::vector 以动态数组实现，size() 与 capacity() 区分元素数与容量；reserve() 可减少重新分配，交换技巧可回收多余容量。
  • <ctime> 提供 time_t / tm 与一组时间函数；rand()、srand()、time() 配合可生成伪随机数；<csignal> 的 signal() 与 raise() 用于捕获与产生信号。

20.10 常见错误与陷阱 #

  • 混淆 <string> 与 C 的 <string.h>：前者才是 std::string 的头文件。
  • 用下标运算符访问越界元素，或把对 string / vector 元素的引用、指针长期保存；一旦发生重新分配，它们会失效。
  • 对 c_str() 返回的 const char* 强制转换后写入；需要可写缓冲时应先拷贝。
  • 误以为 reserve() 会改变 size()，或在 pop_back() 后期待 capacity() 自动下降。
  • 对空 vector 直接用 a[i] = v 赋值：下标只能用于获取已存在的元素，应先 push_back() 或 resize()。
  • 把 size() 与 capacity() 返回值混用，或忽略 end() 指向尾后位置、区间为左闭右开这一约定。
  • 忘记 srand() 设置种子，导致每次运行得到相同的随机数序列。

第21章 现代 C++（C++11 起） #

本章目标：掌握 auto、nullptr、范围 for、lambda、智能指针、右值引用与移动语义等 C++11 核心特性，并了解多线程的基本概念与 pthread 接口。

21.1 引子：为什么需要这一章 #

C++11 标准同时扩充了语言本身与标准库，新特性数量众多。本章不求穷举，只挑选日常开发中应当成为常规装备的那些：让声明更简洁的 auto 与类型推断、更安全的空指针 nullptr、更省心的范围遍历与智能指针、更灵活的 lambda 表达式，以及显著影响性能的右值引用与移动语义。它们大多围绕两件事：减少样板代码，以及让资源的所有权在类型系统中表达得更清楚。多线程部分则依据素材，先讲清线程概念，再介绍 POSIX pthread 接口。

21.2 auto 与 nullptr #

在 C++11 之前，auto 用来指定存储期；新标准中它变为类型推断的占位符，通知编译器根据初始化代码推断变量的真实类型，可用于命名空间、程序块或 for 循环的初始化语句中。最典型的收益是遍历 STL 容器时不必再写一长串迭代器类型。auto 不能直接用来声明函数返回值；若函数带有尾随返回类型，auto 可以出现在返回值位置，此时它只是引导编译器到函数末端寻找类型，例如 template <typename T1, typename T2> auto add(T1 t1, T2 t2) -> decltype(t1 + t2)。

过去用 0 表示空指针，但 0 可以隐式转换为整型，容易引发重载决议上的问题。nullptr 是 std::nullptr_t 类型的值，可隐式转换为任意指针类型、成员指针类型以及 bool（取值为 false），但不存在到整型的隐式转换；为向前兼容，0 仍是合法的空指针值。

cpp
#include <iostream>
using namespace std;

template <typename T1, typename T2>
auto add(T1 t1, T2 t2) -> decltype(t1 + t2) {
    return t1 + t2;
}

int main() {
    auto i = 42;        // i 推断为 int
    auto d = 3.14;      // d 推断为 double
    auto sum = add(1, 3.14);

    int *p = nullptr;   // 空指针
    // int n = nullptr; // 错误：nullptr 不能隐式转换为整型
    if (!p) {
        cout << "p 为空指针" << endl;
    }
    cout << i << " " << d << " " << sum << endl;
    return 0;
}

21.3 范围 for、初始化列表与非成员 begin() / end() #

C++11 扩展了 for 语句，支持形如 for (声明 : 范围) 的范围 for 循环。当只想对集合或数组的每个元素做操作、不关心下标、迭代器位置或元素个数时，这种写法最清晰。它可以遍历 C 类型数组、初始化列表，以及任何重载了非成员 begin() 与 end() 的类型。

非成员 std::begin() 与 std::end() 是新加入标准库的函数，与所有 STL 容器兼容，也对 C 类型数组提供了重载。它们除了提高代码一致性，还便于泛型编程：同一个模板函数可以同时处理容器与数组。参见 第20章「标准库与 STL 速览」。

注意：素材仅在说明范围 for 可遍历的对象时提到「初始化列表」，未给出初始化列表类型及其 API，故本章不补写具体用法。

21.4 lambda 表达式 #

lambda 表达式（lambda expression）是从函数式编程引入的匿名函数，可用于任何需要函数对象、函子或 std::function 的地方。基本形式为 [捕获](参数列表) { 函数体 }，例如 [](int n) { return n % 2 == 1; } 可作为一个判断奇数的谓词交给 std::find_if()。

若试图用 auto 声明一个捕获自身的递归 lambda，会因「对象类型由初始表达式决定、而初始表达式又引用自身」形成循环依赖，编译器报出类似 'fib': a symbol whose type contains 'auto' must have an initializer 的错误。解决办法是用 std::function<int(int)> 显式指定函数类型，打破这一循环依赖。

21.5 范围遍历与算法综合示例 #

下面的例子把范围 for、非成员 std::begin() / std::end() 与 lambda 表达式放在同一段代码里：先用引用遍历并改写容器元素，再对 C 数组用同一套算法查找首个偶数。

cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> v;
    v.push_back(1);
    v.push_back(2);
    v.push_back(3);

    for (int &e : v) {        // 范围 for，通过引用可修改元素
        e = e * e;
    }
    for (int e : v) {
        cout << e << " ";
    }
    cout << endl;

    // std::begin / std::end 同时适用于容器与 C 数组
    int arr[] = {4, 5, 6};
    auto pos = find_if(std::begin(arr), std::end(arr),
                       [](int n) { return n % 2 == 0; });
    if (pos != std::end(arr)) {
        cout << "首个偶数：" << *pos << endl;
    }
    return 0;
}

21.6 override、final 与强类型枚举 #

虚函数的 virtual 关键字在派生类中是可选的，阅读代码时往往要追溯到继承体系源头才能判断某个成员函数是否为虚函数；更微妙的是，参数类型或 const 限定稍有不同，本意上的「重写」就会退化成重载。C++11 加入两个标识符来表达意图：override 表示该函数应当重写基类中的虚函数，若签名不匹配则编译报错（如 'D::f' : method with override specifier 'override' did not override any base class methods）；final 表示该虚函数不应再被派生类重写。二者可同时写成 override final，被标记为 final 的成员函数不能再被重写。

传统枚举会把枚举常量暴露到外层作用域，容易与同一作用域中其他枚举的同名常量冲突，还会被隐式转换为整型。强类型枚举用 enum class 标识：不向外层作用域暴露枚举常量、不隐式转换为整型，并允许用户指定底层类型（传统枚举也增加了这一性质）。例如 enum class Options {None, One, All}; Options o = Options::All;。

21.7 智能指针 #

智能指针（smart pointer）在 <memory> 中提供带引用计数、可自动释放内存的指针：

  • unique_ptr：所有权不需要共享时使用。它没有拷贝构造函数，但可以通过移动构造函数把所有权转让给另一个 unique_ptr；转让需 std::move()，转让后交出所有权的智能指针为空，get() 返回 nullptr。
  • shared_ptr：所有权需要共享时使用，多个智能指针共同管理同一对象。
  • weak_ptr：持有被 shared_ptr 管理对象的引用但不改变引用计数，用于打破循环引用（例如树结构中父节点持有子节点的共享引用、子节点又持有父节点引用，若两端都共享所有权就会形成循环，导致内存无法释放）。访问对象必须先调用 lock() 取得 shared_ptr；若对象已过期，lock() 返回空的 shared_ptr，也可用 expired() 判断。
  • make_shared 是非成员函数，可一次性分配共享对象与智能指针自身的内存；显式使用 shared_ptr 构造函数至少需要两次分配，除了额外开销，在类似 foo(shared_ptr<int>(new int(42)), seed()) 的场景中，若 seed() 抛出异常还可能造成内存泄漏。
  • auto_ptr 已被废弃，不再使用。

注意：素材示例带有排版粘连（如 newint(42)、std::unique_ptr _buffer）与笔误，本教程按可编译形式重写；make_shared 减少分配次数、避免上述泄漏风险的结论来自素材，未补充其他实现细节。参见 第8章「指针」。

21.8 static_assert 与 type traits #

static_assert 提供编译期断言：条件为真时什么也不发生，为假时编译器打印指定的错误信息，例如素材中类模板 Vector<double, 2> 实例化时得到 error C2338: Size is too small。

type traits 是一些在编译期提供类型信息的类，定义在 <type_traits> 中，分为三类：helper class（产生编译期常量）、type traits class（编译期获取类型信息）与 type transformation class（把已有类型变换为新类型）。二者配合可以在模板中约束类型：auto add(T1 t1, T2 t2) -> decltype(t1 + t2) 原本对 add(1, 3.14)、add("one", 2) 都会通过，加上 static_assert(is_integral<T1>::value, "Type T1 must be integral"); 之后即可在编译期拒绝非整型实参。素材中的类型萃取条件遗漏了模板参数，本教程统一写作 std::is_integral<T>::value。

注意：素材示例中 static_assert 的条件表达式与其报错示例不一致，本教程只说明编译期断言与错误信息机制，不照抄该条件式。

cpp
#include <iostream>
#include <memory>
#include <type_traits>
#include <utility>
using namespace std;

template <typename T>
class NumberBox {
    static_assert(is_integral<T>::value, "T must be an integral type");
public:
    explicit NumberBox(T v) : value_(v) {}
    T get() const { return value_; }
private:
    T value_;
};

int main() {
    NumberBox<int> box(7);                 // 满足编译期断言
    cout << "box = " << box.get() << endl;

    unique_ptr<int> p1(new int(42));
    unique_ptr<int> p2 = std::move(p1);    // 所有权转移
    if (!p1) {
        cout << "p1 已交出所有权" << endl;
    }
    if (p2) {
        cout << "p2 = " << *p2 << endl;
    }

    auto p3 = make_shared<int>(10);        // 一次性分配对象与智能指针所需内存
    cout << "p3 = " << *p3 << endl;
    return 0;
}

21.9 右值引用与移动语义 #

C++11 引入右值引用（rvalue reference，用 && 标识）区分对左值与右值的引用：左值是有名字的对象，右值是无名的临时对象。移动语义（move semantics）允许修改右值——此前右值被视为不可修改，等同于 const T&。

类或结构体此前有若干隐含的成员函数：默认构造函数、拷贝构造函数、析构函数与拷贝赋值运算符。拷贝构造与拷贝赋值提供逐位的浅拷贝，若类中含有指向其他对象的指针，只会复制指针值而不管指向的对象；很多场合需要显式提供深拷贝。但当用来初始化或拷贝的源对象是右值时，仍要完整拷贝、随后右值又被释放，这就产生了本不需要的空间分配与内存复制。

C++11 新增移动构造函数与移动赋值运算符，形参为 T&&。它们可以直接「偷走」临时对象内部指针所指向的资源：例如容器含一个指向元素数组的指针，用临时对象初始化时只需复制指针值，省去一次内存分配、一次数组复制以及随后的内存释放。素材用 Buffer 类演示了这一点：getBuffer() 返回临时对象时，Buffer<int> b4 = getBuffer<int>("buf4"); 调用移动构造函数，b1 = getBuffer<int>("buf5"); 调用移动赋值运算符。

std::move() 的作用是把一个左值转换为右值引用。之所以需要它，是因为具名对象即使在移动构造函数内部也是左值（例如形参 temp），若写成 _name(temp._name) 调用的仍是拷贝构造函数；改为 _name(std::move(temp._name)) 才会调用 std::string 的移动构造函数。std::unique_ptr 没有拷贝构造函数，因此必须用 std::move() 转移。

注意：素材只给出移动构造与移动赋值的一种实现方式，并明确说明实现方式并不唯一；本章只讲清左右值区分、资源转移与 std::move() 的作用，不补写其他标准细节。

21.10 多线程：概念与 pthread 接口 #

多线程是多任务处理的一种特殊形式。多任务处理分两类：基于进程的是程序的并发执行，基于线程的是同一程序片段的并发执行；多线程程序中每个可同时运行的部分称为一个线程，每个线程定义一条单独的执行路径。

素材以 Linux 操作系统和 POSIX Threads（Pthreads）为例，该 API 在 FreeBSD、NetBSD、GNU/Linux、Mac OS X 与 Solaris 等类 Unix 系统上可用，编译时需要链接 -lpthread。

接口 作用
pthread_create(thread, attr, start_routine, arg) 创建新线程并使其可执行；成功返回 0，非 0 表示失败。attr 为属性对象，可用 NULL 取默认值；start_routine 是线程运行函数；arg 必须把引用强制转换为 void* 传递，无参数时用 NULL
pthread_exit(status) 显式退出线程。若 main() 在所创建的线程之前结束且通过它退出，其余线程继续执行；否则会在 main() 结束时被自动终止
pthread_join(threadid, status) 阻塞调用者，直到指定线程终止。只有创建时定义为可连接（joinable）的线程才能被连接
pthread_detach(threadid) 分离线程。创建时定义为可分离（detached）的线程永远不能被连接

素材的示例还用 pthread_attr_init() 初始化属性对象、pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_JOINABLE) 设置线程为可连接、用 pthread_attr_destroy() 释放属性，并在主线程中对每个线程调用 pthread_join() 等待完成。向线程传递多个参数时，可把数据装入结构体，再把结构体地址强制转换为 void* 传入，线程运行函数内再转换回原类型读取。

注意：std::thread 为 C++11 标准库线程设施，但素材未给出其 API，故不补写具体用法。

21.11 小结 #

  • auto 依据初始化表达式推断类型，nullptr 是 std::nullptr_t 类型的空指针值，不会隐式转为整型。
  • 范围 for 遍历 C 数组、初始化列表及提供非成员 begin() / end() 的类型；std::begin() / std::end() 让容器与数组可用同一套泛型代码。
  • override 与 final 把重写意图写进声明；enum class 强类型枚举不污染外层作用域、不隐式转整型。
  • unique_ptr、shared_ptr、weak_ptr 分别对应独占、共享与弱引用；make_shared 减少分配次数。
  • lambda 表达式可替代函数对象；递归 lambda 需用 std::function 明确类型。
  • static_assert 与 type traits 把类型约束提前到编译期；右值引用 && 与移动语义避免临时对象带来的多余分配与复制，std::move() 把具名左值转为右值引用。
  • 多线程部分：线程是单独的执行路径，素材给出 pthread_create、pthread_exit、pthread_join、pthread_detach 四个接口及 -lpthread 链接方式。

21.12 常见错误与陷阱 #

  • 用 0 或 NULL 表示空指针参与重载，误以为 nullptr 可以隐式转为整型；int n = nullptr; 是错误写法。
  • 以为 auto 能推断函数返回值类型而省略尾随返回类型；或在不带初始化表达式时声明 auto 变量。
  • 在派生类中写错参数类型、漏掉 const，本意重写却变成重载；加上 override 可让编译器直接报错。
  • 把 weak_ptr 当作普通指针直接解引用；必须先 lock() 取得 shared_ptr。
  • 用 auto 声明捕获自身的递归 lambda，形成类型推断的循环依赖。
  • 在移动构造函数里写 _name(temp._name)，因 temp 是具名左值而意外调用拷贝构造；应使用 std::move()。
  • 认为 std::move() 本身会移动对象；它只做类型转换。
  • 把素材中误识别的作用域运算符照抄进代码，或把漏写模板参数的类型萃取写法当作正确形式。
  • 期望 pthread_join() 能等待一个创建为 detached 的线程；可分离线程永远不能被连接。
