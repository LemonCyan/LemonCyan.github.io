第22章 进阶专题与工程实践 #

本章目标：理解接口与实现分离的两种做法、按类名动态创建类实例的工厂方案，辨析静态多态与动态多态，比较 MFC 与 Qt，并了解可用的延伸学习资源。

22.1 引子：为什么需要这一章 #

前五篇已把语法、内存、面向对象、异常、文件流、标准库（standard library）与现代 C++ 逐层铺开；真实工程里还有几类问题不属于任何单一语法点：怎样让客户代码只依赖一份稳定的头文件（header file）、怎样在运行时按字符串决定创建哪个类、同一份「多态」需求为何既可以用虚函数（virtual function）也可以用函数模板（function template）表达、以及选用哪套图形界面框架。本章集中讨论这些话题，速查信息则收进后面的附录。

注意：本章讨论的「动态创建」是指按类名字符串创建已编译进程序的类实例；C++ 并不能在运行时凭空生成一个编译时还不存在的类。

22.2 接口与实现分离的两种方法 #

素材给出两条路径，目标相同：客户只依赖一份稳定的接口头文件，实现变更时无需重新编译客户代码。

Pimpl Idiom（pointer to implementation）。对外只暴露一个持有实现类指针（pointer）的类：实现类仅做前置声明，数据成员与实现细节全部收进实现类，析构时释放该指针；客户看不到数据成员，也就无法直接操作它们。

cpp
#include <iostream>
#include <string>
using namespace std;

// 实现类只对实现文件可见，这里先做前置声明
class PersonImpl;

class Person {
public:
    Person(const std::string& name, int age);
    ~Person();
    std::string getName() const;
    void setName(const std::string& name);
    int getAge() const;
    void setAge(int age);
private:
    PersonImpl* mPersonImpl;   // 指向实现类的指针
};

// 实现类：数据成员与实现细节全部藏在这里
class PersonImpl {
public:
    std::string name;
    int age;
};

Person::Person(const std::string& name, int age)
    : mPersonImpl(new PersonImpl) {
    mPersonImpl->name = name;
    mPersonImpl->age = age;
}

Person::~Person() {
    delete mPersonImpl;        // 必须释放实现对象
}

std::string Person::getName() const { return mPersonImpl->name; }
void Person::setName(const std::string& name) { mPersonImpl->name = name; }
int Person::getAge() const { return mPersonImpl->age; }
void Person::setAge(int age) { mPersonImpl->age = age; }

int main() {
    Person p("小明", 20);
    cout << p.getName() << " " << p.getAge() << endl;
    p.setAge(21);
    cout << p.getName() << " " << p.getAge() << endl;
    return 0;
}

Object Interface（抽象接口类）。对外暴露一个只含纯虚函数（pure virtual function）的抽象类（abstract class），实现类在 .cpp 中继承它，由工厂函数负责创建。客户只拿到基类指针，编译期不依赖实现类。

cpp
#include <iostream>
#include <string>
using namespace std;

class Animal;                                    // 前置声明
Animal* creat(const std::string& name, int age);  // 工厂函数声明

// 抽象接口类：只含纯虚函数，不暴露数据成员
class Animal {
public:
    virtual ~Animal() {}                         // 虚析构，避免内存泄漏
    virtual std::string getName() const = 0;
    virtual int getAge() const = 0;
    virtual void setName(const std::string& name) = 0;
    virtual void setAge(int age) = 0;
};

// 实现类可放在 .cpp 中，客户代码不必见到它
class RealAnimal : public Animal {
    friend Animal* creat(const std::string& name, int age);
public:
    RealAnimal(const std::string& name, int age)
        : mName(name), mAge(age) {}
    std::string getName() const { return mName; }
    int getAge() const { return mAge; }
    void setName(const std::string& name) { mName = name; }
    void setAge(int age) { mAge = age; }
private:
    std::string mName;
    int mAge;
};

Animal* creat(const std::string& name, int age) {
    return new RealAnimal(name, age);
}

int main() {
    Animal* a = creat("小猫", 2);
    cout << a->getName() << " " << a->getAge() << endl;
    a->setAge(3);
    cout << a->getName() << " " << a->getAge() << endl;
    delete a;                                    // 经虚析构正确释放
    return 0;
}

两种做法的对照如下：

维度 Pimpl Idiom Object Interface
对外可见 一个类 + 指向实现类的指针 纯虚函数构成的抽象基类
客户依赖 只依赖接口头文件 只依赖接口头文件
实现变更 客户无需重新编译 客户无需重新编译
额外收益 隐藏数据成员，降低客户误操作数据的可能 天然支持运行期多态
代价 编译器自动生成的构造函数、拷贝构造函数等需显式处理 同左，且必须声明虚析构函数

注意：素材把「编译器自动生成构造函数与拷贝构造函数」列为两种做法的共同缺点，工程上需要显式处理拷贝与赋值语义。相关基础参见 第12章「类与对象」，多文件组织参见 第18章「预处理与多文件工程」。

22.3 按类名动态创建实例：工厂、映射与静态注册 #

设计链条是：所有可动态创建的类继承同一基类，用基类指针承接结果；创建动作由 new 完成；把「类名字符串 → 创建函数」存入 std::map；创建函数用 typedef void* (*NewInstancePt)(); 统一签名；再借全局静态对象在 main 之前完成登记。素材中的 CObjectFactory 提供 CreateObject(const char*)（未找到返回 NULL）与 RegisterClass，宏 REGISTER_CLASS(class_name) 用 ## 拼接出注册类及其静态成员。

cpp
#include <iostream>
#include <map>
#include <string>
#include <cstddef>
using namespace std;

// 所有可动态创建的类都继承同一基类
class CObject {
public:
    virtual ~CObject() {}
    virtual std::string GetClassName() const = 0;
};

// 统一的创建函数签名
typedef void* (*NewInstancePt)();

class CObjectFactory {
public:
    static void* CreateObject(const char* className) {
        std::map<std::string, NewInstancePt>::const_iterator it =
            dynCreateMap.find(className);
        if (it == dynCreateMap.end()) {
            return NULL;                       // 未注册的类名返回空
        }
        return it->second();                   // 调用对应的创建函数
    }
    static void RegisterClass(const char* className, NewInstancePt np) {
        dynCreateMap[className] = np;
    }
private:
    static std::map<std::string, NewInstancePt> dynCreateMap;
};

std::map<std::string, NewInstancePt> CObjectFactory::dynCreateMap;

// 注册辅助类：其构造函数在 main 之前完成登记
class Register {
public:
    Register(const char* className, NewInstancePt np) {
        CObjectFactory::RegisterClass(className, np);
    }
};

#define REGISTER_CLASS(class_name)                          \
    class class_name##Register {                            \
    public:                                                 \
        static void* NewInstance() {                        \
            return new class_name();                        \
        }                                                   \
        static Register reg;                                \
    };                                                      \
    Register class_name##Register::reg(                     \
        #class_name, class_name##Register::NewInstance)

class CStudent : public CObject {
public:
    std::string GetClassName() const { return "CStudent"; }
};
REGISTER_CLASS(CStudent);

int main() {
    CObject* obj = static_cast<CObject*>(
        CObjectFactory::CreateObject("CStudent"));
    if (obj != NULL) {
        cout << obj->GetClassName() << endl;
        delete obj;
    }
    return 0;
}

注意：main 所在文件必须 #include 所有需要动态创建的类头文件；否则类与注册类不会被编译进程序，映射表也不会构建。素材的读者补充指出：类须最终在主函数所在项目中编译，仅在外部动态库里编译再链接无效。

22.4 静态多态与动态多态再辨析 #

下表依据《C++中的静态多态和动态多态 - lizhenghn - 博客园.md》整理，按素材的「绑定时间」把两种多态并列。整体概念参见 第14章「多态」。

维度 动态多态 静态多态
绑定时机 运行期 编译期
实现机制 继承 + 虚函数 函数模板具现、实参演绎
接口形态 显式接口，以函数签名（名称、参数、返回类型）为中心 隐式接口，由「有效表达式」构成
类型关系 需共有基类，可处理同一继承体系下的异质对象集合 各类型无需共有基类甚至毫无关系，但不能处理异质对象集合
优点 符合面向对象直觉、接口与实现分离、可处理异质集合 效率高、可被编译器优化、可用偏特化与全特化适配特殊类型、带来泛型设计（STL）
缺点 运行期开销、编译器无法优化虚函数、类层次笨重、修改接口影响整个层次 模板调试困难、编译耗时、代码膨胀、编译器兼容性

两者的相同点是都能实现多态、都能使接口与实现分离：动态多态由基类虚函数定义接口、派生类负责实现；静态多态由模板定义接口、类型参数负责实现。

注意：素材《深入理解多态，为什么说静态成员无多态特性？ - CSDN博客.md》以 Java 为例，本教程只取通用结论——静态成员属于类、静态成员函数无 this 且不能被重写，故不参与动态绑定；C++ 侧表述以《C++知识点 —— 整合（持续更新中） - 逆流而尚 的博客 - CSDN博客.md》与《C++ primer.md》为准。该素材还指出：函数重载参数表不同，本质是多个不同函数，编译期即可确定调用目标，不属于运行期多态。

22.5 MFC 与 Qt：两套图形界面方案 #

MFC（Microsoft Foundation Classes） 是微软提供的 C++ 类库，封装 Windows API 并提供应用程序框架。素材列出的特点：与 Windows 兼容性好、可直接调用系统 API、支持 COM；采用 Document/View 模式与模板，结构相对固定；事件驱动依靠消息循环，消息数以千计、难以分辨。字符串方面，Unicode 需要 TCHAR、字符串前加 T 并改动函数名，CString 基于 char*；国际化要靠字符串表、LoadString 与资源 DLL，过程繁琐；界面依赖 resources 与 Visual Studio 的资源编辑器。文档方面 MSDN 规模庞大（素材称约 10 张 CDROM），链接跳转体验差。发布时依赖客户机上的 MFC42.dll 版本。素材认为，由于 MFC 专为 Windows 设计，在速度与响应时间上优于 Qt。

Qt 是跨平台 C++ GUI 框架，也能做控制台与服务器等非 GUI 程序。它面向对象，借助元对象编译器 moc 与宏支持组件编程；用 signals/slots（SIGNAL() / SLOT() / connect）替代回调，素材认为它比 Java 的 listener 更轻量。Qt 提供 250 多个 C++ 类，覆盖模板 collections、serialization、file、I/O、date/time、正则表达式以及 2D/3D 图形与 OpenGL；不强制使用某种设计模式，用 layout 与 Qt Designer 生成可读代码。QString 天生支持 Unicode，tr() 配合 Qt Linguist（XML）完成国际化；没有 resources 概念；文档约 18 MB，由 Qt Assistant 提供。授权方面，Unix 上 GPL 免费，闭源使用需要授权。支持平台包括 Windows 95/98/NT、Linux、Solaris、SunOS、HP-UX、Digital UNIX、Irix、FreeBSD、BSD/OS、SCO、AIX、OS390、QNX 等。

素材的选型建议是：Windows 桌面程序用「windows 编程 + QT」；Linux 上 Qt 更适合嵌入式界面与服务器程序（涉及多线程、线程池）。

注意：素材对 Qt 的起源给出两种说法——一称 1991 年由 Qt Company 开发，另一称由 Trolltech 于 1994 年左右开发；又提到 2008 年诺基亚收购后转让给 Digia、2014 年 4 月发布 Qt Creator 3.1.0。本教程并列保留这些说法，不作取舍。

22.7 小结 #

  • 接口与实现分离的两条路径是 Pimpl Idiom 与 Object Interface（抽象接口类）；两者都把客户依赖收敛到一份头文件，代价是要显式处理编译器生成的构造函数与拷贝构造函数。
  • 按类名动态创建实例的关键链条是：共同基类 → new → 类名到创建函数的 std::map → 统一的函数指针签名 → 静态对象在 main 之前完成注册；宏 REGISTER_CLASS 用 ## 拼接生成注册类。
  • 动态多态以虚函数在运行期绑定、接口显式；静态多态以模板在编译期具现、接口由有效表达式隐式给出；两者都能实现多态与接口/实现分离。
  • MFC 深度绑定 Windows API 与 Document/View，Qt 跨平台并以 signals/slots、Unicode 字符串与布局管理器见长；选型取决于目标平台。
  • 完整资源与路线见 第六篇 附录F，逐条速记见 第六篇 附录G。

22.8 常见错误与陷阱 #

  • 抽象接口类析构函数未声明为 virtual：素材明确指出这会引发内存泄漏；通过基类指针删除派生类对象时只会调用基类析构函数。参见 第14章「多态」。
  • 误以为 C++ 能在运行时创建「未知的类」：只能按类名字符串创建已编译进程序的类；若 main 所在文件没有包含相应头文件，注册不会发生。
  • 混淆 new/delete 与 new[]/delete[]：数组必须用 delete[] 释放。参见 第10章「动态内存管理」。
  • 忽略 Pimpl 的拷贝语义：编译器自动生成的拷贝构造函数会复制指针，导致两个对象共享同一实现对象并重复释放。
  • 把函数重载当作运行期多态：重载在编译期即可确定调用目标，参数表不同本质上是多个不同函数。
  • 只按「快慢」在 MFC 与 Qt 之间选型：素材给出的速度结论建立在「专为 Windows 设计」这一前提上，存在跨平台需求时应另行权衡。
  • std::vector 下标越界：下标只能用于已存在的元素；[] 越界是未定义行为（undefined behavior）。参见 第20章「标准库与 STL 速览」与 第六篇 附录D 常见坑清单。

元素访问 []、at() [] 越界是未定义行为，at() 越界抛 std::out_of_range
输入输出 >>、getline()、<< 从流读取、按行读取、写入流
与 C 串互操作 c_str()、data()、copy() c_str() 返回以空字符结尾的 C 串，data() 不附加结尾空字符，copy() 复制进调用者已有的 C 字符数组
子串与查找 substr(pos, n)、find() 系列、std::string::npos 取子串、查找；npos 表示未找到
比较 compare()、==、!=、< 等 compare() 返回 0、正值或负值
迭代器 begin()、end() 配合标准库算法遍历
字符串流 istringstream、ostringstream 在字符串与数值之间转换

注意：不要长期保存 char& r = s[2]; 或 char* p = &s[3]; 这类引用（reference）或指针，字符串重新分配后它们即失效；需要边界检查时改用 at()。

B.2 std::vector 常用函数 #

迭代器（iterator）是面向对象版本的指针，用来遍历容器（container）中的元素；std::vector 是动态数组，会自动分配内存。

类别 函数 / 运算符 说明
初始化 std::vector<int> v;、std::vector<int> v(n);、std::vector<int> v(n, value);、拷贝构造、迭代器区间构造 素材列出 5 种初始化形式
元素访问与修改 []、front()、back()、assign()、push_back()、insert()、pop_back()、erase()、clear() 下标只能用于已存在的元素
大小与容量 size()、capacity()、resize(n)、reserve(n)、empty() size() 是元素数，capacity() 是已分配容量，resize(n) 改变元素数，reserve(n) 令容量至少为 n
其他 swap()、比较运算符 交换与整体比较
算法（<algorithm>） sort()、reverse()、copy()、find() 配合迭代器使用
迭代器 begin()、end() 遍历容器中的全部元素
  • std::vector<int> a; a[i] = i; 是错误写法：下标只能获取已存在的元素，不能凭空创建新元素。
  • 容量不足时按 1.5～2 倍重新分配并复制元素，此前取得的迭代器、指针与引用随之失效；大量 push_back() 之前先 reserve()，可避免 2～10 次重新分配。
  • 收缩到合适容量可用 std::vector<int>(ivec).swap(ivec);，释放全部内存可用 std::vector<int>().swap(v);。
  • 陷阱：把 int* b 压入容器后 delete b，再访问 a[0] 会得到无法预计的值。

附录C 文件打开模式与流状态速查表 #

参见 第19章「文件与流」。文件流分为 ofstream（写）、ifstream（读）与 fstream（读写）；打开文件的原型是 void open(const char* filename, openmode mode)。

C.1 打开模式 #

模式标志 含义
ios::in 以读方式打开
ios::out 以写方式打开
ios::ate 打开后定位到文件尾
ios::app 追加模式，所有写入都在文件尾
ios::trunc 若文件已存在则清空内容
ios::binary 以二进制方式打开

多个模式可用按位或运算符 | 组合，例如 ios::out | ios::trunc。三种流的默认组合是：ofstream 为 ios::out | ios::trunc，ifstream 为 ios::in，fstream 为 ios::in | ios::out。一旦显式给 open() 传入模式参数，默认值会被完全改写。

C.2 流状态与常用成员函数 #

函数 含义
bad() 读写过程中出错
fail() 除 bad() 的情形外，格式错误也会置位
eof() 已到达文件尾
good() 以上任一状态为 true 时返回 false
clear() 重置状态标志
is_open() 判断文件是否成功打开
close() 关闭文件；流对象析构时也会自动调用

其余要点：tellg() / tellp() 返回 pos_type 类型的当前位置；seekg() / seekp() 既可接受绝对位置，也可接受「偏移量 + 方向」两个参数，方向取 ios::beg、ios::cur、ios::end，素材建议文本文件只用绝对位置这一原型。二进制读写用 write(buffer, size) 与 read(buffer, size)。缓存同步发生在文件关闭、缓存写满、使用 flush 与 endl、或调用 sync()（返回 int，失败时返回 -1）时。

附录D 常见坑清单 #

以下各条均来自本教程素材中反复出现的问题。遇到异常现象时，先按清单排查，再回到相应章节复习。

  • 悬垂指针与野指针：指针指向的对象已释放或从未初始化，解引用结果不可预计。素材《C++ 指针.md》把空指针、指针的算术运算、指针与数组列为必须掌握的概念。参见 第8章「指针」。
  • 浅拷贝与重复释放：默认拷贝构造函数按成员复制，含指针成员时两个对象指向同一块内存，一个对象析构后另一个再访问即出错。类数据成员有指针、管理资源或需要析构函数释放资源时，应定义拷贝构造函数做深拷贝。参见 第12章「类与对象」。
  • 头文件循环包含：两个头文件互相 #include，配合预处理指令（preprocessor directive）#ifndef / #define / #endif 守卫会造成「类型或宏尚未定义」的报错；排查方法是按预处理展开顺序逐行还原头文件内容，必要时使用前置声明，并把宏定义移到 #include 之前。参见 第18章「预处理与多文件工程」。
  • new / delete 不匹配：new 数据类型[] 分配的数组必须用 delete[] 释放，单个对象用 delete；new / delete 是运算符，malloc / free 是函数调用，两者不要混用。参见 第10章「动态内存管理」。
  • 数组与容器越界：std::vector 的下标只能用于已存在的元素，std::vector<int> a; a[i] = i; 是错误写法；std::string::at() 越界抛 std::out_of_range，而 [] 越界是未定义行为。参见 第20章「标准库与 STL 速览」。
  • 迭代器失效：std::vector 容量不足时按 1.5～2 倍重新分配并复制元素，此前取得的迭代器、指针与引用全部失效；大量 push_back() 前用 reserve() 预留容量。
  • 异常安全：素材提醒异常只用于处理确实可能不正常的情况，构造器与析构器不应使用异常；try 块找不到匹配的 catch 时异常会中止程序执行，必要时用 catch(...) 兜底。参见 第17章「异常处理」。
  • 抽象接口类缺少虚析构：通过基类指针删除派生类对象时只会调用基类析构函数，造成内存泄漏。参见 第14章「多态」。
  • 把函数重载当成运行期多态：重载的参数表不同，本质上是多个不同函数，编译期即可确定调用目标。
