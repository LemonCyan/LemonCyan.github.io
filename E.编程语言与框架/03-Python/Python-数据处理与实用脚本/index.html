一、实用脚本的通用套路 #

日常脚本的需求翻来覆去四类：批量处理文件、按规则分类归档、定时跑一遍、在线回消息。四类长得不一样，骨架是同一个：输入集合 → 逐个遍历 → 判定分类 → 执行动作 → 记录结果。

python
from pathlib import Path

def collect(src: Path):
    return [p for p in src.iterdir() if p.is_file()]

def decide(p: Path):
    ...          # 判定：返回分类键，None 表示跳过

def apply(p: Path, key: str) -> None:
    ...          # 动作：移动、改名、写库

def main(dry_run: bool = True) -> None:
    ok = skip = fail = 0
    for p in collect(Path(r"C:\data\inbox")):
        key = decide(p)
        if key is None:
            skip += 1
            continue
        try:
            if not dry_run:
                apply(p, key)
            ok += 1
        except Exception as e:
            fail += 1
            print(f"失败 {p}: {e}")
    print(f"完成 ok={ok} skip={skip} fail={fail}")
main(dry_run=True)     # 第一版永远先 dry-run

decide 是纯函数，能单独测；apply 只碰副作用，出问题范围清楚；main 只管调度和计数。try 的位置也是刻意的——在 for 里、在 apply 外层，单个文件失败不会炸掉整批。

需求 关键库 本文落点
数值批量计算 numpy 二 ~ 七
文件读写与遍历 pathlib、open 八、九
编码识别 chardet 十
元数据读取 Pillow、exiftool、ffprobe 十三
后台常驻服务 werobot 十四 ~ 十六

三条硬规矩。先 dry-run：批量移动、改名、删除，第一版一律只打印不执行，shutil.move 覆盖同名文件时不会问你。幂等：跑两次和跑一次结果要一样，做法是让输入随动作消失，反面例子是「在文件名前加前缀」，跑三次变成 bak_bak_bak_xxx.jpg。错误隔离：try 包在单个元素层级，不能包在外面整圈。

二、numpy 是什么：数组与向量化 #

numpy 是 Python 科学计算的基础包。它提供多维数组对象、派生对象（掩码数组、矩阵），以及一批对数组做快速操作的例程：数学、逻辑、形状操作、排序、选择、I/O、离散傅里叶变换、基本线性代数、基本统计、随机模拟。核心是 ndarray，它一面封装同类型的多维数组，一面把操作交给编译好的代码执行。

numpy 的价值在向量化——同样一次计算，用 ndarray 比写 Python 循环快，因为循环被下沉到了 C 层。

python
import time
import numpy as np

n = 1_000_000
t0 = time.perf_counter()
total = 0.0
for i in range(n):
    total += i * 0.5
print(f"list 循环: {time.perf_counter() - t0:.4f}s {total:.3e}")

arr = np.arange(n, dtype=np.float64)
t0 = time.perf_counter()
total = (arr * 0.5).sum()
print(f"numpy 向量化: {time.perf_counter() - t0:.4f}s {total:.3e}")

# list 循环: 0.0921s 2.500e+11
# numpy 向量化: 0.0035s 2.500e+11

差二十多倍，倍数随机器浮动，量级稳定。关键在「循环没有消失，只是换了地方」：arr * 0.5 背后没有 Python 层的 for，numpy 拿到一块连续内存，在 C 里按 dtype 的专用循环做批量浮点乘，一次算一片。全程没有 PyObject 的装箱拆箱，没有每轮循环的字节码分发，没有引用计数增减。Python 循环慢就慢在这些固定开销。.sum() 同理是 C 里的归约；用内建 sum(arr) 会把 ndarray 当迭代器，一个个取出 Python 标量再加，向量化的收益当场清零。

向量化有三个前提，缺一个就退化：内存连续（转置后不连续，某些操作会先偷偷拷一份）；同一 dtype（int 和 float 混算要走类型提升，多一次分配）；全程不碰 Python 对象。最后一条的反例是 np.array([{"v": i} for i in range(1000)], dtype=object)：数组里装的还是 PyObject 指针，numpy 只能逐个回调 Python，比 list 还慢。

语义 Python 循环写法 numpy 向量化写法
逐元素加一 [x + 1 for x in a] a + 1
条件筛选 [x for x in a if x > 0] a[a > 0]
整体求和 sum(a) a.sum()
按列求和 双层循环 a.sum(axis=0)
向量点积 手写累加 np.dot(a, b)
矩阵乘法 三层嵌套 np.dot(A, B)

ndarray 和 Python 内建序列的差别在四处：数组大小固定（list 能动态增长，改尺寸会新建数组）；元素必同类型，所以每个元素占的内存一样大，维度叫 axes、维数叫 rank；大量数据上的数学计算更快、代码更短；越来越多的科学计算库吃 Python 序列，但内部第一步还是先转成 ndarray，输出也是 ndarray。想高效用这些库，只懂 list 和 tuple 不够。

三、ndarray 的创建与属性 #

属性 含义 例子
ndim 维数，也叫 rank 二维数组为 2
shape 各维大小，tuple n 行 m 列为 (n, m)
size 元素总数 (3, 4) 的数组为 12
dtype 每个元素的类型 int32、float64、complex128
itemsize 单个元素占的字节数 float64 为 8
data 指向数据内存的缓冲对象 少直接碰 
python
import numpy as np
a = np.array([1, 2, 3, 4])
print(a, a.dtype, a.shape, a.ndim, a.size, a.itemsize)
# [1 2 3 4] int32 (4,) 1 4 4
b = np.array([1.2, 3.4, 5.6, 5])
print(b, b.dtype)                    # [1.2 3.4 5.6 5. ] float64
c = np.array([[1, 2], [3, 4]], dtype=complex)   # 指定 dtype，整数转复数
print(c, c.dtype)                    # [[1.+0.j 2.+0.j] [3.+0.j 4.+0.j]] complex128

元素类型由传入对象的类型推出来。全是 int 就是 int32（跟着平台走），混了浮点就是 float64。要确定的类型就显式写 dtype=。数组往往「大小已知、值待填」，这几个函数管这件事，默认 dtype 是 float64：

python
print(np.zeros((3, 4)))            # 全 0，先占位再逐块填
print(np.empty((2, 3)))            # 不初始化，值由内存里原来的内容决定
print(np.ones((2, 3, 4), dtype=np.int16).shape)   # (2, 3, 4)
print(np.arange(10, 30, 5))        # [10 15 20 25]，行为类似 range
print(np.arange(0, 2, 0.3))        # [0.  0.3 0.6 0.9 1.2 1.5 1.8]
print(np.linspace(0, 2, 9))        # [0. 0.25 0.5 0.75 1. 1.25 1.5 1.75 2.]

arange(start, stop, step) 给步长、个数算出来；linspace(start, stop, num) 给个数、步长算出来。画函数曲线用后者：x = np.linspace(0, 2 * np.pi, 100)，再 f = np.sin(x)。empty 快是因为不做赋值，直接从内存池切一块；别读它的初始值，那不是 0，是上一任租客留下的东西。

按坐标算值的创建方式是 fromfunction，f 收到的不是标量而是索引网格数组，所以整块运算。与其循环填，不如把「第 i 行第 j 列该是什么」写成公式：

python
def f(x, y):
    return 10 * x + y

print(np.fromfunction(f, (5, 4), dtype=int))
# [[ 0  1  2  3] [10 11 12 13] [20 21 22 23] [30 31 32 33] [40 41 42 43]]

四、索引、切片与变形 #

索引和切片跟 list 一个路子，多了一维逗号语法。

python
a = np.arange(10) ** 3
print(a[2], a[2:5], a[0:6:-2], a[::-1])
# 8 / [8 27 64] / []（步长为负但起点在终点前）/ [729 ... 0]
b = np.fromfunction(lambda x, y: 10 * x + y, (5, 4), dtype=int)
print(b[2:3])      # [[20 21 22 23]]     切片，保留二维
print(b[2])        # [20 21 22 23]       取下标，退化成一维
print(b[0:5, 3])   # [ 3 13 23 33 43]    第 3 列
print(b[:, 1])     # [ 1 11 21 31 41]    所有行的第 1 列
print(b[-1])       # [40 41 42 43]       最后一行
for row in b:                              # 迭代默认以第一维为单位
    print(row)
for ele in b.flat:                         # 当成一个大的一维数组
    print(ele)
print(np.arange(12).reshape(3, 4))              # 行优先填充
print(np.arange(12).reshape(3, -1).shape)       # (3, 4)，-1 表示这一维自己算
temp = np.zeros(shape=(10, 20))
print(len(temp), temp.size)                     # 10 200，len 只给第一维长度
x = np.array([[[0], [1], [2]]])
print(x.shape, np.squeeze(x).shape, np.squeeze(x, axis=(2,)).shape)
# (1, 3, 1) (3,) (1, 3)
y = np.array([1, 2])
print(np.expand_dims(y, axis=0).shape, np.expand_dims(y, axis=1).shape)
# (1, 2) (2, 1)

b[2:3] 形状 (1, 4)，b[2] 形状 (4,)。批量脚本里一行数据变成一维数组、形状对不上，就是这么来的。内存连续时 reshape 返回视图不拷数据，不连续时拷一份，改完别假设原来的变量还指向同一块内存。squeeze() 不带参数删掉所有长度 1 的维，带 axis 只删指定的，那一维必须真的是 1。

秩为 1 的数组、行向量、列向量的区别值得单独记。一维数组 (5,) 的转置还是自己，乘出来是标量，形状信息丢干净；要做矩阵运算，一开始就用 (5, 1) 或 (1, 5) 把维度说清楚：

python
a = np.random.randn(5)
print(a.shape, a.T.shape)                 # (5,) (5,)   转置对一维数组不起作用
print(np.dot(a, a).shape)                 # ()          乘出来是标量
a1 = np.random.randn(5, 1)                # 列向量
# np.dot(a1, a1)  报错 shapes (5,1) and (5,1) not aligned
print(np.dot(a1, a1.T).shape)             # (5, 5)
a2 = np.random.randn(1, 5)                # 行向量
print(np.dot(a2, a2.T).shape)             # (1, 1)
print(np.array([1, 2, 3, 4]).reshape(4, 1).shape)   # (4, 1)

五、广播机制 #

两个形状不同的数组能不能直接算，由两条规则定：从右往左逐维比，相等就继续；不等时其中一个是 1 就沿那维撑开复制，都不是 1 就报错。形状少的数组左边自动补 1。

python
a = np.arange(6).reshape(2, 3)
print(a + 10)                        # 标量作用于每个元素
print(a + np.array([100, 200, 300])) # (2,3) 与 (3,)，补成 (1,3) 再撑成 (2,3)
print(a + np.array([[10], [20]]))    # (2,3) 与 (2,1)，沿列方向撑开
np.ones((2, 3)) + np.ones((4,))
# ValueError: operands could not be broadcast together with shapes (2,3) (4,)
data = np.arange(12, dtype=float).reshape(4, 3)
centered = data - data.mean(axis=0)      # (4,3) - (3,)，按列减，标准化的第一步
rows, cols = np.arange(3).reshape(3, 1), np.arange(4).reshape(1, 4)
print((rows * cols).shape)               # (3, 4)，外积表

广播不真的复制内存，numpy 只改 stride，把同一块数据重复读出来，所以不会额外分配三份。陷阱是形状互补但不合本意时不报错，只是算错：(3,1) 和 (3,) 得到 (3,3)，你以为逐行相减，其实是外积。看到结果形状涨了，先查广播。

六、常用数学与统计函数 #

基础算术运算符都作用于数组，返回新数组。* 是元素乘法，矩阵乘法另外算：

python
a = np.array([20, 30, 40, 40])
b = np.arange(4)
print(a - b)           # [20 29 38 37]
print(b ** 2)          # [0 1 4 9]
print(10 * np.sin(a))  # [ 9.12945251 -9.88031624  7.4511316   7.4511316 ]
print(a < 35)          # [ True  True False False]
A = np.array([[1, 1], [0, 1]])
B = np.array([[2, 0], [3, 4]])
print(A * B)           # [[2 0] [0 4]]    对应元素相乘
print(np.dot(A, B))    # [[5 4] [3 4]]    矩阵乘法
print(A @ B)           # 同上，Python 3.5+ 的运算符写法
c = np.ones(3, dtype=np.int32) * np.linspace(0, np.pi, 3)   # 类型提升
print(c, c.dtype)      # [0. 1.57079633 3.14159265] float64

每次提升都可能多一次内存分配和拷贝，大量数据做运算提前统一到 float64 更稳。

函数 作用 备注
np.sin / np.cos / np.tan 三角函数，参数是弧度 角度先乘 np.pi/180
np.exp e 的幂 大数容易出 inf
np.log / np.log10 自然对数 / 以 10 为底 np.log10(10) 得 1.0
np.nan_to_num nan 换 0、inf 换有限数 洗数据必备
a.sum() / a.min() / a.max() 求和 / 最小 / 最大 axis 指定维度
a.mean() / a.std() 均值 / 标准差 有 nan 用 nanmean
a.cumsum() / a.argmax() 累加 / 最大值下标 长度不变 / 排序类脚本常用
np.median(a) 中位数 抗离群值
np.linalg.norm(x) / np.dot(A, B) 范数 / 矩阵乘法 范数结果是标量

归约默认作用于整个数组，指定 axis 才能分维。范数单独说：linalg 是 linear + algebra，norm 是范数，结果是一个标量，原型是 norm(x, ord=None, axis=None, keepdims=False)，默认的 2 范数是「每项平方求和再开方」：

python
np.random.seed(42)                  # 要复现就固定种子
a = np.random.random((2, 3))
print(a.sum(), a.min(), a.max())    # 全部元素
print(a.sum(axis=0), a.sum(axis=1)) # 按列 / 按行求和
print(a.cumsum(axis=1))             # 按行累加
print(np.linalg.norm(np.array([3, 4])))     # 5.0
print(np.linalg.norm(np.array([3, 4, 5])))  # 7.0710678118654755
m = np.array([[3, 4], [6, 8]])
print(np.linalg.norm(m))            # 全元素平方和开方
print(np.linalg.norm(m, axis=1))    # [ 5. 10.]，按行
print(np.log10(10), np.log(np.e))   # 1.0 1.0
np.set_printoptions(precision=8)
x = np.array([np.inf, -np.inf, np.nan, -128, 128])
print(np.nan_to_num(x))             # inf 换成 float64 最大值，nan 换成 0

np.nan 不是「非常小的数字」，它是「不是一个数」，任何比较都为假，包括 np.nan == np.nan，判断得用 np.isnan。正负无穷是 np.inf 和 -np.inf，有限数替身是 float64 的最大值。正态分布的三个参数：loc 是均值，对应分布中心；scale 是标准差，对应宽度，越大越矮胖；size 是维数。random 标准库那几个常和 numpy 混用，shuffle 原地改、返回 None，写成 p = random.shuffle(q) 会把 p 变成 None：

python
print(np.random.randn(2, 4))     # 标准正态
print(np.random.rand(2, 4))      # 均匀分布 [0,1)

import random
print(random.uniform(10, 20))    # 浮点数，a > b 时得 a >= n >= b
print(random.randint(12, 20))    # 整数，闭区间
print(random.randint(20, 20))    # 永远是 20；randint(20, 10) 报错，下限必须小于上限
random.randrange(10, 100, 2)     # 从 [10, 12, ..., 98] 里取
print(random.choice("学习Python"), random.choice(["JGood", "is", "a"]))
print(random.choice(("Tuple", "List", "Dict")))
p = ["Python", "is", "powerful", "simple", "and so on..."]
random.shuffle(p)
print(p)   # ['powerful', 'simple', 'is', 'Python', 'and so on...']

七、numpy 与原生 list 的差别 #

维度 numpy ndarray Python list
元素类型 必须全同 什么都能放
内存布局 连续，每元素 itemsize 字节 存的是对象指针
长度 固定，改尺寸会新建 可动态增长
逐元素运算 运算符直连，C 层循环 写循环或推导式
一千万次浮点乘 毫秒级 秒级
取子集 布尔掩码 a[a > 0] 推导式 [x for x in a if x > 0]
多维支持 原生，axis 参数齐全 靠嵌套模拟
随机访问单个元素 慢，每次装箱成 Python 标量 快
追加元素 不划算，append 会重建 append 摊还 O(1)
典型用途 整块数值计算 异构容器、小数据、频繁增删

内存差在哪，算一笔就清楚。一千个 int32 数组占 4 KB，连续一块。同样一千个整数的 list，本身 8 KB 指针，加上每个 int 对象约 28 字节，总共 36 KB 上下。数据一大，这个倍数就是能不能装进内存的区别。ndarray 的切片是视图，list 的切片是拷贝；标量取出的成本则反过来：

python
import time

a = np.arange(5)
v = a[1:4]
v[0] = 99
print(a)          # [ 0 99  2  3  4]  原数组被改了

lst = [0, 1, 2, 3, 4]
s = lst[1:4]
s[0] = 99
print(lst)        # [0, 1, 2, 3, 4]   还是原样

arr = np.arange(1_000_000)
t0 = time.perf_counter()
for i in range(0, 1_000_000, 100):
    _ = arr[i]
print(f"ndarray 下标 {time.perf_counter() - t0:.4f}s")   # 比 list 慢，每次都要装箱

要独立副本显式写 .copy()，反过来说切片传参不复制数据。ndarray 取单个元素要把 C 里的值包成 Python 对象，比 list 直接取指针慢，所以「在 numpy 上写 for 循环逐个取」是最差的组合：既丢了向量化，又付了装箱成本。选型一句话：整块数值计算、多维、需要 axis，上 numpy；异构容器、频繁增删、数据量小，用 list。别为了「看起来专业」把十个字符串塞进 ndarray。

八、读写文件：文本与二进制 #

读写文件三件事定生死：编码、换行、模式。

python
from pathlib import Path

text = Path("notes.txt").read_text(encoding="utf-8")   # 显式写 encoding

with open("out.txt", "a", encoding="utf-8", newline="\n") as f:   # 追加
    f.write("第一行\n")

with open("big.csv", encoding="utf-8") as f:           # 逐行读大文件
    for i, line in enumerate(f):
        if i > 10:
            break
        print(line.rstrip("\n"))

with open("miui.cpp", "rb") as f:                      # 二进制读，拿到 bytes
    data = f.read()
print(type(data), len(data))   # <class 'bytes'> 字节数，不是字符数

Windows 上 open() 不写 encoding 会用系统默认（简体中文下常是 gbk），同一个文件在 Linux 上读出来就是乱码。写文件时加 newline="\n" 能压住 \r\n 的自动转换，让文件在任何平台都一样。

模式 含义 文件不存在 文件已存在
r 只读 报错 从头读
w 只写 新建 清空后写
a 追加 新建 末尾接着写
x 排他写 新建 报错
r+ 读写 报错 不清空

批量改名分「算」和「做」两段。plan 只算不干，能反复跑、能断言、能出报表；run 只做一件事，出问题一眼看得出：

python
pattern = re.compile(r"^IMG_(\d+)\.jpg$", re.IGNORECASE)

def plan(root: Path):
    """只算不干，返回 (源, 目标) 列表"""
    jobs = []
    for p in root.iterdir():
        m = pattern.match(p.name) if p.is_file() else None
        if not m:
            continue
        target = p.with_name(f"photo_{int(m.group(1)):05d}.jpg")
        if target.exists():
            print(f"跳过，目标已存在: {target.name}")
            continue
        jobs.append((p, target))
    return jobs

def run(jobs, dry_run=True):
    for src, dst in jobs:
        if dry_run:
            print(f"[dry] {src.name} -> {dst.name}")
        else:
            src.rename(dst)
            print(f"[ok]  {src.name} -> {dst.name}")

建目录用 mkdir(parents=True, exist_ok=True) 一次到底：parents=True 建整条路径，exist_ok=True 让「已存在」不报错，顺手把竞态条件也绕过去。(root / "2024" / "08").mkdir(parents=True, exist_ok=True) 一行就够。

def read_text_auto(path: str) -> str:
    with open(path, "rb") as f:
        raw = f.read()
    enc = chardet.detect(raw).get("encoding") or "utf-8"
    if enc in {"GB2312", "GBK"}:                # 升到超集更安全
        enc = "GB18030"
    try:
        return raw.decode(enc)
    except (UnicodeDecodeError, LookupError):   # 编码名可能不认识
        return raw.decode(enc, errors="replace")

四个边界要记住。confidence 低于 0.8 的结果当参考不当结论。中文识别里 GB2312 和 GBK 分不清是常态，按 GB18030 解码能覆盖超集。短文本判不准，十几个中文字节什么编码都凑得出来，那就看 BOM：UTF-8 开头是 b'\xef\xbb\xbf'，UTF-16 是 b'\xff\xfe' 或 b'\xfe\xff'。编码检测是对整块 bytes 做统计，截断位置落在多字节字符中间时结论会偏，所以切大文件必须切在字符边界上。

十一、按规则分类归档 #

分类归档的本质是把「判定」和「搬运」拆开。判定规则有六种常见形态：

python
import hashlib
import shutil
from datetime import datetime

IMAGE_EXT = {".jpg", ".jpeg", ".png", ".heic", ".webp"}
VIDEO_EXT = {".mp4", ".mov", ".avi", ".mkv"}
DOC_EXT = {".pdf", ".docx", ".xlsx", ".md", ".txt"}

def by_extension(p: Path):
    """按后缀分大类，不认识的返回 None 表示别动"""
    ext = p.suffix.lower()
    if ext in IMAGE_EXT: return "image"
    if ext in VIDEO_EXT: return "video"
    return "doc" if ext in DOC_EXT else None

def by_mtime(p: Path) -> str:
    dt = datetime.fromtimestamp(p.stat().st_mtime)
    return f"{dt.year:04d}/{dt.month:02d}"

def by_size(p: Path) -> str:
    mb = p.stat().st_size / 1024 / 1024
    return "small" if mb < 1 else ("medium" if mb < 100 else "large")

def by_hash(p: Path) -> str:
    """内容前缀分桶，内容相同必然同桶"""
    return hashlib.md5(p.read_bytes()).hexdigest()[:2]

def move_to(src: Path, dest_root: Path, bucket: str) -> Path:
    """重名加序号。shutil.move 遇到同名目标会直接覆盖，两种平台都不问你"""
    dest_dir = dest_root / bucket
    dest_dir.mkdir(parents=True, exist_ok=True)
    target = dest_dir / src.name
    if target.exists():
        stem, suffix, i = src.stem, src.suffix, 1
        while target.exists():
            target = dest_dir / f"{stem}_{i}{suffix}"
            i += 1
    shutil.move(str(src), str(target))
    return target

def archive(src_dir: Path, dest_root: Path, rule, dry_run: bool = True) -> None:
    moved = skipped = failed = 0
    for p in sorted(src_dir.iterdir()):
        if not p.is_file():
            continue
        bucket = rule(p)
        if bucket is None:
            skipped += 1
            continue
        try:
            if dry_run:
                print(f"[dry] {p.name} -> {bucket}/")
            else:
                print(f"[ok]  {p.name} -> {move_to(p, dest_root, bucket).parent.name}/")
            moved += 1
        except Exception as e:
            failed += 1
            print(f"[err] {p.name}: {e}")
    print(f"完成 moved={moved} skipped={skipped} failed={failed}")

判定返回 None 就是「不认识，别动」，这个约定贯彻到底：别在判定里顺手执行动作。

规则 依据 适用 坑
后缀 p.suffix 图片/视频/文档分家 后缀能改，不可信
时间 stat().st_mtime 归档日志、下载文件 复制会刷新 mtime
大小 stat().st_size 分档清理 阈值要按业务调
内容哈希 hashlib 去重、分桶 全量读盘，慢
名称正则 re 有命名规范的批量文件 命名不规范就漏
元数据 EXIF / 文档属性 照片、音视频 文件可能没有元数据

最后一条最贴近「内容真相」。一张照片后缀可能是 .jpg，拍摄时间却写在 EXIF 里，跟文件系统时间能差好几年。

十二、实例：按照片时间戳分类 #

需求很具体：一个目录里几千张照片和几个视频，按拍摄年份和月份分到 年/月 目录下。难点不在移动，在时间从哪来。候选来源五个，可靠性从高到低：

来源 拿到什么 可靠性 依赖
EXIF DateTimeOriginal 相机记录的拍摄瞬间 最高 Pillow
ExifTool 多标签 拍摄、创建、修改时间齐全 高 exiftool

文件名里的日期 命名时写入的日期 中 无
文件系统创建时间 落盘时间 最低 无

按顺序逐个试，第一个拿到答案的就用，全拿不到就跳过。这就是兜底链：

目标目录和源目录是同一个。第一轮移走的文件进了 2024/08/，第二轮 iterdir() 只看顶层，不会再扫到它们，天然幂等。源和目标是同级目录时，就得先排除子目录，或者先把文件列表算完再动手。从文件名兜底，认两种常见日期写法，顺手校验年月合法性：

python
def extract_date_from_filename(image_path: Path):
    m = re.search(r"(19|20)\d{2}[-_]?(\d{2})[-_]?(\d{2})", image_path.name)
    if not m:
        return None
    year, month, day = m.group(0)[:4], m.group(2), m.group(3)
    if not (1 <= int(month) <= 12 and 1 <= int(day) <= 31):
        return None
    return f"{year}-{month}-{day}"

def get_file_creation_time(image_path: Path):
    try:
        return time.strftime("%Y-%m-%d", time.localtime(image_path.stat().st_ctime))
    except Exception as e:
        print(f"文件系统时间读取失败 {image_path}: {e}")
        return None

不带年份校验的 \d{8} 会把 DSC12345678.jpg 里的 12345678 当成 1234 年。Windows 上 st_ctime 是创建时间，Linux 上它是 inode 变更时间，含义不同；要跨平台一致就用 st_mtime，代价是复制文件会刷新它。HEIC 和 MP4 常常没有 EXIF，Pillow 打开 HEIC 会直接抛异常（原生不支持，要装 pillow-heif），所以 mp4/heic 走 ffprobe 才能拿到时间。

真实数据上的命中分布大致是：EXIF 约 70%（手机原图、相机原图），ExifTool 约 15%（EXIF 在但 Pillow 读不到的格式），ffprobe 约 10%（视频），文件名约 3%（截图、下载图），文件系统约 2%（彻底没元数据的）。先跑 dry-run 把这张分布打出来，再决定阈值和例外规则。

十三、读取 EXIF 时间信息 #

EXIF 是图片里的元数据，记着拍摄时间、相机型号、光圈快门、GPS。读取有三条路。第一条，Pillow 直接读，零额外依赖：

python
from PIL import Image, ExifTags

def get_image_time_from_exif(image_path: Path):
    """从 EXIF 里取 DateTimeOriginal，返回 'YYYY-MM-DD'"""
    try:
        with Image.open(image_path) as image:      # 必须 with，否则句柄不释放
            exif_data = image._getexif()
        if not exif_data:
            return None
        for tag, value in exif_data.items():
            if ExifTags.TAGS.get(tag, tag) == "DateTimeOriginal":
                # 格式是 '2024:08:15 10:30:00'，取前 10 位再换分隔符
                return value[:10].replace(":", "-")
    except Exception as e:
        print(f"EXIF 读取失败 {image_path}: {e}")
    return None

_getexif() 返回「标签数字 → 值」的 dict，要先用 ExifTags.TAGS 把数字翻译成名字才能按名匹配。DateTimeOriginal 的格式是 2024:08:15 10:30:00，日期部分用冒号，转成 2024-08-15 才能拼路径。Image.open 不用 with 的话文件句柄不释放，Windows 上后续 shutil.move 会报「文件被占用」。

标签 含义 典型值 用途
DateTimeOriginal 原始拍摄时间 2024:08:15 10:30:00 首选，最准
DateTimeDigitized 数字化时间 同上 扫描件常用
DateTime 文件修改时间 同上 兜底
OffsetTime 时区偏移 +08:00 跨时区校正
SubsecTimeOriginal 秒的小数部分 123 连拍排序
Make / Model 相机厂商 / 型号 Apple / iPhone 15 分设备归档
Orientation 旋转方向 1 ~ 8 显示前要转正

DateTimeOriginal 不带时区。跨时区拍的照片按当地钟走，只有 OffsetTime 存在时才换算得回去。第二条，ExifTool 覆盖面广得多，视频容器格式和 RAW 都认。它是独立可执行文件，不是纯 Python 包，先落地一份再指路径 set EXIFTOOL_PATH=C:\tools\exiftool-13.04_64\exiftool.exe。第三条，ffprobe 读视频，FFmpeg 套件自带的：

python
import subprocess
import exiftool

def get_image_time_with_exiftool(image_path: Path):
    tags = ["EXIF:DateTimeOriginal", "EXIF:CreateDate", "QuickTime:CreateDate"]
    try:
        with exiftool.ExifToolHelper() as et:
            metadata = et.get_metadata(str(image_path))[0]
        for tag in tags:
            if tag in metadata:
                return str(metadata[tag])[:10].replace(":", "-")
    except Exception as e:
        print(f"ExifTool 读取失败 {image_path}: {e}")
    return None

def get_media_creation_time_with_ffprobe(media_path: Path):
    command = [
        "ffprobe", "-v", "error", "-select_streams", "v:0",
        "-show_entries", "stream_tags=creation_time",
        "-of", "default=noprint_wrappers=1:nokey=1", str(media_path),
    ]
    try:
        output = subprocess.check_output(
            command, stderr=subprocess.DEVNULL, timeout=15
        ).decode("utf-8", errors="replace").strip()
    except Exception as e:
        print(f"ffprobe 读取失败 {media_path}: {e}")
        return None
    return output[:10] if output else None

初始化 ExifTool 进程很贵（起一个子进程），批量处理时放在循环外面；上面写法每次调用建一次，适合零散调用，几千个文件要改成整批共用一次会话。ffprobe 的参数逐个说：-v error 只留错误信息，-select_streams v:0 只看第一条视频流，-show_entries stream_tags=creation_time 只取这一个字段，-of default=noprint_wrappers=1:nokey=1 让输出只有值、没有 key= 前缀和段落包装。少了最后这个参数，拿到的是 creation_time=2024-08-15T...，[:10] 切出来就是 creation_t。timeout=15 必须给：损坏的视频会让 ffprobe 卡住不返回，脚本就停在那了。creation_time 常是 UTC（结尾带 Z），EXIF 是本地时间，两者混在一张时间轴上对比会差 8 小时，归档到月份边界附近就可能分错月。 读一批字段的实用写法，标签号记不住就反查，36867 就是 DateTimeOriginal：

def read_exif_summary(image_path: Path) -> dict:

        response = requests.get(url, headers=HEADERS, timeout=10)
        if response.status_code != 200:
            return f"请求失败，状态码: {response.status_code}"
        soup = BeautifulSoup(response.content, "html.parser")
        for block in soup.find_all(class_="container"):
            for a in block.find_all("a", href=True):
                if not a["href"].startswith("https://quarkzy.com/"):
                    continue
                sub = requests.get(a["href"], headers=HEADERS, timeout=10)
                if sub.status_code != 200:
                    continue
                for b in BeautifulSoup(sub.content, "html.parser").find_all("a", href=True):
                    if b["href"].startswith("https://pan.quark"):
                        result += b["href"] + "\n"
    except Exception as e:
        result = f"请求错误：{type(e).__name__}"
    return result

@robot.handler
def weChatReturn(messages):
    """统一入口：按前缀分发"""
    msg = messages.content.strip()
    if msg.startswith("夸克"):
        keyword = msg[len("夸克"):].strip()      # 切掉前缀，留关键词
        if not keyword:
            return "用法：夸克 关键词"
        found = getUrl("https://quarkzy.com/?q=" + keyword)
        if not found.strip():
            return f"没有找到「{keyword}」的资源"
        return found
    return generate_response(msg)

if __name__ == "__main__":
    robot.run()

分流有两个细节。一是前缀长度：中文前缀按字符切，msg[len("夸克"):] 让长度自己算，改前缀不用改两处；写死 msg[3:] 切掉的是「夸克+一个空格」，用户不打空格就丢第一个字。二是空结果要有人话：搜索没找到时返回空串，微信那边收到空消息会报错，用户也一脸茫然。上面三种情况都单独返回了。返回值决定微信收到什么，返回 str 是文本消息；要回图片、图文卡片得用 werobot.reply 里的对象，第一个参数 message 用来取发送方和接收方，不能省：

python
from werobot.reply import TextReply, ImageReply

@robot.handler
def echo(message):
    if message.type == "text":
        return TextReply(message=message, content="收到文字")
    if message.type == "image":
        return ImageReply(message=message, media_id="your_media_id")
    return TextReply(message=message, content="暂不支持这类消息")

@robot.handler
def on_event(message):
    if message.type != "event":
        return None
    if message.event == "subscribe":
        return "欢迎关注，回复「夸克 关键词」查资源。"
    if message.event == "unsubscribe":
        print(f"取关: {message.source}")
    return None

message.type 还能是 voice、video、shortvideo、location、link 和 event，event 里含关注、取关、扫码等动作，做欢迎语就靠它。handler 注册多个时按注册顺序匹配，先命中的先返回：针对性强的、带前缀的放前面，兜底的写 return None 表示「我不处理，交给下一个」。公众号后台的服务器配置里必须填公网地址，微信会发一个 GET 校验，werobot 自动应答；本地调试用内网穿透把 80 端口暴露出去，微信只认 80/443 的域名，不认 IP。

十六、定时任务与常驻运行 #

一次性脚本和常驻服务的差别，全在「进程活着干什么」。最轻的定时方式是脚本里自己转圈，关键是 sleep 要减去本轮耗时。sleep(seconds) 和 sleep(seconds - cost) 的区别在长跑里会显现：每轮耗时 3 秒、周期 300 秒，用前者实际 303 秒一轮，跑一天偏出二十多分钟。

python
import time
import threading
import traceback
from datetime import datetime, timedelta

def job() -> None:
    print(f"[{datetime.now():%Y-%m-%d %H:%M:%S}] 开始")

def loop_every(seconds: int) -> None:
    while True:
        start = time.perf_counter()
        try:
            job()
        except Exception:
            traceback.print_exc()          # 异常吞掉但要留痕
        cost = time.perf_counter() - start
        time.sleep(max(0.0, seconds - cost))

def next_run_at(hour: int, minute: int = 0) -> datetime:
    now = datetime.now()
    target = now.replace(hour=hour, minute=minute, second=0, microsecond=0)
    return target if target > now else target + timedelta(days=1)

def loop_daily(hour: int) -> None:
    while True:
        target = next_run_at(hour)
        time.sleep(max(0.0, (target - datetime.now()).total_seconds()))
        try:
            job()
        except Exception:
            traceback.print_exc()

def start_timer(seconds: int) -> None:
    """常驻服务会阻塞，定时器放后台线程；daemon 让它跟着主进程退出"""
    threading.Thread(target=loop_every, args=(seconds,), daemon=True).start()

用 schedule 语义更清楚，但它一样是单进程轮询，机器重启就没了。生产级定时交给操作系统，脚本只负责「跑一次」：

python
import schedule

schedule.every(10).minutes.do(job)
schedule.every().day.at("02:00").do(job)
schedule.every().monday.at("09:00").do(job)

while True:
    schedule.run_pending()
    time.sleep(1)

bash
# crontab -e，每天凌晨 2 点跑一次
0 2 * * * /usr/bin/python3 /opt/scripts/archive.py >> /var/log/archive.log 2>&1

常驻服务那边不同，它阻塞在自己的事件循环里，robot.run() 后面接的代码不会执行。要同时跑定时任务，就在另一个线程起定时器，然后 start_timer(3600) 加 robot.run()：主线程跑服务，后台线程跑定时。

十七、脚本的日志与容错 #

print 能调试，上生产换 logging。区别在分级、时间戳、落地、能一键关掉。用 %s 占位而不是 f-string，因为占位参数是延迟格式化的：日志级别没开，字符串拼接就不发生，循环里打日志差别不小。

python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)-7s %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
    handlers=[
        logging.FileHandler("archive.log", encoding="utf-8"),
        logging.StreamHandler(),
    ],
)

log = logging.getLogger(__name__)
log.info("开始处理")
log.error("移动失败: %s", path)
级别 用在哪儿 例子
DEBUG 每条明细，默认关掉 读取 EXIF 失败，试下一个
INFO 每批一行，正常流程节点 完成 320 个，跳过 5 个
WARNING 单条异常但已兜底 无时间信息，跳过 DSC001.jpg
ERROR 需要人看一眼的失败 目标目录不可写: D:\photos
CRITICAL 整批都跑不下去 源目录不存在

容错分三层，一层都不能少。单文件层把 try 包在最内层的动作上，PermissionError 单独接出来有意义：Windows 上文件被预览窗口或同步盘占了就是它，重试或跳过都行，不值得当错误上报。整批层让批与批之间互相隔离，log.exception 在 ERROR 级别下附完整堆栈，比 log.error 更适合放在 except 里。进程层让进程退出而不是僵住，同时留下可定位的现场，sys.exit(main()) 把返回值变成退出码，0 成功、非 0 失败，被 cron 或任务计划调度时上层能据此告警，130 是 Ctrl+C 的惯例值：

python
import sys

for p in files:                      # 第一层：单个文件
    try:
        process(p)
    except PermissionError as e:
        log.warning("被占用，跳过 %s: %s", p.name, e)
    except Exception as e:
        log.error("处理失败 %s: %s", p.name, e)

for batch in batches:                # 第二层：批与批之间
    try:
        run_batch(batch)
    except Exception:
        log.exception("批 %s 失败，继续下一批", batch.id)

def main() -> int:                   # 第三层：进程
    try:
        run()
    except KeyboardInterrupt:
        log.warning("用户中断")
        return 130
    except Exception:
        log.exception("未捕获异常，退出")
        return 1
    return 0

sys.exit(main())

几条通用的坑：except: 不写类型会连 KeyboardInterrupt 和 SystemExit 一起吞，Ctrl+C 都停不下来，至少写 except Exception:；异常信息别直接拼绝对路径回给用户，会漏目录结构；重试要退避，三次都间隔 1 秒的话网络抖动照样全挂，改成 1 秒、3 秒、9 秒；文件操作失败后重试前先 sleep(0.5)，句柄释放有延迟。

十八、易错点速查 #

现象 原因 正解
算得比 list 还慢 在 ndarray 上写 for 循环 改向量化表达式，整块算
sum(arr) 反而慢 把 ndarray 当迭代器取标量 用 arr.sum()
结果形状突然涨了 广播把 (3,1) 和 (3,) 撑成 (3,3) 打印 shape 再决定是否 reshape
dtype=object 巨慢 数组里装 Python 对象，C 层退化 数值就用数值 dtype
改了切片，原数组也变了 ndarray 切片是视图 要独立副本就 .copy()
a.T 对一维数组没用 (5,) 的转置还是 (5,) 用 (5,1) 或 reshape
读文本出乱码 没写 encoding，用了系统默认 一律 encoding="utf-8"
w 模式清空了文件 忘了 w 会截断 追加用 a，防覆盖用 x
chardet 报错 LookupError 返回了 Python 不认识的编码名 except (UnicodeDecodeError, LookupError)
Image.open 后移不动文件 句柄没释放 用 with Image.open(...)
HEIC 打不开 Pillow 原生不支持 装 pillow-heif，或用 ffprobe
EXIF 时间是 0 点 只取了 DateTime，不是 DateTimeOriginal 按 Original → Digitized → DateTime 顺序
ffprobe 输出带 creation_time= 少了 -of 参数 加 nokey=1:noprint_wrappers=1
shutil.move 覆盖了文件 同名目标不问直接盖 搬之前查 target.exists()
批量操作跑两遍出双份 脚本不幂等 让输入随动作消失，或加状态标记
服务本机能连、外网不通 HOST 写了 127.0.0.1 改 0.0.0.0

最后一条经验：脚本上线前先拿一百个文件试，别拿全量。一百个能暴露九成的问题——命名不规范的、没有元数据的、被占用的、路径带空格的、文件名超长的。剩下那一成才是真意外。
