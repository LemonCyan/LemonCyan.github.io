一、上位机要做什么 #

串口上位机干四件事：打开串口、把字节收上来、把数据变成人能看的东西、把数据落盘。设备侧不管这些，它按固定帧率往线路上吐报文。 界面按区域切，一块管一件事：

区域 控件构成 职责
串口设置 5 个下拉列表 + 1 个按钮 选串口、波特率、校验位、数据位、停止位，开或关串口
接收设置 2 个单选框 + 1 个复选框 Hex 与 ASCII 互斥切换，是否给接收数据打时间戳
数据发送 1 个单行输入框 + 1 个按钮 手输报文，走同一个串口发出去
数据接收 1 个多行文本域 滚动显示收到的原始数据，超长自动清空
报文解析 两组只读输入框 导航解算字段、原始信息字段，与报文字段一一对应

GUI 程序不能在主线程里阻塞等数据。 Qt 主线程只有一个，它同时干三件事：跑事件循环、分发鼠标键盘事件、重绘界面。而串口读数据天生阻塞——read() 等不到字节就一直等，readline() 要等到换行符才返回。把读操作写进按钮的槽函数，主线程就停在那行代码上，事件循环断了，窗口发白，点关闭没反应，任务管理器显示未响应。 所以收数据必须离开主线程。两条路：把读操作切碎，用 QTimer 定时去问有没有数据；或者开一个 QThread，在后台死循环读，读到就通过信号抛回主线程。前者简单，后者扛得住高速率，第七、八章分别讲。两条路有一个共同点，也是 Qt 的死规矩：后台线程不许碰控件，控件只能在主线程改，跨线程的数据只能走信号与槽。

三、PyQt5 的程序骨架 #

ui_serial_port.py 是生成物，别手改，重新编译就覆盖。业务逻辑放另一个文件，继承生成物里的窗口类。

python
# serial_port.py
from PyQt5.QtWidgets import QMainWindow
from ui_serial_port import Ui_MainWindow     # Designer 生成的界面类

class SerialPort(QMainWindow):
    """串口上位机主窗口"""

    def __init__(self):
        super().__init__()               # 先把 QMainWindow 初始化掉
        self.ui = Ui_MainWindow()
        self.ui.setupUi(self)            # setupUi 要窗口实例，self 本身就是
        self.serial_thread = None

        self.__init_serial_setting__()      # 串口设置区
        self.__init_recv_setting__()        # 接收设置区
        self.__init_recv_data_viewer__()    # 接收显示区
        self.__init_send_data_viewer__()    # 发送区
        self.__init_package_setting__()     # 报文解析区

setupUi(self) 是关键。它把 .ui 里描述的所有控件 new 出来挂到传入的窗口对象上，所以传 self——控件就成了这个窗口的子控件。入口文件 main.py：

python
import sys
from PyQt5.QtWidgets import QApplication
from serial_port import SerialPort

if __name__ == '__main__':
    app = QApplication(sys.argv)     # 事件循环的载体，一个进程只能有一个
    ui = SerialPort()
    ui.show()
    sys.exit(app.exec_())            # 进事件循环，退出时把返回码交给系统

app.exec_() 是阻塞的，程序停在这里等事件进来再分发，它返回的那一刻程序就该结束。exec_ 带下划线是 Python 2 时代 exec 是关键字留下的包袱。QApplication 必须在任何控件之前创建并活到程序结束，把 app 建成局部变量放在函数里，函数一返回它就被回收，界面立刻崩。初始化链拆成几个方法，谁出问题一眼看出来；前后各两个下划线的私有约定，防的是和生成物里 on_控件名_信号名 这类槽函数撞名。

四、信号与槽：Qt 的事件机制 #

Qt 不用回调串事件，用信号与槽。信号是「某件事发生了」的广播，槽是接住广播的普通函数，两者用 connect 连起来：

python
self.ui.btn_send.clicked.connect(self.send_serial_data)

串口程序里它是必需项。后台线程读到数据，你不能这么写：

python
# 错误：后台线程直接改控件
def run(self):
    while self.running:
        data = self.__read_data__()
        self.ui.txt_recv_data_viewer.insertPlainText(data)

run 跑在新线程里，ui.xxx 是主线程创建的控件。Qt 控件不是线程安全的，跨线程直调有三种结局：偶尔正常、界面花屏、进程段错误退出。第三种在开发机上不一定复现，到客户机器上天天复现。正确写法是发信号：

python
# 正确：只管 emit，不碰控件
def run(self):
    while self.running:
        data = self.__read_data__()
        if data:
            self.data_received.emit(data)

emit 在新线程里调用，但槽在哪个线程执行由连接方式决定，这就是 Qt 的线程安全所在。connect 默认是 AutoConnection，它在槽被调用的那一刻检查：发信号的对象和接收槽的对象同线程就直连，同步执行；不同线程自动切成队列连接，把调用打包成事件投进接收方线程的事件队列，等那边的事件循环取出来再执行。所以上面那行 emit 在新线程里瞬间返回，数据被复制进主线程的队列，主线程取出来调 handle_data_received。所有控件操作都发生在主线程，这就是它安全的原因。

连接方式 行为 何时用
AutoConnection 同线程直连，跨线程队列 默认值，绝大多数情况
DirectConnection 立即在发信号的线程执行槽 明确知道不跨线程
QueuedConnection 投递到接收方线程事件队列 强制跨线程
BlockingQueuedConnection 投递并阻塞等槽执行完 两边互等会死锁，别用
UniqueConnection 防重复连接 反复初始化时

跨线程用队列连接有个副作用：参数必须能被 Qt 的元对象系统复制，int、str、list、dict 没问题，自定义类对象不行，除非注册过。这也是 pyqtSignal(str) 只传字符串的原因——最省事。另一个坑：emit 只投递，不保证立刻执行，主线程忙的时候队列会积压，串口每秒几百帧、界面处理不过来时积压越来越长，内存飙升。解法是合并：后台线程攒一小批再发，或者主线程只保留最新值。信号在类的顶层声明，写进 __init__ 会失效：

python
class SerialThread(QThread):
    data_received = pyqtSignal(str)     # 收到一帧数据
    serial_error = pyqtSignal(str)      # 串口异常

五、串口的打开与配置 #

Qt 自家的 QSerialPort #

PyQt5 自带 QtSerialPort，两个类：QSerialPort 管打开读写，QSerialPortInfo 枚举串口。

python
from PyQt5.QtSerialPort import QSerialPort, QSerialPortInfo

for info in QSerialPortInfo.availablePorts():
    print(info.portName(), info.description())

port = QSerialPort()
port.setPortName('COM3')
port.setBaudRate(230400)
port.setDataBits(QSerialPort.Data8)
port.setParity(QSerialPort.NoParity)
port.setStopBits(QSerialPort.OneStop)
if port.open(QSerialPort.ReadWrite):
    port.readyRead.connect(on_ready)   # 有数据就发信号，天然不阻塞

优点是 readyRead 跟 Qt 事件循环原生整合，不用线程不用定时器，数据到了自动唤醒你。缺点是能力有限：超时控制粗，断线检测不灵，非标准波特率支持差，跨平台行为不一致。工业设备的 230400、1500000 很常见，在这里打折扣。

换成 pyserial #

所以本篇用 pyserial，配置面更宽，出错信息也更清楚。枚举用 comports()，port.device 直接喂给 Serial()：

python
import serial, serial.tools.list_ports

for port in serial.tools.list_ports.comports():
    print(port.device, port.description)   # COM3  USB-SERIAL CH340 (COM3)

ser = serial.Serial(port='COM3', baudrate=230400,
                    bytesize=serial.EIGHTBITS, parity=serial.PARITY_NONE,
                    stopbits=serial.STOPBITS_ONE,
                    timeout=2)          # 读超时，秒

timeout 是这套代码里最容易忽略的参数。不写它，readline() 一直阻塞到有换行符；写 2 就是最多等 2 秒，等不到返回 b''。给了超时，读循环才有机会检查退出标志；不给超时，线程卡死在读操作里，stop() 调了也退不出来。

下拉列表装参数 #

串口设置区五个下拉列表加一个按钮，初始化时把可选项灌进去。

python
from PyQt5.QtWidgets import QComboBox

def __init_serial_setting__(self):
    """初始化串口设置区的默认参数"""
    # 五个列表统一：不可编辑、最多显示 10 项、按当前位置插入
    for cbx in (self.ui.cbx_com, self.ui.cbx_baud_rate, self.ui.cbx_parity_bit,
                self.ui.cbx_data_bit, self.ui.cbx_stop_bit):
        cbx.setEditable(False)
        cbx.setMaxVisibleItems(10)                            # 超过 10 项出滚动条
        cbx.setInsertPolicy(QComboBox.InsertAfterCurrent)

    # 串口：系统当前可用串口
    for port in serial.tools.list_ports.comports():
        self.ui.cbx_com.addItem(port.device)

    # 其余四个列表：待填项是 (显示文本, 隐藏数据)，最后一个数是默认下标
    bauds = [1200, 2400, 4800, 9600, 19200, 38400, 57600,
             115200, 230400, 460800, 921600, 1500000]
    parities = [('None', serial.PARITY_NONE), ('Odd', serial.PARITY_ODD),
                ('Even', serial.PARITY_EVEN), ('Mark', serial.PARITY_MARK),
                ('Space', serial.PARITY_SPACE)]
    data_bits = [serial.FIVEBITS, serial.SIXBITS,
                 serial.SEVENBITS, serial.EIGHTBITS]
    plans = [
        (self.ui.cbx_baud_rate, [(str(b), b) for b in bauds], 7),      # 115200
        (self.ui.cbx_parity_bit, parities, 0),                         # None
        (self.ui.cbx_data_bit, [(str(b), b) for b in data_bits], 3),   # 8 位
        (self.ui.cbx_stop_bit,
         [(str(b), b) for b in [serial.STOPBITS_ONE, serial.STOPBITS_TWO]], 0)]
    for cbx, items, default in plans:
        for text, value in items:
            cbx.addItem(text, value)
        cbx.setCurrentIndex(default)

    self.ui.btx_start.clicked.connect(self.open_serial_connection)

按钮的槽，一开一关走同一个函数：

python
def open_serial_connection(self):
    """打开或关闭串口"""
    if not self.serial_thread or not self.serial_thread.isRunning():
        if not self.__validate_setting__():        # 没开：先校验
            return
        self.serial_thread = SerialThread(
            self.ui.cbx_com.currentText(), self.ui.cbx_baud_rate.currentData(),
            self.ui.cbx_data_bit.currentData(), self.ui.cbx_parity_bit.currentData(),
            self.ui.cbx_stop_bit.currentData(),
            'hex' if self.ui.rbn_data_format_hex.isChecked() else 'ascii')
        # 线程信号接主线程的槽
        self.serial_thread.data_received.connect(self.handle_data_received)
        self.serial_thread.serial_error.connect(self.handler_serial_error)
        self.serial_thread.start()
        self.ui.btx_start.setText('关闭串口')
    else:
        self.serial_thread.stop()
        self.ui.btx_start.setText('打开串口')

判断条件两个都不能少。serial_thread 初始是 None，None.isRunning() 直接抛 AttributeError，所以先判空。参数校验一个下巴一个：

python
from PyQt5.QtWidgets import QMessageBox

def __validate_setting__(self):
    """校验串口设置区的参数是否都选了"""
    for cbx, label in [(self.ui.cbx_com, '串口'),
                       (self.ui.cbx_baud_rate, '波特率'),
                       (self.ui.cbx_parity_bit, '校验位'),
                       (self.ui.cbx_data_bit, '数据位'),
                       (self.ui.cbx_stop_bit, '停止位')]:
        if cbx.currentIndex() == -1:
            QMessageBox.warning(self, 'Warning', f'请选择{label}！')
            return False
    return True

def handler_serial_error(self, error):
    """串口线程报上来的异常，弹窗提示"""
    QMessageBox.critical(self, '错误', error)

五个判断对应五个列表，别复制粘贴忘了改控件名——这是校验函数最常见的 bug，看着写了五段，实际在查同一个控件。warning / critical 都是模态弹窗，阻塞到用户点掉，只能在主线程调。这正是错误信息必须通过信号传回主线程的原因。

六、串口参数：波特率、数据位、校验、停止位 #

这四个参数加串口号是串口通信的全部配置。配错的表现只有两种：收不到数据，或者收到乱码。排错方向很明确。

参数 取值 惯性设备实测 配错的后果
串口号 COM1~COM255（Windows），/dev/ttyUSB0（Linux） 插上后枚举得到 打不开，抛 SerialException
波特率 1200 ~ 1500000 等 230400 采样错位，整帧乱码
数据位 5 / 6 / 7 / 8 8 字节被截断，高位丢失
校验位 None / Odd / Even / Mark / Space None 校验失败，或多收一位
停止位 1 / 2 1 帧边界错位，后续全乱
流控 无 / RTS-CTS / XON-XOFF 无 发不出去或丢包

波特率是每秒传输的位数。230400 除以 10（1 起始位 + 8 数据位 + 1 停止位）约每秒 23040 字节，一帧 49 字节，理论上每秒过 470 帧。数据密度上来了，主线程一帧一帧刷界面就吃力。 两边波特率必须完全一致。差一点点也错——接收方按自己的时钟采样，累积偏差超过半个位宽就采错，表现是头几帧正常，越往后越乱。这种情况别怀疑代码，先核对手册。数据位一般固定 8，7 位配 ASCII 的老设备还在服役，遇到就核对手册，别猜。校验位是给每个字节加一位，让「1」的个数满足奇偶规则，惯性设备用 None 的最多，因为上层报文自带累加和校验，串口层就省了。Mark 和 Space 是固定位，用得极少，但下拉列表里要有，不然碰到怪设备没法配。停止位 1 位最常见，2 位出现在一些老式设备上。流控不在下拉列表里，pyserial 用 xonxoff 和 rtscts 控制，默认都关。 五个界面参数一一落到五个关键字参数上，名字和界面标签对不上，记住这张对应：

python
self.serial = serial.Serial(
    port=self.port,              # cbx_com.currentText()
    baudrate=self.baud_rate,     # cbx_baud_rate.currentData()
    bytesize=self.data_bits,     # cbx_data_bit.currentData()   数据位
    parity=self.parity_bits,     # cbx_parity_bit.currentData() 校验位
    stopbits=self.stop_bits,     # cbx_stop_bit.currentData()   停止位
    timeout=2)

七、用 QTimer 轮询收数据 #

QTimer 是主线程里的定时器，不新开线程，事件循环每隔 N 毫秒给它一次执行机会。用它收数据的思路是：把「阻塞等」改成「问一下有没有」。 串口对象设了 timeout，read() 最多等这么久就返回，不管有没有数据；把这句话塞进定时器槽，每次进去读一小段立刻返回，主线程不卡。

python
from PyQt5.QtCore import QTimer
import serial

class SerialPoller:
    """定时器轮询版：不开线程，主线程每 20ms 读一次"""

    def __init__(self, on_data):
        self.on_data = on_data
        self.serial = None
        self.timer = QTimer()
        self.timer.setInterval(20)                 # 20ms 一轮，约 50 次/秒
        self.timer.timeout.connect(self.poll)      # 超时信号接轮询槽

    def start(self, port, baudrate):
        self.serial = serial.Serial(port=port, baudrate=baudrate, timeout=0.02)
        self.timer.start()

    def poll(self):
        """定时器到点，问一句有没有数据"""
        if self.serial is None or not self.serial.is_open:
            return
        n = self.serial.in_waiting                  # 缓冲区里已到的字节数，不阻塞
        if n == 0:
            return                                  # 没数据，立刻让出
        data = self.serial.read(n)                  # 只读已到的，不会等
        if data:
            self.on_data(data)

    def stop(self):
        self.timer.stop()
        if self.serial and self.serial.is_open:
            self.serial.close()

关键是两行：in_waiting 返回接收缓冲区里已到、还没被读走的字节数，非阻塞查询；返回 0 就说明没数据，直接 return，槽函数几微秒结束，事件循环立刻处理下一件事。read(n) 指定读 n 个字节，缓冲区里有 n 个就立刻返回，配合前面的 if n == 0: return，永远不会阻塞。

参数 建议值 说明
setInterval 10~50 ms 太短空转浪费，太长数据积压
serial.timeout 与 interval 相当 有 in_waiting 保护，实际很少等
单次读取量 in_waiting 全读 分多次读会造成帧断裂

setSingleShot(True) 让它跑一次就停，适合「等 3 秒没收到就报警」。定时器版适合数据率低、帧率几十 Hz、你更看重代码简洁的场景。9600 波特率、每秒几百字节的设备，轮询完全够用，代码量比线程少一半，调试也简单——全在主线程，不用考虑线程安全。 它不适合每秒上千帧、921600 以上。原因在定时器粒度上。Windows 默认定时器精度 15.6 毫秒，setInterval(1) 实际 15 毫秒才触发一次，你设 20 毫秒的轮询，真实间隔会在 20 到 36 毫秒之间浮动。每次触发时缓冲区里已经堆了好几帧，一次 read(n) 全读出来，on_data 里得自己拆帧。更硬的问题：主线程既是读取方又是渲染方，界面重绘要几毫秒，定时器到点却被渲染占着，这一轮就漏了。漏了不要紧，数据还在缓冲区，下一轮补读，但界面上看到的就是一阵一顿，波形卡着跳。

维度 QTimer 轮询 QThread 后台线程
代码量 少，一个类搞定 多，要定义信号、写 run、管生命周期
线程安全 全在主线程，不用操心 必须走信号槽，控件不能碰
数据完整性 受定时器抖动影响，会读到多帧粘连 readline() 天然按行切，帧完整
高速率表现 921600 以上丢帧感明显 能吃满串口带宽
主线程压力 读取和渲染抢时间片 读取在后台，主线程只管渲染
退出控制 timer.stop() 立刻生效 依赖 timeout 和 running 标志配合
适用场景 低速设备、原型验证、仪表盘 工业设备、高速率、长时间运行

经验判据：波特率 ≤ 115200 且帧率 < 100 Hz，用 QTimer 省事；超过这个量级直接上 QThread，别等客户投诉丢数据再改。

八、收数据的线程化：QThread #

QThread 的做法是把读串口这个死循环整体搬到后台线程，读到就用 emit 抛出，主线程接住更新界面。

python
from PyQt5.QtCore import QThread, pyqtSignal
import serial

class SerialThread(QThread):
    """串口收发的后台线程"""

    data_received = pyqtSignal(str)     # 收到一帧数据
    serial_error = pyqtSignal(str)      # 串口异常

    def __init__(self, port, baud_rate, data_bits, parity_bits,
                 stop_bits, data_format):
        super().__init__()
        self.port, self.baud_rate = port, baud_rate
        self.data_bits, self.stop_bits, self.parity_bits = (
            data_bits, stop_bits, parity_bits)
        self.running = False        # 运行标志
        self.serial = None          # 串口句柄
        self.__date_format = data_format
        self.__auto_line = True     # 发送时自动补换行

    @property
    def date_format(self):
        return self.__date_format

    @date_format.setter
    def date_format(self, value):
        if not isinstance(value, str) or value not in ['hex', 'ascii']:
            raise ValueError('date_format must be in [hex, ascii]')
        self.__date_format = value

__date_format 双下划线是私有属性，外部通过 property 改并做取值校验。主线程改这个属性是安全的——它只给字符串赋值，不是操作控件。线程主体在 run 里，start() 一调新线程启动，run() 被执行，start() 本身立刻返回，不阻塞主线程。

python
    def run(self):
        """线程入口：打开串口，循环读，读到就发信号"""
        if self.running:
            return
        try:
            # with 保证异常退出时串口也被关掉
            with serial.Serial(port=self.port, baudrate=self.baud_rate,
                               parity=self.parity_bits,
                               bytesize=self.data_bits,
                               stopbits=self.stop_bits, timeout=2) as self.serial:
                self.running = True
                while self.running:
                    data = self.__read_data__()
                    if data:
                        self.data_received.emit(data)     # 抛回主线程
        except Exception as e:
            print('打开串口时失败：', e)
            self.serial_error.emit('打开串口时失败！')
        finally:
            self.running = False
            self.serial = None

读取函数按行切：

python
    def __read_data__(self):
        """按行读一串数据，按当前格式转成字符串"""
        if self.serial is None or not self.serial.is_open:
            return None
        try:
            byte_array = self.serial.readline()   # b'DDR V1.12 52218f4949'
            if len(byte_array) == 0:
                return None
            if self.__date_format == 'ascii':
                return byte_array.decode('utf-8', errors='replace')
            # b'ZZ\x02\x03Z' → '5a 5a 02 03 5a'
            data_str = ' '.join(format(x, '02x') for x in byte_array)
            return data_str + '\r\n' if self.__auto_line else data_str
        except Exception as e:
            print('接收数据异常：', e)
            self.serial_error.emit('接收数据异常！')
            return None

    def stop(self):
        """停线程：改标志 + 等它自己退出"""
        self.running = False
        if not self.wait(3000):
            self.terminate()     # 兜底，只在 wait 超时后用
            self.wait()

发送分两段：线程里的 send_data 负责编码，主线程的 send_serial_data 负责取界面输入和校验。

python
    def send_data(self, data: str):
        """把界面上的字符串发到串口"""
        if not self.running or self.serial is None:
            self.serial_error.emit('请先打开串口！')
            return
        if self.__date_format == 'hex':
            # '5a 5a 02 03 5a' → b'ZZ\x02\x03Z'
            try:
                send_list = [int(tok, 16) for tok in data.split()]
            except ValueError:
                self.serial_error.emit('请输入十六进制数据，以空格分开！')
                return
            if self.__auto_line:
                send_list += [0x0d, 0x0a]
            byte_array = bytes(send_list)
        else:
            if self.__auto_line:
                data += '\r\n'
            byte_array = data.encode('utf-8')       # 'ABC' → b'ABC'
        try:
            self.serial.write(byte_array)
        except Exception as e:
            print('发送失败', e)
            self.serial_error.emit('发送失败！')

    def send_serial_data(self):
        """主线程侧：【发送】按钮的槽"""
        if not self.serial_thread or not self.serial_thread.isRunning():
            QMessageBox.warning(self, 'Warning', '请先打开串口！')
            return
        data = self.ui.let_send_data_viewer.text()
        if data != '':
            self.serial_thread.send_data(data)
            self.ui.let_send_data_viewer.clear()    # 发完清空，方便下一次

send_data 在主线程调用（由按钮槽触发），操作的却是后台线程持有的 self.serial。严格说并发写同一个对象有风险，但一个读一个写，底层是两条独立通道，Windows 上大多没问题。更稳的做法是把发送也做成信号，让后台线程在自己的循环里执行 write。简单项目直接调，加 try/except 兜着。

十、数据实时显示 #

数据进了主线程的 handle_data_received，干四件事：取当前时间；接收区超 5000 字符就清空；按「是否显示时间」决定要不要加时间戳；Hex 模式下往后走报文解析。

python
from PyQt5.QtCore import QDateTime

def handle_data_received(self, data):
    """主线程的槽：后台线程发来的数据在这里落地"""
    current_time = QDateTime.currentDateTime().toString('yyyy-MM-dd hh:mm:ss')
    if self.ui.txt_recv_data_viewer.document().characterCount() > 5000:
        self.ui.txt_recv_data_viewer.clear()      # 超长清空，防止越滚越慢
    if self.ui.cbx_show_time.isChecked():
        self.ui.txt_recv_data_viewer.insertPlainText(f'[{current_time}] {data}')
    else:
        self.ui.txt_recv_data_viewer.insertPlainText(data)
    if self.ui.rbn_data_format_ascii.isChecked():
        return                                    # ASCII 模式不解析报文

document().characterCount() 直接读内部计数，不拷贝文本；用 toPlainText() 再 len() 会先拷一份上万字符的字符串，白花开销。5000 字符是经验值，太小频繁清空，用户还没看清就没了；太大文本域变长后插入和重绘都变慢。清空而不是截断，是因为 QTextEdit 没有「删掉前 N 个字符」的廉价操作，截断要重建整个文档，比清空还慢。

十六进制字符串还原成字节 #

接收区显示的是 5a 5a 02 03 5a 这样的文本，要解析报文得先还原成字节：

python
data = data.replace('0d 0a', '')              # 去掉读取时追加的换行
data = bytes.fromhex(data.replace(' ', ''))   # 去掉空格再转字节

bytes.fromhex() 是 Python 3.7 起的内置方法，要求纯十六进制字符、长度偶数。replace('0d 0a', '') 有前提：读取时给十六进制串追加了 \r\n，渲染出来才是 0d 0a 两个字节的文本。如果设备报文本身含 0x0d 0x0a，这行会误删真实数据。稳妥做法是读取阶段就不加 __auto_line：self.__auto_line = False。

逐帧拆分 #

一次 emit 会带来好几帧粘连的数据。拆法是循环：判断当前字节串是什么报文、解析、切掉、再判断。

python
from package_parse import PackageParse

while data:
    parser = PackageParse(data)
    fmt = parser.get_data_format()
    if fmt == PackageParse.Type.NAl_SOL:
        msg = parser.get_nav_sol()
        msg['current_time'] = current_time
        save_csv('nav_data.csv', msg)
        self.__show_nav(msg)
        data = data[fmt.value:]        # 切掉已消费的帧
    elif fmt == PackageParse.Type.RAW:
        msg = parser.get_raw()
        msg['current_time'] = current_time
        save_csv('raw_data.csv', msg)
        self.__show_raw(msg)
        data = data[fmt.value:]
    else:
        break                          # 头不对，剩下的丢掉

用 Enum 的 value 存帧长，NAl_SOL.value 是 49，RAW.value 是 58，切片长度直接从类型上取，不用另开表。判断点集中在一处：while data: 加 break，比 while data is not None 再在末尾补长度判断清楚。判帧靠三条：长度够不够（导航解算 ≥49，原始信息 ≥58）；前两字节是不是 0x5a 0x5a；第 49 或第 58 字节是不是前面字节的累加和。

python
def validate_nal_sol(self):
    """导航解算：第 49 字节是第 3~48 字节的累加和"""
    return sum(self.__byte_array[2:48]) & 0xFF == self.__byte_array[48]

def validate_raw(self):
    """原始信息：第 58 字节是第 3~57 字节的累加和"""
    return sum(self.__byte_array[2:57]) & 0xFF == self.__byte_array[57]

def get_data_format(self):
    """返回 导航解算 / 原始信息 / 非法"""
    b = self.__byte_array
    if (len(b) >= 58 and b[0] == 0x5a and b[1] == 0x5a
            and self.validate_raw()):
        return PackageParse.Type.RAW
    if (len(b) >= 49 and b[0] == 0x5a and b[1] == 0x5a
            and self.validate_nal_sol()):
        return PackageParse.Type.NAl_SOL
    return PackageParse.Type.UNkNOWN

& 0xFF 是只留低字节，sum() 会超出 255，不取低 8 位永远对不上。先判 RAW 再判 NAl_SOL 是因为 58 字节报文的前 49 字节也会「看起来像」导航解算，但它第 49 字节是数据不是校验和，先判长的那一路能减少误判。

字段怎么算出来 #

报文里是原始字节，得按字段单位和量纲换算，统一走一个转换函数：

python
def translate(hex_array, unit=None):
    """字节数组 → 数值或十六进制字符串
    传 unit 返回数值，不传返回 '0x0A 0x04'
    """
    if unit is not None:
        num = int.from_bytes(hex_array, byteorder='little')   # 小端转整数
        return num / unit
    return ' '.join(f'0x{val:02X}' for val in hex_array)

int.from_bytes(..., 'little') 是关键。串口设备绝大多数用小端（低字节在前），按大端解析出来的数字是反的，表现为数值离谱却不报错。量纲会出现 93206.75556 这种常数，它是 2^32 / 360 / 128 的连乘结果，代表「一个 32 位整数对应多少度」。不要改，改了全错，照抄手册的标度因子。两个报文按「字段名、起止下标、量纲」写成表，解析时照着切，比手写二十行赋值好维护：

    return self._parse(RAW_FIELDS)

量纲为 None 的字段拿到的都是 0x5A 这样的十六进制文本。带物理意义的才传量纲，报文头、状态位、校验和本来就该按原始字节看，硬套一个缩放系数只会把 0x5A 变成 0.9。NAl_SOL 这个拼写是原始协议里的枚举名，保持原样，改了就找不到对应关系。这名字看着难受，但它是和硬件文档的锚点。

十一、画波形：pyqtgraph 或 matplotlib #

串口数据变成曲线，需要一张图。两个库都能嵌进窗口：

维度 pyqtgraph matplotlib
安装 pip install pyqtgraph pip install matplotlib
嵌入方式 直接用 PlotWidget，本身就是 Qt 控件 走 FigureCanvasQTAgg 包装
刷新方式 setData() 重设数据，立即重绘 draw() 全量重画，慢
万点以上 流畅 明显卡顿
API 简洁，为实时设计 完备，偏出版级静态图
适用 实时波形、频谱、示波器 出图报告、离线分析

实时波形用 pyqtgraph，它本身就是 Qt 控件：pip install pyqtgraph numpy。

python
import numpy as np
import pyqtgraph as pg
from PyQt5.QtWidgets import QVBoxLayout, QWidget

class WavePanel(QWidget):
    """波形面板：一个 PlotWidget，两条曲线"""

    def __init__(self, parent=None):
        super().__init__(parent)
        pg.setConfigOptions(antialias=True)        # 实时刷新时可以关掉换性能
        self.plot = pg.PlotWidget()
        self.plot.setBackground('w')
        self.plot.showGrid(x=True, y=True, alpha=0.3)
        self.plot.setLabel('left', '数值')
        self.plot.setLabel('bottom', '采样点')
        self.plot.addLegend()
        self.curve_x = self.plot.plot(pen=pg.mkPen('#1f77b4', width=2), name='GYROX')
        self.curve_y = self.plot.plot(pen=pg.mkPen('#d62728', width=2), name='GYROY')
        QVBoxLayout(self).addWidget(self.plot)
        # 环形缓冲：固定长度数组，写满从头覆盖
        self.max_points = 2000
        self.buf_x, self.buf_y = np.zeros(self.max_points), np.zeros(self.max_points)
        self.pos = 0

    def push(self, gyrox, gyroy):
        """收到一帧塞一个点，不立刻重绘"""
        self.buf_x[self.pos], self.buf_y[self.pos] = gyrox, gyroy
        self.pos = (self.pos + 1) % self.max_points

    def refresh(self):
        """由定时器按 50ms 调一次，统一重绘"""
        n = self.pos if self.pos else self.max_points
        self.curve_x.setData(self.buf_x[:n])
        self.curve_y.setData(self.buf_y[:n])

两个要点。环形缓冲：固定长度的 numpy 数组加游标，写满从头覆盖，内存恒定，界面不会因为跑了十小时吃掉几个 G。直接 list.append 再 setData，跑一小时就卡死。重绘频率：每收一帧就 setData，230400 波特率下每秒几百次重绘，得不偿失。数据来了只管塞缓冲，重绘交给一个 50ms 的 QTimer 统管，主线程不会被重绘压满。 想用 matplotlib 也行，嵌入方式是 FigureCanvasQTAgg：

python
import matplotlib
matplotlib.use('Qt5Agg')                 # 必须在导入 pyplot 之前设
from matplotlib.backends.backend_qt5agg import FigureCanvasQTAgg
from matplotlib.figure import Figure

class MplPanel(FigureCanvasQTAgg):
    """matplotlib 画布，当普通控件用"""

    def __init__(self, parent=None):
        self.fig = Figure(figsize=(6, 3), dpi=100)
        super().__init__(self.fig)
        self.ax = self.fig.add_subplot(111)
        self.line_x, = self.ax.plot([], [], lw=1, label='GYROX')
        self.ax.legend(loc='upper right')

    def refresh(self, xs):
        self.line_x.set_data(range(len(xs)), xs)
        self.ax.relim()
        self.ax.autoscale_view()
        self.draw()          # 这一步很贵，别放在高频率回调里

matplotlib.use('Qt5Agg') 必须在 import pyplot 之前，否则后端已经选定，改不动。draw() 是全量重画，几十毫秒一次是上限，间隔要拉到 100ms 以上，数据用环形缓冲攒着。姿态角三个、角速度三个、加速度三个，九条曲线要分开看，用 GraphicsLayoutWidget 搭网格并共享 X 轴：

win = pg.GraphicsLayoutWidget()
p1 = win.addPlot(row=0, col=0, title='姿态角')
p2 = win.addPlot(row=1, col=0, title='角速度')
p2.setXLink(p1)          # 拖动一个，另一个跟着动

十二、数据保存到文件 #

解析出的字典直接写 CSV，先写表头再写数据，第二次以后只追加：

python
import csv, os

def save_csv(file_name, row: dict):
    """字典追加写入 CSV，文件不存在时先写表头"""
    file_exists = os.path.exists(file_name)
    # newline='' 是 csv 模块的要求，不加会多出空行
    with open(file_name, 'a', newline='', encoding='utf-8') as f:
        writer = csv.writer(f)
        if not file_exists:
            writer.writerow(row.keys())
        writer.writerow(row.values())

newline='' 不能省。Windows 下不加，csv.writer 写的 \r\n 会被文本模式再转换一次，每行之间多一个空行。encoding='utf-8' 也要写，Python 3 在 Windows 上默认用 GBK，字段里有中文时到别人机器上就是乱码。导航解算写 nav_data.csv，原始信息写 raw_data.csv。分文件是因为两路报文字段完全不同，混在一个表里会有一半列永远空着。 高频写入会拖慢主线程。每秒几百次 open + write + close，磁盘扛不住，界面跟着顿。改成攒一批再落盘：

python
class CsvWriter:
    """攒够 N 行才真正写盘"""

    def __init__(self, file_name, flush_every=50):
        self.file_name = file_name
        self.flush_every = flush_every
        self.buffer = []

    def append(self, row: dict):
        self.buffer.append(row)
        if len(self.buffer) >= self.flush_every:
            self.flush()

    def flush(self):
        if not self.buffer:
            return
        file_exists = os.path.exists(self.file_name)
        with open(self.file_name, 'a', newline='', encoding='utf-8') as f:
            writer = csv.writer(f)
            if not file_exists:
                writer.writerow(self.buffer[0].keys())
            writer.writerows(row.values() for row in self.buffer)
        self.buffer.clear()

    def close(self):
        self.flush()      # 退出前必须调，否则最后几十行丢在内存里

def closeEvent(self, event):
    """窗口关闭时收尾：先停线程，再刷盘"""
    if self.serial_thread and self.serial_thread.isRunning():
        self.serial_thread.stop()
    for writer in self.writers.values():
        writer.close()
    event.accept()

CSV 之外还该存一份二进制原始流，把 readline() 拿到的字节原样追加到 .bin。CSV 是给人看的，.bin 是给复盘用的——解析逻辑写错了，原始流还在，能重跑。两者不冲突，都存。

十三、异常处理与断线重连 #

**第一层，打开串口时。**端口被占用、不存在、没权限都在这时候暴露，一次就报清楚：

python
try:
    self.serial = serial.Serial(port=self.port, baudrate=self.baud_rate, timeout=2)
except serial.SerialException as e:
    self.serial_error.emit(f'打开串口失败：{e}')
    return

**第二层，读写循环里。**每次读包一层 try，出错就发信号、置标志、退出循环：

python
try:
    byte_array = self.serial.readline()
except (serial.SerialException, OSError) as e:
    self.running = False
    self.serial_error.emit(f'串口断开：{e}')
    return None

关键是 self.running = False。出错后不置标志，while 会继续转，每转一圈抛一次异常，日志瞬间刷屏，界面弹出几百个错误框。一旦断开，循环必须停。SerialException 之外还要接 OSError，Windows 上拔掉 USB 转串口，底层报的是 OSError，只接前者会漏掉最常见的那一种。 第三层，退出时。finally 里保证串口被关、标志被清：

python
finally:
    self.running = False
    if self.serial and self.serial.is_open:
        self.serial.close()
    self.serial = None

断线重连按次数封顶，超过就停手：

python
def __reconnect__(self):
    """断线后按固定间隔重试"""
    if not self.__want_reconnect:
        return
    self.__reconnect_tries += 1
    if self.__reconnect_tries > 10:
        self.serial_error.emit('重连失败，请检查设备连接')
        return
    self.start()

重连要加退避间隔，别一断就狂开端口。第 1 次等 1 秒，第 2 次 2 秒，逐步拉长。把它做成一个 QTimer，由主线程按间隔触发 serial_thread.start()，比在线程里 sleep 干净。断线时界面上要能看出来：串口一断，把「关闭串口」按钮恢复成「打开串口」，状态栏写清楚断开原因，别让用户对着一个不动的时间戳猜。

十四、打包成可执行文件 #

交付时对方机器上没有 Python，用 PyInstaller 打成 exe。

bash
pip install pyinstaller
pyinstaller -F -w -n SerialTool main.py

-F 打成单文件，-w 不显示黑色控制台窗口，-n 指定输出名字。产物在 dist\SerialTool.exe。想压小一点，用 --exclude-module 剔掉没用到的模块：

bash
pyinstaller -F -w -n SerialTool ^
  --exclude-module tkinter ^
  --exclude-module matplotlib ^
  --exclude-module PyQt5.QtWebEngineWidgets ^
  main.py

--exclude-module 要谨慎，剔掉后再用到它，程序会在运行时报 ModuleNotFoundError，打包阶段看不出来。几个反复踩的点：

现象 原因 处理
双击闪退，无任何提示 用了 -w，异常没人显示 先去掉 -w 打包，看控制台报什么
提示找不到 Qt 平台插件 插件目录没打进去 加 --collect-all PyQt5
图标没生效 没配 icon --icon=app.ico，图标要是 .ico 不是 .png
杀毒软件报毒 单文件自解压行为可疑 换 -D 目录模式，或用商业签名
单文件启动要好几秒 每次运行都解压到临时目录 换 -D，启动快但文件多
打出来的 exe 巨大 把 numpy、matplotlib 全带上了 用 --exclude-module 逐个剔

第一次交付用 -D 目录模式，更快也更少出问题，确认稳定了再换 -F。打包后 __file__ 指向的不再是源码位置，PyInstaller 会把它解压到临时目录，读文件的地方要走这个函数：

python
import sys, os

def resource_path(relative):
    """兼容源码运行和 PyInstaller 打包后的资源路径"""
    base = getattr(sys, '_MEIPASS', os.path.dirname(os.path.abspath(__file__)))
    return os.path.join(base, relative)

纯代码的串口工具用不到，但把 .ui 或配置文件一起打包时就得走它。

十五、易错点速查 #

现象 根因 解法
窗口白屏、点不动、显示未响应 主线程里阻塞等数据 读操作挪到 QThread，或用 QTimer 轮询
程序关掉后端口仍被占用 串口没 close() 用 with serial.Serial(...)，或在 finally 里关
关闭串口时界面卡几秒 wait() 等 readline() 超时 给 timeout 设小值（0.2~1 秒）
线程退不出来 timeout=None，readline() 永久阻塞 必须给超时
后台线程里弹窗，程序崩 跨线程操作控件 错误文本走信号回主线程弹
界面偶发花屏或段错误 直接改控件没走信号槽 跨线程更新一律 emit
信号连了但槽不执行 pyqtSignal 写在 __init__ 里 移到类顶层当类属性
收到乱码 波特率或数据位不一致 对着手册逐个核对
十六进制解析抛 ValueError 含空格、换行或长度奇数 先 replace(' ', '')，确保长度偶数
CSV 每行之间多空行 没写 newline='' open(..., newline='')
CSV 中文乱码 没指定编码 encoding='utf-8'
数值明显不对但不报错 字节序搞反 int.from_bytes(..., 'little')
波形跑久了越来越卡 数据点无限堆积 环形缓冲 + 定时重绘
校验和始终对不上 帧长或校验范围记错 累加范围核对手册，只取 & 0xFF
exe 双击闪退 -w 把异常吞了 先去 -w 打包看报错
打包后找不到 Qt 插件 插件目录未收集 --collect-all PyQt5

几条不以现象归纳的。QApplication 只能有一个，写成全局单例，别在函数里反复创建，第二个会直接让程序退出。Designer 生成的 .py 每次编译都覆盖，手写的逻辑一律放另一个文件继承它，写进生成物的重新编译一次就全没了。QComboBox.currentData() 返回 None 的情况必须防，列表为空时取出来就是 None，直接塞给 serial.Serial 会抛 TypeError，错误信息还看不出是哪个参数。cbx_com 里的串口列表启动时扫一次就固定了，用户中途插拔转换器列表不会变，加个「刷新」按钮重新灌一遍，或者每次打开串口前重扫。报文解析里所有切片都要先判长度，data[2:48] 在 data 只有 10 个字节时不抛异常，返回 b''，sum(b'') 是 0，校验和恰好为 0 的坏帧就被当成合法帧。

最后一条，也最容易忘：**关闭窗口时先停线程，再关串口，最后才让窗口消失。**顺序反了，线程还在 readline，窗口对象已经销毁，下一次 emit 时接收方不存在，程序退出会抛一串 RuntimeError。
