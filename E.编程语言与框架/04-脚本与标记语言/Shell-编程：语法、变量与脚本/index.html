一、Shell 是什么：命令解释器 #

Shell 有三重身份。一是命令解释器，你在提示符下敲一行，它解析、执行、把结果写回终端。二是编程语言，有变量、分支、循环、函数，能写进文件一次跑完。三是内核外面那层壳，进程创建、文件打开、并行调度都靠它向内核发起系统调用。

两种执行方式：

方式 怎么用 适合什么
交互式 Interactive 敲一条，解释执行一条 临时查看、试命令、救急
批处理 Batch 事先写成脚本，一次执行 重复动作、初始化、巡检

脚本是解释执行的，不编译。Shell 从文件里一行一行读，读到一行执行一行，等价于你把这几十行命令逐条敲进终端。没有编译期检查，拼错一个变量名，要跑到那一行才暴露。

每条命令执行完给一个退出状态，放在 $? 里。0 是成功，非 0 是失败。这是 Shell 唯一的错误通道，后面所有条件判断都建在它上面。

记住一句话：Shell 脚本就是一组有序的命令，加上控制它们顺序的语法。

二、几种 Shell：sh、bash、zsh #

Shell 常见路径 说明
Bourne Shell（sh） /bin/sh、/usr/bin/sh 老祖宗，POSIX 语法的基准
Bourne Again Shell（bash） /bin/bash Linux 默认，兼容 sh，加了数组、[[ ]]、进程替换
C Shell（csh） /usr/bin/csh 语法像 C，写脚本少用
K Shell（ksh） /usr/bin/ksh 商业 Unix 常见
Shell for Root /sbin/sh root 的应急壳
zsh /bin/zsh 兼容 bash 大部分语法，补全与提示符更花，macOS 默认
dash /bin/dash Debian 系 /bin/sh 的实现，启动快，只认 POSIX

语法差异不能互换。数组、[[ ]]、local、${var//a/b} 在 sh、dash 里没有。#!/bin/sh 的脚本用 bash 跑没问题，反过来把 bash 语法塞进 #!/bin/sh，落到 dash 上会报 Bad substitution。

bash
echo "$SHELL"          # 登录 shell
echo "$0"              # 当前进程名
ps -p $$ -o comm=      # 当前 shell 的可执行文件名

多数人并不区分 sh 和 bash，#!/bin/sh 的老脚本，当它是 bash 的兼容子集读就行。

三、第一个脚本 #

bash
#!/bin/bash
# 在终端打印一行字
a="hello world"
echo "$a"

存成 hello.sh，chmod u+x hello.sh 之后 ./hello.sh，输出 hello world。

第一行 #! 后面跟解释器路径，告诉系统用谁来读这个文件。没有这一行，执行时会用当前 shell 顶上，行为不可控。

除首行外，# 开头到行尾全是注释。首行的 #! 是特例，它不是注释。

赋值号两边不能有空格。写成 a = "hello world" 会报 a: command not found，因为 Shell 把 a 当命令、= 和后面的内容当参数了。

一行没写完，行尾加 \ 续行：

bash
echo "这行很长，" \
     "拆成两行写"

四、执行方式与 shebang #

4.1 四种跑法 #

bash
# 1. 加执行权限，用相对路径调用
chmod u+x test.sh
./test.sh

# 2. 直接交给解释器
/bin/bash test.sh

# 3. 把目录塞进 PATH，任意位置直接敲文件名
chmod u+x test.sh
PATH+=:/home/fs/Temp
test.sh

# 4. 搬进系统可执行目录
chmod u+x test.sh
sudo mv test.sh /bin/
跑法 要执行权限 进程 变量能否带回当前 shell
./test.sh 要 新子 shell，按 shebang 选解释器 不能
sh test.sh / bash test.sh 不要 新子 shell，按命令行指定解释器 不能
. ./test.sh / source ./test.sh 不要 当前 shell 能
test.sh（已在 PATH） 要 新子 shell 不能

一定要写 ./test.sh，不能只写 test.sh。直接写文件名，系统会去 PATH 列出的目录里找，/bin、/sbin、/usr/bin、/usr/sbin 在列表里，当前目录不在，所以找不到命令，报 bash: test.sh: command not found。./ 就是告诉系统「就在当前目录找」。

4.2 子 shell 与当前 shell 的关键差别 #

这条差别是后面变量作用域、export、配置文件生效方式的根。

bash
name="dangxu"
echo "${name}"     # dangxu

test.sh 里只有一行 echo "${name}"。直接跑，输出是空的：

bash
./test.sh          # 空
sh ./test.sh       # 空
bash ./test.sh     # 空
. ./test.sh        # dangxu
source ./test.sh   # dangxu

依据只有一条：没有被 export 导出的变量不是环境变量，子 shell 继承不到。./、sh、bash 都另起了一个子进程，父进程的普通变量传不进去；. 和 source 在当前进程里逐行执行脚本，变量当然还在。

. 和 source 效果一样，. 更短，但点号后面必须有一个空格：. ./test.sh。被包含的脚本不需要执行权限，因为它不是被当成程序启动的。

4.3 shebang 的细节 #

bash
#!/bin/bash            # 写死路径，最直接
#!/usr/bin/env bash    # 走 PATH 找 bash，可移植性好

shebang 必须是文件第一行的前两个字节，前面不能有空行，也不能有 BOM。带 BOM 时前面多了三个不可见字节，内核认不出来，报 bad interpreter，排查起来很费时间。

改完 .bashrc 想让配置立刻生效，同样靠 source：

bash
source ~/.bashrc

新开终端当然也生效，但那要重开一次会话。

五、变量：定义、引用与作用域 #

先把核心摆出来：Shell 里一切都是字符串。 变量没有类型，number=123 存的是三个字符 1、2、3，不是整数。算术要用 $(( )) 或 let 显式触发，比较要靠 -eq 这类数字运算符，条件判断靠命令的退出状态。理解这一点，后面九成诡异现象都能解释。

5.1 定义 #

bash
varName="value"

等号两边不能有空格，varName = "value" 会当成命令执行。首字符必须是字母或下划线，中间不能有空格，可以用下划线，不能用标点和 bash 关键字（if、then、fi、for、do、done、case、esac、function）。值里有空格必须加引号。

5.2 引用 #

变量名前加 $，或者用 ${} 明确边界：

bash
#!/bin/bash
skill="Ada"
echo "i am good at ${skill}Script"   # i am good at AdaScript
echo "i am good at $skillScript"     # i am good at （$skillScript 未定义，展开为空）

不加花括号时，解释器把 $skillScript 整个当成一个变量名。

5.3 重新赋值 #

bash
myUrl="http://see.xidian.edu.cn/cpp/linux/"
echo "${myUrl}"
myUrl="http://see.xidian.edu.cn/cpp/shell/"
echo "${myUrl}"

第二次赋值直接写变量名，不能写 $myUrl="..."。加上 $ 之后 Shell 先把变量值替换出来，再把那一串当命令去找，报 command not found。只有引用时才加 $。

5.4 只读与删除 #

bash
#!/bin/bash
myUrl="http://see.xidian.edu.cn/cpp/shell/"
readonly myUrl
myUrl="http://see.xidian.edu.cn/cpp/danpianji/"    # bash: myUrl: readonly variable

脚本停在这一行。unset 删变量，但删不掉只读变量，报 cannot unset: readonly variable。

bash
unset varName
set          # 列出当前 shell 的所有变量（本地变量 + 环境变量）

5.5 作用域三档 #

定义位置 可见范围 写法
函数内加 local 只活在函数体里 local tmp=1
脚本或终端里直接赋值 当前 shell 进程，以及被 source 进来的脚本 a=1
加 export 当前进程 + 所有子进程 export PATH

函数是容易翻车的地方，不加 local 的变量是全局的：

bash
#!/bin/bash
count=0
bump() { count=$((count + 1)); }    # 直接改外面那个
bump
echo "$count"        # 1

inner() { local count=99; }         # 只活在函数里
inner
echo "$count"        # 1

未定义的变量展开成空字符串，不报错。这是脚本静默出错的头号原因，排查手段见「十七、脚本的调试与排错」。

六、环境变量与 export #

按生存期分两类：永久变量写进配置文件，改了对以后所有会话生效；临时变量 export 出来，只活在当前 shell 会话里，关掉就没了。

6.1 三种设置方式 #

位置 生效范围 是否永久 立即生效
/etc/profile 所有用户 是 source /etc/profile
~/.bash_profile 单个用户 是 source ~/.bash_profile
命令行 export 当前 shell 及其子进程 否 立即 
bash
# vi /etc/profile，追加一行
export PATH=/home/fs:$PATH
source /etc/profile          # 不 source 就要等下次登录

# vi /home/guok/.bash_profile，追加一行
export CLASSPATH=./JAVA_HOME/lib:$JAVA_HOME/jre/lib
source /home/guok/.bash_profile

# 命令行临时加一个，关掉 shell 就失效
export TEMP_VAR="Temporary Value"

6.2 export 到底做了什么 #

普通变量只属于当前进程，export 把变量加进进程的环境块，子进程启动时复制一份过去：

bash
plain="本进程可见"
export shared="子进程也可见"

bash -c 'echo "shared=$shared"'   # shared=子进程也可见
bash -c 'echo "plain=$plain"'     # plain=

export -n shared 撤销导出，变量本身还在，只是不传给子进程了。

export 是单向复制，不是共享内存。子 shell 里改值，父 shell 看不见：

bash
export A=1
bash -c 'A=2'
echo "$A"        # 1

6.3 PATH #

PATH 决定敲一个命令名时去哪里找可执行文件，格式是冒号分隔的目录串：

bash
PATH=$PATH:/your/custom/path
PATH+=:/home/fs/Temp        # 追加写法，+= 后面跟的是冒号
echo "$PATH"

把当前目录 ./ 放进 PATH 有安全风险，别人在你的工作目录里丢一个同名脚本，你敲命令就执行了它。

6.4 常用环境变量 #

变量名 内容
PATH 查找命令与程序的目录列表
HOME 当前用户的主目录
HISTSIZE 保留的历史命令条数
LOGNAME 当前用户的登录名
HOSTNAME 主机名
SHELL 当前用户使用的 shell 类型
LANGUAGE 语言相关设置
MAIL 邮件存放目录
PS1 主提示符，root 是 #，普通用户是 $

6.5 常用操作 #

bash
echo "$HOME"                       # /home/fs
export HELLO="Hello"; echo "$HELLO"
env                                # 只列环境变量
set                                # 列全部变量，含本地变量和函数
export TEST="Test"; env | grep TEST
unset TEST; env | grep TEST        # 第二句无输出

env 只看导出的环境变量，set 把本地变量、函数定义一起倒出来，输出长得多。

七、特殊变量：$0、$?、$#、$@ #

这些变量由 Shell 自己维护，脚本和函数里都能用。

变量 含义
$0 当前脚本的文件名
$n 第 n 个参数，$1 到 $9，第十个起写 ${10}
$# 参数个数
$* 所有参数，拼成一个字符串
$@ 所有参数，各自独立
$? 上一条命令的退出状态，或函数的返回值
$$ 当前 shell 进程的 PID
$! 最后一个后台进程的 PID
$- 当前 shell 的选项开关

7.1 $* 与 $@ 的差别 #

不加引号时两者一样，都按空格切开。加引号时差别就出来了：

bash
#!/bin/bash
echo "--- \$* 不加引号 ---"
for var in $*; do echo "[$var]"; done
echo '--- "$@" 加引号 ---'
for var in "$@"; do echo "[$var]"; done

执行 ./test.sh "a b" c：

text
--- $* 不加引号 ---
[a]
[b]
[c]
--- "$@" 加引号 ---
[a b]
[c]
写法 展开结果
$* 所有参数拼成一个字符串，再按空白切成多个词
"$*" 一个字符串，参数之间用 IFS 的第一个字符连接
$@ 与 $* 表现相同
"$@" 每个参数各占一个词，原样保留空格

遍历参数一律写 for x in "$@"，这是唯一能保住参数边界的写法。

7.2 $# 与 $n #

bash
#!/bin/bash
if [ $# -lt 2 ]; then
    echo "用法: $0 源目录 目标目录" >&2
    exit 1
fi
echo "第一个参数: $1"
echo "共 $# 个参数"

参数多于九个，第十个写 ${10}，$10 会被解释成 $1 后面跟一个 0。shift 把参数列表左移一位，原来的 $2 变成 $1，$# 减一：

bash
echo "$1"
shift
echo "$1"

7.3 $? 与 $$、$! #

bash
ls /etc/passwd > /dev/null; echo "$?"            # 0
ls /no/such/file > /dev/null 2>&1; echo "$?"     # 2

$? 每次命令执行后都会被覆盖，判断前中间不能插别的命令：

bash
grep -q "root" /etc/passwd
echo "找到了吗"           # echo 把 $? 覆盖成 0
if [ $? -eq 0 ]; then     # 这里判断的已经是 echo 的结果

$$ 是当前 shell 的 PID，写临时文件名常用它防冲突。$! 是后台任务的 PID：

bash
echo "当前 shell PID: $$"
sleep 30 &
echo "后台任务 PID: $!"
wait

八、字符串操作 #

字符串是 Shell 唯一真正常用的数据类型。单引号、双引号、不加引号，行为完全不同。

8.1 引号差异 #

写法 变量展开 命令替换 转义字符 通配符 空白处理
'text' 不展开 不执行 原样 不展开 整体一个词
"text" 展开 执行 生效 不展开 整体一个词
text 展开 执行 生效 展开 按空白切词

规则背下来：单引号里任何字符原样输出，变量无效；单引号里不能出现单引号，加转义也不行；双引号里可以有变量，也可以有转义字符。

不加引号最危险，它会做分词和通配展开：

bash
name="a b"
for f in $name; do echo "[$f]"; done      # [a] [b]
for f in "$name"; do echo "[$f]"; done    # [a b]

变量一律加双引号，除非你明确要分词。

未加引号的词还会做通配展开：* 任意长度任意字符，? 单个字符，[abc] 括号里任一个，[a-z] 范围内任一个，[^abc] 排除这些。ls file[3-4][5-9].c 是两个位置各取范围内一个字符。for f in $* 里带 * 的值会被展开成文件名列表，要原样传就加引号。

8.2 转义与输出 #

bash
a=10
echo -e "Value of a is $a \n"    # 换行生效
echo "Value of a is $a \n"       # 原样输出 \n
printf "Value of a is %s\n" "$a"  # 更可控的写法

echo -e 才解释 \n、\t。要精确控制格式就用 printf。

8.3 长度、切片、替换 #

bash
s="hello world"
echo "${#s}"        # 11
echo "${s:0:5}"     # hello
echo "${s:6}"       # world
echo "${s: -3}"     # rld，负偏移前面要有空格

按路径裁剪和替换：

bash
f="/var/log/nginx/access.log"
echo "${f/nginx/apache}"    # /var/log/apache/access.log，只换第一处
echo "${f//l/L}"            # 全部替换
echo "${f#*/}"              # var/log/nginx/access.log，去掉最短前缀
echo "${f##*/}"             # access.log，去掉最长前缀
echo "${f%.*}"              # /var/log/nginx/access，去掉最短后缀
echo "${f%/*}"              # /var/log/nginx，去掉最长后缀

# 从左边切，% 从右边切，单个符号取最短匹配，双写取最长匹配。取文件名用 ${f##*/}，取扩展名用 ${f##*.}。

bash 4 起有大小写转换：

bash
v="Hello"
echo "${v^^}"    # HELLO
echo "${v,,}"    # hello

8.4 变量替换：默认值 #

形式 说明
${var} 变量本来的值
${var:-word} var 为空或未定义时返回 word，不改变 var
${var:=word} var 为空或未定义时返回 word，并把 var 设成 word
${var:?message} var 为空或未定义时把 message 送到 stderr，脚本退出
${var:+word} var 已定义时返回 word，不改变 var 
bash
unset PORT
echo "${PORT:-8080}"    # 8080
echo "${PORT}"          # 空，PORT 没被改
echo "${PORT:=8080}"    # 8080
echo "${PORT}"          # 8080，赋值了
: "${TOKEN:?TOKEN 未设置，退出}"    # 必填参数检查，顺手把脚本停掉

8.5 命令替换 #

bash
now=$(date +%F)      # 推荐
now=`date +%F`       # 反引号，Esc 键下方，和 ~ 同一个键
echo "$(basename "$(pwd)")"    # $() 能嵌套，反引号不能

命令替换把命令的标准输出变成一个字符串，塞进当前命令的参数位置。ls \pwd`就是把当前路径作为参数交给ls`。它和管道不同：管道传数据流，命令替换传一段文本。

九、数组 #

bash 支持一维数组，不支持多维，长度不限。下标从 0 开始，可以是整数，也可以是算术表达式。

bash
#!/bin/bash
arr=(alpha beta gamma)      # 括号定义，空格分隔
echo "${arr[0]}"            # alpha，下标 0 才是第一个
echo "${arr[2]}"            # gamma

arr2[0]=zero; arr2[5]=five  # 逐个赋值，下标可以不连续
echo "${arr2[@]}"           # zero five

读全部元素：

bash
echo "${arr[@]}"            # 每个元素一个词
echo "${arr[*]}"            # 拼成一个字符串
echo "${#arr[@]}"           # 元素个数
echo "${#arr[1]}"           # 第 1 个元素的长度
echo "${!arr2[@]}"          # 所有存在的下标：0 5

遍历要加引号，否则带空格的元素会被拆开：

bash
for x in "${arr[@]}"; do
    echo "元素: $x"
done

追加与切片：

bash
arr+=(delta)                # 追加一个元素
echo "${arr[@]:1:2}"        # beta gamma，从下标 1 取 2 个
unset 'arr[1]'              # 删一个元素，注意引号，否则 ] 被当通配符

${#arr[@]} 数的是元素个数，不是最大下标加一。arr2 有下标 0 和 5，长度是 2。稀疏数组别用长度当循环上界。

bash 4 起有关联数组，也就是键值对：

bash
declare -A conf
conf[host]="127.0.0.1"
conf[port]=8080
echo "${conf[host]}:${conf[port]}"
for k in "${!conf[@]}"; do
    echo "$k = ${conf[$k]}"        # 遍历顺序不保证
done

十、算术运算 #

三种写法，优先用第一种。

bash
#!/bin/bash
a=10
b=3

echo $((a + b))        # 13，算术扩展，变量名不用加 $
echo $((a / b))        # 3，整数除法，小数部分直接砍掉
echo $((a % b))        # 1
echo $((2 ** 10))      # 1024
echo $((16#ff))        # 255，支持进制
c=$((a * b)); echo "$c"

$(( )) 里写变量名不用加 $，$(( $a + $b )) 也能跑，多写两个没必要。

let 适合自增和复合赋值：

bash
n=1
let n++
let n+=10
echo "$n"              # 12

expr 是老写法，要空格、要反引号、乘号要转义：

bash
#!/bin/bash
val=`expr 2 + 2`
echo "value : $val"        # value : 4
val=`expr 2 \* 2`
echo "value : $val"        # value : 4

三个容易踩的点：表达式和运算符之间必须有空格，2+2 会原样输出 2+2；整个表达式要被反引号包起来；乘号 * 必须写成 \*，否则被当通配符展开。

运算符 含义
+ - * / 加减乘除，除法取整
% 取余
= 赋值
== != 相等、不等（在 (( )) 里用于判断）
+= -= *= /= 复合赋值
++ -- 自增自减
** 幂

Shell 的算术只有整数，要小数用 bc 或 awk：

bash
echo "scale=2; 10/3" | bc        # 3.33
awk 'BEGIN{printf "%.2f\n", 10/3}'

随机数用 $RANDOM，范围 0 到 32767：

十一、条件判断：test 与 [[ ]] #

条件判断的本质是执行一个命令，看它的退出状态。0 是真，非 0 是假。[ 本身就是一个命令（也叫 test），所以方括号两边必须有空格，[$a -eq 1] 会报 command not found。

写法 说明
test -f file 原始命令形式
[ -f file ] 同 test，靠 ] 收尾，POSIX 通用
[[ -f file ]] bash 关键字，支持 &&、` 
bash
[ -d /etc/fstab ]; echo $?       # 1，不是目录
[ -d /etc ]; echo $?             # 0，是目录
[[ -d /etc ]] && echo ok

11.1 文件测试 #

操作符 作用
-b file 块设备文件
-c file 字符设备文件
-d file 目录
-e file 存在，含目录
-f file 普通文件，不是目录也不是设备
-g file 设置了 SGID 位
-k file 设置了粘着位 Sticky Bit
-p file 具名管道
-u file 设置了 SUID 位
-r file 当前用户可读
-w file 当前用户可写
-x file 当前用户可执行
-s file 文件大小大于 0
-L file 符号链接

11.2 数字比较 #

关系运算符只比数字，比字符串会按字符串规则出错。

操作符 含义
-eq 等于
-ne 不等于
-gt 大于
-lt 小于
-ge 大于等于
-le 小于等于 
bash
[ 10 -eq 10 ] && echo $?          # 0
FreeMem=$(free -m | grep Mem: | awk '{print $4}')
[ "$FreeMem" -lt 1024 ] && echo "Insufficient Memory"

[ 10 -eq 10 ] 的 10 后面必须有空格，[ 10-eq 10 ] 会被当成一个参数。

11.3 字符串比较 #

操作符 含义
= 或 == 内容相同
!= 内容不同
-z 长度为 0，即空串
-n 长度不为 0
str 单独一个字符串，非空即为真 
bash
S=""
[ -z "$S" ] && echo "空串"
NAME="root"
[ "$NAME" = "root" ] && echo "是 root"

变量放在比较符号左边时必须加引号。[ $S = "x" ] 在 S 为空时展开成 [ = "x" ]，直接语法错误。

11.4 逻辑组合 #

写法 含义
&& 与，前面成功才执行后面
|| 或，前面失败才执行后面
! 非，取反
-a 与，老 test 写法
-o 或，老 test 写法 
bash
[ -f /etc/passwd ] && [ -r /etc/passwd ] && echo "可读"
[[ -f /etc/passwd && -r /etc/passwd ]] && echo "可读"
[[ ! -d /etc/fstab ]] && echo "不是目录"

&&、|| 组合的是命令，-a、-o 组合的是 test 的参数。[[ ]] 里用 && 更清晰。

[[ ]] 还支持正则匹配，右侧写扩展正则：

bash
[[ "$file" =~ \.log$ ]] && echo "日志文件"
[[ "$host" =~ ^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$ ]] && echo "看起来是 IPv4"

用 =~ 时右侧不要加引号，加了引号就变成字面比较。

十二、if、case 与循环 #

12.1 if #

三种形态：if ...; then ...; fi、加 else、加 elif。then 可以另起一行，也可以写成 ; then，fi 收尾不能省。

bash
#!/bin/bash
if [ -f "example.txt" ]; then echo "文件存在"; else echo "文件不存在"; fi

12.2 case #

多分支选择，比一串 if/elif 干净：

bash
case "$var" in
    1)     echo "一" ;;
    2|3|4) echo "二三四" ;;
    *)     echo "其他" ;;
esac

取值后面必须跟关键字 in，每个模式以右括号结束，模式之间用 | 表示或，;; 相当于 break，跳到整个 case 末尾，* 兜底放在最后。匹配到第一个模式就执行并跳出，后面的不再检测。

bash
#!/bin/bash
read -p "请输入一个字符，并按 Enter 键确认：" KEY
case "$KEY" in
    [a-z]|[A-Z]) echo "输入的是字母。" ;;
    [0-9])       echo "输入的是数字。" ;;
    *)           echo "输入的是空格、功能键或其他控制字符。" ;;
esac

12.3 for #

bash
#!/bin/bash
for num in 1 2 3 4 5; do           # 列表遍历，每个值以空格分隔
    echo "当前数字是 $num"
done

for ((i = 0; i < 5; i++)); do      # C 风格计数循环
    echo "i=$i"
done

in 省略时，列表默认是位置参数，等价于 for var in "$@"，写成 for var; do echo "$var"; done。

列表是一组用空格分隔的值，每循环一次取下一个赋给变量。列表来自命令输出时要看清分隔符，文件名带空格会在这里出问题：

bash
#!/bin/bash
HLIST="www.baidu.com"
for IP in $HLIST; do
    ping -c 3 -i 0.2 -W 3 "$IP" &> /dev/null
    if [ $? -eq 0 ]; then
        echo "$IP is online"
    else
        echo "$IP is offline"
    fi
done

12.4 while 与 until #

while 条件为真时继续，until 条件为假时继续，两者正好相反。while 用得多，until 很少见。

bash
#!/bin/bash
count=1
while [ $count -le 5 ]; do          # 条件为真就继续
    echo "当前计数是 $count"
    count=$((count + 1))
done

count=1
until [ $count -gt 5 ]; do          # 条件为真就停，与 while 相反
    count=$((count + 1))
done
echo "$count"                       # 6

逐行读文件：

bash
#!/bin/bash
while IFS= read -r line; do
    echo "读到: $line"
done < users.txt

IFS= 保住行首行尾的空格，-r 让反斜杠不被转义。这两个参数漏掉，读进来的内容会被悄悄改写。

while true 配 break、exit 做交互循环：

bash
while true; do
    read -p "输入内容（q 退出）：" ans
    [ "$ans" = "q" ] && break
    echo "你输入了 $ans"
done

12.5 break 与 continue #

break 跳出整个循环，continue 只跳过本次迭代剩下的部分。嵌套循环里都能跟一个数字，表示作用于第几层：

bash
#!/bin/bash
for i in 1 2 3; do
    for j in a b c; do
        [ "$j" = "b" ] && continue 2    # 跳过外层本次迭代，直接进下一轮
        [ "$i" = "3" ] && break 2       # 跳出两层
        echo "$i$j"
    done
done

十三、函数 #

13.1 定义与调用 #

函数定义是 名字() { 命令; }，function 关键字可省，写成 function 名字() { ... } 也认。调用只写函数名，不加括号：

bash
#!/bin/bash
Hello() {
    echo "hello, world"
}
Hello

Hello2() {
    echo "hello2, world"
    return 1
}
Hello2
echo "exit=$?"        # exit=1

函数定义写进 .profile 之类的登录配置，登录后就能在提示符下直接当命令敲。

13.2 参数 #

函数内部用 $n 取参数，和脚本的位置参数同一套规则：$1、$2 到 ${10}，$# 是参数个数，遍历用 "$@"，$? 是返回值。

bash
#!/bin/bash
add_fun() {
    echo "收到 $# 个参数，第一个: $1，全部: $@"
}
add_fun str1 str2 str3

13.3 返回值 #

返回值只有一条通道：退出状态，范围 0 到 255。0 表示成功，其他值表示失败。不写 return 时，函数最后一条命令的退出状态就是返回值。接收返回值用 $?。

bash
sum() { return $(($1 + $2)); }
sum 5 10; echo "$?"      # 15
sum 300 10; echo "$?"    # 54，310 取模 256

要返回字符串，return 会报 numeric argument required。正确做法是 echo 出来，用命令替换接：

bash
get_path() { echo "/var/log/nginx"; }
p=$(get_path); echo "$p"

13.4 局部变量与删除 #

函数里的 local 变量在「5.5 作用域三档」已经演过，出了函数就没了。删除函数用 unset -f：

bash
unset -f demo

13.5 文件包含 #

bash
. ./lib.sh
source ./lib.sh

两种写法效果相同，点号后面必须有一个空格。被包含的脚本不需要执行权限，它在当前 shell 里逐行执行，里面的变量和函数都留得下来。

十四、输入输出与重定向 #

14.1 read #

选项 作用
-p "提示" 显示提示语
-t 秒 等待超时，超时返回非 0
-n 数 读满指定字符数就返回
-s 不回显，输密码用
-r 反斜杠不转义
-a 数组 按 IFS 切分后存进数组 
bash
#!/bin/bash
read -p "请输入内容: " user_input
read -n 5 user_variable          # 只读 5 个字符
read -s -p "密码: " PASS         # 不回显
read -t 10 -p "10 秒内输入: " ANS

read 一次读一行，最后一个变量拿走剩下的全部内容，所以 read AA BB CC 输入 1 2 3 4 时，CC 拿到的是 3 4。

14.2 三个文件描述符 #

编号 名称 默认去向
0 标准输入 stdin 键盘
1 标准输出 stdout 终端
2 标准错误 stderr 终端

14.3 重定向符号 #

写法 作用
> file 标准输出写入 file，覆盖，不存在就新建
>> file 标准输出追加到 file
< file 把 file 当标准输入
2> file 标准错误写入 file
2>> file 标准错误追加到 file
&> file 正确和错误一起写入，等于 > file 2>&1
&>> file 正确和错误一起追加
n > file 文件描述符 n 重定向到 file
n >& m 把 n 合并到 m
n <& m 输入合并
<< tag here document，tag 之间的内容作为输入
<<< "str" here string，把字符串当输入 
bash
echo "hello world" > test        # 覆盖写入
echo "hello Eric" >> test        # 追加
ls /nope 2> err.log              # 错误进文件
./run.sh &> all.log              # 正确错误一起进文件
./run.sh > out.log 2>&1          # 同上，顺序不能反

2>&1 表示「把 stderr 指向 stdout 当前指向的地方」。写成 > out.log 2>&1 时，先把 stdout 指向文件，再把 stderr 指向同一个文件。反过来写 2>&1 > out.log，stderr 还指着终端，只有 stdout 进了文件。

here document，EOF 两侧不能有空格，写 <<'EOF' 则内容里不做变量展开：

bash
cat > /tmp/conf.txt <<EOF
host=127.0.0.1
port=8080
EOF

/dev/null 是黑洞，写进去的东西直接消失：

bash
command > /dev/null 2>&1        # 全部丢弃
cat /dev/null > ~/.bash_history # 清空文件内容
./build.sh 2>&1 | tee build.log # 屏幕和文件都要

十五、管道与命令替换 #

| 把左边命令的标准输出接到右边命令的标准输入。左边要有输出，右边要能读输入。

bash
ls /usr/bin | wc -l
ps -ef | grep nginx | grep -v grep

管道的各段同时启动，右边阻塞等左边的数据，数据流式通过，不会先攒成一整个大文件。

三种写法的数据流向不同：cmd1 | cmd2 把左输出送进右进程的 stdin，cmd > file 把输出写进文件，cmd < file 把文件内容送进 stdin。

管道有一个必须记住的坑：每一段都在子 shell 里执行，变量改了带不回来。

bash
#!/bin/bash
count=0
echo "a" | while read -r line; do
    count=$((count + 1))
done
echo "$count"        # 0，不是 1

count=0
while read -r line; do
    count=$((count + 1))
done < <(echo "a")
echo "$count"        # 1

命令替换的写法和嵌套规则在「8.5 命令替换」讲过，这里只强调区别：管道传的是数据流，命令替换传的是执行完的整段文本。能用 $() 就别用反引号，反引号里反斜杠的处理规则反直觉，还没法嵌套。

十六、文本处理：grep、sed、awk #

三个工具分工：grep 找行，sed 改行，awk 拆列。

工具 干什么 典型场景
grep 按模式过滤行 从日志里捞错误行
sed 按行做替换、删除、打印 批量改配置
awk 按字段切分、统计、格式化 取某一列、求和、报表

16.1 grep #

bash
grep "root" /etc/passwd              # 含 root 的行
grep -n "root" /etc/passwd           # 带行号
grep -i "error" app.log              # 忽略大小写
grep -v "INFO" app.log               # 反向，排除
grep -c "ERROR" app.log              # 只数行数
grep -r "listen 80" /etc/nginx/      # 递归目录
grep -E "error|warn|fatal" app.log   # 扩展正则
grep -w "root" /etc/passwd           # 全词匹配

-E 开扩展正则（|、+、?、() 不用转义），不加 -E 用基本正则，这些符号要加反斜杠。-F 表示纯字符串，不走正则。

在目录里挖内容，常和 find 搭：

bash
find ./ -name "*" -exec grep -n "string" {} \;
find . -type f -name "*.conf" -exec grep -n "port" {} \;

16.2 sed #

bash
sed 's/old/new/' file            # 每行第一处替换
sed 's/old/new/g' file           # 每行全部替换
sed -i 's/8080/9090/g' app.conf  # 直接改文件，没有备份
sed -i.bak 's/8080/9090/g' conf  # 先备份再改
sed -n '1,5p' file               # 只打印 1 到 5 行
sed '/^$/d' file                 # 删空行
sed '/^#/d' file                 # 删注释行
sed -n '/ERROR/p' app.log        # 打印匹配行
sed 's/^/  /' file               # 每行前面加两个空格
sed 's/$/;/' file                # 每行末尾加分号

sed 默认打印所有行，-n 关掉默认输出，配合 p 才只打印你要的。

16.3 awk #

bash
awk '{print $1}' file                    # 第一列
awk '{print $1, $3}' file                # 第一、三列
awk -F: '{print $1, $3}' /etc/passwd     # 冒号当分隔符
awk 'NR==1' file                         # 第一行
awk 'NR>2 && NR<6' file                  # 第 3 到 5 行
awk '/ERROR/' file                       # 匹配正则的行
awk '{sum += $2} END {print sum}' file   # 第二列求和
awk '{c[$1]++} END {for (k in c) print k, c[k]}' file
awk 'BEGIN{print "开始"} {print $1} END{print "结束"}' file

$0 是整行，$1 到 $n 是各字段，NF 是字段数，NR 是行号。-F 指定分隔符，不指定就按连续空白切分。

取出当前可用内存再判断够不够，这是 grep 加 awk 的经典组合：

bash
FreeMem=`free -m | grep Mem: | awk '{print $4}'`
[ $FreeMem -lt 1024 ] && echo "Insufficient Memory"

按第四列排序 /etc/passwd，-t: 指定冒号为分隔符，-k 4 取第四段，-n 按数值比较：

bash
cat /etc/passwd | sort -t: -k 4 -n

日志里按状态码统计次数：

bash
awk '{print $9}' access.log | sort | uniq -c | sort -rn | head

16.4 find 配套用法 #

bash
find /etc -type d -print                  # 只找目录
find /etc -name .svn -type d -print       # 找名为 .svn 的目录
find . ! -type d -print                   # 排除目录
find . -type l -print                     # 只找符号链接
find . -type f -exec ls -l {} \;          # 对每个文件执行 ls -l
find /app -name "/app/bin" -prune -o -print   # 跳过 /app/bin

-f 是普通文件，-d 是目录，-l 是符号链接，! 取反，-prune 让 find 不进入某个目录，-exec ... {} \; 对每个结果执行一次命令。

十七、脚本的调试与排错 #

先做语法检查再跟踪，两步都不改脚本本身：

bash
bash -n deploy.sh       # 只查语法
bash -x deploy.sh       # 打印每一行展开后的命令

脚本内部按段开关跟踪，只盯可疑的那一段：

bash
set -x
counter=$((counter + 1))
set +x

export PS4='+ [${LINENO}] ${FUNCNAME[0]:-main}: '   # 带行号和函数名

四个防护开关，写在脚本头部：

bash
#!/bin/bash
set -euo pipefail
开关 作用
set -e 任何命令返回非 0 就退出
set -u 引用未定义变量时报错退出，而不是展开成空
set -o pipefail 管道中任意一段失败，整条管道算失败
set -x 打印执行轨迹

set -e 有例外：if 条件、&&/|| 左侧、! 取反里的失败不会触发退出，这些位置本来就要看返回值。

定位哪一行出错，用 trap：

bash
trap 'echo "第 $LINENO 行失败，退出码 $?" >&2' ERR

常见退出码：0 成功，1 通用错误，2 用法错误，126 找到文件但没有执行权限，127 命令找不到，130 被 Ctrl+C 中断。脚本里判 $? 时，这几个值比 1 更值得单独处理。

脚本行为诡异时，先怀疑三件事：变量没值（set -u 能揪出来）、引号丢了导致分词、用了相对路径而当前目录不对。中间结果直接打出来看，比盯代码快：

bash
echo "DEBUG: pwd=$(pwd) files=$(ls | wc -l)" >&2

装了 shellcheck 就跑一遍，未加引号的变量、误用的 [、$? 被覆盖这类问题它都能报出来。

十八、易错点速查 #

症状 原因 写法
a: command not found 赋值号两边有空格 a="value"
变量值少了一截 变量名后直接接字面量 "${a}Script"
输出只剩第一个词 变量没加引号被分词 "$var"
方括号报 command not found [ 两边缺空格 [ -f "$f" ]
unary operator expected 空变量放进 [ ] [ -z "$v" ]
循环里累加器始终为 0 管道子 shell 改了副本 done < <(...)
数字比较不走数值 用了 = 比数字 [ "$a" -eq "$b" ]
函数 return 字符串报错 return 只能 0-255 echo 出来配合 $()
改了配置没生效 没 source，或改错文件 source ~/.bashrc
脚本换台机器跑不起来 shebang 找不到解释器 #!/usr/bin/env bash
source 报文件找不到 点号后面少了空格 . ./lib.sh
$? 判断错了 中间插了别的命令 紧跟着判断
文件名带空格被拆开 用了 $(ls) 或 $* "$@"、find -print0
读文件丢首尾空格 read 没加 -r、没清 IFS while IFS= read -r line
浮点运算出 0 Shell 只算整数 bc 或 awk

几条收尾习惯。变量引用一律加双引号，除非你在遍历列表。命令替换用 $()，别用反引号。脚本开头写 set -euo pipefail，把错误尽早暴露，别让它跑到后面变成另一个现象。写临时文件用 mktemp，别硬编码 /tmp/a.txt，多开几次就撞了。

删文件前先 echo 一遍路径。rm -rf "$dir"/ 里的 dir 为空时，那行命令会删掉根目录下的东西，动手前先判断 [ -n "$dir" ]。
