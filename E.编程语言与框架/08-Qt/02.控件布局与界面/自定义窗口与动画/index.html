本篇讲两件事：不走系统标题栏的自定义窗口怎么搭，界面进出场与滚动字幕这类动画怎么写。 讲什么：FramelessWindowHint 去边框、无边框后的拖动、自绘标题栏按钮、最小化最大化关闭、阴影圆角、掉到任务栏下面的复位、QPropertyAnimation 淡入淡出、滚动字幕的字符法与像素法。 不讲什么：QSS 选择器语法、布局管理器的细节、图形视图框架、窗口嵌入。这些各有专篇。 跨篇指路：样式表看《样式表完整指南》，窗口透明看《窗体透明》与《半透明》，阴影看《再谈阴影边框》，布局看《容器与布局管理》。

一、为什么要自定义窗口 #

系统标题栏是窗口管理器画的，不是 Qt 画的。它的颜色、高度、按钮位置由系统主题决定，你的 QSS 管不到。想做出和设计稿一致的界面，第一刀就是砍掉它。

cpp
this->setWindowFlags(Qt::FramelessWindowHint);

一行代码，标题栏没了。代价从这里开始。

去掉边框不只少了一条灰条。窗口管理器顺手撤走的还有一整串交互能力，这些原本你一行代码都不用写。

能力 有系统标题栏 设了 FramelessWindowHint
按住标题栏拖动移动 系统提供 自己实现
边缘/角落拖拽缩放 系统提供 自己实现
拖到屏幕边缘吸附分屏 系统提供 自己实现
双击标题栏最大化/还原 系统提供 自己实现
最小化、最大化、关闭按钮 系统提供 自己绘制并连槽
右键标题栏弹出系统菜单 系统提供 自己拼菜单
任务栏悬停预览、Aero Snap 系统提供 多数场景会退化
外观可控程度 低 完全可控
需要写的代码量 0 行 几百行

这张表的右列就是自定义窗口的主要成本。产品说「标题栏太丑，换掉」，你要接的其实是右列一整条清单。

先问一句：真的需要整窗自绘吗。分三种情况。

  • 只想去掉标题栏的颜色和图标，按钮还要系统的：用 Qt::CustomizeWindowHint 配合保留按钮位，只关掉标题栏绘制，改动最小。
  • 登录框、启动页、悬浮工具条、播放器控制条：整窗自绘合理，控件少，交互简单。
  • 主窗口带完整菜单、工具栏、多文档：要连带补上缩放、吸附、最大化还原、系统菜单，工作量大，先算清楚。

本篇按最难的一档走，把该补的交互都补齐。你按需取用。

二、去掉系统边框 #

窗口初始化的地方设标志位。两个标志各有分工。

cpp
// 窗口初始化时调用，一般在构造函数里
this->setWindowFlags(Qt::FramelessWindowHint          // ① 去掉标题栏与窗口边框
                   | Qt::WindowStaysOnTopHint);        // ② 锁定窗口浮在任务栏之上

// 开启鼠标跟踪。不设的话，没有按键按下时 mouseMoveEvent 不触发
this->setMouseTracking(true);

Qt::WindowStaysOnTopHint 不是可选项。只设 FramelessWindowHint 时，用户能把窗口拖进任务栏区域下方，窗口被任务栏盖住，点不回来，只能去任务管理器结束进程。这个 hint 让窗口始终在任务栏之上。

setMouseTracking(true) 解决另一个坑：Qt 默认只在有按键按下时才发 mouseMoveEvent。拖动靠按键触发不假，但悬停高亮、边缘光标切换都要无按键的移动事件。

还有几处必须交代。

  • setWindowFlags() 在窗口 show() 之后再调用，窗口会先隐藏，要重新 show()。写在构造函数里没这个问题。
  • 要半透明或圆角时加 setAttribute(Qt::WA_TranslucentBackground)。不加，背景画不出透明，圆角外面是一块黑或灰。细节在第六章。
  • QDialog 默认按 Esc 会 reject()，改无边框后这个行为还在，不想留就重写 keyPressEvent()。
  • 标志位在窗口创建前定好。运行中反复改 windowFlags 会重建原生窗口句柄，位置和焦点跟着丢。

只想砍掉标题栏绘制、保留系统按钮区，把两个 hint 换成 CustomizeWindowHint | WindowMinimizeButtonHint | WindowCloseButtonHint 这一组。按钮还是系统画的，位置由主题定，QSS 依然插不上手。它是过渡方案。

三、无边框窗口的拖动实现 #

边框没了，拖动自己接。原理很短：按下时记住鼠标在窗口里的相对位置，移动时用鼠标的屏幕坐标减掉这个偏移，得到窗口该去的新左上角。

头文件先声明。三个事件都要 override，少一个拖动就断。

cpp
class LoginDialog : public QDialog
{
    Q_OBJECT
protected:
    void mousePressEvent(QMouseEvent *event)   override;
    void mouseMoveEvent(QMouseEvent *event)    override;
    void mouseReleaseEvent(QMouseEvent *event) override;

private:
    QPoint m_movePoint;    // 按下时鼠标相对窗口左上角的偏移
    bool   m_mousePressed; // 左键是否按住
};

实现三个事件。

cpp
// ① 按下：记录鼠标相对窗口客户区的偏移
void LoginDialog::mousePressEvent(QMouseEvent *event)
{
    if (event->button() == Qt::LeftButton)
    {
        m_mousePressed = true;
        // event->pos() 是相对窗口客户区的局部坐标
        // 等价于 event->globalPos() - this->pos()
        m_movePoint = event->pos();
    }
}

// ② 移动：算出新位置并挪窗口
void LoginDialog::mouseMoveEvent(QMouseEvent *event)
{
    if (m_mousePressed)
    {
        // event->globalPos() 是鼠标在整个屏幕坐标系里的绝对坐标
        QPoint globalPos = event->globalPos();

        // 新窗口左上角 = 鼠标全局坐标 - 按下时记下的偏移
        this->move(globalPos - m_movePoint);
    }
}

// ③ 松开：结束拖动
void LoginDialog::mouseReleaseEvent(QMouseEvent *event)
{
    Q_UNUSED(event);
    m_mousePressed = false;
}

构造函数里补一句 m_mousePressed = false;。漏了这句，这个 bool 是未初始化的栈内存，值为 true 时窗口会在鼠标刚移进来时自己乱飞。这是这个方案最高频的翻车点。

拖动三步压成一张表。

步骤 触发时机 要算的量 用的坐标
记录 mousePressEvent 鼠标相对窗口左上角的偏移 event->pos() 局部坐标
计算 mouseMoveEvent 新左上角 = 全局鼠标 − 偏移 event->globalPos() 屏幕坐标
结束 mouseReleaseEvent 清标志位 不用坐标

坐标系转换是这段代码唯一的难点。 用错不报错，只会让窗口跳。四个坐标先分清。

写法 含义 用途
event->pos() 鼠标相对本控件左上角 记偏移
event->globalPos() 鼠标相对屏幕左上角 算新位置
this->pos() 窗口左上角相对屏幕，不含边框 换算、复位
QCursor::pos() 当前鼠标的屏幕坐标 不在事件里时的取法

globalPos() - pos() 就等于 event->pos()，这个恒等式就是整段逻辑的根据。写的时候两个坐标必须成对：记偏移用局部，算位置用全局。混着来就跳。按下时忘了记偏移、或者移动时直接 move(event->pos())，窗口左上角会瞬移到鼠标处；用了 frameGeometry() 却用 move() 设置，会差出一个标题栏高度。

拖动逻辑放在窗口类上有个隐含前提：鼠标事件得能到窗口。标题栏一旦做成子控件（比如 QWidget *titleBar），事件被子控件吃掉，父窗口的 mousePressEvent 收不到。两条路：给子控件装 installEventFilter(this)，把按下/移动/松开用 QApplication::sendEvent(this, event) 转给窗口；或者子类化标题栏，自己发「被拖了」的信号。前者改动小，后者结构清楚。

移动事件里再加一个 event->buttons() & Qt::LeftButton 判断，比只信 m_mousePressed 更保险，能兜住「按下后跑到别的窗口松开」导致标志位漏掉的情况。坐标也可以直接读 QCursor::pos()，拖动期间与 event->globalPos() 等价。

四、自绘标题栏与按钮 #

按钮得自己造。QToolButton 比 QPushButton 合适：更紧凑，图标居中，没有多余内边距。

cpp
void MainWidget::initTitleButtons()
{
    int w = this->width();  // 当前窗口宽度

    // 1. 建按钮，父对象设成窗口自己
    QToolButton *minButton   = new QToolButton(this);
    QToolButton *closeButton = new QToolButton(this);

    // 2. 借系统主题取标准图标，省得自己画
    minButton->setIcon(style()->standardPixmap(QStyle::SP_TitleBarMinButton));
    closeButton->setIcon(style()->standardPixmap(QStyle::SP_TitleBarCloseButton));

    // 3. 相对窗口右上角硬定位，(x, y, w, h)
    minButton->setGeometry(w - 46, 5, 20, 20);
    closeButton->setGeometry(w - 25, 5, 20, 20);

    // 4. 悬停提示
    minButton->setToolTip(tr("最小化"));
    closeButton->setToolTip(tr("关闭"));

    // 5. 扁平化：透明底、无边框
    const char *flat = "QToolButton{ background-color: transparent; border: none; }";
    minButton->setStyleSheet(flat);
    closeButton->setStyleSheet(flat);

    // 6. 连到窗口自带的槽
    connect(minButton,   &QToolButton::clicked, this, &QWidget::showMinimized);
    connect(closeButton, &QToolButton::clicked, this, &QWidget::close);
}

style()->standardPixmap() 从当前系统主题取标准图标，比自己切图省事，风格还跟系统一致。它取的是位图，缩放会糊，高分屏或自定义视觉还是得用 SVG。

第 3 步的硬编码坐标有个前提：窗口宽度固定。窗口能缩放时，w - 46 只在初始化那一刻对，拉宽后按钮跑到中间。resizeEvent() 里补一次重定位能救，不是好办法。

用布局更稳。右侧留白交给 addStretch()，按钮自然贴右，窗口拉宽拉窄都不用管。

cpp
QWidget *titleBar = new QWidget(this);
titleBar->setFixedHeight(32);

QHBoxLayout *lay = new QHBoxLayout(titleBar);
lay->setContentsMargins(8, 0, 8, 0);
lay->setSpacing(4);
lay->addWidget(new QLabel(tr("登录"), titleBar));
lay->addStretch();   // 把后面的按钮顶到右边

minBtn = new QToolButton(titleBar);
minBtn->setIcon(style()->standardPixmap(QStyle::SP_TitleBarMinButton));
minBtn->setStyleSheet("QToolButton{ background: transparent; border: none; }"
                      "QToolButton:hover{ background: rgba(255,255,255,0.25); }");
connect(minBtn, &QToolButton::clicked, this, &QWidget::showMinimized);

closeBtn = new QToolButton(titleBar);
closeBtn->setIcon(style()->standardPixmap(QStyle::SP_TitleBarCloseButton));
closeBtn->setStyleSheet(minBtn->styleSheet());
connect(closeBtn, &QToolButton::clicked, this, &QWidget::close);

lay->addWidget(minBtn);
lay->addWidget(closeBtn);

按钮尺寸随字体和主题走，改个字也不会错位。

窗口背景有三种铺法。

方案一，QLabel 贴图。最直接。

cpp
QLabel *background = new QLabel(this);

background->setPixmap(QPixmap(":/images/login_bg.png"));
background->setGeometry(0, 0, this->width(), this->height());
background->setScaledContents(true);   // 图片自适应 QLabel 尺寸
background->lower();                   // 压到最底层，别挡住输入框

lower() 这行不能省。不加它，背景会盖在表单上面，界面看起来像空的。

方案二，QLabel 加 QSS 纯色。不要图片只要主题色时用它：同样建一个底层 QLabel，setGeometry() 铺满，setStyleSheet("background-color: rgb(240, 248, 255);")，再 lower()。

方案三，重写 paintEvent() 直接画。窗口能被拉大拉小时走这条，QLabel 拉伸会糊，尺寸变化还得手动同步 setGeometry。

cpp
// 头文件里声明
protected:
    void paintEvent(QPaintEvent *event) override;

// 源文件里实现
void MainWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);

    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing);   // 圆角和图片边缘才平滑

    QPixmap pixmap(":/images/login_bg.png");
    painter.drawPixmap(this->rect(), pixmap);        // 按当前 rect 拉伸，跟着尺寸走
}
方案 代码量 尺寸自适应 像素质量 适合
QLabel 贴图 最少 需手动同步 拉伸易糊 固定尺寸的登录框
QLabel + QSS 纯色 最少 需手动同步 纯色无所谓 扁平主题
重写 paintEvent 中等 天然自适应 可控 可缩放窗口

paintEvent 这条路还能往下走。圆角、半透明玻璃、渐变、描边，都在这里一次画完。第六章接着讲。

五、最小化、最大化、关闭 #

三个动作都有现成的槽，直接用。

cpp
showMinimized();  // 最小化到任务栏
showMaximized();  // 最大化，铺满可用区域
showNormal();     // 从最小化或最大化还原
close();          // 请求关闭，会走 closeEvent

最小化和关闭是单行道，接上就完事。最大化不是，得能来回切。

cpp
void MainWidget::onMaxButtonClicked()
{
    if (isMaximized())
        showNormal();     // 已在最大化，还原
    else
        showMaximized();
}

图标和状态要同步。在 changeEvent() 里听 WindowStateChange，比在每个按钮槽里手写一遍可靠。

cpp
void MainWidget::changeEvent(QEvent *event)
{
    if (event->type() == QEvent::WindowStateChange) {
        if (isMaximized()) {
            m_maxBtn->setIcon(QIcon(":/icons/restore.svg"));
            m_maxBtn->setToolTip(tr("还原"));
        } else {
            m_maxBtn->setIcon(QIcon(":/icons/max.svg"));
            m_maxBtn->setToolTip(tr("最大化"));
        }
    }
    QWidget::changeEvent(event);
}

双击标题栏最大化，系统不再提供，得自己补。 用户按这个习惯天天用，无边框之后最容易被漏掉。在 eventFilter 里接 MouseButtonDblClick，判左键后走 onMaxButtonClicked()，返回 true 把事件吃掉。

细节：MouseButtonDblClick 之前一定先来一个 MouseButtonPress，拖动逻辑已经记过一次偏移。所以拖动只在移动超过阈值（比如 4 像素）后才真正 move()，双击前窗口就不会被挪走一小段。

关闭按钮连 close()，不连 qApp->quit()。前者只关这一个窗口，还能被 closeEvent 拦下来做确认；后者直接退进程，多窗口一关全没。

cpp
void MainWidget::closeEvent(QCloseEvent *event)
{
    if (m_hasUnsaved) {                     // 有未保存内容先问一句
        if (QMessageBox::question(this, tr("确认"),
                                  tr("内容还没保存，确定退出？"))
            != QMessageBox::Yes) {
            event->ignore();                // 拦下，窗口留着
            return;
        }
    }
    saveGeometrySettings();
    event->accept();
}

位置记忆用 saveGeometry() / restoreGeometry()，不用自己存 x/y/w/h。

cpp
QSettings settings("MyCompany", "MyApp");
settings.setValue("mainWindow/geometry", saveGeometry());           // 关闭时写
restoreGeometry(settings.value("mainWindow/geometry").toByteArray()); // 启动时读

顺序有讲究：restoreGeometry() 放在 show() 之前，放后面会先闪一下默认位置再跳过去。

有托盘图标时，关闭按钮的语义要改：调 hide() 收进托盘，再 event->ignore() 拦下这次关闭。托盘菜单里必须补一个「退出」项，把标志位（比如 m_reallyQuit）置真后走 qApp->quit()。不给这个出口，用户点关闭就再也找不回窗口了。

六、窗口阴影与圆角 #

系统标题栏被砍掉时，窗口投影也一起没了。深色桌面上一块无边框矩形会显得很飘，看不出边界。阴影和圆角得自己画。

前提两行，缺一不可。

cpp
setAttribute(Qt::WA_TranslucentBackground);   // 让窗口背景能透出桌面
setWindowFlags(Qt::FramelessWindowHint);      // 去掉系统边框

只设 WA_TranslucentBackground 不设 FramelessWindowHint，系统边框还在，透明只作用在客户区，看起来像窗口里挖了个洞。

圆角用 paintEvent 画，QPainterPath 裁一个圆角矩形。

cpp
void MainWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);

    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing);

    QPainterPath path;
    path.addRoundedRect(this->rect(), 12, 12);   // 半径 12

    painter.setClipPath(path);                   // 之后画的内容都落在圆角内
    painter.fillPath(path, QColor(250, 250, 252));

    painter.setPen(QPen(QColor(0, 0, 0, 40), 1));  // 浅描边，边界更清楚
    painter.drawPath(path);
}

setClipPath() 只裁画笔，不裁子控件。窗口里放列表、表格这类控件时，四个角还是会被它们盖住。解法是给内容区留出圆角半径的内边距，让控件不贴到角上。

阴影有三条路。

做法 效果 代价 适合
QGraphicsDropShadowEffect 柔和投影 窗口要留外边距 中小窗口
手绘多层半透明圆角矩形 完全可控 自己调层数和透明度 视觉要求高
setMask(QRegion) 裁形状 硬边裁剪 无抗锯齿，边缘有锯齿 只做异形

QGraphicsDropShadowEffect 最省事，但它画到窗口矩形之外的部分会被裁掉，而顶层窗口自己就是边界。解法是套一层：外层窗口透明留边距，内层容器才是真内容。

cpp
QWidget *outer = new QWidget;                       // 外层只负责托住阴影
outer->setAttribute(Qt::WA_TranslucentBackground);
outer->setWindowFlags(Qt::FramelessWindowHint);

QWidget *inner = new QWidget(outer);                 // 内层是真内容
inner->setStyleSheet("background: white; border-radius: 12px;");

QGraphicsDropShadowEffect *shadow = new QGraphicsDropShadowEffect(inner);
shadow->setBlurRadius(24);
shadow->setColor(QColor(0, 0, 0, 90));
shadow->setOffset(0, 4);
inner->setGraphicsEffect(shadow);

QHBoxLayout *lay = new QHBoxLayout(outer);
lay->setContentsMargins(20, 20, 20, 20);   // 这 20 像素就是阴影的落脚处
lay->addWidget(inner);

setContentsMargins() 的值要大于 blurRadius() 的一半左右，不然阴影还是被切。四边阴影厚薄不一，多半是 margin 给偏了。

手绘阴影用于视觉要求高又不想要嵌套结构的地方。思路是多画几层，一层比一层大、一层比一层淡，最里面那层是实底。

setMask() 那条只建议用在异形窗口（圆形、十字、贴图片轮廓）。它按 1 位掩码裁，边缘没有过渡，圆角是一格一格的。半径小于 8 像素勉强能看，大半径别用。

七、拖动到任务栏之上的复位 #

无边框窗口有个独有事故：拖到屏幕底部松手，窗口大半沉到任务栏下面。标题栏看不见，也没有系统吸附把它拉回来。

根子在标志位。补 Qt::WindowStaysOnTopHint 能解决大部分情况，窗口拖不过任务栏。

cpp
this->setWindowFlags(Qt::FramelessWindowHint | Qt::WindowStaysOnTopHint);

它有副作用：窗口压在所有普通窗口上面，用户切到浏览器它还在最前。登录框、悬浮球、提示条合适，主窗口不合适。

主窗口走另一条：松手时检查位置，跑出可用区域就拉回来。

三个屏幕矩形先分清。

接口 含义 差在哪
screen->geometry() 整块屏幕 含任务栏占的那一条
screen->availableGeometry() 可用区域 排除了任务栏、Dock
QGuiApplication::screens() 所有屏幕 多屏场景要遍历

判断用 availableGeometry()。用 geometry() 判断的话，窗口落在任务栏那条上照样算「在屏幕内」，用户还是够不着。

cpp
void MainWidget::clampToScreen()
{
    // 取窗口当前所在屏幕，取不到就退回主屏
    QScreen *screen = QGuiApplication::screenAt(frameGeometry().center());
    if (!screen)
        screen = QGuiApplication::primaryScreen();
    if (!screen)
        return;

    const QRect avail = screen->availableGeometry();
    QRect win = frameGeometry();

    if (win.right() < avail.left())          // 完全跑出左边
        win.moveLeft(avail.left());
    else if (win.left() > avail.right())     // 完全跑出右边
        win.moveRight(avail.right());
    if (win.bottom() > avail.bottom())       // 沉到任务栏下面，往上提
        win.moveBottom(avail.bottom());
    if (win.top() < avail.top())             // 标题栏跑出去就拖不回来了
        win.moveTop(avail.top());

    if (win.topLeft() != frameGeometry().topLeft())   // 有变化才移动
        move(win.topLeft());
}

接入点就是拖动结束：mouseReleaseEvent 里把 m_mousePressed 清掉后调一次 clampToScreen()。

比整窗判断更温和的一条：只要求标题栏留 40 像素可见。把标题栏矩形 QRect(mapToGlobal(QPoint(0, 0)), QSize(width(), m_titleBar->height())) 与 avail 做一次 intersects()，不相交就把窗口横向挪回 avail 中央。窗口允许大半在屏幕外，符合真实使用习惯。

多屏容易漏一点：QGuiApplication::screenAt() 收的是全局坐标，传相对坐标会一直返回空。frameGeometry().center() 是全局坐标，能直接用。

八、窗口的显示与隐藏动画 #

窗口「啪」一下弹出、「啪」一下消失，观感生硬。开场淡入、关闭淡出，是客户端里最便宜的一档质感提升。

先看反例，这写法在问答区出现频率不低。

cpp
// 错误做法：用 for 循环硬改透明度
void LoginDialog::closeEvent(QCloseEvent *event)
{
    for (int i = 0; i < 100000; i++)
    {
        if (i < 10000)        this->setWindowOpacity(0.9);
        else if (i < 20000)   this->setWindowOpacity(0.8);
        // ... 依次往下
        else                  this->setWindowOpacity(0.0);
    }
    QApplication::quit();
}

两个致命问题。

  • 阻塞 GUI 主线程。for 循环占满主事件循环，期间一次 paintEvent 都排不进去。用户看不到渐变，只看到窗口卡住一秒然后突然消失。
  • 空转烧 CPU。十万次无意义的自增和赋值，单核瞬间飙满，笔记本风扇立刻响。

真正要的是「非阻塞地、按时间推进地改一个值」。Qt 的动画子系统干的就是这个。

QPropertyAnimation 动态改窗口的 windowOpacity 属性（0.0 全透明，1.0 全不透明），挂在事件循环上，每帧推进一点。

淡入，构造函数末尾启动。

cpp
MainWidget::MainWidget(QWidget *parent)
    : QWidget(parent)
{
    ui->setupUi(this);

    // 0.0 全透明 -> 1.0 完全显示
    QPropertyAnimation *fadeInAnim = new QPropertyAnimation(this, "windowOpacity");
    fadeInAnim->setDuration(800);                    // 800 毫秒
    fadeInAnim->setStartValue(0.0);
    fadeInAnim->setEndValue(1.0);
    fadeInAnim->setEasingCurve(QEasingCurve::InOutQuad);   // 二次缓入缓出

    fadeInAnim->start(QAbstractAnimation::DeleteWhenStopped);
}

start() 的 DeleteWhenStopped 参数很关键。动画对象是 new 出来的，不传它就得自己找时机 delete，很容易漏。传了它，Qt 播完自己回收。

淡出麻烦一点。用户点关闭时窗口立刻销毁，动画来不及播。得拦下这次关闭，先播动画，播完再真关。

cpp
// 头文件
protected:
    void closeEvent(QCloseEvent *event) override;
private:
    bool m_isFadingOut = false;   // 是否正在淡出

cpp
void MainWidget::closeEvent(QCloseEvent *event)
{
    // 已经在淡出流程里，放行，让窗口真正关掉
    if (m_isFadingOut) {
        event->accept();
        return;
    }

    // 1. 拦下这次关闭，窗口先别消失
    event->ignore();
    m_isFadingOut = true;

    // 2. 1.0 完全显示 -> 0.0 全透明
    QPropertyAnimation *fadeOutAnim = new QPropertyAnimation(this, "windowOpacity");
    fadeOutAnim->setDuration(800);
    fadeOutAnim->setStartValue(1.0);
    fadeOutAnim->setEndValue(0.0);
    fadeOutAnim->setEasingCurve(QEasingCurve::InOutQuad);

    // 3. 播完了再 close()，这次 m_isFadingOut 为 true，直接放行
    connect(fadeOutAnim, &QPropertyAnimation::finished, this, [this]() {
        this->close();
    });

    fadeOutAnim->start(QAbstractAnimation::DeleteWhenStopped);
}

m_isFadingOut 是这段代码的开关。没有它，finished 里调 close() 又触发 closeEvent()，又拦一次、又播一遍，死循环。

对比项 for 循环改透明度 QPropertyAnimation
主线程 被占满，界面冻住 空闲，事件循环照常跑
实际视觉效果 卡一秒然后消失 真正的渐变
CPU 空转飙高 每帧一次属性写，很低
能否中途取消 不能 能，stop()
代码量 一堆分支 六行

两个细节让效果更稳。显示前先把透明度压到 0，避免窗口先实心闪一下再淡入；关闭被外部因素打断时给个超时兜底，别卡在半透明状态。

cpp
setWindowOpacity(0.0);   // show() 之前
show();

QTimer::singleShot(1000, this, [this]() {   // 兜底
    if (m_isFadingOut && isVisible())
        this->close();
});

只是隐藏而不是关闭（托盘场景），把 closeEvent 换成 hideEvent，或者点关闭时主动走一个 playFadeOut()，播完调 hide()。逻辑一样，动作不同。

九、QPropertyAnimation 的用法 #

构造函数第二个参数是这个属性在元对象里的名字，一个字符串。

cpp
new QPropertyAnimation(this, "windowOpacity");
new QPropertyAnimation(this, "geometry");
new QPropertyAnimation(widget, "myAlpha");

字符串意味着编译期查不出错。属性名拼错，运行时没有任何提示，动画一动不动。

它依赖 Qt 的属性系统，只能动声明为 Q_PROPERTY 的属性。 普通成员变量碰不到，因为元对象里根本没有这个名字。

geometry、windowOpacity、pos、size 是 QWidget 已经注册好的，直接能用。自己写的变量想参与动画，必须走完整的三件套。

cpp
class CustomWidget : public QWidget
{
    Q_OBJECT
    // 注册属性，三种角色写全
    Q_PROPERTY(int myAlpha READ myAlpha WRITE setMyAlpha)

public:
    int myAlpha() const { return m_myAlpha; }

    void setMyAlpha(int val) {
        m_myAlpha = val;
        update();   // setter 里必须主动触发重绘，否则值变了画面不动
    }

private:
    int m_myAlpha = 255;
};

三件套是：类里有 Q_OBJECT、头文件里有 Q_PROPERTY(类型 名字 READ getter WRITE setter)、有对应的 getter 和 setter。缺 Q_OBJECT 就干脆没有元对象，属性表是空的；缺 setter 编译能过，运行时警告找不到可写属性。

setter 里那句 update() 最容易忘。属性值确实在变，动画也正常跑，但控件不知道自己该重画，屏幕上就是一个静止画面。

哪些属性可以动，一张表看完。

属性名 类型 效果 备注
windowOpacity qreal 整窗透明度 0.0~1.0，顶层窗口生效
geometry QRect 位置和大小一起变 会触发 resizeEvent
pos QPoint 只动位置 比 geometry 省
size QSize 只动大小 子控件缩放常用
minimumWidth / maximumWidth int 展开收起 抽屉、折叠面板
自定义 Q_PROPERTY 可插值类型 自己解释 需 Q_OBJECT + getter/setter

普通成员变量为什么不行，补一句：动画每帧做的是「算中间值 → 找到属性 → 调 setter 写进去」，这个「找到属性」靠元对象的 QMetaProperty 查表。没注册的变量不在表里，中间值算出来也没有落点。

常用配置就五六项。

cpp
QPropertyAnimation *anim = new QPropertyAnimation(w, "geometry");

anim->setDuration(300);                       // 时长，毫秒
anim->setStartValue(QRect(0, 0, 200, 100));   // 起点
anim->setEndValue(QRect(100, 50, 400, 300));  // 终点
anim->setEasingCurve(QEasingCurve::OutCubic); // 缓动曲线
anim->setLoopCount(3);                        // 循环次数，-1 无限
anim->setKeyValueAt(0.5, QRect(50, 20, 300, 200));  // 走到一半时的中间态

anim->start(QAbstractAnimation::DeleteWhenStopped);

缓动曲线决定「快慢怎么分配」，观感差别很大。

曲线 感觉 场景
Linear 匀速 进度条、滚动字幕
InOutQuad 两头慢中间快 淡入淡出
OutCubic 快速冲出再缓停 弹窗滑入
OutBack 冲过头再回弹 强调性动作
OutBounce 落地弹跳 趣味交互

多个动画一起跑或接着跑，用动画组：QParallelAnimationGroup 是并行，QSequentialAnimationGroup 是排队，addAnimation() 塞成员，start(QAbstractAnimation::DeleteWhenStopped) 统一启动。两个组还能互相嵌套。

cpp
QParallelAnimationGroup *group = new QParallelAnimationGroup(this);

QPropertyAnimation *move = new QPropertyAnimation(w, "pos");   // 平移
move->setDuration(300);
move->setStartValue(QPoint(-200, 100));
move->setEndValue(QPoint(40, 100));
group->addAnimation(move);

QPropertyAnimation *fade = new QPropertyAnimation(w, "windowOpacity");  // 同时淡入
fade->setDuration(300);
fade->setStartValue(0.0);
fade->setEndValue(1.0);
group->addAnimation(fade);

group->start(QAbstractAnimation::DeleteWhenStopped);

重复点按钮触发动画时，先 stop() 掉上一个。两个动画同时改同一个属性，最后谁赢取决于谁后写，画面会抖。

cpp
if (m_anim->state() == QAbstractAnimation::Running)
    m_anim->stop();
m_anim->setStartValue(w->geometry());   // 从当前位置接着走
m_anim->setEndValue(targetRect);
m_anim->start();

十、滚动字幕的实现 #

公告栏、头条条、欢迎语，需要文字横向循环滚动。Web 里叫走马灯（Marquee）。两条思路：截字符，或者按像素重画。

方案一，字符位移。QTimer 定时截字符串尾部塞回 QLabel，逐字符向左跳。

cpp
// 初始化
m_scrollCaptionStr = QStringLiteral("欢迎加入我们：Qt分享&&交流 26197884  ");
m_scrollCaptionLabel = new QLabel(this);

m_timer = new QTimer(this);
connect(m_timer, SIGNAL(timeout()), this, SLOT(scrollCaption()));
m_timer->start(500);   // 每 500 毫秒动一格

// 槽函数
void MyWidget::scrollCaption()
{
    static int nPos = 0;

    if (nPos > m_scrollCaptionStr.length())   // 截到末尾，回起点
        nPos = 0;

    m_scrollCaptionLabel->setText(m_scrollCaptionStr.mid(nPos));  // 截剩余全部文本

    nPos++;
}

字符串末尾那几个空格不是手滑。mid(nPos) 截出来的文本会越截越短，文字在标签里立刻左对齐重排，看起来是「跳一下」而不是「滚出去」。补空格让截断后的长度基本不变，跳感能压下去。

500 毫秒一格很慢，字号一大跳格感非常明显。这是方案一的上限。

方案二，像素级重画。自绘控件，定时器每次把 X 偏移减 1，paintEvent 里按偏移画文本。平移连续，没有接缝。

cpp
// MarqueeWidget.h
#pragma once
#include <QWidget>
#include <QTimer>

class MarqueeWidget : public QWidget
{
    Q_OBJECT
public:
    explicit MarqueeWidget(QWidget *parent = nullptr);
    void setText(const QString &text);   // 设置滚动内容
    void setSpeed(int ms);               // 设置步进间隔

protected:
    void paintEvent(QPaintEvent *event) override;

private slots:
    void updateOffset();

private:
    QString m_text;      // 字幕内容
    int m_offset;        // 水平绘制偏移（X 坐标）
    int m_textWidth;     // 文本渲染后的物理宽度
    QTimer *m_timer;     // 步进定时器
    int m_speedMs;       // 触发间隔
};

cpp
// MarqueeWidget.cpp
#include "MarqueeWidget.h"
#include <QPainter>
#include <QFontMetrics>

MarqueeWidget::MarqueeWidget(QWidget *parent)
    : QWidget(parent)
    , m_offset(0)
    , m_textWidth(0)
    , m_speedMs(30)   // 30ms 走一像素
{
    m_timer = new QTimer(this);
    connect(m_timer, &QTimer::timeout, this, &MarqueeWidget::updateOffset);
    m_timer->start(m_speedMs);
}

void MarqueeWidget::setText(const QString &text)
{
    m_text = text;
    // 用当前字体量出文本在屏幕上的真实像素宽度
    m_textWidth = fontMetrics().width(m_text);
    m_offset = this->width();   // 初始在控件右边缘之外，从右边探进来
    update();
}

void MarqueeWidget::setSpeed(int ms)
{
    m_speedMs = ms;
    m_timer->start(m_speedMs);
}

void MarqueeWidget::updateOffset()
{
    m_offset -= 1;   // 每次左移一像素
    // 文本右端也完全移出左边缘了，回最右侧重新开始
    if (m_offset < -m_textWidth)
        m_offset = this->width();
    update();        // 触发 paintEvent
}

void MarqueeWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);
    QPainter painter(this);
    painter.setRenderHint(QPainter::TextAntialiasing);   // 文本抗锯齿

    // Y 轴按字体高度居中
    int fontHeight = fontMetrics().height();
    int yPos = (this->height() - fontHeight) / 2 + fontMetrics().ascent();
    painter.drawText(m_offset, yPos, m_text);
}

边界判断是这段代码的核心。m_offset 从 width() 一路减到 -m_textWidth，跑完「文本宽度 + 控件宽度」的完整行程才复位。判成 m_offset < 0 就复位的话，文字刚滚出左边缘就闪回右边，中间空一大段。

speedMs 直接决定观感。30ms 一像素约 33 像素/秒，慢；10ms 约 100 像素/秒，接近跑马灯；5ms 以下开始吃 CPU，每秒要重绘 200 次。

fontMetrics().width() 在 Qt 5.11 之后标记为废弃，新代码写 horizontalAdvance()。

cpp
m_textWidth = fontMetrics().horizontalAdvance(m_text);
维度 方案一（截字符） 方案二（像素重画）
实现成本 十几行，不用建类 一个自定义控件
平滑度 逐字符跳 逐像素平移
大字号表现 跳感明显 一样平顺
扩展性 只能改文本 可改颜色、渐变、加图标
CPU 占用 极低（2 次/秒） 中（30 次/秒重绘）
适合 短提示、非核心区域 公告栏、头部头条

方案一胜在短。字符不多、位置不显眼的提示条，用它足够，不必为一个提示条新建类。

方案二胜在好改。想加渐变底色、想在文字前画个小喇叭、想让文字淡出，都在 paintEvent 里加几行。专业项目走这条。

十一、动画的性能与取舍 #

动画本质是「按时间改值 + 重绘」，开销全在重绘上。控制住重绘的范围和频率，性能就不是问题。

几段实测管用的做法。

  • 定时器间隔别低于 16ms。60 帧是 16.6ms 一帧，比这更快只增加 CPU，屏幕刷不出来。滚动字幕 30ms 一像素已经是 33 帧的效果，够看。
  • 只重绘变化的区域。update() 不带参数是整控件重绘，带 QRect 只重绘那一块。
  • 抗锯齿要付代价。文本用 TextAntialiasing 就够，别顺手全开 Antialiasing。
  • 动画对象要能回收。DeleteWhenStopped 最省心，deleteLater() 也行。
  • 动画期间避免 layout() 重算。改 geometry 会让子控件跟着重排，改 pos 就绕开了。
  • 复杂静态内容先渲染到 QPixmap 缓存，paintEvent 里直接贴，不每次重画路径和渐变。
cpp
// 只重绘文字经过的那一条，不整屏刷
update(m_offset - 2, 0, m_textWidth + 4, height());

属性动画和定时器动画的取舍，看改的是什么。

场景 选型 原因
窗口透明、位置、尺寸 QPropertyAnimation 有现成属性，非阻塞
自定义视觉参数（角度、偏移、颜色） 自定义 Q_PROPERTY + 属性动画 一样非阻塞，代码统一
定时推进的循环运动 QTimer + 手动改值 要精确控制步长和边界
一次性简单延迟 QTimer::singleShot 不用造动画对象

还有一个容易忽略的点：windowOpacity 在部分 Linux 合成器上不生效，没有桌面合成的环境里也没效果。跨平台产品要给兜底，别把交互信息只放在透明度变化上。

十二、易错点速查 #

把这一篇踩过的坑压成一张表，出问题先在这里对一遍。

现象 原因 改法
窗口拖不动 没设 setMouseTracking(true)，或事件被吃掉 开跟踪；子控件装事件过滤器
鼠标一按窗口跳到鼠标位置 移动时直接 move(event->pos()) move(event->globalPos() - m_movePoint)
鼠标刚移进窗口就乱飞 m_mousePressed 未初始化 构造函数里置 false
拖动两倍速 偏移里混进了窗口位置 偏移只取 event->pos()

无边框后点不到窗口 缺 WindowStaysOnTopHint 补上，或松手时 clampToScreen()
圆角外面一圈黑边 没开 WA_TranslucentBackground 加 setAttribute

几句表里放不下的话。

setWindowFlags() 在 show() 之后调用会让窗口隐藏，记得再 show() 一次。

属性名是字符串，拼错不报错。写成常量比散落的字面量可靠。

同一属性上跑两个动画会互相覆盖，切页、连点按钮时先 stop()。

restoreGeometry() 必须在 show() 之前调，否则先闪默认位置。

滚动字幕复位时用 this->width() 而不是 width() + 1，差一个像素会出现一道不该有的白缝。

拖动只在移动超过阈值后才 move()，双击判定的误触会少很多。
