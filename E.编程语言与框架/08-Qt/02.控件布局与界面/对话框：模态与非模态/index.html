这篇只讲对话框：模态与非模态的差别、三种模态级别、exec() 与 show() 的分工、标准对话框、自定义对话框、返回值，最后落到一个能直接抄的透明提示框。

不讲这些：主窗口的布局与停靠、QMessageBox 的 QSS 皮肤重绘、非对话框的浮层（QToolTip、无边框窗体的拖拽与缩放）。前两样看「05-布局与界面架构」和「01-控件基础与用法」，后一样看「03-自定义窗口与样式」；事件循环本身的机制在「05.多线程与事件循环」那一册。

环境对齐 Qt 6.x + C++17。三端行为不一致的地方会当场点出来。

一、对话框是什么 #

QDialog 是 QWidget 的子类，多出来的东西只有三样：模态属性、exec() 入口、返回值。抓住这三样，对话框就没有别的秘密。

拿到「要不要做成对话框」的疑问，先回答三个问题：谁被挡住，只挡父窗口还是挡住整个应用；怎么开，exec() 卡住代码还是 show() 立刻返回；结果怎么给，返回值还是信号。三个问题答完，实现方式基本就定了。

对比项 普通窗口（QWidget） 对话框（QDialog）
模态 默认没有，要手动设 有 setModal() / setWindowModality()
阻塞入口 只有 show() show() / open() / exec()
返回值 无 Accepted / Rejected / 自定义码
关闭语义 close() accept() / reject() / done(code)
键盘行为 无内建 Esc → reject()，回车 → 默认按钮

最后一行是白送的。QDialog 里按 Esc 走 reject()，按回车触发默认按钮，这两个行为不用自己写代码。

cpp
class RenameDialog : public QDialog {
    Q_OBJECT
public:
    explicit RenameDialog(QWidget* parent = nullptr) : QDialog(parent) {
        setWindowTitle("重命名");
        setModal(true);                    // 应用级模态

        auto* edit = new QLineEdit(this);
        auto* box  = new QDialogButtonBox(
            QDialogButtonBox::Ok | QDialogButtonBox::Cancel, this);
        connect(box, &QDialogButtonBox::accepted, this, &QDialog::accept);
        connect(box, &QDialogButtonBox::rejected, this, &QDialog::reject);

        auto* layout = new QVBoxLayout(this);
        layout->addWidget(edit);
        layout->addWidget(box);
    }
};

// 调用
RenameDialog dlg(this);
if (dlg.exec() == QDialog::Accepted) {
    // 用户点了确定
}

QDialogButtonBox 值得一直用。它按平台自动排按钮顺序：Windows 是「确定 取消」，macOS 是「取消 确定」。手写两个 QPushButton 就得自己判断平台。

代码到这儿能跑，但「为什么能跑」才是下面几章要拆的东西。

二、模态与非模态的本质差别 #

先把最容易跑偏的一句话摆前面：模态的本质，是开了一个局部事件循环。

exec() 不是 sleep()，也不是把线程挂起。它做的事是「在当前线程里再套一层事件循环」，让代码停在这一行不再往下走，但事件照样分发。这是理解后面所有行为的钥匙。

cpp
int QDialog::exec() {
    setAttribute(Qt::WA_ShowModal, true);
    show();

    QEventLoop eventLoop;
    m_eventLoop = &eventLoop;

    // 卡在这里，直到 accept() / reject() / done() 被调用
    return eventLoop.exec(QEventLoop::DialogExec);
}

注意里面的 show()。exec() 内部已经显示窗口了，调用方再写一句 show() 是多余的。

一次 exec() 的完整时序：

text
主事件循环 ──► dialog->exec()
                 │
                 ├─► setAttribute(WA_ShowModal, true)
                 ├─► show()                        窗口出现
                 └─► 新建 QEventLoop，进入嵌套循环
                          │
                          │  ← 点击、输入、重绘、定时器，都在这里被处理
                          │
                          ├─► accept() / reject() / done(code)
                          └─► eventLoop 退出
                 │
                 └─► 返回 int（DialogCode）──► 主事件循环继续

从这张图能推出四条结论，一条比一条实用：

  • 不创建新线程。嵌套循环跑在主线程里，QThread::currentThreadId() 前后一致。
  • 界面仍然活着。对话框能重绘，定时器能触发，QMovie 能动，进度条能走——原因就在这里。
  • 阻塞是逻辑阻塞。CPU 没闲着，事件循环在分发，只是你的执行流被拦住了。
  • 循环退出只有三个口子：accept()、reject()、done(int)。别的路都绕不出去。

拿一段代码验证第二条：

cpp
void MainWindow::testEventLoop() {
    qDebug() << "1. 线程 ID:" << QThread::currentThreadId();

    QDialog dialog(this);
    QTimer::singleShot(1000, [this]() {
        // 这个定时器会在哪一层循环里被处理？
        qDebug() << "2. 定时器触发，线程 ID:" << QThread::currentThreadId();
    });

    qDebug() << "3. 调用 exec() 前";
    dialog.exec();
    qDebug() << "4. exec() 返回后";
}
// 输出顺序: 1 -> 3 -> 2 -> 4
// 三行线程 ID 完全相同

顺序是 1 -> 3 -> 2 -> 4，不是 1 -> 3 -> 4。定时器在对话框还开着的时候就被处理掉了，这证明嵌套循环确实在分发事件。如果 exec() 真是把线程挂起，2 这一行永远不会打印。

非模态就简单了。show() 只是把窗口显出来就返回，一行都不多停。没有嵌套循环，也就没有「执行流被拦住」这回事。

对比项 模态（exec()） 非模态（show()）
执行流 卡在 exec() 这一行 立刻返回下一行
事件循环 多一层嵌套 仍只有主循环
父窗口 被禁用，点不动 照常可交互
界面刷新 照常刷新 照常刷新
新线程 不开 不开
结果获取 返回值 只能靠信号

倒数第二行值得划重点：两者都不开线程。别把「模态」和「同步阻塞 API」混成一件事，它俩只是执行流走向不同。QML 那边没有 exec()，对应物是 open() 加 onClosed。

三、三种模态级别 #

模态不是开关，是三档。枚举叫 Qt::WindowModality：

枚举值 阻塞范围 典型场景
Qt::NonModal 什么都不挡 工具窗口、浮动面板、查找替换
Qt::WindowModal 只挡父窗口及其祖先链 子文档的保存确认、单文档的进度框
Qt::ApplicationModal 挡住本应用所有窗口 登录、全局设置、致命错误

用一张关系图说明三档的差别。假设窗口树是 MainWindow → DocWindowA → saveDialog：

text
Qt::NonModal
  MainWindow      [可以点]
  DocWindowA      [可以点]
  DocWindowB      [可以点]
Qt::WindowModal（父窗口 = DocWindowA）
  MainWindow      [被禁用]   ← 祖先链一起挡
  DocWindowA      [被禁用]
  DocWindowB      [可以点]
Qt::ApplicationModal
  MainWindow      [被禁用]
  DocWindowA      [被禁用]
  DocWindowB      [被禁用]

WindowModal 挡的是「父窗口和它的祖先」，不是「只挡父窗口」。同级的 DocWindowB 不受影响，这是它和 ApplicationModal 的分界线。

设置方式有两种，别弄混：

cpp
// 方式一：setModal，只有两档结果
setModal(true);    // 等价于 Qt::ApplicationModal
setModal(false);   // 等价于 Qt::NonModal

// 方式二：setWindowModality，三档都给
setWindowModality(Qt::WindowModal);        // 只挡父窗口链
setWindowModality(Qt::ApplicationModal);   // 挡全应用
setWindowModality(Qt::NonModal);           // 不挡

想用 WindowModal，只能走 setWindowModality()。setModal() 给不了这一档，踩过的人不少。

普通 QWidget 没有 exec()，但也能做模态：

cpp
QWidget* widget = new QWidget();

// 方式一：setWindowModality，推荐
widget->setWindowModality(Qt::ApplicationModal);
widget->show();

// 方式二：WA_ShowModal 属性
widget->setAttribute(Qt::WA_ShowModal, true);
widget->show();

两种方式都要求窗口还没显示。窗口已经在屏幕上再去改模态属性，是无效的：

cpp
// 错的：可见时改不动
dialog->show();
dialog->setWindowModality(Qt::ApplicationModal);   // 没有任何效果

// 对的：先藏，改完再显
dialog->hide();
dialog->setWindowModality(Qt::ApplicationModal);
dialog->show();

无边框窗口还有个坑。光设模态属性，模态会静默失效：

cpp
// 模态不生效
widget->setWindowFlags(Qt::FramelessWindowHint | Qt::WindowStaysOnTopHint);
widget->setWindowModality(Qt::ApplicationModal);

// 补上 Qt::Dialog 标志才有模态
widget->setWindowFlags(Qt::Dialog | Qt::FramelessWindowHint
                       | Qt::WindowStaysOnTopHint);
widget->setWindowModality(Qt::ApplicationModal);

原因是模态的实现依赖窗口管理器认它是个「对话框类型的顶层窗口」，Qt::Dialog 就是告诉系统这一点的标志位。做自绘提示框、自绘登录窗时，这一笔不能漏。

三端表现也不一致：

平台 差异
macOS WindowModal 会变成 Sheet，吸附在父窗口标题栏下，不能拖动
Windows 模态期间点击父窗口，标题栏会闪烁提示
Linux (X11) 部分窗口管理器直接忽略模态标志，别指望它

X11 那条是实打实的：别把「父窗口挡住」当成安全边界，逻辑上该自己挡的还得自己挡。

四、exec 与 show 的选择 #

一句话分工：要拿结果用 exec()，要不阻塞用 show() 加信号。

exec() 返回 int，值就是 QDialog::DialogCode；show() 返回 void，什么都没有。这是两者最硬的区别，也是选型的第一判据。还有第三个选项 open()，夹在中间：

方法 卡住代码 建嵌套循环 默认模态 返回值 拿结果的方式
exec() 是 是 应用模态 int 直接比较返回值
show() 否 否 非模态 void 连 accepted / rejected 信号
open() 否 否 窗口模态 void 连 finished(int) 信号

open() 是「UI 挡住、代码继续」的折中档。它和 exec() 一样能挡住父窗口，但不会把调用方卡在那里，结果从 finished 信号里拿。

要结果、代码也能等，就用 exec()：

cpp
void MainWindow::onLogin() {
    LoginDialog dialog(this);          // 栈上创建

    if (dialog.exec() == QDialog::Accepted) {
        QString user = dialog.username();
        // 执行登录逻辑
    }
    // 函数返回，dialog 自动析构
}

栈分配配 exec() 是最省事的写法。对话框活不过这个函数作用域，不需要管内存。但栈分配的对话框千万别设 WA_DeleteOnClose，否则 exec() 返回后析构一次、属性又删一次，双重释放直接崩。

要结果、代码不能等，就用 open()：

cpp
void MainWindow::closeEvent(QCloseEvent* event) {
    if (!m_isModified) { event->accept(); return; }

    auto* dialog = new QDialog(this);
    dialog->setModal(true);
    // ... 布置 UI

    connect(dialog, &QDialog::finished, this, [this, dialog](int result) {
        if (result == QDialog::Accepted) {
            saveDocument();
        }
        dialog->deleteLater();        // 关键：异步删除
    });

    event->ignore();
    dialog->open();                   // 关键：不卡代码，但挡住窗口
}

这段是「关窗时问要不要保存」的标准写法。open() 不建嵌套循环，所以 closeEvent 能干净地返回；结果在 finished 里处理，对话框用 deleteLater() 收尸。

不需要结果的工具窗，就用 show()：

cpp
class FindDialog : public QDialog {
    Q_OBJECT
public:
    explicit FindDialog(QWidget* parent) : QDialog(parent) {
        setModal(false);                            // 非模态
        setWindowFlags(windowFlags() | Qt::Tool);   // 工具窗样式
        setAttribute(Qt::WA_DeleteOnClose, false);  // 复用同一个实例
    }
protected:
    void closeEvent(QCloseEvent* event) override {
        hide();          // 藏起来，不销毁
        event->ignore();
    }
};

// 调用方：成员变量持有，防止开出一堆
QPointer<FindDialog> m_findDialog;      // QPointer 兜住悬空

void MainWindow::showFind() {
    if (!m_findDialog) {
        m_findDialog = new FindDialog(this);
    }
    m_findDialog->show();
    m_findDialog->raise();              // 提到最前
    m_findDialog->activateWindow();     // 抢焦点
}

hide() 而不是 close()，是为了保留用户上次填的内容。查找框一关就把输入清空，用户会骂人。

exec() 混 show() 也是多余动作：

cpp
// 多余
dialog->show();
dialog->exec();     // exec() 里已经 show() 过了

// 干净
dialog->exec();

open() 和 exec() 也别对着一个对象轮着调，状态容易错乱。

五、标准对话框 #

Qt 自带一套对话框，九成场景不用自己从零画。

类 用途 静态便利函数
QFileDialog 选文件、选目录、保存 getOpenFileName / getSaveFileName / getExistingDirectory
QMessageBox 提示、警告、错误、询问 information / warning / critical / question / about
QColorDialog 选颜色 getColor
QFontDialog 选字体 getFont
QInputDialog 要一行文本、一个数字、一个下拉项 getText / getInt / getDouble / getItem
QProgressDialog 带取消的进度 无，用实例
QWizard 多步向导 无，用实例
QErrorMessage 错误信息排队显示 无，用实例

这些类都是 QDialog 的子类，exec()、show()、返回值那套规则原样适用。

静态函数是省事版。它们内部 new 一个对话框、exec() 一下、把结果返回、自己删掉，调用方一行搞定：

cpp
bool ok = false;
QString name = QInputDialog::getText(this, "重命名", "新名称：",
                                     QLineEdit::Normal, "未命名", &ok);
if (ok && !name.isEmpty()) {
    rename(name);
}

注意最后一个 bool* 参数。静态版把「用户点了确定还是取消」塞进这个指针里，返回的字符串本身区分不了这两种情况：用户点取消返回空串，点了确定但没输入也返回空串。

静态版搞不定的需求，就用实例：

cpp
QFileDialog dlg(this);
dlg.setFileMode(QFileDialog::ExistingFiles);   // 允许多选
dlg.setNameFilter("图片 (*.png *.jpg);;所有文件 (*)");
dlg.setViewMode(QFileDialog::Detail);
if (dlg.exec() == QDialog::Accepted) {
    QStringList files = dlg.selectedFiles();
}

判据很简单：要改选项（多选、过滤器、初始目录、原生与非原生切换）就用实例，只是拿个结果就用静态函数。标准对话框的按钮文案和顺序由平台决定，别硬改。真要改，用 setButtonText() 而不是重画按钮。

六、文件与目录对话框 #

QFileDialog 是用得最多的一个，四个静态函数覆盖全部常规需求：

函数 用途 返回值
getOpenFileName 选一个已有文件 QString
getOpenFileNames 选多个已有文件 QStringList
getSaveFileName 选保存路径 QString
getExistingDirectory 选一个已存在的目录 QString 
cpp
QString path = QFileDialog::getOpenFileName(
    this,
    "选择配置文件",                              // 标题
    m_lastDir,                                   // 初始目录
    "配置文件 (*.ini *.json);;所有文件 (*)");     // 过滤器

if (!path.isEmpty()) {
    m_lastDir = QFileInfo(path).absolutePath();   // 记住，下次还用
    loadConfig(path);
}

返回值判断只用 isEmpty()。用户点取消时返回空串，这是唯一可靠的判据。

过滤器字符串的分号是双的：;; 分隔不同类别，() 里单个空格分隔多个后缀。写成单分号，下拉框里只会剩一条。

选目录有个易错点，getExistingDirectory 只返回目录。想「选目录且要求非空」，靠 ShowDirsOnly 选项：

cpp
QString dir = QFileDialog::getExistingDirectory(
    this, "选择导出目录", m_lastDir,
    QFileDialog::ShowDirsOnly | QFileDialog::DontResolveSymlinks);

保存对话框不会替你建文件，它只给路径。写盘失败要自己处理：

cpp
QString path = QFileDialog::getSaveFileName(
    this, "导出报告", m_lastDir + "/report.csv", "CSV (*.csv)");
if (path.isEmpty()) return;                    // 用户取消

QFile f(path);
if (!f.open(QIODevice::WriteOnly | QIODevice::Truncate)) {
    QMessageBox::warning(this, "写入失败", f.errorString());
    return;
}
f.write(buildCsv());

原生对话框和 Qt 自绘版行为不完全一样。要保证三端长得一样，给实例设 QFileDialog::DontUseNativeDialog 选项；只在测试或强定制时这么干，原生版能记住系统级位置、能访问网络位置、有系统收藏夹，关了这些全没。

七、消息提示框 #

QMessageBox 是最省事的反馈手段，五个静态函数按语义分：

静态函数 图标 默认按钮
information 信息 i OK
warning 警告三角 OK
critical 错误叉 OK
question 问号 Yes / No
about 应用图标 OK 
cpp
// 纯告知，不需要结果
QMessageBox::warning(this, "保存失败", "磁盘空间不足。");

// 需要用户决策，看返回值
auto ret = QMessageBox::question(
    this, "覆盖确认", "目标文件已存在，要覆盖吗？",
    QMessageBox::Yes | QMessageBox::No, QMessageBox::No);

if (ret == QMessageBox::Yes) {
    overwrite();
}

按钮组合可以自己拼，StandardButton 之间用 | 连接。顺序按平台规范自动排，不用管。

要改按钮文案、要加自定义按钮、要控制默认焦点，就得用实例：

cpp
QMessageBox box(this);
box.setIcon(QMessageBox::Question);
box.setWindowTitle("未保存的更改");
box.setText("文档已修改。");                       // 主文案，粗体大字
box.setInformativeText("关闭前要保存吗？");        // 补充说明，小字
box.setStandardButtons(QMessageBox::Save | QMessageBox::Discard | QMessageBox::Cancel);
box.setDefaultButton(QMessageBox::Save);           // 回车默认走这个
box.setEscapeButton(QMessageBox::Cancel);          // Esc 走这个

if (box.exec() == QMessageBox::Save) {
    saveDocument();
}

setText 和 setInformativeText 分层是有讲究的。主文案一句话说清发生了什么，补充说明讲后果或选项。全塞进 setText 会变成一大坨。setDefaultButton 和 setEscapeButton 建议每次都给，默认按钮是「删除」这类危险操作时，用户一个回车就误删了。

QMessageBox 的父窗口传 nullptr 时，对话框跑到屏幕中间，且不带父窗口的模态。类成员函数里别忘了传 this。

八、自定义对话框 #

标准对话框搞不定的，就子类化 QDialog。骨架固定，四步：控件全部 new 到 this 上靠父子关系析构；用布局管理器排，别用 setGeometry 硬定位；QDialogButtonBox 的 accepted / rejected 接到 accept() / reject()；校验不通过就在 accept() 之前拦住。

cpp
class SettingsDialog : public QDialog {
    Q_OBJECT
public:
    explicit SettingsDialog(QWidget* parent = nullptr) : QDialog(parent) {
        setWindowTitle("设置");
        resize(420, 300);

        m_hostEdit = new QLineEdit(this);
        m_portSpin = new QSpinBox(this);
        m_portSpin->setRange(1, 65535);

        auto* form = new QFormLayout;
        form->addRow("服务器：", m_hostEdit);
        form->addRow("端口：", m_portSpin);

        auto* box = new QDialogButtonBox(
            QDialogButtonBox::Ok | QDialogButtonBox::Cancel, this);
        connect(box, &QDialogButtonBox::accepted, this, &SettingsDialog::tryAccept);
        connect(box, &QDialogButtonBox::rejected, this, &QDialog::reject);

        auto* layout = new QVBoxLayout(this);
        layout->addLayout(form);
        layout->addStretch();          // 把按钮顶到底部
        layout->addWidget(box);
    }

    QString host() const { return m_hostEdit->text().trimmed(); }
    quint16 port() const { return static_cast<quint16>(m_portSpin->value()); }

private slots:
    void tryAccept() {
        if (host().isEmpty()) {
            QMessageBox::warning(this, "输入无效", "服务器地址不能为空。");
            m_hostEdit->setFocus();     // 把焦点送回问题控件
            return;                     // 不调 accept()，对话框不关
        }
        accept();                       // 校验通过才关
    }

private:
    QLineEdit* m_hostEdit;
    QSpinBox*  m_portSpin;
};

关键点在于 tryAccept() 和 accept() 分开。校验不过就直接 return，对话框留在原地，用户改完再点确定。把所有校验塞进 accept() 的 if 里也能写，但阅读性差一些。

子类化之后注意两件事：别在构造函数里调 exec()，那会形成套娃；值成员的访问器写成 const 的，调用方读到的永远是关闭那一刻的状态。

connect 只连一次，写在 new 完的下一行，别写在每次 show() 之前，否则每打开一次就多连一遍，槽函数跑多次。长期存在的设置面板也别每次 new，成员变量持有，show() / hide() 复用。

九、对话框的返回值 #

QDialog 里结果就一个 int，两个预定义值：

值 数值 由谁设置
QDialog::Accepted 1 accept()
QDialog::Rejected 0 reject()

exec() 返回它，result() 也能读它，两个值永远一样。三个关窗函数的差别：

cpp
accept();        // 等价于 setResult(Accepted); done(Accepted); hide();
reject();        // 等价于 setResult(Rejected); done(Rejected); hide();
done(42);        // setResult(42); 发 finished(42); hide();

想让返回值带业务含义，就走 done()：

cpp
enum Choice { Apply = 10, ApplyAll = 11, Skip = 12 };

// 对话框里
connect(btnApply,    &QPushButton::clicked, this, [this]() { done(Apply); });
connect(btnApplyAll, &QPushButton::clicked, this, [this]() { done(ApplyAll); });
connect(btnSkip,     &QPushButton::clicked, this, [this]() { done(Skip); });

// 调用方
switch (dlg.exec()) {
case Apply:    applyOne();  break;
case ApplyAll: applyAll();  break;
case Skip:                  break;
default:       return;      // 用户按 Esc 或点叉，返回 Rejected(0)
}

自定义码别用 0 和 1，那两个被 Accepted / Rejected 占了。用 10 以上的值，默认分支就能干净地兜住「取消」。

show() 和 open() 没有返回值，结果只能从信号拿：

cpp
connect(dlg, &QDialog::finished, this, [](int code) {
    // code 就是 result()
});
connect(dlg, &QDialog::accepted, this, []() { /* 只关心接受 */ });
connect(dlg, &QDialog::rejected, this, []() { /* 只关心取消 */ });

三个信号的关系：accept() 先发 accepted()，再发 finished(Accepted)；reject() 先发 rejected()，再发 finished(Rejected)；done(n) 只发 finished(n)。

点窗口右上角的叉，等价于 reject()。这条默认行为想改，重写 closeEvent()：

cpp
void MyDialog::closeEvent(QCloseEvent* event) {
    if (m_hasUnsaved) {
        auto ret = QMessageBox::question(this, "确认", "放弃未保存的修改？");
        if (ret != QMessageBox::Yes) {
            event->ignore();       // 拦下关闭
            return;
        }
    }
    QDialog::closeEvent(event);    // 走默认：相当于 reject()
}

十、透明与半透明对话框 #

透明有三条路，效果完全不同，选错就白折腾：

做法 透的是什么 能不能透过看到桌面
setWindowOpacity() 整个窗口，包括子控件 不能
WA_TranslucentBackground 窗口背景的透明通道 能
QPalette + alpha 只有窗口背景，子控件不受影响 不能

第一条最省事，一条语句搞定整体淡化：

cpp
QDialog dlg(this);
dlg.setWindowOpacity(0.85);      // 0.0 全透明，1.0 不透明
dlg.exec();

子控件会跟着一起变淡。要「框体半透明但文字清楚」，这条不行。

第二条是自绘浮层的正路，两个属性必须成对出现：

cpp
class Toast : public QWidget {
public:
    explicit Toast(QWidget* parent = nullptr) : QWidget(parent) {
        setWindowFlags(Qt::FramelessWindowHint | Qt::Tool);
        setAttribute(Qt::WA_TranslucentBackground, true);   // 关键
        resize(320, 60);
    }
protected:
    void paintEvent(QPaintEvent*) override {
        QPainter p(this);
        p.setRenderHint(QPainter::Antialiasing);

        QColor bg(30, 30, 30);
        bg.setAlphaF(0.75);                                 // 半透明底
        p.setBrush(bg);
        p.setPen(Qt::NoPen);
        p.drawRoundedRect(rect().adjusted(1, 1, -1, -1), 8, 8);
    }
};

WA_TranslucentBackground 只对顶层窗口生效，而且必须配 FramelessWindowHint，否则系统标题栏那块会出灰边。

第三条最容易被绊住。QPalette 设了 alpha 却没效果，九成是漏了 setAutoFillBackground(true)：

cpp
QColor bg(190, 230, 250);
bg.setAlphaF(0.6f);

QPalette pal;
pal.setBrush(widget->backgroundRole(), bg);
widget->setPalette(pal);
widget->setAutoFillBackground(true);   // 漏了这一句，前面白设

原因是子控件默认不主动填背景，setPalette 会被静默忽略。这一条是下一章那个提示框的核心。

QSS 也能写半透明，写法和上面等价：

cpp
label->setStyleSheet("background-color: rgba(190, 230, 250, 153); color: red;");

153 是 60% 的 255 取整。QSS 的优先级高于 QPalette，两者混用时以 QSS 为准。

还有一条：windowOpacity 在部分 X11 组合器下不生效，WA_TranslucentBackground 在部分老驱动上会出黑底。这两条都得在实际目标机上验，别只看开发机。

十一、模拟 QQ 的提示框 #

客户端里用户操作失败（密码错、网络超时），最常见的反馈是一条短暂浮出的横条：无标题栏、背景微透、左边一个图标、中间红字、右上角一个关闭按钮。QQ 登录窗就是这个路子。下面这个 ErrorWidget 可以直接抄。

头文件：

cpp
#pragma once
#include <QWidget>
#include <QLabel>
#include <QToolButton>

class ErrorWidget : public QWidget {
    Q_OBJECT
public:
    explicit ErrorWidget(QWidget* parent = nullptr);
    ~ErrorWidget();

    void setTipInfo(const QString& info);      // 设置提示文字
    void setTipIcon(const QPixmap& pixmap);    // 设置提示图标

private slots:
    bool closeWidget();                        // 隐藏提示框

private:
    QLabel*      m_msgLabel;      // 左侧图标
    QLabel*      m_askLabel;      // 中部文字
    QToolButton* m_closeButton;   // 右侧关闭按钮
};

实现：

cpp
#include "ErrorWidget.h"
#include <QPalette>
#include <QStyle>

ErrorWidget::ErrorWidget(QWidget* parent)
    : QWidget(parent)
{
    int parentWidth  = parent ? parent->width() : 300;
    int widgetHeight = 28;
    resize(parentWidth, widgetHeight);
    // ① 去掉系统标题栏，做成浮在父控件上的横条
    setWindowFlags(Qt::FramelessWindowHint);

    // ② 背景设成 60% 透明度的浅蓝
    QPalette palette;
    QColor bgColor(190, 230, 250);
    bgColor.setAlphaF(0.6f);                       // 0 全透，1 不透
    palette.setBrush(backgroundRole(), bgColor);
    setPalette(palette);

    // ③ 必须开这个，否则上一步的调色板被静默忽略
    setAutoFillBackground(true);
    // ④ 左侧图标
    m_msgLabel = new QLabel(this);
    m_msgLabel->setGeometry(QRect(5, 4, 20, 20));
    m_msgLabel->setScaledContents(true);
    m_msgLabel->setStyleSheet("background-color: transparent;");
    // ⑤ 中间文字，红字，标签自身透明
    m_askLabel = new QLabel(this);
    m_askLabel->setGeometry(QRect(30, 0, parentWidth - 60, widgetHeight));
    m_askLabel->setAlignment(Qt::AlignCenter);
    m_askLabel->setStyleSheet("background-color: transparent; color: red;");
    // ⑥ 右侧关闭按钮，用系统原生关闭图标
    m_closeButton = new QToolButton(this);
    m_closeButton->setIcon(style()->standardPixmap(QStyle::SP_TitleBarCloseButton));
    m_closeButton->setGeometry(parentWidth - 20, 0, 20, 20);
    m_closeButton->setStyleSheet("QToolButton{ background-color: transparent; }");
    m_closeButton->setCursor(Qt::PointingHandCursor);
    // ⑦ 关掉它
    connect(m_closeButton, &QToolButton::clicked, this, &ErrorWidget::closeWidget);
}

ErrorWidget::~ErrorWidget()
{
    // 子控件的父子关系会收尸，不用手动 delete
}

void ErrorWidget::setTipInfo(const QString& info)
{
    m_askLabel->setText(info);
}

void ErrorWidget::setTipIcon(const QPixmap& pixmap)
{
    m_msgLabel->setPixmap(pixmap);
}

bool ErrorWidget::closeWidget()
{
    hide();      // 只藏不销毁，下次照样 show()
    return true;
}

三个子控件都写了 background-color: transparent，这一笔不能省。子标签默认会填自身背景，把父控件的半透明底盖掉，看起来就是「透明没生效」。

第 ③ 步的 setAutoFillBackground(true) 是全篇最容易漏的一行。setPalette 本身没错，缺的是「让 Qt 真的用它画背景」这个开关。

集成到登录窗：

cpp
// 构造里初始化，先藏着
m_errorWidget = new ErrorWidget(this);
m_errorWidget->hide();

// 登录失败的槽
void LoginDialog::onLoginFailed(const QString& reason)
{
    m_errorWidget->setTipIcon(QPixmap(":/Icons/error_tip.png"));
    m_errorWidget->setTipInfo(reason);

    if (m_errorWidget->isHidden()) {
        m_errorWidget->show();
    }
}

isHidden() 判一下，避免连续错误时反复 show() 造成闪烁。整个控件只 new 一次，后续全靠 show() / hide() 复用。

想加淡入，用 QPropertyAnimation 打 windowOpacity：

cpp
auto* anim = new QPropertyAnimation(m_errorWidget, "windowOpacity");
anim->setStartValue(0.0);
anim->setEndValue(1.0);
anim->setDuration(300);
anim->start(QAbstractAnimation::DeleteWhenStopped);

技术点回查：

技术点 实现方式
去标题栏 setWindowFlags(Qt::FramelessWindowHint)
半透明背景 QColor::setAlphaF() + QPalette::setBrush()
修复子控件透明失效 setAutoFillBackground(true)
内嵌子件透明 子标签加 background-color: transparent
系统关闭图标 style()->standardPixmap(QStyle::SP_TitleBarCloseButton)
显隐复用 show() / hide()，不重复 new

十二、对话框的常见坑 #

内存管理是最集中出问题的地方：

写法 后果 正确做法
栈分配 + show() 函数一返回就消失 堆分配 + WA_DeleteOnClose
栈分配 + WA_DeleteOnClose 双重释放，崩 栈分配时别设这个属性
堆分配，无 parent 无删除 泄漏 给 parent，或 deleteLater()
堆分配 + exec() 后忘了删 泄漏 deleteLater() 或 WA_DeleteOnClose

exec() 期间父窗口被删，是另一个隐蔽的坑：

cpp
// 危险：exec() 期间 this 会被删掉
void ParentWidget::dangerous() {
    QDialog* dialog = new QDialog(this);
    connect(someTimer, &QTimer::timeout, this, &QObject::deleteLater);
    dialog->exec();          // 父窗口在嵌套循环里被删 → 未定义行为
}

// 安全：改成 open() + finished
void ParentWidget::safe() {
    QDialog* dialog = new QDialog(this);
    connect(dialog, &QDialog::finished, this, [dialog](int) {
        dialog->deleteLater();
    });
    dialog->open();
}

嵌套循环会放事件进来，事件里能删掉任何东西，包括你脚下这块地。这就是 Qt 官方不推荐 exec() 的实质原因。

在模态对话框里跑长循环也是坑。界面会冻住，因为嵌套循环被你的 for 占了，没机会分发重绘事件：

cpp
// 错：对话框卡死，进度条不动
void MyDialog::onOkClicked() {
    for (int i = 0; i < 1000000; ++i) heavyComputation();
    accept();
}

// 对：丢到工作线程，结果用队列连接送回来
void MyDialog::onOkClicked() {
    m_okButton->setEnabled(false);
    QtConcurrent::run([this]() {
        for (int i = 0; i < 1000000; ++i) heavyComputation();
        QMetaObject::invokeMethod(this, &QDialog::accept, Qt::QueuedConnection);
    });
}

Qt::QueuedConnection 那一笔别省，工作线程里直接调 accept() 是跨线程碰 UI。

还有个小坑：connect 写在 show() 之前，同一个对话框反复打开，信号就重复连了，槽跑多次。

cpp
// 错：每打开一次连一遍
connect(dialog, &QDialog::accepted, this, &MainWindow::onAccepted);

// 对：加去重标志
connect(dialog, &QDialog::accepted, this, &MainWindow::onAccepted,
        Qt::UniqueConnection);

十三、易错点速查 #

症状 真正的原因 一行修法
对话框一闪就没 栈上对象 + show() 改堆分配
关窗后崩 栈分配又设了 WA_DeleteOnClose 去掉该属性
父窗口点不动，子窗口也点不动 用了 ApplicationModal 换 setWindowModality(Qt::WindowModal)
setModal() 设不出窗口级模态 它只有两档 改 setWindowModality(Qt::WindowModal)
运行时改模态没反应 窗口已可见 hide() → 改 → show()
无边框窗没有模态效果 缺 Qt::Dialog 标志 setWindowFlags(Qt::Dialog | ...)
拿不到 exec() 的结果 用的是 show() 换 exec()，或连 finished
每次打开弹多个框 非模态每次 new 成员变量持有
槽函数跑了好几次 信号重复连接 Qt::UniqueConnection
模态框里进度条不动 主线程里跑长循环 QtConcurrent 加队列连接
半透明背景不生效 漏了 setAutoFillBackground setAutoFillBackground(true)
子标签盖住半透明底 子件没设透明 加 background-color: transparent
DontUseNativeDialog 后功能变少 自绘版不支持系统特性 只在需要统一外观时关

三句话收尾：模态是局部事件循环，不是线程挂起；要结果用 exec()，要不卡代码用 open() 或 show()；三种模态级别里，WindowModal 只能靠 setWindowModality() 设出来。
