本篇只讲一件事：程序在干活的时候，怎么让用户知道「在干」「干完了」「干坏了」。

讲什么：转圈等待的三种实现（gif / 纯代码绘制 / 多图片轮换）、自定义提示框的三种形态（仿 QMessageBox / 右下角冒泡 / 不规则形状）、进度条与进度对话框，以及它们底下共用的那一层东西——定时器。

不讲什么：主界面布局、QSS 主题体系、QDialog 基类的完整 API。无边框窗口的拖拽套路在「对话框与提示框」这一组里另有专篇，定时器本身的用法看 Qt 定时器那一篇。

一条主线先说在前面：屏幕上所有「自己会动、自己会消失」的东西，底下都挂着一个 QTimer，而 QTimer 靠事件循环投递超时。调用方在忙循环里不返回事件循环，等待框就既不刷新也不消失。后面每一节都会绕回这句话。

一、用户反馈的几种形态 #

界面上给用户的反馈，按两个维度一切就清楚了：打不打断用户，和需不需要结果。

形态 典型控件 是否模态 有返回值 生命周期由谁定
转圈等待 自绘 QWidget / QDialog + QMovie 多数是模态 无 任务边界
轻提示（冒泡） 无边框 QWidget 非模态 无 定时器
警告确认 QMessageBox 或自绘 QDialog 模态 Accepted / Rejected 用户点按钮
进度 QProgressBar / QProgressDialog 可模态可非模态 取消标记 任务全过程

四种形态看着差得远，实现上却都绕不开三件事：

  1. 画出来——paintEvent 里绘，或者贴 QLabel，或者交给 QSS。
  2. 动起来——QMovie 逐帧，或者 QTimer 改坐标、改图片、改文字。
  3. 消失掉——QTimer 数到点，或者用户点按钮。

第 1 件是体力活，第 2 件是熟活，出事的永远是第 3 件。因为「自动消失」这四个字里没有用户，只有时间；而时间在 Qt 里不是一个能自己走的东西，它必须挂在事件循环上。事件循环不转，定时器就不发信号，提示框就钉在屏幕上。

这条因果链值得单独写一遍：

text
QTimer::start(ms)
    -> 向事件循环注册一个定时器
    -> 事件循环每轮检查有没有到期的定时器
    -> 到期则投递 QTimerEvent
    -> 事件循环把事件派发给对象的 timerEvent()
    -> 槽函数执行，改坐标 / 改透明度 / close()

链路中间任何一环断开（事件循环没跑、对象所在线程没事件循环、被 while 循环堵住），后面全是空谈。

反过来看也挺有用：模态对话框的 exec() 之所以能让动画动起来，不是因为它阻塞，而是因为它自己又起了一层事件循环。这点在讲 QProgressDialog 时会再碰一次。

二、等待提示框：QMovie 播放 gif #

最省事的一种做法。骨架三句话：继承 QDialog，去掉系统边框，放个 QLabel 挂上 QMovie。

2.1 视觉骨架 #

窗口属性只调三个地方：

  • setWindowFlags(Qt::Dialog | Qt::FramelessWindowHint) 去掉标题栏和边框。
  • setWindowOpacity(0.85) 让整个窗口半透明，露出底下的界面。
  • setStyleSheet 铺一层底色，配合圆角。

底色选得跟 gif 的边缘色接近，后面讲白边会用到这个前提。

2.2 完整实现 #

cpp
#include <QDialog>
#include <QLabel>
#include <QMovie>
#include <QTimer>
#include <QVBoxLayout>
class LoadingDialog : public QDialog
{
    Q_OBJECT
public:
    explicit LoadingDialog(QWidget *parent = nullptr);
    void startLoading();
    void stopLoading();
private slots:
    // 定时刷新底部 waiting 文本
    void changeText();
private:
    QLabel *movie_label;
    QLabel *tip_label;
    QMovie *movie;
    QTimer *timer;
    int index;
    QString base_info;
};
// 构造函数
LoadingDialog::LoadingDialog(QWidget *parent)
    : QDialog(parent), index(0)
{
    // 1. 固定尺寸、半透明度与无边框标志
    setFixedSize(120, 120);
    setWindowOpacity(0.85);
    setWindowFlags(Qt::Dialog | Qt::FramelessWindowHint);
    // 背景色与 loading 动图的边缘色保持同一系
    setStyleSheet("background-color: rgb(55, 135, 215); border-radius: 5px;");
    // 2. 创建并配置 QMovie 播放动图
    movie_label = new QLabel(this);
    movie_label->setStyleSheet("background-color: transparent;");
    movie_label->setScaledContents(true);
    movie = new QMovie(":/icon/loading"); // 对应 res 里的 loading.gif
    movie_label->setMovie(movie);
    // 3. 创建提示文字标签
    tip_label = new QLabel(this);
    tip_label->setStyleSheet("color: white; background-color: transparent;");
    base_info = tr("waiting");
    tip_label->setText(base_info);
    // 布局排列
    QVBoxLayout *layout = new QVBoxLayout(this);
    layout->addWidget(movie_label, 0, Qt::AlignCenter);
    layout->addWidget(tip_label, 0, Qt::AlignCenter);
    layout->setContentsMargins(15, 15, 15, 15);
    setLayout(layout);
    // 4. 初始化文本变化定时器
    timer = new QTimer(this);
    connect(timer, &QTimer::timeout, this, &LoadingDialog::changeText);
}
// 启动动画与模态运行
void LoadingDialog::startLoading()
{
    movie->start();
    timer->start(500); // 每 500ms 刷新一次文本
    this->exec();      // 进入模态循环，阻塞调用者
}
// 隐藏与停止
void LoadingDialog::stopLoading()
{
    index = 0;
    timer->stop();
    movie->stop();
    this->accept();
}
// 5. 动态交替增加小数点
void LoadingDialog::changeText()
{
    index++;
    QString dots;
    if (index == 1) {
        dots = ".";
    } else if (index == 2) {
        dots = "..";
    } else {
        dots = "...";
        index = 0;
    }
    tip_label->setText(base_info + dots);
}

2.3 拆开看三个动作 #

movie->start()：QMovie 自己内部有一套帧推进机制，但别以为它独立于事件循环。它靠 QTimer 或内部空闲事件触发下一帧，同样吃事件循环。

timer->start(500)：每 500ms 进一次 changeText()，index 在 1/2/3/0 之间循环，拼出 .、..、...、空。四个状态里空的那一帧是刻意留的，不然点位只增不减，看不出「还在动」。

this->exec()：进入了模态事件循环。调用方这一行卡住，但 Qt 在 exec() 内部又开了一层自己的事件循环，所以 gif 在动、点在加、窗口能重绘。这是它跟「忙等」的本质区别——它虽然把调用方挡住了，却没把事件流挡住。

调用侧的写法：

cpp
void Widget::onQueryClicked()
{
    LoadingDialog dlg(this);
    QTimer::singleShot(0, &dlg, [&dlg]() {
        // 真正的耗时活儿放在这里，跑完关框
        doHeavyWork();
        dlg.stopLoading();
    });
    dlg.startLoading();
}

singleShot(0, ...) 是为了等 exec() 真的把循环跑起来之后再干活，不然计时器还没响应，stopLoading() 先执行了。

2.4 停止必须干净 #

stopLoading() 里三行都不能省：

cpp
index = 0;        // 归零，下次 start 从 "." 开始
timer->stop();    // 停文本定时器，否则 lambda 还在往里写
movie->stop();    // 停帧，省 CPU
this->accept();   // 退出 exec()

少停一个定时器，exec() 退出后对象已析构，槽函数还挂在定时器上，下一次超时就是野指针。这类崩溃堆栈里看到的往往是 QTimer 的 timeout，根因却在对象生命周期。

2.5 gif 白边的成因与解法 #

动图背景在 PS 里导出成透明，放到半透明蓝色底板上，边缘却是一圈白色毛刺。原因不在 Qt，在 GIF 这个格式。

现象 原因 解法
图案边缘一圈白毛 GIF 只有 1 位索引透明，边缘做抗锯齿时用白色做混合色 导出时把 Matte 色设成目标背景色
放大后边缘发糊 索引调色板只有 256 色，过渡色被量化掉 减小动图尺寸，靠 setScaledContents 放大
透明区变黑块 半透明窗口 + 1 位透明通道叠加 底板用不透明纯色，别叠在任意内容上

GIF 的透明通道是 1 位索引透明度：要么全透明，要么全不透明，不支持 Alpha 渐变半透明。为了边缘显得平滑，做图的人会在图案边缘加一圈和目标背景融合的过渡像素。如果他做图时的背景是白色，这圈过渡色就融合成了白边。放到非白底板上，白边立刻露出来。

解法只有一个方向：导出时把「混合/哑光（Matte）」颜色设成提示框的真实背景色。本文的底板是 rgb(55,135,215)，就把 Matte 也设成它。边缘像素与底板同色，视觉上就没有边界，动图看着是「长」在底板上的。

换底板就得重导一次 gif，这是 GIF 方案最烦的地方，也是下一篇要换纯代码的理由之一。

2.6 插件依赖 #

QMovie 读 gif 走的是 Qt 的 qgif 图片插件。两个坑：

  • 静态编译或者裁剪过的 Qt 没带 imageformats/qgif，QMovie 不报错，isValid() 返回 false，界面上就是一片空白。
  • 发布时 plugins/imageformats 目录没跟着 exe 走，本机跑得好，客户机上不动。

排查先打一行 qDebug() << movie->isValid() << movie->supportedFormats();，比盯着界面猜快得多。

三、等待提示框：纯代码绘制 #

gif 那套有一个绕不过去的短板：资源在别人手里。

3.1 换掉 gif 的四个理由 #

  • 显示模糊。gif 是点位图，塞进 120×120 的框里，缩放一下就糊。
  • 分辨率改不动。界面要上高分屏，得重新导一套图。
  • 移植麻烦。Qt 要带上 gif 插件才认，静态编译得自己编进去。
  • 依赖美工。你不是美工的时候，图得求人做，做出来还经常不是想要的，来回改的时间比写代码长。

纯代码画一个转圈，一个文件搞定，配色、尺寸、速度全是参数。

3.2 头文件 #

cpp
#ifndef PROGRESS_INDICATOR_H
#define PROGRESS_INDICATOR_H
#include <QWidget>
#include <QColor>
class QProgressIndicator : public QWidget
{
    Q_OBJECT
public:
    explicit QProgressIndicator(QWidget *parent = nullptr);
    bool isAnimated() const;
    int  animationDelay() const;
    void setColor(const QColor &color);
    QColor &getColor();
    bool isDisplayWhenStop() const;
    void setDisplayWhenStop(bool is_display_when_stop);
public slots:
    void startAnimation();
    void stopAnimation();
    void setAnimationDelay(int delay_time);
protected:
    void timerEvent(QTimerEvent *) override;
    void paintEvent(QPaintEvent *) override;
private:
    int    angle;                 // 当前旋转角度
    int    timer_id;              // startTimer 返回的 id，-1 表示没在转
    int    delay_time;            // 每帧间隔毫秒
    bool   is_display_when_stop;  // 停了之后还画不画
    QColor color;                 // 胶囊条颜色
};
#endif // PROGRESS_INDICATOR_H

整个类没有 QTimer 成员，只有一个 int timer_id。这是刻意的：省一个对象，也省一层信号槽。

3.3 实现 #

cpp
#include "progress_indicator.h"
#include <QPainter>
QProgressIndicator::QProgressIndicator(QWidget* parent)
    : QWidget(parent)
{
    setSizePolicy(QSizePolicy::Fixed, QSizePolicy::Fixed);
    setFocusPolicy(Qt::NoFocus);
    angle = 0;
    timer_id = -1;
    delay_time = 40;
    is_display_when_stop = false;
    color = Qt::black;
}
bool QProgressIndicator::isAnimated() const
{
    return (timer_id != -1);
}
int QProgressIndicator::animationDelay() const
{
    return delay_time;
}
void QProgressIndicator::setColor(const QColor &color)
{
    this->color = color;
    update();
}
QColor & QProgressIndicator::getColor()
{
    return color;
}
void QProgressIndicator::setDisplayWhenStop(bool is_display_when_stop)
{
    this->is_display_when_stop = is_display_when_stop;
    update();
}
bool QProgressIndicator::isDisplayWhenStop() const
{
    return is_display_when_stop;
}
void QProgressIndicator::startAnimation()
{
    angle = 0;
    if (timer_id == -1)
    {
        timer_id = startTimer(delay_time);
    }
}
void QProgressIndicator::stopAnimation()
{
    if (timer_id != -1)
    {
        killTimer(timer_id);
    }
    timer_id = -1;
    update();
}
void QProgressIndicator::setAnimationDelay(int delay_time)
{
    if (timer_id != -1)
    {
        killTimer(timer_id);
    }
    this->delay_time = delay_time;
    if (timer_id != -1)
    {
        timer_id = startTimer(delay_time);
    }
}
void QProgressIndicator::timerEvent(QTimerEvent *)
{
    angle = (angle + 30) % 360;
    update();
}
void QProgressIndicator::paintEvent(QPaintEvent *)
{
    if (!is_display_when_stop && !isAnimated())
        return;
    int width = qMin(this->width(), this->height());
    QPainter p(this);
    p.setRenderHint(QPainter::Antialiasing);
    int outer_radius = (width - 1) * 0.5;
    int inner_radius = (width - 1) * 0.5 * 0.4;
    int capsule_height = outer_radius - inner_radius;
    int capsule_width  = (width > 32) ? capsule_height * .30 : capsule_height * .35;
    int capsule_radius = capsule_width / 2;
    for (int i = 0; i < 12; i++)
    {
        QColor color = color;
        color.setAlphaF(1.0f - (i / 12.0f));
        p.setPen(Qt::NoPen);
        p.setBrush(color);
        p.save();
        p.translate(rect().center());
        p.rotate(angle - i * 30.0f);
        p.drawRoundedRect(-capsule_width * 0.5, -(inner_radius + capsule_height),
                          capsule_width, capsule_height,
                          capsule_radius, capsule_radius);
        p.restore();
    }
}

3.4 这段绘制在算什么 #

关键就四步，全是几何。

  1. 定基准：width = qMin(w, h)，取短边。控件被拉成 200×80 也只按 80 画，不会变形。
  2. 分内外圈：outer_radius 是外半径，inner_radius 是内半径，取 0.4 倍。两者之差 capsule_height 就是那根胶囊条的长度。
  3. 算胶囊粗细：capsule_width 按尺寸分档，宽过 32 用 0.30，否则用 0.35。小图标要给条子相对粗一点，不然眼睛看不见。
  4. 铺 12 根：for (i = 0; i < 12; i++)，每根转 angle - i * 30 度，12 × 30 = 360，正好一圈。

p.translate(rect().center()) 把坐标原点挪到中心，之后画在负数坐标上是相对中心定位，p.save()/restore() 保证每根的旋转互不污染。

透明度那行是灵魂：

cpp
color.setAlphaF(1.0f - (i / 12.0f));

i 从 0 到 11，alpha 从 1.0 线性降到 0.083 左右。第 0 根最实，往后越来越淡，视觉上就是「头部亮、尾巴淡」的拖尾，转起来才有方向感。少了这行，12 根一样黑，看着像静止的齿轮。

速度由 delay_time = 40 和 angle += 30 共同决定：40ms 走 30 度，转满一圈 12 帧要 480ms。

3.5 用法 #

cpp
QProgressIndicator *indicator = new QProgressIndicator(this);
indicator->setColor(QColor(55, 135, 215));
indicator->startAnimation();
// 活儿干完了
indicator->stopAnimation();

stopAnimation() 之后控件会「消失」，不是被 hide，是 paintEvent 里那行 if (!is_display_when_stop && !isAnimated()) return; 直接不画。想停了之后保留一个静止的图标，调 setDisplayWhenStop(true)。

有一处要留意：setAnimationDelay() 里两个 if (timer_id != -1) 的判断时机不对称。第一个 killTimer 之后 timer_id 并没有被置回 -1，所以第二个判断仍然成立，能重新起定时器；但如果进来时本来就没在转（timer_id == -1），两个判断都不成立，新值只是记下来，不会启动。想「改速度并立刻生效」，自己先 stopAnimation() 再 startAnimation() 更稳。

4.2 实现 #

cpp
#include "loading_widget.h"
#include <QPixmap>
// 公共辅助：把过长的字符串做省略显示
namespace Util {
    bool updateText(const QString &text, int width, QString &elidedText) {
        if (text.length() > 20) {
            elidedText = text.left(17) + "...";
            return true;
        }
        return false;
    }
}
LoadingWidget::LoadingWidget(QWidget *parent)
    : QWidget(parent)
{
    index = 1;
    loading_label = new QLabel(this);
    account_label = new QLabel(this);
    waiting_label = new QLabel(this);
    // 用第一帧的尺寸把 Label 定死，后面换帧不会抖动
    QPixmap pixmap(QString(":/loginDialog/") + QString::number(index, 10));
    loading_label->setFixedSize(pixmap.size());
    loading_label->setPixmap(pixmap);
    loading_label->setScaledContents(true);
    // 右半边：账号 + 等待提示语
    QVBoxLayout *v_layout = new QVBoxLayout();
    v_layout->addWidget(account_label);
    v_layout->addWidget(waiting_label);
    v_layout->setSpacing(15);
    v_layout->setContentsMargins(0, 0, 0, 0);
    // 水平布局：左图 + 右文本，两侧加弹簧居中
    QHBoxLayout *h_layout = new QHBoxLayout();
    h_layout->addStretch();
    h_layout->addWidget(loading_label);
    h_layout->addLayout(v_layout);
    h_layout->addStretch();
    h_layout->setSpacing(20);
    h_layout->setContentsMargins(0, 0, 0, 30);
    // 100ms 一帧，每秒 10 帧
    timer = new QTimer(this);
    timer->setInterval(100);
    connect(timer, &QTimer::timeout, this, &LoadingWidget::updatePixmap);
    this->setLayout(h_layout);
    this->translateLanguage();
}
LoadingWidget::~LoadingWidget()
{
}

{

}

    this->account = account;

// 核心：图片轮播更新
void LoadingWidget::updatePixmap()
{
    index++;
    // 总共 8 张序列帧，命名 1.png ... 8.png
    if (index > 8) {
        index = 1;
    }
    QPixmap pixmap(":/loginDialog/" + QString::number(index, 10));
    loading_label->setPixmap(pixmap);
}

三个细节值得单独点一下。

尺寸先定死。loading_label->setFixedSize(pixmap.size()) 拿第一帧的尺寸把 Label 锁住。不锁的话，八张图里只要有一张尺寸差一像素，布局就会每 100ms 抖一次，肉眼看得见。

资源路径拼得取巧。QString::number(index, 10) 转成十进制字符串，直接拼到 ":/loginDialog/" 后面。qrc 里的别名没有扩展名，所以 :/loginDialog/1 就能找到 1.png。别名写错的表现是图没了、也不报错，只留个空 Label。

停止要回第一帧。start(false) 里除了停定时器，还要把 index 归 1 并重设 pixmap。不然下次登录从第七帧开始，看着像卡了一下。

4.3 换个更轻的定时器 #

new QTimer + 信号槽做帧切换，能跑，但多一层连接。省掉 QTimer 成员，改用 QObject::startTimer()，在 timerEvent() 里接活：

cpp
// 构造函数里直接启用内置定时器
// int timerId = this->startTimer(100);
void LoadingWidget::timerEvent(QTimerEvent *event)
{
    if (event->timerId() != timerId)
        return;
    index++;
    if (index > 8) {
        index = 1;
    }
    loading_label->setPixmap(QPixmap(QString(":/loginDialog/") + QString::number(index, 10)));
}

类声明少一个成员，少一次信号槽投递。代价是定时器 id 得自己管，忘了 killTimer(timerId) 就是关不掉的动画。

event->timerId() != timerId 这行判断别省。一个控件上挂了多个 startTimer 时，timerEvent 会把所有定时器的超时都送到同一个函数，不按 id 分流，两套动画就串在一起了。

五、三种等待实现的对比 #

三种做法都能转圈，选型看资源和约束。

维度 QMovie + gif 纯代码绘制 多图片轮换
外部资源 一个 gif 文件 无 一组 1..N 的 png
分辨率自适应 差，拉伸就糊 好，按控件短边算 差，受首帧尺寸限制
换配色 重新导图 一行 setColor 重新出图
速度调节 改 gif 帧延时，需重导 delay_time 一个参数 改 setInterval
帧驱动 QMovie 内部 timerEvent 改 angle QTimer 改 index
依赖事件循环 是 是 是
代码量 最少 中 中
适用场景 设计给了成品 gif 要任意尺寸与配色 美术给了序列帧

判断顺序可以这么走：

  • 有现成 gif、尺寸固定、只在一处用 → QMovie，最省事。
  • 要上高分屏、要跟随主题色、要嵌入到各种尺寸的框里 → 纯绘制，别犹豫。
  • 美术只给了序列帧，且必须是那种有质感的 3D 球 → 多图片轮换，接受固定尺寸。
  • 三者都要注意：动画由定时器驱动，定时器由事件循环驱动。这一层没变过。

还有一条不属于代码的选型标准：谁维护。gif 的改动成本在美工，纯绘制的改动成本在改那一行参数的人。团队里没有能出图的人，纯绘制就是更靠谱的那条路。

六、自定义提示框：仿 QMessageBox #

QMessageBox 好用，但它的控件类型、尺寸、布局、默认样式全是内置的。直接把没做过样式处理的默认弹框丢给用户，界面格调立刻掉一档。真实项目里要让提示框和主界面是同一套视觉，只能继承 QDialog 自己画。

6.1 无边框之后要补的四件事 #

  1. 没有标题栏了 → 自己画标题文本 + 关闭按钮，用绝对坐标摆。
  2. 窗口拖不动了 → 自己处理 mousePressEvent / mouseReleaseEvent / mouseMoveEvent。
  3. 直角窗口压着圆角背景图 → 用 QBitmap 做遮罩裁剪。
  4. 图标、文本、复选框、确定按钮的显隐要组合 → 用一个 setInfo 一次配齐。

        emit msgChecked(check_box->isChecked(), true);
    }
    this->accept();

{
    if (!check_box->isHidden()) {
        if (!ok_button->isHidden()) {
            emit msgChecked(check_box->isChecked(), false);
        } else {
            emit okMessageHidden(check_box->isChecked());
        }
    }
    this->reject();
}

6.4 三个容易写错的点 #

遮罩靠 QBitmap。QBitmap 是 1 位色深的图，白色 = 不透明、黑色 = 透明。先整张填白，再画一个黑色圆角矩形，setMask(bitmap) 之后窗口就只剩圆角矩形那块可见。写在 paintEvent 里是为了跟着尺寸走：窗口一 resize，下一帧就重建遮罩。代价是每次重绘都要分配一张位图，尺寸固定时可以把 setMask 挪到 resizeEvent。

拖拽的偏移量在 press 里算。move_point = event->globalPos() - pos() 记的是「鼠标点落在窗口内部的哪个位置」。move 里用新的 globalPos 减掉它，窗口就贴着鼠标走。若在 move 里现算偏移，窗口会抖着跳。

两个信号的语义不一样。msgChecked(checked, is_ok) 是「有复选框、也有两个按钮」时用，第二个参数区分确定/取消；okMessageHidden(checked) 是「只有一个按钮」时用。判断依据是 ok_button->isHidden()，别用 check_box->isChecked() 去猜。

6.5 用法 #

cpp
// 双按钮确认（例：文件删除）
MsgBox *msg_box = new MsgBox(this);
msg_box->setInfo(QString("文件删除"), QString("确实要把文件放入回收站吗?"),
                 QPixmap(":/icon/attention"), true, false);
if (msg_box->exec() == QDialog::Accepted) {
    // 执行删除
}
// 单按钮警告（例：文件名非法）

msg_box2->setInfo(QString("重命名"), QString("文件名不能包含下列任何字符：\n     \\ / : * ? \" < > |"),
                  QPixmap(":/icon/attention"), true, true);
msg_box2->exec();
// 带复选框（例：批量删除，可记住选择）
MsgBox *msg_box3 = new MsgBox(this);
msg_box3->setInfo(QString("批量文件删除"), QString("确实要把所有文件放入回收站吗?"),
                  QPixmap(":/icon/attention"), false, false);

exec() 的返回值来自 accept() 和 reject()，也就是 okOperate() 和 cancelOperate() 最后那两行。业务代码只认 Accepted 还是 Rejected，不用管点的是哪个按钮。

七、自定义提示框：右下角冒泡 #

网页右下角老弹那种提示，桌面端一样能做。原理拆开就三段：

  1. 显示：从屏幕底部往上缓慢移动，定时器一格一格改位置，到位就停。
  2. 驻留：另一个定时器数秒，数够了切下一段。
  3. 退出：直接关，或者一格一格降透明度，淡到看不见再关。

三段各有一个定时器，接力跑。这是本章最值得记的结构。

7.3 三个定时器各管一段 #

定时器 间隔 干什么 谁停它
timer_show 5ms 每次把 y 减 1，从屏幕底部升到目标位置 y 到位后自己停，启动 timer_stay
timer_stay 1000ms 数到 9，也就是停 9 秒 数满后自己停，启动 timer_close
timer_close 200ms 每次透明度减 0.1，10 次淡到 0 透到 0 后自己停，调 close()

注意三处接力都是「停自己 + 起下一个」，而且 showMessage() 一进来先把三个全 stop 再重置状态。少了这个重置，气泡连弹两次时会带着上一轮的透明度和位置跑。

timer_show 用 5ms 是有点浪费的，800ms 内跑 160 次 move()；改成 15~20ms 一次、每次挪 4~5 像素，效果一样，CPU 少一截。

7.4 定位用 availableGeometry #

cpp
desk_rect = desktop->availableGeometry();
normal_point.setX(desk_rect.width() - rect().width());
normal_point.setY(desk_rect.height() - rect().height());

availableGeometry() 扣掉了任务栏，geometry() 没有。用前者，气泡才不会被任务栏压住；用后者，在底部任务栏的机器上会少掉一条。

setWindowFlags 里加了 Qt::WindowStaysOnTopHint，气泡才会浮在别的窗口上。代价是它也会盖住你自己的模态框，所以气泡都不设父窗口——有父窗口，层级就会把它吞掉。

8.2 八个点怎么走 #

drawPolygon 按点的顺序连线并填充，所以点的顺序就是轮廓。

序号 坐标 拐到哪
0 (15, 0) 左上，尖角的顶点
1 (15, 15) 尖角右侧下来
2 (0, 15) 往左平移到左边缘
3 (0, height-1) 左下
4 (width-1, height-1) 右下
5 (width-1, 15) 右上，回退到 y=15
6 (30, 15) 沿顶边往左，到尖角右侧
7 (15, 0) 回到起点，闭合

0 → 1 → 2 画出的是左上那个小三角尖；2 → 3 → 4 → 5 是主体矩形；5 → 6 是顶边那一段；6 → 7 把尖角左边补齐。整个图形只在左上角「挖」了一个向上突出的尖。

想改尖角位置，只改前三个点和后两个点；想改尖角宽度，把那个 15 和 30 一起改，保持 30 = 15 × 2，尖角才是等腰的。

8.3 透明背景的两个前提 #

cpp
setWindowFlags(Qt::FramelessWindowHint);
setAttribute(Qt::WA_TranslucentBackground);

两行缺一不可。没有 FramelessWindowHint，系统边框会画在图形外面；没有 WA_TranslucentBackground，尖角以外的区域会填成灰色或黑色方块，多边形再准也没用。

tip_label->move(1, 16) 里的 16 是给尖角让位：文本从尖角下面开始排，不会压到那个三角上。宽度减 2、高度减 17，是给左右各 1px 的边框和对上方的 16px 留白。

8.4 三种提示框放在一起比 #

维度 仿 QMessageBox 右下角冒泡 不规则提示
基类 QDialog QWidget QWidget
模态性 模态，exec() 取返回值 非模态，不取返回值 非模态
形状 矩形 + QBitmap 圆角 矩形 + QBitmap 圆角 drawPolygon 多边形带尖角
定位 居中于父窗口 右下角，从屏幕底部升起 贴光标或贴控件
消失方式 用户点按钮 三段定时器接力 定时器或失焦即关
打断用户 会 不会 不会
适合 需要用户决策的操作 通知类信息 输入校验的即时提示

三者的共同点是「自己画、自己摆、自己收」，不同点全在「谁来决定它消失」。需要用户表态的，交按钮；只是通知的，交定时器；校验提示这种跟输入绑定的，交输入框的 focusOut 或下一次输入。

九、提示框的自动消失与定位 #

9.1 三条消失路径 #

路径 写法 适合 依赖什么
一次性定时 QTimer::singleShot(ms, obj, &F::close) 提示框只管弹一下 事件循环
步进定时 定时器每 tick 改透明度/坐标，到阈值再 close() 需要淡出、滑出 事件循环
用户操作 按钮 clicked 接 accept()/close() 警告确认 用户

第一种最省事：

cpp
QTimer::singleShot(3000, &tip, &QWidget::close);

单次定时器到点发一次 timeout 然后自己销毁，不用管生命周期。前提是那个 tip 活过这 3 秒——栈对象活得比函数短，3 秒后就是野指针。要么让它是 new 出来的（setAttribute(Qt::WA_DeleteOnClose) 收尾），要么用 this 当上下文，让 Qt 在对象销毁时自动断掉这次定时。

第二种就是冒泡那套 myClose()：每 200ms 把 setWindowOpacity 减 0.1，减到 0 才 close()。想滑动退出，把透明度换成坐标，逻辑一样。

关于消失，最该记住的一句是：singleShot 和 QTimer 是同一个东西。「设了 3 秒自动关，结果 30 秒都不关」不是定时器坏了，是主线程没回到事件循环。等主线程闲下来，那几次超时会一次性挤进来。

9.2 定位 #

右下角冒泡用的是 availableGeometry()：

cpp
QRect avail = QApplication::desktop()->availableGeometry();
int x = avail.right()  - width()  - 20;
int y = avail.bottom() - height() - 20;
move(x, y);

availableGeometry() 扣掉了任务栏和屏幕边缘保留区，geometry() 没扣。用错的那个，气泡会被任务栏压住一条。

贴着父窗口弹出的居中写法：

cpp
QWidget *p = parentWidget();
QPoint center = p->mapToGlobal(p->rect().center());
move(center.x() - width() / 2, center.y() - height() / 2);

多显示器下 QApplication::desktop()->availableGeometry(widget) 要传 widget，拿到的才是那块屏的可用区域。不传，拿到的是主屏，副屏上弹出来的位置全偏。

十、进度条：QProgressBar #

设计器里拖一个按钮和一个 QProgressBar，构造函数里先初始化量程：

cpp
ui->progressBar->setRange(0, 50000 - 1);
ui->progressBar->setValue(0);

按钮的槽里按任务进度改值：

cpp
void MainWindow::on_pushButton_clicked()
{
    for (int i = 0; i < 50000; i++)
    {
        for (int j = 0; j < 20000; j++);   // 假装在干活
        ui->progressBar->setValue(i);
    }
}

setValue() 会按 range 自动算百分比并显示，不用自己乘 100。

跑起来却是窗口一片白、标题栏写着「无响应」、进度条一动不动。原因不在 setValue，在事件循环：setValue() 只改成员变量再调 update()，而 update() 不绘制，只往事件队列塞一个 QPaintEvent；队列得靠事件循环来取，你却卡在 50000 × 20000 的空转里，一层都没退出去。这几十秒里界面唯一的变化，是系统把窗口标成「无响应」。

让它动起来，只需要在循环里给事件循环一个出口：

cpp
void MainWindow::on_pushButton_clicked()
{
    for (int i = 0; i < 50000; i++)
    {
        for (int j = 0; j < 20000; j++);
        ui->progressBar->setValue(i);
        QCoreApplication::processEvents();   // 让事件队列被处理一次
    }
}

加了这一行，进度条动了，窗口也不标「无响应」了。代价在第十二章。

十一、进度对话框：QProgressDialog #

QProgressDialog 把「进度条 + 标签 + 取消按钮」打包成一个对话框，调法和 QProgressBar 差不多：

cpp
void MainWindow::on_pushButton_clicked()
{
    QProgressDialog process(this);
    process.setLabelText(tr("processing..."));
    process.setRange(0, 50000);
    process.setModal(true);
    process.setCancelButtonText(tr("cancel"));
    for (int i = 0; i < 50000; i++)
    {
        for (int j = 0; j < 20000; j++);
        process.setValue(i);
        if (process.wasCanceled())
            break;
    }
}

注意这段代码里没有 processEvents()，进度条却在动。这不是玄学，是 QProgressDialog::setValue() 内部干了活：它在模态状态下会自己调一次 QCoreApplication::processEvents()，好让「取消」按钮能被点上。不这么做，一个模态对话框就把自己的取消按钮锁死了——按钮事件同样进不了队列。

两个控件的差别：

维度 QProgressBar QProgressDialog
形态 嵌在界面里的条 独立弹出的对话框
取消按钮 得自己加 自带，文字可改
刷新靠谁 得自己 processEvents() setValue() 内部已经调了
模态性 无 setModal(true) 后挡住主界面
用在哪 进度是界面的一部分 进度要独占用户注意力

wasCanceled() 必须在每轮循环里查，而且查到就得真的 break。只查不退，用户点了取消，进度条还在一格一格走到 100%，那是骗人。

十二、阻塞式反馈与异步反馈 #

12.1 模态不是「界面停了」 #

exec() 挡住的是调用方那一行代码，界面没停——它自己开了一层事件循环，所以 gif 会动、点会加、按钮能点。区别只在于：模态事件循环会拦下发给其他窗口的输入，主界面看得见、点不动。

QProgressDialog 更微妙：setValue() 内部的 processEvents() 会把积压的输入事件一起派发出去，所以「取消」能点。同样被派发的，还有主界面上其他控件的输入事件。

12.2 代价一：重入 #

processEvents() 期间用户点到了主界面的另一个按钮，那个槽函数会当场执行完再返回，你才继续跑循环。如果槽里又开了个模态框、改了你正在用的容器、删了当前对象，回到循环时状态已经不是离开时的样子。这是「进度条动了，程序偶尔崩」最常见的原因，堆栈里指向的往往是你以为不会重入的那一行。

防守动作：跑 processEvents() 前后禁用会引发重入的控件；判一个「正在处理」标志位，重入直接返回；别用裸指针指向会被删的对象，用 QPointer；只放必要的队列进来——processEvents(QEventLoop::ExcludeUserInputEvents) 把输入排除，进度条照样刷，用户点不动东西。

12.3 代价二：取消后的半成品 #

break 出来只是停了循环，已经写到一半的文件、已经插了一半的数据都还在。取消路径要和正常路径一样有清理：关文件、删临时文件、回滚事务、复位状态机。

12.4 正解：把活儿搬出主线程 #

三种做法的取舍：

做法 界面能否刷新 主界面能否操作 重入风险 代码量
忙循环 + 模态框 靠 exec() 的事件循环 不能 低 少
忙循环 + processEvents() 能 能 高 中
工作线程 + 信号槽 能 能 无 多

第三种是把耗时逻辑放进 QThread 或 QtConcurrent，主线程只管收信号改 UI：

cpp
QThread *worker = new QThread(this);
Worker *w = new Worker;          // Worker 里是纯计算，不碰任何控件
w->moveToThread(worker);
connect(worker, &QThread::started, w, &Worker::run);
connect(w, &Worker::progress, progressBar, &QProgressBar::setValue);  // 跨线程自动排队
connect(w, &Worker::finished, worker, &QThread::quit);
connect(worker, &QThread::finished, w, &QObject::deleteLater);
worker->start();

跨线程的信号槽默认走队列连接，progress 会被投递回主线程的事件循环里执行。主线程全程空闲，进度自己会更新，不需要 processEvents()，也就不存在重入。

一条边界：Worker 里只放计算，不要在里面 new QWidget、不要碰 QPixmap、不要调 setValue。Qt 的界面类只能在其所属线程使用，跨线程碰控件是未定义行为，崩得还很随机。

症状 根因 改法
