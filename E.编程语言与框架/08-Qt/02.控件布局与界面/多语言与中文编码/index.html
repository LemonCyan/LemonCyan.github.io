这篇只讲界面上的「文字」：同一界面怎么按语言换文案，中文怎么不乱码，嵌入式板子上没有实体键盘时输入从哪来。

不讲布局细节，不讲样式表，不讲 QML 的 qsTr（机制同源，只换了提取工具）。控件用法、菜单托盘、布局架构在同目录其他篇里。

一、Qt 的国际化机制 #

一句话：源码里写原文，运行时按语言加载翻译。

你写 tr("welcome")，代码里就是 welcome 这个英文词。用户切到中文，QTranslator 从 .qm 里查出 welcome 对应 欢迎，控件就显示中文。C++ 里一个汉字都没有。

好处三条：加语言只加 .qm 不改代码；源码纯 ASCII，跟显示编码彻底解耦；翻译外包只需要给 .ts。

阶段 做什么 输入 输出 工具
1 打标记 用 tr() 包住可见文本 .cpp / .ui 带 tr() 的源码 手写
2 提取 扫源码收集所有 tr() 源码目录 .ts（XML） lupdate
3 翻译 逐条填译文 .ts .ts（已填） Qt Linguist
4 编译 转二进制 .ts .qm lrelease
5 加载 启动或切换时装进去 .qm 界面换语言 QTranslator

阶段边界要把住：.ts 是中间格式，人读人改；.qm 是运行时格式，程序读，人改不了。改了 .ts 不等于改了 .qm。

text
tr("welcome") 改成 tr("hello")
   ├─ 没跑 lupdate      → .ts 里还是 welcome → 界面显示 hello
   ├─ 跑了没译          → .ts 里 hello 是 unfinished → 界面显示 hello
   └─ 译了没跑 lrelease → .qm 里没有 hello → 界面显示 hello

三种断法现象一样：显示英文原文。所以「国际化配了没用」九成不是代码问题，是流水线没跑全。

别写 tr("欢迎使用")。源码一旦被 MSVC 按 GBK 解释，.ts 里提取出来就是乱码；这门语言也只剩中文，想加英文得回头改代码。不翻译的常量用 QStringLiteral。

.qm 别裸放在安装目录，用户手一抖删了界面就回退成英文。扔进 .qrc：

xml
<RCC>
    <qresource prefix="/qm">
        <file>app_zh_CN.qm</file>
        <file>qt_zh_CN.qm</file>
    </qresource>
</RCC>

代价是改翻译要重编译，发布版无所谓。

二、tr 与 QObject::tr 的区别 #

tr() 不是关键字，是 QObject 的静态成员函数。

cpp
static QString QObject::tr(const char *sourceText,
                           const char *disambiguation = nullptr,
                           int n = -1);

Q_OBJECT 展开时会塞一个 tr 重载，它和 QObject::tr 只差一件事：context。

写法 context 适用场景
类内 tr("x") 当前类名，如 MainWidget 有 Q_OBJECT 的类，占绝大多数
QObject::tr("x") 固定 QObject 自由函数、main()
QCoreApplication::translate("Ctx", "x") 手写 Ctx 明确指定上下文

"MainWidget" 会原样写进 .ts 的 <context><name>。翻译表按 context 分段，所以跨类同名文本互不干扰：MainWidget 的 "ok" 和 SettingDialog 的 "ok" 是两条独立条目，能翻成两个词。

自由函数里没有 this，写 tr() 编不过：

cpp
static QString makeTitle()
{
    return QCoreApplication::translate("Common", "application title");  // 自带上下文
}

非 QObject 的纯工具类想用裸 tr()，类里加一句 Q_DECLARE_TR_FUNCTIONS(StringUtil)，context 就变成 StringUtil。

tr 是静态的，这是「切换语言不生效」的根因 #

tr() 在调用那一刻查表返回一份 QString 拷贝，之后跟翻译表再无联系。

cpp
MainWidget::MainWidget(QWidget *parent) : QWidget(parent)
{
    label = new QLabel(tr("welcome"), this);   // 此刻取到「欢迎」，字符串定死
}

后面 installTranslator 装进新语言，这个 QLabel 上的文字不会自己变。翻译表变了，赋过值的控件不知道。所以每条可见文本的赋值要集中到一个能反复调用的函数里，这就是第六章的 translateLanguage()。这不是风格偏好，是 tr() 语义决定的硬约束。

静态数组、const char* 常量表编译期不能调 tr()，用标记宏让 lupdate 认出来：

cpp
static const char *const g_items[] = { QT_TR_NOOP("open"), QT_TR_NOOP("save") };
menu->addAction(tr(g_items[0]));    // 用的时候逐个翻

跨类引用别人的常量用 QT_TRANSLATE_NOOP("OtherClass", "text")。复数用第三个参数 tr("%n file(s)", "", count)。

三、ts 文件与 lupdate #

lupdate 只干一件事：扫源码，把 tr() 里的字符串抠进 .ts。

bash
lupdate src/ -ts translations/app_zh_CN.ts

.pro 工程更省事，先声明再一条命令全刷：

bash
TRANSLATIONS += translations/app_zh_CN.ts \
                translations/app_en_US.ts
lupdate app.pro

它会顺带扫 .ui 的 retranslateUi() 和 QML 的 qsTr()，不用手写提取规则。Creator 里对应 工具 → 外部 → Linguist → 更新翻译。

.ts 长这样：

xml
<TS version="2.1" language="zh_CN">
<context>
    <name>MainWidget</name>
    <message>
        <location filename="main_widget.cpp" line="72"/>
        <source>main widget</source>
        <translation type="unfinished"></translation>
    </message>
</context>
</TS>

要点四条：language 由文件名后缀推导，app_zh_CN.ts → zh_CN，文件名别乱起；<location> 只是行号提示，不参与查表；unfinished 是空的，运行时回退显示 <source> 原文；译文填了但没在 Linguist 里点「完成」，还是 unfinished，lrelease 会跳过。

改代码后重跑 lupdate 不是全量重建，是合并：

源码变化 .ts 结果 你要做什么
新增 tr("copy") 新条目，unfinished 翻译它
tr("ok") 改成 tr("confirm") 旧条目 obsolete，新条目 unfinished 译新条，清旧条
删掉某个 tr() 条目带 vanished 注释留着 加 -no-obsolete 清
译文没动 原样保留 什么都不用做

obsolete 条目不会自己消失，重构几次 .ts 能膨胀一倍。定期清：

bash
lupdate app.pro -no-obsolete

最容易踩的一条：改了源码里的英文字面量，忘了重跑 lupdate。.ts 没新串，.qm 没新串，运行时 tr("confirm") 查不到，界面显示 confirm。看着像「翻译失效」，其实是提取没做。

四、翻译与 lrelease #

Linguist 打开 .ts，三栏是上下文列表 / 字符串列表 / 编辑区。每条有两种状态，翻完得手动置位：

标记 含义 lrelease 是否收录
无标记 unfinished 未翻译 不收，运行时显示原文
✓ 绿色 已翻译并确认 收录
? 黄色 有警告（长度、标点、占位符） 收录，但要人看一眼

占位符 %1、%2 数量对不上会报警告。中文语序和英文不同，很容易漏 %1，运行时就少一段内容。

bash
lrelease translations/app_zh_CN.ts -qm app_zh_CN.qm

lrelease app.pro      # 批量，按 TRANSLATIONS 出
lrelease *.ts         # 不用工程文件也行

Linguist 里 文件 → 发布 等价，输出到同级目录。

维度 .ts .qm
格式 XML 文本 二进制
谁读 人、Linguist QTranslator
体积 大，几十 KB 到几 MB 小，约为 .ts 三四成
能否手改 能 不能
运行时可加载 不能 能
版本管理 提交进 git 构建产物，可不提交

查表键是 (context, source, disambiguation) 三元组的哈希。.qm 本质是哈希表，加载时整块读入内存，查一次常数时间，所以切语言不用重建控件。

tr() 只管字符串，日期、货币、千分位归 QLocale：

cpp
QLocale locale(QLocale::Chinese, QLocale::China);
qDebug() << locale.toString(QDate::currentDate(), QLocale::LongFormat);

两件事常被混在一起，结果界面中文、日期还是 MM/dd/yyyy。

五、加载翻译文件 #

load() 最常用的重载是「文件名 + 目录前缀」，filename 不带 .qm 后缀。写成 "app_zh_CN.qm" 加载失败，而且不抛异常，只返回 false。这个坑吃掉过一下午。

cpp
#include <QApplication>
#include <QTranslator>
#include <QLibraryInfo>
#include "main_widget.h"

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QTranslator app_translator;                      // 自己的翻译
    if (app_translator.load("app_zh_CN", ":/qm")) {
        app.installTranslator(&app_translator);
    } else {
        qWarning() << "load app_zh_CN.qm failed";
    }

    QTranslator qt_translator;                       // 内置控件的翻译
    const QString qt_dir = QLibraryInfo::location(QLibraryInfo::TranslationsPath);
    if (qt_translator.load("qt_zh_CN", qt_dir)) {
        app.installTranslator(&qt_translator);
    } else {
        qWarning() << "load qt_zh_CN.qm failed, dir =" << qt_dir;
    }

    MainWidget w;
    w.show();
    return app.exec();
}

两个 translator 都是 main 的栈变量，活到 app.exec() 返回，生命周期正好。installTranslator 不接管所有权，只存指针。你把 QTranslator 定义在会退出的函数里，或者 new 完又 delete，指针悬空，下次查表直接崩。

内置控件的英文按钮和右键菜单 #

典型的「汉化不彻底」：自己的界面全中文，点个 QMessageBox 弹 Yes / No / Cancel，QLineEdit 右键是 Undo / Cut / Copy / Paste / Select All。

有人图省事 setContextMenuPolicy(Qt::NoContextMenu) 把右键菜单关掉。文本录入区这么干，用户没法复制粘贴，体验直接崩。

正解是加载官方 qt_zh_CN.qm。这些字符串属于 QPlatformTheme、QLineEdit、QMessageBox 等 Qt 自己的上下文，你的 .ts 里根本没有。从安装目录拿：

text
C:\Qt\Qt5.15.2\5.15.2\msvc2019_64\translations\qt_zh_CN.qm
/opt/Qt/6.5.3/gcc_64/translations/qt_zh_CN.qm

复制到工程，扔进 .qrc（前缀 "/qm"），再加载：

cpp
QTranslator translator;
if (translator.load("qt_zh_CN", ":/qm")) {
    app.installTranslator(&translator);
} else {
    qWarning() << "Failed to load translation file: qt_zh_CN";
}

Qt6 里 QLibraryInfo::location() 换成了 QLibraryInfo::path()：

cpp
#if QT_VERSION >= QT_VERSION_CHECK(6, 0, 0)
    const QString qt_dir = QLibraryInfo::path(QLibraryInfo::TranslationsPath);
#else
    const QString qt_dir = QLibraryInfo::location(QLibraryInfo::TranslationsPath);
#endif

部分精简安装包的 translations 目录里只有 qt_zh_CN.ts，自己编一份：lrelease qt_zh_CN.ts -qm qt_zh_CN.qm，或者 Linguist 打开走 文件 → 发布。

多个 translator 可以共存，查表时后装的先查：

cpp
app.installTranslator(&qt_translator);    // 先装：兜底的内置控件翻译
app.installTranslator(&app_translator);   // 后装：优先命中的应用翻译

反过来的话，你 .ts 里碰巧有 QLineEdit 上下文的重名条目，会被官方包盖掉。

六、语言切换的运行时实现 #

需求两条：不重启就换语言；下次启动记住上次的选择。三件事缺一不可。

  1. 所有可见文本用 tr() 包住，一处不能漏。
  2. 所有 setText / setWindowTitle 集中进 translateLanguage()，构造函数末尾也调它。
  3. 换语言后依次调所有活着的窗口和对话框的 translateLanguage()。

语言用枚举，别用下拉框下标——以后加一门日文插在中间，switch 不用跟着改。

cpp
enum LANGUAGE
{
    UI_ZH = 0,  // 中文
    UI_EN = 1   // 英文
};

主窗体要存成员：所有控件指针、SettingDialog *setting_dialog、QTranslator *m_translator、LANGUAGE m_currentLanguage。构造函数只搭架子，文本一律不写死。

cpp
MainWidget::MainWidget(QWidget *parent)
    : QWidget(parent)
{
    this->setMinimumSize(400, 300);

    welcome_label  = new QLabel();
    setting_button = new QPushButton();
    ok_button      = new QPushButton();
    cancel_button  = new QPushButton();
    setting_dialog = new SettingDialog(this);

    QHBoxLayout *button_layout = new QHBoxLayout();
    button_layout->addStretch();
    button_layout->addWidget(setting_button);
    button_layout->addWidget(ok_button);
    button_layout->addWidget(cancel_button);
    button_layout->setSpacing(10);

    QVBoxLayout *main_layout = new QVBoxLayout();
    main_layout->addWidget(welcome_label, 0, Qt::AlignCenter);
    main_layout->addLayout(button_layout);
    main_layout->setContentsMargins(10, 10, 10, 10);
    this->setLayout(main_layout);

    // 关键点 1：构造末尾先重译一次，把初值填上
    this->translateLanguage();

    connect(setting_button, &QPushButton::clicked, this, &MainWidget::showSetting);
    connect(setting_dialog, &SettingDialog::switchLanguage,
            this, &MainWidget::onSwitchLanguage);
}

// 关键点 2：所有 tr() 集中在这里，随时可重入
void MainWidget::translateLanguage()
{
    this->setWindowTitle(tr("main widget"));
    welcome_label->setText(tr("welcome to Qt"));
    setting_button->setText(tr("setting"));
    ok_button->setText(tr("ok"));
    cancel_button->setText(tr("cancel"));
}

// 关键点 3：加载翻译文件并分发重译
void MainWidget::onSwitchLanguage(int index)
{
    LANGUAGE language = static_cast<LANGUAGE>(index);
    if (m_currentLanguage == language) {
        return;                       // 选了同一门语言，什么都不做
    }
    m_currentLanguage = language;

    QString language_qm;
    switch (language) {
    case UI_EN: language_qm = QString(":/qm/main_widget_en"); break;
    case UI_ZH:
    default:    language_qm = QString(":/qm/main_widget_zh"); break;
    }

    m_translator->load(language_qm);          // 同一个 QTranslator 重新 load
    this->translateLanguage();                // 重译主界面
    setting_dialog->translateLanguage();      // 重译子对话框
    Util::writeInit("./user.ini", "language", QString::number(language));  // 存盘
}

void MainWidget::showSetting()
{
    setting_dialog->loadConfig();     // 打开前把当前语言同步到下拉框
    setting_dialog->exec();
}

Util::writeInit / readInit 就是个 QSettings 包装。没有这两行，用户每次启动都得重选语言，前面白干。

对话框只负责发信号，不碰翻译器。职责分开，主窗体一个人管加载。

cpp
SettingDialog::SettingDialog(QWidget *parent)
    : QDialog(parent)
{
    this->setMinimumSize(300, 200);
    this->setWindowFlags(windowFlags() & ~Qt::WindowContextHelpButtonHint);

    language_label     = new QLabel();
    language_combo_box = new QComboBox();
    info_label         = new QLabel();

    language_combo_box->addItem("Chinese (中文)", UI_ZH);
    language_combo_box->addItem("English (英文)", UI_EN);

    QHBoxLayout *lang_layout = new QHBoxLayout();
    lang_layout->addStretch();
    lang_layout->addWidget(language_label);
    lang_layout->addWidget(language_combo_box);
    lang_layout->addStretch();

    QVBoxLayout *main_layout = new QVBoxLayout();
    main_layout->addWidget(info_label, 0, Qt::AlignCenter);
    main_layout->addLayout(lang_layout);
    this->setLayout(main_layout);

    this->translateLanguage();

    connect(language_combo_box, SIGNAL(currentIndexChanged(int)),
            this, SIGNAL(switchLanguage(int)));
}

void SettingDialog::translateLanguage()
{
    this->setWindowTitle(tr("setting dialog"));
    info_label->setText(tr("no brothers no programming"));
    language_label->setText(tr("language"));
    language_combo_box->setItemText(UI_ZH, tr("chinese"));
    language_combo_box->setItemText(UI_EN, tr("english"));
}

setItemText(UI_ZH, ...) 能这么写，是因为枚举值和索引正好对齐。加语言时要么保证这个对齐，要么用 language_combo_box->setItemText(language_combo_box->findData(UI_ZH), tr("chinese"))。currentIndexChanged 传的是索引不是 userData，槽里还得转一次。

入口读回上次的选择：

cpp
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QString language_value;
    QString language_suffix = "zh";
    LANGUAGE language = UI_ZH;

    if (Util::readInit("./user.ini", "language", language_value)) {
        language = static_cast<LANGUAGE>(language_value.toInt());
        if (language == UI_EN) {
            language_suffix = "en";
        }
    }

    QTranslator translator;
    translator.load(QString(":/qm/main_widget_") + language_suffix);
    app.installTranslator(&translator);

    MainWidget main_widget;
    main_widget.setTranslator(&translator);   // 交给主窗体，切换时复用
    main_widget.setLanguage(language);
    main_widget.show();

    return app.exec();
}

translator 是独立变量，主窗体的 m_translator 只是指针别名，切语言时 load() 一直操作同一对象，不漏内存。启动只 installTranslator 一次，初值靠构造函数里的 translateLanguage() 填，别在 main 里再 setWindowTitle 一遍。

更省事：接 LanguageChange 事件 #

窗口一多，onSwitchLanguage 里就得写一长串 xxx_window->translateLanguage()，漏一个就漏一个。installTranslator / removeTranslator 会让所有顶层窗口收到 QEvent::LanguageChange：

cpp
void MainWidget::changeEvent(QEvent *event)
{
    if (event->type() == QEvent::LanguageChange) {
        translateLanguage();
    }
    QWidget::changeEvent(event);
}

两个前提：在已装上的 translator 上重新 load() 不触发事件，得先摘再装——

cpp
qApp->removeTranslator(m_translator);
m_translator->load(language_qm);
qApp->installTranslator(m_translator);

——translateLanguage() 里只做重设文本这种幂等操作。别在里面 new 控件、addItem、连信号，否则切一次加一批，切三次下拉框九条。.ui 生成的 retranslateUi() 在这个事件里会自动调用，纯 Designer 界面不用手写重译函数。

日期这类跟语言绑定的设置顺手一起切：

cpp
QLocale::setDefault(language == UI_EN
                    ? QLocale(QLocale::English, QLocale::UnitedStates)
                    : QLocale(QLocale::Chinese, QLocale::China));

QDateEdit、QSpinBox 的格式是构造时定下的，setDefault 之后要重新 setLocale 才生效。

七、中文乱码的三种成因 #

同一行 tr("你好")，Windows + MSVC 下跑得好好的，搬到 Linux + GCC 或者打包发布后成了一堆符号。

链路就三段：源码文件是什么编码 → 编译器按什么编码读它 → 运行时按什么编码解释这些字节。三处任一不匹配，界面就是乱码。

# 环节 它决定什么 典型错法 现象
1 源文件物理编码 磁盘上那几个字节是 UTF-8 还是 GBK 编辑器存成 GBK；UTF-8 带 BOM 传 Linux 编译报换行符不匹配；或编译过但显示乱码
2 编译器对字面量的解释 源字节转成执行字符集字节 MSVC 默认 ANSI 代码页（GBK），GCC 默认 UTF-8 Windows 正常、Linux 乱码，或反之
3 显示端编码 拿到字节后按什么字符集解码 终端 locale 是 C；字体没中文字形；fromLocal8Bit 用错 locale ????、方块、æ¬¢è¿ 
text
"你好" 在编辑器里
  │ ① 存盘：UTF-8 无 BOM → 6 字节 E4 BD A0 E5 A5 BD
  ▼
.cpp 文件字节
  │ ② 编译：MSVC 不加 /utf-8，按 GBK 理解这 6 个字节
  ▼
执行字符集里的字节（已错）
  │ ③ QString 构造：按 UTF-8 解码这串错字节
  ▼
QString 内容（错）→ 绘制（必然乱码）

①对②不对会报错；②对③不对，程序不崩但乱码；三处全对才正常。这就是「同一个乱码看着像同一个问题、修法却完全不同」的原因。

成因一：源文件编码 #

  • Windows 记事本另存为「ANSI」得到的是 GBK。VS Code 打开看着正常，因为它按内容猜编码。
  • Qt Creator / VS Code 默认存 UTF-8 无 BOM。MSVC 不带 /utf-8 就按系统代码页读，把 UTF-8 中文当 GBK，报 C4819，或者更糟——不报错，静默产出乱码字节。
  • 从网页复制粘贴代码，粘进来是 UTF-8；粘进 GBK 文件就混编了。

判定真实编码别猜，看原始字节，前三个字节是 EF BB BF 就带 BOM：

bash
Format-Hex -Path .\main.cpp -Count 8

统一规矩：全仓库 UTF-8 无 BOM，.gitattributes 兜一层 *.cpp text working-tree-encoding=UTF-8。

成因二：编译器的解释 #

这条最隐蔽，代码在编辑器里看着完全正常。

平台 / 编译器 默认源码读取编码 默认执行字符集
Windows / MSVC 系统本地代码页（简体中文即 GBK / GB18030） GBK
Linux / GCC、MinGW UTF-8 UTF-8
macOS / Clang UTF-8 UTF-8

tr("你好") 的字节被读进来，再转成执行字符集写进二进制。MSVC 拿 GBK 读 UTF-8 字节，转完就废了。这时上层 QString 怎么解码都救不回来，数据在编译期已经错。/utf-8 就是告诉 MSVC：源码按 UTF-8 读，执行字符集也输出 UTF-8，一个开关管两头。

成因三：显示端 #

编译没问题、字节也对，最后一步解码错了照样乱码。

cpp
QString s = QString::fromUtf8(byte_array);       // 数据是 GBK，该用 fromLocal8Bit
QString s = QString::fromLocal8Bit(byte_array);  // 数据是 UTF-8，该用 fromUtf8
  • Windows 控制台默认代码页 936。qDebug() << QString("中文") 出乱码，chcp 65001 多半个案能解决。Qt5 的 qDebug 走 toLocal8Bit，Qt6 走 UTF-8。
  • 板子上没有中文字体，字符有编码但画不出来，全是方块。这是字体问题不是编码问题，见第十一章。
  • 串口、网络传中文，两端要约定死。发送方 toUtf8()，接收方就 fromUtf8()。

八、源码编码与编译器选项 #

编辑器侧：Qt Creator 走 工具 → 选项 → 文本编辑器 → 行为 → 文件编码，默认编码设 UTF-8。VS Code 锁死两项，autoGuessEncoding 一定要关——开着它会「智能」地把某些无 BOM 的 UTF-8 猜成 GBK，一打开就乱。

text
"files.encoding": "utf8",
"files.autoGuessEncoding": false

Visual Studio 用 文件 → 高级保存选项 选 UTF-8 带签名，它对无 BOM 的 UTF-8 判断很不积极。

MSVC：/utf-8 #

qmake 工程里只在 MSVC 下传，这个参数同时管源码编码和执行字符集：

bash
msvc {
    QMAKE_CXXFLAGS += /utf-8
}

CMake 工程换成：

bash
if (MSVC)
    add_compile_options(/utf-8)
endif()

命令行等价于 cl /utf-8 /EHsc main.cpp。/utf-8 是 /source-charset:utf-8 /execution-charset:utf-8 的合并写法，只想改一头就分开写。

老编译器的 pragma #

MSVC 2015 之前没有 /utf-8，只能写在每个含中文的 .cpp 顶部：

cpp
#ifdef _MSC_VER
#pragma execution_character_set("utf-8")
#endif

只有 MSVC 认这条 pragma，GCC/Clang 见到会警告 unknown pragma，所以必须包 #ifdef。它还只影响窄字符串字面量的执行字符集，不管源文件读入编码。新工程别用这招，/utf-8 干净。

GCC / MinGW 默认就是 UTF-8 读入、UTF-8 输出，要显式写死也行：g++ -finput-charset=UTF-8 -fexec-charset=UTF-8 main.cpp。-fexec-charset=GBK 别碰，跨平台一搬就废。

代码侧：把编码钉在字面量上 #

写法 语义 何时用
"中文" 普通窄字面量，编码取决于编译器执行字符集 不推荐
u8"中文" 强制 UTF-8 字节（C++20 起是 char8_t） 需要 const char* 时
QStringLiteral("中文") 编译期生成 UTF-16 数据段，运行时零解码 中文常量首选
QString::fromUtf8("中文") 运行时按 UTF-8 解码 来源编码不确定时
tr("中文") 交给翻译系统 禁止

QStringLiteral 在编译期就把 QString 的静态数据（UTF-16 加头部）铺好，运行时只是拿指针，没有 strlen、没有 fromUtf8 转换。

cpp
ui->label->setText(QStringLiteral("中文测试"));   // 好：固定中文走它
ui->title->setText(tr("about"));                  // 好：可翻译的走 tr
ui->label->setText("中文测试");                   // 差：编译器说了算

九、QTextCodec 的历史包袱 #

Qt4 里 QString 内部是 UTF-16，但从窄字符串构造时默认解码方式不是 UTF-8，而是本地编码，Windows 上就是 GBK。所以 Qt4 工程必须在 main 开头把它掰过来。

cpp
#include <QTextCodec>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QTextCodec *codec = QTextCodec::codecForName("System");  // 系统本地编码，Windows 即 GBK
    QTextCodec::setCodecForLocale(codec);      // 文件系统读写
    QTextCodec::setCodecForTr(codec);          // tr() 入参（解决 tr("中文") 乱码的关键）
    QTextCodec::setCodecForCStrings(codec);    // char* / QByteArray 构造 QString

    MainWindow w;
    w.show();
    return app.exec();
}

四行各管一摊。全指向 System，本质是「让我们用 GBK 说话，内部再转 UTF-16」。

这套东西被砍，原因三个：全局状态，改一次影响整个进程，库代码和业务代码抢着设；隐式转换不可控，QString s = "中文"; 走哪个 codec 看不出来；跨平台双重标准，Linux 上 System 是 UTF-8、Windows 上是 GBK。

Qt5 直接删了 setCodecForTr 和 setCodecForCStrings，粘过来报 no member named。setCodecForLocale 保留，因为文件系统和本地化确实要它。Qt6 再退一步，QTextCodec 整个类从 QtCore 挪到 Qt5Compat 模块，用之前先加 QT += core5compat，不加就找不到头文件。

替代品是 QStringConverter 一族：

cpp
#include <QStringConverter>
#include <QStringDecoder>

QStringDecoder decoder(QStringDecoder::System);   // 系统本地编码 → QString
QString text = decoder(gbk_bytes);

if (auto enc = QStringConverter::encodingForName("GBK"); enc.has_value()) {  // 代替 codecForName
    QStringDecoder gbk(*enc);
    QString s = gbk(gbk_bytes);
}

和 QTextCodec 的差别：QStringDecoder 每次使用单独创建，没有全局状态，也就没有「谁后设谁赢」。

需求 Qt4 Qt5 Qt6
全局本地编码 setCodecForLocale setCodecForLocale 不提供，本地编码由系统决定
tr() 入参编码 setCodecForTr 已移除，假定 UTF-8 已移除，假定 UTF-8
char* 转 QString setCodecForCStrings 已移除，默认 fromUtf8 已移除，默认 fromUtf8
按名取编码器 codecForName codecForName QStringConverter::encodingForName
解码一段字节 codec->toUnicode() codec->toUnicode() QStringDecoder
模块 <QTextCodec> <QTextCodec> <QStringConverter> 或 core5compat

存量 Qt4 工程别大改。先做两件不碰业务逻辑的事：搜 setCodecForTr / setCodecForCStrings 注释掉，改用 QStringLiteral 包中文；源码统一 UTF-8 无 BOM，MSVC 加 /utf-8。这两步做完，tr("中文") 这类写法基本也能对。真要一份代码兼容两代，用 #if QT_VERSION < QT_VERSION_CHECK(5, 0, 0) 把四行包起来就行。

十、Qt5 与 Qt6 的编码处理差异 #

维度 Qt5 Qt6
源码字面量假设 需显式保证 UTF-8，MSVC 要 /utf-8 明确按 UTF-8 处理
QString(const char*) 默认 fromUtf8（5.0 起） 默认 fromUtf8，语义不变
QString::fromAscii 已删 无
QTextCodec 在 QtCore，可用 移至 Qt5Compat，要加 core5compat
本地编码 API setCodecForLocale QStringDecoder::System
qDebug() 输出 走 toLocal8Bit，控制台要设代码页 走 UTF-8，控制台乱码基本没有了
QTextStream 设编码 setCodec("UTF-8") setEncoding(QStringConverter::Utf8)
C++ 标准 C++11 起 C++17 起

Qt6 并没有「自动修好乱码」。分三种情况：源码是 UTF-8 且开了 /utf-8，升级无感；源码是 GBK、Qt5 靠本地编码侥幸跑通的，Qt6 下必乱，因为不再给你全局改本地编码的口子；依赖 QTextCodec 的代码，Qt6 下直接编译不过。第 2 类最难，项目里往往没人知道当初存成了 GBK。升级前先全仓库扫一遍非 UTF-8 文件。

fromLocal8Bit 在 Qt6 仍然危险，它到今天还是「按系统本地编码解」：

cpp
QFile f("data.txt");
f.open(QIODevice::ReadOnly);
QString text = QString::fromLocal8Bit(f.readAll());   // 文件是 UTF-8，Windows 上必乱

这段在 Linux 开发机上一直正常，打包到 Windows 就乱。文件、网络、数据库的数据编码是明确的，别拿 fromLocal8Bit 碰运气：

cpp
QString text = QString::fromUtf8(f.readAll());

QTextStream in(&f);
in.setEncoding(QStringConverter::Utf8);   // Qt5 是 in.setCodec("UTF-8")
QString text2 = in.readAll();

setCodec 换 setEncoding 是 Qt5 升 Qt6 的必改点。中文路径炸掉则多半是 locale 问题：QString 存 UTF-16，转成系统调用需要的编码时按本地编码走，Linux 上 locale 是 C 或 POSIX 就失败。板子上先 export LANG=C.UTF-8 再启动程序。

十一、嵌入式下的中文显示 #

板子上中文显示不出来，九成是字体不是编码。字符编码全对，屏幕上照样是方块，因为渲染时找不到能画这个码位的字形。

交叉编译 Qt 要带字体支持：

bash
./configure -fontconfig -qt-freetype -no-opengl \
            -qt-kbd-usb -qt-mouse-tslib

Qt4 的 QWS 下用 QWS_FONT 或启动参数指定；Qt5 / Qt6 换平台插件，字体目录走 QT_QPA_FONTDIR：

bash
export QWS_DISPLAY=LinuxFB:/dev/fb0          # Qt4 QWS
export QWS_KEYBOARD=USB:/dev/event2
./app -qws -font wenquanyi

export QT_QPA_PLATFORM=linuxfb               # Qt5 / Qt6
export QT_QPA_FONTDIR=/usr/share/fonts

最稳的办法是把字体编进资源，随程序走，不依赖板子的字体目录：

cpp
int font_id = QFontDatabase::addApplicationFont(":/fonts/wqy.ttc");
if (font_id >= 0) {
    const QString family = QFontDatabase::applicationFontFamilies(font_id).value(0);
    qApp->setFont(QFont(family, 12));   // 全应用生效
}
现象 原因 处理
中文全是方块 无中文字形 装字体到 /usr/share/fonts，或用 addApplicationFont
中文显示成空 字体有但缺码位 换完整字库（文泉驿、思源黑体）
界面中文正常，文件路径打不开 板子 locale 是 C/POSIX export LANG=C.UTF-8
汉字糊成一团 点阵字体被缩放 用对应字号的点阵，或换矢量字体
程序跑不动 完整字库几 MB 做字体子集，只保留用到的字

别塞完整思源黑体，几十 MB 的字体在 64MB 内存的板子上直接把程序拖死。按界面实际用到的字符做子集，几百 KB 够用。反过来，.qrc 会把字体整个编进 exe 再解压到内存，等于双份占用——字体大时反而适合放文件系统，启动时 addApplicationFont("/usr/share/fonts/wqy.ttc")。

十二、嵌入式键盘输入 #

板子上没有实体键盘，输入从哪来？两条路。

方案 做法 优点 缺点
一 写普通按键驱动，开 Qt 线程读键值，用信号发给目标控件 直观，容易控制 每个界面都要接槽函数，代码散
二 把驱动写成标准键盘驱动，让 QTE 以为在跟标准键盘打交道 上层零改动，keyPressEvent 直接可用 驱动侧复杂，调试在 kernel 里

项目里多数用第一种。要通用性、要让界面代码完全不感知按键来源，选第二种。分两步：先拿真的 USB 键盘验证 QTE 能识别；再写驱动模拟标准键盘输入。

第一步：验证 QTE 认识标准键盘 #

配置 QTE 时加键盘支持参数 ./configure …… -qt-kbd-usb ……。内核要开 USB HID 键盘支持（CONFIG_USB_HID、CONFIG_HID_GENERIC、CONFIG_INPUT_EVDEV）。插上键盘后会出现 event 节点，比如 /dev/event2，然后告诉 QTE 用哪个设备：

bash
export QWS_KEYBOARD=USB:/dev/event2

写个最小程序，只看重写 keyPressEvent 能不能收到键：

cpp
class MyDialog : public QDialog
{
    Q_OBJECT
protected:
    virtual void keyPressEvent(QKeyEvent *k);
};

void MyDialog::keyPressEvent(QKeyEvent *k)
{
    qDebug("in press event %x", k->key());
}

按 F1 到 F11，终端打出：

text
in press event 1000030
in press event 1000031
in press event 1000032
in press event 1000033
in press event 1000034
in press event 1000035
in press event 1000036
in press event 1000037
in press event 1000038
in press event 1000039
in press event 100003a

查 Qt 帮助：Key_F1 = 0x1000030。能收到这串值，说明 QDialog 的 keyPressEvent 拿得到键盘信号，QTE 和 USB 键盘连接正常。这一步别跳过——驱动写完没反应时，你得知道该怀疑驱动还是怀疑 Qt 层。

第二步：写驱动模拟标准键盘 #

参考 /driver/usb/input/usbkbd.c，核心是写一个支持 EV_KEY 的 input 设备驱动。

c
struct input_dev *input_dev;

/* usbkbd.c 的扫描码→键码映射表，256 项，这里列前两行 */
static unsigned char usb_kbd_keycode[256] = {
     0,  0,  0,  0, 30, 48, 46, 32, 18, 33, 34, 35, 23, 36, 37, 38,
    50, 49, 24, 25, 16, 19, 31, 20, 22, 47, 17, 45, 21, 44,  2,  3,
    /* …… 其余 224 项省略 …… */
};

/* 初始化 */
static int button_init(void)
{
    input_dev = input_allocate_device();          /* 分配 input 设备 */
    input_dev->evbit[0] = BIT(EV_KEY) | BIT(EV_LED) | BIT(EV_REP);
    for (i = 0; i < 255; i++) {
        set_bit(usb_kbd_keycode[i], input_dev->keybit);   /* 设置支持的键码 */
    }
    input_register_device(input_dev);             /* 注册 input 设备 */
    return 0;
}

/* 注销 */
static void __exit button_cleanup(void)
{
    input_unregister_device(input_dev);           /* 注销 input 设备 */
}

三个关键点：evbit 里必须有 EV_KEY，这是键盘事件类型；keybit 用 set_bit 逐个登记支持的键码，不登记的键内核不会往上报；input_register_device 之后才会生成 /dev/input/eventN 节点。

中断里取键值、递交事件：

c
static irqreturn_t button_irq(int irq, void *dev_id, struct pt_regs *regs)
{
    /* ……读硬件寄存器，判断哪个键按下…… */
    input_report_key(input_dev, 59, 1);    /* 模拟 F1 按下 */
    input_report_key(input_dev, 59, 0);    /* 模拟 F1 抬起 */
    input_sync(input_dev);                 /* 一次完整事件结束 */
    return IRQ_HANDLED;
}

59 来自内核 include/linux/input.h 的 #define KEY_F1 59。input_report_key(dev, code, value)，value 为 1 按下、0 抬起。按下和抬起必须成对报，只报按下不报抬起，上层会认为键一直按着，keyPressEvent 只触发一次，之后再也收不到。最后 input_sync 把这一批事件提交，少这一句，事件会被缓冲到下一次才生效。

物理按键都会抖，一次按下会在几十毫秒内打出多个边沿。驱动里加软件去抖，或者用定时器延后采样，别把原始电平直接往上报。

上层怎么接 #

驱动搞定后，上层跟接标准键盘一模一样：

cpp
void MyWidget::keyPressEvent(QKeyEvent *event)
{
    switch (event->key()) {
    case Qt::Key_F1: doHelp();    break;
    case Qt::Key_Up: moveUp();    break;
    default: QWidget::keyPressEvent(event);
    }
}

Qt4 的 QWS 靠 QWS_KEYBOARD=USB:/dev/event2 挂设备。Qt5 / Qt6 没有 QWS 了，改走 evdev 插件：

bash
export QT_QPA_PLATFORM=eglfs
export QT_QPA_EVDEV_KEYBOARD_PARAMETERS=/dev/input/event2

另一条路是上 Qt Virtual Keyboard，屏幕点输入。板子带触摸屏、按键又少时比写驱动省事，代价是要编 qtvirtualkeyboard 模块、占内存、界面适配要重做。
