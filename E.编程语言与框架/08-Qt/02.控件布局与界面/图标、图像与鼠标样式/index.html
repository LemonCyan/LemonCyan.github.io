本篇讲 Qt 里「程序里的图」：图标怎么切分与合并、图像怎么变换、鼠标指针怎么换、可执行文件怎么带图标。

讲什么：QIcon 与 QPixmap 的区别、雪碧图的切分与拼装、QImage 的镜像与各类变换、QCursor 的十八种系统样式与自定义光标、Windows 下 .exe 图标的落地步骤、.qrc 资源文件的写法。

不讲什么：Qt Quick 的 Image / IconImage、SVG 渲染细节、第三方图标库选型、样式表里 image: 的完整语法。

跨篇指路：窗口外观（无边框、圆角、阴影）看同目录的窗口样式篇；控件排布看布局管理篇；绘制事件与 QPainter 的坐标体系看绘图篇。本篇只在拼图时用到 QPainter，不展开。

一、Qt 的图标体系 #

先说结论：QIcon 不是「一张图」，它是一组图的集合。同一个 QIcon 里可以塞进 16×16、32×32、64×64 的同一枚图标，也可以塞进「正常」「禁用」「选中」三种状态的版本。绘制时 Qt 按控件要求的尺寸和当前状态，挑一张最接近的出来用。

QPixmap 就是一张位图。多大就是多大，不会替你缩放，也没有状态的概念。

混用是新手最容易踩的坑。QPushButton::setIcon() 收的是 QIcon，你塞一个 QPixmap 进去，编译器会走 QIcon(const QPixmap&) 这个隐式构造，看着编译通过了，实际上你只给了它一个尺寸、一个状态。换个高 DPI 屏幕就糊。

对比项 QIcon QPixmap
本质 多尺寸、多状态图标的集合 一张位图
尺寸 内部存多份，绘制时按需挑 固定，改尺寸要新建
状态 有 Normal / Disabled / Active / Selected 与 On / Off 无
缩放 自动选最接近的尺寸 必须显式 scaled()
线程 绘制依赖 GUI 线程 只能在 GUI 线程用
典型来源 .qrc、主题图标、QPixmap / QImage 文件、grab()、QImage 转换
主要消费方 setIcon()、QAction、窗口图标 setPixmap()、drawPixmap()、光标

再往下还有一层分工：QImage 与 QPixmap。第五章单独讲，先给表。

对比项 QImage QPixmap
面向 像素操作 屏幕显示
存储位置 内存，CPU 可直读 依赖显示设备，落在显存或窗口系统服务端
跨线程 可以，值类型、可重入 不行，只能 GUI 线程
逐像素读写 setPixel / pixel / scanLine / bits() 不提供，要读写先转 QImage
格式 QImage::Format_ARGB32 等明确枚举 平台相关，不保证能读回
转换成本 — QPixmap::fromImage() / toImage() 有拷贝
用在哪 图像处理、算法、保存、上传 贴到控件、drawPixmap、QCursor

记一句：算图用 QImage，显示用 QPixmap。

二、QIcon 的多状态与多尺寸 #

QIcon 的组织维度有三个：尺寸、模式（Mode）、状态（State）。三个维度任意组合成一个槽位，一个 QIcon 可以有很多槽位。

Mode 是交互状态：

枚举 含义 谁触发
QIcon::Normal 正常 默认状态
QIcon::Disabled 禁用 控件 setEnabled(false)
QIcon::Active 激活 鼠标悬停
QIcon::Selected 选中 item view 里被选中

State 是开关状态，只有两档：QIcon::Off（关）和 QIcon::On（开）。给可勾选按钮（setCheckable(true)）用，checked 时 Qt 取 On 那一份。

往 QIcon 里塞图有两个入口。

cpp
QIcon icon;

// addFile：声明「这张文件代表哪个尺寸」，不是「缩放到这个尺寸」
icon.addFile(":/icons/save_16.png", QSize(16, 16), QIcon::Normal, QIcon::Off);
icon.addFile(":/icons/save_32.png", QSize(32, 32), QIcon::Normal, QIcon::Off);
icon.addFile(":/icons/save_32_disabled.png", QSize(32, 32), QIcon::Disabled, QIcon::Off);

// addPixmap：直接用内存里已有的图
QPixmap pm(64, 64);
pm.fill(Qt::transparent);
icon.addPixmap(pm, QIcon::Normal, QIcon::On);

addFile 的第二个参数只是索引标签。文件本身多大就多大，改标签不会缩放文件。你标 32×32 实际给了张 128×128 的图，Qt 会按 128×128 存着，取 32 的时候还得缩一次。

想看 QIcon 里到底有哪些尺寸：

cpp
const QList<QSize> sizes = icon.availableSizes(QIcon::Normal, QIcon::Off);
for (const QSize &s : sizes)
    qDebug() << s;

取图用 pixmap()，它会挑：

cpp
QPixmap p = icon.pixmap(QSize(24, 24), QIcon::Normal, QIcon::Off);

挑选顺序是：完全匹配的尺寸 → 比要求大的里面最小的 → 最大的那个缩下来。最后一步是硬缩放，有损。所以高 DPI 场景要给 2x 资源，或者用带 devicePixelRatio 的重载：

cpp
// 第四个参数是 devicePixelRatio，2.0 表示要 2 倍图
QPixmap p2 = icon.pixmap(QSize(24, 24), QIcon::Normal, QIcon::Off, 2.0);

QIcon 自己没有 setIconSize。图标显示多大归控件管：

cpp
button->setIcon(icon);
button->setIconSize(QSize(24, 24));   // 控件负责显示尺寸
toolBar->setIconSize(QSize(20, 20));
listWidget->setIconSize(QSize(32, 32));

这两行别写反逻辑：setIconSize 是向 QIcon 要一张 24×24，不是把某个固定图压成 24×24。

Linux 桌面用主题图标：

cpp
QIcon folder = QIcon::fromTheme("folder-open");
if (folder.isNull())
    folder = QIcon(":/icons/folder.png");   // 主题里没有就回退资源

QIcon::setThemeName("hicolor") 指定主题，QIcon::setFallbackThemeName() 指定兜底主题。Windows 上没有图标主题，fromTheme 会返回空，回退分支必须有。

别在绘制路径里现造QIcon。构造它要读文件、解码、转格式，塞进 paintEvent 或 data() 里逐行调用会直接卡住滚动。

三、图标切分：从雪碧图取出单图 #

雪碧图（sprite sheet）就是「多张有相同功能的小图拼成一张大图」。美工出一张，开发者按需切。好处很实在：文件少、IO 少、解码少、换肤时整体替换一张就行。

QQ 的等级图标是经典例子。0 到 9 十个数字图标排成一行，要显示「LV888」就取三张「8」再拼起来。要是每个等级、每种位数都单独画一张，数量会失控。

前提两条：美工给的图必须小图等宽等高、横向或纵向紧密排列；开发者得知道每张小图的序号。

核心 API 是 QPixmap::copy(const QRect&)，返回原图的一块副本，原图不动。

cpp
// 从宽度为 count 倍小图宽的大图里，取第 index 张小图
QPixmap getPixmap(const QString &name, int count, int index)
{
    if (name.isEmpty() || count <= 0 || index < 0 || index >= count)
        return QPixmap();

    QPixmap sheet(name);
    if (sheet.isNull())
        return QPixmap();

    const int w = sheet.width() / count;
    const int h = sheet.height();
    if (w <= 0)
        return QPixmap();

    return sheet.copy(w * index, 0, w, h);
}

三个容易漏的检查：

  1. count <= 0 会除零崩掉。
  2. sheet.width() % count != 0 时最后一张被截窄，后面全部错位。
  3. 越界的 index 拿到空图，界面上一片白，不报错也不崩，最难查。

纵向排列把 copy(w * index, 0, ...) 换成 copy(0, h * index, ...)。二维网格用列数换算：

cpp
const int cols = 4;
QRect cell((index % cols) * w, (index / cols) * h, w, h);
QPixmap one = sheet.copy(cell);

原来那种写十遍赋值的写法收进容器：

cpp
QVector<QPixmap> digits;
digits.reserve(10);
for (int i = 0; i < 10; ++i)
    digits.append(getPixmap(":/level/level_value", 10, i));

取用时 digits[n]。要拼「888」，按位取值再合并，就是下一章的事。

切分想省内存，可以把 QPixmap 换成 QImage。QImage::copy() 语义一样，而且它能在工作线程里跑——QPixmap 不行。

四、图标合并：拼装与叠加 #

「合并」有两种，别搞混：

方式 做什么 典型用途
横向 / 纵向拼装 把小图按坐标摆进大图的互不重叠区域 做雪碧图、拼等级数字、拼多个徽章
叠加绘制 多张图压在同一块区域，靠 alpha 合成 给图标加角标、加边框、加半透明遮罩

拼装的骨架：先算目标尺寸，建透明底画布，用 QPainter 逐张 drawPixmap。

cpp
QPixmap assemble(const QVector<QPixmap> &parts, int gap)
{
    if (parts.isEmpty())
        return QPixmap();

    int w = 0, h = 0;
    for (const QPixmap &p : parts) {
        w += p.width() + gap;
        h = qMax(h, p.height());
    }
    w -= gap;

    QPixmap canvas(w, h);
    canvas.fill(Qt::transparent);          // 关键：先铺透明

    QPainter painter(&canvas);
    int x = 0;
    for (const QPixmap &p : parts) {
        painter.drawPixmap(x, h - p.height(), p);   // 底对齐
        x += p.width() + gap;
    }
    painter.end();
    return canvas;
}

QPixmap 构造出来的像素内容是未初始化的，不 fill(Qt::transparent) 就会带随机垃圾。这是拼接出现「背景变色」的第一大原因。

第二大原因是合成模式。默认 CompositionMode_SourceOver，画到透明底上没问题；但如果画布先铺了不透明色，或者往同一块反复绘制，就得显式清一次源：

cpp
QImage canvas(QSize(pageWidth * pageCount, pageHeight),
              QImage::Format_ARGB32_Premultiplied);
canvas.fill(Qt::transparent);

QPainter painter(&canvas);
painter.setRenderHint(QPainter::Antialiasing, true);

// 先整体清成透明，再切回正常叠加
painter.setCompositionMode(QPainter::CompositionMode_Source);
painter.fillRect(canvas.rect(), Qt::transparent);
painter.setCompositionMode(QPainter::CompositionMode_SourceOver);

for (int i = 0; i < pageCount; ++i) {
    painter.drawImage(QRect(pageWidth * i, 0, pageWidth, pageHeight),
                      QImage(QString(":/newFeature_%1").arg(i)));
}
painter.end();

totalLabel->resize(canvas.size());
totalLabel->setPixmap(QPixmap::fromImage(canvas));

Format_ARGB32_Premultiplied 是画布首选格式：alpha 预乘，SourceOver 合成最快，边缘不会发黑。

用 QImage 当画布还有个好处：可以在工作线程拼完，回 GUI 线程 QPixmap::fromImage() 一次性转过去。

叠加就是同一区域画多次，后画的压前面的：

cpp
QPixmap base  = icon.pixmap(64, 64);
QPixmap badge(":/icons/badge_new.png");

QPixmap out(base.size());
out.fill(Qt::transparent);
{
    QPainter p(&out);
    p.setRenderHint(QPainter::SmoothPixmapTransform, true);
    p.drawPixmap(0, 0, base);
    p.drawPixmap(base.width() - badge.width(), 0, badge);   // 右上角
}
button->setIcon(QIcon(out));

高分屏要单独处理。合并前把每张图按 devicePixelRatio 放大，画布同比例放大，最后给画布设回 dpr，否则在 150% 缩放的屏幕上拼出来的图会糊。

cpp
const qreal dpr = QGuiApplication::primaryScreen()->devicePixelRatio();
QPixmap scaled = part.scaled(part.size() * dpr,
                             Qt::KeepAspectRatio,
                             Qt::SmoothTransformation);
scaled.setDevicePixelRatio(dpr);

拼好的图如果要给 setIcon()，记得包回 QIcon——setIconSize() 配合 QIcon 才能让控件按需挑图，直接塞 QPixmap 就丢了多尺寸的能力。

五、QImage 与 QPixmap 的差别 #

这两个类不是同一层级的东西，别当成「一个叫 A、一个叫 B」。

QImage 是纯 CPU 侧的像素缓冲。它自己持有数据，Format_ARGB32 就是 4 字节一个像素，Format_RGB888 就是 3 字节。你能拿到 bits()、scanLine()、scanLine(0)，能逐像素改，能丢进线程池跑。除了字体渲染需要 QGuiApplication 存在，它不碰窗口系统。

QPixmap 是显示侧的对象。数据放哪由平台决定：X11 下是 XRender 的 pixmap，Windows 下是 DIB，macOS 下是 CGImage。所以 Qt 文档明说 QPixmap 只能在 GUI 线程用。

按任务选：

你要做的事 用哪个 理由
读改某个像素的颜色 QImage QPixmap 没有 pixel() 接口
灰度化、二值化、卷积 QImage 要逐像素或 scanLine
在工作线程处理图片 QImage QPixmap 只能 GUI 线程
存成 PNG / JPG QImage save() 作用在实际像素上
贴到 QLabel QPixmap setPixmap() 只收它
paintEvent 里画图 QPixmap drawPixmap 走设备，快
做鼠标光标 QPixmap QCursor 构造要它
交给控件当图标 QIcon 需要状态与尺寸

转换就两个方向：

cpp
QImage img = pixmap.toImage();          // 拷贝，大图慎用
QPixmap pm = QPixmap::fromImage(img);   // 拷贝，必须在 GUI 线程

fromImage 第二个参数是 Qt::ImageConversionFlags，默认 Qt::AutoColor，会顺手做一次格式适配。默认参数就够，别乱动。

两条容易忽略的规矩：

第一条，在 GUI 线程外构造 QPixmap，Qt5 会打警告 QPixmap: It is not safe to use pixmaps outside the GUI thread，某些平台直接崩。Qt6 的检查还在。

第二条，QPixmap 不保证能读回原始像素。某些平台上 QPixmap 是 24 位存储，透明信息在合成时就丢了。你从 QPixmap 转回 QImage 去读 alpha，拿到的全是 255。做图像处理的正确姿势是 QImage 进、QImage 出，只在最后一步转 QPixmap 交给界面。

QPixmap 家族里还有个 QBitmap，1 位深度的单色图，用来做遮罩。现在用得少了，setMask() 之外基本见不到。

六、图像变换：镜像、旋转与缩放 #

镜像 #

QImage 给了个直白的方法：

cpp
QImage QImage::mirrored(bool horizontal = false, bool vertical = true) const;

默认值是 (false, true)，意味着 img.mirrored() 得到的是上下颠倒的图。第一次用容易踩这一脚。

四个组合：

horizontal vertical 效果 场景
false false 与原图一致 占位、接口统一
true false 左右翻转 对称按钮背景、角色朝左 / 朝右切换
false true 上下翻转（默认） 倒影、折射、反射
true true 双向翻转，等价绕中心转 180° 要转 180° 又不想重采样

mirrored() 不改原对象，返回新副本。用返回值，别指望 img 自己变了。

cpp
QImage original(":/Images/logo");
QImage flipped = original.mirrored(true, false);   // 左右翻转
label->setPixmap(QPixmap::fromImage(flipped));

QPixmap::mirrored() 在 Qt5 有（5.15 起标记废弃），Qt6 删掉了。统一走 QImage：

cpp
QPixmap src(":/Images/logo.png");
QPixmap out = QPixmap::fromImage(src.toImage().mirrored(true, false));

不想来回转，就用 QPainter 的变换矩阵直接画，省一次拷贝。

旋转 #

QImage::transformed(const QTransform&, Qt::TransformationMode) 是通用入口。90° 的整数倍用 QTransform::rotate，走快速路径，不重采样：

cpp
QImage out = src.transformed(QTransform().rotate(90), Qt::FastTransformation);

transformed() 返回的图会自动扩到能容下旋转后的内容，长宽互换。这一点在布局里算尺寸时要记住，别拿原图的 size() 去摆。

QImage::rotated(qreal) 是糖，内部就是 transformed。90 的整数倍结果精确，非整数倍带插值，边缘会软。

镜像也能用矩阵表达，一次搞定翻转叠加旋转：

cpp
QTransform t;
t.translate(src.width(), 0);
t.scale(-1, 1);                 // 水平镜像
QImage flipped = src.transformed(t);

缩放 #

scaled() 有两个正交的决策：尺寸策略、插值模式。

尺寸策略：

枚举 行为
Qt::IgnoreAspectRatio 拉成给定尺寸，不管比例，会变形
Qt::KeepAspectRatio 保比例，缩到能放进目标框
Qt::KeepAspectRatioByExpanding 保比例，缩到能盖满目标框，多出来的裁掉

插值模式：

枚举 质量 速度 用在哪
Qt::FastTransformation 最近邻，有锯齿 快 缩小到一半以下、临时预览
Qt::SmoothTransformation 双线性 + 预缩放 慢 最终显示、放大 
cpp
QPixmap thumb = src.scaled(128, 128,
                           Qt::KeepAspectRatio,
                           Qt::SmoothTransformation);

放大必须用 SmoothTransformation，最近邻放大出来全是马赛克块。缩小到很小（比如 1000px 缩到 32px）时，SmoothTransformation 内部会先做一次双线性预缩再采样，效果比 FastTransformation 好一截，代价是慢。列表里几百个缩略图，可以先用 FastTransformation 缩到目标尺寸的 4 倍，再 SmoothTransformation 缩到目标，质量和耗时的折中。

scaledToWidth(w, mode) / scaledToHeight(h, mode) 是糖，内部固定 KeepAspectRatio。

QTransform 的 translate / scale / rotate 是累积左乘的，先写先生效。想绕中心转，先把原点挪到中心：

cpp
QTransform t;
t.translate(w / 2.0, h / 2.0);
t.rotate(angle);
t.translate(-w / 2.0, -h / 2.0);
QImage rotated = src.transformed(t, Qt::SmoothTransformation);

绕中心转会让外接矩形变大，边角出现透明区。想保持原尺寸，就按 qSqrt(w*w + h*h) 建画布再居中裁，或者用 QPainter::setClipRect() 裁。

七、图像格式与保存 #

QImage::Format 是个很长的枚举，日常就这几个：

格式 每像素 用途
Format_ARGB32 4 字节，非预乘 通用，逐像素处理时最直观
Format_ARGB32_Premultiplied 4 字节，预乘 alpha 绘制画布、合成首选
Format_RGB32 4 字节，alpha 固定 255 不要透明的场景
Format_RGB888 3 字节 与外部库、硬件对接，省内存
Format_Grayscale8 1 字节 灰度图、掩膜
Format_Indexed8 1 字节 + 调色板 GIF、老式图标

预乘和非预乘的区别：预乘把 RGB 提前乘了 alpha。合成时少一次乘法，边缘不发黑；代价是你直接读某个像素的 RGB，拿到的不是原色，而是乘过的值。做取色、算平均色这类逐像素算法，用非预乘的 Format_ARGB32 更省心。

判断透明通道和格式，就是 img.hasAlphaChannel() 和 img.format() != QImage::Format_ARGB32 两个判断，不匹配就 convertToFormat() 转一次。

保存：

cpp
QImage img(":/Images/shot.png");

bool ok = img.save("D:/out/shot.png");                  // 按后缀猜格式
ok = img.save("D:/out/shot.jpg", "JPG", 92);            // 显式格式 + 质量
ok = img.save("D:/out/shot.png", "PNG", 9);             // PNG 的「质量」是压缩级别 0-9

质量参数的语义随格式变。JPEG 是 0-100 的有损质量，PNG 是 0-9 的压缩级别（9 最小最慢）。把 92 传给 PNG 不会报错，会被夹到范围里，含义完全不同。

后缀和显式格式冲突时显式格式赢。save("a.png", "JPG") 写出来的是 JPEG 数据，但文件名叫 .png，读取方会懵。

QImageWriter::supportedImageFormats() 和 QImageReader::supportedImageFormats() 返回当前构建实际支持的格式列表。插件缺失时这两个列表会比你预期的短，部署时 imageformats 目录别漏拷，这是「开发机能存 PNG、现场机器存不了」的根源。

要错误原因就得换 QImageWriter，save() 只返回 false：

cpp
QImageWriter writer("D:/out/shot.jpg", "JPG");
writer.setQuality(90);
writer.setOptimizedWrite(true);
writer.setProgressiveScanWrite(true);
if (!writer.write(img))
    qWarning() << writer.errorString();

路径没权限、目录不存在、格式插件缺失，三种错误都只返回 false，靠 errorString() 才分得清。

八、鼠标指针样式 #

QCursor 管光标。设置分两层：控件级、应用级。

控件级最常用：

cpp
this->setCursor(Qt::PointingHandCursor);          // 整个窗口
ui->pushButton->setCursor(Qt::ForbiddenCursor);   // 单个按钮
ui->lineEdit->setCursor(Qt::IBeamCursor);         // 输入框

unsetCursor() 撤销，回到继承父控件的状态。子控件没设过，就跟着父控件走。

Qt::CursorShape 的内置取值：

常量 形态 用在哪
Qt::ArrowCursor 默认箭头 默认状态
Qt::UpArrowCursor 向上箭头 表头、列排序提示
Qt::CrossCursor 十字线 画图、测距、精确取点
Qt::WaitCursor 沙漏 / 转圈 阻塞等待
Qt::BusyCursor 箭头 + 转圈 后台忙但仍可交互
Qt::IBeamCursor 工字形 文本录入
Qt::SizeVerCursor 上下箭头 垂直拉伸
Qt::SizeHorCursor 左右箭头 水平拉伸
Qt::SizeBDiagCursor 左下到右上对角 对角线拉伸
Qt::SizeFDiagCursor 左上到右下对角 对角线拉伸
Qt::SizeAllCursor 四向箭头 画布拖动、移动元素
Qt::SplitVCursor 上下双线带箭头 垂直分割线调节
Qt::SplitHCursor 左右双线带箭头 水平分割线调节
Qt::PointingHandCursor 手型 按钮、超链接
Qt::ForbiddenCursor 红色禁止圈 不可放置、不可用
Qt::OpenHandCursor 张开的手 可以拖
Qt::ClosedHandCursor 握住的手 正在拖
Qt::WhatsThisCursor 问号箭头 「这是什么」帮助模式

十八个之外还有个 Qt::BlankCursor，把光标藏起来。全屏播放、游戏、自己用 QPainter 画光标时会用到。

应用级用静态方法，内部是一个栈：

cpp
QApplication::setOverrideCursor(Qt::WaitCursor);

// 耗时业务逻辑...

QApplication::restoreOverrideCursor();

必须成对。setOverrideCursor 压栈，restoreOverrideCursor 弹栈。嵌套三次就要 restore 三次。中途 return 或异常漏了 restore，光标会一直卡在等待态，只能重启程序。

用 RAII 包一层，防漏：

cpp
class WaitCursorGuard
{
public:
    WaitCursorGuard()  { QApplication::setOverrideCursor(Qt::WaitCursor); }
    ~WaitCursorGuard() { QApplication::restoreOverrideCursor(); }
};

{
    WaitCursorGuard guard;
    doHeavyWork();      // 中途 return 也会被析构复原
}

changeOverrideCursor(Qt::CursorShape) 改栈顶那一层，不压新的。适合「等待 → 禁止」这种同层切换，不用配一次 restore。

QApplication::overrideCursor() 查栈顶，返回 QCursor*，栈空时给 nullptr。

优先级：override 光标压过控件自己的 setCursor()。这就是它「强制」的来源，也是调试时「我明明设了手型却不生效」的头号原因——某处漏了 restore。查的时候先看 overrideCursor() 是不是非空。

九、自定义光标 #

系统给的十八个不够用时，用图片画一个。

cpp
void useCustomCursor()
{
    QPixmap pixmap(":/Images/custom_cursor.png");
    if (pixmap.isNull())
        return;

    // 尺寸先归一到 32x32
    const QSize target(32, 32);
    if (pixmap.size() != target)
        pixmap = pixmap.scaled(target, Qt::KeepAspectRatio, Qt::SmoothTransformation);

    // 热点：箭头类点左上角，十字类点中心
    const int hotX = pixmap.width() / 2;
    const int hotY = pixmap.height() / 2;

    QCursor cursor(pixmap, hotX, hotY);
    this->setCursor(cursor);
}

构造签名：

cpp
QCursor(const QPixmap &pixmap, int hotX = -1, int hotY = -1);

热点（hotspot）是「光标坐标」的锚点：鼠标位置落在图上哪个像素。传 (-1, -1) 让 Qt 自己按中心算。箭头形状的光标热点在左上角 (0, 0)，十字和圆环在中心。热点越界时 Qt 会夹到图内，不崩，但定位会偏。

尺寸是硬约束。Windows 的自定义光标走 CreateIconIndirect，位图规格受限，32×32 稳妥。把 128×128 的图直接塞进去，会出现锯齿、残缺，甚至设置失败。X11 那边限制在 64×64 附近，并且要求热点合法。所以先 scaled 到 32×32 再构造，比出了问题再回头查省事。

scaled 出来的图 dpr 还是 1。要适配高分屏，得按 devicePixelRatio 缩放并 setDevicePixelRatio()，然后验证目标平台吃不吃这个尺寸——自定义光标在高分屏上显小是长期存在的问题，各平台接口不统一。

自绘圆圈光标画不全 #

用 QPainter 在内存里画个透明圆当橡皮擦光标，边缘总缺一块。

原因：画笔有粗细。pen.setWidth(2) 时，drawEllipse(0, 0, 32, 32) 的实际绘制边界是 34×34，超出 QPixmap 的 32×32 物理包络，超出的部分被裁掉。

cpp
QPixmap makeCircleCursor(int d, int penWidth, const QColor &color)
{
    QPixmap pm(d, d);
    pm.fill(Qt::transparent);

    QPainter p(&pm);
    p.setRenderHint(QPainter::Antialiasing, true);

    QPen pen(color, penWidth);
    p.setPen(pen);
    p.setBrush(Qt::NoBrush);

    const int inset = penWidth / 2 + 1;
    p.drawEllipse(inset, inset, d - inset * 2, d - inset * 2);
    p.end();

    return pm;
}

给笔宽留出内缩，圆才闭合。同一个道理适用于所有自绘图形：矩形、圆角框、边框线，画之前先把边界扣掉半个笔宽。

平台差异 #

平台 自定义光标支持 尺寸 备注
Windows 完整 32×32 稳妥 走 CreateIconIndirect
X11 完整 64×64 附近 要有活动窗口
Wayland 部分 依合成器 光标按协议由客户端提供，行为有差异
macOS 完整 按点数算 Retina 下自动适配

平台分支用宏：

cpp
#ifdef Q_OS_WIN
    // Windows 专属处理
#elif defined(Q_OS_MACOS)
    // macOS 专属处理
#else
    // X11 / Wayland
#endif

恢复系统光标用 unsetCursor()，回到继承状态。如果之前用 QApplication::setOverrideCursor() 覆盖过，记得 restore，否则自定义光标撤不掉。

别在 mouseMoveEvent 里每次 new 一个 QCursor。构造它要分配平台资源，鼠标移动事件一秒几十上百次，资源会漏。做成成员或静态缓存，事件里只切换引用：

cpp
// 构造一次，存成成员
Canvas::Canvas() : m_eraseCursor(makeCircleCursor(32, 2, Qt::red), 16, 16) {}

// 事件里只切换引用，不重新构造
void Canvas::mouseMoveEvent(QMouseEvent *e)
{
    setCursor(m_eraseCursor);
    QWidget::mouseMoveEvent(e);
}

十、可执行程序图标 #

先说清边界：这件事 Qt 不管。setWindowIcon() 只管任务栏和标题栏那个小图标；.exe 文件在资源管理器里显示什么，由操作系统读可执行文件的资源段决定。Qt Assistant 里搜「Setting the Application Icon」，官方给的是按平台分开的做法。

Windows：三步 #

第一步，准备 .ico。必须是 .ico，PNG 不行。.ico 是容器格式，里面装 16 / 32 / 48 / 256 多个尺寸，资源管理器按当前视图大小自己挑一张。只装一张 256×256，小图标视图下会被缩得发糊。

第二步，写 .rc 文件。项目根目录建 logo.rc（文件名随意，后缀必须是 .rc），写一行：

text
IDI_ICON1               ICON                    "images\\player.ico"

路径相对 .rc 文件所在目录。Windows 资源脚本语法里用双反斜杠；单反斜杠多数情况能过，撞上转义字符就出事。

第三步，.pro 里挂上：

text
RC_FILE = logo.rc

挂好之后跑一遍构建，生成的 .exe 就带图标了：

bash
qmake MyApp.pro
make -j8              # Windows 下换成 nmake 或 jom

改完 .rc 一定要 Rebuild。只 Build 不会重新编译资源脚本，.exe 上还是旧图标，很容易误判成「做法错了」。

Visual Studio 环境可以不写 RC_FILE：把 .rc 当现有文件拖进解决方案管理器，或者在项目属性的资源编译器选项里关联。

CMake 项目：

text
if(WIN32)
    target_sources(MyApp PRIVATE "${CMAKE_CURRENT_SOURCE_DIR}/logo.rc")
endif()

CMake 认 .rc 后缀，会交给 RC 编译器处理。

平台差异 #

平台 做法 关键文件 谁负责
Windows 资源脚本把 .ico 编进 PE 资源段 .ico + .rc + RC_FILE 编译器 / 链接器
Linux .desktop 文件里的 Icon= 指向图标 myapp.desktop + PNG/SVG 桌面环境
macOS .app bundle 内 plist 的 CFBundleIconFile .icns + Info.plist bundle 打包

Linux 的 .desktop：

text
[Desktop Entry]
Type=Application
Name=MyApp
Exec=/opt/myapp/myapp
Icon=/opt/myapp/icons/myapp.png
Categories=Utility;
Terminal=false

Icon= 也可以只写名字（如 myapp），让桌面环境去 /usr/share/icons/hicolor/<尺寸>/apps/ 下按名搜。写绝对路径更省事，但要保证安装脚本把它拷到位。

macOS 用 qmake 时，.pro 里加一行 ICON = myapp.icns 就够。.icns 里同样装多个尺寸，iconutil 能把一组 PNG 打成 .icns。

别和 setWindowIcon 混了 #

运行时的窗口图标是另一回事：QApplication::setWindowIcon(QIcon(":/icons/app.png"))。它影响任务栏、Alt+Tab、部分窗口管理器的标题栏，不改文件外观。两处都配好，用户才会觉得这是一个完整的程序。

十一、资源文件 .qrc 的用法 #

前面代码里 ":/Images/logo" 这种冒号路径，都来自 .qrc。资源文件把图片、图标、翻译、QSS 编进二进制，运行时从内存读，不依赖外部文件，也就没有「用户删了图片，界面变白板」的问题。

最小的 .qrc：

text
<RCC>
    <qresource prefix="/">
        <file>images/logo.png</file>
        <file>images/shot.jpg</file>
    </qresource>
</RCC>

<file> 里是相对 .qrc 所在目录的路径。前缀 / 加文件名，访问路径就是 :/images/logo.png。

前缀分组 + 别名：

text
<RCC>
    <qresource prefix="/icons">
        <file>icons/save.png</file>
        <file>icons/open.png</file>
    </qresource>
    <qresource prefix="/translations">
        <file alias="zh_CN.qm">build/app_zh_CN.qm</file>
    </qresource>
</RCC>

alias 只改访问名，不动原文件。上面那条的访问路径是 :/translations/zh_CN.qm。

qmake 挂载：

text
RESOURCES += app.qrc

CMake 两种写法：

text
set(CMAKE_AUTORCC ON)                          # 方式一：列 .qrc，靠 AUTORCC
qt_add_executable(MyApp main.cpp app.qrc)

qt_add_resources(MyApp "app"                   # 方式二：显式声明
    PREFIX "/"
    FILES images/logo.png images/shot.jpg
)

方式二不写 .qrc，路径由 PREFIX 加文件名推出，省一个文件。文件多了还是 .qrc 好管。

几条实战规矩：

改完 .qrc 必须重新构建。资源编进了二进制，增量构建有时不重新跑 rcc，界面上还是旧图。排查第一招就是 Rebuild。

路径大小写敏感。Windows 文件系统不敏感，但 rcc 生成的资源表按字面存键，":/Images/Logo.png" 和 ":/images/logo.png" 是两个不同的键。换到 Linux 构建就原形毕露。

别把大文件塞 .qrc。资源在启动时解码，几十兆的图会让 main() 之前就卡住，内存一直占着。视频、大背景图放外部，用相对路径或 QStandardPaths 找。

资源路径不能用 ../ 跳出 .qrc 所在目录，<file>../shared/logo.png</file> 会被 rcc 拒绝。

资源是只读的。QFile 以 WriteOnly 打开 :/... 会失败，要写先拷到 QStandardPaths::writableLocation(QStandardPaths::AppDataLocation) 再改。想知道资源里都有什么，用 QDirIterator it(":/", QDirIterator::Subdirectories) 顺着 hasNext() 走一遍就能打出来。

十二、易错点速查 #

现象 原因 改法
图标在高 DPI 屏上发糊 只塞一张小图，QIcon 硬放大 addFile 塞多尺寸，或给 2x 资源
setIconSize 设了没效果 传进去的是 QPixmap 隐式转的 QIcon 显式构造 QIcon，尺寸交给控件
拼出来的图背景发灰、有色块 画布没 fill(Qt::transparent) 先铺透明，再 SourceOver 绘制
拼接后边缘一圈黑边 用非预乘格式做合成 画布改 Format_ARGB32_Premultiplied
切图错位，后面全歪 sheet.width() % count != 0 校验整除，或改用二维网格坐标
切出来一片空白 index 越界，copy 返回空图 加范围检查，空图给占位图
工作线程里崩 非 GUI 线程用了 QPixmap 线程里用 QImage，回 GUI 线程转
转回 QImage 后 alpha 全 255 平台 QPixmap 不存透明信息 全流程走 QImage，最后一步再转
mirrored() 结果上下颠倒 默认 vertical = true 要左右翻转写 mirrored(true, false)
旋转后布局错位 transformed 返回的图长宽互换 用返回图的 size() 算布局
放大后满是马赛克 用了 FastTransformation 放大走 SmoothTransformation
光标一直卡在等待态 setOverrideCursor 漏了 restore RAII 包一层，或查 overrideCursor()
自定义光标锯齿、残缺 图太大或热点越界 先 scaled 到 32×32，热点落在图内
自绘圆环光标缺一块 画笔宽度撑出画布边界 内缩半个笔宽再 drawEllipse
.exe 图标没变 只 Build 没 Rebuild 重新构建，确认 .pro 有 RC_FILE
图标改完还是旧的 改了 .qrc 没重新跑 rcc Rebuild，别信增量构建
Linux 上资源加载失败 资源键大小写敏感 路径与 <file> 大小写完全一致
存 PNG 体积巨大 把 JPEG 的质量 92 传给了 PNG PNG 用 0-9 压缩级别

这些坑一半是「格式与线程选错」，一半是「差一次 Rebuild」。先把这两类排掉，剩下的才是真 bug。图标那点事说到底就三句话：QIcon 管集合，QPixmap 管显示，QImage 管像素。分清了，切图、拼图、变换、光标、程序图标全是一路顺下来的。
