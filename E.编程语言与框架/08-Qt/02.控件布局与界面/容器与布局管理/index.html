这一篇只干一件事：把控件摆进窗口，并让它们在窗口缩放时不变形。

讲什么：布局管理器的接管机制、四种基础布局、布局项的所有权、嵌套与尺寸传递、sizePolicy 与 stretch、间距与边距、QTabWidget 与 QStackedWidget 的分工、QSplitter、QDockWidget、子部件遍历、无边框窗口与样式表。

不讲什么：单个控件的行为参数（QLineEdit 的校验、QComboBox 的代理模型）在同目录的控件基础篇；ui 文件的加载与信号槽绑定在《Qt_界面与逻辑分离》和《QUiLoader加载ui文件》；窗口阴影、半透明、出现动画这类纯视觉手法在 03-自定义窗口与样式。

一、Qt 的布局体系 #

先记住一句话：布局管理器接管了子控件的几何尺寸。

这句话解释新手最常撞的那堵墙。写 setLayout 之前，resize() 和 move() 是你说的话；挂上布局之后，布局在每次父控件尺寸变化时重算全部子项，亲手调 setGeometry() 把每个控件摆到位。你之前那两个调用不会报错，只是被下一轮分配覆盖。

cpp
// 手动摆位：resize / move 说了算
QWidget *a = new QWidget;
QPushButton *b1 = new QPushButton("手摆", a);
b1->move(20, 20);
b1->resize(120, 40);   // 生效

// 加了布局：resize / move 立刻失效
QWidget *c = new QWidget;
QVBoxLayout *v = new QVBoxLayout(c);
QPushButton *b2 = new QPushButton("布局");
v->addWidget(b2);
c->show();
b2->resize(400, 300);  // 下一轮重算就改回去
b2->move(0, 0);        // 同样无效

想改尺寸，改的必须是布局的输入，不是布局的输出。

你的目标 该动的地方
控件固定成某个像素 setFixedSize()，或 sizePolicy 设 Fixed
控件至少要多高 setMinimumHeight()
控件要吃掉多余空间 sizePolicy 设 Expanding，配布局 stretch
控件之间留空 addStretch() / addSpacing()
窗口缩到刚好包住内容 layout()->setSizeConstraint(QLayout::SetFixedSize)
整体统一留白 布局的 setContentsMargins()

1.1 布局是一棵树 #

布局不是列表，是树。QLayout 继承自 QObject 和 QLayoutItem，所以一个布局既是若干控件的容器，也是它父布局眼里的一个「项」。

层次 类型 职责
容器 QWidget 提供绘制区域，持有唯一一个顶层布局
布局 QBoxLayout / QGridLayout / QFormLayout / QStackedLayout 计算子项位置
布局项 QWidgetItem / QSpacerItem / 子 QLayout 计算的最小单位
子控件 QWidget 最终被 setGeometry() 的对象

一个 QWidget 同时只能挂一个顶层布局。第二次 setLayout() 返回 false，控制台打印 already has a layout，界面毫无变化——这种静默失败很耗人。

1.2 核心 API #

API 作用
QWidget::setLayout(QLayout *) 装顶层布局，已有布局时返回 false
QWidget::layout() 取顶层布局
QLayout::invalidate() 标记缓存失效，下次事件循环重算
QLayout::activate() 立刻同步重算一次
QLayout::setEnabled(false) 布局暂时退出接管，子控件回到手动摆位
QLayout::totalMinimumSize() 布局能压到的最小尺寸

setSizeConstraint 决定窗口本身能不能被拖动缩放。

枚举 效果
SetDefaultConstraint 窗口最小尺寸取布局最小尺寸（默认值）
SetFixedSize 窗口尺寸锁成布局的 sizeHint，用户改不动
SetMinimumSize 窗口最小尺寸 = 布局最小尺寸
SetMaximumSize 窗口最大尺寸 = 布局最大尺寸
SetMinAndMaxSize 上下都锁

1.3 什么时候重算 #

触发 说明
父控件 resize 布局拿到新矩形，重排全部子项
addWidget / addLayout / removeWidget 布局树结构变了
子控件 sizeHint 变化 setText、setFixedSize、字体或样式变化，发 LayoutRequest
子控件 show / hide 隐藏项不参与分配
样式表重算 QSS 的 margin / padding 进 sizeHint
activate() 强制同步重算，用来读正确的 geometry

最后一行常被忽略：刚 addWidget 完就去读 widget->geometry()，拿到的是还没排过的旧值。要立刻取正确几何，先 layout()->activate()。

二、四种基础布局 #

Qt 自带布局类不少，日常真正用的是四个：水平、垂直、网格、表单。

布局类 基类 排列方式 伸缩手段 典型场景
QHBoxLayout QBoxLayout 从左到右一行 addWidget(w, stretch) 工具栏、按钮行、状态条
QVBoxLayout QBoxLayout 从上到下一列 addWidget(w, stretch) 侧边栏、设置页、整体骨架
QGridLayout QLayout 行列网格，可跨行跨列 setColumnStretch / setRowStretch 计算器键盘、参数表、九宫格
QFormLayout QLayout 左标签右输入两列 setFieldGrowthPolicy 登录框、属性面板

QHBoxLayout 和 QVBoxLayout 只差方向。两者都继承 QBoxLayout，可以直接构造 new QBoxLayout(QBoxLayout::TopToBottom, parent)，也能在运行期 setDirection() 换向。枚举有四个：LeftToRight、RightToLeft、TopToBottom、BottomToTop。后两个反向值做 RTL 语言适配才用得上。

2.1 水平与垂直 #

标题靠左、按钮靠右、中间留白，用弹簧把三块顶开。

cpp
QWidget *bar = new QWidget;
QHBoxLayout *h = new QHBoxLayout(bar);
h->setContentsMargins(8, 4, 8, 4);   // 左 上 右 下
h->setSpacing(6);
h->addWidget(new QLabel("工程"));
h->addStretch(1);                    // 吃掉中间空白
h->addWidget(new QPushButton("确定"));
h->addWidget(new QPushButton("取消"));

三个按钮平分一行，靠每个都带 stretch：

cpp
QHBoxLayout *h = new QHBoxLayout;
h->addWidget(new QPushButton("上一步"), 1);
h->addWidget(new QPushButton("下一步"), 1);
h->addWidget(new QPushButton("完成"), 1);

2.2 网格 #

第二个 addWidget 重载带跨距，参数顺序是控件、行、列、行跨、列跨。

cpp
QGridLayout *g = new QGridLayout;
g->addWidget(new QLabel("用户名"), 0, 0);
g->addWidget(new QLineEdit,       0, 1);
g->addWidget(new QLabel("备注"),   1, 0);
g->addWidget(new QTextEdit,       1, 1, 1, 2);   // 跨 2 列
g->addWidget(new QPushButton("确定"), 2, 2);
g->setColumnStretch(1, 1);        // 第 2 列吃掉横向余量
g->setColumnMinimumWidth(0, 72);  // 标签列不准再窄
g->setRowStretch(1, 1);           // 备注行吃掉纵向余量

网格的行列会自己长。中间留空的格子照样占位，(0,2) 空着不代表后面的控件会挤过来。要占住某个格子就塞 QSpacerItem，不要指望自动塌陷。

2.3 表单 #

QFormLayout 自动处理「标签列右对齐、输入列左对齐」。用 QGridLayout 也能做，但每加一项都要维护行号。

cpp
QFormLayout *f = new QFormLayout;
f->addRow("主机", new QLineEdit("127.0.0.1"));
f->addRow("端口", new QSpinBox);
f->addRow(new QLabel("凭据"));          // 单控件独占一行，当分组标题
f->addRow("用户名", new QLineEdit);
f->setLabelAlignment(Qt::AlignRight | Qt::AlignVCenter);
f->setFieldGrowthPolicy(QFormLayout::AllNonFixedFieldsGrow);
f->setRowWrapPolicy(QFormLayout::DontWrapRows);

FieldGrowthPolicy 管输入列怎么长：FieldsStayAtSizeHint 保持建议尺寸，ExpandingFieldsGrow 只让 Expanding 的输入框长，AllNonFixedFieldsGrow 让所有非固定尺寸的输入框都长。RowWrapPolicy 管窗口太窄时怎么办：DontWrapRows 硬撑，WrapLongRows 只把长行折下去，WrapAllRows 让标签全跑到输入框上方。

三、布局的嵌套与优先级 #

嵌套只有一个入口：addLayout()。它接收一个 QLayout *，把这个子布局整体当成一个布局项。

cpp
QWidget *panel = new QWidget;
QVBoxLayout *outer = new QVBoxLayout(panel);   // 外层：上下两段
outer->setContentsMargins(0, 0, 0, 0);
outer->setSpacing(4);

QHBoxLayout *row = new QHBoxLayout;            // 内层：一排按钮
row->addWidget(new QPushButton("刷新"));
row->addWidget(new QPushButton("导出"));
row->addStretch(1);

QTextEdit *log = new QTextEdit;
log->setReadOnly(true);

outer->addLayout(row);   // 内层布局当项用
outer->addWidget(log, 1);

3.1 尺寸怎么往上传递 #

内层布局先按自己的规则算，算完把三个数交出去。外层看不到内层里的具体控件，只看到这三个数。

传递方向 规则
向上（尺寸） 内层 sizeHint = 子项 sizeHint 之和 + spacing + 自身 margins
向上（最小） 内层最小尺寸是子项最小尺寸之和，压不下去
向下（空间） 外层先满足各子项最小值，再按 stretch 与 sizePolicy 分余量
向下（上限） 分到手的尺寸不得超过子项 maximumSize

这条链路有个直接后果：嵌套越深，最小尺寸越大。每层布局都带自己的 margins 和 spacing，向上传递时相加。四层嵌套、每层留 9 像素边距，光边距就吃掉 72 像素。窗口缩到某个宽度就缩不动，原因常在这里。定位靠逐层打印 totalMinimumSize()，看哪一层突然变大。

3.2 优先级 #

顺序 依据 说明
1 minimumSize 先保底，每项至少拿到这个尺寸
2 sizeHint 再按建议尺寸铺开
3 stretch 余量按权重分
4 sizePolicy 决定某项接不接受这份余量
5 maximumSize 最后兜上限，超了就不给

这个顺序解释两个常见现象：设了 setFixedSize() 之后再给 stretch 也没用，因为 maximumSize 兜住了；两个都设 Expanding 的控件，最终比例由 stretch 决定，不由 sizeHint 决定。

3.3 增删项的所有权 #

布局管着两样东西：布局项和控件，两者的生命周期是分开的。这是 Qt 布局里最容易踩的一条线。

操作 布局项 控件对象
removeWidget(w) 被摘掉 仍在，父对象不变
takeAt(i) 交给你，返回值持有它 仍在，不删
delete item 销毁 不删
removeTab / clear 摘掉 不删
父控件析构 一起销毁 一起销毁

removeWidget() 只是把控件从排布里摘出来，控件还挂在父控件上，它会停在原地不动，也会被别的布局接管。要真正消失得自己删。

cpp
layout->removeWidget(btn);   // 只是从布局里摘掉，控件还在窗口上飘着
btn->deleteLater();          // 摘掉并销毁才写这一行

takeAt() 把布局项的所有权交给你，返回值必须自己处理，不处理就是泄漏。

cpp
QLayoutItem *item = vbox->takeAt(0);
if (QWidget *w = item->widget()) w->setParent(nullptr);   // 先脱离，避免连带删除
delete item;                                              // 只销毁布局项

替换用 replaceWidget()，它返回被换下来的旧项，同样要自己收拾。

cpp
QLayoutItem *old = vbox->replaceWidget(btnOld, btnNew);
if (old) delete old;   // 旧项销毁；btnOld 对象还在，需要时再删

3.4 三栏骨架 #

左边树、右上下两块内容，是配置类工具最常见的样子。

cpp
QWidget *main = new QWidget;
QHBoxLayout *root = new QHBoxLayout(main);

QTreeWidget *tree = new QTreeWidget;
tree->setMinimumWidth(160);

QVBoxLayout *right = new QVBoxLayout;
right->addWidget(new QTextEdit, 2);   // 2 : 1 分高度
right->addWidget(new QTextEdit, 1);

root->addWidget(tree, 0);             // 0 = 不参与拉伸
root->addLayout(right, 1);            // 1 = 吃掉剩余宽度

tree 的 stretch 给 0，它保持 minimumWidth(160) 不再长；right 给 1，横向余量全归它。纵向由里面两个编辑框的 2:1 决定。需要用户自己拖分隔条时，别手写这套嵌套，用 QSplitter。

四、伸缩因子 sizePolicy 与 stretch #

窗口从 800 拖到 1400，多出的 600 像素分给谁？答案由两个东西共同决定：sizePolicy 说「我想不想变大」，stretch 说「变大的份额归谁」。

QSizePolicy 是二维的。水平一个策略、垂直一个策略，互不干扰——横向狂吃、纵向纹丝不动，是桌面程序里最常见的形态。

cpp
QWidget *w = new QWidget;
QSizePolicy sp = w->sizePolicy();
sp.setHorizontalPolicy(QSizePolicy::Expanding);
sp.setVerticalPolicy(QSizePolicy::Fixed);
w->setSizePolicy(sp);

// 一步写法
w->setSizePolicy(QSizePolicy(QSizePolicy::Expanding, QSizePolicy::Fixed));

4.1 七个策略值 #

策略 sizeHint 的地位 拉伸时 压缩时 用在哪
Fixed 就是固定尺寸 不长大 不缩小 固定图标、方形开关
Minimum 是最小尺寸 可以长大 不肯缩到 sizeHint 以下 按钮、标签
Maximum 是最大尺寸 不长大 可以缩小 上限明确的展示区
Preferred 是最优尺寸 可以长大 可以缩小 绝大多数控件
Expanding 合理尺寸 尽量吃满余量 可以缩小 主编辑区、日志框、画布
MinimumExpanding 是最小尺寸 尽量吃满余量 不肯缩到 sizeHint 以下 至少多宽又要占满的区
Ignored 被忽略 尽量占满 可以压到 0 贴图背景、装饰层

Minimum 与 MinimumExpanding 差在拉伸意愿：前者拿到够用的就停，后者主动去抢余量。Maximum 与 Preferred 差在缩小时让不让：前者以 sizeHint 为上限，后者把 sizeHint 当参考。

子控件的默认策略不用猜，打印出来看：

cpp
QPushButton *b = new QPushButton;
qDebug() << b->sizePolicy().horizontalPolicy()
         << b->sizePolicy().verticalPolicy();

常见控件的默认策略大致如下，对着上表读一遍就知道它们为什么那个脾气。

控件 水平 垂直 表现
裸 QWidget Preferred Preferred 宽高都可伸可缩
QPushButton Minimum Fixed 横向能长，高度永远一行字
QLineEdit Expanding Fixed 横向吃满，高度锁死
QLabel Preferred Preferred 跟着文字走
QTextEdit Expanding Expanding 双向吃满
QGroupBox Preferred Preferred 框内内容决定建议尺寸

QPushButton 垂直 Fixed 这一条，是「按钮在垂直布局里永远那么矮」的根因。想让按钮变高，光加 stretch 没用，得把垂直策略改成 Minimum 或直接 setMinimumHeight()。

4.2 stretch 才是份额 #

sizePolicy 只表态，分多少由 stretch 定。QBoxLayout 的 addWidget 第二个参数就是 stretch。

cpp
QVBoxLayout *v = new QVBoxLayout;
v->addWidget(new QTextEdit, 3);        // 拿 3 份余量
v->addWidget(new QTextEdit, 1);        // 拿 1 份
v->addWidget(new QPushButton("关闭")); // 0 份

窗口长高 200 像素，两个编辑框按 3:1 分，拿走 150 和 50，按钮一个像素不多拿。加入之后还能改：setStretch(0, 3) 按下标改，setStretchFactor(edit, 2) 按控件指针改。

QGridLayout 没有 stretch 参数，改用行列权重：

cpp
g->addWidget(new QLineEdit, 0, 0);
g->addWidget(new QPushButton("查找"), 0, 1);
g->setColumnStretch(0, 1);   // 输入列吃余量
g->setColumnStretch(1, 0);

4.3 两个都没设会怎样 #

stretch 全是 0 时，余量不会消失，布局按各子项的 sizePolicy 和 sizeHint 自行分配。结果是 Expanding 的控件把空间全吃掉，其他控件保持 sizeHint。这份自行分配是隐式的，难精确控制；只要对比例有要求，就把 stretch 显式写出来。

组合 结果
policy = Expanding，stretch = 0 会变大，比例靠布局内部估算
policy = Preferred，stretch = 0 拿到 sizeHint 就停
policy = Expanding，stretch = 2 明确按权重分配
policy = Fixed，stretch = 5 policy 优先，stretch 无效
policy = Ignored，stretch = 0 压到 0 或撑满，看空间

后两行是重点：Fixed 直接压掉 stretch，Ignored 让 stretch 失去参照。给控件设了 setFixedSize() 之后再研究 stretch，是在做无用功。

4.4 弹簧 #

addStretch() 是往布局里塞一个 QSpacerItem，策略为 Expanding。它占空白，不撑开某个控件。

cpp
QHBoxLayout *h = new QHBoxLayout;
h->addStretch(1);                      // 左侧空白
h->addWidget(new QPushButton("确定"));
h->addWidget(new QPushButton("取消"));
h->addStretch(1);                      // 右侧等量 → 按钮组居中

两个弹簧权重相等，按钮组居中；只留左边一个，按钮组靠右。要固定像素的间隔用 addSpacing(12)，它不参与拉伸分配。

五、间隔与边距 #

间距就两组：布局内部项与项之间的 spacing，布局四周与容器边界之间的 contentsMargins。

cpp
QVBoxLayout *v = new QVBoxLayout(widget);
v->setSpacing(8);                        // 项与项之间
v->setContentsMargins(12, 12, 12, 12);   // 左 上 右 下

contentsMargins 的参数顺序是左、上、右、下，不是 CSS 的顺时针。setContentsMargins(0, 12, 0, 0) 表示左右贴边、顶部留 12 像素。

5.1 默认值来自 style #

布局的默认 spacing 和 margins 由 QStyle 决定，Windows 风格下 margins 一般是 (9,9,9,9)、spacing 是 6，Linux 和 macOS 上不同。别背数字，用代码问：

cpp
int l, t, r, b;
v->getContentsMargins(&l, &t, &r, &b);
qDebug() << "margins" << l << t << r << b << "spacing" << v->spacing();

跨平台产品里凡是要对齐的地方，都显式设一遍。

5.2 四种留白手段 #

手段 作用范围 参与拉伸 用法
setSpacing(n) 布局内所有相邻项 否 统一按钮行间距
setContentsMargins(l,t,r,b) 布局与容器四边 否 面板整体留白
addSpacing(n) 插入固定空白项 否 某两段之间额外加宽
addStretch(n) 插入弹性空白项 是 居中、把内容顶开

前两个是布局属性，改一次全局生效；后两个是插项，位置固定，跟着顺序走。要精确控制某一处间隔用插项，要统一风格用属性，定点插入用 insertSpacing(index, size)。

cpp
QVBoxLayout *v = new QVBoxLayout;
v->addWidget(new QLabel("基本信息"));
v->addSpacing(4);      // 标题与内容贴近
v->addWidget(new QLineEdit);
v->addSpacing(20);     // 与下一段拉开
v->addWidget(new QLabel("高级选项"));

5.3 贴边与紧凑面板 #

默认 9 像素边距在嵌套时会叠加，做出「怎么都对不齐」的观感。让子面板完全贴边，是消除叠加的第一步：setContentsMargins(0, 0, 0, 0) 配一个小 setSpacing(2)，内层就不再自带留白。

样式表的 margin 和 padding 会叠加在布局边距之外，两者都设就是相加。给容器加 QSS 边框时，把 margin 归零，不然内容离边框一段距离。

六、QTabWidget 的使用 #

QTabWidget 是带标签栏的页面容器，由两个控件拼出来：QTabBar 管那排标签，QStackedWidget 管页面堆叠。

组件 职责
QTabBar 绘制标签项，处理点击与键盘导航，发 currentChanged
QStackedWidget 管理页面栈，只显示当前页

单个标签不是 QWidget。QTabBar 在 paintEvent 里用 QStylePainter 直接把文字和图标画上去，一千个标签也不会产生一千个控件对象——但也没有「标签控件」可以单独设属性，样式只能走 QSS。

cpp
QTabWidget *tab = new QTabWidget(this);

QWidget *page1 = new QWidget();          // 不传 parent
QVBoxLayout *l1 = new QVBoxLayout(page1);
l1->addWidget(new QLabel("页面一"));

QWidget *page2 = new QWidget();
QVBoxLayout *l2 = new QVBoxLayout(page2);
l2->addWidget(new QLabel("页面二"));

tab->addTab(page1, QIcon(":/icons/a.png"), "基本 &1");  // Alt+1 切换
tab->addTab(page2, "高级 &2");

connect(tab, &QTabWidget::currentChanged, this, [](int index) {
    qDebug() << "切到第" << index << "页";
});

标签文字里的 &1 是快捷键标记，Alt+1 直接跳页，做设置面板很省事。

七、QTabWidget 的隐藏与动态增删 #

「隐藏一个标签」有四种做法，效果完全不同，先分清再动手。

做法 标签栏 页面 索引 能切回去
setTabEnabled(i, false) + QSS 收宽度 还在，宽度归零 保留 不变 能
removeTab(i) 消失 仍在内存 后面全部前移 需重新插入
tabBar()->hide() 整条消失 保留 不变 能用代码切
setTabBarAutoHide(true) 只剩一页时收起 保留 不变 能

7.1 单个标签的视觉隐藏 #

removeTab() 之后想恢复，得自己记位置重新插入，索引管理很快失控。用「禁用 + 宽度归零」能保住索引。

cpp
void hideTab(QTabWidget *tab, int index)
{
    if (index < 0 || index >= tab->count()) return;
    // 要隐藏的正是当前页，先切到一个可用页
    if (tab->currentIndex() == index) {
        for (int i = 0; i < tab->count(); ++i) {
            if (i != index && tab->isTabEnabled(i)) {
                tab->setCurrentIndex(i);
                break;
            }
        }
    }
    tab->setTabEnabled(index, false);
}

配套的 QSS 是关键，不禁用只是变灰，宽度还在：

text
QTabBar::tab:disabled { width: 0px; padding: 0px; margin: 0px; color: transparent; }

代价是：隐藏首尾标签时，相邻标签的圆角伪状态会错位，tab:first 和 :last 认定的是禁用项。标签少、只隐藏中间的，直接用它；隐藏首尾又要圆角，改走 removeTab。

7.2 整条标签栏的隐藏 #

cpp
tab->tabBar()->hide();            // 立刻收起，页面区域随之变大
tab->tabBar()->show();
tab->setTabBarAutoHide(true);     // 只剩一页时自动收起，多页时自动出来

tabBar() 返回 QTabBar *，要包含 <QTabBar>。标签栏隐藏后页面照常显示，setCurrentIndex() 依然可用，只是用户点不到标签。

7.3 与 QStackedWidget 的差别 #

隐藏标签栏之后，两者看上去一模一样，行为差别还在。

维度 QTabWidget（标签栏已隐藏） QStackedWidget
页面管理 内部套一层 QStackedWidget 自己就是栈
增删 API addTab / removeTab / insertTab addWidget / removeWidget / insertWidget
标签文本 存在 QTabBar 里，即使看不见 不存在这个概念
角落控件 有 无
标签栏信号 仍有 tabBarClicked 等 无
何时该用 标签要按条件显示隐藏 导航完全自己控制

结论很直白：导航是标签栏，选 QTabWidget；导航是侧边列表、工具栏按钮、下拉框，选 QStackedWidget。先选了 QTabWidget 再费劲把标签栏藏掉，多半是把两者定位搞混了。

7.4 可关闭的标签 #

关闭前问一句「存不存」，关闭后自己删页面。

cpp
void handleClose(int index)
{
    QWidget *page = widget(index);
    if (!page) return;
    if (auto *edit = qobject_cast<QTextEdit *>(page)) {
        if (edit->document()->isModified()) {
            auto ret = QMessageBox::question(this, "未保存", "关闭前要保存吗？",
                          QMessageBox::Save | QMessageBox::Discard | QMessageBox::Cancel);
            if (ret == QMessageBox::Cancel) return;
            if (ret == QMessageBox::Save) saveTo(edit);
        }
    }
    removeTab(index);       // 只是摘掉，对象还活着
    page->deleteLater();    // 交给事件循环删，别在信号里析构
}

setTabsClosable(true);
connect(this, &QTabWidget::tabCloseRequested, this, &ClosableTabWidget::handleClose);

delete page 也能编译过，但这里正在响应 tabCloseRequested，信号发射方的栈还没退，deleteLater() 更稳。

7.5 延迟加载 #

一启动就把二十个重量级页面全建出来，启动速度会明显变慢。先塞占位页，等用户点进去再建。

cpp
void addLazyTab(const QString &label, std::function<QWidget *()> factory)
{
    int index = addTab(new QWidget(), label);   // 占位
    m_factories.insert(index, std::move(factory));
}

void ensureLoaded(int index)
{
    auto it = m_factories.find(index);
    if (it == m_factories.end()) return;
    QWidget *placeholder = widget(index);
    QWidget *real = it.value()();               // 此刻才真正构造
    QString label = tabText(index);
    removeTab(index);
    insertTab(index, real, label);
    setCurrentIndex(index);
    placeholder->deleteLater();
    m_factories.erase(it);
}

connect(this, &QTabWidget::currentChanged, this, &LazyTabWidget::ensureLoaded);

工厂函数里可以放耗时构造，但要外部准备的 IO 得另开线程，别在工厂里阻塞界面。

7.6 自定义 QTabBar #

右键菜单、双击重命名、拖到窗口外独立成窗，都得子类化 QTabBar。QTabWidget::setTabBar() 是 protected 的，只能在子类里调。

cpp
class CustomTabBar : public QTabBar
{
public:
    explicit CustomTabBar(QWidget *p = nullptr) : QTabBar(p)
    {
        setContextMenuPolicy(Qt::CustomContextMenu);
        connect(this, &QTabBar::customContextMenuRequested, this, [this](const QPoint &pos) {
            int i = tabAt(pos);
            if (i < 0) return;
            QMenu menu(this);
            menu.addAction("重命名", [this, i]() { emit renameRequested(i); });
            menu.addAction("关闭",   [this, i]() { emit tabCloseRequested(i); });
            menu.exec(mapToGlobal(pos));
        });
    }
signals:
    void renameRequested(int index);
};

class CustomTabWidget : public QTabWidget
{
public:
    explicit CustomTabWidget(QWidget *p = nullptr) : QTabWidget(p)
    { setTabBar(new CustomTabBar(this)); }   // 旧标签栏被接管并删除
};

双击事件重写 mouseDoubleClickEvent，用 tabAt(e->pos()) 判断点在哪一项；拖出成窗要另建一个顶层窗口，把页面 setParent 过去。

7.7 索引漂移与性能 #

动态增删最隐蔽的 bug 是索引失效。缓存过 index 的地方，removeTab 之后全指向别的页。稳妥做法是只缓存 QWidget *，操作前用 indexOf() 反查。

问题 症状 处理
索引漂移 删一页后关错页、切错页 缓存指针，用 indexOf 反查
页面不释放 removeTab 后内存不降 补 page->deleteLater()
页面全预加载 启动慢、内存高 走 7.5 的延迟加载
OpenGL 页泄漏 显存不释放 关闭前 makeCurrent() 后释放纹理与 FBO

八、QStackedWidget 与页面切换 #

QStackedWidget 只做一件事：把多个页面叠在一起，同一时刻只显示一个。它没有标签栏，切换全靠代码。

API 作用
addWidget(w) / insertWidget(i, w) 追加 / 插入，返回索引
removeWidget(w) 摘掉一页，不删对象
setCurrentIndex(i) / setCurrentWidget(w) 切页
currentWidget() / currentIndex() 当前页
count() / indexOf(w) / widget(i) 总数 / 反查 / 取页

信号只有两个：currentChanged(int) 和 widgetRemoved(int)。

8.1 侧边栏导航 #

一列菜单配一块内容区，用 QListWidget 当导航最省事。

cpp
QHBoxLayout *main = new QHBoxLayout;
QListWidget *nav = new QListWidget;
nav->setFixedWidth(150);
nav->addItems({"常规", "外观", "高级"});

QStackedWidget *stack = new QStackedWidget;
stack->addWidget(createGeneralPage());
stack->addWidget(createAppearancePage());
stack->addWidget(createAdvancedPage());

main->addWidget(nav);
main->addWidget(stack, 1);           // 内容区吃掉剩余宽度
connect(nav, &QListWidget::currentRowChanged, stack, &QStackedWidget::setCurrentIndex);
stack->setCurrentIndex(0);           // 让两边初始状态一致

最后一行别漏。QListWidget 的初始 currentRow 是 -1，不主动对齐，建完界面左侧没有任何一项高亮，用户看不出当前在哪一页。

8.2 与 QTabWidget 的分工 #

场景 该选谁
用户直接点标签切页 QTabWidget
导航是侧边列表、工具栏、下拉框 QStackedWidget
切换由程序驱动（向导、步骤跳转） QStackedWidget
标签上百且要流畅 QStackedWidget + QComboBox
标签要按权限动态显示隐藏 QTabWidget
需要标签拖动重排、关闭按钮 QTabWidget

两者底层是同一套东西：QTabWidget 内部就有一个 QStackedWidget。差别只在有没有那排标签，以及随之而来的标签管理 API。

8.3 尺寸与堆叠行为 #

QStackedWidget 用的是 QStackedLayout，它的 sizeHint 取所有页面的最大值，不是当前页。一页横向特别宽，整个控件就跟着宽，即使当前显示的是个窄页面。布局的 setStackingMode() 有两个值：StackOne 只显示当前页，StackAll 全部可见、后加的在上面。后者做叠层水印或悬浮提示才用得上，普通切页不要碰。页面切走只是隐藏，对象还在内存里，数据、定时器、网络请求都还在跑，该停的停。

九、QSplitter 可拖动分隔 #

布局把尺寸写死，QSplitter 交还给用户。它管理一排控件，中间插一条分隔条，拖哪边哪边变大。

cpp
QSplitter *sp = new QSplitter(Qt::Horizontal);
sp->addWidget(new QTreeWidget);
sp->addWidget(new QTextEdit);
sp->setStretchFactor(0, 0);        // 左树不参与拉伸
sp->setStretchFactor(1, 1);        // 右侧吃余量
sp->setSizes({200, 600});          // 初始尺寸，像素
sp->setHandleWidth(4);             // 分隔条宽度
sp->setChildrenCollapsible(false); // 不允许拖到 0 宽
API 作用
setOrientation(dir) Qt::Horizontal / Qt::Vertical，运行期可换
setSizes(QList<int>) / sizes() 设置 / 读回各段尺寸
setStretchFactor(i, n) 整体缩放时各段的伸缩权重
setCollapsible(i, bool) 某一段能否被拖到 0
setHandleWidth(n) / setOpaqueResize(bool) 分隔条粗细 / 拖动时实时重排
saveState() / restoreState() 记住用户拖过的比例

9.1 尺寸与权重是两回事 #

setSizes() 是初始绝对尺寸，setStretchFactor() 是整体缩放时的分配权重。两者要一起设，否则初始比例漂亮，一放大就散。

cpp
QSplitter *sp = new QSplitter(Qt::Vertical);
sp->addWidget(new QTextEdit);      // 上：代码
sp->addWidget(new QTextEdit);      // 下：输出
sp->setStretchFactor(0, 3);
sp->setStretchFactor(1, 1);
sp->setSizes({450, 150});

setSizes 传进去的数字不保证被原样接受。控件的 minimumSize 会把它顶回来，传 {0, 100} 得到的往往是 {最小宽度, 剩余}。

9.2 与布局配合 #

QSplitter 本身就是一个 QWidget，可以塞进任何布局，也可以在里面再放 QSplitter 做嵌套。「左树中码右属性、下面终端」就是三层嵌套。

cpp
QSplitter *outer   = new QSplitter(Qt::Vertical);     // 上内容 / 下终端
QSplitter *content = new QSplitter(Qt::Horizontal);   // 左树 / 中码 / 右属性
content->addWidget(new QTreeWidget);
content->addWidget(new QTextEdit);
content->addWidget(new QListWidget);
content->setSizes({180, 600, 220});
content->setChildrenCollapsible(false);   // 三栏都不许拖没

outer->addWidget(content);
outer->addWidget(new QTextEdit);
outer->setStretchFactor(0, 4);
outer->setStretchFactor(1, 1);

放进去之后不要再给里面的控件套布局去调位置，那是在和分隔条抢控制权。每个控件该做的是把自己的内部内容用布局排好。

9.3 分隔条样式 #

QSS 里 QSplitter::handle 给底色，:horizontal 与 :vertical 分别给 width 和 height，:hover 加高亮。setHandleWidth() 和 QSS 的 width 都设时以 QSS 为准，别两边都改。分隔条太细不好抓，3 到 5 像素是比较舒服的区间。

十、QDockWidget 停靠窗口 #

QDockWidget 是能被拖出、拖回、贴边、叠成标签页的浮动面板，必须挂在 QMainWindow 上。普通 QWidget 没有停靠区域。

区域 枚举
顶部 / 底部 Qt::TopDockWidgetArea / Qt::BottomDockWidgetArea
左侧 / 右侧 Qt::LeftDockWidgetArea / Qt::RightDockWidgetArea 
cpp
QDockWidget *dock = new QDockWidget("属性", this);
dock->setObjectName("propDock");            // 恢复布局必须靠它
dock->setAllowedAreas(Qt::LeftDockWidgetArea | Qt::RightDockWidgetArea);
dock->setFeatures(QDockWidget::DockWidgetMovable | QDockWidget::DockWidgetFloatable);

QWidget *body = new QWidget;
QVBoxLayout *v = new QVBoxLayout(body);
v->setContentsMargins(6, 6, 6, 6);
v->addWidget(new QLabel("宽度"));
v->addWidget(new QSpinBox);
v->addStretch(1);
dock->setWidget(body);                      // dock 内容要自己铺满

addDockWidget(Qt::RightDockWidgetArea, dock);
setCentralWidget(central);                  // 中央部件必须先有
API 作用
addDockWidget(area, dock) 放到指定区域
splitDockWidget(a, b, dir) 把一个 dock 放在另一个旁边
tabifyDockWidget(a, b) 两个 dock 叠成标签页
setDockOptions(...) AnimatedDocks、AllowNestedDocks、AllowTabbedDocks
setDockNestingEnabled(bool) 是否允许任意方向继续切分

features 三个值：DockWidgetClosable、DockWidgetMovable、DockWidgetFloatable，默认全开。菜单里那个「显示 / 隐藏属性面板」的勾选项直接用 toggleViewAction()，它会自动同步勾选状态，不要自己 hide()。

cpp
menu->addAction(dock->toggleViewAction());

QSettings s("MySoft", "Tool");
s.setValue("geometry", saveGeometry());
s.setValue("state", saveState());
restoreGeometry(s.value("geometry").toByteArray());
restoreState(s.value("state").toByteArray());

objectName 必须唯一且稳定，restoreState 靠它认人。restoreState() 要在所有 dock 建完之后调，早调会恢复出一个没有面板的空布局。

十一、遍历与获取子部件 #

界面一复杂，子控件被层层布局包着，你手上只有父窗口的 this，要拿里面某个 QLineEdit 就得靠查找。

cpp
QList<QLineEdit *> edits = this->findChildren<QLineEdit *>();
QLineEdit *one = this->findChild<QLineEdit *>("line_edit_2");   // 按 objectName

findChildren<T>() 有两个可选参数：名字（QString 或 QRegularExpression）和查找选项（默认 Qt::FindChildrenRecursively，可改 Qt::FindDirectChildrenOnly）。模板参数写 QLineEdit * 返回指针列表，写 QLineEdit 返回值拷贝列表，后者很少用。按类型找之前先给控件起名，名字是空串时按名查找永远失败。

cpp
QPushButton *btn = new QPushButton;
QLineEdit *e1 = new QLineEdit;
QLineEdit *e2 = new QLineEdit;
e1->setObjectName("line_edit_1");
e2->setObjectName("line_edit_2");

QVBoxLayout *v = new QVBoxLayout;
v->addStretch();
v->addWidget(btn);
v->addWidget(e1);
v->addWidget(e2);
v->addStretch();
v->setSpacing(10);
v->setContentsMargins(20, 0, 0, 20);
setLayout(v);

QList<QLineEdit *> list = this->findChildren<QLineEdit *>();
for (int i = 0; i < list.size(); ++i) {
    QLineEdit *edit = list.at(i);
    edit->setText(QString("line_edit%1").arg(i));
    if (edit->objectName() == "line_edit_2") {
        btn->setText(edit->objectName());   // 按钮文字同步为该项的名字
    }
}

11.1 返回的是 QList #

findChildren 的产物是 Qt 自己的容器。QList 在 Qt 5 里是指针数组，在 Qt 6 里和 QVector 统一成连续内存，两者可以互换。

特性 Qt 容器 STL 容器
隐式数据共享 支持（写时复制） 不支持
平台一致性 各平台行为一致 依赖编译器实现
线程安全 只读操作可跨线程 要自己加锁
传参成本 只拷指针，写时才深拷 按值传即深拷

Qt 容器传值不心疼，因为写时复制；但一个容器被多处持有后，某处一改就触发整份复制，遍历时修改要留神。

容器 底层 适用
QList Qt 6 为连续内存 通用列表，首选
QVector 连续内存 数值计算、随机访问
QLinkedList 双向链表 频繁中间插删
QMap 红黑树 要按 key 有序遍历
QHash 哈希表 只按 key 查，不管顺序

选 QMap 还是 QHash，看要不要有序遍历。要就 QMap，不要就 QHash，平均查找快一个量级。

11.2 一边遍历一边删 #

findChildren 拿到一堆子控件，逐个 delete 是最容易崩的地方。

cpp
// 错误：删掉当前项之后，迭代器已经失效
for (auto it = list.begin(); it != list.end(); ++it) {
    if ((*it)->objectName().isEmpty()) delete *it;   // 下一轮 ++it 未定义
}

// 正确一：先把要删的攒起来，遍历完再处理
QList<QWidget *> doomed;
for (QWidget *w : list) if (w->objectName().isEmpty()) doomed << w;
for (QWidget *w : doomed) w->deleteLater();

// 正确二：erase 返回下一个可用的迭代器
for (auto it = list.begin(); it != list.end(); ) {
    if ((*it)->objectName().isEmpty()) it = list.erase(it);
    else ++it;
}
操作 QList / QVector QMap / QHash QLinkedList
插入 全部迭代器失效 其他迭代器仍可用 其他迭代器仍可用
删除 被删项及其后失效 仅被删项失效 仅被删项失效
排序 全部失效 不适用 全部失效

拿不准就按「改动之后全部作废」处理，重新 findChildren 一次最省心。返回顺序没有承诺，别假设它按创建顺序或屏幕位置排，要顺序就自己按 geometry() 的 y 坐标排序。

11.3 用 QVariant 挂数据 #

子部件列表常要附带一份数据（节点 id、配置键）。给控件塞 QVariant 动态属性最省事，不用子类化。

cpp
QWidget *w = new QWidget;
w->setProperty("nodeId", 1001);
w->setProperty("path", "/var/log");
int id    = w->property("nodeId").toInt();   // 取回
QString p = w->property("path").toString();

QVariant 是 Qt 的通用类型容器，属性系统、数据库取值、信号槽跨类型传参全靠它。

转换方式 用途
toInt() / toString() 失败返回默认值，调用方无从判断
toInt(&ok) 带成功标志，能判断
canConvert<T>() 只说明「原则上能转」，不代表值能转
value<T>() / qvariant_cast<T>() 取 QColor、QImage 这类 GUI 类型 
cpp
QVariant v = "hello";
v.canConvert<int>();   // true：字符串原则上能转整数
v.toInt();             // 0：实际转换失败，返回默认值

v = "42";
v.toInt();             // 42

bool ok = false;
int n = v.toInt(&ok);  // 要判断成败走这个重载

QColor color = variant.value<QColor>();          // GUI 类型要带模块头
QVariant back = palette().background().color();  // 存，隐式转换

QVariantMap person;                              // 嵌套容器装树形数据
person["name"] = "Alice";
person["age"] = 30;
person["scores"] = QVariantList{95, 87, 92};

十二、界面组织技巧 #

布局把控件摆对，剩下的观感问题多半落在窗口本身和样式表上。

12.1 无边框与窗口标志 #

需求 写法
只留关闭按钮 setWindowFlags(Qt::CustomizeWindowHint | Qt::WindowCloseButtonHint)
完全无边框 setWindowFlags(Qt::FramelessWindowHint)
置顶显示 setWindowFlags(Qt::WindowStaysOnTopHint)
不进任务栏 setWindowFlags(Qt::Tool | Qt::X11BypassWindowManagerHint)

常用标志还有 Qt::WindowTitleHint、Qt::WindowSystemMenuHint、Qt::WindowMinimizeButtonHint、Qt::WindowMaximizeButtonHint、Qt::WindowMinMaxButtonsHint，后者一次给出最小化加最大化两个按钮。改 windowFlags 会让窗口重建，改完要重新 show()，之前的 setGeometry 也会被重置：位置信息改前存或改后设。

托盘图标点一下要把主窗升起来，只调 show() 不够，窗口常被压在别的窗口后面。正确序列是先 showNormal() 恢复正常尺寸、再 raise() 提到 Z 轴最上层、最后 activateWindow() 抢输入焦点。

12.2 无边框窗口最大化的坑 #

FramelessWindowHint 的窗口一 showMaximized() 就会盖住底部任务栏，开始菜单点不到。正确做法是不用最大化，把窗口几何设成屏幕的可用区域。

cpp
void MainWidget::toggleMaximize()
{
    if (m_isMaximized) {
        setGeometry(m_normalGeometry);             // 还原
        maxButton->setIcon(QIcon(":/icons/maximize"));
    } else {
        m_normalGeometry = geometry();             // 先记住原位置
        QScreen *screen = QGuiApplication::primaryScreen();
        setGeometry(screen->availableGeometry());  // 已扣掉任务栏
        maxButton->setIcon(QIcon(":/icons/restore"));
    }
    m_isMaximized = !m_isMaximized;
}

availableGeometry() 是扣除任务栏和系统面板的可用区域，geometry() 是整块物理屏。多显示器要用 screenAt(pos) 取当前所在那块屏的屏幕对象。QApplication::desktop() 在 Qt 5 起就废弃了。

12.3 圆角背景与文本定位 #

去掉标题栏后想贴圆角背景图，重写 paintEvent 比重设样式表可靠，样式表在无边框窗口上容易被裁剪。

cpp
void LoginDialog::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event)
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);   // 圆角去锯齿
    QBrush brush;
    brush.setTextureImage(QImage(":/images/login_bg.png"));
    painter.setBrush(brush);
    painter.setPen(QPen(Qt::black, 1));
    painter.drawRoundedRect(rect(), 5, 5);                 // 半径 5
}

窗口圆角只是画上去的视觉，点击热区还是方的，要真裁掉角上的鼠标事件得配 setMask()。日志窗口高频追加内容时，滚动条要跟着尾巴走：append() 之后最大值才更新，所以 verticalScrollBar()->setValue(maximum()) 必须写在追加之后，滚回顶部就把值设 0。

12.4 QPalette 与样式表 #

角色 管什么
QPalette::Window 窗口背景底色
QPalette::WindowText 窗口上的文字颜色
QPalette::Base 输入类控件背景（QLineEdit、QTextEdit）
QPalette::Text Base 之上的输入文字颜色
QPalette::Button / QPalette::ButtonText 按钮背景 / 按钮文字

样式表和调色板同时生效时，控件级 QSS 优先。定整体配色用调色板，抠单个控件细节用 QSS，混着改会打架。

坑 现象 处理
QComboBox QAbstractItemView::item 高度无效 下拉项高度不变 先 setView(new QListView)
滚动条箭头去不掉 上下箭头还在 add-line / sub-line 的 height 设 0
复选框状态贴图对不上 悬停、按下没图 六态都写：unchecked 三态加 checked 三态
边框与内容贴太近 文字框看着挤 容器 margin 归零，靠 padding 撑

十三、易错点速查 #

现象 原因 处理
resize() / move() 无效 布局接管了几何尺寸 改 sizeHint、sizePolicy 或 stretch
布局完全不生效 没调 setLayout，构造时也没传 parent 补一行 setLayout
第二次 setLayout 没反应 一个控件只能有一个顶层布局 先摘旧布局，或包一层 QWidget
removeWidget 后控件还在 只是出布局，对象未删 补 deleteLater()
删了布局项控件仍在 delete item 不碰 widget 先 item->widget() 取指针再删
窗口缩不下去 逐层 margins 与 spacing 累加 打印 totalMinimumSize() 定位
按钮垂直方向不长大 QPushButton 垂直策略是 Fixed 改策略或 setMinimumHeight
设了 stretch 没变化 该项 Fixed 或已 setFixedSize 先解掉固定尺寸
间距怎么都对不上 spacing、margins、QSS 三处叠加 内层 margins 归零，外层统一控制
页面切走仍占 CPU 只是 hide，逻辑还在跑 切页时停定时器、停刷新
removeTab 后内存不降 页面对象没删 widget(i) 取指针后 deleteLater
splitter 拖不到 0 setChildrenCollapsible(false) 需要折叠就打开
findChild 拿到空指针 objectName 没设或拼错 设名后再查，或用正则
遍历子部件时崩溃 边遍历边 delete 先收集后删，用 deleteLater
无边框最大化盖任务栏 showMaximized 吃整屏 用 availableGeometry()
canConvert 为真却取到 0 它只报潜在能力 用 toInt(&ok) 判断

布局这件事的收尾只有一句：凡是位置和尺寸，交给布局算；凡是「想让它变成什么样」，去改布局的输入。手伸到 resize 和 move 上去改结果，只会被下一轮重算覆盖。
