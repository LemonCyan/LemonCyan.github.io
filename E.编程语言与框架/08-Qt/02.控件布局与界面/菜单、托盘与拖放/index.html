这一篇只做一件事：把「点一下触发某个动作」的链路讲透。同一批 QAction，从菜单栏、右键菜单、托盘菜单三个入口进入，最后再讲把文件从资源管理器拖进窗口。

讲什么：QAction 与 QMenu 的从属关系、QMenuBar 的用法、右键 contextMenuEvent、图标快捷键与分隔符、QWidgetAction 定制菜单、按钮弹出菜单、QSystemTrayIcon 的完整用法与平台限制、拖放的三个环节与自定义 MIME 数据。

不讲什么：QToolBar 的停靠与溢出菜单在《容器与布局管理》；QSS 语法与无边框窗口在 03-自定义窗口与样式；QClipboard 的读写属于数据传递话题；模型视图的 mimeData / dropMimeData 重写在 03-模型视图与表格。

一、QMenu 与 QAction #

先记住一句话：菜单的本质是 QAction 的容器。

这话不是修辞。QMenu 本身不存文字、不存图标、不存勾选状态，它只按顺序持有一串 QAction 指针；弹出时挨个问每项要文案、图标、是否勾选、是否可用，再交给 QStyle 画。QMenuBar 是 QMenu 的容器，QMenu 是 QAction 的容器，QToolBar 也是 QAction 的容器——三层下来，真正干活的只有最下面那层。

1.1 一个 QAction，三个入口 #

这是 Qt 菜单体系最值钱的设计。你 new 一个 QAction，它可以同时被菜单栏、右键菜单、工具栏引用，因为它本来就不属于任何一处。谁引用它，谁负责画它。

cpp
// 一个行为对象
QAction *act_grid = new QAction(QIcon(":/icon/grid"), tr("显示网格"), this);
act_grid->setCheckable(true);
act_grid->setShortcut(QKeySequence(Qt::CTRL | Qt::Key_G));

// 入口一：菜单栏
QMenu *view_menu = menuBar()->addMenu(tr("视图"));
view_menu->addAction(act_grid);

// 入口二：工具栏
ui->mainToolBar->addAction(act_grid);

// 入口三：某个控件的右键菜单
ui->treeWidget->addAction(act_grid);
ui->treeWidget->setContextMenuPolicy(Qt::ActionsContextMenu);

// 三处显示同一个勾选状态：改一次，三处同时变
connect(act_grid, &QAction::toggled, canvas, &Canvas::setGridVisible);

状态同步是自动的，不需要你写任何转发代码。QAction 内部在 setChecked()、setEnabled()、setText() 之后发 changed()，所有引用它的容器都监听这个信号并重绘自己。所以三处入口看到的永远是同一份真值。

反过来也要注意：你在菜单里点一下勾选，工具栏上那个按钮会跟着凹陷，快捷键按下也一样。想让某处不跟着变，唯一的办法是不共享 QAction——那是设计上的分叉，不是显示上的分叉。

三处入口的分工：

入口 载体 弹出方式 典型用途
菜单栏 QMenuBar::addMenu() 点菜单标题 全局命令：文件、编辑、视图
右键菜单 控件重写 contextMenuEvent() 手动 exec() 针对当前选中项的命令
托盘菜单 QSystemTrayIcon::setContextMenu() 系统转发右键 窗口隐藏后唯一的交互入口
按钮菜单 QWidget::setMenu() 点按钮 某个批量操作的几种变体

1.2 QAction 的常用属性 #

方法 作用 备注
setText() 菜单项文字 带 & 的字母是助记符，&& 表示真的 &
setIcon() 左侧图标 系统主题图标用 QIcon::fromTheme()
setShortcut() 快捷键 会显示在菜单项右侧，见第四章
setCheckable() 变成可勾选项 配 toggled(bool) 用
setChecked() 当前勾选状态 三处入口自动同步
setEnabled() 灰掉 triggered 不再发出，快捷键也失效
setVisible() 隐藏 仍在容器里，只是不画
setData() 挂自定义数据 QVariant，遍历菜单时取值用
setStatusTip() 状态栏提示 鼠标滑过时由 QMainWindow 显示
setMenuRole() macOS 菜单归位 QuitRole / AboutRole 等

一个容易忽略的点：setVisible(false) 和 setEnabled(false) 不是一回事。前者让项消失，后者让它灰着留在原位。做权限控制时用前者更干净，但菜单布局会跳，做可用性提示时用后者。

1.3 该连哪个信号 #

信号 什么时候发 用在哪
QAction::triggered(bool) 用户点击或按快捷键 命令类动作，最常用
QAction::toggled(bool) 勾选状态变化 开关类动作
QAction::hovered() 鼠标滑到项上 做右侧预览、联动高亮
QMenu::aboutToShow() 菜单即将弹出 动态重建菜单内容
QMenu::triggered(QAction*) 菜单内任意项被触发 统一分发，省一堆 connect
QMenu::aboutToHide() 菜单收起 清理临时状态

QMenu::triggered(QAction *action) 这个重载值得单说：菜单项很多、槽函数逻辑又相似时，连一个信号就够，靠 action->data() 区分来源：

cpp
connect(recent_menu, &QMenu::triggered, this, [this](QAction *act) {
    openFile(act->data().toString());
});

动态菜单的标准写法是 aboutToShow 里重建：

cpp
connect(recent_menu, &QMenu::aboutToShow, this, [this] {
    recent_menu->clear();                       // 详见第三章关于 clear() 的坑
    for (const QString &path : recent_files) {
        QAction *act = recent_menu->addAction(QFileInfo(path).fileName());
        act->setData(path);
    }
    recent_menu->setEnabled(!recent_files.isEmpty());
});

clear() 之后再 addAction()，是「重建」而不是「更新」。项数在十以内无所谓，上百项时改成复用已有 action、只改文案。

二、菜单栏 QMenuBar #

QMenuBar 挂在 QMainWindow 上，由 menuBar() 懒创建——第一次调用时才 new，所以说「主窗口天生有一个菜单栏」是对的，说「它一定存在」要看有没有调用过。

cpp
// 主窗口构造函数里
QMenu *file_menu = menuBar()->addMenu(tr("文件(&F)"));
QAction *act_new  = file_menu->addAction(tr("新建(&N)"));
QAction *act_open = file_menu->addAction(tr("打开(&O)"));
file_menu->addSeparator();
QAction *act_quit = file_menu->addAction(tr("退出(&Q)"));

act_new->setShortcut(QKeySequence::New);        // Ctrl+N，跨平台
act_open->setShortcut(QKeySequence::Open);      // Ctrl+O
act_quit->setShortcut(QKeySequence::Quit);      // Ctrl+Q

connect(act_new,  &QAction::triggered, this, &MainWindow::newFile);
connect(act_open, &QAction::triggered, this, &MainWindow::openFile);
connect(act_quit, &QAction::triggered, qApp, &QApplication::quit);

QKeySequence::New 这类标准键比自己写 Qt::CTRL | Qt::Key_N 好，macOS 上会自动变成 Cmd+N。自己拼的 CTRL 在 macOS 上也映射成 Cmd，但 META 在 Windows 上就没有对应物了。

2.1 助记符与 Alt 键 #

tr("文件(&F)") 里的 &F 是助记符，按 Alt+F 展开「文件」菜单，再按字母执行对应项。规则几条：

写法 显示 说明
&File File，F 带下划线 单个 & 标助记符
&&File &File 双写表示字面量 &
文件(&F) 文件(F) 括号里的助记符是 Windows 惯例

同一层级内助记符别重复，重复的那一项拿不到焦点。菜单项多了以后用 findChild 遍历检查一遍比人眼靠谱。

2.2 原生菜单栏 #

macOS 会把 QMenuBar 搬到系统屏幕顶栏，这是系统规范，不是 Qt 抽风。QMenuBar::setNativeMenuBar(bool) 能关掉，关掉后菜单栏回到窗口内部。两个后果要提前知道：

  • 搬到系统顶栏后，QWidgetAction 里的自定义控件不显示。定制菜单在 macOS 上只能退化成普通菜单项，或者干脆关掉原生菜单栏。
  • 关于 / 偏好设置 / 退出 这几项会被系统按 setMenuRole() 重新归位，「帮助」菜单里的「关于」会跑到应用菜单里去。这不是 bug，是你该主动设 role 的地方。

Windows 和多数 Linux 桌面没有「原生菜单栏」这个概念，这个属性设了也没效果。

2.3 重建菜单 #

菜单内容随状态变化时（插件加载完才出现对应菜单），两种做法：menuBar()->clear() 全清再建，或者保住 QMenu 对象、只 clear() 它里面的 action。前者会把 QMenu 一起删掉，你手上缓存的 QMenu* 立刻悬空；后者只删 action。

三、右键上下文菜单 #

右键菜单是菜单体系里用得最多的一处。三种落地方式，选哪种取决于你要不要按点击位置区分内容。

方式 代码 适合场景
重写 contextMenuEvent() void contextMenuEvent(QContextMenuEvent*) override 内容要随点击位置变，最灵活
Qt::CustomContextMenu 连 customContextMenuRequested(QPoint) 不想派生子类，槽里拿到局部坐标
Qt::ActionsContextMenu widget->addAction(...) 后设策略 菜单固定，纯 QAction 集合

第二种方式的写法：

cpp
ui->listWidget->setContextMenuPolicy(Qt::CustomContextMenu);
connect(ui->listWidget, &QWidget::customContextMenuRequested,
        this, [this](const QPoint &pos) {
    QMenu menu(this);
    menu.addAction(tr("重命名"));
    menu.addAction(tr("删除"));
    menu.exec(ui->listWidget->mapToGlobal(pos));   // 注意：局部坐标要转全局
});

这里 pos 是控件局部坐标，exec() 要的是全局坐标，忘了 mapToGlobal 菜单就弹到屏幕左上角去。

3.1 重写 contextMenuEvent 的完整骨架 #

下面这个 ImageTree 继承 QTreeWidget，三个步骤：构造阶段建 action 并连槽、单独一个函数设文案（方便做多语化）、重写事件时按顺序挂进菜单再弹。头文件里补齐 <QMenu>、<QContextMenuEvent>、<QCursor>。

cpp
class ImageTree : public QTreeWidget
{
    Q_OBJECT
public:
    explicit ImageTree(QWidget *parent = nullptr);

protected:
    void contextMenuEvent(QContextMenuEvent *event) override;

private:
    void createActions();
    void translateLanguage();

private slots:
    void selectImages();
    void selectFolder();
    void removeSelectedImages();
    void removeAllImages();

private:
    QMenu *pop_menu;
    QAction *add_images_action, *add_folder_action;
    QAction *remove_selected_action, *remove_all_action;
};

ImageTree::ImageTree(QWidget *parent)
    : QTreeWidget(parent)
{
    createActions();
    translateLanguage();
}

void ImageTree::createActions()
{
    pop_menu = new QMenu(this);

    // 父对象给 this（控件），不给 pop_menu —— 原因见 3.3
    add_images_action      = new QAction(this);
    add_folder_action      = new QAction(this);
    remove_selected_action = new QAction(this);
    remove_all_action      = new QAction(this);

    connect(add_images_action,      &QAction::triggered, this, &ImageTree::selectImages);
    connect(add_folder_action,      &QAction::triggered, this, &ImageTree::selectFolder);
    connect(remove_selected_action, &QAction::triggered, this, &ImageTree::removeSelectedImages);
    connect(remove_all_action,      &QAction::triggered, this, &ImageTree::removeAllImages);
}

void ImageTree::translateLanguage()
{
    add_images_action->setText(tr("添加图片"));
    add_folder_action->setText(tr("添加文件夹"));
    remove_selected_action->setText(tr("删除所选图片"));
    remove_all_action->setText(tr("删除所有图片"));

    add_images_action->setIcon(QIcon(":/icon/add_image"));
    add_folder_action->setIcon(QIcon(":/icon/add_folder"));
}

void ImageTree::contextMenuEvent(QContextMenuEvent *event)
{
    // 1. 先清掉残留的项，防止同一批 action 被重复挂入
    pop_menu->clear();

    // 2. 按顺序挂入
    pop_menu->addAction(add_images_action);
    pop_menu->addAction(add_folder_action);
    pop_menu->addSeparator();
    pop_menu->addAction(remove_selected_action);
    pop_menu->addAction(remove_all_action);

    // 3. 弹出位置用全局坐标
    pop_menu->exec(QCursor::pos());

    // 4. 标记事件已处理，不再向上传递
    event->accept();
}

exec() 是阻塞的，菜单收起才返回。传 QCursor::pos() 和传 event->globalPos() 在右键场景下等价；多屏、高 DPI 缩放不一致的环境里，QCursor::pos() 更稳，因为它取的是当前真实指针位置。

3.2 二级菜单 #

菜单项多到需要分组时，用 addMenu() 挂子菜单，层级不设上限：

cpp
QMenu *submenu = new QMenu(tr("添加效果"), pop_menu);
QAction *action_text_watermark  = new QAction(tr("添加文本水印"), this);
QAction *action_image_watermark = new QAction(tr("添加图片水印"), this);

submenu->addAction(action_text_watermark);
submenu->addAction(action_image_watermark);

pop_menu->addMenu(submenu);      // 子菜单的标题就是 QMenu 构造时那个字符串

子菜单的父对象给 pop_menu，生命周期跟着父菜单走。反过来把 submenu 建成局部对象、挂到菜单上再出函数，菜单收起时它就被栈回收了，下次右键必然崩。

3.3 clear() 的删除规则 #

QMenu::clear() 删的不只是「菜单里的条目」，它会删掉父对象是它自己的那些 QAction。原文那份代码里 action 的父对象写成了 this（树控件），所以 clear() 只清指针、不删对象，下一轮 addAction() 还能用。

换成 new QAction(pop_menu)，clear() 之后那几个指针就悬空了，第二次右键时 addAction() 拿到野指针，直接崩。两条路选一条：

  • action 的父对象给控件（或 this），菜单只做引用，可以反复 clear + add。
  • action 的父对象给菜单，那就别 clear，改在构造时挂一次，靠 setVisible() 控制显隐。

3.4 表头穿透 #

QTreeWidget / QTableWidget 重写 contextMenuEvent() 之后，在表头上右键也会弹这个菜单。原因是表头是子控件，事件先给它，它不处理就冒泡给父控件。

在事件开头做一次位置校验就够了：

cpp
void ImageTree::contextMenuEvent(QContextMenuEvent *event)
{
    if (header()->isVisible() && header()->rect().contains(header()->mapFrom(this, event->pos())))
        return;                       // 落在表头上，不弹

    // ... 后续正常流程
}

如果不想做坐标换算，直接判断 event->pos().y() < header()->height() 在默认布局下也对，但换过布局就会错。

3.5 右键点了但选中项没变 #

QTreeWidget 收到右键时不会自动把被点的那一项设为当前项。你的槽函数里 currentItem() 拿到的还是上一次左键选中的东西，于是「删除所选」删错了行。

修法是在弹菜单之前手动锁一次焦点：

cpp
void ImageTree::contextMenuEvent(QContextMenuEvent *event)
{
    QTreeWidgetItem *item = itemAt(event->pos());
    if (!item)
        return;                       // 点在空白处，不弹
    setCurrentItem(item);             // 先锁焦点，再弹菜单

    pop_menu->clear();
    // ...
    pop_menu->exec(QCursor::pos());
}

itemAt() 收的是视口坐标。事件坐标来自 this，而树控件的视口会带偏移（有表头时 y 方向就差表头高度），严格写法是 itemAt(viewport()->mapFrom(this, event->pos()))。多数树控件场景下两者相等，别在有表头的表格里赌这个。

四、菜单的图标、快捷键与分隔符 #

这三样是菜单的「排版语言」，单独拎出来讲，因为它们决定了一个菜单看起来是专业工具还是玩具。

4.1 图标 #

setIcon() 收一个 QIcon。QIcon 内部能塞多个尺寸和状态，Qt 按控件的 devicePixelRatio 和当前状态自己挑一张，你不需要为高 DPI 单独做适配——前提是你把 1x 和 2x 的图都塞进去：

cpp
QIcon icon;
icon.addFile(":/icon/open_16.png", QSize(16, 16));
icon.addFile(":/icon/open_32.png", QSize(32, 32));
action->setIcon(icon);

Linux 上优先用系统主题图标，图标风格才和桌面一致。QIcon::fromTheme() 找不到时返回空图标，所以一定要带 fallback：

cpp
QIcon open_icon = QIcon::fromTheme("document-open", QIcon(":/icon/open.png"));

第二个参数是兜底，资源里的图标永远在，不会出现「菜单项左边一片空白」。

混排有个视觉坑：一部分项有图标、一部分没有，没有图标的那几项文字会整体左移，看着像没对齐。解决办法二选一——给所有项都设图标（哪怕是占位透明图），或者在 QSS 里把图标列固定下来：

text
QMenu::item {
    padding: 6px 28px 6px 32px;   /* 左侧 32px 留给图标 */
}
QMenu::icon {
    left: 8px;
}

4.2 分隔符 #

addSeparator() 返回那个分隔符 QAction 的指针，不是 void。这一点有用：分隔符也是 action，可以 setVisible(false)，可以在分组整体隐藏时一起藏掉。

写法 效果
addSeparator() 追加到末尾
insertSeparator(before) 插到指定 action 前面
连续两个分隔符 只画一条
首尾的分隔符 自动不画

最后两条是 Qt 自己的容错：你按数据驱动的逻辑盲目插分隔符，插出来的重复项和首尾项不会露出难看的横线。所以动态重建菜单时可以放心地「每组后面都加一条」。

4.3 快捷键 #

方法 说明
setShortcut(QKeySequence) 单个快捷键
setShortcuts(QList<QKeySequence>) 一组备选，任一命中即可
setShortcutContext(Qt::ShortcutContext) 生效范围
QKeySequence::New 等标准键 跨平台映射，优先用
Qt::AA_DontShowShortcutsInContextMenus 右键菜单里不显示快捷键

setShortcutContext() 的四个取值：WidgetShortcut 只管本控件，WidgetWithChildrenShortcut 连子控件一起算，WindowShortcut 是默认值（窗口激活就管用），ApplicationShortcut 切到别的窗口也管用。做全局热键（比如 Ctrl+Shift+F12 呼出窗口）要设 ApplicationShortcut，但系统级全局热键 Qt 自己做不到，那要看平台 API。

同一窗口里两个 action 用同一个快捷键，Qt 会打印 Ambiguous shortcut overload 并且两个都不触发。这种「按了没反应又没报错」的情况，先怀疑快捷键打架，别怀疑信号槽。

五、QMenu 的个性化定制 #

QAction 只能给文字加图标，想要菜单里出现播放按钮、音量滑块、头像这类东西，就得往菜单里塞控件。路线是 QMenu + QWidgetAction + QAction，外层再套 QSS。

QWidgetAction 的用法两步：new QWidgetAction(parent)，然后 setDefaultWidget(widget)。这个 action 加进菜单后，菜单不再画文字行，而是把这整个 widget 摆进去。

下面是一个音乐播放器的托盘菜单，模仿酷狗那种「播放控制条 + 功能项」的结构。

cpp
// 构造函数：分三步走，建 action、建控件块、往菜单里挂
SystemTray::SystemTray()
    : QSystemTrayIcon()
{
    this->createActions();       // 普通菜单项 + 播放控制块
    this->createPlayAction();    // QWidgetAction 里的按钮和标签
    this->addActions();          // 按顺序挂进 pop_menu
    this->translateLanguage();   // 统一设文案，方便多语化
    this->setContextMenu(pop_menu);
}

void SystemTray::createActions()
{
    this->setIcon(QIcon(":/images/music.png"));

    pop_menu = new QMenu();
    show_action      = new QAction(pop_menu);
    setting_action   = new QAction(pop_menu);
    lock_lrc_action  = new QAction(pop_menu);
    show_lrc_action  = new QAction(pop_menu);
    login_action     = new QAction(pop_menu);
    logout_action    = new QAction(pop_menu);

    connect(show_action,     &QAction::triggered, this, &SystemTray::showWidget);

定制菜单有四个坑，都在代码之外：

坑 现象 处理
同一个 QWidgetAction 挂两个菜单 第一处菜单里控件消失 一个菜单一个 action，控件会被 reparent
点控件区菜单不关 菜单悬浮着不动 在按钮 clicked 里手动 pop_menu->hide()
菜单宽度被文字项撑开 控制条那条特别宽或特别窄 给 play_widget 设 setFixedWidth()，或 QSS 写 QMenu { min-width: 240px; }
macOS 原生菜单栏 控件整块不显示 关掉 setNativeMenuBar(false)，或换成普通菜单项

第一条尤其容易踩：setDefaultWidget() 的作用是把控件 reparent 到 action 上，一个 action 只能持有一个 widget，同一个 action 进第二个菜单时，控件被搬走，第一个菜单里就空了。想做「同一套控制条在两个菜单里都出现」，就建两个 QWidgetAction。

六、按钮弹出菜单 #

按钮带下拉菜单是最省地方的做法：一个按钮占住工具条，点开是一组变体操作。实现只要一行 setMenu()。

cpp
void WatermarksToolWidget::createButton()
{
    remove_watermarks_button = new QPushButton(this);

    remove_menu = new QMenu(remove_watermarks_button);   // 父对象给按钮，别写空
    remove_selected_action = new QAction(remove_menu);
    remove_all_action      = new QAction(remove_menu);

    remove_menu->addAction(remove_selected_action);
    remove_menu->addAction(remove_all_action);

    // 一行绑定：点按钮弹菜单
    remove_watermarks_button->setMenu(remove_menu);

    // 不要下拉三角就加这一行，见 6.2
    // remove_watermarks_button->setStyleSheet("QPushButton::menu-indicator{image:None;}");
}

void WatermarksToolWidget::translateLanguage()
{
    remove_watermarks_button->setText(tr("去除水印"));
    remove_selected_action->setText(tr("去除所选水印"));
    remove_all_action->setText(tr("去除所有水印"));
}

setMenu() 之后 QPushButton 会自动在右侧画出下拉三角，这个三角由 QStyle 的 PE_IndicatorArrowDown 提供，跟你的按钮风格绑定，不用自己画。

6.1 两种按钮的差别 #

控件 点击行为 适合
QPushButton::setMenu() 点按钮任意位置都弹菜单，按钮自身不触发 按钮的唯一作用就是弹菜单
QToolButton::setMenu() + InstantPopup 同上 工具条上的图标按钮
QToolButton + MenuButtonPopup 点主体执行默认动作，点小箭头才弹菜单 一个主操作 + 几个变体
QToolButton + DelayedPopup 长按才弹菜单 少用，用户发现不了

MenuButtonPopup 是工具条上最实用的组合：中间的图标按钮执行「默认动作」，右边小三角负责切换默认动作。切换靠 setDefaultAction()：

cpp
QToolButton *btn = new QToolButton(this);
btn->setPopupMode(QToolButton::MenuButtonPopup);
btn->setMenu(remove_menu);
btn->setDefaultAction(remove_selected_action);   // 主体点下去就是它

// 用户在菜单里选了别的项，主体跟着换
connect(remove_menu, &QMenu::triggered, btn, &QToolButton::setDefaultAction);

MenuButtonPopup 模式下默认动作会被自动触发，别在 defaultAction 上再连一次 clicked，会执行两遍。

6.2 去掉下拉三角 #

cpp
remove_watermarks_button->setStyleSheet("QPushButton::menu-indicator{image:None;}");

image:None 把三角的图换掉，三角消失但位置还在，按钮文字不会跟着往右挪。想让文字占满，再加 width:0px;。

也有人用 QPushButton::menu-indicator{ subcontrol-position: right center; right: 8px; } 把三角往里推，避免它贴着按钮边缘。

三角消失后要留个提示，不然用户不知道这按钮能展开。常见做法是文案带一个「▾」，或者在鼠标悬停的 tooltip 里写清「点击展开」。

七、系统托盘：QSystemTrayIcon #

桌面后台程序、通讯工具在最小化或关闭后不退出，而是缩到任务栏角落常驻，这就是系统托盘。Qt 里对应 QSystemTrayIcon，四件事：设置图标、设置提示文字、挂右键菜单、显示。

cpp
QSystemTrayIcon *tray = new QSystemTrayIcon(this);
tray->setIcon(QIcon(":/icon/login.png"));      // 没有图标就不要 show()
tray->setToolTip(tr("我就是托盘"));
tray->setContextMenu(tray_menu);               // 右键菜单
tray->show();

顺序有讲究：setIcon() 必须在 show() 之前。先 show 再 setIcon，在部分平台上传图标的那条消息已经发过去了，后面补的图标不刷新，图标位置一片空白。

对象的生命周期是第二个坑。托盘的 parent 传 this（主窗口）很自然，但主窗口一销毁托盘跟着没，如果这是「退出登录」这种局部窗口，整个托盘就消失了。长期驻留的托盘对象放在 main() 里、或者给 qApp 当父对象更稳：

cpp
// main.cpp
TrayMenu *tray_menu = new TrayMenu(qApp);
QSystemTrayIcon *tray = new QSystemTrayIcon(qApp);
tray->setIcon(QIcon(":/icon/login.png"));
tray->setContextMenu(tray_menu);
tray->show();

托盘菜单本身用 QMenu 派生一个类，把 action 集中管起来：

cpp

八、托盘图标与提示 #

8.1 图标 #

托盘图标由系统绘制到通知区域，尺寸由系统定（Windows 是 16 或 24 像素，按 DPI 缩放）。你给一张 256 的图，系统缩下来，缩得模糊；给一张 16 的图，高 DPI 屏上又糊。做法是往 QIcon 里塞多个尺寸：16 / 20 / 24 应付 100% 到 125% 缩放，32 / 40 / 48 应付 150% 到 200%，64 以上留给大图标视图和部分 Linux 面板。

macOS 上要区分深浅色模式：托盘图标应该做成「模板图标」，系统自动反色。

cpp
QIcon tray_icon(QIcon::fromTheme("app"));
tray_icon.setIsMask(true);        // 声明这是模板图，随菜单栏深浅色反色
tray->setIcon(tray_icon);

8.2 提示文字与气泡通知 #

setToolTip() 是鼠标悬停时的提示，Windows 下有长度上限，太长会被截断，写一句短话。

showMessage() 推气泡，四个参数都能省，最常用前两个：

cpp
tray->showMessage(tr("托盘标题"), tr("托盘已启动并在后台运行。"),
                  QSystemTrayIcon::Information, 5000);   // 5 秒后自动消失
参数 取值 说明
图标 NoIcon / Information / Warning / Critical 影响气泡左边的图与系统提示音
时长 毫秒 0 或省略表示用系统默认，很多平台忽略此值

两个前提要先查：QSystemTrayIcon::supportsMessages() 返回 false 时气泡不会出现（部分 Linux 面板就是这样）；系统开了「专注助手 / 勿扰」时，气泡被丢进通知中心，用户看不到。所以通知只是辅助，关键信息别只靠气泡。

用户点了气泡，messageClicked() 信号会发出，拿它来打开主窗口是常规用法：

cpp
connect(tray, &QSystemTrayIcon::messageClicked, this, &LoginDialog::showNormal);

九、托盘菜单与事件 #

9.1 setContextMenu 与 activated 的分工 #

setContextMenu(QMenu*) 让系统接管右键：右键点图标，菜单弹出，这一路你不用写代码。代价是右键不再发 activated(Context)——菜单被系统截走了，信号自然不会来。别在 activated 里给 Context 再写一遍弹菜单的逻辑，会看到菜单闪一下又消失。

左键和双击走 activated(QSystemTrayIcon::ActivationReason)：

枚举值 触发时机
Trigger 单击左键
DoubleClick 双击左键
MiddleClick 单击中键
Context 右键（设了 contextMenu 后不再发）
Unknown 无法识别，兜底分支

单击和双击在部分平台上会连着发：双击的第一次单击先触发一次 Trigger。所以单击恢复窗口、双击做别的事，用户双击时会先恢复窗口再执行另一件，逻辑上容易打结。稳妥做法是双击只做和单击相同的事。

9.2 关闭窗口变托盘 #

这套流程有三段代码：closeEvent 里截住关闭、托盘菜单里给「显示」、退出时真退出。

cpp
// LoginDialog.cpp
LoginDialog::LoginDialog(QWidget *parent)
    : QDialog(parent)
{
    system_tray = new QSystemTrayIcon(this);
    system_tray->setToolTip(tr("我就是托盘"));
    system_tray->setIcon(QIcon(":/icon/login"));

    tray_menu = new TrayMenu(this);
    system_tray->setContextMenu(tray_menu);

    connect(system_tray, &QSystemTrayIcon::activated, this, &LoginDialog::onIconActivated);
    connect(tray_menu, &TrayMenu::showWidget, this, &LoginDialog::showNormal);

    system_tray->show();
    system_tray->showMessage(tr("托盘标题"), tr("托盘已启动并在后台运行。"));
}

void LoginDialog::onIconActivated(QSystemTrayIcon::ActivationReason reason)
{
    switch (reason) {
    case QSystemTrayIcon::Trigger:
        this->showNormal();
        this->raise();            // 从其他窗口后面提到前面
        this->activateWindow();   // 抢键盘焦点
        break;
    case QSystemTrayIcon::DoubleClick:
        this->showNormal();
        break;
    default:
        break;
    }
}

void LoginDialog::closeEvent(QCloseEvent *event)
{
    if (system_tray->isVisible()) {
        hide();                   // 只隐藏，不退出
        event->ignore();
    } else {
        event->accept();
    }
}

showNormal()、raise()、activateWindow() 三个一起调才稳：第一个把最小化还原，第二个把窗口提到 Z 序前面，第三个拿焦点。少一个就会出现「任务栏图标亮了但窗口还在后面」的怪状。

还有一个必须改的全局开关：

cpp
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QApplication::setQuitOnLastWindowClosed(false);   // 关键
    LoginDialog dlg;
    dlg.show();
    return app.exec();
}

这个属性默认是 true，意思是「最后一个窗口关闭时退出程序」。窗口一 hide，程序就直接退了，托盘图标跟着没，看起来像「点了关闭整个程序闪退」。把它关掉，退出时机就完全由你决定——托盘菜单里的「退出」里调 qApp->quit()：

cpp
connect(action_quit, &QAction::triggered, qApp, &QApplication::quit);

退出前把图标收掉（system_tray->hide() 再 qApp->quit()），某些平台上残留的托盘图标要等鼠标划过才消失。

十、托盘的平台差异 #

托盘是「系统提供的扩展点」，不是 Qt 的绘制区域，所以行为在三个平台上差别很大。

平台 实现 表现差异
Windows Shell_NotifyIcon 图标在通知区域；Win10 起默认收进「隐藏的图标」折叠区
macOS NSStatusItem 图标在屏幕右上角菜单栏；跟随深色模式反色；无气泡，走通知中心
Linux X11 XEmbed 托盘协议 需要面板支持（KDE、XFCE、MATE 有）；GNOME 3 默认没有
Linux Wayland StatusNotifierItem / AppIndicator 需要装扩展，Qt5 支持不完整
嵌入式 Linux 多数无桌面环境 完全没有托盘，isSystemTrayAvailable() 直接 false

所以第一行代码不是 new QSystemTrayIcon，是判断有没有：

cpp
if (!QSystemTrayIcon::isSystemTrayAvailable()) {
    // 没有托盘：不要拦截 closeEvent，让程序正常退出
    QMessageBox::information(this, tr("提示"),
                             tr("当前桌面环境不支持系统托盘，关闭窗口将退出程序。"));
} else {
    system_tray->show();
}

不判断的后果很具体：show() 不报错、不返回 false、图标不出现。你以为功能好了，用户那边「最小化后程序就没了」，还找不到去哪找回窗口。GNOME 用户尤其容易撞上——默认不装托盘扩展，托盘区根本不存在。

supportsMessages() 也要单独判断，它和 isSystemTrayAvailable() 是两件事：托盘在，但气泡通知不被支持，这在部分 Linux 面板上成立。

macOS 还有两条：

  • 托盘菜单是原生菜单，QWidgetAction 里的控件不显示，定制菜单在 mac 上要做退化版。
  • 图标必须是模板图标（setIsMask(true)），否则深色菜单栏上会是一个浅色方块。

跨平台的保底策略收成两行：const bool tray_ok = QSystemTrayIcon::isSystemTrayAvailable();，有托盘才 show()，closeEvent 里按 tray_ok 决定 hide() 还是 accept()。这个值存成成员变量，别在 closeEvent 里每次现查——托盘会在运行期间消失（用户手动关了面板），缓存一个初始判断结果，行为才一致。

十一、拖放的三个环节 #

拖放是两个动作：拖动、放下。一个控件可以当拖动点、当放下点，或者两者都当。文件从桌面拖进窗口是「当放下点」，列表内拖动排序是「两头都当」。

整条链路有三个环节，缺一个就不生效：

环节 代码 少了的后果
一、开门 setAcceptDrops(true) 拖动事件根本不派发，光标始终是禁止符号
二、验货 dragEnterEvent() 里 acceptProposedAction() dropEvent() 永远不触发
三、收货 dropEvent() 里解析 mimeData() 松手了，什么都没发生

第一环最冤：忘了 setAcceptDrops(true)，你在 dragEnterEvent() 里打满日志也一条都看不到。QWidget 默认不接受放下，Qt 连事件都不派给你，光标也不会变。

cpp
class TabelView : public QTableView
{
public:
    explicit TabelView(QWidget *parent = nullptr)
        : QTableView(parent)
    {
        setAcceptDrops(true);                          // 环节一：开门
        setDragDropMode(QAbstractItemView::DragDrop);
        setDragEnabled(true);
        setDropIndicatorShown(true);                   // 拖动时显示落点指示
        setWindowTitle("TabelView");
    }

protected:
    void dragEnterEvent(QDragEnterEvent *event) override;   // 环节二
    void dropEvent(QDropEvent *event) override;            // 环节三
};

void TabelView::dragEnterEvent(QDragEnterEvent *event)
{
    // 只收文件，别的一律拒
    if (event->mimeData()->hasFormat("text/uri-list"))
        event->acceptProposedAction();
    qDebug() << "drag enter";
}

void TabelView::dropEvent(QDropEvent *event)
{
    const QList<QUrl> urls = event->mimeData()->urls();
    if (urls.isEmpty())
        return;

    for (const QUrl &url : urls) {
        QString file_name = url.toLocalFile();
        qDebug() << file_name;
    }
}

acceptProposedAction() 这一句是第二环的全部。它告诉 Qt「这个控件接受拖过来的东西」，Qt 才会把后续的 dragMoveEvent()、dropEvent() 继续送过来。只调 accept() 也能接住事件，但没接收「建议动作」（复制还是移动），光标图标会不对。

文件拖放的 MIME 类型是 text/uri-list，用来装统一资源标识符——可以是本地文件名，也可以是 HTTP、FTP 地址。MIME 类型由 IANA 定义，格式是「类型/子类型」。检查它是不是这个类型，就挡住了从浏览器拖来的一段文字。

urls() 拿到多个 URI 是常态（用户一次框选十个文件），也会遇到非本地文件。所以先判空，再逐个 toLocalFile()；对非本地 URI，toLocalFile() 返回空串。

dragMoveEvent() 和 dragLeaveEvent() 在多数场景里不用重写，Qt 默认行为够用。要画自定义落点提示、或者拖动进入不同区域时改光标，才去碰它们。

用 QAbstractItemView 的派生类时，setDragDropMode() 一次性把拖动和放下打开：

模式 行为
NoDragDrop 都关（默认）
DragOnly 只能拖出去
DropOnly 只能拖进来
DragDrop 内部拖动重排 + 接受外部放下
InternalMove 只在内部移动，不接外部数据

InternalMove 是排序列表最省事的选法，配合 setDragEnabled(true) 就够了。

十二、自定义拖放数据 #

text/uri-list 和 text/plain 只够传现成的东西。要传自己的对象（比如树节点的 id、文档里的图元），得自定义 MIME 类型——格式是 application/x-你的应用名-类型名，x- 前缀表示私有类型。

发起端用 QDrag + QMimeData：

cpp
QMimeData *mime = new QMimeData;
QByteArray payload;
QDataStream out(&payload, QIODevice::WriteOnly);
out << node_id << node_name;
mime->setData("application/x-mytree-node", payload);

QDrag *drag = new QDrag(this);
drag->setMimeData(mime);            // mime 的所有权交给 drag，别自己 delete
drag->setPixmap(QPixmap(":/icon/node.png"));
drag->setHotSpot(QPoint(8, 8));     // 光标在拖影里的位置

// 阻塞到松手，返回用户最终选的动作
if (drag->exec(Qt::CopyAction | Qt::MoveAction) == Qt::MoveAction)
    removeNode(node_id);            // 用户选了「移动」，源端才删

exec() 的返回值是这条链路的最后一环。传进去的是「允许哪些动作」，返回的是「用户实际选了哪个」：按住 Ctrl 拖是复制，直接拖是移动。源端只在该删的时候删。

四个细节：

  • QDrag 和 QMimeData 归 QDrag 管，setMimeData() 之后不要手动 delete。
  • 拖影用 setPixmap()，不给的话系统画一个默认矩形，很难看。
  • 自定义类型名要写全，application/x-mytree-node 和 application/x-mytree-node2 是两个类型，接收端 hasFormat() 精确匹配。
  • 数据要自己序列化。QDataStream 最省事，in >> id >> name 的顺序必须和写出的顺序一致，改结构体就两边一起改。

接收端一律先问再取：

cpp
void TabelView::dropEvent(QDropEvent *event)
{
    if (!event->mimeData()->hasFormat("application/x-mytree-node")) {
        event->ignore();
        return;
    }

    QByteArray data = event->mimeData()->data("application/x-mytree-node");
    QDataStream in(&data, QIODevice::ReadOnly);
    int id = 0;
    QString name;
    in >> id >> name;

    event->acceptProposedAction();
}

拖动不是一点鼠标就开始。QApplication::startDragDistance() 定了最小位移，防止把单击误判成拖动。手写 mouseMoveEvent 发起拖动时，判断 (event->pos() - press_pos).manhattanLength() >= QApplication::startDragDistance()，别用固定像素值。

十三、易错点速查 #

症状 原因 修法
改了一处菜单的勾选，别处没变 各自 new 了 QAction 共享同一个 QAction
第二次右键崩溃 clear() 把菜单自己拥有的 action 删了 action 的父对象给控件，或别 clear
右键点了，选中的还是上一行 右键不改变当前项 弹菜单前 setCurrentItem(itemAt(pos))
表头上右键也弹菜单 事件从子控件冒泡上来 开头判 header()->rect().contains(...) 直接 return
菜单弹在屏幕左上角 传了局部坐标 exec() 要全局坐标，mapToGlobal()
快捷键按了没反应也不报错 两个 action 撞了同一快捷键 查 Ambiguous shortcut overload
有图标和没图标的项文字不齐 图标列宽度不固定 统一设图标，或 QSS 固定 padding-left
菜单里的按钮点完菜单不关 菜单不接管 QWidgetAction 的点击 按钮 clicked 里手动 pop_menu->hide()
同一个 QWidgetAction 挂两个菜单，控件只在一处出现 setDefaultWidget 会 reparent 一个菜单一个 action
托盘图标不显示，也不报错 桌面环境没有托盘 先查 isSystemTrayAvailable()
关窗口整个程序退出 quitOnLastWindowClosed 默认为 true setQuitOnLastWindowClosed(false)
托盘气泡不出来 面板不支持通知 查 supportsMessages()，或走系统通知
拖放完全没反应 少 setAcceptDrops(true) 构造函数里补上
能拖进来，松手没反应 dragEnterEvent 没 accept acceptProposedAction()
dropEvent 里 urls() 是空 拖的不是文件 hasFormat("text/uri-list") 先判断

最后一条经验：菜单和托盘的所有问题，九成落在「对象生命周期」和「平台差异」两件事上；拖放的所有问题，九成落在「三个环节少了一个」。遇到怪现象，先按这两条分个类，再翻代码。
