这一篇只干一件事：让界面好看。QSS 怎么写，窗口怎么透，背景怎么铺，无边框窗口的阴影从哪来。

讲什么：QSS 的语法与作用域、选择器、盒模型与边框、背景（颜色/渐变/图片）、按钮与输入框的状态样式、继承与优先级、QSS 与 QPalette 的关系；窗体的三种透明做法与背景透明的坑；阴影边框的三条实现路线，以及它和无边框窗口怎么配。

不讲什么：布局与尺寸分配在《容器与布局管理》；控件自身的行为参数（校验器、模型、代理）在控件基础篇；出现动画、切换动画在动画那篇；整套换肤的主题管理器属于架构话题，这里只到单个控件与单个窗口的层面。

一、Qt 的三种外观手段 #

改外观，Qt 只给了你三个入口。认清这三个，后面所有技巧都是它们的花式组合。

手段 入口 改的是什么 典型用途
QSS 样式表 setStyleSheet() 绘制参数：颜色、边框、圆角、背景、字体、子控件布局 统一皮肤、区分状态
QPalette 调色板 setPalette() 角色色：Window、Base、Text、Button、Highlight 跟随系统深浅色、局部换色
自绘 重写 paintEvent() 像素级输出 渐变底、阴影、不规则形状

三者的最小例子：

cpp
btn->setStyleSheet("QPushButton { background: #2E3648; color: #BDC8E2; }");   // QSS

QPalette pal = palette();                                                     // QPalette
pal.setColor(QPalette::Window, Qt::black);
setPalette(pal);

void MyWidget::paintEvent(QPaintEvent *)                                      // 自绘
{
    QPainter painter(this);
    painter.fillRect(rect(), Qt::black);
}

窗口这一层还有四个开关，它们管的不是「控件怎么画」，是「窗口整体怎么合成」：

开关 作用 常见搭配
setWindowOpacity(qreal) 整窗透明度，含所有子控件 淡出动画、置灰提示
setAttribute(Qt::WA_TranslucentBackground) 窗口底色透明，自绘内容可带 Alpha 圆角、不规则窗口、阴影外层
setWindowFlags(Qt::FramelessWindowHint) 去掉系统标题栏与边框 自定义标题栏、浮层
setGraphicsEffect(...) 给控件挂离屏特效 QGraphicsDropShadowEffect 投影

把四个来源排一条优先级，从低到高：

text
1. QStyle 原生绘制        —— 平台风格画出来的按钮、滚动条
2. QPalette 角色色        —— 原生 style 读它来取色
3. QSS                    —— QStyleSheetStyle 代理原生 style，命中规则就接管
4. paintEvent 自绘        —— 你自己落了笔，前面三样都白说

1.1 QSS 是「样式表」，不是「主题引擎」 #

这是本篇最重要的一句话，先钉死。

QSS 只改绘制外观，不改布局，不改行为。它不会替你创建子控件，不会改事件处理，不会动 geometry()。你写 QPushButton { background: red; }，按钮的位置、大小、点击响应一条都没变。

有一个折返点要提防：QSS 不动 geometry()，但 QStyleSheetStyle 会参与 sizeFromContents 的计算。你写了 min-width: 120px 或大 padding，控件的 sizeHint() 就被撑大，布局按新的 sizeHint 重新分配空间 —— 看起来像「QSS 改了布局」，其实是布局读到了新的建议尺寸。

1.2 设了 QSS，原生样式就整体让位 #

第二个必须钉死的点。控件一旦被 QSS 命中，QStyleSheetStyle 就把原生 style 包了一层：你没声明的属性回落原生绘制，你声明了绘制关键属性，原生那条绘制路径就整段被替换。

cpp
// 只想要个圆角，结果按钮的按下位移、焦点框、默认按钮边框全没了
btn->setStyleSheet("QPushButton { border-radius: 6px; background: #3A3F4B; }");

原生 QPushButton 那套「未按下是凸起、按下是凹陷、获得焦点加一圈虚线」是 QStyle::drawControl(CE_PushButton) 一点点画出来的。你碰了 background 和 border，走的就不再是那条路径。

两条路补回来：

cpp
// 路线 A：补齐所有状态，自己把立体感画回来
btn->setStyleSheet(R"(
    QPushButton { background: #3A3F4B; color: #E6E6E6; border: 1px solid #4A4F5B;
                  border-radius: 6px; padding: 6px 14px; }
    QPushButton:hover   { background: #454B58; }
    QPushButton:pressed { background: #2E333D; padding-top: 7px; }
    QPushButton:disabled{ background: #2A2E36; color: #6B7280; }
    QPushButton:focus   { border: 1px solid #5B8DEF; }
)");

// 路线 B：换一套风格，让原生绘制本身可预期（跨平台一致）
qApp->setStyle(QStyleFactory::create("Fusion"));
// 或者只给某一个控件换，不动全局
btn->setStyle(QStyleFactory::create("Fusion"));

路线 B 的价值在跨平台：Windows 的 windowsvista 风格与 Linux 的 fusion 画出来的按钮差别很大，QSS 覆盖之后差异被放大。先把风格统一，再谈 QSS。

1.3 自定义 QWidget 子类的背景不生效 #

QWidget 子类设 background-color 常常没反应，因为裸 QWidget 的 paintEvent 里没有「按样式表画背景」这一步。两个解法：

cpp
// 解法一：打开这个属性，样式表的背景由基类绘制
setAttribute(Qt::WA_StyledBackground, true);

// 解法二：自己用 QStyleOption 画，兼容性最好
void MyWidget::paintEvent(QPaintEvent *)
{
    QStyleOption opt;
    opt.initFrom(this);
    QPainter p(this);
    style()->drawPrimitive(QStyle::PE_Widget, &opt, &p, this);
}

QFrame、QAbstractButton、QLabel 这些本来就带绘制逻辑，不受此困扰。踩坑的永远是自写的 QWidget / QMainWindow 子类。

二、QSS 是什么：语法与作用域 #

2.1 一条规则的骨架 #

QSS 的语法跟 CSS 基本一致，一条规则 = 选择器 + 声明块。

css
选择器 {
    属性: 值;
    属性: 值;
}

多个选择器用逗号分隔，多条声明用分号分隔：

css
/* 逗号：一组控件共享同一套声明 */
QPushButton, QLineEdit, QComboBox { color: red; font-family: Arial; }

/* 分号：一条规则里放多个属性 */
QPushButton { color: red; font-family: Arial; line-height: 26px; }

四条硬规矩：

  • 声明必须以 ; 结尾，最后一条也建议加上，漏了整条规则会被丢弃。
  • 注释只有 /* */ 一种，// 不是注释，会把后面的内容当成值解析。
  • 数值带单位，长度用 px，颜色可写 red、#eb7350、rgb(110,110,110)、rgba(0,0,0,80)。
  • 属性名跟 CSS 大部重合，但 Qt 不是浏览器，不支持的属性静默忽略，不报错也不警告。

常用属性一张表：

属性 取值示例 作用
color white / #eb7350 / rgb(110,110,110) 前景色，也就是文字色
background-color 同上 背景色
background-image url(:/img/bg.png) 背景图
border-style solid / outset / inset / none 边框样式
border-width 2px 边框粗细
border-color red 边框颜色
border-radius 6px 圆角半径
font-family "Microsoft YaHei" 字体族
font-size 14px 字号
font-style italic 斜体
font-weight bold 加粗
padding 4px 10px 内边距

font 是简写，一条顶五条：

css
QLabel {
    font: bold italic 18px "Microsoft YaHei";
    color: #BDC8E2;
}

2.2 QSS 写在哪：三个作用域 #

写法 影响范围 适用场景
widget->setStyleSheet(...) 该控件及其后代 单个控件特调
window->setStyleSheet(...) 整窗所有子控件 一个窗口内统一皮肤
qApp->setStyleSheet(...) 全进程所有窗口 全局主题、加载 .qss 文件 
cpp
// 全局：启动时读一个 qss 文件
QFile f(":/style/app.qss");
if (f.open(QIODevice::ReadOnly | QIODevice::Text)) {
    qApp->setStyleSheet(QString::fromUtf8(f.readAll()));
    f.close();
}

this->setStyleSheet("QLineEdit { border: 1px solid #444; }");    // 单窗口
nameEdit->setStyleSheet("QLineEdit { border: 1px solid red; }"); // 单控件

作用域的传递规则要记清：对父控件设样式表，子控件会继承匹配到的规则。这就是为什么给窗口设了 background-image，里面所有没单独设背景的子控件看着都像被染了一层 —— 规则命中了子控件。

子控件自己再设一次，就以自己那份为准；但它不会「加在上面」，是替换掉自己这一层，父级规则里对它命中的部分依然生效。

2.3 路径怎么写 #

背景图与图标的位置有三种：

css
/* 绝对路径：能跑，但别进仓库 */
#MainWindow { border-image: url(D:/1.png); }

/* 相对路径：相对进程工作目录，换个启动位置就找不到 */
#MainWindow { border-image: url(1.png); }

/* 资源路径：编译进二进制，最稳 */
QPushButton { border-image: url(:/images/image/Icon19.png); }
QLabel     { border-image: url(:/images/image/Icon7.png); }

第三种走 Qt 资源系统（.qrc），路径以 : 开头，不依赖任何外部文件，发布时少一堆「图丢了」的问题。

border-image 与 background-image 的区别在第五章讲背景时展开，这里先记一句：铺满整个控件区域用 border-image，需要平铺/定位/留白用 background-image。

三、选择器：类型、类、ID、属性 #

3.1 五把筛子 #

写法 名称 命中谁
QPushButton 类型选择器 所有 QPushButton，含子类
.QPushButton 类选择器 所有 QPushButton 实例，不含子类
QPushButton#okButton ID 选择器 对象名恰为 okButton 的那个
QPushButton[flat="false"] 属性选择器 属性 flat 为 false 的实例
QDialog QPushButton 后代选择器 是 QDialog 后代的所有按钮
QDialog > QPushButton 子代选择器 是 QDialog 直接子级的所有按钮 
cpp
setStyleSheet("QPushButton { color: red; }");              // 类型：全部按钮都红字
setStyleSheet(".QPushButton { color: red; }");             // 类：不含 MyFancyButton 子类

okButton->setObjectName("okButton");                       // ID：objectName 必须先设
setStyleSheet("QPushButton#okButton { color: green; }");

setStyleSheet("QPushButton[flat=\"false\"] { border: 1px solid #666; }");   // 属性

setStyleSheet("QDialog QPushButton { color: blue; }");     // 后代：隔几层都算
setStyleSheet("QDialog > QPushButton { color: blue; }");   // 子代：只差一层

ID 选择器有个前提：objectName 得设。UI 设计器里拖出来的控件默认叫 pushButton、label，不动手改名，一堆控件会撞在同一个 ID 上，你以为是精确打击，其实是全中。

cpp
// 从 .ui 里加载的控件，最好在 setupUi 之后统一改一遍
ui->pushButton_ok->setObjectName("okButton");
ui->pushButton_cancel->setObjectName("cancelButton");

3.2 伪状态：控件的当下处境 #

伪状态接在选择器后面，用 : 引出，描述控件此刻的交互状态。

伪状态 含义
:hover 鼠标悬停
:!hover 不悬停
:pressed 被按下
:checked 选中（可勾选控件）
:disabled 被禁用
:enabled 可用
:focus 有焦点
:hover:checked 悬停且选中
:hover:!pressed 悬停且未按下

前置 ! 是否定，多个伪状态串联表示「同时满足」。

cpp
// 单个状态
lineEdit->setStyleSheet("QLineEdit:hover { background-color: black; color: yellow; }");

// 串联状态
checkBox->setStyleSheet("QCheckBox:checked:hover { background-color: green; }");

QPushButton 支持的常用伪状态就是上面这五个；QCheckBox 与 QRadioButton 多一个 :checked，配 ::indicator 子控件一起用。

3.3 子控件：控件的零件 #

复杂控件由多个零件组成，零件用 :: 引出，单独设样式。QTabWidget 的页签、QComboBox 的下拉箭头、QSlider 的槽与握把、QScrollBar 的轨与滑块，都是这个道理。

QPushButton 有一个 ::menu-indicator，只有调过 setMenu() 才会出现：

cpp
btn->setMenu(menu);   // 挂上菜单，指示器图标自动出现

btn->setStyleSheet(R"(
    QPushButton::menu-indicator {
        image: url(:/img/arrow_down.png);
        subcontrol-position: right center;
        subcontrol-origin: padding;
        right: 10px;
        top: 15px;
    }
)");
参数 含义
image 指示器图标
subcontrol-position 指示器在按钮内的对齐位置
subcontrol-origin 指示器的参考矩形（padding / border / content / margin）
right top left bottom 指示器距参考矩形四边的偏移

其他常见零件：

css
QComboBox::drop-down        { subcontrol-origin: padding; subcontrol-position: right center;
                              width: 20px; border-left: 1px solid #444; }
QComboBox::down-arrow       { image: url(:/img/arrow.png); }
QTabBar::tab                { background: #2E3648; padding: 6px 18px; }
QTabBar::tab:selected       { background: #3A3F4B; }
QCheckBox::indicator        { width: 16px; height: 16px; }
QCheckBox::indicator:checked{ image: url(:/img/check.png); }
QSlider::groove:horizontal  { height: 4px; background: #444; }
QSlider::handle:horizontal  { width: 12px; margin: -4px 0; background: #5B8DEF; border-radius: 6px; }
QScrollBar::handle:vertical { background: #4A4F5B; border-radius: 4px; min-height: 24px; }

3.4 选择器的优先级 #

多条规则同时命中一个控件时，越具体的赢。粗略的次序是：

text
ID 选择器 > 属性选择器 > 类选择器 > 类型选择器
带伪状态的 > 不带伪状态的
子控件 > 该子控件所属的父控件样式

css
/* OK 按钮同时命中三条，最后一条赢 */
QPushButton            { background: #333; }   /* 输 */
QPushButton[flat="false"] { background: #444; } /* 输 */
QPushButton#okButton   { background: #5B8DEF; } /* 赢 */

真要靠优先级解决问题，说明结构已经乱了。更稳的做法是给每个控件一个唯一的 objectName，一条规则对应一个控件，别赌谁更具体。

四、盒模型与边框 #

4.1 四层结构 #

QSS 沿用了 CSS 的盒模型，一个控件从外到内四层：

text
+----- margin（外边距，控件外围留白）----------------+
|  +-- border（边框，画在 padding 之外）----------+  |
|  |  +-- padding（内边距）--------------------+  |  |
|  |  |  content：文字 / 图标 / 子控件          |  |  |
|  |  +--------------------------------------+  |  |
|  +------------------------------------------+  |
+----------------------------------------------+
层 对应属性 影响
margin margin / margin-left 等 控件与相邻控件的间距
border border-width / border-style / border-color 边框粗细、线型、颜色
padding padding / padding-left 等 内容与边框的距离
content 无对应属性 文字、图标、子控件的实际区域

Qt 没有 box-sizing 这个概念，边框与内边距都画在控件矩形内部，padding 挤的是内容，不是控件本身。想让整个控件变高，写 min-height，别指望 padding 撑开外部尺寸 —— 除非控件在布局里是 sizeHint 驱动的，那时 padding 会通过 sizeFromContents 把建议尺寸带大。

4.2 边框的两种写法 #

分写三属性，或者用简写一条搞定：

css
/* 分写：样式、宽度、颜色各自控制，做单边边框时更灵活 */
QLabel { border-style: solid; border-width: 2px; border-color: red; border-radius: 20px; }

/* 简写：顺序是 宽度 样式 颜色 */
QLabel { border: 2px solid red; border-radius: 8px; }

只画一边，用单边属性：

css
QWidget#header { border-bottom: 1px solid #3A3F4B; }   /* 只要底部一条分隔线 */
QTableView     { border: none; gridline-color: #3A3F4B; }

border-style 的取值跟 CSS 一致：none、solid、dashed、dotted、double、groove、ridge、inset、outset。原生的「立体感」就是靠 outset/inset 画出来的，这套在 QSS 里也能用，只是效果跟着平台风格走，跨平台不稳定。

4.3 圆角的三个限制 #

圆角看着简单，三个地方会翻车。

第一，border-radius 只影响自己的绘制区域，不裁剪子控件。父控件圆角了，里面的方形子控件照样伸出去。

cpp
// 老办法：遮罩。锯齿明显，已不推荐
setMask(QRegion(rect(), QRegion::Rectangle));

// 现行做法：让内部容器整体缩进 1px 避免溢色
outer->setStyleSheet("QWidget#outer { background: #2E3648; border-radius: 8px; }");
layout->setContentsMargins(1, 1, 1, 1);

第二，圆角要靠 border 才画得干净。只写 background 加 border-radius，四角在低分辨率下会残留一两个锯齿点，补一条同色 border 能压掉。

第三，别对顶层窗口用 QSS 写 border-radius 就以为窗口变圆角了。窗口的方角是系统给的，要圆角得靠 WA_TranslucentBackground 加自绘，第九章讲。

4.4 文字位置：text-align 的半边天 #

QSS 里的 text-align 只对一部分控件生效。

css
QPushButton { text-align: left center; padding-left: 10px; }   /* 支持 */
QLabel      { text-align: center; }                            /* 无效，白写 */

QLabel 的文字位置只能靠 padding 挤，padding: 8px 7px 9px 10px 的顺序是上 右 下 左，跟 CSS 一个规矩；或者干脆调 API：

cpp
label->setAlignment(Qt::AlignLeft | Qt::AlignVCenter);

五、背景：颜色、渐变、图片 #

5.1 纯色 #

css
QLabel    { background-color: #2E3648; }
QLabel    { background-color: rgb(110, 110, 110); }
QLabel    { background-color: rgba(46, 54, 72, 200); }   /* 第四位是 Alpha */
QWidget#panel { background: transparent; }

background 是简写，可以一次写颜色、图片、重复方式、位置：

css
QLabel { background: #2E3648 url(:/img/grid.png) no-repeat left center; }

5.2 渐变 #

QSS 里三种渐变，都用函数写，不需要任何图片资源。

css
/* 线性：起点到终点拉一条色带 */
QWidget#header { background: qlineargradient(x1:0, y1:0, x2:1, y2:1,
                                             stop:0 #2E3648, stop:0.5 #3A3F4B, stop:1 #454B58); }

/* 径向：中心亮、边缘暗 */
QPushButton#round { background: qradialgradient(cx:0.5, cy:0.5, radius:0.8,
                                                fx:0.5, fy:0.5, stop:0 #5B8DEF, stop:1 #2E3648); }

/* 锥形：绕圆心扫一圈 */
QWidget#dial { background: qconicalgradient(cx:0.5, cy:0.5, angle:90,
                                            stop:0 #5B8DEF, stop:1 #2E3648); }
函数 关键参数 说明
qlineargradient x1 y1 x2 y2 是 0~1 的相对坐标 起点到终点拉一条色带
qradialgradient cx cy 圆心、radius 半径、fx fy 焦点 焦点与圆心不重合时会产生偏心高光
qconicalgradient cx cy 圆心、angle 起始角度 角度按逆时针走，单位是度

stop 的数值在 0~1 之间，可以写多个，颜色支持 #RRGGBB 与 rgba()。渐变边界想要硬过渡，让相邻两个 stop 的值相同。

5.3 背景图片：background-image 与 border-image #

这两个属性长得很像，行为差得远。

css
/* 会平铺，按 position 对齐，不拉伸 */
QLabel {
    background-image: url(:/img/tile.png);
    background-repeat: no-repeat;      /* no-repeat / repeat / repeat-x / repeat-y */
    background-position: left center;  /* left / center / right + top / center / bottom */
}

/* 铺满整个控件的边框盒，会拉伸 */
QPushButton { border-image: url(:/img/btn_normal.png); }
对比项 background-image border-image
默认行为 平铺 拉伸铺满
能否控制重复 background-repeat 四种取值 不支持
能否控制位置 background-position 九宫格 不支持
九宫格拉伸 不支持 支持，用 border-image 的切片参数
典型用途 背景纹理、小图标 按钮三态切图、带边框的圆角底

border-image 的九宫格写法，四个值表示上右下左的切片宽度，最后的 stretch 表示中间区域拉伸：

css
QPushButton#card {
    border-image: url(:/img/card.png) 8 8 8 8 stretch stretch;
    border-width: 8px;
}

切片图的好处是圆角和描边永远清晰，只有中间部分被拉伸。切图的设计决定了能拉伸的方向：stretch 双轴都拉，repeat 平铺，round 平铺并把边缘缩放对齐。

5.4 用 QSS 设窗口背景，我不推荐 #

窗口背景有三条路：QPalette、paintEvent 自绘、QSS。这里先把结论摆出来 —— 对顶层窗口，别用 QSS 设背景。窗口设了 QSS 背景，子控件不单独声明就会被规则命中，整窗看着都像被染了一层；想修就得给每个子控件补 background: transparent，越补越乱。

cpp
// 典型现场：工具栏、状态栏、中央控件全糊上了同一张图
this->setStyleSheet("QMainWindow { background-image: url(:/img/bg.jpg); }");

子控件用 QSS 设背景完全没问题，窗口这一层交给 QPalette 或 paintEvent 更省事。背景要随窗口尺寸变化、要跟换肤联动，走 paintEvent 最灵活：改完调 update() 立刻重绘。范围一律用 this->rect()，别写死 QRect(0, 0, 400, 400)，窗口一缩放，写死的矩形就不够用。

cpp
void IIIMark::paintEvent(QPaintEvent *)
{
    QPixmap pixmap = QPixmap(":/qm/safe").scaled(this->size());
    QPainter painter(this);
    painter.drawPixmap(this->rect(), pixmap);
}

scaled(this->size()) 会按窗口尺寸拉伸，非纯色图会被拉变形。要不变形，用 Qt::KeepAspectRatio 保住比例，剩下的空白用同色补上。

六、按钮与输入框的样式 #

6.1 QPushButton 的完整一套 #

字体、文字位置、边框、背景、三态，五个部分拼出一个能看的按钮。

css
QPushButton {
    font-family: "Microsoft YaHei"; font-size: 16px;
    font-weight: bold; font-style: italic;
    color: #BDC8E2; background-color: #2E3648;
    border: 2px solid #3A3F4B; border-radius: 20px;
    text-align: center;                /* 按钮支持，QLabel 不支持 */
    padding: 8px 7px 9px 10px;         /* 上 右 下 左 */
}

背景图版本：

css
QPushButton#iconBtn {
    background: #2E3648 url(:/img/icon.png) no-repeat left center;
    padding-left: 28px;          /* 给图标留出位置，文字不被压住 */
}

padding-left 是给背景图让位的标准手法。background-position: left center 只负责把图放在左边，图不会自己挤开文字。

三个动态状态，一个都不能少：

css
QPushButton:hover    { color: red;   border-color: green;      background-color: aqua; }
QPushButton:pressed  { color: green; border-color: blueviolet; background-color: black; }
QPushButton:disabled { color: blue;  border-color: brown;      background-color: aqua; }

少了 :disabled，禁用状态的按钮会显示成「看起来能点」的样子，用户点到没反应，体验直接掉档。少了 :pressed，按下没有反馈，手感为零。

6.2 背景图按钮：三态切图 #

按钮做图片皮肤，最省事的做法是三张图对应三个状态。

cpp
ui->pushButton_1->setStyleSheet(R"(
    QPushButton {
        border-image: url(:/images/image/Icon19.png);
    }
    QPushButton:hover {
        border-image: url(:/images/image/Icon19_hover.png);
    }
    QPushButton:pressed {
        border-image: url(:/images/image/Icon19_pressed.png);
    }
)");

border-image 会自动把图拉满整个按钮，切图按实际尺寸做，或者用上一节的九宫格切片。用 background-image 的话不会拉伸，图小了就只占左上角一块。

6.3 QLineEdit：边框与焦点 #

输入框最容易出问题的不是颜色，是边框一加，高度就变。

css
QLineEdit {
    background: #1E222A;
    color: #E6E6E6;
    border: 1px solid #3A3F4B;
    border-radius: 4px;
    padding: 4px 8px;
    min-height: 24px;              /* 固定住高度，别让边框把行高顶开 */
    selection-background-color: #5B8DEF;
    selection-color: #FFFFFF;
    placeholder-text-color: #6B7280;
}
QLineEdit:hover    { border-color: #4A4F5B; }
QLineEdit:focus    { border: 1px solid #5B8DEF; }
QLineEdit:disabled { background: #23272F; color: #6B7280; }

min-height 是这套里的关键一行。QSS 的 border 挤在内边距之外、内容区之内，不固定高度的话，加了边框的输入框会比旁边没加边框的控件高 2px，整行对不齐。

6.4 QLabel：文字与图标 #

QLabel 的样式比按钮简单，没有伪状态里的 :pressed，只有 :hover 和 :disabled。

css
QLabel {
    font-family: "Microsoft YaHei"; font-size: 14px; font-weight: bold;
    color: #BDC8E2; background-color: #2E3648;
    border: 2px solid red; border-radius: 20px; padding: 8px 10px;
}
QLabel:hover    { color: red;  border-color: green; background-color: aqua; }
QLabel:disabled { color: blue; border-color: brown; background-color: aqua; }

用 QLabel 显示图片，两条路：走 QSS 的 border-image，或者走 setPixmap。

cpp
// 路一：QSS 铺图，会自动填满 label 区域
ui->label_1->setStyleSheet("QLabel { border-image: url(:/images/image/Icon7.png); }");

// 路二：setPixmap，需要自己缩放
QImage image, result;
image.load(temppath);                                   // temppath 是图片路径
result = image.scaled(ui->label_2->width(), ui->label_2->height(),
                      Qt::IgnoreAspectRatio, Qt::SmoothTransformation);   // 按固定大小显示
ui->label_2->setPixmap(QPixmap::fromImage(result));
方式 是否拉伸 是否随控件尺寸变 适合
QSS border-image 拉伸铺满 是，自动 头像、缩略图、皮肤
setPixmap 不拉伸，原尺寸显示 否，改了尺寸要重设 图标、状态标记

setPixmap 那条路要留神：label_2 先 resize 再 scaled，顺序反了拿到的就是旧尺寸；窗口可以缩放的话，尺寸变化得重新 scaled 一遍。SmoothTransformation 与 Qt::FastTransformation 的差别在缩放质量，前者慢一点但边缘干净，小图放大时两者都糊，只能换更好的插值或重新出图。

七、QSS 的继承与优先级 #

7.1 没有 CSS 那种属性继承 #

QSS 不是 CSS 的完整实现，它没有 inherit 关键字，也没有父选择器。你看到的「继承」，本质是选择器命中了子控件。

cpp
// 这条规则命中的不是「窗口」，是「窗口里所有 QPushButton」
this->setStyleSheet("QPushButton { color: red; }");

只有两类属性会真的往下传：color 与 font-*。因为它们是落到控件的 QPalette 与 QFont 上的，而这两个东西本来就向子控件传播。

cpp
// 父窗口设了 color，子控件文字也跟着变
this->setStyleSheet("QWidget { color: #E6E6E6; }");
// 等价于给整棵树设了 palette 的 Text 角色

background、border、padding 这类绘制属性不会传播。父控件有背景，子控件该透明还是透明 —— 子控件看着「被染了」，是因为规则本身也匹配了子控件，不是因为继承。

7.2 三档样式表的叠加 #

三个作用域同时存在时，粒度越细的越靠前：

cpp
qApp->setStyleSheet("QPushButton { background: #5B8DEF; }");   // 全局：所有按钮蓝底
this->setStyleSheet("QPushButton { background: #3A3F4B; }");   // 窗口级：盖住全局
btn->setStyleSheet("QPushButton { background: #E05252; }");    // 控件级：最后生效

同一档内部，后写的规则覆盖先写的，前提是选择器优先级相同。

cpp
btn->setStyleSheet("QPushButton { background: #333; }"
                   "QPushButton { background: #444; }");   // 第二条赢

QSS 不支持 !important，写了会被当成非法值丢掉。想强行压过别人的规则，只能提优先级或者拆成更细的作用域。

7.3 冲突排查的固定动作 #

样式不生效时，别猜，按这个顺序砍：

  1. 把 qApp 的全局样式表临时清成空串，看目标控件恢复没有。恢复了，说明被全局规则压着。
  2. 用 widget->styleSheet() 打印当前控件自己的样式表，确认真的设上了（常见翻车：设在了另一个同名对象上）。
  3. 把选择器收窄到 #objectName，排除被别的规则抢走。
  4. 还不行就看绘制路径：自写的 QWidget 子类有没有 WA_StyledBackground，paintEvent 里有没有把基类那一步吃掉。

八、QSS 与调色板 QPalette 的关系 #

8.1 QPalette 管的是「角色色」 #

QPalette 不给具体控件指定颜色，它给一组角色赋值，由 QStyle 在各处取用。

角色 用在哪
QPalette::Window 窗口底色
QPalette::WindowText 窗口上的文字
QPalette::Base 输入类控件的底（QLineEdit、QTextEdit、列表视图）
QPalette::Text 输入类控件的文字
QPalette::Button 按钮底色
QPalette::ButtonText 按钮文字
QPalette::Highlight 选中项底色
QPalette::HighlightedText 选中项文字

两种设置背景的写法，效果等价：

cpp
// 写法一：按角色名
QPalette palette(this->palette());
palette.setColor(QPalette::Window, Qt::black);
this->setPalette(palette);

// 写法二：按当前控件的背景角色，动态适配
QPalette palette;
palette.setBrush(this->backgroundRole(), Qt::black);
this->setPalette(palette);

QPalette::Background 是 QPalette::Window 的旧名字，this->backgroundRole() 在裸 QWidget 上返回的也是 Window，三者指向同一个位置。setColor 与 setBrush 都能用，区别是后者接受 QBrush，能塞渐变色。

背景图片走 setBrush：

cpp
QPixmap pixmap = QPixmap(":/qm/safe").scaled(this->size());
QPalette palette(this->palette());
palette.setBrush(QPalette::Window, QBrush(pixmap));
this->setPalette(palette);

scaled(this->size()) 这一步不能省。原图尺寸跟窗口对不上，不缩放就只有左上角一块。代价是拉伸变形，纯色图无所谓，有内容的图会走样。

8.2 autoFillBackground 那行代码 #

setAutoFillBackground(true) 被抄得到处都是，它到底管什么，一句话说清：它决定控件是否用调色板的背景色刷底。

cpp
MyWidget *w = new MyWidget;           // 直接 show 的独立窗口，不写也有背景色
w->show();

MyWidget *child = new MyWidget(parent);      // 塞进父窗口当子控件
child->setAutoFillBackground(true);          // 不写这行就没底色

原因是子控件默认不给自己的矩形填色，指望父控件透出来。要独立于父控件有底色，就得开这个开关。它跟 QSS 是两条路：开了 autoFillBackground 又用 QSS 设 background-color，QSS 赢。

8.3 两者冲突时谁说了算 #

text
QSS 命中绘制属性       → QSS 赢，palette 的对应角色被忽略
QSS 没命中该属性       → 回落 palette，再回落原生 style
场景 结果
只设 QPalette::Window 生效，窗口底色变了
只设 QSS background-color 生效，palette 的 Window 不再参与
两个都设 QSS 的 background-color 生效
QSS 只设 color，palette 设了 Window 各管一段，都生效

实操上的分工：颜色体系用 QPalette 做（跟着系统深浅色走），单个控件的精细外观用 QSS 做。反过来的写法也能跑，只是改主题时要动的地方分散在两处。

九、窗口透明度的三种做法 #

9.1 三层，作用范围完全不同 #

这是本篇第二个必须钉死的点。三种「透明」听上去是一回事，实际作用范围、副作用、能否做圆角，全不一样。

做法 API 透明的是什么 子控件 能否做圆角/不规则
整窗透明度 setWindowOpacity(qreal) 整个窗口的合成结果 一起变透明 否
窗口背景透明 setAttribute(Qt::WA_TranslucentBackground) 窗口底色 保持不透明 是
局部背景透明 QSS background: transparent 指定控件的背景 只影响该控件 否

混用会互相覆盖，不是叠加。setWindowOpacity(0.8) 加上背景 alpha 为 128 的 QSS，最终看到的是两者相乘的结果，比你以为的更透。

9.2 整窗透明度：setWindowOpacity #

cpp
setWindowOpacity(0.5);   // 在构造函数或初始化函数里调用

参数是 qreal，0.0 到 1.0：1.0 完全不透明（默认），0.5 半透明，0.0 等于看不见但窗口还在、鼠标事件照收。

这一层是整窗合成：主窗口、标题栏、里面所有按钮和文字一起变淡。适合做淡入淡出动画、做「窗口失焦时整体变暗」。

它依赖窗口管理器的合成能力。Windows 与 macOS 上直接可用；X11 下需要开 compositing，否则调用无效。有些平台还会因为透明窗口而关掉硬件加速。

9.3 窗口背景透明：WA_TranslucentBackground #

这是做圆角、不规则窗口、阴影外框的前提。子控件不受影响，该不透明还是不透明。

cpp
setAttribute(Qt::WA_TranslucentBackground, true);
setWindowFlags(Qt::FramelessWindowHint);   // 去掉系统标题栏，圆角才看得见

开了之后，窗口底色不再由系统填充，改由你自己的 paintEvent 决定。要半透明底，画一个带 Alpha 的颜色；要圆角，把 fillRect 换成 drawRoundedRect：

cpp
void MyWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);

    // 半透明底：QColor 第四个参数是 Alpha，0 - 255
    painter.fillRect(this->rect(), QColor(0, 0, 255, 80));

    // 圆角底
    painter.setRenderHint(QPainter::Antialiasing, true);
    painter.setPen(Qt::NoPen);
    painter.setBrush(QColor(46, 54, 72, 230));
    painter.drawRoundedRect(rect(), 8, 8);
}

要底图带渐变透明，得用混合模式把渐变和图片合成一遍：

cpp
void QZXingWidget::paintEvent(QPaintEvent *)
{
    QPixmap covert_pixmap(":/Images/background");            // 待混色的原始大图
    QPixmap pixmap(covert_pixmap.width(), covert_pixmap.height());
    pixmap.fill(Qt::transparent);                            // 同尺寸的透明缓冲层

    QPainter painter(&pixmap);
    QLinearGradient linear_gradient(QPoint(0, 0), QPoint(0, pixmap.height()));
    linear_gradient.setColorAt(0,   QColor(255, 255, 255, 100));  // 顶端透明度 100
    linear_gradient.setColorAt(0.5, QColor(255, 255, 255, 150));  // 中部透明度 150
    linear_gradient.setColorAt(1,   QColor(255, 255, 255, 255));  // 底部完全不透明
    painter.fillRect(this->rect(), QBrush(linear_gradient));

    // 关键一步：SourceIn 让渐变与原图按 Alpha 合并
    painter.setCompositionMode(QPainter::CompositionMode_SourceIn);
    painter.drawPixmap(0, 0, covert_pixmap);
    painter.end();

    QPainter painter2(this);                                 // 输出合成后的底图
    painter2.drawPixmap(0, 0, pixmap);
}

CompositionMode_SourceIn 的语义是「结果取源图的形状、目标图的颜色」，所以渐变那一层决定了哪里透、透多少，原图只提供颜色。这段代码的坑在 this->rect() 与缓冲层尺寸不一致时的裁剪行为，缓冲层尺寸一律跟着原图走。

9.4 局部背景透明：QSS 那一层 #

css
/* 完全透明：露出父控件或窗口底色 */
QWidget#panel { background: transparent; }

/* 半透明：自己带 Alpha */
QWidget#panel { background: rgba(46, 54, 72, 160); }

这一层只改指定控件的绘制，窗口本身照常不透明。做「卡片浮层」「半透明工具栏」用它最轻。

两个前置条件缺一不可：控件的父级链路上有半透明底可露；控件本身的 autoFillBackground 没把它刷成实色。自写的 QWidget 子类还要 WA_StyledBackground，否则 background 声明根本不执行。

9.5 另外两条老路子 #

调色板把背景色写成 Alpha 为 0，等于让窗口整体透明、子控件不透明；局部挖洞用 CompositionMode_Clear，画笔把经过的像素 Alpha 直接清零。

cpp
QPalette pal = palette();
pal.setColor(QPalette::Window, QColor(0x00, 0xff, 0x00, 0x00));  // 全透明绿
setPalette(pal);

void MainWindow::paintEvent(QPaintEvent *)          // 挖一个 300x300 的洞
{
    QPainter p(this);
    p.setCompositionMode(QPainter::CompositionMode_Clear);
    p.fillRect(30, 30, 300, 300, Qt::SolidPattern);
}

挖洞这个用法必须叠在 WA_TranslucentBackground 之上，否则清出来的区域是黑的。

十、背景透明的坑 #

10.1 症状对照表 #

透明相关的 bug 长得都很像，按症状反查最快。

症状 原因 修法
半透明背景显示成黑块 没开 WA_TranslucentBackground，窗口表面没有 Alpha 通道 开属性，再用 paintEvent 画
阴影外圈糊一圈黑边 同上，阴影的 Alpha 像素被合成到黑色底上 同上
圆角设了没效果，四角还是直角 系统标题栏还在，方角是它画的 加 Qt::FramelessWindowHint
窗口透了，圆角处的鼠标点不到 命中测试按矩形算，不按像素算 setMask() 收窄，或 WA_TransparentForMouseEvents
子控件也跟着变淡 用了 setWindowOpacity 改用 WA_TranslucentBackground 加自绘
QSS 背景对自写 QWidget 无效 缺 WA_StyledBackground 开属性，或用 PE_Widget 自绘
整窗发黑、控件一片糊 paintEvent 里调了基类又把背景刷实了 QSS 与自绘二选一

10.2 黑块是怎么来的 #

最常见的现场：只写一句 QSS 就想做半透明窗口。

cpp
this->setStyleSheet("QMainWindow { background: rgba(0, 0, 0, 120); }");   // 跑起来一片黑
setAttribute(Qt::WA_TranslucentBackground, true);                          // 先换掉表面
setStyleSheet("QMainWindow { background: rgba(0, 0, 0, 120); }");

顶层窗口默认是不透明表面，QSS 里的 Alpha 只决定颜色怎么跟窗口底色混，底色是黑的，混完还是黑的。先把表面换成支持 Alpha 的，再谈颜色。

10.3 透明不等于点不中 #

窗口的鼠标命中测试走矩形区域，跟像素的 Alpha 无关。整块透明的地方照样挡住鼠标，底下那个窗口点不进去。

cpp
// 整个控件不接收鼠标，事件直接透给下面的兄弟控件
overlay->setAttribute(Qt::WA_TransparentForMouseEvents, true);

// 只让某一块区域可点，其余形状用遮罩切掉
setMask(QRegion(rect(), QRegion::RoundedRectangle));

setMask 是硬手段，遮罩边缘没有抗锯齿，圆角会看到锯齿。做不规则窗口时，遮罩与自绘要算同一套形状，否则会出现「看得见但点不到」或者「点得到但看着是空的」。

十一、阴影边框的实现 #

11.1 先说清 box-shadow #

QSS 的属性表里没有 box-shadow，也没有 text-shadow。你把网页那套抄过来，写了不报错、也不生效，白等半天。

要投影只有三条路，各自的账先算清：

做法 依赖 性能开销 动态调参 大尺寸缩放
九宫格切图 美术给 8 张 PNG 低，只做图案平铺 困难，得重新出图 支持，拉伸不变形
QGraphicsDropShadowEffect 无，纯代码 较高，跑模糊算法 容易，实时生效 差些，快速缩放会卡
paintEvent 手绘渐变 无，纯代码 中，取决于叠几层 容易，改个常量 支持

三条路都有一个共同前提，缺了它阴影会变成一圈黑块：

cpp
setWindowFlags(Qt::FramelessWindowHint | Qt::Dialog);   // 无边框
setAttribute(Qt::WA_TranslucentBackground);             // 背景透明，阴影的 Alpha 才有地方落

窗口固定、皮肤不换、要跑满帧：切图。要快速出效果、参数要动：特效类。既要轻又要能改：手绘。

11.2 路一：九宫格切图 #

一张标准阴影切图裁成 8 份：4 个角固定尺寸，4 条边拉伸填充。绘制时按窗口实际尺寸动态拼。

cpp
#define SHADOW_WIDTH 8   // 阴影边框占的像素宽度

void ShadowWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    const int w = width(), h = height(), s = SHADOW_WIDTH;

    // 切图：0-3 是四条边，4-7 是四个角
    QList<QPixmap> p;
    p << QPixmap(":/shadow/left.png") << QPixmap(":/shadow/right.png")
      << QPixmap(":/shadow/top.png")  << QPixmap(":/shadow/bottom.png")
      << QPixmap(":/shadow/left_top.png")    << QPixmap(":/shadow/right_top.png")
      << QPixmap(":/shadow/left_bottom.png") << QPixmap(":/shadow/right_bottom.png");

    // A. 四角：固定尺寸，不拉伸
    painter.drawPixmap(0, 0, s, s, p[4]);
    painter.drawPixmap(w - s, 0, s, s, p[5]);
    painter.drawPixmap(0, h - s, s, s, p[6]);
    painter.drawPixmap(w - s, h - s, s, s, p[7]);

    // B. 四边：拉伸填充
    painter.drawPixmap(0, s, s, h - 2 * s, p[0].scaled(s, h - 2 * s));
    painter.drawPixmap(w - s, s, s, h - 2 * s, p[1].scaled(s, h - 2 * s));
    painter.drawPixmap(s, 0, w - 2 * s, s, p[2].scaled(w - 2 * s, s));
    painter.drawPixmap(s, h - s, w - 2 * s, s, p[3].scaled(w - 2 * s, s));

    // C. 中间主体：四周各收缩 s，把阴影的位置让出来
    painter.fillRect(QRect(s, s, w - 2 * s, h - 2 * s), Qt::white);
}

切图方案跑起来几乎没有开销，就是若干次 drawPixmap。代价是改阴影颜色、改羽化半径、改圆角都得重新出图，换肤时最烦。

11.3 路二：QGraphicsDropShadowEffect #

Qt 自带的阴影特效，几行代码出一个高斯羽化投影。

cpp
QGraphicsDropShadowEffect *e = new QGraphicsDropShadowEffect(central);
e->setBlurRadius(15);                 // 羽化半径
e->setColor(QColor(0, 0, 0, 80));     // 颜色含 Alpha，RGBA
e->setOffset(0, 0);                   // 偏移量 (X, Y)
central->setGraphicsEffect(e);

参数都能实时改，setBlurRadius 一调立刻重算，做「拖拽时加深阴影」这种交互很省事。

它在顶层窗口上会失效，原因与修法在下一章。

11.4 路三：paintEvent 手绘渐变 #

不带任何资源，用同心矩形叠出软阴影：从窗口边缘往里收缩，每收缩 1px 就把画笔的 Alpha 降一档，Alpha 走 qSqrt 的梯度，边缘淡、中心浓。

cpp
#define SHADOW_PADDING 10   // 预留的外部阴影宽度

void DropShadowWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    // 1. 阴影边缘：由外向内逐层加深
    QColor shadowColor(0, 0, 0, 50);
    for (int i = 0; i < SHADOW_PADDING; ++i) {
        QPainterPath path;
        path.setFillRule(Qt::WindingFill);       // 嵌套路径能正常填充
        int offset = SHADOW_PADDING - i;
        path.addRect(offset, offset, width() - offset * 2, height() - offset * 2);

        int alpha = 150 - qSqrt(i) * 50;         // 二次方根梯度
        if (alpha < 0) alpha = 0;
        shadowColor.setAlpha(alpha);

        painter.setPen(shadowColor);
        painter.drawPath(path);
    }

    // 2. 主体背景：缩进 SHADOW_PADDING
    QPainterPath body;
    body.setFillRule(Qt::WindingFill);
    body.addRect(SHADOW_PADDING, SHADOW_PADDING,
                 width() - SHADOW_PADDING * 2, height() - SHADOW_PADDING * 2);
    painter.fillPath(body, QBrush(Qt::white));
}

想要圆角，把两处 addRect 换成 addRoundedRect，半径自定。这条路的参数全在代码里，改颜色改宽度不用碰资源文件。

十二、阴影与无边框窗口的组合 #

12.1 顶层窗口上挂特效为什么不显示 #

cpp
// 这么写，阴影不会出现
setGraphicsEffect(shadow);

顶层窗口的外围没有多余的像素空间，阴影要往外蔓延，却没地方画。特效被裁在窗口矩形里，看不见。

做法是套一层：外层窗口只负责撑出边距，内层控件才是真正的内容与阴影宿主。

cpp
// 1. 外层：无边框 + 背景透明，布局留 10px 边距给阴影
setWindowFlags(Qt::FramelessWindowHint | Qt::Dialog);
setAttribute(Qt::WA_TranslucentBackground);
QVBoxLayout *layout = new QVBoxLayout(this);
layout->setContentsMargins(10, 10, 10, 10);

// 2. 内层：真实内容与白底
QWidget *central = new QWidget(this);
central->setStyleSheet("background-color: white; border-radius: 4px;");
layout->addWidget(central);

// 3. 特效挂在内层，投影正好落在外层留出的边距里
QGraphicsDropShadowEffect *e = new QGraphicsDropShadowEffect(central);
e->setBlurRadius(15);
e->setColor(QColor(0, 0, 0, 80));
e->setOffset(0, 0);
central->setGraphicsEffect(e);

边距的大小要跟 blurRadius 对齐，10px 边距配 15px 羽化，边缘会被裁掉一点。稳妥的配比是边距略大于羽化半径。三件事的层次别搞混：WA_TranslucentBackground 决定能不能透，border-radius 或 drawRoundedRect 决定圆角形状，QGraphicsDropShadowEffect 决定投影，前两件做错，阴影再好看也白搭。

12.2 最小化还原后白屏 #

Windows 上开发无边框透明窗口，撞得最多的一个 bug：设了 FramelessWindowHint 加 WA_TranslucentBackground，最小化再还原，整窗白屏或黑屏，子控件不再重绘。这是 Qt 与 DWM 混合渲染时的老问题。

修法是接管 changeEvent，在还原的瞬间把窗口重新映射一次并强制重绘。

cpp
protected:
    void changeEvent(QEvent *event) override
    {
        if (event->type() == QEvent::WindowStateChange &&
            windowState() == Qt::WindowNoState) {
            setAttribute(Qt::WA_Mapped);   // 强制重映射底层窗口实例
            update();                      // 触发整窗重绘
        }
        QDialog::changeEvent(event);       // 交回基类
    }

WA_Mapped 平时由 Qt 自己维护，这里手动置上，等于告诉框架「窗口已重新上屏」。少了 update() 那一句，属性改了也不会重画。

十三、易错点速查 #

现象 病根 一句话修法
设了 QSS，按钮的按下反馈没了 绘制关键属性被接管 补齐 :hover / :pressed / :disabled
按钮 QSS 里写了边框，高度对不齐 border 撑了 sizeHint 加 min-height 固定高度
QLabel 的 text-align 无效 只有部分控件支持 用 padding 或 setAlignment
自写 QWidget 的背景色不生效 缺 WA_StyledBackground 开属性，或用 PE_Widget 自绘
窗口 QSS 背景把子控件也染了 规则命中子控件，不是继承 子控件补 background: transparent
半透明背景是黑的 窗口表面没有 Alpha 通道 开 WA_TranslucentBackground
圆角不生效 系统标题栏还在 加 FramelessWindowHint
透明区点不中下面的窗口 命中测试按矩形算 setMask 或 WA_TransparentForMouseEvents
子控件跟着整窗变淡 用了 setWindowOpacity 换背景透明那一层
box-shadow 写了没反应 QSS 没这个属性 切图、特效类、手绘三选一
顶层窗口的阴影不显示 外围没有像素空间 外层留边距，特效挂内层
最小化还原后白屏 Qt 与 DWM 的合成冲突 changeEvent 里补 WA_Mapped 加 update()
阴影外圈一圈黑边 窗口不透明，Alpha 被合成成黑 开 WA_TranslucentBackground

一句话收口：QSS 管绘制、QPalette 管角色色、paintEvent 管像素，透明与阴影都得先有支持 Alpha 的窗口表面。
