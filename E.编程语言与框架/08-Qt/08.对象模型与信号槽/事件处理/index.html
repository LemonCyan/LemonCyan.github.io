本篇讲 Qt 的事件机制：事件从哪来、按什么路径走、在哪一层被拦下来。

讲什么：QEvent 体系、event() 与具体事件处理器的分工、eventFilter 的返回值语义、accept 与 ignore、键盘与鼠标事件、QMouseEvent 的成员、自定义事件。

不讲什么：信号槽的连接语法与跨线程行为，见同目录《信号与槽》；QObject 的父子树与元对象系统，见《QObject 与对象模型》；Qt4 到 Qt5 的事件相关 API 变更，见《Qt4 到 Qt5 的迁移》。

先记住一句话：事件是「外部进来的输入」，信号是「内部出去的通知」。两套机制，拦截办法完全不同。

一、事件与信号的区别 #

先把结论摆出来：这两样不是同一层的东西，混着用迟早出问题。

维度 事件 信号
来源 窗口系统、Qt 内部、代码手动发送 对象状态变化时自己发出
触发者 事件循环从队列里取 发出方代码里的 emit
接收者 明确的目标对象，由事件循环指派 所有 connect 过的槽函数
传递形式 沿父子链冒泡，可逐层拒收 点对点扇出，没有冒泡
能否拦截 能。重写 event()、装 eventFilter、重写具体处理器 不能。emit 之后所有连接都会被调用
返回值 event() 返 bool，处理器里用 accept/ignore void，槽的返回值被忽略
时机 postEvent 异步入队，sendEvent 同步 默认直连同步；跨线程连接才走队列
典型用途 鼠标、键盘、绘制、拖放、定时器、尺寸变化 业务状态变更、控件对外通知

1.1 语义差异决定拦截方式 #

事件的本质是「请求被处理」。系统把「鼠标左键在 (12, 40) 按下」这件事交给你，你可以接、可以不接、可以改完再往下传。信号的本质是「事情已经发生」。发出方通知完就撒手，接收方接不接、怎么接，它管不着，也收不回。

这个差异直接决定了拦不拦得住。事件有几个固定的挂载点：event()、eventFilter()、具体处理器。信号没有挂载点，emit 一执行，连接表里每一对都跑一遍，中间没有关卡能让你把某一路掐掉。

cpp
// 想拦截子控件的按键，用信号做不到
connect(lineEdit, &QLineEdit::textChanged, this, &Widget::onTextChanged); // 只能事后通知
lineEdit->installEventFilter(this); // 这个才是拦截

跨线程的队列连接，底层确实靠投递事件（QMetaCallEvent）实现。那只是实现细节，对上层语义没影响，别拿这个去解释「信号就是事件」。

1.2 选哪个 #

判断标准很干脆：你要「让它别响应」，走事件；你要「响应之后做别的事」，走信号。

需求 走哪条路
屏蔽某个键、某个鼠标操作 事件。重写处理器或装过滤器
自定义控件的绘制、命中测试 事件。paintEvent、mousePressEvent
按钮点击后刷新列表 信号。clicked 连槽
输入框内容变了同步到另一个控件 信号。textChanged
全局监控某个按键 事件。装在 qApp 上的 eventFilter
跨线程通知工作线程收工 信号。队列连接

二、QEvent 体系 #

QEvent 是所有事件类的基类，装的是「发生了什么」，外加几个公共参数：类型、是否已被接受、是否来自窗口系统。事件循环由 QCoreApplication::exec() 拉起，从队列里取本机窗口系统事件，包装成对应的 QEvent 子类对象，再交给目标对象的 event()。

2.1 事件的三种来路 #

方式 接口 spontaneous() 特点
窗口系统自动投递 事件循环内部 true 真实用户交互产生
同步发送 QApplication::sendEvent() false 立即调用目标 event()，返回即处理完
异步发送 QApplication::postEvent() false 进事件队列，等下一轮循环

spontaneous() 用来区分「来自窗口系统」和「代码手动发的」。有些逻辑只该对真实输入生效，比如输入法行为、某些安全校验，靠它判断。

QObject::event() 是接收事件的入口。子类可以重写它处理自定义事件。QWidget 已经重写了 event()，用来把通用事件拆成一个个具体处理器。

2.2 公共部分与子类附加参数 #

基础 QEvent 只带类型，具体描述信息全在子类里：

事件子类 附加参数
QMouseEvent 鼠标位置、按键、按钮状态、修饰键
QKeyEvent 键码、修饰键、文本、是否自动重复
QWheelEvent 滚动增量、方向、像素精度（Qt5.15+）
QResizeEvent 新旧尺寸
QMoveEvent 新旧位置
QFocusEvent 获得还是失去焦点、原因
QDropEvent 拖放数据、位置、允许的动作

用的时候先用 type() 判类型，再 static_cast 成具体子类。Qt 的事件对象在传递过程中类型是确定的，这个向下转型是安全的。

cpp
bool MyWidget::event(QEvent *e) {
    if (e->type() == QEvent::KeyPress) {
        QKeyEvent *ke = static_cast<QKeyEvent *>(e);
        // 现在可以访问 ke->key()、ke->modifiers()
    }
    return QWidget::event(e);
}

2.3 常用事件类型 #

类型 触发时机 配对的处理器
KeyPress 键按下 keyPressEvent()
KeyRelease 键释放 keyReleaseEvent()
MouseButtonPress 鼠标键按下 mousePressEvent()
MouseButtonRelease 鼠标键释放 mouseReleaseEvent()
MouseButtonDblClick 双击 mouseDoubleClickEvent()
MouseMove 指针移动（需按键或开追踪） mouseMoveEvent()
Wheel 滚轮转动 wheelEvent()
Enter / Leave 指针进出控件边界 enterEvent() / leaveEvent()
HoverMove 悬浮移动（需 WA_Hover） event() 里处理
FocusIn / FocusOut 焦点进出 focusInEvent() / focusOutEvent()
Paint 需要重绘 paintEvent()
Resize / Move 尺寸、位置变化 resizeEvent() / moveEvent()
Close 窗口被要求关闭 closeEvent()
ContextMenu 右键菜单请求 contextMenuEvent()
Timer 定时器到期 timerEvent()
ShortcutOverride 快捷键抢占前的最后机会 event() 里处理
User 自定义事件起点 自己重写的 event()

User 是自定义类型的起始值，MaxUser 是上界。落在这个区间之外的编号归 Qt 自己用。

2.4 分发结构 #

text
窗口系统（真实输入）
  │
  └─ QCoreApplication::exec()          事件循环
       │
       └─ QCoreApplication::notify(receiver, event)
            │
            ├─ 装在 qApp 上的 eventFilter        ← 全局关卡
            │
            ├─ 目标对象的 eventFilter（后装的先跑） ← 对象关卡
            │
            ├─ 目标对象的 event()                ← 总入口
            │    │
            │    └─ 按 type() 分派
            │         ├─ KeyPress   → keyPressEvent()
            │         ├─ MousePress → mousePressEvent()
            │         ├─ Paint      → paintEvent()
            │         └─ 其它       → 对应处理器
            │
            └─ 未接受 → 冒泡给父控件

分层的好处很直接：

  1. 每种事件一个独立处理器，职责单一，不用在一个函数里塞几十个 if
  2. 新增事件类型不用动 Qt 源码，注册一个类型编号就能用
  3. 开发者按粒度选层，粗粒度重写 event()，细粒度重写具体处理器

事件对象归谁管，取决于用哪个发送接口，见 10.2 的对照表。

三、事件的传递路径 #

3.1 五个挂载点 #

这是本篇最该记牢的一张表。事件从进来到被消费，会依次经过五层：

层 挂载点 能拦到什么 侵入性
1 重写 QCoreApplication::notify() 全进程所有对象的所有事件 最高，要改应用类
2 装在 qApp 上的 eventFilter 同上 低，不用子类化
3 目标对象的 eventFilter 只有装了过滤器的那个对象 低
4 目标对象的 event() 目标对象的所有事件 中，需子类化
5 具体处理器 只有那一类事件 中，需子类化

顺序就是表的顺序。想在最前面掐掉，就往 1、2 层走；只想改某类事件的行为，第 4、5 层就够。

3.2 拦截粒度 #

event() 能拦到所有事件，具体处理器只能拦那一类。反过来，具体处理器写起来更省事，不用自己判类型再转型。

cpp
// 只关心按键 → 重写具体处理器
void MyEdit::keyPressEvent(QKeyEvent *e) {
    if (e->key() == Qt::Key_Escape) { clearSelection(); return; }
    QLineEdit::keyPressEvent(e);
}

cpp
// 想同时改按键和鼠标 → 重写 event()
bool MyEdit::event(QEvent *e) {
    if (e->type() == QEvent::KeyPress) { /* ... */ }
    else if (e->type() == QEvent::MouseButtonPress) { /* ... */ }
    return QLineEdit::event(e);
}

3.3 冒泡 #

鼠标、滚轮、上下文菜单这类事件，在目标对象没有接受时，会沿父控件链往上找：

text
子控件 mousePressEvent()  →  ignore()
        ↓
父控件 mousePressEvent()  →  ignore()
        ↓
祖父控件 mousePressEvent() →  accept()  → 结束

键盘事件不走这条路。它有焦点机制：谁有焦点谁收，收不到就是收不到，不会上浮给父控件。想让父窗口兜住按键，得在父窗口装过滤器，或者用 QShortcut。

四、event() 与事件处理器 #

event() 是总入口。控件收到的每个事件都先进这里，它读 type() 再分派给具体处理器。搞清这两层的分工，后面所有拦截都能对号入座。

4.1 层次关系 #

层 函数 覆盖范围 什么时候重写
总入口 event(QEvent *) 该对象的所有事件 要同时管多类事件，或在分派之前拦下某类
分派 内部 switch，不可见 — 不用管
具体处理器 keyPressEvent() 等 只有那一类 只改一类事件的行为
兜底 父类同名实现 默认处理 一定要调，除非明确要截断

关键一点：具体处理器是被 event() 调起来的。你在 event() 里对该类型 return true，具体处理器压根不会执行。反过来，重写具体处理器不会影响其它类型的事件，因为 event() 里其余分支照常走。

4.2 重写 event() #

下面这段给编辑器加 Tab 缩进。Tab 默认是切焦点，必须在分派前截走：

cpp
bool MyEditor::event(QEvent *e) {
    if (e->type() == QEvent::KeyPress) {
        QKeyEvent *ke = static_cast<QKeyEvent *>(e);
        if (ke->key() == Qt::Key_Tab) {
            insertPlainText(QStringLiteral("\t"));
            return true;              // 已处理，停止传递
        }
    }
    return QTextEdit::event(e);       // 其余事件交给父类
}

返回值只有两种含义：

返回 含义 后果
true 事件已处理 停止传递，父类不再看到
false 事件未处理 继续交给父类

最后那行 return QTextEdit::event(e); 别省。省掉的直接后果是控件失去全部默认行为：光标不闪、文字选不中、拖不动滚动条，因为键盘和鼠标事件全被你的 return false 或 return true 截断了。

4.3 重写具体处理器 #

只改一类事件时，直接重写对应处理器更短。下面把空格键当 Tab 用，切换焦点：

cpp
void MyLineEdit::keyPressEvent(QKeyEvent *e) {
    if (e->key() == Qt::Key_Space) {
        focusNextChild();             // 切到下一个子控件
    } else {
        QLineEdit::keyPressEvent(e);  // 不处理，还给父类
    }
}

注意这里的表达方式和 event() 不一样：处理器返回 void，它靠 accept/ignore 说明「我处理了没有」，不靠返回值。

4.4 怎么选 #

场景 推荐
只处理单一事件类型 重写具体处理器
同时处理多种事件类型 重写 event()
要在分派之前做预处理或拦截 重写 event()
要处理 Qt 没有专属处理器的类型（如 HoverMove） 重写 event()
不想子类化目标控件 用 eventFilter

4.5 return false 的陷阱 #

cpp
// 反例
bool MyWidget::event(QEvent *e) {
    if (e->type() == QEvent::KeyPress) { /* ... */ return true; }
    return false;                    // ← 所有非按键事件都被吞了
}

return false 不等于「交回父类」，它只表示「没人处理」。要交给父类，得显式调 QWidget::event(e)，把它的返回值返回出去。

五、事件过滤器 eventFilter #

eventFilter() 让你在事件抵达目标对象之前插手。跨控件监听走这条路，不用为了看一眼事件就去子类化对方的控件。

5.1 安装 #

声明写在头文件的 protected 区：

cpp
protected:
    bool eventFilter(QObject *obj, QEvent *e) override;

安装写在构造函数里：

cpp
Xxx::Xxx() {
    combox = new QComboBox(this);
    combox->installEventFilter(this);          // 监视 comboBox 本身
    combox->view()->installEventFilter(this);  // 监视它的下拉视图
}

下拉列表是独立的顶层窗口，不属于 combox 的子控件，所以必须给 view() 单独装一次。只装前一行，下拉列表里按方向键不会有反应。这类「漏装」排查起来最费时间。

5.2 返回值语义 #

这是本篇第二个要背下来的东西。搞反了只有两种结果：事件全被吃掉，或者完全不起作用。

返回 含义 后续
true 我处理了，别再往下传 后面的过滤器不执行，目标对象的 event() 也不执行
false 我不动，继续 交给下一个过滤器，最终进目标 event()

记住方向：true 是「拦死」，false 是「放行」。不是「成功/失败」，是「拦住/放行」。

5.3 完整实现 #

一个过滤器同时盯两个对象时，必须先按 obj 分流，再决定返回什么：

cpp
bool TimeWindows::eventFilter(QObject *obj, QEvent *e) {
    if (e->type() == QEvent::KeyRelease) {
        QKeyEvent *ke = static_cast<QKeyEvent *>(e);

        if (obj == combox->view()) {
            if (ke->key() == Qt::Key_Up) {
                handleUpKey();
                return true;          // 下拉列表的方向键，在此吃掉
            }
        } else if (obj == combox) {
            if (ke->key() == Qt::Key_Y) {
                handleYKey();
                return true;
            }
        }
    }
    return QObject::eventFilter(obj, e);  // 其余放行
}

末尾调 QObject::eventFilter(obj, e) 而不是 return false，是为了不打断基类的默认处理。两者在多数情况下等价，但基类实现有变化时，调基类更稳。

5.4 多个过滤器的顺序 #

一个对象可以装多个过滤器，后装的先执行。装 A 再装 B，事件先到 B 再到 A。

cpp
w->installEventFilter(a);  // 后跑
w->installEventFilter(b);  // 先跑

只要其中任何一个返回 true，后面的都不再执行，目标对象也收不到。排查「过滤器没反应」时，先确认前面是不是有人把它拦掉了。

5.5 线程约束 #

过滤器对象必须和目标对象在同一线程。跨线程装过滤器不会被拒绝，但事件到达时行为不确定，别这么写。

5.6 全局过滤器 #

把过滤器装到 qApp 上，等于监视全进程所有对象的事件：

cpp
qApp->installEventFilter(this);

cpp
bool AppWatcher::eventFilter(QObject *obj, QEvent *e) {
    if (e->type() == QEvent::MouseButtonPress) {
        qDebug() << "press on" << obj->metaObject()->className();
    }
    return QObject::eventFilter(obj, e);  // 只观察，不拦
}

常见用途是全局快捷键、调试期打印事件流、屏蔽某类输入。代价明确：进程里每个事件都要过一遍你的函数，里面别做重活，也别在里面弹窗或跑事件循环。

5.7 对比 #

特性 事件过滤器 重写事件处理器
作用范围 任意对象，一个过滤器可管多个 仅限本对象
侵入性 不用子类化目标控件 必须子类化
适用场景 跨控件统一处理 单控件定制行为
表达是否处理 返回 bool 调 accept() / ignore()
性能开销 略高，每事件一次额外调用 较低

六、事件的接受与忽略 #

6.1 accept 与 ignore #

cpp
event->accept();  // 我要了，到此为止
event->ignore();  // 我不要，往上传

QEvent 构造时默认是已接受状态。但 QWidget 的具体处理器在没处理时，会显式调 ignore()，把球踢出去。

6.2 哪些会冒泡 #

事件 QWidget 默认 说明
MouseButtonPress ignore() 非 popup 时向上冒泡到父控件
MouseButtonRelease ignore() 同上
MouseMove ignore() 同上
Wheel ignore() 同上
ContextMenu ignore() 冒泡到父控件弹菜单
KeyPress ignore() 不冒泡，转给快捷键系统
Close accept() 默认允许关闭，窗口随后隐藏或销毁
Paint accept() 不参与冒泡

键盘事件是特例。它在处理器里被 ignore() 之后不是上浮给父控件，而是交给 QShortcutMap 匹配快捷键。

6.3 accept 不是返回值 #

event() 的 bool 返回值和 accept 状态是两套东西，别混着理解：

  • 处理器返回 void，用 accept()/ignore() 表达是否消费
  • event() 返回 bool，Qt 用它决定是否继续向父类/父控件传递

在两个地方用错，症状很像，都是「该拦的没拦住」。

6.4 closeEvent 里的否决 #

cpp
void Editor::closeEvent(QCloseEvent *e) {
    if (isModified() && !maybeSave()) {
        e->ignore();   // 用户取消，窗口留着
        return;
    }
    e->accept();
}

ignore() 直接取消关闭。maybeSave() 里弹的是模态对话框，跑的是嵌套事件循环，这在这里是合法的，但别在 eventFilter 里这么干。

七、键盘事件 #

cpp
#include <QKeyEvent>

7.1 前提是焦点 #

键盘事件只投给有焦点的控件。没有焦点，一个键都收不到。这是「我重写了 keyPressEvent 却不触发」的第一嫌疑。

cpp
setFocusPolicy(Qt::StrongFocus);  // 点击可得 + Tab 可得
策略 点击获得焦点 Tab 获得焦点
Qt::NoFocus 否 否
Qt::TabFocus 否 是
Qt::ClickFocus 是 否
Qt::StrongFocus 是 是
Qt::WheelFocus 是 是（滚轮也可）

控件默认策略是 Qt::StrongFocus，但 QLabel、纯展示类的控件默认是 NoFocus，想收键盘事件得自己改。

7.2 QKeyEvent 的成员 #

成员 类型 说明
key() int 键码，与 Qt::Key_* 比较
modifiers() 位掩码 Ctrl、Shift、Alt、Meta、Keypad
text() QString 该键产生的文本，组合键时为空
isAutoRepeat() bool 是否为长按产生的重复事件
count() int 事件关联的字符数

key() 给的是物理键位，text() 给的是实际输入的字符。判断「是不是按了 A 键」用 key()；拿到用户打出来的内容用 text()。

7.3 keyPressEvent #

cpp
void Widget::keyPressEvent(QKeyEvent *e) {
    if (e->modifiers() & Qt::ControlModifier) {   // 组合键：Ctrl + M
        if (e->key() == Qt::Key_M) {
            handleCtrlM();
            return;
        }
    }

    if (e->key() == Qt::Key_Up) {
        if (e->isAutoRepeat()) return;            // 忽略长按重复
        keyUp = true;
    } else if (e->key() == Qt::Key_Left) {
        if (e->isAutoRepeat()) return;
        keyLeft = true;
    } else {
        QWidget::keyPressEvent(e);                // 未处理，还给父类
    }
}

isAutoRepeat() 的用处：长按会连发 KeyPress。要区分「首次按下」和「持续按住」，用它在入口过滤掉重复事件，否则方向键会以极快速度刷屏。

7.4 keyReleaseEvent #

cpp
void Widget::keyReleaseEvent(QKeyEvent *e) {
    if (e->key() == Qt::Key_Up) {
        if (e->isAutoRepeat()) return;
        keyUp = false;                            // 标记已释放
    } else if (e->key() == Qt::Key_Left) {
        if (e->isAutoRepeat()) return;
        keyLeft = false;
    } else {
        QWidget::keyReleaseEvent(e);
    }
}

释放事件同样会因长按重复触发，isAutoRepeat() 在两边都要判。漏了释放侧的判断，会出现「松手了但状态被重复置位」的怪现象。

7.5 switch 处理多键 #

按键超过三个，if-else 会很难看，换 switch：

cpp
void TimeWindows::keyReleaseEvent(QKeyEvent *e) {
    switch (e->key()) {
        case Qt::Key_Up:    handleUp();    break;
        case Qt::Key_Down:  handleDown();  break;
        case Qt::Key_Left:  handleLeft();  break;
        case Qt::Key_Right: handleRight(); break;
        default:            QWidget::keyReleaseEvent(e); break;
    }
}

default 分支一定要还回父类，否则所有没列出的键都被吃掉了，包括 Tab 和 Esc。

7.6 修饰键用按位与 #

cpp
// 错：用户按 Ctrl+Shift+M 时匹配不上
if (e->modifiers() == Qt::ControlModifier)

// 对：只要含 Ctrl 就进分支
if (e->modifiers() & Qt::ControlModifier)

modifiers() 是位掩码，== 要求完全相等。小键盘上的键还会带上 Qt::KeypadModifier，用 == 判断会在小键盘上莫名其妙失效。

7.7 快捷键抢在前面 #

QShortcut、QAction 的快捷键在 keyPressEvent 之前匹配。控件收不到某个键，常常不是代码问题，是快捷键先截走了。

要抢回来，在 event() 里处理 QEvent::ShortcutOverride：

cpp
bool MyEdit::event(QEvent *e) {
    if (e->type() == QEvent::ShortcutOverride) {
        QKeyEvent *ke = static_cast<QKeyEvent *>(e);
        if (ke->key() == Qt::Key_Delete && ke->modifiers() == Qt::NoModifier) {
            e->accept();     // 声明我要自己处理，别走快捷键
            return true;
        }
    }
    return QTextEdit::event(e);
}

八、鼠标事件 #

cpp
#include <QMouseEvent>

QMouseEvent 管按下、释放、移动、双击。滚轮不归它管，是 QWheelEvent。

8.1 触发条件 #

事件 触发条件
按下 / 释放 鼠标按键状态改变
移动（默认） 按住某个键并移动
移动（追踪模式） 指针移动就触发，不用按键

8.2 鼠标追踪 #

默认只在按住键时发 MouseMove。要做悬停高亮、跟随提示，必须打开追踪：

cpp
setMouseTracking(true);   // 不按键也收 mouseMoveEvent

只想管「指针进出边界」，别用追踪模式，改成 setAttribute(Qt::WA_Hover)。它发 Enter、Leave、HoverMove 三种，频率低得多。

8.3 传递机制 #

鼠标事件沿控件父子链往上走，直到被接受：

text
子控件 mousePressEvent()   → ignore()
        ↓
父控件 mousePressEvent()   → ignore()
        ↓
祖父控件 mousePressEvent() → accept()  → 事件处理完成

三条控制手段：

  • accept()：接受，停止传递
  • ignore()：忽略，继续向父控件传
  • Qt::WA_NoMousePropagation：无论接受与否，都不往上走

8.4 按下 #

cpp
void Widget::mousePressEvent(QMouseEvent *e) {
    if (e->button() == Qt::LeftButton) {
        startDrag(e->pos());
    } else if (e->button() == Qt::RightButton) {
        showContextMenu(e->globalPos());
    }
}

按下事件里 button() 才有意义，它告诉你哪个键刚被按下。移动事件里这个值是 Qt::NoButton，要看 buttons()。

8.5 移动 #

cpp
void Widget::mouseMoveEvent(QMouseEvent *e) {
    // buttons() 是复数，返回位掩码，必须按位与判断
    if (e->buttons() & Qt::LeftButton) {
        updateDragPosition(e->pos());
    }
}

拖拽时按住两个键的情况不少见，用 == 比较会漏掉组合。

8.6 释放 #

cpp
void Widget::mouseReleaseEvent(QMouseEvent *e) {
    if (e->button() == Qt::LeftButton) {
        endDrag();
    }
}

8.7 双击 #

cpp
void Widget::mouseDoubleClickEvent(QMouseEvent *e) {
    if (e->button() == Qt::LeftButton) {
        selectWord();     // 双击选词
    }
}

双击的事件序列是：

text
Press → Release → DoubleClick → Release

注意它前面带着一套完整的按下和释放。如果 mousePressEvent 里已经做了「单击处理」，双击时会先触发一次单击行为。要区分单双击，得靠定时器延迟，别指望 Qt 帮你判。

8.8 滚轮 #

滚轮用 QWheelEvent：

cpp
void Widget::wheelEvent(QWheelEvent *e) {
    const int dy = e->angleDelta().y();
    if (dy > 0) {
        zoomIn();                 // 向前滚，远离用户
    } else if (dy < 0) {
        zoomOut();                // 向后滚，朝向用户
    } else {
        QWidget::wheelEvent(e);
    }
}

Qt5.15 之前用 delta()，Qt6 已移除，改 angleDelta()。老代码迁移时这是必改项。angleDelta() 的单位是 1/8 度，一格滚轮是 120。

触控板的像素级滚动看 pixelDelta()，它在部分平台上为空。

8.9 右键菜单 #

cpp
void Widget::contextMenuEvent(QContextMenuEvent *e) {
    QMenu menu(this);
    menu.addAction(tr("复制"));
    menu.exec(e->globalPos());
}

ContextMenu 事件受 contextMenuPolicy 控制。默认值 Qt::DefaultContextMenu 才会调这个函数；换成 Qt::CustomContextMenu 是发 customContextMenuRequested 信号；Qt::NoContextMenu 是交给父控件。策略设错，contextMenuEvent() 一行都不执行。

九、QMouseEvent 的成员 #

9.1 坐标获取 #

函数 返回类型 说明
pos() QPoint 相对当前窗口的整型坐标
posF() QPointF 相对当前窗口的浮点坐标
x() / y() int 等价于 pos().x() / pos().y()
globalPos() QPoint 屏幕全局坐标
globalX() / globalY() int 等价于 globalPos().x() / globalPos().y()

9.2 button 与 buttons #

函数 语义 典型场景
button() 触发本次事件的那个键 按下、释放、双击
buttons() 事件发生时所有按下的键（位掩码） 移动、拖拽

释放时，button() 是刚松开的那个，而 buttons() 里已经不含它了。这个时间差是很多「松开判断失效」的根源。

9.3 全局坐标的用处 #

拖动窗口时用 globalPos() 算新位置，用 pos() 会抖：

cpp
void Widget::mouseMoveEvent(QMouseEvent *e) {
    if (isDragging) {
        QPoint newPos = e->globalPos() - dragStartOffset;
        move(newPos);
    }
}

抖的原因：pos() 相对窗口自身，窗口一移动坐标系跟着动，算出来的偏移又变，形成正反馈。globalPos() 相对屏幕，基准固定，环路就断了。

9.4 坐标转换 #

cpp
QPoint globalPoint = mapToGlobal(localPoint);     // 窗口坐标 → 全局坐标
QPoint localPoint  = mapFromGlobal(globalPoint);  // 全局坐标 → 窗口坐标

注意这两个是 QWidget 的成员，坐标系原点在控件左上角。层级深的时候，还有 mapToParent() 和 mapTo() 用于跨控件换算。

9.5 Qt6 改名对照 #

Qt5 Qt6
pos() position()，返回 QPointF
posF() position()
globalPos() globalPosition()
x() / y() position().x() / position().y()
delta() angleDelta()
windowPos() scenePosition()

Qt6 保留了 pos() 的兼容重载，但新代码直接用浮点版本。高 DPI 缩放比例下整数坐标会丢精度，做精确对齐、画布定位时用浮点。globalX()、globalY()、x()、y() 这些 Qt3 时代的便捷函数在 Qt6 里已移除或标记弃用，按上表换掉。

十、自定义事件 #

Qt 的预定义类型够用就不折腾。要往事件队列里塞自己的消息，就得自定义。

10.1 定义类型编号 #

cpp
class ProgressEvent : public QEvent {
public:
    explicit ProgressEvent(int v)
        : QEvent(typeId()), value(v) {}

    static QEvent::Type typeId() {
        static const QEvent::Type t =
            static_cast<QEvent::Type>(QEvent::registerEventType());
        return t;
    }

    int value;
};

两条路：

编号来源 写法 风险
手工偏移 QEvent::User + 1 与第三方库撞号，症状诡异
运行时注册 QEvent::registerEventType() 线程安全，自动避开占用值

User 到 MaxUser 之间的编号归应用层用，落在区间外的会被 Qt 自行分配。手工偏移在多模块工程里撞号概率不低，用 registerEventType() 省事。

10.2 发送 #

cpp
// 同步：立即调用目标 event()，返回后处理完
ProgressEvent ev(42);
QApplication::sendEvent(worker, &ev);

// 异步：入队，等下一轮事件循环
QApplication::postEvent(worker, new ProgressEvent(42));
方式 时机 事件对象所有权 线程安全
sendEvent() 同步，立即执行 调用方，可用栈对象 否
postEvent() 异步，排队 事件队列，必须 new 是

跨线程必须 postEvent()。sendEvent() 会在调用线程里直接跑目标对象的 event()，目标对象如果属于 GUI 线程，就变成了跨线程操作控件，崩得没规律。

10.3 接收 #

自定义类型没有专属处理器，只能重写 event()：

cpp
bool Worker::event(QEvent *e) {
    if (e->type() == ProgressEvent::typeId()) {
        auto *pe = static_cast<ProgressEvent *>(e);
        updateProgress(pe->value);
        return true;                      // 已消费
    }
    return QObject::event(e);             // 其余交回父类
}

typeId() 写成函数内的静态局部变量，C++11 起保证只初始化一次，多线程调用安全。

10.4 与信号的分工 #

两者都能跨线程送消息，选择标准看「要不要拦截」：触发一个业务动作、接收方可有可无、要多个接收方同时响应，用信号；必须送到指定对象、要装过滤器统一观察、要和输入事件一起排队按序处理，用事件。

十一、事件的性能与陷阱 #

事件处理全跑在 GUI 线程上。你在这里多花一毫秒，界面就卡一毫秒。

11.1 鼠标移动是洪水 #

指针一动就是一批 MouseMove，一秒能来上百个。处理器里只记状态，重活交给定时器或脏区合并：

cpp
void Canvas::mouseMoveEvent(QMouseEvent *e) {
    lastPos = e->pos();     // 只记坐标
    update();               // 标脏，真正重绘由事件循环合并
}

11.2 update() 与 repaint() #

接口 时机 是否合并
update() 异步，等循环空闲 会，同轮多次只发一次 paintEvent
repaint() 同步，立刻执行 不会

循环里连调 repaint() 等于自己造了个忙等，CPU 直接拉满。刷新界面一律用 update()。

11.3 postEvent 积压 #

投递速度超过处理速度，队列只涨不消，内存和延迟一起飞。限流靠标志位：已投递就不再投，处理完复位。

11.4 全局过滤器的代价 #

装在 qApp 上的过滤器，每个事件都要过一次。里面做字符串比较、qobject_cast、动态属性查询，全进程跟着慢。调试期开，上线留一个能关掉的开关。

11.5 处理器里 delete this #

cpp
delete this;      // 错：处理器返回后 Qt 还要碰 this
deleteLater();    // 对：投递 DeferredDelete，回到事件循环再删

同一个坑还有另一种形态：处理器里 emit 一个信号，槽里把本对象删了，返回时同样是野指针。跨对象删除一律走 deleteLater()。

11.6 防重入 #

处理器里弹模态对话框会起嵌套事件循环，外面的事件照样进来。设个标志位，入口判断，用完复位。sendEvent() 给同一个对象发同类事件，会直接构建无限递归。

十二、易错点速查 #

现象 根因 修法
重写了 keyPressEvent() 不触发 控件没有键盘焦点 setFocusPolicy(Qt::StrongFocus) + setFocus()
控件失去全部默认行为 event() 没调父类 return Base::event(e)
事件全被吃掉 过滤器里无脑 return true 按 obj、type 分流，其余放行
过滤器完全不生效 装给了错误的对象 installEventFilter() 要装到目标本身
下拉列表方向键没反应 漏给 view() 装过滤器 单独装一次
Ctrl+Shift 组合键失配 用 == 比 modifiers() 改成按位与 &
长按方向键状态乱 漏判 isAutoRepeat() 按下、释放两侧都要判
某个键彻底没响应 快捷键先截走了 处理 ShortcutOverride 并 accept()
拖动窗口抖动 用 pos() 算新位置 改 globalPos()
双击先触发一次单击 双击序列含完整按下/释放 定时器延迟区分
鼠标移动收不到 未开追踪 setMouseTracking(true) 或 WA_Hover
滚轮无输出 Qt6 里用了 delta() 改 angleDelta()
自定义事件收不到 没重写 event() 自定义类型没有专属处理器
父子控件都响应鼠标 冒泡没阻断 accept() 或 WA_NoMousePropagation
删了控件后崩溃 处理器里 delete this deleteLater()
跨线程操作控件崩溃 用了 sendEvent() 改 postEvent()
父子对象都装着过滤器 顺序记反 后装的先执行

这张表覆盖不到所有情况，但能挡掉大多数「明明写了却不生效」的现场。排查顺序永远是：先确认目标对象有没有收到事件（在 event() 里打日志），再确认有没有人先把它拦了（逐个摘掉过滤器），最后才怀疑自己的判断逻辑。
