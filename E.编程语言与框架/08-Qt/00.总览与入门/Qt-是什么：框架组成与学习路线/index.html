一、Qt 是什么 #

一句话：Qt 是一套用 C++ 写跨平台应用的完整开发体系。「完整」这个词是重点，它盖住的不止一层。

三样东西，缺一样就用不顺 #

  • 一套 C++ 框架：几十个类库，从字符串、容器到窗口、网络、数据库全覆盖。
  • 一套构建工具：moc、uic、rcc 三个预处理程序，加上 qmake 或 CMake 的 Qt 集成。
  • 一个元对象系统：给 C++ 补上运行期类型信息，信号槽、属性、反射全靠它。
组成 具体是什么 少了它会发生什么
框架 QObject、QString、容器、控件、网络、SQL 等类 只剩裸 C++，界面得自己调 Win32 / X11 / Cocoa
构建工具 moc、uic、rcc、qmake / CMake 集成、windeployqt 信号槽编译不过，.ui 文件变不成 C++ 代码，图片资源加载不到
元对象系统 Q_OBJECT 宏 + moc 生成的 qt_meta_data_ 数组 + QMetaObject connect 无表可查，反射、属性系统、invokeMethod 全部失效

多数人只学了第一层。控件摆得出来，API 背得出来，一到「为什么信号只写声明不写实现」「为什么 connect 里要写 &QPushButton::clicked」就卡住。卡点在第三层，不在 API。

最小可运行程序 #

不依赖 Designer，也不依赖 .ui 文件，一个完整程序就这么长：

cpp
#include <QApplication>
#include <QLabel>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QLabel label(QStringLiteral("你好，Qt"));
    label.resize(320, 120);
    label.show();
    return app.exec();
}

同目录配一个 CMakeLists.txt：

bash
cmake_minimum_required(VERSION 3.16)
project(hello LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_AUTOMOC ON)     # 少了它，带 Q_OBJECT 的类链接时报 vtable 未定义
set(CMAKE_AUTOUIC ON)     # .ui 自动交给 uic
set(CMAKE_AUTORCC ON)     # .qrc 自动交给 rcc
find_package(Qt6 REQUIRED COMPONENTS Widgets)
add_executable(hello main.cpp)
target_link_libraries(hello PRIVATE Qt6::Widgets)

bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/gcc_64
cmake --build build
./build/hello

三个要点：QApplication 初始化窗口系统并持有事件循环；show() 之后窗口并不立刻出现在屏幕上；app.exec() 才是开始分发事件的地方。把最后一行改成 return 0;，窗口一闪而过。

一个 Widgets 工程的四个文件 #

文件 角色 谁生成
main.cpp 程序入口，实例化主窗体并 show() 模板生成，手写维护
mainwindow.ui XML 格式的界面描述，Designer 可视化拖拽 Designer 存盘
mainwindow.h 类声明，含 Q_OBJECT 与 Ui::MainWindow *ui 模板生成，手写维护
mainwindow.cpp 业务逻辑实现 模板生成，手写维护

头文件里那根指针长这样：

cpp
namespace Ui { class MainWindow; }

class MainWindow : public QMainWindow
{
    Q_OBJECT
public:
    explicit MainWindow(QWidget *parent = nullptr);
    ~MainWindow();
private:
    Ui::MainWindow *ui;
};

构建时 uic 把 .ui 编译成 ui_mainwindow.h，在 Ui 命名空间里定义同名类，内含 setupUi(QWidget *parent)。构造函数第一句就调它：

cpp
MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent), ui(new Ui::MainWindow)
{
    ui->setupUi(this);   // 到这里，控件才被 new 出来并挂到 this 上
}

后台代码只能走 ui->controlName，不能写 this->controlName。原因很直白：控件对象是 setupUi 里创建的，MainWindow 本身没有这些成员。

.ui 只是中间描述，不是运行期结构。改了 .ui 看不到变化，先查两件事：构建目录里的 ui_*.h 有没有重新生成，CMAKE_AUTOUIC 或 QT += widgets 有没有生效。

IDE 与构建工具选型 #

选择 优势 短板
Qt Creator 跨平台，内置 Designer，F1 直接查官方文档，信号槽自动生成 大型 C++ 工程的调试体验弱于 VS
VS + Qt 插件 调试器成熟，Windows 平台顺手 信号槽要手写，中文编码坑更多，工程迁移麻烦

新手期直接用 Qt Creator，文档即查即用这一条能省掉大量搜索时间。要和 Windows 侧代码混编时再切 VS。

构建工具这边，.pro 是 qmake 的描述文件，Qt 5 时代的默认；Qt 6 起官方主推 CMake，QT += core gui widgets 对应 Qt6::Core Qt6::Gui Qt6::Widgets。新工程选 CMake，老工程不必急着迁，迁移踩坑归到「打包部署与工程实践」。

二、Qt 的模块划分 #

Qt 不是一个巨大的单体库，它是几十个模块的集合，按依赖层层往上叠。

分层结构 #

text
        ┌────────────────────────────────────────────┐
        │  路线 A：QtWidgets —— 命令式 C++ 写界面      │
        │  路线 B：QtQuick + QML —— 声明式写界面       │
        └───────────────────┬────────────────────────┘
                            │ 都依赖
        ┌───────────────────▼────────────────────────┐
        │  QtGui：窗口系统、2D 绘制、字体、图像、OpenGL│
        └───────────────────┬────────────────────────┘
                            │ 依赖
        ┌───────────────────▼────────────────────────┐
        │  QtCore：对象模型、容器、事件循环、线程、IO  │
        └────────────────────────────────────────────┘

三条必须记住的关系：

  • QtCore 是根，不含任何 GUI 代码。控制台程序、服务端程序、无屏设备，只链 QtCore 就够。
  • QtGui 依赖 QtCore，管窗口系统集成、绘制原语、字体、图像这些底层能力，它自己不做控件。
  • QtWidgets 与 QtQuick 是两条并行路线，都长在 QtGui 之上，谁也不替代谁。选一条走到底，不要混着学。

按需取模块 #

模块不是全装全链，用到哪个加哪个：

bash
find_package(Qt6 REQUIRED COMPONENTS Core Gui Widgets Network Sql)   # CMake
target_link_libraries(app PRIVATE
    Qt6::Core Qt6::Gui Qt6::Widgets Qt6::Network Qt6::Sql)

QT += core gui widgets network sql                                   # qmake

链接了没用的模块，代价是二进制变大、启动时多加载几个动态库。发布前用 windeployqt 或 macdeployqt 扫一遍依赖，多余的剔掉。

三、Qt Core：一切的基础 #

QtCore 是所有 Qt 程序的底座。不管最后走 Widgets 还是 Quick，这一层都得先吃透。

QObject 与对象树 #

QObject 提供四样东西：父子对象关系、信号槽、事件分发、运行期类型信息。任何要享受这四样的类，都得继承它并在类首行写 Q_OBJECT。

父子关系换来的是自动回收：

cpp
QWidget *panel = new QWidget;
QPushButton *btn = new QPushButton(panel);   // 指定 parent
QLabel *tip = new QLabel(panel);             // 同一个 parent

delete panel;   // btn 与 tip 一起被 delete，不用手动管

规则很硬：继承自 QObject 的对象，构造时指定了 parent，父对象析构时子对象全部跟着走。栈上对象、std::unique_ptr 管理的对象不要设 parent，否则会被删两次。

事件循环里不能直接 delete 一个 QObject，槽函数里删掉正在派发事件的对象会让事件循环踩到野指针。用 deleteLater()，它把删除排到当前事件循环结束后执行：

cpp
connect(worker, &QObject::destroyed, this, &MainWindow::onWorkerGone);
worker->deleteLater();

容器 #

Qt 自带一套容器，接口比 STL 顺手，且全部隐式共享（写时复制）。

cpp
QList<QString> list;
list << "Apple" << "Banana" << "Cherry";   // << 追加，等同于 append
qDebug() << list.size() << list.at(0);

QMap<QString, int> map;                    // 按 key 排序
map["Apple"] = 5;
for (auto it = map.constBegin(); it != map.constEnd(); ++it)
    qDebug() << it.key() << it.value();

QSet<int> set;                             // 哈希集合，无序去重
set << 1 << 2 << 3 << 3;                   // size() 得到 3
容器 底层 适用场景
QList 连续数组（Qt 6）/ 指针数组（Qt 5） 默认选它，随机访问快，尾部追加快
QMap 红黑树 需要按 key 有序遍历
QHash 哈希表 只按 key 查，不关心顺序
QSet 哈希集合 去重、判存在

隐式共享意味着拷贝一个 QList 是 O(1)，没人写就不真复制。代价是非 const 迭代器会触发 detach，循环里要改元素就用 for (auto &x : list)。

QString 与编码 #

QString 内部是 UTF-16，一个 QChar 占两字节。转换点只有几个：

cpp
QString s = QString::fromUtf8("中文");        // 从 UTF-8 字节
QByteArray b = s.toUtf8();                   // 转回 UTF-8 字节
QString n = QString::number(3.14);
int i = s.toInt();                           // 失败返回 0
QString f = QStringLiteral("编译期常量");     // 字面量，零运行期开销

C++ 源文件里的中文字面量，跨平台一致的做法是源文件存 UTF-8 无 BOM，构建时加 -utf-8 或 /utf-8。Windows 上 MSVC 不指定编码会按本地代码页解析，中文直接变问号。

QVariant：万能数据包裹 #

所有通用控件的数据接口都吃 QVariant。它能包 QString、int、double，也能包 QPoint、QRect、QColor。自定义类型要先声明元类型：

cpp
struct Person
{
    int id;
    QString name;
};
Q_DECLARE_METATYPE(Person)   // 必须写在类定义之外、全局作用域

Person p{1001, QStringLiteral("张三")};
QVariant var = QVariant::fromValue(p);   // 包进去
Person back = var.value<Person>();       // 取出来

漏了 Q_DECLARE_METATYPE 的报错信息很长，关键词是 static_assert 与 Type is not registered。看到这个先查宏写没写、写的位置对不对。

事件循环 #

app.exec() 启动的是一台分发器：从系统事件队列取事件，翻译成 QEvent，投给目标对象，目标对象的 event() 再分派到 mousePressEvent、keyPressEvent 这类专用处理函数。自定义事件走同一套机制：

cpp
class MyEvent : public QEvent
{
public:
    enum { Type = QEvent::User + 1 };
    explicit MyEvent(const QString &s)
        : QEvent(static_cast<QEvent::Type>(Type)), m_s(s) {}
    QString payload() const { return m_s; }
private:
    QString m_s;
};

// 投递：异步，进队列，事件循环下一轮处理
QCoreApplication::postEvent(receiver, new MyEvent(QStringLiteral("hello")));

// 接收：重写 event()
bool MyWidget::event(QEvent *e)
{
    if (e->type() == MyEvent::Type) {
        qDebug() << static_cast<MyEvent *>(e)->payload();
        return true;                    // 吃掉，不再往下传
    }
    return QWidget::event(e);           // 其余交给基类，别漏
}

postEvent 异步投递，可以跨线程；sendEvent 同步直调，只能在当前线程用。忘了调基类 event() 会让控件失去默认行为，这是自绘控件最常见的坑。

QThread #

工作线程做耗时计算，继承重写 run：

cpp
class Worker : public QThread
{
    Q_OBJECT
protected:
    void run() override
    {
        for (int i = 0; i < 100; ++i) {
            QThread::msleep(10);
            emit progress(i);        // 信号跨线程自动排队
        }
        emit done();
    }
signals:
    void progress(int percent);
    void done();
};

工作线程绝对不能碰主线程的界面控件。QLabel::setText 在工作线程里调用，轻则界面不刷新，重则直接崩。把数据通过信号发给主线程，由主线程的槽去更新界面。

线程退出也别硬来。terminate() 会打断 run 里的任意一行，锁和堆内存都会留在半截状态。用 requestInterruption() 配合 isInterruptionRequested() 让 run 自己收尾，再 wait() 等它结束。

配置与定时器 #

cpp
QSettings cfg("MyOrg", "MyApp");             // 平台无关的配置存储
cfg.setValue("window/width", 800);
int w = cfg.value("window/width", 640).toInt();

QTimer *timer = new QTimer(this);
timer->setInterval(1000);
connect(timer, &QTimer::timeout, this, &MainWindow::tick);
timer->start();

QSettings 在 Windows 写注册表，在 Linux 写 ~/.config，在 macOS 写 plist。存窗口位置、最近打开的文件这类东西别自己拼路径。

四、Qt GUI 与 Qt Widgets #

QtGui 是底层能力，QtWidgets 是长在它上面的控件库。写桌面程序，日常打交道的是后者，但画图、字体、图像这些活是前者干的。

窗口的三种形态 #

类型 基类 用途
主窗口 QMainWindow 带菜单栏、工具栏、状态栏、停靠窗口的应用主界面
对话框 QDialog 临时交互，模态或非模态
多文档界面 QMdiArea 一个主窗口里开多个子窗口

QMainWindow 的中央区域只能有一个控件，要放多个就得先塞一个容器再上布局。窗口的基础属性一行一个：

cpp
setWindowTitle(QStringLiteral("我的应用程序"));
resize(800, 600);
setWindowIcon(QIcon(QStringLiteral(":/icons/app.png")));   // 图标走 qrc
setMinimumSize(640, 480);

布局管理 #

布局 类 排列方式
垂直布局 QVBoxLayout 子控件从上到下
水平布局 QHBoxLayout 子控件从左到右
网格布局 QGridLayout 按行列定位
表单布局 QFormLayout 左标签右输入框，两列对齐

纯用嵌套就能应付绝大多数界面，剩下的缝隙交给弹簧占位控件（QSpacerItem，Designer 里叫 Horizontal Spacer / Vertical Spacer）。

cpp
auto *mainLayout = new QVBoxLayout(this);
auto *topLayout  = new QHBoxLayout;
topLayout->addWidget(new QLabel(QStringLiteral("关键字：")));
topLayout->addWidget(new QLineEdit);
topLayout->addWidget(new QPushButton(QStringLiteral("搜索")));
mainLayout->addLayout(topLayout);    // 布局可以嵌布局
mainLayout->addWidget(new QTextEdit);
mainLayout->addStretch(1);           // 尾部弹簧，把上面顶住

布局有两种用法，别混：拖 Layout 控件进界面再往里塞子控件（Designer 会在背后自动加一个 QWidget 当容器）；或者选中容器右键「布局」直接指定（容器里所有直接子控件被这个布局接管）。后者更干净，前者用多了会出现一堆无名 QWidget。

不设 layout 的 QWidget，子控件按绝对坐标摆，窗口一缩放界面就散。

通用控件 #

控件 作用 常用接口
QPushButton 按钮 clicked 信号、setEnabled
QLineEdit 单行输入 text、setPlaceholderText、editingFinished
QRadioButton 单选 同组互斥，靠 QButtonGroup 分组
QCheckBox 复选 isChecked、stateChanged
QFrame 容器 / 分隔线 setFrameShape
QProgressBar 进度条 setValue、setRange
QComboBox 下拉框 addItem、currentData

QTabWidget 选项卡 setCurrentIndex、removeTab

这些接口查文档就能上手。下面三个控件有额外技巧，单独说。

QComboBox：显示文本与隐藏数据分离 #

下拉项除了给人看的文本，往往还要绑一个 ID 或实体对象。addItem 的第二个参数就是干这个的：

cpp
auto *combo = new QComboBox(this);
combo->addItem(QStringLiteral("选项 A"), QVariant(1001));   // 文本 -> 隐藏 ID
combo->addItem(QStringLiteral("选项 B"), QVariant(1002));
int id = combo->currentData().toInt();                      // 取当前项的隐藏数据

用户看到「选项 A」，程序拿到 1001。别用 currentIndex() 去映射，顺序一变全错。

QTableWidget #

属性 设为 效果
focusPolicy Qt::NoFocus 去掉点击单元格的虚线框
editTriggers QAbstractItemView::NoEditTriggers 单元格只读，禁双击编辑
selectionBehavior QAbstractItemView::SelectRows 整行选中
selectionMode QAbstractItemView::ExtendedSelection 支持多选

四个常用片段：

cpp
// 单元格里塞控件，是 setCellWidget，不是 setItem
auto *box = new QComboBox;
box->addItem(QStringLiteral("男"));
ui->tableWidget->setCellWidget(row, col, box);

// 单元格上的复选框
auto *item = new QTableWidgetItem;
item->setCheckState(Qt::Unchecked);    // 设了状态，item 自动画成 CheckBox
ui->tableWidget->setItem(row, col, item);

// 挂自定义数据 / 取回
item->setData(Qt::UserRole, QVariant::fromValue(person));
Person p = ui->tableWidget->item(row, col)->data(Qt::UserRole).value<Person>();

// 坐标反查单元格
const QModelIndex idx = ui->tableWidget->indexAt(event->pos());

表头复选框默认不支持，要重绘 QHeaderView：

cpp
class MyHeaderView : public QHeaderView
{
    Q_OBJECT
public:
    explicit MyHeaderView(Qt::Orientation o, QWidget *parent = nullptr);
    void setChecked(bool checked);
signals:
    void headCheckBoxToggled(bool checked);
protected:
    void paintSection(QPainter *painter, const QRect &rect, int logicalIndex) const override;
    void mousePressEvent(QMouseEvent *event) override;
private:
    QRect checkBoxRect(const QRect &sourceRect) const;
    bool m_isOn = false;
};

paintSection 里先调基类画完表头，再在右上角补一个复选框的框和勾。mousePressEvent 里判断点击坐标是否落在 checkBoxRect 内，是就翻转 m_isOn、发信号、viewport()->update()。

QTabWidget #

cpp
ui->tabWidget->setCurrentIndex(1);   // 切页

标准对话框都是静态函数一行调用：

自定义对话框继承 QDialog，摆好控件后从主窗口调用：

class LoginDialog : public QDialog

自定义控件 #

继承 QWidget，重写 paintEvent 画，重写事件函数收输入：

cpp
class GaugeWidget : public QWidget
{
    Q_OBJECT
protected:
    void paintEvent(QPaintEvent *) override
    {
        QPainter p(this);
        p.setRenderHint(QPainter::Antialiasing);
        p.setBrush(Qt::blue);
        p.setPen(Qt::NoPen);
        p.drawRect(rect().adjusted(8, 8, -8, -8));
        p.setPen(Qt::white);
        p.drawText(20, 40, QStringLiteral("42%"));
    }
    void mousePressEvent(QMouseEvent *e) override
    {
        qDebug() << "pressed at" << e->pos();
        e->accept();          // 声明事件已处理，不再上抛
    }
};

paintEvent 里别做耗时计算，它会被反复调用。要动画就用 update() 触发重绘，别在 paintEvent 里自己循环。

图元上百、要单独选中或拖拽时，换图形视图框架：QGraphicsScene 装图元，QGraphicsView 负责显示与缩放，自定义图元继承 QGraphicsItem。细节归 04 绘图与图表。

QSS 语法贴近 CSS，专给 Qt 控件用：

选择器 写法 命中范围

右键菜单 #

两种做法。第一种不动控件类型，设策略加信号：

cpp
ui->btnTest->setContextMenuPolicy(Qt::CustomContextMenu);
connect(ui->btnTest, &QWidget::customContextMenuRequested,
        this, &MainWindow::showBtnMenu);

void MainWindow::showBtnMenu(const QPoint &pos)
{
    QMenu menu(this);                        // 栈对象，函数返回即析构
    QAction *a1 = menu.addAction(QStringLiteral("菜单项 1"));
    menu.addAction(QStringLiteral("菜单项 2"));
    if (menu.exec(ui->btnTest->mapToGlobal(pos)) == a1)   // 必须转全局坐标
        qDebug() << "item 1";
}

第二种重写事件：

cpp
void MyWidget::contextMenuEvent(QContextMenuEvent *event)
{
    QMenu menu(this);
    menu.addAction(QStringLiteral("复制"));
    menu.exec(event->globalPos());
}

第一种适合给别人的控件加菜单，第二种适合自己写的控件。两者不要同时用，会弹两次。

五、Qt Quick 与 QML #

QtWidgets 是拿 C++ 一行行搭界面，QtQuick 是拿 QML 一行行描述界面。两条路都通到 QtGui，选一条走。

QML 是什么 #

QML 是一门声明式语言，语法像 JSON 加 JavaScript。界面用对象树描述，行为用 JS 表达式写，渲染交给场景图（Scene Graph）跑在 GPU 上。

text
QQmlApplicationEngine → ApplicationWindow
                          ├─ ToolBar / Label
                          └─ ColumnLayout
                               ├─ Text { text: "你好" }
                               └─ Button { text: "点我"; onClicked: ... }

最小可运行程序：

cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    QQmlApplicationEngine engine;
    engine.load(QUrl(QStringLiteral("qrc:/main.qml")));
    return engine.rootObjects().isEmpty() ? -1 : app.exec();
}

bash
// main.qml
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    visible: true
    width: 400; height: 300
    title: "Hello QML"

    Column {
        anchors.centerIn: parent
        spacing: 12
        Text { text: "你好，Qt Quick" }
        Button { text: "点我"; onClicked: console.log("clicked") }
    }
}

入口是 QGuiApplication，不是 QApplication。链了 Widgets 才需要后者，两个都链会让启动多初始化一套控件系统。

C++ 与 QML 的互操作细节归「QML 与 Quick」专题，这里只记一条：QML 里能调到的 C++ 方法，必须是 public slots 或 Q_INVOKABLE，类必须有 Q_OBJECT。跟元对象系统是同一套规则。

Widgets 与 Quick 怎么选 #

维度 QtWidgets QtQuick / QML
语言 纯 C++ QML + JS，逻辑可回落到 C++
渲染 CPU 光栅，控件风格跟随平台主题 GPU 场景图，自绘风格一致
上手门槛 低，会 C++ 就能写 中，要额外学 QML 与绑定语法
界面动效 能做，费劲 声明式动画，几行写完
大表格 / 表单密集 现成控件齐全，改造成本低 控件偏少，重表格要自己搭
触屏与嵌入式 可用，触摸优化有限 为触摸与高 DPI 准备
传统桌面工具 首选 不划算
车机 / 平板 / 大屏 勉强 首选

选法就三句：

  • 桌面生产力工具、密集表格与菜单、团队只熟 C++，走 Widgets。
  • 触摸设备、动效多、目标分辨率杂，走 Quick。
  • 两套共存技术上可以（QQuickWidget 把 QML 嵌进 Widgets），代价是多一层胶水，非必要别这么干。

七、Qt 的元对象系统 #

这一章是全文的重心。信号槽、属性、插件、QML 互调，全压在这套机制上。

C++ 缺什么，Qt 补什么 #

标准 C++ 没有运行期类型信息，connect 想按名字找函数做不到，属性想按字符串读写也做不到。Qt 的办法是构建期生成一张表，运行期查表。

text
写代码              构建期                        运行期
Q_OBJECT 宏  ──►  moc 生成 moc_xxx.cpp   ──►   查表分发
                  ├─ qt_meta_data_Xxx[]           ├─ 信号索引
                  ├─ qt_meta_stringdata_Xxx       ├─ 槽索引
                  └─ qt_static_metacall()         └─ switch/case 跳转

moc 干了什么 #

qt_meta_data_Xxx[] 是一张整数数组，记类名、信号槽数量与名字偏移；qt_meta_stringdata_Xxx 是字符串池；qt_static_metacall() 是一个 switch-case，按索引转到真正的成员函数。

connect 只是把「发者、信号索引、收者、槽索引」记进连接表。emit 编译后就是一次普通函数调用，函数体由 moc 生成，负责查表并逐个回调。所以信号只写声明不写实现——实现是 moc 给的。

缺 Q_OBJECT 的症状很统一：编译报「no member named 'staticMetaObject'」，或运行期报 QObject::connect: signal not found。两个报错都先查宏。

元对象能干什么 #

能力 接口 依赖
按名字调方法 QMetaObject::invokeMethod 槽或 Q_INVOKABLE
按名字读写属性 QObject::property/setProperty Q_PROPERTY
跨库转型 qobject_cast<T*> Q_OBJECT + 继承链
打包任意类型 QVariant Q_DECLARE_METATYPE
翻译字符串 tr() Q_OBJECT 里的 tr 静态函数 
cpp
class Gauge : public QWidget
{
    Q_OBJECT
    Q_PROPERTY(int value READ value WRITE setValue NOTIFY valueChanged)
public:
    int value() const { return m_value; }
    void setValue(int v)
    {
        if (v == m_value) return;
        m_value = v;
        emit valueChanged(v);
        update();
    }
signals:
    void valueChanged(int v);
private:
    int m_value = 0;
};

有了 NOTIFY，QML 里 value 一变界面自动刷新，QSS 也能写 Gauge[value="50"]。这就是「属性 + 信号」带来的声明式能力。

uic 与 moc 别搞混 #

工具 输入 输出 解决什么
moc 含 Q_OBJECT 的头文件 moc_xxx.cpp 元数据、信号槽实现
uic xxx.ui ui_xxx.h 界面控件生成与布局
rcc xxx.qrc qrc_xxx.cpp 资源打包进二进制

三个都在构建期跑，构建系统负责调。手写 CMake 忘记 CMAKE_AUTOMOC ON，症状是链接期报 vtable 未定义，翻 moc_*.cpp 一个都没有。

八、信号与槽：Qt 的核心机制 #

信号槽负责对象间解耦通信：发者只管发，不关心谁接；收者只管接，不关心谁发。

三种写法 #

cpp
// 新式：函数指针，编译期检查签名
connect(ui->btnTest, &QPushButton::clicked, this, &MainWindow::onBtnTestClicked);

// 新式 + lambda，适合一次性逻辑、捕获局部变量
connect(ui->btnTest, &QPushButton::clicked, this, [this](bool c) { qDebug() << c; });

// 老式：字符串匹配，写错了要到运行期才报 signal not found
connect(ui->btnTest, SIGNAL(clicked()), this, SLOT(onBtnTestClicked()));

一律用新式。老式的唯一用途是接只暴露 SIGNAL() 宏的第三方代码。

自动关联 #

Designer 里右键控件「转到槽」，会生成固定命名的函数：

cpp
void on_btnTest_clicked();          // on_<objectName>_<信号名>

名字对上了，setupUi 里的 QMetaObject::connectSlotsByName() 自动完成连接。名字错一个字符就静默失联，改了 objectName 一定回头查这里。

连接类型 #

类型 行为 什么时候用
AutoConnection 同线程直调，跨线程排队 默认值，别动
DirectConnection 无视线程，在发射者线程直接调槽 明确知道在干什么
QueuedConnection 一定排队到接收者线程 手动指定跨线程
BlockingQueuedConnection 排队并阻塞等槽返回 少见，同线程用会死锁
UniqueConnection 与 Auto 按位或，重复连接只留一条 防重复触发

跨线程传自定义类型，先用 qRegisterMetaType<T>("T") 注册，否则排队连接丢事件并打印 Cannot queue arguments of type。

生命周期与开销 #

  • 任一端对象被销毁，连接自动断开，不用手动 disconnect。
  • sender 活着、receiver 已被裸 delete，Direct 连接就会踩野指针。用 deleteLater。
  • 主动断开：disconnect(sender, &Sender::sig, receiver, &Receiver::slot)。

信号与槽的开销是一次函数调用加一次查表，不必为了性能换掉它。真正影响性能的是槽里干了什么。

九、Qt 的跨平台原理 #

一份源码，一套 API，编到各平台跑。底层靠平台抽象层（QPA）。

text
你的代码（QWidget / QPainter / QEvent）
        ▼ 只依赖 Qt API
QtGui / QtWidgets ── 统一的绘制与窗口接口
        ▼
QPA 插件（构建时选一个，运行时加载）
  qwindows   qxcb   qcocoa   qeglfs   qoffscreen
        ▼
Win32 / X11 / Cocoa / framebuffer
  • 窗口创建、事件循环、字体枚举、剪贴板，各平台实现全在 QPA 插件里。Linux 上缺 libqxcb.so 就跑不起来，报「could not load the Qt platform plugin xcb」。
  • 构建工具做平台分支：.pro 里 win32 { LIBS += -luser32 }、unix:!macx { LIBS += -lX11 }、macx { ICON = app.icns }。
  • 交叉编译靠 -platform 与工具链文件，产物拿到板子上再补 Qt 运行库。
  • 平台差异不会消失：字体度量、窗口装饰、高 DPI 缩放、路径分隔符各平台都不同。发布前每个目标平台真机跑一遍。

排序的三条理由 #

第一，先 Core 再 UI。容器、QString、QVariant、事件循环搞不清，控件用起来只会抄代码；QVariant 吃透之后，QComboBox、QTableWidget 的自定义数据绑定就是同一件事。

第二，UI 路线只选一条走到底。Widgets 或 Quick，选完别换，两条路的概念模型不通用。第三，模块按需求加，没做过网络就别硬啃 QNetworkAccessManager，写个下载器自然就会；高级阶段那六个主题等有真实项目再补，学早了忘得也快。

十一、常见的学习误区 #

误区 实情
把 Qt 当成一个 C++ 库 它是框架 + 构建工具 + 元对象系统三件套，只学 API 会在 moc 上栽跟头
以为 QtQuick 会取代 Widgets 两条并行路线，桌面工具类项目 Widgets 仍是主力
觉得信号槽是语言特性 是 moc 生成的查表机制，不是 C++ 语法，报错都发生在元数据层
界面全用绝对坐标摆 窗口一缩放就散，布局是必学项，不是可选项
在工作线程里直接改界面 会崩或界面不刷新，跨线程一律走排队信号
到处 delete UI 对象 有 parent 的对象交给对象树，要提前删用 deleteLater
QSS 能搞定所有外观 改不了的属性得回头改代码或重写 QStyle
中文乱码当成环境问题 九成是源文件编码或编译器字符集没指定

最容易踩的两个实例：工作线程里写 ui->label->setText(...) 会崩或界面不刷新，改成 emit finished(...) 由主线程的槽去更新。

十二、易错点速查 #

现象 原因 处理
链接报 vtable 未定义 少了 Q_OBJECT 的实现 补宏，构建系统开 AUTOMOC
connect 报 signal not found 信号名拼错或类没 Q_OBJECT 查宏，改用新式函数指针语法
槽函数不触发 on_xxx_clicked 名字不匹配 对照 objectName 与信号名
中文编译报 C2001 源文件编码与编译器字符集不一致 见下方三条
界面缩放后错位 用了绝对坐标 改布局，加弹簧
启动报 platform plugin 加载失败 缺 QPA 插件或路径不对 查 platforms/ 目录与 QT_QPA_PLATFORM
跨线程队列连接丢事件 自定义类型没注册 qRegisterMetaType
表格设了 setItem 却不显示 行数列数没先设 setRowCount / setColumnCount
单元格里塞不进控件 用了 setItem 改 setCellWidget
QMenu 弹在错误位置 传了局部坐标 用 mapToGlobal(pos)
程序退出时崩溃 栈对象设了 parent 被删两次 栈对象不设 parent

Windows 上中文乱码按顺序试：

cpp
#pragma execution_character_set("utf-8")   // 1. 源文件开头加编译指令
// 2. 源文件存成 UTF-8 with BOM；3. MSVC 加 /utf-8，GCC 与 Clang 加 -finput-charset=UTF-8

还不好就把中文字面量换成 QStringLiteral(u"中文") 或 tr("中文")，把编码问题从编译器手里拿走。

学 Qt 的顺序只有一条主干：吃透 QtCore 的对象模型与事件循环，选一条 UI 路线走通，再按项目需要往上挂模块。元对象系统看着像黑魔法，其实就是一张编译期生成、运行期查询的表。把这张表想明白，后面所有模块都只是在这套规则上加功能。
