本篇只讲一件事：Qt 装好之后，怎么让它真的能编译、能跑起来。范围包括 PATH 与环境变量、qmake 路径与验证、编译器选择（GCC / MinGW / MSVC）、Qt 5 与 Qt 6 构建系统的差别，以及用命令行和 CMake 各跑一个 helloworld。

不讲安装包怎么下载、安装向导怎么点——那是同目录《Qt5.15 的下载与安装》的活；不讲 Qt Creator 的界面、快捷键、定位器——那是《Qt Creator 与开发环境配置》的活；也不讲交叉编译到 ARM 板子，那属于「移植」分支。

文中会出现两段历史：一段是 Ubuntu 上跑 Qt 5.6.1 的 .run 安装包，一段是更早的 Qt 4.8.4 源码编译。老版本的步骤今天不用照抄，但那些坑——qmake 指向 Qt 3、LD_LIBRARY_PATH 没配、链接器找不到库——在 Qt 5 和 Qt 6 上一个都没消失。

一、装完不等于配好 #

向导跑完，Qt Creator 能打开，新建一个空项目，点构建，红字刷屏。这件事每年都有人重新遇到一次。

先摆结论：装完 Qt 之后出现「找不到 qmake」「编译不过」，绝大多数不是 Qt 坏了，而是环境变量没配、或者编译器跟装 Qt 时用的那个不是同一个。Qt 本身是个很安静的库，它不会主动去改你的 shell 配置，也不会热心地帮你把 bin 目录塞进 PATH。安装器只是把文件铺到磁盘上，剩下的接线归你。

判断顺序建议这样走，从便宜到贵：

  1. which qmake / where qmake，看它到底指向哪个文件。
  2. qmake -v，看版本和 Qt 库路径对不对得上。
  3. qmake -query QT_INSTALL_BINS，看这个 qmake 认为自己属于哪套 Qt。
  4. 看 mkspecs 目录名（gcc_64、mingw73_64、msvc2019_64），确认编译器家族。
  5. 最后才怀疑编译器和链接器。
现象 八成原因 去哪一章
终端里 qmake 提示 command not found bin 目录没进 PATH 二
qmake -v 显示 Qt 3.3.8b / 4.8.4，但项目要 5.x /usr/bin/qmake 这条软链指向了系统旧版 三
编译过了，链接报 undefined reference to ... qmake 和编译器不匹配，或缺 -l 库 四、九
报 Unknown module(s) in QT: svg 该模块的 dev 包没装 八、九
程序编出来了，运行时找不到 libQt5Core.so.5 LD_LIBRARY_PATH 没带 Qt 的 lib 二、九
Qt Creator 里绿三角是灰的 Kit 没配好，qmake 路径为空 十一

二、PATH 与环境变量 #

Qt 的环境变量不多，真正干活的是下面这几个。别一次全配，先配前两个，跑不通再往下加。

变量 作用 典型值（Linux / Windows）
PATH 让 shell 找得到 qmake、moc、uic、rcc /opt/Qt5.6.1/5.6/gcc_64/bin / C:\Qt\5.15.2\mingw81_64\bin
QTDIR Qt 安装根，老版本脚本靠它找库 /opt/Qt5.6.1/5.6/gcc_64 / C:\Qt\5.15.2\mingw81_64
LD_LIBRARY_PATH 运行时加载 .so 的搜索路径（仅 Linux） $QTDIR/lib
MANPATH man qmake 能找到手册 $QTDIR/man
QT_SELECT 让 qmake 选择某一代 Qt（Debian / Ubuntu 系生效） qt5、qt4、qt6
QT_PLUGIN_PATH 平台插件、图片格式插件、SQL 驱动的搜索路径 $QTDIR/plugins
CMAKE_PREFIX_PATH 给 CMake 的 find_package(Qt5/Qt6) 指路 $QTDIR

Linux 下的写法，编辑 ~/.bashrc（只影响当前用户）：

bash
export QTDIR=/opt/Qt5.6.1/5.6/gcc_64
export PATH=$QTDIR/bin:$PATH
export MANPATH=$QTDIR/man:$MANPATH
export LD_LIBRARY_PATH=$QTDIR/lib:$LD_LIBRARY_PATH

改完执行 source ~/.bashrc，当前终端立刻生效。想影响全机器，同样的几行写进 /etc/profile。老资料里出现过 vi /home/defonds/.bashrc 这种路径，那是作者的机器，换成你自己的。

注意 PATH=$QTDIR/bin:$PATH 的写法是有方向的：新路径放前面，才盖得住系统里已有的 /usr/bin/qmake。反过来写成 $PATH:$QTDIR/bin，等于白配——shell 先命中旧的那个就返回了。

Windows 下不用改 .bashrc，走「系统属性 → 高级 → 环境变量」，把 C:\Qt\5.15.2\mingw81_64\bin 加进 Path。两个坑：

  • 改完必须关掉终端重开。CMD、PowerShell、Qt Creator 都只在自己启动的那一刻读一次环境变量。
  • 安装器默认会把 Qt 写进系统 PATH 的后面。你机器上同时装过两三个版本时，谁在前面谁生效，跟你想的那个不一定一致。

验证环境变量有没有生效，Linux 用 echo $PATH、env | grep QT，Windows 用 echo %PATH% 或 PowerShell 的 $env:Path。编译期缺头文件这类问题，先在命令行里跑通，别一上来就赖 IDE。

三、qmake 在哪、怎么验证 #

qmake 是个普通的可执行文件，就躺在 Qt 安装目录的 bin 里。Linux 装 Qt 5.6.1（.run 安装包，装到默认的 /opt）时：

text
/opt/Qt5.6.1/5.6/gcc_64/bin/qmake
/opt/Qt5.6.1/5.6/gcc_64/lib
/opt/Qt5.6.1/5.6/gcc_64/include
/opt/Qt5.6.1/5.6/gcc_64/plugins
/opt/Qt5.6.1/Tools/QtCreator/bin/qtcreator

路径层级要念清楚：/opt/Qt5.6.1 是产品版本，5.6 是 Qt 库的版本，gcc_64 是 mkspec（编译器 + 架构）。你要引的永远是 gcc_64 这一层里的东西，不是 /opt/Qt5.6.1 根。

三步验证，缺一不可：

bash
which qmake
qmake -v
qmake -query

qmake -v 正常输出长这样，第二行把库路径也交代了：

text
QMake version 3.0
Using Qt version 5.6.1 in /opt/Qt5.6.1/5.6/gcc_64/lib

只有第一行、没有 Using Qt version，说明这个 qmake 找不到自己的库，qt.conf 或安装目录被动过。

qmake -query 信息量大，常用的几项：

查询键 含义 判断标准
QT_VERSION Qt 库版本 跟你以为的一致
QT_INSTALL_PREFIX 安装根 落在你装的那套目录里
QT_INSTALL_BINS bin 目录 应该正好是你 PATH 里的那个
QT_INSTALL_LIBS 库目录 后续 -L 指这里
QT_INSTALL_PLUGINS 插件目录 SQL 驱动、平台插件在这
QT_INSTALL_HEADERS 头文件根 后续 INCLUDEPATH 指这里
QMAKE_XSPEC mkspec 名 gcc_64 / mingw / msvc2019_64

QMAKE_XSPEC 这一项经常被忽略，但它一句话就把「你这套 Qt 是用什么编译器编的」告诉了 qmake。

被 Qt 3 劫持的 qmake

老 Ubuntu 上很经典的一幕。你明明装好了 Qt 4.8.4 / 5.x，敲 qmake -v 却是：

text
Qmake version: 1.07a (Qt 3.3.8b)
Qmake is free software from Trolltech ASA.

which qmake 给的是 /usr/bin/qmake。追一下这条链：

bash
ls -l /usr/bin/qmake
# /usr/bin/qmake -> /etc/alternatives/qmake
ls -l /etc/alternatives/qmake
# /etc/alternatives/qmake -> /usr/bin/qmake-qt3

绕了两跳，最后落到 qmake-qt3 上。这是 Debian 系的 alternatives 机制在替你做版本仲裁，它选的是「系统里注册过、优先级较高」的那个，跟你手动装的 Qt 没关系。

改法两种。第一种，直接换软链：

bash
sudo rm /etc/alternatives/qmake
sudo ln -s /usr/local/Trolltech/Qt-4.8.4/bin/qmake /etc/alternatives/qmake
qmake -v

text
QMake version 2.01a
Using Qt version 4.8.4 in /usr/local/Trolltech/Qt-4.8.4/lib

输出从 1.07a 变成 2.01a，版本 4.8.4，说明链子通了。第二种是改 PATH，见上一章。两种都行，别同时用，会互相打架，排查时你也说不清是谁在起作用。

四、编译器：GCC 与 MinGW 与 MSVC #

这是本篇最该记住的一段：Qt 的库是二进制，跟编译器是一对一绑死的。用哪个编译器编出来的 Qt，就必须用哪个编译器去编你的程序。混用不一定在编译期报错，但几乎一定在链接期炸，而且报错信息长得很像别的问题，能让你查半天。

维度 MinGW（Windows） MSVC（Windows） GCC（Linux / macOS）
二进制来源 随 Qt 安装器一起打包 需要你自己装 Visual Studio 系统包管理器装
体积 轻，几十 MB，解压即用 重，VS 动辄几个 GB 中等，build-essential 一组
附带工具链 mingw32-make、g++、gdb nmake / msbuild、cl.exe、link.exe make、g++、gdb
调试器 GDB Visual Studio Debugger / cdb GDB
与 VS 集成 无 原生，可直接挂 VS 工程 无
命令行构建 mingw32-make nmake（要先跑 vcvars） make
典型 mkspec win32-g++ / mingw73_64 win32-msvc / msvc2019_64 linux-g++ / gcc_64
常见坑 缺 libgcc_s_seh-1.dll 等运行时 DLL 必须在 VS 开发者命令行里构建 32/64 位与 -fPIC 不匹配

怎么看出手头这套 Qt 是哪种编译器编的？看 mkspecs 目录名，最省事：

text
C:\Qt\5.15.2\mingw81_64\mkspecs\win32-g++        -> MinGW 8.1 / 64 位
C:\Qt\5.15.2\msvc2019_64\mkspecs\win32-msvc      -> MSVC 2019 / 64 位
/opt/Qt5.6.1/5.6/gcc_64/mkspecs/linux-g++        -> GCC / 64 位

目录名里那个 _64 也别漏。64 位的 Qt 库不能链进 32 位程序，反过来也不行，报错是 cannot open file 'Qt5Core.lib' 或者 file format not recognized。

用 MinGW 时，make 换成 mingw32-make，别去下个 MSYS 的 make 混着用。用 MSVC 时，cl.exe 不在默认 PATH 里，必须先开「x64 Native Tools Command Prompt for VS」，或者手动跑一次 vcvars64.bat，否则 qmake 找不到编译器，Makefile 生成出来也是空的。

选哪个？Windows 上做桌面小工具、想少装东西，选 MinGW；要跟已有的 VS 工程、公司内部库、PDB 调试体系对齐，选 MSVC。Linux 上没得选，就是 GCC（或 Clang），装 build-essential 即可。macOS 上是 Clang，随 Xcode Command Line Tools 一起来。

五、Qt 5 与 Qt 6 的构建系统差别 #

这一章的用处：你手上有 Qt 5 的老工程，或者照着旧教程敲的 .pro，放到 Qt 6 环境里能不能跑。答案是一半能、一半不能，差别集中在下面这几格。

项目 Qt 5 Qt 6
主推构建系统 qmake 仍是默认，CMake 可选 CMake 是首选，qmake 仍可用但官方不再推荐
.pro 里声明模块 QT += core gui widgets 同名照写，widgets 仍然存在
CMake 里 find_package find_package(Qt5 REQUIRED COMPONENTS Widgets) find_package(Qt6 REQUIRED COMPONENTS Widgets)
链接写法 Qt5::Widgets Qt6::Widgets
CMake 最低版本 3.1 左右 3.16 起，官方要求 3.16+
C++ 标准 默认 C++11 可用 默认要求 C++17
版本无关写法 find_package(QT NAMES Qt6 Qt5 ...) 后取 ${QT_VERSION_MAJOR} 同左
兼容老 API — Qt5Compat 模块（Core5Compat、GraphicalEffects 等）
部署工具 windeployqt windeployqt，参数基本一致
头文件命名 #include <QtWidgets/QApplication> 同左，模块化头文件策略延续

一句话版本：.pro 文件在 Qt 5 和 Qt 6 之间基本通用，CMake 文件得改包名和最低版本。真正卡人的是 C++ 标准——Qt 6 的库用 C++17 编的，你的工程如果还挂着 -std=c++98，链接期会给你一堆 undefined reference。

写一个能同时吃两代 Qt 的 CMakeLists.txt，前面几行这样起手：

cmake
cmake_minimum_required(VERSION 3.16)

project(helloworld VERSION 0.1 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(QT NAMES Qt6 Qt5 REQUIRED COMPONENTS Widgets)
find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Widgets)

find_package(QT NAMES Qt6 Qt5 ...) 这一行的意思是：先找 Qt6，找不到再退到 Qt5，找到哪个就把主版本号写进 QT_VERSION_MAJOR。后面统一用 Qt${QT_VERSION_MAJOR}::Widgets，两代通吃。

六、第一个项目：命令行版 #

不打开 IDE，纯命令行跑通一次。这一步的价值在于：出问题时你能确定是 Qt 的事还是 IDE 的事。

先建个目录，写一个 main.cpp。Qt 5 的写法：

cpp
#include <QApplication>
#include <QLabel>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QLabel label(QStringLiteral("hello, qt"));
    label.resize(320, 120);
    label.show();

    return app.exec();
}

Qt 4 时代的头文件是 <QtGui/QApplication>，Qt 5 起 QApplication 归到 QtWidgets 模块。直接写 <QApplication> 也能编过，因为 qmake 会把模块的 include 目录全加进去。

只想要控制台输出、不要窗口，把 QApplication 换成 QCoreApplication，QLabel 换成 qDebug()：

cpp
#include <QCoreApplication>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication app(argc, argv);
    qDebug() << "hello, qt" << QT_VERSION_STR;
    return 0;
}

接着三步走。第一步生成工程文件：

bash
qmake -project

它会扫当前目录的源文件，吐出一个 helloworld.pro。内容就这几行，QT += 那行只给了 core gui，用到控件得自己补：

text
TEMPLATE = app
TARGET = helloworld
INCLUDEPATH += .

HEADERS +=
SOURCES += main.cpp
QT += core gui

用控件的，把最后一行改成 QT += core gui widgets（Qt 4 时代写 QT += core gui 就够，widgets 还在 gui 里）。工程大了以后别靠 qmake -project，手写 .pro 更可控：

text
QT       += core gui widgets
CONFIG   += c++17

TARGET    = helloworld
TEMPLATE  = app
SOURCES  += main.cpp

第二步生成 Makefile：

bash
qmake helloworld.pro

第三步编译：

bash
make            # Linux / macOS
mingw32-make    # Windows + MinGW
nmake           # Windows + MSVC，先跑 vcvars

编完得到 helloworld（Windows 上是 helloworld.exe），在当前目录直接跑：

bash
./helloworld

出现一个写着 hello, qt 的小窗口，环境就算通了。这一路走下来没报错，说明 PATH、qmake、编译器、链接器四件事全对上了，剩下的问题就落在 IDE 配置里。

Windows 上把 exe 拷到别的机器跑，会缺一堆 DLL。用 Qt 自带的部署工具补齐：

bash
windeployqt --release helloworld.exe

它按 exe 里登记的依赖，把 Qt5Core.dll、Qt5Gui.dll、platforms/qwindows.dll 一起拷到同目录。

七、第一个项目：CMake 版 #

同一份 main.cpp，换成 CMake。Qt 6 之后这是主线，值得先熟悉。

CMakeLists.txt 全文：

cmake
cmake_minimum_required(VERSION 3.16)

project(helloworld VERSION 0.1 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTORCC ON)
set(CMAKE_AUTOUIC ON)

find_package(QT NAMES Qt6 Qt5 REQUIRED COMPONENTS Widgets)
find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Widgets)

add_executable(helloworld main.cpp)

target_link_libraries(helloworld PRIVATE Qt${QT_VERSION_MAJOR}::Widgets)

CMAKE_AUTOMOC 这三个开关对应 qmake 里自动跑的 moc / uic / rcc。少了它们，带 Q_OBJECT 的类会报 undefined reference to vtable for ...。

配置和构建，关键在 CMAKE_PREFIX_PATH 指向哪个 Qt：

bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_PREFIX_PATH=/opt/Qt5.6.1/5.6/gcc_64
cmake --build build -j4
./build/helloworld

Windows 下换成：

bash
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH=C:/Qt/5.15.2/mingw81_64
cmake --build build

用 MSVC 就把生成器换成 "Visual Studio 16 2019" -A x64，或者 "Ninja" 配 VS 开发者命令行。

CMAKE_PREFIX_PATH 已经是环境变量的，命令行可以不写；但多版本共存时，写在命令行里比改环境变量可靠——它只对这一次构建生效，不会污染别的终端。CMAKE_PREFIX_PATH 里指到 gcc_64 这一层，不要指到 /opt/Qt5.6.1，CMake 认的是 lib/cmake/Qt5/Qt5Config.cmake 这个相对位置。

一次配好之后，版本信息可以打印出来自查：

cmake
message(STATUS "Qt version: ${QT_VERSION_MAJOR}")
message(STATUS "Qt dir: ${Qt${QT_VERSION_MAJOR}_DIR}")

Qt5_DIR 会告诉你 CMake 到底用了哪套 Qt，比猜快。

八、Linux 下的额外依赖 #

Linux 上「装完 Qt」只是装完了库，编译器和一堆开发头文件还在外面。下面这些包按需装，缺哪个装哪个。

包名 缺了会怎样 备注
build-essential 没有 g++、make 一次带走编译链
libgl1-mesa-dev 链接报 cannot find -lGL 装完 .run 安装包后第一个要补的
libqt5svg5* 报 Unknown module(s) in QT: svg Qwt 编译时会撞上
qttools5-dev* 报 Unknown module(s) in QT: designer Qt Designer 插件相关
libssl-dev MySQL 驱动编译不过 老版驱动依赖 OpenSSL
libcrypto++-dev 同上 Qt 5.6 时代需要
libmysqlclient-dev 找不到 mysql.h 编 QMYSQL 驱动
libaio1 MySQL 5.7 deb 装不上 异步 IO 依赖
libmecab2 MySQL server 包装不上 分词库依赖
cmake CMake 工程配不了 Qt 6 路线

用 Qt 5.6.1 的 .run 安装包装完，界面点完 Finish，程序还是编不过，缺的就是 libgl1-mesa-dev：

bash
sudo apt-get install libgl1-mesa-dev

Modbus：源码编 + 改 .pro

拿到 libmodbus-3.0.6.tar.gz，解压、配置、编译、安装四步：

bash
tar xvf libmodbus-3.0.6.tar.gz
cd libmodbus-3.0.6/
./configure
make
sudo make install

装完 /usr/local/include/modbus/ 下有 4 个头文件，/usr/local/lib/ 下有 4 个库文件。老系统上动态库搜索路径不含 /usr/local/lib，把三个软链和实体库拷进 /lib：

bash
sudo cp libmodbus.so* /lib

工程里要用，.pro 加两行：

text
INCLUDEPATH += /usr/local/include/modbus/
LIBS += -L/usr/local/lib -lmodbus

INCLUDEPATH 管编译期找头文件，LIBS 管链接期找库。改完 .pro 必须重新跑一次 qmake，否则改动不生效。

QtXlsx：编一遍，再搬文件

QtXlsxWriter-master 用 Qt Creator 打开，点左下角构建。Qt 5.6 上会挂一次，报错位置在 QList 转 QVector 相关的那一行——把 QList 改成 QVector 再编。

编完在用户目录下得到 build-qtxlsx-Desktop_Qt_5_6_1_GCC_64bit-Debug，里面是头文件、库、pri 文件。搬四处：

bash
sudo cp QtXlsx/ /opt/Qt5.6.1/5.6/gcc_64/include/ -a
sudo cp libQt5Xlsx.so* /opt/Qt5.6.1/5.6/gcc_64/lib
sudo cp libQt5Xlsx.la /opt/Qt5.6.1/5.6/gcc_64/mkspecs/modules/
sudo cp qt_lib_xlsx.pri /opt/Qt5.6.1/5.6/gcc_64/mkspecs/modules/

.so 有四个：libQt5Xlsx.so、.so.0、.so.0.3、.so.0.3.0，一条通配符全带走。mkspecs/modules 下的 .pri 是 qmake 认模块的凭证，少了它 QT += xlsx 会报未知模块。

工程里加：

text
QT += xlsx

加完重新构建 qmake。不重建会提示连不上库。

Qwt：svn 拉源码 + Designer 插件

Qwt 的源码在 SourceForge 的 svn 上：

bash
svn checkout svn://svn.code.sf.net/p/qwt/code/branches/qwt-6.1

没装 svn 先补：sudo apt install subversion。进目录，用目标 Qt 的 qmake 生成 Makefile——这里必须写全路径，别用 PATH 里那个：

bash
cd qwt-6.1
/opt/Qt5.6.1/5.6/gcc_64/bin/qmake
make
sudo make install

make 阶段的两个高频报错，对应的补丁包：

bash
# Project ERROR: Unknown module(s) in QT: svg
sudo apt-get install libqt5svg5*

# Project ERROR: Unknown module(s) in QT: designer
sudo apt-get install qttools5-dev*

装完默认落在 /usr/local/qwt-6.1/。要让 Qwt 控件出现在 Qt Designer 的控件箱里，插件得放对位置：

bash
sudo cp libqwt_designer_plugin.so \
    /opt/Qt5.6.1/Tools/QtCreator/lib/Qt/plugins/designer/

再把 lib 下的库文件分别拷到 Creator 和 Qt 库目录：

bash
sudo cp * /opt/Qt5.6.1/Tools/QtCreator/lib/qtcreator/
sudo cp * /opt/Qt5.6.1/5.6/gcc_64/lib

工程里用 Qwt，.pro 加：

text
INCLUDEPATH += /usr/local/qwt-6.1/include
LIBS += -L"/usr/local/qwt-6.1/lib/" -lqwt

路径带引号是因为某些环境下空格会拆行，写上去不亏。

MySQL：装库、编驱动、建软链

Qt 发行包里不带 QMYSQL 驱动，得自己编。数据库本身可以用 deb 包堆上去，注意依赖顺序，dpkg -i 逐个来：

bash
tar xvf mysql-server_5.7.14-1ubuntu16.04_amd64.deb-bundle.tar
sudo dpkg -i mysql-common_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i libmysqlclient20_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i libmysqlclient-dev_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i libmysqld-dev_5.7.14-1ubuntu16.04_amd64.deb
sudo apt-get install libaio1
sudo dpkg -i mysql-community-client_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i mysql-client_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i mysql-community-source_5.7.14-1ubuntu16.04_amd64.deb
sudo apt-get install libmecab2
sudo dpkg -i mysql-community-server_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i mysql-server_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i mysql-community-test_5.7.14-1ubuntu16.04_amd64.deb
sudo dpkg -i mysql-testsuite_5.7.14-1ubuntu16.04_amd64.deb

跑到 mysql-community-server 那一步会要求设 root 密码，设完就能用 mysql -uroot -p 登录。

驱动源码在 qtbase 里：

bash
tar xvf qtbase-opensource-src-5.6.0-rc.tar.gz
cd qtbase-opensource-src-5.6.0-rc/src/plugins/sqldrivers/mysql/

先 qmake -v 确认版本，再补三个依赖：

bash
sudo apt-get install libssl-dev
sudo apt-get install libcrypto++-dev
sudo apt-get install libmysqlclient-dev

用全路径 qmake 带参数生成 Makefile：

bash
/opt/Qt5.6.1/5.6/gcc_64/bin/qmake \
    "INCLUDEPATH+=/usr/include/mysql" \
    "LIBS+=-L/usr/lib/mysql -lmysqlclient_r" mysql.pro
sudo make

make 报链接错，多半是缺 libmysqlclient_r.so 这个软链。去 /usr/lib/x86_64-linux-gnu 看：

bash
ls -l libmysql*

只有 libmysqlclient.so.20.3.5、没有 libmysqlclient_r.so 的话，补一条：

bash
sudo ln -s libmysqlclient.so.20.3.5 libmysqlclient_r.so

再 sudo make 一遍，过了就把产物拷到 Qt 的插件目录：

bash
sudo cp libqsqlmysql.so /opt/Qt5.6.1/5.6/gcc_64/plugins/sqldrivers/

验一下依赖是否都能解析：

bash
cd /opt/Qt5.6.1/5.6/gcc_64/plugins/sqldrivers/
ldd libqsqlmysql.so

输出里没有 not found 才算成。工程里加 QT += sql 就能用了。

九、编译报错的常见原因 #

把报错信息对着表找，比一行行读日志快。下面这些是从实际项目里攒下来的，顺序按踩到的频次排。

报错片段 真实原因 处理
qmake: command not found bin 没进 PATH 按第二章写 .bashrc / 改系统 Path
Qmake version: 1.07a (Qt 3.3.8b) /usr/bin/qmake 指向 qmake-qt3 换软链，或用 QT_SELECT
undefined reference to 'vtable for X' 带 Q_OBJECT 的类没跑 moc qmake 会自动跑；CMake 要开 CMAKE_AUTOMOC；改过头文件后重新 qmake
undefined reference to 'QApplication::...' .pro 里没加模块 QT += widgets，改完重跑 qmake
cannot find -lGL 缺 OpenGL 开发头 sudo apt-get install libgl1-mesa-dev
Unknown module(s) in QT: svg 没装 svg 模块的 dev 包 sudo apt-get install libqt5svg5*
Unknown module(s) in QT: designer 没装 qttools 的 dev 包 sudo apt-get install qttools5-dev*
Unknown module(s) in QT: xlsx mkspecs/modules 下没 .pri 拷 qt_lib_xlsx.pri 到 mkspecs/modules/
cannot find -lqwt 库路径没写对或没装 补 INCLUDEPATH 与 LIBS，确认 sudo make install 跑过
cannot find -lmysqlclient_r 缺 libmysqlclient_r.so 软链 ln -s libmysqlclient.so.20.3.5 libmysqlclient_r.so
file format not recognized / skipping incompatible 32/64 位库混用 统一到 _64 那一套
LNK2019: 无法解析的外部符号 MSVC 编的程序链了 MinGW 编的 Qt 换同一套，见第四章
fatal error: QApplication: No such file 头文件搜索路径没带模块 重跑 qmake；确认 QT_INSTALL_HEADERS
程序启动即退，提示 could not find the Qt platform plugin "windows" 插件目录没被找到 拷 platforms/ 目录，或设 QT_PLUGIN_PATH
error while loading shared libraries: libQt5Core.so.5 运行时找不到库 设 LD_LIBRARY_PATH，或写 rpath
QtXlsx 编到一半报 QList 类型错 Qt 5.6 的 API 变动 把报错处的 QList 改成 QVector
Project ERROR: Cannot run compiler 'g++' 编译器不在 PATH 或版本不符 装 build-essential；MSVC 先跑 vcvars

几条补充，表里放不下的：

改过 .pro 之后忘了重新 qmake，是最常见的一条。表现是：你明明加了 QT += sql，编出来还是找不到 QSqlDatabase。qmake 生成的 Makefile 是快照，.pro 变了它不会自己更新。

链接错误一律往两个方向想：库没找到（-L 路径不对），或者符号不匹配（编译器不同、位数不同、Debug/Release 不同）。前者补路径，后者换工具链。

Windows 上 MinGW 编出来的 exe 单独拷走会提示缺 libgcc_s_seh-1.dll、libstdc++-6.dll、libwinpthread-1.dll。这三个是编译器运行时，windeployqt 不管它们，得从 MinGW 的 bin 里手动拷，或者加 -static 静态链接。

十、多版本 Qt 共存 #

一台机器上装三四个 Qt 很正常：老项目锁 Qt 4.8，中间项目用 5.6，新项目上 5.15 或 6.5。关键是让它们互不干扰，每个版本各占一个目录，谁也不往别人家里写东西。

版本 来源 安装位置 qmake 全路径
Qt 4.8.4 源码 configure + make install /usr/local/Trolltech/Qt-4.8.4 /usr/local/Trolltech/Qt-4.8.4/bin/qmake
Qt 5.6.1 .run 安装包 /opt/Qt5.6.1/5.6/gcc_64 /opt/Qt5.6.1/5.6/gcc_64/bin/qmake
Qt 5.15.2 在线安装器 ~/Qt/5.15.2/gcc_64 ~/Qt/5.15.2/gcc_64/bin/qmake
Qt 6.5 在线安装器 ~/Qt/6.5.0/gcc_64 ~/Qt/6.5.0/gcc_64/bin/qmake

Qt 4.8.4 那套是自己编的，值得单独说一遍，因为它的目录结构和后来的不一样：configure 不带 -prefix 时，默认装到 /usr/local/Trolltech/Qt-$QT_VERSION，这个默认值写在 configure 脚本里：

bash
QT_INSTALL_PREFIX="/usr/local/Trolltech/Qt-${QT_VERSION}"

想换个地方，配置时给前缀：

bash
./configure -prefix /opt/qt-4.8.4-x11

目录不存在会自动创建。编译过程中生成的文件都会往这个前缀里铺，源码目录保持干净，后面想删也只需要删一个前缀目录。

全套流程，Qt 4 时代 Linux 上的标准走法：

bash
tar zxvf qt-everywhere-opensource-src-4.8.4.tar.gz
cd qt-everywhere-opensource-src-4.8.4/
./configure

configure 会先问你用哪个授权版本：

text
Which edition of Qt do you want to use ?

Type 'c' if you want to use the Commercial Edition.
Type 'o' if you want to use the Open Source Edition.

输入 o，接着确认协议：

text
This is the  Open Source Edition.

You are licensed to use this software under the terms of
the Lesser GNU General Public License (LGPL) versions 2.1.
You are also licensed to use this software under the terms of
the GNU General Public License (GPL) versions 3.

Type '3' to view the GNU General Public License version 3.
Type 'L' to view the Lesser GNU General Public License version 2.1.
Type 'yes' to accept this license offer.
Type 'no' to decline this license offer.

Do you accept the terms of either license?

输入 yes 回车，开始生成 Makefile，配置本身要十来分钟。然后：

bash
make

编译三个小时起步，视机器而定，中间别断电。编完安装：

bash
sudo make install

安装只要几分钟，落进 /usr/local/Trolltech/Qt-4.8.4。验证一下，直接跑 Designer：

bash
/usr/local/Trolltech/Qt-4.8.4/bin/designer

界面起来就说明库装对了。这一步比 qmake -v 更有说服力，因为它连插件、字体、X11 依赖一起验了。

那台机器上还同时存在系统自带的 Qt 3 和 apt 装的 Qt 4，于是 qmake 走的是第三章那条软链，qmake -v 给你 Qt 3.3.8b。所以源码安装的 Qt 装完，第一件事就是处理 qmake 的指向。

配套的 IDE 也是独立安装的。旧时代 Creator 是个 .bin 自解压包，chmod 一下就能跑：

bash
chmod u+x qt-creator-linux-x86-opensource-2.6.1.bin
sudo ./qt-creator-linux-x86-opensource-2.6.1.bin

图形安装界面跟普通安装器一样，一路下一步。装完在菜单里能找到 Qt Creator，但里面的 Kit 还是空的，得手动把 qmake 路径填进去。

顺带记一下 Ubuntu 上走包管理器装 Qt 4 的那条路，快速试手时省事：

bash
sudo apt-get install qt4-dev-tools
sudo apt-get install qtcreator
sudo apt-get install qt4-doc
sudo apt-get install qt4-qtconfig
sudo apt-get install qt4-demos

五个包分别对应开发工具、IDE、帮助文档、配置工具、示例源码。包管理器装的 Qt 会自己注册到 alternatives 里，qmake 跟着它走，这也是为什么手动装的版本容易被盖住。

十一、环境切换与版本管理 #

共存解决了「装得下」，切换解决「用得上」。五条路，按侵入性从小到大排。

方式 生效范围 命令示例 适用场景
qmake 全路径 单次命令 /opt/Qt5.6.1/5.6/gcc_64/bin/qmake 临时验证、CI 脚本
改 PATH 顺序 当前终端会话 export PATH=/opt/Qt5.6.1/5.6/gcc_64/bin:$PATH 手动切环境
QT_SELECT 当前 shell export QT_SELECT=qt5 Debian / Ubuntu 系，多代并存
update-alternatives 全机器 sudo update-alternatives --config qmake 需要持久生效
CMake 的 CMAKE_PREFIX_PATH 单次构建目录 -DCMAKE_PREFIX_PATH=... CMake 工程，最干净

QT_SELECT 是 qtchooser 提供的开关，只认通过包管理器注册过的 Qt，自己解压到 /opt 的那套不在名单里。用之前先看有哪些：

bash
qtchooser -list-versions

update-alternatives 的完整用法，三步注册加切换：

bash
sudo update-alternatives --install /usr/bin/qmake qmake \
    /opt/Qt5.6.1/5.6/gcc_64/bin/qmake 100

sudo update-alternatives --install /usr/bin/qmake qmake \
    /usr/local/Trolltech/Qt-4.8.4/bin/qmake 50

sudo update-alternatives --config qmake

第三条会列出候选让你输入序号，优先级数字大的默认胜出。查当前指向：

bash
update-alternatives --query qmake

改 PATH 顺序是最土也最可靠的一招。压在 ~/.bashrc 里给每个版本写一个函数，敲两个字母就切了：

bash
qt56()  { export QTDIR=/opt/Qt5.6.1/5.6/gcc_64
          export PATH=$QTDIR/bin:$PATH
          export LD_LIBRARY_PATH=$QTDIR/lib:$LD_LIBRARY_PATH
          qmake -v; }

qt48()  { export QTDIR=/usr/local/Trolltech/Qt-4.8.4
          export PATH=$QTDIR/bin:$PATH
          export LD_LIBRARY_PATH=$QTDIR/lib:$LD_LIBRARY_PATH
          qmake -v; }

qmake -v 那行是自检：切完立刻打印版本，省得你以为切了其实没切。反复叠加 PATH 会让它越来越长，切得勤就干脆开新终端。

CMake 工程不用切环境，构建时指定就够：

bash
cmake -S . -B build-qt515 -DCMAKE_PREFIX_PATH=$HOME/Qt/5.15.2/gcc_64
cmake -S . -B build-qt65  -DCMAKE_PREFIX_PATH=$HOME/Qt/6.5.0/gcc_64

两个构建目录并存，互不覆盖，想跑哪个跑哪个。这比全局切版本舒服，也是 CI 里的标准做法。

Qt Creator 里是另一套概念。每个 Kit 绑一个 qmake，新建项目时选 Kit 就等于选版本。Kit 里 qmake 路径填错，表现是新建项目后构建按钮灰着，或者编译报一堆找不到头文件。切版本就去「工具 → 选项 → Kits」改 qmake 路径，改完重新打开项目。

十二、易错点速查 #

最后一章，全是短条目。装完环境卡住时从上往下扫一遍。

  • PATH 里新路径要放前面。写成 $PATH:$QTDIR/bin 等于没配。
  • 改完环境变量必须重开终端和 Qt Creator，它们不热加载。
  • opt 下的 Qt，引路径要引到 gcc_64 这一层，别停在 /opt/Qt5.6.1。
  • qmake -v 只看第一行不够，第二行的 Using Qt version ... in ... 才是关键。
  • 输出 Qmake version: 1.07a (Qt 3.3.8b)，说明 qmake 被人抢了，去查 /etc/alternatives/qmake。
  • 软链法和 PATH 法选一种用，同时上会互相掩盖，排查时分不清谁生效。
  • .pro 改完必须重跑 qmake，再 make。只 make 等于白改。
  • 安装第三方模块（QtXlsx、Qwt）后，务必重新构建 qmake。
  • INCLUDEPATH 是编译期找头文件，LIBS 是链接期找库，两个都得给。
  • 链接错误先看位数：32 位和 64 位库不能混。
  • 链接错误再看编译器：MinGW 编的 Qt 不能喂给 MSVC。
  • Debug 版 Qt 库带 d 后缀（Qt5Cored.dll），跟 Release 版不能混链。
  • MSVC 下编译，先从「x64 Native Tools Command Prompt」进，别用普通 CMD。
  • MinGW 下 make 换成 mingw32-make，别拿 MSYS 的 make 顶。
  • 程序能编不能跑，先看 LD_LIBRARY_PATH，再看 ldd 输出里的 not found。
  • Windows 上跑不起来且报 platform plugin，检查 exe 旁边有没有 platforms\qwindows.dll。
  • windeployqt 不拷编译器运行时，MinGW 的 libgcc_s_seh-1.dll 得自己补。
  • 源码编 Qt 时给了 -prefix，后面所有环境变量都得按这个前缀写，别照抄 /usr/local/Trolltech。
  • 源码编 Qt 要三个小时左右，别在笔记本合盖状态下跑。
  • 服务器上没有 X11 时，designer 起不来，这不代表 Qt 没装好，回头验 qmake -v 即可。
