这篇是两份移植实录的合稿。一块是飞凌 OK335XD（TI AM335X，Cortex-A8），一块是老牌的 JZ2440（S3C2440，ARM920T）。两块板差了七八年，走的路是同一条：换交叉工具链、重编内核、重编 Qt 库、烧系统、把程序跑起来。

讲什么：一条命令一条命令地走完全程。换工具链动哪个文件、内核 Makefile 改哪几行、EABI 在哪打开、SD 卡与命令行两条烧录路径、Nandflash 启动怎么配、程序怎么丢到板上。

不讲什么：Qt 库源码编译的通用原理，交给 Qt 交叉编译：工具链与源码编译；多块板之间的横向差异，交给 Qt 板级移植实战；板上的工程级实操，交给 两个完整的板上项目：全志 H3 与 mini2440。

本篇的定位很窄：烧录系统和编内核支持 EABI这两块，前面几篇都没覆盖。其余部分按实录写，命令照抄能跑。

一、实录的背景：板子与系统 #

两块板 #

项目 OK335XD JZ2440
CPU TI AM335X，Cortex-A8 Samsung S3C2440，ARM920T
主频 最高 1GHz 400MHz
指令集 armv7-a armv4t
内存 512MB DDR 64MB SDRAM
存储 256MB Nandflash 256MB Nandflash
屏幕 7 寸 1024x600 3.5 寸 320x240 / 4.3 寸 480x272
出厂系统 u-boot-2011.09 + linux-3.2.0 + ubi u-boot + linux-2.6.22.6 + 手工 rootfs

OK335XD 是工业级版本，核心板叫 FET335xD。工业级强调的是高低温、振动、电磁干扰环境下的稳定性，跟移植没直接关系，但选型时值得看一眼。这块板由核心板和底板组成，核心板上就四个大件：CPU、NandFlash、Memory、电源管理。

JZ2440 是学习板里最经典的一批，ARM920T 内核，没有 NEON，没有硬件浮点。这一点决定了后面所有编译选项都得走软浮点，-msoft-float 一个都不能少。

Configured with 那一行原稿有整整一屏，灌了一堆 --enable-*。除了查某特性开没开，平时不看，这里掐掉。

板端这一套是：交叉编译器 4.9.4（Linaro 版）、u-boot-2011.09、linux-3.2.0、ubi 文件系统。这套版本在启动日志里能看到，第九章会贴。

为什么要换工具链 #

原厂给的编译器是 3.4.5（glibc 2.3.6）。这套工具链编个 2.6 时代的内核没问题，编 Qt5 就废了。

第一条硬杠：交叉编译器至少 4.7，才支持 C++11。Qt5 源码里 lambda、auto、右值引用到处是，4.7 以下连编译都过不去。

第二条：Qt 默认不开 C++11。要在工程里用，得在 .pro 里加一行：

makefile
CONFIG += c++11

不加也能编，但你的 lambda 会一路报错，报错信息还指不准位置。

我试过拿 4.3.2 去编 Qt5.6。结论是别试：编译过程中大量报错，改到能编过了，用它编应用程序又是另一批问题。最后换友善提供的 4.4.3，一把过。新手直接从这个版本起步，省两天。

换工具链带出的四件事 #

工具链一换，整条链上的东西全得跟着重做。这就是移植工作量的大头：

  1. 重新编译内核
  2. 制作文件系统
  3. 移植 tslib
  4. 移植 Qt5

内核尤其要紧。旧内核是用老编译器编的，新编译器编的用户态程序跑在旧内核上，ABI 一不对，程序直接飞。所以序列只能是自下而上，不能跳步。

素材清单 #

备齐这几样：交叉编译器 arm-linux-gcc-4.4.3.tar.gz；内核 linux-2.6.22.6.tar.bz2 与板级补丁 linux-2.6.22.6_jz2440.patch；4.3 寸屏的 4.3寸LCD_mach-smdk2440.c；Busybox busybox-1.22.1.tar.bz2；tslib tslib-1.4.tar.gz；Qt 源码 qt-everywhere-opensource-src-5.6.0.tar.gz，OK335XD 那边用 5.9.8 的 .tar.xz。

原稿这些包全挂百度网盘，年头久了链接会失效，密码也就不抄了。作者后来把内核、文件系统、u-boot 放到了 GitHub，仓库地址在第十章末尾。

原稿里的插图全部丢失，只剩注记，比如「图：更换编译器成功界面截图」。这类位置我保留说明，不硬编内容。

二、换交叉编译器的完整过程 #

把东西先归拢 #

所有下载的文件先丢到 /work 下。路径统一，后面每一步的命令才不用改。

解压 #

-C / 是关键，直接把压缩包里的 opt 目录铺到根上：

bash
sudo tar zxvf arm-linux-gcc-4.4.3.tar.gz -C /

解压完立刻确认目录出来了，别等报错才回头查：

bash
ls /opt/FriendlyARM/toolschain/4.4.3/bin

这一串 arm-none-linux-gnueabi-* 就是你要用的全套工具。名字记牢，后面 qmake.conf 里写的就是它，写错一个字母，configure 阶段就找不到编译器。

更换的五步 #

步骤 动作 检查点
1 解压到 /opt/FriendlyARM/toolschain/4.4.3 ls bin 能看到 arm-none-linux-gnueabi-gcc
2 改环境变量，把新路径塞进 PATH echo $PATH 里新路径排在旧路径后面也没关系，但必须在
3 重启虚拟机，或 source 对应文件 新开的终端能读到
4 arm-linux-gcc -v 验证 版本号变成 4.4.3
5 编个 hello world 试链接 无 cannot find -lxxx

第 2 步为什么不要直接改 /etc/environment，第三章单独讲，那是原稿踩过的一个坑。

验证 #

bash
arm-linux-gcc -v

输出里能看到 gcc version 4.4.3，就说明 PATH 生效了。看不到，先查 which arm-linux-gcc，它会告诉你到底命中哪一个。

老虚拟机的额外依赖 #

原稿用的韦老大那套 ubuntu9.10 虚拟机，库是齐的。换成 Ubuntu 14.04 或 16.04，编译 tslib 和 Qt 前得补包：

bash
sudo apt-get install autoconf automake libtool

少了 libtool，tslib 的 autogen.sh 直接退不出来。少了 libxcb 相关的开发包，Qt 编到 xcb 平台插件时中断，第六章会再说这个报错。

三、环境变量怎么设才对 #

原稿踩过的坑 #

第一版做法是改 /etc/environment，把原交叉编译器路径换成新的：

text
# 老工具链的路径，注释掉
# PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/work/tools/gcc-3.4.5-glibc-2.3.6/bin"
PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/opt/FriendlyARM/toolschain/4.4.3/bin"

（原稿里两行都带 #，其中一行又被当标题抓走了。它其实是配置文件内容，不是章节。）

这么写有两个后遗症。一是 make install 都往 /usr/local 装，要 root 权限；sudo 会走 secure_path，把 /etc/environment 里的 PATH 覆盖掉，于是安装过程中零零散散报 command not found。二是非登录 shell 读不到，换个终端窗口就失效。

结论：工具链的 PATH 放 /etc/profile，它对所有用户生效，登录 shell 都会读。

bash
sudo vi /etc/profile

文件末尾加一行，别去动已有内容：

bash
export PATH=$PATH:/opt/FriendlyARM/toolschain/4.4.3/bin

四个可写位置怎么选 #

位置 生效范围 适合放什么 坑
/etc/environment 所有用户、所有登录方式 纯 VAR=value，不解析 shell 语法 sudo 的 secure_path 会盖掉它
/etc/profile 所有用户的登录 shell 交叉工具链 PATH 非登录 shell 不读，su - user 才读
~/.bashrc 当前用户的交互 shell 临时试验、别名 sudo 不继承，切用户丢失
板端 /etc/profile 板上所有进程 Qt 运行环境、tslib 变量 写错一个路径，整个图形程序起不来

sudo 下确实需要工具链，用显式传参，别改全局：

bash
sudo env PATH=$PATH make install

宿主机侧：只加工具链 #

宿主机要的就一件事，让 arm-linux-gcc 能被找到：

bash
which arm-linux-gcc
arm-linux-gcc -v

which 命中的路径必须是 /opt/FriendlyARM/toolschain/4.4.3/bin/ 那个。命中老路径，说明 /etc/profile 里有更靠前的 PATH 定义，或者当前 shell 还是旧环境。

板端侧：一张总表 #

板端 /etc/profile 的变量比宿主机多，每个都卡着程序的启动路径。先把作用理清：

变量 作用 OK335XD 取值 JZ2440 取值

LD_LIBRARY_PATH 动态库搜索路径 $QTDIR/lib:$QTDIR/tslib/lib /usr/local/Qt5.6/lib
QT_QPA_PLATFORM_PLUGIN_PATH 平台插件目录 $QTDIR/plugins/ $QTEDIR/plugins
QT_QPA_PLATFORM 显示后端与屏参 linuxfb:fb=/dev/fb0:size=1024x600... linuxfb:fb=/dev/fb0:size=480x272...
QT_QPA_GENERIC_PLUGINS 触摸插件名 tslib tslib
QT_QPA_FB_TSLIB 让 linuxfb 认 tslib 不设 1
QT_QPA_FONTDIR 字体目录 $QTDIR/fonts $QTEDIR/lib/fonts

OK335XD 的完整 profile #

板上 Qt 装在 /opt/QT5.9_A8，tslib 也并进去，路径统一：

bash
/opt/QT5.9_A8/tslib >: pwd
/opt/QT5.9_A8/tslib
/opt/QT5.9_A8/tslib >: vim /etc/profile

文件内容，QT configuration 往下是关键段：

bash
#!/bin/sh
export PATH=\
/bin:\
/sbin:\
/usr/bin:\
/usr/sbin:\
/opt/QT5.9_A8/lib

export PS1='\w >: '
export USER=`id -un`
export LOGNAME=$USER
export HOSTNAME=`/bin/hostname`

# QT configuration
export QTDIR=/opt/QT5.9_A8
export QT_QPA_FONTDIR=$QTDIR/fonts
export QT_QPA_PLATFORM_PLUGIN_PATH=$QTDIR/plugins/
export LD_LIBRARY_PATH=$QTDIR/lib:$QTDIR/tslib/lib:$LD_LIBRARY_PATH
export QT_QPA_PLATFORM=linuxfb:fb=/dev/fb0:size=1024x600:mmSize=1024x600:offset=0x0:tty=/dev/tty1

export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/lib:/usr/lib
export PATH=$PATH:/opt/QT5.9_A8/tslib/lib

# Touch Screen configuration
export QT_QPA_GENERIC_PLUGINS=tslib
export TSLIB_FBDEVICE=/dev/fb0
export TSLIB_TSDEVICE=/dev/input/event0
export TSLIB_CALIBFILE=/etc/pointercal
export TSLIB_CONFFILE=$QTDIR/tslib/etc/ts.conf
export TSLIB_PLUGINDIR=$QTDIR/tslib/plugins
export QML2_IMPORT_PATH=$QTDIR/qml

USER、LOGNAME 下面原本还有 HISTSIZE、HISTFILESIZE、PAGER、EDITOR、INPUTRC、network_cfg_dir，以及 ll、df 几个别名，跟移植无关，这里省掉。

三点说明。PATH 用了续行符，逐行往下排，比一整行长串好改。QT_QPA_FONTDIR 指向的 fonts 目录当时并不存在，字库还没移植，先写着不报错，用中文字体时才需要。QML2_IMPORT_PATH 只有跑 QML 才用，纯 Widgets 项目可以不写。

原稿在这几行后面还跟了 // 开发板上QT存放的路径 这类行内注释。shell 里 // 不是注释符，抄的时候要么删掉，要么换成 #，放行尾会被当成命令参数。

JZ2440 的完整 profile #

Qt5.6 装在 /usr/local/Qt5.6，tslib 在 /usr/local/tslib，两套分开：

bash
#!/bin/sh
# tslib
export T_ROOT=/usr/local/tslib
export LD_LIBRARY_PATH=/usr/local/tslib/lib:$LD_LIBRARY_PATH
export TSLIB_CONSOLEDEVICE=none
export TSLIB_FBDEVICE=/dev/fb0
export TSLIB_TSDEVICE=/dev/input/event0
export TSLIB_PLUGINDIR=$T_ROOT/lib/ts
export TSLIB_CONFFILE=$T_ROOT/etc/ts.conf
export POINTERCAL_FILE=/etc/pointercal
export TSLIB_CALIBFILE=/etc/pointercal

# Qt
export QTEDIR=/usr/local/Qt5.6
export LD_LIBRARY_PATH=/usr/local/Qt5.6/lib:$LD_LIBRARY_PATH
export QT_QPA_GENERIC_PLUGINS=tslib
export QT_QPA_FONTDIR=$QTEDIR/lib/fonts
export QT_QPA_PLATFORM_PLUGIN_PATH=$QTEDIR/plugins
export QT_QPA_PLATFORM=linuxfb:fb=/dev/fb0:size=480x272:mmSize=480x272:offset=0x0:tty=/dev/tty1
export QT_QPA_FB_TSLIB=1

tslib 段和 Qt 段顺序别倒：LD_LIBRARY_PATH 是累加的，谁先写谁在前。屏参按自己的屏改，3.5 寸 320x240 就把 size=480x272:mmSize=480x272 换成 size=320x240:mmSize=320x240。JZ2440 V3 的 4.3 寸屏用 480x272 正好。

三个立刻能测出来的错 #

  1. ts_calibrate 报 error while loading shared libraries: libts.so.0：LD_LIBRARY_PATH 里漏了 tslib 的 lib 目录。
  2. 界面只占屏幕左上角一块，或者整个花掉：QT_QPA_PLATFORM 里的 size 和实际分辨率不符。
  3. 程序起来就退出，日志里有 QFontDatabase: Cannot find font directory：QT_QPA_FONTDIR 指向了空目录。

四、重新编译内核 #

为什么非编不可 #

换工具链就得重编内核，理由有三个：老内核跟新工具链的 ABI 不匹配；EABI 要在内核配置里打开；板级补丁要重新打一遍。

内核源码用 linux-2.6.22.6，配 JZ2440 的板级补丁。手上不是 JZ2440 也没关系，用自己板子已经移植好的内核重编一遍即可，重点只有一个：内核里必须开 EABI。

解压与打补丁 #

bash
tar jxvf linux-2.6.22.6.tar.bz2
cd linux-2.6.22.6
patch -p1 < ../linux-2.6.22.6_jz2440.patch

-p1 是跳过一层目录前缀。补丁打不上，先看 patch 输出里的 .rej 文件名，多半是源码版本不对。

4.3 寸屏的 JZ2440 要换 LCD 驱动，3.5 寸的跳过这步：

bash
mv ../4.3寸LCD_mach-smdk2440.c arch/arm/mach-s3c2440/mach-smdk2440.c

改 Makefile：两处 #

不改，4.4.3 编译器编到一半就停。

第一处是版本号。友善做这款工具链时塞了个最低内核版本限制（2.6.32.2），直接编出来启动会报 kernel too old，卡在那儿不动。折中办法是把内核版本号骗上去：

makefile
VERSION = 2
PATCHLEVEL = 6
SUBLEVEL = 22
EXTRAVERSION = .6

把 SUBLEVEL = 22 改成 SUBLEVEL = 32。这只骗过工具链的检查，内核本身还是 2.6.22.6 的代码。改版本号有副作用，模块路径 lib/modules/2.6.32.6 会跟着变，正式做产品该换更高版本的内核，别在这上面凑合。

第二处是调试信息格式。4.4.3 不认 gdwarf2：

makefile
ifdef CONFIG_DEBUG_INFO
CFLAGS += -g
AFLAGS += -gdwarf2
endif

注释掉 AFLAGS += -gdwarf2 那一行：

makefile
# AFLAGS += -gdwarf2

编 #

bash
make uImage -j4

产物在 arch/arm/boot/uImage。-j4 按机器核数给，虚拟机单核就写 -j2，别硬堆，内存不够会 OOM。

改动点 位置 不改的后果
板级补丁 arch/arm/mach-s3c2440/ 等 编出来跑不到自己板上
LCD 驱动 mach-smdk2440.c 屏不亮或分辨率错
SUBLEVEL 顶层 Makefile 启动报 kernel too old
AFLAGS += -gdwarf2 顶层 Makefile 编到汇编阶段报错
CONFIG_AEABI menuconfig 用户态程序跑飞

五、让内核支持 EABI #

EABI 是什么，为什么值一章 #

ARM 有两套 ABI：老的 OABI 和新的 EABI（Embedded Application Binary Interface）。两者不是换个名字，是调用约定真的不一样。

差别主要在浮点和结构体。浮点参数走 VFP 寄存器还是走栈，float 提升成 double 的时机，结构体按 4 字节还是 8 字节对齐——这些规则两边不同。编译器按一套规则放参数，内核或库按另一套规则取，取出来的就是垃圾。

表现出来的症状很不讲道理：程序起来就段错误，栈回溯对不上，或者动态链接器直接报 GLIBC not found。看着像库的问题，根子在 ABI 不一致。

规矩只有一条：内核、Qt 库、你的应用，必须用同一套 EABI 规则编出来。

打开配置 #

bash
make menuconfig

路径：

text
Kernel Features ->
    <*> Use the ARM EABI to compile the kernel

这一项必须选中。开完保存，.config 里会出现 CONFIG_AEABI=y，编完再确认一次：

bash
grep AEABI .config

三条链上的对齐 #

环节 该有的样子 查法
交叉编译器 4.4.3（或更高，≥4.7 支持 C++11） arm-linux-gcc -v
内核 CONFIG_AEABI=y，启用 EABI grep AEABI .config
Qt 库 用同一个 arm-linux-* 前缀编 qmake.conf 里的 QMAKE_CC
应用程序 用同一个 Qt 的 qmake 生成 which qmake

这四行任何一行错位，运行时都炸。移植里七八成的坑，都在这张表里。工具链换了，内核和 Qt 库都得用同一套工具链重编，缺一环就等着在板上排错。

有个快速判断法：把板上的可执行文件拉回 PC，用工具链自带的 readelf -A 看 ABI 属性。

bash
arm-linux-readelf -A your_app | head -20

输出里 Tag_ABI_VFP_args 一行，写 VFP registers 还是 AAPCS，是硬浮点和软浮点的分界线。老 ARM9 板子（JZ2440、mini2440）只有软浮点一条路，编 Qt 时 -msoft-float 必须带上；Cortex-A8/A9 才能谈硬浮点。

六、编译 Qt 库 #

先编 tslib #

Qt 的 linuxfb 后端要靠 tslib 拿触摸坐标，所以 tslib 必须先在。JZ2440 用 tslib-1.4：

bash
tar zxvf tslib-1.4.tar.gz
sudo mkdir -p /usr/local/tslib
cd tslib
./autogen.sh
./configure --host=arm-linux ac_cv_func_malloc_0_nonnull=yes --prefix=/usr/local/tslib
make
sudo make install

ac_cv_func_malloc_0_nonnull=yes 是绕开 gnulib 那个 rpl_malloc 的老问题，先给 configure 一个确定答案。

编的过程中真撞上 undefined reference to 'rpl_malloc'，改 config.h.in：把文件末尾的 #undef malloc 注释掉，重新 make。

装完改配置文件，这步不做触摸永远没反应：

bash
cd /usr/local/tslib/etc/
sudo vi ts.conf

把 # module_raw input 前面的 # 和空格去掉：

module_raw input

打包装进根文件系统：

bash
cd /usr/local
sudo tar zcvf tslib.tar.gz tslib
mkdir -p /work/my_rootfs/usr/local
cp tslib.tar.gz /work/my_rootfs/usr/local
cd /work/my_rootfs/usr/local
tar zxvf tslib.tar.gz
rm tslib.tar.gz

OK335XD 那边用的是 tslib-1.16，源码放 /home/tavi/ok335x/3rdparty/qt/tslib/tslib-1.16，安装结果统一落到 /home/tavi/ok335x/3rdparty/install：

改 mkspecs，这一步决定编出来的库能不能跑 #

Qt 自带 linux-arm-gnueabi-g++ 这个 mkspec，但里面的 CPU 参数是泛指的，得按自己的板子改：

bash
cd /work/qt-everywhere-opensource-src-5.6.0/qtbase/mkspecs/linux-arm-gnueabi-g++
vi qmake.conf

JZ2440（ARM920T）这么写：

makefile
QT_QPA_DEFAULT_PLATFORM = linuxfb
QMAKE_CFLAGS += -msoft-float -D__GCC_FLOAT_NOT_NEEDED -march=armv4t -mtune=arm920t
QMAKE_CXXFLAGS += -msoft-float -D__GCC_FLOAT_NOT_NEEDED -march=armv4t -mtune=arm920t

march 是 CPU 架构，mtune 是具体型号。2440 是 armv4t + arm920t，写错了编出来的指令板子不认，一执行就 Illegal instruction。

换板子按这张表改：

板子 CPU -march -mtune 浮点
JZ2440 S3C2440 / ARM920T armv4t arm920t 软浮点
Tiny6410 S3C6410 / ARM1176 armv6 arm1176jzf-s 软浮点
OK335XD AM335X / Cortex-A8 armv7-a cortex-a8 软浮点或 -mfpu=neon
IMX6 i.MX6 / Cortex-A9 armv7-a cortex-a9 同上

Cortex-A8 的写法就是把两行换成：

makefile
QMAKE_CFLAGS  += -msoft-float -D__GCC_FLOAT_NOT_NEEDED -march=armv7-a -mtune=cortex-a8
QMAKE_CXXFLAGS += -msoft-float -D__GCC_FLOAT_NOT_NEEDED -march=armv7-a -mtune=cortex-a8

Cortex-A9 同理，-mtune=cortex-a9。

再往下是编译器定义段，关键是加 -lts，让链接时挂上 tslib：

makefile
# modifications to g++.conf
QMAKE_CC = arm-none-linux-gnueabi-gcc -lts
QMAKE_CXX = arm-none-linux-gnueabi-g++ -lts
QMAKE_LINK = arm-none-linux-gnueabi-g++ -lts
QMAKE_LINK_SHLIB = arm-none-linux-gnueabi-g++ -lts

# modifications to linux.conf
QMAKE_AR = arm-none-linux-gnueabi-ar cqs
QMAKE_OBJCOPY = arm-none-linux-gnueabi-objcopy
QMAKE_NM = arm-none-linux-gnueabi-nm -P
QMAKE_STRIP = arm-none-linux-gnueabi-strip

-lts 挂在编译命令上看着怪，实际是链接期的依赖，4.4.3 这套工具链容忍它。少这一行，Qt 编得过，但 linuxfb 插件里的触摸代码找不到 ts_read 符号。

configure 与编译 #

bash
sudo mkdir -p /usr/local/Qt5.6
cd ../../../
./configure \
  -prefix /usr/local/Qt5.6 \
  -opensource \
  -release \
  -confirm-license \
  -xplatform linux-arm-gnueabi-g++ \
  -shared \
  -qt-zlib \
  -no-gif \
  -qt-libjpeg \
  -no-nis \
  -no-opengl \
  -no-cups \
  -no-glib \
  -no-dbus \
  -no-rpath \
  -no-sse2 -no-sse3 -no-ssse3 -no-sse4.1 -no-sse4.2 \
  -no-avx \
  -no-openssl \
  -nomake tools \
  -qreal float \
  -qt-libpng \
  -tslib \
  -nomake examples \
  -I /usr/local/tslib/include \
  -L /usr/local/tslib/lib
选项 干什么 省掉的代价
-xplatform linux-arm-gnueabi-g++ 指定 mkspec 编成 x86 版本，板上跑不了
-prefix /usr/local/Qt5.6 安装路径 库散在源码树里，打包麻烦
-shared 编动态库 静态链接，单个程序几十兆
-no-opengl 关 OpenGL 老板没 GPU，开着只多编一堆废码
-qreal float qreal 用 float 默认 double，ARM9 上软浮点慢一倍
-tslib 接上触摸库 触摸没反应
-no-sse2 一串 关 x86 SIMD configure 把宿主机当成目标机，编出一堆 x86 指令
-no-pch 未加 保留预编译头 —

-qreal float 这行别漏。默认 qreal 是 double，ARM9 没有 FPU，double 全靠软浮点模拟，界面重绘能慢到肉眼可见。

七、烧录系统：SD 卡方式 #

什么时候必须走 SD 卡 #

Nandflash 出厂是空的，或者被擦坏了，板上没有任何可执行代码，这时候只能让 CPU 从 SD 卡起 u-boot。这是唯一一条不依赖板上存储的启动路径。

推荐做法：HPUSBFW #

把 SD 卡插进笔记本的卡槽，用官方推荐的 HPUSBFW 格式化。这个工具的关键作用不是格式化，是把分区设成活动分区。不设活动分区，开发板上电就找不到启动代码，卡里的东西全在也没用。

原稿的截图丢了，位置在「HPUSBFW 格式化 SD 卡」和「SD Card Formatter 格式化界面」两处。

备选：SD Card Formatter + diskpart #

SD Card Formatter 也能格式化，但它不设活动分区。补这一步用 Windows 自带的 diskpart：

text
Windows + R  ->  输入 diskpart
list disk
select disk 2          # 认准 SD 卡的编号
list partition
select partition 1
active

select disk 这一步千万别选错，选成系统盘就是另一回事了。

放引导文件 #

分区做好，把编译出来的两个引导镜像拷到分区根目录：

text
MLO
u-boot.img

MLO 是 SPL，必须第一个被找到，所以放根目录、文件名不能改。这两块是 AM335X 的规矩，三星的板子不认 MLO。

工具 设活动分区 适用 备注
HPUSBFW 自动 首选 官方推荐，一步到位
SD Card Formatter 不设 备选 需再跑 diskpart
diskpart 手动 补救 Windows 自带，无依赖
Linux fdisk + dd 手动 批量刷整盘镜像 见下一章

八、烧录系统：命令行方式 #

拨码开关定启动介质 #

OK335X 支持 SD 卡和 Nandflash 两种启动，由拨码开关决定。老板子是两个拨码：

  • SD 卡启动：1 On，2 On
  • Nandflash 启动：1 Off，2 On

（On 是拨到上方，Off 是拨到下方。）

新买的 OK335XD 简化成一个拨码：

  • SD 卡启动：拨到 On
  • Nandflash 启动：拨到 Off

从 SD 卡进 u-boot #

卡插好，拨码拨到 SD，上电。串口接 console 口，波特率 115200，盯住输出，按任意键打断自动启动，再输入 0 进 u-boot 命令行。

bash
OK335X# setenv ipaddr 192.168.2.222        # U-boot 自己的 IP
OK335X# setenv serverip 192.168.2.2        # tftp 服务器（你的 PC）IP
OK335X# pri                                # 打印当前环境变量，核对一遍

两个 IP 必须在同一网段，serverip 指向跑 tftp 服务的那台机器。

擦干净再写 #

bash
OK335X# nand erase.chip
NAND erase.chip: device 0 whole chip
100% complete
OK

erase.chip 是整片擦除，包括环境变量区。擦完先存一次环境变量，否则重启后 ipaddr 又没了：

bash
OK335X# save

一键烧三样 #

uboot 的脚本里预先写好了命令序列，直接 run：

bash
OK335X# run bsys

这一条会把 u-boot、linux 内核、根文件系统依次通过 tftp 拉到内存，再写进 Nandflash 的对应分区。分区偏移就是第九章日志里那六个 MTD 分区。

手工分步（脚本没跑通时） #

run bsys 挂住，就退回手工。套路是 tftp 下载到内存，再 nand write 到偏移：

bash
OK335X# tftp 0x82000000 uImage
OK335X# nand write 0x82000000 0x100000 0x500000

内核分区的起始偏移 0x100000、长度 0x500000，与第九章的分区表一一对应。写错偏移，板子起来是黑屏。

另外两条路：dd 与 fastboot #

dd 走整盘镜像。PC 上把整个系统合成一个 .img，直接把镜像怼到 SD 卡裸设备：

bash
sudo dd if=ok335xd_sd.img of=/dev/sdb bs=4M conv=fsync

of= 后面是整块卡，不是分区（/dev/sdb，不是 /dev/sdb1）。这条命令没有确认步骤，敲错设备名就毁了别的盘。写完用 sync 冲一次缓存再拔卡。

fastboot 走 USB。板子进 fastboot 模式后，在 PC 上推镜像：

bash
fastboot flash boot uImage
fastboot flash rootfs rootfs.ubi
fastboot reboot

这条路适合批量生产：不用拆卡、不用接串口，USB 一插一条命令一个板子。

方式 通道 适用场景 风险点
SD 卡启动 + run bsys 网线 tftp 首次烧录、救砖 拨码与 IP 配错
手工 tftp + nand write 网线 tftp 换单个分区（只换内核） 偏移写错
dd 整盘镜像 SD 读卡器 批量做启动卡 设备名选错
fastboot USB 产线批量刷机 需要板子支持 fastboot
Nandflash 内升级 板上 u-boot 系统已在跑，升级组件 断电即砖

九、Nandflash 启动配置 #

拨回去，拔卡，上电 #

系统烧完，断电，拔掉 SD 卡，拨码拨到 Nandflash，重新上电。板子这时从 Nandflash 起 u-boot，再引导内核。

想单独升级怎么办 #

板子已经在跑，只想换内核，就不必再走 SD 卡+run bsys。断电重上，串口按任意键停在 u-boot，然后 tftp 拉新内核，nand write 到 0x100000，reset。

这条路省事，但断电时机不对就是砖。手上要备着一张启动卡。

中文字体 #

默认移植出来的 Qt 不认中文，界面上全是方块。

先把字库放到位，DroidSansFallback.ttf 丢进 /usr/local/Qt5.6/lib/fonts。字库没放进去之前，QT_QPA_FONTDIR 指过去也只是个空目录。

工程里 .pro 加一行：

makefile
QT += gui

main.cpp 里注册字体，再给整个应用设上：

cpp
#include <QFontDatabase>

int id = QFontDatabase::addApplicationFont("/usr/local/Qt5.6/lib/fonts/DroidSansFallback.ttf");
QString msyh = QFontDatabase::applicationFontFamilies(id).at(0);
QFont font(msyh, 10);
font.setPointSize(20);
this->setFont(font);

addApplicationFont 返回 -1 说明路径不对或文件损坏，后面 .at(0) 会直接崩。先判一下再往下走。

缺 libiconv 会让中文变成 Latin-1 #

程序跑起来，日志里刷这两行：

text
QIconvCodec::convertFromUnicode: using Latin-1 for conversion, iconv_open failed
QIconvCodec::convertToUnicode: using Latin-1 for conversion, iconv_open failed

意思是系统的 iconv 不可用，Qt 退回 Latin-1，中文全废。交叉编一个 libiconv 补上：

bash
mkdir -p /usr/local/libiconv
./configure --host=arm-none-linux-gnueabi --prefix=/usr/local/libiconv \
  CC=arm-none-linux-gnueabi-gcc \
  LDFLAGS="-L/opt/FriendlyARM/toolschain/4.4.3/arm-none-linux-gnueabi/sys-root/lib" \
  --enable-static
make
sudo make install

把 preloadable_libiconv.so 拷到板上 /lib，再在 /etc/profile 末尾加一行 export LD_PRELOAD=/lib/preloadable_libiconv.so。

LDFLAGS 指向 sys-root/lib 这一句不能省，否则链接 stage 找不到 glibc 的桩库，编到一半停。

用 qmake 编应用 #

在 Windows 的 Qt Creator 里把界面画好、调试顺，再把源码拷到虚拟机编。先手动跑一遍，确认产物是 ARM 的，再传上板：

bash
/usr/local/Qt5.6/bin/qmake
make
scp your_app root@192.168.1.17:/apps/

嫌全路径难敲，把 /usr/local/Qt5.6/bin 加进 PATH。但要注意，加了之后 qmake 就是交叉版的了，PC 上的原生编译会被它接管，用的时候心里有数。

OK335XD 那边的做法一样：Ubuntu 下新建测试工程，Qt Creator 里配好交叉编译器，编译出可执行文件，拷到板上跑。

十一、验证与排错 #

验证顺序不能反 #

按这个顺序走，出问题能立刻定位在哪一层：

  1. ts_calibrate：能弹出校准界面，说明 fb、tslib、触摸三者通了
  2. ts_test：画点、拖线，坐标跟手指对得上
  3. 一个空窗口的 Qt 程序：能起窗，说明 Qt 库和插件加载正常
  4. 正式程序：看业务逻辑

第一关过不了，别往下试。后面所有报错都是它的衍生现象。

JZ2440 上直接 cd /usr/local/tslib/bin && ./ts_test，能画点、能拖线就过关。OK335XD 上 tslib 的 bin 目录被改名成 tests，里面十个测试程序齐全，先 cd 进去：

bash
/opt/QT5.9_A8/tslib >: cd tests/
ts_calibrate  ts_finddev  ts_harvest  ts_print  ts_print_mt  ts_print_raw
ts_test  ts_test_mt  ts_uinput  ts_verify  iconv
/opt/QT5.9_A8/tslib/tests >: ./ts_calibrate

屏幕弹出十字校准界面，点完五个点，校准值写进 /etc/pointercal。这个文件删了就得重新校。

触摸那个坑值得单说 #

selected device is not a touchscreen I understand 这条报错看着像 tslib 的问题，其实在更下层。

内核 include/linux/input.h 里定义 EV_VERSION 为 0x0100000，tslib 编译时按自己头文件里的宏去比对设备上报的版本号，两边不一致就拒绝打开设备。老内核配新 tslib，或者反过来，必撞。

处理办法：改内核头文件里的 EV_VERSION 对齐，然后重编内核，重点是触摸驱动那部分。只重装 tslib 没用。

十二、易错点速查 #

易错点 现象 正确做法
工具链放 /etc/environment sudo make install 报 command not found 放 /etc/profile，或 sudo env PATH=$PATH
只换了编译器没重编内核 程序起来段错误、GLIBC not found 内核、Qt 库、应用全用同一套工具链重编
内核没开 CONFIG_AEABI 用户态程序跑飞，栈回溯对不上 Kernel Features 里勾上 EABI
-march 抄了别人的值 Illegal instruction 按 CPU 查表：2440 用 armv4t，A8 用 armv7-a
漏 -msoft-float ARM9 上浮点计算异常或奇慢 老板子必须带，A8/A9 再谈硬浮点
SUBLEVEL 没改 启动报 kernel too old 改 Makefile，正式产品换高版本内核
AFLAGS += -gdwarf2 没注释 4.4.3 编到汇编阶段中断 注释掉这一行
SD 卡没设活动分区 板上电不认卡，无任何输出 HPUSBFW 格式化，或 diskpart active
忘了放 MLO 板子从 SD 卡起不来 MLO 和 u-boot.img 都放根目录，文件名不改
nand write 偏移写错 起来黑屏或跑飞 对照分区表，Kernel 起始 0x100000
擦完没 save 重启后 IP 配置丢失 nand erase.chip 之后立刻 save
ts.conf 里 module_raw input 被注释 触摸完全没反应 去掉行首 # 和空格
-qreal float 漏了 界面重绘慢得明显 configure 带上，ARM9 上没有 FPU
字库路径写死成 PC 路径 板上中文全是方块 用板上绝对路径，addApplicationFont 查返回值
LD_PRELOAD 指向不存在的 .so 所有程序起来就报加载失败 先确认 /lib/preloadable_libiconv.so 在位
板上删了 plugins 程序报 This application failed to start because no Qt platform plugin plugins/platforms 必须跟着 lib 一起拷

移植这件事，难点从来不在某一条命令，而在「工具链/内核/库三者版本要对齐」这一条线。换交叉编译器，就把内核和 Qt 库都当新的重来一遍；看上去多花的那些编译时间，比在板上靠串口日志猜问题省得多。
