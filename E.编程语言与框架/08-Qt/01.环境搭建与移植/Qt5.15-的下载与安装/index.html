这篇只讲一件事：把 Qt 装到机器上。下载渠道、在线安装器、组件怎么挑、装完的目录长什么样、各系统的环境变量、验证与踩坑，都在这十二节里。

不讲的部分：Qt Creator 的界面与快捷键配置（同目录《Qt Creator 与开发环境配置》）；Qt 源码编译、交叉编译与嵌入式移植、Android 打包（父目录下各组）；qmake 与 CMake 的工程写法（构建工具一组）。

路径示例统一用 D:\Qt（Windows）与 ~/Qt（Linux / macOS）。版本号以官网当前发布为准，本文不写发布日期。

一、装 Qt 要装哪几样东西 #

不少人对「装 Qt」的理解是装一个 IDE。装完打不开工程、编译报链接错误，根子都在这个误解上。Qt 实际由三部分组成，缺一块就跑不起来：

组成 里面有什么 装了它你得到什么 缺了会怎样
Qt 库 QtCore、QtGui、QtWidgets、QtNetwork、QtSql、QtMultimedia、QtQml 等模块的 dll / so / a，外加全套头文件 #include <QWidget> 能编过，符号能链上 找不到头文件；链接期一堆 undefined reference
开发工具 Qt Creator、moc、uic、rcc、qmake、windeployqt / macdeployqt 信号槽能被展开成 C++、.ui 能转 .h、.qrc 能进二进制、程序能打包发布 undefined reference to vtable for Xxx；改 .ui 不生效；发布后客户机上缺 dll
编译器套件 Windows：MinGW（自带 GCC 8.1）或 MSVC（要另装 Visual Studio）；Linux：系统 GCC；macOS：Clang 真正把 .cpp 变成 .exe / 可执行文件 工程建好了，构建按钮是灰的，提示 no valid kits

三者的绑定关系，看一个目录就明白：

text
D:\Qt\Qt5.15.2\5.15.2\mingw81_64\   ← 一个「套件」，名字里写死了编译器
    include\        Qt 库的头文件
    lib\            Qt 库的 .a / .dll.a，链接用
    bin\            Qt5Core.dll 等运行库 + moc.exe / uic.exe / rcc.exe
    plugins\        platforms\qwindows.dll、imageformats\ 等运行时插件
    mkspecs\        qmake 的编译规则，决定用哪个编译器、加哪些 flag

mingw81_64 这个名字的含义是「GCC 8.1 + 64 位」。同一个 5.15.2 下面还并列着 msvc2019_64，两套库互不通用。安装器里勾组件，本质就是在这三样里挑一套对得上的组合：库给你了，工具给你了，编译器要么安装器顺手装（MinGW），要么你自己先去装（MSVC）。

一句话记法：选组件 = 选编译器 + 选位数 + 选要不要附加模块。

套件名是安装器、aqt、CMake 共用的叫法，认几个常用后缀，看到名字就知道它拿什么编译器：

套件名 编译器 位数 出现场合
mingw81_64 MinGW GCC 8.1 64 Windows + MinGW 套件
mingw81_32 MinGW GCC 8.1 32 Windows + MinGW 套件（32 位）
msvc2019_64 MSVC 2019（VS 16.x） 64 Windows + VS 2019
msvc2019_32 MSVC 2019 32 Windows + VS 2019（32 位）
gcc_64 系统 GCC 64 Linux 官方二进制
clang_64 Clang 64 macOS 官方二进制
android_arm64_v8a NDK 里的 Clang arm64 Android 目标，见 Android 一组

名字里的数字不是装饰，msvc2017_64 和 msvc2019_64 是两套库，配套的 VS 版本不同，混用一样是链接期报错。

二、版本怎么选：LTS 与最新版 #

Qt 的版本线不复杂，记住 LTS 就够用：

大版本 LTS 版本 现状 什么时候选
Qt 4 无正式 LTS 说法 早已停止维护 只有维护十几年前的老项目时才碰
Qt 5 5.15 Qt5 的最后一个 LTS 维护存量项目、依赖 Qt5 独有模块、目标平台没有 Qt6 支持
Qt 6 6.2、6.5 Qt6 的 LTS 线 新项目默认走这条线，选官网仍在维护的那个 6.x LTS
Qt 6 6.x 最新版 非 LTS，生命周期短 想尝新特性、能接受升级折腾

三个事实先摆清楚：

  1. Qt 5.15 是 Qt5 的最后一个 LTS。Qt5 这条线到它为止，之后全是 Qt6。
  2. Qt6 的 LTS 是 6.2 和 6.5。要上 Qt6，就选 LTS，别选中间的非 LTS 版本。
  3. 新项目直接上 Qt6 LTS，维护老项目留 5.15。这条判断能省掉后面很多返工。

5.15 的开源版补丁停在 5.15.2，再往后的 5.15.x 只对商业授权开放，具体到哪一个小版本，以官网为准。也就是说，用开源版 5.15 就是拿 5.15.2 长期用下去，没有新补丁。它是 LTS，但它不是还在更新的 LTS。

两个大版本的语言要求也不一样：Qt6 要 C++17，Qt5 用 C++11 就够。Qt6 把 QTextCodec、QRegExp 这一类挪进了 core5compat 模块，从 5.15 迁到 6 得改 include 和少量 API。

按场景对号入座：

text
新项目，没有历史包袱              → Qt6 的 LTS
要兼容 Win7 / 老系统 / 老编译器    → Qt 5.15
手上项目是 5.15，还要继续维护      → 5.15.2 开源版，或买商业授权拿补丁
只是学 Qt 语法、跑跑示例           → 哪个装得上用哪个，5.15 资料更多

三、在线安装器与离线包 #

Qt 官方下载入口只有一个域名：download.qt.io。找安装器看这三个地址：

text
https://download.qt.io/official_releases/online_installers/    当前在线安装器
https://download.qt.io/archive/qt/                             历史版本与旧离线包
https://download.qt.io/archive/online_installers/              旧版在线安装器

三个平台的安装器文件名长得像这样：

平台 文件名 备注
Windows qt-unified-windows-x86-online.exe 32 位安装器，能装 64 位套件
Linux qt-unified-linux-x64-online.run 下载后 chmod +x
macOS qt-unified-macOS-x64-online.dmg 挂载后拖进 Applications

5.15 起，开源版不再提供离线安装包。官方在 5.15.0 目录下的 OFFLINE_README.txt 写得很直白：

text
Due to The Qt Company offering changes, open source offline installers are not
available any more since Qt 5.15.
Read more about offering changes in the https://www.qt.io/blog/qt-offering-changes-2020 blog.

If you need offline installers, please consider our new Qt for Small Business
offering: https://www.qt.io/blog/available-now-qt-for-small-businesses

翻成一句话：从 5.15 开始，开源用户只能用在线安装器；要离线包就买商业版 / Small Business。所以本篇的安装步骤全部围绕在线安装器写。

在线安装器吃网络，国内直连官方源要拉几十兆到几个 G，加镜像能省一大截时间。

Windows 上在 cmd 里带镜像参数启动：

bash
qt-unified-windows-x86-online.exe --mirror https://mirrors.tuna.tsinghua.edu.cn/qt/

Linux 上先给执行权限，再带参数启动：

bash
chmod +x qt-unified-linux-x64-online.run
./qt-unified-linux-x64-online.run --mirror https://mirrors.ustc.edu.cn/qtproject/

可用的镜像以各高校镜像站当前目录为准，路径后缀不一定是 /qt/，进站看一眼再填。

公司网络走代理的，安装器读的是系统代理设置（Windows 在「Internet 选项 → 连接 → 局域网设置」），界面里没有填代理的输入框。代理需要认证时先把本机代理挂好，再启动安装器，否则第一次请求就失败。

不想开图形界面、想在 CI 里批量铺环境，用 aqtinstall 更省事：

bash
pip install aqtinstall
python -m aqt list-qt windows desktop --arch 5.15.2
python -m aqt install-qt windows desktop 5.15.2 win64_mingw81 -O C:\Qt

第一条列出 5.15.2 有哪些架构可装，第二条把 MinGW 64 位套件装进 C:\Qt。aqt 拉的是官方二进制，路径布局与图形安装器一致，kit 指向同一个 bin 就行。

还有一条路是操作系统自带的包管理器（Linux 的 apt / dnf、macOS 的 brew）。版本由发行版决定，装出来的不是官方二进制，路径也和在线安装器不同。要跟官方文档对齐，用在线安装器；只想快点有个能编的 Qt，包管理器更省事。

四、安装器的组件选择 #

选中 Qt 5.15.2 那一行，右边会出现一堆可选套件与模块。这张表按「装不装」排：

组件路径 装不装 说明
Qt 5.15.2 → MinGW 8.1.0 64-bit 纯 Qt 开发勾 64 位 自带 GCC，装完即可编译，最省事的一条路
Qt 5.15.2 → MinGW 8.1.0 32-bit 要出 32 位程序才勾 与 64 位并存不冲突
Qt 5.15.2 → MSVC 2019 64-bit 用 Visual Studio 编译就勾 编译器本身要另装 VS 2019，安装器只给 Qt 库
Qt 5.15.2 → MSVC 2019 32-bit 同上，按位数需要 32 位工程必须配 32 位库，混用直接链接失败
Qt 5.15.2 → Sources 想单步进 Qt 源码就勾 几个 G，调试期很值，出问题也靠它看实现
Qt 5.15.2 → Qt Charts 画统计图就勾 独立模块，不勾就得自己编
Qt 5.15.2 → Qt WebEngine 嵌网页才勾 体积最大的一块，编译产物几百 MB 起
Qt 5.15.2 → Qt Debug Information Files 要看崩溃栈就勾 Windows 上的 pdb，体积大
Developer and Designer Tools → Qt Creator 勾 IDE 本体
Developer and Designer Tools → MinGW 8.1.0 勾 与上面的 MinGW 套件配套，命令行编译要用
Developer and Designer Tools → CMake / Ninja 勾 Qt6 工程默认构建系统，Qt5 也能用
Developer and Designer Tools → Qt Creator CDB Debugger Support 装了 VS / Windows SDK 再勾 用 CDB 调试 MSVC 程序

两条选择规则，照着抄就行：

  1. 纯 Qt 编程，不碰 Visual Studio：MinGW 8.1.0 32-bit + MinGW 8.1.0 64-bit，Tools 里的 MinGW 一起勾上。
  2. 用 VS2019 的编译器：MSVC 2019 32-bit + MSVC 2019 64-bit，然后单独去装 Visual Studio 2019 与 Windows SDK。

别全选。全选一次十几个 G，其中大半三年都用不上，而且每个套件都会在 Qt Creator 的 kit 列表里占一行，选 kit 时反而更难找。

位数必须成对：Qt 库 32 位配编译器 32 位，Qt 库 64 位配编译器 64 位。32 位库配 64 位编译器的报错是 LNK1112: module machine type 'x86' conflicts with target machine type 'x64'，第一次见很难往位数上想。

组件装少了不用重装整个 Qt。安装目录根下的 MaintenanceTool.exe 随时能加装、删组件、升级，这也是安装器本体值得留好的原因。

五、Qt 5.15 的安装步骤 #

以 Windows + 官方在线安装器为例。Linux 与 macOS 的步骤一致，差别只在安装器怎么启动（Linux 先 chmod +x，macOS 挂载 dmg）。

  1. 运行 qt-unified-windows-x86-online.exe。UAC 弹窗点「是」，安装器先自解压，界面出来前要等几秒。
  2. 登录 Qt 账号。没有账号就点 don't have Qt account? Sign up 去官网注册，邮箱 + 密码即可，开源用户一样要登录。这一步连的是官方账号服务，卡住不动多半是网络，回到第三节加 --mirror。
  3. 勾选开源使用条款。用开源版就选 I have read and agree ...（LGPL / GPL），商业授权走另一条。这里选完改不回来，动手前想清楚。
  4. 选安装目录。示例 D:\Qt。三条硬要求：不要中文、不要空格、不要装在 C:\Program Files 下面（写权限问题会拖到后面才炸）。安装器会自己在下面建 Qt5.15.2 子目录。
  5. 选组件。这一步按第四节那张表勾，别全选。
  6. 点 Next 开始下载。进度条按组件走，几十兆到几个 G。装到一半断了不用慌，重跑安装器会接着装。
  7. 装完点 Finish，勾上 Launch Qt Creator。
  8. 第一件事不是建工程，是先确认 kit。进 工具 → 选项 → Kits，看有没有一行是「编译器、Qt 版本、调试器」三项都打了勾的。全是感叹号就说明编译器没装上或路径不对，回第四节补组件。

装完之后别再动了。同一个目录不要同时被安装器和手动拷贝改，MaintenanceTool.exe 靠目录里的元数据判断哪些组件已装，元数据对不上就会出现「明明装了却列不出来」。

安装器出问题先找日志，%TEMP% 下的 qt-unified-*.log 里写了每一步在拉哪个 URL、失败在哪一条。带着日志去搜错误码，比截图问人快。

卸载或重装也走安装器：MaintenanceTool.exe → 卸载，它按组件清单一项项删。想换安装目录只有两条路，卸载重装，或者装到新目录再用 MaintenanceTool 删旧目录。手动删文件夹会留下注册表项与开始菜单快捷方式，下次重装时安装器还会提示「已存在安装」。

六、安装后的目录结构 #

按 D:\Qt 装完，目录长这样：

text
D:\Qt
└─ Qt5.15.2\
   ├─ 5.15.2\
   │  ├─ mingw81_64\          ← 套件：GCC 8.1 / 64 位
   │  │  ├─ bin\              Qt5Core.dll、moc.exe、uic.exe、rcc.exe、qmake.exe
   │  │  ├─ include\          QtCore、QtWidgets …… 头文件
   │  │  ├─ lib\              .a / .dll.a，链接用
   │  │  ├─ plugins\          platforms\qwindows.dll、imageformats\、sqldrivers\
   │  │  ├─ qml\              QML 模块
   │  │  └─ mkspecs\          qmake 编译规则
   │  ├─ msvc2019_64\         ← 套件：MSVC 2019 / 64 位
   │  └─ Src\                 ← 勾了 Sources 才有
   ├─ Tools\
   │  ├─ mingw810_64\         ← 编译器本体，gcc.exe 在这里
   │  ├─ QtCreator\           ← qtcreator.exe
   │  ├─ CMake\
   │  └─ Ninja\
   └─ MaintenanceTool.exe     ← 加装组件 / 升级 / 卸载

几个位置记牢，后面配环境和排错全靠它们：

位置 用途
<套件>\bin 运行时 dll 与 moc / uic / rcc / qmake，PATH 要指向这里
<套件>\plugins\platforms\qwindows.dll Windows 平台插件，缺了程序起不来
<套件>\lib\cmake\ CMake 的 find_package(Qt5) 靠这里的 config 文件
<套件>\mkspecs\ qmake 判断编译器、生成 Makefile 的依据
Tools\mingw810_64\bin gcc / g++ / mingw32-make，命令行编译要加进 PATH
Tools\QtCreator\bin qtcreator.exe，从命令行启动就调它
Tools\CMake\bin cmake.exe，构建 Qt6 工程要用

32 位与 64 位套件是两套独立目录。mingw81_64 和 mingw81_32 各有自己的 bin，PATH 里同时加两个 bin 会让 moc 与库版本对不上，只加你要用的那一个。

版本目录嵌了三层，D:\Qt\Qt5.15.2\5.15.2\mingw81_64 这种路径看着别扭，但它就是官方安装器的固定布局。很多老教程里写的 QTDIR 值就长这样，抄的时候别漏层。

七、Windows 下的环境变量 #

安装器不往系统 PATH 里写任何东西。Qt Creator 靠 kit 里配好的绝对路径编译，于是 IDE 里一切正常，一开命令行就提示 qmake 不是内部或外部命令。命令行要能编，得自己加环境变量。

变量 建议值 作用
QTDIR D:\Qt\Qt5.15.2\5.15.2\mingw81_64 指向当前套件，老工程、老脚本会读它
PATH 追加 %QTDIR%\bin 与 D:\Qt\Qt5.15.2\Tools\mingw810_64\bin 让 qmake、moc、gcc、mingw32-make 能被找到
QT_PLUGIN_PATH 平时不用设 程序找不到插件时临时指向 <套件>\plugins
QT_QPA_PLATFORM 平时不用设 排平台插件问题时设成 offscreen 或 windows

永久写进系统：此电脑 → 属性 → 高级系统设置 → 环境变量，改用户变量比改系统变量安全，改完要重开命令行才生效（新进程才继承新值）。

命令行里临时设，一次一个窗口：

text
D:\> set QTDIR=D:\Qt\Qt5.15.2\5.15.2\mingw81_64
D:\> set PATH=%QTDIR%\bin;D:\Qt\Qt5.15.2\Tools\mingw810_64\bin;%PATH%
D:\> qmake -v
QMake version 3.1
Using Qt version 5.15.2 in D:/Qt/Qt5.15.2/5.15.2/mingw81_64

PowerShell 语法不同，别混着抄：

text
PS> $env:QTDIR = "D:\Qt\Qt5.15.2\5.15.2\mingw81_64"
PS> $env:PATH  = "$env:QTDIR\bin;D:\Qt\Qt5.15.2\Tools\mingw810_64\bin;$env:PATH"
PS> qmake -v

机器上同时装着 5.15 与 6.x 时，PATH 里的先后顺序决定命令行走哪一套。qmake -v 打出来的路径就是第一顺位那个，要换版本就调顺序，别把两套 bin 都留着指望命令自己挑。

程序里怎么读这些环境变量 #

装完 Qt，接着要做的事经常是在代码里读系统变量：临时目录、用户配置目录、Qt 装在哪。Qt 给了两种读法。

第一种，QProcess::systemEnvironment()。它返回 QStringList，每个元素是 key=value，得自己切：

cpp
#include <QProcess>
#include <QStringList>
#include <QDebug>

QString getAppDataPath()
{
    // 拿到全部键值对
    QStringList environmentList = QProcess::systemEnvironment();
    QString appPath("");

    foreach (const QString &environment, environmentList)
    {
        // 忽略大小写匹配 "APPDATA="
        if (environment.startsWith("APPDATA=", Qt::CaseInsensitive))
        {
            // 切掉 "=" 之前的部分
            appPath = environment.mid(QString("APPDATA=").length());
            break;
        }
    }
    return appPath;
}

第二种，Qt 4.6 之后引入的 QProcessEnvironment，一行取值，不用切字符串：

cpp
#include <QProcessEnvironment>
#include <QString>

// 当前用户的漫游配置目录
QString appData = QProcessEnvironment::systemEnvironment().value("APPDATA");

// 可执行文件搜索路径
QString sysPath = QProcessEnvironment::systemEnvironment().value("PATH");

不确定变量名的时候，把全部变量打出来挨个过一遍：

cpp
#include <QProcess>
#include <QStringList>
#include <QDebug>

void printAllEnvironments()
{
    QStringList environmentList = QProcess::systemEnvironment();
    foreach (const QString &environment, environmentList)
    {
        qDebug() << environment;
    }
}

Windows 上打出来的一堆里，这几个跟 Qt 装完后的排错直接相关：

变量 典型值 用途
APPDATA C:\Users\username\AppData\Roaming 存用户配置、本地数据库
LOCALAPPDATA C:\Users\username\AppData\Local 存缓存、临时文件
TMP / TEMP C:\Users\username\AppData\Local\Temp 系统临时目录
QTDIR D:\Qt\Qt5.15.2\5.15.2\mingw81_64 当前使用的 Qt 套件路径
OS Windows_NT 操作系统类型
NUMBER_OF_PROCESSORS 4 CPU 核心数，开线程时参考
PROCESSOR_ARCHITECTURE x86 / AMD64 处理器架构，判断 32 / 64 位
USERNAME wangl-d 当前登录账户

QProcessEnvironment 还有个用处是给子进程传干净环境。先拷一份系统环境，删掉不要的键，再塞给 QProcess：

cpp
QProcessEnvironment env = QProcessEnvironment::systemEnvironment();
env.remove("PATH");
process.setProcessEnvironment(env);

这么写能避免子进程捡到开发机 PATH 里的 Qt，把调试环境带歪。

八、Linux 下的依赖与安装 #

Linux 上有三条路，按场景挑：

方式 产物 / 命令 适用
发行版仓库 sudo apt install qtbase5-dev qtcreator build-essential 想快、不挑小版本
官方在线安装器 .run 安装器，产物在 ~/Qt 要 5.15 官方二进制、要和 Windows 同版本
源码编译 见父目录《源码编译》一组 要裁模块、要换编译选项

仓库安装（Debian / Ubuntu 系）：

bash
sudo apt update
sudo apt install -y build-essential qtbase5-dev qtbase5-dev-tools \
    qt5-qmake qtchooser qtcreator libgl1-mesa-dev

qtbase5-dev 带库和头文件，qtbase5-dev-tools 带 moc / uic / rcc，qt5-qmake 是 qmake，qtchooser 用来在多个 Qt 版本间切换。仓库里的 Qt5 具体小版本由发行版决定（Ubuntu 20.04 是 5.12 一线，22.04 到 5.15，以发行版仓库为准）。

Fedora 系换成：

bash
sudo dnf install -y qt5-qtbase-devel qt5-qttools-devel qt-creator gcc-c++ make

在线安装器在 Linux 上要先给执行权限，还依赖一批 X11 / OpenGL 库，缺了会卡在启动或运行阶段：

bash
chmod +x qt-unified-linux-x64-online.run
sudo apt install -y libxcb-xinerama0 libxkbcommon-x11-0 libxcb-icccm4 \
    libxcb-image0 libxcb-keysyms1 libxcb-render-util0 libxcb-shape0 \
    libgl1-mesa-dev libfontconfig1
./qt-unified-linux-x64-online.run

装完程序报这个错：

text
qt.qpa.plugin: Could not load the Qt platform plugin "xcb" in "" even though it was found.

那是 xcb 相关依赖没装全，按上面那条 apt 补齐就能过。想先分清是插件问题还是程序问题，用 offscreen 跑一遍：

bash
QT_DEBUG_PLUGINS=1 QT_QPA_PLATFORM=offscreen ./your_app

Linux 下的环境变量比 Windows 少。qmake 与 moc 有绝对路径，安装器不写 PATH，用的时候自己导：

bash
export PATH=$HOME/Qt/5.15.2/gcc_64/bin:$PATH
qmake -v

别往 LD_LIBRARY_PATH 里塞 Qt 的 lib。官方二进制带 rpath，塞进去反而让系统里另一份 Qt 抢先加载，症状是程序起来就段错误，或者窗口画不出来。确实要用（比如自己编的库），临时设一次，别写进 ~/.bashrc。

Linux 上 xcb 与 wayland 两套平台插件都躺在 <套件>/plugins/platforms/ 下。Wayland 会话里跑不动的时候，QT_QPA_PLATFORM=xcb 强制走 X11，是个立刻能验证的开关。

九、macOS 与其他系统 #

先横着看一遍各平台该走哪条路：

系统 推荐方式 编译器 备注
Windows 在线安装器 MinGW / MSVC 见第五、七节
Linux 在线安装器或发行版仓库 系统 GCC 见第八节
macOS 在线安装器 dmg Clang，套件名 clang_64 先装 Xcode Command Line Tools
macOS（Homebrew） brew install qt@5 系统 Clang 版本跟 brew 走，路径不在 ~/Qt
其他 UNIX 源码编译 系统编译器 见父目录《源码编译》一组

macOS 装之前先补编译工具链，否则 kit 里编译器那一栏永远是空的：

bash
xcode-select --install

dmg 挂载后把安装器拖进 Applications 再运行，后续步骤与 Windows 一致：登录账号、同意协议、选目录、选组件。装完的套件叫 clang_64，库在 ~/Qt/5.15.2/clang_64，文件后缀是 .dylib 与 .framework，部署工具是 macdeployqt。

Apple Silicon 机器上，Qt 5.15 的官方二进制只有 x86_64，靠 Rosetta 跑；要原生 arm64 二进制，用 Qt6 的 LTS。具体哪个小版本开始提供 arm64，以官网为准。

Homebrew 那条路适合只想快速有个 Qt 的场景：

bash
brew install qt@5
brew --prefix qt@5      # 拿安装前缀，配 CMake 或 kit 时要用

brew 装的 Qt 不在 ~/Qt 下，也不带 Qt Creator。要 IDE 就单独 brew install --cask qt-creator，然后在 Creator 里把 Qt 版本指到 brew --prefix qt@5 那个目录。

iOS 与 Android 都不算「装桌面版 Qt」的范畴：

目标 去哪篇
Qt 源码编译 父目录《源码编译》一组
嵌入式 / 交叉编译 父目录《嵌入式移植》一组
Android / iOS 打包 父目录《Android》一组
构建工具与工程写法 父目录《构建工具》一组

这些不在此篇展开。把桌面环境装顺，再往下走会轻松很多。

十、验证安装是否成功 #

装完别急着建工程，按这张表逐项过一遍：

检查项 命令 期望输出
qmake 在不在 qmake -v QMake version 3.1 + Using Qt version 5.15.2 in ...
套件路径对不对 qmake -query QT_INSTALL_PREFIX 指向 ...\5.15.2\mingw81_64
moc 能不能跑 moc -v 打印 Qt 版本号
编译器 g++ --version / cl GCC 8.1.0 / MSVC 19.29
位数一致 qmake -query QT_ARCH 与编译器一致（x86_64 / i386）
Creator 的 kit 打开 Creator → 工具 → 选项 → Kits 至少一个 kit 三项全勾

命令行编一个最小程序，比看版本号更有说服力。两个文件就够：

cpp
// main.cpp
#include <QApplication>
#include <QLabel>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QLabel label("Qt 装好了");
    label.show();
    return app.exec();
}

工程文件叫 hello.pro，内容三行：

ini
QT += widgets
SOURCES += main.cpp

bash
qmake hello.pro
mingw32-make          # MSVC 用 nmake，Linux / macOS 用 make

窗口弹出来，说明库、moc、编译器三样都对上了。接着确认部署工具：

bash
windeployqt --version     # Windows
macdeployqt --version     # macOS

windeployqt 只认 PE 文件，拿自己编出来的 exe 试：

text
D:\demo> windeployqt --no-translations release\demo.exe

它会往 exe 旁边拷 Qt5Core.dll、platforms\qwindows.dll 等一堆文件，输出里能看到拷贝清单。这一步过了，发布出去就不会再缺 dll。

Qt Creator 里的最终确认：新建 Qt Widgets Application，选一个 kit，点绿色三角。构建输出最后一行是 Finished 且窗口起来，就算装对了。构建失败时先看第一行 Starting: ...，那行写着用的是哪个 qmake、哪个 g++，对不上就是 kit 配错了。

十一、安装失败的几种情形 #

现象 原因 处理
登录界面一直转圈或报网络错误 连不上 Qt 账号服务 加 --mirror 换镜像，检查代理；账号服务本身不通就先关 VPN 再试
Cannot retrieve remote tree，组件列表空白 镜像地址写错，或该镜像没同步 换回官方源或换另一个镜像，后缀以站内实际目录为准
下载到一半失败退出 网络抖动、磁盘不足、杀软拦截写入 重跑安装器接着装；安装目录排除出杀软扫描
装完 Creator 里没有可用 kit 编译器没装（MSVC 缺 VS，或 MinGW 只勾了库没勾 Tools） 用 MaintenanceTool.exe 补装 Tools 里的 MinGW，或手动指 kit 路径
链接报 LNK1112: module machine type conflict 库位数与编译器位数不一致 32 配 32，64 配 64
链接报 undefined reference to '__imp_...' MSVC 库配 MinGW 编译器，或反过来 套件与编译器必须来自同一行
链接报 undefined reference to vtable for Xxx 类里有 Q_OBJECT 但 moc 没跑 重新执行 qmake 让 moc 参与；确认头文件进了 HEADERS
双击 exe 报 no Qt platform plugin could be initialized 找不到 platforms\qwindows.dll 拷整个 platforms 目录，或用 windeployqt 部署
本机能跑，别人机器报缺 dll 程序依赖了开发机 PATH 里的 Qt windeployqt 把依赖拷到 exe 旁边
Linux 报 Could not load the Qt platform plugin "xcb" xcb 相关库缺失 补 libxcb-xinerama0 等依赖，见第八节
qmake: command not found PATH 没加，或加的是另一个套件 只加一个套件的 bin，见第七节
中文路径下编译失败、生成物名字乱码 工程或安装路径带中文 路径全英文，不带空格
升级 Qt 后老工程编不过 模块与头文件在 Qt6 里挪了位置 改 include，装 core5compat，或退回 5.15
装完第一次启动 Creator 就崩 显卡驱动与 OpenGL 不匹配 加 -noload Welcome，或设 QT_OPENGL=software 再起

排查顺序固定成这五步，能省掉一半弯路：

text
1. 看安装器日志 %TEMP%\qt-unified-*.log —— 装的时候就没成功？
2. 看 qmake -v 的路径 —— 是不是加错了套件 bin？
3. 看 kit 里的编译器路径 —— 与库位数、编译器家族是否一致？
4. 看构建输出第一行 Starting —— 实际调的是哪个 qmake / 哪个 g++？
5. 看运行时缺哪个 dll —— 用 windeployqt 补齐

十二、易错点速查 #

易错点 后果 正确做法
以为装 Qt = 装 Qt Creator 命令行编不了，发布缺库 库 + 开发工具 + 编译器三样齐备
新项目还上 5.15 几年后又得迁一次 新项目上 Qt6 的 LTS
全选组件 十几个 G，kit 列表一片乱 只勾当前项目要用的套件与模块
32 位库配 64 位编译器 LNK1112 位数成对
MSVC 套件配 MinGW 编译器 链接期一片 undefined reference 套件名里的编译器就是唯一选择
两个套件的 bin 都塞进 PATH moc 与库版本错位，报错莫名其妙 PATH 里只留当前套件
装到中文或含空格路径 qmake 生成失败，Makefile 路径错乱 D:\Qt 这类纯英文目录
指望安装器自动写 PATH 命令行找不到 qmake 自己加 QTDIR 与 PATH
往 LD_LIBRARY_PATH 塞 Qt lib 加载到系统里另一份 Qt，起不来 官方二进制靠 rpath，别设
直接拷 exe 发给别人 对方报缺 dll、缺平台插件 windeployqt / macdeployqt
装完不验证就开工 报错全堆在业务代码里查 按第十节逐项过一遍
勾了 MSVC 却没装 VS kit 全红 先装 VS 2019 + Windows SDK，再勾 MSVC 套件
新版本直接覆盖旧目录 老工程的编译环境被换掉 新版本装到新目录，两个 kit 并存
只看版本号判断装对了 版本对、位数错，编出来一堆怪问题 版本 + 位数 + 编译器家族三项一起看

装 Qt 这件事，卡人的从来不是点 Next，是三样东西有没有对上：库的套件名、编译器的家族、目标的位数。这三样对齐，组件选择、环境变量、验证步骤都是顺手的活。装完拿第十节那张表过一遍，比后面在业务代码里查「为什么编译不过」省事得多。
