这篇只讲一件事：用 Qt 写 Android 应用，环境怎么装、APK 怎么出。范围限于 Windows 与 Linux 上的 Qt Creator + JDK + Android SDK + NDK + Gradle 这条链，Qt 5 与 Qt 6 两代工程都覆盖。

不讲的部分：Windows 桌面端与 Visual Studio 的集成、编辑器调优与安装包提速，见同目录另外两篇。Qt Widgets 与 QML 语法本身不展开。

读法：想动手的从第二章顺着往下走；已经卡在 Gradle 阶段的，直接跳到第十一章。

一、Qt 在 Android 上的运行方式 #

先把本质说清楚。不然装环境就是照着截图一路点下一步，出错了不知道错在哪一层。

Qt for Android 的产物是一个普通 APK。里面没有业务 Java 代码，只有一个壳：QtActivity。这个 Activity 在 onCreate 里加载 native 库，经 JNI 跳进 C++ 的 main()，由 QGuiApplication 或 QApplication 接管，再走 QML 引擎或 QWidget 的场景图，最后落到 OpenGL ES 上刷新屏幕。

Qt 的库不是设备自带的，是跟着你的 APK 一起编译进去的。

这一点决定了后面所有事。你的 APK 体积以 MB 计，因为它里面装了一个完整的 Qt 运行时。

启动链长这样：

text
QtActivity (Java，在 APK 的 classes.dex 里)
  │  onCreate() → System.loadLibrary("...")
  ▼
libQt6Core_arm64-v8a.so、libQt6Gui_arm64-v8a.so、libapp<abi>.so
  │  JNI 跳转
  ▼
main() → QGuiApplication / QApplication
  │
  ▼
QML 引擎 或 QWidget 场景图 → OpenGL ES / Vulkan → 屏幕

QtActivity 那一层是 Java 写的，由 Qt 官方预先编译好，用户不碰。我们要编译的只有自己那部分 C++/QML，加上把它和 Qt 运行时装配成 APK 的过程。

1.1 每套 ABI 都要一份 Qt 库 #

ARM 和 x86 的机器码不通用，Android 设备只会加载和自己 CPU 架构匹配的那套 .so。APK 里的 native 库按目录分装：

text
lib/arm64-v8a/
lib/armeabi-v7a/
lib/x86/
lib/x86_64/

于是就这么一条规矩：想要支持几种架构，APK 里就得有几套 Qt 库；体积也是按套数往上翻。

ABI 目录名 位数 用在哪 Qt 5 时代的套件名
arm64-v8a 64 位 ARM 2016 年后的绝大多数真机 android_arm64_v8a
armeabi-v7a 32 位 ARM 老机型、低端设备、部分平板 android_armv7，Qt Creator 里显示为 Android for armeabi、Android for arm
x86 32 位 x86 旧版 Android 模拟器 android_x86
x86_64 64 位 x86 新版模拟器（Intel 机器上快得多） android_x86_64

选哪几套按发布目标定：只在自己手机上调试就打一套，上商店至少 arm64-v8a 加 armeabi-v7a，要跑模拟器再加 x86_64。四套全开的体积和编译时间都按四倍算，慎用。

一套 arm64 的 Qt 6 Core+Gui+Quick 运行时是十几 MB 的 .so，两套就是两倍。商店包和调试包的体积差就是这么来的。

1.2 早期的另一种思路：Ministro #

Qt 5 还有个选项叫 Ministro：APK 里不放 Qt 库，启动时唤起设备上的 Ministro 服务，由它联网下载或复用已装的 Qt 依赖。包只有几兆，但国内网络下这个服务几乎装不上，程序首次启动就黑屏。

策略 APK 体积 依赖 结论
Ministro 服务安装 Qt 几 MB 设备要有 Ministro，且能联网 已经过时
捆绑 Qt 库进 APK 15 MB 起步 无 Qt 6 唯一的做法

1.3 构建链上的三个角色 #

编译阶段是三个工具接力：CMake 或 qmake 把 C++/QML 编成 .so，androiddeployqt 找齐 Qt 依赖、生成 Android 工程骨架、注入清单，Gradle 加 AGP 负责编资源、打包、签名。分清这三层，报错信息一出来就知道该查哪，第七章按这个顺序展开。

二、需要装哪几样东西 #

链条上有五样东西必须有，少一样编译就断在哪一环。先把全局图放出来。

组件 在链条里干什么 缺了会怎样
Qt for Android（含源码同版本的预编译库） 提供每个 ABI 的 Qt 库与 androiddeployqt 等工具 没有 Android 套件，Kit 里根本不出现 Android 选项
JDK 编译 Java 壳、跑 Gradle、调 keytool 和 jarsigner 签名 Gradle 起不来，签名命令找不到
Android SDK 提供 platforms、build-tools、platform-tools 清单里的 API 等级解析不了，aapt2 找不到
Android NDK 提供交叉编译器和系统头文件、android.toolchain.cmake C++ 编译直接失败
Gradle + AGP 把上面这些拼成 APK 打包阶段报错，androiddeployqt 走不完

Qt 本身从 Qt 官方安装器装。装的时候必须勾上对应版本的 Android 组件，没勾的话后面无论怎么配路径都没用：

text
Qt Maintenance Tool → Add or Remove Components
  └─ Qt 6.x.x
       ├─ Android arm64_v8a
       ├─ Android armv7
       ├─ Android x86_64   （要跑模拟器就勾）
       └─ Sources / Qt Creator
  └─ Developer and Designer Tools
       ├─ Qt Creator
       └─ CMake / Ninja

这些东西的装法分两种：让 Qt Creator 自己下，或者自己手动装。前者省事，后者可控。

2.1 版本配套是硬约束 #

五样东西有版本兼容要求，任意一样过新或过旧，都会在 Gradle 阶段炸。先把已知的配套关系列清楚。

Qt 版本 JDK NDK Gradle AGP SDK API
Qt 6.10 17+ r27c，即 27.2.12479018 8.14.3 8.10.1 28 ~ 36
Qt 6.5 及以上 17+ 以 Qt 文档的兼容表为准 8.x 与 Gradle 同代 28 ~ 36
Qt 5.2 1.7 / 7 r9b 不用 Gradle，走 Ant 1.9.2 无 由清单里的 target 决定
Qt 5.1.1 1.7 / 7 r9b（含 legacy-toolchains） 不用 Gradle，走 Ant 1.9.2 无 由清单里的 target 决定

要点就三条：Qt 官方构建用哪个 NDK 就得用哪个，差一个小版本都容易出符号链接错误；Gradle 与 AGP 必须同代升级，AGP 版本写在 android-build/build.gradle 里；JDK 低了是硬伤，Qt 6 的 Gradle 脚本用了 JDK 17 的语法，JDK 11 直接编译失败。具体小版本以 Qt 文档的兼容表为准。

2.2 Qt 5 时代的老清单 #

如果你维护的是 Qt 5.1.1 / 5.2 的老工程，当年的清单长这样，和现在完全不是一回事：

安装包 文件名示例 作用
Qt 离线安装包（含 Android 套件） qt-windows-opensource-5.1.1-android-x86-win32-offline.exe Qt for Android 的预编译库
Android ADT Bundle adt-bundle-windows-x86_64-20131030.zip（64 位）、adt-bundle-windows-x86-20131030.zip（32 位） 里面带 Eclipse、SDK Manager、ADT
Android NDK android-ndk-r9b-windows-x86_64.zip 加 android-ndk-r9b-windows-x86_64-legacy-toolchains.zip 交叉编译器
Apache Ant apache-ant-1.9.2-bin.zip 当年生成 APK 的构建工具
JDK jdk-7-windows-i586.exe Java 环境

老教程最容易漏两点。一是 NDK 的两个压缩包必须解压合并到同一个目录：r9b 主包和 legacy-toolchains 包分开解压只会得到空工具链目录，编译时找不到 arm-linux-androideabi-gcc。二是所有解压出来的东西放在同一个物理大目录下，比如 D:\qtforandroid\，路径里不能有中文和空格，Ant 和 NDK 的脚本都吃不下。Ant 已经被 Gradle 取代，新工程不用管它。

三、JDK 与版本要求 #

JDK 是链条里最容易被忽视、又最先被卡住的一环。

3.1 版本对应关系 #

Qt 版本 需要的 JDK 说明
Qt 6.x 17 及以上 必须是 64 位。官方推荐 Adoptium（Temurin）
Qt 5.2 及以上 1.7 / 7 或 8 老的 Android 插件只认这个区间
Qt 5.1.1 1.7 / 7 当年配的是 jdk-7-windows-i586.exe

三个来源都能用：

  • Adoptium（Temurin）：https://adoptium.net/，开源、免费、长期维护，首选。
  • OpenJDK：https://openjdk.java.net/。
  • Oracle JDK：能用，但授权条款要看清楚。

不要用 Android Studio 自带的 JBR。它的版本跟着 Studio 走，升级一次就变一次，Qt Creator 那边配好的路径会失效。老老实实单独装一个 JDK 17。

3.2 Windows 上装与验证 #

装完先确认命令行能找到它：

text
java -version
javac -version

输出里应该能看到 17 之类的版本号。看到 1.8 就说明 PATH 里还有旧 JDK 排在前面。

配置环境变量。临时生效（只对当前 PowerShell 窗口）：

text
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-17.0.11.9-hotspot"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version

永久生效（写进用户环境变量，重开终端后可用）：

text
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Eclipse Adoptium\jdk-17.0.11.9-hotspot", "User")
$old = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "%JAVA_HOME%\bin;$old", "User")

JAVA_HOME 指向的是 JDK 根目录，不是 bin 目录。这一点经常搞反。

签名要用 keytool，它和 jarsigner 都在 %JAVA_HOME%\bin 下面。PATH 里没有 %JAVA_HOME%\bin 的话，第八章的签名命令会直接报「不是内部或外部命令」。

3.3 Linux 上装与验证 #

bash
# Ubuntu / Debian
sudo apt install openjdk-17-jdk

# 验证
java -version
which keytool

# 设置 JAVA_HOME，要永久生效就写进 ~/.bashrc 或 ~/.profile
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export PATH=$JAVA_HOME/bin:$PATH

keytool 找不到就说明 JAVA_HOME/bin 没进 PATH，第八章的签名命令会跟着一起失败。

3.4 JDK 版本的坑 #

现象 原因 处理
Gradle 报 Unsupported class file major version 用了 JDK 17 之前的版本 换 JDK 17+
Gradle 报 Invalid Java version JAVA_HOME 指向了 JRE，不是 JDK 改指向 JDK 根目录
keytool: command not found PATH 里没有 JDK 的 bin 把 %JAVA_HOME%\bin 加到 PATH 最前面

PATH 里有多个 JDK 时，排在最前面的那个生效。装完新的记得确认 java -version 输出的就是想要的版本，别让旧 JDK 挡在前面。

四、Android SDK 与 NDK #

SDK 和 NDK 是两个独立的东西，装法不同，职责也不同。

SDK 是给 Java 那一侧用的：编译清单、打包资源、跑 adb、签名。NDK 是给 C++ 那一侧用的：交叉编译器、C/C++ 标准库、Android 的系统头文件。Qt 的 C++ 代码全靠 NDK 编，Qt 的 APK 装配全靠 SDK 打包。

4.1 SDK 里到底要哪几个包 #

SDK 不是一个整体，是一堆可以单独装的包。Qt 的构建链只依赖其中四个：

包名 装的目录 里面有什么 少了会报什么
cmdline-tools sdk/cmdline-tools/latest/bin sdkmanager、avdmanager 连装包的工具都没有
platforms;android-34 sdk/platforms/android-34 该 API 等级的 android.jar 清单里的 targetSdk 解析不出来
build-tools;34.0.0 sdk/build-tools/34.0.0 aapt2、zipalign、apksigner 资源编译失败，签名找不到工具
platform-tools sdk/platform-tools adb、fastboot 装不上设备，看不到日志

Qt 6.5 及以上要求 SDK 的 API 等级落在 28 到 36 之间，build-tools 用 34.0.0 这一代。

4.2 方式一：让 Qt Creator 自己装 #

最省事的一条路，官方也推荐。打开 Qt Creator，进 Edit → Preferences（Windows 上是 工具 → 选项），左侧选 Devices → Android，点 Set Up SDK。Qt Creator 会自己下好 Android Command-line SDK Tools、Platform Tools、Build Tools，以及和自己版本匹配的 NDK。

这个按钮干的事就是替你跑 sdkmanager，路径也一并填进 Android 配置页，你不用记目录。

装完先别编译，看一眼 ABI 那栏有没有 arm64-v8a、armeabi-v7a。有就说明 Qt 的 Android 库被认出来了；空白或者报 Failed to detect the ABIs used by the Qt version，回去查 Qt 组件勾没勾全。

4.3 方式二：手动装 #

需要自己控制版本、或者在 CI 上跑，就得手动来。下载地址：

text
SDK 命令行工具：https://developer.android.com/studio#command-line-tools-only
NDK：https://developer.android.com/ndk/downloads

Linux 上的完整脚本：

bash
#!/bin/bash

# 配置变量 - 按 Qt 版本调整
ndkVersion="r27c"
sdkBuildToolsVersion="34.0.0"
sdkApiLevel="android-34"
repository="https://dl.google.com/android/repository"

# 下载 SDK Command-line Tools
wget -q $repository/commandlinetools-linux-11076708_latest.zip
unzip -qq commandlinetools-linux-11076708_latest.zip -d android-sdk
mkdir -p android-sdk/cmdline-tools/latest
mv android-sdk/cmdline-tools/* android-sdk/cmdline-tools/latest/ 2>/dev/null || true

# 下载 NDK
wget -q $repository/android-ndk-$ndkVersion-linux.zip
unzip -qq android-ndk-$ndkVersion-linux.zip

# 设置环境变量
export ANDROID_SDK_ROOT=$(pwd)/android-sdk
export ANDROID_NDK_ROOT=$(pwd)/android-ndk-$ndkVersion
export PATH=$PATH:$ANDROID_SDK_ROOT/cmdline-tools/latest/bin

# 接受许可证
yes | sdkmanager --licenses

# 安装必要组件
sdkmanager "platforms;$sdkApiLevel" \
           "platform-tools" \
           "build-tools;$sdkBuildToolsVersion"

echo "SDK 安装完成"
echo "ANDROID_SDK_ROOT=$ANDROID_SDK_ROOT"
echo "ANDROID_NDK_ROOT=$ANDROID_NDK_ROOT"

那段 mv 不能省。cmdline-tools 的压缩包解出来是 cmdline-tools/bin，而 sdkmanager 要求自己的路径里带 latest 这一层，不搬就报 Could not determine SDK root。

Windows 上同样的流程，在 PowerShell 里跑：

text
$ndkVersion = "r27c"
$sdkBuildToolsVersion = "34.0.0"
$sdkApiLevel = "android-34"
$repository = "https://dl.google.com/android/repository"

# 下载 SDK Tools
Invoke-WebRequest "$repository/commandlinetools-win-11076708_latest.zip" -OutFile "sdk-tools.zip"
Expand-Archive -Path "sdk-tools.zip" -DestinationPath "android-sdk" -Force

# 下载 NDK
Invoke-WebRequest "$repository/android-ndk-$ndkVersion-windows.zip" -OutFile "ndk.zip"
Expand-Archive -Path "ndk.zip" -DestinationPath "." -Force

# 设置环境变量
$env:ANDROID_SDK_ROOT = "$PWD\android-sdk"
$env:ANDROID_NDK_ROOT = "$PWD\android-ndk-$ndkVersion"

# 安装 SDK 组件
& "$env:ANDROID_SDK_ROOT\cmdline-tools\bin\sdkmanager.bat" --sdk_root="$env:ANDROID_SDK_ROOT" `
    "platforms;$sdkApiLevel" "platform-tools" "build-tools;$sdkBuildToolsVersion"

--sdk_root 这个参数别漏。SDK 装在非标准位置时，sdkmanager 靠它定位，不加会把包装到用户目录去。

4.4 环境变量 #

手动装的一大好处是可以把路径写进环境变量，命令行编译和 CI 都好办。

变量 指向 谁在用
ANDROID_SDK_ROOT SDK 根目录 sdkmanager、Gradle、androiddeployqt
ANDROID_NDK_ROOT 具体版本的 NDK 目录 CMake 工具链、androiddeployqt
JAVA_HOME JDK 根目录 Gradle
ANDROID_HOME SDK 根目录（老名字） 老版本工具，与 ANDROID_SDK_ROOT 同时写一份更保险

Linux 写进 ~/.bashrc：

bash
export ANDROID_SDK_ROOT=$HOME/android-sdk
export ANDROID_NDK_ROOT=$HOME/android-ndk-r27c
export PATH=$PATH:$ANDROID_SDK_ROOT/platform-tools:$ANDROID_SDK_ROOT/cmdline-tools/latest/bin

Windows 一样，用 [Environment]::SetEnvironmentVariable 写进 User 变量，ANDROID_NDK_ROOT 指向版本目录 D:\android\sdk\ndk\27.2.12479018。装完用 adb version 和 sdkmanager --list_installed 验证。

4.5 NDK 版本：这一步错得最多 #

NDK 版本必须和 Qt 官方构建时用的那个版本一致。Qt 6.10 用的是 r27c，完整版本号 27.2.12479018。差一个小版本就容易出现符号链接错误，这是编译失败最集中的原因。

看一下你手上 Qt 对应的 NDK：

Qt 版本 NDK 版本 完整目录名
Qt 6.10 r27c 27.2.12479018
其他 6.x 以 Qt 文档的兼容表为准 目录名就是版本号
Qt 5.2 r9b 主包加 legacy-toolchains 包合并
Qt 5.1.1 r9b 同上，两个压缩包合并到一个目录

NDK 目录还有一个结构问题：Qt Creator 要的是版本目录，不是 ndk 这一层。

填法 结果
D:/android/sdk/ndk/27.2.12479018 正确
D:/android/sdk/ndk 报 NDK directory structure isn't correct
D:/android/sdk/ndk/27.2.12479018/toolchains 报找不到 android.toolchain.cmake

对应到 ANDROID_NDK_ROOT，填的也是版本目录本身。

4.6 老版本 SDK 的 ADT Bundle #

Qt 5.1.1 那会儿还没有 cmdline-tools，用的是 ADT Bundle：一个 zip 里打包了 Eclipse、SDK Manager 和 ADT 插件。解压后在 adt-bundle-windows-x86_64-20131030\sdk 下面能看到 tools、platform-tools、platforms 这几个目录。

那时的 PATH 需要手工把一堆 bin 串起来：

text
C:\Program Files (x86)\Java\jdk1.7.0\bin;
C:\Qt\Qt5.1.1\5.1.1\android_armv7\bin;
C:\Qt\Qt5.1.1\5.1.1\android_x86\bin;
C:\Qt\Qt5.1.1\5.1.1\mingw48_32\bin;
C:\Qt\Qt5.1.1\Tools\mingw48_32\bin;
C:\Qt\Qt5.1.1\Tools\QtCreator\bin;
D:\qtforandroid\adt-bundle-windows-x86_64-20131030\sdk\tools

每条之间用分号隔开，最后一条不要留分号。配完点确定，重开一个命令行窗口才生效。

五、在 Qt Creator 里配置 Android Kit #

Kit 是 Qt Creator 里的「一套编译配置」。它把四样东西绑在一起：Qt 版本、编译器、调试器、目标设备。Android 的 Kit 全部由 Android 配置页的路径推导出来，所以路径填错了，Kit 里就是一堆红字。

5.1 先填 Android 页面的三个路径 #

进 工具 → 选项 → Devices → Android（英文界面是 Tools → Options → Devices → Android），填三个路径：

配置项 填什么 校验方式
JDK 位置 JDK 根目录，如 C:\Program Files\Eclipse Adoptium\jdk-17.0.11.9-hotspot 或 /usr/lib/jvm/java-17-openjdk-amd64 下面一行会显示解析到的 Java 版本号
Android SDK 位置 SDK 根目录，里面要有 platforms、build-tools、platform-tools 不报红即通过
Android NDK 位置 NDK 的版本目录，如 ndk/27.2.12479018 下面会列出可用 ABI

页面下方还有一块 OpenSSL 设置，第十章讲网络功能时再用。Qt 5 时代的界面里还有第四个路径：Ant 位置，指向 apache-ant-1.9.2 的根目录。Qt 6 没有这一项，看到老教程让你填 Ant，说明那是 Qt 5 时代的截图。

5.2 Kits 页面 #

三个路径都变绿之后，进 工具 → 选项 → Kits。先在 Qt Versions 标签页确认每个 Android Qt 版本都被识别出来，路径形如 C:\Qt\6.10.0\android_arm64_v8a\bin\qmake.exe；再到 Kits 标签页，自动生成的 Kit 名字形如 Android Qt 6.10.0 Clang arm64-v8a，逐个点开检查四栏：

Kit 里的项 应该是什么
Device type Android Device
Compiler Android Clang (C++, arm64) 之类，对应目标 ABI
Qt version 对应 ABI 的 Android Qt，不能选桌面版
CMake tool Qt 自带的 CMake，不要用系统里别的版本

四个 ABI 对应四个 Kit。要给哪个架构出包，就切到哪个 Kit。想一个包带全部架构，用第七章的 QT_ANDROID_BUILD_ALL_ABIS，不用在这里配多个 Kit。

5.3 一个 Kit 的通电测试 #

新建一个空工程，切到 Android Kit，看左下角的运行按钮：

按钮状态 含义
绿色三角形 桌面套件，跑在本机
绿色小机器人（带 Release/Debug 字样） Android 套件配置成功，可以编译部署
灰色不可点 Kit 里某一栏没配好，回 Kits 页面看红字

看到小机器人，环境这一关就过了。后面的问题都归构建和签名。

5.4 老版本 Qt Creator 的对应操作 #

Qt Creator 3.0 那代叫「选项」，进去选 Android，填四项：JDK 路径、Android SDK 路径（adt-bundle 里的 sdk 目录）、Android NDK 路径（合并后的 NDK 根目录）、Ant 路径（apache-ant-1.9.2 根目录）。同一页还有「启动 Android AVD 管理器」，用来配模拟器（见第九章）。

老界面的坑在于路径层级的说法不统一。看目录里有没有 bin/java.exe、platforms/android-34、toolchains，有就是对的层。

5.5 Kit 配好之后该确认什么 #

在 Kit 生效之前，跑一次配置检查，比反复重启 Qt Creator 省事：

检查项 命令 期望
Qt 的 Android 库是否完整 看 C:\Qt\6.10.0\android_arm64_v8a\lib 下有 libQt6Core_arm64-v8a.so 存在
androiddeployqt 是否在 看 android_arm64_v8a\bin\androiddeployqt.exe 存在
NDK 是否被识别 Qt Creator 的 Android 页会列出 ABI 列出 arm64-v8a 等
adb 是否可用 adb devices 有设备列表输出

androiddeployqt 不在，说明 Qt 安装时没勾 Android 组件，只能重开 Maintenance Tool 补装。

六、第一个 Android 应用 #

环境配好了，先跑一个最小的东西把链条验通。这个工程不需要好看，能装到设备上弹出一行字就算成功。

6.1 选模板 #

文件 → 新建文件或项目，模板页里两个选择：Qt Widgets Application 用于传统控件和从桌面迁过来的项目，界面写 QWidget 代码或 .ui；Qt Quick Application 用于新的触屏项目，QML 描述界面、C++ 做后端。模板页右侧的平台列表里 Android 应该是可用状态，灰的就说明 Kit 没配好，回第五章。

6.2 选 Kit #

Qt 6 的 Android Kit 名字里带 ABI：Android Qt 6.10.0 Clang arm64-v8a、...armv7、...x86_64。勾目标架构那个，顺手把 Desktop Qt 6.10.0 MinGW 64-bit 也勾上，逻辑先在 PC 上调通再上设备。

Qt 5 时代的 Kit 名字不一样：Qt Creator 3.0 是 Android for armeabi (GCC 4.7, Qt 5.2.0)，Qt 5.1.1 是 Android for arm (GCC 4.8, Qt 5.1.1)。这两代都要选 arm 或 armeabi，x86 那套只能装到模拟器上。

6.3 类信息这一步 #

Qt Widgets 模板会问基类。选 QWidget，取消勾选 Generate form。不用 .ui 文件，界面全在 cpp 里手写，少一层文件，排查时干扰少。

6.4 写一行字 #

打开 widget.cpp，加头文件：

text
#include <QLabel>

构造函数里塞一行：

text
Widget::Widget(QWidget *parent)
    : QWidget(parent)
{
    // 创建一个标签显示文本，以当前 Widget 为父窗口
    new QLabel("Hello Qt on Android !", this);
}

QLabel 挂在 this 上，父窗口销毁时它跟着走，不用手动 delete。QML 版更短：Main.qml 里放一个 Text { text: "Hello Qt on Android !" }，main.cpp 用 QQmlApplicationEngine 加载它。

6.5 界面上哪几个按钮有用 #

左侧 项目 面板管构建、运行和 Android 打包配置，切 Release、配签名、建清单都在那里。左下角那个按钮负责切 Debug/Release 和切 Kit，Android Kit 生效后它变成小机器人；旁边绿色三角一次做完编译、链接、打包、部署、拉起设备。底部两个输出窗口分工明确：编译输出 是编译器和链接器的话，应用程序输出 接的是 logcat，白屏和闪退的答案在后一个里，不在前一个。

工程默认没有 android/ 目录。第一次编译后在 android-build 里生成模板，复制到源码目录再改，第十章细讲。

6.6 一份能跑的 CMakeLists.txt #

text
cmake_minimum_required(VERSION 3.16)
project(MyApp VERSION 1.0 LANGUAGES CXX)

find_package(Qt6 REQUIRED COMPONENTS Core Gui Quick)
qt_standard_project_setup()

qt_add_executable(MyApp main.cpp)
target_link_libraries(MyApp PRIVATE Qt6::Core Qt6::Gui Qt6::Quick)

# Android 特定配置
if(ANDROID)
    set_target_properties(MyApp PROPERTIES
        QT_ANDROID_PACKAGE_SOURCE_DIR "${CMAKE_CURRENT_SOURCE_DIR}/android"
    )
endif()

install(TARGETS MyApp
    BUNDLE DESTINATION .
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}
)

最后的 install(TARGETS) 别删。androiddeployqt 靠 install 规则把要进包的 .so 归拢起来，删掉会得到一个没有 native 库的空壳 APK，装上就闪退。

6.7 qmake 版 #

还在用 qmake 的工程：

ini
QT += quick core gui

CONFIG += c++17

SOURCES += main.cpp

# Android 资源目录
android {
    ANDROID_PACKAGE_SOURCE_DIR = $$PWD/android

    # 额外库（如果需要）
    ANDROID_EXTRA_LIBS += \
        $$PWD/libs/$$ANDROID_TARGET_ARCH/libcustom.so
}

ANDROID_TARGET_ARCH 跟着当前 Kit 变，取值就是 arm64-v8a、armeabi-v7a 这些。所以第三方库要按架构分目录摆，一个目录喂所有 ABI 会在链接时报架构不符。

七、APK 的构建过程 #

点一下运行按钮，后台跑了七八个步骤。知道顺序，报错信息一出来就知道停在哪。

7.1 从源码到 APK 的完整步骤 #

步 谁在做 产物
1 CMake 配置，加载 NDK 工具链与 Qt build-android/
2 NDK 的 Clang 交叉编译 C++/QML libapp_arm64-v8a.so
3 CMake 按 install 规则归拢 android-build/libs/arm64-v8a/
4 androiddeployqt 生成部署配置 android-MyApp-deployment-settings.json
5 androiddeployqt 收集 Qt 依赖 libQt6Core_arm64-v8a.so 等一整串
6 androiddeployqt 生成 Android 工程 build.gradle、AndroidManifest.xml
7 Gradle + AGP 编译 Java 壳、编资源、打包 未签名 APK
8 签名与对齐 可安装的 APK

7.2 命令行编译 #

bash
cmake -S . -B build-android \
    -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK_ROOT/build/cmake/android.toolchain.cmake \
    -DCMAKE_PREFIX_PATH=$QT_ANDROID_PATH \
    -DANDROID_ABI=arm64-v8a \
    -DANDROID_PLATFORM=android-28 \
    -DCMAKE_BUILD_TYPE=Release

cmake --build build-android

cmake --build build-android --target apk

三个变量最容易配错：

变量 含义 填错的表现
CMAKE_TOOLCHAIN_FILE NDK 的交叉编译工具链文件 找不到编译器，或者编出 x86 目标文件
CMAKE_PREFIX_PATH 对应 ABI 的 Qt 安装目录 链接报架构不匹配，或者找不到 Qt6Config
ANDROID_ABI 目标架构 装到设备上提示 ABI 不支持
ANDROID_PLATFORM 编译期最低 API 等级 用了设备上没有的符号，运行时崩

CMAKE_PREFIX_PATH 要指到 C:\Qt\6.10.0\android_arm64_v8a 这一层，不是 C:\Qt\6.10.0。指到上一层，CMake 会挑到桌面版 Qt，编出来的东西装不上。

ANDROID_PLATFORM 是编译期的下限，和清单里的 targetSdkVersion 不是一回事。前者决定能用哪些系统 API，后者决定运行时的兼容行为。

7.3 手动调 androiddeployqt #

CMake 的 apk 目标背后就是这条命令：

bash
androiddeployqt \
    --input build-android/android-MyApp-deployment-settings.json \
    --output build-android/android-build \
    --android-platform android-34 \
    --gradle
参数 作用
--input CMake 生成的部署配置，不要手写
--output Android 工程的输出目录
--android-platform 用哪个 API 等级的资源编译，写 android-34 这种形式
--gradle 走 Gradle；Qt 5 老工程不加这个就走 Ant

7.4 一次出多套架构 #

Qt 6 的 CMake 支持一次编多个 ABI：

bash
cmake -S . -B build-android \
    -DQT_ANDROID_BUILD_ALL_ABIS=ON \
    -DCMAKE_PREFIX_PATH=$QT_ANDROID_PATH
开关 效果
只写 -DANDROID_ABI=arm64-v8a 单架构，编译快，包小
-DQT_ANDROID_BUILD_ALL_ABIS=ON 全部已安装的 ABI 一起编，产物一个多 ABI 包
两个都写 ALL_ABIS 优先，ANDROID_ABI 被忽略

走全 ABI 的前提是每个架构的 Qt 库都装了。少装一个，配置阶段就报找不到对应的 Qt，编不下去。

7.5 产物在哪 #

编译成功后，android-build 底下是这样：

text
build-android/android-build/
├── AndroidManifest.xml
├── build.gradle
├── libs/arm64-v8a/          ← 最终进包的 native 库
└── build/outputs/apk/
    ├── debug/android-build-debug.apk
    └── release/android-build-release-unsigned.apk
路径 是什么
android-build/libs/<abi>/ 最终进包的 native 库，缺库就看这里
android-build/build.gradle AGP 与 Gradle 版本写在这里，改版本改这个文件
build/outputs/apk/debug/ 调试包，自动签名
build/outputs/apk/release/ 发布包，名字带 unsigned，未签名

Qt 5 + Ant 那一代的路径不同，APK 落在工程目录的 <工程名>/android/bin/ 下。老教程里说「去 android/bin 找」，说的就是那个时代。

7.6 增量编译与清理 #

改了清单、换了 ABI、动了签名配置，先清再编：rm -rf android-build（Windows 上是 Remove-Item -Recurse -Force android-build），然后 cmake --build build-android --target apk。Gradle 缓存会把旧清单和旧 .so 继续用上，改半天看不到效果就是这个原因。清理只删构建目录，源码里的 android/ 不要碰。

八、签名与打包 #

APK 不签名装不上，这是 Android 的硬规则，不是可选项。

8.1 debug 包与 release 包 #

项 debug release
签名 自动，用调试证书 必须自己提供 keystore
产物名 android-build-debug.apk android-build-release-unsigned.apk
能否装到设备 能 未签名版本装不上
能否上架 不能 能，商店还要 AAB
证书期限 调试证书自带 keytool 的 -validity 决定

调试证书躺在家目录的 .android/debug.keystore，第一次 debug 编译时自动生成。它的密码是固定的 android，谁都能签。拿它发布等于把包名送人，别干这事。

8.2 建自己的 keystore #

bash
keytool -genkey -v \
    -keystore my-release-key.jks \
    -keyalg RSA \
    -keysize 2048 \
    -validity 10000 \
    -alias my-key-alias

跑起来会问你密码和一堆证书信息（姓名、组织、城市、国家）。填完在当前目录得到一个 my-release-key.jks。

参数 含义 建议
-keystore 密钥库文件名 用有意义的文件名，发布后不要改名
-keyalg RSA 密钥算法 保持 RSA
-keysize 2048 密钥长度 2048 位起步
-validity 10000 天数 10000 天约 27 年，够用
-alias 别名 签名时要对上，别记错

8.3 在 Qt Creator 里配签名 #

Qt 6 的路径：

  1. 左侧 项目，切到 Android Kit，构建版本选 Release。
  2. 展开 Build Settings → Build Android APK，找到 Signing。
  3. 选密钥库文件，填别名和密码。
  4. 勾上 Sign package。

Qt Creator 3.x 的路径不一样：项目 → Android 套件 → 运行 标签 → 部署配置 → 点 详情 → 勾「对包签名」。没有 keystore 时点 Create，填密钥位置、别名、密码和证书组织信息，Qt Creator 会替你调 keytool。

同一页面上还有两个开关，顺手一起配：

开关 作用 建议
Open package location after build 编译完自动弹出 APK 所在目录 调试期勾上，省得每次找路径
Qt Library Deployment 选 Qt 库怎么进包 选捆绑进 APK，Ministro 那条路已经废弃

8.4 命令行签名 #

bash
# 生成未签名包
androiddeployqt --output build-android/android-build --gradle

# 签名
jarsigner -verbose -sigalg SHA256withRSA -digestalg SHA-256 \
    -keystore my-release-key.jks \
    build-android/android-build/build/outputs/apk/release/android-build-release-unsigned.apk \
    my-key-alias

# 对齐
zipalign -v 4 \
    android-build-release-unsigned.apk \
    MyApp-release.apk

zipalign 在 build-tools/<版本号>/ 目录下，不在 PATH 里就用全路径。签名和对齐的顺序在老工具链上是先签后对齐；换成 apksigner 的话，必须对齐完再签，顺序反了包会被判为损坏。

也可以让 androiddeployqt 一次做完：

bash
androiddeployqt \
    --input android-MyApp-deployment-settings.json \
    --output android-build \
    --android-platform android-34 \
    --gradle \
    --sign my-release-key.jks my-key-alias \
    --storepass 你的密码

8.5 生成 AAB #

上 Google Play 要的是 App Bundle。Qt 6.3 起 androiddeployqt 支持直接出：

bash
androiddeployqt \
    --input android-MyApp-deployment-settings.json \
    --output android-build \
    --android-platform android-34 \
    --gradle \
    --aab

AAB 不能直接装到设备上，它是给商店做二次分发的格式。要装机器测试，还是用 APK。

8.6 签名的三条铁律 #

铁律 后果
同一个应用的所有版本用同一份 keystore 换证书的包，设备会拒绝覆盖安装，用户必须先卸载
keystore 和密码要备份 丢了就再也发不出这个包名的更新，只能换包名重来
keystore 不进 git 仓库泄露等于密钥泄露，别人可以伪造你的更新包

九、在真机与模拟器上运行 #

编译过了不等于跑得起来。这一章把「装到东西上」这段走完。

9.1 真机四步 #

  1. 开开发者选项：设置 → 关于手机，连点版本号七次，再打开 USB 调试。
  2. 数据线连电脑。手机上弹出「允许 USB 调试吗」，勾上「一直允许」再点确定。
  3. 验证：adb devices。

List of devices attached 下面要有序列号加 device 字样。看到 unauthorized、offline 或者一片空白，按下面这张表查：

现象 原因 处理
unauthorized 手机上的授权弹窗没点允许 拔插重来，或者 adb kill-server 后再 adb devices
offline 手机端 adb 服务没起来 重连，必要时关掉再打开 USB 调试
列表为空 驱动没装，或者线只能充电 装厂商 ADB 驱动，换一根数据线

Windows 上设备管理器里出现带黄色感叹号的 Android 设备，就是驱动没装。小米、华为、三星各有自己的 ADB 驱动，装完 adb devices 才认。

Qt Creator 里点绿色运行按钮，弹目标设备选择框，选中真机（老素材里那台是 Motorola XT882、Android 2.3.6），确定。编译打包完，手机上直接启动。

手动装包：

bash
adb install -r build-android/android-build/build/outputs/apk/debug/android-build-debug.apk

-r 是覆盖安装，保留应用数据。

9.2 模拟器 #

Qt 5 时代在 Qt Creator 的 Android 页面点「启动 Android AVD 管理器」，弹窗里点 New：

字段 填什么
AVD Name android，起个短名，命令行要用
Device 标准分辨率的一项
Target 想要的 Android API 版本

点了 OK 回到列表，选中后点 Start → Launch，等桌面出来。第一次启动慢，别急着关窗口。

命令行启动：

bash
emulator -avd android

android 就是 AVD Name。关掉模拟器：回到那个命令行窗口按 Ctrl + C。

9.3 真机与模拟器的差别 #

项 真机 模拟器
ABI arm64-v8a、armeabi-v7a x86、x86_64
Kit 怎么选 arm 或 armeabi x86_64 或 x86
启动速度 快 慢，几分钟
摄像头、蓝牙、传感器 有 模拟或者没有
适合干什么 最终验收 快速看界面

9.4 看运行日志 #

应用程序输出 面板接的就是 logcat，qDebug() 打的东西全在里面。手动看用 adb logcat | grep -i qt。界面空白时先在这里找 QML 加载失败的报错，再看第十一章。

十、资源和权限配置 #

能跑之后就该收拾外观和权限了：图标、名称、包名、API 等级、权限，全在 android/ 目录和清单文件里。

10.1 建自己的 android 目录 #

第一次编译后，android-build/AndroidManifest.xml 里会生成一份模板。复制到源码目录，在旁边建 res/drawable-ldpi、drawable-mdpi、drawable-hdpi、drawable-xhdpi、drawable-xxhdpi 五个目录，每个放一张 icon.png。

五档 DPI 不是随便定的，系统按设备密度挑对应目录里的图：

DPI 目录 推荐尺寸 适用设备
drawable-ldpi 36×36 低分辨率旧设备
drawable-mdpi 48×48 中等分辨率
drawable-hdpi 72×72 高分辨率
drawable-xhdpi 96×96 超高分辨率
drawable-xxhdpi 144×144 现代高端设备

只放一套也能跑，系统会缩放，但桌面上的图标会发虚。要出正式包就五套都放。

10.2 让工程指向这个目录 #

CMake 项目：

text
if(ANDROID)
    set_target_properties(MyApp PROPERTIES
        QT_ANDROID_PACKAGE_SOURCE_DIR "${CMAKE_CURRENT_SOURCE_DIR}/android"
    )
endif()

qmake 项目：

ini
android {
    ANDROID_PACKAGE_SOURCE_DIR = $$PWD/android
}

设了 QT_ANDROID_PACKAGE_SOURCE_DIR 之后，android-deployqt 会拿这个目录里的清单和 res/ 覆盖掉自动生成的那份。不设就一直用自动模板，改什么都没用。

10.3 清单里要改的字段 #

Qt Creator 里双击 AndroidManifest.xml 打开图形化清单编辑器，或者在 Qt 提供的界面上点 XML Source 手写。要动的就这几项：

字段 作用 注意
package 包名 把默认的 org.qtproject.example 改成自己的反域名，如 com.foruok.helloqt
android:versionCode 内部版本号，整数 每次上架必须加一，不能回退
android:versionName 显示给用户的版本 字符串，随便写
minSdkVersion 最低支持的 API 低于这个版本的设备装不上
targetSdkVersion 目标 API 影响运行时的兼容行为
android:label 应用名 显示在桌面和最近任务里
uses-permission 权限 见 10.4

改名字用 XML 源码最直接：

xml
<application android:label="你的应用名称">
    <activity android:label="你的应用名称"
              ...>
    </activity>
</application>

两处都改。application 上的 label 决定桌面图标下面那行字，activity 上的 label 决定标题栏。

包名一旦发布就不要再改。改了等于换了一个应用，老用户收不到更新。

10.4 权限 #

权限在清单里声明，Qt Creator 的清单编辑器有个下拉列表可以直接加。常用的几个：

权限 什么时候要
android.permission.INTERNET 任何联网功能，HTTP、WebSocket 都算
android.permission.ACCESS_NETWORK_STATE 判断有没有网
android.permission.READ_EXTERNAL_STORAGE 读手机存储里的文件
android.permission.WRITE_EXTERNAL_STORAGE 往存储里写文件
android.permission.CAMERA 调摄像头
android.permission.ACCESS_FINE_LOCATION 定位

Android 6 之后，危险权限光在清单里声明不够，运行时还要向用户申请。Qt 里用 QtAndroid::requestPermissions 那一套，别指望清单写完就通了。

10.5 OpenSSL：联网功能的额外一步 #

Qt 的安装包不带 OpenSSL，这是法律限制。要用 HTTPS 或 QSslSocket，得自己把 OpenSSL 库塞进 APK，否则联网请求全部失败，报的是「找不到 SSL 后端」。KDAB 维护了一份预编译好的库：https://github.com/KDAB/android_openssl。

CMake 项目用 FetchContent 拉：

text
include(FetchContent)

FetchContent_Declare(
    android_openssl
    GIT_REPOSITORY https://github.com/KDAB/android_openssl.git
    GIT_TAG master
)
FetchContent_MakeAvailable(android_openssl)

if(ANDROID)
    add_android_openssl_libraries(MyApp)
endif()

qmake 项目直接写 android { include(/path/to/android_openssl/openssl.pri) }。Qt Creator 那边在 Devices → Android 的 OpenSSL 设置里指定目录，再到项目设置 Build Android APK 勾上 Include prebuilt OpenSSL libraries。

装完验证一下：

text
#include <QSslSocket>
#include <QDebug>

void checkSsl() {
    qDebug() << "SSL 支持:" << QSslSocket::supportsSsl();
    qDebug() << "SSL 库版本:" << QSslSocket::sslLibraryBuildVersionString();
}

supportsSsl() 返回 false 就是库没进包。这时候先确认 APK 里有没有 libssl_*.so（解压 APK 看 lib/<abi>/），再确认清单里有没有 INTERNET 权限。少任何一个，HTTPS 都走不通。

Android 这条路报错的地方集中，按现象查比按报错原文猜快。

11.1 现象速查表 #

Execution failed for task ':processDebugResources' AGP 与 Gradle 版本不配套 查 android-build/build.gradle，对齐版本后清理重编

11.2 两条高频报错的原文 #

Failed to detect the ABIs used by the Qt version：Qt 的 Android 库没装全，Qt Creator 从 android_arm64_v8a 这几个目录里读不到东西。开 Qt Maintenance Tool → Add or Remove Components，勾上对应版本的 Android 组件，重启 Qt Creator。还报就去 C:\Qt\6.10.0\android_arm64_v8a\lib 看有没有 libQt6Core_arm64-v8a.so。

NDK directory structure isn't correct：路径层级不对，要的是版本目录而不是 ndk 这一层，把 /path/to/ndk 改成 /path/to/ndk/27.2.12479018。改完重选一次 Kit 就生效。

11.3 Gradle 构建失败 #

最常见的是 Execution failed for task ':processDebugResources'，几乎都出在 AGP 与 Gradle 的版本配上。

  1. 打开 android-build/build.gradle，看 com.android.tools.build:gradle 的版本。
  2. 对照 android-build/gradle/wrapper/gradle-wrapper.properties 里的 Gradle 版本，两者必须同代。
  3. 清掉构建目录再编：
bash
rm -rf android-build
cmake --build . --target apk

Gradle 的日志里往上翻，真正的错因在第一次出现的 Caused by 后面。processDebugResources 只是最后一层壳。

11.4 Windows 路径过长 #

报 FileNotFoundException，或者 Gradle 跑到一半莫名失败。Windows 路径默认限 260 字符，而 Android 构建路径叠了 build-android/android-build/build/intermediates/... 这么长一串。把工程挪到 C:\Dev\MyApp 这种短路径最快；不想挪就在组策略或注册表里启用 LongPathsEnabled（Windows 10 以上）。

11.5 装上了但跑不起来 #

先查三件事：解压 APK 看 lib/arm64-v8a/ 下有没有 libQt6Core_arm64-v8a.so；跑 adb shell getprop ro.product.cpu.abi 拿设备 ABI 和 Kit 对一下；再看清单里的 minSdk 有没有高于设备版本。三条都对还是闪退，去 logcat 里找 UnsatisfiedLinkError。卸载重装就能解决的，是签名冲突。
