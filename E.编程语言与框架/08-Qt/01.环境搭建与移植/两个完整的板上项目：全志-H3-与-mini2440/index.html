一、两个案例的背景 #

两块板子差了十来年。放一起看，正好把嵌入式 Qt 的两条路走全：一条是新板子跑新系统、缺桌面，靠平台插件绕过去；一条是老板子跑老架构，靠降版本和裁剪挤进去。

1.1 全志 H3 那块板子 #

NanoPi M1 加法板，友善之臂做的，大小约树莓派的 2/3，能跑 Debian、Ubuntu-MATE、Ubuntu-Core、Android。主控全志 Allwinner H3。引出的口子：HDMI、以太网、USB-Host、USB-OTG、DVP camera、AVOUT（音视频）、板载麦克风、红外接收、兼容树莓派 GPIO、独立调试串口。

烧的是 FriendlyCore，基于 Ubuntu core 22.04 构建，内置 Qt4.8，没有 X11 桌面环境。

1.2 要做的事 #

在这块没有桌面的板子上跑一个 Qt 程序，用 LCD 屏显示车牌识别的结果。识别不在本地算，由局域网里的车牌识别系统推过来。

二、全志 H3：板子与系统准备 #

2.1 把系统摸清楚 #

FriendlyCore 是个没有桌面的 Ubuntu core，开机只有控制台和 fbdev，没有 X server，也没有窗口管理器。这对我们不是坏事，省下的内存和 CPU 全给应用。

Qt 是预装的，板端编译全靠里面的 qmake：

root 密码是 fa。宿主机推代码过去：

bash

现场设备不能靠 DHCP。改 /etc/network/interfaces：

iface eth0 inet static

eth0 拿到 192.168.0.100 就算通了，后面所有 HTTP 请求都打这个地址。

2.4 确认板子能跑图形 #

没有 X11 不等于没有屏。帧缓冲设备是 /dev/fb0，Qt 直接往上面写：

bash
root@NanoPi-M1-Plus:~# ls -l /dev/fb0
crw-rw---- 1 root video 29, 0 Jan 17 2023 /dev/fb0
root@NanoPi-M1-Plus:~# cat /sys/class/graphics/fb0/virtual_size

540x960，竖屏 LCD，和 mainwindow.cpp 里写死的窗口尺寸对得上。

2.5 平台插件只有一个选择 #

Qt 官方文档《How to Build, Install and Setting Qt Application》按板子型号列了可用插件。定位到 Allwinner H3，能选的只有 LinuxFB——通过 Linux 的 fbdev 子系统直接往帧缓冲写像素。中间没有 X server，没有合成器，也没有窗口管理器。这点决定了后面所有的启动参数和调试方式。

三、无 X11 意味着什么 #

3.1 先把「无图形」这个误解打掉 #

听到「系统没有 X11」，很多人的第一反应是这板子画不了界面。不对。

X11 只是 Linux 上众多图形栈里的一种。Qt 画一个按钮，走的是这条链：

text
QWidget / QPainter -> QPA 平台插件（Qt5）或 QWS（Qt4）
                   -> linuxfb / eglfs
                   -> /dev/fb0 或 GPU
                   -> LCD 屏

X11 是中间可选的一层。拿掉它，Qt 直接把像素写进帧缓冲，屏幕照样亮。板子上要的正是这个效果：图形栈更短，内存更省，启动更快。

3.2 三种落地方式 #

方式 中间层 谁在画 依赖 适合
X11 X server + 窗口管理器 X server 软件合成 libX11、xorg、字体 桌面 PC，多窗口
linuxfb 无 CPU 直接写 fb 只要 /dev/fb0 单窗口全屏、无 GPU
eglfs 无 GPU 走 EGL/GLES GPU 驱动、EGL、GLES 有 GPU、要动画
QWS（Qt4） 自带轻量窗口系统 Qt 自己 QtEmbedded 库 Qt4 时代的板子

全志 H3 官方给的是 linuxfb。理由直白：板子不跑多窗口，也不要窗口管理器，一个全屏应用顶满就完事。

3.3 Qt4 和 Qt5 的分界 #

这条线得记住，两个案例正好各占一边：

Qt4.x Qt5.x
图形抽象层 QWS（Qt Window System） QPA（Qt Platform Abstraction）
启动方式 ./app -qws 环境变量 QT_QPA_PLATFORM
指定后端 QWS_DISPLAY QT_QPA_PLATFORM=linuxfb:...
插件形态 编进库里 plugins/platforms/libqlinuxfb.so

H3 上的 Qt4.8.6 走左列，mini2440 上的 Qt5.6 走右列。两套参数别混着用。

3.4 在 H3 上怎么起 #

Qt4 程序要带 -qws，告诉 Qt 别去找 X11，改用自带窗口系统。屏竖装的时候转 90 度：

bash
root@NanoPi-M1-Plus:/opt/PlateLCDDisplay/build# export QWS_DISPLAY='Transformed:Rot90'
root@NanoPi-M1-Plus:/opt/PlateLCDDisplay/build# ./PlateLCDDisplay -qws
参数 作用 取值
-qws 用 Qt/Embedded 窗口系统，不找 X11 开关
QWS_DISPLAY 显示方向与变换 Transformed:Rot90，角度 0/90/180/270

Transformed: 前缀表示做旋转，冒号后面跟 Rot 加角度，不写就是 0 度。

3.5 反过来：有桌面的宿主机更麻烦 #

板子上没 X11，一路顺。宿主机上有 X11，反而多事：

text
X Error: BadShmSeg (invalid shared segment parameter) 128
  Extension:    131 (MIT-SHM)
  Minor opcode: 2 (X_ShmDetach)
  Resource id:  0x2c0000c

MIT-SHM 是 X11 的共享内存扩展，远程桌面或虚拟显示环境下经常不通。在 /etc/environment 末尾加一行，然后 source 一下再跑：

text
QT_X11_NO_MITSHM=1

这个坑只在宿主机出现，板子上碰不到。写在这里是因为你一定会先在宿主机跑通再往板子搬，撞上了别以为是代码的问题。

3.6 代价要认 #

省掉 X11 不是白拿的：

少了什么 后果 怎么补
窗口管理器 只有一个全屏窗口，多窗口叠不起来 用 QStackedWidget 自己切页
窗口装饰 没有标题栏、没有关闭按钮 Qt::FramelessWindowHint
系统输入法 中文输入得自己接 内嵌软键盘，或只读显示
鼠标指针 默认没有指针图形 -qws 下带 -mouse，或不管
剪贴板 跨应用复制粘贴没有 应用内自己存

这个项目的窗口开头就是无边框加置顶，尺寸按屏幕写死 540x960：

cpp
setWindowFlags(Qt::CustomizeWindowHint | Qt::FramelessWindowHint | Qt::WindowStaysOnTopHint);

没有窗口管理器时 WindowStaysOnTopHint 没意义，留着不碍事。

四、Qt WebApp 是什么 #

4.1 一句话定位 #

Qt WebApp 是个 C++ 写的轻量 HTTP 服务器模板库，灵感来自 Java Servlet。

它干的事：让你的 Qt 程序自己开一个 HTTP 端口，外面用浏览器或 HTTP 客户端就能访问进来。

它不干的事：它不是通用 Web 框架，不是替代 nginx 的东西，也不处理前端页面渲染。你给它一个请求，它调你的 service()，你在里面写响应。

判断要不要用它：

你想做的事 合不合适
给设备做一个配置页 合适
给设备留一个远程控制接口 合适
让上位机用 HTTP 推数据进来 合适
当静态网站服务器 勉强能，用它自带的 StaticFileController
扛几千并发做公网服务 不合适，换 nginx
做完整 MVC Web 应用 不合适，没路由表、没 ORM、没中间件

4.2 三个组件 #

组件 目录 作用
HTTP 服务器 httpserver/ HTTP(S) 1.0/1.1，多线程连接处理
模板引擎 templateengine/ 变量替换，把数据填进 HTML
缓冲记录器 logging/ 日志落文件，支持滚动与运行时改配置

4.4 配置文件长什么样 #

整个库靠一个 ini 驱动，[listener] 段管网络：

text
[listener]
;ip=192.168.0.110
port=80
minThreads=4
maxThreads=100
cleanupInterval=60000
readTimeout=10000
maxRequestSize=6000000
maxMultiPartSize=10000000
键 含义 注意
ip 监听地址 注释掉就监听所有网卡
port 监听端口 80 要 root，内部服务用 8080 省事
minThreads 空闲工作线程下限 从空池起步，线程按需创建
maxThreads 并发线程上限 上生产前用压测工具量
cleanupInterval 回收空闲线程的间隔（毫秒） 每个周期关一个空闲线程
readTimeout 连接空载超时（毫秒） 防「只连不发」的简单 DoS
maxRequestSize 常规请求体上限（字节） 防大请求把内存吃穿
maxMultiPartSize 上传文件上限（字节） 防恶意大文件

这堆参数里只有 port 和 maxThreads 是必调的。板子内存小，maxThreads 别照抄 100。

五、在 H3 上搭 Web Server #

5.1 先想清楚在哪写代码 #

板子上内置 Qt4.8。稳妥做法是宿主机装一套同样的 Qt4.8，代码拷过去直接编。

这里没这么干。宿主机开发环境是 Qt6.5.0，先在 Qt6.5 上把功能写顺，再回板子上改兼容性：

5.3 封装一个 HttpServerManager #

直接调 HttpListener 也能跑，但配置读取、线程管理、单例访问会散在各处。包一层。

bash
root@zhengyang:/opt/qt-project/PlateLCDDisplay/modules# mkdir httpServerManager && cd httpServerManager
root@zhengyang:/opt/qt-project/PlateLCDDisplay/modules/httpServerManager# touch HttpServerManager.h HttpServerManager.cpp
root@zhengyang:/opt/qt-project/PlateLCDDisplay/modules/httpServerManager# touch HelloworldRequestHandler.h HelloworldRequestHandler.cpp
root@zhengyang:/opt/qt-project/PlateLCDDisplay/modules/httpServerManager# touch httpServerManager.pri
文件 作用
httpServerManager.pri 子工程文件，作用类似 Makefile 片段，登记头文件与源文件
HttpServerManager.h/.cpp 读配置、起监听、持有日志器，单例
HelloworldRequestHandler.h/.cpp 请求处理实现，后面拆成控制器

httpServerManager.pri：

INCLUDEPATH += $$PWD
DEPENDPATH += $$PWD

CONFIG(debug, debug|release) {
    DEFINES += SUPERVERBOSE
}

HEADERS += $$PWD/HttpServerManager.h \
    $$PWD/HelloworldRequestHandler.h

SOURCES += $$PWD/HttpServerManager.cpp \
    $$PWD/HelloworldRequestHandler.cpp

再往 .pro 加 include ($$PWD/modules/httpServerManager/httpServerManager.pri)。

头文件里除了单例入口 getInstance() 和两个槽，就是八个配置项的 getter/setter：

cpp
class HttpServerManager : public QObject
{
    Q_OBJECT
private:
    explicit HttpServerManager(QObject *parent = 0);

public:
    static HttpServerManager *getInstance();
    // ip / port / minThreads / maxThreads
    // cleanupInterval / readTimeout / maxRequestSize / maxMultiPartSize
    // 每一项都配一对 getXxx() / setXxx()
    QString searchConfigFile();

public slots:
    void slot_start();
    void slot_stop();

private:
    static HttpServerManager *_pInstance;
    static QMutex _mutex;
    bool _running;
    HttpListener *_pHttpListener;          /* http 服务监听器 */
    QSettings *_pHttpListenerSettings;     /* http 服务器配置 */
};

.cpp 三块关键逻辑。第一块是单例与默认值，构造里的值是「配置读失败时的兜底」：

cpp
HttpServerManager::HttpServerManager(QObject *parent)
    : QObject(parent), _pHttpListener(0), _pHttpListenerSettings(0),
    _running(false), _port(8088), _minThreads(2), _maxThreads(10),
    _cleanupInterval(60000), _readTimeout(60000),
    _maxRequestSize(100), _maxMultiPartSize(1024*1024*1024)
{
}

HttpServerManager *HttpServerManager::getInstance()
{
    if(!_pInstance)
    {
        QMutexLocker lock(&_mutex);
        if(!_pInstance) { _pInstance = new HttpServerManager(); }
    }
    return _pInstance;
}

第二块是 slot_start()。读 ini 的 [listener] 组，逐项塞进成员，最后 new HttpListener，把请求处理器交给它：

cpp
void HttpServerManager::slot_start()
{
    if(_running) { LOG_Debug << "It's running!!!"; return; }
    _running = true;

    QString httpServerPath = searchConfigFile();
    LOG_Debug << httpServerPath << "exit:" << QFile::exists(httpServerPath);

    if(!_pHttpListenerSettings)
    {
        _pHttpListenerSettings = new QSettings(httpServerPath, QSettings::IniFormat);
        _pHttpListenerSettings->beginGroup("listener");
        qDebug("config file loaded");

        setIp(_pHttpListenerSettings->value("ip").toString());
        setPort(_pHttpListenerSettings->value("port").toUInt());

5.4 第一个请求处理器 #

实现只重写 service() 一个虚函数：

cpp
void HelloworldRequestHandler::service(HttpRequest& request, HttpResponse& response)
{
    QString text = "全志H3 - Qt & QtWebApp搭建Http Server（无X11系统）Hello world!";

    QByteArray data = text.toLocal8Bit();          // 转本地编码字节数组

    response.setHeader("Content-Type", "text/plain; charset=utf-8");
    response.write(data,true);
}

这里没做 URI 分发：访问 /、/abc 还是 /API，回的都是同一句话。够验证通路，不够干活。

response.write() 两个参数：

参数 类型 说明
data QByteArray 响应体内容
lastPart bool，默认 false 是否最后一块

lastPart=true 时自动补 Content-Length。不设 Content-Length 也不设 Connection: close，就走分块传输（Chunked Transfer Encoding）。

源码里中文用 toLocal8Bit() 转字节，而 Content-Type 又声明 charset=utf-8。这两件事要一致，否则浏览器解出来是乱码。宿主机 locale 是 UTF-8 时碰不出问题，板子上 locale 不对就露馅——第六章会踩到。

void PlateController::service(HttpRequest& request, HttpResponse& response)
{
    QJsonParseError err;
    QJsonDocument json_recv = QJsonDocument::fromJson(request.getBody(),&err);
    if(json_recv.isNull()) { ResponseUtils::fail(response, nullptr); return; }

    QJsonObject object = json_recv.object();
    if(!object.contains("requestid") || !object.contains("data"))
    { ResponseUtils::fail(response, nullptr); return; }

    QString requestid   = object.value("requestid").toString();
    QString servicename = object.value("servicename").toString();
    QJsonValue value    = object.value("data");

    if(value.isObject() && servicename == "welcome")
    {
        QJsonObject data = value.toObject();
        plate_welcome plate;
        plate.carmark = data.value("carmark").toString();
        plate.line1   = data.value("line1").toString();
        plate.line2   = data.value("line2").toString();
        plate.line3   = data.value("line3").toString();

        // 缺字段就用默认字号与颜色
        plate.carmarkSize  = data.value("carmarkSize").toString().isEmpty()  ? 59 : data.value("carmarkSize").toString().toInt();
        plate.line1Size    = data.value("line1Size").toString().isEmpty()    ? 44 : data.value("line1Size").toString().toInt();
        plate.line2Size    = data.value("line2Size").toString().isEmpty()    ? 44 : data.value("line2Size").toString().toInt();
        plate.line3Size    = data.value("line3Size").toString().isEmpty()    ? 44 : data.value("line3Size").toString().toInt();
        plate.carmarkColor = data.value("carmarkColor").toString().isEmpty() ? "#FFF" : data.value("carmarkColor").toString();
        plate.line1Color   = data.value("line1Color").toString().isEmpty()   ? "#FFF" : data.value("line1Color").toString();
        plate.line2Color   = data.value("line2Color").toString().isEmpty()   ? "#FFF" : data.value("line2Color").toString();
        plate.line3Color   = data.value("line3Color").toString().isEmpty()   ? "#FFF" : data.value("line3Color").toString();
        plate.pictureUsed  = data.value("pictureUsed").toString().isEmpty()  ? 0 : data.value("pictureUsed").toString().toInt();

        LOG_Info << "carmark:" << plate.carmark << "line1:" << plate.line1;
        LOG_Info << "line2:" << plate.line2 << "line3:" << plate.line3;

        emit welcome(plate);
        ResponseUtils::success(response, requestid);
        return;
    }

    if(value.isObject() && servicename == "advLoadImage")
    {
        QJsonObject data = value.toObject();
        QString advName = data.value("AdvName").toString();
        QString base64  = data.value("Data").toString();

        if(!base64.isEmpty() && !advName.isEmpty())
        {
            QByteArray byteArray = QByteArray::fromBase64(base64.toLocal8Bit());

            QImage image;
            if(image.loadFromData(byteArray,"jpg"))
                LOG_Info << "Image loaded successfully.";
            else
                LOG_Info << "Failed to load image.";

            QDir dir(HttpServerManager::getInstance()->getBgPath());
            QString filePath = dir.filePath(advName + ".jpg");

            if (image.save(filePath)) {
                LOG_Info << "Image " << filePath << " saved successfully!";
                ResponseUtils::success(response, requestid);
            } else {
                LOG_Info << "Image " << filePath << " saved failed!";
                ResponseUtils::fail(response, nullptr);
            }
            return;
        }
    }

    ResponseUtils::fail(response, nullptr);
}

6.6 用 HTTP 接口改 IP #

三个字段先校验再落盘：ip 用 QHostAddress(ip).isNull() 判，netmask 转 toIPv4Address() 后逐位检查是不是连续掩码，gateway 同 ip 的判法。

cpp
void IPsettingcontroller::service(HttpRequest& request, HttpResponse& response)
{
    Parser parser; bool ok;
    QVariantMap result = parser.parse(request.getBody(), &ok).toMap();
    if(!ok) { ResponseUtils::fail(response, nullptr); return; }

    QString requestid = result["requestid"].toString();
    QString ip = result["ip"].toString();
    QString netmask = result["netmask"].toString();
    QString gateway = result["gateway"].toString();

    if(!validateIPAddress(ip))    { ResponseUtils::fail(response, requestid, "IP地址不合法"); return; }
    if(!validateNetmask(netmask)) { ResponseUtils::fail(response, requestid, "子网掩码不合法"); return; }
    if(!validateGateway(gateway)) { ResponseUtils::fail(response, requestid, "网关不合法"); return; }

    // 清空后重写
    QFile file("/etc/network/interfaces");
    file.open(QIODevice::WriteOnly | QIODevice::Truncate | QIODevice::Text);
    file.close();

    QFile configFile("/etc/network/interfaces");
    configFile.open(QIODevice::Append | QIODevice::Text);
    QTextStream out(&configFile);
    out << "auto eth0\n" "iface eth0 inet static\n"
        "address " << ip << "\n" "netmask " << netmask << "\n"
        "gateway " << gateway << "\n";
    configFile.close();

    QProcess process;
    process.start("sudo systemctl restart networking");
    process.waitForFinished(-1);

    ResponseUtils::success(response, requestid);
}

七、mini2440：老兵不老 #

S3C2440 是 ARM920T 核，ARMv4T 架构，没有硬件浮点。板子上 64M SDRAM、NAND Flash，跑 linux 5.2.8 加 busybox 1.25.0。

这块板子的价值不在性能，在于它是「最坏情况」的样本。能在这上面把 Qt 跑起来，换任何一块新板子都只是换参数：

约束 数字 后果
架构 ARMv4T Qt 5.7 起不再支持，最高只能到 5.6
内存 64M SDRAM 库要裁，-no-* 一堆
浮点 无硬件 FPU 必须 -msoft-float，-qreal float
存储 NAND，烧写要整包进内存 库目录不能整个塞根文件系统
显示 240x320 LCD，/dev/fb0 走 linuxfb，别想 GPU
输入 触摸屏，靠 tslib 必须编 tslib 插件

八、Qt5.6 在 mini2440 上的可行性 #

8.1 版本谱系先分清 #

Qt 的包名容易搞混：

名字 指什么
Qt/X11 用于 Linux/Unix，如 qt-x11-opensource-src-4.5.3.tar.gz，给 PC 用
Qt Windows 用于 Windows
qt-everywhere 配不同参数既能编 x86 也能编 ARM，Qt4.6 起提供
Qt/Embedded 给 ARM 的版本，如 qt-embedded-linux-opensource-src-4.5.3.tar.gz

Qt/Embedded 从 Qt4.1 改名 Qtopia Core，Qt4.4.1 又改名 Qt for Embedded Linux，到 Qt4.6 之后不再单独发这种包，统一发 qt-everywhere。

8.2 为什么钉死在 5.6 #

新版 Qt 已经不认 ARMv4T 了，mini2440 只能选 5.6，再高编不过。

bash
root@zhengyang:/work/sambashare/tools# wget https://download.qt.io/new_archive/qt/5.6/5.6.0/single/qt-everywhere-opensource-src-5.6.0.tar.xz
root@zhengyang:/work/sambashare/tools# tar -xvf qt-everywhere-opensource-src-5.6.0.tar.xz

镜像用 https://download.qt.io/archive（官方）、中科大（旧版本较全）、清华。

8.3 裁剪清单 #

配置项 作用
-no-opengl 没 GPU，省一大块
-no-cups / -no-nis / -no-openssl 不打印、不用网络目录、不做 TLS
-no-glib / -no-dbus 少两个运行时依赖
-nomake tools / -nomake examples 不编工具与例子，省时间省空间
-no-gif / -qt-libjpeg / -qt-libpng / -qt-zlib 图片与压缩按需留，zlib 用 Qt 自带的
-qreal float 实数用 float，ARMv4T 上 double 没有硬件支持
-tslib 接触摸屏
-shared / -no-rpath 动态库，不写死运行时路径

裁完 lib 加 plugins 还是不小，后面得挑着拷进根文件系统。

九、移植步骤 #

9.1 改 qmake.conf #

改的是 qtbase/mkspecs/linux-arm-gnueabi-g++/qmake.conf。原文件里编译器写的是 arm-linux-gnueabi-gcc 那套裸名字，我们装的是 arm-linux-gcc 4.8.3，名字和路径都对不上，得逐项换掉，同时补几项 ARMv4T 特有的东西：

改动 值 为什么
Qt_QPA_DEFAULT_PLATFORM linuxfb 默认平台插件定成 linuxfb
QMAKE_CFLAGS / QMAKE_CXXFLAGS -msoft-float -D__GCC_FLOAT_NOT_NEEDED 硬件不支持浮点，软件模拟
同上 -O0，并删掉 -O1/-O2/-O3 优化等级拉高编译器会乱来，先关掉
QMAKE_CC / QMAKE_CXX / QMAKE_LINK / QMAKE_LINK_SHLIB 绝对路径 + -march=armv4t -mtune=arm920t 必须写全路径，架构钉死
QMAKE_AR / QMAKE_OBJCOPY / QMAKE_NM / QMAKE_STRIP 绝对路径 同上

改完的样子：

text
Qt_QPA_DEFAULT_PLATFORM = linuxfb
QMAKE_CFLAGS   += -msoft-float -D__GCC_FLOAT_NOT_NEEDED
QMAKE_CXXFLAGS += -msoft-float -D__GCC_FLOAT_NOT_NEEDED

QMAKE_CXXFLAGS += -O0
QMAKE_CXXFLAGS -= -O1
QMAKE_CXXFLAGS -= -O2
QMAKE_CXXFLAGS -= -O3
QMAKE_CFLAGS += -O0
QMAKE_CFLAGS -= -O1
QMAKE_CFLAGS -= -O2
QMAKE_CFLAGS -= -O3

include(../common/linux.conf)
include(../common/gcc-base-unix.conf)
include(../common/g++-unix.conf)

QMAKE_CC         = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-gcc  -march=armv4t -mtune=arm920t
QMAKE_CXX        = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-g++  -march=armv4t -mtune=arm920t
QMAKE_LINK       = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-g++  -march=armv4t -mtune=arm920t
QMAKE_LINK_SHLIB = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-g++  -march=armv4t -mtune=arm920t

QMAKE_AR         = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-ar cqs
QMAKE_OBJCOPY    = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-objcopy
QMAKE_NM         = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-nm -P
QMAKE_STRIP      = /usr/local/arm/4.8.3/bin/arm-none-linux-gnueabi-strip
load(qt_config)

9.5 挑着拷进根文件系统 #

不能把 lib 和 plugins 整个拷进根文件系统。做完的镜像会超 64M SDRAM 的量，而 uboot 烧写是把整包读进内存再写 NAND，超了就烧不进去。走 NFS 启动没这个限制。

副本策略：留一份完整的在原处，另做一份只含 lib 和 plugins 的推给板子：

bash
root@zhengyang:/usr/local# cp -rfd qt5.6 qt5.6-1
root@zhengyang:/usr/local/qt5.6# rm -rf doc include bin mkspecs qml translations
root@zhengyang:/usr/local# mkdir -p /work/nfs_root/rootfs/usr/local/
root@zhengyang:/usr/local# cp -rfd qt5.6 /work/nfs_root/rootfs/usr/local/
root@zhengyang:/usr/local# rm -rf qt5.6 && mv qt5.6-1 qt5.6

板子上只剩两个目录：lib 和 plugins。根文件系统在 /work/nfs_root/rootfs，环境变量写进它的 /etc/profile：

bash
export QtEDIR=/usr/local/qt5.6
export LD_LIBRARY_PATH=/usr/local/qt5.6/lib:$LD_LIBRARY_PATH
export Qt_QPA_GENERIC_PLUGINS=tslib
export Qt_QPA_FONTDIR=$QtEDIR/lib/fonts
export Qt_QPA_PLATFORM_PLUGIN_PATH=$QtEDIR/plugins
export Qt_QPA_PLATFORM=linuxfb:fb=/dev/fb0:size=240x320:offset=0x0:tty=/dev/tty1
export Qt_QPA_FB_TSLIB=1
export LD_PRELOAD=/lib/preloadable_libiconv.so

Qt_QPA_PLATFORM 那行是关键：linuxfb 指定后端，fb= 指定帧缓冲设备，size= 指定分辨率，tty= 指定控制台。Qt_QPA_FB_TSLIB=1 让 linuxfb 接 tslib 的触摸事件。

9.6 补 libiconv #

最后一行 LD_PRELOAD 指向 libiconv。这是编码转换库，PC 上的 glibc 自带，arm-linux 下得自己编：

bash
root@zhengyang:/work/sambashare/tools# wget https://ftp.gnu.org/pub/gnu/libiconv/libiconv-1.14.tar.gz
root@zhengyang:/work/sambashare/tools# tar xzvf libiconv-1.14.tar.gz && cd libiconv-1.14
root@zhengyang:.../libiconv-1.14# CC=arm-linux-gcc ./configure --host=arm-linux --prefix=/usr/local/libiconv CFLAGS="-march=armv4t -O2 -Wall -W" --enable-static
root@zhengyang:.../libiconv-1.14# make

make 卡在老代码上：

text
./stdio.h:1010:1: error: 'gets' undeclared here (not in a function)
 _GL_WARN_ON_USE (gets, "gets is a security hole - use fgets instead");
Makefile:914: recipe for target 'progname.o' failed

新版 glibc 把 gets 拿掉了。改 srclib/stdio.in.h，把那一行套进条件编译：

_GL_WARN_ON_USE (gets, "gets is a security hole - use fgets instead");
#endif

拿 digitalclock 开刀，Kit 选 Mini2440 Qt 5.6.0 GCC 32bit，【构建】里先【执行 qmake】再【重新构建项目】，然后把它拷进根文件系统：

bash
[root@zy:/]# ./digitalclock
digitalclock (56): undefined instruction: pc=(ptrval)
CPU: 0 PID: 56 Comm: digitalclock Not tainted 5.2.8 #31
Hardware name: Samsung S3C2440 (Flattened Device Tree)
PC is at 0xb601b7d0
Code: e3500000 0a000022 e59f70e8 e3a06c01 (ee070fba)

非法指令。先确认文件架构，arm-linux-readelf -A digitalclock 报 Tag_CPU_name: "4T"、Tag_CPU_arch: v4T，架构没错。

那就看是哪条指令。内核打这条日志的地方是：

c
#ifdef CONFIG_DEBUG_USER
        if (user_debug & UDBG_UNDEFINED) {
                pr_info("%s (%d): undefined instruction: pc=%p\n",
                        current->comm, task_pid_nr(current), pc);
                __show_regs(regs);  dump_instr(KERN_INFO, regs);

要这条日志出来，得 CONFIG_DEBUG_USER 开着，还要靠命令行参数 user_debug 打开对应位——在 uboot 的 bootargs 里加 user_debug=31。之前已经配好了，所以能看到 PC。

dump.dis 有 9M 多，里面没定位到 ee070fba。这一步卡住，留给 arm-linux-gdb 远程调试接着查。

十一、可以复用的经验 #

先问板子支持到哪个版本，再决定写什么代码。 H3 上写 Qt6.5 的代码，到板子上 qInfo() 都没有；mini2440 上想用 Qt5.15，编译器直接告诉你 ARMv4T 不认。两个坑都是「先写后查」造成的。

配置文件的搜索路径要多写几条。 开发机上是 build/../etc，板子上是 /opt/xxx/etc，同一份代码要都能找到。searchConfigFile() 那七个候选路径就是为这个准备的。

HTTP 线程和 UI 线程分开。 moveToThread 加信号槽，是这套结构里唯一不能省的东西。HTTP 线程直接 setText() 会随机崩，而且崩得没法复现。

日志缓冲处理完就清。 线程复用会把上一个请求的上下文带到下一个，排错时看日志能把自己看晕。

板子上先跑通最小程序，再上业务。 digitalclock 这种几十行的例子，一次能把库路径、平台插件、字体、触摸全试出来。

能换格式就换格式，别跟插件死磕。 jpg 插件在 H3 上折腾半天没生效，换成 png 十分钟解决。

十二、易错点速查 #

现象 原因 处理
程序起不来，报找不到平台插件 -qws 没带，或 QT_QPA_PLATFORM 没设 Qt4 加 -qws；Qt5 设 QT_QPA_PLATFORM=linuxfb:fb=/dev/fb0
