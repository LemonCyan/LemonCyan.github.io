一、QML 与 Qt Quick 的分工 #

先掐掉一个常见误会：把 QML 和 Qt Quick 当成同一个东西。不是。

QML 是语言。 全称 Qt Meta-Object Language，一门声明式的界面描述语言。它管的是「界面怎么被写出来」：语法、属性、绑定、表达式、内嵌 JavaScript。文件后缀 .qml，内容是文本。谁来解析、谁来画，它不管。

Qt Quick 是框架。 它用 QML 这门语言写成，提供一整套视觉元素（Item、Rectangle、Text、Image）、视图控件、定位器、动画与过渡。跑起来靠 Qt Quick 的场景图渲染后端。

所以「用 QML 做界面」这句口头禅，准确说法是：用 QML 写，由 Qt Quick 渲染。语言负责表达，框架负责实现。

分清这一点有实际好处。报错里出现 QtQuick 模块名，是框架没导入或版本不对；报错说语法错误，是语言层面写错。两类问题的排查路径不同，混在一起只能瞎猜。

声明式不是命令式 #

这是本篇最要紧的一段。

写 C++ 界面时，你在下命令：先 new 一个按钮，再 setGeometry(10, 10, 100, 30)，接着 connect 信号槽，窗口一缩放，你还要响应 resizeEvent 重新算一遍坐标。代码是一串按时间执行的步骤，界面是这些步骤跑完之后的残影。

写 QML 时，你描述的是「界面应该长什么样」。不写步骤，写关系：

qml
Rectangle {
    width: 400; height: 300

    Rectangle {
        width: parent.width / 2
        height: parent.height / 2
        color: "steelblue"
    }
}

width: parent.width / 2 不是一个赋值动作。它是一句声明：这个宽度永远等于父级宽度的一半。父级改宽，子级自动跟着改，你一行事件处理代码都不用写。

这就是声明式与命令式最根本的差别。引擎在背后维护一张依赖表，谁依赖谁记得清清楚楚，被依赖的值一变，依赖它的表达式重新求值。你描述状态，引擎负责让状态成立。

Qt5 里的三种程序形态 #

同一个 Qt5，能做出三种形态完全不同的程序，选型前先把边界划清楚：

形态 模板/入口 界面 典型场景
控制台应用 QCoreApplication 无界面 命令行工具、服务端守护进程、批处理
传统窗口应用 QApplication + QWidget 原生控件逐层绘制 重型 PC 客户端、表单类业务系统
Qt Quick 应用 QGuiApplication + QML 场景图 GPU 加速 触摸终端、动效密集的现代界面

控制台应用没有渲染开销，QString、容器、文件 I/O 照样能用，做数据加工最省心。QWidget 那套是最成熟的桌面写法，控件齐、年头长、坑都被踩平了。Qt Quick 强在动效与跨端，适合屏幕会动的地方。

混编是大型项目的常态：C++ 扛底层逻辑与重计算，QML 扛前端界面与交互。谁擅长什么就让谁干，别硬把动画塞进 paintEvent，也别拿 QML 去算大数据。

QML 与 C++ 各管什么 #

维度 QML C++
描述方式 声明式，写状态与关系 命令式，写执行步骤
主要职责 界面结构、样式、动效、交互 数据结构、算法、网络、存储
属性更新 绑定表达式自动重算 手动 setXxx 触发重绘
动画 一行 Behavior 或 NumberAnimation 定时器改值 + update()
布局适配 锚点、绑定，随父级伸缩 重写 resizeEvent 重算几何
热改界面 改完 .qml 直接跑，不用重编译 改一个像素也要重编译链接
执行开销 属性求值、绑定维护有成本 直接，贴近机器
适合写 看得见的部分 算得清的部分

一句话记住分工：看得见的交给 QML，算得清的交给 C++。

二、从 Qt4 到 Qt5 的架构变化 #

这段历史值得花五分钟看，因为它直接决定你今天 .pro 文件里写什么。

Qt4 的老路：Graphics View #

Qt4 时代的 QML 主要跑在 Graphics View Framework（图形视图框架） 上。QGraphicsScene 装图元，QGraphicsView 负责显示，每个 QML 元素对应一个图元对象。

这条路的问题很实在：图元是软件绘制的，一帧一帧往窗口上刷，用不上显卡。界面元素一多，动画就掉帧；全屏淡入淡出这种效果，全靠堆 CPU。当时的 QML 更像一个实验品，跑在桌面和早期移动设备上都吃力。

Qt5 换了引擎：Scene Graph #

Qt5 把渲染后端整个换掉，改为基于 OpenGL Scene Graph（场景图） 的硬件加速体系。元素不再是一个个独立图元，而是先组织成一棵场景图节点树，再批量提交给 GPU，一次绘制调用画一批。动画因此变成改节点属性的事，GPU 跟着重绘。

同时废弃了 Qt4 里庞大的 QtDeclarative 模块，按职责拆成两个：

新模块 职责
Qt QML QML 语言解析、JavaScript 运行环境、与 C++ 类型的绑定引擎
Qt Quick 视觉元素画布、视图控件、过渡动画、场景图渲染

拆分的意义在于解耦。只用语言能力（比如写个配置解析器）不必拖上整套视觉元素；只用视觉元素时，语言层也独立演进。

落到工程文件上 #

.pro 里必须显式链接这两个模块，缺一个就编译或链接报错：

QT += qml quick

C++ 里引入对应头文件，注意 Qt5 的类名已经换过一轮，QDeclarativeView 那一套不再使用：

cpp
#include <QQmlEngine>       // QML 引擎
#include <QQmlComponent>    // 组件加载与实例化
#include <QQmlApplicationEngine>  // 应用级引擎，推荐入口
#include <QQuickView>       // 现成的窗口容器

用 CMake 的工程则写：

text
find_package(Qt5 COMPONENTS Qml Quick REQUIRED)
target_link_libraries(HelloQml PRIVATE Qt5::Qml Qt5::Quick)

旧教程里那些 QT += declarative、#include <QDeclarativeView> 的写法，在 Qt5 下会直接失败。看到这类代码，说明它是 Qt4 时代的，思路可以参考，代码不能照抄。

三、创建第一个 QML 程序 #

装什么 #

机器上要有带 Qt Quick 2.0+ 的 Qt 开发包。官方离线安装包（Qt 5.2.0 或更高）勾上对应套件的 Qt Quick 组件，装完启动 IDE Qt Creator。

套件（Kit）这一项别漏。Qt Creator 里，编译器、Qt 版本、调试器三者绑成一个 Kit，建工程时选哪个 Kit，就决定了用哪套 qmake 和哪个版本的 Qt 库。装包时只勾了 MSVC 没勾 MinGW，建工程时 Kit 列表会是空的，那不是 Qt Creator 坏了，是组件没装全。

走一遍向导 #

第一步，开向导。 点左上角 文件 → 新建文件或项目...，快捷键 Ctrl + N。

第二步，选模板。 左侧分类选 Application（应用程序），右侧模板选 Qt Quick Application，点「选择」。

第三步，填名称与路径。 项目名例如 HelloQml，路径自己挑。

路径里不要出现中文、空格、特殊字符。qmake、Makefile、链接器三层都会在这种路径上绊倒，报错信息还各说各话。放到 D:\work\HelloQml 这种干净路径下，能省掉一整类玄学问题。

第四步，选 Kit 与组件库。 勾上本机已装的编译链（例如 Desktop Qt 5.x MSVC2015/MinGW），后面一路「下一步」，最后「完成」。

整个流程压成一条线：

text
新建文件或项目
  -> Application / 应用程序
  -> Qt Quick Application / 模板
  -> 输入项目名称与路径（不含中文、空格、特殊字符）
  -> 选择 Qt 套件 Kit 与默认组件库
  -> 生成初始 QML 模板工程

生成出来的三个核心文件 #

向导跑完，项目树里能干活的主要是这三个：

文件 角色 说明
main.cpp C++ 引导入口 创建应用对象与 QML 引擎，加载首个 QML 界面
main.qml QML 界面描述 定义窗口外观与内部布局
qml.qrc 资源配置 把 QML 源码与图片打包进最终 .exe

.qrc 这个容易被忽略。少了它，程序在开发机上跑得好好的，拷到别人机器上就白屏——因为 QML 文件没被打进二进制，运行时找不到。Qt Creator 新建工程时会自动把 main.qml 加进去，你后面新增 .qml 文件时，要记得手动加进 qml.qrc。

main.cpp：C++ 引擎引导端 #

cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);

    // 创建 QML 应用程序引擎
    QQmlApplicationEngine engine;

    // 引导加载资源包中的首个 QML 文件
    engine.load(QUrl(QStringLiteral("qrc:///main.qml")));

    return app.exec();
}

注意这里用的是 QGuiApplication，不是 QApplication。QGuiApplication 不带 QWidget 那一套，只提供窗口与事件循环，QML 界面够用，依赖也更轻。工程里确实要混进 QWidget 窗体，才换成 QApplication。

engine.load() 是异步的入口：它把 QML 文件编译成组件再实例化，app.exec() 之后事件循环接管。加载失败时 engine.rootObjects() 为空，程序不崩但也没窗口，所以排查白屏先看这条。

main.qml：QML 界面描述端 #

qml
import QtQuick 2.2
import QtQuick.Window 2.1

// 定义窗口组件
Window {
    visible: true
    width: 360
    height: 360
    title: qsTr("Hello QML World")

    // 在窗口中放置一个文本组件
    Text {
        text: qsTr("Hello World")
        anchors.centerIn: parent
        font.pointSize: 20
        color: "blue"
    }
}

两类东西要分清：Window 来自 QtQuick.Window 模块，是真正带标题栏的系统窗口；Text 来自 QtQuick，是画在窗口里的元素。只导入 QtQuick 不导入 QtQuick.Window，Window 就是未知类型，报「is not a type」。

qsTr() 包住的是待翻译字符串，交给 lupdate/lrelease 抽取时能识别。界面上的文字都该这么包，哪怕现在不打算做多语言。

编译运行 #

左下角点绿色三角 运行，快捷键 Ctrl + R。编译通过后，弹出一个窗口，中间一行居中的蓝色文字。

跑起来之后还有个小插曲。有些同学会在应用程序输出窗口看到这么一行：

text
QML debugging is enabled. Only use this in a safe environment.

说明当前是 Debug 模式，Qt 默认开了 QML 调试端口，好让 IDE 能断点、能看性能剖析。发版给用户时切到 Release 模式，或者在 .pro 里注销 QML 调试选项，这行提示就不再出现。

另一种入口：Qt Quick UI 项目 #

模板列表里还有个 Qt Quick UI，它只生成 QML 文件，不带 main.cpp，用 qmlscene 或 Qt Creator 的 QML 预览直接跑。写单页界面、试控件效果，这个最省事。

最小的 HelloWorld.qml：

qml
import QtQuick 2.0

Rectangle {
    width: 360; height: 360
    color: "lightgray"

    Text { anchors.centerIn: parent; text: "Hello World"; font.pointSize: 16 }

    MouseArea {
        anchors.fill: parent
        onClicked: Qt.quit()   // 点击界面任意地方退出程序
    }
}

这段代码把 QML 的结构讲透了：顶层是一个 360×360 的矩形，中心摆一行文字，上面再盖一层 MouseArea 负责接收点击。没有 main，没有事件循环，Qt.quit() 直接结束。

四、QML 的语法骨架 #

QML 的语法不长，一屏能写完。真正需要花时间的是属性与绑定那一章的语义，语法本身记住下面几条就够。

一个完整的例子 #

qml
// rectangle.qml
import QtQuick 2.0

// 根元素为 Rectangle
Rectangle {
    id: root
    width: 120; height: 240
    color: "#D8D8D8"

    // 子元素 1：图片
    Image {
        id: rocket
        x: (parent.width - width) / 2; y: 40
        source: 'assets/rocket.png'
    }

    // 子元素 2：文本
    Text {
        y: rocket.y + rocket.height + 20
        width: root.width
        horizontalAlignment: Text.AlignHCenter
        text: 'Rocket'
    }
}

这段代码里能看出 QML 的层级结构：Image 和 Text 都写在 Rectangle 的大括号里，它们就是 Rectangle 的子元素。子元素隐式继承父元素的坐标系，x、y 永远相对于父元素计算，不是相对整个屏幕。

x: (parent.width - width) / 2 是水平居中的常见写法：父宽减自身宽，剩下一半放左边。parent 指直接父元素，width 指自己。

五条硬规矩 #

import 在第一行，且在根元素之前。 引入指定版本的模块。做基础界面先导入 QtQuick 2.0，用到 Window 再加 QtQuick.Window 2.1。版本号写高了没有、写低了缺属性，都会在加载时报错。

每个 .qml 文件有且仅有一个根元素。 两个并列的顶层对象不合法。需要多个并列物，外面包一层 Item。

属性写成 name: value。 冒号不是赋值的分号，是键值声明。一行可以写多个属性，用分号隔开：width: 120; height: 240。

注释与 C++、JS 一致。 单行 //，多行 /* ... */。

用 id 给元素起名。 id 在文件内唯一，不能有引号，首字符必须小写。需要被别的元素引用时才起 id，不是每个元素都要。最外层根元素统一叫 id: root，能少踩一类引用混乱的坑。

语法元素速查 #

语法元素 写法 要点
模块导入 import QtQuick 2.0 必须在根元素之前
根元素 Rectangle { ... } 全文件仅一个
子元素 大括号内嵌套 隐式继承父坐标系
标识符 id: root 文件内唯一，小写开头
属性 width: 120 键值声明，非赋值
多属性同行 width: 120; height: 240 分号分隔
单行注释 // 说明 与 C++ 相同
多行注释 /* 说明 */ 与 C++ 相同
字符串 "text" 或 'text' 单双引号都能用
字符串翻译 qsTr("text") 可被 lupdate 抽取

分组属性两种写法 #

一组属性属于同一大类时，用点号层层展开，或者用大括号块打包：

qml
Text {
    font.family: "Ubuntu"
    font.pixelSize: 24
    font.bold: true
}

等价于：

qml
Text {
    font { family: "Ubuntu"; pixelSize: 24; bold: true }
}

块写法少打几个字，但里面的属性一多就难读。代码风格上，两个以上属性用点号写，超过四个再考虑块。

附加属性 #

有一类属性不属于元素自己，而是由外部类型挂到它身上，写法是 类型名.属性名：

qml
Text {
    id: otherLabel
    KeyNavigation.tab: input2
    Keys.onSpacePressed: console.log("space")
}

KeyNavigation、Keys、Layout 都是附加类型的常见出处。这类属性有一个共同点：被挂载的元素必须拿到焦点，处理器才会触发。

五、属性与绑定 #

属性是 QML 的骨架，绑定是 QML 的灵魂。这章把两者拆开讲。

属性的真面目 #

QML 里的属性不是字典里的键值对，它是对象上的一个真实成员：有类型、有初值、有变更信号、能被绑定。你写 width: 120，引擎给这个对象装上一个叫 width 的 int 属性，同时在内部登记「这个值从字面量 120 来」。

类型决定了能放什么。给 width 赋字符串，引擎不干，运行时直接报类型错误。

绑定：写关系，不写值 #

qml
Rectangle {
    width: 200
    height: 2 * width
}

height: 2 * width 不是「此刻把 400 算出来存进去」。它是「height 永远等于 width 的两倍」。你把 width 改成 300，height 自动变 600，不用写一行代码去同步。

绑定能挂多个依赖：

qml
Rectangle {
    id: root
    width: 400; height: 300

    Rectangle {
        id: panel
        width: parent.width / 2
        height: parent.height - 40
        color: "steelblue"
        Text { anchors.centerIn: parent; text: panel.width + " x " + panel.height }
    }
}

width: parent.width / 2，父级一改宽，子级跟着改；height: parent.height - 40 同理。这就是声明式界面的自适应：你只描述约束，重算的事归引擎。

再看一个反例，方便体会区别。C++ 里做同样的事，得在 resizeEvent 里重算每个子控件的几何；控件嵌套几层，这段代码就有几层，还得防着漏改。

绑定与赋值：一字之差，天壤之别 #

写法 名字 语义 后续变化
text: "count " + n 绑定（:） 强约束，生命周期内始终成立 n 变，text 自动重算
text = "count " + n 赋值（=） 一次性操作，算完就落地 原来的绑定被永久销毁

= 是绑定杀手。只要对被绑定的属性执行一次 JS 赋值，那条绑定关系就没了，之后依赖项再怎么变，这个属性也不动。

qml
Text {
    id: label
    x: 24; y: 24
    property int spacePresses: 0
    text: "Space pressed: " + spacePresses + " times"
    focus: true

    Keys.onSpacePressed: {
        increment()          // 走函数，spacePresses 变，text 自动跟着变
    }

    Keys.onEscapePressed: {
        label.text = ''      // 破坏性赋值，text 的绑定到此为止
    }

    function increment() {
        spacePresses = spacePresses + 1
    }
}

按空格，计数加一，文本跟着刷新。按下 Esc，文本清空，看着像清屏——代价是 text 的绑定被销毁了。再按空格，spacePresses 照样加，屏幕上的文本却一直是空的。

这不是 bug，是语义。真要清空又想保留绑定，用 Qt.binding() 把表达式重新挂回去：

qml
Keys.onEscapePressed: {
    label.text = Qt.binding(function() {
        return "Space pressed: " + spacePresses + " times"
    })
}

记住一条足够用：给属性用 :，给变量用 =。分不清时会出「界面不刷新」的怪病，八成就是这里错了。

自定义属性 #

元素自带的属性不够用，自己加。语法是 property <类型> <名字>: <初值>：

qml
Rectangle {
    property int times: 24
    property string userName: "guest"
    property color accent: "#33B5E5"
    property bool busy: false
    property real progress: 0.0
}

自定义属性可以被绑定、被外部读写、被内部子元素引用，用起来和内置属性没有区别。给组件写配置项，靠的就是这个。

属性别名 #

alias 把一个内部子元素的属性直接映射到根元素上，相当于开一扇窗：

qml
Rectangle {
    id: root
    property alias text: label.text
    property alias anotherTimes: label.times

    Text {
        id: label
        property int times: 0
        text: "Start"
    }
}

外部拿到这个组件时，只能看见根元素上声明的属性。label 是内部 id，外面引用不到。想让外部改内部文本，就得用 alias 把 label.text 导出成根上的 text。

这条规则在组件开发里是硬约束：不导出的属性，就是私有属性。外部只能访问组件根节点暴露的属性，内部子节点的属性必须通过 alias 映射出去。

alias 只能指向已存在的 id 属性，不能指向表达式，也不能自带初值。

属性变更信号处理器 #

属性值一变，引擎自动发一个 on<属性名>Changed 信号，首字母大写：

qml
Rectangle {
    width: 100
    onWidthChanged: console.log("width changed to:", width)
}

这比手动 connect 省事：不用找信号名，不用管连接对象。调试绑定关系时，往几个关键属性上各挂一个 console.log，能看清谁在什么时候被重算。

静态的东西别写成绑定。width: 120 就是字面量，别写成 width: 60 * 2；几千个绑定全在动，属性求值会成为热点。

六、元素树与父子关系 #

一棵视觉树 #

QML 文件写出来是一棵树。根元素是树干，大括号里嵌套的都是孩子，孩子的孩子继续往下长。

qml
Item {
    id: root
    width: 400; height: 300

    Rectangle {
        id: card
        width: 200; height: 120
        Text { id: title; text: "标题" }
    }
}

root 是 card 的父元素，card 是 title 的父元素。这层父子关系不只影响谁被谁包含，还决定坐标、裁剪、Z 序、可见性、销毁时机。

坐标永远相对父级 #

子元素的 x、y 是相对父元素左上角算的，不是相对屏幕，也不是相对窗口。父元素挪了，整棵子树跟着挪，子元素的 x 不用改。

qml
Image {
    id: rocket
    x: (parent.width - width) / 2
    y: 40
}

parent.width / 2 在父级变宽时自动重算，是动态居中；写成 x: 150 就是钉死的静态位置。三种引用别混：

写法 指向 适用场合
parent.width 直接父元素的宽度 需要跟随父级伸缩
root.width 根元素（靠 id 引用） 需要跟整窗宽度对齐
width 元素自己 表达式里引用自身

parent 是内建引用，不用声明；root 是起出来的 id，必须先在根元素上写 id: root。

Z 序：后写的盖先写的 #

同一层级里，QML 中后面声明的元素默认拥有更高的 Z 值，画在更上面。这条规则不用配置，按书写顺序自动成立。

想改叠放层次，显式设 z：

qml
Rectangle { z: 2; color: "red" }

Z 序和事件接收是绑在一起的。两个 MouseArea 区域重叠时，上层那个先吃点击事件，吃了就不再往下传。界面上「按钮点了没反应」，先查是不是被上面一层透明的 MouseArea 挡住了。

旋转与缩放不动几何 #

视觉元素都能平移、旋转、缩放。平移改 x、y；旋转改 rotation，单位是度，取值 0 到 360；缩放改 scale，小于 1 缩小，大于 1 放大：

qml
Item {
    ClickableImage { id: rocket1; x: 20; y: 100; source: "assets/rocket.png"
                     onClicked: x += 5 }
    ClickableImage { id: rocket2; x: 140; y: 100; source: "assets/rocket.png"
                     smooth: true; onClicked: rotation += 5 }
    ClickableImage { id: rocket3; x: 240; y: 100; source: "assets/rocket.png"
                     smooth: true; onClicked: { rotation += 5; scale -= 0.05 } }
}

smooth: true 开启纹理过滤，旋转或缩放时不开会有明显锯齿，开了多占一点渲染开销。静态不动的图没必要开。

关键在于：rotation 和 scale 只改最终画面的渲染外观，不改变元素的 x、y、width、height。一个 scale: 2 的元素，逻辑尺寸还是原来那个，锚点、布局、命中检测都按原尺寸算。想在缩放后重新布局，得自己去算，别指望引擎帮你改 width。

焦点也是父子关系 #

QML 里同一时刻只有一个元素持有键盘焦点。focus: true 声明候选，谁真正拿到要看层级。

把 TextInput 加个背景框封装成可复用组件，是这里的经典陷阱：

qml
// 错误示范：根元素用 Rectangle
Rectangle {
    width: 96; height: input.height + 8
    color: "lightsteelblue"; border.color: "gray"
    property alias text: input.text
    TextInput { id: input; anchors.fill: parent; anchors.margins: 4; focus: true }
}

用了两个实例再按 Tab 切换，焦点会卡住，进不去内部的 TextInput。原因很简单：外部给的焦点落在根元素 Rectangle 上，Rectangle 不是焦点范围，不会把焦点往下传。

把根元素换成 FocusScope 就好了：

qml
// 正确示范：根元素用 FocusScope
FocusScope {
    width: 96; height: input.height + 8
    property alias text: input.text
    Rectangle { anchors.fill: parent; color: "lightsteelblue"; border.color: "gray" }
    TextInput { id: input; anchors.fill: parent; anchors.margins: 4; focus: true }
}

FocusScope 的语义是：当它自己获得焦点时，把焦点下发给内部 focus: true 的那个子节点。做自定义输入组件，根元素一律用 FocusScope。

父子的生命周期 #

父元素销毁，子树跟着销毁。这是 QML 内存管理的底线：不用手动 delete 子元素，父元素一走，孩子全部回收。

反过来要注意：动态创建的对象如果不挂到某个父元素下，就得自己管它的生命周期，否则会漏。

七、C++ 与 QML 的两种连接方式 #

连接有两个方向，别混：

  • C++ 加载 QML：程序入口在 C++，main() 里把界面拉起来。
  • QML 使用 C++：界面里要数据、要算法，把 C++ 对象或类型交给 QML。

两个方向同时用，就是标准混编结构。

方向一：C++ 加载 QML #

三种写法，选哪种看场景。

写法 A：QQmlApplicationEngine。 工程模板默认就是它，根元素可以是 Window：

cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    QQmlApplicationEngine engine;
    engine.load(QUrl(QStringLiteral("qrc:///main.qml")));
    return app.exec();
}

写法 B：QQuickView。 自带窗口容器，代码更短，适合小窗体或嵌入式界面：

cpp
#include <QGuiApplication>
#include <QQuickView>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    QQuickView view;
    view.setSource(QUrl(QStringLiteral("qrc:/qml/HelloWorld.qml")));
    view.show();
    return app.exec();
}

QQuickView 继承自 QWindow，本身就是窗口，所以根元素必须是 Item 一类的可视元素，不能是 Window。拿 Window 当根元素喂给它，加载会失败。

写法 C：QQmlComponent 手工实例化。 适合需要动态加载、按需创建多个界面的场合：

cpp
#include <QGuiApplication>
#include <QQmlEngine>
#include <QQmlComponent>
#include <QQuickWindow>
#include <QDebug>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);

    QQmlEngine engine;                                   // 1. 初始化引擎
    QQmlComponent component(&engine,                     // 2. 装载组件
        QUrl(QStringLiteral("qrc:/qml/HelloWorld.qml")));

    if (!component.isReady()) {                          // 3. 判断是否失败
        qWarning() << "QML Component load error:" << component.errorString();
        return -1;
    }

    QObject *obj = component.create();                   // 4. 实例化并显示
    QQuickWindow *window = qobject_cast<QQuickWindow*>(obj);
    if (window) window->show();

    return app.exec();
}

三种写法摆一起对比：

写法 头文件 根元素要求 代码量 适用场景
QQmlApplicationEngine QQmlApplicationEngine 可以是 Window 最少 标准应用入口，首选
QQuickView QQuickView 必须是 Item 少 小窗体、嵌入到别的窗口里
QQmlComponent QQmlEngine + QQmlComponent 自己 qobject_cast 多 动态加载、延迟创建、多界面切换

三者的共同点：都要把 QML 文件放进资源包（qrc:/），加载失败都要看 errorString() 或 rootObjects()。

方向二：把 C++ 交给 QML #

两种手段，用途不同。

手段一：setContextProperty 注入对象。 把现成的 C++ 对象塞进 QML 上下文，QML 里直接按名字用：

cpp
// 1. 初始化数据库连接并配置模型
QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE");
db.setDatabaseName("cities.db");
if (!db.open()) qFatal("Unable to open database");

QSqlTableModel *cityModel = new QSqlTableModel(this);
cityModel->setTable("city");
cityModel->select();

// 2. 把 C++ 数据模型暴露给 QML 上下文
QQmlApplicationEngine engine;
engine.rootContext()->setContextProperty("cityModel", cityModel);
engine.load(QUrl(QStringLiteral("qrc:///main.qml")));

QML 侧当原生对象用：

qml
ListView {
    width: 240; height: 300
    model: cityModel
    delegate: Text { text: model.city }   // model.city 对应表的 city 列
}

model.city 里的 city 就是数据库表的列名，QSqlTableModel 的列角色自动映射成 QML 里的属性名。

setContextProperty 简单直接，代价是 QML 侧看不出类型，IDE 没有补全，写错名字只有运行时才知道。工程一大，这种隐式依赖很难查。

手段二：qmlRegisterType 注册类型。 把 C++ 类注册成 QML 类型，QML 里像内置元素一样声明：

cpp
#include <QQmlApplicationEngine>
#include <qqml.h>

class City : public QObject
{
    Q_OBJECT
    Q_PROPERTY(QString name READ name WRITE setName NOTIFY nameChanged)
public:
    explicit City(QObject *parent = nullptr) : QObject(parent) {}
    QString name() const { return m_name; }
    void setName(const QString &n) { m_name = n; emit nameChanged(); }
signals:
    void nameChanged();
private:
    QString m_name;
};

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);

    qmlRegisterType<City>("City", 1, 0, "City");   // 注册为 City 1.0 的 City 类型

    QQmlApplicationEngine engine;
    engine.load(QUrl(QStringLiteral("qrc:///main.qml")));
    return app.exec();
}

QML 侧先导入模块，再声明对象：

qml
import QtQuick 2.0
import City 1.0

City {
    name: "Beijing"
    onNameChanged: console.log("name is now", name)
}

注册类型的做法对 QML 友好：有类型信息、能补全、能写绑定。要对外暴露复杂数据结构，优先选这条路。

两种手段的边界：

对比项 setContextProperty qmlRegisterType
接收方 一个现成对象 一个可实例化的类型
QML 侧写法 model: cityModel City { name: "..." }
类型信息 无，运行时才校验 有，能补全
多实例 不行，全局唯一 可以，要几个建几个
适用场景 单例服务、数据模型、全局配置 可复用控件、数据结构

QML 调 C++ 的前提 #

不管走哪条路，QML 能碰到的东西都受元对象系统约束：

  • 属性要 Q_PROPERTY 声明，带 NOTIFY 才能被绑定跟踪
  • 方法要 Q_INVOKABLE，或者声明成槽
  • 信号直接写在 signals: 段里，QML 侧按 on<信号名> 接

少了 Q_OBJECT 宏，上面这些全部失效。编译能过，运行时 QML 侧找不到属性——这个坑踩一次就记住了。

八、QML 的类型系统 #

QML 的类型分两类：值类型和对象类型。值类型像是内置的标量，对象类型是可以声明的元素。

值类型与 C++ 的对应 #

写自定义属性、写 C++ 接口，两边的类型要对得上：

QML 类型 含义 C++ 对应
int 整数 int
real 浮点数 double / qreal
bool 布尔 bool
string 字符串 QString
url 资源路径或网址 QUrl
color 颜色 QColor
date 日期时间 QDateTime
list<Type> 列表 QList<T> / QQmlListProperty
var 任意类型 QVariant
alias 属性别名 无对应，纯 QML 概念

var 是个万能口袋，什么都能装，代价是丢了类型检查。数据来源不确定时用它挡一下，确定下来就该换成具体类型。

url 用得比想象中多。Image.source、Loader.source、setSource() 全收 url，写相对路径 "assets/rocket.png" 时，引擎按 QML 文件所在位置解析，不是按工作目录。

对象类型：一切都从 Item 长出来 #

视觉元素的根是 Item。它自己不画任何东西，完全透明，但定义了所有可视元素共有的能力：几何（x、y、width、height）、层级（z）、可见性（visible、opacity）、焦点（focus）、状态与变换（rotation、scale）。

Item 在界面里的角色，相当于 HTML 里的 div：不画东西，只当容器，负责分组和定位。需要一块空白区域承载子元素，就用它。

往下分叉出来的几个，是最常打交道的：

元素 职责 关键属性
Item 纯容器，无绘制 x、y、width、height、z
Rectangle 填充矩形 color、border、radius、gradient
Text 只读文本 text、font、color、elide、wrapMode
Image 图片渲染 source、fillMode、clip
MouseArea 非视觉交互区 anchors.fill、onClicked

Rectangle 支持纯色、边框、圆角，也支持渐变：

qml
Rectangle {
    width: 200; height: 100
    color: "lightsteelblue"
    border.color: "slategrey"; border.width: 2
    radius: 8

    gradient: Gradient {
        GradientStop { position: 0.0; color: "lightsteelblue" }
        GradientStop { position: 1.0; color: "slategrey" }
    }
}

color 和 gradient 一起写时，gradient 优先。

MouseArea 是少数非视觉元素之一：它不画东西，只在自己覆盖的矩形范围内捕获鼠标事件。anchors.fill: parent 让它盖满父元素，这是给任意元素加点击能力的标准手法。

一个文件就是一个类型 #

QML 的可复用性靠文件名实现。把一整套元素写进以大写字母开头的独立 .qml 文件，这个文件名立刻成为一个新类型，同目录下别的 QML 文件可以直接声明它。

Button.qml 里的 Rectangle 根元素，被外部当 Button 用。这套机制省掉了注册、头文件、编译，代价是文件名必须大写开头——小写开头会被当成 id 而不是类型。

九、信号与槽在 QML 里怎么写 #

QML 里的信号槽比 C++ 轻。不用 connect，写个处理器就行。

接现成的信号 #

元素发出信号，你写一个 on<信号名> 处理器，信号名首字母大写：

qml
Rectangle {
    id: button
    width: 100; height: 50
    color: "blue"
    MouseArea { anchors.fill: parent; onClicked: console.log("Button clicked!") }
}

MouseArea 有 clicked 信号，所以处理器叫 onClicked。信号带参数时，参数在处理器里直接可用，不用声明。

声明自己的信号 #

qml
// Button.qml
Rectangle {
    id: root
    property alias text: label.text
    signal clicked

    width: 116; height: 26
    color: "lightsteelblue"
    border.color: "slategrey"

    Text { id: label; anchors.centerIn: parent; text: "Start" }

    MouseArea {
        anchors.fill: parent
        onClicked: root.clicked()   // 发射根级信号
    }
}

signal clicked 一行就声明完。内部 MouseArea 收到点击后转发 root.clicked()，外部就能接 onClicked：

qml
Item {
    Button {
        id: startButton
        x: 10; y: 10
        text: "Click Me"
        onClicked: statusText.text = "Button clicked!"
    }

    Text { id: statusText; x: 10; y: 50; text: "waiting..." }
}

注意 text: "Click Me" 能生效，靠的是前面那条 property alias text: label.text。信号和别名是自定义组件的两条基本 API：一条给外部发通知，一条给外部改外观。

带参数的信号 #

qml
Rectangle {
    signal moved(int dx, int dy)
}

// 外部
onMoved: console.log("moved", dx, dy)

参数名写在信号声明里，处理器里直接用。

键盘事件：Keys 附加属性 #

拿到焦点的元素加 Keys.on<键名>Pressed，就能接物理按键：

qml
Item {
    width: 400; height: 200
    focus: true

    Rectangle { id: square; x: 8; y: 8; width: 40; height: 40; color: "green" }

    Keys.onLeftPressed: square.x -= 8
    Keys.onRightPressed: square.x += 8
    Keys.onUpPressed: square.y -= 8
    Keys.onDownPressed: square.y += 8

    Keys.onPressed: {
        switch (event.key) {
        case Qt.Key_Plus:  square.scale += 0.2; break;
        case Qt.Key_Minus: square.scale -= 0.2; break;
        }
    }
}

方向键用专用处理器，其余按键走统一的 Keys.onPressed，从 event.key 里取枚举值。focus: true 不能少，没有焦点就收不到按键。

接 C++ 的信号 #

C++ 类里声明了信号，注册或注入到 QML 之后，QML 侧的接法和原生元素一样：

qml
City {
    onNameChanged: console.log("name is now", name)
}

信号名首字母大写接到 on 后面。这一条能让 C++ 的数据变化直接驱动界面，是混编里最常用的一根线。

十、JavaScript 在 QML 里的角色 #

QML 内嵌了 JavaScript 引擎，这不是附加功能，是语言设计的一部分。属性表达式、事件处理器、函数体，三处都能写 JS。

三种落点 #

属性表达式里写算术和逻辑：

qml
Rectangle {
    width: parent.width / 2
    height: width * 0.6
    color: width > 200 ? "steelblue" : "lightgray"
}

事件处理器里写多行脚本：

qml
MouseArea {
    onClicked: statusText.text = "clicked at " + mouse.x + ", " + mouse.y
}

声明函数：

qml
Text {
    property int spacePresses: 0
    text: "Space pressed: " + spacePresses + " times"

    function increment() {
        spacePresses = spacePresses + 1
    }
}

函数可以定义在元素内部，用名字直接调用。作用域链是元素自己、父元素、根元素、全局。

Qt 自带的全局对象 #

Qt 这个全局对象挂了一批工具函数，写界面时随手能用：

qml
Text { text: Qt.md5("hello, world") }
Rectangle { color: Qt.rgba(0, 0, 255, 0.4) }
MouseArea { onClicked: Qt.quit() }

Qt.md5() 算散列，Qt.rgba() 拼半透明颜色，Qt.quit() 退出应用。Qt.application 还能拿到版本号、参数列表这些全局信息。

边界在哪 #

JS 在 QML 里是胶水，不是主力。这几条线别越：

  • 别在大循环里跑重计算。属性求值和循环都在主线程，卡住就是界面卡住。
  • 别拿 JS 写业务算法。同一段逻辑放 C++ 里快一个量级，还能编译期检查。
  • 别用 JS 做字符串拼接生成界面。QML 是声明式的，动态结构用 Loader、Repeater。
  • JS 里改属性用 = 会破坏绑定，这一条在第五章说过，是同一件事。

十一、常见编译错误 #

缺失 GLES2/gl2.h #

在 Visual Studio 里编译 Qt5 的 QML 工程，撞上这个的概率很高：

text
fatal error C1083: 无法打开包括文件: "GLES2/gl2.h": No such file or directory

原因是 Qt5 默认用 ANGLE 做 Direct3D 到 OpenGL ES 2.0 的转换层，而工程没把 ANGLE 的头文件目录加进包含路径。

修法四步：

  1. Visual Studio 里右键项目，选「属性」。
  2. 展开「配置属性」→「C/C++」→「常规」。
  3. 找到「附加包含目录」(Additional Include Directories)，在尾部追加 ANGLE 头文件目录 $(QTDIR)\include\QtANGLE。
  4. 确定，重新编译。

顺带提一句，改完记得看「配置」下拉框是 Debug 还是 Release，只改一个配置，另一个照样报错。

其他高频错误 #

现象 原因 处理
Unknown module(s) in QT: quick .pro 没链接模块 QT += qml quick
GLES2/gl2.h 找不到 缺 ANGLE 包含路径 附加包含目录加 $(QTDIR)\include\QtANGLE
Window is not a type 没导入 QtQuick.Window import QtQuick.Window 2.1
Cannot assign to non-existent property 属性名拼错或类型不符 核对属性名与值类型
qrc:/main.qml: No such file 文件没进 qml.qrc 把新增 .qml 加进资源文件
窗口不出现，程序不崩 engine.load() 失败 打印 rootObjects() 判断是否为空
QML debugging is enabled... Debug 模式开了调试端口 切 Release 或注销 .pro 里的调试选项
界面元素不显示 width/height 为 0，或没设 visible 检查尺寸与可见性
属性改了界面不动 绑定被 = 破坏 改用 : 或 Qt.binding()

Window is not a type 和 Cannot assign to non-existent property 这两条，九成是 import 少了或者手滑打错，先看这两处。

十二、易错点速查 #

把本篇反复提到的坑收成一张表，写代码时对着看。

易错点 表现 正确做法
把 QML 当 Qt Quick 不知道报错该查语言还是查框架 QML 是语言，Qt Quick 是框架与控件集
命令式思维写界面 用定时器和重算去同步尺寸 用绑定描述关系，width: parent.width / 2
= 破坏绑定 改过一次之后界面再不更新 属性用 :，变量用 =，必要时 Qt.binding()
一个文件多个根元素 加载即报语法错误 外层包一层 Item
根元素没起 id: root 子元素引用父级时写法混乱 最外层统一 id: root
组件内部属性外部读不到 外部访问提示不存在 用 property alias 导出
Rectangle 当输入组件根 Tab 键切不进内部 TextInput 根元素换 FocusScope
以为 scale 会改宽度 缩放后布局错位 rotation/scale 只改渲染，width 不变
旋转后边缘锯齿 图形边缘毛糙 smooth: true
透明 MouseArea 挡住点击 下层按钮点了没反应 检查 Z 序，必要时去掉遮挡层
新增 .qml 没进 qrc 开发机正常，换机白屏 加进 qml.qrc 后重新构建
项目路径含中文或空格 各种找不到文件的怪错 换纯英文无空格路径
C++ 类漏了 Q_OBJECT QML 侧属性全找不到 补宏，重新 qmake
用 QQuickView 载 Window 根 加载失败 换 QQmlApplicationEngine，或把根元素改成 Item

这些点单独看都是小知识，凑在一起就是「为什么我的界面不刷新」「为什么换台机器就白屏」这两类老问题。回头查表，比翻文档快。
