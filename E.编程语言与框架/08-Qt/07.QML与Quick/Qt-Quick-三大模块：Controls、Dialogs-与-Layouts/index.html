本篇讲模块层面：QtQuick.Controls、QtQuick.Dialogs、QtQuick.Layouts 三个可选模块各自提供什么、怎么 import、版本怎么对、样式怎么换、彼此怎么配合。 本篇不讲单个控件的属性细节，也不讲 Row/Column/Grid 的手把手写法。 跨篇：布局元素的具体用法看《布局》那篇；ColorDialog、FileDialog 的逐个演示看《对话框》那篇；Item/Window 这些地基看《QML 与 Qt Quick 入门》。

一、Qt Quick 的模块化设计 #

Qt Quick 不是一个巨型模块。它是一套「核心 + 一堆可选模块」的结构。QtQuick 本身只提供最基础的视觉元素：Item、Rectangle、Text、Image、MouseArea、TextInput、ListView、Animation。够你画东西，够你动起来，但里面一个控件都没有。

控件、对话框、布局系统全在别的模块里。不 import，就用不了。

模块 提供的东西 默认是否可用 典型用途
QtQuick Item / Rectangle / Text / Image / ListView / Animation 是，核心模块 搭画面骨架
QtQuick.Window Window / Screen 否 独立窗口、屏幕信息
QtQuick.Controls Button / ApplicationWindow / StackView / Menu 否 现成控件
QtQuick.Controls.Material Material 样式附加属性 否 换风格
QtQuick.Templates Controls 2 的抽象基类 否 自定义控件继承
QtQuick.Dialogs ColorDialog / FileDialog 否 系统对话框
QtQuick.Layouts RowLayout / ColumnLayout / GridLayout / Layout 否 会分配尺寸的布局

三个模块里 Controls、Dialogs、Layouts 都在 Qt5.1 一起登场（需要 Qt Quick 2.1），都是额外的东西。Controls 到 Qt5.7 被重写成第二版，于是又多出 QtQuick.Templates，这条线后面单开一章。

缺模块的报错 #

没 import 就写控件，引擎在加载阶段直接失败：

text
qrc:/main.qml:3 module "QtQuick.Controls" is not installed

版本号写高了是同一类错误，但信息更具体，第二行会把你手上的 Qt 支持到哪个版本摊开（available versions: 2.0 2.1 ... 2.12）。看到它别去改代码里别的部分，先看 Qt 版本。

项目文件里挂依赖 #

Qt5 里这三个模块在源码树里都挂在 qtquickcontrols 仓库下，qmake 一行够（Controls 1 的老工程把 2 去掉）：

QT += quick quickcontrols2

Qt6 的 CMake 工程按模块拆开：

cmake
find_package(Qt6 REQUIRED COMPONENTS Quick QuickControls2 QuickDialogs2)
target_link_libraries(app PRIVATE
    Qt6::Quick
    Qt6::QuickControls2
    Qt6::QuickDialogs2
)

QtQuick.Layouts 在 Qt6 跟着 Qt6::Quick 走，不用单独找；Qt5 里它随 quickcontrols 一起部署。部署阶段用 windeployqt，它会把 qml/ 下的模块拷走，手工打包最容易漏 qml/QtQuick/Controls.2 和 qml/QtQuick/Layouts 两个目录，漏了就是上面那句 is not installed。

二、import 与版本号 #

import 语句决定两件事：哪些类型可见，以及哪个版本的 API 可见。

qml
import QtQuick 2.15
import QtQuick.Window 2.15
import QtQuick.Controls 2.15
import QtQuick.Layouts 1.15
import QtQuick.Dialogs 1.3

版本号不是统一的。QtQuick 和 QtQuick.Controls 用 2.x，QtQuick.Layouts 一直是 1.x，QtQuick.Dialogs 也是 1.x。三套数字各走各的，抄别人代码时最容易在这里翻车。

五种写法 #

写法 作用 例子
模块 + 版本 最常用的形式 import QtQuick.Controls 2.15
模块 + 别名 解决重名 import QtQuick.Controls 1.4 as Old
无版本号 Qt5.15 之后与 Qt6 可用 import QtQuick.Controls
相对目录 引入本地自写组件 import "components"
JS 文件 引入函数库 import "utils.js" as Utils

别名这招在迁移期救命。Controls 1 和 Controls 2 的 Button 名字撞了，靠 as 分开：

qml
import QtQuick.Controls 1.4 as C1
import QtQuick.Controls 2.15

C1.Button { text: "老按钮" }
Button { text: "新按钮" }

Qt 5.15 和 Qt6 允许省掉版本号，import QtQuick 这样写拿到的是当前 Qt 能提供的最高版本。写库、写跨版本组件时用这种，省得处处对版本；老工程想钉死行为就别省。

版本号到底管什么 #

版本号是 API 的可见性闸门，不是装饰。写 2.5 就只看到 2.5 为止的 API，新属性会报 Cannot assign to non-existent property；写 2.15 而 Qt 只到 2.12，就是前面那种 version 2.15 is not installed。

Qt 版本 QtQuick QtQuick.Controls QtQuick.Layouts QtQuick.Dialogs
5.9 2.9 2.2 / 1.4 1.3 1.1
5.12 2.12 2.12 / 1.5 1.12 1.2
5.15 2.15 2.15 / 1.5 1.15 1.3
6.2 6.2 6.2 6.2 6.2
6.5 6.5 6.5 6.5 6.5

Qt6 起三套版本号终于对齐到 Qt 版本本身，从 5.15 迁到 6.x 时 import QtQuick.Layouts 1.15 这类写法要跟着改。

样式模块也是 import 进来的。Controls 2 的样式不是属性，是单独的子模块：

qml
import QtQuick.Controls 2.15
import QtQuick.Controls.Material 2.15
import QtQuick.Controls.Universal 2.15

不 import 样式模块，Material.accent 这种附加属性根本不存在，编译期就错。

三、QtQuick.Controls：控件库 #

这个模块的定位一句话：给 Qt Quick 补上一整套做完整界面的控件，让你不用从 Rectangle 和 MouseArea 开始拼按钮。官方说法是与 Qt Quick、Qt Quick Layouts 配合使用；实际也是这样，控件本身不负责排布，排布交给 Layouts 或者定位器。

import 写法：

qml
import QtQuick.Controls 1.0

这是最早的写法，对应 Controls 1。新代码写 2.x。类型按用途分四组，比按字母排好记。

应用程序窗口 #

类型 作用
ApplicationWindow 顶级应用程序窗口
MenuBar 水平菜单栏
StatusBar 状态栏，放状态信息
ToolBar 工具栏，放工具按钮及相关控件
Action 可绑定到项目的抽象用户界面操作

ApplicationWindow 是 Controls 提供的，不是 QtQuick.Window 的 Window。前者带 menuBar、toolBar、statusBar、header、footer 五个槽位，后者只是一块光板窗口。做桌面程序用前者。

导航和视图 #

类型 作用
ScrollView 给另一个项目提供滚动视图
SplitView 可拖动分割，切分项目之间的空间
StackView 基于堆栈的导航模型
TabView 多页堆叠，用户选一页
TableView 带滚动条、表头、造型的表格视图

StackView 是做页面流转的主力，push / pop / replace 三个方法覆盖九成场景。SplitView 用在左右分栏、可拖分隔条的场合。

控制器 #

这一组接收或提供用户输入，数量最多：

类型 作用
Button 带文本标签的按钮
CheckBox 带文本标签的复选框
ComboBox 下拉列表
GroupBox 带标题的框架
Label 文本标签
ProgressBar 进度指示器
RadioButton 带文本标签的单选按钮
Slider 水平或垂直滑块
SpinBox 自旋框
TextArea 多行可编辑文本
TextField 单行可编辑纯文本
ToolButton 工具按钮，多放在工具栏里
ExclusiveGroup 声明若干互斥控件

ExclusiveGroup 最容易被忽略。它不是可见控件，是给 RadioButton、Action、MenuItem 分组用的容器：

qml
ExclusiveGroup { id: alignGroup }

RadioButton { text: "左对齐"; exclusiveGroup: alignGroup; checked: true }
RadioButton { text: "右对齐"; exclusiveGroup: alignGroup }

不挂 ExclusiveGroup 时，同一父项下的 RadioButton 会自己互斥；一旦它们被拆到不同父项里，就必须靠这个组重新绑在一起。

菜单 #

类型 作用
Menu 菜单栏项、上下文菜单、弹出菜单
MenuSeparator 菜单内的分隔项
MenuItem 菜单或菜单栏里的一项

一个能跑的骨架 #

qml
import QtQuick 2.15
import QtQuick.Controls 2.15
import QtQuick.Layouts 1.15

ApplicationWindow {
    id: window
    width: 720
    height: 480
    visible: true
    title: "模块演示"

    menuBar: MenuBar {
        Menu {
            title: "文件"
            MenuItem { text: "打开"; onTriggered: stack.push("Page2.qml") }
            MenuSeparator { }
            MenuItem { text: "退出"; onTriggered: Qt.quit() }
        }
    }

    toolBar: ToolBar {
        RowLayout {
            anchors.fill: parent
            ToolButton {
                text: "后退"
                enabled: stack.depth > 1
                onClicked: stack.pop()
            }
            Item { Layout.fillWidth: true }
            Label { text: "就绪" }
        }
    }

    StackView {
        id: stack
        anchors.fill: parent
        initialItem: Page {
            ColumnLayout {
                anchors.fill: parent
                anchors.margins: 12
                Label { text: "第一页" }
                Button { text: "进入子页"; onClicked: stack.push("Page2.qml") }
                Item { Layout.fillHeight: true }
            }
        }
    }
}
  • 槽位属性直接吃控件，menuBar / toolBar 填进去就自动摆放，不用自己 anchors。
  • ToolBar 里的内容不会自己拉伸，得套一层 RowLayout 加 anchors.fill: parent，再用 Layout.fillWidth: true 的空 Item 做弹簧。
  • StackView 的 initialItem 直接给一个 Page 就够，push 传 URL（示例里是同目录的 Page2.qml）或 Component 都行；Page 自带 header / footer 槽位。

Action #

Action 把「一个操作」抽出来，让菜单项和工具栏按钮共用一个行为：

qml
Action {
    id: saveAction
    text: "保存"
    shortcut: StandardKey.Save
    onTriggered: console.log("save")
}

MenuItem { action: saveAction }
ToolButton { action: saveAction }

改一处 enabled、text、icon，两边同时变。菜单项和按钮各绑一遍 onClicked 是界面代码变烂的起点。

命名冲突 #

QtQuick 有 Text、TextInput、ListView，Controls 有 Label、TextField、TableView，名字不撞但语义容易混：显示文字用 Label（带主题色、支持换行），单行输入用 TextField、多行用 TextArea，原始 TextInput 只在要细控制时用；长列表的 ListView 来自 QtQuick，Controls 没重写它，TableView 才是 Controls 的。

混用的后果不是报错，是样式不一致：一半控件跟着主题走，一半是你手调的色值。

四、Controls 1 与 Controls 2 的分界 #

这是 Qt Quick 里最需要一次讲清的历史包袱。Controls 1 是 Qt5.1 的产物，Controls 2 是 Qt5.7 的产物。两者名字一样，实现完全不是一个东西。同一个工程里同时 import 两个模块是合法的，那才是灾难的开始。

维度 Controls 1（1.x） Controls 2（2.x）
引入版本 Qt 5.1 Qt 5.7
实现基础 自带一套完整的 QML 控件实现 建立在 QtQuick.Templates 之上
默认观感 与 QtWidgets 接近，桌面味重 扁平，触控友好
换样式 QtQuick.Controls.Styles 里逐个控件写 Style 整体换 style 子模块（Default / Material / Universal / Fusion / Imagine）
性能 控件层级深，绑定多 层级浅，Delegate 更省
Qt6 已移除 唯一选择
高 DPI / 移动端 处理差，不适配 支持良好，为触控设计

分界线差在哪 #

Controls 1 的思路是「我直接给你一个 Button 的完整实现」，你想改外观就 import QtQuick.Controls.Styles，交给它一个 ButtonStyle：

qml
import QtQuick.Controls 1.4
import QtQuick.Controls.Styles 1.4

Button {
    text: "老式按钮"
    style: ButtonStyle {
        background: Rectangle { color: control.pressed ? "#ccc" : "#eee"; radius: 3 }
        label: Text { text: control.text; anchors.centerIn: parent }
    }
}

Controls 2 反过来：「Button 只是控制逻辑的壳，长什么样由 background 和 contentItem 两个插槽决定」：

qml
import QtQuick.Controls 2.15

Button {
    text: "新式按钮"
    background: Rectangle { color: parent.pressed ? "#ccc" : "#eee"; radius: 3 }
    contentItem: Text {
        text: parent.text
        horizontalAlignment: Text.AlignHCenter
        verticalAlignment: Text.AlignVCenter
    }
}

同样是改外观，Controls 1 用一个 style 对象整体替换，Controls 2 用两个属性做局部替换。后者的写法能自然继承到 CheckBox、RadioButton、Switch 这些派生控件上，这是它结构上的优势。

覆盖面的此消彼长 #

两个版本的控件清单不是包含关系，互相都有对方没有的东西：

类型 Controls 1 Controls 2
ApplicationWindow / MenuBar / ToolBar 有 有（StatusBar 改用 footer 自己摆）
Button / CheckBox / RadioButton / Slider / SpinBox 有 有
ComboBox / GroupBox / ProgressBar / TextField 有 有
StackView 有 有
TableView 有 5.12 起才有
SplitView 有 5.13 起才有
TabView 有 换成 TabBar + TabButton + StackLayout 自己拼
Dialog / Popup / ToolTip 无 有
SwipeView / PageIndicator 无 有
Switch / RangeSlider / Dial 无 有
Action 有 5.10 起才有

这解释了迁移期最常见的两个抱怨：「新版本没有 TabView」和「新版本没有 SplitView」。前者不是缺失，是控件被拆成了可组合的零件；后者等到 5.13。

怎么选 #

新项目一律 Controls 2，import QtQuick.Controls 2.15。Controls 1 在 Qt6 里被整块删掉，今天写的 Controls 1 代码没有升级路径，只有重写路径；Controls 2 的样式体系可换、层级浅、支持高 DPI 和触控，也没有第二个选项。

老项目分两种情况：Controls 1 界面只有零星几处，按控件逐个换；界面庞大且深度依赖 QtQuick.Controls.Styles，先加别名共存（import QtQuick.Controls 1.4 as C1），按页面替换，别一次全动。不要做的是继续在 Controls 1 上新增功能，技术债不会自己变小。

五、控件样式与自定义 #

样式是 Controls 2 里最值得单独讲的部分，它不只是一套配色，而是一套可替换的机制。

五个内置样式 #

样式 import 观感
Default 不需要额外 import 中性、扁平，什么都像一点
Fusion QtQuick.Controls.Fusion 桌面感，接近 QtWidgets 的 Fusion
Imagine QtQuick.Controls.Imagine 图片资源驱动，换目录即换皮肤
Material QtQuick.Controls.Material Android Material Design
Universal QtQuick.Controls.Universal Windows 10 风格

Default、Material、Universal 从 5.7 起就有，Fusion、Imagine 是后续版本补进来的。

三种设定方式 #

配置文件方式，工程根目录放 qtquickcontrols2.conf：

text
[Controls]
Style=Material

[Material]
Theme=Dark
Accent=Teal
Primary=BlueGrey

这个文件要挂进 qrc，不然运行时找不到。环境变量方式适合调试，改一次不用重编译：

text
QT_QUICK_CONTROLS_STYLE=Material
QT_QUICK_CONTROLS_MATERIAL_THEME=Dark

C++ 里硬设要放在加载 QML 之前，加载之后再设无效，界面上不会有任何反应：

cpp
#include <QQuickStyle>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    QQuickStyle::setStyle("Material");
    // ...
}

附加属性微调 #

样式模块 import 之后，可以用附加属性改局部值：

qml
import QtQuick.Controls.Material 2.15

ApplicationWindow {
    Material.theme: Material.Dark
    Material.accent: Material.Teal

    Button {
        text: "确定"
        Material.elevation: 4
        Material.background: Material.Orange
        Material.foreground: "white"
    }
}

附加属性挂在 ApplicationWindow 上会往下继承，挂在单个 Button 上只管它自己。Material.elevation 只在 Material 样式下有含义，换成 Fusion 就静默失效，不报错。Universal 的写法一样：Universal.theme: Universal.Dark、Universal.accent: Universal.Crimson。

自己做一个控件 #

要复用一套外观，做法是继承 QtQuick.Templates 里的抽象类型，把 background 和 contentItem 填上：

qml
import QtQuick 2.15
import QtQuick.Templates 2.15 as T

T.Button {
    id: control
    implicitWidth: implicitBackgroundWidth + leftInset + rightInset
    implicitHeight: implicitBackgroundHeight + topInset + bottomInset
    padding: 6

    contentItem: Text {
        text: control.text
        font: control.font
        color: control.enabled ? "#222222" : "#999999"
        horizontalAlignment: Text.AlignHCenter
        verticalAlignment: Text.AlignVCenter
    }

    background: Rectangle {
        implicitWidth: 96
        implicitHeight: 32
        radius: 4
        color: control.down ? "#d0d0d0" : (control.hovered ? "#e8e8e8" : "#f2f2f2")
        border.color: "#c0c0c0"
    }
}

三个要点：继承 T.Button 而不是 Button，跳过样式层，避免默认外观和新外观叠在一起；implicitWidth 用父类的 implicitBackgroundWidth / implicitContentWidth 加内边距算，别写死数字，否则文字被截；交互状态用 control.down、control.hovered、control.enabled，不要自己监听 MouseArea，模板基类已经把事件处理完了。

做到这一步，控件就是主题无关的。换 Material 也好换 Fusion 也好，它保持自己的样子。要让它跟随主题，把颜色换成 control.palette.button、control.palette.text 这类调色板引用。

样式与 Palette #

palette 是跨样式的那层抽象，Default、Fusion 尊重调色板，Material、Universal 的样式属性优先。

qml
ApplicationWindow {
    palette.window: "#2b2b2b"
    palette.windowText: "#eeeeee"
    palette.text: "#eeeeee"
    palette.button: "#3c3c3c"
    palette.highlight: "#0d7377"
    palette.highlightedText: "#ffffff"
}

这组键跟 QtWidgets 的 QPalette 是同一个概念，从桌面端迁过来的人会熟。

六、QtQuick.Dialogs：对话框 #

这个模块只干一件事：提供创建和交互的系统对话框类型。import 写法最早的版本号是 1.0：

qml
import QtQuick.Dialogs 1.0

Qt5 后续停在 1.2、1.3，Qt6 换成 6.x。它跟 Controls 的 2.x 不共用一个号段，别以为写 2.x 才对。

类型 作用
ColorDialog 选择颜色的对话框
FileDialog 从本地文件系统选择文件的对话框
MessageDialog 提示、确认、警告对话框（1.3 起）

就这三个。Controls 里有二十多个控件，Dialogs 只有三个类型，因为对话框本身能力有限，复杂交互应该做成页面而不是对话框。

通用生命周期 #

三个类型共享同一套使用方式：

qml
FileDialog {
    id: fileDialog
    title: "选择文件"
    onAccepted: console.log("选了: " + fileDialog.fileUrl)
    onRejected: console.log("取消了")
}

Button {
    text: "打开文件"
    onClicked: fileDialog.open()
}

用 open() 显示、close() 关闭，也可以直接设 visible: true。用户点确定触发 accepted()，点取消或关窗触发 rejected()，两个信号的时机都在对话框关闭之后。

ColorDialog 关键属性 #

属性 作用
color 当前选中的颜色
showAlphaChannel 是否显示透明度通道
title 窗口标题
modality 模态级别 
qml
ColorDialog {
    id: colorDialog
    title: "选颜色"
    showAlphaChannel: true
    onAccepted: rect.color = colorDialog.color
}

FileDialog 关键属性 #

属性 作用
folder 当前所在文件夹，用 URL
nameFilters 过滤规则数组
selectExisting 只允许选已存在的文件
selectMultiple 允许多选
selectedFile 单选结果，URL
selectedFiles 多选结果，URL 数组
defaultSuffix 保存时自动补的后缀 
qml
FileDialog {
    id: openDialog
    title: "打开"
    folder: shortcuts.pictures
    nameFilters: [ "图片 (*.png *.jpg)", "所有文件 (*)" ]
    selectMultiple: true
    onAccepted: console.log(selectedFiles.length)
}

folder 和 selectedFile 都是 url，不是字符串路径。file:///C:/... 这种形态丢给 Image.source 能用，丢给 QFile 就得先 toLocalFile()，这个转换是最常见的错。nameFilters 的格式是 "描述 (*.ext)"，描述和括号之间有一个空格，写成 "图片(*.png)" 在某些平台过滤会失效。

七、原生对话框与 QML 对话框 #

同一个「打开文件」需求，Qt 里有四种做法，长相和行为都不一样。

做法 实现 外观 模块
FileDialog（Qt5） QML 绘制 跟系统不一样，Qt 自己一套 QtQuick.Dialogs 1.x
FileDialog（labs） 平台原生 API 系统原生 Qt.labs.platform
Dialog QML Popup 你自己画 QtQuick.Controls 2.x
FileDialog（Qt6） 平台原生 API 系统原生 QtQuick.Dialogs 6.x

Qt5 的困境 #

Qt5 里 QtQuick.Dialogs 的对话框是 QML 实现的，按钮和文件列表都由 Qt 自己画。好处是跨平台一致，坏处是 Windows 上用户看到的是一个不像资源管理器的文件框。想要原生外观，Qt5.6 之后换模块：

qml
import Qt.labs.platform 1.1

FileDialog {
    title: "打开"
    folder: StandardPaths.writableLocation(StandardPaths.DocumentsLocation)
    onAccepted: console.log(file)
}

Qt.labs.platform 里除了 FileDialog，还有 FolderDialog、ColorDialog、FontDialog、MessageDialog，以及 Menu、MenuBar、SystemTrayIcon。它一直挂着 labs 前缀，Qt5 没转正。属性名也不同：原生版用 file（单个 URL）和 currentFolder，QML 版用 selectedFile 和 folder，两套代码不能直接对拷。

Qt6 收敛了 #

Qt6 把 QtQuick.Dialogs 整个重写，全走平台原生：

qml
import QtQuick.Dialogs

FileDialog {
    title: "打开"
    currentFolder: StandardPaths.writableLocation(StandardPaths.PicturesLocation)
    nameFilters: [ "图片 (*.png *.jpg)" ]
    onAccepted: console.log(selectedFile)
}

属性名跟着 Qt.labs.platform 的路线走，folder 变成 currentFolder。Qt6 里 labs 版的对应类型基本被替代，新代码直接用 QtQuick.Dialogs。

Controls 的 Dialog 是另一回事 #

QtQuick.Controls 的 Dialog 不是系统对话框，它是 Popup，纯 QML 绘制，能塞任意内容：

qml
Dialog {
    id: confirmDialog
    title: "确认"
    modal: true
    anchors.centerIn: parent
    standardButtons: Dialog.Ok | Dialog.Cancel

    Label { text: "要删除这条记录吗？" }
    onAccepted: console.log("确定")
    onRejected: console.log("取消")
}

它跟系统对话框不是竞品。要在窗口里弹一个自己设计的确认框，用它；要选文件、选颜色、选字体，用 QtQuick.Dialogs。判断标准一句话：需要碰文件系统或系统级资源，用 QtQuick.Dialogs；只是问用户一句话，用 Controls 的 Dialog。

模态层级 #

值 效果
Qt.NonModal 不阻塞，能点后面的窗口
Qt.WindowModal 阻塞父窗口
Qt.ApplicationModal 阻塞整个应用

QtQuick.Dialogs 的类型用 modality 属性，Controls 的 Dialog 用 modal: true。写成 Dialog { modality: ... } 是无效属性，Controls 2 的 Dialog 没有这个属性。

八、QtQuick.Layouts：布局 #

这个模块的定位：一组在界面里放置项目的 QML 类型，而且它们会调整自己项目的大小。「会调整」是关键词，这就是布局和定位器的全部区别。

qml
import QtQuick.Layouts 1.0

版本号是 1.x，从 5.1 到 5.15 都停在 1.x，Qt6 才对齐到 6.x。这点跟 Controls 的 2.x 完全不同，抄代码时最容易出错。

类型 作用
Layout 附加属性集合，把项目推进 RowLayout / ColumnLayout / GridLayout
RowLayout 等同于 GridLayout，但只有一行
ColumnLayout 等同于 GridLayout，但只有一列
GridLayout 动态把项目放进网格

Layout 不是控件，不是容器，是一组附属在子项上的属性。写 Layout { } 是错的，正确写法是 Layout.fillWidth: true。GridLayout 的 columns 和 rows 二选一给值，决定先填行还是先填列。

Layout 附加属性全表 #

这些属性写在布局的子项上，不写在布局自己身上：

属性 作用
Layout.minimumWidth 子项允许的最小宽度
Layout.preferredWidth 子项想要的宽度
Layout.maximumWidth 子项允许的最大宽度
Layout.fillWidth 是否参与剩余宽度的分配
Layout.minimumHeight 最小高度
Layout.preferredHeight 想要的高度
Layout.maximumHeight 最大高度
Layout.fillHeight 是否参与剩余高度的分配
Layout.alignment 在自己那一格里怎么对齐
Layout.margins / Layout.leftMargin 等 外边距、单边外边距
Layout.row / Layout.column 显式指定格子位置
Layout.rowSpan / Layout.columnSpan 跨行、跨列

不写 fillWidth 时，子项按 preferredWidth 拿尺寸，剩下的空间留在布局里；写了 fillWidth: true 才去分摊。

一个三列布局 #

qml
import QtQuick 2.15
import QtQuick.Controls 2.15
import QtQuick.Layouts 1.15

ApplicationWindow {
    width: 600
    height: 400
    visible: true

    GridLayout {
        anchors.fill: parent
        anchors.margins: 12
        columns: 3
        columnSpacing: 8
        rowSpacing: 8

        Label { text: "用户名" }
        TextField {
            Layout.fillWidth: true
            Layout.columnSpan: 2
            placeholderText: "输入用户名"
        }

        Item { Layout.fillHeight: true }

        Button { text: "取消"; Layout.preferredWidth: 80 }
        Button { text: "登录"; Layout.preferredWidth: 80 }
    }
}

columns: 3 定死三列，子项按顺序填格子；Layout.columnSpan: 2 让输入框横跨两列；中间那个空的 Item { Layout.fillHeight: true } 是弹簧，把按钮顶到最下面；布局自己用 anchors.fill 贴满父项，它的子项只用 Layout.* 属性。

嵌套布局 #

布局是项目，布局可以嵌套布局，这是它比定位器更适合复杂界面的原因：

qml
ColumnLayout {
    anchors.fill: parent

    RowLayout {
        Layout.fillWidth: true
        Layout.preferredHeight: 40
        Label { text: "标题"; Layout.fillWidth: true }
        ToolButton { text: "×" }
    }

    RowLayout {
        Layout.fillWidth: true
        Layout.fillHeight: true
        ListView {
            Layout.fillWidth: true
            Layout.fillHeight: true
            model: 20
            delegate: ItemDelegate { text: "第 " + index + " 行" }
        }
        ColumnLayout {
            Layout.preferredWidth: 160
            Button { text: "新增"; Layout.fillWidth: true }
            Button { text: "删除"; Layout.fillWidth: true }
        }
    }
}

嵌套层上的 Layout.fillWidth 是给外层看的，内层子项的 Layout.fillWidth 是给这一层看的。同一个属性名，作用域由它所在的父项决定。

尺寸计算顺序 #

  1. 子项先报自己的 implicitWidth / implicitHeight。
  2. 布局用子项的 Layout.preferredWidth（没写就用 implicit）算出自己的 implicitWidth。
  3. 布局被外部给的 width 才是最终可用空间。
  4. 可用空间减去所有非填充项，剩下的分给 fillWidth: true 的项。
  5. 分配时受 minimumWidth、maximumWidth 夹逼，超出的部分留白，不会强行撑满。

所以「布局宽度设了但子项没铺满」不是 bug，是 maximumWidth 卡住了，或者压根没写 fillWidth。

九、Layouts 与定位器的分工 #

两者的名字像，行为不是一回事。

项目 定位器（Positioner） 布局（Layout）
类型 Row、Column、Grid、Flow RowLayout、ColumnLayout、GridLayout
所属模块 QtQuick，不用额外 import QtQuick.Layouts，必须 import
职责 只摆放，不管尺寸约束 摆放之外还分配尺寸
子项尺寸 不碰，子项自己多大就多大 按 preferred / fill / 边界改写子项尺寸
自身尺寸 取子项最大值，被动 由子项推导，也能被外部约束
子项改尺寸后 重新排位置 重新算空间分配
嵌套 可以，但尺寸失控 可以，尺寸逐层传
适合 固定尺寸的一排按钮、图标墙 会随窗口缩放的表单、分栏

一句话记：Row 只管把东西排成一排，RowLayout 会把这一排的空间分清楚。

混用的硬规则 #

布局的子项不要写 x、y、width、height、anchors：

text
QML Layout: Detected anchors on an item that is managed by a layout.
This is undefined behavior; use Layout.alignment instead.

这条警告的意思很直：这些属性归布局管，你再设一遍就是两套逻辑抢同一个值。后果不是崩，是尺寸跳动、拖窗口时错位、偶尔正常。要么全交给 Layout.*，要么这个子项干脆别放进布局。

要定位，用 Layout.alignment: Qt.AlignRight | Qt.AlignVCenter；要尺寸，用 Layout.preferredWidth；要外边距，用 Layout.margins。反过来，定位器的子项可以用 width、height，但别在会被重新排列的位置上加 anchors.fill，定位器不会给子项留空间，它只按 spacing 排。

怎么挑 #

会随窗口伸缩的界面，用布局；元素尺寸固定、只求排整齐，用定位器。整个界面多是布局打底，局部一小块用定位器。别为了「统一」把固定尺寸的图标行也塞进 RowLayout，多一层分配逻辑只会让尺寸算不明白。

十、三个模块怎么配合 #

一个真实的小窗体，三个模块全用上：Controls 出控件，Layouts 排布，Dialogs 选文件。

qml
import QtQuick 2.15
import QtQuick.Controls 2.15
import QtQuick.Layouts 1.15
import QtQuick.Dialogs 1.3

ApplicationWindow {
    id: window
    width: 640
    height: 420
    visible: true
    title: "文件查看器"

    FileDialog {
        id: fileDialog
        title: "选择文本文件"
        nameFilters: [ "文本 (*.txt)", "所有文件 (*)" ]
        onAccepted: pathLabel.text = selectedFile
    }

    ColumnLayout {
        anchors.fill: parent
        anchors.margins: 12
        spacing: 8

        RowLayout {
            Layout.fillWidth: true
            Label {
                id: pathLabel
                text: "未选择文件"
                elide: Text.ElideMiddle
                Layout.fillWidth: true
            }
            Button {
                text: "浏览"
                onClicked: fileDialog.open()
            }
        }

        ScrollView {
            Layout.fillWidth: true
            Layout.fillHeight: true
            TextArea {
                readOnly: true
                placeholderText: "文件内容"
            }
        }
    }
}

C++ 侧只要一个 QGuiApplication 加一个 QQmlApplicationEngine：

cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    QQmlApplicationEngine engine;
    engine.load(QUrl("qrc:/main.qml"));
    return app.exec();
}

几个配合点：

  • ApplicationWindow 必须用 QQmlApplicationEngine 加载。用 QQuickView 会报错，因为 QQuickView 的根项目必须是 Item，而 ApplicationWindow 是 Window。
  • FileDialog 挂在 ApplicationWindow 里当一个普通子项就行，它不是视觉元素，不占布局空间。
  • ScrollView 在 Layout 里要 fillWidth + fillHeight 都开，只开一个会出现滚动条和内容对不上。
  • 三个模块的 import 顺序自由，但同名类型按后 import 的优先，别名是唯一可控的做法。

十一、模块选择与版本兼容 #

按需求挑模块：

你要做的 用哪个 import
画矩形、文字、图片 QtQuick import QtQuick 2.15
按钮、输入框、菜单、页面栈 QtQuick.Controls import QtQuick.Controls 2.15
让界面随窗口伸缩 QtQuick.Layouts import QtQuick.Layouts 1.15
选文件、选颜色、选字体 QtQuick.Dialogs import QtQuick.Dialogs 1.3（Qt5）/ 6.x（Qt6）
换整套皮肤 样式子模块 import QtQuick.Controls.Material 2.15
做自己的控件 QtQuick.Templates import QtQuick.Templates 2.15 as T
多窗口、拿屏幕信息 QtQuick.Window import QtQuick.Window 2.15

Qt5 迁 Qt6 的清单，四条：

  • QtQuick.Controls 1.x 整块删除，1.x 界面必须重写成 2.x。
  • QtQuick.Dialogs 重写为原生实现，folder 改 currentFolder，Qt.labs.platform 的对应类型被替代。
  • QtQuick.Layouts 版本号从 1.x 变成 6.x，import QtQuick.Layouts 1.15 要跟着改。
  • 版本号全省掉最省心：import QtQuick.Layouts 在 5.15 和 Qt6 都能跑。

十二、易错点速查 #

这些坑按出现频率排，前四个几乎每个工程都会踩一次。

现象 原因 处理
module "QtQuick.Controls" is not installed 没 import，或部署漏了模块目录 加 import，检查 qml/QtQuick/Controls.2
version 2.15 is not installed Qt 版本低于写的 import 版本 降版本号，或看报错里的 available versions
Cannot assign to non-existent property import 版本低于用到的属性 提 import 版本
控件画出来了但没样式 样式模块没 import 加 import QtQuick.Controls.Material
QQuickStyle::setStyle 无反应 调用在加载 QML 之后 挪到 engine.load 之前
布局里子项位置乱跳 子项写了 anchors 或 width 删掉，改用 Layout.*
控件不随窗口放大 没写 Layout.fillWidth 子项和布局逐层开 fill
Dialog 的 modality 无效 那是 Dialogs 的属性 改用 modal: true
QQuickView 加载 ApplicationWindow 失败 根项目类型不匹配 换 QQmlApplicationEngine
Qt6 编译不过 Controls 1 代码 1.x 已删除 重写成 2.x

这些错误里有九成落在两个地方：版本号对不上，以及把布局当定位器用。把这两件事想清楚，剩下的多是查属性名。
