这篇讲什么：QML 的动画体系。属性动画、数值与颜色动画、状态的写法、状态之间的过渡、缓动曲线、动画分组与嵌套。核心结论先摆在这——QML 的动画是「改变属性值」的一种特殊方式，PropertyAnimation 干的事就是随时间把某个属性从 A 挪到 B。能被动画的只有属性，不是任意东西。

这篇不讲什么：布局（Row/Column/Grid/锚点）在同目录《布局》里；点击与悬停事件在《按钮与鼠标》；文字排版在《文本与标签》；工程结构与导入在《QML 与 Qt Quick 入门》；三大模块（QtQuick / QtQuick.Controls / QtQuick.Layouts）的边界在《三大模块》。C++ 侧怎么注册类型、怎么接 QAbstractAnimation，这篇不碰。

前置：会写 Item 的属性、会给 id、会接 onClicked。不熟就先回入门篇补一趟。

一、QML 的动画体系 #

动画的核心原理是值插值（Value Interpolation）。动画定义一条变化曲线，把某个属性值在指定时间内从起始值平滑推到目标值。中间那些帧不用我们算，插值器算。

这句话反过来读更有用：动画的输入是属性，输出是属性值。于是有三条硬限制：

  • 属性得先存在。没声明就先 property int foo: 0。
  • 属性得有类型。int、real、color、rotation（本质是 real）能插值；string 不能；var 里塞个对象更不能。
  • 属性得可写。被绑定表达式占着的属性（x: parent.width / 2）一旦被动画改，绑定就断了。这个坑第十章单独讲。

很多人第一次写 QML 动画会问「怎么让这个函数动起来」「怎么让这个信号动起来」。答案是不行。函数和信号不是属性，没有值可插。要动就只能落到属性上：改 x、改 opacity、改 scale、改 color。

一个全局时钟 #

Qt Quick 里所有动画由同一个全局计时器驱动。好处两条：不同动画之间能精确同步；渲染侧好安排帧，开销压得住。

所以「动画写多了就卡」这个说法不准。卡的原因往往不是动画数量，是每帧里干了重活——动画属性上挂了昂贵绑定，或者动画了一个会触发重新布局的属性。第十章细说。

体系分三层 #

层次 元素 回答的问题
值层 PropertyAnimation 及派生类 某个属性的值怎么变
配置层 State + PropertyChanges 某个状态下各属性应该是什么值
连接层 Transition 两个状态之间怎么切过去

值层是地基，配置层和连接层都围绕它搭。搞混三层，写出来的动画就会拧巴：把该写进状态里的值塞进动画，或者把本该交给过渡的地方堆一串 SequentialAnimation。

分清楚的标准一句话：改一个值，用属性动画；描述「界面处于什么形态」，用状态；描述「从形态 A 到 B」，用过渡。

一个界面同时有「折叠」「展开」「悬停」三种形态，就用状态；每种形态内部某个按钮要呼吸，就用属性动画；切形态时想有过程，就加过渡。三样东西各管一段，别互相顶班。

二、属性动画 PropertyAnimation #

PropertyAnimation 是通用基础动画。它不关心属性的语义，只关心「这个属性的值和目标值之间能不能插值」。所有具体动画元素都是它的特化。

六个关键属性 #

属性 作用
target 动画作用于哪个对象
property 属性名，字符串，单个
properties 属性名列表，字符串，逗号分隔，多个一起动
from / to 起点值与终点值
duration 时长，毫秒
loops 循环次数，Animation.Infinite 为无限

一段能跑的最小例子：

qml
PropertyAnimation {
    id: move
    target: box          // 哪个对象
    property: "x"        // 哪个属性
    from: 20             // 从哪
    to: 380              // 到哪
    duration: 800        // 走多久
    easing.type: Easing.OutCubic
}

move.start() 就开跑。box 是某个 Rectangle 的 id，容器代码这里省掉了。

from 和 to 可以省 #

  • 省 from：从属性的当前值开始。这是最常用的写法，尤其是反复触发的动画。
  • 省 to：走到属性当前的绑定值或者当前值。等价于「往它本来该在的地方走」，适合做「临时偏移后归位」。
  • 两个都省：动画什么也不做。

省 from 有个副作用要想清楚：如果动画正在跑的时候又被 start() 一次，新动画的起点是当前那一帧的值，不是最初的值。这正好是做「打断后接着走」想要的效果。

property 与 properties #

property: "x" 管一个属性。properties: "x,y" 管一组，用同一个 from/to、同一段时长一起插值。

qml
PropertyAnimation {
    target: box
    properties: "x,y"
    to: 0
    duration: 400
}

注意 properties 里的 from/to 对列表里所有属性生效。x 要从 20 到 0、y 要从 300 到 0，这种不同步的需求就分两个动画写，别硬塞。

loops 与 alwaysRunToEnd #

qml
NumberAnimation on rotation {
    to: 360
    duration: 2000
    loops: Animation.Infinite
}

loops: 3 跑三遍。loops: Animation.Infinite 一直跑。循环动画每轮结束回到起点，所以 to: 360 的旋转看不出接缝，to: 100 的位移会明显弹回去。

alwaysRunToEnd: true 让 stop() 不立刻中断，而是把当前这一轮跑完再停。收起面板这类「已经开始了就别半路掐断」的场景用它。

派生关系 #

NumberAnimation、ColorAnimation、RotationAnimation 都是从 PropertyAnimation 派生的，只是把属性类型固定下来，target / from / to / duration / easing 全部继承。SequentialAnimation、ParallelAnimation、PauseAnimation、SmoothedAnimation、SpringAnimation、PathAnimation、PropertyAction、ScriptAction 则直接继承 Animation。

动画类型一览 #

元素 管什么 典型落点
PropertyAnimation 任意可插值属性 兜底，通用
NumberAnimation 数值 x y width height opacity scale
ColorAnimation 颜色 color border.color
RotationAnimation 角度 rotation
Vector3dAnimation 三维向量 transform 里的平移
PauseAnimation 不改任何属性，只占时间 序列里的停顿
SequentialAnimation 串行组合 先移动再变色
ParallelAnimation 并行组合 边移动边旋转
SmoothedAnimation 跟随型平滑 鼠标跟随、滚动位置
SpringAnimation 弹簧往复 弹性归位
PathAnimation 几何路径 沿曲线运动
PropertyAction 瞬时改值 序列中某个节点切换状态
ScriptAction 执行脚本 序列中触发一次业务逻辑

PauseAnimation 到 ScriptAction 这一段的细节放在第八章，那里讲组合。

三、数值动画与颜色动画 #

PropertyAnimation 能用，但每次都要写 property: "x" 有点啰嗦。派生类把属性名固定下来了，写法更紧。

NumberAnimation #

最常用。凡是数值属性都能动：

qml
Rectangle {
    id: panel
    width: 200; height: 60
    color: "#31c48d"

    NumberAnimation on opacity {
        from: 1.0
        to: 0.2
        duration: 600
        easing.type: Easing.InOutQuad
    }
}

数值属性的判定标准是类型，不是名字。width 是 real，能动；objectName 是 string，不能动；自定义的 property real progress 能动。

ColorAnimation #

颜色插值走的是 RGBA 各通道，所以 "black" 到 "green" 中间会经过一批暗绿，不是跳变。

qml
Rectangle {
    id: led
    width: 100; height: 100
    radius: width / 2
    color: "black"

    ColorAnimation on color {
        to: "green"
        duration: 2000
    }
}

ColorAnimation 只能作用在 color 类型的属性上。往 real 属性上挂它不会报编译错，运行起来也不会有任何变化。

RotationAnimation #

rotation 本质是 real，理论上 NumberAnimation 也能动。RotationAnimation 多出来的是方向控制：

qml
RotationAnimation on rotation {
    to: 90
    duration: 600
    direction: RotationAnimation.Shortest
}

direction 三个取值：

取值 走法
RotationAnimation.Shortest 默认，走角度差最短的那一侧
RotationAnimation.Clockwise 强制顺时针
RotationAnimation.Counterclockwise 强制逆时针

从 350 转到 10，Shortest 走 20 度，Clockwise 走 340 度。要「转两圈回到原位」的效果，别指望 to: 0，写 to: 720。

RotationAnimation 还有 origin.x / origin.y 控制旋转中心，不写默认绕元素中心。

属性类型和动画元素对不上时 QML 不吭声：动画跑起来了，属性值没变。这类问题查半天，不如一开始就核对类型。int / real 给 NumberAnimation，color 给 ColorAnimation，rotation 给 RotationAnimation，其余可插值类型交给 PropertyAnimation 兜底。

四、动画的三种使用方式 #

同一个动画效果，QML 给了三种挂法。选哪种看触发源，不看个人喜好。

方式一：属性关联动画 #

直接在属性声明的位置挂 on <property>：

qml
Rectangle {
    width: 60; height: 60
    color: "#e0533d"

    NumberAnimation on y {
        to: 240
        duration: 1200
        loops: Animation.Infinite
        easing.type: Easing.InOutQuad
    }
}

特点：元素一加载就自动跑。没有 id 就没有 start() / stop()，控制权交出去了。

它挂的是属性的默认值位置，等于「这个属性的初始值由动画给出」。这种写法拿不到控制权，要停下只能从外部干预——把整个元素隐藏，或者干脆换成方式三。

方式二：行为动画 #

给属性指定一个默认行为，属性值被谁改都走动画：

qml
Rectangle {
    id: knob
    width: 40; height: 40
    color: "#f0a020"
    y: 200

    Behavior on y {
        NumberAnimation { duration: 400 }
    }

    MouseArea {
        anchors.fill: parent
        onClicked: knob.y = knob.y === 200 ? 60 : 200
    }
}

knob.y = 60 这一句赋值本身是瞬时的，Behavior 把它接住转成了 400 毫秒的过渡。特点：能自动响应所有导致属性改变的事件，不用为每个入口单独写动画。

代价是隐式。读代码时看到一行赋值，得翻回去找有没有 Behavior，才知道它会不会动。第九章专门讲它。

方式三：独立动画 #

把动画当独立节点放，用 id 控制：

qml
NumberAnimation {
    id: fly
    target: rocket
    property: "x"
    from: 20
    to: 400
    duration: 1500
    easing.type: Easing.InOutCubic
}

MouseArea {
    anchors.fill: parent
    onClicked: fly.start()
}

特点：最灵活。start()、stop()、pause()、resume()、restart()、complete() 全套接口都在，还能读 running 和 progress 做联动。

三种方式对照 #

维度 属性关联 行为 独立
触发时机 元素加载即跑 属性被改时 手动调用
可控性 无 低 完整
复用性 一次一个属性 一个属性一个行为 一个动画打多个目标
代码位置 属性旁 属性旁 独立节点
典型场景 装饰性循环动画 交互反馈、开关 复杂时序、可打断的转场

判断规则：需要「什么时候开始」由代码决定，就用独立动画；需要「只要这个值变就动」，就用行为；只是开局跑一下给人看，就用属性关联。

三种方式可以混用。一个界面里循环的背景用属性关联，按钮的位移用行为，抽屉的开合用独立动画，互不冲突。

五、状态 States #

界面在开发时最容易被写成「一堆 if 判断属性」。QML 把这套东西显式化了：界面被描述为一系列离散的状态，每个状态下各属性的取值都不一样，状态之间用名字区分。

三个基本零件 #

  • State 元素描述一种界面配置，放在主项目的 states 列表里。
  • 每个状态有唯一的字符串 name。
  • 默认状态的名字是空字符串 ""，代表元素刚加载时的属性值。
  • 状态内部用 PropertyChanges 描述「在当下这个状态里，哪个对象的哪些属性应该是什么值」。
qml
states: [
    State {
        name: "go"
        PropertyChanges { target: light1; color: "black" }
        PropertyChanges { target: light2; color: "green" }
    },
    State {
        name: "stop"
        PropertyChanges { target: light1; color: "red" }
        PropertyChanges { target: light2; color: "black" }
    }
]

states 是个列表，顺序不代表优先级。名字重复的后果是行为未定义，别撞名。

切换状态 #

给根项目的 state 属性赋一个新的状态名就切过去了：

qml
MouseArea {
    anchors.fill: parent
    onClicked: parent.state = (parent.state === "stop" ? "go" : "stop")
}

state 是个普通属性，能赋值、能读、能绑。所以也能写成声明式：

qml
state: lightOn ? "go" : "stop"

也能用 State 的 when 属性，绑一个布尔表达式，表达式为 true 时自动切入该状态：

qml
State {
    name: "expanded"
    when: root.hovered && !root.locked
    PropertyChanges { target: panel; height: 320 }
}

when 写多个状态时，后面的状态优先。这条容易踩，别让两个 when 同时为真还指望有确定结果。

红绿灯完整例子 #

两个灯，黑色底框，stop 状态上灯亮红，go 状态下灯亮绿：

qml
import QtQuick 2.0

Rectangle {
    id: trafficLightBox
    width: 150; height: 270
    color: "darkgray"
    radius: 10

    // 默认初始状态设为 stop
    state: "stop"

    // 1. 红灯（上灯）
    Rectangle {
        id: light1
        x: 25; y: 15
        width: 100; height: 100
        radius: width / 2
        color: "black"      // 默认黑色（熄灭）
    }

    // 2. 绿灯（下灯）
    Rectangle {
        id: light2
        x: 25; y: 135
        width: 100; height: 100
        radius: width / 2
        color: "black"
    }

    // 3. 状态变更的属性配置
    states: [
        State {
            name: "stop"
            PropertyChanges { target: light1; color: "red" }
            PropertyChanges { target: light2; color: "black" }
        },
        State {
            name: "go"
            PropertyChanges { target: light1; color: "black" }
            PropertyChanges { target: light2; color: "green" }
        }
    ]

    // 4. 点击整个区域切换状态
    MouseArea {
        anchors.fill: parent
        onClicked: {
            parent.state = (parent.state === "stop" ? "go" : "stop")
        }
    }
}

跑起来会发现点击时颜色是瞬间跳变的。这不是写错了，是还没加过渡——第六章补。

增量修改原则 #

PropertyChanges 里写的是相对于默认状态 "" 的值，不是相对于「上一个状态」的值。

light2 的初始颜色就是 black，所以在 stop 状态里那条 PropertyChanges { target: light2; color: "black" } 是多余的，删掉效果一样。留在那儿不算错，只是噪音。

这条原则的推论：某个属性没出现在任何 PropertyChanges 里，它在所有状态下都保持默认值。反过来说，一旦它出现在某个状态里，退出该状态时 QML 会把它恢复到默认值，不会停在上一个状态的值上。

如果确实需要「退出状态时不要恢复」，把 restoreEntryValues 设成 false：

qml
PropertyChanges {
    target: panel
    height: 320
    restoreEntryValues: false    // 退出该状态后 height 停在 320
}

这个默认值 true 是有道理的：状态是「配置」，配置撤了就该回原样。设成 false 就等于让状态偷偷改全局，后面的人读代码会很难受。有明确理由再用。

状态里还能改什么 #

PropertyChanges 管属性值。位置类的调整还有 AnchorChanges，父子关系有 ParentChange：

qml
State {
    name: "docked"
    AnchorChanges {
        target: panel
        anchors.left: parent.left
        anchors.right: undefined
    }
}

AnchorChanges 存在的意义是：锚点不是普通属性，用 PropertyChanges 改不动，只能用它。移动元素时如果原有属性是锚点绑定的，状态里也得配 AnchorChanges，否则新加的 x 会被锚点压回去。

状态与过渡的分工 #

谁 管什么 不写会怎样
State 某个状态下各属性是什么值 界面没有可切换的形态
Transition 状态之间怎么切过去 切换瞬间完成，值跳变

只写 State，界面能用，但切换是硬切。只写 Transition 没有 State，没什么可切的，过渡也挂不上。两个一起写才有动画。

这条分工是整篇的骨架。搞混它会走两条弯路：把过渡能做的事写成手写动画（维护成本翻倍），或者把状态该管的值写进动画（切回去就乱）。

六、过渡 Transitions #

Transition 挂在根项目的 transitions 列表里，负责「状态切换时怎么走」。

from 与 to 是过滤器 #

qml
transitions: [
    Transition {
        from: "stop"; to: "go"
        ColorAnimation { target: light1; properties: "color"; duration: 2000 }
        ColorAnimation { target: light2; properties: "color"; duration: 2000 }
    }
]

from / to 填状态名。只有状态从 from 指定的值变到 to 指定的值时，这个过渡才播。两个都能写通配符 *，代表匹配任意状态。

写法 匹配范围
from: "a"; to: "b" 只匹配 a 到 b
from: "*"; to: "b" 任何状态进 b
from: "a"; to: "*" a 到任何状态
都不写 等价于 * 到 *，所有切换
from: ""; to: "*" 从默认状态出发的所有切换

不写 from / to 的 Transition 是全能过渡，任何状态切换都走它。原型阶段很方便，但一个界面有五六种状态时这样写会让动效全撞一起，后面拆起来麻烦。规则是：能写明就写明。

补上过渡后的红绿灯 #

第五章那个红绿灯，只在 states 后面接一段 transitions 就够了，其余代码一行不动：

qml
transitions: [
    Transition {
        from: "stop"; to: "go"
        ColorAnimation { target: light1; properties: "color"; duration: 2000 }
        ColorAnimation { target: light2; properties: "color"; duration: 2000 }
    }
]

现在从 stop 切到 go，红灯慢慢熄灭、绿灯缓缓亮起，两秒走完。

从 go 切回 stop 还是秒切，因为我们只定义了单向的 Transition。这个不对称现象正好证明 from / to 是过滤器——不是装饰。

要双向就再来一条 Transition（from: "go"; to: "stop"，动画照抄），或者抽成一条通用的：

qml
Transition {
    from: "*"; to: "*"
    ColorAnimation { duration: 2000 }    // 目标与属性自动匹配
}

过渡里的动画可以省略 target #

Transition 里的动画有个便利之处：target 和 properties 能省。省掉时，动画自动作用于这次状态切换中发生变化的那些对象的那些属性。

所以上面那条 ColorAnimation { duration: 2000 } 是能跑的，它自己找上了 light1.color 和 light2.color。

这个自动匹配在「状态里改了七八个属性，只想统一给个时长」时特别省事。但在「只想给其中一个属性加动画」时会管得太宽，那样就老老实实写 target + properties。

过渡里能放什么 #

任何 Animation 都行，SequentialAnimation、ParallelAnimation 嵌套也照放：

qml
Transition {
    from: "collapsed"; to: "expanded"
    ParallelAnimation {
        NumberAnimation { target: panel; properties: "height"; duration: 300 }
        NumberAnimation { target: panel; properties: "opacity"; from: 0.6; to: 1.0; duration: 300 }
    }
}

一个 Transition 里放多个动画，默认是并行的。要串行就自己包一个 SequentialAnimation，别指望列表顺序。

三个坑 #

  • transitions 写在根项目上，不是写在 State 里。State 没有 transitions 属性。
  • 过渡的时长和状态的 when 条件会打架。when 条件在过渡进行中翻转，过渡会中断并从当前值重新起跑。写连续动画时想清楚这一点。
  • 过渡里动画的 from 别硬写。状态切换的起点是「切换前的实际值」，写死 from 会让打断后的动画跳一下。

七、缓动曲线 Easing #

前面所有例子都在改 easing.type，这里说清它到底干什么。

它只改速度分配 #

一次动画有三样东西：起点值、终点值、时长。这三样定完，动画的「总账」就定了。缓动曲线改的是这笔账在路上怎么分配。

text
duration = 1000ms，从 0 到 100
Linear     : 每 100ms 走 10
OutQuad    : 前 100ms 走 30，最后 100ms 走 3

终点还是 100，总时长还是 1000 毫秒。缓动曲线影响观感，不影响时长。 想要更快，改 duration；想要更自然，改 easing.type。这两件事别混。

不写 easing.type 时默认是 Easing.Linear，也就是匀速。匀速的问题不是难看，是「不像真的」——现实里没有东西是突然获得速度又突然停下的。所以默认动画看着机械。

In / Out / InOut #

QML 的缓动名是两段式：方向 + 曲线，比如 Out + Bounce。

前缀 含义 什么时候用
In 慢起步，越来越快 元素离开视野、被收走
Out 快起步，越来越慢 元素进入视野、落位
InOut 两头慢，中间快 从 A 到 B 的位移、循环动画

判断方法：Out 是「刹车」，In 是「油门」，InOut 是「先给油再刹车」。 一个东西飞出去，用 In；一个东西停下来，用 Out。

常用曲线 #

类型 手感 适用
Easing.Linear 匀速，机械 进度条、旋转、滚动
Easing.InQuad / OutQuad / InOutQuad 二次曲线，轻微加减速 通用首选
Easing.InCubic / OutCubic 三次曲线，加减速更明显 位移、面板滑动
Easing.InSine / OutSine 正弦，过渡最柔 淡入淡出、透明度
Easing.InOutQuad 对称加减速 循环动画、往复运动
Easing.OutCirc 圆弧收尾，停得干脆 抛掷物的上升段
Easing.OutBounce 落地弹几下 掉落、归位、提示
Easing.InBack / OutBack 起跑前回拉 / 到点后过冲 弹出、抽屉
Easing.InElastic / OutElastic 橡皮筋震荡 强调型反馈

OutBounce 的用法：

qml
NumberAnimation {
    target: square; properties: "x"
    from: 40; to: 500
    duration: 2000
    easing.type: Easing.OutBounce    // 落地后像乒乓球一样弹几下
}

OutBounce 特别适合「东西掉到位置上」这类场景，因为它自带多次衰减反弹，不用手写 SequentialAnimation。

弹性与回弹的参数 #

OutElastic 和 OutBack 带可调参数：

qml
NumberAnimation {
    target: panel; properties: "scale"
    to: 1.0
    duration: 500
    easing.type: Easing.OutElastic
    easing.amplitude: 1.2     // 震荡幅度
    easing.period: 0.35       // 震荡周期
}

OutBack 同理，只是参数换成 easing.overshoot，1.0 是默认，2.0 冲出去一大截。

amplitude 调大，弹得更夸张；调小到接近 0，就退化成 OutQuad 一类。

参数调过头会变成「物体冲出去再飞回来」，观感很怪。这个靠试，别看文档猜数值。

怎么选 #

三条经验：

  • 位移用 OutCubic 或 InOutQuad，稳，不容易出错。
  • 透明度用 OutSine 或 Linear，透明度上做花活很别扭。
  • 带物理意味的动作（掉落、弹回、甩出）用 OutBounce / OutBack / OutElastic，但别在同一屏上用超过一种。

同一屏里混三种缓动，人会觉得自己在看不同步的东西。缓动是用来统一节奏的，不是用来展示的。

八、动画分组与嵌套 #

单个动画只能改一个属性。现实里的运动是多维的，靠组合描述。组动画自己也是 Animation，能互相嵌套，深度不限。

三种时间工具 #

元素 作用 整组时长
SequentialAnimation 子动画依次播 子动画时长之和
ParallelAnimation 子动画同时播 取最长的那个
PauseAnimation 占一段时间，什么也不做 自定

时长规则要记住：ParallelAnimation 里放一个 300ms 和一个 800ms，整组就是 800ms，短的那个跑完停在终点值等着，不会自动循环。想让短的撑满，给它写 loops。

两个瞬时动作 #

PropertyAction 在时间轴某个点上瞬间改属性值，没有插值过程。ScriptAction 在某个点上执行一段 JS。

qml
SequentialAnimation {
    id: blink
    loops: Animation.Infinite
    NumberAnimation { target: dot; properties: "opacity"; to: 0.0; duration: 250 }
    PropertyAction { target: dot; property: "color"; value: "#d0342c" }
    ScriptAction { script: console.log("切到告警色") }
    PauseAnimation { duration: 200 }
    NumberAnimation { target: dot; properties: "opacity"; to: 1.0; duration: 250 }
}

PropertyAction 只改一个属性，用 property 不用 properties。它是「不能插值的属性」的唯一办法——source 没法渐变，硬挂 NumberAnimation 什么也不会发生。

跟随与路径 #

元素 用途 关键属性
SmoothedAnimation 平滑追随一直在变的目标 velocity、duration
SpringAnimation 弹簧式往复逼近 spring、damping、epsilon
PathAnimation 沿几何路径运动 path、orientation

SmoothedAnimation 用鼠标跟随、滚动位置这类场景，目标是活的，它持续追而不是跑到就停。SpringAnimation 在目标附近震荡衰减，damping 越小震得越久。PathAnimation 的 path 里塞 PathLine、PathQuad、PathCubic 描述轨迹。

嵌套实战：扔足球 #

一个球从左下抛到右下，同时自转。拆成三个维度：X 轴匀速右移（线性）；Y 轴先向上抛（减速）再向下坠落（加速并反弹）；rotation 行进中持续自转。

曲线分配：

  • Y 轴上升段用 OutCirc，模拟重力把速度吃掉。
  • Y 轴下落段用 OutBounce，模拟落地碰撞反弹。
  • X 轴与旋转用线性。
text
ParallelAnimation
├── SequentialAnimation         Y 轴：先升后降
│   ├── NumberAnimation  y -> 20    占 40%   OutCirc
│   └── NumberAnimation  y -> 240   占 60%   OutBounce
├── NumberAnimation      x -> 400   占 100%  线性
└── RotationAnimation    rotation -> 720   占 110%

结构决定观感：Y 轴必须串行（先上后下，不能同时），X 与旋转并行。整体套一层 ParallelAnimation，让三条线一起起跑。

qml
import QtQuick 2.0

Item {
    id: root
    width: 480; height: 300
    property int duration: 3000

    Rectangle {                     // 天空
        id: sky
        width: parent.width; height: 200
        gradient: Gradient {
            GradientStop { position: 0.0; color: "#0080FF" }
            GradientStop { position: 1.0; color: "#66CCFF" }
        }
    }

    Rectangle {                     // 草地
        id: ground
        anchors.top: sky.bottom
        anchors.bottom: parent.bottom
        width: parent.width
        gradient: Gradient {
            GradientStop { position: 0.0; color: "#00FF00" }
            GradientStop { position: 1.0; color: "#00803F" }
        }
    }

    Image {
        id: ball
        x: 20; y: 240
        source: "assets/soccer_ball.png"

        MouseArea {
            anchors.fill: parent
            onClicked: {
                ball.x = 20; ball.y = 240; ball.rotation = 0;
                anim.restart()
            }
        }
    }

    ParallelAnimation {
        id: anim

        SequentialAnimation {       // Y 轴：先升后降
            NumberAnimation {
                target: ball; properties: "y"
                to: 20
                duration: root.duration * 0.4
                easing.type: Easing.OutCirc
            }
            NumberAnimation {
                target: ball; properties: "y"
                to: 240
                duration: root.duration * 0.6
                easing.type: Easing.OutBounce
            }
        }

        NumberAnimation {           // X 轴：匀速右移
            target: ball; properties: "x"
            to: 400
            duration: root.duration
        }

        RotationAnimation {         // 自转两圈
            target: ball; properties: "rotation"
            to: 720
            duration: root.duration * 1.1
        }
    }
}

root.duration 抽出来当中枢，改一个数整段节奏一起变。四段按 0.4 / 0.6 / 1.0 / 1.1 的比例分配，比例守住，整体快慢随便调。

restart() 之前先把 x、y、rotation 归位。restart() 只是从头播，不会自动复位属性值——不复位的话第二次点，球会从上次停的位置重新起跑。

九、行为 Behavior #

Behavior on <property> 给一个属性装默认过渡。值被改时自动走它。

qml
Rectangle {
    id: knob
    width: 36; height: 36
    radius: 18
    color: "#f0a020"

    Behavior on x {
        NumberAnimation { duration: 350; easing.type: Easing.OutCubic }
        enabled: animationsEnabled
    }
}

四条要点：

  • 一个属性只能挂一个 Behavior，挂第二个会被忽略。
  • enabled: false 临时关掉，全局开关就靠它。
  • 它对所有修改生效，包括绑定变化、状态切换、脚本赋值。状态过渡里已经写了动画，Behavior 再插一手就是两段动画抢一个属性，最后谁赢取决于执行顺序。
  • 它只处理「值变了」，不区分「为什么变」。

Behavior 的价值是把动效从业务代码里剥离。knob.x = 200 读起来就是赋值，过渡藏在属性声明处。适合「所有入口都该有过渡」的属性，比如开关位移、面板高度。反过来，如果某个入口需要瞬间改值，它会挡路，只能临时 enabled: false。

十、动画的性能与取舍 #

动什么属性便宜 #

属性 代价 说明
x / y 低 只动位置，不动布局
opacity 低 合成阶段处理
scale / rotation 低 同上
color 中 需要重新光栅化
width / height 高 触发布局，子元素跟着重排
anchors.* 高 每次变化重算锚点链

结论直白：

  • 缩放别动 width / height，改 scale。
  • 位移别动锚点，改 x / y 或变换。
  • 列表 delegate 里少用 width 动画，一屏几十个 delegate 同时重排，帧率立刻掉。

三条纪律 #

  • 动画属性上别挂复杂绑定。每帧求值一次，绑定里再算点东西，开销是乘上去的。
  • 动画数量不是问题，每帧的工作量才是。全局时钟统一驱动，多几个动画本身不疼。
  • 别过度。装饰性循环动画一屏最多一个，多了用户的注意力会被切碎。

给动画留开关 #

无障碍设置里有一项「减少动态效果」。在根项目上声明 property bool animationsEnabled: true，所有 Behavior 的 enabled 和独立动画的 running 都读它。真要关的时候一处改完，不用满文件找 duration。

十一、实战：交互驱动的动画 #

把前九章的东西拼到一个红绿灯上。三招都不难，加起来就是能用的交互。

第一招：亮灯带缩放 #

在 go 状态里，除了变色，让绿灯略微放大、红灯略微缩小：

qml
State {
    name: "go"
    PropertyChanges { target: light1; color: "black"; scale: 0.9 }
    PropertyChanges { target: light2; color: "green"; scale: 1.1 }
}

过渡里同时挂颜色和缩放两条动画，缩放用 OutBack 做出弹出感：

qml
transitions: [
    Transition {
        from: "*"; to: "*"
        ColorAnimation { duration: 400; easing.type: Easing.InOutQuad }
        NumberAnimation { properties: "scale"; duration: 300; easing.type: Easing.OutBack }
    }
]

这里省了 target，靠过渡自动匹配变化的属性。颜色走 400ms 的 InOutQuad，缩放走 300ms 的 OutBack，两条时长不同、曲线不同，观感才有层次。

第二招：黄灯闪烁 #

加一个 attention 状态，配一个循环动画。状态里只改颜色，闪烁交给独立动画：

qml
State {
    name: "attention"
    PropertyChanges { target: light1; color: "black" }
    PropertyChanges { target: light2; color: "yellow" }
}

SequentialAnimation {           // 闪烁交给独立动画，只碰 opacity
    id: blink
    running: trafficLightBox.state === "attention"
    loops: Animation.Infinite
    NumberAnimation { target: light2; properties: "opacity"; to: 0.25; duration: 350 }
    NumberAnimation { target: light2; properties: "opacity"; to: 1.0; duration: 350 }
}

running 直接绑状态名，进 attention 就闪，离开就停。这比在 onStateChanged 里手动 start() / stop() 干净，也不会漏掉「状态被其他代码改掉」的情况。

第三招：节奏统一 #

三个状态的过渡时长别各写各的。在根项目上声明 property int uiDuration: 400，所有 duration 都引用它。以后要整体调快，改一处。散落在各处的魔法数字是动效维护中最难还的债。

十二、易错点速查 #

现象 原因 改法
动画完全不生效 属性名拼错，或类型不能插值 核对 properties 与属性类型
动画第一次生效，之后属性不再跟随绑定 动画写入了被绑定占用的属性，绑定被断 用 Behavior，或改动画 target
状态切换是硬跳 只写了 states，没写 transitions 补 Transition
单向过渡有动画，反向秒切 from / to 只配了一个方向 再写一条，或用 * 通配
状态退出后属性没回默认值 用了 restoreEntryValues: false 确认是否真要保留，否则删掉这句
width 动画卡顿 触发子元素重排 改 scale，或改用变换
组动画比预期短 ParallelAnimation 取最长子动画 给短的子动画补 loops
restart() 后位置不对 属性没复位，只重播了动画 重启前手动归位
状态里改锚点无效 锚点不是普通属性 用 AnchorChanges
两个动画抢一个属性 Behavior 与 Transitions 同时管 留一个，另一个 enabled: false

最后一条最容易漏。看到某个属性动得「怪怪的」，先数一遍有几条路径在改它：状态过渡、Behavior、脚本赋值、绑定更新。四条里只要两条同时开着，结果就不由你决定。
