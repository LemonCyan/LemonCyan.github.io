本篇只讲 QML 里用来「取一个值」的两类对话框：ColorDialog 与 FileDialog，都来自 QtQuick.Dialogs。范围包含模块结构、打开与结果回传、两个控件的全部属性、过滤器与默认后缀、保存与多选、原生与自绘的分界、Qt5 与 Qt6 的写法差异。不展开 Popup 的布局与过渡动画，不展开控件样式定制。控件基础见同目录《QML 与 Qt Quick 入门》一篇，模块划分见《三大模块》一篇，排布见《布局》一篇，点击与事件见《按钮与鼠标》一篇。

一、QML 的对话框从哪来 #

QML 自己不带「对话框」这种东西。

QtQuick 里能拿到的最小单位是 Item：一块画在场景里的矩形区域，没有窗口边框，没有标题栏，也不会浮在别的窗口之上。想真的弹出「另一个窗口」，起点只有 Window，或者带样式的 ApplicationWindow。对话框是在这层基础上包出来的约定：一个有标题的窗口，里面放内容，底部放按钮，关掉之后把「用户点了哪一边」告诉调用方。

QML 里有三个来源，先分清，后面所有讨论都建立在这个前提上。

来源 典型类型 是不是独立窗口 典型用途
QtQuick.Dialogs ColorDialog、FileDialog、FontDialog、MessageDialog 是，优先交给系统 取颜色、取文件、取字体、简单确认
QtQuick.Controls 的 Dialog Dialog、MessageDialog Controls 2 里不是，它是 Popup 表单、设置页、带自定义内容的提示
自己拼 Window + Rectangle + Button 是 特殊外观、特殊交互、嵌入式设备

差别不在「谁更高级」，而在「谁来画这个窗口」。

1.1 为什么取颜色和取文件要单独一个模块 #

这两件事系统自己就有实现：macOS 的取色器、Windows 的打开文件框、各 Linux 桌面的对应组件。重画一遍要面对熟悉度（快捷键、侧边栏、最近位置）、平台差异（盘符、网络位置、权限提示）、以及沙箱授权（移动端和 macOS 下文件访问走系统流程，自绘对话框拿不到授权）。

QtQuick.Dialogs 就冲着这三点去：能用系统给的，就用系统给的。

1.2 一个必须先接受的结论 #

QML 的对话框是异步的。

open() 只是「请把这个窗口显示出来」，它立刻返回。用户选完之后，结果通过 accepted 信号送回来。你在 open() 下一行读选中的颜色或文件，读到的是上一次的旧值，或者空。

这跟 QtWidgets 的 QColorDialog::getColor()、QFileDialog::getOpenFileName() 完全不同，那两个是阻塞调用，不返回就说明用户还没选完。第三章拆开讲透。

二、QtQuick.Dialogs 模块 #

QtQuick.Dialogs 是独立模块，不是 QtQuick.Controls 的一部分，跟 QtQuick、QtQuick.Controls 并列，需要单独 import。它在 Qt 5.1 里作为新模块加入，定位就是把平台对话框接进 QML。Qt 6 里整体重写过，导入语句和行为都有变化，第十章专门对比。

2.1 导入语句 #

Qt5 带版本号，要挑一个和你的 Qt 版本对得上的小版本：

qml
import QtQuick 2.1
import QtQuick.Dialogs 1.0

Qt6 可以省略版本号，模块名不变：

qml
import QtQuick
import QtQuick.Dialogs

版本号写高了，Qt Creator 在导入行下面画红线，运行时报 module "QtQuick.Dialogs" version 1.9 is not installed。这种错跟逻辑无关，先看这一行。

2.2 模块里的类型一览 #

类型 干什么 Qt5 Qt6
ColorDialog 取一个颜色 有 有（重写）
FileDialog 取文件路径，或取保存路径 有 有（重写）
FolderDialog 只取文件夹 无 有（从 FileDialog 拆出）
FontDialog 取字体 有 有（重写）
MessageDialog 提示、确认、多按钮询问 有 有（重写）

FolderDialog 是 Qt6 新拆的类型。Qt5 选文件夹要写 FileDialog 加 selectFolder: true，Qt6 直接用 FolderDialog。本篇只展开前两个；FontDialog 结构和 ColorDialog 几乎一样——一个 font 属性存结果，一个 accepted，一个 rejected——看完前两个自己就能推。

2.3 共享骨架 #

不管哪个类型，骨架都是四个部位：

  • 一组配置属性：title、modality，以及各自特有的属性，必须在打开之前设好。
  • visible：bool，默认 false。
  • open() / close()：两个方法，等价于把 visible 设成 true / false。
  • accepted / rejected：两个信号，点确定走前者，点取消或直接关窗口走后者。
qml
ColorDialog {
    id: picker
    title: "选个颜色"
    onAccepted: { /* 用户点了确定 */ }
    onRejected: { /* 用户点了取消 */ }
}

所有对话框的差异，都在第一项里那几个特有属性。

2.4 声明不等于打开 #

把 ColorDialog { } 写在 QML 文件里，不等于它会弹出来。visible 默认 false，声明这一刻它只是个对象，藏在内存里等着。素材里那种「一启动就弹」的写法，是把这一步塞进组件完成时：

qml
Component.onCompleted: visible = true

意思是：等组件构造完，立刻打开，等价于调 open()。

三、对话框的打开与结果 #

这一章是本篇核心。搞不清它，后面属性背得再熟也没用。

3.1 一次交互四个时刻 #

时刻 发生什么 你该做什么
准备 设 title、过滤条件、初始目录 打开之前设好，打开后再改有些会被忽略
打开 调 open()，窗口出现 什么都不做，等
用户操作 挑颜色、选文件、翻目录 不参与
收尾 点确定 → accepted；点取消 → rejected 两个信号里分别处理

关键在第三格：用户操作的这段时间，你的代码在继续跑别的事件。open() 不会停在那里等，它把「显示窗口」排进事件循环，立刻返回，下一行照常执行。

3.2 错误写法 #

先看新手一定会写的版本：

qml
Button {
    text: "选颜色"
    onClicked: {
        colorDialog.open()
        // 错：这里读到的不是用户即将选的颜色
        root.bgColor = colorDialog.color
    }
}

open() 返回时用户连对话框都没看见，color 里装的是上一次的结果，第一次运行时是默认值。这段代码不报错、不崩溃，只是行为诡异：第一次点按钮颜色不变，第二次点变成第一次选的那个，永远慢一拍。

3.3 正确写法 #

把取值挪进 onAccepted：

qml
Button {
    text: "选颜色"
    onClicked: colorDialog.open()
}

ColorDialog {
    id: colorDialog
    title: "选择背景色"
    onAccepted: root.bgColor = colorDialog.color
    onRejected: console.log("取消选择，颜色保持不变")
}

顺序反过来了：先打开，用户选完，信号回来，这时候才读值。open() 那一行后面干干净净。

3.4 为什么模态也救不了你 #

有人想：modality 设成 Qt.ApplicationModal，总该阻塞了吧。不是。素材这句说得准确：

模态并不意味着有任何阻塞调用等待被接受或拒绝的对话框，它只是阻止用户与父窗口或应用程序窗口同时交互。

模态管的是用户能不能点别的窗口，不管你的代码跑到哪一行。这两件事在 Qt 里是分开的。QML 的对话框一律非阻塞，exec() 这种同步返回的对话框在这套体系里不存在。

3.5 和 QtWidgets 的对照 #

维度 QtWidgets QML QtQuick.Dialogs
典型调用 QColorDialog::getColor() ColorDialog { open() }
是否阻塞 阻塞，不返回就是没选完 不阻塞，open() 立刻返回
结果怎么拿 函数返回值 accepted 信号里读属性
取消怎么知道 返回无效值（如无效 QColor） rejected 信号
代码形态 顺序执行，一行接一行 回调，拆成函数或信号处理
出错形态 编译期发现返回值没用 运行期读到旧值，不报错

最后一行是重点。QtWidgets 那套写错编译器提醒你，QML 这套写错了一声不吭，只是结果不对。

3.6 accepted 与 rejected 都要接 #

用户点「确定」，accepted 发出来。点「取消」，或者点窗口右上角的叉，rejected 发出来。两个信号是互斥的两条路。

只接 accepted 的后果：用户点取消之后，程序还停在「等结果」的状态。逻辑里那个 pending 标志、那个「处理中」的提示、那个被禁用的按钮，会永远停在那儿。

qml
ColorDialog {
    id: picker
    onAccepted: {
        root.chosen = picker.color
        root.busy = false
    }
    onRejected: {
        root.busy = false   // 这句不能省
    }
}

onRejected 里常常「什么都不用做」，但把状态复位这件事必须做。写一个空的 onRejected: {} 也比不写好——它至少让 review 时看见这里被考虑过。

3.7 用状态机管住异步 #

交互一多，散落的信号处理会乱。用一个显式状态字段收口：

qml
Item {
    id: root
    property string pendingAction: ""   // "" | "bg" | "fg"

    function pickColor(which) {
        root.pendingAction = which
        picker.open()
    }

    ColorDialog {
        id: picker
        onAccepted: {
            if (root.pendingAction === "bg") root.bgColor = picker.color
            else if (root.pendingAction === "fg") root.fgColor = picker.color
            root.pendingAction = ""
        }
        onRejected: root.pendingAction = ""
    }
}

一个对话框服务多个用途，靠 pendingAction 记住「这次是为谁打开的」，不用为每种颜色各开一个 ColorDialog。同样的模式换到文件上：pendingAction = "openConfig" / "saveReport"。

3.8 重复打开与关闭 #

open() 在已打开状态下再调一次，行为依平台而定，稳妥做法是先判断：

qml
onClicked: if (!picker.visible) picker.open()

close() 是硬关，它不发 accepted，也不发 rejected。在代码里主动 close()，就得自己复位状态。写「取消按钮」时特别容易忘：那个按钮该走会让 rejected 发出来的路径，而不是直接 close()。

四、ColorDialog：取颜色 #

ColorDialog 允许用户从调色板里挑一种颜色。它最初不可见，要么设 visible = true，要么调 open()。属性 color 存用户选择的颜色，modality、showAlphaChannel、title、visible 各管一件事。

4.1 属性与方法总览 #

成员 类型 默认 说明
color color 平台默认 用户选中的颜色（Qt6 里叫 selectedColor）
modality Qt::WindowModality 非模态 是否挡住父窗口
showAlphaChannel bool true 是否允许调整透明度
title string 空 窗口标题
visible bool false 是否可见
open() 方法 — 显示对话框，等价于 visible = true
close() 方法 — 关闭对话框
accepted 信号 — 用户确认
rejected 信号 — 用户取消

color 是读写属性。打开之前给它赋初值，对话框会带着这个颜色出现，用户从当前色开始改——改一个已有对象的颜色时先把原色塞进去，用户不用从零调。

4.2 最小可用例子 #

素材里的原始例子，Qt5 写法：

qml
import QtQuick 2.1
import QtQuick.Dialogs 1.0

ColorDialog {
    id: colorDialog
    title: "Please choose a color"
    onAccepted: {
        console.log("You chose: " + colorDialog.color)
        Qt.quit()
    }
    onRejected: {
        console.log("Canceled")
        Qt.quit()
    }
    Component.onCompleted: visible = true
}

三件事都在：设标题、接两个信号、组件完成时打开。Qt.quit() 只是这个独立示例的退出动作，真实项目里换成业务逻辑。同一份逻辑的 Qt6 写法，属性名换了：

qml
import QtQuick
import QtQuick.Dialogs

ColorDialog {
    id: colorDialog
    title: "请选择颜色"
    onAccepted: console.log("你选了：" + colorDialog.selectedColor)
    onRejected: console.log("已取消")
    Component.onCompleted: open()
}

open() 和 visible = true 等价，写哪个都行，用 open() 更直白。

4.3 color：结果存在哪 #

color 的类型是 QML 的 color，不是字符串。它能吃 "#ff8800"、"#80ff8800"（带 alpha）、"red" 这种命名色，也能吃 Qt.rgba()、Qt.hsla() 的返回值。Rectangle { color: picker.color } 直接绑上去，绑定会自动更新。

有个坑：color 在用户确认之前装的是「当前候选色」，对话框里拖滑块时它就在变。别拿它当已确认结果用，已确认结果只有 onAccepted 里读出来那一次算数。Qt6 把两个语义拆成 color（当前）和 selectedColor（确认后），用意就在这里。

4.4 showAlphaChannel：透明度要不要给 #

默认 true，对话框里会多一根 alpha 滑杆。素材原文：「提供了一种对话框是否会改变不透明度方式。默认情况下，此属性为 true。此属性必须设置为所需的值，然后再打开对话框。」

两点记住：一是默认开着，不要透明度得显式写 showAlphaChannel: false；二是打开之前设好，打开后再改，多数平台不会重建已弹出的对话框。

不要透明度就关掉，理由很实际：多一根滑杆，用户会去拖它，然后拿着一个半透明的颜色回来，糊在整个界面上。

qml
ColorDialog {
    id: picker
    showAlphaChannel: false
    onAccepted: root.bgColor = picker.color
}

4.5 modality：挡不挡父窗口 #

默认非模态。这点和 FileDialog 不一样，那边默认 Qt.WindowModal。非模态意味着颜色对话框开着时用户还能点主窗口——对「调色」这种需要来回试的场景更好用，一边调一边看主界面效果。要挡就显式设：

qml
modality: Qt.WindowModal        // 挡住父窗口
modality: Qt.ApplicationModal   // 挡住整个应用的所有窗口

素材里还有一句要留意：在 macOS 上只允许非模态的颜色对话框。这是平台限制，不是代码写错，跨平台项目别指望 macOS 上的取色器会挡住主窗口。

4.6 title、visible、open()、close() #

title 是窗口标题。原生对话框不一定把它画在系统标题栏上——有的平台忽略，有的放在对话框内部，设了没显示出来先怀疑平台。

visible 默认 false，素材原文：「这个属性设置对话框是否可见。」方法 open() 显示对话框给用户，相当于设置 visible 为 true；close() 关闭对话框。落到代码上就是 picker.open() 与 picker.close() 两行。再强调一次：close() 不发信号，想让 onRejected 里的复位逻辑跑到，别用 close()。

4.7 背后的三层实现 #

素材把这条降级链写得很清楚，值得原样保留：平台支持就用平台自己的颜色对话框；不支持，退一步去实例化一个 QColorDialog（QtWidgets 那个）；这条也不通，才轮到 QML 自己画的 DefaultColorDialog.qml。

那是个普通 QML 文件，能打开、能改、能换外观。素材原文说它「包含一个矩形来保持对话框的内容，因为某些嵌入式系统中不支持多个顶层窗口」。也就是最底层这条路上，所谓对话框其实是盖在主窗口上的一块矩形，看着像窗口，实际不是。桌面上跑得好好的取色器，挪到嵌入式板子上会变成一块盖在界面中央的面板，没标题栏，没窗口阴影——这不是 bug，是降级到了第三条路。

还有一句：对话框会自动瞬态（transient）它的父窗口。所以不管你把 ColorDialog 声明在项目树哪一层，它都居中出现在「声明它的那个 Item 或 Window」的位置。位置不对，先看它写在哪一层。

五、颜色值的传递与使用 #

拿到颜色之后怎么往下传，比怎么拿到更影响后续代码质量。

5.1 类型就是 color，别降到字符串 #

qml
property color accent: "#ff8800"          // 好：全程保持 color
accent = picker.color

property string accentText: "#ff8800"     // 差：转成字符串再转回来
accentText = picker.color.toString()

转成字符串再拼回 #、再补齐位数，全是白干的活，还留一堆格式不统一的隐患。color 能吃四种输入："#rgb"、"#aarrggbb"、命名色（"steelblue"）、Qt.rgba() / Qt.hsla() / Qt.darker() 这类函数的返回值。

color 和 C++ 的 QColor 直接对应，属性声明成 QColor，QML 赋过去自动转换，不用写 toString() 再解析：

cpp
Q_PROPERTY(QColor accent READ accent WRITE setAccent NOTIFY accentChanged)

5.2 比较与反算 #

color 内部是浮点分量，别用 == 直接比，用 Qt.colorEqual()：

qml
if (Qt.colorEqual(root.bgColor, "#ffffff"))
    root.theme = "light"

用户挑了个背景色，还得决定上面的字用黑还是白。按感知亮度算：

qml
function readableOn(c) {
    var l = 0.2126 * c.r + 0.7152 * c.g + 0.0722 * c.b
    return l > 0.5 ? "#000000" : "#ffffff"
}

.r / .g / .b 是 0 到 1 的浮点，这套系数是常用权重，够用。

5.3 存盘时存成字符串 #

要记住用户选的颜色，存成 "#aarrggbb" 或 "#rrggbb" 字符串，读回来直接塞进 color 属性，QML 会解析。透明度不想留就别存 alpha 位——存了四通道又忘了处理，界面会莫名其妙发虚。这跟第四章 showAlphaChannel 的取舍是一件事。

六、FileDialog：取文件 #

FileDialog 干的事：让用户从本地文件系统里挑一个已存在的文件、挑一个目录，或者指定一个要保存的新文件名。三个用途共用一套属性组合，所以属性比 ColorDialog 多，也更容易配错。

6.1 属性与方法总览 #

成员 类型 默认 说明
fileUrl url 空 用户选中的单个文件路径
fileUrls list<url> 空 选中的多个文件路径
folder url 空 当前所在文件夹；打开前设它可定位初始目录
modality Qt::WindowModality Qt.WindowModal 是否挡住父窗口
nameFilters list<string> 空 文件名过滤器
selectExisting bool true 只能选已存在的文件/目录
selectFolder bool false 选的是目录而非文件
selectMultiple bool false 允许多选
selectedNameFilter string 第一个 当前生效的过滤器
title string 空 窗口标题
visible bool false 是否可见
open() / close() 方法 — 显示 / 关闭
accepted / rejected 信号 — 确认 / 取消

十一个属性里，selectExisting、selectFolder、selectMultiple 是联动的，第八章拆。

6.2 最小可用例子 #

素材里的原始例子，Qt5 写法：

qml
import QtQuick 2.1
import QtQuick.Dialogs 1.0

FileDialog {
    id: fileDialog
    title: "Please choose a file"
    onAccepted: {
        console.log("You chose: " + fileDialog.fileUrls)
        Qt.quit()
    }
    onRejected: {
        console.log("Canceled")
        Qt.quit()
    }
    Component.onCompleted: visible = true
}

注意它打的是 fileUrls（复数）。单选场景打 fileUrl 更直接，少一层列表。Qt6 的同一件事：

qml
import QtQuick
import QtQuick.Dialogs

FileDialog {
    id: fileDialog
    title: "请选择文件"
    fileMode: FileDialog.OpenFile
    onAccepted: console.log("你选了：" + fileDialog.selectedFile)
    onRejected: console.log("已取消")
}

fileUrl 变成 selectedFile，fileUrls 变成 selectedFiles，多了 fileMode。第十章有完整对照表。

6.3 fileUrl 与 fileUrls #

fileUrl 类型是 url，不是 string，这是第一个容易踩的地方：

qml
onAccepted: console.log(fileDialog.fileUrl)   // file:///home/user/a.txt

url 带协议头，本地文件是 file:/// 开头。要交给 C++ 打开，用 QUrl::toLocalFile() 或 Qt.urlToLocalFile 那类工具函数，别自己切字符串。

素材原文有一句要记住：「只有当一个文件被选中此属性才被设置，其他情况，将是空。」取消之后它会不会留着上一次的值，没有保证，别依赖。

fileUrls 是 list<url>，单选时列表里只有一个元素，取消时是空列表。判断「用户到底选没选」，判空列表比判 fileUrl 是否为空更可靠。

6.4 folder：初始目录与回读 #

最被低估的一个属性。打开之前赋值，文件浏览器直接定位到那个目录，用户在「上次那张图所在目录」继续，不用重新翻一遍。

素材原文：「当前选定的文件夹的路径。之前调用的 open() 来设置此属性将导致文件浏览器最初定位在指定的文件夹中。关闭对话框后，此属性的值也被更新。」

写是定位，读是知道用户最后停在哪：

qml
FileDialog {
    id: openDialog
    folder: root.lastDir
    onAccepted: {
        root.lastDir = folder
        root.loadModel(fileUrl)
    }
}

Qt6 里这个属性叫 currentFolder（早期 6.x 里还是 folder），以所用版本为准。

6.5 modality、title、visible #

modality 默认 Qt.WindowModal，素材原文：「默认是 Qt.WindowModal。」什么都不写它就会挡住父窗口，这符合直觉：选文件一旦开始，用户得先把它结束掉。要挡整个应用用 Qt.ApplicationModal，要放开用 Qt.NonModal——取文件场景放开没意义。挡住的仍是用户操作，不是代码执行。

title 是标题，素材原文：「对话框标题。」原生对话框在部分平台上不显示自设标题，用系统默认的「打开」「保存」。visible 默认 false，open() 等价于设它为 true，close() 关闭且不发信号。

6.6 背后的降级链 #

结构照搬 ColorDialog：有原生打开文件框就用原生的，没有退到 QFileDialog（QtWidgets），再不行才用 QML 画的 DefaultFileDialog.qml。

素材原文里有个明显的复制痕迹，那句写着「FileDialog 的应用将是一个平台的颜色对话框」。这里「颜色」是从 ColorDialog 那篇抄过来的，实际是平台的文件对话框。看老文档遇到这种痕迹，按上下文纠正即可。

DefaultFileDialog.qml 同样可改，也是为「不支持多个顶层窗口」的嵌入式系统准备的：可见时被包进一个窗口，只能有一个窗口时就盖在主窗口顶部。居中规则和 ColorDialog 一样，相对声明它的 Item 或 Window。

七、文件过滤器与默认后缀 #

过滤器决定用户在文件框里看得见什么。配错了，用户会觉得「我的文件不见了」。

7.1 nameFilters 的语法 #

list<string>，每个元素一个过滤器。单个过滤器内部的多个模式用空格分隔，后面可以跟一个括号包起来的文字描述。素材给的例子：

qml
FileDialog {
    nameFilters: [ "Image files (*.jpg *.png)", "All files (*)" ]
}

拆开看这一个元素：Image files 是给人看的描述，(*.jpg *.png) 是匹配规则，两个 *. 之间用空格隔开，意思是「jpg 或 png」。规则要点：

  • 支持 ? 和 * 通配符。
  • 一个过滤器里的多个模式用空格分隔。
  • 描述文字可有可无，只写 "*.png" 也合法，只是用户看到一串通配符。
  • 列表顺序就是下拉框顺序，第一个默认生效。

7.2 目录不受过滤 #

素材原文一句：「注：目录不包括过滤器。」

过滤器只筛文件，不筛文件夹。用户在任何过滤条件下都能进目录——这是文件框的基本行为，不是你配错了。别指望用过滤器藏起某些目录，做不到。

7.3 selectedNameFilter：读和写 #

string，当前生效的那一个过滤器。素材原文：「这个属性可以在对话框可见之前设置，设置默认名称的过滤器，也可以在对话框可见设置当前名称过滤器时设置。当用户选择了一个不同的过滤器它也会被更新。」

qml
FileDialog {
    nameFilters: [ "Text (*.txt)", "Markdown (*.md *.markdown)" ]
    selectedNameFilter: "Markdown (*.md *.markdown)"   // 打开时默认选这项
    onAccepted: root.kind = selectedNameFilter          // 读用户最后选的
}

写入的字符串必须和 nameFilters 里某一项逐字符一致。差一个空格就不生效，而且不报错。这是排查「默认过滤器没生效」的第一嫌疑点。

7.4 defaultSuffix：保存时补后缀 #

用户输入 report，你想要 report.txt。Qt6 里交给 defaultSuffix：

qml
FileDialog {
    fileMode: FileDialog.SaveFile
    defaultSuffix: "txt"
}

只写后缀本身，不带点。用户自己敲了后缀就不覆盖。Qt5 的 FileDialog 没有这个属性，得在 onAccepted 里自己拼：

qml
onAccepted: {
    var p = fileUrl.toString()
    if (p.indexOf(".") === -1) p += ".txt"
    root.save(p)
}

这段粗糙判断会把目录名里带点的路径判错。真要用，先切出文件名那一段再判，别对整条路径判。

7.5 过滤器写得让人能用 #

  • 至少留一个「所有文件（*）」。用户拖进来的后缀千奇百怪，卡死过滤器等于卡死入口。
  • 描述写人话。「PNG 图片」比「*.png」直观。
  • 同类文件别拆成多项。PNG 和 JPG 分成两项用户要切两次，写成 图片 (*.png *.jpg) 一次到位。
  • 后缀大小写。部分平台的文件框大小写敏感，要兼容就显式加 *.PNG。

八、保存与多选 #

一个控件覆盖三种模式，靠三个布尔属性组合，这是最容易配出矛盾的地方。

8.1 三个布尔属性的联动 #

素材把关系写得很死：

你设的 连带后果 结果
selectFolder: true selectMultiple 变 false，selectExisting 变 true 只能选一个已存在的目录
selectMultiple: true selectExisting 变 true 只能多选已存在的文件
selectExisting: false selectMultiple 变 false 保存模式，只能给一个名字

第 1、2 条的意思是：这几条不是并列的，是互相覆盖的。同时写 selectFolder: true 和 selectMultiple: true，多选那条被吃掉，最后是选一个目录。素材原文的顺序也很明确：「此属性必须设置为所需的值，然后再打开对话框。」三个都要在 open() 之前设完。

8.2 打开与保存 #

qml
FileDialog {
    id: openDlg
    title: "打开文件"
    selectExisting: true
    selectMultiple: false
    selectFolder: false
    nameFilters: [ "配置文件 (*.json *.ini)", "所有文件 (*)" ]
    onAccepted: root.open(fileUrl)
}

三个布尔写出来虽然正好是默认组合，但读代码的人不用去查默认值。保存改成 selectExisting: false，含义是「允许指定一个不存在的文件名」，文件框会让你输入新名字，覆盖已有文件时弹确认：

qml
FileDialog {
    title: "保存为"
    selectExisting: false
    nameFilters: [ "文本文件 (*.txt)" ]
    onAccepted: root.saveTo(fileUrl)
}

Qt6 换成显式的 fileMode，常用取值就两个：FileDialog.OpenFile 与 FileDialog.SaveFile，默认前者。枚举比三个布尔更好读，用途一眼可见：

qml
FileDialog {
    title: "保存为"
    fileMode: FileDialog.SaveFile
    defaultSuffix: "txt"
    onAccepted: root.saveTo(selectedFile)
}
用途 Qt5 Qt6
打开单个文件 selectExisting: true（默认） fileMode: FileDialog.OpenFile（默认）
保存文件 selectExisting: false fileMode: FileDialog.SaveFile
选目录 selectFolder: true 用 FolderDialog
多选文件 selectMultiple: true 读 selectedFiles，能否多选取决于平台

8.3 多选 #

Qt5 打开 selectMultiple: true，结果读 fileUrls：

qml
FileDialog {
    selectMultiple: true
    nameFilters: [ "图片 (*.png *.jpg *.jpeg)" ]
    onAccepted: {
        for (var i = 0; i < fileUrls.length; ++i)
            root.add(fileUrls[i])
    }
}

读 fileUrls 不是 fileUrl——多选时 fileUrl 只反映其中一个，平台之间还不一致。遍历时用局部变量接长度，别在循环条件里反复读 .length。Qt6 里对应 selectedFiles，多选在原生对话框上是否真的放开取决于平台实现和所用版本，设了没生效先用 console.log(selectedFiles.length) 确认拿到的到底是一个还是多个。

8.4 覆盖确认自己再兜一层 #

原生文件框在保存模式下会问「文件已存在，是否覆盖」，但别把它当唯一防线：有的平台根本不问，用户也会在文件框外面把文件删了又建。

qml
onAccepted: {
    if (root.exists(selectedFile))
        overwriteConfirm.open()
    else
        root.saveTo(selectedFile)
}

这又回到第三章：确认框也是异步的，overwriteConfirm 的 onAccepted 才是真正写盘的地方。异步会传染——一个对话框的结果里再开一个对话框，回调就套一层。

九、原生对话框与自绘对话框 #

到这儿你已经用过两条路：QtQuick.Dialogs 的原生对话框，和 QtQuick.Controls 的 Dialog。选哪条，取决于你在意什么。

9.1 原生那条路拿到了什么 #

ColorDialog、FileDialog 优先用系统实现，白拿这几样：

  • 系统级交互。侧边栏、最近访问、快捷键、路径补全，全是系统给的。
  • 权限流程。沙箱、移动端存储授权，走系统的那一套，你自己写不出来。
  • 平台观感。用户不会觉得这个对话框「不像这个系统的」。

代价也明确：外观不跟你的应用主题走。深色界面弹出一个浅色的系统文件框，这不是 bug，是这条路的设计。另外 title 在部分平台上被忽略，内容区完全不可定制。

9.2 自绘那条路拿到了什么 #

QtQuick.Controls 的 Dialog 是个 Popup，画在你的窗口内部，不是你另开一个顶层窗口。

  • 样式统一。跟你的主题、圆角、字体完全一致。
  • 完全可定制。想放预览图、想加「最近使用」列表、想在中间插一段说明，随便。
  • 可测。它就是个 Item，能拿 objectName 定位，能做界面自动化。

代价是：权限、平台路径规则、系统集成，全得自己处理。做「选文件」这件事，自绘永远做不过系统。

9.3 怎么选 #

场景 选择 理由
取颜色、取文件、取字体 原生（QtQuick.Dialogs） 系统集成与权限白拿
确认删除、保存前提示 自绘（Dialog） 内容要嵌业务信息，样式要统一
表单、设置页 自绘 原生给不了这个布局
嵌入式、无窗口系统 自绘 降级路径本来就是盖一块矩形，不如自己控制

有一条混合策略值得试：文件与颜色走原生，确认与提示走自绘。用户在两个地方看到两套外观，多数人不会在意——他们只在意「能不能选到文件」。

十、Qt5 与 Qt6 的差异 #

Qt6 把 QtQuick.Dialogs 整体重写了，方向是「优先系统原生，去掉 QML 自绘的兜底」。同一段代码从 Qt5 搬到 Qt6，导入行、属性名、模式开关三处都要动。下面这张表按「你原来写的什么，现在改成什么」组织。

项目 Qt5 写法 Qt6 写法
导入 import QtQuick.Dialogs 1.0 import QtQuick.Dialogs（版本号可省）
取色结果 colorDialog.color colorDialog.selectedColor
取色当前值 与结果同为 color color 是当前值，selectedColor 是确认值
单选文件结果 fileDialog.fileUrl fileDialog.selectedFile
多选文件结果 fileDialog.fileUrls fileDialog.selectedFiles
当前目录 fileDialog.folder fileDialog.currentFolder（早期 6.x 仍是 folder）
打开/保存切换 selectExisting: false fileMode: FileDialog.SaveFile
选目录 selectFolder: true FolderDialog（新类型）
多选 selectMultiple: true 读 selectedFiles，多选是否放开依平台
补后缀 自己拼字符串 defaultSuffix: "txt"
QML 自绘兜底 Default*.qml 可改 走系统实现，兜底路径的行为有变
Qt.labs.platform 另一条原生路 已并入 QtQuick.Dialogs

具体某个小版本里哪个属性被弃用、哪个又被加回来，以所用版本为准——Qt6 这条线上对话框模块改动比较频繁，查当前版本的文档比背表可靠。

10.1 迁移三步 #

第一步，改导入行，去掉版本号。第二步，把 fileUrl / fileUrls / color 换成新名字，这一步编译器不帮你，得靠搜索。第三步，把三个布尔换成一个 fileMode，选目录的地方换成 FolderDialog。

改完先跑一遍所有对话框路径，重点看两处：多选还能不能用，title 还显不显示。这两处行为在平台之间差异最大。

10.2 一个容易忽略的行为变化 #

Qt5 那条路上，平台不支持原生对话框时会退到 QML 自绘的 Default*.qml，那是一段你能打开改的 QML。Qt6 里这条路优先系统原生，你在 Qt5 里对 Default*.qml 做过的美化，搬过来之后往往不起作用。当初改过那些文件，迁移前先确认改动是否还有意义；改了没生效，别怀疑配置，就是这条路换了。

十一、自定义对话框的实现 #

原生对话框管不到的需求，用 QtQuick.Controls 的 Dialog 自己搭。它也有 accepted 与 rejected，异步模型和前面完全一致——这一点让人省心，学会一套到处能用。

11.1 一个带确认的自绘对话框 #

qml
import QtQuick
import QtQuick.Controls

Dialog {
    id: confirm
    title: "删除确认"
    modal: true
    anchors.centerIn: Overlay.overlay
    width: 320
    standardButtons: Dialog.Ok | Dialog.Cancel

    property string targetName: ""

    Text {
        text: "确定要删除「" + confirm.targetName + "」吗？此操作不可撤销。"
        wrapMode: Text.WordWrap
    }

    onAccepted: root.remove(confirm.targetName)
    onRejected: root.abort()
}

三个要点：

  • modal: true 只是挡住背后的交互，和原生那条路一样，它不阻塞代码。
  • standardButtons 会给底部自动排好「确定」「取消」，onAccepted / onRejected 就是它俩的回调。
  • 打开用 confirm.open()，不要自己设 visible——Popup 的 open() 里带了过渡和焦点处理。

11.2 结果怎么带出来 #

自绘对话框没有 selectedColor 这种现成属性，结果就是你自己的属性。property string targetName 就是个例子：打开前赋值，onAccepted 里读。

qml
confirm.targetName = "report.txt"
confirm.open()

和 pendingAction 那套是同一个思路，只不过自绘对话框可以把结果放成自己的属性，比全局状态字段干净。

11.3 MessageDialog 的两个版本 #

提一句 MessageDialog，因为名字撞车最厉害：QtQuick.Dialogs 有一个，QtQuick.Controls 也有一个，两者不是同一个类型，属性也不通用。

  • QtQuick.Dialogs 的那个：text、informativeText、detailedText、standardButtons，接 accepted / rejected，走系统观感。
  • QtQuick.Controls 的那个：一个 Popup，样式跟你主题走，适合放在自定义界面里。

导入哪个模块，就拿到哪个。两个都导入了还写 MessageDialog {}，编译器会报类型歧义——用的时候加限定，或者改导入别名。

十二、易错点速查 #

把前面散落的坑收成一张表。出问题时从上往下扫一遍，多数能直接命中。

症状 原因 修法
选完颜色，界面慢一拍才变 在 open() 下一行读了结果 挪进 onAccepted
点取消后按钮一直是禁用状态 只接了 accepted 补 onRejected，复位状态
取消后程序卡在「等待中」 用 close() 当取消，信号没发 走会发 rejected 的路径
文件框总从用户目录开始 没设 folder 打开前赋上次的目录
设了默认过滤器没生效 字符串和 nameFilters 差一个字符 逐字符对齐
多选只拿到一个文件 读了 fileUrl 读 fileUrls / selectedFiles
保存模式弹成了打开模式 selectExisting 没设 显式 selectExisting: false 或 fileMode
保存出来的文件没有后缀 没设 defaultSuffix 补 defaultSuffix: "txt"
直接拿 fileUrl 当路径用 它是 url，带 file:/// 转本地路径
深色界面里对话框是浅色的 原生对话框不跟应用主题 换自绘 Dialog，或接受它
macOS 上取色器挡不住主窗口 平台只允许非模态取色器 别假设它会挡
从 Qt5 搬到 Qt6 后属性报 undefined 属性改名了 查第十章对照表

最后一条原则：对话框这条路，永远不要在 open() 之后写依赖结果的代码。要连着做两件事，就把第二件事写成第一件事的 onAccepted 里的一次调用。
