本篇只讲 QML 中用来「显示文字」的两个元素：Text 与 Label。范围包含两者的属性差异、字体字号、颜色与特效、换行与省略号、富文本边界、对齐与行高、控件样式跟随、长文本滚动、动态绑定刷新、渲染开销。不涉及用户输入类元素（TextInput、TextEdit、TextArea），不涉及自定义字体加载的完整流程。控件整体结构见同目录《三大模块》一篇，容器排布见《布局》一篇，鼠标与点击响应见《按钮与鼠标》一篇。

一、 Text 与 Label 的分工 #

先把身份分清楚，后面所有属性讨论都建立在这个前提上。

Text 属于 QtQuick 模块，是一个直接继承 Item 的基础可视元素。它只做一件事：把字符串画到场景里。它没有样式系统，没有主题，没有默认间距，颜色和字号不给就按平台默认字体来。

Label 属于 QtQuick.Controls 模块，是一个控件。在 Controls 1 里它直接继承 Text；在 Controls 2 里它是 Control 加一套文本模板的组合，但对外暴露的属性名和 Text 基本对齐。它多出来的能力是跟随控件样式：主题规定的文字颜色、主题规定的默认字号、主题切换时自动重绘。

一句话对照：

  • Text 是「我自己决定长什么样」。
  • Label 是「主题决定我长什么样，我只负责内容」。

1.1 对照表 #

维度 Text Label
所属模块 QtQuick QtQuick.Controls
导入写法 import QtQuick 2.15 import QtQuick.Controls 2.15
基类 Item Control（Controls 2）/ Text（Controls 1）
默认文字颜色 黑色（不随主题） 跟随主题，深色主题下自动变白
默认字号 平台默认字体 主题规定的控件字号
主题切换响应 无 自动重绘
font.* / elide / wrapMode 原生属性 同名属性，语义一致
渲染开销 低 略高（多一层 Control 包装与内边距计算）
典型场景 纯视觉文字、图表标注、游戏 UI、自定义绘制 表单标签、列表项标题、按钮内部文字、设置页说明
可否放子元素 可以，但文字会盖在子元素上 可以，同样按绘制顺序

1.2 选型规则 #

界面主体是 Controls 搭的（ApplicationWindow + Page + Button + TextField），标签文字一律用 Label。你换了 Material 深色主题，Label 自己变白，Text 还是黑的，得手动改。

界面是纯 Quick 手绘的（Canvas、自定义 Item 拼装、游戏 HUD），或者文字只是视觉装饰，用 Text。少一层 Control，少一次样式查询。

混用也常见：Controls 界面里放一块自己画的图表，图表内部的坐标轴文字用 Text 更快更省。判断标准不是「哪个更高级」，而是「这行字要不要吃主题」。

1.3 两段等价代码 #

用 Text 写：

qml
import QtQuick 2.15

Text {
    text: "用户名"
    color: "#333333"
    font.pixelSize: 14
}

用 Label 写同一件事：

qml
import QtQuick.Controls 2.15

Label {
    text: "用户名"
    font.pixelSize: 14
}

第二段没写 color。这就是差别：主题给了默认色，你不写也正确；第一段不写 color 就是纯黑，深色背景下直接看不见。

二、 Text 的常用属性 #

Text 的属性分四组：内容、外观、排版、状态。先把全景铺开，后面几章逐组展开。

2.1 属性总表 #

属性 类型 作用 备注
text string 要显示的字符串 支持 \n 硬换行
color color 文字颜色 十六进制或 SVG 颜色名
font font 复合字体属性组 用 font.xxx 逐项设置
style enumeration 文字特效 Text.Normal / Outline / Raised / Sunken
styleColor color 特效辅助色 只对非 Normal 生效
horizontalAlignment enumeration 水平对齐 AlignLeft / AlignRight / AlignHCenter / AlignJustify
verticalAlignment enumeration 垂直对齐 AlignTop / AlignBottom / AlignVCenter
wrapMode enumeration 换行策略 默认 NoWrap
elide enumeration 省略号位置 默认 ElideNone
maximumLineCount int 最多显示几行 配合 elide 才有省略效果
textFormat enumeration 解析格式 默认 AutoText
clip bool 超出边界硬裁剪 与 elide 是两种思路
lineHeight real 行高倍数 默认 1.0
lineHeightMode enumeration 行高计算方式 ProportionalHeight / FixedHeight
fontSizeMode enumeration 字号自适应缩放 默认 FixedSize
minimumPixelSize int 缩放像素下限 配合 fontSizeMode
minimumPointSize int 缩放点值下限 配合 fontSizeMode
baseUrl url 相对资源基准路径 影响图片、链接解析
linkColor color 超链接颜色 富文本下生效

2.2 只读状态属性 #

这几个属性不能赋值，但能读出来做判断，做自适应布局时很有用。

属性 类型 含义
lineCount int 排版后实际占用的行数
truncated bool 内容是否被省略号截断过
contentWidth real 文本实际需要的宽度
contentHeight real 文本实际需要的高度
effectiveHorizontalAlignment enumeration 最终生效的水平对齐（含 RTL 修正）

truncated 值得单独记一下：它让你能判断「这行字被吃掉了」，从而挂一个「展开全文」按钮。判断条件写成 visible: label.truncated 就够了，不用自己比字符串长度。

2.3 两个交互信号 #

信号 参数 触发时机
onLineLaidOut line 排版引擎算出每一行几何位置时
onLinkActivated link 点击富文本中的 <a href> 链接时

onLineLaidOut 每行触发一次，可以在里面改 line.x、line.width，做首行缩进、漏斗形排版这类型效果。onLinkActivated 只传链接字符串，打开浏览器要自己调 Qt.openUrlExternally(link)。这两块在第六、七章展开。

2.4 最小可用示例 #

qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 360
    height: 120
    visible: true

    Text {
        anchors.centerIn: parent
        text: "用户名"
        color: "#333333"
        font.pixelSize: 14
    }
}

width / height 都没写。Text 会按内容的 implicitWidth、implicitHeight 自动撑开，直接居中就对。只有在你需要限制宽度做换行或省略时，才该显式给 width。

三、 字体与字号 #

font 是复合属性。可以整体赋值一个 Qt.font({...}) 对象，也可以逐项写 font.pixelSize。逐项写更好读，冲突时以最后赋值为准。

3.1 字体属性组 #

属性 类型 说明
font.family string 字体家族名，不区分大小写，如 "Helvetica"、"微软雅黑"
font.pointSize real 以点为单位设字号，与设备像素比无关
font.pixelSize int 以像素为单位设字号，直接对应屏幕像素
font.bold bool 加粗，等价于 weight: Font.Bold
font.italic bool 倾斜
font.underline bool 下划线
font.strikeout bool 删除线
font.weight enumeration 字重级别，比 bold 更细
font.letterSpacing real 字符间距，正数拉伸、负数收缩
font.wordSpacing real 单词间距，只对空格分隔的文本起作用
font.capitalization enumeration 大小写转换策略

六个布尔与数值属性一次看完：

qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 300
    height: 250
    visible: true

    Column {
        anchors.centerIn: parent
        spacing: 8

        Text { text: "普通文本"; color: "blue" }
        Text { text: "指定字体 (Helvetica)"; font.family: "Helvetica" }
        Text { text: "斜体文本"; font.italic: true }
        Text { text: "删除线文本"; font.strikeout: true }
        Text { text: "下划线文本"; font.underline: true }
        Text { text: "加粗文本"; font.bold: true }
        Text { text: "像素大小字号 (16px)"; font.pixelSize: 16 }
        Text { text: "点大小字号 (16pt)"; font.pointSize: 16 }
    }
}

3.2 pointSize 与 pixelSize 怎么选 #

pixelSize 是物理像素数，写死 16 就是 16 个像素高。pointSize 是排版点，换算时会乘上 DPI 缩放。同一段代码拿到 4K 屏上，pixelSize: 16 的字会显得很小，pointSize: 16 会跟着系统缩放变大。

桌面应用优先 pointSize。要求像素级精确对齐（自绘图标旁边配文字、刻度标签）时用 pixelSize。

两个都写时，后写的覆盖前面的：

qml
Text {
    text: "谁生效"
    font.pixelSize: 20
    font.pointSize: 10   // 这一行生效，前面的 pixelSize 被清掉
}

别在同一处混写两套单位，阅读成本高，还容易出「改了没反应」的错觉。

3.3 字重五档 #

bold: true 只有粗和不粗两档。要更细的控制用 font.weight。

qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 300
    height: 200
    visible: true

    Column {
        anchors.centerIn: parent
        spacing: 10

        Text { text: "Font.Light - 细体"; font.weight: Font.Light }
        Text { text: "Font.Normal - 常规"; font.weight: Font.Normal }
        Text { text: "Font.DemiBold - 半粗"; font.weight: Font.DemiBold }
        Text { text: "Font.Bold - 粗体"; font.weight: Font.Bold }
        Text { text: "Font.Black - 极粗"; font.weight: Font.Black }
    }
}

字重能不能看出差别，取决于字体文件本身有没有这么多字重。系统字体只装了一个 Regular 时，Light 和 Black 画出来一样，引擎不会伪造。要么换带全套字重的字体，要么接受降级。

3.4 大小写转换 #

font.capitalization 只改渲染，不改 text 的值。绑定的数据还是原样，做逻辑时拿到的也是原样。

qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 300
    height: 220
    visible: true

    Column {
        anchors.centerIn: parent
        spacing: 10

        Text { text: "Hello World"; font.pointSize: 16; font.capitalization: Font.MixedCase }
        Text { text: "Hello World"; font.pointSize: 16; font.capitalization: Font.AllUppercase }
        Text { text: "Hello World"; font.pointSize: 16; font.capitalization: Font.AllLowercase }
        Text { text: "Hello World"; font.pointSize: 16; font.capitalization: Font.SmallCaps }
        Text { text: "hello world"; font.pointSize: 16; font.capitalization: Font.Capitalize }
    }
}

五档含义：

取值 效果
Font.MixedCase 默认，不改动
Font.AllUppercase 全部转大写
Font.AllLowercase 全部转小写
Font.SmallCaps 小号大写字母（原本的小写字母用小字号的大写形态）
Font.Capitalize 每个单词首字母大写

Font.SmallCaps 依赖字体是否支持，字体不提供小型大写字母时表现接近全大写。中文没有大小写概念，这五个值对中文文本无效。

3.5 字符间距与单词间距 #

  • font.letterSpacing 控制单个字符之间的物理间距。
  • font.wordSpacing 控制以空格分隔的单词之间的间距。
qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 450
    height: 200
    visible: true

    Column {
        anchors.centerIn: parent
        spacing: 15

        Text { text: "Hello World (默认间距)"; font.pointSize: 16 }

        Text {
            text: "Hello World"
            font.pointSize: 16
            font.letterSpacing: 30
        }

        Text {
            text: "Hello World"
            font.pointSize: 16
            font.wordSpacing: 30
        }
    }
}

letterSpacing: 30 是 30 个像素，不是 30 倍。字号 16 配 30 像素间距，字会散成一串独立符号。做标题字距时给 1 到 3 就够。

wordSpacing 对中文几乎没用，中文句子不以空格分词。想给中文加字距，还是用 letterSpacing。

3.6 字号自适应缩放 #

框子尺寸固定、内容长度不定时，可以交给 fontSizeMode 自动缩字号。

取值 行为
Text.FixedSize 默认。字号完全由 pointSize / pixelSize 决定，装不下就溢出
Text.HorizontalFit 宽度不够时缩字号，保证单行完整显示
Text.VerticalFit 高度不够时缩字号，保证竖向完整显示
Text.Fit 宽高任一不够都缩

必须配 minimumPixelSize 或 minimumPointSize 一起用。不设下限，长文本会把字号缩到 1px，肉眼看见的是一片灰线。

qml
Rectangle {
    width: 120
    height: 40
    color: "#f0f0f0"

    Text {
        anchors.fill: parent
        anchors.margins: 4
        text: "设备名称很长很长"
        font.pointSize: 16
        fontSizeMode: Text.HorizontalFit
        minimumPointSize: 8
        horizontalAlignment: Text.AlignHCenter
        verticalAlignment: Text.AlignVCenter
    }
}

自适应在每次文本或尺寸变化时都要重新算字号，是逐级试探的过程，开销比固定字号高。只在确实需要的少数元素上用，别全局开着。

四、 颜色与样式 #

4.1 color 的几种写法 #

color 是 color 类型，不是字符串。下面这些写法都能用：

写法 示例 说明
十六进制 RGB "#00FF00" 纯绿
十六进制 ARGB "#8000FF00" 带 50% 透明度
SVG 颜色名 "steelblue"、"red" 不区分大小写
函数构造 Qt.rgba(0.2, 0.6, 0.9, 1.0) 分量都是 0 到 1 的浮点
透明 "transparent" 等于全透明

把 color 设成 "transparent" 不会让元素不占位，字仍然参与排版，只是看不见。想隐藏用 visible: false，隐藏后连布局都不占。这两件事在布局里后果完全不同。

4.2 文字特效 style #

style 给文字加描边、投影、浮雕。适合游戏 UI、大屏看板这类要「立起来」的场景。

取值 效果 styleColor 的作用
Text.Normal 默认，无特效 无效
Text.Outline 沿字轮廓描边 描边颜色
Text.Raised 右下投影，看起来凸起 投影颜色
Text.Sunken 左上投影，看起来凹陷 投影颜色 
qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 300
    height: 220
    visible: true

    Column {
        anchors.centerIn: parent
        spacing: 12

        Text {
            text: "Normal Style"
            font.pointSize: 20
            style: Text.Normal
        }
        Text {
            text: "Outline Style"
            font.pointSize: 20
            style: Text.Outline
            styleColor: "red"
        }
        Text {
            text: "Raised Style"
            font.pointSize: 20
            style: Text.Raised
            styleColor: "green"
        }
        Text {
            text: "Sunken Style"
            font.pointSize: 20
            style: Text.Sunken
            styleColor: "blue"
        }
    }
}

描边和投影是额外的一次或两次绘制。一个元素上开了特效，渲染成本至少翻倍；整屏几十个带特效的文字滚动时，帧率会掉。特效适合标题，不适合列表内容。

styleColor 单独写、不配 style 时完全不生效，这是新手最常见的无效配置。

4.3 clip 硬裁剪 #

clip: true 把超出元素边界的内容直接切掉，不留任何提示。

qml
Rectangle {
    width: 60
    height: 30
    color: "#eeeeee"

    Text {
        anchors.verticalCenter: parent.verticalCenter
        text: "abcdefghijklmnopqrstuvwxyz"
        font.pointSize: 16
        clip: true
    }
}

注意 clip 的裁剪边界是元素自己的 width / height。Text 没显式给宽高时，宽高就是内容尺寸，裁剪框和文字一样大，clip: true 看不出任何效果。裁剪要生效，先给一个比内容小的框。

五、 换行、截断与省略 #

这一章是 Text 最容易踩坑的地方。三个属性各管一段，配合起来才有想要的结果。

5.1 elide：省略号放哪 #

取值 说明 效果示意
Text.ElideNone 默认，不加省略号 Hello World! 被切断
Text.ElideLeft 省略号在左 ...lo World!
Text.ElideMiddle 省略号在中间 Hello...orld!
Text.ElideRight 省略号在右 Hello Wor...

两个前提，缺一不可：

  1. 元素要有明确且小于内容宽度的 width。
  2. 文本不是富文本（textFormat 为 RichText / StyledText 时 elide 无效）。

第一条是硬规则。只写 elide: Text.ElideRight 不给 width，Text 的宽度会跟着内容长，永远不存在「超出」，省略号一次都不会出现。

5.2 wrapMode：怎么断行 #

取值 行为
Text.NoWrap 默认。不换行，遇到 \n 才断，其余一直向右延伸
Text.WordWrap 在单词边界换行。单个单词超宽时该词仍会溢出
Text.WrapAnywhere 到边界就断，不管是不是单词中间
Text.Wrap 优先按单词断，单词本身超宽时在词内强制断开

WordWrap 和 Wrap 的区别就在超长单词上。英文 URL、没有空格的长串用 WordWrap 会直接捅出容器，用 Wrap 才安全。中文每字都是断点，WordWrap 和 Wrap 表现一致。

wrapMode 一旦不是 NoWrap，Text 的高度就跟着行数长。父容器不给高度限制，它会一直长下去，撑破界面。

5.3 maximumLineCount：最多几行 #

maximumLineCount 限制排版的可见行数，超出的行不画。单独用它只是「少画几行」，内容被生硬地砍断，没有省略号。它必须和 elide 一起用。

5.4 三者配合：做「最多两行，超出省略」 #

qml
Text {
    width: 200
    text: "Qt Quick 提供了一套声明式界面描述方式，文本元素在其中承担最基础的显示职责。"
    wrapMode: Text.WordWrap
    maximumLineCount: 2
    elide: Text.ElideRight
}

三个属性的分工：

属性 管什么 不设的后果
wrapMode 怎么断行 全挤一行，向右溢出
maximumLineCount 最多显示几行 行数无限增长，永远不「超出」
elide 截断处怎么标 最后一行被硬切，看不出还有内容

再加上 width 这个前提。四件事齐了，两行加省略号才出来。

5.5 完整对照实验 #

同一段长文本，六种配置的渲染差异：

qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 400
    height: 320
    visible: true

    Column {
        anchors.centerIn: parent
        spacing: 15

        // A. 关闭裁剪：文字越过 50px 限制溢出显示
        Text {
            text: "abcdefghijklmnopqrstuvwxyz"
            width: 50
            clip: false
            font.pointSize: 16
        }

        // B. 开启裁剪：超出 50px 的部分被强行隐藏
        Text {
            text: "abcdefghijklmnopqrstuvwxyz"
            width: 50
            clip: true
            font.pointSize: 16
        }

        // C. 不省略：默认状态
        Text {
            text: "abcdefghijklmnopqrstuvwxyz"
            width: 50
            font.pointSize: 16
            elide: Text.ElideNone
        }

        // D. 左侧省略：...xyz
        Text {
            text: "abcdefghijklmnopqrstuvwxyz"
            width: 50
            font.pointSize: 16
            elide: Text.ElideLeft
        }

        // E. 中间省略：ab...yz
        Text {
            text: "abcdefghijklmnopqrstuvwxyz"
            width: 50
            font.pointSize: 16
            elide: Text.ElideMiddle
        }

        // F. 右侧省略：abc...
        Text {
            text: "abcdefghijklmnopqrstuvwxyz"
            width: 50
            font.pointSize: 16
            elide: Text.ElideRight
        }
    }
}

clip 和 elide 是两条完全不同的路。clip 是硬切，边缘会切在字母的半边，用户不知道后面还有；elide 是礼貌地告诉用户「后面还有」。给人看的文本用 elide，装饰性图形里的文字用 clip。

5.6 用 truncated 做「展开全文」 #

truncated 在内容被省略时变 true，配合它挂按钮最省事：

qml
Column {
    width: 200

    Text {
        id: body
        width: parent.width
        text: "很长的一段说明文字，超出两行就省略。"
        wrapMode: Text.WordWrap
        maximumLineCount: 2
        elide: Text.ElideRight
    }

    Text {
        text: body.truncated ? "展开" : ""
        color: "#2a6fdb"
        visible: body.truncated
    }
}

六、 富文本与 HTML 子集 #

6.1 textFormat 四个取值 #

取值 解析方式 适用
Text.AutoText 默认。用 Qt::mightBeRichText() 快速探测是否含标签，含则按富文本走 内容来源不确定时
Text.PlainText 全部当纯文本，<b> 原样打印 用户输入、日志、代码片段
Text.StyledText 支持 HTML 3.2 的子集标记，嵌套要求严格 简单的粗体、斜体、颜色、链接
Text.RichText 支持更完整的 HTML 4 标记 排版复杂的说明文字

AutoText 的探测是启发式的：字符串里出现 < 和 > 配对，就会被当成标签。所以显示用户输入的内容必须显式写 textFormat: Text.PlainText，否则用户打一行 <b>hi</b> 就会变成粗体，严重的还会被当成注入。

6.2 富文本的能力边界 #

RichText 不是浏览器。它背后是 Qt 自己的富文本引擎，只认 HTML 的一个子集。

能用的：

  • 字符样式：<b>、<i>、<u>、<s>、<font color size face>
  • 段落：<p>、<br>、<center>、<h1> 到 <h6>
  • 列表：<ul>、<ol>、<li>
  • 链接：<a href="...">
  • 图片：<img src="..." width="..." height="...">
  • 表格：基础的 <table>、<tr>、<td>，不支持合并单元格的复杂布局
  • style 属性里的少量 CSS：color、background-color、font-size、font-family、text-decoration

不能用的：

  • 外部 CSS 文件、<style> 块里的大部分选择器
  • float、flex、grid 这类布局属性
  • 伪类、动画、position
  • JavaScript

指望用一个 Text 做图文环绕、多列排版，做不到。复杂排版拆成多个 Text 加布局容器拼，每个 Text 只负责自己那一段。

StyledText 是更小的子集，主要就 <b>、<i>、<u>、<font>、<a>、<br> 这几个。它对嵌套闭合的要求很严，少一个 </b>，整段会退回纯文本显示，标签原样露出来。

6.3 富文本里的图片 #

qml
Text {
    width: 300
    wrapMode: Text.WordWrap
    textFormat: Text.RichText
    text: "状态：<img src='qrc:/icons/ok.png' width='16' height='16'> 已通过"
}

图片路径按 baseUrl 解析。baseUrl 不设时用 QML 文件所在目录。qrc: 开头的绝对路径不受影响。

width / height 建议都写。只写一个，另一边按原始比例算；两个都不写，图片按原始像素撑开，很容易把行高顶到几十像素。

6.4 链接点击 #

富文本里的 <a href> 不会自己打开浏览器。要在 onLinkActivated 里处理。

qml
import QtQuick 2.15
import QtQuick.Window 2.15

Window {
    width: 350
    height: 150
    visible: true

    Text {
        anchors.centerIn: parent
        font.pointSize: 16
        textFormat: Text.RichText
        text: "请访问 <a href='http://qt-project.org'>Qt 官方网站</a>。"

        onLinkActivated: {
            console.log("检测到链接点击: " + link)
            Qt.openUrlExternally(link)
        }
    }
}

link 参数就是 href 里的字符串。Qt.openUrlExternally() 交给系统默认程序处理，是安全做法；自己拼 Process 或 cmd 命令执行 URL，等于把手伸进系统命令层。

linkColor 单独控制链接颜色，不设时用主题的链接色。鼠标悬停不会自动变手型，需要自己在 MouseArea 里设 cursorShape: Qt.PointingHandCursor。

6.5 性能选型 #

RichText 会启动完整的富文本解析排版引擎，每个文本元素都要建文档结构、跑布局。列表、滚动视图这类高频创建销毁的场景，几百个 RichText 元素能把界面卡住。

选型顺序：能 PlainText 就 PlainText；只需要粗体斜体就 StyledText；实在要复杂排版才上 RichText。动态内容频繁刷新的元素，优先 PlainText。

七、 文本对齐与行高 #

7.1 水平与垂直对齐 #

属性 取值 说明
horizontalAlignment Text.AlignLeft 左对齐，默认
Text.AlignRight 右对齐
Text.AlignHCenter 水平居中
Text.AlignJustify 两端对齐，只对多行生效，最后一行不拉伸
verticalAlignment Text.AlignTop 顶部对齐，默认
Text.AlignBottom 底部对齐
Text.AlignVCenter 垂直居中

对齐生效的前提是元素比内容大。Text 没给 width 时宽度等于内容宽度，左对齐和右对齐画出来一模一样；没给 height 时垂直对齐也没有可分配的余量。

qml
Rectangle {
    width: 200
    height: 80
    color: "#f5f5f5"

    Text {
        anchors.fill: parent
        text: "居中的一段说明"
        horizontalAlignment: Text.AlignHCenter
        verticalAlignment: Text.AlignVCenter
    }
}

alignJustify 处理英文长段落时，行内单词间距会被拉伸到等宽；中文两端对齐看起来和左对齐接近，因为中文本身字距均匀。

effectiveHorizontalAlignment 是只读属性，返回包含书写方向修正后的实际对齐值。做阿拉伯语、希伯来语这类 RTL 界面时读它，不要读 horizontalAlignment。

7.2 行高 #

属性 取值 说明
lineHeight real 行高数值，默认 1.0
lineHeightMode Text.ProportionalHeight 默认。lineHeight 是当前字号的倍数
Text.FixedHeight lineHeight 是固定像素值 
qml
Text {
    width: 240
    text: "行高 1.0 的效果\n行高 1.6 的效果\n行高 1.6 的效果"
    wrapMode: Text.WordWrap
    lineHeight: 1.6
    lineHeightMode: Text.ProportionalHeight
}

正文行高给 1.4 到 1.6 之间比较舒服。lineHeight 小于 1 时上下行会重叠，中文字形有下伸部分，1.2 以下就糊了。

FixedHeight 模式配 lineHeight 一个大于字号的像素值，做固定行距的表格打印效果。

7.3 onLineLaidOut 干预排版 #

onLineLaidOut 在排版引擎算出每行几何位置时触发，每行一次。参数 line 有 number、x、y、width、height，改 x 和 width 就能重排这一行。

qml
Text {
    width: 300
    text: "QML is a declarative language used to design user interface-centric applications. This is a paragraph layout demonstration."
    wrapMode: Text.WordWrap

    // 前 3 行整体右移 30 像素，并收窄同样的宽度
    onLineLaidOut: {
        if (line.number < 3) {
            line.x = line.x + 30
            line.width = line.width - 30
        }
    }
}

改 x 必须同时改 width，否则行尾会顶出元素边界被截断。这个信号的调用很频繁，里面只做算术，别翻数据、别建对象。

用它做首行缩进、阶梯式排版、漏斗形标题都行。line.number 从 0 开始。

八、 Label 与 Controls 样式体系 #

8.1 最小用法 #

qml
import QtQuick.Controls 2.15

Label {
    text: "Hello world"
}

就这一行，字号、颜色、行高全部来自主题。换 Material 深色主题，它自己变成浅色字。

8.2 用 Text 那套属性改外观 #

Label 暴露的属性和 Text 对齐，照样能逐项覆盖：

qml
Label {
    text: "Hello world"
    font.pixelSize: 22
    font.italic: true
    color: "steelblue"
}

一旦显式写了 color，主题就不再管这行字的颜色。深色主题切换时它保持 steelblue，不会自动变。要保留主题跟随，就别写 color。

8.3 继承关系与成员 #

Controls 1 里 Label 直接继承 Text，属性表就是 Text 的全文，加上 Item 的基础成员。Controls 2 里它是 Control，属性通过模板转发，名字保持兼容。

Label 上可用的、来自 Text 语义的成员：

类别 成员
内容 text、textFormat、baseUrl、linkColor
颜色与特效 color、style、styleColor
字体 font.family、font.pointSize、font.pixelSize、font.bold、font.italic、font.underline、font.strikeout、font.weight、font.capitalization、font.letterSpacing、font.wordSpacing
排版 horizontalAlignment、verticalAlignment、effectiveHorizontalAlignment、wrapMode、elide、maximumLineCount、lineHeight、lineHeightMode
字号自适应 fontSizeMode、minimumPixelSize、minimumPointSize
裁剪 clip
只读状态 lineCount、truncated、contentWidth、contentHeight
信号 onLineLaidOut、onLinkActivated

Label 额外带 Control 那一层的成员：padding、leftPadding、rightPadding、topPadding、bottomPadding、background、contentItem、font、palette、enabled、hovered、focusPolicy。

background 在 Label 上默认是空。想给文字加个底色块，自己塞一个 Rectangle：

qml
Label {
    text: "标签"
    padding: 8
    background: Rectangle {
        color: "#e8f0fe"
        radius: 4
    }
}

padding 只在有 background 或参与 Control 布局计算时看得出效果。Label 的 implicitWidth 会把 padding 算进去。

8.4 palette 与主题色 #

Label 的文字颜色来自 palette.windowText。想批量改一组标签的颜色，改父级的 palette：

qml
Column {
    palette.windowText: "#666666"

    Label { text: "第一项" }
    Label { text: "第二项" }
}

在 Controls 2 里 palette 会沿控件树向下继承。给 ApplicationWindow 设一次，全局生效。

注意 palette 的传播只对没显式写 color 的 Label 起作用。写了 color 的那一个就脱离了调色板。

8.5 Controls 1 与 Controls 2 的差异 #

项目 Controls 1 Controls 2
基类 直接继承 Text 继承 Control
默认颜色来源 系统调色板 QPalette Qt Quick Controls 2 样式
样式切换 依赖 QStyle 换 Material / Universal 等风格即可
elide / maximumLineCount 原生支持 支持，个别版本对富文本组合有差异
主题定制 改 QPalette 或用 SystemPalette 改 palette 或自定义 background / contentItem

新工程直接用 Controls 2。Controls 1 只在维护老项目时才会碰到，它的文档里 Label 定位是「位于 QtQuick.Controls 1.0，继承于 Text」的文本标签。

8.6 Label 的常见误用 #

  • 给 Label 设 width 后忘了设 elide：文字被硬切，没有省略号。
  • 给 Label 设 color，又期望深色主题自动适配：颜色被写死，主题失效。
  • 用 Label 当富文本容器，elide 不生效还找不到原因：富文本下 elide 无效。
  • 在 Label 里放大量子元素：Label 是控件不是容器，子元素会盖在文字上，层级不可控。

九、 长文本与滚动 #

Text 本身不滚动。文本超过元素高度时，要么被裁掉，要么撑破父级。要滚动只能外面套容器。

9.1 Flickable + Text #

qml
import QtQuick 2.15

Flickable {
    width: 320
    height: 200
    clip: true
    contentWidth: width
    contentHeight: body.implicitHeight
    flickableDirection: Flickable.VerticalFlick

    Text {
        id: body
        width: parent.width
        text: "很长的说明文字……"
        wrapMode: Text.WordWrap
    }
}

关键是 contentHeight: body.implicitHeight。Text 开了换行后 implicitHeight 就是排版后的真实高度，绑给它，滚动范围才对。

contentWidth: width 配合 Text 的 width: parent.width，保证文本宽度跟着可视区走，不会出现横向滚动条。

Flickable 自己不会裁剪，不加 clip: true 内容会画到容器外面。

9.2 ScrollView 包起来 #

qml
import QtQuick 2.15
import QtQuick.Controls 2.15

ScrollView {
    width: 320
    height: 200
    clip: true

    Label {
        width: parent.width
        text: "很长的说明文字……"
        wrapMode: Text.WordWrap
    }
}

ScrollView 的 contentWidth / contentHeight 会自动跟着唯一子项的 implicitWidth / implicitHeight 走，比自己算省事。子项必须有确定的宽度，否则换行算不出来，高度是错的。

9.3 长文本的渲染代价 #

滚动区里放一个几千字的 Text，每次滚动只是平移纹理，代价不大。真正贵的是文本内容变化：改一次 text，整段重新排版。滚动视图里频繁改文本，帧率会掉。

要可编辑的多行长文本，用 TextArea，它在 ScrollView 里能自动撑高。TextArea 属于输入类元素，这篇不展开。

9.4 分页与按需渲染 #

文本量到几万字，一次性排版会明显卡顿。做法是拆段：每段一个 Text，放进 ListView，靠 delegate 的复用按需创建。这样只有可视区附近的段落被排版。

拆段时每段保留自己的 wrapMode 和 width，不要指望父容器统一换行——Text 不跨元素延续排版状态。

十、 动态文本与绑定 #

text 是普通可绑定属性，表达式里用到什么，什么变了它就重算。

qml
Column {
    property int count: 0

    Text { text: "当前共 " + count + " 条" }
    Text { text: "剩余 " + (100 - count) + " 条" }
}

改 count 就刷新两处。拼接用 +，跨 Qt 版本都稳；模板字符串在部分老版本 QML 引擎里不认，别用。

10.1 绑定被打断后用 Qt.binding 恢复 #

命令式赋值会把绑定拆掉。onClicked: tip.text = "已提交" 之后，再改数据源，tip 不再跟着变。要恢复绑定：

qml
Label {
    id: tip
    text: "就绪"
}

Button {
    onClicked: tip.text = Qt.binding(function() { return "共 " + model.count + " 条" })
}

10.2 C++ 侧推送 #

Q_PROPERTY 必须带 NOTIFY 信号，属性变化才会推到 QML。没有 NOTIFY 的属性只在初始化时读一次。

10.3 宽度变化会触发重算 #

implicitHeight、truncated、lineCount 都依赖当前宽度。父容器宽度变了，它们跟着变，绑定它们的表达式重新求值。拿它们做高度动画时，留意别形成「改高度 → 改宽度 → 改高度」的循环。

十一、 性能与渲染注意点 #

  • 格式取最轻的：PlainText > StyledText > RichText。
  • 特效少开：style 非 Normal 时每帧多一次绘制，标题用，正文别用。
  • 隐藏用 visible: false，不要用 color: "transparent"，后者照样排版。
  • 长列表把文本放进 ListView 的 delegate，靠复用避免重复创建。
  • layer.enabled: true 会把文本渲染到离屏纹理，文字本身变化频繁时反而更慢。
  • 文本按秒级刷新（计时器、进度）时，先判断值是否真的变了，直接赋值同值也会触发重排。

十二、 易错点速查 #

现象 原因 处理
省略号不出现 没给 width，宽度随内容长 显式设宽度
省略号仍不出现 textFormat 是富文本 改 PlainText 或拆段
只显示一行没省略 缺 maximumLineCount 加行数限制
文字被硬切、边缘缺半字 用了 clip 而不是 elide 换 elide
文字溢出容器 wrapMode 是 NoWrap 改 WordWrap 或 Wrap
行数不增长、文字重叠 父容器高度写死 高度绑 implicitHeight
对齐没反应 元素宽高等于内容大小 给 width / height
深色主题下字看不见 用了 Text 且没设 color 换 Label 或绑 palette
切主题后颜色不变 Label 上写死了 color 删掉 color，走 palette
用户输入被当标签渲染 AutoText 自动探测 显式 PlainText
styleColor 无效 没配 style 加上 style: Text.Outline
字号缩到看不见 fontSizeMode 没设下限 加 minimumPointSize
中文行距发糊 lineHeight 低于 1.2 提到 1.4 到 1.6
链接点了没反应 没接 onLinkActivated 调 Qt.openUrlExternally(link)

排查顺序固定：先看宽度，再看 wrapMode 和行数上限，最后看 textFormat。文本显示问题九成出在这三处。
