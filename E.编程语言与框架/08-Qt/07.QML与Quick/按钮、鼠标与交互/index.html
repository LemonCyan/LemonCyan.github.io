这篇讲交互的两条腿：看得见的按钮，摸得着的指针。Button 管外观和状态机，MouseArea 管把点击翻译成信号，cursorShape 管鼠标指针长什么样。三样东西各管一段，混着用就会出事。

讲什么：QtQuick.Controls 里 Button 的属性、信号、可切换状态、用 background 与 contentItem 改样式；MouseArea 的按钮过滤、事件穿透、悬停判定；Qt::CursorShape 枚举与自定义光标。

不讲什么：控件库内部实现、C++ 侧的自绘委托、Qt Quick 3D 的拾取、完整手势框架。

指路：import 与窗口骨架见《QML 与 Qt Quick 入门》；Row、Column、anchors 见《布局》；按下与悬停的视觉过渡见《动画》；Dialog 与按钮盒见《对话框》。

一、Button 与 Controls 2 #

Button 不在 QtQuick 基础模块里。它属于 QtQuick.Controls。你写 import QtQuick 2.15 之后随手敲 Button {}，报「Button is not a type」，不是拼写错了，是模块没引。

两行 import 摆平：

qml
import QtQuick 2.15
import QtQuick.Controls 2.15

Button {
    text: "Send"
    onClicked: console.log("send")
}

这四行能跑，是因为 Button 自带一套默认外观。文字、背景、按下变深、悬停高亮、获得焦点时的虚框，全在控件内部做好了。

Button 的来路 #

Button 继承 AbstractButton，AbstractButton 继承 Control，Control 继承 Item。

这条链决定了它能干什么：

层级 给出的能力
Item width、height、anchors、visible、opacity、事件坐标
Control padding、background 委托、contentItem 委托、implicitWidth、font、availableWidth
AbstractButton text、checkable、checked、pressed、hovered、down、icon、clicked 等信号
Button 默认的 background 与 contentItem 实现，一个拿来就能显示的按钮

Button 不是 Rectangle 的子类，也不是 MouseArea 的包装。它自己处理鼠标、自己画背景、自己维护状态。

Controls 1 和 Controls 2 是两套东西 #

老教程里写 import QtQuick.Controls 1.4、写 ButtonStyle、写 style: ButtonStyle {...}，那是 Controls 1。Controls 2 把样式系统整个换掉了，style 属性没了，换成了两个委托 background 和 contentItem。

两套的分界就在 import 行：QtQuick.Controls 1.4 是一套，QtQuick.Controls 2.15 是另一套。视觉基座也从 QStyle 换成了纯 QML 描述，所以 Controls 2 的按钮换主题只要换风格模块，不用重编 C++。

看老文照抄属性名之前，先看 import 行。对不上就是版本错位，不是你的代码有 bug。本篇以下都以 Controls 2 为准，旧属性清单在第二章留了一张对照表。

一个控件，不是一块区域 #

分清这件事，后面所有坑都能自己推出来：

Button 是控件。它有外观，有状态，有默认尺寸，有焦点策略。

MouseArea 是区域。它没有任何外观，color、radius、border 一个都没有。它只负责把指针事件转成信号。

qml
// 想要一个看得见的按钮：用 Button
Button { text: "确定" }

// 想要一张图片能点：用 MouseArea 套住图片
Image {
    source: "logo.png"
    MouseArea {
        anchors.fill: parent
        onClicked: console.log("logo clicked")
    }
}

要用图片当按钮时，别硬塞一个 Button。Button 的背景会盖住图，你还得把 background 掏空、把 padding 抹平，绕一圈回到原点。

二、Button 的常用属性 #

旧文档属性清单对照 #

老资料给的属性列表是 Controls 1 时代的，一条一条对着看：

旧属性 类型 含义 Controls 2 的对应物
action Action 挂一个动作对象，由它提供 text、checked、tooltip 等 action
activeFocusOnPress bool 按下时是否获取焦点，默认 false 归入 focusPolicy 的语义
checkable bool 按钮是否可以勾选，默认 false checkable
checked bool 按钮是否处于选中态，只有 checkable 为真才有意义，默认 false checked
exclusiveGroup ExclusiveGroup 按钮加入的互斥组，默认空 ButtonGroup
hovered bool 指针是否划过控件 hovered
iconName string 主题图标名，找到主题图标时优先于 iconSource icon.name
iconSource url 按钮图标地址，无图标时为空字符串 icon.source
isDefault bool 是否为默认按钮，默认 false Controls 2 无同名属性，默认按钮由对话框决定
menu Menu 赋一个菜单就得到下拉按钮，默认空 用 Menu 手动 popup()
pressed bool 控件是否正被按住 pressed（只读）+ down
style Component 控件的样式组件 background + contentItem
text string 按钮文字，无文字时为空字符串 text
tooltip string 悬停提示信息 ToolTip.text + ToolTip.visible

isDefault 那条得说清楚：Controls 1 里它只改外观，按下回车要发生什么，还得你自己连。Controls 2 干脆把这件事交给对话框和按钮盒，Button 上不再有这个属性。

menu 那条同理。Controls 1 的按钮挂上 menu 就带一个小三角，点一下弹菜单。Controls 2 不给你这个糖，自己弹：

qml
Button {
    text: "更多"
    onClicked: moreMenu.popup()
}

Menu {
    id: moreMenu
    MenuItem { text: "打开" }
    MenuItem { text: "另存为" }
}

Controls 2 常用属性 #

日常写代码会碰到的就这么些：

属性 类型 说明
text string 按钮上的文字
icon.name string 主题图标名，有主题图标时优先于 icon.source
icon.source url 图标地址
icon.color color 给图标上色，透明时保留原色
display enum 图标与文字的排布：AbstractButton.IconOnly、TextOnly、TextBesideIcon、TextUnderIcon、TextOverIcon
checkable bool 能否勾选，默认 false
checked bool 是否已勾选，默认 false
highlighted bool 高亮态，视觉上比普通态更醒目，用来标「主操作」
flat bool 扁平态，不画背景和边框，只有内容
pressed bool 只读，是否被按住
down bool 可写，控件拿它渲染按下态
hovered bool 只读，指针是否悬停，需要开启悬停
autoExclusive bool 同一父级下的同组可勾选按钮自动互斥
action Action 绑定动作对象，属性与信号由动作驱动
enabled bool 是否可用，false 时不响应点击且变灰
padding real 内容四周留白，影响 implicitWidth

flat 和 highlighted 是最容易被忽略的两个。工具栏上用 flat: true，按钮就没边框，跟工具条融成一片；对话框主按钮用 highlighted: true，视觉上把「确定」推到前台。

qml
Row {
    spacing: 8

    Button { text: "取消" }
    Button { text: "确定"; highlighted: true }
    Button { text: "帮助"; flat: true }
}

display 这个枚举决定图标和文字怎么排。只想要图标时写 display: AbstractButton.IconOnly，文字仍然留在 text 里，读屏软件照样念得出来。

qml
Button {
    text: "设置"
    display: AbstractButton.IconOnly
    icon.source: "qrc:/icons/gear.svg"
    ToolTip.visible: hovered
    ToolTip.text: "设置"
}

三、点击信号与状态 #

信号表 #

Button 往外发的信号：

信号 触发时机 说明
clicked() 按下并在按钮内松开 最常用，一次完整点击
pressed() 指针按下 视觉反馈的起点
released() 指针松开 不论松在按钮内还是外都会发
doubleClicked() 双击 第一次单击的 clicked 已经先发过
pressAndHold() 按住不放超时 长按，用来触发次一级操作
toggled() checked 变化 只在 checkable 为真时有用

一次点击的完整顺序是 pressed → released → clicked。中间如果指针移出按钮再松开，clicked 就不发了，但 released 照发。没有单独的「取消」信号，撤临时状态就在 released 里自己判断。

把顺序打出来看：

qml
Button {
    text: "点我"
    onPressed: console.log("pressed")
    onReleased: console.log("released")
    onClicked: console.log("clicked")
}

单击输出三行。按下后拖出去再松开，只输出前两行。

pressed 和 down 的区别 #

pressed 是只读的，反映真实指针状态。down 可写，是控件用来渲染的按下标志。

down 能改写，意味着你能做「程序化按下」：

qml
Button {
    id: btn
    text: "模拟"
    down: area.pressed
}

MouseArea {
    id: area
    anchors.fill: parent
}

down: btn.pressed 这种写法会破坏绑定，别绕。要读真实状态就读 pressed，要把某个按钮画成按下样，才动 down。

长按与双击 #

pressAndHold 的判定在松开之前。用户按住不动，超时后信号发出，此时 clicked 还没轮到。手指抬起时 released 照发。

qml
Button {
    text: "按住"
    onPressAndHold: console.log("长按触发")
    onClicked: console.log("普通点击")
}

长按之后还要在 released 里清掉临时 UI，否则按住弹出的浮层会留在屏幕上。

doubleClicked 要留意：双击时第一次单击的 clicked 已经发出去了。想区分单双击，只能在 clicked 里起个短定时器延迟处理，Qt 不会替你等。

与 Action 联动 #

action 属性把按钮接到一个 Action 上，text、enabled、checkable、checked 都由动作驱动，triggered 与 clicked 双向连通。给 Action 设好 text、shortcut、enabled 和 onTriggered，然后写 Button { action: saveAction } 就接上了。

好处是一份逻辑能同时挂到菜单项、工具栏按钮和快捷键上，不用三处复写。绑了 action 之后仍然可以覆盖 text、icon.source，覆盖值优先。

四、可切换按钮 #

checkable 与 checked #

默认按钮是触发器，点一下发一次信号，状态不保留。加 checkable: true 就变成开关：

qml
Button {
    text: "加粗"
    checkable: true
    onToggled: console.log("checked =", checked)
}

checked 的决定权在 checkable 手上。checkable: false 时写 checked: true 没有任何效果，按钮视觉也不会变。

toggled 只在 checked 真的变化时发。程序里给 checked 赋同一个值，不会多发一次。

互斥组 #

一排按钮只允许一个选中，用 ButtonGroup：

qml
ButtonGroup {
    id: alignGroup
    exclusive: true
}

Row {
    spacing: 4
    Button { text: "左"; checkable: true; ButtonGroup.group: alignGroup }
    Button { text: "中"; checkable: true; ButtonGroup.group: alignGroup }
    Button { text: "右"; checkable: true; ButtonGroup.group: alignGroup }
}

exclusive: true 是默认值。改成 false 就退化成多选组，一个组里能同时亮多个。

exclusive 有一个反直觉行为：组里已经有一个选中时，再点那个已选中的按钮，它不会被取消。想要「再点取消」的效果，得自己写：

qml
Button {
    text: "切换"
    checkable: true
    onClicked: if (wasChecked) checked = false
    property bool wasChecked: false
    onPressed: wasChecked = checked
}

autoExclusive #

不想建组对象，用 autoExclusive：

qml
Row {
    Button { text: "小"; checkable: true; autoExclusive: true }
    Button { text: "中"; checkable: true; autoExclusive: true; checked: true }
    Button { text: "大"; checkable: true; autoExclusive: true }
}

规则是：同一个父级下，所有 autoExclusive: true 且 checkable: true 的兄弟按钮自动互斥。父级一变，组就散了。所以别把同组按钮塞进不同的 Row 里。

显式 ButtonGroup 和 autoExclusive 别同时用。两套互斥规则叠一起，谁赢取决于创建顺序，调起来很烦。

五、按钮样式定制 #

两个委托：background 和 contentItem #

Controls 2 把按钮的外表切成两半：

委托 负责 默认内容
background 底板：底色、圆角、边框、阴影 一个跟随风格的主题矩形
contentItem 内容：文字、图标及其排布 一个内部 IconLabel

要换外观，就重写这两个之一。只换颜色改 background，只改文字排版改 contentItem。

qml
Button {
    text: "保存"
    background: Rectangle {
        implicitWidth: 96
        implicitHeight: 36
        radius: 6
        color: parent.down ? "#1f6fd0" : (parent.hovered ? "#3a86e0" : "#2f80ed")
        border.color: "#1f6fd0"
        border.width: 1
    }
}

parent.down、parent.hovered 能直接用，是因为 background 的父对象就是这个按钮。这是 Controls 2 里约定好的关系，不是巧合。

注意 background 的宽高不用自己管。控件会把 background 的 width/height 填成控件尺寸，你填 implicitWidth/implicitHeight 只决定「自然尺寸」——控件没被外部指定大小时就取这个值加上 padding。

状态驱动配色 #

一个按钮至少要覆盖四种态：常态、悬停、按下、禁用。写成一张表对照着填：

状态 判定条件 建议处理
常态 无 主色
悬停 hovered 主色提亮一档
按下 down 主色压暗一档
选中 checked 用辅色区分，不要只加粗字
禁用 !enabled 灰度 + 降低不透明度 
qml
background: Rectangle {
    implicitWidth: 100
    implicitHeight: 36
    radius: 6
    opacity: parent.enabled ? 1.0 : 0.45
    color: {
        if (!parent.enabled) return "#b8bcc2"
        if (parent.checked) return "#123f6d"
        if (parent.down) return "#1a5c9e"
        if (parent.hovered) return "#2f80ed"
        return "#5a9bea"
    }
}

color 里写多行 if 比嵌套三元好读。QML 的绑定表达式是完整 JS，别硬压成一行。

hovered 要真能用起来，控件得收到悬停事件。在高 DPI 或某些窗口系统上指针行为异常时，先确认按钮没被透明层盖住。

旧做法的对应关系 #

Controls 1 时代是 style: ButtonStyle { background: ...; label: ... } 这么写的，样式内部用 control.text、control.hovered 取控件属性。Controls 2 不认这套，映射只有三处：style 里的 background 换成 background，label 换成 contentItem，样式内的 control.xxx 换成 parent.xxx。搬代码时按这三条替换，剩下基本能跑。

改 contentItem #

想给文字加描边、想图文混排成别的形状，接管 contentItem：

qml
Button {
    id: btn
    text: "下载"
    icon.source: "qrc:/icons/download.svg"
    contentItem: Row {
        spacing: 6
        Image { source: btn.icon.source; width: 16; height: 16 }
        Text { text: btn.text; color: "#ffffff"; font.pixelSize: 14 }
    }
}

给按钮一个 id 再在委托里引用它，比 parent.parent 一路往上摸稳得多。自己写 contentItem 之后，display 就不起作用了——那个枚举是默认委托在用的。

六、MouseArea：更底层的交互 #

MouseArea 是个纯交互区域。它不画任何东西——没有 color，没有 radius，没有 border。它的全部工作是接住指针事件，再翻译成信号。

这意味着两件事：

一是它必须有个尺寸。MouseArea 没有 implicitWidth，不写宽高就是零，零尺寸接不到任何事件。要么 anchors.fill: parent，要么显式给 width/height。

二是它存在的意义就是「给没有交互能力的东西加上交互」。

qml
Rectangle {
    width: 200; height: 120
    color: area.pressed ? "#c8d8ea" : "#e8f0f8"

    Text { anchors.centerIn: parent; text: "可点击的卡片" }

    MouseArea {
        id: area
        anchors.fill: parent
        onClicked: console.log("card clicked")
    }
}

Rectangle 本身不认识鼠标。塞一个填满它的 MouseArea，卡片就活了。

图片同理，只是多了悬停与光标：

qml
Image {
    source: "avatar.png"
    width: 64; height: 64

    MouseArea {
        anchors.fill: parent
        hoverEnabled: true
        cursorShape: Qt.PointingHandCursor
        onClicked: profilePopup.open()
    }
}

anchors.fill 让区域盖满图片，hoverEnabled 打开悬停跟踪，cursorShape 让指针变成手型。三件事各管一段。

acceptedButtons 决定接哪些键 #

MouseArea 默认只接左键，acceptedButtons: Qt.LeftButton。要右键菜单，得显式加：

qml
MouseArea {
    anchors.fill: parent
    acceptedButtons: Qt.LeftButton | Qt.RightButton | Qt.MiddleButton

    onClicked: {
        if (mouse.button === Qt.RightButton)
            contextMenu.popup()
        else if (mouse.button === Qt.LeftButton)
            selectItem()
    }
}

mouse.button 是「这次事件是哪个键」，mouse.buttons 是「此刻所有按下的键的集合」。判断单键用前者，判断组合键用后者。

acceptedButtons 设成 Qt.NoButton 就是「一个键都不接」。这不是关掉 MouseArea，而是让它彻底不吃事件——它就是穿透用的开关，下一章会用到。

enabled 与 visible #

enabled: false 之后，MouseArea 不再接收任何输入，也不发悬停信号。但它仍然占着位置，挡住下层——要彻底让开，用 visible: false 或者干脆别创建。

七、MouseArea 的事件与穿透 #

信号与 mouse 参数 #

信号 携带参数 触发时机
clicked(mouse) mouse 在区域内按下并松开
doubleClicked(mouse) mouse 双击
pressed(mouse) mouse 指针按下
released(mouse) mouse 指针松开
pressAndHold(mouse) mouse 按住超时
positionChanged(mouse) mouse 指针在区域内移动
entered() 无 指针进入区域，需 hoverEnabled
exited() 无 指针离开区域，需 hoverEnabled
wheel(wheel) wheel 滚轮滚动
canceled() 无 事件被上层抢走或指针拖出后失焦

mouse 里常用的几个字段：

字段 含义
mouse.x / mouse.y 相对本区域的坐标
mouse.button 本次事件的按键
mouse.buttons 当前所有按下的按键
mouse.modifiers 修饰键，如 Qt.ControlModifier、Qt.ShiftModifier
mouse.accepted 是否消费掉这次事件
mouse.wasHeld 该键此前是否被按住

拖拽定位就靠 mouse.x、mouse.y，或者干脆交给 drag 组：

qml
Rectangle {
    id: knob
    width: 40; height: 40

    MouseArea {
        anchors.fill: parent
        drag.target: knob
        drag.axis: Drag.XAxis
        drag.minimumX: 0
        drag.maximumX: 200
        onClicked: console.log("坐标", mouse.x, mouse.y)
    }
}

drag.target 让区域自己处理拖动，不用手写 onPositionChanged 里的位移计算。

覆盖 Button 会吃掉点击 #

这是本篇最该记住的坑。

Button 内部已经有一套鼠标处理。你在它里面再放一个 MouseArea 并铺满，事件先到 MouseArea，它默认把事件消费掉，Button 就收不到，onClicked 永远不会触发。

现象很好认：按钮看着能按、按下有视觉反馈（因为内部处理按下时的部分状态），但 onClicked 里的日志一行不打印。

三种处理，按场景选：

做法 写法 适用场景
不要叠 把 MouseArea 换成按钮的 onClicked 首选，能不加层就不加
让事件穿透 acceptedButtons: Qt.NoButton 只想改光标或做悬停特效，不接管点击
转发合成事件 propagateComposedEvents: true + mouse.accepted = false 需要自己先看一眼，再交给下层

穿透写法：

qml
Button {
    text: "确定"
    onClicked: console.log("按钮自己的点击")

    MouseArea {
        anchors.fill: parent
        hoverEnabled: true
        cursorShape: Qt.PointingHandCursor
        acceptedButtons: Qt.NoButton   // 关键：一个键都不接，事件全放行
    }
}

acceptedButtons: Qt.NoButton 之后，这个 MouseArea 依然能收悬停、依然能改光标，但按下一律不消费，Button 照常触发 onClicked。

第三种做法的细节：

qml
MouseArea {
    anchors.fill: parent
    propagateComposedEvents: true

    onClicked: {
        console.log("我处理了")
        mouse.accepted = false   // 交给下层
    }
}

propagateComposedEvents 只对合成事件（clicked、doubleClicked、pressAndHold）生效，而且必须配 mouse.accepted = false。只设前者不设后者，事件还是断在这一层。

父子层级的传播 #

事件沿视觉树往上走，但 MouseArea 不像 DOM 那样自动冒泡。子级消费掉，父级 MouseArea 就收不到；要让父级也拿到，同样得靠 propagateComposedEvents。

这带来一个常见现象：整页一个 MouseArea 铺满父容器，里面几个子 MouseArea，结果是点空白处父级响应、点子元素只有子元素响应。这个行为是对的，别去修。

preventStealing: true 是反方向的锁：声明「这个区域的事件不许被 Flickable 之类抢走」。典型用在可滑动列表里的滑块上——不设它，一拖滑块，列表先滚起来了。

八、鼠标指针样式 #

cursorShape #

指针形状由 cursorShape 决定，取值来自 Qt::CursorShape 枚举。它挂在 MouseArea 上，不挂在 Item 上，也不挂在 Button 上。

qml
MouseArea {
    anchors.fill: parent
    cursorShape: Qt.PointingHandCursor
}

绑成常量就是静态效果。绑成表达式就是动态效果：

qml
MouseArea {
    anchors.fill: parent
    hoverEnabled: true
    cursorShape: containsMouse
                 ? (pressed ? Qt.ClosedHandCursor : Qt.OpenHandCursor)
                 : Qt.ArrowCursor
}

这段表达的是：指针在区域内且没按，张开手；按住，握拳；不在区域内，普通箭头。

设了不生效的两种情况 #

指针没变成你写的那个形状，先查这两条，别急着怀疑 Qt。

第一条，动态绑定没开 hoverEnabled。cursorShape 写成常量时，指针一进入区域就切，跟悬停无关。但只要表达式里用了 containsMouse、hovered 之类的状态，没开 hoverEnabled 时 containsMouse 恒为 false，表达式永远算到兜底分支，光标就一直是那个兜底值。

qml
MouseArea {
    anchors.fill: parent
    // 少了 hoverEnabled: true —— 永远走 Qt.ArrowCursor
    cursorShape: containsMouse ? Qt.PointingHandCursor : Qt.ArrowCursor
}

第二条，被上层元素挡住。cursorShape 只对指针真正落在的那个 MouseArea 生效。上层铺了一层透明的 MouseArea，或者 z 更大的兄弟元素盖在上面，下层永远不知道指针在它身上。

排查方法：临时给上层 MouseArea 加个半透明背景，看是不是它在偷偷拦。或者顺手把上层设成 acceptedButtons: Qt.NoButton，事件放行，光标也就归下层管了。

还有一条非 Bug 的情况：触屏平台上没有物理指针，cursorShape 不产生任何视觉效果。代码留着不会报错，只是看不见。

九、自定义光标 #

内置 22 个够用，但有时候你要的是一张图：画笔工具的笔尖、游戏里的准星、看板里拖着走的卡片缩略图。

cursorShape 只吃枚举，给不了图片路径。两条路。

隐藏系统指针，自己画一个 #

Qt.BlankCursor 把系统指针抹掉，再用一个 Image 跟着指针位置走：

qml
Item {
    anchors.fill: parent

    Image {
        id: customCursor
        source: "qrc:/cursors/pen.png"
        width: 24; height: 24
        visible: area.containsMouse
        x: area.mouseX - width / 2
        y: area.mouseY - height / 2
        z: 9999
    }

    MouseArea {
        id: area
        anchors.fill: parent
        hoverEnabled: true
        cursorShape: Qt.BlankCursor
        onClicked: drawDot(mouse.x, mouse.y)
    }
}

要点三条：hoverEnabled: true 才有 containsMouse，也才有不按键时的 mouseX/mouseY；cursorShape: Qt.BlankCursor 藏掉系统指针；z 给足，别被其他元素盖住。

这个方案的代价是跟随有延迟——指针移动事件和重绘不在同一帧里完成，快速划动时自绘光标会滞后一点。需要零延迟的场合走第二条路。

C++ 侧构造自定义光标 #

QCursor 支持用位图构造：QCursor penCursor(QPixmap::fromImage(img), 0, 0)，后两个数字是热点坐标；再调 QQuickItem::setCursor(penCursor) 把光标挂到元素上。

热点（hot spot）是指针的落点，画笔类光标要设到笔尖，不能留在左上角，否则用户会觉得画不准。

这条路没有跟随延迟，代价是要接触 C++ 层，并且光标资源得打进资源文件。纯 QML 项目里为了一个光标开一个 C++ 类不值，用第一条路。

换光标别忘复位 #

自定义光标只在指定区域生效。离开区域还在显示自绘指针，多半是 visible 绑定写漏了；containsMouse 只在 hoverEnabled 为真时更新，这条又绕回第八章那两个坑。

十、悬停与触摸 #

hoverEnabled 到底开了什么 #

MouseArea 的 hoverEnabled 默认是 false。关着的时候，区域不跟踪指针移动，只处理按下与松开。

打开之后多出这些能力：

能力 没开 开了
entered / exited 信号 不发 进入离开各发一次
containsMouse 属性 恒 false 实时反映指针是否在内
positionChanged 只在按住拖动时发 不按键也会随移动发
用于 cursorShape 的动态绑定 失效 正常
hovered 视觉反馈 无 有

所以一句 hoverEnabled: true 往往能救活一整片悬停特效。开关按钮的滑过预览、卡片的浮起阴影、指针形状切换，全依赖它。

hovered 不等于 pressed #

三个状态别混：hovered 是指针停在上方没按，pressed 是按下，containsMouse 是指针在区域内（按住拖出再拖回仍算）。用途也不同——hovered 提亮、pressed 压暗、containsMouse 控制自绘光标的显示。Button 的 hovered 由控件内部维护，不用你开开关；MouseArea 的 containsMouse 要自己开 hoverEnabled。

触摸平台上的差别 #

触屏没有「悬停」这个动作。手指要么在按，要么不在。于是：

cursorShape 在触屏上没有视觉效果，因为压根没有指针可画。

hoverEnabled 带来的 entered/exited 在触屏上不可靠，containsMouse 的表现也因平台而异。界面逻辑别把关键流程压在悬停上——悬停只能做锦上添花的视觉层。

MouseArea 本身在触屏上照常工作。单击、长按、拖动都是它的基本盘。

做双端适配的思路：交互入口用 clicked/pressed，视觉增强用 hovered。前者两端都通，后者只对桌面端加料。

十一、按钮与 MouseArea 怎么选 #

兜了一圈，回到那条主干：

Button 是 Controls 2 的控件，自带外观与状态机；MouseArea 是纯交互区域，不带外观。

要一个看得见的按钮，用 Button。要在一个已有元素上接点击——一张图、一块矩形、一段文字、一个自绘图形——用 MouseArea。

逐项对比：

维度 Button MouseArea
模块 QtQuick.Controls QtQuick 基础模块
外观 自带背景、文字、图标 无，完全透明
尺寸 有 implicitWidth/implicitHeight 无，必须显式给或锚定
状态 pressed、hovered、checked、down pressed、containsMouse
主信号 clicked、toggled、pressAndHold clicked、positionChanged、entered、wheel
键盘可达 有焦点策略，可 Tab 切换、空格触发 无键盘支持
无障碍 有角色与文本，读屏能念 无
定制成本 改两个委托，成本中 自己画，成本看需求
适合 表单、工具栏、对话框按钮 图片热点、自绘控件、拖拽、区域手势

表里「键盘可达」和「无障碍」那两行比别的都重要。Button 有键盘可达性和无障碍信息，MouseArea 没有。用 MouseArea 手搓出来的「按钮」，Tab 键跳不过去，读屏软件念不出来。表单和主流程上的操作，别用它替代 Button。

组合的正确姿势 #

三种常见组合，各归其位：

第一种，按钮里叠一层 acceptedButtons: Qt.NoButton 的 MouseArea 只为改光标，点击照旧穿透，写法见第七章。

第二种，自绘控件外面套一层 MouseArea 接点击，内部视觉全自己画。图表、色块、缩略图都走这个路子。

第三种，Button 加自定义 background，既不丢键盘可达性，又拿到完全自定义的外观。这是「既想要控件的能力，又想要自己的样子」的标准答案。

要在这个基础上再抓双击或右键，才轮到往里面加 MouseArea——加了就必须处理事件归属，别让它白吃点击。

十二、易错点速查 #

按踩坑频率排：

# 现象 原因 修法
1 Button 里放了 MouseArea，onClicked 不触发 MouseArea 消费了指针事件 去掉这层，或设 acceptedButtons: Qt.NoButton
2 cursorShape 设了没反应 动态绑定没开 hoverEnabled，或被上层挡住 加 hoverEnabled: true，检查上层是否有透明 MouseArea
3 MouseArea 完全没反应 没给尺寸，宽高为 0 anchors.fill: parent 或显式设宽高
4 右键菜单弹不出来 acceptedButtons 默认只接左键 加 Qt.RightButton
5 MouseArea 改不了颜色 MouseArea 没有外观属性 颜色写在父级 Rectangle 上
6 checked 改了没效果 checkable 为 false 先设 checkable: true
7 互斥组里点已选项取消不掉 互斥组的行为如此 自己在 onClicked 里判断并取消
8 按钮变大后文字被裁 自定义 background 没给足 implicitWidth/implicitHeight 补齐自然尺寸，或去掉固定宽高
9 contentItem 改了但图标不显示 默认委托被替换，display 不再生效 自己在 contentItem 里摆图标和文字
10 搬来的样式代码报 control 未定义 Controls 1 的 ButtonStyle 写法 换成 Controls 2 的 background/contentItem，control 改 parent
11 子级 MouseArea 拦住了父级 事件被消费，不自动冒泡 propagateComposedEvents: true 且 mouse.accepted = false
12 拖滑块时列表先滚了 Flickable 抢走了拖动 给 MouseArea 设 preventStealing: true
13 触摸屏上悬停特效不出现 触屏没有悬停动作 悬停只做视觉增强，主流程用 clicked
14 双击时单击逻辑也跑了 双击前必先发一次 clicked 在 clicked 里延迟处理并判双击
15 按钮禁用后还能点 用了 opacity 伪装禁用 用 enabled: false，别只改透明度

十五条里前四条能盖住八成问题。剩下的是版本迁移和委托定制带来的，遇到再查。

要一句话收口：看得见的交给 Button，它的键盘与无障碍能力别丢；摸得着的交给 MouseArea，它的 hoverEnabled 与 acceptedButtons 是全部要害；两者叠在一起时，先想清楚谁来接点击，再动手写。
