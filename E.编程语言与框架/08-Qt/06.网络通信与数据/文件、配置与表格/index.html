本篇只讲本地数据的三条路：把目录里的文件翻出来，把程序配置存下去，把表格读写掉。三件事看着散，落点是一个——Qt 程序怎么在本地放数据。

不讲网络那一层，收发报文见同目录《Qt 网络编程》与《网络应用实例》。JSON、XML 的解析见《JSON 与 XML》，用 SQL 存结构化数据见《数据库》，磁盘与系统目录信息见《系统信息》。CSV 只作为 Excel 的兜底方案带一句。

代码按 Qt 5 与 Qt 6 通用的写法给，只在两代有差异的地方单独标注。

一、本地数据的三类载体 #

动手之前先分清存的是什么。Qt 里本地数据大致分三类，三类的 API 完全不搭界，混着用要吃苦头。

载体 主力 API 存什么 谁来读
散文件与目录 QDir、QDirIterator、QFileInfo、QFile 图片、日志、导出物、用户素材 程序自己，用户也用文件管理器直接翻
配置项 QSettings 窗口尺寸、上次打开的目录、地址与端口、开关状态 程序启动读一次，退出写一次
表格 QXlsx、QAxObject 报表、批量导入的业务数据 Excel / WPS，或者对接的第三方系统

1.1 三个维度分选型 #

第一维看数据量。十个键值对，写配置；几万行结构化记录，走表格或数据库；几百上千张图片，走文件系统，路径记在配置里。

第二维看谁消费。只有自己程序读的，随便放；要交给会计用 Excel 打开的，就得是 xlsx 或 csv；要跟别的系统对接的，格式得按对方的约定来。

第三维看跨平台要求。这条决定了你能不能碰 COM，后面第八章会展开。

1.2 配置与数据的分界 #

配置是「程序行为的参数」，数据是「用户干活的产物」。两者混在一起的后果很直接：用户换台机器，导出目录丢了不要紧，但配置跟着乱就找不回状态。

我们按这个规则切：启动时决定界面长什么样的东西进配置，用户亲手创建的文件进数据目录。数据目录用 QStandardPaths::writableLocation(QStandardPaths::AppDataLocation) 取，别自己拼路径。

cpp
const QString dataDir = QStandardPaths::writableLocation(QStandardPaths::AppDataLocation);
QDir().mkpath(dataDir);   // 首次运行时要自己建，Qt 不会替你建

1.3 一条硬规则：配置里不放二进制 #

QSettings 的值最终落成文本或注册表的字符串，塞进去的 QByteArray 会被转义成 @ByteArray(...)。图片、证书、缓存一律别往配置里放。Windows 上还有额外代价：注册表单个值超过 1 MB 就开始别扭，几十 MB 直接写失败。配置项保持短小的标量，这是它该干的事。

二、遍历目录：QDir 与 QDirIterator #

QDir 不是「一个目录对象」，它更像「一次查询的说明书」：路径 + 过滤条件 + 排序规则，三个东西配好，再问它要列表。

cpp
QDir dir(path);
if (!dir.exists())
    return;

先查存在。QDir 构造时不校验路径，exists() 才真的去问文件系统。

2.1 只遍历下一层：entryInfoList #

这是最常用的一手，一次拿到目录下所有条目的完整信息。

cpp
void ImageTree::addFolderImages(const QString &path)
{
    QDir dir(path);
    if (!dir.exists())
        return;

    // 只要文件，不要符号链接
    dir.setFilter(QDir::Files | QDir::NoSymLinks);

    QFileInfoList list = dir.entryInfoList();
    if (list.count() <= 0)
        return;

    for (int i = 0; i < list.count(); ++i) {
        QFileInfo info = list.at(i);
        QString suffix = info.suffix();
        if (QString::compare(suffix, "png", Qt::CaseInsensitive) == 0)
            m_paths.append(info.absoluteFilePath());
    }
}

逻辑三段：设过滤、取列表、按后缀筛。entryInfoList() 返回 QFileInfoList，每一项都带了大小、时间、权限，后面第三章细讲这些字段。

系统看来，一个目录下的条目包括子目录、文件、快捷方式。setFilter 就是在切这三类。

2.2 只遍历下一层：setNameFilters #

第二种写法不取 QFileInfo，直接拿文件名，过滤器交给 QDir 做。

cpp
void ImageTree::addFolderImages(const QString &path)
{
    QDir dir(path);
    if (!dir.exists())
        return;

    QStringList filters;
    filters << "*.jpeg" << "*.jpg" << "*.png"
            << "*.tiff" << "*.gif" << "*.bmp";

    dir.setFilter(QDir::Files | QDir::NoSymLinks);
    dir.setNameFilters(filters);       // 只保留上面这些后缀

    if (dir.count() <= 0)
        return;

    for (int i = 0; i < dir.count(); ++i) {
        QString fileName = dir[i];                       // 只有文件名
        m_paths.append(dir.absoluteFilePath(fileName));  // 拼全路径
    }
}

setNameFilters 顾名思义过滤的是名字。dir[i] 只给文件名，要全路径得自己拼，或者用 dir.filePath(dir[i])。老代码里手工拼分隔符的写法是这么来的：

cpp
QChar separator = QDir::separator();   // Windows 上是 '\\'
if (!path.contains(QLatin1Char('/')))
    separator = QLatin1Char('\\');

为什么有人宁可用 contains 判断也不信 QDir::separator()？因为在 Windows 上它返回 '\\'，而从 QLineEdit 或某个配置里读进来的路径习惯写 '/'，两者对不上，拼出来的路径就多一个反斜杠。

正解是别拼：dir.absoluteFilePath(fileName) 内部会做规范化，'/' 和 '\\' 都能吃。

2.3 后缀过滤的大小写坑 #

第一种写法拿 QFileInfo，带全部元信息，后缀比较能自己控大小写，只用下一层就选它。

问题出在第二种。Windows 的文件名不区分大小写，a.JPG 和 a.jpg 是同一个东西，但 setNameFilters 是拿通配符逐字符比的，*.jpg 匹配不到 a.JPG、a.Jpg。

这是老代码里真实踩过的坑：用户从相机拷进来的文件是 .JPG，列表就是空的。

修法是把过滤权收回来：

cpp
// 1. 不调 setNameFilters，只按 QDir::Files 取全部
// 2. 拼出全路径后构造 QFileInfo
QFileInfo info(filePath);
// 3. 取后缀，比较时忽略大小写
if (QString::compare(info.suffix(), "jpg", Qt::CaseInsensitive) == 0)
    m_paths.append(info.absoluteFilePath());

suffix() 给最后一个点之后的串，completeSuffix() 给第一个点之后的整段。archive.tar.gz 前者是 gz，后者是 tar.gz，按需选。

2.4 递归遍历：QDirIterator #

要找子目录里的文件，别再手写递归，用 QDirIterator。

cpp
void ImageTree::addSubFolderImages(const QString &path)
{
    QDir dir(path);
    if (!dir.exists())
        return;

    QStringList filters;
    filters << "*.jpeg" << "*.jpg" << "*.png"
            << "*.tiff" << "*.gif" << "*.bmp";

    QDirIterator it(path, filters,
                    QDir::Files | QDir::NoSymLinks,
                    QDirIterator::Subdirectories);

    while (it.hasNext()) {
        it.next();                                     // 这一句漏了就是死循环
        QFileInfo info = it.fileInfo();
        m_paths.append(info.absoluteFilePath());
    }
}

构造函数的四个参数就是全部配置：起点路径、名字过滤器、QDir::Filter、QDirIterator::IteratorFlag。Subdirectories 一开，它自己往下钻，你不用管层级。

next() 是必须的。hasNext() 只判断还有没有下一个，不移动游标；漏掉 next()，循环条件永远成立，界面直接卡死。这是这段代码最经典的错法。

第四个参数就三个值：默认只看一层；Subdirectories 递归全部子目录，深度优先；FollowSymlinks 跟随符号链接，默认不跟，防成环。两个按位或，就是递归加跟随。

2.5 手写递归的老写法 #

十年前常见的是这种，思路是「取整层列表 → 遇到目录就递归」。

cpp
void ImageTree::addSubFolderImages(const QString &path)
{
    QDir dir(path);
    if (!dir.exists())
        return;
    dir.setFilter(QDir::Dirs | QDir::Files | QDir::NoSymLinks);
    dir.setSorting(QDir::DirsFirst);

    const QFileInfoList list = dir.entryInfoList();
    for (const QFileInfo &info : list) {
        if (info.fileName() == "." || info.fileName() == "..")
            continue;
        if (info.isDir())
            addSubFolderImages(info.filePath());            // 递归
        else if (QString::compare(info.suffix(), "png", Qt::CaseInsensitive) == 0)
            m_paths.append(info.absoluteFilePath());
    }
}

能跑，但别用。两个毛病：每个子目录都完整 entryInfoList() 一次，几十万个文件的树要几十次全量分配；递归深度跟着目录深度走，碰上软链接成环或者超深目录，栈就危险。QDirIterator 内部维护的是一个显式目录栈，同样深度优先，但它只在需要时读一段，栈在堆上。

2.6 说到底：entryList 与 QDirIterator 差在哪 #

这是本篇必须掰开的一处。两者底层都是 readdir，但取数节奏完全不同。

对比项 entryList / entryInfoList QDirIterator
取数方式 一次把整个目录读完，返回 QStringList / QFileInfoList 迭代器，next() 一次取一个
内存 与目录条目数成正比，10 万条就是几十 MB 常数级，只留当前位置
首字节延迟 要等整个目录读完才有第一个结果 第一个结果几乎立刻就有
递归 不支持，要自己写递归函数 Subdirectories 一行开
排序 支持 setSorting 不支持，按底层顺序给
中途停止 不行，列表已经全建好了 随时 break，后面的不再读
适合 小目录、要排序、要反复随机访问 大目录、递归、边找边处理

一句话记住：entryList 是把目录整个搬进内存，QDirIterator 是顺着目录一个个拿。

所以递归遍历大目录必须用后者。一个装了几十万张图片的素材库，entryInfoList() 会在主线程里卡好几秒，界面白屏；换 QDirIterator 后同样的活，边遍历边往列表控件里填，用户能看见进度。

要排序怎么办？小目录直接 setSorting(QDir::Name | QDir::IgnoreCase)；大目录先迭代收齐再自己 std::sort，排序开销躲不掉，但内存峰值可控，遍历阶段也不阻塞界面。

三、文件信息与过滤 #

QFileInfo 是每个文件的档案卡。构造它不会去读文件内容，只在第一次问某个属性时去 stat 一次，之后缓存。

cpp
QFileInfo info("/data/report.tar.gz");
info.fileName();          // "report.tar.gz"
info.baseName();          // "report"
info.completeBaseName();  // "report.tar"
info.suffix();            // "gz"
info.completeSuffix();    // "tar.gz"

3.1 路径族方法 #

方法 返回 例子（当前目录 /app，传入 ./img/a.png）
filePath() 构造时给的路径原样 ./img/a.png
absoluteFilePath() 补全为绝对路径 /app/img/a.png
canonicalFilePath() 绝对且解析掉 .. 与链接 /app/img/a.png
path() 所在目录，原样 ./img
absolutePath() 所在目录，绝对 /app/img
dir() / absoluteDir() 上面两个的 QDir 版本 —
isRelative() / isAbsolute() 路径形态 true / false

absoluteFilePath() 最常用，导出列表、写日志、当 QFile 的入参都靠它。canonicalFilePath() 更严格，但它要求文件真实存在，文件不存在时返回空串。

3.2 类型与状态方法 #

方法 用途
exists() 是否存在（文件或目录都算）
isFile() / isDir() 是文件还是目录
isSymLink() 是符号链接
readLink() / symLinkTarget() 链接指向哪里
isHidden() 隐藏文件（Linux 上以 . 开头，Windows 上看属性）
isRoot() 是不是根目录
isBundle() macOS 的 .app 这类包
isReadable() / isWritable() / isExecutable() 权限探测，注意它问的是当前进程的权限
permissions() / permission(QFile::Permissions) 权限位
owner() / ownerId() / group() / groupId() 属主与属组，Windows 上返回空
refresh() 丢掉缓存重新 stat

3.3 大小与时间 #

方法 返回
size() qint64，字节数
created() 创建时间，Linux 上常拿不到，退化成修改时间
lastModified() 最后修改时间
lastRead() 最后访问时间，很多文件系统按挂载选项关掉了

按修改时间排序是最常见的需求，std::sort(list.begin(), list.end(), [](const QFileInfo &a, const QFileInfo &b) { return a.lastModified() > b.lastModified(); }); 一行就够。

3.4 QDir 的过滤器枚举 #

setFilter 收的是 QDir::Filters，可以按位或。

枚举值 含义
QDir::Dirs 列子目录
QDir::Files 列文件
QDir::Drives 列盘符（Windows）
QDir::NoSymLinks 排除符号链接
QDir::Hidden 包含隐藏文件
QDir::System 包含设备文件、管道这类
QDir::Readable / Writable / Executable 按权限过滤
QDir::NoDot 去掉 .
QDir::NoDotDot 去掉 ..
QDir::NoDotAndDotDot 两个都去掉
QDir::AllDirs 所有目录，不受名字过滤影响
QDir::AllEntries 文件 + 目录 + 盘符
QDir::CaseSensitive 名字过滤区分大小写

默认值不用背，组合写清楚就行，最常见的一行：

cpp
dir.setFilter(QDir::Files | QDir::NoSymLinks | QDir::Readable);

排序归 setSorting() 管，常用的有 QDir::Name、QDir::Time、QDir::Size、QDir::Unsorted（不排，大目录最快），再配 QDir::DirsFirst、QDir::Reversed、QDir::IgnoreCase 组合。给用户看的列表用 Name | IgnoreCase | DirsFirst，纯机器处理的批量任务用 Unsorted 省掉排序开销。

四、文件读写：QFile 与 QTextStream #

QFile 是 QIODevice 的文件实现，QTextStream 是套在它上面的文本层。分层很清楚：QFile 管字节，QTextStream 管编码和格式。

4.1 打开模式 #

open() 收了模式后会先关掉已打开的描述符，再重新打开。

模式 含义
QIODevice::ReadOnly 只读，文件必须存在
QIODevice::WriteOnly 只写，文件不存在就建，存在就清空
QIODevice::ReadWrite 读写
QIODevice::Append 追加，写游标定位到末尾
QIODevice::Truncate 配合写模式，打开时截断
QIODevice::Text 读时把 \r\n 转成 \n，写时反过来

Text 这个标志在 Windows 上是刚需。不加它，读进来每行末尾带一个 \r，按行处理时字符串比较全是错的；不加它，写出去是纯 \n，记事本老版本会显示成一行。

cpp
QFile file(path);
if (!file.open(QIODevice::ReadOnly | QIODevice::Text)) {
    qWarning() << "open failed:" << file.errorString();
    return;
}

报错别只看 false，errorString() 才有信息量。

4.2 逐行读大文件 #

不要 readAll() 读一个几百 MB 的日志。

cpp
QFile file(path);
if (!file.open(QIODevice::ReadOnly | QIODevice::Text))
    return;

QTextStream in(&file);
while (!in.atEnd()) {
    const QString line = in.readLine();
    if (line.isEmpty())
        continue;
    parseLine(line);
}

atEnd() 配 readLine() 是标准套路。QTextStream 自带缓冲，逐行读并不慢。

4.3 编码：Qt 5 与 Qt 6 的差异 #

这是中文乱码的主要来源。

Qt 5 里 QTextStream 默认用 QTextCodec::codecForLocale()，中文 Windows 上就是 GBK。写出去的 UTF-8 文件被它当 GBK 读，必然乱码。Qt 6 把 QTextCodec 挪出了核心模块，默认编码改成 UTF-8，接口也换了：

cpp
QTextStream in(&file);
in.setCodec("UTF-8");                      // Qt 5
in.setEncoding(QStringConverter::Utf8);    // Qt 6

两代各写一行，显式写一遍是好习惯，不用猜。要处理带 BOM 的 UTF-8，用 in.setAutoDetectUnicode(true)，Qt 会看 BOM 自己判断。

4.4 写文本 #

cpp
QFile file(path);
if (!file.open(QIODevice::WriteOnly | QIODevice::Text | QIODevice::Truncate))
    return;

QTextStream out(&file);
out.setEncoding(QStringConverter::Utf8);   // Qt 5 用 setCodec("UTF-8")
out << "时间,数值\n";
out << QDateTime::currentDateTime().toString("yyyy-MM-dd hh:mm:ss") << ',' << 3.14 << '\n';
out.flush();
file.close();

QTextStream 析构时会 flush()，但那是在作用域结束时，中途要保证落盘就手动 flush()。

4.5 原子写：QSaveFile #

直接写目标文件，写到一半崩了，原文件就废了。QSaveFile 先写临时文件，commit() 时才替换。

cpp
QSaveFile file(path);
if (!file.open(QIODevice::WriteOnly | QIODevice::Text))
    return;

QTextStream out(&file);
out << content;
if (!file.commit())          // 不 commit 就什么都不写
    qWarning() << "commit failed:" << file.errorString();

配置导出、报表落盘这类「用户数据不能丢」的场景，用它。少一次 commit()，文件就是空的。

QDir 只提供 removeRecursively()，没有递归拷贝，要整棵树搬家用 QDirIterator 自己遍历配 QFile::copy。单文件的 exists、remove、rename、copy、resize 都是 QFile 的静态接口，不必先构造对象。

五、QSettings 是什么 #

一句话：QSettings 把「程序配置」这层抽象掉了。

你写的还是同一份代码——settings.setValue("net/port", 8080)。落到哪里、用什么格式、键名怎么翻译成层级，全由平台后端决定。

平台 默认后端 落盘位置 格式
Windows 注册表 HKEY_CURRENT_USER\Software\<组织>\<应用> 注册表键值
Linux / BSD INI 文件 ~/.config/<组织>/<应用>.conf INI
macOS plist ~/Library/Preferences/com.<组织>.<应用>.plist XML plist
嵌入式 Linux INI 文件 同上 INI

这就是它存在的理由。你不需要为 Windows 写一套注册表代码、为 Linux 写一套解析 ini 的代码、为 macOS 再写一套 plist，一套 setValue / value 走完三个平台。

5.1 三种构造方式 #

cpp
// 一、用默认的组织名与应用名（要先设好）
QCoreApplication::setOrganizationName("MyCompany");
QCoreApplication::setApplicationName("DataTool");
QSettings settings;                       // 后端按平台自动选

// 二、显式给组织与应用
QSettings settings("MyCompany", "DataTool");

// 三、直接指定文件与格式
QSettings settings("/etc/datatool/user.ini", QSettings::IniFormat);

第一种最省事，但有个前提：setOrganizationName 必须在第一次构造 QSettings 之前调用。名字是在构造时拼进路径的，之后再改不影响已经建好的实例。

5.2 NativeFormat 与 IniFormat #

QSettings::Format 的可选值：

枚举 含义 可用平台
QSettings::NativeFormat 平台原生后端（注册表 / plist / ini） 全平台
QSettings::IniFormat 强制用 INI 文件 全平台
QSettings::Registry32Format 32 位视图注册表 Windows
QSettings::Registry64Format 64 位视图注册表 Windows
QSettings::InvalidFormat 非法 —

要指定位置，就用 IniFormat 加绝对路径。这是唯一能让配置跟着程序走、或者放进 U 盘带走的方式：

cpp
QSettings settings(QDir(QCoreApplication::applicationDirPath()).filePath("user.ini"),
                   QSettings::IniFormat);

Windows 上 32 位程序在 64 位系统里，注册表被重定向到 WOW6432Node，另一个 64 位程序读同一个「逻辑路径」，读到的是另一份配置。要用跨位宽的同一份数据，显式指定 Registry64Format，或者干脆改用 INI 文件。键名用 '/' 分层，等价于 INI 的 [section]，等价于注册表的子键：settings.setValue("net/server/port", 8080) 落到 INI 里是 [net] 节下的 server\port=8080。

5.3 为什么不用自己写 ini #

手写 QSettings 的替代品有一堆小事要处理：读写编码、值里带换行和引号怎么转义、类型怎么存（bool 存成 "true" 还是 "1"）、多线程同时写会不会互相截断、写到一半进程被杀怎么办。QSettings 全替你做了，还顺手给了跨平台和三套后端。

代价是它的行为细节不透明，第七章讲清楚它到底写到哪、什么格式、什么时候真正落盘。

六、QSettings 的读写与分组 #

老代码里最常见的是一对封装函数，把路径、组名、键名都当参数传进去。

cpp
bool Util::writeInit(const QString &path, const QString &user_key, const QString &user_value)
{
    if (path.isEmpty() || user_key.isEmpty())
        return false;

    // 栈对象，出了作用域自动析构并落盘
    QSettings config(path, QSettings::IniFormat);
    config.beginGroup("config");
    config.setValue(user_key, user_value);
    config.endGroup();
    return true;
}

bool Util::readInit(const QString &path, const QString &user_key, QString &user_value)
{
    user_value.clear();
    if (path.isEmpty() || user_key.isEmpty())
        return false;

    QSettings config(path, QSettings::IniFormat);
    user_value = config.value("config/" + user_key).toString();
    return true;
}

调用端：

cpp
// 界面控件里取用户输入
QString address = address_line_edit->text();
QString port    = port_line_edit->text();

// 写进 user.ini
Util::writeInit("./user.ini", "address", address);
Util::writeInit("./user.ini", "port", port);

// 启动时读回来
QString address_value, port_value;
Util::readInit("./user.ini", "address", address_value);
Util::readInit("./user.ini", "port", port_value);

生成的文件长这样：

ini
[config]
address=192.168.1.100
port=8080

写法上有三个点值得说。一是别 new QSettings，老代码里 new 完不 delete，读配置的地方调用频繁，久了就是问题；栈对象析构时会 sync()，正好。二是 beginGroup / endGroup 与 "group/key" 两种写法等价，组名多了用前者，别混着用搞乱层级。三是读取用 value("config/" + user_key)，手工拼串容易漏斜杠，拼错的结果是读到空值、toString() 返回空串，不报错，contains() 能确认键到底在不在。

6.1 值的类型 #

setValue 收 QVariant，Qt 常见类型能直接存，读的时候用对应的 toXxx() 取。

类型 写入 读出
整数 setValue("a", 8080) value("a").toInt()
浮点 setValue("a", 3.14) value("a").toDouble()
布尔 setValue("a", true) value("a").toBool()
字符串 setValue("a", "text") value("a").toString()
字符串列表 setValue("a", QStringList{"x","y"}) value("a").toStringList()
日期时间 setValue("a", QDateTime::currentDateTime()) value("a").toDateTime()
尺寸 / 点 / 矩形 setValue("a", QSize(800,600)) value("a").toSize() / toPoint() / toRect()
字节串 setValue("a", QByteArray("...")) value("a").toByteArray()

读的时候一定要给默认值。配置项第一次运行必然不存在，toInt() 返回 0，toString() 返回空串，程序逻辑很容易被 0 带进沟里。

cpp
const int port = settings.value("net/port", 8080).toInt();       // 缺省 8080
const QString host = settings.value("net/host", "127.0.0.1").toString();

6.2 判断存在与删除 #

cpp
if (settings.contains("net/port")) { ... }   // 键存在
settings.remove("net/port");                 // 删单个键
settings.remove("net");                      // 删整组，连带子键
settings.clear();                            // 清空全部
QStringList keys = settings.allKeys();       // 所有键，形如 "net/port"

allKeys() 给的是完整路径串。只看一个组里的键，beginGroup("recent") 之后取 childKeys()，再 endGroup()。

6.3 数组 #

一组同类数据（最近打开的文件、多个服务器地址）别自己编号当键名，用数组接口。写用 beginWriteArray + setArrayIndex + endArray，读用 beginReadArray，它直接返回元素个数，endArray 收尾。落下时是 recent/1/path 这样的键，Qt 另存一个 size 记长度。

6.4 落盘时机 #

QSettings 不是每次 setValue 都写盘，它攒着，在三个时机同步：

  • 调 sync()，立刻写
  • 实例析构
  • 事件循环空闲时（内部有定时器）

要保证写下去，明说：

cpp
settings.setValue("net/port", port);
settings.sync();
if (settings.status() != QSettings::NoError)
    qWarning() << "配置写入失败";

status() 会告诉你 AccessError（路径不可写、权限不够）还是 FormatError（文件内容坏了）。配置写到 Program Files 下面这类只读目录，就是 AccessError，而且它是静默的，你不查就永远不知道用户设置没保存。

6.5 线程与实例 #

QSettings 是可重入的，不是线程安全的——多个线程同时用一个 QSettings 实例会出问题。做法很简单：每个线程各建各的实例，指向同一个文件。不同实例写同一文件时，Qt 用文件锁加重读保证不互相覆盖。代价是性能，频繁写配置的场合先在内存里攒，退出前一次性写。

七、配置文件的存储位置与格式 #

7.1 它到底写到哪 #

别猜，让它自己说。QSettings s(QSettings::IniFormat, QSettings::UserScope, "MyCompany", "DataTool"); 之后 s.fileName() 给的就是真正落盘的那个路径，三种典型输出：

text
Windows 注册表模式： HKEY_CURRENT_USER\Software\MyCompany\DataTool
Windows INI 模式：   C:/Users/you/AppData/Roaming/MyCompany/DataTool.ini
Linux INI 模式：     /home/you/.config/MyCompany/DataTool.conf

注意 Linux 上扩展名是 .conf 而不是 .ini，Qt 在 IniFormat 下按平台补后缀。

7.2 作用域 #

QSettings 的第二个参数 Scope 决定写用户区还是系统区：

Scope Windows Linux
QSettings::UserScope HKEY_CURRENT_USER ~/.config
QSettings::SystemScope HKEY_LOCAL_MACHINE /etc/xdg

SystemScope 需要管理员权限，普通用户写会拿到 AccessError。程序里存用户偏好一律用 UserScope。

7.3 改默认落点 #

不想每次构造都传路径，就改全局默认：

cpp
QSettings::setDefaultFormat(QSettings::IniFormat);        // 全平台统一走 ini
QSettings::setPath(QSettings::IniFormat, QSettings::UserScope, "/opt/myapp/conf");

setDefaultFormat 会让后面所有 QSettings settings; 都走 ini。setPath 把默认目录挪到别处，打包成绿色版、装进 U 盘、放进容器，都靠这两行。

QStandardPaths 里对应的位置：

枚举 用途
AppConfigLocation 本应用的配置目录，读写配置首选
AppDataLocation 本应用的数据目录，放导出物、缓存
ConfigLocation 所有应用的配置根目录
DocumentsLocation 文档目录，给用户存产物
TempLocation 临时目录，进程退出后会被清 
cpp
const QString dir = QStandardPaths::writableLocation(QStandardPaths::AppConfigLocation);
QDir().mkpath(dir);
QSettings settings(dir + "/user.ini", QSettings::IniFormat);

AppConfigLocation 在 Linux 上是 ~/.config/<组织>/<应用>，Windows 上是 AppData/Roaming/<组织>/<应用>。它建目录不会自动创建，mkpath 得自己调。

7.4 INI 里长什么样 #

ini
[net]
server\host=127.0.0.1
server\port=8080

[ui]
mainwindow\geometry=@ByteArray(\x1\xd9\xd0\xcb\0\x2\0\0...)
recent\1\path=/tmp/a.txt
recent\size=1

几个格式细节值得记：组名里的 / 被写成 \，这是 Qt 的 INI 方言，标准 ini 解析器读不了这种嵌套；字符串里有换行、引号、首尾空格时，Qt 会加引号并转义；QByteArray 写成 @ByteArray(...)，自定义类型写成 @Variant(...)；文件编码是 UTF-8，中文直接写进去不转义。

7.5 注册表模式的两个坑 #

Windows 下用 NativeFormat（默认）时，配置进注册表，两个问题必须知道。一是位数重定向：32 位程序访问 Software\MyCompany 实际落在 Software\WOW6432Node\MyCompany，同一个程序出了 32 位和 64 位两个版本，用户会发现「设置不通用」。二是键名大小写：注册表不区分，Linux 的 ini 区分，代码里 value("Net/Port") 在 Windows 能读到 net/port，到 Linux 就是空值，键名从一开始就统一小写。

跨平台程序最省事的做法：开局一行 setDefaultFormat(QSettings::IniFormat)，全平台都落文件，行为一致，调试时还能直接打开看。

八、Excel 的两条路 #

Qt 自己没有 Excel 支持。能干这活的只有两条路，外加一个退路。

维度 QXlsx COM（QAxObject） CSV
依赖 只要 Qt，加一个第三方库 装了 Office 或兼容 WPS 无
平台 Windows / Linux / macOS / Android / 嵌入式 只有 Windows 全平台
读写速度 中，直接拼 XML 慢，进程间 COM 调用 快，纯 IO
内存 中，整份文档建在内存里 高，另起一个 Excel 进程 低
格式能力 样式、公式、基础图表 Excel 对象模型全量 纯文本，无格式
文件格式 只能 xlsx xls / xlsx / xlsm / pdf 都能导 文本
典型场景 跨平台报表、客户机器没装 Office 调 Excel 宏、打印排版、复杂图表 海量数据、系统间交换

选择顺序很明确：

text
要跨平台            -> QXlsx
客户机器上没有 Office -> QXlsx
要宏 / 打印排版 / 复杂图表 -> COM
剩下的情况          -> QXlsx

COM 那条路的隐性成本在于它真的会启动 EXCEL.EXE。用户能看到窗口闪一下（或者后台进程残留），杀毒软件会拦，服务器上跑更是一场灾难。不是非它不可，就别选。

8.1 CSV 为什么只能当退路 #

CSV 没有格式、没有类型，日期和数字都是字符串。它的价值在两个地方：百万行级别的导出，它比 xlsx 快一个数量级；系统间交换数据，谁都读得动。

真要用 CSV，别用 QString::split(',')。字段里带逗号（"Doe, John"）就切错了。按 RFC 4180 来：

cpp
QString toCsvField(const QString &text)
{
    if (text.contains(',') || text.contains('"') || text.contains('\n')) {
        QString temp = text;
        temp.replace('"', "\"\"");     // 内部双引号翻倍
        return "\"" + temp + "\"";     // 整体包一层引号
    }
    return text;
}

读的时候同理，得用状态机扫字符：遇到引号进入引号内模式，引号内的 "" 算一个转义引号，逗号只在引号外才算分隔符。写个三十行的解析器不算难，但别用正则硬凑。

九、QXlsx：读写 xlsx #

9.1 xlsx 到底是什么 #

.xlsx 不是二进制表格，它是一个 zip 包。把后缀改成 .zip 解开，里面是一堆 XML：

路径 内容
xl/worksheets/sheet1.xml 单元格数据
xl/sharedStrings.xml 共享字符串，重复文本只存一份
xl/styles.xml 字体、颜色、边框
[Content_Types].xml 包结构描述

QXlsx 不启动 Excel，它直接按 OOXML 规范写这些 XML，再压成 zip。所以它跨平台，也不需要客户机器装 Office。

9.2 选版本 #

GitHub 上星最多的 dbzhang800/QtXlsxWriter 停在 2014 年前后，别用。生产环境用活跃分支 QtExcel/QXlsx。qmake 工程按源码引入，静态链接报错时加 DEFINES += XLSX_NO_LIB 让编译器直接吃源码：

QT += core gui
include(3rdparty/QXlsx/QXlsx.pri)   # 路径按实际目录改
DEFINES += XLSX_NO_LIB

CMake 工程换成：

cmake
add_subdirectory(3rdparty/QXlsx)
target_link_libraries(YourApp PRIVATE QXlsx::QXlsx)

代码里引头文件 #include "xlsxdocument.h" 和 #include "xlsxformat.h"。

9.3 写一份带样式的报表 #

cpp
void generateReport()
{
    QXlsx::Document xlsx;

    // 样式对象建在循环外，避免每行都新建一份
    QXlsx::Format headerFormat;
    headerFormat.setFontBold(true);
    headerFormat.setFontColor(Qt::white);
    headerFormat.setPatternBackgroundColor(QColor("#4472C4"));

    xlsx.write("A1", "时间", headerFormat);
    xlsx.write("B1", "数值", headerFormat);

    // 按行顺序写，减少 XML 游标来回跳
    for (int row = 2; row <= 10000; ++row) {
        xlsx.write(row, 1, QDateTime::currentDateTime());   // 自动识别成日期
        xlsx.write(row, 2, row * 1.5);
    }

    if (!xlsx.saveAs("Report.xlsx"))
        qCritical() << "保存失败";
}

write() 有两种寻址：write("A1", value) 用 Excel 坐标，write(row, col, value) 用行列号。两者都从 1 开始，write(1,1,...) 是 A1。

值传 QVariant，QDateTime、QDate、double、QString 都能自动选对单元格类型。

9.4 公式与读取 #

写公式就是写一个以 = 开头的字符串：

cpp
xlsx.write("C2", "=SUM(A2:B2)");
xlsx.write("D2", "=AVERAGE(A2:A100)", headerFormat);

读的时候：

接口 作用
QXlsx::Document xlsx("file.xlsx") 打开已有文件
xlsx.read(row, col) 读单元格，返回 QVariant
xlsx.read("A1") 同上，坐标式
xlsx.currentWorksheet()->dimension() 取已用区域，形如 A1:Z100
xlsx.selectSheet(name) 切工作表 
cpp
QXlsx::Document xlsx("Report.xlsx");
if (!xlsx.load())
    return;

const QXlsx::CellRange range = xlsx.currentWorksheet()->dimension();
for (int r = range.firstRow(); r <= range.lastRow(); ++r) {
    for (int c = range.firstColumn(); c <= range.lastColumn(); ++c) {
        const QVariant v = xlsx.read(r, c);
        if (!v.isValid())
            continue;                    // 空单元格返回无效 QVariant
        qDebug() << r << c << v.toString();
    }
}

先拿 dimension() 定边界，再按边界遍历。不这么干就是逐格试探，几十万次无效读取。

9.5 合并单元格与冻结窗格 #

操作 接口 例子
合并 mergeCells(range, format) xlsx.mergeCells("A1:D1", headerFormat)
取消合并 unmergeCells(range) xlsx.unmergeCells("A1:D1")
冻结首行 Worksheet::setFreezePane(1, 0) 第 1 行以上冻结
冻结首列 Worksheet::setFreezePane(0, 1) 第 1 列以左冻结
冻结行列 Worksheet::setFreezePane(1, 1) A1 左上，行列都冻

setFreezePane(row, col) 的参数是冻结线下方与右侧的起始位置。(1, 0) 意思是「第 1 行往下才是滚动区」，也就是首行被钉住。

其他格式接口还有 setColumnWidth() / setRowHeight() 调行列尺寸，Format::setHorizontalAlignment() / setVerticalAlignment() 调对齐，Format::setBorderStyle() 设边框，Format::setTextWrap() 自动换行。

9.6 大文件与已知限制 #

QXlsx 是 DOM 模式，整份文档都建在内存里，行数上到几十万就撞墙。

场景 做法
写大文件 分批写、定期 saveAs()；循环外建 Format 对象
读大文件 没有流式接口，先看 dimension() 只读必要区域
真要读超大文件 自己解压 xlsx，用 SAX 扫 sheet1.xml；或者换 libxlsxwriter 只管写
百万行导出 直接出 CSV，让用户用 Excel 打开另存

另外三条限制：图表只支持基础类型，复杂可视化截图当图片插；受密码保护的文件支持不完整；只写 xlsx，不写 xls，也不导 pdf。所以它不适合「把 Excel 当数据库」的用法，要那么干，该上数据库。

十、COM 方式操作 Excel #

Windows 上还有另一条路：ActiveQt 模块里的 QAxObject，通过 COM 直接驱动本机的 Excel 进程。本质是拿 C++ 去调 Excel 的 VBA 接口，所以 VBA 里能干的它都能干。

10.1 工程配置 #

QT += axcontainer

这个模块只有 Windows 有，Linux 和 macOS 上 qmake 会直接报找不到模块。跨平台工程用 win32 { ... } 把它包起来，顺手加个 DEFINES += HAVE_EXCEL_COM 供代码里判断。

源文件头部：

cpp
#include <QAxObject>
#include <QDebug>
#include <QColor>

10.2 读一份已有的表 #

cpp
void readExcel(const QString &filePath)
{
    // 关联 Excel 进程，机器上必须装了 Excel 或兼容的 WPS
    QAxObject excel("Excel.Application");
    excel.setProperty("Visible", false);          // 后台静默

    QAxObject *workbooks = excel.querySubObject("Workbooks");
    QAxObject *workbook = workbooks->querySubObject("Open(const QString&)", filePath);
    if (!workbook) {
        qWarning() << "打开失败:" << filePath;
        excel.dynamicCall("Quit()");
        return;
    }

    // 工作表集合
    QAxObject *sheets = workbook->querySubObject("Sheets");
    const int sheetCount = sheets->property("Count").toInt();
    qDebug() << "工作表数量:" << sheetCount;

    for (int i = 1; i <= sheetCount; ++i) {
        QAxObject *sheet = workbook->querySubObject("Sheets(int)", i);
        qDebug() << i << sheet->property("Name").toString();
    }

    // 第一个表的已用区域，自动算出边界，不用自己数
    if (sheetCount > 0) {
        QAxObject *sheet = workbook->querySubObject("Sheets(int)", 1);
        QAxObject *usedRange = sheet->querySubObject("UsedRange");

        const int startRow = usedRange->property("Row").toInt();
        const int startCol = usedRange->property("Column").toInt();
        const int rowCount = usedRange->querySubObject("Rows")->property("Count").toInt();
        const int colCount = usedRange->querySubObject("Columns")->property("Count").toInt();

        // VBA 的行列索引从 1 开始，和 C++ 不一样
        for (int r = startRow; r < startRow + rowCount; ++r) {
            for (int c = startCol; c < startCol + colCount; ++c) {
                QAxObject *cell = sheet->querySubObject("Cells(int,int)", r, c);
                qDebug() << r << c << cell->property("Value").toString();
            }
        }
    }

    workbook->dynamicCall("Close(Boolean)", false);   // false = 不保存
    excel.dynamicCall("Quit()");
}

querySubObject 是 COM 调用的入口，字符串里写的是 VBA 的方法名和参数签名。dynamicCall 用于没有返回值的调用。

10.3 新建、排版、合并 #

cpp
void createAndStyleExcel(const QString &savePath)
{
    QAxObject excel("Excel.Application");
    excel.setProperty("Visible", true);

    QAxObject *workbooks = excel.querySubObject("Workbooks");
    QAxObject *workbook = workbooks->querySubObject("Open(const QString&)", savePath);
    QAxObject *sheets = workbook->querySubObject("Sheets");

    // 删掉第一个表
    sheets->querySubObject("Item(int)", 1)->dynamicCall("delete");

    // 在末尾加一个表并改名
    const int count = sheets->property("Count").toInt();
    QAxObject *lastSheet = sheets->querySubObject("Item(int)", count);
    QAxObject *newSheet = sheets->querySubObject("Add(QVariant)", lastSheet->asVariant());
    lastSheet->dynamicCall("Move(QVariant)", newSheet->asVariant());
    newSheet->setProperty("Name", "数据表");

    // 定位单元格，写值、调行高列宽
    QAxObject *cell = newSheet->querySubObject("Cells(int,int)", 2, 2);
    cell->setProperty("Value", "Qt 导出报表");
    cell->setProperty("RowHeight", 40);
    cell->setProperty("ColumnWidth", 30);

    // 对齐：-4108 是 xlCenter
    cell->setProperty("HorizontalAlignment", -4108);
    cell->setProperty("VerticalAlignment", -4108);
    cell->setProperty("WrapText", true);

    // 背景色与边框
    cell->querySubObject("Interior")->setProperty("Color", QColor(220, 245, 220));
    cell->querySubObject("Borders")->setProperty("Color", QColor(0, 0, 255));

    // 字体
    QAxObject *font = cell->querySubObject("Font");
    font->setProperty("Name", QStringLiteral("微软雅黑"));
    font->setProperty("Size", 14);
    font->setProperty("Bold", true);
    font->setProperty("Italic", false);
    font->setProperty("Underline", 0);            // 1 单下划线，2 双下划线
    font->setProperty("Color", QColor(255, 0, 0));

    // 合并 C5:E8 并居中
    QAxObject *range = newSheet->querySubObject("Range(const QString&)", "C5:E8");
    range->setProperty("Value", "合并区");
    range->setProperty("HorizontalAlignment", -4108);
    range->setProperty("VerticalAlignment", -4108);
    range->setProperty("MergeCells", true);       // 拆分改 false

    workbook->dynamicCall("SaveAs(const QString&)", "E:\\StyledReport.xlsx");
    workbook->dynamicCall("Close(Boolean)", true);
    excel.dynamicCall("Quit()");
}

10.5 进程残留是最大的坑 #

QAxObject excel("Excel.Application") 起的是一个真实进程。Quit() 只是让它退出，子对象还握着 COM 引用，引用计数不归零，EXCEL.EXE 就赖在任务管理器里。收尾顺序固定：Close(Boolean) → Quit() → 逐个 delete 子对象，别指望作用域结束就干净。

进程泄漏的后果是累积的：用户点十次导出，任务管理器里十个 EXCEL.EXE，每个吃几十 MB。抓到这种 bug 别怀疑 COM 本身，先数进程。

另外两条：Visible = true 会让窗口抢焦点，批量导出时务必设 false；把这段代码放进 Windows 服务里跑，会遇到 DCOM 身份与桌面会话问题，跑不通是常态，那时候该换 QXlsx。

十一、导出报表的实践 #

把前面三块拼起来，就是一个完整的导出流程：遍历目录拿数据源、按 QXlsx 写表、把用户的选择记进 QSettings。

11.1 先定格式再写代码 #

数据规模 选什么 原因
几千行，要样式 QXlsx 快、无依赖、样式够用
十万行以上 CSV xlsx 的内存扛不住
要宏、要打印排版 COM 只有它能调 Excel 全量接口
客户机器不确定装没装 Office QXlsx 不赌环境

11.2 记住上次的导出目录 #

导出对话框每次都从「文档」开始，用户体验很差。把上一次的目录存进配置，下次直接定位：

cpp
QSettings settings(m_iniPath, QSettings::IniFormat);
const QString lastDir = settings.value("export/lastDir",
        QStandardPaths::writableLocation(QStandardPaths::DocumentsLocation)).toString();
const QString path = QFileDialog::getSaveFileName(this, "导出报表", lastDir, "Excel (*.xlsx)");
if (path.isEmpty())
    return;
settings.setValue("export/lastDir", QFileInfo(path).absolutePath());
settings.sync();   // 程序被强杀也不丢

文件名带个时间戳再落盘，QDateTime::currentDateTime().toString("yyyyMMdd_hhmmss") 拼进名字就行。覆盖用户上次的报表等于毁掉一次工作，导出前也可以 QFileInfo::exists() 探一次再问用户。

11.3 批量导出：遍历 + 落表 #

一个目录一批源文件，逐个读出来写进同一个工作簿：

cpp
void exportFolder(const QString &srcDir, const QString &outFile)
{
    QXlsx::Format header;
    header.setFontBold(true);
    header.setPatternBackgroundColor(QColor("#4472C4"));
    header.setFontColor(Qt::white);

    QXlsx::Document xlsx;
    xlsx.write("A1", "文件", header);
    xlsx.write("B1", "大小", header);
    xlsx.write("C1", "修改时间", header);

    int row = 2;
    QDirIterator it(srcDir, QStringList() << "*.csv" << "*.txt",
                    QDir::Files | QDir::NoSymLinks,
                    QDirIterator::Subdirectories);
    while (it.hasNext()) {
        it.next();
        const QFileInfo info = it.fileInfo();
        xlsx.write(row, 1, info.fileName());
        xlsx.write(row, 2, static_cast<double>(info.size()));
        xlsx.write(row, 3, info.lastModified());
        ++row;

        if (row % 500 == 0)
            QCoreApplication::processEvents();   // 大目录别让界面假死
    }

    xlsx.write(row, 1, "合计");
    xlsx.write(row, 2, QString("=SUM(B2:B%1)").arg(row - 1));

    if (!xlsx.saveAs(outFile))
        qCritical() << "导出失败:" << outFile;
}

三件事在这段代码里同时发生：QDirIterator 递归取源文件、QFileInfo 出元信息、QXlsx 写表加公式。

11.4 失败要报告，不是吞掉 #

批量导出必有失败项：文件被占用、权限不够、单个表坏了。别 return 了事，把失败清单攒进一个 QStringList，循环里 failed << info.absoluteFilePath()，收尾时用 QMessageBox::warning 一次性列给用户。静默跳过，等着被投诉。

十二、易错点速查 #

现象 原因 处理
遍历大目录界面卡住 用了 entryInfoList()，整个目录进内存 换 QDirIterator，边取边处理
递归遍历死循环 漏了 it.next() while (it.hasNext()) { it.next(); ... }
*.jpg 匹配不到 .JPG setNameFilters 区分大小写 去掉名字过滤，用 suffix() + Qt::CaseInsensitive 比
读到的每行末尾多个怪字符 打开时没加 QIODevice::Text 加 Text，读时转掉 \r
中文文件内容乱码 Qt 5 默认用本地编码（GBK） setCodec("UTF-8")，Qt 6 用 setEncoding(QStringEnum::Utf8)
配置写不进去，还不报错 目录只读，status() 没查 写后 sync() + 查 status()
程序重启配置没了 构造了临时 QSettings，没 sync() 就崩了 改完显式 sync()
Linux 上读不到配置而 Windows 正常 键名大小写：注册表不敏感，ini 敏感 键名统一小写
32/64 位程序配置不通用 注册表 WOW6432Node 重定向 显式 Registry64Format，或全平台改 INI
导出 xlsx 全是空单元格 saveAs() 前进程退出 / 未 commit 检查 saveAs 返回值
任务管理器里一堆 EXCEL.EXE COM 子对象没释放，引用计数不归零 Close → Quit → delete 子对象
Linux 编译报找不到 axcontainer ActiveQt 只有 Windows 用 win32 {} 包起来，或直接换 QXlsx
COM 读取越界，最后一列丢了 VBA 索引从 1 开始，UsedRange 起始不一定为 1 用 Row / Column 取起点再加 Count
单元格 read() 返回无效值 空单元格返回无效 QVariant isValid() 判一下再取
QByteArray 塞进配置后读出来带转义 QSettings 把它写成 @ByteArray(...) 换成文件另存，配置只放标量

几句收尾的判断：

配置这层，开局一行 setDefaultFormat(QSettings::IniFormat) 能省掉后面一整类跨平台麻烦。要位置可控就传绝对路径，别依赖默认目录。

目录遍历这层，先问自己目录有多大。过万就默认上 QDirIterator，别等用户按了「打开素材库」才发现白屏。

Excel 这层，默认选 QXlsx。只有在「确定是 Windows」「确定装了 Office」「确定需要 Excel 独有能力」三条同时成立时，才动 COM。
