开篇边界说明

讲什么：程序怎么知道自己跑在什么机器上。CPU 型号与核数、物理内存与虚拟内存、磁盘容量、系统版本、标准目录、屏幕参数，以及 Qt 里拿到这些数字的具体写法。 不讲什么：不做性能调优，不讲显卡与驱动查询，不引第三方采集库（libstatgrab、psutil 这一类），不讲监控服务的部署与上报链路。 跨篇指路：进程与资源占用的关系看同目录《进程：QProcess 与单实例控制》；把采集结果上报服务端看《Qt 网络编程：TCP、UDP 与 HTTP》；结果存成配置文件看《文件、配置与表格》；结果入库看《数据库：SQLite 与 MySQL》。

一、为什么程序要知道系统信息 #

写客户端时，早晚会碰到「让程序报一下自己跑在哪台机器上」的需求。诊断面板、性能监视器、状态条、崩溃日志头、安装器预检查，都是同一件事的不同外壳。

这些需求归成六类：

  • 展示类。状态栏一行「i7-12700 / 32 GB / 可用 18.4 GB」，用户扫一眼就知道机器状态。
  • 降级类。内存小于 4 GB 关掉图片缓存，核数小于 4 把并行任务数压到 2。
  • 排障类。崩溃日志带上系统版本、内核版本、CPU 架构，远程定位能省掉三轮来回问。
  • 预检类。安装器先看磁盘剩余空间和 CPU 架构，不满足就拦在门口。
  • 上报类。埋点数据带机器画像，按机型做统计。
  • 自检类。程序内部跑个基准，用核数决定线程池大小。

第一反应往往是「Qt 里有没有现成接口」。答案是有，但只覆盖了一小半。

这里就是这类需求最根本的一条限制——Qt 只封装了「跨平台那一小部分」系统信息。QSysInfo 给你系统名与架构，QStorageInfo 给你磁盘容量，QStandardPaths 给你标准目录，这些跨平台，写一遍跑三端。但具体到 CPU 型号字符串、内存总量与可用量、CPU 使用率，Qt 一个都不给。原因不复杂：这些值在三个平台上语义就不一样，硬封装一个「统一接口」出来，字段含义会打架，维护成本高过收益。Qt 选择不做，把活留给调用方。

剩下的活只能掉到平台 API。Linux 读 /proc 下的伪文件，Windows 调 Win32 接口。这是本篇的主线。

需求 Qt 有跨平台接口吗 没有时去哪拿
系统名与版本 有，QSysInfo::prettyProductName() 不用掉平台
内核类型与版本 有，QSysInfo::kernelType() / kernelVersion() 不用掉平台
CPU 架构 有，QSysInfo::currentCpuArchitecture() 不用掉平台
逻辑核数 有，QThread::idealThreadCount() 够用，多数场景不必再查
CPU 型号字符串 没有 Linux 读 /proc/cpuinfo；Windows 读注册表或走 __cpuid
CPU 使用率 没有 Linux 两次读 /proc/stat 求差；Windows 两次调 GetSystemTimes 求差
物理内存总量与可用量 没有 Linux 读 /proc/meminfo；Windows 调 GlobalMemoryStatusEx
交换区 / 页面文件 没有 Linux 看 SwapTotal / SwapFree；Windows 看 ullTotalPageFile / ullAvailPageFile
虚拟内存限额 没有 Linux 看 CommitLimit / Committed_AS；Windows 看 ullTotalVirtual / ullAvailVirtual
磁盘总容量与可用容量 有，QStorageInfo::bytesTotal() / bytesAvailable() 不用掉平台
文件系统类型 有，QStorageInfo::fileSystemType() 不用掉平台
标准目录（下载、配置、缓存） 有，QStandardPaths 不用掉平台
屏幕分辨率与 DPI 有，QScreen 不用掉平台
主机名 有，QSysInfo::machineHostName() 不用掉平台

读法：左列是你要的东西，中列写「有」的直接调 Qt，写「没有」的往右列走。中间那条分界线，就是本篇要反复跨越的地方。

连带一条结论：跨平台封装不等于跨平台取值。你可以写一个 SystemMonitor 类，对外签名全平台一致，类内部一定是 #ifdef 分叉。接口统一了，实现没有统一。认清这点，后面就不会执着于「找一个跨平台的 CPU 型号 API」——它不存在。

二、QSysInfo：系统与版本 #

QSysInfo 是 Qt 里最省事的一块。全静态方法，不用构造对象，#include <QSysInfo> 即可。

cpp
#include <QSysInfo>
#include <QDebug>
#include <QThread>

void dumpSysInfo()
{
    qDebug() << "产品名:"   << QSysInfo::prettyProductName();
    qDebug() << "产品类型:" << QSysInfo::productType();
    qDebug() << "产品版本:" << QSysInfo::productVersion();
    qDebug() << "内核类型:" << QSysInfo::kernelType();
    qDebug() << "内核版本:" << QSysInfo::kernelVersion();
    qDebug() << "当前架构:" << QSysInfo::currentCpuArchitecture();
    qDebug() << "构建架构:" << QSysInfo::buildCpuArchitecture();
    qDebug() << "构建 ABI:" << QSysInfo::buildAbi();
    qDebug() << "主机名:"   << QSysInfo::machineHostName();
    qDebug() << "逻辑核数:" << QThread::idealThreadCount();
}

几个字段的定位容易混，拆开看：

方法 返回什么 典型值 用在哪
prettyProductName() 给人看的完整系统名 Windows 11 (10.0) 界面展示、日志抬头
productType() 小写机器判断用系统代号 windows / ubuntu / debian 分支判断
productVersion() 系统版本号 10 / 22.04 版本比较、上报字段
kernelType() 内核类别 winnt / linux / darwin 底层能力判断
kernelVersion() 内核版本 6.8.0-45-generic 排障日志
currentCpuArchitecture() 当前进程跑的架构 x86_64 / arm64 选二进制、选算法分支
buildCpuArchitecture() 编译时的架构 x86_64 判断是否交叉编译产物

productType() 返回小写串而不是枚举，拼错不报错，只会静默走进 else 分支。这是它最容易踩的地方。想稳一点，包一层枚举：

cpp
enum class OsKind { Windows, Linux, Mac, Other };

OsKind currentOsKind()
{
    const QString t = QSysInfo::productType();
    if (t == QLatin1String("windows")) return OsKind::Windows;
    if (t == QLatin1String("macos") || t == QLatin1String("osx")) return OsKind::Mac;
    if (t == QLatin1String("ubuntu") || t == QLatin1String("debian")
        || t == QLatin1String("fedora") || t == QLatin1String("arch")) return OsKind::Linux;
    return OsKind::Other;
}

productType() 在 Linux 上返回发行版代号，不是笼统的 linux。想一网打尽所有发行版，别靠它，看编译期宏 Q_OS_LINUX，或者看 kernelType() == "linux"。

版本比较别自己拆字符串，QOperatingSystemVersion 把这件事办好了：

cpp
#include <QOperatingSystemVersion>

void checkOsVersion()
{
    const QOperatingSystemVersion cur = QOperatingSystemVersion::current();
    qDebug() << cur.majorVersion() << cur.minorVersion() << cur.microVersion();

    if (cur >= QOperatingSystemVersion::Windows10) qDebug() << "Win10 及以上";
    if (cur >= QOperatingSystemVersion(QOperatingSystemVersion::Windows, 10, 0, 22000))
        qDebug() << "Win11 及以上";
}

它支持 >=、< 这类比较运算符。判断 Win11 用构建号 22000 这条分界线，这是公开的版本分界，不是猜的。

两个唯一 ID 方法顺带提一句：machineUniqueId() 标识机器，bootUniqueId() 标识本次启动。取不到时返回空串，别当数据库主键硬依赖——换机器、重装系统、容器重建，值都会变。

三、CPU 信息与核数 #

核数先看 Qt 给的答案。

cpp
#include <QThread>

int cores = QThread::idealThreadCount();

它返回系统报告的逻辑处理器数量，含超线程。8 核 16 线程的机器，它返回 16。拿它定线程池大小合适，拿它当「物理核数」展示给用户就错了。

物理核与逻辑核的区别，在 Linux 上得靠 /proc/cpuinfo 自己算。这个文件是「一块一块」的结构：每个逻辑处理器一段，段内 键 : 值，段间空行。

text
processor	: 0
vendor_id	: GenuineIntel
model name	: 12th Gen Intel(R) Core(TM) i7-12700
cpu MHz		: 2100.000
cache size	: 25600 KB
physical id	: 0
siblings	: 20
core id		: 0
cpu cores	: 12

processor	: 1
...
字段 含义 备注
processor 逻辑处理器编号 出现几次就是几个逻辑核
model name CPU 型号字符串 x86 上有，部分 ARM 平台没这个键
cpu MHz 当前主频 随调频变化，不是标称频率
cache size 末级缓存大小 部分平台不提供
physical id 物理 CPU 插槽编号 多路机器上区分两颗 CPU
core id 该插槽内的物理核编号 与 physical id 组合才唯一
siblings 同插槽的逻辑核数 除以 cpu cores 就是超线程倍数
cpu cores 同插槽的物理核数 拿物理核数的关键字段

两个数字的算法要分清：逻辑核数 = processor 行出现次数；物理核数 = 所有 (physical id, core id) 组合去重后的数量。素材里数 processor 行的写法最简单，实际项目里一份文件顺手把型号与物理核一起解出来更划算：

cpp
#include <QFile>
#include <QTextStream>
#include <QSet>

struct CpuBrief
{
    QString modelName;
    int logicalCores  = 0;
    int physicalCores = 0;
};

CpuBrief readLinuxCpu()
{
    CpuBrief out;
    QFile f(QStringLiteral("/proc/cpuinfo"));
    if (!f.open(QIODevice::ReadOnly | QIODevice::Text)) return out;

    QSet<QString> keys;              // "physical id/core id" 去重集合
    QTextStream in(&f);
    QString pid, cid;
    auto flushSeg = [&] {            // 一段结束，记下「插槽/核」二元组
        if (!pid.isEmpty() && !cid.isEmpty()) keys.insert(pid + QLatin1Char('/') + cid);
        pid.clear();
        cid.clear();
    };
    while (!in.atEnd()) {
        const QString line = in.readLine();
        if (line.trimmed().isEmpty()) { flushSeg(); continue; }
        const int colon = line.indexOf(QLatin1Char(':'));
        if (colon < 0) continue;
        const QString k = line.left(colon).trimmed();
        const QString v = line.mid(colon + 1).trimmed();
        if (k == QLatin1String("processor"))        ++out.logicalCores;
        else if (k == QLatin1String("model name")) { if (out.modelName.isEmpty()) out.modelName = v; }
        else if (k == QLatin1String("physical id")) pid = v;
        else if (k == QLatin1String("core id"))     cid = v;
    }
    flushSeg();
    out.physicalCores = keys.isEmpty() ? out.logicalCores : keys.size();
    return out;
}

最后那行兜底有讲究。ARM 平台的 /proc/cpuinfo 常常没有 physical id 和 core id，去重集合为空。这时候退化成逻辑核数，比返回 0 强。

型号字段名也别写死。x86 是 model name，部分 ARM 板子写成 Processor、Hardware、model name 混着来。要通用就按优先级挨个试，试不到留空——界面上显示「未知型号」，比显示一串乱码体面。

Windows 上拿核数与分页规格走 GetSystemInfo，素材给全了：

cpp
#ifdef Q_OS_WIN
#include <windows.h>
#endif
#include <QDebug>

void getWindowsCpuInfo()
{
#ifdef Q_OS_WIN
    SYSTEM_INFO si;
    GetSystemInfo(&si);
    qDebug() << "逻辑处理器个数:" << si.dwNumberOfProcessors;
    qDebug() << "处理器掩码:"     << si.dwActiveProcessorMask;
    qDebug() << "分页大小:"       << si.dwPageSize;
    qDebug() << "处理器类型:"     << si.dwProcessorType;
    qDebug() << "架构级别:"       << si.wProcessorLevel;
    qDebug() << "修正版本:"       << si.wProcessorRevision;
    qDebug() << "最小寻址单元:"   << si.lpMinimumApplicationAddress;
    qDebug() << "最大寻址单元:"   << si.lpMaximumApplicationAddress;
#endif
}

字段的实际用途要说清，不然容易被当成凑数的：

字段 真实含义 什么时候用
dwNumberOfProcessors 逻辑处理器数 定线程池大小，等价于 idealThreadCount()
dwActiveProcessorMask 活动处理器位掩码 绑核用，老接口
dwPageSize 内存页大小 做内存对齐、算页数
dwProcessorType 处理器类型 历史字段，别拿它判架构
wProcessorLevel / wProcessorRevision 家族号与步进 排障时附进日志
lpMinimumApplicationAddress / lpMaximumApplicationAddress 可用地址空间范围 看 32 位程序在 64 位系统上的余量

判架构别看 dwProcessorType，看 si.wProcessorArchitecture，或者直接用 QSysInfo::currentCpuArchitecture()。32 位进程跑在 64 位系统上时，GetSystemInfo 返回的是「当前进程视角」，想要机器真实架构得调 GetNativeSystemInfo。

CPU 型号字符串，Win32 里没有直接接口。常见做法是读注册表：

cpp
#include <QSettings>

QString windowsCpuModelName()
{
    QSettings reg(
        QStringLiteral("HKEY_LOCAL_MACHINE\\HARDWARE\\DESCRIPTION\\System\\CentralProcessor\\0"),
        QSettings::NativeFormat);
    return reg.value(QStringLiteral("ProcessorNameString")).toString().trimmed();
}

这条路在主流 Windows 版本上都成立，读不到返回空串。想更底层还有 __cpuid 取 0x80000002 到 0x80000004 三个叶子里的厂商串，但代码量大，日常需求用注册表足够。

四、内存信息 #

内存比 CPU 更麻烦，因为有四个容易混的概念：物理内存总量、物理内存可用量、交换区、虚拟内存限额。四者语义不同，报给用户时混着说，用户就会问「我 32 GB 内存，你怎么说只剩 8 GB」。

先看 Windows，一个 MEMORYSTATUSEX 全拿到：

cpp
#ifdef Q_OS_WIN
#include <windows.h>
#endif
#include <QDebug>

// 字节转 MB。用常量不用宏，避免和别的头文件撞名
static constexpr quint64 kMb = 1024ull * 1024ull;

void getWindowsMemoryInfo()
{
#ifdef Q_OS_WIN
    MEMORYSTATUSEX statex;
    statex.dwLength = sizeof(statex);   // 必须在调用前赋值结构体长度
    if (GlobalMemoryStatusEx(&statex))
    {
        qDebug() << "物理内存使用率 (%):"    << statex.dwMemoryLoad;
        qDebug() << "物理内存总量 (MB):"     << statex.ullTotalPhys / kMb;
        qDebug() << "可用物理内存 (MB):"     << statex.ullAvailPhys / kMb;
        qDebug() << "页面文件总大小 (MB):"   << statex.ullTotalPageFile / kMb;
        qDebug() << "可用页面文件大小 (MB):" << statex.ullAvailPageFile / kMb;
        qDebug() << "虚拟内存总大小 (MB):"   << statex.ullTotalVirtual / kMb;
        qDebug() << "可用虚拟内存大小 (MB):" << statex.ullAvailVirtual / kMb;
    }
#endif
}

dwLength 那一行是硬性要求。不赋值就调，接口返回失败，statex 里全是 0，你还以为机器没内存。这个坑每个写 Win32 的人都踩过一次。

七个字段的语义：

字段 单位 含义 说明
dwMemoryLoad 百分比 物理内存使用率 系统给的近似值，别和公式结果做等值比较
ullTotalPhys 字节 物理内存总量 系统可用部分，不是主板插的条数总和
ullAvailPhys 字节 可立即分配的物理内存 对应「可用」，不是「空闲」
ullTotalPageFile 字节 页面文件上限 含物理内存提交上限，不只是 pagefile.sys 大小
ullAvailPageFile 字节 剩余提交量 提交内存耗尽时会先在这里报警
ullTotalVirtual 字节 当前进程虚拟地址空间上限 进程视角，不是整机
ullAvailVirtual 字节 当前进程剩余可提交量 同上

ullTotalVirtual 与 ullTotalPageFile 差着一个量级，因为它们根本不是一个东西：前者是进程地址空间，后者是系统提交限额。界面上给用户看「虚拟内存」，要显示 ullTotalPageFile，不是 ullTotalVirtual。

想拿「主板实际插了多少」，ullTotalPhys 不够——它扣掉了内核与硬件保留部分。GetPhysicallyInstalledSystemMemory 从 SMBIOS 读，返回单位是 KB。

Linux 换一套词。/proc/meminfo 是一份纯文本的 键: 值 单位 清单：

text
MemTotal:       32624560 kB
MemFree:         1234567 kB
MemAvailable:   18432100 kB
Buffers:          345678 kB
Cached:         12345678 kB
SwapTotal:       8388604 kB
SwapFree:        8388604 kB
Slab:             456789 kB
CommitLimit:    24695884 kB
Committed_AS:    5432100 kB

注意单位。内核写的 kB 实际是 KiB，1024 字节，不是 1000 字节。除以 1024 得 MB，别再除一次 1000。

读取代码，素材里的写法照搬，只把过时的 QString::SkipEmptyParts 换成 Qt::SkipEmptyParts：

cpp
#include <QFile>
#include <QTextStream>

struct MemBrief
{
    qint64 totalKb = 0;
    qint64 availKb = 0;
    qint64 freeKb  = 0;
    qint64 swapTotalKb = 0;
    qint64 swapFreeKb  = 0;
    double usagePercent = 0.0;
};

MemBrief readLinuxMem()
{
    MemBrief out;
    QFile f(QStringLiteral("/proc/meminfo"));
    if (!f.open(QIODevice::ReadOnly | QIODevice::Text)) return out;

    QTextStream in(&f);
    while (!in.atEnd()) {
        const QStringList parts =
            in.readLine().split(QLatin1Char(' '), Qt::SkipEmptyParts);
        if (parts.size() < 2) continue;
        const qint64 v = parts.at(1).toLongLong();
        const QString &key = parts.at(0);
        if      (key == QLatin1String("MemTotal:"))     out.totalKb = v;
        else if (key == QLatin1String("MemAvailable:")) out.availKb = v;
        else if (key == QLatin1String("MemFree:"))      out.freeKb  = v;
        else if (key == QLatin1String("SwapTotal:"))    out.swapTotalKb = v;
        else if (key == QLatin1String("SwapFree:"))     out.swapFreeKb  = v;
    }
    if (out.totalKb > 0) {
        out.usagePercent =
            static_cast<double>(out.totalKb - out.availKb) / out.totalKb * 100.0;
    }
    return out;
}

关键在最后那个公式。分子是 MemTotal - MemAvailable，不是 MemTotal - MemFree。

差多少？看上面的样例：MemFree 只有 1.2 GB，MemAvailable 有 18.4 GB。用 MemFree 算，使用率是 (32624560-1234567)/32624560 = 96%；用 MemAvailable 算，是 43%。同一台机器，一个数字在报警，一个数字很健康。

原因不难懂。Linux 会把空闲内存拿去做页缓存（Cached）和块缓冲（Buffers），这些内存随时可以回收给应用。MemFree 只统计「完全没被碰过」的页，MemAvailable 是内核估算的「不触发换页就能给新应用用」的量，已经把可回收缓存算进去了。所以——MemFree 不等于「可用」，要看 MemAvailable。

MemAvailable 在 3.14 之前的内核里没有这个键。真要在老内核上跑，退化成 MemFree + Buffers + Cached 做近似，量级对得上，精度差一些。

指标 语义 拿它做什么
MemFree 完全空闲的页 别用来算使用率
MemAvailable 可回收后的可用量 算使用率、算还能开多少缓存
Buffers + Cached 页缓存与块缓冲 看缓存占了多少，判断内存被谁吃了
SwapTotal / SwapFree 交换区总量与剩余 这就是 Linux 的「虚拟内存」
Committed_AS / CommitLimit 已提交量与提交上限 看 overcommit 余量，不是物理内存
Slab / PageTables 内核对象与页表占用 排查内核态内存增长

素材提到 /proc/vmstat 对应「虚拟内存指标」，这里纠正一下定位。它不是容量文件，是内核计数器集合，一行一个累加值：

text
nr_free_pages 302145
pgpgin 8234512
pswpin 12034
pswpout 45120
pgsteal_kswapd 30124

正确用法是两次采样求差，算换页速率与缺页速率。要看「虚拟内存还剩多少」，回 /proc/meminfo 看 SwapTotal / SwapFree。pswpin 与 pswpout 增长快，说明机器在频繁换入换出，内存真不够了。

五、磁盘与存储 #

磁盘这块 Qt 给得不错，QStorageInfo 是跨平台的，Windows 盘符与 Linux 挂载点都认。

cpp
#include <QStorageInfo>
#include <QDebug>

void dumpStorage()
{
    for (const QStorageInfo &v : QStorageInfo::mountedVolumes()) {
        if (!v.isValid() || !v.isReady() || v.isReadOnly()) continue;
        qDebug() << v.displayName() << v.fileSystemType()
                 << v.bytesTotal() / kMb << "MB"
                 << v.bytesAvailable() / kMb << "MB 可用";
    }
}

单个卷用 QStorageInfo::root() 或直接构造 QStorageInfo(path) 拿，字段一样。

三个容量方法的差别必须分清：

方法 含义 用于
bytesTotal() 卷总容量 展示「总共多大」
bytesFree() 空闲字节 含只有 root 能用的保留块
bytesAvailable() 当前用户可用字节 判断「还能不能写」

普通用户身份下，bytesFree() 比 bytesAvailable() 大一点，差的是文件系统给 root 预留的部分（ext4 默认 5%）。算「还能存多少文件」用 bytesAvailable()，用 bytesFree() 会算出装得下却写不进去的尴尬。

几个细节：

  • mountedVolumes() 会带出 proc、sysfs、tmpfs、squashfs 这些伪文件系统，用 fileSystemType() 过滤，或只认 bytesTotal() 超过阈值的项。
  • U 盘拔掉后，缓存的 QStorageInfo 对象不会自己失效，要重读先调 refresh()。
  • isValid() 表示路径对应真实挂载点，isReady() 表示当前能不能访问，两个都要检查。
  • Windows 上断连的网络映射盘 isReady() 返回 false，遍历时别当本地盘算进总容量。

六、标准路径 QStandardPaths #

QStandardPaths 解决另一个问题：配置放哪、缓存放哪、日志放哪。硬编码 C:/Users/xxx/AppData 或 ~/.config 的代码，换台机器就崩。

cpp
#include <QStandardPaths>
#include <QDebug>

void dumpPaths()
{
    qDebug() << "配置:" << QStandardPaths::writableLocation(QStandardPaths::AppConfigLocation);
    qDebug() << "缓存:" << QStandardPaths::writableLocation(QStandardPaths::CacheLocation);
    qDebug() << "数据:" << QStandardPaths::writableLocation(QStandardPaths::AppDataLocation);
    qDebug() << "下载:" << QStandardPaths::writableLocation(QStandardPaths::DownloadLocation);
    qDebug() << "临时:" << QStandardPaths::writableLocation(QStandardPaths::TempLocation);
}

三端实际落点：

枚举 Windows Linux macOS
AppConfigLocation %APPDATA%/<组织>/<应用> ~/.config/<组织>/<应用> ~/Library/Preferences/<应用>
AppDataLocation %APPDATA%/<组织>/<应用> ~/.local/share/<组织>/<应用> ~/Library/Application Support/<应用>
CacheLocation %LOCALAPPDATA%/<组织>/<应用>/cache ~/.cache/<组织>/<应用> ~/Library/Caches/<应用>
TempLocation %TEMP% /tmp /var/folders/...
DownloadLocation %USERPROFILE%\Downloads ~/下载 或 ~/Downloads ~/Downloads

注意 AppConfigLocation 里的组织名与应用名，来自 QCoreApplication::setOrganizationName() 和 setApplicationName()。这两个不设，路径会退化成一堆空目录拼接，落点不受控。程序入口第一件事就该设它们。

writableLocation() 只返回第一个，standardLocations() 返回整条搜索链（配置会散在系统级和用户级两处）。读配置按链找，写配置只用第一个。

cpp
// 在 PATH 里找可执行文件，找不到返回空串
const QString git = QStandardPaths::findExecutable(QStringLiteral("git"));

// 按搜索链找第一个存在的文件
const QString cfg = QStandardPaths::locate(
    QStandardPaths::ConfigLocation, QStringLiteral("app/settings.ini"));

writableLocation() 返回的目录不保证存在，写文件前先 QDir().mkpath() 建一遍。这是新手最常漏的一步。

七、屏幕与环境信息 #

程序跑在什么屏幕上，也是「系统信息」的一部分。高分屏适配、截图工具、投屏软件都要这份数据。

cpp
#include <QGuiApplication>
#include <QScreen>

void dumpScreens()
{
    for (QScreen *s : QGuiApplication::screens()) {
        qDebug() << "名称:"     << s->name()
                 << "尺寸:"     << s->size()
                 << "可用区:"   << s->availableGeometry()
                 << "逻辑 DPI:" << s->logicalDotsPerInch()
                 << "物理 DPI:" << s->physicalDotsPerInch()
                 << "缩放:"     << s->devicePixelRatio()
                 << "刷新率:"   << s->refreshRate();
    }
}
方法 含义 坑
size() 逻辑像素尺寸 不是物理像素，别直接拿去截图
availableGeometry() 扣掉任务栏/面板的可用区 最大化窗口应该用它
logicalDotsPerInch() 系统报告的逻辑 DPI 受缩放设置影响
physicalDotsPerInch() 按物理尺寸估算的 DPI 显示器没报 EDID 时会不准
devicePixelRatio() 逻辑像素到物理像素的倍率 截图、OpenGL 视口必须乘它
refreshRate() 刷新率 部分驱动报 0，别拿去做除法

多屏环境下 QGuiApplication::primaryScreen() 只给主屏。做截图或全屏工具必须遍历 screens()，按各自的 devicePixelRatio() 处理，否则副屏上的图会发虚。

环境变量属于最后一块。Qt 有跨平台读取接口，不用 getenv：

cpp
#include <QProcessEnvironment>

void dumpEnv()
{
    // 环境块只拷一次，别放进循环里反复调
    const QProcessEnvironment env = QProcessEnvironment::systemEnvironment();
    if (env.contains(QStringLiteral("QT_SCALE_FACTOR"))) {
        qDebug() << "缩放因子:" << env.value(QStringLiteral("QT_SCALE_FACTOR"));
    }
    // 读单个变量用 qEnvironmentVariable，不存在时返回空串
    qDebug() << "平台插件:" << qEnvironmentVariable("QT_QPA_PLATFORM");
}

QProcessEnvironment::systemEnvironment() 第一次调用会把整个环境块拷一份，量不大但也不是零成本。放进循环里反复调没有意义，拿一次缓存住。

八、跨平台的信息获取策略 #

到这一步，各平台的手段都摆出来了。往下要做的是把它们收进一个类，让调用端看不见 #ifdef。

先定数据结构，所有字段按「取不到 = 0 或空」的约定，不留半初始化状态：

cpp
struct SystemSnapshot
{
    QString osName;
    QString osVersion;
    QString cpuModel;
    int     logicalCores   = 0;
    int     physicalCores  = 0;
    qint64  memTotalBytes  = 0;
    qint64  memAvailBytes  = 0;
    qint64  swapTotalBytes = 0;
    qint64  diskTotalBytes = 0;
    qint64  diskAvailBytes = 0;

    double memUsagePercent() const
    {
        if (memTotalBytes <= 0) return 0.0;
        return static_cast<double>(memTotalBytes - memAvailBytes)
               / memTotalBytes * 100.0;
    }
};

采集函数按平台分叉，公共部分提到外面：

cpp
#include <QThread>
#include <QSysInfo>
#include <QStorageInfo>

CpuBrief readLinuxCpu();          // 见第三章
MemBrief readLinuxMem();          // 见第四章
QString  windowsCpuModelName();   // 见第三章

SystemSnapshot collectSnapshot()
{
    SystemSnapshot s;
    s.osName       = QSysInfo::prettyProductName();
    s.osVersion    = QSysInfo::productVersion();
    s.logicalCores = QThread::idealThreadCount();

    // 磁盘跨平台，直接问 QStorageInfo
    const QStorageInfo root = QStorageInfo::root();
    if (root.isValid() && root.isReady()) {
        s.diskTotalBytes = root.bytesTotal();
        s.diskAvailBytes = root.bytesAvailable();
    }

#if defined(Q_OS_LINUX)
    const CpuBrief cpu = readLinuxCpu();
    const MemBrief mem = readLinuxMem();
    s.cpuModel       = cpu.modelName;
    s.physicalCores  = cpu.physicalCores;
    s.memTotalBytes  = mem.totalKb * 1024;      // 这里的 kB 是 KiB
    s.memAvailBytes  = mem.availKb * 1024;
    s.swapTotalBytes = mem.swapTotalKb * 1024;
#elif defined(Q_OS_WIN)
    // windows.h 需在本文件顶部、包含 Qt 头之前引入
    s.cpuModel = windowsCpuModelName();
    MEMORYSTATUSEX st;
    st.dwLength = sizeof(st);
    if (GlobalMemoryStatusEx(&st)) {
        s.memTotalBytes  = static_cast<qint64>(st.ullTotalPhys);
        s.memAvailBytes  = static_cast<qint64>(st.ullAvailPhys);
        s.swapTotalBytes = static_cast<qint64>(st.ullTotalPageFile);
    }
#endif
    return s;
}

封装的规矩三条：

  • 接口返回值，不返回错误码。取不到就给 0，调用端统一按 0 处理，比到处判错误码清爽。
  • 平台分叉只出现在一个函数里。业务代码不许出现 #ifdef Q_OS_WIN，否则以后加 macOS 要改几十处。
  • 没实现的平台直接留空，界面上显示「未知」，别编个默认值糊弄过去。

平台与手段的对应关系，第一章那张表已经列全，这里只补一条：凡是表里标「没有」的行，都要在 collectSnapshot() 里按宏分叉，并且各给一个兜底值——物理核数取不到就用逻辑核数，内存取不到就给 0，界面再按 0 显示「未知」。兜底不是糊弄，是让程序在不认识的机器上还能把界面画出来。

九、信息采集的性能与时机 #

系统信息不是免费的。读一次 /proc/meminfo 要走内核的 seq_file 机制生成几十行文本，再逐行 split 解析，中间带着 QString 分配。单次开销不算大事，架不住高频调用。

更要命的是放错位置。采集绝不能放进 paintEvent。paintEvent 会被窗口重绘、滚动、鼠标悬停反复触发，一秒几十上百次。在里面读文件，等于把 UI 线程按在地上摩擦，界面会肉眼可见地卡顿、拖影。系统信息只跟「时间」有关，跟「重绘」无关，放 paintEvent 里逻辑本身就错。

正确做法是定时采集、缓存结果、界面只读缓存：

cpp
class SysInfoPoller : public QObject
{
    Q_OBJECT
public:
    explicit SysInfoPoller(QObject *parent = nullptr) : QObject(parent)
    {
        connect(&m_timer, &QTimer::timeout, this, &SysInfoPoller::tick);
        m_timer.start(2000);        // 2 秒一次，够用且不吵闹
    }
signals:
    void snapshotReady(const SystemSnapshot &snap);
private slots:
    void tick()
    {
        if (m_busy) return;         // 上一轮没跑完就跳过，别堆积
        m_busy = true;
        emit snapshotReady(collectSnapshot());
        m_busy = false;
    }
private:
    QTimer m_timer;
    bool   m_busy = false;
};

频率怎么定，看用途：

用途 间隔 说明
状态栏常驻显示 2~5 秒 用户感知不到差别，CPU 开销几乎为零
性能面板折线图 1 秒 再快人眼也分不出，图只会抖
崩溃日志随附 触发时一次 不要定时采，事件驱动
排障模式 用户手动触发 给个「重新检测」按钮，别自动刷

CPU 使用率还有一条特殊规则：必须两次采样求差，单次读数没有意义。/proc/stat 给的是从开机到现在的累计节拍数，不是瞬时占用率。读一次只能知道「开机以来一共花了多少时间在 CPU 上」，跟当前负载没关系。

cpp
struct CpuTimes
{
    qint64 total = 0;
    qint64 idle  = 0;
};

CpuTimes readLinuxCpuTimes()
{
    CpuTimes t;
    QFile f(QStringLiteral("/proc/stat"));
    if (!f.open(QIODevice::ReadOnly | QIODevice::Text)) return t;
    const QString line = QTextStream(&f).readLine();
    if (!line.startsWith(QLatin1String("cpu "))) return t;
    const QStringList parts = line.split(QLatin1Char(' '), Qt::SkipEmptyParts);
    for (int i = 1; i < parts.size(); ++i) {
        const qint64 v = parts.at(i).toLongLong();
        t.total += v;
        if (i == 4 || i == 5) t.idle += v;    // idle + iowait
    }
    return t;
}

double cpuUsageBetween(const CpuTimes &a, const CpuTimes &b)
{
    const qint64 dTotal = b.total - a.total;
    const qint64 dIdle  = b.idle - a.idle;
    if (dTotal <= 0) return 0.0;    // 间隔内没变化，别让除零带走程序
    return static_cast<double>(dTotal - dIdle) / dTotal * 100.0;
}

几个坑一起说掉：

  • 字段顺序是 user nice system idle iowait irq softirq steal guest guest_nice，idle 在第 4 位。
  • guest 与 guest_nice 已经被算进 user 和 nice，全部相加会重复计数，总时间偏大、使用率偏低。
  • 两次采样间隔太短，差值小，除出来的数字抖得厉害。1 秒起步。

Windows 上同理，GetSystemTimes 给的是累计的 100ns 时间片：

cpp
#ifdef Q_OS_WIN
static qint64 ftToU64(const FILETIME &ft)
{
    ULARGE_INTEGER u;
    u.LowPart  = ft.dwLowDateTime;
    u.HighPart = ft.dwHighDateTime;
    return static_cast<qint64>(u.QuadPart);
}

void readWindowsCpuTimes(qint64 &idleOut, qint64 &totalOut)
{
    FILETIME idleFt, kernelFt, userFt;
    if (!GetSystemTimes(&idleFt, &kernelFt, &userFt)) {
        idleOut = totalOut = 0;
        return;
    }
    const qint64 idle   = ftToU64(idleFt);
    const qint64 kernel = ftToU64(kernelFt);   // 这个值里已经包含 idle
    const qint64 user   = ftToU64(userFt);
    idleOut  = idle;
    totalOut = kernel + user;
}
#endif

kernel 时间包含 idle，所以总量是 kernel + user，不是 idle + kernel + user。这条搞错，使用率会算成负增长。

十、把信息展示到界面 #

数据到手，最后一步是显示。字节换算单独抽一个函数，别到处写 / 1024 / 1024：

cpp
QString formatBytes(qint64 bytes)
{
    static const char *units[] = { "B", "KB", "MB", "GB", "TB" };
    if (bytes <= 0) return QStringLiteral("未知");
    double v = static_cast<double>(bytes);
    int i = 0;
    while (v >= 1024.0 && i < 4) { v /= 1024.0; ++i; }
    return QString::number(v, 'f', i == 0 ? 0 : 1)
           + QLatin1Char(' ') + QLatin1String(units[i]);
}

显示内存占用，QProgressBar 比一串数字直观：setRange(0, 100)，setValue() 传 memUsagePercent() 四舍五入后的整数，标签文本用 formatBytes() 拼成「已用 / 总量（百分比）」。百分比要自己先算出来再传，别指望进度条替你换算。

界面上的几条经验：

  • 采集放 UI 线程就够，只要间隔在 1 秒以上，单次耗时压不到帧。真担心卡顿，把 collectSnapshot() 丢进 QtConcurrent::run，结果用信号回主线程。
  • 数字别每秒刷新。盯着一行来回跳的「可用 18.4 GB / 18.5 GB」，只会觉得程序在抽风。2 秒一刷，或者用滑动平均。
  • 取不到的值显示「未知」，不要显示 0。0 GB 总内存会让用户以为程序坏了。
  • 单位统一。内存与磁盘都用 GB，别一个用 MB 一个用 GB 混着排。

十一、常见故障与现象 #

现象 原因 处理
Linux 上内存使用率常年 96% 用了 MemFree 当可用量 换成 MemAvailable，老内核用 MemFree+Buffers+Cached
Windows 上内存字段全是 0 MEMORYSTATUSEX::dwLength 没赋值 调用前 statex.dwLength = sizeof(statex)
界面滚动时卡顿、拖影 在 paintEvent 里读 /proc 或调 Win32 定时采集 + 缓存，绘制只读缓存
CPU 使用率恒为 0 或 100 只采样一次，或两次间隔为 0 两次采样求差，间隔 1 秒以上，判 dTotal > 0
核数显示 16，用户说是 8 核 idealThreadCount() 是逻辑核 展示时标明「逻辑处理器」，物理核另算
CPU 型号显示空白 平台没这个字段（部分 ARM） 字段名按优先级试探，取不到显示「未知」
磁盘可用量比资源管理器少 用了 bytesFree() 换成 bytesAvailable()
配置写入失败、目录不存在 writableLocation() 不保证目录存在 写前 QDir().mkpath()
老代码在 Qt 6 编译不过 QString::SkipEmptyParts 在 Qt 6 已移除 改 Qt::SkipEmptyParts，Qt 5.14 起就支持
引入 windows.h 后 min/max 冲突 Windows 头文件定义了同名宏 编译选项加 NOMINMAX，或用 (std::min)(a,b) 写法
副屏截图发虚 没乘 devicePixelRatio() 按屏幕各自的倍率缩放
界面显示「0 GB」但机器有内存 采集失败被当成 0 显示 采集失败返回负值，界面判负显示「未知」

十二、易错点速查 #

易错点 正确做法
以为 Qt 有跨平台的 CPU 型号 / 内存接口 只有 QSysInfo、QStorageInfo、QStandardPaths 这一层跨平台，细节必须掉平台 API
用 MemFree 算 Linux 内存使用率 用 MemAvailable，它是内核估算的可回收后可用量
把 /proc/vmstat 当虚拟内存容量文件 它是内核计数器，容量答案在 /proc/meminfo 的 SwapTotal / SwapFree
把 ullTotalVirtual 当系统虚拟内存 它是进程地址空间，系统提交限额看 ullTotalPageFile
单次读 /proc/stat 算 CPU 使用率 累计值，必须两次采样求差
GetSystemTimes 里把 kernel + idle 相加 kernel 已含 idle，总量是 kernel + user
把 /proc/meminfo 的 kB 当 1000 字节 是 KiB，1024 字节
在 paintEvent 里采系统信息 定时采集，缓存快照，界面只读缓存
硬编码 C:/Users/xxx/AppData 用 QStandardPaths::writableLocation()
不设 setOrganizationName / setApplicationName 入口处先设，否则标准路径拼不出来
用 #define MB (1024*1024) 用 constexpr quint64，宏容易和别的头文件撞名
productType() 当枚举用 它返回小写字符串，比常量串，或自己包一层枚举
认为 GetSystemInfo 报的是机器真实架构 32 位进程里它报的是进程视角，看真实架构用 GetNativeSystemInfo
遍历 mountedVolumes() 直接累加容量 先过滤 isValid() / isReady()，再排掉伪文件系统与只读卷
