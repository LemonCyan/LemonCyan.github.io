本篇讲什么：Qt 的 SQL 模块怎么接数据库、怎么执行 SQL、怎么做增删改查与事务、怎么在 SQLite 上压榨性能。主角是三个类：QSqlDatabase、QSqlQuery、QSqlTableModel。

本篇不讲什么：不讲 SQL 语法本身，不讲 MySQL 服务端的安装与运维，不讲模型视图框架的完整用法，不讲网络协议层。

跨篇指路：把数据当配置文件、当表格读写，走 QSettings / QFile / QTextStream 的那条路在「文件、配置与表格」；把查询结果铺到 QTableView 上的模型视图基础也在那篇；Qt 跟远端服务说话的那一层在「Qt 网络编程」与「网络应用实例」。

一、Qt SQL 模块的结构 #

QtSql 给的是一套跟平台、跟数据库种类都无关的 SQL 接口。同一份 QSqlQuery 代码，换一个驱动字符串就能从本地文件挪到远端服务器。这层抽象靠驱动插件实现：QSqlDatabase 本身不干活，它只是持有一个驱动实例加上一堆连接参数。先在项目文件里把模块引进来，否则 #include <QSqlDatabase> 直接编不过：

text
QT += sql

完整调用链是这样：

text
应用程序
  │  QSqlDatabase::addDatabase("QSQLITE")
  ▼
QSqlDatabase  ── 持有驱动插件实例 + 一份连接参数
  │  open()
  ▼
驱动插件 qsqlite.dll / qsqlmysql.dll
  │
  ├── QSQLITE ──► SQLite 引擎（进程内，直接读写 .db 文件）
  └── QMYSQL  ──► libmysql.dll ──► MySQL 服务端（走网络）
  │
  ▼
QSqlQuery  ── exec() 执行 SQL，拿回结果集
  │
  ├── next() + value() 逐行取
  ├── record() → QSqlRecord 按列取
  └── QSqlQueryModel / QSqlTableModel → QTableView

最后一步有个分叉：裸 QSqlQuery 是手工取数据，QSqlTableModel 是把整张表接到视图上。两条路不冲突，一个程序里混着用也行，但要清楚各自管什么。

类 管什么 注意点
QSqlDatabase 一个连接的句柄：驱动、主机、库名、账号、选项 连接句柄不能跨线程
QSqlQuery 执行 SQL，持有结果集游标 一条语句一个对象，别乱复用
QSqlRecord 一行数据的列集合，按列名或列号取值 由 record() 或模型拿到
QSqlField 单个字段的元信息：名字、类型、是否空 类型来自驱动，SQLite 上偏弱
QSqlError 出错的文本、驱动文本、错误码 每次 exec() 失败都该打印
QSqlQueryModel 只读查询结果的模型 默认只抓 256 行
QSqlTableModel 单表可读写模型，支持提交与回滚 编辑策略要显式设
QSqlRelationalTableModel 带外键关联的单表模型 外键列自动换成显示值

Qt 桌面版自带的驱动就这些，名字不区分大小写，习惯写大写：

驱动名 后端 备注
QDB2 IBM DB2 7.1+ 需要 DB2 客户端库
QIBASE Borland InterBase 需要客户端库
QMYSQL MySQL 需要 libmysql.dll
QOCI Oracle Call Interface 需要 Oracle 客户端
QODBC ODBC，含微软 SQL Server 走系统数据源
QPSQL PostgreSQL 7.3+ 需要 libpq
QSQLITE SQLite 3 Qt 自带引擎，无外部依赖
QSQLITE2 SQLite 2 老库，基本不用
QTDS Sybase 自适应服务器 已废弃

这张表里最该记住的是 QSQLITE 那一行：它不需要任何外部动态库。这是后面所有选型讨论的起点。

线程安全这块是 Qt SQL 里最容易埋雷的地方，先把结论摆出来：

层 线程安全性 后果
SQLite 引擎 默认 Serialized 模式，引擎内部加锁 多连接并发读没问题
QSqlDatabase 非线程安全 连接句柄不能跨线程传递
QSqlQuery 绑在创建它的连接上 跟着连接走，同样不能跨线程

典型错误：在 A 线程 addDatabase 并 open()，把 QSqlDatabase 存进成员变量，B 线程直接拿来 exec()。看着没事，跑久了出随机崩溃或者结果错乱。连接是线程私有资源，跟文件句柄一个性质。

开跑之前先查驱动，能省掉大量猜错方向的时间：

cpp
if (!QSqlDatabase::isDriverAvailable("QSQLITE")) {
    qCritical() << "Fatal Error: QSQLITE driver not loaded!";
    return;
}

qDebug() << "Available SQL Drivers:";
foreach (const QString &driver, QSqlDatabase::drivers()) {
    qDebug() << "  " << driver;
}

打印出来的这份清单，是排 driver not loaded 时最先该看的东西。清单里没有 QMYSQL，问题就不在 exec()，在驱动文件本身。

二、连接数据库 #

一次完整连接就五步：加驱动、设参数、打开、用、关闭。没有连接池配置，没有隔离级别，Qt 把这些全收进 setConnectOptions() 的字符串里。

cpp
QSqlDatabase database = QSqlDatabase::addDatabase("QSQLITE");
database.setDatabaseName("database.db");
database.setUserName("root");
database.setPassword("123456");

if (!database.open()) {
    qDebug() << database.lastError();
    qFatal("failed to connect.");
}

三处容易踩的点：setDatabaseName() 对 SQLite 是文件路径，相对路径相对进程工作目录，不是相对 exe 所在目录，调试跑得好好的、双击发布版就找不到库，多数栽在这里，改用绝对路径；SQLite 根本不认用户名密码，写 root / 123456 只是为了让同一段代码换 MySQL 时不用改结构，别以为设了密码文件就加密了；qFatal 会直接终止进程，生产代码换成错误弹窗加 return。

方法 适用后端 说明
addDatabase(driver, name) 全部 第二个参数是连接名，缺省 qt_default_connection
setDatabaseName(path) 全部 SQLite 是文件路径，MySQL 是库名
setHostName(host) 网络类 IP 或域名
setPort(port) 网络类 MySQL 默认 3306
setUserName(user) 网络类 SQLite 忽略
setPassword(pwd) 网络类 SQLite 忽略
setConnectOptions(str) 全部 分号分隔的键值对
open() / close() 全部 返回 bool
lastError() 全部 返回 QSqlError，看 .text()

连接名 #

不带第二个参数调用 addDatabase，Qt 生成名为 qt_default_connection 的默认连接。同一段代码执行两次就会看到：

text
duplicate connection name 'qt_default_connection', old connection was overwritten.

这句话不是致命错误，但意味着旧连接被顶掉了，还挂在旧连接上的 QSqlQuery 会变成野指针状态。管理的办法是给每个连接起名，并按名字取回实例，别到处 addDatabase：

cpp
// 只在初始化处创建一次
QSqlDatabase db = QSqlDatabase::addDatabase("QMYSQL", "log_db");
db.setHostName("192.168.1.100");
db.setPort(3306);
db.setDatabaseName("gv_local");
db.setUserName("root");
db.setPassword("root123");
db.open();

// 其它类里按名字取，不要重复创建
QSqlDatabase dbLog = QSqlDatabase::database("log_db");
if (!dbLog.isOpen()) {
    qDebug() << "log_db 未打开:" << dbLog.lastError().text();
}

database("log_db") 返回的是同一个连接的副本句柄，不是新连接，不需要你 close()，也不该由某个局部作用域擅自 removeDatabase。要改参数重开，就用第二个布尔参数关掉自动打开：QSqlDatabase::database("log_db", false)，接着 setHostName("192.168.1.101") 再 open()，失败照样看 lastError().text()。

失败时看什么 #

open() 失败，lastError() 里能直接指路，四个字段都打出来：

cpp
if (!db.open()) {
    QSqlError err = db.lastError();
    qDebug() << err.type() << err.text()
             << err.driverText() << err.databaseText();
}

driverText() 是 Qt 驱动层的话，databaseText() 是后端数据库自己说的话。两者不一致时信 databaseText()，它更接近真相。

错误文本片段 实际含义
Driver not loaded 驱动插件或它依赖的库不在位
Unable to open database file 路径错、目录不存在、权限不足
Access denied for user 账号密码错，或该账号不许从这台机器连
Can't connect to MySQL server 主机端口不通、服务没起、防火墙
database is locked 另一连接占着写锁，没设 busy timeout
no such table 库连上了，但表建在别的库或别的 schema

三、驱动：SQLite 与 MySQL 的差别 #

这一节是本篇的分水岭。同样一句 QSqlDatabase::addDatabase("QMYSQL")，在 SQLite 上碰不到的问题，在 MySQL 上会全线撞上来。

QSQLITE 的引擎跟着 Qt 一起编译，装完 Qt 就有；QMYSQL 的驱动插件在多数官方二进制包里根本没编进去，你得自己解决驱动文件，必要时自己编。

报错现场 #

代码里引了 sql 模块，.pro 也加了 QT += sql，编译零警告，一运行输出这个：

text
QSqlDatabase: QMYSQL driver not loaded
QSqlDatabase: available drivers: QSQLITE QODBC QODBC3 QPSQL QPSQL7

注意第二行。可用清单里没有 QMYSQL，说明 Qt 压根没找到那个插件文件。这跟 setHostName 写没写对、密码对不对、表存不存在，全都没关系。driver not loaded 是文件问题，不是代码问题。

驱动是两层 #

qsqlmysql.dll 只是一座桥，它自己不做协议，底下还得调 MySQL 官方的客户端通信库 libmysql.dll。桥在、底下的库不在，一样装不起来。

text
Qt 代码
  │  QSqlDatabase::addDatabase("QMYSQL")
  ▼
plugins/sqldrivers/qsqlmysql.dll      ← Qt 编译产出的插件
  │  依赖
  ▼
libmysql.dll                          ← MySQL 官方客户端库，需自己提供
  │  协议
  ▼
MySQL Server : 3306

三层排法 #

按顺序查，别跳步。

第一层，插件在不在。去 Qt 安装目录下看 plugins/sqldrivers/：

text
C:\Qt\5.15.2\msvc2019_64\plugins\sqldrivers\
    qsqlite.dll
    qsqlmysql.dll
    qsqlodbc.dll

没有 qsqlmysql.dll，后两层都不用查了。要么自己编，要么换一个带 MySQL 驱动的安装包。

第二层，libmysql.dll 在不在。把 MySQL 安装目录 lib/ 下的 libmysql.dll 找出来，或者去官网下 MySQL Connector/C 的 zip 包，解压后在 lib/ 里取。然后拷到两处：开发期拷到 Qt 编译链的 bin/，例如 C:\Qt\Qt5.9.1\5.9.1\msvc2015_64\bin\；发布时拷到跟 exe 同级目录。

第三层，位数对不对。这一步漏了，前面全白干。

位数陷阱：拷过去的 libmysql.dll 的体系结构必须跟当前 Qt 编译链的位数完全一致。用 MinGW 32bit 编译，就得找 32 位的库；用 MSVC 64bit，就得配 64 位。混着来不报错，只静默装载失败，然后还是那句 driver not loaded。

判断手头的 dll 是几位，用 dumpbin 看机器类型：

text
dumpbin /headers libmysql.dll | findstr machine

64 位输出 8664 machine (x64)，32 位输出 14C machine (x86)。跟编译器对一遍，不一致就换。

自己编驱动 #

官方包里没有，就从 Qt 源码编。路径在 qtbase/src/plugins/sqldrivers，用 qmake 带着 MySQL 的头和库路径走一遍：

text
cd %QTDIR%\qtbase\src\plugins\sqldrivers
qmake -- MYSQL_INCDIR="C:/mysql/include" MYSQL_LIBDIR="C:/mysql/lib"
nmake sub-mysql

MSVC 用 nmake，MinGW 用 mingw32-make。编完在 plugins/sqldrivers/ 下产出 qsqlmysql.dll，把它连同 libmysql.dll 一起放进程序的 sqldrivers 子目录。发布目录的最终形态：

text
MyApp\
    MyApp.exe
    libmysql.dll
    sqldrivers\
        qsqlmysql.dll
        qsqlite.dll

调试期还能用环境变量临时指一下插件路径：

text
set QT_PLUGIN_PATH=C:\Qt\5.15.2\msvc2019_64\plugins

SQLite 与 MySQL 的差异 #

维度 SQLite MySQL
驱动来源 Qt 自带，零配置 需自备插件 + libmysql.dll
部署形态 单个 .db 文件 独立服务进程
连接方式 打开文件 TCP 连接，可跨机器
账号体系 无 有，用户/权限/主机白名单
数据类型 动态类型，弱约束 静态类型，强约束
并发写 单写者，靠文件锁 多连接并发写
事务隔离 整库级 会话级，可选隔离级别
存储过程 不支持 支持
备份 拷文件 mysqldump 或物理备份
适合场景 单机、嵌入式、移动端 多端协同、服务端、高并发

选型判断很直接：数据只给本机这个进程用，上 SQLite；数据要给多台机器、多个客户端共享，上 MySQL。

text
是否需要多节点 / 多客户端共享数据？
├─ 是 → MySQL（或 PostgreSQL）
└─ 否
    └─ 写入并发是否超过 1000 次/秒？
        ├─ 是 → MySQL
        └─ 否 → SQLite

写入并发那条线不是绝对的。批量导入时 SQLite 包在事务里能跑到五万条每秒，但那是串行吞吐，不是并发能力。多个线程同时写同一个文件，SQLite 仍然只允许一个写者。

四、执行 SQL：QSqlQuery #

QSqlQuery 负责执行语句、持有结果集。它管的不只是 SELECT，CREATE TABLE 这类 DDL、INSERT/UPDATE/DELETE 这类 DML、以及 PRAGMA、SET NAMES 这种数据库特有命令，全走它。

方式 写法 适用
直接执行 query.exec("DELETE FROM student") 无参数、只跑一次
预编译执行 query.prepare(sql); query.exec(); 带参数、跑多次
批量执行 query.execBatch() 同一语句多组参数

QSqlQuery 有两个构造函数，区别很关键：QSqlQuery q1; 绑定到默认连接 qt_default_connection，QSqlQuery q2(db); 绑定到 db。程序里只有一个连接时无所谓，一旦有多个（比如本地 SQLite 加远端 MySQL），必须显式传连接对象，否则语句跑到哪个库上完全看运气。

下面把 SQLite 上的典型操作走一遍，用 student 表做例子，字段是 id、name、age。先备好语句模板：

cpp
QString create_sql     = "create table student (id int primary key, name varchar(30), age int)";
QString select_max_sql = "select max(id) from student";
QString insert_sql     = "insert into student values (?, ?, ?)";
QString update_sql     = "update student set name = :name where id = :id";
QString select_sql     = "select id, name from student";
QString select_all_sql = "select * from student";
QString delete_sql     = "delete from student where id = ?";
QString clear_sql      = "delete from student";

建表、取当前最大 id、插入、更新：

cpp
QSqlQuery sql_query;
if (!sql_query.exec(create_sql)) {
    qDebug() << sql_query.lastError();
} else {
    qDebug() << "table created!";
}
int max_id = 0;
if (sql_query.exec(select_max_sql) && sql_query.next()) {
    max_id = sql_query.value(0).toInt();
    qDebug() << QString("max id:%1").arg(max_id);
}
sql_query.prepare(insert_sql);
sql_query.addBindValue(max_id + 1);
sql_query.addBindValue("name");
sql_query.addBindValue(25);
if (!sql_query.exec()) {
    qDebug() << sql_query.lastError();
} else {
    qDebug() << "inserted!";
}
sql_query.prepare(update_sql);
sql_query.bindValue(":name", "Qt");
sql_query.bindValue(":id", 1);
if (!sql_query.exec()) {
    qDebug() << sql_query.lastError();
} else {
    qDebug() << "updated!";
}

value(0) 取第一列。表空时 max(id) 返回 NULL，toInt() 给 0，max_id 保持初始值 0，逻辑是对的。建表语句没有参数，用 prepare() 是多余一步，直接 exec(create_sql) 更省。

查询、删除、清空、收尾：

cpp
// 查部分列，按列名取值
if (sql_query.exec(select_sql)) {
    while (sql_query.next()) {
        int id = sql_query.value("id").toInt();
        QString name = sql_query.value("name").toString();
        qDebug() << QString("id:%1    name:%2").arg(id).arg(name);
    }
}

// 查全部列，按列号取值
sql_query.prepare(select_all_sql);
if (sql_query.exec()) {
    while (sql_query.next()) {
        int id = sql_query.value(0).toInt();
        QString name = sql_query.value(1).toString();
        int age = sql_query.value(2).toInt();
        qDebug() << QString("id:%1    name:%2    age:%3").arg(id).arg(name).arg(age);
    }
}

// 删一行、清空表、关闭并删库文件
sql_query.prepare(delete_sql);
sql_query.addBindValue(max_id);
sql_query.exec();
if (sql_query.exec(clear_sql)) {
    qDebug() << "cleared";
}

database.close();
QFile::remove("database.db");

select * 的列顺序由表结构决定。能确定顺序时按序号取值最快，但表结构一改，取到的值全错位还不报错，稳妥办法是按列名取。QFile::remove 之前必须先 close()：Windows 上文件句柄没放掉，删除会失败且不报错——remove 返回 false，多数人不检查，于是下次启动读到的还是旧库。

手段 说明
exec() 返回值 false 表示失败，马上看 lastError()
lastError().text() 人可读的错误描述
numRowsAffected() 影响行数，UPDATE/DELETE 后查它
isActive() 语句是否活动，有结果集时为 true
isSelect() 是否 SELECT 类语句
lastQuery() 实际执行的 SQL 文本，调试时打印

lastQuery() 待在出错分支里打出来，能立刻看出占位符替换后的真实语句长什么样：

cpp
if (!query.exec()) {
    qDebug() << "SQL:" << query.lastQuery();
    qDebug() << "ERR:" << query.lastError().text();
}

numRowsAffected() 在 SQLite 上返回真实改动行数。UPDATE 的值跟原值相同时，SQLite 仍算作一行受影响，这点跟某些数据库不一样。另外，QSqlQuery 能复用，但复用时上一个结果集会被顶掉：

cpp
QSqlQuery q;
q.exec("select id from student");
while (q.next()) {
    int id = q.value(0).toInt();
    q.exec(QString("select name from student where id = %1").arg(id)); // 外层游标没了
}

内层 exec 一执行外层结果集就作废，循环直接退出。这种场景就老实开两个对象。想主动放掉资源调 finish()，它把结果集交还驱动，不关连接。

五、查询结果与 QSqlRecord #

exec() 成功后游标停在第一条之前，next() 往前挪一格，返回 false 表示到底。这是标准的前向遍历，别指望往回走。

写法 例子 特点
按列号 query.value(0) 最快，改表结构就错位
按列名 query.value("name") 可读，每次查名字
按记录 record.value("name") 类型信息完整，适合复用

第三种适合在循环外先把 record 拿出来，顺手把列号算好：

cpp
QSqlQuery query("select id, name, age from student", db);
QSqlRecord rec = query.record();
const int idxId   = rec.indexOf("id");
const int idxName = rec.indexOf("name");
qDebug() << "列数:" << rec.count();

for (int i = 0; i < rec.count(); ++i) {
    qDebug() << i << rec.field(i).name() << rec.field(i).type();
}

while (query.next()) {
    qDebug() << query.value(idxId).toInt()
             << query.value(idxName).toString();
}

indexOf() 返回列在记录里的位置，找不到返回 -1。record() 要在 exec() 之后调，执行前拿到的是空记录。

方法 返回
record.count() 列数
record.fieldName(i) 第 i 列的名字
record.field(i) 第 i 列的 QSqlField
field.name() / field.type() 字段名 / QVariant 类型枚举
field.isNull() 该字段是否为空
record.isNull(i) 第 i 列是否 NULL

类型转换要带 ok #

SQLite 是动态类型，同一列里这行存整数、下行存字符串都不稀奇。toInt() 失败返回 0，跟真的存了 0 分不清，关键字段的转换要带检查：

cpp
QVariant idValue = rec.value("id");
bool ok = false;
int id = idValue.toInt(&ok);
if (!ok) {
    qDebug() << "id 不是整数:" << idValue;
}

判空别用 == 0 或者 isEmpty()。数据库里的 NULL 到 Qt 是无效的 QVariant，判法是 v.isNull()；v.toString().isEmpty() 对应的是存了空字符串。两个值不是一回事，COUNT()、WHERE name IS NULL、唯一索引的行为都不一样。

总行数也别用 size()，它在很多驱动上返回 -1，执行计划里没有总行数的信息，要总数就单独查一次：

cpp
int total = 0;
QSqlQuery cq(db);
if (cq.exec("select count(*) from student") && cq.next()) total = cq.value(0).toInt();

at()、seek()、previous() 这些回到前面去的接口，不同驱动支持程度不同。要稳定就只用 next()。exec() 返回 true 也不代表有数据，只代表语法没错，空结果时第一次 next() 就返回 false：

cpp
if (!query.exec("select id from student where age > 100")) {
    qDebug() << "语句出错:" << query.lastError().text();
} else if (!query.next()) {
    qDebug() << "查询成功，但没有匹配行";
} else do {
    qDebug() << query.value(0).toInt();
} while (query.next());

do...while 省掉一次 next()，第一个值不会漏。

六、增删改与事务 #

单条 INSERT 谁都会写，真正拉开差距的是批量插入。这一节是整篇里最值钱的一段。

默认行为：每条语句一次提交 #

exec() 执行完一条 INSERT，如果没有显式开事务，SQLite 会把它当成独立事务立刻提交。提交意味着写磁盘，写磁盘意味着 fsync。一条一条插一万行，就是一万次事务、一万次刷盘。这不是慢一点，是慢几个数量级。

cpp
db.transaction();
QSqlQuery query(db);
query.prepare("insert into student values (?, ?, ?)");
for (int i = 0; i < data.size(); ++i) {
    query.addBindValue(data[i].id);
    query.addBindValue(data[i].name);
    query.addBindValue(data[i].age);
    if (!query.exec()) {
        qDebug() << "第" << i << "条失败:" << query.lastError().text();
        break;
    }
}
db.commit();

一万次插入变成一次事务、一次刷盘。实测差异在十几倍到几十倍之间，量越大差得越多。

方式 事务次数 刷盘次数 一万行耗时量级
逐条 exec() 1 万 1 万 秒级到几十秒
包一个事务 1 1 毫秒级
分包事务，每 1000 条一提交 10 10 毫秒级，略慢于单事务
调用 作用 失败时
db.transaction() 开启事务 返回 false，驱动不支持或已在事务里
db.commit() 提交 返回 false，看 lastError()
db.rollback() 回滚，撤销本次事务全部改动 返回 false

忘掉 commit() 的后果比想象中严重：连接不关，数据一直悬着；连接一关，SQLite 自动回滚，数据全部消失。代码看着跑完了，重启程序发现一条都没进去。

分批提交 #

事务不是越大越好。一次事务堆进十万行，回滚日志和 WAL 文件跟着涨，中途崩溃的恢复时间也变长。每 1000 条提交一次是个合适的折中：

cpp
const int batchSize = 1000;
db.transaction();

QSqlQuery query(db);
query.prepare("insert into student values (?, ?, ?)");
for (int i = 0; i < data.size(); ++i) {
    if (i > 0 && i % batchSize == 0) {
        if (!db.commit()) { qDebug() << db.lastError().text(); break; }
        db.transaction();
    }
    query.addBindValue(data[i].id);
    query.addBindValue(data[i].name);
    query.addBindValue(data[i].age);
    if (!query.exec()) {
        qDebug() << "失败:" << query.lastError().text();
        db.rollback();
        break;
    }
}

if (!db.commit()) {
    qDebug() << "最后一批提交失败:" << db.lastError().text();
    db.rollback();
}

注意循环结束后的那次 commit()。前面每满 1000 条提交过一次，剩下的零头挂在最后一个事务里，不提交就等于丢了。

出错就回滚 #

事务的价值不只在快，还在原子性。一组操作要么全成，要么全不成：

cpp
if (!db.transaction()) {
    qDebug() << "开事务失败:" << db.lastError().text();
    return false;
}

QSqlQuery q(db);
q.prepare("update account set balance = balance - ? where id = ?");
q.addBindValue(100);
q.addBindValue(1);
if (!q.exec()) { db.rollback(); return false; }

q.prepare("update account set balance = balance + ? where id = ?");
q.addBindValue(100);
q.addBindValue(2);
if (!q.exec()) { db.rollback(); return false; }

if (!db.commit()) { db.rollback(); return false; }
return true;

转账这个例子最能说明问题：没有事务，扣了钱、加钱失败，账户就凭空少了一百。db.transaction() 不支持嵌套，已经在事务里再调一次返回 false。真要部分回滚就用 SQL 的保存点：q.exec("savepoint sp1") 打点，出错时 q.exec("rollback to sp1") 只撤销打点之后的改动，q.exec("release sp1") 把改动并入外层事务，最后照常 db.commit()。

改完删完想确认动了多少行，用 numRowsAffected()，返回 -1 表示驱动报不出这个数，SQLite 和 MySQL 都能正常报。

七、预编译语句与参数绑定 #

这一节只有一条规矩：SQL 里带变量，就用占位符，别拿 + 拼字符串。

拼字符串的两个后果 #

第一种是 SQL 注入。用户输入被当成语句的一部分执行：

cpp
// 用户输入 name 为  x'; DROP TABLE student; --
QString sql = "insert into student values (1, '" + name + "', 20)";
query.exec(sql);
// 实际执行: insert into student values (1, 'x'; DROP TABLE student; --', 20)

表就没了。第二种更常见，不用恶意攻击，用户名字里带个单引号就炸：

cpp
QString name = "O'Brien";
QString sql = "insert into student values (1, '" + name + "', 20)";
// 语句变成 ... values (1, 'O'Brien', 20)   引号不配对，语法错

报的是 near "Brien": syntax error，看着莫名其妙。prepare() + bindValue() 把两个问题一起解决：值走单独的绑定通道，不参与语句文本拼接，驱动按「值」处理它，引号、分号、-- 都只是普通字符。

两种占位符 #

形式 写法 绑定 API 特点
位置占位符 insert into t values (?, ?, ?) addBindValue(v) / bindValue(i, v) 靠顺序对应
命名占位符 update t set name = :name where id = :id bindValue(":name", v) 靠名字对应，不怕乱序

位置占位符从 0 开始编号，第一个 ? 是 0 号：

cpp
query.prepare("insert into student values (?, ?, ?)");
query.addBindValue(1);        // 第 0 个
query.addBindValue("张三");    // 第 1 个
query.addBindValue(20);       // 第 2 个
query.exec();

也可以显式下标，效果一样：query.bindValue(0, 1);。命名占位符可读性更好，参数多时优势明显：

cpp
query.prepare("update student set name = :name where id = :id");
query.bindValue(":name", "Qt");
query.bindValue(":id", 1);
query.exec();

Qt 支持三种命名前缀：:name、@name、$name，含义相同，选一种用到底。

API 场景 说明
addBindValue(v) 位置占位符 按调用顺序依次对应 ?
bindValue(pos, v) 位置占位符 显式指定第几个
bindValue(":name", v) 命名占位符 按名字绑定
bindValue(name, v, type) 需指定驱动类型时 第三参是 QSql::ParamType
execBatch() 多组参数一次执行 先 prepare，再多次 addBindValue

execBatch() 是先把多组值都塞进去，再一次性执行：

cpp
query.prepare("insert into student values (?, ?, ?)");
QVariantList ids, names, ages;
for (int i = 0; i < 1000; ++i) {
    ids << i;
    names << QString("n%1").arg(i);
    ages << 20 + i % 5;
}
query.addBindValue(ids);
query.addBindValue(names);
query.addBindValue(ages);
if (!query.execBatch()) {
    qDebug() << query.lastError().text();
}

三个 QVariantList 长度必须一致，长度不等会失败。

现象 原因 处理
Parameter count mismatch 占位符个数跟绑定次数不一致 数一遍 ? 的个数
数值列里存进了字符串 传了 QString 而列是数值 传 int / double
中文变问号 连接编码不对 MySQL 上执行 SET NAMES UTF8
绑 NULL 失败 传了空字符串 传构造出来的空 QVariant
占位符没生效 ? 写在引号里了 '?' 是字面量，不是占位符

绑 NULL 的正确写法是 query.bindValue(":remark", QVariant(QVariant::String));。预编译还有第二个好处：同一条语句反复执行时只解析一次语法、生成一次执行计划，后面每次只换参数。所以 prepare() 必须放在循环外：

cpp
query.prepare("insert into log values (?, ?)");
for (const auto &item : logs) {
    query.bindValue(0, item.level);
    query.bindValue(1, item.msg);
    query.exec();
}

放进循环里，就退化成了每次重新解析。

八、模型化：QSqlTableModel #

前面都是手工取数据。要往 QTableView 上铺，用模型省事得多——不用自己建行、不用自己填格子，连编辑都能直接写回数据库。

模型 读写 用途
QSqlQueryModel 只读 展示任意 SELECT 的结果
QSqlTableModel 可读写 单表编辑，改动可提交可撤销
QSqlRelationalTableModel 可读写 带外键的单表编辑，外键列显示为可读值

只读展示，几行就够：

cpp
QSqlQueryModel *model = new QSqlQueryModel(this);
model->setQuery("select id, name, age from student", db);
model->setHeaderData(0, Qt::Horizontal, "编号");
model->setHeaderData(1, Qt::Horizontal, "姓名");
model->setHeaderData(2, Qt::Horizontal, "年龄");
ui->tableView->setModel(model);

setQuery 的第二个参数是连接，不传就用默认连接，多连接程序里必错。

QSqlTableModel 的标准流程 #

cpp
QSqlTableModel *model = new QSqlTableModel(this, db);
model->setTable("student");
model->setEditStrategy(QSqlTableModel::OnManualSubmit);
model->select();

model->setHeaderData(0, Qt::Horizontal, "编号");
model->setHeaderData(1, Qt::Horizontal, "姓名");
ui->tableView->setModel(model);

四步：设表名、设编辑策略、select() 拉数据、挂到视图。setTable 之后必须 select()，否则视图是空的。

策略 行为 适合
OnFieldChange 改一个格立刻写库 实时性要求高、数据量小
OnRowChange 换行时才写库 表格编辑的常规选择
OnManualSubmit 全攒着，调 submitAll() 才写 批量编辑、要「保存/取消」按钮

OnManualSubmit 的配套调用：

cpp
bool ok = model->submitAll();      // 提交所有改动
if (!ok) {
    qDebug() << model->lastError().text();
    model->revertAll();            // 或全部撤销
}

submitAll() 失败时改动还留在模型里，视图上看着像保存成功了，其实库里没变，所以失败分支一定要处理，不能只调不查返回值。写回单个单元格是 model->setData(model->index(row, 1), "新名字"); 再 submitAll()；删一行是 model->removeRow(row) 再 submitAll()，removeRow 只在模型里标记删除，提交时才真正 DELETE。想让视图按数据库现状重来一遍，model->select() 重新查。

带外键的表用 QSqlRelationalTableModel：setTable("student") 之后加一句 setRelation(3, QSqlRelation("class", "id", "name")) 再 select()。第 3 列的值原本是班级 id，视图里直接显示班级名，编辑时下拉框也自动变成班级列表，不用自己维护 id 到名字的映射。

大数据量下的模型 #

QSqlQueryModel 默认只抓 256 行，视图往下滚时才继续抓，靠的是 canFetchMore() 和 fetchMore()。所以直接在模型上问「一共多少行」问不准：

想要 做法
真实总行数 单独 select count(*)
边滚边加载 视图会自动调 fetchMore()
一次全加载 while (model->canFetchMore()) model->fetchMore(); 慎用

数据超过一万行就别指望模型全量加载，改分页查：

cpp
QString sql = QString("select id, name from student limit %1 offset %2")
                  .arg(pageSize).arg(page * pageSize);
query.exec(sql);

单元格反复读同一位置时，还能给模型加一层缓存，减少往回查数据库的次数：

cpp
class CachedTableModel : public QSqlTableModel {
public:
    QVariant data(const QModelIndex &index, int role) const override {
        if (m_rowCache.contains(index.row()))
            return m_rowCache.object(index.row())->value(columnName(index.column()));
        return QSqlTableModel::data(index, role);
    }
    bool setData(const QModelIndex &index, const QVariant &value, int role) override {
        if (!m_rowCache.contains(index.row()))
            m_rowCache.insert(index.row(), new QVariantMap());
        m_rowCache.object(index.row())->insert(columnName(index.column()), value);
        m_rowStatus[index.row()] = 2;   // 标记为已修改
        return true;
    }
private:
    QString columnName(int c) const { return headerData(c, Qt::Horizontal).toString(); }
    QCache<int, QVariantMap> m_rowCache;
    QMap<int, int> m_rowStatus;
};

m_rowStatus 记录每行状态：0 未加载、1 已缓存、2 已修改，提交时按状态决定哪些行要写回。这套做法只在行数几千、编辑频繁的场景下划得来，再多就该上分页。

九、SQLite 的实用技巧 #

SQLite 的能力一半在 SQL，一半在 PRAGMA。这些开关决定它跑得快还是慢。

cpp
QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE", "main");
db.setDatabaseName("app_data.db");
db.setConnectOptions("QSQLITE_BUSY_TIMEOUT=5000");   // 锁冲突等 5 秒再报错
if (!db.open()) {
    qDebug() << db.lastError().text();
    return;
}

QSqlQuery q(db);
q.exec("PRAGMA journal_mode=WAL");
q.exec("PRAGMA synchronous=NORMAL");
q.exec("PRAGMA cache_size=-20000");
q.exec("PRAGMA foreign_keys=ON");
q.exec("PRAGMA temp_store=MEMORY");
q.exec("PRAGMA mmap_size=268435456");
参数 作用 副作用
journal_mode=WAL 写前日志模式，读写不再互斥 多出 -wal、-shm 文件，占磁盘
synchronous=NORMAL 降低刷盘频率 断电时最后几条事务会丢，库不损坏
synchronous=OFF 完全不刷盘 断电会整库损坏，只用在可重建的数据上
cache_size=-20000 页缓存 20MB（负数是 KB） 值过大会吃掉进程内存
foreign_keys=ON 外键约束生效 SQLite 默认关闭，不设等于没约束
busy_timeout=5000 遇锁等 5 秒 设在主线程会卡 UI
temp_store=MEMORY 临时表放内存 大排序会吃内存
mmap_size=268435456 内存映射 256MB 32 位程序上别设太大

foreign_keys 这条最容易被忽略。建表时写 references 只是声明，PRAGMA foreign_keys=ON 才真正校验，而且它按连接生效，每个新连接都要重新设一次。busy_timeout 有两种设法，效果一样：open() 之前走 db.setConnectOptions("QSQLITE_BUSY_TIMEOUT=5000")，或 open() 之后走 q.exec("PRAGMA busy_timeout=5000")，后者能中途改。

内存数据库与自增主键 #

测试时不想留文件，库名写 :memory:，整个库活在内存里，连接一关就没了。注意它是每连接一个独立库，两个连接各自 :memory: 拿到的是两个空库，共享不了。

max(id) + 1 这个写法只在单线程、无删除的场景下成立。删掉最大那条之后 max 退回去，新插入的 id 会跟已有的撞。要真自增，建表时声明：

sql
create table student (
    id   integer primary key autoincrement,
    name varchar(30),
    age  int
);

autoincrement 保证 id 单调递增且永不复用。不带它，SQLite 也用当前最大值 +1 自增，但删除后会复用旧 id。

日期与工具 #

SQLite 没有日期类型，三种存法：文本 2024-03-15 10:30:00 存 text，字典序即时间序（格式必须统一），可读性最好；Unix 时间戳存 integer，排序天然正确，但肉眼看不懂；Julian 日数存 real，同理。文本格式要用 yyyy-MM-dd HH:mm:ss 这种定长补零写法，2024-3-5 会排到 2024-12-01 后面去，存取两侧统一用 QDateTime::toString("yyyy-MM-dd HH:mm:ss") 和 QDateTime::fromString(...)。

想直接看库里的数据，命令行之外还有几个图形工具：SQLite Manager 开源、可独立运行、也能当 Firefox 插件；SQLite Administrator 图形化建表改表、有语法着色、界面中文、适合入门；SQLite Database Browser 是基于 Qt 的轻量 GUI，向导式操作，面向非技术用户。

发布时库文件要可写。装在 Program Files 下的程序往自己目录写 .db 会被 UAC 拦，改写到 QStandardPaths::AppDataLocation。WAL 模式下备份要把 .db 连同 -wal、-shm 一起拷，只拷主文件会丢最近的事务。库文件是二进制，别用 QFile 按文本模式读写。

十、性能优化要点 #

先看基准数据。SQLite 3.35+ 在标准 SSD 上的大致量级：

操作类型 模式 吞吐量 瓶颈
单条 Insert 自动提交 约 100 次/秒 磁盘 I/O
批量 Insert 事务 5 万次/秒以上 单次 fsync
查询 Select WAL 模式 10 万次/秒以上 内存读取

这张表最该记住的是前两行的差距：同一个库、同一台机器，只因为有没有事务，差三个数量级。

优化清单 #

项 做法 收益
批量写入 包 transaction() 收益最大的一项
同步模式 synchronous=NORMAL 明显减少刷盘
页缓存 cache_size=-20000 减少重复读盘
内存映射 mmap_size=268435456 大库随机读变快
索引 给 WHERE、ORDER BY、JOIN 的列建 大表查询从全扫变查找
只取需要的列 别写 select * 减少解码与传输
分页 limit + offset 视图不全量加载
预编译 prepare() 提到循环外 省重复解析

索引不是越多越好。每加一个索引，写入就要多维护一棵 B 树，磁盘占用也跟着涨。删改频繁的表，索引数量控制住。想看语句走没走索引，执行 explain query plan select * from student where name = 'Qt';，输出里出现 SCAN TABLE 是全表扫，出现 SEARCH TABLE ... USING INDEX 才是走了索引。

已知限制 #

限制 表现 应对
单写者 即使 WAL 模式也只允许一个写线程 写入队列，生产者-消费者
页大小 4KB 大表产生内存碎片 大表分页查询
动态类型 跟 Qt 强类型系统冲突 转换带 ok 检查
模型只抓 256 行 视图行数对不上 单独 COUNT(*)
无存储过程 业务逻辑只能写在代码里 上 MySQL
不支持 2PC 无分布式事务 上 MySQL

单写者这条是硬限制。开 WAL 只是让「读」不被「写」挡住，写与写之间仍然排队。写并发上去以后，正确做法是单开一个写线程，别的线程把写请求丢进队列，由它串行落库。

分布式事务、存储过程、OLAP 实时分析、高并发 Web 后端，这四类需求 SQLite 接不住。全文检索上 FTS5 能用，但能力不如 PostgreSQL。移动端、桌面端本地存储、嵌入式设备数据记录、单机配置与缓存，这几类是它的主战场。

十一、连接管理与释放 #

连接管理出问题，症状往往不是报错，而是莫名其妙的卡死和崩溃。

移除连接的顺序 #

removeDatabase() 之前，那个连接上的所有 QSqlQuery 和 QSqlDatabase 副本句柄都必须先析构。用作用域控制是最省心的办法：

cpp
{
    QSqlDatabase db = QSqlDatabase::addDatabase("QMYSQL", "temp_db");
    db.setHostName("192.168.1.100");
    db.setDatabaseName("gv_local");
    db.open();

    QSqlQuery query(db);
    query.exec("select 1");
    db.close();
}   // 右括号：query 和 db 的生命周期结束，析构

QSqlDatabase::removeDatabase("temp_db");

把 removeDatabase 写进作用域内部，或者让 QSqlQuery 活得比 db 长，Qt 会打印这行警告：

QSqlDatabasePrivate::removeDatabase: connection 'temp_db' is still in use, all queries will cease to work.

随后那个连接上的查询全部失效。这类问题在析构顺序复杂的类里特别难查。

步骤 正确做法
1 所有 QSqlQuery 先离开作用域或 finish()
2 db.close()
3 QSqlDatabase 副本句柄离开作用域
4 最后 QSqlDatabase::removeDatabase(name)

每线程一连接 #

多线程操作数据库必须遵循「每线程一连接」。连接对象既不能跨线程传，也不能跨线程共享：

cpp
QString threadConnName = QString("WorkerConn_%1")
                             .arg((quintptr)QThread::currentThreadId());
{
    QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE", threadConnName);
    db.setDatabaseName("app_data.db");
    db.setConnectOptions("QSQLITE_BUSY_TIMEOUT=5000");
    db.open();
    QSqlQuery query(db);
    query.exec("insert into logs values ('INFO', 'msg')");
    db.close();
}
QSqlDatabase::removeDatabase(threadConnName);

连接名里带线程 id 是为了让每个线程拿到自己的连接，避免撞名覆盖。别在 QThread::run() 外面创建连接再传进线程使用，那是崩溃的常见来源。线程结束时一定要把连接清掉，线程反复创建销毁而连接一直留着，会攒出一堆失效句柄，SQLite 上表现为文件锁迟迟不释放。

全局单连接 #

主线程独占一个连接，是所有用法里最简单的：用 QSqlDatabase::addDatabase("QSQLITE", "main") 建一次，调用方只拿 QSqlDatabase::database("main") 的副本，谁都不许 removeDatabase，程序退出时统一在 main 返回前清理，别指望静态对象的析构顺序。

数据库操作耗时超过几十毫秒时，别放在 UI 线程。查询本身不卡，卡的是等待锁和磁盘 I/O。放到工作线程，用信号把结果送回界面。

十二、易错点速查 #

现象 原因 处理
QMYSQL driver not loaded 驱动插件或 libmysql.dll 不在位 查 sqldrivers 目录，补齐库并核对位数
duplicate connection name 重复 addDatabase 默认连接 给连接起名，按名字取实例
connection still in use QSqlQuery 比连接活得久 用作用域控制析构顺序
编译报找不到 QSqlDatabase 没引模块 .pro 加 QT += sql
发布版找不到 .db 相对路径相对工作目录 改绝对路径或 AppDataLocation
database is locked 多连接抢写锁 设 busy_timeout，写操作串行化
事务提交后数据全没 漏了 commit() 或中途回滚 检查每个分支都有 commit 或 rollback
批量插入慢如蜗牛 每条语句自动提交 包进 transaction()，每 1000 条一提交
中文存进去变问号 连接编码不对 MySQL 上 SET NAMES UTF8
数据里有单引号就语法错 拼字符串 改 prepare() + bindValue()
Parameter count mismatch 占位符与绑定值个数不等 数 ?，检查 prepare 是否漏调
select * 取值错位 按列号取，表结构变了 按列名取，或用 record() 算下标
size() 返回 -1 驱动不提供总行数 单独 select count(*)
视图行数只有 256 模型懒加载 用 COUNT(*)，别问模型
submitAll() 后库里没变 提交失败但没查返回值 检查返回值并打印 lastError()
外键约束形同虚设 没开 PRAGMA foreign_keys 每个连接都设一次
id 撞车 用 max(id)+1 手工编号 用 autoincrement 主键
拷了 .db 却丢数据 WAL 模式下漏了 -wal 三个文件一起拷
程序退出时卡一下 连接没关就销毁 显式 close() 再 removeDatabase()

排错顺序建议固定成一条线：先 QSqlDatabase::isDriverAvailable() 确认驱动，再 open() 看 lastError()，再打印 lastQuery() 看语句，最后单独跑一遍 SELECT 验证数据。这四步能把绝大多数问题定位到具体一层，省掉在错误方向上猜的时间。

写完一句 SQL，先问自己三个问题：变量是不是走绑定了，批量写是不是包事务了，连接是不是这个线程自己的。三个都过了，Qt 的数据库层基本不会给你添麻烦。
