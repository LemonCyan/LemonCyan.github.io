本篇只讲结构化数据的读写：Qt 里怎么生成和解析 JSON，怎么用两种方式解析 XML，以及怎么把 XML 写回去。

不讲 HTTP 回包怎么收，那在《Qt 网络编程》；不讲 .ini 与 QSettings，那在《文件配置与表格》；不讲 QSqlQuery 的结果集，那在《数据库》。这三处都会拿到 JSON 或 XML 文本，拿到之后往本篇看。

代码按 Qt 5 写，Qt 6 通用。QJson* 全在 QtCore；DOM 那套在 QtXml，要加模块；流式那套又回到 QtCore，不用加。

一、JSON 与 XML 的分工 #

JSON（JavaScript Object Notation）是轻量级数据交换格式，语法取自 JavaScript 标准 ECMA-262 第三版的一个子集。它跟语言无关，但按 C 语言家族的书写习惯来：{} 是对象，[] 是数组，, 分隔成员，: 连键值。文本形式人能直接读，机器解析成本也低。今天几乎每个 Web API 都吐 JSON。

XML（Extensible Markup Language）是可扩展标记语言。它比 JSON 老，也更啰嗦，但能表达 JSON 表达不了的东西：属性与文本分开、注释、处理指令、DTD、命名空间、混合内容（标签和文本交错）。项目的系统配置、老式数据交换、网络报文，尤其是带 schema 校验的场合，XML 仍是主力。

两者在 Qt 里都归「结构化数据」。选谁不看新旧，看对面是谁给的。

维度 JSON XML
数据模型 对象 / 数组 / 六种标量值 元素树，元素可带属性、文本、子元素
类型系统 有，null、bool、number、string 分开 无，一切是字符串，类型靠应用自己解释
体积 小，没有闭合标签开销 大，每个元素都要闭合
可读性 短，嵌套深了括号难对齐 结构显式，适合人手工改配置
注释 不支持 支持
校验 无标准 schema XSD / DTD / RELAX NG
解析代价 低 高，DOM 尤甚
Qt 里的类 QJsonDocument 一族，在 QtCore QDomDocument 一族在 QtXml，QXmlStreamReader 在 QtCore

一条实用判据：数据只在自己程序里流转，用 JSON；要给人手改、要跟外部系统对接且对方只认 XML，用 XML。

1.1 Qt 4 时代得自己找库 #

Qt 5 之前，Qt 没有内置 JSON 支持，要自己下载编译第三方库。三个常见选择：

库 特点 备注
JsonCpp C++ 处理 JSON 的开发包，接口偏重 独立库，不受 Qt 版本影响
cJSON 单文件，超轻，可作 ANSI-C 标准解析器 嵌进纯 C 项目方便
QJson 基于 Qt 的第三方包，把 JSON 解析成 QVariant，数组映射 QVariantList，对象映射 QVariantMap 名字跟 Qt 5 的 QJson* 撞车，别混

到 Qt 5，官方给了 QJsonDocument，读写 JSON 不用再外挂。今天没有理由再引第三方 JSON 库，除非你要的是一次性扫几百兆的流，那是另一回事。

二、QJson 家族的四个类 #

四个类，分工固定。先记住一句话：QJsonDocument 是「文档」，QJsonObject 和 QJsonArray 是「节点」，QJsonValue 是「值」。

类 角色 你能拿它做什么
QJsonDocument 文档容器，负责与字节流互转 fromJson() / toJson()、isNull() / isEmpty()、isObject() / isArray()、object() / array()、setObject() / setArray()
QJsonObject 对象节点，键值对集合，键唯一且为字符串 insert() / remove() / take()、value() / operator[]、contains()、size()、keys()、isEmpty()
QJsonArray 数组节点，有序值列表 insert() / append() / removeAt() / takeAt()、at() / operator[]、size()、isEmpty()
QJsonValue 单个值，六种类型之一 isNull() / isBool() / isDouble() / isString() / isArray() / isObject()，加对应的 toXxx()

2.1 文档与节点的边界 #

这条边界是初学最容易踩的坑。QJsonDocument::fromJson() 返回的是文档，不是对象。文档本身不能取键，你得先问它装的是对象还是数组，再转成节点：

cpp
QJsonDocument doc = QJsonDocument::fromJson(byte_array);
if (doc.isObject()) {
    QJsonObject root = doc.object();   // 到这里才是节点
    QJsonValue v = root.value("name");
}

反过来也一样。QJsonObject 不能直接 toJson()，必须先塞进文档：

cpp
QJsonObject obj;
obj.insert("name", "Qt");
QByteArray out = QJsonDocument(obj).toJson(QJsonDocument::Compact);

文档的 isNull() 判的是「有没有内容」，isEmpty() 判的是「对象或数组里有没有成员」。两个不是一个意思，QJsonDocument().isNull() 为 true。

QJsonDocument 除了 UTF-8 文本，还能读写 Qt 自己的二进制格式：toBinaryData() 与 fromBinaryData()。二进制版解析比文本快，但格式是 Qt 内部的，跨语言、跨大版本都不保证兼容，只适合进程内临时传递；落盘和对外交互一律 toJson() / fromJson()。

2.2 QJsonValue 的六种类型 #

类型枚举 判断方法 取值方法 说明
Null isNull() toVariant() JSON 的 null，跟「键不存在」不是一回事
Bool isBool() toBool() true / false
Double isDouble() toDouble() JSON 只有一种数字，双精度，没有 int
String isString() toString() UTF-8 存的 QString
Array isArray() toArray() 转成 QJsonArray
Object isObject() toObject() 转成 QJsonObject

「数字都是 double」是硬事实。JSON 里写 5，取出来 isDouble() 为真，toDouble() 得 5.0。要整数就 toInt()，或者 toVariant().toInt()。超过 2^53 的整数在 JSON 里不安全，ID 类字段建议直接当字符串传。

QJsonObject::value() 对不存在的键返回一个 Undefined 的 QJsonValue：isNull() 为 false，所有 isXxx() 全为 false。所以先 contains() 再取，比拿 isNull() 当「没有」要稳。

2.3 QVariant 的双向通道 #

QJsonObject 与 QVariantMap 互转（QJsonObject::fromVariantMap() / toVariantMap()），QJsonArray 与 QVariantList 互转，QJsonDocument::toVariant() 直接吐 QVariant：顶层是对象给 QVariantMap，是数组给 QVariantList。跟已有的 QVariant 代码（模型/视图、属性系统）对接时省事，代价是类型信息被抹平，数字全变 double。

三、生成 JSON #

3.1 生成对象 #

从空对象开始，insert() 一个个塞，套进文档，再 toJson()。

cpp
QJsonObject json;
json.insert("name", QString("Qt"));
json.insert("version", 5);
json.insert("windows", true);

QJsonDocument document;
document.setObject(json);
QByteArray byte_array = document.toJson(QJsonDocument::Compact);
QString json_str(byte_array);

三步拆开写是为了看清结构：组装节点 → 交给文档 → 输出字节。熟了以后一行就够：

cpp
QByteArray byte_array = QJsonDocument(json).toJson(QJsonDocument::Compact);

toJson() 有两种格式，差别只在空白。Compact 的结果：

json
{"name":"Qt","version":5,"windows":true}

Indented 的结果：

json
{
    "name": "Qt",
    "version": 5,
    "windows": true
}

Compact 给网络传，一个字节都不浪费；Indented 给人看，调试时打进日志。发出去用 Compact，落盘给人改用 Indented。

3.2 生成数组 #

数组下标连续，insert(0, ...)、insert(1, ...) 按序塞。也可以 append()，效果一样且不用自己数下标。

cpp
QJsonArray json;
json.insert(0, QString("Qt"));
json.insert(1, QString("version"));
json.insert(2, true);

QJsonDocument document;
document.setArray(json);
QByteArray byte_array = document.toJson(QJsonDocument::Compact);
QString json_str(byte_array);

结果：

json
["Qt","version",true]

setArray() 与 setObject() 是文档的两个入口，用错一个，顶层结构就错。文档装对象或装数组，二选一；也能两者都不装，那时 isNull() 为真。

json.insert("version", 5) 里的 5 是 int，QJsonValue 有 int 构造，转成 double 存。json.insert("name", "Qt") 也行，const char* 会转 QString，但涉及非 ASCII 时显式写 QString::fromUtf8("...") 或 QStringLiteral，别让编译器按本地编码猜。

json["name"] = "Qt" 也行，operator[] 对不存在的键先插一个 Null 再赋新值；读的时候一律用 value()。还有一条：QJsonObject 内部按键的字典序排，insert 的顺序不等于输出顺序，别靠 JSON 的输出顺序传递业务语义。

四、解析 JSON #

4.1 标准流程 #

五步：判错 → 判文档类型 → 取根节点 → 判值类型 → 取值。少一步就有坑。

cpp
QByteArray byte_array = "{\"name\":\"Qt\",\"version\":5,\"windows\":true}";

QJsonParseError json_error;
QJsonDocument parse_document = QJsonDocument::fromJson(byte_array, &json_error);

if (json_error.error == QJsonParseError::NoError) {
    if (parse_document.isObject()) {
        QJsonObject obj = parse_document.object();
        if (obj.contains("name")) {
            QJsonValue name_value = obj.value("name");
            if (name_value.isString()) {
                QString name = name_value.toString();
            }
        }
        if (obj.contains("version")) {
            QJsonValue version_value = obj.value("version");
            if (version_value.isDouble()) {
                int version = version_value.toVariant().toInt();
            }
        }
        if (obj.contains("windows")) {
            QJsonValue windows_value = obj.value("windows");
            if (windows_value.isBool()) {
                bool flag = windows_value.toBool();
            }
        }
    }
}

结果：

text
name：Qt
version：5
windows：true

原稿这里用的是 obj.take("name")。take() 能取值，但取完会把键从对象里删掉：解析完就丢、每个键只取一次，没毛病；但同一个键要再取一遍就取不到了，调试时对象也被掏空，看不到原始内容。换成 value()，只读不删，行为更好预测。

version 那一行值得单独说。isDouble() 过了之后，toVariant().toInt() 与 toInt() 等价，后者更直接。toInt() 对非数字返回 0，不抛错，所以前面的 isDouble() 判断不能省。

4.2 解析数组 #

cpp
QJsonParseError json_error;
QJsonDocument parse_document = QJsonDocument::fromJson(byte_array, &json_error);

if (json_error.error == QJsonParseError::NoError) {
    if (parse_document.isArray()) {
        QJsonArray array = parse_document.array();
        int size = array.size();
        for (int i = 0; i < size; ++i) {
            QJsonValue value = array.at(i);
            if (value.isString()) {
                QString name = value.toString();
                qDebug() << i << name;
            } else if (value.isBool()) {
                bool flag = value.toBool();
                qDebug() << i << flag;
            }
        }
    }
}

结果，数组不同下标对应的值：

text
0：Qt
1：version
2：true

array.at(i) 返回 QJsonValue，下标越界不崩，返回 Undefined，所有 isXxx() 为假，取值全空。循环上界用 size()，别写死。Qt 5.1 起还能直接范围 for：

cpp
for (const QJsonValue &v : array) {
    if (v.isString())
        qDebug() << v.toString();
}

有个高频提问正好落在这：拿到了 {"code":100000,"text":"你好 嘻嘻"}，isArray() 进不去。原因很简单，顶层是对象不是数组。把 isArray() 换成 isObject()，array() 换成 object()。

4.3 取值 API 对照 #

场景 写法 说明
判断键在不在 obj.contains("k") 取之前先问一句
只读取值 obj.value("k") 键不存在返回 Undefined
取出并删除 obj.take("k") 取完键就没了
按键取值 obj["k"] 非 const 版本对缺失键会插一个 Null
遍历所有键 obj.keys() 按键的字典序返回
数组按下标 arr.at(i) / arr[i] 越界返回 Undefined
数组追加 arr.append(v) / arr.push_back(v) 末尾追加
数组遍历 for (const QJsonValue &v : arr) 只读用 const 引用

五、JSON 的嵌套结构与数组 #

真实报文不会只有一层。典型形状是「对象套数组，数组里再套对象」。生成和解析都得逐层走。

5.1 生成嵌套 #

自底向上：先造内层节点，再造外层，最后交给文档。

cpp
// 内层：地址对象
QJsonObject address;
address.insert("city", QStringLiteral("Hangzhou"));
address.insert("zip", QStringLiteral("310000"));

// 内层：成员对象
QJsonObject member;
member.insert("id", 1);
member.insert("nick", QStringLiteral("一去丶二三里"));
member.insert("vip", true);
member.insert("address", address);   // 对象套对象

// 中间层：成员数组
QJsonArray members;
members.append(member);
members.append(QJsonObject{
    {"id", 2},
    {"nick", QStringLiteral("奋斗的孩子")},
    {"vip", false}
});

// 顶层：对象
QJsonObject root;
root.insert("title", QStringLiteral("Qt 学习小组"));
root.insert("count", members.size());
root.insert("members", members);

QByteArray out = QJsonDocument(root).toJson(QJsonDocument::Compact);

QJsonObject{ {"id", 2}, ... } 是初始化列表构造，Qt 5.4 起支持。临时对象用它省几行；成员多、要顺序插、要判断插入结果，还是老实 insert()。

结果是：

json
{"count":2,"members":[{"address":{"city":"Hangzhou","zip":"310000"},"id":1,"nick":"一去丶二三里","vip":true},{"id":2,"nick":"奋斗的孩子","vip":false}],"title":"Qt 学习小组"}

看输出的顺序：键被按字典序重排了，数组的元素顺序原样保住。数组顺序是语义的一部分，对象键顺序不是。前端如果按字符串比对报文，这条差异会咬人。

5.2 解析嵌套 #

一路 isObject() / toObject() / toArray() / at() 往下钻：

cpp
QJsonParseError err;
QJsonDocument doc = QJsonDocument::fromJson(out, &err);
if (err.error != QJsonParseError::NoError || !doc.isObject()) {
    qWarning() << "bad json:" << err.errorString();
    return;
}

QJsonObject root = doc.object();
QString title = root.value("title").toString();
int count = root.value("count").toInt();   // 数字统一 double，toInt() 会截断

QJsonArray members = root.value("members").toArray();
for (const QJsonValue &mv : members) {
    if (!mv.isObject())
        continue;
    QJsonObject member = mv.toObject();
    int id = member.value("id").toInt();
    QString nick = member.value("nick").toString();
    bool vip = member.value("vip").toBool();
    qDebug() << id << nick << vip;

    if (member.value("address").isObject()) {
        QJsonObject addr = member.value("address").toObject();
        QString city = addr.value("city").toString();
        qDebug() << "  city:" << city;
    }
}

三个要点：

  • toObject() 对非对象返回空对象，之后 value() 全给 Undefined，取值全空，不崩。所以进循环先 isObject() 拦一下，别直接 toObject()。
  • toArray() 同理，非数组返回空数组，size() 为 0，循环一次都不进。语义上「没有数据」和「结构不对」被混成一样了，要区分只能自己先判类型。
  • 嵌套层数没有上限，每层都该有条防御，尤其报文来自外部。

层数一多，value().toObject().value().toArray().at().toObject() 这种链就没法看，中间断一环就静默返回空。常见做法：每层取完立刻判 isObject() / isArray()，断了就早退；或者封个按路径取值的函数，路径元素放 QVariant，int 走数组分支、QString 走对象分支，断了统一返回 Undefined。

六、解析失败怎么处理 #

JSON 侧用 QJsonParseError，XML 侧用 xml.hasError()。两者共性：不判错的话，失败给你一个空文档或空树，后面所有取值静默为空，真正的错因要到几百行之外才炸出来。

6.1 QJsonParseError 的字段 #

字段 类型 说明
error QJsonParseError::ParseError 枚举值，NoError 才算成功
offset int 出错位置的字节偏移，从 0 起，可直接拿来切原文定位

6.2 错误枚举速查 #

枚举 含义 常见成因
NoError 无错误 ——
UnterminatedObject 对象没闭合 少写 }
MissingNameSeparator 键值之间缺 : 手工拼报文
UnterminatedArray 数组没闭合 少写 ]
MissingValueSeparator 成员之间缺 , 拼接时漏了逗号
IllegalValue 值非法 裸标识符、单引号字符串、True 这种大小写错
TerminationByNumber 数字后面接不上字符 123abc
IllegalNumber 数字格式错 1.2.3、01、+5
IllegalEscapeSequence 转义序列非法 \x、\'
IllegalUTF8String 字符串不是合法 UTF-8 本地编码（GBK）字节直接塞进报文
UnterminatedString 字符串没闭合 少写 "
MissingObject 该给对象的地方给了别的 报文结构跟约定不符
DeepNesting 嵌套层数超限 生成端递归失控，或恶意构造
DocumentTooLarge 文档超过解析器上限 一次吞了超大文件
GarbageAtEnd 文档结束后还有多余字符 多拼了一段、粘了两个包

GarbageAtEnd 在实际项目里出现频率最高，它基本等于「你的缓冲区里塞了两条报文」，跟 TCP 粘包是同一类问题。

6.3 带定位信息的报错 #

cpp
QJsonParseError err;
QJsonDocument doc = QJsonDocument::fromJson(payload, &err);
if (err.error != QJsonParseError::NoError) {
    qWarning("JSON 解析失败：%s（偏移 %d）",
             qPrintable(err.errorString()),
             err.offset);
    int from = qMax(0, err.offset - 20);
    qWarning() << "就近内容：" << payload.mid(from, 60);
    return false;
}

errorString() 给一句人话，offset 给位置，两个都打。offset 是字节偏移不是字符偏移：报文全 ASCII 时两者一致，含中文时对不上，切原文要按字节切，QByteArray::mid() 正好是字节。

6.4 不判错的后果 #

fromJson() 失败时返回 QJsonDocument()，isNull() 为真。你直接 doc.object()，拿到一个空 QJsonObject：contains() 全 false，value() 全 Undefined，toString() 全空串。

然后代码一路往下走：空用户名写进数据库、空 token 拿去请求、if (name.isEmpty()) 报出「参数错误」而不是「解析失败」。真正的错因被埋在第一现场之外。两个判断一个都不能省：err.error != NoError 就返回；isObject() / isArray() 跟预期不符也返回。XML 侧同理：QDomDocument::setContent() 返回 bool 并输出 error 字符串和 row/column，QXmlStreamReader 用 hasError() 加 errorString()，具体写法在后面两章，判断逻辑跟 JSON 这章是一个道理。

七、XML 的两种解析方式 #

XML 是标记语言，项目的系统配置、数据交换、网络报文，这三处最常见。QtXml 模块提供了读写接口，解析这条路有两条：DOM 和流式。

方式 代表类 工作方式 内存 所在模块
DOM QDomDocument 一族 整体读入，建成节点树 高，约为文件大小数倍 QtXml
SAX QXmlSimpleReader 事件回调推给你 低 QtXml
流式 QXmlStreamReader / QXmlStreamWriter 拉模型，自己调 readNext() 低 QtCore

从 Qt 5.0 起，官方推荐用 QXmlStreamReader 与 QXmlStreamWriter 解析和生成 XML。这两个类在 QtCore 核心模块里，工程文件不用加模块；DOM 与 SAX 那套树接口的类留在 QtXml，要加 QT += xml。

7.1 SAX 为什么被流式替掉 #

SAX 是推模型：解析器读到什么就回调你的 handler，你继承 QXmlDefaultHandler，重写 startElement() / characters() / endElement()，状态全靠成员变量自己攒。处理逻辑一复杂，状态机就乱，断点也没法跟。

拉模型把控制权交回给你：while 循环里自己 readNext()，读到第几个 token、现在在哪个元素里，一眼能看清。Qt 官方推荐流式类的原因就在这，SAX 留着兼容旧代码。

八、QDomDocument：DOM 树 #

8.1 工程配置 #

DOM 在 QtXml 里，.pro 加一行：

text
QT += xml

CMake 工程换成：

text
find_package(Qt6 REQUIRED COMPONENTS Xml)
target_link_libraries(你的目标 PRIVATE Qt6::Xml)

头文件按需引入：

cpp
#include <QDomDocument>
#include <QDomElement>
#include <QDomNodeList>
#include <QDomNode>
#include <QFile>
#include <QMessageBox>
#include <QDebug>

8.2 待解析的示例文件 #

person.xml：根元素 <persons> 带一个 name 属性，里面两个 <person>，各带 id 属性与四个子元素。

8.3 把文件加载成树 #

cpp
void parseXML(QString file_name)
{
    if (file_name.isEmpty())
        return;

    QFile file(file_name);
    if (!file.open(QFile::ReadOnly | QFile::Text)) {
        QMessageBox::warning(nullptr, "Warning", "Open file error!");
        return;
    }

    QDomDocument document;
    QString error;
    int row = 0, column = 0;

    // 1. 文件内容整体读入，建成内存里的 DOM 树
    if (!document.setContent(&file, false, &error, &row, &column)) {
        QMessageBox::critical(nullptr, "Error",
            QString("Parse file failed at line %1, col %2: %3")
            .arg(row).arg(column).arg(error));
        file.close();
        return;
    }
    file.close();   // 树已建好，文件句柄可以放手

    if (document.isNull()) {
        QMessageBox::warning(nullptr, "Warning", "Document is null!");
        return;
    }

setContent() 有五个参数：QIODevice*、是否处理命名空间、错误串、错误行、错误列。第二个参数传 false 表示不处理命名空间；传 true 后元素名会带命名空间前缀，tagName() 拿到的字符串跟你想的不一样。

setContent() 返回之后文件就能关。DOM 把整棵树搬进内存了，后续所有操作都不再碰这个 QFile——这就是 DOM 吃内存的根源。

documentElement() 跳过 XML 声明和注释，直接给根元素。attribute() 对不存在的属性返回空串，想区分「没有这个属性」和「属性值是空串」，得先用 hasAttribute() 问一句。

8.5 遍历法一：兄弟指针 #

cpp
    // 继续在 parseXML() 里
    qDebug() << "--- firstChildElement & nextSiblingElement ---";
    QDomElement person_element = root.firstChildElement("person");
    while (!person_element.isNull()) {
        QString id = person_element.attribute("id");
        qDebug() << "Person ID:" << id;

        QDomElement child = person_element.firstChildElement();
        while (!child.isNull()) {
            QString tag_name = child.tagName();   // "name"、"age"
            QString tag_value = child.text();     // 对应的文本
            qDebug() << "  " << tag_name << ":" << tag_value;
            child = child.nextSiblingElement();   // 移向同级下一个兄弟元素
        }
        person_element = person_element.nextSiblingElement("person");
    }

三个要点：

  • firstChildElement("person") 只找同名子元素，自动跳过空白文本节点。XML 里元素之间的换行和缩进会生成文本节点，用 childNodes() 遍历会把这些也算进去，所以按元素遍历一律用 firstChildElement() / nextSiblingElement()。
  • nextSiblingElement("person") 带标签名时只返回同名兄弟，中间夹着别的元素直接跳过；不带参数就返回任意下一个兄弟元素。
  • isNull() 是循环终止条件。走到最后一个元素时，nextSiblingElement() 给你一个空元素，isNull() 为真，循环退出。

8.6 遍历法二：QDomNodeList #

cpp
    // 同一份数据，换种遍历法，parseXML() 结尾
    qDebug() << "--- QDomNodeList ---";
    QDomNodeList list = root.childNodes();
    int count = list.count();
    for (int i = 0; i < count; i++) {
        QDomNode dom_node = list.item(i);
        if (dom_node.isElement()) {
            QDomElement element = dom_node.toElement();
            QString id_val = element.attribute("id");
            qDebug() << "Node index" << i << ", ID:" << id_val;

            QDomNodeList child_list = element.childNodes();
            int child_count = child_list.count();
            for (int j = 0; j < child_count; j++) {
                QDomNode child_dom_node = child_list.item(j);
                if (child_dom_node.isElement()) {
                    QDomElement child_element = child_dom_node.toElement();
                    QString tag = child_element.tagName();
                    QString val = child_element.text();
                    qDebug() << "    " << tag << "=>" << val;
                }
            }
        }
    }
}

childNodes() 给的是全部子节点，文本节点、注释节点都在里面，所以必须 isElement() 过滤，再 toElement() 转成元素，之后才能用 tagName() / attribute()。QDomNode 是所有节点的基类，QDomElement 是它的子类，这一层转换不能省。

两种遍历法的差别：第一种只走元素，代码短、意图清楚；第二种能拿到完整节点序（含文本节点），适合统计、校验、需要知道空白在哪的场合。

QDomElement::text() 只给直属文本，不往子元素里钻。元素里再套元素时，深层的文本拿不到，得自己递归下去。节点类型上，QDomNode 是所有节点的基类，元素、文本、注释、文档都派生自它，isElement() / isText() 判完再用 toElement() / toText() 转下去，一步都不能跳。

九、QXmlStreamReader：流式解析 #

QXmlStreamReader 是更快、更方便的流式解析器，也是传统 SAX 解析器（QXmlSimpleReader）的替代品。它随读随走，不把整个文档载进内存，处理大 XML 时速度和内存占用都好过 DOM。

它在 QtCore 里，.pro 不用加 QT += xml。

9.1 核心思路 #

一个 while：只要没读完、没出错，就 readNext() 把指针往前挪一格，拿到当前 token 类型，按类型分支处理。核心就这么点，剩下全是对 token 的解读。

9.2 Token 类型速查 #

Token 出现时机 取什么
StartDocument 文档开头，一次 无
StartElement 遇到 <tag ...> name()、attributes()
EndElement 遇到 </tag> name()
Characters 元素内的文本 text()
Comment <!-- ... --> text()
DTD <!DOCTYPE ...> text()
EntityReference 实体引用 name()
ProcessingInstruction <?xml ...?> 一类 processingInstructionTarget()
EndDocument 文档结尾，一次 无
Invalid 出错 errorString()

Characters 会被切段。文本里出现实体引用（&amp;）或 CDATA 时，一段连续文本会拆成多个 Characters token。要拿完整文本得自己拼。这点跟 DOM 的 text() 直接给整段不一样，是流式解析的固有代价。

9.3 完整解析代码 #

cpp
#include <QFile>
#include <QXmlStreamReader>
#include <QList>
#include <QMap>
#include <QMessageBox>
#include <QDebug>

class ParseXML
{
public:
    void parseXML(const QString &file_name);

private:
    QMap<QString, QString> parsePerson(QXmlStreamReader &xml);
    void addElementDataToMap(QXmlStreamReader &xml, QMap<QString, QString> &map) const;
};

// 1. 主流式解析函数
void ParseXML::parseXML(const QString &file_name)
{
    if (file_name.isEmpty())
        return;

    QFile file(file_name);
    if (!file.open(QFile::ReadOnly | QFile::Text)) {
        QMessageBox::information(nullptr, "Error", "Open file error!");
        return;
    }

    // QXmlStreamReader 能挂任何 QIODevice：QFile、QTcpSocket、QBuffer 都行
    QXmlStreamReader xml(&file);
    QList<QMap<QString, QString>> persons;

    // 循环推流，直到读完或出错
    while (!xml.atEnd() && !xml.hasError()) {
        QXmlStreamReader::TokenType token = xml.readNext();

        // 文档起点，跳过
        if (token == QXmlStreamReader::StartDocument)
            continue;

        if (token == QXmlStreamReader::StartElement) {
            // 根节点，继续往下读
            if (xml.name() == "persons")
                continue;
            // person 节点，进属性和子节点
            if (xml.name() == "person")
                persons.append(this->parsePerson(xml));
        }
    }

    // 拦截 XML 格式错误
    if (xml.hasError()) {
        QMessageBox::warning(nullptr, "Parse Error", xml.errorString());
    }

    // 卸载设备并重置 reader 状态，释放资源
    xml.clear();
    file.close();

    qDebug() << "Total parsed persons:" << persons.size();
}

// 2. 读一个 <person> 及其子元素
QMap<QString, QString> ParseXML::parsePerson(QXmlStreamReader &xml)
{
    QMap<QString, QString> person;

    // 校验当前位置确实是 person 的开始标签
    if (xml.tokenType() != QXmlStreamReader::StartElement || xml.name() != "person")
        return person;

    // 属性表
    QXmlStreamAttributes attributes = xml.attributes();
    if (attributes.hasAttribute("id"))
        person["id"] = attributes.value("id").toString();

    xml.readNext();   // 指针前移

    // 只要没读到 </person> 就继续处理子元素
    while (!(xml.tokenType() == QXmlStreamReader::EndElement && xml.name() == "person")) {
        if (xml.tokenType() == QXmlStreamReader::StartElement) {
            if (xml.name() == "name" || xml.name() == "age"
                || xml.name() == "email" || xml.name() == "website") {
                this->addElementDataToMap(xml, person);
            }
        }
        xml.readNext();
    }

    return person;
}

// 3. 把元素里的字符数据（Characters）填进 Map
void ParseXML::addElementDataToMap(QXmlStreamReader &xml, QMap<QString, QString> &map) const
{
    if (xml.tokenType() != QXmlStreamReader::StartElement)
        return;

    QString element_name = xml.name().toString();   // "name"、"age"

    xml.readNext();   // 挪进元素内部，此时 token 应为 Characters

    if (xml.tokenType() != QXmlStreamReader::Characters)
        return;

    map.insert(element_name, xml.text().toString());
}

9.4 三个易错点 #

第一，readNext() 会移动位置，位置错了 text() 就是空。站在 <name> 的 StartElement 上，text() 此时是空的；必须 readNext() 一次，token 变成 Characters，text() 才有内容。上面 addElementDataToMap() 干的就是这件事。

第二，helper 消费了一个 token，调用方要按当前位置理解后续。addElementDataToMap() 把指针停在 Characters 上，parsePerson() 的循环接着 readNext()，正好走到 </name> 的 EndElement；再下一轮 readNext() 才到 <age>。位置对不上，整段解析全乱。

第三，xml.clear() 不能漏。reader 握着设备的指针，不清空的话设备被销毁后 reader 里是野指针。

9.5 atEnd 与 hasError 的分工 #

  • atEnd() 为真：流读完了，已经拿到 EndDocument，或者设备没数据了。
  • hasError() 为真：遇到格式错误，errorString() 给描述。

循环条件两个都要，缺一个就会在出错后死循环或读到越界。循环退出后再判一次 hasError()，因为退出有两种原因——读完，或者出错——得分开处理。

十、DOM 与流式的取舍 #

两条路都能解析同一份 XML，选错就是内存爆或者代码绕。

判据 选 DOM 选流式
文件大小 几 KB 到几 MB，能整份放进内存 几十 MB 以上，或者大小不可控
访问方式 要反复查找、回跳、按路径取 顺序扫一遍就完事
是否要改结构 要增删节点再写回 不改，只读
数据来源 本地配置文件 网络流、串口流、超大日志
错误定位 想要行号列号 只想知道错了没有
开发成本 低，遍历直观 中，状态自己维护

一句话概括：大文件用流式，要反复查找用 DOM。

10.1 内存差多少 #

DOM 把每个元素、属性、文本都变成对象，节点对象本身有头有开销，加上字符串是按值存的，实际占用要按原文件的好几倍算。一个 100 MB 的 XML 交给 QDomDocument，进程内存冲到几百 MB 不奇怪，32 位程序直接分配失败。

流式解析的内存占用跟文件大小无关，只跟当前处理的元素深度有关，基本是常数级。

10.2 流式的硬限制 #

QXmlStreamReader 不能回头。读到 </person> 之后想再看一眼前面的 <name>，只能重新读一遍文件。所以：

  • 需要多次遍历同一份数据，先把关心的字段抽进自己的结构（QList<QMap<...>>、结构体数组），后面全在结构上操作。
  • 需要父子双向引用（比如后面才出现的 parentId 要指回前面的节点），第一遍建立索引，第二遍再回填。
  • 需要随机取第 N 个节点，流式帮不上，读完存进 QVector 再按下标取。

10.3 混合用的写法 #

工程里的常见形态是「流式扫大文件，抽出的片段交给 DOM 细看」：外层 QXmlStreamReader 循环找 <person>，找到后调 xml.readElementText(QXmlStreamReader::IncludeChildElements) 把这一段的完整内容（含子元素）当字符串取走，再 QDomDocument::setContent() 建一棵小树随便翻。readElementText() 会把指针自动跳到 EndElement 之后，跟外层循环不冲突；参数决定要不要包含子元素，默认只取纯文本，那样 <person> 里的标签就全丢了。这是流式和树式之间的接口。

十一、写 XML #

生成 XML 比解析省心，结构是自己定的，不用猜。工具也有两个：QXmlStreamWriter 和 QDomDocument。

11.1 QXmlStreamWriter #

跟 reader 对称，同样在 QtCore，.pro 不用加模块。

cpp
QFile file("out.xml");
if (!file.open(QFile::WriteOnly | QFile::Text)) {
    qWarning() << "open failed";
    return;
}

QXmlStreamWriter xml(&file);
xml.setAutoFormatting(true);   // 打缩进，给人看
xml.writeStartDocument();      // <?xml version="1.0" encoding="UTF-8"?>

xml.writeStartElement("persons");
xml.writeAttribute("name", "Qt");

xml.writeStartElement("person");
xml.writeAttribute("id", "1");
xml.writeTextElement("name", QStringLiteral("一去丶二三里"));
xml.writeTextElement("age", "25");
xml.writeTextElement("email", "liang19890820@163.com");
xml.writeTextElement("website", "http://blog.sina.com.cn/liang19890820");
xml.writeEndElement();         // </person>

xml.writeEndElement();         // </persons>
xml.writeEndDocument();
file.close();
调用 作用 注意
writeStartDocument() / writeEndDocument() 写 XML 声明与收尾 成对，漏一半输出就非法
writeStartElement() / writeEndElement() 开闭标签 成对，嵌套顺序要对
writeAttribute() 写属性 必须在开始标签之后、任何内容之前
writeTextElement() 标签 + 文本 + 闭合，一步到位 会自动转义 &、<、>
writeCharacters() 只写文本 空文本不会产生 Characters token
writeCDATA() 写 CDATA 段 文本里有大量 < > 时用
setAutoFormatting(true) 自动缩进 生产报文关掉，省字节

writeTextElement() 是高频调用，它等于 writeStartElement() + writeCharacters() + writeEndElement() 三句。要写原样的实体引用，用 writeEntityReference()；要写注释，用 writeComment()。

写完必须 close() 或者至少 flush()。writer 有自己的缓冲，不关文件的话，磁盘上只有一个半截 XML。

11.2 QDomDocument 写回 #

已经有树、或者要在已有文档上改，用 DOM 更顺手。

cpp
QDomDocument doc;
QDomElement root = doc.createElement("persons");
root.setAttribute("name", "Qt");
doc.appendChild(root);

QDomElement person = doc.createElement("person");
person.setAttribute("id", "1");
root.appendChild(person);

QDomElement name = doc.createElement("name");
name.appendChild(doc.createTextNode(QStringLiteral("一去丶二三里")));
person.appendChild(name);

// 输出
QByteArray bytes = doc.toByteArray(4);   // 缩进 4 个空格
QFile f("out.xml");
if (f.open(QFile::WriteOnly | QFile::Truncate))
    f.write(bytes);

toByteArray(int indent) 与 toString(int indent) 只差返回类型，前者 QByteArray，后者 QString。带 indent 会缩进，传 0 或 -1 输出紧凑格式。

11.3 写完要能读回来 #

生成端和解析端必须约定同一套东西：编码（一律 UTF-8）、根元素名、属性还是子元素承载数据、空值怎么写（空元素、空字符串、还是干脆不写这个标签）。约定不一致，自己写的文件自己的解析器都读不对。最省事的验证方式：写完立刻用自己的解析函数读一遍，跑通了再交给外部。

十二、易错点速查 #

现象 原因 处理
isArray() 进不去 顶层是对象不是数组 换 isObject()，取 object()
解析完所有字段都是空 没判 error.error，失败文档当成功用 先判错再取值
QJsonObject 直接 toJson() 编译不过 对象不是文档 QJsonDocument(obj).toJson(...)
数字取出来是 0 或截断 JSON 只有 double，toInt() 直接截 先 isDouble()，再定精度
同一个键第二次取不到 第一次用了 take() 只读取值用 value()
中文变乱码 报文按本地编码塞进 QByteArray 全程 UTF-8，QString::fromUtf8()
GarbageAtEnd 缓冲区里粘了两条报文 先切帧再解析，一帧一解析
offset 定位偏了 那是字节偏移不是字符偏移 按字节 mid()，别按字符数
DOM 遍历数量对不上 childNodes() 里含空白文本节点 改用 firstChildElement()
遍历提前结束 忘判 isNull() while (!e.isNull())
text() 拿不到深层文本 它只给直属文本 递归进子元素取
流式 text() 是空的 停在 StartElement 上没前进 先 readNext() 到 Characters
流式解析到一半想回头 拉模型不能回退 先抽进自己的结构体再处理
半个文档当完整文档用 循环退出后没判 hasError() 退出后再判一次
链接报 undefined reference DOM 类在 QtXml 里 .pro 加 QT += xml
写出的文件是半截 writer 缓冲没刷 close() 或 flush()

JSON 这条线，认准 QJsonDocument 是文档、QJsonObject / QJsonArray 是节点。解析时 fromJson() 拿文档，判完类型再 object() / array() 逐层往下钻；生成时一层层组装节点，最后 QJsonDocument(obj).toJson() 一次输出。两端的错误判断都不能省，QJsonParseError 和 isObject() 是两个闸门。

XML 这条线，认准「大文件用流式，要反复查找用 DOM」。DOM 建树、随机访问方便、吃内存；流式边读边走、省内存、不能回溯。QXmlStreamReader 的坑集中在一个地方：readNext() 把指针挪到哪，你就得在哪取数据，挪错了 text() 就是空的。
