这篇只讲一件事：把数据变成曲线，再让它动起来、看起来顺眼。主线四步——建图、灌数据、刷新、美化。碰到的接口就那么几个：addGraph()、graph()、setData()、addData()、removeDataBefore()、replot()、setPen()、setBrush()、setLineStyle()、setScatterStyle()。

不讲的部分：qcustomplot.h/qcustomplot.cpp 怎么塞进工程、widget 怎么提升、帮助文档怎么挂进 Qt Creator，这些在同目录《QCustomPlot 入门与安装》里。坐标轴刻度的精细定制、缩放拖拽交互、性能调优的完整清单在《QCustomPlot 坐标轴与性能》里。柱状图、蜡烛图、财务图元不在本篇范围。

代码里的 customPlot 和 ui->customPlot 指的是同一个东西——提升后的 QCustomPlot 控件指针。素材里两种写法混着用，跟着上下文看就行。

一、画一条曲线最少要几步 #

QCustomPlot 是个小型的 Qt 绘图类，静态曲线、动态曲线、多重坐标曲线、柱状图、蜡烛图都能画。前置只有两件事：工程里放进 qcustomplot.h 和 qcustomplot.cpp，界面上把一个 widget 提升成 QCustomPlot。装完之后，本章的起点就是一个能画图的控件指针。

五步，一步都不能省，最后一步最容易被忘。

cpp
QCustomPlot *plot = ui->customPlot;

// 1. 建一条曲线
plot->addGraph();

// 2. 造数据
QVector<double> x(101), y(101);
for (int i = 0; i < 101; ++i) {
    x[i] = i / 5.0 - 10;          // 写 i / 5 就是整数除法，只会得到一堆整数
    y[i] = x[i] * x[i] * x[i];    // y = x^3
}

// 3. 灌数据
plot->graph(0)->setData(x, y);

// 4. 定视窗
plot->xAxis->setRange(-10, 10);
plot->yAxis->setRange(-1000, 1000);

// 5. 真正画出来
plot->replot();

把这段的因果捋直：

text
addGraph()            建一个空的曲线容器，拿到下标
    |
    v
setData()/addData()   往容器里塞点
    |
    v
setRange()            决定坐标系里哪一段被显示
    |
    v
replot()              把这一刻的状态画到屏幕上

前四步只改内存里的对象状态。屏幕上一个像素都不会动。第五步才发生绘制。

漏掉 replot() 的现象特别典型：编译通过、运行不报错、控件是白的、控制台干干净净。新手第一反应是「数据没进去」，加 qDebug() 一打，数据明明在。问题出在没人通知控件重新画。

还有一个前置条件得先满足：ui->customPlot 这个控件本身得是 QCustomPlot 类型。也就是说 widget 提升那一步已经做完了。提升的时候类名每个单词首字母大写，写 QCustomPlot，不要写 Qcustomplot 或 qcustomplot，否则 Qt 认不出这个类，界面直接空白。工程 .pro 里还得有 QT += printsupport，QCustomPlot 用了打印相关的类，缺了这行链接就报错。

骨架落到工程里就这么多。头文件里放 #include "qcustomplot.h" 和 Ui::Widget *ui，剩下全在构造函数：

cpp
Widget::Widget(QWidget *parent) :
    QWidget(parent),
    ui(new Ui::Widget)
{
    ui->setupUi(this);

    ui->customPlot->addGraph();
    ui->customPlot->graph(0)->setPen(QPen(Qt::blue));

    QVector<double> x(101), y(101);
    for (int i = 0; i < 101; ++i) {
        x[i] = i / 5.0 - 10;
        y[i] = x[i] * x[i] * x[i];
    }

    ui->customPlot->graph(0)->setData(x, y);
    ui->customPlot->xAxis->setRange(-10, 10);
    ui->customPlot->yAxis->setRange(-1000, 1000);
    ui->customPlot->replot();
}

Widget::~Widget()
{
    delete ui;
}

顺手把每行在干什么记住：

| 代码 | 作用 | 不做会怎样 | | addGraph() | 新建一条曲线，返回 QCPGraph* | 没有载体，graph(0) 是空指针 | | graph(0) | 取第 0 条曲线 | 下标越界返回 nullptr，解引用就崩 | | setPen() | 线的颜色、粗细、虚实 | 默认黑色细线，多条曲线分不清 | | setData(x, y) | 整条曲线数据替换 | 曲线是空的 | | xAxis->setRange() | X 轴显示区间 | 默认区间不含你的数据，看到空白 | | replot() | 重绘整幅图 | 全部白干 |

二、graph 与 addGraph 的区别 #

这一对是最容易搞混的。名字像，行为完全不同。

addGraph() 是创建。调一次，曲线条数加一，返回新曲线的指针，下标是 graphCount() - 1。

graph(i) 是取用。它不创建任何东西，只按号取。取不到就返回 nullptr。

cpp
plot->addGraph();          // 0 号诞生
plot->addGraph();          // 1 号诞生
plot->addGraph();          // 2 号诞生

plot->graph(0)->setPen(QPen(Qt::blue));
plot->graph(1)->setPen(QPen(Qt::red));
plot->graph(2)->setPen(QPen(Qt::green));

素材里那段代码是两条曲线，graph(0) 和 graph(1) 这两个下标就是这么来的：第一次 addGraph() 拿到 0，第二次拿到 1。顺序颠倒过来，颜色和名字就全对不上。

顺手把相关的都列在一张表里：

| 调用 | 语义 | 返回值 | 副作用 | | addGraph() | 新建一条曲线 | QCPGraph* | 条数 +1，图例多一条 | | graph(0) | 取 0 号曲线 | QCPGraph* | 无 | | graph() | 等价 graph(0) | QCPGraph* | 无 | | graphCount() | 现有条数 | int | 无 | | removeGraph(i) | 删掉 i 号 | void | 它后面的下标全部前移 | | clearGraphs() | 清空全部曲线 | void | 数据和图例条目一起没 |

写循环加数据的时候，有一种错法见一次就忘不掉：

cpp
// 错：每次来数据都新建一条曲线
void Widget::onNewSample(double key, double value)
{
    ui->customPlot->addGraph();
    ui->customPlot->graph(ui->customPlot->graphCount() - 1)->addData(key, value);
    ui->customPlot->replot();
}

跑起来的数据不是一条曲线，是一堆只有一个点的曲线，图例刷刷往下长。正确写法是把建图放在初始化里，回调里只碰数据：

cpp
// 初始化一次
void Widget::setupPlot()
{
    ui->customPlot->addGraph();
    ui->customPlot->graph(0)->setPen(QPen(Qt::blue));
    ui->customPlot->graph(0)->setName("曲线");
}

// 回调里只加数据
void Widget::onNewSample(double key, double value)
{
    ui->customPlot->graph(0)->addData(key, value);
    ui->customPlot->replot();
}

graph(i) 还有个小坑：i 超过 graphCount() - 1 时不抛异常，安静地给你 nullptr。所以 graph(1)->setPen(...) 这种写法，如果前面只 addGraph() 了一次，程序当场挂。初始化顺序按「先 addGraph，再 graph(i)」摆，别倒。

三、给曲线灌数据：setData 与 addData #

两个函数，一件事情的两种做法。分清了，静态和动态就都通了。

setData() 是替换。整条曲线的旧数据先被扔掉，再装新的一批。装完曲线上一共就这么多点。

addData() 是追加。旧数据原地不动，新点接在后面。

| 方法 | 语义 | 旧数据 | 典型场景 | | setData(keys, values) | 整条替换 | 清空 | 静态曲线、整批重算 | | setData(key, value) | 替换成单点 | 清空 | 很少用 | | addData(key, value) | 追加一个点 | 保留 | 实时曲线主循环 | | addData(keys, values) | 追加一批 | 保留 | 一次性到达的一帧数据 | | removeDataBefore(key) | 删掉 key 之前所有点 | 部分删除 | 滚动窗口 | | removeDataAfter(key) | 删掉 key 之后所有点 | 部分删除 | 回放、裁剪 | | dataCount() | 当前点数 | — | 监控有没有堆内存 | | data()->clear() | 清空数据，保留样式 | 清空 | 重新开始采集 |

静态曲线用 setData，两行就完事：

cpp
QVector<double> x(101), y(101);
for (int i = 0; i < 101; ++i) {
    x[i] = i / 5.0 - 10;
    y[i] = x[i] * x[i] * x[i];
}

// 传入数据，setData 的两个参数类型是 QVector<double>
ui->customPlot->graph(0)->setData(x, y);

实时曲线用 addData，一个点一个点往里塞：

cpp
// key 是横坐标，单位秒；value 是这一秒的值
ui->customPlot->graph(0)->addData(key, value);

两个参数都是 double。传 QVector<int> 编不过，先在源头就用 double。两个 vector 长度不一致时短的说了算，多出来的被丢掉——只在调试输出里提醒一句，程序照跑，点数得自己数。

key 有序这件事得说清楚。QCustomPlot 内部按 key 排序，addData 会维持这个顺序。你自己灌 setData 的时候如果 key 是乱序或者有重复，线会在图上来回折，看着像画错了。时间戳单调递增就不会有这问题。

addData 还有个成本问题：加一个点，容器会重新分配一次空间。批量数据进来时别写 for 循环逐点加，直接整批进：

cpp
// 慢一点
for (int i = 0; i < keys.size(); ++i)
    graph->addData(keys.at(i), values.at(i));

// 快一点
graph->addData(keys, values);

四、静态曲线 #

静态的意思是数据一次给全，之后不再变。画法就是 setData 一把灌进去，replot 一次。

下面这条把素材里的例子补完整，两条曲线，一条三次函数一条直线：

cpp
Widget::Widget(QWidget *parent) :
    QWidget(parent),
    ui(new Ui::Widget)
{
    ui->setupUi(this);

    // 设定背景为黑色（默认白底，想换就打开这行）
    // ui->customPlot->setBackground(QBrush(Qt::black));

    // 设定右上角图形标注可见
    ui->customPlot->legend->setVisible(true);
    // 设定右上角图形标注的字体
    ui->customPlot->legend->setFont(QFont("Helvetica", 9));

    QVector<double> x(101), y(101);
    // 图形为 y = x^3
    for (int i = 0; i < 101; ++i) {
        x[i] = i / 5.0 - 10;
        y[i] = x[i] * x[i] * x[i];     // 也可以写成 qPow(x[i], 3)
    }

    // 添加图形
    ui->customPlot->addGraph();
    // 设置画笔
    ui->customPlot->graph(0)->setPen(QPen(Qt::blue));
    // 设置画刷，曲线和 X 轴围成面积的颜色
    ui->customPlot->graph(0)->setBrush(QBrush(QColor(255, 255, 0)));
    // 设置右上角图形标注名称
    ui->customPlot->graph(0)->setName("曲线");
    // 传入数据，setData 的两个参数类型为 double
    ui->customPlot->graph(0)->setData(x, y);

    QVector<double> temp(20), temp1(20);
    // 图形为 y = 10*x + 10
    for (int i = 0; i < 20; ++i) {
        temp[i] = i;
        temp1[i] = 10 * i + 10;
    }

    // 添加第二条图形
    ui->customPlot->addGraph();
    // 设置画笔
    ui->customPlot->graph(1)->setPen(QPen(Qt::red));
    // 设置画刷，曲线和 X 轴围成面积的颜色（直线不填充，先注释掉）
    // ui->customPlot->graph(1)->setBrush(QBrush(QColor(0, 255, 0)));
    // 传入数据
    ui->customPlot->graph(1)->setData(temp, temp1);
    // 设置右上角图形标注名称
    ui->customPlot->graph(1)->setName("直线");

    // 设置 X 轴文字标注
    ui->customPlot->xAxis->setLabel("time");
    // 设置 Y 轴文字标注
    ui->customPlot->yAxis->setLabel("temp/shidu");

    // 设置 X 轴坐标范围
    ui->customPlot->xAxis->setRange(-20, 20);
    // 设置 Y 轴坐标范围
    ui->customPlot->yAxis->setRange(-1100, 1100);

    // 在坐标轴右侧和上方画线，和 X/Y 轴一起形成一个矩形
    ui->customPlot->axisRect()->setupFullAxesBox();

    // 静态曲线：数据一次到位，重绘一次
    ui->customPlot->replot();
}

逐段拆开看：

| 段落 | 干了什么 | 换成别的会怎样 | | legend->setVisible(true) | 显示图例 | 图例框空着或者不显示，看不出哪条是哪条 | | legend->setFont(...) | 图例文字字体 | 默认字号偏大，条目多时挤 | | graph(0)->setPen(QPen(Qt::blue)) | 蓝色实线 | 默认黑色，两条曲线都黑 | | graph(0)->setBrush(...) | 曲线与 X 轴之间填黄 | 只剩一条线，没有面积感 | | graph(0)->setName("曲线") | 图例里的文字 | 图例条目无名 | | graph(0)->setData(x, y) | 灌 101 个点 | 空曲线 | | xAxis->setRange(-20, 20) | X 轴视窗 | 默认区间不含数据，看到空白 | | yAxis->setRange(-1100, 1100) | Y 轴视窗 | 三次函数尾部被切掉 | | setupFullAxesBox() | 上下左右围成完整矩形 | 只有左边和下面两根轴，看着缺一块 |

setupFullAxesBox() 做的事比看起来多：它把上、右两根轴的可见性打开，并且让它们的范围和下、左轴同步。所以调用之后，右侧和上方也有刻度，整幅图是一个闭合的框。

x 的取值 i / 5.0 - 10 得注意那个小数点。i / 5 是整数除法，i 从 0 到 100 只会产出 0 到 20 的整数，x 的分布变成台阶，y = x^3 画出来是折线。这个错误不报错，但图明显不对。

静态曲线不等于只能在构造函数里画。按钮点了重新算一遍，也是静态：

cpp
void Widget::onRecalcClicked()
{
    const int n = 200;
    QVector<double> keys(n), values(n);
    for (int i = 0; i < n; ++i) {
        const double t = i / double(n - 1);        // 0..1
        keys[i] = t * m_span;
        values[i] = qSin(t * m_freq * 2 * M_PI);
    }

    // 整体替换，旧数据不留
    m_plot->graph(0)->setData(keys, values);
    // 让坐标轴自己贴合新数据
    m_plot->graph(0)->rescaleAxes();
    m_plot->replot();
}

rescaleAxes() 是省事的做法：它把两条轴的范围按这条曲线的数据自动收紧。配合 setData 用，不用手算上下限。手算上下限的场景是「视窗要跨多次刷新保持一致」，那就老老实实 setRange。

还有第三种定范围的办法，素材里提过一句：

cpp
// setRange(double position, double size, Qt::AlignmentFlag alignment)
// 参数分别是：原点、偏移量、对齐方式
m_plot->xAxis->setRange(-20, 40, Qt::AlignRight);

三个参数的版本是「给我一段宽度，对齐到我指定的位置」。Qt::AlignRight 表示 position 是右边界，区间就是 [position - size, position]。实时曲线滚动窗口靠的就是它，下一章正面用。

五、实时动态曲线 #

实时的核心不是「画得快」，是「数据一直在加，视窗一直在跟」。这件事分成四个动作：

  1. 定时器定节拍
  2. 每次节拍取一个（或一批）新样本
  3. addData 追加到曲线
  4. 把窗口往前推，把走出窗口的老数据删掉

素材那版是 Qt4 环境（fedora9 + Qt 4.7 + Creator 2.0.1），基类模板选 QMainWindow，界面上拖一个 widget，提升为 QCustomPlot，控件名改成 customPlot。头文件长这样：

cpp
// mainwindow.h：头文件里放三个东西——初始化函数、数据槽、定时器成员
class MainWindow : public QMainWindow
{
    Q_OBJECT

public:
    explicit MainWindow(QWidget *parent = 0);
    ~MainWindow();

    // 设置 qcustomplot 画图属性，实时
    void setupRealtimeDataDemo(QCustomPlot *customPlot);

private slots:
    // 添加实时数据槽
    void realtimeDataSlot();

private:
    Ui::MainWindow *ui;
    // 定时器，周期调用 realtimeDataSlot() 槽，实现动态数据添加到曲线
    QTimer dataTimer;
};

实现部分：

cpp
// mainwindow.cpp
#include "mainwindow.h"
#include "ui_mainwindow.h"
#include <QVector>
#include <QTimer>
#include <QTime>
#include <QDateTime>

MainWindow::MainWindow(QWidget *parent) :
    QMainWindow(parent),
    ui(new Ui::MainWindow)
{
    ui->setupUi(this);

    setupRealtimeDataDemo(ui->customPlot);
    ui->customPlot->replot();

    ui->checkBox_temp->setChecked(true);
    ui->checkBox_hui->setChecked(true);
}

MainWindow::~MainWindow()
{
    delete ui;
}

// 画图初始化
void MainWindow::setupRealtimeDataDemo(QCustomPlot *customPlot)
{
    // 这段前置检查在 Qt 4.7 以下才有意义，老 demo 里留着
    // #if QT_VERSION < QT_VERSION_CHECK(4, 7, 0)
    // QMessageBox::critical(this, "", "You're using Qt < 4.7, "
    //     "the realtime data demo needs functions that are available with Qt 4.7");
    // #endif

    customPlot->addGraph();                                   // blue line
    customPlot->graph(0)->setPen(QPen(Qt::blue));
    customPlot->graph(0)->setName("temp");
    // customPlot->graph(0)->setBrush(QBrush(QColor(240, 255, 200)));
    // customPlot->graph(0)->setAntialiasedFill(false);

    customPlot->addGraph();                                   // red line
    customPlot->graph(1)->setPen(QPen(Qt::red));
    customPlot->graph(1)->setName("hui");
    // customPlot->graph(0)->setChannelFillGraph(customPlot->graph(1));

    // X 轴按时间显示
    customPlot->xAxis->setTickLabelType(QCPAxis::ltDateTime);
    customPlot->xAxis->setDateTimeFormat("hh:mm:ss");
    customPlot->xAxis->setAutoTickStep(false);
    customPlot->xAxis->setTickStep(2);

    customPlot->axisRect()->setupFullAxesBox();

    // 让下/左轴的范围变化同步到上/右轴
    // connect(customPlot->xAxis, SIGNAL(rangeChanged(QCPRange)),
    //         customPlot->xAxis2, SLOT(setRange(QCPRange)));
    // connect(customPlot->yAxis, SIGNAL(rangeChanged(QCPRange)),
    //         customPlot->yAxis2, SLOT(setRange(QCPRange)));

    // 定时器反复调用 MainWindow::realtimeDataSlot
    connect(&dataTimer, SIGNAL(timeout()), this, SLOT(realtimeDataSlot()));
    dataTimer.start(0);            // 0 是跑满事件循环，没有节流

    customPlot->legend->setVisible(true);
}

void MainWindow::realtimeDataSlot()
{
    // key 的单位是秒
    double key = QDateTime::currentDateTime().toMSecsSinceEpoch() / 1000.0;

    qsrand(QTime::currentTime().msec() + QTime::currentTime().second() * 10000);

    // 用随机数产生两条曲线
    double value0 = qrand() % 100;
    double value1 = qrand() % 80;

    if (ui->checkBox_temp->isChecked())
        ui->customPlot->graph(0)->addData(key, value0);        // 添加数据 1 到曲线 1
    if (ui->checkBox_hui->isChecked())
        ui->customPlot->graph(1)->addData(key, value1);        // 添加数据 2 到曲线 2

    // 删除 8 秒之前的数据。这里的 8 要和下面设置横坐标宽度的 8 配合起来
    // 才能起到想要的效果，可以调整这两个值，观察显示的效果。
    ui->customPlot->graph(0)->removeDataBefore(key - 8);
    ui->customPlot->graph(1)->removeDataBefore(key - 8);

    // 自动设定曲线的 y 轴范围，不设定就容易看不到图像
    // 也可以用 ui->customPlot->yAxis->setRange(low, up) 手动设定 y 轴范围
    ui->customPlot->graph(0)->rescaleValueAxis();
    ui->customPlot->graph(1)->rescaleValueAxis(true);

    // 这里的 8，是指横坐标时间宽度为 8 秒。想要横坐标显示更多的时间，
    // 就把 8 调整成更大的值，比如要显示 60 秒，那就改成 60。
    // 这时 removeDataBefore(key - 8) 中的 8 也要改成 60，否则曲线显示不完整。
    ui->customPlot->xAxis->setRange(key + 0.25, 8, Qt::AlignRight);

    ui->customPlot->replot();
}

这一段里有六个细节值得单独抠。

时间戳用秒。toMSecsSinceEpoch() / 1000.0 拿的是浮点秒。X 轴刻度要靠这个数值算位置，用毫秒量级的整数会让刻度步长的量纲变成上万，setTickStep(2) 完全没有意义。

两个 8 必须一致。removeDataBefore(key - 8) 说「只保留最近 8 秒」，setRange(key + 0.25, 8, Qt::AlignRight) 说「视窗宽 8 秒」。两个值错开会出现两种难看的样子：删除窗口比显示窗口小，曲线左边一截凭空消失；删除窗口比显示窗口大，左边留一条空白。要显示 60 秒，两处一起改成 60。

key + 0.25 那 0.25。它是往右多留的一点余量。时间戳一直在涨，如果窗口右边界正好等于最新点，曲线终点就贴在边框上，视觉上像被砍断。给一点提前量，曲线末端就在框内。

rescaleValueAxis() 的两个版本。无参版本按本条曲线接管 Y 轴范围；rescaleValueAxis(true) 的 true 表示只放大不缩小——已经有别的曲线定好的范围，这条曲线只能往外扩，不能往回缩。所以顺序上是先 graph(0) 无参定调，再 graph(1) 带 true 扩容，两条曲线才都落在可见范围内。顺序倒了，先来的那条会被挤出去。

setTickStep(2) 前要关自动。setAutoTickStep(false) 关掉自动步长，setTickStep(2) 才有意义。不关的话，QCustomPlot 根据当前范围自己算步长，你设的值被覆盖。

dataTimer.start(0) 不是「每秒 0 次」，是「跑满」。Qt 的 0 间隔定时器在事件循环一空闲就发下一次 timeout，CPU 占用直接拉满。素材是 demo，图快。真实项目给 20 到 50 毫秒，二十到五十帧，人眼已经看不出卡顿。

最后一行的 replot() 在槽的末尾，也就是「本帧数据全部加完、窗口推完」之后再画。位置别挪到 addData 前面。

六、replot 的时机与性能 #

把这句话钉死：QCustomPlot 的所有修改都不会自动重绘。改数据、改颜色、改坐标范围、改图例，屏幕上一律没反应，必须自己调一次 replot()。

replot() 干的事是重绘整幅图，不是只画新加的那个点。刻度、标签、网格、图例、每条曲线的全部点，全走一遍。所以它的开销跟「图上有多少东西」相关，跟「你改了多少东西」无关。改一个像素的颜色，代价和第一次画完整幅图一样。

调用的时机只有一个原则：一帧的改动全部做完，调一次。

cpp
// 错：循环里每次都重绘整幅图
for (int i = 0; i < keys.size(); ++i) {
    graph->addData(keys.at(i), values.at(i));
    m_plot->replot();
}

// 对：全改完，画一次
for (int i = 0; i < keys.size(); ++i)
    graph->addData(keys.at(i), values.at(i));
m_plot->replot();

第二种写法省下的是 N 次整图绘制的开销，不是 N 次数据写入的开销。点数一多，差距肉眼可见。

还有一种情况：多个地方各自都需要「让图更新」，一个定时器里改数据要 replot，一个按钮里改样式也要 replot，两处都写 replot()，同一轮事件循环里就画了两遍。replot() 带参数能解决：

cpp
// 本轮事件循环里不管调多少次，只留最后一次真正的重绘
m_plot->replot(QCustomPlot::rpQueuedReplot);

四个优先级摆在一起看：

| 参数 | 行为 | 适合 | | rpImmediateRefresh | 立刻同步重绘 | 改动极少，必须马上看到 | | rpQueuedRefresh | 标脏，等事件循环来画 | 想延后一拍 | | rpRefreshHint | 由内部提示决定 | 默认值，平时不用显式传 | | rpQueuedReplot | 同一轮里的多次请求合并成一次 | 循环里连续改数据 |

rpQueuedReplot 的合并范围是「同一轮事件循环」。跨轮的两次调用仍然是两次重绘，它不改变刷新率。

还有几条容易踩的：

  • replot() 必须在 GUI 线程调。采集线程里直接调会崩或者画花。
  • 控件没显示、宽度为 0 时调 replot() 没有意义，画布尺寸是零。
  • replot() 期间别改数据。绘制过程中改容器内容，行为不可预期。
  • 控件被遮住或者最小化时，replot() 照样耗 CPU，只是没人看。这种时候把定时器停掉更实在。

要压绘制成本，还有一招，素材里以注释形式给了：

cpp
// 想彻底关掉抗锯齿换取速度，放开这段
customPlot->setNotAntialiasedElements(QCP::aeAll);

QFont font;
font.setStyleStrategy(QFont::NoAntialias);
customPlot->xAxis->setTickLabelFont(font);
customPlot->yAxis->setTickLabelFont(font);
customPlot->legend->setFont(font);

setNotAntialiasedElements(QCP::aeAll) 把抗锯齿整体关掉，曲线边缘会出现锯齿。刻度文字另算，文字的平滑是字体渲染的事，得单独把字体的策略设成 QFont::NoAntialias。两处都做了，才是真的全关。

关抗锯齿的副作用是字变糊、线条发毛。可以只针对曲线关，标签照旧平滑：

cpp
// 只对曲线图元关抗锯齿，刻度文字不受影响
customPlot->setNotAntialiasedElements(QCP::aeNone);
customPlot->graph(0)->setAntialiased(false);

七、刷新的两种模式 #

「什么时候 replot」有两种安排方式，选错的那个会同时浪费 CPU 和延迟。

| 模式 | 触发源 | 节拍 | 适合 | 代价 | | 定时器轮询 | QTimer::timeout | 固定 | 采集频率稳定，需要限帧 | 数据到了没到点，延迟最多一个周期 | | 数据驱动 | 串口/网络/采集线程的信号 | 不固定 | 数据稀疏、事件型 | 高频数据直接把重绘打爆 |

素材用的是第一种：QTimer 定节拍，槽里取数据、加数据、推窗口、重绘。节拍由你控制，帧率稳定，代价是最多等一个周期。

第二种更常见于「来一条画一条」的场景：串口读完一帧就发个信号，槽里 addData 加 replot。数据慢的时候反应最快，数据快的时候就是灾难——一秒进来一千条，就是一千次整图重绘。

真实项目多数是两种混着用，也就是「定时器轮询 + 队列缓冲」：

cpp
// 采集回调：只入队，不碰界面
void Widget::onSample(double value)
{
    QMutexLocker locker(&m_mutex);
    m_pending.append(value);
}

// 刷新定时器：一次取走，一次重绘
void Widget::onFlush()
{
    QVector<double> batch;
    {
        QMutexLocker locker(&m_mutex);
        batch.swap(m_pending);          // 交换指针，不是逐元素拷贝
    }
    if (batch.isEmpty())
        return;

    const double now = QDateTime::currentMSecsSinceEpoch() / 1000.0;
    const double step = 0.02;           // 采样间隔 20ms
    double key = now - batch.size() * step;

    for (int i = 0; i < batch.size(); ++i) {
        m_plot->graph(0)->addData(key, batch.at(i));
        key += step;
    }

    m_plot->graph(0)->removeDataBefore(now - 30);        // 只留 30 秒
    m_plot->xAxis->setRange(now + 0.5, 30, Qt::AlignRight);
    m_plot->replot(QCustomPlot::rpQueuedReplot);
}

这套结构的好处：采集侧写入永远不阻塞在重绘上，界面侧每帧只画一次。队列长度就是「这一帧要消化多少点」，堆积说明刷新跟不上，把定时器周期调大或者降低采样率。

batch.swap(m_pending) 这一句值得说一下。用它把攒的数据整体换出来，锁的持有时间只有一次指针交换，比在锁里循环拷元素短得多。

两个模式的边界条件：

| 现象 | 说明 | 处理 | | 队列越积越长 | 刷新慢于采集 | 降采样、加大定时器周期 | | 曲线一顿一顿 | 定时器周期太长 | 缩短周期，或改成 rpQueuedReplot | | 数据到了图不动 | 忘了 replot() | 在槽尾补一次 | | 数据到了图动得比数据慢 | 数据驱动的节拍被重绘拖住 | 换成队列缓冲 |

八、曲线外观：线型、颜色与粗细 #

外观三件套：setPen 管线的颜色和粗细，setLineStyle 管点与点之间怎么连，setScatterStyle 管点上画不画标记。三者互不干扰。

线型用 setLineStyle：

cpp
// 阶梯线，从左边那个点的高度横向拉到下一个点
ui->customPlot->graph(0)->setLineStyle(QCPGraph::lsStepLeft);

LineStyle 一共六个值：

| 枚举 | 形状 | 用在什么数据上 | | lsNone | 不连线，只剩点 | 纯散点图 | | lsLine | 直线连接（默认） | 连续采样 | | lsStepLeft | 阶梯，取左端点高度 | 采样保持、开关量、档位 | | lsStepRight | 阶梯，取右端点高度 | 采样保持的另一侧 | | lsStepCenter | 阶梯，取两点中点 | 量化后的台阶数据 | | lsImpulse | 每个点向基线画竖线 | 脉冲、频次分布 |

默认是 lsLine。所以不设 setLineStyle 的时候，看到的就是折线连起来的样子。阶梯线和脉冲线的区别在于：阶梯线有横向段，把「值没变」这件事画出来了；脉冲线没有横向段，每个点独立一根竖线。

颜色、粗细、虚实全在 QPen 里：

cpp
QPen pen(QColor(0, 120, 215));   // 颜色
pen.setWidthF(2.0);              // 线宽，浮点，2.0 比 1 明显粗一档
pen.setStyle(Qt::SolidLine);     // 实线
ui->customPlot->graph(0)->setPen(pen);

setPen 接的是值传递，传进去会拷一份。所以下面这段不生效：

cpp
QPen pen(Qt::green);
ui->customPlot->graph(0)->setPen(pen);

pen.setColor(Qt::red);           // 改的是局部变量，曲线还是绿的

要换色就再调一次 setPen。

线宽用 setWidthF 而不是 setWidth。setWidth 收整数，setWidthF 收浮点。高 DPI 屏上 1.5 这种宽度只有 setWidthF 认。

虚实样式用 pen.setStyle()：Qt::SolidLine 实线、Qt::DashLine 虚线、Qt::DotLine 点线、Qt::DashDotLine 点划线、Qt::DashDotDotLine 双点划线、Qt::CustomDashLine 自定义 dash pattern。

曲线名字也在这里设，setName() 决定图例里显示什么：

cpp
ui->customPlot->graph(0)->setName("温度");
ui->customPlot->graph(1)->setName("湿度");

组合起来是一段完整的样式初始化：

cpp
void Widget::styleGraph(int index, const QColor &color, const QString &name)
{
    QCPGraph *g = m_plot->graph(index);

    QPen pen(color);
    pen.setWidthF(1.6);
    pen.setStyle(Qt::SolidLine);
    g->setPen(pen);

    g->setLineStyle(QCPGraph::lsLine);
    g->setName(name);
}

九、散点与填充 #

点上加标记用 setScatterStyle。素材里的写法：

cpp
// 圆点，直径 5
ui->customPlot->graph(0)->setScatterStyle(
    QCPScatterStyle(QCPScatterStyle::ssCircle, 5));

QCPScatterStyle 的构造函数签名是 QCPScatterStyle(ScatterShape shape, double size = 6)，第二个参数默认 6 像素，不给就用 6。

注意「默认不显示点」这件事。曲线刚建出来 scatterStyle 是 ssNone，加多少数据都只有一条线，点一个都看不见。要看到点必须显式设一次。

常用的形状：ssNone（默认，不画）、ssDot、ssCross、ssPlus、ssCircle（空心圆）、ssDisc（实心圆）、ssSquare、ssDiamond、ssStar、ssTriangle、ssTriangleInverted、ssCrossSquare、ssPlusSquare、ssCrossCircle、ssPlusCircle、ssPeace。

只给形状和大小，点会用曲线自己的画笔颜色画。要单独指定点的画笔和填充：

cpp
QCPScatterStyle ss;
ss.setShape(QCPScatterStyle::ssDisc);
ss.setSize(8);
ss.setPen(QPen(Qt::darkBlue));          // 点的边框
ss.setBrush(QBrush(Qt::yellow));        // 点的填充
ui->customPlot->graph(0)->setScatterStyle(ss);

填充面积走的是另一条路：setBrush。素材里的 setBrush(QBrush(QColor(255, 255, 0))) 就是把曲线和 X 轴围成的区域涂黄。

cpp
// 曲线与零轴之间的面积填充
ui->customPlot->graph(0)->setBrush(QBrush(QColor(255, 255, 0)));

填充有两种对象：

| 目标 | 做法 | 效果 | | 到零轴 | setBrush(brush) | 曲线与基线之间涂色 | | 到另一条曲线 | setBrush(brush) + setChannelFillGraph(other) | 两条曲线之间涂色 |

cpp
// graph(0) 填到 graph(1) 上
ui->customPlot->graph(0)->setBrush(QBrush(QColor(240, 255, 200)));
ui->customPlot->graph(0)->setChannelFillGraph(ui->customPlot->graph(1));

setChannelFillGraph 的语义是「我这条曲线，往那条曲线方向填充」。挂在谁身上谁被填。两条曲线的 key 范围要有重叠，不重叠的部分没东西可填。

实心填充会盖住网格线和别的曲线。用带透明度的颜色：

cpp
// 第四个参数是 alpha，0 全透明，255 不透明
ui->customPlot->graph(0)->setBrush(QBrush(QColor(0, 120, 215, 90)));

填充还能加抗锯齿开关，素材注释里出现过：

cpp
// 填充区不抗锯齿，省一点绘制成本，边缘略糙
ui->customPlot->graph(0)->setAntialiasedFill(false);

十、多条曲线与图例 #

多条曲线的做法就一句：addGraph() 调几次。每条曲线各自持有数据、画笔、线型、名字，互不干扰。

cpp
ui->customPlot->addGraph();
ui->customPlot->graph(0)->setPen(QPen(Qt::blue));
ui->customPlot->graph(0)->setName("temp");

ui->customPlot->addGraph();
ui->customPlot->graph(1)->setPen(QPen(Qt::red));
ui->customPlot->graph(1)->setName("hui");

ui->customPlot->graph(0)->setData(x, y0);
ui->customPlot->graph(1)->setData(x, y1);

ui->customPlot->legend->setVisible(true);
ui->customPlot->replot();

QCustomPlot 不做颜色轮换。不设 setPen，几条曲线全是黑色细线，叠在一起分不出谁是谁。每条都要自己设。

图例相关操作：

| 调用 | 作用 | | legend->setVisible(true) | 显示图例 | | legend->setFont(QFont("Helvetica", 9)) | 图例字体 | | legend->setBrush(...) / setBorderPen(...) | 图例底色与边框 | | setName("温度") | 决定该条目文字 | | removeFromLegend() | 只从图例里摘掉，曲线还在 | | setVisible(false) | 整条曲线隐藏，图例条目一起消失 | | axisRect()->insetLayout()->setInsetAlignment(0, ...) | 图例贴到哪个角 |

图例默认是显示的，一条带名字的曲线都没有时它就是个空框，看着像没生效。所以素材里那句 legend->setVisible(true) 更像习惯写法，真正的开关是 setName。

图例位置可以挪。默认在右上角，想放左上：

cpp
ui->customPlot->axisRect()->insetLayout()->setInsetAlignment(0, Qt::AlignLeft | Qt::AlignTop);

只隐藏图例条目、保留曲线：

cpp
ui->customPlot->graph(1)->removeFromLegend();      // 曲线还在画，图例里没它

两条曲线量纲差太远（一条 0 到 100，一条 0 到 0.01），一条会被压成一条平线。解决办法是给第二条配独立的 Y 轴：

cpp
// 打开右侧 Y 轴
ui->customPlot->yAxis2->setVisible(true);
ui->customPlot->yAxis2->setLabel("湿度 %RH");
// 让第二条曲线用右侧轴
ui->customPlot->graph(1)->setValueAxis(ui->customPlot->yAxis2);

右侧轴的可见性默认是关的，得显式打开。setupFullAxesBox() 会把它一起打开并同步范围，所以调了这个函数之后不需要再手动 setVisible(true)。

再多几条曲线，建议把索引和颜色定义成常量，别在代码里散着写 graph(3)：

cpp
enum CurveIndex { kTemp = 0, kHumidity = 1, kPressure = 2 };

const QColor kCurveColors[] = {
    QColor(0, 120, 215),
    QColor(214, 39, 40),
    QColor(44, 160, 44)
};

const char *kCurveNames[] = { "温度", "湿度", "气压" };

for (int i = 0; i < 3; ++i) {
    m_plot->addGraph();
    m_plot->graph(i)->setName(kCurveNames[i]);
    QPen pen(kCurveColors[i]);
    pen.setWidthF(1.6);
    m_plot->graph(i)->setPen(pen);
}

十一、大数据量的处理 #

数据量上去之后，卡的地方不是「画线」本身，是「点数 × 每帧重绘次数」。能动的旋钮就那几个。

| 手段 | 做法 | 省在哪 | | 批量塞数据 | addData(keys, values) 一次传两个 vector | 少 N 次容器增长判断 | | 自适应抽样 | setAdaptiveSampling(true) | 屏幕装不下的点按像素抽掉 | | 关抗锯齿 | setNotAntialiasedElements(QCP::aeAll) | 少做边缘混合 | | 限历史长度 | removeDataBefore(key - 窗口) | 点数不随运行时间涨 | | 合并重绘 | replot(rpQueuedReplot) | 一轮一次整图绘制 | | 固定刻度步长 | setAutoTickStep(false) + setTickStep | 少算一遍刻度布局 | | 源头降采样 | 采集端抽点、按需聚合 | 从根上少一半点 |

自适应抽样默认开着，它按当前像素宽度决定画哪些点。多数曲线图靠这个开关就够了。要严格按原始点画，就 setAdaptiveSampling(false)，只在「点的密度本身就是信息」的图上这么干，比如脉冲图。

限历史长度是硬要求。实时曲线不加 removeDataBefore，点数只增不减，跑一晚上内存和遍历量都堆起来了：

cpp
static const double kWindowSec = 60.0;

// 只保留最近 60 秒
graph->removeDataBefore(key - kWindowSec);
// 视窗宽度用同一个常量，别在两个地方各写一个数
plot->xAxis->setRange(key + 0.5, kWindowSec, Qt::AlignRight);

十二、易错点速查 #

| 症状 | 原因 | 处理 | | 代码写了图不动 | 没调 replot() | 改完补一次 | | 图例越跑越长 | 回调里 addGraph() | 建图挪到初始化 | | 曲线只显示一截 | 坐标范围没覆盖数据 | setRange 或 rescaleAxes() | | 曲线在框外 | Y 轴没按数值缩放 | rescaleValueAxis() | | 越跑越卡 | 旧数据没删 | removeDataBefore | | 线来回折 | key 乱序或有重复 | 保证单调递增 | | 时间轴显示成数字 | 没设时间刻度类型 | setTickLabelType(ltDateTime) | | 时间刻度挤成一团 | setTickStep 太小 | 关自动步长后调大 | | 两条曲线叠成一条平线 | 量纲差太大 | 第二条挂 yAxis2 | | 编译报 printsupport | .pro 缺链接 | QT += printsupport | | 控件一片空白 | 提升时类名大小写错 | 写 QCustomPlot | | 程序当场崩 | graph(1) 越界 | 先 addGraph() 再取 | | 填充盖住网格 | brush 不透明 | 颜色带 alpha | | 关抗锯齿后字发糊 | 字体也设了 NoAntialias | 只对图元关，字体不关 | | 采集线程里崩 | 跨线程调 replot() | 信号槽回主线程 |

四条底线，照着写不会错：

  1. 建图只做一次，数据回调里只碰 addData。
  2. 一帧的改动全做完，再调一次 replot()。
  3. 实时曲线必须配 removeDataBefore 和滚动窗口，两个数值同源。
  4. 图不动先看有没有 replot()，再怀疑数据。
