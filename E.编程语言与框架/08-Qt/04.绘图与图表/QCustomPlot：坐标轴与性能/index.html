这篇把 QCustomPlot 的坐标轴拆开讲：四根轴怎么摆、范围怎么定、刻度和标签怎么调、日期轴怎么接；后半段说清「删除图形」到底有几个层次、绘制成本花在哪、数据量大时怎么少花时间。

不讲安装与控件提升，不讲第一条曲线怎么画。入门见同目录的 QCustomPlot 入门；曲线样式与数据点组织见 QCustomPlot 曲线；和 Qwt、QChart 的取舍见同目录的选型那篇。

版本基线是 QCustomPlot 2.x。1.x 的刻度接口是另一套（setTickStep、setAutoTickCount），2.x 换成 QCPAxisTicker，照 1.x 的文章抄会直接编不过。文中的耗时数据是在 Qt 5.14 + MinGW 64 位下测的，机器不同数字会浮动，倍数关系可以参考。

一、QCPAxis 的四根轴 #

一个 QCPAxisRect 天生带四个 QCPAxis 成员，名字是写死的，不用自己 new：

成员 位置 默认可见 定位
xAxis 下 是 主轴，key 轴，横坐标
yAxis 左 是 主轴，value 轴，纵坐标
xAxis2 上 否 副轴，默认与 xAxis 无关
yAxis2 右 否 副轴，默认与 yAxis 无关

默认只画左、下两根。要让上、右也出来，挨个打开：

cpp
QCustomPlot *plot = ui->customPlot;

plot->xAxis2->setVisible(true);
plot->yAxis2->setVisible(true);
plot->replot();

四根都要，一行更省事：

cpp
// 缺哪根补哪根，四边全开；参数 true 表示副轴范围跟着主轴走
plot->axisRect()->setupFullAxesBox(true);
plot->replot();

setupFullAxesBox 的参数容易被忽略。传 false 或省略时，只负责把轴建出来并显示，副轴的范围和主轴没有任何关系，你拖主轴，上边那根刻度不会动。传 true 才把范围连起来。

按位置取轴，适合写通用函数，不用记成员名：

cpp
QCPAxis *bottom = plot->axisRect()->axis(QCPAxis::atBottom);
QCPAxis *left   = plot->axisRect()->axis(QCPAxis::atLeft);
QCPAxis *top    = plot->axisRect()->axis(QCPAxis::atTop);
QCPAxis *right  = plot->axisRect()->axis(QCPAxis::atRight);

一根轴身上的元素是成套的，命名有规律，记住这一组就够改外观：

元素 设置方法 说明
轴线 setBasePen(QPen) 轴本身那条线
主刻度线 setTickPen(QPen) 朝内朝外都算同一条
子刻度线 setSubTickPen(QPen) 主刻度之间的小格
刻度文字 setTickLabelColor、setTickLabelFont 刻度值
轴标题 setLabelColor、setLabelFont 轴名
网格线 grid()->setPen 网格挂在轴上，不挂在矩形上

改四根轴的颜色，一眼能分清谁是谁：

cpp
plot->xAxis->setBasePen(QPen(Qt::red, 4));
plot->yAxis->setBasePen(QPen(Qt::blue, 4));
plot->xAxis2->setBasePen(QPen(Qt::yellow, 4));
plot->yAxis2->setBasePen(QPen(Qt::green, 4));
plot->replot();

轴线的两头能加装饰，枚举 QCPLineEnding 里挑：esNone、esFlatArrow、esSpikeArrow、esLineArrow、esDisc、esSquare、esDiamond、esBar、esHalfBar、esSkewedBar。

cpp
plot->xAxis->setUpperEnding(QCPLineEnding::esSpikeArrow);  // 终点箭头
plot->xAxis->setLowerEnding(QCPLineEnding::esDisc);        // 起点圆点
plot->yAxis->setUpperEnding(QCPLineEnding::esSquare);      // 终点小方块

装饰是往轴外面画的，轴贴着控件边缘时会被裁掉，记得给 axisRect 留边距。

网格线属于轴，不属于轴矩形，所以四根轴各有一套网格。副轴的网格默认不画，要开得自己动手：

cpp
plot->axisRect()->setBackground(QBrush(Qt::black));

plot->xAxis->grid()->setPen(QPen(QColor(180, 180, 180), 1, Qt::DashLine));
plot->yAxis->grid()->setPen(QPen(QColor(180, 180, 180), 1, Qt::DashLine));

plot->xAxis->grid()->setSubGridPen(QPen(QColor(50, 50, 50), 1, Qt::DotLine));
plot->yAxis->grid()->setSubGridPen(QPen(QColor(50, 50, 50), 1, Qt::DotLine));
plot->xAxis->grid()->setSubGridVisible(true);
plot->yAxis->grid()->setSubGridVisible(true);

plot->xAxis->grid()->setZeroLinePen(QPen(Qt::white));   // 0 值那条线单独上色
plot->yAxis->grid()->setZeroLinePen(QPen(Qt::white));

副轴要网格，照抄一份把 xAxis 换成 xAxis2 就行，四根轴各管各的：

cpp
plot->xAxis2->grid()->setVisible(true);
plot->xAxis2->grid()->setPen(QPen(QColor(180, 180, 180), 1, Qt::DashLine));

子网格是主刻度之间的细分线，跟「子刻度线」不是一回事：子刻度是轴上那截短线，子网格是铺满绘图区的细线。子网格默认关，因为线条密度翻倍，绘图成本跟着涨。

轴矩形背景除了纯色，还能铺图片：

cpp
plot->axisRect()->setBackground(QPixmap(":/image/background.jpg"));
plot->axisRect()->setBackgroundScaled(true);
plot->axisRect()->setBackgroundScaledMode(Qt::IgnoreAspectRatio);

三种缩放模式的区别在于图片和矩形的比例对不上时怎么办：

模式 效果
Qt::IgnoreAspectRatio 拉伸铺满，图会变形，不留边
Qt::KeepAspectRatio 整张图可见，比例不变，两侧或上下留空
Qt::KeepAspectRatioByExpanding 比例不变，铺满矩形，超出部分裁掉

背景用图片时，setBackgroundScaled(true) 必须开，否则图片按原始像素画，控件一放大就露底。

二、范围设置与自动缩放 #

范围是坐标轴的第一属性。设了不重绘，界面上什么都不会变，这条是新手踩得最多的坑：

cpp
plot->xAxis->setRange(0, 1000);
plot->yAxis->setRange(0, 1100);
plot->replot();       // 少了这一行，上面两行等于白写

除了成对给，还能只动一端，或者直接塞一个 QCPRange：

cpp
plot->yAxis->setRangeLower(0);
plot->yAxis->setRangeUpper(500);

plot->xAxis->setRange(QCPRange(-10, 10));

plot->yAxis->setRangeReversed(true);   // 反向：Y 轴从上往下递增

setRangeReversed(true) 在画深度、排名、瀑布图这类「越大越靠下」的数据时很省事，不用把数据取负。

范围还有一处常被误解的地方：setRange 给的是坐标值，不是像素。控件 800 像素宽、范围 0 到 1000，一个像素对应 1.25 个坐标单位；控件拉宽到 1600 像素，范围不变，刻度密度自动变稀。刻度文字的数量由 ticker 决定，跟像素宽度没有直接挂钩，所以窗口拉得很宽时刻度会显得稀疏，这时候去调刻度数量，不要去调范围。

自动定范围靠 rescaleAxes()，它按现有数据算上下界，跟当前范围无关：

cpp
plot->graph(0)->rescaleAxes();   // 只按这一条曲线算
plot->rescaleAxes();             // 按所有可见可绘项算
plot->replot();

调用顺序有讲究。数据没进去就 rescaleAxes()，什么也算不出来，范围停在原地；先 setData，再 rescale，最后 replot：

cpp
plot->graph(0)->setData(x, y);
plot->rescaleAxes();
plot->replot();

rescaleAxes 有一个布尔参数 onlyVisiblePlottables，默认 false，意思是把隐藏的曲线也算进去。曲线多、经常图例里开关的时候，这个默认值会让范围一直撑得很大，改成 true 更符合直觉：

cpp
plot->rescaleAxes(true);   // 只按当前可见的曲线定范围

还有个细节：空数据的曲线不参与计算，范围保持原样。所以「清完数据再 rescale」不会得到 0 到 1，而是保持上一次的范围，这一点跟不少人的预期相反。

范围变化有信号 rangeChanged(const QCPRange &)，用它做联动，比自己算偏移可靠：

cpp
// 老写法，C++11 之前也能编
connect(plot->xAxis, SIGNAL(rangeChanged(QCPRange)),
        plot->xAxis2, SLOT(setRange(QCPRange)));

拖动和缩放要显式打开，不开的话鼠标在上面怎么拉都没反应：

cpp
plot->setInteractions(QCP::iRangeDrag | QCP::iRangeZoom);

// 只允许横向拖动、横向缩放，纵向锁死
plot->axisRect()->setRangeDragAxes(plot->xAxis, nullptr);
plot->axisRect()->setRangeZoomAxes(plot->xAxis, nullptr);

像素和坐标的换算是两条对称的接口，做游标、点选、自定义 tooltip 全靠它们：

需求 调用
坐标值 → 控件像素 axis->coordToPixel(value)
控件像素 → 坐标值 axis->pixelToCoord(pixel)
控件内是否落在绘图区 拿 plot->axisRect()->rect() 判断

注意 pixelToCoord 吃的是 QCustomPlot 控件自身的坐标，不是全局屏幕坐标。鼠标事件里拿到的是控件坐标，直接用；如果经过 mapToGlobal 转过，先转回来。

点击取值的完整链路是这样，先换算横坐标，再去曲线上取对应的 y：

cpp
void Widget::onMouseRelease(QMouseEvent *e)
{
    if (e->button() != Qt::MiddleButton)
        return;

    // 像素 → 坐标
    int idx = qRound(plot->xAxis->pixelToCoord(e->pos().x()));
    if (idx < 0 || idx >= plot->graph(0)->dataCount())
        return;

    // 坐标 → 数据点，前提是 key 就是 0,1,2... 的下标
    double y = plot->graph(0)->data()->at(idx)->value;
    QToolTip::showText(e->globalPos(),
                       QString("x: %1  y: %2").arg(idx).arg(y),
                       plot, QRect(0, 0, 1, 1), 10000);
}

at(index) 拿的是第几个点，不是 key 等于多少的点。只有 key 恰好等于下标（x[i] = i 这种最省事的造数据方式）时，这两个概念才对得上。

时间轴上 key 是一串秒数，用 at 会直接取错位置，要么越界，要么取到牛头不对马嘴的点。这种场合用 key 找迭代器：

cpp
// 找到第一个 key 不小于 now 的点
auto it = plot->graph(0)->data()->findBegin(now);
if (it != plot->graph(0)->data()->constEnd())
    double y = it->value;

一条通用规则：先把「像素」「坐标」「数据点下标」三个概念分清，再下手。三者混用是游标、tooltip 这类功能出错的主因。

三、刻度：数量、长度与子刻度 #

2.x 里刻度由 QCPAxisTicker 负责，axis->ticker() 拿到当前 ticker，改它的属性：

cpp
plot->xAxis->setRange(-15, 15);
plot->xAxis->ticker()->setTickCount(11);      // 主刻度 11 个
plot->xAxis->ticker()->setTickOrigin(1);      // 从 1 开始排布

setTickOrigin 改的是刻度序列的起点，不是范围。范围 -10 到 15、原点设 1，刻度就变成 -14、-9、-4、1、6、11 这一串，间隔不变，整体错位。有人要「刻度从 1 开始」，实际要的就是它。

刻度数量有两套策略，选错会得到相反的结果：

策略 行为 适用
tssReadability 可读性优先，自动把数量调整成好读的步长，你设的 11 会被改成 10 或 12 默认值，绝大多数场合
tssMeetTickCount 数量优先，尽量满足你设的数字 刻度必须固定条数、要对齐排版 
cpp
// 数量必须准，关掉可读性自动调整
plot->xAxis->ticker()->setTickStepStrategy(QCPAxisTicker::tssMeetTickCount);
plot->xAxis->ticker()->setTickCount(11);

顺手记一个反例：范围 -100 到 100 默认只出 5 个主刻度，看着很空，设成 11 才有常见的密度。这不是 bug，是可读性策略在算「好看的步长」。

刻度线的长度向内、向外分开设，单位是像素：

cpp
QPen pen;
pen.setColor(Qt::red);
pen.setWidth(2);
plot->xAxis->setTickPen(pen);

plot->xAxis->setTickLengthIn(30);    // 向绘图区里延伸 30 像素
plot->xAxis->setTickLengthOut(10);   // 向轴外延伸 10 像素

pen.setColor(Qt::blue);
plot->xAxis->setSubTickPen(pen);
plot->xAxis->setSubTickLengthIn(15);
plot->xAxis->setSubTickLengthOut(5);

主刻度和子刻度的长度是不同的两组接口，setTickLengthIn/Out 与 setSubTickLengthIn/Out 别混。向内延伸的那截画在绘图区内部，会跟网格线、曲线抢地方，刻度线很长时把 setTickLengthIn 压小一点，画面干净很多。

换 ticker 要用 QSharedPointer 包一层，轴会接管生命周期：

cpp
QSharedPointer<QCPAxisTickerText> textTicker(new QCPAxisTickerText);
textTicker->addTick(1, "低");
textTicker->addTick(5, "中");
textTicker->addTick(9, "高");
plot->xAxis->setTicker(textTicker);

常用的 ticker 子类：

ticker 用途 关键调用
QCPAxisTicker 默认线性刻度 setTickCount、setTickOrigin、setTickStepStrategy
QCPAxisTickerFixed 固定步长 setTickStep(0.5)、setScaleStrategy
QCPAxisTickerText 每一格自己给文字 addTick、setTicks
QCPAxisTickerDateTime 时间轴 setDateTimeFormat、setDateTimeSpec
QCPAxisTickerTime 运行时长计时 setTimeFormat
QCPAxisTickerLog 对数轴 配合 setScaleType(stLogarithmic)
QCPAxisTickerPi 以 π 为单位 setFractionStyle

QCPAxisTickerFixed 的 setScaleStrategy 决定步长能不能被缩放：ssNone 严格按你给的步长，ssMultiples 允许取整数倍，ssPowers 允许取 10 的幂。要「每 0.5 一格，一格都不许改」就用 ssNone。

四、刻度标签的格式 #

刻度文字的样子由两个属性控制：setNumberFormat 管样式，setNumberPrecision 管位数。格式串的字母沿用 QString::number 那一套，另加两个 QCustomPlot 自己的扩展：

字符 含义 例子
e 科学计数法 1.20e+06
f 定点小数，不用指数 1200000
g 自动选择，数小用定点、数大用指数 1.2 或 1.2e+06
b 指数部分写成漂亮的 10 的幂 1.2×10⁶ 形式的底子
c 乘号换成 × 必须跟在 b 后面

setNumberPrecision 对应 QString::number(double n, char format, int precision) 里的 precision，也就是小数点后保留的位数：

cpp
plot->xAxis->setNumberFormat("gbc");   // g 灵活、b 漂亮指数、c 乘号改成 ×
plot->xAxis->setNumberPrecision(1);
plot->replot();

三个常用组合的差别值得记住：

格式 效果
g 数小的时候用定点，数大的时候用科学计数
gb 数小用定点，数大用 10 的整数次幂写法，比 1.2e+06 好读
gbc 在 gb 基础上把乘号显示成 ×

非法格式不会崩，也不会报错，处理方式有两种，都容易踩：

cpp
plot->xAxis->setNumberFormat("fc");      // c 缺了 b，格式被削减成 "f"
plot->xAxis->setNumberFormat("hello");   // 首字符不是 e/f/g，格式保持原样不变

第一条说明 c 不能单独存在，它修饰的是 b 产生的幂写法；第二条说明校验只看第一个字符，后面跟一串野字母不会报错，你会在屏幕上继续看到旧格式，误以为设置没生效。

刻度文字本身还有几个开关。默认在轴外面，需要塞到绘图区里面就改 LabelSide：

cpp
plot->xAxis->setTickLabels(true);                        // 显示刻度值
plot->xAxis->setTickLabelSide(QCPAxis::lsInside);        // 刻度值画在轴内侧
plot->xAxis->setTickLabelColor(Qt::gray);
plot->xAxis->setTickLabelPadding(6);                     // 文字与刻度线之间的间距

lsInside 省掉了轴外面的空间，代价是刻度文字压在曲线上，数据贴着轴的场合会互相遮挡。数据密的时候别用。

要完全自定义每一格的文字，换成 QCPAxisTickerText：

cpp
QSharedPointer<QCPAxisTickerText> t(new QCPAxisTickerText);
t->addTick(0, "关");
t->addTick(1, "开");
t->addTick(2, "待机");
plot->xAxis->setTicker(t);
plot->xAxis->setRange(-0.5, 2.5);      // 留出两端的余量，标签才不会被挤到边上

addTick 只登记坐标和文字，不负责范围。范围不手动调，第一格和最后一格的文字会被裁掉半截。

五、日期时间轴 #

时间轴的 key 是一个 double，单位是秒，起点是 Unix 纪元。这个约定要记牢，单位搞错的表现很夸张。

标准做法，换 ticker：

cpp
QSharedPointer<QCPAxisTickerDateTime> dt(new QCPAxisTickerDateTime);
dt->setDateTimeFormat("MM-dd\nhh:mm:ss");   // 格式串支持换行
dt->setDateTimeSpec(Qt::LocalTime);
plot->xAxis->setTicker(dt);

时间格式串走 Qt 的 QDateTime::toString 语法，常用的几个：

格式串 显示效果
hh:mm:ss 时:分:秒，适合分钟级的滚动窗口
MM-dd\nhh:mm 两行，日期在上、时间在下，适合跨天的长窗口
yyyy-MM-dd 完整日期，适合天级数据
MMM d 三月 5 这种简短形式

写数据时把时间转成 key，两种写法等价：

cpp
// 写法一：官方实时示例的路子，毫秒除以 1000
double key = QDateTime::currentDateTime().toMSecsSinceEpoch() / 1000.0;

// 写法二：用 ticker 自带的转换，语义更直白
double key2 = QCPAxisTickerDateTime::dateTimeToKey(QDateTime::currentDateTime());

两种写法都要盯住单位。把毫秒直接塞进 key，时间轴会跑到五万年后，刻度文字显示成一串看不懂的年份；这就是单位错了，不是格式错了。

时间轴几乎不 rescaleAxes()，因为它算出来的范围会把整段历史都包进去，实时曲线立刻被压成一条线。正确做法是手动滚窗口：

cpp
double now = QDateTime::currentDateTime().toMSecsSinceEpoch() / 1000.0;

plot->graph(0)->addData(now, value);
plot->xAxis->setRange(now - 60, now + 1);   // 只显示最近 60 秒
plot->replot();

now + 1 那点余量是给最右侧刻度文字留的位置，不给的话最新一格的标签会被右边框切掉。

画「程序跑了多久」这类相对时间，用 QCPAxisTickerTime，它的 key 是从 0 开始的秒数：

cpp
QSharedPointer<QCPAxisTickerTime> tt(new QCPAxisTickerTime);
tt->setTimeFormat("%h:%m:%s");   // %h 时 %m 分 %s 秒 %z 毫秒
plot->xAxis->setTicker(tt);
plot->xAxis->setRange(0, 3600);

%z 是毫秒位。做采样耗时统计时把格式改成 %m:%s.%z，一眼能看出百毫秒级的抖动。

时区是另一个坑。数据按 UTC 存、ticker 按 Qt::LocalTime 显示，标签会整体差 8 小时。两边必须对齐，存 UTC 就配 Qt::UTC：

cpp
dt->setDateTimeSpec(Qt::UTC);

日期轴的 key 必须单调递增。乱序的 key 在日期轴上会让曲线出现回折的横线，看着像数据回退，实际是排序问题。批量灌历史数据时先 std::sort 再 setData，顺带把 alreadySorted 设成 true，这一点在第十章还会用到。

六、轴标题与标签旋转 #

轴标题就是那个「x」「y」，接口很简单：

cpp
plot->xAxis->setLabel("时间 / s");
plot->yAxis->setLabel("温度 / ℃");
plot->xAxis->setLabelColor(Qt::black);
plot->xAxis->setLabelPadding(4);     // 标题与刻度文字之间的间距

刻度文字太长会互相压，两个办法：旋转，或者抽稀。旋转更快：

cpp
plot->xAxis->setTickLabelRotation(-45);

正负号决定朝上还是朝下，两边都试一次，看哪边不压字。旋转之后文字占了矩形外面一块三角区，axisRect 的自动边距算不准，底部就会被裁掉：

cpp
plot->axisRect()->setAutoMargins(QCP::msNone);
plot->axisRect()->setMargins(QMargins(60, 20, 20, 70));   // 左 上 右 下

自动边距关掉就全靠手填，四个数字要跟着旋转角度和字号调。这个值调起来烦，但比标签被裁强。

setPadding 和 setOffset 是两个容易搞混的接口：

接口 作用 典型用途
setPadding(int) 轴标题与刻度文字之间的距离 标题离刻度太近时推开
setOffset(int) 整根轴往绘图区内部平移 让轴离开控件边缘，给装饰留位置 
cpp
plot->xAxis->setPadding(50);
plot->xAxis->setOffset(50);

两个都给 50，是能立刻看出差别的最快方式：padding 只动标题，offset 连轴线、刻度、标题整体挪。

图表的标题不属于任何一根轴，它挂在布局上。做法是插一行，塞一个 QCPTextElement：

cpp
plot->plotLayout()->insertRow(0);
QCPTextElement *title = new QCPTextElement(plot, "实时曲线",
                                           QFont("Microsoft YaHei", 12, QFont::Bold));
plot->plotLayout()->addElement(0, 0, title);

QCPTextElement 是布局元素，能设对齐和颜色，比在轴标题里硬塞长文字好控制：

cpp
title->setTextColor(Qt::darkBlue);
title->setFont(QFont("Microsoft YaHei", 14));

标题行插进去之后，axisRect 自动往下让。这时 axisRect 从布局的第 0 行变成了第 1 行，凡是用 plotLayout()->element(0, 0) 取轴矩形的代码都要跟着改，否则拿到的就是标题对象。

七、多条轴与轴矩形 #

一个绘图区里再挂一根副轴，能做双量纲并排显示，这是副轴最常见的用法：

cpp
plot->yAxis2->setVisible(true);
plot->yAxis2->setRange(0, 100);          // 右边这根表示百分比
plot->yAxis2->setLabel("湿度 / %");

// 第二条曲线挂到右轴上
plot->graph(1)->setValueAxis(plot->yAxis2);
plot->graph(1)->setPen(QPen(Qt::darkGreen));
plot->replot();

用 setValueAxis 之前，那根轴必须已经 setVisible(true)，否则曲线是画在图外面的，屏幕上什么都没有。setKeyAxis 同理，可以把某条曲线挂到上边的 xAxis2 上。

这一步做完，两根轴的范围互相独立，互不干扰。反过来，要联动就用 setupFullAxesBox(true) 或者自己连 rangeChanged，两条路的效果一样，区别在控制粒度：前者整根照抄，后者可以加偏移或换比例。

更彻底的分离是多个 QCPAxisRect，上下两个图共用一条时间轴：

cpp
QCPAxisRect *second = new QCPAxisRect(plot);
plot->plotLayout()->addElement(1, 0, second);

second->axis(QCPAxis::atBottom)->setLabel("时间 / s");
second->axis(QCPAxis::atLeft)->setLabel("压力 / kPa");
second->axis(QCPAxis::atBottom)->setRange(0, 60);
second->axis(QCPAxis::atLeft)->setRange(0, 200);

每个 axisRect 自带完整四根轴，取的时候用 second->axis(QCPAxis::atLeft)，不要用 plot->yAxis，那是第 0 个矩形里的轴。新手在这里翻车最多：数据挂到了第 1 个矩形，范围却设在第 0 个矩形上，屏幕上曲线一动不动。

上下两个图要左右对齐，靠 QCPMarginGroup 把边距绑在一起：

cpp
QCPMarginGroup *group = new QCPMarginGroup(plot);
plot->axisRect(0)->setMarginGroup(QCP::msLeft | QCP::msRight, group);
second->setMarginGroup(QCP::msLeft | QCP::msRight, group);

绑上之后，两块的左边距取最大值，绘图区的左边界严格对齐，不绑就会出现上下两图左边缘差几个像素的错位，出图的时候很明显。

图例挂在轴矩形上，不挂在整个控件上：

cpp
plot->legend->setVisible(true);
plot->axisRect()->insetLayout()->setInsetAlignment(0, Qt::AlignTop | Qt::AlignRight);

setInsetAlignment 的第 0 个元素就是 legend。要挪到左上，把对齐改成 Qt::AlignTop | Qt::AlignLeft；要放进第二个矩形，用 second->insetLayout()->addElement(plot->legend, ...)。

plotLayout() 本身是个网格，铺成 2×2 四块矩形：

cpp
// 默认的轴矩形占了 (0,0)，另外三块自己补
plot->plotLayout()->addElement(0, 1, new QCPAxisRect(plot));
plot->plotLayout()->addElement(1, 0, new QCPAxisRect(plot));
plot->plotLayout()->addElement(1, 1, new QCPAxisRect(plot));

// 取第 3 块（行列从 0 起）
QCPAxisRect *third = qobject_cast<QCPAxisRect *>(plot->plotLayout()->element(1, 0));

同一行列号重复 addElement 不会替换原来的元素，而是往那格里再叠一层，两个元素互相覆盖，看着像界面错乱。建之前用 element(row, col) 判一下那格有没有东西。

重建布局时注意顺序：clear() 之后要立刻把 axisRect 加回去，中间不能有任何取 plot->xAxis 的调用，原因见第八章。

控件里轴矩形的个数不影响绘制成本。真正花时间的是每个矩形里的数据点，多加两块空图，代价只有边框和刻度文字，小到测不出来。这一点在第九章展开。

八、清除图形：三种清除的范围 #

「怎么删掉画出来的图」是 QCustomPlot 论坛里被问得最多的问题，翻十三个回复能数出五种答案，每种都在删东西，删的范围完全不同。选错只有两种结果：屏幕上残留旧图，或者直接崩。

按层次分，删除动作落在三层上：

层次 删什么 代表调用 风险
数据层 只清点，曲线对象留着 graph(0)->data()->clear() 无
对象层 删曲线、删可绘项、删标注 removeGraph、clearGraphs、clearPlottables、clearItems 指针失效
布局层 连轴矩形和布局一起删 plotLayout()->clear() 轴指针悬空，崩

8.1 清数据：曲线还在，点没了 #

最轻的一层，只清容器里的数据点：

cpp
plot->graph(0)->data()->clear();
plot->replot();

老代码里更常见的写法是 clearData()，效果一样：

cpp
plot->graph(0)->clearData();
plot->replot();

编译器报没有这个成员时，换成 data()->clear()，两种写法清的是同一个容器。还有人写成 data().data()->clear()：data() 返回 QSharedPointer<QCPGraphDataContainer>，再点一次 .data() 拿到容器的裸指针，->clear() 清的还是容器。三种写法结果相同，只是绕的层数不同。

清数据的边界很清楚：曲线对象、图例项、画笔、线型、可见性、轴范围全部不动。定时刷新的场景就靠它，一轮 clear 加一轮 setData，曲线不重建，图例不闪。

要提醒一句：setData 本身会覆盖旧数据，清空这一步不是必须的。先 clear 再 setData，等于多跑一趟内存释放。

8.2 删曲线：removeGraph 的两个雷 #

删掉整条曲线，用 removeGraph：

cpp
plot->removeGraph(1);   // 删索引 1 那条
plot->replot();

第一个雷是指针。removeGraph 内部会 delete 曲线对象，之前存下的指针立刻失效：

cpp
QCPGraph *g = plot->graph(1);
plot->removeGraph(1);
g->setName("x");        // 野指针，崩

第二个雷是索引前移。删掉索引 1 之后，原来的索引 2 变成 1，索引 3 变成 2。循环里从小到大删，会跳着删、删到越界：

cpp
// 错误：删完 i=1，i=2 已经不存在了
for (int i = 0; i < plot->graphCount(); ++i)
    plot->removeGraph(i);

正确的批量删法是倒着来：

cpp
for (int i = plot->graphCount() - 1; i >= 0; --i)
    plot->removeGraph(i);
plot->replot();

论坛原帖里那段代码写的是 for (int i = count - 1; i > 0; i--)，条件写成了 i > 0，索引 0 那条永远删不掉。屏幕上总剩一根线，就是这个 >。边界必须是 >= 0。

还有一处别手欠。removeGraph 自己负责释放，不要提前 delete：

cpp
// 错误：二次释放
QCPGraph *g = plot->graph(0);
delete g;
plot->removeGraph(0);

8.3 clearGraphs 与 clearPlottables 的边界 #

一次清全部，有两个入口，清的范围不一样：

cpp
plot->clearGraphs();      // 只清 QCPGraph
plot->clearPlottables();  // 清所有 QCPAbstractPlottable
plot->clearItems();       // 清所有 QCPAbstractItem
plot->replot();

QCPGraph 的基类就是 QCPAbstractPlottable，所以 clearPlottables() 会把曲线、柱状图 QCPBars、曲线图 QCPCurve、金融图 QCPFinancial、统计盒 QCPStatisticalBox 一并清掉，比自己挨个 removeGraph 省事。

它清不掉文字。这就是论坛里那个疑问的来源：用 clearPlottables() 清完，标题和箭头纹丝不动。因为那段文字是 QCPItemText，属于另一棵继承树：

基类 归类 具体类型 清除接口
QCPAbstractPlottable 可绘项，跟数据绑定 QCPGraph、QCPBars、QCPCurve、QCPFinancial、QCPColorMap clearPlottables()
QCPAbstractItem 标注项，不跟数据 QCPItemText、QCPItemLine、QCPItemTracer、QCPItemStraightLine、QCPItemRect clearItems()

两棵树没有交集，要清干净就得两个都调：

cpp
plot->clearPlottables();
plot->clearItems();
plot->replot();

clearGraphs() 和 clearPlottables() 在「只有曲线」的图里效果一样。图里混了柱状图或者配色图，只能用后者，否则柱子和色图会留下来。

8.4 连布局一起清：plotLayout()->clear() #

最狠的一层。它删的是布局元素，轴矩形是布局元素之一，所以四根轴跟着一起没了：

cpp
plot->plotLayout()->clear();                                   // 轴矩形已经删除
plot->plotLayout()->addElement(0, 0, new QCPAxisRect(plot));   // 必须立刻补回来
plot->axisRect()->setupFullAxesBox(true);
plot->replot();

危险点在中间那一步。plot->xAxis 是 QCustomPlot 缓存的指针，指向的轴对象已经随轴矩形一起被删。清完布局、还没重建矩形的时候，任何一句 plot->xAxis->setRange(...) 都是野指针操作，表现是崩溃或者满屏花屏。

所以要记住这条顺序：clear() 之后第一件事是 addElement 一个 QCPAxisRect，中间不要碰任何轴。

只删局部的多余元素，用 removeAt，它同样会 delete 元素：

cpp
// 从后往前删，保留第 0 个（也就是轴矩形）
for (int i = plot->plotLayout()->elementCount() - 1; i > 0; --i)
    plot->plotLayout()->removeAt(i);

这套循环和删曲线的循环是同构的，都是倒序、都从尾部走，理由也一样：删一个，后面的索引全前移。

8.5 不算清除的第三条路：隐藏与裁剪 #

有些需求写成「清除」，实际不该清。曲线要能随时回来，就别删：

cpp
plot->graph(1)->setVisible(false);   // 藏起来，数据、图例项全保留
plot->graph(1)->setVisible(true);    // 一句话回来

实时曲线只关心最近一段，用 removeBefore 按 key 裁窗口，比清空重填稳：

cpp
double now = QDateTime::currentDateTime().toMSecsSinceEpoch() / 1000.0;
plot->graph(0)->data()->removeBefore(now - 60);   // 只留最近 60 秒

曲线对象一路不换，图例、画笔、轴范围都不用重设，数据容器也不会每次重新分配。

8.6 选哪个：一张决策表 #

你的目的 用哪个 备注
同一根曲线换一批数据 data()->clear() 后 setData，或直接 setData 直接覆盖更省
少一条曲线 removeGraph(i) 多条要倒序删
全部重来，轴保留 clearGraphs() / clearPlottables() 混了柱状图用后者
连文字、箭头、游标一起清 clearPlottables() + clearItems() 两个都得调
换轴、换布局、整图重建 plotLayout()->clear() + 重建 QCPAxisRect 高危，注意顺序
只是暂时不看 setVisible(false) 最省，别删
只裁掉过期的点 data()->removeBefore(key) 实时曲线的正解

一个可复用的清场函数：

cpp
void resetPlot(QCustomPlot *plot)
{
    plot->clearPlottables();   // 曲线、柱、曲线图、金融图
    plot->clearItems();        // 文字、箭头、游标
    plot->replot();
}

清完记得 replot()。这些 clear 系列不会自动重绘，屏幕上是上一帧的残影，直到下一次重绘才更新。拖动窗口触发重绘时旧图又冒出来，看着像「没清干净」，其实只是没画。

九、性能：影响绘图速度的因素 #

先把成本结构摆清楚。一次 replot() 重画的是整个控件，从轴、网格、刻度文字到每条曲线的全部点。所以每帧成本大致是：

text
每帧成本 ≈ 总数据点数 × 单点路径成本 + 刻度文字与图例的排版成本
总成本   ≈ 每帧成本 × 每秒重绘次数

公式里没有「控件数」和「轴数」。加一块空轴矩形，代价是四条边框加十来个刻度文字；一条十万点的曲线，代价是十万段线段。两者不在一个量级。所以卡的时候先数点，再数重绘，最后才看控件摆得对不对。

QCustomPlot 自己已经做了两层压成本的事：自适应采样（画的时候按像素密度丢点）和文本对象缓存（刻度文字不用每帧重新排）。剩下的开销主要来自三个地方：半透明填充、抗锯齿、粗线条。这三样都是逐像素混合，面积一大就压不住。

把影响项列成表，按处理优先级排：

因素 为什么慢 处理
数据点数 点数直接决定路径长度，十万点起明显 抽稀、开自适应采样
replot() 次数 每次都全量重画 节流合并，见第十一章
setData 的 alreadySorted 传 false 时每次插入都要重排 有序数据传 true
抗锯齿 每段线都做边缘混合 关掉可绘项的抗锯齿
半透明填充 alpha 混合的面积翻倍 去掉 brush 或改不透明
线宽 粗线要生成多边形轮廓 1 到 2 像素够用
刻度文字与图例 文本布局有缓存，但数量多了照样顶不住 减少刻度数、别每帧改格式
子网格 线条数量直接翻倍 不需要就关

setData 的第三个参数值得单独说，因为它常被随手写成默认值。实测耗时（毫秒）：

数据量 alreadySorted = true alreadySorted = false
1000 16.8 13.6
10000 21.6 22.6
100000 22.5 43.7
500000 43.3 197.2

读法：一万点以下两者打平，false 甚至略快一点；十万点时 true 快一倍左右；五十万点时 true 快 4.5 倍。结论分明：小数据不用管这个参数，大数据必须先保证 key 升序，再把 true 传进去。

cpp
// key 已经升序，直接告诉它别排了
plot->graph(0)->setData(keys, values, true);

代价是责任转移：传了 true，数据结构就必须真有序，乱序会画出回折的横线，而且不报错。

抗锯齿的开关粒度按元素类型走，不用全关：

cpp
// 曲线不做抗锯齿，坐标轴和图例保留
plot->setNotAntialiasedElements(QCP::aePlottables);

// 散点图另有开关
plot->setNotAntialiasedElements(QCP::aeScatters);

// 全关，导出大量静态图时用
plot->setNotAntialiasedElements(QCP::aeAll);

aePlottables 管曲线本体，aeScatters 管散点标记，两个是分开的。只画线、不开散点的时候，设前者就够。

线宽和填充是最容易顺手加的两样东西，也是最容易白烧性能的两样：

cpp
// 成本可控
plot->graph(0)->setPen(QPen(Qt::blue, 1));

// 成本翻倍：粗线加半透明填充
plot->graph(0)->setPen(QPen(Qt::blue, 4));
plot->graph(0)->setBrush(QBrush(QColor(0, 0, 255, 40)));

setBrush 那行的 alpha 只有 40，看着很淡，代价是整块面积逐像素混合。实时刷新时把它去掉，帧率立刻回来。

Qt 版本也有关系。Qt 4.8 之后底层绘图路径优化过一轮，同一份代码在新版本上跑，replot 的耗时明显下降。项目还锁在 Qt 4.7 的话，先升版本，再谈优化手段。

十、大数据量的优化手段 #

优化顺序只有一条：先减点，再减重绘，最后才抠细节。反着做，先把线宽改成 1 像素、把图例关掉，收益不如抽稀十分之一。

10.1 第一手段：让 QCustomPlot 自己丢点 #

QCPGraph 有自适应采样，默认是开的，先确认没被前人手贱关掉：

cpp
plot->graph(0)->setAdaptiveSampling(true);

它的作用是：曲线在像素上只占那么宽，点比像素还密的时候，采样阶段直接跳掉中间的点，只保留视觉上有贡献的极值点。数据量越大、控件越窄，省得越多。关掉它，十万点就是老老实实画十万段线。

10.2 第二手段：进去之前先抽稀 #

自适应采样发生在绘制阶段，数据容器里还是全量。想连内存和 setData 的排序成本一起省，就在填数据前抽稀。按桶取极值是保住波形的最省做法：

cpp
void decimate(const QVector<double> &keys, const QVector<double> &values,
              int bucket,
              QVector<double> &outKeys, QVector<double> &outValues)
{
    outKeys.clear();
    outValues.clear();

    const int n = keys.size();
    if (bucket < 2)
        bucket = 2;                 // 挡住 0，也挡住除零
    outKeys.reserve(n / bucket * 2 + 4);
    outValues.reserve(n / bucket * 2 + 4);

    for (int i = 0; i + bucket <= n; i += bucket) {
        int iMin = i, iMax = i;
        for (int j = i + 1; j < i + bucket; ++j) {
            if (values[j] < values[iMin]) iMin = j;
            if (values[j] > values[iMax]) iMax = j;
        }
        // 极值按 key 顺序放，出来的容器仍然升序
        const int a = qMin(iMin, iMax);
        const int b = qMax(iMin, iMax);
        outKeys   << keys[a]   << keys[b];
        outValues << values[a] << values[b];
    }
}

「每桶取一对极值」比「每 n 个点取一个」强的地方在于波形不塌：尖峰只要落在桶里，就一定被保留。每桶取一个的话，窄尖峰会被整片跳过去，看起来像数据丢失。

bucket 取多大，看控件宽度。800 像素宽的图，一帧能画的点也就一两千个，bucket = 数据量 / 2000 起步，再往上调。数据量本身不到两千的，别抽稀，抽完波形反而变糙。

cpp
QVector<double> k2, v2;
decimate(keys, values, keys.size() / 2000, k2, v2);
plot->graph(0)->setData(k2, v2, true);   // 抽稀后仍然升序

抽稀是预处理，别放进每帧的刷新回调里。数据进来时算一次，存起来复用。

10.3 第三手段：滑动窗口，让总量不增长 #

实时曲线卡，多数不是「一帧太慢」，而是「点一直在涨」。画了半小时，容器里堆了几十万点，每秒还要全量重绘几十次。裁掉窗口外的旧点，成本立刻封顶：

cpp
// 只保留最近 120 秒
plot->graph(0)->data()->removeBefore(lastKey - 120);

配合 addData 追加，容器规模稳定在一个常数上：

cpp
double key = QDateTime::currentDateTime().toMSecsSinceEpoch() / 1000.0;
plot->graph(0)->addData(key, value);
plot->graph(0)->data()->removeBefore(key - 120);
plot->xAxis->setRange(key - 60, key + 1);   // 只显示 60 秒

容器留 120 秒、视野只给 60 秒，是为了拖动时左边还有数据可看。两个数拉开一倍，拖动手感明显好。

10.4 第四手段：把不看的都关掉 #

细节优化放这里，收益不大但零成本：

cpp
plot->legend->setVisible(false);              // 图例不排文字
plot->xAxis->grid()->setVisible(false);       // 主网格
plot->yAxis->grid()->setVisible(false);
plot->xAxis->grid()->setSubGridVisible(false); // 子网格
plot->xAxis->ticker()->setTickCount(6);       // 刻度数量压到 6
plot->setNotAntialiasedElements(QCP::aePlottables);

还有一条容易忽略：别在刷新回调里改刻度格式或换 ticker。文本对象缓存靠的是格式稳定，格式一变缓存整体作废，每帧都重新排版刻度文字，成本比画曲线还高。

cpp
// 格式设置放在初始化的地方，只跑一次
plot->xAxis->setNumberFormat("gb");
plot->xAxis->setNumberPrecision(3);

十一、重绘策略与节流 #

replot() 是唯一真正画图的入口。它默认走队列：同一次事件循环里调十次 replot()，实际只画一次。所以下面这种写法不算浪费：

cpp
plot->graph(0)->setData(k1, v1);
plot->graph(1)->setData(k2, v2);
plot->xAxis->setRange(0, 60);
plot->replot();          // 前面三句只是改状态，这一句才画

真正浪费的是反过来的写法：数据来一个点就 setData 一次、replot 一次。硬件一秒给一千个点，就是一秒画一千帧，CPU 全烧在重排刻度文字上。

标准解法是脏标记加定时器，把「来了就画」改成「攒够一批再画」：

cpp
// 数据到了只记账，不动界面
void DataWidget::onSample(double key, double value)
{
    m_plot->graph(0)->addData(key, value);
    m_lastKey = key;
    m_dirty = true;
}

// 50ms 统一刷一次
void DataWidget::onRefresh()
{
    if (!m_dirty)
        return;
    m_dirty = false;

    m_plot->graph(0)->data()->removeBefore(m_lastKey - 120);
    m_plot->xAxis->setRange(m_lastKey - 60, m_lastKey + 1);
    m_plot->replot();
}

初始化那两句：

cpp
m_timer = new QTimer(this);
connect(m_timer, &QTimer::timeout, this, &DataWidget::onRefresh);
m_timer->start(50);      // 20 帧每秒，人眼够用

50 这个数可以调，但要清醒：它直接决定每秒重绘次数。给 10 就是 100 帧每秒，一帧 30ms 的图直接跑满；给 100 是 10 帧每秒，数字跳动感明显。20 帧是实时曲线的常用档。

采集在子线程时，控件操作必须回主线程：

cpp
// 采集线程只发数据，不碰 QCustomPlot
emit sampleReady(key, value);

// 主线程槽函数里才动控件
connect(worker, &Worker::sampleReady, this, &DataWidget::onSample,
        Qt::QueuedConnection);

QCustomPlot 是 QWidget 的子类，跨线程调它的成员就是踩 Qt 的线程红线，表现是随机崩溃、花屏、界面假死。用信号槽排队回主线程，别在子线程里 replot。

有两类重绘是 QCustomPlot 自己发起的，不要再叠一层：

触发 谁发的 你要做的
控件大小变化 内部 resizeEvent 自动 replot 别在 resizeEvent 里再调一次
拖动、滚轮缩放 内建交互自动 replot 别在 rangeChanged 里再调一次

在 rangeChanged 里回一句 replot()，一次拖动会触发几十次重绘，手感立刻变粘。

需要同步出图时才用立即模式：

cpp
// 默认队列模式，下一轮事件循环画
plot->replot();

// 立即模式：调用返回时已经画完，能紧接着截图
plot->replot(QCustomPlot::rpImmediateRefresh);
plot->savePng("output.png", 1200, 800);

rpImmediateRefresh 会当场把整幅图重画一遍，放进刷新循环里等于把节流全废掉。它只适合「改完属性马上要一张图」的场合。

批量重建时包一圈，省掉中间的无效重绘：

cpp
plot->setUpdatesEnabled(false);
plot->clearPlottables();
// ... 一次性把新数据、新轴范围、新刻度都设好
plot->setUpdatesEnabled(true);
plot->replot();

十二、易错点速查 #

按现象查，一条一条对。

现象 原因 处理
setRange 后界面没变 没调 replot() 设完范围补一次重绘
清完数据旧图还在 clear 系列不自动重绘 同上
removeGraph 之后崩 之前存的指针已被 delete 删完立刻丢弃指针，改用索引
批量删曲线总剩一条 循环写成 i > 0 边界用 i >= 0，倒序删
删完几条曲线后索引错位 索引前移，从小到大删 一律倒序
clearPlottables() 后文字还在 文字是 QCPAbstractItem，不是 plottable 补一句 clearItems()
plotLayout()->clear() 后崩 轴矩形被删，plot->xAxis 悬空 立刻 addElement 新的 QCPAxisRect，中间别碰轴
刻度数量设了不准 tssReadability 策略会改数量 换 tssMeetTickCount
setNumberFormat("xxx") 无效 首字符不是 e/f/g，格式被忽略 首字符必须是 e、f、g
setNumberFormat("fc") 只剩 f c 必须跟在 b 后面 写成 gbc
旋转刻度后底部被裁 自动边距算不准旋转后的外框 setAutoMargins(QCP::msNone) + setMargins
上轴右轴不跟着动 setupFullAxesBox 没传 true 传 true，或连 rangeChanged
第二条曲线不显示 setValueAxis 前轴没 setVisible(true) 先把轴显示出来
第二个轴矩形设范围无效 范围设在 plot->yAxis 上 用 second->axis(QCP::atLeft)
时间轴标签跑到 1970 或五万年后 key 单位错，塞了毫秒 key 用秒
时间标签整体差 8 小时 数据 UTC，ticker 用 Qt::LocalTime 两边对齐时区
日期轴曲线出现回折横线 key 乱序 排序后再 setData
实时曲线越跑越卡 容器里点数一直涨 data()->removeBefore
setData 十万点明显变慢 alreadySorted 传了 false 保证升序后传 true
散点图卡 散点标记的抗锯齿开销 aeScatters 关掉
图例不显示 只加了曲线，没开图例 plot->legend->setVisible(true)
保存的图是空白 保存前没重绘，或控件还没显示 先 replot，再 savePng

遇到问题按这个顺序自检，比乱改属性快：

  1. 屏幕上没变化，先找缺的那个 replot()。
  2. 删东西没删干净，先判断删的层次对不对：数据、对象，还是布局。
  3. 删完崩溃，先找自己保存过的指针。
  4. 卡，先数点数，再数每秒重绘次数，最后才看线宽和抗锯齿。

删除动作这一块再压一遍，因为它是这类问题的高发区：

cpp
// 只要新数据，曲线保留
plot->graph(0)->data()->clear();

// 少一条曲线（多条要倒序）
plot->removeGraph(i);

// 清全部可绘项，再清标注项
plot->clearPlottables();
plot->clearItems();

// 整图重建：清布局后必须立刻补回轴矩形
plot->plotLayout()->clear();
plot->plotLayout()->addElement(0, 0, new QCPAxisRect(plot));

plot->replot();   // 以上任何一条之后都别忘

记住这张对照表和这句「清完要重绘、删完要丢指针」，这一章的坑基本就绕完了。
