一、QPainter 在 Qt 绘图层的位置 #

Qt 的 2D 绘图系统是分层的，骨架由三个类撑起来。QPainter 负责执行绘图操作，QPaintDevice 提供绘图设备，是一个二维空间的抽象，QPaintEngine 提供后端接口，把抽象的绘制指令翻译成具体后端能执行的动作。

名字先对齐一下。不少老文章写成 QPainterDevice、QPainterEngine，Qt 文档里的真名是 QPaintDevice 和 QPaintEngine。看源码、看报错、搜文档的时候用真名，不然搜不到。

类 角色 你在代码里碰到的形态
QPainter 执行绘制。画笔、画刷、字体、变换、裁剪、渲染提示都挂在它身上 你自己 new 出来的那个对象
QPaintDevice 绘图设备的抽象，规定「往哪画」和坐标系的度量单位 QWidget、QPixmap、QImage、QPrinter、QSvgGenerator 都是它的子类
QPaintEngine 后端接口，规定「怎么画」 一般不直接碰。raster 引擎、OpenGL 引擎、PDF 引擎各管一摊

一次绘制走下来是这样一条链：

text
你的代码
  └─ QPainter            记录状态：pen / brush / font / transform / clip / hints
       └─ QPaintEngine   后端实现：raster（软件光栅）/ OpenGL / PDF / SVG / 打印机
            └─ QPaintDevice   落地目标：屏幕 / 内存位图 / 打印纸 / 文件

这条链决定了一件事：QPainter 能在任何 QPaintDevice 的子类上画。同一段绘制代码，目标从窗口换成 QImage 再换成 QPrinter，代码不用改。这就是为什么打印报表和屏幕显示能共用一套绘制逻辑。

QPainter 在整条技术栈里的位置，是「最底层的那只手」。它上面所有画东西的东西，最后都落到它身上：

上层设施 跟 QPainter 的关系
QChart、QCustomPlot、QwtPlot 自己算好坐标，把每条线、每个刻度、每段文字交给 QPainter 画
QGraphicsView 图形视图框架 场景渲染时逐个项调用项的 paint()，项的 paint() 里就是 QPainter
QStyle 控件样式 画按钮边框、焦点框、下拉箭头，全是 QPainter
QLabel 显示文字 内部渲染文字走的还是 QPainter::drawText()
QWidget 本身 重绘时给你一个 paintEvent()，里面递进来的就是 QPainter 的位置

所以「Qt 里画得不对」这个问题，往上追三层，答案经常就在这一层。

QPainter 能干的活：几何图元（点、线、折线、矩形、圆角矩形、椭圆、弧、弦、饼、多边形）；图像（QPixmap、QImage，支持缩放、平铺、按源区域裁剪）；文字（普通文字、带对齐换行的段落、路径文字）；抗锯齿；Alpha 混合与像素合成；渐变 / 纹理 / 图案填充；矢量路径 QPainterPath；平移、旋转、错切、缩放；矩形与路径裁剪。

有两件事动手前就该记住。QPainter 是有状态的对象，不是无状态的函数集合：调了 setPen() 之后这个画笔一直起作用，直到你改它，绘制指令按顺序执行，前面的设置影响后面所有绘制。一个绘图设备在同一时刻只能有一个活跃的 painter，别在 paintEvent() 里建了一个之后，又在别处对同一个 widget 建第二个。painter 析构会自动 end()，放栈上跟着作用域走最省事。

二、三种可绘制的地方 #

QPainter 的构造函数要一个 QPaintDevice*。传什么进去，就画在什么上面。可用的目标归成五类：

绘制目标 类 典型用途 关键点
屏幕控件 QWidget 及其子类 自定义控件、界面装饰、指示器 只能在 paintEvent() 里画，内容不持久，被遮挡后要重画
离屏位图 QPixmap 预生成缓存、图标合成、贴图 依赖 GUI 后端，绘制快，天生适合往屏幕上贴
离屏图像 QImage 线程内绘制、像素级处理、存文件 纯内存操作，可以跨线程，格式转换方便
打印 / PDF QPrinter 报表输出、导出 PDF 同一套代码换个设备就出纸，坐标系是点不是像素
矢量导出 QSvgGenerator 导出可缩放图形 只支持 SVG 能表达的特性，位图效果和部分合成模式会丢

前三种是日常主力，建 painter 的姿势也分三种。

画到屏幕上，只能这样：

cpp
void MyWidget::paintEvent(QPaintEvent *event)
{
    QPainter painter(this);
    painter.drawLine(0, 0, 100, 100);
}

画到 QImage 上，随处可写，连线程里都行。QPixmap 用法一样，只是类型换一行：

cpp
QImage image(400, 300, QImage::Format_ARGB32_Premultiplied);
image.fill(Qt::white);
QPainter painter(&image);
painter.setRenderHint(QPainter::Antialiasing, true);
painter.drawEllipse(QPointF(200, 150), 120, 80);
painter.end();          // 画完就 end，别把 painter 留在外面
image.save("out.png");

上面这几个目标里，只有画到控件上有额外约束。原因很实在：窗口的像素归窗口系统管，你只能在系统允许的那一刻往上面写。

为什么 QPainter 只能在 paintEvent 里用 #

这是初学者栽得最狠的一个坑，报错长这样：

text
QWidget::paintEngine: Should no longer be called
QPainter::begin: Paint device returned engine == 0, type: 1

代码长这样：

cpp
MyWidget::MyWidget(QWidget *parent) : QWidget(parent)
{
    QPainter painter(this);          // 错：构造函数里画
    painter.drawLine(0, 0, 100, 100);
}

一行都画不出来，还刷两行警告。三个原因叠在一起。

第一，构造函数执行的时候，控件还没走完创建流程，底层的绘制后端（QPaintEngine）还没准备好。QPaintDevice::paintEngine() 返回空，QPainter::begin() 直接失败。

第二，就算后端准备好了，你画上去的内容也活不过这一帧。窗口第一次显示、被遮挡后重新露出、尺寸变化，系统都会发一个重绘事件，paintEvent() 里的内容是这个时候生成的。你在构造函数里画的像素，跟系统随后的重绘没有任何关系。

第三，窗口内容不被保存。Qt 不会替你缓存「上次画了什么」，它只会一遍遍喊你重画。所以绘制逻辑必须写在能被反复调用的地方，也就是 paintEvent()。

还有几种变形的错法：new QPainter(this) 存成成员变量、在按钮的 clicked 槽里建 painter、在子线程里对 widget 建 painter、在 show() 之前画。报错一样，原因还是那三条——时机不对，设备没就绪。

正确的拆法是把「算什么」和「画在哪」分开：

cpp
class GaugeWidget : public QWidget
{
public:
    void setValue(double v) { m_value = v; update(); }   // 只改数据 + 请求重绘
protected:
    void paintEvent(QPaintEvent *event) override
    {
        QPainter painter(this);                          // 每次重绘重新建
        painter.setRenderHint(QPainter::Antialiasing, true);
        painter.drawText(rect(), Qt::AlignCenter, QString::number(m_value, 'f', 1));
    }
private:
    double m_value = 0.0;
};

外部改数据，update() 请求重绘，paintEvent() 里根据最新数据重画。这套分工是 Qt 绘图的固定套路，别绕开它。

真要「随便在哪画」，就把目标换成 QImage 或 QPixmap：先画到离屏图像，再在 paintEvent() 里用 drawImage() / drawPixmap() 一次性贴上去。这是唯一的合法出口，也是双缓冲的做法。

三、paintEvent 里画 #

paintEvent() 的签名是 void QWidget::paintEvent(QPaintEvent *event)，protected virtual。基类的默认实现是空的：不重写，控件就什么都不画；重写了，绘制逻辑就在这里跑。

哪些情况会触发重绘，四类：

触发时机 说明
控件第一次显示 系统自动产生一个绘图事件
调了 repaint() 或 update() update() 排队等下一轮事件循环，repaint() 立即同步重绘
被遮挡后又露出来 只对之前被遮住的那块区域产生重绘事件
窗口尺寸变化 拉伸、最大化、布局重新计算都算

update() 和 repaint() 的区别值得单独说一句。update() 只是把区域记进待重绘列表，等事件循环转回来再合并处理，多次调用会被压成一次。repaint() 立刻同步执行，不给合并机会。日常用 update()，性能好得多。只有在需要「这一行代码执行完，屏幕上必须已经是新画面」的场合（比如抓图前），才用 repaint()。

QPaintEvent 带了两个信息：rect() 是本次要重绘的矩形区域，region() 是精确区域。窗口被另一个窗口遮住一角再露出来时，这两个值只覆盖露出部分，不是整个控件。

擦背景的时候用 painter.fillRect(event->rect(), Qt::white)，别用 fillRect(rect(), ...) 擦整个控件。局部重绘是性能优化的第一站，控件越大、刷新越频繁，差别越明显。

两条线别踩：paintEvent() 里别调 update()，会形成「重绘 → 请求重绘 → 重绘」的死循环，界面直接卡死；也别做重活，读大文件、查数据库、算复杂布局全挪到外面算好，paintEvent() 只负责往屏幕上搬。

在子控件上画 #

paintEvent() 画的是自己这个控件。界面上摆了一堆子控件，想直接往某个子控件上画，两条路。

第一条，给子控件单独写个类，重写它的 paintEvent()。结构干净，但子控件种类一多，类就爆炸。

第二条，给子控件装事件过滤器，在 eventFilter() 里截住它的 QEvent::Paint：

cpp
line_label->installEventFilter(this);

bool MyWidget::eventFilter(QObject *obj, QEvent *event)
{
    if (obj == line_label && event->type() == QEvent::Paint)
    {
        int h = line_label->height();
        int w = line_label->width();

        QPainter painter(line_label);       // 目标设备是子控件，不是 this
        painter.setPen(QPen(Qt::gray, 1, Qt::DashLine));
        painter.drawLine(w / 2, 0, w / 2, h);
    }
    return QWidget::eventFilter(obj, event);
}

注意 QPainter painter(line_label) 这行：设备传的是子控件指针。这是合法用法，因为此刻正处在子控件的绘制事件处理流程里，后端是就绪的。

两种方式的取舍很直白：

方式 适用场景 代价
子类化重写 paintEvent() 绘制逻辑固定、只此一种 每种画法一个类
installEventFilter() 多个子控件画法各不相同 一个过滤器管一片，判断写在 if 里

界面上子控件多、每个画法还不一样的时候，用事件过滤器。加一行 installEventFilter 就多覆盖一个控件，不用新增类。

位置这一层讲清楚了，后面全是具体怎么画。下一章从画笔开始，因为所有能看见的轮廓都由它决定。

四、画笔 QPen #

画一个图形，Qt 拆成两件事：轮廓怎么描，内部怎么填。描轮廓的是 QPen，填内部的是 QBrush。这两个类撑起了 QPainter 绝大部分视觉表现。

先看 QPen。它管的是线和边缘，属性有五个：

属性 接口 作用
颜色 / 画刷 setColor(QColor) / setBrush(QBrush) 线本身用什么颜色。用 setBrush() 可以拿纹理或渐变当线条颜色
线宽 setWidth(int) / setWidthF(qreal) 单位是逻辑像素。setWidthF() 支持小数宽度
线型 setStyle(Qt::PenStyle) 实线、虚线、点线、点划线等
端点样式 setCapStyle(Qt::PenCapStyle) 线段两个端头怎么收口
连接样式 setJoinStyle(Qt::PenJoinStyle) 两条线段拐角处怎么接

构造函数有这几个重载：

cpp
QPen();
QPen(Qt::PenStyle style);
QPen(const QColor &color);
QPen(const QBrush &brush, qreal width,
     Qt::PenStyle style = Qt::SolidLine,
     Qt::PenCapStyle cap = Qt::SquareCap,
     Qt::PenJoinStyle join = Qt::BevelJoin);
QPen(const QPen &pen);

默认构造出来的 QPen() 是黑色、1 像素宽、实线、SquareCap、BevelJoin。

对应的 set 函数一整套：

cpp
void setBrush(const QBrush &brush);
void setColor(const QColor &color);
void setWidth(int width);
void setWidthF(qreal width);
void setStyle(Qt::PenStyle style);
void setCapStyle(Qt::PenCapStyle style);
void setJoinStyle(Qt::PenJoinStyle style);

同一个画笔，两种写法，效果完全一样。构造函数代码短，但那串 3、DashDotLine、RoundCap 堆在一起，读的时候得数位置；set 函数啰嗦，可每个参数名摆在那儿，改的时候不用数。维护期长的代码选后者。

cpp
// 写法一：构造函数，一行搞定
QPainter painter(this);
QPen pen(Qt::green, 3, Qt::DashDotLine, Qt::RoundCap, Qt::RoundJoin);
painter.setPen(pen);

// 写法二：set 函数，一行一个属性
QPen pen2;                       // 默认画笔
pen2.setStyle(Qt::DashDotLine);
pen2.setWidth(3);
pen2.setBrush(Qt::green);
pen2.setCapStyle(Qt::RoundCap);
pen2.setJoinStyle(Qt::RoundJoin);
painter.setPen(pen2);

painter.setPen(Qt::gray) 这种写法是隐式转换：Qt::GlobalColor 直接转成 QPen，得到 1 像素实线画笔。临时改一下颜色够用。

线型 #

Qt::PenStyle 枚举值：

枚举 效果
Qt::NoPen 不画线。轮廓完全消失
Qt::SolidLine 实线，默认值
Qt::DashLine 虚线，一段一段
Qt::DotLine 点线
Qt::DashDotLine 点划线
Qt::DashDotDotLine 双点划线
Qt::CustomDashLine 自定义，配合 setDashPattern()

自定义虚线要自己给节奏：

cpp
QPen pen(Qt::black);
pen.setStyle(Qt::CustomDashLine);
QVector<qreal> pattern;
pattern << 6 << 3 << 2 << 3;    // 实 6 空 3 实 2 空 3
pen.setDashPattern(pattern);

setDashPattern() 里的数字单位是线宽的倍数，不是像素。同一份 pattern，线宽从 1 变成 4，虚线段会长四倍。这个换算关系坑过不少人。

端点样式与连接样式 #

端点样式管一条线两头的收口，连接样式管两条线拐角怎么接。两组都只对宽线生效：线宽为 1 时，三种端点看起来毫无区别，Qt 文档写明 cap style 只对 width 大于 1 的线有意义。想让端点变圆，先把 setWidth() 调大。

枚举 效果
Qt::FlatCap 平头，端点正好停在坐标点，不往外伸
Qt::SquareCap 方头，端点向外伸出半个线宽，默认值
Qt::RoundCap 圆头，端点向外画一个半圆
Qt::MiterJoin 尖角，两条线的外边缘延长相交，默认值
Qt::BevelJoin 斜角，拐角处直接切一刀
Qt::RoundJoin 圆角，拐角处补一段圆弧
Qt::SvgMiterJoin SVG 规范的尖角，配 setMiterLimit() 用

MiterJoin 在很尖的锐角上会伸出一根长刺，那是 miter 长度超限，用 setMiterLimit() 限制，超了自动退化成 BevelJoin。

一个能跑的完整例子 #

素材里的这段代码把「改画笔 → 再画一笔 → 再改 → 再画」的循环走了一遍：

cpp
void MyWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.drawLine(0, 0, 100, 100);          // 默认画笔：黑色 1px 实线

    QPen pen(Qt::green, 5, Qt::DashLine, Qt::FlatCap, Qt::RoundJoin);
    painter.setPen(pen);                       // 换绿色粗虚线
    painter.drawArc(QRectF(70, 40, 80, 60), 30 * 16, 120 * 16);

    pen.setWidth(2);                           // 同一个 pen，改完必须重设
    pen.setStyle(Qt::SolidLine);
    painter.setPen(pen);
    painter.drawRect(50, 50, 20, 100);
}

两个细节。角度单位是 1/16 度，30 度要写 30 * 16，120 度写 120 * 16，drawArc()、drawPie()、drawChord() 全按这个规矩，忘了乘 16 画出来的弧小得看不见。

pen 是个值对象，改完要重新 setPen(pen)，QPainter 才拿得到新值。改了 pen 没重设，painter 手里还是旧的那份，因为 setPen() 拷贝的是副本。

五、画刷 QBrush #

QBrush 管填充。它定义了 QPainter 的填充模式，属性有四组：样式（style）、颜色（QColor）、渐变（QGradient）、纹理（QPixmap / QImage）。

构造函数一长串，从参数就能把属性反推出来：

text
QBrush()   QBrush(Qt::BrushStyle style)
QBrush(const QColor &color, Qt::BrushStyle style = Qt::SolidPattern)
QBrush(Qt::GlobalColor color, Qt::BrushStyle style = Qt::SolidPattern)
QBrush(const QColor &color, const QPixmap &pixmap)
QBrush(Qt::GlobalColor color, const QPixmap &pixmap)
QBrush(const QPixmap &pixmap)   QBrush(const QImage &image)
QBrush(const QGradient &gradient)   QBrush(const QBrush &other)

QBrush 的样式枚举是 Qt::BrushStyle，按填充内容分成这几类：

组别 枚举 说明
不填充 Qt::NoBrush 什么都不填。默认构造的 QBrush() 就是它
纯色 Qt::SolidPattern 单一颜色填满
图案 Qt::HorPattern / VerPattern / CrossPattern / BDiagPattern / FDiagPattern / DiagCrossPattern 横线、竖线、十字、反斜线、斜线、斜十字
密度图案 Qt::Dense1Pattern ~ Qt::Dense7Pattern 从最密到最疏的七档点阵
渐变 Qt::LinearGradientPattern / RadialGradientPattern / ConicalGradientPattern 三种渐变
纹理 Qt::TexturePattern 拿位图平铺

这里有个必须讲清的分工，也是「画了半天只有框」的根源：

设置 结果
只设 QPen，不设 QBrush 空心图形。只有一圈轮廓，里面是透明的
只设 QBrush，不设 QPen 实心块，没有独立轮廓。边框用的是 painter 当前的画笔
两个都设 轮廓一圈 + 内部填充，这才是完整图形
QPen 设成 Qt::NoPen 轮廓消失，只剩填充

QPainter 刚建出来的时候，画刷默认是 Qt::NoBrush。这解释了为什么新手第一次 drawRect() 只看到一根线：他没设画刷，Qt 也没替他填。

颜色 #

填纯色是最简单的用法，颜色可以给 Qt::GlobalColor 常量，也可以给 QColor 对象：

cpp
painter.setBrush(QColor(0, 0, 255));                   // 纯蓝
painter.setBrush(QColor(0, 0, 255, 128));               // 半透明蓝
painter.setBrush(QColor::fromRgbF(0.2, 0.4, 0.9));      // 浮点分量
painter.setBrush(Qt::yellow);                           // 全局颜色常量

带 alpha 的 QColor 是最常用的半透明手段，比调 setOpacity() 精细，因为它只影响这一个画刷。

线性渐变 #

QLinearGradient 取两个点定方向，颜色沿这条轴线插值：

cpp
void myWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);

    QLinearGradient linear(rect().topLeft(), rect().bottomLeft());
    linear.setColorAt(0.0, Qt::red);
    linear.setColorAt(0.5, Qt::green);
    linear.setColorAt(1.0, Qt::blue);          // 红 → 绿 → 蓝

    painter.setPen(Qt::gray);                   // 边框颜色
    painter.setBrush(linear);                   // 区域填充色
    painter.drawRect(QRect(0, 30, this->width(), this->height() - 30));
}

setColorAt() 的位置参数是 0 到 1 之间的比例。两端不设颜色，剩下的范围按最近的端点颜色延伸。

渐变不限于矩形。设成画刷之后，画什么图形都按图形自身的坐标去采样，圆、多边形、路径都行。

辐射渐变 #

构造函数是 QRadialGradient(center, radius, focalPoint)。圆心加半径定出一个圆，再给一个焦点。插值规则是焦点位置算 0，圆环边界算 1，然后在两者之间插颜色。焦点不在圆心时，得到一个偏心的光斑效果。

cpp
QRadialGradient radialGradient(QPointF(200, 190), 50, QPointF(275, 200));
radialGradient.setColorAt(0, QColor(255, 255, 100, 150));
radialGradient.setColorAt(1, QColor(0, 0, 0, 50));
painter.setBrush(radialGradient);
painter.drawEllipse(QPointF(200, 190), 50, 50);

超出渐变范围的部分怎么处理，由 setSpread() 决定：

枚举 行为
QGradient::PadSpread 用端点颜色一直铺下去，默认值
QGradient::RepeatSpread 重复整个渐变
QGradient::ReflectSpread 镜像来回反射

锥形渐变 #

构造函数是 QConicalGradient(center, angle)。角度在 0 到 360 度之间，从给定角度开始沿逆时针绕中心点插值。

cpp
QConicalGradient conicalGradient(QPointF(350, 190), 60);
conicalGradient.setColorAt(0.2, Qt::cyan);
conicalGradient.setColorAt(0.9, Qt::black);
painter.setBrush(conicalGradient);
painter.drawEllipse(QPointF(350, 190), 50, 50);

颜色沿圆周方向变化，拿来做表盘底纹、饼图配色很顺手。

gradient() 属性只在样式是 LinearGradientPattern、RadialGradientPattern、ConicalGradientPattern 三者之一时才起作用。painter.setBrush(linear) 这种写法会顺手把样式设成对应的渐变样式，不用手动 setStyle()。

纹理填充 #

把一张位图当填充内容，铺满整个图形的内部：

cpp
void MyWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);

    QBrush brush(QColor(0, 0, 255), Qt::Dense4Pattern);   // 蓝色密点图案
    painter.setBrush(brush);
    painter.drawEllipse(220, 20, 50, 50);

    brush.setTexture(QPixmap("../mydrawing/eryuelan.JPG"));  // 换成图片纹理
    painter.setBrush(brush);                                 // 必须重设

    static const QPointF points[4] = {
        QPointF(270.0, 80.0), QPointF(290.0, 10.0),
        QPointF(350.0, 30.0), QPointF(390.0, 70.0)
    };
    painter.drawPolygon(points, 4);
}

setTexture() 会顺手把 style() 改成 Qt::TexturePattern，不需要先手动设样式，这个自动切换是 Qt 定的规矩。

纹理路径别学 ../mydrawing/eryuelan.JPG 那种写法。相对路径按进程当前工作目录解析，跟源码目录没关系，换个启动方式图就没了。图片走 qrc 资源，写成 :/images/pattern.png，编进二进制。

图案画刷（Dense4Pattern 这类）在高分屏和缩放环境下的观感不稳定。要做稳定纹理直接用图片，图案枚举只适合快速示意。

六、画基本图元 #

QPainter 的绘制函数都叫 draw...，名字见名知义。常用的这一批：

函数 画什么
drawPoint() / drawPoints() 一个点 / 一组点
drawLine() / drawLines() 一条线 / 一组线
drawPolyline() / drawPolygon() 折线（不闭合）/ 多边形（闭合后填充）
drawRect() / drawRoundRect() 矩形 / 圆角矩形
drawEllipse() 椭圆，宽高相等时就是圆
drawArc() 弧，只有线，不闭合
drawChord() 弦，弧的两端连成直线后闭合填充
drawPie() 饼块，弧的两端连到圆心后闭合填充
drawPath() 任意路径，QPainterPath 描述
drawText() 文字
drawPixmap() / drawImage() 位图 / 图像

坐标参数有两种形态：整数版的 QRect、QPoint，浮点版的 QRectF、QPointF。要做精确布局和坐标变换，用浮点版，qreal 不丢精度。

直线 #

cpp
painter.setPen(Qt::gray);              // 画笔设为灰色
painter.drawLine(0, 0, 100, 100);      // 起点 (0,0)，终点 (100,100)

折线 #

四个点连成一条折线，顺手圈出一个「凹」形边框：

cpp
void myWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setPen(Qt::gray);
    static const QPointF points[4] = {
        QPointF(0, 30), QPointF(0, this->height() - 1),
        QPointF(this->width() - 1, this->height() - 1), QPointF(this->width() - 1, 30)
    };
    painter.drawPolyline(points, 4);
}

drawPolyline() 不闭合，从最后一个点回到第一个点的那段不会画。要闭合轮廓用 drawPolygon()，它把首尾连起来，并且顺带用当前画刷填内部。

背景图 #

铺一张背景图，一行就够：

cpp
QPainter painter(this);
painter.drawPixmap(rect(), QPixmap(skin_name));    // 拉伸铺满整个控件

rect() 是控件的整个区域，图片被拉伸到正好铺满，源图比例跟控件比例不一致时变形。要保持比例，用带源矩形和目标矩形的重载，自己算缩放后的目标区域。

圆角窗体 #

去掉标题栏、背景透明，再用纹理画刷加圆角矩形，得到一个圆角窗体：

cpp
setWindowFlags(Qt::FramelessWindowHint);          // 去掉标题栏
setAttribute(Qt::WA_TranslucentBackground);       // 没画到的地方透明

void myWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    QBrush brush;
    brush.setTextureImage(QImage(background_image));
    painter.setBrush(brush);                      // 画刷负责背景图
    painter.setPen(Qt::black);                    // 画笔负责边框线
    painter.drawRoundedRect(QRect(0, 0, this->width() - 1, this->height() - 1), 5, 5);
}

drawRoundedRect(rect, xRadius, yRadius) 的后两个参数是圆角在 x、y 方向的半径。

这个写法有个已知毛病：Qt::WA_TranslucentBackground 加上无边框之后，窗体 showMinimized() 最小化，再次显示时窗体上的子控件会失去焦点。要绕开就自己处理 changeEvent() 里的 QEvent::WindowStateChange，重新显示后手动给焦点控件 setFocus()。

弧、弦、饼 #

三个函数的参数格式一样：一个矩形框定椭圆，然后是起始角和跨度角，单位都是 1/16 度。

cpp
QRectF box(50, 50, 120, 120);

painter.setPen(QPen(Qt::darkBlue, 3));
painter.drawArc(box, 45 * 16, 180 * 16);          // 只有弧线

painter.setBrush(Qt::cyan);
painter.drawChord(box, 45 * 16, 180 * 16);        // 弧 + 弦，闭合填充

painter.setBrush(Qt::magenta);
painter.drawPie(box, 45 * 16, 270 * 16);          // 扇形饼块

角度从三点钟方向开始，逆时针为正。跨度给负数就是顺时针画。

QPainterPath #

图形一复杂，draw...() 那一堆函数就不够用了。QPainterPath 能装任意组合的线段、弧、贝塞尔曲线：

cpp
QPainterPath path;
path.moveTo(20, 80);
path.lineTo(80, 20);
path.quadTo(140, 140, 200, 80);                   // 二次贝塞尔
path.cubicTo(240, 40, 280, 120, 320, 80);         // 三次贝塞尔
path.addEllipse(QPointF(60, 140), 30, 30);        // 往里塞个圆
path.closeSubpath();
painter.setPen(QPen(Qt::darkGreen, 2));
painter.setBrush(QColor(200, 255, 200));
painter.drawPath(path);

想分别控制描边和填充，用 strokePath(path, pen) 和 fillPath(path, brush)；两个都要就是 drawPath()。路径还能拿来做裁剪区（setClipPath()）、做文字排版基线（addText()）、做命中测试（contains()）。

七、文字与字体 #

文字是 QPainter 三件套里的第三件：画笔、画刷、字体。绘制文字用 drawText()，字体由 QFont 给出。

drawText() 常用的三个重载是 drawText(QPointF position, QString text)、drawText(int x, int y, QString text)、drawText(QRectF rectangle, int flags, QString text)。

前两个的 y 是基线位置，不是文字顶边。写 drawText(10, 0, "...") 的时候，字会有一大半跑到控件上方看不见，因为基线在 y=0，字体的升部全在负坐标区。

要按矩形框排版、要居中、要自动换行，用第三个重载，靠 flags 控制对齐：

flag 作用
Qt::AlignLeft / AlignRight / AlignHCenter 水平方向左、右、居中
Qt::AlignTop / AlignBottom / AlignVCenter 垂直方向顶、底、居中
Qt::AlignCenter 水平垂直都居中，等于上面两组各取居中
Qt::TextWordWrap 按单词边界换行
Qt::TextSingleLine 强制单行，换行符当空格 
cpp
void MyWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::TextAntialiasing, true);

    QFont font = painter.font();
    font.setFamily("Microsoft YaHei");
    font.setPixelSize(18);
    font.setBold(true);
    painter.setFont(font);

    painter.setPen(QColor(30, 30, 30));
    painter.drawText(rect().adjusted(12, 12, -12, -12),
                     Qt::AlignCenter | Qt::TextWordWrap,
                     "一段需要居中并且自动换行的说明文字");
}

QFont 的常用属性：

属性 接口
字体族 setFamily()
字号 setPointSize()（点）/ setPixelSize()（像素）
粗体 setBold(true) 或 setWeight(QFont::Bold)
斜体 setItalic(true)
下划线 / 删除线 setUnderline(true) / setStrikeOut(true)
字距 setLetterSpacing()

点数和像素别混用。界面布局按像素算的时候用 setPixelSize()，跨 DPI 的一致性更好控制。

排版前想量一下文字的尺寸，用 QFontMetrics：

cpp
QFontMetrics fm(painter.font());
int w = fm.horizontalAdvance("测量这段文字");   // Qt 5.11+，旧版用 fm.width()
int h = fm.height();
int asc = fm.ascent();
int desc = fm.descent();

// 超长自动加省略号
QString elided = fm.elidedText(longText, Qt::ElideRight, availableWidth);
painter.drawText(QRect(10, 10, availableWidth, h), Qt::AlignLeft | Qt::AlignVCenter, elided);

文字量大、刷新频繁的时候（比如实时数值面板），QStaticText 比 drawText() 省。它把文字的形状预先排好、缓存起来，每帧只做一次贴图，适合内容固定、只改位置的场景。

八、图片与像素图 #

Qt 把图像分成两个类，分工很明确：

类 适合干什么 代价
QPixmap 往屏幕上显示。内部格式跟显示后端对齐，绘制快 依赖 GUI 后端，不能在非 GUI 线程里操作
QImage 逐像素读写、格式转换、跨线程处理、存文件 显示时要先转成 QPixmap，多一次拷贝

绘制接口有三个：

cpp
void drawPixmap(const QRectF &target, const QPixmap &pixmap, const QRectF &source);
void drawPixmap(const QPointF &p, const QPixmap &pixmap);
void drawImage(const QRectF &target, const QImage &image, const QRectF &source);
void drawTiledPixmap(const QRectF &rect, const QPixmap &pixmap, const QPointF &offset);

drawTiledPixmap() 是平铺，适合做网格底纹、棋盘背景，不用自己写双层循环。

缩放绘制要注意质量。默认情况下 Qt 用最近邻采样，图片缩小一半会出锯齿。想让缩放平滑，开这个渲染提示：

cpp
painter.setRenderHint(QPainter::SmoothPixmapTransform, true);
painter.drawPixmap(targetRect, pixmap, pixmap.rect());

按比例缩放到固定框里，目标矩形自己算：

cpp
QPixmap src(":/images/photo.jpg");
QRectF box(20, 20, 300, 200);
QSizeF scaled = src.size();
scaled.scale(box.size(), Qt::KeepAspectRatio);
QRectF target(box.center().x() - scaled.width() / 2,
              box.center().y() - scaled.height() / 2,
              scaled.width(), scaled.height());
painter.drawPixmap(target, src, src.rect());

QSize::scale() 配 Qt::KeepAspectRatio 直接给出等比缩放后的尺寸，比自己算比例可靠。

线程里要做图像处理，就用 QImage：在工作线程画好，通过信号把 QImage 传回 GUI 线程，再 QPixmap::fromImage() 转一次贴上去。这是「后台生成 + 前台显示」的标准做法。

九、坐标变换：平移、旋转、缩放 #

QPainter 的默认坐标系是控件左上角为原点，x 向右增大，y 向下增大，单位是逻辑像素。坐标变换改的是「逻辑坐标到设备坐标」的映射关系。四个函数：

函数 效果
translate(dx, dy) 平移。原点挪到 (dx, dy)
rotate(angle) 旋转。顺时针为正，单位是度
scale(sx, sy) 缩放。sx 或 sy 给负数就是镜像
shear(shx, shy) 错切。把矩形压成平行四边形
resetTransform() 清空所有变换，回到单位矩阵

顺时针为正这点容易搞反。数学课本里逆时针为正，Qt 里 y 轴朝下，所以顺时针是正角。想让表针顺时针走，rotate() 传正数。

变换是累乘的 #

这是整章最重要的一条：变换不会互相覆盖，是在当前变换的基础上继续右乘。调几次叠加几次，顺序直接影响结果：

cpp
// 写法 A：先平移，再旋转
painter.translate(100, 100);
painter.rotate(45);
painter.drawRect(-20, -20, 40, 40);
// 矩形在自己被挪到的位置上原地转动

// 写法 B：先旋转，再平移
painter.resetTransform();
painter.rotate(45);
painter.translate(100, 100);
painter.drawRect(-20, -20, 40, 40);
// 平移的 (100,100) 被旋转了 45 度，矩形跑到斜方向上去

用矩阵看很清楚。写法 A 是 T · R，点先转再移。写法 B 是 R · T，点先平移到 (100,100)，再被 R 绕着原点转 45 度，(100,100) 这个位置本身就转了。

记住一句话：后写的变换作用在「已经变换过的坐标系」上。translate(100,100) 之后的 rotate(45)，转的是原点已经挪到 (100,100) 的那个坐标系。

绕指定点旋转 #

rotate() 永远绕当前坐标系的原点转。想让图形绕自己的中心转，套路是把原点搬过去，转完搬回来：

cpp
QPointF center(150, 150);

painter.save();                    // 存一份干净状态
painter.translate(center);         // 原点搬到图形中心
painter.rotate(30);                // 现在绕着它转了
painter.translate(-center);        // 原点搬回左上角
painter.drawRect(QRectF(center.x() - 50, center.y() - 30, 100, 60));
painter.restore();                 // 状态还原，后续绘制不受影响

这三行 translate / rotate / translate 是所有「绕点旋转」的通用模板。少掉最后的 translate(-center)，图形会绕着左上角转一大圈。

一个完整的例子 #

画一圈表盘刻度，同时用上平移、旋转、缩放：

cpp
void DialWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);
    const QPointF center(width() / 2.0, height() / 2.0);

    for (int i = 0; i < 60; ++i)
    {
        painter.save();
        painter.translate(center);      // 原点挪到圆心
        painter.rotate(i * 6.0);        // 每格 6 度
        painter.scale(1.0, i % 5 == 0 ? 2.0 : 1.0);   // 整点刻度拉长
        painter.setPen(QPen(Qt::black, i % 5 == 0 ? 2.0 : 1.0));
        painter.drawLine(QPointF(0, -100), QPointF(0, -110));
        painter.restore();              // 关键：每圈都还原
    }
}

循环里 save() 和 restore() 一对，是最要紧的地方。少了 restore()，60 次 rotate(6) 累加成 360 度，60 次 translate(center) 把原点推出屏幕，画出来一团乱。

scale(1.0, 2.0) 这类非等比缩放也会影响线宽。画笔宽度在变换后跟着缩放走，缩放 2 倍的地方线也粗 2 倍。要线宽恒定，把画笔设成 cosmetic：pen.setCosmetic(true)，或者 setWidth(0)，宽度 0 表示「永远 1 像素，不管怎么缩放」。

高分屏 #

逻辑坐标跟物理像素之间隔着设备像素比。控件 400 逻辑像素宽，在 2 倍屏上是 800 物理像素，这个换算 QPainter 自己处理。往 QImage 上画、之后又当控件背景贴的时候，要手动对齐比例，否则图在高分屏上会糊：

cpp
const qreal dpr = devicePixelRatioF();
QImage buffer(size() * dpr, QImage::Format_ARGB32_Premultiplied);
buffer.setDevicePixelRatio(dpr);
buffer.fill(Qt::transparent);
QPainter painter(&buffer);      // 照常按逻辑坐标画，dpr 交给 QImage

setDevicePixelRatio() 这行是关键，缺了它，drawImage() 贴上去的图会被当成 1 倍图拉伸。

十、抗锯齿与渲染提示 #

抗锯齿（反走样）让图形边缘和文字不发毛刺。它由渲染提示控制，用 setRenderHint() 打开：

cpp
painter.setRenderHint(QPainter::Antialiasing, true);       // 图形边缘抗锯齿
painter.setRenderHint(QPainter::TextAntialiasing, true);   // 文字抗锯齿

可用的提示：

渲染提示 作用 什么时候开
QPainter::Antialiasing 图形边缘抗锯齿 画圆、弧、斜线、曲线时开
QPainter::TextAntialiasing 文字抗锯齿 几乎总该开
QPainter::SmoothPixmapTransform 位图缩放用平滑插值 缩放显示图片时开
QPainter::NonCosmeticBrushPatterns 图案画刷跟随变换 图案要跟着图形一起旋转、缩放时开
QPainter::LosslessImageRendering 无损渲染图像 需要保真输出时开，代价高
QPainter::VerticalSubpixelPositioning 文字垂直亚像素定位 排版要求精确基线时开

抗锯齿不是白给的。它要把每个边缘像素算成混合色，小图形密集绘制时开销明显。两类场景该关掉：横平竖直的 1 像素网格线（抗锯齿会把一条像素线摊成两个半透明灰边，看起来更糊，关掉之后线条锐利还更快）；上万个图元的批量绘制（画一张十万点的散点图，每个点都开抗锯齿，帧率直接掉）。

设置是「开一次，一直生效」，跟画笔一样属于 painter 的状态，会跟着 save() / restore() 走。

还有两个跟渲染有关的开关，顺手记一下：

cpp
painter.setClipRect(QRectF(0, 0, 200, 200));       // 只在指定区域内绘制
painter.setClipPath(path);                          // 按路径裁剪
painter.setCompositionMode(QPainter::CompositionMode_Multiply);  // 合成模式

裁剪区之外的一切绘制都被丢掉，这是做「图形超出控件边界就切掉」的最省事手段。合成模式控制新旧像素怎么混，SourceOver 是默认的半透明覆盖，CompositionMode_Clear 可以直接擦掉一片区域。

十一、保存与恢复状态 #

QPainter 是个状态机，它记住的东西比想象的多：

状态 相关接口
画笔 setPen() / pen()
画刷 setBrush() / brush()
字体 setFont() / font()
变换矩阵 translate() / rotate() / scale() / setWorldTransform()
裁剪区 setClipRect() / setClipPath()
渲染提示 setRenderHint()
合成模式 setCompositionMode()
整体透明度 setOpacity()

save() 把当前这一整套压进栈，restore() 从栈里弹出并恢复。这是个标准的栈，可以嵌套：

cpp
void MyWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setPen(Qt::black);
    painter.setBrush(Qt::white);
    painter.save();                       // 第 1 层

    painter.translate(100, 100);
    painter.setPen(Qt::red);              // 只在这个区块里生效
    painter.drawRect(0, 0, 50, 50);
    painter.save();                       // 第 2 层，嵌套

    painter.rotate(45);
    painter.setBrush(Qt::blue);
    painter.drawRect(-25, 25, 50, 50);
    painter.restore();                    // 回到第 1 层：蓝画刷没了，旋转没了

    painter.drawEllipse(QPointF(0, 0), 20, 20);   // 红画笔 + 白画刷 + 没有旋转
    painter.restore();                    // 回到最初：黑画笔 + 白画刷
}

三条实践规则。save() 和 restore() 必须成对，restore() 次数多于 save() 时 Qt 会打印 QPainter::restore: Unbalanced save/restore 警告，状态还被搞乱。

每个「临时改样式」的区块都包一对。要改画笔颜色画一笔，改完还原，比手动记「原来是什么颜色」再设回去可靠得多。

painter 析构时会自动 end()，但 save() 的栈不会自动清。局部函数里 save() 了没 restore() 就返回，栈里留一层垃圾，下次从同一层取状态时对不上。

写库函数的时候这一条尤其要紧：函数内部随便改画笔、改变换，进出都用 save() / restore() 包住，调用方不用关心你改了什么。这也是 Qt 自己的绘制代码的写法。
