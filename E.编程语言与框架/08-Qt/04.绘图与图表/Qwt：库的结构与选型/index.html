这篇讲 Qwt 的整体面貌：它由哪些控件组成，内部怎么分层，什么场景值得用它。读完你应该能回答一个问题——我的项目该不该上 Qwt，上哪一半。

不讲的部分：源码怎么编、库怎么装进 Qt Creator、.pro 和 CMake 怎么写完整，这些在同目录《Qwt 编译与安装》里。曲线怎么画、坐标轴怎么定制、缩放平移怎么配，在《Qwt 曲线与坐标轴》里。QwtPlotBarChart、QwtPlotHistogram 画统计图的细节在《QwtPlot 统计图》里。QCustomPlot、QChart、QPainter 各自有专篇，这一篇只在选型章做横向对比。

代码片段都是能编译的骨架，为了短，省略了头文件保护和 ui_*.h 之类。控件类那几章的例子直接扔进一个 QWidget 的构造函数就能看效果。

一、Qwt 的定位：技术型图表 #

Qwt 全称 Qt Widgets for Technical Applications，一个基于 Qt 的 C++ GUI 组件库，写给科学和工程领域的程序用。当前稳定版 6.3.0，支持 Qt 5.6+ 和 Qt 6.x。官方那份 User's Guide 还停在 6.2，里面写的兼容范围是 Qt 4.8 和全部 Qt5 版本——版本号对不上，别以为文档过期了库就不能用。

先把这个库的定位钉死：它是技术型图表库，不是商业图表库。这两个词不是修辞，它们决定了一套 API 长什么样、哪些功能做得深、哪些功能压根不做。

维度 技术型图表（Qwt 这类） 商业图表（报表、大屏）
首要目标 读得准、刷得快、量程可配 好看、有动画、配色抓眼
典型图元 曲线、刻度、网格、表盘、滑块 饼图、环形图、漏斗图、指标卡
数据规模 十万点级实时流 几十个类目
交互重点 框选缩放、游标取值、精确读数 悬浮提示、点击下钻
审美取向 素、克制、能黑白打印 渐变、阴影、圆角
轴的需求 四条轴、对数轴、时间轴、自定义标签 一条分类轴

Qwt 的强项集中在工业界面那一侧：仪表盘、刻度控件、实时曲线。这三类东西有个共同点——它们不是「数据可视化」，是「设备面板」。面板要的是刻度对得上、指针不抖、量程能改，不是配色好看。

判断一个需求该不该找 Qwt，问一句就够：这个界面是不是要贴在机器旁边给人看的？是，往下读。不是，直接去看 Qt Charts 那一篇。

它的价值不在「能画图」 #

能画图的库太多了。Qwt 真正难被替代的地方是：工业界面里那些零碎控件，它已经做完了。温度表、压力表、转速表、方向罗盘、模拟时钟、旋钮、滑块、滚轮、温度计柱、独立刻度条——这些东西你手写一个要两三天，还要处理拖动、键盘、鼠标滚轮、刻度对齐、暗色主题下看不清。Qwt 里全是现成的类，new 出来设几个属性就能用。

所以选 Qwt 的理由，九成是「为了这些控件」，剩下一成是「为了 LGPL 系许可」。

Qwt 有两半，很多人只用过一半 #

这是理解这个库的关键，也是新手最容易漏掉的部分。

Qwt 不是一个绘图库加一堆附属品。它是两个平行的半区，各自有基类、各自的用法：

绘图类：QwtPlot 加它上面挂的一堆可绘项（QwtPlotItem 的派生类）。画曲线、画频谱、画柱状图走这一半。

控件类：QwtDial、QwtSlider、QwtCompass、QwtKnob、QwtThermo 这一批。它们自己就是 QWidget，扔进布局就跟 QPushButton 一样用，跟绘图没有依赖关系。

绘图类 控件类
入口 QwtPlot QwtAbstractScale 的派生类
是不是 QWidget QwtPlot 是（继承 QFrame），可绘项不是 都是
怎么进界面 item->attach(plot) 加进 layout，跟普通控件一样
谁负责画 QwtPlotCanvas 的 paintEvent 遍历图元 控件自己的 paintEvent
数据怎么给 setSamples() 批量灌 setValue() 给单个数
典型用途 曲线、频谱、柱状、K 线 表盘、旋钮、滑块、温度计
上手成本 中，得理解坐标映射 低，设属性就行

很多人装了 Qwt，只用了 QwtPlot 画曲线，然后抱怨「这库也没什么特别的」——表盘那一半从来没打开过。反过来也成立：有人只要一个旋钮，结果去翻 QwtPlot 的文档，翻了半天没找到。两个半区在文档里是平铺的，annotated.html 一长串类名混在一起，不先建立这个二分，看文档就是瞎逛。

二、Qwt 的模块划分 #

Qwt 不是一个铁板一块的库。编译期有一组开关，决定哪几块进二进制。这些开关写在源码根目录的 qwtconfig.pri 里。

QWT_INSTALL_PREFIX = /usr/local/qwt-$$QWT_VERSION

QWT_CONFIG += QwtPlot          # 绘图模块
QWT_CONFIG += QwtWidgets       # 仪表盘控件
QWT_CONFIG += QwtSvg           # SVG 导出，依赖 Qt SVG
QWT_CONFIG += QwtOpenGL        # OpenGL 画布
QWT_CONFIG += QwtDesigner      # Designer 插件

每个开关对应一块源码。关掉哪个，哪块的 .cpp 就不参与编译，库体积和依赖一起缩。

开关 打开后多出什么 关掉的代价
QwtPlot 整套 2D 绘图：QwtPlot、QwtPlotCanvas、全部可绘项 没有图可画
QwtWidgets QwtDial、QwtSlider、QwtKnob、QwtThermo、QwtCompass、QwtWheel 只剩绘图那一半
QwtSvg QwtPlotSvgItem，把 SVG 当图元贴进坐标系 SVG 相关能力全没
QwtOpenGL QwtPlotGLCanvas，OpenGL 渲染后端 高密度曲线只能走光栅
QwtDesigner qwt_designer_plugin，Designer 里能拖控件 只能手写代码摆位置
QwtMathML QwtMathMLTextEngine，QwtText 支持 MathML 标签退回纯文本

QwtSvg 打开需要 Qt SVG 模块，编译报 qsvgrenderer.h not found 就是没装，把这个开关注释掉即可。

QwtWidgets 很容易被忽略。有人只要 QwtPlot，编的时候把 QwtWidgets 关了，后来想在界面上放个刻度条，发现 qwt_scale_widget.h 引不到——QwtScaleWidget 就归在 QwtWidgets 里。

两条裁剪路线 #

改 qwtconfig.pri 是一条路。还有一条，直接在工程文件里下手，适合你手上只有一份别人配好的源码、不方便重新跑 qmake 的情况。

greaterThan(QT_MAJOR_VERSION, 4) {
    QT += printsupport
    QT += concurrent
}

DEFINES += QWT_NO_SVG
DEFINES += QWT_NO_OPENGL

再进 src 目录删掉这四个文件：

text
qwt_plot_svgitem.h
qwt_plot_svgitem.cpp
qwt_plot_glcanvas.h
qwt_plot_glcanvas.cpp

DEFINES 里那两个宏是「告诉源码别有这块」，删文件是「让构建系统根本看不见这块」。两个动作要配对，只定义宏不删文件，某些构建配置下还会去编那个 .cpp，然后报头文件找不到。

QT += printsupport 和 QT += concurrent 是硬依赖：QwtPlot 的打印、导出走 QtPrintSupport，缺了它链接时报 QPrinter 相关符号找不到；concurrent 给部分渲染代码用。Qt 5 之后这两个模块不再默认包含，Qt 4 时代不用写这两行，所以老代码搬过来会缺。

环境要求 #

依赖项 最低版本 推荐版本
Qt 5.6.0 6.5+
C++ 标准 C++11 C++17
编译器 MSVC 2017 / GCC 7 / Clang 5 MSVC 2022 / GCC 13

Qwt 不发布二进制包。Linux 各大发行版基本都打了包，但常常不带 examples 目录；Windows 上没得选，只能自己编源码，这条路在《Qwt 编译与安装》里讲透。

按文件名前缀认模块 #

src/ 是平铺的，一个类一对 .h/.cpp，靠文件名前缀分职能。记住前缀，翻源码时不用一层层点目录。

前缀 归属 代表类
qwt_plot.*、qwt_plot_canvas、qwt_plot_layout 绘图核心 QwtPlot、QwtPlotCanvas、QwtPlotLayout
qwt_plot_curve、qwt_plot_grid、qwt_plot_marker … 可绘项 QwtPlotCurve、QwtPlotGrid、QwtPlotMarker
qwt_scale_engine、qwt_scale_draw、qwt_scale_map、qwt_scale_div 刻度体系 QwtScaleEngine、QwtScaleDraw、QwtScaleMap
qwt_dial*、qwt_compass*、qwt_knob、qwt_slider、qwt_wheel、qwt_thermo 控件半区 QwtDial、QwtCompass、QwtKnob
qwt_text*、textengines/ 文本与排版 QwtText、QwtTextEngine
qwt_symbol、qwt_legend、qwt_picker、qwt_painter、qwt_event_pattern 支撑设施 QwtSymbol、QwtLegend、QwtPicker

三、QwtPlot 与可绘项体系 #

QwtPlot 继承 QFrame，是个容器，不是画布。它自己几乎不画东西，只负责三件事：摆好四条轴、把矩形区域分配给画布、管理挂上来的图元。

text
QFrame
  └── QwtPlot
        ├── QwtPlotCanvas          画布，真正落笔的那块
        ├── QwtScaleWidget x4      上 / 下 / 左 / 右四条轴
        ├── QwtLegend              图例，insertLegend() 之后才存在
        ├── QwtPlotLayout          给上面几块算矩形
        └── QwtPlotItem x N        通过 attach() 挂进来的可绘项
组件 职责 生命周期
QwtPlot 容器，负责坐标轴与图元的布局 随父窗口销毁
QwtPlotCanvas 渲染层，处理绘制和输入 由 QwtPlot 管理
QwtPlotItem 图元（曲线、标记、网格） attach() 后归 QwtPlot 所有
QwtScaleEngine 刻度计算引擎 通过 setAxisScaleEngine() 设置

组合模式。QwtPlot 不继承画布能力，它持有一个画布；不继承图元能力，它持有 N 个图元。想给图表加新东西，写一个新图元挂上去，不用动 QwtPlot 一行代码。

可绘项的层次 #

这是整个绘图半区的骨架。所有能画在 QwtPlot 上的东西，都继承 QwtPlotItem：

text
QwtPlotItem                     基类，定义 draw() / rtti() / boundingRect()
├── QwtPlotCurve                折线 / 散点 / 阶梯线
├── QwtPlotMarker               横线、竖线、单点、箭头，可带标签
├── QwtPlotGrid                 主次网格
├── QwtPlotHistogram            直方图
├── QwtPlotBarChart             柱状图（单组 / 多组）
├── QwtPlotMultiBarChart        分组柱状
├── QwtPlotIntervalCurve        区间带（误差棒、置信带）
├── QwtPlotTradingCurve         K 线 / OHLC
├── QwtPlotSpectroCurve         按数值上色的点
├── QwtPlotRasterItem           栅格基类
│   └── QwtPlotSpectrogram      二维场、热力图、等高线
├── QwtPlotShapeItem            任意 QPainterPath
├── QwtPlotVectorField          矢量场（风场、梯度）
├── QwtPlotZoneItem             竖条区间标记
├── QwtPlotSvgItem              SVG 图（需 QwtSvg）
└── QwtPlotTextLabel            贴在画布上的浮动文本

QwtPlotItem 不是 QObject。这一点要先记住：它不能进信号槽，不能 setParent()，也没有 deleteLater()。它在不在，只看 attach() 和 detach()。

attach() 改变所有权。挂上去之后 QwtPlot 拥有这个图元，QwtPlot 析构时会把它一起删掉。所以别这么写：

cpp
QwtPlotCurve curve;      // 栈对象
curve.attach(plot);      // 所有权交出去了，但对象还在栈上
// 函数返回时 curve 析构，plot 手里留着一个野指针

要么 new 出来挂上不管，要么 detach() 拿回所有权再自己删。detach() 之后 QwtPlot 不再管它。

rtti() 给每个子类一个枚举值（QwtPlotItem::Rtti_PlotCurve、Rtti_PlotGrid…），遍历 plot->itemList() 时按这个分流，比自己写 dynamic_cast 干净。

可绘项一览 #

类 画什么 关键接口
QwtPlotCurve 折线、散点、阶梯线 setSamples()、setStyle()、setPen()、setSymbol()、setCurveAttribute()
QwtPlotMarker 横线、竖线、单点、带标签的标记 setLineStyle()、setValue()、setLabel()
QwtPlotGrid 网格 setMajorPen()、setMinorPen()、enableX()、enableY()
QwtPlotHistogram 直方图，每根柱有独立区间和高度 setSamples(QwtIntervalSample…)、setBrush()
QwtPlotBarChart 柱状图，带类目标签 setSamples()、setBarTitle()、setLegendMode()
QwtPlotMultiBarChart 分组柱状，一组多个系列 setSamples()、setBarTitles()
QwtPlotSpectrogram 二维标量场、热力图、等高线 setData(QwtRasterData*)、setColorMap()
QwtPlotSpectroCurve 按数值上色的散点 setColorRange()、setColorMap()、setPenWidth()
QwtPlotIntervalCurve 区间带 setSamples(QwtIntervalSample…)
QwtPlotTradingCurve K 线 setSamples(QwtOHLCSample…)、setSymbolStyle()
QwtPlotShapeItem 任意路径形状 setShape()、setPen()、setBrush()
QwtPlotVectorField 矢量场 setSamples()、setSymbol()、setMagnitudeScaleFactor()
QwtPlotZoneItem 一段竖直区间高亮 setInterval()、setOrientation()
QwtPlotSvgItem 把 SVG 贴进坐标系 loadFile()

这套图元覆盖的范围，比很多人以为的宽。QwtPlotSpectrogram 能直接画热力图和等高线，QwtPlotVectorField 能画流场，QwtPlotTradingCurve 是给金融做的。真到要画这些的时候，不用自己写 paintEvent。

渲染流程 #

replot() 是唯一的更新入口。它内部干的事：

text
replot()
  ├── updateAxes()                重算四条轴的 QwtScaleDiv
  ├── 图元的缓存标记失效
  ├── canvas->invalidateBackingStore()
  └── 触发 QwtPlotCanvas::paintEvent()
        └── 遍历已 attach 的图元
              └── item->draw(painter, xMap, yMap, canvasRect)

updateAxes() 只算刻度，不落笔。真正画发生在 QwtPlotCanvas::paintEvent 里，按 z() 值从低到高，逐个调图元的 draw()。每个图元拿到的 xMap、yMap 是 QwtScaleMap，负责把数据坐标换成像素坐标。

这条链路解释了那个最常见的现象：数据全填对了，屏幕上还是白的——内存里的状态没问题，缺的是发起这次 paintEvent 的那一下 replot()。也解释了为什么高频刷新要去掉它：整条链路每帧跑一遍，十万点就是十万点乘以一次坐标变换，帧率直接崩。高频场景走 QwtPlotDirectPainter，只画新进来那一段，不碰整块画布，细节在《Qwt 曲线与坐标轴》。

一个能跑的骨架 #

cpp
#include <qwt_plot.h>
#include <qwt_plot_curve.h>
#include <qwt_plot_grid.h>
#include <qwt_legend.h>

class SensorPlot : public QwtPlot {
public:
    explicit SensorPlot(QWidget *parent = nullptr) : QwtPlot(parent) {
        setTitle("传感器实时监控");
        setCanvasBackground(Qt::white);

        setAxisTitle(QwtPlot::xBottom, "时间 (s)");
        setAxisTitle(QwtPlot::yLeft, "温度 (°C)");
        setAxisScale(QwtPlot::xBottom, 0.0, 100.0);   // 第三个参数是步长，省了就让引擎自己算
        setAxisAutoScale(QwtPlot::yLeft);

        auto *grid = new QwtPlotGrid();
        grid->setMajorPen(Qt::gray, 0, Qt::DotLine);
        grid->attach(this);

        insertLegend(new QwtLegend(), QwtPlot::RightLegend);
    }

    void addCurve(const QVector<double> &x, const QVector<double> &y) {
        auto *curve = new QwtPlotCurve("温度传感器 A");
        curve->setPen(Qt::red, 2);
        curve->setRenderHint(QwtPlotItem::RenderAntialiased, true);

        curve->setSamples(x, y);   // 拷贝一份，调用后 x/y 可以随便改
        curve->attach(this);
    }
};

setAxisScale(axis, min, max, step) 的第四个参数是主刻度步长，不是「刻度个数」。写成 0, 10, 1 意思是每 1 一格，不是分 1 格。忘了这个参数，QwtScaleEngine 会按画布尺寸自己挑一个看着顺眼的步长。

交互设施 #

缩放、平移、滚轮放大不用自己接鼠标事件：QwtPicker 是采集层，QwtPlotZoomer、QwtPlotPanner、QwtPlotMagnifier 是三个成品，都装在 plot->canvas() 上。

cpp
auto *zoomer = new QwtPlotZoomer(plot->canvas());
zoomer->setMousePattern(QwtEventPattern::MouseSelect2, Qt::RightButton, Qt::ControlModifier);
zoomer->setRubberBand(QwtPicker::RectRubberBand);
zoomer->setZoomBase(true);              // 当前视图记为缩放栈第 0 层

auto *panner = new QwtPlotPanner(plot->canvas());
panner->setMouseButton(Qt::MiddleButton);

auto *magnifier = new QwtPlotMagnifier(plot->canvas());
magnifier->setWheelFactor(1.1);         // 滚轮每格 10%

装错对象的表现是：鼠标在轴区域有反应，在画布上没反应。setZoomBase(true) 也别忘，不调它，缩放栈的基准是当前坐标范围，用户缩进去就退不回原始视图。

四、仪表盘与刻度盘 #

从这里开始进入控件半区。第一个是 QwtDial，圆形刻度盘，仪表盘家族的老祖宗。

QwtDial 继承 QwtAbstractSlider，也继承 QwtAbstractScale，所以它先天带着「量程」「刻度」「值」三件套。它多了两样东西：一个可扫过任意角度的刻度弧，一根指针。

理解 QwtDial 只需要四个参数：

参数 接口 说明
量程 setRange(min, max) 刻度覆盖的数值范围
刻度弧 setScaleArc(start, end) 单位是度，0 度指向正上方，正值顺时针
值 setValue(double) 指针位置
模式 setMode() RotateNeedle 转指针，RotateScale 转刻度盘

默认刻度弧是 -135 到 135，扫过 270 度，留出下方 90 度的缺口。想做成半圆表就写 -90, 90，想做成近乎整圆就写 -170, 170。

cpp
#include <qwt_dial.h>
#include <qwt_dial_needle.h>

auto *dial = new QwtDial(this);
dial->setRange(0.0, 100.0);
dial->setScaleArc(-120.0, 120.0);     // 扫过 240 度
dial->setValue(62.0);
dial->setWrapping(false);             // 到顶不绕回 0
dial->setMode(QwtDial::RotateNeedle);
dial->setNeedle(new QwtDialSimpleNeedle(QwtDialSimpleNeedle::Arrow,
                                        true,        // 带中心圆点
                                        Qt::black,   // 指针颜色
                                        Qt::gray));  // 中心颜色
dial->setScaleMaxMajor(10);           // 主刻度最多 10 个
dial->setScaleMaxMinor(5);            // 每个主刻度之间再分 5 格

connect(dial, &QwtDial::valueChanged, this, &Widget::onDialMoved);

setWrapping() 决定指针到了最大值之后是停住还是绕回最小值。温度、压力这类量必须停住，写成 false；罗盘方位角这种循环量才用 true。

setMode() 的两种模式视觉差别不小：RotateNeedle 是盘面固定、指针转，符合大部分人对仪表盘的印象；RotateScale 是指针固定朝上、整个刻度盘转，老式罗盘和某些车载仪表用这个。

仪表盘不是拿来读数的 #

新手常犯的错：把仪表盘当数字显示用，指望用户读出「62.3」。圆形刻度盘能给的精度就是一两格，要精确读数就在旁边配 QLabel 或 QDoubleSpinBox，表盘看趋势，数字看准确值。

工业界面的通行做法是「三件套」：表盘给整体感受，数字给精确值，告警区给状态。QwtDial 只管第一件。

告警区和色带 #

QwtDial 没有「告警区」这个概念，QwtThermo 才有（setAlarmLevel()）。要在表盘上标红区，重写 drawScaleContents() 自己画扇形最省事。刻度线和标签的颜色、字体走 QwtDialScaleDraw。

五、滑块、旋钮与刻度条 #

控件半区的全貌先摆一张表。除了表盘，剩下的都是「长得像普通控件」的那批，不需要理解角度。

控件类 外形 基类 值怎么给 用途
QwtDial 圆盘 + 指针 QwtAbstractSlider setValue() 温度、压力、占空比
QwtCompass 罗盘 + 磁针 QwtDial setValue()，0~360 航向、方位
QwtSpeedoMeter 转速表 QwtDial setValue() 转速、速度
QwtAnalogClock 三针时钟 QwtDial setTime() 时间显示、装饰
QwtSlider 带刻度的滑块 QwtAbstractSlider setValue() 参数调节
QwtWheel 圆柱滚轮 QwtAbstractSlider setValue() 连续微调
QwtKnob 旋钮 QwtAbstractScale setValue() 面板上排一排参数
QwtThermo 温度计柱 QwtAbstractScale setValue() 液位、温度、压力
QwtScaleWidget 刻度尺 QWidget setScaleDiv() 纯刻度显示

QwtSlider：带刻度的滑块 #

标准 QSlider 只有一根槽和一个把手，没有刻度，不能显示当前值。QwtSlider 把这些补上了。

属性 接口 说明
方向 构造参数 Qt::Horizontal / Qt::Vertical 建的时候定
刻度位置 setScalePosition() NoScale、BelowScale、BesideScale、TrailingScale
把手尺寸 setHandleSize(const QSize&) 默认按字体算
边距 setBorderWidth() 槽到控件边缘的留白
间距 setSpacing() 槽和刻度之间的间距
步长 setStep()、setPageStep() 方向键 / PageUp 的步进 
cpp
auto *slider = new QwtSlider(this, Qt::Horizontal);
slider->setRange(0.0, 100.0);
slider->setValue(35.0);
slider->setScalePosition(QwtSlider::BelowScale);
slider->setHandleSize(QSize(16, 20));
slider->setStep(1.0);
slider->setPageStep(10.0);

setScalePosition() 是最常用的一个。默认不带刻度，很多人抱怨「QwtSlider 跟 QSlider 长得一样」，就是没设这个。

QwtKnob：旋钮 #

旋钮在实机上比滑块省地方，面板上排一排很好看。QwtKnob 继承 QwtAbstractScale，不是 QwtAbstractSlider——它能显示值、能转、能改，但没有 QwtAbstractSlider 那套键盘和滚轮逻辑。

属性 接口 说明
总转角 setTotalAngle(double) 默认 90 度，常见 270
旋钮宽度 setKnobWidth(int) 0 表示按字体自动算
样式 setKnobStyle() Sunken、Raised、Flat
中心符号 setSymbol(QwtSymbol*) 中间那个小点或小横线
边框 setBorderWidth() 
cpp
auto *knob = new QwtKnob(this);
knob->setRange(0.0, 11.0);            // 音量那味儿
knob->setValue(7.0);
knob->setTotalAngle(270.0);
knob->setKnobWidth(60);
knob->setKnobStyle(QwtKnob::Raised);
knob->setSymbol(new QwtSymbol(QwtSymbol::Ellipse,
                              QBrush(Qt::NoBrush), QPen(Qt::black, 2), QSize(6, 6)));

setSymbol() 值得单独说。不设它，旋钮就是一个光疙瘩，用户不知道当前转到哪。设一个小圆点或者小横线，位置就清楚了。

QwtWheel：滚轮 #

滚轮适合「连续微调」的场合：时间轴、频率、倍率。它长得像一个竖着的圆柱，用鼠标拖或者滚轮键滚。

cpp
auto *wheel = new QwtWheel(this);
wheel->setOrientation(Qt::Horizontal);
wheel->setRange(1.0, 1000.0);
wheel->setValue(100.0);
wheel->setWheelWidth(30);
wheel->setTotalAngle(175.0);   // 圆柱面张开的角度
wheel->setMass(0.5);           // 惯性，拖完松手会滑一下

setMass() 是个物理量，控制拖动松手后的滑行距离。设 0 就立刻停。这个手感细节，标准 QSlider 是没有的。

QwtThermo：温度计 #

一根柱子，填补区域随值变化。液柱方向、刻度位置、填充色都能改，还带告警阈值。

属性 接口 说明
方向 setOrientation() 竖直 / 水平
刻度位置 setScalePosition() NoScale、LeadingScale、TrailingScale
柱宽 setPipeWidth(int)
填充 setFillBrush(const QBrush&)
告警阈值 setAlarmLevel(double) 超过这个值换色
告警色 setAlarmBrush()、setAlarmEnabled(bool) 
cpp
auto *thermo = new QwtThermo(this);
thermo->setOrientation(Qt::Vertical);
thermo->setScalePosition(QwtThermo::TrailingScale);
thermo->setRange(0.0, 120.0);
thermo->setValue(85.0);
thermo->setPipeWidth(16);
thermo->setFillBrush(QBrush(Qt::darkCyan));
thermo->setAlarmLevel(95.0);
thermo->setAlarmBrush(QBrush(Qt::red));
thermo->setAlarmEnabled(true);

告警这一套是 QwtThermo 独有的，表盘和滑块都没有。做液位、温度、压力这类有硬上限的量，它比表盘省事。

QwtScaleWidget：独立刻度条 #

QwtPlot 里那四条轴，独立出来就是 QwtScaleWidget。它是个纯显示控件，不带值、不带交互，就是一根带刻度的尺子。

cpp
#include <qwt_scale_widget.h>

auto *scale = new QwtScaleWidget(QwtScaleDraw::BottomScale, this);
QwtScaleDiv div(0.0, 100.0, QList<double>() << 0.0 << 60.0 << 100.0);   // 主刻度
div.setTicks(QwtScaleDiv::MediumTick, QList<double>() << 20.0 << 40.0 << 80.0);
div.setTicks(QwtScaleDiv::MinorTick, QList<double>() << 10.0 << 30.0 << 50.0 << 70.0 << 90.0);
scale->setScaleDiv(div);
scale->setTitle(QwtText("湿度 (%)"));

它的价值在于「跟 QwtPlot 共用一套刻度绘制代码」。你把一个 QwtScaleWidget 摆在 QwtPlot 旁边，刻度线宽、字体、标签格式自动一致，不用手工对齐。

六、QwtDial 家族 #

QwtDial 不是孤零零一个类，它下面还有三个变体。这一族的关系值得单独画一遍，因为官方文档里它们分散在五六个头文件里。

text
QwtAbstractScale : QWidget
├── QwtAbstractSlider
│   ├── QwtSlider
│   ├── QwtWheel
│   └── QwtDial
│       ├── QwtCompass
│       ├── QwtSpeedoMeter
│       └── QwtAnalogClock
├── QwtKnob
└── QwtThermo

这棵树说明三件事。

QwtSlider、QwtWheel、QwtDial 是兄弟，共享 QwtAbstractSlider 的拖动、键盘、滚轮逻辑，setStep()、setPageStep()、setReadOnly() 对三者通用。

QwtKnob 和 QwtThermo 挂在 QwtAbstractScale 下，不经过 QwtAbstractSlider：有量程、有刻度、能显示值，但没有完整的输入逻辑。QwtKnob 能拖是它自己重写了鼠标事件，不是靠继承。

三个变体 #

类 外形 独有接口 用途
QwtDial 圆盘 + 指针 setScaleArc()、setMode()、setWrapping()、setNeedle() 温度、压力、占空比
QwtCompass 罗盘玫瑰 + 磁针 setRose()、setNeedle()、setValue() 走方位角 航向、方位、天线指向
QwtSpeedoMeter 转速表，刻度弧不对称 刻度按转速特性排布 转速、速度
QwtAnalogClock 三针时钟 setTime(const QTime&)、setHand() 时间显示、界面装饰

QwtCompass 的用法跟 QwtDial 几乎一样，区别在于它默认带一圈罗盘玫瑰（QwtCompassRose），指针换成磁针。它的值域习惯写成 0 到 360，指北为 0，顺时针增加。

cpp
#include <qwt_compass.h>
#include <qwt_compass_rose.h>

auto *compass = new QwtCompass(this);
compass->setRange(0.0, 360.0);
compass->setValue(45.0);
compass->setWrapping(true);            // 方位角是循环量
compass->setRose(new QwtSimpleCompassRose(4, 1));   // 4 个主方向，1 层细纹

QwtAnalogClock 是这一族里最不像「控件」的一个。它不上报值，只显示时间，靠 setTime() 单向下发，当装饰用可以，当时间显示器不如直接 QLabel。

cpp
#include <qwt_analog_clock.h>

auto *clock = new QwtAnalogClock(this);
clock->setTime(QTime::currentTime());
// 之后每次 update 前再调一次 setTime()

针的体系 #

指针不是一根画死的线，是独立的对象，可替换。这一层设计让 QwtDial 的观感能换而不动逻辑。

text
QwtDialNeedle                     抽象基类，draw() + setPen()/setBrush()
├── QwtDialSimpleNeedle           箭头 / 射线
├── QwtCompassMagnetNeedle        双色磁针（Thin / Triangle 两种样式）
└── QwtCompassWindArrow           风向箭头（Style1 / Style2）

cpp
// 换一根细长的射线指针，不带中心点
dial->setNeedle(new QwtDialSimpleNeedle(QwtDialSimpleNeedle::Ray, false, Qt::darkBlue));

// 换磁针
compass->setNeedle(new QwtCompassMagnetNeedle(QwtCompassMagnetNeedle::TriangleStyle,
                                              Qt::white, Qt::red));

setNeedle() 会接管所有权，旧针自动删。你换的时候不用管上一根。

子类化：自定义表盘 #

官方给的接口够用的时候，设属性就行。要在盘面上加东西（单位文字、告警扇区、刻度数字换格式），继承 QwtDial 重写虚函数。

cpp
class Tachometer : public QwtDial {
public:
    explicit Tachometer(QWidget *parent = nullptr) : QwtDial(parent) {
        setRange(0.0, 8000.0);
        setScaleArc(-140.0, 140.0);
        setScaleMaxMajor(8);
        setScaleMaxMinor(4);
        setWrapping(false);
        setReadOnly(true);                  // 纯显示，不接受拖动
        setNeedle(new QwtDialSimpleNeedle(QwtDialSimpleNeedle::Arrow, true, Qt::black));
    }

protected:
    // 画盘面正中的附加内容：单位、档位提示
    void drawScaleContents(QPainter *painter, const QPointF &center, double radius) const override {
        Q_UNUSED(radius);
        painter->save();
        painter->setPen(QPen(Qt::darkGray));
        QFont f = painter->font();
        f.setPointSizeF(f.pointSizeF() * 0.9);
        painter->setFont(f);
        painter->drawText(QRectF(center.x() - 40, center.y() + 10, 80, 20),
                          Qt::AlignCenter, "r/min");
        painter->restore();
    }
};

drawScaleContents() 的坐标系原点已经平移到表盘中心，center 就是圆心，radius 是半径。在这个函数里画东西，跟着刻度弧一起转（RotateScale 模式下）。

需要改刻度本身的画法，走另一条路：替换 QwtDialScaleDraw，重写 label()，跟 QwtPlot 上换 QwtScaleDraw 是一个套路。

七、控件类与绘图类的分界 #

两个半区看着不搭界，底下其实共用一套刻度内核。这一章把共用部分挖出来，因为它决定了你学一边能不能推到另一边。

共用的内核 #

四件东西，绘图和控件都用：

类 干什么 谁在用
QwtScaleMap 数据坐标 ↔ 像素坐标的线性映射 QwtPlot 给每个图元发两个；QwtAbstractScale 内部有一个
QwtScaleDiv 一组刻度值，分主 / 中 / 次三档 轴、表盘、滑块、独立刻度条
QwtScaleEngine 根据范围算出一份 QwtScaleDiv 轴和所有刻度控件
QwtAbstractScaleDraw 把 QwtScaleDiv 画成线和标签 轴、表盘、刻度条

QwtScaleEngine 有几个现成的派生：QwtLinearScaleEngine（默认）、QwtLogScaleEngine（对数）、QwtLog10ScaleEngine。

cpp
plot->setAxisScaleEngine(QwtPlot::yLeft, new QwtLogScaleEngine(10));   // 绘图：左轴换成以 10 为底的对数
knob->setScaleEngine(new QwtLogScaleEngine(10));                       // 控件：旋钮刻度换成对数

setScaleEngine() 会接管所有权，旧引擎自动删。对数引擎要求范围全为正数，喂进去 0 或负数，QwtScaleDiv 会算出一堆无效刻度，控件画成一团乱麻，QwtPlot 那条路则直接崩。

分界在哪 #

维度 绘图半区 控件半区
基类 QwtPlot（QFrame）、QwtPlotItem（无 QObject） QwtAbstractScale（QWidget）
进界面的方式 item->attach(plot) 加进 layout，跟按钮一样
数据的粒度 一批：setSamples()、setData() 一个：setValue()
触发重绘 replot() 整块 update() 自己那一块
缩放平移 要装 QwtPlotZoomer / QwtPlotPanner / QwtPlotMagnifier 内置，鼠标拖就转
鼠标事件 交给 QwtPicker 体系 自己重写 mousePressEvent() 之类
一个窗口里几个 一个 十来个
值变了怎么通知 没有信号，图元不是 QObject valueChanged(double) 信号

最后一行是使用体感上最大的差别：表盘转了能 connect，曲线上的点移了没有信号，你得自己在数据源头做通知。

这个分界为什么重要 #

找类的时候不迷路。要「显示一个数」，去控件半区找 QwtAbstractScale 的派生；要「显示一组数」，去绘图半区找 QwtPlotItem 的派生。annotated.html 那一长串按这个二分扫一眼就分完了。

混用不打架。一个窗口里左边一块 QwtPlot 画温度曲线，右边一排 QwtThermo 显示当前值，上面一个 QwtDial 显示压力——四个独立对象，各自 new、各自进布局，没有任何绑定关系。想让表盘跟着曲线的最后一个点走，自己 connect 数据源，两边都 setValue() / replot()。

学一边能推另一边。刻度引擎、刻度绘制、坐标映射是共用的，会了 setAxisScaleEngine()，knob->setScaleEngine() 不用重新学。

八、Qwt 的设计取向 #

用了几天之后能感觉到，这个库的每个决定都指向同一个方向：可预测、可裁剪、不替你审美。挑几条影响使用方式的。

组合优先，继承靠后 #

QwtPlot 不让你重写 paintEvent 来加东西，正道是写一个 QwtPlotItem 派生类，实现 draw()，然后 attach()。原因在渲染流程里：QwtPlotCanvas 按顺序遍历图元，每个图元自己算位置、自己画。你重写 QwtPlot::paintEvent，等于绕开整条链路，缩放、图例、坐标轴全得自己重做。

数据所有权写得很明确 #

setSamples(const QVector<double>&, const QVector<double>&) 拷贝，setRawSamples(const double*, const double*, int) 不拷贝只记指针。拷贝版安全、慢一点；裸指针版快、责任在你。setData(QwtRasterData*) 那类接口是第三套语义——接管对象所有权，QwtPlotSpectrogram 析构时会删掉你传进去的 QwtRasterData。三种并存，用之前先看文档里 \sa 那段的所有权说明。

绘制统一走 QwtPainter #

所有落笔的地方都不直接调 QPainter::drawLine()，而是走 QwtPainter 的静态函数。这层薄封装的价值在切后端：屏幕、打印、SVG 导出、QwtPlotDirectPainter 增量绘制，同一份代码跑在不同设备上。副作用是断点容易断在 QwtPainter 里，看不出哪个图元画的，往上翻一层调用栈。

文本不是 QString #

标签、标题、图例文字都是 QwtText，不是 QString。QwtText 多带字体、颜色、边框、旋转角度、以及「文本引擎」这个维度。

文本引擎在 textengines/ 目录里：打开 QwtMathML 开关，QwtText 就能渲染 MathML 公式，不打开就是纯文本。这是 Qwt 里唯一一块「排版」能力。

事件模式抽象成枚举 #

QwtEventPattern 把鼠标和键盘动作抽象成 MouseSelect1 到 MouseSelect6、KeySelect1 到 KeySelect6 这样的槽位。控件只认槽位，不认具体按键。

cpp
zoomer->setMousePattern(QwtEventPattern::MouseSelect2, Qt::RightButton, Qt::ControlModifier);

好处是换键位不用改事件处理代码，只改映射。QwtPicker 那一套（QwtPlotPicker、QwtPlotZoomer、QwtPlotPanner、QwtPlotMagnifier）全建立在这个抽象上。

刻意不做的事 #

没有动画，没有过渡效果，没有内置主题，没有 CSS 美化钩子。颜色、字体、线宽全部自己去 setPen()、setPalette()、setFont()，想要一套深色主题就封装几个函数把二十个属性刷一遍。

这个取向没打算藏：官方截图页上的图全是白底黑字灰网格，能直接进论文和测试报告。要「炫」的东西，这个库不提供，也不打算提供。

许可与维护 #

许可不是 GPL，是自家的 Qwt License 1.0，以 LGPL 为底本加了几条例外。对闭源程序来说，这条路比 Qt Charts 的「GPL 或买商业授权」好走。

维护上，主笔是 Uwe Rathmann，Josef Wilgen 是 Qwt 0.2 之前的作者。develop 分支要求 Qt 5.6+ 和 C++11，6.x 各分支继续支持 Qt 4.8 以上。版本节奏不快，一两年一版，但分支支持得久——6.1 到现在还有人在用。multiaxes 分支从 develop 派生，做多 Y 轴，这个需求喊了很多年一直没并进主干，要一条轴叠三四条 Y 轴只能自己拉分支编。

九、什么时候该用 Qwt #

判断依据按重要性排：先看要不要那批控件，再看数据量，再看许可，最后看你能不能接受它的长相。四项都能接受，这个库就适合你。

需求 结论
工控、医疗、仪表面板，要表盘 / 旋钮 / 温度计 用，这些控件别处没有
示波器式实时曲线，十万点级 用，配 QwtPlotDirectPainter
频谱图、热力图、等高线 用，QwtPlotSpectrogram 现成
多子图、多轴、对数轴混排 用，QwtPlotLayout 和四条轴撑得住
曲线要能框选缩放、游标取值 用，QwtPlotZoomer / QwtPicker 配好了
需要在 Designer 里拖控件摆界面 用，打开 QwtDesigner 开关
商业报表、月度柱状图、饼图 不用，Qt Charts 更省事
大屏可视化、要动画、要主题皮肤 不用，Qwt 不做这些
Qt Quick / QML 界面 不用，Qwt 是 Widgets 库
只要导出一张静态图 不用，QPainter 直接画更短

三个具体场景 #

工业面板。1024×768 的屏，左上角两个表盘，右上角一条温度计柱，下面一条曲线，右边一排旋钮。这些控件全现成，两天能出原型。

实时曲线。每秒几百个点，滚动显示最近十分钟。setRawSamples() 零拷贝、setAutoReplot(false) 关自动刷新、QwtPlotDirectPainter 只画增量段，这套组合能撑到几十万点不卡。细节在《Qwt 曲线与坐标轴》。

测试报告出图。跑完实验生成 PDF，里面嵌十几张曲线图。QwtPlot 能直接渲染到 QPrinter 或 QSvgGenerator，同一份绘制代码，屏幕和图稿一致。

用它的成本 #

编译一次性成本最高：没有官方二进制包，Windows 上必须自己编，第一次踩坑能耗掉半天。外观是默认白底黑线灰网格，要好看得自己刷二十来个属性，库没有主题机制。文档由 Doxygen 生成，接口说明齐全，「怎么组合起来用」主要靠 examples/，教程数量远不如 Qt Charts。

维护与支持渠道 #

邮件列表是官方推荐的第一渠道，所有 Qwt 相关问题都往那扔；第二是 Qt Centre 论坛的 Qwt 子版块。官方还留了个人支持邮箱，但话说得直白：没有正当理由就不用公开渠道、直接发邮件过去，会被静默忽略。

Python 那边有个 PyQt-Qwt，是 Qwt 的 PyQt 包装，只用 Python 的话可以走这条路，省掉 C++ 编译。源码包从 SourceForge 的项目页取，也能从 git 仓库拉；版本变更摘要单独一页，升级前扫一眼。

官方截图页把能力分了五类，看它怎么分类比看类名快：曲线图、频谱图与等高线、柱状图与直方图、其他图表、表盘罗盘旋钮滚轮滑块温度计。前四类是绘图半区，第五类是控件半区。这个分法跟本篇的二分完全对得上。

十、Qwt 与 QtCharts 的分工 #

这两个库经常被摆在一起比，但它们解决的不是同一类问题。

特性 Qwt Qt Charts
许可 Qwt License 1.0，LGPL 底本加例外，闭源友好 GPLv3 / 商业许可
定位 科学绘图、工业控制 商业报表、金融 K 线
曲线样式 折线、散点、阶梯、样条（setCurveAttribute(Fitted)） 折线、样条
数据规模 十万点级，有 OpenGL 后端和增量绘制 万点级开始吃力
轴体系 四条轴，每轴独立的 QwtScaleEngine 和 QwtScaleDraw 轴对象，定制面窄
交互 QwtPlotZoomer / QwtPlotPanner / QwtPlotMagnifier 三行配完 自己写事件
附带控件 表盘、旋钮、滑块、温度计、滚轮 无
集成 要编译安装，配 .pro 或 CMake Qt 自带，QT += charts
外观 朴素，能黑白打印 默认观感好，有主题
动画 无 有
文档与示例 Doxygen + examples/，教程少 官方文档全，示例多
版本节奏 一两年一版，老分支支持久 跟 Qt 版本走

三段筛 #

第一筛，许可。 软件闭源，Qwt 能直接上；Qt Charts 要么 GPL（整个程序跟着 GPL），要么买商业授权。这一条能筛掉一半的选择困难。

第二筛，要不要那批控件。 需要表盘、旋钮、温度计，只有 Qwt 有现成的。Qt Charts 一个都没有。

第三筛，数据量和轴的需求。 十万点实时流、四条轴各配各的引擎、对数轴混排，Qwt 的结构天生支持。Qt Charts 也能做，但要绕。

三筛过完还没定，说明需求不硬，挑你团队熟的。许可、控件、数据量三条里任何一条卡住，答案就已经出来了。

别混着用 #

一个窗口里左边 QwtPlot 右边 QChart，技术上能跑，许可上各按各的协议也不算冲突。但整个软件闭源的话，带 Qt Charts 那一半就把整体拉回 GPL 了——要么全 Qwt，要么买授权。外观上也会割裂：Qwt 的曲线是 1px 实线加方块标记，Qt Charts 默认带渐变和圆角，放一起像两个软件拼的。

十一、源码结构导读 #

目录 #

text
qwt-6.3.0/
├── src/            全部 C++ 实现，平铺，一个类一对 .h/.cpp
├── classincludes/  每个类一个转发头，方便 #include <QwtPlot>
├── designer/       Qt Designer 插件工程
├── examples/       官方示例，很多控件用法只在这里有
├── playground/     实验性代码，不参与构建
├── textengines/    文本引擎（MathML 等）
└── doc/            Doxygen 配置

src/ 是平的，没有子目录，找类靠文件名前缀，前缀表在第二章。

classincludes/ 这层容易被忽略。写 #include <QwtPlot> 能成，靠的是这里每个类一个只转发一行的头文件；直接写 #include <qwt_plot.h> 也行，类名大小写敏感。

examples/ 是重点。Doxygen 只讲单个类的接口，怎么把 QwtDial 和 QwtSlider 摆一块、QwtPlot 怎么嵌进 QSplitter、QwtPicker 怎么自定义显示，全在示例里。装库时一定带 examples，Linux 发行版的二进制包常常把它裁掉。

类文件的固定套路 #

每个类的头文件长一个样：先 #include <qwt_global.h> 拿 QWT_EXPORT，再 class QWT_EXPORT QwtPlotCurve : public QwtPlotItem，然后构造函数、setXxx() 设置接口、xxx() const 查询接口，最后是 draw()、rtti()、boundingRect() 这几个虚函数重写。

QWT_EXPORT 在动态库模式下展开成 __declspec(dllexport/dllimport) 或 visibility 属性。自己写派生类不用加这个宏，只有要塞进 Qwt 库本身才需要。

最短的可用工程 #

.pro 里三行：

greaterThan(QT_MAJOR_VERSION, 4) {
    QT += printsupport
    QT += concurrent
}
QT += qwt

INCLUDEPATH += /path/to/qwt-6.3.0/src
LIBS += -L/path/to/qwt-6.3.0/lib -lqwt

代码骨架，从对象声明到出图：

cpp
#include <qwt_plot.h>
#include <qwt_plot_curve.h>
#include <QVector>

class Widget : public QWidget {
    Q_OBJECT
public:
    explicit Widget(QWidget *parent = nullptr);
private:
    QwtPlot *plot;
    QwtPlotCurve *curve1;
    QVector<double> xData1, yData1;
};

Widget::Widget(QWidget *parent) : QWidget(parent) {
    plot = new QwtPlot(this);
    plot->setObjectName(QString("qwtPlot"));
    plot->setGeometry(QRect(10, 10, 531, 261));

    plot->setAxisScale(QwtPlot::yLeft, 0.0, 100.0, 10.0);   // 0~100，每 10 一格
    plot->setAxisScale(QwtPlot::xBottom, 0.0, 10.0, 1.0);   // 0~10，每 1 一格
    plot->setAxisTitle(QwtPlot::xBottom, tr("时间"));

    curve1 = new QwtPlotCurve;
    curve1->setPen(Qt::red, 0.5);
    curve1->attach(plot);
    curve1->setVisible(true);

    for (int i = 0; i < 100; ++i) {
        xData1.push_back(i);
        yData1.push_back(i * i);
    }

    curve1->setSamples(xData1, yData1);
    xData1.clear();              // setSamples 拷贝过，清空不影响曲线
    yData1.clear();

    plot->replot();
}

setAxisScale() 的第四个参数是主刻度步长，不是刻度个数。素材里源码注释那句「设置底部的个数」是错的，照它理解调出来的轴会跟预期差很远。

setGeometry() 是绝对定位的写法。用布局的话，plot 加进 QVBoxLayout 就行，不用算矩形。

读源码的路线 #

想改 Qwt 的行为，按这个顺序读，别一上来就翻 qwt_plot_canvas.cpp：

概念误区 #

一是以为 Qwt 只有一个 QwtPlot。 控件半区那六七个类跟绘图半区分量相当，只画曲线的人用不上，不等于不存在。二是以为 QwtPlotItem 是 QObject。 不是。没有信号，不能 setParent()，生命周期由 attach() / detach() 决定；在栈上建图元再 attach()，会让 QwtPlot 析构时对着一个已销毁的对象调 delete。

三是以为 setSamples() 和 setRawSamples() 等价。 一个拷贝一个不拷贝。用裸指针版，源数组在曲线存活期间被 clear() 或者出了作用域，画出来就是垃圾数据或者直接崩。四是以为版本号越新越好。 项目还停在 Qt 5.9 的话，6.1 也能用，没必要为了新版去升 Qt；反过来，Qt 6 项目只能用 6.2 以上。

Qwt 版本 Qt 5.x Qt 6.x 建议
6.1.x 支持 不支持 旧项目沿用
6.2.0 支持 部分支持 过渡版本
6.3.0 支持 支持 新项目用这个

到这里，Qwt 的两个半区、可绘项层次、设计取向和取舍逻辑都摆完了。下一步该动手了：把库编出来，画第一条曲线，再往界面上摆一个表盘。
