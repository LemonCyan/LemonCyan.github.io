本篇讲 Qt 里比 QPainter 高一层的那套东西：Graphics View Framework。它把「我要画什么」换成「场景里有哪些对象」，管理、命中、事件、局部重绘全交给框架。

  • 讲什么：场景、视图、图元三个角色；图元类型；怎么放进场景；三层坐标与映射；图元变换；碰撞与拾取；事件传播；选中拖动焦点；动画；性能开关；和 QPainter 的分工；易错点。
  • 不讲什么：QPainter 自身的画笔、画刷、变换、渲染提示，翻同目录两篇 QPainter；QCustomPlot、Qwt、QChart 的用法。
  • 跨篇指路：只想把东西画出来、不需要对象模型，看 QPainter 绘图基础；要手写命中测试又不建对象树，看 QPainter 绘图进阶；画统计图表去看 QChart、QCustomPlot、Qwt 那几篇；选型纠结先看选型篇。

一、Graphics View 解决什么问题 #

QPainter 是命令式的。每次 paintEvent() 进来，你把整幅图从头画一遍。窗口里有什么只有你脑子里有，代码跑完，对象就没了，屏幕上只剩像素。

这套模型在三种需求面前会崩，三件事都得你自己扛。第一是命中测试。用户点在 (x, y)，落在哪个图形上？QPainter 画完什么都没留，你只能自建一张形状表，手动遍历，自己算点在不在多边形里。图形一多，这段代码就是个小几何库。

第二是局部重绘。改一个图形的位置，你得重画整块区域，或者自己算脏矩形并集。算多了白画，算少了留残影。

第三是对象管理。z 序、父子关系、选中状态、可见性、透明度，全得自己用数组记。记完这些，你手里已经是一个简陋框架了，还带着 bug。

Graphics View 把这三件事做成基础设施。它的做法是基于图元，不是基于像素：你不描述「画什么」，你描述「场景里有哪些对象」。怎么画、要不要重画、谁先谁后、点中了谁，框架负责。

需求 拿 QPainter 手写 用 Graphics View
命中测试 自己存形状、自己遍历、自己算包含 scene->items(pos)、itemAt()，走索引
局部重绘 自己算脏矩形，或整块重画 item->update()，框架算暴露区域
对象属性 自建 struct 加数组，手动同步 图元自带 pos、rotation、scale、z、opacity
层级关系 自己排序、自己算累积变换 setParentItem()，子树自动跟随
事件分发 在 mousePressEvent 里写一长串 if 框架把事件送到对应图元
缩放平移 改 painter->scale() 再手动换算所有坐标 view->scale()，底层数据不动

框架内部用 BSP 树做空间索引。BSP 是 Binary Space Partitioning，二元空间分割，把场景递归切块，查「这一片有哪些图元」不用扫全表。官方文档的说法是能实时渲染包含数百万个图元的场景——这个数字有前提：图元自身绘制开销要小，场景结构要合理。

判断标准很好用。图形几十个、位置不变、不需要点选拖拽，QPainter 手画更省事。图形上百、要选中、要拖动、改属性后要自动重绘，换 Graphics View。数量大还要交互，没得选。

这里最容易走偏的一点 #

Graphics View 的世界是场景坐标系，不是屏幕像素。

图元有自己的局部坐标，场景有自己的逻辑坐标，视图才对应屏幕像素。你点一下鼠标，拿到的是视图坐标；要判断点中了谁，得先映射到场景坐标；图元内部画东西，用的是图元自己的局部坐标。三层坐标没理清，点击必偏，拖动必飘。

后面第五章专门拆这三层。先记住一句：任何一次交互，先想清楚「我现在这个坐标是哪一层的」。

二、三个角色：场景、视图、图元 #

框架由三个类撑起来，名字像，职责差得远。

text
   输入事件（鼠标 / 键盘 / 拖放）
            │
            ▼
   QGraphicsView    视图：QWidget 子类，负责显示，把视图坐标映射成场景坐标
            │  事件转换 + 坐标映射
            ▼
   QGraphicsScene   场景：图元容器 + 空间索引 + 事件分发，自身不可见
            │  命中测试，找到目标图元
            ▼
   QGraphicsItem    图元：自己画自己，自己收自己的事件，有自己的局部坐标
角色 类 一句话职责 代码里的形态
场景 QGraphicsScene 图元容器、空间索引、事件分发中心 自己 new，addItem() 往里塞
视图 QGraphicsView 观察场景的窗口，显示、缩放、坐标映射 QWidget 子类，能放进布局
图元 QGraphicsItem 场景里的基本单位，自己画自己 标准图元直接用，复杂的自己继承

这是改进版的 MVC。多出来的一层是「视图可以有多个」：一个场景能同时挂几个视图，各自缩放级别、可视区域互不相干。

2.1 场景 QGraphicsScene #

场景扮演模型（Model）。它本身不可见，不是 widget，没法放进布局。它管四件事：

  • 图元管理：维护所有图元的位置和状态，包括 z 序、选中集合、父子树。
  • 事件传播：把视图转来的事件分发给对应图元，处理传播和接受/忽略。
  • 图元查找：items()、itemAt()、collidingItems()，做碰撞和区域查询。
  • 渲染管理：自己不上屏，但提供 render() 把内容画到 QImage 或 QPrinter，导出和打印走这里。

场景还持有两样容易被忽略的东西：sceneRect 定义逻辑边界，滚动条范围由它决定；空间索引默认是 BSP 树，可以换成线性索引。

2.2 视图 QGraphicsView #

视图是观察场景的窗口，扮演 View。它是 QWidget 子类，能进布局、能继承、能吃样式表。它负责：

  • 可视化：显示场景可视区域，自带滚动条。
  • 交互接口：收键盘、鼠标、滚轮、拖放，把视图坐标转成场景坐标后交给场景。
  • 坐标变换：支持仿射变换，scale()、rotate()、translate() 都在这层。缩放平移只改观察角度，不改底层数据。
  • 渲染加速：setViewport() 换视口，挂 QOpenGLWidget 就走 GPU。

视图不拥有场景。view->setScene(scene) 之后场景的生命周期还是你自己管。一个场景挂多个视图，是做「总览图加局部放大」的常用手法。

2.3 图元 QGraphicsItem #

图元是场景里的基本图形单位。它不只有几何，还有逻辑状态：

  • 几何形状：boundingRect() 给边界矩形，shape() 给精确轮廓。前者做快速排除，后者做精确命中。
  • 交互处理：处理点击、拖拽、滚轮、悬停、键盘焦点、拖放。
  • 层级关系：支持父子嵌套，子图元的坐标和变换相对父图元。
  • 绘图实现：重写 paint() 画自己，函数里拿到的就是 QPainter。

QGraphicsItem 不是 QObject，没信号槽，不能 connect。要信号槽就继承 QGraphicsObject，它是 QObject 和 QGraphicsItem 的多重继承。

场景拥有图元。scene->addItem(item) 之后，场景析构时会 delete 掉所有图元。你自己再 delete，就是二次释放。

这块补一句：还有三个名字值得记住。QGraphicsWidget 既是图元又能参与 QGraphicsLayout 布局系统；QGraphicsLayout 有两个具体实现，线性布局和网格布局；QGraphicsProxyWidget 把普通 QWidget 包成图元塞进场景，嵌现有控件时用它。

三、图元的类型与继承体系 #

QGraphicsItem 是抽象基类，直接实例化没意义，paint() 和 boundingRect() 都是纯虚的。Qt 预制了一批标准图元，都直接或间接继承它：

text
QGraphicsItem（抽象基类）
├── Ellipse / Rect / Line / Polygon / Path   五个基本形状
├── Pixmap / SimpleText / Text               位图与文本
├── ItemGroup                                分组容器
├── Widget ── ProxyWidget                    widget 风格图元
└── QGraphicsObject                          QObject + QGraphicsItem
图元类 用途 关键点
QGraphicsEllipseItem 圆、椭圆、扇形、弧 构造函数吃「矩形 + 可选起止角度」
QGraphicsRectItem 矩形、圆角矩形 常用来做背景板、选框
QGraphicsLineItem 单条线段 折线要用 QGraphicsPathItem
QGraphicsPolygonItem 多边形 填充规则可设奇偶或环绕
QGraphicsPathItem 任意路径 曲线和复合形状的通用出口
QGraphicsPixmapItem 贴图 setTransformationMode() 控制缩放插值质量
QGraphicsSimpleTextItem 纯文本标签 字体、颜色靠 setFont() 和 setBrush()
QGraphicsTextItem 富文本 setTextInteractionFlags() 能让它可选中、可编辑
QGraphicsItemGroup 分组 会把成员坐标改成组内相对坐标，见 4.3

标准图元不够就自己继承。一个能画能点的图元最少两个函数：

cpp
class NodeItem : public QGraphicsItem
{
public:
    QRectF boundingRect() const override
    {
        const qreal pad = 1.5;   // 画笔宽 3，向外各扩一半，不扩边缘会留残影
        return QRectF(-20 - pad, -20 - pad, 40 + 2 * pad, 40 + 2 * pad);
    }

    void paint(QPainter *painter, const QStyleOptionGraphicsItem *, QWidget *) override
    {
        painter->setRenderHint(QPainter::Antialiasing, true);
        painter->setPen(QPen(Qt::darkCyan, 3));
        painter->setBrush(QColor(200, 240, 240));
        painter->drawEllipse(QPointF(0, 0), 20, 20);
    }
};

boundingRect() 有条硬规则：必须覆盖 paint() 画出的所有像素，包括画笔宽度的一半。画笔宽 3，边界就要外扩 1.5。漏掉这一圈，图元移动时边缘留下擦不掉的痕迹，看着像鬼影。反过来也不能乱大——边界虚胖会让重绘面积和脏矩形计算一起变粗。

形状变了要通知框架：在 boundingRect() 返回新值之前调 prepareGeometryChange()，改完再 update() 请求重绘。

忘了 prepareGeometryChange()，框架还拿旧边界做裁剪和索引，新画的部分被裁掉，碰撞检测也按旧形状算。

QGraphicsItem 和 QGraphicsObject 怎么选 #

对比项 QGraphicsItem QGraphicsObject
基类 只有图元 QObject + QGraphicsItem
信号槽 没有 有，能 connect
属性动画 不能直接 QPropertyAnimation 能，pos、rotation、scale、opacity 都是属性
内存开销 小 多一个 QObject 的开销
适用 数量大、静态、纯展示 要发信号、要做动画、要挂事件过滤

图元上千又不需要信号槽时，坚持用 QGraphicsItem。QObject 的元对象机制不是白给的。

四、把图元放进场景 #

最小一套东西不到二十行。先有场景，再有视图，视图挂上场景，图元塞进场景。

cpp
QGraphicsScene *scene = new QGraphicsScene(this);
scene->setSceneRect(0, 0, 800, 600);        // 逻辑边界，滚动条范围跟它走
QGraphicsView *view = new QGraphicsView(scene, this);
view->setRenderHint(QPainter::Antialiasing, true);

// 便捷函数返回新图元，所有权立刻归场景
QGraphicsRectItem *rect = scene->addRect(QRectF(0, 0, 120, 60));
rect->setPos(100, 80);                      // 场景坐标，不是视图坐标

// 手动 new 的必须先 addItem，否则不显示
auto *ell = new QGraphicsEllipseItem(QRectF(-40, -40, 80, 80));
ell->setPos(300, 200);
scene->addItem(ell);

sceneRect 建议显式设。不设的时候场景自动算所有图元的包围盒，图元一动包围盒就变，滚动条跟着跳。给个稳定的逻辑范围就老实了。

addXxx() 系列（addRect、addEllipse、addLine、addPolygon、addPath、addPixmap、addSimpleText、addText）省掉 new 加 add 两步。批量塞几百个图元时，每次 addItem() 都会触发索引重排，先 scene->setItemIndexMethod(QGraphicsScene::NoIndex)，塞完再改回来。

所有权三条，记牢：

写法 后果
addItem() 之后自己 delete item 场景里留野指针，下次渲染崩溃
图元还在场景里就 delete scene 正常，图元自动清掉
removeItem() 之后不 delete 内存泄漏，场景不再管它

要临时藏起来，用 setVisible(false)，别从场景里摘。

4.1 父子层级 #

父子关系靠 setParentItem() 建立，和 Qt 对象树是两套东西。

cpp
QGraphicsRectItem *parent = new QGraphicsRectItem(QRectF(0, 0, 200, 120));
parent->setPos(100, 100);
scene->addItem(parent);

QGraphicsEllipseItem *child = new QGraphicsEllipseItem(QRectF(-10, -10, 20, 20));
child->setParentItem(parent);   // 挂上之后不要再 addItem
child->setPos(20, 20);          // 相对父图元原点，不是场景坐标

父图元的变换作用到整棵子树：父转 30 度子跟着转，父隐藏子一起消失，父移动子的场景位置也变。

四条规矩：setParentItem() 之后图元自动归属父所在场景；删父图元会连子图元一起删；子图元始终画在父之上，ItemStacksBehindParent 能反过来；子图元的 boundingRect() 仍在自己的局部坐标里算。

4.2 分组 #

QGraphicsItemGroup 把多个图元打包成一个逻辑单元，统一选中、统一移动。

cpp
QGraphicsItemGroup *group = scene->createItemGroup(scene->selectedItems());
group->setFlag(QGraphicsItem::ItemIsMovable, true);
group->setFlag(QGraphicsItem::ItemIsSelectable, true);

scene->destroyItemGroup(group);   // 解散，成员坐标还原成场景坐标

createItemGroup() 会把成员坐标重算成组内相对坐标，视觉上不动。手动 addToGroup() 就得自己处理这层换算。

进组之后成员没法单独选中，组是一个整体。临时打包用组，长期固定结构用父子层级更省事。

4.3 z 序 #

谁画在上面由 zValue() 决定，默认 0，同值按插入顺序，后加的在上。setZValue(-1) 沉底，setZValue(10) 浮顶。

选中不会自动提升 z 值，想让选中项浮上来得自己接管。图元多了频繁改 z 有排序成本，静态场景一次设好。

五、三个坐标系与映射 #

这一章是本篇的核心。三层坐标理不清，点击和拖动一定错。

text
  图元坐标 ──mapToScene──► 场景坐标 ──mapToScene──► 视图坐标
  局部原点，paint() 在这里   逻辑世界原点，索引/碰撞靠它   窗口左上角，屏幕像素
  ◄───────────────────────  ◄────────────────────────
       mapFromScene                mapFromScene

  图元坐标 ──mapToParent──► 父图元坐标（子图元的直接参照系）
坐标系 原点 单位 谁在用 典型 API
图元坐标 图元自身局部原点 (0, 0) 逻辑单位 paint()、boundingRect()、shape() event->pos()
场景坐标 场景逻辑原点 (0, 0) 逻辑单位 索引、碰撞、图元绝对位置 scenePos()、mapToScene()
视图坐标 视图窗口左上角 屏幕像素 原始鼠标事件、滚轮、拖放 QMouseEvent::pos()
父图元坐标 父图元的局部原点 逻辑单位 父子之间换算 mapToParent()

5.1 图元坐标 #

基准是图元自己的原点 (0, 0)，也叫局部坐标系。

关键特性：图元在场景里怎么移动、旋转、缩放，paint() 里的坐标始终是这套局部坐标。你在 (0, 0) 画个圆，它永远画在自己中心附近，不会因为图元挪了位置就跑。同一段绘制代码，图元放到哪都对。

boundingRect() 和 shape() 的返回值必须基于这套坐标。返回场景坐标是最容易犯的错，表现是显示不全、点不中、拖动留残影。

5.2 场景坐标 #

基准是场景原点 (0, 0)，所有图元共享的逻辑世界坐标系。

图元在场景里的绝对位置用 scenePos()。场景层的事件处理、碰撞检测、区域查询都在这层，sceneRect 也在这层定义。把画布想成一张很大的逻辑纸，视图是拿取景框看纸上的局部，挪取景框不影响纸上的内容。

5.3 视图坐标 #

基准是视图窗口左上角，单位是屏幕像素。

鼠标事件最初拿到的就是这个坐标，QMouseEvent::position() 返回相对视图部件的像素坐标。它和场景坐标之间隔着一层视图变换：缩放 2 倍时，视图上移动 2 像素，场景里只走 1 个单位。

滚动条偏移已经算在映射里了，别再去减 scrollBar->value()。

5.4 常用映射 API #

转换方向 API 用在哪
视图 → 场景 view->mapToScene(QPoint) 鼠标点击位置换成逻辑坐标
场景 → 视图 view->mapFromScene(QPointF) 场景位置映射回像素，定位浮层
场景 → 图元 item->mapFromScene(QPointF) 判断点是否落在图元内部
图元 → 场景 item->mapToScene(QPointF) 取图元的绝对位置
子 → 父 item->mapToParent(QPointF) 子图元在父图元里的位置
图元 → 图元 itemA->mapFromItem(itemB, pt) 两个图元之间换算
矩形批量 view->mapToScene(QRect) 视口矩形对应的场景区域

矩形映射返回的是旋转后的包围盒，不能当原矩形用。

5.5 一次点击的完整换算 #

用户点在图元上，从收到事件到判定命中，坐标跑了三趟：

cpp
void CanvasView::mousePressEvent(QMouseEvent *event)
{
    const QPoint viewPos = event->position().toPoint();   // 1. 视图坐标（像素）
    const QPointF scenePos = mapToScene(viewPos);         // 2. 场景坐标（逻辑）
    QGraphicsItem *hit = scene()->itemAt(scenePos, transform());
    if (hit)                                              // 3. 图元局部坐标
        qDebug() << viewPos << scenePos << hit->mapFromScene(scenePos);
    QGraphicsView::mousePressEvent(event);                // 交给基类继续分发
}

图元的 mousePressEvent() 里更省事，框架已经算好了：

cpp
void NodeItem::mousePressEvent(QGraphicsSceneMouseEvent *event)
{
    // event->pos()       图元局部坐标，算相对位移用这个
    // event->scenePos()  场景坐标，跨图元比较用这个
    // event->screenPos() 屏幕全局坐标，弹菜单用这个
    qDebug() << "局部" << event->pos() << "场景" << event->scenePos();
    event->accept();
}

这就是素材里那句提醒的落地：event->pos() 是图元局部坐标，event->scenePos() 是场景坐标。混用时缩放为 1 不报错，一缩放就全歪。

5.6 视图变换 #

QGraphicsView 自己带一层变换，缩放平移旋转都加在这层：

cpp
view->scale(2.0, 2.0);       // 视图放大 2 倍，图元数据不动
view->rotate(45);
view->translate(50, 0);
view->resetTransform();      // 清掉所有视图变换

视图变换只改观察角度。所有图元的 pos()、rotation() 还是原值，sceneRect 也不变。这就是它比直接改 painter->scale() 好用的地方。

滚轮缩放要注意缩放中心。以鼠标位置为中心，先记下鼠标下的场景点，缩放后再把它挪回鼠标下面：

cpp
void CanvasView::wheelEvent(QWheelEvent *event)
{
    const QPointF before = mapToScene(event->position().toPoint());
    const double factor = event->angleDelta().y() > 0 ? 1.15 : 1.0 / 1.15;
    scale(factor, factor);
    const QPointF delta = mapToScene(event->position().toPoint()) - before;
    translate(delta.x(), delta.y());   // 少了这行，缩放中心跑到视图中心
    event->accept();
}

偷懒也行：setTransformationAnchor(QGraphicsView::AnchorUnderMouse) 让框架代劳。限制缩放范围靠自己记累积系数，别去读 transform().m11() 硬算。

六、图元的变换：位置、旋转、缩放 #

图元自己也能变换，和视图变换是两层独立的东西。视图变换是相机怎么摆，图元变换是物体怎么摆。

6.1 三个基本属性 #

cpp
item->setPos(100, 50);        // 位置：在父坐标系里的平移
item->setRotation(30);        // 旋转：绕变换原点转，度数，顺时针为正
item->setScale(0.5);          // 缩放：以变换原点为基准

旋转正方向是顺时针，因为 y 轴向下，和数学课本相反。

三个属性都绕 transformOriginPoint 起作用，它默认是 (0, 0)，也就是图元的局部原点。setTransformOriginPoint(QPointF(20, 20)) 就改成绕局部坐标那一点转。

绕中心旋转有两条路：把几何中心放在原点，或者显式设原点。

cpp
auto *box = new QGraphicsRectItem(QRectF(-40, -30, 80, 60));
box->setRotation(45);                    // 中心在原点，原地转

auto *box2 = new QGraphicsRectItem(QRectF(0, 0, 80, 60));
box2->setTransformOriginPoint(box2->boundingRect().center());
box2->setRotation(45);                   // 原点在左上角，靠原点修正

用 QRectF(0, 0, 80, 60) 又不设原点，图元绕着左上角甩出去。这是「一转位置就乱」的头号原因。

6.2 组合顺序是固定的 #

setPos()、setRotation()、setScale() 叠起来的顺序固定：先缩放，再旋转，最后平移。调用顺序不影响结果。

要非标准组合，用 setTransform() 塞一个 QTransform：

cpp
QTransform t;
t.translate(100, 100);
t.rotate(30);
t.shear(0.2, 0);          // 错切
t.scale(1.5, 1.0);
item->setTransform(t);

QTransform 和那三个属性是叠加关系，不是覆盖关系。一个图元上别混用两套接口，不然会出现「怎么调都不对」的局面。

6.3 视图变换和图元变换的区别 #

维度 视图变换 view->scale() 图元变换 item->setScale()
影响范围 整个场景的显示 单个图元及其子树
改的是什么 相机，观察方式 物体，数据状态
是否改数据 不改，pos() 保持原样 改，图元在场景里的实际形态变了
典型用途 缩放浏览、平移画布 图形尺寸变化、动画
其他视图 不影响 所有视图一起变
重置 resetTransform() 一把清 逐项恢复

混用的典型后果是：你想放大画布，结果图元的 pos() 变了，存下来的数据跟着变。

6.4 子图元继承父图元的变换 #

父图元 scale(2) 之后，子图元的视觉尺寸也翻倍，但子图元自己的 scale() 还是 1；子图元的 scenePos() 变了，pos() 没变。

层次越深，每次 scenePos() 的矩阵连乘越长。常用位置缓存起来比每次现算划算。

七、碰撞检测与拾取 #

碰撞检测分两级，这是性能设计的核心。

第一级是粗略检测，基于 boundingRect()。两个图元的边界矩形不相交，直接排除，不做精细计算。这一步便宜，能干掉绝大部分候选。

第二级是精确检测，基于 shape()。边界相交了，再拿 QPainterPath 做真实包含判断。圆图元在这步才算圆而不是方框，圆环在这步才把中间的空洞挖掉。

cpp
bool hit  = itemA->collidesWithItem(itemB);          // 两个图元是否碰撞
bool hit2 = item->collidesWithPath(path);            // 图元是否与路径碰撞
QList<QGraphicsItem *> hits = scene->collidingItems(item);

shape() 默认返回 boundingRect() 构成的矩形路径。要按真实轮廓判定就得重写：

cpp
QPainterPath NodeItem::shape() const
{
    QPainterPath path;
    path.addEllipse(QPointF(0, 0), 20, 20);              // 外圆
    if (m_shape == Ring) {
        QPainterPath hole;
        hole.addEllipse(QPointF(0, 0), 12, 12);          // 内圆
        path = path.subtracted(hole);                    // 挖空
    }
    return path;
}

不重写的后果很具体：圆环点中间空洞也命中，两个斜放矩形在角落空隙互报碰撞。shape() 还有个近亲 shadow()，给阴影用，默认也返回 boundingRect()。

7.1 拾取接口 #

接口 作用
scene->itemAt(scenePos, transform) 该点最上层的图元，没有返回 nullptr
scene->items(scenePos) 该点下所有图元，按 z 序从上到下
scene->items(rect) / items(path) 与矩形或路径相交的所有图元
view->itemAt(viewPos) 视图坐标版本，内部先映射再查
scene->selectedItems() 当前选中的图元
scene->collidingItems(item) 与它碰撞的图元

itemAt() 只返回最上面那个，适合点选。要「穿透式」拾取、选中被遮挡的底层图元，用 items() 拿列表自己挑。

拾取还有一组 Qt::ItemSelectionMode 可选：ContainsItemShape、IntersectsItemShape、ContainsItemBoundingRect、IntersectsItemBoundingRect。items(rect) 默认按精确形状相交，itemAt() 默认按包围盒相交。这个不一致导致「点在圆角外面一点点也命中了」，要严格判定就显式传 Qt::IntersectsItemShape。

7.2 命中测试的开关 #

cpp
item->setAcceptedMouseButtons(Qt::NoButton);  // 照常绘制，但不响应鼠标
item->setVisible(false);                      // 不画，也不参与拾取
item->setOpacity(0.01);                       // 还是能点中

前两个都把图元从拾取候选里摘掉，用途不同：背景网格线要「看得见但不响应」，用第一个；临时隐藏用第二个。半透明只是绘制时乘 alpha，命中不受影响，这点跟直觉相反。

ItemIgnoresTransformations 是另一个常用开关：设了它，图元不跟随视图缩放，永远保持屏幕上的固定像素大小，做标注点、图钉、文字标签时必用。代价是命中区域也按屏幕尺寸算。

八、事件传播与交互 #

事件从窗口进来，到图元处理，走一条固定路径。

text
  窗口系统（QApplication 分发）
        │
        ▼
  QGraphicsView::mousePressEvent()     拿到视图坐标
        │  映射成场景坐标，包装成 QGraphicsSceneMouseEvent
        ▼
  QGraphicsScene::mousePressEvent()    按场景坐标做命中测试
        │  找到目标图元，设好 pos / scenePos / screenPos
        ▼
  QGraphicsItem::mousePressEvent()     图元局部坐标
        │
        ├── accept() → 到此为止，事件被吃掉
        └── ignore() → 冒泡给父图元 → 回到场景默认处理

这条链决定三件事：坐标在哪层转换、谁有权拒绝事件、拒绝后落在哪。

8.1 鼠标事件的基础配置 #

图元默认接收鼠标点击。悬停和内置拖拽要显式开启，这是最常漏的一步：

cpp
setAcceptHoverEvents(true);                        // 不开，hover 事件永不触发
setFlag(QGraphicsItem::ItemIsMovable, true);       // 内置拖拽移动
setFlag(QGraphicsItem::ItemIsSelectable, true);    // 选中状态支持

三个开关各管一摊。只开 ItemIsMovable 不开 ItemIsSelectable，拖能拖但选中集合不更新；只开 ItemIsSelectable，能选中但拖不动。

再补两个常用设置：setAcceptedMouseButtons(Qt::LeftButton | Qt::RightButton) 限定响应哪些键，setCursor(Qt::OpenHandCursor) 设悬停光标。

8.2 accept 与 ignore #

  • accept()：事件被吃掉，不再往上传播。
  • ignore()：冒泡给父图元；父图元也不要，最终回到场景做默认处理。
cpp
void NodeItem::mousePressEvent(QGraphicsSceneMouseEvent *event)
{
    if (m_locked) { event->ignore(); return; }   // 锁定状态不响应，让它冒泡
    QGraphicsItem::mousePressEvent(event);       // 基类处理选中和内置拖动
}

不调基类实现，ItemIsMovable 的内置拖动就废了。调了但没让基类接受，后续移动事件收不到，按下去了拖不动。

8.3 悬停 #

cpp
void NodeItem::hoverEnterEvent(QGraphicsSceneHoverEvent *event)
{ m_hovered = true;  update(); }          // 只改状态 + 请求重绘
void NodeItem::hoverLeaveEvent(QGraphicsSceneHoverEvent *event)
{ m_hovered = false; update(); }

事件里只改状态，外观留给 paint() 去读。在事件里直接画东西，下一次重绘就被覆盖了。

8.4 拖放 #

框架支持标准 Qt 拖放机制，图元要当接收者三步走：

cpp
class DropZoneItem : public QGraphicsItem
{
public:
    DropZoneItem() { setAcceptDrops(true); }        // 第一步：开启接收
protected:
    void dragEnterEvent(QGraphicsSceneDragDropEvent *e) override
    {   // 第二步：判断接不接
        e->mimeData()->hasUrls() ? e->acceptProposedAction() : e->ignore();
    }
    void dragLeaveEvent(QGraphicsSceneDragDropEvent *) override { update(); }
    void dropEvent(QGraphicsSceneDragDropEvent *e) override   // 第三步：处理
    {
        for (const QUrl &url : e->mimeData()->urls())
            qDebug() << "收到" << url.toLocalFile();
        e->acceptProposedAction();
    }
};

事件类型是 QGraphicsSceneDragDropEvent，不是 widget 那套 QDragEnterEvent。照抄 widget 代码编译不过。

8.5 滚轮、右键菜单、事件过滤 #

滚轮多半该在视图层做缩放，图元只在带修饰键时接管：

cpp
void NodeItem::wheelEvent(QGraphicsSceneWheelEvent *event)
{
    if (!(event->modifiers() & Qt::ControlModifier)) {
        event->ignore();     // 交给视图缩放画布
        return;
    }
    setOpacity(qBound(0.2, opacity() - event->angleDelta().y() / 1200.0, 1.0));
    update();
    event->accept();         // 接受之后视图就拿不到缩放机会了
}

右键菜单要注意坐标：

cpp
void NodeItem::contextMenuEvent(QGraphicsSceneContextMenuEvent *event)
{
    QMenu menu;
    menu.addAction(QStringLiteral("删除"));
    if (menu.exec(event->screenPos()))     // 要屏幕坐标，不是 pos()
        delete this;
}

QMenu::exec() 要全局屏幕坐标，传 pos() 或 scenePos()，菜单会跑到奇怪的位置。

要在事件到达图元之前插一手，用 sceneEventFilter()：

cpp
filterItem->installSceneEventFilter(targetItem);

bool FilterItem::sceneEventFilter(QGraphicsItem *watched, QEvent *event)
{
    if (event->type() == QEvent::GraphicsSceneMousePress)
        return false;      // false = 继续派发；true = 吞掉，目标收不到
    return QGraphicsItem::sceneEventFilter(watched, event);
}

返回值语义反着记最容易翻车：返回 true 目标图元就再也收不到事件了。

九、选中、拖动与焦点 #

三种状态三套 flags，混在一起写就乱。

能力 需要的 flag 相关接口
能被选中 ItemIsSelectable setSelected()、scene->selectedItems()
能拖动 ItemIsMovable 基类 mouseMoveEvent() 改 pos()
能收键盘 ItemIsFocusable setFocus()、hasFocus()
位置变化可拦截 ItemSendsGeometryChanges itemChange(ItemPositionChange)

9.1 选中 #

setFlag(QGraphicsItem::ItemIsSelectable, true) 之后，setSelected() 选中、scene->clearSelection() 清空、scene->selectedItems() 取集合。

选中集合变化时场景发 selectionChanged() 信号，接它更新状态栏比每个图元自己数省事，scene->selectedItems().size() 就是当前数量。

选中外观别自己存成员变量，直接读 option->state，框架自动同步：

cpp
void NodeItem::paint(QPainter *p, const QStyleOptionGraphicsItem *option, QWidget *)
{
    const bool sel = option->state & QStyle::State_Selected;
    p->setPen(QPen(sel ? Qt::blue : Qt::black, sel ? 2 : 1));
    p->drawRect(QRectF(-20, -20, 40, 40));
    if (option->state & QStyle::State_HasFocus) {          // 焦点框
        p->setPen(QPen(Qt::darkGreen, 1, Qt::DashLine));
        p->drawRect(boundingRect().adjusted(1, 1, -1, -1));
    }
}

state 里还有 State_MouseOver。自己镜像一份状态，迟早漏同步。

9.2 拖动 #

内置拖动只要 ItemIsMovable。要限制范围、做网格吸附，用 itemChange() 拦：

cpp
QVariant NodeItem::itemChange(GraphicsItemChange change, const QVariant &value)
{
    if (change == ItemPositionChange && scene()) {
        QPointF np = value.toPointF();
        np.setX(qRound(np.x() / 10.0) * 10.0);      // 吸附到 10 的网格
        np.setY(qRound(np.y() / 10.0) * 10.0);
        return np;                                   // 返回值才是最终位置
    }
    if (change == ItemSelectedHasChanged)
        update();
    return QGraphicsItem::itemChange(change, value);
}

ItemPositionChange 的返回值真正生效，这是做约束的正规位置。ItemPositionHasChanged 是「已经改完了」，只能事后补救。

自己接管拖动就重写三个鼠标事件，位移用场景坐标差算：

cpp
void NodeItem::mousePressEvent(QGraphicsSceneMouseEvent *event)
{ m_startPos = pos(); event->accept(); }

void NodeItem::mouseMoveEvent(QGraphicsSceneMouseEvent *event)
{   // 位移用场景坐标差，视图缩放时也不会飘
    setPos(m_startPos + event->scenePos() - event->buttonDownScenePos(Qt::LeftButton));
    event->accept();
}

两个经典坑：拿 event->pos() 往 setPos() 上累加，参照系跟着图元一起动，越拖越快、发散；拿 QCursor::pos() 当拖动坐标，那是屏幕坐标，中间还隔着一层视图变换。

9.3 焦点 #

键盘事件只发给有焦点的图元。

cpp
setFlag(QGraphicsItem::ItemIsFocusable, true);   // 先声明能拿焦点
setFocus();

cpp
void NodeItem::keyPressEvent(QKeyEvent *event)
{
    if (event->key() == Qt::Key_Left)        moveBy(-5, 0);
    else if (event->key() == Qt::Key_Delete) delete this;
    else QGraphicsItem::keyPressEvent(event);
}

两个细节。视图本身要设 setFocusPolicy(Qt::StrongFocus)，不然点完视图按键被窗口吞掉。场景的 stickyFocus 属性：设 true 点空白处不清焦点，默认 false 点空白就清。场景里同时只有一个焦点图元，scene->focusItem() 拿到的就是它。

十、动画与定时器 #

让图元动起来有三条路。

10.1 属性动画 #

图元继承 QGraphicsObject 之后，pos、rotation、scale、opacity 都是属性，QPropertyAnimation 直接能用：

cpp
auto *anim = new QPropertyAnimation(node, "pos", this);
anim->setDuration(1000);
anim->setStartValue(QPointF(0, 0));
anim->setEndValue(QPointF(400, 300));
anim->setEasingCurve(QEasingCurve::OutCubic);
anim->start();                        // 1 秒内滑到 (400, 300)

这条路不用管重绘，pos 变了框架自己请求更新对应区域。你只描述「从哪到哪、多久、什么缓动」。组合动画用 QSequentialAnimationGroup（依次播）和 QParallelAnimationGroup（同时播）。

10.2 advance() 帧同步 #

scene->advance() 会遍历所有图元，对每个调两次 advance(int phase)：phase == 0 算下一帧状态，phase == 1 应用。适合帧同步的物理或游戏逻辑。

cpp
void BallItem::advance(int phase)
{
    if (phase == 0) return;              // 第一遍只算，不改位置
    QPointF np = pos() + m_velocity;
    if (np.x() < 0 || np.x() > 800) m_velocity.setX(-m_velocity.x());
    setPos(np);
}

// 场景自己不会定时调 advance，得你驱动
auto *timer = new QTimer(this);
connect(timer, &QTimer::timeout, scene, &QGraphicsScene::advance);
timer->start(16);                        // 约 60 帧

10.3 定时器手改属性 #

最原始也最可控：QTimer 里自己算位置，改完记得 update()。逻辑随便写，缺点是重绘和时间基准都得自己管。

方式 适合什么 注意
QPropertyAnimation 一次性过渡、循环动画、缓动 图元必须是 QGraphicsObject
advance() 每帧都更新的仿真（碰撞、粒子） 要自己起定时器驱动
QTimer 手改属性 简单周期变化、外部数据驱动 改完手动 update()

动画改 pos 不触发 itemChange()，除非开了 ItemSendsGeometryChanges。靠 itemChange 做约束的图元，一上动画约束就失效。

十一、大量图元的性能优化 #

图元数量上去后，默认设置在几个地方会拖后腿。哪些开关有用，取决于场景是「静态一大批」还是「少量频繁动」。

11.1 边界矩形要准 #

boundingRect() 的效率对性能影响极大，这是最基础的一条：必须覆盖 paint() 画出的所有像素，包括画笔宽度的一半，但不能乱大；形状固定就把结果缓存，别每次重算；边界改了先 prepareGeometryChange()。

边界虚胖的代价是双份：脏矩形变大，重绘面积跟着涨；BSP 索引分区变粗，查询命中率下降。

11.2 视口更新模式 #

最见效的开关。默认 MinimalViewportUpdate，框架算最小脏区域。图元密集且频繁移动时，算脏矩形的开销会超过直接重绘。

模式 行为 适用
FullViewportUpdate 整个视口重绘，不算脏矩形 图元密集、频繁移动、动画多
MinimalViewportUpdate 只重绘最小脏区域（默认） 图元少、改动区域小
SmartViewportUpdate 框架自己判断用最小还是全量 拿不准时先用这个
BoundingRectViewportUpdate 重绘所有变化区域的包围盒 变化分散但集中在一小块
NoViewportUpdate 框架不刷新，全靠你调 viewport()->update() 自己控制刷新时机

view->setViewportUpdateMode(QGraphicsView::FullViewportUpdate) 就切到全量重绘。NoViewportUpdate 最激进，一切刷新靠手动触发。批量改上千个图元属性时这么干很划算：改完统一刷一次，中间一次都不刷。

11.3 缓存 #

两级缓存，别搞混。视图缓背景用 view->setCacheMode(QGraphicsView::CacheBackground)，背景静态（网格、底图、标尺）时直接砍掉背景绘制开销，重绘只画图元。图元缓存自身用 setCacheMode()：

cpp
item->setCacheMode(QGraphicsItem::DeviceCoordinateCache);   // 按屏幕分辨率缓存
item->setCacheMode(QGraphicsItem::ItemCoordinateCache);     // 按图元自身坐标缓存

前者适合不缩放或缩放范围小的图元，缩放时重画缓存；后者适合反复缩放的复杂图元，缓存一次多次复用，放大后有点糊。缓存不是白给的，每个缓存图元多一份像素内存，图元上千时只给「绘制复杂且不常变」的开。

11.4 细节层次（LOD） #

levelOfDetailFromTransform() 把变换矩阵折成一个缩放系数，直接拿来判：

cpp
void NodeItem::paint(QPainter *painter, const QStyleOptionGraphicsItem *option, QWidget *)
{
    const qreal lod = option->levelOfDetailFromTransform(painter->worldTransform());
    if (lod < 0.2) {
        painter->setBrush(Qt::gray);
        painter->drawRect(boundingRect());              // 小到看不清就画色块
    } else {
        painter->drawEllipse(QPointF(0, 0), 20, 20);    // 放大才画细节
        painter->drawText(QRectF(-20, -20, 40, 40), Qt::AlignCenter, QStringLiteral("节点"));
    }
}

缩小到看不清时还照原样画，等于白烧 CPU。配套开关 ItemUsesExtendedStyleOption 开了之后 option->exposedRect 才管用，可以只画暴露区域那一块。

11.5 索引模式 #

场景默认用 BSP 树索引，查找快，图元移动时要维护树。图元频繁移动时，重建成本会高于查找收益：

cpp
scene->setItemIndexMethod(QGraphicsScene::NoIndex);        // 全在动，关索引
scene->setItemIndexMethod(QGraphicsScene::BspTreeIndex);   // 静态场景，用树
scene->setBspTreeDepth(12);

树深影响分区粒度，调大了索引更精细但构建更慢，调小了反过来。这个值要靠测，没有通用答案。

11.6 硬件加速与几条习惯 #

cpp
view->setViewport(new QOpenGLWidget());        // 合成交给 GPU
view->setViewportUpdateMode(QGraphicsView::FullViewportUpdate);

paint() 太重的话，换 GPU 也救不了——瓶颈从光栅化挪到了绘制调用。

  • 别在 paint() 里 new QPen、QBrush、QFont，提前建好。
  • 别在 paint() 里算几何，坐标在属性变更时算好。
  • 不可见图元用 setVisible(false)，别删了又加，增删比刷界面贵。
  • 一次性建大量图元先 NoIndex，建完改回来。
  • 高频改动时先量再调，用 QElapsedTimer 量一次重绘耗时，别凭感觉改。

十二、与 QPainter 的分工 #

同一个 QPainter，两种用法，边界很清晰。

维度 QPainter 直接画 Graphics View
绘制模型 命令式，每帧从头画 保留式，对象常驻场景
对象是否存在 不存在，画完即忘 存在，可随时查、改、删
命中测试 自己算 框架按索引和 shape() 算
局部重绘 自己算脏矩形 item->update()
事件处理 在 widget 里写判断 分发到图元自己处理
对象数量 几十个以内舒服 上百、上千个也扛得住
内存 几乎没有额外开销 每个图元一份对象开销
代码量 简单图形很短 简单图形更啰嗦

一句话分界：对象多且要交互用 Graphics View，简单绘制用 QPainter。

具体到判断：

  • 自绘控件外观、进度条、仪表盘、波形小图、装饰性背景 → QPainter。
  • 画布上要拖要选要连线的节点、流程图、拓扑图、看板 → Graphics View。
  • 一次性导出图片、打印 → 两者都能到 QImage；统计图表别自己写，看 QChart、QCustomPlot、Qwt。

两者能混用，而且经常混用。图元的 paint() 里就是 QPainter，Graphics View 挡不住你手写任何绘制代码。反过来，整个场景也能一次性落到 painter 上：

cpp
QImage canvas(1600, 1200, QImage::Format_ARGB32);
canvas.fill(Qt::white);
QPainter p(&canvas);
scene->render(&p);          // 场景内容渲染到图片
p.end();

导出、打印、生成缩略图走这条路，比截图视图稳，还不受窗口尺寸限制。

十三、易错点速查 #

现象 原因 处理
图元移动后边缘留残影 boundingRect() 没算画笔半宽 边界外扩 penWidth/2
新形状被裁掉、碰撞按旧形状算 改边界前没调 prepareGeometryChange() 先通知，再改数据
点哪都点不中 坐标层级混用 视图坐标先 mapToScene()
画面缩放后点选全偏 view->itemAt() 传了场景坐标 视图版吃 QPoint，场景版吃 QPointF
hover 事件不触发 没开 setAcceptHoverEvents(true) 构造函数里补上
拖放事件收不到 没开 setAcceptDrops(true) 图元不支持时要显式开
拖动越拖越快、发散 用 event->pos() 累加 setPos() 用 scenePos() 差值
旋转后位置乱飞 变换原点默认在 (0, 0) setTransformOriginPoint(中心)
选中集合永远为空 没开 ItemIsSelectable 开 flag，或直接 setSelected()
图元跟着视图缩放变大变小 标注类图元不需要缩放 开 ItemIgnoresTransformations
圆形图元点角上也命中 shape() 默认返回包围盒 重写 shape() 返回真实轮廓
右键菜单跑到屏幕角落 传了 pos() 或 scenePos() QMenu::exec() 要 screenPos()
图元发不出信号 QGraphicsItem 不是 QObject 改继承 QGraphicsObject
动画一上，位置约束失效 属性动画不走 itemChange() 开 ItemSendsGeometryChanges 并改用定时器
删了图元程序崩 场景里留野指针 removeItem() 与 delete 成对
图元多起来拖动卡 默认最小脏区域重绘 FullViewportUpdate 加按需缓存
视图按 Delete 没反应 视图没有焦点或不处理键盘 setFocusPolicy(Qt::StrongFocus)
缩放时画面乱跑 缩放锚点不在鼠标下 AnchorUnderMouse 或手动补 translate()
