这篇只讲一件事：把 Qwt 装起来。它是什么、版本怎么选、编译的通用四步、Linux 与 Windows 下的具体命令、Designer 插件怎么配、工程里怎么引用、怎么交叉编译到 ARM、装完怎么验证、踩坑怎么排。

不讲的部分：QwtPlot 的曲线与图例怎么画、坐标轴刻度怎么设、鼠标缩放平移交互、Qwt 的库结构与源码组织，这些在同目录的曲线与坐标轴篇、统计图篇、库结构篇里。QCustomPlot 的用法在 QCustomPlot 三篇里，QChart 与 QPainter 手绘、图形视图框架各有专篇，选型对比单独成篇。本篇只管「装」，装完能在一个空工程里编译出 #include <qwt_plot.h> 就算达标。

一、Qwt 是什么：为什么必须自己编译 #

Qwt 全称 Qt Widgets for Technical Applications，LGPL 协议的开源项目，给技术类程序提供 2D 绘图控件和一组工具类。数据源是数值、数组或一组浮点数，输出形式为曲线（Curves）、滚动条（Slider）、圆盘（Dials）、仪表盘（Compasses）。它建在 Qt 上，跨平台特性直接继承过来。

界面上那些图形不是一个个独立写死的控件，而是对基类的组合扩展。基类这层值得先记一遍，查文档、读源码都靠它：

基类 职责
QwtAbstractScale 含刻度尺的所有类的抽象基类
QwtAbstractScaleDraw 绘制刻度尺的抽象基类
QwtAbstractSlider 滑块部件的抽象基类
QwtAnalogClock 时钟的模拟类
QwtArrayData 含两个 QwtArray 实例的数据类
QwtArrowButton 箭头按钮
QwtClipper 裁剪类
QwtColorMap 数值到颜色的映射
QwtCompass 指南针部件
QwtCompassMagnetNeedle 指南针的磁针
QwtCompassRose 罗盘部件的抽象基类
QwtCompassWindArrow 风向标指示器

源码包的目录就是这么分工的：

目录 / 文件 内容
src/ 核心代码，库本体
designer/ Designer 插件源码，编出那个让 Qt Designer 能拖控件的 .dll / .so
examples/ 官方示例，很多图都是从这儿来的
doc/ 离线文档
textengines/ 数学公式 / MathML 文本渲染引擎
qwt.pro 主工程文件，qmake 就是对它下手
qwtconfig.pri 功能开关：OpenGL、Designer 插件、examples、安装前缀
qwtbuild.pri 构建开关：debug_and_release、编译参数

examples 里的工程要能编过，前提是 src/ 或 designer/ 下已经生成 qwt.lib / qwt.dll 这一套。先把库编出来，示例才有得链。

与另外两个库的分工 #

维度 Qwt QCustomPlot QChart
交付形态 需自行编译成库 2 个源文件 Qt 官方附加模块
装起来的动作 qmake + make + 拷三类文件 拷文件 + 一行 .pro 装模块 + 一行 .pro
编译要求 必须同编译器、同版本重编 随你的工程一起编 随 Qt 一起发行
主要风险 编译器或版本错配 大文件编译慢 模块没装

选型那篇展开取舍。这里只记一句：Qwt 是三者里唯一需要你先动手造一遍的。

真正的门槛：它不是拷贝就能用的库 #

这是全篇的根，也是各类安装失败的总根源。

QCustomPlot 全部实现就在 qcustomplot.h 和 qcustomplot.cpp 两个文件里，拷进工程就能编。Qwt 不是。Qwt 是一套预编译产物：库文件、头文件、Designer 插件，三样分开交付，每一样都跟「你是用哪个编译器、哪个 Qt 版本、Debug 还是 Release 编出来的」绑死。

所以 Qwt 的编译有一条铁律：

编 Qwt 用的编译器，必须和你编目标程序用的编译器是同一套；编 Qwt 用的 Qt 版本，必须和你目标程序用的 Qt 版本对得上。

对不上会怎样。你在 32 位 Qt 里编的程序，去链 64 位 Qwt，链接器直接报符号找不到。你用 MSVC 编的 Qwt，去链 MinGW 编的程序，.lib 和 .a 根本不是一个格式。你用 Qt 4 的 qmake 编出来的 Qwt，拿到 Qt 5 的工程里，头文件里的宏定义和 ABI 全变，编得过也跑不起来。

再细一层，还有四个地方会咬人：

错配项 表现
编译器家族不同（MSVC / MinGW） 库格式不同，链接期就崩
位数不同（32 / 64） unresolved external symbol
Qt 大版本不同（4 / 5） 头文件宏冲突、ABI 不兼容，编过也照样崩
Debug / Release 不同 MSVC 下不同运行库，链上就报错；库文件名差一个 d

Linux 上还有一层更阴的坑：系统里同时装着 Qt4 和 Qt5，qmake 是软链接，你切进 Qwt 目录直接敲 qmake，落到哪个版本全看软链接指向。素材里那台机器就是这样，/usr/bin/qmake 指向 /usr/lib/x86_64-linux-gnu/qt5/bin/qmake，一个 qmake -v 打出 QMake version 3.0 和 Using Qt version 5.3.1，这就是 Qt5 的。同一台机器上 /usr/lib/x86_64-linux-gnu/qt4/bin/qmake -v 打出 QMake version 2.01a 和 Using Qt version 4.8.6。两个都能用，用错一个，后面所有步骤白干。

qmake、qtcreator、qtdesigner、Qt 库本身，四者版本必须一条线。要么全 Qt4，要么全 Qt5。Qt Creator 是 Qt5 时代的 IDE，它的界面编辑器调的就是 Designer，链的是哪套 Qt，插件就得是哪套编的。

二、下载与版本选择 #

官方主页 http://qwt.sourceforge.net/。官方不提供二进制包，只给源码，这是 Qwt 必须自己编的第二个原因——上游压根没给你编好。

SourceForge 的下载页 https://sourceforge.net/projects/qwt/，一个版本对应三个文件，值得一起下：

文件 用途
qwt-6.1.2.zip / qwt-6.1.0.tar.bz2 源码，编译用
qwt-6.1.2.pdf 用户手册
qwt-6.1.2.qch Qt Creator 帮助文档，装完能按 F1 查

旧版本还能走 SVN 拿源码，素材里给的是这两条：

bash
# 最新稳定分支
svn co https://qwt.svn.sourceforge.net/svnroot/qwt/branches/qwt-6.0

# 最新构建版（trunk）
svn co https://qwt.svn.sourceforge.net/svnroot/qwt/trunk/qwt

SVN 那条路的毛病是源码包不完整、版本号带 -svn 后缀，编译出来的东西跟正式包不完全一样。想省事就下 tar 包或 zip 包。

版本怎么挑 #

素材里出现的版本，和它们对应的 Qt，整理成这张表：

Qwt 版本 配套 Qt 场景
5.2.1 Qt 4 时代（qtsdk-2010.01） 老工程，Qt4 + 老 Designer
6.0.1 Qt 4.7 / 4.8 过渡期，src/ 里还是老工程结构
6.1.0 Qt 4.8 以上，兼容 Qt 5 用得最广的一版，Qt5 早期项目首选
6.1.2 Qt 5.5（MinGW 4.9.2 实测） Qt5 中期项目
6.1.0-rc3 Qt 5.0.1（MinGW 47_32 实测） rc 预览版，只在老教程里出现

挑选规则很短：目标工程的 Qt 是哪个大版本，Qwt 就挑同一大版本里最新的稳定版。Qt5 项目用 6.1.x，Qt4 项目用 6.1.0 或 5.2.1。别拿 5.2.1 去配 Qt5，那一版的头文件和 Qt5 的容器改动打架。

rc 版和正式版的差别要认真对待。qwt-6.1-rc3 这种预览版在旧教程里很常见，但它的 qwtbuild.pri、qwtconfig.pri 里的开关跟正式版有出入，照着正式版教程改会找不到对应行。

安装前缀先定好 #

qwtconfig.pri 里管着装到哪儿。默认值长这样：

bash
unix {
    QWT_INSTALL_PREFIX    = /usr/local/qwt-$$QWT_VERSION-svn
}
win32 {
    QWT_INSTALL_PREFIX    = C:/Qwt-$$QWT_VERSION-svn
}

想改就改这两行。素材里实际落地的位置：

平台 版本 实际安装路径
Linux 6.1.0 /usr/local/qwt-6.1.0
Windows + MinGW 6.1.2 C:\Qwt-6.1.2
Linux 5.2.1 源码目录内就地使用，或 /usr/local/qwt-5.2.1

路径里有中文、有空格，后面 qmake 和 make 会在某一环出问题，解压时就放到纯 ASCII 路径下。

三、编译的通用流程 #

九篇旧稿讲的是同一套动作，只是平台不同。骨架就四步：

步骤 命令 干什么
1 改 qwtconfig.pri 定安装前缀，关掉跑不起来的模块
2 qmake qwt.pro 生成 Makefile。这一步定了你用哪套 Qt
3 make / nmake / mingw32-make 真编译，几分钟到十几分钟
4 make install / nmake install 装进前缀目录，得到头文件、库、插件

第 2 步是整条链的分水岭。qmake qwt.pro 一旦跑错版本，后面 make 出来的产物就是废的，装进去也是废的。

三个子工程 #

qwt.pro 是个总工程，底下三块可以单独编：

子工程 目录 产物
核心库 src/ / 根工程 qwt.dll+qwt.lib / libqwt.so / libqwt.a
Designer 插件 designer/ qwt_designer_plugin.dll / libqwt_designer_plugin.so
示例 examples/ 各个 demo 可执行文件，依赖前两者

只想要控件，编前两个就够。示例是拿来验证和抄代码的，编不编不影响你写工程。

产物清单 #

不同平台的产物名字不一样，认清楚这三个家族：

平台 / 编译器 动态库 导入库 / 静态库 插件
Windows MSVC qwt.dll / qwtd.dll qwt.lib / qwtd.lib qwt_designer_plugin.dll（+ .lib）
Windows MinGW qwt.dll / qwtd.dll libqwt.a / libqwtd.a qwt_designer_plugin.dll
Linux / ARM libqwt.so libqwt.a libqwt_designer_plugin.so

带 d 的是 Debug 版。MSVC 下 Debug 和 Release 的运行库不同，混链会报错，两套都得编出来。

构建工具对号入座 #

环境 构建命令
Linux / MinGW make
MinGW 在 Windows 命令行 mingw32-make
MSVC 命令提示符 nmake

mingw32-make 和 make 是一回事，MinGW 发行包为了不和别的 make 撞名才改了名。

静态库还是动态库 #

默认编出来是动态库。想要静态库，素材里给的路子是改 qmake 生成的那个 Makefile，把目标从 libqwt.so 改成静态库再 make。另一条更干净：在 .pro 里换 CONFIG。

动态库的代价是运行时得能找到它，Linux 靠 -Wl,-rpath 或 LD_LIBRARY_PATH，Windows 靠 exe 旁边或 PATH。静态库省掉这一步，代价是 exe 变大、每次 Qwt 升级都要重链。

四、Linux 下的编译与安装 #

Linux 是最顺的一条路：不用管 IDE，qmake + make + make install 三连就完了。坑集中在版本。

先确认 qmake 是谁 #

别急着编。第一件事是看 qmake 落在哪个版本上：

bash
qmake -v

输出 QMake version 3.0 + Using Qt version 5.x 就是 Qt5；输出 QMake version 2.01a + Using Qt version 4.8.x 就是 Qt4。

再顺着软链接看到底指哪儿：

bash
which qmake
ls -l /usr/bin/qmake

素材里那台机器打出来是这样：

text
lrwxrwxrwx 1 root root 39 Jul  4 13:46 /usr/bin/qmake -> /usr/lib/x86_64-linux-gnu/qt5/bin/qmake*

这就是已经指到 Qt5 上了。系统里同时装了 Qt4 和 Qt5 时，两个 qmake 都在：

bash
# Qt5
/usr/lib/x86_64-linux-gnu/qt5/bin/qmake -v
# QMake version 3.0
# Using Qt version 5.3.1 in /usr/lib/x86_64-linux-gnu

# Qt4
/usr/lib/x86_64-linux-gnu/qt4/bin/qmake -v
# QMake version 2.01a
# Using Qt version 4.8.6 in /usr/lib/x86_64-linux-gnu

要哪套就显式敲全路径，别依赖软链接。这是 Linux 上装 Qwt 最省事的一条经验：qmake 命令前带上绝对路径，比改软链接、改 PATH 都稳。

编 6.1.0（Qt5 路线） #

bash
tar xvf qwt-6.1.0.tar.bz2
cd qwt-6.1.0
qmake qwt.pro
make
sudo make install

编完 make install，/usr/local 下就多出一个 qwt-6.1.0：

text
qwt-6.1.0-> ls
doc/  features/  include/  lib/  plugins/

插件在 plugins/designer/ 下：

text
qwt-6.1.0-> ls -l plugins/designer/
total 144K
-rwxr-xr-x 1 root staff 144K Jul  4 11:18 libqwt_designer_plugin.so*

这四样东西分清楚了，后面配工程就不迷路：include/ 是头文件，lib/ 是库，plugins/ 是 Designer 插件，doc/ 是文档。

Linux 上三个必踩的错 #

现象 原因 处理
Project ERROR: Unknown module(s) in QT: svg qmake 用的 Qt 不带 svg 模块，或版本不一致 换成目标 Qt 的 qmake 重来
qwt_plot_glcanvas.h:15:17: fatal error: qgl.h: No such file or directory 这套 Qt 没编 OpenGL 支持 在 qwtconfig.pri 里注释掉 QWT_CONFIG += QwtOpenGL
Project ERROR: Unknown module(s) in QT: designer 缺 Qt Designer 开发包 sudo apt-get install qttools5-dev*

第一条那个 svg 报错，最像环境问题的样子，实际就是 qmake 找错了。你系统里装的 Qt5 如果是精简包，svg 模块确实没有，这种情况下换一个带 svg 的 Qt，或者在 qwtconfig.pri 里把 QwtSVG 关掉。

第二条的改法，具体到文件是这样一行：

bash
# 在 qwtconfig.pri 里注释掉
# QWT_CONFIG     += QwtOpenGL

qgl.h 是 Qt 的 OpenGL 头文件，Qt 编译时没加 -opengl 就没有这个头。Qwt 的 OpenGL 画布是个可选优化，关掉不影响普通绘图。

第三条是 designer 模块缺失，qttools5-dev 里带着 QtDesigner 的头和库。装完重新 qmake qwt.pro && make。

把插件塞进 Qt5 的插件目录 #

编完之后插件只是躺在 /usr/local 里，Qt Creator 不会自动去那儿找。要复制到 Qt 自己的 designer 插件目录：

bash
sudo cp /usr/local/qwt-6.1.0/plugins/designer/libqwt_designer_plugin.so \
    /usr/lib/x86_64-linux-gnu/qt5/plugins/designer

复制完确认一眼：

text
designer-> pwd
/usr/lib/x86_64-linux-gnu/qt5/plugins/designer
designer-> ls
libcontainerextension.so  libqquickwidget.so  libqwt_designer_plugin.so*
libworldtimeclockplugin.so
libcustomwidgetplugin.so  libqwebview.so      libtaskmenuextension.so

列表里出现 libqwt_designer_plugin.so 就成了。重启 Qt Creator，Designer 里会多出一栏 Qwt widgets。

用系统包装的 Qt 与自编译的 Qt #

路径不一样，这是旧教程最容易对不上的地方。素材里给了两组对照：

组件 系统包安装（apt） 自编译安装
Qt 的 designer 插件目录 /usr/lib/qt4/plugins/designer 或 /usr/lib/i386-linux-gnu/qt4/plugins/designer /usr/local/Trolltech/Qt-4.8.5/plugins/designer
Qt Creator 库目录 /usr/lib/qtcreator 或 /usr/lib/i386-linux-gnu/qtcreator /home/han/soft/qtcreator-2.8.1/lib/qtcreator
Qt Creator 自带 designer 插件目录 依安装方式而定 /home/han/soft/qtcreator-2.8.1/bin/plugins/designer

自编译 Qt 4.8.5 装在 /usr/local/Trolltech/Qt-4.8.5，Qt Creator 2.8.1 装在 /home/han/soft/qtcreator-2.8.1，那三条 cp 就是照着这张表来的：

bash
# 1. 插件进 Qt 自带的 designer
sudo cp /usr/local/qwt-6.1.0/plugins/designer/libqwt_designer_plugin.so \
    /usr/local/Trolltech/Qt-4.8.5/plugins/designer

# 2. 库进 Qt Creator 的库目录，Qt Creator 里调 Qwt 控件要靠这些
sudo cp /usr/local/qwt-6.1.0/lib/* /home/han/soft/qtcreator-2.8.1/lib/qtcreator

# 3. 插件再进 Qt Creator 自带的 designer
sudo cp /usr/local/qwt-6.1.0/plugins/designer/libqwt_designer_plugin.so \
    /home/han/soft/qtcreator-2.8.1/bin/plugins/designer

第 2 条容易被漏。Qt Creator 在 Qt5 时代是自带一套 Qt 运行的，插件目录里的 .so 要能加载，就得让 Qt Creator 进程能找到 libqwt.so，所以库还得塞进它的 lib/qtcreator。

环境变量补齐 #

再补一份 LD_LIBRARY_PATH，避免运行时找不到库。编辑 /etc/profile，末尾加四行：

bash
export QTDIR=/usr/local/Trolltech/Qt-4.8.5
export PATH=$QTDIR/bin:$PATH
export MANPATH=$QTDIR/man:$MANPATH
export LD_LIBRARY_PATH=$QTDIR/lib:$LD_LIBRARY_PATH

存盘后让改动立即生效：

bash
source /etc/profile

重启 Qt Creator，界面设计器里就有 Qwt 控件了。

编 5.2.1（Qt4 老路线） #

5.2.1 的流程在 Qt Creator 里点出来，不用命令行：

步骤 动作
1 解压 qwt-5.2.1
2 Qt Creator → open projects → 选中 qwt-5.2.1/qwt.pro → open
3 build → clean all → run qmake
4 rebuild
5 进 qwt-5.2.1 目录，make install

第 3 步那个 clean all 别跳。它清掉你上一次编译失败留下的中间文件，run qmake 才重新生成正确的 Makefile。跳过它，你编的就是上次残留的对象文件。

装完把 qwt-5.2.1/lib 下那四个库文件复制出去：

bash
# 四个库文件分别拷到两个位置
cp /qwt-5.2.1/lib/* /qtsdk-2010.01/qt/lib/
cp /qwt-5.2.1/lib/* /qtsdk-2010.01/lib/

懒一点的做法，不拷库，直接在工程文件里指路径：

bash
INCLUDEPATH += /usr/local/qwt-5.2.1/include
LIBS += -L"/usr/local/qwt-5.2.1/lib/" -lqwt

5.2.1 的 Designer 插件和 6.x 不同，是个两文件组合，在源码目录 qwt-5.2.1/designer/plugins/designer 下。复制到 Qt SDK 的 designer 目录：

bash
cp /qwt-5.2.1/designer/plugins/designer/* /qtsdk-2010.01/bin/designer/

这样在 /qtsdk-2010.01/qt/bin/designer 里就能看到 Qwt 控件。

5.2.1 在老 Qt4 环境里有个历史遗留问题：Qt Creator 自带的 designer 看不到 Qwt 控件。原因跟版本无关，跟目录有关——Qt SDK 的 designer 和 Qt Creator 的 designer 是两个不同的目录，插件只进了前一个。把插件同时拷进 Qt Creator 的 designer 目录就解决了。Linux 下这一步比 Windows 简单，不用管编译器家族，都是 GCC 编的。

Linux 装第三方库的两条通则 #

素材里那位作者总结得很实在，把这两条记住，装任何 Qt 第三方库都能套：

第一条，qmake 要选对。这是成功的基石。你系统里装着别的 Qt 版本（跟系统一块装的，最常见的是 qt3），直接切进源码目录敲 qmake，系统给的是默认那个，一路点下去，最后你会发现 Qwt 控件出现在 qt3 的 designer 里。

第二条，编工程时要能让编译器找到库。要么把库拷进系统默认搜索路径（和 Qt 的库放一块，lib 和 designer 两个目录都得对上），要么在工程文件里加头文件和库的搜索路径：

bash
INCLUDEPATH += /usr/local/qwt-5.2.1/include
LIBS += -L"/usr/local/qwt-5.2.1/lib/" -lqwt

这两条做好，第三方库的安装就不再繁琐。

五、Windows 下的编译与安装 #

Windows 比 Linux 多一层：编译器有两个家族，MSVC 和 MinGW，两家的库互不通用。先定家族，再动手。路线有三条：

路线 适用 构建工具
MinGW 命令行 Qt 自带 MinGW 套件 mingw32-make
MSVC 命令提示符 Qt 的 MSVC 套件 + Visual Studio nmake
Qt Creator 图形界面 不想碰命令行 Qt Creator 内部调用上面的工具

三条路的产物一样，区别只在谁帮你敲命令。

路线一：MinGW 命令行 #

环境先备好。装 Qt 时选带 MinGW 的离线包（例如 qt-opensource-windows-x86-mingw492-5.5.0.exe），安装时勾上 MinGW 组件，再把 MinGW 的 bin 加进系统 Path：

text
D:\Qt\5.5\mingw492_32\bin

源码解压到纯英文路径，例如 D:\qwt-6.1.2\。别放桌面、别放中文目录，Makefile 里的路径带空格会断。

从开始菜单找 Qt 5.5 对应的终端入口，名字是 Qt 5.5 for Desktop (MinGW 4.9.2 32 bit)，别用系统的 cmd。这个快捷方式已经把 MinGW、qmake、Qt 的环境变量都设好了，用错了就是版本错配。

bash
cd D:\qwt-6.1.2
qmake qwt.pro
mingw32-make
mingw32-make install

第三步要等几分钟，一堆 C++ 文件全量编，5 到 15 分钟都正常。别中途 Ctrl+C，编到一半断掉留下的 .o 会让下次编出诡异错误。

mingw32-make install 跑完，Qwt 自动落到 C:\Qwt-6.1.2。进去看一眼：

text
C:\Qwt-6.1.2
├── include\     头文件
├── lib\         libqwt.a  libqwtd.a  qwt.dll  qwtd.dll
├── plugins\designer\   qwt_designer_plugin.dll
└── doc\         文档

路线二：MSVC 命令提示符 #

VS2010 + Qt5.1 那一套。别用普通 cmd，要从开始菜单进：

text
开始菜单 → 所有程序 → Microsoft Visual Studio 2010
→ Visual Studio Tools → Visual Studio 命令提示 (2010)

这个入口设好了 cl.exe、link.exe、nmake 的环境。进去之后三步分开编：

text
# 1. 编核心库
cd E:\QWT
qmake qwt.pro
nmake

# 2. 编 Designer 插件
cd designer
qmake designer.pro
nmake

# 3. 编示例（可选）
cd ..
cd examples
qmake examples.pro
nmake

也可以偷懒用 VS 直接导入 qwt.pro，在 IDE 里点生成，效果一样。命令行好在能看清每一步在哪断。

MSVC 这条路的产物在 E:\QWT\lib\ 下：qwt.dll、qwtd.dll、qwt.lib、qwtd.lib。插件在 E:\QWT\designer\plugins\designer\ 下：qwt_designer_plugin.dll 和 qwt_designer_plugin.lib。

路线三：Qt Creator 图形界面 #

不用命令行，直接在 IDE 里点。第一步，Qt Creator → 打开文件或项目，选 Qwt 根目录的 qwt.pro。第二步，选构建套件（Kit），选 Desktop Qt 5.x MSVC2010 还是 MinGW，决定编出来的库是哪一家。

第三步是改配置。双击打开 qwtbuild.pri，找到这一行，前面加 # 注释掉：

bash
# CONFIG           += debug_and_release

第四步，点绿色三角，编 Release 或 Debug。

第三步是关键。debug_and_release 会让 qmake 一次生成两套规则，MinGW 下混编容易报错，注释掉它按单配置编。

产物不在源码目录，在工程外部的构建目录里，名字类似 D:\build-qwt-Desktop_Qt_5_5_0_MinGW_32bit-Debug\。插件在构建目录的 designer\plugins\designer\ 下。

一定要拷出去的那几样 #

编完不等于能用。库在源码目录（或构建目录）里躺着，Qt 的编译器、链接器、Designer 都不知道它在。要按类别拷到 Qt 套件里。以 Qt 5.1 套件路径 D:\Software\Qt\Qt5.1.0\5.1.0\msvc2010 为例：

拷贝项 从 到 少了的后果
动态库 lib\qwt.dll lib\qwtd.dll ...\msvc2010\bin\ 程序启动报找不到 dll
导入库 lib\qwt.lib lib\qwtd.lib ...\msvc2010\lib\ 链接期报未解析符号
Designer 插件 designer\plugins\designer\qwt_designer_plugin.dll ...\msvc2010\plugins\designer\ 或 ...\Tools\QtCreator\bin\plugins\designer\ Designer 里没有 Qwt Widgets 分组
头文件 src\*.h ...\msvc2010\include\QWT\（新建目录） 编译期报找不到 qwt_plot.h

MinGW 套件把路径里的 msvc2010 换成 mingw48_32 或 mingw492_32，.lib 换成 .a。

Win7 + Qt 5.5 + MinGW 4.9.2 那套，实际落地的路径长这样：

text
D:\Qt\5.5\mingw492_32\bin                ← qwt.dll  qwtd.dll
D:\Qt\5.5\mingw492_32\lib                ← libqwt.a  libqwtd.a
D:\Qt\5.5\mingw492_32\plugins\designer   ← qwt_designer_plugin.dll
D:\Qt\5.5\mingw492_32\include\Qwt        ← 所有 .h

更老的一套（Qt 5.0.1 + MinGW 47_32 + qwt-6.1-rc3），路径换成 D:\Qt\Qt5.0.1\5.0.1\mingw47_32\，插件来源是构建目录：

text
D:\Qt\qwt-6.1-rc3\lib\*.dll                     → mingw47_32\bin
D:\Qt\qwt-6.1-rc3\lib\*.a                       → mingw47_32\lib
D:\Qt\qwt-build-Desktop_Qt_5_0_1_MinGW_32bit-Debug\designer\plugins\designer\
    libqwt_designer_plugin.a  qwt_designer_plugin.dll
                                                → mingw47_32\plugins\designer
D:\Qt\qwt-6.1-rc3\src\*                         → mingw47_32\include\qwt（新建）

这套里有个细节值得注意：头文件是把 src 整个目录下的文件全拷进去，不只 .h，源码里带着 .cpp 的实现文件，拷全了不影响编，拷漏了会缺定义。

顺手把帮助文档装上 #

.qch 那个文件是给 Qt Creator 按 F1 用的，装起来只用一分钟：

  1. 把 qwt-6.1.2.qch 拷到 Qt 的帮助文档目录，例如 D:\Qt\5.5\Docs\Qt-5.5\。
  2. Qt Creator → 工具 → 选项 → 帮助 → 文档。
  3. 点「添加…」，选中那个 .qch，应用。

之后在代码里把光标停在 QwtPlot 上按 F1，API 就出来了。没有它，查一个类要么翻 PDF，要么去搜网页。

六、Qt Creator 的 Designer 插件 #

Qwt 控件出现在 Designer 的控件箱里，靠的是那个插件 .dll / .so。这一步没做对，症状很统一：代码能编，界面上找不到 QwtPlot。

三个目录，别搞混 #

Qt 的安装里同时存在好几个 designer 相关目录，拷错地方就是白拷：

目录 谁来读
<Qt套件>\plugins\designer\ Qt Designer 本体、Qt Creator 内部的界面编辑器
<QtCreator>\bin\plugins\designer\ Qt Creator 自带的 Designer 组件
<QtCreator>\lib\qtcreator\ Qt Creator 进程运行时加载的库

MSVC 的插件是 .dll 加 .lib，两个都得拷；MinGW 是 .dll 一个（有时带 .a）。Linux 是 libqwt_designer_plugin.so，只有一个文件。

拷完必须重启 Qt Creator 才生效。Qtcreator 只在启动时扫插件目录，运行中拷进去不会被发现。

编译器家族对不上，插件加载不了 #

这是 Windows 上最容易卡住的地方。官方发行的 Windows 版 Qt Creator 是用 MSVC 编的，它的插件加载器认 MSVC 的 DLL 格式。你用 MinGW 编出来的 qwt_designer_plugin.dll 拷进去，它加载失败——不报错，就是不出现。

遇到这种情况，不要跟 Qt Creator 死磕，用独立的 Qt Designer 程序编辑 .ui：

  1. 在项目里右键 mainwindow.ui，选「用…打开」→「Qt Designer」。
  2. Qt Designer 起来之后，左侧 Widget Box 拖到底，能看到 Qwt Widgets 分组。
  3. 拖一个 QwtPlot 到界面中间，保存关闭。
  4. 回 Qt Creator 运行工程，二维坐标画布就渲染出来了。

判断插件到底有没有被加载，看 Qt Creator 的「工具 → 选项 → 环境 → 关于插件」，或者启动时加 -widgetcount 之类的调试参数。省事的办法是直接打开 Designer 看控件箱——看得见就是成了。

控件箱在哪个位置 #

Qwt 控件不会插在列表顶部，它在 Widget Box 的最下面，分组名 Qwt Widgets。素材里那位作者的原话是「在 qt designer 左边 widget box 拖到最后 就有了 qwt 控件了」。找不到的时候先滚到底，别急着怀疑装失败。

七、Visual Studio 下使用 Qwt #

VS 里没有 .pro 文件，Qwt 的路径和库名要写进项目属性。三处配置，缺一个都编不过：

位置 填什么
配置属性 → C/C++ → 常规 → 附加包含目录 $(QTDIR)\include\QWT
配置属性 → 链接器 → 输入 → 附加依赖项 qwtd.lib（Debug）/ qwt.lib（Release）
配置属性 → C/C++ → 预处理器 → 预处理器定义 QWT_DLL

第三条最容易漏。不定义 QWT_DLL，头文件里的导入导出宏就按静态库展开，链接时一堆 unresolved external symbol，看着像库没拷对，实际是宏没加。

配置完就能直接写：

cpp
#include <qwt_plot.h>
#include <qwt_plot_curve.h>

Debug 和 Release 要分别配一遍。VS 的属性对话框默认只改当前配置，切到 Release 还得再填一次，或者用「所有配置」下拉。

Qt4 时代还有一套老做法，不走 plugins\designer，而是把插件编出来直接扔进 Qt 安装目录的 plugins\designer：

text
D:\Qt\4.7.4\plugins\designer

那一版插件产物叫 qwtplugin.dll / qwtplugin.lib，跟 6.x 的 qwt_designer_plugin.dll 命名不同。老工程照老名字找文件，别拿 6.x 的教程硬套。

还想让 Qwt 的 dll 在任何目录都能被找到，把 lib 目录加进系统 PATH：

text
D:\qt\qwt\lib

八、在工程里引用 Qwt #

库装好了，工程还得会指。.pro 里的写法就这几行，改动点只有路径：

bash
# 动态库宏，MSVC 下必须，不定义就报未解析符号
DEFINES += QWT_DLL

# 头文件搜索路径
INCLUDEPATH += D:/Software/Qt/Qt5.1.0/5.1.0/msvc2010/include/QWT
DEPENDPATH  += D:/Software/Qt/Qt5.1.0/5.1.0/msvc2010/include/QWT

# 链接库
LIBS += -LD:/Software/Qt/Qt5.1.0/5.1.0/msvc2010/lib -lqwt

路径用正斜杠，别用反斜杠。qmake 在 Windows 上认正斜杠，反斜杠会被当转义符吃掉。

Linux 上的写法多一个 rpath：

bash
INCLUDEPATH += /usr/local/qwt-6.1.0/include
LIBS += -L/usr/local/qwt-6.1.0/lib -lqwt -Wl,-rpath,/usr/local/qwt-6.1.0/lib

-Wl,-rpath,<路径> 把库路径烧进可执行文件，运行时自动去那儿找，不用配 LD_LIBRARY_PATH。动态库不加这一项，程序编得出来，一运行就报 error while loading shared libraries: libqwt.so.6。

MinGW 下把库名换成 .a 那一套：

bash
DEFINES += QT_DLL QWT_DLL
LIBS += -L"D:/Qt/5.5/mingw492_32/lib" -lqwtd
LIBS += -L"D:/Qt/5.5/mingw492_32/lib" -lqwt
INCLUDEPATH += D:/Qt/5.5/mingw492_32/include/Qwt

两行 LIBS 都写上，Debug 走 -lqwtd，Release 走 -lqwt，qmake 按当前配置各取所需。

用 qwt.prf 少写几行 #

Qwt 自带 qmake 特性脚本，路径配好之后可以直接 include：

bash
CONFIG += qwt
include(D:/Works/Qt/QWT/qwt.prf)

或者引它的辅助函数脚本：

bash
include(D:/Works/Qt/QWT/qwtfunctions.pri)

用 qwt.prf 的好处是不用自己拼 INCLUDEPATH 和 LIBS，升级 Qwt 只改 qwt.prf 一处。坏处是路径写死在 .pro 里，换台机器就断，团队协作时容易互相打架。

还有一种纯拷贝派：把 examples 里某个例子的代码直接搬到工程里，连库都链好，只改业务部分。这条路适合刚开始摸 Qwt 的时候抄结构，正式工程还是走 .pro 配置。

运行时找库 #

编过不等于跑得起来。运行时库路径三套解法：

平台 办法
Linux -Wl,-rpath 烧进可执行文件，或 export LD_LIBRARY_PATH=/usr/local/qwt-6.1.0/lib
Windows dll 放在 exe 同目录，或把 lib 加进系统 PATH
两种都行 静态链接，运行时没有外部依赖

Linux 上 LD_LIBRARY_PATH 写进 /etc/profile 是一次性解法，重开终端也还在生效。临时测试就 export 一行。

九、交叉编译到 ARM #

ARM 版和 x86 版是同一个源码，改几个开关就能编。但有一条不能绕：必须用交叉编译工具链把 Qwt 重编一遍，x86 的 libqwt.so 拷到板子上一定跑不起来——指令集不同，动态链接器加载时就失败。

做法是用 Qt Creator 打开 Qwt 的 qwt.pro，构建套件选 ARM-GCC 那一套。选了之后，qmake、编译器、链接器都由这个 Kit 提供，编出来的就是 ARM 目标码。

三处开关要改 #

改 qwtconfig.pri，两处注释、一处放开：

开关 动作 不改的后果
QWT_CONFIG += QwtOpenGL 注释掉 报 qgl.h: No such file or directory
QWT_CONFIG += QwtDesigner 注释掉 报 qwt_designer_plugin.h:23: Error: Undefined interface
QWT_CONFIG += QwtExamples 取消注释 没有 examples/bin，板子上没东西可跑

第一条，具体到文件是这样：

bash
# 交叉编译 arm 版 Qt 时没有 OpenGL 支持
# QWT_CONFIG   += QwtOpenGL

不改的话编译会断在这儿：

text
qwt_plot_glcanvas.h:15:17: fatal error: qgl.h: No such file or directory
compiling qwt_abstract_slider.cpp

qgl.h 属于 Qt 的 OpenGL 模块。你移植到板子上的 Qt 编的时候没开 OpenGL，头文件就没有，Qwt 的 OpenGL 画布编不过。关掉不影响普通 QPainter 绘图。

第二条：

bash
# arm 上不需要 designer plugin
# QWT_CONFIG   += QwtDesigner

不改会报：

text
qwt_designer_plugin.h:23: Error: Undefined interface

插件要链 QtDesigner 模块，交叉编译的 Qt 多数没编这个模块，头文件里的接口声明就悬空。板子上也不装 Designer，这个插件编出来没用。

第三条是给测试用的。默认不编 examples，把注释去掉再 make，examples 下会自动生成 bin 目录，装着一堆 demo 可执行文件。

命令行方式 #

不想开 IDE，命令行也能编，关键是 qmake 必须是交叉工具链那一份：

bash
# 编库
cd qwt-6.1.0/src
qmake
make

# 编示例
cd ../examples
qmake
make

src 和 examples 分开编，是因为示例依赖库。先把 src/lib 下的 .so 拿出来，示例才有得链。

拷到板子上 #

bash
# 库进板子的 Qt 库目录
scp qwt-6.1.0/src/lib/libqwt.so.* root@<板子IP>:/usr/lib/

# 示例进板子
scp -r qwt-6.1.0/examples/bin root@<板子IP>:/opt/qwt-examples/

素材里的路径是开发板上 Qt 库的 /lib 目录。前提是移植 Qt 的时候已经把 Qt 库的环境变量配好了——LD_LIBRARY_PATH 指到那个目录，或者 ldconfig 认过一遍。Qwt 的 .so 放进去，跟 Qt 的库同级，动态链接器才找得到。

examples/bin 里的可执行文件和 src/lib 里的 .so 都拷过去，就能在板子上跑各个例子。

ARM 上多留意的几点 #

项 说明
工具链一致 Qwt、Qt、你的程序，三者必须是同一套交叉工具链和同一个 sysroot
版本一致 板子上跑的 Qt 版本，和你编 Qwt 用的 Qt 版本必须相同
部署路径 .so 放板子的库搜索路径里，或在程序里写 rpath
插件不编 ARM 上不需要 Designer 插件，编了白占空间
示例可编可不编 只为验证，正式出库时关掉

板子上跑不起来，先敲 ldd ./examples/realtime 看缺哪个 .so。缺 libqwt.so.6 就是库没拷对位置，缺 libQt5Widgets.so.5 就是 Qt 的库环境变量没生效。

十、各平台差异对照 #

九篇旧稿讲的是同一套流程，差异全在这张表里：

平台 / 环境 编译器 构建命令 装到哪 动态库 插件
Linux + Qt5（6.1.0） GCC qmake + make + make install /usr/local/qwt-6.1.0 libqwt.so libqwt_designer_plugin.so
Linux + Qt4（5.2.1） GCC Qt Creator 里 run qmake + rebuild 源码目录就地用 libqwt.so designer/plugins/designer/ 下两文件
Windows + MinGW（6.1.2） MinGW 4.9.2 qmake + mingw32-make + install C:\Qwt-6.1.2 qwt.dll qwt_designer_plugin.dll
Windows + MSVC（6.1.0） MSVC 2010 qmake + nmake 源码目录 / 手动拷 qwt.dll + qwt.lib qwt_designer_plugin.dll + .lib
Windows + Qt Creator 随 Kit IDE 内构建 外部构建目录 同上 构建目录 designer\plugins\designer\
ARM 交叉编译 arm-gcc qmake + make 板子 /lib libqwt.so 不编（注释 QwtDesigner）

6.1 与 5.2 的差别 #

跟版本走的东西不多，但每条都能卡你半小时：

项 Qwt 5.2.1 Qwt 6.1.x
插件产物 两个文件，designer/plugins/designer/ 下 一个 qwt_designer_plugin.dll / libqwt_designer_plugin.so
安装前缀变量 qwtconfig.pri qwtconfig.pri（同名，内容不同）
构建开关 少 qwtbuild.pri 里有 debug_and_release，MinGW 下要注释
头文件目录 拷 src/ 里的 .h make install 后自带 include/，直接拷
示例 需单独 qmake 6.1.x 用 QWT_CONFIG += QwtExamples 控制
配 Qt5 不行 6.1.0 起支持 Qt5

5.2.1 那一版是 Qt4 时代的产物，qwtconfig.pri 里的开关布局和 6.x 不一样，照着 6.x 教程找行会找不到。它的插件也确实不是单个 .so，是两个文件一起用。

6.1.0 和 6.1.2 之间的差别小，主要是修 bug 和对新 Qt 的适配。6.1.0 声明支持 Qt 4.8 以上和 Qt5，Qt 5.5 环境下用 6.1.2 更省事。

十一、验证安装是否成功 #

装完之后按顺序过五道检查，哪一道断就回哪一章。

检查 命令 / 动作 通过标准
1. 文件齐不齐 ls <前缀>/include ls <前缀>/lib ls <前缀>/plugins/designer 三样都在
2. qmake 对不对 qmake -v 版本与你目标 Qt 一致
3. 工程能不能编 空工程 #include <qwt_plot.h> 编译通过
4. 链接能不能过 .pro 里加 LIBS += -lqwt 链接通过，无未解析符号
5. Designer 认不认 打开 Designer 看控件箱 出现 Qwt Widgets 分组

三样东西，三种坏法 #

这是整篇最该记住的一张表。Qwt 装完要拷三样东西，少哪一样，症状完全不同：

缺什么 症状出现的时机 具体报错
缺头文件（include/） 编译期 fatal error: qwt_plot.h: No such file or directory
缺库（.lib / .a / .so） 链接期 undefined reference to QwtPlot::... 或 LNK2019
缺插件（designer/...） 设计期，代码照编 Designer 里没有 Qwt 控件，代码里 new 一切正常
缺运行时 dll / so 运行期 程序起不来，报找不到 libqwt.so.6 / qwt.dll

按报错出现的时机反推缺什么，比翻教程快得多。编译期报找不到头文件，去查 INCLUDEPATH；链接期报未解析符号，去查 LIBS 和 QWT_DLL 宏；运行期报加载失败，去查 PATH / LD_LIBRARY_PATH / rpath；只有界面里看不到控件，才是插件的问题。

用示例做终检 #

examples 里的 realtime 是最省事的验证目标，它把曲线、坐标轴、定时刷新全走了一遍：

bash
# Linux 装完后
cd /usr/local/qwt-6.1.0/examples
./realtime

窗口起来、曲线开始滚动，说明头文件、库、运行时路径三样全对。这个例子挂了，别去改自己的业务代码，先回来排查安装。

版本自查清单 #

装完最后一件事是对一遍版本，四者必须一条线：

text
qmake -v                  → QMake version / Using Qt version
Qt Creator 关于对话框      → 基于哪个 Qt 编的
Designer 的关于对话框      → 同上
Qwt 源码包版本             → 与上面匹配

素材里那位作者的踩坑记录值得抄一遍：Linux 里同时装了 Qt4 和 Qt5，编 Qwt 时版本没统一，出一堆不兼容问题，把版本一一统一之后问题就消失了。这不是运气，是机制。

十二、易错点速查 #

按症状排，遇到直接对号。

现象 原因 处理
Unknown module(s) in QT: svg qmake 用的 Qt 不带 svg，或与目标 Qt 版本不一致 换成目标 Qt 的 qmake，重新 qmake qwt.pro
Unknown module(s) in QT: designer 缺 QtDesigner 开发包 sudo apt-get install qttools5-dev*
qgl.h: No such file or directory Qt 没编 OpenGL，或交叉编译时无 OpenGL qwtconfig.pri 注释 QwtOpenGL
qwt_designer_plugin.h:23: Error: Undefined interface 交叉编译的 Qt 没有 Designer 模块 qwtconfig.pri 注释 QwtDesigner
Designer 里没有 Qwt 控件 插件没拷到对的目录，或没重启 Qt Creator 按第六章三个目录对号，拷完重启
MinGW 编的插件在 Qt Creator 里不出现 官方 Windows QtCreator 是 MSVC 编的，加载不了 MinGW DLL 用独立 Qt Designer 打开 .ui
链接报 unresolved external symbol 没定义 QWT_DLL，或库格式/位数不对 .pro 加 DEFINES += QWT_DLL，核对编译器家族与位数
编译报找不到 qwt_plot.h 没拷头文件，或 INCLUDEPATH 写错 拷 include/ 到 include/QWT，路径用正斜杠
程序启动报找不到 libqwt.so.6 运行时库路径没配 加 -Wl,-rpath，或设 LD_LIBRARY_PATH
Windows 上程序启动报找不到 qwt.dll dll 不在 exe 旁边也不在 PATH 拷 dll 到 exe 同目录，或把 lib 加进 PATH
MinGW 下 debug_and_release 报错 一次生成两套规则，MinGW 混编出问题 qwtbuild.pri 里注释 CONFIG += debug_and_release
编译中途大量报错 上次失败留下的 .o 残留 Qt Creator 里 clean all 后 run qmake 再编
ARM 上程序起不来 用了 x86 的 libqwt.so，或 Qt 版本不一致 用交叉工具链重编，核对板子上的 Qt 版本
make install 后找不到装哪了 没看 QWT_INSTALL_PREFIX 回 qwtconfig.pri 看那一行

这张表里出现频次最高的是三条：qmake 版本选错、QWT_DLL 宏漏定义、插件拷错目录。三条都不涉及技术难点，全是路径和名字没对上。

把这三条记住，Qwt 的安装就没什么神秘的了：它就是一套必须由你自己编、编完必须按三类文件分别部署、每一类都跟编译器和版本绑死的库。装一次摸清路径，第二次换机器照着抄表就行。
