本篇只讲 QPainter 的进阶部分：路径怎么组合、渐变怎么铺、图层怎么合成、双缓冲怎么摆、文字怎么排。

一、QPainterPath：复合路径 #

先把结论摆出来：QPainterPath 是「可以用布尔运算组合的图形」，不是「一串画图命令」。

这个区别决定了整篇的写法。drawLine / drawRect / drawEllipse 是一次性动作，画完什么都没留下。路径是一个对象，它把几何形状存下来，之后能被填充、被描边、被拿去裁剪、被和其他路径求交并差。所以复杂形状都该用路径，别拿一堆图元去拼。

为什么要强调这个。举个最常见的需求：一个圆角标签，左边要挖个半圆缺口。用 drawRect + drawEllipse 拼，你得算好两个图形边缘怎么对齐，缺口处还得用背景色再盖一块矩形，一旦背景是渐变或者图片，盖色就露馅。用路径，一条 subtracted() 就完事，一路 drawPath 下去，填充色、边框、裁剪都是同一份几何。路径的骨架是「子路径 + 当前点」，QPainterPath 内部维护一个 currentPosition()，lineTo() 从当前点画直线到目标点，cubicTo() / quadTo() 画三次、二次贝塞尔曲线，画完当前点就移到终点。

moveTo() 不产生任何绘制，它只把当前点搬走，等于结束上一个子路径、开一个新的。closeSubPath() 则是画一条直线回到本子路径的起点，并把路径标记为闭合。

构造一块形状，能用的接口就这些：

接口 作用 备注
moveTo(p) 移动当前点，开新子路径 不产生线段
lineTo(p) 直线到 p 从 currentPosition() 起
cubicTo(c1, c2, p) 三次贝塞尔 两个控制点 + 终点
quadTo(c, p) 二次贝塞尔 一个控制点 + 终点
arcTo(rect, start, span) 圆弧 角度以度为单位，逆时针为正
closeSubPath() 闭合当前子路径 连回起点
addRect() / addEllipse() 加入矩形、椭圆 各自成为独立子路径
addPolygon() 加入多边形 Qt::WindingFill 传入时按填充规则闭合
addText(x, y, font, text) 把文字转成轮廓 每条笔画都是一个子路径
addRegion() 把 QRegion 转成路径 用于不规则位图区域
addPath(other) 并入另一个路径 只是拼起来，不做布尔运算
connectPath(other) 用一条直线连到另一个路径起点后并入 适合串接曲线

一个箭头，走一遍上面这些接口：

cpp
QPainterPath path;
path.moveTo(10, 100);
path.cubicTo(10, 100, 100, 10, 200, 70);
path.lineTo(200, 50);
path.lineTo(220, 80);
path.lineTo(200, 110);
path.lineTo(200, 90);
path.cubicTo(200, 100, 100, 50, 50, 100);

QPainter painter(this);
painter.setRenderHint(QPainter::Antialiasing);
painter.setPen(QPen(QColor(255, 0, 0), 2));
painter.setBrush(QColor(255, 0, 0, 40));
painter.drawPath(path);

setPen 决定轮廓，setBrush 决定填充，drawPath 一次画完。想只描边不填充，setBrush(Qt::NoBrush)；想只填充不描边，setPen(Qt::NoPen)。

填充规则：OddEvenFill 与 WindingFill #

路径相交的时候，哪些区域算「内部」，由填充规则决定。默认是 Qt::OddEvenFill。

奇偶规则的说法很直白：从待判定的点向外画一条水平线，数它穿过路径边界的次数，奇数次就在内部，偶数次在外部。所以两个同心圆放进同一个路径，内圈就成了洞——射线穿两次，是偶数。

Qt::WindingFill 换成绕数规则：看边界绕这个点转了几圈，绕数非零就算内部。两个同向的同心圆用绕数规则，内圈照样是实心的；把内圈反向（比如用逆序的 addEllipse 或用 arcTo 反着走），绕数抵消，洞又回来了。

cpp
QPainterPath ring;
ring.addEllipse(QPointF(100, 100), 80, 80);
ring.addEllipse(QPointF(100, 100), 40, 40);
// 默认 OddEvenFill：中间的圆是洞
painter.drawPath(ring);

ring.setFillRule(Qt::WindingFill);
// 同向子路径：整个圆盘都被填满
painter.drawPath(ring);

判断规则落在代码里就一句 path.setFillRule(Qt::WindingFill)。别小看它，后面讲布尔运算和挖洞都靠这个开关。

路径的度量与判定 #

路径能自己回答几何问题，不用你再维护一份数据。

函数 返回 用途
boundingRect() 精确包围盒 布局、定位，慢
controlPointRect() 含控制点的包围盒 快速估算，比上面快一个量级
isEmpty() 是否为空 空路径绘制是空操作
elementCount() / elementAt(i) 路径元素数量与第 i 个元素 序列化、调试
contains(pt) / contains(rect) 点或矩形是否在路径内 命中测试
intersects(rect) 与矩形是否有交集 脏区判断
toFillPolygon() 转成一个 QPolygonF 交给其他库
toSubpathPolygons() 每个子路径转一个多边形 逐块处理
percentAtLength() / pointAtPercent() 按长度比例取点 沿路径做动画
angleAtPercent() 该点处的切线角度 让箭头贴着路径转

boundingRect() 和 controlPointRect() 的差别值得记一下：曲线段真实外轮廓会小于控制点撑开的框。做裁剪、贴图时用前者，做「占多大地方」的估算用后者。

只想要轮廓：QPainterPathStroker #

路径本身没有宽度，宽度是 QPen 给的。如果你需要「描边之后的那一圈形状」——比如给文字加描边、给选区做外扩、把一个细路径加粗成可填充的实体——那就得把笔宽烘焙进几何。

QPainterPathStroker 干这事：

cpp
QPainterPathStroker stroker;
stroker.setWidth(8);
stroker.setJoinStyle(Qt::RoundJoin);
stroker.setCapStyle(Qt::RoundCap);
QPainterPath outline = stroker.createStroke(path);

createStroke() 返回的是「填充这块就是描边效果」的闭合路径。之后可以拿它做裁剪、做布尔运算、做碰撞检测。直接 drawPath 加粗笔也能看，但你的到不了几何层面。

二、路径的布尔运算 #

单个路径解决不了「从 A 里扣掉 B」，这就轮到布尔运算。

四个函数，接口都收一个 const QPainterPath &，返回新路径：

方法 语义 典型场景
united(p) 并集：A ∪ B 两个形状连成一块
intersected(p) 交集：A ∩ B 只保留重叠部分
subtracted(p) 差集：A − B 挖洞、开缺口
simplified() 自身化简 消除自交、合并重叠的子路径

对应的运算符也重载了：+= 等于 addPath，-= 等于 subtracted，&= 等于 intersected，|= 等于 united。

一条环形用差集写出来，比前面那个奇偶填充的版本更能说明问题：

cpp
QPainterPath outer;
outer.addEllipse(QPointF(120, 120), 90, 90);

QPainterPath inner;
inner.addEllipse(QPointF(120, 120), 45, 45);

QPainterPath ring = outer.subtracted(inner);
painter.setPen(Qt::NoPen);
painter.setBrush(QColor(0, 120, 215));
painter.drawPath(ring);

差集版本有两个好处：结果是「真的没有那块几何」，不是靠填充规则糊出来的；导出的路径拿去任何地方用都一致，包括裁剪、contains() 命中测试、转成多边形给别的库。

几个必须知道的点。

第一，布尔运算按填充规则判定内外。也就是说，参与运算的路径如果自己内部有洞，那些洞也会参与结果。运算前先把规则设清楚，别让两边的 fillRule 打架。

第二，未闭合的子路径会被隐式闭合。你画了一条开放折线去做 subtracted，Qt 会先把它首尾连上再算。开放路径做差集，结果往往不是你以为的形状。

第三，布尔运算比拼接贵。它要做几何求交，子路径越多越慢。别放进 paintEvent 每帧重算，算一次缓存起来。

第四，结果路径的子路径数量会增加，elementCount() 会明显变大。做序列化或者频繁比较时留意这一点。

挖洞的两种做法 #

同一个需求——一个矩形中间挖个圆——有两条路。

用奇偶填充：把圆当成第二个子路径塞进同一个路径，fillRule 保持 OddEvenFill，圆就成了洞。代码最短，一次 drawPath。

cpp
QPainterPath hole;
hole.addRect(0, 0, 200, 200);
hole.addEllipse(QPointF(100, 100), 40, 40);
// OddEvenFill 下，中间那块自动变成洞

用差集：rectPath.subtracted(circlePath)。代码长一点，但结果是干净的闭合轮廓，拿去 QPainterPathStroker 加边、拿去 setClipPath 裁剪都不会出意外。

经验分界：只是在屏幕上画，用奇偶填充；要把结果当几何数据继续用，用差集。

布尔运算与抗锯齿的关系 #

有个坑得提前说。两个路径做并集，边界处会出现「重叠边的抗锯齿叠加」问题吗。不会——united() 返回的是一个单一路径，绘制时按整体抗锯齿处理，内部那些原来的公共边已经不存在了。

但如果你不做并集，直接连着画两个半透明图形，公共边会出现一条比周围更暗的细线，因为两笔的半透明像素叠了一次。这种接缝在渐变背景上极其显眼。解决办法就是并集，或者干脆关掉抗锯齿画整数像素对齐的矩形。

cpp
// 错：接缝
painter.setBrush(QColor(0, 0, 0, 128));
painter.drawRect(0, 0, 100, 100);
painter.drawRect(100, 0, 100, 100);

// 对：并成一块
QPainterPath a, b;
a.addRect(0, 0, 100, 100);
b.addRect(100, 0, 100, 100);
painter.drawPath(a.united(b));

三、渐变：线性、径向与锥形 #

渐变是 QGradient 的子类，而 QGradient 能被 QBrush 直接吃进去。所以用法永远是三步：造渐变、塞停靠点、setBrush。

cpp
QLinearGradient g(0, 0, 200, 0);
g.setColorAt(0.0, Qt::red);
g.setColorAt(1.0, Qt::blue);
painter.fillRect(rect(), g);   // fillRect 直接收 QBrush，渐变隐式转换

setColorAt(stop, color) 的 stop 是 0 到 1 之间的比例，不是像素，也不是角度。0 是起点，1 是终点，中间随便插。插几个点就是几段，颜色在相邻两点之间线性插值。

停靠点要按升序设。乱序设进去，Qt 文档里的说法是行为未定义，实测多数版本是画出一堆硬边。想省事就先把点排序再 setColorAt。

三个子类都从 QGradient 拿到两个公共开关。

setSpread() 决定超出渐变范围之后怎么继续：

值 行为
QGradient::PadSpread 默认。端点颜色往外延展，平涂
QGradient::RepeatSpread 重复整个渐变
QGradient::ReflectSpread 镜像来回反射

setCoordinateMode() 决定坐标怎么解释：

值 坐标基准
QGradient::LogicalMode 默认。走 painter 的逻辑坐标，受变换矩阵影响
QGradient::ObjectBoundingMode 相对被填充对象的包围盒，取值 0 到 1
QGradient::ObjectMode 相对对象包围盒，用绝对坐标

ObjectBoundingMode 在做可复用组件时好用：同一个 QBrush 存成成员，控件大小变了也不用重算渐变。

线性渐变 QLinearGradient #

两个控制点定方向，颜色沿这条线插值。

cpp
QLinearGradient linearGradient(0, 0, 200, 100);
linearGradient.setColorAt(0.0, Qt::red);
linearGradient.setColorAt(0.5, Qt::green);
linearGradient.setColorAt(1.0, Qt::blue);
painter.setBrush(linearGradient);
painter.drawRect(0, 0, 200, 100);

两点连线决定的不只是方向，还有渐变长度。(0,0) 到 (200,0) 是 200 像素铺完，(0,0) 到 (0,100) 是竖向 100 像素铺完，(0,0) 到 (200,100) 是斜着铺，两点的垂直等值线才是色带。

控制点之外的部分，PadSpread 下用端点色继续平涂。所以填充区的实际尺寸大于两点距离也不会出现透明边。方向反了或者两个控制点重合（零长度），渐变会退化成一片纯色，而且不报警。颜色不对时先打印两个控制点看看。

径向渐变 QRadialGradient #

三个参数：圆心、半径、焦点。

cpp
QRadialGradient radialGradient(QPointF(200, 190), 50, QPointF(275, 200));
radialGradient.setColorAt(0.0, QColor(255, 255, 100, 150));
radialGradient.setColorAt(1.0, QColor(0, 0, 0, 50));
painter.setBrush(radialGradient);
painter.drawEllipse(QPointF(200, 190), 50, 50);

圆心加半径定出一个圆。焦点是颜色的「零点」，停靠点 0 落在焦点上，停靠点 1 落在圆周上，颜色在两者之间插值。

焦点在圆心时，得到的是标准的同心圆光晕，适合做按钮高光、指示灯。焦点挪到圆边附近，光晕就偏心，像球体从侧上方被打光——立体感的来源就在这一个参数上。

焦点跑到圆外是合法的，Qt 会照算，只是靠近那一侧的色带被压得极扁。想让高光更「散」，就把半径放大、焦点留在圆心。setSpread() 在这里同样管用，RepeatSpread 会变成一圈圈的同心环。

锥形渐变 QConicalGradient #

两个参数：圆心、起始角。

cpp
QConicalGradient conicalGradient(QPointF(350, 190), 60);
conicalGradient.setColorAt(0.2, Qt::cyan);
conicalGradient.setColorAt(0.9, Qt::black);
painter.setBrush(conicalGradient);
painter.drawEllipse(QPointF(350, 190), 50, 50);

角度单位是度，范围 0 到 360。颜色沿逆时针、从给定角度开始绕着圆心插值。停靠点是「绕了多少圈的比例」，0 和 1 在同一个角度上重合。

锥形渐变天生是环形的，所以填充矩形时四角会被硬切。它适合做仪表盘刻度盘、色轮、加载环，不适合做面板底色。

三个类型的对照：

类型 构造参数 颜色走向 典型用途
QLinearGradient 起点、终点 沿两点连线插值 面板底色、进度条、卡片阴影
QRadialGradient 圆心、半径、焦点 从焦点向圆周发散 光晕、按钮高光、球体
QConicalGradient 圆心、起始角 绕圆心逆时针旋转插值 色轮、仪表盘、加载环

三个类都是 QGradient 的子类，setColorAt / setSpread / setCoordinateMode 全部通用。切类型时只改构造函数那一行。

四、图案填充 QBrush #

QBrush 管两件事：填什么颜色，用什么模式填。

构造函数的完整清单看着吓人，理一遍就清楚了：

cpp
QBrush();                                              // 空画刷，NoBrush
QBrush(const QColor &color, Qt::BrushStyle style = Qt::SolidPattern);
QBrush(Qt::GlobalColor color, Qt::BrushStyle style = Qt::SolidPattern);
QBrush(const QPixmap &pixmap);                          // 纹理
QBrush(const QImage &image);                            // 纹理
QBrush(const QGradient &gradient);                      // 渐变
QBrush(const QBrush &other);

四个属性藏在里面：样式 style、颜色 color、渐变 gradient、纹理 texture。

style 由 Qt::BrushStyle 枚举给出。默认值是 Qt::NoBrush，意思是不填。新手把 setBrush 忘了、或者只设了颜色没设样式，看到的就是一片空白——先查这个。

枚举分三组：

组 取值 说明
不填充 Qt::NoBrush 默认值，只画轮廓
实心 Qt::SolidPattern 纯色填充，用得最多
图案 Qt::Dense1Pattern 到 Qt::Dense7Pattern、Qt::HorPattern、Qt::VerPattern、Qt::CrossPattern、Qt::BDiagPattern、Qt::FDiagPattern、Qt::DiagCrossPattern 点、线、斜线的组合，密度从密到疏
渐变 Qt::LinearGradientPattern、Qt::RadialGradientPattern、Qt::ConicalGradientPattern 配合 gradient() 生效
纹理 Qt::TexturePattern 配合 texture() 生效

图案填充的粒度是固定的 8×8 像素单元，不随变换缩放，做脏污纹理、禁用态斜纹够用，做精细质感不行。

gradient() 只在样式是三种渐变之一时才起作用。直接 QBrush(QLinearGradient(...)) 构造，样式会自动设成 LinearGradientPattern，不用手写。

texture() 同理，setTexture() 一调用，style() 自动切成 Qt::TexturePattern。这一点文档写得很清楚，实际写代码时也确实是这个行为，所以设纹理不需要先改样式。

纹理的来源可以是 QPixmap，也可以是 QImage，后者用 setTextureImage()：

cpp
QBrush brush(QColor(0, 0, 255), Qt::Dense4Pattern);
painter.setBrush(brush);
painter.drawEllipse(220, 20, 50, 50);

brush.setTexture(QPixmap(":/images/pattern.png"));   // 自动变 TexturePattern
painter.setBrush(brush);

static const QPointF points[4] = {
    QPointF(270.0, 80.0),
    QPointF(290.0, 10.0),
    QPointF(350.0, 30.0),
    QPointF(390.0, 70.0)
};
painter.drawPolygon(points, 4);

纹理从设备的坐标原点开始平铺，图案的相位跟绘制位置无关，只跟笔刷的变换有关。想让纹理跟着图形走，用 QBrush::setTransform() 或者在外面套一层 painter.translate()：

cpp
QBrush tiled(QPixmap(":/tile.png"));
QTransform t;
t.translate(12, 8);          // 挪一下纹理相位
tiled.setTransform(t);
painter.fillRect(rect(), tiled);

图片文件找不到时 QPixmap 是空的，QBrush 拿到空 pixmap 就退化成不填。加载失败不报错，就是画不出来——路径写错了先检查 QPixmap::isNull()。

颜色侧：QColor 支持 RGB、HSV、CMYK 三种模型，也支持 SVG 1.0 里的颜色名。RGB 是面向硬件的，HSV 更贴近人眼的感觉（色调 0–359，饱和度 0–255，亮度 0–255），CMYK 是给打印机用的。QColor 还能带 alpha 做半透明填充，这条留到第八章细讲。

QPen：轮廓的另一半 #

填充靠 QBrush，轮廓靠 QPen。一个图形想好看，这两个得一起调。

QPen 的属性有五个：线型、线宽、颜色（或画刷）、端点风格、连接风格。构造时可以一次给全，也可以逐项 set。

cpp
// 一次给全：代码短，参数顺序靠记
QPen pen(Qt::green, 3, Qt::DashDotLine, Qt::RoundCap, Qt::RoundJoin);
painter.setPen(pen);

// 逐项设：啰嗦，改哪一项一眼看得出
pen.setStyle(Qt::DashDotLine);
pen.setWidth(3);
pen.setBrush(Qt::green);
pen.setCapStyle(Qt::RoundCap);
pen.setJoinStyle(Qt::RoundJoin);

线型 Qt::PenStyle 六个值：

值 效果
Qt::SolidLine 实线，默认
Qt::DashLine 虚线
Qt::DotLine 点线
Qt::DashDotLine 点划线
Qt::DashDotDotLine 双点划线
Qt::CustomDashLine 自定义，配合 setDashPattern()

自定义虚线得给一个「实、虚、实、虚」的长度序列，单位是线宽而不是像素：

cpp
QPen pen;
pen.setStyle(Qt::CustomDashLine);
QVector<qreal> dashes;
dashes << 4 << 2 << 1 << 2;   // 实 4 虚 2 实 1 虚 2，单位是笔宽
pen.setDashPattern(dashes);

序列里的奇数位是实线段，偶数位是空档，循环使用。线宽改了，虚线的视觉长度跟着变，这就是「单位是线宽」的含义。

端点风格 Qt::PenCapStyle 三种，只对线宽大于 1 的线有可见差别：

值 端点
Qt::FlatCap 平头，端点正好停在坐标上
Qt::SquareCap 方头，端点外扩半个笔宽
Qt::RoundCap 圆头，端点外扩半个笔宽且是半圆

FlatCap 和 SquareCap 的差别就半个笔宽，画对齐到像素的表格线时能看出来：用 FlatCap 更贴边。

连接风格 Qt::PenJoinStyle 四种，线宽大于等于 1 就生效：

值 拐角
Qt::MiterJoin 尖角，两条边延长相交
Qt::BevelJoin 斜切，拐角被切平
Qt::RoundJoin 圆角

MiterJoin 在极小锐角上会炸出一根很长的刺（斜接长度趋向无穷）。Qt 内部有斜接限制，太尖时自动退化成 BevelJoin，多数场景不用管。真被刺到了，换 BevelJoin 或 RoundJoin。

一个完整的画笔驱动绘制：

cpp
void MyWidget::paintEvent(QPaintEvent *)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing);

    painter.drawLine(0, 0, 100, 100);          // 默认画笔

    QPen pen(Qt::green, 5, Qt::DashLine, Qt::FlatCap, Qt::RoundJoin);
    painter.setPen(pen);

    QRectF rectangle(70.0, 40.0, 80.0, 60.0);
    int startAngle = 30 * 16;                  // 单位是 1/16 度
    int spanAngle = 120 * 16;
    painter.drawArc(rectangle, startAngle, spanAngle);

    pen.setWidth(2);                           // 同一个 pen 改属性
    pen.setStyle(Qt::SolidLine);
    painter.setPen(pen);
    painter.drawRect(50, 50, 20, 100);
}

drawArc 的角度单位是 1/16 度，这是 Qt 保留下来的老约定，30 * 16 就是 30 度。弧的起点在三点钟方向，逆时针为正。drawPie 和 drawChord 用同一套角度约定。

五、图层合成：CompositionMode #

前面所有绘制都在干一件事：把源像素盖到目标像素上。这个「盖」的规则就是合成模式，默认 QPainter::CompositionMode_SourceOver。

SourceOver 是最符合直觉的叠加：源有 alpha，目标在下面透出来。alpha 为 255 时完全盖住，alpha 为 0 时什么都不发生。日常画图全是这个模式，所以很少有人注意到它其实是个可选项。

改成别的模式，绘制行为就完全变了。

模式 语义 典型用途
SourceOver 默认叠加 一切常规绘制
SourceIn 只保留源与目标重叠的部分，透明度相乘 用形状当遮罩切图
SourceOut 只保留源在目标之外的部分 从目标里剪掉源的形状
DestinationIn 只保留目标与源重叠的部分 圆角化、异形裁剪
DestinationOut 从目标里扣掉源的形状 挖洞、擦除
DestinationOver 源画在目标之下 画背景层
Clear 把目标区域清成全透明 橡皮擦
Xor 异或混合 对比度强的临时高亮
Plus 相加，越叠越亮 光斑、火焰叠加
Multiply 相乘，越叠越暗 阴影、染色
Screen 反乘，越叠越亮 发光、去黑底
Darken / Lighten 取各通道的暗/亮值 图层混合

SourceIn 和 DestinationIn 只差一个词，方向完全相反，这是最容易搞反的一对：

  • SourceIn 的结果在源的坐标系里，目标只是拿来提供 alpha。
  • DestinationIn 的结果在目标里，源当作剪刀。

做圆角头像时用的是 DestinationIn：先把照片画进离屏图，再画一个圆角矩形，模式设成 DestinationIn，照片就被圆角矩形剪成圆角。原因很直接——你要留下的是照片（目标），剪它的是圆角形状（源）。

cpp
QPixmap rounded(int size, int radius)
{
    QPixmap out(size, size);
    out.fill(Qt::transparent);

    QPainter p(&out);
    p.setRenderHint(QPainter::Antialiasing);
    p.setRenderHint(QPainter::SmoothPixmapTransform);

    // 第一层：目标，照片铺满
    p.drawPixmap(0, 0, size, size, m_source);

    // 第二层：源，圆角矩形当剪刀
    p.setCompositionMode(QPainter::CompositionMode_DestinationIn);
    QPainterPath clip;
    clip.addRoundedRect(QRectF(0, 0, size, size), radius, radius);
    p.fillPath(clip, Qt::black);

    return out;
}

注意 fillPath 用的是 Qt::black。在 DestinationIn 里颜色通道不参与结果，只有 alpha 有意义，用黑用白都一样。写上 Qt::black 是为了让读代码的人立刻明白「这里只关心形状」。

挖洞是同一套思路反着来：

cpp
// 从已经画好的内容里扣掉一个圆
p.setCompositionMode(QPainter::CompositionMode_DestinationOut);
p.setBrush(Qt::black);
p.setPen(Qt::NoPen);
p.drawEllipse(QPointF(120, 120), 40, 40);

擦除用 Clear，效果等于把目标区域重置成全透明：

cpp
p.setCompositionMode(QPainter::CompositionMode_Clear);
p.setPen(Qt::NoPen);
p.setBrush(Qt::black);      // Clear 模式下颜色无所谓
p.drawEllipse(mousePos, 20, 20);

三个必须记住的约束。

第一，合成模式只在同一个绘制设备内部生效。你在 widget 上设 SourceIn，它不会去和父窗口、和桌面合成，目标只有这块 widget 自己的像素缓冲。想要和后面的窗口内容混合，得走窗口透明那条路，看第八章。

第二，目标必须已经画过东西。在空白 widget 上直接 SourceIn，目标是空的，结果也是空的——看起来就是「什么都没画出来」。这类 bug 排查起来很绕，先用离屏图把目标层铺好再合成，一眼就能定位。

第三，模式是 painter 的状态，会一直保留到下次设置。setCompositionMode(SourceIn) 之后忘了改回来，后面的文字、边框全部失效。能成对写就成对写：

cpp
p.save();
p.setCompositionMode(QPainter::CompositionMode_DestinationIn);
p.fillPath(clip, Qt::black);
p.restore();

六、双缓冲与离屏绘制 #

这一节解决最典型的症状：自绘控件一刷新就闪。

原因不神秘。paintEvent 里逐个图元往下画，屏幕（或者窗口系统的缓冲）在绘制过程中被一块块改。人眼看到的是中间状态：先是一块白底，然后出现矩形，再出现曲线。update() 触发得越频繁，这种半成品帧越多。

Qt 的 QWidget 从 Qt 4 起自带 backing store，正常情况下把一帧画完再整体刷到屏幕上，闪烁已经轻很多。但两种场景它救不了你：一个是自绘内容很重、单帧耗时超过两个刷新周期，update() 追不上，照样看到撕裂；另一个是你需要透明、需要跨控件合成，widget 自己的缓冲不给你这个机会。

解法就是自己离屏：把复杂内容画到 QImage 或 QPixmap 上，paintEvent 里只做一次 drawPixmap 贴上去。

代价是内存和多一次拷贝，换到的是「一帧只有一次贴图」，没有中间态。

关键在缓存策略。缓存不能只建一次，也不能每帧重建：

cpp
class GaugeWidget : public QWidget
{
public:
    explicit GaugeWidget(QWidget *parent = nullptr) : QWidget(parent) {}

protected:
    void resizeEvent(QResizeEvent *e) override
    {
        m_cacheValid = false;
        QWidget::resizeEvent(e);
    }

    void setValue(qreal v)
    {
        if (qFuzzyCompare(m_value, v))
            return;
        m_value = v;
        m_cacheValid = false;   // 内容变了才作废
        update();
    }

    void paintEvent(QPaintEvent *) override
    {
        if (!m_cacheValid || m_cache.size() != size() * devicePixelRatioF()) {
            rebuildCache();
            m_cacheValid = true;
        }
        QPainter p(this);
        p.drawPixmap(0, 0, m_cache);
    }

private:
    void rebuildCache()
    {
        const qreal dpr = devicePixelRatioF();
        m_cache = QPixmap(size() * dpr);
        m_cache.setDevicePixelRatio(dpr);
        m_cache.fill(Qt::transparent);

        QPainter p(&m_cache);
        p.setRenderHint(QPainter::Antialiasing);
        p.setRenderHint(QPainter::TextAntialiasing);
        drawDial(p);            // 所有重活都在这里，一帧只干一次
    }

    void drawDial(QPainter &p);

    QPixmap m_cache;
    bool    m_cacheValid = false;
    qreal   m_value = 0;
};

三个细节值钱。

m_cache.size() != size() * devicePixelRatioF() 这一句是给高 DPI 用的。不乘 dpr，缓存永远是 1 倍分辨率，贴到 2 倍屏上就糊。

setDevicePixelRatio() 必须跟着设。不设的话 drawPixmap(0, 0, m_cache) 会按物理像素画，缓存被画成两倍大。

resizeEvent 里作废缓存，别忘了调基类。窗口尺寸变化是最高频的缓存失效来源。

QImage 和 QPixmap 怎么选，看下面的表：

维度 QImage QPixmap
存储位置 应用内存，像素可读可写 由窗口系统管理，不能直接读像素
线程 可以在非 GUI 线程绘制（文字除外） 必须在 GUI 线程
I/O 为读写像素优化 不适合做像素操作
显示 要转成 QPixmap 才快 为屏幕显示优化
隐式共享 支持 支持

一句话：后台线程算图用 QImage，屏幕上贴图用 QPixmap。QPixmap 的数据用户拿不到，QImage 的能拿到；要在绘制之后做逐像素处理、或者塞进工作线程，只能选 QImage。

QImage 的常用接口分四类，用得上的记下来：

类别 函数 说明
几何 width() / height() / size() / rect() 尺寸与包含矩形
几何 valid(x, y) 坐标是否在图内
几何 offset() / setOffset() 与其他图像的相对偏移
几何 dotsPerMeterX() / dotsPerMeterY() 物理分辨率
颜色 pixel(x, y) / setPixel(x, y, rgb) 取/设单像素，返回 QRgb
颜色 pixelIndex() / color(i) / setColor(i, c) 索引图像取色
颜色 colorTable() / colorCount() 调色板与条目数
颜色 hasAlphaChannel() 是否带 alpha
颜色 allGray() / isGrayscale() 能否安全转灰度
文字 text(key) / setText(key, v) / textKeys() 附属元数据
低级 depth() / format() 位深与存储格式
低级 bytesPerLine() / sizeInBytes() 每行字节数、总字节数
低级 scanLine(y) / bits() 行首指针、首像素指针
低级 cacheKey() 唯一标识，用于缓存判断

载入和保存走这几条路：构造函数传路径、load()、loadFromData()、静态的 fromData()；保存用 save()。能读写的格式用 QImageReader::supportedImageFormats() 和 QImageWriter::supportedImageFormats() 查，别假设 PNG、JPG 之外的都能读。

存储格式决定像素怎么解释，动像素之前先 convertToFormat()：

格式 含义
QImage::Format_Mono 单色，高位在前（MSB）
QImage::Format_MonoLSB 单色，低位在前（LSB）
QImage::Format_Indexed8 8 位索引，256 色调色板
QImage::Format_RGB32 32 位，无 alpha
QImage::Format_ARGB32 32 位，带 alpha，非预乘
QImage::Format_ARGB32_Premultiplied 32 位，alpha 已预乘，绘制最快

8 位和单色图用颜色索引表存，setPixel() 改的是索引值，要改颜色得 setColor()。32 位图直接存 ARGB，QRgb 就是 0xAARRGGBB 这个无符号整数。

预乘格式是最容易踩的坑：Format_ARGB32_Premultiplied 里 RGB 已经乘过 alpha 再除以 255，直接读出来的数值不是原色。做像素级处理前后各来一次 convertToFormat()，别在预乘缓冲区上算颜色。

交互绘图还有一套双缓冲写法，逻辑是多开一块临时缓冲：把图像缓冲拷进临时缓冲，在临时缓冲上画这一笔的临时内容，画完再回写图像缓冲；没有正在进行的交互，就直接把图像缓冲贴到屏幕。

cpp
void DrawingWidget::paintEvent(QPaintEvent *)
{
    QPainter p(this);
    if (m_dragging) {
        // 交互中：先贴图像缓冲，再叠临时缓冲
        p.drawImage(0, 0, m_canvas);
        p.drawImage(0, 0, m_temp);
    } else {
        p.drawImage(0, 0, m_canvas);
    }
}

void DrawingWidget::mousePressEvent(QMouseEvent *e)
{
    m_dragging = true;
    m_temp = m_canvas;              // 拷贝当前内容
    m_last = e->pos();
}

void DrawingWidget::mouseMoveEvent(QMouseEvent *e)
{
    if (!m_dragging)
        return;
    QPainter p(&m_temp);            // 在临时缓冲上画预览
    p.setPen(QPen(Qt::darkGray, 1, Qt::DashLine));
    p.drawRect(QRect(m_last, e->pos()).normalized());
    update();
}

void DrawingWidget::mouseReleaseEvent(QMouseEvent *e)
{
    m_dragging = false;
    QPainter p(&m_canvas);          // 确认结果落到图像缓冲
    p.drawRect(QRect(m_last, e->pos()).normalized());
    m_temp = QImage();
    update();
}

为什么不用异或笔。Qt 4 起不再提供异或笔，CompositionMode_Xor 不是当年那个「画两遍就擦掉」的东西，它做的是像素异或混合，颜色会跟着背景变，效果完全不可控。要矩形、直线的拖拽反馈，直接用 QRubberBand，它是 Qt 专门为这个场景留的控件；要自定义的反馈图形，就用上面这套临时缓冲。

反过来的需求也存在：有人想关掉系统双缓冲，自己管绘制。一句 setAttribute(Qt::WA_PaintOnScreen) 就关了，代价是闪烁问题全归你。

cpp
myWidget->setAttribute(Qt::WA_PaintOnScreen);

配 WA_OpaquePaintEvent 一起用能省一次背景擦除——前提是你的 paintEvent 真的把每个像素都覆盖了，漏一块就是花屏。

QPaintDevice 家族里，QPainter 能在这些设备上画：

设备 特点 场景
QWidget 屏幕控件 自绘控件
QImage 硬件无关，像素可访问，可跨线程 离屏合成、图像处理
QPixmap 屏幕显示优化，数据不可见 缓存、贴图
QBitmap 单色 pixmap 掩码、自定义光标
QPicture 记录并重放 QPainter 指令 图形录制、跨设备复用
QPrinter 打印机，X11 上走 PostScript 报表、PDF 导出
QSvgGenerator 输出 SVG 矢量导出

想自己实现绘图设备，得从 QPaintDevice 继承并实现 paintEngine()，同时写一个 QPaintEngine 子类。这条路上没人走，知道有这么回事就够。

QPicture 值得单独提一句，因为它能录能放：

cpp
QPicture picture;
picture.load("mypicture.pic");

QPainter painter(this);
painter.drawPicture(0, 0, picture);   // 在 (0,0) 重放全部指令
// picture.play(&painter); 等价写法

录制就是正常画，只是 painter 构造在 QPicture 上。存下来的是平台无关的指令流，与分辨率无关，同一份 QPicture 打到屏幕、PDF、打印机上都能正确缩放。图标、矢量装饰用它很划算：录一次，到处重放。

七、裁剪区域 #

裁剪的意思是「后面的绘制只在这块区域里生效」。三个入口：

cpp
painter.setClipRect(QRectF(0, 0, 100, 100));
painter.setClipPath(path);           // 任意形状
painter.setClipRegion(region);       // 多个矩形的并集

裁剪是 painter 的状态，和合成模式一样会一直保留。每设一次裁剪，就要有一次 restore() 兜底，否则后面所有绘制（包括文字）都被限制在那一小块里。这是自绘控件里出现频率最高的 bug 之一。

cpp
painter.save();
painter.setClipPath(roundedPath);
painter.drawImage(0, 0, m_photo);    // 只在圆角区域内出现
painter.restore();

painter.drawText(10, 30, tr("说明文字"));   // 恢复后正常绘制

裁剪和合成模式解决的是两件不同的事，别混用：

手段 影响的层 边缘 代价
裁剪 绘制范围，像素根本不会被写入 硬边，不抗锯齿 低，容易硬件加速
合成模式 像素混合，画了但结果被丢弃或混合 可抗锯齿 中，需要读回目标像素
遮罩（mask） 窗口级别的可见性 硬边 低，但平台相关

要抗锯齿的边缘，用合成模式或 setMask 之外的办法，裁剪的边界永远是硬的。

裁剪在性能上有正面价值。paintEvent 收到的事件带一个 rect()，那是系统算出来的脏区，只重绘这一块就已经省掉大半工作：

cpp
void paintEvent(QPaintEvent *e) override
{
    QPainter p(this);
    p.setClipRect(e->rect());        // 只画脏区
    // ... 绘制全量内容，超出脏区的部分被裁掉
}

内容复杂而脏区小的时候，这一句能把每帧耗时压到原来的零头。前提是你的绘制代码不做和面积无关的重活（比如每帧重新构造渐变、重新 load 图片）。裁剪还能省掉手工算坐标：画一个圆角进度条，填充部分只到某个比例，与其自己算圆角被截断后的形状，不如让路径动手。

cpp
QPainterPath bar;
bar.addRoundedRect(QRectF(0, 0, 300, 12), 6, 6);

painter.save();
painter.setClipPath(bar);                    // 整条轨道都限制在圆角内
painter.fillRect(QRectF(0, 0, 300, 12), trackBrush);
painter.fillRect(QRectF(0, 0, 300 * m_ratio, 12), progressBrush);
painter.restore();

两个矩形都是直角，但被圆角路径一裁，两端自然圆了。这个套路在进度条、图片裁切、滚动容器里到处能用。

八、图像合成与透明 #

Alpha 通道就是透明度，取值 0 到 255：0 完全透明，255 完全不透明。QColor 的第四个参数就是它。

平台支持上有一句老话要交代：Windows、macOS 和带 XRender 扩展的 X11 上，Qt 都支持 alpha 通道。X11 的 alpha 走的就是 XRender，没有这个扩展的老服务器上，半透明会退化成不透明。

窗口级别的透明是另一个东西。QWidget::setWindowOpacity(qreal level) 设的是整个窗口的不透明度，原理和 alpha 通道不同：Windows 和 macOS 上可用，X11 上要靠 Composite 扩展。它作用于整个窗口，不会区分你画的内容。

要做「窗口背景透明、只留自己画的形状」，得走这条路：

cpp
setAttribute(Qt::WA_TranslucentBackground);
setWindowFlags(Qt::FramelessWindowHint);

然后 paintEvent 里只画需要的形状，没画到的地方保持透明。不规则窗口、圆形悬浮球、带阴影的面板都这么做。

半透明图形叠在彩色背景上，容易出现「颜色不对」的错觉。原因多半是预乘格式：Format_ARGB32_Premultiplied 上的 RGB 已经是乘过 alpha 的值，直接当颜色读就偏暗。做像素运算前后各转一次格式。

QBitmap 是单色 pixmap，专门干掩码的活：给 QRegion 提供形状、给窗口设 mask、给 QCursor 做形状、给 QBrush 做纹理。它只有两色，1 位表示，所以做不了抗锯齿边缘。

QImage 也提供直接的 alpha 操作：

cpp
QImage img(":/photo.png");
QImage mask(":/mask.png");                 // 灰度图当遮罩

img.setAlphaChannel(mask.convertToFormat(QImage::Format_Alpha8));
// 或者用一个形状现算
QImage alpha = img.createAlphaMask(Qt::MaskInColor);

createAlphaMask() 从图像本身算 alpha，createHeuristicMask() 猜一个能裁掉边框的掩码。两个都适合快速处理带纯色背景的素材图。

叠图最稳的写法是这一套：目标缓冲 fill 透明 → 画底图 → 换合成模式 → 画上层 → 恢复。裁剪限范围、setOpacity() 压整层透明度、最后用 DestinationIn 统一裁形，圆角、异形、遮罩、渐隐全在这五步里拆得出来。

setOpacity() 和 alpha 是互补的两个工具：setOpacity 作用于「这一批绘制」的整体，一次设好，之后每笔都按这个比例压透明度；alpha 是单笔颜色的属性。做淡入淡出动画，改 setOpacity 最省事。

九、文字排版与对齐 #

文字在 QPainter 里有三层：QFont 描述想要什么字体，QFontInfo 告诉你实际拿到了什么，QFontMetrics 给出排版需要的度量。

QFont 里写的是「请求」。系统没有这个字体时，Qt 会找最接近的已装字体，QFontInfo::exactMatch() 返回 false。所以字体名写错不会报错，只是默默换了字体，行高、字宽全变。

cpp
QFont font("Noto Sans CJK SC", 12);
font.setBold(true);
painter.setFont(font);

QFontInfo info(font);
if (!info.exactMatch())
    qWarning() << "字体没匹配上，实际用了" << info.family();

QFontDatabase 能列出系统里所有可用字体族，做字体选择器时用它；QApplication::setFont() 设应用级默认字体，控件没单独设过就跟着它走。选中的字体里缺某个字符时，Qt 会逐字符回退到其他字体。回退也找不到，画出来是一个空心方块——「豆腐块」。看到方块的唯一解释是字体缺字，不是编码问题，换个带全字符集的字体就解决。

绘制文字的主力是 drawText，它有好几个重载，选错一个就白折腾：

重载 行为
drawText(QPointF p, const QString &t) 从 p 开始画，p 是基线左端
drawText(const QRectF &r, int flags, const QString &t) 在矩形内按 flags 对齐，不换行除非给了换行 flag
drawText(const QRect &r, int flags, const QString &t, QRect *br) 同上，额外回填实际占用矩形
drawText(const QRectF &r, const QString &t, QTextOption) 用 QTextOption 描述对齐与换行

最常用的是矩形加 flags 这个版本。flags 是位或的组合：

flag 作用
Qt::AlignLeft / Qt::AlignRight / Qt::AlignHCenter 水平对齐
Qt::AlignTop / Qt::AlignBottom / Qt::AlignVCenter 垂直对齐
Qt::AlignCenter 水平垂直都居中，等于前两者的组合
Qt::TextWordWrap 按词换行，超长单词不拆
Qt::TextWrapAnywhere 任意位置换行，长串也能断
Qt::TextSingleLine 强制单行，换行符变空格
Qt::TextElideRight 超宽时右侧省略号

AlignVCenter 和 AlignCenter 的差异在中文场景会显现：AlignCenter 以整个矩形为基准，AlignVCenter 是同一个意思；但真正让文字看起来「偏上」的是行高——QFontMetrics::height() 里包含了上伸和下伸，视觉中心不在几何中心。抠得细就把基线算出来，用点版本绘制：

cpp
QFontMetrics fm(painter.font());
int baseline = (rect.height() + fm.ascent() - fm.descent()) / 2;
painter.drawText(QPointF(rect.left(), rect.top() + baseline), text);

排版之前先量。QFontMetrics::boundingRect() 和 QPainter::boundingRect() 都能在画之前算出占多大，先算后画比先画后补稳：

cpp
QRect need = fm.boundingRect(QRect(0, 0, 200, 1000),
                             Qt::TextWordWrap | Qt::AlignLeft,
                             longText);
// need.height() 就是换行后的实际高度，据此决定控件高度或分页

度量里常用的几个：

函数 含义
ascent() / descent() 基线以上、以下的高度
height() / leading() 行高（含行间距）、行间距
horizontalAdvance(s) 字符串宽度（Qt 5.11 起替代 width()）
boundingRect(s) 字符串外框
elidedText(s, mode, width) 按宽度生成带省略号的文本
lineSpacing() 行距

省略号不用自己截，交给 elidedText：

cpp
QString shown = fm.elidedText(title, Qt::ElideRight, labelRect.width());
painter.drawText(labelRect, Qt::AlignLeft | Qt::AlignVCenter, shown);

需要复杂排版——分栏、富文本、文字环绕——就别在 paintEvent 里手算了。多行按宽度断行用 QTextLayout，富文本用 QTextDocument::drawContents()。这两个都能吃 QPainter，输出位置精确可控。

文字还能变成路径。addText() 把字形轮廓塞进 QPainterPath，之后随你怎么填：

cpp
QLinearGradient linearGrad(QPointF(200, 0), QPointF(1000, 0));
linearGrad.setColorAt(0.0, Qt::black);
linearGrad.setColorAt(1.0, Qt::white);

QFont font("隶书", 80);
font.setBold(true);

QPainterPath textPath;
textPath.addText(200, 300, font, tr("电子工业出版社"));

painter.setPen(Qt::NoPen);
painter.setBrush(linearGrad);
painter.drawPath(textPath);

addText 的前两个参数是文字基线的起点，不是左上角。字太大跑到画布外，先查这两个数。

文字抗锯齿单独有一个开关：QPainter::TextAntialiasing。开了 Antialiasing 不等于开了它，两个要分别设。小字号在低 DPI 屏上开文字抗锯齿会发虚，大字号不开会有锯齿，按场景定。

十、绘制性能与取舍 #

先记住渲染提示这张表，它不是「全开就快」的开关，每一项都在拿质量换时间。

提示 作用 代价
QPainter::Antialiasing 图形边缘抗锯齿 中等，曲线和路径明显变慢
QPainter::TextAntialiasing 文字抗锯齿 低
QPainter::SmoothPixmapTransform 图像缩放走双线性插值，不走近邻 中高，大图缩放显著变慢
QPainter::LosslessImageRendering 打印时按原始分辨率渲染 只对打印有意义
QPainter::NonCosmeticBrushPatterns 画刷图案随变换缩放 低

不开抗锯齿的斜线是阶梯状的，开了就顺滑——但 45 度以外的细线会变灰、变淡，因为覆盖不足一个像素的线被平均掉了。1 像素宽的网格线要么关掉抗锯齿，要么对齐到半像素坐标（0.5 偏移），二选一。

优化的顺序有讲究，从收益最大往下排：

顺序 手段 收益
1 缓存不变内容，paintEvent 只贴图 最大，从每帧重画变每帧一次拷贝
2 只画脏区，setClipRect(e->rect()) 大，尤其内容复杂时
3 减少状态切换：合并同色绘制，减少 setPen / setBrush 中
4 把静态层和动态层分开缓存 中，动画场景显著
5 换设备：QGraphicsView 或 OpenGL 大，但架构要改

状态切换是真有成本。setPen 不是赋值，它要把笔的设置下发到绘图引擎，重建画笔的缓存。一个循环里画一千条线、每条都换一次颜色，性能就掉在这上面。按颜色分组画，或者改用一次 drawLines 画整批——批量接口比循环单次调用快得多，这是 Qt 绘图里最实在的一条优化。

坐标变换的接口有五个：translate() 平移、rotate() 旋转、scale() 缩放、shear() 错切，worldTransform() 取当前矩阵。全部走 save() / restore() 的栈式管理，画一个转起来的图标就是 save() → 平移到中心 → rotate() → 平移回去 → 画 → restore()，走完坐标系原样还原。

QTransform 是 3×3 矩阵，m11/m22 是缩放，m12/m21 是错切，dx/dy 是平移。Qt 4.3 引入 QTransform 之后，老代码里的 QMatrix 逐渐退场，QTransform 支持透视变换，toAffine() 能退化成 QMatrix（透视数据会丢）。设备无关的绘图标配是窗口/视口变换：setWindow() 把逻辑坐标映射到矩形，setViewport() 指定落在设备的哪块区域。

cpp
painter.setWindow(QRect(-100, -100, 200, 200));   // 逻辑坐标 -100..100

现在画 (-100, -100) 就落在设备左上角，代码里再也不用管控件多大、打印机能打多宽。窗口和视口都是线性映射，不做裁剪——超出范围的内容只是被映射到外面去了。

十一、自绘控件的实践 #

前面所有零件拼起来，就是一个自绘控件。骨架长这样：

cpp
class BadgeWidget : public QWidget
{
    Q_OBJECT
    Q_PROPERTY(QString text READ text WRITE setText)
public:
    explicit BadgeWidget(QWidget *parent = nullptr);

    QString text() const { return m_text; }
    void setText(const QString &t);

    QSize sizeHint() const override;

protected:
    void paintEvent(QPaintEvent *e) override;
    void resizeEvent(QResizeEvent *e) override;

private:
    void invalidate();

    QString m_text;
    bool    m_hover = false;
    QPixmap m_cache;
    bool    m_cacheValid = false;
};

sizeHint() 给布局一个建议尺寸，minimumSizeHint() 给下限。不实现的话控件默认就是 (0,0)，塞进 QHBoxLayout 会被压成一条缝——这是自绘控件第一个「不显示」的原因。

cpp
QSize BadgeWidget::sizeHint() const
{
    QFontMetrics fm(font());
    return QSize(fm.horizontalAdvance(m_text) + 24, fm.height() + 12);
}

paintEvent 里只有三件事：取缓存、贴缓存、按需重建。

cpp
void BadgeWidget::paintEvent(QPaintEvent *)
{
    if (!m_cacheValid || m_cache.size() != size() * devicePixelRatioF()) {
        const qreal dpr = devicePixelRatioF();
        m_cache = QPixmap(size() * dpr);
        m_cache.setDevicePixelRatio(dpr);
        m_cache.fill(Qt::transparent);

        QPainter p(&m_cache);
        p.setRenderHint(QPainter::Antialiasing);
        p.setRenderHint(QPainter::TextAntialiasing);

        // 背景取调色板，别写死颜色
        const QColor bg = palette().color(QPalette::Highlight);
        const QColor fg = palette().color(QPalette::HighlightedText);

        QPainterPath shape;
        shape.addRoundedRect(QRectF(rect()).adjusted(1, 1, -1, -1), 8, 8);
        p.fillPath(shape, m_hover ? bg.lighter(110) : bg);

        p.setPen(fg);
        p.setFont(font());
        p.drawText(rect(), Qt::AlignCenter, m_text);

        m_cacheValid = true;
    }

    QPainter p(this);
    p.drawPixmap(0, 0, m_cache);
}

paintEvent 里三件事不要做：不要 new 控件、不要 load 图片文件、不要构造 QFont 和 QPainterPath 之外的重量级对象。这些东西放在构造函数里，或者放进缓存重建的路径里。颜色一律从 palette() 取，写死 Qt::white 的控件，用户切到深色主题就是一块白板；要跟随系统强调色，QPalette::Highlight 是正解。

enterEvent / leaveEvent 里改 m_hover，然后 invalidate()，缓存作废、update() 触发重画。状态驱动的控件，所有视觉差异都该落在一个 bool 上。

需要跟原生风格保持一致时，别自己画背景，把 QStyleOption 交给 style()->drawPrimitive(QStyle::PE_Widget, ...)，背景、边框、禁用态、焦点框全由当前主题决定，你只管自己的内容。想彻底不吃原生风格，就在构造函数里 setAttribute(Qt::WA_OpaquePaintEvent) 自己全包。

缓存失效点要列全，漏一个就是画面不更新：

触发 处理
resizeEvent 缓存作废（尺寸变了）
内容 setter 缓存作废
changeEvent（字体、调色板、样式） 缓存作废
hover / press 状态变化 缓存作废
高 DPI 迁移 缓存作废

用 update() 而不是 repaint()：前者把多次请求合并成一次重绘，后者立刻同步重画，在鼠标移动事件里调它就是自己给自己制造卡顿。

十二、易错点速查 #

现象 原因 修法
图形画不出来 QBrush 默认 Qt::NoBrush 显式 setBrush(Qt::SolidPattern) 或设颜色
只画了轮廓没填充 setBrush 忘了，或传了 Qt::NoBrush 检查 brush
半透明图形边缘有暗线 相邻图形各自画一次，公共边叠加 用 united() 并成一条路径
文字挤在一起 用了点版本的 drawText 换矩形加 flags 的重载
文字画到框外 点版本传的是基线，不是左上角 用矩形版本，或自己算基线
圆角处出现白边 先裁形再画，边缘未被覆盖 先画内容，再 DestinationIn 裁
合成后什么都没了 目标层是空的 先把目标层画进离屏图
SourceIn 和 DestinationIn 结果反了 两者方向相反 想保留谁，就用谁的 In
后面所有绘制都被切掉 setClipPath 没配对 restore 成对写 save/restore
控件不显示 没实现 sizeHint() 返回一个合理尺寸
控件一刷新就闪 每帧重画全部图元 缓存到 QPixmap，只贴图
高 DPI 屏上发糊 缓存没乘 devicePixelRatio 尺寸乘 dpr，再 setDevicePixelRatio
缓存画出来两倍大 设了 dpr 但绘制坐标也乘了 绘制用逻辑坐标，dpr 只作用于位图

渐变方向反了 起终点顺序反了 交换两个点
纹理不显示 QPixmap 加载失败 查 isNull() 和资源路径
图案填充位置对不上 纹理从设备原点铺 用 QBrush::setTransform() 平移
虚线看不出效果 线宽是 1 线宽加到 2 以上
端点风格没差别 线宽是 1，FlatCap 与 SquareCap 重合 加粗线宽
圆锥渐变硬边 0 和 1 位置颜色不同 两处设同一个颜色
半透明颜色偏暗 在预乘格式上直接读 RGB 先 convertToFormat
文本框里全是方块 字体缺字 换带完整字符集的字体
线程里画文字崩溃 QFont 依赖底层 GUI 文字回主线程，或用 QPainterPath
鼠标移动时卡顿 用了 repaint() 换 update()
打印结果和屏幕不一致 没用窗口/视口映射，硬编码像素 setWindow() 做逻辑坐标

几条压箱底的：

QPainter 一次只能有一个活跃实例作用在同一个设备上。重复构造第二个 painter 去画同一块 widget，Qt 会打一行 QPainter::begin: A paint device can only be painted by one painter at a time，然后什么都不画。begin() 失败一定要查返回值：自定义设备或者后台缓冲正在被别的 painter 占用时，QPainter p(device) 构造完 isActive() 是 false，之后的调用全是空操作，不崩不报错，静悄悄地丢掉所有绘制。

坐标全用浮点。QPainter 内部按浮点算，int 重载会在边界处产生半像素偏移，1 像素线画成 2 像素灰线就是这么来的。要整数像素就把线对齐到 0.5。

QPainterPath 建一次，存成员，别在 paintEvent 里反复 addEllipse。路径构建要做几何计算和内存分配，每帧重建等于每帧都做无用功——这也是第十节那条「缓存优先」的具体落点。
