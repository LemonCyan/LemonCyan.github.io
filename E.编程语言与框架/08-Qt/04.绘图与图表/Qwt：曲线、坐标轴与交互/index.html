上一篇把 Qwt 装进了 Qt 工程，这一篇讲装完之后怎么画出能看的东西。主线有五步：挂曲线、喂数据、配坐标轴、加图例、鼠标缩放平移。走通这五步，日常用法就覆盖了大半。

本篇范围 讲什么：QwtPlot 的容器模型、QwtPlotCurve 的挂载与数据源、QwtAxis 与 QwtScaleDiv/QwtScaleDraw 两层坐标轴、QwtLegend 的可点击图例、QwtPlotZoomer/QwtPlotPanner/QwtPlotMagnifier 三件套鼠标交互，以及刷新与易错点。 不讲什么：编译安装、库目录结构、统计类图表、QChart 与 QPainter 自绘路线，各有一篇。 跨篇指路：选型犹豫先看同目录选型篇；想要类似效果但排斥 Qwt，看 QCustomPlot 三篇；只画静态示意图，QPainter 两篇更轻。

一、QwtPlot 的结构 #

先把心智模型钉死：QwtPlot 是一块画布加一张可绘项清单，它自己不会画任何数据。

曲线、网格、标记全是「可绘项」（QwtPlotItem 的子类）。你 new 出来，attach() 挂到 QwtPlot 上，QwtPlot 在重绘时遍历清单，让每个项把自己画到画布坐标系里。detach() 摘下来，它就不在清单里了，自然画不出来。这条规则没有例外，新手最常见的「代码跑通了但界面全白」，九成是忘了 attach。

结构可以拆成四层：

组成 类型 职责
画布 QwtPlotCanvas QFrame 派生的绘制面，接收鼠标事件，管背景与边框
布局 QwtPlotLayout 算画布区、四条轴区、标题区、图例区各占哪块矩形
坐标轴 QwtScaleWidget × 4 四条边各一个，管轴范围、刻度、标签
可绘项清单 QwtPlotItemList 所有挂上来的项，按 z 序与 rtti 管理

QwtPlot 继承自 QWidget，但把绘制交给画布、把排版交给布局。所以换画布调 setCanvas()、调对齐调 plotLayout()->setAlignCanvasToScales()，都是在这两层上动手。

可绘项清单 #

QwtPlotItem 靠 rtti() 分类，靠 setZ() 定前后遮挡。常用子类：

类 rtti 用途
QwtPlotCurve Rtti_PlotCurve 折线、阶梯线、散点、样条
QwtPlotGrid Rtti_PlotGrid 主/次网格线
QwtPlotMarker Rtti_PlotMarker 单点标记、水平/垂直参考线
QwtPlotHistogram Rtti_PlotHistogram 直方图
QwtPlotBarChart Rtti_PlotBarChart 柱状图
QwtPlotIntervalCurve Rtti_PlotIntervalCurve 带上下界的区间带
QwtPlotSpectrogram Rtti_PlotSpectroCurve 热力图、频谱图
QwtPlotShapeItem Rtti_PlotShape 任意多边形、路径
QwtPlotTextLabel Rtti_PlotTextLabel 画布内文字

遍历已挂的项用 itemList()，参数是 rtti 过滤条件：

cpp
QwtPlotItemList curves = itemList( QwtPlotItem::Rtti_PlotCurve );
qDebug() << "curve count =" << curves.size();   // 画布上挂了几条曲线

不传参数就是全部可绘项。返回的是副本，删项不会让它失效，但里面的指针会悬空。

所有权与生命周期 #

QwtPlot 不接管可绘项的所有权。你 new 的 QwtPlotCurve 归你管，QwtPlot 只记了个指针。兜底在析构：QwtPlotItem 的析构函数里自动调 detach()，所以只要宿主销毁时把项一起 delete，就不会留野指针。惯用写法是成员变量持有，宿主析构时统一 delete。

反过来，setCanvas() 接管画布、insertLegend() 接管图例、setAxisScaleDraw() 接管自绘刻度对象，这三个由 QwtPlot 负责销毁，别自己再 delete 一遍。

一个最小的宿主类 #

这个类把「一块画布 + 若干可绘项」落成代码，逻辑全在构造函数里，main() 直接 show() 就能看到图。

cpp
// plotlines.h
#define QWT_DLL   // 动态链接 Qwt 时必须定义，否则符号导入导出对不上

#include <qwt_plot.h>          // 基类
#include <qwt_plot_layout.h>   // 布局
#include <qwt_plot_canvas.h>   // 画布
#include <qwt_plot_curve.h>    // 曲线
#include <qwt_plot_grid.h>     // 网格
#include <qwt_plot_zoomer.h>   // 缩放，panner/magnifier 同目录同风格
#include <qwt_plot_picker.h>   // 取值，配 qwt_picker_machine.h
#include <qwt_legend.h>        // 图例，配 qwt_legend_label.h
#include <qwt_symbol.h>        // 符号点

class PlotLines : public QwtPlot
{
    Q_OBJECT
public:
    explicit PlotLines( QWidget *parent = nullptr );

private Q_SLOTS:
    void showItem( const QVariant &itemInfo, bool on );   // 点击图例切可见性
};

main() 里 PlotLines line; line.resize( 600, 400 ); line.show(); 三行就能出窗口。工程文件补两行，路径按自己的安装位置改。调试版链 qwtd，Release 链 qwt，混链会在运行期崩在构造函数里：

text
INCLUDEPATH += D:/Qt/Qt5.15.2/5.15.2/msvc2019_64/include/Qwt
LIBS        += -L D:/Qt/Qt5.15.2/5.15.2/msvc2019_64/lib -lqwt

二、挂一条曲线 #

QwtPlotCurve 是 Qwt 里用得最多的项。用法只有三步：new、喂数据、attach。顺序可以换，但 attach 必须在第一次 replot() 之前完成。

cpp
QwtPlotCurve *curve = new QwtPlotCurve( "curve" );   // 构造参数就是图例上的名字
curve->setPen( Qt::blue, 2 );
curve->setRenderHint( QwtPlotItem::RenderAntialiased, true );
curve->setSamples( points );   // QPolygonF 或 QVector<QPointF>
curve->attach( this );         // 挂到本 QwtPlot

setTitle() 与构造参数等价，中途改名用前者，记得重绘才生效：

cpp
curve->setTitle( QString( "信道 %1" ).arg( channelIndex + 1 ) );

要不要上图例，由 Legend 属性控制，默认开着：

cpp
curve->setItemAttribute( QwtPlotItem::Legend, true );   // 上图例
curve->setItemAttribute( QwtPlotItem::Legend, false );  // 不上图例
curve->setLegendAttribute( QwtPlotCurve::LegendShowLine );  // 图例里画线，不画点

setLegendAttribute() 还能取 LegendShowSymbol 或两者按位或。只设线不设符号，图例里就是一个纯色小横杠。

摘下来与隐藏 #

cpp
curve->detach();              // 从清单移除，曲线消失，对象还在
curve->attach( this );        // 再挂回去
curve->setVisible( false );   // 不摘，只是不画

setVisible(false) 的项在图例里也一起消失，因为 QwtLegend 跟 QwtPlotItem 的可见性绑定。想让图例项留着、曲线不画，得自己接管图例的显示逻辑。

不 attach 会怎样 #

不报错、不警告，编译链接全过，运行起来就是一块空白画布——QwtPlot 压根不知道有这个对象存在。同理，attach 到 A 却对 B 调 replot()，也是空白。一个项同一时刻只属于一个 QwtPlot，往第二个 attach 会先自动从第一个摘掉。

三、给曲线喂数据 #

QwtPlotCurve 不存业务数据，它存的是 QwtSeriesData<QPointF> 的指针。setSamples() 是一组语法糖，内部替你包一层数据源。弄清这层包装，实时刷新的性能问题就有解了。

cpp
void setSamples( const QVector<QPointF> &samples );
void setSamples( const QPolygonF &samples );
void setSamples( const QVector<double> &xData, const QVector<double> &yData );
void setSamples( QwtSeriesData<QPointF> *data );   // 接管所有权

最后那个重载是关键：传进去的数据源对象由曲线负责 delete。前面几个重载内部就是这么做的，包一层 QwtPointArrayData 或 QwtPointSeriesData 塞进去。

一次性数据 #

数据量小、画完不动，直接怼 QPolygonF；X 和 Y 分开算就传两个数组：

cpp
QPolygonF points1;
points1 << QPointF( 1, 1 ) << QPointF( 2, 2 ) << QPointF( 3, 3 )
        << QPointF( 4, 4 ) << QPointF( 5, 5 ) << QPointF( 6, 6 );
curve->setSamples( points1 );

QVector<double> xs, ys;
for ( int i = 0; i < 500; ++i )
{
    xs.append( i * 0.01 );
    ys.append( std::sin( i * 0.01 ) );
}
curve->setSamples( xs, ys );

两个数组长度必须一致。短的会被截断，长的部分直接丢掉，不报警告。

流式数据 #

实时波形要不断追加点。每来一个点就 setSamples() 一次，等于每帧重建整个数组，几千点就开始卡。正确做法是继承 QwtSeriesData<QPointF>，让曲线直接读你的环形缓冲：

cpp
class RingSeries : public QwtSeriesData<QPointF>
{
public:
    explicit RingSeries( int cap ) : m_buf( cap ), m_cap( cap ) {}

    void append( const QPointF &p )
    {
        m_buf[ m_head ] = p;
        m_head = ( m_head + 1 ) % m_cap;
        if ( m_count < m_cap ) ++m_count;
    }

    virtual size_t size() const override { return m_count; }

    virtual QPointF sample( size_t i ) const override
    {
        const int start = ( m_head - m_count + m_cap ) % m_cap;   // 起点随写入滑动
        return m_buf[ ( start + int( i ) ) % m_cap ];
    }

    // 自动缩放和 zoomer 的边界都读它，每帧都会调
    virtual QRectF boundingRect() const override
    {
        if ( !m_count ) return QRectF();
        QRectF r( sample( 0 ), sample( 0 ) );
        for ( size_t i = 1; i < m_count; ++i )
            r |= QRectF( sample( i ), sample( i ) );
        return r;
    }

private:
    QVector<QPointF> m_buf;
    int m_head = 0, m_count = 0, m_cap;
};

挂上去时曲线接管所有权，自己不 delete。boundingRect() 里别做全量扫描之外的二次计算，缓存一个增量维护的 QRectF 更稳。

cpp
RingSeries *series = new RingSeries( 4096 );
QwtPlotCurve *wave = new QwtPlotCurve( "wave" );
wave->setSamples( series );
wave->attach( this );

数据丢进去却没画出来 #

现象 查什么
位置全挤在左下角 轴范围还是默认的 [0, 1000]
曲线在画布外 数据不在 setAxisScale() 给的区间内
曲线是空的 setSamples() 传了空容器，或长度不一致被截断
图例里有、画布上没有 setVisible(false)，或 z 序被压住

第一项最常见。默认范围是 [0, 1000]，喂一百个 0 到 1 的数据点，只占左下角一丝。要么 setAxisScale()，要么开自动缩放。

四、坐标轴：QwtAxis 与 ScaleDiv #

坐标轴这块最容易糊。Qwt 把它拆成两层，很多「我明明设了范围怎么没用」的问题，都是把两层搞混了。先看第一层，四条轴的身份：

cpp
enum Axis
{
    yLeft  = 0,    // 左侧纵轴
    yRight = 1,    // 右侧纵轴
    xBottom = 2,   // 底部横轴
    xTop   = 3,    // 顶部横轴

    axisCnt = 4    // 轴的总数，不是某条轴
};

QwtPlot::yLeft、QwtPlot::xBottom 这些常量就是给下面所有 API 当第一个参数用的。axisCnt 常被误当成一条轴传进去，它只该出现在 for ( int i = 0; i < QwtPlot::axisCnt; i++ ) 里。四条轴默认只显示 yLeft 和 xBottom 的刻度标签，另外两条要手动打开：

cpp
enableAxis( QwtPlot::yRight, true );
enableAxis( QwtPlot::xTop, true );

两层职责 #

层 类 管什么 改它的 API
轴本身 QwtAxis（QwtPlot::Axis + QwtScaleWidget） 范围、可见性、位置、标题、颜色、宽度 setAxisScale()、setAxisAutoScale()、enableAxis()
刻度划分 QwtScaleDiv 轴上打哪些刻度点，分主刻度与次刻度 setAxisScaleDiv()
刻度绘制 QwtScaleDraw 刻度点怎么画成线、刻度值怎么变成文字 setAxisScaleDraw()、enableComponent()

一句话分工：改范围动第一层，改刻度分布动 ScaleDiv，改刻度长相动 ScaleDraw。

三者是单向关系：QwtScaleDiv 由 QwtScaleEngine 按范围算出来，QwtScaleDraw 拿着它去画。你手动塞一个 ScaleDiv 进去，就把「算」这一步跳过了。

第一层：设范围 #

cpp
setAxisTitle( QwtPlot::yLeft,   "ylabel" );
setAxisTitle( QwtPlot::xBottom, "xlabel" );
setAxisScale( QwtPlot::yLeft,   0.0, 10.0 );
setAxisScale( QwtPlot::xBottom, 0.0, 10.0 );
setAxisScale( QwtPlot::xBottom, 0.0, 100.0, 10.0 );   // 第 4 参是主刻度步长提示

不想算范围，交给引擎按数据自动定：

cpp
setAxisAutoScale( QwtPlot::yLeft, true );

自动缩放会读所有可绘项的 boundingRect()，取并集再加边距。这条路上有两个坑：任何一项的 boundingRect() 返回空，整条轴就退回默认范围，自定义 QwtSeriesData 时必须实现好它；开了自动缩放就别再对同一条轴调 setAxisScale()，两者互相打架，后调的赢，下次重绘又会被覆盖。

还有一条硬限制：自定义了 QwtScaleDraw 的轴不能同时开自动缩放。自动缩放会重算 ScaleDiv，而你自定义的 label() 假设了一个固定刻度序列。要自定义刻度，就手动 setAxisScale()。

第二层：自己定刻度 #

QwtScaleDiv 装三组刻度值，按 QwtScaleDiv::TickType 索引：MajorTick（长刻度，带标签）、MediumTick（中刻度）、MinorTick（短刻度），NTickTypes 是组数。构造一个自定义 ScaleDiv 挂上去，就能精确控制哪几处出现长刻度、哪几处只有短刻度：

cpp
void DataDisplay::setAxisTick()
{
    QList<double> ticks[ QwtScaleDiv::NTickTypes ];

    // 长刻度只放 0 和 10，轴上就只在这两处显示标签
    ticks[ QwtScaleDiv::MajorTick ] << 0 << 10;

    // 1 到 9 塞进短刻度，只画小短横，不带字
    for ( int i = 1; i < 10; ++i )
        ticks[ QwtScaleDiv::MinorTick ] << i;

    QwtScaleDiv scaleDiv(
        ticks[ QwtScaleDiv::MajorTick ].first(),   // 下限
        ticks[ QwtScaleDiv::MajorTick ].last(),    // 上限
        ticks );                                   // 三组刻度值

    setAxisScaleDiv( QwtPlot::yLeft, scaleDiv );
}

两个细节：上下限参数单独给，不跟刻度值集合绑定，上限 100、刻度只到 50 时轴画到 100、刻度止步于 50；Qwt 6.2 起构造函数改成收 QList<QList<double>>，老代码的裸数组写法会报警告。回到引擎计算：

cpp
setAxisScaleDiv( QwtPlot::yLeft, QwtScaleDiv() );

轴与曲线的绑定 #

一条曲线用哪两条轴，由 setAxes() 指定，默认是 xBottom 配 yLeft：

cpp
curve->setAxes( QwtPlot::xBottom, QwtPlot::yRight );   // 横轴用底边，纵轴用右边

双 Y 轴就靠这个：左轴给一组曲线，右轴给另一组量纲不同的曲线，各自 setAxisScale，互不干扰。

五、刻度与标签 #

QwtScaleDraw 负责把 ScaleDiv 里的刻度值变成屏幕上的刻度和文字。它的 label() 是虚函数，重写它就等于接管了标签生成。

X 轴存秒数、显示成「分:秒」：

cpp
class TimeScaleDraw : public QwtScaleDraw
{
public:
    virtual QwtText label( double v ) const override
    {
        // v 是刻度值，返回什么就显示什么
        QDateTime dt = QDateTime::fromSecsSinceEpoch( static_cast<qint64>( v ) );
        return dt.toString( "mm:ss" );
    }
};

setAxisScaleDraw( QwtPlot::xBottom, new TimeScaleDraw() );   // 所有权交给 QwtPlot

const qint64 now = QDateTime::currentSecsSinceEpoch();
setAxisScale( QwtPlot::xBottom, now - 10, now );

QDateTime::setTime_t() 在 Qt 5.8 之后废弃、Qt 6 里彻底删除。老代码抄过来编译不过，改用 fromSecsSinceEpoch()，参数是 qint64。

Y 轴底层存 0 到 100、显示成 0 到 10：

cpp
class VScaleDraw : public QwtScaleDraw
{
public:
    virtual QwtText label( double v ) const override
    {
        return QwtText( QString::number( v / 10 ) );   // 除以 10 再转文字
    }
};

setAxisScaleDraw( QwtPlot::yLeft, new VScaleDraw() );   // 不能与自动伸缩同时用
setAxisScale( QwtPlot::yLeft, 0.0, 100.0 );

轴上出现 0、1、2 … 10，数据侧照旧按 0 到 100 算。这招适合「内部按整数放大存、对外按小数显示」的场景，省掉一层数据转换。label() 只在主刻度位置被调用，次刻度不调，别指望在那儿做过滤。

控制刻度密度 #

cpp
setAxisMaxMajor( QwtPlot::xBottom, 10 );   // 最多 10 个大间隔
setAxisMaxMinor( QwtPlot::xBottom, 5 );    // 每个大间隔内最多 5 个小间隔

范围 [0, 100] 配这两行，长刻度落在 0、10、20 … 100，每两个长刻度之间 4 个短刻度。两个「最多」都是请求不是命令：缩放、动态增长、范围变化都会让实际间隔数跟着变，引擎在「整除好看」和「不超过上限」之间优先前者。设了 10 最后出现 12 个，是正常行为。

刻度样式 #

cpp
void DataDisplay::setTickStyle()
{
    for ( int i = 0; i < QwtPlot::axisCnt; i++ )   // 0 是 yLeft，2 是 xBottom
    {
        QwtScaleWidget *scaleWidget = axisWidget( i );
        if ( scaleWidget )
            scaleWidget->setMargin( 0 );   // 刻度值与轴之间的留白

        QwtScaleDraw *scaleDraw = axisScaleDraw( i );
        if ( scaleDraw )
            scaleDraw->enableComponent( QwtAbstractScaleDraw::Backbone, false );
    }

    plotLayout()->setAlignCanvasToScales( true );   // 画布边缘对齐刻度
}

enableComponent() 的开关表：

组件 枚举值 关掉以后
主干线 QwtAbstractScaleDraw::Backbone 轴那条线消失，只剩刻度
刻度线 QwtAbstractScaleDraw::Ticks 刻度小横线消失，只剩标签
标签 QwtAbstractScaleDraw::Labels 文字消失，只剩线

老笔记里写的「true 表示禁用、false 表示可用」是反的。enableComponent( comp, true ) 是启用，照着那句注释反着调，会发现刻度怎么都出不来。

setAlignCanvasToScales( true ) 让画布左边缘对齐到 Y 轴最大标签宽度。不开这个，标签宽度一变画布就跟着抖。

标签文字还有几个旋钮：

cpp
QwtText title( "时间 (s)" );          // 轴标题带颜色
title.setColor( Qt::darkGray );
setAxisTitle( QwtPlot::xBottom, title );

setAxisLabelRotation( QwtPlot::xBottom, -45.0 );   // 标签旋转，X 轴拥挤时用
setAxisLabelAlignment( QwtPlot::xBottom, Qt::AlignRight | Qt::AlignTop );

// 轴的颜色：QwtScaleDraw 不管颜色，走 QwtScaleWidget 的 palette
axisWidget( QwtPlot::yLeft )->setPalette( QPalette( Qt::darkBlue ) );

setAxisLabelRotation() 只影响标签文字，刻度线不动。旋转之后必须配一次 setAxisLabelAlignment()，否则文字会飘到轴的另一侧。

六、图例 QwtLegend #

图例在 Qwt 里是独立控件，不是 QwtPlot 的一部分。你 new，用 insertLegend() 交给 QwtPlot 摆放：

cpp
QwtLegend *legend = new QwtLegend;
legend->setDefaultItemMode( QwtLegendData::Checkable );   // 每个图例项可点
insertLegend( legend, QwtPlot::RightLegend );             // 放右侧

insertLegend() 接管图例所有权，同时把位置写进 QwtPlotLayout。换位置不用删，再调一次就行；彻底拿掉传 nullptr。位置枚举有 LeftLegend、RightLegend、BottomLegend、TopLegend、ExternalLegend。最后一个表示 QwtPlot 不管摆放，你自己当普通控件加进某个 layout。

图例项的模式有三种：

模式 行为
QwtLegendData::ReadOnly 纯展示，点击无反应
QwtLegendData::Checkable 显示勾选框，点击发 checked 信号
QwtLegendData::Clickable 可点，只有点击信号，没有勾选状态

设成 Checkable 只给了勾选框的样子，切换可见性还得自己接信号。Qwt 不替你改曲线的 visible。信号原型带三个参数，第三个是点击序号，可以忽略：

cpp
connect( legend, SIGNAL( checked( const QVariant &, bool, int ) ),
         this,   SLOT( showItem( const QVariant &, bool ) ) );

void PlotLines::showItem( const QVariant &itemInfo, bool on )
{
    QwtPlotItem *plotItem = infoToItem( itemInfo );
    if ( plotItem )
        plotItem->setVisible( on );
}

槽里拿到的是 QVariant 形式的信息包，得用 infoToItem() 换回指针。反方向用 itemToInfo( item )，把可绘项换成 QVariant，用来找它在图例里的标签控件：

cpp
const QVariant itemInfo = itemToInfo( items[i] );
QwtLegendLabel *legendLabel =
    qobject_cast<QwtLegendLabel *>( legend->legendWidget( itemInfo ) );

if ( legendLabel )
    legendLabel->setChecked( true );   // 勾选框与曲线状态对齐

legendWidget() 返回 QWidget*，实际类型是单个 QwtLegendLabel，或包了一组的容器。qobject_cast 判空之后再用，别硬转。

初始只显示第一条 #

多条曲线同屏容易糊，常见做法是启动时只开第一条，其余交给用户点。这段逻辑要放在 insertLegend() 之后，因为得先有图例控件才能设勾选状态：

cpp
QwtPlotItemList items = itemList( QwtPlotItem::Rtti_PlotCurve );

for ( int i = 0; i < items.size(); i++ )
{
    if ( i == 0 )
    {
        QwtLegendLabel *label = qobject_cast<QwtLegendLabel *>(
            legend->legendWidget( itemToInfo( items[i] ) ) );
        if ( label ) label->setChecked( true );
        items[i]->setVisible( true );
    }
    else
    {
        items[i]->setVisible( false );
    }
}

Rtti_PlotCurve 是过滤条件，想连网格、标记一起遍历就换成 QwtPlotItem::Rtti_PlotItem 或干脆不传参数。图例项多到放不下时，Qwt 6.2 起可以限列数 legend->setMaxColumns( 2 )；6.1 及更早没有这个接口，只能走 ExternalLegend 自己排。

七、多条曲线与样式 #

曲线一多，逐个 new 就不可维护了。用循环加容器：

cpp
QVector<QwtPlotCurve *> m_curves;   // 成员变量，析构时统一 delete

static const QColor kColors[] = {
    Qt::blue, Qt::red, Qt::darkGreen, Qt::magenta, Qt::darkCyan
};

for ( int ch = 0; ch < channelCount; ++ch )
{
    QwtPlotCurve *curve = new QwtPlotCurve( QString( "信道 %1" ).arg( ch + 1 ) );

    curve->setPen( kColors[ ch % 5 ], 2 );
    curve->setRenderHint( QwtPlotItem::RenderAntialiased, true );
    curve->setSamples( dataOfChannel( ch ) );
    curve->setZ( ch );                                  // 后建的压在上面
    curve->setLegendAttribute( QwtPlotCurve::LegendShowLine );
    curve->attach( this );

    m_curves.append( curve );
}

取模会在第 6 条曲线上开始重复配色。数量超过配色数时，让线型参与区分：

cpp
static const Qt::PenStyle kStyles[] = {
    Qt::SolidLine, Qt::DashLine, Qt::DotLine, Qt::DashDotLine
};
curve->setPen( QPen( kColors[ ch % 5 ], 2, kStyles[ ( ch / 5 ) % 4 ] ) );

QwtSymbol 的形状也能参与区分，枚举里有 Ellipse、Rect、Diamond、Triangle、Cross、XCross、Star1、Hexagon 等十几种，配合填充色能撑到几十条不重样。

一个画布放两组量纲不同的曲线，各用各的轴：

cpp
for ( int i = 0; i < groupA.size(); ++i )
    groupA[i]->setAxes( QwtPlot::xBottom, QwtPlot::yLeft );    // 第一组走左轴

for ( int i = 0; i < groupB.size(); ++i )
    groupB[i]->setAxes( QwtPlot::xBottom, QwtPlot::yRight );   // 第二组走右轴

enableAxis( QwtPlot::yRight, true );
setAxisScale( QwtPlot::yLeft,  0.0, 1.0 );
setAxisScale( QwtPlot::yRight, 0.0, 1000.0 );

右轴默认不显示，enableAxis 那行漏了，第二组曲线会贴着画布右边缘画、却没有任何刻度参照。同一条轴上的多条曲线共用范围，想让它们都看得见，要么手动给一个能包住全部数据的范围，要么开自动缩放。

八、曲线外观：画笔、符号与填充 #

外观由三样决定：线（pen 加 style）、点（symbol）、面（brush 加 baseline）。

cpp
curve->setPen( Qt::blue, 2 );                        // 颜色 + 线宽
curve->setPen( QPen( Qt::blue, 2, Qt::DashLine ) );  // 完整控制
curve->setRenderHint( QwtPlotItem::RenderAntialiased, true );

抗锯齿是每个可绘项各自持有的属性，不开就是明显锯齿，斜线尤其难看。比线宽更重的性能项是点数，上万点的折线做抗锯齿，重绘会明显拖帧。

setStyle() 换的是连接方式，跟 pen 的 DashLine 不是一回事：

枚举 效果
QwtPlotCurve::NoCurve 只画符号点，不连线
QwtPlotCurve::Lines 相邻点直线连接（默认）
QwtPlotCurve::Sticks 每个点向基线画一根竖线
QwtPlotCurve::Steps 阶梯线
QwtPlotCurve::Dots 每点一个小方点
QwtPlotCurve::UserCurve 自己实现的曲线

阶梯线再细分方向，样条平滑是另一个属性：

cpp
curve->setStyle( QwtPlotCurve::Steps );
curve->setCurveAttribute( QwtPlotCurve::Inverted, true );   // 先竖后横，默认先横后竖
curve->setCurveAttribute( QwtPlotCurve::Fitted, true );     // 样条插值

Fitted 视觉上平滑，但数据点会被带偏——它不保证曲线穿过每个原始点。做测量数据展示时别开，画示意曲线时随便开。

符号点：

cpp
QwtSymbol *symbol = new QwtSymbol(
    QwtSymbol::Ellipse,       // 形状
    QBrush( Qt::yellow ),     // 填充
    QPen( Qt::red, 2 ),       // 描边
    QSize( 6, 6 ) );          // 尺寸

curve->setSymbol( symbol );   // 曲线接管 symbol 的所有权
curve->setSymbol( nullptr );  // 去掉符号点

传进去的 QwtSymbol 归曲线管，别再自己 delete，也别在两条曲线间共用同一个指针。第二条曲线 setSymbol() 时会把它 delete 掉，第一条曲线的符号就成了野指针，重绘直接崩。共享外观要传拷贝：

cpp
QwtSymbol *s2 = new QwtSymbol( symbol->style(), symbol->brush(),
                               symbol->pen(), symbol->size() );
curve2->setSymbol( s2 );

填充与裁剪：

cpp
curve->setBaseline( 0.0 );                             // 填充下界
curve->setBrush( QBrush( QColor( 0, 0, 255, 40 ) ) );  // 半透明填充
curve->setClipToScaleRect( true );                     // 默认，超出轴范围裁掉

setBaseline() 不设，填充以 Y 轴下限为界。两者配合出来就是常见的面积图。setClipToScaleRect( false ) 能让曲线不按轴范围裁剪，但画布之外照样看不见。

想改什么 调什么
线颜色、线宽 setPen( color, width )
虚线点线 setPen( QPen( color, w, Qt::DashLine ) )
连接方式（阶梯、竖线） setStyle()
平滑 setCurveAttribute( Fitted, true )
抗锯齿 setRenderHint( RenderAntialiased, true )
数据点形状、面积填充 setSymbol()、setBaseline() + setBrush()
图例里画线还是画点 setLegendAttribute()
前后遮挡 setZ()

九、鼠标缩放与平移 #

Qwt 把鼠标交互做成三个独立的事件机器：QwtPlotZoomer、QwtPlotPanner、QwtPlotMagnifier。它们都不是 QwtPlot 的成员，而是你 new 出来、绑到画布上的对象。

cpp
#include <qwt_plot_zoomer.h>
#include <qwt_plot_panner.h>
#include <qwt_plot_magnifier.h>

QwtPlotZoomer *zoomer = new QwtPlotZoomer( canvas() );   // 框选局部放大
zoomer->setRubberBandPen( QColor( Qt::blue ) );          // 框选矩形的边线颜色

QwtPlotPanner *panner = new QwtPlotPanner( canvas() );   // 拖拽平移
panner->setMouseButton( Qt::RightButton );               // 右键拖，左键留给框选

QwtPlotMagnifier *magnifier = new QwtPlotMagnifier( canvas() );   // 滚轮整体缩放
magnifier->setMouseButton( Qt::LeftButton );

构造函数收 QWidget*，传 canvas() 而不是 this。传 this 能编过，但事件过滤装到了 QwtPlot 上，画布先吃掉事件，结果就是没反应。

类 触发方式 作用 关键 API
QwtPlotZoomer 拖出矩形 局部放大，可逐级回退 setMousePattern()、setRubberBandPen()、zoom()
QwtPlotPanner 按住鼠标拖动 平移视口，不改缩放 setMouseButton()、setOrientations()
QwtPlotMagnifier 滚轮 以光标为中心整体缩放 setMouseButton()、setWheelFactor()

焦点：收不到事件的头号原因 #

三件套靠事件过滤器工作，过滤器装在画布上。画布拿不到焦点，鼠标事件就转不成 Qwt 的交互。

cpp
canvas()->setFocusPolicy( Qt::StrongFocus );
canvas()->setFocus();
setAttribute( Qt::WA_TransparentForMouseEvents, false );
setMouseTracking( true );   // 取值提示类功能要用

几个专门踩这坑的场景：把 QwtPlot 塞进 QScrollArea，外层滚动区先吃掉事件，panner 拖不动；自定义画布子类重写了 mousePressEvent() 却没调基类实现，事件链断在半路；给 QwtPlot 装了 eventFilter 并返回 true，事件到此为止；用 WA_TransparentForMouseEvents 把画布设成透明，事件直接穿透到下层控件。

缩放的鼠标模式 #

QwtPlotZoomer 用 setMousePattern()，第一个参数是模式位：

cpp
void setMousePattern( QwtEventPattern::MousePatternCode code,
                      Qt::MouseButton button,
                      Qt::KeyboardModifiers modifiers = Qt::NoModifier );

MousePatternCode 有 7 个值，其中 MouseSelect1 到 MouseSelect6 是六个鼠标槽位。Qwt 自带的例子只用了前三个：

槽位 含义 默认绑定
MouseSelect1 拉框放大 左键
MouseSelect2 恢复到原始范围 右键 + Ctrl
MouseSelect3 回退到上一次放大之前 右键

MouseSelect4 到 MouseSelect6 是预留槽位，默认的 QwtPickerMachine 不会读它们。想派活用就得自己写 QwtPickerMachine 子类。找不到说明不是文档没查到位，这块本来就留给自定义机器。

三种绑定方案 #

原稿测出来的三套组合，直接可用。

cpp
// 方案一：默认右键恢复原样，放大方式自定义
zoomer->setMousePattern( QwtEventPattern::MouseSelect1, Qt::LeftButton, Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect1, Qt::RightButton, Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect1, Qt::LeftButton );   // 左键放大
zoomer->setMousePattern( QwtEventPattern::MouseSelect1, Qt::RightButton );  // 与恢复重叠，不推荐

// 方案二：默认左键放大，恢复方式自定义
zoomer->setMousePattern( QwtEventPattern::MouseSelect2, Qt::LeftButton, Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect2, Qt::RightButton, Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect2, Qt::LeftButton );   // 与放大重叠，不推荐
zoomer->setMousePattern( QwtEventPattern::MouseSelect2, Qt::RightButton );  // 右键恢复原样

// 方案三：左键放大、右键恢复原样，回退上一级自定义
zoomer->setMousePattern( QwtEventPattern::MouseSelect3, Qt::LeftButton, Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect3, Qt::RightButton, Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect3, Qt::LeftButton );   // 与放大重叠，不推荐
zoomer->setMousePattern( QwtEventPattern::MouseSelect3, Qt::RightButton );  // 与恢复原样重叠

最后那行是坑：同一个键同时绑给 MouseSelect2 和 MouseSelect3，冲突时先匹配到的赢，恢复原样盖掉回退上一级。结果就是右键永远回不到上一级，只能一步跳回原点。

Qwt 例子里的组合是方案二叠方案三：先按方案二把「恢复原样」挪到 Ctrl+右键，空出裸右键；再按方案三把裸右键绑给「回退上一级」。两行合起来，三个动作互不冲突。

cpp
zoomer->setMousePattern( QwtEventPattern::MouseSelect2, Qt::RightButton,
                         Qt::ControlModifier );
zoomer->setMousePattern( QwtEventPattern::MouseSelect3, Qt::RightButton );

Panner 和 Magnifier 用 setMouseButton( button, modifiers = Qt::NoModifier )，签名跟 Zoomer 的 setMousePattern() 不同，写混了编译期就报错。Panner 默认左键拖动，Magnifier 默认滚轮缩放，setMouseButton() 是给「按住某键拖动也能缩放」开的口子：

cpp
magnifier->setWheelFactor( 1.2 );   // 每格缩放 20%，默认 1.2；小于 1 是缩小方向

用代码控制缩放栈 #

QwtPlotZoomer 内部维护缩放历史栈，每次框选放大就是压栈。代码里也能操作：

cpp
zoomer->setZoomBase();                            // 以当前轴范围作为「原始状态」
zoomer->setZoomBase( QRectF( 0, 0, 10, 10 ) );    // 手动指定原始范围
zoomer->zoom( QRectF( 2, 2, 4, 4 ) );             // 放大到指定矩形
zoomer->zoom( 0 );                                // 回到原始状态（下标 0）
zoomer->zoom( -1 );                               // 回退一级

数据会变的场景里，setZoomBase() 必须重做。曲线更新、轴范围跟着变之后，旧的 zoom base 就失效了，用户按右键「恢复原样」会回到一个早就不存在的范围，图看着像空了。

滚轮缩放与框选缩放共用同一套轴范围，但缩放栈只记录框选产生的层级。用滚轮放大之后再按回退，回的是上一次框选的位置。这个行为经常被当成 bug，实际是设计如此。Panner 的平移量跟画布尺寸绑定，画布被压扁时，同样的拖动距离对应的数据位移就变大。

十、十字准星与取值提示 #

要给用户读数，标准做法是 QwtPlotPicker 加两条 QwtPlotMarker 画的准星线。

cpp
#include <qwt_plot_picker.h>
#include <qwt_picker_machine.h>

QwtPlotPicker *picker = new QwtPlotPicker( canvas() );
picker->setStateMachine( new QwtPickerTrackerMachine() );   // 只跟踪，不选区
picker->setTrackerMode( QwtPicker::AlwaysOn );              // 提示框常显
picker->setRubberBand( QwtPicker::VLineRubberBand );        // 竖向准星
picker->setRubberBandPen( QPen( Qt::gray, 1, Qt::DashLine ) );

状态机决定交互性质，对象归 picker 管，new 完别管了：

状态机 行为 配的信号
QwtPickerTrackerMachine 只跟踪鼠标位置 moved( const QPoint& )
QwtPickerClickPointMachine 单击取一个点 selected( const QPointF& )
QwtPickerDragPointMachine 按住拖动取点 appended / selected

跟随鼠标的准星 #

两条 QwtPlotMarker，一竖一横，用 moved 驱动：

cpp
QwtPlotMarker *vLine = new QwtPlotMarker;
vLine->setLineStyle( QwtPlotMarker::VLine );
vLine->setLinePen( QPen( Qt::red, 1, Qt::DashLine ) );
vLine->attach( this );

QwtPlotMarker *hLine = new QwtPlotMarker;
hLine->setLineStyle( QwtPlotMarker::HLine );
hLine->setLinePen( QPen( Qt::red, 1, Qt::DashLine ) );
hLine->attach( this );

connect( picker, &QwtPicker::moved, this, [this, vLine, hLine]( const QPoint &pos ) {
    // 像素坐标换数据坐标，两个方向各取各的变换器
    const double x = canvasMap( QwtPlot::xBottom ).invTransform( pos.x() );
    const double y = canvasMap( QwtPlot::yLeft  ).invTransform( pos.y() );

    vLine->setXValue( x );
    hLine->setYValue( y );
    replot();
} );

canvasMap() 返回某条轴方向的坐标变换器，invTransform() 把像素转成数据值。写反是常见错：横轴取 pos.y()、纵轴取 pos.x()，准星就只会沿对角线跑。setLineStyle() 可选 NoLine、HLine、VLine、Cross；Cross 一条标记就能画十字，省一个对象，代价是两条线的颜色线宽绑在一起。

提示框文字 #

重写 trackerTextF() 定制格式：

cpp
class ValuePicker : public QwtPlotPicker
{
public:
    explicit ValuePicker( QWidget *canvas ) : QwtPlotPicker( canvas ) {}
protected:
    virtual QwtText trackerTextF( const QPointF &pos ) const override
    {
        return QwtText( QString( "x = %1\ny = %2" )
                        .arg( pos.x(), 0, 'f', 3 )
                        .arg( pos.y(), 0, 'f', 3 ) );
    }
};

picker->setTrackerFont( QFont( "Consolas", 9 ) );
picker->setTrackerMode( QwtPicker::ActiveOnly );   // 鼠标移出画布就隐藏

Qwt 6 里要覆盖的是 trackerTextF()，trackerText() 是旧的 QPoint 版本重载。覆错了不报错，只是不生效。AlwaysOn 与 ActiveOnly 的差别在鼠标移出画布之后：前者留着最后的位置，后者立刻隐藏。取值提示用后者更干净。

吸附到最近的数据点 #

准星跟着鼠标走，读数要显示最近的那个采样点，这段得自己算：遍历 data()->sample( i )，按 std::fabs( sample( i ).x() - xValue ) 找最小距离，取到下标之后 curve->sample( best )，再把两条准星挪到该点坐标上。点少时线性扫；上万点的波形要建 X 索引，或者先用 qwtUpperSampleIndex() 定位区间再二分。

十一、重绘与刷新 #

Qwt 不自动刷新。改数据、改轴范围、改外观，都得重画一遍才看得见。replot() 是全量重绘：重算布局、重算所有轴的 ScaleDiv、遍历清单画每一项，开销跟曲线数和点数成正比。

开了自动重绘，attach()、detach()、轴范围变更会自己触发，不用每步手写：

cpp
setAutoReplot( true );   // 构造函数末尾开一次，之后省心

代价是不可控：一次批量操作十次变更，它就重绘十次。

cpp
setAutoReplot( false );
for ( int i = 0; i < channels; ++i )
{
    m_curves[i]->setSamples( newData[i] );
    m_curves[i]->setPen( colors[i], 2 );
}
setAutoReplot( true );
replot();

数据持续变化的场景，把 setAutoReplot(false) 常开，只在数据齐了之后显式 replot()，帧率立刻稳下来。

实时刷新 #

cpp
QTimer *timer = new QTimer( this );
timer->setInterval( 33 );   // 约 30 fps

connect( timer, &QTimer::timeout, this, [this]() {
    m_series->append( QPointF( m_elapsed, sampleValue() ) );   // 追加一个点
    setAxisScale( QwtPlot::xBottom, m_elapsed - 10.0, m_elapsed );
    replot();
} );
timer->start();

三个注意点：时间轴滚动会让 zoomer 的 zoom base 失效，要么每次 setZoomBase()，要么用户开始缩放后停止滚动时间窗；setAxisScale() 每次都让引擎重算刻度，比手喂 ScaleDiv 慢；别在 paintEvent() 或 draw() 里调 replot()，会递归到栈溢出。

只重画画布 #

cpp
canvas()->replot();

它跳过布局与轴的重算，只把画布内容重绘一遍，适合「轴范围没变、只有曲线数据变了」的场景。差别在于布局：replot() 会重算标签宽度、图例占位、画布对齐，canvas()->replot() 不走这一步。

要出图的话走 QwtPlotRenderer：render( this, &image ) 画进 QImage，renderDocument() 直接出 PDF/SVG。它的输出字号跟屏幕尺寸相关，导出小图时字号会被压得看不清，把画布放大再导。

十二、易错点速查 #

现象 原因 处理
界面全白，代码不报错 可绘项没 attach() 每个 new 出来的项都挂上
曲线挤在左下角一小块 轴范围还是默认的 [0, 1000] setAxisScale() 或 setAxisAutoScale()
曲线完全看不到 数据不在轴范围内，或 setVisible(false) 打印 data()->boundingRect() 对一下范围
图例里有、画布上没有 z 序被压住，或数据源返回空 setZ() 调大，检查 size()
图例能点但曲线不变 只设了 Checkable，没接 checked 连信号，用 infoToItem() 改可见性
图例项是灰的 Legend 属性被关，或曲线不可见 setItemAttribute( QwtPlotItem::Legend, true )

三件套全收不到鼠标 画布没焦点，或外层控件吃掉事件 setFocusPolicy( Qt::StrongFocus ) + setFocus()
右键既恢复又回退 同一个键绑给了 MouseSelect2 和 3 其中一个换成 Ctrl + 该键
刻度线不显示 enableComponent() 第二参数理解反了 true 是启用，false 是关闭
自定义刻度 + 自动缩放不生效 两者互斥 自定义 QwtScaleDraw 时用手动 setAxisScale()
setTime_t 编译不过 Qt 5.8 起废弃，Qt 6 删除 换 QDateTime::fromSecsSinceEpoch()
重绘时崩溃 一个 QwtSymbol 被两条曲线共用，delete 两次 每条曲线 new 一个自己的
放大后按恢复，图是空的 数据变了但 zoom base 没更新 数据变化后调 setZoomBase()
准星沿对角线跑 两个方向的坐标取反了 横轴 pos.x()，纵轴 pos.y()
提示框不显示 覆盖的是 trackerText() Qwt 6 里改 trackerTextF()
刷新越来越卡 每帧重建整个数组，或自动重绘开着 自定义 QwtSeriesData + 关自动重绘
导出图片字号太小 渲染尺寸小于屏幕尺寸 先把画布放大再 render()
