这篇讲什么：Qt 自己的容器类——QList、QLinkedList、QMap、QHash、QStringList，以及挂在它们身上的两套迭代器（Java 风格、STL 风格）。核心是那件把 Qt 容器和 STL 容器区分开的事：隐式共享，也就是写时复制。

这篇不讲什么：不讲泛型算法（qSort、std::sort、qFind、qLowerBound 那一套），那是下一篇的事；不讲 QVariant、不讲模型视图，那是第四篇；QByteArray、QSet、QCache 只在需要对照时提一句。

跨篇指路：前面是《Qt 入门与信号槽》《布局与基础控件》，后面依次是 Qt 的算法函数、模型视图与 QVariant、定时器与网络、文本流与 XML、绘图与动画、工程实践。读完这篇你应该能选对容器、写对遍历、避开迭代器失效的雷。

一、Qt 容器与 STL 容器 #

Qt 有一整套自己的容器。它们和 STL 的 vector、list、map、unordered_map 长得像，接口名字也像，但底下不是一套实现。

先把几个概念钉死。

容器（Container） 是存数据的类。和裸数组比，容器的好处是容量自己长、边界自己管、附带一堆现成操作。Qt 的容器类和 C++ 标准库的容器类定位一致，都是「装东西的模板类」。

迭代器（Iterator） 是遍历容器的句柄。它把「怎么走」和「走到了哪个元素」打包成一个对象，让遍历逻辑和容器内部结构解耦。你换容器，遍历代码不一定换。

映射（Map） 在容器语境里不是地图，是「关键字到值的对应」。存的是 key-value 对，靠 key 取值。

为什么 Qt 不直接用 STL？历史占大头。Qt 诞生在 1995 年，STL 还没进标准，编译器支持也参差。等 STL 落地，Qt 的容器已经被海量代码依赖，改不动了。于是 Qt 一直维护自己那套，同时把 STL 容器当一等公民对待——Qt 的算法函数两边都吃。

对照表，先有个整体印象：

维度 Qt 容器 STL 容器
命名 QList、QMap、QHash std::vector、std::map、std::unordered_map
隐式共享 有（写时复制） 无
ABI 稳定性 Qt5 内保证 随编译器与标准库版本变
与 QString、QVariant 集成 原生 要转换
迭代器失效规则 按类逐个写在文档里 标准统一规定
元素要求 可拷贝（Qt5 里还得可赋值） 视容器而定，vector 在 C++11 后可移动

「元素要求可拷贝」这条在 Qt5 会咬人。QList<QObject> 编不过，因为 QObject 禁了拷贝构造。你想装一堆控件，只能装指针：QList<QWidget *>。而 QList<QWidget *> 又不负责释放——容器销毁时只丢指针，对象还在。要么你自己 qDeleteAll，要么用 QScopedPointer 包一层，要么就让父对象管。

Qt 容器值语义这一点要提前接受：容器里存的是值，不是引用。QList<QString> list; list.append(s); 之后你改 s，list 里那份不动。

两类容器能互转，成本不高：QList::toVector()、toStdVector()、toStdList()，反方向用 fromVector()、fromStdList()。Qt6 里 QVector 成了 QList 的别名，toVector() 已移除。Qt5 时代「数值密集计算用 QVector」的建议也一并作废，第十一章细说。

二、QList：最常用的顺序容器 #

QList 是 Qt 里出场率最高的容器，没有之一。头文件 <QList>，模板参数是元素类型。

先看一段能跑的最小例子。原始素材里那段代码是残的——main 拿了 argc/argv 却没建 QCoreApplication，末尾还 return a.exec();，a 根本没声明。补全后是这样：

cpp
// 问题描述：使用 Qt 容器 QList 的一个例子
// 往容器里塞 0~9，删掉元素 5，把剩下的打印出来
#include <QCoreApplication>
#include <QList>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    QList<int> list;
    // 往 list 中添加 0~9 的元素
    for (int i = 0; i != 10; ++i)
    {
        list.push_back(i);
    }

    list.removeOne(5);   // 移除容器 list 中的元素 5

    // 输出容器中的所有元素
    foreach (int element, list)
    {
        qDebug() << element;
    }

    return 0;            // 没有事件循环要跑，直接 return 0
}

两点值得多说。

return 0 而不是 return a.exec()：exec() 是事件循环，得等有人 quit() 才返回。这个程序没有信号槽、没有窗口、没有定时器，进了 exec() 就永远挂着。批处理式的 Qt 程序不需要 QCoreApplication 实例，也不需要 exec()；真要用它（比如为了 applicationDirPath()），记得别调 exec()。

removeOne(5) 只删第一个匹配项，返回 bool——删掉了是 true，没有是 false。想全删用 removeAll(5)。

append 和 push_back 是同一件事，prepend 和 push_front 也是，Qt 保留两套命名，一套贴 C++ 习惯，一套贴 STL 习惯。常用接口分四组记。

增

cpp
QList<QString> list;
list.append("alpha");          // 尾部追加，摊销 O(1)
list.push_back("beta");        // 同上
list.prepend("zero");          // 头部插入
list.push_front("minus");      // 同上
list.insert(2, "middle");      // 在索引 2 处插入
list << "x" << "y";            // operator<< 链式追加

删

cpp
list.removeAt(0);              // 按下标删，越界是未定义行为
list.removeFirst();
list.removeLast();
list.removeOne("beta");        // 删第一个等于该值的元素，返回 bool
list.removeAll("x");           // 删所有等于该值的元素，返回删除个数
QString taken = list.takeAt(1); // 删掉并把元素取出来
QString head = list.takeFirst();
list.clear();

take* 系列和 remove* 的区别：take* 会把元素返回给你，remove* 直接丢掉。

查

cpp
int n     = list.size();       // 元素个数
bool empty = list.isEmpty();   // 比 size() == 0 可读
QString a = list.at(0);        // 带边界检查的读
QString b = list[0];           // 不带检查（debug 下有 Q_ASSERT）
QString c = list.first();
QString d = list.last();
bool has  = list.contains("alpha");
int idx   = list.indexOf("alpha");   // 找不到返回 -1
int last  = list.lastIndexOf("alpha");

at() 和 operator[] 在 release 下都是直接下标，区别在 debug：at() 断言越界，operator[] 也断言但语义上更宽松。工程里读元素统一用 at()，改元素用 operator[]，意图清楚。

改

cpp
list[0] = "ALPHA";
list.replace(1, "BETA");
QList<QString> sub = list.mid(1, 3);   // 从索引 1 取 3 个
list.swap(other);                      // 换内容，O(1)
list.reserve(100);                     // 预分配容量
list.squeeze();                        // 收回多余容量

size() 返回 int，这是 Qt5 的事。Qt6 改成了 qsizetype（64 位下是 long long），int n = list.size(); 直接搬过去会有窄化警告。

QList 容量分段长，append 多数时候不搬家；知道要装几千个元素就先 reserve()，省的是反复扩容时的整块拷贝。它慢的是头部和中间插入——底层连续数组要整体右移，prepend 在 Qt5 是 O(n)。真需要频繁头插，用 std::list。

还有 qDeleteAll。容器装指针时它帮你逐个 delete。两步都得做——只 qDeleteAll 不 clear()，容器里留着一堆已释放的地址，下次谁读谁崩：

cpp
QList<MyItem *> items;
items << new MyItem(1) << new MyItem(2);
qDeleteAll(items);   // 逐个 delete
items.clear();       // 清掉悬空指针

三、QLinkedList：链表（已废弃） #

链表（Linked List）是基础数据结构里的老面孔。它线性存数据，但不按线性顺序铺在内存里，而是每个节点存一个指向下一个节点的指针。

这个结构决定了它的性能画像：

  • 插入删除 O(1)——只要手里已经有那个位置的指针，改两根指针就完事。
  • 按下标访问 O(n)——得从头一路数过去。
  • 不要求连续内存——不用预先知道总大小，碎片内存也能用。
  • 代价是每个节点多一份指针开销，且缓存不友好。

QLinkedList 就是 Qt 版的链表。上代码：

cpp
// 问题描述：往 QLinkedList 里添加元素，然后打印
#include <QCoreApplication>
#include <QLinkedList>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // QLinkedList 提供一个链表（Linked List）的模板类
    QLinkedList<int> list;

    // 往链表中添加数据
    list << 1 << 3 << 5;

    foreach (int i, list)
        qDebug() << i;

    return 0;
}

QLinkedList 的接口和 QList 高度相似：append、prepend、insert、removeAt、size、contains、indexOf 都有。差别在底层——QLinkedList 没有下标运算 operator[]，也没有 at()。这不是遗漏，是设计：链表按下标访问是 O(n)，Qt 干脆不给你这个接口，免得你写出看着 O(1) 实际 O(n) 的循环。要用它就只能靠迭代器或 first()/last()，很不方便，这也是它被淘汰的原因之一。

Qt6 里 QLinkedList 被移除了。 头文件不存在，类不存在，编译直接报错。官方给的替代是 std::list：

cpp
// Qt6 写法
#include <list>
#include <algorithm>

std::list<int> list;
list.push_back(1);
list.push_back(3);
list.push_back(5);

for (int v : list)
    qDebug() << v;

std::list 是双向链表，接口和 QLinkedList 对应的部分几乎一一映射：push_back 对 append，push_front 对 prepend，size 对 size，迭代器用法也接近。迁移工作量不大，主要是把 foreach (int i, list) 换成范围 for，把 QLinkedList<T>::iterator 换成 std::list<T>::iterator。

顺带说一句：链表在真实项目里的出场率远低于教科书给人的印象。现代 CPU 的缓存预取对连续内存极其友好，一次缓存命中省下的时间，够数组做完十几次元素移动。除非你有明确的「大对象 + 中间频繁增删」场景，QList 往往比链表快。这也是 Qt6 敢直接删掉 QLinkedList 的底气。

操作 QList（连续） QLinkedList（链表）
尾部追加 摊销 O(1) O(1)
头部插入 O(n) O(1)
中间插入 O(n) O(1)，需先定位
按下标访问 O(1) 不提供
内存局部性 好 差
每元素额外开销 低 一或两个指针

四、QMap 与 QHash 的分工 #

这两个都是映射容器，都存 key-value 对，接口也像到可以互相替换的程度。但底层完全不同，选错会让程序慢一个数量级，或者行为不符合预期。

QMap 是基于红黑树的有序字典。 红黑树是一种自平衡二叉查找树，插入、删除、查找都是 O(log n)。它最大的价值是有序——迭代器遍历时，元素严格按 key 升序出来。

QHash 是基于哈希表的无序字典。 查找、插入、删除平均 O(1)。它不管顺序，元素按哈希值散落在桶里，遍历顺序取决于哈希函数和容量，跟插入顺序无关。

先看 QMap。素材里那段代码同样残了——employees 没声明，main 的花括号丢了。补全：

cpp
// 2014/8/28 wayne HDU
// 问题描述：QMap 的一个例子，插入 key-value 并用迭代器遍历输出
#include <QCoreApplication>
#include <QMap>
#include <QMapIterator>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // QMap 提供基于红黑树的字典模板类
    QMap<int, QString> employees;
    employees.insert(1, "wayne");      // 元素形式：关键字——值
    employees.insert(3, "Jane");
    employees.insert(2, "Roshan");

    // QMapIterator 提供 QMap 的 const（常量）版本迭代器，输出所有元素
    QMapIterator<int, QString> iter(employees);
    while (iter.hasNext())
    {
        iter.next();
        qDebug() << iter.key() << " " << iter.value();
    }

    return 0;
}

注意插入顺序是 1、3、2，输出顺序却是 1、2、3。红黑树把 key 排好了，这就是 QMap 存在的理由。

两个容器对 key 类型的要求不一样。QMap 要 operator<，QHash 要 operator== 加一个全局 qHash() 重载。自定义 key 时两样都得写：

cpp
struct Emp
{
    int id;
    QString name;

    bool operator<(const Emp &o) const  { return id < o.id; }   // 给 QMap
    bool operator==(const Emp &o) const { return id == o.id; }  // 给 QHash
};

uint qHash(const Emp &key, uint seed = 0)   // 给 QHash
{
    return qHash(key.id, seed);
}

qHash 的第二参数 seed 从 Qt5 开始有，用来防哈希碰撞攻击。自定义 qHash 时把 seed 传下去，别吞掉。Qt6 里签名换成 size_t qHash(const T &, size_t)。

QHash 的例子：

cpp
// 2014/8/29 wayne HDU
#include <QCoreApplication>
#include <QHash>
#include <QHashIterator>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // 建立一个 Hash 对象，往对象中添加元素
    QHash<int, QString> employee;
    employee.insert(1, "wayne");
    employee.insert(2, "Jane");
    employee.insert(3, "Roshan");

    // 利用对象的 const 版本的迭代器实现对对象的遍历
    QHashIterator<int, QString> iter(employee);
    while (iter.hasNext())
    {
        iter.next();
        qDebug() << iter.key() << " " << iter.value();
    }

    return 0;
}

这段输出未必是 1、2、3。别依赖它。Qt5 的 QHash 用随机种子（可用 QT_HASH_SEED 环境变量固定），同一个程序两次运行的遍历顺序都会不同。依赖 QHash 的遍历顺序是明确的 bug。

分工怎么定？一张表：

判据 选 QMap 选 QHash
是否要按 key 排序遍历 要 不要
查找性能 O(log n) 平均 O(1)
内存占用 每节点三指针 + 颜色位，偏高 桶数组 + 节点链，偏低
key 类型要求 operator< operator== + qHash()
遍历顺序 严格升序，稳定 不定，随机种子一换就变
适合数据量 小到中等 中到大型
典型场景 配置文件项、有序字典、范围查询 缓存、索引表、去重映射

一句话：要按 key 排序遍历用 QMap，只做查找用 QHash。 数据量上千还拿 QMap 当查找表，就是拿 O(log n) 换一个你根本没用上的有序性。

QMap 还多几个 QHash 没有的接口：lowerBound()、upperBound()，用来做范围查询。这两个是红黑树的红利，哈希表给不了。

两个容器都有 value(key) 和 value(key, defaultValue)。前者在 key 不存在时返回默认构造的 T——QString 是空串，int 是 0，太容易掩盖 bug。养成写默认值的习惯，要区分「不存在」和「存在但是空值」就配一次 contains()：

cpp
QMap<int, QString> map;
QString a = map.value(99);                                 // 空串，悄悄通过
QString b = map.value(99, QStringLiteral("<missing>"));    // 明确默认值
if (map.contains(99)) { /* 真的存在 */ }

insert 在 key 已存在时会覆盖旧值。想只在不存在时插入，Qt5 没有 tryInsert，得先 contains() 再决定；一个 key 挂多个值要用 QMultiMap / QMultiHash。删除用 remove(key)，返回删除个数；take(key) 删掉并返回 value，「取出即删除」时好用。

五、QStringList：字符串列表 #

QStringList 继承自 QList<QString>，是 Qt 里第二常用的容器。它没有引入新结构，只是在 QList<QString> 上补了一批字符串专用操作。

正因为继承关系，QStringList 天然具备隐式共享和按下标快速访问——素材里那句「和 QList 一样，QStringList 是隐式共享的，它能够基于索引快速访问数据」就是这个意思。

基础例子，素材里的 main 少了花括号、foreach 体是空的，补全后：

cpp
// 2014/8/29 wayne HDU
#include <QCoreApplication>
#include <QStringList>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    QStringList list;
    QString line = "a,b,c,d,e,f,g";

    // 按照指定标识符将 string 分解成多个子 string，返回这些子 string 的列表
    list = line.split(",");

    // 将 QStringList 中的指定 string 用另外的 string 代替
    list.replaceInStrings("b", "banana");

    // 遍历输出所有元素
    foreach (QString elem, list)
    {
        qDebug() << elem;
    }

    return 0;
}

输出是 a、banana、c、d、e、f、g。

replaceInStrings 有两个重载，第二个带 Qt::CaseSensitivity：

cpp
list.replaceInStrings("B", "banana", Qt::CaseInsensitive);

四个高频操作，记住就够用大半：

cpp
// 1. 切分
QStringList parts = QString("/usr/local/bin").split("/", Qt::SkipEmptyParts);
// parts == {"usr", "local", "bin"}

// 2. 合并
QString joined = parts.join("\\");   // "usr\\local\\bin"
QString csv    = parts.join(", ");   // "usr, local, bin"

// 3. 过滤
QStringList all = {"apple.txt", "notes.md", "photo.png"};
QStringList txt = all.filter("*.txt");         // 通配符或子串匹配

// 4. 判断
bool has = all.contains("notes.md");

QString::split 的第二个参数是分割行为，取 Qt::KeepEmptyParts 或 Qt::SkipEmptyParts。Qt5.14 之前是 QString::KeepEmptyParts，之后挪进了 Qt:: 命名空间，老代码会编译警告。默认值在 Qt5 是 KeepEmptyParts——这意味着一串连续的逗号会切出一堆空串。"a,,b".split(",") 得到三个元素，中间那个是空的。做 CSV 解析时这个默认值能坑死人，显式写 Qt::SkipEmptyParts 更安全。

removeDuplicates() 去重并保留首次出现的顺序，sort() 排序（默认区分大小写）。QStringList 和 QString::split / join 是一对，文本处理里九成的「按分隔符拆开再拼回去」都靠它们。

QCommandLineParser 拿到的位置参数是 QStringList，QFileDialog::getOpenFileNames 返回的也是 QStringList，QSettings 读数组值还是 QStringList。这个类型会反复出现，早点用熟。

六、隐式共享与写时复制 #

这是本篇最该记住的一节。 Qt 容器和 STL 容器最大的差别不是接口，是这一层。

隐式共享（implicit sharing）也叫写时复制（copy-on-write，COW）。原理一句话：容器对象里存的是一个指向共享数据块的指针，加一个引用计数。拷贝容器时不复制数据，只把引用计数加一。谁要修改数据，先检查引用计数——不是 1 就复制一份独占的再改，是 1 就直接改。

cpp
QList<QString> a;
a << "one" << "two" << "three";

QList<QString> b = a;    // 不复制三个 QString，只把引用计数从 1 加到 2
b[0] = "ONE";            // b 发现引用计数是 2，先复制整块，再改自己的那份

// 此刻 a[0] == "one"，b[0] == "ONE"

数据指针能直接验证这件事：

cpp
QList<int> a;
a << 1 << 2 << 3;
QList<int> b = a;
qDebug() << (a.constData() == b.constData());   // true，同一个数据块
b[0] = 99;                                      // 触发 detach
qDebug() << (a.constData() == b.constData());   // false，b 已复制

好处很直接：按值传递 QList、QString、QMap 是廉价的。函数签名写 void handle(QStringList files) 不会拷贝几千个字符串，只加一次引用计数。这让 Qt 的 API 敢到处按值传参，代码也更干净。

代价是三个坑。

坑一：非 const 访问会触发 detach。 下面这段看着只是读，实际把整个容器复制了一遍：

cpp
void dump(QList<int> list)          // 按值传，此时没复制
{
    for (int i = 0; i < list.size(); ++i)
        qDebug() << list[i];        // operator[] 是非 const 的，detach！
}

operator[] 返回可写引用，所以它必须 detach。改用 at() 或 constFirst() 这类 const 接口就不 detach：

cpp
void dump(const QList<int> &list)   // 加 const 引用，压根没有 detach 的机会
{
    for (int i = 0; i < list.size(); ++i)
        qDebug() << list.at(i);     // const 访问，不 detach
}

坑二：范围 for 和 foreach 会隐式拷贝，并触发 detach。

cpp
for (const QString &s : list)             // 对 list 调 begin()，非 const 版本，detach！
    qDebug() << s;

for (const QString &s : qAsConst(list))   // Qt5.7+，强制 const 遍历，不 detach
    qDebug() << s;

Qt6 里 qAsConst 还在，但推荐用 std::as_const。foreach 宏本身就是把容器拷一份再遍历，对 COW 容器来说是廉价的，但循环体里一旦非 const 访问就 detach。所以 foreach 里的容器变量尽量当只读用。

坑三：迭代器在 detach 后失效。 这一点第七章之后会反复出现。任何时候你拿到迭代器，然后对容器做了非 const 操作，之前那个迭代器就悬空了。隐式共享让这个时机变得不直观——看起来「只是读了一下」，实际已经 detach 了。

要判断当前容器是否独占数据，用 isDetached()。要主动放弃共享、拿到独占副本，用 detach()。这两个在调试 COW 相关性能问题时有用。

线程安全这块要说清：隐式共享的引用计数是原子的，但容器实例本身不是线程安全的。 多个线程可以各自持有一个指向同一数据块的容器副本并只读访问，这是安全的。但只要有一个线程开始写，就会 detach 出自己的副本，也不会影响别人。真正危险的是多个线程同时操作同一个容器对象——那和普通容器一样需要加锁，QList 不会帮你。

QString、QByteArray、QPixmap、QImage、QVariant、QFont 全是隐式共享的。这套机制在 Qt 里是全局设计，不只是容器的事。理解了它，很多「为什么这里没拷贝」和「为什么这里莫名很慢」的问题就都有答案了。

七、遍历的四种方式 #

同一个 QList，至少有四种走法。选哪种，看你要不要在遍历中改容器。

cpp
QList<QString> list;
list << "a" << "b" << "c";

第一种，下标循环。

cpp
for (int i = 0; i < list.size(); ++i)
    qDebug() << list.at(i);

需要下标时唯一的选择。缺点是手写 i 容易越界。

第二种，foreach 宏或范围 for。

cpp
foreach (const QString &s, list)     // Qt 自己的宏
    qDebug() << s;

for (const QString &s : list)        // C++11 范围 for
    qDebug() << s;

最简洁。foreach 定义在 <QForeach> 里，Qt 官方从 Qt5.7 起建议改用范围 for。两者都不方便在遍历中安全删元素。

第三种，Java 风格迭代器。

cpp
QListIterator<QString> iter(list);
while (iter.hasNext())
    qDebug() << iter.next();

只前进时最直观。QMutableListIterator 版本可以删除和修改元素。

第四种，STL 风格迭代器。

cpp
for (QList<QString>::const_iterator it = list.constBegin(); it != list.constEnd(); ++it)
    qDebug() << *it;

能和 std::sort、std::find_if、std::accumulate 这些泛型算法直接对接。Qt 自己的算法函数也吃这套。

对照一下：

方式 写法 能在遍历中删元素 能对接 STL 算法 推荐场景
下标循环 for (int i...) 要格外小心，见第十章 否 需要下标、需要跨元素访问
foreach / 范围 for foreach (x, list) 不安全 否 只读遍历，日常首选
Java 风格迭代器 QListIterator 用 QMutableListIterator 否 需要 hasNext 语义、要正向反向切换
STL 风格迭代器 begin() / end() 用 erase() 并接返回值 是 配合算法函数、需要精确定位

日常按这个顺序挑：只读就用范围 for；要删要用 STL 风格或 QMutableListIterator；要下标就用第一种。foreach 算是历史遗产，新代码可以不写。

八、Java 风格迭代器 #

Qt 提供两套迭代器，「Java 风格」这个词指的是接口形态：用 hasNext() / next() 这种谓词 + 取值的组合，而不是 C++ 的指针运算。

按容器和可变性交叉，一共这几组，可写的加 Mutable 前缀：

容器 只读迭代器 可写迭代器
QList、QQueue QListIterator QMutableListIterator
QLinkedList QLinkedListIterator QMutableLinkedListIterator
QMap、QMultiMap QMapIterator QMutableMapIterator
QHash、QMultiHash QHashIterator QMutableHashIterator
QSet QSetIterator QMutableSetIterator

QListIterator 是只读的，不提供任何改容器的接口。核心方法：

方法 作用
hasNext() 后面还有元素？
next() 返回后一个元素，并把迭代器移过去
peekNext() 返回后一个元素，不移动
hasPrevious() 前面还有元素？
previous() 返回前一个元素，并移过去
peekPrevious() 返回前一个元素，不移动
toFront() 移到第一个元素之前
toBack() 移到最后一个元素之后
findNext(v) 向后找值 v，找到返回 true 并停在它上面
findPrevious(v) 向前找值 v

next() 和 peekNext() 的区别必须分清：next() 有副作用（迭代器前进），peekNext() 没有。写循环时把这两个搞混，就是死循环或者跳元素。

素材里那段代码演示的是反向遍历：先 toBack() 跳到尾后，再一路 previous() 走回来。

cpp
// 问题描述：使用 Iterator（迭代器）实现对容器的遍历
#include <QCoreApplication>
#include <QList>
#include <QListIterator>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    QList<int> list;
    for (int i = 1; i <= 5; ++i)
    {
        list.append(i);
    }

    // QListIterator 为 QList 和 QQueue 提供一个 Java 风格的 const 迭代器
    // QList 有 Java 风格和 STL 风格两套迭代器，Java 风格层次更高，接口更安全
    QListIterator<int> iter(list);

    // toBack() 将迭代器移动到容器的尾后（最后一个项目之后）
    iter.toBack();

    // hasPrevious() 判断当前迭代器前面是否还有项目
    while (iter.hasPrevious())
    {
        // previous() 返回前一项，并且将迭代器移动到前一项的位置
        qDebug() << iter.previous();

        if (iter.hasPrevious())
        {
            // peekPrevious() 返回前一项，但是并不移动迭代器
            qDebug() << "has previous..." << iter.peekPrevious();
        }
    }

    return 0;
}

输出是 5、has previous... 4、4、has previous... 3、3……一路到 1。注意每次 previous() 之后，peekPrevious() 看的是同一个位置，所以打印出来的值和上一条 previous() 的返回值差 1。

QMutableListIterator 是可写的，在只读接口之外多了三个：

方法 作用
remove() 删除最近一次 next()/previous() 返回的元素
insert(v) 在当前位置插入 v
setValue(v) 修改最近一次 next()/previous() 返回的元素
value() 读取最近一次跳过的元素（不必重新 next）

remove() 有个前提：它删的是「最近一次跨过的那个元素」。刚构造完就调 remove() 是未定义行为，必须先 next() 一次。

素材里的第二个例子，一边遍历一边删掉值等于 5 的元素：

cpp
// 2014/8/28 wayne HDU
// 问题描述：利用 QMutableListIterator 迭代器删除容器中的元素
#include <QCoreApplication>
#include <QList>
#include <QDebug>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // 建立一个容器对象，往里面添加 0~9 的元素
    QList<int> list;
    for (int i = 0; i != 10; ++i)
        list.append(i);

    // QMutableListIterator 提供的是普通迭代器，能改变底层容器
    // 而 QListIterator 是 const 迭代器，不能改变底层容器
    QMutableListIterator<int> iter(list);

    // 遍历容器所有元素，删除指定元素
    while (iter.hasNext())
    {
        if (iter.next() == 5)
            iter.remove();
    }

    // 将迭代器移动到容器的头部（在所有项之前的位置）
    iter.toFront();

    // 遍历容器所有元素，并打印出来
    while (iter.hasNext())
        qDebug() << iter.next();

    return 0;
}

输出 0 到 9，中间没有 5。

这段代码的关键在 iter.next() == 5 和 iter.remove() 这两步的先后。next() 先把迭代器推到元素 5 上并返回它的值，之后 remove() 才知道要删谁。删掉之后迭代器自动停在「下一个元素之前」的正确位置，循环继续，不会跳元素也不会越界。这就是 Java 风格迭代器在「边遍历边删」场景下的价值——位置管理它替你做完了。

QMutableListIterator 删完之后如果还想用 value() 读当前位置，要注意它现在指向的是被删元素后面的那个。用 peekNext() 更安全。

QMapIterator / QHashIterator 除了 next()，还要靠 key() 和 value() 取值：

cpp
QMapIterator<int, QString> iter(map);
while (iter.hasNext()) { iter.next(); qDebug() << iter.key() << ":" << iter.value(); }

QMutableMapIterator 的 setValue() 只能改 value，不能改 key。要改 key 只能删了重插——改 key 等于改位置，红黑树和哈希表都撑不住。

九、STL 风格迭代器 #

STL 风格就是大家熟悉的 begin() / end() 加 *it、++it。它比 Java 风格更底层，也更通用——泛型算法只认这套。

cpp
#include <QList>
#include <QDebug>
#include <algorithm>

QList<int> list;
list << 5 << 1 << 4 << 2 << 3;

// 只读遍历
for (QList<int>::const_iterator it = list.constBegin(); it != list.constEnd(); ++it)
    qDebug() << *it;

// 排序，直接吃 STL 算法
std::sort(list.begin(), list.end());

// 查找
QList<int>::iterator found = std::find_if(list.begin(), list.end(),
                                          [](int v) { return v > 3; });
if (found != list.end())
    qDebug() << "first > 3 is" << *found;

三种取迭代器的写法要分清：

写法 类型 是否 detach 说明
begin() iterator 会 可写遍历，触发写时复制
end() iterator 会 同上
constBegin() const_iterator 不会 只读遍历，首选
constEnd() const_iterator 不会 同上

在非 const 容器上调 begin() 会 detach，即使你只是想读。只读遍历一律用 constBegin() / constEnd()。对 const 容器（const QList<int> &）调 begin()，返回的本身就是 const_iterator。

QList 的迭代器支持随机访问，能做 it + n、it2 - it1、it[3]。QLinkedList 的只支持双向，只能 ++ 和 --。这是容器能力差别，不是 Qt 的锅。

要在遍历中插入或删除，用 insert() / erase()，并且必须接住返回值：

cpp
// 在元素 4 前面插一个 100
for (QList<int>::iterator it = list.begin(); it != list.end(); ++it)
{
    if (*it == 4)
    {
        it = list.insert(it, 100);   // insert 返回指向新元素的迭代器
        ++it;                        // 跳过刚插入的元素
        break;
    }
}

insert() 在 QList 上会让所有迭代器失效，因为底层数组会重新分配。erase() 只让被删元素的迭代器及其之后的失效。这个区别在循环里很关键，第十章专门讲。

Java 风格和 STL 风格不要混着用。混用时只要中间有一次修改操作，两边的位置记录就对不上，行为不可预期。选一套，从头用到尾。

十、遍历时删除元素的陷阱 #

这是 Qt 容器里最高频的 bug，没有之一。看错误示范：

cpp
QList<int> list;
for (int i = 0; i != 10; ++i)
    list << i;

// 错误：想删掉所有偶数
for (int i = 0; i < list.size(); ++i)
{
    if (list.at(i) % 2 == 0)
        list.removeAt(i);   // 删完后面整体左移，i 却继续 +1
}

跑完之后剩下的不是 1、3、5、7、9。removeAt(i) 之后，原来 i+1 的元素顶到了 i 的位置，而循环下一轮又 ++i，正好把它跳过。连续两个待删元素相邻时，第二个就活下来了。想删一半结果删了三分之一，根因就在这。更糟的写法是在同一个 i 上连删两次，第二次直接越界。

正确处理有三种。

写法一：倒序遍历。 从后往前删，被删元素后面的下标变化完全不影响还没处理的元素。

cpp
for (int i = list.size() - 1; i >= 0; --i)
    if (list.at(i) % 2 == 0)
        list.removeAt(i);

注意 list.size() - 1 在空容器时是 -1，int 类型下循环条件 i >= 0 直接不成立，所以空容器也安全。但如果你把 i 写成 unsigned 或 qsizetype，-1 会变成巨大正数，直接崩。这个下标变量必须是有符号类型。

写法二：STL 风格迭代器，接住 erase 的返回值。

cpp
for (QList<int>::iterator it = list.begin(); it != list.end(); )
{
    if (*it % 2 == 0)
        it = list.erase(it);   // erase 返回下一个元素的迭代器
    else
        ++it;                  // 只有没删的时候才前进
}

两个细节不能漏：循环头里不写 ++it；erase 的返回值必须赋回 it。漏任何一个都是未定义行为。

写法三：QMutableListIterator。

cpp
QMutableListIterator<int> it(list);
while (it.hasNext())
{
    if (it.next() % 2 == 0)
        it.remove();
}

最不容易写错的版本，remove() 之后迭代器位置由 Qt 维护。

Qt6.1 起 QList 有了 removeIf()，一行搞定：

cpp
// 仅 Qt6.1+
list.removeIf([](int v) { return v % 2 == 0; });

Qt5 里没有这个接口，得自己写上面三种之一。

绝对不要在 foreach 或范围 for 里删元素：

cpp
// 危险
foreach (int v, list)
{
    if (v == 5)
        list.removeOne(5);   // 迭代器已失效，行为未定义
}

foreach 内部持有一份副本加一个迭代器，容器一变，迭代器就悬空。这类代码有时「看起来能跑」，有时崩，有时悄悄少删一个，取决于容器容量和数据量。

对照总结：

手法 安全性 适用
正序 for + removeAt(i) 错 别写
倒序 for + removeAt(i) 对 简单直接，下标有符号
STL 迭代器 + it = erase(it) 对 需要精确控制，能配合算法
QMutableListIterator::remove() 对 最易读，首推
foreach / 范围 for 里删 错 别写
QList::removeIf() 对 Qt6.1+，一行完事

映射容器的删除同理，只是换成 key：

cpp
QMutableMapIterator<int, QString> it(map);
while (it.hasNext())
{
    it.next();
    if (it.value().isEmpty())
        it.remove();   // 删掉当前 key-value 对
}

十一、Qt5 到 Qt6 的容器变化 #

这套教程写于 Qt5 时代。搬到 Qt6，容器层有几处硬变化，不标注会误导。

QVector 与 QList 合并。 Qt6 里 QVector 变成 QList 的别名，QList 的底层实现换成了原来 QVector 的连续数组。这件事影响两头：

  • Qt5 里 QList<T> 对大于指针的 T 存的是堆上的指针数组，逐元素访问多一次跳转；QVector<T> 是真正的连续内存，数值计算更快。所以 Qt5 里装 double、装大结构体要用 QVector。
  • Qt6 里两者是同一个东西，都是连续内存，QList 直接拿到了 QVector 的性能。Qt5 时代「数值用 QVector」的建议在 Qt6 不再必要。

QList::toVector() 在 Qt6 已经移除（因为转过去还是自己），toStdVector() 保留。

QLinkedList 被移除。 第三章讲过，Qt6 没有这个类，替代是 std::list。

QSet 的底层换过。 它和 QHash 同源，key 类型要 operator== 加 qHash()，迭代顺序从来不可依赖。Qt6 之后 QSet 与 QHash 的内部实现已经分开，但这条要求没变。

size() 的返回类型变了。 Qt5 返回 int，Qt6 返回 qsizetype。所有 int n = container.size(); 的写法都要跟着改，否则是窄化转换。同理 count()、indexOf()、循环变量类型。

qHash() 的签名变了。 Qt5 是 uint qHash(const T &key, uint seed = 0)，Qt6 是 size_t qHash(const T &key, size_t seed = 0)。自定义 key 的 qHash 重载必须改返回类型和参数类型。

foreach 还能用，但官方不推荐了。 Qt6 里定义 QT_NO_FOREACH 可以彻底禁用这个宏，强制团队改用范围 for。新项目直接写范围 for。

一张迁移对照表：

Qt5 Qt6 处理
QVector<T> QList<T> 的别名 代码能编过，可逐步替换命名
QLinkedList<T> 已移除 换 std::list<T>
list.toVector() 已移除 删掉这层转换
int n = list.size() qsizetype 改类型或 static_cast<int>
uint qHash(const T&, uint) size_t qHash(const T&, size_t) 改签名
QString::KeepEmptyParts Qt::KeepEmptyParts 换命名空间
qVariantValue<T>() 已移除 用 qvariant_cast<T>()
QList::removeIf Qt6.1 起可用 Qt5 里自己写循环

qAsConst 在 Qt6 仍然可用，但等价物是 C++17 的 std::as_const，新代码用后者。

Qt5 代码搬 Qt6 时，容器相关的编译错误九成集中在上表前四行。改完这几处，剩下的多半是 QString 的 API 变动。

十二、易错点速查 #

现象 原因 处理
遍历删元素，结果少删一半 正序 for + removeAt(i)，下标被跳过 倒序遍历，或 it = erase(it)
foreach 里改容器，随机崩溃 迭代器随容器修改而失效 换 QMutableListIterator 或 STL 迭代器
函数按值收 QList，性能反而很差 循环里用 operator[] 触发 detach 改 const 引用 + at()
范围 for 遍历后容器被复制 begin() 非 const，触发 COW detach 用 qAsConst(list) / std::as_const
QList<QObject> 编译失败 QObject 禁拷贝，容器要求元素可拷贝 装指针 QList<QObject *>
装指针的容器内存泄漏 容器不负责 delete 元素 qDeleteAll(c); c.clear();
QHash 遍历顺序每次不同 哈希表无序，Qt5 还随机化种子 要顺序就换 QMap
map.value(k) 拿到空值分不清 key 不存在时返回默认构造 T 传默认值 + contains() 判断
QMap 编译报 operator< 缺失 红黑树要求 key 可比较 给 key 类型补 operator<
QHash 编译报 qHash 缺失 哈希表要求可哈希 补 operator== 和全局 qHash()
自定义 qHash 后碰撞严重 没把 seed 传下去，或哈希函数太弱 return qHash(key.id, seed);
迭代器用着用着崩了 中间调了非 const 接口，容器 detach 修改后重新取迭代器
list.size() - 1 当循环起点崩了 空容器时 -1 被当成无符号巨大值 下标变量用 int
"a,,b".split(",") 多出空元素 默认 KeepEmptyParts 显式传 Qt::SkipEmptyParts

一句话收尾：容器选型看「要不要顺序」和「按什么访问」，遍历看「要不要在遍历中改」。这两件事想清楚，Qt 容器这块就不会踩坑。
