一、文本流与二进制流 #

先分层。QIODevice 是字节层，QFile、QBuffer、QTcpSocket、QProcess 都继承它。字节层只认 QByteArray，read() 给你一串 char，write() 收一串 char。它不知道什么是中文，什么是换行。

再往上一层是 QTextStream。它是「文本」和「字节流」之间的翻译层：一边是 QString（内部 UTF-16），一边是磁盘上的字节，中间靠一个编码规则做双向转换。你给它 QString，它按编码压成字节写出去；你从它读 QString，它按编码把字节还原成字符。

所以「写文件」拆开是三步：QFile::open() 拿到字节通道；QTextStream 拿这个通道当底座，负责编码翻译；<< 把 QString 交进去，flush() 把缓冲区推给操作系统。很多人卡在第一步和第二步的边界上，以为 QFile 会自己认中文。

三者的分工：

类型 处理对象 负责什么 编码感知
QFile QByteArray / char* 打开、定位、读写原始字节 完全不感知
QTextStream QString 文本↔字节转换、格式化、按行切分 全靠你设的编码
QDataStream 任意可序列化类型 定长二进制打包（int 固定 4 字节等） 不涉及，纯二进制

QTextStream 和 QDataStream 一字之差，用途完全不同。前者给人看，后者给程序看。

维度 文本流（QTextStream） 二进制流（QDataStream）
人类可读 是，记事本能开 否，二进制乱码
跨平台换行 自动处理 \r\n（QIODevice::Text） 不处理
数值精度 会丢（浮点变字符串） 原样保留
体积 大 小
版本兼容 好，格式自己定 依赖 Qt 版本和字节序
适用 配置、日志、XML、CSV 缓存、协议包、大型数组

要人能看、要跨版本，用文本流；要快、要省、要精确还原，用二进制流。

再说编码的本质。QString 存的是 UTF-16 码元，QChar 一个占 16 位。汉字「中」是 U+4E2D，内存里就是 0x4E2D。写到文件得按规则 encode：UTF-8 是 E4 B8 AD 三字节，GBK 是 D6 D0 两字节，UTF-16LE 是 2D 4E 两字节。同一个字三种字节序列，读的时候编码对不上就还原成别的字。这就是乱码的全部原理。

QTextStream 不设编码时用系统默认。Qt5 在 Windows 中文环境下这个默认是 GBK（代码页 936）。于是程序在本机写、本机读一切正常；文件发给用 UTF-8 的同事，全是「锟斤拷」。结论提前说：文本文件一律显式设成 UTF-8，别赌默认值。

二、QTextStream 的用法 #

构造 #

三种构造方式，对应三种底座：

cpp
// 1. 挂在 QIODevice 上（QFile、QBuffer、QTcpSocket 都行）
QFile file("F:/test.txt");
QTextStream out(&file);
QTextStream w(&file, QIODevice::WriteOnly);

// 2. 挂在 QString 上：设备就是内存，用于拼字符串
QString buffer;
QTextStream mem(&buffer, QIODevice::WriteOnly);

// 3. 挂在 C 的 FILE* 上：stdout / stderr
QTextStream console(stdout);

第二种形式很实用——它让「拼一段带格式的文本」变成流式输出，不用一路 +=。构造函数不替你打开文件，QFile::open() 必须在前面且必须检查返回值，否则流对象挂在一个没打开的设备上，所有写入静默丢弃。

写入 #

cpp
void WriteText()
{
    QFile file("F:/test.txt");
    if (!file.open(QIODevice::WriteOnly | QIODevice::Text)) {
        qDebug() << "打开失败：" << file.errorString();
        return;
    }
    QTextStream out(&file);
    out.setCodec("UTF-8");     // Qt6 改成 out.setEncoding(QStringConverter::Utf8);
    out << "Hello\n";
    out << "World\n";
    out << QString::fromUtf8("中文一行\n");
    out << 42 << ' ' << 3.14159 << '\n';
    out.flush();               // 把内部缓冲区压进 QFile
    file.close();
}

QIODevice::Text 在 Windows 上把 \n 自动翻成 \r\n，读的时候再翻回来，文本模式建议一直带上。flush() 把 QTextStream 的缓冲区清空到设备，file.close() 也会触发一次，但提前 return 的分支不会——显式 flush 能保住已写的内容。

读取 #

函数 行为 什么时候用
readLine() 读一行，去掉行尾换行符 逐行处理大文件
readAll() 一次读完剩下的全部 小配置文件
read(n) 读 n 个字符 定长字段
operator>> 按空白分词读一个「词」 空格分隔的数据 
cpp
void ReadText()
{
    QFile file("F:/test.txt");
    if (!file.open(QIODevice::ReadOnly | QIODevice::Text))
        return;
    QTextStream in(&file);
    in.setCodec("UTF-8");      // Qt6：in.setEncoding(QStringConverter::Utf8);

    while (!in.atEnd()) {      // 逐行读，用 atEnd() 判断结束
        QString line = in.readLine();
        qDebug() << line;
    }
    file.close();
}

新手常写成这样：

cpp
QString Line;
while ((Line = out.readLine()) != NULL) {   // 错的
}

两个问题。readLine() 返回 QString 不是指针，跟 NULL 比较是在跟空字符串比。更要紧的是没法区分「读到一个空行」和「已经读完」——文件里本来就有空行时，循环会提前退出。正确写法是 while (!in.atEnd())，或者：

cpp
while (true) {
    QString line = in.readLine();
    if (line.isNull())      // 真正读完时返回 null QString
        break;
    process(line);          // 空行 "" 会走到这里，isNull() 为 false
}

readLine() 到末尾返回 null QString，空行返回空但非 null 的 QString。isNull() 和 isEmpty() 是两个状态，这是那个坑的关键。

定位与状态：in.pos() 给当前字符位置，in.seek(0) 回开头，in.status() 返回 Ok / ReadPastEnd / ReadCorruptData，in.reset() 清缓冲并重置状态。读完整个文件后再读会变成 ReadPastEnd，这是正常现象，不是错误。

三、编码设置 #

这是全篇最容易出事的章节。QTextStream 的编码在两个大版本之间换了名字，也换了做法：

项目 Qt5 Qt6
设编码 setCodec("UTF-8") setEncoding(QStringConverter::Utf8)
取编码 codec()->name() encoding()
编码类 QTextCodec（QtCore 内） QStringConverter；QTextCodec 移到 core5compat
默认编码 系统本地编码（Windows 中文 = GBK） UTF-8
工程配置 无 用 QTextCodec 需 QT += core5compat

Qt5：

cpp
#include <QTextStream>
#include <QTextCodec>

QTextStream in(&file);
in.setCodec("UTF-8");                             // 最简形式
in.setCodec(QTextCodec::codecForName("GBK"));     // 需要 GBK 时
in.setCodec(QTextCodec::codecForMib(106));        // 按 MIB 编号

Qt6：

cpp
#include <QTextStream>
#include <QStringConverter>

QTextStream in(&file);
in.setEncoding(QStringConverter::Utf8);      // 默认值，仍建议写明
in.setEncoding(QStringConverter::Latin1);
in.setEncoding(QStringConverter::System);    // 要「回到旧行为」才用它

QStringConverter::Encoding 只有 Utf8、Utf16、Utf16LE、Utf16BE、Utf32、Latin1、System 这么几个，不像 QTextCodec 能枚举几十种。GBK、Shift-JIS 在 Qt6 里要么走 System，要么自己上 ICU。

想同时兼容两个版本，用条件编译：

cpp
QTextStream in(&file);
#if QT_VERSION < QT_VERSION_CHECK(6, 0, 0)
in.setCodec("UTF-8");
#else
in.setEncoding(QStringConverter::Utf8);
#endif

BOM 的问题 #

UTF-8 文件可以有 BOM（EF BB BF），也可以没有。Windows 记事本保存 UTF-8 时默认带。BOM 不是字符，但不处理就会被当成正文第一个字符——读出来的第一行首部多一个看不见的 \uFEFF，字符串比较全部失败。

cpp
out.setGenerateByteOrderMark(false);   // 写：不带 BOM（Linux/Unix 友好，推荐）
in.setAutoDetectUnicode(true);         // 读：自动识别并跳过 BOM

setAutoDetectUnicode() 默认就是 true，它检查开头是不是 UTF-16/UTF-32 的 BOM 并据此切换编码，但不认 UTF-8 的 BOM——那个得自己清：QString first = in.readLine(); 之后判断 first.at(0) == QChar(0xFEFF)，是就 first.remove(0, 1)。

手工转换 #

不经过流，直接在 QString 和 QByteArray 之间转：

cpp
QByteArray utf8  = str.toUtf8();
QString    back  = QString::fromUtf8(utf8);
QByteArray latin = str.toLatin1();

// Qt5 专用：任意编码
QTextCodec *codec = QTextCodec::codecForName("GBK");
QByteArray  gbkBytes = codec->fromUnicode(str);
QString     restored = codec->toUnicode(gbkBytes);

fromLocal8Bit / toLocal8Bit 是最容易被误用的两个函数。「本地」指运行环境，在你的机器上是 GBK，在别人的服务器上是 UTF-8。用它读写文件，跨机器必出问题。只在跟系统 API 打交道时才用，比如读 argv、写注册表路径。

四、格式化与对齐 #

QTextStream 有一整套格式化开关，做日志、做导出、做对齐表格全靠它：

成员函数 作用 常见取值
setFieldWidth(n) 输出项占 n 个字符宽 0 表示关闭
setPadChar(c) 宽度不足时的填充字符 ' '、'0'
setFieldAlignment(a) 填充位置 AlignLeft/AlignRight/AlignCenter/AlignAccountingStyle
setIntegerBase(b) 整型输出进制 2、8、10、16
setRealNumberPrecision(p) 浮点保留的小数位数 1~17
setRealNumberNotation(n) 浮点记法 FixedNotation/ScientificNotation/SmartNotation
setNumberFlags(f) 数字修饰 ShowBase/ForceSign/ForcePoint/UppercaseDigits

关键在于：字段宽度只对紧跟着的那一个输出项生效，输出完自动清零。所以每一列都得重新设一次。

cpp
QFile file("books.txt");
if (!file.open(QIODevice::WriteOnly | QIODevice::Text))
    return;
QTextStream out(&file);
out.setCodec("UTF-8");

out.setFieldAlignment(QTextStream::AlignLeft);
out.setFieldWidth(24);
out << "书名";
out.setFieldAlignment(QTextStream::AlignRight);
out.setFieldWidth(8);
out << "章节数" << Qt::endl;

out.setFieldAlignment(QTextStream::AlignLeft);
out.setFieldWidth(24);
out << QString::fromUtf8("Qt5 自学教程");
out.setFieldAlignment(QTextStream::AlignRight);
out.setFieldWidth(8);
out << 12 << Qt::endl;
file.close();

text
书名                    章节数
Qt5 自学教程              12

中文字符是按字符数算宽度，不是按终端显示宽度。一个汉字在等宽字体里占两格，setFieldWidth 只算一个字符，纯中文的表在终端里会对不齐。要严格对齐就得自己按显示宽度补空格，或者换 QTableView。

AlignAccountingStyle 是给金额用的，正负号单独占一列，负数不会把数字挤歪。

setPadChar 和 setNumberFlags 都是持久设置，不像宽度那样自动复位。忘了关就会让后面所有输出项都补零、带前缀。

setIntegerBase(16) 配 ShowBase | UppercaseDigits 打出来是 0XFF；setRealNumberNotation(FixedNotation) 配 setRealNumberPrecision(3) 把 3.14159265 压成 3.142。

这些也有操作符版本，可以夹在 << 链里：

cpp
out << qSetFieldWidth(10) << hex << showbase << 255
    << qSetRealNumberPrecision(4) << qSetFieldWidth(0) << dec << Qt::endl;

qSetFieldWidth、qSetPadChar、qSetRealNumberPrecision 只作用一次；hex/dec/bin/oct、showbase、fixed/scientific、forcesign 是持久状态。left / right / center 也有操作符版本，但它们占的是全局命名空间的名字，跟 Qt::left 撞在一起时编译器挑不出来，用 setFieldAlignment 更省心。

endl 是「换行 + flush」，Qt::endl 是新写法。只想换行就写 '\n'——循环里用 endl 会让每次换行都触发一次系统调用，写十万行日志时差距很明显。

五、读写文件与内存 #

QTextStream 不关心底座是什么，同一段格式化代码可以原封不动用在文件、内存、控制台上：

cpp
QFile file("log.txt");
file.open(QIODevice::WriteOnly | QIODevice::Append | QIODevice::Text);
QTextStream toFile(&file);          // 落到文件

QString s;
QTextStream toMem(&s, QIODevice::WriteOnly);   // 落到内存

QTextStream toConsole(stdout);      // 落到标准输出

QByteArray raw;
QBuffer buf(&raw);
buf.open(QIODevice::WriteOnly);
QTextStream toBuf(&buf);            // 落到 QBuffer

追加写用 QIODevice::Append，它把写入位置移到文件尾。只写 WriteOnly 是截断模式，每次打开都把原文件清空。

内存流最被低估。拼 SQL、拼 HTML、拼 CSV，比一路 += 干净：

cpp
QString buildCsv(const QList<Book> &books)
{
    QString out;
    QTextStream s(&out, QIODevice::WriteOnly);
    s << "name,chapters,price\n";
    for (const Book &b : books)
        s << b.name << ',' << b.chapters << ',' << b.price << '\n';
    return out;
}

流持有的是 QString*，函数返回时流先析构、out 才被拷贝出去，顺序是对的。反过来，QString 先死、流还活着，就是悬垂引用。

方式 内存占用 适用场景
readAll() 整个文件大小 配置、几 MB 以内的小文件
readLine() 循环 一行大小 日志、CSV、几百 MB 的大文件
read(n) 分块 n 个字符 定长记录

小文件用 readAll() + split('\n') 更省事：

cpp
QTextStream in(&file);
in.setCodec("UTF-8");
const QStringList lines = in.readAll().split('\n', Qt::SkipEmptyParts);

Qt5 里第二个参数叫 QString::SkipEmptyParts，Qt6 挪到了 Qt::SkipEmptyParts。这是 Qt5 代码迁 Qt6 时最常见的编译错误之一。

QFile 的操作失败不抛异常，全靠返回值：

cpp
if (!file.open(QIODevice::WriteOnly | QIODevice::Text)) {
    qWarning() << "open failed:" << file.errorString() << file.error();
    return;
}
QFileDevice::FileError 含义
NoError 正常
OpenError 打不开（路径不存在、没权限）
ReadError / WriteError 读/写失败
PermissionsError 权限不足
ResourceError 资源不足（磁盘满、fd 用尽）

F:/test.txt 这种硬编码绝对路径只适合跑示例。真做项目，路径从 QStandardPaths::writableLocation(QStandardPaths::AppDataLocation) 拿，再 QDir::mkpath() 建目录。

六、XML 的两种解析方式 #

XML 是棵树：一个根元素，下面挂子元素，元素带属性，元素之间夹文本。Qt 提供两套读法，对应两种截然不同的内存模型。

xml
<?xml version="1.0" encoding="UTF-8"?>
<Books>
    <Book Name="Qt5 自学教程" ID="0">
        <Chapter Name="信号与槽" ID="0"/>
        <Chapter Name="布局与控件" ID="1"/>
        <Chapter Name="文本流与 XML" ID="2"/>
    </Book>
    <Book Name="C++ 模板" ID="1">
        <Chapter Name="函数模板" ID="0"/>
    </Book>
</Books>

这份 books.xml 后面几章都用它。

类 模型 内存 能否回溯
QDomDocument DOM 树，整份建成节点树 与文件同量级，常见 5~10 倍 能，随便跳
QXmlStreamReader 流式/拉模式，一次一个事件 只占当前元素 不能，读完就过
QXmlSimpleReader SAX 推模式，回调驱动 很小 不能

第三种是历史包袱，接口老、写起来啰嗦，新代码不用它。模块依赖别忘：QDomDocument 在 QtXml 模块里，.pro 不写 xml 就链接不过。

两种模型的心理图景：DOM 是文件读完你手里有一棵完整的树，想问哪个节点就问哪个，往上找父节点也行，改完再写回也行；流式是文件成了条河，你站在岸边 readNext() 捞事件，处理完扔掉，河水流过不回头。

所以选型判据很清楚：大文件用流式，要反复查找用 DOM，第九章展开说。

七、QDomDocument：DOM 树 #

加载与错误检查 #

三步：打开文件、setContent() 解析、检查返回值。

cpp
QDomDocument doc;
QFile file("F:/test.xml");
if (!file.open(QIODevice::ReadOnly | QIODevice::Text))
    return -1;

QString errorMsg;
int errorLine = 0, errorColumn = 0;
if (!doc.setContent(&file, &errorMsg, &errorLine, &errorColumn)) {
    qDebug() << errorMsg << "line" << errorLine << "col" << errorColumn;
    file.close();
    return -1;
}
file.close();

setContent() 有五个重载，最常用的是收 QIODevice* 和收 QByteArray 的两个。它返回 bool，失败时 doc 是个空文档——根元素为空，任何 firstChildElement() 都返回空节点，任何 attribute() 都返回空字符串。

这就是不检查错误的代价：程序不崩，但后面一路空值，跑出来全是空结果，你还不知道错在哪。解析必须检查返回值，并把 errorLine 打出来，XML 报错九成在行号上。

找节点 #

入口是根元素：

cpp
QDomElement root = doc.documentElement();       // 等价于 doc.firstChildElement()
if (root.isNull())
    return -1;
qDebug() << "root tag =" << root.tagName();     // Books

往下找有三种方式：

函数 范围 返回
elementsByTagName(name) 该节点下所有后代中匹配的元素 QDomNodeList
firstChildElement(name) 直接子元素中的第一个匹配 QDomElement
childNodes() 全部直接子节点（含文本、注释） QDomNodeList

elementsByTagName() 是递归的：在根上找 Book 拿到所有 Book，在某本 Book 上找 Chapter 拿到它自己的章节。方便，也是陷阱——在根上找 Chapter 会把所有书的章节压平成一个列表，父子关系就没了。

节点与元素的区别 #

QDomNode 是基类，QDomElement 是子类。QDomNodeList 里装的是 QDomNode，元素、文本、注释、处理指令都有。用之前先判类型：

cpp
if (bookNode.isElement()) {
    QDomElement book = bookNode.toElement();
    // 现在才能用 tagName() / attribute()
}

不判直接 toElement() 也能编译，拿到的是空元素，attribute() 返回空字符串，问题被推迟到很远的地方才暴露。

完整例子：遍历并打印 #

读 books.xml，先列书名，再逐本列章节：

cpp
// 2014/9/16
// 读取 xml 文件内容并显示在控制台
#include <QCoreApplication>
#include <QDomDocument>
#include <QDomElement>
#include <QFile>
#include <QDebug>

void ListElement(QDomElement root, const QString &tagName, const QString &attribute)
{
    QDomNodeList items = root.elementsByTagName(tagName);
    qDebug() << "Total items =" << items.count();
    for (int i = 0; i < items.count(); ++i) {
        QDomNode itemNode = items.at(i);
        if (itemNode.isElement()) {
            QDomElement item = itemNode.toElement();
            qDebug() << " -" << item.attribute(attribute)
                     << "ID =" << item.attribute("ID");
        }
    }
}

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);
    QDomDocument doc;
    QFile file("F:/test.xml");
    if (!file.open(QIODevice::ReadOnly | QIODevice::Text)) {
        qDebug() << "Failed to open file";
        return -1;
    }
    QString errorMsg;
    int errorLine = 0, errorColumn = 0;
    if (!doc.setContent(&file, &errorMsg, &errorLine, &errorColumn)) {
        qDebug() << "Failed to load document:"
                 << errorMsg << "line" << errorLine << "col" << errorColumn;
        return -1;
    }
    file.close();

    // 获得根元素
    QDomElement root = doc.firstChildElement();
    if (root.isNull()) {
        qDebug() << "no root element";
        return -1;
    }
    // 读取指定节点下的元素
    qDebug() << "Books:";
    ListElement(root, "Book", "Name");

    qDebug() << "\r\nMore Advanced";
    // QDomNodeList 是包含 QDomNode 对象的列表
    QDomNodeList books = root.elementsByTagName("Book");
    for (int i = 0; i < books.count(); ++i) {
        QDomNode bookNode = books.at(i);
        if (bookNode.isElement()) {                 // 是元素才往下走
            QDomElement book = bookNode.toElement();
            qDebug() << "Chapter in" << book.attribute("Name");
            ListElement(book, "Chapter", "Name");
        }
    }
    qDebug() << "Finished";
    return 0;
}

text
Books: 2 本
More Advanced
Chapter in "Qt5 自学教程" -> 3 章
Chapter in "C++ 模板" -> 1 章
Finished

要往上找，QDomNode::parentNode() 返回父节点，配 nextSibling() / firstChild() 就能自己写递归遍历整棵树。

八、QXmlStreamReader：流式解析 #

流式的思路是「拉」：你主动调 readNext()，它每次吐一个 token，类型有 StartDocument、StartElement、EndElement、Characters、Comment、EndDocument。

cpp
#include <QXmlStreamReader>
#include <QDebug>

QFile file("F:/test.xml");
if (!file.open(QIODevice::ReadOnly | QIODevice::Text))
    return -1;
QXmlStreamReader xml(&file);
while (!xml.atEnd() && !xml.hasError()) {
    QXmlStreamReader::TokenType token = xml.readNext();
    if (token == QXmlStreamReader::StartElement) {
        if (xml.name() == QLatin1String("Book")) {
            qDebug() << "Book:" << xml.attributes().value("Name").toString();
        } else if (xml.name() == QLatin1String("Chapter")) {
            qDebug() << "  Chapter:" << xml.attributes().value("Name").toString();
        }
    }
}
if (xml.hasError()) {
    qDebug() << "XML error:" << xml.errorString()
             << "line" << xml.lineNumber() << "col" << xml.columnNumber();
    return -1;
}
file.close();

xml.name() 返回 QStringView（Qt6）或 QStringRef（Qt5），跟 QLatin1String 比较是零分配的。attributes() 返回 QXmlStreamAttributes，value("Name") 拿到的同样是轻量引用，.toString() 才真正分配内存。

元素内容是纯文本时，别自己拼：

cpp
// <Name>信号与槽</Name>
if (xml.isStartElement() && xml.name() == QLatin1String("Name")) {
    QString text = xml.readElementText();   // 读内容，并自动跳到 EndElement
}

readElementText() 一次把开始标签到结束标签之间的文本取出来，游标停在 EndElement 之后。元素里还嵌着子元素时它会返回拼接后的文本，所以只对叶子元素用。

Qt 官方示例里更常见的写法是：

cpp
while (xml.readNextStartElement()) {
    if (xml.name() == QLatin1String("Book"))
        parseBook(xml);                  // 自己递归进去
    else
        xml.skipCurrentElement();        // 不认识就整段跳过
}

readNextStartElement() 内部循环 readNext() 直到遇见开始元素或文档结束；skipCurrentElement() 把当前元素连同子元素一起吃到一个 EndElement 上，这是对流式解析里「未知标签」最省心的处理。

错误检查在循环外还得再来一次：

cpp
if (xml.hasError()) {
    qWarning() << "解析失败：" << xml.errorString()
               << "第" << xml.lineNumber() << "行";
    return -1;
}

循环条件里虽然带了 !xml.hasError()，但 atEnd() 在出错时同样返回 true。漏掉这一判，解析失败时你只会看到「什么都没输出」，连哪一行错了都不知道。QXmlStreamReader 遇错即停，错误后 name()、attributes() 全返回空，所以检查要放在循环结束后立刻做。

九、DOM 与流式的取舍 #

维度 QDomDocument QXmlStreamReader
内存 与文件同量级，10 倍常见 只占当前元素
随机访问 能，任意节点随便跳 不能，读完就过
回溯 能，parentNode() 往上走 不能
修改后写回 能，改树再 toString() 不能，只能读
解析速度 慢（建树有开销） 快
代码量 少，直接查 多，得自己维护状态
上手难度 低 中
适用 配置文件、UI 描述、小 XML 日志、导出、几百 MB 的 XML

判据只有一句：大文件用流式，要反复查找用 DOM。具体到场景：配置只读一次、几百行、要在里面找十几种节点，用 DOM；服务器拉回来的 5 MB 数据边解边入库，用流式；只关心某一段、其余跳过，用流式配 skipCurrentElement()；要改完存回去，或者要按父节点、兄弟节点做关系判断，用 DOM。

还有一种混合打法：外层用 QXmlStreamReader 快速定位到目标元素，把那一小段子树转成字符串，再喂给 QDomDocument 单独解析。既有流式的速度，又有 DOM 的便利——大文件里只挖一小块时值得这么做。

十、写 XML #

用 QDomDocument 拼树 #

cpp
QDomDocument doc;
// 处理指令就是第一行的 <?xml version="1.0" encoding="UTF-8"?>
doc.appendChild(doc.createProcessingInstruction(
    "xml", "version=\"1.0\" encoding=\"UTF-8\""));

QDomElement root = doc.createElement("Books");
doc.appendChild(root);

QDomElement book = doc.createElement("Book");
book.setAttribute("Name", "Qt5 自学教程");
book.setAttribute("ID", 0);
root.appendChild(book);

QDomElement chapter = doc.createElement("Chapter");
chapter.setAttribute("Name", "文本流与 XML");
book.appendChild(chapter);

QFile file("F:/test.xml");
if (!file.open(QIODevice::WriteOnly | QIODevice::Text | QIODevice::Truncate)) {
    qDebug() << "Failed to write file";
    return;
}
QTextStream out(&file);
out.setCodec("UTF-8");       // Qt6：setEncoding(QStringConverter::Utf8)
out << doc.toString(4);      // 4 是缩进空格数
out.flush();
file.close();

doc.toString(4) 输出格式化后的 XML，不带参数的话全挤在一行——内容没错，但人没法看。

createElement 之后元素还没进树，必须 appendChild 才挂上去。这一步漏了，toString() 里就只有一根光杆根元素。属性值里的 &、<、" 会被自动转义成 &amp;、&lt;、&quot;，不用自己处理。

打开模式里的 QIODevice::Truncate 不能省。写回原文件时新内容比旧的短，不截断就会在末尾留下上一版的残余字节，拼出一份坏 XML。

用 QXmlStreamWriter #

不建树，直接往流里写，省内存：

cpp
QXmlStreamWriter w(&file);           // file 已按 WriteOnly | Text | Truncate 打开
w.setAutoFormatting(true);
w.writeStartDocument();              // 自动写 XML 声明
w.writeStartElement("Books");
w.writeStartElement("Book");
w.writeAttribute("Name", "Qt5 自学教程");
w.writeAttribute("ID", "0");
w.writeTextElement("Chapter", "文本流与 XML");
w.writeEndElement();                 // 关 Book
w.writeEndElement();                 // 关 Books
w.writeEndDocument();

QXmlStreamWriter 自己在内部处理编码（默认 UTF-8），不需要 QTextStream 包一层。writeAttribute() 同样做转义，setAutoFormatting(true) 打开缩进。

维度 QDomDocument 建树 QXmlStreamWriter
内存 全在内存，与输出等量 只占当前层
先攒后写 支持，可反复改 不支持，写了就走
适合 少量、需要反复调整 大量、顺序直出

十一、做一个小型 XML 编辑器 #

把读和写接起来：一个窗口，一棵树，一个保存按钮。读 XML 填树，改树写回 XML。

界面 #

在 Qt Designer 里给 Dialog 放两个控件：

控件 objectName 用途
QTreeView treeView 显示 Book / Chapter 两级结构
QPushButton pushButton 文本改成「保存」，点一下写回 XML

.pro 里要 QT += core gui xml（第六章写过），再加本篇的源文件：

SOURCES += main.cpp dialog.cpp
HEADERS += dialog.h
FORMS   += dialog.ui

头文件 #

cpp
#ifndef DIALOG_H
#define DIALOG_H

#include <QDialog>
#include <QFile>

    Q_OBJECT

private slots:
    void on_pushButton_clicked();       // 保存

private:

树的两级靠 QStandardItem 的父子关系表达：根项叫 Books，下面每行一本书，每本书下面挂章节。这套模型在第五篇《模型视图与 QVariant》里讲过，这里直接复用。on_pushButton_clicked() 是 auto-connect 命名，setupUi() 自动连好，不用写 connect。

读：XML 到树 #

cpp
#include "dialog.h"
#include "ui_dialog.h"
#include <QDomDocument>
#include <QTextStream>
#include <QDebug>

Dialog::Dialog(QWidget *parent) :
    QDialog(parent),
    ui(new Ui::Dialog)
{
    ui->setupUi(this);
    fileName = "F:/test.xml";
    model = new QStandardItemModel(0, 1, this);
    model->setHeaderData(0, Qt::Horizontal, "Books / Chapters");
    ui->treeView->setModel(model);
    ReadFile();                         // 启动就把文件读进来
}

Dialog::~Dialog()
{
    delete ui;
}

void Dialog::ReadFile()
{
    model->removeRows(0, model->rowCount());   // 重新加载时不叠加
    QStandardItem *root = new QStandardItem("Books");
    model->appendRow(root);

    QDomDocument doc;
    QFile file(fileName);
    if (!file.open(QIODevice::ReadOnly | QIODevice::Text)) {
        qDebug() << "Failed to open" << fileName;
        return;
    }
    QString errorMsg;
    int errorLine = 0, errorColumn = 0;
    if (!doc.setContent(&file, &errorMsg, &errorLine, &errorColumn)) {
        qDebug() << "Parse error:" << errorMsg
                 << "line" << errorLine << "col" << errorColumn;
        file.close();
        return;
    }
    file.close();

    QDomElement xmlRoot = doc.documentElement();     // 根元素
    QDomNodeList books = xmlRoot.elementsByTagName("Book");
    for (int i = 0; i < books.count(); ++i) {
        QDomNode bookNode = books.at(i);
        if (!bookNode.isElement())
            continue;
        QDomElement book = bookNode.toElement();
        QStandardItem *bookItem = new QStandardItem(book.attribute("Name"));
        // 读这本书下的章节
        QDomNodeList chapters = book.elementsByTagName("Chapter");
        for (int h = 0; h < chapters.count(); ++h) {
            QDomElement chapter = chapters.at(h).toElement();
            QStandardItem *chapterItem = new QStandardItem(chapter.attribute("Name"));
            bookItem->appendRow(chapterItem);
        }
        root->appendRow(bookItem);
    }
    ui->treeView->expandAll();          // 两级都展开
}

removeRows(0, model->rowCount()) 放在开头，是为了「重新加载」时不叠加；首次调用时模型是空的，这一句不做事。

写：树到 XML #

cpp
void Dialog::WriteFile()
{
    QStandardItem *root = model->item(0, 0);
    if (!root)
        return;

    QDomDocument doc;
    doc.appendChild(doc.createProcessingInstruction(
        "xml", "version=\"1.0\" encoding=\"UTF-8\""));
    QDomElement xmlRoot = doc.createElement("Books");
    doc.appendChild(xmlRoot);

    for (int i = 0; i < root->rowCount(); ++i) {
        QStandardItem *book = root->child(i, 0);
        if (!book)
            continue;

        QDomElement xmlBook = doc.createElement("Book");
        xmlBook.setAttribute("Name", book->text());
        xmlBook.setAttribute("ID", i);
        xmlRoot.appendChild(xmlBook);

        for (int h = 0; h < book->rowCount(); ++h) {
            QStandardItem *chapter = book->child(h, 0);
            if (!chapter)
                continue;
            QDomElement xmlChapter = doc.createElement("Chapter");
            xmlChapter.setAttribute("Name", chapter->text());
            xmlChapter.setAttribute("ID", h);
            xmlBook.appendChild(xmlChapter);
        }
    }

    QFile file(fileName);
    if (!file.open(QIODevice::WriteOnly | QIODevice::Text | QIODevice::Truncate)) {
        qDebug() << "Failed to write file";
        return;
    }
    QTextStream out(&file);
    out.setCodec("UTF-8");      // Qt6：out.setEncoding(QStringConverter::Utf8);
    out << doc.toString(4);
    out.flush();
    file.close();
    qDebug() << "Finished";
}

void Dialog::on_pushButton_clicked()
{
    WriteFile();                // 保存
}

这套往返就这样：启动读 XML 填 model，双击节点改名字，点保存把 model 转回 XML 落盘，关掉再开还是改后的内容。

几个真会踩的点 #

ID 用循环下标是权宜之计。 删掉中间一本书，后面所有书的 ID 全变，外部引用就对不上。真项目要用稳定 ID（UUID 或时间戳），存在节点的 Qt::UserRole 里。

中文要落对编码。 doc.toString() 返回 QString，写出去那一步必须显式设 UTF-8，否则 Qt5 在中文 Windows 下按 GBK 落盘，文件头的 encoding="UTF-8" 就和实际字节打架。

QStandardItem 默认可编辑。 不想要就 setEditable(false)，或在 treeView 上设 setEditTriggers(QAbstractItemView::NoEditTriggers)。想限制只能改章节不能改书名，就在建 bookItem 时单独关。

空树保存会把文件清空。 拿不到根项就直接 return，别硬写——一份空文档比一份旧文档更糟。

十二、易错点速查 #

现象 原因 修法
文件里中文变问号或乱码 没设编码，走了系统默认 setCodec("UTF-8") / setEncoding(Utf8)
读出的第一行开头有个怪字符 文件带 UTF-8 BOM 判 QChar(0xFEFF) 后 remove(0, 1)
逐行读时循环提前退出 用 readLine() != NULL 判结束 改成 while (!in.atEnd())
写入的内容只出现一部分 没 flush() 就提前 return 退出前 out.flush()
追加写变成了覆盖 只写了 WriteOnly 加 QIODevice::Append
改短后文件末尾有残余 没加 Truncate 加 QIODevice::Truncate
解析失败后一路空值 setContent() 返回值没判 判返回值并打印 errorLine
流式解析静默无输出 循环后没判 hasError() errorString() + lineNumber()
toElement() 拿到空元素 节点不是元素 先 isElement() 再转
找不到想要的节点 elementsByTagName() 是递归的 缩小范围到父元素再查
表格输出最后一列错位 字段宽度只作用一次 每个输出项前重设 setFieldWidth
数字全补了零 setPadChar('0') 是持久设置 用完 setPadChar(' ') 复位
链接报找不到 QDomDocument .pro 少了模块 QT += xml
Qt6 编译报 setCodec 不存在 API 改名 换 setEncoding，或用 core5compat
SkipEmptyParts 找不到 Qt6 挪了命名空间 用 Qt::SkipEmptyParts

一页纸能查完的东西，别去翻文档。真出问题时先确认三件事：文件到底是不是 UTF-8、open() 的返回值是不是 true、解析的返回值是不是 true。这三处对了，剩下的都是逻辑问题。
