一、Qt 是什么 #

先把名字念对。Qt 的官方发音和英文 cute 一样，cute 是「可爱的、漂亮的」。有人习惯读「Q-T」两个字母，老外一般直接读 cute。

Qt 是一个跨平台的 C++ 开发框架。它最出名的是做图形界面，但界面只是它的一部分：控制台工具、后台服务、嵌入式设备上的程序，都能用 Qt 写。你想做的东西只要能塞进 C++，Qt 都能陪你走完。

它是 Digia 公司的产品，自由且开源，在 GNU 宽通用公共许可证（LGPL / GPL）条款下发布。这一点值得单独说一句：源码在你手上，遇到问题能翻实现，不用等厂商排期。所有版本都支持一堆编译器，GCC 的 C++ 编译器和 Visual Studio 的编译器都在名单里。换平台换编译器，业务代码几乎不用动，这是 Qt 最实在的价值。

二、Qt 与 C++ 的关系 #

不少初学者会被 Qt 的写法绕住，以为这是另一门语言。不是。Qt 就是一个 C++ 类库，加上两个代码生成器。你写的仍然是 C++，编译的仍然是 g++ 或 cl，new 和 delete、继承、虚函数、模板，一样不落。

那「特殊代码」是什么？两处。

第一处：Q_OBJECT 宏和 moc。

信号槽不是 C++ 语言自带的机制。C++ 里没有「信号」这个关键字，也没有办法在运行期按名字调用一个成员函数。Qt 的做法是：你在类里写 Q_OBJECT，moc 扫描这个头文件，生成一个 moc_xxx.cpp，里面塞进一张表，记录「这个类有哪些信号、哪些槽、名字是什么、参数类型是什么」。connect 的时候查这张表，发信号的时候也查这张表。所以：

  • Q_OBJECT 必须写在类的 private 区，且类要直接或间接继承 QObject。
  • 忘了写 Q_OBJECT，connect 会静默失败，运行时只给你一行警告，不报错。这是新手最容易踩的坑。
  • 改了头文件里的信号或槽，要重新跑 qmake，让 moc 重新生成。只点「构建」有时候不生效。

第二处：uic 生成的 ui_xxx.h。

你在 Designer 里拖了一个 pushButton，uic 就在 ui_mainwindow.h 里生成一个类，成员叫 pushButton，类型是 QPushButton*。于是你在代码里能写 ui->pushButton->setText("Close")。这不是魔法，是生成的代码。

Qt 的写法与原生 C++ 对照

三、第一个程序：Hello World #

Hello World 在所有语言的学习里都排第一，因为它足够小，又能跑通「写代码 → 编译 → 运行」这条完整链路。我们也从它开始，只是用 Qt 的方式写：建一个控制台工程，让程序同时用三种方式把同一句话吐出来。

第一步：建工程

模板选「Qt Console Application」，不要选「Qt Widgets Application」。选错了程序也能跑，但会多出一堆用不上的文件，后面看工程结构会糊涂。向导走三步：选模板、选构建套件（Kit）、填工程名和保存路径。路径不要带中文和空格。这条规矩要记住，qmake 在空格路径上的表现一直不够稳，中文路径在部分编码下还会引起 moc 报错。

第二步：写 main.cpp

原稿的注释被换行截断了几处，代码块也是几段粘合的。下面这版能直接编译。

cpp
// 2014/7/19 wayne HDU
// 问题描述：让控制台程序输出 Hello World
// 分别使用 Qt 库设施和标准库设施实现输出

#include <QCoreApplication>
#include <QDebug>
#include <QTextStream>

#include <iostream>
#include <string>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // 方法一：用 qDebug 设施输出
    // QString 类提供 Unicode 字符串，便于程序国际化
    QString sentence = "Hello World";

    // qDebug 调用调试信息处理程序。没有处理程序时，内容被打印到 stderr
    // 窗口模式下该消息被传输到控制台，否则传输到调试器
    qDebug() << sentence;

    // 方法二：用标准库 cout 输出流
    std::string new_sentence = "\"Hello World\"";
    std::cout << new_sentence << std::endl;

    // 方法三：用 Qt 库的文本输出流
    // QTextStream 提供方便的读写接口，这里把 cout 与标准输出关联
    QTextStream cout(stdout);
    cout << sentence << endl;

    return a.exec();
}

三种输出的区别

方式 头文件 输出到哪 适合场景
qDebug() <QDebug> 没有处理程序时进 stderr，窗口模式下进控制台或调试器 调试信息，能自动加引号、能直接打 Qt 类型
std::cout <iostream> 标准输出 你熟悉的标准 C++ 流程，和 Qt 类型混用要转换
QTextStream <QTextStream> 你指定的 FILE* 或 QString 要格式化数字、要写到文件、要拼字符串

运行起来，控制台看到三行：

text
Hello World
"Hello World"
Hello World

第一行是 qDebug 的输出，注意它给 QString 自动加了双引号，这是 qDebug 处理 QString 的固定行为。第二行带双引号是因为我们自己在字符串里写了转义的 \"。第三行是 QTextStream，它不加引号，和 cout 一致。

为什么控制台程序也要 QCoreApplication

因为 a.exec() 启动了事件循环。控制台程序如果只用 cout，理论上可以不要这两行，直接 return 0。但只要程序里出现任何 Qt 的事件、定时器、网络请求，就必须有 QCoreApplication 和 exec()。养成一开始就写上的习惯，后面加定时器不用返工。QCoreApplication 是「无界面版」的 Qt 应用对象，管事件循环和全局资源；做界面时换成 QApplication，后者继承自前者，多管了窗口系统的东西。

四、工程文件 .pro 的结构 #

.pro 是 qmake 的输入。qmake 读它，生成各平台的 Makefile。熟悉 gcc 的人对 Makefile 不陌生，不熟悉的话记住一句：Makefile 是给 make 的施工图，.pro 是给 qmake 的施工图。

用 Qt Creator 建工程时，这个文件自动生成，很多人从来没打开过。它是项目的内容描述，包含源文件、头文件、一般配置，以及应用相关的细节，比如要链接哪些额外的库、要加哪些额外的搜索路径。

一个控制台工程的完整 .pro

#-------------------------------------------------
# 项目文件：hello.pro
# qmake 读这个文件，生成 Makefile
#-------------------------------------------------

# 一个项目中使用的 Qt 模块列表
QT += core      # 使用 core 模块，所有其他 Qt 模块都依赖它
QT -= gui       # 不包含 gui 模块，gui 模块提供编写图形用户界面所需的接口

# TARGET 决定生成目标的名字，默认与工程文件名相同
# 不同平台生成的后缀不同：Windows 下是 *.exe，Unix 下没有后缀
TARGET = hello

# 指定项目的配置和编译选项
CONFIG += console      # 建立控制台程序所需的链接器标志
CONFIG -= app_bundle   # 不把可执行文件集成成一束（这是默认值）

# 模板变量，用来定义将建成的项目类型
TEMPLATE = app         # 说明 makefile 将构建一个应用程序

# 一个列表，列出应用程序的 C++ 源文件
# 多个文件用反斜杠 \ 换行
SOURCES += main.cpp

关键字段逐条过

字段 作用 常见取值 踩坑提示
QT 声明要链接的 Qt 模块 core、gui、widgets、network、xml、sql 加了 widgets 就不用再写 gui，它自带
QT -= gui 从模块列表里减掉 gui、widgets 控制台工程减掉 gui，能减小体积
TARGET 生成的可执行文件名 任意字符串 不写就取工程文件名
TEMPLATE 项目类型 app、lib、subdirs 写 subdirs 就是多工程聚合
CONFIG 编译与链接选项 console、debug、release、c++11 要 C++11 就写 CONFIG += c++11
SOURCES 源文件列表 main.cpp 等 少写一个文件，链接期报 undefined reference
HEADERS 头文件列表 mainwindow.h 等 带 Q_OBJECT 的头文件必须写进来，否则 moc 扫不到
FORMS .ui 文件列表 mainwindow.ui 写了 uic 才会生成 ui_xxx.h
RESOURCES .qrc 文件列表 res.qrc 图片、图标、qss 都从这里进
INCLUDEPATH 额外头文件搜索路径 $$PWD/include 用 $$PWD 表示 .pro 所在目录
LIBS 额外链接库 -L$$PWD/lib -lfoo 顺序有讲究，被依赖的放后面

几条实战经验

改完 .pro 必须重跑 qmake。Qt Creator 里是「构建 → 执行 qmake」，命令行是 qmake hello.pro 再 make。只点「运行」不会重新生成 Makefile，你会对着一个明明写对了的配置发呆。

SOURCES 里加了文件但 IDE 里没显示，右键工程选「执行 qmake」就回来了，这不是 bug，是 qmake 的缓存。跨平台路径一律用 /，qmake 会自己转换，写 \ 在 Windows 上碰巧能用，到 Linux 就废了。

五、main 函数做了什么 #

Qt 程序的 main 短得让人不安。五行代码，两个对象，一个 return。拆开看。

cpp
int main(int argc, char *argv[])
{
    QApplication a(argc, argv);   // ① 应用对象
    MainWindow w;                 // ② 窗口对象
    w.show();                     // ③ 显示
    return a.exec();              // ④ 进事件循环
}

① QApplication a(argc, argv);

这一个对象管三件事：全局资源（字体、调色板、剪贴板、光标）、事件分发、以及那个著名的事件循环。

argc, argv 要传给它，因为 Qt 自己要吃掉一些命令行参数，比如 -style、-platform、-reverse。你传进去，它处理完再把剩下的留给你。有且只能有一个 QApplication 对象，而且必须在任何界面部件创建之前构造，放在 main 的第一行最稳。

② MainWindow w;

窗口对象在栈上。这一点很多人不敢信，因为 Qt 的例子里到处是 new。栈上没问题，main 结束时 w 析构，窗口跟着销毁，干干净净。

用 new 也行，但要记住 new 出来的顶层窗口没人替你删，除非你给了父对象。

③ w.show();

show() 把窗口标记为「可见」，然后交给窗口系统去画。它不阻塞，下一行立刻执行。

刚 new 出来的窗口是隐藏的，不调用 show() 就什么都看不到。这是新手第一个「程序跑起来但没窗口」的原因。

④ return a.exec();

这是整个程序的心脏。

exec() 启动主事件循环，然后一直不返回，直到有人调用 exit() 或 quit()。循环里干的事是：从窗口系统取事件（鼠标、键盘、重绘、定时器到期），找到对应的接收对象，分发过去，处理完再取下一个。

return a.exec(); 把 exec() 的返回值当 main 的返回值。exec() 返回的就是传给 exit() 的那个值，默认 0。

没有 exec() 会怎样

界面一闪就退。

原因：main 一路执行到结尾，栈上的 w 析构，QApplication 析构，进程结束。窗口还没来得及画第二帧。你在 show() 后面 sleep(5) 也没用，事件循环没跑起来，窗口系统收不到重绘请求，屏幕上是一片空白或者一块没刷新的区域。

这就是那个核心结论：QApplication 管资源和事件循环，窗口是界面，exec() 让程序「活起来」。

三步对照表

行 干什么 少了会怎样
QApplication a(argc, argv); 建应用对象，初始化 Qt 全局环境，准备事件循环 后面所有界面部件都没法创建，崩在构造里
MainWindow w; w.show(); 建窗口并标记可见 程序在跑，屏幕上什么都没有
return a.exec(); 启动事件循环，进入「等事件、处理事件」的无限循环 界面一闪就退，程序立刻结束

六、GUI 编程的基本思路 #

图形用户界面（Graphical User Interface，GUI），指用图形方式显示的计算机操作用户界面。和早期计算机用的命令行界面比，图形界面对用户更友好。代价是算力：画像素、处理鼠标、维护几十个窗口的状态，比敲一行命令贵得多。

控制台程序和 GUI 程序的根本差别

控制台程序是「顺序执行」的：读输入、算、打印、退出。你写什么它做什么，做完就死。

GUI 程序是「事件驱动」的：程序启动后不做事，就等。等鼠标点、等键盘按、等定时器响、等网络回包。每来一个事件，找到该处理它的对象，调一个函数，处理完继续等。程序的生命周期等于事件循环的生命周期。理解这一点，你就理解了为什么 main 里要 exec()，为什么信号槽是核心机制，为什么不写 while(1) 也不会卡死。

GUI 程序的三段式

所有 Qt 界面程序都长这样：

text
① 建应用      QApplication a(argc, argv);
② 建界面      MainWindow w;  w.show();
③ 跑循环      return a.exec();

中间那些「按钮按下要干嘛」的逻辑，不写在 main 里，而是挂在信号槽上，等事件来了再执行。这是 Qt 和「写个 for 循环打印」最大的思维差异。

从向导到窗口：四步走

原文用截图演示了建 GUI 工程的过程，截图没了，用文字补全。第一步，新建项目，模板选「Qt Widgets Application」，向导问你基类选哪个，三选一：QMainWindow、QWidget、QDialog，默认给 QMainWindow，类名默认 MainWindow，可以改。第二步，向导自动生成四个文件：main.cpp、mainwindow.h、mainwindow.cpp、mainwindow.ui，外加一个 .pro。第三步，双击 mainwindow.ui 进 Designer，从控件箱拖一个 Push Button 到窗口上，双击改文字。第四步，编译运行，看到一个带按钮的窗口。

QMainWindow 默认自带的东西

向导建出来的主窗口默认有菜单栏、工具栏、状态栏。做小例子时它们占地方，很多人第一件事就是把它们删掉。删不删都行，不影响后面的内容。想要界面标题显示成别的，在 Designer 右下角的属性面板里改 windowTitle，比如改成 gui。

这一步就是原文说的「把 MainWindow 的 windowTitle 改成 gui，这样整个界面的名字就显示 gui 了」。

ui->setupUi(this) 干了什么

向导生成的构造函数里有一行：

cpp
ui->setupUi(this);

它把 .ui 文件里描述的控件全部创建出来，挂到 this（也就是这个 MainWindow 对象）上，设置好位置、大小、文字、信号槽连接。执行完这一行，ui->pushButton 才是一个真实存在的对象。

少这一行，后面所有 ui->xxx 全是空指针，运行时直接崩。

七、信号与槽：入门 #

信号和槽是 Qt 里最重要的概念。它解决的问题很朴素：两个对象之间怎么说话。

在 GUI 编程中，我们改了一个部件，经常要通知别的部件。更一般地，我们希望任意两类对象之间能互相通信。举原文那个例子：用户单击关闭按钮，我们希望窗口的 close() 函数被调用。按钮不知道窗口在哪，窗口也不知道按钮什么时候被按，硬编码写死就是一团乱麻。信号槽把这件事解耦了。

两句话记住它

  • 信号就是「事件发生时发出的通知」。 它属于某个对象，事件来了就发出去，发完不管谁来接。没人接也不报错。
  • 槽就是「被通知时执行的函数」。 它也是一个普通的成员函数，只是被登记成「可以接信号」。
  • connect 把两者接起来。 一根线，从发送者的某个信号，连到接收者的某个槽。

初学者只需要记住三个问题：谁发、发什么、谁来接。

拿门铃打比方。门铃是发送者，「有人按了」这个动作发出信号。屋里的人各有各的槽：有人去开门，有人喊一嗓子，有人装没听见。按门铃的人不需要知道屋里有几个人、谁去开。他按，线就通了。

代码里的样子

cpp
connect(发送者, SIGNAL(信号名(参数类型)), 接收者, SLOT(槽名(参数类型)));

四个参数，就是「谁发、发什么、谁来接、接什么」。

先看一个能跑的例子

界面上放一个水平滑动条 horizontalSlider 和一个进度条 progressBar。拖动滑条，进度条跟着变。这两个控件在 Designer 里拖出来就行，名字保持默认。

cpp
// mainwindow.h
#ifndef MAINWINDOW_H
#define MAINWINDOW_H

#include <QMainWindow>

namespace Ui {
class MainWindow;
}

class MainWindow : public QMainWindow
{
    Q_OBJECT    // 必须写，否则信号槽失效

public:
    explicit MainWindow(QWidget *parent = 0);
    ~MainWindow();

private:
    Ui::MainWindow *ui;
};

#endif // MAINWINDOW_H

cpp
// mainwindow.cpp
#include "mainwindow.h"
#include "ui_mainwindow.h"

MainWindow::MainWindow(QWidget *parent) :
    QMainWindow(parent),
    ui(new Ui::MainWindow)
{
    ui->setupUi(this);

    // connect 创建一个连接：
    // 发送者 ui->horizontalSlider 的 valueChanged(int) 信号
    // 接到接收者 ui->progressBar 的 setValue(int) 槽
    connect(ui->horizontalSlider, SIGNAL(valueChanged(int)),
            ui->progressBar,      SLOT(setValue(int)));

    // 拖动滑条时，progressBar 的 setValue 会被反复调用
    // 进度条长度就跟着变了
}

MainWindow::~MainWindow()
{
    delete ui;
}

cpp
// main.cpp
// 2014/7/27 Wayne HDU
// 问题描述：信号和槽的例子，用水平滑动条的移动控制进度条的长度

#include "mainwindow.h"
#include <QApplication>

int main(int argc, char *argv[])
{
    QApplication a(argc, argv);
    MainWindow w;
    w.show();
    return a.exec();
}

运行起来，界面上有两个进度条：一个接在滑条上，一个没接。拖滑条，前者跟着走，后者纹丝不动。这个对照是故意留的，就是为了让你看清「接了才有反应」。

为什么这两个能接上

因为 Qt 已经替你把线备好了。QSlider 有信号 valueChanged(int)，值一变就发；QProgressBar 有槽 setValue(int)，给个数就设进度。你只需要把同名同类型的两个端口连起来。

参数类型必须对得上。int 对 int 行，int 对 QString 不行。槽的参数可以比信号少（信号发三个，槽只接一个，多的丢掉），反过来不行。

两种建立连接的方式

第一种，写代码 connect。就是上面那种，最常用，也最好读。

第二种，在 Designer 里连。右键按钮，选「转到槽（Go to slot）」，弹出的对话框列出这个控件所有信号，选一个，Qt Creator 自动生成一个槽函数，命名规则是 on_对象名_信号名，然后你往函数体里填代码。原文说的「右键它，选择菜单 Go to slot」就是这条路径。

自动生成的槽有个隐藏机制：只要函数名符合 on_pushButton_clicked() 这个格式，setupUi 会自己帮你 connect，你连 connect 都不用写。方便，但也容易让人找不到连接在哪。工程大了之后，我建议老老实实写 connect，一眼能看见。

第三种是 Designer 底部的「信号/槽编辑器」，手填发送者、信号、接收者、槽四栏。做原型快，维护起来费劲。

断开连接

cpp
// disconnect 断开发送者信号与接收者方法之间的连接
// 连接被顺利移除返回 true，否则返回 false
disconnect(ui->horizontalSlider, SIGNAL(valueChanged(int)),
           ui->progressBar,      SLOT(setValue(int)));

什么时候用？临时让某个控件失去响应，或者防止重复连接。注意：重复 connect 会建立多条连接，同一个信号来一次，槽被执行多次。这是很隐蔽的 bug，排查时先数 connect 的个数。

还有一条要记住：任意一方对象被销毁时，连接自动移除。 所以父子对象树一崩，你不用手动清连接，Qt 会处理。

新式写法

Qt 5 起支持函数指针形式的 connect，推荐用：

cpp
// 新式：编译期检查信号和槽是否存在、参数是否匹配
connect(ui->horizontalSlider, &QSlider::valueChanged,
        ui->progressBar,      &QProgressBar::setValue);

老式 SIGNAL() / SLOT() 宏是字符串，编译期什么都查不出来，写错一个字母也能编过，运行时只在控制台打一行警告：

text
QObject::connect: No such slot MainWindow::setvalue(int)

新式写法把所有错误提前到编译期。源码里那种老式宏的写法，看懂就行，新代码用新式。

写自己的信号和槽

三条规矩：信号写在 signals: 下面，只声明不实现，实现由 moc 生成；槽写在 public slots: 或 private slots: 下面，正常写实现；发信号用 emit，它是个空宏，加不加都能编过，写上是给读代码的人看的。

cpp
class Counter : public QObject
{
    Q_OBJECT

public:
    void addOne() { ++m_value; emit valueChanged(m_value); }

signals:
    void valueChanged(int newValue);                 // 只声明，不实现

public slots:
    void onValueChanged(int v) { qDebug() << v; }    // 槽要写实现

private:
    int m_value = 0;
};

信号槽入门的三句话

谁发：ui->horizontalSlider。发什么：valueChanged(int)。谁来接：ui->progressBar 的 setValue(int)。把这三个名字填进 connect，功能就通了。剩下的一切，包括自定义信号、队列连接、跨线程，都是在这三句话上做加法。第二篇讲布局和控件时会反复用到这套机制。

八、窗口与控件的关系 #

QWidget 是所有界面对象的基类。按钮是 QWidget，标签是 QWidget，输入框是 QWidget，窗口本身也是 QWidget。区别只在于：有没有父对象。

  • 没有父对象的 QWidget 是顶层窗口。 它有自己的标题栏、边框，能独立出现在任务栏。
  • 有父对象的 QWidget 是子部件。 它画在父对象内部，坐标相对父对象左上角，没有自己的标题栏，父对象销毁时它一起销毁。

同一份代码，new QPushButton("OK") 是个独立小窗口，new QPushButton("OK", this) 是窗口里的一个按钮。区别只有第二个参数。

三个常用基类

基类 是什么 自带什么 什么时候选
QWidget 最裸的界面对象 什么都没有，一块可以画的矩形 要完全自定义外观，或者做容器
QMainWindow 主窗口 菜单栏、工具栏、状态栏、中央部件、停靠窗口 程序的主界面
QDialog 对话框 一个按钮区，默认支持模态 提示、设置、需要用户先回答再继续的场合

QMainWindow 的布局是固定的：中间只能有一个「中央部件」，四周留给菜单栏、工具栏、状态栏。所以你往主窗口里塞东西，要先指定谁是中央部件：

cpp
ui->setupUi(this);

// 把给定的组件设定成主窗口的中央部件
// 这里是把 plainTextEdit 设为中央部件，它会自动铺满中间区域
setCentralWidget(ui->plainTextEdit);

不设中央部件，你在主窗口上直接拖控件，运行起来看不见或者位置乱掉。这是 QMainWindow 和 QWidget 最容易被忽略的差别。

对话框与模态

对话框（Dialog）是一种特殊的视窗，用来向用户显示信息、通知用户某些事、或者请求用户输入，或者三者兼有。

严格地讲，只存在一种对话框，但有不同的显示方式：模态（Modal）和非模态（Modeless）。

类型 行为 用户能不能操作主窗口 适合什么
模态 强制要求回应，不回应就没法继续 不能 确认危险操作、必须填完才能往下走的表单
非模态 不强制回应，可以不理它继续干活 能 查找替换框、颜色设置、工具栏式面板

原文对这两类的描述值得抄下来：非模态对话框是非强制回应的，用于请求非必须的资料，用户可以不理它或者不给任何信息，继续当前工作，两个窗口都能打开、都处于活动状态或者获得焦点。典型的非模态是工具栏，比如文字颜色设置。查找/替换对话框也算，也可以设计成工具栏。

模态对话框强制要求用户回应，否则不能继续操作，直到与该对话框完成交互。它用于「需要一些额外信息才可以往下走」的场合，或者只想确认用户真要执行一个危险操作。原文还有一句实在话：模态对话框一般被视为不好的设计方案，因为它以一种用户不喜欢看到的方式出现，或者被习惯忽略弹窗的用户跳过，反而挡不住危险操作。

代码里怎么控制：

cpp
// Modal 属性决定 show() 弹出的 dialog 是模态还是非模态
// 默认是 false，show() 弹出的是非模态窗口
// 设为 true 等价于设置 QWidget::windowModality 为 Qt::ApplicationModal
dialog->setModal(false);   // true 为模态，false 为非模态

// show() 走的是 Modal 属性
dialog->show();

// exec() 无视 Modal 属性，一律按模态处理
// 而且是阻塞的，用户关掉对话框才返回
dialog->exec();

记两条就够：show() 看 setModal，exec() 一律模态且阻塞。想弹个不等人的窗口用 show()，想让用户必须先处理这个窗口用 exec()。

父子关系还管什么

除了「谁删谁」，父子关系还决定三件事。坐标：子部件的 (0,0) 是父部件的左上角，不是屏幕左上角，move(10, 10) 是往父窗口右下挪 10 像素。裁剪：子部件超出父部件区域的部分不显示，窗口缩到比按钮还小时，按钮被切掉一半，而不是画到窗口外面。布局：父部件装了布局管理器（QVBoxLayout 之类）后，子部件的位置和大小由布局算，你手动 move() 和 resize() 会被覆盖，布局是第二篇的主题，这里只要知道它会接管位置。

一个对象树的例子

cpp
QWidget *window = new QWidget;              // 顶层窗口
QPushButton *btn = new QPushButton("OK", window);   // btn 的父是 window
QLabel *lab = new QLabel("hi", window);     // lab 的父也是 window

delete window;    // window 析构时自动 delete btn 和 lab
                  // 不需要 delete btn，更不能删两次

这套机制解决了 C++ GUI 里最烦的内存管理问题。你只管 new，删的责任交给父对象。代价是：如果一个对象被 new 出来、又没给父对象、又不是栈对象，它就没人管了，泄漏。初学者查内存泄漏，先查这一条。

九、显示一个窗口 #

概念讲完，做个真东西。目标是：一个主窗口，中间一块文本编辑区，菜单里有个「新建窗口」的动作，点了弹出一个对话框。同时演示模态和非模态的差别。

原文这里配了建工程、加菜单栏、加工具条的截图，按流程复述一遍。

第一步：建 GUI 工程

做小例子时工具条和状态栏用不上，删掉也行。原文就是删掉之后做的，不影响逻辑。

从控件箱拖一个 Plain Text Edit 到窗口上。它不会自动变成中央部件，得在 mainwindow.cpp 的构造函数里手动写一行 setCentralWidget(ui->plainTextEdit);，原文就是这么干的。

从空项目起步：一个带 HTML 的标签

原文末尾还给了一个更小的例子：不用向导，从一个空项目（Empty Project）建一个应用程序，在一个标签上显示 HTML 格式的字符串。

先补一句 HTML 是什么。超文本标记语言（HyperText Markup Language，HTML），是为「网页创建和其他能在浏览器里看到的信息」设计的一种标记语言。它用来结构化信息，比如标题、段落、列表，也能描述文档的外观和语义。Qt 的很多控件支持一个 HTML 子集，所以你能用 <h2>、<font> 这些标签直接控制文字样式。

cpp

cpp

十、编译与运行 #

在 Qt Creator 里

在 Qt Creator 里按左下角的绿三角就行。它背后做的事和你手敲命令一样：跑 qmake 生成 Makefile，跑 moc 和 uic 生成辅助代码，调编译器，链接，然后启动程序。构建模式有 Debug 和 Release，Debug 带调试符号，能下断点，体积大、运行慢；Release 优化过，体积小。开发时用 Debug，给别人之前切 Release，这一步别忘。Qt Creator 默认开「影子构建（Shadow build）」，编译产物放在工程目录旁边的 build-xxx-Debug 文件夹里，不污染源码目录，别关掉。

在命令行里

text
qmake hello.pro      # 生成 Makefile
make                 # Linux / macOS / MinGW 环境下的 GNU make
mingw32-make         # Windows + MinGW，make 被改名了
nmake                # Windows + MSVC

编完在输出目录里找可执行文件。Windows 上是带 .exe 的那个。

构建套件（Kit）

Qt Creator 的「项目 → 构建设置」里能看到 Kit。一个 Kit 就是「编译器 + Qt 版本 + 调试器」的组合。常见的坑：机器上装了两个 Qt 版本（比如 MinGW 版和 MSVC 版），工程配到了 MinGW 的 Kit，但代码里用的库是 MSVC 编的，链接期报错。遇到莫名其妙的链接错误，先看 Kit 选对没有。

常见报错对照表

现象 原因 怎么办
undefined reference to 'MainWindow::xxx' 函数声明了没实现，或者实现所在的 .cpp 没进 SOURCES 检查实现，检查 .pro，重跑 qmake
QObject::connect: No such slot 槽名拼错，或者忘了 Q_OBJECT 用新式 connect，编译期就能抓住
改动信号槽后行为没变 moc 没重新生成 执行 qmake 再构建
cannot find -lXXX 链接库路径或库名不对 检查 LIBS，检查 Kit 的位数（32/64 要一致）
程序跑起来没有窗口 忘了 w.show()，或者中央部件没设 补 show()，补 setCentralWidget
中文在界面上是方块 字体缺中文，或者源文件编码乱 换字体，源文件存成 UTF-8
双击 exe 报缺 DLL 直接跑脱离了 Qt 的运行环境 用 windeployqt 拷依赖，或从 Qt Creator 里跑

最后一条值得多说一句。Qt Creator 里跑得好好的 exe，拷到别的机器上双击就报「找不到 Qt5Core.dll」。因为 Qt Creator 运行时会把 Qt 的 bin 目录加进 PATH。发布时用 Qt 自带的 windeployqt your.exe，它把需要的 DLL 全拷过来。

第二篇会讲什么

本篇的界面全是 Designer 拖出来的，位置靠手摆。窗口一缩放，按钮就跑偏。下一章解决这件事：布局管理器（Layout）。

布局的作用是管理窗口中的部件，按键、标签、编辑栏，让它们以合理的方式摆放。原文有一句话很实在：布局不是必须的，但没人喜欢杂乱无章的窗口界面。

同一篇里还有两个概念先记住：

Tab 键。指的是你键盘上那个 Tab。在很多窗口里按 Tab 可以在部件之间移动焦点，从一个按键跳到另一个按键，或者从一个窗口跳到另一个窗口。

伙伴编辑（Buddy）。把两个不同部件关联在一起，前提是二者可以关联。典型用法是把一个 label 和一个 line edit 设成伙伴，焦点移到 label 上时（按 Alt 加快捷键），焦点自动跳到 line edit 里。

这些在第二篇《布局与基础控件》里展开，那里会给出完整的可运行工程。

十二、易错点速查 #

编号 现象 原因 修法
1 程序一闪就退 main 里没调 exec() return a.exec();
2 编译通过，运行时窗口不出现 忘了 w.show() 补上
3 connect 没反应，只打一行警告 槽名拼错，或类里没写 Q_OBJECT 用新式 connect，补 Q_OBJECT
4 一个信号触发槽很多次 同一个连接 connect 了多次 数一遍 connect，或 disconnect 多余的那根
5 主窗口上控件看不见 没设中央部件 setCentralWidget(...)
6 主窗口控件位置乱飞 没装布局管理器，或装了又被手动 move 覆盖 交给布局，别手摆
7 改了 .pro 不生效 没重跑 qmake 执行 qmake 再构建
8 ui->xxx 空指针崩溃 构造函数里没调 ui->setupUi(this) 补这一行，且要在使用控件之前
9 编译报 undefined reference .cpp 没进 SOURCES，或 Kit 选错 检查 .pro 和构建套件
10 对话框弹出后主窗口还能点 用了 show() 且 setModal(false) 要模态就 setModal(true) 或 exec()
11 对话框关掉程序就崩 用了 exec()，之后又 delete dialog，或重复删 用 Qt::WA_DeleteOnClose，或者只 new 一次重复 show()
12 拷贝 exe 到别的机器跑不起来 缺 Qt 的 DLL windeployqt
13 中文显示成方块或乱码 源文件编码／字体不对 源码存 UTF-8，选带中文的字体
14 手动 delete 子对象后崩溃 父对象析构时又删了一次 交给父子关系，别手删有父对象的部件
15 路径带中文导致 moc 失败 qmake 对中文路径的编码处理不稳 工程放到纯英文路径下

十五条里，第 1、3、8 条出现的次数最多。三条都指向同一个地方：三个必须做的动作漏了一个。QApplication、setupUi、exec()，缺一个程序就不正常。
