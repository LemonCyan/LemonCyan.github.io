这是一套 9 篇的 Qt5 入门教程，本篇是第八篇。它只讲「自己动手画东西」这一件事：QPainter 的画笔细节、三种渐变填充、属性动画，最后附上给控件加提示的做法。模型视图不讲，网络不讲，定时器只在本篇第八章里作为动画的一种驱动方式出现。

全系列顺序：Qt 入门与信号槽 → 布局与基础控件 → 容器与遍历 → Qt 的算法函数 → 模型视图与 QVariant → 定时器与网络 → 文本流与 XML → 绘图与动画 → 工程实践。九篇平铺在同一个目录下，按顺序读最省力。本篇默认你已经会写 paintEvent，会 connect 信号槽——这两样在第六篇《定时器与网络》里讲过。

读法建议：一、二章是画笔，三到六章是渐变，七到九章是动画，十、十一章是 ToolTip。ToolTip 和绘图没有血缘关系，它讲的是「鼠标悬停时给一句话」，只是当年被收进了同一个目录。你完全可以先跳过去，回头再看。

一、QPainter 的绘制流程 #

Qt 里所有自绘的控件，入口只有一个：重写 paintEvent。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);   // 绑定到 this，之后所有绘制都落在窗口上
    // 画点什么
}

先说一个新手天天踩的坑：能不能在构造函数里画？

不能。构造函数执行的时候窗口还没显示出来，QPainter painter(this) 拿不到绘图设备，Qt 会在控制台甩一行 QPainter::begin: Paint device returned engine == 0，然后拒绝干活。就算侥幸画上了，窗口一遮一露内容也全没了——系统不替你保存窗口画面，它只在你该重画的时候来问你。paintEvent 就是那个「问你」的时刻。

所以自绘的固定套路是：数据存在成员变量里，画面在 paintEvent 里按数据重新生成。 数据变了，调 update() 请求重画，别的什么都不用管。这一点和第七章的属性动画、第八章的定时器驱动是同一套逻辑。

三个对象的关系

初学者最容易混的是 QPainter、QPen、QBrush 三者的分工。

对象 管什么 怎么设
QPainter 执笔的手。负责「画」，不管长什么样 QPainter painter(this);
QPen 画笔。管轮廓线的颜色、粗细、虚实、端点和拐角 painter.setPen(pen);
QBrush 画刷。管内部填充的颜色或图案 painter.setBrush(brush);

一句话记法：pen 画边，brush 填心。你要画一条线，只有笔起作用；你要画一个实心矩形，笔和刷都起作用；你要是把 brush 设成 Qt::NoBrush，那矩形就只剩一个空心框。

绘制流程的五步

任何一次绘制都可以拆成这五步，顺序别乱。

text
1. 造 QPainter，绑定绘图设备
2. 设 QPen（描边外观）
3. 设 QBrush（填充外观）
4. 调 drawXxx 系列函数（真正落笔）
5. QPainter 析构，自动 end()

第 5 步不用你手写。QPainter 是个栈对象，函数返回时析构函数会调 end()，把绘图设备交还出去。这也是为什么 QPainter painter(this); 千万别写成 new QPainter(this)——手工 new 出来的对象没人给你 end，设备一直占着，后面的绘制全失败。

一个完整的例子

画一个带描边的圆角矩形，把所有环节串一遍。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);

    // 抗锯齿：不加的话斜线和圆角会有一圈台阶
    painter.setRenderHint(QPainter::Antialiasing, true);

    QPen pen(Qt::darkBlue);       // 描边颜色
    pen.setWidth(4);              // 线宽 4 像素
    pen.setStyle(Qt::SolidLine);  // 实线
    painter.setPen(pen);

    QBrush brush(Qt::yellow);     // 填充颜色
    brush.setStyle(Qt::SolidPattern);
    painter.setBrush(brush);

    QRect rect(60, 60, 240, 120);
    painter.drawRoundedRect(rect, 16, 16);   // 圆角半径 16
}

Antialiasing 是 QPainter::RenderHint 里的一个枚举值，含义是「边缘做混色补偿」。粗线、斜线、圆角、弧线都该开。开了以后 CPU 会多干一点活，但省下来的是你的眼睛。

drawXxx 家族

QPainter 的落笔函数按「有没有 pen / brush」分三类，记清楚能省不少调试时间。

函数 用 pen 用 brush 说明
drawLine 是 否 画线段，只需要笔
drawRect / drawRoundedRect 是 否 只画边框，空心的
drawEllipse / drawArc 是 否 只画轮廓
drawPolygon / drawPath 是 填充 有闭合区域时会用 brush 填内部
fillRect 否 是 纯填充，不画边
drawText 是 否 用笔的颜色画字
drawPixmap 否 否 直接贴图，两者都不看

注意 drawRect 和 fillRect 是两回事。想画实心矩形写了 drawRect 却发现是空心的，是因为 brush 还是默认的 NoBrush。drawRect 在有 brush 时也填内部，fillRect 则完全不描边。

坐标与变换

paintEvent 里的坐标原点是控件左上角，x 向右，y 向下。这一点和数学课上的直角坐标系相反，画图表的时候记得翻一下。

坐标系可以被改。translate、rotate、scale、shear 四个函数改的是「笔下的世界」，不是「画出来的图形」。改完之后你画的矩形会自动落在新坐标里。

cpp
QPainter painter(this);
painter.setPen(QPen(Qt::black, 3));

QRect rect(0, 0, 80, 80);
painter.drawRect(rect);          // 原点第一次用

painter.translate(120, 40);      // 坐标系整体右移 120、下移 40
painter.rotate(30);              // 顺时针转 30 度（单位是度，不是弧度）
painter.drawRect(rect);

变换会累加。上面 translate 之后再 rotate，旋转是绕着新的原点转的。想让一个图形绕自己的中心转，得先用 translate 把原点挪到图形中心，再 rotate，再画以中心为原点的图形。

画完一块、想回到干净状态，别手动反向 translate 回来，用配对的 save() 和 restore()。

cpp
painter.save();                  // 压栈：记住当前所有状态
painter.translate(200, 100);
painter.rotate(45);
painter.drawText(0, 0, "斜着写");
painter.restore();               // 出栈：坐标系、pen、brush 全部还原

栈里存的不只是坐标变换，pen、brush、字体、裁剪区都会一起存。这个特性在写复杂 paintEvent 的时候极其救命。

二、画笔的细节：端点与连接 #

上一章说 pen 管轮廓线。线宽是 1 的时候它没什么细节，线宽一上去，两个参数立刻决定观感：capStyle 和 joinStyle。

素材里那个例子，核心就一行 linePen.setWidth(15)。线宽 15 的线，端点收成什么形状，肉眼一眼就看出来了。原稿的代码被平台粘得七零八落，这里重写一遍能编译的版本。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    QPen linePen(Qt::red);        // 新建画笔并设颜色
    linePen.setWidth(15);         // 线宽 15，端点形状才看得出来

    QPoint startPoint(30, 30);
    QPoint endPoint(300, 30);

    // 第一条：平头
    linePen.setCapStyle(Qt::FlatCap);
    painter.setPen(linePen);
    painter.drawLine(startPoint, endPoint);

    // 第二条：方头，起点下移 20
    startPoint.setY(50);
    endPoint.setY(50);
    linePen.setCapStyle(Qt::SquareCap);
    painter.setPen(linePen);
    painter.drawLine(startPoint, endPoint);

    // 第三条：圆头
    startPoint.setY(70);
    endPoint.setY(70);
    linePen.setCapStyle(Qt::RoundCap);
    painter.setPen(linePen);
    painter.drawLine(startPoint, endPoint);
}

素材里那版有三处要修：painter.setPen(linePen) 只调了一次，后两条线用的是旧画笔；endPoint 的 y 坐标从来没改过，第二条线画成了斜的；Qpen 大小写错，应该是 QPen。这三处都是抄教程时最容易连带抄错的类型。

cap 是线段两端怎么收尾

Qt::PenCapStyle 一共三个值。它管的是一条线段的两个端点长什么样，跟拐角无关。

枚举值 中文 端点形状 对线段总长的影响
Qt::FlatCap 平头 端点处直接切断，和线垂直 不多占长度
Qt::SquareCap 方头 切断后再向外延伸半个线宽，方角 两端各多出半个线宽
Qt::RoundCap 圆头 以端点为圆心补一个半径半线宽的半圆 两端各多出半个线宽

默认值是 Qt::SquareCap。这个默认值坑过不少人：画一条 drawLine(0, 0, 100, 0) 配 width=15，你以为是 100 像素长，实际占了 115 像素，两端各多出 7.5。要精确对齐用 FlatCap。

FlatCap 和 SquareCap 的区别只在「多不多那半个线宽」，两者的角都是方的。RoundCap 才是圆。三种放在一起，线宽 15 时差别非常明显：平头是两个直切口，方头是两个外凸的方角，圆头是两个半圆。

join 是拐角怎么接

Qt::PenJoinStyle 管的是一条折线自己拐弯的地方。它和 cap 完全是两码事——cap 看两端，join 看中间。

枚举值 中文 拐角外侧的形状 适用场景
Qt::MiterJoin 尖角 两条边延长相交，成一个尖 矩形、折线图、需要硬朗线条的地方
Qt::BevelJoin 斜角 外侧直接切一刀，成一个斜平面 粗线不要尖刺时
Qt::RoundJoin 圆角 外侧补一段圆弧 手绘感、路径动画
Qt::SvgMiterJoin SVG 尖角 按 SVG 规范的 miter 规则 与 SVG 渲染对齐时用

默认是 Qt::BevelJoin。注意这个默认值和 cap 的默认值不是一回事，别记串。

MiterJoin 有个副作用：夹角很小的时候，两条边的延长线会跑到很远的地方相交，尖刺会戳出画面。Qt 用 setMiterLimit() 拦这个，默认阈值是 2（单位是线宽的倍数），超过就自动退化成 BevelJoin。想保留长尖刺就把这个值调大。

把两个参数一起看

写一段代码，一遍看完 cap 和 join 的所有组合。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    QPen pen(Qt::darkGreen);
    pen.setWidth(20);
    pen.setJoinStyle(Qt::MiterJoin);
    painter.setPen(pen);

    // 一个 100x100 的直角折线，看 join 的效果
    QPainterPath path;
    path.moveTo(60, 60);
    path.lineTo(200, 60);
    path.lineTo(200, 200);
    painter.drawPath(path);

    // 换个 join 再来一次
    pen.setJoinStyle(Qt::RoundJoin);
    pen.setColor(Qt::darkRed);
    painter.setPen(pen);
    painter.translate(220, 0);
    painter.drawPath(path);
}

QPainterPath 用来拼多条线段。moveTo 抬笔移到起点，lineTo 落笔画到下一个点。整条路径最终一次性交给 drawPath，拐角处就按 joinStyle 处理。你要是改成两次独立的 drawLine，那就成了两个互不相干的线段，join 根本不会生效——因为它们没有「拐角」。

四个容易忽略的点

第一，闭合路径上的 cap 无效。drawRect、drawEllipse、closeSubpath() 之后的路径，首尾已经接上了，没有「端点」，cap 自然无从谈起。

第二，cap 会改变图形的包围盒。上一章讲过 Antialiasing，这里补一句：SquareCap 和 RoundCap 让线段实际占用面积变大，如果按坐标算好了对齐，用它们就会错位半个线宽。

第三，虚线也会受 cap 影响。setStyle(Qt::DashLine) 之后每一个短划的两端都按 cap 收尾。RoundCap + 虚线，看起来像一串小香肠。

第四，线宽为 0 有特殊含义。setWidth(0) 表示「美容线」（cosmetic pen），永远画 1 像素宽，不管坐标系怎么缩放。画缩放任意的辅助网格线就用它，写成 QPen(Qt::gray, 0)；正常描边别用 0。

三、渐变填充 #

渐变这个词被营销文案用坏了，说清楚它本来的意思就行：**同一个图形里，颜色从这一头到那一头连续变化。**不去说它「充满变幻无穷的神秘浪漫气息」，那是广告词，不是技术描述。

真正要记住的是下面这句，本篇最要紧的一句：

渐变是 QBrush 的一种，不是独立的绘制方式。

新手最大的误解是以为 QPainter 有个 drawGradient 之类的东西。没有。QPainter 从头到尾只认 pen 和 brush。渐变做的事情，是先造一个会变色的画刷，然后拿这个画刷当普通 QBrush 用。落笔还是 drawRect、drawEllipse、drawPath 那些老函数，一个都没换。

标准三步

cpp
// 第一步：造渐变对象，指定它的几何范围
QLinearGradient grad1(25, 100, 150, 170);

// 第二步：往渐变上挂颜色停靠点，位置范围 0 ~ 1
grad1.setColorAt(0.0, Qt::white);
grad1.setColorAt(0.5, Qt::yellow);
grad1.setColorAt(1.0, Qt::black);

// 第三步：包成 QBrush，交给 setBrush，然后照常画
QBrush brush(grad1);
painter.setBrush(brush);
painter.drawRect(QRect(10, 10, 200, 200));

三步的顺序不能反。你不能先把 brush 设上去再往渐变里加颜色——QBrush 构造的时候是拷贝了渐变的当前状态，后面再改 grad1 不会自动同步到已经建好的 brush 上。改了渐变想生效，重新 setBrush 一次。

方便的重载

只填充不描边的时候，fillRect 有个直接吃 QGradient 的重载，能省掉手写 QBrush：

cpp
QRect rec1(10, 10, 200, 200);
QLinearGradient grad1(25, 100, 150, 170);
grad1.setColorAt(0.0, Qt::white);
grad1.setColorAt(1.0, Qt::black);

painter.fillRect(rec1, grad1);   // QGradient 直接当 QBrush 用

这个重载之所以能成立，正是因为 QGradient 可以隐式转换成 QBrush。这条转换路径本身就说明了它的身份——它就是画刷的一个来源。

素材原稿里三种渐变的代码被评论区文字和站外链接切断得只剩半截，第二、第三种连对象构造都被吃掉了。这里补全。

三种渐变对照

类 中文名 构造参数 颜色往哪个方向变 典型用途
QLinearGradient 线性渐变 起点 x,y、终点 x,y 沿两点连线方向均匀过渡 背景条、按钮、标题栏
QRadialGradient 径向渐变 圆心 x,y、半径；可选焦点 从圆心向外一圈圈扩散 球体、光晕、高光点
QConicalGradient 锥形渐变 中心 x,y、起始角度 绕中心一圈，角度方向变化 色轮、雷达图、进度环

三者都是 QGradient 的子类，都有 setColorAt，都能塞进 QBrush。区别只在「颜色沿哪个方向走」。

颜色停靠点怎么工作

setColorAt(pos, color) 里的 pos 是 qreal，范围 0 到 1，代表「沿渐变方向的进度」，不是像素。

cpp
QLinearGradient g(0, 0, 300, 0);   // 横向 300 像素
g.setColorAt(0.0, Qt::red);        // 左端
g.setColorAt(0.3, Qt::green);      // 30% 处
g.setColorAt(1.0, Qt::blue);       // 右端

0.3 落在 x=90 的位置。停靠点之间自动线性插值，不需要你手动补中间色。

两条边界规则：比第一个停靠点还靠前的区域，全用第一个停靠点的颜色；比最后一个停靠点还靠后的区域，全用最后一个停靠点的颜色。所以你要是只设了 0.2 和 0.8 两个点，两端会变成纯色块——很多人以为是渐变失效了，其实是这条规则在起作用。

setColorAt 可以反复调用，同一个位置设两次会覆盖。想清空所有停靠点用 setStops，一次传一个 QGradientStops 列表。

四、线性渐变与径向渐变 #

线性渐变

构造函数的四个数字就是起点和终点坐标：QLinearGradient(x1, y1, x2, y2)。颜色沿这条向量线性变化，垂直于这条向量的线上面颜色相同。

cpp
QLinearGradient grad(25, 100, 150, 170);

这个例子的起点是 (25, 100)，终点是 (150, 170)，方向是右下方，所以颜色从左上一路变到右下。素材原稿用的就是这组数字。

也可以先默认构造，再调 setStart 和 setFinalStop：

cpp
QLinearGradient grad;
grad.setStart(0, 0);
grad.setFinalStop(0, 200);       // 竖直方向的渐变

三个矩形看方向差异，代码可以直接跑。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);

    // 横：左浅右深
    QLinearGradient g1(20, 20, 220, 20);
    g1.setColorAt(0.0, Qt::white);
    g1.setColorAt(1.0, Qt::darkCyan);
    painter.fillRect(QRect(20, 20, 200, 80), g1);

    // 竖：上浅下深
    QLinearGradient g2(20, 120, 20, 200);
    g2.setColorAt(0.0, Qt::white);
    g2.setColorAt(1.0, Qt::darkMagenta);
    painter.fillRect(QRect(20, 120, 200, 80), g2);

    // 斜：左上到右下
    QLinearGradient g3(20, 220, 220, 300);
    g3.setColorAt(0.0, Qt::white);
    g3.setColorAt(1.0, Qt::darkGreen);
    painter.fillRect(QRect(20, 220, 200, 80), g3);
}

注意 QLinearGradient 的起点终点和你要填的矩形没有任何绑定关系。矩形的范围是 fillRect 说了算，渐变的范围是构造参数说了算。两者不一致时，矩形内部取的是「把渐变按这个方向无限延伸后」的值。想严格对齐，让渐变的起终点正好落在矩形的两个角上。

径向渐变

QRadialGradient(cx, cy, radius) 三个参数：圆心和半径。颜色从圆心开始，沿半径方向向外变。

cpp
QRadialGradient grad(100, 100, 80);
grad.setColorAt(0.0, Qt::white);
grad.setColorAt(0.6, Qt::yellow);
grad.setColorAt(1.0, Qt::darkYellow);
painter.fillRect(QRect(20, 20, 160, 160), grad);

还有第四个参数，焦点 focalPoint：

cpp
QRadialGradient grad(100, 100, 80, 60, 60);

圆心还在 (100, 100)，但最亮的那个点跑到了 (60, 60)。这在画球体高光的时候特别好用——真实世界的球，最亮的点不在几何圆心，而在偏向光源的那一侧。默认焦点等于圆心，渐变就是一环环的同心圆；焦点偏离圆心，环会变成偏心的一族椭圆。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    // 同心：焦点默认在圆心
    QRadialGradient g1(100, 100, 70);
    g1.setColorAt(0.0, Qt::white);
    g1.setColorAt(1.0, Qt::black);
    painter.setBrush(QBrush(g1));
    painter.setPen(Qt::NoPen);
    painter.drawEllipse(QPoint(100, 100), 70, 70);

    // 偏心：焦点挪到左上方，像被左上角的灯光照到
    QRadialGradient g2(280, 100, 70, 250, 70);
    g2.setColorAt(0.0, Qt::white);
    g2.setColorAt(1.0, Qt::black);
    painter.setBrush(QBrush(g2));
    painter.drawEllipse(QPoint(280, 100), 70, 70);
}

扩散方式

三种渐变都有 setSpread，管的是「超出渐变定义范围的地方怎么着色」。这一点素材里没提，但画大面积背景一定会遇到。

枚举值 效果
QGradient::PadSpread 超出范围就用边缘颜色填满。默认值
QGradient::RepeatSpread 超出范围就重复整个渐变
QGradient::ReflectSpread 超出范围就镜像翻转后重复，像照镜子 
cpp
QRadialGradient g(150, 150, 40);
g.setColorAt(0.0, Qt::white);
g.setColorAt(1.0, Qt::blue);
g.setSpread(QGradient::ReflectSpread);   // 超出半径 40 的地方开始镜像
painter.fillRect(QRect(0, 0, 300, 300), g);

PadSpread 在矩形比渐变范围大的时候会让你觉得「渐变只占了中间一小块，外面全是纯色」。这不是 bug，是默认扩散方式。想铺满整个矩形，要么把渐变的半径调大到覆盖矩形，要么换成 RepeatSpread。

五、锥形渐变 #

前两种渐变是「沿一条线」或「沿一个半径」变。锥形渐变换了个方向，它是绕着一个中心点，按角度扫过去。想象一支圆规钉在纸上，笔尖绕一圈，颜色就在这一圈里从 A 变到 B。

构造函数是 QConicalGradient(cx, cy, angle)。前两个是中心坐标，第三个是起始角度，单位是度。

角度的约定只有一条：**0 度在三点钟方向，正角度逆时针走。**这和数学课上的极坐标一致，也和屏幕坐标 y 轴向下的直觉相反，所以画的时候要拧一下。

cpp
QConicalGradient grad(150, 150, 0);   // 中心 (150,150)，从三点钟方向起扫
grad.setColorAt(0.0, Qt::white);
grad.setColorAt(0.2, Qt::green);
grad.setColorAt(1.0, Qt::black);
painter.fillRect(QRect(50, 50, 200, 200), grad);

素材里的第三种渐变就是这个，原稿连构造语句都被抓取垃圾截掉了，只剩三行注释掉的 setColorAt。补全之后就是上面这段。

代码：一整个色轮

锥形渐变最标准的用途就是色轮。色相 0 到 360 度绕一圈，正好对应锥形渐变的 0 到 1。

cpp
void Dialog::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    QConicalGradient wheel(160, 160, 90);   // 从十二点钟方向起
    // 六个色相点，位置均匀分布
    wheel.setColorAt(0.0,  Qt::red);
    wheel.setColorAt(0.17, Qt::yellow);
    wheel.setColorAt(0.33, Qt::green);
    wheel.setColorAt(0.5,  Qt::cyan);
    wheel.setColorAt(0.67, Qt::blue);
    wheel.setColorAt(0.83, Qt::magenta);
    wheel.setColorAt(1.0,  Qt::red);        // 回到红，首尾必须接上

    painter.setPen(Qt::NoPen);
    painter.setBrush(QBrush(wheel));
    painter.drawEllipse(QPoint(160, 160), 120, 120);
}

0.0 和 1.0 都写 Qt::red，这不是多余。锥形渐变从起点扫满一圈回到起点，如果首尾颜色不同，接缝处会有一道硬边。这道边在色轮上非常显眼，是锥形渐变的头号 bug。

锥形渐变的三个特性

特性 说明
中心之外的区域 按 spread 方式着色，默认是最后一圈的颜色一直铺出去
只受角度影响 半径不参与计算，同一个角度上的所有点到中心的颜色都一样
起始角度可调 第三个参数改的是「从哪里开始数 0」，走向永远是逆时针

第二条要单独强调。锥形渐变的颜色只跟当前位置相对中心的极角有关，跟距离无关。所以它填出来的形状是一圈一圈的扇面，不是同心环。填一个正方形，你会看到四个角是同一圈颜色——这跟径向渐变的观感完全不同。

想让颜色朝某个方向聚拢，不用改 setColorAt 的顺序，把停靠点对称着放就行：0.0 和 1.0 都写 Qt::yellow，中间 0.5 写 Qt::darkYellow，亮黄就只集中在扫过的那个方向上。画雷达扫描线、进度环的拖尾，用它比手动算弧加透明度省事。

六、渐变与图形的配合 #

到这一步，三种渐变都造得出来了。剩下的问题是：怎么让它跟真实图形的几何配合起来，而不是各画各的。

当画笔用

渐变不只能填内部，还能描边。QPen 有一个吃 QBrush 的构造函数：

cpp
QLinearGradient g(0, 0, 200, 0);
g.setColorAt(0.0, Qt::darkRed);
g.setColorAt(1.0, Qt::darkBlue);

QPen pen(QBrush(g), 8);        // 线宽 8，颜色由渐变决定
painter.setPen(pen);
painter.setBrush(Qt::NoBrush); // 内部不填
painter.drawRoundedRect(QRect(20, 20, 200, 100), 12, 12);

线的每一段颜色由它所在位置的渐变值决定，所以一条水平线会从深红渐变到深蓝。这个效果拿来画标题分隔条很好用，一行代码就有质感。

当文字颜色用

drawText 用的是 pen 的颜色。想让文字本身带上渐变，把 pen 换成渐变笔：

cpp
QLinearGradient g(20, 0, 300, 0);
g.setColorAt(0.0, Qt::darkCyan);
g.setColorAt(1.0, Qt::darkMagenta);

QPen textPen(QBrush(g), 0);    // 线宽 0，字体轮廓不需要粗细
painter.setPen(textPen);

QFont font = painter.font();
font.setPointSize(36);
font.setBold(true);
painter.setFont(font);
painter.drawText(QRect(20, 40, 320, 80), Qt::AlignCenter, "Gradient");

注意 drawText 不吃 brush，无论你把 brush 设成什么都不影响文字内部。文字的填充色永远来自 pen。这是 drawText 和 drawPath 的一个实质区别。

当路径填充用

drawPath 用 brush 填内部，用 pen 画轮廓。所以渐变路径的写法就是老三步，一个都不变。

cpp
QPainterPath path;
path.moveTo(60, 200);
path.cubicTo(160, 100, 260, 300, 360, 200);
path.lineTo(360, 260);
path.lineTo(60, 260);
path.closeSubpath();

QLinearGradient g(60, 180, 60, 260);
g.setColorAt(0.0, Qt::cyan);
g.setColorAt(1.0, Qt::darkBlue);

painter.setPen(QPen(Qt::darkBlue, 2));
painter.setBrush(QBrush(g));
painter.drawPath(path);

里面那对 pen + brush 就是第一章讲的五个步骤，只是 brush 换成了渐变。到这儿「渐变是 QBrush 的一种」这句话应该已经变成条件反射了。

坐标模式

这一节是配合问题的关键，也是最容易被忽略的一处。

渐变对象的坐标默认是逻辑坐标——就是你在 paintEvent 里写的那套坐标。控件放大缩小时，渐变不会跟着缩放，你会看到渐变范围还停在原来那圈像素上，而图形已经变大了。

解决办法是 setCoordinateMode：

枚举值 含义
QGradient::LogicalMode 默认。渐变坐标就是绘制时用的逻辑坐标
QGradient::ObjectMode 渐变坐标相对于当前 setBrush 后那个图形的局部坐标，图形动渐变跟着动
QGradient::ObjectBoundingMode 坐标用 0~1 的比例表示，相对于图形包围盒，图形缩放渐变一起缩放

ObjectBoundingMode 最省心，特别适合「同一个写法的渐变套用到不同尺寸的控件」这种场景：

cpp
QLinearGradient g(0, 0, 0, 1);       // 用 0~1 表示：从上到下
g.setCoordinateMode(QGradient::ObjectBoundingMode);
g.setColorAt(0.0, Qt::white);
g.setColorAt(1.0, Qt::lightGray);

// 同一支渐变，两个不同尺寸的矩形都能铺满
painter.fillRect(QRect(20, 20, 200, 60), g);
painter.fillRect(QRect(20, 100, 200, 200), g);

如果还留在默认的 LogicalMode，第二个高 200 的矩形就只会被上面 60 像素那一段渐变覆盖，剩下全是最末一个停靠点的纯色。

一个完整的配合例子

拼一个渐变的胶囊按钮，把填充和描边一起走一遍。

cpp
QRect rect(40, 40, 220, 56);

// 背景：竖直渐变，按包围盒比例算，换尺寸自动适应
QLinearGradient bg(0, 0, 0, 1);
bg.setCoordinateMode(QGradient::ObjectBoundingMode);
bg.setColorAt(0.0, QColor(90, 140, 220));
bg.setColorAt(1.0, QColor(50, 90, 170));
painter.setPen(Qt::NoPen);
painter.setBrush(QBrush(bg));
painter.drawRoundedRect(rect, 28, 28);

// 描边：斜向渐变，按逻辑坐标精确对齐
QLinearGradient border(rect.topLeft(), rect.bottomRight());
border.setColorAt(0.0, QColor(200, 220, 255));
border.setColorAt(1.0, QColor(30, 60, 120));
painter.setPen(QPen(QBrush(border), 2));
painter.setBrush(Qt::NoBrush);
painter.drawRoundedRect(rect, 28, 28);

两块内容用了两种坐标模式：背景跟着包围盒走，描边钉死在绘制坐标上。缩放测试时差别一目了然。

七、属性动画 QPropertyAnimation #

前面六章都是「画一帧」。从这一章开始让它动起来。

Qt 给动画准备了一整套框架，最常用的类是 QPropertyAnimation。它的工作方式一句话能说完：在一段时间内，把一个对象的某个属性从 A 平滑推到 B，中间自动插值。

但这句话里藏着一个致命的限定条件，必须先讲清楚：

QPropertyAnimation 只能动声明为 Q_PROPERTY 的属性，动不了普通成员变量。

为什么必须是 Q_PROPERTY

QPropertyAnimation 的构造函数长这样：

cpp
QPropertyAnimation(QObject *target, const QByteArray &propertyName, QObject *parent = 0);

第二个参数是属性名，一个字符串。运行时它拿这个名字去 target 的元对象里查，查到就调那个属性的 WRITE 函数写入新值，查不到就打印一行警告然后什么也不做。

普通成员变量不在元对象里。moc 只认 Q_PROPERTY 宏里声明过的东西。你写 qreal m_value;，moc 看不见它；你写 Q_PROPERTY(qreal value READ value WRITE setValue)，moc 才会在生成的 moc_xxx.cpp 里给 value 登记一条记录。这是元对象系统和普通 C++ 成员之间的根本分界。

这也是它和手写定时器的最大差别：定时器方案里，你是自己 m_value += step; update();，改什么变量、改多少、什么时候改，全由代码决定，编译器全程知情。属性动画里，改动是由框架按名字派发的，字符串写错一个字母，编译期毫无反应，运行时只给你一句 QPropertyAnimation: you're trying to animate a non-existing property。

动手写一个可动画的属性

拿一个自绘的圆角矩形当例子，让它的圆角半径动起来。

cpp
// roundbox.h
#ifndef ROUNDBOX_H
#define ROUNDBOX_H

#include <QWidget>

class RoundBox : public QWidget
{
    Q_OBJECT
    // 关键：把这个属性登记进元对象系统
    Q_PROPERTY(qreal radius READ radius WRITE setRadius)

public:
    explicit RoundBox(QWidget *parent = 0);

    qreal radius() const { return m_radius; }
    void setRadius(qreal r);

protected:
    void paintEvent(QPaintEvent *e);

private:
    qreal m_radius;
};

#endif // ROUNDBOX_H

Q_PROPERTY(qreal radius READ radius WRITE setRadius) 这一行的三段各管一件事：READ 指定读取函数，WRITE 指定写入函数，属性名 radius 就是动画里要传的字符串。READ 和 WRITE 都是可选的，但动画需要 WRITE，没有它就只能读不能改。

实现部分，setRadius 里改值并请求重画。

cpp
#include "roundbox.h"
#include <QPainter>
#include <QPropertyAnimation>

RoundBox::RoundBox(QWidget *parent) : QWidget(parent), m_radius(0)
{
}

void RoundBox::setRadius(qreal r)
{
    m_radius = r;
    update();                    // 值变了就请求重画，这一步不能省
}

void RoundBox::paintEvent(QPaintEvent *e)
{
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);
    painter.setPen(Qt::NoPen);
    painter.setBrush(QColor(70, 130, 200));
    painter.drawRoundedRect(rect().adjusted(4, 4, -4, -4), m_radius, m_radius);
}

update() 是画面刷新的开关。属性动画只负责改值，改完值之后画面会不会变，取决于你的 setRadius 里有没有 update()。忘了写，程序跑得很欢，界面一动不动——这是新手最容易卡住的地方。

启动动画

cpp
QPropertyAnimation *anim = new QPropertyAnimation(box, "radius");
anim->setDuration(1200);                     // 1200 毫秒跑完
anim->setStartValue(0.0);
anim->setEndValue(60.0);
anim->setEasingCurve(QEasingCurve::OutBounce);  // 缓动，第九章讲
anim->start(QAbstractAnimation::DeleteWhenStopped);

三件事：目标对象、属性名、起止值。setDuration 的单位是毫秒，1200 就是 1.2 秒。

start() 的参数建议固定写 QAbstractAnimation::DeleteWhenStopped。默认行为是动画跑完就停在那儿等你来删，你 new 出来又没存指针，就漏了。加上这个标志，动画结束自动析构。

中间过程你一行代码都不用写。Qt 每帧算一个插值，调 setRadius，你的 paintEvent 被 update() 触发，画面就动了。整条链路是：动画框架 → setRadius → update() → paintEvent。

动 Qt 自带的属性

自己写的属性要登记，QWidget 自带的一堆属性早就登记好了，直接拿来用。

cpp
// 窗口淡入
QPropertyAnimation *fade = new QPropertyAnimation(this, "windowOpacity");
fade->setDuration(600);
fade->setStartValue(0.0);
fade->setEndValue(1.0);
fade->start(QAbstractAnimation::DeleteWhenStopped);

windowOpacity 是 QWidget 的现成属性，范围 0 到 1。同理还有 geometry、pos、size、minimumWidth 这些。动 geometry 就是窗口或控件的位置加尺寸一起变，做滑出式面板很方便。

cpp
QPropertyAnimation *slide = new QPropertyAnimation(panel, "geometry");
slide->setDuration(300);
slide->setStartValue(QRect(-200, 0, 200, height()));
slide->setEndValue(QRect(0, 0, 200, height()));
slide->start(QAbstractAnimation::DeleteWhenStopped);

图形项怎么办

QGraphicsItem 不是 QObject 的子类，没有元对象系统，属性动画动不了它。要动图形项，得用 QGraphicsObject——它是 QGraphicsItem 和 QObject 的双继承版本，属性表齐全。

它自带的 x、y、rotation、opacity、scale、pos 都是 Q_PROPERTY，直接可用：

cpp
QPropertyAnimation *spin = new QPropertyAnimation(item, "rotation");
spin->setDuration(2000);
spin->setStartValue(0.0);
spin->setEndValue(360.0);
spin->start(QAbstractAnimation::DeleteWhenStopped);

注意属性名是 "rotation" 不是 "angle"，"pos" 也能直接动，类型是 QPointF。Qt 的插值器认识 qreal、QPoint、QPointF、QRect、QSize、QColor 这些常见类型，自定义结构体要自己写插值函数。

和手写定时器的分工

对比项 QPropertyAnimation QTimer 手写
需要 Q_PROPERTY 需要 不需要
中间帧计算 框架负责 自己算步长
速度控制 setDuration 一行 改定时器间隔，容易抖
暂停 / 恢复 pause() / resume() 自带 自己维护状态位
缓动曲线 内置几十种 手写公式
循环播放 setLoopCount 一行 自己数次数
适用场景 属性平滑变化 定时重绘、逐帧推进、自定义逻辑

结论不是「用属性动画替代定时器」。属性动画擅长「从 A 到 B」，定时器擅长「每过一会儿干点事」。第八章的粒子碰撞例子就是后者，属性动画做不来。

八、动画的驱动方式 #

第七章的动画由框架推着走。素材里的那篇动画走的是另一条路：**自己拿定时器推。**两条路都合法，选哪条看你要动的东西能不能被描述成一个属性。

素材里的做法

原例是满屏小方块互相碰撞，碰上了变红，没碰上保持绿。这个动画里，每个方块的位置还依赖碰撞检测的结果，没法写成「从 A 到 B」，所以只能用定时器。

先看数据结构。MyItem 继承 QGraphicsItem，自己维护角度和速度。

cpp
// myitem.h
#ifndef MYITEM_H
#define MYITEM_H

#include <QGraphicsItem>

class MyItem : public QGraphicsItem
{
public:
    MyItem();
    QRectF boundingRect() const;
    void paint(QPainter *painter, const QStyleOptionGraphicsItem *option, QWidget *widget = 0);

protected:
    void advance(int phase);        // 由场景统一调度

private:
    qreal angle;                    // 旋转角度
    qreal speed;                    // 速度
    void DoCollision();             // 碰撞后的处理
};

#endif // MYITEM_H

advance(int phase) 是个特殊入口。QGraphicsScene::advance() 被调用时，场景会遍历所有图形项，每个项的 advance 被调两次：第一次 phase == 0，用来做「准备」；第二次 phase == 1，用来做「移动」。这是为了让碰撞检测有时间差，不是设计失误。

cpp
void MyItem::advance(int phase)
{
    if (!phase) return;             // phase 为 0 时什么也不做
    setPos(mapToParent(0, -speed)); // 沿自身坐标系向上移动
}

mapToParent 把「自身坐标系里的一个偏移」换算成「父坐标系里的位置」。图形项被 setRotation 转过以后，自身坐标系也跟着转了，所以按自身坐标移动才能得到「朝着自己面朝的方向飞」的效果。用 setPos(pos() + QPointF(0, -speed)) 就没有这个效果，方块会全部朝屏幕上方飞。

paint 里顺手做碰撞检测。

cpp
void MyItem::paint(QPainter *painter, const QStyleOptionGraphicsItem *option, QWidget *widget)
{
    QRectF rec = boundingRect();
    QBrush brush(Qt::red);

    if (scene()->collidingItems(this).isEmpty())
    {
        brush.setColor(Qt::green);      // 无碰撞
    }
    else
    {
        brush.setColor(Qt::red);        // 有碰撞
        DoCollision();
    }

    painter->fillRect(rec, brush);
    painter->drawRect(rec);
}

collidingItems(this) 返回和当前项相交的所有项。空列表说明没碰上。

DoCollision 里处理反弹：转个方向，再判断有没有飞出场景边界，飞出去了就拉回来。

cpp
void MyItem::DoCollision()
{
    setRotation(rotation() + 180 + (qrand() % 20 - 10));

    QPointF newPoint = mapToParent(-boundingRect().width(), -(boundingRect().width() + 2));
    if (!scene()->sceneRect().contains(newPoint))
    {
        newPoint = mapToParent(0, 0);   // 出界了，退回原位
    }
    setPos(newPoint);
}

素材原稿这里写的是 qrand() % 1，这个表达式永远等于 0，两个分支实际上是同一个结果。想取随机量，模数必须大于 1，比如 qrand() % 20 得到 0 到 19。

搭建场景的代码，定时器一接就通了。

cpp
Dialog::Dialog(QWidget *parent) :
    QDialog(parent),
    ui(new Ui::Dialog)
{
    ui->setupUi(this);

    ui->graphicsView->setRenderHint(QPainter::Antialiasing);
    scene = new QGraphicsScene(this);
    scene->setSceneRect(-200, -200, 400, 400);
    ui->graphicsView->setScene(scene);

    QPen myPen(Qt::black);
    myPen.setWidth(2);
    scene->addLine(QLineF(scene->sceneRect().topLeft(), scene->sceneRect().topRight()), myPen);
    scene->addLine(QLineF(scene->sceneRect().topLeft(), scene->sceneRect().bottomLeft()), myPen);
    scene->addLine(QLineF(scene->sceneRect().bottomRight(), scene->sceneRect().topRight()), myPen);
    scene->addLine(QLineF(scene->sceneRect().bottomRight(), scene->sceneRect().bottomLeft()), myPen);

    const int ItemCount = 25;
    for (int i = 0; i < ItemCount; ++i)
    {
        MyItem *item = new MyItem();
        scene->addItem(item);
    }

    timer = new QTimer(this);
    connect(timer, SIGNAL(timeout()), scene, SLOT(advance()));
    timer->start(100);          // 每 100 毫秒推进一帧
}

connect(timer, SIGNAL(timeout()), scene, SLOT(advance())) 这一行是全篇最省事的一行。定时器超时，场景推进，所有图形项的 advance 被调两次，位置更新，视图自动重绘。你一手都没伸进去。

驱动方式对照

方式 触发机制 适合动什么 代码量
QPropertyAnimation 框架按时间插值 单个 Q_PROPERTY 属性 五六行
QTimer + QGraphicsScene::advance 定时器轮询 场景内所有图形项的逐帧状态 十几行
QTimer + 自定义槽 定时器轮询 任何东西，包括非属性成员 看逻辑
QVariantAnimation 框架插值，valueChanged 信号 不能写成属性的量 七八行
QSequentialAnimationGroup 框架串行调度 一串按顺序播放的动画 组合而成
QParallelAnimationGroup 框架并行调度 一串同时播放的动画 组合而成

QVariantAnimation 单独说一句，它是不需要 Q_PROPERTY 的动画类：

cpp
QVariantAnimation *anim = new QVariantAnimation;
anim->setDuration(1000);
anim->setStartValue(0.0);
anim->setEndValue(1.0);
connect(anim, &QVariantAnimation::valueChanged, this, [this](const QVariant &v) {
    m_ratio = v.toDouble();     // 普通成员变量，照样能动
    update();
});
anim->start(QAbstractAnimation::DeleteWhenStopped);

它只负责算插值然后发信号，值往哪儿塞由你决定。想动普通成员变量又想要缓动曲线，用这个，别硬着头皮去加 Q_PROPERTY。

想编排顺序用 QSequentialAnimationGroup，addAnimation 进去的动画会一个接一个播；换成 QParallelAnimationGroup 就同时播。

九、缓动曲线 #

上一章代码里出现过一行 setEasingCurve(QEasingCurve::OutBounce)。这行管的是「进度怎么分配」，图形本身一点没变。

线性插值是「时间过一半，值走一半」。物理世界里的东西不是这样动的：掉下来的球越掉越快，弹起来越弹越慢，刹车是猛地一顿再滑。缓动曲线就是给进度做一层映射，让动画的节奏像真的。

QEasingCurve 一共几十种，常用的这一批记下来就够。

枚举值 观感 用在哪
Linear 匀速，一板一眼 进度条、旋转指示器
InQuad / OutQuad / InOutQuad 慢起快收 / 快起慢收 / 两头慢中间快 大多数位移，OutQuad 最耐看
InCubic / OutCubic / InOutCubic 同上，但更陡 需要明显加速感的位移
OutBack 冲到终点再回弹一点 弹窗弹出、按钮按下
OutBounce 落地弹几下，幅度递减 掉落物、提示冒出
OutElastic 绕终点来回晃，像弹簧 有弹性的面板
InOutSine 两头缓、中间快，最柔和 淡入淡出、透明度变化
OutInQuad 先快停一下再加速 转场 
cpp
QPropertyAnimation *anim = new QPropertyAnimation(box, "radius");
anim->setDuration(900);
anim->setStartValue(0.0);
anim->setEndValue(60.0);
anim->setEasingCurve(QEasingCurve::OutBack);   // 冲过头再回来一点
anim->start(QAbstractAnimation::DeleteWhenStopped);

Out 开头的是「先快后慢」，适合进入画面；In 开头的是「先慢后快」，适合离开画面；InOut 两头都缓。名字里的 Quad、Cubic 是幂次，数字越大曲线越陡。OutBack 会短暂越过终点值，属性有硬性取值范围时（比如 windowOpacity 只能是 0 到 1），越过的那一下会被夹回边界，观感会打折。

自定义曲线用 QEasingCurve::setCustomType 传一个函数指针进去，输入输出都是 0 到 1 的 qreal。日常写界面，内置那几十种够用了。

十、ToolTip 的设置 #

这一章换个话题。ToolTip 是鼠标在控件上停一会儿旁边冒出来的小黄条，讲清楚它跟绘图没关系，只是当年被归在同一个目录下。

一句话定义：**ToolTip 是鼠标悬停在控件上、不点击不按键时出现的那段帮助信息。**你在 Word 里把鼠标搁在保存图标上，看到「保存 (Ctrl+S)」，那就是它。

设置只有一行。

cpp
ui->pushButton1->setToolTip("保存当前文件");

setToolTip 是 QWidget 的成员函数，所有控件都有。设了就有，不设就没有。清空传空字符串。

显示的时机和位置

默认延迟由 QApplication 管，停大约 700 毫秒才冒出来。想改全局延迟：

cpp
QToolTip::setFont(QFont("Microsoft YaHei", 10));   // 全局字体

想立刻弹、自己定位置，用静态函数：

cpp
QToolTip::showText(QCursor::pos(), "手动弹出的提示", this);

这个版本绕过了延迟，也绕过了「鼠标必须停在控件上」的限制。做自定义悬浮提示时用它。

样式

QToolTip 支持一部分 Qt 样式表属性，配色能改：

cpp
qApp->setStyleSheet("QToolTip { color: #333; background-color: #fffbe6; "
                    "border: 1px solid #d4c88a; padding: 4px; }");

只认颜色、边框、内边距这几个，字体大小得通过 QToolTip::setFont 设。

和 What's This 的关系

ToolTip 是「鼠标停上去自动出现」。Qt 还有个兄弟叫 What's This 帮助，触发方式完全不同：窗口右上角一个「?」按钮，点它进入提问模式，鼠标变成问号，再点某个控件才弹说明。

cpp
ui->pushButton->setWhatsThis("这个按钮会把当前文档另存为一份副本。");

它适合放比 ToolTip 长一截的说明文字。机制上两者都是字符串，都能吃富文本，区别只在触发路径。素材里那篇顺带讲了事件过滤器，跟 ToolTip 不是一回事，这里不展开——installEventFilter 那一套在讲事件系统的地方更合适。

十一、富文本与图片 ToolTip #

setToolTip 的字符串不是纯文本。Qt 会先试着按富文本解析，解析失败才退回纯文本。

cpp
ui->pushButton1->setToolTip("Hello <font color='red'><b>World</b></font>"
                            "<ul>"
                            "<li>Item 1</li>"
                            "<li>Item 2</li>"
                            "<li>Item 3</li>"
                            "</ul>");

<font color> 改颜色，<b> 加粗，<ul><li> 出列表。多段字符串字面量挨着写会自动拼接，所以上面四行其实是一个长字符串。

用资源文件里的图片

ToolTip 里的 <img> 能直接引用 Qt 资源系统的路径：

cpp
ui->pushButton2->setToolTip("<img src=':image/panda.png'>KungFuPanda");

开头的冒号是资源路径的标记，后面跟着 .qrc 里登记的别名。资源文件是这么加的：项目右键 → 添加新文件 → Qt → Qt Resource File，起个名字比如 res，然后在生成的 res.qrc 里 Add Prefix（填 /image）→ Add Files（选图片）。

.qrc 本质上是一份 XML 清单，构建时 rcc 工具把列出来的图片编成 C++ 数组塞进可执行文件。所以运行时不需要图片文件在旁边，拷走一个 exe 就能跑。素材原稿这一步的截图丢了，内容补在这里。

路径写法要和 .qrc 里的前缀对齐。前缀 /image 加文件名 panda.png，引用就是 :/image/panda.png；别名如果写成 :image/panda.png（少一道斜杠），照样能用，Qt 会把前缀拼上去。写错路径的表现是提示框里出现一个破图标记，不报错。

富文本的边界

Qt 的富文本是 HTML 的一个子集，不是完整浏览器。ToolTip 里能用的标签：

能力 支持情况
<b> <i> <u> <s> 支持
<font color size face> 支持
<ul> <ol> <li> 支持
<br> <p> <hr> 支持
<img src> 支持，但不自动缩放
<table> 支持基础表格
CSS <style> 块 不支持
JavaScript 不支持

图片不自动缩放这条要留心。一张 800 像素宽的图塞进 ToolTip，会把提示框撑到半个屏幕。用 <img width='120' height='120' src='...'> 手动限死。

cpp
ui->pushButton2->setToolTip("<img src=':image/panda.png' width='96' height='96'>"
                            "<br>KungFuPanda");

判断该用哪一种

内容 做法
一句话说明 setToolTip("保存当前文件")
需要强调或分行 富文本，<b> + <br>
要列点 富文本，<ul><li>
要配图 富文本 + 资源文件，<img> 记得限宽高
一整段操作说明 换成 What's This，别硬塞 ToolTip

ToolTip 的美德是短。超过两行就该换地方了，鼠标悬停这种交互撑不住长文本。

十二、易错点速查 #

把这一篇里所有翻过车的地方摆在一张表上。

现象 原因 改法
控制台报 Paint device returned engine == 0 在构造函数里造 QPainter 所有绘制搬进 paintEvent
程序跑着但界面不动 setXxx 里忘了 update() 改完值立刻请求重画
想画实心矩形，结果是空心 只设了 pen，brush 是 NoBrush 设 brush，或用 fillRect
线段长度比坐标算出来的长 SquareCap / RoundCap 各多出半线宽 精确对齐用 FlatCap
折线拐角没变化 用了多次 drawLine，没有拐角 拼成 QPainterPath 再 drawPath
闭合矩形的 cap 设了没反应 闭合路径没有端点 正常现象，cap 对闭合路径无效
尖角戳出画面 MiterJoin 在小夹角下尖刺过长 换 BevelJoin，或调大 setMiterLimit
渐变改了颜色画面没变 QBrush 构造时已拷贝旧状态 改完渐变重新 setBrush
渐变只占图形一角，其余纯色 渐变范围小于图形范围，且是 PadSpread 扩大范围 / 换 RepeatSpread / 用 ObjectBoundingMode
控件缩放后渐变不跟着变 默认 LogicalMode setCoordinateMode(QGradient::ObjectBoundingMode)
锥形渐变接缝处有硬边 首尾停靠点颜色不同 0.0 和 1.0 写同一个颜色
径向渐变的环不是同心圆 第四参数焦点偏离了圆心 焦点传圆心坐标，或干脆用三参数构造
文字渐变没效果 给 drawText 设了 brush 文字颜色只认 pen，改 QPen(QBrush(g), 0)
属性动画报 non-existing property 属性没写 Q_PROPERTY，或名字拼错 补 Q_PROPERTY，属性名逐字核对
属性动画跑完就崩 动画对象没人删 start(QAbstractAnimation::DeleteWhenStopped)
图形项动不了 QGraphicsItem 不是 QObject 改用 QGraphicsObject
方块全朝屏幕上方飞 用了 pos() + 偏移，没走自身坐标 setPos(mapToParent(0, -speed))
qrand() % 1 取不到随机数 模 1 恒等于 0 模数改大，如 % 20
ToolTip 里的图撑爆提示框 <img> 不限尺寸就按原始像素画 加 width / height 属性
ToolTip 里图片显示成破图 资源路径和 .qrc 前缀对不上 核对 :/前缀/文件名

三句话收尾。

渐变永远走「造渐变 → 包成 QBrush → setBrush → 照常 draw」这条路，没有例外。cap 管两端，join 管拐角，画粗线之前先把这两个参数想清楚。属性动画的前提是 Q_PROPERTY，没有它就先想想是不是该用定时器或者 QVariantAnimation。
