本篇讲 Qt 界面上「摆东西」这件事：布局管理器怎么接管尺寸，常用控件怎么用，QAction 怎么把菜单、工具栏、右键菜单合成一套，QMessageBox 怎么弹。前一篇《Qt 入门与信号槽》解决的是信号与槽怎么连，这里默认你会写 connect、会用 Designer 拖控件、知道 ui->setupUi(this) 在干什么。本篇不碰模型视图里 QAbstractItemModel 那一层，不碰绘图与动画，不碰定时器与网络，也不碰工程化拆分，这些在后面几篇：《模型视图与 QVariant》《定时器与网络》《绘图与动画》《工程实践》。菜单栏、工具栏的完整工程写法也不在本篇范围，这里只讲它们和 QAction 的关系。

一、布局管理器解决什么问题 #

写界面第一步不是挑控件，是回答一个问题：尺寸由谁说了算。

Qt 里只有两个答案。你说了算，或者布局说了算。先看你说了算的版本：

cpp
#include <QApplication>
#include <QPushButton>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("手算坐标");
    window.resize(320, 120);
    QPushButton *b1 = new QPushButton("one", &window);
    b1->setGeometry(10, 10, 90, 30);
    QPushButton *b2 = new QPushButton("two", &window);
    b2->setGeometry(110, 10, 90, 30);
    QPushButton *b3 = new QPushButton("three", &window);
    b3->setGeometry(210, 10, 90, 30);
    window.show();
    return app.exec();
}

三个按钮横着放，跑起来看着没问题。一换窗口尺寸就露馅：拉宽，右边空一截；拉窄，「three」被切掉一半。系统字体换成大字号，按钮文字挤成两行，谁都不管。

setGeometry 里的坐标是相对父控件的，跟父控件的实际大小没有任何联动关系。父控件变了，子控件不动，手动排版走到这里就到头了。

改成布局，同一件事的核心只有五行（完整程序在第二章）：

cpp
QHBoxLayout *hlayout = new QHBoxLayout;
hlayout->addWidget(b1);
hlayout->addWidget(b2);
hlayout->addWidget(b3);
window.setLayout(hlayout);   // 三个按钮交给水平布局去分

窗口拉多宽，三个按钮就平分多宽。窗口拉高，按钮跟着变高。文字变大，按钮撑开。

布局管理器接管控件的几何尺寸。 这句话是整篇的地基，也是新手撞的第一道墙。它的具体含义有三条：

  1. QLayout 不是 QWidget，它是 QObject。它自己不上屏，只负责算账。
  2. setLayout 之后，布局对象把自己挂到父控件上，开始监听父控件的 QEvent::Resize 和子控件的显隐、字体、sizeHint 变化。
  3. 每次触发，布局重新算一遍所有 item 的矩形，然后替你调 setGeometry。你之前手写的坐标被直接覆盖。

所以用了布局，下面这些写法全部失效：

cpp
// 布局装好之后再写这些，等于白写
b1->setGeometry(0, 0, 400, 40);
b1->move(0, 0);
b1->resize(400, 40);   // 单个子控件的 resize 会被下一次布局重算吃掉

注意 window.resize() 对顶层窗口仍然生效，布局会按新尺寸重新分配；但布局里的子控件，你调 resize 没有意义。想让某个控件大一点，改它的 sizeHint、minimumSize、QSizePolicy，或者改拉伸因子，不要动坐标。

四种布局的分工：

布局类 摆放方式 关键接口 什么时候用
QHBoxLayout 从左到右排一行 addWidget / addStretch / setSpacing 一排按钮、一行输入、工具条
QVBoxLayout 从上到下排一列 同上 竖排表单、侧边栏、上下分区
QGridLayout 行列网格，可跨格 addWidget(w, row, col, rowSpan, colSpan) 标签与输入对齐、九宫格按键区
QFormLayout 左标签右控件两列 addRow("Name", edit) 设置页、录入表单

QSplitter 不在表里，它不是 QLayout 的子类，但它也在管尺寸，第四章单独说。

布局还有一个隐性的好处：窗口缩到很小的时候，布局不会把控件挤成负数宽度，它按 minimumSizeHint 收住，窗口再小就出滚动条或者被系统拒绝。

二、水平与垂直布局 #

QHBoxLayout 和 QVBoxLayout 都继承自 QBoxLayout，区别只在方向。先跑最小版本：

cpp
#include <QApplication>
#include <QHBoxLayout>
#include <QPushButton>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("My App");
    QPushButton *button1 = new QPushButton("one");
    QPushButton *button2 = new QPushButton("two");
    QPushButton *button3 = new QPushButton("three");
    QHBoxLayout *hlayout = new QHBoxLayout;
    hlayout->addWidget(button1);
    hlayout->addWidget(button2);
    hlayout->addWidget(button3);
    window.setLayout(hlayout);   // 设置窗口布局
    window.show();
    return app.exec();
}

换成垂直，只改三处，其余照抄：

cpp
#include <QVBoxLayout>                     // 原来 include 的是 QHBoxLayout
QVBoxLayout *vlayout = new QVBoxLayout;    // 类名和变量名一起换
vlayout->addWidget(button1);               // 三个 addWidget 一字不改
vlayout->addWidget(button2);
vlayout->addWidget(button3);
window.setLayout(vlayout);                 // 设置窗口布局

注意按钮构造时没有传 parent。布局 addWidget 会给控件设 parent，你提前传了也不会出错，只是多一层重设。

弹簧、间距、边距 #

真正决定界面「像不像样」的，是这四个东西：

接口 作用 说明
addWidget(w) 加控件 parent 会被布局重设
addLayout(l) 嵌子布局 嵌套见第五章
addSpacing(px) 固定空隙 不参与拉伸，尺寸写死
addStretch(n) 弹簧 按权重吃掉剩余空间
setSpacing(px) item 之间间距 所有相邻 item 统一生效
setContentsMargins(l, t, r, b) 布局外边距 Designer 里的 layoutLeftMargin 那一组

addStretch 是最常用的一个。按钮默认会被拉伸填满整行，想让它们靠在右边，就在前面塞一个弹簧：

cpp
QHBoxLayout *hlayout = new QHBoxLayout;
hlayout->setContentsMargins(12, 12, 12, 6); // 左 上 右 下
hlayout->setSpacing(8);
hlayout->addStretch(1);        // 左边的弹簧把按钮推到右边
hlayout->addWidget(okButton);
hlayout->addWidget(cancelButton);

两个弹簧夹住控件，控件就居中；弹簧放最后，控件就靠左。弹簧的数值是权重，不是像素，addStretch(2) 比 addStretch(1) 多占一倍空间。

拉伸因子 #

不写弹簧也行，直接给控件分配权重：

cpp
QHBoxLayout *hlayout = new QHBoxLayout;
hlayout->addWidget(sidebar, 0);  // 权重 0，宽度守住 sizeHint
hlayout->addWidget(content, 1);  // 权重 1，吃掉所有多余宽度

第二个参数默认是 0。权重全 0 的时候，多出来的空间按各控件的 QSizePolicy 均分。

对齐 #

某个控件不想被拉满，用对齐标志：

cpp
hlayout->addWidget(titleLabel, 0, Qt::AlignLeft | Qt::AlignVCenter);
hlayout->addWidget(fixedButton, 0, Qt::AlignRight);

addWidget、addLayout 的末尾都能带 Qt::Alignment。第三个参数在有拉伸因子时是位或组合，所以常见写法是 addWidget(w, 1, Qt::AlignCenter)。

QHBoxLayout 和 QVBoxLayout 本质是同一个类换了个方向参数。QBoxLayout::setDirection() 能在横竖之间即时切换，做响应式布局时不用重建控件：

cpp
boxLayout->setDirection(width() < 600 ? QBoxLayout::TopToBottom
                                     : QBoxLayout::LeftToRight);

三、网格布局 #

Grid 就是行列构成的小格子，和作业本的田字格一个意思。QGridLayout 用 (row, col) 定位，行号列号都从 0 开始，不需要预先声明有几行几列，它会自己扩。

一个能跑的完整例子，姓名和电话两行，OK 按钮横跨两列：

cpp
#include <QApplication>
#include <QGridLayout>
#include <QLabel>
#include <QLineEdit>
#include <QPushButton>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("My App");
    QGridLayout *layout = new QGridLayout;
    QLabel    *label1 = new QLabel("Name");
    QLineEdit *edit1  = new QLineEdit;
    QLabel    *label2 = new QLabel("Tel");
    QLineEdit *edit2  = new QLineEdit;
    QPushButton *button = new QPushButton("OK");
    layout->addWidget(label1, 0, 0);
    layout->addWidget(edit1,  0, 1);
    layout->addWidget(label2, 1, 0);
    layout->addWidget(edit2,  1, 1);
    layout->addWidget(button, 2, 0, 1, 2); // 第 2 行第 0 列，占 1 行 2 列
    layout->setColumnStretch(1, 1);        // 第 1 列吃掉多余宽度
    window.setLayout(layout);
    window.show();
    return app.exec();
}

摆出来的格子是这样：

第 0 列 第 1 列
第 0 行 label1（Name） edit1
第 1 行 label2（Tel） edit2
第 2 行 button（占两列） 同上，被 button 合并

addWidget 的四个数字是 row, column, rowSpan, columnSpan。addWidget(button, 2, 0, 1, 2) 表示放在第 2 行第 0 列，向下占 1 行、向右占 2 列。省略后两个参数就是占 1 行 1 列。

拉伸与最小尺寸 #

QGridLayout 默认让每列宽度取该列最宽控件的 sizeHint，多余空间平均分。想指定谁吃空间：

cpp
layout->setColumnStretch(1, 1);   // 输入框那一列拉伸
layout->setRowStretch(3, 1);      // 第 3 行吃掉竖向多余空间
layout->setColumnMinimumWidth(0, 80); // 标签列最窄 80 像素
layout->setRowMinimumHeight(0, 32);

不设 setColumnStretch 的时候，输入框不会跟着窗口变宽，这是初学者最常见的「为什么我的输入框不变长」。

三个坑 #

同一个格子塞两个控件。 后加的会盖住先加的，两者不会并排：

cpp
layout->addWidget(edit1, 0, 1);   // 被覆盖
layout->addWidget(edit2, 0, 1);

留下空洞导致错位。 从 (0,0) 直接跳到 (0,2)，第 1 列会以一个零宽列存在，界面看起来像少了一块。跳格时想清楚是故意的还是漏加。

跟 QFormLayout 混用。 纯两列表单用 QFormLayout 一行代码搞定，不必拿网格硬凑：

cpp
QFormLayout *form = new QFormLayout;
form->addRow("Name", edit1);
form->addRow("Tel",  edit2);

标签宽度、对齐、换行，QFormLayout 都替你算了。

四、Splitter：可拖动的分隔 #

前面三种布局都由程序决定每块占多少，用户不能改。QSplitter 反过来，把分界线交给用户拖。它能让你通过拖拽子对象的边界，改变子对象的形状和大小。一个 Splitter 可以管任意数量的组件，两个、三个、五个都行。

在 Designer 里的做法是：框选两个按键，按工具栏上的「水平分裂器」按钮，或者在选中的控件上右键 → Lay Out → Lay Out Horizontally in Splitter。代码里对应的是：

cpp
#include <QApplication>
#include <QListWidget>
#include <QSplitter>
#include <QTextEdit>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QSplitter *splitter = new QSplitter(Qt::Horizontal);
    QListWidget *list = new QListWidget;
    list->addItems(QStringList() << "one" << "two" << "three");
    QTextEdit *editor = new QTextEdit;
    editor->setPlainText("右边这块是编辑区，拖中间那条线试试");
    splitter->addWidget(list);
    splitter->addWidget(editor);
    splitter->setStretchFactor(0, 0);   // 左边不跟着拉伸
    splitter->setStretchFactor(1, 1);   // 右边吃掉多余宽度
    splitter->setSizes(QList<int>() << 140 << 460); // 初始宽度分配
    splitter->setChildrenCollapsible(false);        // 禁止拖到 0 宽
    splitter->setWindowTitle("Splitter");
    splitter->resize(640, 360);
    splitter->show();
    return app.exec();
}

拖两个子控件之间的那条线，左右比例就变了。QSplitter 自己不画内容，它只管分界线两侧的矩形，内容还是那两个控件自己的事。

几个常用设置 #

接口 作用
addWidget(w) 把控件塞进分栏，按加入顺序从左到右或从上到下排
setOrientation(Qt::Horizontal) 横竖切换，构造参数也能直接给
setSizes(QList<int>) 初始各栏宽度，列表长度要和子控件数一致
setStretchFactor(i, n) 窗口拉伸时第 i 栏的权重，0 表示不拉伸
setChildrenCollapsible(false) 不允许用户把某一栏拖没
setHandleWidth(px) 分界线粗细
setOpaqueResize(false) 拖动时只画一条虚线，松手才重排

两条实践经验：

setSizes 受窗口最终尺寸影响。窗口还没 show、resize 还没生效的时候调用，数值会被裁。稳妥的写法是先 resize，再 setSizes，或者干脆在 show 之后再调一次。

setSizes 之后不要再 addWidget。新加的控件会打乱列表对应关系，需要重新 setSizes。

Splitter 不是布局 #

这一点最容易混。QSplitter 继承自 QWidget，不是 QLayout。它有两种用法：

当窗口用。 自己做顶层窗口，像上面那个例子。

当控件用。 塞进别的布局里，和其他控件一起排：

cpp
QVBoxLayout *vlayout = new QVBoxLayout;
vlayout->addWidget(toolbarRow);
vlayout->addWidget(splitter, 1);   // Splitter 占满剩余竖向空间
vlayout->addWidget(buttonRow);
window.setLayout(vlayout);

和布局的分工：

QLayout QSplitter
父类 QObject QWidget，可见，占事件
尺寸谁定 程序按规则算 用户拖，程序只给初值
能否被布局管理 本身就是布局 当成一个普通控件加进布局
典型场景 固定结构的界面 文件树与编辑区、上下分栏的调试面板

嵌套 Splitter 能做出 IDE 那种三栏效果：外层水平 Splitter 装「左树」和「右区域」，右区域再是一个垂直 Splitter。

五、布局的嵌套 #

真实界面很少只有一层。顶部一排工具栏按钮，中间一块表单，底部一排确认取消，全靠嵌套。

cpp
#include <QApplication>
#include <QGridLayout>
#include <QHBoxLayout>
#include <QLabel>
#include <QLineEdit>
#include <QPushButton>
#include <QVBoxLayout>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("嵌套布局");
    // 顶部一行
    QHBoxLayout *top = new QHBoxLayout;
    top->addWidget(new QLabel("姓名"));
    top->addWidget(new QLineEdit);
    top->addStretch(1);
    // 中间网格
    QGridLayout *center = new QGridLayout;
    center->addWidget(new QLabel("电话"), 0, 0);
    center->addWidget(new QLineEdit,       0, 1);
    center->addWidget(new QLabel("地址"), 1, 0);
    center->addWidget(new QLineEdit,       1, 1);
    center->setColumnStretch(1, 1);
    // 底部一行
    QHBoxLayout *bottom = new QHBoxLayout;
    bottom->addStretch(1);
    QPushButton *ok     = new QPushButton("OK");
    QPushButton *cancel = new QPushButton("Cancel");
    bottom->addWidget(ok);
    bottom->addWidget(cancel);
    // 外层竖排，把三块串起来
    QVBoxLayout *mainLayout = new QVBoxLayout;
    mainLayout->addLayout(top);
    mainLayout->addLayout(center, 1);
    mainLayout->addLayout(bottom);
    window.setLayout(mainLayout);
    window.show();
    return app.exec();
}

三块各自是独立布局，addLayout 把它们串进外层。中间那块给了拉伸权重 1，所以窗口变高时多出来的空间全给表单区，顶栏和底栏保持原高。

四条必须记住的规则 #

一个窗口只有一个顶层布局。 第二次 setLayout 会出警告，旧布局的处理也不受你控制。要换布局，先删掉旧的。

子布局不要传 parent。 写成 new QHBoxLayout(&window) 再 addLayout，等于同时给两个地方当孩子，布局位置会乱。子布局一律 new QHBoxLayout 不带参数，交给 addLayout 认领。

边距会叠加。 外层有 9 像素边距，内层也有 9 像素，视觉上就是 18 像素的空白。对齐设计稿的时候，内层子布局要显式清掉：

cpp
top->setContentsMargins(0, 0, 0, 0);
top->setSpacing(6);

QGroupBox 自带布局容器。 要一块带标题的框，直接给它 setLayout：

cpp
QGroupBox *box = new QGroupBox("连接设置");
QFormLayout *form = new QFormLayout;
form->addRow("主机", new QLineEdit);
form->addRow("端口", new QLineEdit);
box->setLayout(form);

嵌套深度控制在三四层以内。层数一多，改一个边距要往上找四五处，Designer 里也会点错对象。

六、常用控件一览 #

控件是积木，布局是摆法。先把积木清点一遍，后面几章挑重点讲。

控件 干什么 常用信号 常调方法
QLabel 显示文字或图片 无（linkActivated 可选） setText / setPixmap / setAlignment
QPushButton 按钮 clicked / toggled setText / setCheckable / setIcon
QLineEdit 单行输入 textChanged / editingFinished text / setEchoMode / setValidator
QTextEdit 多行富文本编辑 textChanged toPlainText / setPlainText
QCheckBox 复选框，可多选 stateChanged / clicked isChecked / setChecked
QRadioButton 单选钮，同组互斥 toggled isChecked / setChecked
QComboBox 下拉框 currentIndexChanged addItem / currentText / currentData
QListWidget 列表 itemClicked / currentItemChanged addItem / currentItem
QTreeWidget 树形列表 itemClicked setColumnCount / setHeaderLabels
QSlider 滑动条 valueChanged setValue / value / setRange
QProgressBar 进度条 无 setValue / setTextVisible
QSpinBox 数字输入 valueChanged setRange / setValue
QStatusBar 窗口底部状态栏 messageChanged showMessage / addPermanentWidget

QSlider 和 QProgressBar 一起用很常见：滑块动，进度条跟着动，靠信号槽连起来。状态栏不在布局体系里，它由 QMainWindow 管，左半边归 showMessage("就绪", 3000) 这种临时消息，右半边归永久部件：

cpp
// 滑块的 valueChanged 接到进度条的 setValue，初始值先对齐
ui->progressBar->setValue(ui->horizontalSlider->value());
connect(ui->horizontalSlider, &QSlider::valueChanged,
        ui->progressBar, &QProgressBar::setValue);

// 状态栏：永久部件从右边排，用 addPermanentWidget
QLabel *statusLabel = new QLabel("ProgressBar: ", this);
QProgressBar *statusProgress = new QProgressBar(this);
statusProgress->setTextVisible(false);            // 只留色块不显示百分比
ui->statusBar->addPermanentWidget(statusLabel);
ui->statusBar->addPermanentWidget(statusProgress);

列表与树 #

QListWidget 是基于项的列表控件，内部自带模型，加项删项都不用自己写 model。改某一项的颜色：

cpp
for (int i = 0; i != 10; ++i)                 // 先塞十条
    ui->listWidget->addItem(QString::number(i) + " item");

void Dialog::on_pushButton_clicked()          // 选中一项后按按钮
{
    QListWidgetItem *item = ui->listWidget->currentItem();
    if (!item) return;                        // 没有选中就退出，别解空指针
    item->setTextColor(Qt::red);              // 只改这一项的文本颜色
}

QTreeWidget 是带层级的版本，两列：项目名和类型说明。

cpp
ui->treeWidget->setColumnCount(2);                                  // 两列
ui->treeWidget->setHeaderLabels(QStringList() << "Item" << "Type"); // 列标题
QTreeWidgetItem *root = new QTreeWidgetItem(ui->treeWidget);
root->setText(0, "Animals");
root->setText(1, "root");
QTreeWidgetItem *child = new QTreeWidgetItem(root);   // 挂在 root 下
child->setText(0, "Cat");
child->setText(1, "mammal");
ui->treeWidget->currentItem()->setBackgroundColor(0, Qt::green);  // 选中项两列刷底色
ui->treeWidget->currentItem()->setBackgroundColor(1, Qt::red);

顺手：枚举目录不是控件 #

写文件浏览器的时候，控件是壳，真正读盘的是 QDir。它不在布局体系里，但和数据控件总是一起出现。核心就一行：m_dir.entryInfoList() 返回当前路径下所有目录和文件的 QFileInfo 列表，配 foreach 挨个判断 item.isDir() 还是 item.isFile()，路径用 item.absoluteFilePath() 拿。

cpp
QString path("F:/");   // 路径里的 / 是目录分隔符，别和转义符 \ 混了
QDir m_dir(path);
foreach (QFileInfo item, m_dir.entryInfoList(QDir::Files | QDir::NoDotAndDotDot))
    qDebug() << item.absoluteFilePath();

不带参数的 entryInfoList() 会把 . 和 .. 也列出来，过滤靠 QDir::Files、QDir::NoDotAndDotDot 这些标志位。QFileInfo 提供与系统无关的文件信息，大小、修改时间、权限都能问它。

七、按键与 QLineEdit #

QPushButton #

按键是 GUI 最基本的元素。一个能跑的版本：

cpp
#include <QApplication>
#include <QMessageBox>
#include <QPushButton>
#include <QVBoxLayout>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("按键");
    QPushButton *button = new QPushButton("点我");
    QVBoxLayout *layout = new QVBoxLayout;
    layout->addWidget(button);
    window.setLayout(layout);
    QObject::connect(button, &QPushButton::clicked, [&window]() {
        QMessageBox::information(&window, "Title", "Hello World !");
    });
    window.resize(240, 100);
    window.show();
    return app.exec();
}

用 Designer 的话可以省掉 connect。拖一个 pushButton 到窗口上，右键它，选菜单里的 Go to slot，弹出对话框里选 clicked()，按 OK，Qt 自动生成空槽并连好：

cpp
void Dialog::on_pushButton_clicked()
{
    // QMessageBox 提供通知用户、向用户提问并接收答案的模态对话框
    QMessageBox::information(this, "Title", "Hello World !");
}

自动连接的规则是 on_<objectName>_<signalName>。这里的 pushButton 是控件在 Designer 里的 objectName。你把 objectName 改成 okButton，槽名不改，连接立刻失效，编译不报错，点了没反应。这是 Designer 项目里最常见的「按钮失灵」原因。

按钮的几个属性值得记：

接口 作用
setText / text 改文字、读文字
setCheckable(true) 变成可按下的切换按钮，信号换成 toggled(bool)
setEnabled(false) 禁用，灰掉且不接收点击
setDefault(true) 对话框里的默认按钮，用户按回车时触发
setIcon(QIcon(":/icon/new.png")) 挂图标，图标来自资源文件
setShortcut(QKeySequence("Ctrl+O")) 按钮快捷键

clicked 和 pressed 不是一回事。pressed 在鼠标按下就发，clicked 要按下再松开，且松手时鼠标还在按钮上。业务逻辑一律用 clicked。

QLineEdit #

QLineEdit 是单行文本编辑器。撤销重做、剪切粘贴、拖放这些编辑功能它自带，你只管取值。

cpp
#include <QApplication>
#include <QLineEdit>
#include <QMessageBox>
#include <QPushButton>
#include <QVBoxLayout>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("QLineEdit");
    QLineEdit *edit = new QLineEdit;
    edit->setEchoMode(QLineEdit::Password);   // 输入的字符显示为圆点
    edit->setPlaceholderText("请输入密码");
    QPushButton *button = new QPushButton("确定");
    QVBoxLayout *layout = new QVBoxLayout;
    layout->addWidget(edit);
    layout->addWidget(button);
    window.setLayout(layout);
    QObject::connect(button, &QPushButton::clicked, [&]() {
        // 把 lineEdit 里的内容弹出来
        QMessageBox::information(&window, "Password", edit->text());
    });
    window.resize(280, 120);
    window.show();
    return app.exec();
}

setEchoMode 四个取值：

常量 效果
QLineEdit::Normal 原样显示，默认值
QLineEdit::NoEcho 一个字都不显示，连长度都看不出来
QLineEdit::Password 用圆点遮住，长度可见
QLineEdit::PasswordEchoOnEdit 输入时显示原文，失焦后遮住

密码框用 Password。需要用户在输入时看清自己敲了什么，用 PasswordEchoOnEdit。

输入控制：

接口 作用
setPlaceholderText("…") 内容为空时的灰色提示字
setMaxLength(16) 最多 16 个字符
setValidator(new QIntValidator(0, 255, edit)) 只允许 0 到 255 的整数
setReadOnly(true) 只读，仍可复制
setClearButtonEnabled(true) 右侧出现一键清空的叉号
text() / setText() / clear() 取值、赋值、清空

信号要分清：

信号 触发时机
textChanged(const QString &) 文字变了就发，程序调 setText 也发
textEdited(const QString &) 只有用户敲键盘才发，setText 不发
returnPressed() 用户按回车
editingFinished() 回车，或者焦点离开

要监听用户输入用 textEdited，要做联动更新用 textChanged，要提交表单用 editingFinished。

一个实际的校验片段，两次密码比对：

cpp
void Dialog::on_okButton_clicked()
{
    if (ui->userEdit->text().isEmpty()) {
        QMessageBox::warning(this, "提示", "用户名不能为空");
        return;
    }
    if (ui->passEdit->text() != ui->confirmEdit->text()) {
        QMessageBox::warning(this, "提示", "两次密码不一致");
        return;
    }
    accept();   // 关掉对话框，返回 QDialog::Accepted
}

accept() 和 reject() 是 QDialog 的两个出口，调用方用 exec() 的返回值判断用户是确认还是取消。

八、QCheckBox 与 QComboBox #

QCheckBox #

复选框管一件事：某个选项是打开还是关闭。应用程序的「设置」对话框里那一排可以打勾的方框就是它。它表达一个特定状态的选定（on，值为 true）或清除（off，值为 false），用来给用户提供「True/False」「yes/no」这类二选一，也可以多个组合起来表达一组开关。

cpp
#include <QApplication>
#include <QCheckBox>
#include <QMessageBox>
#include <QPushButton>
#include <QVBoxLayout>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    QCheckBox *checkBox = new QCheckBox("I like cat");
    checkBox->setChecked(true);    // 默认勾选；false 表示默认不勾
    QPushButton *button = new QPushButton("确定");
    QVBoxLayout *layout = new QVBoxLayout;
    layout->addWidget(checkBox);
    layout->addWidget(button);
    window.setLayout(layout);
    QObject::connect(button, &QPushButton::clicked, [&]() {
        if (checkBox->isChecked())
            QMessageBox::information(&window, "Dialog", "You Like Cat.");
        else
            QMessageBox::information(&window, "Dialog", "You don't Like Cat.");
    });
    window.resize(260, 120);
    window.show();
    return app.exec();
}

对应到 Designer 项目，槽里就是读 isChecked()：

cpp
void Dialog::on_pushButton_clicked()
{
    if (ui->checkBox->isChecked())
        QMessageBox::information(this, "Dialog", "You Like Cat.");
    else
        QMessageBox::information(this, "Dialog", "You don't Like Cat.");
}

三态复选框用于「部分选中」的场景，比如父节点下有五个子项，只勾了三个：

cpp
checkBox->setTristate(true);
QObject::connect(checkBox, &QCheckBox::stateChanged, [](int state) {
    // Qt::Unchecked / Qt::PartiallyChecked / Qt::Checked
});

stateChanged 的参数是 int，别照着 bool 写。只想关心勾没勾，用 toggled(bool) 更省事。

QRadioButton 与它的区别 #

单选钮给出一组互斥选项：选中其中一个，同组的其他项自动弹起。这跟复选框正好相反，复选框可以同时勾任意多个。

cpp
void Dialog::on_pushButton_clicked()
{
    // 根据 RadioButton 的勾选情况，弹出对应信息
    if (ui->radioButton1->isChecked())
        QMessageBox::information(this, "Title", ui->radioButton1->text());
    if (ui->radioButton2->isChecked())
        QMessageBox::information(this, "Title", ui->radioButton2->text());
}

默认选中项在 Designer 的属性面板里把 checked 打勾，代码里是 setChecked(true)。互斥是自动的，但只在同一个父控件内生效。一个窗口里要放两组互斥选项，必须用 QButtonGroup 分开：

cpp
QButtonGroup *group1 = new QButtonGroup(this);
group1->addButton(ui->sizeSmall);
group1->addButton(ui->sizeLarge);
QButtonGroup *group2 = new QButtonGroup(this);
group2->addButton(ui->colorRed);
group2->addButton(ui->colorBlue);
QCheckBox QRadioButton
选择数量 同组内可选任意多个 同组内只能选一个
默认状态 都不勾合理 必须有一个默认勾上
取消 再点一次就取消 点已选中的不会取消
典型场景 功能开关、多选过滤 单选设置、二选一流程
分组 不需要 同父窗口自动一组，多组靠 QButtonGroup

QComboBox #

组合框是一个文本框加一个列表框，点右侧三角弹出列表。它比列表框省地方，选项多的时候优势明显。它也被叫做弹出式菜单。

cpp
#include <QApplication>
#include <QComboBox>
#include <QMessageBox>
#include <QPushButton>
#include <QVBoxLayout>
#include <QWidget>
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("QComboBox");
    QComboBox *comboBox = new QComboBox;
    for (int i = 0; i != 10; ++i)
        comboBox->addItem(QString::number(i) + " Item");  // number 把 int 转成 QString
    QPushButton *button = new QPushButton("取当前值");
    QVBoxLayout *layout = new QVBoxLayout;
    layout->addWidget(comboBox);
    layout->addWidget(button);
    window.setLayout(layout);
    QObject::connect(button, &QPushButton::clicked, [&]() {
        // 输出当前 ComboBox 选中的内容
        QMessageBox::information(&window, "Title", comboBox->currentText());
    });
    window.resize(260, 120);
    window.show();
    return app.exec();
}

Designer 版本只有一个区别：控件从 ui->comboBox 拿。

cpp
void Dialog::on_pushButton_clicked()
{
    QMessageBox::information(this, "Title", ui->comboBox->currentText());
}

常用接口：

接口 作用
addItem(text) / addItems(QStringList) 追加一项或一批
addItem(text, userData) 带隐藏数据的项
insertItem(index, text) 插到指定位置
removeItem(index) / clear() 删一项、清空
currentText() 当前显示的文本
currentData() 当前项的 userData，返回 QVariant
currentIndex() / setCurrentIndex(i) 当前序号，从 0 开始，空的时候是 -1
count() 项数
findText("Python") 按文字找序号，找不到返回 -1
setEditable(true) 允许用户手打，变成可编辑组合框
setItemText(i, "xx") 改第 i 项的显示文字

显示文字和背后取值分开存，是组合框最好用的地方：

cpp
comboBox->addItem("C++",    "cpp");
comboBox->addItem("Python", "py");
QString id = comboBox->currentData().toString();  // 拿到 "cpp" 而不是 "C++"

界面文案改了，数据库里的键值不用动。

信号有三个，用途不同：

信号 触发时机
currentIndexChanged(int) 当前项变了就发，setCurrentIndex 也发
activated(int) 用户主动选了一项才发
editTextChanged(const QString &) 可编辑模式下，输入框文字变化才发

做界面联动用 activated，避免代码里 setCurrentIndex 又触发一遍业务逻辑，绕成死循环。

九、QAction：动作抽象 #

QAction 表示一个用户界面操作，可以被插入到控件里。这句话的重点是「操作」而不是「按钮」。

菜单、工具栏按钮、键盘快捷键都能调用同一条命令，用户期望不管从哪个入口点，命令的行为完全一样。QAction 就是为这件事存在的：把命令本身从它的外观里剥出来。

所以真正的模型是这样：

一个 QAction 同时挂在菜单、工具栏、右键菜单上，状态自动同步。 你 setEnabled(false)，三处一起变灰；你 setChecked(true)，三处一起打勾；你改 setText，三处一起改名。它不是三个独立按钮共用一段代码，是一个对象被三个容器同时引用。

挂载位置：

挂载到哪 写法 用户看到什么
菜单栏 menu->addAction(act) 下拉菜单里的一行
工具栏 toolBar->addAction(act) 带图标的按钮
右键菜单 widget->addAction(act) + setContextMenuPolicy(Qt::ActionsContextMenu) 右键弹出一行
快捷键 act->setShortcut(QKeySequence::Open) 全局按键
普通按钮 button->setDefaultAction(act) 按钮自动跟随动作的文字与图标

一个完整的 QMainWindow 例子，三个动作，三处挂载：

cpp
#include <QAction>
#include <QApplication>
#include <QMainWindow>
#include <QMenuBar>
#include <QMessageBox>
#include <QStyle>
#include <QToolBar>
class MainWindow : public QMainWindow
{
public:
    MainWindow()
    {
        // 三个命令，各建一次，绝不重复
        QAction *actNew  = new QAction("New",  this);
        QAction *actOpen = new QAction("Open", this);
        QAction *actSave = new QAction("Save", this);
        actNew->setIcon(style()->standardIcon(QStyle::SP_FileIcon));
        actOpen->setIcon(style()->standardIcon(QStyle::SP_DialogOpenButton));
        actSave->setIcon(style()->standardIcon(QStyle::SP_DialogSaveButton));
        actNew->setShortcut(QKeySequence::New);
        actOpen->setShortcut(QKeySequence::Open);
        actSave->setShortcut(QKeySequence::Save);
        // 挂载点一：菜单栏
        QMenu *fileMenu = menuBar()->addMenu("&File");
        fileMenu->addAction(actNew);
        fileMenu->addAction(actOpen);
        fileMenu->addSeparator();
        fileMenu->addAction(actSave);
        // 挂载点二：工具栏
        QToolBar *toolBar = addToolBar("Main");
        toolBar->addAction(actNew);
        toolBar->addAction(actOpen);
        toolBar->addAction(actSave);
        // 挂载点三：右键菜单
        setContextMenuPolicy(Qt::ActionsContextMenu);
        addAction(actNew);
        addAction(actOpen);
        addAction(actSave);
        // 动作本身的行为
        connect(actNew, &QAction::triggered, this, [this]() {
            QMessageBox::information(this, "Title", "New");
        });
        connect(actOpen, &QAction::triggered, this, [this]() {
            QMessageBox::information(this, "Title", "Open");
        });
        connect(actSave, &QAction::triggered, this, [this, actNew]() {
            QMessageBox::information(this, "Title", "Save");
            // 保存过就不再需要「新建」，三处入口同时变灰
            actNew->setEnabled(false);
        });
        resize(520, 320);
    }
};
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    MainWindow window;
    window.show();
    return app.exec();
}

跑起来点一次 Save，New 在菜单里、工具栏上、右键菜单里同时灰掉。这就是同步，不需要写三份代码。

Designer 里的做法 #

在 Designer 的 Action Editor 里加动作，或者右键窗口 → Add Action。动作出现在 Action Editor 列表里，直接拖到菜单栏或工具栏上就完成挂载，一个动作拖两次就是两个入口。

槽的连接同样是自动命名：

cpp
// 此处的动作都简化处理，并不对应真实的文件操作
void MainWindow::on_actionNew_triggered()
{
    QMessageBox::information(this, "Title", "New");
}
void MainWindow::on_actionOpen_triggered()
{
    QMessageBox::information(this, "Title", "Open");
}
void MainWindow::on_actionSave_triggered()
{
    QMessageBox::information(this, "Title", "Save");
}

规则是 on_action<动作名>_triggered。动作名就是 Action Editor 里的 Name 列，也就是 objectName。拼错一个字母，连接不存在，编译通过，点击无反应，这种情况排查起来最费时间。

图标与资源 #

动作的图标从资源文件来。新建一个 .qrc，把 png 加进去，代码里就是：

cpp
action->setIcon(QIcon(":/icons/new.png"));   // :/ 是资源路径前缀

QIcon 支持多尺寸和禁用态灰化，不用自己准备两套图。

几条容易踩的细节 #

QAction 的 parent 只有一个，但可以挂在多个容器上。别对同一个动作调两次不同 parent 的构造。

triggered 和 toggled(bool) 是两回事。setCheckable(true) 之后，动作变成开关，两个信号都会发，但 toggled 带状态值，勾选逻辑接它更直接。

工具栏上的动作如果只想要图标不要文字，toolBar->setToolButtonStyle(Qt::ToolButtonIconOnly)。

反例值得点一下：给菜单项建一个 QPushButton、给工具栏再建一个、给右键菜单用 QMenu::addAction("New") 现造一个。三份逻辑、三份图标、三份禁用状态，改一处漏两处。看到这种代码，先合并成 QAction。

十、QMessageBox #

QMessageBox 显示一个模态对话框，里面有一个系统图标、一组按钮和一段简短的应用程序消息，比如状态或错误信息。消息框返回一个值，告诉你用户点了哪个按钮。

模态的意思是这个框不关掉，主窗口就收不到输入。它用来打断用户，所以别滥用。

五种现成的：

静态函数 图标 默认按钮 用途
information 蓝色 i Ok 通知一件事
question 问号 Yes / No（可自定） 询问并拿回答
warning 黄色感叹号 Ok 提示风险
critical 红色停止 Ok 报错
about 应用图标 Ok 关于本程序

四个按钮，四种用法：

cpp
void Dialog::on_pushButton_clicked()
{
    // information 对话框输出信息
    QMessageBox::information(this, "Information", "This is information");
}
void Dialog::on_pushButton_2_clicked()
{
    // question 询问，按不同回答弹出不同对话框
    QMessageBox::StandardButton reply;
    reply = QMessageBox::question(this, "Question", "Do U Like Cats ?",
                                  QMessageBox::Yes | QMessageBox::No);
    if (reply == QMessageBox::Yes)
        QMessageBox::information(this, "Answer", "U Love Cat.");
    else
        QMessageBox::information(this, "Answer", "U doesn't Like Cat.");
}
void Dialog::on_pushButton_3_clicked()
{
    // warning 对话框输出警告信息
    QMessageBox::warning(this, "Warning", "This is Warning");
}
void Dialog::on_pushButton_4_clicked()
{
    // 自定义按钮组合，征求答案
    QMessageBox::question(this, "Custom", "U Feel Good?",
                          QMessageBox::Yes | QMessageBox::No
                          | QMessageBox::YesToAll | QMessageBox::NoToAll);
}

按钮用位或拼，返回值是 QMessageBox::StandardButton 枚举。这里要纠一处旧稿的错：写 YesAll / NoAll 编译不过，枚举名是 YesToAll / NoToAll。

静态函数只够应付「确定/取消」。要设默认按钮、加详细文本、控制 Esc 行为，就得建对象：

cpp
QMessageBox box(this);
box.setWindowTitle("保存");
box.setText("文档已修改，是否保存？");
box.setIcon(QMessageBox::Question);
box.setStandardButtons(QMessageBox::Save | QMessageBox::Discard | QMessageBox::Cancel);
box.setDefaultButton(QMessageBox::Save);            // 回车默认走这个
box.setEscapeButton(QMessageBox::Cancel);           // Esc 走这个
box.setDetailedText("修改时间：2026-01-01 10:00");  // 「显示详情」里的长文本
box.setInformativeText("不保存将丢失本次编辑");     // 正文下方的小字
if (box.exec() == QMessageBox::Save)
    saveFile();

exec() 返回 int，和枚举比较不会报错，但类型上不干净，想严谨就 static_cast<QMessageBox::StandardButton>(box.exec())。

几条使用原则：

确认类操作把危险选项放右边、默认按钮放安全的那一项，防止用户盲敲回车。

消息正文要具体。「操作失败」没用，「无法连接到 192.168.1.10:502，连接被拒绝」才有用。

不要在定时器回调或者 paintEvent 里弹框。模态框会开自己的事件循环，重入能把状态搞乱。

十一、控件与布局怎么配合 #

顺序永远是四步：建控件 → 加进布局 → 布局挂到窗口 → show。跳步就会遇到「窗口一片空白」。

几个高频组合问题：

动态加控件。 直接 addWidget 就能上屏，布局会重算：

cpp
QLineEdit *edit = new QLineEdit;
rowLayout->addWidget(edit);
edit->setFocus();

动态删控件。 要从布局里摘掉再删，只 delete 控件会留下一个空位：

cpp
QLayoutItem *item = rowLayout->takeAt(0);   // 摘掉第 0 项，布局不再管它
if (item) {
    delete item->widget();                  // 删控件
    delete item;                            // 删包装的 layout item
}

隐藏控件。 hide() 之后布局会把它的空间让出来，不是留个洞。想让位置保留，用 setRetainSizeWhenHidden(true)。

QScrollArea 里放网格布局。 少一句 setWidgetResizable(true)，QGridLayout 就是不按滚动区宽度重排，内容挤成一团或者撑出横向滚动条：

cpp
QScrollArea *area = new QScrollArea;
QWidget *content = new QWidget;
content->setLayout(gridLayout);      // 内容 widget 自带布局
area->setWidget(content);
area->setWidgetResizable(true);      // 关键一句：内容随滚动区宽度重排

尺寸谈判的三方。 控件给 sizeHint（我想要多大）和 minimumSizeHint（我最小能多小），布局按 QSizePolicy（我愿不愿意被拉伸）分配，最后父窗口的实际尺寸拍板。三者打架的时候，先看 sizePolicy，再看有没有 minimumWidth 卡住。

QSizePolicy 含义 适合
Fixed 尺寸不变 图标、固定大小的按钮
Minimum 不能再小，可以更大 标签
Preferred 用 sizeHint，可伸可缩 输入框
Expanding 主动吃掉多余空间 文本编辑区、列表
Ignored 完全由布局决定 特殊自绘控件

占位符。 没有控件可放又要占住一块空间，用 QSpacerItem；要弹性空间，还是 addStretch 最省事。

十二、易错点速查 #

现象 原因 处理
窗口一片空白，控件没出现 建了布局没 setLayout，或者忘了 show 四步走完
用了布局后 setGeometry 无效 布局每次重算都会覆盖坐标 改 sizeHint / sizePolicy / 拉伸因子
窗口拉大，控件不跟着变 全部拉伸因子为 0 且 sizePolicy 是 Fixed 加 addStretch 或给权重
输入框不随窗口变长 QGridLayout 没设 setColumnStretch 给输入框那一列设权重
两个控件叠在一起 塞进了同一格 换行号列号，或用跨格
点按钮没反应 Designer 槽名和 objectName 不一致 核对 on_<objectName>_<signal>
布局边距大得离谱 父子布局边距叠加 子布局 setContentsMargins(0,0,0,0)
QScrollArea 里布局不生效 没开 setWidgetResizable 打开它
菜单项行为不一致 每个入口各建了一套控件 合并成一个 QAction
QMessageBox 编译不过 写了 YesAll / NoAll 改 YesToAll / NoToAll
密码框露出明文 忘了 setEchoMode 设成 QLineEdit::Password
单选钮一选就两个同时亮 不同组的按钮同一个 parent 用 QButtonGroup 分组
删除控件后界面留空位 只 delete 没从布局摘 takeAt 后再删
组合框联动跑成死循环 用 currentIndexChanged 做联动 改用 activated

布局这条线的判断标准只有一句：任何控件的坐标都应该由别人算出来，你的代码里不该出现 setGeometry。控件那条线的标准也简单：命令做成 QAction，提示交给 QMessageBox，输入的每一种格式都配一个对应的控件。

把这四类东西摆明白，后面的模型视图、定时器网络才有地方落脚。
