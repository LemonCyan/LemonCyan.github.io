这篇讲什么：模型/视图架构里最常被跳过的一层——委托（delegate），还有 QVariant 这个什么都能装的类型容器。委托管「怎么画、怎么编辑」，QVariant 管「值怎么在模型、视图、委托之间流动」。

不讲什么：不讲从零实现 QAbstractItemModel（index、parent、rowCount 那一套），不讲 QSortFilterProxyModel 的代理链，也不碰 QGraphicsView 图形视图框架。

跨篇指路：QList、QMap 这些容器看《容器与遍历》；paint 里的 QPainter、渐变、坐标变换看《绘图与动画》；QSettings 存取 QVariant 看《工程实践》；信号槽带自定义类型参数看《Qt 入门与信号槽》。

一、委托在模型视图里的位置 #

Qt 的模型/视图不是经典 MVC，它把控制器拆掉了，换成了委托。三个角色各管一件事：

角色 具体类 干什么 你要不要写
模型 QAbstractItemModel 及其子类 存数据，回答「第 r 行第 c 列是什么」 数据特殊时继承
视图 QTableView、QListView、QTreeView 算行高列宽、滚动、处理键盘鼠标 直接用
委托 QStyledItemDelegate 等 单个格子的绘制与编辑 要自定义外观就继承

关键点在于：视图不认识你的数据类型，委托也不认识。它们只认 QVariant。视图问模型要值，模型返回一个 QVariant；视图把画格子这件事转交给委托，委托再自己问模型要值，然后决定画成什么样。

一次绘制的调用链长这样：

text
QTableView 决定重绘某个 index
    │
    ├─ delegate = index 对应的委托（setItemDelegate 设的，或视图默认的）
    │
    ├─ delegate->paint(painter, option, index)
    │        │
    │        ├─ index.data(Qt::DisplayRole) ──> QVariant
    │        ├─ 转成 int / QString / 自定义结构体
    │        └─ 用 QPainter 画出来
    │
    └─ delegate->sizeHint(option, index) ──> QSize，决定这一行多高

模型返回值的那个参数叫 role。同一个 index 能给出很多份数据，靠 role 区分：

Role 含义 典型类型
Qt::DisplayRole 显示用的文本 QString、int
Qt::EditRole 进编辑器时的值 原始类型
Qt::DecorationRole 图标、色块 QIcon、QColor
Qt::ToolTipRole 悬停提示 QString
Qt::TextAlignmentRole 对齐方式 int（Qt::Alignment）
Qt::CheckStateRole 勾选状态 int
Qt::UserRole 起 你自己定义的 随便

Qt::UserRole 是分界线。往后的 Qt::UserRole + 1、Qt::UserRole + 2 都归你用，Qt 不碰。放自定义结构体就走这里。

装委托就一行：

cpp
ui->tableView->setItemDelegate(new BarDelegate(this));
// 只对某一列装
ui->tableView->setItemDelegateForColumn(1, new BarDelegate(this));

不设的话视图会自己 new 一个默认委托，绘制和 QLineEdit 编辑都能用，只是长得普通。setItemDelegate 只影响这个视图，不动模型。

需要自定义外观的理由就两类：默认画法表达不了你的数据（进度、色块、星标、图表），默认编辑器收不了你的输入（限定范围、只能选不能填）。这两件事都在委托里做，跟模型无关。模型该干的是存取，不该操心一个格子长什么样。

二、QItemDelegate 与 QStyledItemDelegate #

Qt 里有两个委托基类，长得很像，脾气不同。

对比项 QItemDelegate QStyledItemDelegate
出身 Qt 4.0，早期模型/视图的初版委托 Qt 4.4，为样式系统重写
绘制来源 自己手写 drawDisplay、drawFocus、drawCheck 交给 QStyle::drawControl(CE_ItemViewItem)
是否受 QSS 影响 基本不受 受，QTableView::item 之类选择器生效
是否跟随主题 不跟随，深色主题下容易白底黑字 跟随系统主题、平台风格
默认编辑器 走 QItemEditorFactory 同样走工厂，另加样式适配
现状 保留兼容，新代码不建议用 推荐基类

结论很直接：新代码继承 QStyledItemDelegate。QItemDelegate 是老的，源码里还在，用它写出来的表格在 Windows 深色模式、macOS 上会和周围控件脱节，QSS 写了也不生效。

两者能被重写的位置一致，就五个：

重写点 干什么 什么时候必须动
paint() 画这个格子 默认画法不够用
sizeHint() 报这个格子要多宽多高 行高被内容挤扁或撑爆
createEditor() 造一个编辑控件 默认编辑器不匹配输入
setEditorData() / setModelData() 编辑器与模型之间搬值 自定义编辑器时的配套
updateEditorGeometry() 摆编辑器位置 自定义编辑器时的配套

前两个管显示，后三个管编辑。显示侧的两个函数互相独立，你可以只重写 paint；编辑侧的三个基本绑在一起，改了 createEditor 就得跟着改另外两个，updateEditorGeometry 落下了编辑器会缩在左上角。

继承后记得带上基类名做初始化：

cpp
#include <QStyledItemDelegate>

class BarDelegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    explicit BarDelegate(QObject *parent = nullptr);

    void paint(QPainter *painter, const QStyleOptionViewItem &option,
               const QModelIndex &index) const override;
    QSize sizeHint(const QStyleOptionViewItem &option,
                   const QModelIndex &index) const override;

    QWidget *createEditor(QWidget *parent, const QStyleOptionViewItem &option,
                          const QModelIndex &index) const override;
    void setEditorData(QWidget *editor, const QModelIndex &index) const override;
    void setModelData(QWidget *editor, QAbstractItemModel *model,
                      const QModelIndex &index) const override;
    void updateEditorGeometry(QWidget *editor,
                              const QStyleOptionViewItem &option,
                              const QModelIndex &index) const override;
};

Q_OBJECT 别省。委托本身不发射信号也能跑，但一旦要用 qobject_cast、或者在里面写 tr()、或者挂到信号槽上，缺了它链接期就报错。

三、重写 paint：自定义绘制 #

paint 的签名固定，参数就三样：画笔、样式选项、索引。option.rect 是这块格子的矩形，坐标系已经切到视口，直接画。

思路分两种：

  • 完全自绘：不管默认外观，从背景到文字全自己来。
  • 半自绘：先让基类把背景、选中高亮、焦点框画掉，再叠上自己的内容。

第二种更省事，样式一致性也更好。写一个把整数画成进度条的委托：

cpp
void BarDelegate::paint(QPainter *painter,
                        const QStyleOptionViewItem &option,
                        const QModelIndex &index) const
{
    // 只处理第 1 列，其余原样交给基类
    if (index.column() != 1) {
        QStyledItemDelegate::paint(painter, option, index);
        return;
    }

    int value = index.data(Qt::DisplayRole).toInt();
    value = qBound(0, value, 100);

    painter->save();

    // 先画背景、选中态、焦点框，但把文字清掉，免得和自己的数字重叠
    QStyleOptionViewItem opt(option);
    initStyleOption(&opt, index);
    opt.text.clear();
    QStyledItemDelegate::paint(painter, opt, index);

    QRect r = option.rect.adjusted(4, 4, -4, -4);
    int w = r.width() * value / 100;

    painter->setRenderHint(QPainter::Antialiasing, true);

    // 底槽
    painter->setPen(Qt::NoPen);
    painter->setBrush(QColor(0xe6, 0xe6, 0xe6));
    painter->drawRoundedRect(r, 3, 3);

    // 进度
    painter->setBrush(QColor(0x2f, 0x81, 0xf7));
    painter->drawRoundedRect(QRect(r.left(), r.top(), w, r.height()), 3, 3);

    // 数字
    painter->setPen(QColor(0x22, 0x22, 0x22));
    painter->drawText(r, Qt::AlignCenter, QString::number(value) + QLatin1Char('%'));

    painter->restore();
}

几个必须守的习惯：

  • save() / restore() 成对出现。QPainter 的笔、刷、字体、裁剪区都是状态，你在格子里改了不还原，下一个格子跟着遭殃，现象是滚动时颜色乱跳。
  • initStyleOption(&opt, index) 会把模型的 Display、Decoration、CheckState、字体、对齐、背景刷全部灌进 opt。不调这一句，opt.text、opt.icon 都是空的，选中背景也画不出来。
  • 选中态要自己判：if (option.state & QStyle::State_Selected)，选了之后颜色反白，深色进度条压在深色背景上就看不清了。
  • 画文本用 option.font 或者 painter->setFont(opt.font)，别用默认字体，字号会和其他格子不一样。

要画色块给别人看，比进度条还短：QColor c = index.data(Qt::UserRole + 1).value<QColor>();，isValid() 过了就 fillRect(option.rect, c)，前后照样 save() / restore()。

这里取值用的是 value<QColor>() 而不是 toInt()。QVariant 里装的是 QColor 就得按 QColor 取，取错类型拿回默认构造值，颜色变成全黑，还不报错。这条坑在后半篇还会碰见。

四、重写 sizeHint：自定义尺寸 #

sizeHint 返回 QSize，视图靠它算行高、列宽。默认实现会去量文字宽度和图标尺寸，量出来是什么就用什么。

出问题的地方在这里：默认实现只认 Qt::DisplayRole 里的文字。你把值画成了进度条，文字被清空了，默认高度就会缩成一行紧贴，格子挤得难看；反过来文字超长，行高又会被撑开。

覆盖它，给个下限：

cpp
QSize BarDelegate::sizeHint(const QStyleOptionViewItem &option,
                            const QModelIndex &index) const
{
    QSize s = QStyledItemDelegate::sizeHint(option, index);

    if (index.column() == 1) {
        s.setHeight(qMax(s.height(), 28));   // 进度条至少 28 高
        s.setWidth(qMax(s.width(), 160));    // 至少 160 宽
    }
    if (index.column() == 0) {
        s.setHeight(qMax(s.height(), 28));
    }
    return s;
}

先调基类再修，不要凭空造一个 QSize(160, 28) 返回。凭空造会让长文本被裁、图标被压，字体换了也不知道跟着变。

行高统一还有更省事的做法，不写委托也能办到：

cpp
ui->tableView->verticalHeader()->setDefaultSectionSize(32);
ui->tableView->verticalHeader()->setSectionResizeMode(QHeaderView::Fixed);

固定行高适合数据齐整的表格，省掉每行都算一遍的开销。有长文本要换行时才需要 sizeHint 动态算，并且记得打开 setWordWrap(true)。

sizeHint 被调用得非常频繁，里面不要做数据库查询、不要 new 对象、不要拼大字符串。它只该读 index.data() 然后算几个数。真算不动就缓存，用 QHash<QModelIndex, QSize> 或者干脆按列定死。

五、重写 createEditor：自定义编辑器 #

编辑这一侧是三个函数联动，缺一个就残。

先说 createEditor。它的活是「按这个 index 造一个控件，父对象设成传入的 parent，然后返回」。视图把它贴到格子位置上，用户改完值，视图再回调 setModelData 把值写回模型。

默认实现走 QItemEditorFactory，按 QVariant 的实际类型挑控件：

模型返回的类型 默认编辑器
int QSpinBox
double / float QDoubleSpinBox
QString / QByteArray QLineEdit
bool QComboBox（真/假）
QDate QDateEdit
QTime QTimeEdit
QDateTime QDateTimeEdit
枚举（已注册） QComboBox

这张表有个前提：模型的 data(index, Qt::EditRole) 返回的类型要对。你的模型返回 QString，用户就得手打数字，因为工厂只看见字符串。

所以先问一句：默认编辑器够不够用？够用就别写委托。范围限制、只能选、带校验这几类需求，才需要动手。

老教程里的例子是给表格加一个 0 到 100 的 QSpinBox 编辑器。这个例子完整跑得起来，我们按现在的写法重排一遍。

头文件照第二节那个 BarDelegate 抄，重写点换成编辑侧四个函数：

cpp
#include <QStyledItemDelegate>

class Delegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    explicit Delegate(QObject *parent = nullptr);
    QWidget *createEditor(QWidget *parent, const QStyleOptionViewItem &option,
                          const QModelIndex &index) const override;
    void setEditorData(QWidget *editor, const QModelIndex &index) const override;
    void setModelData(QWidget *editor, QAbstractItemModel *model,
                      const QModelIndex &index) const override;
    void updateEditorGeometry(QWidget *editor,
                              const QStyleOptionViewItem &option,
                              const QModelIndex &index) const override;
};

实现：

cpp
#include "delegate.h"
#include <QSpinBox>

Delegate::Delegate(QObject *parent)
    : QStyledItemDelegate(parent)
{
}

// 造编辑器：QSpinBox，限定 0~100
QWidget *Delegate::createEditor(QWidget *parent,
                                const QStyleOptionViewItem &option,
                                const QModelIndex &index) const
{
    QSpinBox *editor = new QSpinBox(parent);
    editor->setFrame(false);          // 去掉边框，和格子贴合
    editor->setMinimum(0);
    editor->setMaximum(100);
    return editor;
}

// 模型 -> 编辑器：打开编辑器时调用一次
void Delegate::setEditorData(QWidget *editor, const QModelIndex &index) const
{
    int value = index.model()->data(index, Qt::EditRole).toInt();
    QSpinBox *spinBox = static_cast<QSpinBox *>(editor);
    spinBox->setValue(value);
}

// 编辑器 -> 模型：编辑结束时调用
void Delegate::setModelData(QWidget *editor, QAbstractItemModel *model,
                            const QModelIndex &index) const
{
    QSpinBox *spinBox = static_cast<QSpinBox *>(editor);
    spinBox->interpretText();          // 把还在输入框里的文本落实成数值
    model->setData(index, spinBox->value(), Qt::EditRole);
}

// 摆位置：把编辑器铺满格子
void Delegate::updateEditorGeometry(QWidget *editor,
                                    const QStyleOptionViewItem &option,
                                    const QModelIndex &index) const
{
    editor->setGeometry(option.rect);
}

interpretText() 那一句看着多余，实际是必要的。用户在 QSpinBox 里敲了 55 但还没按回车、焦点还在行编辑框里，value() 拿到的是上一次的值。interpretText() 先把文本解释成数值，再取就对了。不写这一句的典型现象：最后一格改的数字丢了。

现在把表格搭起来。用 QStandardItemModel 当模型，4 行 2 列，初始值全填 0：

cpp
#include "dialog.h"
#include "ui_dialog.h"
#include <QStandardItemModel>

Dialog::Dialog(QWidget *parent)
    : QDialog(parent)
    , ui(new Ui::Dialog)
{
    ui->setupUi(this);

    model = new QStandardItemModel(4, 2, this);

    // 往模型里填原始数据，初始值都是 0
    for (int row = 0; row != 4; ++row) {
        for (int col = 0; col != 2; ++col) {
            QModelIndex index = model->index(row, col, QModelIndex());
            model->setData(index, 0, Qt::EditRole);
        }
    }

    ui->tableView->setModel(model);
    // 不设这一句就用视图自带的默认委托
    ui->tableView->setItemDelegate(new Delegate(this));
}

Dialog::~Dialog()
{
    delete ui;
}

QStandardItemModel 是现成能用的模型，一格一个 QStandardItem，值还是 QVariant。index(row, col, QModelIndex()) 的第三个参数是父索引，顶层写 QModelIndex()（无效索引）。

换成 QComboBox 编辑器，createEditor 和 setModelData 这样写：

cpp
QWidget *Delegate::createEditor(QWidget *parent,
                                const QStyleOptionViewItem &option,
                                const QModelIndex &index) const
{
    QComboBox *editor = new QComboBox(parent);
    editor->addItem(QStringLiteral("低"), 0);
    editor->addItem(QStringLiteral("高"), 2);
    return editor;
}

void Delegate::setModelData(QWidget *editor, QAbstractItemModel *model,
                            const QModelIndex &index) const
{
    QComboBox *box = static_cast<QComboBox *>(editor);
    model->setData(index, box->currentData().toInt(), Qt::EditRole);
}

setEditorData 里一句话就行：box->setCurrentIndex(box->findData(value));。按 userData 找回索引，比按文本找字符串稳。currentData() 取的就是 addItem 第二个参数塞进去的 QVariant。

谁在推动这些回调？视图。用户双击格子，视图调 createEditor，调 setEditorData 填值，调 updateEditorGeometry 定位；用户回车或点别处，编辑器发出 commitData(QWidget*)，视图接住去调 setModelData，然后编辑器发 closeEditor 收摊。这一串视图已经写好了，你只要保证三个函数各自正确，不用自己连信号。

自己写了 createEditor 又不写 setModelData 会怎样：值改了，模型里一点变化没有，界面回滚成旧值。看着像缓存问题，其实是你没把值写回去。

六、QVariant：万能类型容器 #

QVariant 干的事很朴素：装一个值，顺便记住这个值是什么类型。取的时候能原样取回，也能按需转成别的类型。

官方文档的措辞是「像 Qt 里大多数常用数据类型的联合体」。比 C 的 union 多两件事：一是知道当前装的是谁，二是能对常见类型自动转换。C 的 union 你取错成员就是读出乱码，QVariant 取错类型最多拿个默认值。

先看基本形态：

cpp
QVariant v;                          // 无效值，isValid() 为 false
v = 42;                              // 装 int
v = QStringLiteral("hello");         // 换成 QString
v = QDate(2024, 5, 1);               // 换成 QDate

赋值就是换内容，类型标签跟着换，不残留旧值。

几个要认识的状态：

方法 含义
isValid() 装没装东西。默认构造的返回 false
isNull() 装的东西本身是不是空（空 QString、空指针、0 值）
typeName() 当前类型名，如 "int"、"QString"（Qt6 用 typeId()）
userType() 当前类型的整型 id
clear() 清成无效状态

isValid() 和 isNull() 不是一回事。QVariant(QString()) 是 valid 且 null：它确实装了个 QString，只是这个字符串是空的。QVariant() 是 invalid，连装了什么都说不出来。

跑一个最小例子，就是老教程里那个 main：

cpp
#include <QCoreApplication>
#include <QDebug>
#include <QVariant>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    QVariant vi = 42;
    QVariant vs = QStringLiteral("hello");
    QVariant vbad;                       // 无效

    // 直接打印，QVariant 对 QDebug 有重载
    qDebug() << vi << vs << vbad;        // 42 "hello" QVariant(Invalid)
    qDebug() << vi.typeName();           // "int"
    qDebug() << vi.toInt() + 1;          // 43
    qDebug() << vs.canConvert<int>();    // false
    qDebug() << vs.toInt();              // 0

    return 0;
}

qDebug() << v 能直接打，是因为 Qt 给 QVariant 写了 operator<<。调试模型返回什么类型时，把 index.data() 直接打出来最快，别猜。

QVariant 内部对能存的数据做隐式共享（QString、QImage 这类本身就是隐式共享的），拷贝一个 QVariant 不会复制底层大块内存。往容器里塞几千个 QVariant 不用太心疼。

七、QVariant 能装什么 #

内置类型覆盖得很宽，按用途分组：

分组 类型
整数 int、uint、short、ushort、long、ulong、qlonglong、qulonglong、char、signed char、uchar
浮点与布尔 float、double、bool、qreal
字符与字符串 QChar、QString、QByteArray、QStringList、QBitArray
日期时间 QDate、QTime、QDateTime
几何 QPoint、QPointF、QSize、QSizeF、QRect、QRectF、QLine、QLineF、QPolygon、QPolygonF、QRegion、QMatrix、QTransform
绘图与外观 QColor、QBrush、QPen、QFont、QPalette、QImage、QPixmap、QBitmap、QIcon、QCursor、QKeySequence
容器 QVariantList、QVariantMap、QVariantHash
其他常用 QUrl、QUuid、QLocale、QRegularExpression、QJsonValue、QJsonObject、QJsonArray、QJsonDocument
指针 QObject * 及派生类指针
自定义 用 Q_DECLARE_METATYPE 声明过的任意类型

三条边界要记住：

  • 裸数组进不去。int arr[10] 不行，包成 QList<int> 或者 std::vector 再说。
  • 引用进不去。存进去的是拷贝，改 QVariant 里的值不影响外面那个对象。
  • 指针能进，但 QVariant 不管所有权。装了个 new 出来的对象，QVariant 析构时不会 delete 它，内存还得你自己收。

QVariantList 就是 QList<QVariant>，QVariantMap 就是 QMap<QString, QVariant>。这两个能嵌套，于是能拼出树形结构：

cpp
QVariantMap person;
person["name"]  = QStringLiteral("张三");
person["age"]   = 30;

QVariantList people;
people << person;
QVariant root(people);      // 能一路套下去

这套结构和 JSON 一一对应。Qt 5 的 QJsonObject、QJsonArray 能直接和 QVariantMap、QVariantList 互转（QJsonObject::toVariantMap()、QJsonArray::toVariantList()），收发配置、读写缓存都用这条路径。

八、QVariant 的读写与转换 #

写进去三种写法都行：QVariant v1 = 42; 走构造，v2 = QStringLiteral("abc"); 走赋值，v3.setValue(QDate(2024, 1, 1)); 走 setValue。效果一样。

读出来分两条路。第一条是 toXxx() 系列，做数值和字符串层面的转换：

写法 返回 失败时
toInt() int 0
toInt(&ok) int ok 置 false
toDouble(&ok) double 0.0，ok 为 false
toString() QString 空字符串
toBool() bool false
toDate() / toTime() / toDateTime() 对应类型 无效对象
toByteArray() QByteArray 空

带 bool *ok 的重载是唯一能知道成功与否的入口。数字解析必须用它：

cpp
QVariant v = QStringLiteral("abc");

bool ok = false;
int n = v.toInt(&ok);
// n == 0, ok == false

qDebug() << v.canConvert<int>();     // false，提前问一句也行

不带 ok 的写法，"abc" 和 "0" 结果一模一样，都是 0。配置文件里一个拼错的端口号，就这么被悄悄读成 0 了。

第二条路是模板取值，两个函数：

cpp
QVariant v = QColor(Qt::red);

QColor c1 = v.value<QColor>();          // QVariant::value<T>()
QColor c2 = qvariant_cast<QColor>(v);   // 全局函数

两者行为对照：

对比项 v.value<T>() qvariant_cast<T>(v)
归属 QVariant 的成员模板 全局函数模板
类型完全匹配 直接取回，零开销 直接取回，零开销
类型不匹配但可转 走 QMetaType 转换，成功则返回 同
转换失败 返回 T()，即默认构造值，静默 返回 T()，并在调试构建下打 warning
适用场合 已知类型，日常首选 模板代码里拿不到 QVariant 对象时

失败语义要拎清。v.value<MyStruct>() 里如果 v 装的是 QString，你拿到一个字段全空的 MyStruct，编译器不吭声，运行时不报错，界面上一片空白，你得回头一行行查。

qvariant_cast 失败会 warn，比静默好一点，但 release 构建下同样只是返回默认值，不能靠它兜底。

所以两条路都该先问 canConvert()：

cpp
QVariant v = index.data(Qt::UserRole + 1);

if (v.canConvert<Player>()) {
    Player p = v.value<Player>();
    // 用 p
} else {
    qWarning() << "UserRole + 1 不是 Player：" << v.typeName();
}

canConvert<T>() 是编译期取到类型 id 再问运行时的元类型系统。Qt 5.2 起也有 canConvert(int typeId)，需要动态判类型时用它。

还有一个原地转换的接口，成功返回 true，失败不改内容：

cpp
QVariant v = QStringLiteral("128");
bool ok = v.convert(QMetaType::Int);
// ok == true，此时 v 装的就是 int 128

QVariant bad = QStringLiteral("abc");
qDebug() << bad.convert(QMetaType::Int);   // false，bad 仍是 "abc"

convert() 会改自己，toInt() 不改。循环里反复读同一个值就别用 convert，改一次之后下次读到的类型变了，容易乱。

QVariant 之间比较用 ==，同类型才可靠。类型不同时它会去尝试数值层面的比较，QVariant(1) 和 QVariant("1") 的结果跟你直觉未必一致。要比就先把类型统一。

九、自定义类型进 QVariant #

内置类型够用是常态。真遇到自己的结构体——一条任务、一个坐标点、一份配置——QVariant 也能装，前提是走完三步。

拿一个任务结构体开刀：

cpp
struct Task
{
    QString title;
    int progress = 0;
    bool done = false;
};

它对元类型系统的要求：public 的默认构造函数、public 的拷贝构造函数、public 的析构函数。三条都不满足，编译期就过不去。上面这个结构体自动满足。

第一步声明，第二步注册：

cpp
Q_DECLARE_METATYPE(Task)             // 编译期：让 QVariant 认识这个类型
qRegisterMetaType<Task>("Task");     // 运行期：让元对象系统能按名字构造它

Q_DECLARE_METATYPE 把 Task 和它的类型 id 挂钩，让 QMetaType::type<Task>()、qvariant_cast<Task>、QVariant::fromValue 都能编译通过。它写在头文件里、struct Task 之后、全局作用域，别塞进类或命名空间（真要塞，得和 Task 同作用域）。声明一次就够，重复声明报重复定义。

qRegisterMetaType 是运行时动作，把类型注册进元对象系统，程序能在运行期按名字找到它并构造一份副本。放 main() 里，或者第一次用到之前的初始化函数里。

第三步，存取：

cpp
Task t;
t.title = QStringLiteral("写文档");
t.progress = 40;

QVariant v = QVariant::fromValue(t);        // 装进去
Task back = v.value<Task>();                // 取回来
qDebug() << back.title << back.progress;    // "写文档" 40

QVariant::fromValue() 是模板函数，能推类型就用它；setValue() 是成员的等价写法。取回一律 value<Task>()。

两步常被混。差别在用途：

步骤 写什么 何时生效 缺了会怎样
声明 Q_DECLARE_METATYPE(Task) 编译期 QVariant::fromValue 直接编译不过
注册 qRegisterMetaType<Task>("Task") 运行期 单线程直接连接能用；跨线程队列连接运行时报 Cannot queue arguments of type 'Task'

跨线程信号槽那一条是硬要求。connect(..., Qt::QueuedConnection) 时，参数要被打包进事件队列，Qt 得在运行期按名字构造一份副本。没注册就构造不出来，连接照样建立，发信号时才发现没反应，控制台留下一行 QObject::connect: Cannot queue arguments of type 'Task'。

单线程直接连接不走这条路，Task 能当参数传，值也能塞进 QVariant，一切正常。等到哪天把耗时的活挪到工作线程，坑才浮出来。所以写库代码时就把 qRegisterMetaType 一起写上，别等出事再补。

枚举也走同一套：

cpp
enum Priority { Low, Normal, High };
Q_DECLARE_METATYPE(Priority)

// 注册之后可以在 QVariant 里存，也能在属性系统里用
qRegisterMetaType<Priority>("Priority");

不声明 Q_DECLARE_METATYPE 的枚举，QVariant::fromValue(Priority::High) 编译不过，只能退化成 int 存进去。退化本身能跑，但 value<Priority>() 取回来就是默认值 0 了。

十、QVariant 在 Qt 里的用武之地 #

QVariant 不是给模型/视图专用的，它散在 Qt 各处。列几个真会碰上的：

场景 接口 说明
模型数据 data() / setData() 所有 role 的返回值都是 QVariant
配置持久化 QSettings::value() / setValue() 能存几乎所有内置类型
对象属性 setProperty() / property() 动态属性，QSS 里也能读到
信号槽参数 connect() 的队列连接 参数走元类型系统打包
反射调用 QMetaObject::invokeMethod 参数是 QGenericArgument，背后是 QVariant
列表控件 QComboBox::addItem(text, userData)、itemData() 每项挂一个附加值
树控件 QTreeWidgetItem::setData(column, role, value) 树版模型/视图的简化接口
动作附加数据 QAction::setData() / data() 一个动作挂一份业务数据
JSON 互转 QJsonObject::toVariantMap() 配置和网络报文都靠它

QSettings 值得单说。它读出来的东西永远是 QVariant，你以为存了 int 就取到 int，其实得自己转：

cpp
QSettings s("MyOrg", "MyApp");
s.setValue("window/width", 1024);
s.setValue("window/pos", QPoint(100, 100));

int w = s.value("window/width", 800).toInt();          // 默认值 800
QPoint p = s.value("window/pos", QPoint(0, 0)).toPoint();

value() 的第二个参数是缺省值。键不存在时返回它，别指望返回 0 或者空——返回的是无效 QVariant，toInt() 照样给 0，你分不清「存的是 0」和「压根没存」。

动态属性也很常用。给控件挂个标记，不用派生类：

cpp
button->setProperty("role", "danger");
button->setProperty("level", 3);

qDebug() << button->property("level").toInt();         // 3
qDebug() << button->property("nope").isValid();        // false

QSS 里能直接选中它：QPushButton[role="danger"] { color: white; }。改完属性记得让样式重新算一遍：style()->unpolish(w); style()->polish(w);，不然界面不刷新。

列表控件挂附加值，是省掉平行数组的老办法：combo->addItem(QStringLiteral("北京"), 0x10); 之后用 combo->currentData().toInt() 取回那个 0x10。

这些地方的共同点是：接口不知道你会塞什么，所以统一用 QVariant 收。代价是取的时候必须自己保证类型对得上。

十一、两者怎么配合 #

前面分开讲了。合起来看，一条数据从模型走到屏幕，路是这样：

text
模型 data(index, Qt::UserRole + 1)
    └─> QVariant（里面装着 Task）
            │
            ▼
    委托 paint(painter, option, index)
            ├─ canConvert<Task>() 为假 → 走基类默认画法
            └─ 为真 → value<Task>() 取出结构体，按 title / progress 画

QVariant 是运输工具，委托是消费方。模型只管把值塞进 QVariant 交出去，不关心谁来取、取走去干什么；委托只管从 QVariant 取，不关心这个值存在哪里。两边唯一的约定就是角色名和类型。

写一个把 Task 画成「标题 + 进度条」的委托：

cpp
class TaskDelegate : public QStyledItemDelegate
{
public:
    explicit TaskDelegate(QObject *parent = nullptr)
        : QStyledItemDelegate(parent) {}

    void paint(QPainter *painter, const QStyleOptionViewItem &option,
               const QModelIndex &index) const override
    {
        QVariant raw = index.data(Qt::UserRole + 1);
        if (!raw.canConvert<Task>()) {
            QStyledItemDelegate::paint(painter, option, index);
            return;
        }
        Task t = raw.value<Task>();

        painter->save();

        QStyleOptionViewItem opt(option);
        initStyleOption(&opt, index);
        opt.text.clear();
        QStyledItemDelegate::paint(painter, opt, index);

        QRect r = opt.rect.adjusted(6, 4, -6, -4);

        // 标题
        painter->setPen(t.done ? QColor(0x88, 0x88, 0x88)
                               : opt.palette.color(QPalette::Text));
        painter->drawText(QRect(r.left(), r.top(), r.width(), 18),
                          Qt::AlignLeft | Qt::AlignVCenter, t.title);

        // 底槽
        QRect bar(r.left(), r.top() + 20, r.width(), 6);
        painter->setPen(Qt::NoPen);
        painter->setBrush(QColor(0xe0, 0xe0, 0xe0));
        painter->drawRoundedRect(bar, 3, 3);

        // 进度
        painter->setBrush(t.done ? QColor(0x34, 0xa8, 0x53)
                                 : QColor(0x2f, 0x81, 0xf7));
        painter->drawRoundedRect(
            QRect(bar.left(), bar.top(), bar.width() * t.progress / 100, 6), 3, 3);

        painter->restore();
    }

    // sizeHint 按第四节的办法给个 40 的下限，这里不重复
};

模型侧只需要两件事：data() 在 Qt::UserRole + 1 上返回 QVariant::fromValue(task)，setData() 接住编辑结果写回去。

cpp
QVariant TaskModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid() || index.row() >= m_tasks.size())
        return QVariant();

    const Task &t = m_tasks.at(index.row());

    if (role == Qt::DisplayRole)
        return t.title;                       // 显示文本还是给基类用
    if (role == Qt::UserRole + 1)
        return QVariant::fromValue(t);        // 整条结构体给委托

    return QVariant();
}

Qt::DisplayRole 那条别省。基类 paint 要用它算默认尺寸，QSortFilterProxyModel 排序过滤也认它，树形展开的搜索框同样靠它。哪怕委托里把文字清空了，模型这一份还得留着。

职责分清楚：

谁 管什么 不该碰什么
模型 存数据、按 role 返回 QVariant 字体、颜色、行高
视图 布局、滚动、选中、键盘鼠标 单个格子怎么画
委托 画格子、造编辑器、搬值 数据怎么存、存在哪

三方守住这条线，换个皮肤只改委托，换套存储只改模型，加个代理只插一层，互不牵连。混在一起写的表格也能跑，改一次全得重读。

十二、易错点速查 #

现象 原因 改法
表格和周围控件风格不搭，QSS 不生效 继承了 QItemDelegate 换 QStyledItemDelegate
格子内容画出来了，但选中背景丢了 paint 里没调基类 先 QStyledItemDelegate::paint，再叠自绘
滚动时颜色乱跳、字体突变 paint 里改了 QPainter 状态没还原 save() / restore() 成对
自绘格子高度贴得死紧 sizeHint 没给下限 调基类后 qMax 一下
编辑器缩在格子左上角一小块 没重写 updateEditorGeometry editor->setGeometry(option.rect)
最后一格改的值没写进模型 setModelData 里少了 interpretText() 取值前先 interpretText()
双击能编辑，改完又变回旧值 setModelData 没调 model->setData 补上，role 用 Qt::EditRole
编辑器在格子上留残影 createEditor 返回的控件没设父对象 new QSpinBox(parent)
v.value<T>() 拿到一堆空字段 类型不匹配，静默返回默认构造值 先 canConvert<T>()
fromValue(task) 编译报错 漏了 Q_DECLARE_METATYPE(Task) 头文件里补声明
跨线程发信号没反应，控制台报 Cannot queue arguments 漏了 qRegisterMetaType<Task>() main() 里补注册
toInt() 把 "abc" 读成 0，查不出错 没用带 ok 的重载 toInt(&ok) 加判断
配置里存了 0，取出来分不清是没存还是真 0 键不存在时返回无效 QVariant value() 带缺省值，或先 contains()
QVariant(1) == QVariant("1") 结果反直觉 跨类型比较会尝试数值转换 比较前统一类型
Qt 6 编译报 type() 弃用 Qt 6 改用 typeId() 返回 QMetaType 新代码直接用 typeId()

最后三条经验，写的时候顺手带上。

第一，模型里所有 data() 分支都要有 return QVariant(); 兜底。漏掉返回值是未定义行为，Release 下能返回随机值，界面上冒出乱码字符。

第二，委托里判断类型用 canConvert，别用 typeName() 比字符串。typeName() 在 Qt 5 和 Qt 6 返回值有差异，注册名会带上命名空间。

第三，QStyledItemDelegate 的 paint 里调基类时传的是你自己拼的 opt，不是原始 option。initStyleOption 填过的 opt 带了正确的文字和图标，基类靠它算背景和焦点框。传原始 option 也能跑，只是样式不会完全对。

委托和 QVariant 这两块，一个决定「长什么样」，一个决定「装什么」。把本节那个 TaskDelegate 加上 TaskModel 手敲一遍，模型/视图的门就算进了。
