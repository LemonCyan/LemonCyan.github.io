这篇讲 Qt 自己那套带 q 前缀的算法函数：qSort、qCopy、qFill、qFind，顺带把同批的 qCount、qEqual、qBinaryFind、qDeleteAll 一起过一遍，最后讲它们在 Qt 6 里的下场。

讲什么：每个函数怎么调、参数顺序怎么记、容器和迭代器怎么取、怎么传自定义比较、Qt 5 的代码搬到 Qt 6 怎么改。

不讲什么：排序和查找算法本身的原理。快排怎么分区、二分怎么折半，那是数据结构课的内容。这里只谈接口、返回值、以及会踩的坑。

跨篇指路：容器本身在《容器与遍历》里讲过，本篇默认你熟 QList / QVector / QStringList 的增删改查。模型视图与 QVariant、定时器与网络、文本流与 XML、绘图与动画、工程实践在后面几篇。

一、Qt 的泛型算法 #

Qt 4 时代，<QtAlgorithms> 这个头文件里塞了一批模板函数，全带 q 前缀。它们干的活和 <algorithm> 里的标准算法一样：给一对迭代器，对区间做排序、复制、填充、查找。入口就一行：

cpp
#include <QtAlgorithms>

把这批函数的家底列一下：

函数 干什么 参数形状
qSort 排序，不稳定 (begin, end[, lessThan]) 或 (container[, lessThan])
qStableSort 排序，稳定 同上
qCopy 正向复制 (srcBegin, srcEnd, dstBegin)
qCopyBackward 反向复制 (srcBegin, srcEnd, dstEnd)
qFill 填同一个值 (begin, end, value) 或 (container, value)
qFind 线性查找 (begin, end, value)
qBinaryFind 二分查找，要求已排序 (begin, end, value)
qLowerBound / qUpperBound 二分定位插入点 (begin, end, value)
qCount 数某个值出现几次 (begin, end, value)
qEqual 两段区间逐元素比 (begin1, end1, begin2)
qLess / qGreater 两个比较器仿函数 当 lessThan 参数用
qSwap 交换两个值 (a, b)
qDeleteAll 对指针容器逐个 delete (begin, end) 或 (container)

这批函数的本质，一句话说完：Qt 在标准算法外面包了一层薄壳。

拿 qFill 举例，Qt 5 源码里的实现就是转发：

cpp
template <typename ForwardIterator, typename T>
inline void qFill(ForwardIterator first, ForwardIterator last, const T &val)
{
    std::fill(first, last, val);
}

qSort 转发 std::sort，qCopy 转发 std::copy，qFind 转发 std::find。没有第二套实现，没有额外优化，就是把 std:: 换成 q，把 #include <algorithm> 省掉。

那当年为什么要包这一层？三个理由：

  1. 少一个 include。Qt 的教程习惯从一个 .cpp 讲起，能少写一行是一行。
  2. 风格统一。Qt 容器的成员函数是驼峰（append、removeAt），迭代器是 begin() / end()，q 前缀的函数看着就像容器 API 的延伸。
  3. Qt 4 的编译器环境。MSVC 6 / 2003 那批编译器对 STL 支持残缺，Qt 自己包一层能兜住。

第三条今天不成立，第一条也无所谓，第二条只是观感。所以这套函数在 Qt 5.15 全部标记废弃，在 Qt 6 全部删除。这句是整篇的纲，后面每一节都在给这句话补细节。

二、qSort：排序 #

三个重载，前两个吃迭代器，第三个直接吃容器：

cpp
template <typename RandomAccessIterator>
void qSort(RandomAccessIterator begin, RandomAccessIterator end);

template <typename RandomAccessIterator, typename LessThan>
void qSort(RandomAccessIterator begin, RandomAccessIterator end, LessThan lessThan);

template <typename Container>
void qSort(Container &container);

给容器时，内部取 container.begin() 和 container.end()，所以要求容器支持这两个成员。QList、QVector、QStringList、QVarLengthArray 都行，裸数组不行。

素材里的例子是把一堆整数排一遍：

cpp
// 问题描述：qSort 算法的例子
#include <QCoreApplication>
#include <QList>
#include <QDebug>
#include <QtAlgorithms>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // 新建一个 QList 对象
    QList<int> list;
    list << 3 << 1 << 2 << 0;

    // 不传比较器，qSort 按 operator< 比较，也就是升序
    qSort(list);

    // 遍历数据，并且输出数据
    foreach (int elem, list)
        qDebug() << elem;

    return a.exec();
}

输出四行：0 1 2 3。

关于这行代码，素材原稿的注释写的是「qSort 使用快速排序算法按照降序对数据进行排序」。这句有两个问题：

  • 方向反了。不传比较器时用的是 operator<，结果是升序。想要降序得显式传 qGreater<int>()。
  • 「快速排序」这个说法只对了一半。qSort 转发 std::sort，标准只承诺平均 O(n log n)，不承诺用哪种分区策略。introspective sort 是主流实现，不是纯快排。

同一件事的迭代器写法：

cpp
QList<int> list;
list << 3 << 1 << 2 << 0;

qSort(list.begin(), list.end());

两种写法等价，容器版就是帮你把 begin() / end() 敲了一遍。

稳定性。std::sort 不稳定，qSort 跟着不稳定。两个「相等」的元素排完谁在前，没有承诺。要稳定就换 qStableSort，它转发 std::stable_sort，代价是多一块临时内存，复杂度仍是 O(n log n)。

cpp
qStableSort(list.begin(), list.end(), lessThan);

初学阶段排序对象容器时，稳定性经常被忽略：排完发现同一分数的两个学生顺序变了，回来查半天，才发现是选了不稳定版本。

三、qCopy：复制 #

原型只有一个，返回值是目标区间写完之后的下一个位置：

cpp
template <typename InputIterator, typename OutputIterator>
OutputIterator qCopy(InputIterator begin, InputIterator end, OutputIterator dest);

参数顺序要背下来：先源区间的 begin / end，再目标的起点。目标只给一个参数，因为长度由源区间决定。返回值可以接着往后写，链式拼接就靠它：

cpp
out = qCopy(a.begin(), a.end(), out);
out = qCopy(b.begin(), b.end(), out);

素材里的例子是把 QStringList 的内容复制进 QVector<QString>：

cpp
// 问题描述：使用 qCopy 的一个例子
#include <QCoreApplication>
#include <QDebug>
#include <QVector>
#include <QStringList>
#include <QtAlgorithms>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // 往对象中添加元素
    QStringList list;
    list << "a" << "b" << "c";

    // QVector 提供一个动态数组，元素存在相邻的存储单元，支持基于索引的快速访问
    QVector<QString> vec(3);   // 3 个元素，每个都是默认构造出来的空串

    // 把 list 的三个元素复制到 vec 的头部
    qCopy(list.begin(), list.end(), vec.begin());

    // 遍历 vec 对象，并且输出其中的内容
    foreach (const QString &elem, vec)
        qDebug() << elem;

    return a.exec();
}

输出三行："a" "b" "c"。带引号是 QDebug 打印 QString 的固定格式，不是数据里真有引号。想输出裸字符串用 qDebug() << qPrintable(elem);。

素材注释里那句「新建一个对象，并指定其中有 3 个元素，但是这 3 个元素未初始化」——这句得纠一下。QVector<QString> 的 (int size) 构造会把每个元素默认构造出来，QString 的默认构造是空串，不是你读出来的野内存。对 QVector<int> 这类标量容器，元素是值初始化成 0，也不是随机值。所以「未初始化」这个描述不成立：在被你写之前读到的都是确定值。

真正需要记住的坑是这个：qCopy 不扩容。目标区间必须已经装得下。

cpp
QVector<QString> vec;                          // 空的
qCopy(list.begin(), list.end(), vec.begin());  // 越界写，未定义行为

QVector<QString> ok(list.size());              // 这样才对
qCopy(list.begin(), list.end(), ok.begin());

vec.begin() 对空容器等于 vec.end()，往这个位置写就是踩内存。Qt 不像 std::back_inserter 那样有插入迭代器可以自动扩容，qCopy 没有这层保护。

反向复制用 qCopyBackward，第三个参数是目标区间的尾后位置，从后往前写：

cpp
QVector<int> v;
v << 1 << 2 << 3 << 4 << 5 << 0 << 0;

// 把前 5 个元素整体右移两位，源和目标是同一块内存
qCopyBackward(v.begin(), v.begin() + 5, v.end());

// 结果：1 2 1 2 3 4 5

这种源与目标重叠、目标在右侧的场景，必须从后往前复制。换成 qCopy 就会从第一个开始覆盖，数据当场毁掉。重叠且目标在左侧，反过来用正向的 qCopy 才对，方向和重叠位置绑死。

四、qFill：填充 #

原型两个，容器版只是省了迭代器：

cpp
template <typename ForwardIterator, typename T>
void qFill(ForwardIterator begin, ForwardIterator end, const T &value);

template <typename Container, typename T>
void qFill(Container &container, const T &value);

素材里那个例子补全之后是这样：

cpp
// 问题描述：qFill 的一个例子
#include <QCoreApplication>
#include <QDebug>
#include <QVector>
#include <QtAlgorithms>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    // 新建一个 QVector 对象，5 个元素，内容都是空串
    QVector<QString> vec(5);

    // qFill 用固定数据填充指定的范围
    qFill(vec.begin(), vec.end(), QString("wayne"));

    // 遍历对象 vec 并且输出其中内容
    foreach (const QString &elem, vec)
        qDebug() << elem;

    return a.exec();
}

输出五行 "wayne"。

素材那句注释「新建一个 Qvector 对象，其容量大小为 5，其内容为空（blank）」也有偏差。QVector<QString> vec(5) 定的是元素个数，不是容量。size() 是 5，capacity() 往往更大。刚构造完时内容确实是空串，填完就变 wayne 了。

qFill 最要紧的一条：它不改容器大小。它只覆盖区间里已经存在的元素。

cpp
QVector<int> v;          // size() == 0
qFill(v.begin(), v.end(), 7);   // 什么也没干，区间是空的

v.resize(10);            // 先撑开
qFill(v.begin(), v.end(), -1);  // 现在 10 个 -1

只填一段也行，区间由你划：

cpp
QVector<int> v(10);
qFill(v.begin(), v.begin() + 3, 0);   // 前 3 个置 0，其余保持原值

容器版写法 qFill(v, -1) 等价于 qFill(v.begin(), v.end(), -1)，一次填完整个容器。这两个重载在 Qt 5 里都在，Qt 6 里都没了。

五、qFind：查找 #

原型一个，返回第一个等于 value 的位置，找不到返回 end：

cpp
template <typename InputIterator, typename T>
InputIterator qFind(InputIterator begin, InputIterator end, const T &value);

素材里的例子是残缺的，main 只写了一半，补全之后：

cpp
// 问题描述：qFind 算法的例子
#include <QCoreApplication>
#include <QList>
#include <QDebug>
#include <QtAlgorithms>

int main(int argc, char *argv[])
{
    QCoreApplication a(argc, argv);

    QList<int> list;                 // 新建 QList 容器的对象
    list << 10 << 20 << 30 << 40;

    // 查找对象中数据，返回对应迭代器；若不存在，则返回尾后迭代器（最后一个元素后面）
    QList<int>::iterator iter = qFind(list.begin(), list.end(), 30);

    // 输出对应查找结果的信息
    if (iter != list.end())
        qDebug() << "Found " << *iter;
    else
        qDebug() << "Not Found Number.";

    return a.exec();
}

输出 Found 30，注意中间两个空格，QDebug 会给自己插一个分隔符。

qFind 最要紧的是那个 if。返回尾后迭代器不能解引用，直接 *iter 就是未定义行为，轻则读到垃圾，重则段错误。这条判断漏掉，是新手在这类接口上翻车的第一名。

素材结尾有段评价，原文意思是「虽然查找也可以用循环实现，但用算法更简洁，形式上更整齐，而且效率更高」。前两句成立，最后一句不成立：qFind 内部就是 std::find，一个 for 从头扫到尾，复杂度 O(n)，和手写循环没有性能差别。它的价值是意图明确——读到 qFind(...) 就知道这里在找东西，不用先读三行循环体才反应过来。

再补一刀：qFind 只能找「等于某个值」，没有谓词版本。想找第一个满足条件的元素，它做不到：

cpp
// qFind 没有这种重载，编译不过
qFind(list.begin(), list.end(), [](int v) { return v > 25; });

这种场合只能手写循环，或者直接用 std::find_if。这是 q 版比 STL 版弱的地方之一，不需要绕。

qBinaryFind 是二分版，要求区间已经按同一个比较器排好序，O(log n)：

cpp
QList<int> list;
list << 5 << 1 << 9 << 3;
qSort(list);                                   // 必须先排，不然结果不可信

QList<int>::iterator it = qBinaryFind(list.begin(), list.end(), 3);
if (it != list.end())
    qDebug() << "Found " << *it;

返回的是「若干个相等元素里的某一个」，不保证是第一个。要拿第一个、或者要拿插入位置，用 qLowerBound / qUpperBound：

cpp
// 第一个不小于 3 的位置
QList<int>::iterator lo = qLowerBound(list.begin(), list.end(), 3);
// 第一个大于 3 的位置
QList<int>::iterator hi = qUpperBound(list.begin(), list.end(), 3);

// 3 重复了几次
int dup = hi - lo;

忘了先排序而直接二分，是最难查的一类 bug：数据少的时候照样能找到，数据一多就随机找不到。

六、qCount 与 qEqual 等其他函数 #

同一批函数里还有几个容易被忽略的，顺手一起记掉。

qCount：数某个值在区间里出现几次，返回 int。

cpp
template <typename InputIterator, typename T>
int qCount(InputIterator begin, InputIterator end, const T &value);

cpp
QList<int> list;
list << 1 << 2 << 2 << 3 << 2;
int n = qCount(list.begin(), list.end(), 2);   // n == 3

返回类型是 int 而不是 qsizetype，元素个数超过 20 亿的容器会溢出。这种规模现实中见不到，但把它拿去和 size_t 比较时会产生有符号 / 无符号混用的警告。

qEqual：两段区间逐元素比，只给第二个区间的起点，长度按第一个区间算。

cpp
template <typename InputIterator1, typename InputIterator2>
bool qEqual(InputIterator1 begin1, InputIterator1 end1, InputIterator2 begin2);

cpp
QList<int> a, b;
a << 1 << 2 << 3;
b << 1 << 2 << 3 << 4;

bool same = qEqual(a.begin(), a.end(), b.begin());   // true，只比前 3 个

第二个区间不够长就是越界读。qEqual 不信 end2，因为根本没这个参数。

qLess / qGreater：两个空壳仿函数，用途只有一个——给 qSort / qBinaryFind 传一个「反方向」。

cpp
template <typename T> struct qLess
{
    inline bool operator()(const T &t1, const T &t2) const
    { return t1 < t2; }
};

template <typename T> struct qGreater
{
    inline bool operator()(const T &t1, const T &t2) const
    { return t1 > t2; }
};

cpp
QList<int> list;
list << 3 << 1 << 2;
qSort(list.begin(), list.end(), qGreater<int>());   // 降序：3 2 1

qSwap：交换两个值。

cpp
int x = 1, y = 2;
qSwap(x, y);   // x == 2, y == 1

Qt 6 里这个职能由 std::swap 承担，新代码直接写 std::swap 就行，不用管 qSwap 在不在。

qDeleteAll：这是这批函数里唯一活到 Qt 6 的，值得单独说。

cpp
template <typename ForwardIterator>
void qDeleteAll(ForwardIterator begin, ForwardIterator end);

template <typename Container>
void qDeleteAll(const Container &c);

它遍历区间，对每个元素执行 delete。元素类型必须是指针，值语义的容器传进去编译不过。

cpp
QList<QWidget*> widgets;
widgets << new QLabel("a") << new QLabel("b");

qDeleteAll(widgets);   // 两个 QLabel 被 delete
widgets.clear();       // 容器里的指针还留着，必须清掉

第二个参数是本篇最该记的一条：qDeleteAll 只 delete，不清容器。删完容器里躺着一堆野指针，size() 一点没变，下次遍历就是踩雷。所以标准写法永远是两行：qDeleteAll(c); c.clear();。

它对 QHash / QMap 也适用，删的是 value。key 不是指针，不用管。

七、与 STL 算法的关系 #

把两套接口摆在一张表里，差异一眼看完：

用途 Qt 版 STL 版 头文件 差异
排序 qSort std::sort <algorithm> 完全等价，都不稳定
稳定排序 qStableSort std::stable_sort <algorithm> 完全等价
正向复制 qCopy std::copy <algorithm> 等价，都返回目标尾后位置
反向复制 qCopyBackward std::copy_backward <algorithm> 等价
填充 qFill std::fill <algorithm> 等价
线性查找 qFind std::find <algorithm> 等价，都返回迭代器
二分查找 qBinaryFind std::binary_search / std::lower_bound <algorithm> std::binary_search 只返回 bool
下界 qLowerBound std::lower_bound <algorithm> 等价
上界 qUpperBound std::upper_bound <algorithm> 等价
计数 qCount std::count <algorithm> std::count 返回 difference_type
区间相等 qEqual std::equal <algorithm> 等价
比较器 qLess / qGreater std::less / std::greater <functional> 等价
交换 qSwap std::swap <utility> 等价
删指针 qDeleteAll 无 <QtAlgorithms> Qt 独有，Qt 6 仍在

「完全等价」不是修辞。Qt 5 的实现就是一行转发，两套接口编译出来的机器码一样。性能上不存在「Qt 版更快」这回事，两边的优化等级取决于同一个标准库实现。

参数形状唯一的实质差异在容器重载上：qSort(list)、qFill(vec, 0) 这种吃整个容器的写法，STL 里没有对应物，必须自己展开成 std::sort(list.begin(), list.end())。

迭代器怎么取 #

Qt 容器的迭代器有两套取名法，用错了就是编译错误：

取法 非 const 容器 const 容器 备注
begin() / end() iterator 不可用 Qt 5 上会触发 detach
constBegin() / constEnd() const_iterator const_iterator Qt 风格
cbegin() / cend() const_iterator const_iterator STL 风格，C++11
rbegin() / rend() reverse_iterator — 反向遍历 
cpp
QList<int> list;
list << 3 << 1 << 2;

// Qt 风格：只读遍历用 constBegin / constEnd
for (QList<int>::const_iterator it = list.constBegin(); it != list.constEnd(); ++it)
    qDebug() << *it;

// STL 风格：cbegin / cend
for (auto it = list.cbegin(); it != list.cend(); ++it)
    qDebug() << *it;

// C++11 range-for，读起来最省事
for (int v : list)
    qDebug() << v;

有一个坑藏在 begin() 里。Qt 5 的 QList / QVector 是隐式共享（copy-on-write）的，在非 const 对象上调用 begin() 会触发 detach——为了让你能改元素，它先把共享的数据拷一份。遍历十万个元素的容器，如果写成 for (auto it = list.begin(); ...)，那一次 detach 就白拷了整个容器。

只读遍历一律用 constBegin() / cbegin()，或者在 const 引用上遍历，这条习惯能省掉一整类性能问题。

Qt 6 的变化：QList 和 QVector 合并，QVector 成了 QList 的别名，底层就是连续数组，迭代器直接就是 T*。constBegin() / constEnd() 还在，cbegin() / cend() 也在，两套都留着。也就是说 Qt 6 里 Qt 容器的迭代器天然满足 RandomAccessIterator，直接喂给 std::sort / std::copy 没有任何障碍，取不取 constBegin 只影响 const 正确性。

顺带一个调试技巧：QList / QVector / QStringList 都有 QDebug 的流操作符，一行就能看全内容，不用写循环：

cpp
QList<int> list;
list << 3 << 1 << 2;
qDebug() << list;   // 输出 (3, 1, 2)

八、自定义比较函数 #

qSort 的第三个参数是任意可调用对象，三种写法都能用。

一、内置仿函数，最省事，适合升序改降序：

cpp
QList<int> list;
list << 3 << 1 << 2 << 0;
qSort(list.begin(), list.end(), qGreater<int>());   // 3 2 1 0

二、普通函数指针，适合比较逻辑要在多处复用：

cpp
bool byAbs(int a, int b)
{
    return qAbs(a) < qAbs(b);
}

QList<int> list;
list << -5 << 3 << -1 << 4;
qSort(list.begin(), list.end(), byAbs);   // -1 3 4 -5

三、lambda，适合一次性逻辑，Qt 5 起可用（Qt 5 要求 C++11，所以 lambda 一直能写）：

cpp
struct Student
{
    QString name;
    int score;
};

QList<Student> students;
students << Student{"张三", 82} << Student{"李四", 91} << Student{"王五", 76};

qSort(students.begin(), students.end(),
      [](const Student &a, const Student &b) {
          return a.score > b.score;   // 分数从高到低
      });

三条硬规矩，违反了会出事：

  1. 必须是严格弱序。比较器里只能写 <，不能写 <=。写成 a.score <= b.score，std::sort 在元素相等时会越界访问，崩溃位置在标准库内部，堆栈看不出问题出在你的 lambda 上。
  2. 不能改元素。参数要传 const 引用，比较函数只回答「a 该不该排在 b 前面」，不动数据。
  3. 保持一致性。排序用的比较器和后面 qBinaryFind 用的比较器要同一个，升序排完拿降序规则去二分，结果随机。

指针容器是另一个独立坑。QList<Student*> 直接排，排的是指针地址：

cpp
QList<Student*> ptrs;
// ...
qSort(ptrs);   // 按地址排，和 score 一点关系都没有

// 必须显式给比较函数
qSort(ptrs.begin(), ptrs.end(),
      [](const Student *a, const Student *b) {
          return a->score > b->score;
      });

QList<QString> 这类存指针的容器（QString 内部是隐式共享的数据指针，但 operator< 已经按内容比了）不在此列。判断标准很简单：operator< 比的是不是你想要的东西。不是就传比较器。

九、Qt6 里这些函数去哪了 #

Qt 6 的 <QtAlgorithms> 里只剩 qDeleteAll 和几个位运算函数（qCountLeadingZeroBits、qCountTrailingZeroBits、qPopulationCount 系列）。排序、复制、填充、查找，全部消失。

Qt 5 的老代码原样扔进 Qt 6 编译，第一刀就卡在这里：

text
error: 'qSort' was not declared in this scope
error: 'qCopy' was not declared in this scope
error: 'qFill' was not declared in this scope
error: 'qFind' was not declared in this scope

不是链接错误，是编译错误——声明都没了。没有 #define 能把它救回来，也没有兼容头文件。

迁移对照表 #

这张表是本篇最实用的部分，照着改就行：

两处不严格等价，替换时手要停一下：

一是 qBinaryFind → std::lower_bound。两者返回的迭代器含义不同：qBinaryFind 返回「某个等于 value 的元素」的位置，找不到返回 end；std::lower_bound 返回「第一个不小于 value 的元素」的位置，不管 value 在不在。所以拿 lower_bound 判存在性要多写一步：

cpp
auto it = std::lower_bound(v.begin(), v.end(), value);
bool found = (it != v.end() && !(value < *it));

如果只想知道在不在，直接 std::binary_search(v.begin(), v.end(), value)，返回 bool，代码短一半。

二是容器版重载。qSort(c)、qFill(c, v)、qDeleteAll(c) 这种吃整个容器的形式，STL 一个都没有。std::sort 只有迭代器版，机械替换 qSort( 会得到 std::sort(c) 这样编译不过的东西，必须人工展开成 std::sort(c.begin(), c.end())。

迁移的做法 #

批量替换能覆盖大部分，但顺序有讲究：

  1. 先给文件加 #include <algorithm>，编译器不会因为你用了 std::sort 就自动引入。
  2. 全局替换 qSort( → std::sort(、qFind( → std::find(、qCopy( → std::copy(、qFill( → std::fill(。
  3. 编译一遍，把报「没有匹配的函数」的单参数调用逐个改成 begin() / end() 形式。
  4. 最后过一遍 qBinaryFind，按上面的差异手动改。

想在 Qt 5 阶段就把问题暴露完，编译前加一行宏，把废弃 API 直接变成错误：

cpp
#define QT_DISABLE_DEPRECATED_BEFORE 0x050F00   // 关掉 5.15 之前标废弃的全部接口

这样在 Qt 5.15 上编译老工程，凡是还在用 qSort 的地方当场报错，等于拿到一份完整的待迁移清单。提前跑一遍，比升级到 Qt 6 之后对着一屏 error 猜要省事得多。

十、该用 Qt 版还是 STL 版 #

结论先给：新代码一律用 STL，老代码别动。

场景 选谁 理由
新写 Qt 6 项目 std::* q 版已经不存在，没有选择余地
维护 Qt 4 / Qt 5 老工程 保持原样 能用就没必要制造 diff，迁移集中做一次
只想删掉指针容器里的对象 qDeleteAll Qt 独有，Qt 6 仍在，比自己写循环短
需要谓词查找 std::find_if qFind 没有谓词版
需要稳定排序 std::stable_sort 语义最直白
需要按多个字段排序 std::sort + lambda 两边都行，统一到 std 少一套心智
团队协作 全项目统一 std::* 一半 qSort 一半 std::sort 最费神

判断标准就一句：这个操作在 C++ 标准里有对应吗？有就用 std::，没有才考虑 Qt 那个。

按这条标准筛下来，能留下来的 Qt 专属算法只剩 qDeleteAll 一个。它没有标准对应物——标准库没有「对指针容器批量 delete」这种东西，std::for_each 配 lambda 能写但绕。

再说混用的代价。同一次提交里既有 qSort(list) 又有 std::sort(v.begin(), v.end())，读代码的人要在两套命名习惯之间来回切，还要额外判断「这里用 q 版是不是有什么特殊原因」。答案是没有，就是历史遗留。统一到 std::*，这类无谓的疑惑直接归零。

有一个反方向的诱惑要挡一下：不要因为「Qt 版名字更短」就留着它。qSort(list) 确实比 std::sort(list.begin(), list.end()) 短，但短的那部分在 Qt 6 里会变成编译错误，多敲的十几个字符是一次性成本。

十一、实际项目中的选择 #

几个真实场景，直接抄。

场景一：清空一个指针容器

cpp
QList<QWidget*> widgets;
widgets << new QLabel("a") << new QLabel("b") << new QLabel("c");

qDeleteAll(widgets);   // 逐个 delete
widgets.clear();       // 清掉指针，这行不能漏

Qt 6 里这段原样能编。要是容器里存的是值（QList<QLabel>），qDeleteAll 编译不过，也不需要——析构函数自己会收拾。

场景二：按结构体字段排序

cpp
struct FileItem
{
    QString name;
    qint64  size;
};

QVector<FileItem> items;
// ...

std::sort(items.begin(), items.end(),
          [](const FileItem &a, const FileItem &b) {
              if (a.size != b.size)
                  return a.size > b.size;    // 大的在前
              return a.name < b.name;        // 大小相同按名字
          });

多字段排序就是在这个 lambda 里加 if。别写成 return a.size > b.size && a.name < b.name;，那是错的——两个条件同时要求成立，几乎所有元素都会被判成「不小于」，排序结果跟没排一样。

场景三：找第一个满足条件的对象

cpp
auto it = std::find_if(devices.begin(), devices.end(),
                       [](const Device &d) { return d.port == 8080; });

if (it != devices.end())
{
    qDebug() << "found:" << it->name;
}

qFind 干不了这个，它只能比相等。

场景四：去重

cpp
QVector<int> v;
v << 3 << 1 << 2 << 3 << 1;

std::sort(v.begin(), v.end());                              // 先排，1 1 2 3 3
auto last = std::unique(v.begin(), v.end());                // 重复的挪到尾部，1 2 3 ? ?
v.erase(last, v.end());                                     // 截掉，1 2 3

std::unique 只把不重复的元素往前挪，返回新的逻辑尾部，容器长度没变，所以后面那行 erase 是必须的。这就是经典的 erase-remove 惯用法，q 版从来没有对应物。

QVector 有 erase(first, last) 这个重载，能这么写。Qt 5 的 QList 只有单参数的 erase(pos)，要循环删，或者干脆换成 QVector 再处理。Qt 6 里 QList 和 QVector 是同一个东西，两个重载都在。

场景五：只是想给字符串去重

cpp
QStringList list;
list << "a" << "b" << "a";
list.removeDuplicates();   // a b

QStringList 自带 removeDuplicates()，用不着算法。碰到这类需求先翻容器自己的成员函数，Qt 在容器层给的东西比算法层多。

场景六：给 QMap 的 value 排序

cpp
QMap<QString, int> map;
// ...

QList<int> values = map.values();
std::sort(values.begin(), values.end());

map.values() 返回一个独立的 QList，排它不影响 QMap 内部顺序。想按 value 反查 key，得自己建一个 pair 列表再排，QMap 本身永远按 key 有序。

场景七：Qt 5 老工程的增量迁移

做法是划边界，不做大爆炸式替换：新写的文件全部用 std::*，老文件保持原样；哪天要动某个老文件，顺手把它里面的 q 版函数换掉，一次换一个文件。加一个 CI 任务，用 grep -rn "qSort\\|qFill\\|qCopy\\|qFind" 统计剩余数量，只降不升。

十二、易错点速查 #

# 现象 原因 处理
1 编译报 'qSort' was not declared Qt 6 已删除该函数 换 std::sort
2 排完顺序没变 区间是空的，或者 begin() 来自另一个容器 检查 begin() / end() 是不是同一对象
3 排序时崩在标准库内部 比较器写了 <=，破坏严格弱序 比较器只写 <
4 排指针容器没按内容 operator< 比的是地址 传自定义比较函数
5 取 *it 崩了 qFind 没找到，返回尾后迭代器 先判 it != end()
6 qCopy 写崩或数据乱 目标区间没空间 先 resize 到源长度
7 qFill 之后 size() 没变 它只覆盖，不扩容 先 resize 再填
8 qBinaryFind 找不到确实存在的值 区间没排序 先排序，比较器保持一致
9 const 容器上调 begin() 编译失败 const 对象只有 constBegin() 用 constBegin() / cbegin()
10 遍历时代码莫名变慢 非 const begin() 触发 detach 只读遍历用 constBegin() / cbegin()
11 qCount 和 size_t 比较有警告 它返回 int，有符号 强转或改用 std::count
12 qDeleteAll 之后容器里还有东西 它只 delete，不清容器 后面补一句 clear()
13 Qt 6 里写 QVector 报废弃警告 它已是 QList 的别名 直接用 QList
14 foreach 突然编译不过 定义过 QT_NO_FOREACH 改用 for (const T &x : c)
15 删完元素后迭代器失效 改容器大小让迭代器全部作废 删元素用索引倒着走，或者先收集再删

最后一条值得单独展开，它是所有容器算法共有的坑。std::sort、std::copy、qFill 都会改动容器内容，之前拿到的迭代器全部作废，再解引用就是未定义行为。

cpp
// 错：边遍历边删，it 在 erase 之后失效
for (auto it = list.begin(); it != list.end(); ++it)
{
    if (*it < 0) list.erase(it);   // 下一轮 ++it 踩空
}

// 对：erase 返回被删元素的后一个位置，用它续上
for (auto it = list.begin(); it != list.end(); )
{
    if (*it < 0)
        it = list.erase(it);
    else
        ++it;
}

Qt 5 的 QList::erase 返回被删元素之后的迭代器，这个写法在 Qt 5 和 Qt 6 里都成立。

这批 q 前缀的函数到这儿就讲完了。回顾一遍主线：它们是标准算法的薄封装，存在的理由是省一个 #include 和统一命名风格；功能上一个都不缺替代品；Qt 6 已经全部删除，唯一活下来的是 qDeleteAll。你现在看到老代码里的 qSort，知道它在 Qt 6 里对应 std::sort，知道容器版重载要手动展开成 begin() / end()，这节就没白读。往后写新代码，<algorithm> 直接引入，不用再惦记 q 版。
