本文只讲树。讲 QTreeWidget 与 QTreeView 怎么分工、树怎么建、节点怎么增删改、展开折叠怎么控、三态勾选怎么联动、多列表头怎么配、图标与自定义显示怎么塞、自定义模型怎么把层级结构喂给视图、parent() 与 index() 怎么互相推导、节点多了怎么懒加载、右键菜单与拖拽怎么接。

不讲模型/视图架构里角色、信号、代理模型的完整拼图，那是同目录《QTableView 与模型/视图架构》的事；不讲委托的通用写法与编辑器工厂，那是同目录《委托》的事；不讲二维表格，那是同目录《QTableWidget》的事。代码默认 C++17 + Qt 5.15 / Qt 6。

全程咬住一条主线：给定一个 QModelIndex，你能立刻算出它的父是谁、在第几行、在第几列；反过来给父、行、列，你能造出正确的 index。这三者推错一处，树要么展不开，要么直接崩。

一、QTreeWidget 与 QTreeView 的分工 #

两个类名字像，定位完全不同，选错了后面全是返工。

QTreeWidget 是便利控件。节点数据由 QTreeWidgetItem 自带，new 一个 item 塞进去就是一行，不用写任何模型。树结构、列数、勾选、图标全挂在 item 自己身上。

QTreeView 是纯视图。自己不存数据，只负责画，数据来自你挂上去的模型。模型必须能回答两个问题：「这个节点有几个孩子」「这个孩子的父亲是谁」。数据在业务层、界面只是投影，或者节点数上万，选它。

维度 QTreeWidget QTreeView
数据存放 QTreeWidgetItem 自带 外部模型
节点类型 只能是 QTreeWidgetItem 任意，靠模型映射
上手成本 低，new 完就能用 高，要实现 6 个虚函数
上千节点 开始吃力 只画可见区，量大也不虚
数据界面分离 分离不了 天然分离
排序过滤 得自己撸 接 QSortFilterProxyModel
一数据挂多视图 做不到 一个模型挂几个视图都行
增删通知粒度 item 级 行区间级，可精确通知

判定口径三条：节点数不到一千、数据只给这一个控件用，选 QTreeWidget；数据已经在业务层活着一份、控件只是看一眼，选 QTreeView；要排序、要过滤、要拖到另一个视图，还是 QTreeView。

cpp
// QTreeWidget：三步建一棵树
QTreeWidget *tree = new QTreeWidget(this);
tree->setColumnCount(2);
tree->setHeaderLabels({QStringLiteral("名称"), QStringLiteral("说明")});
auto *root = new QTreeWidgetItem(tree, {QStringLiteral("设备"), QStringLiteral("根节点")});
new QTreeWidgetItem(root, {QStringLiteral("电机"), QStringLiteral("一号电机")});
new QTreeWidgetItem(root, {QStringLiteral("传感器"), QStringLiteral("温度")});
tree->expandAll();

// QTreeView：视图 + 模型两件套，树形关系交给模型
QTreeView *view = new QTreeView(this);
QStandardItemModel *model = new QStandardItemModel(this);
model->setHorizontalHeaderLabels({QStringLiteral("名称"), QStringLiteral("说明")});
auto *dev = new QStandardItem(QStringLiteral("设备"));
model->appendRow(dev);
dev->appendRow(new QStandardItem(QStringLiteral("电机")));
view->setModel(model);
view->expandAll();

两段行数差不多，差别在后面：加一个节点要去改业务数据时，QTreeWidget 得同时改 item 和业务对象，两边迟早不一致；QTreeView 只改业务对象，再发一次模型通知。树多十层、多几个页面共用一棵树，这个差别会变成事故。

二、用 QTreeWidget 建树 #

入口只有两个：addTopLevelItem() 加顶层，构造或 addChild() 加子节点。

cpp
// 顶层三种写法，选一种，别混着来
auto *a = new QTreeWidgetItem;                 // 一：先建后挂，适合先设属性再上树
a->setText(0, QStringLiteral("顶层 A"));
tree->addTopLevelItem(a);
auto *b = new QTreeWidgetItem(tree);           // 二：构造时指定父控件，等效 addTopLevelItem
b->setText(0, QStringLiteral("顶层 B"));
auto *c = new QTreeWidgetItem(tree, {QStringLiteral("顶层 C"), QStringLiteral("说明")});  // 三：最省事

// 子节点把父从 tree 换成父 item
auto *child = new QTreeWidgetItem(parentItem, {QStringLiteral("子节点"), QStringLiteral("二级")});
parentItem->addChild(new QTreeWidgetItem({QStringLiteral("子节点2")}));   // 追加到末尾
parentItem->insertChild(0, new QTreeWidgetItem({QStringLiteral("插到最前")}));

列数必须在塞数据之前定好。setColumnCount(3) 之后每个 item 才有 3 个格子，先在 2 列树上写好的 item 拿去 3 列的树，第 3 列就是空的。只给表头文本不给列数，QTreeWidget 会按文本数量补足；只给列数不给表头，列头就是空的。两个都写。

cpp
tree->setColumnCount(3);
tree->setHeaderLabels({QStringLiteral("名称"), QStringLiteral("类型"), QStringLiteral("备注")});

item->setText(0, QStringLiteral("水泵"));
item->setData(0, Qt::UserRole, 1001);                      // 挂业务主键
item->setTextAlignment(1, Qt::AlignRight | Qt::AlignVCenter);

Qt::UserRole 起往上都是你的地盘，挂 id、挂指针都行，取的时候 item->data(0, Qt::UserRole).toInt()。这是 QTreeWidget 唯一体面的「数据界面分离」替代品。Designer 里双击控件能直接编静态节点树，只能用于死数据，运行时还要增删就老老实实写代码。

三、节点的增删改 #

风险不在调用，在谁拥有这块内存。先记一条：QTreeWidget 拥有它下面所有 item，析构时递归删干净；但用 takeTopLevelItem() / takeChild() 摘出来的 item 由你负责。

cpp
// 增
tree->addTopLevelItem(new QTreeWidgetItem({QStringLiteral("新顶层")}));
tree->insertTopLevelItem(0, new QTreeWidgetItem({QStringLiteral("插队")}));
parentItem->insertChild(2, new QTreeWidgetItem({QStringLiteral("老三")}));

删要看清名字。removeChild() 会 delete 掉那个 item，takeChild() 只摘下来交给你，不 delete 就漏。

cpp
delete parentItem->takeChild(0);          // 摘下来顺手删
delete tree->takeTopLevelItem(0);         // 顶层同理，QTreeWidget 没有 removeTopLevelItem()
QTreeWidgetItem *orphan = parentItem->takeChild(1);
if (orphan) { delete orphan; orphan = nullptr; }

QTreeWidgetItem 析构时会 qDeleteAll(childItems)，所以删父节点等于删整棵子树，不用自己写递归：

cpp
qDeleteAll(parentItem->takeChildren());    // 只清子节点，保留父
while (tree->topLevelItemCount() > 0)      // 清全树但保留表头
    delete tree->takeTopLevelItem(0);

tree->clear() 连表头一起清，之后必须重新 setHeaderLabels()。

cpp
item->setText(0, QStringLiteral("改名后"));
item->setIcon(0, QIcon(":/icons/pump.png"));
item->setCheckState(0, Qt::Checked);
item->setFlags(item->flags() | Qt::ItemIsEditable);   // 允许双击编辑
item->setHidden(true);                                // 隐藏但仍在树里

一次改几千个 item，每个 setter 都触发重绘，界面会卡死。批量操作包一层：setUpdatesEnabled(false) … setUpdatesEnabled(true)。

上了模型就不是这套 API 了。增删必须走 beginInsertRows() / endInsertRows()、beginRemoveRows() / endRemoveRows()。直接动底层容器不发通知，视图缓存的行号全乱，症状是点错行或者崩溃。QStandardItemModel::removeRow(row, parentIndex) 内部已经成对调好，自定义模型得自己写，细节在第九章。

四、展开、折叠与遍历 #

展开状态属于视图，不属于数据。同一棵树换一个视图，展开状态要重新设。

cpp
view->setExpanded(index, true);
bool open = view->isExpanded(index);
view->expand(index);                  // 等价 setExpanded(index, true)
view->collapse(index);
view->expandAll();
view->collapseAll();
view->expandToDepth(1);               // QTreeView 才有：顶层全开，二级以下不动
view->expandRecursively(index, -1);   // Qt 5.13+，-1 表示不限深度

QTreeWidget 是 QTreeView 的子类，上面都能用，另外多一层 item 语义：expandItem(item)、collapseItem(item)、itemExpanded(item)。

信号分两套，视图侧发 QModelIndex，便利控件侧发 QTreeWidgetItem*：

cpp
connect(view, &QTreeView::expanded,  this, [](const QModelIndex &idx){ /* ... */ });
connect(view, &QTreeView::collapsed, this, [](const QModelIndex &idx){ /* ... */ });
connect(tree, &QTreeWidget::itemExpanded,  this, [](QTreeWidgetItem *it){ /* ... */ });
connect(tree, &QTreeWidget::itemCollapsed, this, [](QTreeWidgetItem *it){ /* ... */ });

两个信号都在子节点真正可见之后才发，里面读子节点数量是安全的。

两套世界要打通，全靠这两个函数：

cpp
QModelIndex idx = tree->indexFromItem(item);      // item -> index，默认第 0 列
QModelIndex idx2 = tree->indexFromItem(item, 2);  // 指定列
QTreeWidgetItem *it = tree->itemFromIndex(idx);   // index -> item，先判空

遍历用迭代器，带标志位能只走一类节点：

cpp
QTreeWidgetItemIterator it(tree);
while (*it) { qDebug() << (*it)->text(0); ++it; }

QTreeWidgetItemIterator picked(tree, QTreeWidgetItemIterator::Checked);
QTreeWidgetItemIterator leaves(tree, QTreeWidgetItemIterator::HasChildren);

标志还有 Selected、Hidden、NotChecked、NoChildren，能按位或组合。迭代过程中删节点会让迭代器失效，要删就先收集到 QList，循环结束统一删。

模型侧没有 item，只能靠 index 递归。这段是基本功，写熟了自定义模型就是反过来：

cpp
void dumpIndex(const QAbstractItemModel *model, const QModelIndex &parent, int depth)
{
    for (int r = 0; r < model->rowCount(parent); ++r) {
        const QModelIndex idx = model->index(r, 0, parent);
        qDebug().noquote() << QString(depth * 2, ' ') + idx.data(Qt::DisplayRole).toString();
        if (model->hasChildren(idx)) dumpIndex(model, idx, depth + 1);
    }
}
// 入口是无效 index：dumpIndex(model, QModelIndex(), 0);

无效 index 代表「虚根」，它的 rowCount() 就是顶层节点数。这个约定贯穿全文。

定位到某一行：tree->findItems(text, Qt::MatchContains | Qt::MatchRecursive, 0)，Qt::MatchRecursive 不能省，不加只搜顶层。按 Qt::UserRole 里的业务 id 找没有现成 API，自己写个递归，判断 data(0, Qt::UserRole).toInt() 后往 child(i) 走。找「下一个可见行」用 indexAbove() / indexBelow()，比 expandAll 加遍历快得多，它们只走已展开的部分。

五、勾选状态与三态 #

三态是 Qt::CheckState 的三个值：Qt::Unchecked、Qt::Checked、Qt::PartiallyChecked。第三个就是那个减号方块，父节点下一部分子被勾选时用它。

QTreeWidgetItem 的默认 flags 里已经带了 Qt::ItemIsUserCheckable，设了就能点：item->setCheckState(0, Qt::Checked)，读是 item->checkState(0)。勾在第几列就设第几列，一列只放一个勾。

有个自动开关 Qt::ItemIsAutoTristate，行为很粗：只在被勾的那个父节点自己参与时推状态，兄弟之间的传播不做，实际项目里不够用。多数情况还是手写联动。

规则定死：子全勾则父勾，子全不勾则父不勾，其余情况父半勾。挂在 itemChanged 上：

cpp
connect(tree, &QTreeWidget::itemChanged, this, [this](QTreeWidgetItem *item, int column) {
    if (column != 0) return;

    // 1. 向下：父被点，所有子跟着走
    const Qt::CheckState state = item->checkState(0);
    if (state != Qt::PartiallyChecked) {
        for (int i = 0; i < item->childCount(); ++i) {
            QSignalBlocker blocker(tree);          // 阻断回环，最关键的一行
            item->child(i)->setCheckState(0, state);
        }
    }

    // 2. 向上：父节点按子的统计结果重算
    for (QTreeWidgetItem *p = item->parent(); p; p = p->parent()) {
        int checked = 0, partial = 0;
        for (int i = 0; i < p->childCount(); ++i) {
            const Qt::CheckState cs = p->child(i)->checkState(0);
            if (cs == Qt::Checked) ++checked;
            else if (cs == Qt::PartiallyChecked) ++partial;
        }
        QSignalBlocker blocker(tree);
        if (checked == p->childCount() && partial == 0) p->setCheckState(0, Qt::Checked);
        else if (checked == 0 && partial == 0)          p->setCheckState(0, Qt::Unchecked);
        else                                            p->setCheckState(0, Qt::PartiallyChecked);
    }
});

QSignalBlocker 那一行不能省。setCheckState() 会再发一次 itemChanged，槽里又去改子节点，就是无限递归，最后栈溢出。用 blockSignals(true) / blockSignals(false) 配对写也行，但忘了复原就再也收不到信号；QSignalBlocker 靠作用域自动复原。向下传播的前提是先判 state != Qt::PartiallyChecked：用户点半选的父节点，语义是「全选」，这一句就是「点减号变全勾」。

子节点情况 父节点应为 说明
全部 Checked Checked 全选
全部 Unchecked Unchecked 全不选
有勾有不勾 PartiallyChecked 半选，画减号
有 PartiallyChecked PartiallyChecked 无论其余如何
没有子节点 保持自身 叶子不参与推导

收勾选结果用迭代器，只收叶子，避免父子上报重复：

cpp
QList<QTreeWidgetItem*> picked;
QTreeWidgetItemIterator it(tree, QTreeWidgetItemIterator::Checked | QTreeWidgetItemIterator::NoChildren);
while (*it) { picked << *it; ++it; }

模型侧没有 setCheckState()，勾选是角色数据：data() 回 Qt::CheckStateRole，setData() 接住写入，flags() 里带 Qt::ItemIsUserCheckable，少了点不动。

cpp
QVariant MyModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid()) return QVariant();
    if (role == Qt::CheckStateRole && index.column() == 0)
        return nodeOf(index)->checked ? Qt::Checked : Qt::Unchecked;
    if (role == Qt::DisplayRole) return nodeOf(index)->text;
    return QVariant();
}

bool MyModel::setData(const QModelIndex &index, const QVariant &value, int role)
{
    if (role != Qt::CheckStateRole || !index.isValid()) return false;
    nodeOf(index)->checked = (value.toInt() == Qt::Checked);
    emit dataChanged(index, index, {Qt::CheckStateRole});
    return true;
}

dataChanged 只发当前这一个 index，父子联动一样得在 setData() 里自己做，或者交给视图外面的控制器。

六、表头与多列树 #

多列树三件事：列数、列宽、第一列要不要跨列。

cpp
tree->setColumnCount(3);
tree->setHeaderLabels({QStringLiteral("名称"), QStringLiteral("类型"), QStringLiteral("备注")});
tree->headerItem()->setTextAlignment(1, Qt::AlignCenter);   // 表头 item 也能改样式

tree->setColumnWidth(0, 260);
tree->header()->setSectionResizeMode(0, QHeaderView::Interactive);
tree->header()->setSectionResizeMode(1, QHeaderView::ResizeToContents);
tree->header()->setSectionResizeMode(2, QHeaderView::Stretch);

ResizeToContents 按内容自适应，每次刷新都算全部宽度，大表上卡得明显；Stretch 吃掉剩余空间，最后一列用它最合适，不然右边总有一条空白。resizeColumnToContents(col) 是手动算一次，数据加载完调一下再交还 Interactive。

分组标题那种一行占满整宽的节点靠跨列：

cpp
tree->setFirstColumnSpanned(row, QModelIndex(), true);   // QTreeView：行号 + 父 index

const int row = tree->indexOfTopLevelItem(item);         // QTreeWidget：item 先换行号
if (row >= 0) tree->setFirstColumnSpanned(row, QModelIndex(), true);

跨列之后第 2、3 列不显示，别在跨列节点上放勾选框之外的操作控件，用户点不到。setColumnHidden(2, true) 只是不画，数据还在，text(2) 照样读得到；view->setHeaderHidden(true) 关掉表头，单列树基本都这么干。

QTreeWidget 自带排序：

cpp
tree->sortItems(0, Qt::AscendingOrder);      // 一次性

tree->setSortingEnabled(true);               // 点表头就排
tree->header()->setSortIndicator(0, Qt::AscendingOrder);

setSortingEnabled(true) 之后每次插入节点都会触发排序，插入过程中行号会变，indexOfTopLevelItem() 的结果不可信。批量插节点时先关掉，插完再打开并排一次。排序只在一层里生效，父子关系不会被重排打乱，这点和表格不同。纯 QTreeView 上没有 sortItems()，排序在模型或 QSortFilterProxyModel 里做。

所有行等高时开 view->setUniformRowHeights(true)，视图不用逐行量高度，大树上滚动明显顺。前提是行高真的统一，混了 setItemWidget() 塞的控件、或者多行文本，就别开。

七、图标与自定义显示 #

cpp
item->setIcon(0, QIcon(":/icons/folder.png"));
tree->setIconSize(QSize(18, 18));

setIconSize() 是统一缩放，源图尺寸不对会被拉花。资源放 qrc 里，路径写 :/ 开头。模型侧是 Qt::DecorationRole：

cpp
if (role == Qt::DecorationRole && index.column() == 0)
    return QIcon(nodeOf(index)->expanded ? ":/icons/open.png" : ":/icons/folder.png");

图标随展开状态变，收起或展开后要发一次 dataChanged() 让对应行重画。

文字颜色、字体、背景都能按单元格改，模型侧对应 Qt::ForegroundRole、Qt::BackgroundRole、Qt::FontRole：

cpp
item->setForeground(0, QBrush(Qt::red));
item->setBackground(1, QBrush(QColor(255, 245, 200)));
QFont f = item->font(0); f.setBold(true); item->setFont(0, f);

item->setToolTip(0, QStringLiteral("这是一台水泵"));    // 传空串就不弹气泡
item->setStatusTip(0, QStringLiteral("状态栏提示"));

QSS 里的 ::item 规则能盖住背景和颜色，两者冲突时以样式表为准。

下拉框、按钮这类东西塞进格子，QTreeWidget 用 setItemWidget()：

cpp
auto *combo = new QComboBox(tree);
combo->addItems({QStringLiteral("自动"), QStringLiteral("手动")});
tree->setItemWidget(item, 1, combo);

每一行都得 set 一个新的控件实例。同一个 QComboBox* 塞两行，第二行把第一行的位置抢走，第一行变空白，控件只响应最后一次挂载的那行。行被删掉时控件不跟着删，得自己清理。它还会让行高由控件尺寸撑开，setUniformRowHeights(true) 就不能开了。

行末自绘展开按钮 #

默认展开三角在最左、文字之前。要挪到行末、换成自己的图标、带手型光标和气泡提示，用委托。委托类持有视图指针，是为了能查 isExpanded()。

cpp
// ItemDelegate.h
#pragma once
#include <QStyledItemDelegate>
#include <QTreeView>

class ItemDelegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    explicit ItemDelegate(QObject *parent = nullptr);
    ~ItemDelegate() {}

    void setView(QTreeView *treeView);
    void setIconSize(QSize size);
    void setExpandIcon(const QString &expandIconName);
    void setCollapseIcon(const QString &collapseIconName);

    void paint(QPainter *painter,
               const QStyleOptionViewItem &option,
               const QModelIndex &index) const override;
    bool editorEvent(QEvent *event,
                     QAbstractItemModel *model,
                     const QStyleOptionViewItem &option,
                     const QModelIndex &index) override;

signals:
    void toggleExpanded(const QModelIndex &index);

private:
    QTreeView *m_treeView;
    int m_pixmapWidth;
    int m_pixmapHeight;
    QString m_expandIconName;
    QString m_collapseIconName;
};

cpp
// ItemDelegate.cpp
#include "ItemDelegate.h"
#include <QPainter>
#include <QMouseEvent>
#include <QApplication>
#include <QToolTip>

ItemDelegate::ItemDelegate(QObject *parent)
    : QStyledItemDelegate(parent), m_treeView(nullptr), m_pixmapWidth(9), m_pixmapHeight(9)
{
    m_expandIconName   = ":/Images/arrowBottom.png";
    m_collapseIconName = ":/Images/arrowTop.png";
}

void ItemDelegate::setView(QTreeView *treeView) { m_treeView = treeView; }
void ItemDelegate::setExpandIcon(const QString &name) { m_expandIconName = name; }
void ItemDelegate::setCollapseIcon(const QString &name) { m_collapseIconName = name; }
void ItemDelegate::setIconSize(QSize size)
{
    m_pixmapWidth = size.width();
    m_pixmapHeight = size.height();
}

// 1. 在行末画一个动作图标
void ItemDelegate::paint(QPainter *painter,
                         const QStyleOptionViewItem &option,
                         const QModelIndex &index) const
{
    QStyleOptionViewItem viewOption(option);
    // 去掉选中行那圈虚线焦点框
    if (viewOption.state & QStyle::State_HasFocus)
        viewOption.state = viewOption.state ^ QStyle::State_HasFocus;

    // 先让基类把文本、背景、高亮画完
    QStyledItemDelegate::paint(painter, viewOption, index);

    if (!m_treeView) return;
    const QAbstractItemModel *model = index.model();
    if (!model->hasChildren(index)) return;      // 叶子没有展开这回事

    const bool expanded = m_treeView->isExpanded(index);
    const int vOffset = (viewOption.rect.height() - m_pixmapHeight) / 2;
    QRect rect(viewOption.rect.left() + viewOption.rect.width() - 30,   // 行最右侧留 30 像素
               viewOption.rect.top() + vOffset, m_pixmapWidth, m_pixmapHeight);

    const QPixmap pixmap = expanded ? QPixmap(m_expandIconName) : QPixmap(m_collapseIconName);
    painter->drawPixmap(rect, pixmap);
}

// 2. 手型光标、ToolTip、点击切换
bool ItemDelegate::editorEvent(QEvent *event,
                               QAbstractItemModel *model,
                               const QStyleOptionViewItem &option,
                               const QModelIndex &index)
{
    if (!m_treeView || !model->hasChildren(index))
        return QStyledItemDelegate::editorEvent(event, model, option, index);

    const int vOffset = (option.rect.height() - m_pixmapHeight) / 2;    // 与 paint() 必须同算式
    QRect rect(option.rect.left() + option.rect.width() - 30,
               option.rect.top() + vOffset, m_pixmapWidth, m_pixmapHeight);

    auto *mouseEvent = static_cast<QMouseEvent*>(event);
    if (rect.contains(mouseEvent->pos())) {
        const bool expanded = m_treeView->isExpanded(index);
        if (event->type() == QEvent::MouseButtonPress) {
            emit toggleExpanded(index);
        } else if (event->type() == QEvent::MouseMove) {
            QApplication::setOverrideCursor(Qt::PointingHandCursor);
            QToolTip::showText(mouseEvent->globalPos(),
                               expanded ? QStringLiteral("折叠") : QStringLiteral("展开"));
        }
    } else {
        QApplication::restoreOverrideCursor();
    }
    return QStyledItemDelegate::editorEvent(event, model, option, index);
}

paint() 和 editorEvent() 里的矩形必须用同一套算式，差一个像素，鼠标点上去就没反应。要改偏移量就抽成私有函数，别在两处各写一遍。

九、自定义树模型：层级结构的实现 #

QStandardItemModel 的通病是每个节点都背着一整套 item 开销，几十万节点撑不住。要极限性能、要直接映射已有业务树，就得自己写两个类：TreeItem 是纯 C++ 节点，TreeModel 负责把节点的父子关系翻译成 Qt 的坐标。

节点类 #

每个节点记录自己的父指针、子列表，以及这一行各列的数据。

// 2. 造 index：把底层 TreeItem 绑成 internalPointer，这是整个模型的枢纽
QModelIndex TreeModel::index(int row, int column, const QModelIndex &parent) const
{
    if (!hasIndex(row, column, parent)) return QModelIndex();

    TreeItem *parentItem = parent.isValid()
                         ? static_cast<TreeItem*>(parent.internalPointer())
                         : rootItem;

    TreeItem *childItem = parentItem->child(row);
    if (childItem) return createIndex(row, column, childItem);
    return QModelIndex();
}

// 3. 反查父亲：给定子 index，造出父 index
QModelIndex TreeModel::parent(const QModelIndex &index) const
{
    if (!index.isValid()) return QModelIndex();

    TreeItem *childItem = static_cast<TreeItem*>(index.internalPointer());
    TreeItem *parentItem = childItem->parent();

    if (parentItem == rootItem)
        return QModelIndex();      // 顶级节点：视图看来父就是无效 index

    return createIndex(parentItem->row(), 0, parentItem);
}

// 4. 行数：第 1 列之外的兄弟列没有子节点

十、parent 与 index 的父子推导 #

这是整棵树的中枢，四行代码决定一切。想清楚三件事，模型就不会崩。

第一，createIndex(row, column, internalPointer) 里，视图只认 row 和 column，你的节点对象藏在 internalPointer 里，靠 index.internalPointer() 取回。行号写错、指针写错，视图拿到的就是别人家的节点。

第二，internalPointer 必须一直活着。createIndex() 不复制任何东西，只存指针。节点先被 delete、index 还在用，就是野指针，表现是滚动时随机崩。

第三，parent(顶级 index) 必须返回无效的 QModelIndex()，不能返回「虚根的 index」。虚根本来就没有 index，返回了视图就会一直往上爬。

方向 输入 算出 依据
父 → 子 父 index、row、column 子 index parentItem->child(row) + createIndex
子 → 父 子 index 父 index childItem->parent() + parentItem->row()
index → 节点 index TreeItem* index.internalPointer()
节点 → index 节点 行号 + 列号 node->row()，列号自己给
节点 → 父 index 节点 父 index node->parent()，等于 root 就无效

推导链条走一遍，以「设备 → 电机 → 一号电机」为例：

text
index(0, 0, 无效)              -> 设备        createIndex(0, 0, 设备节点)
parent(设备index)              -> 无效 index  parent == rootItem
rowCount(设备index)            -> 1           设备有 1 个孩子
index(0, 0, 设备index)         -> 电机        parentItem=设备, child(0)=电机
index(0, 1, 电机index)         -> 电机第 2 列，同一 internalPointer
parent(电机index)              -> 设备        createIndex(0, 0, 设备)
rowCount(电机index)            -> 1
index(0, 0, 电机index)         -> 一号电机

两处细节决定树活不活：

cpp
if (!hasIndex(row, column, parent)) return QModelIndex();   // 行号越界直接挡掉
if (parent.column() > 0) return 0;                          // 第 1 列之后没有孩子

hasIndex() 内部会调 rowCount() 和 columnCount()，所以这两个函数必须在前、必须正确，否则 index() 一进就返回无效，树看起来永远展不开。parent.column() > 0 那句也是必须：视图会拿同一行的第 2 列 index 去问有没有孩子，若不加这个判断，每列都长出一模一样的子树。

rowCount() 返回 0 的节点没有展开箭头，这条直接决定了懒加载怎么写，见下一章。视图侧的判断永远走 isValid()：无效 index 就是虚根。

十一、懒加载：按需展开 #

节点上万、每个节点的孩子在展开时才去查数据库或解 XML，这就是懒加载。做法一句话：rowCount() 先别去取，等视图真要展开时再填。

老实做法是占位子节点。给每个能展开的节点先塞一个空 item，视图看到有孩子就画箭头；展开时把占位删掉、换成真数据。

cpp
void TreeModel::populate(TreeItem *parent)
{
    if (parent->childCount() > 0) return;                      // 已经填过
    parent->appendChild(new TreeItem({QString()}, parent));    // 一个占位
}

// 真正填充挂到 expanded 信号上：视图问 rowCount 时占位已经在了
connect(view, &QTreeView::expanded, this, [this](const QModelIndex &index) {
    auto *parent = static_cast<TreeItem*>(index.internalPointer());
    if (!parent->placeholder()) return;
    beginRemoveRows(index, 0, parent->childCount() - 1);
    parent->clearChildren();
    endRemoveRows();
    const auto rows = queryChildrenFromDb(parent->row());      // 迟到的真实数据
    beginInsertRows(index, 0, int(rows.size()) - 1);
    for (const auto &r : rows) parent->appendChild(new TreeItem(r, parent));
    endInsertRows();
});

Qt 还提供了一套官方接口，模型里重写 canFetchMore() / fetchMore()：

cpp
bool TreeModel::canFetchMore(const QModelIndex &parent) const
{
    if (!parent.isValid()) return false;
    auto *node = static_cast<TreeItem*>(parent.internalPointer());
    return !node->fetched && node->childCount() == 0;   // 还没取过，且确实该有孩子
}

void TreeModel::fetchMore(const QModelIndex &parent)
{
    auto *node = static_cast<TreeItem*>(parent.internalPointer());
    node->fetched = true;
    const auto rows = queryChildrenFromDb(node->row());
    if (rows.isEmpty()) return;
    beginInsertRows(parent, 0, int(rows.size()) - 1);
    for (const auto &r : rows) node->appendChild(new TreeItem(r, node));
    endInsertRows();
}

canFetchMore() 返回 true，视图就在展开时调 fetchMore()，这是 Qt 内置的时机，比自己连 expanded 信号干净。懒加载树上别再手动 expandAll()，那会一次把所有懒节点全拉出来，界面直接冻住。

hasChildren() 的坑 #

想省掉占位 item，直接重写 hasChildren()：

cpp
bool TreeModel::hasChildren(const QModelIndex &parent) const
{
    if (!parent.isValid()) return true;                  // 顶层永远有
    auto *node = static_cast<TreeItem*>(parent.internalPointer());
    return node->maybeHasChildren;                       // 由业务侧标记
}

关键就在这个返回值。hasChildren() 无条件返回 true，展开箭头会永远显示，包括那些实际没有子节点的叶子——点开之后空空如也，箭头还在，用户看到的就是一堆假箭头。

正确写法只有两个：返回真实有无子节点，或者在懒加载里返回「还有没取过的孩子」这种可判定的条件。业务数据里没有「是否还有子节点」这种信息，就先塞占位 item，别硬编返回值。

hasChildren() 一旦重写，rowCount() 也必须一致：hasChildren() 说 true、rowCount() 返回 0，视图会画出箭头但展开永远是空的；反过来 hasChildren() 说 false，rowCount() 再大也不给箭头，子节点永远看不到。

十二、右键菜单与拖拽 #

右键菜单 #

视图自己 setContextMenuPolicy(Qt::CustomContextMenu)，接 customContextMenuRequested，用坐标换 index。

cpp
view->setContextMenuPolicy(Qt::CustomContextMenu);
connect(view, &QTreeView::customContextMenuRequested, this, [this, view](const QPoint &pos) {
    const QModelIndex index = view->indexAt(pos);
    if (!index.isValid()) return;            // 点在空白处，不给菜单

    QMenu menu(this);
    QAction *addAct  = menu.addAction(QStringLiteral("新增子节点"));
    QAction *delAct  = menu.addAction(QStringLiteral("删除"));
    menu.addSeparator();
    QAction *propAct = menu.addAction(QStringLiteral("属性"));

    QAction *picked = menu.exec(view->viewport()->mapToGlobal(pos));
    if (picked == addAct) addChild(index);
    else if (picked == delAct) removeNode(index);
    else if (picked == propAct) showProperty(index);
});

坐标必须是 viewport()->mapToGlobal(pos)，customContextMenuRequested 给的是视口坐标；直接 map 到视图上，菜单会偏出一个表头的高度。QTreeWidget 换一下就用同一套：tree->indexAt(pos) 之后 tree->itemFromIndex(index) 拿 item。

    return true;
}

dropMimeData() 里 row == -1 是一条容易漏的分支：丢在节点的上方或下方时 Qt 给的是行号，丢在节点身上时给的是 -1 加一个非无效的 parent，两种情况的落点完全不同。beginMoveRows() 的第三个参数是「目标行的插入位置」，同层内向后移动时目标行号要减一，不然后移一格会变成后移两格。搬完必须 endMoveRows()，中间抛异常也要保证配对，否则视图的持久索引全废。

QTreeWidget 侧不用碰 MIME，重写 dropEvent() 或者接 itemDropped / itemMoved，调 takeChild() + insertChild() 完成搬移，搬完记得把勾选状态的父子联动重算一次。

十三、易错点速查 #

现象 原因 修法
树展不开，节点下面是空的 rowCount() 返回 0，或 hasIndex() 一直挡 先修 rowCount()，index() 里别乱加条件
展开后无限套娃 parent() 对顶级返回了虚根 index 顶级一律返回 QModelIndex()
每列长出一模一样的子树 rowCount() 少了 parent.column() > 0 补这句，第 1 列之外返回 0
点第 3 行展开第 5 行 createIndex() 的 row 传错 row 必须用 node->row()
所有行显示同一份数据 internalPointer 传了父节点 必须传当前子节点
滚动时随机崩 index 里存了已 delete 的节点 删节点前先清视图，或改用 QPersistentModelIndex
增删后行号错乱 没发 begin/end 通知 严格配对 beginInsertRows / endInsertRows
叶子也有展开箭头 hasChildren() 无条件 true 返回真实状态，或走占位 item
勾选父子不一致、死循环 itemChanged 里没阻断信号 QSignalBlocker 包住自己的写入
排序后 item 找不到了 setSortingEnabled(true) 期间插入 批量插入先关排序
同一控件出现在多行 setItemWidget() 复用了同一实例 每行 new 一个
itemFromIndex() 返回空 index 无效或来自别的模型 先 isValid()，同一模型才通用
图标被拉变形 setIconSize() 与源图尺寸差太多 源图按目标尺寸出
行高忽大忽小，滚动卡 混用了 setItemWidget 与 setUniformRowHeights 二者选一
委托画的按钮点不动 paint() 与 editorEvent() 矩形不一致 抽同一个函数算区域
expandAll() 界面冻住 懒加载树上全展开，一次拉全部数据 改成按需，或 expandToDepth()
右键菜单位置偏了 用了视图坐标而非视口坐标 viewport()->mapToGlobal(pos)
拖拽落点差一行 dropMimeData() 里 row == -1 未处理 分「丢在身上」和「丢在两行之间」

最后留一条判断准则：树上出现任何「看不见」「点不到」「点错行」的毛病，先打印三件事——当前的 index.row()、index.column()、index.parent().isValid()。三行日志基本能定位到推导链断在哪一环。
