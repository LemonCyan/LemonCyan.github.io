这篇只讲 QTableWidget 一个控件：建表、设表头、填单元格、塞控件、读写数据、排序筛选、多选、右键菜单、QSS 美化、表头塌陷、合并单元格、编辑与光标控制。

不讲模型/视图架构本身怎么实现，不讲委托的 paint 与 createEditor 全流程，不讲 QTreeView 的层级模型——这三块各有一篇。

想接自己的业务数据、想撑住十万行，去看同目录的「QTableView 与模型/视图架构」。想改单元格的渲染和编辑器，去看委托那篇。

QTableWidget 好用的地方在于它不逼你先想清楚数据怎么组织。建个表，setItem 一格一格塞进去，界面就出来了。代价也在这里：数据被 item 绑死在界面上，换个呈现方式就得重写一遍。用之前先认清这条边界，后面九成的坑都能提前绕开。

一、QTableWidget 与 QTableView 的分工 #

QTableWidget 是 QTableView 的子类，源码里就一行继承关系，但两者的用法差别很大。

QTableView 里有个 setModel 成员函数，它是接数据的唯一入口。QTableWidget 把这个函数设成了私有，外面调不到。所以 QTableWidget 只能用它自己内部那套标准模型，每个单元格的内容由一个 QTableWidgetItem 对象承载。

cpp
// QTableWidget 的填法：一格一个 item
tableWidget->setItem(0, 0, new QTableWidgetItem("Jan"));

cpp
// QTableView 的填法：先给模型，视图自己去问模型要
view->setModel(myModel);

一句话记住：QTableWidget 是「自带数据模型的便捷表格」，QTableView 是「纯视图，必须自己接模型」。

关注点 QTableWidget QTableView
数据来源 内部自带模型，item 就是数据 必须 setModel 接自己的模型
setModel 私有，外部调不到 公开，核心入口
填充方式 setItem(row, col, new QTableWidgetItem(...)) 模型里实现 data()、rowCount()
数据与界面 绑死，改数据等于改界面 解耦，换视图不用动数据
一万行 明显卡顿 只渲染可见区域，顺畅
内存 每个格子一个堆上对象 只有模型里那批原始数据
典型场景 配置页、几十到几百行的结果表、临时报表 日志、数据库查询结果、实时刷新的监控表

选型就一句话：要快速做个小表格，QTableWidget；数据量大，或者要和业务数据解耦，QTableView 加自定义模型。

这里的「数据量大」不是虚指。QTableWidget 每个单元格都是一个 QTableWidgetItem 对象，一万行十列就是十万个堆对象，构建、排序、销毁全在主线程上跑。几百到一两千行都能忍，上万行就开始拖滚动条，几万行直接卡死界面。跨过这条线，只有换 QTableView 一条路。

还有一层：QTableWidget 的 item 里塞业务数据只能靠 setData(Qt::UserRole, ...)，一个 item 挂一个 QVariant。要在同一个格子上挂三四个字段，就得自己打包结构体，越写越别扭。业务模型稍复杂，这也是换 QTableView 的理由。

二、创建表格与设置行列 #

构造函数直接给行列数，是 code 里最省事的方式：

cpp
QTableWidget *tableWidget = new QTableWidget(10, 5);   // 10 行 5 列
tableWidget->setWindowTitle("QTableWidget & Item");
tableWidget->resize(350, 200);

空构造再设行列也等价，在 Designer 里拖出来的控件只能走这条路：

cpp
tableWidget->setRowCount(10);
tableWidget->setColumnCount(5);

行高与列宽 #

四组 API，混着用要分清：

cpp
// 按内容自适应
tableWidget->resizeColumnsToContents();      // 所有列
tableWidget->resizeColumnToContents(3);      // 指定列
tableWidget->resizeRowsToContents();         // 所有行

// 直接指定
tableWidget->setColumnWidth(3, 200);
tableWidget->setRowHeight(3, 60);

resizeColumnsToContents() 在数据量大时很费时间，它要把每一列的每个 item 都量一遍。批量填完数据再调一次，别放在循环里。

插入、删除行 #

cpp
int currentRows = tableWidget->rowCount();
tableWidget->insertRow(currentRows);         // 尾部加一行空行
tableWidget->insertRow(0);                   // 插到最前面
tableWidget->removeRow(2);                   // 删第 3 行
tableWidget->setRowCount(0);                 // 清掉所有行

insertRow 与 setItem 的配合是最常见的追加逻辑：

cpp
void appendRow(QTableWidget *tableWidget, const QString &name,
               const QString &time, const QString &size)
{
    int row = tableWidget->rowCount();
    tableWidget->insertRow(row);

    QTableWidgetItem *nameItem = new QTableWidgetItem(name);
    QTableWidgetItem *timeItem = new QTableWidgetItem(time);
    QTableWidgetItem *sizeItem = new QTableWidgetItem(size);

    nameItem->setIcon(QIcon(":/Images/file.png"));

    tableWidget->setItem(row, 0, nameItem);
    tableWidget->setItem(row, 1, timeItem);
    tableWidget->setItem(row, 2, sizeItem);

    QColor textColor("gray");
    timeItem->setTextColor(textColor);
    sizeItem->setTextColor(textColor);
}

三种清空方式的区别 #

这三个函数常被搞混，用错了会把表头一起干掉：

cpp
tableWidget->clear();            // 清所有可见数据，包含表头文字，行还在
tableWidget->clearContents();    // 只清数据，表头保留
tableWidget->setRowCount(0);     // 行数归零，表头也保留

要保留表头就用后两个。clear() 之后表头标签要重新 setHorizontalHeaderLabels 一遍。

外观开关 #

cpp
tableWidget->setShowGrid(true);                                  // 显示网格线
tableWidget->setFrameShape(QFrame::NoFrame);                     // 去掉外围边框
tableWidget->setHorizontalScrollBarPolicy(Qt::ScrollBarAlwaysOff);// 去掉横向滚动条
tableWidget->setVerticalScrollMode(QAbstractItemView::ScrollPerItem); // 竖向按项滚动
tableWidget->setAutoScroll(false);                               // 关掉拖拽时的自动滚动
tableWidget->setAlternatingRowColors(true);                      // 隔行变色

setAlternatingRowColors(true) 要配合 QSS 里的 alternate-background-color 才有颜色，光开开关只拿到系统默认那层浅灰。

三、表头：标签、宽度与自适应 #

表头由 QHeaderView 负责，水平一个、垂直一个，都从表格上拿指针再改：

cpp
QHeaderView *hHeader = tableWidget->horizontalHeader();
QHeaderView *vHeader = tableWidget->verticalHeader();

设置标签 #

两种写法，效果一样：

cpp
// 方法一
QStringList header;
header << "Column 1" << "Column 2" << "Column 3";
tableWidget->setHorizontalHeaderLabels(header);

// 方法二
tableWidget->setHorizontalHeaderLabels(QStringList() << tr("1") << tr("2") << tr("3"));

垂直表头（左侧行号列）同理，用 setVerticalHeaderLabels。多数界面里行号没意义，直接 verticalHeader()->setVisible(false) 藏掉。

单改某一列的表头文字，走 headerItem：

cpp
QTableWidgetItem *columnHeaderItem0 = tableWidget->horizontalHeaderItem(0);
columnHeaderItem0->setText("名称");
columnHeaderItem0->setFont(QFont("Helvetica"));
columnHeaderItem0->setBackgroundColor(QColor(0, 60, 10));
columnHeaderItem0->setTextColor(QColor(200, 111, 30));

注意 horizontalHeaderItem(0) 会返回空指针——得先 setHorizontalHeaderLabels 或者 setHorizontalHeaderItem 建过这个表头项。直接改属性前判一下空。

表头文字加粗，改整个表头的字体最省事：

cpp
QFont headerFont = tableWidget->horizontalHeader()->font();
headerFont.setBold(true);
tableWidget->horizontalHeader()->setFont(headerFont);

宽度模式 #

这是表头最容易记混的一组 API。Qt5 之后叫 setSectionResizeMode，Qt4 叫 setResizeMode，看版本抄：

cpp
// 所有列均匀拉伸，填满表格
tableWidget->horizontalHeader()->setSectionResizeMode(QHeaderView::Stretch);

// 单列单独指定
tableWidget->horizontalHeader()->setSectionResizeMode(0, QHeaderView::Fixed);

// 行高同理
tableWidget->verticalHeader()->setSectionResizeMode(QHeaderView::Stretch);

五种模式的实际行为：

模式 行为 用在哪
Interactive 用户可拖，程序设的值保留（默认） 让用户自己调宽度的列
Fixed 用户拖不动，只有程序能改 图标列、序号列
Stretch 平分剩余宽度，用户拖不动 整表铺满窗口
ResizeToContents 按内容算宽，内容变了自动重算 状态列、短文本列
Custom 交给自定义逻辑 特殊布局

ResizeToContents 在大表上代价高，它每次布局都要遍历该列所有 item 算宽度。几百行以内无所谓，上万行就把窗口拖卡了。

最后一列填满 #

Stretch 是「所有列平分」，setStretchLastSection(true) 是「只让最后一列吃掉剩余空间」，两者经常混淆：

cpp
tableWidget->horizontalHeader()->setStretchLastSection(true);
tableWidget->verticalHeader()->setStretchLastSection(true);

列表类界面要的是后者——前几列固定宽度，最后一列把空白补上。

尺寸与交互 #

cpp
tableWidget->horizontalHeader()->setDefaultSectionSize(150);  // 默认列宽
tableWidget->horizontalHeader()->resizeSection(0, 284);       // 指定列宽
tableWidget->horizontalHeader()->resizeSection(1, 127);

tableWidget->horizontalHeader()->setMinimumSectionSize(60);   // 拖拽下限
tableWidget->horizontalHeader()->setMovable(false);           // 列不能拖换位置
tableWidget->horizontalHeader()->setClickable(false);         // 表头不可点击

setClickable(false) 顺带把点击表头排序的路堵死了，如果还要排序，别关这个。

四、单元格：文本、图标与控件 #

单元格里能放三种东西：纯文本、带图标的文本、任意 QWidget。

文本与图标 #

cpp
// 纯文本
tableWidget->setItem(0, 0, new QTableWidgetItem("Jan"));

// 图标 + 文本
tableWidget->setItem(0, 1, new QTableWidgetItem(QIcon(":/images/IED.png"), "Jan's month"));

// 只有图标
tableWidget->setItem(row, 0, new QTableWidgetItem(QIcon(":/images/kingdemo.ico"), tr("")));

// 后设图标
item->setIcon(QIcon(":/Images/file.png"));

QTableWidgetItem 的构造顺序是 (图标, 文本)，别写反。

单元格样式 #

颜色、字体、对齐都在 item 上设，不进 QSS：

cpp
QTableWidgetItem *item = new QTableWidgetItem("Apple");
item->setBackgroundColor(QColor(0, 60, 10));
item->setTextColor(QColor(200, 111, 100));
item->setFont(QFont("Helvetica"));
item->setTextAlignment(Qt::AlignHCenter | Qt::AlignVCenter);
tableWidget->setItem(0, 3, item);

对齐值可以按位或，水平和垂直各取一个：

cpp
// 水平：Qt::AlignLeft / Qt::AlignRight / Qt::AlignHCenter / Qt::AlignJustify
// 垂直：Qt::AlignTop / Qt::AlignBottom / Qt::AlignVCenter
item->setTextAlignment(Qt::AlignHCenter | Qt::AlignVCenter);

注意 setTextAlignment 的签名在 Qt5 里是 int，传 Qt::Alignment 要显式 int() 转一下；Qt6 改成了 Qt::Alignment，直接传。

塞控件 #

下拉框、进度条、按钮这类东西，用 setCellWidget 塞进格子：

cpp
QComboBox *comBox = new QComboBox();
comBox->addItem("Y");
comBox->addItem("N");
tableWidget->setCellWidget(0, 2, comBox);

这里有个必须记住的坑：setCellWidget 塞进去的控件不占 item，那个位置的 item(row, col) 依然是空指针。取值要走 cellWidget：

cpp
QComboBox *box = qobject_cast<QComboBox *>(tableWidget->cellWidget(0, 2));
QString value = box ? box->currentText() : QString();

反过来，塞过控件的格子再 setItem 也没用，控件盖在上面，用户看到的是控件。要么用控件，要么用 item，一格只选一种。

控件对性能的影响比 item 还大。每个 setCellWidget 都是一个真窗口，一百个格子塞一百个 QComboBox，滚动时就明显掉帧。要大量下拉框，走委托的 createEditor。

复选框 #

复选框不用控件，给 item 设 checkState 就够：

cpp
QTableWidgetItem *item = new QTableWidgetItem("启用");
item->setCheckState(Qt::Checked);
tableWidget->setItem(row, 0, item);

勾选框的图形靠 QSS 的 ::indicator 换图，第九章有完整写法。

只读单个格子 #

整表禁用编辑在第七章讲，单个格子用标志位：

cpp
item->setFlags(item->flags() & ~Qt::ItemIsEditable);

QTableWidgetItem 默认带 ItemIsEditable，位与掉就只读。想恢复就 | Qt::ItemIsEditable 加回去。

五、数据读写与遍历 #

读一个格子：

cpp
QString text = tableWidget->item(row, col)->text();

这行代码是崩溃第一名。item(row, col) 在格子没被 setItem 过时返回空指针，直接 ->text() 就是野指针解引用。凡是从行列号拿 item，先判空：

cpp
QTableWidgetItem *item = tableWidget->item(row, col);
QString text = item ? item->text() : QString();

想省掉判空，就在建表时把每个格子都填上 new QTableWidgetItem()。代价是又多了几万个对象，不划算，还是老实判空。

用户交互取单元格 #

点击、双击靠信号：

cpp
connect(tableWidget, SIGNAL(itemDoubleClicked(QTableWidgetItem*)),
        this, SLOT(getItem(QTableWidgetItem*)));

connect(tableWidget, SIGNAL(itemClicked(QTableWidgetItem*)),
        this, SLOT(onItemClicked(QTableWidgetItem*)));

槽里拿到的指针不会是空，这是信号带来的便利。要注意双击信号发在编辑器打开之前，改 item 的文本不会被编辑器吞掉。

行号与 item 互查 #

item 里有行有列，表格也能反查：

cpp
int row = tableWidget->row(item);      // item 所在行
int col = tableWidget->column(item);   // item 所在列
int idx = tableWidget->currentRow();   // 当前行
QTableWidgetItem *cur = tableWidget->currentItem();

currentRow() 在没选中任何东西时返回 -1，判断别漏。

转移与删除 item #

takeItem 把 item 从表里摘下来，所有权给调用方，不删内存：

cpp
QTableWidgetItem *item = tableWidget->takeItem(row, col);  // 表里没了，item 还在
delete item;                                               // 不 delete 就漏

removeRow(row) 会连同该行所有 item 一起 delete。搞不清这条区别，就会写出「先 removeRow 再 delete item」的双重释放。

绑定业务数据 #

一个 item 只能挂一个 QVariant：

cpp
item->setData(Qt::UserRole, recordId);      // 存
int id = item->data(Qt::UserRole).toInt();  // 取

需要多个字段就往里塞 QVariantMap 或自定义结构体（记得 Q_DECLARE_METATYPE）。塞到第三个字段时，就该考虑换 QTableView 了。

批量填数据的性能 #

一千行以上，逐条 setItem 会肉眼可见地慢。三个开关能救回来不少：

cpp
tableWidget->setUpdatesEnabled(false);   // 填之前关重绘
tableWidget->setSortingEnabled(false);   // 关排序，否则每 setItem 一次重排一次

for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < cols; ++j) {
        tableWidget->setItem(i, j, new QTableWidgetItem(data[i][j]));
    }
}

tableWidget->setSortingEnabled(true);
tableWidget->setUpdatesEnabled(true);    // 一次性重绘

setSortingEnabled(false) 这条最容易被忘。开着排序建表，每插一个 item 都要重排整个表，复杂度直接翻成 O(n²)。

上万行：延迟加载 #

数据上千上万时，界面的可视区域就那么高，只有几十行能看见。全量建 item 是在为看不见的行付内存和布局成本。思路是把数据先存在自己的 list 里，只把可视范围内的行落成 item，滚动条一动再补。

下面这套封装可以直接改改就用，核心是一个记录结构加一个滚动槽：

cpp
/// 保存每一个 item 的信息，不进 QTableWidgetItem
class BigTableWidgetInfo {
public:
    int nRow;          // 行号
    int nColumn;       // 列号
    QString strText;   // 显示文本
    QVariant userData; // 用户关联数据
};

class BigTableWidget : public QTableWidget {
    Q_OBJECT
public:
    BigTableWidget(QWidget *parent = 0);

    void addItem(int row, int column, QString strText, QVariant userData = QVariant());
    void initTableRowAndColumn(int row, int nColumn);
    void clearTableData();
    int getMaxCount() { return m_nMaxCount; }
    void pushData(int row, int column, QString strText, QVariant userData);

protected:
    static void dealClearData(void *users);

private slots:
    void dealChangeValue(int nValue);

private:
    int m_nMaxCount = 0;                            // 一屏最多显示多少行
    QList<BigTableWidgetInfo*> m_listTableInfo;     // 待显示数据
    QList<BigTableWidgetInfo*> m_listCopyTableInfo; // 待清理的垃圾
    QMutex m_tableInfoMutex;
};

初始化时算出「一屏多少行」，并把滚动条信号接上：

cpp
BigTableWidget::BigTableWidget(QWidget *parent) : QTableWidget(parent)
{
    setEditTriggers(QAbstractItemView::NoEditTriggers);
}

void BigTableWidget::initTableRowAndColumn(int row, int nColumn)
{
    setColumnCount(nColumn);
    setRowCount(row);

    QScrollBar *pBar = verticalScrollBar();
    connect(pBar, SIGNAL(valueChanged(int)), this, SLOT(dealChangeValue(int)));

    int nRowHeight = rowHeight(0);
    int nViewportHeight = maximumViewportSize().height();
    m_nMaxCount = nViewportHeight / nRowHeight + 1;
}

真正的加载动作在滚动槽里。数据没加载完时会被滚动条拖过头，这里得夹一下：

cpp
void BigTableWidget::dealChangeValue(int nValue)
{
    int nRealRow = nValue;
    int nRowChanged = 0;
    int nTempColumn = columnCount();
    int nListSize = m_listTableInfo.size() / nTempColumn;

    // 滚动条拖到了还没加载的位置，拉回来
    if (nValue > nListSize) {
        verticalScrollBar()->setValue(nListSize);
        return;
    }

    if (nListSize - nRealRow < m_nMaxCount)
        nRowChanged = nListSize - nRealRow;

    for (int i = 0; i < nRowChanged; ++i) {
        for (int j = 0; j < nTempColumn; ++j) {
            int temp = (i + nRealRow) * nTempColumn + j;
            if (temp >= m_listTableInfo.size())
                return;

            BigTableWidgetInfo *info = m_listTableInfo.at(temp);
            QTableWidgetItem *tempItem = new QTableWidgetItem(info->strText);
            tempItem->setTextAlignment(Qt::AlignHCenter);
            setItem(info->nRow, info->nColumn, tempItem);
        }
    }
}

addItem 负责区分「在首屏」和「在屏幕外」，前者立刻落 item，后者只入队：

cpp
void BigTableWidget::addItem(int row, int column, QString strText, QVariant pUserData)
{
    BigTableWidgetInfo *info = new BigTableWidgetInfo;
    info->nRow = row;
    info->nColumn = column;
    info->strText = strText;
    info->userData = pUserData;
    m_listTableInfo.push_back(info);

    if (row < m_nMaxCount) {
        QTableWidgetItem *tempItem = new QTableWidgetItem(strText);
        tempItem->setTextAlignment(Qt::AlignHCenter);
        setItem(row, column, tempItem);
    }
}

清空要放到后台，否则删几万个对象又是一次卡顿。QtConcurrent::run 起线程，垃圾列表先摘出来再删：

cpp
void BigTableWidget::clearTableData()
{
    if (m_listTableInfo.isEmpty())
        return;

    m_listCopyTableInfo.append(m_listTableInfo);
    QMutexLocker locker(&m_tableInfoMutex);
    m_listTableInfo.clear();
    clearContents();
    setRowCount(1);
    QtConcurrent::run(dealClearData, (void*)this);
}

void BigTableWidget::dealClearData(void *users)
{
    BigTableWidget *pThis = static_cast<BigTableWidget *>(users);
    for (int i = 0; i < pThis->m_listCopyTableInfo.size(); ++i) {
        if (pThis->m_listCopyTableInfo.at(i))
            delete pThis->m_listCopyTableInfo.at(i);
    }
    pThis->m_listCopyTableInfo.clear();
}

这套方案实测带 17000 条记录滚动是顺的。三个必须补的事件处理：

  • 重写 wheelEvent()，把滚轮滚动折算成行偏移后同步一次可见区
  • 重写 resizeEvent()，窗口变高变矮都要重算可见行数
  • 少创建对象，滚出屏幕的 item 优先复用，不要每滚一屏新建一批

延迟加载有个代价：item(row, col) 拿到的只是「已经落表」的那些格子，屏幕外的行查不到 item，只能回自己的 list 查。凡是依赖 item() 的代码都得改。

控件也要复用 #

单元格里塞控件时，「一屏几十行却建了几千个控件」是另一个坑。做法是同一条路：控件全部进一个 QList 缓存，刷新时先全部 hide()，再按可视区从第一条往下摆，摆过底边就停；要新控件时先在缓存里找同类且隐藏的那个，找到就 setData 复用，找不到才 new。这样控件数量恒等于一屏所需，滚动只改数据不改数量。

两条路的终点 #

延迟加载和 Widget 复用都是在 QTableWidget 里硬扛，扛到几万行就到头了。原因是数据仍然分散在 item 和控件的堆对象里，排序、筛选、换列都得整体搬一遍。真到那个规模，正解只有一个：QTableView 加 QAbstractItemModel，让视图按需向模型要 data()，视图有多少行就要多少行。

六、排序与筛选 #

打开排序 #

cpp
tableWidget->setSortingEnabled(true);

开了之后用户点表头就排序，点一下升序、再点降序。代码主动排：

cpp
tableWidget->sortItems(2, Qt::DescendingOrder);   // 按第 3 列降序

数字为什么排不对 #

QTableWidgetItem 的默认比较是拿 text() 做字符串比。于是 10 排在 9 前面，2.5 排在 10.1 后面，日期格式不对也乱。三种解法：

一是把数字写进 Qt::DisplayRole 之外的排序角色。做法是自定义 item，重载比较运算符：

cpp
class NumberItem : public QTableWidgetItem {
public:
    explicit NumberItem(double value)
        : QTableWidgetItem(QString::number(value)), m_value(value) {}

    bool operator<(const QTableWidgetItem &other) const override
    {
        return m_value < other.data(Qt::UserRole).toDouble();
    }

    QVariant data(int role) const override
    {
        if (role == Qt::UserRole)
            return m_value;
        return QTableWidgetItem::data(role);
    }

private:
    double m_value;
};

二是文本补零对齐，0010、0009，字符串比也正确，适合文件大小、序号这种固定位数的场景。

三是干脆别在 QTableWidget 里排，排序交给后台的数据结构，排完重填。

排序与延迟加载冲突 #

延迟加载那套结构里，每个 item 的信息单独存在 list 里。一排序，所有 item 的行列号都要跟着改，改一遍就是 O(n) 次 setItem，还不如不排。真需要排序加大量数据，用三个替代：

做法 代价 适用
换模型/视图，排序交给 QSortFilterProxyModel 要写模型 正解，数据量大时唯一舒服的路
只排当前可见区 顺序不一致 只读展示
后台线程排完再整表重填 一次性卡顿 中等数据量

筛选 #

QTableWidget 没有内置过滤，全靠自己按行隐藏：

cpp
void filterRows(QTableWidget *tableWidget, const QString &keyword)
{
    for (int row = 0; row < tableWidget->rowCount(); ++row) {
        bool hit = keyword.isEmpty();
        for (int col = 0; col < tableWidget->columnCount() && !hit; ++col) {
            QTableWidgetItem *item = tableWidget->item(row, col);
            if (item && item->text().contains(keyword, Qt::CaseInsensitive))
                hit = true;
        }
        tableWidget->setRowHidden(row, !hit);
    }
}

setRowHidden 只是不画，item 还在，数据量大的时候遍历一遍也很慢。筛选词变化频繁就加个防抖，敲一个字筛一遍的做法在上万行时会把输入框拖卡。

按数值或日期筛选，把 contains 换成条件判断即可，思路一样：先算出一个 bool，再 setRowHidden(row, !hit)。

七、选择模式与多选 #

选择和编辑是两组独立的开关，混着设就出怪现象。

选择行为：选中什么 #

cpp
tableWidget->setSelectionBehavior(QAbstractItemView::SelectRows);      // 整行
tableWidget->setSelectionBehavior(QAbstractItemView::SelectItems);     // 单个格子
tableWidget->setSelectionBehavior(QAbstractItemView::SelectColumns);   // 整列

列表式界面用 SelectRows，用户点哪都选中一整行，删行、右键菜单都好写。表格式录入用 SelectItems。

选择模式：能选几个 #

模式 行为 用户操作
SingleSelection 只能选一个 点谁是谁
MultiSelection 可多选，点一下切换选中 不需要按 Ctrl
ExtendedSelection 可多选，要配合 Ctrl / Shift Ctrl 点、Shift 连选、Ctrl+A 全选
NoSelection 不可选择 纯展示 
cpp
tableWidget->setSelectionMode(QAbstractItemView::ExtendedSelection);  // 多选
tableWidget->setSelectionMode(QAbstractItemView::SingleSelection);    // 单选
tableWidget->setSelectionMode(QAbstractItemView::NoSelection);        // 不能选

ExtendedSelection 是管理后台里最常用的那个，Ctrl、Shift、Ctrl+A 全都支持，不用自己写键盘逻辑。

取被选中的行 #

selectedItems() 返回的是 item 列表，不是行号列表。整行选中模式下一次点击会返回整行所有列的 item，所以按行列号去重是必须的：

cpp
bool getSelectedRows(QTableWidget *tableWidget, QSet<int> &selectedRows)
{
    QList<QTableWidgetItem*> selectedItems = tableWidget->selectedItems();
    if (selectedItems.isEmpty())
        return false;

    foreach (QTableWidgetItem *item, selectedItems)
        selectedRows.insert(tableWidget->row(item));

    return true;
}

QSet 顺手把重复行号吃掉。要保住用户的选择顺序，改用 QList 加 contains 判断手动去重。

只关心当前那一个：

cpp
int row = tableWidget->currentRow();      // 没有选中时是 -1
QTableWidgetItem *item = tableWidget->currentItem();

选中变化的时机 #

cpp
connect(tableWidget, &QTableWidget::itemSelectionChanged, this, [this]() {
    QSet<int> rows;
    getSelectedRows(ui->tableWidget, rows);
    updateButtonState(rows.size());
});

这个信号在拖拽框选的过程中也会连发，槽里别做重活。

八、右键菜单 #

两种实现，各有各的坐标坑。

方式一：CustomContextMenu 信号 #

控件自带的信号，接上就能用：

cpp
tableWidget->setContextMenuPolicy(Qt::CustomContextMenu);
connect(tableWidget, &QTableWidget::customContextMenuRequested,
        this, &MyWidget::onTableContextMenu);

槽里的 pos 是相对表格控件的坐标，直接喂给 menu->exec() 菜单会跑到窗口左上角——因为 exec 要的是全局屏幕坐标：

cpp
void MyWidget::onTableContextMenu(const QPoint &pos)
{
    QTableWidgetItem *item = ui->tableWidget->itemAt(pos);
    if (!item)
        return;

    QMenu menu(this);
    menu.addAction(m_actionOpen);
    menu.addSeparator();
    menu.addAction(m_actionDelete);
    menu.addAction(m_actionRename);

    menu.exec(ui->tableWidget->viewport()->mapToGlobal(pos));
}

itemAt(pos) 传的也是控件坐标，不是全局坐标。这两个坐标别混。

方式二：重写 contextMenuEvent #

菜单要复用的场景，重写事件更顺手，动作只建一次：

cpp
void MyWidget::initMenuActions()
{
    m_popMenu = new QMenu(this);

    m_actionOpen = new QAction(tr("打开"), this);
    m_actionDelete = new QAction(tr("删除"), this);
    m_actionRename = new QAction(tr("重命名"), this);

    m_actionRename->setShortcut(QKeySequence("F2"));

    connect(m_actionDelete, &QAction::triggered, this, &MyWidget::onDeleteSelected);
}

void MyWidget::contextMenuEvent(QContextMenuEvent *event)
{
    m_popMenu->clear();                 // 清掉上一次拼进去的动作

    QPoint localPos = event->pos();     // 窗口相对坐标
    QTableWidgetItem *clickedItem = ui->tableWidget->itemAt(localPos);

    if (clickedItem != nullptr) {
        m_popMenu->addAction(m_actionOpen);
        m_popMenu->addSeparator();
        m_popMenu->addAction(m_actionDelete);
        m_popMenu->addAction(m_actionRename);

        m_popMenu->exec(QCursor::pos());   // 全局坐标，直接用鼠标位置最稳
        event->accept();
    }
}

event->pos() 给的是相对接收事件的控件。如果 contextMenuEvent 写在窗口类里，坐标基准是窗口；写在 QTableWidget 子类里，基准是表格。这时 itemAt 之前要 mapFrom 一次，否则点在右下角会算到左上角去。

右键要操作选中行 #

常见需求是「右键某行，菜单里的删除作用于所有选中行」。做法是先判定右键落在第几行，该行不在选中集合里就把选中改成这一行，再弹菜单：

cpp
int row = ui->tableWidget->row(clickedItem);
if (!ui->tableWidget->selectionModel()->isRowSelected(row, QModelIndex()))
    ui->tableWidget->selectRow(row);

漏了这步，用户右键第 5 行再点删除，删掉的是之前选中的那几行。

菜单项按状态禁用 #

动作是复用的，每次弹菜单前都要重设一遍启用状态，否则上一次的禁用状态会留着：

cpp
m_actionOpen->setEnabled(clickedItem != nullptr);
m_actionDelete->setEnabled(ui->tableWidget->rowCount() > 0);

把 QSS 从资源文件读进来 #

样式写死在代码里难维护，放 qrc 里读出来：

cpp
QString qss;
QFile file(":/style.css");
if (file.open(QFile::ReadOnly)) {
    QStringList list;
    QTextStream in(&file);
    while (!in.atEnd()) {
        QString line;
        in >> line;              // 按空白切词，换行会丢
        list << line;
    }
    file.close();
    qss = list.join("\n");
    qApp->setStyleSheet(qss);
}

in >> line 会吃掉换行和空格，所以要用 list.join("\n") 补回来。样式里的多词值（border: 1px solid #242424）靠这个 join 才不会粘成一行。更稳的写法是 QTextStream::readAll()。

焦点虚线 #

点中单元格时四周有一圈虚线焦点框，扁平风格里很扎眼。QSS 的 outline: 0 对 item 无效，得靠委托把焦点状态擦掉：

cpp
class NoFocusDelegate : public QStyledItemDelegate
{
public:
    void paint(QPainter *painter, const QStyleOptionViewItem &option,
               const QModelIndex &index) const override
    {
        QStyleOptionViewItem itemOption(option);
        if (itemOption.state & QStyle::State_HasFocus)
            itemOption.state = itemOption.state ^ QStyle::State_HasFocus;  // 位异或抹掉焦点位

        QStyledItemDelegate::paint(painter, itemOption, index);
    }
};

cpp
tableWidget->setItemDelegate(new NoFocusDelegate(this));

异或而不是与取反：State_HasFocus 这一位是 1 就清掉，是 0 就不动，写法短且不用先判断。

十、表头塌陷的处理 #

「表头塌陷」在实践里指两种完全不同的毛病，解法也不同。搞混了会一直修不好。

第一种：高度塌陷 #

现象：加了 QSS 之后，表头从正常的一行变成贴在表格顶上的一条细线，文字被裁掉一半或完全看不见。去掉 QSS 立刻恢复。

根因在 QHeaderView 的 sizeHint。表头每一段的高度是「样式算出来的内容尺寸 + 边框 + 内边距」堆起来的。一旦 QSS 命中表头，QStyleSheetStyle 就接管了这段计算，而 QSS 里没给的尺寸按 0 处理。于是：

cpp
/* 错一：只给边框不给 padding，高度算出来就只剩两条边框 */
QHeaderView::section { border: 1px solid #242424; }

/* 错二：::horizontal 不是 QHeaderView 的子控件，整条规则匹配不到任何东西 */
QHeaderView::horizontal { background: #525252; }

QHeaderView 的子控件只有 ::section 一族，加上 ::up-arrow、::down-arrow。horizontal、vertical 是 section 的伪状态，正确写法是 QHeaderView::section:horizontal；直接写 QHeaderView::horizontal 时 QSS 不报错，只是静默不生效——背景色回到默认，看着就像表头「没了」。

正确写法的三件套：

cpp
QHeaderView { min-height: 28px; }           /* 兜底：表头整体不低于 28px */
QHeaderView::section {
    padding: 4px 8px;                       /* 必须有 padding，撑起内容高度 */
    border: 1px solid #242424;
    border-left-width: 0px;
    border-top-width: 0px;
}

C++ 侧再补一道保险，把高度钉死：

cpp
tableWidget->horizontalHeader()->setFixedHeight(30);
tableWidget->horizontalHeader()->setDefaultSectionSize(120);   // 列宽，不是高度

setSectionResizeMode(QHeaderView::Stretch) 加在已经塌陷的表头上没用，它管宽度不管高度。

成因 症状 解法
::section 只有 border，没有 padding 高度等于边框厚度，文字被裁 补 padding: 4px 8px
把 QHeaderView::section:horizontal 写成 QHeaderView::horizontal 规则不生效，表头回到默认外观 子控件只有 ::section 一族
只设 QHeaderView { height: 30px } 部分版本 QSS 的 height 对表头无效 用 min-height，或 C++ 里 setFixedHeight
给 QHeaderView 设了 font-size 但没设 padding 字号变小后内容撑不满 同第一条，补 padding
委托里改了 sizeHint 行高被压 委托的 sizeHint 里给 QSize(w, 24)

第二种：高亮塌陷 #

现象：表格只有一行或几行数据，选中某一行时，对应的表头那一段突然变成深灰、看着像凹下去一块。表格本身没变形，只是表头某一段底色变了。

这是 highlightSections 在作怪。表头跟着选中行走：选中某一行时，对应的 section 被置成激活态，由当前 QStyle 决定画成什么颜色。QSS 给表头设了深色背景之后，激活态那层高亮叠上去反而更深，看着就是「塌下去一块」。

一行数据就修好：

cpp
tableWidget->horizontalHeader()->setHighlightSections(false);
tableWidget->verticalHeader()->setHighlightSections(false);

行号栏显示着的时候，垂直表头也要同步关，否则左侧行号一样会闪。

这个属性和排序没关系，关掉之后点表头排序照样可用。

两种塌陷怎么快速分辨 #

看表头高度：整条表头被压成一条线、文字看不见——高度塌陷，查 QSS 的 padding 和选择器。表头高度正常、只有某一段底色变深——高亮塌陷，一行 setHighlightSections(false)。

十一、单元格合并 #

合并用 setSpan，参数是「起始行、起始列、跨几行、跨几列」：

cpp
tableWidget->setSpan(0, 0, 3, 1);   // 从 (0,0) 起，纵向合并 3 行 1 列
tableWidget->setSpan(1, 1, 1, 4);   // 横向合并 1 行 4 列，做通栏标题

合并区只画左上角那个格子的内容。给被覆盖的格子 setItem 不会报错，数据也存进去了，只是不显示——所以取值仍然可以用 item(r, c) 读到，但界面上看不见。要改合并区的显示，改左上角那一格。

撤销合并：

cpp
tableWidget->clearSpans();          // 全部还原
tableWidget->setSpan(0, 0, 1, 1);   // 单点还原，跨行列都设成 1

合并区的行高列宽不受内容影响，得自己定：

cpp
tableWidget->setRowHeight(0, 80);              // 跨 3 行的表头区总高
tableWidget->horizontalHeader()->resizeSection(0, 120);

resizeRowsToContents() 遇到跨行合并会算不准，合并区一律手设行高。

四个坑：

  • 合并和排序一起用，顺序会乱。sortItems 会把 item 按行搬动，合并区间不跟着走。要排序的表，别做纵向合并。
  • 合并区被覆盖的格子依然能被选中。SelectItems 模式下用户点到合并区中间，currentRow() 给的是被覆盖的那一行，不是左上角那行。取值前用 rowSpan 反查一下，或者干脆切成 SelectRows。
  • 网格线穿过合并区。setShowGrid(true) 时合并区内部那条线不会消失，看着像没合上。合并多的表直接 setShowGrid(false)，靠 alternate-background-color 分色。
  • 合并区的 item 判定要按左上角做。写遍历逻辑时先 rowSpan(row, col) > 1 || columnSpan(row, col) > 1 判一下，跳过被覆盖的格子，否则同一份数据会被统计两次。

十二、光标移动与编辑控制 #

禁止编辑 #

cpp
tableWidget->setEditTriggers(QAbstractItemView::NoEditTriggers);

这个参数是位标志组合，取值和含义：

取值 什么时候进编辑
NoEditTriggers 永远不进，用户改不了
CurrentChanged 焦点一落到格子上就进
DoubleClicked 双击
SelectedClicked 单击已经选中的格子
EditKeyPressed 按平台编辑键（F2）
AnyKeyPressed 按任意键，直接覆盖原内容
AllEditTriggers 以上全部

CurrentChanged 放在只读展示的表上会让用户一点就弹出输入框，别随手加。要多种触发并存就按位或：DoubleClicked | EditKeyPressed。

开启持久编辑 #

模拟文件重命名的体验，两步走：

cpp
void enableRenameMode(QTableWidget *tableWidget, int targetRow)
{
    QTableWidgetItem *item = tableWidget->item(targetRow, 0);
    tableWidget->setCurrentCell(targetRow, 0);

    tableWidget->openPersistentEditor(item);   // 常驻编辑器
    tableWidget->editItem(item);               // 光标闪进去，等键盘输入
}

void disableRenameMode(QTableWidget *tableWidget, int targetRow)
{
    QTableWidgetItem *item = tableWidget->item(targetRow, 0);
    tableWidget->closePersistentEditor(item);  // 关编辑器，值已经写回 item
}

openPersistentEditor 和 editItem 的差别：前者让编辑器一直挂着（用户不用双击），后者只是把焦点送进去。两个都要调，少一个就是「有输入框但光标不在」或者「光标在但敲字没反应」。

编辑器关掉后值自动写回 QTableWidgetItem，不用手动 setText。

锁住 Tab 键 #

打开持久编辑后有个默认行为很烦：用户按 Tab，光标照样跳到下一格，把那些本该只读的格子也暴露出来。

拦这个要重写 moveCursor，它是视图里所有键盘导航的统一入口：

cpp
class MyTableWidget : public QTableWidget
{
    Q_OBJECT
public:
    explicit MyTableWidget(QWidget *parent = nullptr) : QTableWidget(parent) {}

    int m_editedRow = -1;   // 当前正在编辑锁定状态的行，-1 表示没有

protected:
    QModelIndex moveCursor(CursorAction cursorAction,
                           Qt::KeyboardModifiers modifiers) override;
};

cpp
QModelIndex MyTableWidget::moveCursor(CursorAction cursorAction,
                                      Qt::KeyboardModifiers modifiers)
{
    if (m_editedRow >= 0)
        return currentIndex();      // 返回当前索引，任何方向键、Tab 都被吃掉

    return QTableWidget::moveCursor(cursorAction, modifiers);
}

那句 return QTableWidget::moveCursor(cursorAction, modifiers) 不能省，也不能写成 if / else if 之后漏掉默认分支。少了它，不在编辑态时所有键盘和鼠标点击的单元格切换全部失效——因为 moveCursor 是导航的唯一出口。

moveCursor 是全局拦截，方向键、Home、End、PgUp 一起被挡住。只想挡 Tab，就判 cursorAction == MoveNext || cursorAction == MovePrevious，其余交回父类。

十三、易错点速查 #

症状 原因 解法
崩溃在 item(...)->text() 格子没 setItem，返回空指针 取值前判空
表头压成一条线 QSS 覆盖了 QHeaderView 的 sizeHint ::section 补 padding，加 min-height
表头某段变深凹下去 highlightSections 默认开着 setHighlightSections(false)
塞了下拉框却取不到值 setCellWidget 的格子没有 item 走 cellWidget(row, col)
填完一千行卡住 开着排序逐条 setItem 先 setSortingEnabled(false)
上万行滚动卡死 每格一个 item 对象 延迟加载，或换 QTableView
数字排成 10 < 9 item 按字符串比较 自定义 item 重载 operator<
点表头不排序 setClickable(false) 关了点击 改回 true，或 setSectionsClickable
右键菜单跑到左上角 exec 要全局坐标 viewport()->mapToGlobal(pos)
删行后崩溃 takeItem 后又 removeRow 二选一，takeItem 要自己 delete
清空后表头文字没了 用了 clear() 换 clearContents()
合并区网格线还在 setShowGrid(true) 关网格线，靠交替色区分
moveCursor 后鼠标点不动 漏了 else 分支 非编辑态交回父类
表头样式设了没反应 把 ::section:horizontal 写成了 ::horizontal 子控件只用 ::section 一族
列宽自适应很慢 ResizeToContents 逐格量宽 只在几百行内用，或手设宽度

这十五条覆盖了 QTableWidget 日常九成的翻车现场。剩下的那一成，都能归到同一个根源：数据被 item 绑在界面上，改动量一大，界面和数据就得一起搬。搬不动的时候，就是该换 QTableView 加自定义模型的时候了。
