本篇讲模型/视图架构本身：QAbstractItemModel 怎么实现，数据怎么读写，改完怎么通知视图，QTableView 怎么配。

不讲 QTableWidget 的 item 级 API，不讲 QTreeView 的展开折叠，不讲委托的完整编辑控件体系。这三块在同目录另外三篇。本篇只在「自定义显示风格」一章碰委托的 paint，因为进度条、焦点虚线、复选框外观绕不开它。

读之前手上要有个能跑的 Qt Widgets 工程，知道信号槽怎么连。代码按 Qt 5 写，Qt 6 的差异在最后一章点出来。

一、模型/视图架构解决什么问题 #

先看不用它的写法。一个文件传输工具，界面上一张表：任务名、大小、进度、速度、剩余时间、状态。很多人一开始把数据读取、业务计算、界面刷新全塞进一个窗口类，定时器里对着 QTableWidget 逐格 setText。

两个毛病跑起来就露。一是数据存了两份：成员变量一份，QTableWidget 内部又存一份 item，两边手动同步，漏一行就是显示和数据对不上。二是换展示方式就得改业务代码，今天树形看目录，明天按状态分组，界面一换刷新逻辑重写。

模型/视图把这两件事切开：

  • 模型只负责「数据怎么取」。它不关心谁来画、画成什么颜色，只回答三个问题：几行、几列、第 r 行第 c 列是什么。
  • 视图只负责「数据怎么画」。它不存数据，也不知道数据从哪来，只按自己的行高列宽把模型给的内容摆到屏幕上。

两者之间的接头只有一套接口：

text
rowCount(parent)      —— 这个模型有多少行
columnCount(parent)   —— 有多少列
data(index, role)     —— 这个位置，按这个角色，给我什么
index(row, column)    —— 把行列号翻译成一个索引对象

视图永远不摸你的内部数组。它拿到行数就画那么多行，画到哪个格子就调一次 data()。你的链表是 QList 还是 std::vector，从 SQLite 捞的还是从网络收的，视图一无所知。

切开之后多了个新义务：改了数据得主动告诉视图。视图不轮询。你把第 3 行的进度从 40 改成 41，不发信号，屏幕上那个 40 就永远停着。这条规矩贯穿全篇。

来路是 MVC：模型持数据，视图管渲染，控制器接输入。Qt 把控制器并进了视图——鼠标点击、键盘移动、双击进编辑，视图自己消化。空出的位置塞进委托（Delegate），专管单元格怎么画、怎么编辑。

text
数据源（内存链表 / 数据库 / 文件流）
      ↓ 读取                  ↑ 信号
   Model ── 索引 ──→ View（QTableView）
   rowCount / columnCount    行高、列宽、选中、滚动
   data / index                    ↓
                              Delegate
                        paint 绘制 / createEditor 编辑

最直接的收益是一份数据挂多个视图。同一个模型，左边 QTreeView 看树，右边 QTableView 看详情，改一处两处一起变，同步代码一行不写。

第二层收益是内存。QTableWidget 给每个单元格 new 一个 QTableWidgetItem，十万行十列就是一百万个对象，光构造就够卡。模型里一行只是一个 QStringList。

代价是代码变多：要自己写 rowCount、data、setData，还要管信号。所以别一刀切：

场景 选择 理由
几十到几百行，写死不变 QTableWidget 直接 setItem，不用写模型类
万行以上，要求秒开 自定义模型 视图只对可见区域调 data()
数据在数据库或外部二进制流里 自定义模型 按需查询，不全量载入
同一份数据给多个视图看 自定义模型 共享模型实例
高频更新（进度、行情、日志） 自定义模型 + dataChanged 局部重绘，不重建
界面高度定制（复合卡片） 自定义模型 + 自定义委托 绘制完全自控

判断标准一条：数据和界面会不会各自独立变化。会，就上模型/视图。不会，QTableWidget 更快收工。

二、三个角色：模型、视图、委托 #

角色 职责 该干的事 不该干的事
模型 Model 持有并暴露数据 存取数据、算行列数、按 role 返回内容、改完发信号 画像素、读鼠标、弹窗
视图 View 布局与交互 行高列宽、选中、滚动、编辑触发、把索引交给委托 存业务数据、算业务值
委托 Delegate 单个格子的绘制与编辑 paint 画内容、createEditor 给编辑控件 存数据、管整表布局

模型是唯一知道数据长什么样的角色。所有模型都基于 QAbstractItemModel。想省事用 QStandardItemModel，它内部替你维护一棵 item 树；想控性能、想直接映射自己的 QList，就继承 QAbstractTableModel（表格）或 QAbstractListModel（一维列表）。QAbstractTableModel 已经把 index() 和 parent() 写好——表格是一层平铺结构，父索引永远是空，这两件没得选。

视图负责把索引铺到屏幕上。QListView 一列，QTableView 二维网格，QTreeView 可展开的层级。它干的活比看上去多：滚动时只对可见区域调 data()，这是大数据量不卡的关键；选中区域怎么算、编辑怎么触发、拖拽怎么放，都在视图里。

委托是视图派出去画单个格子的工人。默认委托 QStyledItemDelegate，画文本、画图标、画选中背景、画焦点虚线。它还有个容易忽略的职责：编辑。双击一个格子，视图不自己建输入框，而是问委托 createEditor() 要控件，setEditorData() 填当前值，编辑结束用 setModelData() 写回模型。

三个角色的连接就这几行：

cpp
QTableView *view = new QTableView(this);
TableModel *model = new TableModel(this);

view->setModel(model);                                // 视图认识模型
view->setItemDelegate(new ProgressBarDelegate(this)); // 视图认识委托
model->setModelData(&m_dataList);                     // 模型认识数据源

setModel 是全篇最重要的一句。它在内部把视图的信号槽接到模型的通知信号上：模型发 dataChanged，视图收到就重绘那几个格子；模型发 rowsInserted，视图收到就调整滚动条和行号映射。漏发信号会出问题，不是视图懒，是它真没收到。

一个模型挂多个视图 #

下面这段用 Qt 自带的 QFileSystemModel：左边一棵树，右边一个列表，看的是同一份文件系统数据。

cpp
QFileSystemModel *model = new QFileSystemModel();
model->setRootPath(QDir::currentPath());

// 左视图：树
QTreeView *tree = new QTreeView(splitter);
tree->setModel(model);
tree->setRootIndex(model->index(QDir::currentPath()));   // 只展示当前目录

// 右视图：列表，挂同一个模型实例
QListView *list = new QListView(splitter);
list->setModel(model);
list->setRootIndex(model->index(QDir::currentPath()));

// 想让两边的多选状态也同步，就共用一个 SelectionModel
list->setSelectionModel(tree->selectionModel());

setRootIndex 是树形模型配视图的固定动作：QFileSystemModel 是一棵树，视图默认从根节点展开，不压缩显示范围就会把整个磁盘铺出来。表格模型的 parent 恒为空，用不上它。

setSelectionModel 那行可选。默认每个视图有自己的选中模型，共享数据不共享选中；共用之后，树上点中的文件列表里也高亮。

三、QAbstractItemModel 的必须实现 #

自己写模型绕不过这张清单。前几个是纯虚函数，不实现编译过不去；后面几个有默认实现，不重写就等于放弃对应功能。

接口 是否必须 作用 表格模型的写法
rowCount(parent) 必须 返回行数 数据容器 size()
columnCount(parent) 必须 返回列数 第一行的列数或表头数量
data(index, role) 必须 按角色返回内容 switch(role) 分派
index(row, col, parent) 必须 行列号转索引 用 createIndex，基类已实现
parent(index) 必须 返回父索引 表格恒返回 QModelIndex()
headerData(...) 可选 表头文字 返回自己的表头列表
flags(index) 可选 能否选中、编辑、勾选 位或标志位
setData(index, value, role) 可选 写入数据 改容器 + 发 dataChanged
insertRows / removeRows 可选 结构增删 成对调 begin* / end*

几个细节。

index() 不要自己实现，用 createIndex()。 表格模型直接用基类的就够，它内部就是 createIndex(row, column)。createIndex 是 protected，只能在模型内调，它构造出的 QModelIndex 记住三件事：模型指针、行、列。视图拿索引回来找你要数据时，你能通过 index.model() 反查是不是自己。

parent 参数不是给你用的。 表格是平的，所有行的父都是空，rowCount 里写 Q_UNUSED(parent) 然后直接返回总数就行。别在这儿加条件判断，除非你真在写树。

data() 第一件事是校验索引。 视图在边界情况下会传无效索引，容器也还没赋值。先 if (!index.isValid()) return QVariant();，再判空指针，再判越界。漏了这三步，运行时段错误，栈里看不出是谁传的。

返回值统一用 QVariant。 不该有内容时返回默认构造的空 QVariant()，别返回 QVariant("")，也别 QVariant(0)。视图靠 isValid() 判断这个 role 有没有数据，返回空字符串会被当成「有内容且为空」，该显示占位的地方就空着。

写表格一律继承 QAbstractTableModel，别从 QAbstractItemModel 硬啃。

四、自定义模型：只读表格 #

从最简单的开始：只读。数据放在 QList<QStringList> 里，模型只当二传手。

cpp
#pragma once
#include <QAbstractTableModel>
#include <QStringList>
#include <QList>

class TableModel : public QAbstractTableModel
{
    Q_OBJECT
public:
    explicit TableModel(QObject *parent = nullptr);
    ~TableModel();

    int rowCount(const QModelIndex &parent = QModelIndex()) const override;
    int columnCount(const QModelIndex &parent = QModelIndex()) const override;
    QVariant data(const QModelIndex &index, int role = Qt::DisplayRole) const override;
    QVariant headerData(int section, Qt::Orientation orientation,
                        int role = Qt::DisplayRole) const override;
    Qt::ItemFlags flags(const QModelIndex &index) const override;

    void setModelData(QList<QStringList> *dataList);
    void setHorizontalHeaders(const QStringList &headers);
    void refreshModel();

signals:
    void updateCount(int count);

private:
    QList<QStringList> *m_rowList;   // 指向外部数据，模型不拥有它
    QStringList         m_headerList;
};

cpp
TableModel::TableModel(QObject *parent)
    : QAbstractTableModel(parent), m_rowList(nullptr)
{
}

void TableModel::setModelData(QList<QStringList> *dataList)  { m_rowList = dataList; }
void TableModel::setHorizontalHeaders(const QStringList &h)  { m_headerList = h; }

int TableModel::rowCount(const QModelIndex &parent) const
{
    Q_UNUSED(parent)
    return m_rowList ? m_rowList->size() : 0;
}

int TableModel::columnCount(const QModelIndex &parent) const
{
    Q_UNUSED(parent)
    if (m_rowList && m_rowList->size() > 0)
        return m_rowList->at(0).size();          // 有数据时看第一行
    return m_headerList.size();                  // 空表时用表头数量兜底
}

QVariant TableModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid() || !m_rowList)          // 三道校验，一个都不能少
        return QVariant();

    int row = index.row();
    int col = index.column();
    if (row >= m_rowList->size() || col >= m_rowList->at(0).size())
        return QVariant();

    if (role == Qt::DisplayRole)
        return m_rowList->at(row).at(col);
    else if (role == Qt::TextAlignmentRole)
        return int(Qt::AlignLeft | Qt::AlignVCenter);   // 靠左、垂直居中

    return QVariant();
}

QVariant TableModel::headerData(int section, Qt::Orientation orientation, int role) const
{
    if (role == Qt::DisplayRole && orientation == Qt::Horizontal)
        if (section < m_headerList.size())
            return m_headerList.at(section);
    return QVariant();
}

Qt::ItemFlags TableModel::flags(const QModelIndex &index) const
{
    if (!index.isValid())
        return Qt::NoItemFlags;
    return Qt::ItemIsEnabled | Qt::ItemIsSelectable;    // 只读、可选择
}

void TableModel::refreshModel()
{
    beginResetModel();      // 通知视图：模型整体重置，整表重画
    endResetModel();
    emit updateCount(rowCount());
}

几个设计选择。

模型持有的是指针，不是数据。 m_rowList 指向视图类里的 QList<QStringList>，业务层在外面直接增删改这个链表，模型只读它。好处是改数据不用绕模型接口，坏处是生命周期要自己管：视图销毁前链表不能先死，否则 data() 里就是野指针。另一种写法是模型自己持有 m_data，对外给 appendRow() / removeRow()，封装更严。两种都行，别混着来。

columnCount 必须有两个兜底。 有数据时用第一行的长度（隐含约定每行等长，插入行时要保证），没数据时退回表头数量。不然空表刚 setModel 那一瞬列数返回 0，视图什么都不画，表头也出不来。

flags 里没有 Qt::ItemIsEditable，这就是只读的来源。 用户双击进不了编辑态，setData 压根不会被调用。想放开编辑，加标志位并实现 setData。

视图那边就三行：

cpp
TableModel *model = new TableModel(this);
model->setHorizontalHeaders(QStringList() << tr("任务名") << tr("大小") << tr("进度"));
model->setModelData(&m_dataList);
view->setModel(model);

表头文字从 headerData 来，单元格文字从 data 来。视图一行都不碰 m_dataList。

五、自定义模型：可编辑 #

只读模型加三样东西就能改：flags 加编辑标志、实现 setData、setData 里发 dataChanged。

cpp
Qt::ItemFlags TableModel::flags(const QModelIndex &index) const
{
    if (!index.isValid())
        return Qt::NoItemFlags;
    // 在只读基础上打开可编辑
    return Qt::ItemIsEnabled | Qt::ItemIsSelectable | Qt::ItemIsEditable;
}

bool TableModel::setData(const QModelIndex &index, const QVariant &value, int role)
{
    if (!index.isValid() || !m_rowList)
        return false;

    if (role != Qt::EditRole && role != Qt::DisplayRole)
        return false;

    int row = index.row();
    int col = index.column();
    if (row >= m_rowList->size() || col >= m_rowList->at(row).size())
        return false;

    QString newText = value.toString();
    if ((*m_rowList)[row][col] == newText)
        return true;                       // 值没变，不必通知

    (*m_rowList)[row][col] = newText;      // 真正写回数据源

    emit dataChanged(index, index, {Qt::DisplayRole, Qt::EditRole});
    return true;
}

要点按顺序。

setData 必须真的写回数据源。 视图的编辑流程是：双击 → 委托 createEditor 建输入框 → setEditorData 填值 → 用户改完 → setModelData 调你的 setData → 编辑器关闭。setData 里什么都没写却 return true，编辑器一关，视图重新调 data() 取值，屏幕上还是旧内容。用户会以为输入被吞了。

别只看 DisplayRole。 走编辑流程时委托传进来的是 Qt::EditRole。只处理 DisplayRole，双击改完按回车没反应。

值没变就别发信号。 一个 if 省掉一堆无谓重绘。滚动、焦点切换都会触发 setData。

roles 列表要写对。 它告诉视图「这些角色变了」，视图只重画声明过的角色。省略第三个参数也能工作（视图保守全刷），写出来更稳。

增删行不能靠 dataChanged，那是改内容用的。结构变了要走专门接口（成对规则的细节在第八章）：

cpp
void TableModel::appendRow(const QStringList &rowData)
{
    int row = m_rowList->size();
    beginInsertRows(QModelIndex(), row, row);   // 插入前：预留位置
    m_rowList->append(rowData);                 // 改数据
    endInsertRows();                            // 插入后：落地
}

void TableModel::removeRow(int row)
{
    if (!m_rowList || row < 0 || row >= m_rowList->size())
        return;
    beginRemoveRows(QModelIndex(), row, row);
    m_rowList->removeAt(row);
    endRemoveRows();
}

两句 begin* / end* 中间夹的必须是真正的数据修改，而且只夹这一件事。视图在 begin* 里把行号映射、选中区域、滚动条位置算好并挂起刷新，end* 里一次性应用。中间去改别的东西，视图算出来的跟你实际的数据就对不上。

六、模型索引 QModelIndex 与持久索引 #

视图不能拿指针直接指你的内存。QList 扩容一次元素地址全变，视图手上那堆指针立刻失效。两者之间传的是一个轻量值对象 QModelIndex。

一个索引由四样东西组成：模型指针、行号、列号、内部指针。内部指针留给树形结构记父节点，表格模型里是空的。

cpp
// 顶级节点（父索引为空）的第 0 行第 0 列
QModelIndex indexA = model->index(0, 0, QModelIndex());

// 以 A 为父节点再往下取（树形结构才用得上）
QModelIndex indexB = model->index(0, 0, indexA);

模型内部造索引要用 createIndex：

cpp
QModelIndex changedIndex = createIndex(row, 2);          // 告诉框架「第 row 行第 2 列」
QModelIndex nodeIndex    = createIndex(row, 0, node);    // 树形模型：内部指针挂自己的节点

createIndex(row, column) 和 createIndex(row, column, void *ptr) 两个重载。后者挂一个指针，树形模型用它指向真实节点，data() 里再 index.internalPointer() 取回来。表格模型用不上，行列号够定位。

QModelIndex 只是一次快照，这是最大的坑：

cpp
// ❌ 这样写会出错
QModelIndex idx = model->index(5, 0);
model->removeRow(0);                     // 第 5 行变成了第 4 行，idx 还指着 5
QString text = idx.data().toString();    // 拿到错行，或者干脆无效

排序、插入、删除之后，之前存的 QModelIndex 会指向别处。isValid() 只挡得住「索引本身作废」，挡不住「指向的已经是另一行」。

要长期盯住某条数据，用 QPersistentModelIndex，框架会在结构变化时自动更新它：

cpp
QPersistentModelIndex m_lastSelected;    // 成员变量

void onSelectionChanged(const QModelIndex &current)
{
    if (current.isValid())
        m_lastSelected = QPersistentModelIndex(current);
}

void onRefreshClicked()
{
    // 中间插了几十行、删了几行，它仍然指向原来那条数据
    if (m_lastSelected.isValid())
        view->scrollTo(m_lastSelected);
}

代价是开销。每个 QPersistentModelIndex 都向模型注册，结构变化时模型要遍历更新。只在真正需要跨刷新追踪的地方用，别在循环里成批造。

index() 的调用频次比你想的高：滚动一格问一次，画一层问一次，data() 里跨列取值又问一次。所以别在 index() 或 data() 里查数据库、读文件——那些事在数据进模型之前就该做完。

七、数据的读写与角色 role #

一个格子里的信息不止一条。同一行「report.pdf」，界面要显示文件名，前面挂类型图标，悬停出完整路径，双击进编辑框，内部还记着数据库主键。

这些塞不进 data() 一个返回值。Qt 的办法是给每次询问加一个 role 参数：同一个 index，你问什么角色，我答什么内容。

role 值类型 视图拿它干什么 典型用途
DisplayRole QString 画单元格文字 文件名、进度值、状态
EditRole 任意 编辑时填进编辑器的初始值 常与 DisplayRole 一致
DecorationRole QIcon 在文字旁画图标 文件类型、状态色块
CheckStateRole int 画复选框 勾选列
ToolTipRole QString 悬停出提示框 完整路径、错误详情
TextAlignmentRole int 文本对齐 数字右对齐、状态居中
BackgroundRole QColor 单元格背景 悬浮高亮、失败行标红
ForegroundRole QColor 文字颜色 已完成行变灰
FontRole QFont 字体 标题行加粗
UserRole 任意 视图不用，给你自己 存数据库主键、存对象指针

UserRole 往后（+1、+2……）都留给你自定义。视图不认识这些角色，它只在需要时来问，你按约定返回。

data() 里按 role 分派，switch 最好读：

cpp
QVariant TableModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid() || !m_rowList)
        return QVariant();

    int row = index.row();
    int col = index.column();
    if (row >= m_rowList->size() || col >= m_rowList->at(row).size())
        return QVariant();

    switch (role)
    {
    case Qt::DisplayRole:
        return m_rowList->at(row).at(col);

    case Qt::EditRole:                       // 编辑时给编辑器的初始值
        return m_rowList->at(row).at(col);

    case Qt::TextAlignmentRole:              // 数字列右对齐
        if (col == 1 || col == 3)
            return int(Qt::AlignRight | Qt::AlignVCenter);
        return int(Qt::AlignLeft | Qt::AlignVCenter);

    case Qt::ToolTipRole:                    // 列宽不够时悬停看全
        return m_rowList->at(row).at(0);

    case Qt::UserRole:                       // 业务主键捎给界面层
        return m_rowList->at(row).at(col);

    default:
        break;
    }
    return QVariant();
}

每条分支前面都要能落到 return，末尾统一兜底。写成 if / else if 链也行，角色一多就散。

取数据时角色是第二个参数：

cpp
QVariant text    = model->data(index, Qt::DisplayRole);     // 要显示的文字
QVariant icon    = model->data(index, Qt::DecorationRole);  // 要显示的图标
QVariant tooltip = model->data(index, Qt::ToolTipRole);     // 悬浮提示
QVariant dbId    = model->data(index, Qt::UserRole);        // 自己绑的业务 ID

QVariant 用之前要转：toString()、toInt()、toDouble()，转失败给默认值。别直接往 QString 里塞，编译过了行为也不对。

role 最有用的一招是跨列读取。 委托画第 1 列时，可以回头问同一行别的列：

cpp
// 在委托的 paint 里，index 是当前要画的格子（第 1 列）
const QAbstractItemModel *itemModel = index.model();
int currentRow = index.row();

QString filename  = itemModel->data(itemModel->index(currentRow, 2), Qt::DisplayRole).toString();
qint64  size      = itemModel->data(itemModel->index(currentRow, 3), Qt::DisplayRole).toLongLong();
qint64  totalSize = itemModel->data(itemModel->index(currentRow, 4), Qt::DisplayRole).toLongLong();
double  speed     = itemModel->data(itemModel->index(currentRow, 5), Qt::DisplayRole).toDouble();

数据全在模型里，画的时候现取。模型不必为「第 1 列要显示什么组合内容」专门准备字段。

八、数据更新与信号通知 #

模型改完数据不发信号，视图就是不知道。这不是视图懒，是它没在轮询。

场景 必须发的信号 要点
单元格内容变了 dataChanged(topLeft, bottomRight, roles) 精确到改动范围
插入行/列 beginInsertRows + endInsertRows 两句之间夹数据修改
删除行/列 beginRemoveRows + endRemoveRows 同上
整体换数据 beginResetModel + endResetModel 状态全丢，代价最大
表头文字变了 headerDataChanged(orientation, first, last) 改完表头列表再发
数据重排但结构没变 layoutChanged() 排序后通知视图重取索引

dataChanged 是三个参数的重载，topLeft 和 bottomRight 圈出改动范围，roles 是 QVector<int>，列出变化的角色（不传就是全变）：

cpp
emit dataChanged(index(row, 2), index(row, 2), {Qt::DisplayRole});          // 一个格子
emit dataChanged(index(row, 0), index(row, colCount - 1), {Qt::DisplayRole}); // 一整行
emit dataChanged(index(topRow, 0), index(bottomRow, colCount - 1));         // 一片区域

只改一格就传两个一样的索引。范围给得越准，重绘的格子越少；给大了不出错，就是白画。

beginInsertRows / endInsertRows 必须成对。 这条要单独强调，因为漏了不报错，会崩。

视图内部维护一张行号到内部结构的映射表。beginInsertRows 让视图先把这张表冻住、把新行要占的位置预留出来，并记住当前滚动条和选中状态；endInsertRows 再把预留位置正式填上，顺手调整滚动条和选中区域。漏了 beginInsertRows 直接收尾，视图看到的是「凭空多了一堆行」，它那张表还是旧长度，接着往下算就越界。

漏 begin* 的典型后果：

  • 行数对不上，滚动条能拖到不存在的位置。
  • 选一片区域后删一行，选中范围错位。
  • 排序视图（QSortFilterProxyModel）里直接崩，栈里是 QModelIndex 的断言。
  • 界面偶尔多出一行空白，重启又没了，最难查的那种。

模板长这样，中间只放数据修改：

cpp
beginInsertRows(QModelIndex(), first, last);   // 预留
m_rowList->insert(first, newRow);              // 只干这一件事
endInsertRows();                               // 落地

beginInsertRows 第一个参数是父索引，表格传空。first 和 last 是新行在插入后的位置区间，插一行就是同一个值。

多行删除要一次性通知区间，别在循环里逐个删：

cpp
// 删第 3 到第 7 行，从后往前删，前面行号才不被挤掉
beginRemoveRows(QModelIndex(), 3, 7);
for (int i = 7; i >= 3; --i)
    m_rowList->removeAt(i);
endRemoveRows();

reset 与 dataChanged 的区别 #

beginResetModel / endResetModel 是「我把模型整个换了」。视图收到后清空所有内部状态：选中项、当前焦点、滚动位置、排序指示器，然后从头问一遍行列数，重新铺一遍。

dataChanged 是「某几个格子内容变了，结构没动」。视图只重绘对应区域，其他一概不动。

两者不能混用。改了个进度值却发 reset，用户正选着的那行会瞬间失去选中，滚动条跳回顶部。

信号位置也要对：begin* 发在数据改之前，end* 发在数据改完之后。顺序反了，视图会在数据还是旧的时候去算新布局。

九、实时刷新数据的正确做法 #

场景很具体：文件传输工具，几十上百个任务，进度每秒都涨。第一版代码在定时器里调 m_model->refreshModel()，里面是 beginResetModel / endResetModel，跑起来四个症状：

  1. 表格闪，整表重画，生硬。
  2. 用户选中的行下一帧没了。beginResetModel 把所有选中状态清掉。
  3. 滚动条跳回顶部。用户正看第 80 个任务，一秒后回到第 1 行。
  4. CPU 高。一百行 × 六列，每秒重建一遍布局。

reset 是给「整体换数据」用的，不是给「刷新数值」用的。这场景用 reset，交互直接残废。正确做法是只改数据，只通知变化的那几个格子：

cpp
void TableModel::updateTaskRow(int row, int progress, double speed, const QString &remain)
{
    if (!m_rowList || row < 0 || row >= m_rowList->size())
        return;

    QStringList &rowList = (*m_rowList)[row];
    rowList[2] = QString::number(progress);
    rowList[3] = formatSpeed(speed);
    rowList[4] = remain;

    // 第 2 到第 4 列一起变，一次通知覆盖整段，不碰选中和滚动位置
    emit dataChanged(index(row, 2), index(row, 4), {Qt::DisplayRole});
}

定时器里改成逐行调，没跑的任务直接跳过：

cpp
void DownloadView::onTimerTick()
{
    for (int row = 0; row < m_model->rowCount(); ++row)
    {
        TaskInfo info = m_taskList.at(row);
        if (!info.isRunning())
            continue;                     // 没跑的任务不动，省一次重绘
        m_model->updateTaskRow(row, info.progress, info.speed, info.remainText);
    }
}

把 refreshModel() 从定时器里删掉，这是全文最有性价比的一处修改。上千行高频更新时 CPU 占用掉一个数量级，用户的拖拽和选中也不再被打断。

一万行的表一秒发一万个 dataChanged 也不至于卡死——视图只画可见的二三十行，其余的不调 data()。滚出去的行数据照样在涨，滚回来那一帧重新取到的就是最新值。

局部重绘：整行悬浮高亮 #

update(index) 是视图级别的局部重绘，跟 dataChanged 同一思路的两个层级。鼠标在表上移动要让整行变色，走的就是这条路。

视图侧捕获移动和离开：

cpp
void TableView::mouseMoveEvent(QMouseEvent *event)
{
    int row = indexAt(event->pos()).row();
    updateRow(row);                    // 换 hover 行，重绘新旧两行
    QTableView::mouseMoveEvent(event);
}

void TableView::updateRow(int row)
{
    if (row == m_currentRow)
        return;                        // 还在同一行，什么都不做

    m_model->setHoverRow(row);
    int columnCount = model()->columnCount();
    for (int i = columnCount - 1; i >= 0; --i) {
        update(model()->index(m_currentRow, i));   // 旧行
        update(model()->index(row, i));            // 新行
    }
    m_model->showToolTip(row);
    m_currentRow = row;
}

void TableView::leaveEvent(QEvent *event)
{
    m_model->setHoverRow(-1);          // 移出表格，清高亮
    int columnCount = model()->columnCount();
    for (int i = columnCount - 1; i >= 0; --i)
        update(model()->index(m_currentRow, i));
    m_currentRow = -1;
    QTableView::leaveEvent(event);
}

模型侧在 data() 里按 hover_row 给背景色：

cpp
void TableModel::setHoverRow(int hoverRow) { m_hoverRow = hoverRow; }

QVariant TableModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid())
        return QVariant();

    int row = index.row();
    if (row < 0 || row >= m_listFile.size())
        return QVariant();

    switch (role)
    {
    case Qt::BackgroundRole:
        if (row == m_hoverRow)                    // 悬停的行给淡蓝背景
            return QColor(180, 200, 220);
        break;
    case Qt::DecorationRole:   break;             // 图标
    case Qt::DisplayRole:      break;             // 文本
    case Qt::TextAlignmentRole: break;
    default:                   break;
    }
    return QVariant();
}

为什么不能用 QSS 办这件事：QTableView::item:hover 只作用单个格子，配了整行选中就很割裂；而且 QSS 判断不了「哪一行被悬停」，它没有行的概念，只有 item 的概念。要整行联动，只能在 data() 里按行号返回颜色，再由视图逐格重绘。

Qt::BackgroundColorRole 是 Qt::BackgroundRole 的旧名，新代码用后者。

十、QTableView 的配置 #

QTableView 默认观感接近 Excel，做产品得挨个调。

配置 调用 说明
整行选中 setSelectionBehavior(SelectRows) 点一格选一行
多选 setSelectionMode(ExtendedSelection) Ctrl 点选、Shift 连选
禁编辑 setEditTriggers(NoEditTriggers) 双击也不进编辑
隔行变色 setAlternatingRowColors(true) 要配 alternate-background-color
隐藏网格 setShowGrid(false) 扁平界面的默认做法

一个配好的构造函数：

cpp
TableView::TableView(QWidget *parent) : QTableView(parent)
{
    // 观感
    setAlternatingRowColors(true);
    setShowGrid(false);
    horizontalHeader()->setStretchLastSection(true);
    verticalHeader()->setVisible(false);

    // 交互
    setSelectionBehavior(QAbstractItemView::SelectRows);
    setSelectionMode(QAbstractItemView::ExtendedSelection);
    setEditTriggers(QAbstractItemView::NoEditTriggers);

    // 组装模型与委托
    m_model = new TableModel(this);
    setModel(m_model);
    m_delegate = new ProgressBarDelegate(this);
    setItemDelegate(m_delegate);

    // 表头与数据源
    QStringList header;
    header << tr("任务名") << tr("大小") << tr("进度")
           << tr("速度") << tr("剩余时间") << tr("状态");
    m_model->setHorizontalHeaders(header);
    m_model->setModelData(&m_dataList);
}

SelectRows 和 ExtendedSelection 是最常配的一对：前者决定「点一格选一行还是选一格」，后者决定「能不能多选」。配了整行选中，selectedIndexes() 返回的仍是一堆单元格索引，要自己去重成行号。

多行反向删除 #

删除选中行是固定需求，这里有个顺序问题必须处理。

cpp
void TableView::removeSelectedRows()
{
    QModelIndexList selectedIdx = selectedIndexes();
    if (selectedIdx.isEmpty())
        return;

    // 1. 单元格索引去重成行号
    QList<int> rowsToDelete;
    foreach (const QModelIndex &index, selectedIdx)
        if (!rowsToDelete.contains(index.row()))
            rowsToDelete.append(index.row());

    // 2. 从大到小排序
    std::sort(rowsToDelete.begin(), rowsToDelete.end(), std::greater<int>());

    // 3. 从后往前删
    foreach (int row, rowsToDelete)
        m_model->removeRow(row);
}

为什么必须倒序：删掉第 2 行之后，原来的第 5 行变成第 4 行。接着按顺序删第 5 行，删掉的是原来的第 6 行，还漏一行没删干净。倒着删，后面的下标不受前面影响。

removeRow 内部走 beginRemoveRows / endRemoveRows，视图跟着更新行号映射。手写 m_dataList.removeAt(row) 却跳过信号，界面会留下删不掉的残影。

单元格悬浮提示 #

文本比列宽长时，鼠标停上去给完整内容。三步。

第一步，开鼠标追踪。视图默认只在按键按下时才收移动事件，槽函数要收 entered 就得先开它：

cpp
table_view->setMouseTracking(true);

第二步，写槽函数。QCursor::pos() 取屏幕坐标，提示框浮在光标位置：

cpp
void TableView::showToolTip(const QModelIndex &index)
{
    if (!index.isValid())
        return;

    QString fileName = m_listFile.at(index.row());   // 该行的完整路径
    if (fileName.isEmpty())
        return;

    QToolTip::showText(QCursor::pos(), fileName);
}

第三步，接视图的 entered 信号，鼠标滑过某项时它会带着那个索引发出来。漏了第一步，这个信号一次都不发，还不报错：

cpp
connect(table_view, &QTableView::entered, this, &TableView::showToolTip);

提示内容也可以直接从 ToolTipRole 来——在 data() 里返回完整路径，视图自己弹，连 connect 都省。要控弹出时机和位置，才需要上面这一套。

隐藏选中时的聚焦虚线 #

Qt 默认在当前项周围画一圈虚线焦点框，选中时特别扎眼。去掉的办法是继承委托，在 paint 里把焦点状态位抹掉：

cpp
void StyledDelegate::paint(QPainter *painter,
                           const QStyleOptionViewItem &option,
                           const QModelIndex &index) const
{
    QStyleOptionViewItem viewOption(option);

    // 位异或把 State_HasFocus 清掉
    if (viewOption.state & QStyle::State_HasFocus)
        viewOption.state = viewOption.state ^ QStyle::State_HasFocus;

    QStyledItemDelegate::paint(painter, viewOption, index);
}

& 判断有没有这一位，^ 把它翻掉（有则清、无则不变）。改完把选项传给父类，其余绘制照旧。装到视图：

cpp
table_view->setItemDelegate(styled_delegate);

setItemDelegate 是整表替换。已经装了进度条委托的话，把清焦点的逻辑并进那个委托，别装两个——后装的会盖掉前一个。

整行选中色用 QSS #

text
QTableView { border: none; background: white; }
QTableView::item:selected { color: white; background: rgb(34, 175, 75); }

配了 SelectRows 之后这一条会让整行变色。用 QSS 之后别再在 data() 里返回 BackgroundRole 处理选中，两套机制打架，QSS 会赢一半，看着像没刷新。

十一、在单元格里放复选框 #

勾选列是最常见的交互：一批任务勾中一起开始，一批文件勾中一起删。做法有四种。

方法 实现途径 优点 缺点
1. 激活编辑委托 重写 createEditor() 返回 QCheckBox 符合经典委托流程 必须先双击该格，复选框才被创建，做不到「直接看到」
2. 重写 Model（推荐） 重写 flags()、data()、setData()，走 CheckStateRole 标准角色机制，性能最好，增删改查全支持 要自定义模型
3. 嵌入静态控件 setIndexWidget(index, widget) 硬塞一个 实现最快 官方写明只适合静态内容；频繁更新、拖拽、增删会出性能与显示冲突
4. 自定义委托重绘 在 paint() 里用 QStylePainter 手画 可扩展性最高，能混画按钮、图标 要自己算点击区域、处理鼠标事件

选第二种。它不建控件对象，复选框是「画」出来的，一万行也不额外吃内存，状态存在模型里跟着数据走。

先准备容器记状态，QMap<int, Qt::CheckState> 够了，键是行号：

cpp
QMap<int, Qt::CheckState> m_checkStateMap;   // 行号 → 勾选状态

第一步，flags() 开勾选权限。 只有标了 Qt::ItemIsUserCheckable 的格子才响应点击，否则画出来也点不动：

cpp
Qt::ItemFlags TableModel::flags(const QModelIndex &index) const
{
    if (!index.isValid())
        return Qt::NoItemFlags;

    if (index.column() == 0)    // 只在第 0 列放复选框
        return Qt::ItemIsEnabled | Qt::ItemIsSelectable | Qt::ItemIsUserCheckable;

    return Qt::ItemIsEnabled | Qt::ItemIsSelectable;
}

第二步，data() 返回状态。 视图画这一格时会来问 CheckStateRole：

cpp
QVariant TableModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid())
        return QVariant();

    switch (role)
    {
    case Qt::CheckStateRole:
        if (index.column() == 0) {
            if (m_checkStateMap.contains(index.row()))
                return m_checkStateMap[index.row()];
            return Qt::Unchecked;      // 没记录过就当未勾选
        }
        break;
    case Qt::DisplayRole:              // 复选框右侧的文字，可留空
        break;
    default:
        break;
    }
    return QVariant();
}

第三步，setData() 存状态。 用户点一下，视图不发数据也不改界面，它发一个 CheckStateRole 的写请求给模型：

cpp
bool TableModel::setData(const QModelIndex &index, const QVariant &value, int role)
{
    if (!index.isValid())
        return false;

    if (role == Qt::CheckStateRole && index.column() == 0)
    {
        m_checkStateMap[index.row()] = (value.toInt() == Qt::Checked)
                                     ? Qt::Checked : Qt::Unchecked;
        emit dataChanged(index, index, {Qt::CheckStateRole});   // 不发就不刷新
        return true;
    }
    return false;
}

三处都不能少。flags 少了 ItemIsUserCheckable，点击没反应；data 不返回 CheckStateRole，格子空着；setData 不存状态，点了闪一下弹回。

value.toInt() 拿到的是 Qt::Checked（2）或 Qt::Unchecked（0），中间还有 Qt::PartiallyChecked（1），三态复选框靠它。

用 QMap 存状态的话，删行时要同步重排键，把所有大于 row 的键减一，否则勾选状态集体错位一行。状态也可以直接存进行数据的某一列，删行时跟着行走，省掉这段重排。

一键全选与表头复选框 #

行内复选框搞定后，接着想要表头也放一个，点一下全选。很多人第一反应是让 headerData 返回 CheckStateRole：

cpp
// ❌ 无效：表头不理这个角色
QVariant TableModel::headerData(int section, Qt::Orientation orientation, int role) const
{
    if (role == Qt::CheckStateRole)
        return Qt::Checked;      // 不会有任何复选框出现
    return QVariant();
}

原因在 Qt 源码里：QHeaderView 绘制表头时只处理 DisplayRole、DecorationRole、FontRole 等少数几个角色，CheckStateRole 的渲染逻辑压根没写。返回什么都不画。

要表头有复选框，只能子类化 QHeaderView：

  1. 重写 paintSection，用 QStylePainter 在指定区域手画 QStyle::CE_CheckBox（或先画 CE_Header 再叠复选框）。
  2. 重写 mousePressEvent，判断点击位置是否落在复选框矩形内，是就翻转状态、发自定义信号 checkAllToggled(bool)。
  3. 视图接住信号，遍历所有行更新 m_checkStateMap，发一次覆盖整列的 dataChanged。

全选不一定非要表头复选框。表格外面放一个普通 QCheckBox 按钮，逻辑一样，代码少一半。

十二、自定义显示风格 #

默认委托只画一行文字。要放进度条、要放「文件名 + 速度 + 底部细进度条」的复合卡片，就得自己动手。

先说简单的：某一列整体换成进度条。

cpp
void ProgressBarDelegate::paint(QPainter *painter,
                                const QStyleOptionViewItem &option,
                                const QModelIndex &index) const
{
    if (index.column() != 2)      // 只对第 2 列（进度列）动刀
    {
        QItemDelegate::paint(painter, option, index);   // 其余列交给父类
        return;
    }

    int progress = index.model()->data(index, Qt::DisplayRole).toInt();

    QStyleOptionProgressBar progressBarOption;
    progressBarOption.state = QStyle::State_Enabled;
    progressBarOption.direction = QApplication::layoutDirection();
    progressBarOption.rect = option.rect;          // 铺满当前单元格
    progressBarOption.fontMetrics = QApplication::fontMetrics();
    progressBarOption.minimum = 0;
    progressBarOption.maximum = 100;
    progressBarOption.textAlignment = Qt::AlignCenter;
    progressBarOption.textVisible = true;
    progressBarOption.progress = progress;
    progressBarOption.text = QString("%1%").arg(progress);

    QApplication::style()->drawControl(QStyle::CE_ProgressBar,
                                       &progressBarOption, painter);
}

关键是 drawControl(QStyle::CE_ProgressBar, ...)。别自己拿 QPainter::drawRect 拼圆角矩形，直接用系统样式引擎，圆角、渐变、暗色主题全自动适配。

option.rect 是视图分给这一格的矩形，赋给 progressBarOption.rect 就是铺满。想留边距自己缩：option.rect.adjusted(2, 6, -2, -6)。

装上去一行，只想管某一列就用 setItemDelegateForColumn(2, delegate)：

cpp
setItemDelegate(new ProgressBarDelegate(this));

复合卡片：一格画三样东西 #

真实需求比进度条复杂。一格同时显示文件名、右上角速度、底部一条细进度条，父类那套绘制不够用，全手绘。

cpp
void DetailProgressBar::paint(QPainter *painter,
                              const QStyleOptionViewItem &option,
                              const QModelIndex &index) const
{
    // 1. 拷样式选项，顺手抹掉焦点虚线
    QStyleOptionViewItem viewOption(option);
    if (viewOption.state & QStyle::State_HasFocus)
        viewOption.state = viewOption.state ^ QStyle::State_HasFocus;

    // 先让父类把背景、选中高亮画好
    QStyledItemDelegate::paint(painter, viewOption, index);

    if (index.column() != 1)
        return;

    const QAbstractItemModel *itemModel = index.model();
    int currentRow = index.row();

    // 2. 跨列取数
    QString filename  = itemModel->data(itemModel->index(currentRow, 2), Qt::DisplayRole).toString();
    qint64  size      = itemModel->data(itemModel->index(currentRow, 3), Qt::DisplayRole).toLongLong();
    qint64  totalSize = itemModel->data(itemModel->index(currentRow, 4), Qt::DisplayRole).toLongLong();
    double  speed     = itemModel->data(itemModel->index(currentRow, 5), Qt::DisplayRole).toDouble();

    if (totalSize <= 0)
        totalSize = 1;
    int progress = static_cast<int>((size * 100.0) / totalSize);
    if (progress > 100)
        progress = 100;

    QString speedText = QString("%1/s").arg(speed);   // 换成自己的速度格式化

    // 3. 排文字：左上角文件名，右上角速度
    painter->drawText(QRect(option.rect.x() + 5, option.rect.y() + 4,
                            option.rect.width() - 80, 16),
                      filename);
    painter->drawText(QRect(option.rect.right() - 75, option.rect.y() + 4, 70, 16),
                      Qt::AlignRight | Qt::AlignVCenter,
                      speedText);

    // 4. 底部一条 6px 高的进度条
    QStyleOptionProgressBar progressBarOption;
    progressBarOption.minimum = 0;
    progressBarOption.maximum = 100;
    progressBarOption.progress = progress;
    progressBarOption.textAlignment = Qt::AlignCenter;
    progressBarOption.textVisible = false;      // 卡片里不写百分比

    int pbHeight = 6;
    int pbMarginY = 4;
    progressBarOption.rect = QRect(option.rect.x() + 5,
                                   option.rect.y() + option.rect.height() - pbHeight - pbMarginY,
                                   option.rect.width() - 10,
                                   pbHeight);

    // 5. 临时 QProgressBar 当样式载体
    QProgressBar tempProgressBar;
    tempProgressBar.setStyleSheet(
        "QProgressBar { border: none; background: rgb(210, 225, 240); border-radius: 3px; }"
        "QProgressBar::chunk { background: rgb(60, 140, 220); border-radius: 3px; }");

    // 6. 把临时组件作为第四个参数传进去
    QApplication::style()->drawControl(QStyle::CE_ProgressBar,
                                       &progressBarOption, painter, &tempProgressBar);
}

几个坐标是手算的：文件名占左边，宽度 rect.width() - 80 给速度留空间；速度靠右，起点在 rect.right() - 75；进度条贴底，rect.y() + rect.height() - pbHeight - pbMarginY。行高变了要跟着调，或者改成按 option.rect.height() 比例算。

开头那次 QStyledItemDelegate::paint 不能省：它画选中背景、隔行色、hover 高亮。不调它，自己画的内容会盖在白底上，选中效果全丢。

委托里画的控件为什么不认 QSS #

你在 main.cpp 里写了全局样式表：

cpp
qApp->setStyleSheet("QProgressBar { border: none; background: #d2e1f0; }"
                    "QProgressBar::chunk { background: #3c8cdc; }");

界面上别的 QProgressBar 都变了，委托里用 drawControl 画出来的还是系统默认灰底。

原因在 QSS 的寻址方式。Qt 解析样式表是沿着控件实例的对象树往上找的。drawControl 的第四个参数是「用哪个控件的样式来画」，传空就没有起点，样式引擎只能用最底层的原始画笔，全局样式自然找不到。

两个解法。

其一，临时造一个控件当载体，把局部样式塞给它，再把指针传进去——就是上面 tempProgressBar 那段。样式写死在代码里，改一次要重编译。

其二，沿用全局样式，把 option.widget（当前视图控件）传进去：

cpp
// 传 option.widget，全局样式就能顺着控件树遗传下来
QApplication::style()->drawControl(QStyle::CE_ProgressBar,
                                   &progressBarOption, painter, option.widget);

option.widget 指向正在画的视图。只要 QTableView 或它的上级设了 QProgressBar 的样式，绘制时就能取到。样式集中写在 qss 文件里，改皮肤不动代码，工程里优先用这个。

第三种做法是不用 drawControl，拿 QPainter 自己画圆角矩形。要什么颜色画什么颜色，代价是暗色主题、高 DPI 缩放、各平台原生观感全得自己处理。

十三、易错点速查 #

症状 原因 修法
数据改了界面不动 没发 dataChanged 改完立刻 emit dataChanged(index, index, roles)
滚动条能拖到不存在的位置 漏了 beginInsertRows 只调了 endInsertRows begin* / end* 成对，中间只放数据修改
删行后选中区域错位 直接改容器，没走 beginRemoveRows 用 removeRows 走标准流程
排序视图里随机崩 结构变化没通知，索引失效 结构变化必发 begin*/end*，排序发 layoutChanged
刷新后选中丢了、滚动跳顶 用了 beginResetModel 改内容用 dataChanged，整体换数据才 reset
单元格空白但数据有值 data() 没处理那个 role，或返回了 QVariant("") 不该有内容就返回空 QVariant()
双击进不了编辑 flags() 没给 Qt::ItemIsEditable 加上标志位
编辑完回车值没保存 setData() 没写回数据源，或只处理了 DisplayRole 处理 EditRole 并写回容器
编辑完界面还是旧值 setData() 里漏了 dataChanged 写回成功就发信号
复选框画出来但点不动 flags() 缺 Qt::ItemIsUserCheckable 补上，且只给放复选框的列
表头复选框怎么都不显示 QHeaderView 不渲染 CheckStateRole 子类化 QHeaderView 重写 paintSection
entered 信号不触发 没开 setMouseTracking(true) 打开鼠标追踪
委托里画的控件不吃 QSS drawControl 没传控件指针 传 option.widget 或临时控件
列数显示为 0、表头也不出 空数据时 columnCount 返回 0 用表头数量兜底

Qt 5 到 Qt 6 的几处变动，迁的时候会碰到：

  • Qt::BackgroundColorRole / Qt::TextColorRole 删了，换成 Qt::BackgroundRole / Qt::ForegroundRole。Qt 5 里两套名字都认，新代码直接用新的。
  • dataChanged 的 roles 参数 Qt 6 是 QList<int>，Qt 5 是 QVector<int>，花括号初始化两种都能过。
  • QItemDelegate 在 Qt 6 被弱化，新代码一律用 QStyledItemDelegate，它走样式引擎，跟 QSS 配合更好。
  • QHeaderView::setResizeMode 早废了，统一用 setSectionResizeMode。
  • QString::SkipEmptyParts 换成 Qt::SkipEmptyParts，QList::toSet() 删了。

一句话收尾：模型管「数据怎么取」，视图管「数据怎么画」，信号是两者之间唯一的桥。桥断了，数据再对，屏幕也不会动。
