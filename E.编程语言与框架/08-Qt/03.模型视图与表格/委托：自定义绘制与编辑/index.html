这一篇只讲委托（Delegate）：一个单元格长什么样、双击之后用什么控件编辑、编辑完的值怎么回到模型。

不讲这些：

  • 模型怎么实现（index / rowCount / data / flags）——见《QTableView 与模型/视图架构》
  • 视图怎么配（列宽、表头、选中模式、编辑触发器）——同上
  • QTableWidget 的便捷用法——见《QTableWidget》
  • 树形结构的展开折叠与层级——见《QTreeView》

读之前，你手上得有一个能跑起来的 QTableView 或 QComboBox。委托是挂在它们身上的，脱离视图没有意义。

一、委托在架构里的位置 #

模型/视图把「数据」和「界面」拆开，中间靠三件东西对接。

角色 基类 干什么 你重写哪个
模型 QAbstractItemModel 存数据、报行列数、按角色给值 data() / setData()
视图 QAbstractItemView 滚动、区域、选中、把格子摆出来 很少重写
委托 QAbstractItemDelegate 一个格子里画什么、用什么控件编辑 paint() / sizeHint() / createEditor()

职责划得很干净：视图只知道「这个单元格占这块矩形」，矩形里的像素它一概不管。它把 option.rect 和 index 一起丢给委托，委托负责把内容填进去。

所以自定义外观、自定义编辑器，全在委托里做。视图和模型一行都不用改。

text
QTableView
   │
   ├── 问模型：data(index, Qt::DisplayRole)  ──►  "60"
   │
   ├── 问委托：sizeHint(option, index)       ──►  这行要多高
   │
   └── 问委托：paint(painter, option, index) ──►  把像素画进 option.rect

编辑走的是另一条路：createEditor 造控件 → setEditorData 灌值 → 用户输入 → setModelData 写回模型。第六章展开这张流程。

这条路就是委托的全部工作。看懂它，剩下的都是细节。

很多人卡住，是把委托当成了「视图的插件」。不对。委托是视图和模型之间的翻译层：模型只会吐 QVariant，视图只会给矩形，中间那个把 QVariant 变成「一行文字加个进度条」、把「用户敲了回车」变成 setData() 的，就是委托。

一个视图只有一个 itemDelegate()。但你可以用 setItemDelegateForColumn(列号, 委托) 给每一列挂不同的委托，这是后面所有花活的基础。

路由写在哪，两条路自选：写在一个委托里，靠 index.column() 分支；拆成多个委托，靠视图的列映射。列多、列行为差得远，就拆开；只差一两列，一个委托更快。

二、QStyledItemDelegate 与 QItemDelegate #

两个类都能继承，接口长得几乎一样。区别在绘制。

QItemDelegate 是 Qt 4.0 时代的东西。它用一堆 drawBackground() / drawDisplay() / drawFocus() 自己拼控件外观，颜色取自调色板。

QStyledItemDelegate 是 Qt 4.4 加的，绘制全部走 QStyle。你在 Windows 上得到 Windows 的选中色，在 Fusion 主题下得到 Fusion 的焦点框。

项 QItemDelegate QStyledItemDelegate
绘制方式 自己的 drawBackground / drawDisplay / drawFocus 调 QStyle::drawControl(CE_ItemViewItem)
跟随系统主题 不跟 跟
是否走 QStyle 不走 走
响应 QSS 弱 强
initStyleOption 也有，参数含义略不同 标准路径
现状 保留兼容 Qt 5 / Qt 6 默认，新代码选它
官方建议 不推荐新增 推荐继承

QTableView 默认挂的就是 QStyledItemDelegate。你 setItemDelegate(new QStyledItemDelegate) 之后界面毫无变化，说明它本来就是它。

空壳子长这样：

cpp
#pragma once
#include <QStyledItemDelegate>

class MyDelegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    explicit MyDelegate(QObject *parent = nullptr)
        : QStyledItemDelegate(parent) {}
};

继承 QStyledItemDelegate 之后，就不要再回去调 QItemDelegate 的成员。两个混着用，initStyleOption() 补出来的参数和 QStyle 的期望对不上，画出来会歪，焦点框位置也会错。

判断标准很简单：要不要跨主题一致的外观。要跟着系统走，选 QStyledItemDelegate；要一套像素级固定、跟主题无关的皮肤，才考虑 QItemDelegate。多数中文项目属于前者。

三、重写 paint：自己画 #

paint() 是委托里被调用最频繁的函数。一帧里每个可见单元格都要来一次。

签名固定，四个参数各管一件事：

cpp
void paint(QPainter *painter,
           const QStyleOptionViewItem &option,
           const QModelIndex &index) const override;
  • painter：画笔，已经绑在视图的 viewport 上
  • option：这块矩形 + 它的状态（有没有选中、有没有焦点、字体多大、图标多大）
  • index：这格对应的模型坐标，取数据全靠它

写 paint() 只有一条规矩要记死：先 initStyleOption()，再动 option 的副本。

initStyleOption(QStyleOptionViewItem *opt, const QModelIndex &index) 会从模型补齐 text、icon、decorationSize、features、displayAlignment、font，还会把 index 上 Qt::FontRole、Qt::TextAlignmentRole、Qt::BackgroundRole、Qt::CheckStateRole 的值合进 opt。

不调它，你手上的 opt.text 是空的，opt.features 是 None。拿这个 opt 去 QStyle::drawControl()，样式会认为这格没内容、不可选，于是选中态的底色没了，焦点框也不画了。你画出来的东西看着「在」，但点上去一片死，键盘也走不过去。

标准开头永远是三行：拷一份 QStyleOptionViewItem opt = option;、调 initStyleOption(&opt, index)、再画。option 是 const 引用，必须拷贝；别 const_cast 改原对象，那些字段被同一行的其他列共用，改了会串。

1. 只改一点：拷副本，交给父类 #

最省事的自定义，是让父类照常画，自己在前后加点料。素材里那个「去掉选中虚线框」就是这么干的：

cpp
void ItemDelegate::paint(QPainter *painter,
                         const QStyleOptionViewItem &option,
                         const QModelIndex &index) const
{
    QStyleOptionViewItem viewOption(option);

    // 去掉 item 被选中时默认的虚线焦点边框
    if (viewOption.state & QStyle::State_HasFocus)
    {
        viewOption.state &= ~QStyle::State_HasFocus;
    }

    // 背景、文字、选中底色，仍交给默认实现
    QStyledItemDelegate::paint(painter, viewOption, index);

    // …后面在右侧补图标
}

state 是个位标志集合。素材里写的是 ^（异或），效果一样，但读起来绕；viewOption.state &= ~QStyle::State_HasFocus 是标准的清位写法，意图更直白。

这条路径不需要手动 initStyleOption()。QStyledItemDelegate::paint() 内部会再调一次，把你副本里空着的 text 补上。手动调用只在「自己画」时才必需。

2. 完全自己画：先让样式铺底，再叠内容 #

cpp
void ScoreDelegate::paint(QPainter *painter,
                          const QStyleOptionViewItem &option,
                          const QModelIndex &index) const
{
    QStyleOptionViewItem opt = option;
    initStyleOption(&opt, index);

    painter->save();

    // 1. 底、选中态、焦点框、文字，全交给样式
    const QWidget *widget = opt.widget;
    QStyle *style = widget ? widget->style() : QApplication::style();
    style->drawControl(QStyle::CE_ItemViewItem, &opt, painter, widget);

    // 2. 在右侧抠一块区域画评分条
    const int score = index.data(Qt::UserRole + 1).toInt();   // 0 ~ 100
    QRect bar = opt.rect.adjusted(opt.rect.width() - 90, 9, -10, -9);

    painter->setRenderHint(QPainter::Antialiasing, true);
    painter->setPen(Qt::NoPen);

    // 底槽
    painter->setBrush(QColor(0xE4, 0xE4, 0xE4));
    painter->drawRoundedRect(bar, 3, 3);

    // 实心部分
    QRect fill = bar;
    fill.setWidth(bar.width() * qBound(0, score, 100) / 100);
    painter->setBrush(score >= 60 ? QColor(0x2E, 0xA0, 0x43)
                                  : QColor(0xD9, 0x3A, 0x3A));
    painter->drawRoundedRect(fill, 3, 3);

    painter->restore();
}

三个动作，顺序不能换：initStyleOption → drawControl 铺底 → 自己叠。

opt.widget 就是视图的 viewport，有为空的时候。空的时候退回 QApplication::style()，别直接 opt.widget->style()。

painter->save() / restore() 要成对。你改了 pen、brush、font、clip 却没还原，后面的单元格会接着用你的设置画，出现「一列正常一列花」的怪现象。Qt 不保证每次调 paint() 都给你一个干净的 painter 状态。

opt.rect 是整个单元格的矩形。drawControl(CE_ItemViewItem, ...) 画完之后，opt.text 那块内容基本占满了左边。要在右边加东西，可以从 opt.rect 里抠出右侧一段，也可以先把文字清掉自己排：

cpp
opt.text.clear();      // 让样式只画底，不画字
style->drawControl(QStyle::CE_ItemViewItem, &opt, painter, widget);
// 接下来整块 rect 都是你的

opt.text.clear() 之后，选中底色和焦点框照样画，因为它们看的是 opt.state，不是 opt.text。这也解释了为什么 initStyleOption() 必须先调：state 里的位是视图传进来的，但 features（有没有图标、有没有勾选框）要靠它补。

3. 别在 paint 里干重活 #

paint() 每帧对每个可见格调一次，滚动时一秒几十帧。new 对象、读文件、查库、拼大字符串，都不要放在这里。

QPixmap 尤其要小心：非 GUI 线程构造它会直接崩，反复从磁盘加载会让滚动掉帧。放 :/ 资源里，用静态局部变量缓存：

cpp
static const QPixmap pixmap(QStringLiteral(":/Images/delete.png"));

C++11 起静态局部变量的初始化是线程安全的，只会加载一次。细节在第十一章展开。

四、重写 sizeHint：自定义行高 #

cpp
QSize sizeHint(const QStyleOptionViewItem &option, const QModelIndex &index) const override;

默认实现按字体高度和 decorationSize 估算，返回值在 QSize(0, 24) 这个量级。48×48 的缩略图往格子里一塞，上下就被裁掉。

cpp
QSize ThumbDelegate::sizeHint(const QStyleOptionViewItem &option,
                              const QModelIndex &index) const
{
    QSize base = QStyledItemDelegate::sizeHint(option, index);
    if (index.column() == 0)
        base.setHeight(qMax(base.height(), 64));   // 缩略图列给 64
    return base;
}

几个要点：

  • sizeHint 只是建议值，视图可以不听。QTableView 默认行高取 verticalHeader()->defaultSectionSize()，要让 sizeHint 生效，得配 resizeRowsToContents()，或者 verticalHeader()->setSectionResizeMode(QHeaderView::ResizeToContents)。
  • QTreeView 要 setUniformRowHeights(false)，否则它拿第一行的高度套所有行。
  • 委托被多列共用时，视图按列分别问 sizeHint，行高取所有列的最大值。
  • 同一行会被问很多次，里面别算复杂东西。

多行文本的高度：

cpp
QSize WrapDelegate::sizeHint(const QStyleOptionViewItem &option,
                             const QModelIndex &index) const
{
    QStyleOptionViewItem opt = option;
    initStyleOption(&opt, index);

    const QFontMetrics fm(opt.font);
    const int w = qMax(60, opt.rect.width() - 16);
    QRect br = fm.boundingRect(QRect(0, 0, w, 10000),
                               Qt::TextWordWrap, opt.text);
    return QSize(w, qMax(24, br.height() + 12));
}

这里有个坑：sizeHint 里 option.rect.width() 不总是可靠。视图在布局前就问高度时，宽度是 0 或上一轮的值。行高要求稳，就别依赖宽度，固定一个上限，或者直接返回常量。

QTableView::setWordWrap(true) 只打开换行，行高不会自己变，必须配合上面的 sizeHint。

五、重写 createEditor：自定义编辑控件 #

cpp
QWidget *createEditor(QWidget *parent,
                      const QStyleOptionViewItem &option,
                      const QModelIndex &index) const override;

视图第一次进入编辑态时调它。你返回什么控件，用户就用什么编辑。

三条规则：

  1. parent 一定要用。控件必须有父对象，归属视图的 viewport。
  2. 返回 nullptr 表示这格不给编辑。哪怕模型 flags() 里带着 Qt::ItemIsEditable，也能在这一层挡掉。
  3. 每次编辑都新建一个，别拿成员变量存指针复用。视图退出编辑时会 deleteLater() 掉它。

素材里的多列路由：第一列给 QLineEdit，第二列给 QSpinBox，其余列退回父类。

1. 头文件 MultiColumnDelegate.h #

cpp
#pragma once
#include <QStyledItemDelegate>

class MultiColumnDelegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    explicit MultiColumnDelegate(QObject *parent = nullptr);

    // 1. 造编辑控件
    QWidget *createEditor(QWidget *parent,
                          const QStyleOptionViewItem &option,
                          const QModelIndex &index) const override;

    // 2. 模型数据 -> 控件
    void setEditorData(QWidget *editor, const QModelIndex &index) const override;

    // 3. 控件 -> 模型
    void setModelData(QWidget *editor,
                      QAbstractItemModel *model,
                      const QModelIndex &index) const override;

    // 4. 控件几何
    void updateEditorGeometry(QWidget *editor,
                              const QStyleOptionViewItem &option,
                              const QModelIndex &index) const override;
};

2. createEditor 实现 #

cpp
QWidget *MultiColumnDelegate::createEditor(QWidget *parent,
                                           const QStyleOptionViewItem &option,
                                           const QModelIndex &index) const
{
    // 按列号路由，造不同的编辑器
    if (index.column() == 0)
    {
        QLineEdit *lineEdit = new QLineEdit(parent);
        lineEdit->setStyleSheet(QStringLiteral("border: none; background: #E6F3FF;"));
        return lineEdit;
    }
    else if (index.column() == 1)
    {
        QSpinBox *spinBox = new QSpinBox(parent);
        spinBox->setFrame(false);        // 去掉微调器默认外边框
        spinBox->setMinimum(0);
        spinBox->setMaximum(100);
        return spinBox;
    }

    // 其它列交给父类（默认返回去掉边框的 QLineEdit）
    return QStyledItemDelegate::createEditor(parent, option, index);
}

素材原稿里那行 lineEdit << "border: none; background: #E6F3FF;"; 是拼贴时被截断的残渣，正确写法就是上面的 setStyleSheet()。

setFrame(false) 做的事很具体：去掉编辑器自带的描边。单元格本身已有网格线，编辑器再套一圈框，视觉上就是双层边框。

比列号更耐用的路由方式是看角色的值：

cpp
const QString kind = index.data(Qt::UserRole + 3).toString();
if (kind == QLatin1String("spin")) { /* … */ }

这样同一个委托能跨表复用，不用关心自己是第几列。

六、setEditorData 与 setModelData #

编辑器造出来只是空壳。数据要灌进去，改完要写回来。

text
                委托编辑器的生命周期
双击单元格
   │
   v
[ createEditor ] ──────────► 实例化编辑器（如 QSpinBox），返回指针
   │
   v
[ updateEditorGeometry ] ──► 调整几何，让它盖住单元格
   │
   v
[ setEditorData ] ─────────► 从 Model 读数据，载入编辑器
   │
   编辑中…（等用户回车或失焦）
   │
   v
[ setModelData ] ──────────► 把编辑器的值写回 Model
   │
   v
  编辑器销毁

这五步少一步，编辑就不对。

少 setEditorData：双击之后编辑器是空的，用户以为数据丢了。

少 setModelData：用户改了、按了回车、界面回弹成老值。

少 updateEditorGeometry：编辑器缩在左上角，尺寸是控件自己的初始大小，盖不住格子。

少 createEditor：双击弹出默认的 QLineEdit，你的下拉框永远不出现。

1. setEditorData：读 EditRole，不是 DisplayRole #

cpp
void MultiColumnDelegate::setEditorData(QWidget *editor,
                                        const QModelIndex &index) const
{
    // EditRole：可编辑的原始值，是 QDate、int 这类类型，不是格式化过的字符串
    QVariant val = index.model()->data(index, Qt::EditRole);

    if (index.column() == 0)
    {
        QLineEdit *lineEdit = qobject_cast<QLineEdit *>(editor);
        if (lineEdit)
            lineEdit->setText(val.toString());
    }
    else if (index.column() == 1)
    {
        QSpinBox *spinBox = qobject_cast<QSpinBox *>(editor);
        if (spinBox)
            spinBox->setValue(val.toInt());
    }
    else
    {
        QStyledItemDelegate::setEditorData(editor, index);
    }
}

DisplayRole 是给人看的（"60 分"），EditRole 是给编辑器用的（60）。灌数据必须用 EditRole，否则 toInt() 拿到的是 0。

qobject_cast 一定判空。列号分支和控件类型理论上一一对应，但路由一改就容易错位，判空是最后一道保险。

2. setModelData：写完记得 interpretText() #

cpp
void MultiColumnDelegate::setModelData(QWidget *editor,
                                       QAbstractItemModel *model,
                                       const QModelIndex &index) const
{
    if (index.column() == 0)
    {
        QLineEdit *lineEdit = qobject_cast<QLineEdit *>(editor);
        if (lineEdit)
            model->setData(index, lineEdit->text(), Qt::EditRole);
    }
    else if (index.column() == 1)
    {
        QSpinBox *spinBox = qobject_cast<QSpinBox *>(editor);
        if (spinBox)
        {
            // 让 QSpinBox 立刻校验并提交刚敲进去的文本
            spinBox->interpretText();
            model->setData(index, spinBox->value(), Qt::EditRole);
        }
    }
    else
    {
        QStyledItemDelegate::setModelData(editor, model, index);
    }
}

interpretText() 这行是摔出来的。用户在 QSpinBox 里敲了 88 直接按回车，控件内部还停在「文本未提交」状态，此时 value() 返回的是旧值。interpretText() 强制先解析文本再取值，拿到的才对。

QDoubleSpinBox、QDateEdit、QTimeEdit 有同样的毛病，一并加上。

走默认的 eventFilter，回车会先触发 commitData，顺序刚好对，不加也看不出来。一旦自己接管 keyPressEvent，问题立刻暴露。

3. updateEditorGeometry：一行，但别省 #

cpp
void MultiColumnDelegate::updateEditorGeometry(QWidget *editor,
                                               const QStyleOptionViewItem &option,
                                               const QModelIndex &index) const
{
    Q_UNUSED(index)
    // 编辑器铺满单元格
    editor->setGeometry(option.rect);
}

option.rect 是单元格在 viewport 坐标里的矩形。编辑器是 viewport 的子控件，坐标系统一致，直接 setGeometry 就对。想让编辑器内缩一点留出网格线，用 option.rect.adjusted(1, 1, -1, -1)。视图在滚动、改列宽、改行高时都会再调这个函数，里面只设几何，别塞别的逻辑。

4. 提交时机在你手上 #

默认流程由 QStyledItemDelegate::eventFilter() 驱动：回车 → commitData() → closeEditor(editor, SubmitModelCache)；Esc → closeEditor(editor, RevertModelCache)；失焦 → 提交。

自己托管复杂控件（比如带弹出列表的编辑器）时，得手动发这两个信号。只发 closeEditor 不发 commitData，值丢了；只发 commitData 不发 closeEditor，编辑器赖在格子上不走：

cpp
emit commitData(editor);   // 值回模型
emit closeEditor(editor, QAbstractItemDelegate::SubmitModelCache);   // 关掉编辑器

5. 五个重写点，一张表收尾 #

重写点 何时被调 干什么 漏写的后果
paint() 每次重绘、每格一次 把内容画进 option.rect 格子空白，或只剩默认文字
sizeHint() 布局、resizeRowsToContents 给出高宽建议值 图标被裁、文字挤成两行
createEditor() 进入编辑态 造编辑器，返回指针 只能用默认 QLineEdit
setEditorData() 编辑器刚造好 模型值灌进控件 编辑器空白，看着像数据丢了
setModelData() 编辑结束、提交时 控件值写回模型 改了等于没改，界面回弹

前两个管「看」，后三个管「改」。这条线划清楚，排错就能一眼定位：显示不对找 paint / sizeHint，编辑不对找 createEditor / setEditorData / setModelData。

七、委托的绘制流程与 opt 参数 #

paint() 的调用链：

text
viewport 重绘
   │
   ├── QAbstractItemView::paintEvent()
   │
   ├── 对每个可见 index 构造 QStyleOptionViewItem
   │      ├── rect  = visualRect(index)
   │      ├── state = 视图状态位（选中、焦点、悬停…）
   │      ├── widget = viewport
   │      └── font / decorationSize / displayAlignment
   │
   └── itemDelegate(index)->paint(painter, option, index)

option 是视图填的骨架，initStyleOption() 再往里补模型那一半。自己画的时候，两边都要吃满。

option 常用字段：

字段 含义 用在哪
rect 单元格在 viewport 里的矩形 所有绘制、子区域计算
state 状态位集合 判断选中、悬停、禁用、焦点
text DisplayRole 的文本（initStyleOption 后才有） 自绘文字
icon DecorationRole 的图标 自绘图标
font 合成后的字体（含 FontRole） QFontMetrics 测量
decorationSize 图标期望尺寸 图标布局
displayAlignment 文字对齐（含 TextAlignmentRole） 文字排版
features HasDisplay / HasDecoration / HasCheckIndicator 位 样式据此决定画什么
widget viewport 指针，有空的场合 取 style()
backgroundBrush BackgroundRole 带来的底色 手绘背景

state 里常用的位：

状态位 什么时候有
State_Selected 该格被选中
State_HasFocus 有焦点框（当前编辑格）
State_MouseOver 鼠标悬停在这格上
State_Enabled 视图可用
State_Active 窗口是活动窗口（焦点框颜色分亮暗）
State_Editing 正在编辑

读法就是按位与：option.state & QStyle::State_Selected、& QStyle::State_MouseOver、& QStyle::State_Enabled。拿不到 State_MouseOver，先看视图开没开 setMouseTracking(true)。

option.rect 是 viewport 坐标，不是窗口坐标，也不是屏幕坐标。绘制直接用；做鼠标命中判断时，QMouseEvent::pos() 也是 viewport 坐标，两边一致，可以直接比较。第八章就是这个用法。滚动之后 rect 会自动跟着偏移，paint() 里不用管滚动条的 value()。

八、QComboBox 委托：下拉列表带删除按钮 #

多账号登录界面里，账号框是个下拉列表。展开之后每一行除了账号名，右侧还有一个小叉。鼠标滑过时小叉高亮，点一下就把这条账号从历史里删掉。

这是委托最典型的两个重写点凑在一起：paint 画图标，editorEvent 接点击。

1. 场景拆解 #

控件是不可编辑的 QComboBox。下拉那一层是它内部的 view()，一个 QAbstractItemView，委托挂在这里。每行右侧留 9×9 的图标位，距右边缘 30 像素；点中图标就发信号，主窗口弹确认框，removeItem 删行。

2. 头文件 ItemDelegate.h #

cpp
#pragma once
#include <QStyledItemDelegate>
#include <QModelIndex>

class ItemDelegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    explicit ItemDelegate(QObject *parent = nullptr);
    ~ItemDelegate() {}

    // 绘制：在每行右侧加删除小图标
    void paint(QPainter *painter,
               const QStyleOptionViewItem &option,
               const QModelIndex &index) const override;

    // 事件：响应鼠标悬停与点击
    bool editorEvent(QEvent *event,
                     QAbstractItemModel *model,
                     const QStyleOptionViewItem &option,
                     const QModelIndex &index) override;

signals:
    void deleteItem(const QModelIndex &index);   // 删除项信号
};

3. paint：先铺底，再画叉 #

cpp
#include "ItemDelegate.h"
#include <QPainter>
#include <QMouseEvent>
#include <QApplication>
#include <QToolTip>

ItemDelegate::ItemDelegate(QObject *parent)
    : QStyledItemDelegate(parent)
{
}

void ItemDelegate::paint(QPainter *painter,
                         const QStyleOptionViewItem &option,
                         const QModelIndex &index) const
{
    QStyleOptionViewItem viewOption(option);

    // 去掉 item 被选中时默认的虚线焦点边框
    if (viewOption.state & QStyle::State_HasFocus)
    {
        viewOption.state &= ~QStyle::State_HasFocus;
    }

    // 先让默认实现画背景和左侧文字
    QStyledItemDelegate::paint(painter, viewOption, index);

    // 算删除按钮的位置，垂直居中
    const int iconSize = 9;
    const int verticalOffset = (viewOption.rect.height() - iconSize) / 2;

    // 按钮矩形：距离右边缘 30 像素
    QRect deleteRect(viewOption.rect.left() + viewOption.rect.width() - 30,
                     viewOption.rect.top() + verticalOffset,
                     iconSize, iconSize);

    // 从资源文件加载并绘制
    QPixmap pixmap(QStringLiteral(":/Images/delete.png"));
    painter->drawPixmap(deleteRect, pixmap);
}

iconSize 和「距右 30 像素」这两个数字，paint 和 editorEvent 里各写了一遍。经验是抽成一个私有函数，两边都调：

cpp
static QRect iconRect(const QStyleOptionViewItem &option)
{
    const int iconSize = 9;
    return QRect(option.rect.left() + option.rect.width() - 30,
                 option.rect.top() + (option.rect.height() - iconSize) / 2,
                 iconSize, iconSize);
}

两处各写一份，改了 paint 忘了改 editorEvent，就会出现「看得到图标但点不中」——这种 bug 排查起来很费时间。

4. editorEvent：命中判断 #

cpp
bool ItemDelegate::editorEvent(QEvent *event,
                               QAbstractItemModel *model,
                               const QStyleOptionViewItem &option,
                               const QModelIndex &index)
{
    // 与 paint() 完全相同的按钮区域
    const QRect deleteRect = iconRect(option);

    QMouseEvent *mouseEvent = static_cast<QMouseEvent *>(event);

    if (deleteRect.contains(mouseEvent->pos()))
    {
        if (event->type() == QEvent::MouseButtonPress)
        {
            emit deleteItem(index);
        }
        else if (event->type() == QEvent::MouseMove)
        {
            QApplication::setOverrideCursor(Qt::PointingHandCursor);
            QToolTip::showText(mouseEvent->globalPos(),
                               QStringLiteral("删除账号信息"));
        }
    }
    else
    {
        QApplication::restoreOverrideCursor();
    }

    return QStyledItemDelegate::editorEvent(event, model, option, index);
}

光标那段的写法有坑，第九章讲怎么改。

5. 绑定到下拉视图 #

cpp
// 主窗口初始化
ItemDelegate *pDelegate = new ItemDelegate(this);

// 关键：委托设给 QComboBox 的下拉视图
ui->comboBox->setItemDelegate(pDelegate);

// 接删除信号
connect(pDelegate, SIGNAL(deleteItem(QModelIndex)),
        this, SLOT(onDeleteAccount(QModelIndex)));

删除槽：

cpp
#include <QMessageBox>

void Widget::onDeleteAccount(const QModelIndex &index)
{
    // 确认框，防误触
    QMessageBox::StandardButton btn = QMessageBox::question(
        this,
        QStringLiteral("提示"),
        QStringLiteral("确认要删除所选的账号记录吗？"),
        QMessageBox::Yes | QMessageBox::No,
        QMessageBox::No);

    if (btn == QMessageBox::Yes)
    {
        // 直接从数据模型里移除对应行
        ui->comboBox->removeItem(index.row());
    }
}

removeItem() 会同步删掉 QComboBox 内建模型里的那一行，下拉视图收到 rowsRemoved 后自动重排，不需要手动刷新界面。

6. 为什么挂在 setItemDelegate 上就生效 #

QComboBox 内部由两部分组成：

部件 作用 委托管不管
QLineEdit 常态显示当前选项 不管
QAbstractItemView（view()） 下拉展开时的列表 管

QComboBox::setItemDelegate() 转手就把委托设给了内部 view()。所以改的是下拉列表里每一项的绘制和交互，跟上面那行显示框无关。你看到 QComboBox 的文字没变样式，是对的。

正因如此，这套委托换个宿主也成立：设给 QListView、QTableView 的第一列，效果一样。它只认 index 和 QStyleOptionViewItem。

九、事件过滤与交互响应 #

委托能碰到的事件有两类，入口完全不同。

入口 签名 收什么事件 谁调的
editorEvent bool editorEvent(QEvent*, QAbstractItemModel*, const QStyleOptionViewItem&, const QModelIndex&) 落在 item 上的鼠标按键、滚轮、键盘 视图，在把事件交给 item 之前
eventFilter bool eventFilter(QObject*, QEvent*) 落在编辑器控件上的所有事件 编辑器控件

一句话分工：editorEvent 管「还没进编辑态时，格子上的点击」；eventFilter 管「已经进了编辑态，编辑器里的按键」。

editorEvent 的返回值是拦截开关：

  • return true —— 我已处理，视图别再往下走。整行不会因为这次点击被选中。
  • return false / 转交父类 —— 视图照常处理，该选中选中，该进入编辑进入编辑。

素材里最后一句 return QStyledItemDelegate::editorEvent(...)，等于「图标之外的地方一律照常」。要让点叉时不选中整行，就在命中图标时直接 return true。

1. 光标那段的坑 #

cpp
QApplication::setOverrideCursor(Qt::PointingHandCursor);   // 压栈
QApplication::restoreOverrideCursor();                     // 弹栈

这是一对栈操作，不是开关。鼠标在下拉列表里每移动一像素就 MouseMove 一次，如果每次都 setOverrideCursor，栈里会堆上几十层；而离开时只 restore 一次，光标永远回不去。

改法一，别碰全局栈，改控件自己的 cursor：

cpp
if (const QWidget *vp = option.widget)
{
    const_cast<QWidget *>(vp)->setCursor(
        onIcon ? Qt::PointingHandCursor : Qt::ArrowCursor);
}

option.widget 是 const QWidget *，setCursor 不是 const 函数，所以要 const_cast。它指向的是视图的 viewport，改它只影响这个控件。

真要用 setOverrideCursor，就得自己记一个 bool m_cursorPushed：只在没压栈时 setOverrideCursor，只在压过栈时 restoreOverrideCursor。editorEvent 不是 const 函数，成员直接写就行。

2. 悬停高亮 #

想让图标在鼠标悬停时换色换图，得让视图知道现在哪个格子被悬停，再触发重绘：

cpp
// editorEvent 的 MouseMove 分支
if (index != m_hoverIndex) {
    m_hoverIndex = index;
    if (option.widget)
        option.widget->update();      // 重绘，paint 里就能读到新标记
}

cpp
QPersistentModelIndex m_hoverIndex;                            // 成员
const bool hovered = (m_hoverIndex == QPersistentModelIndex(index));   // paint 里判断

m_hoverIndex 用 QPersistentModelIndex，别用裸 QModelIndex。后者在模型插入删除行之后会失效，指针指向别处，paint 里拿去比较就是错的行。

option.state 里也有 State_MouseOver，但它只在视图开了 setMouseTracking(true) 时才可靠。视图由 QComboBox 内部持有，改它的设置不如自己记一个标记省事。

3. 哪些事件值得拦 #

事件 常见用法
MouseMove 悬停高亮、光标换形、弹 tooltip
MouseButtonPress 点按钮子区域、发信号
MouseButtonRelease 拖拽的落点（配合 MouseButtonPress 起手）
MouseButtonDblClick 双击弹独立窗口，而不是就地编辑
KeyPress 空格 / Del 直接操作当前项
Wheel 拦掉滚轮，避免滚动时误改值

Wheel 那条容易忽略。编辑器在格子上时，用户滚动鼠标滚轮，QSpinBox 会跟着变数值 —— 用户以为在翻页，结果数据被改了。委托里拦掉：

cpp
bool SpinDelegate::eventFilter(QObject *obj, QEvent *event)
{
    if (event->type() == QEvent::Wheel)
        return true;              // 吃掉滚轮，交还给视图滚动
    return QStyledItemDelegate::eventFilter(obj, event);
}

注意这是 eventFilter，不是 editorEvent —— 它拦的是编辑器控件上的事件。

十、进度条委托与其他常见形态 #

委托能画的形状，取决于你想在格子里塞什么。常见几种：

形态 重写点 关键
进度条 paint QStyle::CE_ProgressBar + QStyleOptionProgressBar
复选框居中 paint CE_ItemViewItem 画不了居中，得自己算 rect
缩略图 paint + sizeHint 图标尺寸决定行高，sizeHint 必须跟上
星级评分 paint + 可选 editorEvent 按 x 坐标反推第几颗星
颜色块 paint 纯 fillRect，注意跟随选中态调整亮度
富文本 paint QTextDocument::drawContents()，成本高，行性别太多
行内按钮 paint + editorEvent 和第八章的小叉同构，只是画成按钮
下拉编辑 createEditor 返回 QComboBox，setEditorData 里 setCurrentIndex

进度条那一版最常被问，代码不长：

cpp
void ProgressDelegate::paint(QPainter *painter,
                             const QStyleOptionViewItem &option,
                             const QModelIndex &index) const
{
    QStyleOptionViewItem opt = option;
    initStyleOption(&opt, index);

    // 底、选中态照常
    const QWidget *widget = opt.widget;
    QStyle *style = widget ? widget->style() : QApplication::style();
    style->drawControl(QStyle::CE_ItemViewItem, &opt, painter, widget);

    const int value = qBound(0, index.data(Qt::UserRole + 1).toInt(), 100);

    QStyleOptionProgressBar pb;
    pb.rect = opt.rect.adjusted(4, 4, -4, -4);
    pb.minimum = 0;
    pb.maximum = 100;
    pb.progress = value;
    pb.text = QStringLiteral("%1%").arg(value);
    pb.textVisible = true;
    pb.textAlignment = Qt::AlignCenter;
    pb.state = opt.state & QStyle::State_Enabled;

    style->drawControl(QStyle::CE_ProgressBar, &pb, painter, widget);
}

两个细节。pb.state 要跟着 opt.state 的 State_Enabled 走，否则禁用状态下进度条还是满色。QStyleOptionProgressBar 别用默认构造的 rect，一定要从 opt.rect 里抠，否则会画在 (0,0)。

复选框居中的思路一样：先 drawControl(CE_ItemViewItem) 铺底，但先把 opt.features 里的 HasCheckIndicator 清掉，再自己算一个居中的 QRect 调 CE_CheckBox。

十一、委托的性能与复用 #

委托是无状态的，至少在对外的语义上是。它被所有单元格共用，paint 里不该存「上一个格子」的信息。

要存也行，条件是键能区分格子：QPersistentModelIndex、或在 paint 里按 index 查表。存一个裸 QModelIndex 当缓存，模型一动就错。

复用清单：

  • 一个委托管所有列，靠 index.column() 分支；列行为差得远就拆成多个，用 setItemDelegateForColumn。
  • 图片、字体、QFontMetrics 全部 static 或成员变量，在构造函数里准备好。
  • sizeHint 返回值要稳定。同一行两次调用返回不同高度，视图会反复重排。
  • 批量改数据时 setUpdatesEnabled(false)，改完再打开，比逐行刷新快一个量级。
  • 万行以上的表格，别在 paint 里访问数据库或网络。真需要异步取数，让模型在后台线程准备好缓存，paint 只读内存。

所有权这块容易搞混。QAbstractItemView::setItemDelegate() 不接管所有权：栈对象能跑，因为委托活得比视图的可见期长；跨函数传就用 new 并给 parent，tableView->setItemDelegate(new ScoreDelegate(tableView)) 会随视图一起销毁。

委托自己 new 的编辑器也一样：new QSpinBox(parent) 里的 parent 由视图传入，退出编辑时视图负责回收，我们一行 delete 都不用写。

十二、易错点速查 #

现象 原因 修法
选中态没了、焦点框不画 自绘前没调 initStyleOption 先 initStyleOption(&opt, index) 再画
一列正常一列花 painter 状态没还原 save() / restore() 成对
双击是空编辑框 没写 setEditorData 用 EditRole 灌值
改了值界面回弹 没写 setModelData 写完 setData(index, v, Qt::EditRole)
微调器值差一位 少了 interpretText() 取 value() 前强制解析文本
编辑器盖不住格子 没写 updateEditorGeometry editor->setGeometry(option.rect)
图标画在左上角 用了默认构造的 option.rect 一律从 option.rect 派生
图标看得到点不中 paint 与 editorEvent 的 rect 算法不一致 抽成一个 iconRect() 共用
光标变不回来 setOverrideCursor 是栈，MouseMove 反复压栈 改 option.widget->setCursor()
滚轮误改数值 QSpinBox 吃了 Wheel eventFilter 里 return true 拦掉
表格滚动卡顿 paint 里加载图片 / 建对象 静态缓存 QPixmap
自定义委托完全没生效 设给了视图，代码没重新编译 moc 确认 Q_OBJECT 与 setItemDelegate 都到位
下拉框样式没变 以为 setItemDelegate 管上面那行 QLineEdit 它只管下拉列表，显示框另说

排错的顺序是固定的：先看「画」还是「改」。画不对，从 paint 的 initStyleOption 一行往下查；改不对，从 createEditor 挨到 setModelData，四步逐个打日志。

委托这套接口从 Qt 4 到 Qt 6 没怎么变过。吃透一次，换到 QListView、QTableView、QTreeView、QComboBox 上都是同一套写法。
