LemonCyan's BlogDeploy #

用 Obsidian 写笔记，用自建的 md → html 生成器（1.site/）把笔记渲染成具有桌面/窗口系统的现代静态站点，经 GitHub Actions 自动化发布到 GitHub Pages。

  • 站点主页：https://lemoncyan.loc.cc
  • 备用地址：https://lemoncyan.github.io/

💡 关于本页：这份 README 本身会被生成器单独渲染为站点的「关于本站」页面（/about/），并在顶栏与桌面图标提供直达入口。

站点已全面告别 Hexo 等黑盒框架，全站由位于 1.site/ 的极简自建生成器驱动：无臃肿依赖、零运行时黑盒、毫秒级启动、完全掌控渲染与交互细节。

✅ 哪些目录会发布？唯一判据 #

站点的发布规则遵循极简哲学：无需维护繁杂的白名单或忽略列表，只看一级目录名的首字符。

目录类型 判定规则 是否发布 典型代表
公开知识库 单个大写英文字母 + 分隔符（.、-、_、、） ✅ 发布 A.硬件与固件、B.内核、Z.杂项
内部工具与资产 数字开头 ❌ 不发布 1.site（生成器）、2.img（图片）、3.app（App源）、8.职业发展
临时草稿与小写 小写字母开头或无前缀 ❌ 不发布 api.service、drafts
系统与隐藏配置 点（.）开头 ❌ 不发布 .git、.github、.obsidian、.agent

该规则在 1.site/src/topdirs.js 的正则中实现：

javascript
export const PUBLISH_PATTERN = /^[A-Z][.\-_、．]/;

内容编排约定 #

  • 无须 front matter：文章标题直接取自文件名（自动过滤 1.、2.1. 等排序编号），分类自动映射目录层级。如果 Markdown 中写了 YAML 头，生成器会自动安全丢弃，不污染正文。
  • 自定义目录外观：未登记的目录会自动去掉 A. 前缀，并根据目录名哈希自动分配 18 色调色板中的协调色；如需指定专属图标与主色调，可在 1.site/src/config.js 的 topDirs 中指定。

如何扩展一个新 App？ #

  1. 在 3.app/ 下创建 my-app.html。
  2. 内部编写该 App 的专属 <style> 与功能逻辑，并在 <head> 中按需声明元数据：
    html
    <title>应用名称</title>
<meta name="app-icon" content="🚀">          <!-- 图标字符，默认取标题首字 -->
<meta name="app-color" content="#4caf50">     <!-- 图标底色，默认自动哈希配色 -->
<meta name="app-scheme" content="dark">       <!-- 默认明暗主题 (light/dark) -->
<meta name="app-scroll" content="yes">        <!-- 是否由窗口外壳接管整体滚动条 -->
  3. 若需外部依赖或 JS/CSS，放置在 3.app/assets/<app-name>/ 下，使用相对路径引用。构建器会自动扫描并同步打包到 dist/apps/assets/。
  4. 规范提示：请给样式选择器添加作用域前缀（如 .myapp-root），切勿直接污染 body / html，明暗主题通过监听 document.body.dataset.scheme 保持全站无缝跟随。

🖼️ 本地图片免折腾方案 #

2.img/ 是本地图片存储中心。构建时整目录无损镜像至产物 dist/img/。

在 Obsidian 中编写笔记时，直接按本地习惯引用，无需关心线上路径：

markdown
![电路原理图](2.img/hardware/circuit.png)
![电路原理图](/2.img/hardware/circuit.png)   <!-- 带前导斜杠同样兼容 -->

生成器在构建期会自动检测并将所有首段为 2.img 的路径改写为 /img/...。这意味着：

  • 在 Obsidian 离线编辑时：本地路径完全畅通，图片秒开。
  • 在部署上线后：浏览器解析为 /img/... 静态资源，双端表现百分之百一致。

🚀 本地开发与编译 #

全站为纯静态产物架构：先编译生成 HTML，再由本地轻量服务器进行预览。所有命令在 1.site/ 目录下运行。

1. 环境准备 #

  • Node.js：20.11+（推荐与 CI 对齐使用 Node 24）
  • npm：随 Node 附带（仓库已内置 1.site/package-lock.json）

2. 构建与运行指令 #

bash
cd 1.site

# 1. 首次安装依赖
npm ci

# 2. 全量构建（构建 HTML + 建立 Pagefind 中文搜索索引）
npm run build

# 3. 启动本地预览（访问 http://127.0.0.1:4173/）

3. 高效调试技巧 #

  • 极速样式调优：npm run build:50（仅渲染前 50 篇文档，几秒出预览）。
  • 指定目录过滤：node build.js --limit 50 --filter "A.硬件与固件"。
  • 单独更新索引：npm run index（直接对已有 dist/ 重建搜索索引）。

🚀 自动化部署流水线（CI/CD） #

站点的发布由 .github/workflows/workflow.yml 完全托管，具备高容错性与零污染提交特点：

flowchart TD
    A["git push 到 main / 每日 UTC 00:17 定时"] --> B["Actions Runner 环境初始化 (Node 24)"]
    B --> C["Refresh ETF data\n(node fetch/fetch-etf.mjs)"]
    B --> D["Refresh radar data\n(node fetch/fetch-radar.mjs)"]
    C --> E["全量构建 (npm run build)"]
    D --> E
    E --> F["dist/ 完整性质量门禁检测"]
    F --> G["发布至 LemonCyan/LemonCyan.github.io\n(绑定域名 lemoncyan.loc.cc)"]

流水线关键特性 #

  1. 每日定时自动更新：每天 UTC 00:17（北京时间 08:17）自动唤醒流水线，将 ETF 穿透率与 GitHub Radar 日榜刷新至最新状态。
  2. 零脏提交（Clean Git History）：动态抓取脚本只改写 Actions 虚拟机的临时构建工作区，数据直接打入 dist/ 发布，不向仓库产生任何机器 commit，代码历史始终清爽。
  3. 安全与质量门禁：
    • 抓取失败带 continue-on-error，哪怕网络波动也不会阻断文档内容发布。
    • 严格的发布前校验：必须保证 dist/index.html 与 dist/pagefind/ 索引完备才执行推送。
  4. 极速增量推送：停用 force_orphan，采用增量提交推送至 Pages 仓库，发布耗时由几分钟缩减至十几秒。

⚠️ 已知限制与说明 #

  • 未公开引用：当笔记中引用了个人未公开的私有笔记时，wikilink 将原样展示为 [[...]]。
  • Mermaid 离线呈现：Mermaid 图表依赖 CDN 按需加载，若处于完全离线环境，图表将保留清晰的代码块样式并标注等待联网。
  • TOC 生成门槛：右侧「本页目录」仅在正文中存在 ≥2 个层级标题时自动激活，避免简短随笔占用侧边空间。
