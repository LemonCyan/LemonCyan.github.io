USB 设备的自动挂载

这篇讲两件事：U 盘插进一台没有键盘、没有屏幕的机器之后，怎么自动挂上去；挂上去之后，怎么自动做事。

全文按一条链子走：识别设备 → 决定挂载点 → 执行挂载 → 触发后续动作。udev 负责前半段的识别与触发，udisks2 与 systemd-mount 负责真正的挂载，脚本或 systemd 单元负责后续动作。四段少一段，链子就断。

不讲的部分：设备节点的权限位、固定节点名、/dev/sdX 名字漂移，那些在《USB 设备的权限与固定节点名》里。内核 USB 枚举流程、文件系统内部布局也不在这儿展开。

命令在 systemd 系的 Linux 上验证过。发行版默认配置有差异，涉及默认值的地方都给了查询命令，你拿本机输出对标。

一、无头设备为什么需要自动挂载 #

机柜里的机器、树莓派、车载盒子、放在配电箱旁边的采集终端，共同点是没有键鼠没有屏。你要它读 U 盘里的数据，只能远程 ssh 或者干脆不登录。

手动挂载的三个隐含前提，这类设备一个都不满足：

  • 人在机器旁边
  • 有终端可以敲 mount
  • 知道这次插进来的设备叫 /dev/sdb1 还是 /dev/sdc1

第三条最阴。先插的盘是 sda，拔掉再插就变成 sdb，重启之后又变回 sda。写死 /dev/sdb1 的脚本，在第二次插拔时就开始作妖。

所以自动挂载要解决的不是「敲一条 mount 命令」，而是让机器自己走完四步。

步骤 要回答的问题 谁来做
识别设备 这是块盘吗？有可识别的文件系统吗？卷标和 UUID 是什么？ 内核 uevent + udev 的内建 blkid
决定挂载点 挂到哪个目录？第二个设备插进来会不会撞车？ 规则脚本 / udisks2 / systemd-mount
执行挂载 用什么类型、什么参数真正挂上去？ mount / udisksctl / systemd-mount
触发后续动作 挂了之后跑什么？同步、校验、上报？ systemd 单元、path 单元、轮询脚本

三个最常见的误判 #

写了 udev 规则就会挂载——不会。规则只是把「设备插入了」翻译成「跑一条命令」。命令里没有 mount，那就是没挂。规则本身不含任何挂载语义。

挂载点写死 /media/usb 就行——插第一个盘没问题，插第二个盘时要么 mount 报目录忙，要么后一个把前一个盖住：/media/usb 底下看到的是第二块盘的内容，第一块盘的数据还在，但你访问不到了。

规则里可以随便跑脚本——udev 的 worker 有处理超时，脚本阻塞太久会被直接杀掉，日志里只剩一行 timeout。

二、udev 触发与挂载的时机 #

设备插上时，内核通过 netlink 广播 uevent，内容是 ACTION、DEVPATH、SUBSYSTEM、DEVNAME 这组键值。systemd-udevd 收到后，按 /etc/udev/rules.d/ 与 /usr/lib/udev/rules.d/ 里的规则逐条匹配，命中的规则依次执行。

一块 U 盘插上，你会看到不止一个事件：

text
KERNEL[1234.567] add  /devices/pci0000:00/.../usb1/1-1 (usb)                      <- 接口
KERNEL[1234.789] add  /devices/pci0000:00/.../1-1:1.0/host4/.../block/sdb (block) <- 整盘
KERNEL[1234.812] add  /devices/pci0000:00/.../block/sdb/sdb1 (block)              <- 分区

只对分区事件做动作，是最稳的选法。整盘事件发生时分区表还没解析完，此时 blkid 拿不到卷标。

规则里有哪些可用的键 #

键 含义 例子
ACTION 事件类型 add、remove、change
SUBSYSTEM 子系统 block、usb
KERNEL 设备名 sdb1、sd[b-z][0-9]
DEVTYPE 设备类型 partition、disk
ENV{ID_FS_TYPE} 文件系统类型，内建 blkid 填 vfat、ext4、ntfs
ENV{ID_FS_LABEL} 卷标 KINGSTON
ENV{ID_FS_UUID} 文件系统 UUID 1A2B-3C4D
ENV{DEVNAME} 设备节点全路径 /dev/sdb1

ID_FS_* 不是内核给的，是 udev 的内建 blkid 程序读出来后注入 ENV 的。所以规则里能直接用，脚本里也能直接读环境变量——$ID_FS_LABEL、$ID_FS_TYPE、$DEVNAME 就是这么来的。

RUN 的语义，和它为什么不等同于挂载 #

RUN+= 里的命令由 udev 的 worker 进程执行，是同步的：worker 等命令返回才处理下一个事件。命令的 stdout/stderr 不进终端，只进 journal，也拿不到完整的交互环境。

关键在于 worker 的挂载命名空间。udev 从某几个版本起，worker 跑在私有的 mount namespace 里。你在里面 mount 成功，退出码是 0，但挂载点只存在于 worker 自己的命名空间，namespace 一销毁就没了。用户空间永远看不到 /media/XXX 变成挂载点。

这正是那个经典的坑：新版本 udev 上 mount 失效。修法是把 udevd 的挂载传播方式改成共享。

bash
# 把 unit 拷一份到 /etc 再改，避免升级被覆盖
cp /usr/lib/systemd/system/systemd-udevd.service /etc/systemd/system/
# 编辑该文件，把 MountFlags 改成 shared
systemctl daemon-reload
systemctl restart systemd-udevd

较新的 systemd 不再用 MountFlags=，改用 PrivateMounts= 表达同一件事，值取 no。别照抄网上的旧文章，先看本机到底写了什么：

bash
systemctl cat systemd-udevd | grep -E 'MountFlags|PrivateMounts'

worker 的超时 #

udev.conf 里有 event_timeout，控制单个事件的处理时长上限，systemd 上游默认 180 秒。超过就杀 worker，脚本连清理都做不完。

这个值能用 udevadm control --timeout= 临时改，但别靠调大它来跑长任务。180 秒里做一次 rsync 全量同步，盘大一点就超。正确路子是在规则里起一个 systemd 服务，命令立刻返回，活让服务慢慢干。

分区还是整盘 #

挂分区用 /dev/sdb1，前提是盘上有分区表，绝大多数 U 盘和移动硬盘属于这种。挂整盘用 /dev/sdb，前提是没有分区表、文件系统直接写在盘上，只有少数裸格式化的盘是这样。

看 lsblk 有没有子节点就知道当前是哪种。规则里用 DEVTYPE=="partition" 只吃分区，用 =="disk" 只吃整盘，两个都不写则全会命中，一次插盘触发两次动作。

三、识别设备：blkid 与 UUID #

挂载点名字从哪来？三个来源：卷标、UUID、设备名。可靠性依次升高。

先看盘上有什么：

bash
$ sudo blkid
/dev/sda1: UUID="a1b2c3d4-..." TYPE="ext4" PARTUUID="..."
/dev/sdb1: LABEL_FATBOOT="KINGSTON" LABEL="KINGSTON" UUID="1A2B-3C4D" TYPE="vfat"

更直观的是 lsblk -f，它把类型、卷标、UUID、挂载点并排列出来，排查时比 blkid 顺手。加 -o NAME,FSTYPE,LABEL,UUID,MOUNTPOINTS,SIZE 只看想要的列。输出形如：

text
NAME   FSTYPE FSVER LABEL     UUID        MOUNTPOINTS
sdb
└─sdb1 vfat   FAT32 KINGSTON  1A2B-3C4D   /media/KINGSTON

卷标做挂载点的四个坑 #

老写法优先用 $ID_FS_LABEL 当挂载点名，思路直观，坑不少：

  1. 卷标可以为空。很多量产 U 盘出厂无卷标，ID_FS_LABEL 是空串，mkdir -p /media/ 就把根挂了。脚本必须处理空值，回退到设备名。
  2. 卷标可以重名。两块都叫 KINGSTON 的盘同时插上，挂载点撞车。
  3. 卷标里可以有空格、中文、/。空格让 mkdir 的参数裂开，/ 让路径变成子目录，必须过滤。
  4. 卷标可以随时改。换台机器、用 fatlabel 改一下，挂载点就变了，下游脚本全乱。

UUID 是稳定标识 #

UUID 在格式化时生成，跟着文件系统走，不随插拔和重启变化。用它定位是标准做法。

bash
# 取 UUID 的两种写法
sudo blkid -s UUID -o value /dev/sdb1
lsblk -no UUID /dev/sdb1

# udev 环境里直接读，不用再调 blkid
echo "$ID_FS_UUID"

vfat 的 UUID 只有 8 位十六进制（形如 1A2B-3C4D），重复概率比 ext4 的 128 位 UUID 高，批量做盘时要留意。

一个安全的命名函数 #

把「卷标优先、回退设备名、再做字符清洗」封成函数，后面几章的脚本都调它：

bash
# /lib/udev/usb-name.sh
# 从 udev 环境变量算出挂载点名，保证非空、无空格、无斜杠
usb_name() {
    local n="${ID_FS_LABEL:-}"
    # 只留字母数字和少数符号，其余替换成下划线
    n=$(printf '%s' "$n" | tr -c 'A-Za-z0-9._-' '_')
    # 卷标为空或清洗后为空，回退到设备名 sdb1
    [ -n "$n" ] || n="${DEVNAME##*/}"
    printf '%s' "$n"
}

tr -c 'A-Za-z0-9._-' '_' 把不在集合里的字符全换成下划线，中文卷标会变成一串下划线，但路径合法。想保住可读性，就得改用 UUID 命名。

四、用 udisks 挂载 #

udisks2 是 freedesktop 那套的磁盘管理服务，跑在系统总线上，桌面环境「插入自动弹文件管理器」就是它和文件管理器配合的结果。它不做内核层的事，只把「挂载」包装成一个 D-Bus 方法，顺带处理挂载点分配和权限。

先确认它在跑：

bash
systemctl status udisks2
# 没有这个服务，下面的命令全部会报连不上系统总线

一条命令挂上去 #

bash
udisksctl mount -b /dev/sdb1
# Mounted /dev/sdb1 at /media/liuluhua/KINGSTON

注意挂载点的构成：/media/ + 调用者用户名 + 卷标。这是 udisks2 的分配规则——有会话的调用者，挂载点放自己名下。卷标为空时它用 UUID 或设备名兜底。同名盘已经挂过一块，它在后面接 1、2 后缀。

这就直接消掉了第二章那个「插第二块盘撞车」的问题。udisks2 帮你做唯一化，不用自己拼路径。

卸载和查询：

bash
udisksctl unmount -b /dev/sdb1      # 挂载点目录一起清掉，不留空壳
udisksctl mount -b /dev/sdb1 -o ro  # 只读挂载
udisksctl info -b /dev/sdb1         # 看 IdLabel/IdUuid/IdType/MountPoints

info 会把设备的标识和挂载点全列出来，排查「到底挂哪了」比翻 mount 输出快。

不装 CLI 也能挂 #

udisksctl 只是 D-Bus 客户端，手上有 gdbus 也一样调 org.freedesktop.UDisks2.Filesystem.Mount，对象路径形如 /org/freedesktop/UDisks2/block_devices/sdb1，返回的字典里有 mount-points。

写 Qt 程序时这条路特别顺手——老代码用 org.freedesktop.Hal 的 DeviceAdded 信号，HAL 早就没了，换成 org.freedesktop.UDisks2 的 InterfacesAdded 才是现在能跑的路子。Qt 工程里在 .pro 加 QT += dbus，#include <QtDBus/QDBusConnection>，连接写法不变：

text
QDBusConnection::systemBus().connect(
    "org.freedesktop.UDisks2",
    "/org/freedesktop/UDisks2",
    "org.freedesktop.DBus.ObjectManager",
    "InterfacesAdded",
    this, SLOT(slotDeviceAdded(QDBusObjectPath, QVariantMap)));

槽函数里拿到对象路径，判断是不是 /block_devices/sd*，再看接口里有没有 Filesystem，就区分出「这是一块可挂载的 U 盘分区」。记录下这个对象路径，拔出时的 InterfacesRemoved 拿它比对，就知道盘是不是真的走了。

udisks 的三个现实约束 #

约束 表现 绕法
依赖 D-Bus 系统总线 Failed to connect to system bus 确认 dbus-daemon 与 udisks2 都在跑
依赖 polkit 授权 Not authorized to perform operation 装 polkit 规则，或让调用者属有权限的组
无会话时挂载点位置不同 变成 /media/KINGSTON，没有用户名层 从 udisksctl mount 输出里解析挂载点

最后一条在无头机器上很关键。没有登录会话时，udisks2 拿不到用户名，只能挂到 /media/<卷标>。同一份脚本，桌面机上挂载点带用户名，服务器上不带，按固定路径读文件就找不到。挂载点必须从命令输出或 info 里拿，不能靠猜。

五、用 systemd-mount 挂载 #

systemd-mount 是 systemd 提供的临时挂载入口。它不在本地调 mount(2)，而是让 PID 1 生成一个 .mount 单元再由 systemd 去挂。这一点在 udev 场景下很重要。

基本用法 #

bash
systemd-mount --no-block --collect /dev/sdb1
  • --no-block：下完单立刻返回，不等挂载完成
  • --collect：单元失败或卸载后自动回收，不在内存里堆垃圾单元

不指定挂载点时，它在 /run/media/ 下自动挑位置。挂了同名设备两次，它自己加后缀。看具体挂哪了：

bash
systemd-mount --list

卸载：

bash
systemd-mount --umount /dev/sdb1
systemd-mount --umount /run/media/KINGSTON    # 也可以按挂载点

为什么它在 udev 里更可靠 #

第二章讲过，udev worker 有私有 mount namespace，在里面 mount 出的挂载点用户看不见。systemd-mount 绕开了这个问题：请求发给 PID 1，挂载动作在初始命名空间里执行，也就是用户看得见的那个。

如果一定要在 udev 规则里直接挂载，systemd-mount 比裸 mount 稳。但更推荐第六章的写法——规则里什么都不挂，只起一个服务。

手写 .mount 单元 #

要固定下来，自己写：

ini
# /etc/systemd/system/media-usbdata.mount
[Unit]
Description=USB data disk
After=dev-disk-by\x2duuid-1A2B\x2d3C4D.device
Requires=dev-disk-by\x2duuid-1A2B\x2d3C4D.device

[Mount]
What=/dev/disk/by-uuid/1A2B-3C4D
Where=/media/usbdata
Type=vfat
Options=rw,noatime,uid=1000,gid=1000,umask=0022

[Install]
WantedBy=multi-user.target

两个硬性规则，违反就起不来：

  1. 单元文件名必须由挂载点反推。/media/usbdata 对应 media-usbdata.mount，斜杠换短横、开头的斜杠去掉。用 systemd-escape -p --suffix=mount /media/usbdata 生成，别手拼。
  2. Where= 必须和单元名一致。不一致时 systemd 直接拒绝加载，报 Where= setting doesn't match unit name。

After= 里的设备名也有讲究。/dev/sdb1 对应 dev-sdb1.device，但 sdb1 会漂移。用 UUID 定位更稳，那串 \x2d 是短横的转义，systemd 单元名里不允许裸短横出现在这个位置。用 systemd-escape 生成能省掉一堆猜。

fstab 与自动挂载的差别 #

这两件事经常被混为一谈。

fstab 自动挂载（udev / udisks / systemd-mount）
触发时机 开机时 local-fs.target 阶段 设备插入事件发生时
设备不在的后果 默认卡住启动，进 emergency 无影响，事件没发生就没动作
适合场景 系统盘、固定的数据盘 随插随用的移动介质
挂载点 写死 可以动态分配

fstab 里也能写移动盘，但必须加 nofail，否则盘不在就起不来：

text
UUID=1A2B-3C4D  /media/usbdata  vfat  rw,noatime,nofail,x-systemd.device-timeout=5s  0 0

x-systemd.device-timeout=5s 把等待设备的时间压到 5 秒，比默认的 90 秒舒服得多。再进一层，用 x-systemd.automount 让它按需挂载——访问 /media/usbdata 时才去挂，盘没插就返回错误而不是阻塞。

fstab 加 nofail 也不能算自动挂载：盘插上时不会自动挂，得 systemctl daemon-reload 或者等下次开机。要「插上就挂」，还是得走事件驱动。

三种方式放在一起比 #

维度 裸 mount + udev 规则 udisks2 systemd-mount
谁执行挂载 udev worker 自己 udisksd PID 1
受 worker 命名空间影响 是，要改 MountFlags 否 否
挂载点唯一性 自己拼，容易撞 自动分配，冲突加后缀 自动分配，冲突加后缀
依赖组件 只要 mount D-Bus + polkit + udisks2 systemd
卸载清理目录 要自己 rm -r 自动 自动
无头环境可用性 好，但要处理命名空间 看会话与 polkit 好
上手成本 最低 中 中

三条路都能用。选择标准很简单：机器上已经有 udisks2 就顺着它，纯 systemd 环境用 systemd-mount，最小系统连 udisks 都装不上就用裸 mount，但记得处理命名空间与挂载点冲突。

六、写 udev 规则触发挂载 #

规则放 /etc/udev/rules.d/，名字以数字开头决定加载顺序。自己加规则用 99- 开头，保证在系统默认规则之后执行——这样 ID_FS_* 这批变量已经被 60-persistent-storage.rules 里的 IMPORT{builtin}="blkid" 填好了。### 那条老规则，有个真 bug

原始版本写的是：

text
ENV{DEVTYPE}="partition",RUN+="/lib/udev/automount.sh",ENV{REMOVE_CMD}="/lib/udev/autounmount.sh"

ENV{DEVTYPE}="partition" 用的是单等号。udev 规则语法里，= 是赋值，== 才是比较。写成单等号，规则的意思是「把 DEVTYPE 设成 partition」，条件恒为真，结果这条规则对所有设备生效——包括整盘、包括光驱、包括你不想碰的任何块设备。

正确写法：

ini
# /etc/udev/rules.d/99-usb-automount.rules
# 只对「有文件系统的分区」在插入时动作
ACTION=="add", SUBSYSTEM=="block", ENV{DEVTYPE}=="partition", ENV{ID_FS_TYPE}!="", RUN+="/lib/udev/usb-mount.sh"

# 拔出时只做清理
ACTION=="remove", SUBSYSTEM=="block", ENV{DEVTYPE}=="partition", RUN+="/lib/udev/usb-umount.sh"

逐项解释：

  • ACTION=="add" 只吃插入，remove 单独一条。合成一条会漏掉拔出时的清理
  • SUBSYSTEM=="block" 挡住 USB 接口本身的事件，那些没有文件系统
  • ENV{DEVTYPE}=="partition" 只吃分区，不吃整盘
  • ENV{ID_FS_TYPE}!="" 排除没格式化的裸分区，否则 mount 必定失败，日志里刷一堆报错

ENV{REMOVE_CMD}= 那个写法要丢掉。它不是 udev 的标准语义，不会在拔出时自动执行。要用就得在匹配 remove 的规则里写 RUN+=。

调试规则的四条命令 #

规则写完别急着插盘，先跑这几条：

bash
udevadm test /sys/class/block/sdb1        # 语法检查 + 看会不会命中
udevadm control --reload-rules            # 改完必须重载，否则内核里还是旧规则
udevadm monitor --udev --property         # 实时看插拔时到底发了什么事件
udevadm info --query=all --name=/dev/sdb1 # 查设备最终的属性集合

udevadm test 的输出会列出所有匹配到的规则和设置的环境变量。如果 RUN 那行没出现，说明匹配条件写错了——去核对 DEVTYPE 到底是 partition 还是 disk。

udevadm monitor --property 尤其值得开着，插一次盘看完整事件流，你会看到 add 连着来好几条，也会看到 ID_FS_LABEL 只在分区事件里才有。

规则里能跑什么，不能跑什么 #

能跑的：写文件、改权限、创建符号链接、调 systemd-run 下单、调一个几毫秒就返回的轻量命令。不能跑的：rsync、dd、fsck、等待网络、任何 sleep 超过一两秒的东西。

原因在第二章讲过：worker 有 event_timeout，超时被杀；就算没超时，worker 是串行处理事件的，一条规则卡住，后面所有设备的 udev 处理全部排队。你会看到鼠标键盘都开始延迟响应——因为它们也在等 udev。

正确姿势：规则只负责下单 #

ini
# /etc/udev/rules.d/99-usb-automount.rules
ACTION=="add", SUBSYSTEM=="block", ENV{DEVTYPE}=="partition", ENV{ID_FS_TYPE}!="", \
  TAG+="systemd", ENV{SYSTEMD_WANTS}+="usb-mount@%k.service"

ACTION=="remove", SUBSYSTEM=="block", ENV{DEVTYPE}=="partition", \
  TAG+="systemd", ENV{SYSTEMD_WANTS}+="usb-umount@%k.service"

%k 是 udev 的替换符，值等于 KERNEL，也就是 sdb1。ENV{SYSTEMD_WANTS} 让 systemd 拉起一个模板单元，udev 自己立刻返回，不等结果。活全在服务里干，服务没有 180 秒的限制。

TAG+="systemd" 让 udev 把这个设备交给 systemd 管理，缺了它 SYSTEMD_WANTS 不一定生效。

对应两个模板单元：

ini
# /etc/systemd/system/usb-mount@.service
[Unit]
Description=Mount USB partition %i
After=dev-%i.device
BindsTo=dev-%i.device

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/lib/udev/usb-mount.sh %i
ExecStop=/lib/udev/usb-umount.sh %i

BindsTo=dev-%i.device 保证设备消失时服务跟着退出，顺带触发 ExecStop。这比靠 remove 事件再发一次规则更可靠——拔盘时 remove 事件的属性集合是残缺的，有些 ENV 已经拿不到了。

Type=oneshot + RemainAfterExit=yes：脚本跑完服务算「已启动」并保持，ExecStop 才会被执行。用默认的 simple 类型，服务一退出就被判为结束，ExecStop 不跑。

七、挂载后自动执行脚本 #

挂上了不等于完事。真正的需求是「盘一插上，把里面的数据搬到本地」或者「把本地配置同步到盘里」。这一步有三种实现机制。

机制 触发源 延迟 适合
systemd 单元 udev 的 SYSTEMD_WANTS 最低，事件直连 无头设备、开机即用
path 单元 文件系统变化 低，内核 inotify 挂载点固定或可预测
轮询脚本 定时器 取决于间隔 挂载点不确定、要跨多个设备

路径单元的写法 #

usb-sync.path 里写 PathExists=/media/usbdata/READY，PathChanged= 则盯内容变化。好处是不用改 udev，缺点是挂载点必须可预测——udisks2 那种带用户名的动态路径就用不了。

轮询更笨但更宽容：不管挂哪儿，只要目录出现就干活。初版走的就是这条路，逻辑是探测 /media/ 下有没有对应目录。

那段轮询脚本，语法有问题 #

原版贴的是：

sh
UDISK=$1
while (true)
do
	if [ -e"$UDISK" ];
	then
		echo"Mounted device [$UDISK] found !"
	...

三处硬伤，sh 下都会报错或行为不对：

  1. while (true)——(true) 是子 shell，true 退出码 0，条件恒真，语法上居然能跑，但白 fork 一个进程。写 while true 或 while : 就行
  2. [ -e"$UDISK" ]——[ 是命令，参数之间必须有空格。少了空格，sh 拿到的是 -e/tmp/x 这一个字符串，报 unknown operand
  3. echo"Mounted..."——同理，被当成一个叫 echo"Mounted..." 的命令，报 command not found

修正后：

bash
#!/bin/sh
# 轮询等待挂载点出现，最多等 60 秒
UDISK="$1"
[ -n "$UDISK" ] || { echo "usage: $0 <mountpoint>"; exit 2; }

i=0
while [ "$i" -lt 20 ]; do
    if [ -d "$UDISK" ]; then
        echo "mounted: $UDISK"
        exit 0
    fi
    i=$((i + 1))
    sleep 3
done
echo "timeout waiting for $UDISK"
exit 1

把 while true 换成有上限的循环，是轮询必须做的事。无限循环的守护脚本在设备永远不出现的场景下会一直跑，日志被刷满，还占一个进程位。

挂载后干活：双向同步 #

U 盘内目录与本地目录双向同步，是这个需求里最实的一块。核心工具是 rsync，双向靠两趟单向同步拼出来，每趟带 --update 保护较新的一方：

bash
#!/bin/bash
# /usr/local/bin/usb-sync.sh <挂载点>
set -u

MOUNT="${1:?need mountpoint}"
LOCAL="/srv/data"

[ -d "$MOUNT" ] || { echo "no such dir: $MOUNT"; exit 1; }
mountpoint -q "$MOUNT" || { echo "not a mountpoint: $MOUNT"; exit 1; }

# 第一趟：盘 -> 本地，只补新的
rsync -a --update --delete-missing-args "$MOUNT/" "$LOCAL/"
# 第二趟：本地 -> 盘，只补新的
rsync -a --update --delete-missing-args "$LOCAL/" "$MOUNT/"

两个细节值得停下来讲。

mountpoint -q 那行不能省。挂载点目录在盘没挂上时也存在——mkdir 出来的空目录一直都在。直接往里 rsync，等于把本地数据往一个空目录里拷，看着像同步成功，实际全丢在本地磁盘上，一重启就没了。

--update 让 rsync 跳过「目标端更新」的文件。两趟都加，才能保证两边各自较新的版本都不会被旧版本覆盖。不加的话，第一趟会用盘上的旧文件盖掉本地的新文件，第二趟再用本地（已被覆盖）的文件盖掉盘上的——两边一起退回到旧版本。

双向同步的已知局限 #

这套逻辑只管文件内容和时间戳，不管删除。盘上删掉的文件，本地不会删；本地删掉的，盘上也不会删。要同步删除就得把 --delete-missing-args 换成 --delete，那样任一次误操作都会双向扩散，风险高得多。

文件名大小写也不能忽略。vfat 不区分大小写，ext4 区分。本地有 readme.txt 和 README.txt 两个文件，同步到 vfat 盘上会互相覆盖。做盘时统一用小写命名，能省掉这类问题。

八、挂载参数的选择 #

mount -o 后面那一串选项，在 U 盘场景里有一半是为了绕开 vfat 的权限模型，另一半是为了减少写入。

那串参数逐项拆 #

text
-o gid=100,dmask=000,fmask=111,utf8,flush,rw,noatime,users
选项 作用 要注意什么
rw 读写挂载 系统默认按 ro 挂时要显式写才生效
noatime 不更新文件访问时间 U 盘减少写放大，明显延长寿命
uid / gid 把盘上所有文件属主压成指定用户/组 gid=100 是 users 组，各发行版数值不一定一致
fmask 文件权限掩码 111 去掉执行位，文件变成 666
dmask 目录权限掩码 000 保留全部，目录变成 777
umask 文件和目录共用 和 fmask/dmask 同时写时后者优先
utf8 按 UTF-8 解析文件名 中文文件名靠它，vfat 缺省用的码页不一定是 UTF-8
flush 关闭前刷盘更积极 牺牲一点写入性能，换拔出时的数据完整性
users 允许任何用户挂载和卸载 多用户机器上等于放开权限

vfat 没有真正的 Unix 权限位，盘上那些 rwx 全靠挂载时这几个掩码造出来。所以 vfat 盘挂上之后，所有文件属主都是挂载时指定的那个 uid，跟盘上原来是谁创建的没关系。

ext4 盘的权限存在 inode 里，uid=/gid=/umask= 这三个会被内核直接拒掉（unknown option），导致挂载失败。一块 ext4 移动硬盘插上来，那套统一参数就挂不上。

按用途分三档 #

bash
# 只读巡检盘：绝对不动盘上数据
mount -t vfat -o ro,noatime,utf8 /dev/sdb1 /media/ro

# 单人使用的数据盘：属主是自己，权限宽松
mount -t vfat -o rw,noatime,utf8,uid=1000,gid=1000,umask=0022 /dev/sdb1 /media/data

# 多用户共享盘：目录可进可读，文件只读
mount -t vfat -o rw,noatime,utf8,uid=0,gid=100,fmask=0133,dmask=0022 /dev/sdb1 /media/share

fmask=0133 让文件没有写和执行位，只有属主能写（属主是 root），普通用户只能读。共享盘就该这样。

两个容易踩的细节 #

uid/gid 的数值不稳定，写 gid=100 之前先 getent group users 确认。直接写组名不行，vfat 的挂载选项只认数字。

flush 和 sync 不一样。sync 让每次写入同步落盘，vfat 上性能掉得厉害，拷几个 G 能慢一倍以上。flush 只在关闭文件、卸载这类时机刷，是更好的折中。

errors=remount-ro 是 ext4 的选项，写进 vfat 的挂载参数里会报错。换文件系统时记得一起换参数，别照抄。

用 UUID 定挂载点，别用设备名 #

bash
mount /dev/sdb1 /media/data          # 靠内核枚举顺序
mount UUID=1A2B-3C4D /media/data     # 靠文件系统标识

第二种稳定。系统会自动去 /dev/disk/by-uuid/ 下找对应链接，这条路径是 udev 的 60-persistent-storage.rules 维护的，跟会漂移的 sdb1 无关。

by-uuid 之外还有 by-label、by-partuuid、by-id。by-id 用的是硬件序列号，同一个盘不管插哪个口都是同一个名字，做固定挂载点时比 by-uuid 更贴合硬件。

九、卸载与忙设备 #

挂载容易卸载难。umount 报 target is busy 是最常见的卡点，意味着还有进程在里面或者有文件被打开。

bash
$ umount /media/data
umount: /media/data: target is busy.

先找是谁：

bash
fuser -vm /media/data     # 列出占用该挂载点的进程
lsof +D /media/data       # 备选

常见占用者：shell 的当前目录就在里面、文件管理器开着、rsync 还在跑、编辑器打开了里面的文件、tail -f 挂着日志。

从温和到粗暴 #

bash
cd /                       # 1. 让当前 shell 离开这个目录，很多人忘了这步
umount /media/data         # 2. 正常卸载
fuser -km /media/data      # 3. 杀掉占用进程再卸
umount -l /media/data      # 4. 懒卸载：先从目录树摘掉，等占用结束再释放
umount -f /media/data      # 5. 强制卸载

-l（lazy）是对 U 盘拔出场景够用的一招：目录立刻从树里消失，进程手里的文件句柄还能继续读写，直到它们关闭。代价是那块盘在这期间不能安全拔——数据还在内核缓存里往外写。

-f 只对网络文件系统有意义，本地块设备上用 -f 基本等于没效果，umount 还是会报忙。

拔盘前的顺序 #

卸载 → 等写完 → 断开。跳过第一步直接拔，vfat 上正在写的文件会坏，严重时整个文件系统变成只读甚至要 fsck。

原版拔出脚本的逻辑是「卸载 + 删目录」：

sh
mount_point=$ID_FS_LABEL
if [ -z $mount_point ];
then
mount_point=${DEVNAME##*/}
fi
if [ -n $mount_point ];
then
umount -l /media/$mount_point rm -r /media/$mount_point
fi

三处必须修：

  1. [ -z $mount_point ] 变量没加引号。卷标为空时 [ -z ] 只有一个参数，不同 sh 实现行为不一致。写 [ -z "$mount_point" ]
  2. umount -l /media/$mount_point rm -r /media/$mount_point 是两件事被写成一行，中间没有 ; 也没有 &&。umount 会把后面那串全当额外参数，rm 压根不执行，还报 bad usage
  3. 删目录应该加 &&，保证只在卸载成功后删

修正版：

bash
#!/bin/sh
# /lib/udev/usb-umount.sh
# 拔出后清理：先卸载，成功后删目录
set -u
. /lib/udev/usb-name.sh

[ -n "${ID_FS_LABEL:-}" ] || [ -n "${DEVNAME:-}" ] || exit 0
mp="/media/$(usb_name)"

# 只有确实是挂载点才卸，避免误删同名普通目录
if mountpoint -q "$mp" 2>/dev/null; then
    umount -l "$mp" || umount "$mp" || exit 1
fi

# 目录非空说明还有东西没走干净，别删
[ -d "$mp" ] && { rmdir "$mp" 2>/dev/null || rm -rf "$mp"; }

用 rmdir 优先、失败再 rm -rf，是防止误删的最后一道闸：rmdir 只能删空目录，如果挂载没真摘掉，rmdir 会失败，你就知道有问题了，而不是把盘上的数据当本地目录删了。

mountpoint -q 这个检查也必须留着。拔盘事件发生时，如果挂载点目录刚好和数据盘上某个同名目录重了，没有这个检查就会对普通目录动手。

设备已经拔了怎么办 #

物理上已经把盘拔了，但挂载点还在——mount 输出里那个条目还在，访问它报 Transport endpoint is not connected 或者一直卡住。

bash
umount -l /media/data      # 直接摘，设备不在也能摘掉
fuser -vm /media/data      # 顽固条目，找还在引用它的进程，杀完再来一次

/etc/mtab 现在是 /proc/self/mounts 的软链，不要手改。内核的挂载表才是真相，改文本文件会让状态更乱。

十、一个完整的双向同步实例 #

把前面几章拼起来：一块 U 盘插进无头机器，自动挂载，挂载完把盘里的数据同步到本地，再把本地的新文件补回盘上。

目录布局 #

text
/lib/udev/usb-name.sh          命名函数，第三章
/lib/udev/usb-mount.sh         挂载脚本
/lib/udev/usb-umount.sh        卸载清理，第九章
/usr/local/bin/usb-sync.sh     双向同步，第七章
/etc/systemd/system/usb-mount@.service
/etc/udev/rules.d/99-usb-automount.rules
/srv/data/                     本地数据目录
/media/                        挂载点根

挂载脚本 #

bash
#!/bin/sh
# /lib/udev/usb-mount.sh [设备名]
# 由 usb-mount@.service 调用，参数是 sdb1 这类裸设备名
set -u
. /lib/udev/usb-name.sh

# 两种调用方式：服务传参，或直接读 udev 环境
if [ $# -ge 1 ]; then
    dev="/dev/$1"
    # 服务环境下没有 udev 变量，自己补
    eval "$(udevadm info --query=property --name="$dev" \
        | grep -E '^(ID_FS_LABEL|ID_FS_TYPE|ID_FS_UUID)=' | sed 's/^/export /')"
else
    dev="$DEVNAME"
fi

[ -b "$dev" ] || { echo "not a block device: $dev"; exit 1; }

name=$(usb_name)
mp="/media/$name"

# 已是挂载点说明这块盘已经挂过了
if mountpoint -q "$mp" 2>/dev/null; then
    echo "already mounted: $mp"
    exit 0
fi
mkdir -p "$mp"

# 按文件系统类型分支，参数不能通用
case "${ID_FS_TYPE:-}" in
    vfat|exfat)
        opts="rw,noatime,utf8,flush,uid=0,gid=100,umask=0022" ;;
    ext4|ext3|ext2|xfs)
        # 这类文件系统的权限来自 inode，不能加 uid/gid/umask
        opts="rw,noatime" ;;
    iso9660|udf)
        opts="ro,noatime" ;;
    *)
        echo "unsupported fs type: ${ID_FS_TYPE:-unknown}"
        rmdir "$mp" 2>/dev/null; exit 1 ;;
esac

if ! mount -t "$ID_FS_TYPE" -o "$opts" "$dev" "$mp"; then
    echo "mount failed: dev=$dev mp=$mp type=$ID_FS_TYPE opts=$opts"
    rmdir "$mp" 2>/dev/null
    exit 1
fi
echo "mounted $dev at $mp"

按文件系统类型分开拼参数，是这段脚本最关键的地方。统一一套参数，ext4 盘必然挂不上。

服务单元 #

ini
# /etc/systemd/system/usb-mount@.service
[Unit]
Description=USB automount %i
After=dev-%i.device
BindsTo=dev-%i.device

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/lib/udev/usb-mount.sh %i
ExecStop=/lib/udev/usb-umount.sh %i
# 挂载成功后再同步，失败不影响单元结论
ExecStartPost=-/usr/local/bin/usb-sync.sh /media/%i
TimeoutStartSec=300

ExecStartPost 前面的短横表示失败不影响单元结论。同步出错不该把挂载判成失败，否则 systemd 会去执行 ExecStop 把它卸掉，本来挂好的盘没了。

TimeoutStartSec=300 给同步留时间。默认 90 秒对一个几 G 的同步肯定不够，超了单元被杀、ExecStop 触发卸载，现象是「盘插上几秒就没了」。

规则 #

ini
# /etc/udev/rules.d/99-usb-automount.rules
ACTION=="add", SUBSYSTEM=="block", ENV{DEVTYPE}=="partition", ENV{ID_FS_TYPE}!="", \
  TAG+="systemd", ENV{SYSTEMD_WANTS}+="usb-mount@%k.service"

拔出不需要单独规则。BindsTo=dev-%i.device 会在设备节点消失时让服务退出，ExecStop 里做清理。少一条规则，少一个出错的地方。

上线顺序 #

bash
chmod +x /lib/udev/usb-name.sh /lib/udev/usb-mount.sh /lib/udev/usb-umount.sh
chmod +x /usr/local/bin/usb-sync.sh
systemctl daemon-reload                        # 单元改了先重载
udevadm control --reload-rules                 # 规则改了必须做
udevadm trigger --action=add --sysname-match=sdb1
journalctl -u 'usb-mount@*' -f

顺序不能乱。先重载单元再触发事件，否则 udev 让 systemd 拉服务时单元还不存在，报 Unit not found。

十一、失败处理与日志 #

自动挂载出问题时机器没屏幕，你只能靠日志。提前把日志铺好，事后能省几小时。

来源 命令 能看到什么
内核 dmesg -T | tail -40 设备枚举、分区表解析、文件系统报错
udev journalctl -u systemd-udevd 规则匹配、worker 超时、RUN 命令的输出
服务 journalctl -u 'usb-mount@*' 你自己脚本里 echo 的内容

脚本里所有 echo 都进 journal，不写就没得查。挂载失败时把目录状态也打出来，排错时一眼看清：

bash
mount -t "$ID_FS_TYPE" -o "$opts" "$dev" "$mp" || {
    echo "mount failed: dev=$dev mp=$mp type=${ID_FS_TYPE:-?} opts=$opts"
    ls -ld "$mp"
    cat /proc/self/mountinfo | grep -F " $mp " || true
}

把参数原样打出来很值。九成的挂载失败原因是某个选项不被接受，而错误信息只说 Invalid argument，不告诉你是哪个选项。

常见错误对照 #

症状 多半是什么 查法
规则不触发 匹配条件写错，或没 reload-rules udevadm test /sys/class/block/sdb1
规则跑了但没挂上 worker 私有命名空间 systemctl cat systemd-udevd | grep PrivateMounts
mount 报 Invalid argument 选项不被该文件系统接受 打印 $opts 逐个减
mount 报 wrong fs type -t 和实际文件系统不一致 blkid /dev/sdb1
挂上了但读不到文件 挂到了错误的命名空间或目录 udisksctl info -b /dev/sdb1 看 MountPoints
第二块盘把第一块盖了 挂载点写死 用 UUID 或让 udisks 分配
服务启动即失败 单元缺 Type=oneshot + RemainAfterExit journalctl -u 看退出码
同步超时导致盘被卸 TimeoutStartSec 太短 调长，或把同步拆成独立单元

加一层健康检查 #

无头设备上值得放个定时器，定期确认该挂的还挂着：写一个 usb-health.timer，OnUnitActiveSec=60s，配套服务的脚本读 /etc/usb-mounts.conf（一个 UUID 一行），逐个 mountpoint -q，缺失就重跑挂载脚本并记日志。某次事件丢了，一分钟内也能自愈。

十二、易错点速查 #

# 坑 正确做法
1 以为写了 udev 规则就会挂载 规则只把插入事件转成「跑一条命令」，挂载得命令里自己做
2 挂载点写死 /media/usb 用卷标/UUID 拼唯一路径，或让 udisks / systemd-mount 分配
3 规则里 ENV{DEVTYPE}="partition" 用单等号 比较用 ==，单等号是赋值，条件恒真
4 用 ENV{REMOVE_CMD} 当拔出钩子 没有这个语义，拔出要单独写 ACTION=="remove" 规则
5 规则里跑 rsync / dd worker 有 event_timeout，超时被杀，改用 SYSTEMD_WANTS
6 worker 里 mount 成功但用户看不到 worker 在私有 mount namespace，改 MountFlags=shared 或用 systemd-mount
7 卷标为空时 mkdir -p /media/$LABEL 变成 /media/ 先判空，回退到设备名
8 卷标含空格或 / 直接拼路径 用 tr -c 清洗，或改用 UUID
9 第二块同名盘盖掉第一块 挂载点必须唯一，冲突时加后缀
10 ext4 上写 uid=/umask= 这两类选项只对 vfat/exfat 起作用，按类型分支
11 拔盘后挂载点目录残留，下次挂不上 卸载成功后清目录，rmdir 优先
12 umount 报 busy 就先 -f -f 对本地块设备没用，先找占用进程或 cd /
13 卸载和删目录写在同一行没分隔符 用 && 或分成两行
14 while (true) / [ -e"$X" ] / echo"..." sh 里参数必须用空格分开
15 同步比时间戳，两边时区或时间不一致 rsync --update 靠时间戳判断，两边时间要可信
16 同步前不检查挂载点 mountpoint -q 必校验，否则把本地数据写进空目录
17 忘了 daemon-reload 或 control --reload-rules 改单元重载单元，改规则重载规则，两件事分开
18 服务默认超时太短，长任务被杀 显式设 TimeoutStartSec，或把长任务拆成独立单元

上线前的四项自检 #

bash
# 1. 规则语法与匹配
udevadm test /sys/class/block/sdb1 2>&1 | grep -E 'RUN|SYSTEMD_WANTS'
# 2. 单元文件语法
systemd-analyze verify /etc/systemd/system/usb-mount@.service
# 3. 脚本在最小环境下能跑
env -i /bin/sh /lib/udev/usb-mount.sh sdb1
# 4. 手动触发一次完整流程
udevadm trigger --action=add --sysname-match=sdb1 && journalctl -f -u 'usb-mount@*'

第 3 条最容易被跳过。udev 和服务启动时的环境变量极少，PATH 里往往只有 /usr/sbin:/usr/bin:/sbin:/bin。你在交互式 shell 里跑得好好的脚本，到了 udev 里因为找不到某个命令就挂了，而且不报错——因为 stdout 你也没看。脚本里给命令写绝对路径，或者开头自己设 PATH。

自动挂载这条链子的本质，是把人插盘之后那一串动作拆成机器能自己走完的四步。任何一步指望「应该会这样」，链子就断在那儿。
