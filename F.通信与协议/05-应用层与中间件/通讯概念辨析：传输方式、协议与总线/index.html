这篇只讲概念的分野。工业通信里那几个天天被混着说的词，各指什么。

讲什么：物理层/传输方式、协议、总线这三层怎么分；RS485 与 Modbus 为什么不是一回事；常见组合；终端电阻为什么到处都要；几条工业总线按实时性怎么排；选型与调试各按什么顺序判断。

不讲什么：Modbus 报文结构、功能码、CRC 逐字节拆解，串口的 termios 配置与收包状态机，CAN 的帧结构与位时序，MQTT 与 ZeroMQ 的实现。这些各有专篇。

主线一句话：传输方式只负责把 0 和 1 变成电平送出去，协议负责让这些 0 和 1 有能被对方理解的结构。这两件事各管各的，能自由组合。

现场排障的，直接跳第十章，那里按三层给了排查顺序表。理顺概念，从第一章读。

一、三个层次：物理、协议、总线 #

1.1 三个词被当成同义词 #

「我们这条线是 485 的」「这套是 Modbus」「现场走的是 Profibus」，三句话语法一样，指的东西分属三个层次。日常聊不出事，一旦要选型、接线、查故障，就开始互相打架。

层次 回答的问题 典型名字
物理层 / 传输方式 电信号怎么送出去 RS232、RS485、RS422、CAN 收发器、以太网 PHY
协议 字节怎么组织、怎么应答 Modbus RTU、Modbus TCP、CANopen、Profibus-DP、EtherCAT
总线 / 网络 一条链路挂几个节点、怎么寻址 主从总线、多主总线、星型交换网络

记住这张表的形状。下面三节拆每一行。

1.2 物理层：说电信号怎么传 #

物理层管的事很朴素：把一位数据变成线上的电压或差分电平，送到对面，再还原成一位。它不关心这一位属于什么字节，也不关心这个字节是温度还是开关量。

  • RS232：单端对地，摆幅大（正负十几伏），抗干扰靠摆幅。距离短，点对点。
  • RS485：差分，A、B 之间的压差表示 0 和 1。共模干扰同时压在两根线上，相减抵消。距离长，能挂多个节点。
  • RS422：差分，收发各一对线，全双工。485 的全双工亲戚。
  • CAN：差分，收发器带线与逻辑，多节点可同时抢占，靠仲裁决定谁先说。
  • 以太网：差分对加变压器隔离，帧由 PHY 收发，双绞线里跑的是编码后的符号。

这几句里没有一句提到「这一帧的第 3 个字节是什么」。物理层到此为止。

1.3 协议：说字节怎么组织 #

协议层接手物理层送上来的字节流，回答四个问题：边界在哪（一帧从哪到哪）、谁在说话（地址怎么定）、说什么事（功能码、命令字）、对不对（校验怎么算、错了怎么办）。

Modbus RTU 的答案是一串朴素约定：地址 + 功能码 + 数据 + CRC，帧之间靠 3.5 个字符时间的静默分隔。Modbus TCP 去掉 CRC，前面套一个 MBAP 头，靠 TCP 保证顺序与完整。

同一件事，换一种协议，字节的组织方式完全不同。 反过来，同一份 Modbus RTU 报文放在 485 上跑还是放在光纤转换器上跑，内容一个字不用改。

1.4 总线：说拓扑与寻址 #

  • 点对点：两端一连，没有第三方。RS232、422 全双工接法。
  • 多点共享：一条线挂一串，同一时刻只有一个在说。485 半双工、CAN。
  • 主从：主站发问，从站按地址应答。Modbus RTU 是典型。
  • 多主：谁都能主动发，靠仲裁分优先级。CAN 是多主。
  • 交换式网络：每节点单独一条链路接交换机，冲突被吃掉。以太网走这条。

总线还要管两件物理事：终端匹配、节点数上限。第六章与第七章展开。

1.5 三层可以自由组合 #

传输方式 上面能跑的协议 拓扑
RS485 Modbus RTU、Profibus-DP（借用物理层）、私有协议、DL/T 645 多点主从
RS232 Modbus ASCII、私有协议、调试终端 点对点
CAN CANopen、J1939、DeviceNet、CANaerospace 多主
以太网 Modbus TCP、EtherCAT、Profinet、EtherNet/IP、TCP/IP 星型交换
光纤转换 透传上面任意一种 视转换器而定

这张表挡掉两种错误提问。

第一种：「能不能把 Modbus 改成 485？」没法答。Modbus 是协议，485 是传输方式，一个跑在另一个上面，没有「改」的关系。

第二种：「我们用的是 CAN 不是 Modbus，二选一。」也错。CAN 提供传输与仲裁，CANopen 才是上面的应用协议。同一条 CAN 线上能同时跑 CANopen 与自定义报文，只要 ID 规划好。

1.6 混着说的代价 #

每一层出问题的现象与查法完全不同。物理层坏了是没波形、幅度不对、长线偶发丢帧、动线就断；协议层坏了是波形好好的、示波器上看数据也在发，主站却报「非法功能码」或 CRC 错误；总线层配错了是单台单独接能通、一挂上整条线就不通，或者地址撞了两台一起应答。

三层的现象不重叠。混成一个「通信不通」，只能靠猜。分层之后，每一步都有明确的下一步。

二、传输方式不是协议 #

2.1 素材里那句钥匙 #

原始笔记里有一句话把整个话题的钥匙交出来了：

485 通讯、232 通讯，这讲的是采用何种传输方式。既然是传输方式，重点就是「传输」两字。不管是 232 还是 485，只起到传输作用，可以传输 Modbus 协议信息，也可以传输其他协议信息。

这段的意思是：485 这个说法里没有约定任何一个字节长什么样。 现场听到「这条是 485 的」，说的只是电气规格：差分、两线、半双工、能挂几十个节点、距离上千米（视速率与线材而定）。

2.2 RS485 干的活只有一件事 #

text
逻辑 1  →  A 比 B 高若干毫伏
逻辑 0  →  B 比 A 高若干毫伏

外加一个方向控制：半双工收发器有 DE（驱动器使能）脚，拉高才能发，拉低只听。发完要立刻切回接收，切晚了会把总线上别人的数据顶掉。

它不知道当前这一位是地址的高位还是 CRC 的末位，也不知道一帧有几个字节——「帧」是协议层造出来的概念，485 根本没有帧的概念。这也解释了一个现象：485 转 USB 的模块通电后，串口助手敲什么对面收到什么，因为模块只做电平转换，一个字节都不解释。

2.3 三种传输方式的差别全在电气 #

项目 RS232 RS485 RS422
信号方式 单端，对地 差分，A/B 两线 差分，收发各一对
双工 全双工 半双工 全双工
典型距离 十几米 上千米（速率越低越远） 上千米
节点数 2 几十个（看收发器驱动能力） 一主多从
抗共模干扰 弱，靠摆幅 强，靠相减抵消 强
终端电阻 一般不需要 长线两端需要 长线两端需要

表里没有任何一行提到协议。选 485 还是 422 是电气问题：要不要全双工、干扰多强、线拉多长。选 Modbus 还是私有协议是协议问题：主站软件支持什么、要不要标准化。两件事分开选，选项数量相乘，不是二选一。

2.4 同一条 485 线上跑什么，485 不知道 #

一条 485 线从 PLC 主站口出去，挂八台仪表。六台是标准 Modbus RTU，两台是老设备，用厂商私有报文：帧头两字节、长度一字节、异或校验。

物理层完全正常：同一对 A/B 线，同一波特率，同一套终端电阻。485 对两种报文一视同仁，只管把电平送过去。不正常的只在协议层：六台 Modbus 表看不懂私有帧，静默丢弃；两台私有设备收到 Modbus 帧也丢弃。总线不冲突，因为主站按地址分时问话。

这就是分层的价值：物理层一套，协议层两套并存，地址规划好就互不干扰。若把「485」和「Modbus」当成一件事，这个方案设计不出来。

2.5 波特率是传输方式自己的参数 #

波特率是每秒钟传输的数据位数。计算机处理的是「0」和「1」组成的机器语言，一个「0」或一个「1」就是一位。波特率设成 9600，意味着一秒钟之内能够传输 9600 个「0」或是「1」，它决定了通信的传输速度。

常用数值：

text
2400   4800   9600   19200   38400   57600   115200

这串数字不是随便排的，都是常见晶振频率能干净分出来的点。单位是「位/秒」不是「字节/秒」，9600 除以 10（一帧常见的位数）才是每秒约 960 个字符。

2.6 波特率不是越大越好 #

数值越大速度越高，那是不是设得越大越好？不是。它要根据现场传输条件决定，设得越大，要承担的通信失败风险越大。

原因在物理层：位宽变窄，9600 时一位约 104 微秒，115200 时只有 8.68 微秒，线缆分布电容与终端反射在宽位时被平均掉，在窄位时直接把边沿压塌；两端晶振偏差是固定比例，位宽越窄，采样点越容易跑出那一位的窗口；长线高频衰减更狠，同一根线跑 9600 能拉一千米，跑 115200 也许几十米就开始丢。

现场的做法是够用就好。一条 485 挂八台表、每秒轮询一轮，9600 足够了。硬上 115200，换来的只是更短的可用距离与更高的误码率。调试顺序也对：先降速，怎么都不通时把波特率从 115200 降到 9600 试一次，通了说明问题在电气与线材，不在协议。

三、协议不是总线 #

3.1 总线管谁在什么时候能说话 #

协议定义字节的形状，总线定义说话的机会。共享线路上同一时刻只能有一个发送方，否则两个驱动同时往一对线上灌电流，结果是一片乱电平。

  • 主从轮询。主站按顺序问 1 号、2 号、3 号，被问到的才应答。485 上的 Modbus RTU。简单、确定性好，代价是轮一圈的总时间随节点数线性增长。
  • 载波侦听加仲裁。谁都能在空闲时开始发，发的同时盯着线，发现自己发的位被强势位压掉就立刻退出、转为接收。CAN。优先级由报文 ID 决定，ID 越小越优先。
  • 交换式转发。每节点独占一条链路接交换机，按 MAC 表只送目的端口。以太网，冲突在星型拓扑里被消灭。

这三种跟协议内容无关。同一条 CAN 线今天跑 CANopen 明天跑自定义报文，仲裁照样按 ID 走。

3.2 一条线上能并存多种协议 #

只要地址规划不撞，多种协议能共用一条物理链路。一条 CAN 线可以这样分：

text
ID 0x180~0x1FF   运动控制，CANopen 的 PDO
ID 0x600~0x67F   CANopen 的 SDO 配置通道
ID 0x0C0~0x0CF   厂商私有状态广播
ID 0x7DF         诊断请求

四组 ID 段各归各家，收发器一视同仁，控制器按 ID 过滤。总线上没有「这条线是 CANopen 的」这种属性，只有 ID 分配约定。485 同理，只是没有硬件过滤，全靠软件按地址判断。

3.3 同一种协议能跑在不同总线上 #

Modbus 是最典型的例子，它被移植到了几乎所有能传字节的介质上：

变体 承载 校验 典型场景
Modbus RTU RS485 / RS232 CRC16 仪表、电表、变频器
Modbus ASCII RS232 / 拨号 Modem LRC 低速、可读调试
Modbus TCP 以太网 + TCP/IP 无（靠 TCP） 车间级、SCADA 采集
Modbus RTU over TCP 以太网 保留 CRC16 串口服务器透传

最后一行值一提：串口服务器把 485 上的原始字节流打包进 TCP，字节内容一字不改，包括 CRC。这种用法里 485 的物理约束还在（半双工、主从、终端电阻），只是中间一段换成了网线。同一份报文能从铜线跑到光纤再跑进 TCP，报文本身不用改，这是分层的直接证据。

3.4 总线层的三个物理约束 #

节点数上限。 485 收发器的输入阻抗决定能挂多少，标准把负载定义为单位负载，一条总线带 32 个单位负载，用 1/8 负载的收发器能带更多。CAN 收发器把节点数卡在几十到一百多，具体看收发器与布线。

距离与速率反比。 同一条线速率翻倍，可用距离大致减半，485、CAN 都成立，原因是高频衰减与位宽变窄。

终端匹配。 长线两端要接终端电阻，否则边沿反射。第六章单独讲。

3.5 从站地址不是节点数 #

Modbus 的从站地址范围 1 到 247，看起来能挂 247 台，但 485 的电气上限只有几十台。地址空间是协议层给的字段宽度，电气负载是物理层能驱动的实际节点数，真实上限取两者中小的那个。

挂 40 台表时地址够用、电气已到顶；挂 5 台时两个限制都不碰。现场遇到「地址不冲突但接不通」，先数节点数、看收发器型号，别先怀疑地址。

四、常见组合对照 #

4.1 组合总表 #

组合 传输方式 协议 拓扑 典型领域
RS485 + Modbus RTU 差分半双工 Modbus RTU 主从多点 电表、水表、变频器、PLC
以太网 + Modbus TCP 交换式链路 Modbus TCP 星型 车间采集、SCADA
CAN + CANopen 差分多主 CANopen 多主 运动控制、伺服、编码器
CAN + J1939 差分多主 SAE J1939 多主 商用车、发动机、农机
以太网 + EtherCAT 交换式，从站直通 EtherCAT 线/环/树 高速运动控制

第 2 列只有几个值，第 3 列有十几个。传输方式的选项比协议少得多，因为电气标准就那几套，协议可以随便长。

4.2 三种最常见的落地 #

RS485 + Modbus RTU：设备便宜、两线接线、能拉上千米、主站软件满地都是。分工是 485 负责电平、方向切换、距离，Modbus RTU 负责地址、功能码、CRC、帧间静默判定。两端必须一致的东西只有四样：波特率、数据位、校验、停止位。

以太网 + Modbus TCP：同一个协议搬过去改了三点——去掉 CRC（TCP 的校验和、序列号、重传已包了可靠性）；加 7 字节 MBAP 头（事务标识、协议标识、长度、单元标识）；没有帧间静默（TCP 是字节流，帧边界由 MBAP 的长度字段给出）。地址变成 IP，从站地址塞进「单元标识」。一层套一层，正是分层的直接体现。

CAN + CANopen / J1939：CAN 提供传输与仲裁，另一层补应用。CANopen 定义对象字典、SDO 配置通道、PDO 过程数据通道、NMT、心跳，运动控制爱用：仲裁天然给了优先级，急停与位置环用 ID 小、优先级高的帧，配置报文用低优先级，冲突时高优先级先走。J1939 面向商用车与重型机械，报文 ID 里塞了优先级、PGN、源地址。两套能跑在同一个收发器上，甚至同一条线上，只要 ID 不撞，换协议不用换线。

以太网 + EtherCAT：帧不在每个从站停下来重组，从站用硬件在帧经过时读写属于自己的那段数据，一帧扫完整条链。物理上还是标准以太网 PHY 与线缆，只是以太网类型字段换成了 EtherCAT 的值。

4.3 RS232 + 自定义协议：一种最小组合 #

老设备里最常见的组合。232 负责电平，协议是厂商自己定的，帧格式往往写在一张纸上。私有协议也得定帧内结构，而这件事要回到位的级别，因为一个字符由几个位组成是配置决定的。

数据位。 计算机处理的是「0」和「1」组成的机器语言，一个字符用几个位的组合表示，这就是数据位的含义。

text
01000001 → A    01000010 → B    01000011 → C
01000100 → D    01000101 → E    01000110 → F

大写 A 是 01000001，八个「0」或「1」，数据位就是八位。合法的数据位值是 4、5、6、7、8，常用的 8 位与 7 位。

设了数据位就知道数据长度，然后能按波特率算传输一个字符要多少时间。数据位 8、波特率 9600：

text
8 / 9600 = 0.00083 秒 = 0.83 毫秒

这还不是最终正确的算法，原因在停止位与校验位。

停止位。 光有数据位不能通信：接收方怎么知道一个字符传完了？靠停止位。有停止位就有起始位，告诉接收方一个字符开始。

为什么格式里不用设置起始位？停止位是高电平（1），接收方收到连续高电平表示一个字符传输结束；起始位是低电平（0），收到连续低电平表示下一个字符开始。停止位可靠（1 位或 2 位），干扰造出假起始位的概率就不大。常用的停止位是一位与二位。

停止位设 2 位，则一起始 + 八数据 + 两停止，总位数 11：

text
11 / 9600 = 0.0011 秒 = 1.1 毫秒

这还不是最终值，因为没算校验位。

校验方式。 抗干扰做得再好也只是提高，不能完全消除。「0」会变成「1」，「1」会变成「0」，这种错误一定发生。接收方要判断收到的字符对不对，办法是加一个校验位。

  • 偶校验（even，简写 e）：字符里「1」的个数是奇数就置 1，是偶数就置 0，让总的「1」为偶数。A 的 01000001 有两个「1」是偶数，校验位 0，发出 01000001 0。
  • 奇校验（odd，简写 o）：字符里「1」的个数是偶数就置 1，是奇数就置 0，让总的「1」为奇数。同样是 A，校验位 1，发出 01000001 1。
  • 无校验（none，简写 n）：没有校验位。

它怎么起作用：干扰把某个「0」变成「1」，偶校验下「1」的个数变成奇数、奇校验下变成偶数，接收方算一遍发现不符，回一个奇偶校验错误。

它没法完全校验正确。奇校验发 A 的 01000001 1，干扰后收到 01000010 1，那其实是 B。「1」的位置变了，个数还是奇数，奇校验认为合法。发的是 A，收的是 B，校验位还说没事。 所以每套标准协议都要再加校验和：Modbus RTU 用 CRC，Modbus ASCII 用 LRC。

奇偶校验与校验和不是一回事，这里混淆的人很多：

名称 管什么 覆盖范围
奇偶校验 判断一个字符传得对不对 单个字符
校验和（CRC / LRC） 判断一组字符传得对不对 整帧

回到格式。9600，o，8，2 即一起始位、八数据位、一校验位、两停止位，总位数 12：

text
12 / 9600 = 0.00125 秒 = 1.25 毫秒

1.25 毫秒才是传输一个字符 A 的最后理论值，用它估算传一组字符要多久。用无校验方式，算的时候不加校验位那一位。这套算法跟协议无关，任一帧格式、任一传输方式都成立。以太网上没有起始位与停止位，因为它同步、有帧边界，不靠电平变化找字符边界——这本身就是传输方式差异的又一例证。

五、高频混淆点 #

5.1 「485」不是协议 #

最高频的一条。485 是电气标准，全称 TIA/EIA-485，规定差分电平、共模范围、负载数量、方向控制。它没有规定帧头几个字节、地址在哪一位、校验怎么算、命令字怎么编。

判别方法很简单：问一句「这一帧的第三个字节是什么」，答不出来的是传输方式，答得出来的是协议。

5.2 「CAN」既是物理层也是数据链路层 #

CAN 特殊一点，规范本身包含两层：物理层管差分电平、位填充、位时序、同步；数据链路层管数据帧、远程帧、错误帧、过载帧的结构，以及 CRC、应答位、仲裁、错误计数与总线关闭。

但它不含应用层。规范里没有「温度值」这种概念，数据场就是若干个字节，含义由上层协议定。所以「CAN」比「485」覆盖得宽，又比「CANopen」覆盖得窄，中间这一档最容易说不清。

5.3 「以太网」是链路层，TCP/IP 在其之上 #

以太网管同一段链路里帧怎么送：48 位 MAC 地址、帧校验、最小帧长。它不管 IP 地址，也不管端口号。TCP/IP 压在它上面：IP 负责寻址与路由，TCP 负责可靠传输、顺序、重传。

所以两者不是并列的两项，是上下两层。这也解释了 EtherCAT 为什么能跑在以太网上却不用 TCP/IP：它绕过网络层与传输层，直接用以太网帧。

说法 层 管什么
以太网 链路层 MAC 寻址、帧、CRC
IP 网络层 IP 地址、路由
TCP / UDP 传输层 端口、连接、可靠性
Modbus TCP 应用层 功能码、数据含义

5.4 「串口」是物理接口，UART 是控制器 #

这两个词天天互换着用，其实是硬件里两个不同位置的东西。

  • UART：SoC 内部的外设控制器，负责并串转换、起始停止位插入、校验位生成、波特率分频。CPU 通过寄存器跟它打交道。
  • 串口（物理接口）：芯片引脚外面的电平形式与接插件。TTL 电平、RS232 电平、RS485 差分是不同的物理接口。

中间还隔着电平转换：TTL 的 3.3V 要变成 232 的正负十几伏，得加 MAX232 一类芯片；要变成 485 差分，得加 485 收发器。所以「串口不通」的坏点有四处：UART 配置、引脚复用、电平转换芯片、接插件与线缆。全说成「串口坏了」就没法往下查。

5.5 剩下三条短记 #

波特率与比特率。 波特率是每秒的符号数，比特率是每秒的位数。串口里一个符号就是一位，两个数值相等，日常混用不出事。到了别的传输方式就不成立：以太网用编码，一个符号带多个位；CAN 有位填充，实际数据速率与线速率不等。

半双工约束着协议的样子。 485 半双工，收发共用一对线，方向要切换，这个电气特性直接塑造了 Modbus RTU 的形态：主从轮询、帧间静默、不能同时收发。422 与 232 全双工，跑在上面的协议可以做流式传输，不用等静默。协议的样子被传输方式的电气特性约束着，这是两层之间少见的耦合点。

校验位不是万能。 它只管一个字符，整帧靠 CRC 或 LRC。

5.6 混淆点速查 #

说法 实际是什么 容易错在哪
485 协议 电气标准 根本没有「485 协议」这东西
CAN 协议 物理层 + 链路层规范 以为它包含应用层
以太网协议 链路层 跟 TCP/IP 混为一谈
串口协议 物理接口 + UART 以为有帧约定，其实没有

Profibus 是协议 物理层用 485，上层自有 以为 Profibus 就是 485

六、终端电阻的通用原理 #

6.1 从光进入水面说起 #

光从空气进入水面，水面会反射一部分光线回去。原因是空气与水的媒质不同，光进入不同媒质时会在临界点反射。

电信号在传输线上跑是同一回事。传输线有自己的特性阻抗，信号沿线传播时，如果末端阻抗突然减小甚至完全没有，信号就在末端产生反射。反射波沿线路跑回来，叠加到后续信号上，把波形搅乱。

术语对齐一句：传输线阻抗不连续的地方就有反射，强度由两端阻抗的差决定，差得越多反射越强。

6.2 反射为什么造成误判 #

反射波不是噪声，是原信号的一部分能量折回来，跟原信号一起压在接收端的判决点上。幅度叠加时同相，电压被抬高，0 会被认成 1；幅度抵消时反相，电压被压低，1 会被认成 0；边沿振铃则是反射波滞后一小段到达，在边沿后造出一串震荡，在这段里采样就是碰运气。

这三种都表现为「偶发丢帧」「长线才出错」「动一下线就好」。示波器上看，边沿上是一串明显的过冲与回弹。

6.3 终端电阻做的事就是阻抗匹配 #

彻底消除反射的办法只有一个：让传输线末端看起来无限长。做法是在末端接一个等于特性阻抗的电阻，信号跑到末端看到的负载与线的特性阻抗一致，能量被吸收，没有反射。

RS485 与 CAN 的特性阻抗标称都是 120 Ω，所以两端的终端电阻都是 120 Ω。 这不是某个协议的专利，是这两种差分线的特性阻抗决定的数值。

以太网也一样，只是匹配做在内部：双绞线特性阻抗约 100 Ω，PHY 芯片里已有端接网络，网线两头不用外接电阻。同轴时代就不同，10BASE2 细缆要在两端各拧一个 50 Ω 端接器，中间还要接 T 型头。

终端电阻是传输线阻抗匹配的通用做法，凡是「长线 + 高速」的传输方式都会碰到，只是内置还是外置的区别。

6.4 为什么只有两端，中间不能加 #

两端各一个 120 Ω 并联，总线看到的端接阻抗是 120 Ω，跟线的特性阻抗匹配，正确。中间每多挂一个 120 Ω 就多并联一个：三个变 40 Ω，五个变 24 Ω。

后果两条：阻抗失配，40 Ω 对 120 Ω 的线反射照样有，终端反而成了新的不连续点；驱动过载，485 收发器的差分输出电流有上限，负载阻抗太低，输出差分电压被拉下去，接收端认不出电平。CAN 更严重，显性电平靠收发器驱动整个总线阻抗产生压差，端接不对幅度直接不达标。

规则很硬：只有物理上最远的两个端点各接一个，中间一个都不加。 分支线也要短，因为分支本身就是阻抗不连续点。

6.5 偏置电阻是另一件事 #

总线空闲时 A、B 之间没有驱动，压差会落在不确定区，接收器输出随机电平，被软件读成一串假起始位。偏置电阻给 A、B 加一个微弱固定偏压，让空闲状态明确为「1」。

终端电阻管反射，偏置电阻管空闲状态。 素材里的原话是「加一个偏置电阻，人为地保持阻抗平衡，减弱信号反射对线路的影响」——这一句讲的是现场加电阻的动机：不让人为地留一个阻抗断口，反射就没有着力点。

阻值差一个数量级，偏置是几百欧到几千欧，串在电源与地之间。很多模块把两组电阻都做在板子上，用跳线帽选，现场调不通时先看清跳线选的是哪一组。

6.6 什么时候可以不加 #

线很短、速率很低、桌面临时调试两三种情况可以不加：反射能量还没大到影响判决，或反射在一位之内衰减完。但现场必须加。临时能通与长期稳定是两件事，温漂、湿度、线材老化都会让边沿变差，短线的余量会被慢慢吃掉。遇到「白天正常晚上丢帧」「夏天出问题」，先量终端电阻。

七、工业总线的谱系 #

7.1 五条线，五个出身 #

工业总线不是一套统一标准演进出来的，是几家厂商各自解决自己的问题，然后竞争并存。理解出身比记参数有用。

总线 出身 物理层 解决的问题
Modbus Modicon，1979 485 / 232 / 以太网 让 PLC 与仪表用一套简单报文说话
Profibus 西门子主导，德国标准 485（DP）/ 光纤 工厂自动化的设备级与车间级连接
Interbus Phoenix Contact 串行，环形 传感器/执行器层的接线简化
CANopen CAN in Automation 组织 CAN 运动控制里的设备互操作
EtherCAT Beckhoff 以太网 用标准以太网做到硬实时

7.2 各家的定位 #

Modbus 最朴素：简单到一张纸能写完，所以活得最久，也最容易被移植。三种变体共用一套功能码，实现一个从站栈工作量很小，低端 MCU 也能跑。没有实时性保证、没有节点管理、没有诊断机制，主站轮一圈的时间随节点数线性增长。优势也一样：谁都能做，串口助手加 CRC 小工具，五分钟能调通一台表。

Profibus 物理层借用 485（DP 变体），上层是自有协议，令牌传递加主从混合：多主之间传令牌，拿到令牌后跟自己的从站通信。强项是工程集成不是协议本身，一套编程环境把组态、诊断、报警全包了，代价是绑定厂商。

Interbus 是传感器总线：串行通信，物理环形，逻辑上是移位寄存器，一帧在环里走一圈，每个节点在固定位置读写自己那几位。素材里给它的定位是「传感器/调节器总线系统」，目标是省线，一堆分散的开关量用一条环串起来，接线量比传统星型少一个数量级。

CANopen 补上 CAN 缺的应用层：对象字典、SDO、PDO、NMT、心跳。素材对 CAN 的定性只有一句——「canbus 是 real-time 数据总线」，这句定性落在仲裁上：ID 越小优先级越高，高优先级的帧不会被低优先级的挡住，最坏延迟能算出来。对象字典是核心，每个参数有 16 位索引加 8 位子索引，访问方式统一，让不同厂商的设备能被同一套主站工具识别与配置。

EtherCAT 从站用专用芯片，帧经过时不中断，硬件在飞行中读写，一帧扫完整链，周期能压到几十微秒。它把以太网这个传输方式用得最彻底：不改帧结构，不加 TCP/IP，直接用。代价是硬件依赖，从站必须有专用芯片，普通网卡当不了从站。

八、按实时性排序 #

8.1 排序不看速率，看延迟的确定性 #

这里的「实时」指的不是「快」，是延迟有上界、抖动小。

一条总线能跑 100 Mbps，但每次传输的延迟在 1 到 50 毫秒之间浮动，运动控制里完全不能用。反过来，一条 1 Mbps 的总线，如果最坏延迟稳定在 2 毫秒以内，反而能满足不少场合。

排序看三件事：周期能压到多小、抖动多大、最坏情况能不能算出来。

总线 实时性 周期量级 抖动 确定性来源
EtherCAT 最高 微秒到亚毫秒 极小 硬件直通，主站独占链路
Profibus-DP 较高 毫秒 小 令牌加主从，周期可算
CANopen 中 毫秒 视负载 仲裁优先级，负载低时稳定
Interbus 中 毫秒 小 移位寄存器，结构固定
Modbus RTU 低 十毫秒到百毫秒 大 主站轮询，无优先级机制
Modbus TCP 低 十毫秒以上 大 走 TCP，重传与拥塞不可控

周期量级一栏都是量级，实际值跟节点数、报文长度、主站性能相关，视实现而定，不能当硬指标。

8.2 复杂度排序几乎是反过来的 #

总线 复杂度 上手门槛 专用硬件
Modbus 最低 串口助手就能调 无
CANopen 中 要懂对象字典 CAN 控制器
Interbus 中高 要懂环形拓扑 专用主站卡
Profibus 高 要懂 GSD 与令牌 专用主站卡
EtherCAT 最高 要懂分布式时钟 专用从站芯片

实时性与复杂度基本同向：越实时的东西越贵越难。这是选型时的核心张力。

8.3 有一条中界线 #

要控制运动、要做位置环、要多轴同步，往右走，EtherCAT 或 CANopen。要采集数据、要抄表、要监控状态，往左走，Modbus 够用。

绝大多数「不知道该选哪个」的场合，是因为没先回答「这台设备的数据要不要参与控制」。要参与控制，实时性就是硬指标；只是采集展示，百毫秒延迟无所谓。

九、选型的判断顺序 #

9.1 四步，顺序不能反 #

最常见的错法是从协议细节开始：先看 Modbus 支持哪些功能码，再比 CANopen 的对象字典，比到最后发现主站设备根本不支持。正确的顺序反过来：

text
第一步  实时性要求   →  要不要上实时总线
第二步  距离与节点数 →  物理层选什么
第三步  主站与工具链 →  协议选什么
第四步  协议细节     →  参数怎么配

每一步都在砍掉一大批选项，最后剩下的往往只有一两个。

9.2 第一步：实时性 #

问一句：这个数据晚到 100 毫秒会怎么样？

无所谓的话，采集温度、抄电表、看状态，Modbus 够了。会出问题的话，伺服位置环、多轴插补、急停联锁，必须上实时总线。

这一步决定后面所有的预算量级。实时总线意味着专用芯片、专用主站、专用工具链。

9.3 第二步：距离与节点数 #

场景 距离 节点数 物理层倾向
单机柜内 几米 十来个 板级总线或以太网
一条产线 几十到几百米 几十个 485 或 CAN
跨车间 上千米 上百个 光纤或分段加中继
跨厂区 数千米 分散 以太网 + 网关

距离与节点数一起决定物理层能不能用，这一步跟协议无关。485 与 CAN 的节点数、距离上限都在物理层规格里，翻手册就有。

9.4 第三步：主站与工具链 #

这一步在实际项目里权重最大，却最容易被忽略。问题很具体：现场的主站设备支持什么。

  • PLC 只有 485 口，那就是 Modbus RTU，没得选。
  • 上位机只有以太网，那就是 Modbus TCP 或加串口服务器。
  • 运动控制器只认 EtherCAT，那从站必须选 EtherCAT 的。

协议不是技术上更优就能上，得看对面接不接得住。这一条往往在第一步之前就把选项砍完了，但工程上的思考顺序是先想清需求，再被现实收窄。

9.5 第四步：协议细节 #

到这一步才轮到波特率、校验、地址、功能码、超时、重试次数。这些参数配错了要调很久，但它们不影响选型决策，只影响调通的速度，调整成本低、可逆。

9.6 一个反例 #

见过一种设计：为了「技术先进」，把一条抄电表的 485 线换成了 EtherCAT。

结果每块电表都要加一个 EtherCAT 从站接口，成本涨了十倍；电表本身只支持 Modbus RTU，还得加协议转换；整个系统从「一秒一轮」变成「一毫秒一轮」，可抄表本来就不需要这么快。

这是把第四步当成了第一步。抄表的实时性要求是「一分钟内更新」，用 EtherCAT 是纯浪费。反过来也有：拿 Modbus RTU 做三轴插补，周期抖动几十毫秒，做出来的运动是抖的。这是把第一步的需求低估了。

十、调试时的分层定位 #

10.1 通不了，先分三层 #

现场最常见的浪费是跳层排查。线还没量就开始改 CRC 算法，地址还没确认就开始怀疑协议版本。

按层往下走，每层有明确的通过标准：

层 查什么 通过标准 工具
物理层 电压、接线、终端电阻、地 差分波形干净，幅度达标 万用表、示波器
链路/总线层 方向切换、仲裁、节点数、地址冲突 单台能通，多台不撞 总线分析仪
协议层 帧格式、校验、功能码、超时 帧解析正确，CRC 通过 串口助手、协议分析软件
应用层 数据含义、字节序、缩放 数值与现场一致 上位机、万用表对照

四层的现象完全不重叠，所以顺序不能乱。

10.2 物理层的三件事 #

量电压。 485 的 A、B 之间，空闲时靠偏置电阻有几百毫伏压差，发送时有 1 到 6 伏差值。232 的 TX 对 GND，空闲是负电平，约 -5 到 -12 伏。量不到预期值，后面全都不用查。

查接线。 485 的 A、B 接反是最常见的错，症状是「完全不通」，跟没接一样。对调试一次，一分钟的事。

量终端电阻。 断电，用万用表量 A、B 之间的电阻。两端各一个 120 Ω 并联，读数约 60 Ω。读数是 120 Ω 说明只接了一个，是 40 Ω 说明接了三个，读数很小说明有人把中间节点也加了。这是最快的一次判断，别跳过。

10.3 链路层：单台能通，多台不通 #

物理层过了，就把设备一台一台往上加。

单台能通，说明物理层与协议层都没问题，问题在总线层：查地址冲突、节点数上限、方向切换时序。单台也不通，问题在物理层或协议层，回到上一层。

「单台能通、挂第二台就乱」，大半是两台地址设成了同一个；或者一台设备的方向切换太慢，发完不释放总线，把别人的应答顶掉了。

10.4 协议层：波形好，数据错 #

物理上已经干净，问题在字节的组织。按这个顺序查：

  1. 参数一致性。波特率、数据位、校验、停止位四样逐个对。这一项占协议层故障的一半以上。
  2. 帧边界。RTU 靠 3.5 字符静默分帧，主站发太快，从站会粘帧。查主站的帧间隔设置。
  3. 地址。从站地址是否与主站配置一致，广播地址 0 有没有被误用。
  4. 校验。CRC 高低字节顺序，Modbus 是低字节在前，这是实现里最常见的坑。
  5. 功能码。设备是否支持，不支持的会回异常码。

10.5 应用层：数据通了但不对 #

帧收对了，CRC 也对，数值就是不对。常见原因四个：字节序（一个 32 位浮点，四字节的排列顺序各厂不一致）、缩放系数（寄存器里存 1234，实际值是 12.34，因为有个 100 倍系数写在手册第 47 页）、寄存器偏移（手册编号从 1 开始，协议地址从 0 开始，差一位）、有无符号（负温度读出来是 65535，因为按无符号解析了）。

这一层的问题不在通信，在文档。查手册，别改代码。

10.6 分层排查的一张流程图 #

text
不通
 ├─ 量电压：不对 → 查接线、查电平转换、查供电
 ├─ 量终端电阻：不对 → 按 60Ω 目标修正两端
 ├─ 单台单独接：不通 → 回物理层与参数
 └─ 单台能通
     ├─ 多台挂上就乱 → 查地址冲突、节点数、方向切换
     ├─ 有波形但解析失败 → 查波特率/校验/帧间隔/CRC 字节序
     └─ 帧对但数值错 → 查字节序、缩放、寄存器偏移、符号

按这张图走，每一步都有明确的下一步。跳层查，等于把四层的不确定性混在一起。

十一、从概念到实践 #

11.1 三条判断句 #

第一句：这一层是电气还是约定？ 问的是物理层与协议层的分界。答「电气」的，查线、查电平、查终端电阻；答「约定」的，查参数、查帧格式。

第二句：这条线上有几家在说话？ 问的是总线层。一家就没有寻址问题；多家要看是主从还是多主，地址与优先级怎么排。

第三句：这个数据晚到会怎样？ 问的是选型的起点。无所谓就选简单的，会出事就往实时总线走。

11.2 换个设备怎么套 #

新拿一台设备，先看它标的接口：

text
RS485 接口，支持 Modbus RTU，8N1，9600~115200

拆开读：RS485 是物理层，两线差分半双工，长线要终端电阻，A/B 不能反；Modbus RTU 是协议层，帧格式固定，CRC16，地址 1 到 247；8N1 是帧内位结构，8 个数据位、无校验、1 个停止位；9600~115200 是传输方式的速度范围，跟线长成反比。

再遇到：

text
CAN 接口，支持 CANopen，500 kbps

CAN 是物理层加链路层，差分、多主、有仲裁；CANopen 是应用层，对象字典、SDO、PDO；500 kbps 是位速率，需要两端终端电阻 120 Ω。

同一套拆法，套到任何接口描述上都成立。

11.3 为什么这套分层能省时间 #

因为它把一个大问题切成了几个小问题，每个小问题有独立的验证手段。

不分层时，「通信不通」是一个黑洞：线、参数、协议版本、数据含义全缠在一起，只能靠经验和运气一个个试。分层之后每层都有对应工具：万用表量物理层，总线分析仪看链路层，串口助手看协议层，上位机看应用层。工具对上了，问题收敛得快。

RS485 只负责把 0 和 1 变成差分电平传出去，它不知道也不关心上面跑的是 Modbus 还是私有协议。以太网只负责把帧送到对端，上面可以是 TCP/IP，也可以是 EtherCAT。 这个分层认清了，选型与调试都不会乱。

十二、易错点速查 #

12.1 概念层 #

易错点 现象 正确做法
把 485 当协议 说不清帧里有什么字段 485 是电气标准，协议另选
把 Modbus 当硬件 以为换协议要换线 协议与线缆无关
把 CAN 当完整协议栈 以为 CAN 有应用层 CAN 只到链路层
把以太网当 TCP/IP 认为 EtherCAT 不算以太网 以太网是链路层，TCP/IP 在其上
认为串口就是 UART 引脚没波形就怀疑芯片 分 UART、复用、电平转换、接插件四段查
认为波特率越高越好 长线高频丢帧 按线长与噪声降速
认为校验位能保证正确 A 收成 B 还认为合法 校验位只管单字符，整帧靠 CRC

12.2 物理层与接线 #

易错点 现象 正确做法
终端电阻只接一端 长线偶发丢帧 两端各 120 Ω，读数约 60 Ω
中间节点也加终端电阻 波形幅度整体被压低 只有两端加
485 的 A/B 接反 完全不通 对调 A/B 试
忘接信号地 时通时不通，碰线就断 差分线也要共地
分支线拉太长 高速时局部误码 分支尽量短
偏置电阻当终端电阻用 空闲电平仍不确定 两者功能不同，分开选跳线
用杜邦线拉长距离 干扰丢包 换双绞或加驱动

12.3 参数与协议 #

易错点 现象 正确做法
两端波特率不一致 全是乱码 两端设同一个值
校验位奇偶配反 数据对但错误计数涨 两端一致，多数场景用无校验
停止位 1 配 2 间歇帧错误 两端一致
帧间隔不够 从站粘帧、解析失败 主站帧间隔大于 3.5 字符时间
CRC 字节序搞反 CRC 恒错 Modbus 的 CRC 低字节在前
地址冲突 多台同时应答，电平混乱 逐台确认地址
广播地址误用 多台同时回，冲突 0 地址只用于写，不应答
节点数超上限 越挂越不稳 查收发器负载能力

12.4 选型层 #

易错点 现象 正确做法
从协议细节开始选型 选完发现主站不支持 先定实时性，再定距离节点数，再定主站
用实时总线做纯采集 成本暴涨，收益为零 采集类用 Modbus 就够
用简单协议做运动控制 运动抖动，周期不稳 实时要求高的上 EtherCAT 或 CANopen
忽略厂商绑定 换品牌要重学一套 把工具链成本算进选型
忽略协议转换成本 每台设备加一个网关 前期把协议统一
只看纸面速率 实际距离与干扰不达标 速率与距离一起评估

12.5 一句话收尾 #

工业通信的坑，八成出在三件事上：层没分清、线没接对、参数没对齐。层分清是前提，线接对是基础，参数对齐是耐心活。这三件按顺序做完，剩下的问题基本都能在十分钟里定位。
