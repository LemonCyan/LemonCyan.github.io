本篇讲两件事：套接字选项这组「行为开关」怎么调，以及 UDP 的一对多发送怎么落地。

讲：setsockopt / getsockopt 的调用姿势，SO_REUSEADDR 为什么能救重启，它和 SO_REUSEPORT 的分界，广播与组播的编址、组管理、TTL 与回环。

不讲：套接字超时（SO_RCVTIMEO、SO_SNDTIMEO、select / poll 等待）在同组的《套接字的超时控制》；三次握手与四次挥手的状态流转在《TCP 套接字编程》；epoll 与并发模型在《服务器并发模型》。

读法：第三章到第六章围着服务端重启与 TCP 行为打转，第七章到第十一章围着 UDP 一对多打转，两段可以拆开看。

一、套接字选项是什么 #

socket() 只决定协议族和类型：IPv4、TCP、UDP。剩下的行为细节——收缓冲多大、关连接时怎么收尾、端口能不能复用——不在 socket() 的参数里，而在内核为每个套接字维护的一组开关里。这组开关就是套接字选项。

选项分两层。一层是通用的，SOL_SOCKET，跟协议无关；另一层挂在具体协议上，IPv4 用 IPPROTO_IP，TCP 用 IPPROTO_TCP，IPv6 用 IPPROTO_IPV6。名字在同一层里唯一，所以同一个选项名出现在两层也不冲突。

层 代表选项 管什么
SOL_SOCKET SO_REUSEADDR SO_REUSEPORT SO_KEEPALIVE SO_LINGER SO_RCVBUF SO_SNDBUF 套接字自身的行为
IPPROTO_TCP TCP_NODELAY TCP_KEEPIDLE TCP_KEEPINTVL TCP_KEEPCNT TCP 协议的细节动作
IPPROTO_IP IP_MULTICAST_TTL IP_MULTICAST_LOOP IP_MULTICAST_IF IP_ADD_MEMBERSHIP IPv4 单播、广播、组播的收发行为
IPPROTO_IPV6 IPV6_MULTICAST_HOPS IPV6_MULTICAST_LOOP IPV6_JOIN_GROUP 同上，IPv6 版

读写的入口只有两个函数：

text
int getsockopt(int sockfd, int level, int optname, void *optval, socklen_t *optlen);
int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);

布尔型选项一律用 int 传：0 是关，非 0 是开，长度写 sizeof(int)。别传 char，也别把 4 写死。带结构的选项要按结构传，比如 SO_LINGER 收 struct linger，IP_ADD_MEMBERSHIP 收 struct ip_mreq。

设置时机有讲究，设晚了不报错，但也不生效，这种哑巴失败最难查。

选项 必须在什么之前设
SO_REUSEADDR / SO_REUSEPORT bind() 之前
SO_BROADCAST 往广播地址 sendto() 之前
SO_RCVBUF / SO_SNDBUF connect() 或 listen() 之前设，改的是后续窗口的参照
TCP_NODELAY 建连之前最省事，建连后设也认
IP_ADD_MEMBERSHIP 收包之前，recvfrom() 之前
IP_MULTICAST_TTL / IP_MULTICAST_LOOP 发包之前

有一条要认清：setsockopt 返回 0 只说明请求被接受，不代表内核照单全收。缓冲区大小这类值内核会按自己的上下限裁剪，甚至成倍放大。想知道真实生效多少，getsockopt 读回来。

二、setsockopt 的用法 #

level 填层，optname 填选项名，optval 指向值，optlen 是值的字节数。五个参数里 optlen 最容易写错。

c
#include <sys/socket.h>
#include <netinet/in.h>
#include <netinet/tcp.h>
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

/* 布尔开关：SOL_SOCKET 下的选项多数走这里 */
static void set_bool_opt(int fd, int level, int optname, const char *name)
{
    int on = 1;
    if (setsockopt(fd, level, optname, &on, sizeof(on)) < 0) {
        fprintf(stderr, "setsockopt(%s): %s\n", name, strerror(errno));
        exit(1);
    }
}

/* 整型值：SO_RCVBUF、SO_SNDBUF、IP_MULTICAST_TTL 走这里 */
static void set_int_opt(int fd, int level, int optname, int val, const char *name)
{
    if (setsockopt(fd, level, optname, &val, sizeof(val)) < 0) {
        fprintf(stderr, "setsockopt(%s): %s\n", name, strerror(errno));
        exit(1);
    }
}

/* 回读：确认内核真正给了多少；失败返回 -1 */
static int get_int_opt(int fd, int level, int optname)
{
    int val = 0;
    socklen_t len = sizeof(val);
    if (getsockopt(fd, level, optname, &val, &len) < 0) return -1;
    return val;
}

拿一个 socket 串起来看：

c
int main(void)
{
    int fd, want, got;

    if ((fd = socket(AF_INET, SOCK_STREAM, 0)) < 0) { perror("socket"); exit(1); }

    set_bool_opt(fd, SOL_SOCKET, SO_REUSEADDR, "SO_REUSEADDR");

    want = 1 << 20;                          /* 想要 1MB 收缓冲 */
    set_int_opt(fd, SOL_SOCKET, SO_RCVBUF, want, "SO_RCVBUF");

    got = get_int_opt(fd, SOL_SOCKET, SO_RCVBUF);
    printf("want=%d got=%d\n", want, got);    /* 两者不等是常态 */

    close(fd);
    return 0;
}

want 和 got 不相等，是常态。内核对缓冲区有自己的上下限和记账方式，你给的是期望值，不是命令。

setsockopt 失败时 errno 会说明问题：

errno 含义
EBADF sockfd 不是合法的文件描述符
ENOTSOCK sockfd 指向的不是套接字
EFAULT optval 指向的内存不可访问
EINVAL optlen 非法，或选项值本身非法
ENOPROTOOPT 这一层没有这个选项，多半是 level 和 optname 配错
EPERM 该选项需要特权

ENOPROTOOPT 是最常见的自伤。TCP_NODELAY 挂 IPPROTO_TCP，SO_REUSEADDR 挂 SOL_SOCKET，写反了就是它。

三个习惯值得带上：

  1. 每次 setsockopt 都查返回值。选项没生效不会崩，只会让问题推迟到线上。
  2. 长度一律 sizeof(变量)，别写字面量。结构体换平台会变大小，字面量跟着出错。
  3. 报错时把选项名打出来。perror("setsockopt") 只说失败，不说哪个选项失败。

getsockopt 的 optlen 是值-结果参数：进来时告诉内核缓冲区多大，出去时告诉内核实际写了多少。调用前一定初始化：

c
int val = 0;
socklen_t len = sizeof(val);
if (getsockopt(fd, SOL_SOCKET, SO_TYPE, &val, &len) < 0) {
    perror("getsockopt");
}
printf("type=%d len=%u\n", val, (unsigned)len);

SO_TYPE 读回来的是 SOCK_STREAM 还是 SOCK_DGRAM，排查「这个 fd 到底是 TCP 还是 UDP」时很好用。

三、SO_REUSEADDR：为什么重启会 bind 失败 #

先复现。写一个最小的 TCP 时间服务，端口 10013，收一次连接就把当前时间写回去，然后自己重启。第一次跑没问题，第二次跑就翻车：

text
$ ./timeserv                 # 第一次起来，bind call OK
$ telnet localhost 10013     # 收到时间，对端关闭连接
$ kill %1                    # 服务停掉，端口进 TIME_WAIT
$ ./timeserv
bind: Address already in use

端口明明没人监听了，netstat -anp | grep 10013 也看不到 LISTEN，可 bind 就是拒绝。这就是本篇要解决的那个问题。

TIME_WAIT 是谁留下的 #

TCP 连接关闭走四次挥手。先发 FIN 的那一方是主动关闭方，它关闭后进入 TIME_WAIT，停留 2MSL。

服务端被 Ctrl-C 杀掉时，内核替它关闭套接字，FIN 从服务端发出。于是服务端成了主动关闭方，TIME_WAIT 落在服务端这一侧，端口被这个状态占着。TIME_WAIT 不是 LISTEN，所以 netstat 里看得出端口被占，但看不出有服务在跑。

这个等待期在 UNPv1（《Unix 网络编程》卷一，中文版 P166–168 就是专门讨论这个选项的那几页）里的描述是「端口释放后要等两分钟左右才能再被使用」。两分钟这个数不是随便定的，它等于 2MSL，MSL 是报文在网络里的最大生存时间，取值由协议栈配置决定。

为什么非要等：

  1. 让这次连接里迟到的重复报文在网络中自然消亡，不会漂到下一个用同一端口的新连接里。
  2. 最后一个 ACK 如果丢了，对端会重传 FIN，本端还能重发 ACK。

这两条都是协议正确性，不是性能开关。所以工程上不去动 2MSL，而是让内核允许在 TIME_WAIT 期间重新绑定同一个地址加端口。这就是 SO_REUSEADDR。

一句话记法：SO_REUSEADDR 解决的是「TIME_WAIT 期间无法重新 bind」的问题。

Richard Stevens 的 UNPv1 里对这个选项有完整解答，中文版 P166–168 页。下面几个例子是为了验证它写的实测代码。

它管什么、不管什么 #

端口当前状态 设了 SO_REUSEADDR 能否 bind 说明
完全空闲 能 跟选项无关
TIME_WAIT，本地地址与端口一致 能 选项的作用点
ESTABLISHED / LISTEN 被另一个 socket 占着同一地址同一端口 不能 照旧返回 EADDRINUSE
多个 socket 绑同一端口、各自不同的本地 IP 能 见下面第二种情况

所以这个选项不是「端口随便抢」。端口被别人真正用着，它一样拒绝。它只对「残留状态」放行。

素材里强调过一条规则：两个 socket 的地址和端口冲突，而你要重用时，旧的 socket 和新的 socket 都要设 SO_REUSEADDR，只有一方设还是会出问题。 这条针对的是两个都还活着的 socket 共存的情形（下面第二、三、四种情况）。TIME_WAIT 那个 socket 已经关闭，没有选项可设，此时只有新 socket 一个参与者。

UNPv1 列的四种情况 #

第一种：TIME_WAIT 期间重绑。 有一个相同本地地址和端口的 socket1 处于 TIME_WAIT（四次挥手留下的），新起的 socket2 要占这个地址端口，就得设这个选项。服务端程序永远应该在 bind() 之前设 SO_REUSEADDR。

第二种：同一端口上起同一服务器的多个实例。 多个进程各绑同一端口，但每个实例绑的 IP 地址不能相同。有多块网卡或者用 IP Alias 的机器上能试出来。TCP 下没法让两个服务器绑完全相同的 IP 加端口。

第三种：单个进程把同一端口绑到多个 socket 上。 每个 socket 绑不同的本地 IP。这和第二种很像，区别在于第二种是多个进程、第三种是一个进程里的多个 fd。这一般不用于 TCP 服务器。

第四种：完全相同的地址和端口重复绑定。 只用于 UDP 组播，不用于 TCP。这个特性只在支持组播的系统上有，而且只对 UDP 套接字成立（TCP 不支持组播）。

四条压成一句：前三条解决「不同身份共用同一个端口号」，第四条解决「同一份数据要发给多个接收者」。

例一：让它自己重启 #

素材里第一个测试程序就是这样：父进程 accept，fork() 出子进程，子进程写完时间后 sleep(1)，然后 execlp() 把同一个程序再启动起来。等于服务自己重启自己，循环往复。用 telnet localhost 10013 就能一直看到新的时间。

c
/* timeserv.c —— TIME_WAIT 与 SO_REUSEADDR 的实测程序 */
#include <netinet/in.h>
#include <sys/socket.h>
#include <unistd.h>
#include <time.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAXLINE 100

int main(void)
{
    int listenfd, connfd, flag = 1;
    socklen_t len = sizeof(int);
    struct sockaddr_in servaddr;
    char buff[MAXLINE + 1];
    time_t ticks;

    if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) < 0) { perror("socket"); exit(1); }

    memset(&servaddr, 0, sizeof(servaddr));
    servaddr.sin_family = AF_INET;
    servaddr.sin_addr.s_addr = htonl(INADDR_ANY);
    servaddr.sin_port = htons(10013);

    /* 必须在 bind 之前 */
    if (setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &flag, len) < 0) { perror("setsockopt"); exit(1); }
    if (bind(listenfd, (struct sockaddr *)&servaddr, sizeof(servaddr)) < 0) { perror("bind"); exit(1); }
    printf("bind call OK!\n");
    if (listen(listenfd, 5) < 0) { perror("listen"); exit(1); }

    for (;;) {
        if ((connfd = accept(listenfd, NULL, NULL)) < 0) { perror("accept"); exit(1); }

        if (fork() == 0) {                  /* 子进程 */
            close(listenfd);                /* 这句不能少，见下文 */
            ticks = time(NULL);
            snprintf(buff, sizeof(buff), "%.24s\r\n", ctime(&ticks));
            write(connfd, buff, strlen(buff));
            close(connfd);
            sleep(1);
            execlp("timeserv", "timeserv", (char *)NULL);
            perror("execlp");
            exit(1);
        }
        close(connfd);                      /* 父进程关掉已连接 fd，回去 accept */
    }
}

编译后放到 PATH 里某个目录（比如 $HOME/bin），运行 timeserv，再 telnet localhost 10013。把 setsockopt 那四行注释掉重编，就会稳定复现 bind: Address already in use。

close(listenfd) 为什么不能少：fork() 之后父子进程共享同一个打开文件描述，监听 fd 的引用计数变成 2。子进程不关，那个 LISTEN 状态的套接字就一直活着——它不进 TIME_WAIT，它是实打实活着的监听者。子进程 execlp() 重启出来的新实例会继承这个 fd，再 bind 同一端口，内核看到端口上已经有一个 LISTEN 的套接字，直接拒绝。子进程只负责 connfd，listenfd 应当立刻还回去。

例二：一个进程绑两个地址 #

第二种情况素材作者没有环境实测，就没有给程序。第三种情况给了一个，验证一个进程把同一端口绑到两个不同本地 IP 上：

c
/* twobind.c —— 单进程把 10013 绑到两个本地地址 */
#include <netinet/in.h>
#include <sys/socket.h>
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    int fd1, fd2, flag = 1;
    socklen_t len = sizeof(int);
    struct sockaddr_in servaddr1, servaddr2;

    if ((fd1 = socket(AF_INET, SOCK_STREAM, 0)) < 0) { perror("socket"); exit(1); }
    if ((fd2 = socket(AF_INET, SOCK_STREAM, 0)) < 0) { perror("socket"); exit(1); }

    memset(&servaddr1, 0, sizeof(servaddr1));
    memset(&servaddr2, 0, sizeof(servaddr2));
    servaddr1.sin_family = AF_INET;
    servaddr2.sin_family = AF_INET;

    if (inet_pton(AF_INET, "127.0.0.1", &servaddr1.sin_addr) <= 0) { printf("inet_pton: 127.0.0.1\n"); exit(1); }
    if (inet_pton(AF_INET, "128.160.1.230", &servaddr2.sin_addr) <= 0) { printf("inet_pton: 128.160.1.230\n"); exit(1); }

    servaddr1.sin_port = htons(10013);
    servaddr2.sin_port = htons(10013);

    /* 两个 fd 都要设，只设一边仍然失败 */
    if (setsockopt(fd1, SOL_SOCKET, SO_REUSEADDR, &flag, len) < 0) { perror("setsockopt"); exit(1); }
    if (setsockopt(fd2, SOL_SOCKET, SO_REUSEADDR, &flag, len) < 0) { perror("setsockopt"); exit(1); }

    if (bind(fd1, (struct sockaddr *)&servaddr1, sizeof(servaddr1)) < 0) { perror("bind fd1"); exit(1); }
    if (bind(fd2, (struct sockaddr *)&servaddr2, sizeof(servaddr2)) < 0) { perror("bind fd2"); exit(1); }

    printf("bind fd1 and fd2 OK!\n");
    getchar();                  /* 挂住，方便用 netstat 看两个绑定 */
    close(fd1);
    close(fd2);
    return 0;
}

两边都设了选项才通过，去掉任意一个，第二次 bind 就失败。第四个地址里的 128.160.1.230 要换成你自己机器上真有的地址，否则会得到 EADDRNOTAVAIL。

第四种情况只用于 UDP 组播，跟 TCP 关系不大，素材作者也没写测试程序。第八章会把它讲透。

这套程序在 Linux 下编译通过，其他 UNIX 平台也能跑。

慎用的一面 #

这个选项放开的只是本地地址和本地端口。一个套接字由五元组确定：协议、本地地址、本地端口、远程地址、远程端口。SO_REUSEADDR 不改变五元组的唯一性，所以重启后的服务程序有概率收到不该属于它的迟到数据。

后果是「服务程序反应混乱」这种低概率事件，实际很少见，但不是零。素材里那份问答给的结论是：必须意识到这一点，慎重使用。我的做法是只在服务端监听套接字上设，不在每条连接上瞎设。

四、SO_REUSEADDR 与 SO_REUSEPORT 的区别 #

名字只差一个词，能力差一个量级。

SO_REUSEADDR：让同一地址加端口能被重新绑定。它不能让两个进程同时监听同一个端口。 SO_REUSEPORT：允许多个进程同时监听同一地址加端口，内核把新连接分给其中一个。

前者是兼容老连接，后者是横向扩展。混着理解必然踩坑。

对比项 SO_REUSEADDR SO_REUSEPORT
解决的问题 TIME_WAIT 期间绑不上 多进程抢同一端口
两个进程同时 LISTEN 同一端口 不行 行
前提 bind() 之前设 bind() 之前设，且参与的所有 socket 都设
分发能力 没有，谁先绑谁拿到 有，内核对新连接做负载均衡
典型场景 服务端重启、同端口多 IP 多 worker 进程、不停机平滑重启
绑定组播地址时 与 SO_REUSEPORT 等效 与 SO_REUSEADDR 等效

SO_REUSEPORT 的语义，UNPv1 里的原话意思是：它允许完全重复的捆绑，但仅当所有想绑相同 IP 和端口的套接字都指定了这个选项才行。一个设一个不设，后者失败。另外，如果被绑的 IP 是一个组播地址，那两个选项等效。

Linux 上 SO_REUSEPORT 还有一条额外要求：参与复用的 socket 必须属于同一个 euid，不满足就 EACCES。这条写在 man 7 socket 里，不是各家实现都一致，跨平台时先查文档。

多 worker 的写法就是个模板：

c
/* reuseport.c —— 多个进程同时监听 10013 */
#include <sys/socket.h>
#include <netinet/in.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

int main(void)
{
    int listenfd, connfd, on = 1, i;
    struct sockaddr_in addr;

    for (i = 0; i < 4; i++) {
        if (fork() == 0) {
            if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) < 0) { perror("socket"); exit(1); }
            setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));
            if (setsockopt(listenfd, SOL_SOCKET, SO_REUSEPORT, &on, sizeof(on)) < 0) {
                perror("setsockopt SO_REUSEPORT");
                exit(1);
            }

            memset(&addr, 0, sizeof(addr));
            addr.sin_family = AF_INET;
            addr.sin_addr.s_addr = htonl(INADDR_ANY);
            addr.sin_port = htons(10013);
            if (bind(listenfd, (struct sockaddr *)&addr, sizeof(addr)) < 0) { perror("bind"); exit(1); }
            listen(listenfd, 128);

            for (;;) {
                connfd = accept(listenfd, NULL, NULL);
                if (connfd < 0) { perror("accept"); continue; }
                printf("pid %d 拿到一条连接\n", getpid());
                close(connfd);
            }
        }
    }

    for (i = 0; i < 4; i++) { wait(NULL); }
    return 0;
}

四个子进程都 bind 成功。内核按四元组哈希把新连接分下去，每个进程只处理分到自己手上的那几条。

几点实操经验：

  • 分发以连接为单位，不是以报文为单位。一条 TCP 连接一旦落到某个进程，后续数据都在那个进程里。UDP 上按四元组哈希，同一个客户端固定落到同一个 socket。
  • 分得不一定均匀，内核的哈希对短连接、端口集中在少数几个的客户端会偏。
  • 平滑重启是它最常见的用法：新版本进程先起来绑同一端口，老进程处理完存量连接再退。
  • 只有 SO_REUSEPORT 能让两个进程同时 LISTEN。只设 SO_REUSEADDR 就去起第二份，照样 EADDRINUSE。

UNPv1 给的两条使用建议，直接抄下来能用：

  1. 在所有 TCP 服务器中，bind 之前设置 SO_REUSEADDR。
  2. 编写一个同一时刻在同一主机上可运行多次的组播应用程序时，设置 SO_REUSEADDR，并把本组的组播地址作为本地 IP 来绑。

第二条的意思是：组播接收端要绑到组地址或 INADDR_ANY，同一台机器上跑多份接收程序时，多份都要设这个选项。

五、其他常用选项 #

先把常用的一批摆成表，后面挑几个展开。

选项 层 作用 默认 代价
SO_REUSEADDR SOL_SOCKET 允许 TIME_WAIT 期间重绑 关 收到迟到数据的概率上升
SO_REUSEPORT SOL_SOCKET 多进程同时监听同一端口 关 分发不均、调试变难
SO_BROADCAST SOL_SOCKET 允许发广播 关 子网内所有主机都收
SO_KEEPALIVE SOL_SOCKET 空闲连接探活 关 探测周期长，占少量带宽
SO_LINGER SOL_SOCKET 控制 close() 的行为 立即返回 设 0 会发 RST，丢未发数据
SO_RCVBUF SOL_SOCKET 接收缓冲大小 内核决定 太大会增加内存与延迟
SO_SNDBUF SOL_SOCKET 发送缓冲大小 内核决定 同上
TCP_NODELAY IPPROTO_TCP 关掉 Nagle 关（即 Nagle 开着） 小包变多

SO_BROADCAST #

不设它，往 255.255.255.255 发 sendto 会得到 EACCES，报 Permission denied。默认关掉是有意为之：防止程序一不留神把包撒满整个子网。开法就一行，on 取 1：setsockopt(fd, SOL_SOCKET, SO_BROADCAST, &on, sizeof(on));

SO_KEEPALIVE #

TCP 空闲一段时间后自动发探测，探不通就判定连接失效。它探的是「连接两端的内核还通不通」，探不出「对端应用是否还在正常干活」。

开了之后探测间隔、次数由内核参数控制，Linux 上可以用 TCP_KEEPIDLE（空闲多久开始探）、TCP_KEEPINTVL（探测间隔）、TCP_KEEPCNT（探几次算死）覆盖。具体默认值随内核版本和发行版变化，别背数字，用 sysctl 查。

c
int on = 1, idle = 60, intvl = 10, cnt = 3;

setsockopt(fd, SOL_SOCKET, SO_KEEPALIVE, &on, sizeof(on));
setsockopt(fd, IPPROTO_TCP, TCP_KEEPIDLE,  &idle,  sizeof(idle));
setsockopt(fd, IPPROTO_TCP, TCP_KEEPINTVL, &intvl, sizeof(intvl));
setsockopt(fd, IPPROTO_TCP, TCP_KEEPCNT,   &cnt,   sizeof(cnt));

应用层有心跳协议时，别指望它替代心跳：它的时间尺度是分钟级，心跳是秒级。

SO_LINGER #

控制 close() 那一刻干什么。结构体两个字段：

c
struct linger {
    int l_onoff;    /* 0 关闭，非 0 开启 */
    int l_linger;   /* 停留秒数 */
};
l_onoff l_linger close() 的行为
0 不看 默认行为，立即返回，内核在后台把数据发完
非 0 0 丢弃发送缓冲里的数据，直接发 RST
非 0 > 0 阻塞到数据发完或者超时，超时就丢弃

l_linger = 0 是「我要立刻断，别管对端收没收到」。用它主动发 RST 来快速清理连接是可以的，指望它把数据送干净不行——对端会看到连接被重置，缓冲里没发的数据全丢。设置就两行：struct linger lg = { 1, 3 }; 加 setsockopt(fd, SOL_SOCKET, SO_LINGER, &lg, sizeof(lg));

SO_RCVBUF 与 SO_SNDBUF #

调收发缓冲。UDP 突发流量丢包，先加 SO_RCVBUF；高带宽长肥管道上吞吐上不去，先看 SO_SNDBUF 和窗口。

c
int want = 4 * 1024 * 1024;
setsockopt(fd, SOL_SOCKET, SO_RCVBUF, &want, sizeof(want));

int got = 0;
socklen_t len = sizeof(got);
getsockopt(fd, SOL_SOCKET, SO_RCVBUF, &got, &len);
printf("want=%d got=%d\n", want, got);

前面说过，got 不等于 want 是常态。不读回来，你永远不知道内核给了多少。

超时相关的两个 #

SO_RCVTIMEO 和 SO_SNDTIMEO 也是 SOL_SOCKET 层的选项，同组另一篇《套接字的超时控制》把它们和 select / poll / alarm 几种等待手法放在一起讲，这里只留名字。

六、TCP_NODELAY 与 Nagle 算法 #

Nagle 算法管的是「小包什么时候发」。规则很短：如果还有已发出但没被确认的数据，小于 MSS 的小片数据先攒着，等确认回来或者攒够一个 MSS 再发。

目的很实在：一个字节一个字节地写，网络里就一串 40 字节头带 1 字节载荷的包，带宽浪费在头上。攒起来合并，链路效率高。

代价出现在请求-响应型协议上。你写一个小请求，对方等收到才回，你这边前一个包没确认、下一个包被 Nagle 扣着，两头一等，交互就慢一拍。对端再叠一个延迟确认（delayed ACK，收到数据先等一小会儿，指望搭上反向数据一起确认），一次往返就被拉长。

TCP_NODELAY 就是关掉 Nagle：每次 write 立刻发，不等。

c
int on = 1;
setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &on, sizeof(on));
场景 TCP_NODELAY 怎么设
RPC、数据库客户端、请求-响应型自定义协议 关掉 Nagle（设为 1）
交互式终端、游戏指令 关掉 Nagle
大文件、日志搬运、批量顺序写 保持默认，让 Nagle 合并
自己拼好整包再写 都可以，影响不大

Linux 上还有个 TCP_CORK，比 TCP_NODELAY 更狠：塞住就完全不发，直到取消塞住或者攒够 MSS。适合「先写协议头、再写正文」的拼包场景，写完正文再 uncork，避免头一个包、体一个包。

两个选项名字反着来：TCP_NODELAY 是「别等」，TCP_CORK 是「先别发」。别同时用。

七、广播：向 subnet 内所有主机发 #

广播只有一个收件人集合：本子网里的所有主机。

地址有两种写法。

  • 255.255.255.255：受限广播。只在本链路内生效，路由器不转发，也不需要配路由。
  • 子网广播（定向广播）：把主机位全置 1，比如 192.168.40.0/24 的广播地址是 192.168.40.255。

子网广播地址是算出来的，不是查出来的：

c
/* ip 与 mask 都取主机字节序，返回广播地址（主机字节序） */
unsigned int broadcast_of(unsigned int ip, unsigned int mask) { return ip | ~mask; }

192.168.40.23 配 255.255.255.0 代进去：0xC0A82817 | 0x000000FF 得 0xC0A828FF，就是 192.168.40.255。

广播只能走 UDP，TCP 没有广播这个概念。

发之前必须开 SO_BROADCAST，否则 sendto 返回 EACCES，报 Permission denied。

c
int fd, on = 1;
const char *msg = "hello-subnet";
struct sockaddr_in dst;

fd = socket(AF_INET, SOCK_DGRAM, 0);                          /* 广播只能走 UDP */
setsockopt(fd, SOL_SOCKET, SO_BROADCAST, &on, sizeof(on));    /* 不开就 EACCES */

memset(&dst, 0, sizeof(dst));
dst.sin_family = AF_INET;
dst.sin_port = htons(9999);
inet_pton(AF_INET, "192.168.40.255", &dst.sin_addr);          /* 换成你的子网广播地址 */

sendto(fd, msg, strlen(msg), 0, (struct sockaddr *)&dst, sizeof(dst));

接收端跟普通 UDP 一样，绑端口等 recvfrom：

c
struct sockaddr_in addr;

memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_addr.s_addr = htonl(INADDR_ANY);   /* 绑任意地址才能收到广播 */
addr.sin_port = htons(9999);
bind(fd, (struct sockaddr *)&addr, sizeof(addr));

广播的硬边界：

  • 只在同一子网内生效，路由器不转发。想跨网段，换组播。
  • 子网里每台主机都会收到这份包，哪怕它的进程根本没打算理你。规模越大噪声越大。
  • 接收端必须绑对端口，并且绑 INADDR_ANY。绑到一个具体单播地址上，广播包进不来。

网卡支不支持，ifconfig 那行标志里就写着：eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST> mtu 1500。带 BROADCAST 和 MULTICAST 才能干这两件事。

八、组播：向一组主机发 #

组播把收件人集合从「本子网所有主机」缩小到「加入了某个组的主机」，而且路由器可以帮忙转发。

地址在 224.0.0.0/4，也就是 224.0.0.0 到 239.255.255.255。这个范围的二进制开头四位固定是 1110，机器就靠这四位分辨单播、组播、保留地址。

几个要记住的段：

范围 用途
224.0.0.0/24 链路本地，TTL 必须是 1，路由器不转发（224.0.0.1 是本子网所有主机）
224.0.1.0 起 一些公开的协议用途，比如 mDNS 用 224.0.0.251
239.0.0.0/8 管理范围，可以当私网地址一样自己分配

组地址是「目的地址」，不是某台主机的地址。发的人不需要加入组，收的人才必须加入。这一点跟广播刚好相反——广播谁都能收，组播得先报名。

发送端的核心是三个选项：出口网卡、TTL、回环。目的地填组地址。

c
/* mcast_send.c —— 往组播组发一条 UDP */
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define GROUP "239.1.2.3"
#define PORT  9999

int main(void)
{
    int fd, ttl = 4;
    struct in_addr ifaddr;
    struct sockaddr_in dst;

    if ((fd = socket(AF_INET, SOCK_DGRAM, 0)) < 0) { perror("socket"); exit(1); }

    /* 出口网卡：多网卡机器上必须指，填本机某块网卡的 IPv4 地址 */
    inet_pton(AF_INET, "192.168.40.23", &ifaddr);
    if (setsockopt(fd, IPPROTO_IP, IP_MULTICAST_IF, &ifaddr, sizeof(ifaddr)) < 0) {
        perror("setsockopt IP_MULTICAST_IF"); exit(1);
    }
    if (setsockopt(fd, IPPROTO_IP, IP_MULTICAST_TTL, &ttl, sizeof(ttl)) < 0) {
        perror("setsockopt IP_MULTICAST_TTL"); exit(1);
    }

    memset(&dst, 0, sizeof(dst));
    dst.sin_family = AF_INET;
    dst.sin_port = htons(PORT);
    /* 用 inet_pton 直接填结构体，别用整数转 */
    if (inet_pton(AF_INET, GROUP, &dst.sin_addr) <= 0) { fprintf(stderr, "bad group\n"); exit(1); }

    if (sendto(fd, "hello-group", 11, 0, (struct sockaddr *)&dst, sizeof(dst)) < 0) {
        perror("sendto"); exit(1);
    }
    close(fd);
    return 0;
}

素材里记的几条实战坑，全是真踩出来的：

坑一：sendto 报 network is unreachable。 发组播包的机器要有网关。网卡的 IP 可以随便设，但一定要设。还要有到 224.0.0.0/4 的路由：

text
# route add -net 224.0.0.0 netmask 240.0.0.0 dev eth0
# route add default gw 192.168.40.1 dev eth0

224.0.0.0 配掩码 240.0.0.0 就是 224.0.0.0/4，一条路由覆盖整个组播段。内核发组播跟发单播一样要查路由表，查不到就报不可达。

坑二：setsockopt: No such device。 这条报错跟网卡无关，问题在组播 IP 本身：送进内核的那个 32 位网络地址开头不是 1110，内核的合法性检查通不过，找不到对应的组播设备，就回一个 ENODEV。

原因九成是字节序。把 "239.1.2.3" 当整数直接赋给 sin_addr.s_addr，得到的是主机字节序的数字，内核按网络字节序解释，前四位自然对不上。两种正确写法：

c
struct sockaddr_in srv;

/* 写法一：inet_aton 直接填结构体（推荐） */
inet_aton("239.1.2.3", &srv.sin_addr);

/* 写法二：inet_network 返回主机字节序的数值，再 htonl 转网络序 */
srv.sin_addr.s_addr = htonl(inet_network("239.1.2.3"));

inet_pton 与 inet_aton 一样直接写进 struct in_addr，是当下更常用的一对。凡是「地址字符串 → 结构体」，让它自己转，别手工拼整数。

九、加入与退出组播组 #

接收端多一步：向内核报名，说自己要这个组的数据。

结构体是 struct ip_mreq，两个字段：imr_multiaddr 是组地址，imr_interface 是本地网卡地址（填 INADDR_ANY 表示让内核挑）。

加入用 IP_ADD_MEMBERSHIP，退出用 IP_DROP_MEMBERSHIP，层都是 IPPROTO_IP。

c
/* mcast_recv.c —— 加入组播组、收包、退出 */
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define GROUP "239.1.2.3"
#define PORT  9999

/* join 非 0 时加入，为 0 时退出 */
static int set_membership(int fd, const char *group, const char *ifip, int join)
{
    struct ip_mreq mreq;

    memset(&mreq, 0, sizeof(mreq));
    if (inet_pton(AF_INET, group, &mreq.imr_multiaddr) <= 0) { fprintf(stderr, "bad group\n"); return -1; }
    if (ifip == NULL) {
        mreq.imr_interface.s_addr = htonl(INADDR_ANY);
    } else if (inet_pton(AF_INET, ifip, &mreq.imr_interface) <= 0) {
        fprintf(stderr, "bad interface\n"); return -1;
    }
    if (setsockopt(fd, IPPROTO_IP, join ? IP_ADD_MEMBERSHIP : IP_DROP_MEMBERSHIP,
                   &mreq, sizeof(mreq)) < 0) {
        perror(join ? "IP_ADD_MEMBERSHIP" : "IP_DROP_MEMBERSHIP");
        return -1;
    }
    return 0;
}

int main(void)
{
    int fd, on = 1;
    struct sockaddr_in addr;
    char buf[1500];

    if ((fd = socket(AF_INET, SOCK_DGRAM, 0)) < 0) { perror("socket"); exit(1); }

    /* 同一主机跑多份接收程序时，这个选项必须有 */
    setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));

    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY);
    addr.sin_port = htons(PORT);
    if (bind(fd, (struct sockaddr *)&addr, sizeof(addr)) < 0) { perror("bind"); exit(1); }

    if (set_membership(fd, GROUP, NULL, 1) < 0) { exit(1); }
    printf("joined %s:%d\n", GROUP, PORT);

    for (;;) {
        ssize_t n = recvfrom(fd, buf, sizeof(buf), 0, NULL, NULL);
        if (n < 0) { perror("recvfrom"); break; }
        printf("got %zd bytes\n", n);
    }

    set_membership(fd, GROUP, NULL, 0);
    close(fd);
    return 0;
}

几个要点：

  • 加入和 bind 的先后没有硬性要求，先 bind 端口再 join 更清晰。绑 INADDR_ANY 或绑组地址本身都能收到 IPv4 组播。
  • imr_interface 填 INADDR_ANY 让内核挑网卡；多网卡机器上建议显式填某块网卡的 IPv4 地址，否则会从错的那块加入。填错网卡地址会得到 setsockopt: No such device，跟第八章的坑二是同一个报错、不同成因。
  • 成员关系是按 socket 记的。同一个进程开两个 socket 加入同一个组，退出时两个都要退。
  • 不显式 IP_DROP_MEMBERSHIP，close() 时内核也会自动退。差别在于长驻进程频繁开关 socket 时，显式退出更好查。
  • 同一台机器上多个进程收同一组的同一端口，每个进程都要设 SO_REUSEADDR，并把组地址作为本地 IP 绑——这就是第四章 UNPv1 第二条建议的用处。

十、组播的 TTL 与回环 #

两个选项决定「这个包能走多远」和「自己会不会收到自己的包」。

IP_MULTICAST_TTL 是组播的跳数上限：

值 含义
0 只在本机，不出网卡
1 只在本子网，出不了路由器（组播的默认值）
n > 1 允许经过 n-1 台路由器

默认是 1，意味着「开箱就在本地链路」。要跨网段，必须显式调大，而且中间路由器得支持组播路由（IGMP / PIM），否则包到边界就没了。

IP_MULTICAST_LOOP 控制本机回环：开着的时候，你发出去的组播包会回送给本机那些加入了这个组的 socket。单机收发的调试全靠它——一台机器既当发送端又当接收端，不用第二台机器就能验证代码。关掉之后，本机只看得到别的机器发来的包。

c
int ttl = 4;
unsigned char loop = 0;      /* 0 关，1 开 */
setsockopt(fd, IPPROTO_IP, IP_MULTICAST_TTL, &ttl, sizeof(ttl));
setsockopt(fd, IPPROTO_IP, IP_MULTICAST_LOOP, &loop, sizeof(loop));

类型上有个小坑：TTL 这一项有的实现按 unsigned char 收，有的按 int 收。按 int 传更省心，内核会取低字节。传 int 却只拷过去一个字节的，是这类代码里最常见的错位来源。

IPv6 一套对应关系：IPV6_MULTICAST_HOPS、IPV6_MULTICAST_LOOP、IPV6_MULTICAST_IF，加入组用 IPV6_JOIN_GROUP 配 struct ipv6_mreq。名字换了，语义一样。

十一、广播与组播的取舍 #

对比项 广播 组播
地址 255.255.255.255 或子网广播 224.0.0.0/4 里的一个组地址
谁能收到 同子网内的所有主机 只有加入了这个组的主机
跨子网 不行，路由器不转发 可以，前提是路由器支持 IGMP / PIM
发送端准备 开 SO_BROADCAST 选出口网卡、设 TTL
接收端准备 绑端口就行 绑端口，再 IP_ADD_MEMBERSHIP
对无关主机的打扰 全子网都被打扰 没有，不加入就收不到
规模上限 一个子网 一个组，可以跨网段
代码复杂度 低 中

结论很硬：主机多了用组播，同一个网段内两个主机用广播。

判断的切口是收件人数量和对无关主机的打扰。两台机器在同一交换机下互发通知，广播三行代码就完事，加组、设 TTL 全是多余动作。几十台、上百台设备要收同一份数据，广播会把每台机器都惊动一遍，跨网段还过不去，这时候只能上组播。

组播多出来的成本也要认：

  • 组地址要人肉规划。224.0.0.0/24 留给协议，自己用 239.0.0.0/8，当私网地址一样分，别撞车。
  • 跨网段要网络侧配合。交换机、路由器不认 IGMP，包就出不了本链路，代码改到天亮也没用。
  • 组播地址是「目的地」不是「主机」，抓包时看到目的 MAC 是 01:00:5e 开头别以为是攻击，那是 IPv4 组播映射到以太网的固定前缀。

十二、易错点速查 #

现象 原因 处理
bind: Address already in use，服务刚停 上一轮主动关闭，端口在 TIME_WAIT bind 前设 SO_REUSEADDR
设了 SO_REUSEADDR 还是 EADDRINUSE 端口被另一个 LISTEN / ESTABLISHED 的 socket 真占着 那不是 TIME_WAIT，选项管不了，去查占用进程
两个进程都想 LISTEN 同一端口 用了 SO_REUSEADDR 改用 SO_REUSEPORT，且两边都设
设了 SO_REUSEPORT 还是失败 只有一边设了，或 euid 不同 参与复用的 socket 全部设，且同 euid
子进程退出后端口仍不释放 fork 后子进程没关 listenfd 子进程里 close(listenfd)
sendto 报 Permission denied 没开 SO_BROADCAST 发广播前设上
sendto 报 Network is unreachable 没有到 224.0.0.0/4 的路由或网关 加组播路由，配默认网关
setsockopt 报 No such device 组地址字节序错，首位不是 1110；或 imr_interface 填错网卡 用 inet_pton / inet_aton 填结构体；核对网卡地址
本机收不到自己发的组播 IP_MULTICAST_LOOP 被关了 打开回环，或换台机器收
跨网段收不到组播 TTL 是默认的 1 调大 IP_MULTICAST_TTL，并让路由器支持 IGMP
改了 SO_RCVBUF 没变化 内核按上下限裁剪 getsockopt 回读真实值
选项设了没反应 设晚了，或 level 配错 地址类选项在 bind 前设；核对 IPPROTO_TCP / SOL_SOCKET

回头看，这一串报错里只有一个是协议本身要求的，其余全是选项没配对或者字节序没转对。套接字选项这层薄薄的开头，坑基本都在「什么时候设」和「值是什么类型」这两件事上。把这两件事记住，广播和组播剩下的就是算地址、加组、调 TTL 的体力活。
