一句话定位：后面所有套接字代码，都要先落在这篇的地址结构和字节序上。

一、套接字是什么 #

套接字是进程间通信的一种机制，也是其中唯一能把通信范围从「一台机器」推到「两台机器」的那一种。管道、消息队列、共享内存都被限制在同一台计算机系统内部做资源共享；套接字没有这个限制，一台机器上的进程可以和另一台机器上的进程交换数据。同一台主机上的两个进程用它通信，同样可以。

套接字采用 C/S 模型，也就是 Client/Server，客户端—服务器模型。

在动地址结构之前，先把两个描述方式立起来，后面填结构体时要用到：

  • 半相关描述：{协议，本地地址，本地端口}
  • 相关描述：{协议，本地地址，本地端口，远程地址，远程端口}

一个套接字是通信线路的一个端点。半相关能确定「我是谁」，相关能确定「我和谁」。两个进程用套接字通信，各自先建好自己的端点，创建套接字时就分配端口号和网络地址。进程 A 要给进程 B 发数据，A 必须知道 B 的网络地址和端口号，没有别的路可走。

服务器这一侧做了什么 #

服务器先调用 socket() 创建一个套接字。它是系统分配给该服务器进程的、类似文件标识符的资源，不和别的进程共享（同一个进程里换个线程去用它，也是同一个东西，不存在线程独占）。

接下来服务器给套接字起名字。本地套接字的名字是 Linux 文件系统里的一个文件名；网络套接字的名字是与客户连接相关的服务标识符，也就是端口号或访问点。这个标识符让内核能把进入某个端口号的连接转交给正确的服务器进程。Web 服务器在 80 端口上建套接字，浏览器也知道访问 Web 节点要用 80 端口建 HTTP 连接。

bind 给套接字命名（关联到本地某个地址或文件），命名之后服务器进程开始等客户来连。listen 创建一个队列，用来存放来自客户的请求连接。accept 从队列里取走一个连接，此时它创建一个与命名套接字不同的新套接字，这个新套接字只服务这一个客户，命名套接字保留下来继续接别的客户。

这一点很容易记混：监听套接字不传数据，传数据的是 accept 返回的那个。

客户端这一侧做了什么 #

客户端更简单。先 socket() 建一个未命名套接字，然后把服务器的命名套接字当作一个地址，调 connect 建连接。连接一建立，就可以像用底层文件描述符那样，用套接字做双向数据通信。

text
服务器：socket() → bind() → listen() → accept() → read()/write() → close()
客户端：socket() → connect() → write()/read() → close()

确定套接字的三个属性 #

套接字的特性由三个属性定死：域（domain）、类型（type）、协议（protocol）。

属性 参数名 作用 常见取值
域 domain 指定通信使用的网络介质，即协议族 AF_INET、AF_UNIX
类型 type 指定通信方式 SOCK_STREAM、SOCK_DGRAM
协议 protocol 指定具体协议，填 0 表示用默认 0

域决定「在哪张网上说话」。AF_INET 指 Internet 网络，绝大多数 Linux 局域网用的都是它。AF_UNIX 是 UNIX 文件系统域，一台还没联网的计算机上的套接字也能用这个域，它的底层协议就是文件输入/输出，地址就是文件名——程序跑起来时，当前目录下就能看到那个地址文件。

端口那一层要单独说：服务器计算机上会同时跑多个服务，客户通过 IP 加端口指定某个服务。系统内部，端口用一个唯一的 16 位整数标识；系统外部，靠 IP 地址和端口号的组合确定。套接字作为通信终点，开始通信之前必须绑定一个端口。知名服务有固定端口，ftp 是 21，httpd 是 80。小于 1024 的端口是系统服务保留区，选端口别往那里面撞。

二、套接字描述符与文件描述符 #

这一节是整篇的地基，讲透了，后面全是细节。

在 Linux 里，套接字就是一个文件描述符。 socket() 返回一个 int，这个 int 是进程文件描述符表的下标，和 open() 返回的东西是同一类对象。所以 read、write、close、fcntl、dup2 这些调用，套接字全部照收。

这不是巧合，是设计。UNIX 的哲学是「一切皆文件」，套接字被做成了 VFS 里的一个 inode，只不过它背后挂的不是磁盘，是网络协议栈。你的代码里对一个网络连接做 read，和从 /etc/hosts 做 read，走的系统调用入口是同一个，中间才分叉。

c
/* accept 之后拿到的 conn，和普通文件描述符的用法完全一致 */
char buf[1024];
ssize_t n = read(conn, buf, sizeof(buf));
if (n > 0) {
    write(conn, buf, n);   /* 原样 echo 回去 */
} else if (n == 0) {
    close(conn);           /* 对端关闭，read 返回 0 */
}

read 返回 0 表示对端已经关了连接，这是文件语义的「读到文件末尾」，在网络里就是「对面不说了」。这是判断断连最标准的手法，别去猜 errno。

描述符表里都有什么 #

进程的 fd 表就是一个小整数数组，0 是标准输入，1 是标准输出，2 是标准错误。socket() 返回的会是最小的空闲槽位，所以一个刚起来的服务端进程，监听 fd 经常就是 3。

同一类 fd 你都能拿来做这些事：

操作 文件 套接字 说明
read / write 支持 支持 套接字未连接时 write 返回 ENOTCONN
close 支持 支持 关掉 fd，释放引用
fcntl 支持 支持 改 O_NONBLOCK、O_ASYNC
dup / dup2 支持 支持 dup2(sock, 1) 就把 stdout 接到网络
select / poll / epoll 支持 支持 进 fd_set 的就是这类整数
lseek 支持 不支持 网络流没有「位置」这个概念

最后一行是两者唯一显眼的分界：套接字不可寻址，lseek 会返回 ESPIPE。除此之外的差异都在语义层（有没有连接、会不会丢包），不在接口层。

select 那套 FD_ZERO / FD_SET / FD_ISSET 宏能直接吃套接字，原因也在这里——它们吃的是整数 fd，不关心这个整数背后是磁盘还是网卡。

非阻塞也是文件描述符那套 #

accept 在队列空的时候会阻塞到有客户连进来。想改这个行为，不用找套接字专用的开关，还是 fcntl：

c
int flags = fcntl(sock, F_GETFL, 0);
fcntl(sock, F_SETFL, O_NONBLOCK | flags);

这段代码对一个串口 fd 同样成立。只要你在写网络程序时反复意识到「手上是个 fd」，很多 API 就不用背了，去查文件 IO 的手册页即可。

关闭的时候也一样，close(fd) 就完事。要记得连接两端都关；服务器判断到 read 返回 0 之后再关，比较干净。有个例外：面向连接的套接字如果开了 SO_LINGER 选项，close 在还有未发完的数据时会阻塞，那属于套接字选项的范畴，见《套接字选项》组。

三、地址结构：sockaddr 与 sockaddr_in #

每个套接字域都有自己的地址格式。bind、connect、accept 这些函数要能处理任意域的地址，又不能为每个域写一个原型，于是搞了一个通用壳子 sockaddr，具体域的地址结构塞进壳子里，用指针强转传进去。

c
/* 通用地址结构，定义在 <sys/socket.h> */
struct sockaddr {
    sa_family_t sa_family;   /* 地址族，AF_xxx */
    char        sa_data[14]; /* 14 字节，装具体地址 */
};

/* Internet 域地址结构，定义在 <netinet/in.h> */
struct sockaddr_in {
    sa_family_t    sin_family; /* 地址族，AF_INET */
    in_port_t      sin_port;   /* 端口号，网络字节序 */
    struct in_addr sin_addr;   /* IP 地址，网络字节序 */
    unsigned char  sin_zero[8];/* 填充，全 0 */
};

struct in_addr {
    in_addr_t s_addr;          /* 32 位无符号整数，网络字节序 */
};

sa_data 是 14 字节，sin_port（2 字节）+ sin_addr（4 字节）+ sin_zero（8 字节）正好 14 字节。这就是 sockaddr_in 和 sockaddr 能互相强转而不出错的原因：两者尺寸相同，前两个字节都是地址族。sin_zero 存在的唯一目的就是把结构体撑到一样大，填的时候清零，别拿它存业务数据。

四个字段逐个说 #

字段 类型 长度 填什么 字节序
sin_family sa_family_t 2 字节 AF_INET 主机序，无需转换
sin_port in_port_t（uint16_t） 2 字节 端口号，如 8080 必须是网络字节序
sin_addr struct in_addr 4 字节 IPv4 地址 必须是网络字节序
sin_zero unsigned char[8] 8 字节 全 0，填充 无意义

sin_family 是唯一不用转字节序的字段。它只有 2 字节，但内核按本地整数读它，两边在同一台机器上，不存在跨机器解释的问题。

sin_port 和 sin_addr.s_addr 会被原样塞进 IP 报文头跟着包上网络，对面是任意 CPU，所以必须是网络字节序。这里漏一个 htons，端口就会变成一个完全不同的数——第五章、第六章把这件事算给你看。

一份能用的初始化代码 #

c
#include <string.h>
#include <arpa/inet.h>
#include <netinet/in.h>
#include <sys/socket.h>

struct sockaddr_in addr;

memset(&addr, 0, sizeof(addr));          /* 先把 sin_zero 清零 */
addr.sin_family = AF_INET;               /* 地址族，主机序 */
addr.sin_port   = htons(8080);           /* 端口，转成网络字节序 */
addr.sin_addr.s_addr = htonl(INADDR_ANY);/* 监听本机所有网卡 */

INADDR_ANY 的值是 0，htonl(0) 还是 0，写 0 也行，但写 htonl(INADDR_ANY) 能表明你知道自己在干什么。反过来，如果只想绑回环地址，用 inet_addr("127.0.0.1") 或 htonl(INADDR_LOOPBACK)，注意 inet_addr 的返回值已经是网络序，别在外面再套一层 htonl。

memset 那行不能省。栈上的结构体是脏的，sin_zero 里残留任何东西，某些实现会拿去比较结构体是否相等，或者在内核拷贝时留下垃圾。

AF_UNIX 域用的结构体 #

c
/* 定义在 <sys/un.h> */
struct sockaddr_un {
    sa_family_t sun_family;  /* AF_UNIX */
    char        sun_path[108]; /* 文件系统路径名 */
};

本地域的地址就是一个路径字符串，没有端口，没有字节序问题。这也是为什么本地套接字调试起来省心：出问题直接 ls -l 看那个 socket 文件在不在。用相对路径时它会建在服务器的工作目录下，所以两边都认得的绝对路径（比如 /tmp/xxx.sock）更省事。

传参时一律用通用指针 #

c
int bind(int sockfd, const struct sockaddr *address, socklen_t address_len);

你手里的是 struct sockaddr_in，传参时强转成 struct sockaddr *：

c
bind(listenfd, (struct sockaddr *)&addr, sizeof(addr));

第三个数传 sizeof(struct sockaddr_in)，不要传 sizeof(struct sockaddr)。两者数值上都是 16，传错了也能跑，但换个域（比如 sockaddr_un 更长）就崩了，养成传「实际结构体大小」的习惯。socklen_t 是老 API 里 int 和 size_t 打架留下的产物，别纠结，照写。

accept 的第三个数是指针，因为它是输入输出参数：进去时告诉内核缓冲区多大，出来时内核告诉你实际写了多少。connect 和 bind 是纯输入，所以传值。

四、地址转换：inet_aton 与 inet_ntoa #

人写地址写成 132.241.5.10，机器要的是 32 位整数。中间这座桥就是地址转换函数。

早期那套 API 有三个：inet_addr、inet_aton、inet_ntoa。它们是 IPv4 专用的，头文件在 <arpa/inet.h>（Windows 那边是 <winsock.h>）。

c
#include <arpa/inet.h>

in_addr_t inet_addr(const char *cp);                    /* 字符串 → 网络序整数 */
int       inet_aton(const char *cp, struct in_addr *inp);/* 字符串 → in_addr */
char     *inet_ntoa(struct in_addr in);                 /* in_addr → 字符串 */

inet_addr 与 inet_aton #

inet_addr 把点分十进制字符串转成一个无符号长整型，返回值已经是网络字节序，所以填进 sin_addr.s_addr 时不要再套 htonl。

c
ser_sock.sin_addr.s_addr = inet_addr("132.241.5.10");

这段代码缺错误检查。inet_addr 出错返回 -1，而 -1 转成无符号正好是 255.255.255.255，也就是广播地址。两个含义撞在同一个值上，写代码的人一分心就把广播地址当错误码用，或者反过来把错误当广播地址发出去。要么补检查，要么换 inet_aton。

c
if (inet_aton("132.241.5.10", &ser_sock.sin_addr) == 0) {
    fprintf(stderr, "非法地址\n");
    return -1;
}

inet_aton 用出参回填，成功返回非 0，失败返回 0，两者不会混淆。它比 inet_addr 晚出生，行为更规矩。

inet_ntoa 的静态缓冲区 #

inet_ntoa 把 in_addr 转回点分字符串，参数是结构体本身不是长整型。它返回一个 char *，指向函数内部的一块静态缓冲区——每次调用都会覆盖上一次的结果。

c
#include <stdio.h>
#include <string.h>
#include <arpa/inet.h>

int main(void)
{
    struct in_addr addr1, addr2;
    unsigned long l1, l2;

    l1 = inet_addr("192.168.0.74");
    l2 = inet_addr("211.100.21.179");
    memcpy(&addr1, &l1, 4);        /* inet_addr 的返回值已经是网络序，直接拷 */
    memcpy(&addr2, &l2, 4);

    /* 两个 %s 都指向同一块静态内存 */
    printf("%s : %s\n", inet_ntoa(addr1), inet_ntoa(addr2));

    printf("%s\n", inet_ntoa(addr1));
    printf("%s\n", inet_ntoa(addr2));
    return 0;
}

跑出来的结果是这样的：

text
192.168.0.74 : 192.168.0.74
192.168.0.74
211.100.21.179

第一行的两个地址变成了同一个。原因不是求值顺序玄学，而是 printf 拿到的是两个指向同一块内存的指针，格式化输出时那块内存里只剩最后写进去的 192.168.0.74。可变参数从右往左求值，addr2 先求，addr1 后求，把前面的结果盖掉了。

要保住地址就自己拷一份：

c
char buf[INET_ADDRSTRLEN];
strcpy(buf, inet_ntoa(addr1));

换成 inet_pton 与 inet_ntop #

新代码用这两个，能同时支持 IPv4 和 IPv6，而且目标缓冲区由你提供，不存在静态内存被覆盖的问题。

c
int inet_pton(int af, const char *src, void *dst);        /* 成功 1，格式错 0，失败 -1 */
const char *inet_ntop(int af, const void *src, char *dst, socklen_t size);

c
struct in_addr a;
inet_pton(AF_INET, "132.241.5.10", &a);   /* 填进去的已经是网络序 */

char out[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &a, out, sizeof(out));

inet_pton 的 p 是 presentation（字符串），n 是 numeric（二进制）。名字里就写着方向，比 aton / ntoa 好记。

主机名和服务名那条路 #

地址和端口硬编码在程序里，代码就只能连那一台机器。想通一点，让程序自己去查：

c
#include <netdb.h>

struct hostent *gethostbyname(const char *name);
struct hostent *gethostbyaddr(const void *addr, socklen_t len, int type);

hostent 里的字段够用了：

字段 含义
h_name 主机的官方名字
h_aliases 别名列表
h_addrtype 地址类型，AF_INET
h_length 单个地址的字节数，IPv4 是 4
h_addr_list 地址列表，每个元素是网络序的二进制地址

这些函数查的是 /etc/hosts 和 DNS（早年还有 NIS，Network Information Service，旧称黄页服务）。查不到就返回空指针。h_addr_list 里放的是二进制地址，直接 printf("%s") 打出来是乱码，得先 inet_ntoa 或 inet_ntop 转成字符串。

服务名那条路对应 getservbyname 和 getservbyport，查的是 /etc/services：

c
struct servent *getservbyname(const char *name, const char *proto);
struct servent *getservbyport(int port, const char *proto);

proto 填 "tcp" 或 "udp"，分别对应 SOCK_STREAM 和 SOCK_DGRAM。返回的 servent 里，s_name 是服务名，s_port 是端口号——这个值已经是网络字节序，直接赋给 sin_port 就行。这一点坑了不少人：查出来的端口自己又 htons 一遍，端口就飞了。

再补一个 gethostname，拿本机名字：

c
int gethostname(char *name, size_t length);

名字写进 name 并以 \0 结尾，太长会被截断。成功返回 0，失败返回 -1 并设 errno。

把这几件事串起来，一个「连到标准服务」的程序骨架就是：gethostbyname 拿 IP，getservbyname 拿端口，填进 sockaddr_in，connect 过去。整个过程里地址和端口没有一个字是硬编码的。

gethostbyname 和 inet_ntoa 一样返回静态内存，不可重入，多线程里要么加锁要么换成 getaddrinfo。

五、字节序：大端与小端 #

多字节整数在内存里怎么摆，CPU 厂商各有各的选择，于是分成两派。

  • 小端法（Little-Endian）：低位字节放在低地址端，也就是该值的起始地址；高位字节放在高地址端。
  • 大端法（Big-Endian）：高位字节放在低地址端；低位字节放在高地址端。

拿 0x12345678 举例，78 是低位字节，12 是高位字节。假设变量起始地址是 0x1000：

地址 小端法 大端法
0x1000 78 12
0x1001 56 34
0x1002 34 56
0x1003 12 78

一句话记法：小端是「尾巴在前」，最低位字节最靠前（地址最小）；大端是「脑袋在前」，最高位字节最靠前。

自己测一下 #

不看文档，直接让程序告诉你：

c
#include <stdio.h>

int main(void)
{
    unsigned int x = 0x12345678;
    unsigned char *p = (unsigned char *)&x;

    if (*p == 0x78)
        printf("小端\n");
    else if (*p == 0x12)
        printf("大端\n");
    else
        printf("两个都不是\n");

    return 0;
}

原理是利用 char * 逐字节访问：p 指向变量起始地址，也就是最低地址。取出来的第一个字节是 0x78 就是小端，是 0x12 就是大端。

用 union 更短：

c
union {
    unsigned int  i;
    unsigned char c[4];
} u;

u.i = 0x12345678;
printf("%s\n", u.c[0] == 0x78 ? "小端" : "大端");

哪些 CPU 是哪一派 #

平台 字节序
x86 / x86_64（Intel、AMD） 小端
ARM 可配置，多数实现跑小端
MIPS 双端，看具体型号
PowerPC 大端（部分可切换）
SPARC 大端
Motorola 6800 系列 大端

字节序只在多字节类型（short、int、long、float）上有分歧。char 数组、字符串没有分歧——"GET" 就是三个字节按顺序摆。这就是为什么纯文本协议在跨平台时看着毫无问题，一旦开始填端口号、填长度字段，立刻就出岔子。

六、网络字节序与主机字节序 #

主机字节序就是本机 CPU 的顺序，也叫本地字节序。网络字节序是 TCP/IP 规定好的一种数据表示格式，与具体的 CPU 类型、操作系统无关，目的是让数据在不同主机之间传输时能被正确解释。网络字节序采用大端排序。

为什么非要统一，看一个真实现象就懂了。

在本机跑起来一个服务器和客户端，用 netstat 看连接：

text
$ netstat -A inet
Active Internet connections (w/o servers)
Proto Recv-Q Send-Q Local Address        Foreign Address      State
tcp        0      0 localhost:9741       localhost:51246      TIME_WAIT

Local Address 是服务器自己的地址和端口，Foreign Address 是远程客户的地址和端口。

程序里明明写的是 addr.sin_port = 3366;，netstat 里却显示 9741。差在哪？

把两个数换成十六进制，谜底就出来了：

text
3366 = 0x0D26
9741 = 0x260D

低字节 0x26 和高字节 0x0D 换了个位置。x86 是小端机，0x0D26 存进内存时是 26 0D——低字节在前。内核和网络那边按大端读这两个字节，读成 0x260D，也就是 9741。

一个数字，在内存里被按另一种顺序解释，就变成了另一个数字。端口 3366 变成 9741 还算温和，落在别的值上直接就是个不可用的端口。

补救就是转换。程序在填充结构体之前，把主机序转成网络序：

c
addr.sin_port = htons(3366);   /* 转完再填 */

转完之后再看，netstat 显示的就是正常的 3366：

text
tcp        0      0 localhost:3366       localhost:34411      TIME_WAIT

哪些地方必须转 #

凡是会被原样发到网络上、由对端解释的多字节字段，都要转。落到套接字编程这一层，就是两处：

位置 字段 宽度 处理
sockaddr_in sin_port 16 位 htons 进去，ntohs 出来
sockaddr_in sin_addr.s_addr 32 位 用 inet_addr/inet_pton 填，返回值已是网络序

再往下的 IP 头、TCP/UDP 头里的源端口、目的端口、长度、校验和，也全是网络序，那是协议栈干的活，你写应用层代码时不用管。

sin_family 不用转。它只在本地内核和你的进程之间传递，不上网络。

最后一句判断标准：这个字段会不会被别人机器读到？ 会，就转。不会，就算了。

七、字节序转换函数 #

四个函数，两个方向，两个宽度，凑成一张表。名字就是含义，拆开看：h 是 host，n 是 network，s 是 short（16 位），l 是 long（32 位）。

函数 方向 宽度 典型用途
htons 主机 → 网络 16 位 填 sin_port
htonl 主机 → 网络 32 位 填 sin_addr.s_addr、IP 头字段
ntohs 网络 → 主机 16 位 读 sin_port、读对端端口
ntohl 网络 → 主机 32 位 读 sin_addr.s_addr

原型在 <arpa/inet.h>（Windows 下是 <winsock.h>，带 PASCAL FAR 调用约定修饰）：

c
#include <arpa/inet.h>

uint32_t htonl(uint32_t hostlong);   /* host to network long  */
uint16_t htons(uint16_t hostshort);  /* host to network short */
uint32_t ntohl(uint32_t netlong);    /* network to host long  */
uint16_t ntohs(uint16_t netshort);   /* network to host short */

long 在这里指 32 位，不是 long int 的长度。写代码时用 uint32_t / uint16_t 更稳，老代码里那套 unsigned long int 在 64 位机器上会让人多看一眼。

它就是高低位互换 #

小端机上调 htons(0x1234)，结果字节变成 34 12，读回来就是 0x3412。所以有人把 htons 总结成「把数的高低字节换个个儿」：

text
0x1234  --htons-->  0x3412

这个说法在小端机上完全成立，在大端机上不成立——大端机上调 htons 什么都不发生，因为主机序本来就是网络序。所以别把「互换」当定义，只当小端机上的现象。

转还是不转，编译器不管 #

这几个函数在字节序相同的机器上，实现就是直接 return，空操作，编出来一条指令都不多。这意味着：

  • 用错了不会崩，只会静默地错。
  • 不能靠「反正 x86 上转了也没事」蒙过去，换台大端机代码就是错的。
  • 也不能因为「反正两头都是 x86」就不写，早晚有一天对面不是 x86。

所以规矩是硬性的：填充 sockaddr_in 时该转就转，一条不落。 转换函数不是优化手段，是协议约定的一部分。

一份转全了的填充代码 #

c
#include <string.h>
#include <arpa/inet.h>
#include <netinet/in.h>

struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));

addr.sin_family = AF_INET;                    /* 不上网络，不转 */
addr.sin_port   = htons(8080);                /* 16 位，htons */
addr.sin_addr.s_addr = inet_addr("10.0.0.7"); /* 返回已是网络序，不再转 */

三个字段，三种处理，一眼看出谁该转。把这段背下来，比背手册有用。

打印的时候方向反过来，用 ntohs：

c
printf("对端端口 %u\n", ntohs(peer.sin_port));

忘了 ntohs 打出来的就是那个 9741。

常见的四个错 #

写法 问题 后果
addr.sin_port = 8080; 漏了 htons 端口变成 0x901F=36895 那类值，连不上
addr.sin_port = htons(htons(8080)); 转了两次 小端机上又转回主机序，同样连不上
addr.sin_addr.s_addr = htonl(inet_addr("10.0.0.7")); inet_addr 返回值已是网络序，又套一层 IP 变成完全不同的地址
addr.sin_family = htons(AF_INET); 对 2 字节的本地字段做转换 多数机器上无害，逻辑上错

第一、二、三条都会让程序「跑得起来但连不上」，报错还是 Connection refused 或者 Cannot assign requested address，排查起来全靠 ss -tnl 看内核里到底绑成了什么端口。这就是字节序坑最阴的地方：它不报错，它改数据。

八、套接字的类型 #

域决定在哪张网上说话，类型决定用什么方式说话。AF_INET 域下主要的类型就三种。

类型 协议 连接 可靠性 边界 适用
SOCK_STREAM TCP 面向连接 可靠、有序 字节流，无边界 HTTP、SSH、数据库连接
SOCK_DGRAM UDP 无连接 不可靠、无序 保留报文边界 DNS、日志上报、音视频
SOCK_RAW 自定 无 取决于上层 保留报文边界 ping、抓包、自定义协议
SOCK_SEQPACKET — 面向连接 可靠、有序 保留报文边界 AF_UNIX 下偶尔用，AF_INET 不支持

流套接字 SOCK_STREAM #

流套接字提供有序、可靠、双向的字节流连接。数据按什么顺序发，就按什么顺序收：发 A-B-C，收到的也是 A-B-C。

可靠性来自 TCP。IP 协议只管把数据包从一台机器路由到另一台机器，丢了不管、乱了不管。TCP 补上排序、流控和重传，保证大批数据完整到达，或者明确报一个错误出来。大消息会被切片、传输、再重组，这一层对应用完全透明。

它像文件流：你往里写一堆字节，底层按自己的节奏分块落盘或发出。代价是没有消息边界——写两次 100 字节，对面一次 read 拿到 200 字节，或者分四次拿完，都算正常。所以应用层必须自己定长度：要么先发 4 字节长度头，要么用 \r\n\r\n 这种分隔符。

流套接字在 AF_INET 域下由 TCP/IP 实现，socket(AF_INET, SOCK_STREAM, 0) 建出来的就是它。

数据报套接字 SOCK_DGRAM #

和流套接字相反，SOCK_DGRAM 不建立也不维持连接。发数据时不需要在收发两端做 TCP 那样的握手，把数据打成一个包，加上远程 IP 地址，直接发出去。

数据通过相互独立的报文传输，无序、不可靠：会丢、会被复制、会乱序到达。对可发送的数据报长度也有限制，超过 MTU 的分片在链路上更容易丢。

好处是开销小。不用维护连接状态，不用花时间建连接，所以快。它适合「单次（single-shot）」查询：发一个短请求，等一个短响应，比如 daytime 服务、DNS 查询、状态上报、低优先级日志。服务器崩了客户也不受牵连，不用重连，不用重启。

因为不可靠，重要的数据得自己写重传和超时检查。用 UDP 时把 read / write 换成 sendto / recvfrom：

c
ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);

ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                 struct sockaddr *src_addr, socklen_t *addrlen);

sendto 从 buf 取 len 字节，发给 dest_addr 指的那个地址。recvfrom 在套接字上等数据包，把来源地址填进 src_addr，来源地址长度写进 *addrlen。flags 正常调用填 0。两个函数成功返回实际收发的字节数，出错返回 -1 并设 errno。

UDP 套接字不用 listen，也不用 accept。服务端 socket → bind → 循环 recvfrom；客户端 socket → sendto → recvfrom。想给 recvfrom 加超时，用 setsockopt 设 SO_RCVTIMEO，或者用 sigaction 挂 SIGALRM 打断阻塞。

原始套接字 SOCK_RAW #

SOCK_RAW 让你直接读写 IP 层报文，自己拼 IP 头或者读别人拼好的。ping 的 ICMP、traceroute、自己写的抓包工具都走这条路。它需要 root 或者 CAP_NET_RAW 权限，普通用户建不出来。

顺带纠一个素材里的笔误：有的旧笔记把它写成 SOCK_ROW，正确的是 SOCK_RAW。编译不过的时候先看拼写。

协议参数填什么 #

socket() 的第三个参数 protocol 在九成场景下填 0。填 0 表示「按 domain 和 type 自己挑默认协议」，AF_INET + SOCK_STREAM 就挑 TCP，AF_INET + SOCK_DGRAM 就挑 UDP。只有在同一对 domain/type 下存在多个协议时才需要显式指定，比如 SOCK_RAW 要说明是 IPPROTO_ICMP 还是 IPPROTO_TCP。

九、socket 函数与返回值 #

socket 系统调用创建一个套接字，返回一个描述符，这个描述符就是后面所有操作的把手。

c
#include <sys/socket.h>

int socket(int domain, int type, int protocol);

三个参数，正好对应第一章那三个属性。

参数 含义 常用取值
domain 协议族，决定地址格式 AF_INET（网络）、AF_UNIX（本机文件）
type 通信类型 SOCK_STREAM、SOCK_DGRAM、SOCK_RAW
protocol 具体协议 填 0 用默认

AF_UNIX 和 AF_INET 的分界再明确一下：前者在 Linux 文件系统里实现本地套接字，走文件 IO，快，但只能本机；后者走 TCP/IP，能跨机器。两者都能用同一套 read / write，所以服务端代码换个 domain 就能从网络版切成本地版。

返回值就两种 #

成功返回非负整数，就是文件描述符；失败返回 -1，同时设置 errno。这跟 open、read、write、bind、listen、accept、connect、close 完全一致——整个系统调用家族的约定是统一的：-1 是失败，细节看 errno。

所以每个系统调用后面都该跟一段检查：

c
#include <stdio.h>
#include <errno.h>
#include <string.h>
#include <sys/socket.h>

int fd = socket(AF_INET, SOCK_STREAM, 0);
if (fd < 0) {
    fprintf(stderr, "socket 失败: %s\n", strerror(errno));
    return -1;
}

strerror(errno) 能把 EAFNOSUPPORT、EMFILE、EPROTONOSUPPORT 这些翻成人话。fd 用完一定要 close，不然 EMFILE（进程 fd 用光）会在压测时找上门。

建 TCP 和建 UDP 各一行，这是全书出现频率最高的两行代码：

c
int tcp_fd = socket(AF_INET, SOCK_STREAM, 0);
int udp_fd = socket(AF_INET, SOCK_DGRAM, 0);

close 也是同一套 #

通信结束，两端都 close。服务器读到 read 返回 0 就说明对端已经关了，这时关自己的这一侧，干净。close 只是把 fd 的引用计数减一，多进程共享同一个 fd 时要小心：父子进程各持一份引用，一边 close 不影响另一边，连接要等都关完才真正断。

想在关之前把缓冲里的数据推出去，用 shutdown(fd, SHUT_WR) 只关写方向，还能继续读对方的回应。这是 HTTP 短连接里常见的手法。

十、端口与地址的绑定规则 #

socket() 建出来的套接字还没有名字，别人找不到它。给套接字命名，就是把一个地址结构绑上去，这一步是 bind。

c
#include <sys/socket.h>

int bind(int sockfd, const struct sockaddr *address, socklen_t address_len);

sockfd 是 socket() 返回的那个 fd，address 是你要绑的地址，address_len 是地址结构体的实际长度。成功返回 0，失败返回 -1 并设 errno。

传参时把具体结构体指针强转成通用指针，长度给真实大小：

c
bind(listenfd, (struct sockaddr *)&addr, sizeof(addr));

AF_UNIX 域绑的是一个文件系统路径名，AF_INET 域绑的是 IP 加端口。这是两种「名字」：文件系统的名字看得见摸得着，网络的名字只是端口号加地址的组合。

端口从哪来 #

端口是 16 位整数，范围 0 到 65535，分成三段：

范围 归属 说明
0 – 1023 系统保留 绑定要 root，ftp 21、ssh 22、http 80 都在这里
1024 – 49151 注册端口 自定义服务挑这一段
49152 – 65535 动态端口 内核分配给客户端 connect 时用的临时端口

已经占用的知名端口列在 /etc/services 里。选端口时避开这个文件里出现过的值——不过说实话，没那么好的运气能撞上，选 3000 以上基本不会有事。

bind 失败最常见的两个 errno：

errno 含义 处理
EADDRINUSE 端口被占用 换端口，或开 SO_REUSEADDR
EACCES 权限不够 1024 以下的端口要 root

SO_REUSEADDR 那一条值得单独讲。服务端重启时，上一个进程留下的连接还在 TIME_WAIT 状态，端口被内核占着，bind 直接失败。加两行就能跳过这个等待：

c
int on = 1;
setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));

这段代码要在 bind 之前调用。

绑哪个地址 #

sin_addr.s_addr = htonl(INADDR_ANY) 表示绑本机所有网卡：从 127.0.0.1 进来的连得上，从 192.168.x.x 进来的也连得上。服务器这么写。

只想让本机访问，绑回环：inet_addr("127.0.0.1")。这时候外部机器连不上，调试期用这个能省掉防火墙的干扰。

一台机器可以有多个网卡、多个 IP，每个网卡对应一个硬件接口。绑具体 IP 就是绑具体网卡，只在那张卡上收包。

listen 建队列 #

绑好名字之后，还不能收连接，得先声明「我准备接受连接」。

c
int listen(int sockfd, int backlog);

backlog 是队列的最大长度，也就是允许排队的未处理连接数。队列满了，后来的客户端请求会被拒绝或者超时。返回值同样是成功 0、失败 -1 并设 errno。

backlog 填多少？填 SOMAXCONN 让内核用它的上限，或者填个跟并发量匹配的数（128、512）。这个值不是并发连接数的上限，只是「已经完成握手但还没被 accept 取走」的排队长度。

accept 取连接 #

c
int accept(int sockfd, struct sockaddr *address, socklen_t *address_len);

accept 阻塞，直到队列里有客户端连进来。取的是队列里排第一个的未处理连接。

客户的地址会写进 address 指向的结构体，长度写进 *address_len。如果客户地址超过这个长度，会被截断——所以传之前把长度设成 sizeof(struct sockaddr_in)。不关心对端地址就传 NULL：

c
int conn = accept(listenfd, NULL, NULL);

成功时返回一个新的套接字描述符，这个新 fd 专供这一个客户使用，监听 fd 继续留着接下一个。写服务端时最常见的一类 bug，就是把 listenfd 拿去 read，读不出东西还以为客户端没发。

队列空的时候 accept 会一直阻塞。想改，用 fcntl 设 O_NONBLOCK（第二章那段代码），或者用 select / poll 先探再取。

connect 发起连接 #

c
int connect(int sockfd, const struct sockaddr *address, socklen_t address_len);

客户端拿一个未命名套接字，把服务器的地址塞进 address，调 connect。sockfd 必须是 socket() 返回的合法 fd，成功返回 0，失败返回 -1 并设 errno。

连接不能立刻建立时，connect 会阻塞一段不确定的超时时间，超时到了就放弃，返回失败。被信号打断、而那个信号又被处理了，connect 同样失败——这是 EINTR，要自己重试。

客户端不调 bind。内核在 connect 时给它分配一个临时端口和一个本机 IP，这叫隐式绑定。想指定源端口或者源地址，才需要显式 bind。

一次完整通信的调用顺序 #

text
服务器                                    客户端
socket()    建监听 fd
bind()      绑地址和端口
listen()    建连接队列
accept()    ←── 阻塞等连接 ──────────────  socket()   建 fd
            ←────────────────────────────  connect()  发起连接
            ←── 返回新的 conn fd ────────
read(conn)  ←────────────────────────────  write()
write(conn) ─────────────────────────────→  read()
close(conn)                                close()

握手、确认、重传全在协议栈里，应用层看到的就是 connect 成功、accept 返回。收发数据时，服务端用 recv / send 或者 read / write 都行，UDP 那边换成 recvfrom / sendto。全部结束后双方 close。

十一、易错点速查 #

把前面十章踩过的坑压成一张表，写代码时对着扫一眼。

易错点 症状 改法
sin_port 漏 htons 端口变成 36895 之类的怪值，连不上 填之前先 htons
sin_port 转了两次 小端机上等于没转，仍连不上 只转一次，别叠 htons
inet_addr 的结果又套 htonl IP 变成完全不相干的地址 inet_addr / inet_pton 的返回值已是网络序
忘了 memset 结构体 sin_zero 带脏数据，行为诡异 初始化前 memset(&addr, 0, sizeof(addr))
bind 传 sizeof(struct sockaddr) 换个域就出错 传实际结构体大小
htons 用在 sin_family 上 多数机器无害，逻辑错 地址族不转字节序
拿 listenfd 去 read 读不到数据，errno 是 ENOTCONN 用 accept 返回的 conn fd
少写 SO_REUSEADDR 重启就 EADDRINUSE bind 前 setsockopt
inet_ntoa 存了指针 多个地址打印出来一样 立刻 strcpy 到自己的缓冲区
把 SOCK_STREAM 当消息边界 一次 read 拿半个包或两个包 应用层加长度头
accept 不处理返回值 fd 泄漏，压测时 EMFILE 每次成功都记住 close
-1 当普通值用 inet_addr 的 -1 被当成 255.255.255.255 每个系统调用都查返回值

十二条里有十条跟两个主题有关：字节序和 fd 生命周期。这正好就是本篇的两条主线。

再补三条不在这张表里、但每次都有人问的：

bind 成功不代表能连上。绑 INADDR_ANY 只说明所有网卡都收，防火墙和 iptables 还在半路上拦着。

127.0.0.1 和 0.0.0.0 不是一回事。前者只收本机回环的包，后者收所有网卡。服务端绑 0.0.0.0，客户端连 127.0.0.1 是通的；服务端绑 127.0.0.1，客户端从别的机器连就永远超时。

端口号在两个方向上都是网络序。自己填进去的要用 htons，从 accept 的 address 里、从 getservbyname 的 s_port 里读出来的已经是网络序，打印之前要 ntohs。方向搞反，症状跟漏转一模一样。

写网络代码的节奏应该是这样的：先想清楚手上这个整数要不要上网络，再想清楚这个 fd 现在还有没有人持引用。这两件事想明白了，剩下的都是查手册的活。
