网络基础速记：挥手、排错命令与网卡收发 #

1. TCP 四次挥手 #

  主动关闭方                        被动关闭方
  ESTABLISHED                       ESTABLISHED
      │  FIN (seq=x)                    │
      ├───────────────────────────────►│  被动方收到，通知应用进程
      │                                │
  FIN_WAIT_1                           │
      │  ACK (ack=x+1)                  │
      │◄───────────────────────────────┤
  FIN_WAIT_2                     CLOSE_WAIT
      │  FIN (seq=y)                    │
      │◄───────────────────────────────┤  被动方处理完数据后关
      │                                │
      │  ACK (ack=y+1)                  │
      ├───────────────────────────────►│
  TIME_WAIT                        CLOSED
      │  等待 2MSL
      ▼
  CLOSED
  • 为什么四次：TCP 是全双工，两个方向要各自关闭一次，而 ACK 与 FIN 不能像握手那样合并（被动方可能还有数据没发完）。
  • TIME_WAIT 等 2MSL：MSL = 报文在网络中被丢弃前的最长存活时间。等 2MSL 是为了 (1) 让最后那个 ACK 有机会重传，(2) 让本次连接的旧报文在网络中彻底消失，不会串到下一个同端口连接。
  • 谁先进 TIME_WAIT：主动关闭的一方。所以服务器端频繁短连接会出现大量 TIME_WAIT，这正是 SO_REUSEADDR 存在的原因。

2. 网络状态检测命令 #

命令 用途
ifconfig / ip addr 查看/配置网络接口
ping 检测网络连通性（ICMP）
netstat / ss 查看网络状态：监听端口、连接、协议栈统计
traceroute 检测到目的主机经过的路由器
tcpdump 抓包，显示本机网络流量

排查顺序建议：ifconfig 看链路是否 up → ping 看三层通不通 → ss -lntp 看端口是否监听 → traceroute 看路径 → tcpdump 看报文。

3. 网卡驱动收发的完整过程 #

发送：

  1. 网络设备驱动从上层协议栈拿到 sk_buff；
  2. 取出有效数据与长度，放入临时缓冲区（DMA 缓冲）；
  3. 以太网要求帧最小 64 字节，不足则在尾部补 0；
  4. 设置硬件寄存器，启动发送；
  5. 发送完成中断里回收缓冲区、更新统计。

接收：

  1. 由中断触发（收到包 → 网卡拉中断）；
  2. 中断处理程序判断中断类型，若是接收中断则读取收到的数据到 sk_buff；
  3. 把 sk_buff 通过 netif_rx / NAPI 上抛给上层协议栈。

这就是「中断上半部只管把数据搬走，协议栈处理放到软中断/NAPI 轮询」的由来——避免高速收包把 CPU 全耗在中断里。
