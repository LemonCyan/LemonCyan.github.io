这一篇只讲一件事：一个服务器进程怎么同时伺候多个客户端。从最简单的循环开始，一路走到多进程、多线程、IO 多路复用，最后落到两版聊天室代码上。

讲：四种并发模型的流程、代码、开销与选型；并发下的共享数据怎么加锁；客户端掉线怎么发现、怎么回收。

不讲：阻塞/非阻塞/信号驱动/异步 IO 这几档的内核细节，那是同组《IO 模型》篇的地盘；socket/bind/listen/accept 每个参数什么意思，看《套接字编程基础》；三次握手、TIME_WAIT 那些看协议分析那一组。

整篇的主线一句话：服务器并发模型的演进，就是「怎么让一个进程处理多个连接」的演进。

一、服务器要解决的核心矛盾 #

一个 listenfd，N 个客户端。矛盾出在两处阻塞上。

第一处是 accept：没有新连接进来时，主线程停在这儿。这没什么伤害，反正没事干。第二处是 recv：连上的客户端不发数据时，处理它的那条执行流停在这儿——这一处才是所有麻烦的源头。

循环服务器里，recv 阻塞在客户端 A 身上，客户端 B、C、D 的连接请求就躺在内核的 backlog 队列里没人 accept。队列满了，内核直接丢掉新连接，客户端看到的是连接超时或者 RST。于是有四条路线，区别只在一件事上：谁去承担那个阻塞。

路线 一个连接由谁负责 同时能服务几个 主要代价
循环服务器 主进程轮流 1 个，其余排队 一个慢客户端拖住全体
多进程 一个子进程 受进程数上限 fork 开销，共享数据难
多线程 一个线程 受线程数上限 要加锁，调试难
IO 多路复用 一个线程加一个事件循环 受 fd 上限约束 代码复杂度上去了

注意这里没有哪个模型「消灭」了阻塞。阻塞一直存在，四条路线做的是把阻塞挪到不碍事的地方。

  • 多进程和多线程：把阻塞关进子执行流里，主流程只管 accept，谁卡住都只卡自己那一份。
  • 多路复用：把阻塞收拢到 select/epoll 这一个系统调用上，内核告诉你谁就绪了，你就处理谁，没就绪的一个都不碰。

理解了这个「阻塞搬家」的视角，四种模型的差别就一目了然，后面每一节都能对回这张表。

二、循环服务器 #

最原始的做法。TCP 循环服务器的流程三步：

  1. 服务器从连接请求队列里取出一个请求，accept 建立连接，拿到已连接套接字。
  2. 在这个已连接套接字上循环 recv，收到就处理、就 send 回去，直到客户端关闭连接。
  3. close 已连接套接字，回到第 1 步。

落到代码上就是两层嵌套循环：外层 accept 等新客户端，内层 recv 把当前这个客户端伺候到断开为止。

回射服务器：循环版 #

服务器收到什么就原样发回什么，客户端从键盘读一行发过去、等回显，输入 quit 退出。

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define BUFFER_SIZE 128
#define PORT 8888

int main(void)
{
    int listenfd, clientfd, n;
    struct sockaddr_in serveraddr, clientaddr;
    socklen_t peerlen;
    char buffer[BUFFER_SIZE];

    if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket error");
        exit(-1);
    }
    printf("listenfd:%d\n", listenfd);

    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(PORT);
    serveraddr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listenfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) < 0) {
        perror("bind error");
        exit(-1);
    }
    printf("bind successfully!\n");

    if (listen(listenfd, 10) == -1) {
        perror("listen error");
        exit(-1);
    }
    printf("listening....\n");

    while (1) {
        peerlen = sizeof(clientaddr);
        if ((clientfd = accept(listenfd, (struct sockaddr *)&clientaddr, &peerlen)) < 0) {
            perror("accept error");
            exit(-1);
        }
        printf("connection from [%s:%d]\n",
               inet_ntoa(clientaddr.sin_addr), ntohs(clientaddr.sin_port));

        while (1) {                       /* 内层：伺候这一个客户端，伺候到它走 */
            memset(buffer, 0, sizeof(buffer));
            if ((n = recv(clientfd, buffer, BUFFER_SIZE, 0)) == -1) {
                perror("recv error");
                break;
            }
            if (n == 0) {                 /* 对端关闭 */
                break;
            }
            printf("Received message:%s\n", buffer);
            if (send(clientfd, buffer, n, 0) == -1) {
                perror("send error");
                break;
            }
            printf("sendmessage:%s\n", buffer);
        }
        close(clientfd);                  /* 这个客户端结束，回到外层 accept */
        printf("client is closed, waiting for next...\n");
    }

    close(listenfd);
    return 0;
}

两个细节值得盯一眼。send 的第三个参数用的是 n，不是 BUFFER_SIZE：recv 返回多少就发多少，多余的空间不能发出去，否则会带出一串 \0。内层循环里 recv 出错走的是 break 而不是 exit，因为一个客户端出错不该带走整个服务器。

客户端：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#define BUFFER_SIZE 128
#define PORT 8888

int main(void)
{
    int clientfd, n;
    struct sockaddr_in serveraddr;
    char buffer[BUFFER_SIZE];

    if ((clientfd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket error");
        exit(-1);
    }
    printf("clientfd:%d\n", clientfd);

    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(PORT);
    serveraddr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (connect(clientfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) == -1) {
        perror("connect error");
        exit(-1);
    }
    printf("connect successfully!\n");

    while (1) {
        printf("input > ");
        fgets(buffer, sizeof(buffer), stdin);
        if (strcmp(buffer, "quit\n") == 0) {
            break;
        }
        buffer[strlen(buffer) - 1] = '\0';    /* 砍掉 fgets 留下的 '\n' */
        if (send(clientfd, buffer, strlen(buffer), 0) == -1) {
            perror("send error");
            exit(-1);
        }
        memset(buffer, 0, sizeof(buffer));
        if ((n = recv(clientfd, buffer, sizeof(buffer), 0)) == -1) {
            perror("recv error");
            exit(-1);
        }
        if (n == 0) {
            break;                            /* 服务器意外关掉了 */
        }
        printf("echo:%s\n", buffer);
    }
    close(clientfd);
    return 0;
}

循环服务器的特点 #

  • 服务器用两层循环嵌套：外层 accept 接客，内层 recv 服务。这个结构决定了它同一时刻只能有一个客户端在线。
  • 当前客户端没处理完，其他客户端必须一直等。等的地方是内核 backlog，等满了就丢。
  • 客户端的网络越慢、交互越拖沓，其他客户端等得越久。telnet 挂在那儿不发数据，整个服务器就陪它一起挂。

一句话结论：这个模型无法同时为多个客户端服务。它的价值在于简单，调试的时候拿它验证 bind/listen/accept 通不通最省事。

UDP 与 TCP 的循环结构差别 #

UDP 循环服务器没有连接的概念，结构更简单：

text
socket -> bind -> while(1) { recvfrom; 处理; sendto; }

一个数据报处理完就回去等下一个，没有内层循环，也就没有「被某个客户端钉死」这件事——每个数据报都是独立的，处理完立刻返回。TCP 做不到这一点，因为 TCP 是有连接的字节流，你没法从字节流里切出「这一次请求到这里结束」。这个差异在后面会变成一个好用的类比：IO 多路复用的 TCP 服务器，本质上就是把 UDP 那种「处理完这一下就回去等」的循环，硬搬到了 TCP 上。内核帮你判断哪个 fd 有数据了，你就只处理它这一下，处理完立刻回去等下一轮。

三、多进程并发 #

思路很直接：父进程只负责 accept，接到一个连接就 fork 一个子进程，把服务这个客户端的活整个交给子进程。父进程立刻回到 accept 等下一个。

流程三步：

  1. 父进程从连接请求队列取出请求，accept 拿到已连接套接字。
  2. 父进程 fork 出子进程，子进程拿已连接套接字为客户端服务；客户端关闭时子进程退出。
  3. 父进程 close 已连接套接字，回到第 1 步。
c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <signal.h>
#include <sys/wait.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define BUFFER_SIZE 128
#define PORT 8888

void handler(int signo);

int main(void)
{
    int listenfd, clientfd, n;
    pid_t pid;
    struct sockaddr_in serveraddr, clientaddr;
    socklen_t peerlen;
    char buffer[BUFFER_SIZE];

    if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket error");
        exit(-1);
    }
    printf("listenfd:%d\n", listenfd);

    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(PORT);
    serveraddr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listenfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) < 0) {
        perror("bind error");
        exit(-1);
    }
    if (listen(listenfd, 10) == -1) {
        perror("listen error");
        exit(-1);
    }
    printf("listening....\n");

    signal(SIGCHLD, handler);          /* 子进程死了要回收，不然变僵尸 */

    while (1) {
        peerlen = sizeof(clientaddr);
        if ((clientfd = accept(listenfd, (struct sockaddr *)&clientaddr, &peerlen)) < 0) {
            perror("accept error");
            exit(-1);
        }
        printf("connection from [%s:%d]\n",
               inet_ntoa(clientaddr.sin_addr), ntohs(clientaddr.sin_port));

        if ((pid = fork()) < 0) {
            perror("fork error");
            exit(-1);
        } else if (pid == 0) {          /* 子进程 */
            close(listenfd);            /* 子进程不接客，监听套接字一定关掉 */
            while (1) {
                memset(buffer, 0, sizeof(buffer));
                if ((n = recv(clientfd, buffer, BUFFER_SIZE, 0)) == -1) {
                    perror("recv error");
                    break;
                }
                if (n == 0) {
                    break;
                }
                printf("Received message:%s\n", buffer);
                if (send(clientfd, buffer, n, 0) == -1) {
                    perror("send error");
                    break;
                }
            }
            printf("client is closed\n");
            exit(0);                    /* 子进程必须退，退不出去会继续 accept */
        } else {                        /* 父进程 */
            close(clientfd);            /* 父进程不跟这个客户端通数据 */
        }
    }
    close(listenfd);
    return 0;
}

void handler(int signo)
{
    pid_t pid;
    while ((pid = waitpid(-1, NULL, WNOHANG)) > 0) {
        printf("child(%d) is over!\n", pid);
    }
}

这里有两组 close 是初学者最容易漏的。

  • 子进程 close(listenfd)：不关的话，子进程也持有监听套接字，等父进程哪天挂了，这个监听套接字还是被活着，端口一直被占着，重启服务器报 Address already in use。
  • 父进程 close(clientfd)：不关的话，父进程每接一个连接就漏一个 fd，跑几万个连接之后进程被 ulimit 卡死。

这两条都跟 fork 的语义有关：fork 之后子进程拿到的是父进程文件描述符表的完整副本，两边指向同一个打开的文件，引用计数加一。谁不用谁就必须关，否则引用计数永远降不到零。

waitpid 外面的 while 也不能省。多个子进程几乎同时死掉时，SIGCHLD 只会投递一次，信号不排队，一次 handler 里得把所有已死的子进程全回收掉。WNOHANG 保证没有死子进程时立即返回 0，不阻塞。

四、多线程并发 #

多进程的活换线程干，流程一模一样：主线程 accept，接到连接就 pthread_create 一个线程，把服务这个客户端的活交给它。和多进程比，代码上有一个显著简化：线程共享同一个文件描述符表，不需要再考虑「父闭子闭」那套。代价是引入了一个新问题——所有线程共享同一份全局变量，谁改都得加锁。

回射服务器：线程版 #

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <pthread.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define BUFFER_SIZE 128
#define PORT 8888

void *serve_client(void *arg)
{
    int fd = *(int *)arg;
    char buffer[BUFFER_SIZE];
    int n;

    free(arg);                          /* 堆上那个 int 用完就还回去 */
    while (1) {
        memset(buffer, 0, sizeof(buffer));
        if ((n = recv(fd, buffer, BUFFER_SIZE, 0)) <= 0) {
            break;                      /* -1 出错，0 对端关闭，都是收摊信号 */
        }
        if (send(fd, buffer, n, 0) == -1) {
            break;
        }
    }
    close(fd);
    printf("thread %lu done, fd=%d closed\n", (unsigned long)pthread_self(), fd);
    return NULL;
}

int main(void)
{
    int listenfd, clientfd, *arg;
    struct sockaddr_in serveraddr, clientaddr;
    socklen_t peerlen;
    pthread_t tid;

    if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket error");
        exit(-1);
    }
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(PORT);
    serveraddr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listenfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) < 0) {
        perror("bind error");
        exit(-1);
    }
    if (listen(listenfd, 10) == -1) {
        perror("listen error");
        exit(-1);
    }
    printf("listening....\n");

    while (1) {
        peerlen = sizeof(clientaddr);
        if ((clientfd = accept(listenfd, (struct sockaddr *)&clientaddr, &peerlen)) < 0) {
            perror("accept error");
            continue;
        }
        printf("connection from [%s:%d]\n",
               inet_ntoa(clientaddr.sin_addr), ntohs(clientaddr.sin_port));

        arg = malloc(sizeof(int));      /* 每个线程一份，不能用栈上的 &clientfd */
        *arg = clientfd;
        if (pthread_create(&tid, NULL, serve_client, arg) != 0) {
            perror("pthread_create");
            free(arg);
            close(clientfd);
            continue;
        }
        pthread_detach(tid);            /* 不 detach 就漏线程栈 */
    }
    close(listenfd);
    return 0;
}

arg = malloc(sizeof(int)) 这一行是全篇最容易写错的地方。写成 pthread_create(&tid, NULL, serve_client, &clientfd) 会出两种事故：一是主线程下一轮 accept 立刻把 clientfd 覆盖掉，新线程读到的是别人的 fd；二是主线程的函数栈往后被复用，读到的是垃圾值。用 malloc 每个线程一份，是成本最低的解法。直接 (void *)(long)clientfd 强转也可以，只要 fd 装得进指针。

编译要带 -lpthread，一条命令：gcc server.c -o server -lpthread。

进程还是线程 #

多进程和多线程做的是同一件事，选哪个取决于你更怕哪一类问题。

维度 多进程 多线程
隔离性 一个子进程段错误只死自己 一个线程段错误带走整个进程
数据共享 要靠共享内存、管道、socket，麻烦 全局变量直接共享，方便
共享的代价 几乎不用加锁 处处要加锁
创建开销 fork 复制页表，重 建线程轻，但仍有栈开销
上下文切换 重，要换地址空间 轻，同一地址空间
调试难度 相对好查，gdb 跟单个进程 竞态难复现，线程栈不好看
数量上限 几百到几千，取决于内存 几千到上万，取决于栈大小

结论不是「线程比进程好」，而是：

  • 要隔离崩溃就用进程。一个客户端把服务器搞崩了，不该连累其他几百个客户端。nginx 的多 worker、Chrome 的多进程标签页都是这个理由。
  • 要共享数据就用线程。所有连接都要读写同一份在线列表、同一份缓存，进程方案得靠共享内存加信号量，写起来比线程加锁累得多。
  • 两者都要的时候，用「多进程 + 每个进程内部多线程」。进程数量控制在 CPU 核数附近，进程内线程数按连接规模给，兼顾隔离和共享。

没有绝对优劣。脱离场景谈哪个更好，等于没谈。

五、线程池 #

每来一个连接就 pthread_create 一个线程，在客户端几百个的时候够用。到几万个就开始出问题：线程创建和销毁本身要花时间，每个线程的栈默认 8MB（虚拟内存，但页表和内核调度结构是实打实的），线程数一多，调度器光是切换就吃掉大量 CPU 时间。

线程池把这笔开销摊平：启动时固定建 N 个线程，它们一起去任务队列里抢活干。结构就三样东西：

  • 一个任务队列（环形数组或链表），存待处理的 fd；
  • 一个互斥锁，保护队列的头尾指针和计数；
  • 两个条件变量，一个在队列空时让 worker 睡，一个在队列满时让主线程睡。
c
#include <pthread.h>

#define MAX_TASK   1024
#define WORKER_NUM 8

typedef struct {
    int fd;
} task_t;

static task_t task_queue[MAX_TASK];
static int head = 0, tail = 0, count = 0;
static pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t not_empty = PTHREAD_COND_INITIALIZER;
static pthread_cond_t not_full = PTHREAD_COND_INITIALIZER;

void push_task(int fd)
{
    pthread_mutex_lock(&lock);
    while (count == MAX_TASK) {              /* 用 while 不用 if，防止虚假唤醒 */
        pthread_cond_wait(&not_full, &lock);
    }
    task_queue[tail].fd = fd;
    tail = (tail + 1) % MAX_TASK;
    count++;
    pthread_cond_signal(&not_empty);
    pthread_mutex_unlock(&lock);
}

int pop_task(void)
{
    int fd;
    pthread_mutex_lock(&lock);
    while (count == 0) {
        pthread_cond_wait(&not_empty, &lock);
    }
    fd = task_queue[head].fd;
    head = (head + 1) % MAX_TASK;
    count--;
    pthread_cond_signal(&not_full);
    pthread_mutex_unlock(&lock);
    return fd;
}

void *worker(void *arg)
{
    while (1) {
        int fd = pop_task();
        serve_client_fd(fd);                /* 读循环 + 末尾 close */
    }
    return NULL;
}

主线程只做一件事：

c
for (i = 0; i < WORKER_NUM; i++) {
    pthread_create(&tid, NULL, worker, NULL);
}
while (1) {
    clientfd = accept(listenfd, NULL, NULL);
    push_task(clientfd);
}

pthread_cond_wait 必须套在 while 里，这个是硬规矩。它会被信号或者别的线程 broadcast 唤醒，醒来的时候条件不一定成立，得再检查一遍再决定睡还是干活。写成 if，队列明明还是空的它也往下走，pop_task 返回一个垃圾 fd。

线程池有两个参数要试：

参数 给大了会怎样 给小了会怎样
worker 数 线程切换变多，内存涨 队列堆积，连接等超时
队列长度 内存占着不用 突发流量时 push 阻塞，主线程被拖住

worker 数按负载类型定：全是 recv/send 这种 IO 等待的，给几十上百都行，反正它们大部分时间在睡；有 CPU 计算的，给到核数附近就到头了。队列满了以后 push_task 阻塞主线程，这其实是一种反压，比无限堆任务把内存吃干净要好。

六、IO 多路复用服务器 #

前三种模型都在想办法「多造几个执行流」。多路复用反着来：只留一个执行流，把「等」这件事交给内核。

内核手里有所有 fd 的状态，谁可读了、谁可写了它一清二楚。你只要问它一句「这些 fd 里哪些能读」，它阻塞到至少有一个就绪，然后告诉你结果。你照着结果挨个处理，处理完再问一轮。

核心结构就两样东西：

  • 一个集合，装着所有要监听的 fd——监听套接字加所有已连接套接字；
  • 一个事件循环，每轮把集合拷一份、交给 select、遍历返回的结果、分别处理。
text
+-------------------------------------------+
|  global_rdfs: {listenfd, connfd1, connfd2, ...}  |
+-------------------------------------------+
                    |  每轮拷一份
                    v
              select()  阻塞等待
                    |  返回就绪的那几个
                    v
        for fd in 0..maxfd: FD_ISSET(fd) ?
                    |
        +-----------+------------+
        |                        |
   fd == listenfd           其他 fd
   有新连接则 accept        有数据则 recv/send
   并 FD_SET 进集合         出错或 0 则 close + FD_CLR

完整实现 #

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/select.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define PORT    8888
#define MAXSIZE 128

int main(void)
{
    int i, nbyte, listenfd, confd, maxfd;
    char buffer[MAXSIZE];
    fd_set global_rdfs, current_rdfs;
    struct sockaddr_in addr, clientaddr;
    socklen_t addrlen = sizeof(struct sockaddr_in);
    socklen_t caddrlen = sizeof(struct sockaddr_in);

    if ((listenfd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket error");
        exit(-1);
    }
    printf("socket successfully!\nlistenfd : %d\n", listenfd);

    memset(&addr, 0, addrlen);
    addr.sin_family = AF_INET;
    addr.sin_port = htons(PORT);
    addr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listenfd, (struct sockaddr *)&addr, addrlen) == -1) {
        perror("bind error");
        exit(-1);
    }
    printf("bind successfully!\nlisten port:%d\n", PORT);

    if (listen(listenfd, 5) == -1) {
        perror("listen error");
        exit(-1);
    }
    printf("listening...\n");

    maxfd = listenfd;
    FD_ZERO(&global_rdfs);
    FD_SET(listenfd, &global_rdfs);        /* 监听套接字也要被 select 看着 */

    while (1) {
        current_rdfs = global_rdfs;        /* select 会改集合，每轮必须重新拷 */
        if (select(maxfd + 1, &current_rdfs, NULL, NULL, NULL) < 0) {
            perror("select error");
            exit(-1);
        }

        for (i = 0; i <= maxfd; i++) {
            if (!FD_ISSET(i, &current_rdfs)) {
                continue;                  /* 这个 fd 没动静，跳过 */
            }
            if (i == listenfd) {           /* 监听套接字就绪：有新连接 */
                if ((confd = accept(listenfd, (struct sockaddr *)&clientaddr, &caddrlen)) == -1) {
                    perror("accept error");
                    continue;
                }
                printf("Connect from [IP:%s PORT:%d]\n",
                       inet_ntoa(clientaddr.sin_addr), ntohs(clientaddr.sin_port));
                FD_SET(confd, &global_rdfs);      /* 新套接字必须加进集合 */
                if (confd > maxfd) {
                    maxfd = confd;                /* 修正 select 的第一个参数 */
                }
            } else {                       /* 已连接套接字就绪：有数据 */
                nbyte = recv(i, buffer, sizeof(buffer) - 1, 0);
                if (nbyte <= 0) {          /* 0 是对端关闭，-1 是出错 */
                    close(i);
                    FD_CLR(i, &global_rdfs);      /* 不清掉的话下一轮 select 报 EBADF */
                    printf("fd %d closed\n", i);
                } else {
                    buffer[nbyte] = '\0';
                    printf("recv:%s\n", buffer);
                    send(i, buffer, nbyte, 0);
                }
            }
        }
    }
    return 0;
}

为什么这里不能用阻塞 recv #

这是多路复用最容易走偏的地方。事件循环是单线程的，你在循环里对一个 fd 调 recv，如果这个 fd 上根本没有数据，recv 就阻塞了，整个循环停在那儿，其他所有 fd 一个都轮不到。一个客户端发了个半截包就再也不发，全服务器跟着装死。

select 存在的意义就是先问清楚「哪个能读」，然后再 recv。在那个已经就绪的 fd 上 recv，数据已经躺在内核缓冲区里，recv 立刻返回，不会阻塞。所以顺序不能反：先 select，后 recv，而且只对 FD_ISSET 为真的 fd 做 recv。send 也有同样的风险：对端接收窗口满了，send 会卡住。要彻底解决得把 fd 设成非阻塞，send 返回 EAGAIN 就挂个写缓冲，等 select 报可写再发。这一步属于工程化的加法，先知道坑在哪。

select 的硬上限 #

fd_set 是一个位图，FD_SETSIZE 定死 1024。想监听第 1025 个 fd，得改内核头文件重编译，等于没有办法。

每轮都要把整个位图从用户态拷到内核态、再拷回来，然后用户态从 0 到 maxfd 线性扫一遍。连接数上千时，大多数轮次里就绪的只有一两个 fd，剩下 999 次 FD_ISSET 全是白扫。这是 select 的效率瓶颈所在。

poll 把位图换成结构体数组，摆脱了 1024 的限制，但线性扫描还在。epoll 把「注册」和「等待」拆开：epoll_ctl 一次注册长期生效，epoll_wait 直接返回就绪的那几个，不用遍历全集。三者的取舍在《IO 模型》篇里拆得更细，这里只记结论：连接数小、跨平台要求高，用 select；连接数上千、只在 Linux 上跑，用 epoll。代码骨架完全一样，只换中间那层等待调用。

七、四种模型的对比与选型 #

把四种模型摆在一起，差别就清楚了。

维度 循环 多进程 多线程 IO 多路复用
阻塞落在哪 主流程（recv） 子进程 线程 select/epoll 一处
并发连接数 1 数百到数千 数千到上万 上万，受 fd 上限
每连接内存 无额外 每进程一份地址空间 每线程一份栈 一个结构体
崩溃隔离 全挂 强，一个挂了不影响别的 弱，一个线程挂全进程挂 弱
数据共享 天然共享 难，要共享内存 直接共享，需加锁 直接共享，不用加锁
代码复杂度 低 中，要处理僵尸进程 中，要处理竞态 高，状态机要自己维护
CPU 利用率 低，大量时间在阻塞 高 高 最高，不做无用遍历
典型场景 短连接小工具、调试 稳定性优先的 daemon 中小规模服务、共享状态多 高并发网关、IM、代理

选型不用纠结，按下面几条走：

  • 客户端十几个，请求几毫秒就完事，写循环服务器。别为了以后的高并发提前上多路复用。
  • 要抗住单客户端崩溃、要跑长连接但数量不大，用多进程。再配 SIGCHLD 回收。
  • 连接之间要频繁交换数据（聊天室、房间、广播），用多线程。共享在线列表加锁比共享内存加信号量省事太多。
  • 连接数上万、每个连接的数据量小，用多路复用。这时候线程栈的内存开销和切换开销已经压不住了。
  • 真实产品不会只用一种。nginx 是「多个 worker 进程 + 每个进程内 epoll 事件循环」，进程数贴着 CPU 核数，一个 worker 崩了其他照跑；Redis 是单进程 epoll，靠「所有操作都在内存里、不阻塞」来保证事件循环不被拖住。

最后记一句：这四种模型是累积关系，不是替代关系。多路复用不是「更高级的多线程」，它只是把「等」的成本从「每个连接一份栈」换成了「一个循环一次系统调用」。选哪个，看你手上连接的规模和它们之间要不要共享数据。

八、共享数据的同步问题 #

多线程模型里，所有线程共享同一份地址空间。这份便利是有账单的：任何被两个以上线程碰过的数据，都得有人管。

聊天室里要共享的东西：

  • 在线客户端列表（谁在线、对应哪个 fd、叫什么名字）；
  • 房间和成员关系；
  • 各种计数器（在线人数、消息总数）；
  • 日志文件句柄。

拿在线列表举例。三个线程会同时动它：主线程这边新连接进来要 add_user，各个客户端线程要遍历它做广播，客户端掉线要 del_user。一个线程正在 del_user 里把某个 fd 置 -1，另一个线程刚好在遍历同一个位置，读到的是中间态——槽位被标成空，可 name 里还是老数据；或者 fd 刚被置 -1，位置立刻被下一个人占了，广播线程把消息发给了新来的那个人，本来该收消息的人收不到。

如果在线表是用链表做的，后果更直接：A 线程正在遍历 p->next，B 线程把 p 那个节点 free 掉了，A 拿到野指针，轻则读到垃圾数据，重则段错误，整个进程一起死。这是多线程服务器最常见的崩溃原因，没有之一。

解决办法不是「小心点」，是把所有对共享表的操作关进互斥锁：

c
static pthread_mutex_t online_lock = PTHREAD_MUTEX_INITIALIZER;

规则很简单：进函数先 lock，改完 unlock；临界区内不调用任何会长时间阻塞的函数。

锁的粒度 #

一把大锁保护整张在线表，在这个场景里够用。临界区里只有几个循环比较和赋值，纳秒级，锁竞争不构成瓶颈。但有一个位置必须小心：不要在锁里 send。

send 是系统调用，对端接收窗口满了它会阻塞几秒甚至更久。把 send 放在锁里，等于把整个服务器的广播串行化，一个慢客户端能让所有线程排队等锁，多线程白写了。

正确做法是两段式：锁内只做一件事——把要发消息的 fd 拷进一个本地数组；解锁之后再逐个 send。

c
static void broadcast(int except_fd, const char *msg)
{
    int i, n = 0, fds[MAX_ONLINE_NUM];

    pthread_mutex_lock(&online_lock);        /* 锁内：只拷快照 */
    for (i = 0; i < MAX_ONLINE_NUM; i++) {
        if (online[i].fd != -1 && online[i].fd != except_fd) {
            fds[n++] = online[i].fd;
        }
    }
    pthread_mutex_unlock(&online_lock);

    for (i = 0; i < n; i++) {                /* 锁外：慢慢发 */
        if (send(fds[i], msg, strlen(msg), 0) < 0) {
            continue;                        /* 发失败不急，对面 recv 会返回 0 */
        }
    }
}

快照会有个副作用：拷完 fd 之后到真正 send 之间，那个客户端掉了、fd 被系统回收又分配给了新连接，消息就发错了人。这个时间窗极小，聊天室这种场景可以接受；要求严格的话，得给每个连接一个不变的 ID，send 之前再核对一次。

几种同步手段怎么挑 #

手段 管什么 用在哪
互斥锁 pthread_mutex 同一时刻只让一个线程进临界区 在线列表增删、计数器自增
读写锁 pthread_rwlock 读可以并发，写独占 配置表、路由表这类读远多于写的
条件变量 pthread_cond 等待某个条件成立，不占 CPU 任务队列空/满、线程池唤醒
信号量 sem_t 计数型资源配额 限制同时处理的连接数
原子操作 单个变量的无锁自增 统计计数，不值得为它上锁

选型的顺序是：先看是不是「多个线程改同一块数据」，是就上互斥锁；如果读多写少到锁竞争明显，再换读写锁；如果线程需要「等到某件事发生」而不是「抢着改」，用条件变量。

两条防死锁的硬规矩 #

  • 不嵌套加锁。真需要两把锁时，全局统一加锁顺序，所有线程都按「先 A 后 B」来，绝不允许有人反过来。
  • 临界区里不调用外部函数，尤其不调用会阻塞的（recv、send、write 到慢设备、pthread_join）。

九、聊天室实战：多线程版 #

需求四条：连上先报名字；发的消息广播给其他所有人；某人退出时通知剩下的人；在线人数有上限。

数据结构是在线表加一把锁：

#define MAX_ONLINE_NUM  512
#define NAME_LEN        32

struct ON_LINE {
    int  fd;                 /* -1 表示这个槽位空着 */

static struct ON_LINE online[MAX_ONLINE_NUM];

服务器全貌：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <pthread.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <netinet/in.h>

static void broadcast(int except_fd, const char *msg);   /* 定义见上一节 */

static void online_init(void)
{
    int i;
    for (i = 0; i < MAX_ONLINE_NUM; i++) {
        online[i].fd = -1;
        online[i].name[0] = '\0';
    }
}

static int add_user(int fd, const char *name)
{
    int i, idx = -1;

    pthread_mutex_lock(&online_lock);
    for (i = 0; i < MAX_ONLINE_NUM; i++) {
        if (online[i].fd == -1) {
            online[i].fd = fd;
            strncpy(online[i].name, name, NAME_LEN - 1);
            online[i].name[NAME_LEN - 1] = '\0';
            idx = i;
            break;
        }
    }
    pthread_mutex_unlock(&online_lock);
    return idx;
}

static void del_user(int fd)
{
    int i, found = 0;
    char name[NAME_LEN];
    char msg[NAME_LEN + 32];

    pthread_mutex_lock(&online_lock);        /* 先把名字抄出来，再清槽位 */
    for (i = 0; i < MAX_ONLINE_NUM; i++) {
        if (online[i].fd == fd) {
            strncpy(name, online[i].name, NAME_LEN);
            name[NAME_LEN - 1] = '\0';
            online[i].fd = -1;
            online[i].name[0] = '\0';
            found = 1;
            break;
        }
    }
    pthread_mutex_unlock(&online_lock);

    if (!found) {
        return;
    }
    snprintf(msg, sizeof(msg), "%s left!\n", name);
    broadcast(-1, msg);
}

static void *serve_client(void *arg)
{
    int fd = (int)(long)arg;                 /* fd 按值传进来，不传栈地址 */
    int n;
    char buffer[BUFSIZ];
    char name[NAME_LEN];
    char msg[BUFSIZ + NAME_LEN + 16];

    n = recv(fd, name, NAME_LEN - 1, 0);     /* 第一包是名字 */
    if (n <= 0) {
        close(fd);
        return NULL;
    }
    name[n] = '\0';

    if (add_user(fd, name) < 0) {            /* 满员 */
        snprintf(msg, sizeof(msg), "server full, bye\n");
        send(fd, msg, strlen(msg), 0);
        close(fd);
        return NULL;
    }
    snprintf(msg, sizeof(msg), "%s joined!\n", name);
    broadcast(fd, msg);

    while (1) {
        memset(buffer, 0, sizeof(buffer));
        n = recv(fd, buffer, sizeof(buffer) - 1, 0);
        if (n <= 0) {                        /* 0 对端关闭，-1 出错 */
            break;
        }
        buffer[n] = '\0';
        snprintf(msg, sizeof(msg), "%s say %s", name, buffer);
        broadcast(-1, msg);                  /* -1 表示连自己一起发 */
    }

    close(fd);
    del_user(fd);
    printf("fd %d is offline\n", fd);
    return NULL;
}

对着原始素材改的四处，每一处都是真实事故点：

原写法 问题 改法
pthread_create(&pid, NULL, func, (void *)(&new_fd)) 传的是 main 栈上变量的地址，下一轮 accept 立刻覆盖 (void *)(long)new_fd 按值传

del_user(fd, index) 用调用方算的快照下标 下线时槽位已被复用，index 指向的不是这个人的名字 只传 fd，函数内部按 fd 找

十、聊天室实战：多路复用版 #

同样的聊天室，换一个线程管全部连接。这一版没有 pthread，也没有锁。

没有锁不是忘了写，是结构上不需要。整个服务器只有一个线程，所有对在线集合的读写都发生在同一个事件循环里，物理上不存在并发。并发模型的差别在这里体现得最直白：多线程用锁换并行，多路复用用「不并行」换掉锁。

只多一个集合 #

上一章的 online[] 表换成一个 fd_set。fd_set 本身就把「在线」这件事表达完了：位为 1 就是在线。

c
#define N 64
typedef struct sockaddr SA;

int main(int argc, char *argv[])
{
    int listenfd, connfd, i, j, maxfd, n;
    char buf[N];
    fd_set global_rdfs, current_rdfs;
    struct sockaddr_in myaddr;

    if (argc < 3) {                          /* ./server 127.0.0.1 8888 */
        printf("Usage : %s <my_ip> <my_port>\n", argv[0]);
        exit(-1);
    }

    if ((listenfd = socket(PF_INET, SOCK_STREAM, 0)) < 0) {
        perror("fail to socket");
        exit(-1);
    }

    bzero(&myaddr, sizeof(myaddr));
    myaddr.sin_family = PF_INET;
    myaddr.sin_port = htons(atoi(argv[2]));          /* 端口是字符串，转成二进制 */
    myaddr.sin_addr.s_addr = inet_addr(argv[1]);     /* inet_addr 直接产出网络字节序 */

    if (bind(listenfd, (SA *)&myaddr, sizeof(myaddr)) < 0) {
        perror("fail to bind");
        exit(-1);
    }
    if (listen(listenfd, 5) < 0) {
        perror("fail to listen");
        exit(-1);
    }

    FD_ZERO(&global_rdfs);
    FD_SET(listenfd, &global_rdfs);      /* 监听套接字也在集合里，它也要被等 */
    maxfd = listenfd;

    while (1) {
        current_rdfs = global_rdfs;      /* 备份用：select 会改掉传进去的集合 */
        if (select(maxfd + 1, &current_rdfs, NULL, NULL, NULL) < 0) {
            perror("fail to select");
            exit(-1);
        }

        for (i = 3; i <= maxfd; i++) {   /* 0/1/2 被标准流占了，从 3 起 */
            if (!FD_ISSET(i, &current_rdfs)) {
                continue;
            }
            if (i == listenfd) {         /* 监听套接字就绪：来新人了 */
                if ((connfd = accept(i, NULL, NULL)) < 0) {
                    perror("fail to accept");
                    continue;
                }
                FD_SET(connfd, &global_rdfs);     /* 一定加进集合，不然它永远不被等 */
                if (connfd > maxfd) {
                    maxfd = connfd;
                }
                printf("client %d join\n", connfd);
            } else {                     /* 普通套接字就绪：有人说话了 */
                n = recv(i, buf, N - 1, 0);
                if (n <= 0) {            /* 0 关连接，-1 出错，都收摊 */
                    close(i);
                    FD_CLR(i, &global_rdfs);
                    printf("peer %d closed\n", i);
                } else {
                    buf[n] = '\0';
                    for (j = 3; j <= maxfd; j++) {   /* 广播给其他所有人 */
                        if (j == listenfd || j == i) {
                            continue;    /* 监听套接字不回发，说话人自己也不回发 */
                        }
                        if (FD_ISSET(j, &global_rdfs)) {
                            send(j, buf, n, 0);      /* 发 n 个字节，不是 N 个 */
                        }
                    }
                }
            }
        }
    }
    return 0;
}

广播循环里的 FD_ISSET(j, &global_rdfs) 判断不能省。for 扫的是 3..maxfd 整个号段，中间有空洞（客户端走了 fd 就空了，新客户端会拿到下一个号），不判断就会往一个已经关闭的 fd 上 send，触发 SIGPIPE。

send(j, buf, n, 0) 里的 n 也必须是 recv 的返回值。原始代码写的是 send(j, buf, N, 0)，每次都发满 N 字节，把上一轮残留的旧消息一起发出去，接收端看到的是一串粘在一起的内容。

这一版丢掉了什么 #

和多线程版比，多路复用版丢了名字：

  • 没有登录握手，服务器不知道谁是谁，只能按 fd 编号报「client 4 join」；
  • 掉线通知也一样，只能说 peer 4 closed。

补齐要加状态：给每个连接配一个 struct client { int fd; char name[32]; }，用数组或者 fd -> client 的映射存起来。加完这些，fd_set 就只是个「谁在线」的索引，真正的业务状态还是要在外面维护一份——这跟多线程版的 online[] 长得一样，区别只是访问它的永远只有这一个线程。

十一、客户端掉线与资源回收 #

所有模型都逃不过这一节。连接是会断的，而服务器必须知道。

三种终止路径 #

recv 的返回值是唯一的权威信号：

返回值 含义 动作
> 0 收到数据 处理业务
0 对端关闭（收到 FIN） close + FD_CLR + 从在线表删除 + 广播离开
-1 且 errno == EINTR 被信号打断 重试，不算断开
-1 且 errno == EAGAIN/EWOULDBLOCK 非阻塞下暂无数据 直接返回，继续等下一轮
-1 其他 连接异常（RST 等） 和 0 一样处理，收摊

最常漏的是把 -1 当成断开。慢速网络下 EINTR 很常见，一漏就是「什么都没发生却把用户踢了」。

处理顺序也有讲究：先 close(fd)，再 FD_CLR(fd, &global_rdfs)，最后从在线表里删。反过来的话，中间任何一次异常都会留下一个「表里还有、内核已经关了」的 fd，下一轮 select 直接返回 EBADF。

fd 泄漏是怎么发生的 #

一次 close 漏掉，那个 fd 号就一直被占着。服务器的 fd 上限由 ulimit -n 给定，几千次掉线之后 accept 开始返回 EMFILE，新连接全部失败，而服务器自己看不出来任何异常。

查法很直接：

text
lsof -p <pid> | wc -l
ls /proc/<pid>/fd | wc -l

数字一直涨不回落，就是漏了。哪一行代码漏的，在掉线处理函数里打一行日志就能定位。

SIGPIPE：最容易带走整个进程的一行 #

向一个已经收到 RST 的连接 send，内核会给进程发 SIGPIPE。它的默认动作是终止进程，不打日志，不留 core，服务器就这么无声无息地没了。

两种挡法，选一个：

c
signal(SIGPIPE, SIG_IGN);                          /* 全局忽略，send 返回 -1 */

c
send(fd, buf, n, MSG_NOSIGNAL);                    /* 单次调用，不产生信号 */

多线程服务器里这个更致命：一个线程 send 到死连接，信号发给整个进程，所有线程一起没。

拔网线检测不到 #

recv 返回 0 的前提是对端正常关了连接，或者中间设备回了 RST。客户端直接断电、网线被拔，对端什么都没发，服务器这边的 recv 会一直阻塞，连接对象一直挂着。

两个办法：

  • SO_KEEPALIVE 打开 TCP 保活，内核隔一段时间发探测包，默认要两小时才判定死亡，太长；
  • 应用层心跳：客户端每 30 秒发一个约定好的包，服务器维护每个连接的最后活跃时间，事件循环里每轮扫一遍，超时的直接 close 并清理。聊天室这类场景走这条。

十二、易错点速查 #

现象 根因 修法
客户端 B 迟迟连不上，accept 没反应 循环服务器被 A 的 recv 钉住 换多线程或多路复用，别在单执行流里阻塞收
服务器莫名退出，无日志 send 到已关闭连接触发 SIGPIPE signal(SIGPIPE, SIG_IGN) 或 MSG_NOSIGNAL
select 报 EBADF 关闭了 fd 却没 FD_CLR 关连接时同步清集合
新连接收不到任何数据 accept 后忘了 FD_SET，或忘了更新 maxfd 两句都要写，maxfd 取大值
广播内容串台、粘包 send 的长度用了缓冲区大小而非 recv 返回值 一律用 recv 的返回值
线程读到别人的 fd pthread_create 传了栈上变量的地址 按值传 (void *)(long)fd，或 malloc 一份
并发下在线表数据错乱、偶发段错误 多线程裸改共享表，没有锁 所有增删查都关进互斥锁
广播一慢全体卡住 send 写在锁的临界区里 锁内拷 fd 快照，锁外发
僵尸进程越堆越多 fork 之后没回收子进程 SIGCHLD 里 while (waitpid(-1, NULL, WNOHANG) > 0)
重启服务器报 Address already in use 旧连接的 TIME_WAIT 占着端口 setsockopt 开 SO_REUSEADDR
连接数涨到几千后 accept 返回 EMFILE fd 泄漏 掉线路径逐个核实 close
客户端断网后连接永远不释放 没有心跳，也没有保活 应用层心跳加超时清理

回到主线收尾。四种模型解决的是同一个问题：怎么让一个进程处理多个连接。循环靠排队，多进程和多线程靠多造执行流，多路复用靠让内核替你等。判断依据永远是三条——连接规模有多大、连接之间要不要共享数据、能不能容忍一个连接拖垮其他连接。这三条想清楚了，选哪个模型不需要犹豫。
