一、TCP 编程的固定流程 #

套接字是网络编程的 ID。网络通信说到底还是进程间通信，只不过两个进程不在同一台机器上。

网络里每个节点都有网络地址，也就是 IP 地址。两个进程通信，先要确定各自所在节点的地址。但 IP 只能定位到计算机，一台机器上还同时跑着好多进程，光有 IP 不够，还得有端口号。一台机器上一个端口号一次只分给一个进程，端口号与进程一一对应。IP 加端口，才能唯一确定网络里的一个进程。

把网络地址和端口号塞进一个结构体，就是套接口地址结构。多数套接字函数都要一个指向它的指针做参数，靠它传地址。每个协议族都有自己的地址结构，名字一律以 sockaddr_ 开头，后缀是该协议族名里的两个字母。

套接字有三种类型。

类型 名称 语义 谁在用
SOCK_STREAM 流式套接字 可靠、面向连接、按序收发 TCP
SOCK_DGRAM 数据报套接字 不可靠、无连接、报文独立、不保证顺序 UDP
SOCK_RAW 原始套接字 直接访问 IP、ICMP 等底层协议 协议开发

端口号是逻辑意义上的端口，指 TCP/IP 协议里的端口，范围 0 到 65535。80 给 HTTP，21 给 FTP。0 到 1023 一般被系统程序占用。端口号是个 16 位整数。

端口号只有本地意义，它只标识本机上的各个进程。互联网上不同机器的同一个端口号之间没有任何联系。16 bit 够放 64K 个端口号，对一台机器够用。

基本套接字调用顺序是这样一条链：

text
创建套接字 socket() --> 绑定本机端口 bind() --> 监听 listen() --> 接受连接 accept() / 请求连接 connect()
     --> 数据传输 send()、recv()、read()、write() --> 关闭套接字 close()

服务端和客户端走的是两条路。

步骤 服务端 客户端
1 socket() 建套接字 socket() 建套接字
2 bind() 绑 IP 与端口 不 bind，内核自己挑源端口
3 listen() 转被动监听 无
4 accept() 阻塞等连接，返回新套接字 connect() 主动发起连接
5 用新套接字 read/write 用同一个套接字 read/write
6 close() 关新套接字，再关监听套接字 close() 关套接字

记住一句话：TCP 服务端是五步加一个循环。socket → bind → listen → accept → 处理，处理完回到 accept 继续等下一个连接。少了这个循环，服务端就是一次性程序，一个客户端聊完就退出。

把两边合起来，一条完整的时间线是：服务端 socket → bind → listen → accept，客户端 socket → connect，握手完成，两边各自 read/write 收发数据，最后 close 收尾。

connect() 这一步不是空等。它触发 TCP 的三路握手：客户 TCP 发一个 SYN 分节，告诉服务器自己在这个连接里发送数据的初始序列号；服务器确认这个 SYN，同时也发自己的 SYN，带上自己那一侧的初始序列号；服务器把 SYN 和自己的 ACK 合在一个分节里发回；客户再确认服务器的 SYN。握手完，连接就 Established 了。

服务端这边对应的动作叫被动打开，靠 socket、bind、listen 三步完成。客户端那边叫主动打开。

二、服务端：socket 到 listen #

socket() #

socket() 建一个套接字，同时指定协议族和类型。

c
#include <sys/socket.h>

int socket(int family, int type, int protocol);
参数 含义 常用取值
family 协议族 AF_INET、AF_INET6、AF_LOCAL、AF_ROUTE、AF_KEY
type 套接字类型 SOCK_STREAM、SOCK_DGRAM、SOCK_RAW
protocol 具体协议 0，原始套接字除外

AF 是 Address Family 的缩写。返回值成功是非负的套接字描述符，出错返回 -1。

socket() 成功时返回的那个小非负整数叫套接字描述符，简称 sockfd，和文件描述符是一路货。注意，这一步只指定了协议族和类型，既没指定本地协议地址，也没指定远程协议地址。

写个最小的：

c
int sockfd = socket(AF_INET, SOCK_STREAM, 0);
if (sockfd == -1) {
    perror("create socket fail");
    exit(1);
}
printf("create success\n");

bind() #

有了套接字，服务端下一步把它绑到本机的某个端口上。bind() 干这件事。

c
#include <sys/socket.h>

int bind(int sockfd, const struct sockaddr *my_addr, socklen_t addrlen);
参数 含义
sockfd socket() 返回的套接字描述符
my_addr 指向 sockaddr 的指针，里面装着地址、端口、IP
addrlen 地址结构长度，填 sizeof(struct sockaddr)

成功返回 0，出错返回 -1。

IPv4 的地址结构叫 sockaddr_in，定义在 <netinet/in.h> 里：

c
struct sockaddr_in {
    sa_family_t    sin_family;  /* address family: AF_INET */
    in_port_t      sin_port;    /* port in network byte order */
    struct in_addr sin_addr;    /* internet address */
};

struct in_addr {
    uint32_t s_addr;            /* address in network byte order */
};

三个成员记牢：sin_family 是协议族，IPv4 填 AF_INET；sin_port 是 16 位端口号，必须是网络字节序；sin_addr.s_addr 是 32 位 IP 地址，也必须是网络字节序。

bind() 的灵活度比你想的高。它既能指定端口，也能指定 IP，能只指定一个，也能都不指定。

  • 端口填 0：内核在 bind 时挑一个临时端口。bind 不把这个端口号返回给你，因为第二个参数是 const 的，改不了。想拿内核分配的端口号，得再调 getsockname()。
  • IP 填 INADDR_ANY：通配地址，值一般是 0。内核会等到套接字已连接（TCP）或在套接字上发出数据报（UDP）时才挑本地 IP。这么写就是「接收任意 IP」。
  • IP 填具体地址：机器有多张网卡时，用它绑到特定那张网卡上。
c
my_addr.sin_addr.s_addr = htonl(INADDR_ANY);          /* 接收任意 IP */
my_addr.sin_addr.s_addr = inet_addr("192.168.0.123"); /* 绑到指定网卡 */
my_addr.sin_port = htons(12345);                      /* 绑到指定端口 */

字节序这里不能忘。htons() 把 16 位主机字节序转成网络字节序，htonl() 管 32 位。忘了转换，端口就从 2345 变成别的数，客户端连不上，你还找不到原因。

完整的一次「建套接字加绑端口」：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#define PORT 2345

int main(void)
{
    int sockfd;
    struct sockaddr_in addr;
    int addr_len = sizeof(struct sockaddr_in);

    if ((sockfd = socket(AF_INET, SOCK_STREAM, 0)) < 0) {
        perror("socket fail");
        exit(-1);
    }
    printf("socket created successfully!\n");
    printf("socket id is %d\n", sockfd);

    memset(&addr, 0, addr_len);
    addr.sin_family = AF_INET;
    addr.sin_port = htons(PORT);
    addr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(sockfd, (struct sockaddr *)(&addr), addr_len) < 0) {
        perror("bind error");
        exit(-1);
    }
    printf("bind port successfully!\n");
    printf("local port:%d\n", PORT);

    return 0;
}

跑出来是这样：

text
fs@ubuntu:~/qiang/net$ ./socket
socket created successfully!
socket id is 3
bind port successfully!
local port:2345
fs@ubuntu:~/qiang/net$

socket id is 3 说明 0、1、2 已经被标准输入、标准输出、标准错误占了，新套接字排到 3。

listen() #

监听是什么意思？就是让套接字的端口一直处于等待状态，盯着网络里的客户机，等某个客户机发请求。有请求来，端口就接受这个连接。

c
#include <sys/socket.h>

int listen(int sockfd, int backlog);
参数 含义
sockfd 套接字描述符
backlog 已完成连接队列的长度上限，多数系统默认 5

成功返回 0，出错返回 -1。

listen() 把主动连接的套接字变成被动连接的套接字。刚由 socket() 返回时，系统认为你要调 connect() 去连别人，这是主动连接；服务端要的是反过来，等别人来连。系统默认按主动连接处理，所以得靠 listen() 明确告诉内核：这个套接字改成被动等客。

listen() 并没有真正接受连接。它只是把套接字的状态设成监听模式，真正接受连接的是 accept()。调用顺序是 socket → bind → listen，之后才是 accept。

listen() 只适用于 SOCK_STREAM 和 SOCK_SEQPACKET 类型的套接字。AF_INET 下 backlog 最大值可设到 128。

backlog 的含义要抠准：它是内核里那个已完成连接队列的长度上限，不是这个服务端一生能接的连接总数。TCP 连接是个过程，服务端正在处理上一个请求时，后面还会来新的请求，其中有些处在半连接状态，有些已经握手完成等着被取走。内核在自己的空间里维护队列跟踪这些连接，队列不能无限大，backlog 就是这个上限。队列满了，新来的连接会被拒或被丢弃。

加 listen 之后：

c
listen_fd = listen(sockfd, 10);
if (listen_fd == -1) {
    perror("listen fail");
    exit(1);
}
printf("listen success\n");

这段跑起来，打印 listen success 之后程序就退出了，因为没调 accept 去取连接。想看住端口，得在 listen 后头接上 accept，端口才一直开着等客。

三、服务端：accept 与连接队列 #

服务端处于监听状态时，客户机的连接请求来了，它并不会立刻处理，而是把这个请求放进等待队列，等到系统空闲再处理。接受连接请求的函数是 accept()。

c
#include <sys/socket.h>

int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
参数 含义
sockfd 监听套接字描述符
addr 结果参数，存对端地址，不关心就传 NULL
addrlen 结果参数，传入结构体大小，返回实际填写的大小，可传 NULL

成功返回一个建立好连接的新套接字描述符，出错返回 -1。

accept() 默认阻塞，一直到有一个客户连接建立后才返回。它从内核里把已经建立的客户连接取出来，交给你一个代表这条连接的套接字，你拿着它就能和这个客户点对点通信。

这里有两个套接字，必须分清：

套接字 谁产生 干什么 能不能收发数据
监听套接字 socket() 建，listen() 转监听 只负责在该端口上接客 不该
连接套接字 accept() 返回 代表一条已存在的点到点连接 该

accept() 返回的是新套接字，服务端监听的套接字只负责接客，不该拿来收发数据。 这是最常搞错的地方：新手拿到 sockfd 就往上 read，发现读不到东西，或者读到了却串了别的连接。

为什么要两个套接字？一个描述字功能太多用起来不直观，内核也确实为每条新连接真真切切产生了一个新的描述字。看返回值的数字就能验证：监听套接字是 3，accept() 之后回来的是 4。

addr 和 addrlen 都是结果参数。addr 收回来的是客户端地址，addrlen 收回来的是这个地址结构的字节数。你对客户地址不感兴趣，两个都传 NULL 就行，这也是最快活的写法：

c
newfd = accept(sockfd, NULL, NULL);

想打印是谁连上来的，就给真实地址结构。下面这段把「五步加循环」和地址打印都装进去了：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define MYPORT 3490

int main(void)
{
    int sockfd, newfd, n;
    char buf[100];
    socklen_t len;
    struct sockaddr_in servaddr, clientaddr;

    sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd == -1) { perror("socket error"); exit(1); }

    bzero(&servaddr, sizeof(servaddr));
    servaddr.sin_family = AF_INET;
    servaddr.sin_port = htons(MYPORT);
    servaddr.sin_addr.s_addr = htonl(INADDR_ANY);
    bzero(&(servaddr.sin_zero), 8);

    n = bind(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr));
    if (n == -1) { perror("bind error"); exit(1); }
    if (listen(sockfd, 10) == -1) { perror("listen error"); exit(1); }
    printf("listening on %d ...\n", MYPORT);

    while (1) {
        len = sizeof(clientaddr);
        newfd = accept(sockfd, (struct sockaddr *)&clientaddr, &len);
        if (newfd == -1) { perror("accept error"); exit(1); }

        if (inet_ntop(AF_INET, &clientaddr.sin_addr, buf, sizeof(buf)) == NULL) {
            perror("inet_ntop error"); exit(1);
        }
        printf("conneting from %s ,port is %d\n", buf, ntohs(clientaddr.sin_port));
        close(newfd);
    }
}

while (1) 把 accept 包住，这就是五步加循环。每转一圈接一个客，接完 close(newfd) 关掉这条连接，回到 accept 继续等。len 进循环必须重置成 sizeof(clientaddr)，accept 会把它改成实际长度，第二圈不重置就传错了。

inet_ntop 把 32 位网络字节序地址转成点分十进制字符串，ntohs(clientaddr.sin_port) 把对端端口转回主机字节序。不转，打印出来就是一串看不懂的数。

再看一个更短的验证版本，只 accept 一次，重点看返回的编号：

c
if (listen(sockfd, 5) == -1) { perror("listen error"); exit(-1); }
printf("listening...\n");

if ((newsockfd = accept(sockfd, (struct sockaddr *)&caddr, &caddr_len)) == -1) {
    perror("accept error"); exit(-1);
}
printf("accepted a new connection ..\n");
printf("new socket id : %d\n", newsockfd);

跑起来，程序停在 listening... 之后不动，说明 2345 端口正在监听，等着本机的连接请求。打开浏览器敲 http://192.168.3.51:2345/（换成你自己的 IP），回车，终端里立刻多出几行：

text
fs@ubuntu:~/qiang/netprogram/tmp$ ./lisacc
socket successfully!
socket id : 3
bind successfully!
local port : 2345
listening...
accepted a new connection ..
new socket id : 4

接到连接，创建了新套接口，ID 是 4。3 和 4 摆在这儿，两个套接字的分工不用再解释。

getsockname 与 getpeername #

两个查询函数，调试时很顶用。

c
#include <sys/socket.h>

int getsockname(int sockfd, struct sockaddr *localaddr, socklen_t *addrlen);
int getpeername(int sockfd, struct sockaddr *peeraddr, socklen_t *addrlen);

getsockname() 返回与套接字关联的本地协议地址。四个使用场合：

  • TCP 客户端不调用 bind，connect 成功返回后，getsockname 能告诉你内核给这条连接分配的本地 IP 和本地端口号。
  • 以端口号 0 调用 bind 之后，用它拿到内核分配的本地端口号。
  • 拿某个套接字的地址族。
  • 绑了通配 IP 的 TCP 服务器上，连接建立后用它拿到分配给此连接的本地 IP。

getpeername() 返回远程协议地址。服务器 accept 之后 fork 出子进程做业务处理时，子进程手里没有 accept 的 addr 结果，得靠 getpeername 拿对端地址和端口号。

端口填 0 让内核分配，再用 getsockname 查回来，关键就这几行：

c
servaddr.sin_port = htons(0);
bind(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr));
listen(sockfd, 10);

socklen_t len = sizeof(servaddr);
if (getsockname(sockfd, (struct sockaddr *)&servaddr, &len) == -1) {
    perror("getsockname error"); exit(1);
}
printf("port :%d\n", ntohs(servaddr.sin_port));

每次跑 port 都不一样，这就是内核临时分配的效果。日志里想记真实监听端口，别拿变量里那个 0，要拿 getsockname 问回来的值。

四、客户端：socket 到 connect #

客户端比服务端短。建套接字之后不 bind，本地地址交给内核去挑。你只要把服务端的地址填进 sockaddr_in：协议族（IPv4 填 AF_INET）、目的 IP、目的端口。

c
#include <sys/socket.h>

int connect(int sockfd, struct sockaddr *serv_addr, int addrlen);
参数 含义
sockfd socket() 返回的套接字描述符
serv_addr 保存着目的端口和 IP 的 struct sockaddr
addrlen 填 sizeof(struct sockaddr)

成功返回 0，出错返回 -1。serv_addr 指向的结构体里存着远处服务器的 IP 与端口号。

connect() 不是发个包就完事，它触发 TCP 三路握手。握手成功才返回 0，所以这个函数返回 0 的那一刻，连接已经是 Established 状态，可以立刻收发。

填 sockaddr_in 时用到的转换函数 #

IP 地址有两种形态：点分十进制字符串，给人看；32 位二进制，给网络传。两边的转换函数得熟。

函数 方向 原型 返回值
inet_addr 字符串 → 32 位网络字节序 in_addr_t inet_addr(const char *strptr) 成功返回地址，出错返回 INADDR_NONE
inet_aton 字符串 → 32 位网络字节序 int inet_aton(const char *strptr, struct in_addr *addrptr) 成功 1，字符串非法 0
inet_ntoa 32 位网络字节序 → 字符串 char *inet_ntoa(struct in_addr inaddr) 成功返回字符串指针，出错 NULL
inet_pton 字符串 → 二进制（支持 v4/v6） int inet_pton(int family, const char *src, void *dst) 成功 1，非法 0，出错 -1
inet_ntop 二进制 → 字符串（支持 v4/v6） const char *inet_ntop(int family, const void *src, char *dst, size_t len) 成功返回 dst，出错 NULL

inet_addr 出错返回 -1，但 255.255.255.255 转出来也是 -1，分不清。inet_aton 和 inet_pton 的返回值把「非法字符串」和「系统错误」分开了，写代码优先用这两个。inet_ntoa 返回的是静态缓冲区，不可重入，多线程里要换成 inet_ntop。

还有字节序。多字节整数在内存里有两种放法：

  • 小端：低位字节放低地址，也就是值的起始地址；高位字节放高地址。PC 走这个。
  • 大端：高位字节放低地址，低位字节放高地址。

网络上的数据流是字节流。一个多字节数值，先传哪个字节？网络字节序的规定是：收到的第一个字节当高位看。这就要求发送端发的第一个字节是高位。而发送端发数据时，第一个字节是数字在内存起始地址里的那个字节，所以多字节数值在发送前，内存里得按大端摆。

发送方和接收方的主机字节序不一样，为了保证收到后能正确解析，数据发之前和收之后都要在主机字节序和网络字节序之间转换。四个函数：

函数 方向 原型 用途
htons 主机 → 网络 uint16_t htons(uint16_t hostshort) 16 位端口号
htonl 主机 → 网络 uint32_t htonl(uint32_t hostlong) 32 位 IP 地址
ntohs 网络 → 主机 uint16_t ntohs(uint16_t netshort) 16 位端口号
ntohl 网络 → 主机 uint32_t ntohl(uint32_t netlong) 32 位 IP 地址

名字里的字母有讲究：h 是 host，n 是 network，s 是 short，l 是 long。16 bit 的端口号用带 s 的两个，IP 地址用带 l 的两个。调用这几个函数只是让数据得到对应的字节序，你不用关心本机的主机字节序和网络字节序是否真的相同；真相同的话，系统把它们定义成空宏，调用等于没做事。

看一个实测 htonl 的：

c
#include <stdio.h>
#include <arpa/inet.h>

int main(void)
{
    int num = 0x12345678, i;

    printf("before convert :%x\n", num);
    for (i = 0; i < 4; i++)
        printf("[%d]:0x%x\n", i, *((char *)&num + i));

    num = htonl(num);
    printf("after convert :%x\n", num);
    for (i = 0; i < 4; i++)
        printf("[%d]:0x%x\n", i, *((char *)&num + i));
    return 0;
}

把 int 转成 char * 再 +i，就是按字节往后挪，一次看一个字节。小端机器上转换前依次是 0x78 0x56 0x34 0x12，转换后变成 0x12 0x34 0x56 0x78，高位跑到前头去了。

完整客户端与错误处理 #

客户端 IP 从命令行传进来，argv[1]。三种情况都要给出人话提示：

情况 现象 提示
IP 不可达 connect 失败 No route to host
IP 通但服务端没开 connect 失败 Connection refused
正常 connect 返回 0 连上了

代码：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define SERVER_PORT 3490

int main(int argc, char *argv[])
{
    int sockfd, i, n;
    socklen_t len;
    struct sockaddr_in servaddr;

    if (argc < 2) {
        printf("usage: ./client <server_ip>\n");
        exit(1);
    }

    sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd == -1) { perror("socket error"); exit(1); }
    printf("create successful\n");

    len = sizeof(servaddr);
    bzero(&servaddr, sizeof(servaddr));
    servaddr.sin_family = AF_INET;
    servaddr.sin_port = htons(SERVER_PORT);

    n = inet_pton(AF_INET, argv[1], &servaddr.sin_addr);
    if (n == -1) {
        printf("%s\n", strerror(errno));
        exit(1);
    }
    if (n == 0) {
        printf("ip error\n");
        exit(1);
    }

    i = connect(sockfd, (struct sockaddr *)&servaddr, len);
    if (i < 0) {
        printf("can't connect to %s,exit\n", argv[1]);
        printf("%s\n", strerror(errno));
        exit(1);
    }
    printf("connect to %s successfully\n", argv[1]);

    close(sockfd);
    return 0;
}

inet_pton 的三档返回值必须分开处理：返回 1 是转成功了，返回 0 是 argv[1] 根本不是合法 IP 字符串，返回 -1 是 family 参数非法，具体错误在 errno 里。

strerror(errno) 是把错误码翻译成人话的关键。No route to host、Connection refused 这类提示全是它给的。别自己手写一串硬编码的错误文案，翻不出来。

五、数据收发：read、write、send、recv #

连接建立以后，两边的动作就对称了。TCP 通信是双向的，双方对等，谁都能发谁都能收。

四个函数分两组：read/write 是文件那一套，套接字也是文件描述符，直接能用；send/recv 是套接字专用的，多一个 flags 参数。

c
#include <unistd.h>

ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);

c
#include <sys/socket.h>

ssize_t send(int sockfd, const void *buf, size_t len, int flags);
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
函数 方向 关键参数 返回值
write 发 buf 是要发的内容 实际写入的字节数，出错 -1
send 发 buf 是发送缓冲区地址，len 是长度 实际发送的字节数，出错 -1
read 收 buf 是存放数据的缓冲区 实际读到的字节数，0 表示对端关闭，出错 -1
recv 收 buf 是接收缓冲区，出参 实际接收的字节数，0 表示对端关闭，出错 -1

flags 一般填 0。填别的值是在要特殊行为，初学阶段别碰。

send 的 buf 是入参，你往里放要发的东西；recv 的 buf 是出参，函数往里写收到的内容，你在外头读。这两个方向搞反了，程序会拿到一堆垃圾。

UDP 那边用的是另一对，比上面两个多两个地址参数：ssize_t sendto(int sockfd, const void *buf, size_t len, int flags, const struct sockaddr *dest_addr, socklen_t addrlen)，ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags, struct sockaddr *src_addr, socklen_t *addrlen)。

用在 TCP 上时，后面几个跟地址有关的参数不起作用，效果等同于 send 和 recv。TCP 已经建好连接，内核知道对端是谁，不需要每次传地址。写 TCP 就用 send/recv 或者 read/write，别拿 sendto 凑数。

返回值必须看 #

四个函数返回的都是「实际搬运的字节数」，不是「你要的字节数」。

write(fd, buf, 100) 返回 37，意思是这次只发出去 37 字节，剩下 63 字节还在你的缓冲区里，得再发。这叫短写。TCP 发送缓冲区满了就会这样。同理，read(fd, buf, 100) 返回 37 也不代表出错，只代表这次内核给了你 37 字节。

所以正确的收发是循环：

c
int write_all(int fd, const char *buf, int len)
{
    int n, total = 0;

    while (total < len) {
        n = write(fd, buf + total, len - total);
        if (n < 0) {
            if (errno == EINTR)
                continue;
            return -1;
        }
        if (n == 0)
            break;
        total += n;
    }
    return total;
}

EINTR 是信号打断。read、write、send、recv 被信号中断时返回 -1 并把 errno 设成 EINTR，这不是真错误，重来一次就行。不处理 EINTR，程序会在收到 SIGCHLD、SIGALRM 之类的信号时莫名其妙失败。

返回 0 是另一回事。对 read、recv 来说，返回 0 表示对端已经关了连接（收到 FIN），这时候该退出循环、关套接字。0 不是「暂时没有数据」，别把它当无事发生。

再看 EINTR 重试在服务端读循环里的写法：

c
do {
    ret = read(newfd, buf, BUFSIZ - 1);
} while (ret < 0 && EINTR == errno);

if (ret < 0) {
    perror("read");
    exit(1);
}
if (!ret) {
    break;          /* 对端关闭 */
}

do ... while 把 read 包住，只要失败原因是 EINTR 就再读一次。退出循环后，真的负值才是错，0 就是对端走了。

六、地址复用 SO_REUSEADDR #

服务端写完，按 Ctrl+C 停掉，改两行再跑，撞上这个：

text
fs@ubuntu:~/net$ ./server
bind error: Address already in use

端口明明没程序在用，ps 也看不到，bind 就是失败。原因在上一轮的连接还挂在 TIME_WAIT 状态上。内核认为那个端口上的四元组还没彻底死掉，不放你重绑。

解决方法是在 bind 之前把 SO_REUSEADDR 打开：

c
#include <sys/socket.h>

int setsockopt(int sockfd, int level, int optname,
               const void *optval, socklen_t optlen);
参数 填什么
sockfd 套接字描述符
level 选项所在的协议层，通用套接字选项填 SOL_SOCKET
optname 选项名，地址复用填 SO_REUSEADDR
optval 指向选项值的缓冲区
optlen 选项值的长度

成功返回 0，出错返回 -1。写法就三行：

c
int on = 1;
if (setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on)) < 0) {
    perror("setsockopt");
    exit(1);
}

位置很关键：必须在 socket 之后、bind 之前。绑完了再设，这一轮已经来不及，只能等下次。&on 传 1 是开，传 0 是关。

开了之后，TIME_WAIT 的旧连接不再挡住新 bind，服务端改完代码重编，立刻能起。开发期这一条能省下大量干等的两分钟。

这里绑的还是同一个端口。SO_REUSEADDR 允许你把新套接字绑到一个还有旧连接处于 TIME_WAIT 的端口上，语义是「复用这个地址」，不是「同时监听」。想两个进程同时监听同一端口，那是 SO_REUSEPORT 的活，两个选项作用不同，别混着用。

七、连接的关闭与 TIME_WAIT #

收发完了要关。关门的函数是 close：

c
#include <unistd.h>

int close(int fd);

成功 0，出错 -1。套接字是文件描述符，close 干的是把引用计数减一，减到 0 才真正释放，同时内核发出 FIN 分节，告诉对端「我这边没数据要发了」。

TCP 断开是四次挥手：

text
主动关闭方                     被动关闭方
    FIN  ------------------->       （我方不再发数据）
    <-------------------  ACK
    <-------------------  FIN       （对方也不再发数据）
    ACK  ------------------->       进入 TIME_WAIT

主动关闭的那一方最后进入 TIME_WAIT，要等 2MSL 才真正消失。Linux 上 MSL 是 30 秒，也就是 60 秒左右。

为什么非要等？两个理由。最后那个 ACK 如果丢了，对端会重发 FIN，这期间本机得还在，才能把 ACK 补上。另外，这条连接上还有旧报文在网络里游荡时，TIME_WAIT 能让它们自然死掉，不至于被下一个同四元组的新连接收进去。

看现场用 ss -tan | grep TIME-WAIT，或者 netstat -an | grep 2345。

TIME_WAIT 堆几千个不稀奇，端口不够用了才叫事。

close 有个副作用要留意：它同时关掉读写两个方向。有时候你只想告诉对端「我不发了」，还想继续收，这就要 shutdown：

c
#include <sys/socket.h>

int shutdown(int sockfd, int how);
how 效果
SHUT_WR 关写方向，发 FIN，还能继续 read
SHUT_RD 关读方向
SHUT_RDWR 两个方向都关 
c
shutdown(fd, SHUT_WR);   /* 我发完了，对端 read 会返回 0，但它还能继续发 */

服务端关套接字的顺序也有讲究：先 close(newfd) 关这条连接，再 close(sockfd) 关监听套接字。反过来也能跑，但监听套接字先关掉，后面来的连接请求就没处落，正在处理的这条也会被连带断掉。

同一个描述符别 close 两次。第二次会关掉另一个恰好复用了这个编号的套接字，或者直接返回 EBADF，两种都不好查。

还有一种关法：SO_LINGER。把 l_onoff 设非 0、l_linger 设 0，close 不发 FIN 而直接发 RST，跳过四次挥手，也不进 TIME_WAIT。这条只在你明确要「立刻掐断」时用，正常通信别碰，对端会收到 Connection reset by peer。

八、一个完整的 TCP 回声程序 #

把前面的东西拼起来。服务端收什么回什么，客户端从键盘读一行发出去，再读回显。

服务端 server.c：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <strings.h>
#include <unistd.h>
#include <errno.h>
#include <arpa/inet.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define SERVER_PORT 5001
#define QUIT "quit"

int main(void)
{
    int fd = -1, newfd, ret, on = 1;
    struct sockaddr_in sin;
    char buf[BUFSIZ];

    /* 1. 创建套接字，顺手打开地址复用 */
    if ((fd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket"); exit(1);
    }
    if (setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on)) < 0) {
        perror("setsockopt"); exit(1);
    }

    bzero(&sin, sizeof(sin));
    sin.sin_family = AF_INET;
    sin.sin_port = htons(SERVER_PORT);
    if (inet_pton(AF_INET, "0.0.0.0", (void *)&sin.sin_addr.s_addr) != 1) {
        perror("inet_pton"); exit(1);
    }

    /* 2. 绑定 */
    if (bind(fd, (struct sockaddr *)&sin, sizeof(sin)) != 0) {
        perror("bind"); exit(1);
    }

    /* 3. 监听 */
    if (listen(fd, 5) != 0) {
        perror("listen"); exit(1);
    }
    printf("listen on port %d ...\n", SERVER_PORT);

    /* 4. 阻塞等客户端的连接请求 */
    if ((newfd = accept(fd, NULL, NULL)) == -1) {
        perror("accept"); exit(1);
    }
    printf("client connected, newfd = %d\n", newfd);

    /* 5. 收发循环 */
    while (1) {
        bzero(buf, BUFSIZ);
        do {
            ret = read(newfd, buf, BUFSIZ - 1);
        } while (ret < 0 && EINTR == errno);

        if (ret < 0) { perror("read"); exit(1); }
        if (!ret) { printf("client closed\n"); break; }

        printf("receive data: %s", buf);

        if (!strncasecmp(buf, QUIT, strlen(QUIT))) {
            printf("client is exiting!\n");
            break;
        }
        if (write(newfd, buf, ret) != ret) { perror("write"); break; }
    }

    close(newfd);
    close(fd);
    return 0;
}

客户端 client.c：

c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <strings.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define SERVER_PORT 5001
#define SERVER_IP "192.168.1.101"
#define QUIT "quit"

int main(void)
{
    int fd = -1, ret;
    struct sockaddr_in sin;
    char buf[BUFSIZ];

    if ((fd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket"); exit(1);
    }

    bzero(&sin, sizeof(sin));
    sin.sin_family = AF_INET;
    sin.sin_port = htons(SERVER_PORT);
    if (inet_pton(AF_INET, SERVER_IP, (void *)&sin.sin_addr.s_addr) != 1) {
        perror("inet_pton"); exit(1);
    }

    if (connect(fd, (struct sockaddr *)&sin, sizeof(sin)) != 0) {
        perror("connect"); exit(1);
    }
    printf("connected to %s:%d\n", SERVER_IP, SERVER_PORT);

    while (1) {
        bzero(buf, BUFSIZ);
        if (fgets(buf, BUFSIZ - 1, stdin) == NULL) {
            perror("fgets"); continue;
        }
        write(fd, buf, strlen(buf));

        if (!strncasecmp(buf, QUIT, strlen(QUIT))) {
            printf("client is exiting\n");
            break;
        }
        bzero(buf, BUFSIZ);
        ret = read(fd, buf, BUFSIZ - 1);
        if (ret <= 0) { perror("read"); break; }
        printf("echo: %s", buf);
    }

    close(fd);
    return 0;
}

编译：gcc server.c -o server 和 gcc client.c -o client。先跑服务端，另一个终端跑客户端：

text
fs@ubuntu:~/net$ ./server
listen on port 5001 ...
client connected, newfd = 4
receive data: hello
receive data: quit
client is exiting!

fs@ubuntu:~/net$ ./client
connected to 192.168.1.101:5001
hello
echo: hello
quit
client is exiting

几个点值得说：

  • bzero(&sin, sizeof(sin)) 先把结构体清零。sockaddr_in 里有个 sin_zero 填充字段，不清零会带脏数据进 bind，某些实现上直接失败。
  • inet_pton(AF_INET, SERVER_IP, &sin.sin_addr.s_addr) 把点分十进制字符串转成 32 位网络字节序，比 inet_addr 好，因为它能区分「字符串非法」和「系统错误」。
  • 服务端绑 0.0.0.0 表示接受任意网卡来的连接。原来那版绑的是 192.168.1.101，机器换 IP 就得改代码；绑成通配地址可以跨网段收连接，调试时省事。
  • 服务端 read 返回 0 说明客户端关了连接，直接 break 出循环，别拿这个值当数据。
  • strncasecmp(buf, QUIT, strlen(QUIT)) 是不区分大小写比较前 4 个字节，QUIT 和 quit 都能退出。
  • write(newfd, buf, ret) 用的是 read 的返回值当长度，不是 BUFSIZ。buf 里只有 ret 个字节是这次读到的数据，多发出去的都是残留。
  • 客户端回读用 ret <= 0 一起判了。0 是对端关闭，负值是错，两种都该退出循环。

换个小练习：accept 之后不回声，time() 拿当前时间拼成字符串，write 给客户端，再 close(newfd)。五步一点不变，只换了处理里的内容，一个时间服务器就成了。

这个服务端只接一个客，处理完就退。要做到能连续接客，把 accept 和收发整个包进 while (1)，就是第十章的事。

九、字符串传输的边界问题 #

TCP 是字节流。它不认消息，只认字节。你连着 write 三次，对端一次 read 全收走，或者第一次 read 只拿到半条，剩下的一次补上。

recv 读到的不是「一条消息」，半条是一条，两条拼一起也是一条。字节流没有记录边界这回事。UDP 才有，一个报文一个边界，收的时候要么整条收到，要么收不到。

这带来两个具体麻烦：

  • 切包：一条消息被拆成两次 read，你按「读到什么就是一条」去解析，JSON 解一半就报错。
  • 粘包：两条短消息被合并成一次 read，你把两条当一条处理，第一条的尾巴被当成了第二条的开头。

要解决，只能靠应用层自己约边界。三种做法：

方案 怎么约 优点 代价
长度前缀 先发 4 字节长度，再发内容 二进制安全，解析快 得处理长度字段的字节序
定界符 用 \n 或 \0 结尾 好读，适合文本协议 内容里不能出现定界符，得转义
定长报文 每条固定 N 字节，不够补零 实现最简单 浪费带宽，长度受限

长度前缀 #

发之前先 htonl 出 4 字节长度头，接收端先读满 4 字节，知道长度，再循环读满正文。write_all 用第五章那个。

c
int send_packet(int fd, const char *buf, int len)
{
    uint32_t hdr = htonl(len);

    if (write_all(fd, (char *)&hdr, 4) != 4)
        return -1;
    return write_all(fd, buf, len);
}

int recv_packet(int fd, char *buf, int cap)
{
    uint32_t hdr;
    int len, got = 0, n;

    if (read(fd, &hdr, 4) != 4)      /* 严谨写法也要循环读满 4 字节 */
        return -1;

    len = ntohl(hdr);
    if (len < 0 || len >= cap)
        return -2;                  /* 长度不合理，别直接 malloc */

    while (got < len) {
        n = read(fd, buf + got, len - got);
        if (n <= 0)
            return -1;
        got += n;
    }
    buf[len] = '\0';
    return len;
}

要点三条。长度头必须定字节序，htonl 和 ntohl 一对；正文必须循环读到 len 个字节，不能指望一次 read 到位；len 收到之后先卡范围，负数或者超过缓冲区大小的值直接丢掉，别拿着它去申请内存，那是缓冲区溢出的经典入口。

换行定界 #

文本协议省事，按行读：

c
int read_line(int fd, char *buf, int cap)
{
    int n = 0, r;
    char c;

    while (n < cap - 1) {
        r = read(fd, &c, 1);
        if (r <= 0)
            return -1;
        if (c == '\n')
            break;
        buf[n++] = c;
    }
    buf[n] = '\0';
    return n;
}

一次 read 一个字节，系统调用次数太多，长行会很慢。实际工程里是「攒一块缓冲，在缓冲里找 \n」，找到就切一条出来，剩下的留在缓冲里等下次。这就是给连接配一个读缓冲区的原因。

\0 结尾也算一种定界，但它只能用在内容本身不含 0 字节的场合。传二进制文件时用 \0 定界必错，老老实实上长度前缀。

不管哪种方案，记住同一件事：边界是应用层定的，TCP 不会替你保留消息形状。

十、并发处理与每连接一线程 #

第八章那个服务端有个硬伤：accept 接上一个客，就在收发循环里出不来，第二个客户端连上来只能干等，直到第一个人走。

要同时伺候多个连接，三条路。

方案 做法 撑得住 代价
每连接一进程 fork 出子进程处理 几十到几百 进程重，上下文切换贵
每连接一线程 pthread_create 处理 几百到几千 线程栈吃内存，共享数据要加锁
IO 多路复用 select/poll/epoll 单线程 上万 代码结构完全变，见「IO 模型」组

最直观的是每连接一线程。accept 循环只管接客，接完把新套接字交给线程，主线程立刻回去等下一个。

c
#include <pthread.h>

static void *client_thread(void *arg)
{
    int fd = *(int *)arg;
    char buf[1024];
    int n;

    free(arg);
    while ((n = read(fd, buf, sizeof(buf))) > 0) {
        if (write_all(fd, buf, n) < 0)
            break;
    }
    close(fd);
    return NULL;
}

int main(void)
{
    /* …socket、bind、listen 照旧… */
    while (1) {
        int cfd, *p;
        pthread_t tid;

        cfd = accept(listenfd, NULL, NULL);
        if (cfd < 0) {
            if (errno == EINTR) continue;
            perror("accept"); break;
        }

        p = malloc(sizeof(int));
        if (p == NULL) { close(cfd); continue; }
        *p = cfd;

        if (pthread_create(&tid, NULL, client_thread, p) != 0) {
            close(cfd); free(p); continue;
        }
        pthread_detach(tid);
    }
    return 0;
}

几个必须想清楚的点：

  • 新套接字要用 malloc 出来传给线程。accept 返回的是栈上的 cfd 变量，循环下一圈就被覆盖，线程拿到的就是野值。
  • 必须 pthread_detach。不 detach 又不 join，线程退出后资源不回收，跑久了内存一路涨。
  • 谁 close 谁负责。连接套接字 cfd 归线程关，主线程绝不能顺手关掉，否则线程读到的是别人的数据。
  • 监听套接字 listenfd 是主线程的，线程碰都别碰。
  • 编译加 -lpthread：gcc server.c -o server -lpthread。

线程版的内存账要算清。默认一个线程栈 8MB，一千个连接就是 8GB 虚拟内存，实际用不了那么多但地址空间和页表开销是真的。可以在 pthread_create 之前改属性：

c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 128 * 1024);   /* 128KB 够用 */
pthread_create(&tid, &attr, client_thread, p);
pthread_attr_destroy(&attr);

栈压到 128KB，几千连接才站得住。栈小了就别在线程里开大数组，char buf[1024] 这种规模没事，char buf[64 * 1024] 会直接爆栈。

想用进程版，结构差不多：

c
pid = fork();
if (pid == 0) {
    close(listenfd);            /* 子进程不碰监听套接字 */
    handle(newfd);
    close(newfd);
    exit(0);
}
close(newfd);                   /* 父进程不碰连接套接字 */

父子进程的套接字引用计数各自独立，两边都得关自己不要的那一份，否则那条连接的空闲引用会一直挂着。僵尸进程也要收：一行 signal(SIGCHLD, SIG_IGN); 交给系统托管，或者装个 SIGCHLD 处理函数调 waitpid。不收，子进程退一个留一个僵尸，进程表迟早满。

连接数上到万级，进程和线程都撑不住，这时候必须换 epoll。那套东西单线程管几万个连接，代价是代码里再也不能写「阻塞着等」的逻辑。这一篇不展开。

十一、易错点速查 #

现象 真正的原因 怎么改
bind 报 Address already in use 上一轮连接的 TIME_WAIT 占着端口 bind 前开 SO_REUSEADDR
bind 报 Permission denied 绑了 1024 以下的端口 换高端口，或用 root
客户端 connect 报 Connection refused 服务端没起，或端口不对 先确认 ss -tln 里端口在听
客户端 connect 报 No route to host IP 不可达 查网络、查防火墙
服务端能连上，但 read 读不到数据 拿监听套接字去收发了 用 accept 返回的新套接字
第二个客户端连不上 accept 没放进循环 把 accept 和收发包进 while (1)
并发时数据串台 多线程共享了同一个 cfd 变量 每个连接的 fd 单独 malloc
只收到半条消息 把 read 的返回值当「一条」 循环读到够长，或做长度前缀
两条消息被当成一条 粘包 应用层加边界
程序莫名退出，errno 是 EINTR 被信号打断后没重试 循环里判 EINTR 再读
read 返回 0 之后还在读 0 表示对端已关闭 返回 0 就 break 并关套接字
端口打印成 12345 这种怪数 忘了 htons 或 ntohs 端口一律走 htons/ntohs
打印的客户端 IP 乱码 没做 inet_ntop 32 位网络序要转字符串
并发跑久了内存一直涨 线程没 detach，或 fd 没关 pthread_detach，每个分支都要 close
服务端改完代码重启，bind 直接失败 端口被自己上一轮占着 同上，SO_REUSEADDR

最后钉三句话。

服务端是五步加循环：socket、bind、listen、accept、处理，然后回到 accept。

accept 返回新套接字，监听套接字只负责接客，别拿它收发数据。

TCP 是字节流，消息边界得你在应用层自己约。
