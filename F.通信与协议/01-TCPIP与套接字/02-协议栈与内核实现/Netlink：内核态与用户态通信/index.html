这一篇只讲一件事：Netlink 这条「内核与用户态之间传消息」的套接字协议。讲它的地址结构、消息格式、TLV 属性、用户态收发、内核态注册、多播通知，以及 ip、ss、iw 这些工具为什么把身家压在它身上。

不讲：协议栈分层本身、路由表查找算法、Netfilter 钩子、VLAN 与网桥的转发细节。这些各有一篇，按需跳转。

跨篇指路：分层骨架看《协议栈架构与分层》；包从网卡到协议栈的路径看《Linux 数据收发路径》；路由表与策略路由分别看《路由表》《策略路由》；iptables / nft 的落地看《Netfilter》；抓包手法看《Wireshark 实战》。

全文的内核基线是 3.10.36，用户态接口对齐 glibc 的 linux/netlink.h。这套接口从 2.6 到现在没变过形状，变的只是 netlink_kernel_create() 的参数个数。

一、内核与用户态怎么通信 #

内核态和用户态是两套地址空间，一个指针从这边递到那边没法直接解引用。想交换数据，得有通道。Linux 给了三条老路和一条新路。

老路一，系统调用。read、write、ioctl 都是。参数塞进寄存器，内核先 copy_from_user 拷一份再干活。这条路的天生限制是单向提问：一次调用表达一次请求，内核没法反过来主动找你。

老路二，procfs。mount -t proc 之后 /proc 下挂一堆文件。读 /proc/net/tcp 拿回一段文本，自己 sscanf 解析。能看，能改一点，但是文本格式，字段一多就难对齐。

老路三，sysfs。/sys/class/net/eth0/mtu 一个文件一个值，cat 一下拿到 1500，echo 一下改掉。粒度极细，批次能力为零。要配 40 个 VLAN，你得 echo 40 次。

新路，Netlink。一条 AF_NETLINK 域的套接字。用户态 socket() 建出来，内核态 netlink_kernel_create() 注册进去，两边各自用 socket API 收发。

前三者都是「文件」形态，Netlink 是「套接字」形态。这个差别决定了后面所有用法：

  • 有 fd，就能挂到 select / poll / epoll 上，和别的 fd 一起等事件
  • 有双向队列，内核能主动往里塞消息，不用你先问一句
  • 有 sendmsg / recvmsg，能带控制信息，也能一次带多个消息块
  • 有地址结构，一条链路上可以有多个接收者，靠多播组分发

所以看 Netlink 的心态应该和看 TCP 套接字一样：建 socket、bind、send、recv、close。只是把 AF_INET 换成 AF_NETLINK，把 IP 地址换成 nl_pid，把「端口」换成「协议号 + 多播组」。

c
/* 用户态：建一条 netlink 套接字 */
int fd = socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE);

/* 内核态：注册同一协议号的接收端 */
struct netlink_kernel_cfg cfg = {
    .input = my_recv_cb,
};
struct sock *nlsk = netlink_kernel_create(&init_net, NETLINK_ROUTE, &cfg);

一头一尾两行代码，中间夹着的就是整篇文章要展开的东西：地址怎么填、消息怎么排、属性怎么对齐、回调里能干什么、模块什么时候必须加载。

有一个顺序问题先记住：内核模块必须先加载，用户态 socket() 才建得出来。协议号是内核模块注册的，注册之前 AF_NETLINK 上就没有这个协议，socket() 直接失败。这条坑后面还会再提一次。

二、Netlink 的定位 #

Netlink 是 Linux 内核的一套基于 socket 的通信机制。这句话说得比任何定义都准：「只需要知道怎么创建套接字，发送数据，接收数据就行了」。

这句话是理解它的钥匙。Netlink 没有自己的系统调用，没有自己的设备节点，也没有自己的 ioctl 命令空间。它就是一族套接字操作：

  • 创建：socket(AF_NETLINK, SOCK_RAW, 协议号)
  • 绑定：bind(fd, (struct sockaddr *)&nl_addr, sizeof(nl_addr))
  • 发送：sendto / sendmsg
  • 接收：recvfrom / recvmsg
  • 关闭：close

全是 sys/socket.h 里的东西。strace 一个 ip link，第一行就是 socket(AF_NETLINK, SOCK_RAW|SOCK_CLOEXEC, NETLINK_ROUTE)。

这就是它比 ioctl 好用的根本原因。ioctl 是「一个命令号 + 一个结构体指针」，命令和结构体都写死在系统调用参数里，语义由内核代码固定。Netlink 是「一条套接字 + 一段自描述消息」，消息多长、带哪些字段、字段怎么嵌套，全由消息自身描述。内核加了新属性，老程序不认识就跳过，不用重新编译。

socket() 的第三个参数是 netlink 协议号，内核里就是一组 #define，取值 0 到 31。

协议号 宏 用途
0 NETLINK_ROUTE 路由、链路、地址、邻居、qdisc
1 NETLINK_UNUSED 未使用
2 NETLINK_USERSOCK 预留给用户态自定义协议
3 NETLINK_FIREWALL 旧 ip_queue，已废弃
4 NETLINK_SOCK_DIAG socket 监控，ss 用它
5 NETLINK_NFLOG netfilter / iptables ULOG
6 NETLINK_XFRM IPsec
7 NETLINK_SELINUX SELinux 事件通知
8 NETLINK_ISCSI Open-iSCSI
9 NETLINK_AUDIT 审计，auditd 用它
10 NETLINK_FIB_LOOKUP FIB 查找
11 NETLINK_CONNECTOR 连接器，进程事件等
12 NETLINK_NETFILTER netfilter 子系统
13 NETLINK_IP6_FW IPv6 防火墙
14 NETLINK_DNRTMSG DECnet 路由消息
15 NETLINK_KOBJECT_UEVENT 内核 uevent，udev 用它
16 NETLINK_GENERIC 通用 netlink（genl），新子系统都走这里
17 — 预留给 NETLINK_DM（设备映射事件）
18 NETLINK_SCSITRANSPORT SCSI 传输层
19 NETLINK_ECRYPTFS eCryptfs
20 NETLINK_RDMA RDMA
21 NETLINK_CRYPTO 加密层
— NETLINK_INET_DIAG 等于 NETLINK_SOCK_DIAG，老名字的别名

内核里还有一行 #define MAX_LINKS 32。这张表能占的位就 32 个。unit < 0 || unit >= MAX_LINKS 时创建函数直接返回 NULL，这是硬边界，不是建议。

每个协议号背后是一条独立的「总线」，互相不串。NETLINK_ROUTE 上的消息不会跑到 NETLINK_NETFILTER 上去。同时注意别把两个 0 搞混：协议号 0 是 NETLINK_ROUTE，而 sockaddr_nl.nl_pid 里的 0 表示内核。前者填在 socket() 第三个参数，后者填在地址结构里，位置不同，含义不同。

这套东西的实际消费者很集中。ip、ss、iw、nft、udev、auditd、WireGuard 的 wg，底层全是 netlink。ip link add 落到内核就是一条 RTM_NEWLINK 消息，ss -tlnp 就是往 NETLINK_SOCK_DIAG 发一条 SOCK_DIAG_BY_FAMILY 查询。想读懂这些工具的行为，绕不开消息格式。

三、与 ioctl、procfs、sysfs 的对比 #

四条路一起摆出来看，差异就清楚了。

方式 接口形态 数据形态 方向 事件通知 扩展成本
系统调用 / ioctl ioctl(fd, cmd, &arg) 固定结构体 用户到内核为主 无 高，加命令要改内核
procfs open / read / write 文本 双向，以读为主 无，靠轮询 低，但要自己解析文本
sysfs 一个文件一个值 字符串标量 双向 无，靠 poll 文件 中，值一多就失控
Netlink socket API 二进制 TLV 双向，内核可主动发起 有，多播组分发 低，加属性即可

ioctl：一命令一结构体 #

ioctl 的模型是 ioctl(fd, cmd, arg)。cmd 是一个 32 位整数，里面塞了方向、长度、类型、序号；arg 指着一个固定布局的结构体。用户态和内核态各自 #include 同一个头文件，靠这个头文件对齐布局。

问题不在性能，在扩展。想加一个字段，只能复用结构体末尾的保留位，或者新定义一个命令号。命令号空间有限，同一个功能在两代内核上字段含义还不一样，用户态就得写一堆版本判断。字段一多，结构体越来越胖，每次调用都把整块结构体拷一遍，改一个字段要传全量。

ioctl 也做不了通知。内核想告诉你「eth0 的 link 状态变了」，只能等你下次来问。

procfs：读文本，性能差 #

/proc/net/* 系列是一大坨格式化文本。读一条连接要 open、read 到缓冲区、再 sscanf 逐行解析。字段之间有空格，字段顺序变了你的解析器就崩。

数据量大时更难受。十万条连接，/proc/net/tcp 就是几兆文本，全量读、全量解析。ss 之所以比 netstat 快，正是因为它不走 procfs，走 NETLINK_SOCK_DIAG 直接拿二进制结构。

sysfs：一个文件一个值 #

/sys 下的文件粒度极细。改 MTU 是写 /sys/class/net/eth0/mtu，改 MAC 是写 address，加 VLAN 得去 /proc/net/vlan/config 或者干脆用 ip。

单值读写很直观，批量操作就别扭了。要给 40 个接口配同一个参数，就是 40 次 open + write + close。要原子地改一组关联参数，sysfs 给不了事务语义，中间态会被别人看到。

Netlink：结构化数据加多播 #

Netlink 把上面三个短板一起补了：

  • 一次能传结构化数据，整张路由表、整批邻居条目，一条消息或者一个消息序列搞定
  • 消息自带类型和长度，接收方按属性遍历，不认识的属性跳过，向前兼容
  • 内核能主动发起，链路状态一变就 netlink_broadcast() 推给所有订阅者，用户态不用轮询
  • 支持多播组，一条事件投给多个进程，udev、NetworkManager、systemd-networkd 同时盯着 RTMGRP_LINK 互不干扰

代价也有：二进制格式，自己拼消息、自己算对齐、自己处理字节序。调试比 cat 一个文件麻烦，得靠 nlmon 抓包或者 strace。这些后面都讲。

四、Netlink 的地址结构 #

struct sockaddr_nl 定义在 <linux/netlink.h> 里，一共 12 字节。字段只有四个，但是每个都有坑。

c
struct sockaddr_nl {
    __kernel_sa_family_t nl_family;   /* AF_NETLINK */
    unsigned short       nl_pad;      /* 零填充 */
    __u32                nl_pid;      /* 端口 ID */
    __u32                nl_groups;   /* 多播组位图 */
};
字段 宽度 含义 怎么填
nl_family 2B 地址族 恒为 AF_NETLINK
nl_pad 2B 对齐填充 填 0，填别的没有意义
nl_pid 4B 端口 ID，一条 netlink 总线内的地址 用户态填 0 让内核分配，或自己指定；内核侧恒为 0
nl_groups 4B 32 位多播组位图 订阅哪几组就把哪几位置 1，不订阅填 0

nl_pid 的语义要分清三件事：

  1. 内核自己的 portid 固定是 0。用户态发给内核，dest.nl_pid = 0。
  2. 用户态 bind 时 nl_pid 填 0，内核自动分配一个，取值就是进程 pid。同一个进程里开两条同协议号的 netlink 套接字，第二条 bind 会撞 EADDRINUSE，得自己指定不同的值。
  3. 自己指定也行，比如填 50。后面那两个 demo 双方都写死 50，好处是内核不用查表，netlink_unicast(netlinkfd, skb, 50, ...) 直接投递；坏处是这个值成了约定，用户态必须先 bind 到 50，内核才找得到它。

nl_groups 是位图，不是组号。bit 0 对应第 1 组，bit 1 对应第 2 组，组号比位号大 1。想同时订阅第 1 组和第 4 组，就填 (1 << 0) | (1 << 3)，也就是 0x9。位宽 32 位，因为上限就是 32 组。rtnetlink 的组宏直接按位定义，RTMGRP_LINK 是 0x1，RTMGRP_IPV4_IFADDR 是 0x10，用的时候直接或起来。

c
/* 订阅链路变化和 IPv4 地址变化两组事件 */
struct sockaddr_nl local;
memset(&local, 0, sizeof(local));
local.nl_family = AF_NETLINK;
local.nl_pid    = 0;                                  /* 让内核分配 */
local.nl_groups = RTMGRP_LINK | RTMGRP_IPV4_IFADDR;

if (bind(fd, (struct sockaddr *)&local, sizeof(local)) != 0) {
    perror("bind");
    close(fd);
    return -1;
}

绑定之后可以用 getsockname() 把内核分配到的 nl_pid 取回来，发给别人用。

c
socklen_t len = sizeof(local);
getsockname(fd, (struct sockaddr *)&local, &len);
printf("my portid = %u\n", local.nl_pid);

两个用户进程之间也能直接用 netlink 通信，不经过内核。这时 nl_pid 的唯一性要自己管，常用 pid；对方用 sendto 指定你的 nl_pid 投递。NETLINK_USERSOCK 这个协议号就是留给这种用法。

五、消息格式与属性 TLV #

Netlink 的消息是「头 + 体」。头是固定的 struct nlmsghdr，体是一串属性。多条消息可以首尾相接塞进同一次 sendmsg，接收方按 nlmsg_len 一步步往前挪。

消息头 #

c
struct nlmsghdr {
    __u32 nlmsg_len;    /* 总长度，含头，按 4 字节对齐 */
    __u16 nlmsg_type;   /* 消息类型 */
    __u16 nlmsg_flags;  /* 标志位 */
    __u32 nlmsg_seq;    /* 序号，请求与应答配对用 */
    __u32 nlmsg_pid;    /* 发送方 portid */
};
字段 宽度 作用 注意
nlmsg_len 4B 整条消息的字节数，含 16 字节头 填错就收不了，必须按 NLMSG_SPACE() 算
nlmsg_type 2B 消息类型 小于 0x10 是控制消息，其余由子系统定义
nlmsg_flags 2B 请求、多段、应答标志 NLM_F_REQUEST 必带
nlmsg_seq 4B 序号 多线程共用一个 fd 时必须自增配对
nlmsg_pid 4B 发送方 portid 内核会用它回发应答

nlmsg_type 的低段是内核自己占的：NLMSG_NOOP（1）、NLMSG_ERROR（2）、NLMSG_DONE（3）、NLMSG_OVERRUN（4），NLMSG_MIN_TYPE 是 0x10。0x10 往上是各子系统的私有类型，RTM_NEWLINK 是 16，RTM_DELLINK 是 17，RTM_GETLINK 是 18，RTM_NEWADDR 是 20，RTM_DELADDR 是 21，RTM_GETROUTE 是 26。

nlmsg_flags 里常用的几个：

标志 值 含义
NLM_F_REQUEST 0x01 这是一条请求
NLM_F_MULTI 0x02 后面还有，NLMSG_DONE 收尾
NLM_F_ACK 0x04 要求内核回 NLMSG_ERROR 类型的应答
NLM_F_ECHO 0x08 把自己发的消息回声一份
NLM_F_ROOT 0x100 请求整表（dump）
NLM_F_MATCH 0x200 匹配全部
NLM_F_DUMP 0x300 上面两个的组合，最常用
NLM_F_REPLACE 0x100 覆盖已存在项
NLM_F_EXCL 0x200 已存在就报错
NLM_F_CREATE 0x400 不存在就创建
NLM_F_APPEND 0x800 追加到末尾

同一个值在不同 nlmsg_type 下含义不同（0x100 既是 NLM_F_ROOT 也是 NLM_F_REPLACE），读代码时得结合类型看。

对齐与长度宏 #

整条消息和每个属性都按 4 字节对齐。这样 32 位整数和指针天然落在对齐地址上，memcpy 不用拆字节。宏定义如下：

c
#define NLMSG_ALIGNTO 4U
#define NLMSG_ALIGN(len)   (((len) + NLMSG_ALIGNTO - 1) & ~(NLMSG_ALIGNTO - 1))
#define NLMSG_HDRLEN       ((int) NLMSG_ALIGN(sizeof(struct nlmsghdr)))   /* 16 */
#define NLMSG_LENGTH(len)  ((len) + NLMSG_HDRLEN)
#define NLMSG_SPACE(len)   NLMSG_ALIGN(NLMSG_LENGTH(len))
#define NLMSG_DATA(nlh)    ((void *)(((char *)(nlh)) + NLMSG_LENGTH(0)))
#define NLMSG_OK(nlh, len) ((len) >= (int)sizeof(struct nlmsghdr) && \
                            (nlh)->nlmsg_len >= sizeof(struct nlmsghdr) && \
                            (nlh)->nlmsg_len <= (len))
#define NLMSG_NEXT(nlh, len) ((len) -= NLMSG_ALIGN((nlh)->nlmsg_len), \
                              (struct nlmsghdr *)(((char *)(nlh)) + \
                              NLMSG_ALIGN((nlh)->nlmsg_len)))

几个名字长得很像，作用差很多：

宏 算法 用在哪
NLMSG_ALIGN(n) 向上取到 4 的倍数 算下一条消息的起点
NLMSG_LENGTH(n) n + 16 算载荷加头的长度
NLMSG_SPACE(n) align4(n + 16) 算缓冲区大小，也是 nlmsg_len 该填的值
NLMSG_HDRLEN 16 头长度，固定值
NLMSG_DATA(nlh) (char *)nlh + 16 拿消息体指针

NLMSG_SPACE() 去申请内存、nlmsg_len 也填 NLMSG_SPACE() 的值，memset 一次清零，尾巴上的对齐填充就自动是 0。后面的用户态 demo 就是 nlh->nlmsg_len = NLMSG_SPACE(MAX_PLOAD); 这么写的。

属性 TLV #

消息体不是裸数据，是一串属性。每个属性三段：2 字节长度、2 字节类型、变长数据。这是标准 TLV。

c
struct nlattr {
    __u16 nla_len;    /* 含头长度：2 + 数据长度 */
    __u16 nla_type;   /* 类型，高两位是标志 */
};

#define NLA_F_NESTED        (1 << 15)   /* 里面还是属性串 */
#define NLA_F_NET_BYTEORDER (1 << 14)   /* 数据是网络字节序 */
#define NLA_TYPE_MASK       ~(NLA_F_NESTED | NLA_F_NET_BYTEORDER)

#define NLA_ALIGNTO 4
#define NLA_ALIGN(len) (((len) + NLA_ALIGNTO - 1) & ~(NLA_ALIGNTO - 1))
#define NLA_HDRLEN     ((int) NLA_ALIGN(sizeof(struct nlattr)))   /* 4 */

内存布局长这样，+--+ 是 4 字节边界：

text
+------------------+  <- nlmsghdr 起点
| nlmsg_len   4B   |
| nlmsg_type  2B   |
| nlmsg_flags 2B   |
| nlmsg_seq   4B   |
| nlmsg_pid   4B   |
+------------------+  <- NLMSG_DATA()，偏移 16B
| nla_len  2B      |
| nla_type 2B      |  <- 第一个属性
| data ...         |
| pad to 4B        |
+------------------+
| nla_len  2B      |
| nla_type 2B      |  <- 第二个属性
| data ...         |
| pad to 4B        |
+------------------+  <- 消息结束，总长按 4 对齐

对齐规则要记两条：nla_len 记真实长度，不含尾部填充；指针前进按 NLA_ALIGN(nla_len)，带填充。所以数据长度不是 4 的倍数时，尾部会补若干 0 字节，遍历时必须跳过。

嵌套属性让消息能表达树形结构，这是它比固定结构体灵活的地方。父属性的类型带上 NLA_F_NESTED，它的数据部分就是另一串属性。用内核提供的 helper 拼最省事：

c
struct nlmsghdr *nlh = nlmsg_new(1024, GFP_KERNEL);
struct nlattr *nest;

nla_put_u32(nlh, IFLA_MTU, 1500);
nest = nla_nest_start(nlh, IFLA_LINKINFO);
if (nest == NULL) {
    nlmsg_free(nlh);
    return -1;
}
nla_put_string(nlh, IFLA_INFO_KIND, "vlan");   /* 这一层里再放属性 */
nla_nest_end(nlh, nest);                        /* 回填 nest->nla_len */

nla_nest_start() 只写一个占位的属性头，nla_nest_end() 把「从 nest 开头到当前末尾」的长度回填进 nla_len。这样嵌套层数不限，只要总长度不超过缓冲区。

用户态遍历也一样，一层层剥：

c
int len = nlh->nlmsg_len - NLMSG_HDRLEN;
struct nlattr *na;

for (na = (struct nlattr *)NLMSG_DATA(nlh);
     NLA_OK(na, len);
     na = NLA_NEXT(na, len)) {
    switch (na->nla_type & NLA_TYPE_MASK) {
    case IFLA_IFNAME:
        printf("ifname = %s\n", (char *)NLA_DATA(na));
        break;
    default:
        break;      /* 不认识的属性直接跳过，向前兼容 */
    }
}

default: break; 这一行是 Netlink 向前兼容的全部秘密。内核版本升级加了新属性，老程序不认识，跳过不报错。ioctl 做不到这一点：多出来的字段没有位置放，结构体布局是硬约定。

六、用户态编程：socket 与 bind #

用户态五步走：建 socket、bind 本地地址、填目标地址、发、收。

c
#include <sys/socket.h>
#include <linux/netlink.h>

#define NETLINK_USER 22
#define USER_MSG     (NETLINK_USER + 1)   /* 23，自定义协议号 */
#define USER_PORT    50                   /* 自定义 portid */

int fd = socket(AF_NETLINK, SOCK_RAW, USER_MSG);

三个参数挨个说：

  • 域：AF_NETLINK。写 PF_NETLINK 也能跑，两者值相同，但语义上域和协议族不是一回事
  • 类型：SOCK_RAW。netlink 只有 raw 语义，写 SOCK_DGRAM 也能建出来，内核里走同一个实现
  • 协议号：0 到 31，必须是内核已经注册过的

socket() 失败的两个常见原因：

  • 返回 EPROTONOSUPPORT 或 EAFNOSUPPORT：内核模块没加载，协议号 23 没人注册
  • 返回 EMFILE：fd 耗尽

然后是 bind。标准写法：

c
struct sockaddr_nl local;

memset(&local, 0, sizeof(local));
local.nl_family = AF_NETLINK;
local.nl_pid    = 50;       /* 自己指定，内核按这个值回发 */
local.nl_groups = 0;        /* 单播，不订阅多播 */

if (bind(fd, (struct sockaddr *)&local, sizeof(local)) != 0) {
    printf("bind() error\n");
    close(fd);
    return -1;
}

nl_pid 和 nl_groups 的填法决定这条套接字能干什么：

场景 nl_pid nl_groups 结果
只发不收 0 0 可以省掉 bind，sendto 会隐式绑定
单播收 0 0 内核分配 pid 当地址
单播收，要固定地址 非 0 且不冲突 0 用你给的值，内核按它投递
只收事件 0 非 0 位图 加入对应多播组
既收应答又收事件 0 非 0 位图 两类消息都在同一个队列里

demo 里 #define NETLINK_USER 22 只是占个名字，真正注册的是 USER_MSG（22 + 1 = 23）。22 和 23 都在合法范围里，所以这套写法能跑通。自己写的时候别学这个绕法，协议号直接起个名字就行。

bind 之前还要想清楚一件事：同一个协议号下，同一进程只允许一条套接字绑同一个 nl_pid。想开两条，第二条就别填 0，自己给个别的值，或者干脆用 clone 出来的 pid。

七、发送与接收消息 #

发有两条路：sendto 和 sendmsg。收也有两条：recvfrom 和 recvmsg。

sendto #

从建 socket 到发出去，完整流程一行行看：

c
struct nlmsghdr *nlh;
struct sockaddr_nl dest_addr;
struct _my_msg info;
char *data = "hello kernel";
int ret;

memset(&dest_addr, 0, sizeof(dest_addr));
dest_addr.nl_family = AF_NETLINK;
dest_addr.nl_pid    = 0;      /* 0 = 内核 */
dest_addr.nl_groups = 0;

nlh = (struct nlmsghdr *)malloc(NLMSG_SPACE(MAX_PLOAD));
memset(nlh, 0, NLMSG_SPACE(MAX_PLOAD));
nlh->nlmsg_len   = NLMSG_SPACE(MAX_PLOAD);
nlh->nlmsg_flags = 0;
nlh->nlmsg_type  = 0;
nlh->nlmsg_seq   = 0;
nlh->nlmsg_pid   = local.nl_pid;
memcpy(NLMSG_DATA(nlh), data, strlen(data));

ret = sendto(fd, nlh, nlh->nlmsg_len, 0,
             (struct sockaddr *)&dest_addr, sizeof(struct sockaddr_nl));

dest_addr.nl_pid = 0 就是「发给内核」。这一行是用户态到内核态的唯一开关，填别的值就是发给另一个用户进程。

sendmsg 用 struct msghdr 加 struct iovec 拼，好处是能一次带多个缓冲，拼消息不用先拷进一块连续内存。libmnl、libnl 内部大量用 sendmsg。

c
struct iovec iov = { .iov_base = nlh, .iov_len = nlh->nlmsg_len };
struct msghdr msg = {
    .msg_name    = &dest_addr,
    .msg_namelen = sizeof(dest_addr),
    .msg_iov     = &iov,
    .msg_iovlen  = 1,
};
sendmsg(fd, &msg, 0);

接收循环 #

recv 返回字节数，但缓冲区里会躺着好几条消息，必须循环拆开。这是 netlink 编程里最容易写错的地方。

c
char buf[8192];
struct nlmsghdr *nlh;
int len;

len = recv(fd, buf, sizeof(buf), 0);
for (nlh = (struct nlmsghdr *)buf; NLMSG_OK(nlh, len); nlh = NLMSG_NEXT(nlh, len)) {
    if (nlh->nlmsg_type == NLMSG_DONE)
        break;                              /* dump 结束 */
    if (nlh->nlmsg_type == NLMSG_ERROR) {
        struct nlmsgerr *err = (struct nlmsgerr *)NLMSG_DATA(nlh);
        if (err->error != 0)
            fprintf(stderr, "nl error: %s\n", strerror(-err->error));
        continue;                           /* error == 0 表示 ACK */
    }
    handle_one(nlh);
}

NLMSG_ERROR 这个名字有欺骗性。它承载的不只是错误：error == 0 时它就是一条 ACK，说明你上一条请求内核收到了。

完整用户态 demo #

用户态的 u_netlink.c 全文，去掉被打散的碎片和行号，补上头文件：

c
/*******************************
 file: u_netlink.c
 description: 用户态发一条给内核，再等内核回一条
*******************************/
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <sys/socket.h>
#include <linux/netlink.h>

#define NETLINK_USER 22
#define USER_MSG     (NETLINK_USER + 1)
#define MSG_LEN      100
#define MAX_PLOAD    100

struct _my_msg {
    struct nlmsghdr hdr;
    int8_t data[MSG_LEN];
};

int main(int argc, char **argv)
{
    char *data = "hello kernel";
    struct sockaddr_nl local, dest_addr;
    int skfd;
    struct nlmsghdr *nlh = NULL;
    struct _my_msg info;
    int ret;

    skfd = socket(AF_NETLINK, SOCK_RAW, USER_MSG);
    if (skfd == -1) {
        printf("create socket error...%s\n", strerror(errno));
        return -1;
    }

    memset(&local, 0, sizeof(local));
    local.nl_family = AF_NETLINK;
    local.nl_pid    = 50;
    local.nl_groups = 0;
    if (bind(skfd, (struct sockaddr *)&local, sizeof(local)) != 0) {
        printf("bind() error\n");
        close(skfd);
        return -1;
    }

    memset(&dest_addr, 0, sizeof(dest_addr));
    dest_addr.nl_family = AF_NETLINK;
    dest_addr.nl_pid    = 0;            /* to kernel */
    dest_addr.nl_groups = 0;

    nlh = (struct nlmsghdr *)malloc(NLMSG_SPACE(MAX_PLOAD));
    memset(nlh, 0, NLMSG_SPACE(MAX_PLOAD));
    nlh->nlmsg_len   = NLMSG_SPACE(MAX_PLOAD);
    nlh->nlmsg_flags = 0;
    nlh->nlmsg_type  = 0;
    nlh->nlmsg_seq   = 0;
    nlh->nlmsg_pid   = local.nl_pid;    /* self port */
    memcpy(NLMSG_DATA(nlh), data, strlen(data));

    ret = sendto(skfd, nlh, nlh->nlmsg_len, 0,
                 (struct sockaddr *)&dest_addr, sizeof(struct sockaddr_nl));
    if (!ret) {
        perror("sendto error1\n");
        close(skfd);
        exit(-1);
    }

    printf("wait kernel msg!\n");
    memset(&info, 0, sizeof(info));
    ret = recvfrom(skfd, &info, sizeof(struct _my_msg), 0,
                   (struct sockaddr *)&dest_addr, sizeof(dest_addr));
    if (!ret) {
        perror("recv form kernel error\n");
        close(skfd);
        exit(-1);
    }

    printf("msg receive from kernel:%s\n", info.data);

    free(nlh);
    close(skfd);
    return 0;
}

原 demo 里的 if (!ret) 判断不严谨。sendto 返回 -1 才是失败，返回 0 在 netlink 上几乎不会出现；recvfrom 返回 -1 才是错误，返回 0 表示对端关闭。要改成 if (ret < 0) 才抓得住真正的错误。这里保留原样，是为了让你看清原始 demo 的毛病出在哪，也提醒一句：照抄网上的 netlink 代码，先看它判错误的姿势对不对。

这套代码能跑通，前提是下面这句，它比代码本身更重要：

text
一定要先加载内核模块，要不然用户层创建套接字会失败！
因为内核模块会注册 netlink 所使用的协议类型，本例子中协议类型为 USER_MSG，即 23。

这条依赖在 ip、ss 上体现不出来，因为 NETLINK_ROUTE、NETLINK_SOCK_DIAG 是内核内建注册的，开机就有。自己占协议号 23 的时候，模块没 insmod，用户态连 socket() 都建不出来，报错还只是 Protocol not supported，很容易误判成内核不支持 netlink。

八、内核态编程：netlink_kernel_create #

内核侧干三件事：注册协议号、处理收到的消息、释放。注册就一个函数。

函数原型 #

c
/******************************
 net  : linux 网络命名空间结构体指针
 unit : netlink 协议类型
 cfg  : netlink 内核配置参数结构体指针
 返回 : sock 结构指针
******************************/
static inline struct sock *
netlink_kernel_create(struct net *net, int unit, struct netlink_kernel_cfg *cfg);

3.10 只有三个参数。2.6.36 那会儿是六个：(net, unit, groups, input, cb_mutex, module)。改动不是简化接口，是把散着的参数收进结构体。那句「参数变短了，实际是因为放到该结构体中来了」说的就是这件事。老代码直接编不过，必须重写成 cfg 形式。

三个参数逐个拆：

第一个 net，网络命名空间。不深究就传 &init_net，它在 net_namespace.c 里定义，代表初始命名空间。传对了，这条 netlink 套接字就挂在这个 netns 里，别的 netns 看不见它。

第二个 unit，协议号，取值必须在 [0, MAX_LINKS)。越界直接返回 NULL：

c
static inline struct sock *
__netlink_kernel_create(struct net *net, int unit, struct module *module,
                        struct netlink_kernel_cfg *cfg)
{
    struct socket *sock;
    struct sock *sk;
    struct netlink_sock *nlk;
    struct listeners *listeners = NULL;
    struct mutex *cb_mutex = cfg ? cfg->cb_mutex : NULL;
    unsigned int groups;

    BUG_ON(!nl_table);
    if (unit < 0 || unit >= MAX_LINKS)
        return NULL;
    ...
}

MAX_LINKS 是 32。unit 给 32 就拿回 NULL，调用方必须判空。

第三个 cfg，配置结构体。

netlink_kernel_cfg #

c
struct netlink_kernel_cfg {
    unsigned int groups;                 /* 组数，多播用；单播填 0 */
    unsigned int flags;
    void (*input)(struct sk_buff *skb);  /* 收到消息时的回调 */
    struct mutex *cb_mutex;              /* 回调互斥锁，NULL 用默认锁 */
    void (*bind)(int group);             /* 有 socket 加入组时调用 */
};
字段 作用 填错的后果
groups 多播组数量，决定 nl_groups 有多少位可用 填 0 就多播不了，netlink_broadcast 无人可投
flags 配置标志 填 0
input 收消息回调，参数是 sk_buff 不填就没人收，消息在队列里堆到溢出
cb_mutex 保护回调的互斥锁 填 NULL 用内核默认锁
bind socket 加入多播组时的通知钩子 填 NULL 不通知

input 是最关键的成员。签名固定，参数是内核攒好的 sk_buff，消息头就在 skb->data 上。

c
static void recv_cb(struct sk_buff *skb)
{
    struct nlmsghdr *nlh = NULL;
    void *data = NULL;

    printk("skb->len:%u\n", skb->len);

    if (skb->len >= nlmsg_total_size(0)) {
        nlh  = nlmsg_hdr(skb);
        data = NLMSG_DATA(nlh);
        if (data) {
            printk("kernel receive data: %s\n", (int8_t *)data);
            send_msg(data, nlmsg_len(nlh));
        }
    }
}

nlmsg_total_size(0) 是最小消息长度，16 字节。小于它说明 skb 里连完整的消息头都没有，直接丢。nlmsg_hdr(skb) 展开就是 (struct nlmsghdr *)skb->data。

内核侧发送：单播与多播 #

c
/******************************
 ssk      : sock 结构体指针
 skb      : skb 存放消息，data 字段指向 netlink 消息结构，
            控制块保存地址信息，宏 NETLINK_CB(skb) 用来设置
 portid   : 端口 id
 nonblock : 1 表示无接收缓存可利用时立即返回，
            0 表示无接收缓存可利用时睡眠
 返回     : 发送数据的长度
******************************/
int netlink_unicast(struct sock *ssk, struct sk_buff *skb,
                    __u32 portid, int nonblock);

/******************************
 ssk        : sock 结构体指针
 skb        : 同上
 portid     : 端口 id
 group      : netlink 组，位掩码
 allocation : 内存分配类型，GFP_ATOMIC 用于原子上下文（不可睡眠），
              GFP_KERNEL 用于非原子上下文
 返回       : 发送数据的长度
******************************/
int netlink_broadcast(struct sock *ssk, struct sk_buff *skb,
                      __u32 portid, __u32 group, gfp_t allocation);

两个函数都吃 skb，返回时已经把 skb 消费掉（成功投递和无法投递都一样），调用方不要再自己 kfree_skb，否则就是双重释放。

nonblock 这个参数容易踩错：传 MSG_DONTWAIT（值为 1）是非阻塞，接收队列满时立刻返回；传 0 就在队列满时睡眠。在中断上下文或者持自旋锁的地方，只能传 MSG_DONTWAIT。同理 allocation 在中断上下文只能给 GFP_ATOMIC。

拼一条内核消息 #

c
int send_msg(int8_t *pbuf, uint16_t len)
{
    struct sk_buff *nl_skb;
    struct nlmsghdr *nlh;
    int ret;

    nl_skb = nlmsg_new(len, GFP_ATOMIC);
    if (!nl_skb) {
        printk("netlink_alloc_skb error\n");
        return -1;
    }

    nlh = nlmsg_put(nl_skb, 0, 0, USER_MSG, len, 0);
    if (nlh == NULL) {
        printk("nlmsg_put() error\n");
        nlmsg_free(nl_skb);
        return -1;
    }

    memcpy(nlmsg_data(nlh), pbuf, len);

    ret = netlink_unicast(netlinkfd, nl_skb, USER_PORT, MSG_DONTWAIT);
    return ret;
}

nlmsg_new(size, gfp) 分配 skb 并预留头部空间。nlmsg_put(skb, pid, seq, type, payload_len, flags) 写入消息头并返回指针，失败返回 NULL，这时必须 nlmsg_free() 收尾，否则泄漏。nlmsg_data(nlh) 拿到数据区，拷完原始数据后长度已经在 nlmsg_put() 里填好，不用再手动改 nlmsg_len。

完整内核态 demo #

c
/*******************************
 file: k_netlink.c
 description: 内核态注册协议号 23，收到消息后回发
 kernel: linux-3.10.36
*******************************/

#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/skbuff.h>
#include <linux/netlink.h>

#define NETLINK_USER 22
#define USER_MSG     (NETLINK_USER + 1)
#define USER_PORT    50

MODULE_LICENSE("GPL");
MODULE_AUTHOR("arvik");
MODULE_DESCRIPTION("netlink_demo");

int  send_msg(int8_t *pbuf, uint16_t len) { /* 见上一节 */ }
static void recv_cb(struct sk_buff *skb)    { /* 见上一节 */ }

    .input = recv_cb,
};

static int __init test_netlink_init(void)
{
    printk("init netlink_demo!\n");
    netlinkfd = netlink_kernel_create(&init_net, USER_MSG, &cfg);

        printk(KERN_ERR "can not create a netlink socket!\n");

    }

    printk(KERN_DEBUG "netlink exit\n!");
}

module_exit(test_netlink_exit);

send_msg 和 recv_cb 的内容前面已经拆开讲过，这里留注释，是为了让你看清模块骨架：module_init 里注册，module_exit 里释放，中间 cfg 是全局量，靠 .input 把回调挂上去。

释放那一行值得多看一秒。netlink_kernel_create() 返回 struct sock *，而 sock_release() 要 struct socket *，所以得从 sk_socket 字段翻过去。写反了就是把 sock 当 socket 用，卸载模块时直接崩。

还有一个隐患：模块卸载时如果用户态还开着这条套接字，sock_release 之后那条 fd 就悬空了。严谨的写法是加引用计数，等用户态 close 完了再让模块退出。

九、多播组与事件通知 #

单播是「你问我答」，多播是「有事我通知你」。Netlink 的多播靠 nl_groups 位图加内核的 netlink_broadcast() 撑着。

三件事必须对上，缺一件就收不到：

  1. 内核侧 cfg.groups 要给够，第 n 组得在这个范围里
  2. 用户态 nl_groups 对应位置 1，或者用 setsockopt 加组
  3. 内核侧调 netlink_broadcast(sk, skb, 0, group_mask, gfp)
c
/* 内核侧：链路状态变了，通知所有订阅 RTMGRP_LINK 的进程 */
struct sk_buff *skb = nlmsg_new(len, GFP_ATOMIC);
struct nlmsghdr *nlh;

nlh = nlmsg_put(skb, 0, 0, RTM_NEWLINK, len, 0);
/* ... 填属性 ... */

netlink_broadcast(rtnl, skb, 0, RTMGRP_LINK, GFP_ATOMIC);

portid 传 0 表示不限定接收者，group 是位掩码，位为 1 的组各收一份副本。整个流程是这样：

text
内核事件源              netlink 核心                  订阅者
驱动 / 协议栈  --skb-->  netlink_broadcast()  ------>  udev
                         按 groups 位图复制   ------>  NetworkManager
                         每个订阅者一份 skb   ------>  你的监控程序

用户态加入多播组两种方式：

c
/* 方式一：bind 时带上位图，一次到位 */
local.nl_groups = RTMGRP_LINK;
bind(fd, (struct sockaddr *)&local, sizeof(local));

/* 方式二：bind 之后动态加组，可以反复调 */
int grp = RTMGRP_LINK;
setsockopt(fd, SOL_NETLINK, NETLINK_ADD_MEMBERSHIP, &grp, sizeof(grp));
setsockopt(fd, SOL_NETLINK, NETLINK_DROP_MEMBERSHIP, &grp, sizeof(grp));

方式二适合「先跑起来，再按配置决定订阅什么」的场景，udev 走的就是动态加组。这里有个坑：bind 填的是位掩码，setsockopt 填的是组号，同一件事两套坐标系。NETLINK_ADD_MEMBERSHIP 的组号从 1 数起，第 1 组对应 nl_groups 的 bit 0。两个 1 含义不同，混用就是订阅到隔壁组，而且不会有任何报错。

rtnetlink 常用的组位图：

位掩码 宏 事件
0x1 RTMGRP_LINK 链路 up/down、接口增删
0x2 RTMGRP_NOTIFY 未分类通知
0x4 RTMGRP_NEIGH 邻居表变化，ARP 就在这
0x10 RTMGRP_IPV4_IFADDR IPv4 地址增删
0x20 RTMGRP_IPV4_MROUTE IPv4 组播路由
0x40 RTMGRP_IPV4_ROUTE IPv4 路由变化
0x100 RTMGRP_IPV6_IFADDR IPv6 地址增删
0x400 RTMGRP_IPV6_ROUTE IPv6 路由变化
0x800 RTMGRP_TC 流量控制
0x1000 RTMGRP_IPV4_RULE 策略路由规则

用户态的监听循环和单播一模一样，只是不用发请求：

c
for (;;) {
    int len = recv(fd, buf, sizeof(buf), 0);
    struct nlmsghdr *nlh;

    for (nlh = (struct nlmsghdr *)buf; NLMSG_OK(nlh, len); nlh = NLMSG_NEXT(nlh, len)) {
        if (nlh->nlmsg_type == NLMSG_DONE)
            break;
        handle_event(nlh);
    }
}

多播消息里的 nlmsg_seq 没有配对意义，会是 0，别拿它跟自己的请求序号对。要区分事件类型，只看 nlmsg_type。

NETLINK_KOBJECT_UEVENT 是个例外。它只有一个组（组 1），消息体不是 nlattr 属性串，而是一串 KEY=VALUE\0 拼接的字符串，开头是 add@/devices/... 这种动作加路径。拿 TLV 去解它只会解出一堆垃圾。见到协议号 15，换成字符串解析。

十、常见子系统用到的 Netlink #

协议号表在第二章列过，这里补上「谁在用」和「跑什么消息」，方便按工具反查。

子系统 协议号 用户态工具 典型消息
路由与链路 NETLINK_ROUTE (0) ip、NetworkManager RTM_NEWLINK、RTM_NEWADDR、RTM_NEWROUTE
socket 监控 NETLINK_SOCK_DIAG (4) ss SOCK_DIAG_BY_FAMILY
netfilter NETLINK_NETFILTER (12) nft、iptables-nft、conntrack NFNL_SUBSYS_*
IPsec NETLINK_XFRM (6) ip xfrm、strongSwan XFRM_MSG_NEWSA
内核事件 NETLINK_KOBJECT_UEVENT (15) udev、systemd-udevd add@/devices/...
通用 netlink NETLINK_GENERIC (16) wg、iw、ethtool、devlink 家族自定义命令
审计 NETLINK_AUDIT (9) auditd AUDIT_*
加密层 NETLINK_CRYPTO (21) cryptsetup 部分路径 CRYPTO_MSG_*
SCSI 传输 NETLINK_SCSITRANSPORT (18) iscsiadm 传输层事件
RDMA NETLINK_RDMA (20) rdma RDMA_NLDEV_CMD_*
用户自定义 NETLINK_USERSOCK (2) 各类守护进程 自定义

新子系统大都往 NETLINK_GENERIC 里挤，原因是它支持运行时发现，不用抢那 32 个协议号。用法是先问内核有哪些家族，再按家族发命令：

c
/* 第一步：查家族，确认内核支持 nl80211 */
nlh->nlmsg_type  = GENL_ID_CTRL;
nlh->nlmsg_flags = NLM_F_REQUEST;
genl->cmd        = CTRL_CMD_GETFAMILY;
nla_put_string(nlh, CTRL_ATTR_FAMILY_NAME, "nl80211");
/* 回包里能拿到家族 id、版本号、支持的 op 列表 */

/* 第二步：用拿到的家族 id 发真正想发的命令 */
nlh->nlmsg_type = family_id;
genl->cmd       = NL80211_CMD_GET_INTERFACE;

这条链解释了一件事：iw 是 nl80211 的 CLI 外壳，wg 是 wireguard 家族的外壳，新版 ethtool 走 ethtool 家族。看懂一个 genl 家族的消息序列，同类的都能照着读。

ss 那条线更直接。ss -tan 本质上是一条 SOCK_DIAG_BY_FAMILY 请求，带 inet_diag_req_v2 结构体描述要查的族、协议、状态；内核回一串 inet_diag_msg 加属性。netstat 读 /proc/net/tcp 要全量解析文本，ss 直接拿二进制，差距就在这儿。

十一、调试与抓包 #

netlink 是二进制，cat 不出来，得靠工具。四招够用。

nlmon 虚拟接口 #

内核有个 nlmon 模块，能建一个虚拟接口把 netlink 流量镜像进去，tcpdump 照常抓。这是直接看消息字节的路子。

bash
sudo modprobe nlmon
sudo ip link add nlmon0 type nlmon
sudo ip link set nlmon0 up
sudo tcpdump -i nlmon0 -v

tcpdump 认 netlink 的链路类型，能直接解出 nlmsg_type、nlmsg_len、nlmsg_flags。配合 -x 看十六进制，对齐问题一眼就露出来。

/proc/net/netlink #

bash
cat /proc/net/netlink

输出长这样：

text
sk               Eth Pid   Groups   Rmem Wmem Dump Locks Drops Inode
ffff8800a1b2c000 0   0     00000000 0    0    0    2     0     12345
ffff8800a1b2d800 15  1234  00000001 0    0    0    2     0     12346
ffff8800a1b2dc00 0   50    00000000 0    0    0    2     3     12347

第二列是协议号，Pid 是 portid，Groups 是多播组位图。Drops 那一列非 0，说明用户态收得慢，内核投不动了，消息已经丢。这条信息比任何日志都直接。

strace #

bash
strace -f -e trace=network ip link show 2>&1 | head -40

整个调用链一次看全：socket(AF_NETLINK, SOCK_RAW|SOCK_CLOEXEC, NETLINK_ROUTE)、bind、sendmsg、recvmsg，连每条消息的字节数都在。用户态发送的消息拼错了、长度算错了，这里先看出来。

内核侧 printk #

c
printk(KERN_DEBUG "nl len=%u type=%#x flags=%#x seq=%u\n",
       nlh->nlmsg_len, nlh->nlmsg_type, nlh->nlmsg_flags, nlh->nlmsg_seq);

dmesg -w 盯着。内核里挂不上调试器的时候，这是最快的定位手段。insmod 之后先看有没有 init netlink_demo!，再看 netlink demo init ok!，两行都在才说明注册成功。

十二、易错点速查 #

把踩过的坑按「现象 → 原因 → 解法」排一遍，排错时对着查。

现象 原因 解法
socket() 返回 EPROTONOSUPPORT 内核模块没加载，协议号没人注册 先 insmod，dmesg 确认注册
bind() 返回 EADDRINUSE 同协议号下 nl_pid 撞了 填 0 让内核分配，或换固定值
bind() 返回 EINVAL 长度参数传错 传 sizeof(struct sockaddr_nl)
sendto() 返回 ECONNREFUSED 目标 nl_pid 不存在 确认对端 bind 了、内核侧已 create
recv() 只拿到半条消息 缓冲区比消息小 8KB 起步，或用 MSG_PEEK 探长度
属性解析越界 nla_len 用了对齐后的值 nla_len 是真实长度，指针前进才用 NLA_ALIGN
第二条消息解出来是乱码 没走 NLMSG_NEXT() 循环到 NLMSG_OK() 为假为止
内核收到的消息被截断 nlmsg_len 填了 NLMSG_LENGTH 应该填 NLMSG_SPACE()
多播一条都收不到 cfg.groups 为 0，或位图位填错 内核侧给足组数，用户态按位查表
setsockopt 加组没效果 传了位掩码而不是组号 NETLINK_ADD_MEMBERSHIP 要组号
内核发送后立刻 panic 发送后自己又 kfree_skb netlink_unicast 已消费 skb
nlmsg_put() 失败后内存只涨不降 失败分支没释放 补 nlmsg_free(nl_skb)
卸载模块时崩 sock_release 传了 sock 传 netlinkfd->sk_socket
用户态 fd 还开着就卸载 sock 已释放，fd 悬空 加引用计数或拒绝卸载
3.10 上编不过老代码 netlink_kernel_create 还是六参数 改成 netlink_kernel_cfg 写法
拿 nlmsg_seq 配对多播失败 多播消息不保证序号 只看 nlmsg_type 和属性

再补两条不成表的心得。

第一条，对齐。整条消息按 4 对齐，每个属性也按 4 对齐，nla_len 不含填充但指针前进要跳过填充。这条错了，后面所有属性全歪，而且不报错，只是数据看着不对。

第二条，生命周期与时序。nlmsg_new 出来的 skb，要么交给 netlink_unicast / netlink_broadcast，要么自己 nlmsg_free，没有第三条路。netlink_kernel_create 出来的 sock，卸载时用 sock_release(sk->sk_socket) 释放，别把两种指针搞混。顺序也一样卡死：内核模块先加载，用户态才建得出套接字；用户态先 bind 到固定 nl_pid，内核才投得进去。反了就是失败，而且报错信息不指向真正的原因。

到这里，从 sockaddr_nl 的四个字段，到 nlmsghdr 加 nlattr 的两层结构，再到用户态的 socket/bind/send/recv 与内核态的 netlink_kernel_create/input 回调，整条链路的每一段都对上了。下次 strace 看到 socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE)，你知道后面跟着的是哪一段内存布局。
