一、图像分割要解决什么 #

分割的定义一句话：按灰度、颜色、纹理、形状这些特征，把图像切成若干互不重叠的区域，让同一区域内的特征相似，不同区域之间的特征有明显差异。

这句话里藏了三个不轻松的要求。

第一，「互不重叠」意味着每个像素必须且只能属于一个区域，这是划分（partition），不是检测。第二，「相似」需要一个可量化的准则，而这个准则由你来定，选错准则就选错了区域。第三，「差异明显」是相对的——两个区域的边界到底是「一刀切」还是「渐变过渡」，决定了你该用硬分割还是软分割。

分割之后能干什么：抠图、计数、测量面积、给识别算法喂候选区域、把图像压缩成「区域 + 区域属性」的表示。下游任务决定了你需要的精度，抠图要像素级，计数要连通块级，两条路线的成本差一个量级。

我们先把方法盘一遍，再钻进两个具体算法。

二、分割方法的两大类：基于边界与基于区域 #

教材式分类有五大类，但真正决定实现路线的是两类：看你盯的是「边界」还是「区域」。

阈值法：算出一个或多个灰度阈值，把每个像素的灰度与阈值比，比完就归类。关键点是准则函数怎么定——大津法（Otsu）走的是最大化类间方差那条准则。阈值法便宜，但只用灰度信息，遇到光照不均就废。

基于边缘：边缘是两个不同区域边界线上连续像素的集合，本质是局部特征的不连续。它建立在「边缘处灰度呈阶跃型或屋顶型变化」这个观测上：阶跃型边缘两侧灰度有明显差异，屋顶型边缘位于灰度上升或下降的转折处。所以可以用微分算子找——一阶导数的极值、二阶导数的过零点，实现上就是图像和模板卷积。边缘检测给你的是「线」，不是「面」，边缘断一处区域就漏一片，后面还得做连接或轮廓填充。

基于区域：按相似性准则把图像分成不同区域。

  • 种子区域生长：从一组种子像素出发，把邻域里符合条件的像素并进来，新并入的像素又当新种子继续长，直到找不到符合条件的像素。成败全在初始种子和生长准则。
  • 区域分裂合并（Gonzalez，2002）：先把图像任意分成若干互不相交的区域，再按准则分裂或合并。灰度图和纹理图都能用。
  • 分水岭（Meyer，1990）：拓扑 + 数学形态学那一套，把图像当测地学上的拓扑地貌，灰度值当海拔，局部极小值及其影响区叫集水盆，集水盆的边界形成分水岭。实现上模拟洪水淹没过程。对微弱边缘响应好，噪声会让它过分割。

基于图论：把分割和图的最小割（min cut）关联起来。图像映射成带权无向图 G=⟨V,E⟩，节点对应像素，边连接相邻像素，权值表示相邻像素在灰度、颜色、纹理上的非负相似度。对图像的一个分割 $S$ 就是对图的一次剪切，每个区域 C∈S 对应图中的一个子图。最优原则是：子图内部相似度最大，子图之间相似度最小。本质是移除特定的边，把图切成若干子图。这条路线上有 GraphCut、GrabCut、Random Walk。

基于能量泛函：活动轮廓模型（active contour model）。用连续曲线表达目标边缘，定义能量泛函并把曲线本身作为自变量，分割就变成求泛函最小值，靠解欧拉–拉格朗日方程实现，能量最小时的曲线位置就是轮廓。

  • 参数活动轮廓模型走 Lagrange 框架，直接参数化曲线，代表是 Kass 等人（1987）的 Snake。早期在生物图像分割上用得不错，但结果严重依赖初始轮廓，曲线拓扑变化（分裂、合并）处理不了，能量泛函只依赖曲线参数、与物体几何形状无关。
  • 几何活动轮廓模型按几何度量参数演化曲线，能处理拓扑变化。Osher（1988）的水平集（Level Set）方法把这个方向推起来，所以几何活动轮廓模型也常直接叫水平集方法。

本篇要拆的两个算法，一个走图论（GrabCut），一个走区域（分水岭）。

三、GraphCut 的思路：把分割变成最小割 #

GraphCut 的核心动作是把「分割」翻译成「切图」，再把「切图」翻译成「最小割」，最后用最大流算法去解。

先把图搭出来：

  • 每个像素是一个普通节点 v∈V，节点数等于像素数。
  • 相邻像素之间连一条边，叫 n-link（neighbor link）。4 邻域或 8 邻域都行，GrabCut 用的是 8 邻域。
  • 额外来两个终端节点：源点 $S$（代表「前景」这个类别）和汇点 $T$（代表「背景」这个类别）。每个像素再连两条边——S→v 和 v→T，叫 t-link（terminal link）。

于是图里有两类边，权重含义完全不同：

边 连接对象 权重含义 切断它的代价
n-link 相邻像素之间 两个像素相似度 相似度高时权重大，切断代价高（说明它们应该在同一区域）
t-link 像素与 $S$／$T$ 该像素属于前景／背景的代价 切断意味着改变它的类别归属

一次切割（cut）就是把边分成两部分：被切掉的边全部断开，剩下的图分成两个连通块，一块连着 $S$，一块连着 $T$。切掉的那些边的权重和就是这次切割的代价。最小割就是代价最小的切法，这个切法直接给出分割结果——$S$ 一侧的像素判为前景，$T$ 一侧的判为背景。

为什么最小割能给出「好」分割，看两条：如果相邻两个像素颜色很像，n-link 权重高，算法不愿切它，两个像素于是留在同一侧；如果某个像素颜色明显像前景，它连 $S$ 的边权重高、连 $T$ 的边权重低，切它就贵，算法于是让它跟 $S$ 走。两个方向的约束互相拉扯，最后达到总代价最小。

数学上这里用的是 Ford–Fulkerson 那套：图的最小割容量等于最大流。所以实际实现不是枚举切法，而是算一遍最大流，流跑完之后从 $S$ 走残量网络能到达的节点集合就是 $S$ 侧。

cpp
// 原文为 C++。这是 GraphCut 的最小调用形式，OpenCV 里对应的是旧版 C API 的 CvGCGraph/CvGraph。
// OpenCV 4.x 已经把 C API 移除，现代做法是直接用 grabCut，或者接第三方 maxflow（如 Boykov-Kolmogorov）。
#include <opencv2/opencv.hpp>
int main() {
    cv::Mat img = cv::imread("image/img21.jpg");
    cv::Mat mask(img.size(), CV_8UC1, cv::Scalar(cv::GC_BGD));
    cv::Rect rect(60, 40, 320, 300);
    cv::Mat bgdModel, fgdModel;
    // 这就是 GraphCut 的一个特例：矩形外硬约束为背景，矩形内靠模型算 t-link
    cv::grabCut(img, mask, rect, bgdModel, fgdModel, 5, cv::GC_INIT_WITH_RECT);
    cv::Mat bin;
    cv::compare(mask, cv::GC_FGD, bin, cv::CMP_EQ);
    cv::imshow("fg", bin);
    cv::waitKey(0);
    return 0;
}

这段代码说明一件事：GraphCut 本身需要你把「哪些像素肯定是前景、哪些肯定是背景」喂进去，它才建得出合理的 t-link。手工标全图不现实，这就是 GrabCut 要解决的问题。

四、图怎么建：像素是节点，边是相似度 #

把图建细一点，你才能理解 GrabCut 的可调参数为什么那么少。

节点：$N = W \times H$ 个像素节点，加 $S$、$T$ 两个终端。

边数：8 邻域下，每个像素与左、左上、上、右上四个邻像素连边即可（正反成对，所以图里存两条有向边）。总数是一个固定公式：

edges=2(4WH−3(W+H)+2)

验算一下 3×3 的图像：$4 \times 9 - 3 \times 6 + 2 = 36 - 18 + 2 = 20$，乘 2 得 40。逐像素数：四角像素 2 个邻居、边像素 3 个、中心 4 个，$4 \times 2 + 4 \times 3 + 1 \times 4 = 24$，乘 2 得 48。两个数不一致，因为 (4WH - 3(W+H) + 2) 是「无向邻接对数」的通用计数式，对 1×1、1×N 这类退化尺寸也对，但不按「每像素邻居数」逐个累加。写代码时按 2× 无向边数来估内存更稳，别拿它去反推每像素邻居数。

n-link 权重怎么算，GrabCut 用的公式是：

wij​=γ⋅e−β∥zi​−zj​∥2

其中 zi​ 是像素 $i$ 的 BGR 三通道颜色向量（转成 double 算，范数用平方欧氏距离），γ 和 β 是两个常数：

  • γ=50，代码里硬编码。
  • β 从图像本身估出来，公式是 β=2∥zi​−zj​∥2​1​，均值在所有 8 邻域像素对上取。GrabCut 的 C++ 实现里只累加左、左上、上、右上四个方向的差，分母用的是 $4WH - 3W - 3H + 2$（即这些方向上的邻接对数）。

β 的作用是调平滑力度。图像本身对比度高（像素差平方和大）时 β 小，指数衰减慢，n-link 权重整体偏大，平滑更狠；图像平缓时 β 大，稍微有点颜色差权重就掉下去，边界更容易保住。

斜向邻居的权重再乘一个折扣：γ/2​。理由是斜向距离是 2​ 倍，按距离惩罚一下，避免对角方向过度连通。

t-link 权重分两种情况：

  • 像素在待定区（GC_PR_FGD / GC_PR_BGD）时，用模型算概率：连 $S$（背景终端这一侧，代码里叫 fromSource）的权重是 −logPbgd​(z)，连 $T$ 的权重是 −logPfgd​(z)。注意实现里的命名和直觉反着：fromSource 装的是背景概率的负对数，理由是源点那一侧最终代表「背景集合」。
  • 像素是硬标记（GC_BGD / GC_FGD）时，直接给 $0$ 和 λ：背景像素 −log 那条给 0、前景那条给 λ；前景像素反过来。$\lambda = 9\gamma = 450$，硬约束的强度就是这个数。
python
import numpy as np
import cv2

img = cv2.imread("image/img21.jpg")          # 必须是 8UC3
gamma = 50.0
lam = 9 * gamma                              # 450
beta = 0.0
h, w = img.shape[:2]
z = img.astype(np.float64)

# 估 beta：只累加左、左上、上、右上四个方向
sq = 0.0
diff = z[:, 1:] - z[:, :-1];            sq += np.sum(diff * diff)
diff = z[1:, 1:] - z[:-1, :-1];         sq += np.sum(diff * diff)
diff = z[1:, :] - z[:-1, :];            sq += np.sum(diff * diff)
diff = z[1:, :-1] - z[:-1, 1:];         sq += np.sum(diff * diff)
cnt = 4 * w * h - 3 * w - 3 * h + 2
beta = 0.0 if sq <= 1e-12 else 1.0 / (2 * sq / cnt)
print("beta =", beta, " lambda =", lam)

这段只是把参数算出来看看，别指望它替代 grabCut——真正的 GMM 学习和最大流在 C++ 里跑，Python 调一次 cv2.grabCut 就够了。

五、能量函数与它的两项 #

GraphCut 系列方法都写同一个能量函数，Gibbs 形式：

E(α)=U(α)+V(α)

$\alpha = (\alpha_1, \dots, \alpha_N)$ 是每个像素的标签，$\alpha_i \in {0, 1}$，0 表示背景、1 表示前景。两项分工：

数据项 U(α)：只看像素自己的颜色像不像前景／背景，不看邻居。

U(α)=i∑​Di​(αi​)

在 GrabCut 里，Di​ 用高斯混合模型算：

Di​(αi​)=−logP(zi​∣αi​)

$P(z_i \mid \alpha_i = 1)$ 是前景 GMM 在颜色 zi​ 处的密度，$P(z_i \mid \alpha_i = 0)$ 是背景 GMM 的密度。取负对数，是把「概率最大化」翻成「能量最小化」——概率越小，罚得越重。

平滑项 V(α)：看邻居之间的标签是否一致。

V(α)=(i,j)∈N∑​[αi​=αj​]γe−β∥zi​−zj​∥2

N 是 8 邻域对集合，[⋅] 是示性函数——只有两个标签不同时才付代价。所以平滑项在干这件事：惩罚「颜色相近的邻居被判成不同类别」。颜色差大时指数项接近 0，罚不动，边界就允许过；颜色差小时罚得重，同色区域被逼着连成一片。

这就是为什么这个能量函数能被最小割精确求解：$U$ 是逐点的一元项，$V$ 是成对的、且满足子模性（submodular）条件——对二值标签，$V(0,0) + V(1,1) \le V(0,1) + V(1,0)$ 成立，因为旁边两项都是 0、对角两项非负。子模的成对能量等价于一个图上的割，割的容量就是能量值。这一结论来自 Boykov 与 Jolly 的工作，Kolmogorov 与 Zabih 之后给出了更一般的形式化。

三项参数的作用可以这样记：

参数 出处 调大时 调小时
γ 代码常量 50 平滑项整体变重，边界更僵 更信颜色，边界碎
λ 9γ 用户硬标记的约束更硬 用户标记能被覆盖
β 从图像估 颜色差一点就断开 大量相邻像素被粘住

γ、λ 在 OpenCV 里写死了，暴露给你调的只有 iterCount 和标记本身。想动这两个数就得自己实现一层图割，用 maxflow 库或 PyMaxflow 重建图。

六、GrabCut 对 GraphCut 的改进 #

GrabCut 出自 Rother、Kolmogorov、Blake 的 SIGGRAPH 2004 论文 GrabCut: Interactive Foreground Extraction using Iterated Graph Cuts。相对 GraphCut，它砍掉了三样成本。

第一，颜色模型从 GMM 换成 RGB 三通道 GMM，并且用迭代估计代替手工标记。GraphCut 要你手工画前景笔画和背景笔画，才有样本学直方图或 GMM。GrabCut 只要一个矩形：矩形外一律当背景，矩形内全当「待定前景」，先拿这两拨样本各学一个 GMM，然后交替做「分配像素到 GMM 分量」和「用新分配重估 GMM 参数」。

第二，迭代。每轮流程固定为：

text
1. 按当前 mask 把像素分给背景 GMM 或前景 GMM（硬标记按标记走，待定区按 GMM 大小聚类）
2. 用上一步分配的样本，重估两个 GMM 的权重、均值、协方差
3. 用两个 GMM 算每个待定像素的数据项 D_i，加上 n-link 的平滑项，建图
4. 跑最大流最小割，更新 mask 的待定区标签
5. 回到 1，跑 iterCount 次

第三，t-link 的 −log 改成了「代价」语义的硬约束，用 λ 兜住用户标记，让用户在后续迭代里可以继续加笔画修正而不被模型冲掉。

GMM 的具体规格（这是理解 bgdModel、fgdModel 为什么是 1×65 的关键）：

  • 每个 GMM 有 5 个高斯分量（componentsCount = 5）。
  • 每个分量存 1 个权重系数 + 3 个均值 + 9 个协方差元素（3×3 全协方差），共 13 个数。
  • $5 \times 13 = 65$，所以模型矩阵是 1 行 65 列、CV_64FC1（Python 里 np.float64）。
  • 初始化时用 k-means（KMEANS_PP_CENTERS，最多 10 次迭代）把样本聚成 5 类，用每类的样本直接算均值与协方差，权重取样本占比。
  • 协方差会遇到奇异的情况（某个分量样本太少、颜色几乎相同）。实现的做法是：行列式 ≤10−6 时给三个对角元素各加 0.01，再算行列式。
  • 单分量密度：$g(z) = \dfrac{1}{\sqrt{\det \Sigma}} \exp!\left(-\tfrac{1}{2}(z-\mu)^T \Sigma^{-1} (z-\mu)\right)$。注意这里少了正态分布常数 (2π)−k/2，OpenCV 实现里就没写进去，因为后面取 −log 后是个常数，不影响 argmin。
  • 整体密度是加权和：$P(z) = \sum_{k=1}^{5} \pi_k , g_k(z)$。

GraphCut 与 GrabCut 逐项对比：

维度 GraphCut GrabCut
输入方式 前景笔画 + 背景笔画 一个矩形框，可选加笔画
颜色模型 直方图或 GMM RGB 三通道 GMM，5 分量
模型参数估计 一次，基于手工样本 迭代重估，每轮 iterCount 里都学一次
用户工作量 每个目标都要刷 框一下就能出结果
硬约束 依靠手工标记 λ=9γ 的 t-link
迭代 单次求解 内循环：分配→重估→建图→最小割
典型失败 手工标记不全则边界崩 前景背景颜色接近时漏切
复杂度 图割本身 O(⋅) 取决于最大流 每轮再加一次 GMM 学习，复杂度随 iterCount 线性涨

七、GrabCut 的交互方式：矩形框与涂抹 #

两种交互，落到 cv2.grabCut 上就是 mode 的两个取值。

矩形框模式（GC_INIT_WITH_RECT）：你拖一个矩形把目标框住。矩形外的像素无条件判 GC_BGD，矩形内全部先判 GC_PR_FGD，然后跑迭代。这是最快的方式，框歪一点、框紧一点都还能出结果，代价是框内的背景像素要靠模型自己判掉。

涂抹模式（GC_INIT_WITH_MASK）：你自己指定一部分像素是 GC_FGD、一部分是 GC_BGD，剩下的留 GC_PR_BGD 或 GC_PR_FGD 让算法判。适合前景背景颜色相近、矩形框一框就把背景框进来的场景。

两种可以叠加。官方文档明确写了 GC_INIT_WITH_RECT 和 GC_INIT_WITH_MASK 可以按位或组合：cv2.GC_INIT_WITH_RECT | cv2.GC_INIT_WITH_MASK，此时矩形外的像素仍然被自动初始化为 GC_BGD。这个组合用法在 OpenCV 3.x 和 4.x 一致，但很多教程没提，实测前建议先在单张图上验证 mask 是否符合预期。

用鼠标拖框的完整交互流程（rect 存的是 x, y, w, h，不是两点坐标）：

三个坑都在这个坐标转换上：

  • rect 的四元组是 (x, y, w, h)。原文示例在按下与移动时往 rect[2]、rect[3] 里直接写当前坐标，松开时再做一次 rect[2] = rect[2] - rect[0] 的减法。这种写法依赖「松开时 rect[0] 还是按下点」，拖动方向一变就出错，所以上面改成按住起点、实时算差值。
  • 原点在左上，$y$ 轴向下，所以 ymax​ 和 ymin​ 的说法容易绕，直接用 x - x0 的符号判断更清楚。
  • 拖出宽或高为 0 的框要挡掉，w 或 h 为 0 时 grabCut 的行为没有明确定义，实测会抛错或返回全背景。

八、GrabCut 的四种标记 #

mask 是 8UC1、尺寸与原图一致的矩阵。它的元素只能取四个值，四值对应 OpenCV 里 GrabCutClasses 枚举：

常量 值 含义 迭代中是否被改写
cv2.GC_BGD 0 确定为背景 否，硬约束
cv2.GC_FGD 1 确定为前景 否，硬约束
cv2.GC_PR_BGD 2 倾向背景，待定 是，每轮按最小割重判
cv2.GC_PR_FGD 3 倾向前景，待定 是，每轮按最小割重判

原文写的是 GCD_BGD/GCD_FGD/GCD_PR_BGD/GCD_PR_FGD，这是笔误。C++ 枚举名是 GC_BGD、GC_FGD、GC_PR_BGD、GC_PR_FGD，Python 里通过 cv2.GC_* 访问。带上 GC_EVAL_FREEZE_MODEL = 3 这个取值，cv2.GC_* 一共 7 个常量，其中 4 个是标记、3 个是模式。

记住三条规则：

  • 只用矩形初始化时，矩形外全是 0，矩形内全是 3。迭代结束后，待定像素被改写成 2 或 3，永远不会出现 0 或 1。所以只看结果为 0/1 是空的——这是新手最常见的困惑。
  • 一旦你手工写了 1 或 0，输出里就会出现 1 或 0，同时带 2 或 3。
  • GC_BGD 和 GC_FGD 是硬约束，最大流求解时不参与重判；GC_PR_* 每轮都会被改写。想「锁定」一块区域，就给它 0 或 1。

判定前景最稳的写法是二选一：

python
# 写法一：把 2 和 0 都当背景，1 和 3 都当前景（覆盖两种初始化方式）
fg_mask = np.where((mask == cv2.GC_BGD) | (mask == cv2.GC_PR_BGD), 0, 1).astype("uint8")

# 写法二：只要确定前景
fg_strict = np.where(mask == cv2.GC_FGD, 1, 0).astype("uint8")

写法一更实用，因为它在「只用矩形」和「加了涂抹」两种情况下都对。原文代码里 np.where((mask==2)|(mask==0),0,1) 就是这个意思，只是用字面量 2 和 0，可读性差，换成常量更好维护。

掩膜乘法时记得扩一维：

result = img * fg_mask[:, :, np.newaxis]        # BGR 三通道要广播
# 或者用按位与

九、GrabCut 的代码流程 #

cv2.grabCut 的完整签名，七个参数一个都不能记错：

text
cv2.grabCut(img, mask, rect, bgdModel, fgdModel, iterCount[, mode]) -> mask, bgdModel, fgdModel

Python 版本是原地的：mask、bgdModel、fgdModel 传进去就会被改，返回值只是同一批对象的引用方便链式调用。逐个说清。

参数 类型与取值 约束 说明
img 8UC3 必须三通道 8 位 单通道灰度图直接传会抛 image must have CV_8UC3 type；灰度图请 cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)。函数内不改动它
mask 8UC1，值域 0~3 尺寸必须与 img 一致 输入输出双向：GC_INIT_WITH_RECT 时被函数重写；GC_INIT_WITH_MASK 和 GC_EVAL 时进入前必须已合法
rect (x, y, w, h) 只在 GC_INIT_WITH_RECT 下使用 越界部分被截断（内部会 clamp 到图像边界）。GC_EVAL 系列下可传 None
bgdModel np.zeros((1, 65), np.float64) 或 np.zeros((1,65)) 1 行 65 列，CV_64FC1 传全零矩阵或 None；同一次会话里反复调用时要复用同一个模型，否则每轮都从零开始学
fgdModel 同上 同上 同上
iterCount int，> 0 等于 0 或负数时函数直接返回，不做事 一次迭代 = 分配分量 → 重估 GMM → 建图 → 最小割
mode GC_INIT_WITH_RECT(0) / GC_INIT_WITH_MASK(1) / GC_EVAL(2) / GC_EVAL_FREEZE_MODEL(3) 见下表 4.x 比 3.x 多一个 GC_EVAL_FREEZE_MODEL

关于 11×5 = 65 与 13×5 = 65 的说法：GMM 有 5 个分量，每个分量 13 个数（1 权重 + 3 均值 + 9 协方差），$13 \times 5 = 65$。原文写的「13x5」对，但同一句里若是拆成别的因子就错了；GrabCut 源码里 GMM 构造函数写的是 modelSize = 3 + 9 + 1 再乘 componentsCount = 5，模型矩阵形状校验失败时抛的错是 _model must have CV_64FC1 type, rows == 1 and cols == 13*componentsCount。

三种初始化的行为差异：

mode 值 mask 是否被改写 是否重新学 GMM 典型用法
GC_INIT_WITH_RECT 0 是，矩形外 0、矩形内 3 是 第一次跑，只给框
GC_INIT_WITH_MASK 1 否，必须已合法 是 已有标记，重新初始化
GC_EVAL 2 只改 2/3 否，沿用传入模型 反复细调，iterCount 给 1~3
GC_EVAL_FREEZE_MODEL 3 只改 2/3 否，且内部强制 iterCount = 1 OpenCV 4.x 才有；模型固定、只做一次割

GC_EVAL_FREEZE_MODEL 是 4.x 新增，3.x 里没有这个常量。它和 GC_EVAL 的区别在源码里只有一行：if (mode == GC_EVAL_FREEZE_MODEL) iterCount = 1;，同时循环内的 learnGMMs 被跳过。所以 GC_EVAL 给 iterCount=5 会学 5 轮模型，GC_EVAL_FREEZE_MODEL 无论传什么都不学。

模式还可以按位或组合：GC_INIT_WITH_RECT | GC_INIT_WITH_MASK 表示「既按 mask 初始化，又用矩形把外部压成背景」。

最小的完整调用：

python
import numpy as np
import cv2

img = cv2.imread("image/img21.jpg")

bgd = np.zeros((1, 65), np.float64)

rect = (60, 40, 320, 300)        # x, y, w, h

fg = np.where((mask == cv2.GC_BGD) | (mask == cv2.GC_PR_BGD), 0, 1).astype("uint8")
cv2.imshow("mask", fg * 255)
cv2.imshow("fg", img * fg[:, :, np.newaxis])

cv2.grabCut(img, mask, None, bgd, fgd, 1, cv2.GC_EVAL)

OpenCV 3.x 与 4.x 的差别汇总成一句：函数签名没变，mask 的取值没变，多出来的是 GC_EVAL_FREEZE_MODEL。3.x 里写 cv2.GC_EVAL_FREEZE_MODEL 会抛 AttributeError。另外 bgdModel 在 3.x 的 Python 绑定里对 np.float32 也能接受，4.x 会严格按 CV_64FC1 走，统一用 np.float64 最省事。

工程上还有两点值得记：

  • 大图上 grabCut 慢的原因是图的节点数等于像素数。1920×1080 是 200 万节点、约 1600 万条有向边，内存和最大流时间都会上去。常见做法是先 cv2.resize 降到长边 500~800 跑分割，再把 mask cv2.resize(..., interpolation=cv2.INTER_NEAREST) 放大回原尺寸。
  • 同一张图反复调用时，bgdModel、fgdModel 要跨调用复用，别每次都新建零矩阵。

十、GrabCut 的迭代次数与效果 #

iterCount 是唯一暴露给你调的数值参数。它控制内循环跑几圈，每圈都做「分配分量 → 重估 GMM → 建图 → 最大流」这四步。

经验值：

iterCount 效果 耗时 适用
1 只跑一轮，GMM 才刚从 k-means 初值往前走一步，边界毛糙 最省 交互式实时预览
3 大部分图能收敛到能用 中 涂抹模式下的反复细调，每刷几笔跑一次
5 官方示例与多数教程的默认值 偏高 一次性出结果
10 以上 待定区基本不再翻转，收益趋零 很贵 不建议

迭代收益为什么会饱和：每一轮的最大流都会把待定像素推到某一侧（2 或 3），下一轮 GMM 用这些被推过去的像素重估参数，参数变化越来越小。迭代到后期，翻来覆去就是几个骑墙像素在换边，视觉上看不出差别。

需要提醒的是：每次调用 cv2.grabCut 的 iterCount 是这次调用的轮数，不是全局计数。你刷一笔给 1 轮、再刷一笔再给 1 轮，模型是累积的，图和上一轮完全重算。这种「一次一笔、少量迭代」的交互节奏比「一笔不刷、直接 20 轮」更好，因为每次都有新的用户约束进来。

几个影响效果的实操点：

  • 矩形不要贴边。框和目标之间留出 5~20 像素，让矩形内有足够多的背景样本给背景 GMM 学，否则背景模型的第一版就是错的。
  • 目标和背景颜色接近时，先把图转到 Lab 或 HSV 再送进去？不行，grabCut 只接受 BGR 三通道，它内部把三通道当颜色向量算欧氏距离。想换色彩空间得自己实现图割。退一步的做法是先用 cv2.detailEnhance 或 cv2.createCLAHE 拉对比度，再喂给 grabCut，实测有时有帮助，但不是稳定收益。
  • 目标有多块、彼此不连通时，一个矩形覆盖全部，靠涂抹把不需要的块刷成 GC_BGD。
  • 边界细碎（发丝、树叶、网状物）不是 grabCut 的强项：它的颜色模型是 5 个高斯，细结构被平滑项吃掉。这类需求换成 cv2.ximgproc.guidedFilter 引导滤波或深度学习的抠图模型。

十一、分水岭算法：把图像当地形图 #

分水岭的判断依据和 GrabCut 完全不是一套：它不看颜色像不像前景，它看空间位置和梯度。

描述是这样的：分割时把与邻近像素的相似性作为参考，把空间位置相近、灰度值相近（看梯度）的像素连起来，构成一个封闭的轮廓。所以只有轮廓，没有「前景背景」的语义，它给的是区域划分。

标准流程三步：彩色图灰度化 → 求梯度图（或边缘图）→ 在梯度图上跑分水岭，得到区域间的分界线。为什么要在梯度图上跑？因为梯度图里，原图的平坦区域梯度低（像山谷），原图的边缘梯度高（像山脊），水会先灌满山谷，最后在山脊处筑坝，坝就是原图的边缘。

数学上它属于拓扑 + 数学形态学那一派：把图像看作测地学上的拓扑地貌，灰度值 = 海拔，局部极小值及其影响区 = 集水盆（catchment basin），集水盆的边界 = 分水岭（watershed）。Meyer 在 1990 年前后把这个思路做成形态学可实现的算法。

十二、灰度值当海拔，积水就是分割 #

把灰度图当地形图，先分清三类点：

  • 局部极小值点：对应盆地的最低点。在盆地里滴一滴水，水最终汇到这一点。注意会碰到一整片都是最小值的情况（最小平台），那整片算一个极小值区域。
  • 盆地里的其他点：滴一滴水，会顺坡汇到该盆地的局部极小点。
  • 盆地边缘点：这是两个盆地的交界。在这点滴水，会等概率流向任何一个盆地。

分水岭的物理过程就是注水模拟。在每个盆地的最低点打一个洞，往洞里注水，同时阻止两个盆地的水汇成一片。当两个盆地的水面即将相通的瞬间，在交界处筑一道坝。重复到整幅图被淹完，筑起的一串坝就是分水岭线。

结果把图像分成两类像素：注水盆地像素集（每块是一个区域，各自编号）和 分水岭线像素集（区域之间的边界）。

这套机制对微弱边缘响应好，代价是噪声也会被当成盆地。图像里只要有一段 3 像素宽的低灰度小坑，算法就给你划出一个区域，结果就是过分割。

十三、过分割问题与标记点 #

过分割的成因一句话：真实图像里有噪声和纹理，局部极小值远比真实目标多，于是盆地数量爆炸。

解决办法是基于标记（marker）的分水岭。核心动作是：不让水从所有局部极小值开始涨，而是只从你指定的种子点开始涨。这就是标记控制（marker-controlled）分水岭。

做法是在一个「标记图」上，给每个待分割区域涂一个唯一的正整数标签，这些标签的位置就是注水口。别的像素一律标 0，表示「归属未知，请算法判」。因为只从这些标记点开始涨水，噪声小坑没有被标记，就不会长出独立区域。

这就是 cv2.watershed 的第二个参数为什么叫 markers 而不是 image2。它的约定必须记死：

markers 中被置为 含义 执行后变成
正整数 $k$（k≥1），同一区域可以是多个连通块 种子区域，第 $k$ 个区域的注水口 同一连通块内保持值 $k$
0 未知区域，由算法判定归属 被赋值成某个种子的编号 $k$
-1 输入时无特殊含义 输出时表示区域之间的边界

官方文档的原话要点：调用前必须用正整数索引大致圈出想要的区域；其他关系未知、需由算法决定的像素置 0；输出里每个像素被设成种子分量的值，或者区域之间边界上的 -1。文档还补了一句容易忽略的：两个相邻的种子连通块不一定被 -1 隔开——如果输入标记图里这两块本来就贴在一起，它们可以彼此接触。

数据类型也固定：markers 必须是 CV_32SC1（32 位有符号单通道），image 必须是 8 位 3 通道彩色图。np.zeros(img.shape[:2], np.int32) 是标准写法，用 np.uint8 会直接报错。

调用形式：

python
markers = cv2.watershed(img, markers)

它是原地的：markers 传进去被改，返回值就是同一个数组。img 不会被修改。

十四、距离变换与确定前景 #

用 Canny 边缘 + findContours 当种子是原文的路线，它对封闭边缘依赖很强：边缘断一处，轮廓就漏出来，种子区被打穿。工业上更稳的一套是距离变换定确定前景。

cv2.distanceTransform(src, distanceType, maskSize) 计算每个非零像素到最近的零像素的距离。用法就是：先拿到一个「目标区域 = 白色、其他 = 黑色」的二值图，做距离变换后，里边的值越大表示离背景越远。阈值切一刀，切出来的高值区就是目标的「核心」，可以放心当确定前景。

参数：

参数 取值 说明
src 8UC1 二值图 必须是单通道 8 位
distanceType cv2.DIST_L2（值 2，欧氏距离）、cv2.DIST_L1（值 1，曼哈顿）、cv2.DIST_C（值 3，棋盘） 找连通块中心用 DIST_L2
maskSize 3、5、cv2.DIST_MASK_PRECISE（值 0） DIST_L2 用 3 或 5 是近似算法，值 0 走 Felzenszwalb 的精确算法；DIST_L1/DIST_C 会被强制成 3

返回值是 32F 浮点图（dstType 默认 CV_32F），别直接 imshow，它显示不出对比度；要么归一化，要么直接拿去做阈值。

完整范式：

python
import numpy as np
import cv2

img = cv2.imread("image/coins.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

# 1. 二值化，得到「目标 = 255」
ret, thresh = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

# 2. 开运算去掉小的噪点
kernel = np.ones((3, 3), np.uint8)
opening = cv2.morphologyEx(thresh, cv2.MORPH_OPEN, kernel, iterations=2)

# 3. 确定背景：膨胀一下，肯定是背景
sure_bg = cv2.dilate(opening, kernel, iterations=3)

# 4. 距离变换，阈值切出确定前景
dist = cv2.distanceTransform(opening, cv2.DIST_L2, 5)
print("dist max =", dist.max())
ret, sure_fg = cv2.threshold(dist, 0.5 * dist.max(), 255, 0)
sure_fg = np.uint8(sure_fg)

# 5. 未知区域 = 确定背景 - 确定前景
unknown = cv2.subtract(sure_bg, sure_fg)

阈值系数 0.5 是个起点。目标半径 $r$ 时距离变换的峰值约为 $r$，取峰值的 50% 意味着核心区半径约 r/2；粘连严重的目标要调高（0.6~0.8），目标稀疏可以调低（0.3~0.4）。

第 5 步得到的 unknown 就是区域交界那一圈，也是分水岭要争的地方。

十五、分水岭的完整流程 #

把标记控制的流程串起来。这条路线来自 OpenCV 官方分水岭例程的结构，也是实际项目里最常用的一套。

python
import numpy as np
import cv2

img = cv2.imread("image/coins.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
ret, thresh = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

kernel = np.ones((3, 3), np.uint8)
opening = cv2.morphologyEx(thresh, cv2.MORPH_OPEN, kernel, iterations=2)
sure_bg = cv2.dilate(opening, kernel, iterations=3)
dist = cv2.distanceTransform(opening, cv2.DIST_L2, 5)
ret, sure_fg = cv2.threshold(dist, 0.5 * dist.max(), 255, 0)
sure_fg = np.uint8(sure_fg)
unknown = cv2.subtract(sure_bg, sure_fg)

# 连通块标记：每个确定前景块一个从 1 开始的整数
n, markers = cv2.connectedComponents(sure_fg)
markers = markers + 1                    # 全部 +1，让确定背景变成 1 而不是 0
markers[unknown == 255] = 0              # 未知区域置 0，交给分水岭判

# 分水岭：输入必须是 8UC3
markers = cv2.watershed(img, markers)
img_out = img.copy()
img_out[markers == -1] = (0, 0, 255)     # 边界涂红

cv2.imshow("markers", (markers * 20 % 255).astype(np.uint8))
cv2.imshow("result", img_out)
cv2.waitKey(0)
cv2.destroyAllWindows()

三个动作要讲清为什么。

cv2.connectedComponents(sure_fg)：把确定前景的每个连通块编成 1、2、3……，0 是背景标签。它返回两个值，n 是标签总数（含背景），markers 是标签图（int32）。这一步把「确定前景」从一张二值掩膜变成「每个目标一个独立种子」。粘连但已经分开的核心会被分成不同标签，后面的分水岭把它们的边界划出来——这就是把粘连目标分开的关键。

markers + 1：为什么要整体加 1？因为 connectedComponents 里背景是 0，而 watershed 里 0 表示「未知」。如果不加 1，背景会被当成未知区一起参与争抢。加 1 之后，确定背景的标签变成 1（正整数，是合法种子），未知区靠下一步显式置 0。

markers = cv2.watershed(img, markers)：水从所有正整数标签处开始涨，0 的位置被填上编号，区域交界处变成 -1。

原素材的另一条路线是 Canny + findContours + drawContours 往 markers 上画轮廓。它对封闭性好、轮廓清晰的图（文字、二值化的图标）够用，且能让「每个轮廓 = 一个种子」显式可见：轮廓灰度不同，说明种子编号不同，有多少种灰度就有多少个种子，最后就切出多少个区域。代码里的关键几行是：

python
# 原文为 OpenCV 3 语法。4.x 里 findContours 只返回 contours, hierarchy 两个值
canny = cv2.Canny(gray, 80, 150)
canny, contours, hierarchy = cv2.findContours(canny, cv2.RETR_TREE, cv2.CHAIN_APPROX_SIMPLE)   # OpenCV 3
# contours, hierarchy = cv2.findContours(canny, cv2.RETR_TREE, cv2.CHAIN_APPROX_SIMPLE)        # OpenCV 4

marks = np.zeros(img.shape[:2], np.int32)      # 必须 int32
for i in range(len(contours)):
    marks = cv2.drawContours(marks, contours, i, (i + 1, 0, 0), 1, 8, hierarchy)

两点修正：原文写 cv2.drawContours(marks, contours, index, (index,index,index), 1, 8, hierarchy)，index 从 0 开始时第一个轮廓被画成 0，而 0 在 watershed 里是「未知区」而不是种子，等于白丢一个种子。改成 i + 1 才是合法标签。另外 drawContours 往单通道 int32 图上画时，颜色元组只用第一个分量，写 (i+1, 0, 0) 和写 (i+1, i+1, i+1) 等价，前者更不容易让人误会成三通道。

填色显示部分，原文用双重 Python 循环逐像素查表，大图上慢得离谱。向量化写法：

python
rng = np.random.default_rng(42)
color_tab = rng.integers(0, 255, size=(markers.max() + 1, 3), dtype=np.uint8)
color_tab[0] = (0, 0, 0)
bgr = color_tab[markers]                 # 一次高级索引，-1 的位置要单独处理
bgr[markers == -1] = (255, 255, 255)

result = cv2.addWeighted(img, 0.6, bgr, 0.4, 0)

注意 color_tab[markers] 里如果 markers 有 -1，会索引到最后一列（Python 负索引行为），所以边界要先单独盖掉，顺序不能反。

还有个坐标上的坑：cv2.watershed 会把图像最外一圈像素强制标成 -1。如果你要统计区域面积，记得把 markers[0, :]、markers[-1, :]、markers[:, 0]、markers[:, -1] 排除，否则边界像素会混进统计。

十六、GrabCut 与分水岭的适用场景对比 #

两个算法解决的问题不同，别混用。

维度 GrabCut 分水岭
判据 颜色相似度 + 空间平滑 梯度／拓扑，灰度当海拔
输入 矩形框或涂抹标记 标记图（每区域一个正整数）
是否交互 需要，最少一次框选 可不交互（自动标记），也可交互画种子

颜色相近的目标 弱项，会漏切或漏边界 只要梯度有峰就能分开

实际工程里两者会串起来用：先 GrabCut 把感兴趣的大区域抠出来，再在抠出的区域里用分水岭把内部的多个目标分开。这个组合对「桌上多个同色物体」这类场景特别顺：GrabCut 挡住背景干扰，分水岭拆开彼此粘连的物体。

十七、为什么需要频域 #

前面的方法全在空间域操作：卷积核在图像上滑动，每个输出像素只看它周围的邻域。这套做法的局限在于局部性——3×3 的核永远看不到全图的结构。

有些问题天生是全局的：

  • 图像里有一条周期性的干扰条纹（扫描线、摩尔纹、织物的经纬），它在空间域遍布全图，你没法用一个小核把它抠掉而不伤及细节。
  • 你要在「尺度」上分开处理：大块的光照不均 vs 细节纹理，这两者的区别是频率，不是位置。
  • 卷积核大到几十上百像素（比如大半径的高斯模糊做背景估计），空间域直接卷积的代价按 O(N2K2) 涨，撑不住。

频域给出了另一条路：把图像拆成一堆不同频率的正弦基函数的加权和，然后按频率处理。周期性干扰在频域是几个孤立的亮点，挖掉就行；大尺度结构和小尺度细节在频域是对不同半径的环，分开处理就行；大核卷积在频域退化成逐点相乘，代价 O(N2logN)。

代价是：频域不保留位置信息。你改动一个频点，整幅图都会变。这就是为什么频域滤波适合作全局处理，不适合做边缘检测这种局部任务。

十八、傅里叶变换在图像上的含义 #

傅里叶的想法是：任何波形都能由一系列频率不同的正弦曲线叠加得到。图像是二维信号，于是图像可以分解成一堆二维正弦（更准确说是复指数）基函数的叠加。

二维离散傅里叶变换，M×N 的图像 $f(x,y)$：

F(u,v)=MN1​x=0∑M−1​y=0∑N−1​f(x,y)e−j2π(Mux​+Nvy​)

逆变换：

f(x,y)=u=0∑M−1​v=0∑N−1​F(u,v)ej2π(Mux​+Nvy​)

$F(u,v)$ 是复数，有幅值和相位。$|F(u,v)|$ 是幅度谱，∠F(u,v) 是相位谱。搞图像处理时我们看得多的是幅度谱，但要清楚：相位携带了结构信息，只保留幅度、把相位丢掉，重构出来的图会散架。这篇里所有「频谱图」说的都是幅度谱。

两条性质必须记住，后面每一节都靠它们：

不是局部对应。$F(u,v)$ 取的是整幅图像所有像素与该频点基函数的加权和。改一个像素，所有频点都变；改一个频点，所有像素都变。这和空间域的卷积完全对称，但直觉上很反。

$F(0,0)$ 是所有像素之和。代入 u=v=0，指数项变成 1，$F(0,0) = \frac{1}{MN}\sum f(x,y)$，按上面的归一化就是平均亮度 fˉ​。这个分量叫直流分量（DC），它决定图像的全局亮度。

实图像的频谱还有一个性质：共轭对称，$F(u,v) = F^*(M-u, N-v)$。所以信息量只有一半，这也是 OpenCV 可以用「打包格式」（CCS）把复数结果塞进同等大小的实数矩阵里的原因。

十九、低频与高频的代表物 #

你看到的 频域里是什么
大块平坦区域、整体明暗 低频，靠近频谱中心
边缘、轮廓 高频，远离中心
纹理细节 高频，比轮廓更靠外
噪点 高频，散布在整个外围
平均亮度 $F(0,0)$，直流分量

为什么低频对应「大块平坦」：低频基函数一个周期铺满整幅图，它的变化慢，能匹配的只能是缓慢变化的成分，也就是大面积明暗。高频基函数一个周期只有几个像素，它能匹配的只能是像素间剧烈的跳变，也就是边缘和噪声。

这条对应关系可以直接用在调试上：拿到一张频谱图，中心亮斑大说明图整体平滑，外围亮说明纹理或噪声多、边缘密。

二十、二维傅里叶变换与频谱图 #

直接显示 $|F(u,v)|$ 基本看不见东西，原因两个。

零频在四个角。DFT 的零频在索引 $(0,0)$，而周期性意味着索引 M−1 与 $0$ 相邻，所以低频分布在四个角，直接显示是「中间暗、四角亮」的怪图。$u$ 超过 M/2、$v$ 超过 N/2 的那些频点其实是负频率，物理上就是「离零频更远，但方向在另一边」。

动态范围太大。低频能量比高频高好几个数量级，线性映射成 0~255 之后只有中心一个亮点，其余全黑。

标准做法两步：fftshift 把低频挪到中心，然后取对数压缩动态范围。

python
import numpy as np
import cv2

img = cv2.imread("image/lena.png", cv2.IMREAD_GRAYSCALE)
f = np.fft.fft2(img.astype(np.float32))
fshift = np.fft.fftshift(f)                 # 四角拼到中心，低频到中间
mag = 20 * np.log(np.abs(fshift) + 1)       # 对数压缩，+1 防 log(0)
mag = cv2.normalize(mag, None, 0, 255, cv2.NORM_MINMAX).astype(np.uint8)
cv2.imshow("spectrum", mag)

fftshift 干的事是按象限交换：把矩阵切成四个象限，第 1 和第 4 交换、第 2 和第 3 交换。效果就是「四角拼到中心」。

log(1+|F|) 里的 +1 是防 log0；系数 20 只是为了让结果落在可视区间，改成 10、30 都行，视觉对比度不同而已。

逆变换时必须先 ifftshift 还原，否则图像会平移半个周期：

python
recon = np.fft.ifft2(np.fft.ifftshift(fshift))
recon = np.abs(recon)                        # 理论上是实图，数值误差带小虚部

矩阵边长为偶数时 fftshift 和 ifftshift 结果相同，边长为奇数时不同，两者不能互换。保险的做法是 fftshift 配 ifftshift 成对出现。

频谱中心化在 OpenCV 里没有专门函数。官方例程是手工交换四个象限，等价的一行是 np.fft.fftshift，优先用它。如果整条链都在 OpenCV 里走，也可以把 cv2.dft 的输出直接交给 numpy 的 shift：

python
d = cv2.dft(np.float32(img), flags=cv2.DFT_COMPLEX_OUTPUT)   # 两通道 (实部, 虚部)
d_shift = np.fft.fftshift(d, axes=[0, 1])

cv2.dft 的细节放在第二十五章。

二十一、频谱图的中心化与对数变换 #

中心化和对数变换是两个独立动作，分开做能定位问题。

中心化的两种等价写法：np.fft.fftshift 按象限交换；OpenCV 官方例程的做法是先算出每一维的中间索引 cx = cols // 2、cy = rows // 2，再用 np.vstack + np.hsplit 手工拼接四个象限。两者结果一致，前者更短。别用「把图像乘 (−1)x+y」那条路——那个技巧只管「零频移到中心」这一件事，而且要求你在逆变换时乘回去，和 fftshift 混用会乱。

对数变换：log(1 + |F|) 是压缩动态范围的通用手段。为什么是 log？因为低频幅度能比高频大 103∼106 倍，线性映射后高频全被压到 0。log 把乘法关系变成加法关系，量级差被压成一个可视的渐变。

顺序问题：log 和 fftshift 谁先谁后不影响结果（log 是逐元素运算，shift 是重排），但 normalize 必须放在 log 之后，否则归一化的分母还是那个离谱的最大值。

几种显示选项的差异：

写法 效果 备注
np.abs(F) 直接显示 几乎全黑，中心一个白点 只能看出有没有 DC
np.log1p(np.abs(F)) 结构和细节都能看见 最常用
20*np.log(np.abs(F)+1) 对比度更强，边缘更突出 系数可调，10~20 都行
np.log1p(np.abs(F)) * 255 / np.log1p(max) 免归一化 需要手动防 max 为 0
cv2.magnitude(re, im) + log OpenCV 路线的幅值 cv2.dft 输出两通道时要拆开

如果只是想看频谱图的形状（比如检查陷波滤波器打在哪），还有一招：直接把 |F| 做 cv2.normalize 再 cv2.applyColorMap(mag, cv2.COLORMAP_JET)，伪彩色能把弱信号提出来。

二十二、低通滤波：模糊 #

时域卷积 ↔ 频域相乘。这是所有频域滤波的合法性来源：在频域乘一个掩膜，等价于在空间域做一次卷积。

低通滤波 = 保留中心（低频）、抑制外围（高频）= 空间域的高斯模糊或均值模糊。

python
import numpy as np
import cv2

img = cv2.imread("image/lena.png", cv2.IMREAD_GRAYSCALE)
f = np.fft.fftshift(np.fft.fft2(img.astype(np.float32)))

rows, cols = img.shape
crow, ccol = rows // 2, cols // 2
mask = np.zeros((rows, cols), np.float32)
r = 30
cv2.circle(mask, (ccol, crow), r, 1, thickness=-1)   # 半径 r 的实心圆，圆心是 DC

f_low = f * mask
img_low = np.abs(np.fft.ifft2(np.fft.ifftshift(f_low)))
img_low = np.clip(img_low, 0, 255).astype(np.uint8)

四个细节：

  • 掩膜用 float32 而不是 uint8。用 uint8 也能跑（会隐式转换），但和复数数组相乘时类型提升不确定，显式 float 更稳。
  • cv2.circle(mask, center, r, 1, -1) 里 thickness=-1 是填充，写成 cv2.FILLED 也行。
  • 圆是对称低通；矩形框（mask[crow-r:crow+r, ccol-r:ccol+r] = 1）也能用，但两个方向的截止频率不一样，会对横向和纵向的细节产生不同强度的模糊。
  • ifftshift 必须在 ifft2 之前，否则结果平移半幅。

r 的物理含义：$r$ 越小，保留的频率越少，图越糊。$r$ 取 min(rows, cols) 的 5%~10% 是常见区间。想看极端效果就把 r 给到 5，能看到明显的块状。

低通的应用不止「变模糊」：

  • 去噪：高频噪声被砍掉，代价是边缘一起糊。
  • 背景估计：大半径低通的结果就是「光照分布图」，原图除以它（或相减）能去掉光照不均。
  • 平滑后再阈值：先把纹理抹平，Otsu 的阈值更稳定。

二十三、高通滤波：锐化 #

高通 = 抑制中心、保留外围 = 边缘提取或锐化。

python
mask = np.ones((rows, cols), np.float32)
cv2.circle(mask, (ccol, crow), r, 0, thickness=-1)    # 中心挖洞

f_high = f * mask
img_high = np.abs(np.fft.ifft2(np.fft.ifftshift(f_high)))
img_high = cv2.normalize(img_high, None, 0, 255, cv2.NORM_MINMAX).astype(np.uint8)

注意高通结果的量级问题：挖掉 DC 之后，结果的均值约为 0，负值一片。np.abs 之后再做归一化才显示得出来；如果你要的是「锐化后的图」，不能只保留高频，而是要把高频「加回去」。

两种锐化写法：

python
# 写法一：原图 + k * 高频
k = 1.5
sharp = img.astype(np.float32) + k * (img.astype(np.float32) - img_low.astype(np.float32))
sharp = np.clip(sharp, 0, 255).astype(np.uint8)

# 写法二：频域直接拼一个增益掩膜（低频保持 1，高频放大到 1+k）
boost = np.ones((rows, cols), np.float32)
cv2.circle(boost, (ccol, crow), r, 1 + k, thickness=-1)
img_boost = np.abs(np.fft.ifft2(np.fft.ifftshift(f * boost)))
img_boost = np.clip(img_boost, 0, 255).astype(np.uint8)

写法一的 img - img_low 就是空间域的「非锐化掩蔽」（unsharp mask），和频域高通是同一件事的两种算法；写法二直接在频域做，把「高通 + 直通」合成一个掩膜，省一次逆变换。

低通与高通对照：

项 低通 高通
掩膜形状 中心圆内 = 1，圆外 = 0 中心圆内 = 0，圆外 = 1
保留的频率 低频 高频
空间域效果 模糊、平滑 边缘、锐化
输出量级 与原图同量级，均值保留 均值被挖掉，需归一化
典型用途 去噪、背景估计 边缘提取、细节增强
副作用 边缘变钝 噪声被同步放大
空间域等价 均值/高斯模糊 拉普拉斯、Sobel、非锐化掩蔽

滤波器形状也有讲究：

类型 频域响应 空间域旁瓣 用不用
理想（矩形/圆盘） 突变，0/1 硬切换 长，逆变换是 Sa 函数，产生环状振铃 演示用，少用于出图
高斯 平滑，无零点 短，逆变换还是高斯 首选，不出振铃
巴特沃斯 有过渡带，阶数控制陡度 介于两者之间 需要可控过渡时用

为什么理想低通会振铃：理想低通的频率响应是矩形，它的逆变换是 Sa 函数（$\sin x / x$），在空间域有无穷长的旁瓣；离散截断后旁瓣不消失，就形成明暗相间的环。阶跃边缘被这样处理会出现多重轮廓，非常难看。伽马射线、CT 重建这类应用里，振铃会直接制造假结构。

对比一下同一件事在空间域的样子：高斯模糊的核本身就是高斯，它的傅里叶变换也是高斯，没有截断突变，所以不会振铃。这就是 cv2.GaussianBlur 比「理想低通」好用的原因，两边的结论一致。

二十四、频域滤波与空域卷积的关系 #

卷积定理：$f * h ;\longleftrightarrow; F \cdot H$。图像与核的空间域卷积，等于两者的频域表示逐点相乘再逆变换。

几个推论直接决定实现选型：

空域操作 频域对应 频域掩膜长什么样
均值模糊（box filter） 乘一个二维 sinc 型响应 中心亮、向外振荡衰减
高斯模糊 乘一个二维高斯 中心亮，单调衰减，无零点
拉普拉斯（边缘提取） 乘 −(u2+v2) 型响应 中心 = 0，向外线性增长
Sobel 水平／垂直 乘带方向性的响应 过中心的带状亮区
非锐化掩蔽 乘 1+k(1−Hlow​) 低频 1，高频 1+k
陷波滤波 在特定频率点置 0 外围几个小圆挖掉

复杂度对比是选型的关键之一：

  • 空间域直接卷积：O(N2K2)，$N$ 是图像边长、$K$ 是核边长。
  • 频域：正变换 + 逆变换各 O(N2logN)，中间相乘 O(N2)。
  • 交叉点大约在 $K$ 接近图像边长的 1/10 到 1/20 时，因实现和常数因子而异，别当精确阈值用。

实操上一条重要提醒：离散卷积与频域相乘严格等价的前提是循环卷积。用 FFT 做卷积，边界会「绕回来」，产生环绕伪影。标准补救是把图和核都补零到 M+K−1 的尺寸再变换，OpenCV 的 getOptimalDFTSize 就是算这个尺寸的（它把长度向上取到能被 2、3、5 分解的最接近值）。做滤波器掩膜这种「乘一个响应」的操作不用补零，但要清楚边缘处会有 wrap-around 效应。

什么时候真的该用频域，什么时候不该：

  • 该用：核非常大（半径 50 以上的模糊、大范围背景估计）；需要设计特定频率响应（陷波去周期性条纹、带通提取纹理）；同态滤波（把照射分量这个低频和反射分量这个高频分开处理，做暗部增强）；频域分析本身就是目的（周期性缺陷检测、纹理特征）。
  • 不该用：3×3 到 7×7 的边缘检测与锐化，cv2.filter2D 或 cv2.GaussianBlur 更快也更省内存；只做一次卷积的场合，补零和 FFT 的固定开销已经超过直接卷积。

二十五、OpenCV 里的 DFT 实现 #

有两条路，选一条走通就行。

路线一：np.fft（推荐，最简单）。首尾对称，不用管 flags，不用管归一化。

python
f = np.fft.fft2(img.astype(np.float32))
fshift = np.fft.fftshift(f)
# ... 频域处理，得到 processed ...
img_back = np.abs(np.fft.ifft2(np.fft.ifftshift(processed)))

路线二：cv2.dft / cv2.idft。参数多，但能直接接 OpenCV 的其他函数（cv2.magnitude、cv2.mulSpectrums、cv2.getOptimalDFTSize）。

python
import numpy as np
import cv2

img = cv2.imread("image/lena.png", cv2.IMREAD_GRAYSCALE)
f32 = np.float32(img)

# 1. 补零到最优尺寸（可选，但对大核卷积有必要）
rows, cols = img.shape
opt = cv2.getOptimalDFTSize(rows), cv2.getOptimalDFTSize(cols)
padded = np.zeros(opt, np.float32)
padded[:rows, :cols] = f32

# 2. 正变换：输出 CV_32FC2，通道顺序（实部, 虚部），且不做归一化
dft = cv2.dft(padded, flags=cv2.DFT_COMPLEX_OUTPUT)

# 3. 中心化（numpy 的 fftshift 能直接处理两通道数组）
dft_shift = np.fft.fftshift(dft, axes=[0, 1])

# 4. 取幅度谱
magnitude = cv2.magnitude(dft_shift[:, :, 0], dft_shift[:, :, 1])
magnitude = np.log1p(magnitude)
magnitude = cv2.normalize(magnitude, None, 0, 255, cv2.NORM_MINMAX).astype(np.uint8)

# 5. 逆变换：先 ifftshift，再 idft，用 DFT_SCALE 补上 1/(M*N)
back = np.fft.ifftshift(dft_shift)
inv = cv2.idft(back, flags=cv2.DFT_SCALE | cv2.DFT_REAL_OUTPUT)
img_back = np.clip(inv, 0, 255).astype(np.uint8)

cv2.dft 的 flags 逐个说明（取值来自 OpenCV 4.x 的 DftFlags 枚举）：

flags 值 作用
cv2.DFT_INVERSE 1 做逆变换而不是正变换
cv2.DFT_SCALE 2 结果除以元素个数。文档明确写了：dft 和 idft 默认都不归一化，要让正逆变换互逆，必须显式给其中一次传 DFT_SCALE
cv2.DFT_ROWS 4 对每一行单独做一维变换，而不是整块做二维变换
cv2.DFT_COMPLEX_OUTPUT 16 实数输入时输出完整的复数矩阵（同尺寸、两通道）
cv2.DFT_REAL_OUTPUT 32 逆变换时假定输入共轭对称，输出实数单通道矩阵
cv2.DFT_COMPLEX_INPUT 64 声明输入是复数（两通道）

不传 DFT_COMPLEX_OUTPUT 时，实数输入的正变换输出是「打包格式」（CCS）：还是同样大小的实数矩阵，但实部和虚部交错塞在奇偶列里，压缩了共轭对称带来的冗余。要算幅度谱必须传 DFT_COMPLEX_OUTPUT，否则索引全是乱的。

关于归一化，原文写的是「逆变换后要除以 MN​」。这个说法要修正：OpenCV 的文档写的是逆变换公式里乘 M⋅N1​，也就是除以 M×N，不是 MN​。除以 MN​ 只在 NORM_L2 归一化时出现，别混。两种正确做法：

  • cv2.idft(spectrum, flags=cv2.DFT_SCALE)，让 OpenCV 帮你除。
  • 自己 np.abs(inv) / (rows * cols)。

另外要注意 np.fft 和 cv2.dft 的归一化方向是反的：np.fft.fft2 与 np.fft.ifft2 自带对称的 1/(MN)，所以 np.fft 那条路什么都不用做。混用两条路线（比如用 cv2.dft 正变换、用 np.fft.ifft2 逆变换）会差一个 $MN$ 的系数，图上表现为全白或全黑。

cv2.dft 与 np.fft 的差异汇总：

项 np.fft.fft2 cv2.dft
输出类型 复数 complex64/complex128 两通道实矩阵 CV_32FC2 / CV_64FC2
归一化 正逆各带 1/N​ 的对称约定，实际结果是自洽的 都不归一化，靠 DFT_SCALE
中心化 np.fft.fftshift 同样用 np.fft.fftshift，cv2 没有对应函数
补零尺寸 任意 用 cv2.getOptimalDFTSize 取最优
逆变换 np.fft.ifft2 cv2.idft
幅值 np.abs cv2.magnitude(re, im)
多通道图像 逐通道循环调用 直接把 8UC3 转 32F 后 cv2.dft 会按通道处理？实际是当作多通道数组，行为不稳定，建议 cv2.split 后逐通道做

cv2.dft 在 OpenCV 3.x 与 4.x 之间没有破坏性变化：DFT_INVERSE、DFT_SCALE、DFT_ROWS、DFT_COMPLEX_OUTPUT、DFT_REAL_OUTPUT 四个常量在 3.x 就是这套值。DFT_COMPLEX_INPUT 也在。要注意的是 cv2.dft 的输入深度：3.x 里传 uint8 会抛错，必须先转 np.float32 或 np.float64，4.x 同样如此。转 float32 时对 8 位图没有精度问题，转 float64 则慢一倍。

还有一种更省事的高通路线，不碰 dft 也能理解频域：cv2.Sobel、cv2.Scharr、cv2.Laplacian 这几个空间域算子本质上就是固定频率响应的滤波器，和这里手工搭的频域高通是同一族东西。做工程时优先用它们。
