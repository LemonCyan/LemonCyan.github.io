边检出来了，然后呢。Canny 给你一张只有线条的二值图，线条之间没有关系、没有拓扑、没有几何含义。要往下走，第一步把这些亮像素连成闭合曲线，第二步从曲线里算出面积、周长、包围盒、凸包，第三步把曲线拟合回直线、圆、矩形、任意多边形。

这篇补的正是这一环：它是「边缘检测」的下一步，「目标识别」的前一步。

不讲什么。threshold 的五种类型、cvtColor、滤波核与 Canny 的阈值取舍，见同目录 图像采集与滤波：从摄像头到边缘检测；imread/imwrite 与模块划分见 OpenCV 入门：安装、模块与图像读写；GrabCut 与分水岭那种「按区域分割」的思路见 图像分割与频域分析：GrabCut、分水岭与傅里叶变换；模板匹配和轮廓匹配都解决不了的场景，得上特征点或深度学习，那不在这个目录的范围里。

代码全部 Python + cv2，参数写具体值。原文是 C++ 原型的地方标「原文为 C++」。OpenCV 3.x 与 4.x 的差异逐处标注，findContours 的返回值和它是两回事，第三节之外还有专门一章。

一、轮廓是什么：从边缘到闭合曲线 #

边缘和轮廓在中文里经常被混着用，在 OpenCV 里是两个不同的数据结构。

边缘检测的输出是掩码：和原图同尺寸的 uint8 矩阵，每个像素要么 0 要么 255，背后没有「第几个物体」这个概念。轮廓检测的输出是列表：list[ndarray]，每个 ndarray 形状 (N, 1, 2)，dtype 是 int32，记录一个边界上按顺序走的 N 个点，首尾相接。

从掩码到列表，中间做的是「邻域连通 + 边界跟踪」。OpenCV 用的是 Suzuki 那套边框跟踪算法（findContours 源码注释写明出自 Suzuki85）。它逐行扫描，碰到一个外边界起点就沿边界摸一圈，把点按顺序写进数组，回到起点即闭合，再扫下一个。

整条流水线：

阶段 输入 输出 能回答的问题
灰度 BGR 图 单通道 uint8 每个像素多亮
滤波 灰度图 灰度图 去噪后的亮度
边缘（Canny/Sobel） 灰度图 0/255 掩码 哪里亮度突变
二值化（threshold/adaptive） 灰度图 0/255 掩码 哪些像素属于前景
形态学（开闭运算） 掩码 掩码 断口补上没、噪点清掉没
找轮廓（findContours） 掩码 list[ndarray] 有几个连通边界，各由哪些点组成
描述与拟合 轮廓点集 数值与几何基元 多大、多圆、几条边、斜多少度

最后两行是这篇的主体，前面五行归上一篇。

一个必须说清的边界条件：findContours 吃的是二值图，不是灰度图。抄来的代码传灰度图也能跑，是因为 OpenCV 把非零像素一律当 255，结果取决于你的阈值语义，你控制不了。想稳定就先 threshold 或 Canny 压成 0/255。

二值化之后还有一步常被跳过：形态学闭运算补断口。Canny 出来的边缘常有 1 像素缺口，缺口一多，本该闭合的轮廓被拆成两段，后面的面积和形状判断全错。

python
import cv2
import numpy as np

img = cv2.imread('shapes.jpg', cv2.IMREAD_COLOR)
assert img is not None, '图没读进来，先查路径'

gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
blur = cv2.GaussianBlur(gray, (5, 5), 0)
thresh = cv2.threshold(blur, 0, 255, cv2.THRESH_BINARY_INV + cv2.THRESH_OTSU)[1]

# 闭运算：先膨胀后腐蚀，补 1~3 像素的断口，不改变整体尺寸
kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))
thresh = cv2.morphologyEx(thresh, cv2.MORPH_CLOSE, kernel, iterations=2)

cnts, hier = cv2.findContours(thresh, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
print('轮廓数:', len(cnts), '第一个轮廓:', cnts[0].shape, cnts[0].dtype)

THRESH_BINARY_INV 是因为这一类示例图多半白底黑物，物体是暗的，取反之后物体成了前景（白）。方向搞反，RETR_EXTERNAL 返回的就成了整张图的外框。

二、findContours 的工作方式 #

签名（原文为 C++）：

text
cv2.findContours(image, mode, method[, contours[, hierarchy[, offset]]])

Python 绑定改成了返回值形式，contours 和 hierarchy 不用传，直接接返回值。

两个硬性输入约束：

  • image：8 位单通道二值图。mode 取 cv2.RETR_CCOMP 或 cv2.RETR_FLOODFILL 时允许 32 位整型（cv2.CV_32SC1），官方文档写明的例外。
  • 输入图像会被改动。原文第 37 行「建议使用原始图像的一份拷贝」是老版本的忠告，这个涂改输入的行为在 3.2 之后才拿掉，老版本上一律传副本。
参数 取值 说明
image 单通道 8 位二值图 非零即前景；CCOMP/FLOODFILL 可用 CV_32SC1
mode RETR_* 四种 决定轮廓之间的层级关系，见第三章
method CHAIN_APPROX_* 决定每个轮廓存多少点，见第四章
offset (dx, dy) 给所有点加平移，默认 (0, 0)
返回 contours list[ndarray] 每个元素形状 (N, 1, 2)，dtype int32
返回 hierarchy ndarray 形状 (1, M, 4) dtype int32，值为轮廓下标或 -1

offset 常被忽略，工程里很实用：在 img[y0:y1, x0:x1] 上找完轮廓，传 offset=(x0, y0) 就能直接拿到原图坐标，省一次手工加偏移。

hierarchy 的形状是 (1, M, 4)，不是 (M, 4)，所以要写 hierarchy[0][i]。轮廓点集是 int32，cv2.contourArea 吃 int32 和 float32 都行，你自己做矩阵运算时别指望它是浮点。

三、findContours 的检索模式 #

四种模式，差别只在一件事：父子关系建不建、建几层。

模式 提取范围 hierarchy 结构 典型用途
RETR_EXTERNAL 只取最外层 四个层级字段全为 -1 只要物体个数与外轮廓，忽略内部孔洞
RETR_LIST 全部 平铺，前后字段串成一条链 不关心嵌套，只想遍历所有边界
RETR_CCOMP 全部 两层：顶层是外边界，次层是孔洞 数「有几个实心块」、填洞、连通域替代方案
RETR_TREE 全部 任意层，完整树 需要知道谁套谁，比如文档版式、嵌套图形

原文第 47 行说 RETR_EXTERNAL 会让 hierarchy[i][2] = hierarchy[i][3] = -1，下标 2、3 是父子字段，这半句对；但它暗示只有这两个字段为 -1，实际上前后字段也是 -1，四条全是。

RETR_CCOMP 的语义最容易记混：它把图看成「外边界 + 外边界内部的孔洞」的集合，孔洞里的实心块重新算作外边界。一个甜甜圈式的三层结构在 CCOMP 下会被拍平成两层。

RETR_FLOODFILL 在原素材里只有一句猜测（原文第 51 行「官网没有介绍，应该是洪水填充法」）。它在 Python 绑定里存在，主要是 C 接口的遗留，处理 32 位整型标签图，日常场景用不上，本篇不展开。

实际最常用的是 RETR_EXTERNAL：你只想知道黑底上有几个零件。要数轮廓内部的孔洞，换 RETR_TREE 看父子关系。

python
# 同一张二值图，四种模式的返回差异
for mode, name in [(cv2.RETR_EXTERNAL, 'EXTERNAL'),
                   (cv2.RETR_LIST, 'LIST'),
                   (cv2.RETR_CCOMP, 'CCOMP'),
                   (cv2.RETR_TREE, 'TREE')]:
    cnts, hier = cv2.findContours(thresh, mode, cv2.CHAIN_APPROX_SIMPLE)
    print(f'{name}: 轮廓 {len(cnts)}, hierarchy {None if hier is None else hier.shape}')

四、轮廓的近似方法 #

同一个边界，可以存每个像素，也可以只存拐点。前两档日常用，后两档是 Teh-Chin 链逼近的两个变体。

方法 存点规则 100×100 矩形的点数 适合
CHAIN_APPROX_NONE 相邻点像素位置差不超过 1，全部保留 约 400 个 需要逐像素精度，比如自己算曲率
CHAIN_APPROX_SIMPLE 水平、垂直、对角线方向压缩，只留每段端点 4 个 绝大多数情况，省内存又快
CHAIN_APPROX_TC89_L1 Teh-Chin 链逼近，L1 准则 随曲线变化，拐点附近多、直线段少 不设 epsilon 也要抽稀
CHAIN_APPROX_TC89_KCOS 同上，换一套拟合准则 同左 同上，曲线平滑时略有不同

原文第 58 行把 CHAIN_APPROX_SIMPLE 的规则写成「值保留该方向的重点坐标」，「值」是「只」的错字。它举的例子「一个矩形轮廓只需 4 个点」是对的。

method 只影响存储，不改拓扑。同一个边界在 NONE 和 SIMPLE 下，cv2.contourArea 几乎完全一致，cv2.arcLength 有微小差异（SIMPLE 下按折线算）。真正改变几何形状的是 cv2.approxPolyDP，别把两者混为一谈。

python
cnt_none, _ = cv2.findContours(thresh, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)
cnt_simple, _ = cv2.findContours(thresh, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

# sanity check：压缩存点不该改变面积
print('NONE  点数/面积:', cnt_none[0].shape[0], cv2.contourArea(cnt_none[0]))
print('SIMPLE 点数/面积:', cnt_simple[0].shape[0], cv2.contourArea(cnt_simple[0]))

五、OpenCV 3 与 4 的返回值差异 #

这是实测最常见的崩溃点，没有之一。

OpenCV 3.x 的绑定让 findContours 返回三个值：C++ 原型里 contours 是 OutputArray，还有一份输入图像的副本，两者一起被回传。4.0 起不再复制输入图像，那个返回值被去掉，Python 只剩两个值；4.5.4 之后 hierarchy 还会是 None。

版本 返回值个数 正确写法
3.x 3 image, contours, hierarchy = cv2.findContours(...)
4.0 ~ 4.5.3 2 contours, hierarchy = cv2.findContours(...)
4.5.4+ 2，hierarchy 可为 None contours, hierarchy = cv2.findContours(...)，用前判空

报错长相不一样，但都在这两个里：

text
ValueError: not enough values to unpack (expected 3, got 2)      # 4.x 上写了 3 值
ValueError: too many values to unpack (expected 2)              # 3.x 上写了 2 值

跨版本写法一：按主版本号分支。

python
import cv2

def find_contours(img, mode=cv2.RETR_EXTERNAL, method=cv2.CHAIN_APPROX_SIMPLE):
    """返回 (contours, hierarchy)。"""
    result = cv2.findContours(img, mode, method)
    return (result[1], result[2]) if len(result) == 3 else (result[0], result[1])

写法二：不认版本号，认返回长度，连某些改了 __version__ 的打包版一起兜住。

python
def find_contours_any(img, mode=cv2.RETR_EXTERNAL, method=cv2.CHAIN_APPROX_SIMPLE):
    result = cv2.findContours(img, mode, method)
    contours, hierarchy = ((result[1], result[2]) if len(result) == 3
                           else (result[0], result[1]))
    if hierarchy is None:
        hierarchy = np.full((1, len(contours), 4), -1, dtype=np.int32)
    return contours, hierarchy

后面的示例统一用 find_contours 这个名字，用哪套写法都行。版本号也值得打出来贴进 issue：

python
print(cv2.__version__)   # 例如 4.10.0

六、轮廓的基本属性：面积、周长、边界框 #

拿到轮廓之后第一批量算的东西，都是标量或矩形。这张表是日常查得最多的。

函数 返回 关键参数 口径
cv2.contourArea(cnt) float oriented=False 用格林公式算多边形面积；oriented=True 时带符号，正负表示绕向
cv2.arcLength(cnt, closed) float closed=True 沿点集累加相邻点距离；closed=False 时不算首尾闭合那一段
cv2.boundingRect(cnt) (x, y, w, h) 无 轴对齐外接矩形（AABB），x,y 是左上角
cv2.minAreaRect(cnt) ((cx, cy), (w, h), angle) 无 面积最小的旋转矩形，见第十九章
cv2.minEnclosingCircle(cnt) ((cx, cy), r) 无 最小外接圆，中心与半径都是浮点
cv2.arcLength 配合 approxPolyDP 折线点集 epsilon 见第八章与第九章

contourArea 有两个坑。少于 3 个点的轮廓面积为 0，噪声点和 2 像素线段会被面积过滤直接筛掉，正好省事。arcLength 的 closed 参数不是「轮廓是否闭合」，而是「要不要算最后一段回到起点」；findContours 的点集天然首尾相接，拿周长做 epsilon 基准时一律传 True。

面积过滤是清洗轮廓的第一道闸，阈值给具体值：

python
contours, hierarchy = find_contours(thresh, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
img_area = thresh.shape[0] * thresh.shape[1]

valid = [c for c in contours
         if 100 <= cv2.contourArea(c) <= 0.9 * img_area and len(c) >= 5]
print(f'原始 {len(contours)} 个，过滤后 {len(valid)} 个')

out = img.copy()
for c in valid:
    x, y, bw, bh = cv2.boundingRect(c)           # 左上角 + 宽高
    cv2.rectangle(out, (x, y), (x + bw, y + bh), (0, 255, 0), 2)   # 要两个对角点

过滤里有三个数：100 挡噪声，0.9 * img_area 挡背景框，len(c) >= 5 给 fitEllipse 留点。面积上限不是随手写的：二值化方向搞反、或物体贴着边界时，最外层轮廓会退化成整张图的外框，把它当目标会让后面所有统计失真。

七、轮廓的几何矩与重心 #

cv2.moments(cnt) 返回一个字典，23 个键：m00、m10、m01 是空间矩，mu20、mu11、mu02 是中心矩，nu20、nu11 是归一化中心矩。它和图像矩只差输入是点集还是灰度图，binaryImage=True 时把非零值全当 1 算。

重心两个式子：cx = m10 / m00，cy = m01 / m00。m00 就是轮廓面积（二值点集下和 contourArea 一致），m00 == 0 时除零，退化轮廓会把 cx 算成 nan 或直接抛 ZeroDivisionError。

python
for c in valid:
    M = cv2.moments(c)
    if M['m00'] == 0:
        continue
    cx, cy = int(M['m10'] / M['m00']), int(M['m01'] / M['m00'])
    cv2.drawMarker(out, (cx, cy), (0, 0, 255), cv2.MARKER_CROSS, 12, 2)

重心的用途不止画个点：它是旋转、缩放、平移不变量计算的起点。Hu 矩的 7 个不变量全由归一化中心矩组合而成，cv2.matchShapes 内部就用它们比形状。

八、凸包与凸性缺陷 #

凸包是包含点集的最小凸多边形，多边形内任意两点的连线还在多边形内。轮廓往里凹的地方，凸包用一条直线跨过去。

cv2.convexHull(points, returnPoints=True, clockwise=False) 两个参数值得记：returnPoints=True（默认）返回凸包顶点坐标，形状 (K, 1, 2)，能直接进 drawContours；returnPoints=False 返回原始点集里的下标，形状 (K, 1)，配 convexityDefects 用，因为缺陷函数要的是索引。

cv2.convexityDefects(contour, hull) 返回 (N, 1, 4) 的 int32：每行是起点下标、终点下标、最远点下标、到对应边的距离。距离要除以 256 才是像素值，官方文档写明了，忘了除会拿到放大 256 倍的数。

python
cnt = max(valid, key=cv2.contourArea)
hull_pts = cv2.convexHull(cnt)                      # 画图用，顶点坐标
hull_idx = cv2.convexHull(cnt, returnPoints=False)  # 算缺陷用，点索引
cv2.drawContours(out, [hull_pts], -1, (255, 0, 0), 2)

area_hull = cv2.contourArea(hull_pts)
solidity = cv2.contourArea(cnt) / area_hull if area_hull else 0.0
print(f'凸性比 solidity = {solidity:.3f}')          # 凸形状接近 1.0

if hull_idx is not None and len(cnt) >= 4:
    defects = cv2.convexityDefects(cnt, hull_idx)
    if defects is not None:
        for s, e, f, d in defects[:, 0]:
            if d / 256.0 > 10:                      # 深于 10 像素的凹陷才画
                cv2.circle(out, tuple(cnt[f][0]), 4, (0, 0, 255), -1)

solidity（凸性比）是形状判定的好指标：圆和正多边形接近 1.0，五角星大约 0.5，细长折角物体更低。正常范围是 (0, 1]，算出来大于 1 说明凸包算错了。

凸性缺陷的经典用途是数手指：手掌轮廓的凸包跨过指缝，每个指缝是一个深缺陷，缺陷数 + 1 就是伸出的手指数。这个判断对轮廓质量和手掌朝向都敏感，「缺陷数 + 1」也只在这个前提下成立。

九、多边形逼近：Douglas-Peucker 算法 #

cv2.approxPolyDP(curve, epsilon, closed)，Douglas-Peucker 算法。原文第 262 行把函数名拼成 approxPloyDP，「Ploy」是「Poly」的错字，出现 3 次；第 464 行又把它拼成 findContous。

算法四步：

  1. 取折线首尾两点连成一条直线段。
  2. 找中间所有点到这条线段距离最大的那个，记下最大距离 d。
  3. d > epsilon：把这个点留下，用它把折线切成两段，两段各自递归。
  4. d <= epsilon：这一段当成直线，中间点全丢。

epsilon 是唯一要调的参数，意思是「允许的最大偏差」，单位像素。原文第 262~268 行给了两种说法，「源轮廓与近似多边形的最大差值」对，「近似多边形周长与源轮廓周长之间的最大差值」不对：epsilon 约束的是点到弦的垂直距离，跟周长没有直接关系。

实用取法：epsilon = k * cv2.arcLength(cnt, True)，k 取 0.01~0.05。1% 周长保住形状又显著减点，5% 基本只剩骨架。

python
for k in (0.01, 0.02, 0.05):
    eps = k * cv2.arcLength(cnt, True)
    approx = cv2.approxPolyDP(cnt, eps, True)
    print(f'k={k}, epsilon={eps:.2f}, 顶点数={len(approx)}')

len(approx) 是「几条边」，闭合折线的顶点数等于边数，这个数直接喂给第十章。closed=True 表示首尾相接，轮廓一律传 True；传 False 会把首尾当独立端点，顶点数算错。

输出形状是 (K, 1, 2)，和 findContours 一致，能直接进 drawContours。取坐标要写 approx[i][0][0]，两层下标，是 IndexError 的高发区。

十、判断形状：从顶点数到形状匹配 #

两种思路：按近似顶点数硬判，快、确定、不要模板，缺点是只能判规则多边形，对噪声敏感；按形状相似度打分，cv2.matchShapes 用 Hu 矩的 7 个不变量做比较，对旋转、缩放、平移不敏感，适合和已知模板比对。

顶点数 判定 附加条件
3 三角形 任何三角形都算，不区分正三角
4 四边形，再细分 用 minAreaRect 的宽高比分辨正方形与长方形
5 五边形 —
6 六边形 —
更多 圆或其它 用 4πA/P² 的圆度判断

圆度 = 4 * π * area / perimeter²，正圆极限是 1。二值化出来的圆轮廓圆度在 0.85~0.95，正方形约 0.785，正三角形约 0.6。

python
def classify(cnt):
    peri = cv2.arcLength(cnt, True)
    if peri == 0:
        return 'degenerate', 0.0
    n = len(cv2.approxPolyDP(cnt, 0.02 * peri, True))
    circularity = 4 * np.pi * cv2.contourArea(cnt) / (peri * peri)

    if n == 3:
        return 'triangle', circularity
    if n == 4:
        (_, _), (w, h), _ = cv2.minAreaRect(cnt)
        if max(w, h) == 0:
            return 'quad', circularity
        return ('square' if min(w, h) / max(w, h) > 0.9 else 'rectangle'), circularity
    if n in (5, 6):
        return {5: 'pentagon', 6: 'hexagon'}[n], circularity
    return ('circle' if circularity > 0.85 else f'polygon({n})'), circularity

0.02 和 0.85 都是经验值，不是定理。图小、噪声大、轮廓被切掉一块，圆度会掉到 0.8 以下；epsilon 抬到 0.04，圆会被压成 6 个顶点而走进「六边形」分支。真实场景里这两个值得重标。

cv2.matchShapes(contour1, contour2, method, parameter) 的三种方法：

method 常量 计算依据 特点
1 cv2.CONTOURS_MATCH_I1 Σ|1/mᵢᴬ − 1/mᵢᴮ| 倒数差，小形状差异被放大
2 cv2.CONTOURS_MATCH_I2 Σ|mᵢᴬ − mᵢᴮ| 直接差，最常用
3 cv2.CONTOURS_MATCH_I3 Σ|mᵢᴬ − mᵢᴮ| / |mᵢᴬ| 相对差，对尺度变化更宽容

m 是 Hu 矩的 7 个不变量，parameter 在 OpenCV 里没有被用到，传 0。返回值越小越相似，0 是完全相同。这个「小」没有绝对标准：I2 下同一个圆的两份带噪轮廓常在 0.01~0.1，圆与正方形常在 0.3 以上。用之前先跑自己的模板量分位数，再把阈值钉死。

python
template_circle = cnt          # 拿一个已知圆当模板，正式项目用多张样本的均值
for c in valid:
    score = cv2.matchShapes(template_circle, c, cv2.CONTOURS_MATCH_I2, 0)
    print(f'match(I2) = {score:.4f}', '相似' if score < 0.15 else '不相似')

Hu 矩不区分镜像：左右翻转后 7 个不变量相同（第 7 个理论上变号，实际取绝对值），「p」和「q」在它眼里是一种形状。要区分镜像得靠别的特征。

十一、轮廓的层级关系 #

hierarchy 的四元组是 [next, prev, first_child, parent]，全是 contours 列表的下标，没有对应项为 -1。

原文第 61 行顺序写对了，只是含糊：「后一个轮廓，前一个轮廓，父轮廓，内嵌轮廓的索引」。第 3 个是父轮廓没错，第 4 个准确说是第一个子轮廓，不是「内嵌轮廓」的泛指。

text
RETR_EXTERNAL       每个轮廓 [ -1, -1, -1, -1 ]
RETR_LIST           0 号 [ 1, -1, -1, -1 ]   1 号 [ 2, 0, -1, -1 ]   末号 [ -1, 1, -1, -1 ]
RETR_TREE           外轮廓 A [ B, -1, C, -1 ]   孔洞 C [ -1, -1, -1, A ]

遍历用递归，child 往下、next 往右：

python
def dump_tree(contours, hierarchy, idx=0, depth=0):
    """从 idx 出发，走完同层兄弟和它们的子树。"""
    h = hierarchy[0]
    while idx != -1:
        print('  ' * depth + f'轮廓 {idx}, 面积 {cv2.contourArea(contours[idx]):.0f}')
        if h[idx][2] != -1:                      # 有第一个孩子
            dump_tree(contours, hierarchy, h[idx][2], depth + 1)
        idx = h[idx][0]                          # 下一个兄弟

RETR_TREE 下 child != -1 就说明轮廓内部还有东西。数「有几个实心物体」用 RETR_CCOMP，数 parent 为 -1 的顶层轮廓。版式分析是这套结构的典型用途：表格是外轮廓，单元格是孔洞，格里的文字是孔洞的子轮廓，只看面积判「几个物体」在这种图上必错。

十二、直线检测的两种思路 #

拿到边缘想找直线，有两条路。

第一条对轮廓做拟合：轮廓是直的，cv2.fitLine 给方向；轮廓由几段直线组成，approxPolyDP 先拆折线，每段是一个候选。可控、结果与轮廓一一对应，对断裂和遮挡没辙。

第二条对整张边缘图做霍夫变换：不关心像素属于哪个轮廓，每个边缘点投一票，参数空间里每一条候选直线的票数堆起来。断成几截的同一条直线能重新连起来，代价是对参数敏感，容易出一堆重复线。

思路 输入 输出 抗遮挡 计算量 典型函数
轮廓拟合 单个轮廓 直线方程或折线 弱 极低 fitLine / approxPolyDP
标准霍夫 整张边缘图 (rho, theta) 直线族 中 中 HoughLines
概率霍夫 整张边缘图 (x1, y1, x2, y2) 线段 强 低于标准霍夫 HoughLinesP

原文第 361 行说概率霍夫「计算代价会少一些，执行更快」，对，原因它没写透：标准霍夫让每个边缘点在所有 theta 上投票，累加器是 (rho_num, theta_num) 的二维矩阵；概率霍夫从边缘点里抽样，只给抽中的点投票，票够了就退出。抽样的代价是结果非确定，同一张图跑两次，HoughLinesP 的线段不完全一样。

原文第 356~359 行说两个函数「仅有的差别」是标准与概率，这只对了一半。返回值形状也不同：HoughLines 给无限长的 (rho, theta)，HoughLinesP 给有限线段端点，而返回值差异比算法差异更影响你写代码。

十三、霍夫直线变换的原理 #

直角坐标系里一条直线是 y = kx + b。用 (k, b) 当参数平面有个致命问题：垂直线 k = ∞，参数空间爆掉。

霍夫变换换成法线式：

text
rho = x * cos(theta) + y * sin(theta)

rho 是原点到直线的垂距，theta 是这条垂线与 x 轴的夹角。theta 取 [0, π)，rho 取 [-D, D]，D 是图像对角线长度。任意直线在 (rho, theta) 平面唯一对应一点，垂直线、水平线一视同仁。

关键一步是点与线的对偶：

  1. 图像上的点 (x0, y0)，在每个角度下对应参数平面里的一条正弦曲线 rho = x0 cos θ + y0 sin θ。
  2. 共线的 N 个点，N 条正弦曲线交于同一点 (rho*, theta*)，那个点就是直线的参数。
  3. 于是算法变成：开一个二维累加器，theta 离散 theta_num 份、rho 离散 rho_num 份，每个边缘点算一遍 theta → rho 并在格子上 +1，最后取票数超过阈值的格子。
text
for each 边缘点 (x, y):
    for theta in 0 .. π step Δθ:
        rho = x * cos(theta) + y * sin(theta)
        acc[round(rho / Δρ), round(theta / Δθ)] += 1
找 acc 里超过阈值的局部极大值 → 每条对应一条直线

累加器大小由两个分辨率参数决定。theta 步长常见取 np.pi / 180（1 度），rho 步长默认 1 像素。一张 1000×1000 的图 D ≈ 1414，rho 分 2829 档、theta 分 180 档，累加器 50 万格，单张图的开销。

HoughLines 的签名（原文为 C++）：

text
cv2.HoughLines(image, rho, theta, threshold[, lines[, srn[, stn[, min_theta[, max_theta]]]]])

返回 ndarray 形状 (N, 1, 2)，每行 (rho, theta)，rho 以像素计、theta 以弧度计。画图得自己转回直角坐标，还要往图像外延伸足够远：

python
lines = cv2.HoughLines(edges, 1, np.pi / 180, 150)
out = img.copy()
if lines is not None:
    for rho, theta in lines[:, 0]:
        a, b = np.cos(theta), np.sin(theta)
        x0, y0 = a * rho, b * rho              # 直线上离原点最近的点
        # 沿方向 (-b, a) 往两边各延伸 1000 像素
        cv2.line(out, (int(x0 + 1000 * -b), int(y0 + 1000 * a)),
                 (int(x0 - 1000 * -b), int(y0 - 1000 * a)), (0, 0, 255), 2)

(-b, a) 是直线的单位方向向量，与法线 (a, b) 正交。1000 比图对角线还大，保证线横穿整张图，不会被裁在中间。

十四、标准霍夫与概率霍夫的差别 #

HoughLinesP 的签名（原文为 C++）：

text
cv2.HoughLinesP(image, rho, theta, threshold[, lines[, minLineLength[, maxLineGap]]])

rho、theta 一般固定 1 和 np.pi/180，真正要调的是后三个：

参数 含义 经验起点
threshold 累加器里一条直线至少拿到多少票 图宽的 1/10 到 1/5，100 起步
minLineLength 短于这个长度的线段直接丢 图像短边的 1/10，200 起步
maxLineGap 同一条线上两段之间允许的最大间隙 5~20，噪声大就往大调

minLineLength 和 maxLineGap 要一起看。边缘被噪点打断 15 像素：maxLineGap = 10 时变成两条独立线段，各自短于 minLineLength，两条全丢；maxLineGap = 20 时接成一条，长度够了就留下。原文第 402 行说「一条线段长度大于这个值会被视为两条分开的线段」，主语说反了，是间隙大于 maxLineGap 才会分开。

HoughLinesP 返回 ndarray 形状 (N, 1, 4)，每行 x1, y1, x2, y2。三个细节：

  • 没检测到线时返回 None，必须判空，直接 len() 抛 TypeError。
  • 第二维固定是 1，所以写 for line in lines: x1, y1, x2, y2 = line[0]。原文第 392 行的写法是对的。
  • 同一组边缘点常给出多条几乎重合的线段，要按角度和截距聚类去重。
python
edges = cv2.Canny(blur, 50, 150)
lines = cv2.HoughLinesP(edges, 1, np.pi / 180, threshold=100,
                        minLineLength=80, maxLineGap=10)

out = img.copy()
if lines is not None:
    print('线段数:', len(lines), '形状:', lines.shape)   # (N, 1, 4)
    for x1, y1, x2, y2 in lines[:, 0]:
        cv2.line(out, (x1, y1), (x2, y2), (0, 255, 0), 2)
else:
    print('没检测到直线，先检查 edges 里到底有没有边缘')

edges 一定要显示出来看一眼。九成的「霍夫检测不到直线」是因为 edges 本身就是空图：输入不是灰度、阈值方向反了、Canny 阈值给太高。

十五、霍夫直线的参数调节 #

调参有顺序，乱调只会互相打架：

步骤 检查什么 判据 怎么改
1 edges 有多少白像素 占全图 1%~10% 不在区间就回去改 Canny 阈值
2 结果里有没有重复线 角度和位置几乎重合 调大 threshold
3 长直线有没有被切碎 同方向多段首尾相接 调大 maxLineGap
4 短斜线被漏检 目标线段方向明显 调小 minLineLength
5 角度精度不够 测量结果总落整数度 把 theta 降到 np.pi/360

原文第 363 行说「HoughLinesP 会接收一个由 Candy 边缘检测滤波器处理过的单通道二值图像」，「Candy」是「Canny」的错字，全文出现 5 次。

theta 步长最容易被忽略。用 np.pi/180 时角度分辨率就是 1 度，检出的直线角度一定落在整数度上，做精确测角这个误差已经不可接受。降到 np.pi/360（0.5 度）精度翻倍，累加器尺寸也翻倍，内存和耗时一起涨。机位标定这类任务值这个代价。

rho、theta 之外还有 srn、stn 两个多尺度参数（OpenCV 3.0 起），用于多尺度累加器精化，srn=0 表示经典霍夫。日常不用碰，写在附录的未验证项里。

去重的做法：每条线段算出 (theta, rho)，角度容差 2 度、垂距容差 15 像素，落在同一个桶里的只留最长的一条。

python
def dedup_lines(lines, angle_tol=2, rho_tol=15):
    """按角度 + 垂距聚类，每簇只保留最长的线段。"""
    kept = []
    for x1, y1, x2, y2 in ([] if lines is None else lines[:, 0]):
        length = float(np.hypot(x2 - x1, y2 - y1))
        if length == 0:
            continue
        theta = np.degrees(np.arctan2(y2 - y1, x2 - x1)) % 180.0
        rho = abs(x1 * np.sin(np.radians(theta)) - y1 * np.cos(np.radians(theta)))
        for k in kept:
            d = abs(theta - k['theta'])
            if min(d, 180 - d) < angle_tol and abs(rho - k['rho']) < rho_tol:
                if length > k['len']:
                    k.update(theta=theta, rho=rho, len=length,
                             line=(x1, y1, x2, y2))
                break
        else:
            kept.append({'theta': theta, 'rho': rho, 'len': length,
                         'line': (x1, y1, x2, y2)})
    return [k['line'] for k in kept]

容差是经验值，书页边缘、地形条纹这类长直线可以再放宽。

十六、圆检测：霍夫圆变换 #

一个圆要三个参数 (x, y, r)，直接建三维累加器代价太大。OpenCV 用的是 2.4.9 引入、到 4.x 还在的 HOUGH_GRADIENT：用梯度方向把三维搜索降到一维。

  1. 对灰度图做 Canny 边缘检测，param1 就是这里的高阈值。
  2. 对每个非零边缘点，用 Sobel 算子算局部梯度 (gx, gy)。
  3. 梯度方向就是圆的法线方向，圆心落在沿法线的直线上，正反各一条。
  4. 沿两条法线，按候选半径把票投进圆心累加器。
  5. 票数超过 param2 的位置成为候选圆心，再在该位置上的半径投票里定半径。

原文第 404、408 行两次写成「霍尔变换」，是「霍夫」的错字，「霍尔」与 Hough、Hall 都没有关系。

签名（原文为 C++）：

text
cv2.HoughCircles(image, method, dp, minDist[, circles[, param1[, param2[, minRadius[, maxRadius]]]]])

Python 里 circles 不是参数，是返回值。返回 ndarray 形状 (1, N, 3)、dtype float32，每行 (cx, cy, r)；没检测到时返回 None。

参数 含义 默认值 调法
method 检测方法 无 填 cv2.HOUGH_GRADIENT；4.3+ 还有 HOUGH_GRADIENT_ALT
dp 累加器分辨率相对输入图像的分辨率的倒数 无，必填 1 表示同尺寸；2 表示累加器宽高各半，快但精度降
minDist 两个圆心之间的最小距离（像素） 无，必填 小于真实间距会重复检同一个圆，大于间距会漏检
param1 内部 Canny 的高阈值，低阈值自动取一半 100 边缘弱就调低，噪声多就调高
param2 圆心累加器阈值 100 越小检出越多假圆，越大越只留圆度高的目标
minRadius 最小半径 0 已知尺寸就直接卡死，收益最大
maxRadius 最大半径 0 同上；0 表示不限制

dp 的含义原文第 424~427 行讲对了：「检测内侧圆心的累加器图像的分辨率于输入图像之比的倒数」，「于」是「与」的错字。dp=1 时累加器和原图同尺寸，dp=2 时累加器宽高各是原图的一半。

python
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
gray = cv2.medianBlur(gray, 5)          # 圆检测对椒盐噪声特别敏感

circles = cv2.HoughCircles(gray, cv2.HOUGH_GRADIENT, dp=1, minDist=50,
                           param1=100, param2=30, minRadius=20, maxRadius=120)

out = img.copy()
if circles is not None:
    circles = np.uint16(np.around(circles))     # (1, N, 3) float32 -> uint16
    for c in circles[0, :]:
        cx, cy, r = int(c[0]), int(c[1]), int(c[2])
        cv2.circle(out, (cx, cy), r, (0, 255, 0), 2)
        cv2.circle(out, (cx, cy), 2, (0, 0, 255), 3)
    print(f'检出 {circles.shape[1]} 个圆')
else:
    print('没检测到圆')

circles 是 (1, N, 3)，所以 circles[0, :] 才是圆列表。原文第 451 行注释里的 (1, 3, 3) 是那张图检出 3 个圆时的实际形状，不是通用形状。np.uint16(np.around(...)) 不能省：cv2.circle 要整数坐标，float32 的圆心传进去，某些版本会报错或画出偏移。

十七、霍夫圆的参数与调参经验 #

圆检测的参数耦合比直线更紧，四个参数里任何两个都能互相掩盖问题。按影响大小排序：

顺序 参数 调整方向 现象判断
1 minRadius / maxRadius 先卡死一个区间 半径不定就不要先动 param2，否则会被远处的假圆淹没
2 minDist 从最小的圆心间距起步 重复框住同一个圆 → 调大
3 param2 从 30 试到 50 检出的太少 → 调小；假圆一堆 → 调大
4 param1 80~150 边缘断裂、漏检 → 调小；纹理噪声多 → 调高
5 dp 1，然后试 1.5 或 2 只在速度不够时改，改完必须重新校 param2

比调参更划算的一招：先把输入缩小。原文第 444 行 cv2.resize(img, None, fx=0.5, fy=0.5) 这个习惯值得抄——半径减半，minDist 也减半，累加器小四倍，速度上一档，小圆的噪声还被平均掉了。缩完把半径乘回去。

param2 是「假圆」与「漏检」的平衡点，原文第 433 行的解释对：越小越容易检出根本不存在的圆。param2 = 30 在多数中低分辨率图上是个合理起点，加到 50 常常一个不剩。

HOUGH_GRADIENT_ALT（4.3+）在 4.x 文档里被推荐替代老方法，参数含义不同：param1 变成 Canny 高阈值，param2 变成圆心与半径的拟合贴合度（perfectness），0.9 更严格、0.8 更宽松。这一项不在原素材里，也没在本机验证。

十八、轮廓拟合：fitLine / fitEllipse #

霍夫是「投票式」，另一类是「拟合式」：已知一堆点，求最贴合这些点的直线或椭圆。

cv2.fitLine(points, distType, param, reps, aeps) 返回 (vx, vy, x0, y0)，即方向向量和线上一点。四个参数：

参数 含义 常用值
distType 距离度量 cv2.DIST_L2（最小二乘）、cv2.DIST_L1、cv2.DIST_HUBER
param 某些距离类型的参数（一般是 C 值） 0，表示自动取值
reps 坐标精度 0.01
aeps 角度精度 0.01

DIST_L2 适合噪声均匀的场景，有离群点就换 DIST_HUBER。fitLine 没有硬性点数下限（2 点就能定一条线），少于 5 个点结果没有统计意义。

python
vx, vy, x0, y0 = (float(v) for v in cv2.fitLine(cnt, cv2.DIST_L2, 0, 0.01, 0.01))
angle = np.degrees(np.arctan2(vy, vx)) % 180.0     # atan2 吃的是 (dy, dx)
print(f'倾角 {angle:.2f} 度')

k = 1000                                            # 沿方向延伸画出来
cv2.line(out, (int(x0 - vx * k), int(y0 - vy * k)),
         (int(x0 + vx * k), int(y0 + vy * k)), (255, 0, 0), 2)

fitLine 的每个返回值都是形状 (1,) 的 float32，不是 Python float。直接传给需要标量的函数，某些版本会抛 TypeError: only size-1 arrays can be converted to Python scalars，所以上面显式转了一次。

cv2.fitEllipse(points) 返回 ((cx, cy), (MA, ma), angle)：中心、长轴与短轴长度（直径，不是半轴）、旋转角。这个元组可以直接喂给 cv2.ellipse。

点数下限 5 是硬性的，少一个就抛：

text
cv2.error: OpenCV(...) error: (-5:Bad argument) in function 'fitEllipse'
> Overload resolution failed: ... requires at least 5 points

在前面过滤里挡掉（第六章的 len(c) >= 5 就是干这个的）。

python
ellipse = cv2.fitEllipse(cnt)              # cnt 至少 5 个点
print('中心/轴长/角度:', ellipse)
cv2.ellipse(out, ellipse, (0, 255, 255), 2)

# fitEllipseAMS / fitEllipseDirect 是 4.x 的变体，拟合准则不同；3.x 上没有，会 AttributeError
if hasattr(cv2, 'fitEllipseDirect'):
    print(cv2.fitEllipseDirect(cnt))

fitEllipse 是代数最小二乘拟合，结果依赖点的采样密度。轮廓点逐像素等距，平坦处密、拐弯处稀，轮廓被切掉一段椭圆就明显跑偏。

十九、最小外接矩形与旋转矩形 #

cv2.minAreaRect(cnt) 返回 ((cx, cy), (w, h), angle) 三元组。angle 的语义要单独说。

原文第 164~166 行的定义：「旋转角度 θ 是水平轴逆时针旋转，与碰到的矩形的第一条边的夹角，并且这个边的边长是 width」，以及「θ ∈ (-90 度, 0]」。这是老版本约定，也是理解 boxPoints 顶点顺序的钥匙：

  • w、h 按「与 θ 对应的那条边」「与之垂直的另一条边」定义，不按长短定。
  • θ 为负，表示矩形从水平方向往顺时针转了多少度。

cv2.boxPoints(rect) 返回 4 个顶点，形状 (4, 2)，dtype float32。顺序在实现里固定（从与 θ 对应的边起），但不要依赖顺序：把它当无序点集，要排序自己按 x 或角度排。

boxPoints 返回浮点，传给 drawContours 前要转整型。原文第 153 行写的是 np.int0(box)，np.int0 在 NumPy 1.24 起已移除，新版本直接 AttributeError: module 'numpy' has no attribute 'int0'，应写 np.int32(box) 或 box.astype(np.int32)。

python
rect = cv2.minAreaRect(cnt)
(cx, cy), (rw, rh), angle = rect
box = np.int32(cv2.boxPoints(rect))        # 替代废弃的 np.int0
cv2.drawContours(out, [box], 0, (255, 0, 0), 2)

# 统一到「长边在前、角度归到 0~90 度」，便于横向比较
if rw < rh:
    rw, rh, angle = rh, rw, angle + 90.0
rect_area = rw * rh
fill_ratio = cv2.contourArea(cnt) / rect_area if rect_area else 0.0
print(f'中心 {(cx, cy)}, 边长 {(rw, rh)}, 角度 {angle:.1f} 度, 填充比 {fill_ratio:.3f}')

fill_ratio（轮廓面积 / 最小外接矩形面积）衡量「有多像矩形」：理想矩形 1.0，圆 π/4 ≈ 0.785，三角形 0.5。它比 boundingRect 可靠，后者轴对齐，物体一旋转面积就虚高。

minAreaRect 的角度语义在 4.5.1 前后变过（官方文档写明返回值不一致），依赖角度前先拿一个已知矩形打印一次，比查文档省事。

函数 矩形方向 面积 适用
boundingRect 永远轴对齐 ≥ 最小外接矩形 裁剪 ROI、给检测框画框
minAreaRect 跟随物体主方向 最小 量尺寸、算倾角、做倾斜校正

二十、一个完整的形状识别流程 #

把上面所有零件串起来。输入一张白底图形卡片，输出每个物体的类型、中心、尺寸、倾角。

python
import cv2
import numpy as np


def find_contours_any(img, mode=cv2.RETR_EXTERNAL, method=cv2.CHAIN_APPROX_SIMPLE):
    """OpenCV 3/4 通用包装。"""
    result = cv2.findContours(img, mode, method)
    contours, hierarchy = ((result[1], result[2]) if len(result) == 3
                           else (result[0], result[1]))
    if hierarchy is None:
        hierarchy = np.full((1, len(contours), 4), -1, dtype=np.int32)
    return contours, hierarchy


def describe(cnt):
    """返回描述字典；退化轮廓只给能给的字段。"""
    peri, area = cv2.arcLength(cnt, True), cv2.contourArea(cnt)
    (cx, cy), (mw, mh), _ = cv2.minAreaRect(cnt)
    info = {'area': area, 'bbox': cv2.boundingRect(cnt), 'center': (cx, cy),
            'vertices': None, 'shape': 'degenerate', 'circularity': 0.0}
    if peri <= 0:
        return info

    info['circularity'] = 4.0 * np.pi * area / (peri * peri)
    n = info['vertices'] = len(cv2.approxPolyDP(cnt, 0.02 * peri, True))
    if n == 3:
        info['shape'] = 'triangle'
    elif n == 4:
        info['shape'] = 'square' if min(mw, mh) / max(mw, mh) > 0.9 else 'rectangle'
    elif n in (5, 6):
        info['shape'] = {5: 'pentagon', 6: 'hexagon'}[n]
    elif info['circularity'] > 0.85:
        info['shape'] = 'circle'
    else:
        info['shape'] = f'polygon({n})'
    return info


def main(path):
    img = cv2.imread(path, cv2.IMREAD_COLOR)
    if img is None:
        raise SystemExit(f'读不到图: {path}')

    blur = cv2.GaussianBlur(cv2.cvtColor(img, cv2.COLOR_BGR2GRAY), (5, 5), 0)
    thresh = cv2.threshold(blur, 0, 255,
                           cv2.THRESH_BINARY_INV + cv2.THRESH_OTSU)[1]
    kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (3, 3))
    thresh = cv2.morphologyEx(thresh, cv2.MORPH_CLOSE, kernel, iterations=2)

    contours, _ = find_contours_any(thresh, cv2.RETR_EXTERNAL,
                                    cv2.CHAIN_APPROX_SIMPLE)
    img_area = thresh.shape[0] * thresh.shape[1]
    out = img.copy()
    kept = []

    for c in contours:
        if not 200 <= cv2.contourArea(c) <= 0.9 * img_area:
            continue
        if cv2.arcLength(c, True) <= 0:
            continue
        info = describe(c)
        kept.append((c, info))

        x, y, bw, bh = info['bbox']
        cv2.rectangle(out, (x, y), (x + bw, y + bh), (0, 200, 0), 1)
        cv2.drawContours(out, [np.int32(cv2.boxPoints(cv2.minAreaRect(c)))],
                         0, (255, 0, 0), 2)
        cx, cy = int(info['center'][0]), int(info['center'][1])
        cv2.circle(out, (cx, cy), 3, (0, 0, 255), -1)
        cv2.putText(out, info['shape'], (x, max(y - 6, 12)),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.5, (0, 0, 255), 1, cv2.LINE_AA)

    for i, (_, info) in enumerate(kept):
        print(f"[{i}] {info['shape']:<12} 顶点={info['vertices']} "
              f"面积={info['area']:.0f} 圆度={info['circularity']:.3f} "
              f"中心=({info['center'][0]:.0f},{info['center'][1]:.0f})")
    cv2.imwrite('shapes_out.png', out)
    print(f'共识别 {len(kept)} 个形状')


if __name__ == '__main__':
    main('shapes.jpg')

可替换的档位：二值化换成 Canny + 闭运算就是边缘主导的场景；RETR_EXTERNAL 换 RETR_TREE 就能数孔洞；describe 里那串 if 换成 cv2.matchShapes 打模板分就能判不规则形状；要矫正倾角，把 minAreaRect 的角度归一化后接 cv2.getRotationMatrix2D + cv2.warpAffine。

一个隐含假设要写出来：这套分支依赖「物体是白底上的实心色块，且不互相粘连」。粘连的两个三角形会被当成一个六边形，这是形态学和轮廓法共同的边界，越过它得上分水岭（见 图像分割与频域分析：GrabCut、分水岭与傅里叶变换）。
