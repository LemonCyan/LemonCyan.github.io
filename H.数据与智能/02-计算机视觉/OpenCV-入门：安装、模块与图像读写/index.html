一、OpenCV 是什么：它解决了什么问题 #

裸写 C 或 Python 处理位图，你会陷在四件事里：解码 bmp/jpeg/png 的字节流、按行步长遍历像素、给每个算法抄一遍 SIMD 加速、把结果画到窗口里看一眼。OpenCV（Open Source Computer Vision Library）把这四件事打包成了统一接口：一个跨平台的 Mat 矩阵容器（图像就是它，带上行、列、通道、步长、深度）、2500 多个算法实现、编解码层 imgcodecs（一个 imread 吃掉 bmp/jpeg/png/tiff/webp）、显示层 highgui（三行代码弹出窗口）、视频层 videoio（把摄像头和视频文件抽象成同一个「读一帧」接口）、以及 Python 里一句 import cv2 就能用的语言绑定。

许可方面，OpenCV 本体是 Apache 2.0 [^1]，opencv-python 打包脚本是 MIT。商用没有授权障碍，这一点和某些非自由算法库不同。

它不适合什么：OpenCV 不是深度学习框架。4.x 里虽有 dnn 模块能加载 ONNX 等模型做推理，但训练要靠 PyTorch、TensorFlow。它也不是图像编辑器，画个圆、写个字的绘图 API 只是给调试用的。

二、安装：pip 与 conda 两条路 #

pip：现在的主流方式 #

opencv-python 是预编译 wheel，装完就有静态链接好的 OpenCV 二进制，不需要你再装 OpenCV 本体 [^1]。四个包名只能选一个，它们共用 cv2 命名空间，混装会互相覆盖：

pip 包名 含主模块 含 contrib 扩展模块 依赖 GUI 库 适用场景
opencv-python 是 否 是 桌面开发，需要 imshow
opencv-contrib-python 是 是 是 桌面开发，要用额外算法
opencv-python-headless 是 否 否 服务器、Docker、云函数
opencv-contrib-python-headless 是 是 否 服务器 + 扩展模块

用户同时装了几种会出「同一模块两个来源」的怪问题，官方给的处理办法是全部 pip uninstall 后只留一个 [^1]。

bash
python -m pip install --upgrade pip          # 先保证 pip ≥ 19.3，否则 manylinux2014 轮子装不上
pip -V

pip install opencv-python                    # 桌面环境，只装主模块
pip install opencv-contrib-python            # 需要 contrib 里的额外算法
pip install opencv-python-headless           # 服务器 / Docker，不需要 imshow
pip install "opencv-python==4.12.0.88"       # 钉住版本，行为可复现

版本号的四段含义是 cv_major.cv_minor.cv_revision.package_revision，最后一段是这个 PyPI 打包仓库自己的修订号 [^1]。4.12.0.88 里的 88 不是 OpenCV 的补丁号，别拿它当「OpenCV 4.12.88」。

conda #

conda 渠道有两条：官方 defaults 和社区 conda-forge。今天能用的是 conda install -c conda-forge opencv，或者显式指定频道的 conda install conda-forge::opencv，后者能避免和 defaults 的同名包混淆。

conda-forge 的 opencv 包最新版本是 5.0.0，历史版本包含 2.4.12、2.4.13、3.1.0、3.2.0、3.4.1 一直到 4.13.0 [^2]。跟 pip 包相比它把库拆得更细，libopencv、py-opencv 分开，opencv 本体基本是个元包。

别再用 binstar.org 的老命令 #

网上流传最广的一条命令是 conda install -c https://conda.binstar.org/menpo opencv，它已经失效：binstar.org 是 Anaconda.org 的旧域名，不再作为 conda 频道提供解析。menpo 频道的 opencv 包只发布过 2.4.9.1 和 2.4.11 两个版本 [^3]，OpenCV 3 的构建换了包名放在 menpo/opencv3 下，只有 3.1.0 和 3.2.0 [^3]。即使换成 conda install -c menpo opencv，拿到的也是 OpenCV 2.4.11 的 Python 2.7 构建，没有实用价值。

版本分叉要记住：3.x 与 4.x、4.x 与 5.x 之间的 API 差异比本文覆盖的多，装的时候钉住大版本，别让 CI 里飘。

验证 #

最小验证脚本，参数给全，逐项打印：

python
import cv2
import numpy as np

print("cv2 版本:", cv2.__version__, "是否含 GUI:", "GUI: NONE" not in cv2.getBuildInformation())
print("构建信息前 400 字符:\n", cv2.getBuildInformation()[:400])   # CPU baseline 与 dispatch 列表在这里

img = np.full((6, 8, 3), 128, dtype=np.uint8)     # 6 行 8 列，中灰
img[0:2, 0:3] = (255, 255, 255)                  # 左上角填白
print("形状:", img.shape, "元素总数:", img.size, "类型:", img.dtype)

gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)     # imgproc 能跑通
print("灰度形状:", gray.shape, "灰度左上角:", int(gray[0, 0]))   # (6, 8) 255

cv2.__version__ 打印的是 OpenCV 本体版本，例如 4.14.0。要在日志里区分 wheel 打包版本和 OpenCV 本体版本时，两个都打出来 [^1]。getBuildInformation() 里的 CPU baseline 与 dispatch 列表是判断 NEON、AVX 有没有生效的唯一依据，ARM 板子上先跑这一句。另有一条常被忽略的提示：预编译 wheel 全是 CPU-only 构建，要用 CUDA 后端得自己从源码编译，或者用特定发行版提供的构建 [^1]。

四、OpenCV 的模块划分 #

OpenCV 按顶层目录切模块，每个模块编译成一个库，Python 绑定里则平铺在 cv2 命名空间下。核心的几个：

模块 职责 Python 里怎么用
core 基础数据结构 Mat、Scalar、Point、MatExpr 矩阵表达式、基本数学运算、solve、SVD、DFT/DCT cv2.Mat 不暴露，矩阵直接用 NumPy；cv2.Scalar、cv2.norm 等可见
imgproc 图像处理算法：滤波、形态学、几何变换、颜色空间、直方图、轮廓、分割 cv2.GaussianBlur、cv2.cvtColor、cv2.resize、cv2.findContours
imgcodecs 图像文件读写 cv2.imread、cv2.imwrite、cv2.imdecode
videoio 视频与摄像头 I/O cv2.VideoCapture、cv2.VideoWriter
highgui 窗口、鼠标、滑动条 cv2.imshow、cv2.waitKey、cv2.namedWindow
video 运动估计、背景差分、跟踪 cv2.calcOpticalFlowFarneback、cv2.createBackgroundSubtractorMOG2
calib3d 相机标定、立体视觉、单应矩阵 cv2.calibrateCamera、cv2.findHomography
features2d 特征检测与描述、匹配 cv2.SIFT_create、cv2.BFMatcher
objdetect 级联分类器、二维码、条形码 cv2.CascadeClassifier、cv2.QRCodeDetector
dnn 加载并推理外部深度模型 cv2.dnn.readNetFromONNX
photo 计算摄影：去噪、修复、HDR cv2.inpaint、cv2.createMergeMertens
stitching 全景拼接 cv2.Stitcher_create
ml 传统机器学习：SVM、KNN、决策树、 boosting cv2.ml.SVM_create
flann 近似最近邻搜索 cv2.FlannBasedMatcher
contrib 社区扩展，独立仓库 opencv_contrib，需装 opencv-contrib-python 例如 cv2.xfeatures2d、cv2.ximgproc

contrib 不是 OpenCV 主仓库的一部分，是 opencv_contrib 仓库编译进来的一批额外模块，只出现在 opencv-contrib-python 系列包里 [^1]。这就是为什么同样写 cv2. 前缀的代码，在一台机器上能跑、在另一台报 AttributeError。

依赖方向是单向的：imgproc 依赖 core，imgcodecs 依赖 core，highgui 同时依赖 imgcodecs 和 videoio（见 highgui 头文件的 include 段）。所以你没法只装 imgproc 而不装 core。

五、core 模块：Mat 与基本运算 #

Mat 的数据布局 #

Mat 是 OpenCV 的核心数据结构，一个 n 维稠密数组，支持多通道。头部字段：data（指向像素数据的裸指针）、dims（维数，图像一般是 2）、rows / cols、size（各维长度）、step（每一行占多少字节，不是元素个数 [^4]）、elemSize()（每个像素含所有通道占多少字节）、channels() / depth() / type()。

关键在 step。一张 8 位三通道、宽 640 的图，一行是 640×3 = 1920 字节，step[0] = 1920。如果这块 Mat 是从大图裁出来的 ROI，物理行宽会大于逻辑宽度，step[0] 就大于 cols * elemSize()。构造时若省略 step，AUTO_STEP 会算成 cols * elemSize()，等于假设没有行尾填充 [^4]。手写指针遍历时必须用 step 而不是自己算 cols * 3，否则 ROI 上会错位。isContinuous() 报告内存是否连续，Mat::create 新建的矩阵总是连续的，从矩阵里切出来的子矩阵不连续 [^4]；连续时可以把整块内存当一个超长一维数组处理，OpenCV 内部就这么优化。

type() 与深度、通道的组合 #

type() 是一个整数，编码了「每通道元素大小 + 通道数」：

类型宏 每通道字节 通道数 单像素字节 典型用途
CV_8UC1 1 1 1 灰度图、二值掩码
CV_8UC2 1 2 2 BGR565 等打包格式
CV_8UC3 / CV_8UC4 1 3 / 4 3 / 4 BGR / BGRA
CV_16UC1 / CV_16SC1 2 1 2 16 位深度图、Sobel 中间结果
CV_32SC1 4 1 4 标签图、findContours 的输出
CV_32FC1 4 1 4 归一化数据、DCT 结果
CV_64FC1 8 1 8 高精度几何计算

C++ 里写 CV_8UC3，Python 里对应 numpy.uint8 加形状 (h, w, 3)，不需要手写这些宏。要拼类型号可以用 cv2.CV_8UC3 或 cv2.CV_MAKETYPE(cv2.CV_8U, 3)。

C++ 侧的 Mat 与矩阵表达式 #

原文提供的是 C++ 示例，保留它的写法：

cpp
// 原文为 C++ 示例
Mat image = imread("image.jpg");   // 读取图像并存储到 Mat
imshow("Image", image);            // 显示

Mat A = Mat::ones(3, 3, CV_8UC1);
Mat B = Mat::zeros(3, 3, CV_8UC1);
Mat C = A + B;                     // 逐元素相加，走 MatExpr

A + B 返回的不是 Mat，是 MatExpr 惰性表达式，赋值给 Mat 时才求值。矩阵表达式支持加减、标量运算、逐元素 mul 与 div、矩阵乘 *、转置 t()、求逆 inv()、比较运算、位运算、min/max/abs，其中比较运算返回 8 位单通道掩码，元素为 255 或 0 [^4]。这段是纯 C++ 概念，Python 里 NumPy 已经提供了等价且更顺手的矩阵运算，MatExpr 不会暴露出来。

Python 里的矩阵运算怎么落地 #

python
import cv2
import numpy as np

m1 = np.array([[1, 2], [3, 4]], dtype=np.float32)
m2 = np.array([[0, 1], [1, 0]], dtype=np.float32)
print("逐元素:", np.multiply(m1, m2).tolist())   # [[0.0, 2.0], [3.0, 0.0]]
print("矩阵乘:", (m1 @ m2).tolist())             # [[2.0, 1.0], [4.0, 3.0]]
print("L2 范数:", cv2.norm(m1, cv2.NORM_L2), "均值:", cv2.mean(m1))

逐元素乘法用 np.multiply，@ 和 np.dot 是矩阵乘，两者别混。cv2.NORM_L2、NORM_L2SQR、NORM_L1、NORM_INF、NORM_HAMMING 在 core 头文件的 NormTypes 枚举里分别是 4、5、2、1、6 [^5]，汉明范数后面讲相似度还要用。

imgproc 是 OpenCV 里体量最大的模块，Python 里你调的函数九成落在它身上。按子领域分块看：

表里的函数在 Python 里都加 cv2. 前缀。滤波与边缘检测、分割与频域这两块的具体用法在本目录另外两篇里展开，这里只给最常用的几个，代码都能直接跑。原文给的是 C++ 示例，我补了 Python 版：

python
import cv2
import numpy as np

rng = np.random.default_rng(7)                      # 造一张带噪声的测试图，不依赖外部文件
img = np.full((120, 160, 3), 90, dtype=np.uint8)
cv2.rectangle(img, (40, 30), (120, 90), (200, 200, 200), -1)
img = np.clip(img.astype(np.int16) + rng.normal(0, 12, img.shape).round().astype(np.int16), 0, 255).astype(np.uint8)

blurred = cv2.GaussianBlur(img, (5, 5), 0)          # 5x5 核，sigmaX=0 表示由核宽自动推算
median = cv2.medianBlur(img, 5)                     # 孔径取 5，必须是大于 1 的奇数
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
edges = cv2.Canny(gray, 50, 150, apertureSize=3)    # 低阈值 50，高阈值 150
_, thresh = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)
otsu_val, _ = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)   # Otsu 自动阈值
print("形状:", blurred.shape, median.shape, edges.shape, "Otsu 阈值:", otsu_val)

对应的 C++ 原文写法如下，参数顺序和 Python 一致，只是输出参数在中间：

cpp
// 原文为 C++ 示例
GaussianBlur(image, blurred_image, Size(5,5), 0);      // 平滑，减噪
medianBlur(image, smoothed_image, 5);                  // 去椒盐噪声
Canny(image, edges, 50, 150);                          // 边缘检测
threshold(image, thresh, 127, 255, THRESH_BINARY);     // 阈值化

阈值类型：THRESH_BINARY=0、THRESH_BINARY_INV=1、THRESH_TRUNC=2、THRESH_TOZERO=3、THRESH_TOZERO_INV=4，另有可叠加的 THRESH_OTSU=8、THRESH_TRIANGLE=16 [^6]。插值标志：INTER_NEAREST=0、INTER_LINEAR=1、INTER_CUBIC=2、INTER_AREA=3、INTER_LANCZOS4=4 [^6]。

七、highgui 与 videoio：显示与采集 #

一个负责把图放到屏幕上，一个负责把视频流读成帧序列。入门阶段只需记住几条硬规则。

highgui 的窗口标志 #

cv2.namedWindow 的 flags 来自 WindowFlags 枚举 [^7]：

常量 值 效果
WINDOW_NORMAL 0x00000000 用户可以自由缩放窗口，也能把全屏窗口切回普通大小
WINDOW_AUTOSIZE 0x00000001 用户不能缩放，窗口大小跟随图像
WINDOW_OPENGL 0x00001000 创建支持 OpenGL 的窗口
WINDOW_FULLSCREEN 1 全屏
WINDOW_FREERATIO 0x00000100 图像尽量铺开，不约束宽高比
WINDOW_KEEPRATIO 0x00000000 保持宽高比

namedWindow 的默认参数是 WINDOW_AUTOSIZE，同名窗口已存在时不重复创建、什么都不做 [^7]。Qt 后端的默认组合是 WINDOW_AUTOSIZE | WINDOW_KEEPRATIO | WINDOW_GUI_EXPANDED。原文这里有个字面错误：它写的 cv2.WINDOW_ATTOSIZE 拼错了，正确是 cv2.WINDOW_AUTOSIZE；WINDOW_FREETATIO 同样拼错，正确是 WINDOW_FREERATIO。

videoio 的两个类 #

VideoCapture 和 VideoWriter 覆盖视频文件与摄像头。摄像头的构造参数是设备索引（默认相机传 0），视频文件传路径字符串，也可以传图片序列模板（如 img_%02d.jpg）或视频流 URL [^8]。

VideoCapture.get() 返回驱动上报值，链路是「VideoCapture → API 后端 → 操作系统 → 驱动 → 硬件」，任何一层都会给出和真实值不同的数，所以摄像头帧率读出来是 0 或怪值都属于正常情况 [^8]。

摄像头捕获的完整写法在《图像采集与滤波边缘检测》里，这里只演示视频文件的逐帧读写，确保本篇的读图链路完整：

python
import cv2

cap = cv2.VideoCapture("input.avi")             # 换成你机器上真实存在的文件
if not cap.isOpened():
    raise SystemExit("打不开这个视频文件")

fps = cap.get(cv2.CAP_PROP_FPS)                 # CAP_PROP_FPS = 5
w = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))      # CAP_PROP_FRAME_WIDTH = 3
h = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))     # CAP_PROP_FRAME_HEIGHT = 4
print("fps =", fps, "size =", (w, h))

writer = cv2.VideoWriter("out.mp4", cv2.VideoWriter_fourcc(*"mp4v"), fps, (w, h))
count = 0
while True:
    ok, frame = cap.read()
    if not ok:
        break                                    # 读到结尾，frame 是 None
    writer.write(frame)                          # 帧尺寸必须与构造时严格一致
    count += 1
writer.release()
cap.release()                                    # 两个都要 release，否则文件没写完
print("写入了", count, "帧")

九、图像的数据表示：BGR 与通道顺序 #

这是 OpenCV 最容易让人翻车的一个约定。彩色图的通道顺序是 BGR，不是 RGB。 imread 读进来是 BGR，imwrite 期望写出去的也是 BGR，imshow 显示时也按 BGR 解释 [^9]。绘图函数的 Scalar 构造顺序同样是蓝、绿、红、可选 alpha [^6]。跟其它库打交道时这个差异立刻暴露：

来源 通道顺序 转 OpenCV 要做什么
cv2.imread BGR 不用动
PIL / Pillow Image.open RGB cv2.cvtColor(np.asarray(img), cv2.COLOR_RGB2BGR)
matplotlib imshow 输入 RGB 送进去之前 cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
浏览器 canvas getImageData RGBA cv2.cvtColor(arr, cv2.COLOR_RGBA2BGR)
多数深度学习框架预处理 RGB 训练时按 RGB，推理时也要按 RGB

cv2.COLOR_RGB2BGR 和 cv2.COLOR_BGR2RGB 是同一个枚举值 4，因为互换方向只是同一个翻转操作 [^6]。同理 COLOR_RGBA2RGB 与 COLOR_BGRA2BGR 都是 1（去掉 alpha），COLOR_RGB2RGBA 与 COLOR_BGR2BGRA 都是 0（加 alpha）。

三类取值范围 #

同一个 cvtColor，输入深度不同，能表达的数值范围就不同 [^10]：cv2.CV_8U 是 0 到 255，cv2.CV_16U 是 0 到 65535，cv2.CV_32F 是 0 到 1。线性变换对范围不敏感，非线性变换（例如 BGR 转 Luv）会把输入范围当外部信息用。8 位图不缩放直接转 32 位浮点，函数按 0 到 255 解释而不是 0 到 1，结果就错了 [^10]。归一化必须先做。

python
import cv2
import numpy as np

img = np.full((4, 4, 3), 128, dtype=np.uint8)
luv_wrong = cv2.cvtColor(img.astype(np.float32), cv2.COLOR_BGR2Luv)          # 错：仍按 0..255 解释
luv_ok = cv2.cvtColor(img.astype(np.float32) / 255.0, cv2.COLOR_BGR2Luv)     # 对：先缩到 0..1
print("L 通道均值 错/对:", float(luv_wrong[:, :, 0].mean()), float(luv_ok[:, :, 0].mean()))

图像与原始字节互转 #

Mat 底层是一块连续字节，Python 里用 bytes / bytearray 在两个世界之间搬运。网络收到 JPEG 字节流时就得走这条路：

python
import cv2
import numpy as np

canvas = np.zeros((32, 48, 3), dtype=np.uint8)
canvas[8:24, 12:36] = (30, 160, 220)
ok, buf = cv2.imencode(".png", canvas)          # 第三参数可传格式选项
assert ok, "编码失败"
raw = buf.tobytes()
print("PNG 字节数:", len(raw), "前 4 字节:", raw[:4])

restored = cv2.imdecode(np.frombuffer(raw, dtype=np.uint8), cv2.IMREAD_COLOR)
print("解码回形状:", restored.shape, "像素一致:", bool((restored == canvas).all()))

flat = bytearray(canvas.tobytes())              # 摊平成字节，长度 32*48*3 = 4608
print("摊平后长度:", len(flat), "可还原为:", np.frombuffer(bytes(flat), dtype=np.uint8).reshape(32, 48, 3).shape)

imencode 的第三参数是格式选项列表，例如 JPEG 质量 [cv2.IMWRITE_JPEG_QUALITY, 90]、PNG 压缩级 [cv2.IMWRITE_PNG_COMPRESSION, 3] [^11]。直接操作像素有三种写法，效率从高到低是切片、单像素赋值、item/itemset；item 索引顺序是 (行, 列, 通道)，通道 0、1、2 对应 B、G、R，itemset 新代码别再用，NumPy 已不推荐。

十、读图：imread 与它的 flags #

cv2.imread(filename, flags) 的完整签名是 Mat imread(const String& filename, int flags = IMREAD_COLOR_BGR) [^11]。第二个参数决定解码后给你什么。

flags 枚举全表 #

ImreadModes 的取值（4.14.0 头文件）[^11]：

常量 值 行为
IMREAD_UNCHANGED -1 按原样返回，保留 alpha 通道；忽略 EXIF 方向
IMREAD_GRAYSCALE 0 强制转单通道灰度，走编解码器内部转换
IMREAD_COLOR_BGR / IMREAD_COLOR 1 强制转 3 通道 BGR，默认值
IMREAD_ANYDEPTH 2 输入是 16 位或 32 位就保持该深度，否则转 8 位
IMREAD_ANYCOLOR 4 按图像本身的彩色格式读取
IMREAD_LOAD_GDAL 8 用 GDAL 驱动读，支持栅格与矢量格式
IMREAD_REDUCED_GRAYSCALE_2 / _COLOR_2 16 / 17 灰度 / BGR + 尺寸缩到 1/2
IMREAD_REDUCED_GRAYSCALE_4 / _COLOR_4 32 / 33 灰度 / BGR + 尺寸缩到 1/4
IMREAD_REDUCED_GRAYSCALE_8 / _COLOR_8 64 / 65 灰度 / BGR + 尺寸缩到 1/8
IMREAD_IGNORE_ORIENTATION 128 不按 EXIF 方向旋转
IMREAD_COLOR_RGB 256 强制转 3 通道 RGB

几个必须知道的细节。IMREAD_COLOR_BGR 与 IMREAD_COLOR_RGB 不能同时设 [^11]；IMREAD_COLOR_RGB 是 4.x 后期才加的，3.x 没有这个常量，跨版本代码别用它。IMREAD_UNCHANGED 会同时忽略 EXIF 方向，用 -1 读手机照片方向会歪，要正方向又想保留浮点精度（例如 PFM 文件）得显式传 IMREAD_ANYDEPTH | IMREAD_ANYCOLOR 而不是 -1 [^11]。JPEG 不受 IMREAD_ANYDEPTH 影响，它本身就是 8 位；PNG 每通道支持 8 位或 16 位，16 位 PNG 用 IMREAD_UNCHANGED 读出来是 uint16 的 CV_16UC3。flags 是位掩码，可叠加，按位或即可：IMREAD_ANYDEPTH | IMREAD_ANYCOLOR = 2 | 4 = 6。原文那句「冲突时自动采用较小数字值对应的加载方式」是它自己总结的经验，头文件里没有这条规则，本文不采用。

十一、显示：imshow 与 waitKey #

python
import cv2
import numpy as np

三条硬规则，每条都对应一个真实故障。

imshow 之后必须调 waitKey 或 pollKey。 这两个是 HighGUI 里唯一能取并处理 GUI 事件的入口，不调图像不会画出来，窗口还会卡死 [^7]。waitKey(0) 无限等按键，适合看图；waitKey(25) 等约 25 毫秒，适合放视频帧。

waitKey 返回按键码，没按键返回 -1。 判断退出要写 if cv2.waitKey(1) == 27: break（27 是 ESC），不能写 if cv2.waitKey(1):，很多键码值非零但并不是你想退出的键。

imshow 会按图像深度做缩放 [^7]：8 位无符号原样显示；16 位无符号除以 256，把 [0, 255×256] 映射到 [0, 255]；32 位或 64 位浮点乘以 255，把 [0, 1] 映射到 [0, 255]；32 位整数不再做转换，因为变换方式有歧义，得自己先转成 8 位无符号。最后这条是版本差异点：OpenCV 3 的文档里 32 位整数按「除以 256」处理，4.x 直接拒绝处理，从 3.x 迁到 4.x 时遇到「一片全黑或全白」先查是不是把 CV_32S 直接丢给了 imshow。

窗口比屏幕还大时要先 cv2.namedWindow("demo", cv2.WINDOW_NORMAL) 再 imshow，否则 WINDOW_AUTOSIZE 下窗口固定为图像大小，超出部分看不见 [^7]。waitKey 只在一个 HighGUI 窗口存在且处于活动状态时才工作，多窗口时任意一个活动都行 [^7]。waitKeyEx 返回含方向键、功能键在内的完整键码，waitKey 只返回低字节部分。

imwrite 由扩展名决定编码器，各编码器支持的深度不一样 [^11]：

十三、颜色空间转换 #

cvtColor(src, code, dst=None, dstCn=0) 的四个参数：输入图、转换码、输出图（Python 里可省，直接接返回值）、目标通道数（0 表示由 src 和 code 推导）[^10]。

ColorConversionCodes 的取值（4.14.0 头文件）[^6]：

COLOR_BGRA2BGR 1 BGRA → BGR，去 alpha 8U / 16U / 32F
COLOR_BGR2RGB 4 BGR ↔ RGB 通道翻转 8U / 16U / 32F

几个坑：COLOR_BGR2HSV 的 H 范围是 0 到 180 而不是 0 到 360，这是 8 位存储的取舍，H 除以 2 后能用 1 个字节放下整个色环。要在 HSV 里圈一个红色区间，上下界是 (0, 120, 70) 到 (10, 255, 255)，再加一段 (170, 120, 70) 到 (180, 255, 255)，因为红色跨了 0 和 180 两端。需要 0..255 的完整范围就用 COLOR_BGR2HSV_FULL。Lab 和 Luv 只支持 8U 与 32F 输入，不支持 16U [^6]，手上有 16 位图要先降到 8 位或升到 32 位。COLOR_BGR2BGRA 系列在 4.x 里支持 8U、16U、32F 三种输入，老版本范围更窄，迁移时要验证。

灰度转换的公式与实现 #

教科书公式是 Y = 0.299R + 0.587G + 0.114B，对应 BT.601 的亮度权重。OpenCV 的实现是定点版本 Y = (R * 4899 + G * 9617 + B * 1868 + 8192) >> 14：三个系数分别等于 0.299 * 16384 = 4899、0.587 * 16384 = 9617、0.114 * 16384 = 1868（取整），加 8192 是四舍五入，右移 14 位是除回 16384 [^12]。这条路径覆盖 8U、16U、32F 三种输入。BGRA 不是独立颜色空间，是 BGR 加了不透明度信息，alpha 为 0 表示完全透明，为 255（8 位）表示完全不透明，传统数字图像等价于 alpha 恒为 255。做合成时记住 OpenCV 读图默认会丢掉 alpha（除非用 IMREAD_UNCHANGED），PNG 透明背景读成 IMREAD_COLOR 之后再存盘，透明区域会变成黑色。

颜色空间往返验证 #

python
import cv2
import numpy as np

img = np.zeros((30, 40, 3), dtype=np.uint8)
img[:15, :] = (0, 0, 255)     # BGR，上半纯红

print("灰度:", int(gray[0, 0]))                                          # 76，纯红的亮度
print("HSV :", hsv[0, 0].tolist(), "Lab:", cv2.cvtColor(img, cv2.COLOR_BGR2Lab)[0, 0].tolist())

back = cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)
print("HSV 往返最大误差:", int(np.abs(back.astype(int) - img.astype(int)).max()))

print("合成后上半 BGR:", (img.astype(np.float32) * alpha).astype(np.uint8)[0, 0].tolist())

十四、尺寸变换与 ROI 裁剪 #

resize 的缩放因子与插值 #

cv2.resize(src, dsize, dst=None, fx=0, fy=0, interpolation=INTER_LINEAR)。dsize 给 (宽, 高)，和 NumPy 的 shape 顺序相反，这是新手最高频的错误来源。dsize 传 (0, 0) 时改用 fx、fy 作为缩放因子。插值选择的原则：缩小优先 INTER_AREA，它压制摩尔纹；放大用 INTER_CUBIC 或 INTER_LANCZOS4，代价是慢；要对齐像素网格做标注用 INTER_NEAREST。头文件里写了 INTER_AREA 在缩小场景下能给出无摩尔纹的结果，放大时它退化成接近最近邻 [^6]。几何变换不支持 CV_8S 和 CV_32S，先转 8U 或 32F 再缩放 [^6]。

python
import cv2

十五、为什么需要判断两张图是否相似 #

三个真实场景：去重（相册里的连拍和被压过的同一张图，MD5 只能抓完全相同的文件）、相似推荐与聚类（同一商品的多个角度和背景按视觉归堆）、监控与审核（上万帧里找重复帧或相似帧）。

共性是数据量大、要快、允许误差。逐像素算欧氏距离最准，但每对图要做 H×W×C 次减法平方，图一多就崩。所以工程上用降维后的紧凑表示：压成 64 位哈希，或者压成一条 256 维直方图，再用很便宜的度量比。

十六、哈希算法：aHash、dHash、pHash #

三种算法都基于同一个假设：把图缩到极小尺寸后，留下的是亮度结构，丢掉的是细节噪声。输出都是 64 位。

aHash：均值哈希 #

四步：缩到 8×8（共 64 像素）、转灰度、求 64 个灰度值的平均、按行优先逐像素与均值比较，大于记 1 否则记 0。gray > avg 得到布尔数组，.astype(np.uint8) 变成 0/1，.ravel() 按行优先拍平（第 0 行从左到右，然后第 1 行……），只要两张图用同一套算法顺序就一致。

python
import cv2
import numpy as np

def a_hash(img):
    gray = cv2.cvtColor(cv2.resize(img, (8, 8)), cv2.COLOR_BGR2GRAY)
    return "".join(str(b) for b in (gray > float(gray.mean())).astype(np.uint8).ravel())

SAMPLE = np.zeros((60, 80, 3), dtype=np.uint8)
SAMPLE[:, :40], SAMPLE[:, 40:] = (30, 60, 90), (200, 180, 160)
print(a_hash(SAMPLE))      # 64 位 0/1 串

dHash：差值哈希 #

三步：缩到 9×8（宽度比高度多 1 个像素，得到 8 个可比较的相邻对）、转灰度、每行内 gray[i, j] > gray[i, j+1] 记 1 否则记 0，8 行 × 8 对 = 64 位。切片对比的结果形状正好是 (8, 8)。dHash 编码的是水平方向的梯度符号，对整体亮度偏移不敏感，但保留了边缘走向。

python
def d_hash(img):
    gray = cv2.cvtColor(cv2.resize(img, (9, 8)), cv2.COLOR_BGR2GRAY).astype(np.int16)
    return "".join(str(b) for b in (gray[:, :-1] > gray[:, 1:]).astype(np.uint8).ravel())

print(d_hash(SAMPLE))      # 64 位 0/1 串

pHash：感知哈希 #

五步：缩到 32×32、转灰度、cv2.dct(np.float32(gray)) 做二维离散余弦变换、取左上角 dct[0:8, 0:8] 这 64 个低频系数、与这 64 个系数的均值比较，大于记 1。DCT 的左上角是低频，dct[0, 0] 是直流分量，等于像素和除以边长（cv2.dct 用正交归一化），其余位置对应不同空间频率。人眼对低频结构敏感、对高频细节迟钝，只取左上 8×8 就是主动丢掉高频，所以 pHash 对轻微噪声和重压缩最稳。

python
def p_hash(img):
    gray = cv2.cvtColor(cv2.resize(img, (32, 32)), cv2.COLOR_BGR2GRAY)
    block = cv2.dct(np.float32(gray))[0:8, 0:8]          # DCT 后取左上低频块
    return (block > float(block.mean())).astype(np.uint8).ravel()

SAMPLE[10:20, 10:30] = (255, 255, 255)      # 加一块白，让低频块有梯度
bits = p_hash(SAMPLE)
print(bits.size, "".join(str(int(b)) for b in bits))   # 64 后接 64 位 0/1 串

pHash 的输出是 uint8 数组，不是字符串，和字符串版混用前要统一格式。

十七、汉明距离与相似度阈值 #

64 位哈希之间的差异用汉明距离衡量：两个位串逐位比较，不同的位数就是距离。范围 0 到 64，0 表示完全一致，64 表示每一位都相反 [^13]。字符串版逐位比，整数版异或后数 1 的个数。bit_count() 是 Python 3.10 新增的整数方法，3.9 及以下只能用 bin(x).count("1") 或查表法（64 位拆成 8 个字节，每字节查一张 256 项的位计数表）。C++ 里对应 cv::norm(a, b, NORM_HAMMING)，底层用 POPCNT 指令；NORM_HAMMING = 6，NORM_HAMMING2 = 7 是每两位打包当一位算的变体 [^5]。

python
def cmp_hash(hash1, hash2):
    if len(hash1) != len(hash2):
        return -1                                  # 长度不同代表传参有误
    return sum(1 for a, b in zip(hash1, hash2) if a != b)

def hamming_bits(a: int, b: int) -> int:
    return bin(a ^ b).count("1")                   # 通用写法

def hamming_bits_fast(a: int, b: int) -> int:
    return (a ^ b).bit_count()                     # Python 3.10+

h1, h2 = "0" * 64, "0" * 60 + "1" * 4
x = int(h2, 2)
print(cmp_hash(h1, h2), cmp_hash(h1, "0" * 32), hamming_bits(x, 0), hamming_bits_fast(x, 0))   # 4 -1 4 4

阈值怎么定 #

没有放之四海皆准的阈值。原文给的一组实测值可以当起点：四组图（t1/t2、t1/t3、s1/s2、c1/c2）的三哈希结果分别是 14/19/10、39/33/18、7/23/11、11/29/17 [^13]。其中 s1/s2 被原作者判定为「挺相似的图片」，汉明距离是 7、23、11。从这组数里能读出一条经验：64 位哈希的汉明距离小于 10 可以认为高度相似，10 到 20 之间需要人工复核，超过 20 基本不是同一张图。这个界限是从那一组实测数据归纳的，不是官方推荐值，不同业务得自己标一批样本重定。

阈值方向别搞反：哈希法距离越小越相似，直方图法相似度越大越相似，混在一个条件里判断会得到完全相反的结论。统一成「越大越相似」最省事：

十八、直方图比较法 #

哈希丢掉了颜色分布，直方图正好补这一块。直方图是「每个取值区间有多少像素」的统计，对平移、旋转完全不敏感，对颜色变化敏感。

calcHist 的用法 #

compareHist 的四种方法 #

cv2.compareHist(H1, H2, method) 的 method 来自 HistCompMethods 枚举 [^6]：

常量 值 公式 取值方向 完全相同的结果
HISTCMP_CORREL 0 Σ(H1-Ĥ1)(H2-Ĥ2) / sqrt(Σ(H1-Ĥ1)² · Σ(H2-Ĥ2)²) 越大越相似 1.0
HISTCMP_CHISQR 1 Σ (H1-H2)² / H1 越小越相似 0.0
HISTCMP_INTERSECT 2 Σ min(H1, H2) 越大越相似 与直方图总量相等
HISTCMP_BHATTACHARYYA 3 sqrt(1 - (1/sqrt(Ĥ1·Ĥ2·N²)) · Σ sqrt(H1·H2)) 越小越相似 0.0
HISTCMP_CHISQR_ALT 4 2 · Σ (H1-H2)² / (H1+H2) 越小越相似 0.0
HISTCMP_KL_DIV 5 Σ H1 · log(H1/H2) 越小越相似 0.0

HISTCMP_HELLINGER 是 HISTCMP_BHATTACHARYYA 的同义词，值也是 3 [^6]。4.14.0 的头文件注释里直接写明：OpenCV 算的其实是 Hellinger 距离，它和 Bhattacharyya 系数相关，两者别混着讲。

四种常用方法都动手试一遍：

python
import cv2
import numpy as np

def make(left, right):
    img = np.zeros((40, 40, 3), dtype=np.uint8)
    img[:, :20], img[:, 20:] = left, right
    return img

a, b, c = make((255, 0, 0), (0, 0, 255)), make((250, 5, 5), (5, 0, 250)), make((0, 255, 0), (0, 255, 255))
hists = [cv2.calcHist([im], [0], None, [256], [0, 256]) for im in (a, b, c)]   # b 近 a，c 远 a
ha, hb, hc = hists

for name, m in [("CORREL", cv2.HISTCMP_CORREL), ("CHISQR", cv2.HISTCMP_CHISQR),
                ("INTERSECT", cv2.HISTCMP_INTERSECT), ("BHATTACHARYYA", cv2.HISTCMP_BHATTACHARYYA)]:
    print(f"{name:14s} a-b={cv2.compareHist(ha, hb, m):12.6f}  a-c={cv2.compareHist(ha, hc, m):12.6f}")

能预期到的结果：CORREL 上 a-b 接近 1、a-c 明显更低；CHISQR 上 a-b 接近 0、a-c 更大；INTERSECT 上 a-b 接近直方图总量；BHATTACHARYYA 上 a-b 接近 0。方向相反的两组数不能直接比大小。

两条手写的直方图相似度 #

原文不依赖 compareHist，自己写了两条。第一条是单通道重合度：逐 bin 比较，不等时累加 1 - |h1-h2| / max(h1, h2)，相等时加 1，最后除以 bin 数，值域 0 到 1。第二条把图 resize 到同一尺寸后 cv2.split 成 B、G、R 三个单通道，各自算一遍再取平均。

python
import cv2
import numpy as np

def calculate(img1, img2):
    h1 = cv2.calcHist([img1], [0], None, [256], [0, 256])
    h2 = cv2.calcHist([img2], [0], None, [256], [0, 256])
    return sum(1 - abs(h1[i] - h2[i]) / max(h1[i], h2[i]) if h1[i] != h2[i] else 1
               for i in range(len(h1))) / len(h1)

def classify_hist_with_split(img1, img2, size=(256, 256)):
    img1, img2 = cv2.resize(img1, size), cv2.resize(img2, size)
    return sum(calculate(s1, s2) for s1, s2 in zip(cv2.split(img1), cv2.split(img2))) / 3

a = np.zeros((40, 40, 3), dtype=np.uint8)
a[:, :20] = (10, 20, 30)
print("单通道:", float(calculate(a, a.copy())), "三通道:", float(classify_hist_with_split(a, a.copy())))   # 1.0 1.0

原文的 ranges 写的是 [0.0, 255.0]，我改成了 [0, 256]。8 位图上两者计数结果一样，但 [0, 256] 是头文件用例的写法，语义也更直白：上界开区间，256 正好盖住 255。cv2.split 返回顺序是 B、G、R，先 resize 到同一尺寸是必须的，否则像素总数不同，计数不可比。

INTERSECT 那一行要特别注意：它的公式是 Σ min(H1, H2)，完全没做归一化，两张不同尺寸的图直接比，像素多的那张会天然占优。正确用法是先 cv2.normalize 到相同总量（例如每张除以自己的像素总数），再比。原文手写的 calculate 函数绕开了这个问题，它用的是比值 |h1-h2| / max(h1,h2)，对量级不敏感。

原文的工程实现走的是更简单的路子：遍历所有 itertools.combinations 组合，四路全部算完，只要 n1==0 or n2==0 or n3==0 or n4==1 or n5==1 就判定为重复并把两张图 shutil.move 到输出目录 [^13]。这个判据是「任一路完全一致」，很严，不会误杀，但会漏掉「几乎一样」的重复。大批量跑之前把 O(n²) 的组合数算一下：一万张图是约 5000 万对，每对都算 pHash 的 DCT，时间不可接受，先按文件大小或 aHash 分桶再两两比。

二十、ARM 计算机视觉库：另一条优化路线 #

前面全在讲 OpenCV。如果你把代码部署到 ARM 板子上，还有另一套选择：ARM 官方的计算机视觉库。它和 OpenCV 是两个独立项目，不是 OpenCV 的模块，也不是它的替代品。

它的定位是针对 ARM 架构（ARM CPU 和 Mali GPU）优化的低级软件库，面向图像处理、计算机视觉和机器学习任务 [^14]。关键词是「低级」：它给的是基本运算、卷积核、矩阵乘这类积木，不是 imread、imshow 这种成套的高层接口。许可方面原文写的是「需要获得 MIT 开源许可证，该许可证允许用户自由地使用、修改和分发代码，适用于商业和非商业用途」[^14]，这条表述不准确：MIT 是该库本身采用的许可，不是需要你去「获得」的东西，满足条款（保留版权与许可声明）就能自由使用。这处在附里也列了。

两条加速路径 #

NEON SIMD。NEON 是 ARM 架构里的 SIMD 引擎，一条指令处理多个数据元素。库里的 CPU 实现走 NEON，开发者可以针对目标架构重新编译内置函数，支持 32 位和 64 位代码生成，从而兼容不同的 ARM 处理器 [^14]。NEON 加速的典型任务是视频编解码（H.264 / H.265）、音频解码、图像处理算法（颜色转换、滤镜）、机器学习推理。OpenGL 跨平台这条路上，GPU 版本基于 OpenGL 标准 API 开发，内核程序可以在多种 GPU 架构上运行，靠这个保证可移植性 [^14]。库与操作系统无关，目前已部署在基于 ARM 的 Linux 系统和 Android 片上系统上。

对照着看，OpenCV 内部其实也是同一套思路：它有 hal 硬件加速层，core/cvdef.h 里定义了一整套 CPU 特性枚举 CPU_NEON=100、CPU_NEON_DOTPROD=101、CPU_NEON_FP16=102、CPU_NEON_BF16=103、CPU_SVE=104，走的是运行时分发路线 [^5]。在 ARM 上直接用 OpenCV，NEON 也已经被用上了，ARM CV 库的价值在于「更贴近硬件、更可控、体积更小」，而不是「OpenCV 没用 SIMD」。

周边的四个库 #

原文还点了四个常和 ARM CV 库一起用的项目 [^14]。HPC 是高性能计算库，主要收益是提高仿真吞吐量，让工程团队能并行仿真多个设计方案，和图像处理关系不大，属于同厂商的工具链。Ne10 是开源的、针对 ARM 架构优化的 C 库，包含常用高性能计算函数：数学运算（向量加法、乘法、点积）、矩阵操作（矩阵乘、转置）、变换（快速傅里叶变换 FFT）、实用工具（像素运算、统计函数）；原文给的下载链接指向第三方 fork（github.com/kevinlq/Ne10）而不是 ARM 官方仓库，我按未验证处理，用之前先核对来源。libyuv 专注 YUV 图像缩放与转换，支持 YUV 与 RGB 互转、上采样与下采样、色彩空间转换（如 NV12 到 I420），是视频编解码管线里的常客。Skia 是 Google 的 2D 图形库，用在 Chrome 和 Android 的图形渲染上，支持位图处理（alpha 合成、抗锯齿）、矢量绘制（路径、文字渲染）、图像缩放与压缩。

这四个里 libyuv 和 OpenCV 的重叠最直接（cvtColor 的 YUV 那一票转换码，如 COLOR_BGR2YUV=82）。如果瓶颈是纯 YUV 格式转换，libyuv 往往比走 cvtColor 更合适，因为它不做通用化处理。

维度 OpenCV ARM 计算机视觉库

判断顺序建议这样走：先用 OpenCV 把功能跑通，imread、imshow、cvtColor 能省掉大量胶水代码，原型阶段没有理由不用；再量一下瓶颈落在哪，如果是 imread 解码慢，那跟 NEON 无关，是编解码器的问题，如果是某个卷积或颜色转换吃满 CPU，再考虑换实现；最后确认目标平台的 OpenCV wheel 有没有启用 NEON 分发，cv2.getBuildInformation() 会打出 CPU baseline 和 dispatch 列表，在 ARM 板子上先跑一遍这一行，别在「以为没加速」的假设上重写一遍代码。真的决定换，也要清楚代价：ARM CV 库不给你解码和显示，这两块要么另外拉 libjpeg / libpng / libyuv，要么就在边缘保留一小块 OpenCV。混用是完全正常的工程选择，不是妥协。

二十三、易错点速查 #

通道顺序。imread 出来是 BGR，PIL 是 RGB，matplotlib 要 RGB。任一处漏转颜色就反，用 3 个像素的小图打印一次 [0,0] 的值当场验证。

resize 的 dsize 是 (宽, 高)，NumPy 的 shape 是 (高, 宽)。把变量命名成 w, h 并注释清楚，能少一半 bug。

切片是 [y, x]，Rect 是 (x, y, w, h)。img[100:200, 150:350] 是行 100 到 199、列 150 到 349，写之前想清楚手上的是哪套约定。

ROI 是视图不是拷贝。改 ROI 等于改原图，要独立数据就 .copy()。

imread 失败返回 None，imwrite 失败返回 False。两个都不抛异常，必须自己判。

imshow 后面不跟 waitKey 就看不到图。waitKey 也是取键盘输入的唯一途径。

cvtColor 输入范围要匹配。8 位图转 32 位浮点做非线性变换前，先 /= 255.0。

cv2.findContours 的返回值个数在 3.x 和 4.x 不同。OpenCV 3 返回三个值 (image, contours, hierarchy)，OpenCV 4 返回两个值 (contours, hierarchy)。这是 3 升 4 最常见的崩溃点，3.x 时代的三元解包代码在 4.x 上直接 ValueError: too many values to unpack。要两边都能跑就写 contours, hierarchy = cv2.findContours(...)[-2:]。

IMREAD_UNCHANGED 会忽略 EXIF 方向。手机照片用 -1 读进来会歪，需要方向正确就显式传 IMREAD_ANYDEPTH | IMREAD_ANYCOLOR。

INTERSECT 不做归一化。不同尺寸的直方图直接比，结果偏向像素多的那张，先 normalize 到同一总量。

哈希法距离越小越相似，直方图法越大越相似。混在一个条件里判断会得到完全相反的结论，统一成 1 - d/64 再比。

cv2.split 的返回顺序是 B、G、R，不是 R、G、B。

Python 里的 Mat 就是 NumPy 数组。cv2.Mat 不暴露，所有接受 InputArray 的接口直接吃 np.ndarray，手头有 bytes 或 bytearray 时用 np.frombuffer 转成数组再传。

一个环境只装一个 OpenCV wheel。opencv-python、opencv-contrib-python、*-headless 共用 cv2 命名空间，混装会互相覆盖，报错信息往往和真实原因无关 [^1]。
