人脸这条线上其实有两个问题：找到脸在哪，和认出这是谁。前一个叫检测，后一个叫识别。本篇从 2001 年的 Haar 级联讲到 MTCNN 与 Facenet，把这两个问题分开讲清楚，也把两代方法为什么换掉讲清楚。

讲什么：Haar-like 特征、积分图、AdaBoost 级联、OpenCV 检测实践、PCA 特征脸、MTCNN 三级网络、Facenet 的 Inception ResNet 与三元组损失。

不讲什么：人脸关键点的完整体系、活体检测、年龄性别表情这类属性分析、大规模向量检索的工程索引。这些是另外的题目，本篇只在必要处点到。

跨篇指路：卷积、池化、残差这些基础看同目录讲卷积网络的那篇；训练技巧与数据增强看深度学习训练那篇。篇中代码以 OpenCV 3 与 TensorFlow 1.x 时代的 API 为准，跑之前先对版本。

一、检测与识别是两件事 #

人脸检测的输出是矩形框。丢一张图进去，出来若干个 (x, y, w, h)。它不关心框里是谁，也不关心两个框是不是同一个人。它只回答一个二选一的问题：这块区域是人脸，还是不是。

人脸识别的输出是身份。丢一张裁好的小脸进去，出来一个标签或者一个向量。它默认你已经把脸裁好了、摆正了、缩放到固定尺寸了。

两个输出的形状都不一样，所以不会是同一个模型顺手干完。这就是本篇最要紧的一句话：

检测器输出框，识别器输出向量。很多人的误解是一个模型能全干，实际不是。

把两边摊开对比一下：

维度 人脸检测 人脸识别
输入 整张图（任意尺寸、任意背景） 裁好的人脸小图（固定尺寸）
输出 若干矩形框 + 置信度 身份标签，或一个定长向量
本质任务 二分类 + 框回归 特征提取 + 距离比对
类别数 恒定 2 类：人脸 / 非人脸 等于人数，且随时增减
主要误差 漏检、误检、框不准 认错人、阈值定不准
算力分布 全图扫，量大 只在框内跑，量小
传统方案 Haar + AdaBoost 级联 PCA 特征脸 + KNN
深度方案 MTCNN Facenet / ArcFace

一条流水线长什么样 #

真实系统里两边是串起来的，顺序固定：

  1. 检测：全图跑检测器，拿到 N 个框。
  2. 对齐：根据关键点做仿射变换，把脸摆正。MTCNN 顺手就把 5 个关键点给了。
  3. 裁剪缩放：按框裁出来，缩放到网络要的尺寸（Facenet 是 160×160）。
  4. 提特征：识别网络输出一个向量，比如 128 维。
  5. 比对：算这个向量和底库里每个向量的距离，取最近的那个。

第 4 步之后就没有「人脸」这个概念了，只剩向量。第 5 步也不认识脸，它只做算术。

为什么不用一个分类网络直接干完 #

有人会想：训练一个 1000 类的 softmax 网络，图片进去直接出人名，不是更省事。这条路走不通，卡在三个地方：

  • 它要求输入是裁好的脸。 你把一张带背景、带两个人、脸只占 1/20 面积的原图喂进去，网络看到的是一堆背景像素，输出没有意义。裁脸这件事本身就得靠检测器。
  • 类别是焊死的。 1000 类就是 1000 个人，第 1001 个人来了，只能重训或者加头重训。公司每进一个新人就重训一次模型，没人受得了。
  • 它没有「不认识」这个选项。 softmax 的分母锁死在训练类别上，你给一张陌生人的脸，它也会从 1000 个里挑一个最像的，而且给的置信度还挺高。

第三点最要命。人脸识别系统必须能拒识，而 softmax 的结构天生不支持拒识。度量学习那套（第九、十章）就是为了解决这个才出现的。

检测负责「在哪」，识别负责「是谁」 #

这句话值得拆开再讲一遍，因为搞混它的人太多。

检测是滑动窗口式的穷举 + 判别。它把图切成一堆小块，逐块问「这块是不是脸」。脸大就把图缩小再问一遍（图像金字塔），脸小就直接问。所以检测的时间开销和图像面积、尺度层数成正比。

识别是一对一比对。它拿到一张已经确定是脸的小图，问「这张脸属于谁」。它不关心位置，也不关心图里还有没有人。

一个直观的检验方法：把同一张人脸图平移 20 像素，再缩放到同样大小，识别器给出的向量几乎不变（好的模型欧氏距离小于 0.1）。可如果把它换成一张没有人脸的风景图，检测器会直接返回空，识别器却还是会老老实实吐一个向量出来。识别器没有「这不是脸」的判断力，它只会算距离。

人脸这个方向上的四个任务 #

论文里常把这几个词混着写，实际边界很清楚：

任务 输入 输出 属于
人脸检测 一张图 N 个框 检测
人脸对齐 一张图 + 框 摆正后的人脸图 检测的附属
人脸验证（1:1） 两张脸 是不是同一个人 识别
人脸识别（1:N） 一张脸 + 底库 底库里哪一个人 识别
人脸聚类 一批脸 自动分组 识别
人脸跟踪 一段视频 每帧的位置 检测 + 跟踪

1:1 和 1:N 的区别是工程上最容易被忽略的一点。1:1 只要定一个阈值，判「同」或「不同」。1:N 要做 N 次比对取最大，N 大了以后误识率会累积：单次误识率 0.001，底库 1 万人，期望误识就有 10 次。所以 1:N 的阈值必须比 1:1 严得多，底库还得先做粗筛。

二、Haar 特征与积分图 #

Haar 特征的想法很朴素：人脸有些区域之间亮度关系是稳定的。眼睛比脸颊深，鼻梁两侧比鼻梁深，嘴巴比周围深。把这些「深浅关系」编码成矩形块之间的灰度差，就能当特征用。

这个思路来自 Haar 小波，所以叫 Haar-like 特征。Viola 和 Jones 在 2001 年那两篇论文里用的就是它，配合积分图和 AdaBoost，在当时的硬件上做到了实时。

三类矩形模板 #

模板由黑白相间的矩形组成，特征值定义为白色区域像素和减去黑色区域像素和：

v=白∑​−黑∑​

模板分几种形状：边缘特征（两邻接矩形，一黑一白）、线性特征（三邻接）、中心特征（黑包白）、对角线特征。它们各自对特定走向的边缘敏感：水平、垂直、对角。

有一类模板要单独处理。像「黑—白—黑」这种三邻接结构，如果直接按白减黑算，黑色区域有两块、白色只有一块，像素数量不对等，算出来的值会天然偏向负。所以这类模板的定义是：

v=白∑​−2黑∑​

乘 2 就是为了让黑白两边的像素数对齐。这个细节很多实现里写错，特征值整体偏移一个系数，后面训练出来的阈值就全歪了。

模板本身叫特征原型。原型在子窗口里平移、缩放得到的每一个具体实例叫矩形特征，它算出来的数叫特征值。

为什么特征比像素好用 #

像素是死的。同一个人的两张照片，光照变一点，整片像素值全变，逐像素比对立刻失效。矩形特征算的是差值，光照整体变亮或变暗时，白减黑的差几乎不动。这层不变性是它能用的根本原因，也是它比直接喂像素更省样本的原因。

代价是表达力有限。矩形特征只对边缘、线段这类结构敏感，描述不了曲线。人脸恰好是「结构固定 + 局部有明暗规律」的对象，所以这套特征在人脸上好用，换成别的目标就未必。

特征数量的爆炸 #

矩形特征可以在图上任意位置、任意大小。模板类别、位置、大小三个因素一乘，数量就上去了。原始论文给的数是：24×24 的检测窗口里有 16 万个矩形特征。用 20×20 窗口时是 78,460 个。

这两个数直接带出两个必须解决的问题：

  1. 怎么快速算这么多特征？ 答案是积分图。
  2. 哪些特征才真的有用？ 答案是 AdaBoost 筛选。

积分图：一次遍历，四次查表 #

积分图（Integral Image）是一张和原图同尺寸的表，每个位置存的是原图左上角到该位置这个矩形区域内所有像素的和：

ii(i,j)=k≤i, l≤j∑​f(k,l)

构造只要扫一遍图，用两个递推：

s(i,j)=s(i,j−1)+f(i,j)
ii(i,j)=ii(i−1,j)+s(i,j)

其中 $s(i,j)$ 是当前行从左到当前位置的累加和，边界初始化为 0：s(i,−1)=0，ii(−1,j)=0。扫到右下角，整张表就填好了。

建好之后，图上任意矩形区域的像素和只用四次查表加三次加减。设矩形左上、右上、左下、右下四个角在积分图上的值分别是 $ii(1)$、$ii(2)$、$ii(4)$、$ii(5)$（这里沿用常见的角点编号习惯），则：

Dsum​=ii(α)+ii(β)−ii(γ)−ii(δ)

其中 α 是右下角，β 是左上角，γ、δ 是另外两个角。意思就是「大矩形减小矩形」。

这一步的意义在于：区域求和从「与面积成正比」变成「常数时间」。一个 100×100 的矩形，朴素求和要一万次加法，查表只要四次索引。窗口放大到 500×500，朴素求和贵 25 倍，查表还是四次。检测器要在几十万个窗口上跑，这个差别就是能不能实时的分界线。

用积分图算 Haar 特征值 #

Haar 特征值是两块区域的和之差，两块区域的和都能用四次查表拿到，所以一个特征值总共八次索引、几次加减。

举个具体的。一个两邻接的水平边缘模板，左边白块 A、右边黑块 B。设它们在积分图上的六个角点值为 $ii(1)$ 到 $ii(6)$：

Asum​=ii(5)+ii(1)−ii(2)−ii(4)
Bsum​=ii(6)+ii(2)−ii(5)−ii(3)

特征值就是两者相减：

ii(5)+ii(1)−ii(2)−ii(4)−[ii(6)+ii(2)−ii(5)−ii(3)]

整理之后，这个表达式只和这六个端点的积分图值有关，和矩形的绝对坐标无关。换一个位置、换一个尺度，只要端点相对关系一样，公式一个字都不用改。 这就是「同样四次查表，能处理任意大小」的由来。

特征值要归一化 #

单个特征的原始值范围很宽。一个 12×8 的模板算出来的值能从 -2000 跳到 +6000。跨度这么大，阈值没法定，不同特征之间也没法比。

OpenCV 的做法是拿窗口自身的灰度标准差去除。设当前检测窗口为 w×h，像素为 $i(x,y)$：

sum=∑i(x,y),sqsum​=∑i2(x,y)
mean=w⋅hsum​,sqmean​=w⋅hsqsum​​
varNormFactor=sqmean​−mean2​
normValue=varNormFactorfeatureValue​

归一化之后，特征值被压到一个可比的量纲上，再拿去和阈值比。顺便说，$sum$ 和 sqsum​ 也能用积分图求，一张积分图存灰度、一张平方积分图存灰度平方，代价还是两次查表。

特征好不好，看分布 #

判断一个特征有没有判别力，把它在人脸正样本和非人脸负样本上各算一遍，画两条分布曲线就行。

拿 MIT 人脸库的 2706 张 20×20 正样本做这个实验，会看到两种典型情况：

  • 一个落在人眼区域的特征，正样本上的值几乎全大于 0，分布很集中、偏向一侧，和负样本的分布拉开得很远。这种特征判别力强。
  • 一个位置随便选的特征，值均匀散在 0 两侧，正负样本完全混在一起。这种特征等于噪声。

特征效果好不好，本质看正负样本上的分布分不分得开。 这句话是后面 AdaBoost 筛选的理论基础：筛选就是在几万个特征里，挑那些能把手上的正负样本分开的。

这件事解决了什么 #

到这里，两个原始问题解决了一半：

  • 计算快的问题解决了。积分图让任意矩形特征都变成常数时间，多尺度扫描不再贵得离谱。
  • 特征筛选的问题有了明确标准：看分布可分性。

但 78,460 个特征里，绝大多数没用。真要把它们全用上，分类器又慢又容易过拟合。下一章讲 AdaBoost 怎么从这堆特征里挑出几百个，再用级联把速度再压一截。

三、AdaBoost 级联分类器 #

AdaBoost 是 Freund 和 Schapire 在 1995 年提出的。它的核心想法一句话：把一堆很弱的判断规则加权投票，凑成一个强判断。中文里「三个臭皮匠顶个诸葛亮」说的就是这件事。

Haar 分类器的完整构造是四件东西叠起来：

Haar 分类器=Haar-like 特征+积分图+AdaBoost+级联

四个部件缺一个，要么慢得跑不动，要么准得没法用。四件事的分工：

  • Haar-like 特征负责「描述」。
  • 积分图负责「算得快」。
  • AdaBoost 负责「从几万个特征里挑出几百个，并给每个配权重」。
  • 级联负责「让绝大多数窗口早退」。

弱分类器：一个特征就是一棵树桩 #

最基本的弱分类器只含一个 Haar 特征，决策树只有一层，术语叫树桩（stump）。它的形式是：

h(x,f,ρ,Θ)={1,0,​ρf(x)<ρΘ其他​

参数含义：$f$ 是特征，$f(x)$ 是该特征在子窗口 $x$ 上的值，Θ 是阈值，ρ 是方向（±1）。ρ 存在是因为「特征值大于阈值算人脸」和「小于阈值算人脸」两种情况都得覆盖。这一条看着琐碎，实际不能省：有的特征是人脸比非人脸亮，有的是暗。

训练一个弱分类器就是给一个特征找最优阈值，让它在所有样本上的加权错误率最低。

怎么找一个特征的最优阈值 #

给定一个特征 $f$，把所有训练样本在该特征上的值算出来，排序。然后从头扫一遍排序表，扫到每个位置时维护四个量：

  • T+：全部正样本的权重和。
  • T−：全部负样本的权重和。
  • S+：当前位置之前的正样本权重和。
  • S−：当前位置之前的负样本权重和。

取当前位置的特征值 Fkj​​ 和前一个特征值 Fkj−1​​ 之间的某个数作为阈值。这个阈值把样本分成前后两段。两种分法的错误率分别是「前段判正、后段判负」和反过来。取小的那个：

e=min(S++(T−−S−), S−+(T+−S+))

扫完整个表，就找到了让误差最小的阈值，也就完成了一个弱分类器的训练。复杂度是排序的 O(NlogN)，不是每个候选阈值都重算一遍，这一点让训练还能接受。

强分类器：加权投票 #

78,460 个特征，每个都能训出一个弱分类器，也就是 78,460 个候选。直接全用当然不行。AdaBoost 的做法是迭代地挑，每轮挑当前最好的那个，然后调样本权重，让下一轮更关注被分错的样本。

这套更新规则的效果值得单独说一句：分对了的样本权重乘 βt0​=1，分错了的乘 βt1​。因为 εt​<0.5 时 βt​<1……等等，这里方向要理清。误差小于 0.5 时 $\beta_t = \varepsilon_t/(1-\varepsilon_t) < 1$，那么分对的样本权重乘 1 不变，分错的样本权重乘 βt​<1 会变小——这和「加强错分样本」正好相反。

实际的标准写法是反向的：ωt+1,i​=ωt,i​βt1−ei​​ 中，ei​=0（分对）时指数为 1，权重乘 βt​ 缩小；ei​=1（分错）时指数为 0，权重保持不变。归一化之后，错分样本的相对权重就上升了。结论不变：下一轮的分类器会被迫盯着上一轮做错的那些样本。 索引的写法各版本不同，记住语义就够了。

αt​ 是这一轮的投票权重。εt​ 越小，βt​ 越小，αt​=log(1/βt​) 越大。判得准的弱分类器，说话分量重。

筛选：78,460 个不能全用 #

以 20×20 窗口为例，78,460 个特征，直接全塞进 AdaBoost 里跑，工作量是天文数字。所以前面必须加一道粗筛：先在 78,460 个特征里选出 $T$ 个表现最好的，把这 $T$ 个交给 AdaBoost 训。

粗筛的具体做法。假设有 2000 张人脸正样本、4000 张非人脸负样本，都归一化到 20×20。对 78,460 个特征中的任意一个 fi​，算出它在全部 6000 个样本上的值，得到 6000 个特征值，排序;在这张排序表上找一个最佳切分点，使得该特征下的加权错误率最低。这就锁定了这个特征的阈值。

每个特征都这么走一遍，得到 78,460 个最优弱分类器，再从中取错误率最低的那一批。这才是真正送进 AdaBoost 的输入。

级联：让绝大多数窗口早退 #

强分类器训好了，单个强分类器的准确率还不够看（误检率还是高）。级联的思路是多个强分类器串成一条链，逐级加严：

  • 第 1 级用很少的特征（比如 2 个），只要求「别把真脸漏了」，判得松，误检率高，但极快。
  • 第 2 级特征多一点，把第 1 级放进来的非人脸再刷掉一批。
  • 越往后特征越多、判得越严，走到最后的窗口几乎必然是真脸。

一个窗口必须通过全部级数才被判为正样本，任何一级判负就立即丢弃，不再往下走。

这条链的效率来自一个统计事实：一张图里切出来的几十万个窗口，绝大多数是非人脸。 如果第 1 级能刷掉 50% 的非人脸，第 2 级再刷 50%，走到第 10 级的窗口就只剩千分之一。整体平均下来，每个窗口只走了很少几级，绝大多数在第一、二级就被否了。

三级设计（多级级联）的唯一目的就是快。 每一级都调成「宁可放过，不可错杀」，靠后面的级数来补救精度。单级的误检率是各级误检率的连乘，所以级数一多，整体误检率指数级下降，而平均成本只增加一点点。

对比一下更直观：

方案 平均每窗口计算量 误检率
单个强分类器（全特征） 极高 偏高
10 级级联 很低（多数窗口第 1 级就否） 低

OpenCV 的 XML 分类器文件里，<stages> 下每个 <stage> 就是一级强分类器，里面 internalNodes 和 leafValues 存的是弱分类器的决策树结构和阈值。这是实际部署时最常被问到的两个标签。

五大步骤收个尾 #

训练一个 Haar 分类器的完整流程：

  1. 准备人脸、非人脸样本集，统一归一化到同一尺寸。
  2. 计算积分图，为所有候选特征求值。
  3. 粗筛出 $T$ 个最优弱分类器。
  4. 把这 $T$ 个送给 AdaBoost，迭代训练出强分类器。
  5. 把多个强分类器级联起来。

第 3 步是工程量最大的一步，也是最容易被跳过的一步。跳过它的代价是训练时间从一个下午变成一个季度。

检测阶段：多尺度怎么扫 #

训练用的样本都是 20×20 左右的小图。可现实中的脸有大有小，所以检测阶段必须做多尺度。两种策略：

  • 固定窗口，缩放图像。 把原图按比例缩成一系列金字塔层，每层用同一个滑动窗口扫。缺点是每层都要重算积分图和特征，效率低。
  • 固定图像，放大窗口。 用不断放大的检测窗口在原图上扫。省去了重算积分图，代价是窗口内的特征值算法要跟着变。

OpenCV 的 detectMultiScale 走的是缩放图像这条路，因为缩放后的每层图仍然可以复用「积分图一次构造、多次查询」的性质。

无论哪种，同一张脸都会在多个尺度、多个相邻位置被重复检测到，所以最后必须做区域合并（非极大值抑制）。这一步把重叠的框合成一个。

四、Haar 检测的实践 #

理论讲完，看实际怎么用。OpenCV 自带训练好的 XML 分类器，haarcascades 目录下有一批：正面人脸、侧面人脸、眼睛、鼻子、嘴。另外还有一个 lbpcascades 目录，用的是 LBP 特征而不是 Haar，速度更快、对光照更稳，精度略低。

这些 XML 都要求正面、直立的人脸。侧脸、俯拍、大角度旋转，效果会明显掉。

静态图检测 #

python
# -*- coding: utf-8 -*-
import cv2
import numpy as np


def static_detect(filename):
    # 加载级联分类器，既可以是 Haar 也可以是 LBP 的 xml
    face_cascade = cv2.CascadeClassifier(
        './haarcascades/haarcascade_frontalface_default.xml')

    img = cv2.imread(filename)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

    # scaleFactor：每次迭代图像压缩率
    # minNeighbors：每个候选框要保留的邻近个数
    faces = face_cascade.detectMultiScale(gray, 1.3, 5)

    for (x, y, w, h) in faces:
        cv2.rectangle(img, (x, y), (x + w, y + h), (255, 0, 0), 2)

    cv2.namedWindow('Face Detected')
    cv2.imshow('Face Detected', img)
    cv2.waitKey(0)
    cv2.destroyAllWindows()

detectMultiScale 的三步走：先按 scaleFactor 缩放图像建金字塔，每层用滑动窗口跑级联，最后用 minNeighbors 合并重叠框。

有一个细节要注意：必须先转灰度。 这个分类器是在灰度图上训的，喂彩色图进去，它只会用第一个通道，结果不对。

实际跑出来大体不会理想。常见的失败是背景里某个图案被框住，或者侧着的脸漏掉。这不是代码写错了，是 2001 年的方法在 2020 年的图片上本来就有的极限。

摄像头实时检测 + 眼睛嵌套检测 #

视频检测就是在每一帧上重复静态检测。多出来的一件事是先检脸、再在脸的 ROI 里检眼睛。

python
def dynamic_detect():
    face_cascade = cv2.CascadeClassifier(
        './haarcascades/haarcascade_frontalface_default.xml')
    eye_cascade = cv2.CascadeClassifier(
        './haarcascades/haarcascade_eye.xml')

    camera = cv2.VideoCapture(0)
    cv2.namedWindow('Dynamic')

    while True:
        ret, frame = camera.read()
        if not ret:
            break

        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

        # 人脸检测
        faces = face_cascade.detectMultiScale(gray, 1.3, 5)
        for (x, y, w, h) in faces:
            cv2.rectangle(frame, (x, y), (x + w, y + h), (255, 0, 0), 2)

            # 只在人脸框内找眼睛，省算力也少误检
            roi_gray = gray[y:y + h, x:x + w]
            eyes = eye_cascade.detectMultiScale(
                roi_gray, 1.03, 5, 0, (40, 40))
            for (ex, ey, ew, eh) in eyes:
                cv2.rectangle(frame, (ex + x, ey + y),
                              (x + ex + ew, y + ey + eh), (0, 255, 0), 2)

        cv2.imshow('Dynamic', frame)
        if cv2.waitKey(100) & 0xff == ord('q'):
            break

    camera.release()
    cv2.destroyAllWindows()

眼睛检测这一行多了两个参数：1.03 和 (40, 40)。1.03 比人脸的 1.3 细得多，因为眼睛小，尺度跳太快会直接跳过正确尺寸。(40, 40) 是最小尺寸，作用是压掉假阳性——胡子、鼻影、帧噪声这些小区域容易被误判成眼睛，把最小尺寸卡到 40×40 就能滤掉大部分。

眼睛检测也必须限制在 ROI 里做。全图找眼睛的误检率高得没法用，而且没必要。

detectMultiScale 参数逐个说 #

text
detectMultiScale(image[, scaleFactor[, minNeighbors[, flags[, minSize[, maxSize]]]]])
  • image：输入图像，必须是灰度图（CV_8U）。
  • scaleFactor：每个尺度之间的压缩比例，默认 1.1。这个值决定窗口跳跃的步子。调大（如 1.3）算得快，代价是会跳过某个尺寸的人脸，造成漏检。调小（如 1.05）检得全，但慢。
  • minNeighbors：一个候选框要保留，周围至少要有多少个邻近框。默认 3，意思是有 3 次重叠检测才算确认。调大能压误检，但会漏掉质量差的真脸。
  • flags：
    • CV_HAAR_DO_CANNY_PRUNING：用 Canny 边缘检测先排除掉边缘特别少或特别多的区域，跳过平滑区域。
    • CV_HAAR_SCALE_IMAGE：让分类器不缩放，改缩放图像。内存和缓存用得更合理，性能更好。
    • CV_HAAR_FIND_BIGGEST_OBJECTS：只返回最大的那个目标，返回值只有 0 个或 1 个。
    • CV_HAAR_DO_ROUGH_SEARCH：只能和上面那个一起用，找到第一个候选就停止搜索，只做粗略检测。
    • 新的分类器用不到这些标志，默认给 0。
  • minSize：目标最小尺寸。设小了会拖慢速度、增加误检。
  • maxSize：目标最大尺寸。知道脸不会太大时设上，能省不少时间。

调参的顺序建议是：先固定 scaleFactor=1.1，只调 minNeighbors 到误检可接受；再根据实际场景的脸大小设 minSize；最后才动 scaleFactor 换速度。

这套方法在什么时候还值得用 #

Haar + 级联不是历史遗迹，几种场合仍然合适：

  • 算力极低的嵌入式设备。 没有 GPU、内存只有几十兆，跑不动 CNN。
  • 只需要正面人脸的简单场景。 门禁抓拍、证件照裁剪。
  • 需要极小依赖。 OpenCV 一个 XML 就够，不用装深度学习框架。

不适合的场合也很明确：侧脸、遮挡、强逆光、密集人群、小脸。这些正是下一章要讲的、深度学习接手的场景。

Haar 这条路的价值在于它把「快」推到了当时的顶点，方法本身在设计上非常克制：所有复杂度都压到了训练阶段，检测阶段只做查表和比较。 这个思路到今天还在用。

五、特征脸：PCA 降维做人脸识别 #

前面四章解决「脸在哪」。从这一章起换问题：已知框里是张脸，怎么知道是谁。

最直白的想法是逐像素比对。两张 92×112 的灰度图，拉平成向量，算欧氏距离，距离最小的那个就是答案。这个思路五秒钟就能写出来，然后你会发现它几乎不能用。

逐像素比对为什么不行 #

一张 92×112 的图是 10,304 维。这个维度带来三个麻烦：

  • 维度灾难。 10,304 维空间里，样本点稀得可怕。ORL 库只有 400 张图，400 个点散在 10,304 维空间里，任意两点的距离都差不多，最近邻失去意义。
  • 没有对齐就会崩。 平移几个像素、转个角度，逐像素距离立刻爆掉，但人眼看还是同一张脸。
  • 算得慢。 每次比对一万次乘加，底库一万人的话就是一亿次。

所以要降维。而降维这件事，PCA 恰好做得非常好——它降维的同时保留了方差最大的方向，而人脸图像里方差最大的方向，视觉上看起来就像一张模糊的脸。

这就是「特征脸」（Eigenfaces）这个名字的由来。

数据准备 #

经典的实验数据是 ORL 人脸库：40 个人，每人 10 张，共 400 张，每张 92×112。除了公开库，还要采自己的脸，否则模型不认识你。

采集脚本就是调 Haar 检测器裁脸，缩放到 92×112，存成 .pgm：

加载与训练 #

python
import numpy as np
import cv2
import os


def load_images(data):
    '''
    返回 images:[m,h,w], labels:[m], names:[k]
    '''
    images, labels, names = [], [], []
    label = 0
    for sub_dir in os.listdir(data):
        subject_path = os.path.join(data, sub_dir)
        if os.path.isdir(subject_path):
            names.append(sub_dir)
            for file_name in os.listdir(subject_path):
                img_path = os.path.join(subject_path, file_name)
                img = cv2.imread(img_path, cv2.IMREAD_GRAYSCALE)
                images.append(img)
                labels.append(label)
            label += 1
    return np.asarray(images), np.asarray(labels), names


def face_rec(data):
    X, y, names = load_images(data)

    model = cv2.face.EigenFaceRecognizer_create()
    model.train(X, y)

    face_cascade = cv2.CascadeClassifier(
        './haarcascades/haarcascade_frontalface_default.xml')
    camera = cv2.VideoCapture(0)
    cv2.namedWindow('Dynamic')

    while True:
        ret, frame = camera.read()
        if not ret:
            break
        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        faces = face_cascade.detectMultiScale(gray, 1.3, 5)

        for (x, y, w, h) in faces:
            cv2.rectangle(frame, (x, y), (x + w, y + h), (255, 0, 0), 2)
            roi = gray[y:y + h, x:x + w]
            try:
                # 尺寸必须和训练集一致
                roi = cv2.resize(roi, (92, 112),
                                 interpolation=cv2.INTER_LINEAR)
                params = model.predict(roi)
                print('Label:%s, confidence:%.2f' % (params[0], params[1]))
                cv2.putText(frame, names[params[0]], (x, y - 20),
                            cv2.FONT_HERSHEY_SIMPLEX, 1, 255, 2)
            except Exception:
                continue

        cv2.imshow('Dynamic', frame)
        if cv2.waitKey(100) & 0xff == ord('q'):
            break

    camera.release()
    cv2.destroyAllWindows()

EigenFaceRecognizer_create() 有两个要紧参数：保留的主成分数目，和置信度阈值。主成分数目决定了用多少个特征脸来重建，给得少则只抓最粗的轮廓，给多则容易把光照噪声也学进去。ORL 这种小库，给 50 到 150 之间比较稳。

predict() 返回一个二元组：[0] 是识别出的标签，[1] 是置信度评分。评分越小越可信，0 表示完全匹配。

置信度评分的量纲陷阱 #

三种 OpenCV 识别器的评分量纲完全不同，混着用一定出错：

方法 评分范围 靠谱的阈值
Eigenfaces 0 ~ 20000 低于 4000~5000
Fisherfaces 0 ~ 20000 低于 4000~5000
LBPH 0 ~ 无上限 低于 50，高于 80 算低置信

Eigenfaces 和 Fisherfaces 的评分是「重建误差」的量级，跟图像本身的灰度尺度有关，所以数值大。LBPH 的评分是直方图距离，量纲小得多。把 LBPH 的 50 当阈值套到 Eigenfaces 上，等于全部拒识；反过来则等于全部放行。

这个坑非常常见，因为三种创建函数的调用方式长得一模一样，只有评分标准不同。

人脸识别的完整流程 #

不管用哪种算法，流程都是同一个：

  1. 检测框（Haar）。
  2. 裁剪，缩放到训练时的尺寸（92×112）。这一步漏了必然全错，因为模型只认识这个尺寸。
  3. 送进 predict()。
  4. 用返回的标签去 names 里查名字，用返回的评分和阈值比，决定认还是不认。

第 2 步和第 4 步是最容易出问题的地方。第 2 步出错表现为「全部识别成同一个人」或者直接抛异常；第 4 步出错表现为「谁都能认出来」，包括陌生人。

六、特征脸的原理与局限 #

上一章是调库，这一章把它拆开。拆开之后你会看到 PCA 那套线性代数是怎么落在人脸这件事上的。

从图像到向量 #

设 $m$ 个样本，每张图 w×h，拉平成 n×1 的列向量 xi​∈Rn，其中 $n = w \times h$。训练集 $S = {x_1, x_2, \dots, x_m}$。

目标是找一个变换，把 xi​ 从 Rn 投到 Rk，且 k≪n。以 92×112 为例，n=10304，$k$ 取 100 左右，压缩 100 倍。

PCA 的六步 #

  1. 求均值向量：

    xˉ=m1​i=1∑m​xi​

  2. 每张图去均值：

    Φi​=xi​−xˉ

  3. 拼成矩阵 $A = [\Phi_1, \Phi_2, \dots, \Phi_m]$，协方差矩阵：

    C=m1​AAT

  4. 特征值分解 $C u_i = \lambda_i u_i$。

  5. 特征值从大到小排序，取前 $k$ 个对应的特征向量，组成变换矩阵：

    P=[e1​,e2​,…,ek​]T,P∈Rk×n

  6. 降维：

    Ωi​=PΦi​
测试时给一张新图 $x$，先去均值 $\Phi = x - \bar{x}$，再投影 $\Omega = P\Phi$，然后拿 $\Omega$ 和已有的 $\Omega_1, \dots, \Omega_m$ 算距离，最近邻或者 KNN 投票决定类别。 ### 那个绕开死结的技巧 第 4 步有个坑。$C$ 是 $n \times n$ 的矩阵。$n = 10304$，那 $C$ 是 10304×10304，一亿多个元素，做特征分解要跑到天荒地老，内存也不够。 特征脸算法在这里做了一个非常漂亮的变换。**先不管 $C$，去解 $A^TA$ 的特征值问题。**

$m$ 是样本数，比如 400。400×400 的矩阵做特征分解，秒级完成。设：

ATAvi​=βi​vi​

两边左乘 $A$：

AATAvi​=βi​Avi​

也就是：

C(Avi​)=βi​(Avi​)

结论出来了：ATA 的特征值 βi​ 同时也是 AAT 的特征值，而 AAT 的特征向量是 Avi​。

所以原本要求的 $C$ 的特征向量 ui​，可以直接算成：

ui​=Avi​,i=1,2,…,m

一次 n×m 的矩阵乘就完事，不需要碰那个一亿元素的大矩阵。这是特征脸算法能落地的关键一步。

这里有个前提要记住：用这条路，降维后的维数 $k$ 不能超过样本数 $m$。 因为 ATA 最多只有 $m$ 个非零特征值。你只有 400 张图，就别想着降到 500 维，多出来的维度没有信息。这也是小样本库上 PCA 效果受限的直接原因。

另外还有一个数学细节：ATA 的 $m$ 个特征值对应的是 AAT 的 $n$ 个特征值里最大的前 $m$ 个。这个结论的严格证明要靠奇异值分解，这里记住结论就够用。它保证了按这套方法取到的确实是方差最大的那些方向。

变换矩阵的方向 #

组装 $P$ 的时候方向容易搞反。$P$ 是 k×n，每一行是一个特征向量（转置过来的）。所以：

Ωi​=PΦi​(k×n)⋅(n×1)=(k×1)

反过来写成 ΦiT​PT 也对。代码里因为习惯让每行一个样本，所以会看到一堆转置，容易看晕。

手写实现 #

不调库，自己写一遍：

python
import numpy as np
import cv2
import os
from sklearn import neighbors


class EigenFace(object):
    def __init__(self, dim_num=150, n_neighbors=3, dsize=(100, 100)):
        '''
        dim_num: PCA 降维后的维度 k
        n_neighbors: KNN 的近邻数
        dsize: 预处理时统一缩放的尺寸
        '''
        self.__dim_num = dim_num
        self.__dsize = dsize
        self.__mean = 0.0
        self.__knn = neighbors.KNeighborsClassifier(n_neighbors)

    def __pca(self, X):
        '''
        X: [m, n] 每行一个样本
        返回降维后的 [m, k] 和变换矩阵 [k, n]
        '''
        # 转成 [n, m]，每列一个样本
        X = X.T

        # 均值 [n, 1]
        mean = np.reshape(np.mean(X, axis=1), (-1, 1))
        self.__mean = mean

        # 去均值
        diff = X - mean

        # 关键：不去算 diff @ diff.T 的 [n, n]，改算 diff.T @ diff 的 [m, m]
        cov = np.dot(diff.T, diff) / diff.shape[1]

        # [m, m] 的特征值和特征向量
        eig_vals, eig_vects = np.linalg.eig(cov)

        # 左乘 diff 得到 [n, m] 的特征向量
        eig_vects = np.dot(diff, eig_vects)
        print('特征向量维度：', eig_vects.shape)

        # 特征值从大到小排序
        eig_val_index = np.argsort(eig_vals)[::-1]
        eig_val_index = eig_val_index[:self.__dim_num]

        # 归一化特征向量
        eig_vects = eig_vects / np.linalg.norm(eig_vects, axis=0)

        # 变换矩阵 [k, n]
        trans_mat = (eig_vects.T)[eig_val_index, :]

        # 降维 [k, n] @ [n, m] = [k, m]，再转成 [m, k]
        low_mat = np.dot(trans_mat, diff).T
        print('降维后的维度：', low_mat.shape)
        return low_mat, trans_mat

    def __prepare(self, images):
        '''
        images: [m, h, w] 灰度图
        返回 [m, n]，n = dsize[0] * dsize[1]
        '''
        new_images = []
        for image in images:
            re_img = cv2.resize(image, self.__dsize)
            # 直方图均衡化，压掉曝光不均
            hist_img = cv2.equalizeHist(re_img)
            hist_img = np.reshape(hist_img, -1)
            new_images.append(hist_img)
        return np.asarray(new_images)

    def fit(self, X_train, Y_train):
        X_train = self.__prepare(X_train)
        X_train_pca, self.__trans_mat = self.__pca(X_train)
        self.__knn.fit(X_train_pca, Y_train)

    def predict(self, X_test):
        if len(X_test.shape) == 2:
            X_test = np.expand_dims(X_test, axis=0)
        X_test = self.__prepare(X_test)
        # 投影到低维空间
        X_test_pca = np.dot(self.__trans_mat, X_test.T - self.__mean).T
        return self.__knn.predict(X_test_pca)

有几处值得说明：

  • __pca 里转置了两次。 原理推导时是每列一个样本，代码里习惯每行一个样本。开头 X.T 转过去，结尾 .T 转回来。看代码时盯住这一点就不会晕。
  • cov = np.dot(diff.T, diff) 这一行就是那个绕开死结的技巧。如果写成 np.dot(diff, diff.T)，在 100×100 的图上就是 10000×10000 的矩阵，跑不动。
  • equalizeHist 不能省。 直方图均衡化把每张图的灰度分布拉到接近均匀，能压掉一部分曝光差异，是特征脸能稳住的重要预处理。
  • 特征向量归一化（np.linalg.norm(..., axis=0)）要做，否则不同特征向量的尺度不一致，投影结果会被大的那个主导。

KNN 为什么不直接用最近邻 #

predict 里用的是 KNN 而不是 1-NN，取 $k$ 个最近邻投票。原因是一张图的单个最近邻会是光照最像的那张，而不是同一个人的那张。多取几个投票能压掉这种偶然。$k$ 取 3 到 5 就够，取太大反而被其他类别淹没。

特征脸到底在做什么 #

把前面那些矩阵运算还原成一句话：

它在找一组「脸的基底」，任何一张脸都能表示成这些基底的加权和。

取前几个特征向量，把它们还原成 w×h 的图像来看，出来的确实像一张张幽灵般的脸——有眼睛的窝、鼻子的暗部、脸的轮廓。这些就是「特征脸」本身。后面每个基底的系数就是这张脸的编码。

这个解释也能说明它为什么管用：几张特征脸拼起来的加权和，能近似任意一张对齐好的正面人脸。所以拿系数当特征，等于用极少的信息保住了脸的宏观结构。

但同时也能说明它为什么脆弱。 接下来讲。

特征脸的局限 #

PCA 是线性降维。它只在「方差大的方向就是重要的方向」这个假设下成立，而人脸这件事上这个假设经常不成立。具体表现：

变化因素 特征脸的表现 原因
光照 差 光照变化在像素空间里是全局的大幅偏移，方差极大，会直接抢占前几个主成分
姿态 差 侧脸和正脸在像素空间里是两个完全不同的模式，线性子空间表达不了「旋转」这种非线性变化
表情 差 嘴张开、眼睛眯起，局部像素剧烈变化，主成分无法区分这是表情还是不同的人
遮挡 差 眼镜、口罩、刘海会引入大量与身份无关的方差
对齐误差 差 没对齐的输入和已对齐的底库不在同一个子空间

最要命的是光照和姿态抢主成分这件事。PCA 挑的是方差最大的方向，而同一批样本里光照变化带来的方差，往往比不同人之间的方差还大。结果前几个主成分学到的是「亮暗」，不是「是谁」。这就是为什么特征脸在受控环境（如 ORL 那种统一拍摄）下还过得去，一到真实场景就崩。

第二个结构性问题是它没有「类」的概念。PCA 完全无监督，它不知道哪几张图是同一个人。它只找一个能重建所有图的最优线性子空间，重建得好不等于分得开。Fisherfaces 试图改进这一点——它用 LDA，找的是「类间方差大、类内方差小」的方向，确实比纯 PCA 好一些。但仍在线性框架内，上限没动。

第三个问题是线性这个上限本身。真实的人脸变化（姿态、表情）是高度非线性的流形。要把两张不同姿态的脸映射到一起，需要非线性变换。线性子空间做不到，再多的主成分也不行。

这就是特征脸被深度学习方法取代的原因。

它被取代不是因为数学不漂亮，恰恰相反，那个 ATA 的降维技巧是教科书级的。它被取代是因为线性这个假设在人脸问题上站不住。深度学习提供的是非线性映射，而且是从大量数据里学出来的映射，不是从像素方差里推出来的。

特征脸在今天的用处 #

不是完全没用了。几个场景还能见到：

  • 教学。 它是理解「降维 + 度量」这套思路最短的路径，100 行代码能跑通。
  • 极小样本的快速基线。 每人只有几张图、没有 GPU，PCA + 最近邻能先跑出一个结果，比随机猜强得多。
  • 可解释性要求高的场合。 特征脸本身就是可视化的人脸基底，出了问题能看出是哪几个成分在捣乱。
  • 数据增广的辅助手段。 用特征脸做低维重建，可以生成同一个人略微变化的样本。

把它当基线，别当生产方案。

七、深度学习带来的变化 #

Haar 的路子走到 2010 年代就不够用了。场景变了：从室内的正面抓拍，变成广场、车站、地铁口的自然场景。需求跟着变：

  • 人脸尺度从几十像素到上千像素，跨度大。
  • 一张图里几十上百张脸，密度高。
  • 姿态随意，俯拍、侧脸、仰头都有。
  • 遮挡常态化：口罩、帽子、墨镜、手机挡脸。
  • 表情夸张、化妆伪装。
  • 光照恶劣，逆光、夜间、强补光。

这些条件下 Haar 的表现很差。差的根因是它的特征太弱：几个矩形块的灰度差，描述不了「一张被遮挡的侧脸」。而深度学习换掉了特征本身——不再由人手工设计特征，而是从数据里学。

变化到底在哪 #

三处根本性的不同，值得一条条看：

维度 传统（Haar / PCA） 深度学习
特征来源 人工设计（矩形差、像素方差） 从数据中学
表达能力 线性组合 多层非线性
需要的数据 几千张 十万到百万级
需要算力 CPU 够 需要 GPU
鲁棒性（姿态/遮挡/光照） 弱 强
可解释性 强（能画出特征脸、矩形模板） 弱
调参成本 低（超参少） 高（结构、损失、增强都要调）

这七行里最要紧的是第二行。传统方法的表达能力上限是线性组合，深度学习是多层非线性。 人脸的各种变化本质上是非线性的（一张脸转了 30 度，像素的变化不是线性的），所以非线性这一条决定了上界。

第一行同样关键。人工特征只能编码人已经想到的规律。「眼睛比脸颊深」是人想出来的；「戴口罩的脸在特征空间的哪个方向偏」没人能手工写出来，只能靠数据学。

检测这边怎么变 #

传统检测的做法是「穷举窗口 + 判别」，每个窗口的计算是独立的。深度学习检测器的做法变了，核心是把「找框」变成「回归 + 分类」，并且共享卷积计算。

具体有三条常见路线：

  • 两阶段（如 Faster R-CNN）：先由一个区域提议网络给出候选框，再对每个框分类和精修。准，但慢。
  • 单阶段（如 SSD、YOLO）：在特征图的每个位置直接回归框和类别，一次前向搞定。快，小目标略弱。
  • 级联式（如 MTCNN）：多个由粗到细的小网络串起来，逐级过滤。速度与精度的折中做得很漂亮。

MTCNN 走的是第三条，它和 Haar 级联的思想一脉相承——都是「用一串由松到严的判别器逐级筛」，区别只在于每一级从「AdaBoost 强分类器」换成了「小卷积网络」。这个传承关系很值得注意：级联这个设计思想不是被淘汰了，是被继承并加强了。

识别这边怎么变 #

传统识别是「降维 + 距离」，深度学习识别是「学一个映射」。

关键的一步认识是：人脸识别不该做成分类问题，该做成度量学习问题。

分类的问题前面讲过（第 1 章）：类别焊死、不能拒识、新增人物要重训。度量学习绕开了这三点：

  • 模型输出一个向量，不输出类别。
  • 判断两个人是不是同一个，靠向量距离，不靠 softmax 分数。
  • 新增一个人，只要注册一张图的向量，模型完全不用动。

这个转变的代价是损失函数变复杂了——不能只用交叉熵，得设计一个直接优化「距离关系」的损失。这就是三元组损失（第十章）要解决的事。

数据成了主角 #

一个具体数字对比：Haar 时代，2000 张正样本 + 4000 张负样本就能训一个可用的检测器。Facenet 时代，CASIA-WebFace 是 10575 个人、494414 张图；再往后的数据集规模到百万级、千万级。

这不是量的堆砌，它改变了方法的性质。传统方法是「小数据 + 强先验」，深度学习是「大数据 + 弱先验」。 强先验（矩形特征、级联结构）是人设计的，省数据但限死上限；弱先验（通用卷积结构）不预设太多，靠数据自己长出合适的特征。

代价是：数据不够的时候，深度学习反而不如传统方法。几千张图训 CNN，效果常常打不过调好的 Haar。这是选择方案时该先算的账。

八、MTCNN：三级级联的人脸检测 #

MTCNN 全称 Multi-task Cascaded Convolutional Networks，出自 2016 年那篇 Joint Face Detection and Alignment using Multi-task Cascaded Convolutional Networks。它同时干两件事：检测（找到框）和对齐（找到 5 个关键点）。

为什么它值得单独讲 #

三个原因：

  • 它是级联思想在深度学习上的直接延续，和第三章的 AdaBoost 级联对照着看，能看清什么变了、什么没变。
  • 它一次输出框 + 关键点，把「检测」和「对齐」两步合成一步，工程上省事。
  • 它是 Facenet 的标配前置，第九、十章的所有流程都以它的输出为输入。

三个子网络 #

MTCNN 由三个网络串成，由粗到细：

网络 输入尺寸 作用 速度 输出
P-Net 12×12×3 生成候选框 最快 框 + 概率
R-Net 24×24×3 过滤掉大量非人脸 中等 框 + 概率
O-Net 48×48×3 精修 + 出关键点 最慢 框 + 概率 + 5 点

从 P 到 R 到 O，输入越来越大、通道越来越多、网络越来越深，所以准确率越来越高，速度越来越慢。这个「由粗到细」的排布和 Haar 级联完全同构。

为什么非要三级？一句话：如果一开始就拿 O-Net 全图扫，速度会慢到没法用。 P-Net 先做一层粗过滤，把候选从几十万降到几千；R-Net 再过滤到几百；O-Net 只在几百个候选上跑。每一级都把下一级的输入量砍掉一两个数量级，总时间就下来了。

这和第三章讲的级联效率来源是同一件事：绝大多数候选是背景，让它们在最便宜的阶段被否掉。

图像金字塔 #

三个网络都只吃固定尺寸的输入（12/24/48）。可现实中的脸有大有小。解法是图像金字塔：

把原图按比例 $factor$ 逐层缩小，得到一系列尺度层。每一层都送进 P-Net 扫一遍。缩得越小，原图里的大脸在该层上就越接近 12×12。

具体到代码，尺度序列这样生成：

python
factor_count = 0
scales = []
minl = min(h, w)
# P-Net 窗口是 12x12，所以先算一个基准缩放比
m = 12.0 / minsize
minl = minl * m
while minl >= 12:
    scales += [m * np.power(factor, factor_count)]
    minl = minl * factor
    factor_count += 1

minsize 是你想检测到的最小人脸。factor 一般取 0.709，即每层缩到上一层的 70.9%。层数由「缩到最小边不足 12 就停」决定。

factor 这个参数的取舍和 scaleFactor 一模一样：取大（如 0.8）层数少、快，但会跳过某些尺寸的脸；取小（如 0.5）层数多、慢，检得全。

P-Net 的三个输出 #

P-Net 的输入是 12×12×3 的 RGB 小块，输出分三部分：

  • 是不是人脸：$1 \times 1 \times 2$，两个值分别是「是人脸」和「不是人脸」的概率。两个值严格加起来等于 1。用两个值而不是一个 sigmoid，是为了直接套交叉熵损失。
  • 框回归：$1 \times 1 \times 4$，四个偏移量。为什么需要它：12×12 的窗口不一定正好卡住人脸，会偏左、偏右、偏大、偏小。这四个数是「左上角横坐标偏移、左上角纵坐标偏移、宽度误差、高度误差」，用来把粗框校正到位。
  • 关键点：$1 \times 1 \times 10$，5 个点各两维。5 个点是左眼、右眼、鼻子、左嘴角、右嘴角。

训练时这三部分都要算损失；测试时只需要框和概率，关键点可以不用。

实际用卷积实现时，不会真的把图切成一个个 12×12 的块。一张 h×w 的图送进去，出来一张特征图，特征图上的每个点对应原图一个 12×12 的感受野。这一步就是「卷积替代滑动窗口」，把重叠窗口的重复计算全共享了。 这也是深度检测器比 Haar 快的结构性原因之一：Haar 的每个窗口是独立算的，卷积的窗口共享计算。

R-Net：缩放到 24×24 再判一次 #

P-Net 出来的框不管原来多大，全部缩放到 24×24×3，送进 R-Net。输出结构和 P-Net 一样。

这一步的目的很单纯：去掉大量非人脸框。 P-Net 判得松（阈值只取 0.6），放进来很多误检。R-Net 看到的是 24×24 的完整上下文，比 12×12 的信息多，能判得更准。它把概率低于 0.7 的直接丢掉。

R-Net 之后还要做一次框回归校正和 NMS。NMS 的阈值也从 P-Net 阶段的 0.5 提到 0.7——候选少了，可以合得更激进一些。

O-Net：48×48，出关键点 #

R-Net 剩下的区域缩放到 48×48×3，进 O-Net。结构类似，但测试时输出多了一组关键点：$P$ 个框的坐标、score、以及 5 个关键点的位置。

O-Net 是唯一输出关键点的一级。原因也简单：要定位准确的关键点，需要足够高的分辨率，48×48 才够看清眼睛和嘴角的位置，12×12 和 24×24 都太糊。

损失函数 #

三个子网络、三个任务，损失也分三块，各自乘权重加起来：

人脸分类用交叉熵：

Lidet​=−(yidet​log(pi​)+(1−yidet​)(1−log(pi​)))

yidet​ 是真实标签，pi​ 是网络输出的人脸概率。

框回归用欧氏距离：

Libox​=​y^​ibox​−yibox​​

y^​ibox​ 是校正后的框坐标，yibox​ 是真实框。

关键点定位也用欧氏距离：

Lilandmark​=​y^​ilandmark​−yilandmark​​

总损失是加权和：

mini=1∑N​j∈{det,box,landmark}∑​αj​βij​Lij​

αj​ 是各任务的权重，βij​∈{0,1} 是样本类型指示符（这个样本参与哪个任务）。

权重的设置很有讲究：

网络 αdet​ αbox​ αlandmark​ 侧重
P-Net 1 0.5 0.5 框
R-Net 1 0.5 0.5 框
O-Net 1 0.5 1 关键点

前面两级主要关心框准不准，关键点损失给得小；O-Net 是最后一级，关键点的质量直接影响对齐效果，所以把权重提到 1。

难例挖掘 #

论文里有一段话讲训练策略，值得单独抄下来：

In particular, in each mini-batch, we sort the losses computed in the forward propagation from all samples and select the top 70% of them as hard samples. Then we only compute the gradients from these hard samples in the backward propagation. That means we ignore the easy samples that are less helpful to strengthen the detector during training.

翻成操作：每个 batch 里，把所有样本的损失从大到小排序，只取前 70% 做反向传播。 剩下 30% 损失小的样本不参与梯度更新。

为什么这么做？因为人脸检测的训练集里，大量样本是「一眼就能看出是背景」的简单负样本。它们损失接近 0，梯度也接近 0，参与训练只是浪费算力。让模型专注在难样本上，收敛更快、效果更好。

这和「难例挖掘」是同一个思路，只是做得更简单——不额外挑样本，直接按损失筛。它也解释了为什么 MTCNN 不需要人工挑样本就能训好。

训练数据怎么标 #

数据来自两个公开库：

  • WIDER FACE：32,203 张图，93,703 张脸，提供人脸框的 ground truth。地址 http://mmlab.ie.cuhk.edu.hk/projects/WIDERFace/。
  • CelebA：提供 5 个关键点的标注。用到的部分是 5,590 张 LFW 的图加 7,876 张网络图。

标注方式是把训练数据按 IOU 分成四类：

类型 条件 用途
负样本 窗口与 GT 的 IOU < 0.3 训练分类分支判「非人脸」
正样本 IOU > 0.65 训练分类分支判「人脸」
中间样本 0.4 < IOU < 0.65 只参与框回归，不参与分类
关键点样本 带 5 点标注 训练关键点分支

中间样本只做框回归是个巧妙的设计。IOU 在 0.4 到 0.65 之间的窗口，既不够正也不够负，硬当分类样本会误导分类器；但它对「框该怎么挪」是有信息量的，所以留给回归分支用。

检测主流程 #

把三级串起来的主流程：

text
输入图像
  └─ 建图像金字塔，每层按 factor 缩放
       └─ P-Net 逐层扫描
            ├─ 生成候选框（含框回归校正）
            ├─ 按 threshold[0]=0.6 筛
            ├─ 层内 NMS（0.5）
            └─ 汇总所有层的候选
                 ├─ 全局 NMS（0.7）
                 ├─ 框回归校正
                 ├─ 转成正方形
                 └─ 裁剪到图像边界内
                      └─ R-Net（缩放到 24×24）
                           ├─ 按 threshold[1]=0.7 筛
                           ├─ NMS（0.7）
                           ├─ 框回归校正
                           └─ 转正方形
                                └─ O-Net（缩放到 48×48）
                                     ├─ 按 threshold[2]=0.7 筛
                                     ├─ 框回归校正
                                     ├─ NMS（0.7，Min 模式）
                                     └─ 输出框 + score + 5 个关键点

三个关键设计点：

  • 每级都有自己的阈值，且逐级提高（0.6 → 0.7 → 0.7）。前面的松是为了别漏检，后面的严是为了别误检。
  • 每级之后都做 NMS。没有 NMS，一个脸上会出几百个重叠框。
  • 每级之后都做框回归。每一级都把框往真实位置拉一点，逐级精修。

rerec 那一步是把框转成正方形，因为后面的网络要正方形输入。这一步会改变框的比例，所以必须在缩放前做。

关键点的还原 #

O-Net 输出的关键点是归一化坐标（相对框的比例），要还原到原图得乘框的宽高再加偏移：

python
w = total_boxes[:, 2] - total_boxes[:, 0] + 1
h = total_boxes[:, 3] - total_boxes[:, 1] + 1
points[0:5, :] = np.tile(w, (5, 1)) * points[0:5, :] \
                 + np.tile(total_boxes[:, 0], (5, 1)) - 1
points[5:10, :] = np.tile(h, (5, 1)) * points[5:10, :] \
                  + np.tile(total_boxes[:, 1], (5, 1)) - 1

前 5 行是 x 坐标，后 5 行是 y 坐标。这个还原顺序别弄反，弄反了画出来的点会全部错位成对角关系。

对齐：把脸摆正 #

拿到 5 个关键点之后，就可以做仿射变换，把脸「摆正」。

标准做法是定义一个模板位置（比如把两眼摆到固定坐标、鼻子在中间、两个嘴角对称），然后求解从当前 5 点到模板 5 点的仿射矩阵，对整张脸做变换。这样不同姿态、不同角度的脸都会被归一化到同一个标准姿态。

对齐为什么重要？ 因为识别网络是在对齐好的数据上训的。你喂一张没对齐的脸，它的特征和底库里的特征就不在同一个分布上，距离计算失去意义。实测里，对齐做得好不好对识别准确率的影响，比换个网络结构还大。

MTCNN 的价值有一大半在这里：它不只是给框，还给对齐所需的关键点，一步到位。

用起来的手感 #

实测几个经验值：

  • minsize 按场景设。抓拍场景人脸不会太小，设 40 能省一半时间；监控场景人脸只有 30 像素，得设 20。
  • threshold 三个值可以按需求调。宁可漏检不可误检时，把 [0.6, 0.7, 0.7] 提到 [0.7, 0.8, 0.8]；宁可误检不可漏检则反过来。
  • factor 别小于 0.6，层数会爆。
  • 大图先缩一下再送进去。4000×3000 的图直接跑，金字塔底层就上千个窗口，慢得受不了。

MTCNN 的局限也要知道：它是 2016 年的方法，对超大角度侧脸、严重遮挡、极小脸（小于 20 像素）效果都不好。后来的 RetinaFace、SCRFD 在这些点上更强。但 MTCNN 的结构最干净，用来理解「级联检测」这件事最合适。

九、Facenet：把人脸映射成向量 #

Facenet 是 Google 在 2015 年那篇 FaceNet: A Unified Embedding for Face Recognition and Clustering 里提出的。它的核心想法一句话就能说完：

把一张人脸图映射成一个定长向量，让同一个人的向量距离近、不同人的向量距离远。

没有分类头，没有 softmax 输出类别。输入 160×160 的脸，输出一个 128 维的向量。识别、验证、聚类全靠这个向量之间的欧氏距离。

两步结构 #

一个完整的 Facenet 系统由两段拼成：

  • MTCNN 段：检测 + 对齐，输出 160×160 的标准化人脸图。
  • CNN 段：把这张图映射到欧氏空间，输出 128 维向量。

第二段的产物就是「特征」（embedding）。这个空间的性质是：距离的大小直接对应人脸的相似度。

所以识别流程变成纯算术：

  1. 底库里每个人注册一张图，事先算好向量存起来。
  2. 来了新图，MTCNN 对齐，CNN 算向量。
  3. 和底库所有向量算欧氏距离，取最近的。
  4. 最近距离小于阈值 → 认为是这个人；大于阈值 → 拒识。

这就是度量学习的好处，也是它比分类方案强的根本原因：新增一个人不用重训模型，只要往底库里加一行向量。 一个十万人的底库，注册新人是一次前向推理，几毫秒的事。

为什么拿卷积层当特征不好 #

有人会想：VGG16 去掉全连接层，拿 conv5_3 的输出当特征不就行了。这个做法在图像检索里很常见，但直接搬到人脸识别上效果不好。

原因在于损失函数没约束这件事。VGG16 是用 softmax 训的，softmax 只管「把每一类分开」，不管「同一类的样本要聚在一起」。它允许同一个人的两张图在特征空间里离得很远，只要它们都还在这个人的判决区域内就行。

用一个具体例子看这件事。拿 MNIST 做实验，设计一个网络让最后一层只输出 2 维，把每类的 2 维坐标画出来：

  • 用纯 softmax 训，画出来的图里，同一类（比如紫色）的点会散得很开，类内距离很大。
  • 而不同类的点在某些区域（比如图中心）挤在一起，类间距离很小。

这完全违背了人脸识别要的性质。我们要的是「同类紧、异类远」，softmax 给的却是「只要分对就行」。

性质 人脸识别的需求 softmax 的保证
类内紧凑 必须 无
类间分离 必须 有（判决边界）
可以拒识 必须 无
新增类别免重训 必须 无

softmax 只保证了第二行。其余三行都是空的。所以必须换损失函数——换成直接对这个「距离性质」下手的那种。

Inception ResNet v1 #

Facenet 用的骨干网络是 Inception ResNet v1。这个结构是 Inception 模块和残差连接拼起来的：

  • Inception 模块：同一层里并行放多个不同尺寸的卷积（1×1、3×3、5×5）和池化，把结果在通道维拼接。好处是不用人工选「该用多大的卷积核」，让网络自己学。
  • 残差连接：跨层直连，把输入加到输出上。解决深层网络的梯度消失，让网络能堆很深。

两者合起来的效果是：既有多尺度感受野，又能训得深。

Facenet 官方仓库（https://github.com/davidsandberg/facenet）支持三个骨干：inception_resnet_v1、inception_resnet_v2、squeezenet。前两个大、精度高，最后一个小、适合显存紧张的场景。

网络的最后一层是一个 128 维的全连接，输出 prelogits，再做一个 L2 归一化得到 embeddings：

python
# prelogits: [batch_size, 128]
prelogits, _ = network.inference(image_batch, keep_probability,
    phase_train=phase_train_placeholder,
    bottleneck_layer_size=embedding_size,
    weight_decay=weight_decay)

# L2 归一化，把向量压到单位球面上
embeddings = tf.nn.l2_normalize(prelogits, 1, 1e-10, name='embeddings')

L2 归一化这一步不能省。 它把每个向量压到长度为 1，于是欧氏距离和余弦相似度等价，而且距离有了明确的上界（最大 2）。三元组损失里也要靠它防止特征「无限远离」——不归一化的话，网络会发现「把所有权向量都放大」是降低损失的一条捷径，而这个捷径毫无意义。

用 MTCNN 做对齐 #

模型是在 160×160 的对齐图上训的，所以测试数据也必须对齐到 160×160。这一步用官方脚本：

  datasets/lfw/raw \
  datasets/lfw/lfw_mtcnnpy_160 \
  --image_size 160 --margin 32 --random_order

两个参数要理解：

  • --image_size 160：输出图尺寸。
  • --margin 32：在 MTCNN 给出的框基础上向外扩32 像素再裁。

margin 为什么是扩而不是缩？因为 MTCNN 训的时候框偏紧（贴着脸的边界），而识别网络训练时用的数据框偏松（包含一点额头和下巴）。为了让测试数据和训练数据同分布，得往外扩。这个细节不做，准确率会掉几个点。

            img, minsize, pnet, rnet, onet, threshold, factor)
        # 扩 margin、裁切、缩放到 image_size

三个预训练模型文件是 det1.npy、det2.npy、det3.npy，分别对应 P-Net、R-Net、O-Net。create_mtcnn(sess, None) 里头会自动找这三个文件。

一张图里有多张脸时的处理也要注意。--detect_multiple_faces 没开的话，脚本只保留一张脸，选择标准是「框面积大 且 离图像中心近」：

python
bounding_box_size = (det[:,2]-det[:,0])*(det[:,3]-det[:,1])
img_center = img_size / 2
offsets = np.vstack([(det[:,0]+det[:,2])/2 - img_center[1],
                     (det[:,1]+det[:,3])/2 - img_center[0]])
offset_dist_squared = np.sum(np.power(offsets, 2.0), 0)
index = np.argmax(bounding_box_size - offset_dist_squared * 2.0)

这个打分公式值得记：面积减去到中心距离的平方的两倍。面积大是好事（脸大信息多），偏离中心是坏事（边上是路人）。权重 2.0 是经验值。

算两张脸的相似度 #

实际用得最多的是这个：给定几张图，算两两距离。

  src/img1.jpg src/img2.jpg src/img3.jpg

输出是一个距离矩阵：

0    0.0000    1.0342    1.2871
1    1.0342    0.0000    1.3055

读法：对角线上是 0（自己和自己），非对角线是两两距离。距离小说明像。

核心代码只有几行：

python
# 加载 MTCNN 并做检测对齐，得到 [n,160,160,3]
images = load_and_align_data(image_files, image_size, margin, gpu_memory_fraction)

# 加载 Facenet 模型
facenet.load_model(args.model)

embeddings = tf.get_default_graph().get_tensor_by_name("embeddings:0")
phase_train_placeholder = tf.get_default_graph().get_tensor_by_name("phase_train:0")

feed_dict = {images_placeholder: images, phase_train_placeholder: False}
emb = sess.run(embeddings, feed_dict=feed_dict)

# 两两距离
for i in range(nrof_images):
    for j in range(nrof_images):
        dist = np.sqrt(np.sum(np.square(np.subtract(emb[i, :], emb[j, :]))))

一个真实的坑 #

拿自己人的照片测，会发现距离值分布和预期不一样：同一个人的距离偏大，不同人的距离偏小。

这不是代码错了，是数据分布不匹配。模型是在 CASIA-WebFace 上训的，那个库以白人为主。华人的脸在它的特征空间里没有充分训练，所以同一人之间的距离被拉大、不同人之间的距离被压缩。

三条解法，按代价排序：

  • 换数据。 用华人数据集重训，或者用华人数据集微调最后一层。
  • 重标阈值。 在你自己的数据上跑一批正负样本对，重新画 ROC 找出合适的阈值。这是最省事的做法。
  • 换模型。 用 ArcFace 那类在更大、更多元数据集上训的模型。

第一条最彻底，第二条最实用。永远不要在别人的阈值上直接跑自己的数据，这是踩过最多坑的一条。

小结：Facenet 真正带来了什么 #

三个东西：

  • 度量学习的落地范式。 输出向量而不是类别，距离即相似度，阈值即判决。
  • 可复用的特征。 同一个 128 维向量，验证、识别、聚类、检索全能用。
  • 免重训的扩展性。 底库加人只加一行向量。

这三点合起来，才是它取代特征脸的根本原因。不是因为准确率高几个点，是因为系统架构上更合适。

十、三元组损失与度量学习 #

上一章提到 softmax 不管类内紧凑。这一章讲怎么管。

三元组损失在优化什么 #

思路很直接：既然目标是「距离应该具备某种性质」，那就把距离本身写进损失。

每次从训练集抽三张图组成一个三元组：

  • xia​：anchor，锚点。
  • xip​：positive，和 anchor 同一个人。
  • xin​：negative，另一个人。

希望的性质是：anchor 到 positive 的距离，要比 anchor 到 negative 的距离小，而且小至少一个 margin α：

∥f(xia​)−f(xip​)∥22​+α<∥f(xia​)−f(xin​)∥22​

取平方是为了求导方便。α 是一个正的间隔，强制两类距离之间留出缓冲带。

损失函数按这个不等式写：

Li​=[∥f(xia​)−f(xip​)∥22​+α−∥f(xia​)−f(xin​)∥22​]+​

[⋅]+​ 是取正值部分，即 max(⋅,0)。

这个设计的好处在于它是自适应的：

  • 三元组已经满足不等式时，括号里是负数，被截成 0，这个三元组不产生梯度。
  • 不满足时，损失等于超出量，梯度把 positive 拉近、把 negative 推远。

也就是说，模型只在乎那些「还没排好序」的三元组。已经排对的不管。这是它比逐样本分类高效的地方。

论文里还有一条约束：训练时固定 $\left| f(x) \right|_2 = 1$。这就是 L2 归一化的由来。不固定的话，网络有个廉价的作弊路径——把所有向量同比例放大，让两个距离的绝对差变大，margin 就轻松满足了，但相对关系一点没变。

代码只有八行 #

facenet.py 里的 triplet_loss()：

python
def triplet_loss(anchor, positive, negative, alpha):
    """Calculate the triplet loss according to the FaceNet paper

    Args:
      anchor: the embeddings for the anchor images.
      positive: the embeddings for the positive images.
      negative: the embeddings for the negative images.

    Returns:
      the triplet loss according to the FaceNet paper as a float tensor.
    """
    with tf.variable_scope('triplet_loss'):
        pos_dist = tf.reduce_sum(tf.square(tf.subtract(anchor, positive)), 1)
        neg_dist = tf.reduce_sum(tf.square(tf.subtract(anchor, negative)), 1)

        basic_loss = tf.add(tf.subtract(pos_dist, neg_dist), alpha)
        loss = tf.reduce_mean(tf.maximum(basic_loss, 0.0), 0)

    return loss

逐个变量对到公式上：

变量 形状 对应公式
anchor [batch_size, feature_size] f(xia​)
positive [batch_size, feature_size] f(xip​)
negative [batch_size, feature_size] f(xin​)
pos_dist [batch_size] ∣f(xia​)−f(xip​)∣22​
neg_dist [batch_size] ∣f(xia​)−f(xin​)∣22​
basic_loss [batch_size] $|f(x_i^a)-f(x_i^p)|_2^2 + \alpha - |f(x_i^a)-f(x_i^n)|_2^2$
loss 标量 对 batch 内取平均的 Li​

tf.reduce_sum(..., 1) 那个 1 是在特征维求和，得到每个样本的距离。tf.maximum(basic_loss, 0.0) 就是 [⋅]+​。tf.reduce_mean(..., 0) 沿 batch 维取平均。

完全对得上。这段代码是理解三元组损失最直接的入口，比任何公式推导都快。

采样才是难点 #

三元组损失的形式很简单，难的是怎么挑三元组。这里面的坑很深：

随机采样：随便抽三张，只要 anchor 和 positive 同一人、negative 另一人。能收敛，但收敛慢，性能上不去。因为大部分随机三元组早就满足不等式了，损失是 0，不产生梯度。训练大量时间在空转。

全难采样：每次挑损失最大的三元组（即 negative 比 positive 还近的那些）。梯度信息量最大，但模型容易训崩。原因是一开始模型很差，最难的负样本往往是标注噪声或者极端姿态，模型为了拟合它们会把整个空间搞乱，陷在局部极小值里出不来。

半难采样：挑那些「negative 比 positive 远，但没远出 margin」的三元组。既有梯度，又不会太难。这是 Facenet 论文推荐的做法，也是实际能跑出效果的做法。

采样策略 收敛性 最终性能 实际可用
随机 好 差 不推荐
全难 差（易崩） 好（如果训得动） 风险高
半难 好 好 推荐

半难三元组的选择逻辑可以用一句话描述：对每个 anchor，找那些满足 $d(a,p) < d(a,n) < d(a,p) + \alpha$ 的 negative。 这些负样本「有点难但不太难」。

还有个现实约束：三元组损失需要非常大规模的人脸数据集。 因为要凑出有意义的三元组，得保证同一个人的图足够多（至少几张），不同人之间的多样性足够高。几千人的库根本喂不饱它。论文用的数据集是 2 亿张。

中心损失：另一条路 #

中心损失（Center Loss）走的是另一条路。它不直接优化距离对，而是保留分类框架，同时给每个类别指定一个中心。

思路：同一个类的特征都往自己的类中心靠，不同类的中心自然被推开。

设人脸图 xi​，类别 yi​，类别中心 cyi​​。损失定义为特征到中心的距离：

Li​=21​∥f(xi​)−cyi​​∥22​

一个 batch 的总和：

Lcenter​=i∑​Li​

问题来了：cyi​​ 从哪来？理论上最优的中心是这个类所有图的特征均值。但每次梯度下降都要重算一遍所有图的特征均值，代价太高。

工程上的近似：把中心也当成可学习的参数，用梯度下降一起更新。 初始随机，在每个 batch 内对 cyi​​ 也算梯度、也更新。

而且不能只用中心损失。光靠它，所有类会坍缩到同一个点。必须和 softmax 损失联用：

L=Lsoftmax​+λLcenter​

λ 是平衡系数，控制「聚拢」这个目标占多大比重。

中心损失的代码 #

同样在 facenet.py 里：

python
def center_loss(features, label, alfa, nrof_classes):
    """Center loss based on the paper "A Discriminative Feature Learning Approach
       for Deep Face Recognition" (http://ydwen.github.io/papers/WenECCV16.pdf)
    """
    # nrof_features 就是 feature_size，即 CNN 输出的人脸向量维数
    nrof_features = features.get_shape()[1]

    # centers 是可学习的变量，[类别数, 特征维数]
    centers = tf.get_variable('centers', [nrof_classes, nrof_features],
        dtype=tf.float32,
        initializer=tf.constant_initializer(0), trainable=False)

    label = tf.reshape(label, [-1])

    # 按 label 取出每个样本对应的类别中心
    # centers_batch 形状和 features 一致 [batch_size, feature_size]
    centers_batch = tf.gather(centers, label)

    # 中心和特征的差距，用来更新中心位置
    # alfa 控制更新幅度
    diff = (1 - alfa) * (centers_batch - features)

    # 用 diff 更新中心
    centers = tf.scatter_sub(centers, label, diff)

    # 计算损失
    with tf.control_dependencies([centers]):
        loss = tf.reduce_mean(tf.square(features - centers_batch))

    # 返回损失和更新后的中心
    return loss, centers

几个点值得说：

  • trainable=False。中心不走优化器，靠下面手动更新。这是刻意的：中心需要的是「跟着特征均值缓慢移动」，不是「按梯度大步跳」。
  • alfa 控制更新速度。diff = (1 - alfa) * (centers_batch - features)，然后 scatter_sub。α=0.9 时，中心每步只往特征方向移动 10%。移动太快会让中心跟着 batch 噪声乱抖。
  • tf.control_dependencies([centers])。保证损失计算用的是更新后的中心，而不是旧的。少了这一行，更新和计算就没有顺序保证，训练不稳定。

对照公式 $L_i = \frac{1}{2}|f(x_i) - c_{y_i}|_2^2$，代码里的 tf.reduce_mean(tf.square(features - centers_batch)) 只差一个比例系数（1/2 和取均值）。系数不影响梯度方向，可以忽略。

两种损失怎么选 #

维度 三元组损失 中心损失
优化对象 样本对之间的距离关系 样本到类中心的距离
是否需要分类头 不需要 需要（要和 softmax 联用）
采样难度 高（要设计采样策略） 低（随机取 batch 即可）
数据需求 极大（亿级） 中等
直接优化度量 是 否（间接）
类内紧凑性 好 好（λ 越大越明显）
类间可分性 由 margin 保证 靠 softmax 保证

选的时候看约束：

  • 数据量极大、追求极限准确率 → 三元组（配半难采样）。
  • 数据量中等、想快点出结果 → 中心损失 + softmax。
  • 两个都用 → 这就是 Facenet 官方 train_softmax.py 的默认配置，--center_loss_factor 给个 0.01 左右。

第三种的道理：三元组直接管距离，中心损失管紧凑，softmax 管分类，三管齐下互补。

度量学习这件事的本质 #

把这一章收一句：度量学习不学「这是谁」，学「谁和谁更像」。

这个转向带来三个好处，每个都对应一个人脸系统的实际痛点：

  • 可拒识。 学的是距离，所以能定阈值。距离太大就说不认识，这是分类模型做不到的。
  • 可扩展。 底库变了不用动模型，特征提取器是固定的。
  • 可迁移。 一个度量可以复用到验证、识别、聚类、检索四个任务上。

代价是训练更难。损失函数的设计、采样策略、归一化方式，每一样都得对。这就是为什么 Facenet 论文里一半篇幅在讲采样，而不是讲网络结构。

第三层对比：整条流水线 #

把两代系统完整摆在一起：

传统流水线：Haar 检测 → 裁切 → 缩放到固定尺寸 → PCA 投影 → 和底库算距离 → 最近邻投票 → 拿评分比阈值。

深度流水线：MTCNN 检测 + 关键点 → 仿射对齐 → 缩放到 160×160 → Facenet 前向 → 128 维向量 → 和底库算欧氏距离 → 最近距离比阈值。

结构上几乎一模一样：检测 → 对齐 → 缩放 → 提特征 → 算距离 → 比阈值。

变的是每一步的实现，没变的是流程本身。 这一点很值得琢磨：无论用什么方法，人脸识别这件事的骨架都是「先定位、再标准化、后比对」。这是问题本身的结构决定的，不是方法决定的。

该用哪一套 #

给一张判断表：

场景 建议
嵌入式、无 GPU、只要正脸 Haar + LBPH
教学、讲清原理 Haar + 特征脸
服务器端、要准确率 MTCNN + Facenet/ArcFace
大规模底库（> 10 万） 深度特征 + 向量索引（Faiss 等）
强隐私要求、不能上云 本地小模型，或纯传统方案
需要关键点做姿态分析 MTCNN 或更新的人脸关键点模型
数据只有几百张 传统方法，或者用预训练模型微调

最后一行容易被忽略：数据少的时候，传统方法常常打得过深度学习。 几千张图训 CNN 多半过拟合，而调好参数的 Haar 加特征脸能给出稳定的基线。这是选择方案时该先算的账。

一个常见的误解 #

前面反复提到的那个误解，在这里正式收掉：

「训练一个端到端模型，输入原图输出人名，是不是就一个模型搞定了？」

不行，三个理由前面讲过，这里压缩成三条：

  • 端到端模型要求输入已经裁好、对齐好，裁和裁对齐本身就得靠检测器。
  • 类别是焊死的，新人来了要重训。
  • 它没有「不认识」这个输出，天生不能拒识。

所以真实系统永远是检测器 + 识别器两段，中间夹一个对齐。这个结构从 2001 年到今天没变过。

变的是每一段的实现：从 Haar 到 MTCNN，从特征脸到 Facenet。问题结构稳定，解法在换。 认清了这一点，看新论文的时候就不会被各种名词绕晕——先问它在解决哪一段。

三个最容易被忽略的：

  • phase_train 必须给 False。 给 True 时 dropout 在丢弃神经元、batch norm 用当前 batch 的统计量，同一个输入两次前向出来的向量不一样。表现是「同一张图距离不是 0」。
  • margin 是外扩不是内缩。 负值会让框缩进脸里，切掉额头和下巴，特征分布偏移。
  • 预白化不能省。 facenet.prewhiten() 是按训练时的标准化做的，省了准确率掉得不多，但距离阈值全错。

数学符号的坑 #

推导部分有几个符号特别容易看晕，单独提一下。

PCA 里 ATA 和 AAT 谁是谁。 记法：$A$ 是 n×m（$n$ 像素数，$m$ 样本数）。ATA 是 m×m（小，能算），AAT 是 n×n（大，算不了）。所以去解小的那个，再左乘 $A$ 还原。

降维维数 $k$ 不能超过 $m$。 ATA 最多 $m$ 个非零特征值，要第 m+1 个就没有了。400 张图最多降到 400 维，这跟你想不想无关。

三元组损失里 α 的位置。 是加在 positive 距离上，不是加在 negative 上：

L=[d(a,p)2+α−d(a,n)2]+​

意思是要让 d(a,p)2 加上 margin 之后还小于 d(a,n)2。加错位置的话 margin 方向反了，训练会完全跑偏。

中心损失的 21​ 和代码里的 reduce_mean。 只差常数系数，不影响梯度方向。别为了对齐公式去改代码。

概念上的六个混淆 #

前三条在前面的章节反复讲过，这里压缩成一句话，方便回头查。

检测 ≠ 识别。 检测输出框，识别输出向量。前者问「在哪」，后者问「是谁」。两个模型，两套数据，两套评估指标。

特征脸 ≠ 人脸识别。 特征脸是一套降维方法，可以用在任何「高维向量 + 小样本」的问题上。它只是碰巧在人脸上好用（受控环境下）。

softmax ≠ 度量学习。 softmax 把类别分开，不保证类内紧凑、不保证能拒识、不保证能扩展。要这三样必须换损失。

级联 ≠ 过时的技术。 Haar 的级联和 MTCNN 的三级是同一个思想：让大多数候选在最便宜的阶段出局。这个结构在今天的检测器里还在用。

对齐 ≠ 可有可无的预处理。 不做对齐，识别网络的输入分布和训练分布不一致，距离计算失去意义。实测里对齐的影响大于换网络。

归一化 ≠ 细节。 特征值归一化、L2 归一化、预白化，三个都在不同环节防止「尺度」污染「相似度」。少一个都会出问题。

最后一条实践建议 #

跑这套东西最常见的挫败是「代码跑通了但结果不对」。遇到这种情况，按这个顺序排查，能解决八成问题：

  1. 可视化中间结果。 把检测框画在图上、把对齐后的脸存下来看一眼、把特征脸的前几个成分画出来。九成的问题看一眼图就能定位。
  2. 查数据尺寸。 训练和推理的输入尺寸是否一致，是尺寸链路上最容易断的一环。
  3. 查归一化。 训练时的标准化方式和推理时是否一致。不一致的话模型表现会很奇怪：不至于全错，但准确率莫名低一截。
  4. 查阈值。 距离或评分的阈值是不是在别的数据上标的。这是最常见的「逻辑对但结果错」。
  5. 换一个已知好用的数据。 拿 LFW 或者 ORL 这种公开库跑一遍。公开库上正常、自己的数据上不正常，问题就在数据；公开库上也不正常，问题在代码。

把人脸这条线走完，会看到一个挺有意思的现象：2001 年的 Viola-Jones 和 2015 年的 Facenet，中间隔了十四年，工具从手工特征加级联换成了深度网络加度量学习，但整条流水线的骨架——检测、对齐、提特征、算距离、比阈值——一步都没变。

变的是每一步用什么实现，不变的是问题本身的结构。看清哪些在变、哪些没变，比记住某一代方法的细节更有用：新方法出来的时候，你能直接判断它替换的是哪一段，而不是从零开始理解一遍。
