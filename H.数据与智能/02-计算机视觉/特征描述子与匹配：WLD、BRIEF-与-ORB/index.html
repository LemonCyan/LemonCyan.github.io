关键点找到之后，怎么把它「记下来」，怎么把两张图里的点「对上」，是这篇的全部内容。检测器回答「这个点值不值得关注」，描述子回答「这个点长什么样」，匹配回答「这两个点是不是同一个点」。三段接起来，才有后面的单应性、位姿估计、图像拼接和目标检索。

不讲什么：Harris、FAST、SIFT、SURF 怎么找点，尺度空间怎么搭，DoG 怎么算，都在同目录的《特征检测：角点与尺度不变算法》那篇里。本篇只在描述子需要方向、需要尺度的地方，回头借用一句结论。

讲什么：WLD 这类纹理型描述子怎么把邻域压成直方图；BRIEF 怎么用随机点对比较生成二进制串；BRIEF 缺了什么，ORB 用什么补；暴力匹配和 KNN 怎么调；Lowe 比率测试和 RANSAC 为什么必须上；单应性怎么把目标框出来；最后给一套评估口径和一份踩坑清单。

一、检测与描述的分工 #

一条特征流水线拆成四段：检测、描述、匹配、估计。每段的输入输出都不一样，混着写代码就会乱。

text
图像
  │
  ├─ 检测 ──> 关键点 (x, y, scale, angle, response)
  │
  ├─ 描述 ──> 描述子 (128 维 float / 256 位二进制)
  │
  ├─ 匹配 ──> 对应关系 [(i, j, distance), ...]
  │
  └─ 估计 ──> 变换矩阵 H / F / 位姿 T

检测器只吐位置和几个附属量。尺度告诉描述子该在多大的邻域上取样，方向告诉描述子该把采样图案转到哪个角度。描述子拿到这些，去原图上取一块，按规则压成一串数。匹配拿两串数算距离，距离够小就算对上。

四段的分工写进表里，不容易记错：

环节 输入 输出 回答的问题 代表算法
检测 图像 关键点坐标 + 尺度 + 方向 这个点值不值得关注 Harris、FAST、SIFT、SURF
描述 图像 + 关键点 定长向量或码串 这个点长什么样 SIFT、SURF、WLD、BRIEF、ORB
匹配 两组描述子 索引对 + 距离 哪两个点是同一个点 BFMatcher、FLANN
估计 匹配点坐标 矩阵 + 内外点掩码 两张图怎么变换 findHomography、RANSAC

这个分工不是纸上分类，它直接决定接口。BRIEF 的 compute(image, keypoints) 只接受关键点，自己不产关键点。ORB 的 detectAndCompute 一次干两件事。WLD 干脆连关键点都不要，它对整幅图逐像素扫。

描述子不产出关键点，这件事很要紧 #

BRIEF 是纯描述子。它必须外挂一个检测器，你不给关键点它什么也做不了。原论文里作者拿 CenSurE 提点，实测比配 SURF 的关键点稍好一点。我们自己写代码时为了省事配 SURF，跑出来的效果也就那样。

ORB 是检测加描述的一体机。名字就写着：Oriented FAST and Rotated BRIEF。前半截是检测，后半截是描述。

WLD 是纹理描述子，走的是另一条路。它不关心「点」，它关心「这一小块区域的纹理长什么样」。所以它输出的是整幅图的直方图，用在纹理分类、人脸识别、伪造检测这类任务上。

描述子的长度就是成本 #

描述子长度直接换内存和匹配时间。1000 个特征点，每个描述子占多少字节，乘一下就是内存账。

描述子 维度 单点占用 1000 点占用 距离计算方式
SIFT 128 维 float 512 字节 512 KB 欧氏距离
SURF 64 维 float 256 字节 256 KB 欧氏距离
BRIEF 128 / 256 / 512 位 16 / 32 / 64 字节 16 / 32 / 64 KB 汉明距离
ORB 256 位（默认） 32 字节 32 KB 汉明距离
WLD 12 × 8 × 4 维直方图 全图一份 384 个 float 直方图距离

嵌入式设备上这个账很硬。512 KB 描述子加上匹配时的临时缓冲，几百兆的内存预算直接被吃掉一块。二进制描述子把这块压到十分之一以下，还顺手把距离计算从浮点乘加换成了异或加查表。

匹配方式跟着描述子走 #

匹配不是独立环节，它的距离度量必须和描述子的数值类型对齐。

浮点描述子比较的是向量在高维空间里的远近，用欧氏距离。二进制描述子比较的是两个码串有几位不同，用汉明距离。

汉明距离的实现很朴素：两个码串异或，数结果里 1 的个数。这一步在通用 CPU 上就是一个 popcount 指令，在嵌入式上也能用查表凑出来。这就是二进制描述子快的原因，不是算法更聪明，是底层操作更便宜。

下面这段能跑，用来确认你手里的描述子到底是什么类型：

python
import cv2
import numpy as np

img = cv2.imread('./image/orb1.jpg', 0)

# 浮点描述子
sift = cv2.SIFT_create(100)
kp_s, des_s = sift.detectAndCompute(img, None)
print('SIFT', des_s.shape, des_s.dtype)   # (100, 128) float32

# 二进制描述子
orb = cv2.ORB_create(128)
kp_o, des_o = orb.detectAndCompute(img, None)
print('ORB ', des_o.shape, des_o.dtype)   # (128, 32) uint8

# 汉明距离就是异或后数 1
a = np.unpackbits(des_o[0])
b = np.unpackbits(des_o[1])
print('hamming =', int(np.sum(a != b)))

des_o.dtype 是 uint8，形状 (N, 32)，32 字节正好 256 位。des_s.dtype 是 float32，形状 (N, 128)。看到这两个 dtype，就该知道后面该传哪个 normType 了。

二、一个好的描述子要什么 #

描述子的好坏有一把公认的尺子，量的是它在各种干扰下还能不能认得出同一个点。

性质 含义 退化之后的表现
可复现性 同一物理点在不同图像里算出的描述子足够像 真匹配距离也很大，匹配率掉底
区分性 不同点的描述子差别足够大 满屏误匹配，比率测试筛不出来
紧凑性 位数少，占内存小 内存爆，匹配慢
计算代价 单点计算量小 实时性没了
光照鲁棒 亮度整体漂移不影响描述子 换个曝光就匹配不上
旋转鲁棒 图像转一圈，描述子基本不变 转 30 度就归零
尺度鲁棒 目标远近变化不影响描述子 金字塔层间对不上
噪声鲁棒 高斯噪声、压缩块不影响描述子 同一张图重拍都对不上

这八条互相打架。区分性高往往意味着维度长，维度长就慢；二进制描述子快，但比较的是原始灰度，对噪声和光照都敏。

两大流派 #

描述子的实现路径其实只有两条。

第一条是统计梯度或灰度的分布。SIFT 把邻域切成 4×4 个子块，每块统计 8 个方向的梯度直方图，拼成 128 维。SURF 用 Haar 小波的响应和代替梯度直方图，降到 64 维。HOG 是同一套思路用在检测窗口上。WLD 统计的是差分激励和方向的二维分布直方图，走的是纹理这条路。

第二条是比较像素对的相对关系。BRIEF 直接比较随机点对的灰度大小，一个点对出一位。BRISK 在同心圆上取点对。ORB 用 BRIEF 但把采样图案按主方向转了一下。

两条路的代价差得很远：

维度 梯度统计型 二进制比较型
代表 SIFT、SURF、HOG、WLD BRIEF、ORB、BRISK、FREAK
数值 float bit
距离 欧氏 / 卡方 汉明
计算 多次滤波 + 直方图累加 灰度比较 + 位拼接
内存 大 小
旋转不变 靠主方向对齐梯度 靠旋转采样图案
精度上限 高 中

距离度量的对照表 #

这张表要背下来。传错一个参数，匹配结果就是噪声。

描述子 dtype OpenCV normType 距离含义
SIFT float32 cv2.NORM_L2 128 维欧氏距离
SURF float32 cv2.NORM_L2 64 维欧氏距离
SIFT 的 L1 变体 float32 cv2.NORM_L1 绝对值之和
BRIEF uint8 cv2.NORM_HAMMING 码串不同的位数
ORB（WTA_K=2） uint8 cv2.NORM_HAMMING 码串不同的位数
ORB（WTA_K=3 或 4） uint8 cv2.NORM_HAMMING2 每 2 位一组的汉明距离
BRISK uint8 cv2.NORM_HAMMING 码串不同的位数

NORM_HAMMING2 是个特殊存在。ORB 的 WTA_K 设成 3 或 4 时，一个描述子位不再由一个点对决定，而是由 3 个或 4 个点里灰度最大的那个的编号决定。2 位的取值塞不进 1 位里，描述子按每 2 位编码，距离也得按 2 位一组算。

拿 float32 描述子喂 NORM_HAMMING，OpenCV 会直接抛异常，因为汉明距离只对 CV_8U 有意义。反过来把 uint8 描述子喂 NORM_L2，程序不报错，结果全错，因为欧氏距离在字节上算出来的数值没有物理意义。后者更危险，它静默地给你一堆垃圾匹配。

归一化不是可选项 #

SIFT 描述子在生成末尾要做两件事：先归一化到单位长度，把大于 0.2 的分量截断，再归一化一次。第一遍归一化消掉光照的线性缩放，截断压掉非线性光照造成的个别大分量，第二遍把截断后的长度补回来。

不做这一步，两张图曝光差一点，同一个点的描述子距离就能翻倍。二进制描述子靠比较大小，天然免疫线性光照变化，这是它省事的地方。

描述子的可复现性怎么量 #

给定两张图，同一个物理点在两幅图里的描述子距离，和不同物理点之间的描述子距离，要拉开差距。前者叫类内距离，后者叫类间距离。

一个描述子好用，意味着类内距离远小于类间距离。BRIEF 的论文里给过一组数：256 位描述子，不匹配的点对汉明距离在 128 附近，匹配的点对远小于 128。128 是 256 的一半，就是随机码串的期望距离，说明不相关的两个点算出来的码串跟掷硬币没区别。这个性质是二进制描述子的基线，也是比率测试能工作的前提。

三、WLD：韦伯局部描述符 #

纹理是图像里普遍存在又难描述的东西。粗糙的讲法：图像上地物重复排列，灰度值形成有规则的分布，这就是纹理。

抓纹理的路子有几种。灰度共生矩阵吃二阶概率密度；小波变换贴人眼视觉特性；纹理谱法看模式；纹理元方法找结构基元。LBP 和 WLD 属于后一类，都在邻域像素和中心像素的灰度变化上做文章。它们的共性是易懂、好算、局部描述能力够用，于是被推到纹理分类、目标检测、人脸识别、SAR 图像索引、指纹活体检测、图像伪造检测这些任务上。

WLD 全称 Weber Local Descriptor，韦伯局部描述符。

韦伯定律 #

韦伯定律本来是心理物理学的结论：能引起感觉差别的最小刺激变化量，和原始刺激强度的比值是个常数。

IΔI​=k

$k$ 是常数，ΔI 是差别阈值，$I$ 是原始刺激强度。这条式子的推论很直白：感觉上的变化量不只取决于刺激变了多少，还取决于原来有多强。在暗处挪一格亮度你觉得刺眼，在太阳底下挪同样一格你完全没感觉。

WLD 把这条定律搬到像素邻域上，用两个算子描述局部：差分激励算子和方向算子。计算除边缘像素外每个像素的这两个量，用它们的二维联合直方图表示纹理。

差分激励：灰度变化有多强 #

差分激励管的是局部窗内灰度变化的强度。

先算邻域像素与中心像素的灰度差之和，再除以中心像素灰度，得到比值 Gratio​(xc​)。这个比值的取值范围是 [−P,+∞)，$P$ 是邻域像素个数。用反正切把它压到 (−2π​,2π​)：

ξ(xc​)=arctan(Gratio​(xc​))=arctan(i=0∑P−1​xc​xi​−xc​​)

xc​ 是中心像素灰度，xi​, i=0,1,…,P−1 是邻域像素灰度。

这个式子里有两个设计意图藏在细节里。除以 xc​ 是韦伯定律的直接体现，亮区的绝对变化要除以亮区的基准才可比。arctan 是饱和函数，把过大的比值压进有界区间，防止个别极端像素支配整个直方图。

方向：灰度变化朝向哪 #

方向算子管的是局部窗内灰度变化的空间分布。

取水平方向和垂直方向上中心像素两侧的灰度差，求比值的反正切：

Φ(xc​)=arctan(DH​DV​​)

DH​ 是水平方向中心像素两侧的灰度差，DV​ 是垂直方向的。拿 3×3 窗口、按行优先编号 x0​ 到 x8​ 的约定，DH​=x7​−x3​，DV​=x5​−x1​。

arctan 的值域是 (−2π​,2π​)，只覆盖半圈，分不出对角象限。所以要把它搬到 [0,2π)：

Φ′(xc​)=⎩⎨⎧​Φ(xc​)π+Φ(xc​)π+Φ(xc​)2π+Φ(xc​)​DH​>0, DV​>0DH​<0, DV​>0DH​<0, DV​<0DH​>0, DV​<0​

四段拼起来正好一整圈。第二、第三象限共用 π+Φ，因为原来的 arctan 在那两个象限里给出的正是负值，加上 π 就落回去了。

二维直方图怎么建 #

WLD 用均匀量化。方向 Φ′ 均分成 $T$ 份，差分激励先分成 $M$ 个频段（对应高频、中频、低频变化），每个频段内再均分成 $S$ 格。合起来是 T×C 的二维直方图，其中 C=M×S。

横轴是方向，纵轴是差分激励。每个小矩形记录落在这个（方向，激励区间）里的像素数，数量不同颜色不同。最后按编码规则把它拉成一维向量，作为图像纹理特征的表示。

具体步骤：

  1. 在每个主方向上统计差分激励，得到 $T$ 个子直方图 $H(0)$ 到 H(T−1)。
  2. 把每个 $H(k)$ 分成 $M$ 个子区间 lm​, m=0,…,M−1，把 lm​ 放到坐标 (t=k, m=i) 处。
  3. 把 m=i 这一行的子直方图横向拼成一个直方图 Hi​。
  4. 把所有 Hi​ 拼起来，得到 WLD 直方图。

WLD 区分不了的三种模式 #

这是 WLD 的硬伤，值得单独拎出来。

取三个局部窗，灰度分布分别是高频变化、中频变化、低频变化。按 WLD 的算法算一遍：三种模式下邻域灰度和中心灰度的差值和 ΔI 都等于 0，差分激励就是 0；垂直方向的灰度差值也是 0，方向也是 0。

三种肉眼一看就不同的纹理，WLD 给出完全相同的描述。它分不开。

原因有两条：

  • 差分激励算子本质是个各向同性的边缘检测滤波器，用拉普拉斯核统计邻域与中心的灰度差之和。差值有正有负，加起来互相抵消，局部窗内的灰度变化信息没被充分表达。
  • 方向算子只看水平和垂直两个方向上的梯度方位，表达不了局部窗内灰度变化的空间分布结构，纹理内在的变化特征体现不出来。

纹理既跟各像素间灰度变化的梯度幅值有关，也跟梯度的空间分布有关，两者是一体的。WLD 把它们拆开算，又在各自环节里丢信息，于是撞上这个盲区。

WLD-PNG：正负梯度分离 #

针对上面两个问题，有改进版 WLD-PNG，核心思想两条。

第一条，用局部窗内邻域与中心像素之间灰度变化的正负梯度信息，把正、负差分激励分开算，保住灰度等级的变化特征。原来一个 ΔI 把正负差抵消了，现在正的一路负的一路，各自成账。

第二条，用 LBP 模式提取正负梯度分布的结构信息，反映灰度等级变化的空间分布特征。LBP 擅长表达局部结构的模式类型，正好补上方向算子丢掉的空域结构。

最后把两者用均匀量化和编码技术联合起来，建立纹理特征。这篇不展开 WLD-PNG 的实现，把改进思路记清楚就够了：WLD 的差分激励是求和，求和就抵消，抵消就丢信息，这是设计层面的漏洞，不是参数没调好。

WLD 的代码实现 #

OpenCV 没有提供 WLD。网上能找到的人脸识别版本和 WLD 特征提取程序都是各自改的，下面这一版是自己重写的。

核心是四个滤波器。f1​ 算邻域和与中心的反差，f2​ 取中心像素本身，两者相除就是 Gratio​。f3​ 取垂直方向两侧的差，f4​ 取水平方向两侧的差。

python

                              [0, 1, 0],
                              [0, 0, 0]])

        self.__f3 = np.array([[0, -1, 0],
                              [0, 0, 0],
                              [0, 1, 0]])
        self.__f4 = np.array([[0, 0, 0],
                              [1, 0, -1],
                              [0, 0, 0]])
        # 方向量化个数，修改时也要改 __classify_fai
        self.__T = 12
        # 差分激励量化个数，修改时也要改 __classify_epc
        self.__M = 8
        # 每个频段上把差分激励再均分为 S 格
        self.__S = 4

    def calc_hist(self, image, concatenate=True):
        '''
        输出统计直方图，形状 [M, T, S] 或 [MxTxS, ]
        '''
        his = np.zeros((self.__M, self.__T, self.__S), np.float32)
        rows, cols = image.shape[:2]
        sum_pix = rows * cols
        epc, theta = self.__compute(image)
        for i in range(rows):
            for j in range(cols):
                # 把差分激励分为 8 个区间，各对应一个类别
                m = self.__classify_epc(epc[i][j])
                t = theta[i][j]
                s = self.__classify_s(epc[i][j], m)
                his[m - 1][t - 1][s - 1] += 1
        # 归一化
        his /= sum_pix
        if concatenate:
            his = np.reshape(his, -1)
        return his

    def __compute(self, image):
        '''
        计算每个像素点的差分激励和方向
        '''
        rows, cols = image.shape[:2]
        epc = np.zeros((rows, cols), dtype=np.float32)
        theta = np.zeros((rows, cols), dtype=np.float32)

        # 差分激励 xi
        v1 = cv2.filter2D(image, cv2.CV_16SC1, self.__f1)
        v2 = cv2.filter2D(image, cv2.CV_16SC1, self.__f2)
        for i in range(rows):
            for j in range(cols):
                # 值域 -pi/2 ~ pi/2
                epc[i][j] = np.arctan(v1[i][j] / (v2[i][j] + 0.0001))

        # 方向 Phi，把 [0, 2pi] 均匀量化为 12 个区间
        v3 = cv2.filter2D(image, cv2.CV_16SC1, self.__f3)
        v4 = cv2.filter2D(image, cv2.CV_16SC1, self.__f4)
        for i in range(rows):
            for j in range(cols):
                theta[i][j] = np.arctan(v3[i][j] / (v4[i][j] + 0.0001))
                if v3[i][j] > 0 and v4[i][j] > 0:
                    pass
                elif v3[i][j] > 0 and v4[i][j] < 0:
                    theta[i][j] = theta[i][j] + 2 * np.pi
                else:
                    theta[i][j] = theta[i][j] + np.pi
                theta[i][j] = self.__classify_fai(theta[i][j])
        theta = theta.astype(np.uint8)
        return epc, theta

0.0001 是防除零的偏置。f2​ 只留中心像素，纯黑区域的中心灰度是 0，不加偏置就出 inf。

分类函数把连续值打成离散桶编号。方向按 0.15π 和 0.35π 这类不等宽边界切成 12 段，刻意做成不等宽是为了让纹理方向的主导区间拿到更多分辨率。差分激励按 0.05π、0.15π、0.3π 切成 8 段，中间密两头疏，因为接近 0 的地方才是纹理的常态。

    def __classify_epc(self, value):
        '''
        把差分激励值分类，划分为 8 个区间，类别 1~8
        '''
        if value >= np.pi * (-0.5) and value < (-0.3) * np.pi:
            return 1
        elif value >= np.pi * (-0.3) and value < (-0.15) * np.pi:
            return 2
        elif value >= np.pi * (-0.15) and value < (-0.05) * np.pi:
            return 3
        elif value >= np.pi * (-0.05) and value < 0:
            return 4
        elif value >= 0 and value < 0.05 * np.pi:
            return 5
        elif value >= np.pi * 0.05 and value < 0.15 * np.pi:
            return 6
        elif value >= np.pi * 0.15 and value < 0.3 * np.pi:
            return 7
        else:
            return 8

    def __classify_s(self, value, label):
        '''
        把每个区间内的差分激励再划分为 S 格
        '''
        if label == 1:
            space = ((-0.3) * np.pi - (-0.5) * np.pi) / self.__S
            return int((value - (-0.5) * np.pi) / space) + 1
        elif label == 2:
            space = ((-0.15) * np.pi - (-0.3) * np.pi) / self.__S
            return int((value - (-0.3) * np.pi) / space) + 1
        elif label == 3:
            space = ((-0.05) * np.pi - (-0.15) * np.pi) / self.__S
            return int((value - (-0.15) * np.pi) / space) + 1
        elif label == 4:
            space = 0 - (-0.05) * np.pi / self.__S
            return int((value - (-0.05) * np.pi) / space) + 1
        elif label == 5:
            space = 0.05 * np.pi / self.__S
            return int(value / space) + 1
        elif label == 6:
            space = (0.15 * np.pi - 0.05 * np.pi) / self.__S
            return int((value - 0.05 * np.pi) / space) + 1
        elif label == 7:
            space = (0.3 * np.pi - 0.15 * np.pi) / self.__S
            return int((value - 0.15 * np.pi) / space) + 1
        else:
            space = (0.5 * np.pi - 0.3 * np.pi) / self.__S
            n = int((value - 0.3 * np.pi) / space) + 1
            if n == self.__S + 1:
                n = self.__S
            return n

__classify_s 里 label 等于 4 的分支有个运算符优先级陷阱：0 - (-0.05) * np.pi / self.__S 实际算的是 0 - ((-0.05*pi)/S)，结果是个负数。这一支的 space 应该是 0.05*pi/S。代码原样如此，跑起来这一格的索引会算错，读代码时注意。

__classify_s 的最后一支为什么要卡 n == S+1：arctan 的值域是开区间，但浮点逼近会正好给出 2π​，算出来的索引就溢出到 S+1，落进一个不存在的格子。这个钳位是必需的，不是保守写法。

四、BRIEF：二进制描述子 #

SIFT 用 128 维浮点描述子，512 字节。SURF 用 64 维，256 字节。1000 个特征点，SIFT 就要 512 KB，SURF 要 256 KB。资源紧张的应用，尤其嵌入式，这个量级直接判死刑。而且占的空间越大，匹配就越慢，两件事是绑在一起的。

但这些维里不是每一维都在匹配时起作用。PCA、LDA 这类降维能压一压。局部敏感哈希（LSH）走得更远，直接把 SIFT 描述子转成二值码串，用汉明距离做匹配。汉明距离的计算是异或加数位，现代计算机结构上非常便宜。

BRIEF 走的是另一条更彻底的路：根本不算那个类 SIFT 的描述子，直接从像素比较里出二进制串。

BRIEF 到底在干什么 #

BRIEF，Binary Robust Independent Elementary Features。

流程不复杂：先平滑图像，在特征点周围取一个 Patch，在 Patch 内按选定的方法挑出 nd​ 个点对。对每个点对 $(p, q)$，比较两点的亮度。如果 $I(p) < I(q)$，对应的位取 1，否则取 0。nd​ 个点对全比完，得到一个 nd​ 位的二进制串。

就这些。没有梯度，没有直方图，没有归一化，没有浮点运算。整个过程是一串比较。

nd​ 可以取 128、256、512，OpenCV 三个都支持，默认 256。256 位时，大量实验给出的结论是：不匹配的特征点描述子汉明距离在 128 左右，匹配点对的汉明距离远小于 128。128 是 256 的一半，恰好是随机码串的期望值，说明不相关的两个点算出来的码串跟掷硬币一样。维数定下来，就可以用汉明距离做匹配了。

建立描述子的完整步骤 #

  1. 用 Harris、FAST 等方法检测特征点。
  2. 选定建立描述子的区域，即特征点的一个正方形邻域。
  3. 对该邻域用 σ=2、窗口尺寸 9 的高斯核卷积，消除噪声。这个描述子随机性强，对噪声敏感，平滑不能省。
  4. 用一定的随机化算法生成点对 $(p, q)$，比较 $I(p)$ 和 $I(q)$，前者小返回 1，否则返回 0。
  5. 重复第四步若干次（比如 256 次），得到一个 256 位的二进制码串。

BRIEF 只是描述符，不提供提取特征点的方法。必须外挂一个定位方法，FAST、SIFT、SURF 都行。原论文里作者用 CenSurE 提点，对 BRIEF 来说 CenSurE 的表现比 SURF 特征点稍好一些。

点对的五种选法 #

在特征点邻域 S×S 内选 nd​ 个点对 $(p, q)$，Calonder 的实验中测了五种采样方法：

  • 在图像块内平均采样。
  • $p$ 和 $q$ 都服从 (0,251​S2) 的高斯分布。
  • $p$ 服从 (0,251​S2) 的高斯分布，$q$ 服从 (0,1001​S2) 的高斯分布。
  • 在空间量化极坐标下的离散位置随机采样。
  • 把 $p$ 固定为 $(0,0)$，$q$ 在周围平均采样。

第二种在实测里表现最好，也成了事实标准。$p$、$q$ 都靠近中心，采样点落在特征点周围的概率高，描述子对旋转和视角变化的敏感性低一些。第三种让 $q$ 更分散，是想在中心附近和外围之间拉开跨度。

五种方法的共同点：都是预先固定的采样图案，与图像内容无关。一旦选定，所有特征点用同一套点对。这正是 BRIEF 快的根源，也埋下了它最大的隐患。

优点集中在速度：抛弃了灰度直方图和梯度直方图那套统计，改用检测随机响应，描述子建立速度大幅提升；生成的二进制串便于高速匹配，异或加数位统计在底层运算里实现，硬件上也好做。

  • 不具有旋转不变性。
  • 对噪声敏感。
  • 不具有尺度不变性。

后两条可以靠预处理缓解，第一条是结构性的。旋转问题需要专门的方法修补，ORB 就是冲着这条来的。

def brief_test():

    img1 = cv2.resize(img1, dsize=(600, 400))

    surf = cv2.xfeatures2d.SURF_create(3000)
    keypoints1 = surf.detect(image1)

                               color=(255, 0, 255),

                               color=(255, 0, 255),
                               flags=cv2.DRAW_MATCHES_FLAGS_DRAW_RICH_KEYPOINTS)
    cv2.imshow('sift_keypoints1', image1)
    cv2.imshow('sift_keypoints2', image2)
    cv2.waitKey(20)

    # 2. 计算特征描述符，参数 32 表示 32 字节 = 256 位
    brief = cv2.xfeatures2d.BriefDescriptorExtractor_create(32)
    keypoints1, descriptors1 = brief.compute(image1, keypoints1)
    keypoints2, descriptors2 = brief.compute(image2, keypoints2)

    print('descriptors1:', len(descriptors1), 'descriptors2', len(descriptors2))

    # 3. 汉明距离匹配
    matcher = cv2.BFMatcher_create(cv2.HAMMING_NORM_TYPE)
    matchePoints = matcher.match(descriptors1, descriptors2)

    # 统计距离分布
    minMatch = 1
    maxMatch = 0
    for i in range(len(matchePoints)):
        if minMatch > matchePoints[i].distance:
            minMatch = matchePoints[i].distance
        if maxMatch < matchePoints[i].distance:
            maxMatch = matchePoints[i].distance
    print('最佳匹配值:', minMatch)
    print('最差匹配值:', maxMatch)

    # 取距离靠前的一批作为较好匹配
    goodMatchePoints = []
    for i in range(len(matchePoints)):
        if matchePoints[i].distance < minMatch + (maxMatch - minMatch) / 3:
            goodMatchePoints.append(matchePoints[i])

                             flags=cv2.DRAW_MATCHES_FLAGS_DEFAULT)
    cv2.imshow('matche', outImg)
    cv2.waitKey(0)
    cv2.destroyAllWindows()

BriefDescriptorExtractor_create(32) 的 32 是字节数，对应 256 位、256 个点对。传 16 就是 128 位，传 64 就是 512 位。

cv2.HAMMING_NORM_TYPE 就是 cv2.NORM_HAMMING。这里的匹配器必须用汉明距离，换成默认的 NORM_L2 会跑出一堆无意义的数。

brief.compute 返回的关键点数量会少于输入。它内部会把太靠近边界的关键点剔掉，因为 Patch 加平滑核的范围超出了图像。

那段按 minMatch + (maxMatch - minMatch) / 3 筛匹配的写法，只是按距离分布的相对位置粗略截断，不是比率测试。它能砍掉最差的一批，但砍不掉「最近邻和次近邻一样近」这种歧义匹配。真正的过滤在后面误匹配剔除那一章。

实际跑起来效果一般。BRIEF 对噪声敏感，做了中值滤波，消掉部分误匹配点，但整体匹配质量还是不够。要拿到好的匹配质量，得选两张近似一致、噪声点少的图像。这条不是推脱，是 BRIEF 的适用边界。

自己实现一遍 #

照着 OpenCV 的 C++ 实现抄一遍，能看清 BRIEF 内部的全部机制。

实现要点四个：

  • Patch 尺寸 48，平滑核尺寸 9。关键点距图像边界不足 (48+9)/2 的直接丢掉。
  • 用积分图算窗口和。任取一个点，它周围 9×9 的灰度均值 = 积分图四次查表的加减，O(1)。
  • 每个字节装 8 个点对，用移位把比较结果拼进去。
  • 点对的相对坐标全部写死在代码里，是预先算好的常量表。
python
# -*- coding: utf-8 -*-
'''
自己实现一个 BRIEF 特征描述符
'''
import cv2
import numpy as np
import functools


class BriefDescriptorExtractor(object):
    '''
    BRIEF 描述符实现
    '''
    def __init__(self, byte=16):
        # 邻域范围
        self.__patch_size = 48
        # 平均积分核大小
        self.__kernel_size = 9
        # 占用字节数，16 对应 16*8 = 128 位，即 128 个点对
        self.__bytes = byte

    def compute(self, image, keypoints):
        '''
        计算特征描述符，返回 (特征点, 描述符) 元组
        '''
        if len(image.shape) == 3:
            gray_image = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
        else:
            gray_image = image.copy()
        # 计算积分图像
        self.__image_sum = cv2.integral(gray_image, sdepth=cv2.CV_32S)

        # 移除接近边界的关键点
        keypoints_res = []
        rows, cols = image.shape[:2]
        for keypoint in keypoints:
            point = keypoint.pt
            if point[0] > (self.__patch_size + self.__kernel_size) / 2 \
                    and point[0] < cols - (self.__patch_size + self.__kernel_size / 2):
                if point[1] > (self.__patch_size + self.__kernel_size) / 2 \
                        and point[1] < rows - (self.__patch_size + self.__kernel_size) / 2:
                    keypoints_res.append(keypoint)

        return keypoints_res, self.pixelTests16(keypoints_res)

    def smoothed_sum(self, y, x, keypoint):
        '''
        不采用论文中的高斯平滑，用点邻域内的积分和代替，同样能降低噪声影响
        y, x 是点对中某个像素相对特征点的坐标
        '''
        half_kernel = self.__kernel_size // 2

        # 该像素的绝对坐标
        img_y = int(keypoint.pt[1] + 0.5) + y
        img_x = int(keypoint.pt[0] + 0.5) + x

        # 以该像素为中心、边长 KERNEL_SIZE 的正方形内灰度之和，本质是均值滤波
        ret = self.__image_sum[img_y + half_kernel + 1][img_x + half_kernel + 1] \
            - self.__image_sum[img_y + half_kernel + 1][img_x - half_kernel] \
            - self.__image_sum[img_y - half_kernel][img_x + half_kernel + 1] \
            + self.__image_sum[img_y - half_kernel][img_x - half_kernel]
        return ret

积分图那四行的符号是标准的容斥：右下角减去上方和左侧的重复部分，再加回被减了两次的左上角。索引里的 +1 是因为积分图比原图各边多一行一列。

pixelTests16 是精华所在。它把一个字节的 8 位，用 8 个点对比较结果拼出来：

    def pixelTests16(self, keypoints):
        '''
        创建 BRIEF 描述符
        '''
        descriptors = np.zeros((len(keypoints), self.__bytes), dtype=np.uint8)
        for i in range(len(keypoints)):
            # 固定默认参数
            SMOOTHED = functools.partial(self.smoothed_sum, keypoint=keypoints[i])
            descriptors[i][0] = (((SMOOTHED(-2, -1) < SMOOTHED(7, -1)) << 7) +
                                 ((SMOOTHED(-14, -1) < SMOOTHED(-3, 3)) << 6) +
                                 ((SMOOTHED(1, -2) < SMOOTHED(11, 2)) << 5) +
                                 ((SMOOTHED(1, 6) < SMOOTHED(-10, -7)) << 4) +
                                 ((SMOOTHED(13, 2) < SMOOTHED(-1, 0)) << 3) +
                                 ((SMOOTHED(-14, 5) < SMOOTHED(5, -3)) << 2) +

二进制描述子为什么快 #

快的原因有三层，值得拆开看。

第一层，生成快。每个点对只做两次窗口和查询和一次比较，全程整数运算。窗口和靠积分图 O(1) 拿到，不需要滤波，不需要累加直方图。

第二层，存储省。256 位 32 字节，1000 个点占 32 KB。SIFT 同样 1000 个点占 512 KB，差 16 倍。缓存友好度完全不同，SIFT 的描述子矩阵远超 L1/L2 缓存，匹配时不断从内存拉数据。

第三层，距离计算便宜。两个 32 字节的串，异或得到 32 个字节，每个字节查一次 256 项的 popcount 表再求和，32 次查表加法搞定。SIMD 指令一次能处理 32 个字节，一条指令就是一半的距离计算。浮点欧氏距离要 128 次减法、乘法、累加，还要开方。

三层叠起来，40 倍的速度差就解释清楚了。

五、BRIEF 的旋转不变性缺陷 #

BRIEF 的采样点对是写死的绝对坐标。同一个关键点，图像转 30 度，像素的位置关系全变了，采到的点对比较出来的是完全不同的码串。

假设第 0 号点对的坐标是 (−2,−1) 和 (7,−1)。原图里这两点一个在纹理的亮条上、一个在暗条上，比较结果是 1。图像顺时针转 30 度之后，同样的相对坐标落到了别的位置，两点都落在亮条上，比较结果变成 0。

每一位都有独立出错的机会，256 位里错 20 位，汉明距离就是 20。听起来不大，但真匹配的期望距离本来只有十几，20 位已经把真匹配推到不匹配的区间里去了。

实测曲线 #

前面那张表里的数字是硬的：旋转小于 30 度，BRIEF 的匹配率多数情况超过 SURF；旋转大于 30 度，匹配率快速降到 0 左右。

降到 0 不是「效果变差」，是「完全失效」。这个断崖式下跌的原因很简单：随机点对比较出来的码串，一旦旋转让大部分对比较结果翻转，码串就退化成随机串。两组随机串的汉明距离在位数一半附近，256 位就是 128 左右，跟不相关点对的分布完全重叠。这种情况下比率测试也救不了，因为最近邻和次近邻的距离一样烂。

缺陷的根源：没有方向的描述 #

BRIEF 的比较结果只依赖两个量：采样点的位置，和该位置附近的灰度。位置是固定的，灰度随图像内容变。图像旋转，位置不动，采到的内容变了。

要修这个问题，只有一条路：让采样点的位置跟着图像一起转。而跟着什么转，就得先知道「转了多少」。

这就是方向的概念。描述子必须知道自己该往哪个角度对齐。

ORB 走的是第二条，也是唯一实用的那条。

尺度问题同样存在 #

BRIEF 也不具备尺度不变性。同一个物体拍远一点，关键点邻域的物理范围没变，但图像上的像素跨度变了，固定 48 像素的 Patch 覆盖的内容完全不同。

尺度问题靠金字塔解决：每一层金字塔上检测关键点，在各自那层算描述子。这样不同尺度下的点各算各的，匹配时跨层比较。ORB 就是这么干的。

噪声敏感也一样要治。BRIEF 比较的是单点附近的灰度，椒盐噪声能直接翻转比较结果。前面代码里的中值滤波、高斯平滑、积分图窗口和，都是在给单点灰度做平均，把这层噪声压下去。

ORB 在这一块做得更彻底，它不比较单点，比较的是 5×5 窗口的平均灰度。这样噪声的影响被 25 个像素平摊，单个噪点翻不动比较结果。

六、ORB：FAST + BRIEF 的组合 #

SIFT 和 SURF 精度好，计算慢。ORB 是冲着速度来的，2011 年首次发布，思路是把 FAST 的关键点检测和 BRIEF 的描述子结合，两头都做改进。

ORB 全称 Oriented FAST and Rotated BRIEF，名字就是它的设计文档。

第一步：FAST 找点，Harris 排序 #

先用 FAST 检测特征点。FAST 只判断「这个点周围有没有一圈明显不同的像素」，快，但会吐出大量点，而且不给响应强度。

接着用 Harris 角点的度量方法，从 FAST 点里挑出 Harris 响应值最大的 N 个。Harris 响应函数：

R=detM−k(trace(M))2

$M$ 是邻域内梯度协方差矩阵。FAST 不给响应，Harris 给，拿 Harris 来排序就把 FAST 的短板补齐了。

这个组合的意义：FAST 的检测速度加上 Harris 的质量排序，前者快、后者准。

第二步：金字塔补尺度 #

ORB 没有从算法层面解决尺度不一致。OpenCV 的实现用图像金字塔兜底：构建高斯金字塔，在每一层上检测角点，实现尺度不变性。

这是个工程妥协，不是原理突破。金字塔层数越多，能覆盖的尺度范围越大，代价是检测时间线性增长，跨层匹配的候选也变多。

参数上，nlevels 控制层数，scaleFactor 控制层间尺度比，类似 SIFT 里的 $k$。

第三步：灰度质心法算主方向 #

这是 ORB 补 BRIEF 旋转缺陷的核心。思路：假设角点的灰度和它的质心之间存在一个偏移向量，这个向量指向的方向就是主方向。图像转了，质心跟着转，偏移向量也转，方向就对了。

对任意特征点 $p$，定义邻域像素的矩：

mij​=x=−r∑r​y=−r∑r​xiyjI(x,y)

$I(x,y)$ 是点 $(x,y)$ 处的灰度，i,j=0,1，$r$ 是邻域半径。质心坐标：

C=(m00​m10​​, m00​m01​​)

特征点与质心的夹角就是 FAST 特征点的方向：

θ=arctan(m01​, m10​)

注意 m00​ 是邻域灰度总和，m10​、m01​ 是灰度加权的一阶矩。两者相除得到质心的归一化位置，与灰度绝对强度无关，所以对光照的线性变化免疫。

为了提高旋转不变性，要保证 $x$ 和 $y$ 落在半径为 $r$ 的圆形区域内，即 x,y∈[−r,r]，$r$ 等于邻域半径。用圆而不是方，是因为圆在旋转下形状不变，方形窗口旋转后会切掉角上的内容，质心会漂。

质心法的成本很低：m00​、m10​、m01​ 三个和，每个都是邻域内的加权累加，用积分图或简单的循环就能算。相比描述子本身的 256 次比较，这点开销可以忽略。

第四步：Steer BRIEF #

拿到方向 θ，就可以把采样图案转过去。

对一个特征点，它的 BRIEF 描述子是长度 $n$ 的二值码串，由邻域内 $n$ 个点对生成。把这 $2n$ 个点 (xi​,yi​), i=1,2,…,2n 排成一个矩阵 $S$：

S=[x1​y1​​x2​y2​​……​x2n​y2n​​]

用邻域方向 θ 和对应的旋转矩阵 Rθ​ 构建 $S$ 的校正版本：

Sθ​=Rθ​S

其中：

Rθ​=[cosθ−sinθ​sinθcosθ​]

θ 就是上一步求的主方向。

几何含义直白：把坐标轴转 θ，在以主方向为基准的新坐标系里取点对。图像整体转了 θ，主方向跟着转 θ，采样图案也转 θ，两者抵消，采到的内容不变。

第五步：查表省掉实时旋转 #

每个关键点算一次 Rθ​S，$n$ 个点对就是 $n$ 次旋转矩阵乘法。虽然不贵，但可以更省。

角度离散化：把 360 度分成 12 份，每份 30 度，对 12 个角度分别预先算好一个 Sθ​，做成查找表。每个关键点算出 θ 之后，按最近的 30 度格去查表，直接拿到点集。

代价是方向精度从连续降到 30 度一格，收益是运行时只剩一次查表。30 度的量化误差对 256 位描述子的影响可以接受，这是典型的工程取舍。

第六步：rBRIEF 学出来的点对 #

Steer BRIEF 有个副作用。原来 BRIEF 的每个特征位，在所有特征点上取值的均值接近 0.5，方差很大。方差大意味着区分性强，不同点的描述子差异明显，匹配时不容易误配。

把 BRIEF 按方向调成 Steered BRIEF 之后，均值漂移到更加分散的模式。有方向性的角点关键点对二值串表现出更均衡的分布。论文里用 PCA 分析各个特征向量，结论是 Steered BRIEF 的方差很小，判别性弱，各成分之间相关性大。

方差小就是区分性差，码串之间长得太像，匹配就糊。

为了补回损失的方差、降低码串之间的相关性，ORB 用学习方法挑一组更好的点对，这就是 rBRIEF。

流程：

  1. 建一个约 300k 关键点的测试集，来自 PASCAL 2006 的图像。
  2. 对每个关键点取 31×31 邻域。不同于 BRIEF 先平滑再用高斯分布选点对，ORB 直接算 5×5 区域的平均灰度来代替单点灰度。这里用积分图算均值，噪声被 25 个像素摊平。
  3. 31×31 的 Patch 里有 N=(31−5+1)×(31−5+1) 个这样的 5×5 窗口。从 $N$ 个里选 2 个，共 CN2​ 种选法。
  4. 对 300k 个关键点中的每一个，都能从 31×31 邻域里提取一个很长的二进制串，长度 M=CN2​：
binArray=[p1​​p2​​…​pM​​],pi​∈{0,1}
  1. 300k 个关键点全部做完，得到一个 300k×M 的矩阵，元素是 0 或 1。
  2. 对矩阵的每个列向量（即每个点对在 300k 个点上的测试结果）算均值，按均值重新排序所有列向量，排好组成向量 $T$，$T$ 的每个元素是一个列向量。
  3. 贪婪搜索：把 $T$ 中排第一的列放进 $R$，从 $T$ 里删掉这个点对的测试结果；然后拿 $T$ 中下一个列与 $R$ 里所有元素比较，算相关性，超过预设阈值就丢掉，否则放进 $R$。重复，直到 $R$ 里有 256 个列向量。
  4. 如果 $T$ 走完了还没凑够 256 个，就把相关阈值调高再跑一遍。

这样得到 256 个点对。整个过程叫 rBRIEF。

按均值排序的原因：均值在 0.5 附近的位，0 和 1 各占一半，信息量最大；均值接近 0 或 1 的位几乎恒定，没有区分作用。先排掉低信息量的位，再去做相关性剔除，效率更高。

相关阈值那一步是在保证 256 位里的每一位都尽量独立。位之间相关，等于可用的维度变少，描述子的实际信息量低于 256 位。

七、匹配：暴力匹配与 KNN #

描述子算出来，匹配就是算距离。OpenCV 提供两套东西：BFMatcher 暴力匹配，FlannBasedMatcher 近似最近邻。

暴力匹配 #

两两匹配。A 图提了 $m$ 个描述子，B 图提了 $n$ 个，A 中每一个都要和 B 中所有 $n$ 个比一遍。每次比较给一个距离值，排序，取距离最近的一个作为匹配点。

复杂度 $O(mn)$。1000 对 1000 就是一百万次距离计算。二进制描述子每次 32 次查表加法，一百万次也就几毫秒，可以接受。浮点描述子每次 128 维运算，一百万次就开始难受了。

结果显而易见：大量错误匹配。原因也简单，A 中的某个点，在 B 中总能找到一个距离最近的点，哪怕那个点在物理上毫不相干。距离最小不等于匹配正确，只是在所有候选里相对最小。

这就是为什么后面必须上过滤机制。原始匹配结果不能直接用。

BFMatcher 的接口 #

python
cv2.BFMatcher_create([, normType[, crossCheck]])

两个参数：

normType 指定距离度量类型。默认 cv2.NORM_L2，适合 SIFT、SURF 这类浮点描述子，cv2.NORM_L1 也能用。二进制描述子（ORB、BRIEF、BRISK）必须用 cv2.NORM_HAMMING，返回两个对象的汉明距离。ORB 的 WTA_K 设为 3 或 4 时，要用 cv2.NORM_HAMMING2。

crossCheck 是交叉匹配开关，默认 False。设成 True 之后条件严格得多：只有 A 中第 $i$ 个点到 B 中第 $j$ 个点最近，且 B 中第 $j$ 个点到 A 中第 $i$ 个点也最近，才返回最佳匹配 $(i, j)$。也就是两个点要互相认对方为最近。

交叉验证的代价是计算量翻倍（两个方向都要建索引），收益是过滤掉一大批单向的误匹配。一个纹理独特的点被很多点当成最近邻，那些点之间的匹配就都是单向的，交叉验证能砍掉。

两个方法：match 和 knnMatch #

BFMatcher.match() 返回最佳匹配，每个 query 描述子对应一个 train 描述子。结果是一组 DMatch，用 cv2.drawMatches() 画出来。两幅图先水平拼接，然后在匹配点之间画直线。

BFMatcher.knnMatch() 返回每个关键点的 $k$ 个最佳匹配，$k$ 由用户设定。用 cv2.drawMatchesKnn() 画。要选择性绘制就传一个掩码。

$k$ 近邻匹配的语义：为每个点选 $k$ 个最相似的点。如果这 $k$ 个点之间的差异足够大，就选最相似的那个作为匹配。选 k=2，表示对每个匹配返回最近和次近两个。这是 Lowe 比率测试的基础。

DMatch 的四个属性：

属性 含义
distance 两个描述子之间的距离，越小越好
queryIdx 描述子在 query 描述符集里的索引，即 A 图
trainIdx 描述子在 train 描述符集里的索引，即 B 图
imgIdx train 图像的索引，多图匹配时才用得上

queryIdx 和 trainIdx 别搞反。后面取坐标算单应性时，kp1[m.queryIdx].pt 对应 A 图，kp2[m.trainIdx].pt 对应 B 图。反了，单应性矩阵的方向就反了，透视变换画出来的框会跑到图像外面。

交叉验证与 KNN 的对比 #

策略 判据 保留比例 适用
无过滤 最近邻即匹配 100% 只用来看点分布
距离阈值 distance < D 看 D 的取值 描述子尺度已知时
交叉验证 双向都最近 大幅减少 快速粗筛
KNN + 比率 最近距离 / 次近距离 < 阈值 实测剩 10%~30% 标准做法

交叉验证不需要调参，比率测试需要定阈值。两者可以叠加，也可以只用一个。工程上最常见的是 KNN 加比率测试，交叉验证作为可选的额外约束。

FLANN：大数据集才需要 #

FLANN 全称 Fast Library for Approximate Nearest Neighbors，做最近邻搜索的库，官网 http://www.cs.ubc.ca/research/flann，GitHub 在 https://github.com/mariusmuja/flann。

它针对大型数据集中的快速最近邻搜索和高维特征做了优化。数据集大时比 BFMatcher 快得多。官方给的说法是比其他最近邻搜索软件快 10 倍。

关键在「近似」。FLANN 不一定给你真正的最近邻，它用索引结构快速缩小搜索范围，用精度换速度。数据集小的时候，建索引的开销反而让 FLANN 比暴力匹配慢。特征点几百个，直接 BFMatcher 就行。

python
def flann_test():
    img1 = cv2.imread('./image/orb1.jpg')
    gray1 = cv2.cvtColor(img1, cv2.COLOR_BGR2GRAY)
    img2 = cv2.imread('./image/orb2.jpg')
    img2 = cv2.resize(img2, dsize=(450, 300))
    gray2 = cv2.cvtColor(img2, cv2.COLOR_BGR2GRAY)
    queryImage = gray1.copy()
    trainImage = gray2.copy()

    sift = cv2.SIFT_create(100)
    keypoints1, descriptor1 = sift.detectAndCompute(queryImage, None)
    keypoints2, descriptor2 = sift.detectAndCompute(trainImage, None)
    print('descriptor1:', descriptor1.shape, 'descriptor2', descriptor2.shape)

    # FLANN 匹配
    FLANN_INDEX_KDTREE = 0
    indexParams = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
    searchParams = dict(checks=50)
    flann = cv2.FlannBasedMatcher(indexParams, searchParams)
    matches = flann.knnMatch(descriptor1, descriptor2, k=2)

    # 设置 mask 过滤匹配点
    matchesMask = [[0, 0] for i in range(len(matches))]

    minRatio = 1 / 3
    for i, (m, n) in enumerate(matches):
        if m.distance / n.distance < minRatio:
            matchesMask[i] = [1, 0]   # 只绘制最优匹配点

    drawParams = dict(matchesMask=matchesMask, flags=0)
    resultImage = cv2.drawMatchesKnn(queryImage, keypoints1, trainImage, keypoints2,
                                     matches, None, **drawParams)

    cv2.imshow('matche', resultImage)
    cv2.waitKey(0)
    cv2.destroyAllWindows()

FlannBasedMatcher 吃两个字典，indexParams 和 searchParams。C++ 里对应结构体，Python 里传字典。

indexParams 按描述子类型选：

python
# SIFT、SURF 这类浮点描述子用 KD 树
indexParams = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)

# ORB 这类二进制描述子用 LSH
indexParams = dict(algorithm=FLANN_INDEX_LSH,
                   table_number=6,        # 12
                   key_size=12,           # 20
                   multi_probe_level=1)   # 2

algorithm 可选 LinearIndex、KTreeIndex、KMeansIndex、CompositeIndex、AutotuneIndex。这里选 KTreeIndex，即 kd 树。KTreeIndex 配置简单，只需指定待处理的核密度树数量，理想值在 1 到 16 之间，而且 kd 树可以并行处理。

二进制描述子要用 FLANN_INDEX_LSH，即局部敏感哈希。拿 kd 树去索引二进制串是错的，kd 树依赖欧氏空间的几何性质，汉明空间里不成立。

searchParams 指定索引遍历的次数：

python
searchParams = dict(checks=50)

checks 值越高精度越高，耗时越长。5 棵 kd 树配 50 次 checks 能拿到合理精度的结果，耗时也很短，这是常用的默认组合。

matchesMask 的四种取值 #

k=2 时，A 图一个描述子 a1​ 对应 B 图两个描述子 b1​、b2​，掩码有四种设置：

掩码 效果
[0, 0] 屏蔽掉所有连线
[1, 0] 只显示 a1​ 和 b1​ 的连线
[0, 1] 只显示 a1​ 和 b2​ 的连线
[1, 1] 两条线都画

$k$ 改成别的数，掩码列表的长度跟着变成 $k$。这是 drawMatchesKnn 和其他绘制函数的接口差异，容易踩。

八、误匹配剔除：比率测试与 RANSAC #

暴力匹配的结果必须过滤。这一节讲两道最常用的关卡。

第一道是 Lowe 比率测试，只看描述子距离，不看几何。第二道是 RANSAC，只看几何，不管描述子。两道串起来，误匹配从几万条降到几十条。

为什么必须剔除 #

这个账要算清楚。1000 对 1000 个特征点，暴力匹配给出 1000 对对应关系。真实场景里，两张图的重叠区域只覆盖其中一百来个点，也就是真匹配最多一百多对。剩下八九百对全是错的。

直接拿这 1000 对去算单应性，findHomography 会找到某个能把最多点凑近的变换。因为错匹配占绝对多数，它优化出来的矩阵是冲着错匹配去的。结果就是：变换矩阵荒谬，透视变换画出来的四边形跑到图像外面，或者缩成一个小点。

不用 RANSAC 的 findHomography 更惨，它用最小二乘解，一条错匹配就能把结果拉歪，何况九百条。

所以剔除不是优化，是必需环节。

第一道：Lowe 比率测试 #

思路：对每个 query 点，找最近的两个 train 点。如果最近的那个足够近，而次近的那个明显更远，说明这个匹配是唯一的、可信的。

判据：

d次近​d最近​​<r

$r$ 取 0.75 或 0.8。Lowe 原文给的是 0.8，实践中 0.75 更常用。

为什么这样能筛掉误匹配：如果一个 query 点在 B 图里对应两个差不多近的候选，说明这两个候选在描述子上都跟它像，它选谁都不确定，这个匹配不可信。正确的匹配应该有一个明显更近的候选，把其他的甩开一段距离。

典型数值：真匹配的最近距离 30，次近距离 200，比率 0.15，通过。误匹配的最近距离 110，次近距离 125，比率 0.88，被刷掉。

$r$ 的取值权衡：

$r$ 取值 保留匹配数 误匹配率 适用
0.9 多 高 特征点稀少，宁可多留
0.8 中 中 Lowe 原文推荐
0.75 中偏少 低 实践常用
0.7 少 很低 后续还有强几何约束
0.5 很少 极低 只做粗略验证

有一组流传很广的经验数：比率设置为 0.7，能滤掉约 90% 的误匹配点。这个比例随场景变化很大，但量级是对的。

还有一条要注意：比率测试里 $m.distance$ 和 $n.distance$ 的顺序不能反。写成 n.distance / m.distance 就把判据倒过来了，结果留下的是最差的那批。

比率测试的代码 #

def match_with_ratio(img1, img2):

    bf = cv2.BFMatcher()
    knnMatches = bf.knnMatch(des1, des2, k=2)

    # knnMatches[0] 是两个 DMatch，[0] 最近，[1] 次近
    dMatch0 = knnMatches[0][0]
    dMatch1 = knnMatches[0][1]
    print('near ', dMatch0.distance, dMatch0.queryIdx, dMatch0.trainIdx)
    print('second', dMatch1.distance, dMatch1.queryIdx, dMatch1.trainIdx)

    goodMatches = []
    minRatio = 1 / 3
    for m, n in knnMatches:
        if m.distance / n.distance < minRatio:
            goodMatches.append([m])

    print('保留', len(goodMatches), '对')
    sorted(goodMatches, key=lambda x: x[0].distance)

    outImg = cv2.drawMatchesKnn(img1, kp1, img2, kp2, goodMatches, None,

两个细节。

goodMatches.append([m]) 这里包了一层列表，因为 drawMatchesKnn 期望的结构是「每个元素是一组匹配」。用 drawMatches 的话就不用包，直接 append(m)。这两个函数的输入格式不一样，搞错了会报类型错误或者画出来什么都没有。

minRatio = 1/3 相当严格，0.33。旧代码里的例子指定 100 个特征点、k=2，最后剩 21 组，误匹配基本看不到。放宽到 0.7 会剩更多，但也会带回一些错配。选择哪个取决于后续是否有 RANSAC 兜底。

sorted() 那行是原地排序的无效写法，sorted 返回新列表但不接收返回值，等于没排。要排序得写 goodMatches.sort(key=...)。这不影响匹配结果，只影响绘制顺序。

第二道：RANSAC #

比率测试之后剩下的匹配，绝大多数是正确的，但仍有漏网的。这些漏网的很麻烦：它们在描述子上确实很像，只是物理上不是同一个点，典型来源是重复纹理（窗户、砖墙、文字）。

RANSAC 换一个维度判断：这些匹配点之间的几何关系，能不能用一个变换解释。

原理：

  1. 从匹配点对里随机抽最少的点（单应性要 4 对）。
  2. 用这 4 对算一个变换矩阵 $H$。
  3. 用 $H$ 把 A 图所有匹配点投影到 B 图，算每个点与它匹配点的偏差。
  4. 偏差小于阈值的算内点，统计内点数。
  5. 重复若干轮，保留内点最多的那个 $H$。
  6. 用全部内点重新拟合一次 $H$。

随机抽样的意义：如果内点占比 $p$，抽 4 对全是内点的概率是 p4。p=0.5 时是 6%，抽 100 轮几乎必中。p=0.9 时是 65%，几轮就够了。这也是为什么比率测试要先做一遍，把 $p$ 提上去，RANSAC 的轮数才能降下来。

OpenCV 把这一整套包在 findHomography 里，用 cv2.RANSAC 标志打开。

python
M, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0)

第三个参数选方法，cv2.RANSAC 或 cv2.LMEDS（最小中值）。第四个参数是重投影阈值，单位是像素。5.0 表示投影偏差在 5 像素内算内点。这个值要按图像分辨率和匹配精度调，5 像素对 600×400 的图合适，对 4000×3000 的图就太严。

mask 是 ndarray，长度等于匹配点对数，每个元素表示该匹配是否被用于计算。值为 0 是误匹配，丢弃；值为 1 是正确匹配。

九、单应性估计与目标定位 #

匹配的终点不是一个点对列表，而是一个能用的变换矩阵。有了它，你就能回答「这个物体在另一张图的哪个位置」。

从匹配点到矩阵 #

单应性描述两个平面之间的映射。拍一本书，书页是个平面，从这张图的书页到那张图的书页，就是一个单应变换。

​x′y′w′​​=H​xy1​​,H=​h11​h21​h31​​h12​h22​h32​​h13​h23​1​​

$H$ 是 3×3 矩阵，8 个自由度，最后那个 1 是尺度归一化的结果。每个匹配点对提供 2 个方程，4 对点能解出 8 个未知数。

这就是常说「理论最少 4 对」的来源。实际用 10 对以上，因为重投影误差和量化误差都会吃掉精度，刚好用最少点数解出来的矩阵对噪声极敏。

完整流程 #

findHomography 接收两组点，返回矩阵和内点掩码。

python
import numpy as np
import cv2


def flann_hom_test():
    img1 = cv2.imread('./image/book1.jpg')      # queryImage
    img2 = cv2.imread('./image/book2.jpg')      # trainImage
    gray1 = cv2.cvtColor(img1, cv2.COLOR_BGR2GRAY)
    gray2 = cv2.cvtColor(img2, cv2.COLOR_BGR2GRAY)

    MIN_MATCH_COUNT = 10

    # 1. 检测特征点、算描述符
    sift = cv2.SIFT_create(100)
    kp1, des1 = sift.detectAndCompute(gray1, None)
    kp2, des2 = sift.detectAndCompute(gray2, None)

    # 2. FLANN 匹配
    FLANN_INDEX_KDTREE = 0
    indexParams = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
    searchParams = dict(checks=50)
    flann = cv2.FlannBasedMatcher(indexParams, searchParams)
    matches = flann.knnMatch(des1, des2, k=2)

    # 比率测试
    goodMatches = []
    minRatio = 0.7
    for m, n in matches:
        if m.distance / n.distance < minRatio:
            goodMatches.append(m)   # 用 drawMatches 时不写成 [m]

    # 3. 单应性变换
    if len(goodMatches) > MIN_MATCH_COUNT:
        # 取匹配点坐标
        src_pts = np.float32([kp1[m.queryIdx].pt for m in goodMatches]).reshape(-1, 2)
        dst_pts = np.float32([kp2[m.trainIdx].pt for m in goodMatches]).reshape(-1, 2)
        print('src_pts:', len(src_pts), src_pts[0])
        print('dst_pts:', len(dst_pts), dst_pts[0])

        # 一个平面到另一个平面的映射矩阵
        M, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0)
        matchesMask = mask.ravel().tolist()
        print('matchesMask:', len(matchesMask), matchesMask[0])

        # 计算 img1 中书页四角在 img2 中的位置
        h, w = img1.shape[:2]
        # 源图中书页的四个角点
        pts = np.float32([[55, 74], [695, 45], [727, 464], [102, 548]]).reshape(-1, 1, 2)
        dst = cv2.perspectiveTransform(pts, M)
        # 在 img2 上绘制边框
        img2 = cv2.polylines(img2, [np.int32(dst)], True, (0, 255, 0), 2, cv2.LINE_AA)
    else:
        print('Not enough matches are found - %d/%d' % (len(goodMatches), MIN_MATCH_COUNT))
        matchesMask = None

    # 绘制效果
    draw_params = dict(matchColor=(0, 255, 0),
                       singlePointColor=None,
                       matchesMask=matchesMask,   # 只画内点
                       flags=2)
    img3 = cv2.drawMatches(img1, kp1, img2, kp2, goodMatches, None, **draw_params)
    cv2.imshow('matche', img3)
    cv2.waitKey(0)
    cv2.destroyAllWindows()


if __name__ == '__main__':
    flann_hom_test()

几个关键点。

src_pts 和 dst_pts 必须同序同长。两个列表都从 goodMatches 遍历得到，对应关系天然对齐。如果为了「优化」把两个列表分别过滤一遍，对应关系就断了，单应性必错。

np.float32 不能省。kp.pt 给的是 Python tuple，findHomography 要 float32 的 numpy 数组，reshape(-1, 2) 把它变成 N×2。

matchesMask = mask.ravel().tolist() 把掩码摊成一维列表。drawMatches 期望每个元素是标量，不是列表。这点和 drawMatchesKnn 相反。

flags=2 是 cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS，不画没匹配上的孤立点。配合 matchesMask 使用，画出来只有绿色内点连线，图面干净。

MIN_MATCH_COUNT = 10 是实用阈值。理论 4 对够，实际用 10 对是因为少于 10 对时 RANSAC 的样本空间太小，解出来的矩阵不稳。

pts 那组四角坐标是硬编码的，跟着具体图片走。换图片必须重标，否则框画在错的位置。这是示例代码最常被误用的地方。

单应性为什么能定位目标 #

perspectiveTransform 用 $H$ 把源图四个角点映射到目标图，得到目标图中该平面的四边形轮廓。$H$ 描述平面映射，源图上的整个矩形区域会被精确映射到目标图的一个四边形上。

定位就完成了：你知道了目标在该图中的位置和形状。形状是四边形而非矩形，因为视角变化带来透视形变。

用途不止画框：

用途 做法
目标定位 用 $H$ 映射四角，画出轮廓
图像拼接 用 $H$ 把一幅图 warp 到另一幅的坐标系，叠加
视角矫正 用 $H$ 的逆把倾斜拍的书页拉正
AR 叠加 用 $H$ 把虚拟物体贴到平面上
平面测距 用 $H$ 把像素坐标映射到已知尺寸的平面坐标

适用范围 #

$H$ 有 8 个自由度，假设两视图之间是纯旋转加平面运动。场景不满足这个假设，$H$ 会给出看起来合理但实际错误的结果。

成立条件：目标本身是平面或近似平面；相机只做旋转无平移，或者目标足够远、视差可忽略。

不成立的情况：三维物体的两个视角，视差明显，应该用基础矩阵 $F$ 或本质矩阵 $E$；相机有大平移且目标近，同样用 $F/E$。

用错模型的后果：$H$ 会把内点里的相当一部分也当噪声拒掉，内点数偏少，掩码看起来还行，矩阵算出来却不能用。判定方法是看内点比例，低于 30% 就该怀疑模型选错了。

三种退化情形 #

  • 匹配点全部共线。三点共线已经病态，四点共线直接无解。
  • 匹配点集中在极小的区域内。数值上矩阵接近奇异。
  • 匹配点里有大量重复坐标。比率测试之后仍会出现，因为同一纹理块被多次匹配。

前两种靠 findHomography 内部的检查能挡住一部分，第三种挡不住。要去重：把坐标量化到像素级后统计频次，出现多次的丢掉。

用内点掩码做诊断 #

python
def homography_diag(src_pts, dst_pts):
    M, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0)
    if M is None:
        print('求解失败')
        return None
    inlier = int(mask.sum())
    total = len(mask)
    print('内点 %d / %d = %.1f%%' % (inlier, total, 100.0 * inlier / total))
    print('H =')
    print(np.round(M, 3))
    print('det =', np.linalg.det(M))
    print('cond =', np.linalg.cond(M))
    return M, mask

det 接近 0 或者 cond 很大，说明矩阵病态，映射出来的四边形会离谱。这两个数比肉眼看结果靠谱，跑批量任务时把它们记进日志。

正常情况内点在 50% 以上，cond 在几十到几百量级。内点 20%、cond 上万，就是匹配质量不行，回去查描述子和阈值。

三类指标 #

指标 定义 用途
匹配率 真匹配数 / 理论上可匹配的特征点数 衡量召回
正确率 真匹配数 / 输出的匹配数 衡量精度
重投影误差 匹配点经 $H$ 投影后的平均像素偏差 衡量几何一致

前两个要有真值标注。第三个不需要，它只用匹配点自身的一致性，适合现场快速判断。

python
def reproj_error(src_pts, H, dst_pts):
    proj = cv2.perspectiveTransform(src_pts.reshape(-1, 1, 2), H).reshape(-1, 2)
    err = np.linalg.norm(proj - dst_pts, axis=1)
    return err.mean(), np.median(err), err.max()

均值容易被几个外点拉爆，中位数更稳。两个都打出来对比，差得远说明外点没清干净。

有真值时怎么算匹配率 #

合成数据最容易做。拿一张图，做已知的旋转、缩放、平移，得到第二张。这个变换是真值，你知道每个点在第二张图里该落在哪。

python
def make_pair(img, angle=20, scale=1.0, tx=40, ty=30):
    h, w = img.shape[:2]
    M = cv2.getRotationMatrix2D((w / 2, h / 2), angle, scale)
    M[0, 2] += tx
    M[1, 2] += ty
    warped = cv2.warpAffine(img, M, (w, h))
    return warped, M

有了 $M$，把 A 图每个关键点映射到 B 图，落在图像范围内且附近有 B 图关键点的算「可匹配」。匹配输出里落在容差内的算「真匹配」。

实测数据也有办法。用单应性拟合出来的内点当近似真值：内点视作正确，外点视作错误。这是自举的评估方式，不严格，胜在不需要标注，能用来横向比较不同参数组合。

旋转不变性测试 #

这是评 BRIEF 和 ORB 的关键实验。同一张图按 0、10、20、30、45、60、90 度依次旋转，每次和原图匹配，记录正确匹配率。

角度 BRIEF ORB SIFT
0 度 最高 高 高
10 度 高 高 高
20 度 中 高 高
30 度 接近 0 中高 高
45 度 0 中 高
90 度 0 中 高

BRIEF 在 30 度之后断崖。ORB 的曲线平缓得多，因为主方向把旋转补偿掉了。SIFT 基本不掉，它的梯度直方图在主方向上对齐，而且每个子块的直方图本身对方向有量化容差。

跑这个测试注意两件事。旋转后 warpAffine 会在四角带入大量黑色填充，这些区域的 FAST 检测会给出假点甚至不给点。要么先裁剪可用区域，要么在掩码上只统计原图范围内的点。

尺度不变性测试 #

同一张图缩放到 0.5、0.7、1.0、1.4、2.0，两两匹配。BRIEF 的曲线全线偏低，且随尺度差增大而恶化。ORB 靠金字塔，同层内匹配效果好，跨层较远时掉。

缩放比应当取 1.2k 这种和金字塔层间因子对齐的值。用 1.3、1.7 这种不对齐的比例，ORB 的表现会被人为压低，因为它最接近的两层仍差了一点。

阈值扫描 #

单参数扫描是调参最直接的手段。固定其他参数，只动一个，画曲线。

python
def sweep_ratio(img1, img2, ratios):
    sift = cv2.SIFT_create(100)
    kp1, des1 = sift.detectAndCompute(img1, None)
    kp2, des2 = sift.detectAndCompute(img2, None)
    knn = cv2.BFMatcher().knnMatch(des1, des2, k=2)

    rows = []
    for r in ratios:
        good = [m for m, n in knn if m.distance < r * n.distance]
        n_in = 0
        if len(good) >= 4:
            src = np.float32([kp1[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
            dst = np.float32([kp2[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
            M, mask = cv2.findHomography(src, dst, cv2.RANSAC, 5.0)
            if mask is not None:
                n_in = int(mask.sum())
        rows.append((r, len(good), n_in))
    return rows

看两列：保留数随阈值放宽而增加，内点数先增后减。内点数的峰值对应最优阈值，继续放宽会灌进错匹配，RANSAC 也救不回来。

这张表格比任何「经验值」都可靠。不同数据集的最优比率差别很大，纹理丰富的场景可以收到 0.6，特征稀疏的场景放到 0.85 才行。

ORB_create(128) 的 128 是 nfeatures，最多提取 128 个特征点，不是描述子位数。ORB 的描述子位数固定 256 位（32 字节），由 rBRIEF 那 256 个学出来的点对决定，改不了。

detectAndCompute 的第二个参数是掩码。传 None 表示全图检测。传一个和图像同尺寸的 uint8 掩码，非零区域才检测。做 ROI 匹配时用得上。

sorted(matchePoints, key=lambda x: x.distance) 这行和常见写法不同。旧代码写的是 sorted(...) 却没接返回值，等于没排。这里接上了。

crossCheck=True 时，match 返回的匹配数会比总特征点数少，因为很多点找不到互相认可的对手。这是预期行为。

一个可复用的匹配类 #

把检测、描述、匹配、剔除、估计封在一起，换图片只改输入。

python
class FeatureMatcher(object):
    '''
    特征匹配流水线，三种模式：sift / orb / brief
    '''
    def __init__(self, mode='sift', nfeatures=500, ratio=0.75, ransac_thresh=5.0):
        self.mode = mode.lower()
        self.ratio = ratio
        self.ransac_thresh = ransac_thresh
        self.nfeatures = nfeatures

        if self.mode == 'sift':
            self.detector = cv2.SIFT_create(nfeatures)
            self.norm = cv2.NORM_L2
        elif self.mode == 'orb':
            self.detector = cv2.ORB_create(nfeatures)
            self.norm = cv2.NORM_HAMMING
        elif self.mode == 'brief':
            # BRIEF 只描述不检测，外挂 STAR 检测器
            self.detector = cv2.SIFT_create(nfeatures)
            self.extractor = cv2.xfeatures2d.BriefDescriptorExtractor_create(32)
            self.norm = cv2.NORM_HAMMING
        else:
            raise ValueError('unknown mode: ' + mode)

    def detect(self, gray):
        if self.mode == 'brief':
            kp = self.detector.detect(gray, None)
            kp, des = self.extractor.compute(gray, kp)
            return kp, des
        return self.detector.detectAndCompute(gray, None)

    def match(self, des1, des2):
        bf = cv2.BFMatcher(self.norm, crossCheck=False)
        knn = bf.knnMatch(des1, des2, k=2)
        good = []
        for pair in knn:
            if len(pair) < 2:
                continue
            m, n = pair
            if m.distance < self.ratio * n.distance:
                good.append(m)
        return good

    def locate(self, kp1, kp2, good):
        if len(good) < 4:
            return None, None
        src = np.float32([kp1[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
        dst = np.float32([kp2[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
        H, mask = cv2.findHomography(src, dst, cv2.RANSAC, self.ransac_thresh)
        return H, mask

    def run(self, gray1, gray2):
        kp1, des1 = self.detect(gray1)
        kp2, des2 = self.detect(gray2)
        good = self.match(des1, des2)
        H, mask = self.locate(kp1, kp2, good)
        return dict(kp1=kp1, kp2=kp2, matches=good, H=H, mask=mask)

knnMatch 会返回长度不足 2 的子列表，某些 query 点在图 B 里只有一个候选时就只有一个元素。循环里 len(pair) < 2 的判断不能省，少了会抛 ValueError。

距离度量写错的两种表现 #

值得单独说，因为两个方向的表现完全相反。

把 float 描述子喂 NORM_HAMMING：OpenCV 直接抛异常。error: (-215:Assertion failed) ...，因为你给的数据类型不是 CV_8U。这种错误好，至少它报出来了。

把 uint8 描述子喂 NORM_L2：不报错。欧氏距离在字节数组上算出来是合法的浮点数，只是这个数没有物理意义。256 位码串当成 256 个 0/1 分量，欧氏距离的平方就等于汉明距离，看起来还行。但 OpenCV 实际是对 uint8 原始值算 L2，一个字节的值域是 0 到 255，两个字节差 200 和差 1 的贡献天差地别，跟位比较毫无关系。

结果就是匹配全乱，而且你完全不知道原因。唯一的防线是记住这张表，并在代码里加断言：

python
def check_norm(des, norm_type):
    is_binary = (des.dtype == np.uint8)
    if is_binary and norm_type not in (cv2.NORM_HAMMING, cv2.NORM_HAMMING2):
        raise ValueError('二进制描述子必须用汉明距离')
    if not is_binary and norm_type in (cv2.NORM_HAMMING, cv2.NORM_HAMMING2):
        raise ValueError('浮点描述子必须用 L2 或 L1')

描述子长度和 nfeatures 混淆 #

ORB_create(128) 的 128 是特征点数上限。BriefDescriptorExtractor_create(32) 的 32 是字节数。两个接口长得像，含义完全不同。

判断方法：看描述符矩阵的形状。des.shape 是 (N, 32) 表示 N 个点、每个 32 字节；(N, 128) 表示 N 个点、每个 128 维。第一个维度永远是点数。

金字塔层数和尺度覆盖 #

nlevels=8、scaleFactor=1.2，能覆盖的尺度范围是 1.27≈3.58 倍。目标缩小到 1/5 时，这个范围就不够，最底层那层检测不到。

反过来 nlevels=20 能覆盖 1.219≈38 倍，但检测时间线性增长，而且高层图像只剩几十个像素，检测出来的点毫无意义。

先算清楚你的场景需要几倍的尺度覆盖，再倒推层数。这是最容易拍脑袋定错的一个参数。

最后一句话 #

描述子回答「这个点长什么样」，匹配回答「这两个是不是同一个点」。前半句的核心是采样图案和数值类型，后半句的核心是距离度量和几何约束。四件事对上，流水线才通。

两者互补，不能互相替代。只用比率测试，重复纹理的误匹配会漏过去。只用 RANSAC，内点占比太低时它自己也抽不中正确的样本。
