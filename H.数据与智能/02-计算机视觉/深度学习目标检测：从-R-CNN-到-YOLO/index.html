一、目标检测的两条路线 #

1.1 检测在回答什么问题 #

图像分类回答「图里有什么」。检测要回答三件事：有什么、在哪、有几个。

输出是一组四元组：

text
[(x1, y1, x2, y2, class_id, score), ...]

x1, y1, x2, y2 是框的两个角点，class_id 是类别，score 是模型对这个框的置信程度。一张图里的目标个数是变的，会是 0 个，也会是 30 个，网络的输出长度得跟着变。

这就是检测比分类难的地方。分类的输出形状固定，N 类就是 N 维向量。检测的输出是一个变长集合，而且这个集合还得和人工标注的集合对齐——不能只是「猜对了一堆框」，还得「一个不多一个不少地猜对」。

早期做法是把变长问题转成定长问题：在图上撒一堆固定位置的框，每个框问一次「这里面是什么」，最后用非极大值抑制（NMS）把重复的框压掉。这条路走下去就是滑动窗口。

1.2 两条路线的定义 #

深度学习兴起之后，检测分成两条线。

两阶段（two-stage）：先找「会含目标的区域」，再对每个区域做分类和边框回归。两个阶段各有自己的子网络。

  • 候选生成：Selective Search、EdgeBoxes 这类传统算法，或者后来的 RPN 网络
  • 候选处理：对每个候选框抠特征、分类、回归坐标

代表：R-CNN、SPP-Net、Fast R-CNN、Faster R-CNN、R-FCN。

一阶段（one-stage）：不生成候选，直接在特征图的每个位置上同时预测「有没有目标、是什么类别、框在哪」。一个网络，一次前向。

代表：YOLO、SSD、RetinaNet，以及后面整个 YOLO 家族。

1.3 根本差别：要不要先生成候选 #

这是全篇的主线，先钉死。

两阶段的核心动作是**「先粗筛，再细判」**。它把一个问题拆成两个：第一个模块只回答「这个位置像不像一个完整物体」，不管是什么；第二个模块只回答「这块区域里的东西是什么类别、框要往哪挪」。拆开的好处是每一步都简单，坏处是要跑两遍计算，而且第一阶段漏掉的区域，第二阶段永远看不到——召回率的上限被候选生成锁死了。

一阶段的核心动作是**「一次算完」**。它不再区分「找」和「认」，而是让网络在特征图的每个格子上直接吐出一个完整的判断：这里有个东西，是这个类，框偏移这么多。好处是只有一次前向，速度快；坏处是每个位置都要判一次，绝大多数位置是背景，正负样本比例悬殊到 1:1000 这个量级，训练时梯度会被背景淹没。

两种设计的取舍落成一句话：前者准，后者快。

准 具体指什么：

  • 小目标。候选生成会把小目标所在的小区域单独放大处理，一阶段的小目标在特征图上只有几个像素，下采样几次就没了。
  • 密集目标。两个目标的中心落在同一个格子里时，一阶段只能出一个（YOLOv1 的硬伤），两阶段每个候选独立处理，不受这个限制。
  • 定位精度。两阶段对框做两次修正（RPN 一次、头部一次），一阶段只有一次。

快 具体指什么：

  • 只有一次前向。两阶段是「特征提取 + 每个 RoI 单独过一遍头部」，RoI 数量上千，头部就要跑上千次。
  • 没有候选生成的额外开销。Selective Search 在 CPU 上一张图要 1~2 秒，这个时间比网络前向还长。
  • 端到端可部署。一个网络进、一个结果出，不用在推理流程里插一段 Python 写的区域生成。

二、从滑动窗口到候选区域 #

2.1 传统检测的三步框架 #

深度学习之前，检测是一套流水线，三个步骤：

  • 用不同尺寸的滑动窗口框住图中的某一部分，作为候选区域
  • 提取候选区域的视觉特征：人脸检测用 Haar，行人检测和通用检测用 HOG
  • 用分类器识别，比如 SVM

这套流水线在 2010 年前后被 DPM 推到了顶峰。DPM（Deformable Part Model）把物体看成若干部件的组合，用部件之间的关系描述物体——人脸是眼睛、鼻子、嘴的组合，行人是头、躯干、四肢的组合。这个建模方式贴合自然界大量非刚体目标，DPM 连续拿下 VOC 2007 到 2009 的检测冠军，作者 Felzenszwalb 在 2010 年被 VOC 授予终身成就奖。

DPM 可以看作 HOG + SVM 的扩展。它继承了这两者的优点，在人脸、行人任务上效果不错。问题也很直接：模型复杂，检测慢，改进空间被结构本身卡住。

2.2 滑动窗口为什么走不通 #

滑动窗口的本质是穷举。它做的事是：把所有位置、所有尺度、所有长宽比，全都试一遍。

代价算一下。一张 500×500 的图，如果步长取 8 像素，单尺度就有约 3900 个位置。再叠 3 个尺度、3 个长宽比，就是 3.5 万个窗口。每个窗口都要提一次特征、过一次分类器。HOG 特征提取本身就不便宜，3.5 万次跑下来，一张图要几秒到几十秒。

这里有两个绕不开的矛盾：

  • 覆盖率与代价的矛盾。步长调大，速度上去了，但目标正好卡在两个窗口之间，谁都框不全；步长调小，覆盖率上去了，计算量按平方涨。
  • 尺度与精度的矛盾。尺度取得再密，也只是离散采样。真实目标的尺寸是连续的，总有一个尺度介于两个采样之间，框出来就是差一点。

所以滑动窗口的问题不是「效果差」，是「不划算」：产生了大量冗余候选，其中绝大多数是背景，真正含目标的区域占比很低。它的召回率其实不差，差的是精度和效率。

2.3 区域提名的三种思路 #

目标检测的第一步是要拿到「候选感兴趣区域」（Region Of Interest，ROI）。这个动作叫区域提名（Region Proposal）。

这和 OCR 里的切分是同一类问题。OCR 切分常用过切分：先尽量切碎成小的连通域，连笔画都切开，再根据相邻块的形态特征往回合并。区别在于检测的对象千差万别，形状不规则，大小不一，区域提名比 OCR 切分更难。

思路有三条：

一、滑动窗口。穷举法。不同尺度、不同长宽比全试一遍，送去识别，概率大的留下。复杂度太高，冗余太多，现实里不可行。

二、规则块。在穷举的基础上剪枝，只用固定的大小和长宽比。这在特定场景下很管用——拍照搜题 APP 里的汉字检测就是典型，汉字方方正正，长宽比高度一致，规则块够用。换成通用检测就不行了，依然要访问大量位置。

三、选择性搜索。前两条路的召回都不错，精度拖后腿。问题的核心于是从「找得更全」变成「去冗余」。而冗余候选的共同特征是互相重叠，那就利用这一点：自底向上合并相邻的重叠区域。

第三条路的关键洞察是：不用穷举，也能拿到覆盖良好的候选集。因为自然图像里的物体是由颜色、纹理相近的像素块组成的，先把图切成超像素，再按相似度合并，合并过程中每一级的区域都是候选。

2.4 IOU：候选评估的通用尺子 #

讲候选之前，先把 IOU 立起来。后面每一章都要用。

IOU（Intersection over Union）是两个框的交集面积除以并集面积：

text
IOU = area(A ∩ B) / area(A ∪ B)

取值范围 0 到 1。两个框完全重合是 1，完全不相交是 0。

python
def iou(a, b):
    # a, b 都是 (x1, y1, x2, y2)
    ix1 = max(a[0], b[0])
    iy1 = max(a[1], b[1])
    ix2 = min(a[2], b[2])
    iy2 = min(a[3], b[3])

    iw = max(0, ix2 - ix1)
    ih = max(0, iy2 - iy1)
    inter = iw * ih
    if inter == 0:
        return 0.0

    area_a = (a[2] - a[0]) * (a[3] - a[1])
    area_b = (b[2] - b[0]) * (b[3] - b[1])
    return inter / (area_a + area_b - inter)

IOU 在检测里干三件事：

  • 判定候选框算不算「找到」了目标。IOU > 0.5 就算命中，这是 VOC 的默认标准。
  • 判定一个预测框是正样本还是负样本。训练时按 IOU 分档。
  • 做 NMS 时判断两个框是不是在说同一个物体。

后面你会看到，两阶段和一阶段的所有设计差异，几乎都能用「怎么用 IOU 划正负样本」解释一遍。

2.5 非极大值抑制 #

候选生成会给出大量互相重叠的框。同一个目标被十几个框框住，得留一个。

NMS 的做法：

text
1. 按置信度从高到低排序所有框
2. 取出分数最高的框 A，放进保留列表
3. 计算剩余每个框与 A 的 IOU
4. 删掉 IOU 大于阈值的框（它们和 A 是同一个目标）
5. 回到第 2 步，直到没有框剩下

python
def nms(boxes, scores, thresh=0.5):
    order = scores.argsort()[::-1]
    keep = []

    while order.size > 0:
        i = order[0]
        keep.append(i)
        if order.size == 1:
            break
        rest = order[1:]
        ov = [iou(boxes[i], boxes[j]) for j in rest]
        rest = rest[[k for k, v in enumerate(ov) if v <= thresh]]
        order = rest

    return keep

NMS 有两个毛病，后面会反复遇到：

  • 阈值是硬编码的。调低，密集目标会被误删；调高，重复框删不干净。
  • 它只按分数排序，不看框的几何关系。两个真实目标如果贴得很近、IOU 又很大，其中一个会被干掉。

这两点在 YOLO 那一章会变成具体的设计取舍。

2.6 候选数量为什么定在 2000 #

R-CNN 系列一直用「2000 个候选框」这个数字。它不是拍脑袋，是权衡的结果。

候选少了，召回掉。Selective Search 在 2000 个候选时能覆盖 VOC 上绝大多数真值框；降到 500，漏检明显上升。

候选多了，算力吃不住。R-CNN 要对每个候选跑一次 CNN 前向，2000 个候选在 GPU 上就是 13 秒。翻倍到 4000，时间也翻倍，而召回只涨一点点。

后来 Selective Search 的评估实验给出了这条曲线：横轴候选数，纵轴召回率和平均最高重叠（ABO）。曲线在 2000 附近开始变平——这就是那个数字的来源。Fast 版本的选择性搜索在 2000 个候选时性价比最高。

三、选择性搜索 Selective Search #

3.1 它要解决的具体问题 #

先把难度摆清楚。一张自然图像里，我们不知道要检测什么类别，也不知道目标有多少个、多大。桌上的桌子、瓶子、餐具都是候选目标；餐具包含在桌子这个目标内，勺子又包含在碗内。目标之间有层级关系，也有尺度关系。

用单一视觉特征去切分，一定会崩。举四组反例：

  • 两只猫并排。纹理完全一样，纹理特征分不开它们。
  • 一只变色龙趴在叶子上。颜色几乎一致，颜色特征失效。
  • 一辆车和它的轮胎。人眼一看是一个整体，但颜色、纹理、边缘差距都很大，任何单一特征都会把它们强行分开。
  • 桌子与桌上的碗。这两个明显是两个目标，但空间上贴合。

既然没有一种特征能通吃，就别指望一个特征。既然尺度未知，就别猜尺度。

Selective Search 的三条策略就是这三句话的直接翻译：

  • 适应不同尺度（Capture All Scales）：用图像分割 + 层次化合并算法，把从最细到最粗的所有区域都留一份。
  • 多样化（Diversification）：颜色、纹理、大小、填充多种相似度一起用，不在单一策略上赌。
  • 快速（Fast to Compute）：合并过程是贪心的，代价远低于穷举。

3.2 层次化合并的总体流程 #

核心思路一句话：从每一个超像素出发，反复合并最相似的两个相邻区域，把整个合并过程记录下来。

整个过程产生一棵树。树叶子是初始超像素，树根是整张图，中间每一层的每个节点都是一个候选区域，其外接矩形就是一个候选框。

text
输入：一张图片
输出：候选的目标位置集合 L

1: 用切分方法得到初始区域集合 R = {r1, r2, ..., rn}
2: 初始化相似度集合 S = ∅
3: foreach 相邻区域对 (ri, rj) do
4:     s(ri, rj) = 相似度(ri, rj)
5:     S = S ∪ s(ri, rj)
6: while S != ∅ do
7:     (ri, rj) = argmax S
8:     rt = ri ∪ rj
9:     S = S \ s(ri, r*)
10:    S = S \ s(r*, rj)
11:    St = 计算 rt 与所有邻居的相似度
12:    S = S ∪ St
13:    R = R ∪ rt
14: L = R 中所有区域的外接矩形

拆开看四步：

第一步，初始化。用基于图的图像分割（Felzenszwalb 算法）把图切成很多小块。分割的粒度由参数 k 控制，k 越大块越少越大。这些初始区域是整个算法的地基，切得好坏直接影响上限。

第二步，算相邻对的相似度。只算相邻的，因为只有相邻的才会合并成一个物体。常见实现里「相邻」用外接矩形是否相交来近似判断——不精确，但足够快。

第三步，贪心合并。每次都挑当前相似度最大的一对合并，合并后更新受影响的那部分相似度。注意第 9、10 行：合并 ri 和 rj 之后，原来与它们俩相关的相似度全部作废，要删掉重算；与 rt 有关的新相似度要补进来。这一步决定了算法的复杂度——不是全量重算，只动受影响的部分。

第四步，收集结果。所有出现过的区域（初始的、每次合并产生的）的外接矩形，都是候选框。

关键在于算法只做了一次从下到上的扫描，每个区域都进了集合，所以不需要穷举各种尺寸的窗口。这棵树本身就是多尺度的表示。

3.3 为什么单一策略不行 #

如果粗暴地只用一种相似度，会出两类错：

  • 错误合并。只考虑纹理时，不同颜色的区域很容易被误合并——两只毛色不同的狗纹理都是毛发，会被当成一个。
  • 过度合并。只考虑颜色和纹理时，合并后的区域会不断吞并周围区域，最终整张图合成一块。多尺度只发生在局部，全局尺度丢了。

所以 Selective Search 用三种多样性策略：

  • 多种颜色空间：RGB、灰度 I、Lab、rgI、HSV、rgb、C、H，共 8 种
  • 多种相似度度量：颜色、纹理、大小、填充
  • 改变初始化阈值 k：阈值越大，初始区域越少

8 种颜色空间是为了对付不同的光照和场景条件。这个策略主要作用在初始分割阶段——算两个像素点的相似度时，在不同颜色空间下各算一次两点距离。列一下：

编号 颜色空间 说明
1 RGB 原始通道
2 灰度 I 亮度
3 Lab 感知均匀
4 rgI 归一化 rg 通道 + 灰度
5 HSV 色调饱和度明度
6 rgb 归一化的 RGB
7 C 对立色通道
8 H HSV 的 H 通道

3.4 四种相似度 #

所有单一相似度的值都归一化到 [0, 1]，1 表示最相似，最后相加融合。

颜色相似度 #

对每个颜色通道取 25 个 bin 的直方图，用 L1 归一化。三个通道合起来，每个区域得到一个 75 维向量。

两个区域的颜色相似度用直方图交集算：

text
s_color(ri, rj) = Σ_{k=1}^{n} min(ci^k, cj^k)

ci 和 cj 是归一化后的直方图向量。

为什么这个公式对。每个通道的直方图累加和为 1.0，三个通道就是 3.0。两个区域的直方图完全一样时，每一项的 min 等于自身，累加得 3.0，相似度最大。直方图差别越大，min 取到的小值越多，累加和越小。

合并新区域时，直方图不用重算，按像素数加权平均即可：

text
ct = (size(ri) * ci + size(rj) * cj) / (size(ri) + size(rj))

纹理相似度 #

用类 SIFT 特征。对每个颜色通道的 8 个方向计算方差 σ=1 的高斯微分，每个通道每个方向取 10 个 bin 的直方图，L1 归一化。三个通道 × 8 方向 × 10 bin，得到 240 维向量。

两个区域的纹理相似度算法和颜色完全一样，也是直方图交集；合并后新区域的纹理特征也是按像素数加权平均。

注意这里的设计意图：纹理描述的是局部梯度方向的分布，跟颜色无关。所以它能抓住「两只不同颜色的猫纹理一样」这种情况。

大小相似度 #

text
s_size(ri, rj) = 1 - (size(ri) + size(rj)) / size(image)

两个区域越小，这个值越接近 1，越倾向于先合并。

这是个容易被忽略但很关键的设计。没有它，大区域会一路吞并小区域，多尺度只在局部成立。加上它之后，合并优先在小区域之间发生，整张图的各个位置都在做多尺度合并，尺度多样性是全局的。

填充相似度 #

text
s_fill(ri, rj) = 1 - (size(BBij) - size(ri) - size(rj)) / size(image)

BBij 是能同时框住 ri 和 rj 的最小外接矩形。

这个指标衡量两个区域「吻合」的程度。如果 ri 完全包含在 rj 里，外接矩形就是 rj 自己，BBij 的面积减掉两者面积等于 0，相似度接近 1，优先合并。如果两个区域只是勉强相接，外接矩形会比两者面积之和大很多，相似度低，不该合并。

它解决的是「断崖」问题：两个区域在空间上相邻但拼起来形状很别扭，说明它们约不属于同一个物体。

融合 #

text
s(ri, rj) = w1*s_color + w2*s_texture + w3*s_size + w4*s_fill

默认四个权重都取 1。_calc_sim 就是四项直接相加，取值范围 [0, 6]。

3.5 给区域打分 #

合并过程会产出几千个区域，不能全用。得排序，按需取前 N 个。

打分规则：最先合并的块权重最大。最后那块完整图像权重为 1，倒数第二次合并的权重为 2，以此类推。越早合并的区域，越是「内部高度一致」的小块，越会是完整物体的一部分。

多策略叠加时会有重叠问题：同一个区域被多个策略、多个颜色空间产出，权重怎么算。做法是给它乘一个随机数（打破平局），同一个区域出现多次就把权重累加——多个方法都说你是目标，那确实有理由。

这样每个区域都有了分数，想要多少个候选就取前多少个。

3.6 性能评估 #

评估指标是平均最高重叠率 ABO（Average Best Overlap）。

对每个类别 c，每个真值框 g，在所有候选框集合 L 里找 IOU 最高的那个：

text
ABO = (1/|G|) * Σ_g max_{l in L} IOU(g, l)

对所有类别取平均就是 MABO。

论文的基线配置：RGB 颜色空间、四种相似度组合、分割阈值 k=50。然后每次只改一个参数看 MABO 变化：

配置 MABO 候选数
仅纹理相似度 0.581 —
仅颜色相似度 约 0.63 —
仅大小相似度 约 0.63 —
仅填充相似度 约 0.64 —
四种组合 + HSV 0.693 463
四种组合 + 更小阈值 更高 更多

三条结论：

  • 单独用纹理最差，MABO 只有 0.581，另外三种单独用都在 0.63~0.64 之间。
  • 组合优于任何单一相似度。
  • 颜色空间用 HSV、分割阈值调小，都会拿到更高 MABO，代价是候选数变多。

三种组合策略的 MABO 对比也说明了同一件事：贪心地堆策略能提升 MABO，但计算成本跟着涨。

质量模式（Quality）下，红框是 IOU 最高的候选框，和真值框贴得非常近。速度模式（Fast）在 2000 个候选时的性价比最好——这是工程上最常用的配置。

和其他方法在 VOC 2007 测试集上的对比里，Selective Search 的召回不输，速度是它最大的短板：CPU 上一张图 1~2 秒。这个数字在 Fast R-CNN 那一章会变成一个绕不开的瓶颈。

3.7 用几十行代码看透它 #

抛开工程优化，Selective Search 的核心不到 100 行。下面这版去掉直方图细节，保留骨架。

python
import numpy as np

def sim_colour(r1, r2):
    # 颜色直方图交集，返回 [0, 3]
    return sum(min(a, b) for a, b in zip(r1["hist_c"], r2["hist_c"]))

def sim_texture(r1, r2):
    # 纹理直方图交集，返回 [0, 3]
    return sum(min(a, b) for a, b in zip(r1["hist_t"], r2["hist_t"]))

def sim_size(r1, r2, imsize):
    # 区域越小越相似
    return 1.0 - (r1["size"] + r2["size"]) / imsize

def sim_fill(r1, r2, imsize):
    # 外接矩形越贴合越相似
    bbsize = ((max(r1["max_x"], r2["max_x"]) - min(r1["min_x"], r2["min_x"]))
              * (max(r1["max_y"], r2["max_y"]) - min(r1["min_y"], r2["min_y"])))
    return 1.0 - (bbsize - r1["size"] - r2["size"]) / imsize

def calc_sim(r1, r2, imsize):
    # 四路融合，权重默认都是 1
    return (sim_colour(r1, r2) + sim_texture(r1, r2)
            + sim_size(r1, r2, imsize) + sim_fill(r1, r2, imsize))

def merge_regions(r1, r2):
    # 直方图按面积加权，不用重算
    n = r1["size"] + r2["size"]
    return {
        "min_x": min(r1["min_x"], r2["min_x"]),
        "min_y": min(r1["min_y"], r2["min_y"]),
        "max_x": max(r1["max_x"], r2["max_x"]),
        "max_y": max(r1["max_y"], r2["max_y"]),
        "size": n,
        "hist_c": (r1["hist_c"] * r1["size"] + r2["hist_c"] * r2["size"]) / n,
        "hist_t": (r1["hist_t"] * r1["size"] + r2["hist_t"] * r2["size"]) / n,
        "labels": r1["labels"] + r2["labels"],
    }

def selective_search(im_orig, scale=1.0, sigma=0.8, min_size=50):
    img = generate_segments(im_orig, scale, sigma, min_size)  # Felzenszwalb 图分割
    if img is None:
        return None, {}

    imsize = img.shape[0] * img.shape[1]
    R = extract_regions(img)              # 边框、面积、颜色与纹理直方图
    neighbours = extract_neighbours(R)

    S = {}
    for (ai, ar), (bi, br) in neighbours:
        S[(ai, bi)] = calc_sim(ar, br, imsize)

    while S != {}:
        i, j = sorted(S.items(), key=lambda kv: kv[1])[-1][0]
        t = max(R.keys()) + 1.0
        R[t] = merge_regions(R[i], R[j])

        key_to_delete = [k for k in S if (i in k) or (j in k)]
        for k in key_to_delete:
            del S[k]
        for k in filter(lambda a: a != (i, j), key_to_delete):
            n = k[1] if k[0] in (i, j) else k[0]
            S[(t, n)] = calc_sim(R[t], R[n], imsize)

    regions = []
    for k, r in R.items():
        regions.append({
            "rect": (r["min_x"], r["min_y"],
                     r["max_x"] - r["min_x"], r["max_y"] - r["min_y"]),
            "size": r["size"],
            "labels": r["labels"],
        })
    return img, regions

主循环里那三个循环是最容易看错的地方。key_to_delete 收集所有涉及 i 或 j 的键；删完之后，filter 又把 (i, j) 这一对排除掉——i 和 j 已经合并成 t，它俩之间的相似度不再有意义；剩下的每个邻居 n 都要和新的 t 重算。

工程上还会加三个过滤剪枝：去掉重复框、去掉面积太小的碎块、去掉长宽比离谱的框。size 是区域内真实像素数，不是外接矩形的面积，这点容易搞混。

3.8 它的价值和不值 #

价值就一句话：不用穷举。

穷举要把位置、尺度、长宽比三者都枚举一遍，代价是立方级。Selective Search 只有一次层次合并，代价和初始超像素数量近似线性。它在 2000 个候选的预算内，给出了远比 2000 个随机窗口更好的召回，因为它产出的框都是「某片颜色纹理一致的区域的外接矩形」，天然贴合物体边界。

不值的地方也很清楚：

  • 它不在 GPU 上。整个算法是 CPU 上的图像处理，一张图 1~2 秒。当网络前向已经压到几十毫秒时，这段 CPU 时间就是瓶颈的全部。
  • 它是无类别、无学习的。相似度权重是人工定的四个 1，没有从数据里学任何东西。
  • 它不可微。候选生成和后面的网络是两个独立进程，梯度传不过去，没法联合优化。

这三点直接决定了它会被 RPN 取代——第六章会讲。

在往下走之前，记住一个数字：Selective Search 在 CPU 上一张图要 1~2 秒，产出约 2000 个候选。R-CNN 的所有设计都绕不开这两个数字。

四、R-CNN：第一个深度学习检测器 #

4.1 诞生背景 #

2013 年之前，用深度学习做检测的尝试一直没突破。有文献在 VOC 2007 测试集上的 mAP 只有 30% 出头，OverFeat 在 ILSVRC 2013 测试集上 mAP 只有 24.3%。这些数字比精心调过的 DPM 好不了多少，所以没人认为深度学习在检测上有什么特别。

2013 年 R-CNN 出来，VOC 2007 测试集 mAP 直接跳到 48%。2014 年改网络结构后升到 66%，ILSVRC 2013 测试集 mAP 提到 31.4%。这是第一次有量级感的提升。

R-CNN 是 Region-based Convolutional Neural Networks 的缩写，中文叫基于区域的卷积神经网络。名字已经点题：先把区域找出来，再在区域上跑 CNN。Ross Girshick 的这篇《Rich Feature Hierarchies for Accurate Object Detection and Semantic Segmentation》奠定了这个子领域的基础——2013 年 ICCV workshop，2014 年 CVPR，2015 年 PAMI 期刊版。

R-CNN 不是第一个用深度学习做检测的（OverFeat 更早），但它是第一个能工业级应用的方案。这里有个类比：神经网络和卷积网络都不是新概念，但本世纪突然变得可行，一旦可行就发展极快。R-CNN 的位置类似——方法本身不新，但组合起来的时机对了。

4.2 三步流程 #

R-CNN 的流程非常直白，四个动作，可以归成三步。

第一步，区域提名。用 Selective Search 从原图提取约 2000 个候选框。这一步完全用传统视觉算法，跟深度学习无关。

第二步，区域归一化 + 特征提取。把所有候选框的区域图抠出来，缩放到固定尺寸 227×227（AlexNet 的输入大小），逐个送进 CNN 提特征。每个候选得到一个 4096 维特征向量。

第三步，分类与回归。在特征上挂两个头：用 SVM 做分类识别，用线性回归微调边框位置与大小。每个类别单独训练一个边框回归器。

text
原图
  |
  +-- Selective Search --> 约 2000 个候选框
  |
  +-- 每个候选框抠图、缩放到 227x227
  |
  +-- CNN（AlexNet）逐个前向 --> 4096 维特征
  |
  +-- SVM 分类（每类一个）      --> 类别分数
  +-- 线性回归（每类一个）      --> 边框修正量
  |
  +-- NMS --> 最终检测结果

这里有个常被忽略的词：逐个。2000 个候选框，就是 2000 次 CNN 前向。这是 R-CNN 一切问题的源头。

4.3 训练是怎么分步的 #

R-CNN 的训练不是端到端，是四段独立跑完再拼起来：

  1. 有监督预训练。在 ImageNet 上训一个分类网络（AlexNet），拿到初始权重。
  2. 微调。把预训练网络在检测数据集上继续训，把最后的分类层换成 N+1 类（N 个目标类 + 1 个背景）。这一步用的是候选框，正样本是 IOU ≥ 0.5 的，负样本是 IOU < 0.3 的。
  3. 训练 SVM。把微调后网络在候选框上的 4096 维特征存到硬盘，用这些特征训练每个类别的线性 SVM。正样本只看真值框本身，负样本是 IOU < 0.3 的候选。
  4. 训练边框回归器。同样用硬盘上的特征，每个类别训一个线性回归器，输出四个坐标偏移量。

四步之间靠硬盘传递数据，而且每一步都有自己的超参数、自己的正负样本定义。这就是后来被反复批评的「训练分多步」。

注意第 2 步和第 3 步用的正负样本定义不一样，这不是笔误。微调时 IOU ≥ 0.5 就算正，因为要让网络见到足够多的正样本；训 SVM 时只把真值框当正，因为 SVM 的间隔对样本定义更敏感。这个不一致在 Fast R-CNN 里被统一掉了。

4.4 为什么效果突然就好了 #

R-CNN 的贡献不在于发明了什么模块，而在于把两件事接上了：候选区域解决了「在哪」，CNN 特征解决了「是什么」。

传统方法里，HOG、SIFT 这些手工特征是从梯度统计量里抠出来的，表达能力有限。CNN 在 ImageNet 上训出来的特征，对物体语义的区分度高一个层级。把 HOG 换成 CNN 特征，等于把「是什么」这一环的上限抬高了。

候选区域这一环反而没变——用的还是 Selective Search，和传统方法一样。这也解释了 R-CNN 后续改进的方向：大家很快意识到，瓶颈在别处。

4.5 五条硬伤 #

R-CNN 的问题清单在论文里就有，一共五条：

一、重复计算。2000 个候选框大量重叠，同一个物体被十几个框框住，这十几个框各自跑一次 CNN。卷积特征在重叠区域被反复计算，算力全浪费在这里。这是最致命的一条。

二、SVM 是线性模型。在标注数据不缺的时候，线性分类器不是最好的选择。用 softmax 直接接在网络里，效果更好也更省事。

三、训练测试分多步。区域提名、特征提取、分类、回归四个环节是断开的训练过程，中间数据要单独存在硬盘上。每一步都要单独调参，复现成本高。

四、空间和时间代价高。卷积特征要先落盘，2000 个候选 × 4096 维 × 上万张训练图，特征文件几百 GB。

五、慢。上述缺点叠加的结果：GPU 上一张图 13 秒，CPU 上 53 秒。

13 秒里，CNN 前向占大头。算一下：2000 次前向，如果单次 5 毫秒，就是 10 秒。而实际上这 2000 次前向里，有大量内容是在重复算同一片背景。

text
一张图 13 秒的构成（GPU）
  Selective Search   约 1~2 秒（CPU）
  CNN 前向 x2000     约 10 秒
  SVM + 回归 + NMS   约 0.5 秒

看懂这张表，就懂了后面三代改进的动机：SPP-Net 打 CNN 前向重复，Fast R-CNN 打整体流程，Faster R-CNN 打 Selective Search。

4.6 R-CNN 的定位 #

效果上，R-CNN 把 ILSVRC 2013 的 mAP 从 OverFeat 的 24.3% 提到 31.4%，VOC 2007 从 30% 出头提到 48%。这是第一次质的改变。

工程上，它是第一个跑得通、效果够用的深度学习检测方案。虽然 13 秒一张图没法落地到实时场景，但它证明了路子对。

还有一个贡献常被漏掉：R-CNN 确立了一套术语和工作流——候选框、IOU 划正负样本、NMS 后处理、每类一个回归器。后面几代方法都在改这套流程，但没人推翻它。

4.7 OverFeat：一个必要的旁注 #

OverFeat 是 R-CNN 之前的工作，用 CNN 统一做分类、定位和检测，作者是 Yann LeCun 在纽约大学的团队，拿了 ILSVRC 2013 任务 3（分类 + 定位）的冠军。

三点核心思想：

  • 区域提名：结合滑动窗口和规则块，即多尺度滑动窗口
  • 分类和定位统一用 CNN：模型与 AlexNet 类似，1~5 层是特征抽取层，6~9 层是分类层。分类、定位、检测三个任务共用 1~5 层，只替换 6~9 层
  • 累积：因为用了滑动窗口和多尺度，同一个目标会有多个位置、多个大小的视角，把这些视角上的分类置信度累加起来，判定更准

四个关键步骤：

  1. 用滑动窗口做不同尺度的区域提名，每个区域过 CNN 分类，得到类别和置信度
  2. 用多尺度滑动窗口增加检测数量，提升分类效果
  3. 用回归模型预测每个对象的位置
  4. 边框合并

OverFeat 和 R-CNN 的关系可以用一句换元说清：把 Selective Search 换成多尺度滑动窗口，把每个类别的边框回归器换成统一的回归器，把 SVM 换成多层网络，就是 R-CNN。

但反过来，OverFeat 实际比 R-CNN 快 9 倍。原因只有一个：卷积的共享计算。OverFeat 的滑动窗口是在卷积特征图上滑的，很多位置共享同一片特征；R-CNN 是每个候选框单独裁剪、单独前向，一点共享都没有。

这个对比很关键。它说明「共享卷积计算」这件事从一开始就有更优解，R-CNN 走的是弯路，而后面几代方法都在往 OverFeat 的路上退——只不过退得更彻底。

五、SPP-Net 与 Fast R-CNN #

5.1 SPP-Net 要修的是什么 #

R-CNN 要把每个候选框缩放到 227×227。缩放手段是裁剪（crop）或变形（warp），两者都会引入偏差：

  • crop：强行裁成正方形，目标会被裁掉一部分，剩下半个人
  • warp：强行拉伸成正方形，目标被压扁或拉长，形变严重

为什么非要缩放？因为 CNN 的全连接层要求输入尺寸固定。这是网络结构的约束，不是检测任务的需求。

SPP-Net（何恺明等，MSRA）的做法是：去掉原图上的 crop/warp，改在卷积特征上做空间金字塔池化。

5.2 空间金字塔池化怎么工作 #

SPP 层的操作：

  1. 对整张特征图，对每个通道取全局最大值，得到一组特征
  2. 把特征图均分成 4 份，每份对每个通道取最大值，得到 4 组
  3. 均分成 16 份，同样取最大值，得到 16 组
  4. 以此类推

三组拼起来，如果通道数是 256，维度就是 256 × (1 + 4 + 16) = 5376。关键在于：不管输入特征图多大，输出维度都是固定的。

为什么固定？因为池化的网格数（1×1、2×2、4×4）是预先定死的，每个网格对每个通道输出一个数。输入尺寸变化只影响每个网格覆盖多大范围，不影响输出个数。

text
特征图 任意尺寸 x C 通道
  |
  +-- 1x1 池化   --> C 维
  +-- 2x2 池化   --> 4C 维
  +-- 4x4 池化   --> 16C 维
  |
  +-- 拼接 --> (1+4+16)*C 维，固定

这解决了 R-CNN 的第二个问题（形变偏差），但没有解决第一个问题（重复计算）——SPP-Net 依然是对每个候选框单独池化，虽然特征图只算一次，但候选框的池化和后面全连接层的计算还是逐个做的。更麻烦的是，SPP-Net 的训练依然分多步，依然要训 SVM，依然要把特征存在硬盘上。

5.3 SPP-Net 的检测流程 #

和 R-CNN 的差别集中在第二步：

  • 区域提名：Selective Search 生成约 2000 个候选窗口（和 R-CNN 一样）
  • 区域缩放：不再归一化到 227×227，而是把图缩放到最短边等于 s，s 从 {480, 576, 688, 864, 1200} 里选，标准是让缩放后的候选框大小最接近 224×224
  • 特征提取：整图过一次 CNN（只一次），再用 SPP 层对每个候选框在特征图上取固定维度特征
  • 分类与回归：和 R-CNN 一样，SVM 分类 + 边框回归

这里已经出现了「整图过一次 CNN」的思想，这是 SPP-Net 真正的贡献。但它没有把这个思想贯彻到底——SVM 还是要单独训，特征还是要落盘，梯度还是传不到 SPP 层之前。所以它只是半程改进。

5.4 Fast R-CNN：把流程拧成一根 #

Fast R-CNN 是 Girshick 自己在 2015 年推出的，动机很直接：R-CNN 和 SPP-Net 都有三个共同的毛病。

  • 训练分多步：先微调预训练网络，再对每个类别训 SVM，再训回归器，region proposal 还要单独用 Selective Search 拿。步骤繁琐。
  • 时间和内存开销大：训 SVM 和回归时要用网络特征作输入，特征存盘再读入的耗时不可忽略。
  • 测试慢：每张图的每个 region proposal 都要过一遍卷积，重复操作太多。

Fast R-CNN 相当于把这两个算法一起改掉：训练步骤减少，特征也不用存盘了。

指标很硬：基于 VGG16 的 Fast R-CNN，训练速度比 R-CNN 快约 9 倍，比 SPP-Net 快约 3 倍；测试速度比 R-CNN 快 213 倍，比 SPP-Net 快 10 倍。VOC 2012 上 mAP 在 66% 左右。

5.5 三个设计决策 #

决策一：整图过一次卷积。

把整张图归一化后直接送进深度网络，到接近末尾的少数几层，才加入候选框信息，在末尾几层处理每个候选框。

这一条直接干掉重复计算。2000 个候选框共享同一份卷积特征图，卷积只算一次。

决策二：RoI Pooling。

候选框投影到特征图上，得到一个任意大小的特征区域（RoI projection），然后用 RoI Pooling 把它变成固定大小。

具体操作：设 RoI 在特征图上的大小是 h × w（先忽略通道数），要输出 H × W，就把这个区域划分成 H × W 个网格，每个网格大小约 h/H × w/W，对每个网格做 max pooling。输出就是 H × W。

VGG16 版本用 H = W = 7。不管原始 RoI 多大，最后都是 7×7。

RoI Pooling 就是 SPP 的特例：SPP 是三层金字塔（1×1、2×2、4×4），RoI Pooling 只有一层（7×7）。所以它比 SPP 更简单，而且反向传播的实现也简单——梯度只需要回传到每个网格的最大值位置。

决策三：多任务损失。

分类和回归不再是两个独立模块，而是同一个网络的两个并列输出头，一起训练。

5.6 网络结构 #

主干是 VGG16。完整前向：

  • 输入 224×224（训练时），经过若干卷积层和池化层
  • 进入 RoI Pooling 层。这一层的输入是 conv5 的输出和 P 个候选区域
  • 再接两个 4096 维的全连接层
  • 然后分两路，都是全连接层，输出维度分别是 21 和 84，两路并列不是串行
    • 21 是分类输出：20 个目标类 + 1 个背景，每个候选框在每类上的得分
    • 84 是回归输出：21 类 × 4 个坐标，每个候选框每类的四个坐标偏移
  • 最后两个损失层：分类用 softmaxWithLoss（输入是 label 和分类得分），回归用 SmoothL1Loss（输入是回归输出、target 坐标和权重）
text
原图 (224x224)
  |
  +-- conv1..conv5 + pool --> 共享特征图
  |
  +-- RoI Pooling(候选框 P 个, 7x7)  --> P x 512 x 7 x 7
  |
  +-- fc6 (4096) --> fc7 (4096)
  |
  +--+-- fc_cls  (21)  --> softmaxWithLoss
     |
     +-- fc_bbox (84)  --> SmoothL1Loss

测试时和训练基本一样，只是最后两个 loss 层换成一个 softmax 层，输入分类得分，输出概率；然后对每个类别做 NMS。

5.7 RoI Pooling 的量化误差 #

这一层有个隐患，后来被 Mask R-CNN 用 RoI Align 修掉了，值得在这里说清。

RoI 的坐标是浮点数（候选框投影到特征图后一般带小数），但池化的网格边界要取整。Fast R-CNN 做了两次取整：

  1. 候选框坐标取整到特征图上的整数格点
  2. 每个网格的边界再取整

两次取整累积下来，RoI 和真实区域之间能差出几个像素。对分类影响不大，对分割这种像素级任务就是灾难。Mask R-CNN 的 RoI Align 去掉了这两次取整，改用双线性插值采样。

这条不影响理解 Fast R-CNN 的原理，但它是「RoI Pooling 不是无损操作」的证据。

5.8 训练细节：层次抽样 #

网络输入是图片和候选区域，输出是类别和 bbox，所以训练时每个候选区要提前标好类别和 bbox。样本怎么采，是 Fast R-CNN 的一个设计点。

做法是层次抽样。每个 mini-batch 是 128 个 RoI。先从训练集里选 2 张图，每张图取 64 个 RoI，凑成 128 个。这样同一张图的 64 个 RoI 共享前面的卷积计算，降低训练复杂度。

64 个 RoI 的构成：

  • 25% 是正样本：IOU > 0.5，类别 u >= 1
  • 75% 是背景：IOU ∈ [0.1, 0.5)，类别 u = 0

数据增强只用了水平翻转。测试时每张图约 2000 个 RoI。

正负比例 1:3，这个比例是有讲究的。正样本太多，模型偏向于「到处都有目标」；负样本太多，模型偏向于「什么都没有」。1:3 是经验上收敛稳定的配置。

5.9 损失函数 #

分类损失是 log loss。对真实类别 u 的概率 p_u 取负对数：

text
L_cls = -log(p_u)

分类层输出 K+1 维，K 个类加 1 个背景。

回归损失用 SmoothL1，t^u 是预测的偏移量，u 是类别，v 是真实的回归目标：

text
L_loc = Σ_{i in {x,y,w,h}} smooth_L1(t_i^u - v_i)

smooth_L1(x) = 0.5 * x^2            若 |x| < 1
             = |x| - 0.5            其他

为什么用 SmoothL1 而不用 L2。L2 对离群点太敏感——预测偏得离谱时梯度会爆炸，训练不稳。SmoothL1 在 |x| < 1 时是二次的（小误差时梯度平滑），超出后转成线性的（大误差时梯度有界）。这是个折中。

总损失把两路加起来：

text
L = L_cls + λ * [u >= 1] * L_loc

[u >= 1] 是示性函数：背景样本不参与回归损失。背景没有「正确的框」，让它学回归只会污染梯度。λ 默认取 1。

这个「示性函数屏蔽」的写法，后面 YOLO 的损失函数里会以另一个形式出现（对象性掩码），是同一个思路。

5.10 Fast R-CNN 还剩下什么问题 #

三条改进都到位了，但 Selective Search 还在。它依然是 CPU 上跑的 1~2 秒。

Fast R-CNN 的测试时间构成于是变成这样：

text
Selective Search   约 1~2 秒（CPU，无法优化）
网络前向           约 0.1~0.2 秒（GPU）

瓶颈从 GPU 转移到了 CPU，而且转移得很彻底。网络的加速空间已经不大，剩下的时间全在那段 Python/C++ 写的区域生成代码里。

还有一个结构层面的问题：Fast R-CNN 的候选框是外部输入的，网络只负责判候选，不负责生成候选。这意味着召回率的上限被 Selective Search 锁死了——Selective Search 没框到的东西，Fast R-CNN 永远检不出来。

这两个问题指向同一个答案：把候选生成也做成网络的一部分。这就是 Faster R-CNN。

六、Faster R-CNN 与 RPN #

6.1 RPN 的思路 #

Faster R-CNN 用区域提名网络（Region Proposal Network，RPN）取代 Selective Search。

RPN 的输入是一张任意大小的图片（实际是共享的卷积特征图），输出是一批矩形候选框，每个框带一个目标分数和位置信息。

关键在于它和检测网络共享卷积特征。整张图只算一遍卷积，RPN 在这份特征上提候选，检测头也在这份特征上判候选。区域提名、分类、回归三件事共用同一份特征图，这是加速的根本来源。

text
原图
  |
  +-- 共享卷积层（只算一次）
  |
  +--+-- RPN：在特征图上滑窗，产候选框
     |
     +-- RoI Pooling（用 RPN 输出）--> 检测头：分类 + 回归

6.2 Anchor：把回归问题变成分类问题 #

RPN 要解决的难题是：怎么让网络输出「任意大小、任意长宽比」的框。

直接回归框的四个坐标很难学，因为框的尺度跨度太大。RPN 的做法是引入 Anchor（锚框）：在特征图的每个位置上，预先铺好 k 个固定大小、固定长宽比的参考框，k 一般取 9（3 种尺度 × 3 种长宽比）。

网络不再直接预测框，而是预测相对于 Anchor 的偏移量。Anchor 是固定的、密集的、覆盖全图的，网络只需要回答两个问题：

  • 这个 Anchor 里有没有目标（二分类：object / non-object）
  • 如果有，框要往哪个方向挪多少、缩放多少（四个偏移量）

这样一来，所有框的尺度问题被 Anchor 吸收了，网络只需要学「微调」这件事，难度大幅下降。

text
特征图上一个位置，k = 9 个 anchor
  尺度 128: 1:1, 1:2, 2:1
  尺度 256: 1:1, 1:2, 2:1
  尺度 512: 1:1, 1:2, 2:1

Anchor 的数量算一下：特征图 H × W，每个位置 k 个，总共 H × W × k 个。一张 800×600 的图下采样 16 倍得到 50×38 的特征图，就是 1900 个位置，乘 9 是 17100 个 Anchor。远超 Selective Search 的 2000 个。

多出来的部分靠筛选：先按 object 分数排序取前 N 个，再用 NMS 去掉重叠的，最后剩约 2000 个进入第二阶段。多算的部分全部在 GPU 上并行完成，代价远低于在 CPU 上跑 Selective Search。

6.3 RPN 的训练样本 #

Anchor 数量巨大，但绝大多数是背景。训练时要按 IOU 给 Anchor 打标签：

标签 条件 用途
正样本 与某个真值框 IOU 最高，或 IOU > 0.7 参与分类和回归
负样本 与所有真值框 IOU < 0.3 只参与分类
忽略 IOU 在 0.3 ~ 0.7 之间 不参与损失

「与某个真值框 IOU 最高」这条规则是保底措施：有些目标特别小，没有任何 Anchor 能和它 IOU 超过 0.7，但总得有一个 Anchor 负责它。所以每个真值框至少绑定一个 Anchor。

采样策略：一张图里随机采 256 个 Anchor，正负各占一半。正样本不够就用负样本补。

6.4 四个损失 #

RPN 的损失是分类损失加回归损失：

text
L({p_i}, {t_i}) = (1/N_cls) * Σ L_cls(p_i, p_i*)
                + λ * (1/N_reg) * Σ p_i* * L_reg(t_i, t_i*)
  • p_i 是 Anchor i 含目标的预测概率，p_i* 是真值标签（正 1 负 0）
  • t_i 是预测的四个偏移量，t_i* 是真值偏移量
  • N_cls 是采样总数，N_reg 是 Anchor 位置数
  • λ 平衡两项，默认取 10

注意 p_i* 乘在回归项上：负样本的 p_i* 是 0，回归损失自动被屏蔽。和 Fast R-CNN 里的示性函数是同一个手法。

偏移量的参数化方式是重点，后面的 SS、YOLO 都抄了这一套：

text
t_x = (x - x_a) / w_a
t_y = (y - y_a) / h_a
t_w = log(w / w_a)
t_h = log(h / h_a)

x, y 是框中心，w, h 是宽高，下标 a 表示 Anchor。宽高用 log 是因为框的尺度变化是指数的——从 32 像素到 512 像素是 16 倍，用对数空间表示就变成线性变化，回归起来稳定得多。

6.5 两阶段的具体分工 #

Faster R-CNN 的三个步骤：

  • 特征提取：以整张图为输入，用 CNN 得到特征层（和 Fast R-CNN 一样）
  • 区域提名：在最终的卷积特征层上用 k 个不同尺寸的 Anchor 提名。对每个 Anchor 对应的区域做 object / non-object 二分类，用 k 个回归模型（各自对应不同 Anchor）微调位置与大小
  • 分类与回归：把 RPN 筛出来的候选框投影到特征图上，RoI Pooling 后做多类别分类和第二次边框回归

注意这里有两组回归：RPN 的回归负责把 Anchor 挪到「像物体」的位置，检测头的回归负责把候选框挪到「精确贴合」的位置。同一件事做了两遍，这是两阶段精度的来源。

text
Anchor（17000 个，粗糙）
   |  RPN 第一次回归 + 筛分数
   v
候选框（约 2000 个，大致对齐）
   |  检测头第二次回归
   v
检测框（精确对齐）

Faster R-CNN 在 VOC 2007 上 mAP 73.2%，速度 7 fps。Selective Search 那段 CPU 时间彻底消失了。

6.6 两阶段方法的共同结构 #

把 R-CNN 到 Faster R-CNN 摊平看，所有两阶段方法都能拆成两个子网络：

  • 一个共享的全卷积网络，负责把图变成特征图
  • 一个不共享计算的 ROI 相关子网络，负责对每个候选框单独处理

第二块之所以不共享，是因为每个 RoI 的位置不同、大小不同，网络要在各自的区域里做池化和全连接。「不共享」就是两阶段方法最后的效率包袱。

6.7 R-FCN：把最后一块不共享也干掉 #

R-FCN 的动机就是消掉那个不共享的 ROI 子网络：把最后的全连接层换成一个位置敏感的卷积网络，让所有计算都能共享。

做法是把每个候选区域划分成 k × k 个网格（原文 k = 3，九宫格）。九个网格分别对应：左上、上中、右上、左中、正中、右中、左下、下中、右下。

关键设计：每个网格位置都有自己的输出通道。预测时输出 C + 1 个通道，C 是类别数，+1 是背景。全部输出通道数是 k² × (C+1)。

为什么这样能共享。因为输出不是「一个框的分数」，而是「一张得分图」——图上每个位置都记录了「如果这个位置是某个类别的左上角，分数是多少」。之后对某个 RoI 做池化时，九宫格里的每一格去对应的位置敏感层上取值。这样全卷积层对所有位置通用，只靠池化时的位置索引区分，计算完全共享。

有个容易困惑的点：图里每个位置都铺着一个九宫格，但池化时只有一个起作用。比如 bottom-right 层，只有 RoI 的右下角那个小块被取用。那这一层的其他 8 个块干什么用？答案是它们服务于其他 RoI——偏左或偏上一些的 RoI，它们的右下角正好落在这些位置。

R-FCN 的步骤：

  • 区域提名：用 RPN，RPN 本身是全卷积结构
  • 分类与回归：利用和 RPN 共享的特征做分类。做 bbox 回归时把 C 设为 4

R-FCN 在 VOC 2007 上 mAP 76.6%，速度快于 Faster R-CNN。

七、两阶段方法的问题 #

7.1 三代改进的账本 #

先算总账。

方法 特征提取次数 候选生成方式 候选生成耗时 检测头次数 训练步骤
R-CNN 2000 次 Selective Search 1~2 秒（CPU） 2000 次 4 步
SPP-Net 1 次 Selective Search 1~2 秒（CPU） 2000 次 4 步
Fast R-CNN 1 次 Selective Search 1~2 秒（CPU） 2000 次（RoI Pooling） 1 步
Faster R-CNN 1 次 RPN 约 10 毫秒（GPU） 2000 次（RoI Pooling） 交替训练
R-FCN 1 次 RPN 约 10 毫秒（GPU） 1 次（全卷积） 交替训练

看这张表，改进的路径一目了然：先砍特征提取的重复，再砍候选生成的耗时，最后砍检测头的重复。每一步都在消一个「次数」。

但注意最后一列：训练步骤只从 4 步降到 1 步（Fast R-CNN），Faster R-CNN 反而回到了交替训练——RPN 和检测头要轮流训，因为两者共享特征，一起训会互相拉扯。

7.2 剩下的四个问题 #

一、结构上还是两段。RPN 先判「是不是目标」，检测头再判「是什么目标」。同一块区域被网络看了两遍。这不是浪费了一点算力的问题，是流程本身的复杂度。

Faster R-CNN 需要对约 2000 个 Anchor 先判断是否是目标，再做目标识别，分成了两步。每多一步，就多一组超参数、多一个训练目标、多一处出错的地方。

二、RoI Pooling 是逐个做的。虽然卷积共享了，但 RoI Pooling 和后面的全连接层还是要对每个候选跑一遍。2000 个候选就是 2000 次前向（虽然每次都小）。这个开销在 GPU 上不算致命，但它限制了速度上限。

三、小目标受特征图分辨率限制。RPN 在最后那层特征图上做预测，下采样 16 倍之后，一个 32×32 的小目标只剩 2×2。再小的目标在特征图上根本不存在。这个问题后面靠 FPN 和 SSD 的多尺度特征缓解。

四、标注和训练成本高。RPN 需要 Anchor 的尺度、长宽比设计，这些超参数和数据集的分布强相关。换一个数据集，Anchor 要重新调。

7.3 换个问法：检测能不能一步做完 #

上面四条问题，本质上都在说一件事：两段式流程有结构性开销。

那么反过来问：能不能不要候选这个中间产物，直接从图里回归出框和类别？

这正是 YOLO 的出发点。它的答案不是「把两段做快一点」，而是「把两段合成一段」。

这个转换能成立的技术前提有三个：

  • 卷积网络有能力在整图上做密集预测。语义分割已经证明了这一点——逐像素分类是可行的。
  • 检测的输出可以被固定下来。如果把图切成固定的格子，每个格子输出固定数量的框，那输出就是定长张量，回归就能做。
  • 定位精度可以靠损失函数的设计来补偿。没有候选的二次修正，精度会掉，但可以通过加权、尺度归一化等手段把损失压回来一部分。

代价也很清楚，而且 YOLO 论文自己承认了：定位误差大，小目标弱，密集目标弱。这些不是实现问题，是「一步做完」这个设计的固有代价。

7.4 一阶段的取舍清单 #

在进入 YOLO 之前，先把取舍摆明。一阶段方法放弃的东西：

  • 放弃候选的二次修正（定位精度）
  • 放弃「先粗筛再细判」的分工（对背景的判别力）
  • 放弃对小区域的独立处理（小目标召回）

换来的东西：

  • 一次前向（速度）
  • 端到端联合优化（训练简单，没有多阶段衔接）
  • 全局视野（YOLO 能看到整张图，背景误检显著低于 Fast R-CNN）

第三条容易被低估。Fast R-CNN 的分类器只看候选框里那一小块区域，它不知道框外面是什么。一块纹理像狗的草地，裁剪出来单独看，确实像狗。YOLO 的每个格子虽然也只能看到特征图上对应的位置，但经过多层卷积之后感受野覆盖了大半个图，它能利用上下文。这就是为什么 YOLO 的背景误检率比 Fast R-CNN 低一半——论文里 Fast R-CNN 有 13.6% 的检测是不含任何目标的误报，比 YOLO 高近 3 倍。

八、YOLO：把检测变成回归 #

8.1 一句话说清 YOLO #

YOLO 的全拼是 You Only Look Once，只看一次。

它做的事是：把目标检测任务看成一个回归问题。用单个神经网络直接从图像预测边界框和类别概率，端到端完成检测。不走「先生成候选、再分类」那条路。

效果上：基础版在 Titan X 上 45 fps，快速版（Fast YOLO，卷积层从 24 层减到 9 层）155 fps。同期最好的检测系统 Fast R-CNN 是 0.5 fps。

准确率上 YOLO 落后于当时最好的系统，而且很难精确定位某些目标，尤其是小目标。这个短板 YOLO 论文自己写在摘要里。

8.2 传统流程复杂在哪 #

YOLO 的动机是把前面那些复杂的流程整个推翻。先看传统检测在做什么。

DPM 这类系统用滑动窗口提区域，再用分类器识别。R-CNN 类方法用 region proposal 先生成潜在的 bounding box，再对这些 box 分类，最后后处理去重。这类方法流程复杂，速度慢，训练困难。

拆一下 R-CNN 的完整链条：选择性搜索产生候选框、卷积网络提取特征、SVM 给框打分、线性模型调整框、NMS 去重。五个阶段，每个阶段都得独立精确调优。测试时一张图超过 40 秒。

YOLO 的做法是不优化这条链条的某一环，而是整个扔掉。

8.3 统一检测的三个优点 #

把检测重构成单个回归问题后，得到三个好处：

一、非常快。预测流程简单。基础版 45 fps，快速版 150 fps，实时检测成立。而且这个速度不是靠剪枝、量化换来的，是结构本身的简单。

二、用全图信息预测。滑动窗口和 region proposal 方法在训练和预测时只能看到局部。YOLO 看整张图。直接后果：Fast R-CNN 会把背景里的斑块误检成目标，因为它看不到全局图像；YOLO 的背景误检率比 Fast R-CNN 低一半。

这一点值得展开。Fast R-CNN 的分类器输入是候选框裁剪出来的区域，裁剪之后框外的信息全部丢失。一片像狗的草地，单独裁出来看，纹理、形状确实像。而 YOLO 的卷积层堆叠之后，最后那个格子对应的感受野覆盖了整张图的大半，它能看到「这块草地周围都是草，没有狗的身体」，于是判成背景。

三、学到可泛化的表示。用自然图片训练 YOLO，然后拿到艺术图像上预测，YOLO 比 DPM 和 R-CNN 的准确率高很多。原因是它学的是目标的大小、形状、以及目标和目标之间一般的相对位置关系，这些在艺术品和自然图像里是相似的，虽然像素级别差异很大。

8.4 网络结构 #

主干受 GoogLeNet 启发，但没照搬。24 个卷积层 + 2 个全连接层。用 1×1 降维层接 3×3 卷积层的组合，取代 GoogLeNet 的 Inception 模块。

训练分两段：

  1. 在 ImageNet 1000 类分类任务上预训练卷积层。用的是前 20 个卷积层 + 平均池化 + 全连接，输入分辨率 224×224，训了大约一周，ImageNet 2012 验证集上单裁剪 top-5 准确率 88%，和 Caffe 模型库里的 GoogLeNet 相当。
  2. 换成检测任务。加 4 个卷积层和 2 个全连接层，权重随机初始化。检测需要细粒度视觉信息，所以把输入分辨率从 224×224 提到 448×448。
text
448x448x3
  |
  +-- 24 个卷积层（1x1 降维 + 3x3 卷积交替）
  |
  +-- 2 个全连接层
  |
  +-- 7x7x30 输出张量

最后一层用线性激活，其他所有层用 leaky ReLU：

text
leaky_ReLU(x) = x       若 x > 0
              = 0.1x    其他

输出是 7×7×30 的张量。30 这个数字后面要拆开讲。

YOLO 和 Fast YOLO 除了网络规模（24 层 vs 9 层，滤波器数量也不同），所有训练和测试参数完全一致。这个设计是为了让对比公平——速度差异只来自网络容量。

8.5 检测流程三步 #

text
1. 把输入图片缩放到 448x448
2. 跑一次卷积网络
3. 对模型输出的置信度卡阈值，得到目标位置与类别

就这三步。没有候选生成，没有逐区域分类，没有多阶段后处理。

测试时也只需要一次网络评估。在 VOC 上，每张图网络预测 98 个边界框和每个框的类别概率（7×7×2 = 98）。这个数字对比 Selective Search 的 2000 个候选，少了一个量级。

8.6 网格划分：YOLO 的核心设计 #

这是全篇最重要的设计之一，慢慢拆。

把 448×448 的图切成 S × S 的网格。规则只有一条：如果一个目标的中心点落在某个格子里，这个格子就负责检测该目标。

S = 7，所以是 7×7 = 49 个格子。

每个格子负责三件事：

  • 预测 B 个边界框，每个框带一个置信度（B = 2）
  • 预测 C 个类别概率（VOC 是 C = 20）
  • 只输出一组类别概率，不管 B 是多少个框

为什么第三个设计是这样。因为类别概率是「以这个格子包含目标为前提」的条件概率，它跟具体哪个框无关。一个格子里有什么类别，是这个格子的属性，不是某个框的属性。

于是输出张量的维度拆开：

text
S x S x (B * 5 + C) = 7 x 7 x (2 * 5 + 20) = 7 x 7 x 30

B * 5 里的 5 是 x, y, w, h, confidence：

  • (x, y) 是框中心相对于该格子边界的偏移，取值范围 [0, 1]
  • (w, h) 是框的宽高相对于整张图的比值，取值范围 [0, 1]
  • confidence 是预测框与真实框的 IOU

(w, h) 用整图归一化而不是格子归一化，是因为同一个物体的大小于它落在哪个格子无关。(x, y) 用格子内偏移，是为了让每个格子只关心自己那一小块，位置编码局部化，训练更稳。

text
一个格子的输出（30 维）
  [x1, y1, w1, h1, conf1]    框 1
  [x2, y2, w2, h2, conf2]    框 2
  [p_class1, ..., p_class20] 类别概率，两组框共用

8.7 置信度的定义 #

置信度的定义是：

text
confidence = Pr(Object) * IOU(pred, truth)

拆开看：

  • 如果格子里没有目标，Pr(Object) = 0，置信度为 0
  • 如果有目标，置信度等于预测框与真实框的 IOU

这个设计把两件事压进了一个数：这里有没有东西、框得准不准。训练时它对应一个回归目标，推理时它直接当分数用。

推理时，每个框的类别置信度是两者相乘：

text
score = Pr(Class_i | Object) * confidence

这个分数同时编码了两层信息：这个类别出现在框里的概率，以及预测框贴合目标的程度。

8.8 这个设计的代价 #

网格是启发式的，代价很具体。

S = 7 意味着每格 64×64 像素。整个格子只有一个类别标签、只有一组类别概率。

  • 两个目标的中心落在同一个格子里，只能检出一个。格子只输出一组类别概率，第二个目标直接丢了。密集目标（一群鸟、一排瓶子）尤其明显。
  • 小目标天生吃亏。一个 20×20 的目标，在 64×64 的格子里只占一小块，但格子只输出 2 个框，两个框都得覆盖整个格子的范围。
  • 格子边界上的目标质量下降。目标靠近多个格子的交界处时，会被多个格子同时「认为」归自己管，产生重复检测。论文承认这点，靠 NMS 修正。有意思的是，对 R-CNN 和 DPM 这类方法，NMS 能加 2%~3% mAP；对 YOLO 来说它只是补漏。

论文列了 YOLO 的三个局限：

  • 每个网格只预测两个框、一组类别。相邻目标的预测准确率下降，成队列的目标（一群鸟）识别准确率低。
  • 模型从数据里学框的位置，很难泛化到新的、不常见角度的目标。架构有多个下采样层，用的是相对粗糙的特征来预测框。
  • 损失函数同等对待大框和小框的误差。大框的小误差一般良性，小框的小误差对 IOU 影响大得多。主要错误来源是定位不准。

第三条在损失函数那一章会具体处理。

8.9 和 R-CNN 的异同 #

相似的地方：每个格子都在提潜在的边界框，并用卷积特征给这些框打分。这和 R-CNN 用候选框加 CNN 特征打分，思路是通的。

不同的地方有三条：

  • 空间限制。R-CNN 的候选框可以在任意位置，YOLO 的框被限制在格子里。这个限制缓解了同一目标的重复检测。
  • 框的数量。YOLO 每张图 98 个框，Selective Search 约 2000 个。少了一个量级。
  • 组件是否联合。R-CNN 的五个组件各自独立调优，YOLO 把它们合成一个联合优化的模型。

和 DPM 的对比更彻底：DPM 用不相交的流程做特征提取、区域分类、框预测，YOLO 用单个卷积网络同时做这些事。网络内嵌地训练特征，而不是用 HOG 这类静态特征。

和 OverFeat 的对比：OverFeat 也高效地做滑动窗口检测，但它是个不相交的系统，优化的是定位而不是检测。它的定位器预测时只能看到局部信息，不能推断全局上下文，需要大量后处理才能产生连贯的检测。

8.10 一阶段的通用范式 #

把 YOLO 的骨架抽出来，就是所有一阶段方法的模板：

text
1. 输入图过主干网络，得到特征图
2. 特征图的每个空间位置 -> 一组预测（框偏移 + 置信度 + 类别）
3. 所有位置的预测拼起来，卡阈值 + NMS

SSD 在这个骨架上加了多尺度特征图，RetinaNet 加了 Focal Loss。骨架没变。

这个范式能成立，靠的是「把变长输出转成定长张量」这个技巧。格子固定、每格框数固定、类别数固定，输出就是定长的。检测的变长问题被位置编码吃掉了。

九、YOLO 的网格划分与损失函数 #

9.1 为什么用平方和误差 #

YOLO 优化的是模型输出上的平方和误差。选择理由很实际：容易优化。

但论文自己说了，平方和误差并不完全符合「最大化平均精度」这个目标，而且有两个具体的错配。

错配一：分类误差和定位误差权重相同。

一个 30 维的输出向量里，20 维是类别概率，10 维是框坐标。平方和误差把它们平等对待。可实际上，框偏了 10 个像素和类别判错一个，对 mAP 的影响完全不同。

错配二：背景格子的梯度淹没前景。

一张图 49 个格子，绝大多数不含任何目标。这些格子的置信度目标都是 0，它们的损失会不断把置信度往 0 推。49 个格子里只有 2~3 个有目标，背景格子的梯度占了压倒性多数，模型容易训成「到处都说没东西」，训练早期直接发散。

9.2 两个权重系数 #

针对错配二，加两个系数：

text
λ_coord = 5      # 框坐标损失的权重
λ_noobj = 0.5    # 不含目标格子的置信度损失权重

λ_coord = 5 是把框坐标损失的权重提高 5 倍，补偿错配一。λ_noobj = 0.5 是把不含目标格子的置信度损失压低一半，缓解错配二。

这里有个细节值得注意：λ_coord 加在坐标项上，λ_noobj 乘在「不含目标的置信度项」上。含目标的置信度项不加 λ_noobj——有目标的格子本来就少，不能再压。

9.3 宽高开根号 #

错配一还有一个更细的层面：平方和误差对大框和小框同等加权。

但误差的后果不对称。一个 200×200 的框偏了 10 像素，IOU 掉一点点；一个 20×20 的框偏了 10 像素，IOU 直接腰斩。

解法是直接预测宽高的平方根，而不是宽高本身：

text
预测 sqrt(w)、sqrt(h)，而不是 w、h

开根号让同样的绝对误差在小框上产生的损失更大，在大框上更小——正好对应误差的实际影响。这是个不理想但便宜的近似，论文原话是「部分解决」。

9.4 一个框由谁负责 #

每个格子预测 B = 2 个框，但一个目标只需要一个框来负责。

规则：和真值框当前 IOU 最大的那个预测器负责。

具体做法是算两个预测框与真值的 IOU，取大的那个，把它的 1_ij^obj 设为 1，另一个设为 0。

text
1_i^obj   = 1  格子 i 里有目标
          = 0  没有

1_ij^obj  = 1  格子 i 的第 j 个框负责这个目标（有目标且该框 IOU 最大）
          = 0  其他

为什么这样设计。论文的解释是「导致边界框预测器之间的专业化」——两个预测器各学各的，一个更擅长宽扁的框，一个更擅长瘦高的框，整体召回率提升。

这个机制有个副作用：两个预测器容易退化成「一个负责大部分目标、另一个几乎不用」。实际训练中这种情况常见，但不影响最终效果。

9.5 损失函数的完整拆解 #

多部分损失函数五项，逐项说。

text
L = λ_coord * Σ_i^S² Σ_j^B 1_ij^obj [(x_i - x̂_i)² + (y_i - ŷ_i)²]
  + λ_coord * Σ_i^S² Σ_j^B 1_ij^obj [(√w_i - √ŵ_i)² + (√h_i - √ĥ_i)²]
  +           Σ_i^S² Σ_j^B 1_ij^obj (C_i - Ĉ_i)²
  + λ_noobj * Σ_i^S² Σ_j^B 1_ij^noobj (C_i - Ĉ_i)²
  +           Σ_i^S² 1_i^obj Σ_c∈classes (p_i(c) - p̂_i(c))²

第一项：中心坐标损失。只对「负责的框」生效（1_ij^obj = 1），权重 λ_coord = 5。

第二项：宽高损失。同样只对负责的框生效，同样 λ_coord = 5，但预测目标是开根号后的宽高。

第三项：含目标的置信度损失。负责的框，置信度目标就是它和真值的 IOU。注意这一项没有 λ_noobj。

第四项：不含目标的置信度损失。1_ij^noobj = 1 表示这个框不负责任何目标，置信度目标是 0。权重 λ_noobj = 0.5。

第五项：分类损失。只对含目标的格子生效（1_i^obj = 1），不区分哪个框——因为类别概率是格子级别的。这一项没有 λ_coord，权重是 1。

三个掩码的分工理一下：

掩码 取值条件 作用范围
1_i^obj 格子 i 内有目标中心点 分类损失
1_ij^obj 格子 i 的第 j 个框负责该目标 坐标损失、含目标置信度损失
1_ij^noobj 格子 i 的第 j 个框不负责任何目标 不含目标置信度损失

注意 1_ij^obj 和 1_ij^noobj 不是互补的。在没有目标的格子里，两个框都算 noobj；在有目标的格子里，只有一个框算 obj，另一个框既不是 obj 也不算 noobj——它的置信度损失被完全忽略。这个细节很多实现搞错。

损失函数的两个「仅惩罚」原则：

  • 只有格子里有目标时，才惩罚分类错误
  • 只有预测器「负责」真值框时，才惩罚坐标错误

9.7 用几十行代码复现损失 #

理解损失函数最好的方式是写出来。下面这版按论文逐项实现，输入是 7×7×30 的预测张量和标注。

python
import torch
import torch.nn as nn

class YoloLoss(nn.Module):
    def __init__(self, S=7, B=2, C=20):
        super().__init__()
        self.S, self.B, self.C = S, B, C
        self.l_coord, self.l_noobj = 5.0, 0.5
        self.mse = nn.MSELoss(reduction="sum")

    def forward(self, pred, target):
        # pred, target: (batch, S, S, B*5 + C)
        S, B, C = self.S, self.B, self.C
        pred = pred.view(-1, S, S, B * 5 + C)
        target = target.view(-1, S, S, B * 5 + C)

        pred_boxes = pred[..., :B * 5].reshape(-1, S, S, B, 5)
        tgt_boxes = target[..., :B * 5].reshape(-1, S, S, B, 5)
        pred_cls, tgt_cls = pred[..., B * 5:], target[..., B * 5:]

        # 两个掩码：负责的框、不负责的框
        obj_mask = tgt_boxes[..., 4] > 0
        noobj_mask = tgt_boxes[..., 4] == 0

        def masked_mse(a, b, m):
            return self.mse(a * m, b * m)

        m2 = obj_mask.unsqueeze(-1)
        xy_loss = masked_mse(pred_boxes[..., :2], tgt_boxes[..., :2], m2)

        # 宽高开根号，这是论文的关键技巧
        pred_wh = torch.sign(pred_boxes[..., 2:4]) * \
            torch.sqrt(torch.abs(pred_boxes[..., 2:4]) + 1e-6)
        tgt_wh = torch.sqrt(tgt_boxes[..., 2:4] + 1e-6)
        wh_loss = masked_mse(pred_wh, tgt_wh, m2)

        # 置信度损失分两段：有目标的、没目标的
        obj_conf = masked_mse(pred_boxes[..., 4], tgt_boxes[..., 4], obj_mask)
        noobj_conf = masked_mse(pred_boxes[..., 4], tgt_boxes[..., 4], noobj_mask)

        # 分类损失，只对含目标的格子生效
        cls_mask = tgt_boxes[..., 4].max(dim=-1)[0] > 0
        cls_loss = masked_mse(pred_cls, tgt_cls, cls_mask.unsqueeze(-1))

        return (self.l_coord * xy_loss + self.l_coord * wh_loss
                + obj_conf + self.l_noobj * noobj_conf + cls_loss)

几个实现上的坑，直接说结论：

  • 宽高开根号前要防负数。预测值会为负，sqrt 出 NaN，所以先 abs() 再开根，配合 sign() 还原符号。论文没写这一层，但工程实现里必须有。
  • obj_mask 的构造依赖标注里已经把「负责的框」标好了。这一步在数据加载阶段完成——算两个预测框与真值的 IOU，取大的那个。损失函数本身不做这个判断。
  • reduction="sum" 而不是 "mean"。各个掩码的样本数差异很大，求平均会让权重系数失去意义。
  • 分类损失的掩码用「格子里任一框有目标」而不是「格子里有目标中心」。标准标注下两者等价，但一个格子标了多个目标时就得取 max。

9.8 推理时的后处理 #

推理比训练简单，但有几个细节。

text
1. 网络前向，得到 7x7x30 输出
2. 对每个格子，每个框：score = confidence * class_prob
3. 卡阈值（比如 0.2），低于阈值的丢掉
4. 按类别做 NMS，阈值 0.4~0.5
5. 输出剩余框

第 2 步是 confidence 和 class_prob 相乘，得到每个框在每个类别上的分数。一个框会得到 20 个分数（VOC），取最大那个作为它的类别和分数。

第 4 步为什么按类别做。不同类别的框不该互相抑制——一只狗和一个球挨在一起，它们的框 IOU 会很高，但不该只留一个。

NMS 的阈值在 YOLO 上一般调得比两阶段高一点（0.45 左右），因为 YOLO 本身的定位精度不高，同一目标的两个框 IOU 也不会特别大。

9.9 网格设计带来的最后一个问题 #

回到 8.8 的那三条局限，第三条（损失函数同等对待大小框）已经在 9.3 用开根号部分解决了。前两条（密集目标、小目标）没法用损失函数解决，是结构的固有代价。

论文的实验数据也印证了这一点。VOC 2012 上 YOLO 得 57.9% mAP，比当时最新技术低，接近用 VGG-16 的原始 R-CNN。分细类看：bottle、sheep、tv/monitor 这些类，YOLO 比 R-CNN 或 Feature Edit 低 8%~10%；cat、train 这些类，YOLO 更高。

哪些类低。小物体密集出现的类。哪些类高。目标大、轮廓清晰的类。这个分布和「格子容量有限」的解释完全吻合。

误差分解实验给出了更细的证据。用 Hoiem 的方法对每个类别的前 N 个预测分类：

错误类型 定义
Correct 类别正确且 IOU > 0.5
Localization 类别正确，0.1 < IOU < 0.5
Similar 类别相似，IOU > 0.1
Other 类别错误，IOU > 0.1
Background 任何 IOU < 0.1 的目标

结论：定位错误占 YOLO 错误的大多数，比其它错误源加起来都多。Fast R-CNN 的定位错误少得多，但背景错误更多——它 13.6% 的检测是不含任何目标的误报，比 YOLO 高近 3 倍。

这个分解解释了为什么两个模型组合起来能涨点。Fast R-CNN 最好的模型在 VOC 2007 测试集上 71.8% mAP，和 YOLO 结合后涨 3.2% 到 75%。而把不同版本的 Fast R-CNN 互相组合，只涨 0.3%~0.6%。

原因很直白：两个模型犯的错不一样。集成起作用的条件是误差不相关。Fast R-CNN 强在定位、弱在背景判别；YOLO 反过来。把 YOLO 的背景判断能力叠加到 Fast R-CNN 上，正好补的是短板。

组合的具体做法：对 R-CNN 预测的每个框，检查 YOLO 是否也预测了一个类似的框。是的话，按 YOLO 的概率和两个框的重叠度，对这个预测加权提升。

代价是这个组合没有从 YOLO 的速度里获益——两个模型要分别跑再合并结果。不过因为 YOLO 足够快，比 Fast R-CNN 多的那点计算时间可以忽略。

10.2 差异的本质是样本分布 #

抛开架构细节，两条路线的差异可以归到一件事上：训练时正负样本的比例差两个数量级。

两阶段：候选生成阶段已经把明显是背景的区域滤掉了，进入检测头的 2000 个候选里，正样本（IOU > 0.5）一般占 20%~30%。正负比 1:3 左右，梯度不会被背景淹没。

一阶段：在特征图的每个位置上密集采样。YOLO v1 是 98 个框，SSD300 是 8732 个框。其中真正含目标的只有几个到几十个。正负比 1:100 到 1:1000。

这个差异的直接后果：一阶段的损失函数会被背景主导。YOLO 用 λ_noobj = 0.5 压了一下，SSD 用 hard negative mining（按损失排序取最难的负样本，把正负比压到 1:3）。RetinaNet 的 Focal Loss 是这个问题的终极答案——按样本的易分程度动态降权，易分的负样本损失自动趋近于 0。

Focal Loss 的形式值得记住：

text
FL(p_t) = -α_t * (1 - p_t)^γ * log(p_t)

γ 取 2。当 p_t 接近 1（易分样本），(1-p_t)^γ 接近 0，损失被压没；当 p_t 接近 0（难分样本），权重接近 1，全额保留。一阶段方法加上它，精度追平甚至反超两阶段。

10.3 为什么两阶段在小目标上更强 #

三个原因叠起来。

原因一：两阶段对小区域做了尺寸归一化。RoI Pooling 把任意大小的候选区域都变成 7×7。一个 32×32 的小目标，池化后是 7×7 的特征表示，分辨率被放大了。一阶段的小目标在特征图上只有几个像素，池化只会再缩小。

原因二：候选生成会主动找回小目标。RPN 的 Anchor 有多个尺度，小尺度 Anchor 专门负责小目标。Selective Search 更是从超像素开始合并，最小的候选可以是十几个像素。

原因三：两阶段的分类器只看局部。这一点在小目标上反而是优势——小目标的上下文干扰少，看局部更准。一阶段的全局视野在小目标上帮不上忙，因为目标本身在高层特征图上已经糊了。

这也是为什么后来的 FPN（特征金字塔）成了一阶段的标配：把高层语义和低层高分辨率特征融合，让小目标在高分辨率层上被检测。

10.4 为什么一阶段在背景判别上更强 #

反过来的优势。

YOLO 的背景误检率比 Fast R-CNN 低一半。原因是感受野。

一阶段方法的每个预测位置，经过多层卷积后感受野覆盖了大半张图。它判「这里有没有目标」时，用的是整张图的上下文。一片像狗的草地，YOLO 能看到周围没有狗的身体、没有狗的腿，于是判背景。

两阶段的分类器输入是候选框裁剪出来的区域，框外信息全丢。分类器只看到一小块，判错的机会就多。

这个道理在设计 RoI 头时容易被忘掉。后来的改进（比如给 RoI 特征拼接上下文、或者用更大的 RoI 扩展比例）都是在补这块信息。

10.5 什么时候该选哪条 #

不用纠结架构优劣，按约束选。

选一阶段的场景：

  • 实时性硬约束。视频流、自动驾驶感知、工业质检产线，低于 30 fps 就没法用。
  • 目标尺度分布集中。所有目标都在中等尺寸，没有极端小目标。
  • 部署环境算力有限。边缘设备、嵌入式板子。
  • 训练数据量不大。一阶段结构简单，过拟合风险低一些。

选两阶段的场景：

  • 精度优先。医学影像、遥感、缺陷检测，漏检的代价高。
  • 小目标多。遥感图像的车辆、医学影像的病灶。
  • 目标密集。人群计数、货架商品识别。
  • 允许离线推理。一批图跑几分钟可以接受。

选两者的组合：需要精度又想快，用一阶段做初筛、两阶段做精判，或者用蒸馏把两阶段的能力压到一阶段模型里。工程上更常见的是直接上 YOLO 后期版本——v3 之后多尺度加 FPN，小目标短板补上了大半。

十一、后面的演进（SSD、RetinaNet、YOLOv2~v8） #

11.1 SSD：冲着 YOLO 的缺点来的 #

SSD 的全拼是 Single Shot MultiBox Detector。它的设计目标写在论文里：解决 YOLO 的定位不准和小目标弱。

两个核心改动。

改动一：多尺度特征图。

YOLO 只在最后一层 7×7 的特征图上预测。SSD 在多个尺度的特征图上同时预测：前面的 8×8 网格检测小目标，后面的 4×4 网格检测大目标。

为什么管用。深层特征图分辨率低但语义强，适合大目标；浅层特征图分辨率高但语义弱，适合小目标。一个 32×32 的小目标在 8×8 的特征图上占 4×4 个格子，信息量足够；在 4×4 的特征图上连一个格子都占不满。

改动二：Default Box。

每个格子上铺一系列固定大小的框，SSD 里叫 Default Box，概念上就是 Faster R-CNN 的 Anchor。训练时把真值框分配给 IOU 最大的 Default Box。

text
SSD300 的 Default Box 分布
  conv4_3 (38x38): 4 个/位置
  conv7   (19x19): 6 个/位置
  conv8_2 (10x10): 6 个/位置
  conv9_2 (5x5)  : 6 个/位置
  conv10_2(3x3)  : 4 个/位置
  conv11_2(1x1)  : 4 个/位置
  合计 8732 个

网络结构分两段：前面是标准的图像分类网络（去掉分类相关的层），后面接多个检测用的多尺度特征层。

SSD300 在 VOC 2007 上 74.3% mAP、59 fps。保持 YOLO 速度的同时，精度接近 Faster R-CNN。

它的问题也很清楚：Default Box 的形状和网格大小是事先固定的，对特定图片的小目标提取不够好。这个批评和 YOLO 的格子问题同源——都是「先定结构，再适配数据」。

11.2 RetinaNet：Focal Loss 把一阶段的账还了 #

RetinaNet 的贡献就一个：Focal Loss。但它的影响大——一阶段方法第一次在精度上反超两阶段。

前面 10.2 讲过原理。补充一点设计细节：RetinaNet 用 FPN 做主干，五个尺度各铺 Anchor，总共约 10 万个。这个数量级下正负失衡极端严重，没有 Focal Loss 根本训不动。

γ = 2 的效果：一个 p_t = 0.9 的易分负样本，损失被压到原来的 0.01 倍。10 万个样本里 9.9 万个是易分负样本，压完之后它们的影响和有价值的难样本持平。

11.3 YOLOv2：把 Anchor 引进来 #

YOLOv2（论文名 YOLO9000）改了一批东西，最重要的两条。

Batch Normalization。每个卷积层后加 BN，去掉 dropout。mAP 涨 2% 以上。

Anchor Box。v1 用全连接层直接回归框的宽高，v2 改成 Faster R-CNN 那套 Anchor 机制，预测相对 Anchor 的偏移。但 v2 做了一件 v1 没做的事：用 k-means 在训练集上聚类出 Anchor 的尺寸，而不是手工设计。

聚类用的距离不是欧氏距离，是 1 - IOU。这样才能让聚类结果对应「框的贴合程度」而不是「框的绝对大小」。

VOC 上聚出 5 个 Anchor，平均 IOU 从手工设计的 0.639 提到 0.685。

其他改动：passthrough 层融合浅层特征（粗糙版的 FPN）、多尺度训练（每 10 个 batch 换一次输入尺寸）、Darknet-19 主干。

YOLOv2 在 VOC 2007 上 76.8% mAP、67 fps。

11.4 YOLOv3：多尺度预测 #

v3 的改动集中在三处。

多尺度预测。在三个不同尺度的特征图上各预测一组框，和 SSD 的思路一致但实现不同。13×13 负责大目标，26×26 负责中目标，52×52 负责小目标。每个尺度 3 个 Anchor，共 9 个。

残差主干 Darknet-53。借鉴 ResNet 的 shortcut 连接。53 个卷积层，比 Darknet-19 深得多，但因为有残差，梯度能传下去。

分类改用独立的 logistic。不用 softmax，每个类别独立做二分类。理由是 softmax 假设类别互斥，但实际数据里「人」和「骑手」可以同时成立。改成 logistic 后支持多标签。

v3 在 COCO 上 33.0% AP、51 fps（输入 608）。同期最好的两阶段方法精度更高但慢一个量级。

v3 是 YOLO 系列里被引用最多、工程上最常用的版本，稳定、易部署、精度够用。

11.5 v4 与 v5：工程化的分水岭 #

从 v4 开始，改进的重心从「架构创新」转到「工程配方」。

YOLOv4 的核心是一堆技巧的组合，论文里叫「bag of freebies」（不增加推理成本）和「bag of specials」（小幅增加成本换精度）：

类别 技巧 作用
数据增强 Mosaic 四图拼接，提升小目标和上下文
数据增强 CutMix 区域裁剪粘贴
正则 DropBlock 卷积层的 dropout
主干 CSPDarknet53 跨阶段部分连接，减少重复梯度
颈部 SPP + PANet 空间金字塔 + 双向特征融合
激活 Mish 平滑激活，梯度更稳
损失 CIoU Loss 考虑中心距和长宽比

YOLOv5 没有发表论文，主体思路和 v4 接近，价值在工程：PyTorch 原生实现、完整的训练推理部署链路、模型缩放（n/s/m/l/x 五档）、导出 ONNX/TensorRT 的一键脚本。

工程上 v5 的采用率高于 v4，原因不在精度，在可用性。

11.6 v6 到 v8：主干与标签分配的迭代 #

YOLOX（不叫 v6，但常被当作 v6 讨论）引入两件事：解耦头（分类和回归分开两个分支）、SimOTA 动态标签分配。

YOLOv6 面向工业部署，主打重参数化（RepVGG 风格的训练时多分支、推理时合成单路）。

YOLOv7 的思路是「可训练的 bag of freebies」：梯度路径规划、辅助头训练、模型缩放策略。COCO 上 56.8% AP，速度在同精度里最快。

YOLOv8 改成 anchor-free，用 TaskAlignedAssigner 做标签分配，分类损失用 VFL，回归用 CIoU + DFL。同时把分割、姿态、跟踪整合进同一套框架。

11.7 演进的主线 #

把 v1 到 v8 串起来看，改进集中在四个方向：

方向 v1 的状态 后期的解法 解决了什么
尺度 单层 7×7 网格 FPN 多尺度、三组 Anchor 小目标
框的设计 全连接直接回归 Anchor + k-means 聚类、anchor-free 框的尺度覆盖
样本分配 固定 IOU 阈值 SimOTA、TaskAligned 动态分配 正负样本质量
损失函数 平方和误差 CIoU、DFL、VFL 定位精度

有一条设计始终没变：「每个位置预测固定数量的框」这个范式。v8 换成 anchor-free 也没跳出这个框架。所以第九章讲的网格划分，读后期版本时依然是基础。

十二、评价指标 mAP #

12.1 从混淆矩阵开始 #

检测里的 TP / FP / FN 判定依赖于 IOU 阈值和一个前置约定。

对某个类别、某个 IOU 阈值（比如 0.5）：

情况 判定 说明
预测框与某真值框 IOU ≥ 0.5，且该真值框未被匹配 TP 正确检出
预测框与所有真值框 IOU < 0.5 FP 误检
预测框与真值框 IOU ≥ 0.5，但真值框已被更高分的框匹配 FP 重复检测
有真值框没被任何预测框匹配 FN 漏检

第三条是检测特有的：一个真值框只能被一个预测框匹配。所以 NMS 没清干净的重复框会被算成 FP。

12.2 精度与召回 #

text
Precision = TP / (TP + FP)     预测出来的里面有多少是对的
Recall    = TP / (TP + FN)     真值里面有多少被找出来了

这两个指标互相拉扯。把置信度阈值调低，更多框被留下，召回涨，精度掉；调高，精度涨，召回掉。

单看任何一个都没意义。所以需要一条曲线。

12.3 PR 曲线怎么画 #

关键动作：按置信度排序。

text
1. 把某个类别的所有预测框按置信度从高到低排序
2. 从头开始，每次多纳入一个框，重新算一次 Precision 和 Recall
3. 得到一串 (Recall, Precision) 点
4. 以 Recall 为横轴、Precision 为纵轴，连成曲线

举个具体例子。假设某个类别有 5 个真值框，模型输出了 10 个预测框，按分数排序后逐个核对：

序号 置信度 是否 TP 累计 TP 累计 FP Precision Recall
1 0.95 TP 1 0 1.000 0.20
2 0.90 TP 2 0 1.000 0.40
3 0.85 FP 2 1 0.667 0.40
4 0.80 TP 3 1 0.750 0.60
5 0.70 FP 3 2 0.600 0.60
6 0.65 TP 4 2 0.667 0.80
7 0.60 FP 4 3 0.571 0.80
8 0.55 FP 4 4 0.500 0.80
9 0.40 TP 5 4 0.556 1.00
10 0.30 FP 5 5 0.500 1.00

把后两列画出来，就是 PR 曲线。曲线一定是从右上往右下走的锯齿状——每遇到 TP，召回上升；每遇到 FP，精度下降。

python
import numpy as np

def pr_curve(preds, gts, iou_thresh=0.5):
    # preds: [(score, box)], 已按 score 降序
    # gts:   [box, ...]
    tp = np.zeros(len(preds))
    fp = np.zeros(len(preds))
    matched = set()

    for i, (score, box) in enumerate(preds):
        best_iou, best_j = 0.0, -1
        for j, gt in enumerate(gts):
            v = iou(box, gt)
            if v > best_iou:
                best_iou, best_j = v, j
        if best_iou >= iou_thresh and best_j not in matched:
            tp[i] = 1
            matched.add(best_j)
        else:
            fp[i] = 1

    tp_cum = np.cumsum(tp)
    fp_cum = np.cumsum(fp)
    recall = tp_cum / len(gts)
    precision = tp_cum / (tp_cum + fp_cum + 1e-9)
    return recall, precision

12.4 AP：曲线下的面积 #

AP（Average Precision）是 PR 曲线下的面积。

实际计算不用积分，用插值求和。VOC 有两种算法。

VOC 2007 的 11 点插值：

text
把召回从 0 到 1 均分成 11 个点：0, 0.1, 0.2, ..., 1.0
对每个召回点 r，取所有 recall >= r 的位置里最大的 precision
AP = (1/11) * Σ_{r} p_interp(r)

VOC 2010 之后的全点插值：

text
对每个召回变化的位置，取该位置之后所有 precision 的最大值
AP = Σ (r_{n+1} - r_n) * p_interp(r_{n+1})

python
def ap_voc2010(recall, precision):
    # 从右往左做 precision 包络
    mrec = np.concatenate(([0.0], recall, [1.0]))
    mpre = np.concatenate(([0.0], precision, [0.0]))
    for i in range(len(mpre) - 2, -1, -1):
        mpre[i] = max(mpre[i], mpre[i + 1])

    idx = np.where(mrec[1:] != mrec[:-1])[0]
    return np.sum((mrec[idx + 1] - mrec[idx]) * mpre[idx + 1])

「做包络」这一步为什么必要。PR 曲线是锯齿状的，某个召回点上的 precision 会因为一个 FP 突然掉下去。但一个理性的模型，在召回 0.8 时能达到的精度，不应该低于召回 0.7 时的表现——那个低点只是采样噪声。包络把曲线变成单调不增的，去掉了噪声。

12.5 mAP 的两个层次 #

第一层：类别内平均。对每个类别算一个 AP。20 个类别就有 20 个 AP。

第二层：类别间平均。20 个 AP 取平均，就是 mAP。

text
mAP = (1/N_class) * Σ_c AP_c

所以 mAP 是「平均的平均」。这个名字容易让人误解成「平均精度的均值」而不是「平均精度」。

12.6 mAP@0.5 与 COCO 的指标 #

mAP@0.5 是 IOU 阈值取 0.5 时的 mAP。业界最常用，VOC 的标准，很多论文的主指标。

阈值 0.5 意味着框覆盖一半以上就算对。这个标准偏宽松——一个框只框住了目标的一半，也算命中。

COCO 引入了更严的评测：

指标 含义
AP IOU 从 0.5 到 0.95、步长 0.05，十个阈值取平均
AP@0.5 只用 0.5 阈值，等价于 VOC 的 mAP
AP@0.75 只用 0.75，严标准
AP_S / AP_M / AP_L 按目标面积分档：小 / 中 / 大

AP 那个十阈值平均是 COCO 的主指标，比 mAP@0.5 严格得多。同一模型，AP@0.5 会是 0.55，AP 只有 0.35。这个差距主要在定位精度上。

看论文数据时必须确认用的是哪个指标。把 COCO 的 AP 和 VOC 的 mAP@0.5 放在一张表里比，结论会完全错。

12.7 计算流程收口 #

把前面拆开的步骤连起来：

步骤 输入 操作 输出
1 所有预测框 按类别分组 每类的框列表
2 每类的框列表 按置信度降序排序 有序列表
3 有序列表 + 真值 逐个匹配，标记 TP / FP 累计 TP、FP
4 累计值 算 Precision、Recall PR 序列
5 PR 序列 做 precision 包络 单调曲线
6 单调曲线 积分（插值求和） 该类 AP
7 所有类的 AP 取算术平均 mAP

第 3 步的匹配细节决定成败。要按 IOU 阈值判、要保证一个真值框只被匹配一次、要处理多个预测框抢同一个真值框的情况（分数高的赢）。

12.8 为什么 mAP 不能只看一个数 #

mAP 是个高度压缩的指标，会掩盖很多信息。

掩盖类别不平衡。20 个类别里，如果 15 个类 AP 都在 0.8，5 个类 AP 只有 0.1，mAP 是 0.625，看起来还行。但那 5 个类基本不可用。

掩盖大小目标差异。COCO 分档报 AP_S / AP_M / AP_L 就是为此。一个模型 AP 0.40，拆开看会是 AP_L 0.6、AP_S 0.15——小目标完全不可用。

掩盖误差类型。定位错和分类错在 mAP 里无法区分。查这个得回到 9.9 那套误差分解。

阈值敏感性。mAP@0.5 高的模型不一定 mAP@0.75 也高。前者说明「框住了一半」，后者说明「框得很准」。

实践里报指标至少给三个数：AP@0.5、AP@0.75（或者 COCO 的 AP）、分档的 AP_S。

十三、易错点速查 #

13.1 概念混淆 #

IOU 阈值在不同环节含义不同。

环节 典型阈值 作用
RPN 正样本 > 0.7 判为前景
RPN 负样本 < 0.3 判为背景
RCNN 微调正样本 > 0.5 参与分类回归
RCNN 微调负样本 < 0.3 或 < 0.5 判为背景
评估命中 > 0.5 算 TP

同一个 0.5，在「划正负样本」和「评估命中」两个语境下是两件事。混着说就会出错。

mAP 和 AP 的关系。AP 是单类别，mAP 是多类别平均。说「这个模型 AP 是 0.6」时，一定要问是哪个类别。

Anchor 和 Default Box 是同一个东西。Faster R-CNN 叫 Anchor，SSD 叫 Default Box，YOLOv2 之后也叫 Anchor。结构完全一样。

13.2 实现细节的坑 #

RoI Pooling 的两次取整。候选框坐标取整一次，网格边界再取整一次。累积误差在小目标上很明显。分割任务必须用 RoI Align。

NMS 按类别做。跨类别做 NMS 会把挨在一起的狗和球干掉一个。除了类别互斥的场景（少数），都要按类别分开做。

1_ij^obj 和 1_ij^noobj 不互补。含目标的格子里，只有一个框算 obj，另一个框两个掩码都是 0，置信度损失被完全跳过。写成 1 - obj_mask 就错了。

宽高开根号要防负数。预测值会为负，sqrt 直接 NaN。要 abs + sign。

损失用 sum 不用 mean。各掩码的样本数差异大，求平均会让 λ_coord、λ_noobj 这些权重系数失去意义。

Anchor 的尺度要和数据集匹配。用 COCO 的 Anchor 跑小目标数据集，召回会崩。k-means 聚类是最省事的做法。

13.3 训练不收敛的排查顺序 #

按这个顺序查，命中率最高：

  1. 正负样本比例。打印一个 batch 里的正样本数。如果是 0，说明 Anchor 尺度和数据不匹配，或者标签分配代码有问题。
  2. 损失各项的量级。分类损失、回归损失、置信度损失分别打印。如果回归损失是分类损失的 100 倍，λ 配错了。
  3. 学习率。检测任务的学习率比分类低一个量级。从分类任务直接搬过来，前几个 epoch 就发散。
  4. 数据增强过强。Mosaic 加 CutMix 加随机裁剪，小目标会被增强操作彻底抹掉。
  5. BN 的 batch size。检测的 batch size 很小（2~8），BN 统计量不稳。改成 GroupNorm 或者冻结 BN。

13.4 指标异常的解释 #

mAP 高但实际效果差。看是不是 mAP@0.5。这个阈值宽松，框歪了也算对。

训练集 mAP 正常，测试集崩。先看类别分布。长尾数据集里，mAP 会被头部类别拉高，尾部类别全灭。

同一模型两次训练 mAP 差 2 个点。检测任务的方差本来就大。报结果要跑多次取平均，或者至少说明随机种子。

小目标 AP 接近 0。三个方向：特征图分辨率不够（加 FPN）、Anchor 尺度太大（重新聚类）、数据增强把小目标裁没了。

13.5 两条路线选择的常见误判 #

「一阶段精度一定低」。2017 年 RetinaNet 之后这句话就不成立了。现在的 YOLOv8 在 COCO 上 53.9% AP，超过大部分两阶段方法。

「两阶段一定慢」。R-FCN 和后来的 Light-Head R-CNN 把两阶段压到了接近实时的水平。慢的是 R-CNN 那一代。

「YOLO 只能做检测」。v8 之后同一套框架出分割、姿态、分类。架构上的差别在头部，主干是共用的。

「Anchor 是必须的」。YOLOX、YOLOv8 都是 anchor-free。Anchor 解决的是「框的尺度覆盖」问题，anchor-free 用「每个位置直接回归到目标边界」的思路绕开了它。

13.6 收尾 #

回头看一眼第一章那句话：两阶段先找候选再判，一阶段一次预测全部；前者准，后者快。

这句话在 2015 年是完全成立的。到 YOLOv8 的时代，前半句还成立（架构上确实还有这个区别），后半句已经松动了——一阶段的精度追上来了，两阶段的精度优势只剩下小目标和密集目标这两个特定场景。

但演进的方向没变。整个系列在做的，一直是同一件事：把两阶段的「准」想办法塞进一阶段的「快」里。多尺度塞的是小目标，Focal Loss 塞的是背景判别，动态标签分配塞的是正负样本质量，CIoU 塞的是定位精度。

理解了这个动机，再看任何一个新版本，你都能快速定位它在补哪块短板。这也是本篇想给你的东西——不是记住八个版本的改动清单，是拿到一把能拆解任何检测器的尺子。
