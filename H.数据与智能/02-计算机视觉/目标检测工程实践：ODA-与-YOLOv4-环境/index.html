本篇讲两条落地路径的完整走通过程：谷歌 Object Detection API（TensorFlow 体系）在 VOC 2012 上训练自己的模型，以及 YOLOv4（Darknet）在 Windows 下的编译与训练。

不讲的部分：目标检测算法的推导、YOLO 网络结构的逐行代码分析。原理看同目录的《深度学习目标检测：从 R-CNN 到 YOLO》，YOLO 前向传播与损失函数的代码看《YOLO 源码解析》。

落点在工程：两套工具链分别代表「配置驱动」和「代码驱动」两种范式。命令抄一遍就会，选型的判断和踩过的坑才是留下来的东西。

阅读顺序建议：先看第一章的选型表，再跳到你手上要跑的那一套。两套都要跑，就先让 ODA 的官方 demo 出框，YOLOv4 放最后，它更折腾机器。

一、两套工具链的选择 #

Object Detection API 是谷歌 2016 年开放的物体识别系统，当年在 COCO 识别挑战赛上拿了第一。它不是某一个模型，是一整套框架：模型定义、数据管线、训练循环、导出脚本，全都写好了。你在配置文件里填几行，它就能训。

YOLOv4 是另一条路。AlexeyAB 维护的 darknet 分支，C 写的，编译出 darknet.exe，一条命令推理，一条命令训练。网络结构全在 .cfg 文本里，一行一层。

两套工具链的差别，一句话就能说清：谁在描述模型。

ODA 的模型由 builders 下的 Python 函数拼出来，你用 pipeline.config 决定调哪个 builder、传什么参数。换模型＝换 model 段，换数据集＝换 input_reader 里的两条路径，换类别数＝改一个数字。全程不写代码。

YOLOv4 的模型由 .cfg 描述。想加一层，写一行；想换 anchors，改九个数字；想改类别数，得自己把三处 filters 从 255 算成 (classes+5)*3。写的是配置，但脑子里得装着网络。

text
ODA:     pipeline.config  →  train.py  →  ckpt  →  export  →  frozen_inference_graph.pb
YOLOv4:  yolov4.cfg       →  darknet.exe detector train  →  .weights

上手曲线正好相反。ODA 前半段顺：装依赖、编 protoc、跑 notebook，屏幕上就有框了。到「我要改网络」开始难受，得钻进 object_detection/core 和 meta_architectures，一层层读封装。YOLOv4 前半段卡：CMake、VS、CUDA、cuDNN、OpenCV 五样东西对齐了才出 exe。exe 一出来，后面全是命令行。

维度 Object Detection API YOLOv4（Darknet）
语言与运行时 Python + TensorFlow 图 C + CUDA，编成单个 exe
模型怎么描述 pipeline.config + builder 函数 .cfg 文本，一行一层
换数据集的成本 改两条路径 + 重建 TFRecord 改 .data 里的三行路径 + 重生成标签
换网络结构的成本 改 builder 或加 meta_architecture 直接编辑 .cfg
扩展新算子 写 Python op，进 core 写 C 层，重编
依赖体量 TF、protobuf、slim、若干 Python 包 VS、CMake、OpenCV、CUDA、cuDNN
单机多卡 配置里改 num_clones，代码支持分布式 多卡支持弱，靠多进程
部署形态 导出 pb / SavedModel，配 TF Serving 单 exe + 权重文件，可直接塞进桌面程序
排错难度 Python 栈回溯清晰，逻辑藏在包装里 C 编译错误和运行期崩，靠日志和经验
适合谁 快速验证、服务端批量、要嵌进 TF 体系 边缘设备、桌面软件、需要改结构压延迟

选型上我自己的判断标准是这样几条：

  • 手上是业务数据，只要一个能跑的检测器，先用 ODA。配置文件改完就能训，省下的时间拿去看数据质量。
  • 要压延迟、要上嵌入式、要把检测塞进已有的 C++ 桌面软件，选 YOLOv4。它的推理入口就是一个函数调用。
  • 需要改 backbone、改 loss、改后处理，选 YOLOv4。改 .cfg 和改 C 代码，比改 TensorFlow 的图构造函数直接。
  • 需要多机多卡、需要和 TF 的训练监控体系打通，选 ODA。
  • 两个都不想深挖、只想验证数据集能不能训出东西，ODA 的 samples/configs 里有现成配置，改四个数字就能开跑。

有一条现实要提前说清：ODA 那套代码是 TF1 时代写的，tf.contrib 在新版本里已经移除，tf.app.flags、tf.gfile 也换了位置。照着跑就锁版本（TF 1.12 到 1.15 这一带），或者直接上 TF2 的 Model Garden。本篇按原始代码讲，原因是它把数据管线和训练流程整个摊开在明面上，读一遍比翻文档快。

二、Object Detection API：整体流程 #

先定位代码。Object Detection 模块和 slim 挨着，都在 tensorflow/models 仓库的 research 目录下：

text
models/
    research/
        object_detection/
        slim/
        ...

object_detection 里带了一批在 COCO 上训好的模型，权重可以直接加载来用：

  • SSD + MobileNet，轻量，能在移动设备上实时跑。
  • SSD + Inception V2。
  • R-FCN + ResNet 101，基于区域的全卷积网络。
  • Faster R-CNN + ResNet 101。
  • Faster R-CNN + Inception-ResNet V2。

SSD 系列靠轻量 backbone 换速度，Faster R-CNN 系列吃算力换精度。这条取舍线在后面选模型时还会反复用到。

COCO 是这批权重的来源。微软发布，图像主要从复杂日常场景里截取，目标位置用精确的分割标注定下来，共 91 类。分两批放出：

版本 训练集 验证集 测试集
2014 82783 40504 40775
2015 165482 81208 81434

模型库在 research/object_detection/g3doc/detection_model_zoo.md，每个压缩包里有两样东西：

  • model.ckpt.*：检查点文件，存权重数据，可以接着训。
  • frozen_inference_graph.pb：冻结图，权重和计算图打包在一起，加载就能推理，不需要网络源码。

.pb 是给推理用的，.ckpt 是给微调用的。这两个文件的用途别弄混，后面导出那一步就是拿 .ckpt 生成 .pb。

整套流程固定五步，不管换什么数据集都是这五步：

text
① 标注数据 → 按脚本要求组织目录 → 跑 dataset_tools 里的脚本 → *.record
② 下载对应模型在 COCO 上的预训练权重 → 解压到工程目录
③ 从 samples/configs 挑一个匹配的 config → 改类别数、路径、步数
④ python train.py --train_dir=... --pipeline_config_path=...
⑤ python export_inference_graph.py → frozen_inference_graph.pb → 写推理脚本

第 ① 步最容易翻车，因为它同时牵扯标注格式、目录结构、编码逻辑三件事，任何一处不对，第 ④ 步都会以一句看不懂的报错收场。第四章专门讲这一步。

object_detection 下的目录按职责分，读源码前先有个地图：

路径 职责
protos/ .proto 定义，模型与训练参数的 schema
builders/ 从 proto 配置构造模型、数据集、优化器、预处理
core/ 检测原语：anchor、box coder、NMS、loss、matcher
meta_architectures/ SSD、Faster R-CNN、R-FCN 的整体组装
models/ backbone：Inception、ResNet、MobileNet 等特征提取器
utils/ 配置读取、标签映射、可视化、数据集工具
data/ 标签映射文件，如 mscoco_label_map.pbtxt
dataset_tools/ 各数据集的 TFRecord 转换脚本
samples/configs/ 各模型的 pipeline.config 模板
train.py / eval.py / export_inference_graph.py 三个入口脚本

这张表值得记一下。后面遇到「配置里这个字段是谁读的」，答案在 builders；遇到「这个 loss 怎么算的」，答案在 core；遇到「这个网络长什么样」，答案在 meta_architectures 和 models。

三、环境准备与依赖 #

ODA 用 protobuf 描述模型和训练参数，.proto 文件放在 research/object_detection/protos 下。Python 读不懂 .proto，必须先编译成 _pb2.py。

protoc 编译器从 github.com/google/protobuf/releases/tag/v2.6.1 下载，取 protoc-2.6.1-win32.zip，解压到 models/research 下。解压后 research 目录里会多出 protoc.exe。

在 models/research 下执行：

bash
protoc.exe object_detection/protos/*.proto --python_out=.

没有任何输出就是成功了。去看 object_detection/protos，里面应该多出一批 *_pb2.py。这批文件是后面所有 config_util、model_pb2、input_reader_pb2 的来源，缺一个就 ImportError。

protoc 版本要注意。2.6.1 是当年配套的版本，用 3.x 的 protoc 编老 proto 会报语法不兼容，反过来也一样。工程目录里用哪个版本，认准仓库发布时对应的那个。

编译完，还要补两个文件才能跑通自检：

  • 把 research/slim/nets 整个文件夹复制到 research 下。
  • 把 object_detection/builders/model_builder_test.py 复制到 research 下。

然后在 research 下跑：

bash
python object_detection/builders/model_builder_test.py

跑完无报错，说明 API 能用了。这一步验证的是「proto 编译产物 + backbone 代码 + builder 逻辑」三者的连通性，比直接上训练省时间。

每次跑脚本都手动把文件复制来复制去很烦。彻底一点的做法是把整个 object_detection 复制到 Anaconda 的 Lib\site-packages 下，之后 import object_detection.xxx 在任何目录都能找到。

更推荐的还是环境变量，改完只对当前终端生效，不污染全局：

bash
rem windows，在 research 目录下
set PYTHONPATH=%PYTHONPATH%;%CD%;%CD%/slim

bash
# ubuntu，在 research 目录下
export PYTHONPATH=$PYTHONPATH:${PWD}:${PWD}/slim

%CD% 是当前目录，也就是 research；%CD%/slim 补上 slim 的路径，因为 train.py 会用到 slim 里的 learning 和 model_deploy。这两个环境变量不设，训练脚本会以 ModuleNotFoundError: No module named 'slim' 结束。

依赖清单按用途排：

组件 版本 用途
Python 3.5 - 3.7 脚本运行时
TensorFlow 1.12 - 1.15 图的构造与训练
protobuf / protoc 2.6.1 编译 .proto
lxml 任意 解析 VOC 的 XML 标注
Pillow 任意 读图、校验 JPEG
matplotlib 任意 可视化结果
jupyter 任意 跑官方 notebook

GPU 这一项不是可选项。官方 notebook 和训练脚本里有若干算子只在 GPU 上注册，CPU 环境下会直接抛 module 'tensorflow' has no attribute 'data' 或者 No OpKernel registered。手边没有 N 卡，就用 3.x 的 TF2 版本重写，别硬刚 TF1 的 CPU 路径。

环境验证最短的路径是官方 notebook。在 research 下起服务：

bash
jupyter-notebook

浏览器打开 http://localhost:8888/tree，进 object_detection，点开 object_detection_tutorial.ipynb 逐格跑。这个 notebook 干的事是：下载 ssd_mobilenet_v1_coco 权重，加载 frozen_inference_graph.pb，对 test_images 下的两张图出框。

它能跑通，说明进度条、绘图、label map、pb 加载这几条链路都正常。跑不通，先看 PATH_TO_CKPT 是不是指向了实际下载的模型目录，再看 PYTHONPATH。

预训练权重放在 research 下新建的目录，比如 my_download_pretrained，一个模型一个子目录，目录名保持和压缩包一致。后面写脚本时，路径直接拼这个目录名，别自己改名。

四、TFRecord 数据格式 #

TensorFlow 的训练管线不读原始图片。它读的是一种二进制记录文件，扩展名 .record 或 .tfrecord，里面一条一条装的是 tf.train.Example。

为什么非要转一道？三个理由：

  • 图片解码是 CPU 活。转成 record 后，图片字节流直接躺在文件里，读的时候不用再翻目录、找文件、拼路径。
  • 标注和图片打包在同一条记录里，读的时候天然对齐，不会出现「图片读到了标注没读到」。
  • tf.data.TFRecordDataset 的顺序读吞吐高，配合多个 reader 和 prefetch，能把 GPU 喂饱。

代价是格式固定、不能随便改。改一个字段名，解码器就认不出来。

tf.train.Example 的结构是三层：Example 包 Features，Features 包一个字典，字典的每个 value 是 Feature。Feature 只能是三种之一：bytes_list、float_list、int64_list。

ODA 要求的字段是约定好的，不能自创：

字段名 类型 含义
image/height int64 原图高
image/width int64 原图宽
image/filename bytes 文件名
image/source_id bytes 数据来源标识
image/key/sha256 bytes 图片字节的 sha256
image/encoded bytes JPEG 原始字节流
image/format bytes 固定写 jpeg 或 png
image/object/bbox/xmin float_list 左上角 x，归一化
image/object/bbox/ymin float_list 左上角 y，归一化
image/object/bbox/xmax float_list 右下角 x，归一化
image/object/bbox/ymax float_list 右下角 y，归一化
image/object/class/text bytes_list 类别名
image/object/class/label int64_list 类别 id
image/object/difficult int64_list 是否 difficult
image/object/truncated int64_list 是否截断
image/object/view bytes_list 视角 / pose

四条硬规矩，破了哪条都跑不起来：

  • 坐标必须归一化到 [0, 1]。除以宽或高。写绝对像素值的记录，训练时 loss 会直接 nan。
  • 四个 bbox 列表长度必须等于类别列表长度，一条记录里几个目标就有几个元素。
  • image/encoded 是原始字节，不是 base64，不是路径字符串。
  • image/format 要和实际图片编码一致。声明 jpeg 但塞进 PNG 字节，解码阶段报错。

写一条记录的最小骨架长这样：

python
import tensorflow as tf
from object_detection.utils import dataset_util

example = tf.train.Example(features=tf.train.Features(feature={
    'image/height': dataset_util.int64_feature(height),
    'image/width': dataset_util.int64_feature(width),
    'image/filename': dataset_util.bytes_feature(filename.encode('utf8')),
    'image/source_id': dataset_util.bytes_feature(filename.encode('utf8')),
    'image/key/sha256': dataset_util.bytes_feature(key.encode('utf8')),
    'image/encoded': dataset_util.bytes_feature(encoded_jpg),
    'image/format': dataset_util.bytes_feature('jpeg'.encode('utf8')),
    'image/object/bbox/xmin': dataset_util.float_list_feature(xmin),
    'image/object/bbox/xmax': dataset_util.float_list_feature(xmax),
    'image/object/bbox/ymin': dataset_util.float_list_feature(ymin),
    'image/object/bbox/ymax': dataset_util.float_list_feature(ymax),
    'image/object/class/text': dataset_util.bytes_list_feature(classes_text),
    'image/object/class/label': dataset_util.int64_list_feature(classes),
    'image/object/difficult': dataset_util.int64_list_feature(difficult_obj),
    'image/object/truncated': dataset_util.int64_list_feature(truncated),
    'image/object/view': dataset_util.bytes_list_feature(poses),
}))

with tf.python_io.TFRecordWriter('pascal_train.record') as writer:
    writer.write(example.SerializeToString())

dataset_util 里那四个 helper 就是 Feature 的包装，用它们比手写 tf.train.Feature 省事，也避免类型写错。

生成的文件没有索引，也没法直接打开看。验证的办法是写个解析循环，把前几条读出来打印形状：

python
for i, raw in enumerate(tf.python_io.tf_record_iterator('pascal_train.record')):
    ex = tf.train.Example.FromString(raw)
    f = ex.features.feature
    print(f['image/height'].int64_list.value,
          f['image/width'].int64_list.value,
          len(f['image/object/class/label'].int64_list.value))
    if i > 2:
        break

打印出来的类别数和 bbox 元素数对得上，这份 record 才算能进训练。数量对不上，往下走必然报 shape 不匹配。

这一步我愿意多说一句：整个 ODA 流程里，TFRecord 环节的错误率最高。它错得安静——记录文件生成成功，退出码 0，看不出任何异常。等你在训练脚本里看到 KeyError、InvalidArgumentError、loss is nan，回头找才发现是某个字段列表长度差了一个。所以转换完先做上面的解析抽查，别跳过。

五、使用 VOC 2012 数据集 #

VOC 2012 是 VOC2007 的升级版，一共 17125 张图，每张都有标注，涵盖 20 类：人、动物（猫、狗、鸟等）、交通工具（车、船、飞机等）、家具（椅子、桌子、沙发等）。

下载地址：

text
http://host.robots.ox.ac.uk/pascal/VOC/voc2012/VOCtrainval_11-May-2012.tar

先把谷歌 models 库拉下来，删掉用不上的部分，保留 research。在 research 下新建 voc 文件夹，把 VOC2012 解压进去，得到一个 VOCdevkit 目录。

解压后的结构：

几个目录的用途拎清楚：

字段逐个看：

  • <size> 宽高，<depth> 是通道数，彩图 3。
  • <object> 一个目标一段，可以有多段。
  • <name> 类别名，必须和 pascal_label_map.pbtxt 里的 name 逐字一致。
  • <pose> 姿态，<truncated> 是否被部分遮挡，<difficult> 是否难以辨识。
  • <bndbox> 像素坐标，xmin/ymin 左上，xmax/ymax 右下。
  • <part> 是人体部位框，检测训练用不到，转换脚本也不读，忽略即可。

ImageSets 另外三部分和检测无关，顺带记一下：

  • Action：人的动作，跑、跳这类。
  • Layout：人体部位，头、手、脚。
  • Segmentation：分割用的标签图。SegmentationClass 标每个像素属于哪个类别（2913 张 png），SegmentationObject 标每个像素属于哪个具体物体（759 张 png）。

把 pascal_label_map.pbtxt 复制到 voc 下。这个文件是类别名到 id 的映射，内容是一串 item { id: 1 name: 'aeroplane' }。id 从 1 开始，0 留给背景。

从 object_detection/dataset_tools 把 create_pascal_tf_record.py 复制到 research 下。这份脚本是官方给 VOC 写好的转换器，读懂它就知道自己的数据集该怎么组织：

python
r"""Convert raw PASCAL dataset to TFRecord for object_detection."""

import hashlib
import io
import logging
import os
import sys

from lxml import etree
import PIL.Image
import tensorflow as tf

from object_detection.utils import dataset_util
from object_detection.utils import label_map_util

logging.basicConfig(format='%(asctime)s %(levelname)s %(message)s',
                    level=logging.INFO,
                    stream=sys.stdout)

flags = tf.app.flags
flags.DEFINE_string('data_dir', '', 'Root directory to raw PASCAL VOC dataset.')
flags.DEFINE_string('set', 'train', 'Convert training set, validation set or merged set.')
flags.DEFINE_string('annotations_dir', 'Annotations', '(Relative) path to annotations directory.')
flags.DEFINE_string('year', 'VOC2007', 'Desired challenge year.')
flags.DEFINE_string('output_path', '', 'Path to output TFRecord')
flags.DEFINE_string('label_map_path', 'voc/pascal_label_map.pbtxt', 'Path to label map proto')
flags.DEFINE_boolean('ignore_difficult_instances', False, 'Whether to ignore difficult instances')
FLAGS = flags.FLAGS

SETS = ['train', 'val', 'trainval', 'test']
YEARS = ['VOC2007', 'VOC2012', 'merged']


def dict_to_tf_example(data, dataset_directory, label_map_dict,
                       ignore_difficult_instances=False,
                       image_subdirectory='JPEGImages'):
  # 图片相对路径，由 folder + 子目录 + 文件名 拼出
  img_path = os.path.join(data['folder'], image_subdirectory, data['filename'])
  full_path = os.path.join(dataset_directory, img_path)
  with tf.gfile.GFile(full_path, 'rb') as fid:
    encoded_jpg = fid.read()
  encoded_jpg_io = io.BytesIO(encoded_jpg)
  image = PIL.Image.open(encoded_jpg_io)
  if image.format != 'JPEG':
    raise ValueError('Image format not JPEG')
  key = hashlib.sha256(encoded_jpg).hexdigest()

  width = int(data['size']['width'])
  height = int(data['size']['height'])

  xmin = []
  ymin = []
  xmax = []
  ymax = []
  classes = []
  classes_text = []
  truncated = []
  poses = []
  difficult_obj = []
  for obj in data['object']:
    difficult = bool(int(obj['difficult']))
    if ignore_difficult_instances and difficult:
      continue
    difficult_obj.append(int(difficult))

    # 归一化到 [0,1]
    xmin.append(float(obj['bndbox']['xmin']) / width)
    ymin.append(float(obj['bndbox']['ymin']) / height)
    xmax.append(float(obj['bndbox']['xmax']) / width)
    ymax.append(float(obj['bndbox']['ymax']) / height)

    classes_text.append(obj['name'].encode('utf8'))
    classes.append(label_map_dict[obj['name']])
    truncated.append(int(obj['truncated']))
    poses.append(obj['pose'].encode('utf8'))

  example = tf.train.Example(features=tf.train.Features(feature={
      'image/height': dataset_util.int64_feature(height),
      'image/width': dataset_util.int64_feature(width),
      'image/filename': dataset_util.bytes_feature(data['filename'].encode('utf8')),
      'image/source_id': dataset_util.bytes_feature(data['filename'].encode('utf8')),
      'image/key/sha256': dataset_util.bytes_feature(key.encode('utf8')),
      'image/encoded': dataset_util.bytes_feature(encoded_jpg),
      'image/format': dataset_util.bytes_feature('jpeg'.encode('utf8')),
      'image/object/bbox/xmin': dataset_util.float_list_feature(xmin),
      'image/object/bbox/xmax': dataset_util.float_list_feature(xmax),
      'image/object/bbox/ymin': dataset_util.float_list_feature(ymin),
      'image/object/bbox/ymax': dataset_util.float_list_feature(ymax),
      'image/object/class/text': dataset_util.bytes_list_feature(classes_text),
      'image/object/class/label': dataset_util.int64_list_feature(classes),
      'image/object/difficult': dataset_util.int64_list_feature(difficult_obj),
      'image/object/truncated': dataset_util.int64_list_feature(truncated),
      'image/object/view': dataset_util.bytes_list_feature(poses),
  }))
  return example


def main(_):
  if FLAGS.set not in SETS:
    raise ValueError('set must be in : {}'.format(SETS))
  if FLAGS.year not in YEARS:
    raise ValueError('year must be in : {}'.format(YEARS))

  data_dir = FLAGS.data_dir
  years = ['VOC2007', 'VOC2012']
  if FLAGS.year != 'merged':
    years = [FLAGS.year]

  writer = tf.python_io.TFRecordWriter(FLAGS.output_path)
  label_map_dict = label_map_util.get_label_map_dict(FLAGS.label_map_path)

  for year in years:
    logging.info('Reading from PASCAL %s dataset.', year)
    examples_path = os.path.join(data_dir, year, 'ImageSets', 'Main',
                                 'aeroplane_' + FLAGS.set + '.txt')
    annotations_dir = os.path.join(data_dir, year, FLAGS.annotations_dir)
    examples_list = dataset_util.read_examples_list(examples_path)

    for idx, example in enumerate(examples_list):
      if idx % 100 == 0:
        logging.info('On image %d of %d', idx, len(examples_list))
      path = os.path.join(annotations_dir, example + '.xml')
      with tf.gfile.GFile(path, 'r') as fid:
        xml_str = fid.read()
      xml = etree.fromstring(xml_str)
      data = dataset_util.recursive_parse_xml_to_dict(xml)['annotation']
      tf_example = dict_to_tf_example(data, FLAGS.data_dir, label_map_dict,
                                      FLAGS.ignore_difficult_instances)
      writer.write(tf_example.SerializeToString())

  writer.close()


if __name__ == '__main__':
  tf.app.run()

这段代码有三处值得盯住，自己数据出问题十有八九就在这三处。

第一处，路径拼接：

python
img_path = os.path.join(data['folder'], image_subdirectory, data['filename'])
full_path = os.path.join(dataset_directory, img_path)

data['folder'] 读的是 XML 里的 <folder>。VOC 原始数据里写的是 VOC2012，而 data_dir 传的是 voc/VOCdevkit，拼起来正好是 voc/VOCdevkit/VOC2012/JPEGImages/xxx.jpg。用 labelImg 标自己的数据时，<folder> 往往写成 JPEGImages，目录结构一变，这里就拼不出正确路径。要么改目录，要么改脚本。

第二处，examples_path：

python
examples_path = os.path.join(data_dir, year, 'ImageSets', 'Main',
                             'aeroplane_' + FLAGS.set + '.txt')

这里读的是 aeroplane_train.txt，不是 train.txt。VOC 的 Main 目录里确实有这种按类别拆分的文件，每行还带一个 1 / -1 的标记，read_examples_list 会切掉标记只留文件名。自己造数据集只生成了 train.txt，这行就必须改成：

python
examples_path = os.path.join(data_dir, year, 'ImageSets', 'Main', FLAGS.set + '.txt')

第三处，difficult 的处理。ignore_difficult_instances 默认 False，意味着会被打上 difficult=1 的目标也进训练。样本里有大量这种「必须借背景才能判断」的框，建议设为 True，让它们不参与。命令行加 --ignore_difficult_instances=True 就生效。

要换成自己的数据集，两条路：

  • 把自己的标注整理成和 VOC 一模一样的目录（Annotations、ImageSets/Main、JPEGImages 三件套），直接跑脚本。
  • 保留自己的标注格式，改 dict_to_tf_example 里的读取部分，输出还是那套字段。

第一条省事，第二条灵活。我倾向第一条，尤其数据量不大的时候，花一晚上整理目录比调脚本划算。

转换命令，在 research 下执行：

bash

python create_pascal_tf_record.py --data_dir voc/VOCdevkit --year=VOC2012 --set=val --output_path=voc/pascal_val.record

跑完 voc 下会多出 pascal_train.record 和 pascal_val.record。前者对应 5717 张，后者 5823 张。

转换完，把 voc 文件夹和 create_pascal_tf_record.py 一起挪到 object_detection 下。理由是脚本运行时 import object_detection.utils，把工程放进去就不用折腾环境变量。懒一点的做法是保留在 research 并配上 PYTHONPATH，效果一样。

六、配置文件与模型选择 #

有了 record，下一步是挑模型。这里以 Faster R-CNN + Inception-ResNet V2 为例。先在 COCO 上预训练的这个模型，下载后解压到 voc 下。

模型选型看三件事：目标尺寸、算力预算、延迟要求。

模型 backbone 速度 精度 适用
ssd_mobilenet_v1 MobileNet V1 最快 中低 移动端、实时、目标偏大
ssd_mobilenet_v2 MobileNet V2 快 中 同上，精度略好
ssd_inception_v2 Inception V2 中 中 桌面端推理
faster_rcnn_resnet101 ResNet 101 慢 高 服务端、小目标
faster_rcnn_inception_resnet_v2 Inception-ResNet V2 最慢 最高 精度优先，显存要够
rfcn_resnet101 ResNet 101 较慢 高 全卷积，共享计算

VOC 里的目标尺寸分布大，样本又不多，faster_rcnn_inception_resnet_v2 有点过重。用它讲是因为流程最典型，两阶段结构把配置文件里能改的东西全用上了。

配置文件从 object_detection/samples/configs 来。复制 faster_rcnn_inception_resnet_v2_atrous_coco.config 到 voc 下，改名为 faster_rcnn_inception_resnet_v2_atrous_voc.config。

这份 config 本质上是 TrainEvalPipelineConfig 这个 proto 的文本形式。段落对应关系：

段 对应的 proto 作用

eval_config EvalConfig 验证的样本数、评估次数
eval_input_reader InputReader 验证 record 路径与 label map

七处要改，一处都别漏。

第一处，类别数：

text

  faster_rcnn {
    num_classes: 20

VOC 是 20 类，COCO 是 90，这个数字不改，训练时分类层 shape 对不上。

第二处，验证样本数：

  num_examples: 5823
  max_evals: 10
}

num_examples 要和验证集图片数一致，pascal_val.record 里是 5823 条。写错大了会读空，小了评估不全。想知道确切数字，在转换脚本里打印 len(examples_list) 就行。

改动清单摊开看：

  • fine_tune_checkpoint 指向解压出来的 model.ckpt，不带 .index 后缀，TF 自己补。
  • from_detection_checkpoint: true 表示这是检测模型的检查点，不是分类模型。设 false 就按分类权重加载，变量名对不上，等于从头训。
  • num_steps: 200000 是总步数。原始注释里说 20 万步对 pets 数据集足够，VOC 用不着这么多，本次训练到 4 万多次就手动停了。
  • train_input_reader.input_path 和 label_map_path 换成实际路径。
  • eval_input_reader 两条同理，shuffle: false 保证每次评估顺序一致，num_readers: 1 减少显存占用。

model 段里的 image_resizer 是显存和精度的旋钮：

text
    image_resizer {
      keep_aspect_ratio_resizer {
        min_dimension: 600
        max_dimension: 1024
      }
    }

等比例缩放，缩放后最长边 1024、最短边 600。显存不够就把这两个数往下压，压到 512 和 300 能明显省显存，精度会掉。这个取舍没有标准答案，看你的卡和你的指标要求。

first_stage_anchor_generator 里的 anchor 也是可调项：

text

      grid_anchor_generator {
        scales: [0.25, 0.5, 1.0, 2.0]
        aspect_ratios: [0.5, 1.0, 2.0]
        height_stride: 8
        width_stride: 8
      }

COCO 上标的 anchor 拿到 VOC 上不一定是最好的一档。样本里目标都快占满整图，就把 scales 往上抬；目标又小又密，就往下降。改完 anchor，模型会自己重新分配 proposal。

second_stage_post_processing 里的 NMS 阈值决定最后留多少框：

text

      batch_non_max_suppression {
        score_threshold: 0.0
        iou_threshold: 0.6
        max_detections_per_class: 100
        max_total_detections: 100

      score_converter: SOFTMAX

max_total_detections: 100 意味着单张图最多出 100 个框。数量远大于实际需求时，把这个数降到 20 到 30，后处理能快一截。

bash

同样要在 GPU 下跑。CPU 下会抛 module 'tensorflow' has no attribute 'data'，这个报错和配置无关，是算子没有 CPU kernel。

训练起来之前会遇到一个 Python 3 的兼容问题：

text
ValueError: Tried to convert 't' to a tensor and failed.
Error: Argument must be a dense tensor: range(0, 3) - got shape [3], but wanted [].

原因在 research/object_detection/utils/learning_schedules.py 第 167 到 169 行，range(0, 3) 在 Python 3 里是 range 对象，TF 要的是 list。改法是把那几处的 range(...) 包一层 list(range(...))。这个坑在 TF 1.12 之后的版本里已经修了，遇到就说明版本偏老。

七、训练与监控 #

训练一启动，日志就开始刷。它会打印当前步数、各项 loss（分类、定位、总 loss）、学习率。前几百步 loss 波动大是正常的，RPN 的 proposal 还没稳。

200k 步是配置里写死的上限。全跑完的代价按模型和卡不同，faster_rcnn_inception_resnet_v2 在单张消费级卡上就是按天算。实际训练到 4 万多次就可以停，先看指标够不够，不够再继续。

手动中断不会毁掉已有成果。train_dir 里默认保留 5 个不同步数的检查点，因为 train.py 会把配置里 keep_checkpoint_every_n_hours 的规则用上，加上 TF 自己的保留策略。中断后用同一个 --train_dir 再起，会从最新的检查点续。

train_dir 里的东西：

文件 内容
pipeline.config 训练用的配置副本，自动复制进来
model.ckpt-N.* 第 N 步的检查点，四个文件一组
graph.pbtxt 计算图文本描述
events.out.tfevents.* TensorBoard 事件文件
checkpoint 最新检查点的索引

pipeline.config 被复制进 train_dir 这点很好用。几个月后回来，看这个文件就知道当时用什么配置训的，不用翻聊天记录。

监控用 TensorBoard。在日志目录的上级路径下：

bash
tensorboard --logdir ./train_dir

浏览器打开 http://127.0.0.1:6006。

能看的曲线有这些：

  • Losses/TotalLoss：总 loss，最直接的健康指标。
  • Losses/FirstStageLocalizationLoss、Losses/FirstStageObjectnessLoss：RPN 的定位和前景判别。
  • Losses/SecondStageLocalizationLoss、Losses/SecondStageClassificationLoss：第二阶段。
  • LearningRate：学习率衰减曲线。
  • ModelVars/*：各层权重的直方图。

判断训练是否走偏，看三条：

  • 总 loss 在前 1000 步快速下降，之后缓慢抖动下行，正常。
  • 总 loss 长时间不降，但其他指标在动，多半是学习率太大。
  • 总 loss 变 nan，回去查 TFRecord 里的坐标有没有超出 [0, 1]，或者标签 id 有没有超出 num_classes。

显存和内存不够是这条路上最常见的拦路虎。报错多为 ResourceExhaustedError，或者进程直接被系统杀掉。四个方向，按代价从低到高排：

  • 改 image_resizer，把 min_dimension、max_dimension 压到 300 / 512。
  • 把 train_config.batch_size 保持 1，二阶段模型的 batch 本来就难加。
  • 换小模型，ssd_mobilenet_v1 在同一张卡上能跑更大的 batch。
  • 降 first_stage_max_proposals，从 300 降到 100 甚至 50。

第一条最见效。输入尺寸从 1024 降到 512，特征图面积降到四分之一，显存占用跟着掉一大块。代价是小目标变糊，VOC 里的小目标本来就多，压得太狠指标会明显下滑。

还有一个容易忽略的点：eval 和 train 同时跑会抢显存。train.py 默认不带评估，评估要另起 eval.py，两个进程分卡或者错开跑。

几个节点名的用途：

节点 shape 含义
image_tensor:0 [1, H, W, 3] 输入，uint8，无需归一化
detection_boxes:0 [1, 100, 4] 归一化坐标 [ymin, xmin, ymax, xmax]
detection_scores:0 [1, 100] 置信度，降序
detection_classes:0 [1, 100] 类别 id，float 型，用前转 int
num_detections:0 [1] 留下的框数量

三处细节容易踩：

  • detection_boxes 的顺序是 ymin, xmin, ymax, xmax，不是 xmin, ymin, xmax, ymax。画框时如果框整体偏了 90 度，就是这个顺序。
  • detection_classes 出来是 float，直接索引 category_index 会 KeyError，先 astype(np.int32)。
  • 那张图里 np.uint0 是笔误，正常的图像数组是 np.uint8。原文照抄会报 AttributeError: module 'numpy' has no attribute 'uint0'。

跑出来的效果和官方 COCO 模型对比，一般会差一截。原因不外乎三条：

  • 训练步数不够。4 万步对 Faster R-CNN 不算多。
  • 输入被缩放了，1024 的长边压掉了小目标细节。
  • VOC 只有 20 类，样本量比 COCO 差一个数量级，17125 张对 20 万张。

这三条里第三条是根本。数据规模不够，模型结构和超参怎么调都补不回来。

def build(input_reader_config, transform_input_data_fn=None,
          batch_size=None, max_num_boxes=None, num_classes=None,
          spatial_image_shape=None):
  if not isinstance(input_reader_config, input_reader_pb2.InputReader):
    raise ValueError('input_reader_config not of type '
                     'input_reader_pb2.InputReader.')

  if input_reader_config.WhichOneof('input_reader') == 'tf_record_input_reader':
    config = input_reader_config.tf_record_input_reader
    if not config.input_path:
      raise ValueError('At least one input path must be specified in '
                       '`input_reader_config`.')

    label_map_proto_file = None
    if input_reader_config.HasField('label_map_path'):
      label_map_proto_file = input_reader_config.label_map_path
    # 初始化需要解码的字段，以及解码对应字段的 handler
    decoder = tf_example_decoder.TfExampleDecoder(
        load_instance_masks=input_reader_config.load_instance_masks,
        instance_mask_type=input_reader_config.mask_type,
        label_map_proto_file=label_map_proto_file)

    def process_fn(value):
      processed = decoder.decode(value)
      if transform_input_data_fn is not None:
        return transform_input_data_fn(processed)
      return processed

    # 从 config.input_path 读数据，process_fn 负责解码
    dataset = dataset_util.read_dataset(
        functools.partial(tf.data.TFRecordDataset, buffer_size=8 * 1000 * 1000),
        process_fn, config.input_path[:], input_reader_config)

    if batch_size:
      padding_shapes = _get_padding_shapes(dataset, max_num_boxes, num_classes,
                                           spatial_image_shape)
      dataset = dataset.apply(
          tf.contrib.data.padded_batch_and_drop_remainder(batch_size,
                                                          padding_shapes))
    return dataset

  raise ValueError('Unsupported input_reader_config.')

四步：

  • 从 input_reader_config 里取 record 路径和 label map 路径。
  • 用 TfExampleDecoder 初始化字段解码器。它按固定字段名取值，和第四章那张表一一对应。
  • tf.data.TFRecordDataset 顺序读字节，process_fn 逐条解码，按 prefetch_size 预取。
  • padded_batch_and_drop_remainder 组 batch，末尾不满一个 batch 的数据丢掉。

drop_remainder 这个行为要注意。验证集条数不是 batch_size 整数倍时，最后那几条不会被评估。

训练循环：trainer.train #

text
def train(create_tensor_dict_fn, create_model_fn, train_config, master, task,
          num_clones, worker_replicas, clone_on_cpu, ps_tasks,
          worker_job_name, is_chief, train_dir, graph_hook_fn=None):

  detection_model = create_model_fn()
  data_augmentation_options = [
      preprocessor_builder.build(step)
      for step in train_config.data_augmentation_options]

  with tf.Graph().as_default():
    deploy_config = model_deploy.DeploymentConfig(
        num_clones=num_clones, clone_on_cpu=clone_on_cpu,
        replica_id=task, num_replicas=worker_replicas,
        num_ps_tasks=ps_tasks, worker_job_name=worker_job_name)

    with tf.device(deploy_config.variables_device()):
      global_step = slim.create_global_step()

    with tf.device(deploy_config.inputs_device()):
      input_queue = create_input_queue(
          train_config.batch_size // num_clones, create_tensor_dict_fn,
          train_config.batch_queue_capacity,
          train_config.num_batch_queue_threads,
          train_config.prefetch_queue_capacity, data_augmentation_options)

    summaries = set(tf.get_collection(tf.GraphKeys.SUMMARIES))
    global_summaries = set([])

    model_fn = functools.partial(_create_losses,
                                 create_model_fn=create_model_fn,
                                 train_config=train_config)
    clones = model_deploy.create_clones(deploy_config, model_fn, [input_queue])
    first_clone_scope = clones[0].scope

    update_ops = tf.get_collection(tf.GraphKeys.UPDATE_OPS, first_clone_scope)

    with tf.device(deploy_config.optimizer_device()):
      training_optimizer, optimizer_summary_vars = optimizer_builder.build(
          train_config.optimizer)
      for var in optimizer_summary_vars:
        tf.summary.scalar(var.op.name, var, family='LearningRate')

    total_loss, grads_and_vars = model_deploy.optimize_clones(
        clones, training_optimizer, regularization_losses=regularization_losses)
    total_loss = tf.check_numerics(total_loss, 'LossTensor is inf or nan.')

    if train_config.gradient_clipping_by_norm > 0:
      with tf.name_scope('clip_grads'):
        grads_and_vars = slim.learning.clip_gradient_norms(
            grads_and_vars, train_config.gradient_clipping_by_norm)

    grad_updates = training_optimizer.apply_gradients(grads_and_vars,
                                                      global_step=global_step)
    update_ops.append(grad_updates)
    update_op = tf.group(*update_ops, name='update_barrier')
    with tf.control_dependencies([update_op]):
      train_tensor = tf.identity(total_loss, name='train_op')

按顺序读下来是五段：

  • 建数据增强算子列表。data_augmentation_options 里每一项对应一次预处理，配置里写了什么就建什么。
  • 建两个队列。队列 1 由 N 个线程各读一条记录填进去；队列 2 从队列 1 按 batch_size 取整批，供训练消费。
  • model_deploy.create_clones 按 num_clones 复制模型。单卡时就是一份。
  • 建优化器，算梯度，做裁剪，apply_gradients 落到 global_step。
  • tf.check_numerics 把 inf / nan 在这里就拦住，报出来的信息比后面崩在 loss 里清楚得多。

            train_config.num_steps if train_config.num_steps else None),
        save_summaries_secs=120, sync_optimizer=sync_optimizer, saver=saver)

fine_tune_checkpoint 的加载逻辑是这块的重点。它不加载整个检查点，而是先 restore_map 算出「目标模型里哪些变量能从检查点里找到名字匹配的」，再 get_variables_available_in_checkpoint 过滤一遍，只加载交集。找不到的变量用初始化值。这就是「换类别数还能用 COCO 预训练权重」的原因：分类头那几层的形状变了，加载不上，但 backbone 全部复用。

from_detection_checkpoint 决定 fine_tune_checkpoint_type：

  • true：按检测模型恢复，类别数可以不同，分类头重建。
  • false：按分类模型恢复，只复用 backbone，检测头全部重建。

填错这一个布尔值，效果就是「预训练白做了」。

allow_soft_placement=True 让没有 GPU kernel 的算子自动落到 CPU。这个开关建议一直开着，能省掉不少 Cannot assign a device for operation 的麻烦。

读到这里能看出 ODA 的一个特征：封装重。想改一个 loss 的权重系数，得先在配置里找到对应字段，再看 builder 怎么读它，再进 meta architecture 看它被用到哪。三层下去。这也是为什么有人宁可自己写一份检测代码。定制需求一多，封装的成本就超过收益。

ImageSets/Main 下的 train.txt（5717 条）和 val.txt（5823 条）是文件名列表，不带扩展名。这两个文件是转换脚本的输入。

转换脚本是 scripts/voc_label.py，把它放到 VOCdevkit 文件夹下：

python
import xml.etree.ElementTree as ET
import pickle
import os
from os import listdir, getcwd
from os.path import join

sets = [('2012', 'train'), ('2012', 'val'), ('2007', 'train'),
        ('2007', 'val'), ('2007', 'test')]

classes = ["aeroplane", "bicycle", "bird", "boat", "bottle", "bus", "car",
           "cat", "chair", "cow", "diningtable", "dog", "horse", "motorbike",
           "person", "pottedplant", "sheep", "sofa", "train", "tvmonitor"]


def convert(size, box):
    # box 由实际像素 (xmin, xmax, ymin, ymax) 转成归一化的 (x, y, w, h)
    dw = 1. / (size[0])          # 1/width，单位宽像素长度
    dh = 1. / (size[1])          # 1/height，单位高像素长度
    x = (box[0] + box[1]) / 2.0 - 1    # (xmin + xmax)/2 - 1
    y = (box[2] + box[3]) / 2.0 - 1    # (ymin + ymax)/2 - 1
    w = box[1] - box[0]                # box 宽所占像素数
    h = box[3] - box[2]                # box 高所占像素数
    x = x * dw                         # 归一化后的中心 x
    w = w * dw                         # 归一化后的宽
    y = y * dh                         # 归一化后的中心 y
    h = h * dh                         # 归一化后的高
    return (x, y, w, h)


def convert_annotation(year, image_id):
    # 读 xml，处理后写入 labels 下的同名 txt
    in_file = open('VOCdevkit/VOC%s/Annotations/%s.xml' % (year, image_id))
    out_file = open('VOCdevkit/VOC%s/labels/%s.txt' % (year, image_id), 'w')
    tree = ET.parse(in_file)
    root = tree.getroot()
    size = root.find('size')
    w = int(size.find('width').text)
    h = int(size.find('height').text)

    for obj in root.iter('object'):
        difficult = obj.find('difficult').text
        cls = obj.find('name').text
        if cls not in classes or int(difficult) == 1:
            continue
        cls_id = classes.index(cls)
        xmlbox = obj.find('bndbox')
        b = (float(xmlbox.find('xmin').text), float(xmlbox.find('xmax').text),
             float(xmlbox.find('ymin').text), float(xmlbox.find('ymax').text))
        bb = convert((w, h), b)
        out_file.write(str(cls_id) + " " + " ".join([str(a) for a in bb]) + '\n')


wd = getcwd()

for year, image_set in sets:
    if not os.path.exists('VOCdevkit/VOC%s/labels/' % (year)):
        os.makedirs('VOCdevkit/VOC%s/labels/' % (year))
    image_ids = open('VOCdevkit/VOC%s/ImageSets/Main/%s.txt'
                     % (year, image_set)).read().strip().split()
    list_file = open('%s_%s.txt' % (year, image_set), 'w')
    for image_id in image_ids:
        list_file.write('%s/VOCdevkit/VOC%s/JPEGImages/%s.jpg\n'
                        % (wd, year, image_id))
        convert_annotation(year, image_id)
    list_file.close()

os.system("cat 2007_train.txt 2007_val.txt 2012_train.txt 2012_val.txt > train.txt")
os.system("cat 2007_train.txt 2007_val.txt 2007_test.txt 2012_train.txt 2012_val.txt > train.all.txt")

这段脚本干四件事，逐个说清。

第一件，convert 把像素坐标换成归一化的中心点加宽高。这一步和 ODA 的 TFRecord 转换是同一个目的，但格式不同。ODA 存的是归一化的 xmin, ymin, xmax, ymax 四个值；YOLO 存的是归一化的 x_center, y_center, w, h。两种表示的换算关系自己心里要有数，写反了框会整体错位。

那两行 - 1 是历史遗留的偏移，Darknet 一直带着。它会让框往左上偏半个像素，数据量大了可以忽略，但如果自己做对齐验证，会发现差这么一点。

第二件，convert_annotation 遍历一张图的所有 <object>，跳过 difficult=1 的，把类别名换成索引，写一行 class_id x y w h。注意 difficult 的判断写的是 int(difficult) == 1，没标这个字段的 XML 会在这里抛 AttributeError。labelImg 生成的 XML 一定带这个字段，自己拼的要注意。

第三件，为每个集合生成一个清单文件，内容是图片的绝对路径，一行一张。这个文件就是 Darknet 的 train / valid 指向的东西。

第四件，os.system("cat ...") 把多个清单合并。Windows 下没有 cat，这两行必须注释掉。

所以实际用之前要改两处：

python

python

第一处只留 VOC2012 的训练和验证。第二处注释掉，Windows 上 cat 不存在，不注释就是两句 'cat' is not recognized。

这个脚本不能双击运行，也不能在 IDE 里点运行。 它用的是相对路径 VOCdevkit/VOC%s/...，当前工作目录必须是 VOCdevkit 的父目录。在 IDE 里跑，工作目录是脚本所在目录（也就是 VOCdevkit 里面），路径就变成了 VOCdevkit/VOCdevkit/...，找不到文件。

路径里一律用 /，不要用 \。反斜杠在配置文件里会被当转义符处理，G:\darknet 里的 \d、\V 都没定义，行为不可预期。这是 Darknet 在 Windows 上最容易踩的一个小坑，症状是「路径明明对，就是读不到」。

backup 是训练权重的输出目录，不用手动建，训练时会自动创建。

从 G:\darknet\data 拷一份 voc.names 到 VOCdevkit\data：

text

bus

一行一个类别名，顺序决定类别 id，从 0 开始。这个顺序必须和 voc_label.py 里 classes 列表的顺序完全一致。两个文件顺序差一个，所有标签都会错位，训练照样收敛，只是类别全错。

在 G:\darknet\VOCdevkit 下建 cfg 文件夹，拷一份 yolov4.cfg 进去，改四个地方。

第一处，classes：

text
classes=20

原来是 80（COCO），改成 20。这份 cfg 里有三处 classes=80，三处都要改。三处分别在三个 yolo 检测头前面的那个 [yolo] 段里。

第二处，filters：

text
filters=75

原来是 255。计算公式固定：

text
filters = (classes + 5) * 3 = (20 + 5) * 3 = 75

5 是 x, y, w, h, confidence，3 是每个 grid 三个 anchor。同样三处，位置在每个 [yolo] 之前紧挨着的那个 [convolutional] 里。只改最接近 yolo 的那个 [convolutional] 的 filters，前面的卷积层不动。改错位置，网络结构从那一层开始全乱。

第三处，max_batches：

text
max_batches=40000

经验公式 classes * 2000。20 类就是 40000。

第四处，steps：

text
steps=32000,36000

取 max_batches 的 80% 和 90%。学习率在这两个步数点各衰减一次。写成 0.8 倍和 0.9 倍是 Darknet 的惯例，原因是训练后段要收学习率才能压 loss。

batch 和 subdivisions 和显存直接相关：

text
batch=64
subdivisions=16

实际进网络的 batch 是 batch / subdivisions，也就是 4。显存不够就把 batch 改小（比如 32）、subdivisions 改大（比如 32），实际 batch 变成 1。这两行的乘积决定显存峰值，比值决定梯度累积的效果。

改完配置就能训。在 G:\darknet 下 shift + 右键 开 PowerShell。

没有预训练权重：

bash
./darknet.exe detector train VOCdevkit/data/voc.data VOCdevkit/cfg/yolov4.cfg

有 yolov4.conv.137 预训练权重，放到 G:\darknet 根目录：

bash
./darknet.exe detector train VOCdevkit/data/voc.data VOCdevkit/cfg/yolov4.cfg yolov4.conv.137

这两个命令的差别在最后一个参数。给了预训练权重，backbone 从已有权重起步，收敛快得多；不给就是随机初始化，从零开始，40000 步基本训不出东西。

yolov4.conv.137 这个文件是 COCO 权重里前 137 层的卷积部分，不含检测头。所以它不冲突类别数，20 类和 80 类都能用它起步。这一点和 ODA 的 fine_tune_checkpoint 逻辑一致，都是只恢复能对上的变量。

训练启动后会有两个界面：一个 Loss 曲线窗口，一个不断刷新的文本窗口。文本里每若干轮打印一次：

text
1: 1234.567890, 1234.567890 avg loss, 0.000000 rate, 1.234567 seconds, 64 images

四个数字依次是：当前 batch 的 loss、滑动平均 loss、当前学习率、本轮耗时。

没有 GPU 的机器这里会非常慢。yolov4 在 CPU 上一个 batch 要按分钟算，40000 步就是按周算，不具备可操作性。

有 GPU 的话，三五分钟内不出错就说明流程通了。常见的早期报错只有两类：

  • 文件找不到：Cannot load image、Couldn't open file。回去逐个核对 .data 里的四个路径和 train.txt 里的每行路径，特别注意 / 和 \。
  • 内存不够：Out of memory。改小 batch、改大 subdivisions 再试。

训练过程中每 100 次迭代自动存一次权重，落在 backup 目录：

text

    yolov4_last.weights
    yolov4_1000.weights
    yolov4_2000.weights
    ...

_last 是最新的一份，数字后缀是保存时的迭代次数。中途想停，Ctrl + C 直接中断，已有的权重都在，下次加 -clear 参数或不加都能续。

训练完，测试效果。把最新的权重拷到 VOCdevkit/weights 下，改个名字方便记。

再复制一份 yolov4.cfg，命名为 yolov4-test.cfg，改两行：

"""
预处理工作

@author zy
@since 2022/03/26

import os


def generate_train_and_val_txt():
    '''
    遍历 JPEGImages 下所有文件名，按 4:1 分成训练集和验证集
    并把全路径写入 train.txt、val.txt
    '''
    pwd = os.getcwd()
    source_folder = os.path.join(pwd, 'JPEGImages')
    train_text = os.path.join(pwd, 'ImageSets/Main/train.txt')
    val_test = os.path.join(pwd, 'ImageSets/Main/val.txt')

    if os.path.exists(train_text):
        os.remove(train_text)
    if os.path.exists(val_test):
        os.remove(val_test)

    with open(train_text, 'a') as train_file:
        with open(val_test, 'a') as val_file:
            count = 0
            for file_name in os.listdir(source_folder):
                file_path = os.path.join(source_folder, file_name)
                count = count + 1
                if count % 5 == 0:
                    val_file.write(file_path + '\n')
                else:
                    train_file.write(file_path + '\n')


if __name__ == '__main__':
    generate_train_and_val_txt()

count % 5 == 0 是每五张抽一张进验证集，也就是 4:1。这个划分不看分布，随机性也差（依赖 os.listdir 的顺序），样本量大时某一类会全落在训练集。样本少的时候更要注意手动检查一遍。

十一、Windows 下的坑 #

这一章单独拎出来，因为 Windows 上的问题集中在三处：编译工具链、CUDA 版本匹配、路径。前两处能把人卡一整天，第三处能耗掉一个下午。

坑一：编译工具链的组合 #

VS、CMake、OpenCV 三者的版本和工具集必须对上。对不上的表现从 configure 阶段一直延伸到运行阶段。

症状 原因 处理
No CMAKE_CXX_COMPILER could be found VS 没装 C++ 工作负载 重开 VS Installer，勾「使用 C++ 的桌面开发」
Could NOT find OpenCV OpenCV_DIR 没配或配错 配到 ...\opencv\build，不是 build\x64
链接报 cannot open file 'opencv_world455.lib' 路径含空格或中文，或工具集版本不匹配 挪到纯英文无空格路径，核对 vc15 / vc16
found version "4.5.5" 但运行缺 dll Path 里没加 bin 追加 build\x64\vc15\bin
编译过，运行报 0xc000007b 32 位 dll 混进 64 位进程 只保留 x64 目录，清掉 x86

工具集版本对应的关系：

VS 版本 工具集 OpenCV 目录
VS 2015 vc14 x64\vc14
VS 2017 / 2019 vc15 x64\vc15
VS 2022 vc16 x64\vc16

configure 输出里的 OpenCV RUNTIME: vc15 就是在告诉你用的是哪套。和 VS 版本不一致，链接阶段会报一堆 LNK2019 未解析符号。

Debug 和 Release 也不能混。darknet.exe 在 Release 目录，darknetd.dll 在 Debug 目录（带 d 后缀）。用 Release 的 exe 配 Debug 的 dll，启动就崩。统一用 Release，性能和稳定性都更好。

坑二：CUDA 与 cuDNN 版本必须严格匹配 #

这三者是一条链：显卡驱动 → CUDA → cuDNN。链条上任何一环版本不对，都表现为「编译通过、运行崩溃」，而且报错信息和真正的原因常常对不上。

环节 检查方法 不匹配的表现
驱动 vs CUDA nvidia-smi 看右上角 CUDA Version 安装程序拒绝装，或装完 nvcc -V 报版本不符
CUDA vs cuDNN 看 cuDNN 发布说明支持的 CUDA 版本 编译过，训练启动崩，cudnn 相关 symbol 找不到
cuDNN vs zlibwapi 检查 CUDA bin 下有没有 zlibwapi.dll Could not locate zlibwapi.dll
cuDNN dll 完整性 数一下 bin 下有几个 cudnn_*64_8.dll 训练中途缺某个 cudnn_*_infer64_8.dll

自己验证版本：

bash
nvidia-smi
nvcc -V

nvidia-smi 右上角显示的是驱动支持的最高 CUDA 版本，nvcc -V 显示的是实际装的 CUDA 编译器版本。后者不能超过前者。

关于 cuDNN 装哪一版，看两个地方：

  • cuDNN 的 release notes 里写明支持的 CUDA 版本区间。
  • CUDA 的版本号在 cuDNN 下载页上是按大版本分组的，10.2 和 11.x 是不同包。

装完验证 cuDNN 是否被 CUDA 找到：

text
C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v11.4\bin\cudnn64_8.dll

这个文件存在，且 cudnn_ops_infer64_8.dll、cudnn_cnn_infer64_8.dll 也在，基本就没问题。

坑三：路径里的中文与空格 #

这一条最隐蔽，因为它不报错，或者报的错指向别处。

CMake 官方明确不支持中文路径。源码放在 G:\人工智能\深度学习\36.目标检测\官方库\darknet 下，configure 阶段会失败，错误信息是乱码或者一句含糊的 The C compiler identification is unknown。

处理办法只有一条：挪到纯英文路径。本例挪到 G:\darknet。

挪完必须重做三件事：

  • 系统 Path 里那条 darknet 路径跟着改。
  • 删掉旧的 CMakeCache.txt。这个文件里缓存的是绝对路径，挪了目录还留着它，configure 会继续按老路径找。
  • 重新 configure 一遍，不要直接 Generate。

空格是另一类问题。E:\Program Files\opencv 这个路径里有空格，CMake 能处理，但部分 VS 工程文件里的路径引号会出问题，链接阶段报找不到 lib。装 OpenCV 时如果条件允许，装到 E:\opencv 这种无空格路径能省掉一批麻烦。

还有一类是配置文件里的路径分隔符。前面提过，.data 里必须用 /。train.txt 里的路径也要用 /：

text
G:/darknet/VOCdevkit/VOC2012/JPEGImages/2007_000027.jpg

用 \ 会怎么样？\d、\V、\2 这些在字符串处理时被吃掉，路径变成 G:darknetOCdevkit...，然后报 Cannot load image。这个报错看起来像图片本身有问题，实际是路径被吃了。

其他零碎 #

几个不成体系但会撞上的：

  • 摄像头打不开，先检查 Windows 设置里的相机权限。隐私设置里应用访问相机的开关是关的，demo 子命令会直接崩。
  • demo 子命令没 GPU 时卡成幻灯片，这是预期行为，不是 bug。
  • darknet.exe 从别的目录调用时找不到 cfg 里的相对路径，一定在 G:\darknet 根目录下执行，或者所有路径都写绝对路径。
  • 训练中断后重启，会从 backup 目录里最新的权重继续，但学习率调度是从第 0 步重新算的。想精确续训，用 -clear 之外的方式指定起始步数，效果有限。
  • 显存不足的报错有时是 CUDA error: out of memory，有时是进程直接消失。看 Windows 事件查看器比看控制台有用。

跨平台 三平台一致 Windows 额外要处理一堆工具链问题
定制网络 写 Python builder，改配置文件 schema 直接编辑 .cfg，一行一层
定制算子 写 TF op，重新编译 写 C 函数，重新编译
文档质量 官方文档偏老，示例在 g3doc 里 单一 README 很长，覆盖面广
配套工具 TF 全家桶，TensorBoard、TF Serving 直接可用 独立，靠社区脚本

两种范式各自的成本曲线，画出来不一样。

ODA 的成本集中在前段：环境、protoc、TFRecord。这三样过去了，改配置就能训新数据，边际成本很低。想改网络结构，成本陡然上升，因为要穿过 builder、core、meta_architectures 三层封装。也就是说，它把「常见需求」做成了配置，把「非常见需求」留给了读源码的人。

YOLOv4 的成本集中在前段也集中在中段：编译一次很痛，但只痛一次；每次改 .cfg 都很轻，但每次都要自己算 filters、数 yolo 头的个数。它没有隐藏任何东西，代价是你要知道自己在改什么。

落到选择上，问自己三个问题。

第一个，你是要做产品还是做实验。做产品，推理侧的集成成本比训练侧重要，YOLOv4 的单 exe 形态省事。做实验，要快速换模型、换超参对比指标，ODA 的配置驱动更顺。

第二个，你的数据是不是要频繁变。数据集一天一个版本，用 YOLOv4，全部是文本文件，脚本一跑就换完；用 ODA，每次都要重建 record，17125 张图转一遍不是几秒钟的事。

第三个，你要改的东西在哪一层。只调超参、换 backbone，两边都行。要改 loss、改后处理、加新算子，YOLOv4 的 .cfg 加 C 代码路径更短。

有一条经验：先用手上最小的一份数据，两边各跑通一次。哪怕每边只用 50 张图跑 100 步，跑通之后你对「哪边卡在哪」的判断会准得多。光看对比表选型，容易被前段的痛苦和后段的顺手误导。

三条判断原则，比重查表快：

  • 报错里有 None、tensor、shape，回到数据。九成是 TFRecord 或标签格式。
  • 报错里有 dll、LNK、cuda，回到编译。九成是版本或路径。
  • 报错里有 Cannot load、Couldn't open，回到路径。先看分隔符，再看有没有中文空格。

最后一句：两套流程里，真正花时间的都不是「跑起来」这一步，是数据。TFRecord 的字段、YOLO 的 txt、.names 的顺序，全是围绕同一份图片的不同说法。把标注和目录结构一次做对，后面换框架的迁移成本会低很多。
