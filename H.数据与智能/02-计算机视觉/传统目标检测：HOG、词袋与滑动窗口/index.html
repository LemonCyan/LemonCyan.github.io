这篇讲的是深度学习接管目标检测之前，那套手工作业怎么跑：HOG 特征配 SVM、词袋模型配 SVM、滑动窗口把整张图扫一遍、IOU 和 NMS 收尾。读完你会明白，为什么当年一张图要跑几万个窗口，以及深度网络到底替我们省掉了哪部分活。

不讲什么：不推导 SVM 的对偶问题，不铺开卷积网络的结构细节，也不逐行贴 YOLO 源码。这几块在同目录的《深度学习目标检测原理》和《YOLO 源码解析》里各有专篇。

演进线先摆在这里：滑动窗口穷举所有位置和尺度，接着用候选区域粗筛出几百个像样的框，最后交给深度网络端到端出结果。这条线是全文的主轴，后面每一章都在给它补细节。

一、目标检测要回答两个问题 #

目标检测拆开就两件事。

第一件：图里有没有要找的东西。第二件：它在哪，多大。

前一个是分类，后一个是定位。检测就是把这两件事捆起来，对图里的每个位置都问一遍。

1、传统做法的骨架 #

深度网络出现之前，检测系统的骨架长这样：

text
对每一个候选窗口：
    1. 抠出窗口里的像素，缩放到固定尺寸
    2. 手工设计的算子提特征（HOG / SIFT / 词袋直方图）
    3. 特征向量丢给分类器（SVM / 线性判别）
    4. 记下这个窗口的分数
把所有窗口的分数收拢，做 NMS，输出最终框

一句话概括：检测 = 穷举候选框 + 逐个分类。

系统并不「理解」图像。它不知道猫长什么样，只知道喂进来的那 3780 维向量落在超平面哪一侧。

2、代价有多大 #

一张 720×475 的图，检测窗口 128×64，步长 8 像素，只扫一个尺度：

text
水平方向：(720 - 64) / 8 + 1 ≈ 83 个位置
垂直方向：(475 - 128) / 8 + 1 ≈ 44 个位置
单尺度窗口数：83 × 44 ≈ 3652

再叠一层缩放因子 1.2 的图像金字塔，往下走 7 层：

text
3652 × (1 + 1/1.2² + 1/1.2⁴ + …) ≈ 3652 × 2.6 ≈ 9500 个窗口

近万个窗口，每个都要提一遍 HOG，跑一遍 SVM。提特征比分类本身贵得多——3780 维向量，每一步都是浮点运算。

这就是传统检测慢的根源。不是分类器慢，是候选框太多，而这些框里绝大部分是背景。

3、三个阶段 #

阶段 候选框怎么来 特征怎么来 分类怎么做 代表工作
滑动窗口 固定步长穷举位置和尺度 手工设计（HOG、SIFT、BOW） SVM、线性分类器 HOG+SVM、BOW+SVM
候选区域 图像分割加区域合并，粗筛出 1~2k 个框 手工特征或 CNN 特征 SVM、Softmax R-CNN、Fast R-CNN
端到端 网络自己回归，或 RPN 出候选 网络自己学 网络自己输出 YOLO、SSD、Faster R-CNN

三列的变化方向是一致的：候选框从穷举变成筛选，特征从人设计变成机器学。

深度学习的贡献不是发明了分类器，是把「提特征」这件最贵的活从人手里拿走，顺手用回归替换了穷举。

二、分类、定位、检测、分割的区别 #

这四个任务经常被混着叫，但它们输出的东西完全不同。

任务 输入 输出 回答的问题 典型标签
分类 一张图 一个类别或类别概率 图里是什么 cat
定位加分类 一张图，一个主要物体 类别加一个框 是什么，在哪 cat, (bx,by,bh,bw)
检测 一张图，任意个物体 类别加多个框 有哪些，各在哪 [(cat,box1),(dog,box2)]
分割 一张图 每个像素的类别或实例掩码 每个像素归谁 mask[H][W]

分类只给标签。定位在标签之外多给四个数。检测是定位的复数形式，框的数量不固定。分割把框换成了像素级的蒙版。

1、定位怎么塞进网络输出 #

分类网络的最后一层是 softmax，输出 4 个类别概率——行人、汽车、摩托车、背景。

要它顺带定位，就让它多输出 4 个数：bx, by, bh, bw。

坐标约定：图片左上角 (0,0)，右下角 (1,1)。(bx, by) 是框中心点，bh 和 bw 是框的高和宽，都用图片尺寸的比例表示。

一辆车在画面中间偏下，宽约占 0.4、高约占 0.3：

text
bx ≈ 0.5    # 水平居中
by ≈ 0.7    # 距顶部 0.7，也就是距底部 0.3
bh ≈ 0.3    # 高是图片高的 0.3 倍
bw ≈ 0.4    # 宽是图片宽的 0.4 倍

2、目标标签 y 的样子 #

把分类和定位拼成一个向量，8 维：

text
y = [pc, bx, by, bh, bw, c1, c2, c3]

pc 表示这个位置有没有要检测的对象，有就 1，纯背景就 0。bx, by, bh, bw 是框的位置和大小，只在 pc=1 时有意义。c1, c2, c3 表示属于哪一类，三者最多一个为 1。

图里有车，没有行人也没有摩托：

text
y = [1, 0.5, 0.7, 0.3, 0.4, 0, 1, 0]

图里什么都没有：

text
y = [0, ?, ?, ?, ?, ?, ?, ?]

问号是「不在乎」的位。既然没有对象，框放哪、属于哪类都无所谓，损失函数里这几项直接不参与计算。

3、损失函数怎么处理这些问号 #

用平方误差：

L(y^​,y)=i=1∑8​(y^​i​−yi​)2

pc = 1 时 8 项全算。pc = 0 时只算第一项：

L(y^​,y)=(y^​1​−y1​)2

工程实现里，框坐标用平方误差，pc 用逻辑回归，类别用 softmax 交叉熵。上面的平方误差是为了把结构讲清楚，不要当成标准做法照搬。

4、定位的另一种输出：特征点 #

网络不只能输出框，还能输出点。

人脸关键点：让最后一层多吐 2k 个数，也就是 k 个点的 (x, y) 坐标。取 64 个点就是 128 个数，再加一个「有没有人脸」的标志位，一共 129 个输出单元。

text
[l1x, l1y, l2x, l2y, ..., l64x, l64y, has_face]
共 64×2 + 1 = 129 个

姿态估计同理。胸口中点、左肩、左肘、腰、膝、踝一路标下去，32 个点就是 64 个数。

有一条约束必须守住：特征点 1 在所有图片里必须是同一个语义位置。特征点 1 永远是右眼外眼角，不能这张图是外眼角、下张图是鼻尖。标签不一致，网络学出来的东西就没有意义。

同样的思路落到人脸上能做表情判断，也能做 AR 滤镜——贴皇冠、扭曲脸型，都是先拿到关键点再动像素。

到这儿，分类、定位、检测三件事的关系就理清了。检测等于对图里每个位置做一次「分类加定位」。下一章讲怎么把这个「每个位置」铺满全图。

三、滑动窗口搜索 #

滑动窗口解决的是定位问题里最笨也最直接的那一半：既然不知道目标在哪，那就把每个位置都试一遍。

1、窗口怎么滑 #

固定一个 128×64 的窗口，从左到右、从上到下，按步长移动，每一步抠出一块区域交给分类器。

python
def sliding_window(img, stride, window_size):
    """img: 输入图像; stride: 步长; window_size: (w, h)"""
    for y in range(0, img.shape[0] - window_size[1], stride):
        for x in range(0, img.shape[1] - window_size[0], stride):
            yield (x, y, img[y:y + window_size[1], x:x + window_size[0]])

三个参数决定一切：窗口大小、步长、是否缩放。

步长越小，定位越细，窗口数越爆炸。步长 2 像素扫一张 720×475 的图，光一个尺度就是五万多个窗口。

2、尺度怎么办：图像金字塔 #

窗口大小固定，但目标在图上会很大也会很小。做法是把图像本身缩成不同尺寸，形成金字塔。

python
def resize(img, scale_factor):
    return cv2.resize(
        img,
        (int(img.shape[1] * (1.0 / scale_factor)),
         int(img.shape[0] * (1.0 / scale_factor))),
        interpolation=cv2.INTER_AREA)


def pyramid(img, scale=1.5, min_size=(200, 200)):
    """生成器：逐层产出缩小后的图像，直到小于 min_size"""
    yield img
    while True:
        img = resize(img, scale)
        if img.shape[0] < min_size[1] or img.shape[1] < min_size[0]:
            break
        yield img

构建金字塔的步骤：

  1. 取原图
  2. 按比例缩小
  3. 高斯平滑，抑制缩放带来的锯齿
  4. 只要还没小于最小尺寸，回到第 2 步

scale_factor 是每层之间的缩放比。设为 1.3 意味着每层缩小到上一层的 1/1.3。这个值越小，层数越多，计算越慢，定位越精确。OpenCV 的 detectMultiScale() 里这个参数一般填 1.3。

在缩小的图上找到的目标，坐标要乘回去。

python
scale = float(img.shape[1]) / float(resized.shape[1])
rx, ry = x * scale, y * scale
rx2, ry2 = (x + w) * scale, (y + h) * scale

漏了这一步，画出来的框会全部挤在左上角。

3、窗口数量估算 #

拿一张 720×475 的图，窗口 128×64，步长 8，金字塔 7 层：

层 图像尺寸（约） 窗口数（约）
1 720×475 3652
2 600×396 2500
3 500×330 1700
4 416×275 1150
5 347×229 780
6 289×191 520
7 240×159 340
合计 — 约 10600

一万多个窗口。每个都要做完整的特征提取加分类。传统方法慢，慢在这里。

4、重叠怎么处理 #

滑窗必然产生大量重叠框。同一个目标被十几个窗口同时判为正样本，这是常态，不是 bug。

处理手段是 NMS，见第十一章。

5、这套范式的三个死结 #

死结 具体表现 后来的解法
窗口太多 一张图上万个位置，每个都跑一遍分类器 候选区域（R-CNN 的 Selective Search 出 1~2k 个）、RPN
特征靠人 HOG 的参数（cell 大小、bin 数、归一化方式）全靠实验调 CNN 自己学特征
尺度与位置解耦 位置靠滑、尺度靠金字塔，两者乘起来爆炸 直接回归坐标，YOLO 把位置和类别放在一次前向里出

第二十五条素材里那句话说得准：神经网络兴起之前，人们用简单的线性分类器做检测，因为每个分类器计算成本都很低。换成卷积网络后，单个窗口的成本高得多，滑窗立刻变得不可接受。

这就是为什么 AlexNet 出来之后，检测没马上跟着起飞。分类变强了，但穷举范式还在，成本反而更高。真正的转折是 R-CNN 把候选区域的数目从一万压到两千，以及 YOLO 干脆把穷举和回归一起干掉了。

顺带说一句卷积版的滑窗共享计算：把全连接层换成卷积层，一张 16×16 的输入不用切成 4 张 14×14 分别前向，直接整张送进去，输出 2×2×4，四个角上的结果一次拿到，公共区域的计算只算一次。这是把滑窗变快的正规做法，但它不改变「位置离散、精度受限」这个根本问题，所以后来还是被回归取代了。

四、Bounding Box 怎么表示 #

框的表示法本身没什么玄机，但不同场景约定的坐标系不一样，写代码时最容易在这里翻车。

1、两种主流表示 #

中心点加宽高：(cx, cy, w, h)

左上角加右下角：(x1, y1, x2, y2)

两种表示可以互相转换：

python
# 中心点式 转 角点式
x1 = cx - w / 2
y1 = cy - h / 2
x2 = cx + w / 2
y2 = cy + h / 2

# 角点式 转 中心点式
cx = (x1 + x2) / 2
cy = (y1 + y2) / 2
w = x2 - x1
h = y2 - y1

OpenCV 的 cv2.rectangle 收 (x1, y1, x2, y2)。素材里的 HOG 检测器返回的 found 是 (x, y, w, h)。NMS 实现里用的是 (x1, y1, x2, y2, score)。同一个脚本里三种表示混着走，转换写错一位，框就飞了。

2、归一化坐标 #

网络回归坐标时，一般把数值都压到 0~1，除以图片的宽高：

bx​=Wcx​​,by​=Hcy​​,bh​=Hh​,bw​=Ww​

好处是网络学到的值与输入分辨率解耦。换一张不同尺寸的图，同一套权重照样能用。

3、网格内的相对坐标 #

YOLO 那一套更细一层：把图切成 19×19 网格，每个格子只负责中心点落在自己内部的物体。框的坐标相对格子尺寸定义。

约定格子左上角是 (0,0)，右下角是 (1,1)：

text
bx ∈ [0, 1]   # 中心点相对格子左边界的比例
by ∈ [0, 1]   # 中心点相对格子上边界的比例
bh ≥ 0        # 框高相对格子高的比例，可以大于 1
bw ≥ 0        # 框宽相对格子宽的比例，可以大于 1

bx 和 by 必须落在 0~1 之间。这是定义倒逼出来的：中心点如果不在这个格子里，这个对象就该归别的格子管。

bh 和 bw 可以超过 1。一辆车的框横跨好几个格子很正常，宽是格子宽的 1.5 倍完全合理。

参数化方式不止一种。YOLO 后续版本用 sigmoid 把 bx, by 强行压在 0~1，用指数参数化保证 bh, bw 非负。这里给的是最直白的版本，够用。

4、表示法对照 #

表示 形式 用在哪 注意点
中心点式 (cx, cy, w, h) 网络回归输出、YOLO 标签 存绝对值还是归一化要统一
角点式 (x1, y1, x2, y2) OpenCV 绘图、NMS 计算 必须保证 x2 > x1、y2 > y1
检测器输出 (x, y, w, h) HOG 的 detectMultiScale 与角点式差一个加法，最容易混
归一化 全部除以 W、H 训练标签 推理后要乘回原图尺寸

五、HOG：方向梯度直方图 #

HOG 全名 Histogram of Oriented Gradient，方向梯度直方图。它和 SIFT、SURF、ORB 属于同一类东西：特征描述子。

区别在于它不看颜色，只看梯度。统计图像局部区域的梯度方向分布，拼成向量。

1、它为什么管用 #

核心观点一句话：局部目标的外表和形状，可以被局部梯度或边缘方向的分布描述清楚，哪怕我们并不知道那条边缘具体在哪。

这背后有个朴素的观察。物体在图像上的边缘，表现为灰度剧烈变化的地方，也就是梯度大的地方。而物体的形状，就是这些边缘的走向。

所以只要统计清楚「这片区域里的梯度都朝哪些方向」，形状信息就抓住了。

HOG 对光照变化不敏感，靠的是 block 内的归一化。 光照整体变亮，梯度幅值整体放大，但方向分布不变。归一化把幅值的整体缩放消掉，剩下的方向分布就稳了。局部阴影同理。

行人的轮廓特征在 HOG 里体现得特别好。人体的竖直边缘、肩线、腿部的方向分布很有辨识度，这是 HOG+SVM 成为行人检测经典组合的原因。

2、完整计算流程 #

七步，一步不能少。

text
1. 灰度化
2. Gamma 校正（可选）
3. 计算每个像素的梯度（幅值 + 方向）
4. 划分 cell，统计每个 cell 的梯度方向直方图
5. 若干 cell 组成 block，块内串联
6. block 内做 L2 归一化
7. 所有 block 的描述子串联，得到最终特征向量

第一步：灰度化 #

HOG 是梯度算子，颜色信息用不上。转灰度减少计算量。

第二步：Gamma 校正 #

目的是降低局部阴影和光照变化的影响，同时抑制噪点。

f(I)=Iγ

I 是像素值，γ 是系数。

  • γ < 1：低灰度区动态范围变大，对比度增强；高灰度区动态范围变小，对比度降低；整体灰度值变大
  • γ > 1：低灰度区动态范围变小，对比度降低；高灰度区动态范围变大，对比度提高；整体灰度值变小

γ = 1/2.2 ≈ 0.45 把图像提亮，γ = 2.2 把图像压暗。

代码里常用开平方近似 γ = 0.5，省一次幂运算：

python
img = np.sqrt(img * 1.0 / float(np.max(img)))
img = img * 255

Gamma 校正在 HOG 里不是必须的一步。Dalal 的博士论文提到，对于类内颜色变化大的目标（猫、狗、马），不做 gamma 的 RGB 图效果更好；牛、羊这类做 gamma 后效果更好。用不用要看训练集。

第三步：算梯度 #

用中心差分：

Gx​(x,y)=I(x+1,y)−I(x−1,y)
Gy​(x,y)=I(x,y+1)−I(x,y−1)

梯度幅值和方向：

G(x,y)=Gx​(x,y)2+Gy​(x,y)2​
α=arctanGx​(x,y)Gy​(x,y)​

工程上直接用 Sobel 算子加 cartToPolar：

python
gradient_values_x = cv2.Sobel(self.img, cv2.CV_64F, 1, 0, ksize=5)
gradient_values_y = cv2.Sobel(self.img, cv2.CV_64F, 0, 1, ksize=5)
gradient_magnitude, gradient_angle = cv2.cartToPolar(
    gradient_values_x, gradient_values_y, angleInDegrees=True)
# 把大于 180° 的方向折叠回 0~180°，无符号方向才不重复计数
gradient_angle[gradient_angle > 180.0] -= 180

注意最后那一步。用 180° 无符号方向时，指向右下和指向左上算同一个方向，所以 >180° 的要折叠回来。

关于高斯平滑。 常见做法是先高斯模糊去噪再算梯度。Dalal 的实验结论相反：不做平滑效果最好。原文的说法是从 σ=0 到 σ=2，召回率从 89% 掉到 80%（10⁻⁴ FPPW）。原因是 HOG 基于边缘，平滑会削弱边缘对比度，把有用信息一起抹掉。

第四步：cell 直方图 #

把图像切成 8×8 像素的 cell。每个 cell 统计一个 9 bin 的方向直方图，把 0~180° 均分成 9 份，每份 20°。

text
bin 0: [  0°,  20°)
bin 1: [ 20°,  40°)
bin 2: [ 40°,  60°)
...
bin 8: [160°, 180°]

像素怎么投进 bin：按梯度方向找 bin，按梯度幅值加权。方向 25° 的像素，幅值是 100，就往 bin 1 里加 100。

用幅值加权，不用二值边缘。 用梯度幅值当权重效果最好，用二值边缘权值会严重掉点。道理很简单：明显的边缘该在特征里占更大分量，而 HOG 本来就靠这些边缘纹理吃饭。

双线性插值。 方向落在两个 bin 中心之间的像素，要按距离分摊到相邻两个 bin。方向 10° 正好在 bin 0（0°）和 bin 1（20°）中间，就各分一半。

python
def get_closest_bins(self, gradient_angle):
    """返回 (start_idx, end_idx, weight)，weight 是 end 占的比例"""
    idx = int(gradient_angle / self.angle_unit)   # angle_unit = 180/9 = 20
    mod = gradient_angle % self.angle_unit
    return idx % self.bin_size, (idx + 1) % self.bin_size, mod / self.angle_unit


def cell_gradient(self, cell_magnitude, cell_angle):
    orientation_centers = [0] * self.bin_size
    for i in range(cell_magnitude.shape[0]):
        for j in range(cell_magnitude.shape[1]):
            strength = cell_magnitude[i][j]
            angle = cell_angle[i][j]
            min_angle, max_angle, weight = self.get_closest_bins(angle)
            orientation_centers[min_angle] += strength * (1 - weight)
            orientation_centers[max_angle] += strength * weight
    return orientation_centers

插值也发生在位置上（相邻 cell 之间），不是只有方向。实现完整版时两个维度都要插。

为什么是 9 个 bin、0~180°。 Dalal 的实验结论：无符号方向、9 个 bin 效果最好；bin 数继续加，提升不明显。所以行人检测标配就是 9 bin、0~180°。

第五步：block 串联 #

2×2 个 cell 组成一个 block。一个 block 内 4 个 cell 的 9 维直方图串起来，得到 2×2×9 = 36 维。

block 之间要重叠。 步长取 1 个 cell，不是取整个 block。重叠看起来冗余（每个 cell 的直方图会被算进多个 block），但性能提升显著，这是 HOG 设计里的关键一步。

三种 block 结构：矩形 HOG（R-HOG）、圆形 HOG、中心环绕 HOG。Dalal 的实验表明矩形和圆形效果基本一致，环绕形差一些。

第六步：块内归一化 #

局部光照变化、前景背景对比度变化，会让梯度幅值的动态范围非常大。归一化把光照、阴影、边缘的影响压下去，特征才对它们稳健。

设 v 是未归一化的块特征向量，‖v‖_k 是 k 范数，ξ 是很小的常数（防止分母为 0）。四种方式：

方式 公式 说明
L2-norm $v \leftarrow \dfrac{v}{\sqrt{|v|_2^2 + \xi^2}}$ 行人检测默认用这个
L2-Hys 先算 L2，把 v 的最大值截到 0.2，再归一化一次 比 L2 更抗极端值
L1-norm $v \leftarrow \dfrac{v}{|v|_1 + \xi}$ 计算快，效果略差
L1-sqrt $v \leftarrow \sqrt{\dfrac{v}{|v|_1 + \xi}}$ L1 的开方版

人体检测系统里一般用 L2-norm，Dalal 的文章也验证了它在行人检测上效果最好。

第七步：拼成特征向量 #

所有 block 的描述子依次串起来，就是整张图的 HOG 特征。

3、维度怎么算 #

这是最容易算错的地方，记牢这个例子。

输入 128×64（高×宽），cell 8×8，block 2×2 个 cell，步长 1 个 cell：

text
水平方向 cell 数：64 / 8 = 8
垂直方向 cell 数：128 / 8 = 16

水平方向 block 数：(8 - 2) / 1 + 1 = 7
垂直方向 block 数：(16 - 2) / 1 + 1 = 15

单个 block 维度：2 × 2 × 9 = 36
总维度：7 × 15 × 36 = 3780

通用公式：

m=⌊blockStridex​winSizex​−blockSizex​​+1⌋
n=⌊blockStridey​winSizey​−blockSizey​​+1⌋
c=cellSizex​blockSizex​​×cellSizey​blockSizey​​×nbins
t=m×n×c

代入默认参数：m = (64-16)/8+1 = 7，n = (128-16)/8+1 = 15，c = 2×2×9 = 36，t = 7×15×36 = 3780。

OpenCV 的默认行人检测器是 3781 维，多出来的那个是 SVM 的偏置 b。分类超平面是 wx + b = 0，w 有 3780 维，加上 b 就是 3781。HOGDescriptor_getDefaultPeopleDetector() 返回的正是这 3781 个数。

python
# -*- coding: utf-8 -*-
import cv2
import numpy as np
import math
import matplotlib.pyplot as plt


class Hog_descriptor():
    """HOG 描述符实现"""

    def __init__(self, img, cell_size=8, bin_size=9):
        self.img = img
        # Gamma 校正，gamma 取 0.5
        self.img = np.sqrt(img * 1.0 / float(np.max(img)))
        self.img = self.img * 255
        self.cell_size = cell_size
        self.bin_size = bin_size
        self.angle_unit = 180 / self.bin_size   # 采用 180° 无符号方向
        assert type(self.bin_size) == int, "bin_size 必须是整数"
        assert type(self.cell_size) == int, "cell_size 必须是整数"
        assert 180 % self.bin_size == 0, "bin_size 必须整除 180"

    def extract(self):
        height, width = self.img.shape
        # 1. 计算每个像素的梯度幅值和方向
        gradient_magnitude, gradient_angle = self.global_gradient()
        gradient_magnitude = abs(gradient_magnitude)

        # 2. 每个 cell 的梯度直方图
        cell_gradient_vector = np.zeros(
            (int(height / self.cell_size), int(width / self.cell_size), self.bin_size))
        for i in range(cell_gradient_vector.shape[0]):
            for j in range(cell_gradient_vector.shape[1]):
                cell_magnitude = gradient_magnitude[
                    i * self.cell_size:(i + 1) * self.cell_size,
                    j * self.cell_size:(j + 1) * self.cell_size]
                cell_angle = gradient_angle[
                    i * self.cell_size:(i + 1) * self.cell_size,
                    j * self.cell_size:(j + 1) * self.cell_size]
                cell_gradient_vector[i][j] = self.cell_gradient(cell_magnitude, cell_angle)

        # 可视化：把每个 cell 的直方图绘成线段
        hog_image = self.render_gradient(np.zeros([height, width]), cell_gradient_vector)

        # 3. 2x2 个 cell 组成 block，块内串联并归一化
        hog_vector = []
        for i in range(cell_gradient_vector.shape[0] - 1):
            for j in range(cell_gradient_vector.shape[1] - 1):
                block_vector = []
                block_vector.extend(cell_gradient_vector[i][j])
                block_vector.extend(cell_gradient_vector[i][j + 1])
                block_vector.extend(cell_gradient_vector[i + 1][j])
                block_vector.extend(cell_gradient_vector[i + 1][j + 1])
                # L2 归一化
                mag = lambda vector: math.sqrt(sum(k ** 2 for k in vector))
                magnitude = mag(block_vector) + 1e-5
                if magnitude != 0:
                    block_vector = [e / magnitude for e in block_vector]
                hog_vector.append(block_vector)
        return np.asarray(hog_vector), hog_image

    def global_gradient(self):
        gx = cv2.Sobel(self.img, cv2.CV_64F, 1, 0, ksize=5)
        gy = cv2.Sobel(self.img, cv2.CV_64F, 0, 1, ksize=5)
        return cv2.cartToPolar(gx, gy, angleInDegrees=True)

    def cell_gradient(self, cell_magnitude, cell_angle):
        orientation_centers = [0] * self.bin_size
        for i in range(cell_magnitude.shape[0]):
            for j in range(cell_magnitude.shape[1]):
                strength = cell_magnitude[i][j]
                angle = cell_angle[i][j]
                min_angle, max_angle, weight = self.get_closest_bins(angle)
                orientation_centers[min_angle] += strength * (1 - weight)
                orientation_centers[max_angle] += strength * weight
        return orientation_centers

    def get_closest_bins(self, gradient_angle):
        idx = int(gradient_angle / self.angle_unit)
        mod = gradient_angle % self.angle_unit
        return idx % self.bin_size, (idx + 1) % self.bin_size, mod / self.angle_unit

    def render_gradient(self, image, cell_gradient):
        cell_width = self.cell_size / 2
        max_mag = np.array(cell_gradient).max()
        for x in range(cell_gradient.shape[0]):
            for y in range(cell_gradient.shape[1]):
                cell_grad = cell_gradient[x][y] / max_mag
                angle = 0
                for magnitude in cell_grad:
                    rad = math.radians(angle)
                    x1 = int(x * self.cell_size + cell_width + magnitude * cell_width * math.cos(rad))
                    y1 = int(y * self.cell_size + cell_width + magnitude * cell_width * math.sin(rad))
                    x2 = int(x * self.cell_size + cell_width - magnitude * cell_width * math.cos(rad))
                    y2 = int(y * self.cell_size + cell_width - magnitude * cell_width * math.sin(rad))
                    cv2.line(image, (y1, x1), (y2, x2), int(255 * math.sqrt(magnitude)))
                    angle += self.angle_unit
        return image

5、Dalal 的训练方法 #

不是拿正负样本一把梭，而是两阶段。

  1. 提取正负样本的 HOG 特征
  2. 用正负样本训练一个初始分类器，生成初始检测器
  3. 拿初始检测器在负样本原图上跑一遍，那些被判成目标的矩形区域，就是分类错的负样本，叫难例（hard examples）
  4. 提取难例的 HOG 特征，和第一步的特征合并，重新训练，得到最终检测器

这套二次训练能让每个窗口的误报率（FPPW，False Positives Per Window）下降约 5%。

第二遍训练专门补上「长得像目标但其实不是」的样本，分类器在难例上的边界被推得更准。这个思路后来演化成 OHEM（在线难例挖掘），在深度检测里还在用。

6、HOG 的优缺点 #

优点：

  • 核心思想是「局部外形能被梯度方向分布描述」，对几何和光学变化有不变性
  • 在密集采样的图像块上求取，特征向量里隐含了块与检测窗口的空间位置关系，天然带一点空间结构信息

缺陷：

  • 处理不了遮挡。人体姿势幅度大或物体方向变化大时，检测效果明显下降。这个问题后来靠 DPM 的可变形部件模型改善
  • 没有旋转不变性。和 SIFT 不同，HOG 不选主方向、不旋转直方图，旋转不变性只能靠不同旋转方向的训练样本硬撑
  • 没有尺度不变性。尺度不变性靠缩放检测窗口来凑
  • 对噪点敏感。梯度算子的固有性质，实际工程里在划分 block 和 cell 之后有时会补一次高斯平滑

六、HOG + SVM 检测流程 #

把 HOG 用到检测上，要过三道关：尺度、位置、重叠。

1、两个绕不过去的问题 #

尺度。 目标在图上会占大半幅，也会只占一角。同一个 HOG 特征向量，描述的是固定大小的窗口（128×64）。目标变大变小，梯度结构就变了，同一个超平面判不动。

位置。 目标会出现在任何地方。必须把图像每个位置都扫一遍，拿到那个「刚好框住目标」的窗口。

两个问题各自解法都简单，叠在一起就是成本的乘法。

2、完整流程 #

text
训练阶段：
  1. 收集正样本（有目标的 128×64 裁片）
  2. 收集负样本（没有目标的图片）
  3. 逐张提取 HOG，得到 3780 维向量
  4. 送进线性 SVM 训练，得到 3780 维 w 和标量 b
  5. （可选）难例挖掘，重训一遍
  6. 保存检测器（3781 个数）

推理阶段：
  1. 构建图像金字塔，得到多尺度图像
  2. 每层图上滑动窗口，逐个抠出 128×64 区域
  3. 每个窗口提取 HOG，得到 3780 维
  4. 与 w 做内积加 b，得到分数
  5. 分数过阈值的窗口记为检出，坐标乘 scale 还原
  6. 所有尺度的检出框汇总，做 NMS
  7. 输出最终框

参数 含义 约束

blockSize 块大小 一般是 cellSize 的整数倍

5、训练侧的关键约束 #

正负样本图像的大小必须统一，默认 128×64。原因很直接：SVM 要的是一个固定长度的向量，而 HOG 特征维度由窗口尺寸决定。样本尺寸不一致，维度就对不上，train 直接报错。

推理时窗口可以在任意大小的图上滑，因为每次抠出来的都是 128×64。目标尺寸和窗口尺寸不匹配，靠金字塔缩放来对齐。

这就是传统检测里那句「特征决定窗口，窗口决定样本」的意思。改一个参数，整条链都要跟着动。

七、词袋模型 BOW #

HOG 是密集采样：把整张图切成格子，每格都算梯度。它假设目标是这个窗口的主导内容，背景别太乱。

词袋模型走的是另一条路：先在图上找「有意思的点」，再统计这些点各属于哪一类「视觉词汇」。

1、从文本搬过来的概念 #

Bag-Of-Words 最早出现在 NLP 和信息检索领域。

它的做法是扔掉语法和语序，把一个文档当成一堆词的集合。

示例，三个文档：

text
文档1：I like OpenCV and I like Python
文档2：I like C++ and Python
文档3：I don't like artichokes

建一个字典，共 8 项：

python
dic = {1: 'I', 2: 'like', 3: 'OpenCV', 4: 'and',
       5: 'Python', 6: 'C++', 7: "don't", 8: 'artichokes'}

每个文档用 8 维向量表示，每一维是该词出现的次数：

text
文档1: [2, 2, 1, 1, 1, 0, 0, 0]
文档2: [1, 1, 0, 1, 1, 1, 0, 0]
文档3: [1, 1, 0, 0, 0, 0, 1, 1]

这三个向量就是三个文档的「直方图表示」，可以直接拿去训练分类器。垃圾邮件过滤早期就是这么干的。

语序丢了，但词频留下了。对分类任务来说，这个信息量往往够用。

2、搬到图像上 #

类比很清楚：文档对图像，词对特征，词频对特征出现次数。

三个步骤：

text
1. 特征提取：对每张图检测特征点，算描述子（SIFT / SURF）
2. 学习词袋：把所有描述子汇总，K-means 聚成 k 类，每一类的中心就是一个「视觉单词」
3. 量化图像：每张图的每个描述子，投给最近的视觉单词，统计各单词出现次数，
             得到 k 维直方图向量

得到的 k 维向量就是这张图的「词袋特征」，扔给 SVM 就能分类。

和 HOG 的差别在哪：

对比项 HOG BOW
采样方式 密集，每个 cell 都算 稀疏，只在关键点处算
基础描述子 梯度方向直方图 SIFT（128 维梯度描述子）
特征长度 由窗口尺寸和参数决定（128×64 → 3780） 由聚类数 k 决定（k=40 → 40）
是否含空间信息 有，块的位置固定 没有，词序和位置都丢了
对背景的敏感度 高，背景也进特征 低，关键点少
训练样本量 几百到几千 越多越好，k 越大需要的越多

词袋的向量短得多。k=40 就是 40 维，比 3780 维省太多了。代价是丢了空间结构。

3、一个可视化的例子 #

假设三个目标类：人脸、自行车、吉他。

第一步，从每类图像里提取相互独立的视觉词汇，用 SIFT。

观察会发现，同一类的不同实例虽然各有差异，但总能找到共同的部分。人脸差异很大，但眼睛、嘴、鼻子这些细小部位的结构相当稳定。把这些跨实例共享的局部结构提出来，就是这一类的视觉词汇。

第二步，把三类图像的视觉词汇全部汇到一起。

第三步，用 K-means 构造词汇字典。

K-means 是基于样本间相似性度量的聚类方法，参数 k，把 n 个对象分成 k 个簇，簇内相似度高，簇间相似度低。SIFT 描述子按距离远近聚类，词义相近的合并成一类。假设 k=4，字典就有 4 个词。

第四步，用字典里的词表示图像。

一张图提了很多特征点，每个点都能用字典里最近的那个词近似替代。统计每个词在图中出现的次数，得到 k=4 维向量。

假定存在误差（实际情况也是如此），三类的直方图大致是：

text
人脸：  [3,  30, 3,  20]
自行车：[20, 3,  3,  2]
吉他：  [8,  12, 32, 7]

对应的字典：

python
dic = {1: '自行车', 2: '人脸', 3: '吉他', 4: '人脸类'}

人脸的向量在第 2 维和第 4 维上数值大，自行车的在第 1 维上大，吉他的在第 3 维上大。三个类在这个 4 维空间里分得开，分类器就好做。

这里 k=4 只为讲清楚原理。实际应用中 k 往往在几百到上千，目标类越多，k 越大。

4、词袋的三个设计选择 #

选择 选项 影响
关键点检测器 SIFT、SURF、ORB、密集采样 决定哪些位置参与统计
描述子 SIFT 128 维、SURF 64 维 决定单词的原始形态
聚类数 k 几十到几千 太大过拟合且慢，太小分辨力不够

k 怎么定？没有公式，靠试。素材里两个例子一个用 k=40（猫狗二分类），一个用 k=1000（人脸多分类）。样本量越大、类别越多，k 就该越大。

5、和 HOG 互补的地方 #

HOG 抓的是整体的形状轮廓，BOW 抓的是局部纹理片段的统计分布。

拿猫狗分类举例。HOG 看的是猫耳朵尖、狗嘴长的整体轮廓差异；BOW 看的是「毛茸茸的耳朵纹理出现了几次」这类局部模式。

两者都能配 SVM，都能塞进滑动窗口框架。区别只在于窗口里抠出来的那一小块，喂给什么算子。

八、SIFT 聚类与视觉词典 #

这一章拆开讲词袋里最关键的中间环节：描述子怎么变成词典。

1、SIFT 描述子长什么样 #

SIFT 对每个关键点输出一个 128 维向量。

构造过程：取关键点周围 16×16 的邻域，划成 4×4 个子区域，每个子区域统计 8 个方向的梯度直方图，4×4×8 = 128。

这个向量的性质：对旋转、尺度、亮度变化都有一定不变性。所以同一个物体在不同照片里拍出来，描述子差得不会太离谱。

这正是聚类能工作的前提。如果同一个视觉部件在不同图里的描述子满天飞，K-means 聚出来的簇就没有意义。

2、关键点检测 #

OpenCV 里 SIFT 一个对象同时管提取和描述：

python
self.feature_detector = cv2.xfeatures2d.SIFT_create()
self.descriptor_extractor = cv2.xfeatures2d.SIFT_create()

im = cv2.imread(img_path, 0)          # 灰度读入
keypoints = self.feature_detector.detect(im)
descriptors = self.descriptor_extractor.compute(im, keypoints)[1]

descriptors 的形状是 (关键点数, 128)。一张纹理丰富的图能提几百到几千个点。

空图的坑。 一张纯色图或者低对比度的图，SIFT 检测不到任何关键点，detect 返回空列表，compute 会返回 None。直接塞进 K-means 训练器会崩。素材里的多分类版本加了判断：

python
keypoints = self.feature_detector.detect(im)
if keypoints:
    return self.descriptor_extractor.compute(im, keypoints)[1]
else:
    return None

调用侧也要判断：

python
descriptor = self.sift_descriptor_extractor(files[j][i])
if descriptor is not None:
    bow_kmeans_trainer.add(descriptor)

数据集里只要有一张纯白图，不做判断就会在训练到一半时崩掉。

3、K-means 聚出词典 #

把所有图的描述子堆在一起，得到一个 (总关键点数, 128) 的大矩阵，然后聚类。

OpenCV 的 BOWKMeansTrainer 封装了这套流程：

python
# 参数 k 就是词典大小
bow_kmeans_trainer = cv2.BOWKMeansTrainer(k)

# 逐张添加描述子
for i in range(length):
    bow_kmeans_trainer.add(sift_descriptor_extractor(path(pos, i)))
    bow_kmeans_trainer.add(sift_descriptor_extractor(path(neg, i)))

# 聚类，返回聚类中心
voc = bow_kmeans_trainer.cluster()
print(type(voc), voc.shape)   # <class 'numpy.ndarray'> (40, 128)

voc 的形状是 (k, 128)。k=40 就是 40 个 128 维的中心点，这就是词典。每一行是一个视觉单词。

4、词典构建的四个要点 #

第一，参与聚类的样本数和训练分类器的样本数不是一回事。

素材里猫狗实验的做法：用 10 对样本（10 张狗 + 10 张猫）建词典，用 400 对样本训练 SVM。词典只要几百个描述子就能聚出个像样的结果，不需要全量数据。

人脸检测那个项目规模更大：5000 对样本建词典，k=1000。

第二，K-means 的 k 和样本量要匹配。

100 个描述子聚 1000 类，结果就是每个点自成一簇，词典毫无泛化能力。经验上是每个簇至少要有几十个样本。

第三，词典一旦定下来就不能改。

SVM 的权重矩阵宽度等于 k。改了 k，或者重新聚了一次类，旧模型全部作废，必须重训。所以工程上词典要跟模型一起存。

python
def save(self, path):
    self.svm.save(path)
    f1 = os.path.join(os.path.dirname(path), 'dict.pkl')
    with open(f1, 'wb') as f:
        pickle.dump(self.voc, f)

def load(self, path):
    self.svm = cv2.ml.SVM_load(path)
    f1 = os.path.join(os.path.dirname(path), 'dict.pkl')
    with open(f1, 'rb') as f:
        voc = pickle.load(f)
        self.bow_img_descriptor_extractor.setVocabulary(voc)

svm.mat 和 dict.pkl 必须成对保存、成对加载。只加载模型不加载词典，量化出来的向量和训练时的语义完全对不上，预测结果就是随机的。

第四，聚类本身不便宜。

K-means 的复杂度大致是 O(n·k·d·iter)。n 是描述子总数，d=128，iter 是迭代轮数。几万个描述子聚 1000 类，要跑几分钟到几十分钟。

5、词典大小的权衡 #

k 向量维度 分辨力 过拟合风险 训练成本 适用场景
20 20 低，只能区分大类 低 低 快速验证
40 40 中 低 低 二分类小数据集
200 200 较高 中 中 常规多分类
1000 1000 高，能区分细粒度纹理 高 高 大数据集、人脸
5000 5000 很高 很高 很高 极少见

k 变大，向量变长，SVM 的训练和推理都变慢。而传统方法本来就慢，这条路走不远。

6、从描述子到图像向量 #

词典建好之后，一张图怎么变成 k 维向量：

text
1. 在图上检测关键点，得到 N 个位置
2. 每个位置算一个 128 维描述子
3. 对每个描述子，在词典的 k 个中心里找最近的那个（欧氏距离）
4. 统计每个中心被命中多少次，得到 k 维计数向量
5. 归一化（除以 N，或者做 L2 归一化），消除图片大小的影响

第 3 步的最近邻搜索，OpenCV 用 FLANN 加速：

python
# algorithm=1 表示 KTreeIndex，用 kd 树做最近邻
flann_params = dict(algorithm=1, tree=5)
flann = cv2.FlannBasedMatcher(flann_params, {})

bow_img_descriptor_extractor = cv2.BOWImgDescriptorExtractor(
    descriptor_extractor, flann)
bow_img_descriptor_extractor.setVocabulary(voc)

algorithm 可选 LinearIndex、KTreeIndex、KMeansIndex、CompositeIndex、AutotuneIndex。k=1000、128 维的情况下，kd 树比线性扫描快一到两个数量级。

第 5 步的归一化常常被忽略，但它有实际后果。一张图关键点多（纹理复杂），计数就整体偏大。不做归一化，分类器学到的是「图里有几万个关键点」，而不是「各类纹理的比例」。

九、BOW + SVM 检测流程 #

这一章把前面的东西串起来，先做分类，再做检测。

1、先做识别：猫狗二分类 #

数据集用 Kaggle 的 dogs-vs-cats，训练集 25000 张，一半狗（正样本），一半猫（负样本）。

三步走：

text
1. 取少量正负样本（10 对），SIFT 提特征，K-means 聚类 k=40，得到词典
2. 取更多样本（400 对），用词典量化每张图，训练 SVM
3. 100 个样本测试

完整实现：

python
# -*- coding: utf-8 -*-
'''
词袋模型 BOW + SVM 目标识别
狗返回 True，猫返回 False
'''
import numpy as np
import cv2


class BOW(object):

    def __init__(self):
        self.feature_detector = cv2.xfeatures2d.SIFT_create()
        self.descriptor_extractor = cv2.xfeatures2d.SIFT_create()

    def path(self, cls, i):
        return '%s/%s/%s.%d.jpg' % (self.train_path, cls, cls, i + 1)

    def fit(self, train_path, k):
        self.train_path = train_path

        flann_params = dict(algorithm=1, tree=5)
        flann = cv2.FlannBasedMatcher(flann_params, {})

        # k-means 训练器，k 即词典大小
        bow_kmeans_trainer = cv2.BOWKMeansTrainer(k)

        pos, neg = 'dog', 'cat'

        # 只用 10 对样本建词典
        length = 10
        for i in range(length):
            bow_kmeans_trainer.add(self.sift_descriptor_extractor(self.path(pos, i)))
            bow_kmeans_trainer.add(self.sift_descriptor_extractor(self.path(neg, i)))

        # 聚类得到词典，形状 (40, 128)
        voc = bow_kmeans_trainer.cluster()
        print(type(voc), voc.shape)

        # 用词典初始化 BOW 提取器
        self.bow_img_descriptor_extractor = cv2.BOWImgDescriptorExtractor(
            self.descriptor_extractor, flann)
        self.bow_img_descriptor_extractor.setVocabulary(voc)

        # 400 对样本训练 SVM
        traindata, trainlabels = [], []
        for i in range(400):
            traindata.extend(self.bow_descriptor_extractor(self.path(pos, i)))
            trainlabels.append(1)
            traindata.extend(self.bow_descriptor_extractor(self.path(neg, i)))
            trainlabels.append(-1)

        self.svm = cv2.ml.SVM_create()
        self.svm.train(np.array(traindata), cv2.ml.ROW_SAMPLE,
                       np.array(trainlabels))

    def predict(self, img_path):
        data = self.bow_descriptor_extractor(img_path)
        res = self.svm.predict(data)
        print(img_path, '\t', res[1][0][0])
        return res[1][0][0] == 1.0

    def sift_descriptor_extractor(self, img_path):
        im = cv2.imread(img_path, 0)
        return self.descriptor_extractor.compute(
            im, self.feature_detector.detect(im))[1]

    def bow_descriptor_extractor(self, img_path):
        im = cv2.imread(img_path, 0)
        return self.bow_img_descriptor_extractor.compute(
            im, self.feature_detector.detect(im))


if __name__ == '__main__':
    test_samples = 100
    test_results = np.zeros(test_samples, dtype=np.bool)

    train_path = './data/cat_and_dog/data/train'
    bow = BOW()
    bow.fit(train_path, 40)

    for index in range(test_samples):
        dog = './data/cat_and_dog/data/train/dog/dog.{0}.jpg'.format(index)
        dog_img = cv2.imread(dog)
        test_results[index] = bow.predict(dog)

    accuracy = np.mean(test_results.astype(dtype=np.float32))
    print('测试准确率为：', accuracy)

    font = cv2.FONT_HERSHEY_SIMPLEX
    if test_results[0]:
        cv2.putText(dog_img, 'Dog Detected', (10, 30), font, 1,
                    (0, 255, 0), 2, cv2.LINE_AA)
    cv2.imshow('dog_img', dog_img)
    cv2.waitKey(0)
    cv2.destroyAllWindows()

标签用 1 和 -1。这是 SVM 的标准约定，超平面两侧各取正负一。

预测时同时要标签和分数：

python
def predict(self, img):
    if len(img.shape) == 3:
        img = cv2.cvtColor(img, cv2.COLOR_RGB2GRAY)

    keypoints = self.feature_detector.detect(img)
    if keypoints:
        data = self.bow_img_descriptor_extractor.compute(img, keypoints)
        _, result = self.svm.predict(data)
        label = result[0][0]

        # STAT_MODEL_RAW_OUTPUT 拿原始决策值
        a, res = self.svm.predict(data, flags=cv2.ml.STAT_MODEL_RAW_OUTPUT)
        score = res[0][0]
        return label, score
    else:
        return None, None

分数越低，置信度越高。 这个反直觉的地方必须记住。STAT_MODEL_RAW_OUTPUT 返回的是决策函数值，符号表示类别，绝对值表示离超平面的距离。对正类来说值越大越自信，所以后面筛框时用 score < -1 作为条件。

3、从识别到检测 #

识别只回答「这张裁片是什么」。检测还要回答「在哪」。

做法是滑动窗口套上去：

text
1. 给定一张图，用 14×14 的窗口从左到右、从上到下扫一遍，
   每个窗口用训练好的 SVM 分类
2. 记录每个窗口的预测结果
3. 缩小图像，重复整个滑动过程
4. 一直缩到最小尺寸
5. 汇总所有检出框，做 NMS

素材里用的窗口是 72×72，步长 10，缩放因子 1.2，最小尺寸缩到原图宽度的一半。

4、完整检测主程序 #

python
import cv2
import numpy as np
import os
from detector import BOW
from pyramid import pyramid, sliding_window
from non_max_suppression import nms


def prepare_data(rootpath, samples):
    """按类别目录加载样本路径和标签"""
    files, labels = [], []
    classes = [x for x in os.listdir(rootpath)
               if os.path.isdir(os.path.join(rootpath, x))]

    for idx in range(len(classes)):
        path = os.path.join(rootpath, classes[idx])
        filelist = [os.path.join(path, x) for x in os.listdir(path)
                    if os.path.isfile(os.path.join(path, x))]
        files.append(filelist[:samples])
        labels.append([idx] * samples)

    return files, labels, classes


if __name__ == '__main__':
    # 1. 训练或加载模型
    is_training = False
    bow = BOW()
    if is_training:
        samples = 5000
        rootpath = '../data/face/train'
        files, labels, classes = prepare_data(rootpath, samples)
        bow.fit(files, labels, 1000, samples // 5)
        bow.save('./svm.mat')
    else:
        bow.load('./svm.mat')

    # 2. 测试识别准确率
    start_index, test_samples = 5000, 1000
    test_results = []
    rootpath = '../data/face/train'
    files, labels, classes = prepare_data(rootpath, 6000)

    for j in range(len(files)):
        for i in range(start_index, start_index + test_samples):
            img = cv2.imread(files[j][i])
            label, score = bow.predict(img)
            if label is None:
                continue
            test_results.append(label == labels[j][i])

    accuracy = np.mean(np.asarray(test_results, dtype=np.float32))
    print('测试准确率为：', accuracy)

    # 3. 滑动窗口检测
    w, h = 72, 72
    img = cv2.imread('./3.jpg')
    rectangles = []
    scale_factor = 1.2
    font = cv2.FONT_HERSHEY_PLAIN

    for resized in pyramid(img.copy(), scale_factor,
                           (img.shape[1] // 2, img.shape[1] // 2)):
        scale = float(img.shape[1]) / float(resized.shape[1])
        for (x, y, roi) in sliding_window(resized, 10, (w, h)):
            if roi.shape[1] != w or roi.shape[0] != h:
                continue
            try:
                label, score = bow.predict(roi)
                if label == 1 and score < -1:
                    rx, ry = x * scale, y * scale
                    rx2, ry2 = (x + w) * scale, (y + h) * scale
                    rectangles.append([rx, ry, rx2, ry2, -1.0 * score])
            except Exception:
                pass

    windows = np.array(rectangles)
    boxes = nms(windows, 0.15)

    for x, y, x2, y2, score in boxes:
        cv2.rectangle(img, (int(x), int(y)), (int(x2), int(y2)), (0, 0, 255), 1)
        cv2.putText(img, '%f' % score, (int(x), int(y)), font, 1, (0, 255, 0))

    cv2.imshow('img', img)
    cv2.waitKey(0)
    cv2.destroyAllWindows()

几个细节值得说。

score < -1 是个经验阈值，直接硬编码在代码里，只能靠看结果来调。阈值越负，检出越少越保守。

-1.0 * score 把「越小越好」翻成「越大越好」，因为 NMS 按分数降序排。

NMS 阈值 0.15 比常规的 0.5 低得多。原因是滑窗步长只有 10 像素，相邻框的 IOU 天然就高，用 0.5 抑制不掉。

try/except 包住 predict 是因为某些 ROI 提不到关键点，compute 会返回 None，后续操作崩掉。这是兜底，不是正规做法。

5、效果和它的上限 #

素材里的实验：5000 对正样本训练，1000 张测试，准确率大约 95%。

但换成一张复杂场景图做检测，结果就露馅了：

text
图里会冒出大量错误的边界框。
原因：分类器准确率只有 95%。
     滑窗产生成百上千个窗口，5% 的错误率放到这个基数上，
     就是几十上百个假阳性。

95% 在单张裁片上听着不错，扔进滑窗框架就完全不够。

缓解手段：置信度过滤。人脸的框置信度明显更高，取分数最高的几个框能救回来。但这只是把问题推给后处理，检测器的根本能力没有提升。

而且它假设了图里只有一个目标。多目标场景下，「取最高分」直接失效。

这就是词袋模型加滑窗在检测任务上的上限。分类准确率和候选框数量是一对矛盾，靠提高分类器精度解决，成本是指数级的。

6、识别和检测的区别在哪 #

维度 BOW 识别 BOW 检测
输入 一张裁好的图 一张任意尺寸的图
输出 一个类别 多个框加类别
关键点数量 几百到几千，够统计 小窗口上常提不到点，是主要失效点
计算量 一次前向 上万个窗口的前向
主要误差来源 词典分辨力、SVM 泛化 分类错误被滑窗放大

第三行是词袋做检测的硬伤。72×72 的窗口里，纹理简单的区域提不出足够的关键点，量化出来的向量几乎是空的，compute 直接返回 None。

HOG 没有这个问题，因为它密集采样，任何尺寸的窗口都有梯度可算。这也是 HOG 在检测上更主流的原因。

再看一眼总成本：72×72 窗口，步长 10，在一张 720×475 图上，单层大约 64×40 = 2560 个窗口，乘以金字塔层数，轻轻松松上万。每个窗口内部要做 SIFT 检测、描述子提取、k 近邻搜索、SVM 判别。

四步，一步都不省。

这张账单，就是深度学习要来解决的东西。

十、IOU：交并比 #

检测框和真实框差多少，得有个数字。IOU 就是这个数字。

1、定义 #

交并比（Intersection over Union）：两个框的交集面积除以并集面积。

IOU=Area(A∪B)Area(A∩B)​

取值范围 0 到 1。两个框完全不挨着是 0，完全重合是 1。

2、手算一遍 #

框 A：(x1=50, y1=50, x2=200, y2=200) 框 B：(x1=120, y1=100, x2=280, y2=250)

交集左上角取两者左上角的较大值，右下角取较小值：

text
交集的 x1 = max(50, 120)  = 120
交集的 y1 = max(50, 100)  = 100
交集的 x2 = min(200, 280) = 200
交集的 y2 = min(200, 250) = 200

交集宽高：

text
w = 200 - 120 = 80
h = 200 - 100 = 100
inter = 80 × 100 = 8000

各自面积和并集：

text
area_A = (200-50) × (200-50) = 150 × 150 = 22500
area_B = (280-120) × (250-100) = 160 × 150 = 24000
union = 22500 + 24000 - 8000 = 38500

最终：

text
IOU = 8000 / 38500 ≈ 0.208

两成都不到，说明这俩框差挺远。

3、代码实现 #

python
def iou(box_a, box_b):
    """box 格式 (x1, y1, x2, y2)"""
    x1 = max(box_a[0], box_b[0])
    y1 = max(box_a[1], box_b[1])
    x2 = min(box_a[2], box_b[2])
    y2 = min(box_a[3], box_b[3])

    # 不相交时宽高会变成负数，必须截到 0
    w = max(0.0, x2 - x1)
    h = max(0.0, y2 - y1)
    inter = w * h

    area_a = (box_a[2] - box_a[0]) * (box_a[3] - box_a[1])
    area_b = (box_b[2] - box_b[0]) * (box_b[3] - box_b[1])

    return inter / (area_a + area_b - inter)

max(0.0, ...) 那两行是必须的。两个框不相交时 x2 - x1 是负数，直接乘会得到一个假的「正面积」，IOU 就乱了。

+1 的问题：素材里的 NMS 实现用了 (x2-x1+1)*(y2-y1+1)。这是把像素当成闭区间的老习惯，对 x2 - x1 = 0 的退化框能避免除零。用不用 +1 影响不大，但同一份代码里必须统一，混着用会让 IOU 有微小偏差，卡在阈值边界上就出问题。

4、阈值怎么定 #

主流约定是 IOU ≥ 0.5 算检测正确。0.5 是人为约定的，没有理论依据。

  • 想宽松一点，可以降到 0.45
  • 想严格一点，提到 0.6 或 0.7
  • 很少见到有人把阈值设到 0.5 以下

阈值越高，对定位精度要求越严。COCO 数据集用的是 0.5 到 0.95 共 10 个阈值的平均值（mAP@[.5:.95]），就是嫌单一阈值太宽松。

5、IOU 的三种用途 #

用途 对比对象 作用
评价定位精度 预测框 vs 真实框 判对错，算 mAP
NMS 去重 预测框 vs 预测框 判哪些框该被抑制
样本分配 anchor 框 vs 真实框 判哪个 anchor 负责这个目标

三种用途的阈值互相独立。评价用 0.5，NMS 常见 0.3~0.5，样本分配会取在 0.5 和 0.4 之间划正负样本。

一个坑：IOU 对「尺度不敏感」。框 A 是 10×10 偏了 2 像素，框 B 是 500×500 偏了 20 像素，两者的 IOU 会一样。前者定位误差相对严重得多，但 IOU 看不出来。

6、IOU 的变体 #

后面研究里陆续有改进，代码里偶尔会遇到：

变体 改了什么 解决什么问题
GIOU 加上最小外接框的惩罚项 不相交时 IOU 恒为 0，没有梯度
DIOU 加上中心点距离惩罚 收敛更快
CIOU 再加长宽比一致性 框的形状也要对

传统检测里只用到原始 IOU。这几个变体属于深度学习时代的产物，放在这里只为让你看到名字时不至于懵。

十一、非极大值抑制 NMS #

检测器会在同一个目标周围吐出一堆重叠的框。NMS 负责把它们收成一个。

1、为什么必须做 #

滑窗加分类器的输出，天然是一团乱麻。

同一个目标，被十几个相邻窗口都判成正样本。每个窗口的分数略有不同，位置也略有偏移。

如果直接把这些框都画出来，输出就是一坨重叠的框，根本没法看。

NMS 的目标：每个目标只留一个框，留分数最高的那个。

2、算法步骤 #

text
输入：框集合 B（含坐标和置信度分数）、IOU 阈值 T
输出：保留的框集合 K

1. 把 B 按分数从高到低排序
2. K = 空集
3. 当 B 非空时循环：
   a. 取 B 中分数最高的框 M，加入 K
   b. 从 B 中移除 M
   c. 对 B 中剩下的每个框 X，计算 IOU(X, M)
   d. 把所有 IOU > T 的 X 从 B 中永久移除
4. 返回 K

用一句话概括：按分数排序，保留最高的，抑制与它 IOU 超过阈值的其他框，循环到处理完。

3、手算一遍 #

假设 5 个框，坐标和分数如下：

text
A: (10, 10, 100, 100)  score 0.9
B: (12, 12, 105, 105)  score 0.8
C: (200, 200, 300, 300) score 0.7
D: (14, 10, 102, 98)   score 0.6
E: (210, 205, 295, 290) score 0.5

阈值 T = 0.5。

第一轮。 最高分是 A（0.9），保留 A。算 A 与其余框的 IOU：

text
IOU(A, B): B 几乎和 A 重合 → 约 0.86  > 0.5  → 移除 B
IOU(A, C): 完全不交集       → 0         ≤ 0.5 → 保留 C
IOU(A, D): 和 A 大幅重叠    → 约 0.79  > 0.5  → 移除 D
IOU(A, E): 完全不交集       → 0         ≤ 0.5 → 保留 E

剩下 C、E。

第二轮。 最高分是 C（0.7），保留 C。算 C 与 E：

text
IOU(C, E): 两个框在右下角区域，重叠较多 → 约 0.72 > 0.5 → 移除 E

剩下空集，循环结束。

输出：A、C。 一坨重叠的框被收成两个。

把 T 调到 0.8，结果就不同：IOU(A,B)=0.86 > 0.8 仍被移除，IOU(C,E)=0.72 ≤ 0.8 保留，最后输出 A、C、E 三个框。

阈值越松，留下的框越多。这就是参数敏感的地方。

4、标准实现 #

python
import numpy as np


def nms(boxes, threshold):
    """
    boxes: 形状 [n, 5]，每行为 (x1, y1, x2, y2, score)
    threshold: IOU 阈值，超过就抑制
    """
    if len(boxes) == 0:
        return []

    x1 = boxes[:, 0]
    y1 = boxes[:, 1]
    x2 = boxes[:, 2]
    y2 = boxes[:, 3]
    scores = boxes[:, 4]

    # 每个框的面积，+1 是像素闭区间的老约定
    areas = (x2 - x1 + 1) * (y2 - y1 + 1)
    # 按分数降序排，取索引
    idxs = np.argsort(scores)[::-1]

    keep = []

    while len(idxs) > 0:
        # 当前分数最高的框，直接保留
        i = idxs[0]
        keep.append(i)

        # 计算 i 与其余框的交集范围
        xx1 = np.maximum(x1[i], x1[idxs[1:]])
        yy1 = np.maximum(y1[i], y1[idxs[1:]])
        xx2 = np.minimum(x2[i], x2[idxs[1:]])
        yy2 = np.minimum(y2[i], y2[idxs[1:]])

        # 不相交时截到 0
        w = np.maximum(0.0, xx2 - xx1 + 1)
        h = np.maximum(0.0, yy2 - yy1 + 1)
        inter = w * h

        # 交 / 并
        ovr = inter / (areas[i] + areas[idxs[1:]] - inter)

        # 只保留 IOU 小于等于阈值的框
        inds = np.where(ovr <= threshold)[0]

        # inds 是从 idxs[1:] 里挑的，所以要 +1 回到 idxs 的下标
        idxs = idxs[inds + 1]

    return boxes[keep]

idxs = idxs[inds + 1] 这一行是整段代码唯一的难点。

inds 是在 ovr 上取的索引，而 ovr 是从 idxs[1:]（不含当前框 i）算出来的。所以要 +1 才能对回 idxs 的位置。

漏了 +1，下一轮会把当前框自己当成候选，直接死循环。

np.argsort(scores)[::-1] 是降序排序的惯用写法。等价于 np.argsort(-scores)。

5、向量化的好处 #

上面这段是向量化实现，一轮循环里把当前框和所有剩余框的 IOU 一次算完，而不是写双层 for 循环。

框有几千个时，差距明显。Python 的 for 循环跑几千次乘几千次，慢到不可用。NumPy 的广播一次算完。

素材里的人脸检测项目用 nms(windows, 0.15)，windows 是几万个候选框组成的数组。这种规模不用向量化根本没戏。

6、阈值怎么选 #

阈值 效果 适用场景
0.1 ~ 0.2 抑制极强，密集场景会误删相邻目标 滑窗步长很小、重叠天然严重
0.3 ~ 0.4 常用范围 通用检测
0.5 标准值，与评价阈值对齐 大多数场景
0.7 以上 抑制很弱，重叠框留得多 目标极密集，宁可留错不可删对

素材里的人脸检测用 0.15，原因前面提过：步长 10 像素，相邻框 IOU 天然很高。用 0.5 抑制不掉，输出还是一堆叠在一起的框。

反过来，密集人群检测里用 0.15 会把挨着的两个人合成一个。这是 NMS 的固有矛盾，靠单一阈值解决不了。

7、多类别要分开做 #

如果同时检测行人、汽车、摩托三类，输出向量每个位置有 3 个类别分量。

正确做法：每个类别独立做一次 NMS。

不能把三类混在一起抑制。一个高分的汽车框，会把它附近的摩托车框按 IOU 抑制掉，哪怕它们本来就是两个不同的目标。

python
results = {}
for cls in range(num_classes):
    cls_boxes = [b for b in all_boxes if b.cls == cls]
    results[cls] = nms(cls_boxes, 0.5)

8、NMS 的替代方案 #

NMS 有两个先天问题：阈值是硬编码的，密集场景必错杀或漏杀；不可微，没法端到端训练。

后来的替代方案：

方法 思路
Soft-NMS 不直接删除，按 IOU 线性或高斯衰减分数
Weighted NMS 用 IOU 加权平均重叠框的坐标
learnable NMS 用一个小网络学去重
直接回归 YOLO 这类方法让一个格子只负责一个目标，从源头减少重叠框

传统检测时代没有这些，只有硬阈值那一种。清楚它的失效边界，比记住算法步骤更实用。

十二、传统方法的局限 #

前面把零件都拆过了，这一章算总账。

1、四个结构性缺陷 #

第一，计算成本随精度指数上升。

窗口数正比于 (1/步长)² × 金字塔层数。步长减半，窗口数翻四倍。精度提一档，成本翻几番。

一张图近万个窗口，每个窗口提一遍 HOG，这是一万次完整的特征提取。深度网络只做一次前向。

第二，特征是人设计的，泛化能力有上限。

HOG 的参数（cell 尺寸、bin 数、block 结构、归一化方式）全靠实验调。换一类目标，参数要重调，检测器要重训。

更关键的是，HOG 描述的是梯度的方向分布。猫的耳朵和狗的耳朵，在 8×8 的 cell 里统计出来的直方图会很像。人能看出差别，HOG 看不出来，因为它只保留了方向统计这一个维度。

第三，尺度问题靠金字塔硬扛。

目标尺寸从 32 像素到 400 像素，金字塔要走七八层。每层都要完整扫一遍。

而且相邻层之间的尺寸是离散的。目标正好卡在两层中间，两边都对不齐，检测分数都会掉。192×96 的目标喂进 128×64 的窗口，形变之后特征就偏了。

第四，分类错误被滑窗放大。

素材里那个例子很说明问题：分类器准确率 95%，听起来不错。但一张图有上万个窗口，5% 的错误率就是几百个假阳性。

单张裁片上的 95%，到了整图检测就完全不够用。要把假阳性压到可接受，分类准确率得往 99.9% 上走，传统特征的表达能力撑不住。

2、候选框的另一条路：anchor #

既然穷举窗口太蠢，能不能换个思路，不滑窗、直接让网络输出框？

YOLO 的做法是划网格。把图片切成 19×19 的格子，每个格子负责中心点落在自己内部的目标。

text
输入 100×100×3
输出 19×19×8   （每个格子一个 8 维向量）

8 维向量的含义：[pc, bx, by, bh, bw, c1, c2, c3]。

训练标签怎么定？看目标中心点落在哪个格子，这个格子就负责它。哪怕目标横跨好几个格子，也只归一个格子管。

text
左上格子什么都没有    → y = [0, ?, ?, ?, ?, ?, ?, ?]
绿色格子有辆车，类别 2 → y = [1, 0.4, 0.3, 0.9, 0.5, 0, 1, 0]

中心格子同时压着两辆车的一部分，那也没关系，按约定它不负责任何一辆，标签就是全问号。

推理时一次前向拿到 19×19×8 的输出，每个格子读出「有没有目标、是什么、框在哪」。

好处很实在：

  • 框的坐标是回归出来的，不受窗口步长限制，精度比滑窗高
  • 一次卷积前向，不是跑 361 次分类器，计算大量共享
  • 框的宽高比任意，不用为每种形状调窗口尺寸

anchor box 解决的是另一个问题：一个格子只能出一个目标。

行人中点和汽车中点几乎重合，落在同一个格子里，8 维向量装不下两个目标。

做法是预先定义几个不同形状的 anchor，把向量重复几份：

text
没有 anchor：
y = [pc, bx, by, bh, bw, c1, c2, c3]              8 维

两个 anchor：
y = [pc, bx, by, bh, bw, c1, c2, c3,             前 8 维配 anchor 1
     pc, bx, by, bh, bw, c1, c2, c3]             后 8 维配 anchor 2
                                                  共 16 维

整个输出从 19×19×8 变成 19×19×16，也可以看成 19×19×2×8。

分配规则：每个目标同时分配给「中心点所在的格子」和「形状 IOU 最高的那个 anchor」。

行人又高又瘦，和竖长条 anchor 的 IOU 更高，就写进前半段：

text
pc=1, bx, by, bh, bw, c1=1, c2=0, c3=0

汽车又宽又扁，和横宽 anchor 更匹配，写进后半段：

text
pc=1, bx, by, bh, bw, c1=0, c2=1, c3=0

如果那个格子里只有车，行人走开了，那么 anchor 1 那半段的 pc = 0，后面几位全是问号。

两种情况 anchor 处理不好，得靠兜底规则：

text
一个格子里有三个目标，但只有两个 anchor  → 装不下，只能丢一个
两个目标的形状都匹配同一个 anchor        → 也只能留一个

19×19 的网格下这两种情况很少见，影响有限。3×3 的网格就经常撞上，所以实际实现不会用这么粗的网格。

anchor 形状怎么选：手工定 5 到 10 个，覆盖你要检测的各类目标的长宽比。后期 YOLO 用 k-means 对训练集的框形状聚类，自动挑出最有代表性的一组。这是把「人定形状」也变成「数据定形状」。

3、所以深度学习到底解决了什么 #

回到开头那句话：传统检测 = 穷举候选框 + 逐个分类。

两个环节各有各的贵。深度学习在两个环节上都动了手。

环节 传统做法 深度做法 省下了什么
候选框 滑窗穷举加金字塔 网格回归、RPN、anchor 上万个窗口变成几千个候选或一次前向
特征 HOG、SIFT、词袋直方图，人工设计 卷积层自己学 不再需要为每类目标调参数
分类 线性 SVM 全连接层加 softmax 判别能力大幅提升
后处理 NMS 硬阈值 NMS 仍在使用，部分换成可学习版本 这块其实没被彻底替换

看第四行。NMS 到今天还在用，YOLO、Faster R-CNN、SSD 都离不开它。传统方法留下的不只是历史，还有这个至今没被完全解决的问题。

真正的转折点在于：特征提取从人手里交给了网络。HOG 只能看梯度方向，词袋只能看局部片段的词频，网络能自己找到对当前任务最有判别力的表示。

再加上候选框从穷举变成回归，成本从「上万次特征提取」降到「一次前向」。两件事合起来，检测才从离线跑批变成了实时。

4、这套东西还有用吗 #

有，但场景变了。

  • 算力受限的嵌入式设备，HOG 加线性 SVM 的资源占用远低于一个卷积网络
  • 需要可解释性的场合，HOG 的特征维度有明确物理含义（哪个 cell 的哪个方向），网络的中间层没有
  • 作为教学和调试的基线，先在 HOG 上跑通整条流水线，再换网络，能清楚看到每一步在做什么
  • 数据量极小（几百张）时，手工特征配 SVM 不一定比训练一个网络差

这些是工程判断，不是情怀。知道它什么时候够用，比知道它被淘汰了更有价值。

十三、易错点速查 #

这一章是踩坑清单，按出现频率排。

1、坐标与尺寸 #

坑 现象 正确做法
三种框格式混用 框画到画面外，或者尺寸只有一半 进入函数前统一成 (x1,y1,x2,y2)，出函数再转
(x,y,w,h) 当成 (x1,y1,x2,y2) 框宽高变成坐标值，巨大 cv2.rectangle 要的是角点，(x,y,w,h) 得先加
金字塔坐标没还原 所有框挤在左上角 每个框的四个坐标都乘 scale
归一化坐标没乘回原图 框全部小得看不见 推理后乘 W、H
x2 < x1 IOU 算成负数或者异常大 构造时保证 x2 = x1 + w，y2 = y1 + h

2、HOG 相关 #

坑 现象 正确做法
特征维度和检测器对不上 setSVMDetector 报错 3780 维特征配 3781 维检测器，多的是偏置 b
改了 HOG 参数没重训 检测结果全是垃圾 参数一改维度就变，检测器必须换
忘记折叠 >180° 的角度 方向直方图重复计数 gradient_angle[gradient_angle > 180] -= 180
训练样本尺寸不统一 svm.train 维度报错 全部裁成 128×64
加了高斯平滑 召回率反而下降 HOG 靠边缘，平滑会削弱边缘
block 步长取了整个 block 维度算错，性能也降 步长取 1 个 cell，块之间要重叠

维度公式再写一遍，改参数时手算一遍验证：

text
m = floor((win_w - block_w) / stride_w + 1)
n = floor((win_h - block_h) / stride_h + 1)
c = (block_w / cell_w) × (block_h / cell_h) × nbins
t = m × n × c

win 64×128, block 16×16, stride 8×8, cell 8×8, nbins 9
m = (64-16)/8+1 = 7
n = (128-16)/8+1 = 15
c = 2×2×9 = 36
t = 7×15×36 = 3780

3、BOW 相关 #

坑 现象 正确做法
图像提不到关键点 compute 返回 None，训练崩溃 每次调用都判 if keypoints:
词典和模型没配对保存 加载后准确率掉到随机水平 svm.mat 和 dict.pkl 成对存取
重新聚类后没重训 SVM 预测全错 词典变了，特征语义就变了
词袋向量没归一化 分类器学的是关键点总数 除以关键点数或做 L2 归一化
k 大于描述子总数 每个点自成一簇，没有泛化 每簇至少几十个样本
STAT_MODEL_RAW_OUTPUT 方向搞反 筛不出目标，或者筛出一堆噪声 分数越低置信度越高，阈值取负
小窗口做 BOW 检测 大量 None，漏检严重 检测任务优先 HOG，它密集采样

4、NMS 与 IOU #

坑 现象 正确做法
idxs = idxs[inds + 1] 漏了 +1 死循环 +1 是把 ovr 的下标对回 idxs
IOU 里的宽高没截到 0 不相交的框算出正 IOU w = max(0, x2 - x1)
面积一处加 1 一处不加 边界情况判断不一致 全文件统一，要么全加要么全不加
多类别只做一次 NMS 不同类别的相邻目标互相抑制 每个类别独立跑一遍
NMS 阈值照搬 0.5 滑窗步长小时抑制不干净 步长 10 像素这种，阈值降到 0.15
分数没转成「越大越好」 保留的全是最差的框 NMS 前排一次序，确认方向
忘了先按阈值过滤低分框 计算量暴涨，还留一堆噪声 先丢 score ≤ 阈值 的，再进 NMS

5、训练与数据 #

坑 现象 正确做法
正负样本比例失衡 分类器全判负类，准确率虚高 控制正负比例，看召回率而不是准确率
只报准确率 95% 听着好，检测全是假阳性 检测任务看精确率和召回率
没有难例挖掘 误报率卡在 5% 下不去 拿初版检测器扫负样本，回收判错的框
测试集和训练集同源 准确率虚高 按图像来源切分，不按裁片切分
分类器效果不错就上检测 整图效果断崖式下跌 分类准确率乘上候选框数量，才算真实假阳性数

6、一页总结 #

text
传统目标检测 = 穷举候选框 + 逐个分类

候选框：滑动窗口扫位置，图像金字塔扫尺度
特征：  HOG 统计局部梯度方向分布，归一化后抗光照
        BOW 把 SIFT 描述子聚成词典，统计词频
分类：  SVM，HOG 用线性核，BOW 多分类用 RBF 核
收尾：  IOU 衡量重叠，NMS 按分数排序后抑制高重叠框

贵在哪：窗口数以万计，每个都要完整提特征
好特征：写死在人的先验里，换目标就得重调
出路：  候选框从穷举换成回归，特征从人设计换成网络自己学

传统检测这套流程，零件不多，但每个零件的位置都很清楚。把 HOG 的 3780 维、滑窗的窗口数、NMS 的抑制逻辑这三件事吃透，再去看深度学习检测的论文，你会认出里面每一个模块都在替代前面哪一块。
