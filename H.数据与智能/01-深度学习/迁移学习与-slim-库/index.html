一、为什么不该从头训练 #

从零初始化一个卷积网络，等于让几百万到上亿个参数从随机噪声出发，一步步拟合出「猫耳朵长什么样」这件事。算力和数据两头都咬人。

先看算力。VGG16 在 ImageNet 上训练，2014 年的原始配置是四张卡跑两到三周。ResNet50 好一些，八张 P100 也要几天。你自己一张消费级显卡，跑完一轮完整 ImageNet 按月算，还不算调参的轮次。

再看数据。假设任务是分五种花，训练集三千三百二十张，验证集三百五十张。三千多张图喂给一个一亿三千八百万参数的 VGG16，网络会把训练集背下来：训练损失一路掉到接近零，验证集准确率卡在某个数字上加不动。这不是网络不够深，是参数量和数据量严重不匹配。

底层特征到底通用在哪 #

卷积网络的前几层在看什么，这件事有大量可视化实验支撑。把第一层的卷积核画出来，你看到的是黑白边缘、彩色边缘、不同方向的条带。第二层的滤波器在响应纹理、角点、简单的圆弧。到了中间层，出现的是局部部件：轮子、眼睛、花瓣的形状。只有最后几层才把部件拼成「这是一辆消防车」这种和具体分类体系绑定的判断。

这张分层表要记住：

层的位置 学到的表示 和具体任务的关系
第 1 到 2 层 边缘、色块、方向梯度 任何视觉任务通用
第 3 到 4 层 纹理、角点、简单几何 绝大多数视觉任务通用
第 5 到 7 层 局部部件、物体片段 大部分任务可迁移
最后几层 类别语义、分类边界 和标签体系强绑定

关键判断在后两行。边缘和纹理这件事，识别猫需要，识别花需要，识别工业零件表面缺陷也需要——像素的统计规律不因为你的标签换了就变。所以一个在 ImageNet 上训好的网络，它前面的卷积核拿来用，在你的数据集上仍然在干正确的事。你要换掉的只是最后那层把特征映射到一千个类别的全连接。

这就是迁移学习的假设：底层特征通用，高层特征任务相关。假设成立，就有操作空间——冻结通用部分，只训练任务相关部分。

这个假设成立吗，看数字 #

同一份 flowers 数据（五类，训练集三千三百二十张，验证集三百五十张），三种做法：

做法 训练轮数 验证准确率 备注
三层 CNN 从头训 20 约 55% 数据量撑不住
VGG16 冻结全部卷积，只训最后一层 3 约 60% 训练最快
VGG16 全网络解冻一起训 3 约 90% 收敛慢，显存占用高

五十五和九十五之间的差距，不是网络结构的差距，是「有没有一亿三千万个参数带着 ImageNet 的经验过来」的差距。第一个网络从随机数开始，第二个网络从「已经会看纹理和部件」开始，起点就不在一条线上。

三层 CNN 那一栏也别急着骂它没用。它证明的是另一件事：数据量三千张的时候，网络容量再大也学不到东西，反而更容易过拟合。同样的数据量给 VGG16 从头训，结果只会更差。

什么情况下才考虑从头训 #

不是所有场景都该迁移。判断维度只有两个：数据量，以及你的任务和预训练域的距离。

数据量 和 ImageNet 域的相似度 建议
很小（千级以内） 高（自然图像） 特征提取，只训分类头
中等（万级） 高 解冻高层微调
中等 低（医学、遥感、显微） 解冻更多层，学习率更小
很大（十万级以上） 高 全网络解冻，或从头训
很大 低 从头训，或先在自己的大数据上预训练

「从头训」出现在表里只有两行，而且都带着「很大」。数据量不到十万级，从头训基本是给自己找事。

还有一个硬条件：输入通道数。ImageNet 预训练权重的第一层卷积核是 [3, 3, 3, 64]，对应 RGB 三通道。如果你的输入是单通道灰度图、或者是十三个波段的多光谱，第一层权重直接搬过来形状对不上。这种情况要么把输入复制成三通道强行对齐，要么只加载第一层之后的权重，第一层自己训。

迁移学习省下来的到底是什么 #

省下来的不只是时间。你自己从零训，要经历的是一整套痛苦的寻优过程：学习率试多少、权重初始化用什么分布、数据增强开到多强、正则化系数给多大。这些超参在公开模型上都被人试过了，白盒放在那里。

省下来的还有稳定性。ImageNet 上训出来的权重落在一个比较宽的极小值区域里，你从那里出发做微调，梯度不会一上来就炸。从随机初始化出发，前几百步经常是损失上下乱跳，你得盯着看。

最后省下来的是可复现性。用固定的预训练检查点做起点，别人复现你的实验要容易得多。

结论一句话：只要你的任务是视觉任务，且数据量不是十万级起步，先想迁移，不要先想从头训。

二、迁移学习的三种做法 #

三种做法的分界线只有一条：预训练权重里，有多少参数允许被梯度改掉。

特征提取 #

冻结全部卷积层，只训练你自己新加的分类头。

python
import tensorflow as tf
from nets import vgg
slim = tf.contrib.slim

NUM_CLASSES = 5
checkpoint_file = './log/vgg16/vgg_16.ckpt'

with slim.arg_scope(vgg.vgg_arg_scope()):
    logits, end_points = vgg.vgg_16(images, num_classes=NUM_CLASSES, is_training=False)

# 卷积部分全部冻结：只留最后一层可训练
exclude = ['vgg_16/fc8']
variables_to_restore = slim.get_variables_to_restore(exclude=exclude)
init_fn = slim.assign_from_checkpoint_fn(checkpoint_file, variables_to_restore)

冻结的做法是设 trainable=False：

python
with slim.arg_scope(vgg.vgg_arg_scope()):
    with slim.arg_scope([slim.conv2d], trainable=False):
        logits, end_points = vgg.vgg_16(images, num_classes=NUM_CLASSES)

num_classes 从一千改成五，最后一层 fc8 是全新建的、随机初始化的，其它层从检查点恢复。梯度只会流进 fc8。

特征提取还有一个加速版本，思路来自「冻结的层等价于一个固定函数」：既然卷积部分不更新，它的输出对每张图是常数，那就预先算一遍，把特征向量存到硬盘，之后训练的就是一个很浅的 softmax，读盘比跑前向快得多。

python
# 第一遍：只跑前向，把倒数第二层的特征存盘
import numpy as np

features = []
labels_all = []
restorer = tf.train.Saver(variables_to_restore)
with tf.Session() as sess:
    restorer.restore(sess, checkpoint_file)
    coord = tf.train.Coordinator()
    threads = tf.train.start_queue_runners(sess=sess, coord=coord)
    for _ in range(num_batches):
        feat, lab = sess.run([end_points['vgg_16/fc7'], labels])
        features.append(feat)
        labels_all.append(lab)
    coord.request_stop()
    coord.join(threads)

np.save('flowers_fc7.npy', np.concatenate(features))
np.save('flowers_label.npy', np.concatenate(labels_all))

这一步省掉的是「每遍历一次训练集就重算一遍激活值」。三千张图跑一遍 VGG16 前向，在当时的机器上是分钟级；训练 softmax 只要秒级。

代价是失去数据扩充的随机性——扩充必须在算特征之前做完，而算完之后特征就定死了。数据量很小的时候这个代价不小，扩充是你唯一的多样本来源。

微调 #

解冻一部分高层，和新分类头一起训练。

python
# 只解冻 fc6、fc7、fc8，前面的卷积仍然冻结
variables_to_restore = slim.get_variables_to_restore(exclude=['vgg_16/fc8'])

with slim.arg_scope(vgg.vgg_arg_scope()):
    logits, end_points = vgg.vgg_16(images, num_classes=NUM_CLASSES, is_training=True)

# 卷积层冻结，全连接层可训练
trainable = slim.get_variables(scope='vgg_16/fc6') + \
            slim.get_variables(scope='vgg_16/fc7') + \
            slim.get_variables(scope='vgg_16/fc8')

微调比特征提取多做的事是：让梯度往回穿几层。穿得越深，需要的显存越大，训练越慢，能学到的任务特异性越强。

微调必须配小学习率，理由在「训练策略与学习率」那一章展开。先记住数字：预训练权重的学习率比从头训低一个数量级起步。

从头训 #

随机初始化，全网络训练。

python
# 不加载任何检查点，架构自己定义
with slim.arg_scope(vgg.vgg_arg_scope()):
    logits, end_points = vgg.vgg_16(images, num_classes=NUM_CLASSES, is_training=True)

total_loss = slim.losses.get_total_loss()
optimizer = tf.train.GradientDescentOptimizer(0.01)
train_op = slim.learning.create_train_op(total_loss, optimizer)
slim.learning.train(train_op, log_dir, number_of_steps=100000)

这条路只在数据量足够大、或者预训练域和你的域差到没法借力的时候走。判断标准回到开头那张数据量对照表。

三种做法摆在一起 #

维度 特征提取 微调 从头训
可训练参数 只有分类头 分类头 + 若干高层 全部
数据量需求 千级以内 万级 十万级以上
单轮训练耗时 最短 中等 最长
显存占用 只存前向激活 中高 最高
过拟合风险 低 中 高
收敛速度 几十步见效果 几百到几千步 几万步起
能达到的上限 受限于预训练特征质量 接近该架构上限 取决于数据规模
典型失误 分类头学习率给太小 学习率给太大冲乱权重 数据不够，验证集不涨

怎么选，一条判断链 #

text
数据量 < 1000 张？
  是 -> 特征提取，分类头用较大学习率
  否 -> 继续

任务和 ImageNet 域差异大？（医学影像、工业检测、遥感）
  是 -> 微调，解冻到 conv4 之后，学习率 1e-5
  否 -> 继续

数据量在 1 万到 10 万之间？
  是 -> 微调，解冻 conv5 之后，学习率 1e-4
  否 -> 全网络解冻，学习率 1e-4 起，看损失曲线再降

这条链不是定律，但比拍脑袋强。它把「解冻多少层」和「学习率多大」两个决策绑在数据量上，这是实践里最稳的挂靠点。

三种做法不是互斥的。常见组合是先特征提取跑通流程、拿到一个基线，再微调往上推。先跑通再优化，比一上来就全解冻好排查。

三、特征提取与微调的取舍 #

取舍的实质一句话：你要的是样本效率，还是要的上限。

特征提取的账 #

好处四条：快、特征可缓存、不会把好权重训坏、显存占用小。

「不会把好权重训坏」这条值得展开。微调有一种很难查的故障：学习率给大了，前几百步就把卷积层的权重冲进一个坏区域，之后损失再也回不来。特征提取没有这个风险，卷积层是常量，最坏情况只是分类头没训好，删掉重训就行。这就是「先跑通再上强度」这个顺序的实际理由。

代价三条：上限被预训练特征封住、吃不到扩充的全部收益、分类头在高维特征上容易过拟合。

「吃不到扩充的收益」这条要展开讲。扩充的目的是让模型见到「同一语义、不同像素」的样本，逼它学不变性。分类头只有一个全连接时，它对像素级变化的敏感度由前面的卷积决定，而卷积一点不动，扩充能教会它的东西很有限。数据量很小的时候，扩充往往是你唯一的多样本来源，这个损失不算小。

分类头过拟合的机制很直接：VGG16 的 fc7 输出是 4096 维，三千个样本，一个 4096×5 的全连接只有二十五个参数，倒是不怕过拟合。怕的是你把分类头写成两层感知机，4096→1024→5，参数量四十多万，三千样本压不住。特征提取时代，分类头尽量薄。

微调的账 #

微调把「怎么适配」这件事交给网络自己决定。域差异越大，微调相对特征提取的领先幅度越大。

代价三条：慢、显存高、对学习率敏感。

显存这条容易被低估。特征提取只跑前向，激活值用完就丢。微调要在解冻区间里存下所有中间激活值用于反传。VGG16 在 batch 256 上解冻到 conv5，一块 8G 的卡直接爆。降 batch、或者做梯度累积、或者把解冻区收到 fc6 之后，三条路选一条。

对学习率敏感的具体表现写在「训练策略与学习率」那一章：原学习率会把预训练权重冲乱，症状是损失先降后炸，或者一直不降。

两个维度的四象限 #

判断只看两件事：数据量，以及你的域和 ImageNet 的距离。

和预训练域相似 和预训练域差异大
数据少（千级） 特征提取，只训分类头，学习率 1e-3 微调，但只解冻最后一个卷积块，学习率 1e-5
数据多（十万级） 全解冻微调，学习率 1e-4 从头训，或先在自己的大数据上预训练一轮

左下角是最常见的场景——自己的小数据集、自然图像。特征提取就够拿到一个能看的基线，一小时内出结果。

右上角是最容易白忙的场景。域差得远、数据又少，投入产出比最差，先想办法补数据比调模型划算。

左上角是最容易被高估的场景。数据少、域又近，很多人直接上全解冻，结果三轮下来还不如只训分类头。三千张图喂一亿参数，结果就是过拟合。

什么情况别迁移 #

五条，命中任意一条就别硬搬权重的全部：

  1. 输入通道和预训练不一致，且没法对齐。单通道灰度、多光谱、四通道 RGBA。
  2. 任务是密集预测。分割、检测要改网络结构，预训练卷积仍然有用，但已经不算「直接迁移」。
  3. 数据是非自然图像。频谱图、点云投影、合成渲染图，ImageNet 的纹理先验帮不上忙。
  4. 分辨率差异过大。预训练按 224 输入设计，你要处理两千像素的病理切片，全局池化之后的语义层面对不上。
  5. 输出不是类别。预测美观度分数、预测深度图，最后的分类层本就要重写。

即便命中，也别急着从零训。拿预训练权重当初始化、跑几个 epoch 看损失能不能降，比空想快得多。能降就说明特征还在干活。

一个务实的判断方法 #

两个都跑。特征提取半小时出结果，微调两小时出结果，比验证集。工程上这比背论文里的经验表准。

跑之前先把数据切对。训练集和验证集一定要按目录切，不要用同一个 get_split 拿两份训练集——这种低级错误在小数据集上会把准确率虚高十几二十个点。

四、哪些层该冻、哪些该解冻 #

VGG16 的层命名和参数量分布 #

slim 的 vgg_16 建出来的变量名有规律，按块分组：

变量名前缀 结构 参数量级
vgg_16/conv1 3×3×3×64，3×3×64×64 约 3.8 万
vgg_16/conv2 3×3×64×128 两层 约 22 万
vgg_16/conv3 128→256，三层 约 147 万
vgg_16/conv4 256→512，三层 约 590 万
vgg_16/conv5 512→512，三层 约 707 万
vgg_16/fc6 7×7×512×4096 约 1.02 亿
vgg_16/fc7 4096×4096 约 1677 万
vgg_16/fc8 4096×1000 约 409 万

看清楚一件事：fc6 一层就占了一亿参数，比前面五个卷积块加起来还多七倍。这意味着两件事：

第一，冻结 fc6 省不下多少计算。它本来就是前向的大头，参数多不等于算得多，但矩阵乘法的量摆在那里。

第二，fc6 是最容易过拟合的地方。一亿参数配三千样本，典型的大炮打蚊子。数据少的时候，把 fc6 一起冻掉比留着它「多学点东西」更稳。

冻结的三种写法 #

写法一，arg_scope 里设 trainable=False：

python
with slim.arg_scope(vgg.vgg_arg_scope()):
    with slim.arg_scope([slim.conv2d], trainable=False):
        logits, end_points = vgg.vgg_16(images, num_classes=NUM_CLASSES)

这个写法作用在 slim.conv2d 上，全连接层不受影响，fc6、fc7、fc8 都可训练。

写法二，用 slim 训练脚本的命令行参数：

text
--trainable_scopes=vgg_16/fc8

trainable_scopes 一旦出现，没被列进去的变量全部冻结。它和 --checkpoint_exclude_scopes 配合用：后者声明哪些层不从检查点加载（因为形状变了），前者声明哪些层允许更新。

text
--checkpoint_exclude_scopes=vgg_16/fc8
--trainable_scopes=vgg_16/fc8

写法三，自己筛变量建优化器：

python
trainable_vars = slim.get_variables(scope='vgg_16/fc8')
optimizer = tf.train.GradientDescentOptimizer(learning_rate)
grads = optimizer.compute_gradients(total_loss, var_list=trainable_vars)
train_op = optimizer.apply_gradients(grads)

这个写法最笨，但也最透明。梯度只在你要的变量里流，别的地方一个都不碰。

冻结时 BatchNorm 的处理 #

这一段是全篇最该记住的，也是迁移学习里最容易踩的一个坑。

slim.batch_norm 在一层里建四样东西：

  • gamma，可训练，缩放
  • beta，可训练，偏移
  • moving_mean，不可训练，滑动均值
  • moving_variance，不可训练，滑动方差

后两个的更新不在反向传播里，在 tf.GraphKeys.UPDATE_OPS 这个集合里。训练时 BN 用当前 batch 的均值方差做归一化，同时把 batch 统计量按 decay 混进 moving_mean / moving_variance。

trainable=False 只关掉前两个。

而 slim.learning.create_train_op 默认会把 UPDATE_OPS 里所有 op 都跑一遍。

结果：你以为冻住的卷积层其实在变。weights 确实没动，但 BN 的归一化参数在跟着你的数据漂。漂几个 epoch，这一层的输出分布就和预训练时完全不一样了。「固定函数」不再固定，冻结只剩个名义。

更隐蔽的一层：BN 处在训练模式时（is_training=True），前向用的是当前 batch 的统计量。batch 里的样本互相影响，batch size 给小了，输出抖动明显，验证集指标上不去。batch 设成 1 直接报错。

三种解法。

解法一，冻结区整体切推理模式：

python
with slim.arg_scope(vgg.vgg_arg_scope()):
    logits, end_points = vgg.vgg_16(images, num_classes=NUM_CLASSES, is_training=False)

slim 的 vgg_16 内部会把这个 is_training 传给 slim.batch_norm 和 slim.dropout。BN 走推理模式，用 moving_mean 归一化，不更新统计量，问题解决。

代价是 dropout 也一起关了，fc6、fc7 的正则化没了。数据少的时候这个代价要认——要么接受，要么手动把 dropout 重新打开。

解法二，只保留该更新的 update op：

python
update_ops = tf.get_collection(tf.GraphKeys.UPDATE_OPS)
frozen_prefix = ('vgg_16/conv1', 'vgg_16/conv2', 'vgg_16/conv3', 'vgg_16/conv4')
keep_ops = [op for op in update_ops
            if not op.name.startswith(frozen_prefix)]
train_op = slim.learning.create_train_op(total_loss, optimizer, update_ops=keep_ops)

解冻区的 BN 继续更新，冻结区不动。这个方案最精确，但要自己维护前缀列表，网结构一改就漏。

解法三，清掉全部 update op：

python
train_op = slim.learning.create_train_op(total_loss, optimizer, update_ops=[])

配合 is_training=False 使用，等价于解法一，但意图写在代码里，不会被后来人改回去。

解冻区的 BN 要留在训练模式 #

反方向的坑同样存在。你把 conv5 解冻了，权重在更新，但 BN 还停在推理模式，moving_mean / moving_variance 卡在预训练值上，和更新后的权重对不上。症状是训练损失降得下来，验证集不涨。

规则一句话：解冻区的 BN 跟权重一起切换模式。冻结区推理，解冻区训练。

用 vgg_16 这一个函数建网络时做不到分块控制模式，因为它内部一个 arg_scope 把所有 BN 绑在同一个 is_training 上。要分块，就得自己把网络写出来——这正是「用 slim 构建网络」那一章要做的事。

python
def vgg16_finetune(inputs, num_classes=5):
    # 冻结区：推理模式
    with slim.arg_scope([slim.conv2d], trainable=False):
        with slim.arg_scope([slim.batch_norm], is_training=False):
            net = slim.repeat(inputs, 2, slim.conv2d, 64, [3, 3], scope='conv1')
            net = slim.max_pool2d(net, [2, 2], scope='pool1')
            net = slim.repeat(net, 2, slim.conv2d, 128, [3, 3], scope='conv2')
            net = slim.max_pool2d(net, [2, 2], scope='pool2')
            net = slim.repeat(net, 3, slim.conv2d, 256, [3, 3], scope='conv3')
            net = slim.max_pool2d(net, [2, 2], scope='pool3')
            net = slim.repeat(net, 3, slim.conv2d, 512, [3, 3], scope='conv4')
            net = slim.max_pool2d(net, [2, 2], scope='pool4')

    # 解冻区：训练模式
    with slim.arg_scope([slim.conv2d, slim.fully_connected],
                        activation_fn=tf.nn.relu,
                        weights_initializer=tf.truncated_normal_initializer(0.0, 0.01),
                        weights_regularizer=slim.l2_regularizer(0.0005)):
        with slim.arg_scope([slim.batch_norm], is_training=True):
            net = slim.repeat(net, 3, slim.conv2d, 512, [3, 3], scope='conv5')
            net = slim.max_pool2d(net, [2, 2], scope='pool5')
            net = slim.fully_connected(net, 4096, scope='fc6')
            net = slim.dropout(net, 0.5, scope='dropout6')
            net = slim.fully_connected(net, 4096, scope='fc7')
            net = slim.dropout(net, 0.5, scope='dropout7')
            net = slim.fully_connected(net, num_classes, activation_fn=None, scope='fc8')
    return net

写法有点长，但每一段的模式是显式的。迁移学习出问题的时候，你至少知道该去哪个 with 块里找。

五、数据扩充 #

为什么视觉任务离不开放大 #

计算机视觉的主要矛盾是数据不够。其他领域拿到十万条样本算中等规模，视觉这边十万张图连个像样的实验都不敢做。而且视觉的样本标注成本高——一张图要人看一眼才能标，标注一千万张的代价没人愿意付。

扩充是唯一能把「已经有的样本」榨出更多信息的办法。它做的事是：在不改变标签的前提下，制造同一语义的不同像素形态，逼模型学「不管怎么变，这还是猫」。

前提条件只有一条：变换不能改变语义。水平翻转对猫安全，对文字不成立——镜像之后「b」变成「d」。随机裁剪对大多数物体检测安全，对本来就占满画面的样本会把物体裁掉一半。旋转对卫星图安全，对街景图会让地平线歪掉。上扩充之前先问一句：这个变换之后，人还能给出同一个标签吗。

dtype 陷阱 #

这一条必须先讲，因为它决定了后面所有代码能不能跑对。

有些图像处理函数要求输入是 float32，传 uint8 进去不会报错，但结果不对。resize_images 就是典型。

两种类型转换，效果完全不同：

python
# 写法 A：直接强转，数值仍是 0 到 255
image32 = tf.cast(image, tf.float32)

# 写法 B：按 dtype 范围换算，数值落到 0 到 1
image32 = tf.image.convert_image_dtype(image, dtype=tf.float32)

resize_images 之前要用写法 B，因为插值是按数值算的，uint8 的 0 到 255 和 float32 的 0 到 1 在做加权平均时行为不一样。

显示的时候反过来也有坑。uint8 数据直接转 float32 交给 plt.imshow，会被当成 0 到 1 的浮点图解释，出来一片白。正确做法是先转 float32 再归一化到 [0, 1]，或者转回来用 uint8 显示。

python
def norm(image):
    '''
    归一化：数据要求是 uint8
    '''
    image = tf.cast(image, tf.float32)
    image = tf.subtract(image, 128.0)
    image = tf.div(image, 128.0)
    return image

这是最朴素的一种：减均值除标准差，把像素压到 [-1, 1] 附近。VGG 和 Inception 各自有自己的常数，见下一节。

    filename = ['cat1.jpg']
    # 文件名队列
    filename_queue = tf.train.string_input_producer(filename, shuffle=True)
    # reader 从队列里一次读一个文件
    reader = tf.WholeFileReader()

slim 的两个预处理函数 #

slim 的 preprocessing 目录里按网络分了文件：vgg_preprocessing.py、inception_preprocessing.py。两边的 preprocess_image 签名一样：

text
preprocess_image(image, output_height, output_width, is_training)

is_training 是开关：

  • True，做随机裁剪、随机翻转，输出每次不一样，用于训练
  • False，做确定的居中裁剪或等比缩放，输出固定，用于验证和测试

两个文件的差别在裁剪策略和归一化常数上，具体数值看源码，这里不抄。

用哪个权重就用哪个预处理，这是硬规矩。 加载 VGG16 的检查点，就调 vgg_preprocessing.preprocess_image；加载 Inception 的检查点，就调 inception_preprocessing.preprocess_image。混用的后果是准确率无声地掉几个点到十几个点，没有报错，只有指标异常。原因很直白：预训练权重是在特定的输入分布上训出来的，你喂进去的分布偏了，第一层卷积的响应就全偏了。

自己定义网络的时候反过来自由：没有预训练权重绑着，预处理函数随便挑，甚至只做 x / 255.0 的简单归一化也行。

把扩充塞进数据管道 #

扩充不能挡住训练。做法是 CPU 线程做变换，队列把 batch 递过去，GPU 只管算。

text
CPU 线程 1..n ：读盘 -> 解码 -> 随机裁剪 -> 颜色抖动 -> 入队
                              |
                         batch 队列
                              |
GPU          ：出队 -> 前向 -> 反传 -> 更新

TensorFlow 里 tf.train.batch 的 num_threads 就是干这个的。前面数据管道那篇讲过队列机制，这里只提和扩充相关的两点：

第一，num_threads 给到 8 到 16，小于 GPU 能吃的速度就会成为瓶颈。用 tf.train.batch 还是 shuffle_batch 看你的数据源——DatasetDataProvider 取样本本身已经是随机的，再 shuffle_batch 是浪费。

第二，扩充的超参也是超参。颜色抖动的幅度、随机裁剪的比例范围，都影响结果。幅度太小等于没做，幅度太大把语义改掉了。起点抄别人的开源实现，跑通之后再按验证集微调。

颜色抖动的进阶版是 PCA 颜色增强，出自 AlexNet 论文。思路是对整份数据的 RGB 做 PCA，得到三个主方向，训练时沿主方向随机加减一个幅度。效果是颜色变化沿着数据本身的分布走，比三个通道独立乱抖更接近真实光照变化。要上这个，先找开源实现，别自己推公式。

至此，数据侧的准备齐了：TFRecord 有了、batch 有了、扩充有了。剩下的问题是怎么用一个不啰嗦的方式把网络和权重接起来，这就是 slim 要解决的。

六、slim 库的定位 #

它是什么，为什么这一篇绕不开它 #

slim 是 TensorFlow 的高级封装层，放在 tensorflow.contrib 下面：

python
import tensorflow.contrib.slim as slim

官方对这个目录的描述很直白：这里的代码未经官方支持，随时会被改动或删除，每个子目录有指定负责人。它的定位是承接那些还没进核心库的功能，接口也会变。

所以 slim 不是原生 TensorFlow 的一部分。

那这一篇为什么还要专门讲它？因为 TensorFlow 的 models 仓库里，一大批经典网络的结构代码是用 slim 写的，配套的检查点文件也是按那个结构训出来的。你想用 VGG16 或 Inception 的预训练权重，要么用它的结构定义，要么自己把同样的变量名搭一遍。前者省一天，后者容易在变量名上耗掉一天。

slim 到底省了什么 #

原生 TensorFlow 里定义一个卷积层：

python
input_x = tf.placeholder(dtype=tf.float32, shape=[None, 224, 224, 3])
with tf.name_scope('conv1_1') as scope:
    weight = tf.Variable(tf.truncated_normal([3, 3, 3, 64],
                                             dtype=tf.float32,
                                             stddev=1e-1),
                         name='weights')
    conv = tf.nn.conv2d(input_x, weight, [1, 1, 1, 1], padding='SAME')
    bias = tf.Variable(tf.constant(0.0, shape=[64], dtype=tf.float32),
                       trainable=True, name='biases')
    conv1 = tf.nn.relu(tf.nn.bias_add(conv, bias), name=scope)

slim 里同一层：

python
net = slim.conv2d(input_x, 64, [3, 3], scope='conv1_1')

省掉的不只是行数。原生写法里你没做的事：权重初始化分布要自己挑、正则要自己加、BN 要自己插、激活函数的顺序要自己保证、变量要自己注册进集合。slim 的 conv2d 一次性把这些做成默认行为，你不写就是关掉，写了就覆盖。

这种「默认值 + 局部覆盖」的机制是 slim 的核心设计，也是它最好用也最容易误解的地方。

子模块地图 #

子模块 干什么 迁移学习里的使用频率

七、用 slim 构建网络 #

repeat：同参数重复 #

手写三个相同的卷积层：

python
net = ...
net = slim.conv2d(net, 256, [3, 3], scope='conv2_1')
net = slim.conv2d(net, 256, [3, 3], scope='conv2_2')
net = slim.conv2d(net, 256, [3, 3], scope='conv2_3')
net = slim.max_pool2d(net, [2, 2], scope='pool2')

用 repeat：

python
net = slim.repeat(net, 3, slim.conv2d, 256, [3, 3], scope='conv2')
net = slim.max_pool2d(net, [2, 2], scope='pool2')

repeat 做的事不止是循环。它把 scope 展开成 conv2/conv2_1、conv2/conv2_2、conv2/conv2_3。

这个展开规则要记住。加载预训练权重的时候，变量名是 vgg_16/conv1/conv1_1/weights 这种形状，中间的 conv1_1 就是 repeat 自动加的序号。你自己手写时如果用了别的命名，检查点里的变量就找不到对应的图变量。

stack：不同参数串联 #

三层全连接，输出维度不一样：

python
x = tf.placeholder(dtype=tf.float32, shape=[None, 784])
x = slim.fully_connected(x, 32, scope='fc/fc_1')
x = slim.fully_connected(x, 64, scope='fc/fc_2')
x = slim.fully_connected(x, 128, scope='fc/fc_3')

用 stack：

python
x = slim.stack(x, slim.fully_connected, [32, 64, 128], scope='fc')

卷积层也能用，参数换成元组：

python
# 普通写法
net = slim.conv2d(input_x, 32, [3, 3], scope='core/core_1')
net = slim.conv2d(net, 32, [1, 1], scope='core/core_2')
net = slim.conv2d(net, 64, [3, 3], scope='core/core_3')
net = slim.conv2d(net, 64, [1, 1], scope='core/core_4')

# stack 写法
net = slim.stack(input_x, slim.conv2d,
                 [(32, [3, 3]), (32, [1, 1]), (64, [3, 3]), (64, [1, 1])],
                 scope='core')

repeat 管「全一样」，stack 管「逐层不同」。两个都是语法糖，展开之后等价于手写。

arg_scope：默认参数与局部覆盖 #

如果网络里一大堆参数重复：

python
net = slim.conv2d(input_x, 64, [11, 11], 4, padding='SAME',
                  weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                  weights_regularizer=slim.l2_regularizer(0.0005), scope='conv1')
net = slim.conv2d(net, 128, [11, 11], padding='VALID',
                  weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                  weights_regularizer=slim.l2_regularizer(0.0005), scope='conv2')
net = slim.conv2d(net, 256, [11, 11], padding='SAME',
                  weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                  weights_regularizer=slim.l2_regularizer(0.0005), scope='conv3')

arg_scope 收进来：

python
with slim.arg_scope([slim.conv2d], padding='SAME',
                    weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                    weights_regularizer=slim.l2_regularizer(0.0005)):
    net = slim.conv2d(input_x, 64, [11, 11], scope='conv1')
    net = slim.conv2d(net, 128, [11, 11], padding='VALID', scope='conv2')
    net = slim.conv2d(net, 256, [11, 11], scope='conv3')

第二行的 padding='VALID' 是局部覆盖：显式写出来的参数优先于 arg_scope 的默认值。

多层类型混着用的时候嵌套两层：

python
with slim.arg_scope([slim.conv2d, slim.fully_connected],
                    activation_fn=tf.nn.relu,
                    weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                    weights_regularizer=slim.l2_regularizer(0.0005)):
    with slim.arg_scope([slim.conv2d], stride=1, padding='SAME'):
        net = slim.conv2d(input_x, 64, [11, 11], 4, padding='VALID', scope='conv1')
        net = slim.conv2d(net, 256, [5, 5],
                          weights_initializer=tf.truncated_normal_initializer(stddev=0.03),
                          scope='conv2')
        net = slim.fully_connected(net, 1000, activation_fn=None, scope='fc')

外层管「所有层共有的」，内层管「只有卷积才有的」，最具体的写在调用处。三层覆盖关系不冲突。

这也是「哪些层该冻、哪些该解冻」那一章里那个分块控制 BN 模式的实现手段：两个 arg_scope 套出两个模式区。

变量管理 #

原生 TensorFlow 分两类变量：普通变量（可保存到磁盘）和局部变量（只在 session 里存在）。slim 再切一刀，从普通变量里分出「模型变量」。

python
weights = slim.model_variable('weights', shape=[10, 10, 3, 3],
                              initializer=tf.truncated_normal_initializer(stddev=0.1),
                              regularizer=slim.l2_regularizer(0.05),
                              device='/CPU:0')
model_variables = slim.get_model_variables()

模型变量的含义是：它代表模型参数，靠训练或微调学到，或者从检查点载入。典型反例是 global_step——它参与训练，但它是计步器，不是模型参数。移动平均也一样，它反映模型参数，本身不是模型参数。

python
# 常规变量
my_var = slim.variable('my_var', shape=[20, 1],
                       initializer=tf.zeros_initializer())

# get_variables 拿到模型变量和常规变量的并集
regular_variables_and_model_variables = slim.get_variables()

自己建的变量想加入模型变量集合：

python
slim.add_model_variable(my_var)

这一套分类在迁移学习里直接决定成败。slim.get_variables_to_restore(exclude=[...]) 只在模型变量里筛，你在外面随手建的变量不会混进去，也就不会在恢复检查点时引发「图里有、检查点里没有」的报错。

十几行写一个 VGG16 #

python
def vgg16(inputs):
    with slim.arg_scope([slim.conv2d, slim.fully_connected],
                        activation_fn=tf.nn.relu,
                        weights_initializer=tf.truncated_normal_initializer(0.0, 0.01),
                        weights_regularizer=slim.l2_regularizer(0.0005)):
        net = slim.repeat(inputs, 2, slim.conv2d, 64, [3, 3], scope='conv1')
        net = slim.max_pool2d(net, [2, 2], scope='pool1')
        net = slim.repeat(net, 2, slim.conv2d, 128, [3, 3], scope='conv2')
        net = slim.max_pool2d(net, [2, 2], scope='pool2')
        net = slim.repeat(net, 3, slim.conv2d, 256, [3, 3], scope='conv3')
        net = slim.max_pool2d(net, [2, 2], scope='pool3')
        net = slim.repeat(net, 3, slim.conv2d, 512, [3, 3], scope='conv4')
        net = slim.max_pool2d(net, [2, 2], scope='pool4')
        net = slim.repeat(net, 3, slim.conv2d, 512, [3, 3], scope='conv5')
        net = slim.max_pool2d(net, [2, 2], scope='pool5')
        net = slim.fully_connected(net, 4096, scope='fc6')
        net = slim.dropout(net, 0.5, scope='dropout6')
        net = slim.fully_connected(net, 4096, scope='fc7')
        net = slim.dropout(net, 0.5, scope='dropout7')
        net = slim.fully_connected(net, 1000, activation_fn=None, scope='fc8')
        return net

这一段的变量名和官方 vgg_16 完全对齐：conv1/conv1_1、conv1/conv1_2、fc6、fc7、fc8。所以它的权重能从官方检查点直接恢复。

真实项目里不用自己写这一段，nets/vgg.py 已经提供了：

python

    logits, end_points = vgg.vgg_16(images,
                                    num_classes=NUM_CLASSES,

vgg_16.default_image_size 是 224，输入图片必须按这个尺寸预处理，否则 fc6 的输入维度对不上——fc6 是 7×7×512 的卷积核展平，输入 256 的话空间维度变成 8×8，矩阵形状直接不匹配。

end_points 是个字典，键是第一层到最后一层的名字，值是那一层的输出张量。取中间层做特征提取，或者给外部做可视化，都从这里拿。

自己写的版本和现成的版本功能上等价，差别在于能不能分块挂 arg_scope。要按「冻结区推理模式、解冻区训练模式」那样分块，就得拿出自己写的那一版。

八、加载预训练权重 #

Saver 的两种粒度 #

全量恢复：

python
v1 = tf.Variable(..., name="v1")
v2 = tf.Variable(..., name="v2")

# 恢复全部变量
restorer = tf.train.Saver()

with tf.Session() as sess:
    restorer.restore(sess, "/tmp/model.ckpt")
    print("Model restored.")

部分恢复：

python
# 只恢复 v1 和 v2
restorer = tf.train.Saver([v1, v2])

with tf.Session() as sess:
    restorer.restore(sess, "/tmp/model.ckpt")

Saver 拿到变量列表之后，怎么在检查点文件里找它们？靠每个变量的 var.op.name。所以图里的变量名和检查点里的变量名一致时，直接给列表就行；不一致时必须给字典。

按名字、后缀、命名空间筛 #

slim 提供了四个筛法：

python
v1 = slim.variable(name="v1", ...)
v2 = slim.variable(name="nested/v2", ...)

# 按完整名字
variables_to_restore = slim.get_variables_by_name("v2")

# 按名字后缀，凡是名字里带 2 的都算
variables_to_restore = slim.get_variables_by_suffix("2")

# 按命名空间
variables_to_restore = slim.get_variables(scope="nested")

# 包含式
variables_to_restore = slim.get_variables_to_restore(include=["nested"])

# 排除式
variables_to_restore = slim.get_variables_to_restore(exclude=["v1"])

restorer = tf.train.Saver(variables_to_restore)

get_variables_to_restore 是迁移学习里用得最多的一个：写 exclude=['fc6', 'fc7', 'fc8'] 就是「除了这三层，其它都恢复」。

它筛的是模型变量集合。你在核算外面随手 tf.Variable 建的东西不在里面，所以不会被误拉进来。

变量名不一致时的映射 #

假设你定义的网络变量叫 conv1/weights，而 VGG 检查点里的名字是 vgg16/conv1/weights。直接恢复会报找不到。

加一层前缀：

python
def name_in_checkpoint(var):
    return 'vgg16/' + var.op.name

variables_to_restore = slim.get_model_variables()
variables_to_restore = {name_in_checkpoint(var): var
                        for var in variables_to_restore}
restorer = tf.train.Saver(variables_to_restore)

with tf.Session() as sess:
    restorer.restore(sess, "/tmp/model.ckpt")

字典的键是检查点里的名字，值是图里的变量。方向别搞反了——反过来写报错信息会变得非常难读。

换名字也同一个机制。把 weights 映射成 params1、bias 映射成 params2：

python
def name_in_checkpoint(var):
    if "weights" in var.op.name:
        return var.op.name.replace("weights", "params1")
    if "bias" in var.op.name:
        return var.op.name.replace("bias", "params2")

variables_to_restore = slim.get_model_variables()
variables_to_restore = {name_in_checkpoint(var): var
                        for var in variables_to_restore}
restorer = tf.train.Saver(variables_to_restore)

这个技巧在处理别人转过来的权重时特别有用：从 Caffe 转过来的 VGG 权重，命名习惯和 slim 完全不同，一个映射函数就能省掉手工改检查点。

assign_from_checkpoint_fn #

slim.learning.train 不收 Saver，它收一个 init_fn。这个函数在训练开始前被调一次，负责把权重填进去。

python
from nets import vgg
slim = tf.contrib.slim

image, label = MyPascalVocDataLoader(...)
images, labels = tf.train.batch([image, label], batch_size=32)

# 20 类
predictions = vgg.vgg_16(images, num_classes=20)

train_op = slim.learning.create_train_op(...)

# ImageNet 上训好的检查点
model_path = '/path/to/pre_trained_on_imagenet.checkpoint'
# 新模型的保存目录
log_dir = '/path/to/my_pascal_model_dir/'

# 只恢复卷积层，跳过 fc6、fc7、fc8
variables_to_restore = slim.get_variables_to_restore(exclude=['fc6', 'fc7', 'fc8'])
init_fn = slim.assign_from_checkpoint_fn(model_path, variables_to_restore)

slim.learning.train(train_op, log_dir, init_fn=init_fn)

一千类的 ImageNet 权重迁到二十类的 Pascal VOC，就是这五行的事。

assign_from_checkpoint_fn 还支持 ignore_missing_vars=True。加上它之后，检查点里找不到的变量会被跳过而不报错，适合那种「我知道有些层形状变了」的场景。不加这个参数就是严格模式，缺一个都报错。

预训练和微调在检查点上的区别 #

同样是加载权重，两种目的的参数配置不一样：

预训练 微调
输出类别数 必须和检查点一致 改成自己的类别数
--checkpoint_exclude_scopes 不需要 排除顶层
--trainable_scopes 全部可训练 只列新层
初始学习率 沿用原来的量级 降到原来的十分之一或更低
变量名冲突 没有 有，最后一层形状变了

预训练的意思是在同一个任务上继续训。比如你手上有一份 ImageNet 一千类的检查点，自己又攒了一批一千类的数据，接着训下去即可。

微调的意思是换任务。最后一层的形状从 4096×1000 变成 4096×5，权重没法恢复，必须排除掉让它重新初始化。

「先建网络再恢复」这个顺序在微调里也是硬约束。有些人习惯先 restorer.restore() 再建网络，这样恢复时图里还没有那些变量，Saver 根本没注册它们。顺序错了的症状是：训练照跑，但权重全是随机的，准确率从零开始。

几类典型报错 #

报错信息 真实原因 处理
NotFoundError: Key vgg_16/fc8/weights not found in checkpoint 改了类别数，fc8 形状变了还想着恢复它 加 exclude=['vgg_16/fc8']
Assign requires shapes of both tensors to match fc8 想恢复，但形状是 4096×5 对 4096×1000 同上
ValueError: checkpoint has no key 变量名映射函数写反了 键是检查点名，值是图变量
NotFoundError: Key vgg_16/conv1/conv1_1/weights 自己写的网络把 scope 命名成 conv1_1 少了外层 对齐成 repeat 的展开规则
训练能跑但准确率不涨 恢复在建设计图之前执行，权重全是随机的 移到建图之后
Init operations did not make model ready init_fn 里恢复了不该恢复的变量 收窄 variables_to_restore

这些报错都不难修，难在发现。训练不报错但指标不动的故障，值得在第一个 epoch 结束后打印一次权重检查：

python
with tf.Session() as sess:
    init_fn(sess)
    w = sess.run(tf.get_default_graph().get_tensor_by_name(
        'vgg_16/conv1/conv1_1/weights:0'))
    print('conv1_1 权重均值:', w.mean(), '标准差:', w.std())

随机初始化的权重标准差在 0.01 量级，训好的权重标准差落在 0.1 到 0.3 之间。差一个数量级就是没恢复上。

def get_batch_images_and_label(dataset_dir, batch_size, num_classes,
                               is_training=False, output_height=224,
                               output_width=224, num_threads=10):
    '''
    每次取 batch_size 个样本

    预处理调用 slim 的图片预处理函数：用 vgg 网络就调 vgg 的预处理，
    自己定义网络就自己写，也可以借别的网络写好的归一化

    args:
        dataset_dir: 数据集目录
        batch_size: 一次取多少
        num_classes: 类别数，用于标签 one_hot
        is_training: True 读训练集，False 读验证集
        output_height: 输出高度
        output_width: 输出宽度
        num_threads: 预处理线程数
    return:
        images, labels: batch 张图和 one_hot 标签
    '''
    # 单张图和标签
    image, label = read_flower_image_and_label(dataset_dir, is_training)
    # 预处理，要求输入是 float32
    image = vgg_preprocessing.preprocess_image(
        image, output_height, output_width, is_training=is_training)

    # shuffle_batch 会打乱顺序，batch 不会
    images, labels = tf.train.batch(
        [image, label],
        batch_size=batch_size,
        capacity=5 * batch_size,
        num_threads=num_threads)

    # one_hot
    labels = slim.one_hot_encoding(labels, num_classes)

    return images, labels

两个细节。

第一，download_and_convert_flowers.run() 每次调用都会检查数据集在不在。第一次真下载、真转换，之后直接返回。放在这里是为了让脚本第一次跑就能自举。

第二，preprocess_image 必须和权重配套。这里用 vgg_preprocessing，因为加载的是 VGG 权重。IS_TRAINING 传 True 走随机裁剪，传 False 走确定裁剪，所以训练和验证要各调一次 get_batch，参数不同。

几个必须解释的点。

is_training 用占位符而不是常量。训练时要 True，验证时要 False。如果用常量，验证的时候 dropout 还开着，指标会偏低且抖动。

Saver(params) 和 Saver() 的区别。Saver() 保存全部变量，Saver(params) 只碰 params 里那些。这里用后者，因为 fc8 是新建的，既不需要从检查点恢复，也不需要被这个 saver 重点关照——fc8 由后面的 save 负责存。

tf.train.latest_checkpoint(train_log_dir) 检查有没有存档。有就接着训，没有就从官方权重起。这个「断点续训」的分支在微调里很实用，因为微调经常要中断试参数。

筛选变量还有另一种写法，把每一步都写清楚：

# -*- coding: utf-8 -*-
'''
用卷积网络从头训 flowers，用来和微调后的 VGG 对比
'''

import tensorflow as tf
import input_data
import numpy as np

slim = tf.contrib.slim


def cnn(inputs, num_classes=5):
    '''
    输入 shape 为 [batch_size, 224, 224, 3]
    '''
    with tf.variable_scope('cnn'):
        with slim.arg_scope([slim.conv2d, slim.fully_connected,
                             slim.max_pool2d, slim.avg_pool2d],
                            padding='SAME'):
            net = slim.conv2d(inputs, 64, [5, 5], 4,
                              weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                              scope='conv1')        # 56 x 56 x 64
            net = slim.max_pool2d(net, [2, 2], scope='pool1')   # 28 x 28 x 64
            net = slim.conv2d(net, 64, [3, 3], 2,
                              weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                              scope='conv2')        # 14 x 14 x 64
            net = slim.max_pool2d(net, [2, 2], scope='pool2')   # 7 x 7 x 64
            net = slim.conv2d(net, num_classes, [1, 1], 1,
                              weights_initializer=tf.truncated_normal_initializer(stddev=0.01),
                              scope='conv3')        # 7 x 7 x num_classes
            net = slim.avg_pool2d(net, [7, 7], 7, scope='pool3')
            net = tf.squeeze(net, [1, 2])               # num_classes
            return net

NUM_CLASSES = 5
IMAGE_SIZE = 224

这个网络的结构值得看一眼：conv1 五乘五、步长四，把 224 直接压到 56；conv2 压到 14；conv3 是一乘一卷积，把通道数变成类别数，然后全局平均池化加 squeeze，输出一个长度为 5 的向量。整个网络约四万个参数。

结果摆在一起 #

模型 参数来源 训练轮数 验证准确率
三层 CNN 随机初始化 20 约 55%
VGG16 ImageNet 权重，冻结到只剩 fc8 3 约 60%
VGG16 ImageNet 权重，全网络解冻 3 约 90%

三个数字读法不同。

三层 CNN 的 55% 是「数据量不够」的实证。它训练了二十轮，比另外两个多七倍轮次，准确率还更低。

冻结版的 60% 是「特征提取的上限」。卷积特征本身没问题，但 ImageNet 训出来的特征是为了一千类自然物体服务的，五类花的区分点——花瓣形状、花心纹理——在高层特征里被压得比较扁。只训一个线性分类头，榨不出更多。

全解冻的 90% 说明「适配」这件事值三十个点。卷积层在这三千张图上做了小幅调整，把高层特征重新对齐到花的语义上。三轮就够，因为起点已经很好。

还有一个成本对比不能省：全解冻那一栏的训练时间是冻结版的好几倍。要不要这三十个点，取决于你的时间和显存。

到这里，一个完整的迁移流程跑通了：数据管道、权重加载、冻结策略、训练循环、结果对比。剩下两块拼图是训练策略里的细节和上线前的检查。

十、训练策略与学习率 #

学习率为什么要调小 #

预训练权重已经是某个损失面上的一个好点。这个点的特点是：梯度接近零，四周的谷底比较窄。

你用从头训的学习率往上招呼，第一步的更新量是 lr × grad。lr 大、梯度就算小，乘积照样能把参数推出盆地。推出去之后梯度反而变大，下一步跨得更远，几轮下来权重就成了一堆和预训练毫无关系的数。

症状有两种。一种是损失先降一点点，然后突然炸到 NaN。另一种温和一些：损失缓慢下降到一个比预训练还差的水平，然后卡住。第二种更难查，因为看起来「在学」。

经验数字：微调的初始学习率，取从头训的十分之一或更低。

分场景的学习率表 #

场景 初始学习率 衰减策略
特征提取，只训分类头 1e-3 不用衰减
微调，解冻 fc6 之后 1e-4 每 1000 步乘 0.9
全网络解冻 1e-4 到 1e-5 每 1000 步乘 0.9
域差异大，解冻到 conv3 之后 1e-5 慢衰减，或恒定
从头训 1e-2 到 1e-3 阶梯衰减

只训分类头可以给大学习率，因为卷积不动，怎么折腾都伤不到预训练特征。分类头是个新初始化的层，反而需要大一点的步子才动得起来。

全解冻给 1e-4 是个安全起点。跑到损失不再降，再考虑往下降到 1e-5 续一段。真到了 1e-6 还没动静，问题不在学习率上，回去查权重有没有加载上。

分层学习率 #

底层特征更通用，改动越小越好；高层特征任务相关，允许改动大一些。按这个思路给不同层不同学习率：

python
base_lr = 1e-4

# 底层给 1/10，高层给满
lr_conv = base_lr * 0.1
lr_fc = base_lr

opt_conv = tf.train.GradientDescentOptimizer(lr_conv)
opt_fc = tf.train.GradientDescentOptimizer(lr_fc)

grads = tf.gradients(total_loss,
                     slim.get_model_variables(),
                     colocate_gradients_with_ops=True)

conv_vars = slim.get_variables(scope='vgg_16/conv')
fc_vars = slim.get_variables(scope='vgg_16/fc')

conv_grads = [(g, v) for g, v in zip(grads, slim.get_model_variables())
              if v in conv_vars]
fc_grads = [(g, v) for g, v in zip(grads, slim.get_model_variables())
            if v in fc_vars]

train_op = tf.group(opt_conv.apply_gradients(conv_grads),
                    opt_fc.apply_gradients(fc_grads))

写法啰嗦，效果不一定比单一学习率好。真要用，先确认单一学习率的基线已经调到位了，否则两组超参一起动，出了问题定位不到。

衰减 #

恒定学习率的缺点是后期在极小值附近来回跳。加衰减让步子逐渐变小：

python
learning_rate = tf.train.exponential_decay(
    1e-4,
    global_step,
    decay_steps=1000,
    decay_rate=0.9,
    staircase=True)

staircase=True 表示按阶梯降，每 1000 步整段掉一次；False 是连续平滑降。微调场景用阶梯更好排查——你能明确知道是哪一步之后指标变了。

步数怎么算，得先算清一轮多少步：

text
steps_per_epoch = ceil(n_train / batch_size) = ceil(3320 / 128) = 26

三千三百二十张图、batch 128，一轮二十六步。number_of_steps=100 就是四轮左右。想跑十轮，给 260 步。

这个换算经常被算错。有人把 number_of_steps 当轮数填，实际跑了一百轮，模型早就过拟合了，还以为是自己参数调得好。

warmup #

前几百步用小学习率线性升到目标值，避开刚开始那几步的大梯度。

python
warmup_steps = 500
target_lr = 1e-4

with tf.name_scope('lr'):
    lr = tf.minimum(target_lr, target_lr * tf.cast(global_step, tf.float32) / warmup_steps)

加了 warmup 之后，损失曲线开头那段抖动会小很多。BN 的滑动统计量在开头几步最容易被坏梯度带偏，warmup 顺带把这个问题压住了。

不是所有场景都需要 warmup。特征提取（卷积冻结）压根用不上——没有反向传到卷积，也就没有「冲乱预训练权重」这回事。

优化器 #

官方 VGG 检查点是用 GradientDescentOptimizer 训的。这不代表你不能用 Adam，但意味着两件事。

第一，恢复权重的顺序要对。Adam 会建两个和变量同形的滑动统计量（m 和 v），这些变量注册进图之后，如果你在恢复检查点时用 Saver() 全量恢复，就会去找这两个变量。官方检查点里没有它们，报错。

正确顺序：建网络 → 建 init_fn → 执行恢复 → 建优化器。或者用 exclude 把新变量排除掉。

第二，Adam 的实际步长和 SGD 不一样。它做了梯度归一化，同样标称学习率下，早期实际更新幅度更大。用 Adam 就把学习率再降一档，1e-4 改成 5e-5 起步。

python
# 保守起点
optimizer = tf.train.GradientDescentOptimizer(1e-4)
# 或者
optimizer = tf.train.AdamOptimizer(5e-5)

MomentumOptimizer(1e-4, 0.9) 是个折中，收敛比纯 SGD 快，又不像 Adam 那么激进。

batch size 的取舍 #

batch 优点 缺点
32 到 64 噪声带来正则效果，泛化好一点 BN 统计量抖动，训练不稳
128 折中 无
256 以上 梯度稳，能跑大学习率 显存吃紧，泛化略差，BN 统计量更「平均」

冻结版可以开大 batch，因为只有 fc8 在更新，显存占用小。全解冻版 batch 256 在 8G 卡上基本跑不动 VGG16，降到 64 或者做梯度累积。

梯度累积的做法是攒几个小 batch 的梯度再一次更新：

python
accum_steps = 4
grads_acc = None
for i in range(accum_steps):
    grads, loss = sess.run([grads_and_vars, total_loss], feed_dict=fd)
    if grads_acc is None:
        grads_acc = grads
    else:
        grads_acc = [(a[0] + b[0], a[1]) for a, b in zip(grads_acc, grads)]

apply_grads = optimizer.apply_gradients(grads_acc)
sess.run(apply_grads)

等于用 batch 64 的显存，跑出 batch 256 的梯度。

保存与早停 #

slim.learning.train 的两个参数控制磁盘：

python
slim.learning.train(train_tensor,
                    train_log_dir,
                    number_of_steps=260,
                    save_summaries_secs=300,
                    save_interval_secs=300,
                    init_fn=init_fn)

手写循环里用 tf.train.Saver(max_to_keep=1)，只留最新的一个检查点。max_to_keep 不给的话，默认留五个，几百轮下来磁盘会满。

早停的判断依据是验证集，不是训练损失。训练损失一直降是正常的，验证集连续几轮不涨就该停。

一个实用的保存策略：除了定期保存，额外记一个「验证集最好的那一版」。

python
best_acc = 0.0
...
if accuracy_value > best_acc:
    best_acc = accuracy_value
    save.save(sess, os.path.join(train_log_dir, 'best.ckpt'))

最后上线用 best.ckpt，不用最后一轮的。微调场景里这个差别不小——最后一轮往往已经过拟合了。

损失曲线诊断 #

现象 原因 处理
损失前几步就 NaN 学习率太大 降十倍
损失降一点又弹回初始水平 权重被冲乱 降学习率，重头恢复权重
损失完全不降 权重没恢复上，或者学习率太小 打印权重统计确认，再调学习率
训练损失降、验证不涨 过拟合，或 BN 停在训练模式 加正则，检查 is_training
验证准确率高于训练准确率 数据切分有泄漏 重切，确认验证集没进训练管道
损失曲线锯齿严重 batch 太小，或 BN 统计量抖动 加 batch，或冻结 BN

最后一行值得单独说。冻结区 BN 还在更新的时候，损失曲线会表现出一种特征性的锯齿——降一段、跳一下、再降一段。看到这个形状，先去查 moving_mean 有没有在变。

slim 自带的两个脚本 #

slim 把训练和评估的循环都写好了，用命令行驱动。这两个脚本的价值在于替你处理了断点续训、summary 写入、多卡同步这些杂事。

训练脚本 train_image_classifier.py，基础用法：

text
python train_image_classifier.py \
    --train_dir=./log/train_logs \
    --dataset_name=flowers \
    --dataset_split_name=train \
    --dataset_dir=./datasets/data/flowers \

Windows 上把反斜杠续行去掉，整行敲：

text
python train_image_classifier.py --train_dir=./log/train_logs --dataset_name=flowers --dataset_split_name=train --dataset_dir=./datasets/data/flowers --model_name=inception_v3

预训练就是在同一条命令上再加一个参数：

text
--checkpoint_path=./inception_v3/inception_v3.ckpt

这个参数指向的权重只用于初始化，训练过程中不会被改写。新训出来的模型存到 --train_dir 下。

这里有个限制要提前知道：预训练时样本的输入尺寸和输出类别数必须和原模型一致。下载的检查点是按一千类、299 或 224 输入训的，你的数据集类别数不是一千，就不能走预训练这条路，得走微调。

微调的命令：

text
python train_image_classifier.py \
    --train_dir=./log/in3 \
    --dataset_dir=./datasets/data/flowers \
    --dataset_name=flowers \
    --dataset_split_name=train \
    --model_name=inception_v3 \
    --checkpoint_path=./inception_v3/inception_v3.ckpt \
    --checkpoint_exclude_scopes=InceptionV3/Logits,InceptionV3/AuxLogits \
    --trainable_scopes=InceptionV3/Logits,InceptionV3/AuxLogits

两个参数分工明确：

  • --checkpoint_exclude_scopes：这些层不从检查点加载。它们的形状变了，加载会失败，必须重新初始化。
  • --trainable_scopes：只有这些层参与训练。这个参数一出现，没被列进去的层全部冻结。

例子里的效果是：InceptionV3/Logits 和 InceptionV3/AuxLogits 保持随机初始化并参与训练，其余层的权重从检查点加载且冻结。跑出来的就是「只训最后一层」那个基线。

想跑全解冻，把 --trainable_scopes 去掉，只留 --checkpoint_exclude_scopes。

训练步数：

text
--max_number_of_steps=500

不指定就一直训下去。别指望手动按 Ctrl+C——slim.learning.train 收到中断信号会先存一次检查点再退出，但反复中断容易留下半个检查点。指定步数，等它自己停。

更多参数看 train_image_classifier.py 的源码，scripts 目录里还有用模型识别单张图的例子。

自己写评估 #

脚本适合跑标准流程。要看逐类准确率、要看混淆矩阵，得自己写。

python
import numpy as np
import tensorflow as tf
from nets import vgg
slim = tf.contrib.slim

NUM_CLASSES = 5
IMAGE_SIZE = 224

def evaluate(checkpoint_file, num_batches, batch_size=128):
    images, labels = input_data.get_batch_images_and_label(
        DATA_DIR, batch_size, NUM_CLASSES, False, IMAGE_SIZE, IMAGE_SIZE)

    with slim.arg_scope(vgg.vgg_arg_scope()):
        logits, _ = vgg.vgg_16(images, num_classes=NUM_CLASSES,
                               is_training=False)

    pred = tf.argmax(logits, axis=1)
    restorer = tf.train.Saver()

    # 混淆矩阵：行是真实类，列是预测类
    conf = np.zeros((NUM_CLASSES, NUM_CLASSES), dtype=np.int64)

    with tf.Session() as sess:
        restorer.restore(sess, checkpoint_file)
        coord = tf.train.Coordinator()
        threads = tf.train.start_queue_runners(sess=sess, coord=coord)

        for _ in range(num_batches):
            p, l = sess.run([pred, labels])
            for t, q in zip(np.argmax(l, 1), p):
                conf[t, q] += 1

        coord.request_stop()
        coord.join(threads)

    acc = np.trace(conf) / conf.sum()
    print('总体准确率:', acc)
    for c in range(NUM_CLASSES):
        total = conf[c].sum()
        print('类别', c, '样本数', total, '召回率', conf[c, c] / total)

    return conf

小数据集上，混淆矩阵比总准确率有用得多。总体 90% 看着是四类全对、一类全错——平均下来还是好看的。逐类看才发现有一类被系统性地判成另一类，那多半是这两类的视觉特征在预训练空间里挨得太近，要针对性补样本。

is_training=False 这一句不能省。评估时开着 dropout，每次结果不一样，五百张图能测出五个点的浮动。

导出 #

训练完的模型要能脱离训练框架跑。slim 提供了 export_inference_graph.py，把图结构和权重打成单个 .pb 文件。要上 iOS、Android 或 Linux 端，用 bazel 编译对应平台的产物，具体流程看 models 仓库里 slim 的 Export 说明。

导出有三个坑。

第一，输入尺寸必须和训练时一致。vgg_16.default_image_size 是 224，导出后喂 256 的图，fc6 的形状直接对不上。

第二，BN 必须导出成推理模式。冻结图的时候要确保所有 BN 用的是 moving_mean / moving_variance，不是 batch 统计量。导出前跑一遍 is_training=False 的前向，确认输出稳定。

第三，预处理要跟着搬。训练时用 vgg_preprocessing，推理端也得做同样的减均值、缩放、通道顺序。这一步漏了，模型在服务端的准确率会莫名其妙掉十几个点，而本地测试一切正常——因为本地测试你用的是训练时的预处理代码。

上线前检查清单 #

项目 检查内容
权重 恢复后的 conv1_1 权重标准差在 0.1 以上，不是 0.01 量级
类别数 训练、评估、导出三处的 num_classes 一致
输入尺寸 训练、评估、导出、服务端四处一致
预处理 服务端实现了和训练时同一套归一化
BN 模式 推理路径上所有 BN 都是 is_training=False
标签映射 输出的下标到类名的映射表和训练时一致
指标 在独立验证集上复测过一次，不是只看训练日志
版本 检查点文件、代码、数据集版本三者能对应上

最后一项最容易被忽略。三个月后回头看，发现不知道当时用的哪版权重，只能重训。

十二、易错点速查 #

这一章是全篇的收口。按症状查原因。

症状 原因 处理
训练不报错，验证准确率一直不动 权重没恢复上，从随机初始化开始训 打印权重统计，检查 init_fn 是否在建图之后执行
损失前几步就 NaN 学习率太大，冲出了预训练权重的盆地 降十倍，从 1e-5 试
损失降了一段又弹回初始水平 同上，且已经跑偏 重新恢复权重，降学习率重来
冻结了卷积，但 moving_mean 还在变 只设了 trainable=False，BN 的 update op 还在跑 BN 切推理模式，或清空 UPDATE_OPS
训练准确率正常，验证准确率明显偏低 dropout、BN 停在训练模式 验证路径传 is_training=False
验证准确率比训练准确率还高 数据切分泄漏，验证集混进了训练管道 重切数据，检查 get_split 的 split_name
NotFoundError: Key ... not found in checkpoint 类别数改了，最后一层还想着恢复 get_variables_to_restore(exclude=[...])
Assign requires shapes ... to match 同上，形状对不上 同上
ImportError: No module named nets 没在 research/slim 目录下执行 cd 到正确目录，或加 PYTHONPATH
FailedPreconditionError 出现在队列相关变量 只初始化了全局变量，局部变量没初始化 补 sess.run(tf.local_variables_initializer())
图像预处理后颜色发白或全黑 uint8 直接转 float32 没换算范围 用 tf.image.convert_image_dtype
resize_images 结果有错位块 输入是 uint8，插值按整数算 先转 float32
迁移后准确率掉了十几个点，代码没错 预处理函数和权重不配套 VGG 配 vgg_preprocessing，Inception 配 inception_preprocessing
微调结果不如只训最后一层 数据量太少却全解冻，过拟合 收窄解冻范围，或加正则
换 Adam 后恢复权重报错 优化器建在恢复之前，多出的统计量变量找不到 先恢复，再建优化器
训练跑了很久才发现轮数算错 把 number_of_steps 当轮数填 先算 steps_per_epoch = ceil(n/size)
磁盘被检查点写满 Saver 默认保留最近五个 设 max_to_keep=1
同一份代码两次跑结果差很多 没固定随机种子，扩充太强 固定 seed，降扩充强度
服务端准确率低于本地 预处理或通道顺序不一致 把预处理代码跟着模型一起打包
冻结后训练速度没变快 冻结只影响反传，前向照样算 冻结省的是显存和梯度，不是前向时间

最后一条值得停一下。很多人以为冻结能让训练快好几倍，实测下来只快一点。原因是前向传播一分不少——每一层都要算，fc6 的一亿参数照样要做矩阵乘法。冻结真正省掉的是反向传播的梯度和优化器的变量更新，以及一部分激活值的存储。

想更快，得减少前向的计算量：减小输入尺寸、砍掉 fc6 和 fc7 这两层全连接、或者直接换成更轻的架构。这些是后话，不在这一篇的范围里。

迁移学习的主线回到那句话：底层特征通用，高层特征任务相关。冻结底层、训练高层，用小数据拿到能用的模型。三种做法按数据量选，BatchNorm 该切模式就切模式，学习率比从头训低一个数量级。剩下的都是工程细节。
