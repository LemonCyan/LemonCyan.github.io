这篇讲两件事：环境怎么装，框架怎么用。

讲什么：Theano 与 TensorFlow 1.x 的安装步骤、计算图模型、Session 执行机制、变量/常量/占位符、基本运算，以及一个能跑通的完整小例子。

不讲什么：反向传播的公式推导、卷积与循环网络的结构、TensorFlow 2.x 的 Eager Execution 细节、分布式训练的集群配置。

跨篇指路：推导部分看本目录讲数学基础的那几篇；网络结构看卷积与循环那两篇；数据管道与 tf.data 在后面的工程篇。本篇只负责一件事——让你把第一个环境装起来，把第一个 Session 跑通。

版本交代：文中 TensorFlow 代码全部基于 1.x。1.x 的「先建图、再执行」两阶段模型在 2.x 里被默认关掉了，但读老代码、看老报错、理解 Session.run 到底干了什么，仍然绕不开它。Theano 已经停止维护，这篇把它的装法与用法整段保留，是因为它的设计是理解 TensorFlow 的一面镜子，不是要你现在去用它。

一、深度学习框架解决了什么 #

先把手写训练代码的痛点摆出来。

假设你要训一个 logistic 回归。你自己的代码里会出现这些东西：

python
# 纯手写，不用任何框架
import numpy as np

def train(X, y, steps=1000, lr=0.1):
    N, D = X.shape
    w = np.random.randn(D)
    b = 0.0
    for i in range(steps):
        z = X.dot(w) + b
        p = 1.0 / (1.0 + np.exp(-z))
        # 损失对 w 的梯度，得自己推
        gw = X.T.dot(p - y) / N
        gb = np.sum(p - y) / N
        w -= lr * gw
        b -= lr * gb
    return w, b

两层还能推，三层以上就要在纸上算半天，加个 softmax 加个正则化，错一个符号整晚白干。这就是框架要解决的第一个问题：自动微分。

第二个问题：表达式得有人帮你组织。z = X.dot(w) + b 这行在 numpy 里立刻算完了，你拿不到它的「结构」，想对它求导只能靠你自己记住刚才写过什么。框架把表达式变成一张图，图是有结构的，节点知道自己是谁的孩子，于是求导可以自动遍历。

第三个问题：执行。同一份代码要能跑 CPU、跑 GPU、跑多卡，用户不该为这件事改代码。框架把「算什么」和「在哪算」拆开，设备调度交给它。

第四个问题：优化。内存复用、算子融合、常量折叠。这些东西手写代码做不到，编译式框架能顺手做掉。

把这几个问题合在一起，就是一个深度学习框架的骨架：

能力 解决的问题 谁来做
符号变量 先描述、后计算 框架的 tensor 类型
计算图 表达式有结构、可遍历 框架的图容器
自动微分 不用手推梯度 T.grad / tf.gradients
设备抽象 CPU/GPU 一份代码 框架的执行后端
编译器优化 融合、折叠、复用内存 框架的图优化器

理解这张表，后面两个框架的所有设计差异都能对上号。Theano 和 TensorFlow 1.x 在这五件事上的答案高度一致，区别在于工程实现和抽象层次。

把刚才那段手写代码改写成框架写法，是这个样子：

python
# Theano 写法：先描述，再编译
import theano
import theano.tensor as T

x = T.dmatrix('x')
y = T.dvector('y')
w = theano.shared(np.random.randn(784), name='w')
b = theano.shared(0., name='b')

p_1 = 1 / (1 + T.exp(-T.dot(x, w) - b))
xent = -y * T.log(p_1) - (1 - y) * T.log(1 - p_1)
cost = xent.mean()
gw, gb = T.grad(cost, [w, b])          # 梯度是它自己算的

train = theano.function(
    inputs=[x, y],
    outputs=[p_1, xent],
    updates=((w, w - 0.1 * gw), (b, b - 0.1 * gb)),
)

注意这段代码里没有一行在执行计算。p_1 不是数字，cost 不是数字，gw 也不是数字，它们全是符号。真正的计算发生在 train(...) 被调用的那一刻。

这个「描述与执行分离」的姿态，是这一整篇的主线。

text
手写 numpy：表达式写完就执行，梯度自己推
Theano / TF 1.x：表达式只建图，run 的时候才执行，梯度自动
PyTorch：表达式写完就执行，但框架在背后记了图，梯度自动

三行代码，概括了十年。

二、Theano 与它的时代 #

Theano 出生在蒙特利尔大学 MILA 实验室，2007 年前后开始成型，作者是 Pascal Lamblin、Frédéric Bastien 那一批人，背后站着 Yoshua Bengio。

它干的是一件当时没人干成的事：把「符号计算图 + 自动微分」做成了普通人能用的工具。

在 Theano 之前，做深度学习的人要么手推梯度写 C，要么用 Torch 7 写 Lua。Theano 让你在 Python 里用 numpy 一样的手感写出表达式，然后用一行 T.grad 把梯度拿到手，再把整张图编译成 C 代码跑。2007 年这个体验是跨代的。

它的技术贡献可以列成一张清单：

贡献 具体形态 后来被谁接走
符号张量 T.dmatrix、T.ivector TF 的 tf.placeholder
计算图 表达式组成 DAG TF 的 Graph
自动微分 T.grad(cost, [w, b]) tf.gradients / autograd
函数编译 theano.function([x], y) Session.run 的雏形
共享变量 theano.shared TF 的 tf.Variable
循环抽象 theano.scan tf.while_loop、tf.scan
GPU 后端 .theanorc 里切 device=cuda TF 的 device placement

看这张表你会发现，TensorFlow 的每一个核心概念，在 Theano 里都能找到对应的东西，只是换了名字、换了更好的工程实现。

theano.function 尤其值得停一下。它做的事情是：拿到一组输入符号和输出符号，顺着图反向找到所有依赖，生成一段可执行的代码，编译，缓存。之后你每次调用，走的是编译产物，不是 Python 解释器。

python
x = T.dscalar('x')
y = T.dscalar('y')
z = x + y
f = function([x, y], z)        # 编译
numpy.allclose(f(16.3, 12.1), 28.4)   # True

function() 就是那条分界线。线之前是符号世界，线之后是数值世界。

TensorFlow 的 Session.run() 继承了这条分界线，但走得更远：function 是一函数一编译，TF 把整张默认图当成一个可执行单元，run 的时候才决定要执行哪一部分子图。

那 Theano 为什么没了？

三个原因，一条比一条致命。

编译慢。图一复杂，function() 就要几十秒甚至几分钟。改一行代码重编译一次，调参调到怀疑人生。

调试难。符号世界里没有断点。你想看中间结果，得把它加进 outputs 重新编译一遍。报错信息指向图里的某个节点，跟你写的那行 Python 对不上号。

社区转向。2016 年 TensorFlow 开源，2017 年 PyTorch 开源。Theano 的核心作者 Frédéric Bastien 去了 MILA 做 PyTorch 的编译器相关工作，2017 年 9 月 Theano 宣布停止主要开发，2018 年发布最后一个版本 1.0.5。

text
2007  Theano 起步
2016  TensorFlow 1.0 开源
2017  PyTorch 开源；Theano 宣布停止主要开发
2018  Theano 1.0.5，最后一个版本
2020  TensorFlow 2.x 默认 Eager，动态图成为主流

这条时间线里藏着一个循环：Theano 用「先建图再执行」赢了手写代码，TensorFlow 1.x 把这条路推到尽头，然后大家发现调试太痛苦，PyTorch 用「边定义边执行」把它推翻，TensorFlow 2.x 再跟上去。

所以学 Theano 不是为了用它。是为了看懂后面这些设计选择的来路——为什么 TF 1.x 有 Session，为什么 print 出来是个张量，为什么 tf.function 要存在。这些问题的答案都在 Theano 那张图里。

三、Theano 的安装（Windows 与 Ubuntu） #

先把三个坑说清楚：这两套系统里都会踩到，记住它们，再往下看。

失败原因 典型症状 修法
Python 版本不匹配 pip install 报 is not a supported wheel on this platform；conda 装完 import 就崩 whl 文件名里的 cp35 必须对上你的 Python 3.5；用 python --version 确认

Windows：从 Anaconda 开始 #

Anaconda 是用于科学计算的 Python 发行版，支持 Linux、Mac、Windows，提供包管理和环境管理。它是个打包集合，里面装好了 conda、某个版本的 Python、众多 packages 和科学计算工具。

从其镜像站下载安装包，从中科大镜像的 archive 路径取：

text
http://mirrors.ustc.edu.cn/
archive 路径 → Anaconda3-4.2.0-Windows-x86_64.exe

安装路径按自己的习惯来，这里用 D:\Program Files (x86)\Anaconda，版本选 3-4.2.0。

进入 Anaconda Prompt 命令窗口，先装编译器链：

text
conda install mingw libpython

中间会问 Proceed([y]/n)?，输入 y。

这一步要是卡住或者报错，多半是网络问题，换时间重试。

接着配置环境变量。路径是：计算机 → 属性 → 高级系统设置 → 环境变量。

编辑系统变量 path，追加这两段：

text
D:\Program Files (x86)\Anaconda\MinGW\x86_64-w64-mingw32\lib;
D:\Program Files (x86)\Anaconda\MinGW\bin;

然后回到 Anaconda Prompt：

text
conda install theano pygpu

装失败就先卸再装：

text
conda uninstall theano
conda install theano

新建环境变量 PYTHONPATH，值为：

text
D:\Program Files (x86)\Anaconda\Lib\site-packages\theano

这个路径加了之后运行 spyder 有打不开的情况，实测如此。所以它是个备选手段，先不加，出问题再加。

如果你的电脑没有 GPU，装到这里就结束了，下面的步骤全部跳过。

Windows：PTVS 与 Python 版本 #

接下来给 Visual Studio 装 PTVS。PTVS 是适用于 Visual Studio 的 Python 工具，一个开源插件，支持用 Python 语言编程。

Anaconda 自带 Python 3.5.2，配 VS2015 可以直接装 Python 解释器。

如果你用的是 VS2013，这里有个坑：VS2013 不支持 Python 3.6，需要降到 3.5。VS2015 及以后的版本可以跳过这段。

两条路：卸载 Anaconda 重装一个带 Python 3.5 的版本（比如 Anaconda3-4.0.0），或者用 conda 在线更新。重装更省事，但这里说 conda 的路子。

打开 Anaconda Prompt，创建一个指定 Python 版本的环境：

text
conda create --name python35 python=3.5

不用管是 3.5 点几，conda 会自己找 3.5.x 里最新的。

激活这个环境：

text
activate python35

确认版本：

text
python --version

输出 Python 3.5.5 就说明切过去了。想回默认环境：

text
deactivate python35

删掉一个已有环境：

text
conda remove --name python35 --all

等 Python 3.5 装好，前面那两步要重做一遍：装 MinGW、libpython，再装 theano。

然后下载 PTVS 插件安装：Visual Studio 2013 对应 PTVS 2.2。VS2015 以后版本直接装 Python 支持即可。

装完在 VS 里新建一个 Python 项目，手动指认现有环境，选 Python 3.5。

Windows：两套测试 #

第一套，最直接的：

text
>>> import theano
>>> theano.test()

如果这一步报 ImportError: cannot import name 'configparser'，或者命令窗口执行 spyder 也出同样的问题，先清掉刚才加的路径配置——也就是把 PYTHONPATH 里那条 theano 路径去掉，再重试。

如果 import theano 报 pygpu 相关的错误（装过 CUDA 之后容易出）：

text

spyder 闪退的话，重装它：

text
conda uninstall spyder
conda install spyder

还不行就换个版本的 Anaconda 重来。这不是懒办法，是这个时代的真实体验。

第二套，跑个矩阵乘法对比 numpy：

python
import numpy as np
import time
import theano

A = np.random.rand(1000, 10000).astype(theano.config.floatX)
B = np.random.rand(10000, 1000).astype(theano.config.floatX)

np_start = time.time()
AB = A.dot(B)
np_end = time.time()

X, Y = theano.tensor.matrices('XY')
mf = theano.function([X, Y], X.dot(Y))

t_start = time.time()
tAB = mf(A, B)
t_end = time.time()

print("NP time: %f[s], theano time: %f[s] (times should be close when run on CPU!)" % (
    np_end - np_start, t_end - t_start))
print("Result difference: %f" % (np.abs(AB - tAB).max(),))

判断标准很简单：np time 和 theano time 差不多，配置就没问题。差很多说明图里混进了 GPU 算子或者回退到了 Python 循环。

机器上有别的任务在跑也会导致时间不一致，多测几次。

Windows：CUDA 与 cuDNN #

先确认显卡支持什么版本的 CUDA。打开控制面板，搜索 NVIDIA，双击 NVIDIA 控制面板，点「帮助」→「系统信息」→「组件」，里面会写 CUDA 版本。

然后去官网下载显卡支持的那个版本，双击安装。

这里会遇到第一个坑：提示图形驱动与显卡不兼容。继续装即使成功也用不了 CUDA。

解法是换一个更新一点的 CUDA。比如机器上装 9.0 之后 GPU 跑不起来，装 8.0（cuda_8.0.61_windows.exe）就好了。版本不是越新越好，得对上显卡。

安装时选自定义，把所有的包都勾上，省得后面出莫名其妙的问题。这一步会撞上驱动冲突，导致某些包安装失败。

包装失败的后果是后面用 theano 时跳错。图形驱动装失败的话，运行 theano 会提示 CUDA 版本与驱动版本不一致。真遇到驱动冲突，用驱动精灵卸载显卡驱动再装。

装完验证：

text
nvcc -V

有版本信息输出就说明 nvcc 装好了。

再跑一个 CUDA 自带的样例。装的时候勾了 launch samples 会自动打开样例目录，比如 C:\ProgramData\NVIDIA Corporation\CUDA Samples\v9.0，打开 Samples_vs2015.sln 编译运行，出结果就说明 CUDA 通了。

接着装 cuDNN。下载地址是 https://developer.nvidia.com/cudnn-download，CUDA 8.0 对应 cudnn-8.0-windows7-x64-v6.0.zip。

解压后把里面三个目录的文件拷到 C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v8.0 下对应的目录。

然后重新配置 .theanorc.txt：

makefile

[cuda]
root = C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v9.0

Windows：GPU 与 CPU 实测对比 #

官方给的 GPU 测试程序：

python
from theano import function, config, shared, tensor
import numpy
import time

vlen = 10 * 30 * 768  # 10 x #cores x # threads per core
iters = 1000

rng = numpy.random.RandomState(22)
x = shared(numpy.asarray(rng.rand(vlen), config.floatX))
f = function([], tensor.exp(x))
print(f.maker.fgraph.toposort())
t0 = time.time()
for i in range(iters):
    r = f()
t1 = time.time()
print("Looping %d times took %f seconds" % (iters, t1 - t0))
print("Result is %s" % (r,))
if numpy.any([isinstance(x.op, tensor.Elemwise) and
              ('Gpu' not in type(x.op).__name__)
              for x in f.maker.fgraph.toposort()]):
    print('Used the cpu')
else:
    print('Used the gpu')

这段代码有两个信息量大的地方。

f.maker.fgraph.toposort() 打印的是编译后的图。你能看到 Theano 把 exp 换成了什么实现，是 GpuElemwise 还是 CPU 的 Elemwise。这是它比 Python 层调试更狠的地方——图是可见的。

最后那个 if 判断的也是这件事：图里只要有非 Gpu 的 Elemwise，就说明跑在 CPU 上。

用 GPU 跑，时间大约 0.68 秒。想切成纯 GPU 测试，改 .theanorc.txt：

makefile
[blas]
ldflags=

[global]
device = cuda
floatX = float32
optimizer = None

[cuda]
root = C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v9.0

[nvcc]
fastmath=True
flags =-LD:\Program Files (x86)\Anaconda\libs
compiler_bindir=C:\Program Files (x86)\Microsoft Visual Studio 12.0\VC\bin

[gcc]
cxxflags = -ID:\Program Files (x86)\Anaconda\MinGW

想关掉 GPU 做 CPU 测试，就把 .theanorc.txt 改成只有这两段：

makefile
[blas]
ldflags=

[gcc]
cxxflags = -ID:\Program Files (x86)\Anaconda\MinGW

改完要重启电脑或者重启 spyder 内核，不然不生效。

CPU 跑同样的测试，14 秒。GPU 0.68 秒，差了近 20 倍。这就是当年大家折腾 CUDA 的动力。

Theano 的类型系统在 theano.tensor 子模块下，惯例是：

python

命名规则按首字母记，首字母定类型，后缀定维度：

首字母 含义 位宽

后缀 维度 对应 numpy

python

python
>>> x = T.matrix('x')

>>> layer0_input = x.reshape((500, 3, 28, 28))
>>> layer0_input.type

reshape 之后类型变成了一串布尔值。每个布尔位表示那一维是否可被 broadcast。这是 Theano 做维度对齐的依据，也是它报错信息里经常出现的字符串。

函数与表达式 #

最小的一次完整流程：

python
import numpy
import theano.tensor as T
from theano import function

x = T.dscalar('x')
y = T.dscalar('y')
z = x + y
f = function([x, y], z)

numpy.allclose(f(16.3, 12.1), 28.4)     # True
numpy.allclose(z.eval({x: 16.3, y: 12.1}), 28.4)   # True

两行都是求值，区别在于一行走编译好的函数，另一行走 eval。eval 是便捷入口，内部还是建图编译，慢一点。

f = function([x, y], z) 是这条分界线。左边是符号世界，右边是可执行函数。

print(f([0, 1, 2]))        # [0. 2. 1026.]

>>> x, y = T.dscalars('x', 'y')
>>> z = x + y

共享变量 #

shared 构造的是「多个函数共享」的变量，用 get_value() 读，用 set_value() 改。典型的用法是累加器：

python
>>> from theano import shared
>>> state = shared(0)
>>> inc = T.iscalar('inc')
>>> accumulator = function([inc], state, updates=[(state, state + inc)])

>>> print(state.get_value())
0
>>> accumulator(1)
array(0)
>>> print(state.get_value())
1
>>> accumulator(300)
array(1)
>>> print(state.get_value())
301

注意输出的规律：函数返回的是更新之前的值，updates 在返回之后才生效。accumulator(1) 返回 0，但 state 已经是 1。这是新手最容易看错的地方。

set_value 能直接改：

python
>>> state.set_value(-1)
>>> accumulator(3)
array(-1)
>>> print(state.get_value())
2

再定义第二个函数共享同一个变量：

python
>>> decrementor = function([inc], state, updates=[(state, state - inc)])
>>> decrementor(2)
array(2)                          # 输出的是更新前的值 2
>>> print(state.get_value())      # update 把 state 更新为 0
0

updates 的形式：必须是 (shared-variable, new expression) 的列表，也可以是字典（键是 shared variable，值是 new expression）。语义就是「用后面的值替换前面的值」。

givens：替换任意符号 #

givens 用来替代任何符号变量，不只是共享变量，常量、表达式都能替。

python
>>> fn_of_state = state * 2 + inc
>>> foo = T.scalar(dtype=state.dtype)      # 类型必须与要替换的变量一致
>>> skip_shared = function([inc, foo], fn_of_state, givens=[(state, foo)])
>>> skip_shared(1, 3)
array(7)
>>> print(state.get_value())               # state 没变
0

skip_shared(1, 3) 里，1 给了 inc，3 给了 foo，计算时用 foo 替掉了 state，所以 state * 2 + inc 变成 3 * 2 + 1 = 7。

有个约束要记住：不要引入互相依赖的替代品。替代者的求值顺序没有定义，互相依赖时会以任意顺序工作，结果不可预测。

实际理解 givens 的方式：它是一个机制，允许你用另一种表示（求值到同 shape、同 dtype 的张量）替换公式里的任何一部分。

copy：复制一个函数 #

function 对象可以复制，用 swap 换掉它引用的共享变量：

python
>>> import theano
>>> import theano.tensor as T
>>> state = theano.shared(0)
>>> inc = T.iscalar('inc')
>>> accumulator = theano.function([inc], state,
...                               updates=[(state, state + inc)],
...                               on_unused_input='ignore')
>>> accumulator(10)
array(0)
>>> print(state.get_value())
10

>>> new_state = theano.shared(0)
>>> new_accumulator = accumulator.copy(swap={state: new_state})
>>> new_accumulator(100)
[array(0)]
>>> print(new_state.get_value())
100
>>> print(state.get_value())        # 原函数的 state 未变
10

delete_updates=True 是另一条路，复制出来的函数去掉更新逻辑：

python
>>> null_accumulator = accumulator.copy(delete_updates=True)
>>> null_accumulator(9000)
[array(10)]
>>> print(state.get_value())
10

没有移除 updates 的话，值会变成 9010。移除之后只剩 state 自己的值，inc 参数也不再被使用。

随机数 #

随机流在 theano.tensor.shared_randomstreams 里：

python
from theano.tensor.shared_randomstreams import RandomStreams
from theano import function

srng = RandomStreams(seed=234)
rv_u = srng.uniform((2, 2))        # 均匀分布 2x2
rv_n = srng.normal((2, 2))         # 正态分布 2x2

f = function([], rv_u)
g = function([], rv_n, no_default_updates=True)    # 不更新 rv_n 的随机状态
nearly_zeros = function([], rv_u + rv_u - 2 * rv_u)

三条调用规律，直接背下来：

python
>>> f_val0 = f()
>>> f_val1 = f()        # 与 f_val0 不同的数
>>> g_val0 = g()        # 与前面都不同
>>> g_val1 = g()        # 与 g_val0 相同

第三行最容易踩。no_default_updates=True 关掉了随机状态的自动更新，所以同一个函数反复调用拿到同一个数。

nearly_zeros 那个表达式看着奇怪，其实有它的道理：一个随机变量在一个简单函数里只生成一次，所以 rv_u + rv_u - 2 * rv_u 三次出现的 rv_u 是同一个值，结果恒为零。这是符号求值的一个经典陷阱。

顺带把 numpy 的随机抽样接口摆出来，后面写数据管道时天天用：

接口 行为 区间
rand(d0, d1, ...) 均匀分布 [0, 1)
randn(d0, d1, ...) 标准正态 无界
randint(low, high, size) 整数 左闭右开
random_integers(low, high, size) 整数 闭区间
random_sample(size) 浮点 [0.0, 1.0)
choice(a, size, replace, p) 从 a 中抽样 可指定概率
bytes(n) 随机字节 无

用法示例：

python
>>> np.random.rand(3, 2)                       # 3x2 的随机矩阵
>>> np.random.randn()                          # 一个标准正态样本
>>> np.random.randint(2, size=10)              # 10 个 0 或 1，最大值小于 2
>>> np.random.randint(size=10, low=0, high=3)  # 10 个整数，最低 0，最大不可取 3
>>> np.random.random_integers(5, size=(3, 2))  # 用法同 randint，闭区间
>>> np.random.choice(5, 3)                     # 最大 4，取 3 个
>>> np.random.choice(5, 3, p=[0.1, 0, 0.3, 0.6, 0])            # 非均匀
>>> np.random.choice(5, 3, replace=False)                      # 不放回
>>> np.random.choice(5, 3, replace=False, p=[0.1, 0, 0.3, 0.6, 0])  # 不放回 + 非均匀
>>> np.random.bytes(10)                        # 随机字节串

一个完整的 logistic 训练 #

把前面所有零件拼起来。这个例子来自 Theano 0.8.2 的官方教程，是理解符号计算的最佳入口：

python
import numpy
import theano
import theano.tensor as T

rng = numpy.random

N = 400          # 训练样本数
feats = 784      # 输入变量个数

# 生成数据集：D = (input_values, target_class)
D = (rng.randn(N, feats), rng.randint(size=N, low=0, high=2))
training_steps = 10000

# 声明符号变量
x = T.dmatrix("x")
y = T.dvector("y")

# 权重随机初始化，w 和 b 用 shared，这样多次迭代之间能保住值
w = theano.shared(rng.randn(feats), name="w")
b = theano.shared(0., name="b")

print("Initial model:")
print(w.get_value())
print(b.get_value())

# 构建表达式图
p_1 = 1 / (1 + T.exp(-T.dot(x, w) - b))        # 目标为 1 的概率
prediction = p_1 > 0.5                          # 阈值化后的预测
xent = -y * T.log(p_1) - (1 - y) * T.log(1 - p_1)   # 交叉熵
cost = xent.mean() + 0.01 * (w ** 2).sum()     # 加 L2 正则

gw, gb = T.grad(cost, [w, b])                  # 自动求梯度

# 编译
train = theano.function(
    inputs=[x, y],
    outputs=[prediction, xent],
    updates=((w, w - 0.1 * gw), (b, b - 0.1 * gb)),
)
predict = theano.function(inputs=[x], outputs=prediction)

# 训练
for i in range(training_steps):
    pred, err = train(D[0], D[1])

print("Final model:")
print(w.get_value())
print(b.get_value())
print("target values for D:")
print(D[1])
print("prediction on D:")
print(predict(D[0]))

这段代码里有三个关键点，值得逐个说。

T.grad(cost, [w, b]) 是自动微分。它顺着表达式图反向走一遍，把 cost 对 w 和 b 的梯度都算出来，返回的还是符号。你没有写任何导数公式。

updates=((w, w - 0.1 * gw), ...) 是梯度下降的全部实现。更新规则写成表达式，编译进函数里，每次调用执行一次。学习率就是那个 0.1。

train 和 predict 是两个编译产物。同一个图，两个入口，一个带更新、一个不带。这是 Theano 的复用方式。

对比一下框架出现之前的手写版本：四百行里三百行在处理梯度，现在十行搞定。这就是框架带来的变化。

scan：循环的抽象 #

scan 是 Theano 里最难啃的一块，但绕不开——RNN 就靠它。

调用的一般形式：

python
results, updates = theano.scan(
    fn=lambda y, p, x_tm2, x_tm1, A: y + p + x_tm2 + x_tm1 + A,
    sequences=[Y, P[::-1]],
    outputs_info=[dict(initial=X, taps=[-2, -1])],
    non_sequences=A,
)

四个参数，按顺序讲：

fn 是要反复计算的函数，一般用 lambda。参数顺序有严格要求：先是 sequences 的参数，然后是 outputs_info 的参数，最后是 non_sequences 的参数。

sequences 是要迭代的序列。第一个维度（leading dimension）就是迭代次数。所以 Y 和 P[::-1] 的第一维大小要相同，不同的话取小的那个。

outputs_info 描述要用到前几次迭代的输出。dict(initial=X, taps=[-2, -1]) 表示用前两次和前一次的输出。当前迭代输出记为 x(t)，计算中用到 x(t-1) 和 x(t-2)。

non_sequences 是非序列输入，就是个固定值，每次迭代加的都一样。A 是个常数，比 Y 少一个维度。

返回两个东西：results 是所有迭代输出的堆叠，updates 是随机状态之类的更新列表。updates 要记得传给 theano.function，不然随机数不更新。

官网用两个例子引入 scan：算雅各比矩阵和海森矩阵。

雅各比矩阵：

python
>>> import theano
>>> import theano.tensor as T
>>> x = T.dvector('x')
>>> y = x ** 2
>>> J, updates = theano.scan(
...     lambda i, y, x: T.grad(y[i], x),
...     sequences=T.arange(y.shape[0]),
...     non_sequences=[y, x])
>>> f = theano.function([x], J, updates=updates)
>>> f([4, 4])
array([[ 8.,  0.],
       [ 0.,  8.]])

海森矩阵：

python
>>> x = T.dvector('x')
>>> y = x ** 2
>>> cost = y.sum()
>>> gy = T.grad(cost, x)
>>> H, updates = theano.scan(
...     lambda i, gy, x: T.grad(gy[i], x),
...     sequences=T.arange(gy.shape[0]),
...     non_sequences=[gy, x])
>>> f = theano.function([x], H, updates=updates)
>>> f([4, 4])
array([[ 2.,  0.],
       [ 0.,  2.]])

两个例子的套路一样：对输出的每一维，单独求一次梯度，用 scan 把它们收集起来。雅各比是「每一行对 x 求导」，海森是「梯度的每一维再对 x 求导」。scan 在这里干的活就是把 Python 的 for 循环搬进图里。

CNN 里还有个具体例子。输入层和第一个隐层之间要加卷积，对应的 API 是 theano.tensor.signal.conv.conv2d，它接受两个符号输入。

第一个 4 维张量是 mini-batch 的输入图像，维度含义：

text
mini_batch_size
# of feature input maps
image height
image width

第二个 4 维张量是权值矩阵 W，维度含义：

text
# of feature output maps（即 # of filters）
# of feature input maps
filter height
filter width

python
rng = np.random.RandomState(23455)
input = T.dtensor4('input')
w_shp = (2, 3, 9, 9)        # 3 表示 rgb 三个颜色分量
w_bound = np.sqrt(np.prod(w_shp[1:]))
W = theano.shared(
    np.asarray(rng.uniform(low=-1. / w_bound, high=1. / w_bound, size=w_shp),
               dtype=input.dtype),
    name='W')
conv_out = conv.conv2d(input, W)

w_bound 那个初始化范围是按输入通道数和感受野面积算的，目的是让初始权重落在合理区间。这是早期 CNN 的常规做法。

五、TensorFlow 的设计思路 #

TensorFlow 是 Google 基于 DistBelief 研发的第二代人工智能学习系统，命名来自它的运行原理。Tensor 是张量，也就是 N 维数组；Flow 是流，指基于数据流图的计算。TensorFlow 描述的是张量从流图一端流动到另一端的计算过程。

把 Theano 的贡献和 TensorFlow 的设计摆在一起看，会发现后者是一次工程放大：

Theano 的做法 TensorFlow 1.x 的做法 变化
每个表达式自带一张图 一张全局默认图，所有 op 往里塞 图从「表达式」升到「程序」
theano.function([x], y) 编译一个函数 Session.run(y) 跑一个子图 编译单位变大
theano.shared 显式声明 tf.Variable + 初始化 op 多了初始化阶段
无原生占位符（用 symbolic input） tf.placeholder 独立概念 输入输出分离
.theanorc 切设备 with tf.device(...) 在图里标注 设备分配进了图

这些变化里最重要的是第一条。Theano 里每写一个表达式，它自带一小张图，function 从这些表达式里临时拉出一张大图。TensorFlow 反过来：先有一个全局的默认图，你写的每一句都在往里加节点。

这个反转带来两个直接后果。

图能跨语句、跨函数、跨文件累积。你可以用十个别名函数拼一张巨大的图，最后 run 一次。这在分布式训练里是刚需——图得能传给别人。

图的存在变成了显式的、可读取的对象。tf.get_default_graph() 拿到它，能遍历节点、能导出、能可视化到 TensorBoard。Theano 的图是隐式的，靠表达式之间的引用串起来。

TensorFlow 的五个核心概念，官方文档开篇就列出来了：

  • 用图（graph）表示计算任务
  • 在被称作会话（Session）的上下文里执行图
  • 用 tensor 表示数据
  • 通过变量（Variable）维护状态
  • 用 feed 和 fetch 为任意操作赋值或取数据

第一条和第二条合起来就是那句最关键的话：先建图，再执行。

一个 op 接受 0 个或多个 Tensor，执行计算，产生 0 个或多个 Tensor。图里的节点就是 op，边是 Tensor。数据的形状举例：一组图像可以表示成四维浮点数组，四个维度是 [batch, height, width, channels]。

图要在会话里启动。会话把 op 分发到 CPU 或 GPU 上，提供执行 op 的方法，执行后把产生的 tensor 返回。在 Python 里，返回的 tensor 是 numpy 的 ndarray；在 C 或 C++ 里，返回的是 tensorflow::Tensor 实例。

TensorFlow 支持 C、C++、Python 三种语言。Python 库最好用，提供了大量辅助函数简化建图，这些函数 C 和 C++ 库里还没有。三种语言的会话库是统一的。

TensorFlow 程序被组织成两个阶段：

阶段 干什么 代码形态
构建阶段 把计算步骤描述成图 一堆 tf.xxx() 调用
执行阶段 用会话跑图里的 op sess.run(...)

典型流程：构建阶段建一张图表示神经网络，执行阶段反复执行图里的训练 op。

建图的第一步是创建源 op（source op）。源 op 不需要输入，比如常量（Constant），它的输出被传给其它 op 做运算。Python 库里，op 构造器的返回值代表这个 op 的输出，这些返回值可以传给其它 op 构造器当输入。

TensorFlow 的 Python 库有一个默认图（default graph），op 构造器往它上面加节点。大部分程序用默认图就够了，多图管理的细节在 Graph 类的文档里。

再强调一遍这个反直觉的地方。下面这段代码跑完，product 里什么都没有：

python
import tensorflow as tf

matrix1 = tf.constant([[3., 3.]])
matrix2 = tf.constant([[2.], [2.]])
product = tf.matmul(matrix1, matrix2)

print(product)
# Tensor("MatMul:0", shape=(1, 1), dtype=float32)

print 出来的是 Tensor("MatMul:0", ...)。它描述的是「图里有个节点，名字叫 MatMul，输出第 0 个张量，形状 (1,1)，类型 float32」。它不是 [[12.]]。

这个现象在 TF 1.x 里是常态。你写十行代码，十行都在建图，一行都没算。所有数值要等 Session.run() 才出来。

反过来说，这也是一种能力：建图的时候你就能检查张量的形状和类型，不用真跑一遍数据。静态图的编译期检查就建立在这上面。

TF 1.x 与 TF 2.x 的差别可以列成一张表：

维度 TF 1.x TF 2.x
执行模式 静态图，先建后跑 Eager 默认开，边定义边跑
会话 必须显式创建 Session 不需要
打印张量 打印出节点描述 打印出数值
占位符 tf.placeholder 传数据 直接用 Python 函数参数
图 全局默认图 tf.function 按需追踪
变量初始化 必须 global_variables_initializer() 自动初始化
调试 加 outputs 再 run 一遍 直接 print，直接断点

这张表就是「为什么 TF 2.x 要重写」的答案。TF 1.x 的性能优势还在，但可用性代价太大。

七、计算图与 Session #

运行机制 #

TensorFlow 的运行机制是「定义」与「运行」相分离。从操作层面抽象成两件事：构造模型、运行模型。

图这个容器里有四种东西，必须分清：

概念 是什么 生命周期
张量 tensor 所有数据的载体，N 维数组 图里的边
变量 Variable 模型参数，训练中不断更新 跨 run 持久
占位符 placeholder 输入数据的入口，像函数形参 只活在一次 run 之内
节点 op 图中的运算，0 到多个输入，0 到多个输出 图里的节点

op 是描述张量之间运算关系的东西，是网络里真正的结构。tensor 是流经这些结构的数据。

会话与图交互时，有两种数据流向机制：

  • 注入机制（feed）：通过占位符把数据传进图里。
  • 取回机制（fetch）：从图里把结果取出来。

feed 用 feed_dict 传，fetch 就是在 run() 的第一个参数里点名要哪些张量。

Session 的三种写法 #

第一种，最原始的：

python
import tensorflow as tf

hello = tf.constant('hello TensorFlow')

sess = tf.Session()
print(sess.run(hello))
print(hello.eval(session=sess))
sess.close()

sess.run(hello) 和 hello.eval(session=sess) 等价。后者是 Tensor 对象上的方法，需要指定会话。

Session 用完要 close() 释放资源。忘了关，资源不释放，程序跑久了会出问题。

第二种，用 with 代码块，自动关：

python
a = tf.constant(3)
b = tf.constant(4)

with tf.Session() as sess:
    print(' a + b =  {0}'.format(sess.run(a + b)))
    print(' a * b =  {0}'.format(sess.run(a * b)))

注意 a + b 这一步是在建图，不是算数。sess.run(a + b) 里那个加法节点是 run 的时候才加进图里的——因为 Python 先算 a + b，返回一个新 Tensor，再传给 run。这种写法能跑，但每次都在往图里加节点。

第三种，交互式：

python
sess = tf.InteractiveSession()

x = tf.Variable([1.0, 2.0])
a = tf.constant([3.0, 3.0])

x.initializer.run()                    # 初始化变量

sub = tf.subtract(x, a)
print(sub.eval())                      # [-2. -1.]

InteractiveSession 把自己设成默认会话，之后 Tensor.eval() 和 Operation.run() 不用再指定 session。写 Jupyter 或 IPython 里逐行调试时，这个方便很多。

三种写法对照：

写法 关闭方式 适用场景
tf.Session() 手动 close() 脚本，需要精确控制
with tf.Session() as sess 自动 大部分脚本，推荐
tf.InteractiveSession() 手动 close() Jupyter、IPython 交互

run 到底做了什么 #

python
sess = tf.Session()
result = sess.run(product)
print(result)        # [[12.]]
sess.close()

这一行 sess.run(product) 是整个 TF 1.x 的心脏，拆开看它做了这些事：

product 是 MatMul 节点的输出，会话从它出发反向遍历图，找出它依赖的所有节点——两个 Const 节点。这是一次子图提取。

然后把子图里的 op 分发到可用设备。有 GPU 就用 GPU，没有就用 CPU，用户不用指定。

接着执行。会话负责传好每个 op 需要的输入，op 之间可以并发执行。run(product) 一次调用触发了图里三个 op 的执行。

最后把结果取出来，转成 numpy.ndarray 返回。

python
# 默认图现在有三个节点：两个 Const、一个 MatMul
# 真正进行矩阵相乘，必须在会话里启动这个图

返回值类型值得记一下：Python 里是 numpy.ndarray。所以拿到之后能直接用 numpy 的函数处理，也能 print 出数值。这是符号世界和数值世界的接缝。

一次取多个 #

run() 的第一个参数可以传列表：

python
in1 = tf.constant(1.0)
in2 = tf.constant(2.0)
in3 = tf.constant(3.0)

intermed = tf.add(in1, in2)
mul = tf.multiply(in2, in3)

with tf.Session() as sess:
    re = sess.run([intermed, mul])
    print(re)        # [3.0, 6.0]

一次 run 取回多个张量，比 run 两次快。因为两次 run 会把公共的子图重复执行一遍，一次 run 里公共部分只算一次。

这个优化在训练里很重要。你要拿 loss、accuracy、梯度，全放进一个 list 一次取。

设备指定 #

在实现上，TensorFlow 把图定义转换成分布式执行的操作，把可用的计算资源用足。你不需要显式指定 CPU 还是 GPU，它会自动检测。检测到 GPU 就用找到的第一个 GPU。

机器上有多个 GPU 时，除第一个外默认不参与计算。要让它们参与，得把 op 明确指派过去。with...Device 语句就是干这个的：

python
with tf.Session() as sess:
    with tf.device("/cpu:0"):
        print(sess.run(product))

设备用字符串标识：

text
"/cpu:0"    机器的 CPU
"/gpu:0"    机器的第一个 GPU，如果有的话
"/gpu:1"    机器的第二个 GPU，以此类推

ConfigProto #

更细的控制走 tf.ConfigProto。构一个 config，在创建 Session 时传进去：

python
config = tf.ConfigProto(log_device_placement=True, allow_soft_placement=True)
session = tf.Session(config=config)

两个参数的含义：

log_device_placement=True 打印设备分配日志，每个 op 落在哪个设备上都会输出。排查「为什么没跑在 GPU 上」时非常有用。

allow_soft_placement=True，如果指定的设备不存在，允许 TF 自动分配。比如你写了 /gpu:0 但机器没 GPU，开了这个参数就自动退回 CPU，不开就报错。

GPU 显存控制 #

ConfigProto 生成之后还能设属性来分配 GPU 资源。

按需分配：

python
config.gpu_options.allow_growth = True

意思是刚开始分配少量显存，按需慢慢加。代价是不会释放内存，所以容易产生碎片。笔记本上跑小模型时这个参数几乎必开，否则 TF 一上来就把整块显存吃光。

也可以在创建时就指定：

python
gpu_options = tf.GPUOptions(allow_growth=True)
config = tf.ConfigProto(gpu_options=gpu_options)

或者给固定比例，比如分配 GPU 显存的 70%：

python
gpu_options = tf.GPUOptions(per_process_gpu_memory_fraction=0.7)

allow_growth 和 per_process_gpu_memory_fraction 是两个方向：前者动态、有碎片，后者固定、可预测。多进程共享一块卡时用后者。

完整的一份组合用法：

python
# 按需增长 + 软放置 + 设备日志
config = tf.ConfigProto(
    log_device_placement=True,
    allow_soft_placement=True,
)
config.gpu_options.allow_growth = True

with tf.Session(config=config) as sess:
    sess.run(tf.global_variables_initializer())

还有一条实战经验：显存不够时，先试 allow_growth=True，再试 per_process_gpu_memory_fraction=0.7，还不行就减 batch size。顺序别反。

八、变量、常量与占位符 #

这三样东西的区别，是 TF 1.x 里最该早起弄明白的事。

类型 建图时 有初始值吗 跨 run 保留 典型用途
tf.constant 值写死在图里 有 不变 超参数、固定矩阵
tf.Variable 只登记，需要初始化 无，必须 init 保留 权重、偏置
tf.placeholder 只登记形状和类型 无，必须 feed 不保留 输入数据、标签

常量进图就固化了，改值要重建图。变量是个容器，初始化之后才有值，每次 run 的更新会留在里面。占位符是个空壳，每次 run 用 feed_dict 往里灌。

常量 #

python
matrix1 = tf.constant([[3., 3.]])
matrix2 = tf.constant([[2.], [2.]])

常量在构建阶段就确定了，值写进图里。好处是省事，坏处是图变大——大矩阵当常量塞进图，模型文件会膨胀得很快。

变量 #

变量维护图执行过程中的状态。经典例子是计数器：

python
# 创建一个变量，初始化为标量 0
state = tf.Variable(0, name='counter')

# 创建一个 op，作用是让 state 增 1
one = tf.constant(1)
new_value = tf.add(state, one)
update = tf.assign(state, new_value)

# 启动图后，变量必须先经过初始化 op
init_op = tf.global_variables_initializer()

with tf.Session() as sess:
    sess.run(init_op)
    print(sess.run(state))        # 0
    for _ in range(3):
        sess.run(update)
        print(sess.run(state))    # 1  2  3

三个必须记住的点。

tf.assign(state, new_value) 是图的一部分，和 tf.add 地位相同。它不会因为被写出来就执行，必须 run 才生效。这就是为什么 update 要单独 run。

变量必须初始化。tf.global_variables_initializer() 返回的是一个 op，这个 op 也要 run。忘记这一步，报错是 FailedPreconditionError: Attempting to use uninitialized value。

state 的值跨 run 保留。三次循环打印出 1 2 3，不是每次都 1。这是变量和常量的根本区别。

模型里的参数就是一组变量。神经网络的权重存在变量里，训练过程中反复运行训练图，不断更新这些张量。

占位符与 feed #

feed 用 tensor 值临时替换一个操作的输出。数据作为 run() 的参数提供。feed 只在调用它的方法内存在，方法结束就消失。

最常见的用法，用 tf.placeholder() 创建占位符：

python
input1 = tf.placeholder(tf.float32)
input2 = tf.placeholder(tf.float32)
output = tf.multiply(input1, input2)

with tf.Session() as sess:
    print(sess.run([output], feed_dict={input1: [7.], input2: [2.]}))
    # [array([14.], dtype=float32)]

feed_dict 的键是占位符张量对象本身，值是 numpy 数组或 Python 列表。注意返回结果外面套了一层 list，因为你传的 [output] 是列表。

简化一点，直接传单个张量：

python
a = tf.placeholder(dtype=tf.float32)
b = tf.placeholder(dtype=tf.float32)
add = a + b
product = a * b

with tf.Session() as sess:
    sess.run(tf.global_variables_initializer())
    print(' a + b =  {0}'.format(sess.run(add, feed_dict={a: 3, b: 4})))
    print(' a * b =  {0}'.format(sess.run(product, feed_dict={a: 3, b: 4})))
    # 一次取出两个节点的值
    print(' {0}'.format(sess.run([add, product], feed_dict={a: 3, b: 4})))

最后那行 sess.run([add, product], ...) 一次取两个节点。这是 TF 1.x 的标准写法，能省的重复计算都省掉。

a + b 里没有占位符的显式声明形状，TF 会用 feed 进来的值推断。占位符也可以显式写形状：

python
x = tf.placeholder(tf.float32, shape=[None, 784])
y = tf.placeholder(tf.float32, shape=[None, 10])

None 表示这一维大小待定，多半就是 batch 维。写清形状有个好处：图建好就能查出形状不匹配，不用等到跑数据。

算术与矩阵 #

常用 op 一览：

类别 op 说明
算术 tf.add tf.subtract tf.multiply tf.divide 逐元素
矩阵 tf.matmul 矩阵乘

python
a = tf.constant([[1.0, 2.0]])
b = tf.constant([[3.0, 4.0]])

c = tf.add(a, b)          # 建节点
d = tf.multiply(a, b)     # 建节点

    #  array([[3., 8.]], dtype=float32),
    #  array([[14.]], dtype=float32)]

用变量做累加 #

下面这个例子把变量、占位符、assign、feed 全用上了。任务是对一组数求和再算平均：

python
h_sum = tf.Variable(0.0, dtype=tf.float32)
h_vec = tf.constant([1.0, 2.0, 3.0, 4.0])

# 待添加的数
h_add = tf.placeholder(tf.float32)
# 添加之后的值
h_new = tf.add(h_sum, h_add)
# 更新
update = tf.assign(h_sum, h_new)

with tf.Session() as sess:
    sess.run(tf.global_variables_initializer())

    print('h_sum', sess.run(h_sum))        # h_sum 0.0
    print('h_vec', sess.run(h_vec))        # h_vec [1. 2. 3. 4.]

    for i in range(4):
        sess.run(update, feed_dict={h_add: sess.run(h_vec[i])})
        print('h_sum', sess.run(h_sum))
        # h_sum 1.0
        # h_sum 3.0
        # h_sum 6.0
        # h_sum 10.0

    print('The mean is:', sess.run(h_sum) / 4.0)      # The mean is: 2.5

有个细节值得盯一眼：sess.run(h_vec[i])。h_vec 是个常量张量，h_vec[i] 是对它取索引，返回的又是一个张量。所以这里 run 了两次——内层 run 拿到单个数，外层 run 执行 assign。符号世界里的取值要一层层 run 出来，这是常态。

同样的活，用 InteractiveSession 写：

python
sess = tf.InteractiveSession()
sess.run(tf.global_variables_initializer())

print('h_sum', h_sum.eval())
print("h_vec", h_vec.eval())
print("vec", h_vec[0].eval())

for i in range(4):
    update.eval(feed_dict={h_add: h_vec[i].eval()})
    print('h_sum =', h_sum.eval())

sess.close()

对比一下就看出 InteractiveSession 的价值：不用每次都写 sess.run，直接 .eval()。代码短了，可读性也上来了。

十、一个完整的小例子 #

这一节做二元线性回归。目的是把「准备数据 → 构造模型 → 求解模型」这套流程走一遍。

TF 求解有个好处：不用管反向传播。你只写前向和损失，梯度它自己算。

准备数据 #

python
import numpy as np

def genDate(numPoints, bias, variance):
    """
    :param numPoints: 实例个数，两维数据
    :param bias: 偏向值
    :param variance: 变化幅度
    返回 x 和 y
    """
    x = np.zeros(shape=(numPoints, 2))
    y = np.zeros(shape=numPoints)
    for i in range(0, numPoints):
        # x 形如 [[1,0],[1,1],[1,2]...]
        x[i][0] = 1
        x[i][1] = i
        # y 加正态噪声
        y[i] = i + np.random.normal(loc=bias, scale=variance, size=None)
    return (np.array(x, dtype='float32').reshape(numPoints, 2),
            np.array(y, dtype='float32').reshape(numPoints, 1))

x_data, y_data = genDate(100, 25, 3)
print(x_data.shape, y_data.shape)

x 的第一列恒为 1，这一列就是给截距项留的位置。第二列是自变量。y 在自变量基础上加了正态噪声，噪声均值 25、标准差 3。这个数据天生带一个大的截距，正好用来考验模型。

reshape 到 (n, 1) 是有意为之。后面 tf.matmul 的结果要和 y_data 相减，形状得对齐。

画个散点 #

python
import matplotlib.pyplot as plt
from mpl_toolkits.mplot3d import Axes3D

fig = plt.figure(1, figsize=(8, 4))
ax = Axes3D(fig)

ax.set_zlabel('Z')
ax.set_ylabel('Y')
ax.set_xlabel('X')

ax.scatter(x_data[:, 0], x_data[:, 1], y_data, c='r', s=1)

因为 x 有两维、y 有一维，散点正好落在三维空间的一个面上，画出来是张平面加噪声的样子。

建图求解 #

python
# 构造二元线性回归模型
b = tf.Variable(1.0)
w = tf.Variable(tf.ones([2, 1]))
y = tf.matmul(x_data, w) + b

# 均方差损失
cost = tf.reduce_mean(tf.square(y - y_data))
# 也可以换成绝对损失
# cost = tf.reduce_mean(tf.abs(y - y_data))

# 梯度下降，传入学习率
optimizer = tf.train.GradientDescentOptimizer(0.0001)
# 迭代目标：最小化损失
train = optimizer.minimize(cost)

# 初始化变量
init = tf.global_variables_initializer()

# 设置 GPU 按需分配
config = tf.ConfigProto()
config.gpu_options.allow_growth = True

with tf.Session(config=config) as sess:
    sess.run(init)
    for step in range(100000):
        sess.run(train)
        if step % 10000 == 0:
            print('迭代次数{0}:W->{1},b->{2},{3}'.format(
                step, sess.run(w), sess.run(b), sess.run(cost)))
    rw = sess.run(w)
    rb = sess.run(b)

几个关键位置。

tf.matmul(x_data, w) 里的 x_data 是 numpy 数组，不是张量。TF 会自动把它转成 tf.constant 塞进图里。这个隐式转换方便，但也是图变大的原因之一。

optimizer.minimize(cost) 这一行干了三件事：对 cost 求梯度、创建更新参数的 op、返回这个 op。反向传播的细节全在这里面，你不用管。

学习率 0.0001 这个值不是随便写的。用梯度下降解多元线性回归，学习率大了会震荡不收敛。把它从 0.0001 改成 0.1，损失会来回跳，永远落不下去。

循环十万次看着吓人，但每次 run 走的是编译好的图，实际比 Python 循环快得多。

画出拟合面 #

python
# 计算预测结果
X, Y = np.meshgrid(x_data[:, 0], x_data[:, 1])
Z = rb + rw[0] * X + rw[1] * Y

# 绘制拟合面
ax.scatter(X, Y, Z, 'b--', s=1)

拟合面上的点是蓝色的，原始数据点红色的。均方差损失下，拟合面会更贴近噪声的中心。

换成绝对损失函数，同样的迭代次数，拟合面会略微偏向中位数而不是均值。两者效果都不算差，均方差在小噪声下更平滑，这是实测结论。

不用 TF 也能解 #

同一个问题，手写梯度下降或者调 sklearn 都能解。这段代码值得看一遍，因为它是框架帮你隐藏掉的那部分：

python
import numpy as np
from sklearn import linear_model
import matplotlib.pyplot as plt
from mpl_toolkits.mplot3d import Axes3D

def gradientDescent(x, y, theta, alpha, m, numIterations):
    """
    损失函数取 L(θ) = 1/(2m) * Σ(h(xi) - yi)^2
    :param x: 训练集数据
    :param y: 输出
    :param theta: 估计的参数向量，依次为 b, w1, w2...
    :param alpha: 梯度下降的步长
    :param m: 样本总数
    :param numIterations: 迭代次数
    返回最后迭代值，即局部极小值
    """
    # 构建 x 的增广矩阵，第一列补 1
    temp = np.ones([x.shape[0], x.shape[1] + 1])
    temp[:, 1:] = x
    x = temp
    xTrans = x.transpose()

    for i in range(0, numIterations):
        # hypothesis = X * θ
        hypothesis = np.dot(x, theta)
        # 误差
        loss = hypothesis - y
        # 梯度 x' * E
        gradient = np.dot(xTrans, loss) / m
        # 更新参数
        theta = theta - alpha * gradient
    return theta

gradient = np.dot(xTrans, loss) / m 这一行就是整个反向传播的等价物。对均方差损失来说，梯度恰好能写成这个漂亮的矩阵形式。换成别的损失，这一行就得重推。

继续：

python
x, y = genDate(100, 25, 3)

m, n = np.shape(x)
n = n + 1            # 加了增广列

numIterations = 100000
alpha = 0.0005
theta = np.ones(n)

theta = gradientDescent(x, y, theta, alpha, m, numIterations)
print('theta', theta)

# 用自带库求解，结果应该与梯度下降接近
regr = linear_model.LinearRegression()
regr.fit(x, y)

print('coefficients')
print(regr.coef_)
print('intercept')
print(regr.intercept_)

这里有个有趣的现象：两种方法求出来的参数不一样，但从图形上看拟合效果差不多。原因是多元线性回归有多个解，这多个解都能让均方差最小。数据的第二列是 0..99 的等差数列，和第一列的常数 1 之间没有共线性问题，但噪声会让解的落点有漂移。

sklearn 的 fit 用的是解析解（最小二乘），gradientDescent 用的是迭代解。前者一步到位，后者要靠学习率和迭代次数磨。这就是框架时代之前，大家为什么纠结「优化器怎么选」的原因。

三行代码的对照 #

回到框架的价值上。同一个线性回归，三种写法的代码量：

写法 核心代码行数 梯度 设备
纯 numpy ~20 行 手推公式 仅 CPU
手写梯度下降 ~25 行 手推公式 仅 CPU
Theano ~12 行 T.grad 自动 CPU/GPU
TF 1.x ~8 行 minimize 自动 CPU/GPU

差别不在行数，在「换个模型要改多少」。纯 numpy 换模型要重推梯度，TF 换模型只改前向那几行。这个杠杆效应随模型复杂度放大，两层网络看不出来，五十层网络就天差地别。

十一、两个框架的对比 #

把前面的内容收一下。

维度 Theano TensorFlow 1.x
首次发布 2007 前后 2015
建图 每个表达式自带 全局默认图
执行入口 theano.function(...) Session.run(...)
编译时机 调 function 时编译 建图时增量编译，run 时调度
微分 T.grad(cost, [w, b]) tf.gradients / optimizer.minimize
参数 theano.shared tf.Variable + 初始化 op
输入 符号变量直接当参数 tf.placeholder + feed_dict
设备切换 改 .theanorc 文件 图里写 with tf.device(...)
调试手段 加 outputs 重编译 加 outputs 重新 run
GPU 配置 device=cuda tf.test.is_gpu_available()
现状 2018 年停止维护 1.x 已停止演进，2.x 为主

差异的根子在抽象层次。Theano 是「函数级」的框架，一张图对应一个函数，编译单位也是函数。TensorFlow 是「程序级」的框架，一张图对应整个程序，编译单位是子图。

函数级的好处是简单、可预测、调试范围小。程序级的好处是能跨语句优化、能分布式切分、能导出成文件给别人跑。

代价也很明显。程序级的图会把所有中间状态都留在里面，改一行代码就得重建整张图。Theano 的函数级做法虽然编译慢，但每次编译的范围清楚。

还有一个维度值得单独说：动态图与静态图。

Theano 和 TF 1.x 都是静态图。图先建好，然后往里灌数据。这叫 define-and-run。

PyTorch 是动态图。代码执行到哪行，图就建到哪行，用 Python 的控制流直接当模型的控制流。这叫 define-by-run。写 if 就真的是 if，写 for 就真的是 for。

静态图在部署上有优势：图能序列化、能脱离 Python 运行、能做全局优化。动态图在开发上有优势：能打 Python 断点、能逐行 print、报错栈指向你写的那行。

TF 2.x 的答案是两边都要：默认 Eager，写起来像 PyTorch；需要性能时用 tf.function 把它 trace 成静态图。这个折中方案，本质上是把 Theano 那套东西封装成了一个装饰器。

所以回到开头那句话。Theano 没了，但它的每一个想法都还活着，只是换了个名字藏在后面的框架里。

十二、易错点速查 #

按踩坑的频率排。

Session 相关 #

现象 原因 修法
打印出 Tensor("xxx:0", ...) 这是建图阶段，没执行 sess.run(x) 或 x.eval()
RuntimeError: Attempting to use uninitialized value 没跑初始化 op sess.run(tf.global_variables_initializer())
忘记 sess.close() 资源不释放 用 with tf.Session() as sess
InteractiveSession 下 run 报错 默认会话被覆盖 显式传 session=sess

print 出张量这件事，是新手第一天就会遇到的困惑。原因就是「先建图再执行」——你打印的那个对象是节点描述，不是结果。TF 2.x 里打印直接出数值，所以很多人换到 2.x 之后反而不理解老代码为什么这么写。

类型与形状 #

现象 原因 修法
TypeError: Fetch argument ... has invalid type 把 numpy 数组传给 run 传 Tensor 对象
形状不匹配 matmul 的两边维度对不上 检查 [m,k] x [k,n]
ValueError: Cannot feed value of shape ... feed 的值形状与占位符不符 显式给占位符写 shape
常量与变量相加报 dtype 错 float32 与 float64 混用 统一用 tf.float32

TF 1.x 对 dtype 很敏感。tf.constant([1.0, 2.0]) 默认是 float32，但 np.random.randn(...) 是 float64。混着用会在某个 op 上炸，报错位置离你写错的地方很远。

梯度与训练 #

现象 原因 修法
损失不降，来回震荡 学习率太大 从 1e-4 往下试
损失变 nan 学习率太大或没有归一化 降学习率、标准化输入
参数一直是初始值 没 run 训练 op 检查 sess.run(train) 有没有在循环里
梯度为 None 变量没参与前向计算 顺着 tf.gradients 的输入检查

线性回归那个例子里，学习率从 0.0001 改成 0.1 就会震荡。这个坑在老 TF 代码里极其常见，因为 GradientDescentOptimizer 不会给你任何提示。

一句话总结 #

记住三件事就够了。

打印出来是张量，说明你在建图，不在执行。 要数值就 run。

变量先初始化，再使用。 忘了就报 uninitialized value。

学习率从小往大试，不要反过来。 大了震荡，小了不收敛，中间的窗口比你想的窄。

把这三条记住，剩下的报错基本都是版本和环境问题，查表就行。
