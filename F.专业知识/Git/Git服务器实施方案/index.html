Git服务器实施方案

Windows 局域网 Git 服务器实施方案 #

方案：OpenSSH Server + 裸仓库（无第三方软件、无数据库） 目标：D:\GitServer 存放全部仓库数据，C:\GitServer 作为永久逻辑入口，局域网内任意机器可 clone / push / pull 读者前提：会用命令行，不需要服务器运维经验

快速执行清单 #

如果不想读全文，按顺序做这 9 步：

# 动作 需要管理员
1 跑 scripts\01-环境检查.ps1，对照第 2 节确认现状 否

3 安装 OpenSSH Server（第 5.1 节） 是
4 建目录 + 建逻辑入口联接（第 5.2 节 / 02-安装与配置.ps1） 是
5 改 sshd_config（第 5.3 节 / 脚本自动完成） 是
6 放公钥并收紧 ACL（第 5.4 节） 是
7 建第一个裸仓库（第 5.5 节） 否
8 客户端配置 ~/.ssh/config 并首次推送（第 5.6 节） 否
9 跑验收测试（第 6 节） 否

一条命令跑完 3~5 步（管理员 PowerShell）：

1. 为什么是这个方案 #

对比项 本方案（SSH + 裸仓库） Gitea
额外软件 无（Windows 自带 OpenSSH） 需下载 ~100MB 二进制
常驻进程 sshd（系统服务） gitea.exe + 数据库
Web 界面 无 有
迁移成本 极低（数据自包含，无数据库记录绝对路径） 中（需改 app.ini 多处绝对路径 + 校验）
维护负担 接近零 需跟进版本升级

第一性原理：git 仓库是自包含的内容寻址数据库，一个 .git 目录含全部历史与分支，没有中心注册表。所谓"git 服务器"= 仓库数据 + 传输通道。数据传输层可以随便换，数据本身永远搬得走。

2. 环境现状（本机实测，2026-09-01） #

项目 实测值 影响
操作系统 Windows 11，NT 10.0，Build 26200 支持 OpenSSH Server 可选功能
主机名 PC 局域网内建议用主机名而非 IP（IP 会变）
登录用户 liuluhua（C:\Users\liuluhua） 默认用它作为 SSH 登录账号
局域网 IP 192.168.43.82（WLAN） 另有 VMware 虚拟网卡 192.168.198.1、192.168.32.1，Hyper-V 172.26.176.1
Git for Windows 2.54.0，C:\Programs\Git cmd 目录含 git.exe / git-upload-pack.exe / git-receive-pack.exe
Git 是否在系统 PATH 是，C:\Programs\Git\cmd 在机器级 PATH 中 sshd 服务可直接解析 git，无需额外配置
OpenSSH 客户端 已装（C:\Windows\System32\OpenSSH，在机器级 PATH） 够用
OpenSSH Server 未安装（无 sshd.exe） 必须执行安装步骤
D 盘 128 GB 总容量，53 GB 可用 够用，注意容量规划
C 盘 349 GB 总容量，206 GB 可用 逻辑入口建在 C 盘
D:\GitServer 已存在，空目录 直接可用
C:\GitServer 不存在 待建为联接
~/.ssh 仅有 known_hosts，无密钥对 需生成
当前会话权限 非管理员 安装步骤需右键「以管理员身份运行」

三个必须注意的现状 #

  1. OpenSSH Server 未安装：C:\Windows\System32\OpenSSH 下只有 ssh.exe 等客户端，没有 sshd.exe。这是主要工作量。
  2. 系统里有两个 git：C:\Programs\Git（官方 2.54.0）和 WorkBuddy 自带的便携版（C:\Users\liuluhua\.workbuddy\vendor\PortableGit）。机器级 PATH 里只有官方那个，sshd 服务会解析到官方版本，这是正确的。但你在 WorkBuddy 终端里敲 git --version 可能看到便携版 2.55.0 —— 那是终端临时注入的，不影响服务器。第 6 节有验证命令。
  3. IP 可能变：192.168.43.82 是 DHCP 地址。clone 地址里请写主机名 PC，不要写 IP。

约定：标记 (管理员) 的步骤必须在「以管理员身份运行」的 PowerShell 中执行。 打开方式：开始菜单搜索 PowerShell → 右键 → 以管理员身份运行。

5.0 环境检查（非管理员即可） #

powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\01-环境检查.ps1

对照输出与第 2 节表格。若 OpenSSH Server 显示为 NotPresent，继续下一步。

5.1 安装 OpenSSH Server (管理员) #

方式一：PowerShell（推荐，可复现）

powershell
# 安装（约 1-2 分钟，进度条走完返回 Online : True）
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0

# 启动并设为开机自启
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic

# 确认状态
Get-Service sshd | Format-Table Name, Status, StartType

方式二：图形界面

设置 → 系统 → 可选功能 → 查看功能 → 勾选 OpenSSH 服务器 → 安装。

验收标准：Get-Service sshd 返回 Status = Running、StartType = Automatic。

若 Add-WindowsCapability 报错 0x800f0954：通常是 WSUS 策略禁用了可选功能下载。改用方式二，或临时执行 Set-ItemProperty -Path HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU -Name UseWUServer -Value 0 后重启 Windows Update 服务再试。

5.2 建立目录结构与逻辑入口 (管理员) #

这一步是整个"可迁移"设计的核心，务必不要跳。

powershell
# 1) 三层目录：数据 / 配置 / 备份
New-Item -ItemType Directory -Force -Path 'D:\GitServer\repos'
New-Item -ItemType Directory -Force -Path 'D:\GitServer\config'
New-Item -ItemType Directory -Force -Path 'D:\GitServer\backup'

# 2) 逻辑入口：把 C:\GitServer 联接到 D:\GitServer
New-Item -ItemType Junction -Path 'C:\GitServer' -Value 'D:\GitServer'

# 3) 验证
cmd /c dir C:\GitServer

验收标准：dir C:\GitServer 能看到 repos、config、backup 三个目录。

为什么这么做：所有 clone 地址和钩子脚本都写 C:\GitServer\...。将来仓库搬到 E 盘甚至另一块硬盘，只需删掉旧联接、重建指向新位置，一条命令搞定，所有客户端零改动：

powershell
# 未来迁移时的全部操作（管理员）：
Stop-Service sshd
(New-Item -ItemType Junction -Path 'C:\GitServer.tmp' -Value 'E:\NewLocation') | Out-Null  # 先把数据 robocopy 过去
cmd /c rmdir C:\GitServer            # 删联接（不会删目标数据）
New-Item -ItemType Junction -Path 'C:\GitServer' -Value 'E:\NewLocation'
Start-Service sshd

警告：删联接请用 rmdir（不带 /S），绝不要用 rmdir /S 或 Remove-Item -Recurse —— 某些 Windows 版本会顺着联接删掉目标目录里的真实数据。更保险的做法是在资源管理器里删除联接图标。

5.3 配置 sshd (管理员) #

配置文件在 C:\ProgramData\ssh\sshd_config（注意是 ProgramData 不是 Program Files）。

先备份：

powershell
Copy-Item 'C:\ProgramData\ssh\sshd_config' 'D:\GitServer\config\sshd_config.orig' -Force

需要确认/修改的项：

ini
Port 22                        # 保持默认
PubkeyAuthentication yes       # 必须是 yes，且行首无 #
AuthorizedKeysFile .ssh/authorized_keys   # 用用户目录下的文件
PasswordAuthentication yes     # 先保持 yes，验收通过后再改 no

关键坑位：文件末尾如果有下面这两行且未注释，管理员账号会改从 C:\ProgramData\ssh\administrators_authorized_keys 读公钥，导致你放在用户目录下的公钥完全失效、反复提示输入密码：

ini
Match Group administrators
       AuthorizedKeysFile __PROGRAMDATA__/ssh/administrators_authorized_keys

不同 Windows 版本默认状态不一致（有的版本默认注释、有的默认启用）。先检查：

powershell
Get-Content 'C:\ProgramData\ssh\sshd_config' | Select-String -Pattern 'Match Group|AuthorizedKeysFile'

若输出里有未注释的 Match Group administrators，在两行行首加 # 注释掉。改完必须重启服务：

powershell
Restart-Service sshd

另一种做法是保留该配置、把公钥写进 C:\ProgramData\ssh\administrators_authorized_keys 并严格设 ACL。二者选一，不要两个都配，否则排错时会被自己绕进去。本文采用「注释掉 + 用用户目录」的做法。

以上 5.3 全部修改由 scripts\02-安装与配置.ps1 自动完成，脚本会先备份原文件。

5.4 部署公钥并收紧 ACL (管理员) #

在客户端机器生成密钥（若已有 ~/.ssh/id_ed25519.pub 可跳过）：

bash
ssh-keygen -t ed25519 -C "your-name@device"
# 一路回车，或设置一个 passphrase（推荐）
cat ~/.ssh/id_ed25519.pub

把输出的整行内容（形如 ssh-ed25519 AAAA... your-name@device）复制到剪贴板。

在服务器写入授权文件：

powershell
# 目录
$ak = "$env:USERPROFILE\.ssh"
New-Item -ItemType Directory -Force -Path $ak
New-Item -ItemType File -Force -Path "$ak\authorized_keys"
# 追加公钥（每行一个，多个客户端就追加多行）
Add-Content -Path "$ak\authorized_keys" -Value 'ssh-ed25519 AAAA... your-name@device' -Encoding UTF8

# 收紧权限：继承必须断开，只留 SYSTEM / Administrators / 本人
icacls.exe "$ak\authorized_keys" /inheritance:r
icacls.exe "$ak\authorized_keys" /grant "SYSTEM:(F)" "Administrators:(F)" "$env:USERNAME:(R)"

验收标准：icacls.exe "$env:USERPROFILE\.ssh\authorized_keys" 输出中不应出现 Users、Everyone、Authenticated Users 等条目。只要有多余的组拥有写权限，OpenSSH 会静默拒绝加载该文件，表现为"明明配了公钥还是让输密码"。

5.5 创建第一个裸仓库 #

在服务器上（无需管理员）：

bash
git init --bare C:/GitServer/repos/demo.git

注意：走 C:\GitServer 逻辑入口建仓库，不要直接写 D:\...，保持路径一致性。

多人共享时加 --shared：

bash
git init --bare --shared C:/GitServer/repos/team-project.git

5.6 客户端配置与首次推送 #

客户端 ~/.ssh/config（没有就新建，权限 600）：

Host git-server
    HostName PC                 # 用主机名，避免 IP 变动
    User liuluhua
    Port 22
    IdentityFile ~/.ssh/id_ed25519

克隆地址统一格式：

bash
git clone ssh://git-server/c/GitServer/repos/demo.git

拆开看：ssh:// + 主机别名 + /c/GitServer/repos/仓库名.git 注意盘符是小写 c，路径分隔符是正斜杠 /。

已有本地仓库要推上去：

bash
git remote add origin ssh://git-server/c/GitServer/repos/demo.git
git push -u origin main

6. 验收测试 #

按顺序跑，任一项失败就停下查第 8 节。

bash
# T1 基础连通 + 免密登录（不应提示输密码）
ssh git-server

# T2 服务端 git 解析正确（应输出官方 Git 路径）
ssh git-server "where git"
#   期望：C:\Programs\Git\cmd\git.exe
#   若输出 PortableGit 路径 → 见第 7 节 P2

# T3 服务端能看到仓库目录
ssh git-server "dir C:\GitServer\repos"

# T4 实际克隆
git clone ssh://git-server/c/GitServer/repos/demo.git /tmp/demo-test

# T5 推送往返
cd /tmp/demo-test && echo hello > a.txt && git add . && git commit -m "test" && git push

# T6 另一端再克隆，确认能拿到刚才的提交
git clone ssh://git-server/c/GitServer/repos/demo.git /tmp/demo-test2 && cd /tmp/demo-test2 && git log --oneline -1

T1~T6 全绿之后，才回头关闭密码登录 (管理员)：

powershell
(Get-Content 'C:\ProgramData\ssh\sshd_config') -replace '^\s*#?\s*PasswordAuthentication\s+.*$', 'PasswordAuthentication no' | Set-Content 'C:\ProgramData\ssh\sshd_config' -Encoding UTF8
Restart-Service sshd

关完后重跑 T1，确认仍能登录。

8. 注意事项（坑位清单） #

P1 — 公钥配了还是要求输密码 #

现象：Permission denied (publickey,keyboard-interactive) 排查顺序（命中率从高到低）：

  1. authorized_keys 的 ACL 有多余的组有写权限 → 用 icacls 重设（5.4 节）
  2. sshd_config 末尾 Match Group administrators 未注释 → 注释掉（5.3 节）
  3. 改完配置没重启 sshd → Restart-Service sshd
  4. 公钥格式被换行截断 → authorized_keys 里每个公钥必须是一整行
  5. 看日志：事件查看器 → 应用程序和服务日志 → OpenSSH/Operational

P2 — 服务端解析到错误的 git #

现象：git clone 报 git-upload-pack: command not found 原因：sshd 服务读的是机器级 PATH，不是你交互终端的 PATH 处理：

powershell
$m = [Environment]::GetEnvironmentVariable('Path','Machine')
if ($m -notlike '*C:\Programs\Git\cmd*') {
    [Environment]::SetEnvironmentVariable('Path', "C:\Programs\Git\cmd;$m", 'Machine')
}
Restart-Service sshd

本机遇到的特殊情况：C:\Programs\Git\cmd 已在机器级 PATH，但 WorkBuddy 终端会临时把 PortableGit 插到最前面。判别方法是不要用本机终端自检，要用 ssh git-server "where git" 从外部问服务器。

P3 — 删联接时误删真实数据 #

rmdir /S C:\GitServer 或 Remove-Item -Recurse 在部分 Windows 版本上会穿过联接删除目标目录内容。只用 cmd /c rmdir C:\GitServer（不带 /S）或资源管理器删除。

P4 — 防火墙拦了 22 端口 #

安装 OpenSSH Server 通常会自动加防火墙规则，但不保证。客户端若连不上：

powershell
# 服务器（管理员）
New-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -DisplayName 'OpenSSH Server (sshd)' `
  -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22

P5 — 钩子脚本换行符 #

Windows 下写的 bash 钩子脚本若存成 CRLF，git 执行时报 /bin/sh^M: bad interpreter。钩子脚本一律用 LF 换行：

bash
git config core.autocrlf false
# 或用 VS Code 右下角切换 CRLF → LF

P6 — 裸仓库里直接编辑文件 #

裸仓库没有工作区，只有 git 内部对象。不要在 *.git 目录里手工改文件。要改内容必须 clone 出来改完 push 回去。

P7 — 大文件 #

git 不适合存大二进制文件（视频、模型权重、压缩包）。单仓库超过 1~2 GB 后 clone 会明显变慢。超过 50 MB 的文件建议用 Git LFS 或干脆不放进 git。

P8 — 未推送的提交不在服务器上 #

服务器只保存别人 push 上去的东西。某台客户端上未推送的提交，换机器、重装系统就没了。重要的工作当天 push。

P9 — D 盘剩余空间 #

当前 53 GB。跑 03-校验全部仓库.sh 时会输出每个仓库体积，超过 40 GB 就该考虑换盘或清理历史大文件了。

P10 — 不要同时用两种访问方式写同一个仓库 #

同一个裸仓库同时被 SSH 和 SMB（文件共享）写入，可能损坏对象库。选定 SSH 一种通道。

9. 日常运维 #

新建仓库（标准动作） #

bash
# 在服务器上
git init --bare C:/GitServer/repos/新项目.git

# 在客户端
git remote add origin ssh://git-server/c/GitServer/repos/新项目.git
git push -u origin main

完整性校验 #

bash
bash /c/GitServer/config/scripts/03-校验全部仓库.sh
# 或指定根目录
bash /c/GitServer/config/scripts/03-校验全部仓库.sh /d/GitServer/repos

脚本对每个裸仓库跑 git fsck --full --strict 并统计对象数与提交数，任一仓库校验失败则以非零码退出。

镜像备份 #

bash
bash /c/GitServer/config/scripts/04-镜像备份.sh /d/GitServer/repos /d/GitServer/backup

首次执行对每个仓库做 git clone --mirror，之后再执行只做增量 remote update。备份必须与源仓库在不同物理磁盘上，否则硬盘坏了等于没备份。

当前 D:\GitServer 和 D:\GitServer\backup 在同一块盘，只能防误删、防不了硬盘故障。要真正防灾，备份目标请指向另一块盘或移动硬盘。

10. 迁移手册 #

场景 A：把仓库数据换到本机另一个盘（如 D: → E:） #

powershell
# 1) 停服务（管理员）
Stop-Service sshd

# 2) 带日志的镜像复制
robocopy D:\GitServer E:\GitServer /MIR /R:1 /W:1 /LOG:C:\robocopy-move.log /NP /NFL /NDL

# 3) 校验（必须做，不要相信复制工具）
bash ./scripts/03-校验全部仓库.sh /d/GitServer/repos   # 迁移前数字
bash ./scripts/03-校验全部仓库.sh /e/GitServer/repos   # 迁移后数字，必须完全一致

# 4) 重指向逻辑入口
cmd /c rmdir C:\GitServer
New-Item -ItemType Junction -Path 'C:\GitServer' -Value 'E:\GitServer'

# 5) 起服务
Start-Service sshd

客户端零改动 —— 这正是 5.2 节建逻辑入口的价值。

场景 B：换一台新机器 #

  1. 新机器按本文第 5 节重做一遍（安装 OpenSSH Server + 建目录 + 建联接 + 配 sshd + 放公钥）
  2. 用 robocopy 或移动硬盘把 repos 目录搬过去，落到新机器的 E:\GitServer\repos
  3. 建联接 C:\GitServer → E:\GitServer
  4. 跑校验脚本比对前后数字
  5. 客户端 ~/.ssh/config 里的 HostName 改成新机器主机名，其余不变

注意：裸仓库数据与操作系统、git 版本无关，跨机器、跨 git 版本搬移都是安全的。

场景 C：确认迁移成功 #

三条硬标准，缺一不可：

  • 每个仓库 git fsck --full --strict
  • 每个仓库 git rev-list --all --count
  • 每个仓库 git count-objects -v

11. 故障排查速查表 #

现象 最可能原因 处理
Permission denied (publickey) authorized_keys 权限过宽 / Match Group 未注释 P1
git-upload-pack: command not found 服务端 PATH 无 git P2
连不上（超时） 防火墙 / 服务未启动 / 主机名解析失败 P4，再 Get-Service sshd；主机名不通就临时用 IP
fatal: '...' does not appear to be a git repository clone 路径写错（盘符大小写 / 反斜杠） 用 /c/GitServer/repos/xxx.git 格式
能 clone 但 push 被拒 裸仓库权限不足 / 非 bare 仓库 确认是 --bare；多人场景加 --shared
push 报 deny non-fast-forward 远端有新提交 先 git pull --rebase 再 push
钩子不执行 换行符 CRLF / 无执行权限 P5
服务启动失败 sshd_config 语法错误 用备份的 sshd_config.orig 覆盖回去

日志位置：事件查看器 → 应用程序和服务日志 → OpenSSH → Operational

12. 回滚方案 #

想撤掉 操作（管理员）
只恢复 sshd 配置 Copy-Item D:\GitServer\config\sshd_config.orig C:\ProgramData\ssh\sshd_config -Force; Restart-Service sshd
停掉服务但保留数据 Stop-Service sshd; Set-Service sshd -StartupType Manual
完全卸载 OpenSSH Server Remove-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0（仓库数据不受影响）
删除逻辑入口 cmd /c rmdir C:\GitServer（不要用 /S，见 P3）

任何情况下仓库数据都在 D:\GitServer\repos 里，卸载服务端软件不会碰它。

附录 A：新建专用 git 账号（多人共享时推荐） #

沿用个人账号意味着 SSH 通道拥有你账号的全部权限。多人共享时建议隔离：

powershell
# 管理员 PowerShell
$pwd = Read-Host -AsSecureString "为 git 账号设置密码"
New-LocalUser -Name 'git' -Password $pwd -FullName 'Git Server' -Description 'Git repository access' -PasswordNeverExpires:$true
# 不加入 Administrators 组 → 天然避开 administrators_authorized_keys 那个坑

# 授权目录
icacls.exe 'D:\GitServer' /grant 'git:(OI)(CI)(M)'

然后公钥放 C:\Users\git\.ssh\authorized_keys，客户端 ~/.ssh/config 里 User git。 注意新账号属标准用户组，sshd_config 里的 Match Group administrators 对它不生效，无需注释。

附录 B：定期备份计划任务 #

powershell
# 管理员 PowerShell：每周日凌晨 3 点跑镜像备份
$action  = New-ScheduledTaskAction -Execute 'C:\Programs\Git\bin\bash.exe' `
           -Argument '-c "/d/GitServer/config/scripts/04-镜像备份.sh /d/GitServer/repos /e/GitBackup"'
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Sunday -At 03:00
Register-ScheduledTask -TaskName 'GitRepoMirrorBackup' -Action $action -Trigger $trigger `
           -User 'liuluhua' -RunLevel Highest -Force

把 /e/GitBackup 换成另一块物理磁盘上的路径，否则备份没有防灾价值。
