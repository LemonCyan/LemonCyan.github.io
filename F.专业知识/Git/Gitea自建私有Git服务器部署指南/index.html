Gitea自建私有Git服务器部署指南

Gitea 自建私有 Git 服务器部署指南 #

在局域网或者自己的云服务器上搭 Git 仓库，大家一般会在三种路子里纠结：

  1. 纯命令行（OpenSSH + 裸仓库）：最底层、最纯粹。但没有 Web 界面，查代码得靠本地拉取，新人加 SSH 公钥要登服务器改 authorized_keys，权限控制全靠文件系统 ACL，体验相当硬核。
  2. GitLab：大而全的企业级怪兽。功能应有尽有，但它是名副其实的“内存粉碎机”，空载起步就吃 4GB~8GB 内存，稍微动一下 CPU 风扇狂转，小团队或者闲置小主机根本吃不消。
  3. Gitea：极客与小团队的终极偷懒解法。用 Go 语言编写，编译后就是一个百来 MB 的二进制文件，内存占用只要几十 MB；自带 SQLite 零门槛数据库，连 MySQL 都不用装；网页端几乎 1:1 复刻 GitHub，仓库管理、代码审阅（PR）、Issue 看板、分支保护、用户权限一应俱全。

本文直给三种主流部署方案：

  • 方案一：Docker Compose 一键拉起（全平台首选，容器化推荐）
  • 方案二：Linux 原生二进制 + Systemd 部署（Linux 服务器推荐，免 Docker 极简极速）
  • 方案三：Windows 本地原生部署（Windows PC / 工控机免 Docker 版）

顺便把局域网避坑配置与一键备份一次性讲透。

方案对比速览 #

对比项 手搓 OpenSSH + 裸仓库 GitLab Gitea（推荐）
安装难度 繁琐（配 ACL、配服务、改权限） 复杂（依赖众多、启动慢） 傻瓜式（开箱即用）
内存开销 几十 MB（系统 SSH 服务） 4GB ~ 8GB+（吃配置） ~50MB ~ 100MB（极度轻量）
Web 界面 ❌ 无 ✅ 全功能 ✅ 轻量级 GitHub 体验
数据库 ❌ 无 PostgreSQL / Redis 等一大堆 自带 SQLite 单文件，免维护
适用场景 极简自动化备份通道 几百上千人的大型企业团队 个人、小团队、工控机、家庭 NAS

方案一：Docker Compose 极简部署（全平台首选） #

只要机器上装了 Docker，这就是最省心的方案，一行命令起飞，升级维护只用换镜像版本。

1. 编写 docker-compose.yml #

找个空目录（例如 /opt/gitea 或 D:\Docker\gitea），新建 docker-compose.yml：

yaml
version: "3.8"

services:
  server:
    image: gitea/gitea:latest
    container_name: gitea
    restart: always
    environment:
      - USER_UID=1000
      - USER_GID=1000
      - GITEA__database__DB_TYPE=sqlite3
      - TZ=Asia/Shanghai          # 容器时区：跨平台通用，无需挂载宿主机时间文件
    volumes:
      # 持久化目录：配置、数据库和全部仓库都在这里，备份只拷这个目录即可
      - ./gitea-data:/data
    ports:
      - "3000:3000"   # Web 访问端口
      - "2222:22"     # Git SSH 端口（避开宿主机默认的 22 端口）
✦提示

时区避坑说明：很多 Linux Docker 教程习惯挂载宿主机的 /etc/timezone 和 /etc/localtime。在 Windows 下千万不要这么写，因为 Windows 根本没有这两个文件，Docker Desktop 会报错或创建空文件夹。直接在 environment 中配置环境变量 TZ=Asia/Shanghai，是全平台通用且最标准、最干净的做法。

2. 启动服务 #

在当前目录下直接后台启动：

bash
docker compose up -d

看到 Started 后，打开浏览器访问 http://<服务器局域网IP>:3000，直接进入图形化初始化页面。

方案二：Linux 原生二进制 + Systemd 部署（Linux 服务器首选，免 Docker） #

如果服务器是 Linux（Ubuntu / Debian / CentOS / Rocky 等），且不想装 Docker，直接运行官方编译好的单一二进制文件配合 systemd 守护进程，性能极高且几乎不占资源。

1. 安装基础依赖与创建 git 系统用户 #

为安全起见，绝不要使用 root 用户运行 Gitea，专门给它建一个独立的系统用户 git：

bash
# 1. 安装 git 依赖
# Ubuntu / Debian:
sudo apt update && sudo apt install -y git
# CentOS / RHEL / Rocky:
# sudo yum install -y git

# 2. 创建 git 系统用户
sudo adduser --system --shell /bin/bash --group --disabled-password --home /home/git git

2. 下载 Gitea 二进制程序 #

从官方源下载对应架构（以 64 位 x86_64 为例）的最新二进制文件，并赋予执行权限：

bash
# 下载官方最新二进制文件
sudo wget -O /usr/local/bin/gitea https://dl.gitea.com/gitea/latest/gitea-latest-linux-amd64

# 赋予可执行权限
sudo chmod +x /usr/local/bin/gitea

3. 创建目录结构与授权 #

Gitea 运行需要配置目录、数据目录和日志目录：

bash
# 创建工作目录和数据目录
sudo mkdir -p /var/lib/gitea/{custom,data,log}
sudo chown -R git:git /var/lib/gitea/
sudo chmod -R 750 /var/lib/gitea/

# 创建配置目录（初次配置时允许 git 用户写入，配置完成后收紧）
sudo mkdir /etc/gitea
sudo chown root:git /etc/gitea
sudo chmod 770 /etc/gitea

4. 配置 Systemd 后台自启服务 #

创建 /etc/systemd/system/gitea.service，实现开机自启、崩溃自动重启和后台静默守护：

bash
sudo bash -c 'cat <<EOF > /etc/systemd/system/gitea.service
[Unit]
Description=Gitea (Git with a cup of tea)
After=network.target

[Service]
RestartSec=2s
Type=simple
User=git
Group=git
WorkingDirectory=/var/lib/gitea/
ExecStart=/usr/local/bin/gitea web --config /etc/gitea/app.ini
Restart=always
Environment=USER=git HOME=/home/git GITEA_WORK_DIR=/var/lib/gitea

[Install]
WantedBy=multi-user.target
EOF'

5. 启动服务与放行防火墙 #

bash
# 重载 systemd 并启动 Gitea
sudo systemctl daemon-reload
sudo systemctl enable --now gitea

# 查看运行状态（看到 active (running) 即成功）
sudo systemctl status gitea

如果有系统防火墙，放行 3000（Web）端口：

bash
# Ubuntu (UFW)
sudo ufw allow 3000/tcp

# CentOS / Rocky (Firewalld)
sudo firewall-cmd --permanent --add-port=3000/tcp && sudo firewall-cmd --reload

打开浏览器访问 http://<服务器IP>:3000 进入初始化页面。

安全提示（初次网页配置完成后必做）：
网页引导安装完成后，系统会在 /etc/gitea/app.ini 生成配置文件，此时执行收紧权限防止篡改：
sudo chmod 750 /etc/gitea && sudo chmod 640 /etc/gitea/app.ini

方案三：Windows 本地原生部署（无 Docker 环境） #

如果服务器是 Windows（比如办公室的一台闲置 PC、工控机或 Windows Server），不想折腾 WSL2 和 Docker，直接跑原生单二进制文件更简单。

1. 准备目录与程序 #

  1. 访问 Gitea 官方下载页或 GitHub Release，下载 Windows 版本：
    gitea-windows-4.0-amd64.exe。
  2. 在大容量盘（例如 D: 盘）建立工作目录：
    powershell
    New-Item -ItemType Directory -Path "D:\Gitea"
  3. 将下载的 exe 文件复制到 D:\Gitea，并重命名为简洁的 gitea.exe。

2. 首次启动与初始化 #

在 D:\Gitea 目录下打开终端，敲入：

powershell
.\gitea.exe web

看到控制台输出 Listen: http://0.0.0.0:3000 后，不要关闭窗口，打开浏览器访问 http://localhost:3000（或 http://192.168.x.x:3000），即可看到首次配置引导。

提示：首次网页配置完成后，可以在终端按 Ctrl + C 退出前台运行，接着按下一步将其做成 Windows 后台服务。

3. 将 Gitea 注册为 Windows 后台自启服务 #

不能每次开机都手动开个黑色命令行窗口挂着，用 Windows 内置命令或 NSSM（推荐）把 Gitea 变成开机静默启动的系统服务。

方法 A：使用 Gitea 自带命令注册（最快）

以管理员身份打开 PowerShell，执行：

powershell
# 注册服务
sc.exe create gitea start= auto binPath= "\"D:\Gitea\gitea.exe\" web --config \"D:\Gitea\custom\conf\app.ini\""

# 启动服务
sc.exe start gitea
方法 B：使用 NSSM 守护（推荐，进程崩溃可自动拉起）

下载 NSSM (Non-Sucking Service Manager) 并丢到系统目录后：

powershell
# 打开图形化服务注册界面
nssm install gitea "D:\Gitea\gitea.exe" "web"
nssm set gitea AppDirectory "D:\Gitea"
nssm start gitea

之后即使重启电脑，Gitea 也会在系统后台自动拉起，谁都不用管。

核心配置与避坑指南（首次网页配置） #

打开浏览器进入初始化安装页面时，有几个参数至关重要，填错会导致局域网其他人拉不下代码：

+--------------------------------------------------------+
|                      Gitea 首次安装向导                 |
+--------------------------------------------------------+
| 数据库类型:         [ SQLite3                        ] |
| 仓库根路径:         [ 保持默认或指定大盘路径          ] |
| 运行系统用户:       [ git (Linux) / 默认 (Windows)   ] |
| 域名 (Domain):      [ 192.168.1.100                  ] |  <-- 别填 localhost！
| SSH 服务端口:       [ 2222                           ] |  <-- 避开 22
| HTTP 服务端口:      [ 3000                           ] |
| Gitea 基本 URL:     [ http://192.168.1.100:3000/     ] |  <-- 局域网克隆链接基准
+--------------------------------------------------------+

避坑 1：Gitea 基本 URL（ROOT_URL）不要留 localhost #

  • 问题：如果这里留了 http://localhost:3000/，在别人电脑的浏览器里点进仓库复制 Clone 链接时，链接就会变成 http://localhost:3000/xxx/repo.git，其他人直接 clone 报错。
  • 正解：一定要改成该服务器固定的局域网 IP 或内部域名，例如：
    http://192.168.1.100:3000/。

避坑 2：SSH 端口配置 #

Linux 或 Windows 自身通常已经占用了 22 端口，Gitea 内置的 SSH 服务器最好将端口设置为 2222（或其它空闲端口）。
如果懒得折腾 SSH 密钥，团队内部也可以直接走 HTTP/HTTPS 拉取代码，Git 凭据管理器会自动保存密码，同样非常顺畅。

避坑 3：生产环境关闭自主注册 #

如果不想局域网随便什么人连上来都能自己开账号，可以在安装页面展开可选设置，勾选：

  • 禁止用户自主注册（由管理员统一开账号）。
  • 启用访问限制（必须登录才能查看代码库）。

注意：安装页面最下方的管理员账号可以直接顺手建一个（比如账号 admin，密码设个强密码）。如果在安装阶段没填，注册的第一个普通账号会自动升为超级管理员。

配置文件微调（修改 app.ini） #

所有刚才在网页里填的配置，都会自动存放在：

  • Docker 模式：./gitea-data/gitea/conf/app.ini
  • Linux 原生模式：/etc/gitea/app.ini
  • Windows 原生模式：D:\Gitea\custom\conf\app.ini

如果以后局域网服务器 IP 变了，或者想调整配置，直接用文本编辑器改这个文件，重启服务即可生效。常见优化项：

ini
[server]
DOMAIN       = 192.168.1.100
HTTP_PORT    = 3000
ROOT_URL     = http://192.168.1.100:3000/
SSH_PORT     = 2222
START_SSH_SERVER = true      ; 开启 Gitea 自带的内置 SSH 服务

[service]
DISABLE_REGISTRATION = true  ; 禁止访客随意注册新账号
REQUIRE_SIGNIN_VIEW  = true  ; 必须登录后才能查看仓库（保证内网私密性）

[repository]
DEFAULT_BRANCH = main        ; 新建仓库默认分支名

客户端实战：克隆与推送 #

Gitea 启动后，用法跟 GitHub/Gitee 完全一样。

1. 创建仓库 #

在网页右上角点击 + -> 新建仓库，输入仓库名称（如 DemoProject），点击创建。

2. 本地项目推送到 Gitea #

无论是现有代码仓库还是新项目，网页上都会直接给出完整的指引代码：

bash
# 关联你的私有 Gitea 仓库
git remote add origin http://192.168.1.100:3000/your_name/DemoProject.git

# 推送代码（输入刚才在 Gitea 注册的账号密码）
git push -u origin main

客户端在第一次推送时会提示输入账号密码，Windows / macOS / Linux 的凭据管理器会自动记住，之后 git push、git pull 完全静默无感。

终极偷懒：一键备份与迁移 #

手搓 OpenSSH 裸仓库最大的优点是数据透明，而 Gitea 同样做到了极其清爽的数据隔离。所有的数据（包括 Issue、Wiki、提交、用户信息、头像）就两部分：

  1. 仓库文件（Bare Repositories）
  2. SQLite 数据库单文件

想要备份整个 Git 服务器，只需运行内置备份命令：

bash
# Linux 原生环境
sudo -u git /usr/local/bin/gitea dump -c /etc/gitea/app.ini --work-path /var/lib/gitea

# Windows 原生环境
.\gitea.exe dump -c "custom\conf\app.ini"

# Docker 环境
docker exec -u git -it gitea /app/gitea/gitea dump -c /data/gitea/conf/app.ini

执行完毕后，会在当前目录生成一个 gitea-dump-xxxxxxxx.zip 压缩包。换新服务器时，把这个 zip 解压还原回去即可，绝无复杂的数据库 dump 和权限踩坑。

总结 #

  • 想省心有图形化界面，选 Gitea；
  • 有 Docker 环境：直接 docker compose up -d，30 秒搭好；
  • 无 Docker 环境（如普通 Windows PC）：下载单文件 gitea.exe，浏览器点两下向导，再加个 Windows 服务自启，稳如磐石。
