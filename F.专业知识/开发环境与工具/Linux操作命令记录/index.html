Linux 操作命令记录 #

1. 前言 #

大学毕业快一年了，经常看别人的博客，看着别人学习都很有条理，学什么都记录下来，所以自己也打算开始写属于自己的学习记录。而且很多时候有些技巧用到的时候上网查一下，下次又忘了，所以希望能够做好整理工作。

2. grep 命令 #

刚刚参加工作的时候，对 grep 了解很少，但是工作中需要用的地方很多，所以就先来总结一下。

grep 的功能有非常多，但是看代码却用不到那么多的高级功能，所以只列出对工作有帮助的几个参数，其他的以后如果需要，再继续添加：

bash
grep "字符串" *          # 如果要搜索的目录下没有目录的话，完全不用加参数
grep -r "字符串" *       # 如果有目录，-r 可以递归搜索（-R 也可以，区别可能在符号链接上）
grep -i "字符串" *       # 忽略字符串中的大小写
grep -n "字符串" *       # 列出字符串所在文件的行号，结合 vim 文件 +行号 打开文件很有用

在 grep 实际使用中，可能还会结合转义字符 \，比如带 -> 的，就需要搜索时加转义 \->，不然搜不到的。反正有时候搜索带通用匹配符而又搜不到结果时，就加个转义试试，说不定有惊喜。

其他的参数以及结合正则表达式的方法，只是了解过，平时工作中并不常用，就不列举了。

3. rpm 命令 #

在平时工作中，rpm 命令用的非常多，总结下它的基本用法：

bash
rpm -ivh 包名           # 安装包，虽然 -i 参数就可以了，但是还是习惯 ivh，看起来舒服点
rpm -Uvh 包名           # 升级包，很多时候包已经存在了，这时需要用升级选项
rpm -qi 包名            # 查看 rpm 包的信息
rpm -qf 文件            # 查找文件属于哪个 rpm 包
rpm -qa                 # 查看系统中共安装了哪些 rpm 包（非 rpm 维护的系统如 ubuntu 查不到）
rpm -qpl 包名           # 不用安装或解压缩就可以看到一个 rpm 包中有哪些文件

关于 --nodeps 和 --force：这两个参数平时都会用到，结合上面要用好其实并不容易。刚开始工作一直不敢用这两个参数，现在也还经常忽略它们的使用。而且有时候是必须用的，比如用低版本的包替换高版本等等。

rpm -qi 在工作的时候非常有用：有时候要修改上层的应用，但是却不知道这个上层应用属于哪个 src.rpm 包，此时这个命令真是超级有用。

rpm -qf 的使用场景：安装 rpm 包会在系统中产生很多文件，用这个命令可以找到这个文件属于哪个 rpm 包。Linux 上层应用很多时候有很多 rpm 包，你打开源码完全不知道这个函数调用是怎么实现的。这个时候到 /usr/include 下 grep 一下，找到对应的 .h，之后结合 rpm -qf 和 rpm -qi 参数，非常有效。

--ignorearch 这个参数虽然不常用，但是需要的时候不知道真是要命。忽略平台参数安装，建议慎用。我也只是在 mips64el 架构的内核包拿来在 mips 架构上有时候用的。

4. qemu 命令 #

研究了快一天的 qemu 虚拟机，大体上得到了下面比较靠谱的命令。

1）启动一个安装镜像

bash
qemu-img create -f qcow2 fedora.img 10G
qemu-system-x86_64 -m 2048 -enable-kvm fedora.img -cdrom /path/yours.iso

上面的方法可以启动安装光盘镜像。

2）启动一个文件系统

bash
qemu-system-x86_64 -m 1024 -kernel /boot/vmlinuz-3.10.52-200.nk.6.zy.1.x86_64 \
    -initrd /boot/initramfs-3.10.52-200.nk.6.zy.1.x86_64.img

这个有点反应，但是后面再加参数都没法启动显示界面。

3）fedora 的 arm 版 qemu

当时不知从哪里弄了一个 qemu 中压缩出来的 aarch64 编译机，解压打开就是一个根文件系统，结果用 qemu-system-arm 启动一直报错。至于把华为提供给我们公司的内核和 initrd 更换掉，更是一点输出都没有，感觉好无奈。

最后还是询问了相关人员，才知道：

To use Fedora 23 on QEMU you will need to use a build of UEFI that is not hosted by Fedora for licensing reasons. For convenience a dnf|yum repository had been created.

相关详细链接：http://fedoraproject.org/wiki/Architectures/AArch64/F23/Installation

希望以后谁再需要可以有点帮助。

5. rpmbuild 命令 #

rpmbuild 命令是一个通过 src.rpm 反过来编译 rpm 包的命令。

先用 rpm -ivh 命令安装 src.rpm 包，然后在家目录下就会有一个 rpmbuild 的目录，目录下面会有两个文件夹：SOURCES 和 SPEC。其中 SPEC 文件夹下面是 spec 文件，通过 rpmbuild 命令编译这个文件就可以得到想要的一些东西。

bash
rpmbuild -bp *.spec    # 编译后在 rpmbuild/BUILD 目录下生成了源码
rpmbuild -ba *.spec    # 编译得到 rpm 和 src.rpm 包
rpmbuild -bb *.spec    # 只编译 RPM 包，不编译 SRPM 包
rpmbuild -bs *.spec    # 只编译出 SRPM 包

很多时候有人会直接用 rpm2cpio 命令解压缩得到里面的源码 tar 包，或者到 SOURCES 下面得到源码 tar 包。这种做法会有隐患，因为可能有些 patch 是通过 rpmbuild 编译的过程中打进去的，可能会产生不利的影响。

两个重要参数：

  • --nodeps：忽略依赖，有时候我们只想得到源码，可以考虑在缺依赖的时候使用这个参数；
  • --target：这个参数真是要命，用交叉编译其他平台的包时，这个参数没加的情况下报错真是泪流满面。我之前弄了一周实在搞不定了，然后师傅告诉了我这个参数，当时真是要疯了啊。

6. find 命令 #

对于 find 命令，很尴尬的是我基本用的只有一条：

bash
find . | grep "文件名"

额，虽然粗暴，但是真是基本解决了找文件的需求。如果以后碰到高级点的，再补充。

7. vim #

对于 vim，里面的技巧真是太多了，我只是学会了其中一些，应付工作暂时是够了。

模式与移动

  • esc 键：没事的时候多按几下，让文件处于一般模式，这个模式可以用 hjkl 来进行上下左右移动；
  • home 和 end：快速到一行的行头和行尾，shift+$ 也可以快速到行尾。

插入与编辑

  • i 和 a 键：一个是在当前光标前插入，一个是在当前光标后插入，按了以后就可以从一般模式进入插入模式，进行文本编辑；
  • x：删除一个字符（一般模式下）；
  • r：替换一个字符（一般模式下）；
  • dd：删除一行，其实说是剪切更恰当，因为按 p 又可以粘贴出来了；
  • yy：复制一行；
  • p：粘贴"剪贴板"里的内容；
  • u：撤销命令。

搜索

  • shift+* 或 shift+#：在当前单词上按上面两个组合，可以向下或向上搜索单词，然后按 n 或 N 上下找；
  • /：在一般模式下按 / 然后输入要搜索的单词或字符串，也可以定位，然后按 n 或 N 上下找。这个方法的优势在于可以搜索带空格的字符串，很实用。

可视模式

  • v：按 v 进入可视模式，上下移动可以选中整行，一般用来大面积的删除（d）或复制（y）；
  • ctrl+v：块选中，可以结合上面的删除、复制等命令。另外有时候我们写代码的时候需要连续注释多行，块选中每行代码的最前面部分，然后按大写的 I，之后就进入了插入模式，输入注释符号 // 或 #，然后按下 esc 键就可以注释多行啦，很实用。如果要删除这些注释，块选中后点击 d 就可以了。

ctags 跳转

用 ctags 命令生成 tags 文件，然后修改配置项 ~/.vimrc。如果以前没有也没关系，直接新建一个就好了。然后在最下面写上：

vim
set tags=/路径/tags

一定要注意这个只在当前用户下有效，可能切换到 root 或者其他用户，就会失效。它生效的原理很重要，因为有时候可能你在其他用户下编辑，其他用户也配置了 ctags，然后跳转的地方可能就不是你想要的地方，这会造成很大的困扰。以前我在 root 用户和 user 下都配置了内核源码，关键是路径不一样，然后改来改去发现一团糟，所以一定要去了解配置文件才是跳转的关键。

8. yum #

由于公司的系统有自己的 Yum 源，所以装系统以后就需要自己配置一下。

在 /etc/yum.repo/yous.repo 中写入 yum 库，配置好了后就可以用 Yum 来装软件包了，非常方便：

bash
yum install 包名        # 可以自动检索依赖

作为有时候需要手动去网上解依赖的人来说，yum 真是很方便。特别是编包的时候发现 yum 里都有，真是幸福啊。

这里贴一个 rpm 下载网址：http://rpm.pbone.net/

基本的 rpm 包我会在这里找，输入栏右边有一个高级选项，可以选择包的来源是哪个系统。输入栏下面有分类，有时候可能编译应用或安装驱动的时候，发现少的是动态库，或者你就是想看看某个头文件在哪个 rpm 包里有，就可以勾选第一个选项。如果只是找 rpm 包，就选第三个。另外两个没试过。

9. ssh、scp #

  • ssh：远程登陆一个主机，比如 ssh test@10.3.3.66，然后输入密码就可以登陆别人的电脑了。有时候报一个错，好像和安全有关，需要删掉一个配置文件，具体忘了。
  • scp：拷贝远程主机的东西到本地，或拷贝本地的东西到远程主机，非常实用，而且速度快。
bash
scp yous.txt test@10.3.3.66:/home/test
scp test@10.3.3.66:/home/test/test .

加上 -R 参数可以拷贝目录。

10. 手动改内核 #

有时候内核作了修改后，就会手动换一些内核。一般情况下，操作系统的引导文件在 sda1 分区的 /boot 下面。把要换的内核放到这个目录下，然后修改 grub.cfg 或 boot.cfg——反正复制一下那些大括号里面的东西，然后改下名字。如果想启动时进入字符界面，就在后面加个 3，但是要删掉一些参数，比如 rhgb，其实内核参数基本可以删掉，不确定就多删掉点。

如果系统坏了或者其他什么原因，没法进系统了，但是又不甘心，可以试试手动启动内核。我目前熟悉的有 pmon 和 grub 引导。顺便谴责下 pmon，经常出一些我无法理解的事情，比如同样是我做的系统盘，我的 u 盘无法识别，我师傅的却可以；以及有些机器没法显示引导界面啊，真是不喜欢。

手动引导命令分为 grub 和 pmon。

grub，举一个启动本地磁盘的例子：

linux (hd0,msdos1)/boot/vmlinux
boot

hd0 和 msdos1 表示第一块硬盘和第几分区。ls 可以查看分区。

pmon，举一个 usb 的例子。pmon 下 devls 命令可以查看当前的设备，然后 @ 后面的设备就是这么来的，0 是第一个。再有（好像）是按照 abcd 排的，比如 0a 什么的，可能不对，毕竟快 2 个月没弄了。

load /dev/fs/ext2@usb0/boot/vmlinux-uni
initrd /dev/fs/ext2@usb0/boot/initrd.gz
g console=tty
