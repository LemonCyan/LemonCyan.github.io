SQLite3 基础与命令行实战指南 #

对于咱们写代码 detour 的兄弟来说，每次想存点数据，如果一上来就去装个 MySQL、SQL Server 或者 PostgreSQL，不仅要搞一堆配置文件，还要开端口、配权限，实在是恶心人。这时候，SQLite3 就是个绝对的“爽点”了。它是一个极度轻量级、自包含（self-contained）的数据库，拔了网线照样写，即配即用，没有网络延迟，也不需要你当个数据库运维去天天调优。

今天这篇指南，咱们不扯那些云里雾里的学术黑话，直接从最底层的数据概念讲起，带大家把 SQLite3 的命令行操作与核心 SQL 语法对接起来，帮助大家在实际开发中快速上手。

一、 RDBMS 与关系型数据库核心概念 #

在聊 SQLite 之前，我们得先理清楚什么是“关系型数据库”（RDBMS）。简单来说，关系型数据库是建立在关系模型基础上的数据库，借助于集合代数等数学概念 and 方法来处理数据库中的数据。用大白话讲，就是把所有数据都塞到一张张像 Excel 一样的二维表格里。

为了避免跟其他开发同行交流时鸡同鸭讲，咱们先详细剖析几个关系型数据库的核心术语：

1.1 数据库 (Database) #

数据库是一些关联表的集合。在传统数据库（如 MySQL）中，一个数据库通常代表一个逻辑模式，背后由数据库管理系统通过多个文件来管理。而在 SQLite 中，一个数据库物理上就直接对应一个磁盘文件（例如 company.db）。这使得数据库的管理、备份和移动变得极为简单——拷贝这个文件就完成了备份。

1.2 数据表 (Table) #

表是数据的矩阵。在一个数据库中，表看起来就像一个简单的电子表格，由行 and 列组成。表是存储特定类型实体（如“员工”、“学生”、“订单”）数据的容器。

1.3 列 (Column) 与字段 (Field) #

列是表中垂直的一栏，包含了相同类型的数据。例如“年龄（age）”这一列，它要求存入的所有数据都必须是数字。每一列都有其特定的属性，包括列名、数据类型以及约束条件（如非空限制 NOT NULL）。

1.4 行 (Row) 与记录 (Record) #

行是表中水平的一栏。每一行（又称元组或记录）代表了一组相关的数据。例如，员工表中的一行包含了“张三”、“开发部”、“15000元”、“2023年入职”等所有与张三个人相关的属性。

1.5 主键 (Primary Key) #

主键是用于唯一标识表中每一行记录的关键字段。主键的值在当前列中必须是唯一的，且不能为 NULL。在绝大多数表中，我们都会设计一个自增的主键（如 id），以便能够精确地定位、修改或删除特定的某一行记录。

1.6 外键 (Foreign Key) #

外键用于关联两个表。例如，员工表中有一个名为 dept_id 的列，它指向部门表的主键 id。通过这种设计，两张独立的表就在逻辑上建立起了关联，保证了数据结构的一致性。

1.7 复合键 (Composite Key) #

复合键（组合键）将多个列作为一个索引键。当表中的单一列无法唯一标识一条记录时，我们就需要将两列或多列联合起来作为主键。例如，在“选课表”中，只有“学生ID” and “课程ID”的组合才能唯一确定一条选课记录。

1.8 索引 (Index) #

索引类似于书籍的目录。它是对数据库表中一列或多列的值进行排序的一种结构。使用索引可快速访问数据库表中的特定信息，而不需要每次都进行全表扫描。虽然索引能极大提升查询速度，但它也会占用额外的磁盘空间，并略微拖慢插入和更新的速度。

1.9 参照完整性 (Referential Integrity) #

参照完整性是关系模型必须满足的完整性约束条件，目的是保证数据的一致性。它要求子表（外键所在表）中引用的值必须在父表（主键所在表）中实际存在。例如，不能将一个员工划分到一个根本不存在的“部门ID”下。

1.10 数据冗余 (Redundancy) #

数据冗余是指在不同的地方重复存储相同的数据。过度的冗余会降低数据库的写入性能，但在读多写少的分布式系统或高性能场景中，适当的冗余可以提高查询速度。

二、 SQLite3 架构特性浅析 #

SQLite 是一个非常轻量级的自包含（lightweight and self-contained）DBMS，它可移植性好，很容易使用，很小，高效而且可靠。与传统的数据库不同，它具有以下几个独特的设计：

2.1 进程内运行 #

SQLite 嵌入到使用它的应用程序中，它们共用相同的进程空间，而不是单独的一个进程。这意味着在你的程序内部不需要任何网络配置，也不需要管理服务器。这直接消除了网络延迟，使得本地数据读写速度非常快。

2.2 零权限与零管理 #

SQLite 的数据库权限完全依赖于宿主系统的文件系统权限，没有数据库用户帐户、角色和权限控制的概念。如果你的操作系统用户能够读写该数据库文件，那么你就可以对它进行任何数据库操作。

2.3 数据库级锁定 #

SQLite 采用数据库级的粗粒度锁定。当一个进程需要对数据库进行写入时，它会获得一个写锁，此时其他进程可以继续读取，但不能写入。虽然这限制了其高并发写入的性能，但对于本地应用程序、工具软件或移动 App 来说，这是一种简单而高效的并发控制手段。

2.4 跨平台兼容的物理单文件 #

无论是在 Windows、Linux、macOS 还是嵌入式 RTOS 系统上，SQLite 数据库在磁盘上都表现为一个统一的二进制文件。你可以直接把 Windows 下生成的 .db 文件复制到 Linux 下运行，无需进行任何转换。

三、 系统的安装与部署 #

在开始把玩 SQLite3 之前，你得先在你的系统上把它装起来。不同平台的安装方式略有不同：

3.1 Ubuntu/Debian Linux 系统安装 #

在 Linux 上，SQLite3 通常可以通过系统的包管理器直接一键拉取。打开终端，输入以下命令即可完成安装：

bash
sudo apt-get update
sudo apt-get install sqlite3 libsqlite3-dev
  • 说明：sqlite3 是命令行客户端工具，而 libsqlite3-dev 是开发所需的头文件和静态/动态库文件（如果你打算自己写 C/C++ 代码编译，这个包是必装的）。

3.2 macOS 系统安装 #

如果你使用的是 Mac，可以通过 Homebrew 极为方便地安装：

bash
brew install sqlite3

其实 macOS 系统内部已经默认预装了 SQLite，但是版本通常比较旧，使用 brew 可以确保安装到最新的稳定版本。

3.3 Windows 系统安装 #

Windows 系统下不需要“安装”任何服务，你只需要去 SQLite 官网下载对应的二进制预编译文件：

  1. 访问 SQLite 官网下载页面。
  2. 在 Precompiled Binaries for Windows 部分，下载：
    • sqlite-tools-win-x64-xxxxxx.zip（包含命令行程序 sqlite3.exe）
    • sqlite-dll-win-x64-xxxxxx.zip（包含运行时动态链接库 sqlite3.dll）
  3. 解压这两个压缩包到同一个目录下（例如 C:\sqlite3）。
  4. 将该目录的绝对路径（如 C:\sqlite3）加入到系统的环境变量 PATH 中。
  5. 打开 PowerShell 或 CMD，输入 sqlite3 --version，如果能吐出版本号，则代表安装成功。

四、 SQLite3 命令行工具实战操作 #

进入终端，我们可以使用 sqlite3 命令行工具来对数据库进行交互式操作。命令行工具包含两类指令：以点 . 开头的系统管理命令（dot-commands），以及标准的 SQL 语句。

以下是常用 dot 命令的详细解析与使用场景：

4.1 .help 命令 #

  • 用途：显示所有点命令的帮助信息。
  • 演示：
    sqlite> .help
.archive ...             Manage SQLAR archives
.backup ?DB? FILE        Backup DB (default "main") to FILE
.databases               List names and files of attached databases
.dump ?OBJECTS?          Render database content as SQL
.excel                   Display the output of next command in spreadsheet
.exit ?CODE?             Exit this program
.headers on|off          Turn display of headers on or off
.import FILE TABLE       Import data from FILE into TABLE
.mode MODE ?TABLE?       Set output mode (ascii, csv, column, html, insert, line, list, markdown, quote, table, tabs, trigger)
.output ?FILE?           Send output to FILE or stdout
.read FILE               Execute SQL in FILE
.schema ?PATTERN?        Show the CREATE statements matching PATTERN
.tables ?PATTERN?        List names of tables matching PATTERN
.width NUM1 NUM2 ...     Set column widths for "column" mode

4.2 .database 命令 #

  • 用途：查看当前连接的所有数据库。
  • 演示：
    sqlite> .database
seq  name             file
---  ---------------  ----------------------------------------------------------
0    main             c:\Users\liuluhua\Desktop\BlogDeploy\message.db

4.3 .tables 命令 #

  • 用途：列出当前数据库中的所有数据表。
  • 演示：
    sqlite> .tables
company_employees  student

4.4 .schema 命令 #

  • 用途：查看指定表的创建语句。
  • 演示：
    sqlite> .schema student
CREATE TABLE student (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    score REAL DEFAULT 0.0
);

4.5 输出格式化命令组合 (.headers 和 .mode) #

  • 用途：默认情况下查询结果不含列名且字段以竖线分隔。配置后可以以表格列对齐方式显示。
  • 演示：
    sqlite> .headers on
sqlite> .mode column
sqlite> SELECT * FROM student;
id    name            score
----  --------------  ----------
1     Kobe            99.5
2     James           95.0

4.6 .width 命令 #

  • 用途：在使用 column 模式显示时，显式指定每一列的字符宽度，防止内容较长时被截断。
  • 演示：
    sqlite> .width 5 12 8
sqlite> SELECT * FROM student;

4.7 .output 与重定向命令 #

  • 用途：将接下来的 SQL 查询结果输出重定向到本地磁盘文件，而不是显示在终端上。
  • 演示：
    sqlite> .output my_data_export.txt
sqlite> SELECT * FROM student;
sqlite> .output stdout
    通过最后一行的 .output stdout 命令，可以把数据流切回到屏幕终端。

4.8 .dump 导出数据库 #

  • 用途：将表结构及数据内容完整导出为标准 SQL 脚本。
  • 演示：
    sqlite> .output backup.sql
sqlite> .dump student
sqlite> .output stdout

4.9 .read 导入 SQL 脚本 #

  • 用途：读取并执行本地磁盘文件中的 SQL 命令。
  • 演示：
    sqlite> .read backup.sql

4.10 .import 导入外部 CSV 数据 #

  • 用途：将外部格式化数据直接批量导入到表中。
  • 演示：
    sqlite> .mode csv
sqlite> .import raw_students.csv student

五、 数据类型 Affinity 与倾向转换机制 #

5.1 五大核心存储类 (Storage Classes) #

SQLite 支持以下 5 种基本数据存储类型：

  1. NULL：无值，或者空。
  2. INTEGER：带符号的整数值，占用 1-8 字节。
  3. REAL：浮点数。
  4. TEXT：文本字符串。
  5. BLOB：二进制对象，如图片、文件等原始数据。

5.2 五类类型 Affinity (倾向性) #

在建表时，尽管你声明了具体的类型（如 VARCHAR(50)），SQLite 在解析时会将其归为 5 种 Affinity 之一：

  • TEXT：含有 'CHAR'、'CLOB' 或 'TEXT' 的类型定义。
  • NUMERIC：含有 'NUMR' 或 'NUMERIC'，或者无法被其他类匹配的类型。
  • INTEGER：含有 'INT' 的类型定义（如 TINYINT, INTEGER 等）。
  • REAL：含有 'REAL'、'FLOA' 或 'DOUB' 的类型定义。
  • NONE (BLOB)：未定义类型或显式指定为 BLOB。

5.3 类型倾向性的转换实验 #

sqlite> CREATE TABLE test_affinity (
   ...>   col_int INTEGER,
   ...>   col_txt TEXT,
   ...>   col_num NUMERIC
   ...>);
sqlite> INSERT INTO test_affinity VALUES ('100', 200, '300.5');
sqlite> SELECT col_int, typeof(col_int), col_txt, typeof(col_txt), col_num, typeof(col_num) FROM test_affinity;
col_int     typeof(col_int)     col_txt     typeof(col_txt)     col_num     typeof(col_num)
----------  ---------------     ----------  ---------------     ----------  ---------------
100         integer             200         text                300.5       real

六、 核心 SQL 语法详解与约束设计 #

在 SQLite 中编写 SQL 时，注意每一行 SQL 语句末尾的分号 ;。

6.1 建表约束 (DDL 进阶) #

  • PRIMARY KEY：主键约束，唯一且非空。在 SQLite 中，INTEGER PRIMARY KEY 列会自动担当 rowid 的别名，自增且速度最快。
  • NOT NULL：确保字段不能存储 NULL 值。
  • UNIQUE：保证一列或多列的组合在表中每一行中值都是唯一的。
  • DEFAULT：在插入数据未指定列时，自动填充默认值。可以是一个固定值，或者是系统内置函数，如 (date('now'))。
  • CHECK：数据输入验证约束。例如限制工资不能为负数，限制年龄必须在特定范围内。

6.2 DML 操作示例 #

sql
-- 创建带复杂约束的表
CREATE TABLE IF NOT EXISTS product (
    prod_id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL UNIQUE,
    price REAL NOT NULL CHECK(price >= 0.0),
    stock INTEGER DEFAULT 10 CHECK(stock >= 0)
);

-- 插入并应用冲突替换
INSERT OR REPLACE INTO product (title, price, stock) VALUES ('键盘', 199.0, 5);
-- 如果 title 冲突，这条记录会覆盖旧记录

-- 更新记录
UPDATE product SET stock = stock - 1 WHERE prod_id = 1;

-- 删除记录
DELETE FROM product WHERE stock = 0;

七、 逻辑运算符与真值表详解 #

在 SQL 查询中，WHERE 条件子句是实现数据检索过滤的核心。我们需要使用逻辑运算符来组合多种条件。

7.1 真值表与三值逻辑 #

在关系数据库中，除 TRUE (真) 和 FALSE (假) 外，由于 NULL 的存在，引入了“三值逻辑 (Three-valued Logic, 3VL)”。

7.1.1 AND 运算符真值表 #

A B A AND B
TRUE TRUE TRUE
TRUE FALSE FALSE
TRUE NULL NULL
FALSE TRUE FALSE
FALSE FALSE FALSE
FALSE NULL FALSE
NULL TRUE NULL
NULL FALSE FALSE
NULL NULL NULL

7.1.2 OR 运算符真值表 #

A B A OR B
TRUE TRUE TRUE
TRUE FALSE TRUE
TRUE NULL TRUE
FALSE TRUE TRUE
FALSE FALSE FALSE
FALSE NULL NULL
NULL TRUE TRUE
NULL FALSE NULL
NULL NULL NULL

7.1.3 NOT 运算符真值表 #

A NOT A
TRUE FALSE
FALSE TRUE
NULL NULL

7.2 逻辑运算符实战应用 #

LIKE 运算符 #

  • 概念：通配符模式匹配，常用于字符串的模糊查询。
    • % 代表零个或任意多个字符。
    • _ 代表单个字符。
    • 注意：LIKE 在 SQLite 中默认是不区分大小写的。
  • 应用示例：
    sql
    SELECT * FROM student WHERE name LIKE 'J%';

GLOB 运算符 #

  • 概念：UNIX 文件路径风格的通配符匹配。
    • * 代表零个或任意多个字符。
    • ? 代表单个字符。
    • 重要区别：GLOB 运算符是区分大小写的。
  • 应用示例：
    sql
    SELECT * FROM student WHERE name GLOB 'J*';

BETWEEN 运算符 #

  • 概念：指定字段值落于给定的两个值之间（含两个边界值）。
  • 应用示例：
    sql
    SELECT * FROM student WHERE score BETWEEN 80.0 AND 95.0;

IN 与 NOT IN 运算符 #

  • 概念：IN 检查字段值是否属于给定列表中；NOT IN 检查是否不属于该列表。
  • 应用示例：
    sql
    SELECT * FROM student WHERE name IN ('Kobe', 'James', 'Jordan');
SELECT * FROM student WHERE name NOT IN ('Curry');

IS NULL 与 IS NOT NULL 运算符 #

  • 概念：专门用于判断字段的值是否为空。
  • 原理提示：在 SQL 中，NULL 代表“缺失”或“未知”。任何值与 NULL 进行 = 比较，其结果都是 NULL（非真非假），因此必须使用 IS NULL 关键字进行显式审查。
  • 应用示例：
    sql
    SELECT * FROM student WHERE score IS NULL;

八、 SQLite 核心内置函数库 #

SQLite3 提供了一组非常有用的内置函数，用于执行日期计算、字符串处理和数学运算。

8.1 日期与时间函数 #

在 SQLite 中，日期没有专门的数据类型，而是推荐以 TEXT (ISO8601 格式，如 'YYYY-MM-DD HH:MM:SS') 或 INTEGER (Unix 时间戳) 形式保存。

以下是 SQLite 内置日期计算函数的使用示例：

sql
-- 获取当前系统日期 (格式: YYYY-MM-DD)
SELECT date('now');

-- 获取当前系统时间 (格式: HH:MM:SS)
SELECT time('now');

-- 获取当前系统完整日期时间 (格式: YYYY-MM-DD HH:MM:SS)
SELECT datetime('now');

-- 使用修饰符计算：获取明天的同一时间
SELECT datetime('now', '+1 day');

-- 使用修饰符计算：获取上个月的最后一天
SELECT date('now', 'start of month', '-1 day');

-- 格式化时间戳输出
SELECT strftime('%Y年%m月%d日 %H时%M分%S秒', 'now', 'localtime');

8.2 聚合统计函数 (Aggregate Functions) #

聚合函数常用于做报表开发和数据分析：

sql
-- AVG(x): 计算一列的平均值
SELECT AVG(score) FROM student;

-- COUNT(x): 统计记录数。COUNT(*) 会计算包括 NULL 在内的行数，而 COUNT(col) 不计算该列为 NULL 的行
SELECT COUNT(*), COUNT(score) FROM student;

-- MAX(x) 与 MIN(x): 获取最大和最小值
SELECT MAX(score), MIN(score) FROM student;

-- SUM(x): 计算数值总和
SELECT SUM(score) FROM student;

-- GROUP_CONCAT(x, y): 将分组后的字符串用指定连接符 y 连结起来
SELECT GROUP_CONCAT(name, ', ') FROM student;

8.3 常用数学函数 (Math Functions) #

自 SQLite 3.35.0 版本开始，内置了许多数学计算函数（注意在旧编译版本下需要开启 -DSQLITE_ENABLE_MATH_FUNCTIONS 编译宏）：

sql
-- ABS(x): 绝对值
SELECT abs(-10.5); -- 返回 10.5

-- ROUND(x, y): 四舍五入保留 y 位小数
SELECT round(3.14159, 2); -- 返回 3.14

-- POWER(base, exp): 幂运算
SELECT power(2, 3); -- 返回 8.0

-- SQRT(x): 开平方
SELECT sqrt(16); -- 返回 4.0

九、 触发器 (Trigger) 与视图 (View) 进阶 #

在较为复杂的业务数据库中，为了保证业务的规则一致性和简化查询开发，我们会大量使用触发器与视图。

9.1 触发器 (Trigger) 实战 #

触发器是数据库的回调函数，在指定的表发生 INSERT、UPDATE 或 DELETE 操作时自动调用。

  • 审计日志实战：当员工的薪水发生变化时，自动将历史薪水记录写入审计日志表中。
sql
-- 创建薪水审计日志表
CREATE TABLE IF NOT EXISTS salary_audit_log (
    log_id INTEGER PRIMARY KEY AUTOINCREMENT,
    emp_id INTEGER,
    old_salary REAL,
    new_salary REAL,
    change_time TEXT DEFAULT (datetime('now', 'localtime'))
);

-- 创建触发器，在修改工资时触发
CREATE TRIGGER IF NOT EXISTS audit_salary_update
AFTER UPDATE OF salary ON company_employees
FOR EACH ROW
WHEN OLD.salary <> NEW.salary -- 仅在工资发生实际变化时触发
BEGIN
    INSERT INTO salary_audit_log (emp_id, old_salary, new_salary)
    VALUES (OLD.emp_id, OLD.salary, NEW.salary);
END;

测试触发器：

sql
-- 修改老王的薪水
UPDATE company_employees SET salary = 18000.0 WHERE name = '老王';

-- 查看审计日志是否自动记录
SELECT * FROM salary_audit_log;

9.2 视图 (View) 实战 #

视图是只读的虚拟表，基于 SQL 查询的结果集创建。

  • 高薪员工视图实战：建立一个部门高薪员工清单视图，屏蔽其他低薪敏感数据。
sql
-- 创建视图
CREATE VIEW IF NOT EXISTS v_high_salary_employees AS
SELECT emp_id, name, department, salary
FROM company_employees
WHERE salary >= 12000.0;

-- 像查询普通表一样查询视图
SELECT * FROM v_high_salary_employees;

十、 事务管理与并发锁机制 #

SQLite 完全支持事务的 ACID 特征。在执行批量数据处理或多表联动更新时，必须使用事务进行保护，这同时也是显著提升写盘性能的关键策略。

10.1 事务的基础语法 #

sql
BEGIN; -- 开启事务
UPDATE student SET score = 90 WHERE id = 1;
UPDATE student SET score = 95 WHERE id = 2;
COMMIT; -- 提交事务，安全写入磁盘

如果执行过程中出现异常或错误，可以撤销修改：

sql
ROLLBACK; -- 回滚事务，恢复至 BEGIN 时的状态

10.2 SQLite 的并发锁定级别 #

由于 SQLite 是单文件数据库，其并发写入控制通过对文件的锁定级别升级来实现：

  1. UNLOCKED (未锁定)：没有连接进行读写。
  2. SHARED (共享锁)：支持多个连接同时读取。在此锁状态下，不允许任何写入。
  3. RESERVED (保留锁)：有一个连接表明它在接下来的事务中需要进行写入，但它还没有真正修改文件。此时其他共享锁连接可继续读。
  4. PENDING (未决锁)：写入连接准备提交修改，此时系统不再接受新的共享锁申请，等待现有读取释放。
  5. EXCLUSIVE (排他锁)：写入连接独占文件，开始真正写入物理磁盘。

sql
-- 第一步：基于原有学生表数据，将通过及格线的学生数据备份到临时表
CREATE TABLE temp_student_bak AS 
SELECT id, name, score FROM student WHERE score >= 60.0;

-- 第二步：删除原有旧表结构
DROP TABLE IF EXISTS student;

-- 第三步：创建全新的带有新字段 `email` 的学生表，并设计新的默认值
CREATE TABLE student (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    score REAL DEFAULT 0.0,
    email TEXT DEFAULT 'pending@example.com'
);

-- 第四步：从临时备份表中，将历史数据完整导回到新表结构中
INSERT INTO student (id, name, score)
SELECT id, name, score FROM temp_student_bak;

-- 第五步：清理临时表
DROP TABLE IF EXISTS temp_student_bak;

十二、 性能分析工具：解释计划 (EXPLAIN QUERY PLAN) #

在进行海量数据查询时，如何判定我们建立的索引有没有起到作用？SQLite 提供了 EXPLAIN QUERY PLAN 关键字。

12.1 全表扫描案例 #

sqlite> EXPLAIN QUERY PLAN SELECT * FROM company_employees WHERE salary > 10000;
QUERY PLAN
`--SCAN company_employees

返回 SCAN，意味着数据库在读取整个表的文件数据。对于包含百万级以上的表，全表扫描会引发严重的磁盘 I/O 阻力。

12.2 索引查找案例 #

sqlite> EXPLAIN QUERY PLAN SELECT * FROM company_employees WHERE department = '技术部';
QUERY PLAN
`--SEARCH company_employees USING INDEX idx_emp_dept_salary (department=?)

返回 SEARCH ... USING INDEX，意味着 SQLite 的执行引擎识别并调用了我们建立的复合索引，直接进行范围检索，查询效率极高。

十三、 SQLite 命令行高频报错与排障机制 #

在终端操作 SQLite 数据库时，由于环境配置、SQL 语法拼写以及并发读写等因素，经常会遇到以下经典报错。这里给出详细的原因分析和局之策：

13.1 Error: database is locked #

  • 原因分析：这是 SQLite 引擎最常见的错误，发生在有一个进程正在对文件进行独占写入（持有 EXCLUSIVE 锁），而当前进程尝试获取写锁（或进行冲突级别的读操作）时。
  • 极客解决方案： 在终端中设置超时重试时间，避免一冲突就直接报错挂掉。输入：
    sqlite> .timeout 5000
    这会让 SQLite 在发现文件被锁住时，最多等待 5000 毫秒（5秒）。若在这个时间内持有锁的进程完成了事务，当前操作将继续进行。

13.2 Error: UNIQUE constraint failed #

  • 原因分析：往包含唯一性约束（例如 PRIMARY KEY 或带有 UNIQUE 标识）的字段中插入了已经存在的数据。
  • 极客解决方案： 在插入语句中使用 INSERT OR IGNORE（忽略冲突）或 INSERT OR REPLACE（覆盖冲突）：
    sql
    -- 如果学号冲突，忽略这条插入
INSERT OR IGNORE INTO student (id, name, score) VALUES (1, 'Kobe', 99.0);

-- 如果学号冲突，用新数据替换掉老数据
INSERT OR REPLACE INTO student (id, name, score) VALUES (1, 'Kobe', 100.0);

13.3 Error: no such table: xxx #

  • 原因分析：
    1. 拼写错误。
    2. 启动 sqlite3 命令时，工作目录不对，或者敲错了 db 文件路径。SQLite 会默认新建一个空白的 db 文件打开，此时表当然不存在！
  • 极客解决方案： 首先执行 .database 命令，检查当前打开的物理 db 文件路径是否真的是你期望的那一个。接着执行 .tables 确认该表中是否包含了你打算访问 of 表。

13.4 Error: CHECK constraint failed #

  • 原因分析：插入或更新的数据违反了建表时定义的 CHECK 数据检验约束条件（比如把年龄设置为了 15 岁，而约束要求必须大于 18 岁）。
  • 极客解决方案： 先检查建表 Schema：.schema 表名，对照约束条件对要插入的值进行修正后再提交。

13.5 终端 SQL 字符串转义错误 #

  • 原因分析：在终端里，习惯性地用双引号 " 包裹 SQL 中的字符串常量，或者在双引号里用双引号引发词法解析错误。
  • 极客解决方案： 在 SQL 标准中，字符串字面量必须使用单引号 ' 包裹。如果在单引号中遇到单引号（比如表示“老张的值”），需要用两个单引号进行转义，例如 'Zhang''s data'。

十四、 WAL (Write-Ahead Logging) 预写日志并发调优 #

当多线程或者多个应用实例同时访问同一个 SQLite 文件时，很容易触发 database is locked 读写锁竞争。为了打破这个瓶颈，SQLite 提供了 WAL (预写日志) 模式。

14.1 什么是 WAL 模式？ #

在默认的 Rollback Journal 模式下，写事务在修改数据时，会锁住整个数据库，使得读操作被阻塞。 而在 WAL 模式下，写操作并不直接写入原始数据库文件，而是追加写入到一个独立的 -wal 后缀日志文件中。此时，读操作会优先读取原始数据库，如果发现 WAL 文件中有更新的页面，则读取 WAL 文件中的页面。

14.2 并发调优的爽点与阻力 #

  • 爽点 (优势)：
    1. 读写互不阻塞：读取连接和写入连接可以同时进行，大大提升了读取吞吐量。
    2. 写入速度翻倍：由于很多写入操作被平摊为了顺序追加写入 WAL 文件，减少了大量的磁盘物理随机同步（fsync）。
  • 坑点 (劣势)：
    1. 数据库在运行时，会在同级目录下生成额外的 .db-wal 和 .db-shm（共享内存）文件，在程序退出或关闭数据库时这些文件才会被清理。
    2. WAL 模式不支持网络挂载的共享文件系统（如 NFS、Samba），因为它依赖底层的共享内存映射机制。

14.3 开启 WAL 模式指令 #

在进入命令行工具后，敲入以下命令即可一键开启 WAL 模式：

sqlite> PRAGMA journal_mode=WAL;
journal_mode
------------
wal

如果需要切回默认模式，输入：

sqlite> PRAGMA journal_mode=delete;

十五、 工程局限性与避坑指南 #

尽管 SQLite 是一款卓越且广受欢迎的轻量级数据库，但在设计工程架构时，千万不要把它当成能横扫一切的银弹。它存在以下明显的局限：

  • 锁级别过粗，并发写能力弱：SQLite 在执行写入操作时会锁定整个数据库文件。如果有多个线程或多个客户端程序需要频繁对同一个文件进行 INSERT / UPDATE 写入，容易频繁触发 database is locked 错误。
  • 没有右连接 (RIGHT JOIN) 与全连接 (FULL JOIN)：SQLite 仅支持左连接（LEFT OUTER JOIN）。如果你习惯编写带有复杂右连接的 SQL，必须调整 SQL 中表的声明顺序，换用左连接来实现相同的结果。
  • 缺乏细粒度的安全控制：SQLite 没有专门的用户角色和表权限模型。一旦进程获得了该数据库文件的读写权限，即可对其进行任意删改。
  • 文件存储物理极限：当数据库文件大小超过 10GB 甚至 100GB 时，虽然 SQLite能继续工作，但底层文件系统的文件锁和 I/O 同步会变得十分沉重，此时建议迁移到 PostgreSQL。

掌握了这些底层局限和核心语法，你在命令行的使用和基本的建表、删改、事务操作中就已经能应对自如了。在下一篇中，我们将继续讲解如何通过 C/C++ 语言的 API 接口，实现与 SQLite 数据库的无缝程序交互及二进制 blob 文件的读写。
