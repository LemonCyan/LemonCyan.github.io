C 语言数组与指针算术硬核知识点整合 #

1. 数据的隐式类型转换与强制类型转换 #

1.1 隐式类型转换规则 #

在 C 语言的算术表达式中，不同类型的数据混合运算时会发生隐式类型转换。转换的基本原则是：小类型向大类型看齐（值提升）。 需要特别注意：类型转换改变的是值的类型，而不是变量（对象）本身的类型。

经典表达式分析： #

  • c = c + 1;
    • 常数 1 缺省为 int 类型。
    • 右侧的 c (char) 首先被提升为 int，参与加法运算，得到 32 位 int 结果。
    • 最终结果在赋值给左侧的 c 时，被截断（降级）回 char 类型。
  • i = d + f + 2L * c;
    • c (char) 被转换为 long，与 2L 相乘。
    • f (float) 被转换为 double 与 d (double) 相加。
    • 两部分结果再次统一转换为 double 相加，最终结果截断为 int 赋值给 i。

1.2 强制类型转换的截断细节 #

强制类型转换会直接截断数据，影响后续运算的优先级与结果。

c
// 示例 1
i = 666.6 + 777.7; 
// 666.6 + 777.7 = 1444.3，然后降级为 int，i 最终为 1444

// 示例 2
i = (int)666.6 + (int)777.7; 
// 强转优先：666 + 777，i 最终为 1443

1.3 ASCII 字符与大小写转换 #

字符在底层本质上就是数值。在 ASCII 码表中，小写字母比大写字母大 32（即 'a' - 'A' = 32）。 因此，将大写字母转换为小写字母的核心逻辑非常直接：

c
if (ch >= 'A' && ch <= 'Z')
    ch = ch + 32;

2. 一维数组的地址操作与指针算术 #

2.1 数组名 a、&a 与 &a[0] 的区别 #

对于声明 int a[5];，这三个表达式的值（地址）完全相同，但它们的指针类型和物理含义完全不同：

  • a：数组首元素的地址，类型为 int *。
  • &a[0]：数组首元素的地址，类型为 int *。
  • &a：整个数组的起始地址，类型为数组指针 int (*)[5]。

因为类型不同，当它们进行加法运算（地址偏移）时，增加的跨度也截然不同：

c
int a[5] = {1, 2, 3, 4, 5};
// 假设 a 的基地址为 0x7ffff72087c0

printf("%p", a + 1);       // 偏移 1 个 int（4字节）  -> 0x7ffff72087c4
printf("%p", &a[0] + 1);   // 偏移 1 个 int（4字节）  -> 0x7ffff72087c4
printf("%p", &a + 1);      // 偏移整个数组的大小（5 * 4 = 20字节，即 0x14） -> 0x7ffff72087d4

2.2 数组的测量与初始化规则 #

  • 元素个数动态测量：在编译作用域内，如果只知道数组名，可以通过下式计算元素个数 n：
    c
    int n = sizeof(a) / sizeof(a[0]);
  • 部分元素初始化：如果初始化列表中提供的初始值个数小于数组声明的长度，则剩余的未初始化元素会被编译器自动填零。
    c
    int a[10] = {1, 2, 3}; // a[3] 到 a[9] 自动为 0
int clean[10] = {0};   // 快速将整个数组初始化为 0
  • 自动长度推导：如果在初始化时提供了完整初值，可以省略声明中的数组大小，编译器会自动计算：
    c
    int a[] = {1, 2, 3, 4, 5}; // 自动分配长度为 5

2.3 强制类型转换中的地址偏移陷阱 #

在算术运算中，操作符的优先级和类型转换的顺序极易引发 Bug。

c
int a[5] = {1, 2, 3, 4, 5};
int *p = (int *)&a + 1; // 关键表达式
  • 原理解析：由于类型转换操作符 (int *) 的优先级高于加法 +，上述表达式等价于 ((int *)&a) + 1。
  • 此时 &a 首先被强制转换为 int * 类型的指针。
  • 随后进行的 +1 操作是基于 int * 的指针运算，因此地址只向后偏移了 1 个 int 的大小（4 字节），即指向了 a[1]。
  • 对比：如果是 (int *)(&a + 1)，则会先对整个数组加 1（偏移 20 字节），然后再转成 int *，指向数组包装界限之后的地址。

2.4 数组形参的指针退化与移动 #

当一维数组作为函数参数传递时，它会退化为普通的指针。作为形参的指针本身在函数内部是可变的（可以进行自增 a++ 等操作），这与原数组名（常量指针，不可自增）不同：

c
// 形参 a 退化为 int *，可以通过自增遍历数组
int array(int *a, int size)
{
    for(int i = 0; i < size; i++)
    {
        printf("%d ", *a);
        a++; // 移动指针，指向下一个元素
    }
}

3. 多维数组与指针的高级运算与传参 #

3.1 二维数组的指针本质与等价访问 #

对于二维数组 int a[3][4];，它在内存中是按行连续存放的。数组名 a 代表第一行的地址，其类型为数组指针 int (*)[4]。

四种等价的元素访问写法： #

对于第 i 行第 j 列的元素，以下四种写法在编译器底层完全等价：

c
a[i][j]          // 数组下标法
p[i][j]          // 指针别名下标法（假设 int (*p)[4] = a;）
*(*(a + i) + j)  // 指针偏移解引用法
*(*(p + i) + j)  // 数组指针偏移解引用法

3.2 数组指针作为形参的偏移计算 #

在多维数组传参时，若对形参指针进行偏移，其跨度是“行宽”而不是单个元素宽。

c
#include <stdio.h>

void foo(int b[][3]) // b 的类型是 int (*)[3]，指向一个有 3 个 int 的一维数组
{
    ++b;          // 指针向后偏移一行（3 个 int 的跨度，即 12 字节）
    b[1][1] = 9;  // 在偏移后的基础上，访问 b[1][1]，实际修改了原数组中的哪个元素？
}

int main()
{
    int a[3][3] = { {1, 2, 3}, 
                    {4, 5, 6}, 
                    {7, 8, 9} };
    foo(a);
    printf("%d\n", a[2][1]); // 输出 9
}

原理解析： #

  1. 传入 a 后，b 初始指向第 0 行 {1, 2, 3}。
  2. 执行 ++b 后，b 指向第 1 行 {4, 5, 6}。
  3. 执行 b[1][1] = 9。根据指针计算公式，b[1] 代表当前 b 指针位置往后偏移一行的行首地址，即原数组的第 2 行 {7, 8, 9} 的首地址。
  4. 因此 b[1][1] 实际访问的是原数组的 a[2][1]，成功将其修改为 9。

3.3 二维数组传参的三种等价书写形式与下标省略 #

当我们需要把二维数组（如 int a[3][4]）传入函数时，以下三种形式是完全等价的：

c
int fun(int (*p)[4]);
int fun(int p[3][4]);
int fun(int p[][4]);
  • 本质：这三种声明在编译器眼里都会退化为数组指针 int (*p)[4]。
  • 维度省略规则：定义二维数组并初始化时，第一维的大小可以缺省不写，但第二维的大小绝对不能省略（例如 int a[][4] = {1,2,3,4,5}; 是合法的，而 int a[3][] = ... 或 int a[][] = ... 是非法的）。因为第二维确定了二维数组每行的物理跨度，如果缺失，编译器将无法定位和计算元素的物理偏移。

3.4 数组不可整体赋值限制 #

C 语言不支持将数组作为一个整体进行赋值。以下操作均是非法的：

c
int a[10], b[10];
a = b;  // ❌ 错误：数组名 a 是常量指针（右值），无法作为左值被赋值！
a = {1, 2, 3}; // ❌ 错误：只能在声明初始化时使用花括号赋值，后续无法整体赋值

要复制数组内容，必须通过循环逐个元素赋值，或者使用标准库中的 memcpy 函数。

3.5 字符指针数组（用于表示字符串数组） #

我们可以定义一个指针数组来高效地存放多个字符串的首地址，通常用于表示字符串数组：

c
char *str[3] = {
    "Hello,thisisasample",
    "Hi,goodmorning.",
    "Helloworld"
};
  • 内存模型：str 是一个一维数组，里面存储了 3 个 char * 类型的指针变量。这些指针分别指向常量区存储的字符串字面量的首地址。
  • 取值逻辑：
    • str 指向数组的第 0 号单元，它的指针类型是 char **。
    • *str 取出第 0 个指针，也就是指向第一个字符串的 char * 指针，其值等同于 "Hello,thisisasample"。
    • *(str + 1) 取出第 1 个指针，其值等同于 "Hi,goodmorning." 的首地址。

4. 数组边界安全与清零逻辑 #

4.1 数组下标合法性检查原则 #

  • 无需检查的场景：如果下标值是从程序内部已知安全、正确的逻辑计算出来的（例如严格控制在 [0, size - 1] 范围内的 for 循环计数器），则无需在每次访问时重复进行边界检查。
  • 必须检查的场景：如果下标值直接或间接来源于用户输入、外部网络数据或不受控的文件读取，在使用它访问数组前，必须进行范围检测，确保其不会发生越界，否则极易导致缓冲区溢出漏洞。

4.2 数组清零的边界问题与未定义行为 (UB) #

1) 顺序清零（绝对安全） #

c
#define N_VALUES 5
float values[N_VALUES];
float *vp;

for(vp = &values[0]; vp < &values[N_VALUES]; )
    *vp++ = 0;
  • 边界说明：循环终止时，vp 指向 &values[N_VALUES]。虽然该位置已经超出了数组的有效范围，但由于 C 标准允许获取数组最后一个元素后面那个内存位置的地址进行比较，且循环在此处终止、未对该地址执行解引用操作，因此这是完全安全的。

2) 逆序清零方案 A（安全） #

c
for(vp = &values[N_VALUES]; vp > &values[0]; )
    *--vp = 0;
  • 边界说明：vp 初始指向越界位置 &values[N_VALUES]，但在解引用之前执行了 --vp 自减操作，使指针回到了有效范围内，最后一次循环处理完 values[0] 后，vp 等于 &values[0]，循环终止。此方案也是完全安全的。

3) 逆序清零方案 B（危险！存在未定义行为） #

c
for(vp = &values[N_VALUES - 1]; vp >= &values[0]; vp--)
    *vp = 0;
  • 致命缺陷：当处理完 values[0] 后，vp 执行 vp-- 自减。此时，vp 将指向 values[0] 之前的内存位置（即 &values[-1]）。
  • C 标准明确禁止将指针移动到数组起始位置之前的空间并进行比较。vp >= &values[0] 这个比较操作在底层可能会因为编译器优化、地址溢出或特殊架构而产生未定义行为（UB），导致死循环或崩溃。因此切勿在代码中使用此写法。

5. 字符数组与字符串的底层纽带 #

5.1 字符数组 vs 字符串字面量 #

  • 字符数组：纯粹的字符存储容器，长度为分配的元素个数。除非手动添加，否则末尾不包含结束符 \0。
    c
    char c1[] = {'H', 'e', 'l', 'l', 'o'}; // sizeof(c1) 为 5，非合法的字符串，printf("%s") 打印时会越界乱码
  • 字符串字面量：双引号 "" 括起来的字符序列。编译器会自动在末尾追加结束符 \0。
    c
    char c2[] = "Hello"; // sizeof(c2) 为 6，底层等同于 {'H', 'e', 'l', 'l', 'o', '\0'}

5.2 字符辨析：0、'0'、'\0'、"0" 的物理差异 #

这四个在字面上极具迷惑性，但其底层表现和类型截然不同：

  • 0：整数 0，物理占 4 字节，二进制为 0x00000000。
  • '0'：字符零，物理占 1 字节。在 ASCII 码表中的数值是 48（即十进制 48，二进制 0x30），是可见的打印字符。
  • '\0'：转义字符（即空终止符/NULL），物理占 1 字节。在 ASCII 表中的数值是 0，是一个不可见字符，纯粹用于标识字符串的结束。
  • "0"：字符串字面量，类型为 char[]，在只读常量区占用 2 字节（字符 '0' 和结束符 '\0' 连续排列）。

5.3 使用 %s 读写字符串的核心细节 #

当使用 printf 或 scanf 的 %s 格式控制符操作字符串时，应注意：

  1. 输入地址免 &：在 scanf("%s", buf) 中，由于数组名 buf 本身就是首元素的地址，因此绝对不能在变量前加取地址符 &。
  2. 越界防御：scanf("%s", buf) 会盲目读取直到遇到空白字符（空格/Tab/回车），如果不限制大小，极易导致缓冲区溢出。建议设置足够大的空间。
  3. gets() 与 scanf("%s") 的关键区别：
    • scanf("%s", buf) 读到空格即认为输入结束，空格后的数据会残留在缓冲区中。
    • gets(buf) 允许读入空格，只有遇到换行符 \n 或 EOF 时才结束读取。

6. 动态数组分配与堆栈空间差异 #

6.1 堆动态分配数组生命周期 #

使用 malloc 可以根据用户运行时的输入动态决定数组大小，但必须遵循完整的生命周期管理原则：

c
// 1. 动态申请堆内存
int *p = (int *)malloc(n * sizeof(int));
if (p == NULL) {
    // 2. 检查分配是否成功
    return -1; 
}

// 3. 正常使用数组（如进行排序或计算）
// ...

// 4. 使用完毕必须释放，并将指针置空以防止野指针
free(p);
p = NULL;

6.2 栈数组与常量区指针的内存特征 #

c
char a[10] = "hello"; // 数组 a 分配在栈区，内容是从常量区复制过来的副本
char *q = "hello";    // 指针 q 分配在栈区，但它直接指向只读常量区的同一块内存
  • a 的地址是在栈空间内，生命周期随函数栈帧的销毁而结束，但可以对数组内容进行修改（例如 a[0] = 'H'）。
  • q 指向只读常量区，尝试修改其内容（例如 *q = 'H'）会直接触发段错误（Segmentation fault）。两者在内存地址段上有显著的区别。

7. 经典指针/数组算术面试题与结构体偏移 #

7.1 指针类型转换与数值加法运算 #

指针变量与一个整数相加减时，其地址偏移的单位是所指向类型的大小，而不是单纯的字节数。

示例分析： #

c
struct Test {
    int Num;
    char *pcName;
    short sDate;
    char cha[2];
    short sBa[4];
} *p;

假设 p 的值为 0x100000，且该结构体的大小为 20 字节（经过字对齐填充）：

  1. p + 0x1：
    • 指针加法，增加 1 * sizeof(struct Test) = 20 字节（十六进制为 0x14）。
    • 结果为：0x100014。
  2. (unsigned long)p + 0x1：
    • 强转为无符号长整型，指针退化为普通数值。
    • 结果为普通的整数加法：0x100001。
  3. (unsigned int *)p + 0x1：
    • 强转为指向无符号整型的指针，指向的类型大小变为 sizeof(unsigned int) = 4 字节。
    • 结果为：0x100000 + 4 = 0x100004。

7.2 经典 Little-Endian 内存偏移难题 #

以下是一道经典的 x86 底层指针偏移面试题：

c
#include <stdio.h>

int main()
{
    int a[4] = {1, 2, 3, 4};
    int *ptr1 = (int *)(&a + 1);
    int *ptr2 = (int *)((int)a + 1);
    
    printf("%x,%x\n", ptr1[-1], *ptr2);
    return 0;
}

原理解析： #

  1. ptr1 分支：
    • &a 的类型是数组指针 int (*)[4]，指向整个数组。
    • &a + 1 使得指针偏移了整个数组的大小（4 * 4 = 16 字节），指向了数组 a 边界之后的第一位内存。
    • 强转为 int * 并赋值给 ptr1。
    • ptr1[-1] 等价于 *(ptr1 - 1)，指针回退 4 字节（1 个 int 的跨度），回到了 a[3] 的位置。因此第一个输出值为 4。
  2. ptr2 分支：
    • a 是数组首元素地址。(int)a 将其转为普通的整型数值。
    • (int)a + 1 即将地址数值直接加 1（即地址向后移动了 1 字节）。
    • (int *)((int)a + 1) 将这个偏移了 1 字节的地址强制转换为 int * 类型的指针。
    • 在 x86（小端模式 Little-Endian）下，数组 a[0] 和 a[1] 的内存分布为：
      • a[0] = 0x00000001 -> 字节流为：01 00 00 00
      • a[1] = 0x00000002 -> 字节流为：02 00 00 00
      • 内存中的连续排布为：01 00 00 00 02 00 00 00
    • ptr2 指向 a[0] 的第二个字节，即从 00 开始的 4 个连续字节：00 00 00 02。
    • 在小端模式下读出这 4 字节的整型值，低位在前，高位在后，其值为：0x02000000。
    • 因此，如果是小端模式（如常见 x86 架构），输出为 4, 2000000。如果是大端模式（Big-Endian），a[0] 存储为 00 00 00 01，偏移 1 字节读出的值为 0x00000100，输出为 4, 100。

8. C 语言标准与高级字符串处理函数族 #

8.1 常用字符串函数汇总 #

使用字符串处理函数时，必须包含头文件 #include <string.h>。

1) stpcpy — 拷贝字符串并返回尾指针 #

  • 原型：char *stpcpy(char *destin, const char *source);
  • 特点：功能类似于 strcpy，但返回值不同。strcpy 返回目标缓冲区的起始地址，而 stpcpy 返回拷贝完毕后目标字符串末尾空终止符 \0 的地址。在进行连续字符串拼接时极其高效，省去了重复查找尾部的开销。

2) 大小写敏感与不敏感字符串比较 #

  • strcmp（大小写敏感）：int strcmp(const char *s1, const char *s2);。逐个字符按 ASCII 比较，s1 大于 s2 返回正数，相等返回 0，否则返回负数。
  • strncmp：int strncmp(const char *s1, const char *s2, size_t n);。只比较前 n 个字符。
  • stricmp / strcasecmp（大小写不敏感）：不区分大小写比较两个串。
  • strncmpi / strnicmp（大小写不敏感且限长）：只比较前 n 个字符，不区分大小写。

3) strdup — 在堆中复制并新建字符串 #

  • 原型：char *strdup(const char *str);
  • 底层机制：该函数会在堆内存中自动使用 malloc 申请一块能容纳 str 的新内存块，并将 str 拷贝过去。
  • 注意：由于它是动态申请的，使用完毕后必须手动调用 free() 释放这块空间，否则会产生内存泄漏。

4) strerror — 获取 errno 对应的错误信息 #

  • 原型：char *strerror(int errnum);
  • 使用：在发生系统调用或库函数错误时，传入系统全局错误变量 errno，即可返回一个指向对应中文/英文描述字符串的只读指针，用于系统排错。

5) 字符串高级查找函数族 #

  • strchr 与 strrchr：查找单个字符在串中第一次 / 最后一次匹配的物理位置。
  • strpbrk：char *strpbrk(const char *s1, const char *s2);。查找字符串 s2 中任意字符在 s1 中第一次出现的地址。
  • strcspn：size_t strcspn(const char *s1, const char *s2);。返回 s1 起始处不包含任何 s2 字符的子集长度。
  • strspn：size_t strspn(const char *s1, const char *s2);。返回 s1 起始处完全由 s2 中的字符组成的子集长度。
  • strtok（线程安全大警告）：
    • 原型：char *strtok(char *s1, const char *s2);。按 s2 中的分割符拆分 s1。
    • 致命警告：strtok 内部使用了一个静态局部变量来保存当前拆分后的剩余位置。这导致该函数是不可重入的，且在多线程并发环境下极不安全。在现代 Linux 系统中（Linux 内核 2.6.29 之后已经完全禁用 strtok），推荐使用线程安全的 strtok_r 或速度更快的 strsep。

6) strsep — 快速安全的字符串切分函数（强烈推荐） #

  • 原型：char *strsep(char **stringp, const char *delim);
  • 机制：通过移动二级指针 stringp 来定位分割符，将其用 \0 替换并返回切分出来的子串。当切分完毕时，stringp 会被设为 NULL。
strsep 实战示例：
c
#include <stdio.h>
#include <string.h>

int main(void) {
    char str[] = "root:x::0:root:/root:/bin/bash";
    char *buf = str;
    char *token;
    
    // 循环提取以冒号 ":" 分割的字段，buf 的指向会持续向后移动
    while ((token = strsep(&buf, ":")) != NULL) {
        printf("Token: %s\n", token);
    }
    return 0;
}

7) 文本数值转换与字节交换 #

  • strtod：double strtod(const char *str, char **endptr);。将字符串转换为 double，并在 endptr 中保存切分后的后续文本地址（比普通 atof 更健壮）。
  • strtol：long strtol(const char *str, char **endptr, int base);。根据进制 base（2-36进制，传入0则自动识别前缀如 0x 为 16 进制）将字符串转换为 long。
  • strupr：将字符串中的所有小写字母原地转换为大写。
  • swab：void swab(const char *from, char *to, ssize_t nbytes);。将相邻的奇偶偶数字节两两交换。

8.2 自定义字符数组处理函数逻辑 #

在不使用系统提供的 #include <string.h> 库函数时，以下是各个常用字符串操作的核心手写实现逻辑，有助于深入掌握 \0 封尾的应用：

1) 自定义字符串拼接 my_strcat #

c
void my_strcat(char *s1, const char *s2) {
    int i = 0, j = 0;
    // 1. 寻找 s1 的结束符位置
    while (s1[i] != '\0') {
        i++;
    }
    // 2. 开始物理拼接，直至 s2 出现结束符
    while (s2[j] != '\0') {
        s1[i] = s2[j];
        i++;
        j++;
    }
    s1[i] = '\0'; // 3. 必须在末尾手动封包
}

int my_strcmp(const char *s1, const char *s2) {
    int i = 0, j = 0;
    while (s1[i] != '\0' && s2[j] != '\0') {
        if (s1[i] > s2[j]) return 1;
        else if (s1[i] < s2[j]) return -1;
        i++;
        j++;
    }
    // 处理末尾长度不一致的情况
    if (s1[i] != '\0' && s2[j] == '\0') return 1;
    else if (s1[i] == '\0' && s2[j] != '\0') return -1;
    return 0;
}

5) 自定义字符串逆序算法 my_strrev #

字符串逆序操作是极其经典的原地指针置换算法：

c
void my_strrev(char *str) {
    if (str == NULL) return;
    int len = 0;
    // 1. 获取长度
    while (str[len] != '\0') {
        len++;
    }
    // 2. 双指针相向而行，原地交换字节
    int i = 0;
    int j = len - 1;
    while (i < j) {
        char temp = str[i];
        str[i] = str[j];
        str[j] = temp;
        i++;
        j--;
    }
}

8.3 C 语言字符串操作的安全陷阱与缓冲区溢出 #

由于 C 语言的标准字符串操作函数不提供自动越界边界检查，开发中如果传入非法的非 null 封尾字符数组或分配空间过小，会直接导致可怕的缓冲区溢出 (Buffer Overflow)。

1) strcpy 与 strcat 内存重叠与越界陷阱 #

  • 无边界检验：strcpy(dest, src) 和 strcat(dest, src) 会持续向后拷贝字节，直至在 src 中遇到结束符 \0 为止。
  • 致命的内存空间排列影响（重叠效果案例）： 设在进程的栈空间（或 DATA 段）中紧挨着定义了两个字符数组：
    • Case 1（先定义 str2，后定义 str1）： str1 被编译器存放在比 str2 更高的地址段上。如果调用 strcat(str1, str2) 时发生了溢出，由于 str1 的后方是未知的系统保护区域，程序会立刻发生段错误 (Segmentation Fault) 崩溃强退。
    • Case 2（先定义 str1，后定义 str2）： str2 紧随其后排在 str1 的高地址内存中。如果调用 strcat(str1, str2) 发生溢出，溢出的字符不会引发程序崩溃，而是会静默地覆盖并修改 str2 存储的数据！例如，str1 超长部分的字符会直接写入 str2 的内存中，导致 str2 的内容被意外篡改。
  • 非 C 字符串输入隐患：如果传入的 src 指针指向一个缺失 \0 结束符的纯字符数组，strcpy 将越过该数组界限，持续将内存中邻近的数据拷贝到 dest，导致目标缓冲区严重崩溃，或直接改写无关变量的值。

2) strlen 与 malloc 动态内存分配的“少 1 字节”陷阱 #

strlen(str) 函数在计算长度时不包含末尾的空终止符 \0。

  • ❌ 致命错误示范：
    c
    char *copy = (char *)malloc(strlen(src)); // 漏掉了 1 字节！
strcpy(copy, src); // 拷贝时写入了结束符 '\0'，越界覆写了 malloc 分配块的下一个字节！
  • 崩溃分析：malloc 申请的内存块前后通常保存着堆管理器的控制头数据。越界写入的这个 \0 字节极易把控制头数据篡改。此时程序运行不会立刻报错，但当执行 free(copy) 时，堆管理器会因找不到合法的控制头，导致程序直接崩溃或发生内存泄漏。
  • 正确写法：必须为 \0 预留空间：char *copy = (char *)malloc(strlen(src) + 1);

3) sprintf 格式化越界与 snprintf 救赎 #

  • sprintf(buf, "%s...", data) 也是无边界限制的写入，极易溢出。
  • 安全替代方案：应全面使用带有限长安全机制的版本，如用 snprintf() 代替 sprintf()，用 strncpy() 代替 strcpy()，用 strncat() 代替 strcat()。
  • strncpy 的残缺美：如果 src 的长度大于或等于指定的限制参数 n，strncpy 在拷贝完前 n 个字符后，不会在目标串末尾自动补写 \0！
    • 安全使用规范：每次调用 strncpy 后，必须手动在末尾封包：
      c
      strncpy(dest, src, sizeof(dest) - 1);
dest[sizeof(dest) - 1] = '\0'; // 强制封包，确保绝对安全

9.3 约瑟夫环生存算法 (Josephus Problem) #

33 个犯人排成一圈报数，报到 7 的枪毙，求最后生还者的序号。使用状态数组进行指针自增环形包裹处理：

c
#include <stdio.h>

int main() {
    int fanren[33] = {0}; // 0 表示存活，1 表示死亡
    int i, j, k = -1;
    
    for (i = 0; i < 32; i++) { // 循环枪毙 32 个人
        for (j = 0; j < 7; j++) { // 每次数 7 个人
            k++;
            if (k == 33) k = 0; // 核心：下标环状越界包裹处理
            if (fanren[k] == 1) j--; // 如果当前位置人已死，不占报数，计数值减 1
        }
        fanren[k] = 1; // 击杀第七个人
    }
    
    for (i = 0; i < 33; i++) {
        if (fanren[i] == 0) {
            printf("最后幸存者是: %d 号\n", i + 1); // 幸存者是 31 号
        }
    }
    return 0;
}

9.5 杨辉三角生成与输出 (Pascal's Triangle) #

杨辉三角每行的首尾元素为 1，中间任意元素等于上一行左上角与右上角元素之和：

c
#include <stdio.h>
#define LINE 10

int main() {
    int yanghui[LINE][LINE] = {0};
    int i, j;
    
    for (i = 0; i < LINE; i++) {
        for (j = 0; j <= i; j++) {
            if (j == 0 || i == j)
                yanghui[i][j] = 1; // 边界为 1
            else
                yanghui[i][j] = yanghui[i-1][j-1] + yanghui[i-1][j]; // 状态方程
        }
    }
    
    // 规范对齐打印三角
    for (i = 0; i < LINE; i++) {
        for (j = 0; j <= i; j++) {
            printf("%-4d", yanghui[i][j]);
        }
        printf("\n");
    }
    return 0;
}

10. 实战算法：使两数组元素交换后和之差最小 #

10.1 问题描述 #

有两个数组 a 和 b，大小都为 n，数组元素的值任意且无序。要求通过交换 a 和 b 中的元素，使得数组 a 元素的和与数组 b 元素的和之间的差绝对值最小。

10.2 核心算法实现 (C 语言版) #

下面是一个通过迭代尝试减少两数组和之差的经典局部搜索算法：

c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>

// 交换两数
void swap(int *x, int *y) {
    int temp = *x;
    *x = *y;
    *y = temp;
}

// 获取数组和
int get_sum(int arr[], int n) {
    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum += arr[i];
    }
    return sum;
}

// 最小化两数组和的差值
void minimize_diff(int a[], int b[], int n) {
    int sum_a = get_sum(a, n);
    int sum_b = get_sum(b, n);
    int diff = sum_a - sum_b;
    
    // 如果没有差值，直接返回
    if (diff == 0) return;
    
    int flag = 1;
    while (flag) {
        flag = 0;
        int best_i = -1, best_j = -1;
        int max_reduction = 0;
        
        // 寻找交换后能最大程度减少差值的两个元素
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                // 交换 a[i] 和 b[j] 后，新差值为: (sum_a - a[i] + b[j]) - (sum_b - b[j] + a[i])
                // 等于原差值 diff - 2 * (a[i] - b[j])
                int current_reduction = 2 * (a[i] - b[j]);
                
                // 我们希望新差值的绝对值小于原差值的绝对值
                if (abs(diff - current_reduction) < abs(diff)) {
                    // 如果新的改进大于之前的记录，则更新
                    if (abs(diff) - abs(diff - current_reduction) > max_reduction) {
                        max_reduction = abs(diff) - abs(diff - current_reduction);
                        best_i = i;
                        best_j = j;
                    }
                }
            }
        }
        
        // 如果找到了最优的可行交换，执行交换并重新计算差值
        if (best_i != -1 && best_j != -1) {
            swap(&a[best_i], &b[best_j]);
            sum_a = get_sum(a, n);
            sum_b = get_sum(b, n);
            diff = sum_a - sum_b;
            flag = 1; // 继续下一轮迭代
        }
    }
}

int main() {
    int a[] = {1, 5, 9, 12, 18};
    int b[] = {2, 7, 10, 11, 20};
    int n = 5;

    printf("交换前:\n");
    printf("A 和: %d, B 和: %d, 差: %d\n", get_sum(a, n), get_sum(b, n), get_sum(a, n) - get_sum(b, n));

    minimize_diff(a, b, n);

    printf("交换后:\n");
    printf("A 和: %d, B 和: %d, 差: %d\n", get_sum(a, n), get_sum(b, n), get_sum(a, n) - get_sum(b, n));

    return 0;
}
