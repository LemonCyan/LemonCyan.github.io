面向C++程序员的CSharp教程 #

C# 大致可以看作是 C++ 和 Java 的结合体。其核心概念是引用类型（Reference Types）。这一特性借鉴自 Java，如今已被多种主流语言采用，值得深入理解。它是一套巧妙的机制，支持隐式指针和堆内存使用，并且实现了自动垃圾回收（Garbage Collection）。

C# 比 C++ 更冗长，添加和修改小型功能时更顺手，但整体风格难以明确界定。第一部分介绍 C# 中的语法差异与语法糖，第二部分讲解引用类型，第三部分则介绍那些理解引用类型后才合理的更多差异与语法糖。最后第四部分是关于 C# 编程文化的一些说明。

1 与 C++的细微差异 #

1.1 杂项 #

  • 移除了 if(n=3) 这类问题。C# 不允许任何类型隐式转换为 bool，因此会将其视为语法错误。你需要将所有 if(n) 替换为 if(n!=0)，不过这并不算麻烦。 但 if(b=true) 仍然是可怕的逻辑错误，且指针仍会隐式将空/非空转换为真/假：if(ptr) 等价于 if(ptr!=null)。

  • 类型转换语法相反，类型必须放在括号内：使用 (int)n 而非 int(n)。风格借鉴自 Java。

  • char 类型占 2 字节（采用 UTF-16 编码格式，基本兼容 ASCII）。 若需要将 char[] 用作字节数组，C# 提供了 byte 类型。

  • 点号（.）兼具作用域解析运算符的功能。C++ 中的 c1.age = Cat::maxAge 在 C# 中写成 c1.age = Cat.maxAge。 更极端的例子：Cat::primeCat.age 会变成 Cat.primeCat.age。设计初衷是让初学者只需学习一个“属于”运算符。 双冒号运算符并未被移除，而是被重新用途化。global:: 可以作为路径的起始部分。如果你想了解它，它被称为命名空间别名限定符。

  • 没有 typedef。但 using 关键字被重载，可实现有限的类型定义功能： using intList = System.Collections.Generic.List<int>;（注意此处使用点号进行作用域解析）。但这种定义仅在当前文件有效，且不能用于基本类型：using tailLen t = int; 会报错。奇怪的是，函数指针有专门的类型定义语法（delegate）。

  • 不支持宏。#define sqr(x) (x*x) 是不允许的。

  • 使用未初始化变量会导致编译错误。编译器对此检查非常严格，有时甚至会在无法跟上你的逻辑时，误判变量未初始化。 类似地，将可能未初始化的变量传递给函数、传递包含未初始化字段的结构体，都会导致编译错误——无论函数是否会使用这些变量/字段。其目的是确保 C# 程序永远不会读取无效的垃圾值，也不会因此出现难以复现的间歇性错误。

  • var n = 8; 或 var w = "cow"; 会自动推断类型，类似 C++ 的 auto。 本质上编译器会将 var 替换为具体类型，且该类型必须能被立即确定。理论上这是个小众特性，但在 C# 代码中却被大量使用，甚至毫无意义地替换短类型名。

  • 命名空间中只能包含类和枚举，不能包含变量或函数。 你需要将这些变量/函数定义为静态成员，放在一个“占位类”中。 class stringFuncs { // 占位类 public static string bestWord; public static int compareSomehow(string w1, string w2) {... } } 注意，使用时仍通过点号访问：stringFuncs.bestWord = "cow";`。

  • using 指令的使用受到限制：只能放在文件顶部，且不能指定命名空间中的单个成员。 最多只能写成 using System.Collections.Generic;，无法直接指定 LinkedList。 using 可用于命名空间或类，但引用类时需要额外添加 static 关键字：using static stringFuncs;。 补充说明：using 还有第三种完全不同的用途——using 代码块。当代码块执行完毕时，会立即调用对象的析构函数（用于资源释放）。

  • 没有持久化局部变量： void A() { static int n=0; ...} 这种写法不存在。这其实不算问题——C# 鼓励你编写小型类，用成员变量作为持久化存储。

  • C# 支持与 C++ 类似的指针用法，但只能在“不安全模式（UnSafe mode）”下使用，而大多数运行环境并不支持不安全模式。因此，实际上 C# 中没有显式指针，相关功能由引用类型替代。

  • 数组的变化：

    • 方括号是类型的一部分。这一点非常便捷，示例： int[] A, B; // 两个 int 类型数组 int[] func_takeArray_returnArray(int[] A) { ... }// 参数和返回值同理：

    • 数组自带长度信息：通过 Length 成员函数获取。无需再手动传递 。

    • 索引范围检查：若 A[n] 访问越界，会抛出运行时错误。我知道，这让语言看起来像是给初学者用的，但实际编写快速原型代码时很实用——你可以随意使用数组，即使出错也会得到清晰的异常信息和堆栈跟踪。

    • 除了 [][] 交错数组，还支持矩形多维数组。

    • 交错数组的语法与 C++ 相反。它并非简单的“数组的数组”组合，而是有额外规则，必须从左到右声明。 再举一个示例（源自 StackExchange），更清晰地说明这种“从左到右”规则：

      csharp
      //`int[][,]` 表示“一个数组，其元素是矩形二维数组”：
int[][,] A = new int[4][,]; // 语法确实反直觉
Console.WriteLine(A.Length); // 4
A[0] = new int[4,9];
A[1] = new int[5,2]; // 仍为交错数组，各子数组长度可不同

  • 函数调用时可选择性地指定参数名。max(3,4) 和 max(x:3, y:4) 完全等价。有时用于自注释代码，或灵活调整参数顺序，实际用途是在众多可选参数中只指定部分：

    c#
    void A(int cats, int dogs) { ... } 
A(dogs:5, cats:2); // 等价于 A(2,5)，注意 dogs 先传入
void doStuff(int a=0, int b=0, int c=0, int d=0) { ... } 
doStuff(d:5); // a、b、c 使用默认值，仅指定 d

  • 函数指针的工作方式与 C++ 大致相同。以下代码声明 ff 为指向“接收两个 string 参数、返回 int 的函数”的指针，注意返回类型在末尾而非开头，且使用 System.Func 而非 C++ 风格的 System::Func。使用方式相同，但无需（也不能）添加引用（&）或解引用（*）运算符：

    • 无返回值时，System.Func 不适用（不能写 <string,string,void>），此时需使用 System.Action——它与 System.Func 功能一致，只是默认返回类型为 void
    • 无输入参数时，省略尖括号：System.Action f3; 表示无参无返回值的函数指针。
    • 还有一种旧语法，需先通过 delegate 定义类型别名（类似 typedef）：两种方式完全互通。正因这种旧语法，C# 中的函数指针也被称为“委托（delegate）”。
    c#
    delegate int strCmp_t(string x, string y);
strCmp_t ff;
System.Func<string, string, int> ff; 
// 等价于 C++ 的 int (*f)(string,string);
ff = charsInCommon; // 将函数赋值给 ff 
x = ff("cow", "wookie"); // 可能返回 "ow" 对应的长度
System.Action<int> f2;

  • 支持匿名函数（称为 Lambda 表达式，但并非严格意义上的 Lambda——不支持上下文捕获）。函数体语法与普通函数一致。参数部分无需指定类型（编译器可自动推断），返回类型也会自动推断。=> 是匿名函数的关键字。若函数体仅含单个返回语句，可省略 return 和大括号。还有一种使用 delegate 关键字的过时语法，无使用必要，但仍可能在旧代码中见到。

csharp
gg = (x,y) => { return x*2 - y; };
gg = (x,y) => x*2 - y;
  • C++ 模板函数的功能在 C# 中被拆分为两个特性：
    • 泛型（generics）：语法类似 C++ 模板，但不支持“鸭子类型”——函数体中只能假设类型支持赋值运算符（=），这是一个很大的限制。你可以指定类型必须是类（where T : class），此时函数体可使用 == 进行指针比较，但仍不够实用。 最终可限制输入类型为某个类的子类（where T : Animal），例如从 Animals 列表中筛选 Dog 或 Cat：T aa = Animals[i] as T;。显然，C++ 模板函数的许多实用功能在泛型中无法实现。
    • dynamic 关键字：将变量标记为动态类型，类似模板类型 bool longEnough(dynamic n) { return n.Length > 10; }。限制是：无法简洁地强制两个输入参数为同一类型，也无法直接声明该类型的局部变量（据说可通过 typeof 规避，但较为繁琐）。
  • 不允许用内部作用域变量隐藏外部作用域变量。明确来说，这是将不良编程风格直接列为错误。int i = 8;for(int i=0; i<10; i++) {} // C# 报错：内部 i 隐藏外部 i
  • 有限的“真正引用变量”：不允许 int& n = C[i].age;。但可声明 ref int n，且只能通过“按引用返回”的函数赋值。注意必须添加所有冗余的 ref 关键字。限制是：被引用的对象必须在堆上（但可以是类中的值类型，例如 Cat 中的 age）。
c#
// 通过按引用返回函数赋值引用变量 
ref int n = ref getAgeRef(c1); // 等价于 C++ 的 int& n = &c1.age; 
// 按引用返回函数的定义 
ref int getAgeRef(Cat cc) { ref return cc.age; }
  • 没有头文件或函数原型。但也无需这些——C# 环境会自动扫描所有文件查找依赖。
  • 容器类：
    • List 替代 C++ 的 Vector，基于数组实现。奇怪的是，它包含部分时间复杂度为 O(n) 的成员函数，且没有 pop_back 方法。
    • LinkedList 对应 C++ 的链表类。
    • 哈希表映射类被重命名为 Dictionary（对应 C++ 的 unordered_map）。
    • ArrayList 是 Java 风格的旧版混合类型数组，存储 Object 类型（所有类型的基类），不推荐使用。
  • foreach 循环语法糖：可遍历数组和大多数容器：适用于任何支持外部迭代器的类型（实际上是实现了标准“向前迭代器”接口的类型）。
  • 序列化（Serialization）：无需复杂操作，任何类都可序列化为 XML 格式，之后再反序列化恢复。通常图形界面（GUI）开发中会用到这一特性。标准序列化假设字段是简单的“自有数据”，会递归序列化所有嵌套数据。若数据结构包含指针，则需要额外大量工作。
  • 反射（Reflection）：类的 GetMethods 方法会返回所有函数的签名和名称（包括私有函数），之后可通过这些句柄调用函数。适用于一些特殊场景：例如为任何类快速制作可视化编辑器，或调用编译时未知的类。有时你会看到代码“违规”访问私有变量/函数——它们正是通过反射实现的。反射对实现已知功能没有帮助。

1.2 类/结构体、继承差异 #

  • 结构体（struct）和类（class）的默认访问修饰符是 private，且 public 不会“继承传递”——必须为每个成员显式添加 public。纯数据结构体的写法继承自 Java 的设计：良好的面向对象编程（OOP）应让开发者“费力”才能暴露破坏封装的公共变量。
c#
public struct Dog { 
	public string name; 
	public int age; // 若不加第二个 public，age 会是 private 
}
  • 类中的所有成员变量都会被自动初始化（本质上是默认构造函数的作用），但只要你自定义了任何构造函数，系统就不会再自动生成默认构造函数。类的成员变量可在定义时指定初始值，编译器会秘密将这些初始化逻辑注入到所有构造函数（包括默认构造函数）中。示例：
c#
public class Spot { 
	public int n; // 仅在默认构造函数中初始化为 0 
	public int x = 99; // 任何构造函数都会执行 x=99 
	public string w = getNextName(); // 甚至可以调用函数，同样在构造函数中执行 
}
  • 继承中的动态转换使用 baseClass as subclass 语法。示例：
c#
Animal aa; // Cat 的父类 
Cat cc = aa as Cat; 
if(cc != null) // 确认 aa 是 Cat 类型
  • 不支持类的多重继承。借鉴自 Java 的解决方案是：可实现任意数量的“接口（interface）”。接口是纯契约，本质上是只包含抽象虚函数（=0 函数）的抽象类：
c#
// C++ 版本 
class Worker { public: virtual int doWork() = 0; } 
// 等价的 C# 版本 
interface Worker { int doWork(); // 隐式为 public、virtual 和 abstract }
  • 接口仅能要求实现虚函数，不能包含自身的变量，也不能提供任何实用代码（无默认实现、无辅助函数）。C# 风格要求接口名以大写 I 开头（如 IWorker）。这可能让人误以为接口类型和类类型的指针不可互换，但实际上它们完全兼容——接口类型可像其他父类一样声明变量或作为参数。由于仅能继承一个实际类，调用父类成员的语法被简化：用 base.cost() 替代 C++ 的 animal::cost()。（无需访问继承的接口成员，因为接口没有可访问的具体内容。）虚函数的声明需要额外一步：父类中在函数前添加 virtual（表示该函数可被重写），子类中必须在重写函数前添加 override：
c#
class Animal { // 父类，无特殊之处 
public virtual void eat() {} // 关键：标记为可虚函数 
public virtual void sleep() {} // 同理 
} 
class Cat : Animal { 
public override void eat() { ... } // 标记为虚函数重写 
public void sleep() { ... } // Cat.sleep 不是虚函数 
}

  • 子类中未重写的函数应添加 new 关键字（表示隐藏父类函数），但这是默认行为，因此很少有人显式添加。

    1. new 关键字被用于完全不同的用途（既用于创建对象，也用于隐藏父类函数）。
    2. 这并非实用特性——建议所有需要重写的函数都显式添加 override。
    3. 官方设计理由：假设 Cat.eat 最初是子类中的普通函数，之后父类 Animal 独立添加了 virtual eat 函数。该规则可帮助发现：旧的 Cat.eat 可能不满足 Animal.eat 的后置条件，因此不应被重写。

  • 没有友元函数（friend functions）。

  • 扩展方法（Extension methods）：纯粹的语法糖——本质是普通函数，但调用方式类似成员函数。它无法访问私有变量，也不能是虚函数——除调用语法外，与普通函数完全一致。定义时需在第一个参数前添加 this。调用方式：c1.passTime(4);。唯一用途是允许通过“对象.方法名”的方式调用，方便在 IDE 中通过下拉列表查找。注意：参数列表中的 this 是关键字的又一次复用。

c#
// 第一个参数 "this Cat" 使其成为 Cat 的扩展方法 
public static void passTime(this Cat c, int days) { 
... // 模拟睡觉、进食等逻辑 
// 注意：仅能访问 Cat 的公共成员 
}
  • 属性（Properties）：简化 getter/setter 方法对的编写。使用时完全像访问变量，无需 n = c1.getYears(); 和 c1.setYears(4);，直接 n = c1.years; 和 c1.years = 4;。
  • 属性的使用非常普遍，被视为定义简单变量的“标准方式”。系统会为左值（赋值操作）调用 set，为其他场景调用 get。
  • 无逻辑的空 getter/setter 极为常见，因此有专门的“自动属性（auto-properties）”
c#
class Cat { 
	public int monthsOld; 
	public int years { // 基于 monthsOld 实现的 get/set 
		get { return monthsOld / 12; } // 读取时调用 
		// 赋值时调用，value 是关键字 
		set { if(value < 0) value = 0; monthsOld = value * 12; } 
	}
}

class Cat {
    int _age; // 私有后备变量
    public int age { 
	    get { return _age; } 
	    set { _age = value; } 
    }
}

//自动生成隐藏的后备变量和上述空逻辑代码
public int age { get; set; }

2 引用类型 #

这是 C# 与 C++ 最核心的差异，借鉴自 Java。其设计目标是：隐藏指针和堆/栈的细节，为指针和非指针使用提供统一语法，并支持自动垃圾回收。

2.1 工作原理 #

  • 类型分为两类：不能使用指针的类型，和必须使用指针的类型。
    • 第一类很简单：基本类型（int、float、string、char、bool 等）永远不能有指针——C# 中不存在指向这些类型的指针。
    • 第二类称为引用类型（Reference Types），包括所有自定义类。它们只能是指针，且只能通过 new 在堆上创建——无法像 C++ 那样直接声明类的实例。正因为这一限制，语言可以简化其使用：无需额外语法声明为指针，且会自动解引用。
c#
Cat c1; // 自动被视为指针（引用） 
c1 = new Cat(); // 创建可用 Cat 的标准方式 
c1.name = "fritz"; // 自动解引用 c1
  • Cat c1 = new Cat(); 本质是堆内存分配，看似开销较大，但由于自动垃圾回收，C# 开发者无需关心堆内存的管理细节。术语说明：c1 被称为“引用（reference）”。

因为 Cat 是引用类型，所以所有指向 Cat 的指针都叫引用。关于该机制的几点观察：

  • 指针永远不能指向栈数据。栈上只能存储“值类型”，且无法创建指向值类型的指针。
  • 没有取地址（&）、解引用（*）或箭头（->）运算符。这些运算符在普通类型中被禁用，在引用类型中则通过隐式方式实现。
  • 即使不需要，也必须使用指针和 new。大多数时候我们想要的是 C++ 中“自动存储期”的 Cat，但 C# 强制我们声明堆上 Cat 的指针。因此，C# 程序会产生大量看似“无意义”的垃圾。从 C++ 开发者的视角来看，C# 的内存管理似乎完全没有章法。
  • 没有二级指针（Cat**）。若需类似功能，需创建一个包含单个引用类型成员的小型类。
  • 没有销毁（destroy）命令。好处是不会出现悬空指针——垃圾回收器会定期通过“可达性分析”回收内存：只要有指针指向某个对象，它就不会被销毁。

除语法简化外，引用本质上就是指针：可以为 null，赋值（=）是指针赋值，相等判断（==）是指针比较：

c#
Cat c1 = null; 
c1.name = "Boots"; // 崩溃（空引用异常） 
if(c1 != null) 
	c1.name = "Boots"; // 标准空指针检查 
Cat c1 = new Cat(), 
c2 = new Cat(); 
if(c1 == c2) 
	Console.WriteLine("false：指向不同内存"); 
c2 = c1; // 指针赋值，现在两者指向同一个 Cat

将类变量传递给函数时，本质是按值传递指针：

c#
void catFunction(Cat c1) { 
c1.name = "Squeeky"; // 通过指针修改共享对象 
c1 = null; // 仅修改本地的 c1 指针副本 
}

返回类对象本质是返回指针。以下函数返回指向原始 c1 或 c2 的指针：

c#
Cat longestName(Cat c1, Cat c2) { 
if(c1.name.Length > c2.name.Length) 
	return c1; 
	else return c2; 
}

类中的成员变量若为引用类型，本质也是指针，这容易让人混淆。例如以下代码中，c 初始为 null，需要手动创建实例：

c#
class Home { 
	Cat c; // 初始为 null，需手动执行 c = new Cat(); 
	... 
}

标准链表节点的写法可能让人感到奇怪：next 看似是嵌套的 CatList，但实际上是指针：

c#
class CatList { 
	public Cat c; // 实际存储的 Cat 对象 
	public CatList next; // 仅为指针（引用） 
}

阅读引用类型代码的关键技巧是：在脑中明确区分“普通变量”和“指针”。

c#
Cat c1 = new Cat(); // 视为“实际的 Cat 对象”，c1 被认为是“绑定的” 
Cat c2 = c1; // c2 被用作指向该 Cat 的指针

另一个例子：C++ 中可用 Vector<Cat*> 筛选 Vector<Cat> 中的部分元素，但 C# 中两者都用 List<Cat>，因此需要通过上下文判断哪些是作为指针使用的。

2.2 作为引用类型的数组 #

  • C# 数组是引用类型。数组变量本质是指向堆上实际数组的非 const 指针。不支持指针运算——B 永远不能指向 A 的中间位置。合法的 C# 数组使用方式如下
c#
int[] A = new int[maxCows]; // 注意：使用常量无优势，因为数组始终在堆上动态分配 
int[] B = A; // B 指向 A 
if(A == B) {} // 指针比较，结果为 true 
A = null; 
B = null; // 第 1 行创建的数组现在可被垃圾回收

2.3 结构体与引用类型 #

  • Java 等语言仅支持类作为引用类型，该机制完全可用。C# 额外增加了一个不必要的复杂性：struct 关键字定义值类型类。示例：
c#
struct Point { public double x, y; } 
Point p1; // 终于有了普通的栈变量 
p1.x = 5; // 直接访问，无需 new

这看似很方便——可以像 C++ 那样使用栈上的简单对象。但由于是值类型，永远不能创建指向它的指针（这也意味着结构体不能有虚函数）。实际开发中，class 是首选类型——任何可能需要指针的场景都应使用 class。将对象定义为 struct 被视为一种“为追求性能而冒风险、易出错的做法”。注意：结构体的默认访问修饰符仍是 private。

赋值（=）是成员级浅拷贝，相等判断（==）是成员级比较。结构体与类的对比示例：CatTracker 包含一个引用类型和一个值类型：

c#
class CatTracker { 
	public Cat c; // 指针（引用） 
	public Point spot; // 内嵌值类型 
	public CatTracker() { 
		spot.x = 0; 
		spot.y = 0; // 直接赋值，安全 
		c = new Cat(); // 引用类型必须手动创建实例 
		c.age = 4;
		... 
	}
}

创建 CatTracker ct = new CatTracker(); 时，堆上会创建一个 CatTracker 对象，其中包含内嵌的 Point spot 和指向 Cat c 的指针（c 由 CatTracker 持有）。结构体的一个奇怪语法：构造函数必须使用冗余的 new。

c#
Point p1; 
p1.x = 6; 
p1.y = 8; // 合法，但也可写成： 
p1 = new Point(); // 仅将 x、y 初始化为 0，并非堆分配

这之所以可行，是因为结构体永远不能在堆上创建——new 在这里完全多余。设计目的是让初学者无需区分 Thing 是类还是结构体，都能使用 Thing t = new Thing(); 初始化，两种情况下 t 都会被正确设置。

结构体的最后一个问题是“穿透赋值失效”。假设 c.p.x = 7; 中，c 通过 get 属性返回 p（C# 开发者通常使用属性而非直接暴露字段）。若 Point 是类，这没问题——get 返回指针，可直接修改原始对象；但如果 Point 是结构体，get 会返回 p 的副本，对 x 的赋值只会修改副本，原始对象不会变化。

3 杂项特性 #

引用传递 #

  • C# 支持标准的按引用传递（pass-by-reference），分为“仅输出”和“输入输出”两种专门形式。用 ref 替代了 C++ 的 &，且调用时必须为变量添加 ref 修饰。设计初衷是让调用者明确知道参数会被修改（但实际作用有限）。
c#
void swap(ref int x, ref int y) {...} // 两个参数均按引用传递 
swap(ref num1, ref num2); // 调用时必须添加 ref 关键字

仅输出形式用 out 替代 ref（声明和调用时都需替换），并修改了错误规则：

  1. 实参未初始化不会报错（正常情况下这是编译错误）；
  2. 函数内必须为该参数赋值；
  3. 函数内尝试读取该参数会报错。

核心用法就是这些，但从文化角度看，按引用传递属于高级话题。一方面，几乎所有对象都是按指针传递的，无需按引用传递：

c#
void fixCat(Cat c) { 
	if(c.age < 0) c.age = 0; // 通过指针修改，完全有效 
}

另一方面，术语容易混淆——C# 开发者从一开始就将 Cat c1 称为“引用”，因此“按引用传递引用类型”“按引用传递值类型”等表述非常绕口。微软官方文档曾一度错误地声称“所有类都是按引用传递的”。

LINQ 库 #

它包含一些 SQL 风格的函数，可直接查询数据库，无需额外 API；还提供了一套完全冗余、功能更弱的 SQL 风格语法（示例源自微软文档）：

c#
var q = from c in customers where c.City == "Raleigh" select c;

此外，命名空间中还无理由地包含了常见的列表查询函数——例如“返回所有满足谓词的元素”等。但这些函数都不能修改原始列表，且大多数会创建延迟计算的对象——通常需要在末尾添加 .ToArray() 或 .ToList() 才能立即获取结果。

  • 官方文档是微软的 C# 网站。该文档很多地方不完整，但这似乎被认为是可接受的。
