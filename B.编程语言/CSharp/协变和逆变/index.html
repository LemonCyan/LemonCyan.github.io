协变和逆变

C# 协变与逆变：泛型类型兼容的核心机制（面向 C++ 程序员） #

C# 中的协变（Covariance） 和逆变（Contravariance） 是针对 泛型接口 / 委托 的特性，核心目的是 在类型安全的前提下，支持泛型类型的隐式转换—— 简单说，就是让 IFoo<子类> 和 IFoo<父类> 之间能合理兼容，解决默认泛型 “不变性” 导致的灵活性不足问题。

对 C++ 程序员来说，这是 C# 泛型独有的特性（C++ 模板无直接对应，但可类比 C++ 函数指针的类型兼容规则、C++20 concepts 的约束逻辑），其设计核心是 “类型安全优先”：所有协变 / 逆变转换都必须经过编译器验证，确保不会出现类型转换异常（如将 Dog 存入 List<Cat>）。

一、先搞懂：默认泛型是 “不变的”（为什么需要协变 / 逆变？） #

在理解协变 / 逆变前，必须先明确：C# 泛型默认是 不变的（Invariant）—— 即 List<Cat>（子类泛型）和 List<Animal>（父类泛型）之间没有任何隐式转换关系，即使 Cat 是 Animal 的子类。

示例：默认不变的问题 #

假设存在继承关系：Cat : Animal（Cat 是 Animal 的子类）：

csharp

运行

csharp
class Animal { }
class Cat : Animal { }
class Dog : Animal { }

// 以下代码均编译报错（默认泛型不变）
List<Cat> cats = new List<Cat>();
// List<Animal> animals = cats; // 报错：无法将 List<Cat> 隐式转换为 List<Animal>
// List<Cat> cats2 = new List<Animal>(); // 报错：无法将 List<Animal> 隐式转换为 List<Cat>

为什么默认不变？（类型安全的必然要求） #

如果允许 List<Cat> → List<Animal> 的隐式转换，会出现严重的类型安全问题：

csharp

运行

csharp
// 假设允许这种转换（实际编译报错）
List<Cat> cats = new List<Cat>();
List<Animal> animals = cats; // 非法转换（假设合法）

// 向 animals 中添加 Dog（Animal 的子类，看似合理）
animals.Add(new Dog()); // 此时 cats 列表中混入了 Dog，破坏类型一致性

// 后续从 cats 中读取时，会抛出 InvalidCastException（Cat 不能强转 Dog）
Cat cat = cats[0]; // 灾难！列表里实际是 Dog

正是为了避免这种 “类型污染”，C# 默认禁止泛型类型的直接转换 —— 但这也带来了灵活性问题：有些场景下，List<Cat> 确实 “可以当作”List<Animal> 使用（比如只读取元素，不修改），此时默认不变就显得过于严格。

协变和逆变的核心作用：在 “不破坏类型安全” 的特定场景下，允许泛型类型的隐式转换。

二、协变（Covariance）：子类泛型 → 父类泛型（out 关键字） #

1. 核心定义 #

协变是指：泛型接口 / 委托支持从 “子类泛型” 隐式转换为 “父类泛型”（转换方向与类继承方向一致：Cat → Animal → IFoo<Cat> → IFoo<Animal>）。

  • 标记：接口用 out 关键字修饰泛型参数（如 IEnumerable<out T>）；
  • 核心约束：泛型参数 T 只能作为 方法的返回值 / 只读属性（不能作为方法参数）—— 确保 “只出不进”，避免类型污染。

2. 典型示例：IEnumerable<out T>（C# 内置协变接口） #

IEnumerable<T> 是 C# 最常用的协变接口，其定义如下（简化）：

csharp

运行

csharp
// out 标记 T 为协变类型参数
public interface IEnumerable<out T>
{
    // T 仅作为返回值（GetEnumerator() 返回 IEnumerator<T>，其 Current 属性是 T）
    IEnumerator<T> GetEnumerator();
}

正因为 T 是协变的，所以以下转换是合法的：

csharp

运行

csharp
List<Cat> cats = new List<Cat> { new Cat() };

// 合法：IEnumerable<Cat> → IEnumerable<Animal>（协变转换）
IEnumerable<Animal> animals = cats;

// 遍历 animals：只能读取（IEnumerable 无 Add 方法），不会污染原列表
foreach (Animal animal in animals)
{
    Console.WriteLine(animal.GetType().Name); // 输出 Cat，类型安全
}

3. 协变的类型安全保障：out 关键字的意义 #

out 关键字强制约束：泛型参数 T 只能 “向外输出”（返回值 / 只读属性），不能 “向内输入”（方法参数）。这样一来，协变转换后无法修改原集合（如添加 Dog），自然不会出现类型污染。

如果尝试在协变接口中用 T 作为参数，编译器会直接报错：

csharp

运行

csharp
// 编译报错：协变类型参数 T 不能作为方法参数
public interface IFoo<out T>
{
    void Add(T item); // 错误：T 是协变类型，不能作为输入参数
    T GetItem(); // 合法：T 作为返回值
}

4. 委托的协变：Func<out TResult> #

委托也支持协变，典型例子是 Func<TResult>（无参数、返回 TResult 的委托）：

csharp

运行

csharp
// 定义：Func<out TResult>（TResult 是协变类型参数）
public delegate TResult Func<out TResult>();

// 子类返回值的委托
Func<Cat> getCat = () => new Cat();

// 合法：Func<Cat> → Func<Animal>（协变转换）
Func<Animal> getAnimal = getCat;

Animal animal = getAnimal(); // 返回 Cat，类型安全（Cat 是 Animal 的子类）

三、逆变（Contravariance）：父类泛型 → 子类泛型（in 关键字） #

1. 核心定义 #

逆变是指：泛型接口 / 委托支持从 “父类泛型” 隐式转换为 “子类泛型”（转换方向与类继承方向相反：Animal → Cat → IFoo<Animal> → IFoo<Cat>）。

  • 标记：接口用 in 关键字修饰泛型参数（如 IComparer<in T>）；
  • 核心约束：泛型参数 T 只能作为 方法的输入参数（不能作为返回值 / 只读属性）—— 确保 “只进不出”，避免类型不匹配。

2. 典型示例：IComparer<in T>（C# 内置逆变接口） #

IComparer<T> 是用于比较两个对象的接口，其定义如下（简化）：

csharp

运行

csharp
// in 标记 T 为逆变类型参数
public interface IComparer<in T>
{
    // T 仅作为输入参数（比较两个 T 类型对象）
    int Compare(T x, T y);
}

假设我们有一个比较 Animal 年龄的比较器，由于 T 是逆变的，它可以直接用于比较 Cat（子类）：

csharp

运行

csharp
// 实现 IComparer<Animal>：比较两个 Animal 的年龄（假设 Animal 有 Age 属性）
class AnimalAgeComparer : IComparer<Animal>
{
    public int Compare(Animal x, Animal y)
    {
        return x.Age.CompareTo(y.Age);
    }
}

// 创建父类泛型的比较器
IComparer<Animal> animalComparer = new AnimalAgeComparer();

// 合法：IComparer<Animal> → IComparer<Cat>（逆变转换）
IComparer<Cat> catComparer = animalComparer;

// 用 catComparer 比较两个 Cat（类型安全：Cat 是 Animal 的子类，比较逻辑完全适用）
Cat cat1 = new Cat { Age = 3 };
Cat cat2 = new Cat { Age = 5 };
int result = catComparer.Compare(cat1, cat2); // 返回 -1（3 < 5）

3. 逆变的类型安全保障：in 关键字的意义 #

in 关键字强制约束：泛型参数 T 只能 “向内输入”（方法参数），不能 “向外输出”（返回值）。这样一来，父类的处理逻辑（如比较 Animal 年龄）完全适用于子类（Cat），不会出现类型不匹配。

如果尝试在逆变接口中用 T 作为返回值，编译器会报错：

csharp

运行

csharp
// 编译报错：逆变类型参数 T 不能作为返回值
public interface IFoo<in T>
{
    T GetItem(); // 错误：T 是逆变类型，不能作为返回值
    void Process(T item); // 合法：T 作为输入参数
}

4. 委托的逆变：Action<in T> #

委托的逆变典型例子是 Action<T>（接收 T 类型参数、无返回值的委托）：

csharp

运行

csharp
// 定义：Action<in T>（T 是逆变类型参数）
public delegate void Action<in T>(T obj);

// 父类参数的委托：处理 Animal
Action<Animal> feedAnimal = (animal) => Console.WriteLine($"喂食 {animal.GetType().Name}");

// 合法：Action<Animal> → Action<Cat>（逆变转换）
Action<Cat> feedCat = feedAnimal;

// 调用委托：传入 Cat（类型安全，Cat 是 Animal 的子类）
feedCat(new Cat()); // 输出：喂食 Cat

四、协变与逆变的核心规则（避坑关键） #

1. 标记规则：out = 协变，in = 逆变 #

特性 关键字 转换方向 泛型参数使用约束 典型例子
协变 out 子类泛型 → 父类泛型 仅作为返回值 / 只读属性 IEnumerable、Func
逆变 in 父类泛型 → 子类泛型 仅作为方法参数 IComparer、Action
不变 无 无隐式转换 可作为参数 / 返回值 List、Dictionary<TKey,TValue>

2. 适用范围：仅支持接口和委托 #

协变 / 逆变 只适用于泛型接口和泛型委托，泛型类（如 List<T>、Dictionary<T>）和泛型结构体不支持显式协变 / 逆变（默认不变）。

比如 List<T> 不能标记为协变，因为它的 Add(T) 方法允许修改集合（T 作为参数），this[int index] 既可以读（返回 T）也可以写（接收 T），不符合 out 或 in 的约束。

3. 类型限制：仅支持引用类型 #

协变 / 逆变的转换只支持引用类型，值类型（如 int、DateTime）不支持。例如：

csharp

运行

csharp
IEnumerable<int> ints = new List<int>();
// IEnumerable<object> objs = ints; // 编译报错：值类型不支持协变转换

原因：值类型在泛型中会被 “具体化”（如 List<int> 和 List<object> 是完全独立的类型，无继承关系），而引用类型的泛型实例共享相同的接口结构。

4. 类型安全：编译器强制校验 #

所有协变 / 逆变转换都由编译器验证，确保不会出现运行时类型异常。核心逻辑是：

  • 协变（out）：只能 “读”（返回值），不能 “写”（参数）→ 不会污染原集合；
  • 逆变（in）：只能 “写”（参数），不能 “读”（返回值）→ 父类逻辑适用于子类。

五、与 C++ 的类比（帮助理解） #

C++ 没有直接的 “协变 / 逆变” 关键字，但存在类似的类型兼容场景，可作为类比：

1. 协变类比：C++ 函数指针的返回值协变 #

C++ 中，函数指针的返回值支持 “子类→父类” 的协变（与 C# 协变一致）：

cpp

运行

cpp
class Animal {};
class Cat : public Animal {};

// 父类返回值的函数指针
typedef Animal* (*FuncAnimal)();
// 子类返回值的函数
Cat* CreateCat() { return new Cat(); }

// 合法：FuncCat → FuncAnimal（返回值协变，与 C# 协变逻辑一致）
FuncAnimal func = CreateCat;
Animal* animal = func(); // 安全，Cat* 可隐式转换为 Animal*

2. 逆变类比：C++ 函数指针的参数逆变 #

C++ 中，函数指针的参数支持 “父类→子类” 的逆变（与 C# 逆变一致）：

cpp

运行

cpp
// 子类参数的函数指针
typedef void (*FuncCat)(Cat*);
// 父类参数的函数
void FeedAnimal(Animal* animal) { /* 处理逻辑 */ }

// 合法：FuncAnimal → FuncCat（参数逆变，与 C# 逆变逻辑一致）
FuncCat func = FeedAnimal;
func(new Cat()); // 安全，Cat* 可隐式转换为 Animal*

3. 核心差异 #

  • C#：通过 out/in 关键字显式标记协变 / 逆变，仅适用于泛型接口 / 委托，编译器严格校验；
  • C++：无显式标记，通过函数指针 / 成员函数指针的类型兼容规则隐式支持，适用于函数类型，无泛型层面的直接对应。

六、实际开发中的应用场景 #

1. 协变：多态集合的只读访问 #

当你需要将 “子类集合” 当作 “父类集合” 只读遍历（如展示所有动物，不管是猫还是狗）时，协变接口（IEnumerable<T>）是关键：

csharp

运行

csharp
// 假设存在多个 Animal 子类
List<Cat> cats = new List<Cat>();
List<Dog> dogs = new List<Dog>();

// 协变转换：统一转为 IEnumerable<Animal>
IEnumerable<Animal> allAnimals = cats.Concat<Animal>(dogs);

foreach (var animal in allAnimals)
{
    Console.WriteLine(animal.GetType().Name); // 安全遍历所有动物
}

2. 逆变：通用处理逻辑的复用 #

当你有一个 “处理父类” 的逻辑，想复用它处理所有子类时，逆变接口 / 委托能减少重复代码：

csharp

运行

csharp
// 通用处理 Animal 的逻辑
void PrintAnimalInfo(Animal animal)
{
    Console.WriteLine($"Name: {animal.Name}, Age: {animal.Age}");
}

// 逆变委托：Action<Animal> → Action<Cat>
Action<Cat> printCatInfo = PrintAnimalInfo;
Action<Dog> printDogInfo = PrintAnimalInfo;

// 复用同一逻辑处理不同子类
printCatInfo(new Cat { Name = "Fritz", Age = 3 });
printDogInfo(new Dog { Name = "Buddy", Age = 2 });

3. 自定义协变 / 逆变接口 #

当你设计通用组件时，可通过 out/in 标记泛型接口，提升灵活性：

csharp

运行

csharp
// 协变接口：仅返回数据（只读）
public interface IDataReader<out T>
{
    T ReadData();
}

// 逆变接口：仅处理数据（只写）
public interface IDataProcessor<in T>
{
    void ProcessData(T data);
}

// 使用示例：子类数据 reader 可转为父类 reader
IDataReader<Cat> catReader = new CatDataReader();
IDataReader<Animal> animalReader = catReader; // 协变转换

// 父类数据 processor 可转为子类 processor
IDataProcessor<Animal> animalProcessor = new AnimalDataProcessor();
IDataProcessor<Cat> catProcessor = animalProcessor; // 逆变转换

总结 #

协变和逆变的核心是 “在类型安全的前提下，提升泛型接口 / 委托的灵活性”：

  1. 协变（out）：子类泛型 → 父类泛型，仅支持返回值，适用于 “只读” 场景（如遍历）；
  2. 逆变（in）：父类泛型 → 子类泛型，仅支持参数，适用于 “通用处理” 场景（复用父类逻辑）；
  3. 不变：默认行为，泛型类 / 结构体均为不变，支持读写操作，但无隐式转换；
  4. 与 C++ 类比：类似函数指针的类型兼容规则，但 C# 是泛型层面的显式特性，更安全、更易复用。

对 C++ 程序员来说，无需纠结底层实现，记住核心：out 是 “输出”（协变），in 是 “输入”（逆变），一切转换都以类型安全为前提—— 编译器会帮你校验，只要不违反 out/in 的约束，就能放心使用。
