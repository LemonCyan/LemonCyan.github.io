并发集合

并发集合 #

C# 的 并发集合（Concurrent Collections） 是 System.Collections.Concurrent 命名空间下的线程安全数据结构，核心设计目标是：简化多线程场景下的共享数据访问，无需手动编写锁逻辑（如 lock、Monitor），同时通过细粒度锁、无锁算法等优化，平衡线程安全和性能 —— 完美解决了 C++ 中 “容器 + 手动锁” 模式的繁琐、易错问题。

对 C++ 程序员来说，C# 并发集合可类比为 “C++ 容器 + std::mutex/std::shared_mutex + 原子操作” 的封装版，但更简洁（无需手动管理锁生命周期）、更高效（内置优化的同步机制）、更安全（避免死锁、数据竞争等低级错误）。C++ 需手动组合容器与同步原语，而 C# 直接提供 “开箱即用” 的线程安全集合。

一、核心前提：为什么需要并发集合？ #

多线程编程中，普通集合（如 List<T>、Dictionary<TKey, TValue>）不是线程安全的 —— 多线程同时读写会导致 数据竞争（Data Race），表现为数据错乱、索引越界、程序崩溃等未定义行为。

1. 普通集合的线程安全问题（反例） #

csharp

运行

csharp
// 普通 List<T> 多线程写入（线程不安全）
var list = new List<int>();
// 10个线程同时添加元素
Parallel.For(0, 1000, i => list.Add(i));
Console.WriteLine(list.Count); // 输出可能小于1000（数据丢失），甚至程序崩溃

2. C++ 中的传统解决方案（繁琐且易错） #

C++ 无内置并发集合，需手动组合 “容器 + 锁” 实现线程安全，代码冗余且易出错（如忘记解锁、锁粒度不当导致死锁）：

cpp

运行

cpp
#include <vector>
#include <mutex>
#include <thread>

std::vector<int> list;
std::mutex mtx; // 手动创建互斥锁

void AddItem(int i) {
    std::lock_guard<std::mutex> lock(mtx); // 手动加锁
    list.push_back(i); // 临界区操作
    // 锁自动释放（lock_guard 析构）
}

int main() {
    std::vector<std::thread> threads;
    for (int i = 0; i < 1000; ++i) {
        threads.emplace_back(AddItem, i);
    }
    for (auto& t : threads) t.join();
    return 0;
}

3. C# 并发集合的优势 #

  • 无需手动锁：内部封装同步机制（细粒度锁、无锁算法），开发者无需关注锁逻辑；
  • 高性能：避免全局锁的竞争开销（如 ConcurrentDictionary 用分段锁，ConcurrentBag 用线程本地存储）；
  • 安全 API：提供 TryXXX 系列方法（如 TryDequeue、TryAdd），避免并发操作中的异常；
  • 原生集成：支持 CancellationToken、异步操作等 C# 特性，适配现代并发编程场景。

二、核心概念：并发集合的设计原则 #

1. 线程安全定义 #

C# 并发集合的 “线程安全” 指：多个线程同时执行读写操作时，不会出现数据损坏，且操作结果符合预期—— 但不保证 “原子性复合操作”（如 “检查是否存在 → 不存在则添加” 需额外锁）。

2. 同步机制优化（对比 C++ 手动锁） #

同步方式 原理 C++ 类比 适用场景
细粒度锁 将集合拆分多个片段，每个片段独立加锁（如 ConcurrentDictionary 拆分为 16 个段） std::vector<std::mutex> + 分段锁 读多写少、高频访问的集合
无锁算法 基于 CAS（Compare-And-Swap）原子操作，无锁竞争（如 ConcurrentQueue 的链表实现） std::atomic + CAS 操作 高并发、短操作的集合（队列、栈）
线程本地存储（TLS） 每个线程维护本地缓存，批量合并到全局集合（如 ConcurrentBag） thread_local 容器 + 全局合并 多线程添加、随机访问的无序集合
阻塞锁 操作失败时阻塞线程（如 BlockingCollection） std::mutex + std::condition_variable 生产者 - 消费者模式

3. 关键 API 设计 #

并发集合避免使用普通集合的 “修改即抛异常” API（如 Queue.Dequeue 空队列抛异常），而是提供 TryXXX 方法（返回 bool 表示操作成功与否），更适配并发场景：

普通集合 API 并发集合替代 API 优势
Queue.Dequeue() ConcurrentQueue.TryDequeue(out T result) 空队列时返回 false，不抛异常
Stack.Pop() ConcurrentStack.TryPop(out T result) 空栈时返回 false，不抛异常
Dictionary.Add() ConcurrentDictionary.TryAdd(TKey, TValue) 键已存在时返回 false，不抛异常

三、常用并发集合详解（场景 + 示例 + C++ 对比） #

C# 提供 5 个核心并发集合，覆盖队列、栈、无序集合、字典、阻塞队列场景，以下逐一解析：

1. ConcurrentQueue：线程安全的先进先出（FIFO）队列 #

核心定位

适用于 生产者 - 消费者模式（如任务队列、消息队列），基于无锁链表实现，高并发下性能优于 “Queue<T> + lock”。

核心 API
API 方法 作用
void Enqueue(T item) 入队（线程安全）
bool TryDequeue(out T result) 出队（空队列返回 false）
bool TryPeek(out T result) 查看队首（不删除，空队列返回 false）
int Count 当前元素个数（近似值，并发下不保证精确）
C# 示例：生产者 - 消费者模式

csharp

运行

csharp
using System.Collections.Concurrent;
using System.Threading.Tasks;

// 创建并发队列（无界队列）
var queue = new ConcurrentQueue<int>();
const int ProducerCount = 2; // 2个生产者
const int ConsumerCount = 3; // 3个消费者
const int ItemCount = 100;   // 每个生产者生产100个元素

// 生产者：入队
async Task ProducerAsync(int id, CancellationToken ct)
{
    for (int i = 0; i < ItemCount && !ct.IsCancellationRequested; i++)
    {
        int item = id * 1000 + i;
        queue.Enqueue(item);
        Console.WriteLine($"生产者{id}：入队 {item}");
        await Task.Delay(10); // 模拟生产耗时
    }
}

// 消费者：出队
async Task ConsumerAsync(int id, CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        if (queue.TryDequeue(out int item))
        {
            Console.WriteLine($"消费者{id}：出队 {item}");
            await Task.Delay(15); // 模拟消费耗时
        }
        else
        {
            // 队列空时短暂等待，避免忙等
            await Task.Delay(50);
        }
    }
}

// 执行并发操作
using var cts = new CancellationTokenSource(3000); // 3秒后取消
var producerTasks = Enumerable.Range(0, ProducerCount)
    .Select(id => ProducerAsync(id, cts.Token));
var consumerTasks = Enumerable.Range(0, ConsumerCount)
    .Select(id => ConsumerAsync(id, cts.Token));

await Task.WhenAll(producerTasks);
Console.WriteLine("所有生产者完成，等待消费者处理剩余元素...");
await Task.Delay(1000); // 给消费者时间处理剩余元素
cts.Cancel(); // 取消消费者
await Task.WhenAll(consumerTasks);
Console.WriteLine($"最终队列剩余元素：{queue.Count}");
C++ 对比：手动实现线程安全队列

C++ 需用 std::queue + std::mutex + std::condition_variable 实现，代码繁琐且易出错：

cpp

运行

cpp
#include <queue>
#include <mutex>
#include <condition_variable>
#include <thread>
#include <iostream>

template <typename T>
class ConcurrentQueue {
private:
    std::queue<T> _queue;
    mutable std::mutex _mtx;
    std::condition_variable _cv;
public:
    void Enqueue(T item) {
        std::lock_guard<std::mutex> lock(_mtx);
        _queue.push(std::move(item));
        _cv.notify_one(); // 通知等待的消费者
    }

    bool TryDequeue(T& result, std::chrono::milliseconds timeout = std::chrono::milliseconds(0)) {
        std::unique_lock<std::mutex> lock(_mtx);
        if (timeout.count() == 0) {
            if (_queue.empty()) return false;
        } else {
            // 超时等待
            if (!_cv.wait_for(lock, timeout, [this]() { return !_queue.empty(); })) {
                return false;
            }
        }
        result = std::move(_queue.front());
        _queue.pop();
        return true;
    }
};

// 用法（生产者-消费者）
ConcurrentQueue<int> queue;
void Producer(int id) {
    for (int i = 0; i < 100; ++i) {
        int item = id * 1000 + i;
        queue.Enqueue(item);
        std::cout << "生产者" << id << "：入队 " << item << std::endl;
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
}

void Consumer(int id) {
    int item;
    while (queue.TryDequeue(item, std::chrono::milliseconds(500))) {
        std::cout << "消费者" << id << "：出队 " << item << std::endl;
        std::this_thread::sleep_for(std::chrono::milliseconds(15));
    }
}

int main() {
    std::vector<std::thread> producers;
    std::vector<std::thread> consumers;
    for (int i = 0; i < 2; ++i) producers.emplace_back(Producer, i);
    for (int i = 0; i < 3; ++i) consumers.emplace_back(Consumer, i);
    for (auto& t : producers) t.join();
    for (auto& t : consumers) t.join();
    return 0;
}
适用场景
  • 任务队列（如后台任务调度）；
  • 消息传递（如多线程间的消息通信）；
  • 日志收集（多个线程写入日志，单线程输出）。

2. ConcurrentStack：线程安全的后进先出（LIFO）栈 #

核心定位

适用于 栈式数据共享（如调用栈、缓存栈），基于无锁算法实现，支持批量压栈 / 弹栈（PushRange/TryPopRange），提升批量操作性能。

核心 API
API 方法 作用
void Push(T item) 压栈（线程安全）
bool TryPop(out T result) 弹栈（空栈返回 false）
void PushRange(T[] items) 批量压栈（比多次 Push 高效）
int TryPopRange(T[] items) 批量弹栈（返回成功弹栈的元素个数）
C# 示例：批量操作栈

csharp

运行

csharp
var stack = new ConcurrentStack<int>();

// 批量压栈（100个元素）
stack.PushRange(Enumerable.Range(0, 100).ToArray());
Console.WriteLine($"栈中元素数：{stack.Count}"); // 输出 ~100（并发下近似）

// 批量弹栈（最多50个元素）
var buffer = new int[50];
int poppedCount = stack.TryPopRange(buffer);
Console.WriteLine($"成功弹栈 {poppedCount} 个元素"); // 输出 50
Console.WriteLine($"弹栈的前5个元素：{string.Join(", ", buffer.Take(5))}"); // 输出 99, 98, 97, 96, 95
C++ 对比：手动实现线程安全栈

C++ 需用 std::stack + std::mutex，批量操作需手动循环，效率较低：

cpp

运行

cpp
template <typename T>
class ConcurrentStack {
private:
    std::stack<T> _stack;
    mutable std::mutex _mtx;
public:
    void Push(T item) {
        std::lock_guard<std::mutex> lock(_mtx);
        _stack.push(std::move(item));
    }

    bool TryPop(T& result) {
        std::lock_guard<std::mutex> lock(_mtx);
        if (_stack.empty()) return false;
        result = std::move(_stack.top());
        _stack.pop();
        return true;
    }

    void PushRange(const std::vector<T>& items) {
        std::lock_guard<std::mutex> lock(_mtx);
        for (auto& item : items) _stack.push(std::move(item));
    }
};
适用场景
  • 缓存系统（如最近最少使用缓存 LRU 的栈实现）；
  • 递归任务拆分（如多线程递归计算，任务栈共享）；
  • 批量数据处理（需按顺序逆序处理）。

3. ConcurrentBag：线程安全的无序集合 #

核心定位

适用于 多线程添加、随机访问 的无序场景（如临时数据集合、结果汇总），基于 “线程本地存储（TLS）+ 全局合并” 实现 —— 每个线程优先访问本地缓存，减少锁竞争，性能优于 ConcurrentList（C# 无内置 ConcurrentList）。

核心特性
  • 无序性：不保证元素顺序（遍历顺序不确定）；
  • 重复元素：允许添加重复元素；
  • 高效添加：多线程添加时，优先写入本地 TLS 缓存，几乎无锁竞争；
  • 随机访问：TryTake 随机获取并删除一个元素（非 FIFO/LIFO）。
核心 API
API 方法 作用
void Add(T item) 添加元素（线程安全，高效）
bool TryTake(out T result) 随机获取并删除一个元素（空集合返回 false）
bool TryPeek(out T result) 随机查看一个元素（不删除）
IEnumerable<T> ToArray() 转为数组（快照，并发下可能包含重复元素）
C# 示例：多线程结果汇总

csharp

运行

csharp
var bag = new ConcurrentBag<int>();

// 5个线程同时添加结果
Parallel.For(0, 5, threadId => {
    for (int i = 0; i < 20; i++) {
        bag.Add(threadId * 100 + i); // 每个线程添加20个元素
    }
});

Console.WriteLine($"集合大小：{bag.Count}"); // 输出 100
Console.WriteLine($"前10个元素（无序）：{string.Join(", ", bag.Take(10))}"); // 顺序不确定

// 遍历并移除所有元素
while (bag.TryTake(out int item)) {
    Console.Write($"{item} ");
}
C++ 对比：手动实现无序并发集合

C++ 需用 std::vector + std::shared_mutex（读多写少），但多线程添加时锁竞争严重：

cpp

运行

cpp
template <typename T>
class ConcurrentBag {
private:
    std::vector<T> _data;
    mutable std::shared_mutex _mtx;
public:
    void Add(T item) {
        std::unique_lock<std::shared_mutex> lock(_mtx);
        _data.push_back(std::move(item));
    }

    bool TryTake(T& result) {
        std::unique_lock<std::shared_mutex> lock(_mtx);
        if (_data.empty()) return false;
        // 随机取最后一个元素（高效）
        result = std::move(_data.back());
        _data.pop_back();
        return true;
    }
};
适用场景
  • 多线程任务结果汇总（如并行计算的中间结果）；
  • 临时数据存储（无需顺序，仅需添加和随机访问）；
  • 高并发写入、低频率读取的场景。

4. ConcurrentDictionary<TKey, TValue>：线程安全的键值对集合 #

核心定位

适用于 多线程读写的键值对存储（如缓存、配置表），基于 “分段锁（Segment Lock）” 实现 —— 将字典拆分为 16 个独立片段，每个片段有自己的锁，不同片段的操作可并发执行，大幅提升读多写少场景的性能。

核心优势（对比 C++ std::map + std::mutex）
  • 分段锁：避免全局锁竞争，并发性能提升 10~100 倍；
  • 原子复合操作：提供 AddOrUpdate、GetOrAdd 等原子方法，无需手动加锁；
  • 安全遍历：枚举时不会抛出 InvalidOperationException（普通 Dictionary 遍历中修改会抛异常）。
核心 API
API 方法 作用
bool TryAdd(TKey key, TValue value) 添加键值对（键已存在返回 false）
bool TryGetValue(TKey key, out TValue value) 获取值（键不存在返回 false）
bool TryRemove(TKey key, out TValue value) 移除键值对（键不存在返回 false）
TValue GetOrAdd(TKey key, Func<TKey, TValue> valueFactory) 原子操作：获取值，不存在则创建（线程安全）
TValue AddOrUpdate(TKey key, Func<TKey, TValue> addValueFactory, Func<TKey, TValue, TValue> updateValueFactory) 原子操作：添加或更新（线程安全）
C# 示例：缓存场景（GetOrAdd 原子操作）

csharp

运行

csharp
// 并发字典作为缓存（键：用户ID，值：用户信息）
var userCache = new ConcurrentDictionary<int, string>();

// 模拟10个线程同时查询缓存
Parallel.For(0, 10, threadId => {
    for (int userId = 1; userId <= 5; userId++) {
        // 原子操作：存在则返回，不存在则创建（避免缓存穿透）
        string userInfo = userCache.GetOrAdd(
            key: userId,
            valueFactory: id => $"用户{id}的信息（线程{threadId}创建）"
        );
        Console.WriteLine($"线程{threadId}：{userInfo}");
    }
});

// 输出说明：同一用户ID的信息仅创建一次（原子操作保证）
C++ 对比：手动实现分段锁字典

C++ 需手动拆分片段、管理多个锁，代码极其繁琐：

cpp

运行

cpp
template <typename K, typename V, size_t SegmentCount = 16>
class ConcurrentDictionary {
private:
    struct Segment {
        std::unordered_map<K, V> map;
        std::mutex mtx;
    };
    std::array<Segment, SegmentCount> _segments;

    size_t GetSegmentIndex(const K& key) const {
        std::hash<K> hasher;
        return hasher(key) % SegmentCount;
    }
public:
    V GetOrAdd(const K& key, std::function<V(const K&)> valueFactory) {
        auto& segment = _segments[GetSegmentIndex(key)];
        std::lock_guard<std::mutex> lock(segment.mtx);
        auto it = segment.map.find(key);
        if (it != segment.map.end()) return it->second;
        V value = valueFactory(key);
        segment.map.emplace(key, value);
        return value;
    }
};
适用场景
  • 缓存系统（如用户信息缓存、配置缓存）；
  • 共享状态存储（如多线程共享的计数器、状态表）；
  • 高并发键值对查询（如 API 接口的参数映射）。

5. BlockingCollection：支持阻塞的并发集合（生产者 - 消费者终极方案） #

核心定位

BlockingCollection<T> 是 “并发集合的包装器”，可包装 ConcurrentQueue、ConcurrentStack 等，提供 阻塞操作 和 边界限制（设置最大容量），是生产者 - 消费者模式的 “终极解决方案”—— 无需手动处理队列空 / 满时的阻塞逻辑。

核心特性
  • 阻塞操作：Take() 阻塞直到有元素，Add() 阻塞直到队列有空闲空间（设置边界时）；
  • 边界限制：可设置最大容量（如 new BlockingCollection<int>(100)，队列满时 Add() 阻塞）；
  • 支持取消：集成 CancellationToken，可随时取消阻塞操作；
  • 多生产者 / 多消费者：天然支持多个生产者和消费者并发操作。
核心 API
API 方法 作用
void Add(T item, CancellationToken ct) 添加元素（队列满时阻塞，支持取消）
T Take(CancellationToken ct) 移除元素（队列空时阻塞，支持取消）
bool TryAdd(T item, int millisecondsTimeout) 尝试添加（超时返回 false）
bool TryTake(out T result, int millisecondsTimeout) 尝试移除（超时返回 false）
void CompleteAdding() 标记 “添加完成”，消费者 Take() 完元素后返回
C# 示例：有边界的生产者 - 消费者

csharp

运行

csharp
// 包装 ConcurrentQueue，设置最大容量为 10（队列满时生产者阻塞）
var blockingQueue = new BlockingCollection<int>(new ConcurrentQueue<int>(), boundedCapacity: 10);
const int ProducerCount = 2;
const int ConsumerCount = 2;
const int ItemPerProducer = 50;

// 生产者：添加元素（队列满时阻塞）
async Task ProducerAsync(int id, CancellationToken ct)
{
    for (int i = 0; i < ItemPerProducer; i++)
    {
        int item = id * 1000 + i;
        blockingQueue.Add(item, ct); // 队列满时阻塞
        Console.WriteLine($"生产者{id}：添加 {item}，当前队列大小：{blockingQueue.Count}");
        await Task.Delay(5);
    }
}

// 消费者：移除元素（队列空时阻塞）
async Task ConsumerAsync(int id, CancellationToken ct)
{
    try
    {
        while (!ct.IsCancellationRequested)
        {
            int item = blockingQueue.Take(ct); // 队列空时阻塞
            Console.WriteLine($"消费者{id}：移除 {item}，当前队列大小：{blockingQueue.Count}");
            await Task.Delay(10); // 消费耗时更长，队列可能满
        }
    }
    catch (OperationCanceledException)
    {
        Console.WriteLine($"消费者{id}：取消操作");
    }
}

// 执行
using var cts = new CancellationTokenSource(2000);
var producerTasks = Enumerable.Range(0, ProducerCount).Select(id => ProducerAsync(id, cts.Token));
var consumerTasks = Enumerable.Range(0, ConsumerCount).Select(id => ConsumerAsync(id, cts.Token));

await Task.WhenAll(producerTasks);
blockingQueue.CompleteAdding(); // 标记添加完成
Console.WriteLine("所有生产者完成，等待消费者处理剩余元素...");

await Task.WhenAll(consumerTasks);
Console.WriteLine($"最终队列大小：{blockingQueue.Count}"); // 输出 0
C++ 对比：手动实现阻塞队列

C++ 需用 std::queue + std::mutex + std::condition_variable，边界限制需手动判断：

运行

cpp
template <typename T>
class BlockingQueue {
private:
    std::queue<T> _queue;
    mutable std::mutex _mtx;
    std::condition_variable _notEmpty;
    std::condition_variable _notFull;
    size_t _capacity;
public:
    BlockingQueue(size_t capacity) : _capacity(capacity) {}

    void Add(T item, std::stop_token st) {
        std::unique_lock<std::mutex> lock(_mtx);
        // 队列满时等待，支持取消
        _notFull.wait(lock, st, [this]() { return _queue.size() < _capacity; });
        if (st.stop_requested()) return;
        _queue.push(std::move(item));
        _notEmpty.notify_one();
    }

    T Take(std::stop_token st) {
        std::unique_lock<std::mutex> lock(_mtx);
        // 队列空时等待，支持取消
        _notEmpty.wait(lock, st, [this]() { return !_queue.empty(); });
        if (st.stop_requested()) throw std::runtime_error("Canceled");
        T result = std::move(_queue.front());
        _queue.pop();
        _notFull.notify_one();
        return result;
    }
};
适用场景
  • 有界生产者 - 消费者模式（如线程池任务调度、消息队列限流）；
  • 多线程间的同步数据传输（如主线程与后台线程的通信）；
  • 需要阻塞等待的并发场景（避免忙等浪费 CPU）。

五、常见误区与避坑指南 #

1. 误区 1：并发集合是 “绝对线程安全”（支持所有复合操作） #

  • 错误认知：ConcurrentDictionary 的 ContainsKey + Add 是原子操作；

  • 正确逻辑：并发集合仅保证 单个 API 线程安全，复合操作（如 “检查 → 修改”）需额外锁：

    csharp

    运行

    csharp
    // 错误：复合操作非原子，可能出现重复添加
if (!concurrentDict.ContainsKey(key)) {
    concurrentDict.TryAdd(key, value); // 多线程下可能重复添加
}

// 正确：用原子方法 GetOrAdd（或手动加锁）
concurrentDict.GetOrAdd(key, value); // 原子操作，无重复添加风险

2. 误区 2：并发集合性能一定比 “普通集合 + lock” 好 #

  • 错误认知：所有场景下并发集合都更高效；
  • 正确逻辑：
    • 单线程场景：普通集合性能优于并发集合（无同步开销）；
    • 低并发场景：普通集合 + lock 可能更高效（并发集合的同步优化有固定开销）；
    • 高并发场景：并发集合优势明显（细粒度锁 / 无锁算法减少竞争）。

3. 误区 3：BlockingCollection 只能包装 ConcurrentQueue #

  • 错误认知：BlockingCollection 仅支持队列；

  • 正确逻辑：可包装任何实现 IProducerConsumerCollection<T> 的集合（如 ConcurrentStack、ConcurrentBag），甚至自定义集合：

    csharp

    运行

    csharp
    // 包装 ConcurrentStack，实现阻塞栈
var blockingStack = new BlockingCollection<int>(new ConcurrentStack<int>());
blockingStack.Add(1);
int item = blockingStack.Take(); // 阻塞直到有元素

4. 误区 4：ConcurrentBag 是 “线程安全的 List” #

  • 错误认知：ConcurrentBag 支持索引访问，顺序遍历；
  • 正确逻辑：ConcurrentBag 是无序集合，无索引访问 API，遍历顺序不确定 —— 若需有序访问，应使用 ConcurrentQueue 或 BlockingCollection + 自定义有序容器。

5. 误区 5：忽略 CancellationToken 的使用 #

  • 错误场景：阻塞操作（如 BlockingCollection.Take()）未传入 CancellationToken，导致无法取消；

  • 正确做法：所有阻塞操作都应传入 CancellationToken，避免线程无法退出：

    csharp

    运行

    csharp
    // 正确：支持取消的阻塞操作
try {
    int item = blockingQueue.Take(cts.Token);
} catch (OperationCanceledException) {
    // 处理取消逻辑
}

6. 误区 6：ConcurrentDictionary 的 Count 是精确值 #

  • 错误认知：concurrentDict.Count 能获取实时精确的元素个数；

  • 正确逻辑：并发集合的 Count 是 近似值（高并发下，统计时元素可能被添加 / 删除）—— 若需精确计数，需手动加锁：

    csharp

    运行

    csharp
    // 精确计数（需额外锁，影响性能）
lock (countLock) {
    int exactCount = concurrentDict.Count;
}

六、最佳实践（面向 C++ 程序员的迁移建议） #

  1. 放弃 “容器 + 手动锁” 的思维：优先使用 C# 内置并发集合，无需手动管理锁生命周期和同步逻辑；
  2. 按场景选择合适的集合：
    • 生产者 - 消费者（FIFO）：ConcurrentQueue + BlockingCollection（有界）；
    • 生产者 - 消费者（LIFO）：ConcurrentStack + BlockingCollection；
    • 无序结果汇总：ConcurrentBag；
    • 键值对缓存 / 查询：ConcurrentDictionary；
    • 有界阻塞场景：直接用 BlockingCollection；
  3. 优先使用原子复合操作：如 ConcurrentDictionary.GetOrAdd、AddOrUpdate，避免手动组合多个 API；
  4. 阻塞操作必传 CancellationToken：确保线程能响应取消，避免资源泄漏；
  5. 避免过度使用并发集合：单线程或低并发场景，普通集合（List<T>、Dictionary<TKey, TValue>）性能更优；
  6. 不依赖 Count 属性的精确性：高并发下，Count 仅作参考，无需追求精确值；
  7. 自定义并发集合时实现 IProducerConsumerCollection：可被 BlockingCollection 包装，复用阻塞 / 边界功能。

总结 #

C# 并发集合的核心价值是 “线程安全 + 高性能 + 开发高效”，对 C++ 程序员来说：

  1. 它是 C++ 中 “容器 + 同步原语” 的封装升级，无需关注锁细节，减少出错概率；
  2. 核心集合分工明确，覆盖队列、栈、字典、无序集合、阻塞场景，满足绝大多数并发需求；
  3. 与 C++ 相比，C# 并发集合原生支持取消机制、异步操作、原子复合操作，更适配现代并发编程；
  4. 关键是 “按场景选对集合”，避免滥用 —— 单线程用普通集合，高并发用并发集合，阻塞场景用 BlockingCollection。

C# 并发集合让多线程编程从 “手动控锁的繁琐易错” 走向 “开箱即用的安全高效”，这也是 C# 比 C++ 更适合快速开发并发应用的核心原因之一。
