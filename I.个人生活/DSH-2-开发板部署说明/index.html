0. 这份文档怎么用 #

如果你手头的板子已经能启动、能登录、能上网，你可以跳过「上电 / 串口 / 联网」这些前置步骤，直接从 3.5（换 apt 源） 或 4.6 开始。

如果板子是全新的、或者你不确定里面是什么系统，请从头做。

整条链路一共就 5 件正事：

① 能登录板子（串口或 SSH）
      ↓
② 板子能上网（配静态 IP）
      ↓
③ 装 Node.js 24（arm64 官方二进制）
      ↓
④ npm 全局装 DSH
      ↓
⑤ 写一个 systemd 服务，开机自启 + 崩溃自动重启

第 ⑤ 步做完，整件事就结束了。和手机方案不同，这里没有任何「进程被杀」「锁屏冻结」「开机自启要装额外 APK」的问题——systemd 会一直帮你看着。

一个重要的阅读提示 #

本文所有要复制到板子上执行的脚本，都只使用 ASCII 字符（英文和符号，不含中文）。

这不是洁癖，是被坑出来的：

【踩坑记录】中文注释在 SSH 管道里会变乱码

手机版部署时，我们在一个 shell 脚本里写了一行中文注释： # --- 顺手确保 sshd 在监听（重启后 / 被安卓回收后都需要它）---

从 Windows 通过 SSH 管道把脚本内容喂给板子执行时，Windows PowerShell 默认按 GBK 编码输出、板子按 UTF-8 解码，这行注释变成了： # --- 椤烘墜纭繚 sshd 鍦ㄧ洃鍚紙閲嶅惎鍚?/ 琚畨鍗撳洖鏀跺悗閮介渶瑕佸畠锛?--

单引号被吃掉后，后面整段脚本的引号配平全部错乱，最后报 bash: line 6: unexpected EOF while looking for matching '。 排查花了很久，因为报错位置和真正出问题的位置完全对不上。

对策：脚本里一律写英文注释。要写中文说明，写在文档里、不要写在会被复制执行的代码块里。

所以下面凡是标了 bash / ini 的代码块，都可以放心整段复制。

1.2 结论：怎么选 #

看你的 OK3568 是几 GB 内存版：

你的板子 建议
OK3568 是 2GB/16GB 或 2GB/32GB 选 OK3568。官方适配最完整（20.04 和 22.04 都支持），有板载 WiFi、Type-C 直接当串口用，最省事。推荐装 ForlinxDesktop 22.04（glibc 2.35 最稳）。
OK3568 是 1GB/8GB 放弃 OK3568，选 OK1028A。官方适配表里 1GB 版根本没有 Ubuntu，只有 Linux5.10、AMP、OpenHarmony。见下方警告。
OK3568 是 4GB/32GB 选 OK1028A 更稳。官方适配表里 4GB 版的 ForlinxDesktop 20.04 后面带 * 号，图注写明「系统标*的表示正在适配」——也就是说 4GB 版的 Ubuntu 适配还没完全收尾。虽然跑起来大概率没问题，但你要的是「一次装好就别再折腾」。
只有 OK1028A 就用它，2GB 够跑 DSH（DSH 进程 RSS 约 250~400MB），按第 6 章加个 swap 更稳。

【踩坑记录】OK3568 的内存容量会决定你能装哪个系统

飞凌官网 OK3568-C 页面有一张「操作系统适配明细」表，把 RAM/ROM 组合和可用系统绑死了：

RAM ROM 可装系统
1GB 8GB Linux5.10.160、AMP、OpenHarmony5.1 —— 没有任何 Ubuntu
2GB 16GB Linux5.10.160、Android11、ForlinxDesktop20.04、ForlinxDesktop22.04、Debian11、AMP、OpenHarmony5.1
2GB 32GB 同上（最完整）
4GB 32GB Linux5.10.160、Android11、ForlinxDesktop20.04*、Debian11*、AMP*、OpenHarmony4.1*

表格下面的注写着：「系统标*的表示正在适配」。

所以动手前必须先确认型号。上电后跑 free -m 和 df -h / 看实际内存和 eMMC 容量，或者直接看核心板丝印。

1.3 顺手排除 OK4418 #

如果你手上还有一块 OK4418（S5P4418），不要用它，三条硬门槛一条都过不去：

  1. 32 位 ARM（Cortex-A9、32 位 RISC 指令集）。Node.js 官方早就不出 linux-armv7l 的二进制了（Node 24 的 SHASUMS 里连一条 armv7l 都没有），armv7 在 Node 24 已被降级为 Experimental。
  2. 1GB DDR3。DSH 是 614 个 npm 包的常驻 Node 服务，装包阶段就可能 OOM。
  3. 内核只到 Linux 3.4.39 / 4.4.83。太老。
  4. 顺带：飞凌官网这个产品的页面上直接写着「产品新项目选型不建议购买」。

2.2 网络规划（先想清楚再动手） #

DSH 有个硬性限制，必须先说：

dsh web --host 不接受 0.0.0.0

实测报错： error: --host 0.0.0.0 is an unspecified (wildcard) address, which is not supported: binding every interface would expose remote code execution to the network; bind one concrete IPv4 or IPv6 address instead

也就是说，你必须给板子一个确定的静态 IPv4 地址，不能靠 DHCP 随便给。DHCP 每次续租换了 IP，服务就绑不上、或者绑在老 IP 上你连不进去。

所以我们后面的步骤里，一定会给板子配一个静态 IP。

建议这样规划（假设你的路由器是 192.168.1.1，请按实际改）：

设备 地址
路由器 192.168.1.1
你的 Windows PC 192.168.1.100（通常是 DHCP 自动的，查一下确认）
开发板（本文用这个） 192.168.1.50

先在自己 Windows 上确认网段：

powershell
ipconfig | Select-String -Pattern "IPv4"

看到类似 IPv4 地址 . . . . . . . . . . . . : 192.168.1.100，那网段就是 192.168.1.x，网关是 192.168.1.1。

本文后续所有地方出现的 192.168.1.50 都是示例。你要替换成自己网段里一个没被占用的地址。建议先 ping 192.168.1.50 确认没人用。

本文实测用的那台 OK1028A 是另一种情况：网线一端插板子、另一端直接插 PC 的网口（没有路由器参与）。这时网段是自己定的，实测用 192.168.3.x：PC = 192.168.3.100、板子 = 192.168.3.200。 这种「PC ↔ 板子直连」的模式下，PC 上没有网关，板子上外网得靠 PC 跑代理（见 4.4.5）。有条件插路由器就插路由器——省掉整套代理，而且板子能独立在线、局域网任何设备都能访问（详细迁移步骤见 4.4.6）。

3.2 建立串口调试通道 #

3.2.1 装 CP210x 驱动 #

板子上有一颗 USB 转串口芯片（CP210x 系列），把 Type-C 插到 Windows 上，Windows 不一定自带驱动。

  1. 在飞凌资料包里找 Linux\ToolsDriverAssitant_v5.11.zip（或 CP210x_VCP_Windows_XP_Vista.zip）
  2. 解压
  3. 右键 → 以管理员身份运行 CP210xVCPInstaller_x64.exe（64 位系统）
  4. 装完弹出「安装成功」

3.2.2 找到串口号 #

  1. 用 Type-C 线把板子的 Debug 口连到电脑
  2. 板子上电
  3. Windows 按 Win + X → 打开「设备管理器」
  4. 展开「端口 (COM 和 LPT)」，看到类似 Silicon Labs CP210x USB to UART Bridge (COM3) —— 记下这个 COM3（你的可能不同）

如果设备管理器里出现的是一个带黄色感叹号的「未知设备」，说明驱动没装好，回 3.2.1。

3.2.3 PuTTY 连上去 #

打开 PuTTY，填：

项目 值
Connection type Serial
Serial line COM3（换成你实际的）
Speed 115200
Data bits 8
Stop bits 1
Parity None
Flow control None

点 Open，会弹出一个黑窗口。

这时候按一下板子的 RESET 键（或者重新上电），你应该能看到满屏滚动的启动日志，类似：

U-Boot 2017.09 ...
DDR V1.18 ...
...
Starting kernel ...
...
[  OK  ] Reached target Multi-User System.

看到日志 = 串口通了。

【踩坑记录】串口没输出，先别怀疑板子坏了

90% 的情况是这三件事之一：

  1. Type-C 线是「只充电」线，没有数据线芯。换一根手机数据线试试。
  2. 波特率不对。飞凌这块板固定 115200 8N1，别用 9600。
  3. 插的是 OTG 口而不是 Debug 口。两个口长得很像，认丝印。

3.3 首次上电与登录 #

3.3.1 登录账号 #

Forlinx Desktop（Ubuntu）出厂的账号是固定的：

用户名 密码 说明
forlinx forlinx 普通用户，串口和 SSH 都能登
root root 超级用户，串口能登，SSH 默认不能登

板子启动完，串口窗口最后会停在：

ok3568 login:

输入 forlinx，回车，再输密码 forlinx（输密码时屏幕不显示任何字符，这是正常的，输完直接回车）。

然后你会看到：

forlinx@ok3568:~$

成功。

【踩坑记录】刷完系统第一次启动，不要以为卡住了

如果你刚用 OTG 刷完系统，第一次上电会出现：

[root@buildroot]#

这是初始化脚本在跑，不是登录成功。官方手册明确写： 「If the message shows [root@buildroot]#, it indicates the first reboot after the initial firmware burn. At this point, do not perform any operations; wait for it to reboot automatically. forlinx login: is the normal state.」

你什么都不用做，等它自己重启，第二次才会出现 forlinx login:。

登录后先跑这几条，把实际情况记下来：

  • ldd 的 glibc 版本 —— 必须 ≥ 2.28，否则 Node 24 官方二进制跑不起来

【踩坑记录】怎么判断自己是 20.04 还是 22.04

官方给的两套系统都叫 "Forlinx Desktop"，版本号容易混。看两个地方：

  • cat /etc/issue → 会直接写 Ubuntu 22.04.x LTS 或 Ubuntu 20.04.x LTS
  • ldd --version | head -1 → 22.04 是 2.35，20.04 是 2.31

这两个版本对本文的操作影响很小（Node 都能跑），唯一的差别在第 3.5 节换 apt 源时的文件路径。

3.4 联网（netplan） #

OK3568 用 netplan 管网络。出厂默认：

  • eth0：静态 IP，默认是 192.168.0.123/24，网关 192.168.0.1
  • eth1：DHCP 自动获取

我们的策略：把 eth0 改成你网段的静态 IP。

3.4.1 先看现状 #

bash
ip -br a

预期输出类似：

lo               UNKNOWN        127.0.0.1/8 ::1/128
eth0             UP             192.168.0.123/24 ...
eth1             DOWN

看到 eth0 是 UP 并且有地址，说明网线插在 ETH0 口上。

如果 eth0 是 DOWN、eth1 是 UP，说明你把网线插到 ETH1 口了，换到 ETH0，或者下面配置时把网卡名换成 eth1。

3.4.2 改配置文件 #

配置文件路径：/etc/netplan/01-netcfg.yaml

bash
sudo nano /etc/netplan/01-netcfg.yaml

Ubuntu 22.04 版写法（推荐，注意 gateway4 在 22.04 已废弃，要用 routes）：

yaml
network:
    version: 2
    ethernets:
        eth0:
            addresses: [192.168.1.50/24]
            routes:
              - to: default
                via: 192.168.1.1
            nameservers:
                addresses: [223.5.5.5, 8.8.8.8]
        eth1:
            dhcp4: true

Ubuntu 20.04 版写法（老写法，20.04 上两种都认）：

yaml
network:
    version: 2
    ethernets:
        eth0:
            addresses: [192.168.1.50/24]
            gateway4: 192.168.1.1
            nameservers:
                addresses: [223.5.5.5, 8.8.8.8]
        eth1:
            dhcp4: true

YAML 缩进必须用空格，不能用 Tab。 缩进错了 netplan 直接报错拒绝加载。

保存退出（nano 里是 Ctrl+O 回车 Ctrl+X）。

3.4.3 应用配置 #

bash
sudo netplan apply

然后验证：

bash
ip -br a | grep eth0

预期：

eth0             UP             192.168.1.50/24 ...

再测外网：

bash
ping -c 3 223.5.5.5

预期：

3 packets transmitted, 3 received, 0% packet loss

通了。

【踩坑记录】netplan apply 之后 IP 没变

三个常见原因：

  1. 网线插在 eth1 上，你改的是 eth0。用 ip -br a 看哪个口是 UP。
  2. YAML 缩进错了。跑 sudo netplan try，它会校验语法，错了会直接告诉你哪一行不对，并且 120 秒后自动回滚（防止你把自己关在外面）。
  3. 有别的网络管理工具在抢。跑 systemctl status systemd-networkd NetworkManager 看谁在跑。OK3568 的 Forlinx Desktop 用的是 netplan + NetworkManager 的组合，别手动装 systemd-networkd。

3.8 注册为 systemd 服务 #

看到这行就说明服务本身没问题，Ctrl+C 停掉，接下来交给 systemd。

【踩坑记录】报 --host 0.0.0.0 不支持

完整报错：

error: --host 0.0.0.0 is an unspecified (wildcard) address, which is not supported: binding every interface would expose remote code execution to the network; bind one concrete IPv4 or IPv6 address instead

这不是 bug，是安全设计：DSH 会执行 shell 命令，绑到所有网卡等于把远程代码执行暴露给整个网络。必须指定一个具体 IP。

3.8.2 写 service 文件 #

bash
sudo mkdir -p /opt/log

sudo tee /etc/systemd/system/dsh.service > /dev/null <<'EOF'
[Unit]
Description=DeepSeek Harness Web
Documentation=https://github.com/deepseek-ai
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=0
StartLimitBurst=0

[Service]
Type=simple
WorkingDirectory=/root
Environment=PATH=/opt/node-v24.21.0-linux-arm64/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
Environment=NODE_OPTIONS=--max-old-space-size=1280
ExecStart=/opt/node-v24.21.0-linux-arm64/bin/dsh web --host 192.168.1.50 --port 8080 --no-open
Restart=always
RestartSec=5
StandardOutput=append:/opt/log/dsh-web.log
StandardError=append:/opt/log/dsh-web.log

[Install]
WantedBy=multi-user.target
EOF

逐行解释：

行 作用
After=network-online.target + Wants= 等网络真正就绪再启动。没有这两行，开机时可能网络还没起来，--host 绑不上会失败一次
WorkingDirectory=/root 工作目录。DSH 会把 .dsh 家目录建在这里
Environment=PATH=... 显式给 PATH。不依赖 /etc/profile.d，sudo/systemd 环境下都能找到 node
Environment=NODE_OPTIONS=--max-old-space-size=1280 限制 Node 堆内存。2GB 内存的板子必加，否则 Node 可能吃到 OOM。4GB 版可改 2048
ExecStart=... 用绝对路径，不写 dsh
Restart=always 进程挂了自动拉起
RestartSec=5 等 5 秒再拉（给端口释放留时间）
StartLimitIntervalSec=0 + StartLimitBurst=0 取消重启次数上限（必须写在 [Unit] 段，见下方踩坑）。默认 systemd 在 10 秒内失败 5 次就彻底放弃，我们要它无限重试
StandardOutput=append:... 日志追加到文件。注意 append: 需要 systemd ≥ 240（Ubuntu 20.04/22.04 都满足）

把 --host 192.168.1.50 换成你自己的 IP。 改了 IP 别忘了改这里。

如果你也把 /opt 挪到了独立磁盘/分区上（OK1028A 路线必须这么做，见 4.5），一定要在 [Unit] 段补一行：

ini
RequiresMountsFor=/opt

作用是「/opt 没挂载成功就不启动 dsh」。不写的话，挂载失败时 ExecStart 和 StandardOutput=append:/opt/log/... 的路径都不存在，服务会报 status=209/STDOUT 然后无限重启，而日志里完全看不出真正原因是「盘没挂上」——本文在 OK1028A 上实测吃到了这个亏（restart counter is at 80），详见 4.5.2 与 4.5.6。

【踩坑记录】StartLimitBurst=0 写错段落 = 白写

StartLimitBurst= / StartLimitIntervalSec= 是 [Unit] 段的设置，不是 [Service] 段的。

很多网上教程把它写在 [Service] 里，因为 systemd 230 之前确实允许。但从 systemd 230 开始就不认了，只会在日志里留一句：

Unknown key name 'StartLimitBurst' in section 'Service', ignoring.

而且不会报错、服务照常跑，所以极难发现。Ubuntu 20.04 是 systemd 245、22.04 是 249，都属"不认"的版本。

后果：你以为取消了重启上限，实际仍是默认的「10 秒内失败 5 次就彻底放弃」。板子如果一开机网络没起来、连挂 5 次，服务就永久躺平，直到你手动 systemctl start。

用这条命令验证是否生效：

bash
sudo systemctl show dsh -p StartLimitBurst -p StartLimitIntervalUSec

正确输出是下面这样（两个都是 0）：

StartLimitIntervalUSec=0
StartLimitBurst=0

如果显示 StartLimitBurst=5 / StartLimitIntervalUSec=10s，说明那两行放错段了（或者你改了文件但没 systemctl daemon-reload）。

4.1.1 关键：调试口是 RS232，不是 TTL #

这块板的调试串口是 RS232 电平的 DB9 接口（不是 3.3V TTL，也不是 USB）。

所以你需要的是「USB 转 RS232」的线（线上带一颗 MAX3232/FT232 之类的电平转换芯片），不能用那种几块钱的「USB 转 TTL（CH340/CP2102）」模块直接接。

【踩坑记录】用 USB-TTL 模块接 RS232 口，什么都收不到

RS232 是 ±12V 电平，TTL 是 0/3.3V。直接对接不仅收不到数据，还可能烧掉你 TTL 模块的接收端。

买线的时候认准：「USB 转 RS232 DB9 公/母头」，价格 20~40 元。买回来先在自己电脑上用「串口助手」短接 2、3 脚（TX-RX）做回环测试，能自发自收再上板子。

4.4 联网（ifupdown + 网桥，本文实测） #

⚠️ 本节在真机（OK1028A-C，LS1028A RDB Board）上逐条核对过，和飞凌官方论坛的说法不一样。 官方论坛 OK1028 ubuntu20 配置网口在同一网段使用 讲的是 systemd-networkd + /etc/systemd/network/swp0.network。 但本文实测的出厂镜像根本不是那样：systemd-networkd 是 disabled，真正生效的是 ifupdown（networking.service）+ 一个开机脚本 /root/my-net-init.sh 建网桥。 你如果照着论坛帖子去改 .network 文件，会发现"改了没反应"——因为根本没人在读它。

4.4.1 先看清这块板到底有几个口 #

bash

ip -br addr

实测输出（这块板出厂状态）：

eno0     DOWN            ee:4e:93:28:8b:01
eno2     UP   LOWER_UP   ee:4e:93:28:8b:02
swp0@eno2 ...
swp1@eno2 ...
swp2@eno2 ...
swp3@eno2 ...
br0      DOWN            ee:4e:93:28:8b:02

这 6 个"网口"其实只有 1 个能插网线，看懂这张表很关键：

名字 是什么 能不能插网线
eno0 独立 ENETC 控制器，物理 RJ45 ✅ 能（但出厂没接线，DOWN）
eno2 CPU 和交换芯片之间的内部口，不是物理口 ❌ 不能，别给它配 IP
swp0~swp3 DSA 从设备，交换芯片引出的 4 个物理 RJ45 ✅ 都能（@eno2 表示父设备是 eno2）
br0 软件网桥，把上面某个口桥起来 ❌ 虚拟的

swpX@eno2 里的 @eno2 不是"依赖"，是"父子关系"：Linux 网络设备名后面跟 @xxx，表示它的 master/父设备。看到这个符号就知道它是交换芯片的下挂口。

怎么找出到底哪个口插了网线（这是整节最关键的一步）：

bash
for i in eno0 swp0 swp1 swp2 swp3; do
  ip link set $i up 2>/dev/null
  echo "$i carrier=$(cat /sys/class/net/$i/carrier 2>/dev/null)"
done

carrier=1 的那个就是插了线的口。本文实测是 swp1。

【踩坑记录】出厂脚本 my-net-init.sh 有 5 个真 bug

不是让你去改它（改坏了更麻烦），而是你遇到怪现象时知道往哪儿想：

# 问题 现象 正确写法
1 默认路由指向无载波的 br0 外网完全不通，ping 223.5.5.5 100% 丢包 确认 swp1 有载波后再建路由，或把 IP 直接配在物理口上
2 bridge stp br0 off 语法根本不存在 每次开机都报一行 Command line is not complete ip link set br0 type bridge stp_state 0
3 不可重入 第二次跑报 RTNETLINK answers: File exists 建之前先 ip link show br0 >/dev/null 2>&1 || ip link add ...
4 #!/bin/sh 下用了 bash 专有的 &>/dev/null dash 不认，条件判断恒假 >/dev/null 2>&1
5 硬编码 swp1 你把网线插到别的口就全废 按 carrier 探测

另外：/etc/network/interfaces.d/eno0 里的 gateway 192.168.0.1 会和脚本建的路由打架，见 4.4.3。

4.4.3 修 networking.service failed（出厂就有） #

开机会看到两个红字服务：

bash
systemctl --failed

● ifup@eno0.service   loaded failed failed   ifup for eno0
● networking.service  loaded failed failed   Raise network interfaces

原因 1：路由冲突。

bash
journalctl -u networking --no-pager | tail -20

看到 RTNETLINK answers: File exists + ifup: failed to bring up eno0 → 就是 eno0 那个 gateway 192.168.0.1 和启动脚本抢默认路由。删掉它：

bash
cp /etc/network/interfaces.d/eno0 /etc/network/interfaces.d/eno0.bak

systemctl restart networking

原因 2：eno0 根本没插网线，开机时设备还没注册。

删掉 gateway 后如果改报 RTNETLINK answers: No such device，说明 auto eno0 强制在开机阶段拉起一个不存在的口。改成热插拔：

bash
sed -i 's/^auto eno0$/allow-hotplug eno0/' /etc/network/interfaces.d/eno0
systemctl restart networking
systemctl is-active networking     # expect: active

清掉历史失败记录（不然 systemctl --failed 永远红着）：

bash
systemctl reset-failed
systemctl --failed --no-legend     # expect: empty

4.4.4 把 PC 设成同网段，用网线直连 #

先在 PC 上用管理员 PowerShell 给有线网卡配静态 IP：

powershell

powershell

预期能看到：

IP Address:                           192.168.3.100
Subnet Prefix:                        192.168.3.0/24 (mask 255.255.255.0)

【踩坑记录】只配 IP 不删网关 = 自找麻烦

本文实测的 PC 上残留了 3 条"幽灵永久路由"： 0.0.0.0/0 via 192.168.3.1（两条）+ 0.0.0.0/0 via 192.168.1.1。 因为板子这根线是直连，192.168.3.1 这个网关根本不存在（arp -a 里只有 .200，192.168.3.1 永远 INCOMPLETE）。 结果就是：PC 想上网时会被这条假路由吸走，ping 192.168.3.200 也可能挑错出口。

删掉它们（管理员）：

route delete 0.0.0.0 mask 0.0.0.0 192.168.1.1
route print 192.168.3.200

route print 里必须出现一条 192.168.3.0/24 → 192.168.3.100 的直连路由，否则一定不通。

怎么验证真的通了（不要用 ping 判断）：

powershell

看到 192.168.3.200 ee-4e-93-28-8b-02 dynamic 就说明二层双向已通。

配好后在 PC 上测：

powershell
ssh root@192.168.3.200

密码 root（这块板出厂 root/root；也有 forlinx/forlinx，是 uid 1000 的普通用户）。

【踩坑记录】PC 能 ping 通板子，板子 ping 不通 PC

单向可达，99% 是 Windows 防火墙默认不放开站入站 ICMPv4 Echo Request（有线网卡常被判为"公用网络"，最严格档）。 用管理员 PowerShell 放行：

powershell

但注意：如果你的目的只是「PC 浏览器打开板子上的 DSH 网页」，这个方向根本不用修。 那是 PC 主动连板子的 8080，和 ICMP 无关。

4.4.5 让板子上外网（直连 PC 时：PC 跑一个 HTTP 代理） #

先别急着折腾 NAT。 本文实测这条路上有两个硬障碍：

  1. PC 上没有 192.168.3.1 这个网关（直连场景它不存在）；
  2. PC 侧当前不是管理员，所以 New-NetNat、ICS（Internet 连接共享）、改防火墙全都做不了。

而且 OK1028A 这块板子没有任何无线能力，实测确认：

bash
rfkill list          # prints: no rfkill
iw dev               # prints nothing
lsusb                # only 4x 1d6b:000x Linux Foundation root hubs, no real USB device
lspci                # all Freescale Semiconductor Inc, no WiFi/4G module

内核里也没有 USB WiFi 驱动（/lib/modules/$(uname -r)/kernel/drivers/net/wireless/realtek/rtw88/ 下只有 rtw88_8822c.ko、rtw88_8822ce.ko、rtw88_core.ko、rtw88_pci.ko——全是 PCIe 版，没有 rtw88_8822cu.ko），也没有 rndis_host.ko（所以手机 USB 共享网络也不通）。插个几十块的 USB WiFi 棒是没用的，除非你自己重编内核模块。

所以最省事、实测可行的方案是：在 PC 上跑一个 HTTP 代理，板子通过它出网。

第一步，在 PC 上启动代理（纯 Python 标准库，不用装任何东西）：

powershell
cd C:\Users\liuluhua\Documents\deepseek-harness\default-workspace
python pcproxy.py 7890

看到它监听 0.0.0.0:7890 就行。这个窗口要一直开着，关掉代理板子就断网。

第二步，在板子上配全局代理：

bash
cat > /etc/apt/apt.conf.d/01proxy <<'EOF'
Acquire::http::Proxy "http://192.168.3.100:7890";
Acquire::https::Proxy "http://192.168.3.100:7890";
EOF

cat > /etc/profile.d/99-pcproxy.sh <<'EOF'
export http_proxy=http://192.168.3.100:7890
export https_proxy=http://192.168.3.100:7890
export HTTP_PROXY=$http_proxy
export HTTPS_PROXY=$https_proxy
export no_proxy=localhost,127.0.0.1,192.168.3.0/24
EOF
chmod 644 /etc/profile.d/99-pcproxy.sh

重新登录（或 source /etc/profile.d/99-pcproxy.sh）后验证：

bash
curl -s -o /dev/null -w "baidu=%{http_code}\n" http://www.baidu.com
curl -s -o /dev/null -w "npm=%{http_code}\n" https://registry.npmmirror.com/

预期两个都是 200。本文实测：baidu 0.18s、npmmirror 0.24s、nodejs.org 14.9s（慢但通）。

第三步（本题最关键的一条）：让 Node 也走代理。

板子上的 Node 是 v22.22.0（/usr/bin/node，apt 装的）。它的全局 fetch 默认不读 http_proxy：

bash
node -e "fetch('https://registry.npmmirror.com/').then(r=>console.log('status',r.status)).catch(e=>console.log('ERR',e.message))"

不加处理会输出 ERR fetch failed。加上环境变量就好了：

bash
export NODE_USE_ENV_PROXY=1
node -e "fetch('https://registry.npmmirror.com/').then(r=>console.log('status',r.status))"

预期 status 200（可能附带一条 [UNDICI-EHPA] Warning: EnvHttpProxyAgent is experimental，这是警告不是错误，忽略）。

【踩坑记录】这是本文整个方案里最容易漏的一条

DSH 自己的登录、模型调用全靠 fetch。不设 NODE_USE_ENV_PROXY=1，DSH 起了也登录不上、调不动模型，而且报错只有一句 fetch failed，极难联想到是代理没传到 Node 里。 所以 4.10.2 的 systemd unit 里必须有 Environment=NODE_USE_ENV_PROXY=1。 等价写法是启动参数 node --use-env-proxy，但 systemd 里用环境变量更省事。

【踩坑记录】代理方案的三个能力边界

  1. 只解决 HTTP/HTTPS，不转发任意 TCP（不是 NAT）。所以 ping 223.5.5.5 依然不通——这是正常的，不代表网没通，要看 curl 的结果。
  2. DNS 还是板子自己解析。板子 /etc/resolv.conf 是 8.8.8.8 + 114.114.114.114（出厂脚本写的），在直连场景下这两个 DNS 其实也不可达。但因为走代理时域名是交给代理去解析的，所以不影响 curl/npm。
  3. PC 关掉代理，板子就断网。所以装完 DSH 之后，dsh.service 里那些代理环境变量可以留着（不影响 PC 内网访问板子）；但如果你把板子搬到有路由器的环境，必须把四处代理配置全部拆掉（apt / profile.d / .npmrc / systemd unit），只删一两处会出现「网络通了但命令照样超时」的怪现象——完整清单见 4.4.6 第 ② 步。

4.4.6 把网线插到路由器上（最省事的正解，也是长期方案） #

如果能拉到路由器旁边，这才是最推荐的做法，上面那一整套代理都可以拆掉。

但是不能只把线一插就完事。板子上现在有四处地方写死了 192.168.3.100:7890 这个代理，插到路由器后那些代理都不存在了，会变成"网络明明通了、命令却全超时"的怪现象。必须把四处清干净，见下面的清单。

① 插线、改成 DHCP

网线插路由器 LAN 口，然后在板子上：

bash
# flush the static ip that my-net-init.sh put on br0
ip addr flush dev br0
# ask the router for a lease
dhclient -v br0
ip -4 addr show br0
ip route

ip route 应该看到一条 default via <路由器IP> dev br0。注意这条默认路由必须由 DHCP 产生——如果此时还残留着 default via 192.168.3.1 dev br0，说明 my-net-init.sh 开机又写回去了，见第 ③ 步。

② 拆掉四处代理配置

bash
# 1. apt proxy
rm -f /etc/apt/apt.conf.d/01proxy

# 2. shell profile proxy
rm -f /etc/profile.d/99-pcproxy.sh

# 3. npm user config: remove only the proxy lines, keep prefix/cache/registry
sed -i '/^proxy=/d;/^https-proxy=/d' /root/.npmrc
cat /root/.npmrc

# 4. systemd unit: remove the three proxy lines and NODE_USE_ENV_PROXY
cp /etc/systemd/system/dsh.service /root/dsh.service.bak.$(date +%s)
sed -i '/^Environment=NODE_USE_ENV_PROXY=/d;/^Environment=http_proxy=/d;/^Environment=https_proxy=/d;/^Environment=no_proxy=/d' /etc/systemd/system/dsh.service
grep -n "Environment=" /etc/systemd/system/dsh.service

/root/.npmrc 清理后应该只剩三行：

prefix=/opt/npm-global
cache=/opt/npm-cache
registry=https://registry.npmmirror.com/

dsh.service 清理后 Environment= 应该只剩两行（PATH 与 NODE_OPTIONS）。

【踩坑记录】拆代理的顺序很重要

先拆代理再改 IP，会有一段"两边都不通"的空窗期，不值得。正确顺序是 先让 DHCP 拿到新地址、确认 curl 直连通了，再拆代理。反过来做的话，代理已经删了、新网络还没验证，出问题分不清是哪一步的锅。

③ 把 my-net-init.sh 里的静态 IP 也换掉（否则重启就回退）

出厂脚本 /root/my-net-init.sh 里写死了 ip addr add 192.168.3.200/24 dev br0 和 ip route add default via 192.168.3.1 dev br0。只要它还开着，每次重启都会把静态 IP 和那个不存在的网关重新写回去。两条路选一条：

bash
# option A (recommended): stop using it, let the router hand out the address
systemctl disable my-net-init
# then edit dsh.service so it no longer waits for it
sed -i 's|^After=network-online.target my-net-init.service$|After=network-online.target|' /etc/systemd/system/dsh.service
grep -n "^After=" /etc/systemd/system/dsh.service

bash
# option B: keep it but make it DHCP-based (edit the script by hand)
vi /root/my-net-init.sh
# comment out the "ip addr add ..." and "ip route add default ..." lines,
# and append:  dhclient br0

④ 最关键的一步：--host 里写死的 IP 必须跟着改

dsh 不接受 0.0.0.0，所以 dsh.service 里是 --host 192.168.3.200。插到路由器后 DHCP 很可能给另一个地址（比如 192.168.1.37），这时 dsh 会绑不上、服务起不来。真机实测的报错长这样（注意第一行并不是真正原因，真正原因在中间那行 EADDRNOTAVAIL）：

dsh: startup failed: 2 required plugins did not activate

Failed plugins (1):
  webserver (required)
    Package: @deepseek-ai/dsh-host-webserver
    Error: listen EADDRNOTAVAIL: address not available 192.168.1.37:8081

Plugins waiting for services (5):
  Plugin                  Missing services
  web-runtime (required)  webServer
  open-in-app             webServer
  directory-picker        webServer
  ...

因为 Restart=always + StartLimitBurst=0，它会每 5 秒重试一次、无限重试，日志里反复出现上面这一坨。所以换网络后必须：

bash
# read the address the board actually has now
NEWIP=$(ip -4 addr show br0 | grep -oP '(?<=inet\s)\d+(\.\d+){3}' | head -1)
echo "current ip: $NEWIP"

# rewrite --host in the unit
sed -i "s|--host [0-9.]*|--host ${NEWIP}|" /etc/systemd/system/dsh.service
grep -n "ExecStart=" /etc/systemd/system/dsh.service

systemctl daemon-reload
systemctl restart dsh

【踩坑记录】DSH 的 --host 是硬约束，不是能省略的参数

它明确拒绝通配地址，官方报错原文： error: --host 0.0.0.0 is an unspecified (wildcard) address, which is not supported: binding every interface would expose remote code execution to the network; bind one concrete IPv4 or IPv6 address instead 原因是 DSH 自带 shell 执行能力，绑到全网等于把 root shell 送给局域网。 代价就是每次板子 IP 变化都要改一次 unit。所以长期部署时建议在路由器上给这块板做 DHCP 静态绑定（按 MAC 固定 IP），MAC 是 ee:4e:93:28:8b:02：

bash
ip -br link show br0     # confirm the mac before you use it

固定之后 IP 不再漂移，这条就永远不用再改。

4.5.2 用 SD 卡扩容（治本，本文实测方案） #

准备：一张 SD/TF 卡（本文用的是 256GB），插到板子的 TF 卡座（不是 USB 口）。

第一步：确认卡被识别

bash
lsblk -o NAME,SIZE,MODEL,SERIAL

【踩坑记录】lsblk 里看不到 mmcblk0 = 内核没认出卡，不是"没挂载"

这一点很多人会误判。lsblk 会列出所有块设备，不管挂没挂。所以如果输出里根本没有 mmcblk0，说明是硬件层没识别：

  1. 卡没插到底（TF 卡座是推入式，听到"咔"一声才算到位）；
  2. 插错槽了；
  3. 卡本身或卡座有问题——换一张小容量卡试，能认出来就是这张卡的问题。

重插之后立刻看内核有没有反应：

bash
dmesg | tail -20

出现 mmc0: new high speed SDHC card 之类的行就对了。

另外注意：Linux 服务器不会自动挂载可移动介质（那是桌面环境的 udisks 干的事）。所以"没自动挂载"是正常设计，不是故障。

第二步：格成 ext4（不要用 exFAT / FAT32）

为什么必须是 ext4？ 两个硬理由：

  1. FAT/exFAT 不支持符号链接。npm 全局安装会建 node_modules/.bin/dsh 这样的软链，在 FAT 上 ln -s 直接报 Operation not supported，安装会失败。
  2. FAT/exFAT 的 chmod 是静默无效的。DSH 会把 /root/.dsh/.credentials.yaml 设成 0600（里面有 token 和密钥），在 FAT 上这个权限根本设不上去，等于把凭证裸奔。
bash
# DANGER: confirm the device name first. eMMC is mmcblk1, SD card is mmcblk0
lsblk -o NAME,SIZE,MODEL,SERIAL | grep -E "mmcblk0|mmcblk1"

【踩坑记录】这一行 parted 打错一个字符 = eMMC 上的系统没了

eMMC 是 mmcblk1，SD 卡是 mmcblk0，只差一个数字。格式化前务必用上面那行 lsblk ... | grep 把容量对一遍（SD 卡 229G、eMMC 6G，一眼能分辨）。

确认无误后：

bash
parted /dev/mmcblk0 --script mklabel gpt
parted /dev/mmcblk0 --script mkpart primary ext4 1MiB 100%
mkfs.ext4 -L dshdata /dev/mmcblk0p1

第三步：挂载并写进 /etc/fstab

bash
mkdir -p /mnt/sd
blkid /dev/mmcblk0p1        # note the UUID= value

把下面两行的 UUID 换成你实际的值，追加到 /etc/fstab：

UUID=e891bfd2-6893-4b4c-8a50-07f5fed6ea5b /mnt/sd ext4 defaults,nofail,x-systemd.device-timeout=30s,x-systemd.mount-timeout=30s 0 2
/mnt/sd/opt /opt none bind,nofail,x-systemd.requires-mounts-for=/mnt/sd,x-systemd.after=/mnt/sd,retry=5 0 0

nofail 不是可选项，是必须的。

没有 nofail 的话，一旦卡没插 / 卡坏了 / 识别失败，systemd 会认为挂载失败，开机直接卡在等这个设备（就是本文档 4.3 节说的那个 A start job is running for ... (44s / 1min 30s)，白等 90 秒）。加上 nofail 之后，挂不上就跳过，系统照常起来。

【踩坑记录】bind mount 那行只写 nofail 不够，开机时 /opt 会挂不上

这是本文实测踩到的真实故障，第一次开机就这样：

$ df -Pm / /opt
Filesystem     1048576-blocks  Used Available Capacity Mounted on
/dev/root                6094  5490       588      91% /
/dev/root                6094  5490       588      91% /opt     <-- 不是 SD 卡！

$ findmnt /opt
not mounted

$ journalctl -b -u mnt-sd.mount -u opt.mount --no-pager
Oct 27 16:33:23 forlinx systemd[1]: Dependency failed for /mnt/sd.
Oct 27 16:33:23 forlinx systemd[1]: Dependency failed for /opt.
Oct 27 16:33:23 forlinx systemd[1]: opt.mount: Job opt.mount/start failed with result 'dependency'.

后果连锁：/opt 退回 eMMC 上的空目录 → /opt/npm-global/bin/dsh 不存在 → dsh.service 起不来 → 而 StandardOutput=append:/opt/log/dsh-web.log 的父目录也没了，systemd 连日志都开不出来，报：

dsh.service: Failed to set up standard output: No such file or directory
dsh.service: Failed at step STDOUT spawning /opt/npm-global/bin/dsh: No such file or directory
dsh.service: Main process exited, code=exited, status=209/STDOUT
dsh.service: Scheduled restart job, restart counter is at 80.

注意最后那行 restart counter is at 80 —— 它每 5 秒重试一次，一直数到 80 次都没成功。因为 StartLimitBurst=0 取消了上限，它不会放弃，会永远重试。这是好事也是坏事：好消息是挂载修好后自己就起来了，坏消息是它不会停下来提醒你。

根因：两行 fstab 之间没有依赖关系。/mnt/sd 是 local-fs.target 的一部分，但 bind mount /opt 可以抢在它前面执行；而且 SD 卡枚举本身需要时间，原来写的 x-systemd.device-timeout=5s 只有 5 秒，板子上根本来不及。

修法（就是上面那两行）：

  • /mnt/sd 那行把设备等待放宽到 30 秒（x-systemd.device-timeout=30s + x-systemd.mount-timeout=30s）；
  • /opt 那行显式声明依赖：x-systemd.requires-mounts-for=/mnt/sd + x-systemd.after=/mnt/sd，再加 retry=5 重试。

改完必须 systemctl daemon-reload 让 systemd 重新生成 .mount 单元，然后 systemctl reset-failed mnt-sd.mount opt.mount 清掉失败状态，再 mount /opt 或重启。

【额外加固】dsh.service 里要写 RequiresMountsFor=/opt

光修 fstab 还不够保险——万一哪天卡真的没插，服务照样会陷入「日志路径不存在 → 209/STDOUT → 无限重启」的死循环。

在 [Unit] 段加一行：

ini
RequiresMountsFor=/opt

它的作用是：/opt 没挂载成功就不启动 dsh。这样至少 systemctl status dsh 会明确显示「因为依赖的挂载点没就绪而没启动」，而不是一堆看不懂的 209/STDOUT。

本文实测：加上这行后 reboot，NRestarts=0、http=401、/opt 正常挂载，一次成功。详见 4.5.6。

挂载并验证：

bash
systemctl daemon-reload
mount -a
df -h /opt /mnt/sd

实测输出（/opt 和 /mnt/sd 显示成同设备同容量，就说明 bind mount 生效了）：

Filesystem      Size  Used Avail Use% Mounted on
/dev/mmcblk0p1  229G   61M  217G   1% /opt
/dev/mmcblk0p1  229G   61M  217G   1% /mnt/sd

【踩坑记录】findmnt --verify 报 [W] cannot detect on-disk filesystem type 不用管

完整输出：

/mnt/sd
   [W] cannot detect on-disk filesystem type
0 parse errors, 0 errors, 1 warning

这只是非 root 用户读不了块设备导致探测不到 FSTYPE，0 parse errors, 0 errors 才是重点。用 sudo findmnt --verify 就不会有这条警告，但它不代表任何故障。

4.5.3 把 npm 的全局目录和缓存也搬到卡上 #

光有 /opt 还不够——npm 的全局包默认装在 Node 的 prefix 下，缓存默认在 ~/.npm，这两个都在根分区上。

bash
cat > /root/.npmrc <<'EOF'
prefix=/opt/npm-global
cache=/opt/npm-cache
registry=https://registry.npmmirror.com/
EOF

【踩坑记录】npm config set cache ... --global 必定报 EACCES

实测的完整报错：

npm error code EACCES
npm error syscall mkdir
npm error path /usr/etc
npm error errno -13

三个原因叠在一起：

  1. --global 写的是系统级 npmrc（/usr/etc/npmrc），普通用户没权限；
  2. 命令没加 sudo；
  3. 目标目录 …/npm-cache 当时还不存在。

正确做法：别用 --global。 直接按上面那样手写 /root/.npmrc（或用 npm config set cache /opt/npm-cache，不带 --global），用户级配置完全够用，而且不用 sudo。

本文实测的板子上，Node 是 apt 装的 v22.22.0（/usr/bin/node，来自 nodesource 的 node_20.x 仓库，实际给的是 22.22.0），它的 npm prefix 是 /usr——所以任何 --global 操作都会去写 /usr/etc，必然被拒。

验证配置生效：

bash

npm config get cache

预期：

/opt/npm-global
/opt/npm-cache

4.5.4 顺手修掉「开机等 90 秒」的幽灵挂载 #

出厂 /etc/fstab 里有这么一行（本文实测）：

UUID=d73a3caf-7ca7-4a24-b889-6c411253ddb9 /mnt/usb ext4 defaults 0 2

/mnt/usb 是个预留的"USB 存储"挂载点，这个设备根本不存在（lsblk -f 里找不到那个 UUID）。结果就是每次开机 systemd 都要空等满 90 秒。

bash
cp /etc/fstab /etc/fstab.bak
sed -i '/b889-6c411253ddb9/s/^/#/' /etc/fstab
grep -n "b889" /etc/fstab      # confirm it is now commented out

修完重启对比一下：

bash
systemd-analyze blame | head -10

那个几十秒的 .device 单元应该消失了。如果还在，看 journalctl -b | grep -iE "timed out|usb|b889" 找真正的等待者。

4.5.5 一个必须提醒的副作用 #

/opt 现在被 bind mount 盖住了。这意味着：

  • 卡没插好时，/opt 会退回成 eMMC 上的空目录，Node 和 DSH 一起"消失"，服务起不来（但因为有 nofail，系统本身能正常开机）。这就是前面说的 /opt 被遮蔽（mount 覆盖）的语义。
  • 想看被盖住的原始目录：先 umount /opt，原来的内容就露出来了。
  • 所以卡必须一直插着。如果只是临时装个环境，用完可以把 /mnt/sd/opt 拷回 eMMC。

4.5.6 重启一次，确认挂载真的能自己起来（必做） #

前面 4.5.2 里已经把 fstab 改对了，但这一节必须单独跑一遍，因为「mount -a 当场成功」和「开机时自动挂载成功」是两件完全不同的事——本文实测就栽在这里。

bash
reboot

起来之后，先看挂载，再看服务：

bash
findmnt /mnt/sd /opt
df -Pm / /opt

健康的样子（/opt 的来源必须是 /dev/mmcblk0p1，不是 /dev/root）：

TARGET  SOURCE               FSTYPE OPTIONS
/mnt/sd /dev/mmcblk0p1       ext4   rw,relatime
/opt    /dev/mmcblk0p1[/opt] ext4   rw,relatime

Filesystem     1048576-blocks  Used Available Capacity Mounted on
/dev/root                6094  5499       580      91% /
/dev/mmcblk0p1         233782  1188    220651       1% /opt

不健康的样子（本文实测第一次开机就是这种）：

$ findmnt /opt
not mounted

$ df -Pm / /opt
Filesystem     1048576-blocks  Used Available Capacity Mounted on
/dev/root                6094  5490       588      91% /
/dev/root                6094  5490       588      91% /opt     <-- 错！应该是 /dev/mmcblk0p1

出现第二种情况，按下面的顺序查：

bash
# 1. what does systemd say about these two mount units
journalctl -b -u mnt-sd.mount -u opt.mount --no-pager | tail -30

# 2. is fstab correct (uuid and both option lists)
grep -v '^#' /etc/fstab | grep -v '^$'

# 3. is the card detected at all
lsblk -f | grep mmcblk0

如果日志里出现 Dependency failed for /mnt/sd / Job opt.mount/start failed with result 'dependency'，就是 4.5.2 里那个依赖顺序问题，把两行 fstab 的选项补齐：

bash
cp /etc/fstab /root/fstab.bak.$(date +%s)

# /mnt/sd: replace the whole options field, so it works whatever it was before
sed -i 's|^\(.*[[:space:]]/mnt/sd[[:space:]]\+ext4[[:space:]]\+\)[^[:space:]]\+|\1defaults,nofail,x-systemd.device-timeout=30s,x-systemd.mount-timeout=30s|' /etc/fstab

# /opt: declare the dependency explicitly + retry
sed -i 's|^\(.*[[:space:]]/opt[[:space:]]\+none[[:space:]]\+\)bind[^[:space:]]*|\1bind,nofail,x-systemd.requires-mounts-for=/mnt/sd,x-systemd.after=/mnt/sd,retry=5|' /etc/fstab

grep -v '^#' /etc/fstab | grep -v '^$'

为什么这两条 sed 长得这么吓人：它们匹配的是「路径那一列 + 后面的全部选项」，而不是死记整行内容。这样三种起始状态都能改对：

  • 出厂原样（defaults / bind，完全没有 nofail）；
  • 本文档早期版本（nofail,x-systemd.device-timeout=5s / nofail）；
  • 已经是修好的版本（重跑不会改坏，幂等）。

本文在真机上把三种状态都跑了一遍，并在真实 /etc/fstab 上做了幂等验证（diff 无差异）。

再给 dsh.service 加上挂载依赖（这一行是保命用的）：

bash
cp /etc/systemd/system/dsh.service /root/dsh.service.bak.$(date +%s)
grep -q '^RequiresMountsFor=/opt$' /etc/systemd/system/dsh.service || \
  sed -i 's|^After=network-online.target my-net-init.service$|After=network-online.target my-net-init.service\nRequiresMountsFor=/opt|' /etc/systemd/system/dsh.service
grep -n "RequiresMountsFor" /etc/systemd/system/dsh.service

前面那个 grep -q ... || 是幂等守卫：已经有了就跳过。没有它的话，重复执行 sed 会插出两行一样的 RequiresMountsFor=/opt（systemd 能容忍，但不干净），本文实测确认过这个坑。

RequiresMountsFor=/opt 干什么用的：/opt 没挂载成功就根本不启动 dsh。没有它的话，一旦卡掉了，你会看到服务在无限重启，日志里全是 Failed to set up standard output: No such file or directory / status=209/STDOUT / restart counter is at 80 —— 完全看不出真正原因是"卡没挂上"。

最后清掉失败状态并重启验证：

再起来之后跑这三条，三条都对才算过关：

NRestarts=0 是关键——说明一次就起来了，没有经历过失败重启。如果是 NRestarts=3 之类，说明还有别的东西在拖后腿，去 journalctl -b -u dsh 里找。

4.10 注册为 systemd 服务 #

4.10.1 手动试跑 #

bash
export PATH=/opt/npm-global/bin:$PATH
dsh web --host 192.168.3.200 --port 8080 --no-open

看到：

dsh web: listening on 192.168.3.200 over plain HTTP; restrict this port to a trusted proxy or network
dsh web: http://192.168.3.200:8080/?token=xxxx

Ctrl+C 停掉。

【踩坑记录】--host 0.0.0.0 会被直接拒绝

error: --host 0.0.0.0 is an unspecified (wildcard) address, which is not supported: binding every interface would expose remote code execution to the network; bind one concrete IPv4 or IPv6 address instead

这是 DSH 的安全设计（它内置执行 shell 的能力，暴露到全网等于送人一个 root shell）。必须写板子的具体 IP。 所以 4.4 里把 IP 固定下来不只是为了好看，是 DSH 能启动的前提。

4.10.2 写 service #

OK1028A 是 2GB 内存，--max-old-space-size 给 1280（和 2GB 版 OK3568 一样；如果你手上的 OK3568 是 4GB 版，那边改成 2048）。

bash
mkdir -p /opt/log

cat > /etc/systemd/system/dsh.service <<'EOF'
[Unit]
Description=DeepSeek Harness Web (board)
After=network-online.target my-net-init.service
RequiresMountsFor=/opt
Wants=network-online.target
StartLimitIntervalSec=0
StartLimitBurst=0

[Service]
Type=simple
WorkingDirectory=/root
Environment=PATH=/opt/npm-global/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
Environment=NODE_OPTIONS=--max-old-space-size=1280
Environment=NODE_USE_ENV_PROXY=1
Environment=http_proxy=http://192.168.3.100:7890
Environment=https_proxy=http://192.168.3.100:7890
Environment=no_proxy=localhost,127.0.0.1,192.168.3.0/24
ExecStart=/opt/npm-global/bin/dsh web --host 192.168.3.200 --port 8080 --no-open
Restart=always
RestartSec=5
StandardOutput=append:/opt/log/dsh-web.log
StandardError=append:/opt/log/dsh-web.log

[Install]
WantedBy=multi-user.target
EOF

逐行说明：

行 作用
After=network-online.target my-net-init.service 等网络真的配好再启动。my-net-init.service 是出厂脚本（见 4.4.2），它负责把 192.168.3.200 建出来；如果不等它，DSH 会在 IP 还不存在时启动然后报 EADDRINUSE/绑定失败
RequiresMountsFor=/opt /opt 没挂上就不启动。/opt 是 SD 卡上的 bind mount，卡没插/挂载失败时它会退回 eMMC 上的空目录，此时 ExecStart 和 StandardOutput 的路径都不存在 → 报 status=209/STDOUT 并无限重启（本文实测数到 80 次），而日志里完全看不出真正原因。加了这行，systemd 会直接因依赖不满足而不启动，报错清楚得多
StartLimitIntervalSec=0 + StartLimitBurst=0 取消重启次数上限（必须放在 [Unit] 段，见下方踩坑）。默认 systemd 在 10 秒内失败 5 次就彻底放弃
Environment=PATH=... systemd 有自己的 PATH，不含 /opt/npm-global/bin。不写这行，ExecStart 里就得用绝对路径
NODE_OPTIONS=--max-old-space-size=1280 限制 V8 堆大小，避免 2GB 的板子被 Node 吃光
NODE_USE_ENV_PROXY=1 让 Node 的 fetch 读 http_proxy。不加这条，DSH 起了也登录不上、调不动模型（详见 4.4.5）
http_proxy / https_proxy / no_proxy 代理配置。no_proxy 里必须有 192.168.3.0/24，否则 PC 访问板子自己的 8080 也会被绕去代理
Restart=always + RestartSec=5 崩了就重启，间隔 5 秒
StandardOutput=append:/opt/log/... 日志写在 /opt（SD 卡）上，不是 /var/log。根分区只剩 400MB，日志写那儿迟早写满
WantedBy=multi-user.target 开机自启

【踩坑记录】StartLimitBurst=0 写在 [Service] 段 = 白写

这是 systemd 里最隐蔽的一个坑：StartLimitBurst / StartLimitIntervalSec 属于 [Unit] 段的设置。 从 systemd v230 起，写在 [Service] 里会被静默忽略，只在 journal 里留一句：

Unknown key name 'StartLimitBurst' in section 'Service', ignoring

它不报错、服务照常跑，所以你根本不会发现「取消重启上限」这件事没生效——服务连续挂 5 次之后，systemd 就永久躺平不再拉起了。 Ubuntu 20.04 是 systemd 245、22.04 是 249，两者都不认这种写法。

验证它真的生效了：

bash
systemctl show dsh -p StartLimitBurst -p StartLimitIntervalUSec -p Restart

正确输出（三个值都要对）：

Restart=always
StartLimitIntervalUSec=0
StartLimitBurst=0

如果 StartLimitBurst 显示 5（默认值），就是写错段了。

4.10.3 启动 #

bash
systemctl daemon-reload
systemctl enable --now dsh
systemctl status dsh --no-pager

预期 Active: active (running)。

【踩坑记录】active 了但端口还没在听——这是正常的，要等约 50 秒

实测时间线：systemctl restart dsh 之后 45 秒时 ss -ltn 里还没有 8080，再等 5 秒才出现。总共约 50 秒，绝大部分是 Node 冷启动（要加载 600 多个包）。

这期间不要以为启动失败而反复 restart——每 restart 一次就重新等 50 秒。

想知道它到底在干嘛：

bash
tail -f /opt/log/dsh-web.log

只在真正开始监听后才会出现 dsh web: listening on ... 那行。

4.10.4 拿 token #

bash
grep -o 'http://[^ ]*token=[A-Za-z0-9_-]*' /opt/log/dsh-web.log | tail -1

token 每次重启都会变，因为它是启动时随机生成的。但已经下发的 cookie 不受影响——cookie 的签名密钥存在 /root/.dsh/.credentials.yaml 里，不随进程变化。所以浏览器里登录过一次之后，服务重启了也不会掉登录。

4.11 从局域网验证 #

先在板子上自己测：

# with token -> expect 303 (redirect + Set-Cookie)
curl -s -o /dev/null -w "with-token=%{http_code}\n" "http://192.168.3.200:8080/?token=PASTE_YOUR_TOKEN"

实测：

另外本文实测：这台 Windows 上 curl.exe 访问 HTTPS 站点恒定返回 000（假阴性），但访问 http://192.168.3.200:8080 完全正常。所以验证本地服务用 curl.exe 没问题；要测外网 HTTPS，改用 Python。

实测：RECOVERED after ~65s，NRestarts=1，pid 变了，日志里出现第二个 listening 行和新的 token。

然后重启整块板：

6. 内存不够怎么办 #

这一章对 2GB 版板子（OK1028A 全部、OK3568 的 2GB 版本）是必读的。

6.1 先看现有 swap #

bash
free -m

如果 Swap: 那一行全是 0，就说明没有 swap。

6.2 方案一：加 swap 文件（简单，但伤 eMMC） #

bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

写进 fstab 让它开机生效：

bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

验证：

bash
free -m

Swap: 那行应该显示 total 2047。

【踩坑记录】swap 文件放在 eMMC 上会加速磨损

eMMC 的擦写寿命有限（通常 3000 P/E 左右）。swap 会频繁读写。如果板子要 7×24 长期跑，优先用方案二（zram），方案一只在「临时装个包」时用，用完 sudo swapoff /swapfile && sudo rm /swapfile 删掉。

6.3 方案二：zram（推荐，压缩内存，不碰磁盘） #

zram 是在内存里划一块出来做压缩交换，完全不写 eMMC。

bash
sudo apt-get install -y zram-tools

配置（把 50% 内存拿来做 zram）：

bash
sudo tee /etc/default/zramswap > /dev/null <<'EOF'
ALGO=zstd
PERCENT=50
PRIORITY=100
EOF

启动：

bash
sudo systemctl restart zramswap
free -m

现在 Swap: 行会显示约 1000MB 的 zram。

注意 zram 是「用 CPU 换内存」：压缩/解压要算力，会占用一点 CPU。板子 CPU 有余量，这个交换是划算的。

但 zram 只能救「空闲页面」，救不了「正在被大量使用的内存」。如果 DSH 真的持续要吃 3GB，2GB 内存是救不回来的——那时候换 4GB 版板子才是正解。

6.4 给 Node 限制堆大小 #

service 文件里的 NODE_OPTIONS=--max-old-space-size=... 已经在控制这个：

内存 建议值
1GB 512
2GB 1280
4GB 2048

超过这个值 Node 会自己 GC 或者抛 JavaScript heap out of memory，而不是把整机拖死。

6.5 装完包之后看实际占用 #

bash
# check how much memory the dsh process actually uses
ps -o pid,rss,cmd -p $(systemctl show dsh -p MainPID --value)

# RSS is in KB. we measured 250~400MB on the phone

如果常驻稳定在 300MB 左右，2GB 板子完全够（还剩 1.7GB 给系统和页面缓存）。

7. 常见故障排查 #

7.1 按现象查 #

现象：systemctl status dsh 是 failed（code=exited, status=1） #

先看日志：

bash
sudo journalctl -u dsh -n 50 --no-pager

再手动跑一次看真实报错（systemd 里的报错常常被截断）：

bash
/opt/npm-global/bin/dsh web --host 192.168.1.50 --port 8080 --no-open

常见三种：

报错 原因 修法
EADDRINUSE: address already in use 192.168.1.50:8080 已经有一个实例在跑 sudo systemctl stop dsh，然后 sudo ss -ltnp | grep 8080 确认端口空了
EADDRNOTAVAIL: address not available --host 写的 IP 不是本机现在的 IP（换了网络/IP 变了） 把 ExecStart 里的 --host 改成当前 IP，见 4.4.6 第 ④ 步
--host ... is an unspecified (wildcard) address 写成了 0.0.0.0 改成具体 IP
Cannot find module ... npm 装包不完整 npm install -g @deepseek-ai/dsh@0.2.1-rc.3 --force 重装

EADDRNOTAVAIL 的报错输出很容易看错重点——它第一行是 dsh: startup failed: 2 required plugins did not activate，EADDRNOTAVAIL 埋在中间「Failed plugins」小节里。一看到 plugins did not activate 就去查插件，方向就完全跑偏了。

现象：dsh.service 无限重启，日志里全是 status=209/STDOUT #

完整报错是这样的：

dsh.service: Failed to set up standard output: No such file or directory
dsh.service: Failed at step STDOUT spawning /opt/npm-global/bin/dsh: No such file or directory
dsh.service: Main process exited, code=exited, status=209/STDOUT
dsh.service: Scheduled restart job, restart counter is at 80.

这个报错说的是「标准输出的文件开不了」，不是 dsh 本身坏了。 真正原因是 /opt 没挂上（SD 卡挂载失败或卡没插），于是：

  1. StandardOutput=append:/opt/log/dsh-web.log 的父目录不存在 → systemd 连日志文件都建不出来 → status=209/STDOUT；
  2. 同时 ExecStart=/opt/npm-global/bin/dsh 也不存在；
  3. 每 5 秒重试一次，因为 StartLimitBurst=0 取消了上限，所以会一直数下去（本文实测数到 80 次）。

排查顺序：

bash
# 1. is /opt really on the sd card?
findmnt /opt
df -Pm / /opt

# 2. why did the mount fail?
journalctl -b -u mnt-sd.mount -u opt.mount --no-pager | tail -30

# 3. is the card even detected?
lsblk -f | grep mmcblk0

修法见 4.5.2（fstab 两行加依赖与超时）和 4.5.6（dsh.service 加 RequiresMountsFor=/opt）。临时救急只要把 /opt 挂上再重启服务即可：

bash
systemctl reset-failed mnt-sd.mount opt.mount dsh
mount /opt
systemctl restart dsh

【踩坑记录】这个报错极易被误读

其实刚看到「Failed at step STDOUT … No such file or directory」时，第一反应会是「路径写错了」或「二进制的软链坏了」。实际上 dsh 的安装完全没有问题——把 /opt 挂上之后，ls -l /opt/npm-global/bin/dsh 立刻显示 -> ../lib/node_modules/@deepseek-ai/dsh/lib/bin.js，服务一次就起来了。所以遇到 209/STDOUT，先查挂载，别去重装 npm 包。

现象：active (running) 但浏览器连不上 #

分三步隔离：

bash
# step 1: can the board itself reach it
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.50:8080/

# step 2: is anything listening on the port
sudo ss -ltnp | grep 8080

# step 3: firewall
sudo ufw status
  • 第一步返回 401 → 服务正常，问题在网络路径（网线、IP、防火墙）
  • 第一步返回 000 而且第二步没输出 → 服务没在听，看 journalctl -u dsh -n 50
  • 第一步 401 但 Windows 连不上 → 防火墙或不在同一网段

现象：忘了 token，浏览器打不开 #

token 每次重启都变，从日志里捞：

bash
sudo grep -o 'http://[^ ]*token=[A-Za-z0-9_-]*' /opt/log/dsh-web.log | tail -1

如果日志被截断/轮转了，直接重启服务让它重新打一次：

bash
sudo systemctl restart dsh
sleep 3
sudo grep -o 'http://[^ ]*token=[A-Za-z0-9_-]*' /opt/log/dsh-web.log | tail -1

现象：重启后 IP 变了，服务起不来 #

--host 是写死的。IP 变了就绑不上，报 EADDRNOTAVAIL: address not available（包在 dsh: startup failed: 2 required plugins did not activate 里面）。

这就是为什么第 2.2 节强调必须配静态 IP。 如果你暂时只能 DHCP，两个办法：

  1. 在路由器上做 DHCP 静态绑定（按 MAC 固定分配 IP）—— 推荐，一次做好永久免疫
  2. 改 service 文件里的 --host，然后 sudo systemctl daemon-reload && sudo systemctl restart dsh

一键改 --host 的命令（自动读当前 IP）见 4.4.6 第 ④ 步。

现象：npm install 被杀，Killed #

OOM。做第 6 章加 swap/zram，然后重试。

现象：apt-get update 报 Release file ... is not valid yet #

板子时间不对。见 3.5 节的踩坑记录，用 sudo date -s 或 timedatectl set-ntp true。

现象：SSH 能连上但立刻断开 #

bash
sudo journalctl -u ssh -n 30 --no-pager

常见原因是 home 目录权限不对或者 authorized_keys 权限太开。但这块板是密码登录，一般不会遇到。

7.2 三板斧 #

任何奇怪问题，先跑这三条：

bash
# 1. service status
sudo systemctl status dsh --no-pager

# 2. service logs (last 50 lines)
sudo journalctl -u dsh -n 50 --no-pager

# 3. dsh own log (contains the token)
sudo tail -30 /opt/log/dsh-web.log

90% 的问题在第三条里就有答案。

8. 和手机方案的差异：哪些辛苦活没了 #

如果你之前跟着 DSH-部署说明.md 在手机上部署过，你会明显感觉到轻松。逐条对照：

手机上要处理的坑 板子上
Termux 的 sshd 被杀，重启后要手动 sshd ❌ 没有这回事，sshd 是系统服务
Termux:Boot APK + ~/.termux/boot/ 脚本 ❌ 没有，systemd 就是干这个的
termux-wake-lock + MIUI 省电策略白名单 ❌ 没有，Linux 不玩这套
锁屏后被 cgroup freezer 冻结（TCP 连上但零响应） ❌ 彻底消失。这是把服务从手机搬到板子的最大收益
proot 里 nohup 会被 --kill-on-exit 杀掉，必须用 tmux 持有 ❌ 没有，systemd 直接持有
要写 flock 单实例锁 ⚠️ 基本不需要（systemd 保证只有一个实例），但保留也无害
要写指数退避循环守护 ❌ 一行 Restart=always 替代
Termux 层没有 ip 命令，hostname -I 不支持 ❌ 标准 Linux，ip / hostname -I 都正常
Termux 层 /proc/net/tcp 读不了，查端口还得进容器 ❌ sudo ss -ltnp 直接看
容器里 pip3 指向 Termux 的、hostname -I 被劫持等各种路径污染 ❌ 不存在
每次换 WiFi 要重新探测 IP ❌ 静态 IP 配一次，不动
内存 7.3GB 但只能分给容器 2GB ✅ 板子 2GB 是独占的，不用分给谁
proot-distro login ubuntu -- /bin/bash -s 套娃 ❌ 直接就是 Ubuntu

唯一需要适应的：板子上没有 Termux，所有命令都在真 Linux 里跑，sudo 该加就加。

附录 A 一键安装脚本 #

这块板子的真实情况决定了脚本必须做三件事：① 根分区只有约 400MB，不先确认 /opt 已挂到 SD 卡上，npm install 必定 ENOSPC；② 板子出厂自带 Node v22.22.0，够用，不必再下 1.1GB；③ PC↔板子直连时出网要靠 PC 上的代理，Node 的 fetch 默认不读环境变量，必须 NODE_USE_ENV_PROXY=1。

使用前改三个变量：BOARD_IP（板子的静态 IP）、PROXY（PC 代理地址，没有就留空）、HEAP_MB（按内存，2GB 板用 1280）。保存成 install-dsh.sh，然后 sudo bash install-dsh.sh。

bash
#!/bin/bash
set -e

# ==================== EDIT HERE ====================
BOARD_IP="192.168.3.200"
PORT="8080"
DSH_VER="0.2.1-rc.3"
HEAP_MB="1280"
PROXY="http://192.168.3.100:7890"     # set to "" if the board can reach the internet directly
NPM_PREFIX="/opt/npm-global"
NPM_CACHE="/opt/npm-cache"
LOG_DIR="/opt/log"
# ===============================================

echo "=== 0. preflight ==="
[ "$(id -u)" = "0" ] || { echo "run me as root (sudo)"; exit 1; }
case "$(uname -m)" in
  aarch64|arm64) ;;
  *) echo "FATAL: need aarch64, got $(uname -m)"; exit 1 ;;
esac
echo "arch OK: $(uname -m)"

echo "=== 1. storage preflight (root fs is tiny) ==="
ROOT_AVAIL=$(df -Pm / | awk 'NR==2{print $4}')
echo "root fs available: ${ROOT_AVAIL} MB"
OPT_SRC=$(findmnt -no SOURCE /opt 2>/dev/null || echo "not-mounted")
echo "/opt source: ${OPT_SRC}"
OPT_AVAIL=$(df -Pm /opt | awk 'NR==2{print $4}')
echo "/opt available: ${OPT_AVAIL} MB"
if [ "$OPT_AVAIL" -lt 3000 ]; then
  echo "FATAL: /opt has less than 3 GB free."
  echo "       Node 24 (1.1G) + DSH (860M) + npm cache need about 2.5 GB."
  echo "       Mount the SD card on /opt first - see chapter 4.5."
  exit 1
fi
echo "storage OK"

echo "=== 2. check the board ip is really configured ==="
if ! ip -4 addr show | grep -q "inet ${BOARD_IP}/"; then
  echo "FATAL: ${BOARD_IP} is not configured on any interface right now."
  echo "       configure the ip first (see chapter 3.4 for OK3568, 4.4 for OK1028A)."
  ip -br a | grep -v DOWN || true
  exit 1
fi
echo "board ip OK: ${BOARD_IP}"

echo "=== 3. base packages ==="
if [ -n "$PROXY" ]; then
  export http_proxy="$PROXY" https_proxy="$PROXY"
  export HTTP_PROXY="$PROXY" HTTPS_PROXY="$PROXY"
  export NODE_USE_ENV_PROXY=1
  echo "using proxy: $PROXY"
fi
apt-get update
apt-get install -y ca-certificates curl wget xz-utils

echo "=== 4. pick a node runtime ==="
NODE_OK=0
if command -v node >/dev/null 2>&1; then
  CUR=$(node -v | sed "s/^v//" | cut -d. -f1)
  echo "found node $(node -v)"
  if [ "$CUR" -ge 22 ]; then
    NODE_OK=1
    echo "node >= 22, keep the distro package - saves 1.1 GB"
  fi
fi
if [ "$NODE_OK" != "1" ]; then
  NODE_VER="v24.21.0"
  NODE_DIR="/opt/node-${NODE_VER}-linux-arm64"
  if [ -x "${NODE_DIR}/bin/node" ]; then
    echo "node already extracted: $(${NODE_DIR}/bin/node -v)"
  else
    cd /tmp
    curl -L -O "https://nodejs.org/dist/${NODE_VER}/node-${NODE_VER}-linux-arm64.tar.xz"
    tar -xJf "node-${NODE_VER}-linux-arm64.tar.xz" -C /opt
    echo "node installed: $(${NODE_DIR}/bin/node -v)"
  fi
  cat > /etc/profile.d/98-node.sh <<EOF
export PATH=${NODE_DIR}/bin:\$PATH
EOF
  export PATH="${NODE_DIR}/bin:${PATH}"
fi

echo "=== 5. npm config (user level, never --global) ==="
mkdir -p "$NPM_PREFIX" "$NPM_CACHE" "$LOG_DIR"
cat > /root/.npmrc <<EOF
prefix=${NPM_PREFIX}
cache=${NPM_CACHE}
registry=https://registry.npmmirror.com/
EOF
if [ -n "$PROXY" ]; then
  cat >> /root/.npmrc <<EOF
proxy=${PROXY}
https-proxy=${PROXY}
EOF
fi
cat /root/.npmrc
echo "npm prefix: $(npm config get prefix)"

echo "=== 6. install dsh ${DSH_VER} ==="
if [ -x "${NPM_PREFIX}/bin/dsh" ]; then
  echo "dsh already present: $(${NPM_PREFIX}/bin/dsh --version)"
else
  npm install -g "@deepseek-ai/dsh@${DSH_VER}" --no-fund --no-audit
fi
${NPM_PREFIX}/bin/dsh --version

echo "=== 7. verify native modules (must cd into the package first) ==="
cd "${NPM_PREFIX}/lib/node_modules/@deepseek-ai/dsh"
node -e "require('node-pty'); require('koffi'); console.log('both native modules OK')"

echo "=== 8. install the systemd unit ==="
# only add RequiresMountsFor when /opt really is a separate mount
OPT_MOUNT_LINE=""
if [ "$(findmnt -no SOURCE /opt 2>/dev/null)" != "/dev/root" ] && [ -n "$(findmnt -no SOURCE /opt 2>/dev/null)" ]; then
  OPT_MOUNT_LINE="RequiresMountsFor=/opt"
fi

cat > /etc/systemd/system/dsh.service <<EOF
[Unit]
Description=DeepSeek Harness Web
After=network-online.target
${OPT_MOUNT_LINE}
Wants=network-online.target
StartLimitIntervalSec=0
StartLimitBurst=0

[Service]
Type=simple
WorkingDirectory=/root
Environment=PATH=${NPM_PREFIX}/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
Environment=NODE_OPTIONS=--max-old-space-size=${HEAP_MB}
Environment=NODE_USE_ENV_PROXY=1
Environment=http_proxy=${PROXY}
Environment=https_proxy=${PROXY}
Environment=no_proxy=localhost,127.0.0.1,192.168.3.0/24
ExecStart=${NPM_PREFIX}/bin/dsh web --host ${BOARD_IP} --port ${PORT} --no-open
Restart=always
RestartSec=5
StandardOutput=append:${LOG_DIR}/dsh-web.log
StandardError=append:${LOG_DIR}/dsh-web.log

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable dsh
systemctl restart dsh

echo "=== 9. wait for readiness (about 50s on this board) ==="
OK=0
for i in $(seq 1 45); do
  CODE=$(curl -s -o /dev/null -m 3 -w "%{http_code}" "http://${BOARD_IP}:${PORT}/" || echo 000)
  if [ "$CODE" = "401" ]; then
    OK=1
    echo "ready after $((i*2))s (http 401 is the expected answer)"
    break
  fi
  sleep 2
done

if [ "$OK" != "1" ]; then
  echo "FAIL: not ready after 90s"
  systemctl status dsh --no-pager || true
  journalctl -u dsh -n 40 --no-pager || true
  tail -30 "${LOG_DIR}/dsh-web.log" || true
  exit 1
fi

echo "=== 10. done ==="
systemctl is-enabled dsh
systemctl is-active dsh
echo ""
echo "verify the start limit keys really landed in the [Unit] section:"
systemctl show dsh -p StartLimitBurst -p StartLimitIntervalUSec -p Restart
echo ""
echo "storage + restart health (NRestarts should be 0):"
findmnt -no TARGET,SOURCE /opt || echo "/opt is not a separate mount"
systemctl show dsh -p NRestarts
echo ""
echo "open this url:"
grep -o "http://[^ ]*token=[A-Za-z0-9_-]*" "${LOG_DIR}/dsh-web.log" | tail -1

A.1 脚本要点 #

  1. set -e：任何一步失败立刻退出，不带着半成品往下走。
  2. 第 1 步是存储预检，不是可选项：这块板根分区只有约 400MB，/opt 没挂上 SD 卡就必然 ENOSPC。脚本在 /opt 余量低于 3GB 时直接退出并指向 4.5 节。
  3. 第 4 步优先用出厂自带的 Node：实测板子上已有 v22.22.0（/usr/bin/node），刚好满足 DSH 要求的 Node 22+，省掉 1.1GB 下载。只有低于 22 才回落到官方 arm64 二进制。
  4. /root/.npmrc 而不是 npm config set --global：系统 npm 的 prefix 是 /usr，--global 必写 /usr/etc 导致 EACCES（见 4.5.3）。
  5. NODE_USE_ENV_PROXY=1：Node 22 的 fetch 默认不读 http_proxy。PC↔板子直连时这是唯一能让「登录 DeepSeek 账号 / 调模型」工作的开关，漏了就只报一句 fetch failed（见 4.4.5）。
  6. 第 7 步必须 cd 进包目录：node-pty/koffi 是 DSH 的私有依赖，在任意目录跑 node -e "require('node-pty')" 都会报 Cannot find module——那是假错误。
  7. 就绪判据是 401 不是 200：根路径不带 token 本来就会返回 401，那恰恰说明服务活着。用 200 会永远等不到。
  8. 等待上限 90 秒：实测这块板上首次启动约 50 秒（45 秒时 ss -ltn 还看不到 8080）。
  9. 最后打印 StartLimitBurst / StartLimitIntervalUSec：这是唯一能证明「重启上限真的取消了」的办法；如果显示 5 和 10s，说明这两个键没落进 [Unit] 段。
  10. RequiresMountsFor=/opt 是自动判断的：脚本用 findmnt -no SOURCE /opt 看 /opt 是不是独立挂载（不是 /dev/root）。是就自动写进 [Unit] 段，否则留空——这样同一个脚本在 OK3568（/opt 就在根分区）和 OK1028A（/opt 是 SD 卡）上都能用。这条非常关键，见 4.5.2。
  11. 结尾打印 NRestarts：0 才说明一次就起来了；非 0 说明有东西在拖后腿，去 journalctl -b -u dsh 里找。

⚠️ 这个脚本会覆盖 /etc/systemd/system/dsh.service。如果你已经手写过一个配置好的 service，先 cp /etc/systemd/system/dsh.service /root/dsh.service.bak。

【踩坑记录】不要用 ping 判断板子是否在线

我们在排查手机时踩过：本机 ICMP 被策略拦截，ping 一律返回 PING: transmit failed，但设备其实活得好好的。

正确做法：用 Test-NetConnection -Port 测 TCP 端口，或者直接看串口。
