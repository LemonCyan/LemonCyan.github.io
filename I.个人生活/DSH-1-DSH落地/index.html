在安卓手机上用 Termux + proot-distro 部署 DeepSeek Harness（DSH）Web 服务 #

这份文档写给谁：有一台安卓手机、想在手机上跑起 DSH 并用局域网浏览器访问的人。 前提：不需要任何 Linux 基础。每一行命令都可以直接复制粘贴。 本文档对应的实测环境（你的设备可能略有差异，不影响流程）：

项目 实测值
手机型号 Xiaomi M2012K11C（Redmi K40）
Android 14（SDK 34）
CPU 架构 aarch64 / arm64
内存 7.3 GB（可用约 2.1 GB）
存储 226 GB（可用 207 GB）
Termux 0.118.3
proot-distro 5.10.3
Ubuntu 24.04.5 LTS (Noble Numbat)
Node.js v24.21.0 / npm 11.19.0
DSH 0.2.1-rc.3
最终占用 Node 目录 1.1 GB，其中 DSH 本体 859 MB

2026-11-11 更新：IP 变化自动恢复

原版守护脚本头注释写着 DHCP changes are tolerated，但实测从未兑现：dsh web 是前台阻塞调用，循环顶部的 detect_ip() 只有等 dsh 退出才会执行到；而手机换网段时 Node 进程不会退出，只是绑在一个已失效的 IP 上，于是 supervisor 永久卡死、lan-ip 留着旧值、服务再也不通。

本版为 start-web.sh 增加了 IP 看门狗（默认每 300 秒比对活跃 IP 与绑定记录，不一致就精确重启 dsh 重新绑定），允许绑定蜂窝地址（保住 @xmanrui/dsh-im 的 IM 通道），并同步修正日志时区、三个管理脚本的实时 IP 判断、开机钩子里的 sshd 行。涉及章节：10.2、10.4、10.5、10.6、12.1、12.3、12.4、13.3、13.5、15.2、附录 A / B / F / G。

第 0 章 先搞清楚要做什么 #

0.1 最终形态 #

我们要搭出来的东西长这样（从外到内）：

你的电脑 / 平板 / 手机浏览器
        │  http://<手机局域网IP>:8080
        ▼
┌─────────────────────────────────────────────┐
│ Android 系统                                 │
│  ┌───────────────────────────────────────┐  │
│  │ Termux（一个跑在安卓上的 Linux 终端）   │  │
│  │  ┌─────────────────────────────────┐  │  │
│  │  │ tmux 会话 "dshweb"（保持存活）   │  │  │
│  │  │  ┌───────────────────────────┐  │  │  │
│  │  │  │ proot Ubuntu 24.04 容器    │  │  │  │
│  │  │  │  ┌─────────────────────┐  │  │  │  │
│  │  │  │  │ start-web.sh 守护   │  │  │  │  │
│  │  │  │  │   └─ dsh web :8080  │  │  │  │  │
│  │  │  │  └─────────────────────┘  │  │  │  │
│  │  │  └───────────────────────────┘  │  │  │
│  │  └─────────────────────────────────┘  │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘

为什么套这么多层？

层 作用 为什么不省掉
Termux 安卓上的 Linux 环境 安卓本身跑不了 Node.js
proot Ubuntu 一个「假的」Ubuntu，不需要 root 刷机 Termux 用的是 Android 的 bionic libc，而 DSH 的依赖（尤其原生模块）是按 glibc 编译和测试的，直接在 Termux 里装大概率会撞上找不到 ld-linux-aarch64.so 之类的问题。套一层 Ubuntu 能用标准 glibc，省掉大量兼容性排查
tmux 会话保持 见第 11 章，这是整件事最关键的一个坑
start-web.sh 崩溃自动重启 服务可能因内存压力或系统策略被杀，有守护才能在无人值守时自愈

0.2 你需要准备什么 #

  1. 一台安卓 7.0 以上的手机，arm64 架构（2018 年后的手机基本都是）
  2. 至少 3 GB 可用存储空间（实测占 2 GB 左右）
  3. 手机和你的电脑连同一个 WiFi / 路由器
  4. 手机能上网（安装过程要下载约 500 MB）
  5. 一根数据线 + 一台电脑（第 3 章关闭幽灵进程杀手时要用，只需一次；如果嫌麻烦可以跳过，但要用守护脚本兜底）

0.3 预计耗时 #

阶段 耗时
装 Termux + 基础配置 10 分钟
装 Ubuntu 5～10 分钟
装 Node.js 3～5 分钟

0.4 一个重要的心理准备 #

手机上跑服务器，稳定性天生不如电脑。 本文档里出现的每一个「坑」，都是实测踩出来的，不是理论推演。请严格按顺序操作，不要跳步——特别是第 11 章（tmux），跳过了一定会失败；第 3 章是预防性加固，建议做但不是硬性必需。

第 1 章 安装 Termux（关键：不能用应用商店版本） #

1.1 为什么不能用 Google Play 的 Termux #

Google Play 上的 Termux 最后一次更新是 2020 年，版本停在 0.101。它：

  • 用的是老旧的软件源，pkg install 大量包会 404
  • 不支持 Android 11+ 的某些权限模型
  • 装不了新版 proot-distro

必须从 F-Droid 或 GitHub Releases 安装。

1.2 操作步骤 #

方式一：F-Droid（推荐，能自动更新）

  1. 手机浏览器打开 https://f-droid.org
  2. 下载并安装 F-Droid 客户端（首次安装需要在系统弹窗里允许「安装未知来源应用」）
  3. 打开 F-Droid，搜索 Termux
  4. 点进去，滑到最下面确认版本号是 0.118.x 或更高
  5. 点「安装」

方式二：GitHub Releases（不想装 F-Droid 就用这个）

  1. 手机浏览器打开 https://github.com/termux/termux-app/releases
  2. 找到最新的 release，下载文件名形如 termux-app_v0.118.3+github-debug_arm64-v8a.apk 的包
    • ⚠️ 认准 arm64-v8a，不要下 universal（体积大一倍）也不要下 armeabi-v7a（32 位，跑不了）
  3. 安装

1.3 安装后必须做的两件事 #

① 关闭电池优化

打开 Termux，但先别急着敲命令。回到系统设置：

  • 小米/红米：设置 → 应用设置 → 应用管理 → Termux → 省电策略 → 无限制
  • 华为：设置 → 电池 → 应用启动管理 → Termux → 手动管理，三个开关全开
  • 三星：设置 → 电池 → 后台使用限制 → 从「休眠应用」里移除 Termux
  • 原生安卓：设置 → 应用 → Termux → 电池 → 不受限制

② 允许后台运行

同上路径里，确认「允许后台活动」是开着的。

踩坑记录：不做这一步，手机息屏 10 分钟后 Termux 会被系统冻结，DSH 服务就断了。表现出来是「浏览器突然打不开了，但手机屏幕点亮一下又好了」——这是典型的被冻结，不是服务挂了。

1.4 验证 #

打开 Termux，你会看到一个黑色终端，提示符类似：

~ $

输入：

bash
echo $TERMUX_VERSION

预期输出（版本号可能更新）：

0.118.3

如果什么都没输出（空行），说明你装的是旧版或非官方版，请卸载重装。

踩坑记录：$TERMUX_VERSION 这个变量只有新版 Termux 才有。它是判断「装对了没有」最快的方法。

第 2 章 Termux 基础配置 #

2.1 更新软件源 #

在 Termux 里依次执行：

bash
pkg update -y

bash
pkg upgrade -y

预期：滚动输出大量包信息，最后回到提示符。

踩坑记录：pkg upgrade 过程中如果弹出类似这样的界面：

Configuration file '/data/data/com.termux/files/usr/etc/...'
 ==> File on system created by you or by a script.
 ==> What would you like to do?
    Y or I  : install the package maintainer's version
    N or O  : keep your currently-installed version

一路按 N 再回车（保留你现有的配置）。按 Y 会覆盖配置，可能把源改回默认的。

2.2 换成国内镜像源（强烈建议） #

Termux 默认源在国外，国内下载经常几十 KB/s 甚至超时。执行：

bash
sed -i 's@^\(deb.*stable main\)$@#\1\ndeb https://mirrors.ustc.edu.cn/termux/termux-main stable main@' $PREFIX/etc/apt/sources.list

bash
pkg update -y

验证：

bash
grep -v '^#' $PREFIX/etc/apt/sources.list | grep -v '^$'

预期看到：

deb https://mirrors.ustc.edu.cn/termux/termux-main stable main

踩坑记录：如果 pkg update 报错 Unable to locate package 或 404 Not Found，说明源地址失效了。这时可以换清华源：

bash
sed -i 's@mirrors.ustc.edu.cn@mirrors.tuna.tsinghua.edu.cn@g' $PREFIX/etc/apt/sources.list
pkg update -y

验证：

bash

踩坑记录：proot-distro 新版（5.x）不支持 --version 参数，敲了会报 Error: unknown option。查版本要用 dpkg -l proot-distro。这是文档容易踩的一个坑。

2.4 开启 SSH 服务（可选，但推荐） #

这样你就能在电脑上敲命令，不用一直低头看手机。

① 设置密码

bash
passwd

按提示输入两遍密码（输入时屏幕不显示字符，这是正常的）。本文实测用的是 liuluhua。

② 启动 sshd

bash
sshd

③ 查手机 IP

bash
ifconfig | grep "inet " | grep -v 127.0.0.1

预期类似：

        inet 192.168.3.247  netmask 255.255.255.0  broadcast 192.168.3.255

记下这个 IP（本文是 192.168.3.247），后面一直要用。

④ 从电脑测试

在电脑终端（Windows 用 PowerShell / CMD，Mac 用终端）：

bash
ssh -p 8022 <你的用户名>@192.168.3.247

踩坑记录：

  • Termux 的 SSH 端口固定是 8022（不是 22），因为 22 端口需要 root。
  • 用户名用 whoami 查，实测是 u0_a250 这种形式。
  • 但实测发现：用户名随便填也能登录。 Termux 的 sshd 没有严格的用户名校验，ssh -p 8022 root@192.168.3.247、甚至 ssh -p 8022 totally_fake_user@192.168.3.247 都能用同一个密码登进去，登进去后 whoami 一律是 u0_a250。所以用户名填错不是连不上的原因，连不上要从网络和密码方向查。
  • 第一次连接会问 Are you sure you want to continue connecting?，输入 yes 回车。
  • 如果连不上但手机能上网，大概率是路由器的「AP 隔离」功能（也叫「无线隔离」）。进路由器后台关掉它。这是最常见的连不上的原因。

第 3 章 应对安卓的「幽灵进程杀手」（强烈建议做，属预防措施） #

3.1 这是什么问题 #

Android 12（API 31）开始，系统引入了一个叫 phantom process killer（幽灵进程杀手） 的机制：应用的子进程数量超过上限（AOSP 默认 max_phantom_processes = 32）或总 CPU 占用过高时，系统会静默地把它们杀掉，不给任何提示。

Node.js 会开多个线程，proot 又会产生多个进程，很容易触发这个机制。

症状：DSH 启动成功，你能打开页面，但过一段时间突然就打不开了，日志里看到进程消失（退出码 137 = 128 + 9，即被 SIGKILL 杀掉），然后守护脚本重启，再过一会儿又挂。

诚实说明：本文的实测设备（Redmi K40 / Android 14）上，没有独立复现出「幽灵进程杀手」导致的死亡。日志里唯一一条 exited rc=137 是我们自己手动 pkill -9 做恢复测试造成的（23:57:21 那条，紧接着 backoff 从 5s 变成 10s，正是我们的测试序列）。

所以第 3 章属于预防性措施，不是「本文实测确认的必现故障」。但它是社区里 proot + Node 长期运行的头号已知问题，成本很低（一次 adb 命令），建议照做。如果你跳过这章，请务必用第 10 章的守护脚本兜底。

3.2 先确认你的设备有没有这个限制 #

不用连电脑也能先看一眼（在 Termux 里执行）：

bash
getprop ro.build.version.sdk
  • 输出 31 或更大 → Android 12+，有这个机制，建议做 3.3
  • 输出小于 31 → Android 11 及以下，没有这个机制，可以跳过本章

再查当前的上限值（有些 ROM 已经默认放开）。这一步需要电脑连 adb，先做完 3.3 的 ①～④ 步再回来执行：

bash
adb shell "device_config get activity_manager max_phantom_processes"
  • 输出 null 或一个很大的数（如 2147483647）→ 已经放开了，不用再改
  • 输出 32 或其它小数字 → 需要做 3.3 的第 ⑥ 步

3.3 解决步骤（需要电脑 + 数据线，只需一次） #

① 手机开启开发者选项

设置 → 关于手机 → 连续点击「MIUI 版本」（或「版本号」）7 次 → 提示「您已处于开发者模式」

② 开启 USB 调试

设置 → 更多设置 → 开发者选项 → 打开「USB 调试」

③ 手机连电脑，电脑装 adb

Windows 用户：下载 https://dl.google.com/android/repository/platform-tools-latest-windows.zip，解压到一个目录，在该目录打开 PowerShell。

④ 手机弹窗「允许 USB 调试吗？」，点「允许」

⑤ 执行命令

bash
adb devices

预期：

List of devices attached
a1b2c3d4        device

如果是 unauthorized，说明第 ④ 步没点，重新插拔数据线再点一次。

⑥ 关闭幽灵进程杀手

bash
adb shell "settings put global settings_enable_monitor_phantom_procs false"

bash
adb shell "device_config set_sync_disabled_for_tests persistent"

bash
adb shell "device_config put activity_manager max_phantom_processes 2147483647"

⑦ 验证

bash
adb shell "device_config get activity_manager max_phantom_processes"

预期输出：

2147483647

3.4 如果不方便用电脑 #

方案 A：靠守护脚本兜底

第 10 章的守护脚本会检测进程退出并自动重启。实测从进程被杀到服务恢复约 45～90 秒（退避等待 5～20 秒 + 约 35～45 秒 Node 冷启动）。能用，但会有几十秒的中断，建议还是把 3.3 做完。

方案 B：减少进程数（治标不治本）

在 start-web.sh 里已经有 NODE_OPTIONS=--max-old-space-size=2048 限制内存。不要再额外启动多个 DSH 实例，也不要同时跑别的 Node 程序。

踩坑记录：这个设置写进 device_config 后在手机重启后依然有效，但系统 OTA 升级后可能被重置。如果某天发现服务又开始频繁挂掉（日志里反复出现 exited rc=137 且不是你手动杀的），回来重新执行一次 3.3 的第 ⑥ 步。

第 4 章 安装 proot-distro 与 Ubuntu #

4.1 安装 Ubuntu 容器 #

在 Termux（不是 Ubuntu）里执行：

bash
proot-distro install ubuntu

预期：会下载约 30 MB 的镜像，然后解压出约 250 MB 的 rootfs。输出类似：

[*] Installing Ubuntu (ubuntu)...
[*] Downloading rootfs...
[*] Extracting rootfs...
[*] Configuring...
[*] Successfully installed Ubuntu (ubuntu)

踩坑记录：

  • 如果卡在 Downloading 很久不动，按 Ctrl+C 中断，然后换网络（比如手机开热点给手机自己用？不行——换个 WiFi）重试。proot-distro 支持断点续传，重跑同一条命令即可。
  • 如果报 Error: failed to install 且提到 not enough space，检查存储：df -h /data。
  • 如果报 Error: container already exists，说明之前装过，先 proot-distro remove ubuntu 再装。

4.2 验证安装 #

bash
proot-distro list

预期：


Installed containers:

  * ubuntu

Log in with: proot-distro login <name>

4.3 容器文件到底存在哪（重要） #

这是后面写脚本时必须知道的路径：

/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/
├── manifest.json          # 镜像元数据
├── rootfs/                # ← Ubuntu 的根文件系统，你的 / 就是这个
├── shm/
└── sysdata/

注意：新版 proot-distro（5.x）用的是 containers/ubuntu/rootfs，不是 老教程里的 installed-rootfs/ubuntu/。用老路径会找不到文件。

我们在 Termux 里引用容器内文件时，用这个变量最省事：

bash
ROOTFS=/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs

  • 内核版本显示 6.17.0-PRoot-Distro 是假的，是 proot 伪造的。真实内核是手机的 5.4.274-qgki。这不影响使用。
  • 退出容器：输入 exit 回车，回到 Termux 的 ~ $。
  • 重新进入容器后，之前在容器里 export 的变量、cd 到的目录都会丢失。这是正常的。

4.5 容器和 Termux 的共享关系 #

搞清这一点能省很多困惑：

路径 在 Termux 里 在 Ubuntu 里
/data/data/com.termux/files/home ~（Termux 家目录） /data/data/com.termux/files/home（可访问）
/sdcard 不存在（除非跑过 termux-setup-storage） 不存在
Termux 的 $PREFIX /data/data/com.termux/files/usr 可访问
Ubuntu 的 /root 只能通过 $ROOTFS/root 访问 ~（家目录）

关键结论：Ubuntu 容器没有挂载 /sdcard，所以容器里看不到你的照片、下载文件。这是 proot-distro 的默认行为。

第 9 章 理解 token 与 cookie 机制 #

这一章不操作，但一定要看，否则你会困惑「为什么重启后链接变了」。

9.1 三层认证 #

DSH 的 Web 认证分三层：

① 启动令牌（token）
   └─ 每次 dsh web 启动时随机生成，只存在于当前进程的内存里
   └─ 出现在启动日志的 URL 里：http://IP:8080/?token=xxx

② 浏览器 Cookie
   └─ 第一次带 ① 访问时，服务端校验通过后下发
   └─ 名字形如 dsh-auth-<随机串>，是 HttpOnly 的（JS 读不到，防 XSS）
   └─ 有效期约 30 天

③ 签名密钥
   └─ 存在 ~/.dsh/.credentials.yaml 的 client-connection/browser-session 记录里
   └─ 永久有效，除非你手动删这个文件

9.2 实际表现 #

场景 结果
首次带 token 访问 ✅ 200，同时下发 cookie
之后不带 token、但带 cookie 访问 ✅ 200（30 天内都有效）
不带 token 也不带 cookie ❌ 401
服务重启后，用旧 cookie 访问 ✅ 200（因为签名密钥没变）
服务重启后，用旧 token 访问 ❌ 401（token 变了）
删掉 ~/.dsh/.credentials.yaml 后重启 ❌ 所有旧 cookie 失效，要重新走 token

结论：你只需要在第一次访问时用一次 token，之后浏览器会记住 cookie，直接访问 http://IP:8080/ 就行。

9.3 拿到当前 token #

任何时候想知道当前的 token，执行（在 Termux 里）：

bash
grep -o 'http://[^ ]*token=[A-Za-z0-9_-]*' \
  /data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs/root/dsh-install/web.log \
  | tail -1

或者直接用第 12 章写的 dsh-status.sh。

第 10 章 编写守护脚本（自动重启 + 单实例） #

10.1 为什么需要守护脚本 #

直接在 tmux 里跑 dsh web 是不够的，实测会遇到三个问题：

问题 后果
Node 偶尔被系统杀掉（内存压力） 服务永久挂掉，要手动重启
你手贱又启动一次 第二个进程报 EADDRINUSE，然后两个进程互相干扰
之前遗留的「孤儿」进程还占着端口 新进程永远起不来，而且看不出来是谁占的

第三个问题是最坑的，我们实际遇到过：一个父进程是 1（已被 init 收养）的 supervisor 还在跑，pkill -f start-web.sh 杀不掉它（因为它的命令行里没有这个字符串），它一直在反复重启 dsh 并占着 8080。表现是「日志显示启动成功，但立刻又报端口占用」。

守护脚本要解决的就是这三个问题。

10.2 脚本设计要点 #

机制 解决什么
flock 文件锁 保证同时只有一个 supervisor 在跑，第二个直接退出
端口预检 启动前先探测端口，被占用就等待，等不到就强杀占用者
指数退避重启 崩溃后 5s → 10s → 20s → 40s → 60s 封顶，避免疯狂重启烧电
STOP 标志文件 优雅停止，避免 kill -9 导致状态不一致
自动探测 IP hostname -I 三级回退，取当前真实存在的地址（WiFi 优先，允许蜂窝）
IP 看门狗（默认 300s） 换 WiFi / 换网段 / 切到蜂窝后自动重新绑定，无需手动重启
ip-change.flag 因 IP 变化而重启时跳过指数退避，省下 5～60 秒
允许蜂窝地址 没有 WiFi 时 DSH 仍能启动，IM 插件可继续远程使用（此时 Web 不可达）
日志 TZ='CST-8' 容器内没有 zoneinfo 也能输出与手机一致的本地时间

10.4 写入守护脚本 #

在 Termux 里执行这一整段（一次性粘贴）：

bash
ROOTFS=/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs

cat > "$ROOTFS/root/start-web.sh" <<'EOS'
#!/bin/bash
# DSH Web supervisor.
#   * auto-detects the active IPv4, WiFi or cellular (network changes tolerated)
#   * single instance enforced with flock
#   * port preflight: waits, then kills a stale listener
#   * exponential backoff restart on crash (5s -> 60s)
#   * IP watchdog: re-checks every CHECK_EVERY seconds and rebinds on change
export PATH=/opt/node-v24.21.0-linux-arm64/bin:$PATH
export DSH_HOME=/root/.dsh
export NODE_OPTIONS=--max-old-space-size=2048
PORT=8080
DIR=/root/dsh-install
LOG=$DIR/web.log
DEFAULT_INTERVAL=300
mkdir -p "$DIR"
# The proot container has no zoneinfo files; a POSIX TZ string needs none.
log() { echo "[$(TZ='CST-8' date '+%F %T')] $*" >> "$LOG"; }

detect_ip() {
  local ip
  # Android denies /proc/net/dev, so `ifconfig <iface>` cannot be used here.
  # hostname -I lists every live IPv4: the first is the WiFi address when
  # WiFi is up, otherwise a cellular one. Cellular is allowed on purpose:
  # the dsh-im plugin only needs outbound connectivity.
  ip=$(hostname -I 2>/dev/null | tr ' ' '\n' | grep -E '^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$' | grep -v '^127\.' | head -1)
  [ -z "$ip" ] && ip=$(ifconfig 2>/dev/null | awk '/inet /{print $2}' | grep -v '^127\.' | head -1)
  [ -z "$ip" ] && ip=$(ip -4 addr 2>/dev/null | awk '/inet /{print $2}' | cut -d/ -f1 | grep -v '^127\.' | head -1)
  echo "$ip"
}

HOST=$(detect_ip)
if [ -z "$HOST" ]; then
  log "FATAL: no IPv4 address detected (no WiFi and no cellular?)"
  exit 1
fi
echo "$HOST" > "$DIR/lan-ip"
echo "$PORT" > "$DIR/lan-port"

exec 9>"$DIR/supervisor.lock"
if ! flock -n 9; then
  echo "another supervisor already holds the lock; exiting"
  exit 0
fi
echo $$ > "$DIR/supervisor.pid"
IV0=$(cat "$DIR/check-interval" 2>/dev/null)
case "$IV0" in ''|*[!0-9]*) IV0=$DEFAULT_INTERVAL ;; esac
log "=== supervisor started (pid $$) host=$HOST port=$PORT watchdog=${IV0}s ==="

port_busy() { timeout 3 bash -c "exec 3<>/dev/tcp/$HOST/$PORT" >/dev/null 2>&1; }

n=0
while port_busy; do
  n=$((n+1))
  if [ $n -le 8 ]; then
    log "port $PORT busy, waiting ($n)"
    sleep 2
  else
    log "port $PORT still busy; killing stale dsh"
    pkill -9 -f "bin/dsh web --host $HOST --port $PORT" 2>/dev/null
    sleep 3
    if port_busy; then log "FATAL: port $PORT still busy; aborting"; exit 1; fi
    break
  fi
done

# --- IP watchdog ---------------------------------------------------------
# Exactly one watchdog for the whole supervisor lifetime. State is passed
# through files in $DIR (a subshell cannot write back to this shell's vars).
# Only the recorded dsh.pid is signalled: never pkill -f, which can match
# the tmux server command line (see the deployment guide, ch.15).
watchdog() {
  local iv cur bound pid started now reason recent
  while true; do
    iv=$(cat "$DIR/check-interval" 2>/dev/null)
    case "$iv" in
      ''|*[!0-9]*) iv=$DEFAULT_INTERVAL ;;
    esac
    [ "$iv" -lt 5 ] && iv=5
    sleep "$iv"

    cur=$(detect_ip)
    [ -z "$cur" ] && continue
    bound=$(cat "$DIR/lan-ip" 2>/dev/null)
    pid=$(cat "$DIR/dsh.pid" 2>/dev/null)
    [ -z "$pid" ] && continue
    kill -0 "$pid" 2>/dev/null || continue

    reason=
    if [ "$cur" != "$bound" ]; then
      # Re-read lan-ip: the supervisor may have just rebound between our
      # two reads. Do not kill a freshly started dsh in that race.
      recent=$(cat "$DIR/lan-ip" 2>/dev/null)
      [ "$recent" = "$cur" ] && continue
      reason="active IP $bound -> $cur"
    else
      # Health probe: skip the 90s Node cold-start grace window.
      started=$(cat "$DIR/launch-ts" 2>/dev/null)
      case "$started" in ''|*[!0-9]*) started=0 ;; esac
      now=$(date +%s)
      [ $((now - started)) -lt 90 ] && continue
      if timeout 5 bash -c "exec 3<>/dev/tcp/$bound/$PORT" >/dev/null 2>&1; then continue; fi
      reason="health probe failed (no listener on $bound:$PORT)"
    fi

    log "watchdog: $reason; requesting rebind"
    : > "$DIR/ip-change.flag"
    kill "$pid" 2>/dev/null
  done
}
watchdog 9>&- &
WPID=$!
cleanup() {
  kill "$WPID" 2>/dev/null
  rm -f "$DIR/dsh.pid"
}
trap cleanup EXIT
trap 'cleanup; exit 143' TERM INT

backoff=5
while true; do
  if [ -f "$DIR/STOP" ]; then log "STOP flag found; exiting"; rm -f "$DIR/STOP"; break; fi
  if ! kill -0 "$WPID" 2>/dev/null; then
    log "WARN: watchdog died; restarting it"
    watchdog 9>&- &
    WPID=$!
  fi
  NEW=$(detect_ip)
  if [ -n "$NEW" ] && [ "$NEW" != "$HOST" ]; then
    log "active IP changed $HOST -> $NEW"
    HOST=$NEW
  fi
  # Republish unconditionally on every launch: lan-ip is the single source
  # of truth the watchdog compares against, and must match the real bind.
  echo "$HOST" > "$DIR/lan-ip"
  log "--- launching dsh web on $HOST:$PORT (backoff=${backoff}s) ---"
  date +%s > "$DIR/launch-ts"
  dsh web --host "$HOST" --port "$PORT" --no-open >> "$LOG" 2>&1 9>&- &
  DSH_PID=$!
  echo "$DSH_PID" > "$DIR/dsh.pid"
  wait "$DSH_PID"
  rc=$?
  rm -f "$DIR/dsh.pid"
  log "--- dsh web exited rc=$rc ---"
  if [ -f "$DIR/STOP" ]; then rm -f "$DIR/STOP"; log "stop requested; exiting"; break; fi
  if [ -f "$DIR/ip-change.flag" ]; then
    rm -f "$DIR/ip-change.flag"
    log "rebind: skipping backoff, reset to 5s"
    backoff=5
    continue
  fi
  sleep "$backoff"
  backoff=$(( backoff * 2 ))
  [ $backoff -gt 60 ] && backoff=60
done
log "=== supervisor exiting ==="
EOS

chmod 755 "$ROOTFS/root/start-web.sh"

10.6 各机制详解 #

① flock 单实例锁

bash
exec 9>"$DIR/supervisor.lock"
if ! flock -n 9; then
  echo "another supervisor already holds the lock; exiting"
  exit 0
fi
  • exec 9>文件 打开一个文件描述符 9 指向锁文件
  • flock -n 尝试非阻塞获取排他锁
  • 如果拿不到（说明已有实例在跑），直接退出
  • 锁在进程退出时自动释放，不需要手动清理

这个锁的妙处：即使有个孤儿进程占着端口，新的 supervisor 也会因为拿不到锁而干净退出，不会产生「两个 supervisor 互相打架」的局面。

② 端口预检

bash
port_busy() { timeout 3 bash -c "exec 3<>/dev/tcp/$HOST/$PORT" >/dev/null 2>&1; }

用 bash 内置的 /dev/tcp 做 TCP 连接测试，不依赖 ss 或 netstat（实测容器里 ss 根本没装；netstat 虽然能调到，但那是 Termux 的，不是容器自己的）。

  • 先等 8 次 × 2 秒 = 16 秒，给上一个进程留退出时间
  • 还占着就 pkill -9 强杀
  • 再不行就放弃并记录 FATAL

注意：这里的 $HOST 是局域网 IP（如 192.168.3.247），不是 127.0.0.1。DSH 没有监听回环地址，用 127.0.0.1 探测会永远得到「端口空闲」的错误结论。

③ 指数退避

bash
sleep "$backoff"
backoff=$(( backoff * 2 ))
[ $backoff -gt 60 ] && backoff=60

序列：5s → 10s → 20s → 40s → 60s → 60s → ...

为什么不固定 5 秒：如果 DSH 因为配置错误一直起不来，固定 5 秒会疯狂重启，手机发烫、电池狂掉。退避能让你有时间发现问题。

④ 自动探测 IP（WiFi 优先，允许蜂窝）

bash
ip=$(hostname -I ...)      # 容器内首选
ip=$(ifconfig ...)          # 回退方案
ip=$(ip -4 addr ...)        # 再回退

三级回退，因为不同系统上这三个命令的可用性不一样。实测容器里 hostname -I 和 ifconfig 都能用，ip 命令也有。

本次修正时实测出的两条约束：

  1. Android 拒绝读 /proc/net/dev，所以 ifconfig wlan0（按接口名定向）在 Termux 层和容器内都拿不到地址（Warning: cannot open /proc/net/dev (Permission denied). Limited output.）。只能依赖 hostname -I 的返回顺序：实测它把 WiFi 地址排在蜂窝地址前面，取 head -1 就等价于「有 WiFi 用 WiFi、只剩流量用蜂窝」。
  2. Termux 层的 ifconfig 顺序恰好相反（rmnet_data1 的 10.x 排在 wlan0 的 192.168.x 前面）。所以 12.1 的三个管理脚本里都定义了 active_ip()，显式跟踪接口名、强制 wlan0 优先，保证两层判断一致。早期改成裸 ifconfig | head -1 会让 dsh-start.sh 误报 TIMEOUT（服务其实已经起来了）。

允许蜂窝是有意为之：装上 @xmanrui/dsh-im 后，IM 插件只需要出站网络。绑在蜂窝地址时 Web 页面从任何地方都连不上（运营商 NAT），但 DSH 进程活着、IM 通道仍可远程使用；dsh-status.sh 会明确提示这一点。WiFi 恢复后看门狗会自动切回 Web 可达地址。

⑤ STOP 标志

dsh-stop.sh 会 touch STOP，守护脚本检测到就优雅退出。这样避免 kill -9 打断 DSH 正在写的数据。

⑥ IP 看门狗（2026-11-11 新增，解决「换 IP 后僵死」）

老版脚本的致命问题：dsh web ... 是前台阻塞调用，而循环顶部的 detect_ip() 要等 dsh 退出才会执行到下一轮。IP 从网卡上消失时 Linux 不会通知已绑定的 Node 进程，它不退出、socket 却再也收不到包 —— supervisor 永久停在 do_wait，日志里连一条 LAN IP changed 都不会有。脚本头注释写的「DHCP changes are tolerated」从未兑现；而且老版即便检测到了变化，也只是更新 HOST 变量，没有任何重绑动作。

新版做法：

  • dsh web 改为后台启动，PID 写进 dsh-install/dsh.pid
  • 脚本开头起唯一一个看门狗后台循环，每 check-interval 秒（默认 300）比对 detect_ip() 与 lan-ip
  • 不一致就 kill 记录的那一个 PID —— 绝不用 pkill -f，那会误伤 tmux server（见 15.2）
  • 同时写 ip-change.flag；supervisor 的 wait 返回后看到它，跳过指数退避、把 backoff 重置为 5，下一轮用新 IP 重启
  • 每轮启动前无条件重写 lan-ip，保证绑定记录与实际绑定一致
  • 顺带做一次 /dev/tcp 健康探测（启动后 90 秒宽限期内跳过），覆盖「IP 没变但 socket 僵死」
  • 完全无 IPv4 时跳过本轮，不 kill、不改写文件（避免飞行模式误杀）
  • 看门狗启动时 9>&- 关闭 flock 锁的 fd，避免 supervisor 退出后锁被孤儿进程持有；trap 在退出时清理看门狗

调整检测周期（下一轮循环自动生效，不用重启服务）：

bash
DIR=/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs/root/dsh-install
echo 60 > "$DIR/check-interval"     # 临时改成 60 秒
echo 300 > "$DIR/check-interval"    # 改回默认 5 分钟

文件不存在时脚本用内置默认值 300 秒。每轮只是一次 hostname -I + 读文件，功耗可忽略；沿用现有 termux-wake-lock，不新增唤醒锁、不新增 tmux 会话、不装新包。

实测验证（2026-11-11）：演练时把 check-interval 临时设为 10，再把 lan-ip 改写成假地址 192.0.2.99 模拟 IP 变化。10 秒后日志记录 watchdog: active IP 192.0.2.99 -> 192.168.43.7; requesting rebind，紧接着 rebind: skipping backoff, reset to 5s，48 秒后 HTTP 恢复 401，lan-ip 自动修回真实地址，没有反复重启。随后把间隔改回 300，状态脚本显示 watchdog : every 300s。

日志时区：容器里 /etc/localtime 和 /usr/share/zoneinfo 都不存在（5.5 的软链在实际环境里没有保留），所以 date 输出 UTC，日志比手机时间早 8 小时。改用 POSIX TZ 字符串 TZ='CST-8' date 即可，不需要装 tzdata（Termux 层和容器内都实测通过）。

第 11 章 用 tmux 让服务在 SSH 断开后继续活着 #

11.1 这是整个方案最关键的坑 #

现象：你在 SSH 里启动了服务，日志显示成功，浏览器也能打开。但你把 SSH 窗口一关（或者手机息屏、WiFi 断一下），服务就没了。

原因：proot-distro 启动容器时用了 --kill-on-exit 参数。这个参数的意思是：

当 proot 主进程退出时，杀掉容器内的所有进程。

而 proot 主进程是跟着你的 SSH 会话走的。SSH 一断，proot 退出，容器里所有进程（包括你 nohup 起来的）全部被杀。

nohup、setsid、disown 全部无效——因为杀的不是 shell 的子进程，是整个 proot 的进程树。

验证：你可以在容器里用 nohup dsh web ... & 启动，然后 exit 出容器，再 proot-distro login 进去 ps aux | grep dsh，会发现进程不见了。

11.2 解决方案：tmux 持有整个 proot 进程树 #

思路：不要直接 proot-distro login，而是让 tmux 去启动它。 这样 proot 的父进程是 tmux，tmux 又是由 Android 的 Termux 守护的，SSH 断开不影响。

SSH 会话 ──断开──> ✗ 不影响
                      │
tmux server（Termux 层，独立进程）
  └─ tmux 会话 "dshweb"
      └─ proot-distro login ubuntu
          └─ /bin/bash /root/start-web.sh
              └─ dsh web

  • -s dshweb = 会话名叫 dshweb

第 12 章 编写 start / stop / status 三个管理脚本 #

每次都手敲 tmux new-session ... 太麻烦，而且容易出错。封装成三个脚本。

12.1 写入脚本 #

在 Termux 里执行这一整段：

bash
cat > /data/data/com.termux/files/home/dsh-start.sh <<'EOS'
#!/data/data/com.termux/files/usr/bin/bash
ROOTFS=/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs
DIR="$ROOTFS/root/dsh-install"
termux-wake-lock 2>/dev/null

# Android lists the cellular interface BEFORE wlan0 in ifconfig output,
# while the container's hostname -I lists WiFi first. Track the interface
# name so both layers agree on which address is the active one.
active_ip() {
  ifconfig 2>/dev/null | awk '
    /^[a-zA-Z0-9_]+:/ { i=$1; sub(/:$/, "", i) }
    /inet / {
      ip=$2
      if (ip ~ /^[0-9]+\./ && ip !~ /^127\./) {
        if (i == "wlan0") w=ip
        else if (f == "") f=ip
      }
    }
    END { print (w != "" ? w : f) }
  '
}

# --- make sure sshd is listening too (needed after a reboot or after Android reclaims it) ---
if pgrep -x sshd >/dev/null 2>&1; then
  echo "sshd       : already running"
else
  if sshd 2>/dev/null; then echo "sshd       : started"; else echo "sshd       : FAILED to start"; fi

13.1 开机自启能解决什么问题 #

不装 Termux:Boot 时，手机重启后你有两个服务都是关着的：

服务 作用 不开的后果
sshd 让你能从电脑 SSH 连进来 电脑连 8022 直接 Connection refused
DSH Web 网页界面 浏览器打不开 8080

所以只拉起 DSH 是不够的——重启后你连 SSH 都进不去，根本没法手动敲命令。本章的启动钩子会把两个都拉起来。

⚠️ 本文实测踩到的第一个坑就在这：最初版本的 dsh-start.sh 只启 DSH、不启 sshd。真机上 grep sshd ~/dsh-start.sh 的计数是 0，意味着按那个版本配置的开机自启，重启之后 SSH 依然连不上，而人还在外面、只能干瞪眼。已加守卫修好：

bash
if pgrep -x sshd >/dev/null 2>&1; then
  echo "sshd       : already running"
else
  if sshd 2>/dev/null; then echo "sshd       : started"; else echo "sshd       : FAILED to start"; fi
fi

为什么用 pgrep -x sshd 而不用 pgrep -f sshd：sshd -D 会 fork 出 /libexec/sshd-session -R 子进程，-f 会把它们也算进去，导致判断「已经在跑」而实际主进程没了。-x 只按进程名精确匹配，实测只命中主进程 pid。

13.2 没装 Termux:Boot 时的临时手动启动 #

如果还没装 Termux:Boot，或者刚重启完等不及，手机上进 Termux 敲两条命令（顺序别反）：

bash
sshd                    # ① 先把 SSH 服务拉起来
bash ~/dsh-start.sh     # ② 再拉起 DSH Web（脚本本身也会补一次 sshd）

实测记录（重要）：

本文实测过程中，设备从 192.168.3.247 换到热点网段 192.168.43.22 之后，出现了全端口 Connection refused 的状态——从电脑上扫 22/80/443/8022/8080/5555/9000 全部被拒绝。

这个现象很容易误判。它不是「手机掉线了」，也不是「IP 填错了」，而是 sshd 和 DSH 两个进程都已经被安卓系统回收了，机器上没有任何东西在监听。

区分方法：

现象 含义
连接 超时 / TIMEOUT / 无响应 对方不在线，或者被防火墙丢包
连接 被拒绝 / Connection refused 设备在线且能回包，但那个端口没有程序在监听

换句话说，refused 反而说明网络是通的。看到 refused，去手机上开 Termux 敲 sshd 就对了。

顺便一个佐证：真机上 pgrep -af sshd 只能看到 sshd 主进程和两个 sshd-session，说明 SSH 是按需 fork 的，主进程被杀 = 再也连不上。

另外，用 ping 判断「手机在不在线」在这台机器上不可靠：本机 PowerShell 的 ping 被安全策略拦掉，一律返回 PING: transmit failed，此时手机其实好好地在线。判断在线/离线请用端口探测，不要用 ping。

③ 创建启动钩子

在 Termux 里执行：

bash

bash
cat > ~/.termux/boot/start-dsh.sh <<'EOS'
#!/data/data/com.termux/files/usr/bin/sh
# Termux:Boot hook - runs automatically after the device boots.
# Requires the Termux:Boot addon app (see the deployment guide, chapter 13).
LOG=/data/data/com.termux/files/home/dsh-boot.log

termux-wake-lock 2>/dev/null

sshd

# Wait for a LAN IPv4 to appear (max 60s). Termux's toybox has no
# `ip` command and its `hostname` has no -I option, so use ifconfig.
i=0
IP=
while [ $i -lt 30 ]; do
  IP=$(ifconfig 2>/dev/null | grep "inet " | grep -v 127.0.0.1 | awk '{print $2}' | head -1)
  [ -n "$IP" ] && break
  sleep 2
  i=$((i+1))
done
echo "[$(date)] boot hook: network ip=${IP:-none} after $((i*2))s" >> "$LOG"

sleep 10
bash /data/data/com.termux/files/home/dsh-start.sh >> "$LOG" 2>&1
echo "[$(date)] boot hook: done rc=$?" >> "$LOG"
EOS

chmod 755 ~/.termux/boot/start-dsh.sh
sh -n ~/.termux/boot/start-dsh.sh && echo "syntax OK"

这段钩子做了什么（逐行解释，别跳）：

语句 为什么必须有
termux-wake-lock 拿住唤醒锁，防止息屏后 CPU 休眠把进程挂起
sshd 真机版本多出的这一行：开机后直接把 SSH 拉起来，不必等 dsh-start.sh。和 dsh-start.sh 里的 pgrep -x sshd 守卫构成双保险（已在 2026-11-11 同步进文档）
等 IPv4 的 while 循环（最多 60s） 开机瞬间网络还没起来，此时 dsh-start.sh 探测到的 IP 是空的，会启动失败。必须等网络就绪再启动
用 ifconfig 而不是 ip Termux 的 toybox 没有 ip 命令（实测 ip: command not found）；hostname -I 也不支持（实测 hostname: invalid option -- 'I'）
sleep 10 即使拿到 IP，系统服务（DNS、proot 挂载点）也还要几秒才稳定
日志双保险 boot hook: network ip=... after Ns 证明「网络是否等到」；boot hook: done rc=... 证明「dsh-start.sh 是否跑完」，排查时一眼定位卡在哪一步

13.5 完整开机演练（决定性验证） #

sh ~/.termux/boot/start-dsh.sh 只能证明「脚本能跑」，不能证明「手机上真的开机时它会跑」。完整的演练要做成「把所有东西拆掉 → 只运行钩子 → 看能否全自动恢复」。

⚠️ 这一步必须放在 tmux 里做，因为拆的过程中会杀掉 sshd，你当前的 SSH 会话会当场断开。如果直接在 SSH 里敲，命令做到一半连接就断了，永远看不到结果。

① 在 Termux 里创建演练脚本

bash
cat > "$PREFIX/tmp/bootsim.sh" <<'EOS'
#!/data/data/com.termux/files/usr/bin/bash
L="$PREFIX/tmp/bootsim.log"
: > "$L"
echo "[$(date '+%T')] step0: wait 30s so the calling SSH session is gone" >> "$L"
sleep 30

echo "[$(date '+%T')] step1: kill dsh by explicit PID" >> "$L"
for p in $(pgrep -f '/root/start-web.sh') $(pgrep -f 'bin/dsh web --host'); do
  cl=$(tr '\0' ' ' < /proc/$p/cmdline 2>/dev/null)
  case "$cl" in
    tmux*) echo "[$(date '+%T')]   SKIP tmux server pid=$p" >> "$L";;
    *)     echo "[$(date '+%T')]   kill pid=$p" >> "$L"; kill -9 "$p" 2>/dev/null;;
  esac
done
sleep 3

echo "[$(date '+%T')] step2: tmux kill-session -t dshweb" >> "$L"
tmux kill-session -t dshweb 2>/dev/null
sleep 2
echo "[$(date '+%T')] step3: teardown -> dsh=$(pgrep -f 'bin/dsh web --host' | wc -l) startweb=$(pgrep -f '/root/start-web.sh' | wc -l) sshd=$(pgrep -x sshd | wc -l) tmux=$(tmux ls 2>/dev/null | wc -l)" >> "$L"

echo "[$(date '+%T')] step4: kill sshd too" >> "$L"
pkill -x sshd 2>/dev/null
sleep 4
echo "[$(date '+%T')] step5: sshd now = $(pgrep -x sshd | wc -l)" >> "$L"

echo "[$(date '+%T')] step6: run the Termux:Boot hook exactly as boot would" >> "$L"
sh "$HOME/.termux/boot/start-dsh.sh"
echo "[$(date '+%T')] step7: hook returned rc=$?" >> "$L"

sleep 3

echo "[$(date '+%T')] step9: wait for HTTP (max 120s)" >> "$L"
for i in $(seq 1 60); do

  if [ "$code" = "401" ] || [ "$code" = "200" ]; then
    echo "[$(date '+%T')] step10: HTTP OK ($code) after ~$((i*2))s -> BOOT AUTOSTART WORKS" >> "$L"
    break
  fi
  sleep 2
done

echo "[$(date '+%T')] DONE" >> "$L"
EOS

踩坑记录（这条坑值得单独看）：

第一次写这个演练脚本时，拆服务用的是 pkill -9 -f "proot-distro login ubuntu"，结果演练脚本自己被杀掉了，日志只写到 before: dsh_scripts=3 dsh=1 sshd=1 就没了，dsh-boot.log 根本没生成，一度误以为「开机钩子不生效」。

2026-11-11 补充：真机断电重启仍未验证过

上面的 bootsim 是「杀进程后手动跑钩子」的模拟，不是真的给手机断电重启。真机上可以确认的是：com.termux.boot 已安装且被打开过（shared_prefs 存在，广播接收器已注册）、~/.termux/boot/start-dsh.sh 含裸 sshd 行、dsh-boot.sh 内部还有一层 sshd 守卫、dsh-boot.log 留有 done rc=0 —— 逻辑链路是完整的，重启后不需要手动启动 dsh。

唯一命令行查不到的变量是小米的自启动白名单（见 13.3 的 SecurityException），只能到系统设置里肉眼确认 Termux 与 Termux:Boot 都在白名单里。建议升级完做一次真重启演练：重启手机 → 等约 2 分钟 → 从电脑 ssh -p 8022 连进去 → bash ~/dsh-status.sh。

有了 IP 看门狗之后，开机链路反而更健壮：开机瞬间 WiFi 还没连上时，DSH 会先绑蜂窝地址启动（IM 可用），WiFi 一连上，看门狗在下一次轮询自动切到 Web 可达地址。老版会在开局绑错地址后永远不纠正。

15.1 诊断三板斧 #

遇到任何问题，先按顺序跑这三条：

bash ~/dsh-status.sh

② 看日志尾部

15.2 按现象查 #

现象：dsh-status.sh 显示 http: UNREACHABLE #

排查顺序：

  1. 进程在不在？

    bash
    pgrep -af "bin/dsh web"
    • 没有 → 看日志为什么没起来
    • 有 → 继续

  2. 端口对不对？

    ⚠️ $ROOTFS 这个变量只在你手动 export 过的那个 shell 里有效，新开的终端里是空的。所以下面用的是完整路径：

    bash
    cat /data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs/root/dsh-install/lan-ip

    如果这个 IP 和你手机现在的 IP 不一样（换了 WiFi / 路由器重新分配）：

    首选：什么都不做，等最多 5 分钟。看门狗会比对 active IP 与 bound IP，自动 kill 旧进程并用新 IP 重启（详见 10.6 ⑥ 和「换了 WiFi / 手机 IP 变了」一节）。dsh-status.sh 此时会显示 -> MISMATCH: rebind pending (within 300s)。

    等不及就手动重启（脚本会重新探测，不用改任何文件）：

    bash
    bash ~/dsh-stop.sh && bash ~/dsh-start.sh

    ⚠️ 不要再手动往 lan-ip 里写 IP。2026-11-11 起这个文件是看门狗判定「是否需要重绑」的依据，手写一个不对的值会被当成 IP 变化，白白触发一次重启。（确实需要模拟 IP 变化做演练时才可以这么写，见 10.6 ⑥ 的实测记录。）

  3. 手机本地能不能访问？

    ⚠️ 不要用 127.0.0.1 测。DSH 绑的是具体的局域网 IP（--host 192.168.3.247），没有监听回环地址，所以 curl http://127.0.0.1:8080/ 一定返回 Connection refused（实测确认）。这个现象是正常的，不代表服务挂了。

    要用绑定地址本身测：

    bash
    curl -s -o /dev/null -w "%{http_code}\n" http://192.168.3.247:8080/
    • 返回 401 或 200 → 服务正常，问题在电脑到手机的网络上（AP 隔离 / 防火墙）
    • 返回 000 → 服务真的没起来，回去看日志

现象：三个状态都 RUNNING，但端口从电脑上连不上 #

这是一个很坑的状态，本文实测真实遇到过：

======== DSH Web status ========
active IP  : 192.168.43.7
bound IP   : 192.168.43.7
watchdog   : every 300s
supervisor : RUNNING
dsh process: RUNNING
http       : UNREACHABLE on 192.168.43.7
             (cellular-only? Web is behind carrier NAT, IM still works)

三个条件同时成立：tmux 会话在、node .../dsh web 进程在、ps 也能看到它占着 CPU（State: R、Threads: 11），但端口根本没人监听——从电脑 Test-NetConnection ... -Port 8080 返回 False，手机上 /dev/tcp/192.168.43.22/8080 直接 Connection refused。

上面输出里的 cellular-only? 是状态脚本在 UNREACHABLE 时的固定提示文案；本节的实际原因不是蜂窝网络，别被这行带偏。

怎么确认「进程在但没监听」：

bash
proot-distro login ubuntu -- /bin/bash -c "grep -i ':1F90' /proc/net/tcp /proc/net/tcp6 || echo 'no socket on 8080'"

1F90 是 8080 的十六进制。如果输出 no socket on 8080，就说明内核里根本没有这个监听套接字，进程虽然活着却是空壳。

踩坑记录（三个反直觉点）：

  1. 进程存在 ≠ 端口在听。pgrep、tmux has-session、ps 都正常，dsh-status.sh 也会报 dsh process: RUNNING，但连接就是 refused。别因为「进程在」就断定服务没问题。

  2. 在 Termux 层查不到监听状态。/proc/net/tcp 和 /proc/net/tcp6 在 Termux 里都是 Permission denied（安卓的 /proc 做了限制），/proc/<pid>/net/tcp 也一样被拒；Termux 又没有 ss/netstat/lsof。所以查端口必须进 Ubuntu 容器用 grep /proc/net/tcp，或直接用 /dev/tcp 探测连通性。

  3. 这种状态重启就好，别去改配置。本文实测 bash ~/dsh-stop.sh && bash ~/dsh-start.sh 之后立刻恢复：8080 free → Ready after 52s → http: OK (401)，从 Windows 访问 8080 从 000 变为 401。原因是 proot 里 node 的某个子进程/socket 在安卓回收内存时被掐断而主进程没死透。

    2026-11-11 起不再是「只能手动重启」：看门狗每轮检测（默认 300s）在 IP 没变化时还会对绑定地址做一次 /dev/tcp 健康探测，探测不到就按 dsh.pid 精确 kill 并重绑 —— 最多 5 分钟检测延迟 + 一次约 45 秒冷启动即自动恢复。启动后 90 秒的宽限期保证不会把正常冷启动误判成僵死。等不及仍可手动重启。

如果 dsh-status.sh 报 UNREACHABLE 且进程也在跑：先看 active IP 与 bound IP 是否一致、以及 watchdog 周期；不赶时间就等一个周期让看门狗自己重绑，等不及就直接：

bash
bash ~/dsh-stop.sh && bash ~/dsh-start.sh

若重启后仍是 UNREACHABLE，再按上一节的「端口对不对 / 手机本地能不能访问」继续查。

现象：pkill 把 tmux 自己也杀了（服务莫名其妙整个消失） #

症状：执行完一条 pkill -f "..." 之后，tmux ls 报 no server running，所有会话都没了，dsh-boot.log 也没生成。

原因：tmux 的服务端进程在 /proc/PID/cmdline 里原样保留着创建会话时的整串命令，例如：

tmux new-session -d -s dshweb proot-distro login ubuntu -- /bin/bash /root/start-web.sh

所以 pkill -f "proot-distro login ubuntu"、pkill -f "start-web.sh" 这类宽匹配既命中真正的目标，也命中 tmux server 本身，连人带环境一起打死。

正确做法：遍历 pgrep -f 的结果，读 /proc/$p/cmdline 排除 tmux*，再按 PID 精确杀：

bash
for p in $(pgrep -f 'bin/dsh web --host'); do
  cl=$(tr '\0' ' ' < /proc/$p/cmdline 2>/dev/null)
  case "$cl" in
    tmux*) echo "SKIP tmux pid=$p";;
    *)     kill -9 "$p";;
  esac
done

dsh-stop.sh 里之所以杀的是 "root/start-web.sh" 这种带路径前缀的模式、并且先 tmux kill-session 再 pkill，就是为了绕开这个坑。

现象：换了 WiFi / 手机 IP 变了，网页打不开了 #

2026-11-11 起这一节的行为已变：新版 start-web.sh 带 IP 看门狗，默认 5 分钟内自动恢复，一般不再需要手动重启。下面先讲原理，再给手动兜底。

为什么会「进程活着但服务死了」：dsh web --host 192.168.x.x 绑的是具体地址（DSH 不允许 0.0.0.0，见 8.2）。手机换网段后旧地址从网卡上消失，Linux 不会通知已绑定的 Node 进程 —— 它既不崩溃也不退出，socket 却再也收不到包。

老版脚本还有个致命缺陷：dsh web 是前台阻塞调用，循环顶部的 detect_ip() 只有等 dsh 退出才会执行，而它偏偏不退出。2026-11-11 实测记录：手机已从 192.168.3.254 切到 192.168.43.7，DSH 进程（PID 10661）仍活着、命令行还绑着旧地址，supervisor 卡在 do_wait 14 小时，lan-ip 留着旧值，日志里 LAN IP changed 出现 0 次，从手机本地和电脑侧 curl 8080 全部 000，而 dsh-status.sh 显示 supervisor RUNNING / dsh RUNNING / http UNREACHABLE。

现在的处理方式 —— 等 5 分钟即可

看门狗每 300 秒比对一次活跃 IP 与 lan-ip；不一致就精确 kill 记录在 dsh.pid 里的那一个 dsh 进程，supervisor 跳过指数退避、用新 IP 重启，约 45～60 秒后恢复（绝大部分是 Node 冷启动）。等待期间 bash ~/dsh-status.sh 会这样显示：

active IP  : 192.168.43.7
bound IP   : 192.168.3.254
watchdog   : every 300s
             -> MISMATCH: rebind pending (within 300s)

等不及 / 想立刻恢复：手动重启仍然有效，也仍然不用改任何配置：

bash
bash ~/dsh-stop.sh && bash ~/dsh-start.sh

确认看门狗或重启确实生效：

bash
grep -E "watchdog:|active IP changed|rebind:" \
  /data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs/root/dsh-install/web.log | tail -10

临时缩短等待（下一轮自动生效，不用重启服务）：

bash
DIR=/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs/root/dsh-install
echo 60 > "$DIR/check-interval"     # 临时 60 秒
echo 300 > "$DIR/check-interval"    # 改回默认 5 分钟

只有蜂窝网络时：DSH 会绑 10.x 蜂窝地址正常启动，IM 通道可用，但 Web 从任何地方都访问不到（运营商 NAT）。状态脚本在 UNREACHABLE 时会提示 cellular-only? Web is behind carrier NAT, IM still works。WiFi 恢复后看门狗自动切回。

怎么查现在的 IP（在 Ubuntu 容器里）：

bash
hostname -I | tr ' ' '\n' | grep -E '^[0-9]+\.'

或者直接看脚本记录的值：

bash
cat /data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs/root/dsh-install/lan-ip

⚠️ 提示：如果换了网络后 sshd 也连不上（Connection refused），说明 Termux 本身被系统回收了，得先到手机上 sshd —— 见下面「SSH 报 Connection refused」一节。

现象：日志里有 EADDRINUSE #

Error: listen EADDRINUSE: address already in use 192.168.3.247:8080
dsh: startup failed: 2 required plugins did not activate

原因：有另一个进程占着 8080。

解决：

bash
bash ~/dsh-stop.sh

如果 dsh-stop.sh 之后端口还是被占，说明有孤儿进程（父进程是 1，pkill 杀不到）。手动找：

bash
ps -eo pid,ppid,args | grep -E "proot|dsh" | grep -v grep

找到那个 proot ... /bin/bash /root/start-web.sh 的进程，记下 PID，然后：

bash
kill -9 <PID>

踩坑记录：我们实际遇到过这个。一个 ppid=1 的 proot 进程一直在跑，它的命令行里不含 start-web.sh（只有 proot --kill-on-exit ... /bin/bash -c /bin/bash /root/start-web.sh），所以 pkill -f "start-web.sh" 匹配不到。必须用 pkill -9 -f "root/start-web.sh"（注意前面加 root/）才能匹配。第 10 章的 flock 锁就是为了从根上避免这个局面。

现象：服务起来几分钟后就挂了，反复如此 #

原因：可能是安卓的幽灵进程杀手（第 3 章），也可能是手机内存不足（OOM killer）。

确认：日志里看到 exited rc=137（137 = 128 + 9，被 SIGKILL 杀掉）。

⚠️ 先排除一种情况：如果你刚才手动跑过 pkill -9 -f "bin/dsh web" 做恢复测试，那条 rc=137 是你自己造成的，不是系统杀的。看时间戳能不能对上。

  1. 如果是系统杀的 → 回到第 3 章，用 adb 关闭幽灵进程杀手

  3. 实在查不出 → 靠第 10 章的守护脚本兜底（45～90 秒自动恢复，详见 12.3 的实测表）

现象：安装插件时报 dsh: pnpm was not found #

完整报错：

dsh: pnpm was not found; install pnpm and make it available on PATH.

原因：DSH 本体不带包管理器。dsh plugin 只是把「装插件」这件事转交给外部的 pnpm 去做，而 pnpm 是按 PATH 去找的。第 6 章装的是 Node 官方压缩包，里面只有 npm，没有 pnpm。

为什么是 @11 而不是最新版：

  1. pnpm 12 起改成了「原生二进制 + 安装时跑 install.js 下载对应平台的 exe」。而这台机器的 npm 按默认策略不执行依赖的 install 脚本（npm warn allow-scripts ... install scripts that were not run），很可能装出一个没有真正二进制的空壳，跑起来报错。
  2. pnpm 11 是纯 JS 实现（bin/pnpm.mjs），装完直接可用，不依赖 install 脚本。
  3. 本文实测的 DSH 版本对 pnpm 11 的行为是验证过的。

验证：

11.x.x

现象：SSH 报 Connection refused / 网页也打不开（重点） #

这是本文实测真实遇到过的场景，比超时更常见，也更容易误判成「设备离线」。

关键区别——看错这两个词会走很多弯路：

报错 含义 该往哪查
Connection timed out 包发出去没人应，设备可能不在线 / 被防火墙丢包 网络层：IP、同一 WiFi、AP 隔离
Connection refused 设备收到了包并主动回了 RST，说明网络完全正常，只是那个端口没有程序在监听 应用层：服务进程没起来

所以看到 refused 是好消息：手机在线、网络通、IP 也没填错，纯粹是 sshd 没跑。

快速判定：从电脑上扫几个端口，如果全部都 refused，那 100% 是「机器活着但没服务」：

powershell
# Windows PowerShell 里跑
22,80,443,8022,8080 | ForEach-Object {
  $c = Test-NetConnection 192.168.3.247 -Port $_ -InformationLevel Quiet -WarningAction SilentlyContinue
  "$_ => $c"
}

全部 False + 手机 ARP 表里能看到 MAC 地址（arp -a | findstr 192.168.3.247）→ 确定是进程没了。

解决：在手机 Termux 里跑两条：

bash
sshd
bash ~/dsh-start.sh

踩坑记录：本文实测设备换网段后（192.168.3.247 → 192.168.43.22），从电脑扫 22/80/443/8022/8080/5555/9000 全部 Connection refused，连续重试 10 次（间隔 5 秒）全是 refused。当时一度怀疑是扫描器把「不可达」误报成了「拒绝」，于是做了对照实验：扫描同网段不存在的 192.168.43.99 和外部不存在的 10.99.99.99，两者都是 TIMEOUT 而不是 REFUSED——这才确认 refused 是设备真的回了 RST，即「设备活着、没服务」。执行 sshd 后 8022 立刻变成 OPEN（235 ms）。

另一个容易踩的坑：ping 在这台电脑上被策略拦截（报 PING: transmit failed），ping 不通不能作为「设备离线」的证据，必须用 TCP 端口探测。

现象：SSH 能连但经常超时、连三次成一次 #

这是本文实测遇到的真实情况，不是你的问题。手机端的 sshd 在 proot 环境下响应慢，banner 交换经常超时。

解决：写个重试循环（见附录 C 的 ssh-dev.ps1），或者直接用手机上的 Termux 操作。

A.1 start-web.sh（容器内守护脚本） #

见第 10.4 节。要点回顾：

  • flock -n 9 单实例锁（看门狗与 dsh 都主动关闭 fd 9）
  • detect_ip() 三级 IP 探测，WiFi 优先、允许蜂窝
  • IP 看门狗：默认 300s 比对 lan-ip，不一致则按 dsh.pid 精确 kill 并重绑（见 10.6 ⑥）
  • dsh web 后台启动 + wait，ip-change.flag 让重绑跳过退避
  • port_busy() 用 /dev/tcp 探测端口；看门狗还做健康探测（90s 宽限）
  • 指数退避 5→60 秒；STOP 标志优雅退出
  • log() 用 TZ='CST-8' date，无需 tzdata 即输出手机本地时间

A.2 ~/dsh-start.sh（Termux 层启动） #

见第 12.1 节。要点：

  • termux-wake-lock 防止 CPU 休眠
  • 先确保 sshd 在跑（开机 / 被系统回收后的兜底）
  • tmux has-session 检查是否已在跑
  • active_ip() 显式优先 wlan0，避免误取蜂窝地址
  • 80 秒轮询等待就绪（探测地址用 lan-ip，即 DSH 真实绑定地址）
  • 就绪后自动调 dsh-status.sh 打印地址

A.3 ~/dsh-stop.sh（Termux 层停止） #

见第 12.1 节。要点：

  • 先 touch STOP 让守护脚本优雅退出
  • 最多等 15 秒
  • 然后 tmux kill-session
  • 再 pkill，最后 pkill -9 兜底
  • 最后检查端口是否释放

A.4 ~/dsh-status.sh（Termux 层状态） #

见第 12.1 节。要点：

  • 先显示 active IP / bound IP / watchdog 周期，不一致时提示 MISMATCH: rebind pending
  • 再用实时 IP 做 HTTP 探测，并区分 tmux 会话、dsh 进程、HTTP 状态码
  • UNREACHABLE 时提示「仅蜂窝网络下 Web 被 NAT 挡住、IM 仍可用」
  • token URL 直接从日志按 http://<任意IP>:8080/?token=... 提取，不依赖 lan-ip
  • 打印日志尾部

A.5 ~/.termux/boot/start-dsh.sh（开机钩子） #

见第 13.3 节。要点：

  • termux-wake-lock 防止息屏休眠

  • 最多等 60 秒直到出现局域网 IPv4（用 ifconfig，因为 Termux 无 ip、hostname -I 也不支持）

附录 B 一键部署脚本 #

如果你已经完成了第 1～7 章（Termux 装好、Ubuntu 装好、Node 和 DSH 装好），可以用这个脚本一次性完成第 10～12 章的所有配置。

2026-11-11 起，这里写入的脚本与正文第 10.4 / 12.1 / 13.3 节完全一致（含 IP 看门狗、实时 IP 判断、时区修正），不再是去掉日志的精简版。

为什么用 bash <<'DEPLOY' 而不是 bash -c '...'：新版脚本内部含大量单引号（TZ='CST-8'、awk '...'、case ... '' 等），塞进单引号包裹的 bash -c 会被引号截断。改用带引号的 heredoc 后，脚本内容可以原样内嵌，仍然不会被外层 shell 展开。

在 Termux 里执行：

bash
bash <<'DEPLOY'
set -e
ROOTFS=/data/data/com.termux/files/usr/var/lib/proot-distro/containers/ubuntu/rootfs
DIR="$ROOTFS/root/dsh-install"
mkdir -p "$DIR"

cat > "$ROOTFS/root/start-web.sh" <<'EOS'
#!/bin/bash
# DSH Web supervisor.
#   * auto-detects the active IPv4, WiFi or cellular (network changes tolerated)
#   * single instance enforced with flock
#   * port preflight: waits, then kills a stale listener
#   * exponential backoff restart on crash (5s -> 60s)
#   * IP watchdog: re-checks every CHECK_EVERY seconds and rebinds on change
export PATH=/opt/node-v24.21.0-linux-arm64/bin:$PATH
export DSH_HOME=/root/.dsh
export NODE_OPTIONS=--max-old-space-size=2048
PORT=8080
DIR=/root/dsh-install
LOG=$DIR/web.log
DEFAULT_INTERVAL=300
mkdir -p "$DIR"
# The proot container has no zoneinfo files; a POSIX TZ string needs none.
log() { echo "[$(TZ='CST-8' date '+%F %T')] $*" >> "$LOG"; }

detect_ip() {
  local ip
  # Android denies /proc/net/dev, so `ifconfig <iface>` cannot be used here.
  # hostname -I lists every live IPv4: the first is the WiFi address when
  # WiFi is up, otherwise a cellular one. Cellular is allowed on purpose:
  # the dsh-im plugin only needs outbound connectivity.
  ip=$(hostname -I 2>/dev/null | tr ' ' '\n' | grep -E '^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$' | grep -v '^127\.' | head -1)
  [ -z "$ip" ] && ip=$(ifconfig 2>/dev/null | awk '/inet /{print $2}' | grep -v '^127\.' | head -1)
  [ -z "$ip" ] && ip=$(ip -4 addr 2>/dev/null | awk '/inet /{print $2}' | cut -d/ -f1 | grep -v '^127\.' | head -1)
  echo "$ip"
}

HOST=$(detect_ip)
if [ -z "$HOST" ]; then
  log "FATAL: no IPv4 address detected (no WiFi and no cellular?)"
  exit 1
fi
echo "$HOST" > "$DIR/lan-ip"
echo "$PORT" > "$DIR/lan-port"

exec 9>"$DIR/supervisor.lock"
if ! flock -n 9; then
  echo "another supervisor already holds the lock; exiting"
  exit 0
fi
echo $$ > "$DIR/supervisor.pid"
IV0=$(cat "$DIR/check-interval" 2>/dev/null)
case "$IV0" in ''|*[!0-9]*) IV0=$DEFAULT_INTERVAL ;; esac
log "=== supervisor started (pid $$) host=$HOST port=$PORT watchdog=${IV0}s ==="

port_busy() { timeout 3 bash -c "exec 3<>/dev/tcp/$HOST/$PORT" >/dev/null 2>&1; }

n=0
while port_busy; do
  n=$((n+1))
  if [ $n -le 8 ]; then
    log "port $PORT busy, waiting ($n)"
    sleep 2
  else
    log "port $PORT still busy; killing stale dsh"
    pkill -9 -f "bin/dsh web --host $HOST --port $PORT" 2>/dev/null
    sleep 3
    if port_busy; then log "FATAL: port $PORT still busy; aborting"; exit 1; fi
    break
  fi
done

# --- IP watchdog ---------------------------------------------------------
# Exactly one watchdog for the whole supervisor lifetime. State is passed
# through files in $DIR (a subshell cannot write back to this shell's vars).
# Only the recorded dsh.pid is signalled: never pkill -f, which can match
# the tmux server command line (see the deployment guide, ch.15).
watchdog() {
  local iv cur bound pid started now reason recent
  while true; do
    iv=$(cat "$DIR/check-interval" 2>/dev/null)
    case "$iv" in
      ''|*[!0-9]*) iv=$DEFAULT_INTERVAL ;;
    esac
    [ "$iv" -lt 5 ] && iv=5
    sleep "$iv"

    cur=$(detect_ip)
    [ -z "$cur" ] && continue
    bound=$(cat "$DIR/lan-ip" 2>/dev/null)
    pid=$(cat "$DIR/dsh.pid" 2>/dev/null)
    [ -z "$pid" ] && continue
    kill -0 "$pid" 2>/dev/null || continue

    reason=
    if [ "$cur" != "$bound" ]; then
      # Re-read lan-ip: the supervisor may have just rebound between our
      # two reads. Do not kill a freshly started dsh in that race.
      recent=$(cat "$DIR/lan-ip" 2>/dev/null)
      [ "$recent" = "$cur" ] && continue
      reason="active IP $bound -> $cur"
    else
      # Health probe: skip the 90s Node cold-start grace window.
      started=$(cat "$DIR/launch-ts" 2>/dev/null)
      case "$started" in ''|*[!0-9]*) started=0 ;; esac
      now=$(date +%s)
      [ $((now - started)) -lt 90 ] && continue
      if timeout 5 bash -c "exec 3<>/dev/tcp/$bound/$PORT" >/dev/null 2>&1; then continue; fi
      reason="health probe failed (no listener on $bound:$PORT)"
    fi

    log "watchdog: $reason; requesting rebind"
    : > "$DIR/ip-change.flag"
    kill "$pid" 2>/dev/null
  done
}
watchdog 9>&- &
WPID=$!
cleanup() {
  kill "$WPID" 2>/dev/null
  rm -f "$DIR/dsh.pid"
}
trap cleanup EXIT
trap 'cleanup; exit 143' TERM INT

backoff=5
while true; do
  if [ -f "$DIR/STOP" ]; then log "STOP flag found; exiting"; rm -f "$DIR/STOP"; break; fi
  if ! kill -0 "$WPID" 2>/dev/null; then
    log "WARN: watchdog died; restarting it"
    watchdog 9>&- &
    WPID=$!
  fi
  NEW=$(detect_ip)
  if [ -n "$NEW" ] && [ "$NEW" != "$HOST" ]; then
    log "active IP changed $HOST -> $NEW"
    HOST=$NEW
  fi
  # Republish unconditionally on every launch: lan-ip is the single source
  # of truth the watchdog compares against, and must match the real bind.
  echo "$HOST" > "$DIR/lan-ip"
  log "--- launching dsh web on $HOST:$PORT (backoff=${backoff}s) ---"
  date +%s > "$DIR/launch-ts"
  dsh web --host "$HOST" --port "$PORT" --no-open >> "$LOG" 2>&1 9>&- &
  DSH_PID=$!

C.3 自动输密码（免交互） #

本文实测时，Windows 上无法安装 paramiko（公司网络限制），所以用了 ssh.exe + SSH_ASKPASS 方案。

创建一个 ssh-dev.ps1：

powershell
# ssh-dev.ps1 - run shell commands on the Android/Termux device over SSH
param(
  [string]$Cmd,
  [string]$ScriptFile,
  [switch]$Ubuntu,
  [int]$TimeoutSec = 300,
  [string]$User = 'u0_a250',
  [string]$HostIP = '192.168.3.247',
  [int]$Port = 8022,
  [string]$Password = '你的密码'
)

$ErrorActionPreference = 'Continue'
$Utf8NoBom = New-Object System.Text.UTF8Encoding($false)

# 关键：用 SSH_ASKPASS 自动喂密码，必须配合 stdin 重定向
$askpass = Join-Path $env:TEMP 'dsh_askpass.cmd'
"@echo off`r`necho $Password" | Set-Content -Path $askpass -Encoding ascii
$env:SSH_ASKPASS = $askpass
$env:SSH_ASKPASS_REQUIRE = 'force'
$env:DISPLAY = ':0'

$sshOpts = "-o StrictHostKeyChecking=no -o UserKnownHostsFile=NUL -o PreferredAuthentications=password -o PubkeyAuthentication=no -o ConnectTimeout=20 -o NumberOfPasswordPrompts=1 -o ServerAliveInterval=10 -p $Port $User@$HostIP"

if ($ScriptFile) { $body = [System.IO.File]::ReadAllText((Resolve-Path -LiteralPath $ScriptFile).Path, $Utf8NoBom) }
else { $body = "set -o pipefail`n$Cmd" }
$body = $body -replace "`r`n", "`n"
if (-not $body.EndsWith("`n")) { $body += "`n" }

$stamp = [guid]::NewGuid().ToString('N').Substring(0,8)
$localScript = Join-Path $env:TEMP "dsh_run_$stamp.sh"
[System.IO.File]::WriteAllText($localScript, $body, $Utf8NoBom)

if ($Ubuntu) { $remoteCmd = "proot-distro login ubuntu -- /bin/bash -s" }
else         { $remoteCmd = "bash -s" }

$outRun = Join-Path $env:TEMP 'dsh_ssh_run.txt'
# 关键：stdin 必须重定向，否则 ssh 会走控制台密码提示然后挂死
$runCmd = "ssh $sshOpts `"$remoteCmd`" < `"$localScript`" > `"$outRun`" 2>&1"
$p = Start-Process -FilePath 'cmd.exe' -ArgumentList @('/c', $runCmd) -NoNewWindow -PassThru
if (-not $p.WaitForExit($TimeoutSec * 1000)) {
  try { $p.Kill() } catch {}
  Write-Output "TIMEOUT after ${TimeoutSec}s"
}
Get-Content $outRun -ErrorAction SilentlyContinue
exit $p.ExitCode

用法：

powershell
# 执行单条命令（Termux 层）
powershell -NoProfile -ExecutionPolicy Bypass -File .\ssh-dev.ps1 -Cmd 'uname -a'

# 执行脚本文件（Termux 层）
powershell -NoProfile -ExecutionPolicy Bypass -File .\ssh-dev.ps1 -ScriptFile .\test.sh

# 在 Ubuntu 容器里执行

C.4 三个关键坑（都是实测踩出来的） #

坑 1：SSH_ASKPASS 不生效

必须同时设置三个环境变量：

powershell
$env:SSH_ASKPASS = $askpass
$env:SSH_ASKPASS_REQUIRE = 'force'   # 必须有，否则 ssh 只在没有 tty 时才用 askpass
$env:DISPLAY = ':0'                   # 必须有，否则 ssh 认为没有图形环境

坑 2：不重定向 stdin 会挂死

ssh ... < script.sh 这个 < 必须加。否则 ssh 会尝试从控制台读密码，而 PowerShell 的 Start-Process 没有提供控制台，进程就永远挂在那里直到超时。

坑 3：PowerShell 读 UTF-8 文件被当成 ANSI

用 Get-Content -Raw 读无 BOM 的 UTF-8 文件时，Windows PowerShell 5.1 会按系统 ANSI 代码页（中文系统是 GBK）解码，导致中文变乱码，脚本语法错误。

正确写法：

powershell
[System.IO.File]::ReadAllText($path, (New-Object System.Text.UTF8Encoding($false)))

更省事的办法：脚本里不要写中文，全用 ASCII。

C.5 连接不稳定怎么办 #

本文实测发现，手机端的 sshd 在 proot 环境下响应很慢，TCP 能连上但 SSH banner 交换经常超时，成功率大约 50%。

解决：写重试循环。

powershell
for ($i=1; $i -le 8; $i++) {
  $r = powershell -NoProfile -ExecutionPolicy Bypass -File .\ssh-dev.ps1 -ScriptFile .\task.sh -TimeoutSec 200 2>&1 | Out-String
  if ($r -match "EXPECTED_MARKER") { $r; break }
  "attempt $i failed"; Start-Sleep -Seconds 8
}

E.1 这个部署的安全级别 #

这是「局域网内使用」级别的部署，不适合暴露到公网。

E.2 必须知道的三件事 #

① DSH 能执行任意命令

DSH 是个 coding agent，能读写文件、执行 shell 命令。谁能访问这个页面，谁就能在容器里执行任意命令。

② 不要在公共 WiFi 上跑

咖啡厅、机场、酒店的 WiFi 里，别人可能扫到你的 8080 端口。

③ 不要做端口映射

千万不要在路由器上把 8080 映射到公网。如果确实需要外网访问，用：

  • Tailscale / ZeroTier 之类的虚拟局域网
  • Cloudflare Tunnel
  • 至少加一层 Nginx + Basic Auth + HTTPS

E.3 想要 HTTPS 的话 #

DSH 支持直接上 TLS。在 Ubuntu 容器里执行：

bash
# 生成自签证书（CN 填你手机的局域网 IP）
openssl req -x509 -newkey rsa:2048 -keyout /root/key.pem -out /root/cert.pem -days 365 -nodes -subj "/CN=192.168.3.247"

# 启动
export PATH=/opt/node-v24.21.0-linux-arm64/bin:$PATH
dsh web --host 192.168.3.247 --port 8443 --no-open --tls-cert /root/cert.pem --tls-key /root/key.pem

浏览器会警告「证书不受信任」，手动点「继续访问」即可（自签证书必然如此）。

⚠️ 换了 TLS 之后，第 10 章的守护脚本还是按 HTTP 8080 启动的。想长期用 HTTPS，要改 start-web.sh 里的 PORT=8443 和 dsh web 那行的参数，并把 dsh-start.sh/dsh-status.sh 里探测 URL 的 http:// 改成 https://（还要加 -k 跳过证书校验）。如果你只是想临时试试，直接在容器里前台跑就行，别动守护脚本。

E.4 凭证文件 #

/root/.dsh/.credentials.yaml 里有：

  • client-connection/browser-session 的签名密钥（泄露 = 别人能伪造 cookie）
  • 登录后的 DeepSeek token（如果登录了）

权限应该是 600，检查：

bash
proot-distro login ubuntu -- /bin/bash -c 'ls -l /root/.dsh/.credentials.yaml'

预期：

-rw-------. 1 root root 161 ... /root/.dsh/.credentials.yaml

E.5 建议的加固措施 #

  1. 手机连自己家的 WiFi，不要连公共网络
  2. 怀疑有人蹭用时，最直接的办法是重置签名密钥（下面第 3 条），让所有旧 cookie 立刻失效
  3. 怀疑泄露了，重置签名密钥：
    bash
    bash ~/dsh-stop.sh
proot-distro login ubuntu -- /bin/bash -c 'rm -f /root/.dsh/.credentials.yaml'
bash ~/dsh-start.sh
    这会让所有已下发的 cookie 失效，需要用新 token 重新访问。

说明：DSH 的访问日志只记录启动和退出，不记录每个请求的来源 IP。所以没法靠日志查「谁访问过」。想要访问审计，得在前面套一层 Nginx 之类做反向代理。对家庭局域网场景来说，通常不需要做到这一步。
