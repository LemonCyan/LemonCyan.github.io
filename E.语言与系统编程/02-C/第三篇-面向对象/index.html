第12章 类与对象 #

本章目标：掌握 class/struct、成员与访问控制、构造/析构、初始化列表、this、拷贝构造、静态成员、const 成员、友元、封装与数据抽象。

12.1 引子：为什么需要这一章 #

在 struct 只能把若干数据聚合在一起时（参见 第11章「自定义数据类型」），数据与操作数据的函数是分离的：任何代码都能直接改动结构体的成员，对象处于何种状态难以保证。类 class 把数据和函数组织在同一个结构里，并允许用访问控制规定谁能改动什么，这正是面向对象程序设计模块化的起点。本章建立后续三章的共同基础：继承、多态与运算符重载都建立在类之上。

12.2 类与对象：把数据和函数组织在一起 #

类 class 是一种将数据和函数组织在同一个结构里的逻辑方法。定义类使用关键字 class；struct 在 C++ 中同样可以包含成员函数，二者唯一的区别是默认访问权限：class 的成员默认为 private，struct 的成员默认为 public。此外，union 定义的类也可以有成员函数，默认访问权限为 public，但同一时间只能存储一个数据成员。

类是用户定义的类型，是创建对象的蓝图；对象 object 则是该类型在内存中的实例。同一个类可以生成多个对象，每个对象都拥有自己的一份成员变量，成员函数由这些对象共享。声明对象与声明基本类型变量一样：CRectangle rect; 中 CRectangle 是类型名，rect 是对象名，二者的关系正如 int 与变量名 a。

访问对象的公有成员用直接成员访问运算符 .；若通过指向对象的指针 pointer 访问，则用 ->，例如 p->set_values(3, 4)（参见 第8章「指针」）。成员函数既可以在类内定义，也可以只在类内声明原型、在类外给出实现；在类外定义时必须用范围解析运算符 :: 指明该成员属于哪个类，从而赋予它与类内定义相同的范围属性。类内直接定义的完整函数会被编译器视为 inline 函数，类外定义的则是一般成员函数。

cpp
#include <iostream>
using namespace std;

// class 的成员默认访问权限为 private
class CRectangle {
    int width;   // 私有数据成员，类外不可直接访问
    int height;
public:
    CRectangle(int w, int h) : width(w), height(h) {}  // 构造函数与初始化列表
    void set_values(int w, int h);                     // 成员函数声明
    int area() { return width * height; }             // 类内定义的成员函数
};

// 在类外定义成员函数，必须使用范围解析运算符 ::
void CRectangle::set_values(int w, int h) {
    width = w;
    height = h;
}

int main() {
    CRectangle rect(3, 4);
    CRectangle rectb(5, 6);
    cout << "rect area: " << rect.area() << endl;    // 输出 12
    cout << "rectb area: " << rectb.area() << endl;  // 输出 30
    rect.set_values(2, 7);
    cout << "rect area: " << rect.area() << endl;    // 输出 14
    return 0;
}

12.3 访问控制、封装与数据抽象 #

类体中可以出现多个访问标签 public:、protected:、private:，每个标签指定的访问级别一直有效，直到遇到下一个标签或类体结束，标签出现的次数没有限制。三种访问级别的含义如下表，其中「非成员」指从类外任何位置（如 main 函数、其他类或全局函数）的引用。

访问位置 public protected private
本类的成员函数 是 是 是
派生类 derived class 的成员函数 是 是 否
类外的非成员 是 否 否

private 成员只能由本类的成员函数与友元访问；protected 成员可以被派生类的成员函数访问，但不能被类外代码访问；public 成员在任何能看到该类的地方都可访问。这一规则不因继承方式而改变（参见 第13章「继承与类之间的关系」）。若定义成员时未声明允许范围，class 中默认为 private。

封装是把数据和操作数据的函数绑定在一起的机制，它引申出数据隐藏：把成员状态设为 private，只通过公有成员函数对外提供接口，成员就不会被意外修改。数据抽象则只向外界暴露接口而隐藏实现细节，典型例子是调用标准库 standard library 的 sort() 不必知道排序算法，或使用 cout 输出文本而不必知道它如何显示到屏幕。数据抽象带来两个好处：类的内部受保护，不会因用户级错误导致对象状态受损；类的实现可以随需求变化，只要接口不变，用户代码无需改动，只需重新编译实现。

设计上应把成员状态尽量设为 private，除非确实需要暴露；这一原则同样适用于虚函数。把一个类声明为另一个类的友元类会暴露实现细节、降低封装性，因此理想的做法是尽可能对外隐藏每个类的实现细节。抽象把代码分离为接口与实现两部分，设计组件时必须保持接口独立于实现。

12.4 构造函数、初始化列表与析构函数 #

构造函数 constructor 的名称必须与类名完全相同，绝对没有返回值，连 void 也不能写，在生成对象时自动调用。若类中没有显式定义任何构造函数，编译器会自动提供一个无参的默认构造函数和一个拷贝构造函数；一旦显式定义了任意构造函数，这两个自动提供的构造函数便不再存在，需要时必须自行定义。声明无参对象时不要写空括号：CRectangle rectb; 正确，CRectangle rectb(); 并不创建对象。构造函数也可以像普通函数一样重载，编译器会按对象声明时给出的参数选择匹配的版本。

初始化列表的语法为 类名(形参): 成员1(形参1), 成员2(形参2) { }。它有两个核心规范：成员的真实初始化在进入构造函数体之前完成；初始化顺序与列表中的书写顺序无关，严格取决于成员在类体内的声明顺序。若顺序写错，可能先用一个尚未初始化的成员去初始化另一个成员，得到随机值甚至引发段错误。以下三类成员必须使用初始化列表：const 常量成员、引用 reference 类型的成员，以及派生类构造函数需要显式初始化基类部分时。

只接收一个实参的构造函数默认充当转换构造函数，允许从实参类型隐式转换为该类类型；若不希望发生隐式转换，应在该构造函数前加 explicit 关键字，强制只允许显式实例化。

析构函数 destructor 的名称是 ~类名()，无参数、无返回值、不能重载，一个类只能有一个。对象生命周期结束（局部变量离开作用域，或堆对象被 delete）时自动调用。默认的析构函数不会主动释放类通过指针动态申请的外部资源（如堆内存、文件描述符或 socket 连接）；只要类占用了动态资源，就必须显式编写析构函数并在其中释放。

cpp
#include <iostream>
using namespace std;

class Buffer {
    int* data;   // 指向动态申请的资源
public:
    Buffer(int value) : data(new int(value)) {}  // 构造函数中申请资源
    ~Buffer() {                                  // 析构函数中释放资源
        delete data;
        data = NULL;
    }
    int get() { return *data; }
};

int main() {
    Buffer b(42);
    cout << "value: " << b.get() << endl;
    return 0;   // b 离开作用域，析构函数自动调用
}

12.5 拷贝构造、this 指针与静态成员 #

拷贝构造函数用同一类中已有对象来初始化新创建的对象。编译器自动提供的版本会把源对象的所有非静态数据成员逐个复制给新对象；若类中含有指向动态资源的指针，这种逐个复制会让两个对象共享同一块资源，此时应自行定义拷贝构造函数与析构函数。

在普通成员函数中，this 是一个隐藏的常量指针形参，指向当前调用该函数的对象；在构造函数中，它指向正在被创建的对象。返回 *this 可以实现成员链式调用，也是 operator= 返回自身引用以避免临时对象的常用写法。

静态数据成员被同一类的所有对象共享，内容不依赖于某个对象，可用来统计已声明的对象个数。按标准规定，类内只能写静态数据成员的声明，其定义与初始化必须放在类外的全局范围。静态成员函数属于类而非某个对象，只能引用静态数据成员，不能使用 this；静态数据成员既可以通过对象访问，也可以直接用 类名::成员 访问，二者指向同一个变量。

cpp
#include <iostream>
using namespace std;

class Counter {
    int value;            // 每个对象各有一份
    static int count;     // 静态数据成员，所有对象共享一份
public:
    Counter(int v = 0) : value(v) { ++count; }
    ~Counter() { --count; }
    Counter& add(int n) {         // 返回 *this，支持链式调用
        value += n;
        return *this;
    }
    int get() { return value; }
    static int total() { return count; }  // 静态成员函数只能访问静态成员
};

int Counter::count = 0;   // 静态数据成员必须在类外定义并初始化

int main() {
    Counter a(1), b(2);
    a.add(3).add(4);
    cout << "a = " << a.get() << endl;               // 输出 8
    cout << "total = " << Counter::total() << endl;  // 输出 2
    return 0;
}

12.6 友元：受控地开放非公有成员 #

友元函数 friend function 可以访问类的 private 与 protected 成员，但它并不是成员函数：它在类作用域之外定义，不能用对象加 . 的方式调用，只能像普通函数一样传入对象。友元关系由类显式指定，声明位置与 public、private、protected 标签无关，习惯上放在类定义开头。友元类可以访问与之为友元关系的类的所有私有成员；友元成员函数则只向指定的一个成员函数开放，声明时要用类限定符。

友元关系既不满足对称性，也不具有传递性，并且不能被继承：类 B 是类 A 的友元，并不能推出 A 是 B 的友元、B 的子类是 A 的友元，或 B 的友元是 A 的友元。若一个函数要同时访问多个类的私有成员，必须在每个类中分别声明为友元。使用友元的常见理由是重载运算符与提高性能，但由于它属于面向对象之外的方法，能用成员函数完成的操作应尽量使用成员函数。

12.7 小结 #

  • 类是类型（蓝图），对象是实例；class 成员默认 private，struct 成员默认 public。
  • 类外定义成员函数必须用 ::；用 . 访问对象成员，用 -> 通过指针访问。
  • public、protected、private 分别决定类外、派生类与本类的可访问范围；封装与数据抽象都依赖接口与实现分离。
  • 构造函数无返回值、可重载，初始化列表先于构造函数体执行且顺序由成员声明顺序决定；析构函数负责释放动态资源。
  • this 指向当前对象，*this 支持链式调用；静态成员属于类，静态数据成员须在类外定义。
  • 友元可受控地开放非公有成员，但关系单向、不可传递、不可继承，会降低封装性。

12.8 常见错误与陷阱 #

  • 在初始化列表中按书写顺序推断初始化先后：实际顺序由成员声明顺序决定，用尚未初始化的成员去初始化另一个成员会得到随机值甚至段错误。
  • 显式定义了带参构造函数后仍直接写 Class obj;：编译器不再提供无参默认构造函数，须自行定义。
  • 把声明无参对象写成 Class obj();：这不是创建对象，正确写法是 Class obj;。
  • 在类外定义成员函数时漏写 类名::，或试图从类外直接访问 private 成员。
  • 类持有动态资源却只依赖编译器生成的拷贝构造函数与析构函数，导致资源被共享或在销毁时未被释放。
  • 忘记在类外定义并初始化静态数据成员，或在静态成员函数中使用 this、访问非静态成员。
  • 过度使用友元，把实现细节暴露给外部，破坏封装。

第13章 继承与类之间的关系 #

本章目标：掌握基类/派生类、继承方式与访问控制、构造析构顺序、多重继承，并能分辨类之间的友元关系与继承关系。

13.1 引子：为什么需要这一章 #

若矩形与三角形都需要宽、高以及设置它们的函数，各写一份类会重复大量代码。继承允许我们依据一个已有的类定义新类：已有的类称为基类 base class，新建的类称为派生类 derived class，后者自动获得前者的可见成员，再加上自己的成员。继承表达的是 is a 关系，例如哺乳动物是动物、狗是哺乳动物。本章先说明继承的语法与访问控制，再讨论构造与析构的调用方式以及多重继承。

13.2 定义派生类与继承方式 #

定义派生类要在类名后使用冒号与类派生列表：class derived_class_name : public base_class_name { ... };。其中 public 可换成 protected 或 private，表示被继承成员在派生类中的最低访问限制；若省略，由 class 生成的类默认为 private，由 struct 生成的类默认为 public。实际工程中几乎总是使用 public 继承。三种继承方式对基类成员访问属性的改变如下：

继承方式 基类 public → 派生类 基类 protected → 派生类 基类 private → 派生类
public 继承 public protected 不可直接访问
protected 继承 protected protected 不可直接访问
private 继承 private private 不可直接访问

无论哪种继承方式，两条规则始终成立：private 成员只能被本类成员与友元访问，派生类不能访问；protected 成员可以被派生类访问，但不能被类外代码访问。protected 与 private 的差别只在继承时才表现出来：若希望成员能被派生类的成员函数使用，就应声明为 protected 而非 private。private 继承会把基类完全封装起来，除派生类自身外，其他代码都不能访问从基类继承而来的成员。

下面的示例中，CPolygon 把 width、height 声明为 protected，两个派生类便可直接用它们计算面积。

cpp
#include <iostream>
using namespace std;

class CPolygon {
protected:            // protected 成员可被派生类的成员函数访问
    int width;
    int height;
public:
    void set_values(int w, int h) { width = w; height = h; }
};

class CRectangle : public CPolygon {
public:
    int area() { return width * height; }
};

class CTriangle : public CPolygon {
public:
    int area() { return width * height / 2; }
};

int main() {
    CRectangle rect;
    CTriangle trgl;
    rect.set_values(4, 5);
    trgl.set_values(4, 5);
    cout << rect.area() << endl;   // 输出 20
    cout << trgl.area() << endl;   // 输出 10
    return 0;
}

13.3 哪些成员不被继承，构造与析构如何调用 #

派生类继承基类的所有成员，但以下成员除外：基类的构造函数与析构函数、拷贝构造函数、operator= 成员、重载运算符以及友元函数。友元关系不能被继承，正是因为友元不属于类的成员。

虽然基类构造函数不被继承，但生成派生类对象时，基类的默认构造函数（无参版本）总是被自动调用，且先于派生类构造函数体执行；销毁对象时，基类的析构函数同样自动调用，无需手动调用。若基类没有默认构造函数，或希望调用基类的某个重载构造函数，必须在派生类每个构造函数的定义中显式指定：derived_class_name (parameters) : base_class_name (parameters) { }。

cpp
#include <iostream>
using namespace std;

class Mother {
public:
    Mother() { cout << "Mother: no parameters" << endl; }
    Mother(int a) { cout << "Mother: int parameter" << endl; }
};

class Son : public Mother {
public:
    // 在初始化列表中显式指定要调用的基类构造函数
    Son(int a) : Mother(a) { cout << "Son: int parameter" << endl; }
};

class COutput {
public:
    void output(int value) { cout << value << endl; }
};

// 多重继承：多个基类用逗号分隔
class Rectangle : public Mother, public COutput {
public:
    Rectangle(int a) : Mother(a) {}
    int area(int w, int h) { return w * h; }
};

int main() {
    Son son(1);
    Rectangle rect(1);
    rect.output(rect.area(4, 5));   // 输出 20
    return 0;
}

上例中 Son(1) 先输出基类的构造信息，再输出派生类的构造信息；未在初始化列表指定基类构造函数时，调用的是基类的无参版本。Rectangle 同时继承 Mother 与 COutput，因此既能在初始化列表中指定基类构造函数，也能调用 output。

13.4 多重继承 #

一个派生类可以从多个基类继承属性与成员函数，只需在类派生列表中用逗号把基类分开，并为每个基类分别指定继承方式，形如 class CRectangle : public CPolygon, public COutput { ... };。多重继承让新类同时具备多个基类的能力，例如把几何计算与屏幕输出组合到同一个类中；代价是类层次更复杂，来自不同基类的同名成员可能产生歧义，使用时需要显式限定来源。

注意：蓝图本章目标还列出「组合 / 聚合 / 关联」三种类之间的关系，但本章指定的两份素材只覆盖友元关系与继承关系，没有给出这三种关系的定义与示例。按「不虚构」原则，本篇不展开这部分内容；友元关系参见 第12章「类与对象」。

13.5 小结 #

  • 继承表达 is a 关系，派生类获得基类的可见成员并可扩展自己的成员。
  • 类派生列表中的 public、protected、private 决定被继承成员的最低访问限制，省略时 class 默认为 private。
  • public 继承保持基类访问属性；protected 继承把 public 降为 protected；private 继承把 public 与 protected 降为 private。
  • 基类 private 成员派生类不可访问，protected 成员派生类可访问；构造/析构、拷贝构造、operator=、重载运算符与友元不被继承。
  • 生成与销毁派生类对象时，基类构造函数与析构函数自动调用；可用初始化列表指定要调用的基类构造函数。
  • 多重继承用逗号分隔多个基类，可为每个基类单独指定继承方式。

13.6 常见错误与陷阱 #

  • 把需要被派生类访问的基类成员声明为 private，导致派生类成员函数无法编译。
  • 误以为 private 继承只是隐藏基类成员：它会把基类的 public 与 protected 成员都变为派生类的 private 成员。
  • 基类没有无参构造函数，派生类构造函数又未在初始化列表中显式调用某个基类构造函数，导致编译失败。
  • 以为构造函数、析构函数或友元关系会被派生类继承，进而在派生类中直接调用它们。
  • 多重继承中来自不同基类的同名成员未加限定，引发访问歧义。
  • 省略继承方式后误以为默认是 public：由 class 生成的类默认是 private。

第14章 多态 #

本章目标：掌握虚函数与动态绑定、纯虚函数与抽象类/接口，理解静态成员为何无多态特性，并辨析静态多态与动态多态。

14.1 引子：为什么需要这一章 #

继承带来一个有用的性质：指向派生类对象的指针与指向基类的指针是类型兼容的，因此可以用同一个基类指针数组保存多种派生类对象。但通过基类指针只能引用从基类继承的成员，若派生类各自新增了同名函数，基类指针便无法调用它们。多态要解决的正是这个问题：让同一份调用代码，根据对象的实际类型表现出不同的行为。

14.2 基类指针与虚函数 #

若希望基类指针承认派生类中细化的成员为合法调用，必须在基类中也声明该成员，并用 virtual 修饰。虚函数 virtual function 的作用是：当通过基类指针或引用调用时，程序不再按指针的静态类型，而是按对象的实际类型选择函数版本；这称为动态绑定、后期绑定或运行时绑定。派生类重新定义基类中声明的虚函数，称为覆盖（Override）。

若去掉 virtual，调用就在编译期绑定到基类版本（静态链接、早绑定），各派生类的面积计算都会走基类实现而返回 0。因此，凡是需要「以基类指针统一操作、各派生类分别实现」的成员函数，都应在基类中声明为虚函数。

cpp
#include <iostream>
using namespace std;

class CPolygon {
protected:
    int width;
    int height;
public:
    void set_values(int w, int h) { width = w; height = h; }
    virtual int area() { return 0; }   // 虚函数 virtual function
};

class CRectangle : public CPolygon {
public:
    int area() { return width * height; }
};

class CTriangle : public CPolygon {
public:
    int area() { return width * height / 2; }
};

int main() {
    CRectangle rect;
    CTriangle trgl;
    CPolygon* p1 = &rect;   // 基类指针可以指向派生类对象
    CPolygon* p2 = &trgl;
    p1->set_values(4, 5);
    p2->set_values(4, 5);
    cout << p1->area() << endl;   // 输出 20
    cout << p2->area() << endl;   // 输出 10
    return 0;
}

14.3 纯虚函数、抽象类与接口 #

若基类中无法给出有意义的虚函数实现，可在声明后写 = 0，这样的函数是纯虚函数 pure virtual function；含至少一个纯虚函数的类是抽象类 abstract class，也称为抽象基类 ABC。接口描述了类的行为与功能而不涉及具体实现，C++ 的接口正是用抽象类实现的；注意它与数据抽象不是同一概念，后者是把实现细节与数据分离开的设计技术。

抽象类不能实例化对象，试图实例化会导致编译错误；但可以定义指向它的指针与引用，因为纯虚函数会在派生类中被完整定义。派生类必须实现每一个纯虚函数才能被实例化，否则它仍是抽象类；可实例化的类称为具体类。设计上常用抽象基类为外部应用提供统一、标准化的公有接口，纯虚函数由派生类实现，这样即使系统已经定义完成，新增派生类也不影响已有代码。

cpp
#include <iostream>
using namespace std;

// 含纯虚函数的类是抽象类，不能实例化对象
class Shape {
protected:
    int width;
    int height;
public:
    void setWidth(int w) { width = w; }
    void setHeight(int h) { height = h; }
    virtual int getArea() = 0;    // 纯虚函数 pure virtual function
};

class Rectangle : public Shape {
public:
    int getArea() { return width * height; }
};

class Triangle : public Shape {
public:
    int getArea() { return width * height / 2; }
};

int main() {
    Rectangle rect;
    Triangle tri;
    rect.setWidth(5);
    rect.setHeight(7);
    tri.setWidth(5);
    tri.setHeight(7);
    Shape* shapes[2] = { &rect, &tri };  // 可以定义指向抽象类的指针
    for (int i = 0; i < 2; ++i) {
        cout << shapes[i]->getArea() << endl;   // 输出 35 与 17
    }
    return 0;
}

14.4 静态成员为何无多态，静态多态与动态多态 #

静态成员属于类，不与任何对象实例关联，被所有对象共享；静态成员函数没有 this 指针，只能引用静态数据成员，也不能被重写。多态的存在前提是：有继承关系、派生类重写基类的方法、基类引用或指针指向派生类实例；其实现依赖运行期按对象实际类型进行动态绑定。静态成员既不属于某个对象，也不参与动态绑定，因此不具有多态特性。

从绑定时间看，C++ 的多态可分为静态多态（编译期多态）与动态多态（运行期多态）。动态多态以显式接口和虚函数为基础，客户端通过基类引用或指针操作对象；静态多态以隐式接口和模板具现化为基础，各类型不必有共同基类，只需支持相同的有效表达式。

维度 静态多态（编译期） 动态多态（运行期）
实现机制 模板具现化，编译期决定 继承 + 虚函数，运行期绑定
接口形式 隐式接口，由有效表达式构成 显式接口，以虚函数签名为中心
类型要求 各类无需共有基类，只需支持相同表达式 必须位于同一继承体系
异质对象集合 不能处理 能通过基类指针或引用统一处理
优势 效率较高、编译器可优化、适配性与松耦合 符合客观世界的直觉认识、接口与实现分离、易复用
代价 调试困难、编译耗时、代码膨胀、编译器兼容性 一定的运行时开销、编译器难以优化虚函数、类继承体系笨重

二者的共同点是都能实现多态性、都能使接口与实现相分离：静态多态由模板定义接口、类型参数定义实现，动态多态由基类虚函数定义接口、派生类负责实现。静态多态还通过模板为 C++ 带来了泛型设计，STL 正是其成果（参见 第16章「模板与泛型」）。

cpp
#include <iostream>
using namespace std;

// 静态多态：接口是隐式的，由模板在编译期具现化决定
template <typename T>
void draw(const T& shape) {
    shape.draw();   // 只要求 T 支持 draw() 这一有效表达式
}

class Line {
public:
    void draw() const { cout << "Line" << endl; }
};

class Circle {
public:
    void draw() const { cout << "Circle" << endl; }
};

int main() {
    Line line;
    Circle circle;
    draw(line);
    draw(circle);
    return 0;
}

注意：关于「静态多态」一词，素材存在分歧。C++ 多态.md 把调用在编译期确定版本的早绑定称为静态多态，C++纯虚函数.md 把函数重载称为编译时多态，而 C++中的静态多态和动态多态 - lizhenghn - 博客园.md 将静态多态严格定义为基于模板的编译期多态，并指出函数重载因函数本身不同而无需动态绑定、通常不归入多态。知秋一叶 系列与 C++核心特性与类和对象.md 均未对该词下定义，故本教程采用后者，并在此标注分歧。

注意：蓝图本章目标还列出「虚函数表」「虚析构」「override/final」。指定素材没有给出虚函数表的实现细节、虚析构函数的用法，也没有 C++11 的 override / final 说明符；深入理解多态，为什么说静态成员无多态特性？ - CSDN博客.md 中的 final 指 Java 中不可被重写的方法，与本教程讨论的 C++ 机制不同。按「不虚构」原则，本篇不展开这些标准版本细节，相关内容参见 第21章「现代 C++（C++11 起）」。

14.5 小结 #

  • 基类指针与派生类指针类型兼容，但通过基类指针只能访问从基类继承的成员。
  • 虚函数使调用在运行期按对象实际类型绑定；去掉 virtual 则退化为早绑定，全部调用基类版本。
  • 纯虚函数写作 = 0；含纯虚函数的类是抽象类，不能实例化，但可定义指向它的指针。
  • 派生类必须实现全部纯虚函数才能成为具体类；抽象类为系统提供标准化接口，便于扩充。
  • 静态成员属于类、没有 this、不能重写，因此不参与动态绑定、无多态特性。
  • 静态多态由模板具现化在编译期完成，接口隐式；动态多态由虚函数在运行期完成，接口显式。

14.6 常见错误与陷阱 #

  • 只在派生类中声明函数却用基类指针调用：基类指针无法看到派生类新增成员，须在基类中声明为虚函数。
  • 忘记在基类函数前写 virtual，导致所有调用都被早绑定到基类实现，得到与预期不符的结果（如面积恒为 0）。
  • 试图实例化含纯虚函数的抽象类，或派生类漏实现某个纯虚函数就去创建对象。
  • 误以为静态成员函数可以声明为虚函数参与动态绑定，或在静态成员函数中使用 this。
  • 把函数重载与运行时多态混为一谈：重载在编译期即可确定版本，不需要动态绑定。
  • 期望基于模板的静态多态能处理异质对象集合：模板具现化要求类型一致，异质集合应改用动态多态。

第15章 运算符重载 #

本章目标：掌握运算符重载的规则与限制、成员函数与友元函数两种形式，以及自增自减、输入输出运算符与函数调用运算符的用法。

15.1 引子：为什么需要这一章 #

对基本数据类型，a = b + c 是合法表达式；对类或结构体对象，赋值可以依靠默认的拷贝构造与赋值运算完成，但相加在 C++ 中原本没有定义。运算符重载 operator overloading 让自定义类型也能使用语言内置的运算符，例如把两个二维向量相加得到新向量，或让对象直接用 cout 输出。它本质上是带有特殊名称的函数，因此同样受函数重载规则的约束。

15.2 重载的规则与限制 #

函数重载指同一作用域中名字相同、但形参列表（个数、类型或顺序）不同的多个函数；不能仅通过返回类型不同来重载。调用时编译器把实参类型与各定义的形参类型比较，选出最合适的定义，这一过程称为重载决策（参见 第6章「函数」）。

重载的运算符是带有特殊名称的函数，函数名由关键字 operator 与要重载的运算符符号构成，具有返回类型与参数列表。只能重定义大部分 C++ 内置运算符，且并非所有运算符都可重载。
