第17章 异常处理 #

本章目标：掌握 try/catch/throw、标准异常、栈展开与异常安全，能在程序中报告并处理运行期错误。

17.1 引子：为什么需要这一章 #

在编写程序时，我们常常无法确定一段代码是否总能正常工作：程序可能访问了并不存在的资源，某些变量可能超出预期的范围，也可能出现除以零这类运行期特殊情况。这类情况统称为出错或异常。C++ 的出错处理是 ANSI-C++ 标准引入的功能，它提供了一种把程序控制权从出错位置转移到处理位置的方式，涉及的三个关键字是 try、catch 和 throw。若使用的编译器不兼容该标准，这些功能可能无法使用。

17.2 基本结构：try、throw 与 catch #

try 块中放置可能抛出异常的代码，称为保护代码；catch 块紧跟其后，用于接收并处理异常。throw 用于抛出异常，其形式与 return 相似，但参数不需要括在括号里；操作数可以是任意表达式，表达式结果的类型决定所抛异常的类型，因此这个类型应当能够反映异常的特征。

下面以除以零为例，展示三者配合的完整程序：

cpp
#include <iostream>
using namespace std;

double division(int a, int b) {
    if (b == 0) {
        throw "Division by zero condition!";  // 抛出 const char* 类型的异常
    }
    return a / b;
}

int main() {
    int x = 50;
    int y = 0;
    try {
        double z = division(x, y);
        cout << z << endl;
    } catch (const char* msg) {
        cerr << msg << endl;  // 捕获与 throw 类型匹配的异常
    }
    return 0;
}

注意：抛出的是 const char* 类型的异常，catch 的异常声明就必须写 const char*；类型不匹配时该 catch 块不会被执行。

catch 块必须紧跟在 try 块之后，中间不能插入其它代码。一个 try 块可以对应多个 catch 块，分别声明不同的异常类型。若希望一个 catch 块处理 try 块抛出的任何类型，可以把异常声明写成省略号 catch (...)。

17.3 抛出与捕获的规则 #

throw 一旦执行，try 块立即停止执行，try 块中生成的所有对象都会被销毁，随后控制权才传递给相应的 catch 块；程序在 catch 块结束后继续向下执行。这一由抛出异常而触发局部对象销毁的过程称为栈展开（stack unwinding）。它带来的直接结论是：需要随异常一并清理的资源，应当交给对象的析构函数负责，而不是寄希望于 throw 之后的语句——那些语句不会再被执行。这也是讨论异常安全时的基本出发点。

catch 的参数可以是任何有效的数据类型，因此 catch 可以有多个，各自接受不同类型的参数；运行时由与 throw 参数类型相符的那一个负责处理。下例中同一个 try 块可能抛出 int 或 const char* 两种异常：

cpp
#include <iostream>
using namespace std;

void check(bool resourceReady, int index, int capacity) {
    if (!resourceReady) {
        throw "Allocation failure";  // 抛出 const char* 类型的异常
    }
    if (index >= capacity) {
        throw index;                 // 抛出 int 类型的异常
    }
}

int main() {
    try {
        check(true, 10, 10);
    } catch (int i) {
        cout << "Exception: index " << i << " is out of range" << endl;
    } catch (const char* str) {
        cout << "Exception: " << str << endl;
    }
    return 0;
}

try-catch 也可以嵌套使用：内层 catch 捕获异常后，若希望交给外层继续处理，可以在内层写不带参数的 throw;，把异常原样传递到外面一层，由外层形如 catch (...) 的块统一处理。

如果一个异常由于没有对应的类型而没有被任何 catch 语句捕获，特殊函数 terminate() 将被调用。它的形式是 void terminate();，通常已被定义成立即结束当前进程，并显示一个「非正常结束」（"Abnormal termination"）的出错信息。

17.4 标准异常与自定义异常 #

标准库（standard library）中的一些函数也会抛出异常，它们抛出的对象都是 std::exception 的派生类类型。std::exception 定义在标准头文件 <exception> 中，作为标准异常层次结构的基类；它提供一个公共成员函数 what()，返回异常产生的原因，各派生类都会重载它。由于这是一套类层次结构，若 catch 块使用引用（reference）来捕获 std::exception&，依据继承原则，它也能捕获所有派生类的异常。

标准异常的层次与说明如下：

异常类 说明
std::exception 所有标准 C++ 异常的父类
std::bad_alloc 可以由 new 抛出
std::bad_cast 可以由 dynamic_cast 抛出
std::bad_exception 处理 C++ 程序中无法预期的异常时非常有用
std::bad_typeid 可以由 typeid 抛出
std::logic_error 理论上可以通过阅读代码来检测到的异常
std::domain_error 当使用了一个无效的数学域时抛出
std::invalid_argument 当使用了无效的参数时抛出
std::length_error 当创建了太长的 std::string 时抛出
std::out_of_range 可以由 std::vector 与 std::bitset 的 operator[] 等成员函数抛出
std::runtime_error 理论上不可以通过阅读代码来检测到的异常
std::overflow_error 当发生数学上溢时抛出
std::range_error 当尝试存储超出范围的值时抛出
std::underflow_error 当发生数学下溢时抛出

素材给出过一个 std::bad_typeid 的例子：当 typeid 作用于空指针（pointer）所指向的对象时抛出该异常，用 catch (std::exception& e) 捕获后，e.what() 返回 "Attempted typeid of NULL pointer"。我们既可以直接使用这套标准异常层次，也可以从它们派生出自己的异常类型：

cpp
#include <iostream>
#include <exception>
using namespace std;

struct MyException : public exception {
    const char* what() const throw() {
        return "C++ Exception";      // 重载 what()，给出异常原因
    }
};

int main() {
    try {
        throw MyException();
    } catch (MyException& e) {
        cout << "MyException caught" << endl;
        cout << e.what() << endl;
    } catch (std::exception& e) {
        cout << e.what() << endl;    // 用基类引用兜底其它标准异常
    }
    return 0;
}

17.5 小结 #

  • try 块标识保护代码，throw 抛出异常，catch 块按类型接收；三者构成出错处理的基本结构。
  • throw 操作数的类型决定异常类型；多个 catch 块中由类型相符者执行，catch (...) 用于兜底，不带参数的 throw; 可把异常传递到外层。
  • 抛出异常会触发栈展开，try 块中的局部对象被销毁，控制权转移到 catch，处理完毕后程序继续向下执行。
  • 标准异常以 std::exception 为基类，用引用捕获可覆盖其所有派生类；what() 返回异常原因，也可派生自定义异常。
  • 未捕获的异常会调用 terminate()，通常立即结束进程并给出「非正常结束」信息。

17.6 常见错误与陷阱 #

  • 抛出的类型与 catch 声明的类型不匹配。例如抛出字符串字面量时应以 const char* 捕获，旧资料常写作 char*，在现代 C++ 中已不正确。
  • 以为 catch 块可以写在任意位置：catch 必须紧跟 try 块，中间不能插入其它代码。
  • 只写了一个 catch 块却用 throw 抛出多种类型，未匹配的类型最终无人捕获，程序调用 terminate() 直接结束，并给出 "Abnormal termination"。
  • 把资源清理语句安排在 throw 之后：throw 一旦执行，try 块立即停止，其后的语句不会被执行；应让局部对象的析构函数承担清理。
  • 嵌套 try-catch 中只想把原异常交给外层，却写成带参数的 throw；此时应使用不带参数的 throw;。
  • 自定义异常时忘记重载 what()，导致 catch 中拿不到异常原因。

第18章 预处理与多文件工程 #

本章目标：掌握 #include/#define/#ifdef、头文件守卫、头文件相互包含、接口与实现分离、命名空间深入、extern "C"、编译与链接。

18.1 引子：为什么需要这一章 #

稍具规模的程序很少只由一个源文件构成：源文件之间要共享声明、避免重名、划分接口与实现，还要在编译之前由预处理器完成文本替换与取舍。理解这一过程，才能解释「头文件互相包含编译不过」「链接 C 语言库得到 undefined reference」这类工程问题。

18.2 预处理指令概览 #

预处理指令（preprocessing directive）是写给预处理器（preprocessor）的命令，而不是程序本身的语句。它们以 # 开头，必须各自独占一行，且不用分号结尾；预处理器在编译 C++ 程序时由编译器自动执行，负责对代码做第一次验证和消化。

指令 作用
#include 用指定文件的全部内容替换该指令所在行
#define 定义宏（macro），把名字替换为指定文本
#undef 取消已定义的宏
#ifdef / #ifndef 当指定宏已定义 / 未定义时，才编译其后的代码
#if / #elif / #else / #endif 按常量表达式条件选择编译的代码，并以 #endif 结束
#line 指定其后出错信息中显示的行号与文件名
#error 中断编译并输出参数中给出的出错信息
#pragma 对编译器进行配置，具体参数因平台与编译器而异

#define name value 定义不带参数的宏，例如 #define MAX_WIDTH 100，此后程序中遇到的名字都会被替换为 value；它也可以定义带参数的宏，例如 #define getmax(a,b) a>b?a:b。#undef 完成相反的工作：取消已有宏后，可为后续声明重新定义同名宏。

#include 有两种写法，区别只在查找路径：双引号形式先在包含该指令的文件所在目录下寻找，找不到再到标准头文件路径寻找；尖括号形式直接到标准头文件路径寻找。因此，包含工程内的头文件（header file）用 "..."，包含标准库头文件用 <...>。

预处理器还提供两个运算符：# 把宏参数转换为字符串，例如 #define MKSTR(x) #x 把 MKSTR(HELLO C++) 展开为 "HELLO C++"；## 连接两个令牌，例如 #define CONCAT(x, y) x ## y 把 CONCAT(x, y) 展开为 xy。

#line number "filename" 中 number 是赋给下一行的新行号，其后的行号逐个递增；filename 是可选参数，用于替换出错信息中显示的文件名。#error 常与条件编译配合，例如 #ifndef __cplusplus 与 #error A C++ compiler is required 连用，在 __cplusplus 未定义时中断编译。#pragma 针对平台与编译器进行配置，不支持的参数会被忽略而不产生出错。

预定义的宏名称在任何时候都是定义好的：

宏 含义
__LINE__ 整数值，表示当前正在编译的行在源文件中的行号
__FILE__ 字符串，表示被编译源文件的文件名
__DATE__ 字符串，存储编译开始的日期，格式 "Mmm dd yyyy"
__TIME__ 字符串，存储编译开始的时间，格式 "hh:mm:ss"
__cplusplus 整数值，所有 C++ 编译器都定义；完全遵守标准时应等于或大于 199711L

注意：两份素材对 __DATE__ 格式描述略有差异，另一份写作 month/day/year；按蓝图约定以「知秋一叶」系列为准，本教程采用 "Mmm dd yyyy"。

下面的程序把宏、参数宏、条件编译与预定义宏放在一起；用 gcc -E test.cpp > test.p 把预处理结果重定向到文件，即可看到宏在编译前已被替换为对应文本。

cpp
#include <iostream>
using namespace std;

#define DEBUG
#define MIN(a, b) (((a) < (b)) ? (a) : (b))

int main() {
    int i = 100;
    int j = 30;
#ifdef DEBUG
    cerr << "Trace: Inside main function" << endl;
#endif
    cout << "The minimum is " << MIN(i, j) << endl;
    cout << "Line: " << __LINE__ << ", File: " << __FILE__ << endl;
    cout << "Built at " << __DATE__ << " " << __TIME__ << endl;
#if 0
    cout << "这段代码不会被编译" << endl;  // 用 #if 0 注释掉一段代码
#endif
    return 0;
}

18.3 条件编译、头文件守卫与相互包含 #

条件编译使程序的一部分只在满足条件时才被编译，条件只能够是常量表达式，整串指令以 #endif 结束。#ifdef name 仅在 name 已被定义（无论其值）时编译其后代码，#ifndef 起相反作用。典型用法有二：一是调试开关，把 #ifdef DEBUG 与 #endif 之间的诊断输出纳入编译；二是头文件守卫，固定写法为开头的 #ifndef __HEAD_1_H__、紧随的 #define __HEAD_1_H__ 与文件末尾的 #endif。同一头文件被再次包含时，第二次展开因宏已定义而整个跳过，从而避免递归包含与重复定义。

C/C++ 中头文件相互包含是常见工程错误。素材案例中，head1.h 声明 bool func(ClassA* CA)，参数类型 ClassA 定义在 head2.h，故 head1.h 包含 head2.h；head2.h 又包含 head1.h，且 ClassA 的成员函数用到 head1.h 里的宏 VAR_MACRO。两个源文件分别包含二者，编译后却报 ClassA 与 VAR_MACRO 未定义。把展开顺序排出来，原因就很清楚：

编译单元 展开后的先后顺序 报错原因
source1.cpp → head1.h → head2.h ClassA 的定义在前，#define VAR_MACRO 1 与 func 声明在后 ClassA 的成员函数用到 VAR_MACRO 时，该宏尚未定义
source2.cpp → head2.h → head1.h #define VAR_MACRO 1 与 func 声明在前，ClassA 的定义在后 func 声明时还看不到 ClassA 的定义

修改有两条：在 head1.h 的 func 声明之前加上 class ClassA; 前置声明；把 #define VAR_MACRO 1 移到 #include "head2.h" 之前。两者本质相同：头文件展开是文本替换，声明与宏必须出现在使用点之前。

18.4 命名空间深入 #

命名空间（namespace）把一组全局范围有效的类、对象或函数组织到一个名字下，相当于把全局范围分割成若干子域，从而避免重名造成重复定义错误。定义格式为 namespace identifier { namespace-body }；在命名空间之外访问其成员须用作用域运算符 ::，例如 general::a。

using namespace identifier; 把当前嵌套层与指定命名空间连在一起，使其中的名字可像全局名字一样直接访问。该指令只在其被声明的语句块内有效，若在全局范围声明则对全部代码有效；因此可在不同语句块分别写 using namespace first; 与 using namespace second;。用 namespace new_name = current_name; 可为已有命名空间定义别名。

标准库是命名空间最典型的例子：按 ANSI C++ 标准，其所有类、对象和函数都定义在命名空间 std 下。标准为新头文件沿用原名但去掉 .h 扩展名，例如 iostream.h 变为 <iostream>。使用兼容标准的头文件时，要么写 std::cout，要么用 using namespace std;；对 STL 用户，建议采用这种兼容标准的包含方式。早期编译器允许 iostream.h 等传统头文件，本教程统一使用去掉 .h 的标准头文件。

cpp
#include <iostream>
using namespace std;

namespace first {
    int var = 5;
}

namespace second {
    double var = 3.1416;
}

namespace alias = second;   // 为已有命名空间定义别名

int main() {
    cout << first::var << endl;      // 使用作用域运算符访问
    cout << second::var << endl;
    {
        using namespace first;
        cout << var << endl;         // 5，只在该语句块内有效
    }
    {
        using namespace alias;
        cout << var << endl;         // 3.1416
    }
    return 0;
}

18.5 接口与实现分离 #

较大的软件项目一般由几个小组共同开发，为把影响降到最低，定义好接口势在必行。素材给出两条要求：接口名字要与实际功能相符合；接口要对数据封装，不允许客户直接操作接口之下的数据，尤其不能用 new 与 delete 在堆上操作内存数据，以免误用造成错误。

C++ 中实现接口与实现分离有两种手法：

  • Pimpl Idiom（pointer to implementation）：把实现细目隐藏于指针（pointer）背后，分成只提供接口的 Person 与负责实现的 PersonImpl 两个类。Person.h 只对实现类做前置声明 class PersonImpl;，接口类持有 PersonImpl *mPersonImpl; 成员并把调用转发给它；客户无法直接操作背后以 std::string 保存的细目数据。
  • Object Interface：把接口定义为抽象类，接口全部是纯虚函数，由派生类的成员函数实现（参见 第14章「多态」）。素材中 Animal 是抽象接口，RealAnimal 继承并实现，另有一个类似工厂函数的友元函数返回 Animal* 接口指针。

注意：Object Interface 手法中，抽象接口类的析构函数必须声明为虚函数（virtual function），否则通过接口指针删除派生类对象时可能造成内存泄漏。

两种手法共同降低了客户误操作数据的可能性，也把模块依赖性降到最低：实现细目变更时，客户只依赖接口声明的头文件，无需重新编译。缺点是编译器仍会为接口类自动生成构造函数、拷贝构造函数等成员函数。

cpp
#include <iostream>
#include <string>
using namespace std;

// 抽象接口：只暴露纯虚函数，数据细目由派生类持有
class Animal {
public:
    virtual ~Animal() {}                          // 虚析构函数，避免内存泄漏
    virtual string getName() const = 0;
    virtual void setName(const string& name) = 0;
};

class RealAnimal : public Animal {
public:
    RealAnimal(const string& name) : mName(name) {}
    string getName() const { return mName; }
    void setName(const string& name) { mName = name; }
private:
    string mName;
};

Animal* create(const string& name) {              // 工厂函数：返回接口指针
    return new RealAnimal(name);
}

int main() {
    Animal* a = create("cat");
    cout << a->getName() << endl;
    a->setName("tiger");
    cout << a->getName() << endl;
    delete a;                                    // 经虚析构函数正确释放
    return 0;
}

18.6 extern "C" 与编译、链接 #

一个由 C 语言库与 C++ 主程序组成的工程，编译与链接分三步：用 gcc -c test.c 编译出目标文件，用 ar -rc test.a test.o 打包为静态库 test.a，再用 g++ -o main main.cpp test.a 生成可执行程序。素材中最后一步会得到 undefined reference to 'test()' 与 collect2: ld returned 1 exit status 的链接错误：main.cpp 调用了 C 语言库函数，链接时找不到对应符号。

解决方法是在 C++ 一侧，把与 test.a 相关的头文件声明包进 extern "C" { ... } 中；重新执行 g++ -o main main.cpp test.a 即可链接成功。

18.7 小结 #

  • 预处理指令不是 C++ 语句：以 # 开头、独占一行、不以分号结尾；常见指令包括 #include、#define、#undef、条件编译指令、#line、#error 与 #pragma。
  • #include 的双引号形式先查当前目录再查标准路径，尖括号形式直接查标准路径；宏可带参数，# 转字符串、## 连接令牌。
  • 条件编译只接受常量表达式；头文件守卫用 #ifndef / #define / #endif 三行防止递归包含，相互包含时还需前置声明与正确的宏定义顺序。
  • 命名空间用 :: 限定访问，using namespace 只在声明它的语句块内有效，可定义别名；标准库的名字都在命名空间 std 下。
  • 接口与实现分离有 Pimpl Idiom 与 Object Interface 两种手法，后者要求抽象接口类具备虚析构函数；链接 C 语言库需要 extern "C"。

18.8 常见错误与陷阱 #

  • 在预处理指令末尾加分号，或把多条指令写在同一行：指令不是语句，必须独占一行且不以分号结尾。
  • 在 #if 条件里写非常量表达式：条件只能够是常量表达式。
  • 忽略 #include 两种写法的查找路径差异：工程内头文件用双引号，标准库头文件用尖括号。
  • 头文件缺少守卫，相互包含时出现递归展开；或把宏定义写在 #include 之后，使被包含的文件在宏生效之前就使用它。
  • 头文件相互包含时，在声明使用某类型的函数之前没有给出 class ClassA; 这样的前置声明。
  • 误以为 using namespace 全局有效：它只在声明它的语句块内有效，全局声明才对全部代码有效。
  • Object Interface 手法中忘记把抽象接口类的析构函数声明为虚函数，造成内存泄漏。
  • 链接 C 语言库时未用 extern "C" 包裹相关声明，得到 undefined reference 错误。

第19章 文件与流 #

本章目标：掌握 fstream/ifstream/ofstream、打开模式、文本与二进制、stringstream，能读写 string/int 数据，并理解流状态与流指针。

19.1 引子：为什么需要这一章 #

到目前为止，我们使用的是 iostream 标准库提供的 cin 与 cout，分别用于从标准输入读取、向标准输出写入（参见 第4章「基本输入输出」）。要让程序中的数据在运行结束后仍然存在，或者读取已有的数据文件，就需要标准库中的 fstream。被打开的文件在程序中由一个流对象表示，对这个流对象所做的任何输入输出操作，实际就是对该文件所做的操作。

19.2 三个文件流类与打开模式 #

fstream 标准库定义了三个类：

类 说明 默认打开方式
ofstream 输出文件流，由 ostream 引申，用于创建文件并向文件写入信息 ios::out 与 ios::trunc
ifstream 输入文件流，由 istream 引申，用于从文件读取信息 ios::in
fstream 文件流，由 iostream 引申，同时具备 ofstream 与 ifstream 的功能 ios::in 与 ios::out

要在 C++ 中进行文件处理，源代码中必须包含 <fstream> 与 <iostream>。打开文件使用成员函数 open()：

void open(const char * filename, openmode mode);

第一个参数指定文件的名称和位置，第二个参数定义文件被打开的模式。模式标志可以用 | 组合，例如 file.open("example.bin", ios::out | ios::app | ios::binary); 表示以二进制方式把输出附加到文件末尾。

模式标志 含义
ios::in 为输入（读）而打开文件
ios::out 为输出（写）而打开文件
ios::ate 初始位置在文件尾（文件打开后定位到文件末尾）
ios::app 所有输出附加在文件末尾
ios::trunc 若文件已存在则先删除该文件（把文件长度设为 0）
ios::binary 以二进制方式打开

注意：只有当调用 open() 时没有声明 mode 参数，三个类各自的默认值才会被采用；一旦声明了任何参数，默认值将被完全改写，而不会与调用参数组合。

注意：部分素材还列出 ios::nocreate 与 ios::noreplace，与「知秋一叶」系列及 C++ 文件和流.md 所列模式不一致；按蓝图约定以「知秋一叶」系列为准，本教程只采用上表六种标志。

由于打开通常是第一个操作，三个类都提供可直接调用 open() 的构造函数，参数相同，例如 ofstream file("example.bin", ios::out | ios::app | ios::binary); 与先定义对象再调用 open() 等价。用成员函数 is_open()（bool is_open();）可以检查文件是否顺利打开，返回 true 表示已顺利打开。

读写完成后应调用 close()（void close();）关闭文件：它负责把缓存中的数据排放出来并关闭文件，此后该流对象可以被用来打开其它文件。析构函数会自动调用 close()，程序终止时也会自动刷新所有流、释放内存并关闭所有打开的文件，但显式关闭仍是应当养成的习惯。

19.3 文本文件的读写与流状态 #

ofstream、ifstream 和 fstream 分别从 ostream、istream 和 iostream 引申而来，所以可以使用与 cin、cout 相同的成员函数和运算符：用插入运算符 << 向文件写入，用提取运算符 >> 从文件读取，用 getline 逐行读入字符序列并存入 std::string 对象（参见 第7章「数组与字符串」）。

cpp
#include <fstream>
#include <iostream>
#include <string>
using namespace std;

int main() {
    // 写入文本文件
    ofstream outfile("example.txt");
    if (outfile.is_open()) {
        outfile << "This is a line." << endl;
        outfile << "This is another line." << endl;
        outfile.close();
    }

    // 逐行读取并输出到屏幕
    ifstream infile("example.txt");
    string line;
    while (getline(infile, line)) {
        cout << line << endl;
    }
    infile.close();
    return 0;
}

除了 eof()（ifstream 从 ios 继承，到达文件末尾时返回 true），还有一组用于验证流状态的成员函数，全部返回 bool 值；clear() 无参数，用于重置它们所检查的状态标志。

成员函数 作用
bad() 读写过程中出错时返回 true，例如对未打开为写状态的文件写入，或写入的设备没有剩余空间
fail() 除 bad() 的情形外，格式错误时也返回 true，例如想读入一个整数却得到一个字母
eof() 读文件到达文件末尾时返回 true
good() 最通用：以上任何一个函数返回 true 时，good() 返回 false
clear() 重置以上成员函数所检查的状态标志，无参数

19.4 流指针、二进制读写与缓存同步 #

所有输入输出流对象都至少有一个流指针：ifstream 类似 istream，有一个 get 指针指向下一个将被读取的元素；ofstream 类似 ostream，有一个 put 指针指向写入下一个元素的位置；fstream 同时继承两者。文件位置指针是一个整数值，指定从文件起始位置到指针所在位置的字节数。

成员函数 作用
tellg() / tellp() 返回 pos_type 类型的值（整数），代表当前 get / put 指针的位置
seekg(pos) / seekp(pos) 把指针改为指向从文件开始计算的绝对位置 pos，参数类型与 tellg() / tellp() 的返回值相同
seekg(offset, dir) / seekp(offset, dir) 把指针改为相对 dir 的位移 offset 处

dir 可取三种值：ios::beg 从流开始位置计算，ios::cur 从流指针当前位置计算，ios::end 从流末尾计算。移动的单位是字节而不是行，例如 file.seekg(0, ios::beg) 定位到文件开头，file.seekg(0, ios::end) 定位到文件末尾，file.seekg(10, ios::cur) 从当前位置向文件末方向移动 10 个字节。

注意：get 与 put 指针的值对文本文件和二进制文件的计算方法不同，因为文本模式中某些特殊字符可能被修改。素材建议：对以文本模式打开的文件总是使用 seekg / seekp 的第一种原型，且不要修改 tellg() 或 tellp() 的返回值；对二进制文件则可任意使用这些函数。

在二进制文件中，使用 <<、>> 以及 getline 来输入输出数据没有实际意义，虽然它们符合语法。文件流提供了两个为顺序读写数据特殊设计的成员函数：write(char * buffer, streamsize size) 是 ostream 的成员、被 ofstream 继承；read(char * buffer, streamsize size) 是 istream 的成员、被 ifstream 继承；fstream 同时拥有两者。buffer 是一块内存的地址，用来存储或读出数据，size 表示要从缓存中读出或写入的字符数。下例先取得文件大小，再把整个文件读入缓存：

cpp
#include <fstream>
#include <iostream>
using namespace std;

int main() {
    const char* filename = "example.txt";
    ifstream file(filename, ios::in | ios::binary | ios::ate);  // 打开后定位到文件尾
    long size = file.tellg();                                   // 文件尾位置即字节数
    file.seekg(0, ios::beg);                                    // 回到文件开头
    char* buffer = new char[size];
    file.read(buffer, size);
    file.close();
    cout << "the complete file is in a buffer" << endl;
    delete[] buffer;
    return 0;
}

文件流与一个 streambuf 类型的缓存（buffer）联系在一起，缓存是流与物理文件之间的一块内存。以输出流为例，调用 put 写入单个字符时，字符先被插入缓存而非直接写入文件。缓存被排放（flush）时，数据或被写入物理介质、或被抹掉，这个过程称为同步（synchronization），在以下任一情形下发生：

触发时机 说明
文件被关闭时 关闭之前，所有还没有被完全写出或读取的缓存都将被同步
缓存满时 缓存有一定的空间限制，满时自动同步
控制符明确指明 遇到流中的 flush 与 endl 时发生同步
