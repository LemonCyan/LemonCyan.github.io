第12章 文件 I/O 与标准 I/O #

本章目标：分清系统调用层与 ANSI C 标准库层两套文件 API，能独立完成文件的打开、读写、定位、元数据查询与目录遍历，并在两套 API 之间正确转换。

12.1 引子：为什么需要这一章 #

前面各章的程序都只跟内存打交道：变量、数组、指针、结构体，一旦进程退出，这些数据全部消失。要让程序的结果留下来、要与别的程序交换数据、要读配置、要写日志，就必须把数据落到文件上。文件 I/O（input/output，输入输出）是程序与外部世界的第一个正式接口。

在 C 语言里做同一件事，往往有两套名字。写一个字节到文件，既可以调用 write(fd, &c, 1)，也可以调用 fputc(c, fp)；读一整行，既可以自己循环 read 拼装，也可以直接用 fgets。这不是历史包袱的重复，而是两个层次：前者是操作系统提供的系统调用（system call），后者是 ANSI C 标准库在系统调用之上加了一层用户态缓冲区（buffer）的封装。搞不清这两层，就会写出「明明写了数据，文件里却是空的」「两个函数混着用，读到的位置全乱」这类难以排查的问题。

本章先沿着「系统调用层」走一遍：文件类型、文件描述符、open 与 close、read 与 write、lseek 定位、分块拷贝实战；再沿着「标准库层」走一遍：FILE * 流、fopen 的六种模式、字符/行/格式化/数据块四类读写函数、流定位与状态；最后把两层放在一张表里对照，并补上文件元数据（stat 系列）与目录遍历（opendir 系列）。

注意：本章中大量函数（open、read、write、lseek、stat、opendir 等）不属于 ANSI C 标准库，而由 POSIX 标准（IEEE Std 1003.1）定义，在 Linux / UNIX 上可直接使用，在纯 Windows 环境则需要对应的兼容层。fopen、fread、fwrite、fseek 等才是跨平台可移植的 ANSI C 标准库函数。正文凡出现前者都会标明「POSIX」。

12.2 「一切皆文件」与七种文件类型 #

Linux 的核心设计理念之一是「一切皆文件」：普通文件、目录、硬件设备、网络套接字都被抽象成文件，用统一的接口读写，从而大幅简化系统设计。文件在这里的含义被放大为「以字符序列构成的信息载体」。

按 ls -l 列表输出的第一个标识字符，文件分为七种类型：

标识字符 文件类型 英文名称 物理特性与用途
- 普通文件 Regular File 存放文本、源码、可执行二进制或多媒体数据流
d 目录文件 Directory 存放文件名与 inode 节点映射关系的特殊文件
l 符号链接 Symbolic Link 类似快捷方式，内容仅存放另一个目标文件的路径
p 命名管道 FIFO / Pipe 本地进程间半双工通信通道，数据只在内存缓冲区中，不写盘
s 套接字 Socket 跨主机或本地进程间双向通信的虚拟接口
c 字符设备 Character Device 键盘、鼠标、串口终端等按字节流顺序读写的硬件接口
b 块设备 Block Device 硬盘、U 盘等按扇区块读写、支持随机寻址的存储硬件

设备驱动通常被归为三大类，它们的访问方式差别明显：

设备类别 数据访问方式 用户态接口 常见设备
字符设备 character device 以字节流按顺序串行读取，不支持随机寻址，不能 lseek 寻道 与普通文件相同的 open / read / write / close，节点在 /dev/ 下 键盘、鼠标、串口终端、LCD 显示屏、触摸屏
块设备 block device 可按任意随机顺序访问，但每次物理读写以固定数据块为单位（如 512 字节或 4 KB），内核维护高速缓冲区与 I/O 调度队列 通常先挂载到目录树，再以常规文件方式访问 机械硬盘、固态硬盘、U 盘、SD 卡
网络设备 network device 面向网络数据包的收发，不在文件系统中产生物理节点 没有文件描述符，必须用套接字（socket）接口与 socket / bind / sendto / recvfrom 收发 以太网网卡、环回网卡

注意：网络设备是「一切皆文件」的一个例外——它没有对应的文件描述符，不能用 open 打开、也不能用 read 读取。

12.3 文件描述符 #

文件描述符（file descriptor，简称 fd）是内核用来区分和引用进程已打开文件的句柄。

  • 物理本质：它是一个非负整数，实际上是进程控制块（PCB）中「打开文件描述符表」的数组索引，该索引指向内核中该进程的打开文件记录。
  • 参数传递：进程每次通过系统调用打开或创建文件，内核就返回一个描述符；此后所有读写操作都必须把这个描述符作为参数传进去，由内核映射到真实的物理文件结构。
  • 分配规则：open 成功时返回当前进程最小的可用非负整数描述符。

任何一个 Linux 进程启动时，内核都会自动打开三个标准流，占用前三个描述符：

数值 标准流 POSIX 宏 用途
0 标准输入 standard input STDIN_FILENO 接收键盘或重定向的输入
1 标准输出 standard output STDOUT_FILENO 打印正常结果
2 标准错误 standard error STDERR_FILENO 打印错误信息，与标准输出分开重定向

系统级 I/O 函数（open、read、write、lseek、close）常被称为不带缓冲的 I/O（unbuffered I/O）：这里的「不带缓冲」是指每次 read 或 write 都会直接触发一次底层系统调用，由内核与磁盘/设备交互，不经过用户空间的用户级缓冲区（即 printf / fread 维护的那类缓冲区）。这也正是它们效率低于标准库流式 I/O 的原因：小字节频繁读写时，每次都要陷入内核。

12.4 打开与关闭：open 与 close #

open 是 POSIX 提供的系统调用，用于打开或创建文件：

c
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

/* 两个原型：只在创建新文件时才需要第三个参数 */
int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);

参数与返回值：pathname 是文件路径字符串（绝对或相对）；flags 是控制打开方式的位掩码，用按位或 | 组合；mode 仅在使用 O_CREAT 创建新文件时传入，用于指定新文件的权限位。成功时返回分配的最小可用非负整数描述符，失败返回 -1 并设置 errno。

flags 的常用取值分两组。第一组是互斥的基础打开模式，三者必须且只能选其一：

标志 含义 要点
O_RDONLY 只读打开 与 O_WRONLY、O_RDWR 互斥
O_WRONLY 只写打开 不能读取
O_RDWR 可读写打开 读、写共用同一个文件偏移量

第二组是状态与辅助标志：

标志 含义 要点
O_CREAT 文件不存在则创建 此时必须指定第三个参数 mode
O_EXCL 与 O_CREAT 联用做独占检查 文件已存在则失败，errno 为 EEXIST，可防多进程竞争创建
O_TRUNC 以可写模式成功打开时把文件长度清 0 原有内容全部丢弃，相当于覆盖写
O_APPEND 追加模式 每次 write 前自动把偏移量定位到文件末尾
O_NOCTTY 打开终端设备时不把它设为控制终端 守护进程常用
O_NONBLOCK / O_NDELAY 非阻塞方式打开 管道、FIFO、字符设备无数据时立即返回而不阻塞
O_SYNC 同步写 每次 write 都必须等数据物理落盘才返回
O_NOFOLLOW 路径是符号链接则失败 安全场景下避免被链接诱导
O_DIRECTORY 路径不是目录则失败 只接受目录

mode 控制新建文件的初始权限，但它不是最终权限，还要受进程掩码 umask 的限制，计算方式是 最终权限 = mode & (~umask)。例如传入 0777、系统 umask 为 0022，最终权限就是 0755。常用权限常量如下：

常量 八进制值 含义
S_IRWXU 00700 所有者可读写执行
S_IRUSR / S_IREAD 00400 所有者可读
S_IWUSR / S_IWRITE 00200 所有者可写
S_IXUSR / S_IEXEC 00100 所有者可执行
S_IRWXG 00070 同组用户可读写执行
S_IRWXO 00007 其他用户可读写执行

close 断开描述符与内核文件结构的映射，并释放该描述符供后续 open 复用：

c
#include <unistd.h>

int close(int fd);

成功返回 0，失败返回 -1。关闭之前，操作系统会把因延迟写而暂存在缓冲区的数据物理写回磁盘，并释放相关内核内存。虽然进程退出时内核会自动关闭所有打开的描述符，但长期运行的服务程序必须主动关闭不用的描述符，否则会描述符泄露——达到进程或系统的描述符上限后，将再也打不开任何新文件或套接字。

12.5 读写：read 与 write #

c
#include <unistd.h>

ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);

read 从 fd 读取最多 count 字节到 buf；write 把 buf 处的 count 字节写入 fd（数据只读，故加 const）。两者的返回值类型都是带符号的 ssize_t，语义见下表：

返回值 read 的含义 write 的含义
> 0 实际读到的字节数，可能小于 count（读到文件尾、管道数据不足或被信号打断） 实际写入的字节数，若小于 count 通常是磁盘已满或文件大小超限
0 读到文件尾（EOF）或无数据可读 极少出现（写入 0 字节）
-1 出错，原因记录在 errno 出错，原因记录在 errno

两个最常遇到的 read 错误码：

错误码 触发条件 处理方式
EINTR 阻塞等待输入时被信号打断 判断 errno == EINTR 后重试该次读
EAGAIN 以 O_NONBLOCK 打开且当前无数据可读 不视为故障，稍后重试

「read 一次就能读满 count 字节」是常见的错误假设。文件尾、管道、终端、套接字都可能让实际返回值小于请求值，因此完整的读取逻辑必须放在循环里，直到返回 0 或 -1 为止。

12.6 定位：lseek 与文件空洞 #

每个已打开的文件在内核中都有一个当前的读写偏移量（current file offset，简称 CFO）。默认打开时指向文件开头（若以 O_APPEND 打开则指向文件尾），读写操作会让它自动向后移动；lseek 可以手动定位和调整这个偏移量：

c
#include <sys/types.h>
#include <unistd.h>

off_t lseek(int fd, off_t offset, int whence);

成功时返回定位后的新偏移量（相对文件开头的字节数），失败返回 -1。offset 以字节为单位，正数向后移、负数向前移；whence 指定基准点：

基准点 含义 典型用法
SEEK_SET 以文件开头为基准，直接定位到第 offset 字节 回到文件开头重读
SEEK_CUR 以当前 CFO 为基准 相对前后跳转
SEEK_END 以文件物理结尾为基准 求文件长度、在末尾追加

关于 CFO，有四条容易忽略的规则：

  • 独立偏移：每执行一次 open 或 fopen，内核就为这一次打开记录一个独立的偏移量。多个进程各自 open 同一个物理文件时，它们的位置互不干扰。
  • 读写共享偏移：同一次 open 返回的同一个描述符上，读与写共用同一个 CFO。先读 100 字节，CFO 就后移 100 字节；紧接着写的字节会落在这 100 字节之后，而不会从头覆盖。
  • 流式文件不可定位：命名管道、匿名管道与网络套接字属于流式接口，绝对不支持设置偏移量。对这类描述符调用 lseek 或 fseek 会返回 -1，并把 errno 置为 ESPIPE。
  • 可以定位到文件结尾之后：lseek 允许把偏移量设到超出当前文件物理结尾的位置，随后写入就会产生文件空洞（file hole）。空洞部分在逻辑上被读成 �，但不占用实际磁盘扇区，因此可以极快地初始化巨型虚拟文件（如虚拟机磁盘镜像）。

注意：lseek 只改变内核记录的偏移量，不改变文件内容，也不改变文件大小——除非在超出结尾的位置发生写入，那才会把文件「撑大」并在中间留下空洞。

12.7 实战：三种打开模式 #

下面三个程序分别演示追加、独占创建、截断覆盖三种最常见的打开意图，都用 perror 在失败时打印原因。

c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main(void)
{
    int fd;

    /* 追加读写：写入的数据自动落到文件末尾 */
    fd = open("./a.c", O_APPEND | O_RDWR);
    if (fd < 0) {
        perror("Open file failure");
        return -1;
    }
    printf("Open success, fd = %d\n", fd);
    close(fd);
    return 0;
}

c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main(void)
{
    int fd;

    /* 独占创建：文件已存在则失败，适合「只能由我创建」的场合 */
    fd = open("./a.c", O_CREAT | O_EXCL, 0755);
    if (fd < 0) {
        perror("Create file failure (file might already exist)");
        return -1;
    }
    printf("Create success, fd = %d\n", fd);
    close(fd);
    return 0;
}

c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main(void)
{
    int fd;

    /* 截断覆盖：文件已存在则长度清 0，原有内容全部丢弃 */
    fd = open("./a.c", O_TRUNC | O_RDWR);
    if (fd < 0) {
        perror("Open file failure");
        return -1;
    }
    printf("Open success, fd = %d\n", fd);
    close(fd);
    return 0;
}

三者的对照关系如下：

意图 系统调用标志组合 对应的 fopen 模式 结果
追加写 O_APPEND | O_RDWR a+ 原有内容保留，新数据接在末尾
独占创建 O_CREAT | O_EXCL 无直接对应模式 文件已存在则失败
截断覆盖 O_TRUNC | O_RDWR w+ 原有内容被清空

12.8 实战：求文件大小与分块拷贝 #

利用 lseek 定位到文件结尾并读取返回的偏移量，可以快速算出文件大小：

c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int get_file_size(const char *path)
{
    int fd = open(path, O_RDONLY);
    off_t size;

    if (fd < 0) {
        return -1;
    }

    /* 定位到文件末尾，偏移 0，返回值即文件字节数 */
    size = lseek(fd, 0, SEEK_END);
    close(fd);
    return (int)size;
}

拷贝大文件时不能一次性申请与文件同样大的缓冲区（堆内存可能不够），而要用固定大小的缓冲区做块循环读写。下面给出两种循环控制算法，它们的差别集中在「最后不足一块的尾巴」怎么处理。

方案一：标准断尾循环，循环只处理满块，残余字节在循环外补写：

c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>

int main(int argc, char **argv)
{
    char read_buf[128] = {0};
    int rd_fd, wd_fd, rd_ret = 0;

    if (argc < 3) {
        printf("Usage: %s <src> <dst>\n", argv[0]);
        return -1;
    }

    rd_fd = open(argv[1], O_RDONLY);
    wd_fd = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (rd_fd < 0 || wd_fd < 0) {
        perror("Open file error");
        return -1;
    }

    while (1) {
        rd_ret = read(rd_fd, read_buf, 128);
        if (rd_ret < 128) {
            /* 不足 128 字节：读到文件尾或出错，跳出循环 */
            break;
        }
        write(wd_fd, read_buf, rd_ret);
        memset(read_buf, 0, 128);   /* 清零缓冲区，准备下一次读取 */
    }

    /* 关键一步：跳出循环时缓冲区里还残留最后一批不足 128 字节的数据 */
    if (rd_ret > 0) {
        write(wd_fd, read_buf, rd_ret);
    }

    close(rd_fd);
    close(wd_fd);
    return 0;
}

方案二：紧凑型直接解包写，读到多少就写多少，尾巴自然被覆盖：

c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main(int argc, char **argv)
{
    char buf[128];
    int fdo, fdw, ret;

    if (argc < 3) {
        printf("Usage: %s <src> <dst>\n", argv[0]);
        return -1;
    }

    fdo = open(argv[1], O_RDONLY);
    fdw = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0664);
    if (fdo < 0 || fdw < 0) {
        perror("Open file error");
        return -1;
    }

    while (1) {
        ret = read(fdo, buf, 128);
        if (ret < 0) {
            perror("Read error");
            break;
        }

        /* 读到多少就写多少，天然兼容最后不足 128 字节的尾巴 */
        write(fdw, buf, ret);

        if (ret < 128) {
            /* 返回值小于请求长度，说明已到文件尾，正常结束 */
            break;
        }
    }

    close(fdo);
    close(fdw);
    return 0;
}

两种方案的取舍：

方案 循环内逻辑 尾巴处理 风险
断尾循环 满块才写 循环外单独 write 一次 忘记补写尾巴会丢掉文件末尾
直接解包写 无条件按实际字节写 由 ret < 128 统一收尾 需先判 ret < 0，否则错误码会被当成长度写入

注意：上面两个示例都没有处理 write 的返回值小于请求字节数的情况（如磁盘已满）。工程代码应当检查每次 write 的返回值，并把未写完的部分继续写完，否则拷贝结果可能被悄悄截断。

12.9 标准库层：FILE * 与缓冲区 #

系统调用的每次读写都要陷入内核，对小粒度操作很不划算。ANSI C 标准库因此提供了一层带用户空间缓冲区的高级 I/O：用 FILE * 文件流指针（file stream pointer）代表一个打开的文件，读写先落到用户态缓冲区，攒够一批再真正调用 read / write。

这一层带来三个好处：跨平台可移植（同一份代码在 Linux、Windows 上都能编译运行）、小字节读写效率高（fputc 一百次未必触发一次系统调用）、格式化能力直接可用（fprintf / fscanf）。代价是要理解缓冲区的刷新时机，否则就会出现「数据明明写了，程序崩溃后文件里却没有」。

FILE 结构体对使用者是不透明的，内部有文件描述符、缓冲区指针、缓冲区大小、当前读写位置、错误标志与 EOF 标志。程序只应通过函数操作它，不要直接访问其成员。

12.10 fopen 的六种模式 #

c
#include <stdio.h>

FILE *fopen(const char *path, const char *mode);
int fclose(FILE *stream);

成功返回指向 FILE 结构体的流指针，失败返回 NULL 并设置 errno。mode 的六种取值及其与系统调用标志的对应关系如下：

模式 对应系统调用标志 语义
r O_RDONLY 只读打开，文件必须存在，流定位在文件开头
r+ O_RDWR 可读写打开，文件必须存在，流定位在文件开头
w O_WRONLY | O_CREAT | O_TRUNC 只写打开，存在则长度清 0 覆盖，不存在则新建
w+ O_RDWR | O_CREAT | O_TRUNC 可读写打开，存在则长度清 0 覆盖，不存在则新建
a O_WRONLY | O_CREAT | O_APPEND 追加只写，不存在则新建，写入自动落在文件尾
a+ O_RDWR | O_CREAT | O_APPEND 追加可读写，不存在则新建，写入自动落在文件尾

在上述模式后可以追加字符 b（如 rb、wb+），明确要求以二进制形式打开。Linux / POSIX 系统会忽略这个字符（文本文件与二进制文件在 Linux 下物理结构一致），但它在 Windows 上有实际作用——防止 \n 与 \r\n 之间的自动转换。

fopen 新建的文件默认权限为 0666（所有者、同组、其他用户都可读写），同样会经过 umask 掩码处理。

fclose 关闭流，关闭前会自动把用户缓冲区中残留的数据全部刷入物理文件（相当于隐式调用 fflush），然后释放系统资源。成功返回 0，失败返回 EOF（通常为 -1）。

注意：fopen 与 open 的返回类型不同——前者是 FILE *，后者是整数描述符；两者的失败返回值也不同（NULL 与 -1）。判断失败时不要写错。

12.11 四类读写函数 #

标准库的读写函数按粒度分为四类，选对类别是写出清晰代码的前提。

格式化 I/O：把变量的值按格式串转成文本，或从文本解析出变量。

c
#include <stdio.h>

int fprintf(FILE *stream, const char *format, ...);
int fscanf(FILE *stream, const char *format, ...);

字符级 I/O：一次一个字符，适合逐字符扫描。

c
#include <stdio.h>

int fgetc(FILE *stream);
int getc(FILE *stream);
int fputc(int c, FILE *stream);
int putc(int c, FILE *stream);
int getchar(void);
int putchar(int c);

getc 与 fgetc 作用完全相同，但 getc 在标准库中通常实现为宏，效率略高；putc 与 fputc 同理。getchar() 等价于 getc(stdin)，putchar(c) 等价于 putc(c, stdout)。字符级函数的返回值都是 int（而不是 char），因为要能表示 EOF 这个特殊值。

行级（字符串）I/O：一次读或写一整行。

c
#include <stdio.h>

char *fgets(char *s, int size, FILE *stream);
int fputs(const char *s, FILE *stream);
char *gets(char *s);
ssize_t getline(char **lineptr, size_t *n, FILE *stream);

fgets 从流中读字符存入 s，直到遇到换行符 \n、遇到文件尾 EOF，或已读满 size - 1 个字符为止，最后自动在末尾补 \0；换行符本身会被存入数组。成功返回首地址 s，出错或已到文件尾且未读到任何数据时返回 NULL。

注意：gets 绝对不应在工程代码中使用。它从标准输入读一行却不接受长度限制参数，输入超长就会写穿缓冲区、破坏栈，是经典的安全漏洞来源。必须用 fgets(s, sizeof(s), stdin) 替代。

getline 是 GNU 扩展，需要在使用前定义宏 _GNU_SOURCE 并包含 <stdio.h>。它的特点是自动动态伸缩：若 *lineptr 为 NULL 且 *n 为 0，它会在内部调用 malloc 申请足够空间，把地址写回 *lineptr、容量写回 *n；若容量不够，它会用 realloc 扩容并更新这两个值。成功返回实际读入的字符数（包含末尾换行符 \n，不计算终止符 \0），出错或到文件尾返回 -1。调用者必须自己 free(*lineptr)，否则内存泄漏。

数据块（二进制）I/O：读写结构体、数组等复合二进制块。

c
#include <stdio.h>

size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream);
size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream);

四个参数的语义是易错点：ptr 是缓冲区首地址；size 是每个数据块的字节大小；nmemb 是欲读写的块数量；stream 是目标流。返回值是实际成功读写的完整块数量，而不是字节数。

注意：若 fread 的返回值小于请求的 nmemb，说明读取不足——可能是到达文件尾（EOF），也可能是发生了文件错误。必须再用 feof(stream) 或 ferror(stream) 判定究竟是哪一种，不能一律当作「读完了」。

12.12 流定位与状态控制 #

c
#include <stdio.h>

int fseek(FILE *stream, long offset, int whence);
long ftell(FILE *stream);
void rewind(FILE *stream);
int feof(FILE *stream);
void clearerr(FILE *stream);
int fflush(FILE *stream);

各函数的作用与要点：

函数 作用 返回值与要点
fseek 移动流读写位置，whence 取 SEEK_SET / SEEK_CUR / SEEK_END 成功仅返回 0、失败返回 -1，不返回新位置
ftell 获取流当前绝对位置 成功返回相对文件开头的字节偏移，失败返回 -1L
rewind 把流重置到开头 无返回值，等价于 (void)fseek(stream, 0, SEEK_SET)
feof 检查是否已读到文件尾 先前有读操作越过文件尾则返回非零，否则返回 0
clearerr 清除错误标志与 EOF 标志 无返回值
fflush 强制刷新输出缓冲区 参数为 NULL 时刷写所有打开的流

lseek 与 fseek 的最大差别正在返回值：lseek 成功时直接给出新的绝对偏移，而 fseek 只报告成败，想知道定位后的位置必须额外调用 ftell。这是从系统调用层迁移到标准库层时最容易出错的一处。
