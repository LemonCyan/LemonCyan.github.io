CI和CD

🚀 一、CI/CD 是什么？一句话解释 #

CI/CD = 自动化地构建、测试、部署软件的方式。

它的目标是：

  • 减少人工操作

  • 降低出错率

  • 让软件可以频繁、快速、安全地上线

🧩 二、拆开来看：CI 和 CD 分别是什么？ #

1️⃣ CI = Continuous Integration（持续集成） #

关键词：自动构建 + 自动测试

通俗解释：

每次你写完代码，只要提交到代码仓库（如 GitHub/GitLab），系统就自动帮你：

  • 拉代码

  • 编译

  • 跑测试

  • 检查有没有 bug

不需要人手动跑。

这样做的目的：

  • 越早发现 bug 越便宜

  • 防止代码冲突积累

  • 提高代码质量

2️⃣ CD = Continuous Delivery / Continuous Deployment（持续交付/持续部署） #

它有两个版本：

📌 Continuous Delivery（持续交付） #

自动构建 & 自动测试 ✔ 自动打包成可发布版本 ✔ 部署到生产环境需要人确认 ❗

适用于：希望上线前人工审核的团队。

📌 Continuous Deployment（持续部署） #

自动构建 ✔ 自动测试 ✔ 自动部署 ✔ 全部自动，无需人工点按钮

适用于：成熟、自动化强、测试覆盖率高的团队。

🎯 三、CI/CD 的核心目标 #

目标 解释
自动化 减少人工执行构建、测试、部署
快速且稳定交付软件 小改动也能安全上线
提高质量 自动化测试保障稳定性
降低风险 小步快跑，每次上线变得简单安全

🔧 四、CI/CD 一般是怎么运行的？（完整流程） #

👇 一个最典型的 CI/CD 流水线（Pipeline）：

cpp
开发者提交代码  -->  CI 自动执行：构建 → 测试 → 静态分析
                           ↓
                CD 自动执行：打包 → 部署到测试环境 → 自动化测试
                           ↓
                     (可选) 人工确认
                           ↓
                    自动部署到生产环境

你可以理解为：

软件上线这件事，整个流程都自动帮你干了。

🛠 五、常用 CI/CD 工具（你肯定见过） #

SaaS 类（最容易入门） #

工具 特点
GitHub Actions GitHub 自带，最简单
GitLab CI GitLab 内置，企业用很多
CircleCI 快速易用
Travis CI 老牌工具

自建类（企业常用） #

工具 特点
Jenkins 最强，插件多，但复杂
Drone CI 云原生
Argo CD 专注 Kubernetes 部署

作为新手，GitHub Actions 是最友好且免费的入门工具。

📦 六、实际例子：一个最简单的 CI（持续集成） #

假设你用 GitHub，把下面文件放进仓库：

.github/workflows/ci.yml

yaml
name: CI Demo

on:
  push:
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: 拉取代码
        uses: actions/checkout@v3

      - name: 安装依赖
        run: npm install

      - name: 跑测试
        run: npm test

提交代码后，GitHub 会自动做这些事：

✔ 拉代码 ✔ 安装依赖 ✔ 执行测试

你不需要点任何按钮。

🚀 七、实际例子：一个简单 CI/CD（自动部署） #

把代码推到 main 分支后，自动部署到服务器：

yaml
name: CI/CD

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - name: 构建项目
        run: npm build

      - name: 部署到服务器
        run: |
          scp -r ./dist user@your-server:/var/www/html

这就是一个最基础的 CI/CD。

💡 八、为什么现代开发必须用 CI/CD？ #

1. 没 CI/CD： #

  • 手动构建

  • 手动测试

  • 手动部署

  • 一次上线几小时

  • 很容易出错

2. 有 CI/CD： #

  • 自动构建

  • 自动测试

  • 自动部署

  • 一次上线几分钟

  • 错误大幅减少

你想想，开发者一天提交几十次代码，没有自动化几乎不可能维护。

🧭 九、企业中常见的 CI/CD 流程（高级版） #

企业 CI/CD 会更复杂：

  • 静态代码检查（Lint、SonarQube）

  • 单元测试、集成测试、端到端测试

  • 容器镜像构建（Docker）

  • 推送到镜像仓库（Harbor、ECR）

  • 灰度发布（蓝绿部署、金丝雀发布）

  • 自动回滚

  • 监控报警（Prometheus）

但万变不离其宗：

all about 自动化、可重复、安全 的上线流程。

🎓 十、你作为新手应如何入门？ #

建议学习路线：

① 理解基础概念 #

CI、CD、Pipeline、Runner、构建、测试、部署

② 选择入门工具 #

GitHub Actions（新手最友好）

③ 从简单的 CI 开始 #

自动测试、自动构建

④ 再升级为自动部署 #

部署静态网站、Docker 部署、服务器部署

⑤ 了解企业级流程 #

Kubernetes、ArgoCD、Jenkins、GitLab CI
