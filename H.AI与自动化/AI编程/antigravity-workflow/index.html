Antigravity 工作流入门指南：从零开始设计你的自动化助手 #

本文将带你从零开始理解 Antigravity 的工作流机制，并学会设计属于自己的自动化工作流。

什么是 Antigravity 工作流？ #

Antigravity 是一个强大的 AI 编码助手，它不仅能理解你的意图，还能通过**工作流（Workflow）**机制将复杂任务分解成可复用的步骤。

工作流本质上是一份 Markdown 格式的指令文档，存放在项目根目录的 .agent/workflows/ 文件夹下。当你告诉 Antigravity 执行某个工作流时，它会按照文档中定义的步骤依次执行。

工作流的核心价值 #

痛点 工作流解决方案
重复性任务每次都要重新描述 一次定义，多次调用
执行步骤容易遗漏 标准化流程确保完整性
协作时口径不一致 团队共享同一份工作流
复杂任务需要多次交互 一键触发自动执行

工作流文件结构 #

一个标准的工作流文件由两部分组成：

1. YAML 前置元数据 #

yaml
---
description: 这里简要描述工作流的用途
---
  • description：必填，用一句话说明这个工作流做什么

2. Markdown 正文：具体步骤 #

markdown
## 前置条件
- 确保已安装 Node.js 环境
- 确保 `.env` 文件已配置

## 执行步骤

1. 读取当前目录下的 `config.json` 文件
2. 根据配置生成对应的模板文件
3. 运行 `npm run build` 构建项目
4. 将构建产物复制到 `dist/` 目录

💡 提示：步骤描述越具体，Antigravity 执行越准确。避免模糊的指令如"处理一下"。

快速上手：创建你的第一个工作流 #

场景：自动化发布博客文章 #

假设你每次发布文章都需要：

  1. 检查文章格式
  2. 添加 SEO 元数据
  3. 生成摘要
  4. 复制到发布目录

让我们将这个流程固化为工作流：

Step 1: 创建工作流文件 #

在项目根目录创建文件：.agent/workflows/publish-blog.md

Step 2: 编写工作流内容 #

markdown
---
description: 自动化发布博客文章到指定目录
---

## 前置条件
- 文章文件必须是 `.md` 格式
- 文章必须包含 YAML 前置元数据

## 执行步骤

1. 读取用户指定的文章文件
2. 检查文章格式是否符合规范：
   - 必须包含 `title` 字段
   - 必须包含 `date` 字段
   - 必须包含 `categories` 字段
3. 如果缺少 `description` 字段，根据正文前 200 字生成摘要
4. 检查文章中的图片链接是否有效
5. 将处理后的文章复制到 `source/_posts/` 目录
6. 输出发布成功的确认信息，包含文章标题和发布路径

Step 3: 调用工作流 #

在与 Antigravity 对话时，使用斜杠命令触发：

/publish-blog 请发布 source/_drafts/我的新文章.md

Antigravity 会自动加载 .agent/workflows/publish-blog.md 并按步骤执行。

进阶技巧 #

1. 使用 // turbo 加速执行 #

在步骤前添加 // turbo 注释，可以让该步骤自动执行，无需用户确认：

markdown
2. 创建 build 目录
// turbo
3. 运行 npm install
// turbo
4. 运行 npm run build

步骤 3 和 4 会自动执行，跳过确认环节。

2. 使用 // turbo-all 全量加速 #

在工作流任意位置添加 // turbo-all，所有命令执行步骤都会自动运行：

markdown
---
description: 快速构建项目
---

// turbo-all

## 执行步骤
1. 删除旧的 build 目录
2. 安装依赖
3. 执行构建
4. 运行测试

⚠️ 警告：// turbo-all 适用于你完全信任的工作流。对于涉及删除文件、修改配置等敏感操作，建议保持人工确认。

3. 条件分支处理 #

通过清晰的条件描述，让 Antigravity 根据情况选择不同路径：

markdown
3. 检查 `package-lock.json` 是否存在：
   - 如果存在：运行 `npm ci`
   - 如果不存在：运行 `npm install`

4. 变量与动态内容 #

使用占位符描述动态内容，让工作流更灵活：

markdown
1. 读取用户指定的源文件
2. 将文件中的 `{{DATE}}` 替换为当前日期
3. 将文件中的 `{{AUTHOR}}` 替换为 `config.json` 中的作者名

如何在工作流中嵌入 MCP #

MCP (Model Context Protocol) 允许 Antigravity 连接外部工具和数据源（如网络搜索、数据库、API 接口等），极大地扩展了工作流的能力边界。

在工作流中使用 MCP 非常简单——像指挥人类助手一样，在步骤中明确描述你要使用的工具即可。

1. 核心逻辑 #

Antigravity 会根据你的步骤描述，智能匹配已安装的 MCP 工具。

  • 无需写代码：不用关心工具底层的 API 调用。
  • 自然语言驱动：准确描述"做什么"比"怎么做"更重要。

2. 在步骤中调用 #

你可以在任意步骤中穿插对 MCP 工具的调用指令。

基础写法：

markdown
1. 使用联网搜索工具查询 "2024年前端开发趋势"
2. 读取搜索结果的前 5 篇文章摘要

结合上下文：

markdown
1. 读取项目根目录的 `package.json`
2. 使用 `npm-search` 工具查询每个依赖包的最新版本
3. 生成一份升级建议报告

3. 混合编排实战示例 #

下面是一个结合了 本地文件操作 + 联网搜索 (MCP) + 文件生成 的强大工作流：

markdown
---
description: 竞品分析报告生成器
---

## 执行步骤

1. 读取当前目录下的 `product_features.md` (产品功能列表)
2. 提取文件中的核心功能关键词
3. 针对每个关键词，使用 `search_web` 工具搜索市场上的类似产品
   - 重点关注：定价策略、用户评价、优缺点
4. 使用 `browser` 工具访问搜索到的前 3 个竞品官网，抓取详细文案
5. 综合以上信息，生成 `competitor_analysis.md` 报告

💡 提示：

  • 显式指定：如果你知道具体的工具名称（如 brave-search 或 filesystem），在步骤中明确写出来（例如"使用 brave-search 搜索..."）可以提高执行的准确度。
  • 前置说明：建议在工作流开头的前置条件中简要说明依赖哪些 MCP 服务器，方便协作者提前安装。

实用工作流示例 #

示例 1：项目初始化 #

markdown
---
description: 初始化新项目的标准结构
---

## 执行步骤

1. 创建以下目录结构：
   - `src/` - 源代码目录
   - `tests/` - 测试目录
   - `docs/` - 文档目录
   - `assets/` - 静态资源目录

2. 创建 `.gitignore` 文件，包含常见忽略规则

3. 创建 `README.md` 模板文件

// turbo
4. 运行 `git init` 初始化 Git 仓库

5. 输出初始化完成的确认信息

示例 2：代码审查清单 #

markdown
---
description: 执行代码审查的标准检查流程
---

## 执行步骤

1. 检查是否有未使用的导入语句
2. 检查函数是否有适当的注释/文档
3. 检查是否存在硬编码的敏感信息（API Key、密码等）
4. 检查命名是否符合项目规范
5. 检查是否有重复代码可以抽取
6. 生成审查报告，保存到 `review-report.md`

示例 3：文章生成工作流 #

markdown
---
description: 根据灵感一句话生成完整文章
---

## 前置条件
- 需要配置 MCP 工具（searchweb, unsplash 等）

## 执行步骤

1. 根据用户提供的灵感进行联网搜索调研
2. 整理搜索结果，生成调研报告保存到「调研报告」文件夹
3. 分析用户历史文章标题风格，创作 3-5 个候选标题
4. 根据用户选择的标题撰写正文（1500-3000 字）
5. 使用 Unsplash MCP 搜索相关图片并插入文章
6. 将完成的文章保存到「AI 创作」文件夹，文件名使用文章标题

最佳实践 #

✅ 推荐做法 #

做法 说明
步骤原子化 每个步骤只做一件事，便于追踪和调试
明确输出 每个关键步骤说明预期输出是什么
包含校验 添加检查点确保前序步骤成功
版本管理 将 .agent/workflows/ 纳入 Git 管理
命名规范 文件名使用小写字母和连字符，如 deploy-prod.md

❌ 避免的做法 #

做法 问题
步骤太笼统 "把项目处理好" → Antigravity 不知道具体做什么
缺少前置条件 工作流可能因环境问题失败
硬编码路径 换环境就失效，使用相对路径或配置文件
忽略错误处理 添加"如果失败则..."的处理说明

常见问题 #

Q: 工作流文件放在哪里？ #

A: 必须放在项目根目录的 .agent/workflows/ 文件夹下。

Q: 如何触发工作流？ #

A: 使用 /工作流名称 的斜杠命令格式，例如 /publish-blog。

Q: 工作流支持中文文件名吗？ #

A: 支持，但建议使用英文小写和连字符命名，避免编码问题。

Q: 工作流可以调用其他工作流吗？ #

A: 可以在步骤中描述"执行 xxx 工作流"，Antigravity 会理解并执行。

Q: 如何调试工作流？ #

A:

  1. 先手动逐步执行，确认每步都能成功
  2. 观察 Antigravity 的执行输出，找出卡住的步骤
  3. 细化问题步骤的描述，添加更多上下文

总结 #

Antigravity 工作流是一种将你的重复性工作固化成自动化流程的强大机制：

  1. 创建简单：只需一个 Markdown 文件
  2. 调用便捷：斜杠命令一键触发
  3. 灵活可控：支持条件分支、加速执行等进阶功能
  4. 团队共享：纳入版本管理，团队统一执行标准

现在就动手创建你的第一个工作流吧！从最常做的重复性任务开始，逐步构建你的自动化工具库。
