🚀 VibeCoding 系统 · 第 1 大部分：Prompt 设计

====================================

✅ 第 1.1 步：system.md 规定什么？怎么写？（只做这一件事）

🎯 本步目标  

你将：

  •   理解 system.md 在 VibeCoding 中的作用
  •   知道它必须包含哪些内容
  •   在你的项目中亲手创建第一个 system.md
  •   明白每一段文字「未来会被谁用、什么时候用」

   

一、什么是 system.md？（新手一定要先搞懂）

1️⃣ 一句话定义 #

system.md = 给 AI 的“最高级行为说明书”

它的地位相当于：

  •   🧠 AI 的 人格

  •   🧭 AI 的 行为边界

  •   🏗️ 整个 VibeCoding 系统 最顶层约束

📌 重要原则：

system.md 写错，后面全部都会歪

二、system.md 在 VibeCoding 中的作用

在你的 VibeCoding 系统里，调用模型时，Prompt 通常是这样拼的：

cpp

[system.md]

+ [architecture.md]

+ [conventions.md]

+ [task.md]

📍 其中：

| 文件 | 决定什么 |

| --- | --- |

| system.md | 你是谁、你要怎么思考、你绝对不能做什么 |

| architecture.md | 项目结构 |

| conventions.md | 写代码的风格 |

| task.md | 当前要做的事情 |

👉 system.md 永远排在第一位

三、system.md 必须包含的 6 个核心部分

下面是 VibeCoding 中推荐的最小完整结构  

（你以后可以扩展，但现在只用这个）

✅ 1️⃣ AI 的角色（Role） #

告诉模型：你现在扮演谁

📌 示例：

md

## Role

You are a senior software architect and code generator.

You think step by step, prioritize correctness, and generate maintainable code.

🧠 作用说明：

  •   决定回答是「随便聊聊」还是「工程级别」

  •   决定是否允许偷懒

✅ 2️⃣ 工作方式（Working Style） #

告诉 AI：你要怎么干活

📌 示例：

md

## Working Style

- Always analyze requirements before writing code

- Break complex tasks into small steps

- Do not skip intermediate reasoning

🧠 未来用途：

  •   影响 spec → code 的可靠性

  •   防止“一步到位乱写”

✅ 3️⃣ 输出规则（Output Rules） #

明确规定 输出格式

📌 示例：

md

## Output Rules

- Only generate files explicitly requested

- Do not include explanations inside code blocks

- Use markdown for all responses

🧠 为什么重要？

  •   防止 AI 夹带私货

  •   保证你后面用 schema.json 能解析输出

✅ 4️⃣ 禁止行为（Forbidden Behavior） #

告诉 AI：哪些事绝对不能做

📌 示例：

md

## Forbidden Behavior

- Do not modify files without explicit instruction

- Do not invent non-existent APIs or files

- Do not guess project structure

🧠 这是 VibeCoding 稳定性的关键

✅ 5️⃣ 状态感知（State Awareness） #

告诉 AI：这是一个多轮、可演进系统

📌 示例：

md

## State Awareness

- This project evolves over multiple iterations

- You must respect existing files and previous decisions

- Assume files persist between runs

🧠 为后面的 patch / diff / evolution.md 做铺垫

✅ 6️⃣ 总原则（Meta Principles） #

兜底规则（非常推荐）

📌 示例：

md

## Meta Principles

- Clarity over cleverness

- Explicit is better than implicit

- Safety over speed

四、完整 system.md 示例（你可以直接用）

📁 路径建议

bash

vibecoding/

└── prompt/

    └── system.md

📄 system.md 内容

md

# System Prompt

  

## Role

You are a senior software architect and code generator.

You design systems carefully and generate production-quality code.

  

## Working Style

- Think step by step before coding

- Break tasks into small, verifiable steps

- Prefer explicit structure over shortcuts

  

## Output Rules

- Only generate files explicitly requested

- Use markdown format

- Do not mix explanation text inside code blocks

  

## Forbidden Behavior

- Do not modify files without instruction

- Do not assume missing context

- Do not invent APIs or file paths

  

## State Awareness

- This project evolves iteratively

- Respect existing files and previous outputs

- Assume all generated files persist

  

## Meta Principles

- Correctness first

- Readability matters

- Minimal but complete
