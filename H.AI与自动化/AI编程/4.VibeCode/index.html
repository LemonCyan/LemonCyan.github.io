VibeCode

介绍 #

什么才叫「Vibe Coding」？Vibe Coding 不是“有没有 AI”。而是 你和 AI 的协作方式发生了改变。我们可以这样分层来看

第一层：编程辅助 #

这是大多数人以为的 AI 编程：

  • 我写代码
  • 卡住了
  • 问一下 AI
  • 再继续写 你现在做的事情包括：
  • 选中代码 → 让 AI 解释
  • 让 AI 找 bug
  • 让 AI 优化 这是“AI = 高级搜索 + 解释器”。 有用，但 不是 Vibe Coding 的核心

第二层：Vibe Coding #

关键变化只有一个：你不再“写实现”，而是“描述意图”。你会变成这样：

  • 你：“我要一个能解析日志的工具，支持过滤、统计、导出 CSV”
  • AI：
    • 生成完整项目结构
    • 写核心代码
    • 写测试
  • 你：
    • 调整方向
    • 修正需求
    • 说“这个感觉不对” 你在“调 vibe”，不是写 for 循环。Vibe Coding = IDE + 项目上下文 + 快速迭代

Step A：让 AI 生成而不是解释 #

  • 一句话：

    “给我生成一个 Python CLI，用于处理日志”

  • AI：

    • 生成项目结构
    • 直接落盘到文件

Step B：让 AI 重写整个模块 #

  • 你不选一段
  • 你选 整个文件 / 整个目录
  • AI 给你一个 新版本

Step C：你只负责感觉对不对 #

  • 不关心细节
  • 只关心：
    • 是否好维护
    • 是否优雅
    • 是否符合预期

第 1 阶段 生成 #

从「我写代码」→「我描述意图」。你不写实现，只给方向，代码由 AI 落地

第 1 步：让 AI 直接「生成项目结构 + 文件」

prompt 改成：

“我要一个 Python CLI 工具，用来分析日志文件，支持按关键词过滤，并输出统计结果。”

然后你的目录里直接出现：

cpp
log_analyzer/ 
├── README.md 
├── main.py 
├── analyzer.py 
├── requirements.txt

不是复制粘贴 ，不是聊天 ，是 直接落盘

脚本 #

python
import os 
import sys 
import json 
import requests  
API_KEY = os.getenv("DASHSCOPE_API_KEY") 
if not API_KEY:     
	print("❌ 未检测到 DASHSCOPE_API_KEY")     
	sys.exit(1)  

prompt = sys.argv[1]  
SYSTEM_PROMPT = """ 
你是一个资深软件工程师。 请根据用户需求： 
1. 设计项目目录结构 
2. 生成所有必要文件 
3. 输出 JSON，格式如下：  
{   
"project_name": "xxx",   
"files": {     
"path/to/file1.py": "文件内容",     
"README.md": "说明"   
} 
}  
不要输出多余文字，只输出 JSON。 """ 
resp = requests.post(     
	"https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation",     
	headers={         
		"Authorization": f"Bearer {API_KEY}",         
		"Content-Type": "application/json"     },     
	json={         
		"model": "qwen-turbo",         
		"input": {             
			"messages": [                 
				{"role": "system", "content": SYSTEM_PROMPT},                 
				{"role": "user", "content": prompt}             
			]         
		}     
	} 
)  

data = resp.json() 
content = data["output"]["text"]  
spec = json.loads(content)  
root = spec["project_name"] 
os.makedirs(root, exist_ok=True)  
for path, code in spec["files"].items():     
	full = os.path.join(root, path)     
	os.makedirs(os.path.dirname(full), exist_ok=True)     
	with open(full, "w", encoding="utf-8") as f:         
		f.write(code)  
print(f"✅ 项目已生成：{root}")

第 2 阶段 重构 #

从「生成代码」→「调感觉、调结构、调方向」。这一阶段的核心只有一句话：

结构判断练习 #

打开刚刚生成的项目目录，在 VS Code 里：

  • 打开 ~/vibe/你刚生成的项目
  • 只看文件名，不看内容 然后问自己 3 个问题：
  1. 这个结构我 3 个月后还能维护吗？
  2. 职责有没有混在一起？
  3. 如果加新功能，往哪里加？ 你不需要答案 ，你只需要一个感觉： 顺 / 别扭

用一句话让 AI 重构整个项目 #

shell
python3 qwen_generate.py "重构刚才生成的项目：让核心逻辑和 CLI 解耦，结构更清晰，方便后续扩展"
  • 你没有指定怎么重构
  • 你只描述 “感觉标准”

第 3 阶段 持续演化 #

① 让 AI 持续演进一个真实项目 #

  • 一次次“感觉不对就重来”
  • 最终做出一个你会用的工具
