Antigravity 自定义 MCP Server 配置指南 #

Model Context Protocol (MCP) 是一个开放标准，允许 AI 助手（如 Antigravity）通过标准化的方式连接外部数据和工具。

Antigravity 允许你通过修改配置文件来接入任何符合 MCP 标准的服务器。以下是从零开始的详细配置教程。

1. 核心概念 #

在 MCP 架构中：

  • Host (客户端)：即 Antigravity，它负责发送请求。
  • Server (服务端)：提供工具（Tools）、资源（Resources）或提示词（Prompts）的程序。它通常是一个在本地运行的命令行进程（如 Python 脚本或 Node.js 程序）。

配置的核心就是告诉 Antigravity：如何启动这个服务进程。

2. 准备工作 #

2.1 确认环境 #

大多数 MCP Server 依赖 Python 或 Node.js 运行环境。

  • 如果你使用 Python 编写的 Server，请确保安装了 python (建议 3.10+)。
  • 如果你使用 Node.js 编写的 Server，请确保安装了 node 和 npm。

2.2 获取或创建一个 MCP Server #

你可以使用现成的 Server，也可以自己写。

✅ 示例 A：使用现成的 Server (例如 SQLite) 假设你想让 Antigravity 能查询本地的 SQLite 数据库。你需要先安装该 Server：

bash
pip install mcp-server-sqlite

安装后，你可以通过命令行 mcp-server-sqlite --db-path ./test.db 启动它（这只是测试，不需要手动运行，Antigravity 会自动运行）。

✅ 示例 B：创建一个最简单的自定义 Server (Python) 创建一个文件 D:\my-mcp-server\weather_server.py：

python
from mcp.server.fastmcp import FastMCP

# 初始化 Server
mcp = FastMCP("Weather Demo")

@mcp.tool()
def get_weather(city: str) -> str:
    """获取指定城市的天气信息"""
    return f"{city} 的天气是晴天，气温 25°C"

if __name__ == "__main__":
    mcp.run()

需要安装依赖：pip install mcp

3. 定位配置文件 #

Antigravity 的 MCP 配置文件通常位于你的用户目录下的 .gemini 文件夹中。

Windows 路径：

C:\Users\liuluhua\.gemini\antigravity\mcp_config.json

注意：如果该文件不存在，你可以手动创建一个。

4. 编辑配置 #

用你喜欢的编辑器（VS Code 或记事本）打开 mcp_config.json。结构如下：

json
{
  "mcpServers": {
    "<Server名称>": {
      "command": "<可执行程序>",
      "args": ["<参数1>", "<参数2>", ...],
      "env": {
        "<环境变量名>": "<值>"
      }
    }
  }
}

实战配置 #

我们将上面准备的两个 Server 配置进去。

修改 mcp_config.json 如下：

json
{
  "mcpServers": {
    "sqlite_tools": {
      "command": "python",
      "args": [
        "-m",
        "mcp_server_sqlite",
        "--db-path",
        "D:\\data\\my_database.db"
      ]
    },
    "my_weather_bot": {
      "command": "python",
      "args": [
        "D:\\my-mcp-server\\weather_server.py"
      ]
    }
  }
}

关键点说明：

  1. command：启动命令。如果是 Python 脚本，通常是 python 或 uv (如果你用 uv 管理)。如果是 Node.js，通常是 node。
  2. args：参数列表。注意 Windows 路径中的反斜杠 \ 需要根据 JSON 规范转义为 \\，或者使用正斜杠 /。
  3. env（可选）：如果有 API Key 等敏感信息，不要写在代码里，可以通过 env 字段注入。例如：
    json
    "env": {
  "API_KEY": "sk-cx123..."
}

5. 验证与使用 #

配置完成后，按以下步骤验证：

  1. 重启 Antigravity：确保它重新读取配置文件。

  2. 测试工具： 在对话框中直接通过自然语言请求。

    • 对应 my_weather_bot:

      "请帮我查一下北京的天气。"

      Antigravity 应该会识别到 get_weather 工具并调用它，返回 "北京的天气是晴天..."。

  3. 调试： 如果工具没有生效，检查 Antigravity 的日志（通常在 .gemini 目录下的日志文件中，或通过界面上的 Output 面板），查看是否有启动 Server 失败的报错（如路径错误、缺少依赖等）。

6. 进阶：在工作流中使用 #

一旦配置成功并验证通过，你就可以在 Markdown 工作流中像引用内置工具一样引用它们了。

在 .agent/workflows/check-weather.md 中：

markdown
## 前置条件
- MCP Server `my_weather_bot` 已运行

## 执行步骤
1. 使用 `get_weather` 工具查询 "上海" 的天气
2. 根据天气情况生成一份出行建议

常见问题排查 #

  • 路径错误：Windows 下绝对路径可以写成 D:/project/script.py (推荐) 或 D:\\project\\script.py。
  • 环境问题：如果你的 Python 安装在虚拟环境中，command 字段建议写 python解释器的绝对路径，例如 "d:/envs/myenv/Scripts/python.exe"，以确保依赖包能被找到。
  • stdio 通信：MCP 默认使用标准输入/输出 (stdio) 通信。请确保你的 Server 脚本不要打印任何无关的日志（如 print("debug info")）到标准输出，这会破坏协议格式。日志应该打印到 stderr。
