MCP Server Configuration and Usage Guide #

This guide explains how to manage the MCP services (plugins) configured in the system.

Configuration File #

The core configuration is located at: c:\Users\liuluhua\.gemini\antigravity\mcp_config.json

1. How to Add and Configure a New MCP Server #

To add a new service, you must verify the mcp_config.json file and add a new entry to the plugins array.

Configuration Structure #

Each service is defined as a JSON object with the following fields:

json
{
    "name": "service-name",
    "source": "./plugins/service-directory",
    "description": "Description of the capabilities provided",
    "version": "1.0.0",
    "category": "category-name",
    "strict": false,
    "commands": [
        "./commands/related-command.md"
    ],
    "agents": [
        "./agents/specialized-agent.md"
    ],
    "skills": [
        "./skills/specific-skill"
    ]
}

Field Definitions #

  • name: A unique identifier for the service (e.g., git-pr-workflows).
  • source: The path to the plugin's source code or definition files.
  • description: A human-readable summary of what the service does.
  • category: The grouping for the service (e.g., development, security, productivity).
  • commands: A list of paths to Markdown files that define executable workflows or commands associated with this service.
  • agents: A list of paths to Markdown files that define specialized agent personas (e.g., code-reviewer.md).
  • skills: A list of paths to directories or files defining specific skills or knowledge bases.

2. How to Use Configured MCP Servers #

Once a service is added to mcp_config.json, its capabilities (Commands, Agents, Skills) become available for use.

Using Commands #

Services often expose specific Commands (listed in the commands array). These generally correspond to workflows or specific tasks.

  • Usage: You can trigger these by asking the assistant to perform the specific action described by the command.
  • Example: If a service has a command ./commands/doc-generate.md, you can ask: "Generate documentation for the current file."

Using Specialized Agents #

Services define Agents (personas) tailored for specific tasks (listed in the agents array).

  • Usage: You can explicitly ask the assistant to adopt a specific persona to handle a task with domain-specific expertise.
  • Example: "Act as a security-auditor to check this file for vulnerabilities." (if security-auditor.md is configured).

Using Skills #

Skills provide the assistant with specific technical knowledge or patterns (e.g., react-state-management).

  • Usage: These are passively available. The assistant will utilize this knowledge when answering relevant questions. You can also explicitly ask to apply a specific skill pattern.
  • Example: "Refactor this component using the state management patterns from the frontend-mobile-development service."

Reference #

To see a full list of currently configured services and their descriptions, please refer to: MCP ReadMe
