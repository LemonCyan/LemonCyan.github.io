精度缩放和数据压缩

在存储精度不够的情况下，是否可以通过“乘以 π（pi）”来做某种压缩或保精度的技巧？

这是一个非常有意思的问题，涉及精度缩放与数据压缩的技巧。

一、“乘以 π 再除以 π”是否能提高精度？ #

✅ 理论分析 #

  1. 乘以 π 并不会提升精度

    • 如果你将一个高精度的数 x 乘以 π 后再存储，那么该数值变为 xπ。
    • 在还原时再除以 π，可以得到 xπ/π = x。
    • 但是！如果存储空间精度不足，存储的 xπ 已经无法保留原有的高精度。此外，由于 π 是无理数，存储和还原过程中可能引入额外误差。
    • 实际案例：
      • 原始数据：x = 1.234567890123456789
      • 存储精度：小数点后 6 位
      • 计算：xπ ≈ 3.877681995，但因存储限制只保留 3.87768
      • 还原：3.87768 / π ≈ 1.2345660，误差达 0.00002789

  2. π 不是精度提升因子

    • π 本身并不是一个“特殊的压缩比例”，在二进制浮点表示时需要较多位数表示，这会增加存储开销。
      • π 的二进制表示：11.00100100001111110110101010001010011010001000100...（无限不循环）
      • 这意味着使用 π 作为缩放因子会让数据在存储和计算时更加复杂。

二、业界是如何解决这种精度存储问题的？ #

1. 缩放比例（Scale Factor）是可行方式 #

  • 缩放比例法：
    • 原理：将浮点数乘以一个固定比例 10ⁿ，然后存储为整数。
    • 优势：
      • 避免了浮点数运算中的误差
      • 整数运算性能更高
      • 存储空间更节省
    • 实践案例：
原始数据 缩放因子 存储方式 存储结果 恢复方式 恢复结果
1.2345 10⁴ int32 12345 /10000 1.2345
  • 适用场景：
    • 数据集中存储（数据库、日志）
    • 网络传输
    • 嵌入式系统

2. 定点数（Fixed-Point Number） #

  • 核心概念：

    • 将数值分为整数部分和小数部分（通过固定的小数位数）
    • 相当于通过“人为规定精度”，在牺牲数值范围的同时，提高精度

  • 实现方式：

    • 使用更多位数表示小数部分
    • 严格控制精度范围

  • 实践案例：

    • 温度控制系统：

      • 使用 16 位整数的存储空间
      • 整数部分：高 8 位（表示 -127°C 至 127°C）
      • 小数部分：低 8 位（精度 0.00390625°C）

    • 存储示例：

      • 36.8°C → 存储为 3694（即 36 + 0.8 * 256）
      • 解码：3694 / 256 = 36.8°C

3. 量化（Quantization） #

  • .working 原理：

    • 将数值映射到特定的范围，使用更小的数据类型存储。
    • 常见方式：将 float32 数据映射为 uint8 或 int16 存储。

  • 步骤：

    1. 确定数值范围 [min, max]
    2. 计算缩放因子 scale = (max - min) / (255)
    3. 进行正规化和量化
    4. 存储时用更小的数据类型
    5. 解码时还原缩放因子

  • 实践案例：

原始数据范围 存储类型 量化方式 存储示例 恢复示例
0.0V~5.0V uint8 v * 255 /5 168 168 *5 /255 ≈3.3V
  • 优点：
    • 极大缩减存储空间
    • 适合大规模数据场景
    • 硬件加速支持

4. 自定义结构压缩（Bit Packing） #

  • 核心思想：

    • 根据实际需求，将多个数值打包存储，每个数值只分配必要的位数。

  • 实践案例：

数据类型 数据范围 分配位数 függ 参数
温度 -40~85 8 位 0.5°C 精度
湿度 0~100 7 位 1% RH 精度
  • 实现方法：
    • 使用位操作组合数据
    • 自定义解析规则

三、总结建议 #

方法 是否推荐 行业应用 优点 缺点
乘以 π 再除以 π ❌ 很少 看起来巧妙 实际效果差、误差大
缩放并存储为整数 ✅ 常见 simple、稳定 需提前确定缩放比例
定点数表示 ✅ .embedded 控制精度、节省空间 有限制范围和复杂度
量化存储 ✅ 广泛 高效存储、快速处理 有损、需仔细设计
自定义 bit 打包 ✅ 特殊场景 最大化空间利用 可移植性差、维护复杂
