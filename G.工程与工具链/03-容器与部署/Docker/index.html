1. Docker 概述与核心架构 #

Docker 是一个开源的应用容器引擎，基于 Linux 内核的命名空间（Namespace）、控制组（cgroups）以及联合文件系统（UnionFS）等技术，将应用程序及其依赖环境打包为一个轻量级、可移植、自包含的沙箱容器。

1.1 核心组件 #

  • Docker 守护进程（Docker Daemon / dockerd）：运行在宿主机后台的核心服务，负责监听 Docker API 请求，管理镜像、容器、网络和数据卷等对象。
  • Docker 客户端（Docker Client / docker）：用户与 Docker 交互的主要命令行工具，通过 REST API 与 Docker Daemon 通信。
  • Docker 镜像（Image）：只读模板，包含容器运行所需的操作系统环境、应用程序、配置文件及依赖库。
  • Docker 容器（Container）：镜像的运行实例。基于写时复制（Copy-on-Write, CoW）技术，容器在只读镜像层之上创建专属的可写容器层，运行时的所有文件增删改均记录在可写层。
  • Docker 镜像仓库（Registry）：用于集中存储和分发镜像的托管服务（如 Docker Hub、阿里云容器镜像服务等）。

1.2 名词解释 #

  • 镜像（Image）：类似于 GHOST 打包的 .GHO 系统镜像文件，或者各种系统的 ISO 光盘镜像，可以视为静态的系统快照。
  • 容器（Container）：类似于从某个具体的镜像启动的虚拟机实例，可以视为从某个系统快照恢复过来的正在运行的系统。

1.3 版本选型 #

  • docker.io：Debian/Ubuntu 官方源打包版本，使用 APT 管理系统依赖，适合轻量快速部署。
  • docker-ce：Docker 官方维护的社区免费版（Community Edition），推荐生产环境使用。
  • docker-ee：Docker 官方维护的企业商业版（Enterprise Edition），提供企业级支持与安全扫描。
  • Docker Desktop：官方提供的跨平台桌面图形化发行版（Windows / macOS / Linux），内置 CLI、Compose、Kubernetes 与图形面板，适合本地开发调试。

2. 安装部署 #

2.1 Ubuntu：apt 安装 Docker CE（命令行版） #

  • 添加 Docker 的 apt 仓库：

    bash
    sudo apt update
sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo \
  "deb [arch="$(dpkg --print-architecture)" signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  "$(. /etc/os-release && echo "$VERSION_CODENAME")" stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update

  • 安装 Docker 相关的包：

    bash
    sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

  • 启动服务与设置开机自启：

    bash
    sudo systemctl start docker
sudo systemctl enable docker

  • 测试 Docker 是否已成功安装：

    bash
    sudo docker run hello-world

    也可以直接使用官方源里的 docker.io 版本（更省事，但不含 buildx / compose 插件）：

    bash
    sudo apt update
sudo apt install -y docker.io

2.2 Ubuntu：安装 Docker Desktop（图形界面，可选） #

  • 非 GNOME 桌面环境必须安装 gnome-terminal：

    bash
    sudo apt install -y gnome-terminal

  • 先卸载之前安装的技术预览版或者测试版 Docker Desktop：

    bash
    rm -rf ~/.docker/desktop
rm -rf ~/.config/systemd/user/docker-desktop.service
rm -rf ~/.local/share/systemd/user/docker-desktop.service
sudo rm -f /usr/local/bin/com.docker.cli
sudo apt purge docker-desktop

    注意：

    • 之前没有装过 Docker Desktop 的可以跳过这一步
    • 删除文件夹时如果找不到文件夹直接忽略

  • 从 Docker 官网下载 Docker Desktop 的安装包并安装：

    bash
    sudo apt update
sudo apt install -y ./docker-desktop-<version>-<arch>.deb

    如果安装到最后报错，错误信息类似 N: Download is performed unsandboxed as root, as file '/home/user/Downloads/docker-desktop.deb' couldn't be accessed by user '_apt'. - pkgAcquire::Run (13: Permission denied) 这样的，可以直接忽略（官方做法）。

  • 启动 Docker Desktop：

    bash
    systemctl --user start docker-desktop

  • 退出 Docker Desktop：

    bash
    systemctl --user stop docker-desktop

  • 设置 Docker Desktop 为开机自启：

    bash
    systemctl --user enable docker-desktop

2.5 配置国内镜像源加速 #

针对官方 Docker Hub 拉取镜像缓慢或超时的问题，可通过配置国内加速镜像源解决。

编辑或创建 /etc/docker/daemon.json：

bash
sudo vim /etc/docker/daemon.json

写入镜像源配置（可根据实际情况替换为各大高校或企业镜像站）：

json
{
  "registry-mirrors": [
    "https://docker.mirrors.ustc.edu.cn",
    "https://docker.m.daocloud.io",
    "https://docker.nju.edu.cn",
    "https://mirror.ccs.tencentyun.com"
  ]
}

重载与生效：

bash
sudo systemctl daemon-reload
sudo systemctl restart docker

# 检查加速源是否生效
docker info | grep -A 5 "Registry Mirrors"

3. Docker 核心命令速查 #

3.1 镜像管理（Images） #

命令 说明 常用参数
docker images 列出本地所有镜像 -a（显示所有，含中间层）、-q（仅输出镜像 ID）
docker pull <image>:<tag> 从仓库拉取镜像 默认 tag 为 latest
docker push <image>:<tag> 推送镜像至仓库 推送前需 docker login
docker rmi <image> 删除本地镜像 -f（强制删除）
docker tag <src> <target> 为本地镜像打新标签 例如 docker tag myapp:v1 myreg/myapp:v1
docker history <image> 查看镜像的提交历史层 --no-trunc（显示完整命令）

3.2 容器生命周期管理（Containers） #

命令 说明 常用参数与示例
docker ps 列出正在运行的容器 docker ps -a（列出所有运行过的容器，含已退出的）、docker ps -q（仅输出容器 ID）
docker run 创建并启动新容器 详见下方 docker run 专用参数说明
docker create 创建新容器但不启动 docker create --name mynginx nginx:latest
docker start <container> 启动已停止的容器 启动后需再 docker exec -it <container> /bin/bash 进入
docker stop <container> 优雅停止运行中的容器 发送 SIGTERM，超时后发送 SIGKILL
docker restart <container> 重启容器 docker restart mynginx
docker kill <container> 强制终止容器 直接发送 SIGKILL 信号（想强制结束容器时用它替代 stop）
docker attach <container> 附加到运行中容器的主进程 退出后容器会直接停止，详见 3.4 说明
docker exec -it <container> /bin/bash 在运行中的容器内新开进程/终端 退出后容器不会停止（推荐方式）
docker rm <container> 删除容器（需先停止） -f（强制删除运行中容器）、-v（级联删除匿名卷）

3.3 docker run 核心启动参数 #

bash
docker run [OPTIONS] IMAGE [COMMAND] [ARG...]
  • -d：后台守护模式（Detached Mode）运行容器，输出容器 ID。
  • -it：通常组合使用，-i 保持标准输入打开，-t 分配伪终端，进入交互式命令行（也可以当作固定参数无脑添加）。
  • --name <name>：指定容器别名，方便后续运维管理。该参数只能在 docker run / docker create 创建容器时指定，不能中途更改。
  • -p <host_port>:<container_port>：端口映射（如 -p 8080:80 将宿主机 8080 端口映射到容器内 80 端口）。
  • -P：随机映射宿主机高位端口到容器所有声明的 EXPOSE 端口。
  • -v <host_path>:<container_path>[:ro|:rw]：挂载数据卷或宿主机物理目录。
  • -e KEY=VALUE：设置容器内环境变量（如 -e MYSQL_ROOT_PASSWORD=secret）。
  • --restart：重启策略，可选 no（默认不重启）、always（非正常退出或开机均重启）、on-failure、unless-stopped。
  • --net <network>：指定连接的网络模式（bridge, host, none, 自定义网络）。
  • -m <memory>：限制容器可用内存上限（如 -m 512m）。

从一个已存在的镜像启动一个全新的容器：

bash
docker run -it --name=MyContainer1 ubuntu:20.04 /bin/bash
docker run -it --name=MyContainer2 myorganization/myimage:v1 /bin/bash
docker run -it --name=MyContainer3 aabbcc /bin/bash # docker import 导入的容器

注意：

  • 如果本地找不到对应的镜像，Docker 会自动从网上下载（如果有的话）
  • 执行 exit 命令后，容器会直接停止运行
  • 最好使用 --name 参数指定一个容器名字，以后容器多了方便区分

3.4 运维排错与内部状态检查 #

  • 查看运行中容器：
    bash
    docker ps             # 列出正在运行的容器
docker ps -a          # 列出所有容器（含已退出的容器）
docker ps -q          # 仅列出容器 ID
  • 查看容器日志：
    bash
    docker logs aabbcc                       # 查看某个容器的日志
docker logs -f --tail 100 <container>    # 实时跟踪最近 100 行日志
docker logs -t <container>               # 显示带时间戳的日志
  • 进入容器内部终端：
    bash
    docker exec -it <container> /bin/bash    # 分配新进程进入容器（推荐）
# 提示：若使用 attach 退出时易误杀主进程；若在交互终端中想保留后台运行，使用 Ctrl+P + Ctrl+Q 安全挂起
    • 使用 exec 命令进入的容器，执行 exit 命令后容器不会停止运行
    • 使用 attach 命令进入的容器，执行 exit 命令后容器会直接停止运行
    • 退出容器直接输入 exit（前面没有 docker 这个前缀），或者直接关闭当前容器所在的控制台窗口也可以
  • 查看容器进程与详情：
    bash
    docker top <container>                  # 查看容器内部的活跃进程
docker inspect <container>              # 查看元数据 JSON（含 IP、挂载点、配置等）
docker port <container>                 # 查看具体端口映射关系
docker stats aabbcc                     # 查看某个容器的资源占用状态
docker cp host_file <container>:/path   # 宿主机与容器之间双向拷贝文件

3.5 宿主机与容器之间复制文件（docker cp） #

bash
# 复制宿主机文件到容器
docker cp C:/Test/test.zip aabbcc:/home/myaccount/

# 复制容器文件到宿主机
docker cp aabbcc:/home/myaccount/test.zip C:/Test/

3.6 提交容器修改记录（docker commit） #

把容器的当前状态固化为一个新镜像：

bash
docker commit -m="这里填提交信息" -a="这里填作者" aabbcc myorganization/myimage:v1

注意：冒号后面是 TAG，写什么都可以，不是必须写成版本号。

3.7 [Windows] 创建新容器并把当前文件夹映射到容器中 #

批处理（非 PowerShell！）：

bat
docker run -itd --name=MyContainer -p 10022:22 -v %cd%:/home/wangwenx190/myproject ubuntu:20.04

解释：

  • -it：交互式启动容器并将日志输出到控制台（可以当作固定参数，无脑添加）
  • -d：启动容器后转移到后台运行
  • -p：设置端口转发，空格后面是端口绑定规则，格式为 宿主机端口:容器端口（例中把宿主机 10022 端口映射到容器 22 端口）
  • -v：设置挂载点，空格后面是挂载点参数，格式为 Windows中的路径:容器中的路径
  • %cd%：批处理文件中代表当前文件夹路径
  • /home/wangwenx190/myproject：希望将当前文件夹挂载到容器什么位置
  • ubuntu:20.04：镜像

4. Docker 网络模式 #

Docker 通过 Linux 虚拟网络设备与 iptables/nftables 实现容器间及容器与外部的网络互通。

+---------------------------------------------------------------+
|                        Docker Host                            |
|                                                               |
|  [host 模式]             [bridge 模式 (默认)]                  |
|  Container 直接使用      Host eth0 <---> docker0 网桥         |
|  宿主机网络栈 (IP:Port)                    |                  |
|                                     +------+------+           |
|                                     |             |           |
|                                 veth0 (eth0)   veth1 (eth0)   |
|                                Container 1    Container 2     |
+---------------------------------------------------------------+

4.1 四种常用网络模式 #

  1. bridge 模式（--net=bridge，默认）：
    • 架构：Docker 在宿主机上创建名为 docker0 的虚拟网桥，每个容器分配独立的网络命名空间、虚拟网卡（veth 对）及内网 IP。
    • 通信：容器间通过内部 IP 通信；与外部通信依靠宿主机 iptables NAT 转发，外部访问需通过 -p 映射端口。
  2. host 模式（--net=host）：
    • 特点：容器不拥有独立的网络命名空间，完全共享宿主机的网络设备与端口。
    • 优缺点：省去了 NAT 转发开销，网络性能最高；但失去了端口隔离性，容器端口不能与宿主机冲突。适用于网络吞吐极高或大量端口监听的场景。
  3. container 模式（--net=container:<NAME_or_ID>）：
    • 特点：新容器与已存在的指定容器共享同一个网络命名空间（IP 与端口共享），但文件系统、系统进程依然隔离。常用于伴生服务（Sidecar）或协同代理。
  4. none 模式（--net=none）：
    • 特点：拥有独立的网络命名空间，但未配置任何网卡、IP 或路由，完全断开网络连接。适用于离线计算、封闭安全测试等特定环境。

5. Docker 数据存储与持久化 #

容器默认的文件层随容器生命周期销毁而丢失。为实现数据持久化与跨容器共享，Docker 提供了**数据卷（Volumes）与绑定挂载（Bind Mounts）**机制。

5.1 数据卷（Volume）的特性 #

  • 绕过联合文件系统（UnionFS），直接在宿主机专用目录（/var/lib/docker/volumes/）管理。
  • 容器删除后数据卷仍然保留，除非显式清理。
  • 对卷的修改立即生效，支持多个容器同时并发挂载读取。

5.2 挂载方式对比 #

  • 指定宿主机物理路径（Bind Mount）：
    bash
    docker run -d -v /opt/data:/var/www/html:rw nginx
# 宿主机路径与容器路径强绑定，方便开发调试时实时同步源码
  • Docker 命名卷（Named Volume）：
    bash
    docker volume create my_volume
docker run -d -v my_volume:/var/lib/mysql mysql:latest
# 由 Docker 统一管理，路径解耦，更安全标准
  • 只读挂载保护：
    bash
    docker run -d -v /opt/config:/etc/app/config:ro myapp
# 附加 :ro 标志，容器内部无法修改该目录
  • 数据卷容器共享（--volumes-from）：
    bash
    # 启动数据管理容器
docker run -d --name data_store -v /shared_data busybox
# 启动其他容器共享该存储
docker run -d --name app1 --volumes-from data_store app_image
docker run -d --name app2 --volumes-from data_store app_image

6. Dockerfile 镜像构建 #

Dockerfile 是用于指导 Docker 自动化构建镜像的文本脚本，包含一系列声明式指令。

6.1 常用构建指令 #

  • FROM <image>:<tag>：指定构建基石的基础镜像（必须作为第一条非注释指令）。
  • LABEL maintainer="author <email>"：添加元数据声明镜像作者与说明。
  • RUN <command>：在构建期执行 shell 命令，每一条 RUN 指令都会产生新的镜像层（建议使用 && 合并命令并清理缓存以减少镜像体积）。
  • COPY <src> <dest>：将本地文件/目录直接复制到镜像文件系统指定路径。
  • ADD <src> <dest>：类似于 COPY，但支持网络 URL 下载并会自动解压本地压缩包（tar/gzip）。
  • WORKDIR <path>：指定后续指令的工作目录（相当于容器内部 cd）。
  • ENV KEY=VALUE：设置构建期及运行期的环境变量。
  • ARG KEY=VALUE：设置仅在构建阶段有效的临时参数（可在构建时通过 --build-arg 覆盖）。
  • EXPOSE <port>：声明容器计划监听的网络端口（仅供文档与元数据说明，不代表自动映射）。
  • VOLUME ["/path"]：定义匿名挂载点，确保该路径数据在启动时自动持久化。
  • USER <user|uid>：指定后续运行容器命令的用户身份（增强安全性）。
  • CMD ["executable", "param1", "param2"]：指定容器启动时的默认执行命令，会被 docker run 尾部传入的参数覆盖。
  • ENTRYPOINT ["executable", "param1"]：设定容器启动固定入口，不会被 docker run 简单覆盖，传入参数会追加到其后。

6.2 Dockerfile 实战示例 #

dockerfile
# 基础镜像
FROM ubuntu:22.04

# 维护者信息
LABEL maintainer="admin@example.com"

# 设置工作目录
WORKDIR /app

# 安装环境依赖并清理缓存
RUN apt-get update && apt-get install -y --no-install-recommends \
    nodejs \
    npm \
    && rm -rf /var/lib/apt/lists/*

# 复制依赖定义并安装
COPY package*.json ./
RUN npm install

# 复制源码
COPY . .

# 暴露端口与环境变量
ENV NODE_ENV=production
EXPOSE 3000

# 容器启动入口
ENTRYPOINT ["node"]
CMD ["app.js"]

6.3 执行构建 #

bash
# 当前目录下存在 Dockerfile 时构建
docker build -t myapp:1.0 .

# 指定非当前目录下的 Dockerfile
docker build -f /path/to/Dockerfile -t myapp:1.0 .

7. 镜像与容器的备份、迁移与导入导出 #

在生产运维与离线部署中，经常需要对镜像与容器进行快照备份与跨机迁移。

7.1 核心命令差异对比 #

维度 docker save & docker load docker export & docker import
操作对象 镜像（Image） 容器（Container）
层级与历史 完整保留所有历史构建层、标签元数据 丢弃历史层，仅打包当前容器文件系统快照（扁平化）
体积大小 包含所有层，体积相对较大 仅保留静态文件快照，体积较小
主要场景 基础镜像生产备份、离线环境镜像分发 导出容器运行时状态、快速迁移容器数据文件

7.2 镜像备份与恢复（save / load） #

bash
# 将本地镜像打包保存为 tar 归档
docker save myorganization/myimage:v1 -o myimage.tar
docker save -o nginx_latest.tar nginx:latest

# 传输至目标服务器后恢复镜像
docker load myimage.tar
docker load -i nginx_latest.tar
# 或使用管道流
docker load < nginx_latest.tar

导入后可以使用 docker images 命令查看。

注意：

  • 一定不要使用 > 输出到文件，因为 Windows 和 UNIX 的换行符不一样（CRLF/LF），这样会导致你导出的文件无法跨系统加载。
  • save 命令只针对镜像，不能对容器使用。
  • load 命令只能导入 save 命令生成的文件，不能导入 export 命令生成的文件。

7.3 容器快照导出与镜像导入（export / import） #

bash
# 将运行中或停止的容器导出为文件系统 tar 包
docker export aabbcc -o mycontainer.tar

# 导入该文件系统快照并生成新的镜像
cat mycontainer.tar | docker import - mynewimage:v1.0
docker import mycontainer.tar   # 不指定仓库名/标签时会得到一个 <none>:<none> 镜像

# 使用新导入的镜像启动容器（注意：export 会丢失原镜像的 CMD/ENTRYPOINT 元数据，启动时需指定启动命令）
docker run -d -p 80:80 mynewimage:v1.0 /bin/bash

导入后可以使用 docker images 命令查看。

注意：

  • 一定不要使用 > 保存文件，因为 Windows 和 UNIX 的换行符不一样（CRLF/LF），会导致你导出的容器无法跨系统导入。
  • export 命令只针对容器，不能对镜像使用。
  • import 命令只能导入 export 命令生成的文件，不能导入 save 命令生成的文件。

7.4 容器提交为新镜像（docker commit） #

在调试或快速固化运行时修改时使用：

bash
docker commit -m "install required tools" -a "dev" <container_id> custom_image:tag

注意：冒号后面是 TAG，写什么都可以，不是必须写成版本号。
