1. Docker Compose 概述 #

Docker Compose 是 Docker 官方提供的多容器定义和运行工具。它允许开发者通过声明式的 YAML 配置文件（通常命名为 docker-compose.yml），将包含业务逻辑、数据库、缓存、反向代理等多个相互依赖的容器组合为一个完整的项目进行统一部署与生命周期管理。

1.1 核心优势 #

  • 基础设施即代码（IaC）：所有容器的启动参数、端口映射、挂载卷、环境变量与网络拓扑均沉淀在配置文件中，避免繁琐且易出错的手动 docker run 命令。
  • 环境一致性：一键在开发、测试与生产环境中快速启动或销毁整套隔离的微服务环境。
  • 自动化服务发现：Compose 自动为每个项目创建独立的私有桥接网络，各个服务可以通过服务名称（Service Name）作为域名直接相互通信，无需手动绑定 IP 或维护陈旧的 --link。

1.2 安装与版本说明 #

目前 Docker 官方推荐使用集成在 Docker CLI 中的 Compose V2（命令为 docker compose），同时也兼容传统的独立 Python 版 Compose V1（命令为 docker-compose）。

bash
# Ubuntu/Debian 安装方式
sudo apt update
sudo apt install -y docker-compose-plugin  # Compose V2 插件（推荐）
# 或安装传统独立命令: sudo apt install -y docker-compose

# 确认安装版本
docker compose version   # V2 命令
docker-compose version   # V1 命令

2. docker-compose.yml 核心语法详解 #

docker-compose.yml 是 Compose 的核心定义文件，采用标准的 YAML 语法（严格区分缩进，禁止使用 Tab 制表符）。

2.1 顶级结构 #

一个典型的 Compose 文件由以下顶级关键字构成：

  • version：指定 Compose 文件格式版本（如 "3.8" 或更高；在较新的 Compose Spec 中该字段为可选）。
  • services：核心部分，定义项目中各个微服务容器的配置细节。
  • volumes：声明全局命名的持久化数据卷。
  • networks：声明全局自定义网络。

2.2 服务（Services）常用配置项 #

配置项 功能说明 语法示例
image 指定运行该服务的基础镜像 image: mysql:5.7
build 指定通过本地 Dockerfile 构建镜像 build: ./app 或 build: { context: ., dockerfile: Dockerfile }
container_name 自定义容器名称（若不指定则按 项目名_服务名_序号 自动生成） container_name: my_mysql
restart 容器重启策略 restart: always（宕机自启）、unless-stopped
ports 宿主机与容器端口映射（宿主:容器） ports: ["8080:80", "443:443"]
volumes 挂载卷或主机目录映射 volumes: ["./data:/var/lib/mysql", "my_vol:/app/data"]
environment 注入容器环境变量 environment: { MYSQL_ROOT_PASSWORD: "secret" }
env_file 从外部文件加载环境变量 env_file: [.env, .env.local]
depends_on 定义服务启动依赖顺序（优先启动依赖服务） depends_on: [db, redis]
command 覆盖容器镜像默认的启动命令 command: bundle exec thin -p 3000
networks 指定服务加入的自定义网络 networks: [backend, frontend]

3. 经典多容器实战：WordPress + MySQL 生产范例 #

以下以经典的 WordPress 博客全栈应用（包含 WordPress 业务服务与 MySQL 数据库服务）为例：

yaml
version: "3.8"

services:
  db:
    image: mysql:5.7
    container_name: wordpress_db
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: root_password_here
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wp_user
      MYSQL_PASSWORD: wp_user_password
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - wp_net

  wordpress:
    image: wordpress:latest
    container_name: wordpress_app
    restart: always
    depends_on:
      - db
    ports:
      - "80:80"
    environment:
      WORDPRESS_DB_HOST: db:3306      # 直接使用服务名 'db' 作为数据库主机名
      WORDPRESS_DB_USER: wp_user
      WORDPRESS_DB_PASSWORD: wp_user_password
      WORDPRESS_DB_NAME: wordpress
    volumes:
      - wp_data:/var/www/html
      - ./uploads.ini:/usr/local/etc/php/conf.d/uploads.ini:ro  # 挂载自定义 PHP 上传配置
    networks:
      - wp_net

volumes:
  db_data:
    driver: local
  wp_data:
    driver: local

networks:
  wp_net:
    driver: bridge

3.1 关键配置解析 #

  1. 服务发现与内部 DNS：
    • 在 wordpress 服务的环境变量中，WORDPRESS_DB_HOST 填入的值为 db:3306。
    • Compose 内部的内置 DNS 会自动将主机名 db 解析为 MySQL 容器的内部 IP，无需配置静态 IP 或宿主机端口暴露，保证了数据库的内网安全性。
  2. 启动拓扑与依赖（depends_on）：
    • wordpress 服务配置了 depends_on: - db，保证 Compose 先启动 MySQL 数据库，再启动业务应用。
  3. 数据持久化与配置分离：
    • MySQL 数据库数据（/var/lib/mysql）与 WordPress 静态附件（/var/www/html）使用顶级声明的命名卷 db_data 和 wp_data 进行持久化，容器重启或重建时数据不丢失。
    • 上传限制配置文件 uploads.ini 采用绑定挂载（Bind Mount）并设为只读（:ro），方便在宿主机直接修改配置。

4. Docker Compose 常用运维命令详解 #

Compose 命令默认作用于当前目录下的 docker-compose.yml 文件。如果文件位于其他路径或名称不同，可通过 -f /path/to/compose.yml 参数指定。

提示：若使用 Compose V2，将命令中的 docker-compose 替换为 docker compose 即可。

4.1 服务生命周期管理 #

  • 启动所有服务：
    bash
    docker-compose up -d
# -d 参数表示在后台（Detached 模式）运行所有容器，释放当前终端
  • 构建并启动服务：
    bash
    docker-compose up -d --build
# 若修改了本地 Dockerfile 或构建上下文，使用 --build 强制重新构建镜像后再启动
  • 停止并清理所有资源：
    bash
    docker-compose down
# 停止并删除由当前 yml 创建的容器、默认网络；
docker-compose down -v
# 附带 -v 会连同命名数据卷一同删除（高危操作，常用于环境彻底重置）
  • 启动 / 停止 / 重启服务：
    bash
    docker-compose start [service_name]    # 仅启动已存在的停止容器
docker-compose stop [service_name]     # 停止运行中的容器，保留容器实例
docker-compose restart [service_name]  # 重启所有或指定的单个服务容器
  • 暂停与恢复容器进程：
    bash
    docker-compose pause [service_name]    # 挂起容器内部的所有执行线程，极低资源占用
docker-compose unpause [service_name]  # 恢复被暂停的服务

4.2 运行监控与调试排错 #

  • 查看容器运行状态：
    bash
    docker-compose ps
# 列出当前项目关联的所有容器、运行状态以及端口映射情况
  • 实时追踪服务日志：
    bash
    docker-compose logs -f
# 聚合打印所有服务的实时日志输出
docker-compose logs -f --tail 200 wordpress
# 单独跟踪 wordpress 服务最近 200 行日志
  • 进入容器内部终端：
    bash
    docker-compose exec [service_name] sh
# 类似于 docker exec，直接根据服务名称进入容器执行命令（如排查数据库连接）
docker-compose exec db mysql -u wp_user -p
  • 查看端口映射：
    bash
    docker-compose port wordpress 80
# 查看指定服务的指定端口最终映射到了宿主机的哪个端口
  • 查看进程信息：
    bash
    docker-compose top
# 显示项目中正在运行的每个容器内部进程列表

4.3 构建与维护辅助 #

  • 重新拉取依赖镜像：
    bash
    docker-compose pull
# 针对使用远程镜像的服务，从 Registry 拉取最新版本的镜像
  • 仅构建镜像：
    bash
    docker-compose build [service_name]
  • 运行一次性任务容器：
    bash
    docker-compose run --rm wordpress php -v
# 基于服务配置运行一次性命令，并在执行完成后自动销毁容器（--rm）
  • 清理已停止的容器：
    bash
    docker-compose rm -f -v
# 删除已处于停止状态的容器和关联的未命名卷

5. 生产与开发最佳实践 #

  1. 敏感信息与环境变量解耦：
    • 生产环境中切勿将明文密码硬编码在 docker-compose.yml 中。
    • 推荐在同目录下创建 .env 文件存储变量（如 MYSQL_PASS=YourSecretPass），并在 compose 文件中通过 ${MYSQL_PASS} 引用。.env 文件需加入 .gitignore 避免提交至代码仓库。
  2. 数据卷定期备份：
    • 数据库等状态服务必须使用具名卷挂载。在进行容器或镜像大版本更新前，先备份宿主机挂载目录或数据卷。
  3. 健康检查机制（Healthcheck）：
    • depends_on 默认仅等待依赖容器启动（创建进程），并不能保证容器内的数据库服务已经就绪（端口可监听）。
    • 可在依赖服务中配置 healthcheck，并在上层服务中使用 condition: service_healthy，避免业务服务因数据库启动慢而连接崩溃。
