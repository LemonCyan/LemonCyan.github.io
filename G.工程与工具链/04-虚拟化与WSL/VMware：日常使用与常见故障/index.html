这篇只讲一件事：VMware Workstation / Player 里跑的 Linux 客机，日常用起来会遇到什么、坏了怎么排。

讲什么：

  • 共享文件夹：原理、手动挂载、开机自动挂载
  • 磁盘越用越大：为什么删了文件不变小、快照的代价、怎么收缩 vmdk
  • 编译内存不足：OOM 长什么样、swap 文件怎么应急和善后
  • 上面三件事的排查顺序、易错点速查

不讲什么：

  • 宿主机的 VMware 安装、许可、网络模式（NAT / 桥接 / 仅主机）
  • 虚拟化平台的横向对比、KVM/Xen 那套服务端虚拟化
  • 客机内部与虚拟化无关的调优（内核参数、IO 调度器）
  • Linux 发行版本身的包管理教程

跨篇指路：同一目录下另有 WSL 指南与 QEMU 两篇，Windows 侧的 Linux 环境看前者，想换掉 VMware 看后者；本篇的命令只针对在 VMware 客机里执行的场景。

命令里的用户名用 forlinx 举例，共享文件夹名统一用 ShareDir，换成你自己的。发行版不绑定，包管理器按你实际用的改。

一、VMware 与 open-vm-tools #

装 VMware 官方的闭源 Tools，那套做法已经过时了。官方现在推的是 open-vm-tools，在发行版仓库里直接装，内核升级时不用自己重编模块。

Ubuntu / Debian 系：

bash
sudo apt update
sudo apt install -y open-vm-tools open-vm-tools-desktop

RHEL / CentOS / Fedora 系：

bash
sudo dnf install -y open-vm-tools open-vm-tools-desktop

两个包的分工要分清：

包名 作用 什么时候需要
open-vm-tools 提供 vmware-toolbox-cmd、vmhgfs-fuse、vmtoolsd 这些命令行能力 一定要装
open-vm-tools-desktop 分辨率自适应、剪贴板互通、拖放、共享文件夹的桌面侧支持 带图形界面的客机要装

只装 open-vm-tools、不装 -desktop，GUI 客机上的共享文件夹常常挂不起来，分辨率也不会跟着窗口变。这是漏装包最常见的一个后果。

装完确认服务在跑：

bash
systemctl status vmtoolsd
vmware-toolbox-cmd -v

vmtoolsd 在跑，才说明客机和宿主机之间的那条通道是通的。vmware-toolbox-cmd 报 command not found，基本就是 open-vm-tools 没装上。

如果机器上已经有早年用 tar 包装的官方 VMware Tools，先按它自带的卸载脚本卸掉再装 open-vm-tools。两套东西同时存在会互相抢服务，症状是很难查的挂载失败。

官方 tar 包不要再用，原因很实在：

  • 每次内核升级都要重编模块，内核头文件一缺就编不过
  • 新版内核上编译失败的案例一直在出现，修起来比重装 open-vm-tools 麻烦得多
  • 发行版仓库里的 open-vm-tools 会跟着内核一起升级，不需要你操心

装完建议重启一次客机。vmhgfs-fuse 相关服务是跟着 vmtoolsd 起的，装完不重启，共享文件夹有时要等下一次开机才认。

二、共享文件夹的原理 #

先看它到底是怎么实现的，后面所有报错都好解释。

宿主机上的目录，对客机来说是一块外来文件系统。两边的文件系统语义不一样，宿主机的目录也不是块设备，没法像挂 U 盘那样 mount 一下就完事。VMware 的做法是在客机里跑一段用户态程序，把宿主机的目录「翻译」成客机能看懂的文件系统。这段程序就是：

text
vmhgfs-fuse      新版，FUSE 用户态文件系统
vmhgfs           老版，内核模块

**新版内核要用 vmhgfs-fuse，老教程里的 mount -t vmhgfs 已经不适用。**这是踩坑最多的一条。

老写法长这样：

bash
sudo mount -t vmhgfs .host:/ShareDir /mnt/hgfs

在新内核的发行版上跑，结果是这样：

text
mount: unknown filesystem type 'vmhgfs'

或者：

text
mount: /mnt/hgfs: unknown filesystem type 'vmhgfs'.

原因不复杂：vmhgfs 是个内核模块，得配套你当前内核的头文件编出来。内核接口一变，模块就编不过；模块没编出来，mount -t vmhgfs 自然找不到这个文件系统类型。vmhgfs-fuse 走 FUSE 框架，不用编内核模块，所以能跨内核版本用下去。

FUSE 这条路有个副作用要接受：文件操作要经过用户态一次，大文件的读写吞吐比原生文件系统低。别把编译输出目录、数据库数据目录放在共享文件夹里跑。

三种挂法的路径对照：

写法 文件系统 需求 现状
mount -t vmhgfs .host:/ /mnt/hgfs 老 vmhgfs 内核模块 模块与内核匹配 新内核上不可用
vmhgfs-fuse .host:/ /mnt/hgfs FUSE 有 vmhgfs-fuse 命令 现在的正规做法
/etc/fstab 里 fuse.vmhgfs-fuse FUSE 同上 + fstab 一行 自动挂载用这个

.host:/ 是个虚拟路径，/ 后面跟的是虚拟机的共享目录层级，不是宿主机的绝对路径。宿主机那边 E:\src\ShareDir 配成共享名 ShareDir，客机里就写 .host:/ShareDir，对应的挂载点是客机上的任意空目录。

先把共享名确认掉：

bash
vmware-hgfsclient

输出的每一行是宿主机在 VMware 设置里勾选的共享文件夹名。先在虚拟机设置里启用共享文件夹，这一步才有输出。

vmware-hgfsclient 没有任何输出，按这个顺序查：

现象 原因 处理
设置里没有共享文件夹条目 没配 关机 →「选项」→「共享文件夹」→ 启用，添加一条
配了但没勾「总是启用」 只在本次开机时生效 勾上「总是启用」，或下次手动启用
设置里都有，命令还是空 客机里 open-vm-tools 没起来 检查 vmtoolsd，必要时重启

配好之后，vmware-hgfsclient 打出来的名字要和挂载命令里的名字逐字一致。大小写错一个字母，挂载点就是空的。

三、手动挂载共享文件夹 #

建挂载点并把共享挂上去：

bash
sudo mkdir -p /home/forlinx/ShareDir
vmhgfs-fuse .host:/ShareDir /home/forlinx/ShareDir -o subtype=vmhgfs-fuse,allow_other

allow_other 让非 root 用户也能访问挂载点里的内容。FUSE 默认只允许挂载者本人进挂载点，不加这个参数，你用普通账号 ls 会看到权限拒绝。

allow_other 要生效，/etc/fuse.conf 里得有 user_allow_other 这一行，没有就用 root 补上：

bash
sudo vi /etc/fuse.conf

不想改 /etc/fuse.conf，就用 root 身份挂载，这时不需要 allow_other，但之后普通用户访问挂载点里的文件会受文件本身的权限限制。

只想看全部共享，可以挂根目录：

bash
sudo mkdir -p /mnt/hgfs
vmhgfs-fuse .host:/ /mnt/hgfs

挂根目录时，客机上看到的是 /mnt/hgfs/ShareDir，也就是所有共享名一层铺开。验证：

bash
ls /home/forlinx/ShareDir

/mnt/hgfs 和 /home/forlinx/ShareDir 是两个不同的挂载点，别混用。同一个共享用两种方式挂两次，改了一个地方另一个看不到变化，排查时会以为文件没同步。

uid / gid 这两个挂载选项，是解决「挂上去了但写不进去」的常用手段：

bash
vmhgfs-fuse .host:/ShareDir /home/forlinx/ShareDir \
  -o subtype=vmhgfs-fuse,allow_other,uid=1000,gid=1000

uid / gid 指定的是客机里的用户 ID 和组 ID，宿主机的文件权限它会盖掉。用 id 命令先查自己的数字。用错数字，宿主机里明明可写的文件，客机里还是只读。

想先试挂、不落配置，手动 vmhgfs-fuse 就够了。确认稳定之后，再交给 fstab。

四、开机自动挂载 #

手动挂载重启就没了。让它每次开机自动挂上，写 /etc/fstab 最省事，不用自己写自启脚本。

先备份：

bash
sudo cp /etc/fstab /etc/fstab.bak

在文件末尾加一行，共享名和挂载点要和上面一致：

text
#VMware shared folder
.host:/ShareDir  /home/forlinx/ShareDir  fuse.vmhgfs-fuse  allow_other,uid=1000,gid=1000  0  0

字段含义，一条一条对着看：

字段 值 说明
设备 .host:/ShareDir 共享名要和 vmware-hgfsclient 的输出逐字一致
挂载点 /home/forlinx/ShareDir 必须已经存在的目录
类型 fuse.vmhgfs-fuse 用 FUSE 版本，不要写 vmhgfs
选项 allow_other,uid=1000,gid=1000 逗号分隔，不带空格
dump 0 固定 0
pass 0 FUSE 挂载必须写 0

选项里几个常用的：

选项 作用
allow_other 允许非挂载者访问，配 /etc/fuse.conf 的 user_allow_other
uid=1000 挂载点里文件的属主
gid=1000 挂载点里文件的属组
noatime 不更新访问时间，少一点写操作
nofail 这一行挂失败时不阻塞开机

nofail 值得加，尤其是你不确定共享名会不会改。没有它，共享文件夹一旦挂不上，开机流程会停下来等你处理。

改完不重启就验证：

bash
sudo mount -a
ls /home/forlinx/ShareDir

mount -a 会把 fstab 里所有没挂上的条目挂一遍。它报错就先改回 fstab，别直接重启，否则会卡在挂载上，进不去系统。报错对着看：

报错关键词 常见原因
unknown filesystem type 'vmhgfs' 类型写成了 vmhgfs，改成 fuse.vmhgfs-fuse
mount point does not exist 挂载点目录没建，先 mkdir -p
Transport endpoint is not connected 挂载点被占用了，先 umount 再挂
Permission denied 缺 allow_other，或 /etc/fuse.conf 没放开
挂上了但目录是空的 共享名对不上，回头比对 vmware-hgfsclient 输出

确认 mount -a 干净通过，再重启一次做最终验证：

bash
df -h | grep -i hgfs
mount | grep -i vmhgfs

两条命令都能看到挂载点，才算真正落稳。

也可以把 vmhgfs-fuse 命令写成脚本交给 systemd 或 /etc/rc.local，但多一层依赖，fstab 能解决就别绕。

五、磁盘为什么越用越大 #

「客机里删了 20 GB，宿主机的 .vmdk 一点没小」——这是新手最困惑的一点，也是本篇最想讲透的一点。

先把边界说清楚：

客机的文件系统运行在 .vmdk 这个文件内部。客机删一个文件，改的是 .vmdk 里的内部数据结构；宿主机的文件系统根本不知道 .vmdk 里发生了什么，它眼里那个文件只是「有一堆块被占着」。

所以磁盘增长跨了「客机删了但宿主不知道」的边界。原因分三层，一层比一层靠外：

层次 位置 现象 处理
客机内部 客机的文件系统 df -h 显示空间回来了，但块内容还在 清零空闲块 + 删缓存
快照 宿主机上的 delta 文件 删了快照之前的数据，空间没回来 删快照
vmdk 本身 宿主机上的 .vmdk 即使客机真释放了，vmdk 也不会自动缩小 vmware-toolbox-cmd disk shrink 或重建

按顺序做才有用：先清客机内垃圾 → 删快照 → 再收缩 vmdk。顺序反了，前面的功夫会白做，收缩完还是会看着一样大。

客机内部：删除不等于释放 #

rm 一个文件，对 ext4、xfs 这类日志文件系统来说，只是把 inode 和块位图标记成空闲。盘面上那些块的内容没被清掉，数据还在原地躺着。

从宿主机角度看更直白：.vmdk 里那些块仍然是有内容的块，VMware 没有理由把它们还回去。这就是「删了文件磁盘不变小」的直接原因。

客机释放了空间、但盘面没清零的情况下，还有几个常见的空间黑洞：

来源 说明 处理
VMware 拖放缓存 拖进客机的文件会在这里留一份 删掉 ~/.cache/vmware/drag_and_drop
swap 文件 临时加的 swap 文件本身就占几个 GB 用完 swapoff + 删文件，见第十章
包管理器缓存 apt / dnf 下载的安装包留着 apt clean 之类按发行版清
日志 journal、/var/log 长期不清会涨 按发行版方式限制大小
已卸载软件残留 配置和依赖留下的目录 自己确认后再删

进客机，先看真实占用和分布：

bash
df -h
sudo du -xh --max-depth=1 / 2>/dev/null | sort -h

du 报的数比 df 小很多，就是「已删除但仍有进程持有句柄」的文件占着空间，用 sudo lsof +L1 找出来。VMware 的拖放缓存堆在这个目录，路径按实际用户名改：

bash
rm -rf /home/forlinx/.cache/vmware/drag_and_drop

把空闲块清零，是让后面收缩真正生效的关键一步。在客机里跑：

bash
dd if=/dev/zero of=/zero.fill bs=1M status=progress
sync
rm -f /zero.fill
sync

原理：写一个把剩余空间填满的大文件，等于把空闲块全写成 0；删掉它之后，那些块在盘面上就是干净的。VMware 再看这些块，才知道里面没有真实数据，可以归还给宿主机。

这个操作有几个代价要接受：

  • 会写满整个空闲空间，耗时看磁盘速度，不是几秒钟的事
  • 期间客机磁盘 IO 打满，别同时干别的
  • 要有可写的空闲空间，/ 已经 100% 满就写不进去

dd 报 No space left on device 是正常的，它本来就要把空间写满，写满了就 Ctrl+C 或者等它自己失败，然后 sync 再删。

用 zerofree 也可以，它对未挂载或只读挂载的文件系统清零，效率比 dd 好：

bash
sudo apt install -y zerofree
sudo zerofree -v /dev/sda1

设备名按 lsblk 的实际输出改。zerofree 要求文件系统处于只读或未挂载状态，根分区得进救援模式或者在单用户模式下跑。嫌麻烦就用前面的 dd，虽然慢但不用改运行状态。

快照：后续写操作单独存一份 #

快照会把所有后续写操作单独存一份，写到宿主机上的增量文件里。所以删快照之前，你在客机里删的东西、清的空闲块，都不会让宿主机上的占用变小——数据只是被记到增量文件里了。

删快照才真正释放。

vmdk 本身：不会自动缩小 #

即使客机里空间真的空了、空闲块也清零了，.vmdk 也不会自动缩小。虚拟机磁盘文件的设计是只增不减，VMware 不会主动去分析里面哪些块空了。

这一步必须你主动做：vmware-toolbox-cmd disk shrink，或者在宿主机上重建。两者都在第七章、第八章。

六、快照与它的代价 #

VMware 工具栏 →「虚拟机」→「快照」→「快照管理器」，删掉不用的快照。快照会一直占着宿主机磁盘，不删后面怎么压缩都白搭。

快照这个词容易让人放松警惕。它不是备份，几个代价要提前知道：

代价 说明
不是备份 快照依赖父盘，父盘坏了快照一起没；能回滚到某一刻，但替代不了独立备份
链越长越慢 每次读写都要沿着快照链解析，链长了性能下降
占用持续增长 拍了快照之后的每次写操作都会单独存一份，越用越大
删快照很重 删的时候要把增量数据合并回父盘，磁盘 IO 会飙升，耗时不短

快照管理要养成的习惯：

  • 只在做危险操作之前拍，操作确认没问题就马上删
  • 不要把快照当长期存档，也不要在一条链上叠十几个
  • 拍快照前先确认宿主机的剩余空间够

删快照的注意点：

  • 删快照期间磁盘 IO 飙高是正常的，别在同时跑别的重活
  • 选中某个快照点「恢复到此快照」和「删除」，结果是两码事，看清按钮再点
  • 正在被使用的快照（当前状态）删不掉，先关机

删快照时报错、快照图标却已经消失，这种残留会在宿主机上越堆越多，清不掉。这种情况走第八章的导出 OVF，是最后一条路。

七、收缩虚拟磁盘 #

收缩能生效的前提是前面两章都做完了：客机里清了垃圾、空闲块也清零了、该删的快照也删了。少哪一步，收缩的结果都会让你失望。

vmware-toolbox-cmd 收缩命令要装了 open-vm-tools 才能用。先列出可收缩的挂载点：

bash
sudo /usr/bin/vmware-toolbox-cmd disk list

一般会有 /，然后收缩它：

bash
sudo /usr/bin/vmware-toolbox-cmd disk shrink /

这一步把客户机里已释放的块还给宿主机，.vmdk 文件才会变小。收缩要跑一会儿，期间别操作虚拟机。

disk list 只列出它认为能收缩的挂载点。想收缩的挂载点不在列表里，检查它的文件系统类型和挂载状态。

几个实用参数：

命令 作用
vmware-toolbox-cmd disk list 列出可收缩的挂载点
vmware-toolbox-cmd disk shrink / 收缩指定挂载点
vmware-toolbox-cmd disk shrinkonly / 只做收缩，跳过客机内的空间回收
vmware-toolbox-cmd -v 看当前 Tools 版本

收缩过程中断掉是这套流程常见的翻车点，注意：

  • 收缩期间不要关虚拟机、不要挂起、不要重启客机
  • 不要同时跑大编译、大复制，磁盘 IO 抢起来容易出问题
  • 收缩前在宿主机上确认剩余空间，收缩本身也需要临时空间
  • 收缩完成后，宿主机上等几秒再看 .vmdk 大小，文件系统缓存有延迟

收缩完之后核对结果，客机里 df -h，宿主机上打开虚拟机存储目录看 .vmdk 的实际大小。客机里 df -h 一直是对的，关键是宿主机上那个文件有没有真的变小。

VMware 的工作站在宿主机侧也有收缩入口，选中虚拟机 →「虚拟机设置」→ 硬盘 →「压缩」，或者用 vmware-vdiskmanager 带 -k 参数。它们和客机里的 vmware-toolbox-cmd disk shrink 是一回事，都是把已释放的块归还，前提同样是空闲块已经清零。

收缩这条路对厚置备（预分配）磁盘的效果和精简置备不一样：预分配的盘一开始就占满了宿主机空间，收缩省不出多少。虚拟机的磁盘类型在「虚拟机设置」里能看到。

vmware-toolbox-cmd disk shrink 不总是管用。尤其是快照残留或者磁盘内部结构乱了的时候，它跑完 .vmdk 还是那么大。这种情况往下走第八章，在宿主机上重建。

八、重建 vmdk 与导出 OVF #

收缩命令无效时，只能在宿主机上重建虚拟磁盘。虚拟磁盘文件只会慢慢变大，客户机里删了文件，VMware 不会主动把 .vmdk 缩小。

用 DiskGenius 重建 vmdk #

操作前先关掉虚拟机。这一步不能省，正在运行的虚拟机磁盘文件是锁着的。

  1. 菜单「硬盘 → 打开虚拟硬盘文件」，选中要收缩的 .vmdk，左侧会显示出这块虚拟盘。
  2. 菜单「硬盘 → 新建虚拟硬盘文件 → 新建 VMware 虚拟硬盘文件」，新建一个容量不小于源盘的 .vmdk。
  3. 菜单「工具 → 克隆硬盘」，源盘选原 .vmdk，目标盘选刚新建的，点「开始」。
  4. 复制完对比两个文件大小，新的应该明显小一截。

第 2 步的容量要不小于源盘，小了克隆会失败或者截断数据。目标位置放在另一块有空闲空间的盘上，别和源文件同目录。克隆是整盘逐块复制，源盘多大就要多长时间，几百 GB 的盘跑几个小时很正常，期间别动宿主机的磁盘。第 4 步的对比要看文件属性里的真实字节数，不是看「差不多」。

收尾：在 DiskGenius 里关掉两块虚拟盘（或直接关软件），把源 .vmdk 改名留作备份，再把新文件改成源文件的完全一致的文件名。启动虚拟机确认系统正常，之后才能删掉旧的那个。

收尾这步是整段最容易出错的地方：

  • 新文件名必须和原文件逐字一致，.vmx 配置里记的是文件名
  • 改名前先确认 DiskGenius 完全关掉，文件没被占用
  • 源文件先改名，不要先删
  • 虚拟机启动正常、进系统确认文件都在之后，才删旧的

虚拟机开不起来，就把名字改回去换回源文件，先保证能用再研究哪里错了。

导出 OVF 重建虚拟机 #

删快照时报错、快照图标却已经消失，残留文件会越堆越多，清不掉。导出 OVF 是最后一条路，能腾出一大块空间。

代价是丢掉其他快照。想保留某个快照的状态，先转到那个快照再导出。

  • 选中虚拟机 → 左上角「文件」→「导出为 OVF」，存到另一块有空闲空间的盘（十几个 GB）。
  • 把导出的 OVF 重新部署一遍，确认虚拟机能正常启动。
  • 确认没问题，再清空原来占用的磁盘。

导出会生成 .ovf、.vmdk、.mf 几个文件，目标盘的剩余空间按虚拟机实际占用的 1.5 倍留。导出和重新部署都是慢活，中途断了重来就行，源虚拟机不受影响。新部署的虚拟机要重新对一遍配置，尤其是网络模式和共享文件夹这类依赖宿主机的设置。

两条重建路线怎么选：

路线 保留 丢掉 什么时候用
DiskGenius 克隆 虚拟机原样，配置不动 无 收缩命令无效，但虚拟机本身能正常开
导出 OVF 重新部署 磁盘数据 其他快照 快照残留清不掉、快照管理器报错

两条路都要求虚拟机先关机。开机状态下 .vmdk 被锁，DiskGenius 打不开，导出也会失败。

九、编译时内存不足 #

报错长什么样 #

编译 C++ 时进程被杀，停在这一行：

text
C++: fatal error: Killed signal terminated program cc1plus
compilation terminated.

Killed signal 基本都是 OOM killer 干的，不是编译器 bug。cc1plus 是 GCC 的 C++ 前端，内存占用大，虚拟机内存给少了就会撞上。先确认真的是 OOM：

bash
dmesg -T | grep -i -E 'killed process|out of memory'
free -h

dmesg 里能看到 Out of memory: Killed process ... (cc1plus)，就锤实了。free -h 看当前可用内存和 swap，重点看 available 那一列，它比 free 更能反映真实可用内存。free 低但 available 还行，说明内存主要被缓存占着，那种情况不用慌。

text
              total        used        free      shared  buff/cache   available
Mem:           3.8Gi       3.6Gi       120Mi        12Mi       180Mi       100Mi
Swap:             0B          0B          0B

Swap 是 0，available 只剩一百多兆，编译到一半被 OOM 干掉是必然的。

OOM killer 也不只杀编译器，内核挑的是「最能释放内存」的进程。想确认是编译器被杀，看 dmesg 里的进程名。其他会造成类似现象的情况：

现象 不一定是 OOM 的证据 怎么区分
cc1plus 段错误 Segmentation fault 而非 Killed 看 dmesg，OOM 一定有 Killed process
编译卡死不退出 没被杀，一直跑 free -h 看是否在换页
磁盘写满 报 No space left on device df -h

内存不足的三种解法，先摆在前面做对比：

解法 见效速度 代价 治标还是治本
加 swap 文件 最快，不用关机 换页慢，SSD 上有写入磨损 治标
加虚拟机内存 要关机改配置 受宿主机物理内存限制 治本
减少并行编译数 立刻，改个参数 编译时间变长 治本但慢

三个办法不冲突，急性期先用第三个扛住，再考虑第一个，长期还是第二个。

减少并行编译数 #

make -j8 会同时起 8 个 cc1plus，每个都会吃掉几百兆到 1 GB。内存不够的时候，并行数就是那个乘数。改成 -j2：

bash
make -j2

峰值内存立刻降下来，代价是编译时间变长。CPU 核数和内存不匹配的时候，这个调整是必须的。估算公式：

text
内存 = 每核峰值占用 × 并行数，再加系统本身的占用

具体数字看你的项目，别照抄别人的 -j 值。先按 -j2 跑通，再往上调。其他构建系统里对应的开关：

bash
cmake --build . -- -j2
ninja -j 2

ninja 默认的并行数就等于 CPU 核数，内存小的机器要显式压下来。

加虚拟机内存 #

关掉虚拟机，在「虚拟机设置」里把内存调大，再开机。这是治本的一条路。受两个限制：

  • 宿主机得真有那么多物理内存，别把宿主机自己拖进 swap
  • 32 位客机的内存上限受地址空间限制，加不上去

先在宿主机任务管理器 → 性能 → 内存里看「可用」有多少。给客机的内存别超过宿主机可用内存的一半，宿主机自己也要跑东西。

加 swap 文件应急 #

不改虚拟机配置，就地加 4 GiB swap：

bash
sudo mkdir -p /var/cache/swap
sudo dd if=/dev/zero of=/var/cache/swap/swap0 bs=64M count=64
sudo chmod 0600 /var/cache/swap/swap0
sudo mkswap /var/cache/swap/swap0
sudo swapon /var/cache/swap/swap0
swapon --show

bs=64M count=64，64 × 64 = 4096 MiB，也就是 4 GiB。想要别的容量改 count。dd 这一步也会慢，加上 status=progress 能看到进度。chmod 0600 别省，权限太宽 swapon 会警告。注意这是 swap 文件，不是磁盘分区。

swapon --show 能看到这个文件和它的容量，free -h 的 Swap 那一行也会出现。

swap 只保证编译不被杀掉，机械硬盘上换页会明显拖慢速度。长期要编译大项目，直接给虚拟机加内存更快。

SSD 上还有个磨损问题：swap 换页是持续的小块写入，长期挂着会消耗 SSD 寿命。这是「应急可以、长期别留」的一个理由。

要开机自动挂，把这一行加进 /etc/fstab：

text
/var/cache/swap/swap0 none swap sw 0 0

验证用 swapon -a（mount -a 不管 swap 条目）：

bash
sudo swapon -a
swapon --show

十、swap 文件：应急与善后 #

swap 文件要记得删——很多人加完就忘了，长期跑在 swap 上。

长期挂着 swap 的坏处：

  • 客机以为自己内存够用，实际在拿磁盘当内存，整体响应变慢
  • SSD 持续被写入，寿命被消耗
  • 真正内存不足的时候，换页会掩盖问题，直到彻底卡死

善后是三步，三步都要做，漏一步下次开机又挂上：

bash
sudo swapoff /var/cache/swap/swap0
sudo rm /var/cache/swap/swap0

然后编辑 /etc/fstab，把之前加的那一行删掉：

text
/var/cache/swap/swap0 none swap sw 0 0

三步的作用，缺一步的后果：

步骤 命令 漏了会怎样
停用 sudo swapoff /var/cache/swap/swap0 rm 会报设备忙，删不掉
删文件 sudo rm /var/cache/swap/swap0 几个 GB 的空间白占着
改 fstab 删掉那一行 重启时找不到文件，开机卡住报错

顺序也要对：先 swapoff 再 rm。反过来，文件正被 swap 子系统用着，rm 要么失败，要么删了但空间要到 swapoff 才回来。

如果写过 fstab，记得把那一行也删掉，否则重启会卡在找 swap 文件上。开机卡住的典型提示是找不到 swap 设备，进 rescue 模式改 fstab 就能恢复。

改完 fstab 再确认一次，swapon --show 没有输出、free -h 的 Swap 行是 0，才算清干净。文件是不是真没了也核对一下：

bash
swapon --show
free -h
ls -l /var/cache/swap/

sudo swapoff -a 是停用所有 swap，不是「释放磁盘空间」。只想关这一个就用上面的路径。swapoff --help 看参数，free -m 看当前内存和 swap 用量。swapoff -a 会连发行版安装时自动配的 swap 分区一起停掉，那些是有意配的，别随手用。善后检查表：

检查项 命令 期望结果
还有 swap 在用吗 swapon --show 没有输出，或只剩你保留的分区
内存与 swap 用量 free -h Swap 行符合预期
fstab 里还有残留行吗 grep -i swap /etc/fstab 没有指向已删文件的行
文件真删了吗 ls /var/cache/swap/ 空目录或不存在

/var/cache/swap 这个目录本身可以留着，下次应急再放文件进去。不想留就一起删。

十一、三个故障的排查顺序 #

三个问题看着无关，根源都是「虚拟机与宿主机之间的边界」：

故障 跨的是什么边界 为什么表现出来是这样
共享文件夹挂不上 文件系统边界 宿主机的目录不是块设备，得靠 FUSE 翻译一层
磁盘删了不变小 客机删了但宿主不知道 客机改的是 vmdk 内部结构，宿主机只看文件占了多少块
编译内存不足 客机要的超过宿主给的 客机配的内存是宿主机划出去的一块，超了只能换页或被杀

共享文件夹跨了文件系统边界（所以要用 FUSE）、磁盘增长跨了「客机删了但宿主不知道」的边界（所以要主动收缩）、内存不足是「客机要的超过宿主给的」边界。记住这一句，三个问题的处理方向就都顺了。

共享文件夹挂不上 #

按这个顺序查：

  1. 虚拟机设置里启用共享文件夹了吗（含「总是启用」）
  2. open-vm-tools 和 -desktop 装了没，vmtoolsd 在跑没
  3. vmware-hgfsclient 有输出吗，名字对吗
  4. 挂载命令用的是 vmhgfs-fuse 还是老的 vmhgfs（新内核必须是前者）
  5. allow_other 和 /etc/fuse.conf 配了吗
  6. 挂载点目录存在吗，之前是不是挂过没 umount

磁盘删了不变小 #

按这个顺序：先清客机 → 再删快照 → 最后收缩 vmdk。

  1. df -h 和 du 对齐，确认空间到底在哪一层
  2. 清客机内部：拖放缓存、包管理器缓存、日志、已卸载残留
  3. 清空闲块：dd if=/dev/zero 填满再删，或 zerofree
  4. 删掉不用的快照
  5. vmware-toolbox-cmd disk shrink /
  6. 还不行就走 DiskGenius 重建或导出 OVF

第 2、3 步没做就直接第 5 步，收缩完你会发现白干。

编译内存不足 #

  1. dmesg -T | grep -i -E 'killed process|out of memory' 确认是不是 OOM
  2. 是 OOM，先 make -j2 把当前这轮编译跑完
  3. 还想更快，临时加 swap 文件应急
  4. 长期方案：关机加虚拟机内存
  5. 确认不再需要 swap 后，按第十章三步删干净

三件事的共性 #

每次动手之前，先问自己一句：这个操作是在客机里做，还是在宿主机上做？

  • 清缓存、清空闲块、vmware-toolbox-cmd、make -j2：客机里
  • 快照管理、DiskGenius、导出 OVF、改虚拟机内存配置：宿主机上

在客机里想删快照、在宿主机上找 vmware-toolbox-cmd，这类错位是最浪费时间的一种。命令跑不通先别怀疑版本，先怀疑自己站错了位置。

十二、易错点速查 #

易错点 症状 正确做法
用 mount -t vmhgfs unknown filesystem type 新内核用 vmhgfs-fuse，fstab 写 fuse.vmhgfs-fuse
没装 open-vm-tools-desktop GUI 客机共享文件夹挂不上 两个包都装
还在装官方 tar 包 Tools 内核升级后模块编不过 卸掉，换 open-vm-tools
allow_other 没配 /etc/fuse.conf 普通用户进不去挂载点 加 user_allow_other，或用 root 挂
fstab 里没加 nofail 共享名一改就卡开机 选项里加 nofail
挂载点写 # 开头注释行搞混 改注释把配置注释掉了 注释和配置分两行看
删了客机文件就以为盘会小 宿主机 .vmdk 纹丝不动 先清零空闲块，再删快照，最后收缩
跳过清零直接收缩 收缩完大小没变 dd 填零或 zerofree
把快照当备份 父盘坏了快照一起没 快照只用做临时回滚点
快照链叠很长 虚拟机越来越卡 用完就删，别长期留
删快照时干别的重活 IO 抢到一起，两边都慢 等它跑完再操作
收缩时关虚拟机 收缩中断，白干 收缩期间不关机、不挂起
重建后新 vmdk 名字不一致 虚拟机开不起来 改成和源文件逐字一致
DiskGenius 还没关就改名 文件被占用，改不动 先关软件再改
加完 swap 忘了删 长期跑在 swap 上，SSD 磨损 swapoff + 删文件 + 改 fstab
漏改 fstab 重启卡在找 swap 文件 三步都要做
swapoff -a 当清理命令用 把所有 swap 都停了 指定路径，只关自己加的那个
内存不足就猛加 swap 编译变慢，问题被掩盖 make -j2 先扛，长期加内存
在客机里找快照菜单 找不到 快照管理在宿主机的 VMware 界面
在宿主机上敲 vmware-toolbox-cmd command not found 这个命令在客机里跑

最后一个检查清单，照着过一遍：

  • 共享文件夹：vmware-hgfsclient 有输出 → vmhgfs-fuse 手动挂上 → fstab 写对 → mount -a 干净 → 重启后还在
  • 磁盘：df 和 du 对齐 → 清缓存 → 清零空闲块 → 删快照 → disk shrink → 宿主机上 .vmdk 变小
  • 内存：dmesg 确认 OOM → make -j2 → 必要时加 swap → 用完 swapoff + 删文件 + 改 fstab

三条路都走完，VMware 客机的日常使用就没什么能绊住你了。
