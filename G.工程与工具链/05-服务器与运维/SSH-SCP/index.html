在本地电脑与远程服务器之间拷贝文件，最顺手的工具就是 scp 和 rsync。两者都直接复用 SSH 协议与认证体系，不需要在服务器上额外搭建 FTP 服务，防火墙只要放通 22 端口就能直接传。

很多人的习惯是传单个文件用 scp，遇到大文件、目录同步或定时任务就上 rsync。本文把这两种工具的常用姿势、参数避坑以及跨平台细节一次性讲透。

1. SCP 核心机制与 OpenSSH 9.0 变革 #

SCP（Secure Copy Protocol）是基于 SSH 的传统跨机拷贝工具。它有两个关键特性：

1.1 OpenSSH 9.0 底层协议大翻新 #

在过去几十里，scp 底层使用的是 1982 年 BSD 的 rcp 协议。由于 rcp 协议没有规范客户端与服务端对通配符的展开方式，存在历史上知名的远端路径注入安全漏洞（CVE-2019-6111）。

自 OpenSSH 9.0（2022 年）起，scp 默认全部改用 SFTP 协议作为底层传输，彻底告别了旧 rcp 协议。

这带来了一个现实坑点：

❢重要

如果你的目标服务器是一台老旧 Linux、嵌入式开发板或精简路由器，其 sshd_config 里没有配置 Subsystem sftp internal-sftp，本地的新版 scp 会报错：subsystem request failed on channel 0 或 scp: Connection closed。 此时加上大写 -O 参数，强制回退使用传统 SCP/RCP 协议即可连通：

bash
scp -O ./firmware.bin root@192.168.1.1:/tmp/

2. SCP 常用实战 #

SCP 的语法直观：scp [选项] 源路径 目标路径。谁在远端，谁就带上 user@host: 前缀。

2.1 上传与下载 #

bash
# 1. 本地上传单文件到远端服务器
scp ./app.tar.gz devops@203.0.113.10:/opt/data/

# 2. 从远端下载文件到本地当前目录
scp devops@203.0.113.10:/var/log/nginx/access.log ./

# 3. 递归拷贝整个目录（必须加大写 -r）
scp -r ./dist/ devops@203.0.113.10:/var/www/html/dist/

# 4. 双远端直传（本地机器作为调度端，让两台远端 VPS 间倒腾数据）
scp user1@host1:/data/dump.sql user2@host2:/backup/

2.2 核心参数速查 #

参数 作用 常见踩坑点
-P（大写） 指定 SSH 非标准端口 极高频踩坑：SSH 命令是小写 -p，而 SCP 指定端口必须是大写 -P！写成小写 -p 22222 会被当成「保留属性并将文件改名为 22222」
-p（小写） 保留原始文件的修改时间（mtime）、访问时间与权限位 备份配置文件时建议带上，避免恢复后时间戳全部更新为当前时刻
-r 递归拷贝目录及子内容 漏加 -r 拷目录会直接报 not a regular file 并退出
-C 开启 gzip 压缩传输 传输纯文本、日志、未压缩的 SQL 文件时可压下 60% 流量；传输已经压缩过的 zip/gz 时不要开，白耗 CPU
-l 限制传输速率（单位 Kbit/s） 8 Kbit = 1 KB。若要限速 2 MB/s，设为 -l 16000。生产备份大包时必加，防打爆出口业务带宽
-i 指定私钥文件路径 配合非默认命名的私钥，如 -i ~/.ssh/id_ed25519_prod
-O 强制使用旧版 SCP 协议（避免 SFTP subsystem 依赖） 老旧系统或精简开发板连不上时使用

标准带端口与密钥的上传范例：

bash
scp -P 22222 -i ~/.ssh/id_ed25519 -C -r ./build/ devops@203.0.113.10:/srv/app/

如果本地配置了 ~/.ssh/config（参见 SSH.md），端口、私钥和用户直接被别名吞掉，直接写别名即可：

bash
scp ./app.zip prod:/opt/

3. Windows 与 Linux 跨系统拷贝踩坑点 #

在 Windows（PowerShell 或 CMD）向远程 Linux 拷贝时，路径格式最容易翻车。

3.1 反斜杠转义与制表符灾难 #

在 PowerShell 或批处理中，C:\Files\text.txt 里的 \t 会被终端误当成 Tab 制表符转义，导致文件路径找不到。

安全规范：

  • 路径外层必须加双引号；
  • 推荐在 Windows 终端中统一使用正斜杠 /：
    powershell
    # 正确写法（正斜杠 + 引号）
scp "C:/Users/Administrator/Desktop/app.zip" devops@203.0.113.10:/tmp/

3.2 路径含空格 #

无论 Windows 还是 Linux，路径有空格时必须双重引注：

powershell
scp "C:/My Documents/data.xlsx" "devops@203.0.113.10:'/data/target folder/'"

4. 生产进阶：为什么大文件与目录同步首选 Rsync #

scp 传小文件很方便，但在生产级运维中有三大致命缺陷：

  1. 不能断点续传：传一个 20GB 的数据库镜像，传到 99% 时网络抖动断开，scp 无法续传，只能从 0% 重新来过；
  2. 没有增量比对：一个包含了 5 万张图片的文件目录，只新增了 2 张，scp 会把 5 万张全部重新拷一遍；
  3. 无法排除特定目录：无法方便地跳过 node_modules、.git、日志等垃圾文件。

解决这三点，用 Rsync（Remote Sync）。

bash
# 确认安装
sudo apt install -y rsync   # Debian / Ubuntu
sudo dnf install -y rsync   # RHEL / CentOS

4.1 Rsync over SSH 黄金生产命令 #

bash
rsync -avzP -e "ssh -p 22222" --exclude="*.log" --exclude="node_modules" ./my-project/ devops@203.0.113.10:/opt/my-project/

参数逐个拆解：

  • -a（archive，归档模式）：包含 -rlptgoD，完整保留软链接、权限、属主属组、时间戳与设备文件；
  • -v（verbose）：输出详细过程；
  • -z（compress）：传输中途压缩；
  • -P：最重要的实战参数，等于 --partial（保留未传完的文件，断网后重跑直接断点续传）+ --progress（显示实时传输速率与剩余时间百分比）；
  • -e "ssh -p 端口"：指定底层的 SSH 端口与参数。

4.2 末尾斜杠（/）的生死差异 #

这是 Rsync 全网公认的最深坑：

命令书写 行为 目标端结果
rsync -a /data/web /backup/（源目录末尾无斜杠） 拷贝 web 目录本身 目标端生成 /backup/web/...
rsync -a /data/web/ /backup/（源目录末尾有斜杠） 拷贝 web 目录里面的内容 内容散落在 /backup/... 下，不产生 web 文件夹

记法：有斜杠只拷贝里面的内容，无斜杠连文件夹本身一起拷贝。

4.3 演练模式（Dry-Run） #

在同步生产几万个文件前，先用 -n 跑一遍空转，确保不会误删误改：

bash
rsync -avzn --delete ./dist/ devops@203.0.113.10:/var/www/dist/

-n（--dry-run）只会打印出如果执行会动哪些文件，绝不进行真实的写入和删除。确认无误后再去掉 -n 正式跑。

5. 文件传输方案选型矩阵 #

工具 适用场景 优势 局限
SCP 单文件/临时安装包一次性拷贝 自带工具，无需额外依赖 无断点续传、无增量同步
Rsync 网站发版、数据库冷备份、大目录迁移 差分增量传输、断点续传、支持排他过滤 需两端均装有 rsync
SFTP 交互式操作、第三方图形客户端（FileZilla/WinSCP） 权限受控、可做 chroot 隔离 详见 FTP.md 的 SFTP 章节
NFS 多台服务器实时共享同一目录 原生挂载，对业务完全透明 依赖局域网，详见 NFS.md

6. 常见故障排查 #

错误信息 原因 处理动作
subsystem request failed on channel 0 本地为新版 OpenSSH，服务端缺失 SFTP 子系统 加 -O 回退传统协议：scp -O file user@host:/path
command not found: rsync 远端服务器没有装 rsync 二进制 服务端安装：sudo apt install rsync
Permission denied 目标目录当前用户无写权限 检查目标目录属主，或在目标端先 sudo mkdir 并赋予写权限
Connection timed out 端口不对、防火墙拦截或安全组未开 参考 SSH.md 核对端口与网络连通性
lost connection 传输超大文件时网络抖动中断 换用 rsync -P 重新执行，自动接上进度续传
