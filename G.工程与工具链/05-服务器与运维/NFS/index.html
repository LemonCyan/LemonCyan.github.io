1. NFS 是什么 #

NFS（Network File System，网络文件系统）把远程主机的目录挂到本地目录树上，之后读写它和读写本地磁盘没有区别。协议自 1984 年 Sun 提出，Linux、UNIX、macOS 与多数嵌入式系统原生支持。

两个核心能力：

能力 在服务端 在客户端
共享（export） /etc/exports 声明哪些目录给哪些主机 无需配置
挂载（mount） 无需配置 mount -t nfs 把远端目录接入本地路径
⚠警告

NFS 的访问控制建立在客户端 IP 与 UID 的信任之上，不是账号密码认证。服务端认为 192.168.1.10 就是它自称的那台机器，并按客户端传来的 UID 决定文件归属。因此绝不能把 NFS 端口暴露到公网：能把 UID 伪造成 0 的客户端等于拿到服务端 root。跨公网共享请改用 SSHFS，或 Samba 加认证。

场景 是否适合 NFS 说明
机房内多台 Web 服务器共享上传目录 ✅ 静态文件实时一致，比 rsync 简单
嵌入式开发板网络启动挂根文件系统 ✅ 改代码不必重新烧写，重启即生效
容器跨节点共享持久卷 ⚠️ 可用，但 v3 的锁语义弱，优先 CSI 方案
家里跨公网访问 NAS ❌ 无加密无认证，先用 WireGuard 打隧道
高频小写入且要求强一致 ⚠️ 锁与元数据开销大，改用本地盘或对象存储

1.1 版本选择 #

版本 端口 认证 建议
NFSv3 2049 + rpcbind(111) + mountd/statd 随机端口 AUTH_SYS（UID） 仅老设备兼容时用，防火墙极难配
NFSv4.0 / 4.1 仅 2049 内置，支持 sec=krb5 可用
NFSv4.2 仅 2049 内置，支持服务端复制、稀疏文件 现代部署默认，一个端口穿防火墙
✦提示

v4 把 mountd、statd 并入 2049，不再依赖 rpcbind，云主机安全组只放 2049/tcp 即可，这是选 v4 最实际的理由。挂载时显式写 nfsvers=4.2，否则内核先用 v3 探测、失败再回退，白等几秒。

2. 服务端配置 #

2.1 安装 #

bash
sudo apt update
sudo apt install -y nfs-kernel-server   # 内核态服务端，比用户态 nfs-ganesha 快
sudo systemctl enable --now nfs-server  # Debian/Ubuntu 服务名是 nfs-server，不是 nfs
systemctl status nfs-server --no-pager
ℹ笔记

老教程里的 /etc/init.d/nfs-kernel-server start|stop|restart|status 是 SysV 写法，Ubuntu 16.04 之后由 systemd 接管，对应关系是 service nfs-kernel-server restart → systemctl restart nfs-server。两代命令都还能用，但新版只是把前者转成 systemd 调用，日志进 journald，不再有「4 个连续 OK」这种输出。判据改为：Active: active (exited) 且 exportfs -v 有内容。

2.2 建共享目录 #

bash
sudo mkdir -p /srv/nfs/data
# 属主交给 NFS 匿名映射账号（Debian/Ubuntu 是 nobody:nogroup，RHEL 系是 nfsnobody）
sudo chown -R nobody:nogroup /srv/nfs/data
sudo chmod 755 /srv/nfs/data
⚠警告

源笔记满篇 chmod 777 -R。777 意味着任何能连上 2049 的主机上的任何 UID 都可读可写可执行，等于把目录交给整个网段。确需让任意 UID 写入时，用「all_squash + 0777 + 独立目录」组合，并限定 exports 客户端网段；其余情况一律 chown 属主 + 默认 root_squash。

2.3 /etc/exports 语法 #

格式：共享路径 客户端(选项1,选项2)，一行一条导出，客户端与左括号之间不能有空格。

bash
# 共享目录          客户端            选项
/srv/nfs/data        192.168.1.0/24(rw,sync,no_subtree_check)
/srv/nfs/data        192.168.1.10(rw,sync,no_root_squash)   # 单机白名单，允许保留 root
/srv/nfs/www         10.0.0.0/8(ro,sync,no_subtree_check)   # 只读，给静态资源节点
选项 含义 生产建议
ro / rw 只读 / 读写 静态资源与归档给 ro，减少误删与加密勒索的影响面
sync 数据落盘后才回 ACK 默认，宁可慢也不丢数据
async 先回 ACK 再异步刷盘 只给可重建的临时数据，断电会丢且可能损坏元数据
root_squash 客户端 root 映射为匿名账号 nobody 默认值，必开，防客户端 root 改服务端属主
no_root_squash 客户端 root 保持 root 仅限无盘工作站、嵌入式 rootfs 等特殊场景
all_squash 所有 UID 都映射为匿名账号 匿名共享时用，配合 0777
no_subtree_check 不校验父目录是否也在导出范围内 v4 已是默认；v3 加上可省 stat 开销
insecure 允许客户端源端口 > 1024 容器、NAT 后面的客户端必须加
sec=sys / sec=krb5 UID 认证 / Kerberos 认证 只在跨不可信网段时上 Kerberos
❢重要

源笔记写的 /nfsboot * (rw,sync,no_subtree_check) 有两个错误：星号与左括号之间多了空格，解析器会当成「主机 」加「主机 ()」两条独立条目，导出静默失效；选项里也不该有空格。正确写法是 /nfsboot *(rw,sync,no_subtree_check)。改完必须 exportfs -rav 并核对输出，只有语法错它才会报出来。

[!NOTE] insecure 约束的是客户端源端口：NFS 传统上要求客户端从 <1024 的特权端口发起连接（沿用「只有 root 能绑低端口」的旧假设）。容器内的进程通常拿不到低端口，NAT 也会改写源端口，于是被服务端拒绝，报 access denied by server while mounting。加 insecure 才能放行。它不是加密开关，别指望提升安全性。

2.4 生效与验证 #

bash
sudo exportfs -rav     # -r 重读 exports，-a 全量，-v 打印每条处理结果
sudo exportfs -v       # 复核：目录、客户端、选项三列都要对得上
sudo showmount -e localhost        # 服务端自检导出的目录树
sudo showmount -e 192.168.1.5      # 客户端侧验证：能列出目录说明网络与端口通了

bash
# 临时加一条，不写文件，重启即失效，适合排障对比
sudo exportfs -o rw,sync,no_subtree_check 192.168.1.10:/srv/nfs/data

# 撤销单条导出，不影响其余
sudo exportfs -u 192.168.1.10:/srv/nfs/data

3. 客户端挂载 #

bash
sudo apt install -y nfs-common      # 客户端只要这个，不要装 nfs-kernel-server
sudo mkdir -p /mnt/nfs
sudo mount -t nfs -o nfsvers=4.2 192.168.1.5:/srv/nfs/data /mnt/nfs
✦提示

先做本机自测再上远端：sudo mount -t nfs 127.0.0.1:/srv/nfs/data /mnt/temp 能挂上，说明 exports 与服务都正常，挂不上就是导出或防火墙问题，与目标机无关。测完 sudo umount /mnt/temp。

3.1 挂载选项 #

选项 作用 建议值
nfsvers=4.2 指定协议版本，跳过 v3 探测 显式写上
hard / soft 服务端无响应时无限重试 / 超时返回错误 关键路径 soft，其余 hard
timeo=100 重试超时，单位 0.1 秒 内网 100（10 秒）
retrans=3 重传次数 仅对 soft 有意义
intr 允许信号中断挂起的调用 内核 2.6.25+ 已默认，不必写
rsize/wsize=1048576 单次读写块大小 千兆内网设 1M，v4.2 会自动协商
noatime 不更新访问时间 加上，元数据写明显减少
_netdev 等网络就绪后再挂 fstab 里必加，否则可能卡住开机

3.2 开机自动挂载 #

bash
# /etc/fstab —— 最后两个 0 表示不 dump、开机不 fsck
192.168.1.5:/srv/nfs/data  /mnt/nfs  nfs  nfsvers=4.2,hard,timeo=100,_netdev,noatime  0 0

bash
sudo mount -a      # 先验证再重启，fstab 写错会导致开机进 emergency mode
findmnt /mnt/nfs
⚠警告

用 hard 时服务端一旦宕机，访问挂载点的进程会进入不可中断睡眠（D 状态），kill -9 也杀不掉。若该目录被 Web 服务或数据库依赖，整站跟着挂住。关键路径改用 soft,timeo=50,retrans=2，或用 autofs 按需挂载。

3.3 卸载 #

bash
sudo umount /mnt/nfs        # 有进程占用时报 target is busy
sudo fuser -vm /mnt/nfs     # 先查是谁占着它
sudo umount -f /mnt/nfs     # 强制卸载，服务端已消失时用
sudo umount -l /mnt/nfs     # 懒卸载：立即摘出目录树，引用清零后真正断开
mount | grep nfs            # 查看当前所有 NFS 挂载
✦提示

服务端已关机、umount 卡住不动时，-f 往往也无效（进程处于 D 状态）。用 umount -l 立即解绑，或重启客户端。服务端恢复后记得重新 mount -a。

4. 常用命令与排错 #

bash
# 1. 服务状态与导出清单
systemctl status nfs-server --no-pager
exportfs -v

# 2. RPC 注册情况（v4.2 只用 2049，以下多为 v3 相关）
rpcinfo -p localhost
# 期望看到 nfs 2049/tcp；v3 还会有 mountd、statd、rquotad

# 3. 端口与防火墙：v4 只需 2049
ss -lntp | grep 2049
sudo ufw allow 2049/tcp
# v3 另需 111/tcp+udp（rpcbind）与 mountd/statd 的随机端口，
# 或在 /etc/default/nfs-kernel-server 固定 RPCMOUNTDOPTS="-p 20048"

# 4. 客户端视角
showmount -e 192.168.1.5    # 能看到哪些导出
showmount -a 192.168.1.5    # 谁挂载了哪些目录

# 5. 排障日志
sudo dmesg | tail -20
sudo journalctl -u nfs-server -n 50 --no-pager

4.1 排错表 #

现象 根因 处置
access denied by server while mounting 客户端不匹配、选项含空格、源端口 <1024 被拒 exportfs -v 核对条目；补 insecure；确认网段写法
Connection timed out 2049 被防火墙拦或服务未起 ss -lntp 查监听；ufw status；云上放行安全组
No such file or directory 共享路径写错，或 exports 未生效 服务端 ls -d 该路径；exportfs -rav 重载
挂载成功但 ls 报 Permission denied 服务端目录权限或 UID 被 squash ls -ld 看属主；统一 UID，或 all_squash + 0777
挂上之后只读 服务端 ro，或客户端无写权限 exportfs -v 看 rw/ro；touch 实测
写入很慢 sync 未评估、wsize 太小 可重建数据改 async；调大 wsize
客户端重启卡在启动阶段 fstab 缺 _netdev，或服务端不可达 进单用户改 fstab；补 _netdev，关键项改 soft
umount: target is busy 有进程 cwd 在目录内或开着文件 fuser -vm 定位；umount -l
v3 能挂、v4 挂不上 内核缺 v4 支持，或被 SELinux/AppArmor 拦 cat /proc/filesystems 查 nfs；看审计日志
exportfs: no options for /srv/x * 客户端条目后缺选项括号 补 (rw,sync)

5. 嵌入式实战：开发板网络启动（TFTP 传内核 + NFS 挂 rootfs） #

开发板的 SPI Flash / eMMC 擦写寿命有限，每改一行代码就烧一次镜像无法接受。标准做法把启动拆成两段：

阶段 协议 内容 载体
第一段 TFTP zImage 内核（几 MB） U-Boot 下载到内存固定地址后 go 执行
第二段 NFS rootfs 整个根文件系统 内核按 nfsroot= 挂载主机目录

改应用代码只需在主机上编辑文件、重启开发板；换内核只需替换 tftpboot 里的 zImage。TFTP 只管「一次性、体积小、只读」的内核镜像，NFS 管「持续、体积大、可读写」的根文件系统——这条分工是理解整套流程的主线。

5.1 主机侧：TFTP 服务 #

bash
sudo apt install -y tftp tftpd-hpa    # tftp 是客户端，tftpd-hpa 是服务端
sudo mkdir -p /srv/tftpboot
sudo chown -R tftp:tftp /srv/tftpboot
sudo cp /path/to/zImage /srv/tftpboot/
sudo chmod 644 /srv/tftpboot/zImage

ini
# /etc/default/tftpd-hpa —— 改完必须 restart，不重启等于没改
TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/srv/tftpboot"   # 绝对路径，且必须与实际存放 zImage 的目录一致
TFTP_ADDRESS="0.0.0.0:69"        # 69/udp；TFTP 无认证，只在内网开
TFTP_OPTIONS="--secure --create" # --secure 把服务锁定在该目录内，防目录穿越

bash
sudo systemctl restart tftpd-hpa
systemctl status tftpd-hpa --no-pager
ss -lunp | grep :69
# 自测：本机拉一次，能收到字节数即通
tftp 127.0.0.1 -c get zImage
⚠警告

两个高频报错：① Permission denied —— tftpd 以 tftp 用户身份运行，目录属主或文件可读位不对；用 chown -R tftp:tftp 加 644 解决，不要 chmod 777 -R。② File not found —— 文件名拼错，或 TFTP_DIRECTORY 改过却忘了 restart，服务仍在旧目录里找。另注意 TFTP 走 69/udp，用 curl 测不通是正常的。

5.2 主机侧：导出 rootfs #

bash
sudo mkdir -p /srv/nfs/rootfs
sudo tar -zxvf /path/to/rootfs.tgz -C /srv/nfs/rootfs   # 带上 -C，避免解出多余一层目录
sudo chown -R nobody:nogroup /srv/nfs/rootfs   # RHEL 系写成 nfsnobody:nfsnobody
sudo chmod -R 755 /srv/nfs/rootfs
ls /srv/nfs/rootfs | head      # 应看到 bin dev etc lib linuxrc proc sbin sys usr

bash
# /etc/exports
/srv/nfs/rootfs  192.168.2.0/24(rw,sync,no_subtree_check,no_root_squash)
❢重要

开发板 rootfs 必须加 no_root_squash。板子上所有进程都以 UID 0 运行，一旦被 squash 成 nobody，mknod 建设备节点、chown 改属主、写 /etc 全部失败，现象是内核挂载成功却停在 init 起不来。这是嵌入式共享与普通文件共享最关键的一处差异。

bash
sudo exportfs -rav && sudo exportfs -v
sudo showmount -e localhost

5.3 开发板侧：U-Boot 环境变量 #

bash
# 1. 网络参数：板子自身 IP、服务器 IP、掩码、网关
setenv ipaddr 192.168.2.3        # 板子地址，需与主机同网段且未被占用
setenv serverip 192.168.2.2      # 主机地址，TFTP 与 NFS 都指向它
setenv netmask 255.255.255.0
setenv gatewayip 192.168.2.1     # 直连同网段可不设，跨网段必须正确

# 2. 启动命令：TFTP 取内核到内存 0x20008000，再从该地址执行
setenv bootcmd 'tftp 20008000 zImage; go 20008000'

# 3. 内核启动参数：根文件系统走 NFS
setenv bootargs 'root=/dev/nfs rw nfsroot=192.168.2.2:/srv/nfs/rootfs,vers=4.2 ip=192.168.2.3:192.168.2.2:192.168.2.1:255.255.255.0::eth0:off init=/linuxrc console=ttySAC0,115200'

# 4. 落到非易失存储，否则断电即失
saveenv

bash
# 验证：直接 boot，或分步执行以便观察每一步的耗时与报错
boot
tftp 20008000 zImage
go 20008000

bash
# 换用 zImage_all（已打包 dtb 或模块）时只需改文件名
setenv bootcmd 'tftp 20008000 zImage_all; go 20008000'
saveenv
boot

bootargs 逐段解释 #

片段 作用 写错的后果
root=/dev/nfs 声明根文件系统不在块设备上 内核去找 /dev/mmcblk0p2，报 VFS: Unable to mount root fs
nfsroot=192.168.2.2:/srv/nfs/rootfs 服务器 IP + 导出路径，必须与 exports 逐字符一致 挂载超时，或 No such file or directory
,vers=4.2 指定 NFS 版本 老内核默认 v3，需要 rpcbind，常直接超时
ip=客户端:服务器:网关:掩码::网卡:off 内核态自配 IP（此时用户态尚未启动） 挂载前没网，nfsroot 必然失败；off 表示不做 DHCP
init=/linuxrc 第一个用户态进程，busybox 系统的入口 日志停在末尾无 shell，需确认该路径真实存在
console=ttySAC0,115200 串口控制台与波特率，三星/Exynos 系列常见 屏幕无输出，被误判成「板子没起来」
✦提示

console= 是排查的第一优先级：串口完全无输出时先换 ttySAC0 / ttyAMA0 / ttymxc0 逐个试，再怀疑内核。第二大坑是 nfsroot 与 exports 路径不一致——多一层或少一层目录就是 No such file or directory，用 showmount -e 对照最快。

[!NOTE] 网络启动要求内核已内建 NFS 客户端与网卡驱动：CONFIG_ROOT_NFS=y、CONFIG_IP_PNP=y 缺一不可。若编译成 =m，内核挂载根文件系统时还没有模块可加载，必然失败。

6. 安全与性能 #

6.1 安全基线 #

措施 做法 原因
限制客户端网段 exports 写 192.168.1.0/24，禁用裸 * 横向移动的第一步就是找开放共享
保持 root_squash 用默认值，不为省事关掉 客户端 root 无法改服务端属主、无法造 setuid 文件
只读优先 静态资源与归档一律 ro 勒索软件加密不了只读挂载
匿名共享配 all_squash 配 0777 与独立目录 比裸 777 加 root_squash 更可控
端口收敛 用 v4.2，安全组只放 2049/tcp 端口少一个，攻击面少一片
不跨公网 必须跨就用 WireGuard / IPsec 隧道 NFS 无加密、无强认证，v4 的 Kerberos 部署成本高
挂载审计 定期 showmount -a 发现异常客户端

6.2 性能取舍 #

参数 偏安全 偏性能 折中建议
同步策略 sync async 可重建数据用 async，配置与数据库一律 sync
子树检查 subtree_check no_subtree_check 用 no_subtree_check，v4 已是默认
传输块 默认 wsize=1048576 千兆以上内网设 1M
访问时间 relatime noatime 加 noatime
挂载语义 hard soft 关键路径 soft 防卡死，其余 hard 保正确性 
bash
# 观测：每秒 RPC 调用、重传次数、平均延迟，用来区分网络问题与服务端磁盘问题
sudo apt install -y nfs-utils   # 提供 nfsiostat
nfsiostat 1 5
iostat -xz 1 3                  # 服务端侧对照磁盘利用率
sar -n DEV 1 3                  # 对照网卡吞吐
✦提示

客户端写入慢而服务端磁盘不忙时，先看 nfsiostat 的 retrans 与 avg exe (ms)：retrans 上升说明丢包，多为网卡 offload 或交换机 MTU 不匹配；avg exe 高而 retrans 为 0，则是服务端磁盘 I/O 饱和，该换 SSD 或拆分导出，调参数没有捷径。
