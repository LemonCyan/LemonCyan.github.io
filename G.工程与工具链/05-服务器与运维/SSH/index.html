SSH（Secure Shell）是远程管理 Linux 服务器的事实标准协议。不管是日常终端敲命令、Git 代码拉取、跨机文件传输，还是内网打洞隧道，底层走的都是 SSH。

本文按「连接、配置、密钥、安全加固、隧道转发、排错」的完整链路展开，所有配置与命令均可直接复用。跨机文件传输详解见同目录 SSH-SCP.md；主机防火墙与防御联动见 服务器安全.md。

1. 核心架构与连接基础 #

SSH 采用典型的 C/S 架构，默认监听 TCP 22 端口：

  • 客户端（Client）：本地电脑上的 ssh 命令（Linux/macOS 原生自带，Windows 10/11 亦已内置 OpenSSH Client）；
  • 服务端（Server）：服务器上常驻的守护进程 sshd（OpenSSH Server）。

两端建立会话时，先通过非对称加密完成密钥交换与主机身份校验，随后协商出对称会话密钥，后续传输全部经对称加密保护，彻底阻断网络嗅探。

基础连接命令：

bash
# 标准格式：ssh 用户名@服务器IP
ssh root@192.168.1.50

# 指定非标准端口（注意小写 -p；SCP 中为大写 -P）
ssh -p 22222 root@192.168.1.50

# 显式指定私钥文件
ssh -i ~/.ssh/id_ed25519 -p 22222 root@192.168.1.50

2. 客户端高效运维：~/.ssh/config 别名配置 #

每次连接都要敲一长串 IP、端口、用户和密钥路径极其繁琐。通过配置本地的 ~/.ssh/config（Windows 为 C:\Users\用户名\.ssh\config），敲 ssh prod 即可秒连。

2.1 推荐配置模板 #

编辑本地 ~/.ssh/config：

text
# 全局默认行为（对所有主机生效）
Host *
    # 防连接假死：每 60 秒向服务端发一次心跳
    ServerAliveInterval 60
    # 连续 3 次心跳无响应才判定断开
    ServerAliveCountMax 3
    # 启用长连接 TCP 保活
    TCPKeepAlive yes
    # 优先使用现代 Ed25519 算法
    HostKeyAlgorithms ssh-ed25519,rsa-sha2-512,rsa-sha2-256
    # 首次连接新主机时自动记录指纹，但不放行变更的主机
    StrictHostKeyChecking accept-new

# 场景 1：生产服务器别名
Host prod
    HostName 203.0.113.10
    User devops
    Port 22222
    IdentityFile ~/.ssh/id_ed25519_prod

# 场景 2：测试环境
Host dev
    HostName 192.168.1.80
    User ubuntu
    Port 22
    IdentityFile ~/.ssh/id_ed25519_dev

# 场景 3：通过跳板机/堡垒机直连内网机器
Host bastion
    HostName 203.0.113.200
    User jumpuser
    Port 22

Host internal-db
    HostName 10.0.0.50
    User root
    # 一行声明跳板：通过 bastion 自动透明转发
    ProxyJump bastion

配置后：

bash
ssh prod         # 等价于 ssh -p 22222 -i ~/.ssh/id_ed25519_prod devops@203.0.113.10
ssh internal-db  # 自动经由 bastion 跳板进入内网数据库机器

3. 密钥认证与免密登录 #

密码认证存在被暴力破解的风险。生产环境必须采用非对称密钥认证：客户端持有私钥，服务端存放公钥。

3.1 密钥算法选型 #

算法 安全性 速度 长度 推荐度
Ed25519 极高（抗侧信道） 极快 68 字符（短小不易折行） ⭐⭐⭐⭐⭐ 首选
RSA 4096 高 较慢 500+ 字符 ⭐⭐⭐ 仅老系统兼容时用
RSA 1024/2048 偏低 / 已淘汰 一般 较长 ❌ 严禁新生成

3.2 生成密钥对 #

在本地机器上运行：

bash
# 生成 Ed25519 密钥对，并打上可辨认的注释
ssh-keygen -t ed25519 -C "laptop-2026-ops" -f ~/.ssh/id_ed25519

# 若需设置 passphrase（密钥密码），按提示输入；若免交互直接回车留空

会在 ~/.ssh/ 下生成两个文件：

  • id_ed25519：私钥，绝对不能给任何人，权限必须是 600；
  • id_ed25519.pub：公钥，用于存放到各台服务器上。

3.3 分发公钥到服务器 #

姿势一：ssh-copy-id（Linux / macOS / 现代 Windows） #

bash
# 自动把公钥追加到服务端的 ~/.ssh/authorized_keys 并校正权限
ssh-copy-id -i ~/.ssh/id_ed25519.pub -p 22222 devops@203.0.113.10

姿势二：Windows PowerShell 单行命令 #

如果本地是老版本 Windows，没有 ssh-copy-id 命令，可在 PowerShell 中执行一行流：

powershell
Get-Content $HOME\.ssh\id_ed25519.pub | ssh -p 22222 devops@203.0.113.10 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

3.4 服务端权限铁律 #

SSH 对权限有自我保护机制。如果目录或公钥文件对同组或其他用户开放了写权限，sshd 会直接拒绝读取公钥：

bash
# 服务端执行权限复核
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chown -R $(whoami):$(whoami) ~/.ssh

# 确认用户家目录本身不能是 777（必须 755 或 700）
chmod 755 ~

4. 服务端安全加固（sshd_config） #

修改 /etc/ssh/sshd_config 收缩攻击面。

bash
sudo vim /etc/ssh/sshd_config

4.1 核心加固配置 #

ini
# ---------- 端口与网络 ----------
# 改为高位非标准端口，挡掉 95% 全网自动化端口扫描
Port 22222
# 仅监听 IPv4（根据业务需要，若无 IPv6 环境可只留 0.0.0.0）
ListenAddress 0.0.0.0

# ---------- 身份认证与权限 ----------
# 启用公钥认证
PubkeyAuthentication yes

# 彻底禁用密码认证（确保密钥已实测能登后再改！）
PasswordAuthentication no
ChallengeResponseAuthentication no

# root 登录策略：
# prohibit-password = 禁用密码，但允许凭密钥登录（适合自动化任务）
# no = 彻底禁止 root 直登，必须先用普通用户登录再 sudo
PermitRootLogin prohibit-password

# 禁用空密码
PermitEmptyPasswords no

# 认证超时时间（秒），防止连接挂起占进程
LoginGraceTime 30

# 单连接最大认证尝试次数
MaxAuthTries 3

# ---------- 会话与保活 ----------
# 服务端向客户端发送保活包的间隔（秒）
ClientAliveInterval 60
# 连续 3 次无响应即断开僵尸会话
ClientAliveCountMax 3

# 禁用 X11 转发（纯服务端无需图形）
X11Forwarding no

4.2 语法校验与平滑生效 #

bash
# 1. 语法检查：无输出表示语法完全正确
sudo sshd -t

# 2. 检查防火墙放行新端口
sudo ufw allow 22222/tcp

# 3. 平滑重载（千万别在没有验证前断开当前终端）
sudo systemctl reload sshd
⛔危险

改完端口或关闭密码登录后，绝对不要退出当前终端！立刻新开一个本地终端窗口执行 ssh -p 22222 user@host 测试。确认新终端顺利连入后，再关闭旧终端。万一配置写错导致锁死，当前会话还在，还能当场改回来。

5. SSH 进阶：端口转发与隧道神技 #

SSH 隧道是运维日常最具杀伤力的瑞士军刀，能轻松绕过防火墙阻隔、安全穿透内网。

5.1 本地端口转发（-L，Local Forwarding） #

场景：远程服务器内网有一台 MySQL（10.0.0.5:3306），未对公网开放。你想在本地用 Navicat / DBeaver 直接连它。

bash
# 语法：ssh -L 本地端口:目标内网IP:目标端口 跳板机用户名@跳板机IP
ssh -L 13306:10.0.0.5:3306 -N -f devops@203.0.113.10 -p 22222
  • -N：不执行远程命令，仅用于端口转发；
  • -f：后台运行；
  • 此时本地直接连 127.0.0.1:13306，流量即被加密送入内网的 10.0.0.5:3306。

5.2 远端端口转发（-R，Remote Forwarding，轻量内网穿透） #

场景：你在本地笔记本上写代码（跑在 localhost:3000），想让远在外地的客户或同事直接访问看效果，而本地没有公网 IP。

bash
# 语法：ssh -R 远端端口:本地IP:本地端口 远端服务器用户@远端服务器IP
ssh -R 8080:127.0.0.1:3000 -N -f root@203.0.113.10

外部访客访问 http://203.0.113.10:8080，请求会自动沿 SSH 反向隧道打到你本地的 3000 端口。

注：远端服务器的 sshd_config 需开启 GatewayPorts yes，外部 IP 才能访问该监听端口。

5.3 动态端口转发（-D，SOCKS5 代理） #

场景：把远端服务器作为你的私有 SOCKS5 代理网关，出差时访问内网各种管理页面。

bash
# 本地 10808 端口启动 SOCKS5 代理
ssh -D 10808 -q -C -N -f devops@203.0.113.10 -p 22222

然后在浏览器设置 SwitchyOmega 或系统代理，SOCKS5 指向 127.0.0.1:10808，浏览器所有流量即从远端服务器代发。

6. Windows 下配置 SSH 服务端 #

若需要将一台 Windows 机器（办公主机或工控机）作为受控端接受 SSH 登录：

6.1 开启内置 OpenSSH Server #

在 Windows 10/11 的管理员 PowerShell 中执行：

powershell
# 1. 检查并安装 OpenSSH 服务端
Get-WindowsCapability -Online | Where-Object Name -like 'OpenSSH.Server*' | Add-WindowsCapability -Online

# 2. 启动服务并设置开机自启
Start-Service sshd
Set-Service -Name sshd -StartupType 'Automatic'

# 3. 防火墙放行 22 端口
New-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -DisplayName 'OpenSSH Server (sshd)' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22

6.2 Windows 下的公钥配置 #

Windows 的公钥路径与 Linux 略有差异：

  • 普通用户：公钥写入 C:\Users\<用户名>\.ssh\authorized_keys；
  • 管理员用户（Administrators 组）：必须写入 C:\ProgramData\ssh\administrators_authorized_keys，并收紧 ACL 权限：
    powershell
    icacls.exe "C:\ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

7. 常见故障排查矩阵 #

现象 根因 排查与解决动作
Permission denied (publickey) 公钥未写入、权限过宽、算法不支持 1. 跑 ssh -v user@host 看握手日志；
2. 服务端检查 .ssh 属主与权限是否为 700/600；
3. 查看 /var/log/auth.log 精确报错。
Host key verification failed 远端重装过系统，公钥指纹与本地缓存冲突 本地清理冲突指纹：ssh-keygen -R <服务器IP> 或删除 ~/.ssh/known_hosts 对应行。
Connection refused sshd 服务未启动、端口写错、防火墙拦死 1. 服务端确认 systemctl status sshd；
2. 确认 ss -tulpn | grep 22 监听端口；
3. 云厂商控制台安全组放行对应端口。
Connection timed out 网络路由不可达，或中间防火墙静默丢包 检查本地网络网关、云厂商出入站安全组策略。
长时间无操作终端卡死假死 中间 NAT 路由器超时掐断长连接 本地 ~/.ssh/config 加上 ServerAliveInterval 60。
配置写错被彻底锁死在外 语法错误导致 sshd 起不来，或防火墙断联 登录云厂商提供的 VNC / Web Console 控制台，登录 root 执行 sshd -t 修复配置并重载。
