1. Nginx 是什么 #

Nginx 是事件驱动的 HTTP 服务器与反向代理。单机可维持数万并发连接，内存占用极低；一台机器可以同时承担静态资源服务、反向代理、负载均衡、缓存、TLS 终结。

1.1 能力一览 #

角色 典型用途 关键指令
静态 Web 服务器 HTML / CSS / JS / 图片 / 视频 root alias try_files
反向代理 前后端分离、微服务网关 proxy_pass
负载均衡 多后端实例分流 upstream
缓存 挡住上游与数据库 proxy_cache
TLS 终结 HTTPS、HTTP/2、mTLS ssl_*
限流 防 CC、保护后端 limit_req limit_conn
四层代理 TCP / UDP 转发（MySQL 等） stream 块
ℹ笔记

运行时是 1 个 master + N 个 worker。master 只读配置、管 worker；worker 用 epoll 多路复用处理连接，所以 worker 数一般等于 CPU 核数。nginx -s reload 是平滑的：老 worker 处理完存量请求才退出，不断连接。

1.2 最小可用配置 #

nginx
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile      on;
    keepalive_timeout 65;

    server {
        listen 80;
        server_name example.com;
        root  /var/www/html;
        index index.html;
    }
}

命令 用途

3. 配置结构 #

3.1 五大上下文 #

上下文 作用范围 常见指令
main（全局） 整个进程 worker_processes worker_rlimit_nofile user
events 连接处理 worker_connections use epoll multi_accept
http 所有 HTTP 站点 sendfile keepalive_timeout gzip upstream limit_req_zone
server 一个虚拟主机 listen server_name root ssl_*
location 一个 URL 前缀或正则 proxy_pass try_files alias deny allow

指令只能写在允许的上下文里，放错位置 nginx -t 会直接报 "xxx" directive is not allowed here。

3.2 带注释的骨架 nginx.conf #

nginx
user  www-data;                        # worker 运行身份，不要用 root
worker_processes auto;                 # = CPU 核数
worker_rlimit_nofile 65535;            # 单 worker fd 上限，须小于系统 ulimit -n

error_log /var/log/nginx/error.log warn;
pid       /run/nginx.pid;

events {
    worker_connections 10240;          # 单 worker 最大连接数
    use epoll;                         # Linux 默认即 epoll，写出来便于确认
    multi_accept on;                   # 一次事件循环尽量多收新连接
}

http {
    include       mime.types;
    default_type  application/octet-stream;

    sendfile        on;                # 零拷贝发静态文件
    tcp_nopush      on;                # 配合 sendfile，凑满一个包再发
    tcp_nodelay     on;                # keepalive 连接上立即发，降延迟
    keepalive_timeout  65;             # 空闲长连接保持时间
    keepalive_requests 1000;           # 单连接最多复用多少次

    client_max_body_size 20m;          # 请求体上限，上传报 413 就调这里
    server_tokens off;                 # 隐藏版本号

    gzip on;
    gzip_min_length 1k;                # 太小的文件压了反而变大
    gzip_comp_level 5;                 # 4-6 是性价比区间
    gzip_types text/plain text/css application/json application/javascript
               application/xml image/svg+xml;
    gzip_vary on;                      # 让 CDN 按 Accept-Encoding 分开缓存

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" rt=$request_time '
                    'urt=$upstream_response_time';   # 上游耗时，判断慢在 Nginx 还是后端
    access_log /var/log/nginx/access.log main;

    include /etc/nginx/conf.d/*.conf;   # 站点配置统一放这里
}
❢重要

worker_rlimit_nofile 与 worker_connections 都要小于系统实际 fd 上限，否则高并发时报 Too many open files，日志里是 worker_connections are not enough。

4. location 与路径处理 #

4.1 六种匹配符 #

写法 类型 说明
location = /path 精确匹配 完全相等才命中，优先级最高
location ^~ /path/ 前缀优先 命中后不再尝试正则
location ~ regex 正则，区分大小写 按书写顺序，第一个命中即停
location ~* regex 正则，忽略大小写 同上
location /path/ 普通前缀 记住最长匹配，最后才和正则比较
location @name 命名 location 只能被 try_files / error_page 内部跳转

4.2 优先级口诀 #

✦提示

先精确（=），再 ^~ 前缀，再正则（~ / ~* 按书写顺序），最后普通前缀（取最长）。

容易踩的一点：普通前缀即使最长，也要让位给正则——除非写的是 ^~。所以 location /api/ 想稳赢正则时，写成 location ^~ /api/。

4.3 root vs alias #

指令 路径拼接方式 举例
root /data/www + location /img/ root 值 + 完整 URI /img/a.png → /data/www/img/a.png
alias /data/static + location /img/ alias 值 + URI 去掉 location 前缀 /img/a.png → /data/static/a.png 
nginx
location /img/ {
    root /data/www;        # 实际读 /data/www/img/a.png
}

location /static/ {
    alias /data/static/;   # 实际读 /data/static/a.png，alias 值必须以 / 结尾
}
⚠警告

alias 与 location 的斜杠必须成对。location /static/ { alias /data/static; } 会拼出 /data/statica.png，直接 404。另外 alias 配 try_files 在旧版本有 bug，需要 try_files 时请用 root。

4.4 尾斜杠 301 陷阱 #

location /api/ 收到 /api 时会自动 301 到 /api/。如果前面有 SLB / CDN 终结了 TLS，这个 301 的 Location 会写成 http://内网IP:端口/api/，客户端根本连不上。

nginx
absolute_redirect off;   # 1.11.8+，Location 变相对路径 /api/，最稳妥

# 老版本替代：只去掉端口，仍保留 http:// 前缀
port_in_redirect off;

4.5 前缀带不带斜杠 #

location 请求 /api 请求 /api/x
location /api 命中 命中
location /api/ 301 到 /api/ 命中
location = /api 命中 不命中

两种写法都要照顾时：location = /api { return 301 /api/; } 加 location /api/ { ... }。

5. 静态站点与前后端分离 #

5.1 静态站点最简配置 #

nginx
server {
    listen 80;
    server_name blog.example.com;
    root  /var/www/blog;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff2?)$ {
        expires 30d;                            # 静态资源长缓存
        add_header Cache-Control "public, immutable";
        access_log off;                         # 静态资源不记日志，省 IO
    }
}

5.2 SPA history 路由 #

前端用 history 模式时，刷新 /post/123 会 404，需要把找不到的路径交回 index.html：

nginx
location / {
    root /var/www/app;
    index index.html;
    try_files $uri $uri/ /index.html;    # 只兜底页面路由
}
⚠警告

不要用 error_page 404 /index.html; 兜底。它会把后端接口的 404 也变成 200 + 首页 HTML，前端 JSON.parse 报 Unexpected token '<'。

5.3 子路径部署 #

把站点挂在 https://example.com/blog/ 下时，前端资源路径必须带 base：

bash
vite build --base=/blog/                    # Vite
vue-cli-service build --publicPath=/blog/   # Vue CLI
# 路由 base 也要同步改成 /blog/，否则跳转会跑到根路径

nginx
location /blog/ {
    alias /var/www/blog/;                   # alias 去掉 /blog 前缀
    index index.html;
    try_files $uri $uri/ /blog/index.html;
}

5.4 前后端分离实测案例 #

真实博客项目：静态文件在 /opt/blog/webapp，后端 Node 跑在 30999，前端请求 /blog-api/xxx。

nginx
server {
    listen 3001;
    server_name localhost;

    client_max_body_size 5m;                  # 后台上传图片够用

    root /opt/blog/webapp;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /blog-api {
        proxy_pass http://127.0.0.1:30999/;   # 末尾 / 把 /blog-api 前缀吃掉
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

proxy_pass 末尾有没有 /，决定后端收到什么 URI：

客户端请求 proxy_pass http://127.0.0.1:30999/（带 /） proxy_pass http://127.0.0.1:30999（不带 /）
/blog-api/user http://127.0.0.1:30999/user http://127.0.0.1:30999/blog-api/user

带 / 时 location 前缀被替换成 /；不带 / 时原始 URI 原样转发。

6. 反向代理 #

6.1 标准范式 #

nginx
upstream app_backend {
    server 127.0.0.1:8080;
    keepalive 32;                          # 与后端保持 32 条空闲长连接，避开三次握手
}

server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://app_backend;

        proxy_http_version 1.1;            # keepalive 必须是 1.1
        proxy_set_header Connection        "";        # 清掉 close，否则长连接失效

        proxy_set_header Host              $host;                              # 后端按域名分流
        proxy_set_header X-Real-IP         $remote_addr;                       # 客户端真实 IP
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;         # 代理链 IP
        proxy_set_header X-Forwarded-Proto $scheme;                            # 后端判断 http/https
        proxy_set_header X-Forwarded-Host  $host;
        proxy_set_header X-Forwarded-Port  $server_port;

        proxy_connect_timeout 5s;          # 连上后端的时间
        proxy_send_timeout    60s;         # 后端接收请求体的超时
        proxy_read_timeout    60s;         # 后端响应超时，导出大报表要调大

        proxy_buffering on;                # 先收进缓冲再慢慢发给客户端
        proxy_buffer_size   4k;
        proxy_buffers     8 4k;
        proxy_busy_buffers_size 8k;
    }
}
ℹ笔记

请求头六件套里 Host 和 X-Forwarded-For 最不能漏。漏 Host 会让后端生成错误的回调地址；漏 X-Forwarded-For 后端只能看到 127.0.0.1，日志、风控、限流全部失效。

6.2 WebSocket 升级 #

nginx
map $http_upgrade $connection_upgrade {   # 有 Upgrade 头才发 upgrade，否则发 close
    default upgrade;
    ''      close;
}

server {
    location /ws/ {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 3600s;          # WS 长连接，默认 60s 会被掐断
    }
}

nginx
server {

6.4 四层转发（stream 块） #

不走 HTTP 解析，纯 TCP/UDP 转发，常用于数据库、Redis、MQ 代理：

nginx
stream {
    upstream mysql_cluster {
        server 10.0.0.11:3306;
        server 10.0.0.12:3306;
    }

    server {
        listen 3306;
        proxy_pass mysql_cluster;
        proxy_connect_timeout 3s;
    }
}

7. 负载均衡 #

7.1 upstream 四种策略 #

策略 写法 适用场景
轮询 默认，无需声明 后端无状态、机器配置一致
加权轮询 server IP weight=3; 机器配置有差异
IP 哈希 ip_hash; 需要会话粘性、无共享 session
最少连接 least_conn; 请求耗时差异大

hash $request_uri consistent; 可做 URL 一致性哈希（提升缓存命中）；random two least_conn; 在大集群下比纯 least_conn 更均匀。

7.2 一份完整配置 #

nginx
upstream backend {
    least_conn;                            # 策略写在 upstream 顶部

    server 192.168.0.14:88  weight=2 max_fails=3 fail_timeout=30s;
    server 192.168.0.15:80  weight=1 max_fails=3 fail_timeout=30s;
    server 192.168.0.16:80  backup;        # 前两台全挂才启用
    server 192.168.0.17:80  down;          # 手动摘除，做灰度/维护

    keepalive 64;                          # 保留的长连接数
    keepalive_requests 1000;
    keepalive_timeout 60s;
}

server {
    listen 80;
    server_name www.example.com;

    location / {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_next_upstream error timeout http_502 http_503;   # 这几类失败自动换下一台
        proxy_next_upstream_tries 2;
    }
}
✦提示

max_fails=3 fail_timeout=30s 的含义是：30 秒内失败 3 次就摘除该节点 30 秒，然后重新探测。心跳接口必须返回非 5xx，否则健康检查形同虚设。

8. 缓存 #

nginx
proxy_cache_path /var/cache/nginx levels=1:2
                 keys_zone=api_cache:20m        # 索引区，1m 约 8000 个键
                 max_size=2g                    # 磁盘上限
                 inactive=60m                   # 60 分钟没人访问就清
                 use_temp_path=off;             # 临时文件和缓存同分区，避免跨盘拷贝

server {
    listen 80;
    server_name api.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_cache api_cache;
        proxy_cache_key "$scheme$request_method$host$request_uri";   # 带 query，避免串数据
        proxy_cache_valid 200 302 10m;
        proxy_cache_valid 404 1m;
        proxy_cache_use_stale error timeout updating http_500 http_502 http_503;
        proxy_cache_background_update on;      # 过期后先给旧内容，后台异步刷新
        proxy_cache_lock on;                   # 同一键只有一个回源，防击穿
        add_header X-Cache-Status $upstream_cache_status always;
    }
}
ℹ笔记

X-Cache-Status 常见取值：HIT 命中、MISS 未命中回源、EXPIRED 已过期回源刷新、STALE 用过期内容兜底、BYPASS 跳过缓存。命中率低于 60% 就要检查 proxy_cache_key 是否带了易变参数（cookie、时间戳、utm）。

按需清理（需 ngx_cache_purge 模块）：

nginx
location ~ /purge(/.*) {
    allow 127.0.0.1;
    deny all;
    proxy_cache_purge api_cache "$scheme$request_method$host$1";
}

9.1 证书申请 #

bash
sudo apt install -y certbot python3-certbot-nginx

9.2 A+ SSL 参数 #

nginx
server {
    listen 443 ssl;
    http2 on;                              # 1.25.1+；旧版写 listen 443 ssl http2;

    server_name secure.example.com;

    ssl_certificate     /etc/letsencrypt/live/secure.example.com/fullchain.pem;  # 必须 fullchain，缺中间证书会报错
    ssl_certificate_key /etc/letsencrypt/live/secure.example.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    ssl_stapling on;
    ssl_stapling_verify on;
    ssl_trusted_certificate /etc/letsencrypt/live/secure.example.com/chain.pem;
    resolver 8.8.8.8 1.1.1.1 valid=300s;   # 没配 resolver，stapling 不工作
    resolver_timeout 5s;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    location / {
        root /var/www/html;
        index index.html;
    }
}

# 80 端口统一跳 HTTPS
server {
    listen 80;
    server_name secure.example.com;
    return 301 https://$host$request_uri;
}
❢重要

listen 443 ssl http2; 在 Nginx 1.25.1 起已弃用，会告警 the "listen ... http2" directive is deprecated。新写法是 listen 443 ssl; 加独立一行 http2 on;。ssl_stapling 要真正生效，resolver 与 ssl_trusted_certificate 缺一不可。

9.3 安全响应头 #

nginx
add_header X-Frame-Options        "SAMEORIGIN" always;              # 防点击劫持
add_header X-Content-Type-Options "nosniff" always;                 # 禁止 MIME 嗅探
add_header Referrer-Policy        "strict-origin-when-cross-origin" always;

9.4 basic auth #

bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd admin    # -c 建文件，追加用户时去掉 -c

nginx
location /admin/ {
    auth_basic           "Administrator's Area";
    auth_basic_user_file /etc/nginx/.htpasswd;
}

location = /health {
    auth_basic off;                # 健康检查放行
    access_log off;
    return 200 "ok\n";
}
⚠警告

basic auth 凭据只是 base64 编码，明文可还原，必须配 HTTPS。它只有一层口令，不能替代真正的身份体系。

9.5 IP 访问控制 #

nginx
location /api {
    allow 192.168.1.0/24;
    allow 127.0.0.1;
    deny  all;                     # deny all 必须放最后
}

# 封禁恶意 IP（server 块顶部）
deny 1.2.3.4;
deny 5.6.7.0/24;

allow / deny 按书写顺序匹配，第一条命中即决定结果。

9.6 限流防 CC #

nginx
http {
    # 按 IP 限速：10m 约存 16 万个 IP 状态
    limit_req_zone  $binary_remote_addr zone=perip:10m rate=10r/s;
    limit_conn_zone $binary_remote_addr zone=conn_perip:10m;

    server {
        location /api/ {
            limit_req  zone=perip burst=20 nodelay;   # 允许突发 20，超出直接 503
            limit_conn conn_perip 10;                 # 单 IP 最多 10 个并发
            limit_req_status 429;
            limit_conn_status 429;
        }
    }
}

burst 是允许排队的溢出量；不加 nodelay 会按 rate 匀速放行，加了则突发立即处理。

9.7 mTLS 双向认证要点 #

nginx
server {
    listen 443 ssl;
    http2 on;
    server_name secure.example.com;

    ssl_certificate     /etc/nginx/ssl/server.crt;
    ssl_certificate_key /etc/nginx/ssl/server.key;
    ssl_client_certificate /etc/nginx/ssl/ca.crt;   # 指向签发客户端证书的 CA，不是 client.crt
    ssl_verify_client on;                            # on=强制 / optional=有则验
    ssl_verify_depth 2;

    location / {
        proxy_pass https://127.0.0.1:8443;
        proxy_ssl_certificate     /etc/nginx/ssl/client.crt;   # 反代到后端也走 mTLS 时
        proxy_ssl_certificate_key /etc/nginx/ssl/client.key;

        proxy_set_header X-Client-Verify    $ssl_client_verify;    # SUCCESS / FAILED / NONE
        proxy_set_header X-Client-DN        $ssl_client_s_dn;      # CN=blog-client
        proxy_set_header X-Client-Serial    $ssl_client_serial;
        proxy_set_header X-Client-Fingerprint $ssl_client_fingerprint;
    }
}
❢重要

ssl_client_certificate 必须指向 CA 证书。指向 client.crt 会让所有客户端校验失败，报 400 The SSL certificate error——这是 mTLS 最高频的错误。

10. 多站点托管 #

10.1 方案一：多域名虚拟主机 #

每个站点独立域名、独立证书，互不干扰，是生产首选。

nginx
# /etc/nginx/conf.d/blog.conf
server {
    listen 80;
    server_name blog.example.com;
    root /var/www/blog;
    index index.html;
    location / { try_files $uri $uri/ =404; }
}

# /etc/nginx/conf.d/shop.conf
server {
    listen 80;
    server_name shop.example.com;
    root /var/www/shop;
    index index.html;
    location / { try_files $uri $uri/ =404; }
}

加 HTTPS 时两个站点各配一份 ssl_certificate；通配符证书可用 server_name *.example.com;。

10.2 方案二：单域名子路径 #

只有一个域名、一张证书，站点挂在不同路径下。

nginx
server {
    listen 80;
    server_name example.com;

    location /blog/ {
        alias /var/www/blog/;
        index index.html;
        try_files $uri $uri/ /blog/index.html;
    }

    location /shop/ {
        alias /var/www/shop/;
        index index.html;
        try_files $uri $uri/ /shop/index.html;
    }
}

10.3 两方案对比 #

维度 多域名虚拟主机 单域名子路径
证书 每域名一张，或用通配符 一张搞定
前端改造 不需要 必须注入 base / publicPath
Cookie 隔离 天然隔离 同域共享，需显式指定 Path
扩展性 加站点只加文件 路径越叠越深
推荐场景 独立产品、不同团队 内部小工具、演示环境

11.1 内核参数 #

bash
sudo tee /etc/sysctl.d/99-nginx.conf > /dev/null <<'EOF'
net.core.somaxconn = 65535              # 已完成三次握手的等待队列，小了会丢连接
net.core.netdev_max_backlog = 65535     # 网卡收包队列，高 PPS 场景要调大
net.ipv4.tcp_max_syn_backlog = 65535    # 半连接队列，抗 SYNC flood

net.ipv4.ip_local_port_range = 1024 65535   # 可用临时端口，反代场景要够
net.ipv4.tcp_tw_reuse = 1                   # 复用 TIME_WAIT 连接，只对出向有效

net.ipv4.tcp_fin_timeout = 15
net.ipv4.tcp_keepalive_time = 600
net.ipv4.tcp_keepalive_intvl = 30
net.ipv4.tcp_keepalive_probes = 3

fs.file-max = 1000000                   # 全系统 fd 上限
net.ipv4.tcp_max_tw_buckets = 65535
net.ipv4.tcp_slow_start_after_idle = 0  # 长连接不要在空闲后重新慢启动
EOF

sudo sysctl -p /etc/sysctl.d/99-nginx.conf

11.2 worker 数量与连接上限 #

nginx
worker_processes auto;          # = CPU 核数
worker_rlimit_nofile 65535;
events {
    worker_connections 10240;
}

理论并发上限：

text
最大并发 = worker_processes × worker_connections
作为反向代理时，每个客户端连接还占一条到后端的连接，实际要除以 2

4 核 × 10240 ≈ 4 万并发，反代场景按 2 万算。同时 worker_rlimit_nofile 要 ≥ worker_connections × 2。

bash
ulimit -n                       # 确认 shell 限制
cat /proc/$(pgrep -f 'nginx: worker' | head -1)/limits | grep files

11.3 open_file_cache #

静态文件多时，把 stat 结果缓存起来，省掉每次请求的文件系统调用：

nginx
open_file_cache          max=10000 inactive=60s;   # 缓存 1 万个文件句柄，60 秒不活跃就淘汰
open_file_cache_valid    30s;                      # 多久复核一次元信息
open_file_cache_min_uses 2;                        # 用过两次才缓存
open_file_cache_errors   on;                       # 404 也缓存，避免反复打盘
ℹ笔记

open_file_cache 会让新发布的文件延迟几十秒才可见。频繁发版的目录把它关掉，或者发布后 nginx -s reload。
