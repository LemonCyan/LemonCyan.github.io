1. 三种协议怎么选 #

文件传输在运维里无非四条路：FTP、FTPS、SFTP、TFTP。选错协议造成的麻烦（防火墙不通、密码裸奔、chroot 登不上）比配置本身多得多，先看这张表。

协议 默认端口 加密 连接数 防火墙友好度 穿越 NAT 推荐度
FTP 21（控制）+ 20 或随机（数据） ❌ 明文，密码可嗅探 双连接（控制 + 数据） 差，被动模式要另开端口段 差，被动模式需 pasv_address ⭐ 仅内网/遗留系统
FTPS 990（隐式）/ 21（显式） ✅ TLS 双连接 差，同 FTP 差 ⭐⭐ 甲方指定时
SFTP 22（走 SSH） ✅ SSH 全程加密 单连接 极好，只需 22 好 ⭐⭐⭐⭐⭐ 首选
TFTP 69（UDP） ❌ 无认证无加密 单连接（UDP） 好 好 ⭐ 仅设备刷机/PXE

一句话结论：能用 SFTP 就别用 FTP。只有三种情况才回到 FTP/TFTP——对接只支持 FTP 的老设备、甲方合同写死 FTPS、以及网络设备刷固件 / PXE 装机这类只能用 TFTP 的场景。

❢重要

FTP 与 SFTP 是完全不同的两个协议，只是名字像。SFTP 不是「加密的 FTP」，它是 SSH 协议的一个子系统，跑在 22 端口、单连接、没有主动/被动模式。能在 21 端口连上不代表能用 SFTP，反之亦然。

2. FTP：原理与模式 #

2.1 双连接结构 #

FTP 用两条 TCP 连接：控制连接（21 端口，整场会话保持）发送命令，数据连接（临时建立、传完即关）传文件内容和目录列表。这也是它和其他协议最大的不同。

2.2 主动模式与被动模式 #

模式 谁发起数据连接 数据连接方向 问题
主动（PORT / Active） 服务端（从 20 端口）连客户端 服务器 → 客户端 客户端在 NAT/防火墙后，服务器连不进去
被动（PASV / Passive） 客户端连服务端随机端口 客户端 → 服务器 服务端要在防火墙上开一段随机端口

2.3 为什么建议被动模式 #

绝大多数 FTP 客户端在局域网里，没有独立公网 IP，且默认防火墙只放行出向连接。主动模式下由服务器反向连客户端，这条入向连接会被客户端的 NAT 或防火墙直接丢弃，表现就是能登录、能列目录，一 get 就卡住直到超时。

所以生产环境一律配被动模式；被动模式再配合固定的端口段（pasv_min_port / pasv_max_port），防火墙才有得放行。

2.4 典型响应码 #

码 含义 排查指向
125 数据连接已打开，传输开始 正常
200 命令成功 正常
226 数据传输完毕 正常
331 用户名 OK，等待密码 正常
425 无法打开数据连接 端口被占 / 防火墙拦 / 被动端口段没放行
426 数据连接被关闭，传输中断 网络抖动或服务端主动断开
452 写文件出错 磁盘满 / 权限不足 / 文件被锁
500 语法错误，命令不认识 客户端发了服务端不支持的扩展命令

3. FTP：vsftpd 安装与配置 #

3.1 服务端选型 #

软件 特点 官网
vsftpd 高性能、稳定、配置项少，并发场景首选 http://vsftpd.beasts.org/
ProFTPD 独立实现，认证方式和访问控制更灵活 http://www.proftpd.org/
Wu-ftpd 最老的非商业实现，功能全但已停止维护 http://www.wu-ftpd.org/

新部署直接上 vsftpd，下面全部以它为例。

3.2 认证三模式 #

模式 说明 安全性
匿名 任何人无需密码登录，只能读公开文件 最低，生产禁用
本地用户 用 Linux 系统账号验证，受 /etc/passwd 管 中，注意 chroot
虚拟用户 FTP 专用账号，存在独立库（如 Berkeley DB），碰不到系统资源 最高，配置最繁琐

3.3 安装与启停 #

bash
sudo apt install -y vsftpd          # Debian / Ubuntu
sudo dnf install -y vsftpd          # RHEL / CentOS

# 确认监听（默认 21）
sudo ss -nltp | grep :21
sudo netstat -antup | grep ftp

# 现代写法
sudo systemctl enable --now vsftpd
sudo systemctl status vsftpd
sudo systemctl restart vsftpd

# 老式写法（SysV，仍可用）
sudo service vsftpd start
sudo service vsftpd stop
sudo service vsftpd restart
ℹ笔记

默认监听 21 端口，云服务器还要在安全组里放行 21 和被动端口段，只在系统防火墙里开是不够的。

3.4 四类配置文件 #

文件 作用
/etc/vsftpd.conf（CentOS 为 /etc/vsftpd/vsftpd.conf） 核心配置，所有行为开关
/etc/pam.d/vsftpd PAM 认证配置，决定用本地账号、LDAP 还是虚拟用户库校验
/etc/ftpusers（或 /etc/vsftpd/ftpusers） 黑名单，列出的用户禁止登录，默认含 root 等系统账号
/etc/vsftpd.user_list（或 /etc/vsftpd/user_list） 由 userlist_enable + userlist_deny 决定是白名单还是黑名单

3.5 完整 vsftpd.conf（禁用匿名 + 本地用户 + 被动模式） #

ini
# ---------- 基本 ----------
listen=YES                       # 启用 IPv4 监听
listen_ipv6=NO                   # 与 listen 互斥，除非双栈否则关掉
listen_port=21                   # 监听端口，保持默认 21 客户端才不用改端口

# ---------- 权限掩码 ----------
local_umask=022                  # 上传文件权限 644、目录 755，同组可读便于协作

# ---------- 用户访问控制 ----------
local_enable=YES                 # 允许本地系统用户登录
anonymous_enable=NO              # 禁用匿名，生产必关
chroot_local_user=YES            # 把用户锁在自己的家目录，防止横向翻目录
chroot_list_enable=YES           # 开启例外名单
chroot_list_file=/etc/vsftpd.chroot_list   # 名单内的用户不受 chroot 限制
allow_writeable_chroot=YES       # 允许 chroot 目录可写；不开会报 500 OOPS: vsftpd: refusing to run with writable root inside chroot()

# ---------- 用户名单 ----------
userlist_enable=YES              # 启用 userlist 校验
userlist_deny=NO                 # NO=白名单（只有名单内能登录）；YES=黑名单
userlist_file=/etc/vsftpd.user_list

# ---------- 目录 ----------
local_root=/data/ftp             # 本地用户登录后落到这里（不写则落到各自 home）

# ---------- 被动模式（生产必配） ----------
pasv_enable=YES
pasv_min_port=6000               # 被动端口段下界，防火墙按这个范围放行
pasv_max_port=6010               # 上界；段太窄高并发时会抢不到端口
# pasv_address=1.2.3.4           # 服务器在 NAT 后时填公网 IP，否则 PASV 返回内网地址

# ---------- 传输限制 ----------
max_per_ip=3                     # 单 IP 最多 3 个并发，防单客户端占满
local_max_rate=5000000           # 本地用户限速，单位 bytes/s（≈5 MB/s）
anon_max_rate=3000000            # 匿名限速；匿名已禁用，留着无害

# ---------- 写权限 ----------
write_enable=YES                 # 总开关，不开则所有上传都 550
anon_upload_enable=NO            # 匿名上传（匿名已关，显式写 NO 更明确）
anon_mkdir_write_enable=NO
anon_other_write_enable=NO
# chown_username=ftpuser         # 仅用于匿名上传改属主；本配置已禁用匿名，故注释掉

# ---------- 编码 ----------
utf8_filesystem=YES              # 中文文件名不乱码

# ---------- 日志 ----------
xferlog_enable=YES               # 开启传输日志
xferlog_std_format=YES           # 标准格式，可直接喂 awstats
xferlog_file=/var/log/vsftpd.log # 只留这一个日志出口，避免与 vsftpd_log_file 重复记录

# ---------- 其他 ----------
tcp_wrappers=YES                 # 交给 /etc/hosts.allow、hosts.deny 做一层访问控制
seccomp_sandbox=NO               # 老内核上 seccomp 会误杀，容器里尤其常见
⚠警告

源文件里常见的三处错误写法，抄之前先对照：

  1. listen_port=21 # 设置监听端口为8021 —— 注释与值自相矛盾，值是多少就写多少。
  2. security_mask=077 —— vsftpd 没有这个指令，写了会启动失败；想控权限只用 local_umask。
  3. xferlog_enable=YES 与 vsftpd_log_file 同时设会重复记录两份日志。要标准格式用 xferlog_file，要 vsftpd 自有格式就 xferlog_enable=NO + vsftpd_log_file，二选一。

3.6 用户列表 #

bash
sudo vim /etc/vsftpd.user_list    # 每行一个用户名

text

userlist_deny=NO 时这是白名单——不在名单里的用户即使密码正确也登不进来，这是最容易遗漏的一步。

3.7 创建 FTP 用户 #

bash
# 1) 建专用组
sudo groupadd ftpgroup

# 2) 建用户：指定组、家目录、禁用 shell 登录
sudo useradd -g ftpgroup -d /home/ftpuser -s /sbin/nologin ftpuser

# 3) 设密码
sudo passwd ftpuser

# 4) 建数据目录并授权
sudo mkdir -p /data/ftp
sudo chown ftpuser:ftpgroup /data/ftp    # 属主必须是该用户，否则上传 550
sudo chmod 755 /data/ftp                 # 属主可写，其他只读

# 5) 再次确认禁止 shell 登录（useradd 漏写时补上）
sudo usermod -s /sbin/nologin ftpuser
✦提示

-s /sbin/nologin 是关键：FTP 用户只该传文件，不该有 shell。/etc/ftpusers 黑名单只管 FTP 登录，管不了 SSH——漏了 nologin，这个账号就能 SSH 进来。

4. FTP：防火墙与被动模式端口 #

被动模式下客户端要连服务端的随机端口，不固定就把整个高端口段暴露出去。

ini
pasv_enable=YES
pasv_min_port=6000
pasv_max_port=6010

bash
# firewalld（RHEL / CentOS）
sudo firewall-cmd --permanent --add-port=21/tcp
sudo firewall-cmd --permanent --add-port=6000-6010/tcp
sudo firewall-cmd --reload

# ufw（Debian / Ubuntu）
sudo ufw allow 21/tcp
sudo ufw allow 6000:6010/tcp

# 确认端口确实被监听
sudo ss -nltp | grep -E ':(21|60[0-9][0-9])'
现象 原因 处理
能登录、ls 卡死 被动端口段没放行 放行 pasv_min_port-pasv_max_port
内网正常、公网连不上 服务端在 NAT 后，PASV 返回了内网 IP 配 pasv_address=公网IP
偶发 425 端口段太窄（如 6000-6001），并发时抢不到 扩大范围到 10 个以上

5. SFTP：基于 SSH 的加密传输 #

5.1 SFTP 到底是什么 #

SFTP = SSH File Transfer Protocol，是 SSH 协议自带的一个子系统，不是 FTP 的加密版。连上 22 端口、走完 SSH 握手和认证之后，客户端请求 sftp 这个 subsystem，之后所有文件操作（列目录、读写、改名、改权限）都在这条加密通道里以二进制包形式收发。

由此得来四条与 FTP 截然不同的性质：

维度 FTP SFTP
端口 21 控制 + 数据端口 只有 22，与 SSH 共用
加密 无，账号密码明文过网 SSH 全程加密，可密钥认证
连接数 双连接（控制 + 数据） 单连接，所有操作复用
主动/被动模式 有，必须选一个 完全没有这个概念
防火墙 要开端口段 只开 22
❢重要

「SFTP 连不上，是不是要配被动模式？」——不需要，SFTP 里不存在 PASV/PORT。带 pasv_min_port 报错、或者照着 FTP 教程开 6000-6010 端口，都是把两个协议搞混了。SFTP 只有一个端口：sshd 的 22。

5.2 与 FTPS 的区别 #

FTPS 才是「FTP + TLS」，它保留了 FTP 的双连接结构，只是把两条连接都套上 TLS。两者常被混为一谈：

特性 FTP FTPS SFTP
全称 File Transfer Protocol FTP over SSL/TLS SSH File Transfer Protocol
端口 21 + 数据端口 990（隐式）/ 21（显式 AUTH TLS） 22
加密方式 无 TLS 证书 SSH
连接结构 双连接 双连接 单连接
被动模式 需要 需要 不需要
防火墙端口数 多 多 1
证书管理 无 需要 CA/自签证书 用 SSH 主机密钥
依赖服务 vsftpd vsftpd + ssl_enable=YES OpenSSH
推荐度 低 中（对接强制要求的场景） 高

结论：能改客户端就用 SFTP；对方系统写死了 FTPS 才配 vsftpd 的 ssl_enable（此时同样要处理被动端口段）。

5.3 服务端配置：只允许 SFTP、不允许 SSH 登录 #

目标：建一批账号，能传文件，但 ssh user@host 进不去 shell，也做不了端口转发。全部改造集中在 /etc/ssh/sshd_config。

bash
sudo vim /etc/ssh/sshd_config

ini
# 全局：把 sftp 子系统指向内置实现（不依赖外部 sftp-server 二进制，chroot 更省事）
Subsystem sftp internal-sftp

# 针对 sftpusers 组单独加规则，必须放在文件末尾——
# Match 块会一直生效到下一个 Match 或文件结束，写在中间会波及后面的全局配置
Match Group sftpusers
    ChrootDirectory /data/sftp/%u      # %u 展开为用户名，每人一个根
    ForceCommand internal-sftp          # 强制走 sftp，即使拿到 shell 也只执行这一条
    AllowTcpForwarding no               # 禁端口转发，防止当跳板
    X11Forwarding no                    # 禁 X11 转发
    PermitTunnel no                     # 禁 tun/tap 隧道
    AllowAgentForwarding no             # 禁 agent 转发
    PasswordAuthentication yes          # 需要密钥登录时改成 no

改完先校验再重载，语法错会导致 sshd 起不来、把现有 SSH 会话一起锁死：

bash
sudo sshd -t                      # 语法检查，无输出即通过
sudo systemctl reload sshd        # reload 不断开现有连接；restart 会断
# Ubuntu 上服务名可能是 ssh
sudo systemctl reload ssh
⚠警告

ChrootDirectory 的权限铁律：从 / 到 chroot 目录的每一级都必须属于 root，且组和其他用户不可写（755 或更严格）。任何一级被普通用户或组可写，sshd 会直接拒绝登录，客户端只看到 Permission denied (password)，/var/log/auth.log 里是 fatal: bad ownership or modes for chroot directory component。这是 SFTP 配置最高频的踩坑点，比配置项本身更容易出问题。

常见连锁错误：useradd -d /data/sftp/alice 会自动把 /data/sftp/alice 建成 alice:alice 755，而这层恰好是 chroot 的落脚点，必须改回 root:root。

5.4 建用户完整流程 #

bash
# 1) 建 SFTP 专用组（与 sshd_config 的 Match Group 对应）
sudo groupadd sftpusers

# 2) 建用户：加入 sftpusers，禁 shell 登录
sudo useradd -G sftpusers -s /sbin/nologin -M alice
#   -M 表示不自动建家目录，家目录由下面手动建并精确控制属主
sudo passwd alice

# 3) 建 chroot 根目录：必须 root:root 755
sudo mkdir -p /data/sftp/alice
sudo chown root:root /data/sftp/alice
sudo chmod 755 /data/sftp/alice

# 4) 建可写子目录：chroot 根不可写，只能往下开一层
sudo mkdir -p /data/sftp/alice/upload
sudo chown alice:sftpusers /data/sftp/alice/upload
sudo chmod 755 /data/sftp/alice/upload

# 5) 逐级检查：从 / 到 chroot 根，全部不能是组/其他可写
sudo namei -l /data/sftp/alice

namei -l 的输出是本节的验收工具，一眼能看出哪一级属主或权限不对：

text
drwxr-xr-x root root / 
drwxr-xr-x root root data
drwxr-xr-x root root sftp
drwxr-xr-x root root alice          ← chroot 根，必须 root:root 755
drwxr-xr-x alice sftpusers upload   ← 可写目录放在下一层
✦提示

想让上传目录「多人共享且互相不可删」，把 upload 设为 root:sftpusers 770 并给它加 setgid（chmod 2770），新文件自动继承组。若还要求「只能新建、不能删别人的」，vsftpd 的 delete 没有对应开关，需要靠 ACL 或改用 rssh/scponly 之类做更细的约束。

5.5 客户端用法 #

bash
# 连接（默认 22）
sftp alice@192.168.0.10

# 指定非标准端口，注意是大写 P（小写 p 是 ssh 的 preserve 参数）
sftp -P 2222 alice@192.168.0.10

# 指定密钥
sftp -i ~/.ssh/id_ed25519 alice@192.168.0.10

交互式命令与 FTP 客户端基本同构：

命令 作用
ls / lls 列远端 / 本地目录
cd / lcd 切远端 / 本地目录
pwd / lpwd 显示远端 / 本地当前目录
get 远端 本地 下载
put 本地 远端 上传
mget / mput 批量下载 / 上传（支持通配符）
rm / mkdir / rmdir 删文件 / 建目录 / 删目录
rename 旧 新 改名
chmod 644 文件 改权限
df 看远端磁盘空间
!命令 执行本地命令
bye / exit / quit 退出

非交互上传下载，scp 和 rsync 更顺手——它们与 SFTP 共用 SSH 通道和同一套认证：

bash
# scp：单文件/目录一次性拷贝，-r 递归、-P 指定端口
scp -P 2222 ./a.tar.gz alice@192.168.0.10:/upload/

# rsync over ssh：增量同步、断点续传，适合大目录/定时任务
rsync -avz -e "ssh -p 2222" ./dist/ alice@192.168.0.10:/upload/dist/

# 只看差异不实际传输
rsync -avzn -e "ssh -p 2222" ./dist/ alice@192.168.0.10:/upload/dist/
ℹ笔记

scp 从 OpenSSH 9.0 起默认改用 SFTP 协议传输（-O 可强制回退旧 SCP 协议）。这意味着 sshd_config 里把 Subsystem sftp 写错或删掉，scp 也会一起失效——排查时别只盯 sftp 命令。

5.6 密钥登录 #

密码认证在公网环境迟早被爆破，生产一律换密钥。

bash
# 1) 客户端生成密钥对（ed25519 比 RSA 更短更快，现代系统都支持）
ssh-keygen -t ed25519 -C "alice@ops" -f ~/.ssh/id_ed25519
#   已有 RSA 老密钥时：ssh-keygen -t rsa -b 4096

# 2) 公钥推到服务端（自动追加到 ~/.ssh/authorized_keys 并修好权限）
ssh-copy-id -i ~/.ssh/id_ed25519.pub alice@192.168.0.10
#   非标准端口：ssh-copy-id -p 2222 -i ~/.ssh/id_ed25519.pub alice@host

# 3) 免密验证
ssh -i ~/.ssh/id_ed25519 alice@192.168.0.10 true && echo OK

bash
# 服务端开启公钥认证后，关闭密码认证（确认密钥可用再执行！）

ini
PubkeyAuthentication yes
PasswordAuthentication no
⚠警告

关 PasswordAuthentication 前务必另开一个会话验证密钥能登。改错了再 reload，如果同时禁用了密码且密钥没生效，就只能走云控制台的 VNC 进去了。

5.7 常见故障 #

现象 原因 定位与处理
Connection refused sshd 没启动 / 端口不对 / 防火墙拦截 systemctl status sshd；ss -nltp | grep :22；云安全组放行 22
Connection timed out 网络层不通，安全组或路由丢包 telnet host 22、nc -vz host 22
Permission denied (password)，密码明明对 Chroot 目录权限不合规 namei -l /data/sftp/alice 逐级查；journalctl -u sshd -n 50 找 bad ownership or modes for chroot
登录成功但 Write failed / Permission denied 上传失败 想往 chroot 根写，但根必须是 root 只读 上传到 upload 子目录，确认该目录属主是用户
登录后立刻断开、无报错 shell 无效 + ForceCommand 缺失 确认 Match 块里有 ForceCommand internal-sftp
subsystem request failed Subsystem sftp 未配置或路径错 用 internal-sftp，并确认该行在 Match 块之前
能 SFTP 不能 SSH，符合预期；反过来不行 Match 块写在文件中间，影响了后面的全局段 把 Match 移到文件最末尾

6. TFTP：极简传输 #

6.1 用途与定位 #

TFTP（Trivial File Transfer Protocol）跑在 UDP 69，没有认证、没有目录遍历、没有断点续传，就是个「读一个文件 / 写一个文件」的最小协议。正因为它小到能被固件实现，才有不可替代的场景：

  • 网络设备（交换机、路由器、防火墙）上传/下载 IOS、固件、配置文件
  • 嵌入式开发板加载内核与设备树
  • PXE 网络装机引导，以及 IPMI/ BMC 刷 BIOS
  • 无盘工作站、瘦客户端启动
⚠警告

TFTP 没有任何认证和加密，任何能到 69/UDP 的人都能读写共享目录。它只该出现在隔离的管理网/VLAN 里，绝不能暴露到公网，也不要放在与业务同网段的机器上。

6.2 安装 #

bash
sudo apt install -y tftp-hpa tftpd-hpa   # 前者是客户端，后者是服务端
包名 角色
tftp-hpa 客户端，提供 tftp 命令
tftpd-hpa 服务端守护进程

6.3 配置 #

bash
sudo vi /etc/default/tftpd-hpa

ini
TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/tftpboot"          # 共享根目录，客户端看到的就是这里的顶层
TFTP_ADDRESS="0.0.0.0:69"           # 监听地址与端口；多网卡时填管理网 IP 更安全
TFTP_OPTIONS="--secure --create"    # --create 允许上传新文件（不加只能下载）

创建目录并授权：

bash
sudo mkdir -p /tftpboot

# 推荐：属主给 tftp 服务账号，755/775 足够
sudo chown -R tftp:tftp /tftpboot
sudo chmod 755 /tftpboot

# 需要匿名上传时再放开写权限，且只在隔离网段这么做
# sudo chmod 775 /tftpboot && sudo usermod -aG tftp $USER
⚠警告

网上大量教程写 sudo chmod 777 -R /tftpboot。这只适合本机练习：777 意味着任何本地用户都能往共享目录塞文件、替换固件镜像。生产用 chown tftp:tftp + 755（只下载）或 775（组内可写），再配 TFTP_OPTIONS="--secure" 把路径限制在根目录内。

重启服务：

bash
# 现代写法（systemd）
sudo systemctl restart tftpd-hpa
sudo systemctl enable --now tftpd-hpa
sudo systemctl status tftpd-hpa

# 老式写法（SysV，Ubuntu 老版本或容器镜像里仍能见到）
sudo /etc/init.d/tftpd-hpa restart

6.4 自测 #

bash
cd ~
echo hello > /tftpboot/test.txt      # 造一个测试文件

tftp 127.0.0.1                       # 进入交互环境

text
tftp> get test.txt        # 从 /tftpboot 下载到当前目录
tftp> put xx              # 把当前目录的 xx 上传到 /tftpboot
tftp> quit                # 退出
ℹ笔记

TFTP 交互环境没有任何提示：get 成功不打印任何东西，失败也常常静默。判断成功与否要看本地文件是否出现、ls -l 大小对不对。加 -v（tftp -v 127.0.0.1）能看到传输过程。

6.5 报文与命令语义 #

TFTP 每个数据包都是「2 字节操作码 + 内容」，源文件里的 ID 指的是传输结束标记：

ID 含义
0 正常通信，继续传
1 出错，传输终止
2 文件结束，本次传输完成

服务端与客户端的命令是镜像关系：

命令 服务端动作 客户端动作
get filename 判断文件存在→打开→读→写套接字→关闭 当前目录建文件→读套接字→写入→关闭
put filename 创建文件→读套接字→写入→关闭 打开文件→写入套接字→关闭
list 打开共享目录→读目录→发到套接字→关闭 读套接字显示结果
quit / help — 退出 / 打印帮助

动作 FTP（ftp） SFTP（sftp） TFTP（tftp）

显示模式 passive 切换主动/被动 无此概念 无此概念

✦提示

FTP 客户端默认是 ASCII 模式，传二进制文件（镜像、压缩包、jar）前必须敲 binary，否则行尾会被改写、文件损坏。SFTP/TFTP 没有这个问题——传输层不做任何编码转换。
