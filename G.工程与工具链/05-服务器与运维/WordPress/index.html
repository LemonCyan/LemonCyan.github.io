1. 介绍与架构 #

WordPress 是基于 PHP + MySQL/MariaDB 的开源建站系统。跑起来需要 Web 网关、PHP 执行环境、数据库三层，生产环境再加页面缓存与对象缓存。

层 组件 作用 典型瓶颈
Web 网关 Nginx / Apache 终止 TLS、直出静态文件、把 PHP 请求转给 FPM 连接数打满、缓冲区太小导致 502
PHP 执行 PHP-FPM + OPcache 运行 WordPress 代码，缓存已编译字节码 pm.max_children 不足、内存超卖被 OOM
页面缓存 Nginx FastCGI Cache 整页 HTML 落盘，匿名访客直接命中 登录态未绕过、发布后不失效
对象缓存 Redis 缓存数据库查询结果，登录用户同样受益 无内存上限、drop-in 未生成
数据层 MariaDB / MySQL 持久化文章、选项、用户 缓冲池过小、慢查询
运维 WP-CLI / cron / 备份 批量操作、定时任务、灾备恢复 未配系统 cron、备份未异地
ℹ笔记

通用 Nginx 语法（location 优先级、HTTPS 参数、反向代理、限流）不在此重复，见同目录 Nginx.md。本文只给 WordPress 必需的配置与命令。

全篇统一：域名 example.com、站点根 /var/www/wordpress、库名 wp_production、PHP 8.2、系统 Ubuntu 22.04 / Debian 12。

2. 环境选型：LNMP 与 LAMP #

后端完全一致（PHP-FPM + MariaDB + Redis），差别只在 HTTP 网关是 Nginx 还是 Apache。

维度 LAMP（Apache） LNMP（Nginx）
并发模型 多进程 Prefork，或多进程 + 多线程 Worker/Event 单线程多进程，异步非阻塞事件驱动
静态资源 每连接占一个进程/线程，开销大 sendfile 零拷贝，吞吐极高
动态 PHP mod_php 内嵌，或 mod_proxy_fcgi 只能 FastCGI 转发到 PHP-FPM
配置灵活性 支持目录级 .htaccess，改规则不用重启 规则写在主配置，改完需 reload
内存占用 随并发线性增长 极低，万级并发仅数百 MB
WordPress 适配 .htaccess 伪静态，插件兼容性最好 手写 try_files，性能上限更高
选型建议 多租户平台、客户自行改规则、依赖 Apache 专有模块 生产站点默认选择，低配 VPS 尤佳

mod_php 把 PHP 解释器编进 Apache 进程：静态图片请求也拖着整个解释器占内存，PHP 版本还被绑死。PHP-FPM 是独立守护进程，静态请求不经过 PHP，进程数、超时、慢日志可独立调，多版本可共存。

❢重要

除历史插件强依赖 Apache 专有指令外，一律用 PHP-FPM。即便保留 Apache，也用 Event MPM + mod_proxy_fcgi 桥接，不要用 mod_php。

3.4 Nginx 联动 PHP-FPM（Unix Socket） #

Unix Socket 省掉 TCP 握手与协议栈开销，同硬件吞吐通常比 127.0.0.1:9000 高 15%~25%，且不占端口。

nginx
# /etc/nginx/sites-available/example.com.conf —— 最小可用版，带缓存的完整版见第 9 章
server {
    listen 80;
    listen [::]:80;
    server_name example.com;

    root /var/www/wordpress;
    index index.php index.html index.htm;
    charset utf-8;

    client_max_body_size 64M;          # 需与 php.ini 的 upload_max_filesize 对齐

    location / {
        try_files $uri $uri/ /index.php?$args;   # 文件不存在交给前端控制器解析固定链接
    }

    location ~ \.php$ {
        try_files $fastcgi_script_name =404;     # 防 /uploads/x.jpg/x.php 路径拼接执行
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_param PATH_INFO $fastcgi_path_info;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_buffer_size 128k;                # 默认 4k/8k 遇大页面会截断响应头，直接 502
        fastcgi_buffers 4 256k;
        fastcgi_busy_buffers_size 256k;
        fastcgi_read_timeout 300;                # 导入、生成缩略图等长任务留足时间
    }

    location ~ /\. { deny all; access_log off; log_not_found off; }   # .git/.env/.htaccess
}

bash
sudo mkdir -p /var/www/wordpress
sudo chown -R www-data:www-data /var/www/wordpress
sudo chmod -R 755 /var/www/wordpress

sudo ln -s /etc/nginx/sites-available/example.com.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default    # 防止 default_server 抢占未匹配域名
sudo nginx -t && sudo systemctl reload nginx   # reload 不中断现有连接

4. LAMP 搭建（Apache + Event MPM + PHP-FPM） #

bash
sudo apt install -y apache2
sudo a2dismod mpm_prefork && sudo a2enmod mpm_event      # Prefork 每连接一进程，内存吃不住
sudo a2enmod proxy_fcgi setenvif rewrite headers ssl
sudo a2enconf php8.2-fpm                                 # 让 Apache 认识 FPM 桥接
sudo systemctl start apache2 && sudo systemctl enable apache2

apache
# /etc/apache2/sites-available/example.com.conf
<VirtualHost *:80>
    ServerName example.com
    ServerAdmin webmaster@example.com
    DocumentRoot /var/www/wordpress

    <Directory "/var/www/wordpress">
        Options -Indexes +FollowSymLinks   # 关目录列举，允许软链
        AllowOverride All                  # 让 WordPress 写 .htaccess 伪静态
        Require all granted
    </Directory>

    # .php 一律交给 PHP-FPM 的 Unix Socket，不用内嵌解释器
    <FilesMatch \.php$>
        SetHandler "proxy:unix:/run/php/php8.2-fpm.sock|fcgi://localhost/"
    </FilesMatch>

    ErrorLog ${APACHE_LOG_DIR}/example_error.log
    CustomLog ${APACHE_LOG_DIR}/example_access.log combined
</VirtualHost>

bash
sudo a2ensite example.com.conf && sudo a2dissite 000-default.conf
sudo apachectl configtest && sudo systemctl reload apache2
ℹ笔记

Apache 下伪静态由 .htaccess 承担，无需 try_files；但每次请求都要解析 .htaccess，高并发下是实打实的开销。

6. PHP-FPM 与 OPcache 配置 #

6.1 进程池（/etc/php/8.2/fpm/pool.d/www.conf） #

模式 行为 内存 延迟 适用
static 固定 max_children 个进程常驻 最高 最低，无 fork 高流量稳定站点、内存充足
dynamic 在 min/max_spare_servers 间伸缩 中等 低，有空闲池预热 绝大多数生产默认
ondemand 无请求全部回收 最低 高，冷启动慢 低流量 VPS、多站点闲置隔离

max_children = (可用内存 - 其他服务预留) / 单进程平均内存。单进程内存用 ps 实测，别拍脑袋：

bash
# 取所有 php-fpm 进程平均 RSS（KB）
ps --no-headers -o rss,cmd -C php-fpm8.2 | awk '{sum+=$1; n++} END {printf "进程数=%d 平均RSS=%.1fMB\n", n, sum/n/1024}'

算例：4 GB 机器，MariaDB 与系统预留 1.5 GB，剩 2.5 GB，按 50 MB/进程 → 2500 / 50 = 50。常见插件站点 40~80 MB/进程，空站 25~35 MB。

ini
[www]
user = www-data
group = www-data

; Unix Socket + 属主收窄，避免任意本机用户连上
listen = /run/php/php8.2-fpm.sock
listen.owner = www-data
listen.group = www-data
listen.mode = 0660

pm = dynamic
pm.max_children = 50          ; 按上面公式实测得出
pm.start_servers = 10         ; 约 max_children 的 1/5，启动即预热
pm.min_spare_servers = 5      ; 低于此值立刻 fork，扛突发
pm.max_spare_servers = 20     ; 高于此值回收，避免空转吃内存
pm.max_requests = 1000        ; 处理 N 个请求后重建，防扩展内存泄漏

request_slowlog_timeout = 3s  ; 慢脚本落盘，是定位性能问题的第一现场
slowlog = /var/log/php-fpm/slow.log
pm.status_path = /fpm-status  ; 供监控采集，暴露时务必限内网

bash
sudo mkdir -p /var/log/php-fpm && sudo chown www-data:www-data /var/log/php-fpm   # 目录不存在 FPM 启动失败
sudo systemctl restart php8.2-fpm
⚠警告

max_children 调到 200 不等于更抗压。内存被进程池吃满后，内核 OOM Killer 会随机杀 MariaDB 或 SSH，表现为整机假死。宁可让 FPM 排队（前面还有 FastCGI Cache 顶着），也不要内存超卖。

6.2 php.ini 上传与执行限制（/etc/php/8.2/fpm/php.ini） #

ini
upload_max_filesize = 64M     ; 必须与 Nginx client_max_body_size 一致
post_max_size = 64M           ; 必须 >= upload_max_filesize
max_file_uploads = 30

max_execution_time = 300      ; 主题导入、批量媒体处理
max_input_time = 300

memory_limit = 256M           ; 需 <= 6.1 中按进程估算的值，否则 max_children 计算失效

display_errors = Off          ; 错误打到页面既泄露路径又破坏结构
log_errors = On
error_log = /var/log/php_errors.log
expose_php = Off

date.timezone = Asia/Shanghai ; 与 WordPress 时区一致，避免定时任务错乱

6.3 OPcache（同文件 [opcache] 段） #

ini
opcache.enable = 1
opcache.enable_cli = 0                ; CLI 不需要，省共享内存
opcache.memory_consumption = 256      ; MB，WordPress + 插件约需 128~256
opcache.interned_strings_buffer = 16
opcache.max_accelerated_files = 20000 ; WordPress 插件与主题文件数轻松破万
opcache.revalidate_freq = 60          ; 生产调大减少 stat 开销
opcache.max_wasted_percentage = 10
opcache.save_comments = 1             ; 部分插件依赖注解反射，关掉会报错
; opcache.validate_timestamps = 0     ; 生产可开，但发布代码后必须 reload FPM

bash
sudo systemctl restart php8.2-fpm
php -r 'print_r(opcache_get_status(false));'   # 看 opcache_hit_rate，应在 99% 以上
❢重要

开了 opcache.validate_timestamps = 0 后，发布代码必须显式 systemctl reload php8.2-fpm，否则旧 opcode 一直生效，表现为「代码已更新但站点没变」。CI/CD 里要固定带上这一步。

7. MariaDB 配置 #

编辑 /etc/mysql/mariadb.conf.d/50-server.cnf（MySQL 8 为 /etc/mysql/mysql.conf.d/mysqld.cnf）：

ini
[mysqld]
bind-address = 127.0.0.1              # 数据库永不直接暴露公网
max_connections = 300                 # 需 >= PHP-FPM 的 max_children

# 可用物理内存的 50%~70%，数据库最重要的一个参数
innodb_buffer_pool_size = 2G
innodb_log_file_size = 256M           # 建议为缓冲池的 1/4，过小会频繁 checkpoint
innodb_flush_log_at_trx_commit = 2    # 每秒刷盘，崩溃最多丢 1 秒事务；WordPress 的平衡点
innodb_flush_method = O_DIRECT        # 绕过 OS 缓存，避免双重缓存
innodb_file_per_table = 1             # 单表备份与回收空间

slow_query_log = 1
slow_query_log_file = /var/log/mysql/mariadb-slow.log
long_query_time = 2                   # 超过 2 秒的 SQL 落盘
log_queries_not_using_indexes = 0

character-set-server = utf8mb4        # 4 字节字符（Emoji、生僻字）必需
collation-server = utf8mb4_unicode_ci
skip-name-resolve = 1                 # 跳过反解，减少连接延迟

bash
sudo systemctl restart mariadb
sudo mysql -e "SHOW VARIABLES LIKE 'innodb_buffer_pool_size';"   # 单位字节，确认生效
sudo tail -n 50 /var/log/mysql/mariadb-slow.log
⚠警告

容器里 innodb_buffer_pool_size 不会跟随 memory.limit 自动收缩。容器限额 2 GB 而缓冲池写 2 GB，进程会被反复 OOM 杀死——按容器限额算，不是按宿主机内存算。

8.4 wp-config.php 关键常量 #

bash

php
<?php
define( 'DB_NAME', 'wp_production' );
define( 'DB_USER', 'wp_master' );
define( 'DB_PASSWORD', 'Wp_Pr0d#2026!Str0ng' );
define( 'DB_HOST', 'localhost' );

define( 'DISABLE_WP_CRON', true );      // 高并发下自带 cron 会拖慢首屏，改系统 cron

define( 'WP_DEBUG', false );            // 生产环境必须关，否则路径与 SQL 泄露

SALT 密钥不要手写、不要抄示例、不要多站共用。官方接口 https://api.wordpress.org/secret-key/1.1/salt/ 直接生成 8 组 define，或用 WP-CLI 就地写入：

bash
sudo -u www-data wp config shuffle-salts            # 首次生成
sudo -u www-data wp config shuffle-salts --force    # 密钥泄露时轮换，会让所有用户强制下线
⚠警告

关掉 DISABLE_WP_CRON 后必须补系统定时任务，否则定时发布、备份、插件计划任务全部失效：

bash
(crontab -l 2>/dev/null; echo "*/5 * * * * sudo -u www-data wp cron event run --due-now --path=/var/www/wordpress >/dev/null 2>&1") | crontab -

9. Nginx + FastCGI Cache 完整配置 #

WordPress 有登录态、后台、评论、Feed，全靠 Cookie 与 URL 区分。缓存配错一步，访客会看到别人的用户名，或后台被缓存成静态页。

9.1 http 块定义缓存区（/etc/nginx/nginx.conf） #

nginx
# levels=1:2 两级十六进制子目录，避免单目录文件过多；keys_zone 是内存键索引
# inactive=60m 未被访问即清理，需与 fastcgi_cache_valid 配合；use_temp_path=off 避免跨分区 rename
fastcgi_cache_path /var/cache/nginx/wordpress
                   levels=1:2
                   keys_zone=WORDPRESS_CACHE:100m
                   max_size=5g
                   inactive=60m
                   use_temp_path=off;

# 缓存键必须含 scheme：否则 http 与 https、多域名站点互相串页
fastcgi_cache_key "$scheme$request_method$host$request_uri";

# 后端抖动时返回过期缓存，别让 PHP 打一个嗝就变 502 白屏
fastcgi_cache_use_stale error timeout invalid_header updating http_500 http_503 http_504;

# 忽略上游 Cache-Control/Expires/Set-Cookie，否则 PHP 一发这些头就永不缓存
fastcgi_ignore_headers Cache-Control Expires Set-Cookie;

# 缓存锁：同一 URL 并发未命中只放一个请求回源，防击穿
fastcgi_cache_lock on;
fastcgi_cache_lock_timeout 5s;

sudo mkdir -p /var/cache/nginx/wordpress

nginx
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;

    # 单独放行 ACME 校验，否则证书续期被 301 打断
    location ^~ /.well-known/acme-challenge/ {
        root /var/www/letsencrypt;
        default_type "text/plain";
    }

    location / { return 301 https://$host$request_uri; }
}

server {
    # 新版 Nginx（1.25.1+）已弃用 listen ... http2，改为独立指令
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;

    server_name example.com www.example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;    # 会话复用，省握手开销
    ssl_session_timeout 1d;

    root /var/www/wordpress;
    index index.php index.html index.htm;
    charset utf-8;

    client_max_body_size 64M;            # 与 php.ini 的 post_max_size 一致

    access_log /var/log/nginx/example_access.log;
    error_log  /var/log/nginx/example_error.log warn;

    # ---------- 缓存绕过判定：命中任一条就置 1 ----------
    set $skip_cache 0;

    # 1. 登录用户一律不缓存
    if ($http_cookie ~* "comment_author|wordpress_[a-f0-9]+|wp-postpass|wordpress_no_cache|wordpress_logged_in") {
        set $skip_cache 1;
    }
    # 2. POST（发表评论、表单、后台操作）不缓存
    if ($request_method = POST) { set $skip_cache 1; }
    # 3. 带查询参数不缓存：参数组合无限，只会污染磁盘
    if ($query_string != "") { set $skip_cache 1; }
    # 4. 后台、登录、Feed、XML-RPC、sitemap 不缓存
    if ($request_uri ~* "/wp-admin/|/wp-login\.php|/xmlrpc\.php|wp-.*\.php|/feed/|/sitemap(_index)?\.xml") {
        set $skip_cache 1;
    }

    # ---------- 伪静态：交给 WordPress 前端控制器 ----------
    location / {
        try_files $uri $uri/ /index.php?$args;
    }

    # ---------- PHP 解析 + FastCGI 缓存 ----------
    location ~ \.php$ {
        try_files $uri =404;             # 只允许真实文件，防路径拼接执行

        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_param HTTPS on;

        fastcgi_pass unix:/run/php/php8.2-fpm.sock;

        fastcgi_cache WORDPRESS_CACHE;
        fastcgi_cache_valid 200 301 302 60m;   # 只缓存正常响应，500/跳登录页不进缓存
        fastcgi_cache_valid 404 1m;            # 404 短缓存，防爬虫把不存在的 URL 写满磁盘
        fastcgi_cache_bypass $skip_cache;      # 决定这次要不要读缓存
        fastcgi_no_cache    $skip_cache;       # 决定这次要不要写缓存

        fastcgi_buffer_size 128k;
        fastcgi_buffers 4 256k;
        fastcgi_busy_buffers_size 256k;

        add_header X-FastCGI-Cache $upstream_cache_status always;   # curl -I 一眼看 HIT/MISS/BYPASS
    }

    # ---------- 静态资源 30 天缓存 ----------
    location ~* \.(ogg|ogv|svg|svgz|eot|otf|woff|woff2|mp4|ttf|css|rss|atom|js|jpg|jpeg|gif|png|ico|zip|tgz|gz|rar|bz2|doc|xls|exe|ppt|tar|mid|midi|wav|bmp|rtf|webp)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
        log_not_found off;
        access_log off;
    }

    # ---------- 安全规则 ----------
    location ~ /\. { deny all; access_log off; log_not_found off; }   # .git/.env/.htaccess
    location = /wp-config.php { deny all; }
    location = /readme.html   { deny all; }
    location = /license.txt   { deny all; }
    location ~* /wp-content/uploads/.*\.php$ { deny all; access_log off; }   # 封死图片马 getshell
    location = /xmlrpc.php { deny all; access_log off; }                       # 挡暴力破解与 Pingback 反射
    location = /wp-admin/ { try_files $uri $uri/ /wp-admin/index.php?$args; } # 别被 location / 误吞
}

⚠警告

三个高频坑：① 缓存键漏了 $scheme，http 与 https 互相覆盖；② add_header 在 server 与 location 同时出现会就近覆盖，看不见 X-FastCGI-Cache，误判缓存没生效——同一层级只留一组；③ 把 fastcgi_cache_bypass 写成常量 0，后台页面被缓存，管理员看到别人的登录态。

[!TIP] 缓存参数速查：fastcgi_cache_valid 控制各状态码时长；fastcgi_cache_bypass 管读、fastcgi_no_cache 管写，两者都要挂 $skip_cache；fastcgi_cache_lock 防击穿；inactive 必须 ≥ 主缓存时长。

10. Redis 对象缓存 #

FastCGI Cache 缓整页 HTML，只惠及匿名访客；Redis 缓数据库查询结果，登录用户与后台同样受益。两者并列，不是替代关系。

bash
sudo apt install -y redis-server php-redis
sudo systemctl start redis-server && sudo systemctl enable redis-server
sudo systemctl restart php8.2-fpm                  # 加载 redis 扩展

php -m | grep -i redis && redis-cli ping           # 均应有输出/PONG

bash
# 必须设内存上限 + LRU 淘汰，否则 Redis 会一路吃满直至 OOM
sudo sed -i 's/^# maxmemory .*/maxmemory 512mb/' /etc/redis/redis.conf
sudo sed -i 's/^# maxmemory-policy .*/maxmemory-policy allkeys-lru/' /etc/redis/redis.conf
sudo sed -i 's/^bind .*/bind 127.0.0.1 ::1/' /etc/redis/redis.conf   # 裸奔的 Redis 是最常见挖矿入口
sudo systemctl restart redis-server
redis-cli config get maxmemory-policy

php
/** wp-config.php：指向本机 Redis，多实例用库号 0~15 隔离 */
define( 'WP_REDIS_HOST', '127.0.0.1' );
define( 'WP_REDIS_PORT', 6379 );
define( 'WP_REDIS_DATABASE', 0 );
// define( 'WP_REDIS_PASSWORD', 'your-redis-password' );   // 启用 requirepass 时打开
define( 'WP_REDIS_PREFIX', 'wp_example_' );              // 同机多站必设，否则键冲突串数据
define( 'WP_REDIS_TIMEOUT', 1 );                         // 缩短超时，别让 Redis 抖动拖死 PHP
define( 'WP_REDIS_READ_TIMEOUT', 1 );
define( 'WP_CACHE_KEY_SALT', 'example.com:' );           // 改这个值等价于全站清空对象缓存

❢重要

插件「已启用」≠ 缓存「已生效」。判定只有两条：wp-content/object-cache.php 存在，且 wp redis status 显示 Connected。文件不存在多半是 wp-content 权限不足，与 Redis 服务无关。

[!WARNING] maxmemory-policy 必须是 allkeys-lru 或 volatile-lru。若为 noeviction，内存打满后所有写命令报错，表现为后台上传与保存全部失败，日志只有一句 OOM command not allowed when used memory > 'maxmemory'。

13. 备份 #

13.1 每日备份脚本（/root/scripts/backup_wordpress.sh） #

bash
#!/usr/bin/env bash
set -euo pipefail   # 任一命令失败立即退出，避免半成品包被当成有效备份

BACKUP_DIR="/data/backups/wordpress"
DATE=$(date +"%Y%m%d_%H%M%S")
DB_NAME="wp_production"
DB_USER="wp_master"
DB_PASS="Wp_Pr0d#2026!Str0ng"
WEB_ROOT="/var/www/wordpress"
KEEP_DAYS=15

mkdir -p "${BACKUP_DIR}"

# 1. 数据库：--single-transaction 一致性快照（仅 InnoDB）；--quick 逐行流式读，防大表撑爆内存
mysqldump \
    --single-transaction \
    --quick \
    --routines \
    --triggers \
    --events \
    --default-character-set=utf8mb4 \
    -u"${DB_USER}" -p"${DB_PASS}" "${DB_NAME}" \
    | gzip -9 > "${BACKUP_DIR}/wp_db_${DATE}.sql.gz"

# 2. 源码：排除缓存与升级残留，避免包体虚胖与自我递归；uploads 是用户资产，不排除
tar -zcf "${BACKUP_DIR}/wp_files_${DATE}.tar.gz" \
    -C "$(dirname "${WEB_ROOT}")" "$(basename "${WEB_ROOT}")" \
    --exclude='*/wp-content/cache' \
    --exclude='*/wp-content/upgrade' \
    --exclude='*/wp-content/ai1wm-backups' \
    --exclude='*/wp-content/*.log' \
    --exclude='*.tar.gz' \
    --exclude='*/node_modules'

# 3. 校验：数据库包必须通过 gzip 完整性检查
if ! gzip -t "${BACKUP_DIR}/wp_db_${DATE}.sql.gz" 2>/dev/null; then
    echo "[${DATE}] 备份校验失败：数据库包损坏" >> /var/log/wp_backup.log
    exit 1
fi

DB_SIZE=$(du -h "${BACKUP_DIR}/wp_db_${DATE}.sql.gz" | cut -f1)
FILE_SIZE=$(du -h "${BACKUP_DIR}/wp_files_${DATE}.tar.gz" | cut -f1)

# 4. 清理超期备份：-mtime +N 按修改时间判定
find "${BACKUP_DIR}" -type f -name "wp_*.sql.gz" -mtime +${KEEP_DAYS} -delete
find "${BACKUP_DIR}" -type f -name "wp_*.tar.gz" -mtime +${KEEP_DAYS} -delete

# 5. 落日志，便于事后核对是否真的每天执行过
echo "[${DATE}] 备份成功 db=${DB_SIZE} files=${FILE_SIZE}" >> /var/log/wp_backup.log

脚本里的 DB_PASS 是明文。把凭据放进 /root/.my.cnf（chmod 600）并改用 --defaults-extra-file=/root/.my.cnf，ps 与 crontab 里就不再出现密码。备份落在同一块磁盘等于没有备份，至少用 rclone/rsync 推一份到异地。
