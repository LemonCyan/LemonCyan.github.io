自建 VPN 服务器部署指南（Hysteria2 + VLESS-Reality） #

本文档面向零基础用户，按照步骤从零开始在一台全新的 Linux 服务器上部署自己的科学上网服务。 全程复制粘贴即可，每一步都说明了「做什么」和「为什么」。

1. 方案简介与选型理由 #

1.1 最终方案 #

项目 选型 说明
服务端软件 sing-box 单二进制、无依赖、内存占用低（约 60MB）
协议 A（主力） Hysteria2（UDP 8443） 基于 QUIC，抗丢包能力强，跨境体验好
协议 B（备用） VLESS + Reality（TCP 8443） 走 TCP，伪装成访问真实网站，抗封锁
进程管理 systemd 开机自启、崩溃自动重启
订阅服务 Python 标准库 无第三方依赖，提供 Clash 订阅链接
客户端 Clash / Mihomo 系 Hysteria2 与 Reality 需要 Meta 内核

1.2 为什么这样选 #

为什么是 Hysteria2？ 传统的 TCP 协议（如 Shadowsocks、VMess）在跨境网络出现丢包时，传输速度会急剧下降——因为 TCP 把丢包当作"拥塞"，会自动降速。Hysteria2 走 QUIC（UDP），拥塞控制算法专门为高丢包环境设计，丢包率 10% 的情况下仍能跑满带宽。

为什么还要一个 Reality？ 部分网络环境会对 UDP 流量做 QoS 限速甚至阻断。这时 QUIC 不通，就需要 TCP 备用通道。VLESS + Reality 不需要域名和证书——它在 TLS 握手阶段直接伪装成访问 www.bing.com 等真实网站，从外部看和自己的真实访问无法区分，比传统的 VMess/WS+TLS 抗封锁能力强得多。

为什么不用 WireGuard / OpenVPN？ 这类传统 VPN 协议流量特征明显，在部分网络中容易被识别和限速，更适合做内网互联而非日常翻墙。

为什么不推荐一键脚本 / X-ui 面板？ 面板类工具会额外运行一个 Web 管理界面，增加内存占用和弱口令被爆破的风险。本项目采用最小化部署，没有对外暴露的任何管理面板。

1.3 端口规划 #

8443/TCP  → VLESS-Reality
8443/UDP  → Hysteria2      （TCP 与 UDP 端口号相同但互不冲突）
8080/TCP  → 订阅服务
22/TCP    → SSH

为什么用 8443 而不是 443？ 443 是 HTTPS 标准端口，如果服务器上已经有网站服务，会端口冲突。8443 是备选的 HTTPS 端口，特征上不突兀，且避开了各类网络设备对 443 的重点关注。

2. 准备工作 #

2.1 服务器要求 #

配置项 最低要求 说明
操作系统 Debian 11+ / Ubuntu 20.04+ 本文以 Debian 12 为例
CPU 1 核 足够，代理服务不消耗 CPU
内存 512MB sing-box 实测占用约 60MB
磁盘 1GB 空闲 二进制约 80MB
架构 x86_64 (amd64) 如为 ARM，需换下载链接（见 3.2 节注）
网络 有公网 IPv4 本文方案不依赖 IPv6

2.2 准备工作账号与权限 #

你需要能通过 SSH 以 root 身份登录服务器：

bash
ssh root@你的服务器IP

2.3 检查系统环境 #

登录后，依次执行以下命令确认环境，每一项都应该有正常的输出：

bash
# 查看系统版本
cat /etc/os-release | head -3
# 预期：显示 Debian 12 或 Ubuntu

# 查看 CPU 架构
uname -m
# 预期：x86_64（如果是 aarch64 则是 ARM，见 3.2 节说明）

# 查看内存（看 available 那一列）
free -h
# 预期：available 至少几百 MB

# 查看磁盘
df -h /
# 预期：Avail 至少 1G

# 记录你的公网 IP，后面配置要用
curl -s4 ifconfig.me
# 或 curl -s4 ip.sb

⚠️ 把最后一条命令输出的 IP 记下来，后文会反复用到，记作 <服务器IP>。

2.4 确认端口未被占用 #

bash
ss -tulpn | grep -E ':(8443|8080) '
  • 没有输出 = 端口空闲，可以继续
  • 有输出 = 端口被占用，需要换端口（见 11.1 节），或先停掉占用进程

2.5 开启 BBR 拥塞控制（强烈建议） #

BBR 能显著提升跨境 TCP 传输速度（对 Reality 通道效果明显）：

bash
# 检查是否已开启
sysctl net.ipv4.tcp_congestion_control

如果输出是 net.ipv4.tcp_congestion_control = bbr，说明已开启，跳过本节。

如果不是，执行：

bash
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p

# 验证
sysctl net.ipv4.tcp_congestion_control
# 预期输出：net.ipv4.tcp_congestion_control = bbr

3. 安装 sing-box #

3.1 查询最新版本号 #

打开 https://github.com/SagerNet/sing-box/releases/latest 查看最新版本号，或直接执行：

bash
curl -s https://api.github.com/repos/SagerNet/sing-box/releases/latest \
  | grep -oE '"tag_name": *"[^"]+"' | head -1

输出类似 "tag_name": "v1.14.4"，说明最新版是 1.14.4。

下文的命令中所有 1.14.4 都请替换成你查到的版本号。（版本差异只影响下载地址，配置写法见第 5 节注意事项。）

3.2 下载并解压 #

bash
# 进入临时目录
cd /tmp

# 下载（注意：amd64 对应 x86_64 架构）
V=1.14.4
curl -fL -o sing-box.tar.gz \
  "https://github.com/SagerNet/sing-box/releases/download/v${V}/sing-box-${V}-linux-amd64.tar.gz"

# 解压
tar -xzf sing-box.tar.gz

# 进入解压出的目录（目录名含版本号）
cd sing-box-${V}-linux-amd64

📌 ARM 服务器（如甲骨文 ARM、树莓派）：把上面链接中的 linux-amd64 换成 linux-arm64。

📌 国内服务器下载 GitHub 慢/失败：可先执行

bash
export https_proxy=你的本地代理   # 或使用镜像站

或直接在你的电脑上下载后，用 scp 上传：

bash
# 在你自己的电脑上执行
scp sing-box-1.14.4-linux-amd64.tar.gz root@服务器IP:/tmp/

3.3 安装到系统路径 #

bash
# 赋予执行权限并安装到 /usr/local/bin
install -m 755 sing-box /usr/local/bin/sing-box

# 验证安装成功
sing-box version

预期输出（版本号可能不同）：

sing-box version 1.14.4

Environment: go1.26.10 linux/amd64
Tags: with_gvisor,with_quic,with_dhcp,...

⚠️ 关键检查点：Tags: 那一行里必须包含 with_quic（Hysteria2 依赖）和 with_utls（Reality 依赖）。官方 release 包默认都带，如果是自己编译的则需注意。

3.4 创建配置目录 #

bash
mkdir -p /etc/sing-box/cert

4. 生成密钥与证书 #

本节生成三样东西，每一项都要记录下来，后面配置要用。

4.1 生成 Reality 密钥对 #

bash
sing-box generate reality-keypair

预期输出：

PrivateKey: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PublicKey:  yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy

📝 记下来：

  • PrivateKey → 服务端配置用（绝对不能泄露）
  • PublicKey → 客户端配置用

4.2 生成 UUID #

UUID 相当于 Reality 协议的"用户 ID"：

bash
sing-box generate uuid

预期输出： 类似 5a0fc534-e411-466f-a3d5-5b32d92f8cca

📝 记下来：这个 UUID 服务端和客户端都要用。

4.3 生成 Hysteria2 的 TLS 证书 #

Hysteria2 需要 TLS。我们用自签证书（客户端会跳过证书校验，安全性与 Reality 的加密相比可忽略不计）：

bash
cd /etc/sing-box/cert

# 生成证书，-m 3600 表示有效期 3600 个月（约 300 年，避免过期）
sing-box generate tls-keypair www.bing.com -m 3600 > pair.txt

# 拆分成单独的证书文件和私钥文件
sed -n '/BEGIN CERTIFICATE/,/END CERTIFICATE/p' pair.txt > cert.pem
sed -n '/BEGIN PRIVATE KEY/,/END PRIVATE KEY/p' pair.txt > key.pem

# 删除中间文件，保护私钥权限
rm -f pair.txt
chmod 600 key.pem

# 验证
ls -l
openssl x509 -in cert.pem -noout -subject -dates

预期输出：

-rw-r--r-- 1 root root 1115 ... cert.pem
-rw------- 1 root root 1704 ... key.pem
subject=CN = www.bing.com
notBefore=...
notAfter=...          ← 应该是一个遥远的年份

4.4 设定 Hysteria2 密码 #

自己随便定一个足够复杂的字符串，例如：

Hy2-你的随机字符串-2026

📝 记下来：这个密码客户端也要填。

      "type": "direct",

5.2 修改占位符 #

用编辑器打开文件，把三处占位符替换成第 4 节生成的真实值：

bash
nano /etc/sing-box/config.json
# 或 vi /etc/sing-box/config.json

要替换的三处：

占位符 替换为
把这里换成4.4节你自己定的密码 你在 4.4 节设定的 Hysteria2 密码
把这里换成4.2节生成的UUID 你在 4.2 节生成的 UUID
把这里换成4.1节生成的PrivateKey 你在 4.1 节生成的 PrivateKey

💡 nano 用法：Ctrl+O 保存 → 回车确认 → Ctrl+X 退出。vi 用法：按 i 进入编辑，改完按 Esc，输入 :wq 回车。

5.3 ⚠️ 版本适配说明（重要） #

如果你安装的 sing-box 版本 低于 v1.12，上面的配置写法可能需要调整：

  • dns.servers 中的 {"type": "tls", "server": "8.8.8.8"} 是新格式（v1.12+）
  • 旧版本写法是 {"address": "tls://8.8.8.8"}
  • route.default_domain_resolver 也是 v1.12+ 新增

如果你用的是本文推荐的 v1.14.4，直接用上面的配置即可。 换其他版本时先跑 sing-box check 看报错提示。

5.4 校验配置 #

生成完必须校验，只有输出「配置校验通过」才能继续：

bash
sing-box check -c /etc/sing-box/config.json && echo "✅ 配置校验通过"

如果报错，按提示修改配置文件后重新校验。

常见报错及解决见 11.3 节。

6. 配置 systemd 开机自启 #

6.1 创建服务单元文件 #

bash
cat > /etc/systemd/system/sing-box.service <<'EOF'
[Unit]
Description=sing-box service (Hysteria2 + VLESS-Reality)
Documentation=https://sing-box.sagernet.org
After=network.target nss-lookup.target

[Service]
User=root
WorkingDirectory=/etc/sing-box
CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_BIND_SERVICE CAP_NET_RAW
AmbientCapabilities=CAP_NET_ADMIN CAP_NET_BIND_SERVICE CAP_NET_RAW
ExecStart=/usr/local/bin/sing-box run -c /etc/sing-box/config.json
Restart=on-failure
RestartSec=5s
LimitNOFILE=infinity
LimitNPROC=infinity

[Install]
WantedBy=multi-user.target
EOF

6.2 启动并设置开机自启 #

bash
# 重新加载 systemd 配置（每次改 .service 文件都要执行）
systemctl daemon-reload

# 启动服务并设为开机自启
systemctl enable --now sing-box

# 查看状态
systemctl status sing-box --no-pager

预期输出（关键看 Active: 那一行）：

● sing-box.service - sing-box service (Hysteria2 + VLESS-Reality)
     Loaded: loaded (/etc/systemd/system/sing-box.service; enabled; ...)
     Active: active (running) since ...

出现 active (running) 和 enabled 就成功了。

7. 验证服务是否正常 #

7.1 检查端口监听 #

bash

预期输出（必须同时有 TCP 和 UDP 两行）：

  "outbounds": [
    {
      "type": "hysteria2",
      "tag": "test",
      "server": "你的服务器IP",
      "server_port": 8443,
      "password": "你的Hysteria2密码",
      "tls": {
        "enabled": true,
        "server_name": "www.bing.com",
        "insecure": true,
        "alpn": ["h3"]
      }
    }
  ],

EOF

# 后台运行测试客户端
setsid sing-box run -c /tmp/test-client.json > /tmp/test.log 2>&1 < /dev/null &

# 测试完清理
pkill -f test-client.json

如果输出的 IP 就是你的服务器 IP，说明服务端完全正常。 可以继续下一步。

8. 搭建订阅服务 #

手动填配置太麻烦，我们搭一个订阅服务，客户端只要填一个链接就能自动获取全部配置。

8.1 创建目录 #

bash
mkdir -p /etc/vpn-sub

8.2 编写订阅服务脚本 #

bash
cat > /etc/vpn-sub/server.py <<'PYEOF'
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""轻量订阅服务：对外提供 Clash / sing-box 订阅。仅用 Python 标准库。"""

from __future__ import annotations

import argparse
import logging
import os
import sys
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

BASE_DIR = os.path.dirname(os.path.abspath(__file__))

SUB_TOKEN = os.environ.get("SUB_TOKEN", "")
if not SUB_TOKEN:
    token_file = os.path.join(BASE_DIR, "token.txt")
    if os.path.exists(token_file):
        with open(token_file, encoding="utf-8") as f:
            SUB_TOKEN = f.read().strip()

FILES = {
    "clash": ("clash.yaml", "text/yaml; charset=utf-8"),
    "singbox": ("singbox.json", "application/json; charset=utf-8"),
}

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
logger = logging.getLogger("vpn-sub")


class SubHandler(BaseHTTPRequestHandler):
    server_version = "vpn-sub/1.0"

    def log_message(self, fmt, *args):
        logger.info("%s - %s", self.address_string(), fmt % args)

    def _not_found(self):
        body = b"404 not found\n"
        self.send_response(404)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_HEAD(self):
        self._serve(head_only=True)

    def do_GET(self):
        self._serve(head_only=False)

    def _serve(self, head_only):
        path = self.path.split("?", 1)[0].strip("/")
        parts = [p for p in path.split("/") if p]

        # 期望形式: /<token>/<clash|singbox>
        if len(parts) != 2 or parts[0] != SUB_TOKEN:
            self._not_found()
            return

        name = parts[1]
        if name not in FILES:
            self._not_found()
            return

        fname, ctype = FILES[name]
        fpath = os.path.join(BASE_DIR, fname)
        if not os.path.exists(fpath):
            self._not_found()
            return

        with open(fpath, "rb") as f:
            data = f.read()

        self.send_response(200)
        self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(data)))
        self.send_header("Profile-Update-Interval", "24")
        self.send_header("Content-Disposition", 'inline; filename="%s"' % fname)
        self.end_headers()
        if not head_only:
            self.wfile.write(data)


def main():
    parser = argparse.ArgumentParser(description="轻量 VPN 订阅服务")
    parser.add_argument("--host", default="0.0.0.0")
    parser.add_argument("--port", type=int, default=8080)
    args = parser.parse_args()

    if not SUB_TOKEN:
        logger.error("未配置订阅 token（环境变量 SUB_TOKEN 或 token.txt）")
        sys.exit(1)

    srv = ThreadingHTTPServer((args.host, args.port), SubHandler)
    logger.info("订阅服务启动于 http://%s:%s", args.host, args.port)
    try:
        srv.serve_forever()
    except KeyboardInterrupt:
        pass
    finally:
        srv.server_close()


if __name__ == "__main__":
    main()
PYEOF

8.3 生成订阅 token #

这个 token 相当于访问订阅链接的密码，随机生成，不要用简单字符串：

bash
python3 -c "import secrets; print(secrets.token_urlsafe(16))" > /etc/vpn-sub/token.txt
chmod 600 /etc/vpn-sub/token.txt

# 查看生成的 token，记下来
cat /etc/vpn-sub/token.txt

11. 常见问题 #

11.1 端口被占用怎么办 #

bash
# 看谁在用 8443
ss -tulpn | grep 8443

如果被其他程序占用，两个办法：

办法一：改 sing-box 端口

bash
nano /etc/sing-box/config.json
# 把两处 "listen_port": 8443 改成 9443（或其他空闲端口）
sing-box check -c /etc/sing-box/config.json
systemctl restart sing-box

客户端里的 port 也要同步改成 9443。

办法二：停掉占用端口的程序（如果你确定它没用）

11.2 服务起不来 / 一直重启 #

bash
# 看具体报错
journalctl -u sing-box -n 50 --no-pager

常见原因：

日志关键词 原因 解决
permission denied 没权限读证书 chmod 600 /etc/sing-box/cert/key.pem
address already in use 端口被占用 见 11.1
no such file or directory 证书路径写错 检查配置里 certificate_path
invalid private key Reality 私钥错 重新执行 4.1

11.3 配置校验报错 #

bash
sing-box check -c /etc/sing-box/config.json
报错 原因 解决
legacy DNS server formats are deprecated 用了旧版 DNS 写法 改成 {"type": "tls", "server": "8.8.8.8"}
missing route.default_domain_resolver 缺 DNS 解析器 在 route 里加 "default_domain_resolver": "google"
unknown field "xxx" 字段拼写错误或版本不支持 对照版本文档检查
duplicate listen port TCP/UDP 冲突 确认一个用 TCP 一个用 UDP

11.4 客户端连不上 #

按这个顺序排查：

第一步：确认服务端是活的

bash
systemctl status sing-box --no-pager
ss -tulpn | grep 8443

两个端口（TCP+UDP）都要有输出。

第二步：确认防火墙放行

bash
# 查看 iptables 规则
iptables -L INPUT -n

# 如果用了 ufw
ufw status

如果有 DROP 规则拦截了 8443，需要放行：

bash
iptables -I INPUT -p tcp --dport 8443 -j ACCEPT
iptables -I INPUT -p udp --dport 8443 -j ACCEPT

（云服务器还要在控制台的安全组/防火墙里放行 8443 的 TCP 和 UDP）

第三步：确认客户端配置参数一致

最容易错的地方：

参数 服务端 客户端
server_name / sni www.bing.com 必须是 www.bing.com
short_id ["0123456789abcdef"] 0123456789abcdef（不带引号数组）
Reality 公钥 用 PublicKey 不是 PrivateKey！
端口 8443 8443

第四步：看服务端日志有没有连接进来

bash
journalctl -u sing-box -f
# 然后客户端尝试连接，看有没有日志输出

如果完全没有日志，说明流量没到达服务器（防火墙/安全组问题）。 如果有日志但连接失败，说明配置参数不匹配。

11.5 订阅链接打不开 #

bash
systemctl status vpn-sub --no-pager
ss -tulpn | grep 8080

如果 8080 没监听，看日志：

bash
journalctl -u vpn-sub -n 50 --no-pager

如果返回 404，检查：链接里的 token 是否和 /etc/vpn-sub/token.txt 内容完全一致。

11.6 客户端显示「订阅已过期 1970年」 #

这是正常现象，不影响使用。

订阅服务返回的 Subscription-Userinfo 响应头里带了 expire=0，客户端会把 Unix 时间戳 0 显示成 1970 年。这个字段是给机场套餐用的，自建不需要，只是个显示问题。

11.7 Hysteria2 能连但 Reality 连不上 #

说明 UDP 通、TCP 不通，或者 Reality 参数有误：

  1. 确认服务端 TCP 8443 在监听
  2. 确认客户端用的是 PublicKey 不是 PrivateKey
  3. 确认 short-id 完全一致
  4. 确认 flow: xtls-rprx-vision 两边都写了

反过来，如果 Reality 通而 Hysteria2 不通，多半是 UDP 被运营商 QoS 了，这时用 Reality 即可。

12. 安全建议 #

12.1 保护敏感文件 #

bash
chmod 600 /etc/vpn-sub/token.txt
chmod 600 /etc/vpn-sub/clash.yaml
chmod 600 /etc/sing-box/cert/key.pem
chmod 600 /etc/sing-box/config.json

12.2 订阅链接等同于密码 #

http:// 是明文传输，任何拿到链接的人都能导入你的节点。

  • ❌ 不要发到公开群聊、论坛、截图里
  • ❌ 不要把链接提交给任何在线工具
  • ✅ 如果怀疑泄露，立刻按 10.3 节换 token

12.3 SSH 安全 #

bash
# 安装 fail2ban 防止爆破
apt update && apt install -y fail2ban
systemctl enable --now fail2ban

# 检查状态
fail2ban-client status sshd

更强的方式是改用密钥登录并禁用密码登录：

bash
# 1. 在你自己的电脑上生成密钥（如果还没有）
ssh-keygen -t ed25519 -C "your_email@example.com"

# 2. 上传公钥到服务器
ssh-copy-id root@你的服务器IP

# 3. 测试能否免密登录（务必先用新开一个终端测试！）
ssh root@你的服务器IP

# 4. 确认能登录后，再禁用密码登录
nano /etc/ssh/sshd_config
# 改成：
#   PasswordAuthentication no
#   PermitRootLogin prohibit-password
systemctl restart ssh

# 5. ⚠️ 不要关闭当前已登录的终端！用新终端测试确认能进，再关旧的

12.4 不要对外暴露管理面板 #

本文方案没有任何 Web 管理面板，这是刻意设计的。如果需要增删用户，直接改 /etc/sing-box/config.json 里的 users 数组然后重启服务即可。

12.5 关于 IP 被封 #

如果服务器 IP 被封（国内无法直接访问），处理方式：

  1. 换 IP：在云服务商控制台更换弹性 IP，然后：

    • 改 /etc/sing-box/config.json 无需动（里面没写 IP）
    • 改 /etc/vpn-sub/clash.yaml 和 singbox.json 里的 server 字段
    • systemctl restart vpn-sub
    • 客户端更新订阅

  2. 密钥不用换：UUID、密码、Reality 密钥全部保留。

同一个参数在服务端配置、Clash 客户端、sing-box 客户端里的写法各不相同，这是新手最容易配错的地方。本附录逐字段对照，配置时可直接查表。

E.1 Hysteria2 字段对照 #

概念 服务端 config.json Clash（Mihomo） sing-box 客户端 说明
服务器地址 —（服务端不需要） server: 1.2.3.4 "server": "1.2.3.4" 填公网 IP，不要填域名
端口 "listen_port": 8443 port: 8443 "server_port": 8443 名字不同，值相同
密码 users[0].password password: "password": 三处必须完全一致
TLS 服务器名 tls.server_name sni: tls.server_name 都是 www.bing.com
证书校验 —（自签证书） skip-cert-verify: true tls.insecure: true ⚠️ 字段名完全不同
ALPN — alpn: [h3] tls.alpn: ["h3"] 可不写，写上更稳
带宽声明 — up / down — 仅协商提示，不是限速

⚠️ 最易错点：Clash 叫 skip-cert-verify，sing-box 叫 insecure。含义相同但写混就会报错。

E.2 VLESS-Reality 字段对照 #

概念 服务端 config.json Clash（Mihomo） sing-box 客户端 说明
服务器地址 — server: "server": 公网 IP
端口 "listen_port": 8443 port: 8443 "server_port": 8443
用户 ID users[0].uuid uuid: "uuid": 必须完全一致
流控 users[0].flow flow: xtls-rprx-vision "flow": "xtls-rprx-vision" ⚠️ 两边都要写，少一个就连不上
伪装域名 tls.server_name servername: tls.server_name www.bing.com
TLS 指纹 —（服务端无需） client-fingerprint: chrome tls.utls.fingerprint: "chrome" ⚠️ 服务端不写，客户端必写
公钥 reality.private_key reality-opts.public-key: tls.reality.public_key ⚠️ 服务端用私钥，客户端用公钥
短 ID reality.short_id: ["0123..."] reality-opts.short-id: "0123..." tls.reality.short_id ⚠️ 服务端是数组，客户端是字符串
握手目标 reality.handshake.server + server_port —（隐含在 servername） —（隐含在 server_name） 仅服务端配置
网络类型 — network: tcp —（默认 tcp）
UDP 转发 — udp: true —（默认开启）
Reality 开关 reality.enabled: true 写了 reality-opts 即开启 tls.reality.enabled: true

E.3 三个必须注意的陷阱 #

陷阱 1：公钥和私钥写反 #

服务端： "private_key":  "SNd4_3bcD-..."
客户端： public-key / "public_key": "4eLQWkN7..."

Reality 连不上的原因里，九成都是这一条。

sing-box generate reality-keypair 会同时输出 PrivateKey 和 PublicKey，两者是配对的：

  • PrivateKey → 只能写在服务端
  • PublicKey → 只能写在客户端

私钥一旦泄露，等同于服务被完全接管。

陷阱 2：short_id 格式不同 #

json
// 服务端：数组，可以配多个
"short_id": ["0123456789abcdef", "fedcba9876543210"]

// 客户端：字符串，只能写一个，且必须是服务端列表里的某个值
"short_id": "0123456789abcdef"

客户端写成数组会直接报错。如果服务端配置了多个 short_id，客户端任选其一即可。

陷阱 3：flow 两边都要有 #

服务端： users[0].flow = "xtls-rprx-vision"
客户端： flow          = "xtls-rprx-vision"

服务端写了而客户端没写，连接会在传输层失败，且日志往往不报明显错误，是排查难度最高的一个坑。

E.4 客户端本地字段（与协议无关） #

以下字段只影响客户端本地行为，和服务端配置无关：

字段 位置 作用
mixed-port: 7890 Clash 本地 HTTP/SOCKS 混合代理端口
external-controller Clash 控制面板监听地址
mode: rule Clash 规则模式（相对 global 全局模式）
ipv6: false Clash / sing-box ⚠️ 服务器无 IPv6 时务必关闭，否则解析异常
dns.enhanced-mode: fake-ip Clash 降低 DNS 污染影响

⚠️ 关于 ipv6：如果服务器本身没有 IPv6 出口（可在部署前用 curl -s6 ifconfig.me 检查，无输出即无 IPv6），客户端务必设为 ipv6: false。照抄带 ipv6: true 的配置会出现「能连上但部分网站打不开」的怪现象，极难定位。

E.5 快速自查清单 #

配置完成后，对照下表逐项核对，全部打勾才能保证连得上：

# 检查项 服务端 客户端
1 IP 地址正确 — ☐
2 端口 8443 ☐ ☐
3 Hysteria2 密码一致 ☐ ☐
4 UUID 一致 ☐ ☐
5 server_name / sni 为 www.bing.com ☐ ☐
6 服务端私钥 / 客户端公钥（不要搞反） ☐ ☐
7 short_id 服务端数组、客户端字符串 ☐ ☐
8 flow: xtls-rprx-vision 两边都有 ☐ ☐
9 客户端 client-fingerprint 已设置 — ☐
10 客户端 ipv6: false — ☐

最后提醒：部署完成后，请务必把 UUID、密码、PrivateKey 妥善保管。这些是重建服务的关键。如果服务器重装，只要保留这三个值，服务端配置可以直接复现。
