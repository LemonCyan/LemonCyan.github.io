内网穿透技术分为两类：服务器穿透与建立虚拟局域网。

前者把内网单台机器的某个端口或 Web 服务映射到公网，外部访客不装任何软件，直接拿浏览器或 SSH 终端就能连；后者把分散在多地的设备编进同一个私有加密大内网，外部公网看不到端口，设备间直接走点对点（P2P）打洞通信。

选错方向会做很多无用功。本文将这两种路径的核心方案与落地配置整理归并，去掉冗余描述，直奔实战配置。

graph TD

    Root --> ModeB[模式 2: 建立虚拟局域网<br/>多设备加密互联 / 零公网暴露]

    ModeA --> FRP[1.1 FRP: 有公网 VPS 时的自建网关]
    ModeA --> cpolar[1.2 cpolar: 无 VPS 时的国内穿透]
    ModeA --> OutRay[1.3 OutRay: 本地开发与 Webhook 抓包]
    ModeA --> CF[1.4 Cloudflare Tunnel: 独立域名发布与零信任网关]
    ModeA --> DevTunnel[1.5 Dev Tunnel: 微软官方开发者隧道 / VS Code 原生集成]

    ModeB --> Tailscale[2.1~2.3 Tailscale: 基于 WireGuard 的异地组网<br/>自动 P2P 打洞，一机开启子网路由通全网]

1. 第一类：服务器穿透（单端口/服务暴露至公网） #

这类方案的核心是公网中继接入。访客无需在本地安装客户端，直接访问公网域名或 IP:端口 即可触达内网。

sequenceDiagram
    autonumber
    actor Visitor as 🌍 外部访客 / 客户 (浏览器 / SSH)
    participant Relay as ☁️ 公网服务端 / 边缘节点 (FRP / cpolar / OutRay / Cloudflare / Dev Tunnel)
    participant Client as 🖥️ 内网客户端守护进程

    App-->>Visitor: 5. 沿原路返回响应数据

1.1 FRP：有公网 VPS 时的自建网关 #

手头有一台固定公网 IP 的云服务器时，FRP（Fast Reverse Proxy）是自主掌控度最高、吞吐性能最好的方案。配置全面采用 v0.50+ / v0.60+ 标准 TOML 语法。

1. 服务端配置 (/etc/frp/frps.toml) #

部署在公网 VPS 上：

toml
# 基础服务端口与认证
bindAddr = "0.0.0.0"
bindPort = 7000
auth.method = "token"
auth.token = "YourSuperSecureToken2026"

# HTTP 虚拟主机端口 (如果本地装了 Nginx，填 8080)
vhostHTTPPort = 8080
subDomainHost = "frp.yourdomain.com"

# Web 管理面板
webServer.addr = "0.0.0.0"
webServer.port = 7500
webServer.user = "admin"
webServer.password = "AdminSecret2026"

# 限制客户端可绑定的远程端口范围
allowPorts = [
  { start = 20000, end = 30000 }
]

2. 客户端配置 (/etc/frp/frpc.toml) #

部署在内网机器上：

toml
serverAddr = "vps.yourdomain.com"
serverPort = 7000
auth.method = "token"
auth.token = "YourSuperSecureToken2026"

transport.useEncryption = true
transport.useCompression = true

# 场景 A: HTTP Web 虚拟主机 (二级域名分流)
[[proxies]]
name = "web_app"
type = "http"
localIP = "127.0.0.1"
localPort = 3000
subdomain = "app"  # 访客通过 http://app.frp.yourdomain.com:8080 访问

# 场景 B: 远程 SSH 端口映射
[[proxies]]
name = "ssh_linux"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 22222 # 映射到 VPS 公网的 22222 端口

# 场景 C: STCP (Secret TCP) 私密穿透 (强烈推荐敏感服务使用)
# VPS 上不监听任何公网端口，外部扫描器完全扫不到
[[proxies]]
name = "secret_rdp"
type = "stcp"
secretKey = "SecretKey2026"
localIP = "127.0.0.1"
localPort = 3389

3. 外网访问 STCP 服务（访客端） #

在你的外出笔记本上也装一个 frpc，编辑 frpc_visitor.toml：

toml
serverAddr = "vps.yourdomain.com"
serverPort = 7000
auth.token = "YourSuperSecureToken2026"

[[visitors]]
name = "rdp_visitor"
type = "stcp"
serverName = "secret_rdp"
secretKey = "SecretKey2026"
bindAddr = "127.0.0.1"
bindPort = 13389

运行 frpc -c frpc_visitor.toml 后，本地直接连接 127.0.0.1:13389 就能直通家里远程桌面，公网零暴露面。

4. VPS 与 Nginx 共存（80/443 复用分流） #

当 VPS 已建站占用 80/443 时，用 Nginx 终结 SSL 证书，并反向代理给 FRP 的 8080 端口：

nginx
server {
    listen 80;
    server_name *.frp.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name *.frp.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host; # 必须传递 Host，frps 靠此分发内网服务
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

1.2 cpolar：无 VPS 时的国内穿透（嵌入式与树莓派） #

没有公网云服务器时，自建 FRP 走不通。cpolar 内置了国内多线 BGP 节点，跨网延迟在 20ms~50ms，且自带 9200 本地 Web 控制台，适合树莓派、RK3588、工控机等设备的远程 SSH 调试。

1. 安装与绑定 #

bash
# 一键安装
curl -fsSL https://www.cpolar.com/static/downloads/install-release-cpolar.sh | sudo bash

# 绑定官网账号复制的专属 AuthToken
cpolar authtoken 你的专属AuthToken

# 启动并设置开机自启
sudo systemctl enable --now cpolar

2. 查看隧道并建立连接 #

打开本地浏览器访问 http://<开发板IP>:9200，在「在线隧道列表」中查看分配的公网地址。

终端直接远程连接：

bash
# 格式: ssh 用户名@分配域名 -p 分配端口
ssh zhengyang@5.tcp.vip.cpolar.cn -p 14318

本地 ~/.ssh/config 别名直连：

text
Host my-pi
    HostName 5.tcp.vip.cpolar.cn
    Port 14318
    User zhengyang

配置后终端敲 ssh my-pi 直接连入。

3. 动态端口微信自动推送脚本 #

免费版 cpolar 每次设备重连后公网 TCP 端口会变。通过读取本地 9200 端口 API 抓取最新端口并推送到微信，解决端口变动问题：

python
#!/usr/bin/env python3
import time, requests

CPOLAR_API = "http://127.0.0.1:9200/api/v1/tunnels"
SERVER_CHAN_KEY = "SCTxxxxxxxxxxxxxxxxxx" # 替换为你的推送 Key

def push_ssh_port():
    try:
        resp = requests.get(CPOLAR_API, timeout=5).json()
        for t in resp.get("items", []):
            if t.get("name") == "ssh" or t.get("proto") == "tcp":
                public_url = t.get("public_url") # tcp://5.tcp.vip.cpolar.cn:14318
                host, port = public_url.replace("tcp://", "").split(":")
                msg = f"SSH命令: ssh user@{host} -p {port}"
                requests.post(f"https://sctapi.ftqq.com/{SERVER_CHAN_KEY}.send", 
                              data={"title": "设备新 SSH 端口", "desp": msg}, timeout=5)
                return
    except Exception as e:
        print(f"抓取失败: {e}")

if __name__ == "__main__":
    time.sleep(10)
    push_ssh_port()

1.3 OutRay：本地开发与 Webhook 抓包调试 #

调试微信支付、Stripe 回调或对外展示临时 Demo 时，既不需要配复杂的反向代理，也不需要跑守护进程。OutRay 基于 Node.js，一行命令拉起穿透，自带本地 4040 抓包控制台。

1. 一键启动 #

bash
# 免安装直接运行
npx outray http 3000 --subdomain my-dev-app

终端会输出穿透域名 https://my-dev-app.outray.io 和抓包面板地址 http://127.0.0.1:4040。

2. 本地 Webhook 抓包与一键 Replay #

做支付回调调试时最麻烦的是改了代码还要重新掏手机扫码付款。打开 http://127.0.0.1:4040：

  • 请求的 Header、Query Params、Body Payload 毫秒级展示；
  • 修复代码 bug 后，直接点击面板上的 Replay 按钮，OutRay 原样重新发送该请求到本地 localhost:3000，无需反复扫码。

3. 保护敏感接口 #

bash
outray http 3000 --auth "admin:secret123"

外部访客访问时强制弹出 HTTP Basic Auth 验证。

1.4 Cloudflare Tunnel：免公网 IP 的独立域名发布与零信任网关 #

如果你拥有一个托管在 Cloudflare 的独立域名，想把家庭 NAS、本地 Web 项目或个人博客长期公开发布到互联网，Cloudflare Tunnel（cloudflared）是最省心的方案。

它打破了「公网 IP + 端口映射」的传统做法：内网机器主动向 Cloudflare 边缘节点发起单向出站长连接，防火墙无需开放任何入站端口，直接借助 Cloudflare Anycast CDN 将本地服务发布到独立域名上，自带免费 SSL 证书与 DDoS 防护。

1. 安装客户端 #

以 Linux（Ubuntu / Debian）为例：

bash
# 下载并安装官方 DEB 包
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
cloudflared --version

若是 Windows、macOS 或 Docker，官方也均提供了对应程序与 cloudflare/cloudflared:latest 容器镜像。

2. 登录认证与创建隧道 #

bash
# 1. 登录 Cloudflare 账号，浏览器授权拉取凭证 cert.pem
cloudflared tunnel login

# 2. 创建隧道（例如命名为 homelab）
cloudflared tunnel create homelab

命令执行完毕后，终端会打印出该隧道的 UUID，并在 ~/.cloudflared/ 目录下生成 <Tunnel-UUID>.json 密钥文件。

把凭证移动到系统配置目录：

bash
sudo mkdir -p /etc/cloudflared
sudo cp ~/.cloudflared/*.json /etc/cloudflared/

3. 生产级 Ingress 路由配置 (/etc/cloudflared/config.yml) #

创建并编辑配置文件：

bash
sudo nano /etc/cloudflared/config.yml

写入多服务统一路由规则：

yaml
tunnel: homelab
credentials-file: /etc/cloudflared/你的UUID.json

ingress:
  # 规则 1: 标准本地 Web 服务
  - hostname: app.yourdomain.com
    service: http://127.0.0.1:3000

  # 规则 2: 群晖 NAS / PVE 管理后台 (自签名 HTTPS 服务)
  # 必须开启 noTLSVerify: true，否则校验自签名证书失败会报 502
  - hostname: nas.yourdomain.com
    service: https://192.168.1.100:5000
    originRequest:
      noTLSVerify: true

  # 规则 3: 远程 SSH 服务 (配合 Access 零信任)
  - hostname: ssh.yourdomain.com
    service: ssh://127.0.0.1:22

  # 规则 4: 兜底匹配规则 (必须放在最后一行，未命中域名一律 404)
  - service: http_status:404

测试配置语法是否合法：

bash
sudo cloudflared tunnel --config /etc/cloudflared/config.yml ingress validate

4. 绑定 DNS 路由与开机自启 #

bash
# 自动在 Cloudflare DNS 表中为隧道生成 CNAME 记录
cloudflared tunnel route dns homelab app.yourdomain.com
cloudflared tunnel route dns homelab nas.yourdomain.com
cloudflared tunnel route dns homelab ssh.yourdomain.com

# 注册为系统服务并设置开机自启
sudo cloudflared --config /etc/cloudflared/config.yml service install
sudo systemctl enable --now cloudflared

5. SSH 零信任访问与客户端直连 #

把内网 22 端口直接暴露在公网容易被扫描器撞库。Cloudflare 提供了通过浏览器 SSO 认证的零信任机制：

在 Cloudflare Zero Trust 后台进入 Access -> Applications，为 ssh.yourdomain.com 添加一条策略，仅放行指定邮箱验证码或企业身份源。

在外部笔记本（客户端）配置本地 ~/.ssh/config：

text
Host ssh.yourdomain.com
    ProxyCommand cloudflared access ssh --hostname %h
    User root

终端执行 ssh root@ssh.yourdomain.com 时，会自动唤起本地浏览器弹出 Cloudflare 身份认证窗口，认证通过后终端直接进入内网终端，公网端口完全封闭。

6. 局限与取舍 #

  • 文件上传大小限制：Cloudflare 免费版对 HTTP POST 请求体限制为 100MB。若需向 NAS 传输几个 G 的大文件或视频，不适合走该隧道，应改用 Tailscale 走 P2P 直连；
  • 国内网络延迟：国内三大运营商访问 Cloudflare 免费 Anycast 节点有时会绕道美西，延迟在 150ms~250ms 左右。适合对外展示 Web 或低频管理，对实时高吞吐场景不如自建国内 DERP 或私有反向代理。

1.5 Microsoft Dev Tunnel：微软官方开发者隧道（VS Code 原生集成与临时联调） #

如果只是在本地写代码，临时想把 localhost:3000 或后端接口暴露给异地同事看效果、配合 Webhook 做即时联调，Microsoft Dev Tunnel（开发人员隧道）是极轻量的解法。

它依托微软 Azure 全球中继网络，免去买 VPS 和配置域名的环节，原生支持单命令映射多个端口，支持设置销毁时间（用完即弃），并且与 VS Code 深度绑定。

1. CLI 安装与登录认证 #

bash
# Windows (通过 winget 安装)
winget install Microsoft.devtunnel

# Linux (一键脚本)
curl -sL https://aka.ms/DevTunnelCliInstall | bash

# macOS (Homebrew)
brew install --cask devtunnel

# 使用 GitHub 或微软账号授权登录
devtunnel user login -g

2. 常用命令实战 #

bash
# 1. 临时以匿名公开方式映射本地 3000 端口
devtunnel host -p 3000 --allow-anonymous
# 终端会输出形如 https://xxx-3000.asse.devtunnels.ms 的公网链接

# 2. 同时并发映射多个微服务端口 (前端 3000 + 后端 8080)
devtunnel host -p 3000 8080 --allow-anonymous

# 3. 设置隧道有效期 (例如 2 天后自动删除注销，防止长期裸奔)
devtunnel host -p 3000 --allow-anonymous --expiration 2d

# 4. 创建持久化命名隧道
devtunnel create my-demo -a
devtunnel port create my-demo -p 3000
devtunnel host my-demo

3. VS Code 原生免命令图形化使用 #

在 VS Code 中甚至不需要输入任何终端命令：

  1. 按下 Ctrl + ~ 打开终端面板，切换到「端口 (Ports)」标签；
  2. 点击「添加端口」，填入 3000；
  3. 在端口列表中，右键将「可见性 (Visibility)」切换为「公开 (Public)」；
  4. 编辑器会自动调用底层 Dev Tunnel，在界面中直接生成带 HTTPS 的公网访问地址，并支持在面板内查看请求流量。

4. 局限与取舍 #

  • 生命周期限制：单条隧道最长有效期为 30 天，定位是开发阶段的即时联调与临时演示，不适合作为生产环境的常驻网关。

2. 第二类：建立虚拟局域网（异地私有组网与设备互联） #

如果你的目标是让异地多台设备（手机、笔记本、家里 NAS、工控机）互相访问，不要用服务器穿透把端口裸露到公网上。虚拟局域网方案把所有设备拉进同一个加密私网，外面扫不到任何端口，节点之间优先走 P2P 打洞。

2.1 Tailscale：基于 WireGuard 的私有组网 #

Tailscale 底层使用 WireGuard 内核，把密钥交换、NAT 打洞和拓扑路由全自动化。两端只要有一端具备锥形 NAT 条件，就会自动建立端到端直连，传输速率吃满家里宽带的实际上行带宽。

1. 安装与加入网络 #

bash
# Linux 一键安装
curl -fsSL https://tailscale.com/install.sh | sh

# 启动并绑定账号
sudo tailscale up

复制终端输出的链接在浏览器中用 Google 或 GitHub 账号完成授权。设备随即被分配一个固定的 100.x.y.z 虚拟内网 IP。

在外部笔记本上直接访问：

bash
ping 100.64.0.3
ssh user@100.64.0.3

开启 MagicDNS 后，连 IP 都不用记，直接按主机名访问：

bash
ssh user@my-nas

2.2 核心打法：Subnet Router（打通家庭 192.168.x.x 全网段） #

家里有摄像头、打印机、软路由后台等无法安装 Tailscale 客户端的设备。在一台常开的 Linux（NAS 或软路由）上配置 Subnet Router，整网设备全部打通。

1. 开启 Linux 内核转发 #

bash
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf

2. 宣告家庭局域网网段 #

bash
# 假设家庭局域网为 192.168.1.0/24
sudo tailscale up --advertise-routes=192.168.1.0/24 --accept-dns=false

3. 控制台审批 #

进入 Tailscale 网页后台 Machines 列表，找到这台机器，点击 Edit route settings，勾选刚宣告的 192.168.1.0/24 并保存。

外出笔记本连上 Tailscale 后，浏览器直接输入 http://192.168.1.50 就能直接打开家里的摄像头画面。

⚠警告

家用路由器默认网段多是 192.168.1.0/24。若出差地 Wi-Fi 也是该网段，路由表会优先走本地网卡导致冲突。把家里的路由器 LAN 网段改成 192.168.66.0/24 或 10.188.0.0/24 能彻底避开。

2.3 国内网络优化：自建私有 DERP 中继 #

国内不同运营商跨网通信或遇到双对称 NAT 时，P2P 打洞可能失败。若走 Tailscale 官方海外中继，延迟会跳到 200ms 以上。在便宜国内 VPS 上自建专属 DERP 节点即可压到 20ms~40ms。

1. Docker 启动 DERP 容器 #

开放 VPS 防火墙的 TCP 33445 和 UDP 33445：

bash
docker run -d \
  --name derper \
  --restart always \
  -p 33445:33445 \
  -p 33445:33445/udp \
  -v /etc/ssl/certs/derp.yourdomain.com.crt:/app/certs/derp.yourdomain.com.crt \
  -v /etc/ssl/certs/derp.yourdomain.com.key:/app/certs/derp.yourdomain.com.key \
  fredliang/derper \
  -hostname derp.yourdomain.com \
  -certmode manual \
  -certdir /app/certs \
  -derp-port 33445 \
  -stun-port 33445 \
  -verify-clients=true

参数 -verify-clients=true 必须带上，防止中继被外部扫描脚本盗用流量。

2. 在 Tailscale 控制台配置 ACL DERP Map #

在控制台 Access Controls 中追加自定义区域配置：

json
{
  "derpMap": {
    "OmitDefaultRegions": false,
    "Regions": {
      "900": {
        "RegionID": 900,
        "RegionCode": "custom-cn",
        "RegionName": "My Private CN DERP",
        "Nodes": [
          {
            "Name": "900a",
            "RegionID": 900,
            "HostName": "derp.yourdomain.com",
            "DERPPort": 33445,
            "STUNPort": 33445
          }
        ]
      }
    }
  }
}

客户端运行 tailscale netcheck 验证连通性。
