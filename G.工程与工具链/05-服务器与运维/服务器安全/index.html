一台裸奔在公网的 Linux VPS，几分钟内就会遭到全网扫描脚本的轮番爆破。安全防护不需要复杂的商业软件，把防火墙、SSH 密钥认证、Fail2ban 自动封禁和系统自动补丁配好，就能挡掉 99% 的自动化入侵。

本文按防御层级整理这四道核心防线，命令全部经过实测。

1. UFW 防火墙配置 #

UFW（Uncomplicated Firewall）是 Debian / Ubuntu 上对 iptables / nftables 的前端封装，规则简短直观。

1.1 基础查看与启停 #

bash
# 查看防火墙状态与规则
sudo ufw status

# 详细模式（显示默认策略与日志级别）
sudo ufw status verbose

# 带编号显示（删除单条规则时必用）
sudo ufw status numbered

bash
# 启用防火墙（执行前务必确保放行了 SSH 端口）
sudo ufw enable

# 临时关闭
sudo ufw disable

# 重置所有规则恢复初始状态
sudo ufw reset
⛔危险

敲 ufw enable 前必须确认已经放行了 SSH 端口（22 或你的自定义端口）。如果在云服务器上直接关门，当前连接虽不断，但一旦断开就只能进云厂商控制台走 VNC 救援。

1.2 默认策略与安全基线 #

生产环境标准姿态：默认拒绝所有入站，允许所有出站。

bash
sudo ufw default deny incoming
sudo ufw default allow outgoing

在此基线上，按需逐个凿开入站通道。

1.3 端口与服务放行 #

bash
# 放行 SSH（若改了端口比如 22222，就写 22222/tcp）
sudo ufw allow 22/tcp

# Web 站点标准端口
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 针对 SSH 限制握手频次（30 秒内超过 6 次连接自动拒掉，防无脑扫端口）
sudo ufw limit 22/tcp

细粒度来源 IP 控制（管理后台、数据库等敏感服务）：

bash
# 仅允许指定跳板机 IP（192.168.1.100）访问本机 22 端口
sudo ufw allow from 192.168.1.100 to any port 22 proto tcp

# 仅允许内网网段访问 MySQL
sudo ufw allow from 10.0.0.0/24 to any port 3306 proto tcp

# 明确阻断恶意 IP
sudo ufw deny from 203.0.113.50

1.4 规则修改与删除 #

bash
# 1. 先列出带序号的规则
sudo ufw status numbered

# 2. 按序号删除（比如删掉第 3 条）
sudo ufw delete 3

# 也可以按定义全名删除
sudo ufw delete allow 80/tcp

1.5 典型场景模板 #

Web 业务机：只露 Web 与限速 SSH #

bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw limit 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

被锁在外面时的救援 #

如果因为手抖配错规则导致 SSH 连不上，登录云厂商后台的 VNC/Web Console 控制台：

bash
sudo ufw disable
# 或者重设规则
sudo ufw reset
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw enable

2. Fail2ban 入侵防御 #

UFW 的 limit 只能防瞬间突发，防不了低频持续爆破。Fail2ban 挂在日志后面实时盯梢，一旦某个 IP 在指定窗口内输错 N 次密码，直接拉进 iptables 关进小黑屋。

2.1 安装与配置 #

bash
sudo apt update
sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban

Fail2ban 的规则文件是 /etc/fail2ban/jail.conf，系统升级会覆盖它。必须复制一份 jail.local 进行自定义覆盖：

bash
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo vim /etc/fail2ban/jail.local

修改或添加 [DEFAULT] 和 [sshd] 区域：

ini
[DEFAULT]
# 封禁时长（秒）：3600 = 1 小时；可设为 -1 永久封禁
bantime = 3600

# 统计窗口（秒）：在 10 分钟内累计
findtime = 600

# 窗口内最大重试失败次数
maxretry = 3

# 白名单 IP，用空格隔开（本机与公司公网 IP 务必加进这里，防自己手抖误封）
ignoreip = 127.0.0.1/8 ::1 192.168.1.0/24

[sshd]
enabled = true
port = ssh
# 若自定义了端口如 22222，这里写 port = 22222
filter = sshd
logpath = /var/log/auth.log
maxretry = 3

改完测试语法并重载：

bash
sudo fail2ban-client -t        # 校验配置
sudo systemctl restart fail2ban
sudo systemctl status fail2ban --no-pager

2.2 运维常用命令 #

bash
# 查看所有启用的 jail
sudo fail2ban-client status

# 查看 sshd jail 的详细拦截状态（能看到当前封了哪些 IP、累计抓了多少人）
sudo fail2ban-client status sshd

# 手动解封被误杀的 IP
sudo fail2ban-client set sshd unbanip 1.2.3.4

# 手动封禁某个恶意 IP 一天（86400 秒）
sudo fail2ban-client set sshd banip 5.6.7.8

# 查看 fail2ban 实时拦截日志
sudo tail -f /var/log/fail2ban.log

3. SSH 认证硬核收敛 #

密码认证在公网环境下是最大的弱点。彻底禁用密码认证、只留 Ed25519 密钥，爆破脚本直接在协议握手阶段就断开，连发 payload 的机会都没有。

3.1 客户端生成 Ed25519 密钥 #

在你的本地终端（Mac/Linux/Windows PowerShell）执行：

bash
# 现代首选 Ed25519：更短、更快、抗侧信道攻击
ssh-keygen -t ed25519 -C "ops-laptop-2026" -f ~/.ssh/id_ed25519

# 老系统兼容可选用 RSA 4096：
# ssh-keygen -t rsa -b 4096 -f ~/.ssh/id_rsa

3.2 部署公钥至服务器 #

bash
# 方法 1：一键复制（Linux / macOS / 现代 Windows）
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@your_server_ip

# 若服务端是非标准端口 22222：
ssh-copy-id -p 22222 -i ~/.ssh/id_ed25519.pub user@your_server_ip

手动部署与目录权限铁律（权限错一位 OpenSSH 会直接拒绝加载）：

bash
# 服务端执行
mkdir -p ~/.ssh
chmod 700 ~/.ssh

# 把客户端的 id_ed25519.pub 内容贴入 authorized_keys
vim ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
chown -R $(whoami):$(whoami) ~/.ssh

3.3 服务端 sshd_config 安全收敛 #

bash
sudo vim /etc/ssh/sshd_config

核对并锁定以下关键项：

ini
# 1. 启用公钥认证
PubkeyAuthentication yes

# 2. 彻底禁用密码认证（最关键一步）
PasswordAuthentication no
ChallengeResponseAuthentication no

# 3. root 登录策略：prohibit-password 表示禁密码但允许密钥；no 表示完全禁止 root 直登
PermitRootLogin prohibit-password

# 4. 禁用空密码
PermitEmptyPasswords no

# 5. 限制最大认证尝试次数
MaxAuthTries 3

# 6. 改非标准端口（可选，阻断批量自动化全网扫）
Port 22222

配置检查与平滑重载：

bash
# 检查配置语法，无输出表示正确
sudo sshd -t

# 平滑重载（千万别直接 restart 并退出当前终端！）
sudo systemctl reload sshd
⚠警告

修改完 sshd_config 并 reload 后，绝对不要关闭当前终端！立刻新开一个终端窗口跑 ssh -i ~/.ssh/id_ed25519 -p 22222 user@server 测试。确认新终端能凭密钥畅通连入后，才算加固成功。详细客户端别名配置、堡垒机跳板与隧道转发见同目录 SSH.md。

4. 基础加固：自动安全更新与权限收缩 #

4.1 无人值守安全补丁（unattended-upgrades） #

很多系统沦陷不是因为配置弱，而是 OpenSSL、内核或基础库出了高危 CVE 没及时打补丁。开启无人值守更新，只自动打安全补丁，不升级大版本破坏稳定性：

bash
sudo apt install -y unattended-upgrades update-notifier-common
sudo dpkg-reconfigure --priority=low unattended-upgrades

配置文件 /etc/apt/apt.conf.d/50unattended-upgrades 确认包含：

text
Unattended-Upgrade::Allowed-Origins {
    "${distro_id}:${distro_codename}-security";
};
Unattended-Upgrade::AutoFixInterruptedDpkg "true";
Unattended-Upgrade::Remove-Unused-Kernel-Packages "true";

4.2 普通用户 Sudo 提权与隔离 #

禁止团队成员日常直接共用 root。为每位运维人员建独立账号并赋予 sudo 权限：

bash
# 建普通用户
sudo adduser devops

# 加入 sudo 组
sudo usermod -aG sudo devops

# 验证免密或独立密码
su - devops -c "sudo whoami"

5. 入侵排查与实时审计 #

日常或疑似异常时，按这几组命令快速摸清服务器状态：

5.1 监控暴力破解与登录源 #

bash
# 实时跟踪登录认证日志
sudo tail -f /var/log/auth.log | grep sshd

# 统计当前被拒绝的密码尝试总数
sudo grep "Failed password" /var/log/auth.log | wc -l

# 统计爆破源 IP 排行榜 Top 10
sudo grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head -10

# 查看当前已成功登录的用户会话
w
who
last -n 20   # 查看最近 20 条成功登录历史
lastb -n 20  # 查看最近 20 条失败登录历史

5.2 网络连接与对外异常连接排查 #

bash
# 查看所有监听中的端口及对应进程
sudo ss -tulpn

# 统计当前与本机建立连接的外部 IP
sudo ss -ant | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head -20

5.3 计划任务与隐藏进程初检 #

挖矿木马最爱把持久化脚本写进 crontab 或隐藏目录：

bash
# 检查当前用户及系统的计划任务
crontab -l
sudo cat /etc/crontab
sudo ls -la /etc/cron.*

# 检查可疑高 CPU 占用进程
ps aux --sort=-%cpu | head -10

# 检查 /tmp、/dev/shm 等可读写目录里是否有可疑 ELF 执行文件
sudo find /tmp /var/tmp /dev/shm -type f -perm -111 -ls
