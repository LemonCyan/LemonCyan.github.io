一、为什么要有设备树 #

ARM Linux 在 3.x 之前，板级硬件信息是硬编码在 C 代码里的，导致同一份信息在三处重复：

位置 承担什么 典型文件
arch/arm/mach-xxx 板级资源：寄存器地址、中断号、时钟、GPIO mach-mini2440.c
arch/arm/plat-xxx SoC 公共部分 plat-samsung/devs.c
include/linux/platform_data 私有数据结构定义 s3c2410fb.h

后果是每加一块板子就往内核里塞一份 C 文件，Linus 2011 年在 ARM 邮件列表上直接开火，此后 ARM 全面转向设备树（Device Tree，DT）：硬件描述从 C 代码搬到独立的 .dts 文本文件，内核只留驱动。

三个直接好处：

  • 一个内核镜像 + 不同 dtb，就能启动多块板子；
  • 改引脚、改中断、改分区不用重新编译内核；
  • 硬件信息有了独立、可 diff 的文本载体。

二、dts / dtsi / dtb 与工具链 #

后缀 全称 角色 类比
.dts device tree source 一块板子一棵树，最终编译单元 .c
.dtsi device tree source include SoC 级公共节点，被 dts #include .h
.dtb device tree blob dtc 编译产物，交给内核的二进制 .o

编译用内核自带的 scripts/dtc（也可 apt install device-tree-compiler 单独装）：

bash
# 只编译设备树
make dtbs

# 单独把 dts 编成 dtb
dtc -I dts -O dtb -o s3c2440-smdk2440.dtb s3c2440-smdk2440.dts

# 反向：dtb 还原成可读源码
dtc -I dtb -O dts -o out.dts s3c2440-smdk2440.dtb

反编译是排查现场问题的第一招：拿到厂商镜像里的 dtb，dtc -I dtb -O dts 一看就知道它到底用哪个 compatible 起的机器。

U-Boot 侧需要开启 FDT 支持，并会用到几个命令：

text
CONFIG_OF_LIBFDT=y        # 链接 lib/libfdt，才有 fdt 命令

bash
fdt addr 0x71000000       # 告诉 uboot 内存里哪块是 dtb
fdt resize                # 扩容，为后续 fdt set 腾空间
fdt print /soc/spi@0      # 打印某个节点整棵子树
fdt set /chosen bootargs "..."   # 运行时改 bootargs 再启动
fdt header                # 打印 dtb 头部各字段，离线分析神器

三、节点与属性：一棵树的语法 #

设备树本质是**命名节点（node）+ 名值对属性（property）**组成的一棵树。

3.1 节点格式 #

dts
[label:] node-name[@unit-address] {
    [property definitions]
    [child nodes]
};

硬性规则：

  • 根节点名字必须是 /；
  • node-name 只允许大小写字母、数字、逗号、句点、下划线、加号、减号，长度不超过 31 字符；
  • 节点有 reg 属性才能带 @unit-address，反之没有 reg 就不能写 @xxx；
  • @unit-address 必须等于 reg 的第一个值（十六进制、不带 0x）。写成 serial@50000000 而 reg = <0x50001000 ...> 编译能过，但内核按节点名反查时会找不到；
  • 以 &label 开头的块是引用占位（如 &uart0 { ... };），dtc 会把它合并进对应的 label 节点。

最小可启动树长这样：

dts
/dts-v1/;                                // 版本声明，必须有

/ {
    model = "Samsung SMDK2440";
    compatible = "samsung,s3c2440", "samsung,mini2440";
    #address-cells = <1>;                // 子节点 reg 的地址占 1 个 u32
    #size-cells = <1>;                   // 子节点 reg 的长度占 1 个 u32

    memory@30000000 {
        device_type = "memory";
        reg = <0x30000000 0x4000000>;    // 64MB SDRAM
    };
};

3.2 label 与引用 #

给节点打 label 后，别处用 &label 就能往这个节点里追加/覆盖属性，这是 dtsi + dts 协作的核心机制：

dts
// s3c2440.dtsi 里
cpu0: cpu@0 {
    compatible = "arm,arm920t";
};

// 板级 dts 里：往 cpu0 追加供电信息
&cpu0 {
    cpu0-supply = <&vdd_cpu>;
};

同名节点会合并，同名属性后写的覆盖先写的。

3.3 属性值只有四种形态 #

形态 写法 说明
空 interrupt-controller; 只看有没有，不看值
字符串 / 字符串数组 compatible = "a,b", "c,d"; 逗号分隔
32/64 位整数（cell） reg = <0x30000000 0x4000000>; 尖括号，cell 是 u32
字节序列 mac = [00 00 de ad be ef]; 方括号，按字节写

非 32 位宽度的数组要用 /bits/ 前缀，例如 LCD 的 16 位宽度参数：

dts
width = /bits/ 16 <240>;      // 若不加 /bits/ 16，240 会占满一个 32 位 cell

四、标准属性（内核会读的那些） #

属性 作用 备注
compatible 与驱动匹配的第一顺位 格式 "厂商,型号"，从具体到通用排列
model 人读的板名 只给 /proc/device-tree/model 和日志用
reg 寄存器地址 + 长度 宽度由父节点 #address-cells/#size-cells 决定
status 是否启用 okay / disabled / fail / fail-sss
#address-cells 子节点地址字段占几个 cell 只对子节点生效
#size-cells 子节点长度字段占几个 cell 0 表示没有长度字段（如 i2c 子节点）
ranges 子总线地址到父总线地址的映射 空 ranges; 表示 1:1 直通
interrupt-parent 中断控制器的 phandle 不从父节点继承时显式写
interrupts 中断描述 每个 cell 的含义由控制器 #interrupt-cells 决定
clocks / clock-names 时钟 phandle 与名字 驱动用 clk_get(dev, "name") 取
pinctrl-names / pinctrl-N 引脚状态名与对应配置 见 pinctrl：引脚复用与电气属性
phandle 被引用时的编号 dtc 自动生成，源码里写 &label 即可

4.1 compatible 与 sentinel #

c
static const struct of_device_id my_dt_match[] = {
    { .compatible = "samsung,mini2440-led" },
    { }        /* 哨兵项：必须有，否则遍历 of_match_table 会越界 */
};

匹配规则是两个列表互相比：节点的 compatible 列表从具体到通用排（越靠后越通用），驱动的 of_device_id 表按书写顺序从上往下试，命中就停。所以设备树里写 "samsung,s3c2440-uart", "samsung,s3c2410-uart"，老驱动只认后者也能绑上——of_device_is_compatible 会在节点列表的第 2 项命中并返回 2。

不允许通配符。compatible = "fsl,mpc83xx-uart" 想让一颗驱动通吃 8313/8349 全部型号，dtc 不报错，但内核会把它当成一个普通字符串精确比较，永远匹配不上。要复用就堆具体型号："fsl,mpc8349-uart", "ns16550"。

不带厂商前缀的 compatible（如 ns16550、gpio-keys）是历史遗留，仍被大量老驱动使用，新写 dts 别学。

4.2 #address-cells / #size-cells 与 reg #

reg 的字节数不写死，由父节点说了算：

dts
soc {
    #address-cells = <1>;
    #size-cells = <1>;
    serial@50000000 {
        reg = <0x50000000 0x4000>;    // 1 个 cell 地址 + 1 个 cell 长度
    };
};

64 位系统常见 #address-cells = <2>; #size-cells = <2>;，于是 reg 变四个 cell：

dts
reg = <0x00000000 0x00000000  0x00000000 0x08000000>;
//    地址高 32 位    地址低 32 位    长度高 32 位    长度低 32 位

4.3 ranges：地址空间转换 #

dts
soc {
    compatible = "simple-bus";
    #address-cells = <1>;
    #size-cells = <1>;
    ranges = <0x0 0xe0000000 0x00100000>;
    //       子地址 0  父地址 0xe0000000  长度 1MB

    serial@4600 {
        reg = <0x4600 0x100>;
    };
};

驱动里读到的地址会被内核翻译成 0xe0000000 + 0x4600 = 0xe0004600。调试时记住这条换算，能解释一大半「寄存器地址对不上」的问题。

五、中断描述：四个 cell 怎么读 #

interrupts 每个中断占几个 cell 由中断控制器节点的 #interrupt-cells 决定。S3C2440 的主中断控制器是 #interrupt-cells = <4>，四个数的含义是：

位序 含义 取值
[0] 中断控制器编号 0 = 主中断，1 = 子中断
[1] 主/子中断号 只有子中断时有意义
[2] 硬件中断号 主中断号或子中断号
[3] 触发类型 1 上升沿、2 下降沿、3 双边沿、4 高电平、8 低电平

触发类型对应内核 include/linux/irq.h 的宏：

c
IRQ_TYPE_NONE        = 0x00000000,
IRQ_TYPE_EDGE_RISING = 0x00000001,
IRQ_TYPE_EDGE_FALLING= 0x00000002,
IRQ_TYPE_EDGE_BOTH   = IRQ_TYPE_EDGE_FALLING | IRQ_TYPE_EDGE_RISING,
IRQ_TYPE_LEVEL_HIGH  = 0x00000004,
IRQ_TYPE_LEVEL_LOW   = 0x00000008,

UART0 的收发两个中断就是一组典型写法：

dts
uart0: serial@50000000 {
    compatible = "samsung,s3c2410-uart";
    reg = <0x50000000 0x4000>;
    interrupts = <1 28 0 4>, <1 28 1 4>;
    //            子  28  RXD  高电平
    //                        子  28  TXD  高电平
    status = "okay";
};
  • 主中断号 28 = INT_UART0；
  • 子中断 0 = INT_RXD0、1 = INT_TXD0；
  • 也就是说：先看 [0] 是主还是子，再看 [2] 是哪一号，最后 [3] 定触发边沿。

外部中断走另一套控制器（GPF/GPF 的 #interrupt-cells = <2>，只有「中断号 + 触发类型」两个 cell），需要 interrupt-parent 指过去：

dts
&gpf {
    status = "okay";
};

srom-cs4@20000000 {
    compatible = "simple-bus";
    #address-cells = <1>;
    #size-cells = <1>;
    ranges = <0 0 0x08000000>;

    ethernet@20000000 {
        compatible = "davicom,dm9000";
        reg = <0x20000000 0x2 0x20000004 0x2>;
        interrupt-parent = <&gpf>;
        interrupts = <7 IRQ_TYPE_EDGE_RISING>;   // GPF7 = EINT7
    };
};

#interrupt-cells 写在中断控制器节点上，interrupt-parent 写在使用中断的设备节点上。两者看错一个，中断号就全错。中断从 DTS 到 IRQ number 的完整解析过程见 设备树中断：中断控制器与中断驱动。

六、几个特殊节点 #

节点 作用 内核怎么用
/chosen 启动参数 bootargs 直接变成 boot_command_line
/aliases 设备别名 生成 /proc/device-tree/aliases，如 serial0 = &uart0
/cpus CPU 列表 每个 cpu@N 的 reg 表示第几核
/memory 内存 device_type = "memory" + reg，构成 meminfo
/memreserve/ 保留物理内存 进 memblock 的 reserved 区 
dts
/ {
    chosen {
        bootargs = "noinitrd root=/dev/mtdblock4 rw init=/linuxrc console=ttySAC0,115200";
    };

    aliases {
        pinctrl0 = &pinctrl_0;
        serial0  = &uart0;
    };
};

七、dtb 二进制长什么样 #

dtb 不是压缩包，是四段线性布局：

text
+----------------------------+  0x00
| fdt_header (40 字节)        |
+----------------------------+
| memory reservation block   |  /memreserve/ 的条目，每条 16 字节
+----------------------------+
| structure block            |  节点树本体：BEGIN_NODE / PROP / END_NODE
+----------------------------+
| strings block              |  所有属性名的字符串池（去重）
+----------------------------+

头部结构体（大端）。3.10 之前叫 struct boot_param_header，字段完全相同，读老资料时别当成两个东西：

c
struct fdt_header {
    fdt32_t magic;               /* 0xd00dfeed */
    fdt32_t totalsize;           /* 整个 dtb 大小 */
    fdt32_t off_dt_struct;       /* structure block 偏移 */
    fdt32_t off_dt_strings;      /* strings block 偏移 */
    fdt32_t off_mem_rsvmap;      /* reservation block 偏移 */
    fdt32_t version;             /* 17 */
    fdt32_t last_comp_version;   /* 16 */
    fdt32_t boot_cpuid_phys;
    fdt32_t size_dt_strings;
    fdt32_t size_dt_struct;
};

structure block 只有四种标记：

标记 值 后面跟什么
FDT_BEGIN_NODE 0x1 节点名（含 \0，4 字节对齐）
FDT_END_NODE 0x2 无
FDT_PROP 0x3 {u32 len; u32 nameoff;} + 值
FDT_END 0x9 树结束

7.1 用 uboot 的 fdt header 验证 #

text
=> fdt header
magic:                  0xd00dfeed
totalsize:              0x0000149a        (5274)
off_dt_struct:          0x00000038
off_dt_strings:         0x000012d8
off_mem_rsvmap:         0x00000028
version:                17
last_comp_version:      16
boot_cpuid_phys:        0x00000000
size_dt_strings:        0x000001c2
size_dt_struct:         0x000012a0
number mem_rsv:         0x00000000

把上面的偏移套进实际字节（hexdump 视角）：

text
0x00  d0 0d fe ed     magic
0x04  00 00 14 9a     totalsize
0x08  00 00 00 38     off_dt_struct
0x0c  00 00 12 d8     off_dt_strings
0x10  00 00 00 28     off_mem_rsvmap
0x14  00 00 00 11     version = 17
0x18  00 00 00 10     last_comp_version = 16
0x1c  00 00 00 00     boot_cpuid_phys
0x20  00 00 01 c2     size_dt_strings
0x24  00 00 12 a0     size_dt_struct
0x28  00..00 / 00..00 唯一的 reserve entry 全 0，表示结束
0x38  00 00 00 01     FDT_BEGIN_NODE
0x3c  00 00 00 00     节点名为空串 —— 根节点 /
0x40  00 00 00 03     FDT_PROP
0x44  00 00 00 21     len = 33
0x48  00 00 00 00     nameoff = 0
0x4c  "samsung,s3c2440.samsung,mini2440"  -> compatible 的值

off_dt_strings = 0x12d8 处的第一个字符串就是 compatible，所以 nameoff = 0 指向它。理解了这一层，fdt print 打印不出东西、内核报 bad magic 时，就知道该去 dump 哪几个字节。

八、一个完整的总线节点示例（SPI 控制器） #

以 i.MX8MQ 的 ECSPI1 为例，能看到所有关键属性怎么配合：

dts
ecspi1: spi@30820000 {
    #address-cells = <1>;      // 子节点 reg 只有 1 个 cell（片选号）
    #size-cells = <0>;         // 子节点没有长度字段
    compatible = "fsl,imx8mq-ecspi", "fsl,imx6ul-ecspi";
    reg = <0x30820000 0x10000>;
    interrupts = <GIC_SPI 31 IRQ_TYPE_LEVEL_HIGH>;
    clocks = <&clk IMX8MQ_CLK_ECSPI1>;
    clock-names = "ipg";
    status = "disabled";       // SoC 级默认关闭，板级再开
};

板级文件里打开它，并挂一片 CAN 控制器：

dts
&ecspi1 {
    status = "okay";
    pinctrl-0 = <&pinctrl_spi1>;
    cs-gpios = <&gpio5 9 GPIO_ACTIVE_LOW>;
    fsl,spi-num-chipselects = <1>;

    mcp2518fd@0 {
        compatible = "microchip,mcp2518fd";
        reg = <0>;                       // 片选 0，因为 #size-cells = 0 只写地址
        spi-max-frequency = <20000000>;
    };
};

SPI 的片选既可以走控制器硬件片选，也可以像上面这样用 cs-gpios 交给 GPIO 子系统。用户态想直接收发，从设备 compatible 写 "rohm,dh2228fv" 即可命中内核现成的 spidev 驱动。

九、踩坑清单 #

现象 原因
内核起来就 panic，无任何串口输出 dtb 加载地址压到了内核页表/镜像
unrecognized device tree list 根节点 compatible 与任何 DT_MACHINE_START 的 dt_compat 都对不上
驱动 probe 不进来 of_device_id 表漏了哨兵项；或 compatible 拼写/大小写不一致
could not find clock xxx 时钟 provider 节点还没注册，或被引用的 label 打错
中断号全错 #interrupt-cells 与 interrupts 的字段数不匹配
寄存器地址差了一个基址 ranges 没配或配错，忘了做地址转换
#address-cells 改了但 reg 没改 改了父节点宽度，所有子节点 reg 都要跟着改

有个反复出现的低级错误值得单独记：节点名只能有 -，不能有 _。my_led 能编译通过，但绑不上驱动，也不会报错。
