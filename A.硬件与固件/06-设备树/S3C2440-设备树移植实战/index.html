一、目标与现状 #

项目 改造前 改造后
板级信息载体 arch/arm/mach-s3c24xx/mach-mini2440.c arch/arm/boot/dts/s3c2440-smdk2440.dts
u-boot 传给内核 r2 = atags，r1 = 168（MACH_TYPE_SMDK2440） r2 = dtb 物理地址
内核选板逻辑 setup_machine_tags() 比对 machid setup_machine_fdt() 比对 compatible
中断初始化 mach-mini2440.c 里静态定义 irqchip_init() + dts 中断控制器节点

涉及三块工作：内核开 DT 支持并编译 dtb、u-boot 开 CONFIG_OF_LIBFDT、dts 按 S3C2440 实际硬件改写。

三、u-boot 侧准备 #

3.1 开启 FDT 支持 #

text
# configs/smdk2440_defconfig
CONFIG_OF_LIBFDT=y

这句会链接 lib/libfdt，编出 fdt 命令，也让 bootm 能识别第三个参数是 dtb。

3.2 u-boot.bin 体积限制 #

Mini2440 的 NAND 前 256KB 留给 u-boot（Steppingstone 只有 4KB，前 4KB 还要做搬运），加了 libfdt 之后很容易超。关掉不用的压缩算法：

c
/* include/configs/smdk2440.h */
#undef CONFIG_BZIP2
#undef CONFIG_LZO
#undef CONFIG_LZMA

编译后确认大小：

bash
ls -l u-boot.bin
# 必须 < 256KB，否则 NAND 分区放不下、或被内核分区截断

烧写用 MiniTools 走 USB 下载，或用老的 dnw。

四、dtb 该放在哪：三条硬约束 #

Mini2440 内存 0x30000000 ~ 0x34000000（64MB），内核装载在 0x30008000。dtb 地址不能随便挑：

约束 说明
不能覆盖 u-boot 自身 u-boot 跑在高地址/或已把自己搬到别处，但别赌
不能压到内核镜像 内核 0x30008000，向上 5MB 左右都在用
不能占用内核启动早期要用的内存 内核在 0x30008000 下方放了约 16KB 页表，0x30004000 ~ 0x30008000 不能碰

所以常用 0x30001000：在页表之下，且内核日志会显示

text
Loading Device Tree to 33afa000, end 33afe521 ... OK

内核自己把 dtb 挪到了高端（0x33afa000）——下载地址和最终使用地址不是一回事，前者只要不踩内存即可，后者由内核的 memblock 决定。

五、dts 改造：三个文件 #

5.2.8 里 S3C2440 的设备树文件是「半成品」——内核自带的 s3c2440.dtsi 基本是从 S3C2416 抄的，直接编出来的 dtb 起不来。需要改三处。

5.1 s3c2440.dtsi：SoC 级修正 #

问题 改法
文件里混着 S3C2416 的节点 2416 相关节点全删，只留 2440
#include 的时钟头不对 换成 <dt-bindings/clock/s3c2410.h>
cpus 节点 compatible 写成 2416 改成 "arm,arm920t"
中断控制器节点重复 s3c24xx.dtsi 里已有一个，本文件删掉重复的

5.2 s3c2440-pinctrl.dtsi：只保留真实存在的 bank #

S3C2440 只有 GPA ~ GPJ 十组，后面对 GPL/GPK 的节点全删（保留会在 probe 时访问不存在的寄存器）：

dts
/* 保留 */
gpa: gpa { gpio-controller; #gpio-cells = <2>; };
gpb: gpb { gpio-controller; #gpio-cells = <2>; };
/* ... gpc ~ gpj ... */

/* 外部中断控制器只有 gpf/gpg 两组 */
gpf: gpf {
    gpio-controller;
    #gpio-cells = <2>;
    interrupt-controller;
    #interrupt-cells = <2>;
};
gpg: gpg {
    gpio-controller;
    #gpio-cells = <2>;
    interrupt-controller;
    #interrupt-cells = <2>;
};

5.3 s3c2440-smdk2440.dts：板级补充 #

板级文件要做四件事：改 2416 为 2440、删掉不存在的控制器、补上板载晶振、加上 DM9000。

dts
#include "s3c2440.dtsi"
#include <dt-bindings/gpio/gpio.h>
#include <dt-bindings/interrupt-controller/irq.h>

/ {
    model = "SMDK2440";
    compatible = "samsung,s3c2440", "samsung,mini2440";

    memory@30000000 {
        device_type = "memory";
        reg = <0x30000000 0x4000000>;        /* 64MB */
    };

    /* 板载 12MHz 晶振：内核 clock 框架从设备树里找它 */
    clocks {
        compatible = "simple-bus";
        #address-cells = <1>;
        #size-cells = <1>;
        ranges;

        xti: xti@0 {
            compatible = "fixed-clock";
            reg = <0>;
            clock-frequency = <12000000>;
            clock-output-names = "xti";
            #clock-cells = <0>;
        };
    };

    /* DM9000 挂在 nGCS4 上 */
    srom-cs4@20000000 {
        compatible = "simple-bus";
        #address-cells = <1>;
        #size-cells = <1>;
        ranges = <0x0 0x20000000 0x08000000>;
        status = "okay";

        ethernet@0 {
            compatible = "davicom,dm9000";
            reg = <0x0 0x2 0x4 0x2>;      /* 地址口 2 字节 + 数据口 2 字节 */
            interrupt-parent = <&gpf>;
            interrupts = <7 IRQ_TYPE_EDGE_RISING>;   /* GPF7 = EINT7 */
            local-mac-address = [00 00 de ad be ef];
            status = "okay";
        };
    };
};

再打开实际存在的控制器：

dts
&rtc     { status = "okay"; };
&uart_0  { status = "okay"; pinctrl-names = "default"; pinctrl-0 = <&uart0_data>; };
&uart_1  { status = "okay"; pinctrl-names = "default"; pinctrl-0 = <&uart1_data>; };
&uart_2  { status = "okay"; pinctrl-names = "default"; pinctrl-0 = <&uart2_data>; };
&watchdog{ status = "okay"; };
&i2c_0   { status = "okay"; pinctrl-names = "default"; pinctrl-0 = <&i2c0_bus>; };
&nand0   { status = "okay"; };

&sdhci_0、&sdhci_1、&uart_3 在 2440 上不存在，要删掉，否则 probe 时会 ioremap 到空洞地址。

5.4 NAND 分区也搬进设备树 #

分区表从 mach-mini2440.c 的 mini2440_default_nand_part[] 搬到 dts：

dts
&nand0 {
    status = "okay";

    nand,tacls  = <0xa>;      /* TACLS  = 10ns  */
    nand,twrph0 = <0x19>;     /* TWRPH0 = 25ns  */
    nand,twrph1 = <0xa>;      /* TWRPH1 = 10ns  */

    partitions {
        compatible = "fixed-partitions";
        #address-cells = <1>;
        #size-cells = <1>;

        partition@0 {
            label = "u-boot";
            reg = <0x00000000 0x00040000>;
        };
        partition@40000 {
            label = "params";
            reg = <0x00040000 0x00020000>;
        };
        partition@60000 {
            label = "kernel";
            reg = <0x00060000 0x00400000>;
        };
        partition@460000 {
            label = "rootfs";
            reg = <0x00460000 0x00000000>;   /* 到末尾 */
        };
    };
};

六、fixed-clock：为什么非要写 &xti #

内核时钟框架靠 CLK_OF_DECLARE 注册 provider：

c
/* drivers/clk/clk-fixed-rate.c */
static void __init of_fixed_clk_setup(struct device_node *node)
{
    of_fixed_clk_setup(node);      /* 读 clock-frequency / clock-accuracy */
}
CLK_OF_DECLARE(fixed_clk, "fixed-clock", of_fixed_clk_setup);

它会在节点里读三个属性：clock-frequency（必需）、clock-accuracy（可选）、clock-output-names（可选），然后 clk_register_fixed_rate_with_accuracy() + of_clk_add_provider()。

如果忘了写 &xti 或名字不对，启动日志会出现：

text
_get_rate: could not find clock xti

此时定时器、串口波特率都会算错，表现为串口输出乱码或者完全没输出。这个坑在设备树移植里出现频率极高。

七、启动与验证 #

7.1 下载与启动 #

bash
# 1. dtb 下到 0x30001000
tftp 0x30001000 s3c2440-smdk2440.dtb

# 2. 内核下到 0x30008000（或直接从 nand 读）
tftp 0x30008000 uImage
nand erase.part kernel
nand write 0x30008000 kernel

# 3. 启动：bootm <kernel> <ramdisk|-> <dtb>
bootm 0x30008000 - 0x30001000

没写第三个参数就会退回 ATAGS 模式 —— 这本身也是一个有用的对照实验：同一份内核，加不加 dtb 参数，走完全不同的启动路径。

7.4 用 uboot 现场改 dtb（不改内核也能调参） #

bash
fdt addr 0x30001000
fdt print /chosen
fdt set /chosen bootargs "console=ttySAC0,115200 root=/dev/nfs rw nfsroot=192.168.0.200:/work/nfs_root/rootfs ip=192.168.0.105:192.168.0.200:192.168.0.1:255.255.255.0::eth0:off ignore_loglevel earlyprintk"
bootm 0x30008000 - 0x30001000

调试 bootargs 时这招比反复改 dts 重编译快得多。根文件系统的制作与 NFS 挂载见 根文件系统的制作 与 根文件系统的移植与调试。

八、失败现象对照表 #

现象 原因 处理
Starting kernel ... 之后完全无输出 串口没配对 / dtb 地址踩了内核内存 / xti 时钟没写 先用 ATAGS 模式启动确认内核本身没问题，再逐步加 dtb
unrecognized device tree list 根节点 compatible 与 dt_compat 不符 加 "samsung,s3c2440"
日志乱码 &xti 缺失导致 UART 时钟算错 补 fixed-clock 节点
NAND 挂不上 nand,tacls/twrph0/twrph1 缺失 按上面 5.4 补三个时序属性
网卡 probe 失败 ranges 没配、reg 写成 1 个 cell 用 simple-bus + 两段 reg
中断号对不上 gpf 的 #interrupt-cells = <2> 被写成 4 外部中断控制器只有 2 个 cell
ioremap 报 Unable to handle kernel paging request dts 里留了 2440 上没有的节点（sdhci/uart3） 删掉

九、这套改造之后的目录结构 #

text
arch/arm/boot/dts/
├── s3c24xx.dtsi            # 24xx 系列公共：中断控制器、pinctrl 骨架
├── s3c2440.dtsi            # 2440 SoC 级（本次修正）
├── s3c2440-pinctrl.dtsi    # 引脚复用定义（本次裁剪）
└── s3c2440-smdk2440.dts    # 板级（本次改 compatible/时钟/DM9000/分区）

看懂这四层的分工，再换一块 2440 的板子，只需要改最后一个文件。
