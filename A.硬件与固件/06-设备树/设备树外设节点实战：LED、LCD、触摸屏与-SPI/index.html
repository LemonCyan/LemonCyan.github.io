一、四类情形的对照 #

外设 设备树要描述什么 难点
LED（GPIO 直驱） 寄存器地址 + pinctrl 状态 无，最简单
LCD 寄存器 + 中断 + 时钟 + pinctrl + 一堆屏参 屏参怎么从 C 结构体搬过来
触摸屏 ADC 寄存器 + 中断 + 私有配置 原来放在 platform_data 里的东西没有标准属性名
SPI 控制器 控制器节点 + 从设备子节点 + 片选 #size-cells = 0、cs-gpios

二、LED：最小可用的设备树改造 #

2.1 硬件 #

Mini2440 的 LED1~LED4 接 GPB5~GPB8，低电平点亮：

操作 寄存器 位
配成输出 GPBCON 0x56000010 bit[11:10]=01（GPB5）
输出低/高 GPBDAT 0x56000014 bit5=0 亮 / 1 灭

2.2 两种写法 #

写法 A：直接把寄存器地址写进 reg（把地址当资源，驱动自己 ioremap）

dts
led {
    compatible = "mini2440-led";
    status = "okay";
    reg = <0x56000010 0x04      /* GPBCON */
           0x56000014 0x04>;     /* GPBDAT */
};

驱动侧：

c
struct resource *res;
void __iomem *gpbcon, *gpbdat;

res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
gpbcon = devm_ioremap(&pdev->dev, res->start, resource_size(res));

res = platform_get_resource(pdev, IORESOURCE_MEM, 1);
gpbdat = devm_ioremap(&pdev->dev, res->start, resource_size(res));

两段 reg → 资源数组里两条 IORESOURCE_MEM，顺序与设备树里一致。

写法 B：用 pinctrl 管引脚（推荐，驱动里不碰 CON 寄存器）

dts
/* s3c2440-pinctrl.dtsi */
myled_on: myled-on {
    samsung,pins = "gpb-5", "gpb-6", "gpb-7", "gpb-8";
    samsung,pin-function = <1>;      /* 输出 */
    samsung,pin-val = <0>;           /* 低电平 -> 亮 */
    samsung,pin-pud = <1>;           /* 上拉 */
};

myled_off: myled-off {
    samsung,pins = "gpb-5", "gpb-6", "gpb-7", "gpb-8";
    samsung,pin-function = <1>;
    samsung,pin-val = <1>;           /* 高电平 -> 灭 */
    samsung,pin-pud = <1>;
};

/* 板级 dts */
myled: myled {
    compatible = "myled";
    status = "okay";
    pinctrl-names = "default", "myled_off";
    pinctrl-0 = <&myled_on>;          /* 默认态：全亮 */
    pinctrl-1 = <&myled_off>;         /* 状态 1：全灭 */
};

驱动里切换：

c
priv->pinctrl = devm_pinctrl_get(&pdev->dev);
priv->state   = pinctrl_lookup_state(priv->pinctrl, "myled_off");
pinctrl_select_state(priv->pinctrl, priv->state);

两种写法的取舍：A 简单但把寄存器地址写死在设备树里；B 把引脚配置交给 pinctrl 子系统，可复用、可切状态。新代码用 B。

三、LCD：把 platform_data 搬进设备树 #

3.1 原来的样子 #

非设备树时代，Mini2440 的 LCD 参数放在一个 C 结构体里：

c
static struct s3c2410fb_display smdk2440_lcd_cfg __initdata = {
        .lcdcon5     = S3C2410_LCDCON5_FRM565 | S3C2410_LCDCON5_INVVLINE |
                       S3C2410_LCDCON5_INVVFRAME | S3C2410_LCDCON5_PWREN |
                       S3C2410_LCDCON5_HWSWP,
        .type        = S3C2410_LCDCON1_TFT,
        .width       = LCD_WIDTH,          /* 240 */
        .height      = LCD_HEIGHT,         /* 320 */
        .pixclock    = 156250,
        .xres        = LCD_WIDTH,
        .yres        = LCD_HEIGHT,
        .bpp         = 16,
        .left_margin = HFPD,
        .right_margin= HBPD,
        .hsync_len   = HSPW,
        .upper_margin= VBPD,
        .lower_margin= VFPD,
        .vsync_len   = VSPW,
};

static struct s3c2410fb_mach_info smdk2440_fb_info __initdata = {
        .displays       = &smdk2440_lcd_cfg,
        .num_displays   = 1,
        .default_display= 0,
        .gpccon = 0xaaaaaaaa, .gpccon_mask = 0xffffffff,
        .gpcup  = 0xffffffff, .gpcup_mask  = 0xffffffff,
        .gpdcon = 0xaaaaaaaa, .gpdcon_mask = 0xffffffff,
        .gpdup  = 0xffffffff, .gpdup_mask  = 0xffffffff,
        .lpcsel = ((0xCE6) & ~7) | 1<<1,
};

s3c_device_lcd->dev.platform_data = &smdk2440_fb_info;

里面那两个 gpccon = 0xaaaaaaaa 就是「把所有 LCD 引脚一次性配成功能 2」的暴力写法——这正是 pinctrl 要取代的东西。

3.2 设备树版本 #

引脚先交给 pinctrl：

dts
&pinctrl_0 {
    lcd_pinctrl: lcd-pinctrl {
        samsung,pins = "gpc-8", "gpc-9", "gpc-10", "gpc-11", "gpc-12",
                       "gpc-13", "gpc-14", "gpc-15",
                       "gpd-0", "gpd-1", "gpd-2", "gpd-3", "gpd-4",
                       "gpd-5", "gpd-6", "gpd-7", "gpd-8", "gpd-9",
                       "gpd-10", "gpd-11", "gpd-12", "gpd-13", "gpd-14",
                       "gpd-15",
                       "gpc-0", "gpc-1", "gpc-2", "gpc-3", "gpc-4";
        samsung,pin-function = <2>;       /* LCD 功能 */
    };

    lcd_backlight: lcd-backlight {
        samsung,pins = "gpg-4";
        samsung,pin-function = <3>;       /* GPG4 的 LCD_PWREN 功能号是 3 */
    };
};

再写帧缓冲节点：

dts
fb0: fb@4d000000 {
    compatible = "mylcd";
    reg = <0x4d000000 0x60>;                 /* LCD 控制器寄存器 */
    interrupts = <0 0 16 3>;                 /* 主中断 16 = IRQ_LCD，双边沿 */
    clocks = <&clocks HCLK_LCD>;
    clock-names = "lcd";

    pinctrl-names = "default";
    pinctrl-0 = <&lcd_pinctrl &lcd_backlight>;

    /* 屏参：名字来自 s3c2410fb.c 的 of 解析代码 */
    lcdcon5    = <0xf09>;
    type       = <0x60>;                     /* TFT */
    width      = /bits/ 16 <240>;            /* /bits/ 16 -> 占 2 字节 */
    height     = <320>;
    pixclock   = <156250>;
    xres       = <240>;
    yres       = <320>;
    bpp        = <16>;
    left_margin  = <9>;
    right_margin = <19>;
    hsync_len    = <9>;
    upper_margin = <1>;
    lower_margin = <1>;
    vsync_len    = <1>;
};

几个必须解释的点：

项 说明
reg = <0x4d000000 0x60> LCD 控制器基址 0x4D000000，寄存器区 0x60 字节
interrupts = <0 0 16 3> 主中断控制器的四 cell 格式：0=主、第二项无意义填 0、硬件号 16、触发 3=双边沿
width = /bits/ 16 <240> 16 位参数，不加 /bits/ 16 会占满 32 位 cell，解析出错位
lcdcon5 = <0xf09> 极性、BPP、字节序一个寄存器搞定，值由屏手册决定
pixclock 每像素时钟周期（ps），不是频率

3.3 驱动侧配套 #

drivers/video/fbdev/s3c2410fb.c 里加一条匹配：

c
static const struct of_device_id lcd_dt_match[] = {
    { .compatible = "mylcd", .data = (void *)0 },
    { }
};

并在 probe 里用 of_property_read_u32 把上面每个属性读进 struct s3c2410fb_display。这就是「platform_data 搬迁」的标准套路：C 结构体的每个字段，对应设备树的一个属性；结构体没了，属性留下。

LCD 驱动本身（framebuffer 分配、DMA、调色板、寄存器时序）不走设备树这套逻辑，见 D 模块的 LCD 驱动文章。

四、触摸屏：没有标准属性名时怎么办 #

4.1 硬件 #

Mini2440 用四线电阻屏（LCD-T35 / TD035STEB4），四根线接 S3C2440 的 AIN4 ~ AIN7：

线 引脚
X+ / X- AIN6 / AIN7
Y+ / Y- AIN4 / AIN5

坐标靠 ADC 采样电压换算：

x=Vdriver​Vx+​​​×widthscreen​,y=Vdriver​Vy+​​​×heightscreen​

4.2 设备树 #

触摸屏的 s3c2410_ts_mach_info 里有 delay / presc / oversampling_shift 这些纯私有字段，没有内核标准属性名，只能自定义：

dts
&adc {
    status = "okay";
};

ts@58000000 {
    compatible = "samsung,s3c2410-ts";
    reg = <0x58000000 0x20>;          /* ADC 寄存器 */
    interrupts = <0 31 0 3>;          /* IRQ_TC（触摸） */
    clocks = <&clocks HCLK_ADC>;
    clock-names = "adc";

    samsung,delay     = <10000>;      /* ADCDLY */
    samsung,presc     = <49>;         /* ADCCON 预分频 */
    samsung,oversampling-shift = <2>;
};

驱动里：

c
ts.clock = clk_get(dev, "adc");            /* 对应 clock-names = "adc" */
ts.irq_tc = platform_get_irq(pdev, 0);
ts.io = ioremap(res->start, resource_size(res));

注意原点：老代码里 probe 第一步是 info = dev_get_platdata(dev)，拿到的空指针就报 no platform data。设备树化之后这段必须改成 of_property_read_u32 系列，否则无论 dts 怎么写都进不去。

私有属性命名规范：厂商前缀,属性名，全小写，用 - 分词。samsung, 前缀能避免和内核的通用属性撞名。

五、SPI：控制器 + 从设备两层 #

5.1 控制器节点（SoC 级，通常内核已提供） #

以 i.MX8MQ 的 ECSPI1 为例：

dts
ecspi1: spi@30820000 {
    #address-cells = <1>;          /* 子节点 reg 只有片选号 */
    #size-cells = <0>;            /* 子节点没有长度 */
    compatible = "fsl,imx8mq-ecspi", "fsl,imx6ul-ecspi";
    reg = <0x30820000 0x10000>;
    interrupts = <GIC_SPI 31 IRQ_TYPE_LEVEL_HIGH>;
    clocks = <&clk IMX8MQ_CLK_ECSPI1>, <&clk IMX8MQ_CLK_ECSPI1_ROOT>;
    clock-names = "ipg", "per";
    status = "disabled";          /* SoC 级默认关闭 */
};

5.2 板级打开 + 挂从设备 #

dts
&ecspi1 {
    status = "okay";
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_spi1>;

    cs-gpios = <&gpio5 9 GPIO_ACTIVE_LOW>;   /* 用 GPIO 做片选 */
    fsl,spi-num-chipselects = <1>;

    mcp2518fd@0 {
        compatible = "microchip,mcp2518fd";
        reg = <0>;                        /* 片选 0 */
        spi-max-frequency = <20000000>;   /* 20MHz */
        interrupt-parent = <&gpio1>;
        interrupts = <3 IRQ_TYPE_EDGE_FALLING>;
    };
};

5.3 三个容易踩的点 #

点 说明
#size-cells = <0> SPI 子节点的 reg 只表示片选号，写成 <0 0> 会解析失败
子节点不会被转成 platform_device 它们由 SPI 控制器驱动创建成 spi_device（见 设备树的内核解析与启动流程 8.2）
想从用户态直接收发 从设备 compatible 写 "rohm,dh2228fv"，命中内核自带的 spidev 驱动 
dts
/* 用户态 spidev 用法 */
spidev@0 {
    compatible = "rohm,dh2228fv";     /* spidev 的白名单之一 */
    reg = <0>;
    spi-max-frequency = <1000000>;
};

六、四个例子的共同套路 #

写任何外设节点，按这五步走基本不会错：

  1. 找驱动：内核里已经有驱动吗？看它的 of_device_id 表，compatible 照抄；
  2. 找资源：驱动 probe 里 platform_get_resource / platform_get_irq / clk_get 取什么，就往设备树里补什么；
  3. 找私有参数：原来 platform_data 结构体里的字段，逐个改成属性；
  4. 引脚交给 pinctrl：不再手写 gpccon = 0xaaaaaaaa 这类暴力值；
  5. 验证：/sys/firmware/devicetree/base/<节点> 能 ls 到，/sys/bus/platform/devices 有设备，probe 有日志。

七、排查速查 #

现象 检查
节点在 /sys/firmware/devicetree/base 里有，但没有设备 缺 compatible；或父节点不是 simple-bus
设备有了，probe 报 no platform data 驱动还在用 dev_get_platdata，要改成 of 接口
屏幕花屏/偏移 pixclock、left_margin 等屏参错，或 width = /bits/ 16 少了 /bits/
触摸无反应 clock-names = "adc" 缺失；clk_get(dev, "adc") 拿不到时钟
SPI 从设备没注册 #size-cells 不是 0，或 reg 写成了范围
引脚功能不对 pinctrl 里的 pin-function 号与手册不符
