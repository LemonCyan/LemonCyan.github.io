一、为什么需要上下拉 #

数字输入引脚最怕的是悬空。引脚悬空时电位由漏电流、分布电容和周围干扰共同决定，可能停在高、低之间的任意位置，落在 CMOS 输入的亚稳态区间里：此时上下管同时微导通，既抬高功耗，又让后级电路读到随机值。

上拉/下拉电阻的作用就一个：给悬空的节点一个确定的默认电平，让"没有驱动"这件事被定义成"高"或"低"。

典型的例子是开漏/开集输出：

  • NPN 三极管的 open collector：管子只负责拉低，要输出高电平必须靠外部上拉到 VCC；
  • PNP 三极管的 open collector：管子只负责拉高，要输出低电平必须靠下拉到 GND；
  • I2C 的 SDA/SCL：所有器件都只能拉低，高电平完全由总线上的上拉电阻建立。

二、上拉电阻装在哪：片内还是片外 #

一根外设的 IRQ 线接到 CPU 中断控制器的典型连接里，上拉（下拉同理）有三种可能的位置：

  1. 集成在外设芯片内部；
  2. 集成在 CPU 一侧（中断控制器或 GPIO 控制器内部）；
  3. 芯片内都没有，需要外围电路自己加。

三者电气上等效，都是把一个电阻接到某个电源/地轨上——但"接到哪个轨"不一样，这才是真正要小心的地方。

2.1 电压域不匹配的坑 #

设想一个具体场景：外设工作在 5V 电源域，CPU 中断控制器工作在 3.3V，两者的信号线直连。

CPU 判定高电平的合法范围大约是 2.8V ~ 3.3V。如果高电平是外设内部上拉到 5V 建立的，那么 IRQ 线上的高电平就是 5V——这个电压超过 CPU 引脚的绝对最大额定值，长期工作在过压状态会导致输入级 ESD 二极管持续导通、漏电增大，甚至损坏芯片。

正确做法有两条路：

  • CPU 侧有内部上拉 → 关掉外设的内部上拉（此时外设引脚退化为 open drain，只拉低不拉高），改用 CPU 侧上拉到 3.3V；
  • CPU 侧没有内部上拉 → 只能加外部电阻，上拉到 CPU 需要的那个电压轨（3.3V），而不是外设的 5V。

一句话：上拉的目标电压由"谁来读这根线"决定，而不是由"谁驱动这根线"决定。

三、阻值怎么选：两个方向各自卡住一端 #

数字电路的分析其实很简单：看输出端的驱动能力和输入端的判决门限就够了。下面这段推导决定了上下拉电阻的取值窗口。

假设外设逻辑检测某种状态：正常时三极管 Q 截止，IRQ 输出高电平；检测到事件时 Q 导通，IRQ 被拉到低电平。

3.1 输出高电平时：电阻不能太大 #

Q 截止并不等于完全断开，仍有漏电流 Iq。同时流入 CPU 输入端的电流是 Icpu；CMOS 输入是高阻输入，Icpu 通常很小。

由基尔霍夫电流定律，流过上拉电阻 R 的电流是：

I = Iq + Icpu

R 上的压降就是 I × R。假设 I = 10μA、R = 10kΩ，压降为 10μA × 10kΩ = 100mV。也就是说外设想输出高电平时，线上实际电平是 VCC - 100mV 而不是 VCC。

压降本身不可怕，可怕的是它吃掉噪声容限：当 VCC - I·R 掉到 CPU 的高电平判决门限 VIH 以下，电路就读不到"高"了。

结论一：上拉电阻不能太大。 R 越大，同样的漏电流产生的压降越大，高电平越塌。

3.2 输出低电平时：电阻不能太小 #

理想情况下 Q 导通就是对地短路，IRQ 应该是 0V。实际导通时管子仍有导通电阻 Ron，于是低电平是：

VOL = Ron × I

其中 I 就是此刻灌入管子的电流，约等于 VCC / R。R 越小，灌入的电流越大，VOL 越高——高到超过 CPU 的低电平判决门限 VIL，这根线就会被误读成高电平。同时大电流还带来额外的功耗与管子发热。

结论二：上拉电阻不能太小。 R 越小，拉低时灌电流越大，低电平抬得越高。

3.3 于是存在一个窗口 #

两个约束方向相反，可行取值就是它们的交集：

text
        ┌──────────── 可用区间 ────────────┐
GND ────┴──────────────────────────────────┴──── VCC
     太小：拉低失败（VOL > VIL）      太大：拉不高（VOH < VIH）

工程上的常用取值：4.7kΩ / 10kΩ 覆盖了绝大多数中低速数字信号；I2C 在 100kHz 下常见 4.7kΩ，400kHz 下常降到 2.2kΩ；复位、使能这类几乎不带负载的静态信号可以用到 100kΩ 量级；而高速信号（如 SPI 时钟）则要权衡上升时间，往往依赖芯片内部弱上下拉或干脆不加上下拉。

3.4 内外都挂的时候：并联 #

如果片内、片外同时挂了上拉，且拉到同一个 VCC，那就是简单的并联：

R_eff = (R1 × R2) / (R1 + R2)

等效阻值变小，相当于把工作点往"更小"那一侧推——原本设计得刚好的电路，再加一个内部上拉可能就过头了。所以内外都挂时，要先算过并联后的等效值，再看是否还在窗口内。

如果两个上拉拉到不同的 VCC（例如一个 5V、一个 3.3V），问题就不只是阻值了：两个电源之间会通过这两个电阻形成通路，5V 轨会给 3.3V 轨灌电流。这种情况必须避免，不是"影响一下"的程度。

四、边沿触发与电平触发 #

4.1 电平触发 #

电平中断要求信号在被采样期间保持有效电平：

  • 低电平有效 → 正常时线上应为高 → 需要上拉（把空闲电平钳在高）；
  • 高电平有效 → 正常时线上应为低 → 需要下拉（把空闲电平钳在低）。

注意上下拉可能在片内，也可能在片外，效果一样。

4.2 边沿触发 #

边沿触发关心的是跳变，不是稳态电平，所以"上升沿用下拉、下降沿用上拉"这种说法并不成立。真正决定上下拉的是驱动端的输出结构：

  • 驱动端是 NPN open collector（只能拉低）→ 必须上拉，否则高电平建立不起来；
  • 驱动端是 PNP open collector（只能拉高）→ 必须下拉；
  • 驱动端是推挽输出 → 上下拉只是提供默认态与故障时的安全电平，阻值可以很松。

边沿触发还有一个容易被忽略的约束：脉冲宽度。中断控制器是采样 IRQ 线来判断边沿的，如果高电平维持时间短于采样周期，跳变可能刚好落在两次采样之间而被漏掉。这个最小宽度由中断控制器的手册规定，与外设无关；外设能保证的高电平宽度则要查外设手册。两边都要满足，边沿才不会丢。

4.3 双沿触发 #

同时支持上升沿和下降沿的中断控制器是存在的——例如 PXA270 的中断控制器可以配置成双沿触发，检测到任一方向的跳变就产生一次 GPIO 中断。

但双电平触发（同时把高电平和低电平都当作有效）逻辑上不成立：这样信号永远处于"有效"状态。要用一个引脚表达两种硬件状态，只能是"正常时高阻、事件 A 拉高、事件 B 拉低"这种约定，实际产品里很少见。

双沿触发对软件是有好处的：按键、编码器这类需要同时捕获按下与松开的场景，硬件直接给出两个沿，软件就不必再做去抖与状态机。

五、常见问题速查 #

Q1：片内已经有上拉，外面再加一个会怎样？ 拉到同一个 VCC 时只是并联，等效阻值变小（见 3.4），要重新校验是否还在窗口内。拉到不同 VCC 时会在两个电源轨之间形成直流通路，必须避免。

Q2：片内已经有下拉，外面再加一个会怎样？ 同样是并联。等效下拉变小，意味着外部驱动要灌入更多电流才能把电平拉高；驱动能力弱的输出可能就"拉不起来"了。

Q3：所有输入脚都该加上下拉吗？ 不是。推挽输出驱动的信号不需要，多余的上下拉只会增加驱动负担与功耗。真正需要的是：开漏/开集总线、可能悬空的输入、复位与使能这类必须定义默认态的信号、以及插拔连接器上会短暂浮空的引脚。

Q4：能用软件打开芯片内部上下拉代替外部电阻吗？ 多数 SoC 的 GPIO 都支持软件配置内部上拉/下拉，阻值通常在几十 kΩ 量级，适合做"默认态"和"防悬空"。但它替代不了外部电阻的两件事：驱动电流（内部弱上拉带不动 I2C 这类总线）和目标电压选择（内部上拉只能拉到芯片自己的 IO 电压，跨电压域时必须用外部电阻上拉到接收端需要的轨）。

Q5：为什么同一块板子上，有的信号 4.7k 有的 10k 有的 100k？ 因为每个信号的约束不同：总线速率决定上升时间要求（越快阻值越小），扇出与负载电容决定上升沿能不能拉起来，功耗预算决定静态电流上限，而开漏器件的灌电流能力决定下限。没有一个通用阻值，只有针对每根线算出来的窗口。

六、小结 #

  1. 上下拉的本质是给悬空节点一个确定电平，主要服务开漏/开集输出与可能有默认态要求的输入；
  2. 拉到哪个电压由接收端决定，跨电压域时片内上拉往往是错的；
  3. 阻值受两端夹逼：太大则高电平塌到 VIH 以下，太小则低电平抬到 VIL 以上，可行值是一个窗口而不是一个点；
  4. 内外同时挂就是并联，同轨要重算等效值，异轨会形成电源间通路；
  5. 边沿触发看驱动结构，电平触发看有效电平，另外别忘了采样带来的最小脉宽要求。
