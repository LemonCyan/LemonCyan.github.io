1. ARM 和 x86 争的是什么 #

ARM 基于 RISC，PC 里的 x86 基于 CISC。两边的分歧可以归结成一句话：把复杂度交给编译器和程序员，还是交给 CPU 内核。

CPU 给操作系统和程序提供一组预定义的操作，叫指令集（ISA）。程序依赖它做底层的事：

  • 和内存、存储、网卡这些硬件交互
  • 算术运算
  • 二进制移位一类的数据操作

2. CISC #

早期 x86 指令集很丰富，一条指令能完成一次乘法，或者把一块数据从内存的一个位置搬到另一个位置。这些动作在底层本来要拆成好几步，x86 用一条指令表达完，内部再拆成微操作执行。这类处理器叫复杂指令集计算机（CISC，Complex Instruction Set Computer）。

指令强，代价是译码电路复杂，晶体管更多，芯片面积和功耗都上去了。

3. RISC #

现实中程序只用到 CISC 提供的指令里很小一部分，于是精简指令集（RISC，Reduced Instruction Set Computer）出现了：每条指令只做一个简单动作，单条指令功耗低。复杂操作靠多条指令拼，或者干脆推给编译器。

这就把汇编程序员的活变重了，换来处理器设计变简单。x86 芯片更大、更贵、晶体管更多，换的是单条指令的表达力和高频性能；ARM 单条指令做的事少，遇到复杂循环要多跑几条，但芯片小、省电。

所以 MIPS（每秒百万条指令）不能直接拿来比这两种架构——同一件事，两边要用的指令条数本来就不一样。

4. 能耗决定了它们各占哪块地 #

RISC 最早的需求是给小型机做出性能更好、体积更小的芯片，于是引出第二个设计取舍：主频优先，还是功耗优先。

ARM 集成在 SoC 里，整个芯片的资源管理都围绕低能耗和低发热做。手机里的 ARM SoC 靠被动散热就够，不用风扇。x86 更偏高端处理速度，功耗和散热不是第一位的。

两边都有跑进超算的高性能芯片，取舍不在这。差别在限制条件：ARM 更看重尺寸、电池续航、免风扇和成本，所以主导手机、平板、树莓派；x86 在服务器、PC、笔记本里更常见，这些场景要的是即时性能和灵活性，对散热和尺寸没那么紧。

5. 总线与编址 #

这一部分和指令集无关，是 CPU 怎么找到数据的问题，放在一起容易混，单独列出来。

5.1 三种总线 #

总线 传什么 方向
地址总线（Address Bus） CPU 要读写的内存地址 单向，由 CPU 发出
数据总线（Data Bus） 读写的数据本身 双向
控制总线（Control Bus） 读写请求、状态、中断等控制信号 双向

地址总线宽度决定可寻址空间，32 位对应 4 GiB。数据总线的宽度是一次能传的数据量。控制总线没有固定宽度，跟着外设数量走。

5.2 统一编址与独立编址 #

  • 统一编址（内存映射 I/O）：CPU 用同一套地址总线寻址内存和 I/O 设备，不需要专门的 I/O 指令。代价是 I/O 寄存器占掉一部分地址空间，32 位下实际能用的内存会少于 4 GiB。
  • 独立编址（端口映射 I/O）：I/O 设备有独立的地址空间和专门指令（x86 的 in / out），地址总线全留给内存。

5.3 哈佛结构与冯·诺依曼结构 #

程序分两部分：不再改的指令代码，和运行时不断变的变量。两种结构的差别就是这两部分放哪。

  • 哈佛结构：代码和数据分开存。8051 的代码在 ROM、变量在 RAM；很多 ARM 芯片虽然都在 RAM 里，内部也用分离的指令缓存和数据缓存。程序跑飞时改不到代码区。
  • 冯·诺依曼结构：代码和数据共用一块内存，按地址排在一起。内存利用率高，不用在多个存储区之间切换；代价是代码区没保护时，跑飞的程序可能把指令也改掉。
