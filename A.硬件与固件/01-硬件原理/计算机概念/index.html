1. 冯·诺依曼机怎么跑起来 #

所有语言，Java、Python、Go、C、C++、PHP……最后都要变成二进制指令，在冯·诺依曼结构的机器上按规矩执行。

CPU 从内存取指令，译码，执行；执行时从内存取数据放进寄存器，算完再写回内存。碰到跳转指令，就取跳转目标处的指令接着跑。顺序、循环、分支这些程序结构，都是这么堆出来的。

CPU 和内存、硬盘的速度差了好几个数量级，这是冯·诺依曼结构绕不开的问题。缓存、DMA、同步异步、阻塞，一串概念都是为了让 CPU 别干等。

2. 进程和线程 #

程序要么作为独立进程跑，要么作为进程里的一个线程跑。

CPU 没有「进程」这个概念。它只知道从某个地址取指令、译码、执行，不会察觉到程序已经被换掉了，另一个进程已经抢班夺权。

每个进程有一份操作系统维护的进程控制块，存着切换时要恢复的现场。线程寄居在进程里，共享代码和数据，另外留着自己的一亩三分地：栈、寄存器、线程局部存储。

多线程把吞吐量和响应性拉上来了，代价是同步、通信、锁、死锁。

3. 虚拟内存与交换分区 #

虚拟内存给每个进程一套独立的虚拟地址，进程之间互不打扰。指令必须在物理内存里才能执行，操作系统负责把虚拟地址映射到物理地址，靠分段、分页、页表，再用 CPU 的 TLB 加速。

程序不是一次性全部装进内存的，用到哪一页才装哪一页。

物理内存不够时，操作系统把不活跃的页挪到硬盘上的交换分区（swap），腾出 RAM 给活跃进程。交换分区是硬盘上的一块空间，虚拟内存是进程看到的逻辑地址空间，两者不是一回事。换页太频繁，机器就会一直在读写盘，响应反而崩掉。

4. 网络的核心概念 #

四个词：分组交换、TCP/IP、socket、HTTP(S)。

数据被切成适合传输的小块，编上号，各自走网络路径，到目的地后重新排序拼回原样，这就是分组交换。链路空闲时别的连接也能用，带宽不浪费。

分组丢了怎么办、怎么检测、怎么重发、收到的先缓存在哪，这一串麻烦事归 TCP 管。TCP 在端系统实现，中间节点一无所知——想通这一点，就摸到分组交换和分层的门道了。

教材常把网络分成五层：应用层、传输层、网络层、链路层、物理层。TCP/IP 本身是四层模型，链路层和物理层合在一起。分层没别的，就是数据层层加包装；每过一个节点拆开某一层看一眼，再包好转发出去，直到终点。

5. Hash 和 RSA #

HTTPS 是网络安全通信的地基，Hash 和 RSA 是地基底下那层。

RSA 有一对钥匙，私钥自己藏着，公钥发出去。发消息时先用 Hash 算出摘要，再用私钥对摘要签名；收的一方用公钥验签，同时对原文重算 Hash 比对。两步都过了，才能确认消息没被改、也确实来自持私钥的人。

6. 操作系统 #

操作系统管硬件和软件资源：进程调度、内存分配、文件读写都归它。应用程序不直接碰硬件，走内核给的接口。

6.1 内核 #

内核直接和硬件打交道，负责系统调用、进程调度、内存分配。Linux 内核是多用户多任务的，用调度器给各个进程分 CPU 时间。

6.2 驱动程序 #

驱动让操作系统能跟具体设备通信，打印机、显卡各有一套。装了显卡驱动，才用得上硬件加速。

6.3 接口库 #

接口库把系统调用包了一层，开发者不用自己写陷入内核的那段代码，调 open、read 这类函数就行。

7. 嵌入式操作系统 #

嵌入式系统跑在特定硬件上，功能固定，比如智能家居、汽车电子。内核通常可裁剪，按设备需求决定留哪些模块。可靠性和实时性要求比通用系统高，医疗设备尤其如此。

8. 文件系统 #

文件系统负责把块设备上的数据组织成目录和文件，提供创建、读、写、删除和按路径访问的能力。具体格式见 文件系统.md。

9. Windows 和 Linux 的路径差别 #

  • Windows 按分区组织目录，C:\、D:\ 各有自己的树，路径像 C:\Documents\MyFile.txt。
  • Linux 把所有分区和设备挂到一棵以 / 为根的树上。附加硬盘挂到 /mnt 后，路径就是 /mnt/external_drive/MyFile.txt。

10. 硬盘分区 #

一个物理盘切成多个逻辑单元，MBR 分区表下最多四个主分区：

  1. 主分区：可直接用于启动。
  2. 扩展分区：一种特殊的主分区，本身不存数据，用来装逻辑分区。
  3. 逻辑分区：建在扩展分区里，数量不受四个的限制。

GPT 没有四个主分区的限制，需要更多分区就用它。

10.1 分区格式 #

  • Windows：FAT32、NTFS。NTFS 支持权限、日志、大文件。
  • Linux：ext2 / ext3 / ext4。ext3 起带日志，ext4 是目前常见默认。
