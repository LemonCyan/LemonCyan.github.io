一、先认型号：STM32F103RCT6 #

字段 含义
STM32 ST 的 32 位 MCU 家族
F 产品子系列：F 通用、L 低功耗、H 高性能、W 无线
103 增强型（101 基本型、102 USB 基本型、105/107 互联型）
R 引脚数：T=36、C=48、R=64、V=100、Z=144、I=176
C Flash 容量：6=32K、8=64K、B=128K、C=256K、D=384K、E=512K
T 封装：T=LQFP、H=BGA、U=QFN
6 温度等级：6=-40~85℃、7=-40~105℃

所以 F103RCT6 = 通用型 + 64 脚 + 256KB Flash + LQFP + -40~85℃。

F103 系列内部框图里值得记的三块：

  • Cortex-M3 内核：最高 72MHz，带 NVIC、SysTick、MPU（部分型号）；
  • 总线矩阵：DMA 走独立总线，可以不经内核搬数据；
  • APB1 / APB2 两条外设总线：这条区分决定了所有外设的时钟开关位置——USART1/SPI1/GPIO 挂 APB2，USART2~5/SPI2/I2C/定时器挂 APB1。

二、三种启动方式：BOOT0 与 BOOT1 #

STM32 上电时会在第 4 个时钟上升沿锁存 BOOT0/BOOT1，然后决定从哪块存储取向量表。

BOOT0 BOOT1 启动区域 地址 典型用途
0 x 主 Flash 0x08000000 正常运行
1 0 系统存储器 0x1FFFF000 ISP 串口下载（厂商固化 BootLoader）
1 1 内置 SRAM 0x20000000 调试小代码，掉电即失

注意主 Flash 的地址是 0x08000000，不是 0x00000000。硬件做了地址重映射，物理上取 0x00000000 时实际访问的是 0x08000000；但向量表里的地址、链接地址、烧录地址都用 0x08000000。

三、下载与调试：三种工具链及其坑 #

3.1 串口 ISP（最便宜） #

典型电路是 CH340G/USB-TTL，关键在 DTR# 与 RTS# 两根控制线：

工具 DTR# RTS#
mcuisp 低电平复位 高电平进 BootLoader

坑在两点：

  1. 软件里的勾选项与硬件电平是相反的。板子上 DTR# 接了复位、RTS# 接了 BOOT0，但软件里的「DTR 低电平复位 / RTS 高电平进 BootLoader」勾选逻辑与直觉相反，勾错了就连接不上。
  2. 波特率不要贪高。115200 是稳的，再高容易失败，尤其是用 CH340 的廉价板。

下载完成后必须把 BOOT0 拨回 0 再复位，否则跑到系统存储器里去了，表现为「程序烧进去了但不执行」。

3.2 JLink / ST-Link（最常用） #

JLink 的设置里有两项必须改：接口选 SW（不是 JTAG）、速率降到 5MHz（默认太高，杜邦线一长就连不上）。下载选项卡勾上 Reset and Run，否则烧完只是停在那儿。

3.3 一个共同的坑：BOOT0 忘了拨 #

「烧录成功但运行没反应」的第一嫌疑永远是 BOOT0。第二嫌疑才是时钟配置错（见第六节）。

四、GPIO：结构体指针与位带 #

4.1 结构体映射 #

STM32 的寄存器访问靠的是「结构体基地址 + 偏移」，ST 官方头文件已经把这一层封好了：

c
typedef struct
{
    __IO uint32_t CRL;      /* 0x00 端口配置低寄存器  */
    __IO uint32_t CRH;      /* 0x04 端口配置高寄存器  */
    __IO uint32_t IDR;      /* 0x08 输入数据寄存器    */
    __IO uint32_t ODR;      /* 0x0C 输出数据寄存器    */
    __IO uint32_t BSRR;     /* 0x10 位设置/清除       */
    __IO uint32_t BRR;      /* 0x14 位清除            */
    __IO uint32_t LCKR;     /* 0x18 配置锁定          */
} GPIO_TypeDef;

#define GPIOA  ((GPIO_TypeDef *) 0x40010800)
#define GPIOB  ((GPIO_TypeDef *) 0x40010C00)
#define GPIOC  ((GPIO_TypeDef *) 0x40011000)

__IO 是 volatile 的宏，绝对不能省——省了之后编译器会把连续两次写同一寄存器优化掉，现象是「LED 只闪一下」。

4.2 时钟一定要先开 #

F103 上任何外设在使用前都必须开时钟，而 GPIO 全挂在 APB2：

c
RCC->APB2ENR |= 1 << (portx + 2);
/* GPIOA: 1<<2, GPIOB: 1<<3, GPIOC: 1<<4 ... */

忘了这一句的现象是「代码完全正确但引脚没反应」。这是从 8 位机转过来的第一道坎（51 单片机引脚不需要开时钟）。

4.3 引脚配置的四个字段 #

每个引脚在 CRL/CRH 里占 4 位：CNF[1:0] + MODE[1:0]。八种组合对应八种模式：

MODE CNF 模式 典型用途
00 00 模拟输入 ADC
00 01 浮空输入 按键（外部上拉）
00 10 上拉/下拉输入 按键（用内部电阻）
00 11 保留 —
01/10/11 00 通用推挽输出 LED
01/10/11 01 通用开漏输出 I2C
01/10/11 10 复用推挽输出 USART TX、SPI SCK/MOSI
01/10/11 11 复用开漏输出 I2C 复用

输出模式下 MODE 表示速度：01 10MHz、10 2MHz、11 50MHz。

4.4 上拉与下拉：一个藏在 ODR 里的坑 #

配置成「上拉/下拉输入」（CNF=10）时，方向由 ODR 决定：

ODR 效果
1 上拉
0 下拉

所以库里的 GPI_UP 与 GPI_DOWN 宏数值是相同的（都是 0x08），上下拉靠「先设 ODR 再配 CNF」区分。这是 F1 库最反直觉的地方之一，很多人以为设了 GPI_DOWN 就是下拉，结果 ODR 是 1，实际还是上拉。

4.5 点亮 LED #

Mini板典型接线：LED1=PA8、LED2=PD2，都是低电平点亮（阳极接 VCC，阴极接引脚）。

c
void LED_Init(void)
{
    RCC->APB2ENR |= 1<<2;         /* GPIOA 时钟 */
    RCC->APB2ENR |= 1<<5;         /* GPIOD 时钟 */

    /* PA8 推挽输出 50MHz */
    GPIOA->CRH &= 0xFFFFFFF0;
    GPIOA->CRH |= 0x00000003;

    /* PD2 推挽输出 50MHz；PD2 在 CRL 的 [11:8] 位 */
    GPIOD->CRL &= 0xFFFFF0FF;
    GPIOD->CRL |= 0x00000300;

    GPIOA->BSRR = 1<<8;           /* 置高 = 熄灭 */
    GPIOD->BSRR = 1<<2;
}

BSRR 是原子操作：写高 16 位置 1、写低 16 位清 0，比 ODR |= x / ODR &= ~x 少一次读改写，也避免中断打断时的竞争。

4.6 位带：把位当字节用 #

Cortex-M3 支持把 SRAM/外设区的每一位映射成别名区的一个字：

text
别名地址 = 别名区基址 + (目标地址 - 目标区基址) × 32 + 位号 × 4

两个别名区：

目标区 基址 别名区基址
SRAM 0x20000000 0x22000000
外设 0x40000000 0x42000000 
c
#define BITBAND(addr, bitnum) ((addr & 0xF0000000) + 0x20000000 \
                             + ((addr & 0xFFFFF) << 5) + ((bitnum) << 2))

#define MEM_ADDR(addr)  *((volatile unsigned long *)(addr))

好处是「一位 = 一个 int」，读写都是一条指令，天然原子。代价是别名区不能用位带再套位带，也不支持非 32 位对齐访问。

五、启动文件与内存布局 #

5.1 汇编启动文件做了什么 #

armasm
Stack_Size      EQU     0x00000400      ; 1KB 栈
Heap_Size       EQU     0x00000200      ; 512B 堆

                AREA    STACK, NOINIT, READWRITE, ALIGN=3
Stack_Mem       SPACE   Stack_Size
__initial_sp                            ; 栈顶符号

                PRESERVE8
                THUMB
                AREA    RESET, DATA, READONLY
                EXPORT  __Vectors
__Vectors       DCD     __initial_sp    ; 第 0 项：栈顶
                DCD     Reset_Handler   ; 第 1 项：复位
                DCD     NMI_Handler
                DCD     HardFault_Handler
                ; ... 逐项列出所有中断向量

三个要点：

  1. 向量表第 0 项放栈顶地址，不是函数地址。复位时硬件从 [0] 装载 SP、从 [4] 装载 PC。所以栈顶必须是 RAM 的最高地址（栈向下生长）。
  2. __initial_sp 的值要看 map 文件确认。原文工程里实测是 __initial_sp 0x20001d60，也就是说 RAM 只用了不到 8KB——这对判断「栈会不会溢出」很有用。
  3. __heap_base / __heap_limit 之间是向上生长的堆，被 malloc 使用；__initial_sp 下面是向下生长的栈。两者对撞就是 HardFault。

5.2 复位入口 #

armasm
Reset_Handler   PROC
                EXPORT  Reset_Handler             [WEAK]
                IMPORT  __main
                LDR     R0, =__main
                BX      R0
                ENDP

注意是 __main（C 库的入口，负责初始化 .data 段、清零 .bss 段），不是 main。直接跳 main 会导致全局变量初值全错——这是自己写启动文件时最常见的错误。

5.3 VTOR：向量表重定位 #

text
SCB->VTOR = 0x08000000;   /* 默认值，可省 */

VTOR 的值必须 0x80 对齐（低 7 位保留）。做 Bootloader + APP 双工程时，APP 的 VTOR 必须指向它自己的起始地址，否则中断全跑飞。

六、系统时钟：从 8MHz 到 72MHz #

6.1 四个时钟源 #

时钟源 频率 特点
HSI 8MHz 内部 RC，上电默认，精度差
HSE 4~16MHz（板载多为 8MHz） 外部晶振，精度高
LSI 约 40kHz 内部，供 IWDG 使用
LSE 32.768kHz 外部，供 RTC 使用

PLL 的倍频范围是 ×2 ~ ×16，输出上限 72MHz。

6.2 标准 72MHz 配置 #

c
void RCC_Init(void)
{
    RCC->CR |= 1<<16;                 /* 开 HSE */
    while (!(RCC->CR & (1<<17)));     /* 等 HSERDY */

    RCC->CFGR = 0x00000400;           /* APB1 = HCLK/2（上限 36MHz） */
    RCC->CFGR |= (7<<18);             /* PLL 倍频 ×9：8MHz × 9 = 72MHz */
    RCC->CFGR |= 1<<16;               /* PLL 时钟源 = HSE */

    RCC->CR |= 1<<24;                 /* 开 PLL */
    while (!(RCC->CR & (1<<25)));     /* 等 PLLRDY */

    FLASH->ACR |= 0x32;               /* 2 个等待周期（72MHz 必须） */

    RCC->CFGR |= 2;                   /* 系统时钟 = PLL */
    while ((RCC->CFGR & 0x0C) != 0x08);  /* 等 SWS 变成 PLL */
}

三条硬约束：

  1. APB1 上限 36MHz，所以必须 /2（0x400 的 bit10:8 = 100）；APB2 上限 72MHz，不分频。
  2. 72MHz 必须配 2 个 Flash 等待周期（LATENCY=010），少配会随机取指错误。
  3. HSE_VALUE 宏必须等于板上晶振实际频率。原文有个真实事故：12MHz 的板子用了默认的 8MHz 宏，算出来 12×9=108MHz，串口全乱码，查了很久才发现是宏没改。

6.3 这条约束会传导到串口 #

因为波特率 = 时钟 / 分频，时钟错了波特率就错，现象是「收到的全是乱码」。所以调试串口乱码时，第一件事不是查串口寄存器，而是查时钟树配得对不对。

6.4 顺带看一眼 F7：三个 PLL #

F1 只有一个 PLL，而 F7（比如 F767）有 5 个时钟源、3 个 PLL，这个结构在高端型号上是通用的：

时钟源 频率 用途
HSI 16MHz（RC） 系统时钟或 PLL 输入；分频后还能做 HDMI-CEC 时钟
HSE 4~26MHz（板载 25MHz） 系统时钟或 PLL 输入；2~31 分频后也可作 RTC 时钟
LSI 约 32kHz（RC） IWDG、LPTimer、RTC
LSE 32.768kHz RTC
PLL 见下 倍频输出

三个 PLL 的分工：

PLL 输出 用途
主 PLL PLLP 最高 216MHz；PLLQ 48MHz 系统时钟；USB OTG FS / RNG / SDMMC
PLLI2S N=50~432，R=2~7，Q=2~15 高精度 I2S / SAI / SPDIFRX 音频时钟
PLLSAI N=50~432，Q=2~15，R=2~7 SAI、LCD-TFT 时钟，也可供 48MHz 给 USB/SDMMC/RNG

看出规律没有：主 PLL 管系统和 USB，PLLI2S 管音频，PLLSAI 管显示和备用 48MHz。F1 的时代一个 PLL 就够，是因为外设少；一旦要同时跑 USB、音频和 LCD，就必须拆成多个独立可调的 PLL，否则「动一个频率就崩另一个外设」。

F4/F7 上更麻烦的一点是：改 PLL 必须先切回 HSI（不能直接从 HSE 切到新的 PLL 配置），否则会死机。F1 也是同样的规矩。

七、USART 串口 #

7.1 挂哪条总线 #

外设 总线 时钟上限
USART1 APB2 72MHz
USART2~5 APB1 36MHz

这个区分直接影响 BRR 的计算：同样 9600 波特率，USART1 和 USART2 算出来的 BRR 值不一样。

7.2 BRR：带小数分频 #

F103 的 BRR 是「整数 + 16 分之几」的结构：

text
BRR[15:4]  = USARTDIV 的整数部分（Mantissa）
BRR[3:0]   = USARTDIV 的小数部分（Fraction），单位 1/16
ext{USARTDIV} = rac{f_{PCLK}}{16 imes ext{波特率}}

72MHz、9600 时：

USARTDIV = rac{72000000}{16 imes 9600} = 468.75

于是 Mantissa = 468 = 0x1D4，Fraction = round(0.75 × 16) = 12，BRR = 0x1D4C。

原文这里有一处笔误：写成了 16 × 0.15。小数部分要乘 16 不是乘 0.15，按原写法算出来的 BRR 是错的。

7.3 引脚与初始化 #

c
void USART1_Init(u32 pclk2, u32 bound)
{
    RCC->APB2ENR |= 1<<2;             /* GPIOA */
    RCC->APB2ENR |= 1<<14;            /* USART1 */

    /* PA9 = TX（复用推挽输出 50MHz，CNF=10 MODE=11） */
    GPIOA->CRH &= 0xFFFFF0FF;
    GPIOA->CRH |= 0x00000B00;
    /* PA10 = RX（上拉输入，CNF=10 MODE=00） */
    GPIOA->CRH &= 0xFFFF0FFF;
    GPIOA->CRH |= 0x00008000;

    USART1->BRR = (pclk2 * 10 / bound + 5) / 10;   /* 四舍五入的整数算法 */

    USART1->CR1 |= 1<<13;             /* UE  使能 */
    USART1->CR1 |= 1<<3;              /* TE  发送 */
    USART1->CR1 |= 1<<2;              /* RE  接收 */
    USART1->CR1 |= 1<<5;              /* RXNEIE 接收中断 */

    NVIC_EnableIRQ(USART1_IRQn);
}

(pclk*10/bound + 5)/10 是个巧妙的整数四舍五入：先乘 10 再除以 10，避免浮点。

7.4 内部寄存器速查 #

寄存器 关键位
SR bit7 TXE 发送数据寄存器空；bit6 TC 发送完成；bit5 RXNE 收到数据
CR1 bit2 RE、bit3 TE、bit5 RXNEIE、bit12 M（字长）、bit13 UE
BRR 见上

TXE 与 TC 的区别经常被混：TXE 表示「可以写下一个字节了」，TC 表示「最后一个字节真的从移位器出去了」。要保证发完再关电源/切 485 方向，等的必须是 TC。

7.5 printf 重定向 #

F1 上用 Keil 时，光实现 fputc 不够，还要四件套，否则链接时报 __use_no_semihosting 相关错误：

c
#pragma import(__use_no_semihosting)

struct __FILE
{
    int handle;
};

FILE __stdout;

int _sys_exit(int x)
{
    x = x;
    return 0;
}

int fputc(int ch, FILE *f)
{
    while ((USART1->SR & (1<<7)) == 0);   /* 等 TXE */
    USART1->DR = (u8)ch;
    return ch;
}

_sys_exit 里那句 x = x; 看着莫名其妙，其实是防编译器「未使用参数」警告——删了会报 warning，留着无害。

7.6 接收中断与状态机 #

和 2440 用的是同一套 16 位状态字思路：

text
bit15      接收完成
bit14      已收到 0x0D
bit13~0    有效字节数

中断里必须先读 SR 再读 DR（读 SR 清 RXNE，读 DR 取数据，两个动作是连在一起的），顺序反了会丢数据。

八、NVIC：Cortex-M 的中断控制器 #

8.1 与 2440 的本质差别 #

维度 S3C2440（ARM920T） STM32（Cortex-M3）
向量表 固定在 0x00/0x18 可重定位（VTOR）
IRQ 入口 全部进 0x18，软件查 INTOFFSET 每个中断有自己的入口
嵌套 要手写汇编切模式 硬件自动压栈/出栈
优先级 6 组 × 6 REQ 轮换 16 级抢占 + 16 级子优先级

Cortex-M 上「进中断」不用你写一行汇编：硬件自动把 R0-R3、R12、LR、PC、xPSR 压栈，出中断时自动恢复。这就是为什么 STM32 的中断服务函数可以写成普通 C 函数。

8.2 数量与分组 #

Cortex-M3 定义了 256 个中断位置（16 个内核异常 + 240 个外部中断），但 F103 做了裁剪：10 个内核异常 + 60 个外部中断。所以 STM32F103 的 IRQn 编号最大到 67。

抢占优先级与子优先级的位数由 AIRCR 的 PRIGROUP[10:8] 决定：

分组 抢占位数 子优先级位数 抢占级数
0 0 4 1
1 1 3 2
2 2 2 4
3 3 1 8
4 4 0 16

两条铁律：

  1. 写 AIRCR 必须带 0x05FA 密钥：SCB->AIRCR = (0x05FA<<16) | (group<<8) | ...，不带就写不进去。
  2. 全系统必须用同一个分组。库里默认分组 2，如果某个模块自己改了分组，整个系统的优先级关系都会错乱。

8.3 优先级编码的坑 #

库里 NVIC_EncodePriority 的实际算法是：

c
temp = pre << (4 - group) | sub & (0x0F >> group);

注意后半段的 & (0x0F >> group)：子优先级要先截断再拼接。如果子优先级填了超出位宽的值，不截断就会溢出到抢占位里，导致两个本该同级的优先级变成上下级。

8.4 设置优先级的三行 #

c
NVIC->ISER[ch/32] |= 1 << (ch%32);          /* 使能：位图分 8 个 32 位寄存器 */
NVIC->IP[ch] = prio << 4;                   /* 优先级只放高 4 位！ */

IP[ch] 的低 4 位无效。写 IP[ch] = 0x05 等于 0x00（高 4 位全是 0，最高优先级）。这是新手最常犯的错：明明想设中等优先级，结果成了最高。

九、EXTI：外部中断 #

9.1 19 条线，不是 19 个引脚 #

F103 有 19 条 EXTI 线（F107 是 20 条）：

线 来源
EXTI0~15 对应 Px0~Px15，同一编号的引脚只能选一个端口
EXTI16 PVD 电源检测
EXTI17 RTC 闹钟
EXTI18 USB 唤醒
EXTI19 以太网唤醒（互联型）

关键在于：PA0 和 PB0 共用 EXTI0，不能同时用。选哪个端口由 AFIO 的 EXTICR 决定。

9.2 端口选择：必须先清再写 #

c
/* PC5 → EXTI5 */
AFIO->EXTICR[1] &= ~(0x0F << 4);    /* 先清掉 PC5 对应的 4 位 */
AFIO->EXTICR[1] |=  (0x02 << 4);    /* 2 = 端口 C */

EXTICR[1] 管的是 EXTI4~7，每 4 位一个。PC5 在 [7:4] 位置。

必须「先清再写」：直接 |= 会在原本已经选好别的端口时留下脏位，结果是 0x02 | 0x01 = 0x03——一个不存在的端口编号，现象是中断永远不进。

9.3 三件套配置 #

c
void EXTI5_Init(void)
{
    /* 1. GPIO 输入 */
    RCC->APB2ENR |= 1<<4;                /* GPIOC */
    GPIOC->CRL &= 0xFF0FFFFF;
    GPIOC->CRL |= 0x00800000;            /* 上拉输入 */

    /* 2. AFIO 映射 */
    RCC->APB2ENR |= 1<<0;                /* AFIO 时钟！漏了就配不上 */
    AFIO->EXTICR[1] &= ~(0x0F<<4);
    AFIO->EXTICR[1] |=  (0x02<<4);

    /* 3. EXTI 触发方式 + 使能 */
    EXTI->IMR  |= 1<<5;                  /* 不屏蔽 */
    EXTI->FTSR |= 1<<5;                  /* 下降沿触发 */
    EXTI->RTSR &= ~(1<<5);               /* 不要上升沿 */

    /* 4. NVIC */
    NVIC->ISER[5/32] |= 1<<(5%32);       /* EXTI5 中断号 = 30 */
}

AFIO 时钟那一行是最容易漏的。AFIO 挂在 APB2 的 bit0，忘了开的话 EXTICR 写了也不生效，现象是「引脚电平变了但中断不进」。

9.4 清标志：写 1 清（和定时器相反） #

c
EXTI->PR = 1<<5;    /* 写 1 清，写 0 无效 */

这是 EXTI 的规则。但注意下一节的定时器 SR 是「写 0 清」，两者正好相反。混着写的结果是「中断清不掉，无限触发」。

9.5 共享向量 #

EXTI0~4 各有一个独立中断；EXTI5~9 共享 EXTI9_5_IRQn，EXTI10~15 共享 EXTI15_10_IRQn。共享向量里必须逐位判断：

c
void EXTI9_5_IRQHandler(void)
{
    if (EXTI->PR & (1<<5)) { EXTI->PR = 1<<5; /* 处理 5 */ }
    if (EXTI->PR & (1<<9)) { EXTI->PR = 1<<9; /* 处理 9 */ }
}

十、基础定时器：计数、溢出与延时 #

10.1 三档定时器 #

类型 型号 特点
高级 TIM1、TIM8 带刹车、死区、互补输出，可输出 3 对 PWM
通用 TIM2~TIM5 4 个独立通道，PWM/捕获/编码器
基本 TIM6、TIM7 只有计数和更新中断，用来做时基

三种计数模式：向上（0→ARR）、向下（ARR→0）、中央对齐（0→ARR→0，用于电机）。

10.2 频率公式 #

ext{Freq} = rac{T_{clk}}{(PSC+1) imes (ARR+1)}

这里有个必须知道的隐藏倍频：

APB 预分频 定时器时钟
= 1 = PCLK
≠ 1 = 2 × PCLK

因为定时器挂在 APB1 上，而 APB1 最高只能 36MHz，所以系统 72MHz 时 APB1 必然分频 2，此时定时器时钟自动变成 72MHz（不是 36MHz）。算 ARR 时用 36MHz 会算出一半的频率——这是 F1 上最经典的算错。

10.3 定时中断配置 #

c
void TIM3_Init(u16 arr, u16 psc)
{
    RCC->APB1ENR |= 1<<1;             /* TIM3 时钟 */

    TIM3->ARR = arr;                  /* 自动重装载值 */
    TIM3->PSC = psc;                  /* 预分频 */
    TIM3->DIER |= 1<<0;               /* 更新中断使能 */
    TIM3->CR1  |= 1<<0;               /* 启动计数 */

    NVIC->ISER[1] |= 1<<(29%32);      /* TIM3_IRQn = 29 */
}

延时算法：要 500ms，72MHz 下取 PSC=7199（得 10kHz），ARR=4999（得 500ms）：

arr = rac{t(ms) imes f_{clk}}{1000 imes (PSC+1)} - 1

10.4 那个写 0 清的标志 #

c
void TIM3_IRQHandler(void)
{
    if (TIM3->SR & 0x01)
    {
        /* 业务代码 */
    }
    TIM3->SR = 0;          /* 写 0 清（写 1 无效！） */
}

和上一节 EXTI 的「写 1 清」正好相反。两个都记不住的话，记这句：EXTI 写 1 清，定时器写 0 清。

10.5 DIER 别用 = 赋值 #

text
TIM1->DIER = 1<<0;       /* 错：顺手把 DMA 中断使能位也清了 */
TIM1->DIER |= 1<<0;      /* 对 */

同理，TIM1/TIM8 的更新中断向量是 TIM1_UP_IRQn，不是 TIM1_IRQn——高级定时器把更新中断和捕获中断拆成了两个向量，而 TIM2~5 只有一个。写错向量名编译能过，但中断永远不进。

PWM、输入捕获、编码器测速、RTC 这些内容在 STM32 定时器进阶与传感。

十一、用 GPIO 模拟 SPI：驱动 SSD1306 OLED #

11.1 为什么要「软件 SPI」 #

硬件 SPI 需要把引脚配成复用功能，而很多小项目引脚已经很紧张了——比如要同时留出串口、SWD、几个按键。这时可以用任意四个普通 GPIO 手动翻转电平来模拟 SPI 时序。代价是速度慢（实测约 1.67MHz，硬件 SPI 可到 18MHz），但驱动一块 128×64 的 OLED 完全够用。

本文的例子引脚分配（全部在 GPIOC 上，避开已被占用的 PA/PB）：

信号 引脚 作用
CS PC0 片选，低有效
DC PC1 数据/命令选择：0 命令，1 数据
RES PC2 复位，低有效
SDA PC3 数据线（MOSI）
SCL PC4 时钟线

11.2 软件 SPI 的三个动作 #

SPI 模式 0（CPOL=0, CPHA=0）的时序极其简单：时钟空闲为低，上升沿采样。所以发送一位就是「摆好数据 → 拉高 → 拉低」：

c
#define OLED_SCL_SET()   GPIOC->BSRR = 1<<4
#define OLED_SCL_CLR()   GPIOC->BRR  = 1<<4
#define OLED_SDA_SET()   GPIOC->BSRR = 1<<3
#define OLED_SDA_CLR()   GPIOC->BRR  = 1<<3

void OLED_WR_Byte(u8 dat, u8 mode)
{
    if (mode) OLED_DC_SET(); else OLED_DC_CLR();
    OLED_CS_CLR();

    for (u8 i = 0; i < 8; i++)
    {
        if (dat & 0x80) OLED_SDA_SET();
        else            OLED_SDA_CLR();
        dat <<= 1;
        OLED_SCL_SET();          /* 上升沿，从机采样 */
        OLED_SCL_CLR();
    }

    OLED_CS_SET();
    OLED_DC_SET();               /* 恢复默认：数据模式 */
}

用 BSRR/BRR 而不是 ODR |= / &=：前者是单次写、原子操作，后者是读-改-写三条指令且可能被中断打断。软 SPI 对时序敏感，多几条指令就可能超出 SSD1306 的时序要求。

11.3 SSD1306 的两种寻址模式 #

| 模式 | 命令 | 用法 | ||---|---|---| | 页寻址 | 0x20, 0x02（默认） | 必须手动设页和列，写完一页要重设 | | 水平寻址 | 0x20, 0x00 | 写完自动 +1，跨页自动换行，适合整屏刷新 |

页寻址的关键三条命令：

text
0xB0 + page          设定页地址（page = 0~7，每页 8 行像素）
0x10 | (x >> 4)       设定列地址高 4 位
0x00 | (x & 0x0F)     设定列地址低 4 位

原文这里有个 bug：列低 4 位写成了 0x01 | (x & 0x0F)，正确是 0x00 | (x & 0x0F)。0x01 会让列地址整体偏移 1，现象是所有显示内容左移一列、右边多出一列竖线。这类错误在小屏上不太显眼，很难第一时间发现。

11.4 初始化序列 #

c
void OLED_Init(void)
{
    OLED_RST_CLR();
    delay_ms(100);
    OLED_RST_SET();

    OLED_WR_Byte(0xAE, 0);   /* 关显示 */
    OLED_WR_Byte(0x00, 0);   /* 列低地址 */
    OLED_WR_Byte(0x10, 0);   /* 列高地址 */
    OLED_WR_Byte(0x40, 0);   /* 起始行 = 0 */
    OLED_WR_Byte(0x81, 0);   /* 对比度设置 */
    OLED_WR_Byte(0xCF, 0);   /*   对比度值 */
    OLED_WR_Byte(0xA1, 0);   /* 段重映射（左右镜像） */
    OLED_WR_Byte(0xC8, 0);   /* 行扫描方向（上下镜像） */
    OLED_WR_Byte(0xA6, 0);   /* 正常显示（0xA7 = 反色） */
    OLED_WR_Byte(0x20, 0);   /* 寻址模式 */
    OLED_WR_Byte(0x02, 0);   /*   页寻址 */
    OLED_WR_Byte(0x8D, 0);   /* 电荷泵设置 */
    OLED_WR_Byte(0x14, 0);   /*   使能电荷泵（必须！） */
    OLED_WR_Byte(0xA4, 0);   /* 输出跟随 RAM 内容 */
    OLED_WR_Byte(0xAF, 0);   /* 开显示 */
}

两个命令漏了会「屏全黑」：

  • 0x8D, 0x14 电荷泵使能。没有它，OLED 内部没有高压驱动像素，屏就是黑的（但数据在正常刷）。这是排查「初始化全对但屏不亮」的第一嫌疑。
  • 0xAF 开显示。很多人初始化写完就不管了，忘了最后这一步。

11.5 显存与刷屏 #

SSD1306 内部有一块 128×64 位的显存（1KB），屏幕上的每个像素对应显存里的一位。页寻址模式下，一个「页」是 8 行像素 × 128 列，所以总共 8 页。

MCU 侧通常也维护一份 1KB 的显存数组，所有绘图操作在内存里做，最后整屏 OLED_Refresh() 一次性推过去：

c
u8 OLED_GRAM[8][128];        /* 1KB，正好占满 F103 的 20KB RAM 的 5% */

void OLED_Refresh(void)
{
    for (u8 page = 0; page < 8; page++)
    {
        OLED_WR_Byte(0xB0 + page, 0);        /* 设页 */
        OLED_WR_Byte(0x10, 0);               /* 列高 = 0 */
        OLED_WR_Byte(0x00, 0);               /* 列低 = 0 */
        for (u8 col = 0; col < 128; col++)
            OLED_WR_Byte(OLED_GRAM[page][col], 1);   /* mode=1 数据 */
    }
}

为什么不在绘图函数里直接写屏：SPI 传 1KB 需要时间。软件 SPI 1.67MHz 下，1KB 约 6ms。如果每画一个点就刷一次屏，画面会明显闪烁、并且 CPU 全被占满。内存里画完一次性推，是标准做法。

11.6 字库 #

英文字符用 8×16 或 6×8 的点阵，中文用 16×16。字库就是一大块 const u8 数组，每个字节的每一位代表一个像素。取模软件（PCtoLCD2002）的常用设置是：阴码、逐列式、逆向、C51 格式。

注意：字库一定要加 const，否则它会被放进 RAM。一整套 16×16 的中文（6763 字）就是 216KB，F103 的 20KB RAM 根本放不下。加了 const 之后它进 Flash，不占 RAM。

11.7 软 SPI 的取舍 #

项 软件 SPI 硬件 SPI
速度 约 1.67MHz 可达 18MHz（PCLK/2）
引脚 任意 GPIO 必须用复用的固定引脚
CPU 占用 高（每位循环） 接近 0
代码量 十行 需要配 SPI 寄存器 + DMA
适用 小屏、低速外设、引脚紧张 高速、大量数据

十二、踩坑清单 #

  1. 忘了开外设时钟（RCC->APBxENR），代码全对但没反应。
  2. AFIO 时钟（APB2 bit0）漏开，EXTICR 配置不生效。
  3. BOOT0 没拨回 0，程序烧进去不跑。
  4. HSE_VALUE 与实际晶振不一致，串口全乱码、定时全错。
  5. BRR 小数部分算错（原文写 0.15，应为 ×16）。
  6. NVIC->IP[ch] 低 4 位无效，写小值等于写最高优先级。
  7. 没带 0x05FA 密钥写 AIRCR，分组设不进去。
  8. 全系统分组必须统一，否则优先级关系全乱。
  9. EXTICR 要先清再写，否则残留位选出不存在的端口。
  10. EXTI 写 1 清、定时器 SR 写 0 清，别混。
  11. EXTI5~9 / 10~15 是共享向量，必须逐位判断。
  12. 72MHz 必须配 2 个 Flash 等待周期。
  13. APB1 分频 ≠ 1 时定时器时钟 = 2×PCLK。
  14. 高级定时器更新中断是 TIM1_UP_IRQn。
  15. DIER 用 |= 不要用 =。
  16. __IO / volatile 不能省，否则连续写会被优化掉。
  17. 启动文件第 0 项是栈顶不是函数，复位要跳 __main 不是 main。
  18. VTOR 必须 0x80 对齐，双工程时 APP 必须自己设 VTOR。
  19. TXE 与 TC 不是一回事，切方向要等 TC。

小结 #

从 2440 转到 STM32，编程模型的变化可以概括成三句话：

  1. 不用手写向量表和启动汇编——启动文件、向量表、压栈出栈都是现成的；
  2. 但多了一层「时钟门控」——每个外设用之前都要开时钟，这是 2440 没有的概念；
  3. 寄存器组织从「散落地址」变成「结构体 + 位域」——可读性上去了，但要小心位宽（IP 的低 4 位、BRR 的小数位、DIER 的覆盖写）。
