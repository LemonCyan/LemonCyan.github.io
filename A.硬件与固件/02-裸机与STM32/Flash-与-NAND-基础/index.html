一、Flash Memory 是什么 #

Flash Memory 是一种非易失性存储器。在嵌入式系统中用于存放系统、应用和数据；在 PC 中主要用于固态硬盘和主板 BIOS；绝大部分 U 盘、SD 卡也都是用它做介质。

相比传统硬盘，Flash 质量轻、能耗低、体积小、抗震能力强，但有几个绕不开的局限：

1.1 必须先擦除再写 #

写入时只能把当前为 1 的 bit 改写为 0，无法把已经是 0 的 bit 改回 1；只有擦除操作才能把整块 bit 重新置 1。所以"覆盖写一个字节"在 Flash 上是不存在的，必须先擦掉一整块。

1.2 擦写次数有限 #

每个数据块都有擦除次数上限（十万到百万次不等），超过之后该块无法可靠存储数据，成为坏块。

延长寿命的办法在软件侧：

  • 擦写均衡（Wear Leveling）：通过分散写入、动态映射，均衡使用各数据块；
  • 坏块管理（BBM）：标识坏块，不让坏块参与数据存储。

注意坏块不只是用坏的——生产过程本身就会产生固有坏块。

1.3 读写干扰 #

受物理特性影响，读写某个单元时可能让邻近的 bit 发生位翻转。这种异常可以通过重新擦除恢复，实践中靠 ECC 等算法做错误检测与修正。

1.4 电荷泄漏 #

存储单元的电荷长期不用会慢慢泄漏，导致数据错误。时间尺度比较长，一般十年左右，且是非永久性的，重新擦除可以恢复。

二、NOR Flash 与 NAND Flash #

按存储原理不同，Flash 主要分两类。它们的差异集中在这几点：

维度 NOR Flash NAND Flash
读取速度 略快 与 NOR 相近（视接口而定）
写入速度 慢 快很多
擦除速度 慢（一次擦/写操作约 5s） 快（通常不超过 4ms）
最大擦写次数 少 多
片上执行（XIP） 支持，可直接运行代码 不支持
驱动复杂度 简单 需要 NFTL / 专用文件系统
随机读粒度 可按字节随机读 必须按块/页读
大容量成本 高、体积大 低得多、体积更小

（两者的擦除都是按块进行的。）

2.1 NOR Flash #

按与 CPU 的接口分为两类：

  • Parallel NOR Flash：接到 Host 的 SRAM/DRAM Controller 上，内容可直接映射到 CPU 地址空间，不需要拷到 RAM 就能被访问，因而支持片上执行；
  • Serial NOR Flash：成本更低，主要通过 SPI 接口与 Host 连接。

鉴于擦写慢、成本高，NOR 主要用于小容量、内容更新少的场景——PC 主板 BIOS、路由器系统存储等。

2.2 NAND Flash #

NAND 需要通过专门的 NFI（NAND Flash Interface） 与 Host 通信。

按每个存储单元能存的 bit 数分为三类：

类型 每单元位数 电压等级 特点
SLC（Single-Level Cell） 1 bit 2 级（0/1） 性能最好、寿命最长、成本最高
MLC（Multi-Level Cell） 2 bit 4 级（00/01/10/11） 折中
TLC（Triple-Level Cell） 3 bit 8 级 成本最低、性能与寿命最差

规律很清晰：单元存的 bit 越多，读写越慢、寿命越短，但成本越低。

相比 NOR，NAND 写入性能好、大容量下成本低。手机平板的 eMMC 内部、PC 的固态硬盘，介质都是 NAND。

三、Raw Flash 与 Managed Flash #

由于上面那四条局限（按块擦写、擦写次数、读写干扰、电荷泄漏），要发挥 Flash 的价值，通常需要一个特殊软件层来做坏块管理、擦写均衡、ECC、垃圾回收——这一层叫 FTL（Flash Translation Layer）。

按 FTL 所在位置，Flash 分为两类：

  • Raw Flash：FTL 或 Flash 文件系统跑在 Host 端。Host 软件复杂度高，但整体方案成本低，常用于价格敏感的嵌入式产品。通常所说的 NOR Flash 和 NAND Flash 都属于这一类。
  • Managed Flash：Flash Controller 集成在存储器件内部，对外提供标准化接口。它屏蔽了 Flash 的物理特性，Host 端软件大幅简化。eMMC、SD Card、UFS、U 盘都属于这一类。

这条分界线非常重要：它解释了为什么裸接 NAND 那么麻烦（见下一节），而用 eMMC 却像用硬盘一样简单（见《eMMC 原理与协议》）。

四、一颗具体的 NAND：K9F2G08U0C #

Mini2440 开发板用的是 256MB（2Gb）的 NAND Flash，型号 K9F2G08U0C。常见的 Flash 厂商有 Micron（镁光）、Toshiba（东芝）、Samsung（三星）、MXIC（旺宏）、dosilicon（东芯）、Winbond（华邦）、ESMT 等。

4.1 关键参数 #

  • 容量 256M，外加 8M 的冗余 oob 存储区；
  • page 大小 2K，block 大小 128K；
  • 读一个 page 时顺序读取至少 25ns/字节，随机读取不超过 40μs；
  • 写一个 page 一般 250μs；
  • 擦除一个 block 一般 2ms；
  • 封装有 TSOP 和 FBGA 两种：TSOP 引脚在侧面，FBGA 引脚封在芯片底部。有些客户为了防飞线破解数据，会指定 FBGA 封装。

型号里的数字也有含义：2G 表示容量 2Gb = 256MB，08 表示数据线宽度 8 位。

4.2 三个基本单位：Block / Page / oob #

  • Block（块）：一颗 NAND 由很多块组成，块大小常见 64K/128KB/256KB/512KB。Block 是擦除操作的最小单位。一个块里只要有一个 bit 是坏的，整个块就称为坏块。
  • Page（页）：块内又分很多页，常见 2KB，也有 4KB、8KB。Page 是读写操作的最小单位。
  • oob / Spare Area（空闲区）：每一页都附加一块区域，一般 64 字节。因为 NAND 操作容易位翻转，必须有检测与纠错机制（ECC），oob 就是放校验值的地方。oob 的读写通常随页一起完成。它的用途有三类：
    • 标记是否是坏块；
    • 存储 ECC 数据；
    • 存储文件系统相关数据（例如 jffs2 会用这块空间存特定信息）。

以 K9F2G08U0C 为例：

单位 大小 需要的地址位
Page (2K + 64) Byte，每页 2048 字节 2^11 = 2048，即 11 位
Block (128K + 4K) Byte，每块 64 页 2^6 = 64，即 6 位
总容量 256M / 128K = 2048 Block 2^11 = 2048，即 11 位

4.3 NAND 的引脚 #

NAND 的 I/O 引脚既传命令、又传地址、又传数据：

引脚 作用
I/O 输入命令/地址/数据，读操作时输出数据。芯片未被选中或输出被禁用时浮空到高阻
CLE（Command Latch Enable） 高电平时，WE 上升沿把 I/O 上的内容锁存进命令寄存器
ALE（Address Latch Enable） 高电平时，WE 上升沿把 I/O 上的内容锁存进地址寄存器
CE# 片选，低有效。Busy 状态下 CE# 为高会被忽略，器件不会回到 standby
RE# 读使能，低有效，把数据驱到 I/O 总线上；RE 下降沿后 tREA 数据有效，同时内部列地址计数器加一
WE# 写使能，命令/地址/数据都在 WE 上升沿被锁存
WP# 写保护，防止上电抖动导致误编程/误擦除
R/B# 就绪/忙输出。低电平表示编程、擦除或随机读正在进行，完成后回高。开漏输出，芯片未选中时也不会浮空

由此得到一条必须记住的规则：

CLE 高、ALE 低 → 传命令；CLE 低、ALE 高 → 传地址；CLE、ALE 都低 → 传数据。

常见的 NAND 内部只有一个 chip、每个 chip 一个 plane。容量更大的 NAND 内部有多个 chip、每个 chip 多个 plane，本质上是多了一个主控把多块 Flash 叠在一起。

4.4 地址怎么算 #

NAND 没有独立地址线，容量 256M = 2^28 需要 28 位地址，而总线只有 8 位，所以只能拆成多次发：先发列（col）地址，再发行/页（row）地址。这颗芯片用 5 个周期发完地址。

以"第 25 块的 30 页中的第 24 字节"为例：

text
物理地址 = 块大小 × 块号 + 页大小 × 页号 + 页内地址
         = 128K × 25 + 2K × 30 + 24
         = 3338264 (10)
         = 0x32F018 (16)

0x32F018 拆成二进制后按位切分，得到实际要发的地址序列：

周期 位 值 计算方式
1 A7–A0 0x18 col & 0xFF
2 A10–A8 0 (col >> 8) & 0x07
— A11 0 0 访问存储区，1 访问 oob
3 A19–A12 0x5E page & 0xFF
4 A27–A20 0x06 (page >> 8) & 0xFF
5 A28 0 (page >> 16) & 0x01

其中：

  • 列地址 col = A10–A0 = 地址 & (页大小-1)，表示页内的偏移，本例 0x32F018 & 0x7FF = 0x018；
  • 页地址 page = A28–A12 = 地址 / 页大小，即行地址，本例 0x32F018 / 0x800 = 0x65E。

4.5 从 NAND 启动：Steppingstone #

NAND 不能片上执行——它没有独立地址线，CPU 无法直接取指。那为什么还能从 NAND 启动？

S3C2440A 内置了一块 4K 的 SRAM 缓冲区，称为 Steppingstone。上电时，NAND 中的前 4K BootLoader 被硬件自动搬进 Steppingstone，然后从 SRAM 开始执行。

S3C2440 支持两种 boot 方式，靠 OM 引脚选择：OM[1:0] = 00 使能 NAND 启动。

上电时，Nand Flash 控制器通过 4 个引脚状态获知所接器件的信息：

引脚 含义 取值
NCON 存储器选择 0：普通 NAND（256 字/512 字节页，3 或 4 个地址周期）；1：先进 NAND（1K 字/2K 字节页，4 或 5 个地址周期）
GPG13 页大小 0：256 字（NCON=0）或 1K 字（NCON=1）；1：512 字节（NCON=0）或 2K 字节（NCON=1）
GPG14 地址周期数 0：3 个（NCON=0）或 4 个（NCON=1）；1：4 个（NCON=0）或 5 个（NCON=1）
GPG15 总线宽度 0：8 位；1：16 位

4.6 控制器时序配置 #

NAND 的访问必须遵守时序。以 8 位总线为例，控制器时钟源是 HCLK（AHB 高速总线），假设 HCLK = 100MHz，则 T = 10ns。

命令/地址锁存过程（两者共用一个时序图，因为时序参数基本一致）：

  1. CLE/ALE = 0；
  2. CLE/ALE 拉高，命令/地址开始使能，往 DATA 上放入命令或地址；
  3. 经过 TACLS，拉低 nWE；再经过 TWRPH0，DATA 上的内容在 nWE 上升沿开始被锁存；
  4. 锁存需要时间，再经过 TWRPH1 后锁存完成，此时释放 CLE/ALE。

三个参数的含义：

参数 含义
TACLS CLE/ALE 使能后多久才能发 nWE
TWRPH0 nWE 发出后多久数据才会被锁存
TWRPH1 nWE 释放后多久才能释放 CLE/ALE

对照 K9F2G08U0C 手册的时序参数（tCLS、tALS、tWP、tCLH、tALH）可以得到：

text
TACLS  = max(tCLS, tALS) - tWP
TWRPH0 = tWP
TWRPH1 = max(tCLH, tALH)

为什么命令只要 1 个周期、地址却要 5 个？因为命令无非读写擦，8 位绰绰有余；而地址有 28 位，8 根线一次发不完，只能拆成多周期。

数据锁存过程：

  1. WE# 还是高电平，写使能未开启；
  2. 经过 tWP（TDS）时间，在 WE# 上升沿数据开始被锁存；
  3. 经过 tDH，数据锁存完成；
  4. 再经过 tWH 后释放 WE#；
  5. 重复上述过程发送下一个字节。

读时序的几个参数：

参数 含义
tRR 上一次访问结束后，需等待 ready 状态稳定才能开始下一次访问
tREA RE# 有效到 DATA 数据有效的时间
tREH RE# 释放后到允许下一次读使能的时间
tRC 连续顺序访问时单次访问的时间，本例为 25ns

这几个参数都要按实际使用的 NAND 型号与其手册来配置控制器，换一颗芯片就得重算一遍。

五、小结 #

  • Flash 的四条局限（先擦后写、擦写寿命、读写干扰、电荷泄漏）决定了它必须配一个 FTL，FTL 在 Host 端就是 Raw Flash，在芯片里就是 Managed Flash；
  • NOR 胜在可片上执行、驱动简单，但容量小、贵，适合存代码；NAND 胜在容量大、写入快、便宜，适合存数据，但必须按块擦、按页读写，还要管坏块和 ECC；
  • 裸接 NAND 的所有复杂度都来自"没有地址线"：命令、地址、数据挤在 8 根 I/O 上，靠 CLE/ALE 区分，地址还要拆成 5 个周期发；
  • 正因为裸接 NAND 这么麻烦，才有了 eMMC——把那套 FTL 塞进芯片内部，Host 只看到标准接口。
