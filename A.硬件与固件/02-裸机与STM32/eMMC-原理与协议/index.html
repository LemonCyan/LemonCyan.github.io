一、MMC / SD / SDIO 是一家 #

Linux 内核用一个 MMC subsystem 统一管理 MMC、SD、SDIO，原因很简单：它们本质上是同一套总线规范的不同化身。

MMC（MultiMediaCard）是一种固态非易失性存储的存储卡规范，定义了卡的形态、尺寸、容量、电气信号以及与主机的通信协议。从 1997 年 MMC 规范发布至今，基于不同的考量（物理尺寸、电压范围、引脚数、最大容量、数据位宽、时钟频率、安全特性、是否支持 SPI mode、是否支持 DDR mode 等），演化出了 MMC、SD、microSD、SDIO、eMMC 等不同规范。

三者的定位差别可以这样记：

  • MMC 强调多媒体存储（MM，MultiMedia）；
  • SD 强调安全与数据保护（S，Secure）；
  • SDIO 从 SD 演化而来，强调接口（IO，Input/Output），不再关心另一端接的是什么——可以是 WiFi、Bluetooth、GPS。

MMC 线：

1.2 规范的三个方面 #

MMC 从三个角度定义系统行为，不同岗位的工程师各看各的：

（1）Card Concept（卡）——规定形状、物理尺寸、引脚、内部 block 组成、寄存器。以 eMMC 为例，卡内部包含：

Block 作用
Memory core 存储介质，一般是 NAND / NOR Flash
Memory core interface 管理存储介质的接口，完成读、写、擦除
Card interface（CMD / CLK / DATA） 总线接口，与具体引脚相连
Card interface controller 把总线协议转换成 Memory core interface 的形式
Power 模块 提供 reset、上电检测
寄存器 提供卡的信息、参数、访问控制

引脚上，VDD/GND 供电、RST 复位；CLK 提供同步时钟（可在上升沿、下降沿或双沿采样）；CMD 传输双向命令；DATA 传输双向数据，按类型可以是 1/4/8 条。规范定义了 OCR、CID、CSD、EXT_CSD、RCA、DSR 6 组寄存器。

（2）Bus Concept（总线）——对任何有线协议，总线规范都是最重要的部分：

  • 物理信号只有 CLK、CMD、DATA 三类；
  • 电压范围 1.65–3.6V，据此分两类卡：High Voltage MMC（2.7–3.6V）与 Dual Voltage MMC（1.70–1.95V 与 2.7–3.6V，CPU 可切换）；
  • 数据位宽（data bus width mode）可动态配置：1-bit（默认）/ 4-bit / 8-bit。不用的数据线必须保持上拉，且因为位宽是动态的，CPU 必须能动态 enable/disable 这些上拉电阻；
  • CLK 频率范围有 0–20MHz、0–26MHz、0–52MHz 几档，结合位宽基本决定了访问速度；
  • 主从式总线协议：卡是从机（slave），CPU 是主机（Host）；
  • 总线上可以传三种 token：Command（Host→Slave，启动或结束一个操作）、Response（Slave→Host，应答）、Data（双向，1/4/8 条线，每线每周期传 1 或 2 bit）。一次数据传输（Bus Operation）会用到全部三种 token。

（3）Host Controller（控制器）——总线规范在 Host 端的实现，也是 Linux 驱动工程师最关心的地方，详见下一篇《Linux MMC 子系统与 eMMC 驱动调试》。

二、eMMC 是什么 #

eMMC 是 embedded MultiMediaCard 的简称。MMC 是一种闪存卡标准，定义了架构以及访问 Flash Memory 的接口和协议；eMMC 则是对 MMC 的拓展，以满足更高标准的性能、成本、体积、稳定、易用等需求。

对开发者而言，只要遵循 eMMC 协议，就可以对芯片进行读写。

2.1 整体架构 #

eMMC 内部主要分三大部分：

  • Flash Memory：非易失存储器，通常是 NAND Flash，用于存放系统、应用和数据，类似 PC 里的硬盘；
  • Flash Controller：负责擦写均衡、坏块管理、ECC 校验等；
  • Host Interface：对外的标准 MMC 接口。

2.2 Flash Controller 解决了什么 #

NAND Flash 直接接入 Host 时，Host 端通常需要 NFTL（NAND Flash Translation Layer） 或 NAND Flash 文件系统来做坏块管理、ECC 等工作。

eMMC 在内部集成了 Flash Controller，完成擦写均衡、坏块管理、ECC 校验。相比裸接 NAND：

  • 屏蔽了 NAND 的物理特性，减少 Host 端软件复杂度，Host 只需专注上层业务；
  • 借助 Cache、Memory Array 等技术，读写性能也明显更好。

2.3 Host 接口信号 #

信号 说明
CLK 同步时钟
Data Strobe 由 Device 输出的时钟，频率与 CLK 相同，用于同步 Device 输出的数据。eMMC 5.0 引入
CMD 传输 Host 的 Command 与 Device 的 Response
DAT0–7 8 bit 数据总线

Host 与 eMMC 之间的所有通信都由 Host 以一个 Command 发起，Device 针对不同 Command 给出不同响应。

2.4 在 Linux 中的形态 #

在 Linux 中，eMMC 仍然是一个传统的块设备，上层可以搭载各种文件系统——Android 早期用 yaffs2，现在用 ext4。这层"看起来像普通磁盘"的假象，正是 Flash Controller 带来的。

三、分区管理 #

3.1 四类区域，最多八个硬件分区 #

eMMC 标准把内部 Flash Memory 划分为 4 类区域：

区域 数量 用途 默认大小
Boot Area Partition 1、2 两个 存 Bootloader，支持从 eMMC 启动 通常 4MB
RPMB Partition 1 个 存安全相关数据（指纹、支付密钥、序列号） 通常 4MB
General Purpose Partition（GPP） 1–4 个 存系统或用户数据 出厂默认不存在，需主动配置
User Data Area（UDA） 1 个 主要存储区域 总容量减去其他分区

UDA 的容量不需要设置，配置完其他分区、扣除 Enhanced attribute 损耗之后，剩下的就是 UDA。

3.2 分区编址 #

每个硬件分区的存储空间独立编址，访问地址都是 0 – partition size。具体访问哪个分区，由 Extended CSD 寄存器 PARTITION_CONFIG 字段的 Bit[2:0]（PARTITION_ACCESS） 决定。

所以访问特定分区前，必须先发命令配置 PARTITION_ACCESS，再发数据访问请求。

3.3 Boot Area Partition #

容量：两个 Boot 分区大小完全一致，由 Extended CSD 的 BOOT_SIZE_MULT 决定：

text
Size = 128Kbytes × BOOT_SIZE_MULT

一般 BOOT_SIZE_MULT 为 32 即 4MB；部分厂家允许改写。最大 255，即 255 × 128KB = 32640KB ≈ 31.875MB。

进入 Boot State 的条件（Power-up、HW reset 或 SW reset 之后满足其一即可）：

  • Original Boot Operation：CMD 信号保持低电平不少于 74 个时钟周期；
  • Alternative Boot Operation：74 个时钟周期后，在 CMD 首次拉低之前或 Host 发 CMD1 之前，Host 发送参数为 0xFFFFFFFA 的 CMD0。

进入 Boot State 后，若配置了 BOOT_ACK，eMMC 先回一个 "010" 的 ACK 包，然后把最大 128Kbytes × BOOT_SIZE_MULT 的 Boot Data 发给 Host。传输过程中 Host 可拉高 CMD（Original Boot）或发 Reset 命令（Alternative Boot）中断传输。

Boot Data 从哪个分区读出，由 PARTITION_CONFIG 的 Bit[5:3]（BOOT_PARTITION_ENABLE）设定，可选 Boot Partition 1、Boot Partition 2 或 UDA。Boot Data 放在 Boot Area 比放在 UDA 更安全——能减少误改导致系统无法启动、又无法更新的窘境。

写保护：通过 Extended CSD 的 BOOT_WP 字段，可为两个 Boot 分区独立配置写保护：

  • Power-on write protection：掉电后失效，需每次上电重新配置；
  • Permanent write protection：掉电不失效，需主动关闭才失效。

3.4 RPMB Partition #

RPMB 是 Replay Protected Memory Block。写入时 eMMC 会校验数据合法性，只有指定 Host 能写；读取时提供签名机制，保证读到的是 RPMB 内部真实数据而非攻击者伪造的数据。

它常用来存有防篡改需求的数据，如手机指纹支付相关的公钥、序列号。注意：RPMB 只对写鉴权，读不鉴权，任何人都能读，所以存进 RPMB 的数据通常还要再加密。

容量由 RPMB_SIZE_MULT 决定：

text
Size = 128Kbytes × RPMB_SIZE_MULT

一般 RPMB_SIZE_MULT 为 32 即 4MB；最大 128，即 128 × 128KB = 16384KB = 16MB。

Replay Protect 原理：产线上为每个产品生成唯一的 256 bits Secure Key，烧写到 eMMC 的 OTP 区域（只能烧一次），同时在 Host 的安全区域（如 TEE）保留该 Key。eMMC 内部另有一个 RPMB Write Counter，每完成一次合法写入就加一。

读流程：

  1. Host 发读请求，同时生成 16 bytes 随机数一并发送；
  2. eMMC 读出数据，用 Secure Key 对"数据 + 随机数"做 HMAC SHA-256 签名，把数据、随机数、签名一起回给 Host；
  3. Host 先比对随机数是否与自己发的相同，再用同样的 Key 与算法对"数据 + 随机数"签名；签名一致，则数据确实来自 RPMB。

写流程：

  1. Host 先读当前 Write Counter；
  2. Host 把"待写数据 + Write Counter"拼接后签名，数据、Counter、签名一起发给 eMMC；
  3. eMMC 先比对 Counter 是否与当前值相同，再对"数据 + Counter"签名并与 Host 的签名比较；一致才写入。

Counter 的存在，让重放旧数据包无法得逞。

3.5 General Purpose Partitions（GPP） #

GPP 用于存系统和应用数据，但很多产品根本不启用它——功能上与 UDA 类似，直接用 UDA 就够。

容量：最多 4 个，各自独立配置，需设定 Extended CSD 的三个字段 GP_SIZE_MULT_x_2 / _1 / _0：

text
Size = (GP_SIZE_MULT_x_2 × 2^16 + GP_SIZE_MULT_x_1 × 2^8 + GP_SIZE_MULT_x_0) × (Write protect group size)

Write protect group size = 512KB × HC_ERASE_GRP_SIZE × HC_WP_GRP_SIZE

其中 HC_WP_GRP_SIZE 是写保护的操作块大小，HC_ERASE_GRP_SIZE 是擦除操作的块大小。GPP 配置通常只能做一次（OTP），一般在量产的产线上完成。

分区属性：每个 GPP 可从两类属性中选一种，不能同时设多个。

Enhanced attribute：

  • Default：未设定；
  • Enhanced storage media：标准并未定义其效果，由芯片制造商决定。实际产品中一般是把该分区介质从 MLC 改为 SLC，提升读写性能、寿命与稳定性。代价是：同样的存储单元数下，MLC 容量是 SLC 的两倍，所以总容量会略小于标称值。

Extended attribute：

  • Default：未设定；
  • System code：适合存放操作系统这类很少擦写更新的分区；
  • Non-Persistent：适合存放临时数据，如 tmp 目录、swap 分区。

同样，标准未定义其效果，主要由芯片厂商针对不同应用场景做优化。

3.6 User Data Area（UDA） #

UDA 通常是 eMMC 中最大的分区，也是实际产品中最主要的存储区域。

软件分区：为更合理管理数据，UDA 在产品中会再做软件分区，主流技术是 MBR（Master Boot Record）和 GPT（GUID Partition Table）。原理类似：把介质划成多个 SW Partition，用一个 Partition Table 维护各分区的起始地址、大小等属性；系统启动后扫描 Partition Table，据此把各分区加载进来做数据存取。

区域属性：eMMC 支持为 UDA 中某个特定大小的区域设定 Enhanced attribute，效果同样由厂商定义。实际产品中常把某个 SW Partition 设为 Enhanced storage media，以获得更好的性能与健壮性。

四、总线协议 #

4.1 信号 #

CLK：Host 输出，用于数据传输同步与设备运作驱动。

  • 一个时钟周期内，CMD 与 DAT0–7 都可传 1 bit，即 SDR 模式；DAT0–7 还可配置为 DDR 模式，一个周期传 2 bit；
  • Host 可在通信过程中动态调整频率（需满足 Spec 频率范围），以实现省电或数据流控（避免 over-run / under-run）；
  • 某些场景下 Host 可以关掉时钟，例如 eMMC 处于 Busy 状态时、或接收完数据进入 Programming State 时。

CMD：Host 发 Command、eMMC 回 Response。

DAT0–7：数据总线。上电或软复位后只有 DAT0 可用；初始化完成后可配置 DAT0–3 或 DAT0–7，即 4bit 或 8bit 模式。

Data Strobe：eMMC 发给 Host 的时钟，频率同 CLK，用于 Host 侧接收数据同步。只能在 HS400 模式下启用，启用后提高传输稳定性、省去总线 tuning 过程。

Extended CSD byte[183] BUS_WIDTH 配置总线宽度与 Data Strobe；byte[185] HS_TIMING 配置总线速率模式。

4.2 主从关系 #

一条 eMMC 总线上可以有一个 Host、多个 eMMC Device。所有通信都由 Host 以 Command 发起，Host 一次只能与一个 Device 通信。

上电启动后，Host 为所有 Device 逐个分配地址 RCA（Relative device Address）。需要和某个 Device 通信时，先按 RCA 选中它，只有被选中的 Device 才会响应。

由于协议版本迭代，总线速率越来越高。为兼容旧器件，所有 Device 上电或 Reset 后先进入 Backward Compatible Mode，初始化完成后再由 Host 通过特定流程切到高速模式。

4.3 通信模型 #

读：

  • Single Block Read：Device 只发一个 Block 的数据（Block 字节数由 Host 设定或取 Device 默认值）；
  • Multiple Block Read：Device 持续发送，直到 Host 主动发 Stop Command。

从 eMMC 读数据都是按 Block 读的。

写：

  • Single Block Write：只写入后续第一个 Block；
  • Multiple Block Write：持续写入直到 Host 发 Stop Command。

写数据的流程比读多两道手续：

  1. Device 收到一个 Block 后做 CRC 校验，把结果通过 CRC Token 发给 Host；
  2. 校验成功后 Device 把数据写入内部存储器，此时 DAT0 拉低作为 Busy 信号；Host 必须持续检测 DAT0，直到它变高才发下一个 Block。

若 CRC 失败，Device 不写数据，本次传输后续数据全部忽略。

向 eMMC 写数据都是按 Block 写的。

4.4 Command 格式（48 bit） #

字段 长度 说明
Start Bit 1 固定 "0"。无数据传输时 CMD 保持高电平，Host 发 Start Bit 时 Device 即可检测到并开始接收
Transmission Bit 1 固定 "1"，指示方向为 Host → Device
Command Index + Argument 38 命令的具体内容
CRC7 7 覆盖 Start Bit、Transmission Bit、Command Index 和 Argument
End Bit 1 固定 "1"

CRC 的直观理解：发送方把数据"模 2 除"一个约定数，把余数附在数据后发出；接收方收到后做同样的除法，比对余数是否一致。不一致就说明传输中数据变了。

4.5 Response 格式（48 bit 与 136 bit） #

字段 说明
Start Bit 固定 "0"，无数据传输时 CMD 保持高电平
Transmission Bit 固定 "0"，指示方向为 Device → Host
Content 响应内容，随 Command 不同而不同
CRC7 覆盖 Start Bit、Transmission Bit 和 Content
End Bit 固定 "1"

4.6 Data Block 格式 #

Data Block 由 Start Bit、Data、CRC16、End Bit 组成。不同总线宽度和速率下格式不同：

模式 说明
1 bit Bus SDR CRC 为 Data 的 16 bit 校验值（不含 Start Bit）
4 bits Bus SDR 各 Data Line 上的 CRC 为对应线数据的 16 bit CRC
8 bits Bus SDR 同上，8 条线各一个 CRC16
4 bits Bus DDR 上升沿传奇数字节、下降沿传偶数字节；每线有两个交织的 CRC16，上升沿 bit 组成 odd CRC16，下降沿 bit 组成 even CRC16
8 bits Bus DDR 同上，8 条线

DDR 模式下用两个 CRC16，是为了更可靠的校验；选 CRC16 而非 CRC32，则多半是出于兼容性考虑。

4.7 CRC Status Token #

写传输中，Device 收到一个 Data Block 后做 CRC 校验，在对应的 Data Line 上回一个 token：

  • 校验成功 → Positive CRC status token（010）；
  • 校验失败 → Negative CRC status token（101）。

读数据时，Host 收到 Data Block 后也会做 CRC 校验，但无论成败都不向 eMMC 发送 CRC Status Token。

4.8 总线测试（Bus Testing） #

eMMC 处于 SDR 模式时，Host 可发 CMD19 触发总线测试，验证总线硬件连通性。若 Device 支持，收到 CMD19 后会回 Response，然后发送一组固定测试数据；Host 检查数据是否正确即可判断总线是否连通。

若 Device 不支持总线测试，收到 CMD19 不会回 Response。总线测试不支持在 DDR 模式下进行。

4.9 Sampling Tuning #

由于芯片工艺、PCB 走线、电压、温度等因素影响，数据从 Device 到 Host 的时延存在差异，Host 接收数据时的采样点也需要相应调整。最佳采样点通过 Sampling Tuning 流程得到。

不同 eMMC Device 的最佳采样点可能不同；同一 Device 在不同环境下的最佳采样点也可能不同。

标准定义了在 HS200 模式下可进行 Tuning。大致流程：

  1. Host 把采样点重置为默认值；
  2. Host 向 Device 发 Send Tuning Block 命令；
  3. Device 回一组固定的 Tuning Block 数据；
  4. Host 接收并校验；
  5. Host 修改采样时点，回到第 2 步，直到找到一个有效采样时间点区间；
  6. Host 取该区间的中间值作为采样点，退出 Tuning。

Tuning Block 是专门为 Tuning 设计的特殊数据：相对普通数据，它在传输中更高概率出现 high SSO noise、deterministic jitter、ISI、timing errors，因此能更严格地探出采样窗口。

实际执行 Tuning 的时机、频率和步骤，由 Host 端的 eMMC Controller 实现决定。

五、小结 #

  1. eMMC 的价值是"封装复杂度"：把擦写均衡、坏块管理、ECC 关进芯片内部，Host 只看到块设备与标准协议；
  2. 分区是硬件级的：Boot / RPMB / GPP / UDA 各自独立编址，靠 PARTITION_CONFIG 切换访问目标，不是软件分区表能替代的东西；
  3. RPMB 用 Secure Key + Write Counter 实现防重放，只保证写入不可篡改，不保证读取不可见——所以敏感数据仍要自行加密；
  4. 总线协议三件套是 Command / Response / Data，写有多余的 CRC Token 与 DAT0 Busy 握手；
  5. 速率升级的两条路：加宽（1→4→8 bit）与提速（SDR→DDR→HS200→HS400），到了 HS200/HS400 就必须靠 Tuning 或 Data Strobe 来解决采样窗口问题——这也解释了为什么下一篇的驱动代码里处处是 timing、tuning、clock 相关字段。
