零、工程骨架：所有例程共用的那套东西 #

0.1 三块内存区域 #

区域 地址 说明
SDRAM 0x30000000 程序运行的地方，栈顶常用 0x34000000
片内 SRAM（NAND 启动时） 0x00000000 4KB，硬件把 NAND 前 4KB 拷到这里
片内 SRAM（NOR 启动时） 0x40000000 同样 4KB

所以栈指针的写法永远是二选一：

armasm
ldr sp, =4096               /* NAND 启动：4KB 片内 SRAM，起始 0x00，末尾 0x1000 */
#ldr sp, =0x40000000+4096   /* NOR  启动：片内 SRAM 在 0x40000000 */

0.2 标准 Makefile #

makefile
all:start.o led.o
	arm-linux-ld -Ttext 0x30000000 -o led.elf $^
	arm-linux-objcopy -O binary -S led.elf led.bin
	arm-linux-objdump -D led.elf > led.dis

%.o : %.S
	arm-linux-gcc -g -c $^

%.o : %.c
	arm-linux-gcc -g -c $^

.PHONY: clean
clean:
	rm *.o *.elf *.bin *.dis

两个细节：

  • -Ttext 0x30000000 把链接地址定在 SDRAM；
  • 没有加 -march=armv4t，因为 arm-linux-gcc-4.3.2 默认就是 armv4t，这个版本的 S3C2440 不需要额外指定。

0.3 程序超过 4KB 怎么办 #

这是 2440 裸机最关键的一条分界线。NAND 启动时硬件只把前 4KB 搬进 SRAM，所以：

程序大小 能在哪跑 条件
≤ 4KB，全是位置无关码 0x00000000 或 0x30000000 都行 位置无关码可以随便链接
≤ 4KB，含位置相关码 只能链接到 0x00000000 位置相关码的地址 = 链接基数 + 偏移
> 4KB 只能在 SDRAM 跑 前 4KB 必须先初始化 SDRAM，再把 NAND 内容搬过去

搬运骨架：

armasm
.equ    MEM_CTL_BASE, 0x48000000
.equ    SDRAM_BASE,   0x30000000

_start:
    bl  disable_watch_dog
    bl  memsetup                @ 初始化存储控制器
    bl  copy_nand_to_sdram      @ 搬代码
    ldr pc, =on_sdram           @ 跳到 SDRAM 继续执行
on_sdram:
    ldr sp, =0x34000000
    bl  main
halt_loop:
    b   halt_loop

bl 与 ldr pc, =label 的区别是整个「从 SRAM 跳到 SDRAM」手法的核心：

  • bl 是位置无关的：跳转偏移相对当前 PC，所以还在 SRAM 范围内跳；
  • ldr pc, =label 是位置相关的：取到的地址 = 链接地址基数 + 偏移，也就是 0x30000000 区间，从而完成「跨区域跳转」。

推论：跳转之前的所有代码不得超出 SRAM 大小，否则直接跑飞。

0.4 烧录的两条硬限制 #

用 MiniTools 烧录有两个坑，都是实测出来的：

  1. 直接烧 NAND 不行。即使把 SuperBoot 一起烧进去，断电重启仍然起不来。可行做法是把自己的程序当作 uboot 烧。
  2. 程序不能大于 300KB。原文试到 400 多 KB 就直接烧录失败。

端口 位数 端口 位数

1.2 三类寄存器，语义各不相同 #

寄存器 位宽 语义
PnCON 每引脚 2 位 00 输入 / 01 输出 / 10 功能扩展 / 11 保留
PnDAT 每引脚 1 位 配成输出→写入即电平；配成输入→读出引脚状态；配成功能引脚→读到的是未定义值
PnUP 每引脚 1 位 0 使能上拉，1 禁止上拉（注意是反的！）
EXTINT 每引脚若干位 外部中断触发方式 + 数字滤波器使能

PnUP 那个「0 才使能」是 2440 上最常见的初学坑：想开上拉写 1，结果关掉了。

1.3 点亮 nLED_1（GPB5） #

Mini2440 的四个 LED 都接在 GPB 上，低电平点亮：LED1=GPB5、LED2=GPB6、LED3=GPB7、LED4=GPB8。

GPBCON 地址 0x56000010，GPB5 对应 bit[11:10]。写 01（输出）意味着整个寄存器变成 0x400。

GPBDAT 地址 0x56000014，bit5 = 0 即输出低电平（点亮）。

armasm
/* 配 GPB5 为输出 */
ldr r1, =0x56000010
mov r0, #0x400
str r0, [r1]

/* 输出低电平 */
ldr r1, =0x56000014
mov r0, #0x00
str r0, [r1]

C 版本更直观：

c
int main(void)
{
    unsigned int *p_con = (unsigned int *)0x56000010;
    unsigned int *p_dat = (unsigned int *)0x56000014;

    *p_con = 0x400;          /* GPB5 输出 */
    while (1)
        *p_dat = 0;          /* 一直拉低 */
    return 0;
}

GPBUP 不需要配——目标是输出低电平，跟上下拉无关。

二、S3C2440 的中断控制器 #

2.1 60 个中断源、三层屏蔽 #

2440 的中断控制器接受 60 个中断源。UARTn、AC97、EINTn 这几类对控制器而言是**「或」关系**——多个子原因共用一个中断号。

三条流入路径，也是三种清标志的写法：

text
① 无子中断的内部中断
   外设 → SRCPND 置位 → 未被 INTMSK 屏蔽 → 待处理
② 带子中断的内部中断（如 UART）
   外设 → SUBSRCPND 置位 → 未被 INTSUBMSK 屏蔽 → SRCPND 置位
③ 外部中断
   EINT0~3  → 直接进 SRCPND
   EINT4~23 → EINTPEND → 未被 EINTMASK 屏蔽 → SRCPND 的 EINT4-7 / EINT8-23 位

从 SRCPND 往后：

text
SRCPND → INTMSK 屏蔽（注意：FIQ 也能被 INTMSK 屏蔽）
       → INTMOD 选 FIQ / IRQ
       → 普通中断经 PRIORITY 仲裁，只置 INTPND 的一位
       → 进 IRQ

一个重要区别：FIQ 不影响 INTPND 与 INTOFFSET。这两个寄存器只对 IRQ 有效，因为它们表达的是「当前正在处理哪一个」。FIQ 只有一个，不需要编号。

2.2 寄存器速查 #

寄存器 地址 语义
INTMSK 0x4A000008 0 允许服务，1 屏蔽；屏蔽时 SRCPND 照样置位
INTMOD — 每源 1 位：0 IRQ，1 FIQ
SRCPND — 1 表示已请求；写 1 清除
INTPND — 同上
SUBSRCPND — 子源挂起，11 位；写 1 清除
INTSUBMSK — 子源屏蔽
INTOFFSET — 当前 IRQ 源编号；清 SRCPND + INTPND 时自动清
EINTPEND — 外部中断挂起
EINTMASK — 外部中断屏蔽；0 使能，1 禁止

2.3 清除顺序：最容易踩的坑 #

中断类型 要清的寄存器 顺序
无子中断 SRCPND、INTPND 任意
带子中断 SUBSRCPND → SRCPND → INTPND 必须先清子源
EINT4~23 EINTPEND → SRCPND → INTPND 必须先清 EINTPEND
EINT0~3 SRCPND、INTPND 任意

为什么必须先清子源：如果先清 SRCPND，再在清 SUBSRCPND 的过程中，SRCPND 会以为又有中断发生，又置 1。结果就是一次中断响应两次——现象是「中断处理函数被连续调用两遍，串口打印两遍」。

2.4 优先级仲裁：6 组 × 6 个 REQ #

6 个仲裁组 ARB5~ARB0，每组 6 个 REQ，由 ARB_MODE（1 位）与 ARB_SEL（2 位）控制。ARB_SEL 的四种轮换顺序：

ARB_SEL 顺序
00 REQ0, 1, 2, 3, 4, 5
01 REQ0, 2, 3, 4, 1, 5
10 REQ0, 3, 4, 1, 2, 5
11 REQ0, 4, 1, 2, 3, 5

规律很明显：REQ0 永远最高、REQ5 永远最低，轮换只发生在 REQ1~REQ4 之间。

两种模式：

  • ARB_MODE=0：固定优先级，手动改 ARB_SEL 也不能重配优先级（这是很多人试了半天发现「改了没用」的原因）；
  • ARB_MODE=1：自动轮换，REQ0、REQ5 被服务后 ARB_SEL 不变，REQ1 服务后变 01b、REQ2→10b、REQ3→11b、REQ4→00b。

2.5 开中断的两步法 #

2440 上「开中断」是两件独立的事：清除 CPSR 里的 I 位（总开关）+ 清 INTMSK 里的对应位（外设开关）。少一个都不生效。

第一步，切 SVC 模式并关中断（初始化阶段的标准动作）：

armasm
set_svcmode:
    mrs  r0, cpsr
    bic  r0, r0, #0x1f        /* 清 M[4:0] */
    orr  r0, r0, #0xd3        /* SVC 模式 + 关 FIQ/IRQ */
    msr  cpsr, r0
    mov  pc, lr

0xd3 的拆解：0b1101_0011 → I=1（关 IRQ）、F=1（关 FIQ）、T=0（ARM）、模式位 10011（SVC）。

第二步，屏蔽所有中断（用 mvn r1,#0x00 得到 0xFFFFFFFF）：

armasm
disable_interrupt:
    mvn  r1, #0x00            /* r1 = 0xffffffff */
    ldr  r0, =0x4A000008      /* INTMSK */
    str  r1, [r0]             /* 每一位都写 1 = 全屏蔽 */
    mov  pc, lr

第三步，开总中断（清 CPSR 的 I 位）：

c
void vector_enable(void)
{
    __asm__(
        "mrs r0, cpsr\n"
        "bic r0, r0, #(0x01<<7)\n"   /* 清 I 位 */
        "msr cpsr_c, r0\n"
    );
}

2.6 自定义二级向量表（2440 不支持硬件向量） #

这是 2440 与 Cortex-M 最本质的差别：2440 的所有 IRQ 都进同一个入口 0x18，硬件不告诉你是哪个外设。要分派到具体处理函数，必须自己在软件里查。

一级向量表（位置固定）：

armasm
.text
.global _start
_start:
    b   reset
    ldr pc, _undefined_instruction
    ldr pc, _software_instruction
    ldr pc, _prefetch_abort
    ldr pc, _data_abort
    ldr pc, _not_used
    ldr pc, _irq              /* IRQ 固定在 0x18 */
    ldr pc, _fiq

_irq:  .word irq

二级向量表（利用 INTOFFSET）：

armasm
irq:
    sub   sp, sp, #4            /* 先给 pc 腾一个位置 */
    stmdb sp!, {r0-r1}          /* 保存 r0、r1 */
    ldr   r1, =INTOFFSET
    ldr   r1, [r1]              /* r1 = 当前中断源编号 */
    mov   r0, #31
    sub   r1, r0, r1            /* r1 = 31 - 编号（向量表是反向排列的） */
    ldr   r0, =vector
    add   r0, r0, r1, LSL #2    /* r0 = &vector[31-编号] */
    ldr   r0, [r0]              /* r0 = 目标处理函数地址 */
    str   r0, [sp, #8]          /* 把目标地址写到栈上 pc 的位置 */
    ldmia sp!, {r0-r1, pc}      /* 出栈时 pc 直接被装入，完成跳转 */

这套手法的精髓在最后两行：不写 bx 或 mov pc，而是把目标地址先写到栈上「pc 该在的位置」，再用 ldmia ... {..., pc} 一次性弹出。这样保存、跳转、恢复三步合成一次出栈。

为什么要 31 - 编号：因为 C 数组 vector[] 是从低地址往高地址排的，而中断源编号是从 ADC=31 往下排，所以要做一次反向映射。

中断源编号速查：

中断源 编号 中断源 编号
ADC 31 RTC 闹钟 30
UART0 28 IIC 27
TICK（RTC 节拍） 8 EINT8_23 5
EINT4_7 4

2.7 按键：六路外部中断 #

按键 中断 GPIO 功能
K1 EINT8 GPG0 LED1 亮
K2 EINT11 GPG3 LED2 亮
K3 EINT13 GPG5 LED3 亮
K4 EINT14 GPG6 LED4 亮
K5 EINT15 GPG7 全灭
K6 EINT19 GPG11 全亮

GPGCON 位域：00 输入 / 01 输出 / 10 外部中断 / 11 保留。

c
void eint8_23_int_init(void)
{
    GPGCON &= ~((0x03<<0) | (0x03<<6) | (0x03<<10) | (0x03<<12) | (0x03<<14) | (0x03<<22));
    GPGCON |=  ((0x02<<0) | (0x02<<6) | (0x02<<10) | (0x02<<12) | (0x02<<14) | (0x02<<22));

    /* 清挂起，先清 EINTPEND 再清 SRCPND/INTPND */
    EINTPEND |= (1<<8) | (1<<11) | (1<<13) | (1<<14) | (1<<15) | (1<<19);
    SRCPND   |= BIT_EINT8_23;
    INTPND   |= BIT_EINT8_23;

    EINTMASK &= ~((1<<8) | (1<<11) | (1<<13) | (1<<14) | (1<<15) | (1<<19));
    INTMSK   &= ~BIT_EINT8_23;
}

三个「不需要」省掉很多配置工作：

  1. 六个按键都是低电平触发，正是 EXTINT 的默认值（000），不用改 EXTINT；
  2. 默认走 IRQ（INTMOD 的默认值是 0），不用设 INTMOD；
  3. EINT8~23 在仲裁中优先级相同，不用设 PRIORITY。

两个必须注意：

  • 中断服务里清标志要六个位全清。原文示例只清了 bit8/11/13/14，漏了 bit15/19，导致 K5/K6 按一次会反复触发；
  • 初始化函数里就要先清一次标志，否则上电时残留的挂起位会让中断立刻误触发。

EXTINT 的触发编码：000 低电平 / 001 高电平 / 01x 下降沿 / 10x 上升沿 / 11x 双边沿。

还有个硬件约束：电平中断要求有效逻辑电平至少保持 40ns，因为每个引脚带数字滤波器，确认电平需要长于 3 个时钟。

三、UART 串口 #

3.1 三种串口的规格 #

2440 有 3 个独立异步串口，支持中断或 DMA；系统时钟下最高 115.2Kbps，用外部 UEXTCLK 可以更高；每通道收发各 64 字节 FIFO；通道 0/1 带 nRTS/nCTS 硬件流控。

帧格式：1 起始位 + 5~8 数据位 + 可选奇偶 + 1~2 停止位。

3.2 波特率：只有整数分频 #

UBRDIVn​=(波特率×16UART 时钟​)−1
时钟 波特率 UBRDIV
40 MHz 115200 21
50 MHz 115200 26

注意 2440 没有小数分频（对比 STM32 的 BRR 有 DIV_Fraction），所以高波特率下会有误差。50MHz/115200 算出来是 26.12，取 26 后实际波特率约 115740，误差 0.47%，在可接受范围内，但换晶振后必须重算。

3.3 寄存器速查 #

寄存器 UART0 UART1 UART2
UTXHn（发送） 0x50000020 0x50004020 0x50008020
URXHn（接收） 0x50000024 0x50004024 0x50008024
UBRDIVn 0x50000028 0x50004028 0x50008028

位域：

ULCONn（帧格式）：[6] 0 普通 / 1 红外；[5:3] 0xx 无校验 / 100 奇 / 101 偶 / 110 固定 1 / 111 固定 0；[2] 停止位 1/2；[1:0] 数据位 5/6/7/8。

UCONn（控制）：

  • [11:10] 时钟源：x0 PCLK、01 UEXTCLK、11 FCLK/n；
  • [9]/[8] 发送/接收中断类型：0 脉冲、1 电平；
  • [3:2]/[1:0] 发送/接收模式：00 禁止、01 中断或轮询、10 DMA、11 DMA；
  • FCLK/n 分频公式是分通道的：UCON0 → FCLK/(div+6)、UCON1 → FCLK/(div+21)、UCON2 → FCLK/(div+36)；三者全 0 时 FCLK/44。总范围 7~44。这个「+6/+21/+36」的偏移是 2440 特有的怪设计。

UTRSTATn：bit2 发送器空（缓冲+移位器都空）、bit1 发送缓冲空、bit0 接收数据就绪。开 FIFO 后要改查 UFSTAT 的计数位。

UFCONn：[7:6] Tx 触发深度、[5:4] Rx 触发深度（00 空 / 01 16B / 10 32B / 11 48B）、[2] TxFIFO 复位、[1] RxFIFO 复位、[0] FIFO 使能。

3.4 初始化（115200-8-N-1，PCLK=50MHz） #

c
void uart_init(void)
{
    UART0_RX_STA = 0;

    /* GPH2 = TXD0, GPH3 = RXD0 */
    GPHCON &= ~((3<<4) | (3<<6));
    GPHCON |=  ((2<<4) | (2<<6));
    GPHUP  &= ~((1<<2) | (1<<3));      /* 注意：0 = 使能上拉 */

    ULCON0 = 0x03;      /* 无校验、1 停止位、8 数据位 */
    UCON0  = 0x05;      /* PCLK + 收发中断/轮询 */
    UFCON0 = 0x00;      /* 关 FIFO */
    UMCON0 = 0x00;      /* 关自动流控 */
    UBRDIV0 = 26;       /* 50000000/(115200*16) - 1 */
}

void uart_putchar(u8 ch)
{
    while (!(UTRSTAT0 & (0x01<<2)));    /* 等发送缓冲和移位器都空 */
    UTXH0 = ch;
}

void uart_getchar(char *ch)
{
    while (!(UTRSTAT0 & 0x01));        /* 等接收就绪 */
    *ch = URXH0;
}

3.5 接收中断：一个必须同时开的坑 #

c
void uart_int_init(void)
{
    SUBSRCPND |= BIT_SUB_RXD0 | BIT_SUB_TXD0 | BIT_SUB_ERR0;
    SRCPND   |= BIT_UART0;
    INTPND   |= BIT_UART0;

    INTSUBMSK &= ~BIT_SUB_RXD0;   /* 接收子源 */
    INTSUBMSK &= ~BIT_SUB_TXD0;   /* 发送子源 */
    INTMSK    &= ~BIT_UART0;      /* 总中断   */
}

实测结论：RXD0 与 TXD0 两个子源必须同时打开才生效。只开 RXD0 的话接收中断根本不进——这个现象很奇怪（逻辑上收和发应该独立），但确实是 2440 的实测行为，原文注释里也标了「这俩必须同时开启才生效」。

3.6 接收状态机：一个 u16 管完一帧 #

裸机收一帧数据最省事的写法不是环形缓冲，而是一个 16 位状态字：

text
bit15      接收完成标志
bit14      已经收到 0x0D
bit13~0    已收到的有效字节数

c
u16 UART0_RX_STA = 0;
u8  UART0_RX_BUF[UART_RX_LEN];   /* UART_RX_LEN = 1024 */

void UART0_IRQHandler(void)
{
    u8 ch = URXH0;

    if ((UART0_RX_STA & 0x8000) == 0)          /* 还没收完 */
    {
        if (UART0_RX_STA & 0x4000)              /* 上一个字节是 0x0D */
        {
            if (ch != 0x0A)                     /* 不是 0x0A 说明不是 \r\n */
                UART0_RX_STA = 0;               /* 丢弃重来 */
            else
                UART0_RX_STA |= 0x8000;         /* 完整收到一帧 */
        }
        else
        {
            if (ch == 0x0D)
                UART0_RX_STA |= 0x4000;
            else
            {
                UART0_RX_BUF[UART0_RX_STA & 0x3FFF] = ch;
                UART0_RX_STA++;
                if (UART0_RX_STA > UART_RX_LEN - 1)
                    UART0_RX_STA = 0;           /* 溢出丢弃 */
            }
        }
    }
}

踩坑：如果一行数据接收完成，没有去清自定义状态寄存器的最高位，那么接下来的数据无法接收到。主循环处理完必须 UART0_RX_STA = 0;。

3.7 溢出错误：不清就读不出来 #

手册的硬性要求：当发生溢出错误时，必须读出 URXHn。如果未读出，即使清除了 UERSTATn 的溢出位，下次接收数据将同样发出溢出错误。

也就是说错误标志清了没用，必须把脏数据读掉。

四、RTC：一个只认 BCD 的日历 #

4.1 特性 #

  • 外接 32.768kHz 晶振（2^15，分频容易）；
  • 数据全是 BCD 码：秒、分、时、日、月、年、星期；
  • 独立电源引脚 RTCVDD，主电掉电时靠纽扣电池继续走；
  • 两个中断：INT_RTC（闹钟）、INT_TICK（节拍）；
  • 闰年发生器根据 BCDDATE/BCDMON/BCDYEAR 自动决定月末是 28/29/30/31。

节拍周期公式：

Ttick​=128n+1​ 秒

n 是 TICNT 的计数值（1~127），n=127 得 1 秒。走的是递减计数，运行中不可读。

4.3 位域 #

RTCCON：[0] RTCEN（0 禁止/1 使能）、[1] BCDCOUNT、[2] CLKSEL、[3] CLKRST。

写 BCD 寄存器前 RTCCON[0] 必须置 1；掉电前应清零，防止误写。

RTCALM：[6] 全局闹钟使能，[5] 年、[4] 月、[3] 日、[2] 时、[1] 分、[0] 秒。

4.4 BCD 转换 #

c
u8 bcd_to_ten(u8 val)
{
    return (val >> 4) * 10 + (val & 0x0f);
}

u8 ten_to_bcd(u8 val)
{
    return ((val / 10) << 4) | (val % 10);
}

4.5 读到一半跨秒了怎么办 #

这是 RTC 的经典问题：你按 年→月→日→时→分→秒 的顺序读，如果读到 2059-12-31 23:59，然后读 BCDSEC 恰好为 0，那实际时间可能已经跳到 2060-01-01 00:00。

解决规则很简单：如果 BCDSEC 读到 0，必须从 BCDYEAR 起重读全部。因为秒变 0 意味着刚跨过整分边界，前面的读数可能失效。

4.6 一次读写 #

c
void rtc_set(calendar date)
{
    RTCCON = 0x01;                              /* 使能写 */
    BCDYEAR = ten_to_bcd(date.year - 2000);     /* 以 2000 年为基 */
    BCDMON  = ten_to_bcd(date.month);
    BCDDATE = ten_to_bcd(date.day);
    BCDDAY  = ten_to_bcd(date.week + 1);        /* 星期 1~7 */
    BCDHOUR = ten_to_bcd(date.hour);
    BCDMIN  = ten_to_bcd(date.min);
    BCDSEC  = ten_to_bcd(date.sec);
    RTCCON  = 0x00;
}

void rtc_get(calendar *date)
{
    RTCCON = 0x01;
    date->year  = bcd_to_ten(BCDYEAR) + 2000;
    date->month = bcd_to_ten(BCDMON  & 0x1F);
    date->day   = bcd_to_ten(BCDDATE & 0x3F);
    date->week  = bcd_to_ten(BCDDAY  & 0x07) - 1;
    date->hour  = bcd_to_ten(BCDHOUR & 0x3F);
    date->min   = bcd_to_ten(BCDMIN  & 0x7F);
    date->sec   = bcd_to_ten(BCDSEC  & 0x7F);
    RTCCON = 0x00;
}

读的时候那一堆 & 掩码不是多余：BCD 寄存器的高位是标志位，比如 BCDSEC 的 bit7 是「时钟复位标志」，直接转十进制会得到荒唐的数字。

4.7 节拍中断与闹钟 #

c
void rtc_tick_init(void)
{
    /* (127+1)/128 = 1 秒 */
    TICNT = (1<<7) | (0x7f<<0);   /* 使能节拍中断 + 计数 127 */

    SRCPND |= BIT_TICK;
    INTPND |= BIT_TICK;
    INTMSK &= ~BIT_TICK;
}

void rtc_alarm_init(void)
{
    RTCCON = 1;
    ALMSEC = 0;                        /* 秒数为 0 时触发 */
    RTCALM |= (1<<6) | (1<<0);         /* 全局闹钟 + 秒闹钟 */
    RTCCON = 0;

    SRCPND |= BIT_RTC;
    INTPND |= BIT_RTC;
    INTMSK &= ~BIT_RTC;
}

实测输出：

text
rtc set 2023-01-01 00:00:00
alarm int
NOWTIME: 2023-01-01 SUN 00:00:00
NOWTIME: 2023-01-01 SUN 00:00:59
alarm int
NOWTIME: 2023-01-01 SUN 00:01:00

注意 alarm int 出现了两次：一次是设置时残留的挂起位，一次是真的到点。这再次说明初始化阶段必须先清标志。

五、ADC：10 位、8 通道、500KSPS #

5.1 规格与时钟约束 #

参数 值
分辨率 10 位

硬约束：ADC 时钟必须小于 PCLK/5。PCLK=50MHz 时，ADC 时钟上限 10MHz，实际取 1MHz 是稳妥值。

fADC​=49+150MHz​=1MHz,Tconv​=1MHz5​=5μs

Mini2440 板上 AIN0 接了可调电阻 W1，是练手最方便的一路。

#define ADCTSC  (*(volatile u32 *)0x58000004)   /* 触摸屏控制 */

ADCCON 位域：

位 名称 含义
15 ECFLG 只读；0 正在转换，1 转换结束
14 PRSCEN 预分频器使能
13:6 PRSCVL 预分频值 0~255
5:3 SEL_MUX 000 AIN0 / 001 AIN1 / 010 AIN2 / 011 AIN3 / 100 YM / 101 YP / 110 XM / 111 XP

READ_START 这个位非常实用：开了它之后就不用每次手动写 bit0 了，读一次数据 = 触发下一次转换。

5.3 代码 #

c
typedef enum { AIN0=0, AIN1=1, AIN2=2, AIN3=3, YM=4, YP=5, XM=6, XP=7 } ADC_CHANNEL;

void adc_init(ADC_CHANNEL ch)
{
    /* 使能预分频 + 预分频值 49 + 选通道 */
    ADCCON = (1<<14) | (49<<6) | (ch<<3);
}

u16 adc_read(void)
{
    int i, val = 0;

    for (i = 0; i < 16; i++)
    {
        ADCCON |= 0x1;                 /* 启动转换 */
        while (ADCCON & 0x1);          /* 等启动位被硬件清零 */
        while (!(ADCCON & 0x8000));    /* 等转换结束 */
        val += (ADCDAT0 & 0x3FF);      /* 读 10 位结果 */
    }
    return val >> 4;                   /* 16 次平均 */
}

两个 while 的意思完全不同，别搞混：第一个等的是「启动位被硬件清掉」（说明转换真的开始了），第二个等的是「转换结束标志」。少了第一个循环，会读到上一次的结果。

5.4 浮点链接：一个必须知道的编译错误 #

S3C2440 的 ARM920T 没有硬件浮点单元。只要代码里出现浮点除法，链接时就会报 undefined reference to __aeabi_fdiv / __aeabi_uidivmod / __aeabi_uidiv。

解法是链入软件浮点库 libgcc.a，同时把 lib1funcs.S 加进工程。正确的库路径（按 arm-linux-gcc-4.3.2 的安装位置）：

text
/usr/local/arm/4.3.2/lib/gcc/arm-none-linux-gnueabi/4.3.2/armv4t/libgcc.a

注意是 armv4t 子目录，不是 armv5te——很多教程给的路径是错的。

还有一个连带问题：printf 不支持浮点。要打印电压得自己拆整数和小数：

c
int tmp = (voltage - (int)voltage) * 1000;
printf("AIN0 = %d.%-3dV\r\n", (int)voltage, tmp);

六、I2C 与 AT24C08 #

6.1 控制器 #

2440 的 I2C 支持多主控，四种模式：主发、主收、从发、从收。SCL 频率由 IICCON 的 4 位预分频器决定：

SCL=IICCON[3:0]+1IICCLK​,IICCLK=16PCLK​ 或 512PCLK​

Mini2440 上 SCL 接 GPE14、SDA 接 GPE15，板上芯片是 AT24C08（1024 字节）。

6.2 两个关键寄存器 #

IICCON：

  • [7] ACK 使能（发送模式不需要；接收模式置 1 让第 9 个时钟发出 ACK）；
  • [6] 时钟源：0 → PCLK/16，1 → PCLK/512；
  • [5] 收发中断使能；
  • [4] 中断挂起标志：为 1 时 SCL 被拉低、传输停止；写 0 清除；
  • [3:0] 预分频值。

[4] 这个位的语义很容易搞反：它不是「有中断」的标志，而是「卡住总线」的开关。写 1 反而会把 SCL 拉低。

IICSTAT：

  • [7:6] 模式：00 从收 / 01 从发 / 10 主收 / 11 主发；
  • [5] 读时 0 未忙 / 1 忙；写时 0 发 STOP、1 发 START；
  • [4] 串行输出使能；
  • [3] 仲裁失败；
  • [0] 最后一位的 ACK：0 表示收到 ACK，1 表示无 ACK（又是反的）。

6.3 读写流程 #

text
主发送：
1. IICCON = ACK使能 | 中断使能 | 时钟分频
2. IICSTAT[4] = 1 使能串行输出
3. IICDS = 从设备地址（7 位 + 读写位）
4. IICSTAT = 0xF0  （主发 + 发 START）
5. 每发完一字节进中断，清 IICCON[4]
6. 查 IICSTAT[0] 判断 ACK；无 ACK 则 IICSTAT = 0xD0 发 STOP、IICCON = 0xAF 关中断

主接收：
1~2. 同上
3. IICDS = 从设备地址
4. IICSTAT = 0xB0  （主收 + 发 START）
5. 每字节中断后清 IICCON[4]、查 ACK
6. 有 ACK → 读 IICDS、清挂起、发 ACK、继续读
   无 ACK → IICSTAT = 0x90 发 STOP

6.4 AT24C08 的三个器件特性 #

特性一：从机地址不是固定的，而是按块变化。AT24C08 内部是 4 个 block × 256 字节，地址编码：

text
写： 0xA0 + block * 2
读： 0xA1 + block * 2

所以访问不同 block 时，从机地址本身要变。这是 AT24C08 与 AT24C02（只有 256 字节、地址固定 0xA0）最大的差别。

特性二：页缓冲只有 16 字节。一次写入的数据必须同页、16 字节对齐，超过 16 字节必须分段调用。超了会发生「页内回卷」——写到页尾后又回到页首覆盖，数据静默出错。

特性三：写完必须延时：

c
delay_ms(10);   /* 这个延时一定要足够长，否则会出错。
                   因为 24C08 在从 SDA 上取得数据后，还需要一定时间的烧录过程 */

6.5 一个隐蔽的读时序坑 #

读操作分两段：先以「写地址」的身份发内存偏移（0xA0+block2），再以「读地址」的身份切过来（0xA1+block2）。

切过来之后读到的第一个字节是哑元（器件地址），必须丢弃：

c
temp = IICDS;   /* 丢掉第一个字节 */
iic_ack();
/* 之后才是真正的数据 */

不丢的话，读出来的数据整体错位一个字节。现象是「写进去 Dear my baby，读出来前面多一个乱码字符」。

6.6 引脚配置（注意上拉是反的） #

c
GPECON &= ~((3<<28) | (3<<30));
GPECON |=  ((2<<28) | (2<<30));    /* GPE14/15 设为 IIC 功能 */
GPEUP  |= 0xC000;                   /* 1 = 禁止内部上拉（I2C 靠外部上拉） */

IICCON  = (1<<7) | (0<<6) | (1<<5) | 0x0F;
IICSTAT |= (1<<4);

实际 SCL 频率：50000000 / (16 × (15+1)) = 195312Hz ≈ 0.2MHz。

七、DM9000：把 2440 连上网 #

7.1 为什么需要外部芯片 #

S3C2440 内部没有以太网 MAC，所以 Mini2440 板上外接了一颗 DM9000EP。它的工作实质是「MAC 通过 MII 控制 PHY」：

部分 层次 职责
MAC 数据链路层 组帧、地址过滤、CRC 校验、收发控制
PHY 物理层 加校验、线路编码、驱动双绞线

7.2 一根地址线决定一切 #

DM9000 与 2440 的接线里，最关键的是 CMD 接 LADDR2：

DM9000 引脚 连到 2440 说明
SD0~SD15 LDATA0~LDATA15 16 位数据
CMD LADDR2 高 = 数据，低 = 寄存器地址
INT EINT7（GPF7） 收发完成中断
IOR# nOE 读
IOW# nWE 写
AEN nGCS4（GPA15） 片选，对应 0x20000000~0x28000000

nGCS4 的地址区间是 0x20000000 起，CMD 接在 LADDR2（第 2 位，权重 4）。所以：

c
#define DM_ADD  (*((volatile u16 *)0x20000000))   /* 寄存器地址端口 */
#define DM_DAT  (*((volatile u16 *)0x20000004))   /* 寄存器数据端口 */

结论：DM9000 的地址线已经退化成了类似 NAND 的 ALE 信号，任何操作都必须「先写地址、再读写数据」两步，不能像普通内存一次访问完成。

7.3 片选时序 #

c
void cs_init(void)
{
    BWSCON  &= ~(3<<16);
    BWSCON  |=  (1<<16);            /* bank4 数据宽度 16 位 */

    BANKCON4 = (0<<13)    /* Tacs = 0 clk  */
             | (0<<11)    /* Tcos = 3 clk  */
             | (7<<8)     /* Tacc = 14 clk */
             | (1<<6)     /* Tcoh = 1 clk  */
             | (0<<4)     /* Tah  = 0 clk  */
             | (0<<2)     /* Tacp = 6 clk  */
             | (0<<0);    /* PMC  = normal  */
}

Tacc = 14 clk 是最保守的访问周期。DM9000 是慢速外设，宁可慢一点也不能读错。

7.4 中断配置（高电平触发） #

c
void dm9000_int_init(void)
{
    GPFCON &= ~(0x3<<14);
    GPFCON |=  (0x2<<14);            /* GPF7 设为外部中断功能 */

    EXTINT0 &= ~(0x7<<28);
    EXTINT0 |=  (0x1<<28);           /* EINT7 = 高电平触发 */

    EINTPEND |= 1<<7;
    SRCPND   |= BIT_EINT4_7;
    INTPND   |= BIT_EINT4_7;

    EINTMASK &= ~(1<<7);
    INTMSK   &= ~BIT_EINT4_7;
}

原文正文一处写「高电平触发」、另一处写「上升沿中断」，代码实际用的是高电平。如果实际板子上偶发重复中断，可以改成上升沿（01x）。

7.5 复位、探测、MAC 初始化 #

复位有个很容易漏的动作：必须先把 GPIO0 写 0 给内部 PHY 上电。

c
u8 dm9000_reset(void)
{
    dm9000_reg_write(DM9000_GPCR, GPCR_GPIO0_OUT);   /* GPIO0 设为输出 */
    dm9000_reg_write(DM9000_GPR, 0);                 /* 写 0 = 给内部 PHY 供电 */

    dm9000_reg_write(DM9000_NCR, NCR_LBK_INT_MAC | NCR_RST);
    dm9000_reg_write(DM9000_NCR, 0);
    /* 重复两次才真正复位 */
    dm9000_reg_write(DM9000_NCR, NCR_LBK_INT_MAC | NCR_RST);
    dm9000_reg_write(DM9000_NCR, 0);
}

为什么写两次：芯片有个已知时序特性，单次写 NCR_RST 有时不生效。这是厂商勘误表里的事，别自己「优化」掉。

ID 校验（4 个 8 位寄存器拼成 32 位）：

c
u32 id = dm9000_reg_read(DM9000_VIDL)
       | (dm9000_reg_read(DM9000_VIDH) << 8)
       | (dm9000_reg_read(DM9000_PIDL) << 16)
       | (dm9000_reg_read(DM9000_PIDH) << 24);
/* 期望 0x90000A46 */

默认值：VIDH=0x0A、VIDL=0x46 → 0x0A46；PIDH=0x90、PIDL=0x00 → 0x9000。

注意 dm9000_reg_read 的返回类型必须是 u16。原文写成 u8 会导致读 VIDH/NSR 这类高字节寄存器时被截断成 0——这个 bug 极其隐蔽，因为读 ID 恰好还能过（VIDL 在低字节）。

7.6 发送与接收 #

c
void dm9000_tx(u8 *data, u32 length)
{
    dm9000_reg_write(DM9000_IMR, 0x80);        /* 先关中断，避免发到一半被打断 */

    dm9000_reg_write(DM9000_TXPLL,  length & 0xFF);
    dm9000_reg_write(DM9000_TXPLH, (length >> 8) & 0xFF);

    DM_ADD = DM9000_MWCMD;                     /* 命令：后续写入进 TX SRAM */
    for (i = 0; i < length; i += 2)
        DM_DAT = data[i] | (data[i+1] << 8);

    dm9000_reg_write(DM9000_TCR, TCR_TXREQ);   /* 启动发送 */

    while (dm9000_reg_read(DM9000_TCR) & 0x01) /* bit0 自动清零 = 发送完成 */
        ;

    dm9000_reg_write(DM9000_NSR, 0x2C);        /* 清发送状态 */
    dm9000_reg_write(DM9000_IMR, 0x81);        /* 重新开启接收中断 */
}

接收流程要点：先空读 MRCMDX（丢弃一个无效字节），再读 MRCMD 拿状态和长度，然后数据会跟在后面自动流出：

c
u16 dm9000_rx(u8 *data)
{
    if ((dm9000_reg_read(DM9000_ISR) & 0x01) == 0)   /* 不是接收中断 */
        return 0;
    dm9000_reg_write(DM9000_ISR, 0x01);              /* 写 1 清 */

    ready = dm9000_reg_read(DM9000_MRCMDX);           /* 空读，丢弃 */
    if ((ready & 0x01) != 0x01)
    {
        ready = dm9000_reg_read(DM9000_MRCMDX);
        if ((ready & 0x01) != 0x01)
            return 0;
    }

    status = dm9000_reg_read(DM9000_MRCMD);           /* 读包状态 */
    len = DM_DAT;                                     /* 紧接着就是长度 */

    if (len < DM9000_PKT_MAX)
        for (i = 0; i < len; i += 2)
        {
            u16 tmp = DM_DAT;
            data[i]   = tmp & 0xFF;
            data[i+1] = (tmp >> 8) & 0xFF;
        }
    return len;
}

7.7 一个必须避开的启动配置 #

c
/* 这里如果加入 RCR_ALL 意为接受广播数据，会造成接收数据异常 */
dm9000_reg_write(DM9000_RCR, RCR_DIS_LONG | RCR_DIS_CRC | RCR_RXEN);
dm9000_reg_write(DM9000_IMR, IMR_PAR);

原文明写了这个坑：加 RCR_ALL（接收所有包）会导致接收异常。原因通常与「SRAM 读指针被杂包冲乱」有关，实际调试时如果抓不到包，不要第一反应就加 RCR_ALL。

7.8 协议栈第一层：ARP #

2440 是小端，网络协议是大端，所以 16 位字段发送前必须交换字节：

c
#define SWAP(n) ((((u16)(n) & 0xFF) << 8) | (((u16)(n) >> 8) & 0xFF))

以太网头 14 字节（d_mac[6] + s_mac[6] + frame_type[2]），ARP 体 28 字节，合计 42 字节：

c
typedef struct {
    u8 d_mac[6];
    u8 s_mac[6];
    u16 frame_type;     /* 0x0806 = ARP, 0x0800 = IP */
} ETH_HDR;

typedef struct {
    ETH_HDR ethhdr;
    u16 hw_type;        /* 1 = 以太网 */
    u16 protocol;       /* 0x0800 */
    u8  hwadd_len;      /* 6 */
    u8  protoc_len;     /* 4 */
    u16 opcode;         /* 1 = 请求, 2 = 应答 */
    u8  smac[6];
    u8  sipaddr[4];
    u8  dmac[6];
    u8  dipaddr[4];
} ARP_HDR;

最小可跑的 ARP 应答就是：收到 opcode==1 的请求，把源/目的对调，opcode 改 2，回发 42 字节。

一个实验细节：发给哪台机器必须同网段（原文用 192.168.0.104 请求 192.168.0.155），否则 ARP 广播出不去。

八、踩坑清单 #

  1. PnUP 是 0 使能上拉，写 1 是关。
  2. PnDAT 读到的是未定义值（当引脚配成功能模式时）。
  3. MiniTools 直接烧 NAND 不行，要把程序当 uboot 烧；程序 > 300KB 必失败。
  4. 程序 > 4KB 必须自己搬到 SDRAM，且前 4KB 里不能有任何 rodata。
  5. 中断清标志必须先清子源（SUBSRCPND / EINTPEND），否则一次中断进两次。
  6. 初始化阶段要先清一次挂起位，否则上电立刻误触发。
  7. UART0 的 RXD0 与 TXD0 必须同时使能才生效（实测）。
  8. 接收状态机处理完必须清 bit15，否则再也收不到数据。
  9. 溢出错误必须读掉 URXHn，只清标志不管用。
  10. RTC 寄存器必须按字节访问（STRB/LDRB/char*）。
  11. RTC 读到 BCDSEC=0 要重读全部，否则跨秒/跨年数据错乱。
  12. RTC 读值要按位掩码，高位是标志位不是数值。
  13. ADC 时钟必须 < PCLK/5。
  14. ADC 的两次 while 别少写第一个，否则读到上一次结果。
  15. 浮点要链 libgcc.a（armv4t 目录）+ lib1funcs.S，printf 不支持 float。
  16. AT24C08 的从机地址随 block 变化（0xA0 + block*2）。
  17. AT24C08 页写必须 16 字节对齐，超页会回卷覆盖。
  18. AT24C08 写完必须延时 10ms。
  19. I2C 读的第一个字节是哑元，必须丢弃。
  20. DM9000 的 GPIO0 必须写 0，否则内部 PHY 断电，ID 都读不到。
  21. dm9000_reg_read 必须返回 u16，返回 u8 会丢高字节。
  22. 别加 RCR_ALL，会造成接收异常。
  23. ARP 的 16 位字段发送前要 SWAP（2440 小端 vs 网络大端）。

小结 #

这篇覆盖了 2440 上七类外设，但它们的编程套路是同一个：

  1. 配引脚功能（PnCON，其中外部中断是 10）；
  2. 配控制器（时钟分频、触发方式、使能）；
  3. 开中断要先清标志，且清标志的顺序有讲究（子源在前）；
  4. 等一个状态位（发送就绪、转换完成、ACK 到达）；
  5. 读/写数据寄存器。

真正需要单独记的只有那些「反直觉」的点：PnUP 的 0/1 语义、INTPND 只对 IRQ 有效、RTC 的 BCD 与按字节访问、DM9000 的地址端口退化。这些点在踩坑清单里都列了。
