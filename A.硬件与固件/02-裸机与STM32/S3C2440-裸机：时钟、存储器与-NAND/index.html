零、先看全貌：一颗 2440 上电后要干的四件事 #

text
上电
 ├─ 0x0 处取指（NOR 或 NAND 前 4KB 已被硬件搬到片内 SRAM）
 ├─ 1. 关看门狗         WTCON = 0x53000000
 ├─ 2. 配时钟           12MHz 晶振 → MPLL 400MHz → HCLK 100MHz / PCLK 50MHz
 ├─ 3. 配 SDRAM         BWSCON/BANKCON/REFRESH/BANKSIZE/MRSRB → 0x30000000 可用 64MB
 ├─ 4. 建页表 + 开 MMU  CP15 C1/C2/C3 → 虚拟地址生效
 └─ 5. 访问 NAND        0x4E000000 那组控制器寄存器

这五步里，前三步是硬件使能，第四步是地址空间改造，第五步是外部存储访问。本文按这五步展开。

一、关看门狗：为什么第一件事是它 #

S3C2440 的看门狗上电默认是开着的，超时时间很短（几秒级）。如果程序在初始化阶段卡住，看门狗会不停复位，现象是「板子一直在重启、串口反复打印同一段开头」。所以裸机程序第一条有效指令通常是：

armasm
#define  WTCON      0x53000000

disable_watchdog:
    ldr  r0, =WTCON
    mov  r1, #0x00
    str  r1, [r0]        /* 清零 WTCON：关中断、关计数器、关复位输出 */
    mov  pc, lr

注意这里是写 0 而不是写某个「关闭位」：WTCON 是「使能位全在 0 位段」的结构，整体清零最省事。

二、系统时钟：12MHz 怎么变成 400MHz #

2.1 三路时钟与它们的客户 #

时钟 供给对象 目标频率
FCLK ARM920T 内核 400 MHz
HCLK AHB 总线外设：存储器控制器、中断控制器、LCD 控制器、DMA、USB host 100 MHz
PCLK APB 总线外设：WDT、IIS、I2C、PWM 定时器、MMC/SD、ADC、UART、GPIO、RTC、SPI 50 MHz

两个 PLL：MPLL 产 FCLK/HCLK/PCLK，UPLL 专供 USB（48MHz）。

上电时全板统一跑外部 12MHz 晶振。要让 CPU 跑 400MHz，必须靠 PLL 倍频。

2.2 OM[3:2]：时钟源是晶振还是外部时钟 #

OM[3:2] 主时钟源 USB 时钟源
00 晶振 晶振
01 晶振 外部时钟
10 外部时钟 晶振
11 外部时钟 外部时钟

Mini2440 的 OM3、OM2 都接地 → OM[3:2]=00 → 用 12MHz 晶振。

2.3 最容易踩的一条：不写 MPLLCON 就不会用上 PLL #

复位后 MPLL 虽然已经启动，但它的输出还没有被选作系统时钟，直到软件向 MPLLCON 写入有效值为止。这之前系统直接用外部晶振。

所以有个反直觉的结论：即使你完全不想改默认频率，也必须把相同的值写进 MPLLCON，否则 PLL 输出永远进不了系统。

2.4 倍频公式 #

MPLL=p×2s2×m×Fin​​,m=MDIV+8, p=PDIV+2, s=SDIV
UPLL=p×2sm×Fin​​

注意 MPLL 公式前面有系数 2，UPLL 没有。这个差异是很多人算错 USB 时钟的原因。

PLL 内部结构：VCO（压控振荡器）、前分频 P、反馈分频 M、后分频 S、鉴相器 PFD、电荷泵、环路滤波器。

2.5 三个寄存器 #

寄存器 地址 位域
LOCKTIME 0x4C000000 [31:16] UPLL 锁定计数，[15:0] MPLL 锁定计数
MPLLCON 0x4C000004 MDIV[19:12] / PDIV[9:4] / SDIV[1:0]
UPLLCON 0x4C000008 同上
CLKDIVN 0x4C000014 DIVN_UPLL[3] / HDIVN[2:1] / PDIVN[0]
CAMDIVN 0x4C000018 摄像头时钟分割

CLKDIVN 的分频语义（必须连着 CAMDIVN 一起看）：

  • PDIVN：0 → PCLK=HCLK；1 → PCLK=HCLK/2。
  • HDIVN：
    • 00 → HCLK=FCLK/1
    • 01 → HCLK=FCLK/2
    • 10 → HCLK=FCLK/4（CAMDIVN[9]=0）／FCLK/8（CAMDIVN[9]=1）
    • 11 → HCLK=FCLK/3（CAMDIVN[8]=0）／FCLK/6（CAMDIVN[8]=1）
  • DIVN_UPLL：0 → UCLK=UPLL；1 → UCLK=UPLL/2。UPLL 设 48MHz 时置 0，设 96MHz 时置 1。

很多人照着「HDIVN=10 就是 4 分频」写，结果发现 HCLK 只有 50MHz——因为板上 CAMDIVN[9] 被置了 1。这是 CAMDIVN 这个「不相干」寄存器最阴的地方。

2.6 参数计算（Fin = 12MHz，目标 400:100:50） #

先定分频：FCLK:HCLK:PCLK = 400:100:50 = 1:4:8，即 HDIVN=2（10b）、PDIVN=1、DIVN_UPLL=0：

CLKDIVV​AL=(0≪3)∣(2≪1)∣1=5

再算 MPLL：MDIV=92、PDIV=1、SDIV=1 → m=100、p=3、s=1 → 2×100×12/(3×2) = 400MHz。

再算 UPLL：U_MDIV=56、U_PDIV=2、U_SDIV=2 → m=64、p=4、s=2 → 64×12/(4×4) = 48MHz。

2.7 必须切异步总线模式 #

这是 2440 上最经典的一个坑。HDIVN≠0 时（也就是 FCLK≠HCLK 时），必须把 CPU 从 fast bus mode 切到 asynchronous bus mode，否则 CPU 会在错误的时钟域里跑，行为完全不可预期。

S3C2440 没有同步总线模式（那是 2410/2412 才有的概念），所以只需把 CP15 C1 的最高两位都置 1：

c
mrc p15, 0, r1, c1, c0, 0    /* 读 CP15 C1 */
orr r1, r1, #0xc0000000      /* bit31=1, bit30=1：异步总线模式 */
mcr p15, 0, r1, c1, c0, 0    /* 写回 */

漏这一步的症状：程序跑到某一条指令突然跑飞，或者在中断里随机崩溃。因为 CPU 和总线用不同时钟，时序对不上。

2.8 完整初始化汇编 #

armasm
.text
.global _start
_start:
    bl  disable_watchdog        /* 关看门狗 */
    bl  system_clock_init       /* 设置系统时钟 */
    bl  stack_init              /* 初始化栈 */
    bl  main
loop:
    b loop

#define  WTCON      0x53000000
disable_watchdog:
    ldr  r0, =WTCON
    mov  r1, #0x00
    str  r1, [r0]
    mov  pc, lr

/* FCLK=400MHz HCLK=100MHz PCLK=50MHz UPLL=48MHz */
#define  LOCKTIME     0x4c000000
#define  MPLLCON      0x4c000004
#define  UPLLCON      0x4c000008
#define  CLKDIVN      0x4c000014
#define  M_MDIV       92      /* @Fin=12M  MPLL=400M */
#define  M_PDIV       1
#define  M_SDIV       1
#define  U_MDIV       56      /* @Fin=12M  UPLL=48M  */
#define  U_PDIV       2
#define  U_SDIV       2
#define  DIVN_UPLL    0       /* FCLK:HCLK:PCLK = 1:4:8 */
#define  HDIVN        2
#define  PDIVN        1

system_clock_init:
    ldr r0, =LOCKTIME
    ldr r1, =0xffffffff
    str r1, [r0]                       /* 锁定计数器给最大，先不管它 */

    ldr r0, =CLKDIVN
    ldr r1, =((DIVN_UPLL<<3) | HDIVN<<1 | PDIVN)
    str r1, [r0]

    /* CPU 改为异步总线模式：HDIVN!=0 时必须 */
    mrc p15, 0, r1, c1, c0, 0
    orr r1, r1, #0xC0000000
    mcr p15, 0, r1, c1, c0, 0

    /* 先设 UPLL */
    ldr r0, =UPLLCON
    ldr r1, =((U_MDIV<<12) | (U_PDIV<<4) | U_SDIV)
    str r1, [r0]
    nop                            /* 必须等 7 个 nop 再设 MPLL */
    nop
    nop
    nop
    nop
    nop
    nop

    /* 再设 MPLL */
    ldr r0, =MPLLCON
    ldr r1, =((M_MDIV<<12) | (M_PDIV<<4) | M_SDIV)
    str r1, [r0]
    mov pc, lr

必须「先 UPLL 后 MPLL，中间隔约 7 个 nop」。这是硬件要求：两个 PLL 共用锁定逻辑，靠得太近会互相干扰。写成注释里的「7 个 nop」不是玄学，是手册里的时序要求。

2.9 栈初始化 + 判断 NOR 还是 NAND 启动 #

栈放哪里取决于从哪个介质启动，判断手法非常巧：

armasm
stack_init:
    mov r1, #0
    ldr r0, [r1]              /* 备份 0 地址原值 */
    str r1, [r1]              /* 0 -> [0] */
    ldr r2, [r1]              /* 读回 [0] */
    cmp r1, r2                /* 相等则说明能写：NAND 启动 */
    ldr sp, =0x40000000+0x1000 /* 先假设 NOR 启动，栈放片内 SRAM 顶端 */
    moveq sp, #0x1000          /* NAND 启动：栈放在 0x1000（4KB SRAM 顶端） */
    streq r0, [r1]             /* 恢复原值 */
    mov pc, lr

原理：NOR 启动时 0 地址是 NOR Flash，可以读但不像内存那样写；NAND 启动时 0 地址是片内 4KB SRAM，可以读写。 往 0 地址写个数再读回比较，就知道是哪一种。

  • NAND 启动：栈只能放在 0x1000（4KB SRAM 顶端）——这也是「NAND 启动的引导代码必须在 4KB 内」的物理来源。
  • NOR 启动：栈可以放到 0x40001000（片内 SRAM）。

2.10 时钟效果验证 #

配好时钟后最直观的验证是点灯：把原来 delay 常量不变，灯闪速会明显变快（因为 delay 是空转循环，跑得更快了）。

编译链接：

text
arm-linux-ld -Ttext 0x30000000 -o main.elf start.o main.o
arm-linux-objcopy -O binary -S main.elf main.bin
arm-linux-objdump -D main.elf > main.dis
  • -Ttext 0x30000000：链接地址设成 SDRAM 基址；
  • -S：不把重定位信息和符号信息复制到目标文件（bin 会更小）。

三、存储器控制器与 SDRAM #

3.1 地址空间总图 #

地址范围 用途
0x0000_0000 – 0x3FFF_FFFF Bank0 – Bank7（每 Bank 128MB）
0x4000_0000 – 0x47FF_FFFF 依启动方式不同
0x4800_0000 – 0x5FFF_FFFF 特殊功能寄存器（SFR）
0x6000_0000 – 0xFFFF_FFFF 未使用

27 根地址线 ADDR0–ADDR26、32 位数据线 → 单 Bank 128MB；8 根片选 nGCS0–nGCS7 → 共 1GB。

关键约束：

  • Bank0–Bank5 可焊 ROM/SRAM/各类外设；
  • Bank6–Bank7 才能焊 SDRAM，最大 256MB；
  • CPU 上电从 Bank0 开始执行，所以启动介质必须在 Bank0。

3.2 Mini2440 的 SDRAM 是怎么接的 #

板上是 HY57V561620FTP，两片 32MB×16bit 并联 → 64MB / 32bit，挂 Bank6，地址空间 0x30000000–0x33FFFFFF。

芯片只有 13 根地址线 A0–A12（最多 8MB 空间），靠行/列地址分时复用扩到 64MB：

段 线 数量 由谁锁存
行地址 A0–A12 13 根（8192 行） nSRAS
列地址 A0–A8 9 根（512 列） nSCAS
L-Bank BA1–BA0 2 位 与行地址同时下发

13 + 9 + 2 = 24 位地址，每个地址 2 字节 → 2^25 = 32MB/片，两片并联 64MB。

两个接线细节：

  1. BA0/BA1 接 ADDR24/ADDR25：CPU 按字节寻址，64MB 需要 A25–A0，最高两位正好是 L-Bank 选择。
  2. LADDR2 接芯片 A0：因为 32 位位宽，一个地址对应 4 字节，地址线要错开一根。

3.3 13 个控制器寄存器 #

寄存器 地址 复位值
BWSCON 0x48000000 0x00
BANKCON0–5 0x48000004–0x48000018 0x0700
BANKCON6/7 0x4800001C / 0x48000020 0x0700
REFRESH 0x48000024 0xAC0000
BANKSIZE 0x48000028 0x00
MRSRB6/7 0x4800002C / 0x48000030 —

规律：Bank0–5 只需要 BWSCON + BANKCONx；SDRAM 还要额外 4 个（REFRESH、BANKSIZE、MRSRB6/7）。

3.4 BWSCON：总线宽度与等待 #

每个 Bank 占 4 位：ST / WS / DW。

  • ST（用 nWBE 还是 nBE）：0 用 nWBE[3:0]，1 用 nBE[3:0]；
  • WS（是否使能 WAIT）：0 禁止，1 使能；
  • DW（数据宽度）：00=8 位，01=16 位，10=32 位，11=保留。

对 SDRAM（Bank6）：ST6=0（用数据掩码）、WS6=0（不用 WAIT）、DW6=10（32 位）→ 置 0x02000000。

注意 Bank1 的 DW 是只读的，由 OM[1:0] 决定——这也是判断启动介质的一个旁证。

3.5 BANKCONx：时序 #

字段 含义 编码
Tacs nGCSn 前地址建立 00=0, 01=1, 10=2, 11=4 时钟
Tcos nOE 前片选建立 同上
Tacc 访问周期 000=1, 001=2, 010=3, 011=4, 100=6, 101=8, 110=10, 111=14
Tcoh nOE 后片选保持 0/1/2/4
Tcah nGCSn 后地址保持 0/1/2/4
Tpac Page 模式访问周期 00=0, 01=1, 10=2, 11=4
PMC Page 模式配置 00=1 数据, 01=4, 10=8, 11=16

BANKCON6/7 的 SDRAM 专用段：

  • MT：00=ROM/SRAM，01/10=保留（不能用），11=SDRAM；
  • Trcd：00=2、01=3、10=4 个时钟；
  • SCAN：列地址位数，00=8 位、01=9 位、10=10 位。

本板 9 位列地址、tRCD 取 3 个时钟 → BANKCON6 = BANKCON7 = 0x00018005。

3.6 REFRESH：刷新周期怎么算 #

SDRAM 靠电容存数，电容会漏电，必须周期性刷新。芯片手册给的是「8192 行 / 64ms」，即每行 64ms/8192 = 7.8125μs 必须刷一次。

刷新计数的公式：

refresh_count=211+1−HCLK×Trefresh​

HCLK=100MHz（10ns/周期）、T=7.8125μs → 2049 − 100×7.8125 = 2049 − 781.25 ≈ 1269。

所以 REFRESH 里：

  • REFEN[23] = 1：使能刷新；
  • TREFMD[22] = 0：自动刷新（CBR）；
  • Trp[21:20] = 00：预充电 2 个时钟；
  • Tsrc[19:18] = 00：半行周期 4 个时钟；
  • Counter[10:0] = 1269。

最终值 0x008C0000 + 1269 = 0x008C04F5。

3.7 BANKSIZE 与 MRSRB #

BANKSIZE 关键位：

  • BURST_EN：是否允许 ARM 核突发传输（开了性能更好）；
  • SCKE_EN：SDRAM 省电模式（SCKE 控制）；
  • SCLK_EN：SCLK 是一直有效还是只在访问期间有效（推荐后者）；
  • BK76MAP：Bank6/7 的大小映射。001 = 64M/64M（本板），010=128M/128M，000=32M/32M，依此类推到 2M/2M。

开突发 → 0x000000B1；不开 → 0x00000031。

MRSRB6/7（模式寄存器）：

  • CL[6:4]：CAS 延迟，000=1、010=2、011=3；本板查手册取 CL=3；
  • BT[3]：突发类型，0=顺序（一般都用顺序）；
  • BL[2:0]：突发长度，000=1；
  • 测试模式 [2:0]=00。

→ MRSRB6 = MRSRB7 = 0x00000030。

一个致命提醒：代码已经跑在 SDRAM 里时，绝对不能再去写 MRSRB。改模式寄存器会打断正在进行的访问，等于自己把脚下的地板抽掉。

3.8 SDRAM 初始化汇编（顺序不能乱） #

armasm
#define  BWSCON      0x48000000
#define  BANKCON0    0x48000004
#define  BANKCON6    0x4800001C
#define  BANKCON7    0x48000020
#define  REFRESH     0x48000024
#define  BANKSIZE    0x48000028
#define  MRSRB6      0x4800002C
#define  MRSRB7      0x48000030

memory_init:
    ldr r0, =BWSCON
    ldr r1, =0x02000000       /* Bank6: 32 位宽 */
    str r1, [r0]

    ldr r1, =0x00000700       /* BANKCON0~5 全用默认时序 */
    str r1, [r0, #0x04]
    str r1, [r0, #0x08]
    str r1, [r0, #0x0C]
    str r1, [r0, #0x10]
    str r1, [r0, #0x14]
    str r1, [r0, #0x18]

    ldr r1, =0x00018005       /* BANKCON6: SDRAM + Trcd=3 + SCAN=9位 */
    str r1, [r0, #0x1C]
    str r1, [r0, #0x20]       /* BANKCON7 同 */

    ldr r1, =0x008C04F5       /* REFRESH: 自动刷新, count=1269 */
    str r1, [r0, #0x24]

    ldr r1, =0x000000B1       /* BANKSIZE: 开突发, Bank6/7 各 64MB */
    str r1, [r0, #0x28]

    ldr r1, =0x00000030       /* MRSRB6/7: CL=3 */
    str r1, [r0, #0x2C]
    str r1, [r0, #0x30]
    mov pc, lr

顺序为什么不能乱：BWSCON 定宽度 → BANKCON 定时序 → REFRESH 定刷新 → BANKSIZE 定大小 → MRSRB 最后写模式寄存器。MRSRB 必须最后，因为它是「让 SDRAM 真正进入工作模式」的那一步，前面参数没配好就写等于用错误配置启动芯片。

3.9 超过 4KB 之后必须搬到 SDRAM #

NAND 启动时硬件只把前 4KB 复制到片内 SRAM。超过 4KB 的代码必须先初始化 SDRAM 再手动搬：

c
void copy_nand_to_sdram(void)
{
    extern int __code_start, __bss_start;
    volatile u32 *dest = (volatile u32 *)&__code_start;
    volatile u32 *end  = (volatile u32 *)&__bss_start;
    volatile u32 *src  = (volatile u32 *)0;
    u32 len = (u32)(&__bss_start) - (u32)(&__code_start);

    if (is_boot_from_nor_flash())
    {
        while (dest < end)      /* NOR 可直接当内存读 */
            *dest++ = *src++;
    }
    else
    {
        nand_init();            /* NAND 必须走控制器 */
        nand_chip.nand_read_data(dest, (u32)src, len);
    }
}

调用顺序：

armasm
    bl  memory_init          /* 先有 SDRAM */
    bl  stack_init           /* 才有栈 */
    bl  bss_init             /* 清 bss */
    bl  copy_nand_to_sdram   /* 再搬代码（依赖栈和 nand_chip） */
    ldr pc, =main            /* 跳到 SDRAM 里执行 */

3.10 4KB 阶段的四条铁律 #

  1. ldr pc, =main 之前的所有代码必须不超过 4KB；
  2. 不能用 rodata/data 段数据——尤其串口打印字符串。如果它还在 NAND 里没搬进来，读出来是垃圾，症状是串口乱码甚至程序跑飞；
  3. 全局变量在 bss 段，bss 初始化必须在 SDRAM 初始化之后；nand_chip 这个函数指针结构体就是典型，bss 没清就调用，跳的是随机地址；
  4. 代码必须是位置无关码，否则搬完跳过去就飞。

四、MMU：从物理地址到虚拟地址 #

4.1 为什么需要 MMU #

多进程下直接访问物理地址会互相破坏：A 进程用 0x40000 存了个变量，B 进程不知情也在 0x40000 写东西，两边一起崩。

解法是给每个进程一套独立的 4GB 虚拟地址空间，由 MMU 做「虚拟地址 → 物理地址」的翻译。这样每个进程都以为自己独占内存。

一个常被搞混的点：x86 才有逻辑地址/线性地址的概念（因为分段机制）；ARM 没有分段，逻辑地址、线性地址、虚拟地址是同一个东西。

4.2 三级地址：VA / MVA / PA #

ARM920T 里地址要走三步：

text
CPU 核发出的虚拟地址  VA
        │  加上进程号 PID
        ▼
修改过的虚拟地址    MVA   ← cache 和 MMU 只看这个
        │  查页表
        ▼
物理地址            PA    ← 外设/内存只认这个

为什么要有 MVA 这一层：多个进程的链接地址可能完全相同（都从 0xB0000000 开始），如果直接拿 VA 查页表就会撞车。加上 PID 后 MVA 自然不重叠。

VA → MVA 的规则（PID 从 CP15 C13 读）：

c
if (VA < 32M)
    MVA = VA | (PID << 25);
else
    MVA = VA;

4.3 ARM920T MMU 的四个概念 #

概念 内容
映射粒度 1MB 段（section）、64KB 大页、4KB 小页、1KB 极小页
域 Domain 16 个域，每域 2 位权限，定义在 CP15 C3
TLB 页表的 cache（快表），清 TLB 用 CP15 C8，锁 TLB 用 CP15 C10
双 MMU 指令 MMU 与数据 MMU 独立

域权限编码（CP15 C3 每域 2 位）：

  • 00 = 不可访问（任何访问都产生 domain fault）；
  • 01 = client，访问需检查页表里的 AP 权限；
  • 10 = 保留；
  • 11 = manager，不检查权限（裸机最常用，直接全放开）。

4.4 一级页表与描述符 #

页表基址放在 TTB（Translation Table Base），写入 CP15 C2。读 TTB 时低 14 位被硬件清零，所以页表必须 16KB 对齐（实际上要求 1MB 对齐更省事）。

一级页表最多 4096 项 × 32 位，每项描述 1MB → 覆盖 4GB。索引取 MVA[31:20]。

描述符末两位决定类型：

末两位 类型 后续
10 段（section） 描述符[31:20] 就是物理段基址，加 MVA[19:0] 得 PA
01 粗页（coarse） 去查二级页表
11 细页（fine） 描述符[31:12] + MVA[19:10] 定位二级页表项

二级页表 1024 项，二级描述符末两位：

末两位 页大小 物理地址拼法
01 64KB 大页 描述符[31:16] + MVA[15:0]
10 4KB 小页 描述符[31:12] + MVA[11:0]
11 1KB 极小页 描述符[31:10] + MVA[9:0]

为什么需要两级页表：如果只有一级、每项 4KB，每个进程要 1M 项 × 4 字节 = 4MB 且必须连续，不现实。两级页表可以把二级页表离散分配，并且只把当前需要的部分放内存。

4.5 段描述符的编码 #

一个 1MB 段描述符由几部分拼成：

c
#define MMU_SECDESC_AP       (3<<10)   /* AP：全权限 */
#define MMU_SECDESC_DOMAIN   (0<<5)    /* 域 0 */
#define MMU_SECDESC_NCNB     (0<<2)    /* Non-cacheable, Non-bufferable */
#define MMU_SECDESC_WB       (3<<2)    /* Write Back, Write Allocate */
#define MMU_SECDESC_TYPE     ((1<<4) | (1<<1))   /* 段描述符：末两位 = 10 */

#define MMU_SECDESC_FOR_IO   (MMU_SECDESC_AP | MMU_SECDESC_DOMAIN | MMU_SECDESC_NCNB | MMU_SECDESC_TYPE)
#define MMU_SECDESC_FOR_MEM  (MMU_SECDESC_AP | MMU_SECDESC_DOMAIN | MMU_SECDESC_WB   | MMU_SECDESC_TYPE)

注意 C/B 位（bit3/bit2）：

  • C=0, B=0（NCNB）：不走 cache，也不走写缓冲。所有 I/O 寄存器必须这样配；
  • C=1, B=1（Write Back）：走 cache，写只进 cache。内存段这样配性能最好。

漏配的后果：给寄存器段开了 cache，你会发现「写了寄存器但外设没反应」——因为写只进了 cache 没到总线上；或者「读状态寄存器永远读到旧值」。

4.6 建页表 #

c
void create_page_table(void)
{
    /* 页表放在哪：一块没用到的内存，必须对齐 */
    unsigned int *ttb = (unsigned int *)0x32000000;

    /* 1. 0 地址段：SRAM（NAND 启动）或 NOR Flash */
    create_secdesc(ttb, 0, 0, IO);

    /* 2. 片内 SRAM（NOR 启动时用） */
    create_secdesc(ttb, 0x40000000, 0x40000000, MEM);

    /* 3. 64MB SDRAM：0x30000000 ~ 0x33FFFFFF */
    for (va = 0x30000000; va < 0x34000000; va += 0x100000)
        create_secdesc(ttb, va, va, MEM);

    /* 4. 寄存器段：0x48000000 ~ 0x5B000000 */
    for (va = 0x48000000; va <= 0x5B000000; va += 0x100000)
        create_secdesc(ttb, va, va, IO);

    /* 5. Framebuffer */
    create_secdesc(ttb, 0x33c00000, 0x33c00000, IO);

    /* 6. 链接地址映射：虚拟 0xB0000000 → 物理 0x30000000 */
    create_secdesc(ttb, 0xB0000000, 0x30000000, MEM);
}

第 1 条为什么必须用 NCNB：因为后面还要靠「写 0 地址再读回」判断 NOR/NAND 启动。如果 0 地址段开了 cache 和 write buffer，写进去的数据只停在 cache 里，读回来必然一样 → 永远判成 NAND 启动 → 后续全错。

还有个小细节：寄存器段上界写 0x5B000000 而不是手册上的 0x5B00001C，因为段映射必须 1MB 对齐，向上取整。

4.7 写 TTB、设域、开 MMU #

armasm
/* 1. 把页表基地址写进 CP15 C2 */
ldr r0, =0x32000000
mcr p15, 0, r0, c2, c0, 0

/* 2. 16 个域全部设为 manager（不检查权限） */
ldr r0, =0xffffffff
mcr p15, 0, r0, c3, c0, 0

/* 3. 使能 I-Cache / D-Cache / MMU */
mrc p15, 0, r0, c1, c0, 0
orr r0, r0, #(1<<12)     /* I-Cache */
orr r0, r0, #(1<<2)      /* D-Cache */
orr r0, r0, #(1<<0)      /* MMU     */
mcr p15, 0, r0, c1, c0, 0

也就是说，开 MMU 总共两步：内存里建好页表 + 把基址写进 TTB → 置 C1 的 bit0。顺手把 I/D-Cache 一起打开（bit12 / bit2）。

4.8 Cache 的三条纪律 #

裸机最容易忽略 Cache，然后在 DMA 上栽跟头。三个概念先分清：

  • 清空 clean：把 cache 与 write buffer 里的脏数据写回主存；
  • 使无效 invalidate：把 cache 内容置为不可用，不写回；
  • Write Through / Write Back：一更新就写回主存 / 只写 cache，等被换出时再写回。

三条纪律：

  1. 关 MMU 前必须清空 I/D Cache，否则 dirty 数据跟着一起丢；
  2. 代码有改动 → 使无效 I-Cache，否则 CPU 还在取旧指令；
  3. DMA 涉及的内存：发送前 clean（确保数据真的到内存），接收后 invalidate（丢弃 cache 里的旧副本）。

第 3 条如果漏了，症状是「DMA 说传完了但数据是旧的」或「DMA 收到了但 CPU 读到旧值」——这类问题极难查，因为它依赖时序。

五、NAND Flash 编程 #

5.1 先理解 NAND 和内存的本质差别 #

NOR Flash 可以像内存一样随机读，甚至直接在上面执行代码（XIP）。NAND 不行：

  • 读以页为单位（本板 2KB/页）；
  • 擦除以块为单位（本板 128KB/块 = 64 页）；
  • 用 8 根 I/O 线串行传命令、地址、数据，不能直接寻址；
  • 同一块要写，必须先整块擦除。

所以每次访问一页，都必须重新发一遍「命令 + 5 周期地址 + 再一条命令」，然后连续读 2KB。这是 NAND 编程和内存读写最大的思维差异。

5.2 信号与命令 #

信号 含义
ALE 高 传的是地址
CLE 高 传的是命令
ALE、CLE 都低 传的是数据
CE# 片选，低有效
RE# / WE# 读使能 / 写使能，低有效

常用命令序列：

操作 序列
读 ID 90h + 地址 00h + 连读 5 周期
页读 00h + 5 周期地址 + 30h + 等忙 + 连续读
块擦除 60h + 行地址 + D0h + 等忙 + 70h 读状态
页写 80h + 5 周期地址 + 写数据 + 10h + 等忙 + 70h 读状态
复位 FFh

5.3 5 周期地址怎么拆分 #

c
col  = addr & NAND_PAGE_MASK_SIZE;   /* 页内偏移 */
page = addr / NAND_PAGE_SIZE;        /* 页号 */

_nand_write_addr_byte(col & 0xff);         /* 列地址 A0~A7   */
_nand_write_addr_byte((col >> 8) & 0x0f);  /* 列地址 A8~A11  */
_nand_write_addr_byte(page & 0xff);        /* 行地址 A12~A19 */
_nand_write_addr_byte((page >> 8) & 0xff); /* 行地址 A20~A27 */
_nand_write_addr_byte((page >> 16) & 0x01);/* 行地址 A28     */

前 2 周期是列地址（页内偏移），后 3 周期是行地址（页号）。

  • 列地址 A0–A10 是页内偏移（0–2047）；A11 用来选 OOB 区（2048–2111，共 64 字节）；
  • 行地址 28 位，最大支持 2^28 页 × 2KB = 512GB（远超实际芯片容量）。

5.4 寄存器与初始化 #

控制器基址 0x4E000000：

寄存器 偏移 作用
NFCONF 0x00 时序配置
NFCONT 0x04 控制（使能/片选/ECC）
NFCMMD 0x08 命令（8 位）
NFADDR 0x0C 地址（8 位）
NFDATA 0x10 数据（8 位）
NFSTAT 0x20 状态
NFMECC0/1 0x2C/0x30 主区 ECC
NFSECC 0x34 备份区 ECC

控制器替你做时序：软件只管往 NFCMMD / NFADDR / NFDATA 写，CLE/ALE/RE/WE 的电平由硬件按 NFCONF 自动产生。这是 2440 比「用 GPIO 手工翻转」省事的地方。

NFCONF 的三个时序参数（HCLK=100MHz，T=10ns）：

参数 公式 手册最小值 取值 实际
TACLS max(tCLS, tALS) − tWP 12ns 0 HCLK×0
TWRPH0 tWP 12ns 1 HCLK×(1+1)=20ns
TWRPH1 max(tCLH, tALH) 5ns 0 HCLK×(0+1)=10ns 
c
#define TACLS   0
#define TWRPH0  1
#define TWRPH1  0

NFCONF = (TACLS<<12) | (TWRPH0<<8) | (TWRPH1<<4);
NFCONT = (1<<4) | (1<<1) | (1<<0);   /* InitECC | 强制片选高 | 使能控制器 */

关于 NFCONT 有个细节：网上很多代码写 (1<<1)|(1<<0)，读写也能工作。差的是 bit4 = InitECC，它初始化 ECC 编码器。不初始化 ECC 也能读写数据，但拿到的 ECC 值是无效的。要读 ECC 还得先解锁 MainECCLock（bit6，默认就是 1 即锁定）。

5.5 三个必须知道的位 #

  1. NFSTAT[0] = BUSY：0 = NAND 忙，1 = 就绪。这是反的（多数芯片是 1 忙），写等待函数时特别容易搞错：
c
void _nand_wait_idle(void)
{
    int i;
    while (!(NFSTAT & BUSY));   /* 等 BUSY 位变 1，即就绪 */
    for (i = 0; i < 10; i++);   /* 再空转几个周期满足 tRR */
}

  1. Lock-tight[3]：一旦置 1 软件就再也清不掉，只有复位或睡眠唤醒能解。锁定后 NFSBLK~NFEBLK 之外的区域写/擦全部无效，只能读。这是保护 bootloader 区的机制，调试时千万不要随手置位。

  2. 复位时硬件锁存的只读位：AdvFlash 由 NCON0 决定，PageSize 由 GPG13 决定，AddrCycle 由 GPG14 决定。这些脚在上电那一刻被采样，决定了控制器认为的页大小和地址周期数。Mini2440 上 GPG13/14/15 接了固定电平，所以不用管；自己画板时接错了，NAND 就完全读不出来。

5.6 读 ID：验证接线是否通 #

c
_nand_write_cmd(0x90);       /* READ ID */
_nand_write_addr_byte(0x00); /* 地址 0 */
for (i = 0; i < 5; i++)
    buf[i] = _nand_read_data();
/* buf = EC DA 10 95 44 */

解读：

  • 0xEC = 制造商 Samsung；
  • 0xDA = 器件号；
  • 第 4 字节 0x95：page_size = 1 << (0x95 & 0x03) = 1 << 1 = 2KB；
  • 第 5 字节 0x44：block 128KB、2 个 plane、每 plane 1Gb = 128MB、共 256MB。

对应头文件注释 K9F2G08U0C 258M 28位地址。

5.7 页读 / 块擦除 / 页写 #

c
int nand_read_data(u8 *buf, u32 start_addr, u32 size)
{
    int i = 0, j = 0;

    if (start_addr & NAND_PAGE_MASK_SIZE)
        return -1;                      /* 必须页对齐 */

    _nand_select_chip();

    while (i < size)
    {
        _nand_write_cmd(0x00);          /* 页读命令 */
        _nand_write_addr(start_addr + i);
        _nand_write_cmd(0x30);          /* 启动传输 */
        _nand_wait_idle();

        for (; j < NAND_PAGE_SIZE && i < size; j++)
            buf[i++] = _nand_read_data();
        j = 0;
    }

    _nand_deselect_chip();
    return 0;
}

注意 while 循环里每读一页都重发 0x00 + 地址 + 0x30。写成「发一次命令然后连读多页」是错的——NAND 内部地址不会跨页自动递增到你期望的位置。

块擦除：

c
int nand_block_erase(u32 start_addr, u32 size)
{
    int i, page;

    if ((start_addr & NAND_BLOCK_MASK_SIZE) || (size & NAND_BLOCK_MASK_SIZE))
        return -1;                      /* 必须块对齐 */

    _nand_select_chip();

    for (i = start_addr; i < start_addr + size; i += NAND_BLOCK_SIZE)
    {
        page = i / NAND_PAGE_SIZE;
        _nand_write_cmd(0x60);
        _nand_write_addr_byte(page & 0xff);         /* 只发行地址，不发列地址 */
        _nand_write_addr_byte((page >> 8) & 0xff);
        _nand_write_addr_byte((page >> 16) & 0x01);
        _nand_write_cmd(0xD0);
        _nand_wait_idle();

        _nand_write_cmd(0x70);                      /* 读状态 */
        if (_nand_read_data() & 0x1)
            return -1;                              /* 状态位 0 = 失败 */
    }

    _nand_deselect_chip();
    return 0;
}

两个容易错的地方：

  1. 擦除只发 3 个行地址字节，不发列地址（擦除以块为单位，页内偏移没意义）；
  2. 擦完必须发 0x70 读状态，状态字节 bit0 = 1 表示失败（写保护或坏块）。不查这个位，坏块会静默失败。

5.8 结构体 + 函数指针：裸机里最像驱动的写法 #

c
typedef struct {
    void (*_nand_reset)(void);
    void (*_nand_wait_idle)(void);
    void (*_nand_select_chip)(void);
    void (*_nand_deselect_chip)(void);
    void (*_nand_write_cmd)(u32 cmd);
    void (*_nand_write_addr)(u32 addr);
    u8   (*_nand_read_data)(void);

    int  (*nand_read_data)(u8 *buf, u32 start_addr, u32 size);
    void (*nand_read_id)(u8 *buf);
    int  (*nand_block_erase)(u32 start_addr, u32 size);
    int  (*nand_write_data)(u32 start_addr, u8 *buf, u32 size);
} t_nand_chip;

extern t_nand_chip nand_chip;
extern void nand_init(void);

前七个是「原子操作」，后四个是「完整命令」。这样分层的好处是：写后面四个时只需要考虑「先发什么命令、再发什么地址」，不用关心控制器细节。

一个必踩的坑：nand_chip 是全局变量，落在 bss 段。如果 bss 没初始化就调用 nand_chip.nand_read_data(...)，跳过去的是随机地址。所以调用顺序必须是 bss_init() → nand_init() → 使用。

5.9 NAND 的五条经验 #

  1. 每次读写一页都要重发命令和地址，不能跨页连续；
  2. 读写按页对齐，擦除按块对齐，不对齐直接返回 -1，别硬凑；
  3. NFSTAT[0] 是「1=就绪」，与多数芯片相反；
  4. 擦完/写完必须读状态（0x70），bit0 是失败标志；
  5. 命令与地址之间要留建立/保持时间，for(i=0;i<10;i++); 这种空转不是凑数，是满足 tADL 等参数。

六、ROM / RAM / Flash：为什么嵌入式离不开这三种存储器 #

6.1 三种存储器的定位 #

类型 断电 速度 典型用途
RAM 丢失 最快 运行时数据
ROM 保持 慢 固件、BIOS
Flash 保持 中等 程序存储、U 盘

RAM 再分两类：

  • SRAM（静态）：速度最快、极贵，用于 CPU 的 L1/L2 Cache；
  • DRAM（动态）：慢于 SRAM 但快于任何 ROM，便宜得多，计算机内存就是它。靠电容存电荷，必须周期性刷新（这就是上一篇 DRAM 原理：从存储单元到内存阵列 讲的内容）。

DRAM 家族：FPRAM、EDORAM、SDRAM、DDR SDRAM、RDRAM、SGRAM、WRAM。其中 DDR 靠「一个时钟读写两次」把带宽翻倍。

ROM 家族：

  • PROM：一次性编程；
  • EPROM：紫外光擦除；
  • EEPROM：电擦除，可按字节擦写，但贵且慢；
  • Flash ROM：介于 EPROM 与 EEPROM 之间，靠浮置栅电容存电荷（不漏电→断电保持），擦除以 sector 为单位，写入可以按字节。

还有一类容易忽略的 PSRAM（伪 SRAM）：内部是 DRAM 颗粒，外部给 SRAM 接口，不需要 SDRAM 那样复杂的控制器和刷新逻辑，容量 4~128MB，功耗远低于 SDRAM，常见于手机、PDA、MP3。

6.2 NOR 与 NAND 全面对比 #

维度 NOR NAND

历史：Intel 1988 年推出 NOR，东芝 1989 年发表 NAND。两者的分工从此固定下来：NOR 跑代码，NAND 存数据。

6.3 2440 为什么能从 NAND 启动 #

绝大多数芯片不能直接从 NAND 启动（因为 NAND 不能 XIP），开发板一般要另加一片小 NOR 放启动代码。

S3C2440 是个例外：它靠 NAND 控制器 + 4KB Steppingstone，上电时硬件自动把 NAND 前 4KB 复制到片内 SRAM 并重映射到 0x00。

这一句话解释了本文前面出现过的三个现象：

  1. 为什么 NAND 启动的引导代码必须在 4KB 内；
  2. 为什么「往 0 地址写值再读回」能判断启动介质（NAND 时 0 地址是 SRAM 可写）；
  3. 为什么栈只能放在 0x1000（4KB SRAM 顶端）。

Mini2440 板上同时有 2MB NOR + 256MB NAND，正是「NOR 启动 + NAND 存数据」这个经典组合的实例。

七、踩坑清单 #

  1. 不写 MPLLCON，PLL 输出永远进不了系统——即使你不想改频率也得写一遍。
  2. 必须先 UPLL 后 MPLL，中间隔 7 个 nop。
  3. HDIVN≠0 时必须切异步总线模式（CP15 C1 置 bit31/bit30），否则随机跑飞。
  4. HDIVN=10 的实际分频受 CAMDIVN[9] 影响，可能是 /4 也可能是 /8。
  5. SDRAM 只能挂 Bank6/7，Bank6/7 的 MT 位必须写 11；01/10 是保留值，写了不工作。
  6. MRSRB 必须最后写，且程序跑在 SDRAM 里之后绝不能再写。
  7. REFRESH 的 count 要按自己的 HCLK 重算，抄别人的值在别的频率下会掉数据。
  8. 0 地址段建页表必须用 NCNB，否则「写 0 地址判启动方式」永远判成 NAND。
  9. I/O 寄存器段必须 C=0/B=0，否则写寄存器没反应、读状态读旧值。
  10. DMA 用到的内存：发前 clean、收后 invalidate。
  11. NAND 每次读写一页都要重发命令+地址。
  12. NFSTAT[0] 是 1=就绪，反的。
  13. 擦除只发行地址，不发列地址。
  14. 擦写后必须读 0x70 状态，bit0=1 是失败。
  15. Lock-tight 位置 1 之后软件清不掉，只有复位能解，别乱写。
  16. nand_chip 在 bss 段，bss 没清就用函数指针 = 跳随机地址。
  17. 4KB 阶段的代码不能用 rodata（尤其打印字符串），否则串口乱码。

小结 #

这篇的五步其实是同一条主线：把一颗只会"从 0 地址取指、按 12MHz 跑"的芯片，改造成"能跑 400MHz、有 64MB 内存、有虚拟地址、能读外部存储"的完整系统。

每一步都在做同一件事：写一组寄存器，告诉硬件"我想要的世界长什么样"。区别只在于：

  • 时钟是频率的世界；
  • SDRAM 是时序的世界（差一个时钟周期就读不出数据）；
  • MMU 是地址的世界；
  • NAND 是命令序列的世界。

理解了这个共性，剩下的就是查手册填数字。
