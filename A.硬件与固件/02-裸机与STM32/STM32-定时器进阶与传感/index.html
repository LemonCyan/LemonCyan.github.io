一、PWM 输出 #

1.1 原理：比较匹配决定翻转 #

PWM 的本质是一个计数器 + 一个比较值：

text
CNT 从 0 计到 ARR（自动重装载），然后回 0
当 CNT < CCRx 时输出一种电平，CNT >= CCRx 时输出另一种

于是：

fPWM​=(ARR+1)×(PSC+1)fTIM​​,占空比=ARR+1CCR​

两种常用模式：

模式 CCMR 编码 CNT<CCR CNT>=CCR
PWM 模式 1 110 有效电平 无效电平
PWM 模式 2 111 无效电平 有效电平

模式 1 和模式 2 是互补的，选哪个取决于「有效电平」是高还是低。驱动低电平点亮的 LED 时用模式 2 更符合直觉。

1.2 通道寄存器一览（以 TIM3 通道 1 为例） #

寄存器 关键位 含义
CCMR1 [1:0] CC1S 通道方向：00 输出、01 输入
CCMR1 [3] OC1PE 预装载使能（改 CCR 时不撕裂波形）
CCMR1 [6:4] OC1M 111 = PWM 模式 2
CCER bit0 CC1E 通道使能
CCER bit1 CC1P 输出极性：1 = 低电平有效
CCER bit2 CC1NE 互补通道使能（仅高级定时器）
CCER bit3 CC1NP 互补通道极性

原文里 CCER = 0x0F 就是把 CC1E + CC1P + CC1NE + CC1NP 四位全置 1：通道使能、低有效、互补使能、互补也低有效。

1.3 高级定时器必须多开一位 #

TIM1/TIM8 是高级定时器，多一个刹车与死区寄存器 BDTR。它的 bit15 是主输出使能 MOE，不置这一位，PWM 波形根本出不来：

c
TIM1->BDTR |= 1 << 15;   /* MOE，高级定时器必须有这一句 */

排查顺序：波形没出 → 先看 MOE → 再看 CCER 的 CCxE → 再看 CCMR 的模式位 → 最后看引脚是否配成复用推挽。

1.4 完整配置（TIM3_CH1 = PB4） #

c
void TIM3_PWM_Init(u16 arr, u16 psc)
{
    /* 1. 时钟：TIM3 在 APB1，GPIOB 在 APB2 */
    RCC->APB1ENR |= 1<<1;
    RCC->APB2ENR |= 1<<3;

    /* 2. PB4 复用推挽输出 50MHz（CNF=10 MODE=11 → 0xB） */
    GPIOB->CRL &= 0xFFF0FFFF;
    GPIOB->CRL |= 0x000B0000;

    /* 3. 时基 */
    TIM3->ARR = arr;
    TIM3->PSC = psc;

    /* 4. 通道 1：PWM 模式 2 + 预装载 */
    TIM3->CCMR1 &= ~(7<<4);
    TIM3->CCMR1 |=  (7<<4);      /* OC1M = 111 */
    TIM3->CCMR1 |=  (1<<3);      /* OC1PE */

    /* 5. 使能通道 + 低有效 */
    TIM3->CCER |= (1<<0) | (1<<1);

    /* 6. 初始占空比 */
    TIM3->CCR1 = (arr+1) / 2;

    /* 7. 启动 */
    TIM3->CR1 |= 1<<0;
    TIM3->CR1 |= 1<<7;           /* ARPE 自动重装载预装载 */
}

1.5 一个必须校准的实测 #

原文的实测记录里有个矛盾：文字结论写「50% 占空比得到 10kHz」，但同一段的实测描述是「一个完整周期约 10us」。

10us 周期的频率是 100kHz，不是 10kHz。 重算一遍就清楚了：若 PSC=71（72MHz/72=1MHz），ARR=9，则

f=101MHz​=100kHz

所以实测的 10us 是对的，文字结论的 10kHz 是笔误。写代码时信公式，别信结论里的数字——这类错误在教程里非常常见，建议每次都用示波器复核一遍。

1.6 频率与占空比的算法 #

给定目标频率，反推 ARR：

c
/* fclk：定时器时钟（APB1 分频≠1 时是 2×PCLK）*/
/* frequent：目标频率（kHz）*/
arr = fclk * 1000 / (PSC + 1) / frequent - 1;

占空比：

c
TIM3->CCR1 = (arr + 1) * duty / 100;   /* duty 是百分比 */

要平滑调光/调速，ARR 取大一些（比如 999），PSC 取小一些——分辨率高，但频率低。反过来 100kHz 以上就要牺牲分辨率。

二、输入捕获：测量外部信号的频率和脉宽 #

2.1 链路：五个环节 #

text
外部引脚
  → TIx（通道输入，可能含反相）
  → ICxF 数字滤波（抗抖动）
  → 边沿检测器（上升沿/下降沿/双边沿）
  → ICxPSC 捕获预分频（每 N 个边沿才捕获一次）
  → CCRx 锁存当前 CNT 值

捕获发生时硬件会把 CNT 复制进 CCRx 并置 CCxIF 标志；如果 CCRx 还没读走就又捕获了一次，会置溢出标志 CCxOF，说明「你测得太慢，数据丢了」。

2.2 预分频与分辨率 #

要测 1MHz 的信号（1us 分辨率），把捕获时钟压到 1MHz：

c
TIM3->PSC = 71;      /* 72MHz / (71+1) = 1MHz，每计数 = 1us */

2.3 数字滤波 #

IC1F=3 表示「以 fCK_INT 采样，连续 8 次都是同一电平才认」，即采样频率 = fCK_INT/8，N=8。机械按键、电机编码器这类有抖动的信号必须开滤波，否则一次动作会被捕获很多次。

2.4 测高电平脉宽：状态机 + 两次捕获 #

用例是「捕获一个高电平脉宽」，思路是：上升沿进中断记下 CCR，切下降沿；下降沿进中断再记 CCR，两次相减。

c
u8  TIM3CH1_CAPTURE_STA = 0;   /* bit7 完成 bit6 已捕获上升沿 bit5~0 溢出次数 */
u16 TIM3CH1_CAPTURE_VAL = 0;

void TIM3_IRQHandler(void)
{
    if (TIM3CH1_CAPTURE_STA & 0x80)            /* 已经测完了 */
    {
        TIM3->SR = 0;
        return;
    }

    if (TIM3->SR & 0x01)                        /* 更新溢出 */
    {
        if ((TIM3CH1_CAPTURE_STA & 0x3F) == 0x3F)
            TIM3CH1_CAPTURE_STA |= 0x80;        /* 溢出太多次，硬置完成 */
        else
            TIM3CH1_CAPTURE_STA++;              /* 溢出次数 +1 */
    }

    if (TIM3->SR & 0x02)                        /* 通道 1 捕获 */
    {
        if (TIM3CH1_CAPTURE_STA & 0x40)         /* 已经捕获到上升沿 */
        {
            /* 下降沿：算脉宽 */
            TIM3CH1_CAPTURE_STA |= 0x80;
            TIM3CH1_CAPTURE_VAL = TIM3->CCR1;
            /* 切回上升沿，准备下一次 */
            TIM3->CCER &= ~(1<<1);              /* 先清 */
            TIM3->CCER |=  (0<<1);              /* 再写上升沿 */
        }
        else                                    /* 第一次：上升沿 */
        {
            TIM3CH1_CAPTURE_STA = 0;            /* 清溢出计数 */
            TIM3CH1_CAPTURE_VAL = TIM3->CCR1;
            TIM3CH1_CAPTURE_STA |= 0x40;
            TIM3->CNT = 0;                      /* 关键：清零计数器 */
            /* 切成下降沿 */
            TIM3->CCER &= ~(1<<1);
            TIM3->CCER |=  (1<<1);
        }
    }
    TIM3->SR = 0;
}

三个不能省的细节：

  1. 捕获到上升沿后必须把 CNT 清零。否则下一次溢出计数就不准了，脉宽算出来会多出「已经走过的那一段」。
  2. 改极性必须先 &=~ 再 |=。直接 |= 只能把 0 变 1，切不回上升沿。
  3. 溢出计数上限判断：(STA & 0x3F) == 0x3F 时就置完成位，防止溢出永远数不完。

最终脉宽：

脉宽=溢出次数×65536+CCRx​

因为计数到 ARR=0xFFFF 时每次溢出就是 65536 个计数单位。原文实测 262us（初稿写 258us），差的那 4us 是中断响应延迟和滤波带来的系统性偏差——测脉宽的结果只能当工程近似值，要精确得用硬件捕获+DMA，或者干脆用示波器。

2.5 一个向量名的坑 #

定时器 更新中断向量 捕获中断向量
TIM1 / TIM8 TIM1_UP_IRQn TIM1_CC_IRQn（独立）
TIM2~TIM5 TIMx_IRQn 共用同一个

高级定时器把「更新」和「捕获/比较」拆成了两个中断向量，通用定时器只有一个。名字写错编译照样通过，但中断永远不进——这类 bug 非常难查，因为没有报错。

2.6 测频率 #

测频率有两条路，各有适用场景：

方法 原理 适用
测周法 捕获两个相邻上升沿之间的计数值，f = 时钟/计数值 低频（<1MHz），精度高
计数法 固定闸门时间（比如 1 秒）内数上升沿次数 高频

测周法在低频时精度极高（1us 分辨率下 1kHz 信号误差 0.1%），但高频时计数值太小、误差放大；计数法反过来。

三、编码器模式：直接数转速 #

3.1 增量式编码器输出什么 #

增量式编码器输出 A、B 两路方波，相位差 90°。正转时序：

text
正转： A=1,B=1 → A=0,B=1 → A=0,B=0 → A=1,B=0 → 回到 (1,1)
       11    →   01    →   00    →   10
反转： 11    →   10    →   00    →   01

A 和 B 的先后顺序就代表了方向，这就是「正交编码」名字的来源。

3.2 硬件解码：SMS=011 #

STM32 的定时器自带编码器接口，完全不用软件干预：

c
void TIM4_Encoder_Init(void)
{
    RCC->APB1ENR |= 1<<2;              /* TIM4 */
    RCC->APB2ENR |= 1<<3;              /* GPIOB */

    /* PB6 = TIM4_CH1, PB7 = TIM4_CH2，浮空输入 */
    GPIOB->CRL &= 0x00FFFFFF;
    GPIOB->CRL |= 0x44000000;

    TIM4->ARR = 0xFFFF;
    TIM4->PSC = 0;                     /* 编码器模式不分频 */

    /* SMS = 011：编码器模式 3，A/B 双边沿都计数 */
    TIM4->SMCR &= ~(7<<0);
    TIM4->SMCR |=  (3<<0);

    /* 输入滤波，抖动大的编码器必须加 */
    TIM4->CCMR1 |= (1<<0) | (1<<8);    /* CC1S=01, CC2S=01 */
    TIM4->CCMR1 |= (3<<4) | (3<<12);   /* IC1F=3, IC2F=3 */

    TIM4->CR1 |= 1<<0;                 /* 启动 */
}

三种编码器模式的差别：

SMS 模式 计数倍频
001 编码器模式 1 只在 TI1 边沿计数，1 倍频
010 编码器模式 2 只在 TI2 边沿计数，1 倍频
011 编码器模式 3 TI1 和 TI2 边沿都计数，4 倍频

模式 3 最准，因为每个周期有 4 个边沿可数。所以实际分辨率是「编码器线数 × 4」：

c
delta = 本次读数 - 上次读数;   /* 无符号要注意回绕 */
真实脉冲数 = delta / 4;

3.3 转速公式 #

text
转速(rpm) = (delta / 4 / 编码器线数) × (1000 / 采样周期ms) × 60

用代码写：

c
rpm = (delta / 4.0) / resolution * 1000.0 / period_ms * 60.0;

3.4 一个实测偏差与它的原因 #

原文的实测数据是：13% 占空比下测得 1207 rpm，而外部转速分析仪显示 1065 rpm，偏差 13%。

原因有三个，按可能性排序：

  1. 编码器线数填错（标称值和实际值不一致，最常见）；
  2. 采样周期不是严格的 period_ms——如果放在主循环里、周期受其他任务影响，转速会系统性偏高；
  3. 少算了减速比（带齿轮箱的电机，输出轴转速 = 电机轴 / 减速比）。

要消除这个偏差，正确做法是用定时器的捕获/更新中断做等间隔采样，而不是在主循环里数。

3.5 必须共地 #

原文反复强调的一条：L298N 驱动板、开发板、编码器三者必须共地。不共地时电平参考不同，现象是「编码器读数乱跳、电机一转串口就重启」。这是电机类项目最常见的硬件故障。

四、RTC：独立供电的日历 #

4.1 F1 的 RTC 是「秒计数」模型 #

这里有个重要的版本差异必须先说清楚：

系列 RTC 模型 寄存器
F1 32 位秒计数器 PRL/CNT/ALR，没有 BCD
F4 / L4 日历（BCD） TR/DR，直接读年月日时分秒

原文里这两种模型混着写过（一部分段落用 F4 的 BCD 写法，一部分用 F1 的秒计数）。读代码时一定要先确认板上是哪颗芯片，别把 F4 的 RTC->TR 抄到 F1 上。这一篇按 F1 的秒计数模型写。

4.2 时钟源与约束 #

RTCCLK 来源 说明
HSE/128 用主晶振分频，精度取决于主晶振
LSE 32.768kHz 外部手表晶振，精度最高，推荐
LSI 约 40kHz 内部 RC，精度最差（可能差几个百分点）

两条硬约束：

  1. RTC 时钟必须 < PCLK1/4；
  2. 预分频器最长 2^20（PRL 是 20 位）。

LSE 32.768kHz ÷ 32768 = 1Hz，所以 PRLL = 32767。

4.3 备份域：四步解锁 #

RTC 和备份寄存器在备份域里，默认是写保护的。要写必须按顺序做四件事：

c
/* 1. 取消备份域写保护 */
RCC->APB1ENR |= 1<<28;        /* PWR 时钟 */
PWR->CR |= 1<<8;              /* DBP = 1，取消写保护 */

/* 2. 复位备份域（只做一次） */
RCC->BDCR |= 1<<16;           /* BDRST */
RCC->BDCR &= ~(1<<16);

/* 3. 选时钟源并使能 */
RCC->BDCR |= 1<<0;            /* LSEON */
while (!(RCC->BDCR & (1<<1)));/* 等 LSERDY */
RCC->BDCR |= 1<<8;            /* RTCSEL = 10：LSE */
RCC->BDCR |= 1<<15;           /* RTCEN */

RCC_BDCR 的位域：

位 名称 含义
16 BDRST 备份域软件复位
15 RTCEN RTC 时钟使能
9:8 RTCSEL 00 无、01 LSE、10 LSI、11 HSE/128
1 LSERDY LSE 就绪
0 LSEON LSE 使能

4.4 三个状态位的铁律 #

位 在哪 规则
RTOFF RTC->CRL bit5 必须为 1 才能写寄存器（上一次写已完成）
CNF RTC->CRL bit4 写之前置 1 进配置模式，写完清 0
RSF RTC->CRL bit3 必须为 1 才能读（寄存器已同步）

标准写法：

c
void rtc_wait_rtoff(void) { while (!(RTC->CRL & (1<<5))); }
void rtc_wait_rsf(void)   { while (!(RTC->CRL & (1<<3))); }

void rtc_set(u32 sec)
{
    rtc_wait_rtoff();
    RTC->CRL |= 1<<4;          /* 进配置模式 */
    rtc_wait_rtoff();
    RTC->CNTH = sec >> 16;
    RTC->CNTL = sec & 0xFFFF;
    RTC->CRL &= ~(1<<4);       /* 退出配置模式 */
    rtc_wait_rtoff();
}

4.5 用备份寄存器做「首次初始化」标记 #

问题：每次上电都重新设时间，那 RTC 就白做了（纽扣电池保的电被覆盖）。

解法：用一个备份寄存器当标记。备份寄存器在 VBAT 供电下也能保住内容：

c
#define RTC_MAGIC  0x5050

if (BKP->DR1 != RTC_MAGIC)
{
    /* 第一次上电或电池掉过：从头配置 */
    RCC->BDCR |= 1<<16;         /* 复位备份域 */
    RCC->BDCR &= ~(1<<16);
    /* ... 配 LSE、配 RTC ... */
    BKP->DR1 = RTC_MAGIC;
}
else
{
    /* 只是主电掉了，RTC 还在走，只要重新开 RTCEN */
    RCC->BDCR |= 1<<15;
}

F103 有 42 个 16 位备份寄存器（共 84 字节），掉电不丢（靠 VBAT），用来存校准参数、运行时长、故障码非常方便。

4.6 秒计数转日期 #

F1 的 RTC 只给一个「从 2000-01-01 00:00:00 起算的秒数」，转成年月日要自己算：

c
const u16 mon_table[12] = {31,28,31,30,31,30,31,31,30,31,30,31};
const u32 year_sec[2]  = {31536000, 31622400};   /* 平年 / 闰年 的秒数 */

u8 is_leap(u16 y)
{
    return ((y % 4 == 0) && (y % 100 != 0)) || (y % 400 == 0);
}

两个常量值：平年 365×86400 = 31536000，闰年 366×86400 = 31622400。算法是「先减整年，再减整月，剩下的除 86400 得日、除 3600 得时……」。

4.7 闹钟与唤醒 #

F1 的 RTC 闹钟只比较秒（ALR 寄存器），没有「几点几分」的语义。要按时间闹，得自己把目标时刻转成秒数再写进 ALR。

闹钟中断还需要外部中断线 17：

c
EXTI->IMR  |= 1<<17;
EXTI->RTSR |= 1<<17;
EXTI->PR    = 1<<17;        /* 写 1 清 */
/* NVIC 里使能 RTC_Alarm_IRQn */

忘了 EXTI17 的现象是「ALR 设了，但永远不进中断」——因为 RTC 的闹钟输出只是 EXTI 的一个内部输入源，不经过 EXTI 就到不了 NVIC。

五、案例：51 单片机 PWM 直流电机闭环调速 #

这个案例值得看，因为它是第一个把「PWM 输出」和「转速反馈」闭成一个环的例子，而且用的是一颗 8 位机，没有硬件 PWM、没有编码器接口，全靠软件实现。

5.1 硬件组成 #

部件 作用
51 单片机 产生 PWM + 计转速 + PID 运算
ULN2003 达林顿管阵列，扩流驱动电机（单片机 IO 带不动）
红外对射管 + 555 施密特 测转速，输出干净方波
直流电机 带码盘

555 那一级是点睛之笔：红外接收管输出的信号边沿很缓、带噪声，直接进单片机 IO 会多次触发。用 555 接成施密特触发器整形后，波形干净，计数器才数得准。

5.2 用定时器同时做「PWM 和计数」 #

51 的定时器 0 和 1 都要用，靠 TMOD=0x15 拆开工作方式：

text
TMOD = 0x15  →  高 4 位 0001：定时器 1 工作方式 1（16 位定时，做 PWM 周期）
                低 4 位 0101：定时器 0 工作方式 1（16 位计数，数外部脉冲）

PWM 实现：定时器 1 每 100us 中断一次，维护一个 0~100 的计数值；计数值小于「占空比目标值」时输出高，否则输出低。这样 100 次中断 = 10ms = 100Hz 的 PWM。

转速测量：定时器 0 工作在计数模式（TMOD 的低 4 位 0101 就是「计数器 + 方式 1」），外部脉冲从 T0 引脚进来，硬件自动加一。

5.3 一个必须注意的读取顺序 #

c
pulse_count = TH0 * 256 + TL0;

原文这里写的是 TH0 * 255 + TL0，这是错的。TH0 是高 8 位，权重是 256 不是 255。用 255 算出来的值会随高字节增大而线性偏小，转速越高误差越大——这种错误很难通过「看起来差不多」发现。

另外读 16 位计数器时必须先读 TH0 再读 TL0，并且在读之前可能要把 TR0 清零（或者在两次读之间检查是否溢出），否则可能读到「高字节还是旧的、低字节已经进位了」的撕裂值。

5.4 PID 参数 #

原文给的参数是：

参数 值
Kp 1.2
Ki 0.6
Kd 0.2

这是典型的「位置式 PID」初值。调参顺序永远是：先只开 P（Kp 由小到大，直到出现小幅振荡），再加 I（消静差，Ki 从 Kp 的 1/2 起步），最后加 D（抑制超调，Kd 一般最小）。

直接照抄这三个数在别的电机上不一定稳——它取决于电机功率、负载惯量、采样周期。电机越大，Kp 要越小。

5.5 这个案例暴露的通用问题 #

8 位机软 PWM + 软件计数，能跑但精度有限。对比 STM32 方案，差别一目了然：

项 51 软实现 STM32 硬实现
PWM 定时器中断里翻 IO CCR 寄存器，硬件自动输出
PWM 频率 100Hz（受中断开销限制） 可到 MHz
测速 定时器计数 + 软件换算 编码器接口硬件解码 4 倍频
方向判断 做不了 A/B 相位自动判断
CPU 占用 高（每 100us 一次中断） 接近 0

这也是为什么「学完 51 再学 STM32」是合理的路径：先理解原理（比较匹配、脉冲计数、PID），再换到硬件实现上去。

六、案例：STM32F411 智能手环（整机视角） #

前面两节都是单个外设。这一节看一个完整产品：OV-Watch 开源手环，主控 STM32F411CEU6，跑 FreeRTOS + LVGL。挑它的原因不是功能多，而是它把「低功耗」和「外设分工」这两件事做得很实在。

6.1 外设分工 #

外设 用途 关键点
SPI + DMA 刷屏 DMA 直发，CPU 不参与搬运，多任务下观感才流畅
I2C 所有传感器挂在同一条总线 MPU6050（六轴）、EM7028（心率血氧）、SPL06（气压）、LSM303（磁力计）、AHT21（温湿度）、BL24C02F（EEPROM）
TIM 系统时基 + LCD 背光调光 背光用 PWM，这是定时器最省事的用法
ADC 电池电量 只接一路分压，采出来估算剩余电量
USART 蓝牙模块 KT6368A，串口 AT 透传，做 IAP 和手机通信

6.2 电源链：为什么要 buck-boost #

锂电池电压范围 3.0~4.2V，而 MCU 要 3.3V。用普通 LDO 在电池掉到 3.3V 以下就没法工作了，所以要用升降压（buck-boost）：电压高时降压、低时升压，全程稳定 3.3V。

选的是 TPS63020，关键参数：

参数 值
输入 1.8~5.5V
输出 1.2~5.5V / 2A
静态电流 25µA（节能模式）

这里有个低功耗设计的核心技巧，在 TPS63020 的 PS/SYNC 引脚上：

PS/SYNC 模式 静态电流 带载能力
低电平 Power Save 25µA < 100mA
高电平/悬空 正常模式 7~8mA 4A

手环 99% 的时间在睡眠，所以设计上把 PS/SYNC 直接接地，常驻节能模式。代价是「干重活」（刷屏、蓝牙传输）时带载能力只有 100mA，需要软件在重活前把 PS/SYNC 拉高、干完再拉低。这是典型的用软件换功耗。

6.3 一个必须外置的看门狗 #

这是整个案例里最有价值的一条经验：

STM32F411 的内部看门狗 IWDG 在 STOP 模式下关不掉，只能一直唤醒喂狗，否则就会复位——这样就失去了睡眠的意义。

所以手环上额外加了一颗 TPS3823 外部看门狗：

引脚 连接
RST F411 复位脚
WDI PB2（喂狗脉冲）
WDOG_EN PB1（可关断）

这样 MCU 进 STOP 前把 WDOG_EN 拉低，外部看门狗自己停掉，不需要喂；醒来再打开。功耗敏感的产品，看门狗一定要外置，这是通用结论。

6.4 双区升级与那个致命的地址偏移 #

V2.4 版本把 Flash 分成两区：Bootloader + APP，中间还留了一个 Flag 区记录「APP 是否完整」（只有 APP 全部收完才写这个 Flag，保证不会跑一个残缺的固件）。

固件布局：

text
0x08000000 ~ 0x0800BFFF   Bootloader（48KB）
0x0800C000 ~ ...          APP

只在调试 APP、不烧 Bootloader 时，有两个地方必须同时改：

text
1. Keil 的 Options → Target → ROM 起始地址：0x0800C000  →  0x08000000
2. main() 里的向量表偏移：
   SCB->VTOR = 0x0000C000U;   →   SCB->VTOR = 0x00000000U;

只改一处必炸。 只改 ROM 不改 VTOR：程序能跑，但一进中断就跳回 Bootloader 的向量表，行为完全随机。只改 VTOR 不改 ROM：链接地址不对，连启动都起不来。

发布固件时再改回去（0x0800C000 + 0x0000C000U），编译出 bin 走蓝牙升级。这个「双开关」是所有带 Bootloader 的项目都会踩的坑，建议在代码里用宏隔离：

c
#ifdef DEBUG_APP_ONLY
    SCB->VTOR = 0x00000000U;
#else
    SCB->VTOR = 0x0000C000U;
#endif

6.5 一台手环教会的事 #

经验 说明
DMA 是刷屏的前提 128×128 的屏、每帧 8KB，纯 CPU 搬运会卡到没法看
看门狗要外置 内部 IWDG 进 STOP 关不掉
低功耗是设计出来的，不是优化出来的 PS/SYNC 这根线在一开始就决定了能不能做到 25µA
Bootloader 的地址改动是双开关 ROM 起始 + VTOR，必须同步
传感器全挂一条 I2C 省引脚，但要注意地址冲突和总线电容上限（400pF）
焊接是硬功夫 0402 封装、TPS63020 这种密集引脚，锡膏量控制不好就短路；焊完必须测正负极

七、踩坑清单 #

  1. 高级定时器 TIM1/TIM8 必须置 BDTR 的 MOE（bit15），否则无输出。
  2. PWM 模式 1（110）与模式 2（111）是反的，选错占空比反相。
  3. 改 CCR 前先开 OCxPE 预装载，否则波形会出现毛刺。
  4. 捕获到上升沿后必须清 CNT，否则脉宽算法不准。
  5. 改捕获极性必须先 &=~ 再 |=。
  6. TIM1/TIM8 的更新与捕获是两个独立向量，TIM2~5 共用一个。
  7. 编码器模式 3（SMS=011）是 4 倍频，算转速要除以 4。
  8. 编码器方向由 A/B 相位差决定，硬件自动处理，但读数类型要用有符号。
  9. 电机驱动板、主板、编码器必须共地。
  10. F1 的 RTC 是秒计数，F4 才是 BCD 日历，别混抄。
  11. 写 RTC 必须等 RTOFF=1，进配置模式要置 CNF，读要等 RSF=1。
  12. 备份域写保护要 PWR->CR 的 DBP 位才能解。
  13. RTC 闹钟必须配 EXTI17，否则中断进不来。
  14. RTC 预分频最长 2^20，且 RTC 时钟必须 < PCLK1/4。
  15. TH0*256+TL0 不是 TH0*255。
  16. PID 不能照抄参数，要按负载重调。

小结 #

定时器是整个 MCU 里功能最密集的外设，但它的核心只有三个寄存器：CNT（计数）、ARR（周期）、CCR（比较值）。

  • 让 CNT 自由跑、用 CCR 卡阈值 → PWM 输出；
  • 让外部信号把 CNT 快照到 CCR → 输入捕获；
  • 让外部正交信号驱动 CNT 加减 → 编码器接口。

三种用法共用同一套硬件，区别只在「谁驱动 CNT」和「CCR 是写入还是读出」。理解了这一点，剩下的都是寄存器位的问题了。
