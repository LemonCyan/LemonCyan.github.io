一、先把词分清：异常、中断、异常中断 #

初学者最容易在三个词上打转，先把判据说死：

概念 定义 同步性 谁产生
异常 Exception 处理器执行指令导致原程序中止 同步（与指令执行绑定） CPU 自己
中断 Interrupt 外设请求 CPU 处理，打断当前程序 异步（与指令无关） 外设 / 外部引脚
异常中断 Exception + Interrupt 的合称 — —

一句话记住：中断是唯一与 CPU 运行无关的异常。异常是狭义，中断是广义异常里的一个子集。

这个区分不是文字游戏，它决定了三件实际的事：

  • 异常可以精确（知道出错的是哪条指令，如数据中止）也可以非精确（如某些异步中止）；
  • 异常处理遵守严格程序顺序、默认不能嵌套，必须第一个处理完返回后才能处理后续异常；
  • 中断可以嵌套，靠的是进入处理程序后手动重新打开 IRQ（见第六节）。

1.1 七类异常 #

# 异常 触发时机 进入模式 优先级
1 复位 Reset 上电 / 按 reset 键 SVC 1（最高）
2 数据访问中止 Data Abort 访问的数据地址不存在或非法 ABT 2
3 快速中断 FIQ 外设高速数据传输、通道处理、DMA FIQ 3
4 一般中断 IRQ 绝大多数外设 IRQ 4
5 预取指令中止 Prefetch Abort 流水线取指阶段，目标指令地址非法 ABT 5
6 未定义指令 Undefined 流水线译码阶段，指令无法识别 UND 6
7 软中断 SWI 用户程序主动执行 SWI 指令 SVC 6（最低）

注意优先级不是按向量地址顺序排的：向量表里数据中止在 0x10（第 5 项），但优先级排第 2。

1.2 CPU 为什么需要中断 #

CPU 想知道外设状态只有两条路：

  1. 轮询：定时去读外设寄存器。CPU 被绑住，效率低，实时性差。
  2. 被打断：外设状态变化时主动发信号。CPU 可以专心算自己的，来了再处理。

第二条显然更合理，这就是中断存在的根本原因。FIQ 与 IRQ 的分工则是按「急不急」切：FIQ 有最高优先级与最小延迟，留给高速数据通道（DMA 相关）；其余外设一律走 IRQ。

二、七种工作模式与寄存器分组 #

2.1 模式表 #

模式 缩写 用途 M[4:0]
用户 User usr 正常程序执行，无权限改模式位 0b10000
快速中断 FIQ fiq 高速数据传输与通道处理 0b10001
外部中断 IRQ irq 通常的外部中断 0b10010
管理 Supervisor svc 操作系统保护模式 0b10011
数据访问中止 Abort abt 虚拟存储与存储保护 0b10111
未定义指令 Undefined und 用软件仿真协处理器 0b11011
系统 System sys 运行特权级操作系统任务 0b11111

除 User 外 6 种都是特权模式；除 Sys 外 5 种特权模式又称异常模式（因为能被异常进入）。

异常与模式的对应关系是固定的：复位→SVC，FIQ→FIQ，IRQ→IRQ，预取/数据中止→ABT，未定义→UND，SWI→SVC。

2.2 寄存器总数与 bank #

ARM 核共 37 个寄存器：31 个通用寄存器（含 PC）+ 6 个状态寄存器。但任一时刻你只看得到 16 个通用寄存器（R0~R15）+ 1~2 个状态寄存器，其余被「藏」在各自模式的 bank 里。

分组 寄存器 物理副本数 含义
未备份 R0~R7 1 所有模式共用同一物理寄存器，切换模式时数据会被破坏
备份 R8~R12 2 每个有两个副本（R8_usr / R8_fiq …），只有 FIQ 有独立副本
栈指针 R13 (SP) 6 usr 与 sys 共用一个，其余 5 种异常模式各一个
链接寄存器 R14 (LR) 6 同上
程序计数器 R15 (PC) 1 —

这个分组是异常能正常返回的物理基础：每种异常模式有自己的 R13，所以异常处理入口处的 SP 天然是「这个模式专属的栈」；有自己的 R14，所以被打断的返回地址不会被后续调用覆盖。

2.3 FIQ 为什么比 IRQ 快 #

两个硬件层面的原因，缺一不可：

  1. R8~R12 有独立 bank：FIQ 处理程序只要只用 R8~R15，就完全不用保存和恢复现场（因为那 5 个寄存器本来就是 FIQ 私有的，用完不动别人的）；
  2. 向量表 0x1C 是最后一项：可以直接把 FIQ 处理程序本体放在 0x1C，省掉一条跳转指令的一个时钟周期。

2.4 R13 / R14 / R15 的约定 #

  • R13 = SP：ARM 指令集里只是习惯用法，没有强制；但 Thumb 指令集中有指令强制用 R13 作栈指针。每种异常模式初始化时必须各自把 SP 指向专用栈——这是裸机代码里最常被忘掉的一步，忘了就会出现异常一进栈就把别的数据踩掉。
  • R14 = LR：BL / BLX 调用子程序时置为返回地址，MOV PC, LR 即返回。异常发生时该模式的物理 R14 被硬件置为「应返回地址」，但存在常数偏移，必须按异常类型修正（第四节）。
  • R15 = PC：读 PC 得到的是「当前指令地址 + 8 字节」（ARM 状态，指向下两条指令）；ARM 指令字对齐，PC 的 bit[1:0] 恒为 0。

PC 有两个必须知道的坑：

  1. 用 STR / STM 保存 R15 时，存进去的可能是 +8 也可能是 +12，取决于芯片设计（同一芯片内不会混用）；结论是不要用 STR/STM 保存 PC。
  2. ARMv4 及以上，写入 R15 的地址 bit[1:0] 必须为 0b00，否则结果不可预知；Thumb 状态下写入 R15 的值先与 0xFFFFFFFC 相与（忽略 bit[0]），而 BX 恰恰用 bit[0] 判断切 ARM 还是 Thumb——这种「写 PC 忽略 bit0、切状态看 bit0」的不对称必须记牢。

三、CPSR 与 SPSR #

text
 31  30  29  28  27  26                7   6   5     4  3  2  1  0
  N   Z   C   V   Q  DNM(RAZ)          I   F   T     M4 M3 M2 M1 M0
位 名称 含义
31 N 等于结果 bit[31]；有符号补码运算时 N=1 表示结果为负
30 Z =1 结果为零；CMP 时 Z=1 表示两数相等
29 C 加法（含 CMN）产生进位 C=1（无符号上溢）；减法（含 CMP）产生借位 C=0（无符号下溢）；带移位的非加减指令，C 保存最后一次移出的位
28 V 加减运算中补码有符号数符号位溢出时 V=1
27 Q 仅 ARMv5 E 系列定义，指示增强 DSP 指令是否溢出；其他版本为 DNM(RAZ)
7 I I=1 禁止 IRQ
6 F F=1 禁止 FIQ
5 T ARMv4+ T 系列：0=ARM，1=Thumb
4:0 M[4:0] 处理器模式

低 8 位（I、F、T、M[4:0]）统称控制位，特权模式下软件可改。

CPSR 在任何模式都能访问；SPSR 每种异常模式各一份，异常发生时存 CPSR、异常返回时恢复 CPSR。

关键坑：User 与 Sys 模式没有 SPSR，在这两种模式下访问 SPSR 结果不可预知。所以「在系统模式下读 SPSR」这种代码是错的。

四、异常响应：硬件自动做的事 #

发生异常时，不管软件想不想，CPU 硬件无条件做四步：

  1. 保存执行状态：把当前 CPSR 复制到该异常模式的 SPSR。
  2. 切换模式：把异常码写进 CPSR 的 M[4:0]，同时无论原来是 ARM 还是 Thumb 状态，一律切到 ARM 状态处理（CPSR[5]=0），并置 I 位关 IRQ；如果是 FIQ，再置 F 位关 FIQ。
  3. 保存返回地址：把「PC−4」存进该模式的 LR。
  4. 跳向量：强制把 PC 设为对应的异常向量地址。

进了向量表之后，全部是软件行为。

4.1 返回地址必须按异常类型修正 #

这是整个中断机制里最容易记错的部分。硬件统一存 PC−4，但因为不同异常发生时 PC 指向的位置不同，修正量也不同。

异常 异常发生时 PC 指向 硬件存的 PC−4 指向 正确的返回指令
IRQ / FIQ 当前指令后第 3 条（ARM +12，Thumb +6） 当前指令后第 2 条 SUBS PC, LR_irq, #4
预取指令中止 当前指令后第 2 条（ARM +8，Thumb +4），PC 未更新 当前指令的下一条 SUBS PC, LR_abt, #4
未定义指令 当前指令后第 2 条，PC 未更新 下一条 MOV PC, LR_und
软中断 SWI 当前指令后第 2 条，PC 未更新 下一条 MOV PC, LR_svc
数据中止 当前指令后第 3 条（ARM +12），PC 已更新 当前指令后第 2 条 SUBS PC, LR_abt, #8

为什么 IRQ 要减 4：CPU 是在当前指令执行完之后才查询 FIQ/IRQ 引脚，此时 PC 已经指向「后面第 3 条」，硬件存 PC−4 后指向「后面第 2 条」，再减 4 才回到被打断指令的下一条。

为什么中止要「重新执行」而不是「下一条」：预取中止说明取指地址非法，必须回到出错那条指令重新取；数据中止说明访存失败，必须重新访问那个数据。但硬件存的是「下一条」，所以仍需修正。

这些修正对应的六条返回指令，可以直接背下来：

armasm
SUBS    PC, LR_irq, #4      ; 一般中断
SUBS    PC, LR_fiq, #4      ; 快速中断
SUBS    PC, LR_abt, #4      ; 预取指令中止
MOV     PC, LR_und          ; 未定义指令
MOV     PC, LR_svc          ; 软中断
SUBS    PC, LR_abt, #8      ; 数据访问中止

五、异常向量表 #

向量表每个表项 4 字节，也就是一条 32 位指令的位置。

低端向量 高端向量 异常 模式 优先级 入口时 I 入口时 F
0x00000000 0xffff0000 复位 SVC 1 Set Set
0x00000004 0xffff0004 未定义指令 UND 6 Set Unchanged
0x00000008 0xffff0008 软中断 SWI SVC 6 Set Unchanged
0x0000000C 0xffff000C 指令预取中止 ABT 5 Set Unchanged
0x00000010 0xffff0010 数据访问中止 ABT 2 Set Unchanged
0x00000014 0xffff0014 保留 — — — —
0x00000018 0xffff0018 IRQ IRQ 4 Set Unchanged
0x0000001C 0xffff001C FIQ FIQ 3 Set Set

两个「设计意图」值得单独说：

  • 0x14 为什么空着：ARM7 时代这里留过一个「地址异常」，后来的核把它取消了，位置就空着没复用。所以向量表有 8 个坑，只用 7 个。
  • FIQ 为什么在最后（0x1C）：因为它是最后一项，可以直接把 FIQ 处理程序本体放在这里，不用写 b 跳转，省一个时钟周期。这是 FIQ 快的第二个原因（第一个是 R8~R12 独立 bank）。
  • 复位为什么在 0x0：CPU 上电自动从 0 地址取指。所以 0x0 物理地址必须是非易失存储器（Flash / NVRAM / ROM）。麻烦在于：不用硬件调试器根本跟踪不到那条跳转，裸机调试时「程序没跑起来」往往就是在这一步断掉的。

5.1 向量表两种安装写法 #

armasm
b reset                 ; 复位
b HandleUndef           ; 未定义指令
b HandleSWI             ; 软中断
b HandlePrefetchAbt     ; 预取指令中止
b HandleDataAbt         ; 数据访问中止
b HandleNoUsed          ; 保留
b HandleIRQ             ; 一般中断
b HandleFIQ             ; 快速中断（也可直接放处理程序本体）

另一种等价写法是 ldr pc, _undefined_instruction 这类「把处理程序地址装到 PC」。坑在于：如果目标地址处放着的还是一条未定义指令，就会死循环——这类「向量跳错了」的症状是「一上电就卡死、串口一个字都不出」。

5.2 低端 / 高端向量切换 #

  • 高端向量是 ARM 架构的可选配置，可通过外部输入管脚在硬件上配置，不能用指令改变；
  • 如果芯片内部有标准 CP15，也可以用 CP15 的 C1 寄存器 bit13 切换：bit13=0 低端、bit13=1 高端。

为什么需要高端向量：开了虚拟内存之后，低地址通常是内核进程空间 / 页表空间，向量表不能再躺在 0 地址，只能搬到 0xFFFF0000。

六、现场保存与恢复 #

向量表跳进来之后，第一件事是保存现场，最后一件是恢复现场。标准写法：

armasm
STMFD   SP_excep!, {R0 - R12, LR_excep}    ; 入口：保存现场
    ...                                     ; 处理本体
LDMFD   SP_excep!, {R0 - R12, PC}^         ; 出口：恢复现场并返回

四个必须理解的点：

  1. 这里的 SP 已经是异常模式专属栈（第一节的 bank 机制），现场保存在异常模式栈里，不会污染用户栈；
  2. 最后入栈的 LR_excep 是修正过的返回地址（第四节），所以恢复时能直接弹回 PC；
  3. 脱字符 ^ 表示把 SPSR_excep 恢复到 CPSR，同时完成模式与状态切回。漏掉 ^ 的后果是：寄存器都恢复了，但 CPU 还留在异常模式里，下一次中断就会因为栈不匹配而崩溃；
  4. 入口与出口的 SP_excep 必须一致。如果入口用 SP 入栈、出口用 SP+4 出栈，弹回的 R0~R12 全部错位，症状是「中断处理函数返回后程序跑到野指针」。

异常返回其实是三步：恢复寄存器 → 恢复 CPSR → PC 指向返回地址。一条 LDMFD ..., {..., PC}^ 把三件事全做完。

6.1 中断嵌套怎么做 #

进入 IRQ 时硬件已经置 I=1 关了 IRQ，所以默认不嵌套。要支持嵌套，必须：

  1. 入口保存现场；
  2. 切到系统模式（MSR CPSR_c, #0x1F）——不能在 IRQ 模式下重开 IRQ，否则一旦发生嵌套，新中断的 LR_irq 会把当前 LR_irq 冲掉；
  3. 在系统模式下清 I 位开中断，此时处理函数用的是用户栈；
  4. 处理完后关中断、切回 IRQ 模式、恢复现场返回。

为什么一定要切系统模式：IRQ 模式只有一个物理 LR_irq 和一个 SP_irq。如果在 IRQ 模式下重开中断，第二个中断进来时硬件立刻把 LR_irq 覆盖成新值，第一个中断的返回地址就永久丢失了。切到系统模式后，处理函数用的是系统模式的 LR 和 SP，再嵌套也是压系统栈，LR_irq 始终只在最外层用一次。

七、SWI 与系统调用 #

7.1 指令语义 #

armasm
SWI{cond} immed_24
  • immed_24：24 位立即数，取值 0 ~ 16777215，是「系统调用号」；
  • 执行效果：从用户模式切到管理模式，CPSR 存入 SPSR_svc，PC 跳到 SWI 向量 0x08；
  • 参数按 ATPCS 放 R0~R4。

用户程序为什么要通过 SWI 才能用硬件：用户态没有权限改 CPSR 模式位、也没有权限访问硬件寄存器，唯一的越权通道就是「主动触发一个异常」，这条异常由操作系统提前准备好的处理程序接管。用一句白话：用户只能从柜台窗口递单子，不能进内部操作区。

两种传参约定（都是软件协定，不是硬件规定）：

armasm
; 约定一：立即数指定服务类型，参数用通用寄存器
MOV R0, #34          ; 功能号 34
SWI 12               ; 软中断号 12

; 约定二：立即数被忽略，服务类型由 R0 决定
MOV R0, #12          ; 12 号软中断
MOV R1, #34          ; 功能号 34
SWI 0

7.2 C 里怎么发起系统调用 #

C 语言没有 SWI 对应表达式，必须混合编程：

c
#define __led_on_swi_no   1

int led_on(int led_no)
{
    int ret;
    __asm {
        mov r0, led_no          // ATPCS：第一个参数在 r0
        swi __led_on_swi_no     // 触发软中断
        mov ret, r0             // 取返回值
    }
    return ret;
}

7.3 处理程序：怎么把 24 位立即数抠出来 #

这是 SWI 实现里最漂亮的一个技巧，必须记住：

armasm
; 0x08: 软件中断异常
    b       HandleSWI

IMPORT do_led_on
IMPORT do_led_off

HandleSWI
    STMFD   SP!, {R0-R12, LR}       ; 保存现场
    LDR     R4, [LR, #-4]           ; LR-4 才是 SWI 指令地址
    BIC     R4, R4, #0xFF000000     ; 清高 8 位，只留 24 位立即数

    CMP     R4, #1                  ; 1 -> do_led_on
    LDREQ   LR, =swi_return
    LDREQ   PC, =do_led_on

    CMP     R4, #2                  ; 2 -> do_led_off
    LDREQ   LR, =swi_return
    LDREQ   PC, =do_led_off

    MOVNE   R0, #-1                 ; 没有匹配的号，返回 -1

swi_return
    LDMIA   SP!, {R0-R12, PC}^      ; 恢复现场，^ 把 SPSR 复制回 CPSR

三个关键点：

  1. LR−4 才是 SWI 指令的地址：硬件把「SWI 的下一条指令」存进了 LR，所以要回退一条；
  2. BIC #0xFF000000 清高 8 位：一条 32 位 ARM 指令里，低 24 位才是 immed_24；
  3. 用 LDREQ LR 预置返回地址而不是压栈：R4 被当操作寄存器用，R0~R3 的 ATPCS 参数寄存器一个都没破坏。

7.4 Linux 的真实系统调用号 #

Linux 把「哪个 OS」也编进了立即数：

c
#define __NR_SYSCALL_BASE   0x900000            /* OS_NUMBER << 20 */
#define __NR_open           (__NR_SYSCALL_BASE + 5)   /* 0x900005 */

所以用户态调 open 时，机器码里是 SWI #0x900005。内核侧 vector_swi 的处理顺序是：

armasm
bic     scno, scno, #0xff000000        @ 抹掉高 8 位，先得 0x000005
eor     scno, scno, #OS_NUMBER << 20   @ 异或掉 OS 号（OS_NUMBER = 9）
adr     tbl, sys_call_table            @ 取系统调用表
cmp     scno, #NR_syscalls             @ 越界检查
ldrcc   pc, [tbl, scno, lsl #2]        @ 跳到 sys_open

用 eor 而不是 sub，是因为「判断 OS 号是否匹配」和「取系统调用号」两步被合成了一条指令：如果高 8 位不是 0x90，异或之后的 scno 就会超出表长度，被后面的 cmp 挡掉。

文件分工：

文件 内容
arch/arm/kernel/entry-common.S vector_swi，软中断总入口
arch/arm/kernel/entry-armv.S vector_IRQ / vector_FIQ 与向量表
arch/arm/kernel/calls.S 系统调用函数声明，顺序即调用号
include/asm-arm/unistd.h 调用号规则（__NR_xxx）

八、中断控制器：为什么必须有它 #

处理器一般只有两根左右的中断引脚（Cortex-A9 就是 IRQ 与 FIQ），但 SoC 里的外设几十上百个。所以外设的中断线不直连 CPU，而是先接到中断控制器，控制器再连 CPU 的两根引脚。

text
UART / RTC / ADC / TICK(定时器) / 外部 INT ……   外设中断源
                    │
            中断控制器（GIC / VIC）
                    │
                 ARM 核（nIRQ / nFIQ）

外设只负责「产生电平/边沿」；能不能到达 CPU、到哪个 CPU、优先级多少，全部由中断控制器决定。

8.1 GIC 的两大逻辑块 #

逻辑块 职责
Distributor 分发器 管理所有中断源：使能/禁用、优先级、目标 CPU、触发方式（电平/边沿）、状态机
CPU Interface CPU 接口 每个 CPU 一份，负责向该核投递中断、应答 ACK、结束 EOI

8.2 常用寄存器（PL390 / GICv1-v2） #

寄存器 作用
ICDDCR Distributor 总开关
ICDISER / ICDICER 中断使能置位 / 清除（成对使用）
ICDICPR 清除 pending 标志
ICDIPR 中断优先级（每中断号 1 字节，4 个共用一个 32 位寄存器）
ICDIPTR 目标 CPU（同样 1 字节/中断号）
ICDICFR 触发方式（电平/边沿）
ICCICR CPU 接口使能
ICCPMR 优先级掩码，决定「多高的优先级才允许打断当前 CPU」
ICCIAR 读中断号（读这个动作同时完成 ACK）
ICCEOIR 写回中断号（结束中断）

8.3 一次中断的六步 #

  1. 外设产生中断 → Distributor 把对应中断置为 PENDING；
  2. Distributor 按优先级与目标 CPU 把中断投递给某个 CPU Interface；
  3. CPU Interface 比较该中断优先级与 ICCPMR，通过则拉高 nIRQ / nFIQ；
  4. CPU 进入异常向量，处理程序读 ICCIAR 拿到中断号（这一读同时完成 ACK，状态变为 ACTIVE）；
  5. 驱动按中断号调用注册的处理函数；
  6. 处理完写 ICCEOIR 结束中断；若外设电平仍为高，会再次 PENDING 触发。

三条硬性结论：

  • PENDING 由硬件置位、软件清除；
  • 漏写 EOI 会导致该中断永久不再进入——死中断，现象是「第一次进了，以后再也不进」；
  • 电平触发必须「先清外设中断源，再 EOI」，否则 EOI 之后外设电平还挂着，立刻又 PENDING，形成中断风暴（现象是「一进中断就出不来」）。

8.4 GIC 的三种中断类型 #

类型 全称 特征
SGI Software Generated Interrupt 软件写寄存器产生，用于核间通信，每核私有
PPI Private Peripheral Interrupt 每核私有的外设中断（如本地定时器）
SPI Shared Peripheral Interrupt 共享外设中断，可路由到指定 CPU

8.5 EINT 与中断号 #

  • EINT：一部分中断线从中断控制器直接引出到 SoC 外面的芯片管脚，即外部中断管脚，可以灵活接按键这类外设；这根线上的有效信号可自定义（高电平 / 低电平 / 上升沿 / 下降沿 / 双边沿）。
  • 中断号：SoC 里每个中断源连到中断控制器的线按固定顺序编号，这个号就是中断号。

九、S3C2440 的外部中断（VIC 时代） #

2440 用的是老式 VIC，外部中断由四个寄存器管：

寄存器 作用
EXTINT 外部中断标志
EXTWAKEUP / INTWAKE 唤醒使能：让 EINT 把 CPU 从掉电模式叫醒
EXTMODE 每个管脚选择电平 / 边沿触发
EXTPOLAR 极性：哪种电平或边沿有效

注意 2440 把「触发方式」和「极性」拆成两个寄存器（EXTMODE + EXTPOLAR），而后面 4412 用一个 EXT_INT_CON 编码——这是两代芯片最直观的差别。

9.1 EXTINT 的清除规则（最容易踩的坑） #

  • 向 EXTINT 的 EINT0~EINT3 位写 1 清除；
  • 电平触发方式下，只有该管脚处于无效状态时才能清掉标志；
  • 一旦某位被置位并已执行处理代码，必须清零，否则这个 EINT 以后触发的事件不会被识别。

典型事故：用 EINT0 低电平把系统从掉电模式唤醒后，程序忘了复位 EINT0。结果以后任何唤醒掉电模式的操作都会失败——因为唤醒标志一直是「已触发」状态。

9.2 INTWAKE：唤醒与中断是解耦的 #

INTWAKE 使能 EINT / BOD / RTC 把 CPU 从掉电模式唤醒。但它和「中断能不能产生」是两件事：

  • 相关 EINTn 必须映射到管脚才能实现掉电唤醒；
  • 但中断并不需要为了唤醒而在 VIC 中被使能。

于是有两种合法用法：① 只唤醒不产生中断（简单恢复场景）；② 产生中断但不唤醒。进入掉电模式前要重新编程管脚外部中断功能、选好触发方式与极性；唤醒后要把管脚恢复成原有的外设复用功能。

9.3 改 EXTMODE / EXTPOLAR 的规则 #

当某中断在 VICIntEnable 中被禁止时，软件只能改 EXTMODE / EXTPOLAR 中对应位；重新使能前必须先向 EXTINT 写 1 清标志——因为改变激活方式或极性这个动作本身就可能把 EXTINT 位置位。漏这一步的症状是「改完触发方式，中断立刻误触发一次」。

十、Exynos4412 的外部中断：GPIO + GIC 全流程 #

10.1 GPIO 侧四步 #

  1. 查 DevBoard 与 CoreBoard 原理图，找到芯片引出的对应引脚；
  2. 把 GPX【】CON 的对应 4 bit 设为 0xf，该引脚进入 WAKEUP_INT 状态；
  3. 关闭上下拉（保证边沿干净）：设置 GPX【】PUD；
  4. 配 EXT_INT【】_CON 选触发方式，再配 EXT_INT【】_MASK 使能。

GPX2PUD 位域：

text
GPX2PUD[n]   [2n+1:2n]   n = 0..7   RW
0x0 = Disables Pull-up/Pull-down
0x1 = Enables Pull-down
0x2 = Reserved
0x3 = Enables Pull-up

结论：PUD 每个引脚 2 bit，关上下拉写 0x0（很多人误写成 0x3，结果引脚被上拉，按键松开时也稳在高电平）。

10.2 GIC 侧五步 #

  1. ICDDCR 置 1：GIC 开始监听外设中断并转发到 CPU 接口；
  2. ICDISER 使能对应中断到 Distributor（作为 SPI 时选哪个 CPU 都行）；
  3. ICDIPTR 选择目标 CPU 接口；
  4. ICCICR 置对应 CPU 的位为 1，使能中断送达 CPU；
  5. ICCPMR 低 8 bit 置 0xFF，放开所有优先级。

10.3 编号换算（必考） #

以 57 号中断为例：

  • 使能位：57 % 32 = 1 余 25 → 第 1 个 32 位使能寄存器的第 25 bit；
  • IPTR：57 % 4 = 14 余 1 → ICDIPTR14 的第 8~15 bit（因为每个中断号占 1 字节）。

规律：使能位看 irq % 32 定寄存器序、余数定 bit；IPTR 看 irq % 4 定寄存器序、余数 × 8 定字节偏移。

10.4 处理与清理 #

  1. 读 ICCIAR，中断号在低 10 bit；用 switch/case 分派；
  2. 清两级标志：先清 EXT_INT【】_PEND（GPIO 侧），再清 GIC 侧 pending（ICDICPR）；
  3. 最后向 ICCEOIR 低 10 bit 写入中断号结束中断。

顺序不能反：先清外设源，再 EOI。反了就是中断风暴。

十一、进入 Linux 之后：四阶段模型 #

裸机的中断处理逻辑搬到 Linux 里，被拆成了四个阶段：

阶段 动作
a CPU architecture 相关模块现场保护，然后调用 machine driver 的 handler
b machine driver 根据硬件信息取回 hwirq，经 irq domain 翻译成 irq number
c 调用该 irq number 对应的 high level irq event handler，做流控（嵌套、抢占），遍历 IRQ action 链表，调用驱动注册的处理函数
d CPU architecture 相关模块现场恢复

11.1 两条关键链路 #

问题一：架构层的总入口 handle_arch_irq 从哪来？

text
gic_init_bases -> set_handle_irq(gic_handle_irq) -> handle_arch_irq = gic_handle_irq
gic_handle_irq -> handle_IRQ -> generic_handle_irq() -> generic_handle_irq_desc
              -> desc->handle_irq(irq, desc)

问题二：每个中断号的流控函数 desc->handle_irq 从哪来？

text
s3c_irq_type -> irq_set_handler(data->irq, handle_level_irq)
             -> __irq_set_handler -> desc->handle_irq = handle

真正调到驱动注册的处理函数：

text
handle_level_irq() -> handle_irq_event -> handle_irq_event_percpu
                  -> res = action->handler(irq, action->dev_id)

三者别混：

  • handle_arch_irq 是架构层的「总入口函数指针」，由中断控制器驱动（gic）注册；
  • desc->handle_irq 是每个中断号的「流控 handler」，由 irq_set_handler 按触发类型（电平/边沿）选择——设置触发类型时就顺手挂上了；
  • action->handler 才是 request_irq 注册进来的那个 ISR。

11.2 向量表在 Linux 里的样子 #

Linux 的向量表在 arch/arm/kernel/entry-armv.S，表有 16 个入口，但只有 2 项有效——分别对应 user mode 与 svc mode（代码走到这里时已经是 svc）。

用户注册 ISR 的本质是：挂到 irq_desc 的 action 链上，覆盖该中断号的默认处理。这也是「request_irq 返回 -EBUSY」的由来——共享中断之外，一个中断号只允许一个 handler。

十二、三颗芯片的对照 #

维度 S3C2440（VIC） Exynos4412（GIC） STM32F103（NVIC）
控制器 VIC GIC（Distributor + CPU Interface） NVIC（内核私有）
使能 VICIntEnable ICDISER / ICDICER + ICCICR ISER / ICER
优先级 VIC 优先级寄存器 ICDIPR + ICCPMR IPR，4 bit 一组 + 分组
触发方式 EXTMODE（电平/边沿）+ EXTPOLAR（极性）两个寄存器 EXT_INT_CON 一个配置 + GIC 的 ICDICFR EXTI->RTSR / FTSR 两条寄存器
引脚选择 管脚连接模块 GPX【】CON 4bit = 0xf AFIO->EXTICR 选端口
清标志 EXTINT 写 1 清 EXT_INT_PEND + ICDICPR EXTI->PR 写 1 清
取中断号 读 VIC 地址寄存器 ICCIAR 低 10 bit 读 SCB->ICSR 的 VECTACTIVE
结束中断 写 VIC 清位 ICCEOIR 低 10 bit 无需 EOI（硬件自动）
唤醒解耦 INTWAKE 独立 — EXTI 的 EMR 事件模式

最后一行值得展开：STM32 的 NVIC 没有 EOI 概念，硬件在进入 handler 前就自动清了 pending，所以「漏 EOI 死中断」这类坑在 STM32 上不存在；反过来，STM32 上要小心的是「清 EXTI->PR 的时机」——必须在 handler 里清，否则一退出就立刻又进。

十三、踩坑清单 #

  1. 返回地址必须按类型修正，不能一律 MOV PC, LR：IRQ/FIQ 减 4，预取中止减 4，未定义/SWI 不减，数据中止减 8。
  2. 入口与出口的 SP 必须一致，否则 LDMFD 弹回的 R0~R12 错位。
  3. 必须写 LDMFD ..., {..., PC}^ 的脱字符，漏了就留在异常模式。
  4. 不要用 STR/STM 保存 R15，存 +8 还是 +12 依芯片而定。
  5. User/Sys 模式没有 SPSR，在这两种模式下读 SPSR 不可预知。
  6. FIQ 快在两处：R8~R12 独立 bank + 0x1C 可直接放本体省一次跳转。
  7. SWI 处理要 LR−4 再 BIC #0xFF000000，两步缺一不可。
  8. 裸机装向量表要求 0 地址可写，否则得用高端向量（CP15 C1 bit13 或外部管脚）。
  9. GIC 漏 EOI → 永久不再进中断。
  10. 电平触发要先清外设源再 EOI，否则中断风暴。
  11. 2440 电平方式下只有引脚无效时才能清 EXTINT；唤醒后必须复位 EINT0，否则再也进不了掉电模式。
  12. 2440 改 EXTMODE/EXTPOLAR 后要先写 1 清 EXTINT 再重新使能，改极性本身会置标志。
  13. 4412 关上下拉写 PUD=0x0，不是 0x3。
  14. 中断号换算：使能位 = irq % 32，IPTR 字节偏移 = (irq % 4) × 8。
  15. handle_arch_irq / desc->handle_irq / action->handler 三层别混。

小结 #

这篇的主线其实只有一句话：异常是 CPU 的硬件反射，向量表是反射的入口表，模式 bank 是反射能安全返回的内存基础。

把这三点想通，剩下的都是「查手册填寄存器」：

  • 想知道某个中断现在什么状态 → 看中断控制器的状态寄存器；
  • 想知道为什么中断只进一次 → 查 EOI；
  • 想知道为什么一进中断就卡死 → 查「先清源再 EOI」的顺序；
  • 想知道为什么处理函数返回后跑飞 → 查 SP 是否配对、返回地址修正量是否对。
