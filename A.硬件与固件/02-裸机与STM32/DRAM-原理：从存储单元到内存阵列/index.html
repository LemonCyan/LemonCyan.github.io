零、全景：DRAM 的四层抽象 #

层次 实体 关心的问题

后面五节依次对应这四层，最后一节回到系统级的多 Device 组织。

一、DRAM Storage Cell #

1.1 基本结构 #

DRAM Storage Cell 用 Storage Capacitor（存储电容） 来存储 Bit 信息。一个最简单的、存储 1 bit 的 Cell 由 4 部分组成：

  • Storage Capacitor：存储电容，通过其中电荷的多寡、也就是电容两端电压差的高低，表示逻辑上的 1 和 0；
  • Access Transistor：访问晶体管，导通和截止决定了允许还是禁止对电容所存信息进行读取或改写；
  • Wordline（字线）：决定 Access Transistor 的导通或截止；
  • Bitline（位线）：外界访问电容的唯一通道，Access Transistor 导通后，外界通过 Bitline 对电容读写。

Storage Capacitor 的 Common 端接在 Vcc/2。存 1 时另一端电压为 Vcc，存 0 时另一端为 0，两种状态在电容上呈现的电荷极性相反——这正是后面"Differential Sense Amplifier"能工作的前提。

1.2 直接读写会遇到什么麻烦 #

按最朴素的思路：读的时候把 Wordline 拉高、打开晶体管、看 Bitline 上的电平；写的时候先把目标电平加到 Bitline 上、再打开晶体管。但工程上这么做会遇到三个问题：

  1. 电平不匹配。Bitline 的电容值比 Storage Capacitor 大得多（通常 10 倍以上），电容导通后，即使存的是 1，Bitline 的电压变化也非常微小，外部电路无法直接判读；
  2. 读操作破坏数据。读取过程中 Bitline 与电容电压不一致，会把电容里的电荷搬走一部分，导致下一次读可能读错；
  3. 电荷泄漏。即使不读写，电容上的电荷也会缓慢流失，必须周期性恢复。

为了解决这三个问题，DRAM 引入了 Differential Sense Amplifier（差分敏感放大器）。它由 Sensing Circuit 和 Voltage Equalization Circuit 两部分组成，作用是把电容里微弱的电荷差异放大成标准的逻辑电平呈现在 Bitline 上，并在一次读取后把电荷写回电容，恢复读之前的状态。

1.3 Read Operation 的四个阶段 #

一次完整的读操作依次经过 Precharge → Access → Sense → Restore 四个阶段。下面以读取 Bit 1 为例。

（1）Precharge

通过控制 EQ 信号，让三个均衡晶体管导通，把 Bitline 与 /Bitline 的电压稳定在 Vref 上，Vref = Vcc/2。这一步的目的是让两条位线"归零对齐"，之后任何一点电压偏移都能被放大器分辨出来。

（2）Access

Wordline 拉高，Ta 导通。电容中的正电荷流向 Bitline，把 Bitline 电压抬到 Vref+（一个很小的增量）。

（3）Sense

Bitline 升到 Vref+ 后，交叉耦合的放大器出现正反馈：Bitline 侧的下管比 /Bitline 侧更易导通，/Bitline 侧的上管比 Bitline 侧更易导通。

此时把 SAN（Sense-Amplifier N-Fet Control）拉低到逻辑 0、SAP（Sense-Amplifier P-Fet Control）抬到 Vcc，/Bitline 被更快地拉到 0，Bitline 被更快地拉到 1。最终两条位线稳定在互补的电平上，正确呈现出电容中存储的 Bit——而且这个电平是"全摆幅"的。

（4）Restore

Sense 结束后 Bitline 稳定在 Vcc，这个电压反过来给电容充电。经过特定时间后，电容恢复到读取之前的状态——读破坏的问题由此被消除，所以 DRAM 的读天然是一次"读 + 刷新"。

最后通过 CSL 信号打开列选通管，外界从 Bitline 上把数据取走。

1.4 Write Operation #

写操作的前半段与读完全相同：Precharge、Access、Sense、Restore 一个不少（因为必须先打开整行、把数据缓存到放大器里）。差别在于 Restore 之后还要进行 Write Recovery：

通过 WE（Write Enable）信号让写驱动管导通，把 Bitline 强行拉到 input 的电平、/Bitline 拉到 /input。经过特定时间后电容被放电到目标状态，再关断 Wordline 完成写入。

这也是写比读慢、且写之前必须先 Active 整行的原因。

二、Memory Array 的组织 #

2.1 为什么不能无限往一根位线上挂 Cell #

最直观的扩容方式是"在一个 Bitline 上挂更多 Cell"。但 Bitline 挂得越多就越长，电容越大，信号边沿速率（电平从高变低或反之的速度）越慢，性能随之下降。所以要限制单条 Bitline 上的 Cell 数，把多出来的 Cell 分摊到其他 Bitline 上。

Cell 结构里有两条功能完全等价的位线，正好利用这一点。等两条位线都挂满了再扩容，就只能增加 Bitline 数量——而每增加一组 Bitline，Sense Amplifier、Read Latch、Write Driver 都要跟着增加，成本、功耗、芯片面积一起上涨。

因此实际设计中的取舍是：优先增加一行上的 Cell 数（拉长 Wordline），尽量不增加 Bitline。这带来一个直接结论——Wordline 的数量通常远多于 Bitline。

2.2 Rows × Columns × Data Width #

把 Cells 不断堆叠，最终得到一个 m × n × w 的阵列：

  • m：Wordline 的数量；
  • n：CSL / WE 控制信号的数量；
  • w：一次能读写的 Bit 数。

工程上统一用 Rows × Columns × Data Width 来描述：

概念 定义
Data Width 对该阵列进行一次读写所访问的 Bit 位数，由 CSL / WE 的组织方式决定
Row 与 Wordline 一一对应，即挂在同一根 Wordline 上的所有 Cell。选中一个 Row 就是打开对应 Wordline，把数据缓存到 Sense Amplifier
Column 阵列中可寻址的最小单元。一个 Row 有 n 个 Column，其中 n = Row Size / Data Width。Column Size 与 Data Width 本质相同
Bank 由多个 Memory Array 堆叠而成，每个 Array 称为一个 Bank。各 Bank 的 Rows / Columns / Data Width 完全相同，访问时同一时刻只有一个 Bank 被激活

为什么还要分 Bank？因为 Wordline 也不能无限长——Cell 越多，线越长，电容越大，边沿越慢。把阵列切成多个 Bank，就可以在不牺牲性能的前提下继续扩容量。

2.3 一个例子 #

参数 值
Banks 4
Rows / Bank 16K
Columns / Row 1024
Column Size 16 Bits

总容量 = 4 × 16K × 1024 × 16 bit = 1 Gb。

三、DRAM Device #

以 SDR SDRAM 为例，看一颗 DRAM 芯片对外是什么样子。

3.1 硬件接口 #

信号 类型 说明
CLK Input Host 输出的同步时钟
CKE Input 指示 CLK 是否有效，SDRAM 据此进入/退出 Power down、Self-refresh 等模式
CS# Input 片选
RAS# Input Row Address Strobe，行地址选通
CAS# Input Column Address Strobe，列地址选通
WE# Input Write Enable，写使能
DQML Input 写数据时若为高，DQ[7:0] 的数据被忽略
DQMH Input 写数据时若为高，DQ[15:8] 的数据被忽略
BA[1:0] Input Bank Address，选择操作的 Memory Bank
A[12:0] Input 地址总线，传输行/列地址
DQ[15:0] I/O 数据总线

注意 地址线是行、列复用的：同一组 A[12:0] 在 RAS 有效时是行地址，在 CAS 有效时是列地址。这是"引脚数换时间"的典型做法。

3.2 命令集 #

Host 与 SDRAM 的所有交互都由 Host 发起的 Command 驱动，一个 Command 是若干控制信号的组合：

Command CS# RAS# CAS# WE# DQM BA & A[12:0] DQ[15:0]
Active L L H H X Bank & Row X
Read L H L H L/H Bank & Col X
Write L H L L L/H Bank & Col Valid
Precharge L L H L X Code X
Auto-refresh L L L H X X X
Self-refresh L L L H X X X
Load Mode Register L L L L X REG Value X

各命令的作用：

  • Active：通过 BA 和 A 选中指定 Bank 的一个 Row，打开其 Wordline。任何读写前都必须先 Active。
  • Read：用 A 送出列地址，SDRAM 把 Active 选中的那行里对应列的数据通过 DQ 送出。从发出 Read 到数据出现在总线上所需的时钟周期数定义为 CL（CAS Latency）。
  • Write：用 A 送出列地址，同时用 DQ 送数据。从收到最后一个数据到数据真正写入 Memory 的时间定义为 tWR（Write Recovery）。
  • Precharge：读写之后必须 Precharge 才能再次读写。它以 Bank 为单位，A10 为高表示对所有 Bank 做 Precharge，为低则按 BA 选定单个 Bank。所需时间定义为 tPR（tRP）。
  • Auto-refresh（AR）：刷新按 Row 进行，标准要求在一个刷新周期（常温 64ms、高温 32ms）内把所有 Row 刷一遍。为简化控制器设计，标准规定控制器在一个周期内发 8192 个 AR，SDRAM 每收到一个 AR 就刷 n 个 Row，n = 总 Row 数 / 8192；芯片内部维护一个 Refresh Counter 记录下次要刷的行。于是相邻两个 AR 的间隔为 tREFI = 64ms / 8192 ≈ 7.8μs，完成一次刷新所需时间定义为 tRFC。
  • Self-refresh：Host 让 SDRAM 自己刷新、自己省电，此时不能读写，数据靠芯片内部维持。设备待机时常用。
  • Load Mode Register：初始化时把 tCAS、Burst Length 等参数写进芯片。

因为 AR 会占用总线、阻塞正常请求，而且刷新很费电，标准允许控制器最多延后 8 个 tREFI，再把 8 个 AR 一起发出去——这是"刷新开销"优化的起点。

3.3 Address Mapping #

SDRAM Controller 的核心工作之一，是把 CPU 的物理地址翻译成 Bank / Row / Column。例如一个 32 位物理地址，高位选 Bank，中间选 Row，低位选 Column——具体怎么切由板级设计和控制器寄存器决定，切错了性能会差一大截（见第四章 tRC 的讨论）。

3.4 芯片内部模块 #

模块 作用
Control Logic 解析 Controller 发来的 Command，控制内部各模块（选中 Bank、触发 refresh 等），内含 1 个或多个 Mode Register 保存时序与数据模式配置
Row Decoder 把 Active 携带的 Row Address 映射到具体的 Wordline
Column Decoder 把 Column Address 映射到具体的 CSL，选中特定 Column
Memory Array 存储主体
IO 数据缓存与输入输出。Data Latch / Data Register 缓存数据，DQM Mask Logic、IO Gating 控制收发
Refresh Counter 记录下次要刷新的 Row，每完成一次刷新就更新

3.5 各种类型的 DRAM #

目前主流有 SDR、DDR、LPDDR、GDDR 四类。

SDR 与 DDR：SDR（Single Data Rate）是第一个引入 Clock 的 DRAM，只在时钟上升沿处理总线信号，一个周期传一组数据。DDR（Double Data Rate）在 SDR 基础上采用 2n-Prefetch 架构：一个读写周期内预取 2 倍宽度的数据，然后在时钟上升沿和下降沿各传一次，于是相同时钟频率下速率翻倍。

后续 DDR2/3/4 每一代都靠"更多 Prefetch + 更高时钟"继续翻倍：

标准 Bus clock (MHz) Internal rate (MHz) Prefetch Transfer Rate (MT/s) Voltage
DDR 100–200 100–200 2n 200–400 2.5/2.6
DDR2 200–533.33 100–266.67 4n 400–1066.67 1.8
DDR3 400–1066.67 100–266.67 8n 800–2133.33 1.5
DDR4 1066.67–2133.33 133.33–266.67 8n 2133.33–4266.67 1.05/1.2

读这张表的关键在第 3 列：内部 Memory Array 的读写频率卡在 266.67MHz 上不去。因为 DRAM 用电容存储，受工艺和物理特性限制，充放电时间难以进一步缩短。内部频率上不去，就只能在"宽度"上做文章——通过 Prefetch 增加单次读写周期内操作的数据宽度，再配合总线与 IO 频率的提升来提高整体速率。

LPDDRx：Low Power DDR，用于手机、平板等移动设备。相对 DDR 采用更低工作电压、Partial Array Self-Refresh 等机制降低功耗。

GDDRx：Graphic DDR，用于显卡，追求更高的性能、更低的功耗与发热。

四、时序 #

前面说了有哪些命令，这一节说命令之间必须隔多久。

4.1 一次操作在内部的四个阶段 #

阶段 发生了什么
Command transport and decode Host 通过 Command Bus / Address Bus 把命令与参数传给 SDRAM，SDRAM 解析后驱动内部模块
In bank data movement 数据从 DRAM Cells 读出到 Sense Amplifiers，或从 Sense Amplifiers 写回 Cells
In device data movement 数据经 IO 电路缓存到 Read Latch，或经 IO + Write Driver 更新到 Sense Amplifiers
System data transport 读时 SDRAM 把数据输出到总线；写时 Controller 把数据送到总线

每个阶段都有耗时，而且部分部件被多个操作共用（比如读写都要用 IO 电路），再加上大电流操作要限频，于是命令之间必须遵守时序规则。这些规则由 SDRAM 标准定义。

两个通用量：

  • tCMD：Controller 发出 Command 到 DRAM 接收并解析该 Command 的时间，各类 Command 相同；
  • tParam：Controller 发出 Command 到 DRAM 执行完该 Command 对应操作的时间，随 Command 类型和参数而变。

DDRx 的 Clock 是差分信号，为简化描述，下文只讨论 Positive Clock。

4.2 关键时序参数 #

参数 含义 备注
tRCD Row Address to Column Address Delay：Active 打开 Wordline 把数据读到 Sense Amplifier 的时间 Active 后必须等 tRCD 才能发 Read/Write
tRAS Row Address Strobe：Active 到 Row Restore 完成的时间 发 Activate 后必须等 tRAS 才能 Precharge 或再次 Row Access
tCAS / tCL 收到 Column Read 到第一组数据出现在总线上的时间 可由 Mode Register 配置，通常 3~5 个时钟周期
tBurst 从第一个列数据到最后一个列数据的时间 长度由 Burst Length 决定，常见 2/4/8
tCWD / tCWL Column Write Delay：发完 Write 后到可以送数据的时间 SDRAM 0 cycle，DDR 1 cycle，DDR2 为 tCAS-1，DDR3 可编程
tWR Write Recovery：收到最后一个数据到真正写入 Cells 的时间
tRP Row Precharge：执行 Precharge 所需时间
tRC Row Cycle：两次 Active 之间必须间隔的时间 tRC = tRAS + tRP，直接决定换行访问的性能
tREFI Refresh Interval：相邻两个 AR 的间隔 7.8μs
tRFC Refresh Cycle：完成一次刷新所需时间 DDR3 上最小约 110ns，而 tRC 为 52.5ns

tRFC 比 tRC 长，一部分是因为刷新对所有 Bank 同时进行、本身耗时更久，另一部分是为降低平均功耗而刻意插入的延时——刷新时的电流远大于单个 Row 的 Active+Precharge。

4.3 一条完整的访问链 #

把参数串起来，访问一个 Row 里的数据是这样的：

  1. 发 Precharge（如果该 Bank 之前是打开状态），等 tRP；
  2. 发 Active 打开目标 Row，等 tRCD；
  3. 发 Read / Write，读要等 tCAS 后数据才出来，写要等 tCWD 后才能送数据；
  4. 一个 Row 内可以连续发多个 Read/Write，不用换行就没有 tRC 的惩罚，性能最好；
  5. 要访问另一个 Row 时，先 Precharge（等 tRP），再 Active——两次 Active 之间至少隔 tRC。

由此可以得出两个重要的性能结论：

  • 同一 Row 内的连续访问远快于跨 Row 访问，所以 DRAM Controller 会做请求调度，把落到同一 Row 的访问尽量攒到一起执行；
  • 优化方向只有两条：降低 tRC，或者在一次 Row Cycle 里塞进尽可能多的读写。

4.4 两个降低控制器复杂度的机制 #

Auto Precharge：Read Command 的 A10 设为 1 时触发。DRAM 会在读完成后自己找个合适的时机做 Precharge，Controller 不必再单独发命令。Write 同样支持。

Additive Latency（AL，DDR2 引入）：有了 AL，Controller 发完 Active 后可以紧接着就发 Read/Write，DRAM 在延时 tAL 之后再执行。两个机制的作用相同：让 Controller 的实现更简单，进而在功耗和性能上受益。

4.5 Mode Register #

上述参数中有一部分是可编程的：tCAS、tAL、Burst Length 等。Host 在初始化时通过 Load Mode Register 命令把它们写进 DRAM 的 Mode Register，之后 DRAM 就按这套参数运行。初始化的完整流程要看具体 CPU 与 DRAM 芯片的 Datasheet。

五、多 Device 的组织 #

系统对容量、带宽、性能的要求提高后，会接入多颗 DRAM Device。不同的组织方式，效果差别很大。

5.1 Single Channel #

Controller 只有一组控制与数据总线。

接单个 Device：最常见。单颗芯片在总线宽度和容量上受限，需要大带宽大容量的产品就要接多颗。

接多个 Device（共享总线 + 片选）：多个 Device 共享控制与数据总线，Controller 通过 Chip Select 分时单独访问。它的好处是，当某个 Device 进入刷新周期时，Controller 可以调度去访问别的 Device，提高整体吞吐。注意 CS0 和 CS1 同一时刻只能有一个有效。这种方式只增加容量，不增加带宽。

接多个 Device（合并数据总线）：多个 Device 共享控制线和片选，但 Controller 同时访问它们，各 Device 的数据位拼接成更宽的总线——例如 Device 1 输出到 DATA[0:7]、Device 2 输出到 DATA[8:15]。这样访问 16bit 只需要一个周期，而不是拆成两次 8bit。这种方式容量和带宽同时增加。

5.2 Multi Channel #

Controller 有多组控制与数据总线，每组可以独立访问。

接多个单通道 Device：多个 Device 可以真正并行工作，Controller 对不同 Channel 同时发起读写，吞吐提升。与单通道共享总线的关键差别是：CS0 和 CS1 同一时刻可以同时有效。

接多通道 Device：LPDDR3、LPDDR4 等产品把多个 Channel 做进了单颗芯片内部，于是单颗 Device 上就能获得多通道并发的效果。

六、小结 #

把全文压缩成几句话：

  1. DRAM 的存储单元是电容，读操作天然破坏数据，所以每次读都伴随一次 Restore——这是"读即是刷新"的物理根源；
  2. 位线电容远大于存储电容，必须靠差分敏感放大器把微小差异放大成满摆幅电平；
  3. Bitline 越长越慢、Sense Amplifier 越多越贵，于是形成"多 Wordline、少 Bitline、多 Bank"的结构；
  4. 容量靠增加 Device 或 Bank，带宽靠更宽的合并总线与更多通道，两者不是一回事；
  5. 性能几乎全写在时序参数里：tRCD 决定开行代价，tRC 决定换行代价，tREFI/tRFC 决定刷新的固定开销。理解了这几个数，才看得懂内存控制器为什么那样调度。
