一、boot 这个词 #

计算机领域里「启动」对应英语的 boot，原本是「靴子」。它来自 bootstrap（鞋带），再往前是谚语 pull oneself up by one's bootstraps——拉着自己的鞋带把自己提起来，显然办不到。

早期工程师拿这个比喻描述启动的死结：要启动计算机就得先运行程序，可计算机没启动又运行不了程序。当时的办法是想尽办法把一小段程序塞进内存，机器才能自己跑下去。「拉鞋带」后来简化成了 boot。

经典 PC 的启动分四个阶段：BIOS → 主引导记录 → 硬盘启动 → 操作系统。

二、第一阶段：BIOS #

早期 PC 把开机程序写进只读内存（Read-Only Memory，ROM）芯片。通电后第一件事就是读这块芯片，里面的程序叫基本输入输出系统（Basic Input/Output System，BIOS）。

2.1 硬件自检 #

BIOS 先做硬件自检（Power-On Self-Test，POST），确认硬件满足运行的基本条件。硬件有问题，主板会用不同的蜂鸣声报错，启动中止。

硬件正常，屏幕上会列出 CPU、内存、硬盘等信息，然后 BIOS 把控制权交给下一阶段的启动程序。

2.2 启动顺序 #

BIOS 得知道下一阶段的程序在哪个设备上。它按启动顺序（Boot Sequence）这个优先级列表逐个找可启动设备，顺序可以在 BIOS 设置界面里改。

三、第二阶段：主引导记录 #

BIOS 把控制权交给排在第一位的存储设备，机器读该设备的第一个扇区，也就是最前面的 512 字节。这 512 字节的最后两个字节是 0x55 和 0xAA，就说明这个设备能启动；不是就换启动顺序里的下一个设备。

这 512 字节叫主引导记录（Master Boot Record，MBR）。

3.1 MBR 的结构 #

字节范围 内容
第 1–446 字节 调用操作系统的机器码
第 447–510 字节 分区表（Partition Table），描述硬盘上各分区的情况
第 511–512 字节 主引导记录签名 0x55AA

3.2 分区表 #

分区的好处是能在一块硬盘上装多个操作系统。分区表只有 64 字节，最多定义四个主分区，每个主分区占 16 字节，记着激活状态、分区类型、起止位置等。

条目用 32 位表示扇区号，按 512 字节一个扇区算，单个分区最大约 2 TiB，整块盘的可用容量也卡在这里。要突破就得换 4Kn 扇区，或者改用 GPT 分区表。

四、第三阶段：硬盘启动 #

控制权要交给硬盘上的某个分区，有三种情况。

4.1 情况 A：卷引导记录 #

四个主分区里有且仅有一个是激活的。机器读这个分区的第一个扇区，叫卷引导记录（Volume Boot Record，VBR）。VBR 指出操作系统在分区里的具体位置，接着加载操作系统。

4.2 情况 B：扩展分区与逻辑分区 #

盘越来越大，四个主分区不够用，于是有了扩展分区（Extended Partition），里面可以放多个逻辑分区（Logical Partition）。

机器先读扩展分区的第一个扇区，即扩展引导记录（Extended Boot Record，EBR）。EBR 里也有一张分区表，但只有两项：一个指向当前逻辑分区，一个指向下一个 EBR。顺着这条链往下读，就能找到后面所有逻辑分区。

4.3 情况 C：启动管理器 #

这种情况下，机器读完 MBR 前 446 字节的机器码后，不直接交给某个分区，而是运行预先装好的启动管理器（Boot Loader），让用户选择启动哪个系统。Linux 上最常见的是 GRUB。

4.4 现代平台的两处变化 #

上面这套 BIOS + MBR 是最经典的一条路，今天实际机器上常见两个替代品：

  • UEFI 取代 BIOS：固件不再读 MBR，而是从 GPT 分区的 ESP（EFI System Partition）里读 .efi 程序，签名校验、图形界面、大于 2 TiB 的盘都支持。
  • GPT 取代 MBR 分区表：用 128 位 LBA 寻址，分区表不再受 64 字节限制；配合 UEFI 时必须有一个 ESP。

嵌入式开发板通常两者都没有：上电直接跑固化在片内 ROM 的一段代码（三星叫 iROM，见 Exynos4412 启动链路：iROM、BL1 与 BL2），或者直接跑烧在 Flash/SD 卡上的 U-Boot。

五、第四阶段：操作系统 #

控制权交给操作系统后，内核先被加载进内存。以 Linux 为例，内核文件在 /boot 下；加载成功后启动第一个程序 /sbin/init。

/sbin/init 按配置文件（如 Debian 的 /etc/inittab）创建 init 进程。它是系统启动后第一个进程，PID 为 1，之后所有进程都是它的后代。随后 init 把各模块拉起来，最后执行 /bin/login 显示登录界面。

六、Linux 侧的启动链条与 FHS #

开机到登录界面，大致这条链：

  1. BIOS / UEFI：硬件自检，初始化固件。
  2. Bootloader（GRUB）：加载内核映像和 initramfs。
  3. 内核：接管内存、中断、调度器，挂根文件系统。
  4. 用户空间：内核启动 PID 1，由它拉起其余服务。

6.1 根文件系统目录（FHS）速查 #

FHS（Filesystem Hierarchy Standard）规定了各目录放什么。找文件、写脚本、挂盘都按这套约定来；制作根文件系统时这张表就是目录骨架的依据（见 根文件系统的制作）。

目录 放什么 例子
/ 根目录，所有路径的起点 /home、/etc、/var
/bin 基本用户命令，系统启动和操作必需 ls、cp、mv
/sbin 系统管理命令 init、fdisk
/etc 系统和应用的配置 /etc/fstab（挂载点）、/etc/hosts
/home 各用户的家目录 /home/username
/lib 共享库，供 /bin、/sbin 里的可执行文件用 /lib/x86_64-linux-gnu/libc.so.6
/usr 用户程序和数据 /usr/bin/git、/usr/bin/python
/var 会变的数据 /var/log、/var/mail、缓存
/tmp 临时文件，重启后清空 安装过程的中间文件

登录记录写在 /var/log/wtmp，用 last 读（二进制格式，cat 看不到内容）。

6.2 重置 root 密码 #

忘了 root 密码，可以从 GRUB 改启动参数进 bash 再重置。前提是能物理接触机器、能进 GRUB 菜单。

  1. 开机盯着 GRUB 菜单，出现启动项时按 e 进编辑模式。
  2. 找以 linux 开头的那行，把 ro 改成 rw，行尾加 init=/bin/bash：
text
linux /vmlinuz-xxx rw init=/bin/bash
  1. 按 Ctrl+X 启动，直接拿到不登录的 root shell。
  2. 重设密码：
bash
passwd
  1. 重启：
bash
exec /sbin/init

ro 没改成 rw 的话，根分区是只读挂载，passwd 写不进去，会直接失败。能改 GRUB 启动参数就等于拿到 root，生产环境要设 GRUB 密码或开 Secure Boot 堵住这条路。

6.3 PID 1：System V init 与 systemd #

PID 1 是内核创建的第一个用户空间进程，负责把系统带到可用状态。现代发行版基本都是 systemd，老系统是 System V init。

System V 运行级别 systemd target 作用
0 poweroff.target 关机
1 rescue.target 单用户模式
2、3、4 multi-user.target 多用户文本界面
5 graphical.target 多用户图形界面
6 reboot.target 重启
emergency emergency.target 紧急 Shell

System V init 按运行级别串行跑脚本；systemd 用 target 组织依赖关系，互不依赖的服务可以并行启动，开机更快。

System V 命令 systemctl 命令 作用
service foo start systemctl start foo.service 启动服务
service foo restart systemctl restart foo.service 重启服务
service foo stop systemctl stop foo.service 停止服务
service foo reload systemctl reload foo.service 重载配置，不终止服务
chkconfig foo on systemctl enable foo.service 开机自启
chkconfig foo off systemctl disable foo.service 取消开机自启
chkconfig --list systemctl list-unit-files --type=service 列出启用状态

七、ARM64：内核入口对 bootloader 的要求 #

这是 arm64 内核入口之前的硬件约定，来自内核文档 Documentation/arm64/booting.rst。下面提到具体内核版本限制的地方，只对应当时的文档，用之前先按手上的内核版本核对。这一段是 U-Boot 移植时最容易踩的地方——U-Boot 把这些条件准备错一条，内核就在 Starting kernel ... 之后静默死掉。

7.1 Bootloader 必须做的事 #

  1. 初始化 RAM（必须）。找到并初始化系统所有 RAM，用来存易失数据。怎么发现内存取决于机器：有的靠内部算法自动探测，有的直接读硬件给出的内存信息。
  2. 设置设备树 dtb（必须）。dtb 要 8 字节对齐，最大不超过 2 MB。位置和大小不对，内核起不来。
  3. 解压内核映像（可选）。按当时文档的说法，AArch64 内核没有内置解压器，用 Image.gz 就得由 Bootloader 解压；没实现解压的 Bootloader 可以改用不压缩的 Image。这一点在新内核里可能已经变化，未验证。
  4. 调用内核映像（必须）。内核映像头部带这些字段：
c
u32 code0;        /* 可执行代码 */
u32 code1;        /* 可执行代码 */
u64 text_offset;  /* 加载偏移，小端 */
u64 image_size;   /* 有效映像尺寸，小端 */
u64 flags;        /* 内核标志，小端 */

7.2 进入内核时的寄存器与 CPU 状态 #

项 要求
x0 dtb 在 RAM 里的物理地址，内核靠它认硬件
x1 / x2 / x3 全 0，留给以后用
中断 PSTATE.DAIF 全部屏蔽（Debug、SError、IRQ、FIQ）
异常级别 EL2，或非安全态的 EL1；推荐 EL2，能用上虚拟化扩展
MMU 必须关闭，页表由内核自己建
I-Cache 开或关都行
D-Cache 内核映像占用的那段地址必须清到 PoC（一致性点），别把脏缓存留给内核
DMA 设备 所有带 DMA 的设备必须停掉，否则网络包或磁盘数据会写进内核还没接管的内存
架构定时器 各 CPU 按自身频率设好 CNTFRQ，CNTVOFF 要一致；EL1 启动时 CNTHCTL_EL2 的 EL1PCTEN（bit 0）在可用时必须置上
一致性 所有被引导的 CPU 必须在同一个一致性域里

对比 ARM32 的约定：r0 = 0、r1 = machine id、r2 = atags 或 dtb 地址，关 MMU、D-Cache 必须关、I-Cache 随意、SVC 模式、禁止 IRQ/FIQ。ARM64 用 x0 传 dtb、不再传 machine id——机器类型改由 dtb 的 compatible 匹配（见 设备树的内核解析与启动流程）。

7.3 多核启动：spin-table 与 PSCI #

主 CPU 直接跳到内核映像的第一条指令；其余 CPU 由内核按设备树里的「启用方法」属性拉起来，这个属性由 Bootloader 在进内核前插进 blob。两类：

  • spin-table：cpu 节点要有 cpu-release-addr 属性，指向一个自然对齐、初始化为 0 的 64 位内存位置。从核在原地自旋等这个地址被写非 0，然后跳过去。
  • PSCI（Power State Coordination Interface）：CPU 在内核之外保持待命，所用内存要在内存节点之外，或者通过 /memreserve/ 告诉内核。内核按 ARM DEN 0022A 发 CPU_ON 调用把 CPU 拉进来。

第二个及之后的 CPU，x0 / x1 / x2 / x3 全部置 0。

八、内核自己怎么启动的 #

内核映像分压缩与不压缩两种。压缩版的入口在 arch/<架构>/boot/compressed/head.S，先做前期初始化和自解压，再跳到 arch/<架构>/kernel/head.S。这里只跟不压缩这条线。

  1. Bootloader 把内核映像加载进内存，控制权交给汇编入口 head.S，不是直接进 start_kernel。
  2. head.S 建好页表、打开 MMU 之后，才跳到 C 函数 start_kernel。
  3. start_kernel 初始化内存管理、中断、调度器等子系统，末尾调 rest_init。
  4. rest_init 创建 PID 1 与 PID 2，启动调度器，由 PID 1 拉起用户空间服务。

8.1 head.S 与 head-common.S #

汇编入口在 arch/<架构>/kernel/head.S，符号 __HEAD，还会包含 head-common.S。这一段做三件事：检查处理器和机器类型、配置 MMU 建页表条目、跳到 init/main.c 的 start_kernel。架构相关的部分留在 head.S，公共逻辑才放到 C 代码里。

8.2 start_kernel #

  • Lockdep 初始化：记录锁的获取和释放（包括当时是否在处理中断），用来查死锁。
  • RCU 初始化：读者不加锁访问被保护的数据结构，写者先拷贝、改副本、再在合适时机换指针。
  • SMP 初始化：建立 CPU ID，让多核能正常调度。
  • setup_arch(&command_line)：解析 Bootloader 传进来的启动参数，初始化控制台以便打印启动日志，接着设置 VFS、trace、内存管理、cgroup、ACPI、proc 等子系统。
  • rest_init：创建 init 和 kthreadd，把调度器跑起来。

8.3 rest_init 与 kernel_init #

c
static noinline void __init_refok rest_init(void) {
    int pid;

    rcu_scheduler_starting();
    smpboot_thread_init();

    /* 创建 init 进程，第一个用户空间进程 */
    kernel_thread(kernel_init, NULL, CLONE_FS);
    numa_default_policy();

    /* 创建 kthreadd 用于管理内核线程 */
    pid = kernel_thread(kthreadd, NULL, CLONE_FS | CLONE_FILES);

    /* 让内核进程 kthreadd 处于就绪态 TASK_NORMAL */
    complete(&kthreadd_done);

    /* 启动调度器 */
    init_idle_bootup_task(current);
    schedule_preempt_disabled();
    cpu_startup_entry(CPUHP_ONLINE);
}

这里创建的是两个内核线程：kernel_init 拿到 PID 1，kthreadd 拿到 PID 2。kernel_init 后面会 exec 用户态的 init，才算真正有了第一个用户空间进程。kthreadd 管所有内核线程，新内核线程通过 kthread_create_list 挂到它下面。

kernel_init 选哪个 init 取决于启动参数和配置，找不到就按 /sbin/init → /etc/init → /bin/init → /bin/sh 依次试，全失败才 panic。具体是 BusyBox init、System V init 还是 systemd，看发行版。

九、嵌入式这条链的差异 #

环节 x86 PC 嵌入式 ARM
固件 BIOS / UEFI 多数没有，或片内 iROM（如三星 Exynos4412 的 BLO）
一级引导 MBR 512 字节 iROM 从 eMMC/SD 固定偏移读 BL1
二级引导 GRUB（在 VBR 或 ESP） U-Boot（BL2 或完整 U-Boot）
内核传参 GRUB 命令行 ATAGS（老）或 dtb 里的 /chosen/bootargs
启动媒介 硬盘 eMMC / NAND / NOR / SD / 网络（TFTP）

U-Boot 在这一层做的是 PC 上「BIOS 后半段 + GRUB」两件事：初始化 DDR、串口、网卡、存储控制器，然后按用户命令或 bootcmd 把内核映像搬到内存、备好参数、跳过去。具体怎么实现，看下一节的两篇。

十、速查 #

现象 可能原因
上电无任何输出 串口没初始化 / 波特率不对 / 电源或时钟没起来
Starting kernel ... 后静默 dtb 地址错、x0/r2 没传对、MMU 没关、D-Cache 里有脏数据
内核打印 unrecognized device tree list dtb 的 compatible 与内核 DT_MACHINE_START 的 dt_compat 对不上
卡在 Waiting for root device bootargs 里的 root= 路径与实际分区不符
kernel panic: No working init found 根文件系统里 /sbin/init 缺失或不可执行
改 GRUB 参数能进 shell 但改不了密码 ro 没改成 rw，根分区只读

小结 #

  • PC 的链条是 BIOS → MBR(512B) → VBR/EBR/GRUB → 内核 → init，现代机器换成 UEFI + GPT。
  • Linux 用户空间的第一件事永远是 PID 1：System V init 按运行级别串行跑脚本，systemd 按 target 并行拉服务。
  • ARM64 内核入口的硬要求：x0 放 dtb 物理地址、8 字节对齐、MMU 关、D-Cache 清到 PoC、DMA 设备停掉、CNTFRQ 设好；多核用 spin-table 或 PSCI。
  • 嵌入式把 BIOS+GRUB 这两段压缩成一个 U-Boot，读源码时按「芯片初始化 → 板级初始化 → 驱动 → 命令 → 引导内核」这条线走就不会乱。
