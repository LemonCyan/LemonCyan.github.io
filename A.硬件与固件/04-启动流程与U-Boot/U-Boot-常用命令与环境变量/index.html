一、命令从哪来 #

每条命令都是 U_BOOT_CMD 声明出来的结构体，被链接器摆进 .u_boot_list_2_cmd_2_* 段（原理见 U-Boot 启动流程：从 _start 到 main_loop 第十节）。运行时 find_cmd 在这段区间里按名字线性查找。

用 help 看全集，用 help <cmd> 看单条用法：

text
=> help
?       - alias for 'help'
bdinfo  - print Board Info structure
boot    - boot default, i.e., run 'bootcmd'
bootm   - boot application image from memory
coninfo - print console devices and information
cp      - memory copy
echo    - echo args to console
env     - environment handling commands
go      - start application at address 'addr'
help    - print command description/usage
md      - memory display
mm      - memory modify (auto-incrementing address)
mw      - memory write (fill)
nand    - NAND sub-system
ping    - send ICMP ECHO_REQUEST to network host
printenv- print environment variables
reset   - Perform RESET of the CPU
run     - run commands in an environment variable
saveenv - save environment variables to persistent storage
setenv  - set environment variables
tftp    - download image via network using TFTP protocol
version - print monitor, compiler and linker version

二、环境变量 #

u-boot 把配置存在一块独立的存储区（NOR 的一个扇区、NAND 的一个块、eMMC 的一个分区，或 EEPROM），上电时读进 RAM，saveenv 时写回。全部是 name=value 的字符串。

2.1 三条命令 #

命令 作用
printenv / print 打印全部；print bootargs 只打印一个
setenv name value / set 设置或修改
setenv name 不带 value 就是删除
saveenv / save 写回存储介质 
text
=> setenv test exynos4412-fs4482
=> setenv test                    # 删除
=> setenv ipaddr 192.168.1.111
=> setenv serverip 192.168.1.112
=> saveenv
Saving Environment to NAND...
Erasing NAND...
Erasing at 0x80000 -- 100% complete.
Writing to NAND... OK

第一次 saveenv 之前，启动日志里那句 *** Warning - bad CRC, using default environment 是正常的——它表示「Flash 里那块区域还没有有效数据，先用编译时的默认值」。保存一次就没了。

2.2 必须认识的变量 #

变量 作用
bootcmd 自启动时执行的命令，倒计时结束就跑它，通常是 nand read ...; bootm ...
bootargs 传给内核的命令行参数，root=/console=/init= 都在这里
bootdelay 倒计时秒数；-1 关闭 autoboot，-2 无延时且不检查按键
ipaddr 开发板自己的 IP
serverip TFTP/NFS 服务器（通常是主机）的 IP
netmask / gatewayip 子网掩码与网关
ethaddr MAC 地址，必须在第一次联网前设好，否则报 Error: xxx address not set
loadaddr 默认加载地址，tftp/nand read 不写地址时用它
mtdparts / mtdids NAND 分区表（见下）
verify 是否校验镜像 CRC，n 关闭

bootargs 的典型内容：

text
noinitrd root=/dev/mtdblock3 init=/linuxrc console=ttySAC0,115200

走 NFS 根文件系统时：

text
setenv bootargs root=/dev/nfs nfsroot=192.168.0.200:/nfsboot/rootfs rw \
        console=ttySAC2,115200 ip=192.168.0.105 init=/linuxrc

行末的 \ 是续行符。u-boot 命令行里没有真正的多行输入，靠 \ 把一个变量的值写长。

三、数据传输 #

3.1 网络：tftp #

text
=> tftp 41000000 uImage          # 把主机 /tftpboot/uImage 下到 0x41000000

两种用法：交互式（手敲上面这条，然后手敲 bootm）和自动式（把两条命令写进 bootcmd）：

text
=> setenv bootcmd 'tftp 41000000 uImage; tftp 42000000 exynos4412-fs4412.dtb; bootm 41000000 - 42000000'
=> saveenv

3.2 串口：loadb #

text
=> loadb 0x41000000              # 用 Kermit 协议，主机端配合 kermit / SecureCRT

速度比网络慢得多，但网卡还没移植好时是唯一的下载手段。

四、内存操作 #

命令 用途 例子
md 显示内存 md.b 0x30000000 / md.l 0x30000000 0x10
mm 修改，地址自动递增 mm 0x30000000，回车跳过，输入值改，q 退出
nm 修改，地址不递增 nm 0x30000000，反复改同一个地址
cp 内存区间复制 cp 0x30000000 0x31000000 0x1000
mw 用固定值填充 mw 0x30000000 0x12345678 0x10（写 16 次）
cmp 比较两段内存 cmp.b 0x30000000 0x31000000 0x100

后缀决定访问宽度：.b = 1 字节，.w = 2 字节，.l = 4 字节（默认）。

验证烧进去的镜像对不对，最常用的是 md.b 0x0 看前几十个字节——ARM 的第一条指令 b reset 的机器码是 ea0000be 这类形式，小端存放后显示为 be 00 00 ea。

五、存储设备 #

5.1 NAND #

text
=> nand info                     # 看芯片型号与页/块大小
=> nand erase 0x60000 0x400000   # 擦除，起始 0x60000，长度 4MB
=> nand write 0x30008000 0x60000 0x400000
=> nand read 0x30008000 0x60000 0x400000
=> nand bad                      # 列出坏块

有 mtdparts 之后可以用分区名代替偏移：nand erase.part kernel、nand write 0x30008000 kernel。

5.2 分区表 mtdparts #

text
=> setenv mtdparts 'mtdparts=nand0:512k(u-boot),128k(params),4m(kernel),-(rootfs)'
=> mtdparts

device nand0 <nand0>, # parts = 4
 #: name        size        offset        mask_flags
 0: u-boot      0x00080000  0x00000000    0
 1: params      0x00020000  0x00080000    0
 2: kernel      0x00400000  0x000a0000    0
 3: rootfs      0x0fb60000  0x004a0000    0

尺寸单位支持 k/m，- 表示「剩下的全部」。这个字符串最终会被内核解析成 mtdblock0..3，所以 bootargs 里的 root=/dev/mtdblock3 对应的就是 rootfs 分区。

5.3 eMMC / SD #

text
=> mmcinfo                        # 看容量、总线宽度、速度模式
=> mmc read 0 0x30000000 0x1000 0x100   # 从第 0x1000 块读 0x100 块到内存
=> mmc write 0x30000000 0x1000 0x100
=> fatls mmc 0:1 /               # 列 FAT 分区根目录
=> fatload mmc 0:1 0x30000000 zImage

5.4 NOR #

text
=> flinfo                        # 扇区数与地址范围
=> protect off all               # 解除写保护（必须先做）
=> erase 0x0 0x3FFFF
=> cp.b 0x30000000 0x0 0x40000

六、启动命令 #

命令 引导目标 用于
boot bootcmd 的内容 手动触发自启动
bootm addr [ramdisk] [dtb] Legacy uImage 或 FIT ARM 32 位最常用
bootz addr [ramdisk] [dtb] zImage ARM 32 位
booti addr [ramdisk] [dtb] ARM64 Image ARM64 必需
go addr 裸机程序 调试小工具

bootm 的几个变体：

text
=> bootm 0x30008000 - 0x30001000          # 内核、无 ramdisk（用 - 占位）、dtb
=> bootm 0x6400000#conf@bubblegum96       # FIT：指定 configuration
=> bootm 0x6400000:kernel@arm64           # FIT：只加载某个子镜像
=> iminfo 0x30000000                      # 先看镜像头对不对

iminfo 是排查「镜像烧坏了没」的第一手段，输出形如：

text
## Checking Image at 30000000 ...
   Legacy image found
   Image Name:   Linux-5.2.8
   Image Type:   ARM Linux Kernel Image (uncompressed)
   Data Size:    2154336 Bytes = 2.1 MiB
   Load Address: 30008000
   Entry Point:  30008040

七、写自己的命令 #

三步：开宏、写文件、改 Makefile。

第一步，在板级头文件里开一个开关：

c
/* include/configs/fs4412.h */
#define CONFIG_CMD_MYUBOOT

第二步，在 common/ 下建 cmd_hello.c（文件名必须是 cmd_xxx.c，C 文件内再用宏包住）：

c
#include <common.h>
#include <command.h>

#ifdef CONFIG_CMD_HELLO

static int do_hello(cmd_tbl_t *cmdtp, int flag, int argc, char * const argv[])
{
    printf("hello world, argc=%d\n", argc);
    return 0;
}

U_BOOT_CMD(
    hello,          /* 命令名，不加引号 */
    1,              /* maxargs：不需要参数就填 1 */
    2,              /* repeatable：回车是否重跑 */
    do_hello,       /* 处理函数 */
    "hello command",                 /* usage：一行简short说明 */
    "xiaoqing add hello command!\n"  /* help：详细说明 */
);

#endif

U_BOOT_CMD 六个参数的语义：

参数 含义 注意
name 命令名 不是字符串，不加引号（宏内部会 #name）
maxargs 最大参数个数（含命令本身） 无参数时填 1
repeatable 是否可重复，回车即重跑上次命令 常用 1
cmd 函数指针，签名 int (*)(struct cmd_tbl_s *, int, int, char *[])
usage 简短用法 help 列表里显示
help 详细帮助 help <cmd> 时显示

第三步，改 common/Makefile：

makefile
obj-$(CONFIG_CMD_HELLO) += cmd_hello.o

重新编译烧写，help 里就会出现 hello。

常见坑：name 加了引号 → 编译报错或命令名变成 "hello"；maxargs 填 0 → 任何带参数调用都返回 Usage；忘了改 Makefile → 命令永远不出现，但也不报错。

八、调试常用的几条 #

需求 命令
看板子信息（DRAM 大小、重定位地址、波特率） bdinfo
看控制台设备 coninfo
看 u-boot 编译版本与工具链 version
看定时器是否正常工作 sleep 1（没反应说明 timer 没移植）
看 USB 设备 usb start / usb info
看 I2C 设备 i2c bus / i2c probe
看 GPIO 状态 gpio status -a
复位 reset

bdinfo 的输出值得记一下，它把 gd/bd 里最关键的几项都打出来了：

text
=> bdinfo
arch_number = 0x00000000        # 机器码（有 dtb 时通常为 0）
boot_params = 0x00000000        # ATAGS 地址
DRAM bank   = 0x00000000
-> start    = 0x00000000
-> size     = 0x3FFFFFFF
baudrate    = 115200 bps
TLB addr    = 0x3FFF0000
relocaddr   = 0x3FFD8000        # u-boot 重定位后的地址
reloc off   = 0x2EFD8000
irq_sp      = 0x3FFD0BD0
sp start    = 0x3FFD0BD0

九、踩坑速查 #

现象 原因
Unknown command 'xxx' 宏没开 / Makefile 没加 / 被 --gc-sections 裁掉
Error: dm9000 address not set ethaddr 没设，setenv ethaddr xx:xx:... 后 saveenv
TFTP error: 'File not found' 主机 /tftpboot/ 下没这个文件，或 serverip 填错
nand write 报 Bad block 目标区有坏块，nand bad 确认后换偏移
saveenv 报 Not enough space CONFIG_ENV_SIZE 小于实际变量总长，或分区重叠
改了 bootargs 但内核没收到 有 dtb 时 bootargs 走 /chosen，需要 image_setup_linux；没 dtb 时走 ATAGS
setenv 后重启丢失 没 saveenv，或 CONFIG_ENV_IS_IN_* 配错介质

小结 #

  • 命令来自 .u_boot_list 段，help 是它们的索引；自定义命令三步：开宏、写 cmd_xxx.c、改 Makefile。
  • 环境变量是 u-boot 的「配置文件」，bootcmd 决定怎么启动，bootargs 决定内核怎么跑，两者改完必须 saveenv。
  • 传输靠 tftp（网络好时）或 loadb（网卡没通时）；验证靠 md/iminfo；存储操作靠 nand/mmc/erase。
  • mtdparts 的分区名会变成内核里的 /dev/mtdblockN，bootargs 的 root= 必须和它对上。
