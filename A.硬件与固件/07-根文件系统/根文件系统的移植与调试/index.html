零、先选介质，再动手 #

同一棵 rootfs，装到不同介质上，流程和坑完全不同。

介质 文件系统 移植方式 典型场景
eMMC / SD ext4 做镜像 → 烧录 → 首启扩容 量产、正式产品
裸 NAND yaffs2 / ubifs 打专用镜像 → bootloader 写 老平台（Mini2440 等）
网络（NFS） 主机目录 不烧写，直接挂主机的目录 开发调试期，改一行立刻生效
内存（initramfs） cpio.gz 和内核一起加载 极简系统、救援、安全启动

一句话建议：开发期用 NFS 根，量产前切 eMMC ext4。用 eMMC 反复烧写调驱动，一天就能把板子写废。

一、移植到 eMMC：RK3399 + ubuntu 20.04.4 实战 #

目标：把 Ubuntu Base 的最小根文件系统做成 6 GB 的 ext4 镜像，烧进 eMMC，板子起来后能 ssh。

1.1 拿到 ubuntu-base #

bash
wget https://cdimage.ubuntu.com/ubuntu-base/releases/20.04.4/release/ubuntu-base-20.04.4-base-arm64.tar.gz
mkdir ubuntu
tar -xpf ubuntu-base-20.04.4-base-arm64.tar.gz -C ubuntu

解压后只有 300 MB 左右，连 bash、apt、systemd 都有，但没有内核、没有驱动、没有网卡固件。

1.2 在主机上 chroot 进去装包（关键技巧） #

ARM64 的 rootfs 在 x86 主机上不能直接 chroot，需要 qemu-user-static 做指令翻译：

bash
sudo apt install qemu-user-static binfmt-support
sudo cp /usr/bin/qemu-aarch64-static ubuntu/usr/bin/
sudo cp /etc/resolv.conf ubuntu/etc/resolv.conf
sudo chroot ubuntu

进去以后：

bash
# 换源（arm64 在 ports，不在 archive）
cat > /etc/apt/sources.list <<'EOF'
deb http://ports.ubuntu.com/ubuntu-ports focal main restricted universe multiverse
deb http://ports.ubuntu.com/ubuntu-ports focal-updates main restricted universe multiverse
deb http://ports.ubuntu.com/ubuntu-ports focal-security main restricted universe multiverse
EOF

apt update
apt install -y vim ssh net-tools ethtool ifupdown iputils-ping                htop rsync tcpdump sudo udev

# 设 root 密码 + 建普通用户
echo root:root | chpasswd
useradd -s /bin/bash -m -G sudo ubuntu
echo ubuntu:ubuntu | chpasswd

# 允许 root 走 ssh（仅调试期）
sed -i 's/#PermitRootLogin.*/PermitRootLogin yes/' /etc/ssh/sshd_config

# 串口 getty：没有它，串口登录看不到 login 提示
ln -sf /lib/systemd/system/serial-getty@.service \
       /etc/systemd/system/getty.target.wants/serial-getty@ttyS2.service
exit
❢重要

arm64 的软件源必须是 ports.ubuntu.com。写成 archive.ubuntu.com 会报 404 Not Found 或者下到错误架构的包——这是 chroot 阶段最常见的失败原因。

1.3 做 6 GB ext4 镜像 #

bash
# count=6144 → 6144 × 1 MB = 6 GB
dd if=/dev/zero of=ubuntu.img bs=1M count=6144
mkfs.ext4 ubuntu.img

mkdir mnt
sudo mount ubuntu.img mnt
sudo cp -a ubuntu/* mnt/
sudo umount mnt

# 检查并按实际内容压缩到最小
e2fsck -p -f ubuntu.img
resize2fs -M ubuntu.img          # 6 GB → 约 1.2 GB

为什么先做大再 resize2fs -M？因为 ext4 建好再改小很麻烦，而做大了缩回来是一条命令。这也是 Rockchip 官方固件里 rootfs.img 的做法。

1.4 烧录 #

三条路，按手头条件选：

方式 命令 说明
rkdeveloptool（USB，Linux/macOS） rkdeveloptool db rk3399_loader_v1.20.bin → rkdeveloptool ul rk3399_loader_v1.20.bin → rkdeveloptool wl 0x4000 ubuntu.img 需先让板子进 Maskrom 模式
upgrade_tool（USB，Windows） upgrade_tool db / upgrade_tool wl 0x4000 ubuntu.img 图形化 RKDevTool 更直观
dd / SD 卡 sudo dd if=ubuntu.img of=/dev/sdX bs=4M conv=fsync 只适用于从 SD 卡启动

0x4000 这个偏移不是随便写的，它是分区表里 rootfs 分区的起始扇区号，来自 parameter.txt。烧错偏移 = 板子起来但找不到根。

1.5 首次启动看什么 #

串口日志会很长，只看这几行：

text
[    0.000000] Booting Linux on physical CPU 0x0
[    2.1xxxxx] mmc_host mmc0: card is mmc
[    3.xxxxxx] EXT4-fs (mmcblk0p5): mounted filesystem with ordered data mode
[    3.xxxxxx] VFS: Mounted root (ext4 filesystem) on device 179:5.
[    4.xxxxxx] systemd[1]: Detected architecture arm64.
[    5.xxxxxx] systemd[1]: Reached target Multi-User System.
  • 有 Mounted root → 内核侧成功，问题就在用户态
  • 卡在 Starting kernel ... 之前 → 内核/设备树/loader 的问题
  • 有 VFS: Cannot open root device → 分区号、文件系统类型、root= 参数三者之一错

1.6 起来之后要做的三件事 #

bash
# 1. 让根分区吃满 eMMC
resize2fs /dev/mmcblk0p5
resize2fs /dev/mmcblk0p6

# 2. 时区
ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime

# 3. 网卡（DHCP）
cat > /etc/network/interfaces <<'EOF'
auto lo
iface lo inet loopback

auto eth0
iface eth0 inet dhcp
EOF
ifup eth0

二、移植到裸 NAND：Mini2440 + yaffs2 #

老平台没有块设备抽象，rootfs 必须打成 NAND 专用镜像。

2.1 打镜像 #

bash
./mkyaffs2image rootfs/ rootfs-yaffs2.img

mkyaffs2image 必须和内核里的 yaffs2 用同一份源码编译，否则镜像头里的版本号对不上，挂载时报 No YAFFS2 filesystem found。

2.2 烧写（U-Boot + tftp） #

text
# 板子上电进 U-Boot
setenv ipaddr 192.168.0.105
setenv serverip 192.168.0.200
tftp 0x30000000 rootfs-yaffs2.img

# 擦除再写（NAND 必须按块擦，不能直接覆盖）
nand erase 0x500000 0x3B00000
nand write.yaffs 0x30000000 0x500000 0x3B00000

nand erase 的起始地址与长度必须和内核 mtdparts 里的 rootfs 分区完全一致，写歪了就是"内核活着、根没了"。

2.3 bootargs #

text
noinitrd root=/dev/mtdblock3 init=/linuxrc console=ttySAC0,115200 \
mtdparts=nandflash0:256k(bootloader),128k(params),2m(kernel),4m(rootfs)
字段 含义
root=/dev/mtdblock3 用 NAND 的第 4 个分区（从 0 数第 3 个）作为根
init=/linuxrc busybox 的典型入口；用 systemd 时改成 /sbin/init
mtdparts=... 必须和 U-Boot 里的分区表逐字节一致

三、NFS 网络根：开发期最省事的方式 #

板子不再烧写，直接把主机的目录当根文件系统挂上来。改一行代码，板子重启一次就生效，不用再做镜像。

3.1 服务端（Ubuntu/Debian） #

bash
sudo apt install nfs-kernel-server
sudo mkdir -p /work/nfs_root/ubuntu
sudo cp -a ubuntu/* /work/nfs_root/ubuntu/      # 就是 1.1 里解压的那棵
sudo chown -R root:root /work/nfs_root/ubuntu

/etc/exports：

ini
# 路径            客户端网段(权限)
/work/nfs_root/ubuntu  192.168.0.0/24(rw,sync,no_root_squash,no_subtree_check)

bash
sudo exportfs -ra
sudo exportfs -v          # 确认已生效
sudo systemctl restart nfs-kernel-server
⚠警告

no_root_squash 是导出 rootfs 的必选项。 默认的 root_squash 会把客户端的 root 映射成 nobody，结果就是板子起来了但 /sbin/init 权限不足、/dev 建不出来、一堆 Permission denied。安全上应该在防火墙层面限制网段，而不是靠 root_squash。

3.2 客户端挂载（先在主机上自测） #

bash
sudo mkdir -p /mnt/test
sudo mount -t nfs -o vers=3,nolock 192.168.0.200:/work/nfs_root/ubuntu /mnt/test
ls /mnt/test                  # 能看到 bin/ etc/ usr/ 就说明服务端 OK
sudo umount /mnt/test

这一步必须先做通。跳过自测直接让板子挂载，出问题时你分不清是 NFS 服务端错还是内核 NFS 客户端错。

3.3 内核要开的选项 #

text
File systems --->
    [*] Network File Systems --->
        [*] NFS client support
        [*] NFS client support for NFS version 3
        [*] Root file system on NFS
Networking support --->
    [*] Networking support

少开 Root file system on NFS，启动时会直接 VFS: Cannot open root device "nfs"。

3.4 U-Boot 环境变量与 bootargs #

RK3399 的例子：

text
setenv bootargs 'root=/dev/nfs rw rootwait \
  nfsroot=192.168.0.200:/work/nfs_root/ubuntu,vers=4 \
  ip=192.168.0.105:192.168.0.200:192.168.0.1:255.255.255.0::eth0:off \
  rootfstype=ext4 console=ttyS2,1500000'

Mini2440（DM9000 网卡）的例子更短：

text
setenv bootargs noinitrd root=/dev/nfs rw \
  nfsroot=192.168.0.200:/work/nfs_root \
  ip=192.168.0.105:192.168.0.200:192.168.0.1:255.255.255.0::eth0:off \
  console=ttySAC0,115200 init=/linuxrc

ip= 那串共 7 个字段，按顺序拆开：

位置 值 含义
1 192.168.0.105 板子自己的 IP
2 192.168.0.200 NFS 服务器 IP
3 192.168.0.1 网关
4 255.255.255.0 掩码
5 （空） 主机名
6 eth0 网卡设备名
7 off 关闭自动配置（on 表示用 DHCP）

第 6 个字段写错是最隐蔽的坑：RK3399 的网卡可能叫 eth0，也可能叫 end0 或 enP4p65s0，取决于 systemd 的预测命名规则。

3.5 TFTP 传内核与设备树 #

既然已经上网络了，内核也没必要每次烧：

bash
sudo apt install tftpd-hpa
sudo vim /etc/default/tftpd-hpa

ini
TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/work/tftp"
TFTP_ADDRESS="0.0.0.0:69"
TFTP_OPTIONS="--secure --create"

text
tftp 0x30000000 Image
tftp 0x40000000 rk3399-sd.dtb
booti 0x30000000 - 0x40000000

四、启动失败怎么查：七种报错对照 #

串口输出 真实原因 处理
VFS: Cannot open root device "mmcblk0p5" or unknown-block(179,5) 分区号错 / 该分区没有文件系统 / 内核缺对应 FS 驱动 用 fdisk -l 对分区号；确认内核开了 CONFIG_EXT4_FS 或 YAFFS2
VFS: Unable to mount root fs on unknown-block(0,0) 压根没拿到 root 设备（参数没生效或驱动没起来） 检查 bootargs 是否被覆盖；确认 eMMC/NAND 控制器驱动已加载
Kernel panic - not syncing: No init found rootfs 挂上了，但 /sbin/init 不存在或不可执行 检查 init= 路径；chmod +x；确认不是动态链接缺库
Kernel panic - not syncing: Attempted to kill init! init 起来了但立刻退出（脚本第一行 #! 解释器不存在） 看 shebang；确认 /bin/sh 存在且架构正确
一直 Waiting for root device 介质没被识别 / 时钟或电压不对 查 eMMC 的 vmmc-supply、cd-gpios；SD 卡看是否接触不良
request_module: runaway loop modprobe 根分区驱动是模块，而模块还在根分区里（鸡生蛋） 把根设备驱动编进内核（=y），不要 =m
NFS 根卡在 VFS: Cannot open root device "nfs" 内核没开 NFS 根 / 网卡没通 / no_root_squash 没写 按第三节逐项排查

4.1 一句自查口诀 #

先确认挂上了没（VFS: Mounted root），再确认 init 起了没（Freeing unused kernel memory 之后有没有输出）。 前者失败 = 内核/介质/参数问题；后者失败 = 用户态 rootfs 内容问题。这条分界线决定你接下来该看 dmesg 还是看 rootfs 目录。

4.2 三个通用救命手段 #

手段 用法 作用
init=/bin/sh bootargs 里临时改 跳过所有 init 脚本，直接把 shell 给你。能进就说明 rootfs 是好的，问题在 init 脚本链
rdinit=/bin/sh 仅 initramfs 同上，针对 initramfs
loglevel=8 + earlycon bootargs 让内核最早期就吐日志，定位卡在哪一行

init=/bin/sh 这一个技巧能解决一半以上的"起了但没起来"问题，务必先记住它。

五、从调试到量产 #

NFS 根跑通了，要交付时按这个顺序切：

  1. 固定用户态：把 NFS 目录里验证过的内容整体拷出来，不要在量产镜像里再 apt upgrade
  2. 清体积：删 /var/cache/apt、/usr/share/doc、/usr/share/locale，strip 二进制
  3. 固化网络配置：/etc/network/interfaces 或 systemd-networkd 写死静态 IP
  4. 换 fstab：NFS 根时 /etc/fstab 里那一行 /dev/nfs 必须删掉，否则量产镜像挂载会卡住
  5. 做镜像：按第一节 dd + mkfs.ext4 + resize2fs -M
  6. 缩分区表：改 parameter.txt 里 rootfs 的大小，让它和镜像尺寸匹配
  7. 写首次开机脚本：生成唯一机器码、扩展分区、初始化数据库
✦提示

第 4 步是最容易漏的。切到 eMMC 后如果忘了删 fstab 里的 NFS 行，现象是启动到 systemd 后卡 90 秒（remote-fs 超时），而不是直接失败，非常难查。

六、速查表 #

现象 原因 处理
chroot 里 apt update 报 404 源用了 archive.ubuntu.com 换 ports.ubuntu.com/ubuntu-ports
chroot 里命令报 Exec format error 没装 qemu-aarch64-static 或没拷进 rootfs apt install qemu-user-static 并拷 /usr/bin/qemu-aarch64-static
镜像做完才 300 MB，烧进去启动报空间不足 忘了 resize2fs 或 fstab 里没设自动扩 首启脚本里显式 resize2fs
串口能进 login 但输密码就断 /dev/pts 没挂 / devpts 缺 检查 fstab 与 rcS
烧录后启动还是旧系统 烧错偏移 / 烧到了备份分区 核对 parameter.txt 的起始扇区
NFS 根慢得离谱 没开 async 或网络是百兆 exports 加 async；开发机与板子直连千兆
板子 ping 不通主机，但主机 ping 得通板子 主机防火墙挡了 NFS 的 2049 与 rpcbind 的 111 sudo ufw allow from 192.168.0.0/24
用 init=/bin/sh 进去后根是只读 正常，此时还没跑 remount mount -o remount,rw / 再改
换成 systemd 后 linuxrc 报错 init= 还写着 busybox 的入口 改成 init=/sbin/init 或删掉该参数
yaffs2 挂载报 No YAFFS2 filesystem found mkyaffs2image 与内核 yaffs2 版本不一致 用同一份源码重新编译打包工具
