零、汇编文件的三个组成部分 #

一个 .s 文件里混着三类东西，性质完全不同：

类别 是什么 编译后 例子
指令 CPU 真正执行的机器码 占内存、生成机器码 MOV R0, #1、LDR R1, [R0]
伪指令 汇编器帮你在汇编阶段翻译成别的指令 被替换成真实指令 LDR R0, =0x12345678、ADR R0, _start
伪操作 指导汇编器怎么干活 不生成任何机器码、不占内存 .global、.section、.align、.word

搞混这两者的后果很实际：以为 .word 0x1234 会占用「一条指令」的空间，实际上它只是往数据段里填了 4 个字节。

一、指令分类与立即数 #

1.1 六类指令 #

类别 干什么 代表指令
数据处理 算术、逻辑、比较、移位 MOV ADD SUB AND ORR CMP TST
跳转 改变 PC B BL BX BLX
Load/Store CPU 与内存之间搬数据 LDR STR LDM STM SWP
状态寄存器传送 读写 CPSR/SPSR MRS MSR
协处理器 操作 CP15 等 MCR MRC LDC STC CDP
异常产生 主动触发异常 SWI BKPT

1.2 立即数的 8 位限制 #

ARM 的立即数编码只有 12 位：8 位数值 + 4 位循环右移。所以不是所有 32 位常数都能直接写进指令。

armasm
MOV R0, #0x3F        @ 可以，8 位内
MOV R0, #0xFF000000  @ 可以，0xFF 循环右移 8 位得到
MOV R0, #0x12345678  @ 不行！汇编器会报错
LDR R0, =0x12345678  @ 用伪指令绕过

LDR = 的做法是：把常数放在就近的文字池（literal pool） 里，再用 PC 相对寻址读出来。这也是它为什么「不占指令数但占内存」的原因。

1.3 Thumb 状态：同一颗核的第二套编码 #

ARM 处理器有两种执行状态：ARM 状态（32 位定长指令）与 Thumb 状态（16 位定长指令）。注意 Thumb 不是独立的体系结构，它是同一套架构的另一种编码方式——寄存器模型、异常模型、内存模型完全一样，只是指令编码不同。

为什么要它：代码密度。1 KB 空间在 ARM 状态最多塞 256 条指令，Thumb 状态能塞 512 条。对 Flash 只有几 MB 的嵌入式设备，这是实打实的成本差异。代价是每条指令能表达的信息变少——16 位装不下 ARM 那套「条件码 + 移位器 + 多寄存器」的豪华格式。

维度 ARM 状态 Thumb 状态（Thumb-1）
指令长度 32 位定长 16 位定长
代码密度 低 约高一倍
条件执行 几乎所有指令都可带条件码 只有 B 能条件执行
寄存器可访问性 R0~R15 全部 多数指令只能用 R0~R7
协处理器指令 有（MRC / MCR） 没有
信号量指令 有（SWP） 没有
直接访问 CPSR / SPSR 有（MRS / MSR） 不行，要借 BX 切回 ARM 状态
LDM / STM 任意寄存器组 只能 R0~R7

上表右列的「只能」「只有」「没有」，只对 Thumb-1（ARMv4T 的 16 位子集）成立。ARMv6T2 之后引入 Thumb-2，用 16 / 32 位混合编码把上面这些限制基本补齐了——Cortex-M 系列跑的就是 Thumb-2。看老资料时的困惑多半来自没分清这两者。

切状态的唯一正道是 BX / BLX，因为它们的跳转目标地址的 bit0 决定状态：

text
目标地址 bit0 = 0  →  进入 ARM 状态（地址本身必须是 4 字节对齐）
目标地址 bit0 = 1  →  进入 Thumb 状态（真实指令地址 = 地址 & ~1）

所以从 ARM 代码跳进 Thumb 函数，要故意把地址加 1：

armasm
    ADR  R0, start_thumb + 1     @ +1 只是标记「目标是 Thumb」，不是真地址
    BX   R0                      @ 进入 Thumb 状态执行

几条容易被忽略的规则：

  • 所有中断和异常发生时，处理器自动切回 ARM 状态。也就是说 IRQ / FIQ / SWI 的处理函数第一句一定是 ARM 指令，想在处理函数里调 Thumb 函数得再 BX 一次。
  • MOV 与 ADD 是 Thumb 里仅有的两个能访问 R8~R15 的指令，而且这两种形式不更新条件标志。
  • 汇编器里用 .code 32 / .code 16 切换编码，或用 .thumb / .arm 伪操作；混编时别忘了告诉链接器（-mthumb-interwork）。

二、数据处理指令 #

2.1 传送 #

指令 作用 例子
MOV Rd, #imm / MOV Rd, Rm 传数据或做纯移位 MOV R0, R0, LSL #3 → R0 = R0 * 8
MVN Rd, #imm 传按位取反的值 MVN R0, #4 → R0 = -5

MOV 有五种典型用法，其中两种与函数返回有关：

  • MOV R0, R0 —— 标准 NOP（短延时）；
  • MOV R0, R0, LSL #3 —— 不带算术逻辑运算的纯移位；
  • MOV PC, LR —— 子程序返回（不带 S）；
  • MOVS PC, LR —— 异常返回，同时把 SPSR 恢复到 CPSR；
  • MOV PC, R0 —— 实现跳转，可代替 B。

2.2 逻辑运算 #

指令 作用 用法要点
AND 按位与 清位（配合 MVN 造掩码）、判断某位是否为 1
ORR 按位或 置位
EOR 按位异或 取反某些位：EOR R0, R0, #3 翻转 bit0/bit1
BIC 位清除 BIC R0, R0, #0x87 一次清掉多位（比 AND + 掩码更直观）

寄存器操作三件套：置位用 ORR、清位用 BIC、翻转用 EOR。写驱动配置寄存器时每天都在用，而且绝不能直接赋值（会破坏同一寄存器里其他位的配置）。

2.3 算术运算 #

指令 作用 说明
ADD / SUB 加 / 减 支持移位操作数：SUB R0, R2, R3, LSL #1 → R0 = R2 - (R3<<1)
RSB 反向减 RSB R0, R2, R3 → R0 = R3 - R2
ADC 带进位加 配合 S 后缀做 64 位加法
SBC 带借位减 64 位减法
RSC 带借位的反向减 RSC R3, R1, #0 可得 64 位数取负的高位

64 位取负的经典写法：

armasm
RSBS R2, R0, #0    @ 低 32 位：0 - R0，产生借位
RSC  R3, R1, #0    @ 高 32 位：0 - R1 - 借位

2.4 比较与测试（不写目标寄存器） #

指令 做什么 结果
CMP Rn, Rm 做一次减法 只更新 CPSR 标志位，不存结果
TST Rn, Rm 做一次按位与 只更新标志位
TEQ Rn, Rm 做一次按位异或 只更新标志位，常用于判断两数是否相等（含符号位）

在数据处理指令后加 S 后缀（ADDS、SUBS、MOVS），结果会更新 CPSR 的标志位。不加就不影响标志位——这是和 C 语言最大的思维差异：标志位是显式管理的。

2.5 条件码：16 个后缀，一条指令当两条用 #

ARM 的每条数据处理指令最高 4 位是条件码字段，满足条件才执行，否则当 NOP（不写目标寄存器、不改标志）。这就是 ARM 不需要大量跳转指令的原因。

后缀 含义 标志条件
EQ 相等 Z=1
NE 不等 Z=0
CS / HS 无符号 ≥（进位/无借位） C=1
CC / LO 无符号 < C=0
MI 负数 N=1
PL 非负 N=0
VS 溢出 V=1
VC 未溢出 V=0
HI 无符号 > C=1 且 Z=0
LS 无符号 ≤ C=0 或 Z=1
GE 有符号 ≥ N=V
LT 有符号 < N≠V
GT 有符号 > Z=0 且 N=V
LE 有符号 ≤ Z=1 或 N≠V
AL 总是（默认，可省略） —
NV 从不（历史遗留，别用） —

两组容易被搞混的：HS/LO 是无符号比较，GE/LT 是有符号比较，选错了在负数上就出错；HI/LS 才是「严格大于 / 小于等于」，比 CS/CC 多带一个 Z 条件。

CMP 后面跟着一串带条件码的指令，是编译器最常见的产物：

armasm
    CMP   R0, #10
    MOVGT R1, #1        @ R0 > 10 才执行
    MOVLE R1, #0        @ 否则执行这条

另外三个「不写目标寄存器」的测试指令要分清：

指令 动作 对 C 的影响
CMP Rn, op2 做减法 Rn - op2 改（有借位则 C=0）
CMN Rn, op2 做加法 Rn + op2 改。CMN R0, #1 等价于与 -1 比较
TST Rn, op2 按位与 Rn & op2 改
TEQ Rn, op2 按位异或 Rn ^ op2 改。TEQ 不碰 C，判断两数是否相等且不破坏进位时用它

三、Load / Store 指令 #

3.1 单寄存器寻址方式 #

写法 含义
LDR R0, [R1] 取 R1 指向的内存
LDR R0, [R1, #4] 取 R1+4 处的内存（前索引，偏移不变）
LDR R0, [R1, #4]! 前索引 + ! 写回：R1 = R1 + 4
LDR R0, [R1], #4 后索引：先取，再 R1 = R1 + 4
LDR R0, [R1, R2, LSL #2] 变址：取 R1 + (R2<<2) 处的内存

! 是「地址更新」后缀，遍历数组时用它最简洁。

3.2 三个容易被搞混的 LDR/ADR #

这是汇编里最经典的坑，一定要分清：

写法 得到什么 是否位置无关
LDR R0, 0x12345678 该地址里的值 否
LDR R0, =0x12345678 伪指令：把 0x12345678 这个值装进 R0（走文字池） 否
LDR R0, _start _start 地址处的值 否
ADR R0, _start _start 的地址，相对于当前 PC 计算 是
LDR R0, =_start _start 的绝对地址 否

再看一个更细的对照：

armasm
COUNT  EQU  0x56000054      @ 定义一个「变量」，地址 0x56000054（GPBDAT）

LDR R1, =COUNT              @ R1 = 0x56000054（地址）
MOV R0, #0
STR R0, [R1]                @ 把 0 写进 0x56000054，即「给变量赋值」

LDR R1, =COUNT              @ R1 = 0x56000054
LDR R0, [R1]                @ R0 = 该地址里的值

位置无关码的三条铁律：只能用 B / BL / ADR（相对 PC 取指）；不能用 LDR =（绝对地址进文字池）；不能访问全局变量（同样依赖绝对地址）。U-Boot 重定位前的代码、以及需要在 NAND 里直接执行的代码，都必须遵守。

3.3 多寄存器传送 LDM / STM #

一条指令在一组寄存器和一块连续内存之间搬数据。用途：现场保护、数据复制、参数传递。

两种编址模式：

类别 后缀 含义
数据块 IA Increment After，i++（最常用）
数据块 IB Increment Before，++i
数据块 DA Decrement After，i--
数据块 DB Decrement Before，--i
堆栈 FD Full Descending，满递减（ARM 的 ATPCS 规定用这个）
堆栈 ED Empty Descending
堆栈 FA Full Ascending
堆栈 EA Empty Ascending

名字里的 F（Full）= 栈指针指向栈顶有效数据，D（Descending）= 栈向低地址生长。「满递减」意味着先减 SP 再存。

三个修饰符：

  • {R1, R2, R6-R9}：寄存器组，不含 PC，必须由小到大书写；
  • !：更新基址寄存器。LDMIA R0!, {R3-R9} 执行后 R0 前进；
  • ^：用户模式寄存器组。若 LDM 的列表含 PC，则同时把 SPSR 复制到 CPSR（异常返回）；不含 PC 时，存取的是 用户模式 的寄存器而非当前模式的。^ 不能用于用户模式。

标准现场保护与恢复：

armasm
STMFD SP!, {R0-R7, LR}      @ 保存现场：寄存器组入栈
...
LDMFD SP!, {R0-R7, PC}      @ 普通函数返回（PC = 原 LR）
LDMFD SP!, {R0-R7, PC}^     @ 异常处理返回，同时恢复 CPSR

八种后缀的两套命名（一套讲地址怎么变，一套讲栈怎么长，说的是同一件事）：

数据块视角 含义 等价的堆栈视角 堆栈类型
IA Increment After（i++） LDMFD / STMED 满递减
IB Increment Before（++i） LDMED / STMFA 空递减
DA Decrement After（i--） LDMFA / STMED 满递增
DB Decrement Before（--i） LDMED / STMFD 空递增

上表「等价的堆栈视角」在教材里各家写法略有出入，真正可靠的是左侧那列 IA/IB/DA/DB——它只描述基址寄存器的增减时机。记法：A = After = 先存取再改基址；B = Before = 先改基址再存取；I = 递增、D = 递减。

逐址展开一个例子，R1 = 0x1000：

armasm
LDMIB R1!, {R0, R4-R6}

IB 是「先加再读」，所以从 0x1004 开始：

寄存器 读取地址
R0 0x1004
R4 0x1008
R5 0x100C
R6 0x1010

执行完 R1 = 0x1014（基址更新到最后一个访问单元之后）。若换成 LDMIA，则是 0x1000 / 0x1004 / 0x1008 / 0x100C，执行完 R1 = 0x1010。

3.4 SWP：原子交换 #

SWP Rd, Rm, [Rn] 一次完成「读内存 + 写内存」且不被打断，用途是做信号量。在 ARMv8 上已被 LDXR/STXR 独占访问指令族取代。

四、跳转与返回 #

4.1 四条跳转指令 #

指令 保存返回地址 可跨状态（ARM↔Thumb）
B 否 否
BL 是（存 LR） 否
BX Rm 否 是（看 Rm 的 bit0）
BLX Rm 是 是

BX 的 bit0 是状态切换的关键：Rm 最低位为 1 则切到 Thumb，为 0 则切到 ARM。这就是为什么函数指针的最低位常被拿来标记状态——C 语言里的函数指针跳转，编译后往往是 BLX。

4.2 子程序返回的三种写法 #

armasm
BX   LR                     @ 推荐，可以在 ARM/Thumb 之间返回
MOV  PC, LR                 @ 传统写法
LDMFD SP!, {..., PC}        @ 恢复现场并同时返回（最常用）

异常返回还要带 S 或 ^ 来恢复 CPSR：MOVS PC, LR 或 LDMFD SP!, {..., PC}^。

五、PSR、协处理器与异常产生 #

5.1 MRS / MSR 与四个位域 #

armasm
MRS R0, CPSR                @ 读：状态寄存器 -> 通用寄存器
MSR CPSR_c, #0xD3           @ 写：cpsr[7:0] = 0xD3，切到管理模式并关中断
MSR CPSR_cxsf, R3           @ 写全部域：c/x/s/f
位域后缀 覆盖范围
c 控制位 [7:0]：模式位、I/F 中断屏蔽、T 状态位
x 扩展位 [15:8]
s 状态位 [23:16]
f 标志位 [31:24]：N/Z/C/V

0xD3 = 0b1101_0011 拆开看：I=1（关 IRQ）、F=1（关 FIQ）、T=0（ARM 状态）、模式位 0b10011 = SVC。启动代码里 orr r0, r0, #0xd3 就是这一串的经典用法。

5.2 协处理器指令 #

指令 作用
MRC p15, 0, R0, c1, c0, 0 从 CP15 读控制寄存器（读 MMU/Cache 配置）
MCR p15, 0, R0, c1, c0, 0 写 CP15 控制寄存器（开 MMU、关 Cache）
LDC / STC 协处理器与内存之间搬数据
CDP 协处理器数据处理

5.3 异常产生 #

指令 作用
SWI #n 软中断，Linux 系统调用的入口（open → swi 5，read → swi 6）
BKPT #n 断点，调试器用

顺带一个能量化的对比：发生 FIQ 时处理器只自动保存 R0~R7 共 8 个寄存器（R8_fiq~R14_fiq 有影子寄存器，不用保存）；而发生 IRQ 时要保存 R0~R12 共 13 个。差的这 5 个寄存器（R8~R12）就是「FIQ 比 IRQ 快」的量化答案——不是玄学，是省了 5 次内存访问。

七、程序结构与工具链 #

7.1 段的种类与标志 #

.section 可以带标志位：a 可分配、w 可写、x 可执行。

段 内容 是否进 bin
.text 指令代码 是
.data 已初始化的数据（常量、字符串） 是
.bss 未初始化数据 否，需程序运行时清零
.sdata / .sbss 小数据段，一般不用关心 —

.bss 不进镜像是个优化，但也带来责任：清零必须自己写。C 语言的 bss 清零是在 start.S 里做的，这也是为什么启动代码总要先清一段内存再跳 main。

7.2 GCC 的四个阶段 #

text
预处理(.c/.h -> .i) -> 编译(.i -> .s) -> 汇编(.s -> .o) -> 链接(.o + .lds -> .elf/.bin)

链接阶段的两件事决定了程序的布局：

  • 链接脚本（.lds） 决定每个段放在哪个地址、入口在哪（ENTRY(_start)）；
  • 符号解析 把 .global 声明的符号在不同 .o 之间对上。

链接地址 = 程序运行时「应该」位于的地方。它由 lds 指定，和实际运行地址可能不同——这个差异就是重定位存在的原因。要学写 lds，最好的范本是 U-Boot 的 u-boot.lds。

7.3 一个真实的例子：U-Boot 里 lowlevel_init 的 FLASH 相对寻址 #

这段代码出自 U-Boot 的 board/samsung/smdk2410/lowlevel_init.S，它解释了一个很实用的技巧：代码在 Flash 里跑、但按链接地址（RAM）计算标号时，怎么拿到「我在 Flash 里的真实位置」。

armasm
    ldr  r0, =SMRDATA              @ 链接期算出来的 RAM 地址（错的位置）
    sub  r0, r0, #CONFIG_SYS_TEXT_BASE   @ 减掉链接基址 = 段内偏移
    ldr  r1, _TEXT_BASE            @ 运行期真正的代码基址（Flash 起始）
    add  r0, r0, r1                @ 偏移 + 真实基址 = 真实数据地址

逻辑是这样：链接器给 SMRDATA 分配的是「假设代码从 CONFIG_SYS_TEXT_BASE 开始」的地址；而现在代码实际跑在 Flash 的 _TEXT_BASE 上。两个基址之差就是整体搬移量，所以：

text
真实地址 = 链接地址 - CONFIG_SYS_TEXT_BASE + _TEXT_BASE

这就是「位置相关代码在重定位前如何自举」的标准解法，比 ADR 更通用（ADR 只能覆盖 ±4KB / ±2KB 范围）。

八、AAPCS：调用约定 #

8.1 名词先分清 #

缩写 全称 含义
ABI Application Binary Interface 应用程序二进制接口（最终标准）
EABI Embedded ABI 嵌入式 ABI 变体
PCS Procedure Call Standard 过程调用标准
AAPCS PCS for ARM Architecture ARM 架构的过程调用标准（现行）
ATPCS ARM-Thumb PCS 早期版本，仍是同一套规则的通俗叫法
PIC / PID Position Independent Code / Data 位置无关代码 / 数据

8.2 寄存器使用规则 #

寄存器 别名 规则
R0~R3 a1~a4 传参。被调函数返回前不需要恢复它们
R4~R11 v1~v8 保存局部变量。子程序用了就必须在入口保存、出口恢复
R12 IP 过程调用中间临时寄存器，连接代码段用
R13 SP 栈指针，进出口必须相等，不能挪用
R14 LR 链接寄存器，保存返回地址。保存后可用作他用
R15 PC 程序计数器，不能用作其他用途

Thumb 程序通常只能用 R4~R7 保存局部变量，这是 16 位指令编码里寄存器号只有 3 位的结果。

8.3 堆栈规则 #

ATPCS 规定堆栈是 FD 类型（满递减），且栈操作 8 字节对齐。

汇编程序若包含外部调用，必须满足两条：

  1. 外部接口处的堆栈是 8 字节对齐的；
  2. 用 PRESERVE8 伪指令告诉链接器本文件的栈是 8 字节对齐。

8.4 参数传递 #

固定参数个数：前 4 个走 R0~R3，第 5 个起走栈。

可变参数个数：同样前 4 个走寄存器；超过 4 个走栈时，入栈顺序与参数顺序相反——最后一个参数先入栈。

这条「反过来压栈」的规则初看很怪，但它保证栈上的参数按地址递增顺序排列，被调函数可以用固定偏移访问。

8.5 返回值规则 #

返回类型 放在哪
32 位整数 R0
64 位整数 R0 + R1
浮点数 s0 / d0 / f0（浮点寄存器）
复合型浮点（如复数） f0~fn / d0~dn
更大的结构体 通过内存（由调用者在栈上分配并传指针）

九、GCC 内联汇编 #

9.1 四种基本形式 #

c
/* 1. 最简：无输入输出 */
asm("mov r0, r0");                    /* NOP，短延时 */

/* 2. 多条指令：用换行加制表符分隔 */
asm("mov r0, r0"\n\t"mov r0, r0");

/* 3. 通用模板：四部分 */
asm(code : output operand list : input operand list : clobber list);

/* 4. 带 volatile 与 memory clobber */
asm volatile("mov r0, r0" ::: "memory");

省略规则：尾部没用到可以省，但中间没用到也必须留空占位。例如只写 clobber 时：asm("" ::: "memory");，前面两个冒号不能省。

9.2 操作数约束字母 #

字母 含义
r 任意通用寄存器（编译器挑一个闲着的）
m 内存
i 立即数（只能用于输入）
g 寄存器 / 内存 / 立即数都行（「编译器你看着办」）
a b c d S D 分别对应 x86 的 eax ebx ecx edx esi edi（ARM 上不太用）

修饰符：= 只写（输出），+ 读写，& 早写（输出不能和输入复用同一寄存器）。

9.3 操作数引用与寄存器转义 #

c
int a = 1, b = 2, c = 0;
asm("addl %2, %0"        /* %0=第一个操作数(c)，%2=第三个(b) */
    : "=g"(c)            /* 输出：c */
    : "0"(a), "g"(b)     /* 输入1：与第 0 个操作数同寄存器；输入2：b */
    : "memory");         /* clobber：内存被改了 */
  • %序号 引用操作数，从 0 开始，按「输出在前、输入在后」编号；
  • %%eax 两个 % 才是真正的寄存器名（用来和操作数序号区分）；
  • "0"(a) 表示「用第一个操作数的位置初始化」，所以 %0 和 %1 是同一个东西。

9.4 命名操作数（可读性更好） #

c
asm("mov %[result], %[value], ror #1"
    : [result] "=r" (y)   /* 结果 -> y */
    : [value]  "r"  (x)   /* 输入 <- x */
    :);

命名操作数有独立的命名空间，和数字序号可以混用。名字不会与 C 变量冲突。

9.5 clobber list 与优化 #

这是一个真实的坑：

c
/* 想用关中断保护 c *= b，但没告诉编译器！ */
asm volatile("mrs r12, cpsr"\n\t"orr r12, r12, #0xC0"\n\t"msr cpsr_c, r12" ::: "r12", "cc");
c *= b;   /* This may fail. */

优化器可能把乘法提到两条内联汇编之外，保护就失效了。修正办法是加 "memory"：

c
asm volatile("mrs r12, cpsr"\n\t"orr r12, r12, #0xC0"\n\t"msr cpsr_c, r12" ::: "r12", "cc", "memory");
c *= b;   /* This is safe. */
clobber 项 含义
寄存器名（如 "r12"） 这段汇编改了该寄存器，编译器不要在其中存活跃变量
"cc" 改了条件码（CPSR 标志位）
"memory" 改了内存，编译器的内存缓存全部失效，必须重新读

volatile 的作用是禁止优化器删除或重排这条汇编；"memory" 的作用是禁止优化器跨越它搬运内存访问。两者解决的不是同一个问题，通常要一起用。

9.6 为什么需要内联汇编 #

只有三种情况必须用它：

  1. 程序中要做饱和算术运算（C 没有对应语法）；
  2. 程序要操作协处理器（CP15、NEON 系统寄存器）；
  3. 在 C 中读写 CPSR / SPSR（开关中断、查模式）。

性能不是理由。现代编译器对普通 C 代码的优化通常优于手写汇编；真需要性能时应该用 intrinsics 或调整算法，而不是把整个函数改成汇编。

十、VC 内联汇编 #

用于在桌面端验证算法，语法比 GCC 简单得多：

c
__asm {
    push eax        /* 自己保护要改的寄存器 */
    mov eax, a
    add eax, b
    mov c, eax
    pop eax
}
对比项 GCC 内联汇编 VC 内联汇编
变量引用 必须通过操作数列表 + %n 直接写变量名
寄存器保护 编译器根据 clobber 列表自动调度 必须自己 push/pop
保留字限制 无特殊 有，如 size 作变量名会编译不过
优化能力 强（知道读写集合） 无（不知道你改了哪些寄存器）

结论：效率上 VC 完败。它的唯一价值是入门时更容易看懂「内联汇编在做什么」。

十一、C 与汇编互调 #

11.1 C 调汇编 #

只要汇编函数遵守 AAPCS，C 里直接 extern 声明即可：

c
extern int function(void);   /* 汇编里用 .global function 导出 */
int r = function();

11.2 汇编调 C #

汇编里需要声明外部符号：

armasm
.global function
.extern compare_ip          @ 声明要调用的 C 函数

function:
    STMFD SP!, {R0-R3, LR}   @ 保护现场（R0-R3 是参数寄存器，别覆盖）
    MOV   R0, #0xC0
    MOV   R1, #0xA8
    MOV   R2, #0x01
    MOV   R3, #0x98
    BL    compare_ip         @ 前 4 个参数走 R0-R3
    LDMFD SP!, {R0-R3, PC}   @ 恢复并返回

11.3 内嵌汇编使用物理寄存器的四条限制 #

  1. 不能直接给 PC 赋值，跳转只能用 B / BL；
  2. 不要写过于复杂的 C 表达式（需要太多寄存器，容易冲突）；
  3. 不要同时占用 R0~R3、R12、R14——编译器算中间结果时可能正在用它们；
  4. 内存分配全部由 C 编译器负责，内嵌汇编不支持 .space 这类分配伪指令。

还有两条细节：

  • 内嵌汇编里常量前的 # 可以省略；
  • 只有 B 可以使用 C 程序的标号，BL 不行（因为 BL 会写 LR，破坏 C 的调用链）。

十二、实战：内核里的 memcpy #

Linux 内核里这类小函数常写成内联汇编，是最好的学习材料：

c
/* 位于 arch/x86/boot/compressed/misc.c */
void *memcpy(void *dest, const void *src, size_t n)
{
    int d0, d1, d2;
    asm volatile(
        "rep ; movsl" NL TAB
        "movl %4,%%ecx" NL TAB
        "rep ; movsb" NL TAB
        : "=&c" (d0), "=&D" (d1), "=&S" (d2)
        : "0" (n / 4), "g" (n % 4), "1" ((long) dest), "2" ((long) src)
        : "memory");
    return dest;
}

几个值得注意的点：

  • rep movsl 按 4 字节搬 n/4 次，再用 rep movsb 搬剩下的 n%4 字节——这就是「先按大块搬、再搬余数」的通用套路；
  • =&c / =&D / =&S 里的 & 表示早写：输出不与输入复用寄存器，否则 ecx 从 n/4 被改成 0 之后就找不到 n%4 了；
  • 输入用 "0" / "1" / "2" 绑定到对应输出寄存器，避免额外移动；
  • "memory" 必不可少，否则编译器可能把后续对 dest 的读提到 memcpy 之前。

附录：素材来源与勘误 #

本篇由若干旧稿合并而成，来源并不单一，看的时候要留意三处「时代痕迹」：

  1. §一、§四~§九 的骨架译自 Acorn Archimedes / RISC OS 时代的汇编手册。因此会出现 podule、A5000、82C71x、Econet 这些 1990 年代英国机器的名词，以及 .start_counter 这种带点号的标签、CHR$0 这种 BBC BASIC 写法——它们和 ARM Linux 无关，保留只为对照原书。
  2. §七 的链接脚本与 lowlevel_init 是 U-Boot / S3C2440 的真实代码，可以直接用。
  3. §十一 示例 3 里的 GPKCON = 0x7f008800 / GPKDAT = 0x7f008808 其实是 S5PV210 的地址，不是 S3C2440（2440 的 GPB 控制寄存器在 0x56000010）。结论仍然成立，但地址别照抄。

已修正的原文错误（避免你日后翻旧稿时困惑）：

原文说法 实情
MOV 立即数「不能超过 512」 是 0~255（8 位）配合 4 位循环右移
CPSR 位图里没有 T 位 T 在 bit5，Q 在 bit27
「FIQ 不能调用 SWI」 是编程惯例（FIQ 要求极快、SWI 会切模式），不是硬件禁止
注释用 # ARM 汇编里 # 是立即数前缀，注释是 @（GNU as）或 ;（ARM 官方汇编器）
缺条件码表 已补 §2.5 的 16 条

十三、速查表 #

症状 / 需求 做法
汇编报告「立即数非法」 用 LDR R0, =常数 走文字池
代码搬到别处后跑飞 检查是否用了 LDR = 或全局变量，改成 B/BL/ADR
只想改寄存器的某几位 置位 ORR、清位 BIC、翻转 EOR，别整体赋值
函数返回后跳错地方 BL 的 LR 被覆盖；嵌套时先切系统模式
内联汇编优化后行为错乱 补 volatile 和 "memory" clobber
内联汇编里改了寄存器但 C 值不对 该寄存器必须列进 clobber 列表
汇编调 C 后参数被破坏 入口 STMFD SP!, {R0-R3, LR} 保护参数寄存器
.bss 变量初值不是 0 启动代码没清零 .bss 段
栈错乱 / 崩溃 检查是否 8 字节对齐、SP 进出口是否相等、是否用了 PRESERVE8

小结 #

  • 指令 / 伪指令 / 伪操作要分清：前两个生成代码，第三个只指挥汇编器。
  • 立即数只有 12 位编码，大常数靠 LDR = 走文字池；ADR 相对、LDR = 绝对，这决定能不能写位置无关码。
  • LDM/STM 的 IA/IB/DA/DB 与 FD/ED/FA/EA 是两套命名；ATPCS 规定用 FD 满递减 + 8 字节对齐。
  • AAPCS 是本篇的核心：R0~R3 传参、R4~R11 保存局部变量、R13 栈指针进出口必须相等。记住它，混合编程就不会错。
  • GCC 内联汇编的四部分 + 约束字母 + clobber 列表是一套完整契约；volatile 防重排，"memory" 防内存缓存，通常要一起用。
