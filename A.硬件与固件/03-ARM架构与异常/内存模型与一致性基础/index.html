一、内存模型到底在定义什么 #

一句话定义：memory consistency model 定义了系统中的内存访问必须遵守的规则，本质上就是「一次 read 返回什么值」。

它约束三方：

对象 关心什么
高级语言程序员 我写的代码在多核上会不会看到意外值
编译器作者 允许我做哪些重排
CPU 设计者 硬件必须保哪些序

1.1 放松的两个维度 #

一个模型能「松」到什么程度，取决于两件互相独立的事。

维度一：core 是否可以不走 program order。 细分成三种相关对：

缩写 前者 → 后者 含义
RAW（Read After Write） store → load 先写后读同一地址
WAW（Write After Write） store → store 两次写同一地址
WAR（Write After Read） load → store 先读后写同一地址

前提是这对操作必须落在不同 memory location。同地址有数据依赖，硬件必须保序，否则单核逻辑就崩了。ARMv8 在没有 barrier 时，program order 中不同地址的 RAW、WAW、WAR 对全部可以被重排。

维度二：core 的 write 是否必须全局原子。 也就是 multi-copy atomicity。ARMv8 的 normal memory 写操作不具备 multi-copy atomicity。

1.2 任何模型都不能放松的两条底线 #

  1. 单核上数据依赖与控制依赖必须保序，不能 out of order；
  2. 对同一地址的写必须串行化——有 cache 时靠 cache coherence 协议保证。

这两条丢了，连单线程程序都不成立，谈多核没有意义。

二、Sequential Consistency：那个「理想模型」 #

2.1 定义原文 #

the result of any execution is the same as if the operations of all the processors were executed in some sequential order, and the operations of each individual processor appear in this sequence in the order specified by its program.

通俗版：core 0 执行 A B C D，core 1 执行 a b c d，整体效果等价于单核上按某个交错序执行。可以是 A a B b C c D d，可以是 A B a b C c D d，也可以是 A B C D a b c d——但不是任意排列，合并后的序列必须同时满足 A→B→C→D 与 a→b→c→d 两条 program order。

2.2 SC 的两条规则 #

规则（1）：各 core 严格按 program order 执行，执行完一条才启动下一条，没有 local reordering。

对应的经典例子是 Dekker algorithm：初值 flag0 = flag1 = 0。core 0 想进临界区时先置 flag0 = 1，再判断 flag1 是否为 0；若是 0，说明 core 1 还没执行到 flag1 = 1，也就隐含了「flag0 = 1 已经完成」。SC 保证各自的 local program order 被严格执行，所以两个线程不可能同时进临界区。

规则（2）：从全局看，每一个写操作被系统中所有 core 同时感知。

「同时」的画面感是：CPU 系统和存储系统之间有一个开关，一次只接通一个 core，于是对 memory 的访问天然是原子的、串行的——某个 core 的写完成后，开关才放行下一个内存操作。

配套例子（初值 A = B = 0）的推导链：若 core 1 执行了 B = 1，说明它已经感知到 core 0 对 A 的写；既然「写被所有核同时感知」，core 2 必然也知道 A 等于 1，那么 core 2 读 A 时 A 必须是 1。

两个例子分工不同，别混：Dekker 证明规则（1）（保序 → 互斥），A = B = 0 证明规则（2）（全局同时可见 → 传递可见性）。多数资料只给 Dekker。

2.3 SC 的代价 #

SC 简单直观，但把硬件和编译器的优化空间锁死了，性能代价极大。云计算、大数据把这一要求碾了过去，于是有了 relaxed consistency model。ARMv8 属于 Relaxed Memory Consistency Models，「Relaxed」是相对 SC 而言的。

三、四类模型与它们的重排矩阵 #

先立一个基础内存模型：C1、C2 两个 core，各自私有 L1，共享 L2，最后是主存。全文假设 cache coherence 是完美的（多核 cache 之间的同步与单核无异），以此隔离出「纯 memory order」问题。

3.1 重排矩阵 #

模型 store→load store→store load→load load→store 机制根因
SC 禁止 禁止 禁止 禁止 无 store buffer
TSO 允许 禁止 禁止 禁止 store buffer + FIFO 排空
PSO 允许 允许 禁止 禁止 store buffer 非 FIFO，仅同地址保序
RMO 允许 允许 允许 允许 地址无关的 load/store 全部可打乱

3.2 TSO 是怎么被 store buffer 逼出来的 #

store buffer 给 store 提供缓冲，只要 buffer 还有空位，一次写只需要 1 个时钟周期。作为对比，Cortex-A76 访问一次 L1 也要 3 个 cycle。数据先进 store buffer，再写进 L1。

看三条指令：

text
S1：store flag = set
S2：load  r1  = data
S3：store b    = set

S1 塞进 store buffer 就立即返回，CPU 接着执行 S2；S2 是读，必须等数据到 r1 才能继续。于是很可能 S1 还挂在 buffer 上、S2 已经执行完——特别是当 data 在 cache 里而 flag 不在时，CPU 会更倾向先跑 S2 以减少等待。

此时模型已经从 SC 变成 TSO。但 TSO 有一条定义性的约束：store buffer 必须严格按 FIFO 次序把数据发往主存，先进去的先出来。于是 S3 必定在 S1 之后——store 之间的顺序仍被保住，所以叫「完全存储定序」（Total Store Order）。

TSO 的经典双核反例：SC 下所有可能的执行序是

text
S1 S2 L1 L2
S1 L1 S2 L2
S1 L1 L2 S2
L1 L2 S1 S2
L1 S1 S2 L2
L1 S1 L2 S2

六种里至少有一个 core 的 r1 是 NEW，或者两者都是 NEW。而 TSO 下 store 与 load 之间被 store buffer 解耦，两个 core 的写都还滞留在各自 buffer 里，于是两个 r1 可以同时为 0。这就是 store-load 乱序对代码逻辑的破坏。

3.3 PSO：store buffer 不再 FIFO #

只保证地址相关的指令在 store buffer 中 FIFO，其余的可以乱序。

例子：S1（store flag）与 S2（store data）地址无关。若 flag 已在 C1 的 cache 中，CPU 会优先完成 S2 的 store，等 data 进 cache 后再执行 store data = NEW。可能的执行序变成 S2 L1 L2 S1，C2 在 data 更新之前就跑完了，r2 最终是 0 而不是 NEW。

store-store 乱序会把多线程代码彻底击溃——这类 bug 在单核测试里永远复现不出来。

3.4 RMO：全部放开 #

不仅 store-load、store-store，连 load-load、load-store 都允许。这时即使 C1 侧没有 store-store 乱序，C2 自己 L1 与 L2 之间地址无关导致的 load-load 乱序也足以让 r2 为 0。

ARM 的很多微架构就是 RMO 模型，所以 dmb 才需要带选项：

text
LD   →  约束 load-load / load-store
ST   →  约束 store-store / store-load
SY   →  约束 any-any（全屏障）

屏障的根本作用是：要求 CPU 在此刻以顺序存储一致性模型的方式处理 load 与 store。TSO / PSO 只需写屏障，最简实现就是「等 store buffer 清空」；RMO 则读屏障也要，保证前面的 load 必须先于后面的 load/store。

四、Observability：手册里那几个词到底什么意思 #

这一节啃的是 ARM 手册的定义，读起来枯燥，但不搞清 observer 与 complete 的区别，就看不懂 DSB 到底等了什么。

4.1 observer 不等于 core #

An observer is a master in the system that is capable of observing memory accesses.

两个关键词：master（能通过总线发出读写）与观察（能通过 read/write 感知别人做了什么）。

一个 PE 内部可能有好几个 observer：

observer 能力
执行 load/store 的部件 可读可写
执行取指的部件 只能发起 read
加载页表的部件（table walk） 只能发起 read

所以 observer 数 ≠ core 数。GPU、DMA controller 也都是 observer。

4.2 判据 #

I have observed your write when I can read what you wrote, and I have observed your read when I can no longer change the value you read.

说得非常直白：A 通过 read 拿到了 B 写的值 → A 观察到了 B 的 write；A 无论怎么 write 都影响不了 B 那次 read 的结果 → A 观察到了 B 的 read。

4.3 observed write 的正式定义 #

A write to a location in memory is said to be observed by an observer when: — A subsequent read of the location by the same observer returns the value written by the observed write, or written by a write to that location by any observer that is sequenced in the Coherence order of the location after the observed write. — A subsequent write of the location by the same observer is sequenced in the Coherence order of the location after the observed write.

拆开看有两个反直觉的地方。

反直觉一：read 不一定要读到那个值，也能算「已观察到」。 只要读到的是 coherence order 中排在它之后的写，同样算。

举原文的四核实例。四个 core 跑同一段代码：cpux 把全局变量 A 赋值为 x，然后不断 load A 观察。A 依次被写成 1、2、3、4。某次运行的观测结果是：

core 观测序列
cpu 1 {1, 2}
cpu 2 {2}
cpu 3 {3, 2}
cpu 4 {4, 2}

对应的全局 coherence order 是 {3, 1, 4, 2}。以 cpu4 写的 4 为观察对象：cpu1 起始读到 1，约 300 ns 时读到 2——因为 {3,1,4,2} 里 4 排在 2 之前，此刻 cpu1 已经观察到 4 了，尽管它从没读到过 4。

反直觉二：write 也能「观察」write。 cpu2 执行写 2 时，就因为它在 coherence order 中排在 4 之后，视为 cpu2 已观察到 cpu4 的写。

注意：observed write 永远以某个特定 observer 为视角，不是全局概念。

4.4 globally observed write #

定义结构完全相同，只把「the same observer」换成「any observer in that shareability domain」。两个要点：(1) 限定在一个 shareability domain 内或指定的 observer 集合；(2) 域内所有 observer 都观察到，才算 globally observed。

4.5 observed read #

A read of a location in memory is said to be observed by an observer when a subsequent write to the location by the same observer has no effect on the value returned by the read.

读无法被读感知，只能通过 write 来感知：如果你的写怎么也影响不了某个 read 的结果，那这个 read 已经执行完了。

4.6 completion：为什么「被观察到」还不算完 #

A read or write is complete for a shareability domain when all of the following are true: — The read or write is globally observed for that shareability domain. — Any translation table walks associated with the read or write are complete for that shareability domain.

而 walk 的完成条件是：

A translation table walk is complete for a shareability domain when the memory accesses associated with the translation table walk are globally observed for that shareability domain, and the TLB is updated.

这条把「内存访问完成」与「MMU/TLB 的副作用完成」绑在一起了。它解释了两件工程上的事：

  1. 改完页表为什么必须 DSB 之后才 TLBI，TLBI 之后又要 DSB——因为「完成」的定义里包含 TLB 已更新；
  2. 为什么 DSB 比 DMB 贵得多：DMB 只要求「看起来完成了」（appear to have completed），DSB 要求「真正完成了」（actually complete）。

五、Atomicity 与 coherence order #

5.1 为什么需要单独定义 #

Atomicity 属于软硬件接口里的第二类（行为/操作定义），第一类是寄存器、状态寄存器、协处理器寄存器、指令集这些显式接口。它不显眼，但一样关键。

术语分工要先分清：

  • single-copy atomicity 描述「单核上这一次访问能不能被打断」；
  • 但即便在本核上原子，也挡不住别的核对同一地址动手，于是需要 multi-copy atomicity 描述多核写同一地址时的表现。

两者不是对立概念，是两个不同维度。

5.2 coherence order #

Data accesses from a set of observers to a byte in memory are coherent if accesses to that byte by the members of that set are consistent with there being a single total order of all writes to that byte by all members of that set. This single total order of all writes to that memory location is the coherence order for that byte.

五点解读：

  1. coherent 受限于「a set of observers」，即 shareability domain；域内 observer 共享 memory space 且能访问同一地址。
  2. 是否 coherent 是从域内 observer 的视角观察写动作，观察结果表现为「存在一致的全局写序」。
  3. write serialization 的前提是写同一 memory location。
  4. 拿前面的四核数据验：观测 {1,2} / {2} / {3,2} / {4,2} 与全局序 {3,1,4,2} 是一致的；若 cpu1 观测到 {2,1}，就不存在任何一致的全局序，那就是不 coherent。
  5. 原文用「byte in memory」是因为 ARM 体系里只有 byte 访问永远满足 single-copy atomic，所以拿 byte 当特例。

5.3 single-copy atomicity #

A read or write operation is single-copy atomic only if it meets the following conditions:

  1. For a single-copy atomic store, if the store overlaps another single-copy atomic store, then all of the writes from one of the stores are inserted into the Coherence order of each overlapping byte before any of the writes of the other store are inserted into the Coherence orders of the overlapping bytes.
  2. If a single-copy atomic load overlaps a single-copy atomic store, and for any of the overlapping bytes the load returns the data written by the write inserted into the Coherence order of that byte by the single-copy atomic store, then the load must return data from a point in the Coherence order no earlier than the writes inserted into the Coherence order by the single-copy atomic store of all of the overlapping bytes.

名词先解释：

  • overlap：两条指令同时执行；overlapping byte 是内存区域重叠。例如从 0x000 读 4 字节、从 0x002 读 2 字节，重叠 2 个字节。
  • copy 是什么：PE 访问内存时数据从 memory copy 到寄存器。只触发一次 copy 才叫 single-copy。从奇数地址开始读 2 字节实际会触发两次 copy，所以它是 multi-copy——注意这个 multi-copy 不是 Multi-copy atomicity 里的那个。
  • all of the writes：本次 store 涉及的每一个 bit 作为不可分割整体插入 coherence order。

两条规则的实际含义：8 个 bit 同时被 A、B 两个 store 覆盖时，这 8 个 bit 要么全是 A 的结果、要么全是 B 的结果，不能混合；load 与 store 重叠时，重叠区的返回值要么全被写入、要么完全没写，不存在中间态。

5.4 multi-copy atomicity #

In a multiprocessing system, writes to a memory location are multi-copy atomic if both of the following are true:

  1. All writes to the same location are serialized, meaning they are observed in the same order by all observers, although some observers might not observe all of the writes.
  2. A read of a location does not return the value of a write until all observers observe that write.

这里的 copy 是另一个意思：系统有 n 个 core，每个都可能对同一地址发起写，于是可能有 n 个 register→memory 的 copy 动作。

两条要求都很苛刻：写序要对所有 observer 一致（严于 coherent，不 coherent 必然不 multi-copy atomic）；load 必须阻塞到该值对所有 observer 可见。对性能伤害很大。

5.5 ARMv8 的实际分档 #

single-copy atomicity：

情形 是否 single-copy atomic
对齐的 load / store 是（byte 访问恒成立，2 字节对齐在 2 上也成立，以此类推）
LDP / STP（Load/Store Pair） 不是，但可视为两条 single-copy atomic 指令
LDXP / STXP（各操作 2 个 32-bit） 是

multi-copy atomicity：

内存类型 写是否 multi-copy atomic
Normal memory 不需要具备
Device 类型 + non-Gathering 所有满足 single-copy atomic 的写都是
Device 类型 + Gathering 不需要具备

最后那张表里最容易忽略的是第二行：它决定了设备驱动的 dmb 与映射属性怎么选。

顺带一个写驱动时直接相关的选型结论：要做 atomic64 或 16 字节访问时，LDP/STP 不保证原子，得用 LDXP/STXP。

六、Cache：原子性与一致性的物理底座 #

6.1 数量级差距 #

层级 延迟
寄存器 < 1 ns
cache ≈ 1 ns
主存 ≈ 65 ns

程序从 Flash（eMMC、UFS）load 到 main memory（DDR3/DDR4）后执行。寄存器与主存差近百倍，cache 几乎是「第二层寄存器」——这就是为什么所有乱序优化都围绕 cache 和 buffer 展开。

6.2 Cortex-A53 的层级 #

L1 分 ICache / DCache，每核私有；一个 cluster 内所有 CPU 共享 L2，L2 不区分指令和数据；所有 cluster 共享 L3；L3 经总线连主存。

两个术语：

  • inclusive：某地址数据可同时存在于多级 cache（L1 miss → 查 L2 → 命中则回填 L1）；
  • exclusive：某地址数据只存在于多级中的某一级，不可能同时在 L1 和 L2。

6.3 cache line 与地址划分 #

cache 被切成等大的块，每块一条 cache line，现代硬件一般 4~128 字节。cache line 是 cache 与主存之间传输的最小单位：CPU 只读 1 字节而 miss，控制器也会一次 load 整条 line。

为什么不做成 1 字节：每条 line 需要一个 tag（回写还要 dirty bit，有效性还要 valid bit）。8 字节一条 line 只要 1 个 tag，1 字节一条就要 8 个 tag，硬件成本直接爆炸。

直接映射的算例（64 字节 cache / 8 字节 line，共 8 行）：

部分 位宽 说明
offset 低 3 位 寻址 line 内的 8 个字节
index 3 位 寻址 8 行，即地址 bit3~bit5，index 相同的不同地址落到同一 line
tag 48 − 6 = 42 位 与 index 一起唯一确定地址

先查 valid bit（1 有效 / 0 无效，系统刚启动时全是 0），无效直接判 miss，比 tag 才有意义。

再举一例：512 字节 cache / 64 字节 line → offset 6 位、index 3 位、tag 39 位。

cache 颠簸（thrashing）：依次访问 0x00、0x40、0x80，三者 index 相同、映射到同一 line，每次都 miss 并互相替换，cache 等于不存在。

两路组相连（64 字节 / 8 字节 line）：分成 2 路，每路 4 行；offset 仍是 3 位，index 只要 2 位（一路只有 4 行），index 也叫 set index。先按 index 找到 set，再把 set 内所有 line 的 tag 与地址 tag 比较，任一相等即命中。0x00 进 way 1、0x40 进 way 0，互不冲突；4 路时连 0x80 也能缓存。最差情况与直接映射相同，多数情况更优。

全相连：所有 line 在一个 set，地址不需要 index 部分（「只有一个组可选，等于没得选」），tag 与所有 line 比较。颠簸最少，成本最高。

直接映射 = 单路组相连。这个等价关系能帮你把三种组织方式统一成「路的数量」这一个参数。

练习：32KB、4 路、32 字节 line。每路 8KB、每组 128 字节 → 256 组；offset 5 位、index 8 位、tag 35 位（48 位地址）。

6.4 分配与更新策略 #

策略 含义
读分配 读 miss 时分配 line 并缓存，默认都支持
写分配 写 miss 时；不支持则写只更新主存就结束；支持则先 load 整条 line 再改
写直通（write through） 同时更新 cache 与主存，始终一致
写回（write back） 只更新 cache 并置 dirty bit，主存只在 line 被替换或显式 clean 时更新

写回的直接后果：主存里可能是旧值，新值躺在某条 cache line 里。这就是 DMA 与多核一致性问题在物理层的根源。

为什么 line 是最小传输单位：每条 line 只有一个 dirty bit，这一个 bit 代表整条 line 的修改状态。

写回实例：64 字节直接映射、8 字节 line、写分配 + 写回；CPU 读 0x2a 一个字节。

  1. 按 index 定位 line，valid 有效但 tag 不等 → miss；
  2. 需要从 0x28 起加载 8 字节；
  3. 但该 line 的 dirty bit 已置位，数据 0x11223344 不能丢，按 tag 与行号算出地址 0x0128 并写回主存；
  4. 写回完成后把 0x28 起 8 字节装入该 line 并清 dirty；
  5. 按 offset 取出目标字节返回 CPU。

七、AArch64 的原子操作是怎么落地的 #

7.1 出发点：一条内核注释 #

内核里那段注释的意思是：在 ARM 上 pgprot_noncached 会把内存映射成 strongly ordered，而 strongly ordered 内存上的原子操作是 implementation defined，在 omap 等平台上直接失效。

这句话引出后面一整节：为什么 non-cacheable 内存上原子操作不可靠。

7.2 读写的捷径 #

c
#define atomic_read(v)   READ_ONCE((v)->counter)
#define atomic_set(v, i) WRITE_ONCE(((v)->counter), (i))

普通读写即可，不需要特殊指令。

7.3 分发层：LSE 与 LL/SC 二选一 #

c
#define ATOMIC_OP(op)                                  \
    static inline void arch_##op(int i, atomic_t *v)    \
    {                                                  \
        __lse_ll_sc_body(op, i, v);                    \
    }

#define __lse_ll_sc_body(op, ...)                      \
    ({                                                 \
        system_uses_lse_atomics() ?                    \
            __lse_##op(__VA_ARGS__) :                   \
            __ll_sc_##op(__VA_ARGS__);                 \
    })

ATOMIC_OP(atomic_add)

运行时按 system_uses_lse_atomics() 二选一。这是整条链上最关键的分发点。

7.4 LSE 路径（ARMv8.1 新增） #

c
#define ATOMIC_OP(op, asm_op)                                \
    static inline void __lse_atomic_##op(int i, atomic_t *v)  \
    {                                                        \
        asm volatile(                                        \
            "   " #asm_op "   %w[i], %[v]\n"                \
            : [i] "+r" (i), [v] "+Q" (v->counter)            \
            : "r" (v));                                      \
    }

ATOMIC_OP(andnot, stclr)
ATOMIC_OP(or,     stset)
ATOMIC_OP(xor,    steor)
ATOMIC_OP(add,    stadd)

64 位减法用两条指令：

c
static inline void __lse_atomic64_sub(s64 i, atomic64_t *v)
{
    asm volatile(
        "   neg    %[i], %[i]\n"
        "   stadd  %[i], %[v]"
        : [i] "+&r" (i), [v] "+Q" (v->counter)
        : "r" (v));
}

单条 stadd 就完成一次原子加。但这些是 ARMv8.1 才加的指令，不是所有 AArch64 都支持——这就是必须有运行时分发的原因。

7.5 LL/SC 路径 #

c
#define ATOMIC_OP(op, asm_op, constraint)                              \
    static inline void __ll_sc_atomic_##op(int i, atomic_t *v)         \
    {                                                                  \
        unsigned long tmp;                                             \
        int result;                                                    \
        asm volatile("// atomic_" #op "\n"                               \
            __LL_SC_FALLBACK(                                          \
                "   prfm  pstl1strm, %2\n"                            \
                "1: ldxr  %w0, %2\n"                                  \
                "   " #asm_op "   %w0, %w0, %w3\n"                    \
                "   stxr  %w1, %w0, %2\n"                             \
                "   cbnz  %w1, 1b\n")                                 \
            : "=&r" (result), "=&r" (tmp), "+Q" (v->counter)          \
            : __stringify(constraint) "r" (i));                      \
    }

要点：prfm pstl1strm 先把该地址预取到 L1 供 store 用；ldxr / stxr + 算术指令 + cbnz 构成重试环（标签 1: 与 1b）。

7.6 内存序变体的落地方式 #

c
#define ATOMIC_OPS(...)                                              \
    ATOMIC_OP(__VA_ARGS__)                                            \
    ATOMIC_OP_RETURN(         , dmb ish,  , l, "memory", __VA_ARGS__) \
    ATOMIC_OP_RETURN(_relaxed,          ,  ,  ,         , __VA_ARGS__) \
    ATOMIC_OP_RETURN(_acquire,          , a,  , "memory", __VA_ARGS__) \
    ATOMIC_OP_RETURN(_release,          ,  , l, "memory", __VA_ARGS__) \
    ATOMIC_FETCH_OP (         , dmb ish,  , l, "memory", __VA_ARGS__) \
    ATOMIC_FETCH_OP (_relaxed,          ,  ,  ,         , __VA_ARGS__) \
    ATOMIC_FETCH_OP (_acquire,          , a,  , "memory", __VA_ARGS__) \
    ATOMIC_FETCH_OP (_release,          ,  , l, "memory", __VA_ARGS__)

ATOMIC_OPS(add, add, I)
ATOMIC_OPS(sub, sub, J)

规律非常整齐：

变体 后缀 额外指令 clobber
_relaxed 无 无 无
_acquire a（ldaxr） 无 "memory"
_release l（stlxr） 无 "memory"
全序版 l 额外插 dmb ish "memory"

约束字母 I / J 用于立即数操作数。

7.7 指令清单 #

text
A64:      ldx,   ldax,   stx,   stlx
A32/T32:  ldrex, strex,  ldaex, stlex

ARMv8 的原子操作有 LL/SC 与 LSE 两条实现路线，内核两条都留着。

7.8 为什么 non-cacheable 上不可靠 #

从 Cortex-A55 手册得到的结论：

内存类型 原子操作靠什么实现
cacheable 借助 cache 完成原子性，都没问题
device / non-cacheable 依赖**互联网络（interconnect）**支持，对 ARM 就是各类 AMBA 总线；不支持则引发同步或异步异常

根因不是「CPU core 不会做原子」，而是 SOC 内部总线 / 末端内存的硬件实现不支持原子传输。

AMBA 侧的机制：AXI 有 Atomic transaction support，总线上有专门的协议与信号实现 exclusive access，AMBA 的 exclusive access monitor 会存下传输的 id 与地址，以此监控原子传输。

还有 CPUECTLR.ATOM 控制 atomic 访问走 near / far；默认配置下硬件按 cache hit 情况自动切换，无需软件参与。

现场错误长这样：

text
Data abort with DFSC:
0b110101 implementation defined fault (Unsupported Exclusive or Atomic access).
esr_el3        = 0x0000000096000035

以后看到 DFSC = 0b110101 就能直接定位到这类问题。

原文在这里留了一处口径不一致：正文说「进入同步异常」，而 TODO 里又讨论「为什么 store atomics 会引发异步异常」。这个矛盾原文没解决，引用时别当成定论。

结论的适用范围：问题源自 SOC 内部总线或末端内存的实现，不只 OMAP，很多 ARM 平台都有；但通常 cache 是开着的，所以软件一般不需要关心。

八、速查表 #

概念 一句话
memory consistency model 定义一次 read 应该返回什么值，即允许哪些重排
SC 全序；Dekker + A=B=0 两个例子分别证明保序与全局可见
TSO 只放开 store→load，因为 store buffer 是 FIFO
PSO store buffer 不再 FIFO，store→store 也可乱序
RMO 四种重排全放开，ARM 多数微架构属此类，故 dmb 要带 LD/ST/SY
observer 能发起读写的 master，不等于 core（取指、table walk 各算一个）
observed write 读到该值，或读到 coherence order 中排它之后的值，都算
globally observed 域内所有 observer 都观察到
complete globally observed + 相关 table walk 完成（含 TLB 已更新）
coherence order 同一 byte 上所有写的单一全序
single-copy atomic 一次访问只触发一次 copy；对齐访问满足，LDP/STP 不满足
multi-copy atomic 写对所有 observer 同序 + read 要等所有 observer 看到；normal memory 不要求
write back 主存可能是旧值，新值只在 cache line 里（dirty bit）
non-cacheable 原子 靠 interconnect 支持，不支持就 DFSC = 0b110101

小结 #

  • 多核下「上一次写是谁」无法由 program order 定义，这才需要一致性模型。
  • 任何模型都不能放松两条：单核依赖保序、同地址写串行化。
  • store buffer 造出 TSO，非 FIFO 的 store buffer 造出 PSO，再加上 L1/L2 之间的地址无关性就造出 RMO。
  • observer ≠ core；observed ≠ complete；这两条是读懂 ARM 内存序文档的门槛。
  • single-copy 与 multi-copy atomicity 是两个维度，别对立起来看。
  • 原子操作的可靠性取决于「数据在不在 cache 里」，而非 CPU 本身的算力。
