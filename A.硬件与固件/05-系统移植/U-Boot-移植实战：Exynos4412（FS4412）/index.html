零、移植地图 #

text
第一步  添加单板          复制 origen → fs4412，注册进 boards.cfg
第二步  点亮（点灯法）     确认第一条指令真的跑到了
第三步  串口输出           改 lowlevel_init.S，注释掉 tzpc_init
第四步  网卡 DM9000        配 SROMC 时序 + board_eth_init
第五步  eMMC               初始化时钟/GPIO + movi 命令

每一步都有一个可观测的中间状态：灯亮 → 串口出字 → ping 通 → mmcinfo 出容量。没看到上一级现象，就不要往下走。

一、添加单板 #

u-boot-2013.01 里没有 fs4412，但 board/samsung/origen/ 是同一颗 SoC（Exynos4412），直接派生：

bash
cp -r board/samsung/origen board/samsung/fs4412
mv board/samsung/fs4412/origen.c board/samsung/fs4412/fs4412.c
cp include/configs/origen.h include/configs/fs4412.h

要改的四处：

文件 改什么
board/samsung/fs4412/Makefile origen.o → fs4412.o
include/configs/fs4412.h CONFIG_SYS_PROMPT "ORIGEN #" → "FS4412 # "；CONFIG_IDENT_STRING for ORIGEN → for FS4412
boards.cfg 在 origen 那一行后面加一行
顶层 Makefile 指定 CROSS_COMPILE

boards.cfg 的新行（列的顺序是 Status Arch CPU SoC Vendor Board Target Options）：

text
Active  arm  armv7  exynos  samsung  fs4412  -  -

然后配置编译：

bash
make distclean
make fs4412_config     # 这一步等价于 ./mkconfig fs4412 arm armv7 fs4412 samsung exynos
make -j4

产物：

文件 说明
u-boot.bin 二进制，可直接烧
u-boot ELF，可 objdump
u-boot.srec Motorola S-record
u-boot-fs4412.bin 真正烧的那个，由 build.sh 拼上 BL1/BL2/TZSW 生成

老版配置体系（mkconfig 六参数、boards.cfg 格式）的原理见 U-Boot 编译体系与源码结构 第二节。新版（2014 之后）改成 configs/fs4412_defconfig + Kconfig，操作类似但不再有 boards.cfg。

二、点亮：先确认指令真的跑到了 #

把镜像烧进去、复位、串口没反应——这时候不要猜串口配置，先确认「代码到底有没有执行」。办法是最原始的点灯：

c
/* arch/arm/cpu/armv7/start.S 第 134 行之后插入 */
    ldr r0, =0x11000000      /* GPIO 基址 */
    ldr r1, =0x00220020
    str r1, [r0, #0x120]     /* 配置为输出 */
    ldr r1, =0x00002222
    str r1, [r0, #0x140]     /* 输出高电平，灯亮 */

灯亮 = 第一条指令跑到了，问题在串口。灯不亮 = 镜像没被引导，问题在签名或烧写位置。

这一步还有个前提：Exynos 必须用三星签名后的引导链，所以 build.sh 和 CodeSign4SecureBoot 目录必须先就位（见启动链路那篇）。

三、让串口出字 #

改三个地方，都在 board/samsung/fs4412/lowlevel_init.S：

3.1 加临时栈 #

lowlevel_init: 标号之后立刻补一条设栈指令——此时还没有 C 环境，栈必须手搭：

armasm
lowlevel_init:
    ldr sp, =0x02020000      /* iRAM 里的一块空闲区 */

3.2 关看门狗 #

在 beq wakeup_reset 之后加：

armasm
    ldr r0, =0x10060000      /* WTCON */
    mov r1, #0
    str r1, [r0]

3.3 串口初始化 #

在 uart_asm_init: 里那条 str r1, [r0, #EXYNOS4_GPIO_A1_CON_OFFSET] 之后，补齐管脚复用、时钟源、波特率分频。这一步最容易出错的是时钟源：UART 用的是 PCLK 还是 SCLKMPLL，两者算出来的分频值完全不同。

3.4 注释掉 TrustZone 初始化 #

这是最有名的一坑：

armasm
    bl uart_asm_init
/*  bl tzpc_init */          /* ← 注释掉这一行 */

tzpc_init 会去配 TZPC（TrustZone Protection Controller）寄存器，在非安全启动环境下写这些寄存器会直接卡死，而且不报任何错。串口已经初始化完却一个字都没出来时，八成是它。

改完执行 ./build.sh，烧 u-boot-fs4412.bin，复位后应该看到：

text
U-Boot 2013.01 (Nov 28 2021 - 11:58:20)
CPU:   Exynos4412@1000MHz
Board: FS4412
DRAM:  1 GiB

四、网卡：DM9000 #

Exynos4412 通过 SROMC（Static Memory Controller）外接 DM9000。要配两样东西：SROMC 时序和 GPIO 复用。

4.1 SROMC 时序计算 #

在 board/samsung/fs4412/fs4412.c 里加：

c
#ifdef CONFIG_DRIVER_DM9000
#define EXYNOS4412_SROMC_BASE  0x12570000
#define DM9000_Tacs  (0x1)   /* 0clk address set-up */
#define DM9000_Tcos  (0x1)   /* 4clk chip selection set-up */
#define DM9000_Tacc  (0x5)   /* 14clk access cycle */
#define DM9000_Tcoh  (0x1)   /* 1clk chip selection hold */
#define DM9000_Tah   (0xC)   /* 4clk address holding time */
#define DM9000_Tacp  (0x9)   /* 6clk page mode access cycle */
#define DM9000_PMC   (0x1)   /* normal(1data) page mode */

struct exynos_sromc {
    unsigned int bw;
    unsigned int bc[6];
};

void exynos_config_sromc(u32 srom_bank, u32 srom_bw_conf, u32 srom_bc_conf)
{
    struct exynos_sromc *srom = (struct exynos_sromc *)EXYNOS4412_SROMC_BASE;
    unsigned int tmp;

    /* SMC_BW：设置对应 bank 的总线宽度 */
    tmp = srom->bw;
    tmp &= ~(0xF << (srom_bank * 4));
    tmp |= srom_bw_conf;
    srom->bw = tmp;

    /* SMC_BC：设置对应 bank 的时序 */
    srom->bc[srom_bank] = srom_bc_conf;
}

bc_conf 是按字段拼出来的，每个字段占固定位置：

c
smc_bc_conf = ((DM9000_Tacs << 28)
             | (DM9000_Tcos << 24)
             | (DM9000_Tacc << 16)
             | (DM9000_Tcoh << 12)
             | (DM9000_Tah  <<  8)
             | (DM9000_Tacp <<  4)
             | (DM9000_PMC));

4.2 GPIO 复用 #

DM9000 占用 16 位数据总线 + 若干控制线，要把对应 GPIO 配成功能 2（SROM）：

c
static void dm9000aep_pre_init(void)
{
    unsigned int smc_bw_conf = 0;
    unsigned int smc_bc_conf = 0;
    unsigned char smc_bank_num = 1;

    /* 地址线 / 数据线 / 控制线配置为 SROM 功能 */
    writel(0x00220020, 0x11000000 + 0x120);
    writel(0x00002222, 0x11000000 + 0x140);
    writel(0x22222222, 0x11000000 + 0x180);   /* 数据线 */
    writel(0x0000FFFF, 0x11000000 + 0x188);   /* 上拉 */
    writel(0x22222222, 0x11000000 + 0x1C0);
    writel(0x0000FFFF, 0x11000000 + 0x1C8);
    writel(0x22222222, 0x11000000 + 0x1E0);
    writel(0x0000FFFF, 0x11000000 + 0x1E8);

    /* 16 位总线宽 */
    smc_bw_conf &= ~(0xf << 4);
    smc_bw_conf |= (1 << 7) | (1 << 6) | (1 << 5) | (1 << 4);

    smc_bc_conf = ...;  /* 见上 */
    exynos_config_sromc(smc_bank_num, smc_bw_conf, smc_bc_conf);
}
#endif

然后在 board_init 里调用：

c
#ifdef CONFIG_DRIVER_DM9000
    dm9000aep_pre_init();
#endif

并实现 board_eth_init：

c
int board_eth_init(bd_t *bis)
{
    int rc = 0;
#ifdef CONFIG_DRIVER_DM9000
    rc = dm9000_initialize(bis);
#endif
    return rc;
}

4.3 配置宏 #

include/configs/fs4412.h 里原本是 #undef CONFIG_CMD_PING / #undef CONFIG_CMD_NET（origen 没有网卡），全部打开：

c
#define CONFIG_CMD_PING
#define CONFIG_CMD_NET
#define CONFIG_DRIVER_DM9000
#define CONFIG_DM9000_BASE   0x05000000   /* 片选 bank 的基址 */
#define DM9000_IO            CONFIG_DM9000_BASE
#define DM9000_DATA          (CONFIG_DM9000_BASE + 4)

验证：

text
=> setenv ipaddr 192.168.9.100
=> setenv serverip 192.168.9.120
=> ping 192.168.9.120
dm9000 i/o: 0x5000000, id: 0x90000a46
MAC: 00:40:5c:26:0a:5b
host 192.168.9.120 is alive

看到 id: 0x90000a46 就说明时序和总线宽度都对了——DM9000 的 ID 是固定值 0x90000a46，读不对说明 SROMC 配错。

五、eMMC #

eMMC 在 Exynos4412 上接 MMC4 通道（SD_4_CLK/SD_4_CMD/SD_4_DATA[0:3]，GPK0 管脚）。移植要动三处。

5.1 时钟与 GPIO 初始化 #

c
#ifdef CONFIG_GENERIC_MMC
u32 sclk_mmc4;

int emmc_init(void)
{
    u32 tmp, clock, i;

    /* MMC4 时钟源选 SCLKMPLL */
    tmp = CLK_SRC_FSYS & ~(0x000f0000);
    CLK_SRC_FSYS = tmp | 0x00060000;

    /* 分频到 <= 160MHz */
    tmp = CLK_DIV_FSYS3 & ~(0x0000ff0f);
    clock = get_pll_clk(MPLL) / 1000000;
    for (i = 0; i <= 0xf; i++) {
        sclk_mmc4 = clock / (i + 1);
        if (sclk_mmc4 <= 160) {
            CLK_DIV_FSYS3 = tmp | (i << 0);
            break;
        }
    }
    sclk_mmc4 *= 1000000;

    /* GPK0[0]=CLK, [1]=CMD, [2]=CDn, [3:6]=DATA[0:3] */
    writel(readl(0x11000048) & ~(0xf),   0x11000048);  /* CLK/CMD 下拉使能 */
    writel(readl(0x11000040) & ~(0xff),  0x11000040);  /* CDn 设为输出 */
    writel(readl(0x11000048) & ~(3 << 4),0x11000048);  /* CDn 下拉关闭 */
    writel(readl(0x11000044) & ~(1 << 2),0x11000044);  /* CDn 输出 0，断电 */
    writel(readl(0x11000040) & ~(0xf << 8) | (1 << 8), 0x11000040);
    udelay(100 * 1000);                                 /* 等 100ms */
    writel(readl(0x11000044) | (1 << 2), 0x11000044);   /* CDn 输出 1，上电 */

    writel(0x03333133, 0x11000040);   /* GPK0CON  */
    writel(0x00003FF0, 0x11000048);   /* GPK0PUD  */
    writel(0x00002AAA, 0x1100004C);   /* GPK0DRV  */
#ifdef CONFIG_EMMC_8Bit
    writel(0x04444000, 0x11000060);   /* GPK1CON  */
    writel(0x00003FC0, 0x11000068);
    writel(0x00002AAA, 0x1100006C);
#endif
    return 0;
}
#endif

注意那段「先拉低 CDn 断电 → 延时 100ms → 再拉高上电」的序列。eMMC 的上电复位时序是硬件要求，跳过它有时候能跑、有时候枚举失败，很玄学。

board_mmc_init 改成调它：

c
int board_mmc_init(bd_t *bis)
{
    int err = 0;
#ifdef CONFIG_EMMC
    err = emmc_init();
#endif
    return err;
}

5.4 判断从哪个设备启动 #

同一份 U-Boot 要同时支持 eMMC 和 SD 卡，靠运行时探测：

c
int chk_bootdev(void)
{
    char run_cmd[100];
    struct mmc *mmc;
    int boot_dev = 0;
    ulong start_blk, blkcnt = 0x10;

    mmc = find_mmc_device(0);
    if (mmc == NULL) {
        printf("There is no eMMC card, Booting device is SD card\n");
        return 1;
    }

    start_blk = (24 * 1024 / MOVI_BLKSIZE);
    sprintf(run_cmd, "emmc open 0");
    run_command(run_cmd, 0);
    sprintf(run_cmd, "mmc read 0 %lx %lx %lx", CFG_PHY_KERNEL_BASE, start_blk, blkcnt);
    run_command(run_cmd, 0);
    sprintf(run_cmd, "emmc close 0");
    run_command(run_cmd, 0);
    return 0;
}

6.2 走 NFS 根文件系统 #

开发阶段最省事的方式——内核和根文件系统都不用烧：

bash
# 主机侧
sudo apt-get install nfs-kernel-server
sudo vi /etc/exports
/nfsboot *(rw,sync,no_subtree_check)
sudo /etc/init.d/nfs-kernel-server restart
showmount -e                     # 确认导出成功
cp rootfs.tar.xz /nfsboot && tar xvf rootfs.tar.xz

text
=> setenv bootargs root=/dev/nfs nfsroot=192.168.9.120:/nfsboot/rootfs rw \
         console=ttySAC2,115200 ip=192.168.9.100 init=/linuxrc
=> saveenv

四个参数的语义：

参数 含义
root=/dev/nfs 根文件系统在 NFS 上
nfsroot=<ip>:<dir> 服务器地址与导出目录
ip=<板子ip> 板子的地址（新版内核要求七字段完整格式）
init=/linuxrc 第一个用户进程

NFS 根挂不上的第一检查点：主机 exports 里有没有 no_root_squash。没有的话内核解压完、挂根时就停在 VFS: Unable to mount root fs。详见 根文件系统的移植与调试。

6.3 裁剪 #

FS4412 的板级头文件默认开了很多东西，按需 #if 0 掉：USB、RTC、部分 BOOTP 选项、不用的文件系统。裁剪效果和 S3C2440 一样明显（通常能从 480KB 砍到 250KB 以内），方法见 U-Boot 编译体系与源码结构 第八节。

七、gd_t 与 bd_t：调试时看得懂才有用 #

这两个结构体在 2013.01 里分别定义在：

结构 文件
gd_t arch/arm/include/asm/global_data.h
bd_t arch/arm/include/asm/u-boot.h

关键字段：

c
typedef struct global_data {
    bd_t *bd;                  /* 指向 board info */
    unsigned long flags;
    unsigned int  baudrate;
    unsigned long have_console;
    unsigned long env_addr;
    unsigned long env_valid;   /* 环境变量 CRC 是否有效 */
    unsigned long ram_top;     /* RAM 顶端 */
    unsigned long relocaddr;   /* u-boot 重定位后地址 */
    phys_size_t   ram_size;
    unsigned long mon_len;     /* u-boot 自身长度 */
    unsigned long start_addr_sp;
    unsigned long reloc_off;
    const void   *fdt_blob;
    void        **jt;          /* jump table */
    char env_buf[32];
} gd_t;

typedef struct bd_info {
    unsigned int  bi_baudrate;
    ulong bi_arch_number;      /* 机器码 */
    ulong bi_boot_params;      /* ATAGS 地址 */
    struct { ulong start; ulong size; } bi_dram[CONFIG_NR_DRAM_BANKS];
} bd_t;

gd 指针在 ARM32 上固定在 r8（2013.01 版本；2016.05 之后改成 r9），用 DECLARE_GLOBAL_DATA_PTR 声明后就能直接访问。调试时 bdinfo 命令打出来的就是这个结构体的内容。

八、踩坑速查 #

现象 原因
烧完不启动，串口全无 OM 管脚错 / 没用 build.sh 拼签名链 / movi write uboot 写到了别的副本
灯亮但串口无输出 tzpc_init 没注释 / 串口时钟源算错 / 临时栈没设
串口出乱码 波特率分频算错（PCLK vs SCLKMPLL 搞混）
ping 不通且无 id: 输出 SROMC 时序没配 / GPIO 没配成功能 2
id: 0x00000000 总线宽度错（8 位当 16 位用）或 CS 片选接错 bank
mmcinfo 报 no card CDn 上电序列跳过了 / 时钟超 160MHz / GPK0 复用没配
mmcinfo 显示 1-bit 数据线 GPK0[3:6] 没配，只配了 CLK/CMD
saveenv 失败 eMMC 分区表里没有 env 分区，或 CONFIG_ENV_OFFSET 与该分区冲突
distclean 后编译失败 CodeSign4SecureBoot 被清掉了，重新拷一份

小结 #

  • Exynos4412 的移植顺序是「先能跑 → 再有输出 → 再联网 → 再存储」，每一步都必须看到一个物理现象再往下走，否则错误会层层叠加。
  • 最容易白花时间的三个坑：tzpc_init（串口明明初始化了却不出字）、SROMC 时序（网卡 ID 读成 0）、eMMC 上电序列（mmcinfo 时有时无）。
  • 签名链绕不过去：u-boot.bin 不能直接烧，必须 build.sh 拼成 u-boot-fs4412.bin。
  • gd_t/bd_t 是理解运行期状态的入口，bdinfo 一敲就能看到；调不通时先看 relocaddr 和 ram_size 是否合理。
