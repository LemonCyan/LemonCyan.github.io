一、为什么有多级引导 #

Exynos4412 片内有 64KB ROM 和 256KB SRAM。ROM 里固化的那段代码三星叫 BLO（iROM BOOT code），它做的事只有一件：把启动设备上的一小段代码搬进 SRAM 然后跳过去。为什么不能一步到位？因为完整的 U-Boot 有几百 KB，SRAM 放不下，而 DRAM 还没初始化——初始化 DRAM 的代码本身又必须先跑在 SRAM 里。

于是形成经典的三段：

text
上电
 │
 ├─ iROM（片内 64KB ROM，三星固化，无源码）
 │    1. 读 OM 管脚电平，决定从哪个设备启动
 │       （0110 = eMMC，1000 = SD 卡）
 │    2. 初始化 SRAM
 │    3. 从启动设备拷贝 8KB 到 iRAM 0x02021400 —— 这就是 BL1
 │    4. 校验和解密 BL1，通过后跳过去
 │
 ├─ BL1（三星提供，无源码，已签名）
 │    1. 初始化中断、设置栈
 │    2. 从启动设备拷贝 14KB 到 iRAM 0x02023400 —— 这就是 BL2
 │    3. 跳过去
 │
 ├─ BL2（我们自己编的，等于 U-Boot 的前 14KB 部分）
 │    1. 初始化 DRAM
 │    2. 把完整的 U-Boot 从启动设备搬到 DRAM
 │    3. 跳到 DRAM 里继续跑
 │
 └─ U-Boot 主程序（在 DRAM 里）→ 引导内核

二、iROM 与 OM 管脚 #

iROM 里干的事按顺序：

  1. 关闭看门狗、关闭中断、关闭 MMU、关闭 D-Cache、打开 I-Cache、清 TLB；
  2. 把其他核置为 IDLE，只留 CPU0；
  3. 判断是冷启动还是唤醒（唤醒直接跳 BL1 里的唤醒分支，通常指向内核的唤醒句柄）；
  4. 设置 IRQ 与 SVC 模式的栈，栈就在片内 IRAM 里；
  5. 初始化 iROM 自己使用的变量、只读数据段、清零未初始化数据段；
  6. 导出部分核心函数（给 BL1 用，比如获取复位状态）；
  7. 读 OM 管脚电平，确定启动设备；
  8. 把 BL1 从启动设备读进 iRAM，计算校验和、必要时解密，然后跳转。

OM 管脚（Operating Mode）是板子上几个拨码开关或电阻，上电时被采样：

OM[5:1] 启动设备
0110 eMMC（通道 4）
1000 SD/MMC 卡
其他 NAND、Nor、USB 等

这也是为什么「烧完不启动」时第一步要检查拨码——OM 不对，iROM 根本不去读你烧的地方。

三、BL1：8KB 的硬限制 #

以 SD 卡启动为例，偏移量是死的：

内容 偏移 大小上限 载入位置
保留扇区（分区表） 0 512 字节 —
BL1 512（0x200） 8KB iRAM 0x02021400
BL2 512 + 8K 14KB - 4 字节 iRAM 0x02023400

为什么第一个扇区要留空？因为要和 DOS 分区表共存——很多烧写工具（包括 dd 之后直接用读卡器）会把 SD 卡当普通块设备处理，第一扇区留给分区表是约定俗成的兼容做法。

BL2 的 14KB 里有 最后 4 字节是校验码，所以实际能放代码的是 14K - 4 字节。这个校验码由三星的 mkbl2 工具算出来：

text
mkbl2 的输入：你的 u-boot.bin（截取前 14K-4 字节）
mkbl2 的输出：bl2.bin（14K，末尾 4 字节是校验和）

如果 U-Boot 大于 14KB-4，就只截前面那段做成 BL2，由 BL2 自己去读启动设备上更靠后的完整 U-Boot——这正是 BL2 存在的意义：它不是「缩小版 U-Boot」，而是「引导 U-Boot 的那 14KB」。

四、签名与加密：为什么必须用厂商的 BL1 #

Exynos4412 的 iROM 在跳转前会验证 BL1 的校验和，加密模式下还会解密。这意味着你不能随便写一段代码当 BL1——必须用三星提供的、已签名的 BL1 镜像。

厂商给的 CodeSign4SecureBoot 目录里通常有这么几个文件：

文件 作用
E4412_N.bl1.SCP2G.bin 已签名的 BL1（N 表示普通速度，SCP2G 表示 2GB DRAM 版本）
bl2.bin 用 mkbl2 从你的 u-boot 前 14KB 生成
all00_padding.bin 补齐用的全 0 块
tzsw_SMDK4412_SCP_2GB.bin TrustZone 软件，厂商提供
checksum_bl2_14k.bin Build 过程产物，校验块

最终镜像是一条 cat 拼出来的：

bash
cat E4412_N.bl1.SCP2G.bin bl2.bin all00_padding.bin u-boot.bin \
    tzsw_SMDK4412_SCP_2GB.bin > u-boot-fs4412.bin

顺序就是烧到设备上的物理顺序：BL1 → BL2 → 填充 → 完整 U-Boot → TrustZone。所以 u-boot-fs4412.bin 不是「U-Boot 的镜像」，而是「整条引导链的镜像」，大小远大于 U-Boot 本身。

一个能跑的 build.sh 骨架：

bash
#!/bin/sh
sec_path="CodeSign4SecureBoot/"
CPU_JOB_NUM=$(grep processor /proc/cpuinfo | awk '{field=$NF}; END{print field+1}')
ROOT_DIR=$(pwd)

if [ ! -d $sec_path ]; then
    echo "[ERR] please get the CodeSign4SecureBoot first"
    return
fi

make fs4412_config
make -j$CPU_JOB_NUM

if [ ! -f checksum_bl2_14k.bin ]; then
    echo "[ERR] build failed, run make to check"
    exit 0
fi

cp -rf checksum_bl2_14k.bin $sec_path
cp -rf u-boot.bin $sec_path
rm checksum_bl2_14k.bin

cd $sec_path
cat E4412_N.bl1.SCP2G.bin bl2.bin all00_padding.bin u-boot.bin \
    tzsw_SMDK4412_SCP_2GB.bin > u-boot-fs4412.bin
mv u-boot-fs4412.bin $ROOT_DIR
rm -f bl2.bin u-boot.bin

坑：make distclean 会把 CodeSign4SecureBoot 里的中间文件清掉，之后必须重新拷贝。所以脚本开头那个目录检查不是多余的。

五、烧到 eMMC #

U-Boot 跑起来之后，用 movi 系列命令写 eMMC；或者从主机侧用 fastboot/DNW/SD 卡写入。U-Boot 里最直接的是：

text
=> tftp 41000000 u-boot-fs4412.bin
=> movi write uboot 41000000

movi write uboot 的 uboot 是 eMMC 上的保留分区名，不是文件系统里的路径。eMMC 在 Exynos 平台上被切成几个硬件分区（BL1/BL2/U-Boot/TZSW 各有固定偏移），movi 命令按名字找到对应偏移再写。

六、与 S3C2440 的对比 #

环节 S3C2440（Mini2440） Exynos4412（FS4412）
一级引导 无，NAND 控制器硬件自动搬前 4KB 到 Steppingstone iROM（64KB ROM，软件实现）
一级容量 4KB（片内 SRAM） BL1 8KB
二级 无，4KB 里直接包含搬运代码 BL2 14KB（含 4 字节校验码）
签名 无 必须，iROM 校验/解密 BL1
引导镜像 单个 u-boot.bin cat 拼出来的 u-boot-fs4412.bin
起始地址 0x00000000（映射到 SRAM 或 NOR） BL1 → 0x02021400，BL2 → 0x02023400

这个对比解释了为什么 S3C2440 的移植文档里到处是「前 4KB」的限制，而 Exynos4412 的移植文档里到处是「BL1/BL2/签名」——同样是容量卡死，卡的位置和补救方式完全不同。

七、速查 #

现象 排查
上电完全无反应，串口一个字都没有 OM 管脚不对（iROM 没去读你烧的设备）；或 BL1 签名不对，iROM 校验失败直接停
灯亮但串口无输出 BL2 跑起来了（灯是 BL2 点的），但串口没初始化——去改 lowlevel_init.S 的 uart_asm_init
串口有输出但停在某一行 看停在哪：停在 U-Boot 2013.01 之前说明还在 BL2；之后说明 U-Boot 主程序有问题
checksum_bl2_14k.bin 没生成 编译失败，或者 mkbl2 没跑；单独 make 看完整报错
烧写后启动的是旧版本 eMMC 有多个 U-Boot 副本（A/B 分区），movi write uboot 只更新了一个

小结 #

  • Exynos4412 是 iROM → BL1 → BL2 → U-Boot 四级链，前两级都是厂商固化/签名的，我们只控制 BL2 和 U-Boot。
  • 容量卡死点：BL1 8KB、BL2 14KB-4；所以 BL2 只放「初始化 DRAM + 搬运」这点代码。
  • 镜像必须 cat 拼接：BL1 + BL2 + padding + U-Boot + TZSW，顺序即物理顺序。
  • 签名绕不过去，CodeSign4SecureBoot 是必需品，不是可选优化。
