一、Makefile 的最小知识集 #

1.1 一条规则由五部分组成 #

makefile
target: prerequisites
	command
部分 说明
显式规则 上面这种，最常用
隐式规则 make 内建的「.c → .o」一类推导
变量定义 CC = arm-linux-gcc
文件指示 include、条件判断
注释 # 开头
⚠命令前必须是 **Tab**，不是空格

报 *** missing separator. Stop. 就是这个原因。现代编辑器可能把 Tab 自动转成空格，务必确认。

1.2 四种赋值，别混用 #

写法 求值时机 典型用途
A = x 延时：用到时才展开 可以引用后面才定义的变量
A := x 立即：定义时就展开 最可预测，工程里推荐
A ?= x 若未定义则赋值 给「可从外部传进来」的变量设默认值，如 CROSS_COMPILE ?= arm-linux-
A += x 追加 展开方式随原变量是 = 还是 :=

三者混用最典型的坑：

makefile
A = $(B)
B := hello          # A 展开时 B 已经是 hello，A = hello

C := $(D)           # 此时 D 还没定义，C 变成空
D := world

1.3 自动变量 #

变量 含义
$@ 目标名
$< 第一个依赖
$^ 全部依赖（去重）
$+ 全部依赖（不去重）
$? 比目标新的依赖
$* 模式规则里的 % 匹配部分

内核 Makefile 里满屏的 $@、$(@D)、$< 就是这套东西。$(@D) 是「目标的目录部分」，Buildroot 的包定义里非常常见。

1.4 常用函数 #

函数 作用 例子
$(wildcard) 展开通配 $(wildcard src/*.c)
$(patsubst) 模式替换 $(patsubst %.c,%.o,$(SRC))
$(subst) 字符串替换 $(subst a,b,abc) → bbc
$(foreach) 遍历列表 $(foreach v,$(LIST),$(v).o)
$(filter) / $(filter-out) 保留 / 剔除匹配项 $(filter %.c,$(FILES))
$(if) 条件展开 $(if $(DEBUG),-g,)
$(call) 调用自定义函数 $(call my-func,arg)
$(shell) 执行 shell 取输出 $(shell pwd)
$(origin) 变量来源 见下
$(strip) 去首尾空格并合并中间空白 比较字符串前必用

$(origin X) 的七种返回值，用来判断「这个变量到底从哪来的」：

返回值 含义
undefined 没定义
default make 内建的默认值（如 CC = cc）
environment 从环境变量继承
environment override 环境变量 + 命令行 -e
file 在 Makefile 里定义
command line 命令行传入（make CC=xxx）
override 用 override 强行定义
automatic 自动变量（$@ 等）

1.5 -C 与 -f 的区别 #

选项 换 Makefile 换工作目录 $(CURDIR)
-f file 是 否 不变
-C dir 否 是 变成 dir

内核模块的 $(MAKE) -C $(KDIR) M=$(PWD) modules 就是靠 -C 换目录、靠 M= 指回原目录。

1.6 三个易忽略的语法 #

写法 作用
@command 不回显这条命令
-command 该命令失败也继续（前面加 -）
.PHONY: clean 声明伪目标，避免「目录里正好有个叫 clean 的文件」导致不执行
export VAR 传给子 make
define ... endef 多行命令包
ifeq/ifneq/ifdef/ifndef 条件判断
override VAR := x 覆盖命令行传入的值
target: VAR := x 目标专属变量
✦「`make clean` 说 up to date」十有八九是缺 `.PHONY`

目录里恰好有个叫 clean 的文件或目录时，make 认为目标已存在且无依赖，于是什么也不做。加一行 .PHONY: clean 即可。

1.7 一个可直接用的模板 #

makefile
CC      := arm-linux-gnueabihf-gcc
CFLAGS  := -Wall -O2 -g
LDFLAGS :=

SRC     := $(wildcard src/*.c)
OBJ     := $(patsubst src/%.c,build/%.o,$(SRC))
TARGET  := build/app

.PHONY: all clean

all: $(TARGET)

$(TARGET): $(OBJ)
	@mkdir -p $(dir $@)
	$(CC) $(LDFLAGS) -o $@ $^

build/%.o: src/%.c
	@mkdir -p $(dir $@)
	$(CC) $(CFLAGS) -c -o $@ $<

clean:
	rm -rf build

二、内核模块：从 hello 开始 #

2.1 最小模块 #

c
#include <linux/module.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    printk(KERN_INFO "Hello, world\n");
    return 0;
}

static void __exit hello_exit(void)
{
    printk(KERN_INFO "Goodbye\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("you <you@example.com>");
MODULE_DESCRIPTION("a minimal module");
宏 作用
module_init / module_exit 声明加载/卸载入口。编进内核时 module_init 会被展开成 __initcall，进 initcall 队列
__init / __exit 段标记：__init 的代码在初始化后会被释放；__exit 只对模块有意义
MODULE_LICENSE 必写。不写会在加载时把内核标记为 tainted（污染），很多发行版会因此拒绝加载 
> [!WARNING] `MODULE_LICENSE` 不是「防止警告」的装饰
> 写了 `"GPL"` 才能用 `EXPORT_SYMBOL_GPL` 导出的符号；写 `"Proprietary"` 则不能用。写与不写、写哪一种，直接决定你的模块能否链接成功。

### 2.2 内建（in-tree）三步

**第一步：放源码**。新建 `drivers/hello/`，放 `hello.c`。

**第二步：加 Kconfig**。

drivers/hello/Kconfig #

config HELLO tristate "Hello module support" default m help Say Y here to build hello into the kernel, or M to build it as a module.


**第三步：加 Makefile 并在上层登记**。

drivers/hello/Makefile #

obj-$(CONFIG_HELLO) += hello.o

drivers/Kconfig 里加一行 #

source "drivers/hello/Kconfig"

drivers/Makefile 里加一行 #

obj-$(CONFIG_HELLO) += hello/


然后 `make menuconfig` → `Device Drivers` 下就能看到 `Hello module support`。选 `*` 走 `make uImage`，选 `M` 走 `make modules`。

> [!NOTE] `tristate` 与 `bool` 的区别
> `tristate` 有三态：`< >` 不编、`<*>` 编进内核、`<M>` 编成模块。`bool` 只有两态。选 `tristate` 的项在 menuconfig 里才显示 `M`。

### 2.3 树外（out-of-tree）编译

把 5.2 那份 Makefile 放在模块目录，然后 `make`。产物是 `hello.ko`。

板端测试：

```bash
insmod hello.ko             # 控制台打出 Hello, world
lsmod                       # 能看到 hello 及占用内存
dmesg | tail -n 10          # 看 printk 输出
rmmod hello                 # 注意不带 .ko
⚠`rmmod` 后面不能带 `.ko`

insmod 要带文件名，rmmod 只带模块名。写成 rmmod hello.ko 会报 module hello.ko not found——看起来像「模块没加载」，实际是参数写错。

三、模块 Makefile 的完整解释 #

makefile
ifneq ($(KERNELRELEASE),)
    obj-m := hello.o
else
    KDIR := /lib/modules/$(shell uname -r)/build
    PWD  := $(shell pwd)
all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules
clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean
endif

3.1 为什么会进两次 #

次数 谁进来 KERNELRELEASE 走哪个分支
第 1 次 你敲的 make 未定义 else：递归调用内核 Makefile
第 2 次 内核顶层 Makefile include 你的文件 已定义（如 5.2.8） ifneq：读 obj-m 决定编什么

KERNELRELEASE 由内核顶层 Makefile 里 KERNELRELEASE = $(VERSION).$(PATCHLEVEL).$(SUBLEVEL)... 定义。它是个「身份标记」：有值说明当前是内核在驱动构建，为空说明是用户在驱动。

3.2 KDIR 指向哪 #

写法 适用
/lib/modules/$(shell uname -r)/build 已安装 linux-headers-$(uname -r) 的主机，build 是指向头文件目录的软链
/usr/src/linux-headers-$(uname -r) 同上，直接写实际路径
/home/xxx/linux-3.14 交叉编译：指向完整的内核源码树（不是头文件包）
⚠交叉编译时只给头文件包不够

编 ARM 模块必须用「配好 .config、跑过 make modules_prepare 的完整内核源码树」。只装 linux-headers 的 x86 包会得到 x86 模块，或直接报架构不匹配。

3.3 多文件 #

需求 写法
多文件 → 一个 ko obj-m := helloshow.o + helloshow-y += hello.o show.o
同上，老写法 hello-objs := file1.o file2.o file3.o
多文件 → 多个 ko obj-m := hello.o show.o

命名规则是「ko 名 + -y」，注意 -y 不是 -objs；-objs 是旧版兼容写法。

3.4 交叉编译的正确写法 #

makefile
all:
	$(MAKE) -C $(KDIR) M=$(PWD) ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- modules
clean:
	$(MAKE) -C $(KDIR) M=$(PWD) ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- clean
⚠在命令行敲 `make ARCH=arm ...` 不管用

命令行变量只作用于外层 make。递归进去的那次（-C $(KDIR)）是新进程，除非你把变量显式传进递归命令，或用 export ARCH CROSS_COMPILE。这是「编出来的 .ko 是 x86 的」最常见原因。

四、模块传参 #

c
static int howmany = 1;
static char *whom = "world";

module_param(howmany, int, 0644);
module_param(whom, charp, 0644);
参数位置 含义
第一 变量名，同时也是 sysfs 节点名
第二 类型：byte short ushort int uint long ulong charp bool invbool
第三 sysfs 权限位。不能是 0666（内核不允许所有人可写）；常用 0644

宏展开是 module_param_named(name, name, type, perm)，所以第一个参数同时决定「对外名字」与「变量名」。要两者不同用 module_param_named。

bash
insmod hello.ko howmany=15 whom="aaaaaa"
ls /sys/module/hello/parameters/          # 出现 howmany 与 whom 两个节点
cat /sys/module/hello/parameters/howmany  # 运行期读取
echo 3 > /sys/module/hello/parameters/howmany   # 运行期修改（需 perm 允许写）
类型 特点
bool 接受 0/1、y/n、Y/N
invbool 取反的 bool（写 1 得到 false）
charp 字符指针，insmod 时把字符串拷进内核内存

五、符号导出与跨模块依赖 #

c
/* 模块 B 提供 */
void my_func(void) { ... }
EXPORT_SYMBOL(my_func);           /* 或 EXPORT_SYMBOL_GPL(my_func) */

/* 模块 A 使用 */
extern void my_func(void);

导出后符号写进内核树的 Module.symvers（记录「符号名 + 所属模块 + CRC」）。

⚠树外模块引用别的模块符号，要手动拷 `Module.symvers`

否则加载时报 Unknown symbol my_func (err -2)。把编译 B 时生成的那个 Module.symvers 拷到 A 的源码目录再编 A。另外加载顺序是「先 B 后 A」，卸载顺序反序。

宏 谁能用
EXPORT_SYMBOL 任何许可证的模块
EXPORT_SYMBOL_GPL 只有 MODULE_LICENSE("GPL") 一类兼容许可的模块

六、设备号与字符设备骨架 #

c
#include <linux/fs.h>
dev_t dev;

/* 方式一：静态申请，主设备号 500，次设备号从 0 起 1 个 */
register_chrdev_region(MKDEV(500, 0), 1, "myled");

/* 方式二：动态申请，内核分配 */
alloc_chrdev_region(&dev, 0, 1, "myled");
宏 含义
MAJOR(dev) 高 12 位，主设备号
MINOR(dev) 低 20 位，次设备号（范围 0~1048575）
MKDEV(ma, mi) 拼起来
MINORBITS 20

板端建节点：

bash
cat /proc/devices          # 查已注册的主设备号与名字
mknod /dev/myled c 500 0   # c = 字符设备
ℹ正文里说的「次设备号 0~255」是错的

MINORBITS 是 20，次设备号最大 1048575。0~255 是 u8 的范围，与设备号无关。

七、加载与卸载的完整链路 #

insmod hello.ko
  ├ 内核读 ELF，校验 version magic 与架构
  ├ 定位并重定位符号（依赖 Module.symvers）
  ├ 调用 module_init 注册的函数
  └ 模块状态变为 LIVE

rmmod hello
  ├ 检查引用计数（有人用则失败，报 "in use"）
  ├ 调用 module_exit 注册的函数
  └ 释放内存与符号
命令 作用
insmod 加载指定 .ko
modprobe 按模块名加载，自动处理依赖（需要 depmod 建索引）
lsmod 列出已加载模块与引用计数
rmmod 卸载（只给模块名）
modinfo xxx.ko 看模块元信息（license、author、depends、vermagic）
depmod -a 重建 modules.dep 
> [!TIP] `modprobe` 找不到模块时先跑 `depmod`
> `modprobe: FATAL: Module xxx not found in directory /lib/modules/...` 通常不是文件不在，而是 `modules.dep` 没更新。`make modules_install` 会自动跑 `depmod`，手工拷 `.ko` 进去则要自己跑。

## 八、踩坑速查

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `*** missing separator.  Stop.` | 命令行用了空格而非 Tab | 改 Tab |
| `*** commands commence before first target.  Stop.` | 续行符写成了 `/`，或 `\` 后有空格 | 改成 `\`，且后面紧跟换行 |
| 编出来的 .ko 是 x86 的 | `ARCH`/`CROSS_COMPILE` 没传给递归 make | 写进递归命令行，或 `export` |
| `Unknown symbol xxx (err -2)` | 符号未导出，或 `Module.symvers` 没拷 | 加 `EXPORT_SYMBOL`，拷 symvers |
| `Invalid module format` | `version magic` 与运行内核不符 | `KERDIR` 指向正在跑的那份源码树 |
| `module verification failed: signature and/or required key missing` | 内核开了模块签名 | 签名，或开发期关 `CONFIG_MODULE_SIG_FORCE` |
| `rmmod: module hello.ko not found` | 参数带了 `.ko` | 只写模块名 |
| `Device or resource busy` | 引用计数非 0 | 先关掉打开该设备的进程 |
| menuconfig 里看不到自己的选项 | `Kconfig` 没被上层 source，或 `depends on` 不满足 | 逐级检查 source 链 |
| 选了 `M` 却编进内核 | `obj-$(CONFIG_X)` 写成了 `obj-y` | 改回条件形式 |
