表格Qtxlsx

Qt 应用常常需要导出报表或读取用户数据。CSV 简单实用，但无法包含样式和公式；Excel .xlsx 格式能满足复杂报表展示的需求。

本文介绍如何在 Qt 中使用 QXlsx 库处理 Excel 文件，并说明 CSV 的解析注意事项。

第一部分：核心原理 #

1. XLSX 的本质：XML 的压缩包 #

不同于早期的二进制 .xls (BIFF) 格式，现代 .xlsx (Office Open XML) 实际上是一个 Zip 压缩包。

  • 结构透明：当你把 .xlsx 后缀改为 .zip 并解压，你会看到一堆 XML 文件。
  • 数据分离：
    • xl/worksheets/sheet1.xml：存储具体的单元格数据。
    • xl/sharedStrings.xml：存储共享字符串（优化重复文本的存储）。
    • xl/styles.xml：存储字体、颜色、边框等样式信息。

QXlsx 的工作原理： QXlsx 不依赖 Microsoft Excel，直接操作上述 XML 结构并处理 Zip 包。支持 Windows/Linux/macOS/Android/嵌入式平台，无需启动 Excel 进程。

2. CSV 的本质：RFC 4180 标准 #

CSV (Comma-Separated Values) 看起来简单，但其看似松散的结构往往是生产环境中的陷阱来源。

根据 RFC 4180 标准，标准的 CSV 不仅仅是“逗号分隔”：

  • 编码：虽然 RFC 建议 ASCII，但现代应用通常默认为 UTF-8（带或不带 BOM 经常引发乱码问题）。
  • 转义：如果字段本身包含逗号、换行符或双引号，必须用双引号包围整个字段，且内部的双引号需转义（""）。
  • 无类型：CSV 只有文本。日期 2023-01-01 和数字 0123 在 CSV 中都是字符串，丢失了类型元数据。

第二部分：部署与配置 #

⚠警告

版本选择：GitHub 上星数最多的 dbzhang800/QtXlsxWriter 已多年未更新（最后提交 2014 年前后）。 生产环境请使用活跃分支 QtExcel/QXlsx，当前版本 1.5.0（2024年12月发布）。

1. 依赖管理 #

该库纯 C++ 编写，依赖 Qt Core 和 Qt Gui (如果使用 GUI 模块)。

2. 构建系统集成 #

CMake 集成 #

推荐使用 FetchContent 或 git submodule 集成源码，确保编译一致性。

cmake
# CMakeLists.txt
add_subdirectory(3rdparty/QXlsx) # 假设源码在 3rdparty/QXlsx
target_link_libraries(YourApp PRIVATE QXlsx::QXlsx)

qmake 集成 #

在你的 .pro 文件中：

# 如果作为源码包含
include(3rdparty/QXlsx/QXlsx.pri)

# 确保代码中正确引用
# include "xlsxdocument.h"

如果遇到静态库链接问题，确保定义了 XLSX_NO_LIB 宏，告诉编译器直接编译源码而非寻找动态库。

第三部分：实战场景 #

1. 高性能写入与内存优化 #

处理百万级数据行时，频繁的对象创建和 XML 节点操作是瓶颈。

cpp
#include "xlsxdocument.h"
#include "xlsxformat.h"

void generateReport() {
    QXlsx::Document xlsx;
    
    // 预定义样式，避免循环中重复创建对象
    QXlsx::Format headerFormat;
    headerFormat.setFontBold(true);
    headerFormat.setFontColor(Qt::white);
    headerFormat.setPatternBackgroundColor(QColor("#4472C4"));
    
    // 写入表头
    xlsx.write("A1", "Timestamp", headerFormat);
    xlsx.write("B1", "Value", headerFormat);
    
    // 批量写入数据
    // 注意：尽量按行顺序写入，减少 XML 游标的随机跳转
    for (int row = 2; row <= 10000; ++row) {
        xlsx.write(row, 1, QDateTime::currentDateTime()); // 自动识别为日期格式
        xlsx.write(row, 2, row * 1.5);
    }
    
    // 保存文件
    if (!xlsx.saveAs("Report.xlsx")) {
        qCritical() << "Failed to save report!";
    }
}

2. 公式写入 #

QXlsx 支持写入原生 Excel 公式：

cpp
xlsx.write("C2", "=SUM(A2:B2)"); // 写入公式
xlsx.write("D2", "=AVERAGE(A2:A100)", headerFormat);

3. CSV 解析注意事项 #

虽然 Qt 没有专门的 CSV 解析类（QString::split(',') 是错误的 CSV 解析方式，因为它无法处理带引号的字段），但我们可以遵循 RFC 4180 手动封装或使用轻量级解析器。

错误示范 (Naive Approach):

cpp
// ❌ 无法处理字段中包含逗号的情况： "Doe, John"
QStringList fields = line.split(',');

正确思路: 使用状态机或正则表达式解析 CSV 行，处理双引号转义。对于简单的写操作，确保正确转义：

cpp
QString toCsvField(const QString &text) {
    if (text.contains(',') || text.contains('"') || text.contains('\n')) {
        QString temp = text;
        temp.replace('"', "\"\""); // 转义内部双引号
        return "\"" + temp + "\""; // 包裹双引号
    }
    return text;
}

4. 读取 xlsx 文件 #

读取操作同样简洁，核心 API 为 read() 和 cellAt()。

方法 说明
QXlsx::Document xlsx("file.xlsx") 打开现有文件
xlsx.read(row, col) 读取指定单元格，返回 QVariant
xlsx.currentWorksheet()->dimension() 获取数据范围（如 A1:Z100）

遍历技巧：先通过 dimension() 获取有效区域边界，避免遍历空白单元格浪费性能。若单元格为空，read() 返回无效的 QVariant，需用 isValid() 检查。

5. 合并单元格与冻结窗格 #

操作 API 示例
合并单元格 mergeCells(range, format) xlsx.mergeCells("A1:D1", headerFormat)
取消合并 unmergeCells(range) xlsx.unmergeCells("A1:D1")
冻结首行 通过 Worksheet 对象设置 ws->setFreezePane(1, 0) (行1, 列0)
冻结首列 同上 ws->setFreezePane(0, 1)
冻结行+列 同上 ws->setFreezePane(1, 1) (冻结A1)
ℹ笔记

setFreezePane(row, col) 的参数是冻结线下方/右侧的起始位置。(1, 0) 表示第1行以上被冻结（即首行）。

其他常用格式 API：

  • setColumnWidth(col, width) / setRowHeight(row, height)：调整行列尺寸。
  • Format::setHorizontalAlignment() / setVerticalAlignment()：单元格对齐。
  • Format::setBorderStyle()：设置边框样式。

6. 大文件处理与内存优化策略 #

Qtxlsx 默认将整个文档加载到内存 (DOM 模式)，对于超大文件（>50万行）可能导致内存压力。

优化策略：

场景 建议
写入大文件 分批写入后调用 saveAs()；避免在循环内创建 Format 对象。
读取大文件 Qtxlsx 无原生流式 API。可考虑：① 直接解压 .xlsx 手动解析 sheet*.xml（SAX 方式）；② 使用 libxlsxwriter (C库，支持流式写入)。
仅读取部分数据 先获取 dimension() 判断范围，只遍历必要区域，及时丢弃不需要的数据。
极端优化 对于百万级导出，考虑直接生成 CSV，再由用户用 Excel 打开转换。
❢重要

已知限制：Qtxlsx 不支持 SAX 风格的流式读取。若处理超大文件是核心需求，需评估 libxlsxwriter (写入) 或手动解析 XML 片段 (读取)。

第四部分：方案对比与局限性 #

根据业务场景选择合适的方案：

特性 Qtxlsx (QtExcel/QXlsx) QAxObject (ActiveQt) CSV (Raw Text)
依赖性 仅依赖 Qt 必须安装 MS Office (Windows Only) 无
跨平台 ✅ 全平台 ❌ 仅 Windows ✅ 全平台
读写速度 ⭐⭐⭐ (直接操作 XML) ⭐ (COM Interop 极慢) ⭐⭐⭐⭐⭐ (纯 IO)
内存占用 中 (需构建 DOM 树) 高 (启动 Excel 进程) 低
格式支持 支持样式、公式、图表 支持所有 Excel 功能 ❌ 纯纯文本
适用场景 跨平台报表、无 Office 环境 调用 Excel 宏、复杂特定功能 海量数据备份、系统间数据交换

已知限制 #

  1. 内存消耗：Qtxlsx 采用将整个文档结构加载到内存的模式（Dom-like），对于超大文件（如 100MB+ 的 XLSX），可能会消耗大量 RAM。对于极大数据量的导出，建议分块写入 CSV。
  2. 图表支持有限：虽然支持插入图表，但相比 Excel 及其丰富的图表类型/样式，Qtxlsx 仅支持基础图表，复杂可视化建议截图后作为图片插入。
  3. 加密文件：目前对受密码保护的 Excel 文件支持并不完善。
