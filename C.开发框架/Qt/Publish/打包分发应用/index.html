打包分发应用

把Qt应用交到用户手里，要过几道关：编译方式怎么选，依赖怎么收集，平台怎么配置，安装包怎么做。本文按这个顺序说，Windows、macOS、Linux都涉及。

编译方式选择 #

先决定用静态编译还是动态编译。这不仅仅是技术选择，更关乎你的发布策略——你是想给用户一个清爽的单文件，还是方便维护的文件夹？

静态编译与动态编译对比 #

特性 静态编译 动态编译
可执行文件 单一大文件（50-100MB+） 小文件（几百K） + 一堆DLL（总计差不多）
插件支持 麻烦，得手动导入静态插件 天然支持，丢进去就能用
更新方式 改个标点都得重新编译发布 换个DLL就行
内存占用 独占资源 多个Qt程序跑着能共享内存
部署难度 极简，就一个exe 稍微繁琐，要带一大家子依赖
LGPL合规 坑点：由于链接了Qt库，必须公开你的目标文件或源码 只要不改Qt源码，可以直接闭源商用

怎么选？

  • 内部工具、验证Demo → 静态编译。发给同事测一下，还要人家装环境或者解压，太麻烦。单文件发过去直接跑，爽。
  • 正经商业软件 → 动态编译。除了LGPL的合规考量，你也不希望每次发版用户都要下个几百兆的更新包吧？
  • 开源项目 → 既然都开源了，静态动态其实无所谓。不过动态编译让用户能自己替换Qt库（比如修个底层Bug），更符合开源精神。

应用程序图标与元数据 #

图标是脸面，版本号是身份证。这两样得在编译前就这就埋进去，特别是Windows平台。

设置应用程序图标 #

qmake项目 #

  1. 准备ICO文件 用Photoshop或者ConvertICO这类在线工具把PNG/JPG转成ICO。ICO里放多个尺寸：16×16、32×32、48×48、256×256。

  2. 把ICO文件放项目目录 跟.pro文件放一起。

  3. 改.pro文件

    RC_ICONS = app.ico

  4. 重新编译 跑一遍qmake再编译，exe就带图标了。

CMake项目 #

cmake
# 方法一：用RC文件
# 建个 resources/app.rc，里面写：
# IDI_ICON1 ICON "app.ico"

qt_add_executable(MyApp
    main.cpp
    ${CMAKE_SOURCE_DIR}/resources/app.rc
)

# 方法二：设置Windows应用属性
set_target_properties(MyApp PROPERTIES
    WIN32_EXECUTABLE TRUE
)

Windows版本信息 #

版本信息写在exe资源段里，右键属性能看到。

version.h #

c
#ifndef VERSION_H
#define VERSION_H

#define VER_FILEVERSION             1,0,0,0
#define VER_FILEVERSION_STR         "1.0.0.0"
#define VER_PRODUCTVERSION          1,0,0,0
#define VER_PRODUCTVERSION_STR      "1.0.0"

#define VER_COMPANYNAME_STR         "Your Company"
#define VER_FILEDESCRIPTION_STR     "My Application"
#define VER_INTERNALNAME_STR        "myapp"
#define VER_LEGALCOPYRIGHT_STR      "Copyright (C) 2025"
#define VER_ORIGINALFILENAME_STR    "myapp.exe"
#define VER_PRODUCTNAME_STR         "My Application"

#endif // VERSION_H

version.rc #

#include <windows.h>
#include "version.h"

IDI_ICON1 ICON "app.ico"

VS_VERSION_INFO VERSIONINFO
FILEVERSION     VER_FILEVERSION
PRODUCTVERSION  VER_PRODUCTVERSION
FILEFLAGSMASK   VS_FFI_FILEFLAGSMASK
FILEFLAGS       0
FILEOS          VOS_NT_WINDOWS32
FILETYPE        VFT_APP
FILESUBTYPE     VFT2_UNKNOWN
BEGIN
    BLOCK "StringFileInfo"
    BEGIN
        BLOCK "040904B0"  // 英文(美国), Unicode
        BEGIN
            VALUE "CompanyName",      VER_COMPANYNAME_STR
            VALUE "FileDescription",  VER_FILEDESCRIPTION_STR
            VALUE "FileVersion",      VER_FILEVERSION_STR
            VALUE "InternalName",     VER_INTERNALNAME_STR
            VALUE "LegalCopyright",   VER_LEGALCOPYRIGHT_STR
            VALUE "OriginalFilename", VER_ORIGINALFILENAME_STR
            VALUE "ProductName",      VER_PRODUCTNAME_STR
            VALUE "ProductVersion",   VER_PRODUCTVERSION_STR
        END
    END
    BLOCK "VarFileInfo"
    BEGIN
        VALUE "Translation", 0x0409, 1200  // 英文, Unicode
    END
END

qmake集成 #

VERSION = 1.0.0
QMAKE_TARGET_COMPANY = "Your Company"
QMAKE_TARGET_PRODUCT = "My Application"
QMAKE_TARGET_DESCRIPTION = "Application Description"
QMAKE_TARGET_COPYRIGHT = "Copyright (C) 2025"

RC_ICONS = app.ico
RC_FILE = version.rc

CMake集成（用configure_file） #

cmake
# version.rc.in是模板文件
set(PROJECT_VERSION_MAJOR 1)
set(PROJECT_VERSION_MINOR 0)
set(PROJECT_VERSION_PATCH 0)

configure_file(
    ${CMAKE_SOURCE_DIR}/resources/version.rc.in
    ${CMAKE_BINARY_DIR}/version.rc
    @ONLY
)

qt_add_executable(MyApp
    main.cpp
    ${CMAKE_BINARY_DIR}/version.rc
)

部署工具 #

Qt官方其实提供了“全家桶”式的部署工具，能帮你自动把那些甚至你自己都不知道的依赖库找出来，打包带走。

Windows: windeployqt #

这是Windows下最好用的工具，没有之一。指哪打哪，自动扫描你的exe，把缺的Qt模块一股脑复制过来。

基本用法 #

bash
# 1. 用Release模式编译

# 2. 把exe复制到单独目录
mkdir F:\deploy && copy release\myapp.exe F:\deploy\

# 3. 跑windeployqt
cd F:\deploy
windeployqt myapp.exe

常用参数 #

参数 作用
--release / --debug 指定编译类型
--qmldir <path> QML应用必须加，扫描QML导入
--compiler-runtime 复制MSVC/MinGW运行库
--no-translations 不复制翻译文件，包小点
--no-opengl-sw 不复制软件OpenGL
--no-system-d3d-compiler 不复制D3D编译器
--list <option> 列依赖（source/target/relative/mapping）
--dir <path> 输出目录
--verbose <level> 详细程度（0-2）

实际部署命令 #

bash
# QML应用，全套
windeployqt ^
    --release ^
    --qmldir D:\project\qml ^
    --compiler-runtime ^
    --no-translations ^
    myapp.exe

# Widget应用，精简版
windeployqt ^
    --release ^
    --no-translations ^
    --no-opengl-sw ^
    --no-system-d3d-compiler ^
    myapp.exe

CMake里自动调用 #

cmake
# CMakeLists.txt
if(WIN32)
    find_program(WINDEPLOYQT_EXECUTABLE windeployqt HINTS "${Qt6_DIR}/../../../bin")
    
    add_custom_command(TARGET ${PROJECT_NAME} POST_BUILD
        COMMAND ${WINDEPLOYQT_EXECUTABLE}
            --release
            --no-translations
            $<TARGET_FILE:${PROJECT_NAME}>
        COMMENT "Running windeployqt..."
    )
endif()

CMake部署配置 #

到了Qt 6，CMake脚本里直接能调部署API了。比自己写那堆复杂的copy commands要稳得多。

Qt 6部署API #

cmake
cmake_minimum_required(VERSION 3.21)
project(MyApp VERSION 1.0.0 LANGUAGES CXX)

find_package(Qt6 REQUIRED COMPONENTS Core Widgets)
qt_standard_project_setup()

qt_add_executable(MyApp
    main.cpp
    mainwindow.cpp
)

target_link_libraries(MyApp PRIVATE Qt6::Core Qt6::Widgets)

# 生成部署脚本
qt_generate_deploy_app_script(
    TARGET MyApp
    OUTPUT_SCRIPT deploy_script
    NO_UNSUPPORTED_PLATFORM_ERROR
)

# 安装目标
install(TARGETS MyApp
    BUNDLE DESTINATION .
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}
)

# 执行部署脚本
install(SCRIPT ${deploy_script})

RPATH配置（Linux/macOS） #

让应用能按相对路径找到共享库：

cmake
set_target_properties(MyApp PROPERTIES
    INSTALL_RPATH "$ORIGIN/../lib"
    INSTALL_RPATH_USE_LINK_PATH TRUE
    BUILD_WITH_INSTALL_RPATH TRUE
)

安装包制作 #

DLL找齐了只是第一步，你总不能给用户发个压缩包让他自己解压吧？得做个像样的安装程序。

Qt Installer Framework (IFW) #

Qt官方做的安装程序框架，跨平台，支持在线更新和组件化安装。

目录结构 #

installer/
├── config/
│   └── config.xml          # 全局配置
└── packages/
    └── com.yourcompany.myapp/
        ├── meta/
        │   └── package.xml  # 组件配置
        └── data/
            └── ...          # 应用文件

config.xml #

xml
<?xml version="1.0" encoding="UTF-8"?>
<Installer>
    <Name>My Application</Name>
    <Version>1.0.0</Version>
    <Title>My Application Installer</Title>
    <Publisher>Your Company</Publisher>
    <StartMenuDir>My Application</StartMenuDir>
    <TargetDir>@ApplicationsDir@/MyApp</TargetDir>
    
    <!-- 安装程序图标 -->
    <InstallerWindowIcon>installer_icon</InstallerWindowIcon>
    <InstallerApplicationIcon>installer_icon</InstallerApplicationIcon>
    
    <!-- 维护工具 -->
    <MaintenanceToolName>MaintenanceTool</MaintenanceToolName>
    
    <!-- 在线仓库，可选 -->
    <!-- <RemoteRepositories>
        <Repository>
            <Url>https://your-server.com/repository</Url>
            <Enabled>1</Enabled>
        </Repository>
    </RemoteRepositories> -->
</Installer>

package.xml #

xml
<?xml version="1.0" encoding="UTF-8"?>
<Package>
    <DisplayName>My Application</DisplayName>
    <Description>Core application files</Description>
    <Version>1.0.0</Version>
    <ReleaseDate>2025-01-22</ReleaseDate>
    <Default>true</Default>
    <Script>installscript.qs</Script>
</Package>

生成安装程序 #

bash
# binarycreator在Qt安装目录下
# Windows: Qt\Tools\QtInstallerFramework\4.x\bin\binarycreator.exe
# Linux/macOS: ~/Qt/Tools/QtInstallerFramework/4.x/bin/binarycreator

# 离线安装程序
binarycreator -c config/config.xml -p packages MyAppInstaller

# 在线安装程序
binarycreator -c config/config.xml -p packages -n MyAppOnlineInstaller

Inno Setup（只能用在Windows） #

老牌Windows安装包工具，配置简单。

安装 #

从Inno Setup官网下载装好，打开Inno Setup Compiler，File → New新建脚本。

脚本示例 #

#define MyAppName "My Application"
#define MyAppVersion "1.0.0"
#define MyAppPublisher "Your Company"
#define MyAppURL "https://www.example.com/"
#define MyAppExeName "myapp.exe"

[Setup]
AppId={{XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}
AppName={#MyAppName}
AppVersion={#MyAppVersion}
DefaultDirName={autopf}\{#MyAppName}
OutputDir=.\output
SetupIconFile=app.ico
Compression=lzma
SolidCompression=yes

[Files]
Source: "deploy\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs

[Icons]
Name: "{group}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"
Name: "{commondesktop}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"

IFW和Inno Setup怎么选 #

特性 Qt IFW Inno Setup
跨平台 Windows/macOS/Linux 只有Windows
在线更新 自带 要另找方案
组件化 支持 基本不行
上手难度 中等 容易
安装包大小 大（带框架） 小

常见错误和排查 #

"Could not find Qt platform plugin 'windows'" #

这是新人遇坑率100%的问题。双击exe没有任何反应，或者弹窗报错，十有八九是platforms目录没放对。

解决办法：

  1. 检查目录结构对不对：

    myapp/
├── myapp.exe
└── platforms/
    └── qwindows.dll   # 必须在platforms子目录里

  2. 用windeployqt自动处理：

    bash
    windeployqt myapp.exe

  3. 手动指定插件路径，建个qt.conf：

    ini
    [Paths]
Plugins = .

MinGW运行库缺失 #

用MinGW编译的话，还得复制这几个dll：

从MinGW的bin目录复制：
├── libgcc_s_seh-1.dll 或 libgcc_s_dw2-1.dll（看架构）
├── libstdc++-6.dll
└── libwinpthread-1.dll

OpenGL问题 #

用了OpenGL的应用需要这些文件：

├── libEGL.dll
├── libGLESv2.dll
└── opengl32sw.dll（软件渲染用的）
   或 d3dcompiler_47.dll
✦提示

目标机器有独显的话，一般不需要opengl32sw.dll。加--no-opengl-sw把它排除掉，包能小点。

查依赖的工具 #

工具 平台 说明
Dependencies Windows Dependency Walker的现代替代品
ldd Linux 列动态库依赖
otool -L macOS 列动态库依赖

Windows用Dependencies #

bash
# 去这下载: https://github.com/lucasg/Dependencies/releases
Dependencies.exe myapp.exe
# 打开Dependencies，把你的exe拖进去。看到红色的问号或者感叹号？那就是你要找的“嫌疑犯”。

Linux用ldd #

bash
# 看依赖
ldd ./myapp

# 找缺的库
ldd ./myapp | grep "not found"

调试用的环境变量 #

设了这些变量能看到详细日志：

bash
# Windows (PowerShell)
$env:QT_DEBUG_PLUGINS = 1
$env:QT_PLUGIN_PATH = "C:\path\to\plugins"
./myapp.exe

# Linux/macOS
QT_DEBUG_PLUGINS=1 ./myapp
