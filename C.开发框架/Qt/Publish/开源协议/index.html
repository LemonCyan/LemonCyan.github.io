开源协议

常见开源许可证 #

选择合适的开源协议很重要，它决定了你的代码怎么被使用。最常见的协议有几种，各有各的规则。

开源协议分类 #

开源许可证主要分为两大阵营：

类型 代表协议 核心特征
Copyleft (强传染) GPL v2/v3 衍生作品必须保持相同许可证开源
Weak Copyleft LGPL v2.1/v3 仅库本身保持 Copyleft，链接程序可闭源
Permissive (宽松) MIT, BSD, Apache 2.0 允许闭源商用，仅保留版权声明

LGPL #

LGPL（Lesser General Public License）介于 GPL 和宽松协议之间。如果你用了 LGPL 授权的库，你的主程序可以闭源。前提是用户能够替换这个库的版本，而且库的源代码必须公开。Qt 就是典型的 LGPL 案例。

链接方式对比 #

链接方式 你的代码需开源? 额外义务
动态链接 ❌ 提供协议文本，允许用户替换库
静态链接 ❌ 提供目标文件 + 库源码 + 重链接说明

Mozilla 许可证 #

Mozilla 许可证对代码共享比较宽松。你可以修改和分发代码，即使闭源也没问题。Firefox 就用这个协议。这意味着插件开发者可以保持代码闭源，这是它比 GPL 灵活的地方。

GPL #

GPL 要求如果你用了 GPL 代码，你的整个项目也必须开源。这是强制性的。Linux 内核就是 GPL，所以所有基于 Linux 的发行版都必须公开源代码。用 GPL 代码就要做好开源的准备。

GPLv2 与 GPLv3 主要差异 #

要求 GPLv2 GPLv3
源码公开 ✅ 分发二进制时必须 ✅ 同左
保留许可证文本 ✅ ✅
标注修改内容 ✅ ✅
专利授权 ❌ 无 ✅ 显式授权
反 Tivoization ❌ ✅ 消费设备需提供安装信息
与 Apache 2.0 兼容 ❌ ✅

BSD 许可证 #

BSD 很宽松，几乎没有限制。你可以闭源，可以商用，甚至不用署名（三条款版本除外）。FreeBSD 就是 BSD 协议，很多商业软件直接用了它的代码。企业喜欢 BSD 就是这个原因——省事。

BSD 变体 #

变体 条款数 特殊限制
2-Clause BSD 2 保留版权 + 免责声明
3-Clause BSD 3 + 禁止使用作者名背书

MIT 许可证 #

MIT 是最简单的协议，基本上就是"随便用"。Ruby on Rails、Node.js 都用 MIT。只要保留版权声明，干什么都行。如果你懒得选协议，选 MIT 通常没错。

MIT 合规要求 #

行为 是否允许 额外义务
商业使用 ✅ 无
修改代码 ✅ 无需公开修改
闭源分发 ✅ 保留版权声明和 MIT 协议文本
更换许可证 ✅ 衍生品可用任意协议
专利授权 ❌ 无明确专利条款

Apache 许可证 #

Apache 和 MIT 类似，但多了一些要求，主要是要保留原作者的署名和专利声明。Apache HTTP Server 用这个协议。Apache 2.0 还解决了专利授权的问题，这点比 MIT 强一些。

Apache 2.0 核心优势 #

  • 显式专利授权：贡献者自动授予专利许可
  • 专利报复条款：如果对项目发起专利诉讼，将丧失所有专利权
  • 可闭源商用：允许将代码用于闭源商业产品

实战建议 #

如何选择许可证？ #

场景 推荐许可证 原因
商业闭源产品使用开源库 MIT / BSD / Apache 2.0 无 Copyleft 传染
企业级共享库 Apache 2.0 专利保护 + 专利报复
希望代码保持开源 GPL v3 强 Copyleft
库允许闭源程序链接 LGPL v3 弱 Copyleft
嵌入式设备 避免 GPLv3/LGPLv3 反 Tivoization 条款

如何添加许可证？ #

bash
# 方式一：SPDX 标识符
# SPDX-License-Identifier: MIT

# 方式二：创建 LICENSE 文件
cat > LICENSE << 'EOF'
MIT License

Copyright (c) 2026 Your Name

Permission is hereby granted...
EOF

常见误区 #

❌ 混淆 GPL 与 LGPL #

cpp
// 错误认知：使用 GPL 库只要动态链接就没问题
// 实际：GPL 无论动态还是静态链接，整个程序都必须 GPL

// 正确：确认是 LGPL 而非 GPL
// LGPL 动态链接可免于 Copyleft

❌ 忽略 GPLv2 与 GPLv3 不兼容 #

bash
# Linux 内核是 GPL-2.0-only
# 不能将 GPL-3.0-only 代码合入 Linux
# 除非原代码标注为 GPL-2.0-or-later

❌ Apache 2.0 用于 GPLv2 项目 #

text
Apache 2.0 与 GPLv2 不兼容
Apache 2.0 与 GPLv3 兼容

若项目有 GPLv2 代码，不能引入 Apache 2.0 代码

许可证兼容性 #

graph TD
    subgraph Permissive
        MIT[MIT]
        BSD[BSD 2/3-Clause]
        Apache[Apache 2.0]
    end
    
    subgraph Copyleft
        GPL2[GPL v2]
        GPL3[GPL v3]
        LGPL2[LGPL v2.1]
        LGPL3[LGPL v3]
    end
    
    MIT -->|兼容| GPL2
    MIT -->|兼容| GPL3
    MIT -->|兼容| Apache
    
    BSD -->|兼容| GPL2
    BSD -->|兼容| GPL3
    BSD -->|兼容| Apache
    
    Apache -->|不兼容| GPL2
    Apache -->|兼容| GPL3
    
    LGPL2 -->|兼容| GPL2
    LGPL3 -->|兼容| GPL3
    
    GPL2 -->|不兼容| GPL3

选协议的时候想想：你希望别人怎么用你的代码？想闭源就选 BSD/MIT，想强制开源就选 GPL。想平衡就考虑 LGPL 或 Apache。
