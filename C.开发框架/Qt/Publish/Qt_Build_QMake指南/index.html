Qt_Build_QMake指南

qmake是Qt官方构建工具，负责将.pro工程文件转换为特定平台的Makefile。相比手动编写Makefile，qmake通过声明式语法自动处理头文件依赖、moc预处理、资源编译等Qt特有流程，大幅降低跨平台开发的配置复杂度。

flowchart LR
    A[".pro文件"] --> B["qmake"]
    B --> C["Makefile"]
    C --> D["make/nmake"]
    D --> E["可执行文件/库"]

一、项目描述与创建 #

项目通过.pro文件进行描述，qmake据此生成Makefile。一个典型的项目文件包含：

  • 源文件和头文件列表
  • Qt模块依赖
  • 编译器选项与预处理宏
  • 库链接与路径配置

创建项目文件的三种方式：

方式 适用场景
手动编写.pro文件 精细控制项目配置
Qt Creator新建项目向导 快速创建标准项目结构
qmake -project 从现有源码自动生成

二、.pro文件基础 #

2.1 项目模板 #

通过TEMPLATE变量指定项目类型：

模板 用途 输出产物
app 应用程序（默认） 可执行文件
lib 库项目 静态库/动态库
subdirs 多项目管理 无直接输出
vcapp Visual Studio项目 .vcxproj文件
aux 辅助项目 无编译产物 
makefile
TEMPLATE = app  # 若不指定，默认为app

2.2 核心变量 #

最简.pro文件示例：

makefile
CONFIG  += qt
HEADERS += hello.h
SOURCES += hello.cpp main.cpp
TARGET   = helloworld

常用变量速查表：

变量 说明 示例
HEADERS 头文件列表 *.h
SOURCES 源文件列表 *.cpp
FORMS Qt Designer UI文件 *.ui
RESOURCES 资源文件 *.qrc
DEFINES 预处理宏定义 DEBUG_MODE
INCLUDEPATH 头文件搜索路径 $$PWD/include
LIBS 链接库 -L/path -lname
CONFIG 编译配置选项 c++17 warn_on
QT Qt模块依赖 core gui widgets
TARGET 输出文件名 myapp
DESTDIR 输出目录 bin/

2.3 CONFIG配置选项 #

CONFIG变量控制编译行为，常用选项：

构建类型：

  • debug — 调试版本，包含调试符号
  • release — 发布版本，启用优化
  • debug_and_release — 同时生成两个版本

库类型：

  • staticlib — 生成静态库（.a/.lib）
  • dll — 生成动态库（.so/.dll）
  • plugin — 生成Qt插件

编译选项：

  • c++11 / c++14 / c++17 / c++20 — C++标准版本
  • warn_on — 启用编译器警告
  • warn_off — 禁用警告
  • precompile_header — 启用预编译头文件
  • ordered — 按顺序编译子项目（subdirs模式）
makefile
CONFIG += c++17 warn_on precompile_header
CONFIG -= debug_and_release  # ← 移除选项使用 -=

2.4 Qt模块管理 #

通过QT变量声明模块依赖：

makefile
QT += core gui network sql serialport widgets

# Qt5起widgets从gui分离，需兼容处理
greaterThan(QT_MAJOR_VERSION, 4): QT += widgets

# 控制台程序不需要GUI
QT -= gui

常用Qt模块：

模块 功能
core 核心非GUI功能（默认包含）
gui GUI基础类（默认包含）
widgets 传统桌面控件
network 网络编程
sql 数据库访问
xml XML处理
serialport 串口通信
websockets WebSocket协议
multimedia 音视频处理
quick QML/Qt Quick

三、路径与构建管理 #

3.1 内置路径变量 #

qmake提供多个路径相关变量，理解它们对正确配置项目至关重要：

变量 含义 使用场景
PWD 当前.pro/.pri文件所在目录 引用相对于项目文件的资源
_PRO_FILE_ 主项目文件完整路径 获取项目文件名
_PRO_FILE_PWD_ 主项目文件所在目录 .pri中引用主项目路径
OUT_PWD 构建输出目录（Makefile所在） 引用构建产物

Shadow Build检测：

Qt Creator默认使用影子构建（Shadow Build），将构建产物放在源码目录外。检测方法：

makefile
!equals(_PRO_FILE_PWD_, OUT_PWD) {
    message("当前使用影子构建模式")
    message("源码目录: $$_PRO_FILE_PWD_")
    message("构建目录: $$OUT_PWD")
}

调试路径配置：

makefile
message("PWD           = $$PWD")
message("OUT_PWD       = $$OUT_PWD")
message("_PRO_FILE_    = $$_PRO_FILE_")
message("_PRO_FILE_PWD_= $$_PRO_FILE_PWD_")

3.2 中间文件管理 #

编译过程产生大量中间文件，合理组织可保持项目整洁：

makefile
MOC_DIR     = $$OUT_PWD/temp/moc     # moc生成的元对象代码
RCC_DIR     = $$OUT_PWD/temp/rcc     # rcc资源编译输出
UI_DIR      = $$OUT_PWD/temp/ui      # uic生成的UI头文件
OBJECTS_DIR = $$OUT_PWD/temp/obj     # 编译器目标文件(.o/.obj)

3.3 输出目录配置 #

DESTDIR指定最终产物存放位置：

makefile
# 简单配置
DESTDIR = $$PWD/bin

# 按构建类型分离
CONFIG(debug, debug|release) {
    DESTDIR = $$PWD/bin/debug
} else {
    DESTDIR = $$PWD/bin/release
}

跨平台输出配置示例：

makefile
IDE_BUILD_TREE = $$PWD/../build

win32 {
    CONFIG(debug, debug|release) {
        contains(DEFINES, WIN64): DESTDIR = $$IDE_BUILD_TREE/win64_debug
        else: DESTDIR = $$IDE_BUILD_TREE/win32_debug
    } else {
        contains(DEFINES, WIN64): DESTDIR = $$IDE_BUILD_TREE/win64_release
        else: DESTDIR = $$IDE_BUILD_TREE/win32_release
    }
}

macx {
    CONFIG(debug, debug|release): DESTDIR = $$IDE_BUILD_TREE/mac_debug
    else: DESTDIR = $$IDE_BUILD_TREE/mac_release
}

unix:!macx {
    DESTDIR = $$IDE_BUILD_TREE/linux_$$QT_ARCH
}

四、库文件管理 #

4.1 头文件路径 #

makefile
INCLUDEPATH += $$PWD/include          # 编译器头文件搜索路径
INCLUDEPATH += $$PWD/../third-party/include

DEPENDPATH  += $$PWD/include          # 依赖检查路径（可选）

设计说明：INCLUDEPATH影响编译器-I参数，DEPENDPATH用于qmake分析头文件依赖关系，两者通常设置相同值。

4.2 链接库文件 #

LIBS变量语法遵循Unix链接器约定：

makefile
# -L 指定库搜索路径
# -l 指定库名称（不含lib前缀和扩展名）
LIBS += -L$$PWD/lib -lmylib

# 根据构建类型链接不同版本
CONFIG(debug, debug|release) {
    LIBS += -L$$OUT_PWD/lib -lmylib_d
} else {
    LIBS += -L$$OUT_PWD/lib -lmylib
}

Windows特殊处理：

makefile
win32 {
    # 直接指定.lib文件
    CONFIG(debug, debug|release) {
        LIBS += $$PWD/lib/mylibraryd.lib
    } else {
        LIBS += $$PWD/lib/mylibrary.lib
    }
}

4.3 自动库命名函数 #

定义可复用函数处理Debug/Release库命名差异：

makefile
defineReplace(qtLibraryName) {
    unset(LIBRARY_NAME)
    LIBRARY_NAME = $$1
    CONFIG(debug, debug|release) {
        !debug_and_release|build_pass {
            mac:   RET = $$member(LIBRARY_NAME, 0)_debug
            win32: RET = $$member(LIBRARY_NAME, 0)d
        }
    }
    isEmpty(RET): RET = $$LIBRARY_NAME
    return($$RET)
}

# 使用示例
LIBS += -L$$DESTDIR -l$$qtLibraryName(mycomponent)

4.4 第三方库集成 #

完整的第三方库配置模板：

makefile
# 假设第三方库位于 $$PWD/../vendor/somelib
SOMELIB_ROOT = $$PWD/../vendor/somelib

INCLUDEPATH += $$SOMELIB_ROOT/include
DEPENDPATH  += $$SOMELIB_ROOT/include

win32 {
    CONFIG(debug, debug|release) {
        LIBS += -L$$SOMELIB_ROOT/lib -somelibd
    } else {
        LIBS += -L$$SOMELIB_ROOT/lib -lsomelib
    }
}

unix {
    LIBS += -L$$SOMELIB_ROOT/lib -lsomelib
    # 设置运行时库搜索路径
    QMAKE_RPATHDIR += $$SOMELIB_ROOT/lib
}

五、条件编译 #

qmake提供灵活的条件判断机制，用于处理平台差异和可选功能。

5.1 平台条件 #

条件 匹配平台
win32 Windows（含64位）
macx macOS
unix 所有Unix系统（含macOS和Linux）
linux 仅Linux
android Android
ios iOS 
makefile
win32 {
    DEFINES += PLATFORM_WINDOWS
    LIBS    += -luser32 -lgdi32
}

macx {
    DEFINES  += PLATFORM_MACOS
    LIBS     += -framework Cocoa
    ICON      = resources/app.icns
}

unix:!macx {
    DEFINES += PLATFORM_LINUX
    LIBS    += -lX11
}

复合条件：

makefile
# 非Windows且非macOS（即Linux/BSD等）
!win32:!macx {
    message("Building on Linux/Unix platform")
}

# Windows 64位
win32:contains(QMAKE_TARGET.arch, x86_64) {
    DEFINES += WIN64
}

5.2 架构与编译器判断 #

makefile
# CPU架构
contains(QT_ARCH, arm64) {
    DEFINES += ARCH_ARM64
}
contains(QT_ARCH, x86_64) {
    DEFINES += ARCH_X64
}

# 编译器
*-g++* {
    QMAKE_CXXFLAGS += -Wextra
}
*-msvc* {
    QMAKE_CXXFLAGS += /W4
}

5.3 Qt版本判断 #

makefile
# 版本比较函数
greaterThan(QT_MAJOR_VERSION, 4): QT += widgets
greaterThan(QT_MAJOR_VERSION, 5): QT += core5compat

# 精确版本检查
equals(QT_MAJOR_VERSION, 6) {
    greaterThan(QT_MINOR_VERSION, 4) {
        message("Qt 6.5+ detected")
    }
}

# 版本字符串匹配
contains(QT_VERSION, ^6\\.) {
    DEFINES += QT6_BUILD
}

5.4 自定义条件 #

通过DEFINES定义编译宏：

makefile
DEFINES += ENABLE_FEATURE_X

contains(DEFINES, ENABLE_FEATURE_X) {
    SOURCES += feature_x.cpp
    HEADERS += feature_x.h
}

C++代码中使用：

cpp
#ifdef ENABLE_FEATURE_X
    // 功能X的实现
#endif

通过CONFIG定义构建选项：

makefile
CONFIG += use_opengl

use_opengl {
    QT      += opengl
    DEFINES += RENDER_OPENGL
} else {
    DEFINES += RENDER_SOFTWARE
}

5.5 Debug/Release判断 #

makefile
CONFIG(debug, debug|release) {
    DEFINES += DEBUG_BUILD
    TARGET   = $${TARGET}_d
    LIBS    += -L$$PWD/lib -llogger_d
} else {
    DEFINES += RELEASE_BUILD
    DEFINES += QT_NO_DEBUG_OUTPUT  # 禁用qDebug输出
}

六、多项目管理 #

大型项目通常拆分为多个子模块，使用subdirs模板统一管理。

6.1 项目结构示例 #

MyProject/
├── MyProject.pro          # 主项目文件(subdirs)
├── app/
│   ├── app.pro           # 主程序
│   └── main.cpp
├── core/
│   ├── core.pro          # 核心库(静态)
│   ├── core.h
│   └── core.cpp
└── plugins/
    ├── plugins.pro       # 插件(动态)
    └── myplugin.cpp

6.2 主项目文件 #

makefile
# MyProject.pro
TEMPLATE = subdirs

SUBDIRS += \
    core \
    plugins \
    app

# 定义编译依赖顺序
app.depends     = core plugins
plugins.depends = core

# 或使用ordered保证顺序（效率较低）
# CONFIG += ordered

6.3 静态库子项目 #

makefile
# core/core.pro
QT       -= gui
TARGET    = core
TEMPLATE  = lib
CONFIG   += staticlib c++17

DEFINES += CORE_LIBRARY

HEADERS += core.h core_global.h
SOURCES += core.cpp

导出宏定义（core_global.h）：

cpp
#ifndef CORE_GLOBAL_H
#define CORE_GLOBAL_H

#if defined(CORE_LIBRARY)
#  define CORE_EXPORT Q_DECL_EXPORT
#else
#  define CORE_EXPORT Q_DECL_IMPORT
#endif

#endif

6.4 动态库子项目 #

makefile
# plugins/plugins.pro
QT       -= gui
TARGET    = myplugin
TEMPLATE  = lib
CONFIG   += plugin c++17

DEFINES  += PLUGIN_LIBRARY

HEADERS  += myplugin.h
SOURCES  += myplugin.cpp

# 链接core库
INCLUDEPATH += $$PWD/../core
LIBS        += -L$$OUT_PWD/../core -lcore

6.5 应用程序子项目 #

makefile
# app/app.pro
QT       += core gui widgets
TARGET    = myapp
TEMPLATE  = app
CONFIG   += c++17

SOURCES  += main.cpp mainwindow.cpp
HEADERS  += mainwindow.h
FORMS    += mainwindow.ui

# 链接内部库
INCLUDEPATH += $$PWD/../core
LIBS        += -L$$OUT_PWD/../core -lcore

# 设置运行时库路径（Unix）
unix: QMAKE_RPATHDIR += $$OUT_PWD/../plugins

6.6 常见问题与解决 #

问题 原因 解决方案
链接找不到库 路径配置错误 使用$$OUT_PWD而非$$PWD引用构建产物
Windows导出符号未定义 缺少dllexport 使用Q_DECL_EXPORT/Q_DECL_IMPORT宏
编译顺序错误 依赖未声明 使用.depends明确依赖关系
Debug/Release库混用 命名不一致 统一库命名规则（如debug版加d后缀）

6.7 企业级依赖管理方案 #

当库被多个模块依赖时，硬编码LIBS路径会导致维护困难。Qt Creator采用声明式依赖配置解决此问题：每个模块拥有独立的依赖描述文件，构建时自动解析。

依赖描述文件结构：

makefile
# welcome_dependencies.pri
QTC_PLUGIN_NAME = Welcome         # 模块名称
QTC_LIB_DEPENDS += \              # 依赖的库
    extensionsystem \
    utils
QTC_PLUGIN_DEPENDS += \           # 依赖的插件
    coreplugin

自动依赖解析机制：

makefile
# 递归解析插件依赖（qtcreator.pri核心逻辑）
!isEmpty(QTC_PLUGIN_DEPENDS) {
    LIBS *= -L$$IDE_PLUGIN_PATH
}

done_plugins =
for(ever) {
    isEmpty(QTC_PLUGIN_DEPENDS): break()
    done_plugins += $$QTC_PLUGIN_DEPENDS
    for(dep, QTC_PLUGIN_DEPENDS) {
        dependencies_file =
        for(dir, QTC_PLUGIN_DIRS) {
            exists($$dir/$$dep/$${dep}_dependencies.pri) {
                dependencies_file = $$dir/$$dep/$${dep}_dependencies.pri
                break()
            }
        }
        isEmpty(dependencies_file): error("Plugin dependency $$dep not found")
        include($$dependencies_file)
        LIBS += -l$$qtLibraryName($$QTC_PLUGIN_NAME)
    }
    QTC_PLUGIN_DEPENDS = $$unique(QTC_PLUGIN_DEPENDS)
    QTC_PLUGIN_DEPENDS -= $$unique(done_plugins)  # 去重后继续循环
}

核心思想：通过无限循环逐层解析依赖，每个依赖模块的_dependencies.pri被include后，若声明了新依赖则继续解析，直至所有依赖处理完毕。

库依赖解析同理：

makefile
done_libs =
for(ever) {
    isEmpty(QTC_LIB_DEPENDS): break()
    done_libs += $$QTC_LIB_DEPENDS
    for(dep, QTC_LIB_DEPENDS) {
        include($$PWD/src/libs/$$dep/$${dep}_dependencies.pri)
        LIBS += -l$$qtLibraryName($$QTC_LIB_NAME)
    }
    QTC_LIB_DEPENDS = $$unique(QTC_LIB_DEPENDS)
    QTC_LIB_DEPENDS -= $$unique(done_libs)
}

6.8 Qt Creator工程结构解析 #

Qt Creator源码采用三层架构，是大型Qt项目的经典范例：

qtcreator/
├── src/
│   ├── libs/           # 公共库层（动态库）
│   │   ├── aggregation/
│   │   │   └── aggregation_dependencies.pri
│   │   ├── extensionsystem/
│   │   │   └── extensionsystem_dependencies.pri
│   │   └── utils/
│   ├── plugins/        # 插件层（动态库+插件接口）
│   │   ├── coreplugin/
│   │   │   └── coreplugin_dependencies.pri
│   │   ├── welcome/
│   │   └── bookmarks/
│   └── app/            # 应用层（主程序入口）
│       └── main.cpp
└── qtcreator.pro       # 顶层subdirs工程

依赖配置示例：

makefile
# extensionsystem_dependencies.pri
QTC_LIB_NAME = ExtensionSystem
QTC_LIB_DEPENDS += aggregation utils

# coreplugin_dependencies.pri
QTC_PLUGIN_NAME = Core
QTC_LIB_DEPENDS += aggregation extensionsystem utils

# bookmarks_dependencies.pri
QTC_PLUGIN_NAME = Bookmarks
QTC_LIB_DEPENDS += extensionsystem utils
QTC_PLUGIN_DEPENDS += projectexplorer coreplugin texteditor

最佳实践总结：

原则 说明
声明式依赖 每个模块通过_dependencies.pri声明依赖，无需手动编写LIBS
自动递归解析 构建系统自动处理传递依赖，新增模块只需创建描述文件
命名约定 统一文件命名（模块名_dependencies.pri）确保自动发现
分层架构 libs（基础库）→ plugins（功能插件）→ app（入口）清晰分层

七、预编译头文件 #

预编译头文件（PCH）将稳定的头文件预先编译为二进制格式，显著缩短大型项目的编译时间。

7.1 启用配置 #

makefile
CONFIG             += precompile_header
PRECOMPILED_HEADER  = $$PWD/stable.h

7.2 预编译头文件模板 #

stable.h示例：

cpp
#ifndef STABLE_H
#define STABLE_H

// ===== C标准库 =====
#include <cmath>
#include <cstdlib>
#include <ctime>

// ===== C++标准库 =====
#ifdef __cplusplus
#include <algorithm>
#include <memory>
#include <string>
#include <vector>
#include <map>
#include <functional>

// ===== Qt核心模块 =====
#include <QtCore>
#include <QtGui>

#if QT_VERSION >= QT_VERSION_CHECK(5, 0, 0)
#include <QtWidgets>
#endif

// ===== 项目全局宏 =====

// MSVC UTF-8支持
#ifdef _MSC_VER
#if _MSC_VER >= 1600
#pragma execution_character_set("utf-8")
#endif
#endif

// 调试日志宏
#ifdef QT_DEBUG
#define LOG_DEBUG(msg) qDebug() << "[DEBUG]" << __FILE__ << __LINE__ << msg
#else
#define LOG_DEBUG(msg) qt_noop()
#endif

#endif // __cplusplus
#endif // STABLE_H

性能建议：仅将真正稳定且频繁使用的头文件放入PCH。每次修改PCH会触发完全重编译。

八、完整工程模板 #

以下模板整合了生产环境常用配置：

makefile
#-------------------------------------------------
# 项目基本信息
#-------------------------------------------------
QT       += core gui network sql widgets
greaterThan(QT_MAJOR_VERSION, 4): QT += widgets

TEMPLATE  = app
TARGET    = MyApplication
VERSION   = 1.0.0

#-------------------------------------------------
# 编译选项
#-------------------------------------------------
CONFIG   += c++17 warn_on precompile_header
CONFIG   -= debug_and_release

DEFINES  += QT_DEPRECATED_WARNINGS
DEFINES  += APP_VERSION=\\\"$$VERSION\\\"

# 预编译头文件
PRECOMPILED_HEADER = $$PWD/stable.h

#-------------------------------------------------
# 中间文件目录
#-------------------------------------------------
MOC_DIR     = $$OUT_PWD/generated/moc
RCC_DIR     = $$OUT_PWD/generated/rcc
UI_DIR      = $$OUT_PWD/generated/ui
OBJECTS_DIR = $$OUT_PWD/generated/obj

#-------------------------------------------------
# 输出目录
#-------------------------------------------------
CONFIG(debug, debug|release) {
    DESTDIR  = $$PWD/bin/debug
    TARGET   = $${TARGET}_d
} else {
    DESTDIR  = $$PWD/bin/release
}

#-------------------------------------------------
# 平台特定配置
#-------------------------------------------------
win32 {
    RC_ICONS = resources/app.ico
    QMAKE_CXXFLAGS_WARN_ON += -wd4819
    QMAKE_CXXFLAGS += /FS
    DEFINES += _CRT_SECURE_NO_WARNINGS WIN32_LEAN_AND_MEAN
}

macx {
    ICON = resources/app.icns
    QMAKE_MACOSX_DEPLOYMENT_TARGET = 10.14
}

unix:!macx {
    QMAKE_CXXFLAGS += -Wextra -Wpedantic
}

#-------------------------------------------------
# 源文件
#-------------------------------------------------
HEADERS += \
    stable.h \
    mainwindow.h

SOURCES += \
    main.cpp \
    mainwindow.cpp

FORMS += \
    mainwindow.ui

RESOURCES += \
    resources.qrc

message("构建目录:  $$OUT_PWD")
message("输出目录:  $$DESTDIR")
message("==============================")

9.2 条件包含 #

makefile
# 存在则包含配置文件
exists($$PWD/local.pri) {
    include($$PWD/local.pri)
}

# 包含共享配置
include($$PWD/../common.pri)

9.3 构建时间戳 #

makefile
# 编译时注入构建时间
win32: BUILD_TIME = $$system(echo %DATE% %TIME%)
else:  BUILD_TIME = $$system(date "+%Y-%m-%d %H:%M:%S")

DEFINES += BUILD_TIMESTAMP=\\\"$$BUILD_TIME\\\"

9.4 自定义构建步骤 #

makefile
# 编译前执行
QMAKE_PRE_LINK += echo "开始编译..."

# 编译后执行
QMAKE_POST_LINK += $$QMAKE_COPY $$OUT_PWD/config.ini $$DESTDIR

# 自定义目标
docs.commands = doxygen $$PWD/Doxyfile
QMAKE_EXTRA_TARGETS += docs

9.5 变量操作 #

makefile
# 追加值
SOURCES += newfile.cpp

# 移除值
SOURCES -= oldfile.cpp

# 唯一追加（避免重复）
LIBS *= -lmylib

# 替换值
SOURCES ~= s/old/new/g

# 获取绝对路径
ABSOLUTE_PATH = $$absolute_path(../lib)

十一、小结 #

qmake通过声明式的.pro语法实现跨平台构建管理。掌握以下核心知识点即可应对绝大多数项目需求：

领域 关键点
基础配置 TEMPLATE、QT、CONFIG、HEADERS、SOURCES
路径管理 PWD、OUT_PWD、DESTDIR、临时文件目录
库管理 INCLUDEPATH、LIBS、-L与-l语法
条件编译 平台判断、版本判断、CONFIG/DEFINES条件
多项目 subdirs模板、.depends依赖、静态库/动态库配置
优化技巧 预编译头文件、自定义函数、构建后处理

发展趋势：Qt 6起官方推荐使用CMake作为构建系统，但qmake仍是Qt 5项目的主流选择，且在简单项目中配置更简洁。新项目可考虑采用CMake以获得更好的IDE集成和现代C++支持。
