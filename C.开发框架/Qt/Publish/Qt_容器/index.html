Qt_容器

Qt 容器与 QVariant 完全指南 #

Qt 容器类相比 STL 容器更轻量、更安全，具备隐式数据共享、平台无关性和线程安全特性。本文从容器类型、迭代器到 QVariant 类型系统，提供完整的技术参考。

一、Qt 容器概述 #

1.1 核心特性 #

Qt 容器与 STL 容器的主要区别：

特性 Qt 容器 STL 容器
隐式数据共享 支持（写时复制） 不支持
平台一致性 所有平台行为一致 可能依赖编译器实现
线程安全 只读操作线程安全 需手动同步
内存效率 针对常见场景优化 通用实现

隐式数据共享（写时复制）： 容器作为参数传递时仅复制指针，实际数据在修改时才复制。这消除了传值的性能顾虑。

1.2 顺序容器 #

flowchart LR
    subgraph 顺序容器
        A[QList] --> B[数组实现<br/>快速追加]
        C[QVector] --> D[连续内存<br/>随机访问]
        E[QLinkedList] --> F[链表实现<br/>快速插入删除]
        G[QStack] --> H[LIFO 后进先出]
        I[QQueue] --> J[FIFO 先进先出]
    end
容器 底层实现 适用场景 性能特点
QList<T> 指针数组 通用列表、末尾追加 头尾追加 O(1)，中间插入 O(n)
QVector<T> 连续数组 随机访问、数值计算 随机访问 O(1)，插入 O(n)
QLinkedList<T> 双向链表 频繁中间插入删除 插入删除 O(1)，访问 O(n)
QStack<T> 继承自 QVector 撤销/重做、递归模拟 push/pop O(1)
QQueue<T> 继承自 QList 任务队列、消息缓冲 enqueue/dequeue O(1)

【补充】Qt 5.15+ 建议： QList 在 Qt 6 中成为 QVector 的别名，两者统一为连续内存存储。新项目可直接使用 QList。

1.3 关联容器 #

容器 底层实现 键要求 适用场景
QMap<K, V> 红黑树 提供 operator<() 有序遍历、范围查询
QHash<K, V> 哈希表 提供 operator==() 和 qHash() 快速查找、顺序无关
QMultiMap<K, V> 红黑树 同 QMap 一键多值、有序存储
QMultiHash<K, V> 哈希表 同 QHash 一键多值、快速查找
QSet<T> 哈希表 提供 operator==() 和 qHash() 唯一元素集合

性能对比：

操作 QMap QHash
查找 O(log n) O(1) 平均
插入 O(log n) O(1) 平均
有序遍历 支持 不支持

选择原则： 需要有序遍历或范围查询时选 QMap，否则优先选 QHash 以获得更快的查找速度。

1.4 容器嵌套 #

Qt 容器支持任意层级嵌套：

cpp
QHash<QString, QList<double>> dataMap; // 键为字符串，值为浮点数列表

【修正】C++11 兼容性： C++11 及以后标准已支持 >> 连续书写，无需在模板参数间插入空格。Qt 5+ 项目可直接使用 QList<QList<int>> 语法。

二、容器迭代器 #

Qt 提供两种迭代器风格，各有适用场景。

2.1 STL 风格迭代器 #

STL 风格迭代器自 Qt 2.0 引入，与标准库接口兼容，性能最优。

迭代器类型层次：

迭代器类型 能力 代表容器
输入迭代器 只读、单向 流式数据
输出迭代器 只写、单向 输出流
前向迭代器 读写、单向、可多次遍历 QLinkedList
双向迭代器 读写、双向移动 QMap, QHash
随机访问迭代器 读写、任意跳转 QList, QVector

遍历与修改示例：

cpp
QVector<int> vec = {1, 2, 3, 4, 5};
for (QVector<int>::iterator it = vec.begin(); it != vec.end(); ++it) {
    *it *= 2; // ← 直接修改元素
}
// vec = {2, 4, 6, 8, 10}

只读遍历（推荐）：

cpp
const QMap<QString, int>& map = getDataMap();
for (QMap<QString, int>::const_iterator it = map.constBegin(); 
     it != map.constEnd(); ++it) {
    qDebug() << it.key() << ":" << it.value();
}

2.2 Java 风格迭代器 #

Java 风格迭代器自 Qt 4 引入，API 更简洁，但效率略低于 STL 风格。

设计特点： 迭代器位于元素之间，而非指向元素本身。

flowchart LR
    A["| A | B | C | D |"]
    B["↑"] --> C["迭代器位置"]
    style A fill:#f9f9f9

常用类型：

Java 风格 对应容器 可变版本
QListIterator<T> QList QMutableListIterator<T>
QMapIterator<K,V> QMap QMutableMapIterator<K,V>
QHashIterator<K,V> QHash QMutableHashIterator<K,V>

示例：遍历 QList

cpp
QList<QString> list = {"Apple", "Banana", "Cherry"};
QListIterator<QString> it(list);
while (it.hasNext()) {
    qDebug() << it.next(); // next() 返回当前元素并前进
}

2.3 范围 for 循环与 foreach #

C++11 范围 for（推荐）：

cpp
QStringList list = {"A", "B", "C"};
for (const QString& str : list) {
    qDebug() << str;
}

Qt foreach 宏：

cpp
foreach (const QString& str, list) {
    qDebug() << str;
}

【补充】Qt 5.7+ 建议： 优先使用 C++11 范围 for 循环，foreach 宏在 Qt 6 中已标记为废弃。范围 for 性能更优且语法标准化。

三、迭代器最佳实践 #

3.1 迭代方式选择 #

需求 推荐方式 优点 缺点
简洁只读遍历 范围 for 语法简洁、性能好 无法修改元素
高效读写操作 STL 迭代器 最高效、兼容 STL 算法 语法略复杂
边遍历边删除 STL 迭代器 + erase 安全删除 需手动管理迭代器
API 简洁优先 Java 迭代器 易于理解 效率较低

3.2 遍历时删除元素 #

错误示例（迭代器失效）：

cpp
// ❌ 删除后迭代器失效，导致未定义行为
for (auto it = map.begin(); it != map.end(); ++it) {
    if (it.value() == "remove") {
        map.remove(it.key()); // ← it 已失效
    }
}

正确方案一：使用 erase 返回值

cpp
// ✓ erase 返回下一个有效迭代器
for (auto it = map.begin(); it != map.end(); ) {
    if (it.value() == "remove") {
        it = map.erase(it); // ← 获取新的有效迭代器
    } else {
        ++it;
    }
}

正确方案二：收集后删除

cpp
// ✓ 先收集待删除的键，再统一删除
QStringList keysToRemove;
for (auto it = map.begin(); it != map.end(); ++it) {
    if (it.value() == "remove") {
        keysToRemove << it.key();
    }
}
for (const QString& key : keysToRemove) {
    map.remove(key);
}

3.3 迭代器失效规则 #

操作 QList/QVector QMap/QHash QLinkedList
插入 所有迭代器失效 其他迭代器有效 其他迭代器有效
删除 被删及之后失效 仅被删元素失效 仅被删元素失效
排序 所有迭代器失效 N/A 所有迭代器失效

安全原则： 修改容器后，假设所有现有迭代器均已失效，重新获取迭代器。

四、QVariant 类型系统 #

QVariant 是 Qt 的通用类型容器，可存储任意 Qt 支持的类型，广泛用于属性系统、数据库操作和信号槽参数传递。

4.1 设计动机 #

C++ union 禁止包含具有非默认构造函数或析构函数的类型。若没有 QVariant，以下场景将难以实现：

  • QObject::property() 属性系统
  • 数据库字段值存取
  • 信号槽跨类型参数传递

4.2 基本使用 #

存储与转换：

cpp
QVariant v(123);              // 存储 int
int x = v.toInt();            // x = 123

v = QVariant("hello");        // 存储 QByteArray
v = QVariant(tr("hello"));    // 存储 QString

int y = v.toInt();            // y = 0（无法转换返回默认值）
QString s = v.toString();     // s = "hello"

类型检查与转换：

cpp
QVariant v = 42;

if (v.canConvert<QString>()) {
    QString str = v.toString(); // "42"
}

qDebug() << v.typeName();      // 输出 "int"

4.3 复杂数据结构 #

QVariant 支持嵌套容器，可构建任意复杂的数据结构：

cpp
QVariantMap person;
person["name"] = "Alice";
person["age"] = 30;
person["scores"] = QVariantList{95, 87, 92};

// 等价于 JSON: {"name": "Alice", "age": 30, "scores": [95, 87, 92]}

性能权衡： 嵌套 QVariant 结构灵活强大，但比强类型容器消耗更多内存，类型检查也在运行时进行。

4.4 null 值语义 #

QVariant 支持 null 值，表示"有类型但无值"的状态：

cpp
QVariant x;                    // 无类型无值
QVariant y(QString());         // QString 类型，null 值
QVariant z(QString(""));       // QString 类型，空字符串（非 null）

qDebug() << x.isNull();        // true
qDebug() << y.isNull();        // true
qDebug() << z.isNull();        // false

五、QVariant 与 GUI 类型 #

5.1 类型转换限制 #

QVariant 属于 Qt Core 模块，不直接提供 Qt GUI 类型（如 QColor、QImage、QPixmap）的转换函数。

获取 GUI 类型值：

cpp
QVariant variant = ...;
QColor color = variant.value<QColor>();  // 使用模板函数
// 或
QColor color = qvariant_cast<QColor>(variant);

存储 GUI 类型值：

cpp
QColor color = palette().background().color();
QVariant variant = color;  // ← 自动转换，无需显式构造

5.2 canConvert 与 convert 的陷阱 #

canConvert() 报告的是类型转换的潜在能力，而非当前数据是否可成功转换。

cpp
QVariant v = "hello";

qDebug() << v.canConvert<int>();  // true（字符串原则上可转为整数）
qDebug() << v.toInt();            // 0（实际转换失败）

v = "42";
qDebug() << v.toInt();            // 42（数字字符串转换成功）

安全转换模式：

cpp
bool ok;
int value = variant.toInt(&ok);
if (ok) {
    // 转换成功，使用 value
} else {
    // 转换失败，处理错误
}

六、容器选择速查表 #

根据使用场景快速选择合适的容器：

场景 推荐容器 理由
通用列表、末尾追加 QList Qt 6 统一实现，性能均衡
数值计算、随机访问 QVector 连续内存，缓存友好
频繁中间插入删除 QLinkedList O(1) 插入删除
键值查找（有序） QMap 支持范围查询、有序遍历
键值查找（无序） QHash O(1) 平均查找
唯一元素集合 QSet O(1) 查找、去重
LIFO 栈操作 QStack push/pop 语义明确
FIFO 队列操作 QQueue enqueue/dequeue 语义明确
动态类型存储 QVariant 通用类型容器
