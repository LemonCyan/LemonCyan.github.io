Qt图形视图框架详解

Qt 图形视图框架（Graphics View Framework）提供了一个强大的平台，用于管理和交互大量的定制 2D 图形项，以及一个可视化这些项的视图部件（View widget）。它不仅是传统的 QCanvas 模块的替代品，更是一个功能完备的交互式绘图引擎。

1. 核心架构 (MVC) #

Graphics View 框架采用了基于图元（Item-based）的方法，而非基于像素（Pixel-based）。通过使用 BSP（Binary Space Partitioning，二元空间分割） 树技术，它能够快速查找图元，从而实时渲染包含数百万个图元的场景。

其架构遵循改进的 MVC（Model-View-Controller） 模式：

graph TD
    User((User/Event)) -->|Input| View[QGraphicsView (View)]
    View -->|Transforms| Scene[QGraphicsScene (Model)]
    Scene -->|Dispatches| Item[QGraphicsItem (Item)]
    Item -->|Updates| Scene
    Scene -->|Notifies| View

1.1 场景 (QGraphicsScene) - Model #

QGraphicsScene 是图形项的容器，扮演模型（Model）的角色。它本身是不可见的，主要负责：

  • 图元管理：维护所有图元的位置和状态。
  • 事件传播：将来自视图的事件传递给对应的图元。
  • 图元查找：提供高效的接口（如 items()）来检测碰撞或查找特定区域内的图元。
  • 渲染管理：虽然不直接显示，但提供 render() 函数将场景内容绘制到 QImage 或 QPrinter。

1.2 视图 (QGraphicsView) - View #

QGraphicsView 是观察场景的窗口，扮演视图（View）的角色。它是 QWidget 的子类，负责：

  • 可视化：显示场景的可视区域，支持滚动条。
  • 交互接口：接收键盘、鼠标输入，并转换为场景事件。
  • 坐标变换：支持仿射变换（缩放、旋转），实现视图的缩放和平移，而不改变底层数据。
  • 渲染加速：通过设置视口（Viewport），可以利用 OpenGL (QOpenGLWidget) 进行硬件加速渲染。

1.3 图元 (QGraphicsItem) - Element #

QGraphicsItem 是场景中的基本图形单位。它不仅包含几何信息，还包含逻辑状态：

  • 几何形状：定义自身的边界矩形 (boundingRect()) 和精确形状 (shape())。
  • 交互处理：处理点击、拖拽、键盘焦点等事件。
  • 层级关系：支持父子嵌套，子图元跟随父图元变换。
  • 绘图实现：通过重写 paint() 函数绘制自身内容。

2. 三大坐标系统 #

理解坐标系统是掌握 Graphics View 的关键。框架中存在三个独立的坐标系：图元坐标、场景坐标和视图坐标。

graph LR
    Item[图元坐标 (Item)] <-->|mapToScene / mapFromScene| Scene[场景坐标 (Scene)]
    Scene <-->|mapFromScene / mapToScene| View[视图坐标 (View)]
    Item .->|mapToParent| Parent[父图元坐标]

2.1 图元坐标 (Item Coordinates) #

  • 基准：以图元自身的原点 (0, 0) 为中心。
  • 特性：这是图元的局部坐标系。无论图元如何在场景中移动、旋转或缩放，其内部绘图逻辑（如 paint()）始终基于此坐标系。
  • 应用：boundingRect() 和 shape() 的返回值必须基于此坐标系。

2.2 场景坐标 (Scene Coordinates) #

  • 基准：场景的原点 (0, 0)。
  • 特性：这是所有图元共享的逻辑世界坐标系。
  • 应用：scenePos() 用于获取图元在场景中的绝对位置。场景的事件处理通常基于此坐标。

2.3 视图坐标 (View Coordinates) #

  • 基准：视图窗口（Widget）的左上角。
  • 特性：单位是像素，直接对应屏幕上的物理点。
  • 应用：鼠标事件（QMouseEvent）最初提供的就是视图坐标。

2.4 坐标转换常用 API #

在处理交互时，经常需要在不同坐标系间转换：

转换方向 API 示例
视图 → 场景 view->mapToScene(point) 将鼠标点击位置转换为逻辑坐标
场景 → 图元 item->mapFromScene(point) 判断点击点是否落在图元内部
图元 → 场景 item->mapToScene(point) 获取图元的绝对位置
子 → 父 item->mapToParent(point) 获取子图元在父图元中的位置

注意：在 mousePressEvent 中，务必区分 event->pos() (图元局部坐标) 和 event->scenePos() (场景坐标)。

3. 核心特性与机制 #

3.1 变换 (Transformations) #

Graphics View 支持通过矩阵进行仿射变换。

  • 视图变换：view->scale(2, 2) (放大) 或 view->rotate(45) (旋转)。这只改变观察角度，不修改图元数据。
  • 图元变换：item->setRotation(45) 或 item->setScale(0.5)。这会改变图元在场景中的呈现，并影响其子图元。

3.2 图元分组 (Grouping) #

  • 父子层级：将一个图元设置为另一个的子项 (child->setParentItem(parent))。子项的坐标和变换相对于父项。
  • QGraphicsItemGroup：将多个图元打包成一个独立的逻辑单元，统一处理选择和移动事件。

3.3 碰撞检测 (Collision Detection) #

框架提供两级碰撞检测机制：

  1. 粗略检测：基于 boundingRect()，快速排除不相交的图元。
  2. 精确检测：基于 shape()，通过 QPainterPath 进行像素级精确判断。
  • API：scene->collidingItems(item) 或 item->collidesWithItem(other)。

3.4 动画 (Animation) #

  • QPropertyAnimation：最推荐的方式。图元继承自 QGraphicsObject 后，可以直接对 pos、rotation 等属性应用 Qt 属性动画。
  • Advance 接口：重写 scene->advance() 和图元的 advance(int phase)，适用于帧同步的游戏逻辑。

4. 事件处理与交互 #

Graphics View 拥有完善的事件分发机制。事件首先由 View 接收，转换为 Scene 事件，最后分发给 Item。

4.1 鼠标事件 #

图元默认接收鼠标点击。要处理悬停或拖拽，需显式开启：

cpp
setAcceptHoverEvents(true); // 开启悬停事件 hoverEnterEvent/hoverLeaveEvent
setFlag(ItemIsMovable);     // 开启内置的拖拽移动
setFlag(ItemIsSelectable);  // 开启选中状态支持

4.2 拖放 (Drag & Drop) #

支持标准的 Qt 拖放机制：

  1. 在图元中调用 setAcceptDrops(true)。
  2. 重写 dragEnterEvent、dragLeaveEvent 和 dropEvent。 这使得图元可以作为拖放操作的接收者，处理来自外部或其他图元的数据。

5. 性能优化策略 #

在处理成千上万个图元时，性能是首要考虑因素。

5.1 精确的边界 (Bounding Rect) #

boundingRect() 的效率对性能影响极大。

  • 原则：必须涵盖图元绘制的所有像素（包括画笔宽度的一半），但不能过大。
  • 缓存：如果形状固定，应缓存边界矩形，避免在每次调用时重复计算。

5.2 细节层次 (LOD - Level of Detail) #

在渲染时，根据当前的缩放级别动态调整绘制复杂度。

cpp
void MyItem::paint(QPainter *painter, const QStyleOptionGraphicsItem *option, QWidget *) {
    // levelOfDetailFromTransform 将变换矩阵转换为单一的缩放系数
    qreal lod = option->levelOfDetailFromTransform(painter->worldTransform());
    if (lod < 0.2) {
        painter->drawRect(...); // 缩小看时画简单的框
    } else {
        painter->drawPixmap(...); // 放大看时画高清图
    }
}

5.3 视图渲染优化 #

  • 全视口更新：view->setViewportUpdateMode(QGraphicsView::FullViewportUpdate)。在图元密集且频繁移动的场景下，直接重绘整个视口往往比计算脏矩形（Dirty Rect）更高效。
  • 背景缓存：view->setCacheMode(QGraphicsView::CacheBackground)。如果背景是静态的，开启缓存可显著减少重绘开销。
  • OpenGL 加速：view->setViewport(new QOpenGLWidget())。利用 GPU 进行渲染。

5.4 索引模式 #

  • 动态场景：如果图元频繁移动，BSP 树的重建成本可能高于其带来的查找收益。此时可设为 scene->setItemIndexMethod(QGraphicsScene::NoIndex)，使用线性查找。
