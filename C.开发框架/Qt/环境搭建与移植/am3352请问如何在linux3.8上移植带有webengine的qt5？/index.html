AM335x (AM3352) Linux 3.8 移植 Qt5 WebEngine 问题分析与避坑指南 #

在嵌入式 ARM 平台上移植 Qt5 时，Qt WebEngine 模块是公认的“编译地狱”。它底层基于庞大的 Chromium 浏览器内核，对交叉编译器版本、系统底层库（如 glibc、dbus、udev）、内核系统调用以及硬件浮点支持（NEON）都有极高且严苛的要求。

近期翻看 TI E2E 社区里关于“如何在 AM3352 (Linux 3.8) 上移植带有 WebEngine 的 Qt5”的讨论贴，发现不少同学在交叉编译配置上踩了经典雷区。今天咱们就结合这个讨论，把这里面的大坑和正确配置逻辑给彻底扒个精光。

一、 经典报错现象复盘 #

在论坛讨论中，有开发者在交叉编译 Qt 5.7.1 时遇到了以下两个经典报错：

1. 找不到 -lts (Tslib 库连接错误) #

/usr/local/sbin/arm-linux-gnueabihf/bin/../lib/gcc/arm-linux-gnueabihf/6.2.1/../../../../arm-linux-gnueabihf/bin/ld: cannot find -lts
collect2: error: ld returned 1 exit status
Makefile:149: recipe for target '../bin/qmake' failed

2. 文件格式无法识别 (X86 与 ARM 架构冲突) #

project.o: file not recognized: File format not recognized

并且在交叉编译完成后，使用 qmake 编译自己的程序时，直接甩出一句： Project ERROR: Unknown module(s) in QT: webenginewidgets，表示 libQt5WebEngine.so 根本没生成。

二、 核心错误原因剖析（为什么会踩坑？） #

观察该开发者的配置脚本和 qmake.conf，能一眼看出几处致命错误：

错误 1：-xplatform 参数配置错误 #

bash
# 错误配置：
./configure -xplatform linux-g++ ...
  • 分析：-xplatform 应该指定**目标板（ARM）**对应的编译配置模板。如果设为 linux-g++，Qt 编译系统就会认为当前是要构建 宿主机（X86 PC） 的本地编译器，所以在构建 qmake 等宿主机工具时，硬生生地拿出了 arm-linux-gnueabihf-g++ 去链接 X86 架构的 .o 文件，直接导致了 File format not recognized 报错。
  • 正解：对于 ARM 交叉编译，应该使用诸如 linux-arm-gnueabi-g++ 或 linux-arm-gnueabihf-g++ 这样的配置模板。

错误 2：在 qmake.conf 中野蛮追加 -lts #

make
# 错误配置：
QMAKE_CC  = arm-linux-gnueabihf-gcc -lts
QMAKE_CXX = arm-linux-gnueabihf-g++ -lts
  • 分析：不少人为了省事，直接在编译器命令后面怼上 -lts。然而在编译 qmake 等基础自建工具时，交叉工具链的链接目录里根本还没有 tslib 的搜索路径，直接就报 cannot find -lts 终止编译。
  • 正解：库的包含应该在 configure 阶段通过 -I 和 -L 参数传入，或者在 qmake.conf 中使用 QMAKE_LFLAGS 变量来追加，绝不能硬塞进编译器命令里。

三、 Qt WebEngine 移植硬核要求与正确配置 #

想在 AM335x (Cortex-A8) 上强行跑起 WebEngine，以下几个硬性指标必须满足：

1. 工具链与内核版本限制 #

  • 内核版本限制：Qt WebEngine (Chromium) 内部使用了大量的现代 Linux 特性（如 User Namespaces 等沙盒安全机制）。Linux 3.8 内核版本过低，对很多安全系统调用不支持。TI 官方在 SDK 中提供 WebEngine 库支持，是将内核升级到 Linux 4.4 (LTS)、编译器升级到 GCC 5.3、Qt 升级到 5.6.2 之后才做到的。
  • 工具链要求：编译 WebEngine 至少需要 GCC 5.0 以上的交叉工具链，支持 C++11 和 hard-float。

2. 正确的 configure 配置脚本 #

这是一个针对 ARMv7 (AM335x) 的标准交叉编译 configure 示范脚本：

bash
#!/bin/sh
./configure \
  -v \
  -opensource \
  -confirm-license \
  -prefix /opt/qt-5.7.1-arm \
  -xplatform linux-arm-gnueabihf-g++ \
  -release \
  -shared \
  -qt-zlib \
  -qt-libjpeg \
  -qt-libpng \
  -qt-freetype \
  -qt-sql-sqlite \
  -tslib \
  -I/usr/local/tslib/include \
  -L/usr/local/tslib/lib \
  -no-opengl \
  -skip qtandroidextras \
  -skip qtpurchasing \
  -skip qtvirtualkeyboard

3. 正确的 qmake.conf 配置 #

在 mkspecs/devices/linux-arm-gnueabihf-g++/qmake.conf（或对应的模板）下进行如下配置：

make
MAKEFILE_GENERATOR      = UNIX
CONFIG                 += incremental
QMAKE_INCREMENTAL_STYLE = sublib

include(../../common/linux.conf)
include(../../common/gcc-base-unix.conf)
include(../../common/g++-unix.conf)

# 默认 QPA 平台选择 linuxfb
QT_QPA_DEFAULT_PLATFORM = linuxfb

# 针对 Cortex-A8 (AM335x) 的 ARMv7-A 硬件浮点优化参数
QMAKE_CFLAGS_RELEASE   += -O2 -march=armv7-a -mtune=cortex-a8 -mfpu=neon -mfloat-abi=hard
QMAKE_CXXFLAGS_RELEASE += -O2 -march=armv7-a -mtune=cortex-a8 -mfpu=neon -mfloat-abi=hard

# 指定交叉编译器，切记不可在后面硬塞链接库参数
QMAKE_CC                = arm-linux-gnueabihf-gcc
QMAKE_CXX               = arm-linux-gnueabihf-g++
QMAKE_LINK              = arm-linux-gnueabihf-g++
QMAKE_LINK_SHLIB        = arm-linux-gnueabihf-g++

QMAKE_AR                = arm-linux-gnueabihf-ar cqs
QMAKE_OBJCOPY           = arm-linux-gnueabihf-objcopy
QMAKE_NM                = arm-linux-gnueabihf-nm -P
QMAKE_STRIP             = arm-linux-gnueabihf-strip

load(qt_config)

四、 编译后仍未生成 WebEngine 的检查排错 #

即便 configure 成功过关，如果最后的编译产物里依然缺了 libQt5WebEngine.so，可以从以下三个维度进行排查：

  1. 构建依赖不全：WebEngine 的编译需要在宿主机上安装额外的解析生成工具。确认宿主机上已安装了 python (通常是 python2)、bison、flex、gperf、pkg-config、bzip2。
  2. 硬件浮点缺失：如果你的编译器是 soft-float（软件模拟浮点），WebEngine 会直接跳过编译，因为它内部大量的 JS 引擎及音视频解析强依赖硬浮点（hard-float）。
  3. 查看 config.summary：在执行完 ./configure 后，翻看生成的配置总览报告，找到 WebEngine 一栏，看看是不是显示了 No，并仔细阅读其后附带的未通过原因提示（如缺少必要的底层库等）。
