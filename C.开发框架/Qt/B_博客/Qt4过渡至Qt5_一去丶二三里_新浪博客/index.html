Qt4过渡至Qt5_一去丶二三里_新浪博客

Qt4.x项目平滑移植至Qt5.x开发指南与常见编译错误排查 #

随着技术的发展，Qt5 带来了更为强劲的 QML 渲染引擎（Scene Graph）、更好的 C++11 支持以及更清晰的底层模块划分。

然而，将原有的 Qt4 项目直接用 Qt5 编译时，往往会触发大量的编译错误。这主要是因为 Qt5 对底层类库进行了模块化拆分，并废弃/重构了部分旧的 C++ API。

本文整理了从 Qt4 过渡到 Qt5 过程中最常见的一系列编译错误及对应的修改方案。

一、 核心模块拆分导致的编译错误 #

在 Qt5 中，原本混在 QtCore 和 QtGui 中的许多类被抽离成了独立的子模块。

1. QtWidgets 独立模块 #

  • 报错信息：
    • error: QMainWindow: No such file or directory
    • error: QWidget: No such file or directory
  • 原因：所有窗口控件类（QWidget、QMainWindow、QToolButton 等）被从 QtGui 挪到了新的 QtWidgets 模块中。
  • 解决办法：
    • 在 .pro 项目文件中添加：
      QT += widgets
    • 头文件包含从 #include <QtGui/QWidget> 更改为：
      cpp
      #include <QtWidgets/QWidget> // 或直接 #include <QWidget>

2. QtPrintSupport (打印支持模块) #

  • 报错信息：QPrinter 或 QPrintDialog 提示未定义。
  • 解决办法：
    • 在 .pro 项目文件中添加：
      QT += printsupport
    • 在代码中引入：
      cpp
      #include <QtPrintSupport/QPrinter>
#include <QtPrintSupport/QPrintDialog>

3. QtConcurrent (并发模块) #

  • 报错信息：undefined reference to QtConcurrent::... 链接错误。
  • 原因：在 Qt4 中，QtConcurrent 是 QtCore 的一部分。在 Qt5 中它被剥离为独立模块。
  • 解决办法：
    • 在 .pro 项目文件中添加：
      QT += concurrent
    • 引入头文件：
      cpp
      #include <QtConcurrent/QtConcurrent>

4. QtWebKitWidgets (浏览器控件模块) #

  • 报错信息：无法识别 QWebView 或 QWebFrame。
  • 解决办法：
    • 在 .pro 项目文件中添加：
      QT += webkitwidgets
    • 引入头文件：
      cpp
      #include <QtWebKitWidgets/QWebView>

二、 常用废弃 API 的平滑替换对照表 #

Qt5 废弃了许多老旧、低效的全局辅助函数及类，开发者需要将其替换为现代化的实现：

序号 Qt 4.x 被废弃的 API/类 Qt 5.x 推荐替代实现 说明与代码示例
1 QString::toAscii()
QString::fromAscii()		 toLatin1() / fromLatin1()
toUtf8() / fromUtf8()		 替换为更清晰的字符集编码方法。
QByteArray data = str.toLatin1();
2 QCoreApplication::UnicodeUTF8 直接删除该枚举参数 Qt5 默认所有翻译 tr() 均假设为 UTF-8 编码。
setWindowTitle(tr("标题")); 即可，无需传第四个参数。
3 QWorkspace QMdiArea 多文档区域管理。在 Qt5 中 QWorkspace 已被彻底删除。
#include <QMdiArea>
4 qFindChildren<T>(obj, ...) obj->findChildren<T>(...) 全局泛型查找函数废弃，改用 QObject 成员函数。
auto list = parentObj->findChildren<QPushButton*>();
5 qVariantValue<T>(val) val.value<T>() 变量类型提取改用成员模板方法。
QTime t = val.value<QTime>();
6 qVariantCanConvert<T>(val) val.canConvert(QMetaType::Type) Q_ASSERT(variant.canConvert(QMetaType::QString));
7 Qt::escape(str) str.toHtmlEscaped() HTML 转义。用于转义字符（如 < 转为 &lt;）。
QString esc = rawStr.toHtmlEscaped();
8 QDesktopServices::storageLocation(...) QStandardPaths::writableLocation(...) 系统标准路径获取。注意：standardLocations 返回列表，获取单路径推荐使用 writableLocation。
9 Phonon 媒体框架 QtMultimedia 模块 废弃了第三方的 Phonon，全面采用 Qt 自建的多媒体引擎。
使用 QMediaPlayer 和 QVideoWidget。
10 CONFIG += qtestlib QT += testlib 测试框架引入方式规范化。

三、 高级架构变化 #

1. 插件系统升级 (Plugin Loading) #

在 Qt4 中，我们编写自定义 Qt 插件（例如自定义图片格式插件）时通常使用 Q_EXPORT_PLUGIN 或 Q_EXPORT_PLUGIN2 宏。

  • Qt5 升级方案：这些宏在 Qt5 中被弃用。取而代之的是使用新的 Q_PLUGIN_METADATA 宏：
    cpp
    class MyPlugin : public QObject, public MyInterface
{
    Q_OBJECT
    Q_INTERFACES(MyInterface)
    // 💡 Qt5 新增，支持读取包含元数据的 JSON 配置文件
    Q_PLUGIN_METADATA(IID "org.qt-project.Qt.MyInterface" FILE "myplugin.json") 
};
    新系统的优点在于，Qt 在扫描或查询插件信息时，不需要将插件动态链接库（.dll / .so）物理载入内存（dlopen），从而极大提高了启动速度和软件的稳定性。

2. 自动化重构工具：fixqt4headers.pl #

如果你的老项目非常庞大，里面包含成百上千个头文件需要转换，手动修改 #include 会是一场灾难。

  • 快捷方法：Qt 官方在源码包中提供了一个名为 fixqt4headers.pl 的 Perl 脚本（位于 qtbase/bin/ 下）。
  • 用法：在项目源码根目录下运行该脚本，它会自动扫描所有的 C++ 源文件，自动将旧版的头文件包含格式修正为带有对应模块名称的 Qt5 标准头文件格式。
