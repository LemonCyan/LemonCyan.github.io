Qt之Model/View模型视图委托架构核心原理与基础应用 #

在设计复杂的桌面端图形界面时，如何优雅地管理和展示大量数据是一大挑战。传统的开发方式常将数据源读取、业务计算与 UI 显示硬编码组合在一个控件中，这会导致代码高度耦合、极难扩展。

为了解决这一痛点，Qt 引入了 Model/View（模型/视图）编程架构。该架构由经典的设计模式 MVC (Model-View-Controller) 演变而来，是开发高效、高定制化数据列表与树形网格的基石。

一、 Model/View 架构核心概念 #

传统的 MVC 包含三个主要对象：

  • Model（模型）：持有核心业务数据并定义底层接口。
  • View（视图）：负责将模型数据渲染在屏幕上。
  • Controller（控制器）：拦截并响应用户的按键/点击输入，改变模型数据。

而在 Qt 的 Model/View 架构中，将 控制器（Controller） 与 视图（View） 进行了简化合并，并引入了 委托（Delegate） 的概念。

graph LR
    Data[数据源: 数据库/文件/内存] <--> Model[Model: 数据模型]
    Model <--> View[View: 显示视图]
    Model <--> Delegate[Delegate: 委托渲染/编辑]
    View <--> Delegate
  • 模型 (Model)：与数据源直接通信，为视图和委托提供标准化二维/树形的数据访问接口。所有的模型类都基于 QAbstractItemModel。
  • 视图 (View)：负责布局排版，利用模型给出的虚拟索引将数据项绘制给用户。常见的有 QListView（列表）、QTableView（表格）和 QTreeView（树形）。
  • 委托 (Delegate)：定义了每个数据项的渲染方式，并负责在双击编辑时提供自定义输入控件（例如双击表格某单元格时弹出一个下拉框或日期选择器）。默认委托是 QStyledItemDelegate。

二、 核心机制 1：模型索引 (Model Index) #

为了确保数据结构与展示解耦，视图不能通过内存指针直接访问模型中的数据项。它们之间全部使用临时的 QModelIndex（模型索引） 作为中介传递地址。

获取一个唯一的 QModelIndex 需要指定三个核心坐标：

  1. Row（行号）：0 轴索引。
  2. Column（列号）：Y 轴索引。
  3. Parent（父节点模型索引）：用于表示多级树形分支。
cpp
// 1. 获取顶级节点（父索引为空）第一行第一列的索引
QModelIndex indexA = model->index(0, 0, QModelIndex());

// 2. 获取节点 A 下属子分支（第一行第一列）的索引
QModelIndex indexB = model->index(0, 0, indexA);
⚠警告

QModelIndex 只是一个临时引用的快照。 当模型中的数据发生排序、插入或删除时，已经持有的 QModelIndex 可能会瞬时失效！ 如果需要在业务中长期追踪某条数据项，必须使用 QPersistentModelIndex（持久型模型索引）。

三、 核心机制 2：数据角色 (Item Roles) #

同一个单元格项（如一个文件节点），它往往包含多种维度的信息：显示的文件名、前面的图标、悬停的提示、以及底层存储的数据库物理主键。

在 Model/View 中，我们通过传递不同的 Qt::ItemDataRole（数据角色指示器） 向同一个模型索引获取不同属性的数据：

cpp
// 传入同一个 index，通过不同角色获取不同类型的数据：
QVariant text       = model->data(index, Qt::DisplayRole);    // 获取要显示的普通文本 (QString)
QVariant icon       = model->data(index, Qt::DecorationRole); // 获取显示的图标 (QIcon)
QVariant tooltip    = model->data(index, Qt::ToolTipRole);    // 获取悬浮提示信息 (QString)
QVariant dbId       = model->data(index, Qt::UserRole);       // 获取开发人员自定义绑定的数据 (如 ID)

四、 实战：多视图共享同一数据模型 #

下面演示如何利用 Qt 自带的 QFileSystemModel（文件系统模型），实现一个文件树（QTreeView）与文件列表（QListView）同步联动显示的经典结构。

cpp
#include <QApplication>
#include <QSplitter>
#include <QFileSystemModel>
#include <QTreeView>
#include <QListView>
#include <QDir>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    
    // 1. 创建左右分栏容器
    QSplitter *splitter = new QSplitter();

    // 2. 初始化核心文件系统模型
    QFileSystemModel *model = new QFileSystemModel();
    model->setRootPath(QDir::currentPath()); // 设定根路径监控为当前程序目录

    // 3. 构建左侧树视图并绑定模型
    QTreeView *tree = new QTreeView(splitter);
    tree->setModel(model);
    // 只展示当前路径下的数据
    tree->setRootIndex(model->index(QDir::currentPath()));

    // 4. 构建右侧列表视图并绑定同一个模型
    QListView *list = new QListView(splitter);
    list->setModel(model);
    list->setRootIndex(model->index(QDir::currentPath()));

    // 💡 额外提示：
    // 因为它们共享了同一个模型实例，如果需要让用户的多选状态也在两个视图中同步，
    // 可以显式设置它们共用同一个 SelectionModel：
    // list->setSelectionModel(tree->selectionModel());

    splitter->setWindowTitle("Two views sharing the same model");
    splitter->resize(800, 600);
    splitter->show();

    return app.exec();
}

五、 技术选型：Item-Based 便利控件 vs Model/View #

Qt 还提供了三个“开箱即用”的便利类：QListWidget、QTableWidget 和 QTreeWidget。它们内部自带了基础的 Model，开发者可以通过直观的 Item-based API（如 addItem）直接操作界面。

选型建议 #

  • 便利控件 (Widget 类)：适合小型项目、数据量较少（通常在万条以下）、无需频繁排序和大数据同步的简易表格或列表展示。
  • 视图/模型 (View & Model)：适合大型工业项目、数据量极大（数十万行以上且要求秒开）、数据源来源于数据库或外部二进制文件流、或者界面高度个性化定制编辑的系统。
