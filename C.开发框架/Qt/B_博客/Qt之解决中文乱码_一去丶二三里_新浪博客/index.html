Qt中文乱码解决方案与QTextCodec编码机制（含Qt4与Qt5版本对比） #

在进行 Qt 应用程序开发和跨平台移植时，最容易遇到的问题之一就是中文乱码。同一行包含中文的代码，在 Windows 环境（MSVC 编译器）下运行良好，移植到 Linux 环境（GCC 编译器）或者打包发布后就会变成一堆奇怪的符号。

乱码的根源非常简单：源码文件保存的物理编码、编译器读取源码时的解码器、以及 Qt 运行时用于展示字符的编码，这三者之间不一致。

本文针对 Qt 4 和 Qt 5/6 版本分别给出最优雅的乱码消除方案。

一、 问题根源分析 #

平台/编译器 默认源码读取编码 默认底层编码
Windows / MSVC 系统本地编码（通常为 GBK / GB18030） GBK
Linux / GCC 国际通用编码（UTF-8） UTF-8

如果在 Windows 的 VS/MSVC 下直接双击写中文 tr("你好")，编译器以 GBK 将其编译进二进制字节码，而运行时的 Qt 引擎如果尝试以 UTF-8 或 Latin-1 去读取这些字节，就会发生解码偏差，从而显现为乱码。

二、 针对 Qt 4.x 的解决方案 (QTextCodec 机制) #

在 Qt4 时代，整个元对象反射和 QString 没有默认采用 UTF-8。我们需要在 main.cpp 的第一行配置 QTextCodec 控制全局的字符解码策略：

cpp
#include <QApplication>
#include <QTextCodec>
#include "MainWindow.h"

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    // 💡 1. 获取系统本地的字符编码格式 (Windows 下通常为 System/GBK)
    QTextCodec *codec = QTextCodec::codecForName("System");
 
    // 💡 2. 设置对本地文件系统进行读写时的默认编码
    QTextCodec::setCodecForLocale(codec);
 
    // 💡 3. 设置传入 tr() 函数时的默认字符串编码（解决 tr("中文") 乱码的关键）
    QTextCodec::setCodecForTr(codec);
 
    // 💡 4. 设置通过字符常量或 QByteArray 构造 QString 对象时的解码方式
    QTextCodec::setCodecForCStrings(codec); 

    MainWindow w;
    w.show();
    return app.exec();
}
⚠警告

不要在现代 Qt5/Qt6 工程中复制这四行代码！
setCodecForTr 和 setCodecForCStrings 在 Qt5 中已经被完全废弃并移除，盲目粘贴会导致编译报错。

三、 针对 Qt 5.x / Qt 6.x 的解决方案 (现代化方案) #

从 Qt 5 开始，框架底层全部默认支持 UTF-8 编码，并且彻底废弃了 Qt4 那种运行时全局劫持解码的方式。在 Qt5/6 中解决中文乱码，应当遵循以下三个标准规范：

1. 规范：统一将源码保存为 UTF-8 (带/不带 BOM) #

在你的 IDE（如 Qt Creator 或 Visual Studio）中，将文件默认编码全部强制设置为 UTF-8。

2. 使用：QStringLiteral 宏（推荐） #

对于代码里的所有中文字符串常量，强烈推荐使用 QStringLiteral 包裹。它会在编译期直接生成只读的 UTF-16 数据段，运行时直接加载为 QString，不需要任何运行时的解码开销，性能也是最高的：

cpp
ui->label->setText(QStringLiteral("中文测试"));

3. MSVC 编译器的特殊处理（💡 避坑要点） #

如果源码保存为 UTF-8，但你使用的是 Windows MSVC 编译器，MSVC 依然会顽固地尝试用本地的 GBK 编码去解析它，导致编译报出“换行符不匹配”或乱码。

要彻底解决 MSVC 的解析问题，可以在你的项目 .pro 文件中追加以下命令，强行通知 MSVC 以 UTF-8 格式解析源码：

# 仅限使用 MSVC 编译器时传入 /utf-8 参数
msvc {
    QMAKE_CXXFLAGS += /utf-8
}

(如果是 GCC / MinGW 编译器，则默认就是 UTF-8，无需此配置)
