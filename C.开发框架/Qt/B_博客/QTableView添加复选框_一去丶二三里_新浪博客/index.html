QTableView中添加复选框（CheckBox）的几种方法与实现 #

在进行 Qt 表格视图（QTableView）开发时，单选、多选以及一键全选是十分常见的功能需求。为表格的某一列添加复选框（CheckBox）是实现这些交互最直观、用户体验最好的方式。

在 Qt 中实现表格复选框主要有以下四种方法。本文将对它们进行对比，并详解最常用、性能最佳的“Model 层实现法”。

一、 四种实现方案对比 #

方法 实现途径 优点 缺点
1. 激活编辑委托 重写 QItemDelegate::createEditor() 并返回 QCheckBox 部件。 符合经典代理委托流程。 用户必须双击或单击选中该单元格后，复选框控件才会被创建并显示，不满足日常“直接展示”的需求。
2. 重写 Model 函数 (推荐) 继承 QAbstractTableModel 并重写 flags()、data() 和 setData()。 属于 Qt 的标准数据角色（CheckStateRole）机制，性能最好，完美支持数据的增删改查动态更新。 需要自定义 Model，代码结构偏底层。
3. 嵌入静态小部件 调用 QTableView::setIndexWidget(index, widget) 强行在索引处塞入一个复选框。 实现极其简单快捷。 此方法根据 Qt 官方文档，只适合展示静态内容。若要在表格中频繁进行数据更新、拖拽或增删，会导致严重的性能问题与显示冲突。
4. 自定义委托重绘 继承 QItemDelegate，并在 paint() 函数中手动使用 QStylePainter 绘制复选框外观。 可扩展性极高，除了复选框，还可以混合绘制任意按钮、图标或自定义动效。 绘图逻辑相对复杂，需手算交互鼠标点击坐标区域。

二、 最佳实践：通过自定义 Model 实现复选框 #

下面是使用**方法二（重写 Model 的 CheckStateRole）**实现的具体代码示例。

我们定义一个 QMap 作为模型内部的数据源，用来记录每一行复选框的选中状态：

cpp
// 用于保存行号以及对应的选中状态
QMap<int, Qt::CheckState> check_state_map;

1. 重写 flags()：开启用户可勾选属性 #

必须将第一列（或需要放置复选框的列）的标志位设置为 Qt::ItemIsUserCheckable，否则单元格无法响应鼠标勾选点击。

cpp
Qt::ItemFlags TableModel::flags(const QModelIndex &index) const
{
    if (!index.isValid())   
        return Qt::NoItemFlags;   

    // 仅在第 0 列渲染并启用 CheckBox
    if (index.column() == 0) {
        return Qt::ItemIsEnabled | Qt::ItemIsSelectable | Qt::ItemIsUserCheckable;   
    }
    
    // 其他数据列仅支持启用和选择，不可勾选
    return Qt::ItemIsEnabled | Qt::ItemIsSelectable;   
}

2. 重写 setData()：保存用户勾选状态 #

当用户在界面上点击复选框导致状态改变时，View 会向 Model 发送 Qt::CheckStateRole 的写入请求，我们在此捕获并记录最新状态。

cpp
bool TableModel::setData(const QModelIndex &index, const QVariant &value, int role)
{   
    if (!index.isValid())   
        return false;   
        
    if (role == Qt::CheckStateRole && index.column() == 0)
    {   
        // 记录或更新选中状态并存入 Map 中
        check_state_map[index.row()] = (value.toInt() == Qt::Checked) ? Qt::Checked : Qt::Unchecked;
        
        // 关键：发出数据变更信号以通知视图层重绘
        emit dataChanged(index, index);
        return true;
    }
    return false;   
}

3. 重写 data()：向界面返回当前勾选状态 #

当表格进行渲染重绘时，View 会向 Model 询问当前的 CheckStateRole 状态。

cpp
QVariant TableModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid())
        return QVariant();

    switch (role)
    {
    case Qt::CheckStateRole:
        // 仅在第 0 列返回状态
        if (index.column() == 0) 
        {    
            // 如果已保存过该行的状态，直接返回对应状态，否则默认未勾选
            if (check_state_map.contains(index.row())) {
                return check_state_map[index.row()];
            }
            return Qt::Unchecked;     
        }
        break;
        
    case Qt::DisplayRole:
        // 返回文本数据（可选，复选框右侧可附带文字）
        break;
        
    default:
        break;
    }
    
    return QVariant();
}

三、 表头复选框（QHeaderView）的实现探讨 #

完成上述步骤后，表格中的行已经可以自由勾选了。但如果你希望在表头（Header）也放置一个复选框，以实现“一键全选/全不选”功能，你会发现以下写法是无效的：

cpp
// ❌ 错误做法：QTableView 表头默认不支持 CheckStateRole 角色
QVariant TableModel::headerData(int section, Qt::Orientation orientation, int role) const
{
    if (role == Qt::CheckStateRole) {    
        return Qt::Checked; // 表头并不会理会这个返回值，无法显示 CheckBox
    }
    return QVariant();  
}

为什么无效？ #

因为 Qt 源码中的 QHeaderView 在绘制表头单元格时，默认并未实现对 Qt::CheckStateRole 数据的渲染逻辑。

正确的实现方案 #

若想为表头添加复选框，必须子类化 QHeaderView：

  1. 重写 paintSection 函数，通过 QStylePainter 手动在指定表头单元格内绘制一个 QStyle::CE_Header 或 QStyleElement::Element_CheckBox。
  2. 重写 mousePressEvent，当用户点击表头复选框对应的区域时，发射自定义的全选/取消全选信号，进而更新自定义 Model 的数据源并重绘视图。
