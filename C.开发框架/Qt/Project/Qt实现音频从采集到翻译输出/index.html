Qt实现音频从采集到翻译输出

本文将详细介绍如何使用 Qt (C++) 实现一个完整的音频处理流水线：音频采集 -> 语音转文字 (ASR) -> 机器翻译 (MT)。方案核心采用 Qt 原生多媒体模块进行音频录制，并对接腾讯云的语音识别和机器翻译 API，全流程使用 C++ 实现，避免引入 Python 组件的复杂性。

1. 系统架构设计 #

系统主要包含音频采集、ASR 识别、机器翻译三个核心模块。数据流向清晰，模块间通过信号槽或回调机制解耦。

模块职责 #

  1. 音频采集模块：利用 QAudioSource (Qt6) 或 QAudioInput (Qt5) 采集 PCM 音频数据。支持麦克风输入和系统内录（Loopback）。
  2. ASR 识别模块：通过 HTTPS Post 请求调用腾讯云 一句话识别 API，将音频数据转换为中文文本。
  3. 机器翻译模块：调用腾讯云 文本翻译 API，将识别到的中文翻译为英文。

2. 环境准备与配置 #

Qt 模块依赖 #

在 CMakeLists.txt 或 .pro 文件中添加必要的模块支持：

cmake
# CMakeLists.txt
find_package(Qt6 REQUIRED COMPONENTS Multimedia Network)
target_link_libraries(mytarget PRIVATE Qt6::Multimedia Qt6::Network)

腾讯云 API 准备 #

使用云服务前，需在腾讯云控制台获取 API 密钥：

  • SecretId: 用于标识身份。
  • SecretKey: 用于生成签名，严禁硬编码在客户端代码中（生产环境建议通过临时密钥服务器获取）。

3. 音频采集 (Audio Acquisition) #

Qt Multimedia 模块提供了强大的音频支持。我们主要使用 QAudioSource 类来采集原始音频流。

核心参数配置 #

为了获得最佳的识别效果，必须使用腾讯云 ASR 建议的音频格式：

参数 值 说明
采样率 16000 Hz 语音识别标准采样率
声道数 1 (Mono) 单声道减少数据量且满足需求
格式 Int16 PCM 16位有符号整型 (Little Endian)

设备选择：麦克风 vs 系统内录 #

可以通过遍历 QMediaDevices 来选择特定设备。

  • 麦克风：通常是 defaultAudioInput()。
  • 系统内录：在 Windows 上通常称为 "立体声混音 (Stereo Mix)"。
✦提示

代码技巧：通过判断设备名称字符串（如 "Mix" 或 "混音"）来自动筛选内录设备。

关键代码实现 #

cpp
void AudioCapture::startCapture() {
    // 1. 初始化音频格式
    QAudioFormat format;
    format.setSampleRate(16000);
    format.setChannelConfig(QAudioFormat::ChannelConfigMono);
    format.setSampleFormat(QAudioFormat::Int16);

    // 2. 选择输入设备（示例：查找立体声混音，未找到则用默认）
    const auto devices = QMediaDevices::audioInputs();
    QAudioDevice inputDevice = QMediaDevices::defaultAudioInput();
    for (const auto &device : devices) {
        if (device.description().contains("Stereo Mix") || 
            device.description().contains("立体声混音")) {
            inputDevice = device;
            break;
        }
    }

    // 3. 创建录音对象
    mpAudioSource = new QAudioSource(inputDevice, format, this);

    // 4. 绑定 IO 设备读取
    // start() 返回一个 QIODevice，我们可以监听其 readyRead 信号
    mpIoDevice = mpAudioSource->start();
    connect(mpIoDevice, &QIODevice::readyRead, this, [this](){
        // 读取音频数据并追加到缓存
        QByteArray data = mpIoDevice->readAll();
        m_audioBuffer.append(data);
    });
}

4. 云 API 鉴权 (Signature v3) #

腾讯云 API 需要严格的鉴权签名（TC3-HMAC-SHA256）。这是实现难点之一。

签名流程 #

  1. 拼接规范请求串 (CanonicalRequest)：包含 HTTP 方法、URI、查询字符串、Headers 等。
  2. 拼接待签名字符串 (StringToSign)：包含算法标识、时间戳、凭证范围和规范请求串的哈希值。
  3. 计算签名 (Signature)：使用 SecretKey 派生出 SigningKey，对 StringToSign 进行 HMAC-SHA256 计算。
  4. 构造 Authorization 头：将签名组合成最终的 HTTP Header。
❢重要

签名计算涉及多次 HMAC-SHA256 哈希，建议封装一个通用的 Signer 类。确保时间戳 (Timestamp) 与服务器时间误差不超过 5 分钟。

5. 语音转文字 (ASR) 实现 #

使用 一句话识别 (SentenceRecognition) 接口，适用于 60秒以内的短语音。

请求构造 #

你需要构建一个 JSON 请求体，并将其 Base64 编码后的音频数据放入 Data 字段。

cpp
void AsrClient::recognize(const QByteArray& pcmData) {
    // 构建请求包体
    QJsonObject json;
    json["ProjectId"] = 0;
    json["SubServiceType"] = 2; // 2: 实时识别
    json["EngSerViceType"] = "16k_zh"; // 16k 中文模型
    json["SourceType"] = 1; // 1: 语音数据直接传输
    json["VoiceFormat"] = "wav"; // 或 pcm，需与采集格式一致
    json["UsrAudioKey"] = QUuid::createUuid().toString();
    json["Data"] = QString(pcmData.toBase64()); // 音频流 Base64
    json["DataLen"] = pcmData.size(); // 原始数据长度

    QByteArray payload = QJsonDocument(json).toJson(QJsonDocument::Compact);

    // 发送带有签名的 HTTPS POST 请求...
    post("https://asr.tencentcloudapi.com", "SentenceRecognition", "2019-06-14", payload);
}

6. 机器翻译 (MT) 实现 #

拿到 ASR 返回的中文文本后，紧接着调用 文本翻译 (TextTranslate) 接口。

翻译逻辑 #

翻译接口的鉴权逻辑与 ASR 完全一致，只需修改 Endpoint 和 Action。

cpp
void TmtClient::translate(const QString& sourceText) {
    QJsonObject json;
    json["SourceText"] = sourceText;
    json["Source"] = "zh"; // 源语言
    json["Target"] = "en"; // 目标语言
    json["ProjectId"] = 0;

    QByteArray payload = QJsonDocument(json).toJson(QJsonDocument::Compact);

    // 复用网络发送逻辑
    // Endpoint: tmt.tencentcloudapi.com
    // Action: TextTranslate
    // Version: 2018-03-21
    post("https://tmt.tencentcloudapi.com", "TextTranslate", "2018-03-21", payload);
}

响应处理 #

cpp
// 假设这是 networkManager 的 finished 槽函数
void TmtClient::onReplyFinished(QNetworkReply* reply) {
    QByteArray responseData = reply->readAll();
    QJsonObject root = QJsonDocument::fromJson(responseData).object();
    
    // 解析如: Response -> TargetText
    if (root.contains("Response")) {
       QJsonObject responseObj = root["Response"].toObject();
       if (responseObj.contains("TargetText")) {
           QString targetText = responseObj["TargetText"].toString();
           emit translationReady(targetText); // 发送信号给 UI
       }
    }
}

7. 逻辑整合与优化 #

为了保证 UI 流畅，建议将网络请求和音频编码放在非 UI 线程处理，尽管 QNetworkAccessManager 本身是异步的，但 Base64 编码大段音频可能会短暂阻塞主线程。

性能说明 #

  • VAD 优化：如果在 readyRead 中分析 PCM 振幅发现长时间静音，可自动触发停止逻辑，实现“说完即停”的体验。
  • WAV 头处理：虽然 API 支持 PCM，但封装 44 字节的标准 WAV 头能提高兼容性，便于调试时保存文件播放检查。
