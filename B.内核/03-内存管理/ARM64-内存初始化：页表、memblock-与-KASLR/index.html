一、打开 MMU 之前：内核面对的局面 #

bootloader 摸清系统内存，把 kernel image 和 dtb image 搬进 DRAM，跳到内核入口。此刻 MMU 关着，CPU 眼里只有物理地址。原文这里配过一张「启动之前的内存布局」图，抓取时丢了，用表补上：

对象 谁放在哪 约束 内核的假设
kernel image bootloader 放在 main memory 起始地址偏移 TEXT_OFFSET 处 TEXT_OFFSET 与内核事先谈好（4.4.6 常见值 0x80000） 低于 image 的物理内存，内核不纳入自己的内存管理
dtb image bootloader 随便放 早期要求 8 字节对齐、不跨 2M、落在 image 起始 512M 内 汇编阶段不碰它，进 C 之后再建映射
页表 内核自己在 bss 段之后静态占几页 链接脚本里连续摆放、页对齐 汇编代码自己清零、自己填表项
MMU / D-cache 关 — 看到的地址就是总线上的地址

三条后果决定后面所有代码的形状。image 想要的位置是 PHYS_OFFSET + TEXT_OFFSET，但并非必须——它也可以落在更高的物理地址上，只要不在最底下，下面那段内存内核就不认了，这是取舍不是 bug。cache 的要求只有一条：image 那一段必须 clean 到 PoC，也就是所有 observer 访问时内容一致；页表不在 image 里，所以页表的 cacheline 得自己 invalidate。编译器按虚拟地址编，链接脚本里的 _text、_end 全是虚拟地址，代码实际跑在物理地址上，这个错位从第一行就存在，一直持续到 MMU 打开。

所以内核接手后做的第一件正事不是初始化内存管理，而是先给自己造一个能跑的世界。

二、两段映射的由来：identity mapping 与 kernel image mapping #

汇编初始化阶段准备两套页表，注意是两套。原文此处也丢了图，同样用表代替：

映射 虚拟地址 映射到哪 对齐要求 谁在用
identity mapping（idmap） 数值上等于 PA 同一段 PA，VA == PA 覆盖 .idmap.text（__idmap_text_start~__idmap_text_end） 开 MMU 那几条指令。ARM 架构强推荐，否则取指会被翻译前后含义不同的地址搞疯
kernel image mapping 从 PAGE_OFFSET（4.4.6）或 KIMAGE_VADDR + TEXT_OFFSET（4.15）起 image 所在的 PA section mapping 时 PAGE_OFFSET 要 2M 对齐（4K 页） 正文、rodata、data、bss

开 MMU 的代码被塞进 .idmap.text，这段代码被映射两次：作为 image 的一部分映射到 __idmap_text_start 起的虚拟地址；设它的物理地址是 A，还映射到从 A 起的虚拟地址。A 与 PAGE_OFFSET 谁大谁小没有规定，写死的只有一件事：这几十行指令在两种翻译下必须指向同一块内存。

页表要占多大，值得算一遍。48 位 VA、4K 页、四级映射，地址切成 9 + 9 + 9 + 9 + 12。给 L0~L3 各一页，最后一页 512 项 × 4K = 2M，装不下 image，那就让 PMD 直接放 block 描述符，三级页表覆盖 512 × 2M = 1G，副作用是 PAGE_OFFSET 必须 2M 对齐。16K、64K 页上这个技巧不划算，对齐要求抬得太高：

页大小 不用 section mapping，一页覆盖 用 section mapping 的对齐要求 选择
4K 512 × 4K = 2M 2M 用 section mapping
16K 2K × 16K = 32M 32M 不用，32M 够
64K 8K × 64K = 512M 512M 不用，512M 够

结论：swapper 要预留的页表页数跟级数挂钩——用 section mapping 是 PGTABLE_LEVELS - 1 页，不用是 PGTABLE_LEVELS 页。

有个特例。VA 配 39 位、PA 是 48 位，而 .idmap.text 恰在高端（超出 39 位能表示的范围），上面这结论就废了：PGTABLE_LEVELS 只认虚拟地址位宽和 PAGE_SIZE，不认物理地址。内核的处理是往上挂一级 EXTRA 翻译表，EXTRA_SHIFT = PGDIR_SHIFT + PAGE_SHIFT - 3，EXTRA_PTRS = 1 << (48 - EXTRA_SHIFT)，第四章会看到那段 #ifndef CONFIG_ARM64_VA_BITS_48。页表填完，sctlr_el1.M 一置，kernel 进虚拟地址世界，美中不足是只剩两段地址可见。

三、建页表的三个基础函数 #

版本：4.4.6。三处代码按原样保留，行尾的全角破折号标注改成 // ①。

1、create_table_entry：填一个中间级描述符 #

armasm
.macro    create_table_entry, tbl, virt, shift, ptrs, tmp1, tmp2
    lsr    \tmp1, \virt, #\shift
    and    \tmp1, \tmp1, #\ptrs - 1     // ① table index
    add    \tmp2, \tbl, #PAGE_SIZE      // ② 下一级表 = 当前页 + 一页
    orr    \tmp2, \tmp2, #PMD_TYPE_TABLE // ③ bit0=1 valid, bit1=1 table
    str    \tmp2, [\tbl, \tmp1, lsl #3] // ④ 每项 8 字节
    add    \tbl, \tbl, #PAGE_SIZE       // ⑤ 指针移到下一级
.endm

① linux 术语里这是 PGD/PUD/PMD 描述符，ARM64 术语里是 L0/L1/L2 描述符，填哪级由 tbl 指的那页决定。定位项的办法老一套：地址右移 shift，截 ptrs 位。② 下一级表地址硬编码成「当前页 + 一页」，全靠链接脚本把启动页表连续摆放：

text
BSS_SECTION(0, 0, 0)
. = ALIGN(PAGE_SIZE);
idmap_pg_dir = .;
. += IDMAP_DIR_SIZE;
swapper_pg_dir = .;
. += SWAPPER_DIR_SIZE;

改一个尺寸就得改另一处。③ 光有地址不行，还得告诉 MMU 这项 valid（bit 0）且是 table（bit 1），所以最低两位 0b11：

c
#define PMD_TYPE_TABLE        (_AT(pmdval_t, 3) << 0)

④ lsl #3 是因为一项 8 字节。⑤ 把 tbl 推到下一级供后续调用接着用。

2、create_pgd_entry：把中间级一路串下去 #

armasm
.macro    create_pgd_entry, tbl, virt, tmp1, tmp2
    create_table_entry \tbl, \virt, PGDIR_SHIFT, PTRS_PER_PGD, \tmp1, \tmp2   // ①
#if SWAPPER_PGTABLE_LEVELS > 3                                                // ②
    create_table_entry \tbl, \virt, PUD_SHIFT, PTRS_PER_PUD, \tmp1, \tmp2     // ③
#endif
#if SWAPPER_PGTABLE_LEVELS > 2                                                // ④
    create_table_entry \tbl, \virt, SWAPPER_TABLE_SHIFT, PTRS_PER_PTE, \tmp1, \tmp2
#endif
.endm

名字叫 create_pgd_entry，干的活不止 PGD：所有中间级都建好，每级只填一项，只留最后一级的 PTE（或 section）给别人。② SWAPPER_PGTABLE_LEVELS 跟 ARM64_SWAPPER_USES_SECTION_MAPS 绑定，取 3 或取 2：

c
#if ARM64_SWAPPER_USES_SECTION_MAPS
#define SWAPPER_PGTABLE_LEVELS  (CONFIG_PGTABLE_LEVELS - 1)
#else
#define SWAPPER_PGTABLE_LEVELS  (CONFIG_PGTABLE_LEVELS)
#endif
#define SWAPPER_DIR_SIZE    (SWAPPER_PGTABLE_LEVELS * PAGE_SIZE)
#define IDMAP_DIR_SIZE      (IDMAP_PGTABLE_LEVELS * PAGE_SIZE)

三个例子对着看：

配置 级数 映射链 建几级
48 位 VA，4K 页（section） 4 PGD(L0) → PUD(L1) → PMD(L2) → section PGD + PUD
48 位 VA，16K 页（不 section） 4 PGD → PUD → PMD → PT(L3) → page PGD + PUD + PMD
39 位 VA，4K 页（section） 3 PGD(L1) → PMD(L2) → section 只有 PGD

3、create_block_map：填最后一级的 block 描述符 #

armasm
.macro    create_block_map, tbl, flags, phys, start, end
    lsr    \phys, \phys, #SWAPPER_BLOCK_SHIFT
    lsr    \start, \start, #SWAPPER_BLOCK_SHIFT
    and    \start, \start, #PTRS_PER_PTE - 1    // table index
    orr    \phys, \flags, \phys, lsl #SWAPPER_BLOCK_SHIFT // table entry
    lsr    \end, \end, #SWAPPER_BLOCK_SHIFT
    and    \end, \end, #PTRS_PER_PTE - 1        // table end index
9999:    str    \phys, [\tbl, \start, lsl #3]   // store the entry
    add    \start, \start, #1                   // next entry
    add    \phys, \phys, #SWAPPER_BLOCK_SIZE    // next block
    cmp    \start, \end
    b.ls    9999b
.endm

把 start~end 这段 VA 映射到从 phys 起的 PA，一块一项。三个细节：起止右移 SWAPPER_BLOCK_SHIFT（4K 页时是 21，即 2M 粒度）转索引；orr \flags 把内存属性并进物理地址；b.ls 是闭区间，end 那项也要填。顺手记 4.15 的改名：SWAPPER_BLOCK_SHIFT/SWAPPER_BLOCK_SIZE 早先叫 BLOCK_SHIFT/BLOCK_SIZE，SWAPPER_TABLE_SHIFT 叫 TABLE_SHIFT。

四、__create_page_tables 完整走读 #

版本：4.4.6。跟执行路径走一遍。

1、准备阶段 #

armasm
__create_page_tables:
    adrp    x25, idmap_pg_dir                        // ①
    adrp    x26, swapper_pg_dir
    mov    x27, lr

    mov    x0, x25                                   // ②
    add    x1, x26, #SWAPPER_DIR_SIZE
    bl    __inval_cache_range

    mov    x0, x25                                   // ③
    add    x6, x26, #SWAPPER_DIR_SIZE
1:    stp    xzr, xzr, [x0], #16
    stp    xzr, xzr, [x0], #16
    stp    xzr, xzr, [x0], #16
    stp    xzr, xzr, [x0], #16
    cmp    x0, x6
    b.lo    1b

    ldr    x7, =SWAPPER_MM_MMUFLAGS                  // ④

① adrp 按 4K 粒度算 PC 相对偏移，立即数 21 位，覆盖 ±4G，算出来的地址低 12 位是 0——链接脚本保证符号页对齐，所以够用。此刻 MMU 没开，adrp 拿到的是物理地址。② invalidate idmap_pg_dir 到 swapper_pg_dir + SWAPPER_DIR_SIZE，也就是启动页表那 6 页，理由第一章说过：boot 协议只保证 image 那段 clean 到 PoC。③ 清零的语义很省事：bit 0 是 valid 位，写 0 天然就是 invalid 描述符。④ 内存属性：

c
#if ARM64_SWAPPER_USES_SECTION_MAPS
#define SWAPPER_MM_MMUFLAGS    (PMD_ATTRINDX(MT_NORMAL) | SWAPPER_PMD_FLAGS)
#else
#define SWAPPER_MM_MMUFLAGS    (PTE_ATTRINDX(MT_NORMAL) | SWAPPER_PTE_FLAGS)
#endif
#define SWAPPER_PTE_FLAGS    (PTE_TYPE_PAGE | PTE_AF | PTE_SHARED)
#define SWAPPER_PMD_FLAGS    (PMD_TYPE_SECT | PMD_SECT_AF | PMD_SECT_S)

MT_NORMAL 说明这是普通内存。AF 是 access flag，标记这项被访问过：image 的页永远算 active，直接置 1。SH 配成 0b11 即 inner shareable——domain 里所有 bus master 访问这段是硬件保证一致的，软件不用管 cache。其余位都是 0：AP=0 表示 EL1 可读写、EL0 不许访问；nG=0 表示翻译是全局的、不分进程，内核页本来就该这样。（shareable 的位域图原文也丢了，结论就一句：SH[1:0] 的 0b11 是 inner shareable，0b10 是 outer，0b00 非共享。）

2、建立 identity mapping #

armasm
    mov    x0, x25                                  // ①
    adrp    x3, __idmap_text_start                  // ②

#ifndef CONFIG_ARM64_VA_BITS_48
#define EXTRA_SHIFT    (PGDIR_SHIFT + PAGE_SHIFT - 3)     // ③
#define EXTRA_PTRS    (1 << (48 - EXTRA_SHIFT))           // ④
#if VA_BITS != EXTRA_SHIFT
#error "Mismatch between VA_BITS and page size/number of translation levels"
#endif

    adrp    x5, __idmap_text_end                    // ⑤
    clz    x5, x5
    cmp    x5, TCR_T0SZ(VA_BITS)                    // ⑥
    b.ge    1f

    adr_l    x6, idmap_t0sz                         // ⑦
    str    x5, [x6]
    dmb    sy
    dc    ivac, x6

    create_table_entry x0, x3, EXTRA_SHIFT, EXTRA_PTRS, x5, x6   // ⑧
1:
#endif

    create_pgd_entry x0, x3, x5, x6                 // ⑨
    mov    x5, x3                // __pa(__idmap_text_start)
    adr_l    x6, __idmap_text_end                    // __pa(__idmap_text_end)

    create_block_map x0, x7, x3, x5, x6             // ⑩

① x0 指向 idmap 的 PGD，即 idmap_pg_dir 的物理地址。② x3 存 __idmap_text_start 的物理地址；idmap 的 VA 等于 PA，一个值两种身份都用。

③~⑧ 是「物理地址太高、VA 位宽不够」的补丁。48 位是 ARMv8 上限，扩不上去，所以整段被 #ifndef CONFIG_ARM64_VA_BITS_48 包着。没配 48 位时：clz x5, x5 数出物理地址的前导 0 个数，TCR_T0SZ(VA_BITS) 算出当前 VA 应有的前导 0 个数，前者更小就说明地址超出当前 VA 能表示的范围。

那个 #error 值得单独说。内核要求 PGD 是满的，也就是索引 PGD 的位数必须等于 PAGE_SIZE - 3：48 位 VA + 4K 页是 9+9+9+9+12，42 位 VA + 64K 页是 13+13+16，两者的 PGD 都恰好占满一页。正因为这条，扩出来之后 EXTRA_SHIFT 必然等于 VA_BITS，不等就是配置错；42 位 + 64K 扩到 48 位后映射链是 EXTRA(6-bit) + PGD(13-bit) + PTE(13-bit) + offset(16-bit)。

⑦ 需要的位宽通过 TCR_EL1.T0SZ 生效，但这时还不到写系统寄存器的时候（那在 __cpu_setup 里），所以只把值存进 idmap_t0sz 变量，__cpu_setup 会来取。⑨⑩ 建中间级，再填最后一级；最后一级是 page 还是 block 描述符，看配置。

3、建立 kernel image mapping（4.4.6 里叫 kernel direct mapping） #

armasm
    mov    x0, x26                // ① swapper_pg_dir
    mov    x5, #PAGE_OFFSET       // ②
    create_pgd_entry x0, x5, x3, x6          // ③
    ldr    x6, =KERNEL_END        // __va(KERNEL_END)
    mov    x3, x24                // phys offset
    create_block_map x0, x7, x3, x5, x6      // ④

    mov    x0, x25                // ⑤ 收尾：再 invalidate 一次
    add    x1, x26, #SWAPPER_DIR_SIZE
    dmb    sy
    bl    __inval_cache_range

    mov    lr, x27
    ret

① swapper_pg_dir 就是 swapper（pid 0，即 idle）的地址空间，内核空间全局只有这一份 PGD。② 4.4.6 里 PAGE_OFFSET 是线性区起点，48 位 VA 下为 0xffff800000000000；image 落在 PAGE_OFFSET + TEXT_OFFSET，所以这里从 PAGE_OFFSET 一路映射到 KERNEL_END，多出来的 TEXT_OFFSET 那一截就是 image 前的保留区。③④ 建中间级，再一段段填 block，物理侧从 x24（phys offset）开始跟。⑤ 填完再 invalidate 一次，理由和开头对称：这期间写过页表，那些 cacheline 现在是脏的，而 MMU 一开就直接从内存读页表。4.15 里这段换了面孔：mov_q x5, KIMAGE_VADDR + TEXT_OFFSET 然后 add x5, x5, x23，x23 就是 KASLR 偏移，第十六章看。

五、turn on MMU：.idmap.text 与两次映射 #

页表填完，剩下的事交给 __enable_mmu 和 __primary_switch：

步 动作 为什么
1 TTBR0_EL1 ← idmap_pg_dir 低半区（用户 + idmap）走 TTBR0
2 TTBR1_EL1 ← swapper_pg_dir 高半区内核空间走 TTBR1
3 设 TCR_EL1、MAIR_EL1 翻译粒度、内存属性；T0SZ 取 __cpu_setup 从 idmap_t0sz 读出的值
4 isb，然后 msr sctlr_el1 置 M=1 从这一条起 PC 已被翻译
5 isb，然后 br x27 冲刷流水线，丢掉按物理地址预取的指令

第 4、5 步之间是全链最脆的一段。br x27 里的地址是链接时的虚拟地址，MMU 一开，这个 VA 必须翻译到正确的 PA，否则当场跑飞。靠的就是 identity mapping：.idmap.text 那段 VA 数值上等于 PA，翻译前后指向同一块内存，哪怕流水线里混着两种理解也不出事。ARM 强推荐 idmap，原因就在这几十纳秒里——少了 isb，后面几条指令还在用旧翻译上下文执行。从核走另一条路，但复用同一份页表，同样在 .idmap.text 里，同样靠 idmap 过渡。

4.15 把 idmap 收窄到只覆盖 .idmap.text（4.1.10 那会儿是整个 image，见 ARM64 内核启动与页表建立）。收窄的代价是：任何被塞进这个 section 的函数都得掂量，它在 MMU 开前后的语义必须一致——__primary_switch 里那句 adrp x0, __PHYS_OFFSET 之所以能把虚拟地址当物理用，就因为它在里面。

六、进 C 之后第一件事：early fixmap #

版本：4.4.6。

MMU 开了，sp 有了，BSS 清了，setup_arch 抬眼一看，能访问的还是只有 image 那一段。DTB 的地址是 x0 传进来的物理地址，读不了。于是有个环：要读 DTB 得先建映射，建映射缺页表内存，而伙伴系统没起来，连系统里有多少内存都不知道。答案偏偏就在要读的那个 DTB 里——memory 节点描述了物理内存布局。

破法：PGD 直接用现成的 swapper_pg_dir，剩下三张表在 bss 里静态定好。

c
static pte_t bm_pte[PTRS_PER_PTE] __page_aligned_bss;
static pmd_t bm_pmd[PTRS_PER_PMD] __page_aligned_bss __maybe_unused;
static pud_t bm_pud[PTRS_PER_PUD] __page_aligned_bss __maybe_unused;

void __init early_fixmap_init(void)
{
	pgd_t *pgd;
	pud_t *pud;
	pmd_t *pmd;
	unsigned long addr = FIXADDR_START;

	pgd = pgd_offset_k(addr);
	if (pgd_none(*pgd))
		__pgd_populate(pgd, __pa_symbol(bm_pud), PUD_TYPE_TABLE);
	pud = fixmap_pud(addr);
	if (pud_none(*pud))
		__pud_populate(pud, __pa_symbol(bm_pmd), PMD_TYPE_TABLE);
	pmd = fixmap_pmd(addr);
	__pmd_populate(pmd, __pa_symbol(bm_pte), PMD_TYPE_TABLE);

	BUILD_BUG_ON((__fix_to_virt(FIX_BTMAP_BEGIN) >> PMD_SHIFT) !=
		     (__fix_to_virt(FIX_BTMAP_END) >> PMD_SHIFT));
	...
}

三张表都是 __page_aligned_bss，在 image 里，image 可见所以能直接写。PGD 复用意味着整个系统只有一份内核 PGD。那个 BUILD_BUG_ON 盯的是 FDT 区和 BTMAP 区必须落在同一张 PMD 表里，做不到就得再要一页，而这时候要不到。代价随之定死：一张 PMD 表 512 项 × 4K，fixmap 只能覆盖 2M。「DTB 不能大于 2M」这条要求的真实来源在这儿——不是规范，是页表只建到这一级。

建好表才能映射 DTB。__fixmap_remap_fdt() 里三行关键代码：BUILD_BUG_ON(dt_virt_base % SZ_2M) 要求 FIX_FDT 2M 对齐（FIX_FDT 排在枚举最前面就是为这个）；offset = dt_phys % SWAPPER_BLOCK_SIZE 把 DTB 在 2M 块内的偏移搬到虚拟侧，于是「映射 2M」跟 DTB 真实起点无关；先只映射 2M，offset + *size 越过才补第二段，而多数 DTB 就几十 KB。函数末尾还有一句 memblock_reserve(dt_phys, size)，防止这段内存被分配出去。

一句版本旁注。旧方案是把 DTB 塞在 image 起始 512M 内、8 字节对齐、不跨 2M，然后借 image 的页表加一项了事，位置校验还得在 asm 里写。fixmap 把校验和建表都搬进了 C，bootloader 终于可以随便放 DTB。

七、fixmap 是什么，为什么地址在编译期固定 #

版本：4.4.6。

fixmap 的 fix，固定的是虚拟地址。物理地址不固定，运行时才定。为什么非要固定 VA？因为伙伴系统 ready 之前，内核没有能力分配虚拟地址。注意区别：memblock 能给你物理页，给不了虚拟地址——VA 的管理归 vmalloc 那套，它依赖 vmap_area 记账，记账要靠 slab，slab 要靠伙伴系统。链条太长。

所以干脆在编译期划一段 VA，谁需要谁去填描述符：

c
#define __fix_to_virt(x)  (FIXADDR_TOP - ((x) << PAGE_SHIFT))
#define __virt_to_fix(x)  ((FIXADDR_TOP - ((x) & PAGE_MASK)) >> PAGE_SHIFT)

index 越大地址越低。这个方向容易记反，FIX_BTMAP_BEGIN 和 FIX_BTMAP_END 的数值大小关系就是靠它解释。区域在 FIXADDR_START 和 FIXADDR_TOP 之间，按 4.15 的真实 dump 看，fixed 那一段夹在 vmalloc 之下、PCI I/O 之上，39 位 VA 下是 0xffffffbefe7fb000~0xffffffbefec00000、4116K（原文这里也丢过一张布局图，这是补上的等价信息）。

槽位在枚举里定死，分界线是 __end_of_permanent_fixed_addresses：

八、fixmap 用在哪：DTB、early ioremap、debug uart #

版本：4.4.6。permanent 三项：DTB（顺序不能反，early_fixmap_init() 先建三张表，__fixmap_remap_fdt() 才往 FIX_FDT 里填描述符，反了就是往不存在的页表里写）、early console（走 early_param 注册，parse_early_param 之后就能出字，调试卡在 setup_arch 的内核时这条输出往往是唯一线索，earlycon=uart8250,mmio,0x... 就是给它用的）、text poke（正文只读，改代码得临时搞一条可写映射，改完再撤）。

temporary 是 early ioremap，7 个 slot，每个 256K：

c

{
	int i;

	for (i = 0; i < FIX_BTMAPS_SLOTS; i++)
		slot_virt[i] = __fix_to_virt(FIX_BTMAP_BEGIN - NR_FIX_BTMAPS * i);
}

用起来和 ioremap 一个样：early_ioremap(reg_phys, SZ_4K) 拿指针，readl/writel 读写，early_iounmap(base, SZ_4K) 还。三条纪律：必须成对，漏一次那个 slot 就一直被占着、不报错只会在别处挂；同时最多 7 段、单段不超 256K；early_ioremap_init() 之后才能用，它比 early_fixmap_init() 晚，还依赖后者把表建好。

两者的差别只在「页表从哪来」：前者用静态躺好的，后者缺页表时找伙伴系统。结论一句：伙伴系统之前要碰设备寄存器，用 early ioremap。early_iounmap 之后那个 VA 会被人拿去映射别的物理地址，跨它保住任何指针都是定时炸弹。

「近似子集」这个措辞是有意的。memblock_reserve() 只在 reserved 里加一段，不动 memory；而 memblock_remove() 从两个数组里都摘掉，带 no-map 的 reserved-memory 走的就是 remove——那段内存对 OS 根本不存在，也不建映射。所以 reserved 里每段都能在 memory 里找到（除非被 remove 过），反过来不成立。flags 给 MEMBLOCK_NOMAP 这类标记用；nid 只有开 NUMA 才存在，early_init_dt_add_memory_arch 加内存时把节点号带进来——这是内存模型里 node 概念的源头。

memblock_alloc 不维护自由页位图，而是拿 memory 减 reserved 现算：慢，但简单，只适合启动阶段。还有一条容易踩：memblock 里全是物理地址，reg->base 不能直接解引用，得先 __va()——而 __va() 要成立，那段内存必须已有映射。这条约束在第十三章会把 map_mem 逼出一套特别写法。

十、memory region 怎么建起来 #

版本：4.4.6。这一步的产物就是 memblock.memory。

c
void __init early_init_dt_scan_nodes(void)
{
	of_scan_flat_dt(early_init_dt_scan_chosen, boot_command_line);  // ①
	of_scan_flat_dt(early_init_dt_scan_root, NULL);                 // ②
	of_scan_flat_dt(early_init_dt_scan_memory, NULL);               // ③

① 每个节点都回调一次 early_init_dt_scan_chosen。为什么这么笨？因为 DTB 还没展开成 device_node 树，只能顺着扁平结构扫。② 读 root 的 #address-cells/#size-cells，填进 dt_root_addr_cells/dt_root_size_cells——这两个不是常量，后面解析 reg 要靠它。③ 找 memory 节点。

memory 回调的核心：

		if (!IS_ENABLED(CONFIG_PPC32) || depth != 1 || strcmp(uname, "memory@0") != 0)
			return 0;

十一、reserved region 怎么建起来 #

版本：4.4.6。保留动作分散在几处，按代码顺序看。

① DTB 自己。第六章末尾那句 memblock_reserve(dt_phys, size)。必须保留，否则后面页表内存会分配到 DTB 头上。

② image 和 initrd：

{

③ 扫 /memreserve/ 和 reserved-memory：

c
void __init early_init_fdt_scan_reserved_mem(void)
{

回调 __fdt_scan_reserved_mem 先找本体（depth == 1、名字对得上），找到后校验它带 #address-cells/#size-cells/ranges 且前两个值和 root 一致；扫完所有子节点、depth 退回 1 以下时返回 1 结束扫描。每个子节点：status 可有可无，有就必须是 okay/ok；有 reg 的是静态定义，走 __reserved_mem_reserve_reg()——它看有没有 no-map，有就 memblock_remove()，无就 memblock_reserve()，这个差别在第十三章变成「这段内存建不建映射」；只有 size 的是动态定义，err == -ENOENT 时调 fdt_reserved_mem_save_node() 存进 reserved_mem[]，分配推到下一步。

④ 落实动态定义的那些。fdt_init_reserved_mem() 做四件事：__rmem_check_for_overlap() 查静态 region 有无重叠（有只报错、不改 base/size）；取 phandle 供别的节点引用；size == 0 的调 __reserved_mem_alloc_size() 按 size/alignment/alloc-ranges 算好再分配，把这页从 memory 挪到 reserved；最后 __reserved_mem_init_node()——要么等驱动 probe，要么靠 RESERVEDMEM_OF_DECLARE 在启动期就绪（CMA、per-device coherent DMA 走这条）。

⑤ CMA。arm64_memblock_init → dma_contiguous_reserve 按命令行参数留 CMA 内存，这块留给 CMA 那篇。走完这五步，memblock.memory 是全集，memblock.reserved 是所有不能碰的段，两者一减就是内核真正能用的物理内存。

十二、memblock 到伙伴系统的交接 #

memblock 是临时的，结构体本身标着 __initdata_memblock——账本自己也要被算账。顺序：paging_init 建映射（两数组不动）→ free_area_init_nodes 按 region 算出每个 node/zone 的 present_pages、建 struct page 数组（仍在用 memblock 遍历）→ mem_init 把「memory 减 reserved」整块还给伙伴系统（开始退场）→ free_all_bootmem 之下逐段释放、跳过 reserved（分配职能移交）→ 之后只有 memblock_alloc 的极少数晚期调用还会用一下，__init 段回收后账本消失。

判据很简单：reserved 里的东西永远不进伙伴系统，启动阶段提前 reserve 的那些段（image、DTB、页表、no-map 区）天然不会被别人分配走。

顺序陷阱单独记：free_area_init_nodes 要给每页建 struct page，而 vmemmap 数组自己也要占内存。4.4.6 的 ARM64 上 vmemmap 是一段虚拟区域，背后物理页由 memblock 分配，所以它必须发生在 free_area_init_nodes 之前，并且这时映射必须已经建好。这也是 map_mem 要把整段内存先映射出来的原因之一。

十三、paging_init：为系统内存正式建映射 #

版本：4.4.6。到这里全局只有三段可见：image、DTB、fixmap 那 2M。剩下几 G 在黑暗里，paging_init → map_mem 负责点亮。

先说悖论：建映射要页表内存，页表内存要 memblock_alloc，而 memblock_alloc 返回的物理页要能访问就得先有映射。解法不是「先分配再映射」，而是控制顺序，让要分配的页表内存严格落在已映射的物理范围内。

c
static void __init map_mem(void)
{
	struct memblock_region *reg;
	phys_addr_t limit;

	limit = PHYS_OFFSET + SWAPPER_INIT_MAP_SIZE;          // ①
	memblock_set_current_limit(limit);

	for_each_memblock(memory, reg) {                       // ②
		phys_addr_t start = reg->base;
		phys_addr_t end = start + reg->size;

		if (start >= end)
			break;

		if (ARM64_SWAPPER_USES_SECTION_MAPS) {          // ③
			if (start < limit)
				start = ALIGN(start, SECTION_SIZE);
			if (end < limit) {
				limit = end & SECTION_MASK;
				memblock_set_current_limit(limit);
			}
		}

		__map_memblock(start, end);                     // ④
	}

	memblock_set_current_limit(MEMBLOCK_ALLOC_ANYWHERE);   // ⑤
}

① 给 memblock_alloc 划上限 [PHYS_OFFSET, PHYS_OFFSET + SWAPPER_INIT_MAP_SIZE)，这段的页表全是第四章静态建好的，往里填描述符不需要分配。② 遍历所有 memory region 建映射，reserved 是 memory 的子集，所以保留区的映射顺带也建了——注意是「建映射」，不是「允许分配」。③ 给 section mapping 打的补丁：第一个 memory block 的 start 必定 2M 对齐（image 在那儿），end 不一定；end 没对齐就没法整块 section mapping，create_mapping 会退化成分配 PTE 页，所以把 limit 缩到 end & SECTION_MASK。④ 真正建映射：create_mapping(start, __phys_to_virt(start), end - start, PAGE_KERNEL_EXEC)。⑤ 全部完事，解除上限。

map_mem 之后，第四章那些描述符全被覆盖，属性换成 __pgprot(_PAGE_DEFAULT | PTE_UXN | PTE_DIRTY | PTE_WRITE)。MT_NORMAL、PTE_AF、PTE_SHARED 跟原来一样，新加三个：PTE_UXN 是 Unprivileged Execute-never，禁止 EL0 从这里取指；PTE_DIRTY 是纯软件位，硬件不碰，回收时据此判断要不要回写；PTE_WRITE 是可写，跟 ARMv8 的 AP 位配合，怎么算见 ARM64 地址翻译与页表宏定义。

DTB 里那些 no-map 的段依旧不可见——它们在第十一章被 memblock_remove 掉了，压根不在这轮 for_each_memblock(memory, ...) 里。

	unsigned long addr, length, end, next;

	addr = virt & PAGE_MASK;                        // ①
	length = PAGE_ALIGN(size + (virt & ~PAGE_MASK));

	end = addr + length;
	do {                                            // ②
		next = pgd_addr_end(addr, end);          // ③
		alloc_init_pud(mm, pgd, addr, next, phys, prot, alloc); // ④
		phys += next - addr;
	} while (pgd++, addr = next, addr != end);
}

init_mm 是内核空间的 mm_struct；pgd_offset_k(virt) 找到 VA 对应的 PGD 项；early_alloc 是「缺页表内存时调谁」。那个 virt < VMALLOC_START 检查不是摆设，它是唯一一道门——低于它就等于往用户空间建内核映射，直接拒。① 对齐到页，(addr, length) 是包住 (virt, size) 的最小页对齐范围。② 一段 VA 会跨多个 PGD 项。③ pgd_addr_end 算出当前 PGD 项能覆盖到哪。④ 交给下一级，顺便把物理指针往前推。

c
static void alloc_init_pud(struct mm_struct *mm, pgd_t *pgd,
			   unsigned long addr, unsigned long end,
			   phys_addr_t phys, pgprot_t prot,
			   void *(*alloc)(unsigned long size))
{
	pud_t *pud;
	unsigned long next;

	if (pgd_none(*pgd)) {                                  // ①
		pud = alloc(PTRS_PER_PUD * sizeof(pud_t));
		pgd_populate(mm, pgd, pud);
	}

	pud = pud_offset(pgd, addr);                           // ②

	do {                                                   // ③
		next = pud_addr_end(addr, end);

		if (use_1G_block(addr, next, phys)) {          // ④
			pud_t old_pud = *pud;
			set_pud(pud, __pud(phys | pgprot_val(mk_sect_prot(prot)))); // ⑤

			if (!pud_none(old_pud)) {               // ⑥
				flush_tlb_all();                // ⑦
				if (pud_table(old_pud)) {
					phys_addr_t table = __pa(pmd_offset(&old_pud, 0));
					if (!WARN_ON_ONCE(slab_is_available()))
						memblock_free(table, PAGE_SIZE); // ⑧
				}
			}
		} else {
			alloc_init_pmd(mm, pud, addr, next, phys, prot, alloc);
		}

		phys += next - addr;
	} while (pud++, addr = next, addr != end);
}

① PGD 项是空的，说明还没有 PUD 表，要一页再 pgd_populate；这一刻伙伴系统没起来，alloc 走 memblock。② 定位 addr 落在 PUD 表哪一项。③ 一个 PGD 项下会有多个 PUD 项。④ 能不能用 1G block：4K 页配置下 PUD 项覆盖 1G，且起止 VA 和对应的 PA 都要 1G 对齐。⑤ 能就一行画完 1G，没有 PMD、没有 PTE；4G 内存对齐在 1G 上的话，四个 PUD 项就画完整个线性区。

⑥⑦⑧ 是清旧账。早期 __create_page_tables 在这附近填过 PUD/PMD，现在换成 block 描述符，旧账得清：⑥ 旧项非空；⑦ 新页表建了，旧翻译还赖在 TLB 里，flush_tlb_all() 清干净；⑧ 旧项是 table 类型说明它指向一张 PMD 表，那页可以还了。slab_is_available() 那个 WARN_ON_ONCE 意思是：slab 已经能用的话，这条释放路径就不该再走（说明映射重建发生得太晚）。

c
static void alloc_init_pmd(struct mm_struct *mm, pud_t *pud,
			   unsigned long addr, unsigned long end,
			   phys_addr_t phys, pgprot_t prot,
			   void *(*alloc)(unsigned long size))
{
	pmd_t *pmd;
	unsigned long next;

	if (pud_none(*pud) || pud_sect(*pud)) {                  // ①
		pmd = alloc(PTRS_PER_PMD * sizeof(pmd_t));
		if (pud_sect(*pud)) {                           // ②
			split_pud(pud, pmd);
		}
		pud_populate(mm, pud, pmd);                     // ③
		flush_tlb_all();
	}
	BUG_ON(pud_bad(*pud));

	pmd = pmd_offset(pud, addr);                            // ④
	do {
		next = pmd_addr_end(addr, end);
		if (((addr | next | phys) & ~SECTION_MASK) == 0) { // ⑤
			pmd_t old_pmd = *pmd;
			set_pmd(pmd, __pmd(phys | pgprot_val(mk_sect_prot(prot))));
			if (!pmd_none(old_pmd)) {               // ⑥
				flush_tlb_all();
				if (pmd_table(old_pmd)) {
					phys_addr_t table = __pa(pte_offset_map(&old_pmd, 0));
					if (!WARN_ON_ONCE(slab_is_available()))
						memblock_free(table, PAGE_SIZE);
				}
			}
		} else {
			alloc_init_pte(pmd, addr, next, __phys_to_pfn(phys),
				       prot, alloc);
		}

		phys += next - addr;
	} while (pmd++, addr = next, addr != end);
}

static void alloc_init_pte(pmd_t *pmd, unsigned long addr,
			   unsigned long end, unsigned long pfn,
			   pgprot_t prot,
			   void *(*alloc)(unsigned long size))
{
	pte_t *pte;

	if (pmd_none(*pmd) || pmd_sect(*pmd)) {                 // ⑦
		pte = alloc(PTRS_PER_PTE * sizeof(pte_t));
		if (pmd_sect(*pmd))
			split_pmd(pmd, pte);                    // ⑧
		__pmd_populate(pmd, __pa(pte), PMD_TYPE_TABLE);  // ⑨
		flush_tlb_all();
	}
	BUG_ON(pmd_bad(*pmd));

	pte = pte_offset_kernel(pmd, addr);
	do {
		set_pte(pte, pfn_pte(pfn, prot));               // ⑩
		pfn++;
	} while (pte++, addr += PAGE_SIZE, addr != end);
}

① 两种情形要 PMD 表：PUD 项是空的；或 PUD 项是 1G section 而现在要改它。② 旧的是 1G section 时，split_pud 把它拆成 512 个 2M section——一个 PUD 描述符换 512 个 PMD 描述符，覆盖范围不变，粒度变细。③ 让 PUD 项指向新表，清 TLB。④ 循环逻辑和上一级同构。⑤ 三个地址都 2M 对齐才能用 2M section。⑥ 旧的若是 table 类型，那张 PTE 表可以还了。

⑦ 走到这儿说明要往 4K 粒度落。⑧ 有 2M section 就拆成 512 个 page 描述符。⑨ 让 PMD 项指向新 PTE 表，注意那个区别：PMD 项原本是空的话，新表 512 项全 invalid；原本是 section 的话，split_pmd 已经填好 512 项。⑩ 一页一项，pfn 递增。

整条链是按需分配、能省就省：4K 页且地址都 1G 对齐时走 PUD section，每 1G 一句 set_pud，页表页数 0；2M section 可用时走 PMD section，每 1G 一张 PMD 表；真要 4K 粒度才落到 PTE page，每 2M 一张 PTE 表。所以一个 4G、1G 对齐的系统，map_mem 只花四个 PUD 项——不只省内存，TLB miss 也少一大截。

十五、KASLR：随机化的到底是什么 #

版本：4.15。

先把误解掐掉。KASLR 随机化的不是物理地址，也不是页表结构，而是内核 image 在虚拟地址空间里落哪。物理上 image 还是那块 DRAM，虚拟侧挪一段。为什么值得挪？内核里 gadget 的地址是攻击者的第一需求，地址固定，ROP 链可以写死。

随机的是两样东西，原稿在注释里一带而过：

对象 随机源 影响什么 约束
image 偏移 offset DTB chosen/kaslr-seed .text 的起始虚拟地址 2M 对齐；不超 2^(VA_BITS-2)；不跨 PUD
线性区起点 同一个 seed 的高 16 位 memstart_addr，物理内存被摆到线性区的哪一段 1G 对齐；线性区要装得下全部物理内存

随机源由 bootloader 塞进 DTB：

dts
/ {
    chosen {
        kaslr-seed = <0x10000000>;
    };
};

kaslr-seed 是 64 位值。没有这个属性，kaslr_early_init 返回 0，内核照链接地址跑。命令行可以一票否决：nokaslr，匹配规则很土但严格，必须出现在行首或空格之后，mynokaslr 不生效。

十六、kaslr_early_init 逐行分析 #

版本：4.15。原稿零标题、纯代码加注释，这里拆开。

c
u64 __init kaslr_early_init(u64 dt_phys)
{
	void *fdt;
	u64 seed, offset, mask, module_range;
	const u8 *cmdline, *str;
	int size;

	early_fixmap_init();                                         /* 1 */
	fdt = __fixmap_remap_fdt(dt_phys, &size, PAGE_KERNEL);       /* 2 */

	seed = get_kaslr_seed(fdt);                                  /* 3 */

	if (!seed)
		return 0;

	cmdline = get_cmdline(fdt);

	str = strstr(cmdline, "nokaslr");                            /* 4 */

	if (str == cmdline || (str > cmdline && *(str - 1) == ' '))
		return 0;

	mask = ((1UL << (VA_BITS - 2)) - 1) & ~(SZ_2M - 1);          /* 5 */

	offset = seed & mask;

	/* use the top 16 bits to randomize the linear region */

	memstart_offset_seed = seed >> 48;                           /* 6 */

	if ((((u64)_text + offset) >> SWAPPER_TABLE_SHIFT) !=
	    (((u64)_end + offset) >> SWAPPER_TABLE_SHIFT))
		offset = round_down(offset, 1 << SWAPPER_TABLE_SHIFT);   /* 7 */

	return offset;
}
  • 1 early_fixmap_init() 执行的时刻比名字暗示的早得多：它在 kaslr_early_init 里，而后者被 __primary_switched 调，那时 start_kernel 还没进。第七章那些静态 bm_pud/bm_pmd/bm_pte 就是为了这一刻。
  • 2 __fixmap_remap_fdt() 把物理的 DTB 地址映射到 FIX_FDT，形状和第六章一样。
  • 3 get_kaslr_seed() 从 chosen 取 kaslr-seed，取不到就是 0。

4 认 nokaslr。strstr 找到子串后还得判边界：str == cmdline 是行首，*(str-1) == ' ' 是前有空格，于是 nokaslr 和 foo nokaslr 都拦得住，xnokaslr 拦不住。

5 算掩码，(1UL << (VA_BITS-2)) - 1 取低 VA_BITS-2 位，& ~(SZ_2M - 1) 保证 2M 对齐，VA_BITS=48 时是 0x0000_3fff_ffe0_0000。原稿把这句注释解释成「位于 VMALLOC 区域大小的一半以下」，按宏算其实是 VA 空间的 1/4——VA_BITS-1 才是「一半」（线性区大小），再减一即 VA_BITS-2。措辞对不上，数值本身没错，见附录。

  • 6 线性区也随机。seed >> 48 存进 memstart_offset_seed，后面影响 memstart_addr。
  • 7 不让 image 跨 PUD：判断 _text + offset 和 _end + offset 是否落在同一个 SWAPPER_TABLE_SHIFT 区段，不是就往下对齐。原因很硬——__create_page_tables 启动时只准备了一张 PUD 表，想跨就得再要一张，而那时没有分配器。

调用点在 __primary_switched：

armasm
__primary_switched:

	tst	x23, ~(MIN_KIMG_ALIGN - 1)	// already running randomized?
	b.ne	0f

	mov	x0, x21				// pass FDT address in x0
	bl	kaslr_early_init		// parse FDT for KASLR options

	cbz	x0, 0f				// KASLR disabled? just proceed

	orr	x23, x23, x0			// record KASLR offset

	ldp	x29, x30, [sp], #16		// we must enable KASLR, return
	ret					// to __primary_switch()

x23 是后半程一直带着的偏移。tst + b.ne 防重入：MIN_KIMG_ALIGN 是 image 最小对齐，~(MIN_KIMG_ALIGN - 1) 取高位部分，非零说明 x23 已经带了偏移，别算第二遍。用 orr 不用 mov，是把它「或」进 x23 的低位，靠对齐保证两者不重叠。

x23 最终落到建表代码里。4.15 的版本：

armasm
__create_page_tables:
    adrp	x0, swapper_pg_dir

    mov_q	x5, KIMAGE_VADDR + TEXT_OFFSET  // compile time __va(_text)
    add	x5, x5, x23                         // add KASLR displacement

    create_pgd_entry x0, x5, x3, x6

    adrp	x6, _end                        // runtime __pa(_end)
    adrp	x3, _text                       // runtime __pa(_text)
    sub	x6, x6, x3                          // _end - _text
    add	x6, x6, x5                          // runtime __va(_end)

    create_block_map x0, x7, x3, x5, x6

原稿说「注意第 7 行」，但那是原稿代码块里的 adrp x0, swapper_pg_dir；真正加上偏移的是 add x5, x5, x23（原稿代码块第 11 行，本文压掉空行后更靠前）。行号偏差不影响结论：x3 拿 _text 的运行时物理地址，x6 拿 _end 的物理值，相减得 image 物理长度，再加到带偏移的虚拟起点上得虚拟终点。物理起点不随 offset 变——这就是「随机化虚拟地址」的直接证据。

重定位。x23 一进来，链接时定死的符号全体错位：_text、_etext、_end 的值在链接时确定，现在运行时比它们多 offset，任何通过符号取绝对地址的代码都会拿到旧值。修这件事的是 __relocate_kernel（arch/arm64/kernel/head.S），它把 .rela 段的重定位项逐条应用，让按符号算出来的地址重新对上运行时地址。只需记住：KASLR 下访问符号地址必须走重定位后的值。

最后是 oops 的处理。log 里的函数地址是运行时地址，addr2line 要吃链接地址：

十七、KASLR 与内存布局的相互制约 #

这两件事互为约束，谁也不能随便改：

约束 谁提出 对另一方的限制
启动只建一张 PUD __create_page_tables offset 必须让 image 落在同一 PUD 内，第十六章第 7 行守这条
offset 2M 对齐 section mapping 随机粒度只到 2M，再细就退化成 page mapping
image 在 KIMAGE_VADDR 4.15 布局宏 KIMAGE_VADDR == VMALLOC_START == MODULES_END，image 和 vmalloc 抢高位
线性区恰占 VA 空间一半 linear_region_size = -(s64)PAGE_OFFSET __is_lm_address 才能用一个 bit 判定，BUILD_BUG_ON 锁死
memstart_addr 1G 对齐 ARM64_MEMSTART_ALIGN 线性区随机化只到这个粒度
线性区装下全部物理内存 数学 超了就得从 RAM 末尾倒推基址，并把低端 remove 掉 
c
void __init arm64_memblock_init(void)
{
	const s64 linear_region_size = -(s64)PAGE_OFFSET;

	BUILD_BUG_ON(linear_region_size != BIT(VA_BITS - 1));      // ①

	memstart_addr = round_down(memblock_start_of_DRAM(),       // ②
				   ARM64_MEMSTART_ALIGN);

	memblock_remove(max_t(u64, memstart_addr + linear_region_size,  // ③
			      __pa_symbol(_end)), ULLONG_MAX);
	if (memstart_addr + linear_region_size < memblock_end_of_DRAM()) {
		memstart_addr = round_up(memblock_end_of_DRAM() - linear_region_size,
					 ARM64_MEMSTART_ALIGN);    // ④
		memblock_remove(0, memstart_addr);                     // ⑤
	}
}

① 编译期锁死「线性区 = VA 空间一半」，这是 __is_lm_address 单 bit 判定的前提。② 物理起点按 1G 对齐，对齐后的起点就是线性区的锚。③ 把线性区覆盖不到的高端物理内存摘掉——反正映射不了。④⑤ 物理内存太大、线性区装不下时，改成从 RAM 末尾倒推，再把低端 [0, memstart_addr) 摘掉，副作用很直白：低端那截物理内存内核用不了，这是位宽不够的代价。

换算关系跟着分成两路：__is_lm_address(addr) 看 bit(VA_BITS-1)，为 1 走线性区减 PAGE_OFFSET，为 0 走 image 区减 kimage_voffset。而 kimage_voffset 本身是运行时算的：

armasm
ENTRY(kimage_vaddr)
	.quad	_text - TEXT_OFFSET

__primary_switched:
	ldr_l	x4, kimage_vaddr	// 编译期的 image 虚拟地址
	sub	x4, x4, x0		// x0 = __PHYS_OFFSET（物理）
	str_l	x4, kimage_voffset, x5
	b	start_kernel

这是 KASLR 逼出来的一笔账：虚拟地址随机了，物理地址没变，两者的差只能运行时存起来。老内核里 __virt_to_phys 一句宏的事，4.15 之后得先判走哪条路，再减不同的基。

整条链的形状是三次「以映射换映射」：静态 6 页页表换一个能跑的世界，代价是虚拟世界只剩两段可见；fixmap 的 3 张静态表加 2M 槽位换看见 DTB，代价是 fixmap 总容量锁死在 2M；memblock_alloc 分页表换看见全部内存，代价是分配范围被限在 SWAPPER_INIT_MAP_SIZE 内。

十九、易错点速查 #

  • create_table_entry 的下一级表地址是硬编码的。add \tmp2, \tbl, #PAGE_SIZE 假定页表连续摆放，改 IDMAP_DIR_SIZE/SWAPPER_DIR_SIZE 就得同时改链接脚本。
  • idmap 的 VA 等于 PA，是要求不是巧合。.idmap.text 里的代码在 MMU 开关那一瞬间被两种翻译解释，必须是同一块内存。
  • 清零就是置无效。bit0 是 valid 位，stp xzr 那串不需要额外构造 invalid 描述符；启动页表要 invalidate 两次，中间有 dmb sy。
  • 4K 页 + section mapping 时 PAGE_OFFSET 必须 2M 对齐，create_block_map 的索引算法依赖它。
  • b.ls 是闭区间。create_block_map 里 end 那项也会被填，等价 C 代码别写成 while (start != end)。
  • fixmap 只有 2M。只静态建到 PMD 一级，一张 PMD 表 512 项 × 4K，DTB 的 2M 上限就是这么来的。
  • FIX_BTMAP_BEGIN 数值比 FIX_BTMAP_END 大，地址却更低。__fix_to_virt 是减法；永久槽位和临时槽位不能互借。
  • early_ioremap 必须成对。漏一次 early_iounmap，7 个 slot 就少一个，且不报错，只在别处挂。
  • memblock 里全是物理地址。reg->base 不能直接解引用，要先 __va()；而 __va() 成立的前提是那段已有映射。
  • memblock_reserve 和 memblock_remove 不等价。前者只在 reserved 记一笔，后者从两个数组里都摘掉，no-map 走后者。
  • map_mem 的 limit 是防死锁的。不设 limit，memblock_alloc 会给一个还没映射的物理页，内核一写就飞。
  • if (start >= end) break; 用的是 break。原稿如此，看着像该写 continue，但 region 列表有序，后面只会更小，break 说得通。
  • 大页优先不是优化，是省页表。use_1G_block 成立时连 PMD/PTE 表都不用分配，TLB 压力也小。
  • KASLR 随机化的是虚拟地址。物理地址不动，所以 __virt_to_phys 从一句宏变成两条分支，靠 bit(VA_BITS-1) 分流。
  • kaslr-seed 缺失等于关 KASLR；oops 地址不能直接喂 addr2line，要先按 .text 起点和 TEXT_OFFSET 折回链接地址。
