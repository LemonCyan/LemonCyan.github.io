平台与版本边界：S3C2440/S3C2410，ARMv4T，单核。文中 ARM64、GIC-v2/v3、层级化 irq_domain 只是旁证，别拿本篇代码去套。2.6.x 与 3.x 两个区间里 handle_level_irq 的签名和状态位字段名不一样，遇到我停下来标清楚。

一、裸机中断与 Linux 中断的差别 #

以 Mini2440 按键 K1 走 EINT8 为例。裸机程序干这几件事：配管脚复用为 EINT8 并配触发方式；清 EINTPND 对应位；写 EINTMASK 打开这一路；写 INTMSK 打开 EINT8_23 主中断源；写 CPSR 清 I 位开 IRQ 总中断。

按键按下后硬件把 SRCPND、INTPND 对应位置 1，拉高 IRQ 线，CPU 跳到 0x18：

armasm
    stmdb   sp!, {r0-r12, lr}      @ 保护现场
    bl      key_isr                @ 中断处理函数
    ldmia   sp!, {r0-r12, lr}      @ 恢复现场
    subs    pc, lr, #4             @ 返回

完事。整个路径两层：硬件 + 你的 ISR，全在你手里。

Linux 把这条路拆了。CPU 跳到 0x18 后先落内核向量表，经汇编存现场，再进 C 代码。此时手里只有硬件中断号，不知道调谁。要经中断域翻成 IRQ 编号，查 irq_desc，进流控层，遍历 action，最后才轮到驱动的 handler。

维度 裸机 Linux
中断入口 你在 0x18 自己放代码 编译期定的向量表，链接到 0xffff0000
现场保存 自己写 stmdb/ldmia vector_stub + usr_entry/svc_entry，存成 struct pt_regs
中断号 自己从寄存器读，自己约定 硬件中断号 → irq_domain 翻译 → IRQ 编号
分发给谁 函数名写死，一中断一函数 irq_desc[irq].action 链表，可多个 handler
谁屏蔽/清挂起 ISR 自己写寄存器 irq_chip 回调，流控层统一调度
共享中断 不支持，一线一设备 支持，链表遍历 + dev_id 区分
中断里能干什么 随便，别作死 不能睡眠、不能阻塞，慢了挪下半部或线程化
可重入 自己防 同一 IRQ 在所有 CPU 上被屏蔽，不用防

最后一行多说一句。Linux 保证「同一个中断的同一个 handler 不会同时在两个 CPU 上跑」，靠流控层 mask 中断线再置 IRQ_INPROGRESS。你注册的 handler 天然串行。共享中断里多个 action 之间要不要加锁，那是你自己的事。

二、Linux 中断子系统的三层分工 #

层次 干什么 关键符号 代码位置
一、体系结构相关（硬件封装层） 存现场、切内核栈、拿硬件中断号、调统一入口、恢复现场 vector_irq、irq_handler、asm_do_IRQ、irq_chip arch/arm/kernel/entry-armv.S、irq.c、arch/arm/mach-*/
二、通用逻辑层（generic irq） 统一框架，管 irq_desc、irq_domain、线程化、共享与嵌套中断 irq_desc、irq_data、irq_domain、generic_handle_irq kernel/irq/irqdesc.c、irqdomain.c、handle.c
三、流控层 同源中断并发、何时 mask/unmask/ack/eoi handle_level_irq、handle_edge_irq、handle_simple_irq kernel/irq/chip.c
驱动接口（挂在第二层外侧） 给驱动申请/释放/开关中断 request_irq、free_irq、disable_irq kernel/irq/manage.c、include/linux/interrupt.h

严格说是三层加一个对外接口面。第一层只管把中断号递进去，第三层只管按电气类型走流程，中间靠 irq_desc 和 irq_chip 串起来。三层的接口契约只有两行：

c
/* 第一层 → 第二层：我拿到一个硬件中断号，交给你 */
int generic_handle_irq(unsigned int irq);

/* 第二层 → 第三层：这是第 irq 号的中断描述符，按你的流程走 */
desc->handle_irq(irq, desc);

第一层递进来的是硬件中断号，第二层翻成 IRQ 编号，第三层从 irq_desc 取 action 交给驱动。一条链，三个翻译动作。

流控函数类型是 typedef void (*irq_flow_handler_t)(struct irq_desc *desc);。3.x 只剩一个 desc 参数；2.6.x 是 (unsigned int irq, struct irq_desc *desc) 两个。素材里两种都出现过，别以为谁抄错了 —— 版本不同。

流控函数 适用场景 S3C2440 用不用
handle_simple_irq 软件解码出来的中断，硬件不需流控 不用
handle_level_irq 电平触发，电平保持期间一直请求 用，UART、ADC 这类
handle_edge_irq 边沿触发，会并发重入 用，EINT、定时器
handle_fasteoi_irq 只要 eoi 不需 mask/ack 的控制器 不用
handle_percpu_irq 每 CPU 私有中断，不分发 不用
handle_nested_irq 线程化的嵌套中断 不用

板级代码和驱动通过 irq_set_handler、irq_set_chip_and_handler、irq_set_chip_and_handler_name 挂流控函数，S3C24xx 用第二个。

三、内核启动阶段的中断初始化顺序 #

u-boot 把内核搬到内存跳过去，起点是 start_kernel。先给时序，再挑关键函数看。

阶段 调用 位置 干了什么
1 setup_arch → early_trap_init arch/arm/kernel/setup.c / traps.c 向量表和跳转 stub 拷到 0xffff0000
2 start_kernel → early_irq_init kernel/irq/irqdesc.c 建 irq_desc 数组，填默认值（第七节细讲）
3 early_irq_init 尾部 → arch_early_irq_init arch/arm/kernel/irq.c ARM 没实现，空函数
4 start_kernel → init_IRQ arch/arm/kernel/irq.c 调板级 machine_desc->init_irq 或 DT 路径 irqchip_init
5 init_irq 回调内部 drivers/irqchip/irq-s3c24xx.c 建控制器、建 domain、给 irq_desc 装 handle_irq 和 irq_chip
6 s3c24xx_init_intc 内部 同上 set_handle_irq 把全局 handle_arch_irq 指向 s3c24xx_handle_irq

第 1 步 early_trap_init（arch/arm/kernel/traps.c）用一条 ARM/Thumb 下都未定义的指令 0xe7fddef1 把整页填满，跳错地址立刻 fault 而不是跑飞，然后两次 memcpy 把 .vectors 段拷到 0xffff0000、.stubs 段拷到 +0x1000，最后 flush_icache_range。链接地址在 vmlinux.lds 里写死，所以这两段就是异常向量和跳转 stub。

第 4 步，init_IRQ：

c
void __init init_IRQ(void)
{
    if (IS_ENABLED(CONFIG_OF) && !machine_desc->init_irq)
        irqchip_init();                 /* DT 路径 */
    else
        machine_desc->init_irq();       /* 老式板级路径 */

    /* 后面还有 L2 cache 与 uniphier cache 初始化，与中断无关，略 */
}

分支条件直白：配了 DT 且板级没填 init_irq 走 irqchip_init()，否则走 machine_desc->init_irq()。SMDK2440 填了，所以即使内核开了 DT 支持，它仍走后者：

text
MACHINE_START(S3C2440, "SMDK2440")
        .atag_offset    = 0x100,
        .init_irq       = s3c2440_init_irq,
        .map_io         = smdk2440_map_io,
        .init_machine   = smdk2440_machine_init,
        .init_time      = smdk2440_init_time,
MACHINE_END

.init_irq 指向 drivers/irqchip/irq-s3c24xx.c 里的 s3c2440_init_irq，就是第五节逐个拆的函数。启动时会看到：

text
NR_IRQS: 111
S3C2440: IRQ Support
irq: clearing pending status 00000002

NR_IRQS 定义在 arch/arm/mach-s3c24xx/include/mach/irqs.h：

c
#define IRQ_S3C2416_I2S1        S3C2416_IRQ(7)        /* 7 + 58 + 29 + 16 = 110 */

#if defined(CONFIG_CPU_S3C2416)
#define NR_IRQS (IRQ_S3C2416_I2S1 + 1)               /* 111 */
#else
#define NR_IRQS (IRQ_S3C2443_AC97 + 1)
#endif

111 的来历：16 个 arch 保留槽位 + 58 + 29 + 7 + 1。第六节拆这个编号空间。

四、中断控制器的注册：从 Device Tree 到 intc 设备 #

分岔点就是上一节那个 if。

DT 路径：init_IRQ → irqchip_init() → of_irq_init(__irqchip_begin)，本体只有一行 of_irq_init(__irqchip_begin);。

__irqchip_begin 是链接器拼出的 of_device_id 表，表项由驱动源码里的宏塞进去：

c
IRQCHIP_DECLARE(s3c2410_irq, "samsung,s3c2410-irq", s3c2410_irq_init);

宏展开做三件事：定义 of_device_id 项，compatible 填字符串、data 填初始化函数指针，塞进 .init.irqchip 段。链接时这些段被收集成数组，__irqchip_begin 指到头部。

of_irq_init 拿表后做三件事：

  1. 扫全设备树，把带 interrupt-controller 属性的节点挑出来，按父子关系排成树 —— 保证父控制器先于子控制器初始化；
  2. 从根控制器开始，逐个节点拿 compatible 去表里匹配；
  3. 匹配上就调表里的初始化函数，参数是本控制器的 device_node 和父控制器的 device_node。

所以 DT 下 intc 驱动的初始化函数签名是 int __init xxx_irq_init(struct device_node *node, struct device_node *parent)，node 用来 of_iomap 取寄存器、读 #interrupt-cells，parent 用来建级联。

dts
intc: interrupt-controller@4a000000 {
    compatible = "samsung,s3c2410-irq";
    reg = <0x4a000000 0x100>;
    interrupt-controller;        /* 空属性，声明这是中断控制器 */
    #interrupt-cells = <4>;      /* 上层引用时 interrupts 写 4 个 cell */
};

button {
    compatible = "myboard,key";
    interrupt-parent = <&intc>;
    interrupts = <0 0 0 0>, <0 1 0 0>;
};

这段 dts 是结构示意，具体 compatible 与 reg 区间以你手上内核的 dts 为准，本篇未逐行核对。interrupts 的四元组交给 xlate 函数翻成 hwirq + 触发类型，S3C24xx 用 irq_domain_xlate_twocell。

老式板级路径：init_IRQ → machine_desc->init_irq()。没有 device_node，寄存器基地址硬编码，hwirq 与 IRQ 编号的对应是头文件宏写死的。S3C2440 走这条，三次 s3c24xx_init_intc 的第一个参数 np 全是 NULL —— 意思是「我没有设备树节点」。

两条路最后都落成同一件事：建 irq_domain，把每个 hwirq 映射到 IRQ 编号，给每个 IRQ 的 irq_desc 装 handle_irq 和 irq_chip。区别只在编号是查表还是从 dts 解析。

五、s3c24xx_init_intc 代码走读 #

先看调用方：

c
void __init s3c2440_init_irq(void)
{
    pr_info("S3C2440: IRQ Support\n");

#ifdef CONFIG_FIQ
    init_FIQ(FIQ_START);
#endif

    s3c_intc[0] = s3c24xx_init_intc(NULL, &init_s3c2440base[0], NULL,
                                    0x4a000000);
    if (IS_ERR(s3c_intc[0])) {
        pr_err("irq: could not create main interrupt controller\n");
        return;
    }

    s3c24xx_init_intc(NULL, &init_eint[0], s3c_intc[0], 0x560000a4);
    s3c_intc[1] = s3c24xx_init_intc(NULL, &init_s3c2440subint[0],
                                    s3c_intc[0], 0x4a000018);
}
调用 irq_data parent address 建成什么
第 1 次 init_s3c2440base NULL 0x4a000000 主中断控制器，s3c_intc[0]
第 2 次 init_eint s3c_intc[0] 0x560000a4 外部子中断控制器，返回值没存
第 3 次 init_s3c2440subint s3c_intc[0] 0x4a000018 内部子中断控制器，s3c_intc[1]

第 2 次的返回值没赋给 s3c_intc[2]：s3c_intc[2] 留给 S3C2416 的第二个主控制器（0x4a000040）。外部中断控制器的指针靠 s3c_irq_data.sub_intc 反查，不走 s3c_intc[]。

物理上 S3C2440 只有一个中断控制器，软件抽象成三个：根控制器管 32 个主中断源，两个子控制器一个管 24 个外部中断、一个管 15 个内部子中断。子控制器在硬件上把多路汇成一路，接到根控制器某根输入线上 —— 这就是级联。

c
struct s3c_irq_data {          /* 一个中断源 */
    unsigned int type;                     /* S3C_IRQTYPE_* 触发类型 */
    unsigned long offset;                  /* 该中断源在寄存器里的位偏移 */
    unsigned long parent_irq;              /* 子中断对应的主中断硬件编号 */
    struct s3c_irq_intc *intc;             /* 归属的中断控制器 */
    unsigned long sub_bits;                /* 本中断源下面挂了哪些子中断，位图 */
    struct s3c_irq_intc *sub_intc;         /* 子中断控制器 */
};

struct s3c_irq_intc {          /* 一个中断控制器 */
    void __iomem        *reg_pending;      /* 源挂起寄存器 */
    void __iomem        *reg_intpnd;       /* 中断挂起寄存器 */
    void __iomem        *reg_mask;         /* 中断屏蔽寄存器 */
    struct irq_domain   *domain;           /* 该控制器对应的中断域 */
    struct s3c_irq_intc *parent;           /* 父控制器，主控制器为 NULL */
    struct s3c_irq_data *irqs;             /* 指向下面三个数组之一 */
};

static struct s3c_irq_intc *s3c_intc[3];
/* [0] main intc   [1] sub intc   [2] main intc2 (s3c2416) */

static struct s3c_irq_data init_s3c2440base[32] = {   /* 32 个主中断源 */
        { .type = S3C_IRQTYPE_EINT,  },  /* EINT0 ~ EINT3 */
        { .type = S3C_IRQTYPE_LEVEL, },  /* EINT4to7、EINT8to23 */
        /* 其余项：TIMER0~4、LCD、DMA0~3、SDI、SPI0、USBD、USBH、IIC、
         * SPI1、RTC、nBATT_FLT、TICK 是 EDGE；CAM、WDT/AC97、UART2、
         * UART1、NFCON、UART0、ADCPARENT 是 LEVEL
         */
};

static struct s3c_irq_data init_s3c2440subint[32] = {  /* 15 个内部子中断 */
        { .type = S3C_IRQTYPE_LEVEL, .parent_irq = 28 }, /* UART0-RX/TX/ERR */
        { .type = S3C_IRQTYPE_LEVEL, .parent_irq = 23 }, /* UART1-RX/TX/ERR */
        { .type = S3C_IRQTYPE_LEVEL, .parent_irq = 15 }, /* UART2-RX/TX/ERR */
        { .type = S3C_IRQTYPE_EDGE,  .parent_irq = 31 }, /* TC、ADC */
        { .type = S3C_IRQTYPE_LEVEL, .parent_irq = 6  }, /* CAM_C、CAM_P */
        { .type = S3C_IRQTYPE_LEVEL, .parent_irq = 9  }, /* WDT、AC97 */
};

static struct s3c_irq_data __maybe_unused init_eint[32] = {  /* 24 个外部中断 */
        { .type = S3C_IRQTYPE_NONE, },  /* 0~3 reserved */
        { .type = S3C_IRQTYPE_EINT, .parent_irq = 4 },   /* EINT4~EINT7  */
        { .type = S3C_IRQTYPE_EINT, .parent_irq = 5 },   /* EINT8~EINT23 */
};

三个数组槽位都是 32，实际装了 32、15、24 项。init_s3c2440subint 后 17 个槽零填充，type 为 0 即 S3C_IRQTYPE_NONE，s3c24xx_irq_map 遇到它直接 return 0。sub_bits 和 sub_intc 是级联的骨架：子中断被 map 时反向往父中断源上写这两个字段，同时把父中断流控函数换成 s3c_irq_demux。

正题，s3c24xx_init_intc 完整代码带逐行注释：

c
static struct s3c_irq_intc * __init s3c24xx_init_intc(struct device_node *np,
                                       struct s3c_irq_data *irq_data,
                                       struct s3c_irq_intc *parent,
                                       unsigned long address)
{
    struct s3c_irq_intc *intc;
    void __iomem *base = (void *)0xf6000000; /* static mapping */
    int irq_num;
    int irq_start;
    int ret;

    /* ① 分配控制器结构 */
    intc = kzalloc(sizeof(struct s3c_irq_intc), GFP_KERNEL);
    if (!intc)
        return ERR_PTR(-ENOMEM);

    intc->irqs = irq_data;

    /* ② 记下父控制器 */
    if (parent)
        intc->parent = parent;

    /* ③ 靠物理地址区分是哪个控制器，据此填寄存器地址和编号空间 */
    switch (address) {
    case 0x4a000000:                        /* SRCPND 源挂起寄存器 */
        pr_debug("irq: found main intc\n");
        intc->reg_pending = base;           /* SRCPND */
        intc->reg_mask = base + 0x08;       /* INTMSK */
        intc->reg_intpnd = base + 0x10;     /* INTPND */
        irq_num = 32;                       /* 32 个主中断源 */
        irq_start = S3C2410_IRQ(0);         /* 0 + 16 = 16 */
        break;
    case 0x4a000018:                        /* SUBSRCPND 次级源挂起寄存器 */
        pr_debug("irq: found subintc\n");
        intc->reg_pending = base + 0x18;    /* SUBSRCPND */
        intc->reg_mask = base + 0x1c;       /* INTSUBMSK */
        irq_num = 29;
        irq_start = S3C2410_IRQSUB(0);      /* 0 + 16 + 58 = 74 */
        break;
    case 0x4a000040:                        /* s3c2416 的第二个主控制器 */
        pr_debug("irq: found intc2\n");
        intc->reg_pending = base + 0x40;
        intc->reg_mask = base + 0x48;
        intc->reg_intpnd = base + 0x50;
        irq_num = 8;
        irq_start = S3C2416_IRQ(0);
        break;
    case 0x560000a4:                        /* EINTMASK 外部中断屏蔽寄存器 */
        pr_debug("irq: found eintc\n");
        base = (void *)0xfd000000;          /* 外部中断走另一块静态映射 */

        intc->reg_mask = base + 0xa4;       /* EINTMASK */
        intc->reg_pending = base + 0xa8;    /* EINTPND */
        irq_num = 24;                       /* 24 个外部中断源 */
        irq_start = S3C2410_IRQ(32);        /* 32 + 16 = 48 */
        break;
    default:
        pr_err("irq: unsupported controller address\n");
        ret = -EINVAL;
        goto err;
    }

    /* ④ 清掉上电/uboot 留下的挂起状态，否则一开总中断就假中断 */
    s3c24xx_clear_intc(intc);

    /* ⑤ 建中断域，这一步连锁触发 s3c24xx_irq_map */
    intc->domain = irq_domain_add_legacy(np, irq_num, irq_start,
                                         0, &s3c24xx_irq_ops,
                                         intc);
    if (!intc->domain) {
        pr_err("irq: could not create irq-domain\n");
        ret = -EINVAL;
        goto err;
    }

    /* ⑥ 把 C 入口函数挂到全局上 */
    set_handle_irq(s3c24xx_handle_irq);

    return intc;

err:
    kfree(intc);
    return ERR_PTR(ret);
}

① 用 kzalloc 不用 kmalloc，因为后面靠零值判断：reg_intpnd 为 NULL 表示这个控制器没有独立的 INTPND，清挂起和取中断号都要按 NULL 分支走。

③ 用 address 做 switch，拿物理地址当控制器身份证。0x4a000000 是中断控制器寄存器块物理基址，偏移 0 是 SRCPND、+0x08 是 INTMSK、+0x10 是 INTPND；0x4a000018 是 SUBSRCPND、+0x1c 是 INTSUBMSK；0x560000a4 落在 GPIO 那块，EINTMASK 在 +0xa4、EINTPND 在 +0xa8。

base = 0xf6000000 是 S3C24xx 的静态 IO 映射虚拟基址，0x4a000000 对应它。走外部中断分支时 base 改写成 0xfd000000，因为 0x56000000 那块 GPIO 映射在另一段虚拟地址。这种硬编码虚拟地址是 2.6/3.x 早期风格，后来的驱动改成 of_iomap + ioremap。三个编号空间起点 S3C2410_IRQ(0) = 16、S3C2410_IRQ(32) = 48、S3C2410_IRQSUB(0) = 74，第六节展开。

irq_num = 29 要留意。 内部子中断实际只有 15 个，但域按 29 建。map 会被调 29 次，后 14 次撞上 S3C_IRQTYPE_NONE 槽位直接返回 0。为什么取 29 不给 15，素材原文自己也打了个「为啥是29？」的问号，本篇给不出证据，标为未验证。能确认的只有行为：编号空间按 29 留，实装 15 个。

④ s3c24xx_clear_intc 清挂起。 上电或 uboot 跳过来时 SRCPND/INTPND 里会残留置位，不清的话内核一开总中断就立刻进一次假中断。它先选寄存器 —— reg_source = intc->reg_intpnd ? intc->reg_intpnd : intc->reg_pending;，有 INTPND 就从 INTPND 读，没有就退回 SRCPND。然后最多循环 4 次：读 pend，为 0 或与上一轮 last 相等就 break（防止硬件一直挂着一位导致死循环），把读到的值原样写回 reg_pending 和 reg_intpnd。SRCPND/INTPND 是写 1 清除，写回原值就是清。每轮打一行 irq: clearing pending status %08x，启动日志里那句 irq: clearing pending status 00000002 就是它。

c
static int s3c24xx_irq_map(struct irq_domain *h, unsigned int virq,
                           irq_hw_number_t hw)
{
    struct s3c_irq_intc *intc = h->host_data;         /* 域绑定的控制器 */
    struct s3c_irq_data *irq_data = &intc->irqs[hw];  /* 该 hwirq 的中断源 */
    struct s3c_irq_intc *parent_intc;
    struct s3c_irq_data *parent_irq_data;
    unsigned int irqno;

    irq_data->intc = intc;
    irq_data->offset = hw;                 /* 位偏移就是 hwirq */
    parent_intc = intc->parent;

    switch (irq_data->type) {
    case S3C_IRQTYPE_NONE:
        return 0;                          /* 空槽，什么都不装 */
    case S3C_IRQTYPE_EINT:
        if (parent_intc && (!soc_is_s3c2412() || hw >= 4))
            irq_set_chip_and_handler(virq, &s3c_irqext_chip, handle_edge_irq);
        else
            irq_set_chip_and_handler(virq, &s3c_irq_eint0t4, handle_edge_irq);
        break;
    case S3C_IRQTYPE_EDGE:
        if (parent_intc || intc->reg_pending == S3C2416_SRCPND2)
            irq_set_chip_and_handler(virq, &s3c_irq_level_chip, handle_edge_irq);
        else
            irq_set_chip_and_handler(virq, &s3c_irq_chip, handle_edge_irq);
        break;
    case S3C_IRQTYPE_LEVEL:
        if (parent_intc)
            irq_set_chip_and_handler(virq, &s3c_irq_level_chip, handle_level_irq);
        else
            irq_set_chip_and_handler(virq, &s3c_irq_chip, handle_level_irq);
        break;
    default:
        pr_err("irq-s3c24xx: unsupported irqtype %d\n", irq_data->type);
        return -EINVAL;
    }
    irq_set_chip_data(virq, irq_data);

    if (parent_intc && irq_data->type != S3C_IRQTYPE_NONE) {
        if (irq_data->parent_irq > 31) {
            pr_err("irq-s3c24xx: parent irq %lu is out of range\n",
                   irq_data->parent_irq);
            return -EINVAL;
        }

        /* 往父中断源上登记：我这个子控制器挂在它下面，占这些位 */
        parent_irq_data = &parent_intc->irqs[irq_data->parent_irq];
        parent_irq_data->sub_intc = intc;
        parent_irq_data->sub_bits |= (1UL << hw);

        /* 把父中断的流控函数换成解复用器 */
        irqno = irq_find_mapping(parent_intc->domain, irq_data->parent_irq);
        if (!irqno) {
            pr_err("irq-s3c24xx: could not find mapping for parent irq %lu\n",
                   irq_data->parent_irq);
            return -EINVAL;
        }
        irq_set_chained_handler(irqno, s3c_irq_demux);
    }

    return 0;
}
type 有父控制器（子中断） 无父控制器（主中断） 覆盖范围
S3C_IRQTYPE_EINT s3c_irqext_chip + handle_edge_irq s3c_irq_eint0t4 + handle_edge_irq EINT4~EINT23 / EINT0~EINT3
S3C_IRQTYPE_EDGE s3c_irq_level_chip + handle_edge_irq s3c_irq_chip + handle_edge_irq 定时器、DMA、RTC
S3C_IRQTYPE_LEVEL s3c_irq_level_chip + handle_level_irq s3c_irq_chip + handle_level_irq UART、ADC、CAM
S3C_IRQTYPE_NONE 直接返回，不装 直接返回，不装 保留槽

一句话规律：有父控制器就用 _level_chip（要通过 SUBSRCPND 看子源），没有就用 _chip（直接看 SRCPND）。

最后那个 if (parent_intc && ...) 是级联的落地动作：给父中断源打 sub_intc/sub_bits 标记，把父中断 handle_irq 从流控函数换成 s3c_irq_demux。换完之后父中断进来不再走 handle_level_irq，而是先解复用。

c
static void s3c_irq_demux(struct irq_desc *desc)
{
    struct irq_chip *chip = irq_desc_get_chip(desc);   /* 父中断的 chip */
    struct s3c_irq_data *irq_data = irq_desc_get_chip_data(desc);
    struct s3c_irq_intc *intc = irq_data->intc;
    struct s3c_irq_intc *sub_intc = irq_data->sub_intc;
    unsigned int n, offset, irq;
    unsigned long src, msk;

    /* 非 DT 每类中断一个域，子中断从 hwirq 0 起；
     * DT 只有一个大域，子中断从 hwirq 32 起
     */
    offset = irq_domain_get_of_node(intc->domain) ? 32 : 0;

    chained_irq_enter(chip, desc);

    src = readl_relaxed(sub_intc->reg_pending);   /* SUBSRCPND / EINTPND */
    msk = readl_relaxed(sub_intc->reg_mask);      /* INTSUBMSK / EINTMASK */

    src &= ~msk;                    /* 掐掉被屏蔽的 */
    src &= irq_data->sub_bits;      /* 只留挂在当前父中断下面的 */

    while (src) {
        n = __ffs(src);             /* 最低置位 → 子源位偏移 */
        src &= ~(1 << n);
        irq = irq_find_mapping(sub_intc->domain, offset + n);
        generic_handle_irq(irq);    /* 回到通用逻辑层走流控 */
    }

    chained_irq_exit(chip, desc);
}

两行 &= 是精髓：读子控制器挂起寄存器，src &= ~msk 去掉被屏蔽的，src &= irq_data->sub_bits 只留挂在自己下面的，然后 __ffs 从低位一个个摘、翻成 IRQ 编号、generic_handle_irq 重新进流控层。它调的是 generic_handle_irq 不是 handle_irq_event —— 子中断要完整走一遍流控，不能跳步。

irq_set_chained_handler 和 irq_set_chip_and_handler 走同一条路：后者内部就是 irq_set_chip 绑 chip、再 __irq_set_handler 进 __irq_do_set_handler 把 desc->handle_irq = handle 写下去；前者只是多传一个 is_chained = 1。落到 irq_chip 上就是 s3c_irq_chip / s3c_irq_level_chip / s3c_irqext_chip / s3c_irq_eint0t4 四个实例，都以 irq_ack/irq_mask/irq_unmask/irq_set_type 为主。

s3c_irq_mask 屏蔽子中断时会顺手判断：(mask & sub_bits) == sub_bits 成立就说明这根父线上挂的子中断全屏蔽了，于是递归把父中断也 mask 掉，省一次无意义的中断入口。递归天然只有两级，因为父中断的 parent 是 NULL，if (parent_intc) 进不去。

六、中断号分配与域映射在这个平台上的做法 #

三个起点都是宏加出来的：

c
#define S3C2410_CPUIRQ_OFFSET   (16)
#define S3C2410_IRQ(x)          ((x) + S3C2410_CPUIRQ_OFFSET)
#define S3C2410_IRQSUB(x)       ((x) + S3C2410_CPUIRQ_OFFSET + 58)
空间 起点 数量 覆盖 IRQ 编号 hwirq
arch 保留 0 16 IRQ 0 ~ 15 无（软中断等占位）
主中断 S3C2410_IRQ(0) = 16 32 IRQ 16 ~ 47 0 ~ 31
外部中断 S3C2410_IRQ(32) = 48 24 IRQ 48 ~ 71 0 ~ 23
内部子中断 S3C2410_IRQSUB(0) = 74 29（实装 15） IRQ 74 ~ 102 0 ~ 28

0~15 为什么不给硬件用？ARM Linux 把编号空间最前面一段留给体系结构自己，S3C2410_CPUIRQ_OFFSET 取 16 就是这个约定。所以 S3C2440 上第一个硬件中断（EINT0）拿到的 IRQ 编号是 16，不是 0。

对应关系靠 irq_domain_add_legacy 的 first_hwirq = 0 加 first_irq，走固定偏移：IRQ 编号 = irq_start + hwirq。主控制器 16 + hwirq，外部中断 48 + hwirq，子中断 74 + hwirq。三个域各自的 linear_revmap[] 是 hwirq → IRQ 编号 的一维数组，hwirq 直接当索引。

正向查走 irq_find_mapping(domain, hwirq)，三段判断：hwirq < revmap_direct_max_irq 走直接映射；hwirq < revmap_size 直接返回 domain->linear_revmap[hwirq]；再不行才 radix_tree_lookup(&domain->revmap_tree, hwirq)。S3C24xx 三个域 revmap_size 分别是 32、29、24，所有 hwirq 都落在数组里，走不到基数树那段。

这里为什么用 legacy 域而不是 irq_create_mapping 动态分配？因为 S3C24xx 的 IRQ 编号是头文件写死的宏，一批驱动直接写 IRQ_EINT8 这种常量。编号关系固定在编译期，只能用 legacy 域钉死。irq_create_mapping 会动态挑空闲编号，一用就把这些宏全废了。

七、irq_desc 数组的建立 #

irq_desc 是「一个 IRQ 一份档案」。档案怎么建，取决于 CONFIG_SPARSE_IRQ。

不配 SPARSE_IRQ（S3C2440 默认），kernel/irq/irqdesc.c 里一个静态数组，编译期占好内存：

c
struct irq_desc irq_desc[NR_IRQS] __cacheline_aligned_in_smp = {
    [0 ... NR_IRQS-1] = {
        .handle_irq    = handle_bad_irq,
        .depth         = 1,
        .lock          = __RAW_SPIN_LOCK_UNLOCKED(irq_desc->lock),
    }
};

GNU C 的区间初始化把 111 项全填成同一初值。三个字段各有讲究：handle_irq = handle_bad_irq 让没人认领的中断进来打警告而不是静默丢；depth = 1 表示还没 enable 过，enable_irq 要减到 0 才真开；lock 是每项自带的一把自旋锁。

__cacheline_aligned_in_smp 让每项按 cache line 对齐，避免两 CPU 改相邻项时互踩 cache line。S3C2440 单核用不上，代码是通用的。这块内存在 .data 里常驻，111 项乘 sizeof(struct irq_desc)（3.x 是几百字节量级），几十 KB。

配了 SPARSE_IRQ 就换基数树，early_irq_init 先用 arch_probe_nr_irqs() 拿预分配个数，再逐个 alloc_desc + set_bit + irq_insert_desc 插进树里，末尾照样 return arch_early_irq_init();。预分配多少个由 arch_probe_nr_irqs 定，ARM 上就一行 nr_irqs = machine_desc->nr_irqs ? machine_desc->nr_irqs : NR_IRQS; —— 板级填了就用它，没填用 NR_IRQS。S3C2440 的板子没填，还是 111。

方式 内存 查找 适用
静态数组 编译期固定，NR_IRQS × sizeof(irq_desc) 一次下标，O(1) IRQ 少且连续，S3C24xx
基数树 按需分配，用多少占多少 多级索引，比数组慢 编号跳跃大、数量多

建完之后数组里每项仍是「未认领」：handle_irq 指向 handle_bad_irq、action 空、chip 空。等第五节那串 irq_domain_add_legacy 跑完，111 项里的 71 项才被装上真正的流控函数和 irq_chip。

启动这条线的全貌就齐了：先备档案柜（irq_desc），再登记每个抽屉归谁管（irq_domain + irq_chip + handle_irq），最后把大门钥匙交给 handle_arch_irq。

八、一次中断的执行流程总览 #

键盘按下，到你的 handler 跑完，中间这条链长这样：

text
硬件拉 IRQ 线
  → CPU 跳到 0xffff0018（vector_irq）
    → vector_stub 展开的代码：存 r0/lr/spsr，切 SVC 模式
      → __irq_usr 或 __irq_svc：usr_entry / svc_entry 存 pt_regs
        → irq_handler 宏
          → ldr pc, [handle_arch_irq]        ← 平台挂的 C 入口
            → s3c24xx_handle_irq(regs)
              → s3c24xx_handle_intc()：读 INTPND + INTOFFSET，得 hwirq
                → handle_domain_irq(domain, hwirq, regs)
                  → __handle_domain_irq()：irq_enter + irq_find_mapping
                    → generic_handle_irq(irq)
                      → desc->handle_irq(irq, desc)     ← 流控层
                        → handle_level_irq / handle_edge_irq
                          → mask_ack_irq
                          → handle_irq_event(desc)
                            → __handle_irq_event_percpu()
                              → action->handler(irq, dev_id)   ← 你的 ISR
                              → IRQ_WAKE_THREAD ? __irq_wake_thread()
                          → cond_unmask_irq
                      → irq_exit()                     ← 触发软中断
  → 恢复现场，返回被中断的代码

阶段 函数 文件 上下文

2 存现场 vector_stub、usr_entry/svc_entry arch/arm/kernel/entry-armv.S IRQ → SVC
3 取中断号 s3c24xx_handle_irq → s3c24xx_handle_intc drivers/irqchip/irq-s3c24xx.c SVC，IRQ 关

九、硬件响应与入口汇编 #

ARM 有两种向量表位置：低端 0x00000000、高端 0xffff0000。Linux 用高端。向量表在 arch/arm/kernel/entry-armv.S，八项依次是 vector_rst、vector_und、一条 W(ldr) pc, .L__vectors_start + 0x1000、vector_pabt、vector_dabt、vector_addrexcptn、vector_irq、vector_fiq。IRQ 落在第 7 项，也就是 0x18。

vector_irq 由 vector_stub 宏生成，调用是 vector_stub irq, IRQ_MODE, 4，展开后：

armasm
vector_irq:
        sub     lr, lr, #4              @ lr 是中断处 PC + 8，减 4 得下一条指令

        stmia   sp, {r0, lr}            @ 保存 r0、lr 到 IRQ 模式栈
        mrs     lr, spsr
        str     lr, [sp, #8]            @ 保存中断前的 CPSR 到 spsr_irq

        @ 准备切 SVC32 模式，IRQ 保持关闭
        mrs     r0, cpsr
        eor     r0, r0, #(IRQ_MODE ^ SVC_MODE | PSR_ISETSTATE)
        msr     spsr_cxsf, r0

        @ 紧跟着的分支表按进入中断前的模式选目标
        and     lr, lr, #0x0f
        mov     r0, sp
        ldr     lr, [pc, lr, lsl #2]
        movs    pc, lr                  @ S 结尾，跳转同时恢复 cpsr

        .long __irq_usr                 @ 0  USR_32
        .long __irq_invalid             @ 1
        .long __irq_invalid             @ 2  IRQ_32
        .long __irq_svc                 @ 3  SVC_32

__irq_usr:
        usr_entry                       @ 存 pt_regs 到内核栈
        irq_handler
        b       ret_to_user_from_irq    @ 回用户态，路上处理抢占和信号

__irq_svc:
        svc_entry                       @ 存 pt_regs，被中断的是内核代码

两条最终都汇到 irq_handler 宏。开了 CONFIG_GENERIC_IRQ_MULTI_HANDLER 就间接跳进全局函数指针 handle_arch_irq（ldr r1, =handle_arch_irq / mov r0, sp / ldr pc, [r1]），参数是 sp 也就是 struct pt_regs *。这个指针正是第五节那次 set_handle_irq(s3c24xx_handle_irq) 写进去的 —— 平台代码在这里接管了整条中断入口。没开这个配置就走默认实现 arch_irq_handler_default：

armasm

        get_irqnr_preamble r6, lr

        bne     do_IPI                       @ 多核：核间中断单独处理

get_irqnr_preamble 和 get_irqnr_and_base 由 machine 级代码实现，职责就是从中断控制器寄存器里读出中断号。这条默认路径下每次中断只处理一个中断源，靠 badrne lr, 1b 回跳重复读，直到控制器没有挂起位。

asm_do_IRQ 转发进 handle_IRQ，后者调 __handle_domain_irq(NULL, irq, false, regs)。注意 domain 是 NULL、lookup 是 false —— 意思是「这个 irq 已经是从平台代码翻译好的 IRQ 编号，不用再查域」。S3C2440 走的是 handle_arch_irq 那条，不是这条。

__handle_domain_irq，kernel/irq/irqdesc.c：

c
int __handle_domain_irq(struct irq_domain *domain, unsigned int hwirq,
                        bool lookup, struct pt_regs *regs)
{
    struct pt_regs *old_regs = set_irq_regs(regs);
    unsigned int irq = hwirq;
    int ret = 0;

    irq_enter();

#ifdef CONFIG_IRQ_DOMAIN
    if (lookup)
        irq = irq_find_mapping(domain, hwirq);
#endif

    if (unlikely(!irq || irq >= nr_irqs)) {
        ack_bad_irq(irq);            /* 编号越界，打警告 */
        ret = -EINVAL;
    } else {
        generic_handle_irq(irq);     /* 交给通用逻辑层 */
    }

    irq_exit();                      /* 顺手把软中断处理掉 */
    set_irq_regs(old_regs);
    return ret;
}

四个动作按顺序记：set_irq_regs(regs) 把当前 pt_regs 挂到 per-CPU 变量上（你的 handler 里 get_irq_regs() 拿到的就是它，old_regs 留着恢复）；irq_enter() 抬高 preempt_count 进硬中断上下文，此后不能睡；lookup 为真才查域，S3C2440 那条路为真因为传进来的是 hwirq；irq_exit() 退出中断上下文，里面有 invoke_softirq()，第十四节讲。

十、流控层 handle_irq #

generic_handle_irq 是通用逻辑层的门面，kernel/irq/handle.c：

c
int generic_handle_irq(unsigned int irq)
{
    struct irq_desc *desc = irq_to_desc(irq);

    if (!desc)
        return -EINVAL;
    generic_handle_irq_desc(irq, desc);
    return 0;
}

static inline void generic_handle_irq_desc(unsigned int irq, struct irq_desc *desc)
{
    desc->handle_irq(irq, desc);
}

irq_to_desc 在静态数组配置下就是 &irq_desc[irq]，一次下标。这里调的 irq_desc.handle_irq 就是第五节 s3c24xx_irq_map 装进去的那个 —— 初始化阶段装的什么，运行阶段就跑什么，整条脊柱在这里闭合。

电平触发的完整实现，kernel/irq/chip.c：

c
void handle_level_irq(struct irq_desc *desc)
{
    raw_spin_lock(&desc->lock);
    mask_ack_irq(desc);

    if (!irq_may_run(desc))
        goto out_unlock;

    desc->istate &= ~(IRQS_REPLAY | IRQS_WAITING);

    /*
     * If its disabled or no action available
     * keep it masked and get out of here
     */
    if (unlikely(!desc->action || irqd_irq_disabled(&desc->irq_data))) {
        desc->istate |= IRQS_PENDING;
        goto out_unlock;
    }

    kstat_incr_irqs_this_cpu(desc);
    handle_irq_event(desc);

    cond_unmask_irq(desc);

out_unlock:
    raw_spin_unlock(&desc->lock);
}

逐行看这八步：

  1. raw_spin_lock(&desc->lock) 拿这个中断号的自旋锁，争用双方是同一 IRQ 在多 CPU 上的两个入口，或者线程化后 handler 线程与硬中断。
  2. mask_ack_irq(desc)：先 ack 再 mask。ack 清中断控制器里的挂起位，mask 关掉这根线，合起来保证「从现在到 unmask 之间这根线不再产生新中断」。电平触发的语义要求这个顺序 —— 不先 ack，电平还在，mask 之后挂起位依旧挂着。
  3. irq_may_run(desc)：查 IRQD_IRQ_INPROGRESS | IRQD_WAKEUP_ARMED，置了说明别的 CPU 正在跑，直接退出。这是 SMP 下「同源中断只处理一次」的落点；S3C2440 单核永远返回 true。
  4. 清 IRQS_REPLAY | IRQS_WAITING：重放标记和等待确认标记，进正常处理就都作废。
  5. !desc->action || irqd_irq_disabled()：没人注册 handler（request_irq 还没调），或者被 disable_irq 关着。两种情况都置 IRQS_PENDING 后退出 —— 挂起标记留给下次补，不丢。
  6. kstat_incr_irqs_this_cpu：per-CPU 计数加一，/proc/interrupts 那一列就是它。
  7. handle_irq_event(desc)：进 action 链表，这个函数会在内部放掉 desc->lock，回来时重新拿上。
  8. cond_unmask_irq(desc)：没被 disable 就把线重新打开，电平中断在这里才恢复响应。

mask_ack_irq 和 cond_unmask_irq 都是对 irq_chip 的薄封装：有 irq_mask_ack 回调就一次调完（硬件上更快），没有就分两步调 irq_mask 和 irq_ack，顺手用 irq_state_set_masked 在软件状态位里记一笔，cond_unmask_irq 靠它判断要不要 unmask。

电平中断为什么非得 mask → 处理 → unmask？因为电平信号在设备清掉之前一直保持激活。不 mask 就进 handler，handler 里还没清设备，中断控制器会立刻再报一次，直接打成中断风暴。mask 之后这段窗口里同源中断进不来，天然不嵌套。

边沿触发不一样，handle_edge_irq 进 handler 之前不 mask。骨架如下（结构示意，不同版本的掩码判断和 goto 位置有出入，别照抄）：

text
raw_spin_lock(desc->lock)
if (中断被 disable) { 置 IRQS_PENDING; mask_ack; 退出; }
if (!desc->action)   { mask; 退出; }

do {
    置 IRQ_INPROGRESS;
    handle_irq_event(desc);
    ...
} while ((desc->istate & IRQS_PENDING) && !irqd_irq_disabled(...))

cond_unmask_irq(desc)
raw_spin_unlock(desc->lock)

能确定的语义有三条：进 handler 前不 mask，所以同源中断可以在你 handler 执行期间再次触发；再触发那次会置 IRQS_PENDING 并 mask 掉，只记一次不多记；外层 do/while 检查 IRQS_PENDING，有挂起就把 handler 再跑一遍，跑完才 unmask。

为什么第二次要 mask？IRQS_PENDING 只有一位。不 mask 的话第三次同源中断进来时这一位已经在用了，没法再记录，中断就真丢了。mask 把它变成「最多再排一次队」。

十一、handle_irq_event 与 action 链表遍历 #

不管电平还是边沿，最后都落到 handle_irq_event，kernel/irq/handle.c：

c
irqreturn_t handle_irq_event(struct irq_desc *desc)
{
    irqreturn_t ret;

    desc->istate &= ~IRQS_PENDING;
    irqd_set(&desc->irq_data, IRQD_IRQ_INPROGRESS);
    raw_spin_unlock(&desc->lock);

    ret = handle_irq_event_percpu(desc);

    raw_spin_lock(&desc->lock);
    irqd_clear(&desc->irq_data, IRQD_IRQ_INPROGRESS);
    return ret;
}

锁的走位是关键：先清 IRQS_PENDING（挂起的现在开始处理了），再置 IRQD_IRQ_INPROGRESS（告诉别的 CPU「我在跑」），然后放掉 desc->lock —— handler 要跑很久，攥着锁会让另一个 CPU 的自旋空转，放锁之后 INPROGRESS 位接管互斥职责。跑完重新拿锁、清位、返回结果。handle_irq_event_percpu 再包一层：调完后 add_interrupt_randomness 拿中断到达时序喂熵池（中断间隔是外部世界不可预测的抖动），!noirqdebug 时调 note_interrupt 干伪中断检测 —— 连续很多次没人认领这一路中断就关掉并打警告，防止一根短路的线拖死系统，noirqdebug 内核参数可以关掉这套机制。

真正的遍历：

c
irqreturn_t __handle_irq_event_percpu(struct irq_desc *desc, unsigned int *flags)
{
    irqreturn_t retval = IRQ_NONE;
    unsigned int irq = desc->irq_data.irq;
    struct irqaction *action;

    record_irq_time(desc);

    for_each_action_of_desc(desc, action) {
        irqreturn_t res;

        trace_irq_handler_entry(irq, action);
        res = action->handler(irq, action->dev_id);
        trace_irq_handler_exit(irq, action, res);

        if (WARN_ONCE(!irqs_disabled(),
                      "irq %u handler %pS enabled interrupts\n",
                      irq, action->handler))
            local_irq_disable();

        switch (res) {
        case IRQ_WAKE_THREAD:
            if (unlikely(!action->thread_fn)) {
                warn_no_thread(irq, action);
                break;
            }
            __irq_wake_thread(desc, action);
            /* Fall through - to add to randomness */
        case IRQ_HANDLED:
            *flags |= action->flags;
            break;
        default:
            break;
        }

        retval |= res;
    }

    return retval;
}

for_each_action_of_desc 就是沿 desc->action 单向链表走一圈（for (act = desc->action; act; act = act->next)）。action->handler(irq, action->dev_id) 里的 irq 是 IRQ 编号，dev_id 是你 request_irq 传进去的指针，共享中断里内核靠它区分 action。WARN_ONCE(!irqs_disabled(), ...) 抓的是「handler 返回时中断被打开了」，说明你的代码里调了 local_irq_enable，打完警告强制关回去。

retval |= res 是按位或累积，不是最后一个覆盖前面。原因在 IRQ_HANDLED = (1 << 0)、IRQ_WAKE_THREAD = (1 << 1)，两个一起返回就是 0x3，用或累积才能把「某一路认领了、某一路要唤醒线程」同时表达出来。共享中断上一个设备返回 IRQ_HANDLED、另一个返回 IRQ_NONE 是常态，只要不全 IRQ_NONE 就算认领成功，note_interrupt 不记伪中断。

十二、handler 执行与返回值语义 #

驱动注册的 handler 类型是 irq_handler_t：

c
typedef irqreturn_t (*irq_handler_t)(int, void *);

三个返回值，语义卡得很死：

返回值 值 含义 内核动作
IRQ_NONE 1 << 0 = 0 号位不置 不是我的设备产生的 记一次 unhandled，累积到阈值就判伪中断并禁用该 IRQ
IRQ_HANDLED 1 << 0 = 0x1 是我的，我处理完了 `*flags
IRQ_WAKE_THREAD 1 << 1 = 0x2 上半部只做最小动作，剩下的交给线程 调 __irq_wake_thread 唤醒 action->thread
IRQ_HANDLED | IRQ_WAKE_THREAD 0x3 两者兼顾 既算认领又唤醒线程

三个必须守住的规矩：

  1. 不能返回 IRQ_NONE 了事。共享中断上如果每次都返回 IRQ_NONE，note_interrupt 累积到 irq_err_count 阈值会打印 nobody cared 并把这一路中断禁用。宁可返回 IRQ_HANDLED 也别乱报 IRQ_NONE。
  2. 不能睡眠。中断上下文里没有 task_struct，schedule() 会检测 in_interrupt() 并报 bug；kmalloc(GFP_KERNEL)、mutex_lock、copy_to_user 全都不许。
  3. 不能开中断。就是 WARN_ONCE 抓的那条。

共享中断的 handler 模板长这样：

c
static irqreturn_t key_handler(int irq, void *dev_id)
{
    struct key_dev *dev = dev_id;
    u32 status = readl(dev->base + KEY_STATUS);

    /* 一进来先判断是不是自己的设备，不是就尽快退出 */
    if (!(status & dev->mask))
        return IRQ_NONE;

    /* 清中断源，这一步不能漏，否则电平型会一直重入 */
    writel(status | dev->mask, dev->base + KEY_STATUS);

    /* 只做最小动作，重活丢给下半部 */
    dev->event = 1;
    tasklet_schedule(&dev->tasklet);

    return IRQ_HANDLED;
}

那个 dev_id 就是遍历时的 action->dev_id。共享中断里它必须非 NULL，内核靠它区分「要 free 的是哪一个 action」。非共享中断传 NULL 也行，但养成习惯一律传设备结构指针。

十三、中断线程化在流程里的位置 #

request_threaded_irq 注册两个函数：handler 在硬中断上下文跑，thread_fn 在内核线程里跑。request_irq 就是 thread_fn 传 NULL 的特例。

线程化之后，一次中断要走两段：

段 跑在哪 谁触发 干什么
上半部 硬中断上下文，IRQ 关 硬件中断入口 action->handler，判断 + 清中断源，返回 IRQ_WAKE_THREAD
下半部 内核线程，可被调度 __irq_wake_thread → wake_up_process action->thread_fn，可睡眠、可拿 mutex

唤醒点在 __irq_wake_thread，kernel/irq/handle.c，三个动作：action->thread->flags & PF_EXITING 检查防止唤醒正在退出的线程；test_and_set_bit(IRQTF_RUNTHREAD, &action->thread_flags) 是幂等位，避免同一次中断重复叫醒；desc->threads_oneshot |= action->thread_mask 记下这次是哪个 action 触发的，IRQF_ONESHOT 场景下线程跑完靠它决定何时 unmask，最后 atomic_inc(&desc->threads_active) 再 wake_up_process(action->thread)。

threads_active 的用处是 synchronize_irq()：等这个计数归零，确保所有 handler 线程都跑完。free_irq 内部靠这一步保证「卸载时没有 handler 还在跑」。

线程化在整条脊柱上的位置很明确：它不改动第八节那条链的任何一环，只在第 7 步 __handle_irq_event_percpu 的 switch (res) 里多走一个分支。上半部、下半部共用同一个 irqaction，靠 thread_fn 是否为空区分。线程创建、优先级、IRQF_ONESHOT 的 unmask 时序在《中断下半部》和《驱动申请中断》里。

十四、中断退出与下半部的触发 #

__handle_domain_irq 末尾调 irq_exit()，关键在于判断条件：

c
void irq_exit(void)
{
    lockdep_assert_irqs_disabled();
    ...
    preempt_count_sub(HARDIRQ_OFFSET);

    if (!in_interrupt() && local_softirq_pending())
        invoke_softirq();
    ...
}

!in_interrupt() && local_softirq_pending()：当前不在任何中断上下文里（意味着硬中断、软中断、NMI 都已退干净），并且有挂起的软中断，才真正去处理。这个顺序保证软中断不会在硬中断嵌套里重入。

invoke_softirq 有两条路：没强制线程化就 __do_softirq() 当场跑，跑了 MAX_SOFTIRQ_TIME（2ms）或重启 MAX_SOFTIRQ_RESTART（10 次）还没完就唤醒 ksoftirqd 接手，防止软中断饿死用户进程；强制线程化则直接叫 ksoftirqd。

这里只交代一件事：irq_exit 是中断上下文与下半部的交界点。 上半部跑完，退出时才轮到 softirq；softirq 里再触发 tasklet；tasklet 里可以再往 workqueue 扔。四条线层次是硬中断 → softirq → tasklet → workqueue，越往后越能睡、延迟越大。细节全在《中断下半部》。

irq_exit 之后还有 set_irq_regs(old_regs) 恢复 pt_regs 指针，然后回到第九节的 __irq_svc/__irq_usr 尾部，svc_exit/ret_to_user_from_irq 恢复现场。至此一次中断走完。

十五、多核场景：中断亲和性与 IPI #

S3C2440 是单核 ARMv4T，上面整套代码里一个 SMP 分支都跑不到。但你不能只会单核，别人问你「多核怎么办」，得答得上来。

中断亲和性是中断和 CPU 的绑定关系。GIC 里每个 SPI 有 ITARGETS 寄存器，改它就改了「这个中断送到哪个 CPU」。Linux 把它抽象在 irq_desc.irq_data.common->affinity 这个 cpumask 上，改法有两种：

途径 接口 谁用
用户态 /proc/irq/N/smp_affinity 写一个十六进制掩码 运维调优
内核态 irq_set_affinity() / irq_set_affinity_hint() 驱动想让中断落在自己工作的那个 CPU 上
自动 irqbalance 守护进程周期性改掩码 通用服务器

最终都落到 irq_chip.irq_set_affinity(data, dest, force)。GIC 的实现就是往 ITARGETS 写掩码。这个回调在 S3C24xx 上根本没提供 —— s3c_irq_chip 里没有这一项，所以 /proc/irq/N/smp_affinity 在这个平台上写不进去。

亲和性的用处只有一条：让中断处理落在访问同一份数据的那个 CPU 上，减少 cache line 在核间来回弹。网卡多队列就是这么干的，每个队列一个中断、绑一个 CPU。

IPI（Inter-Processor Interrupt）是核间中断，走的是完全不同的路。它不是外设触发，是 CPU 自己写 GIC 的 SGI 寄存器打另一个 CPU。用途固定几种：resched（让对方重新调度）、stop（停机）、ipi_call（让所有核同步执行函数）。

在 ARM 上的入口就在第九节那段汇编里：ALT_SMP(test_for_ipi r0, r2, r6, lr) 判断这次挂起的中断位里有没有 IPI 那一组，有就走 do_IPI，没有就继续走外设中断那条。do_IPI 里读 gic_irq_data 的 IPI 描述符，取 handle_irq，跟外设中断一样走通用逻辑层。

irq_desc 上跟多核相关的字段，S3C2440 用不上的那批：

字段 作用
irq_data.common->affinity 这个 IRQ 允许落在哪些 CPU
irq_data.common->effective_affinity 实际生效的子集（硬件不一定支持多目标）
affinity_hint 给用户态的建议值，只影响 irqbalance
pending_mask 亲和性变更期间待重发的掩码
percpu_enabled 单个 IRQ 对单个 CPU 的使能位
IRQD_PER_CPU 标记这是个 per-CPU 中断，不走分发

IRQD_PER_CPU 那一项对应 handle_percpu_irq：这种中断不走 desc->action 链表分发，直接在每个 CPU 自己的 irq_desc 上跑，省掉遍历和加锁。ARM 的本地定时器、PMU 中断是这类。

再说一句边界：本章讲的是「多核的接口长什么样」，不是「S3C2440 支持多核」。别把它写进移植笔记当结论。

十六、一个平台初始化的完整时序 #

把前面十五节串成一条时间线，横轴是启动阶段，纵轴是数据结构被填成什么样：

时序 发生什么 irq_desc[16] 的状态 s3c_intc[0]
T0 内核入口 start_kernel 开始 不存在 不存在
T1 early_trap_init 向量表拷到 0xffff0000 不存在 不存在
T2 early_irq_init 111 项静态数组建好，全填默认 handle_irq = handle_bad_irq，action = NULL 不存在
T3 init_IRQ 进 s3c2440_init_irq 打 S3C2440: IRQ Support 同上 还没分配
T4 第一次 s3c24xx_init_intc 主控制器：填寄存器、清挂起、建 32 项 domain IRQ 16~47 逐个被 map 已分配，domain 就绪
T5 第二次 s3c24xx_init_intc 外部中断：24 项 domain，父为主控制器 IRQ 48~71 被 map，同时给 IRQ 20/21 换 s3c_irq_demux 不变，sub_intc/sub_bits 被填
T6 第三次 s3c24xx_init_intc 内部子中断：29 项 domain IRQ 74~102 被 map，同时给 IRQ 22/23/31/37/38 换 s3c_irq_demux 同上，更多 sub_bits 置位
T7 set_handle_irq handle_arch_irq = s3c24xx_handle_irq 不变 不变
T8 设备模型起来 驱动 probe 里 request_irq action 链表挂上你的 handler，depth 减到 0 不变
T9 第一次中断 第八节那条链跑通 irq_count 开始涨 不变
T5、T6 那两行的「被 map」和「换 demux」是同一件事的两面，别理解成两个阶段。s3c24xx_irq_map 一次调用里既给子中断装自己的 chip/handler，又反手把父中断的 handle_irq 换掉。

T7 是全局开关。在它之前 handle_arch_irq 是 arch_irq_handler_default 那条默认路，在它之后换成 s3c24xx_handle_irq。这个赋值发生在第一次 s3c24xx_init_intc 里，也就是 T4 —— 不是 T7 才做。表里单列一行是为了强调它是「一次性、全局」的动作，写在 set_handle_irq 里有 if (handle_arch_irq) return -EBUSY; 保护，第二次调用会失败但没人检查返回值。

一个容易忽略的细节：三次 s3c24xx_init_intc 各自都调了 set_handle_irq。第一次成功，第二三次返回 -EBUSY 被无视。这不影响功能，但你要是往这个函数里加逻辑，别指望它每次都执行。
