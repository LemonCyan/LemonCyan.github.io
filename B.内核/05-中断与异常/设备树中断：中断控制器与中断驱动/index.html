设备树中断：中断控制器与中断驱动 #

设备树里的 interrupts 一行数字，是怎么变成 /proc/interrupts 里那几行、又能被 devm_request_irq 申请到的？本篇沿着「控制器注册 → 属性解析 → 驱动申请」这三段走一遍，用例是 S3C2440 的按键中断。语法背景见 设备树基础与语法，pinctrl 侧见 pinctrl：引脚复用与电气属性。

一、S3C2440 的中断家底 #

类别 数量 说明
主中断 32 SRCPND 每一位一个
内部子中断 15 UART/I2C 等外设内部再细分
外部中断 24 EINT0~7(GPF)、EINT8~23(GPG)

主中断寄存器：

寄存器 地址 要点
SRCPND 0x4A000000 写 1 清
INTMOD 0x4A000004 置 1 则该中断走 FIQ
INTMSK 0x4A000008 置 1 屏蔽
INTPND 0x4A000010 同一时刻只有一位为 1，写 1 清
INTOFFSET 0x4A000014 当前主中断号，硬件直接告诉你
SUBSRCPND 0x4A000018 子中断挂起
INTSUBMSK 0x4A00001C 子中断屏蔽

处理一个中断的固定动作序列是：读 INTOFFSET 知道是谁 → 读 SRCPND 确认 → 写 SRCPND 的对应位清源 → 写 INTPND 的对应位清挂起。少写一步就会反复进中断。

二、设备树里的中断控制器 #

dts
intc: interrupt-controller@4a000000 {
    compatible = "samsung,s3c2410-irq";
    reg = <0x4a000000 0x100>;
    interrupt-controller;          /* 我是中断控制器 */
    #interrupt-cells = <4>;        /* 一个中断用 4 个数描述 */
    /* 没有 interrupt-parent —— 这就是根中断控制器 */
};

外部中断控制器挂在 pinctrl 里（见 pinctrl 篇），并用 interrupt-parent 指回根控制器：

dts
&pinctrl_0 {
    gpf: gpf {
        gpio-controller;
        #gpio-cells = <2>;
        interrupt-controller;
        #interrupt-cells = <2>;    /* 外部中断只有「号 + 触发类型」 */
        interrupt-parent = <&intc>;
    };

    gpg: gpg {
        /* 同上 */
    };
};

四个 cell 的含义由这个控制器的 irq_domain_ops->xlate（S3C24xx 是 s3c24xx_irq_xlate_of）解释。cell 的语义不是内核规定的，是驱动定义的——换一颗 SoC 就必须重新查它 bindings 文档。

三、根中断控制器是怎么注册的 #

text
start_kernel
  init_IRQ()                              arch/arm/kernel/irq.c
    machine_desc->init_irq()              没开 OF 时走这里
    或 irqchip_init()                     开了 OF 且没指定 init_irq
      of_irq_init(__irqchip_of_table)
        -> 遍历表里的 of_device_id
        -> 命中后用 init 回调（s3c2410_init_intc_of）注册
           irq_domain_create_linear()     主中断域
           irq_domain_create_linear()     子中断域

c
/* arch/arm/kernel/irq.c */
void __init init_IRQ(void)
{
        if (IS_ENABLED(CONFIG_OF) && !machine_desc->init_irq)
                irqchip_init();
        else
                machine_desc->init_irq();
        /* L2 cache 初始化 ... */
}

__irqchip_of_table 这个表来自链接脚本：

text
/* arch/arm/kernel/vmlinux.lds */
.init.data : {
    ...
    . = ALIGN(8);
    __irqchip_of_table = .;
    KEEP(*(__irqchip_of_table))
    KEEP(*(__irqchip_of_table_end))
    ...
}

驱动侧用 IRQCHIP_DECLARE 把自己的 of_device_id 塞进这个段，于是注册不需要任何人调用，链接器就替你排好了。这是 Linux 里反复出现的一种「段即注册表」模式（CLK_OF_DECLARE、TIMER_OF_DECLARE 同理）。

四、interrupts 属性怎么变成 IRQ number #

全程发生在 device_node → platform_device 的转换里：

text
of_platform_default_populate_init
  of_platform_default_populate
    of_platform_populate
      of_platform_bus_create
        of_platform_device_create_pdata
          of_device_alloc
            of_irq_count()                 -- 数有几个中断
            of_irq_to_resource_table()
              of_irq_to_resource
                irq_of_parse_and_map
                  of_irq_parse_one
                  irq_create_of_mapping
                    irq_create_fwspec_mapping
                      irq_domain_translate   -> s3c24xx_irq_xlate_of
                      irq_create_mapping     -> 建 hwirq -> virq 映射
                        irq_domain_associate
                          -> s3c24xx_irq_map_of

两个关键点：

  1. of_irq_count() 靠反复调 of_irq_parse_one() 数个数，而后者要先找到 interrupt-parent、读出它的 #interrupt-cells，才知道一行有几个数；
  2. irq_create_mapping() 分配的是全局唯一的 virq，与硬件 hwirq 不一定相等。S3C2440 上 EINT8 的 hwirq 是 0，但 virq 是 16。

五、寄存器申请：从驱动视角看 #

5.1 标准写法 #

c
static int my_probe(struct platform_device *pdev)
{
    int irq, ret;

    irq = platform_get_irq(pdev, 0);       /* 第 0 个中断 */
    if (irq < 0)
        return irq;

    ret = devm_request_irq(&pdev->dev, irq, my_handler,
                           0,                 /* flags=0 -> 用 dts 里的触发方式 */
                           dev_name(&pdev->dev), priv);
    return ret;
}

串口驱动一次申请两个（收 + 发）：

c
ret = platform_get_irq(platdev, 0);    /* RX */
ret = platform_get_irq(platdev, 1);    /* TX */

5.2 一个节点多个中断：按键 6 路 #

dts
mykey: mykey {
    compatible = "mykey";
    interrupt-parent = <&gpg>;
    interrupts = <0 IRQ_TYPE_EDGE_BOTH>,
                 <3 IRQ_TYPE_EDGE_BOTH>,
                 <5 IRQ_TYPE_EDGE_BOTH>,
                 <6 IRQ_TYPE_EDGE_BOTH>,
                 <7 IRQ_TYPE_EDGE_BOTH>,
                 <11 IRQ_TYPE_EDGE_BOTH>;
};

#interrupt-cells = <2>，所以每行两个数：gpg 域内的硬件中断号（从 0 开始）+ 触发方式。GPB/GPG 的硬件号是 bank 内偏移，不是全局 EINT 编号：

引脚 全局外部中断 gpg 域内 hwirq virq（实测）
GPG0 EINT8 0 16
GPG3 EINT11 3 17
GPG5 EINT13 5 18
GPG6 EINT14 6 19
GPG7 EINT15 7 20
GPG11 EINT19 11 21

驱动：

c
static irqreturn_t button_irq(int irq, void *dev_id)
{
    printk("%s enter, irq: %d, %s\n", __func__, irq, (char *)dev_id);
    return IRQ_HANDLED;
}

static int button_probe(struct platform_device *pdev)
{
    int i, ret, irq;
    char *name;

    for (i = 0; i < 6; i++) {
        irq = platform_get_irq(pdev, i);
        if (irq <= 0) {
            dev_err(&pdev->dev, "cannot find irq index %d\n", i);
            return irq;
        }
        name = kasprintf(GFP_KERNEL, "key-%d", i + 1);
        ret = devm_request_irq(&pdev->dev, irq, button_irq, 0, name, name);
        if (ret)
            return ret;
    }
    return 0;
}

5.3 验证 #

bash
[root@zy:/]# cat /proc/interrupts
           CPU0
  7:       1694  s3c-eint   7 Edge      eth0
 16:          3  s3c-eint   0 Edge      key-1
 17:          0  s3c-eint   3 Edge      key-2
 18:          0  s3c-eint   5 Edge      key-3
 19:          2  s3c-eint   6 Edge      key-4
 20:          1  s3c-eint   7 Edge      key-5
 21:          0  s3c-eint  11 Edge      key-6
 27:          4       s3c  27 Edge      54000000.i2c
 32:          9  s3c-level  32 Level     50000000.serial
 33:         60  s3c-level  33 Level     50000000.serial
 59:          0  s3c-level  59 Edge      53000000.watchdog
Err:          0

四列含义：virq : 计数 控制器名 hwirq 触发方式 设备名。第三列的控制器名（s3c-eint / s3c / s3c-level）直接告诉你这个中断挂在哪个 irq_domain 上。

六、注册结果：三个 irq_domain #

整个 2440 起来之后是这么三层：

控制器 irq_domain 大小 覆盖 谁注册
主中断 64（线性） 32 个主中断 s3c2410_init_intc_of
子中断 64（线性） 15 个内部子中断 s3c2410_init_intc_of
外部中断 gpf 8 / gpg 16 EINT0~23 samsung_pinctrl_probe

最后一行是易忽略的点：外部中断控制器是 pinctrl 驱动注册的，所以想用 EINT，设备树里必须有 gpf/gpg 节点，且 pinctrl 驱动已经 probe 完成。

七、中断链路的完整时间线 #

text
1. start_kernel -> init_IRQ -> irqchip_init
     根中断控制器注册（主 + 子两个 domain）
2. arch_initcall_sync -> of_platform_populate
     遍历设备树，把带 compatible 的节点转成 platform_device
     解析 interrupts -> 分配 virq -> 填 resource[IORESOURCE_IRQ]
3. device 与 driver 匹配 -> really_probe -> pinctrl_bind_pins
     pinctrl 驱动 probe -> 注册外部中断控制器（gpf/gpg domain）
4. my_probe -> platform_get_irq -> devm_request_irq
     把 virq 与 handler 绑到 irq_desc 上
5. 硬件来中断 -> 汇编入口 -> 根控制器处理 -> 分发到 handler

第 2 步分配 virq 时，外部中断的 domain 可能还没注册（它要等 pinctrl probe）。这种情况下内核返回 -EPROBE_DEFER，驱动会被延后重试——如果你的按键驱动 probe 一直不进来，先看是不是少了 interrupt-parent 指向的节点。

八、调试命令与常见故障 #

bash
cat /proc/interrupts           # 谁申请了哪个 virq
cat /proc/irq/16/spurious      # 误触发计数
cat /sys/kernel/debug/irq/irq-16/  # domain 信息（需 debugfs）
dmesg | grep -i irq
现象 原因
cannot find irq index 0 dts 没有 interrupts 属性，或节点没转成 platform_device
request_irq failed: -22 #interrupt-cells 与 interrupts 字段数不一致
申请成功但中断进不来 EINTMASK / INTMSK 没打开；或引脚没复用成 EINT
中断疯狂触发 只清了 SRCPND 没清 INTPND，或触发方式配成了 LEVEL
virq 与预期不同 正常现象：virq 全局分配，不等于 hwirq
按键一次按下触发两次 双边沿触发 + 机械抖动，需要在驱动里做去抖
