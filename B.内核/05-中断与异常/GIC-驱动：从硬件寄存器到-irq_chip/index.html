一、GIC 在中断子系统里的位置 #

从下往上三层。硬件是 GIC-400 或 A15 片内 GIC，收外设中断线、比优先级、送一路给 CPU；驱动是 drivers/irqchip/irq-gic.c，初始化寄存器、提供 irq_chip 回调、提供 IPI 发送；通用层是 kernel/irq/*，管 irq domain 映射、irq_desc、flow handler、request_irq。驱动在中间干两件事。一是把物理控制器包装成 generic irq 认识的东西：struct irq_domain 管 hwirq ↔ IRQ number 翻译，struct irq_chip 管 mask / unmask / ack / eoi / set_type / set_affinity。二是接管 CPU 入口：ARM 的 IRQ 向量跳到 arch_irq_handler_default，再经 handle_arch_irq 函数指针进 gic_handle_irq，这个指针由 set_handle_irq() 在初始化时挂上。 于是 /proc/interrupts 里每一行的背后是：硬件一条中断线 → GICD 里的 enable 位 → CPU interface 的优先级比较 → GICC_IAR 读出 ID → irq domain 查表 → irq_desc → flow handler → 你的 handler。本篇按这个顺序拆。

二、GIC-V2 的功能框图和寄存器分区 #

输入侧是外设中断线，PPI（Private Peripheral Interrupt）每核一套，SPI（Shared Peripheral Interrupt）全局共享。GICD_TYPER 报告硬件实现了多少条 SPI（GIC-400 最多 480）和多少个 CPU interface（最多 8 个），有几个 CPU interface 就有几组 PPI 信号线。一组 PPI 线里 6 根实际信号（GIC-400 / A15）：

信号线 interrupt ID 来源
nLEGACYIRQ 31 bypass 模式下直连某 CPU 的 nIRQCPU
nCNTPNSIRQ 30 Non-secure physical timer
nCNTPSIRQ 29 Secure physical timer
nLEGACYFIQ 28 bypass 模式直连 nFIQCPU
nCNTVIRQ 27 Virtual timer，虚拟化相关
nCNTHPIRQ 26 Hypervisor timer，虚拟化相关

Cortex-A15 的实现多一根 Virtual Maintenance Interrupt（ID 25）。Cortex-A9 只有 5 根：nLEGACYIRQ / nLEGACYFIQ 占 31 和 28，private timer 和 watchdog timer 占 29、30，global timer 占 27。输出侧三样：nIRQCPU / nFIQCPU 触发 CPU 进 IRQ / FIQ 模式；nFIQOUT / nIRQOUT 去电源管理模块唤醒 CPU；AXI slave interface 是 CPU 访问 GIC 寄存器的通道。内部切两块：Distributor 和 CPU interface，虚拟化的 Virtual CPU interface 本篇不碰。GIC-400 的寄存器帧按顺序排 4KB 页：

块 帧内偏移 每 CPU 一份 驱动里对应
Distributor（GICD） 0x0000 否，全局一份 of_iomap(node, 0)
CPU Interface（GICC） 0x1000 是，每核一个 of_iomap(node, 1)
Virtual Interface Control（GICH） 0x2000 否 3.17 的驱动没映射
Virtual CPU Interface（GICV） 0x4000 是 3.17 的驱动没映射

绝对地址由 SoC 决定，DT 的 reg 说话。RK3288 上是这样（原文取自 RK3288 的 DTS）：

dts
gic: interrupt-controller@ffc01000 {
	compatible = "arm,gic-400";
	interrupt-controller;
	#interrupt-cells = <3>;
	#address-cells = <0>;
	reg = <0xffc01000 0x1000>,	/* Distributor */
	      <0xffc02000 0x1000>,	/* CPU interface */
	      <0xffc04000 0x2000>,	/* Virtual interface control block */
	      <0xffc06000 0x2000>;	/* Virtual CPU interfaces */
	interrupts;
};

驱动只 of_iomap 前两段（index 0 和 1），虚拟化那两段没映射。

三、Distributor：全局中断的开关与路由 #

Distributor 干四件事，全是全局性质：开关中断（GICD_CTLR 管全局，GICD_ICENABLERn 管单条）；把当前优先级最高的事件送到一个或一组 CPU interface，送多个时硬件保证只 assert 一个 CPU；在一堆 pending 里按优先级挑最高的往上送；管属性（GICD_ICFGRn 定 level / edge，GICD_IGROUPRn 定 group 0 / 1）。GICD_CTLR 在 3.17 的驱动里只有两种写法：初始化开头写 0，结尾写 1。写 1 只使能 group 0。整个驱动没碰过 GICD_IGROUPRn，它赌复位缺省把中断都划进 group 0——复位后该寄存器全 0，这个赌成立。但 secure 侧若有固件改过 group 划分，这段代码就不成立，真实产品里最好显式配一遍。 GICD_ITARGETSRn 是路由的落点，一字节一个中断，bit 位置就是 CPU interface 号。前 8 个（GICD_ITARGETSR0 ~ 7，覆盖 ID 0~31）是只读的，因为 SGI 和 PPI 私有、没有「路由到别人」这回事。读它们返回「本核接在哪个 CPU interface 上」的 mask，CPU0 接在 CPU interface 4 上就读回 0b00010000。这是第九小节 gic_get_cpumask() 有得可读的唯一依据。

四、CPU Interface：每个核私有的那一套 #

CPU interface 是 Distributor 到 CPU 的最后一道闸，管六件事：GICC_CTLR 总开关，关掉后 Distributor 送来事件也不 assert nIRQCPU；读 GICC_IAR 应答，读的动作本身把中断从 pending 改成 active（电平线仍拉着就是 active-and-pending）并 deassert nIRQCPU / nFIQCPU，返回值低 10 位是 interrupt ID、高位是 CPU ID；写 GICC_EOIR 结束，硬件做 priority drop 并通知 Distributor 清 active；GICC_PMR 定优先级门限；GICC_BPR 定抢占粒度；多个中断同时到时挑优先级最高的一个。最后一条的措辞要抠：「挑」发生在读 GICC_IAR 的瞬间，不是中断线拉高的时候。所以 handler 里做再久的事，只要不 EOI，同优先级和更低优先级的都进不来。

五、中断状态机：inactive / pending / active / active-and-pending #

GIC 里每条中断线有四个状态，这套状态机是理解 ack / eoi 时序的全部基础。inactive 是没中断也没在处理；pending 是源拉起来了等 CPU 来取；active 是 CPU 已 ack、正在处理、还没 EOI；active-and-pending 是正在处理而源又拉了一次，电平中断的典型形态。迁移关系：

当前状态 事件 迁移到 备注
inactive 中断源 assert（电平拉高 / 边沿到来） pending Distributor 记为待处理
pending CPU 读 GICC_IAR，且它优先级最高 active 同刻 deassert nIRQCPU
pending 读 GICC_IAR 时源仍 assert active-and-pending 电平中断常直接进双状态
active 写 GICC_EOIR，源已撤销 inactive 一次完整中断服务结束
active 写 GICC_EOIR，源仍 assert pending 立刻又 pending，等下次 ack
active-and-pending 写 GICC_EOIR pending 电平原样拉着，优先级掉落
active-and-pending 源撤销后再写 GICC_EOIR inactive 两个条件都满足才算完
pending 写 GICD_ICPENDRn 对应位 inactive 软件主动丢弃
pending 该线被 GICD_ICENABLERn 关掉 pending（不变） 不 forward，但 pending 不丢

看这张表能推出三件事。一是 EOI 之后电平中断会立刻再 pending，所以 level 中断的 handler 必须先把设备侧中断源清掉再让 EOI 发生，否则出 gic_eoi_irq 就原地再进一次，这是中断风暴的机制。二是 active-and-pending 是 GIC 允许嵌套同一条中断的结构性原因，不是异常。三是 GICD_ICENABLERn 不清 pending，驱动 disable 一条还没处理完的中断后 pending 位还在，重新 enable 会立刻补一次，这解释了不少「关了中断怎么还进来」的现场。SGI 没有电平概念，固定边沿语义，画不出 active-and-pending 这一格。

六、GIC 的中断类型：SGI / PPI / SPI #

ID 空间这样切：0 ~ 15 是 SGI（Software-Generated Interrupt），软件写 GICD_SGIR 触发，用于核间通信；16 ~ 31 是 PPI，每核私有的外设线，timer 都在这里；32 ~ 1019 是 SPI，外部外设全局共享；1020 ~ 1023 规范留给特定用途。1019 是规范上限，具体实现少得多：GIC-400 最多 480 个 SPI，Cortex-A15 和 A9 上最多 224 个。

维度 SGI PPI SPI
ID 范围 0~15 16~31 32~1019（实际见 GICD_TYPER）
谁产生 软件写 GICD_SGIR 片内外设固定连线 外部设备中断线
私有性 每 CPU 私有 每 CPU 私有 全局共享
目标核由谁定 GICD_SGIR 里的 target list 硬件固定本核 GICD_ITARGETSRn
触发类型 固定边沿，不可改 可配（GICD_ICFGRn） 可配（GICD_ICFGRn）
是否进 irq domain 不进 进（root GIC 从 16 起） 进
配置寄存器是否 banked 是 是 否，全局
典型用途 IPI：resched、stop、跨核调用 本地 timer、PMU 网卡、UART、USB、DMA

「banked」在本篇反复出现，含义是同一个地址上有多份寄存器副本，每个 CPU 访问同一地址却摸到自己的那一份。SoC 把 GIC 做成非 banked 形态时地址要按核偏移，偏移 = cpu-offset × cpu-nr，这就是 DT 里 cpu-offset 属性的来历。SGI 不进 irq domain，是因为它没有「一条固定的硬件中断线」这回事：一次 SGI 由源 CPU interface、interrupt ID、目标 CPU interface 列表三元组唯一确定，映射成 IRQ number 没有意义，核间通信走 set_smp_cross_call() 挂的 gic_raise_softirq 那条独立通道。SPI 只看 ID 就够，PPI 和 SGI 光看 ID 不够、还得带上是哪个 CPU interface，所以它们的状态、enable 位、优先级都是 per-CPU 的 banked 寄存器。

七、irq chip driver 的初始化入口 #

驱动靠一个专用 ELF section 知道自己该初始化。drivers/irqchip/irqchip.h 里的 IRQCHIP_DECLARE 把 compatible 字符串和初始化函数打包成 static const struct of_device_id，扔进 __irqchip_of_table section：

c
#define IRQCHIP_DECLARE(name, compat, fn) OF_DECLARE_2(irqchip, name, compat, fn)

#define OF_DECLARE_2(table, name, compat, fn) \
        _OF_DECLARE(table, name, compat, fn, of_init_fn_2)

#define _OF_DECLARE(table, name, compat, fn, fn_type)           \
    static const struct of_device_id __of_table_##name        \
        __used __section(__##table##_of_table)            \
         = { .compatible = compat,                \
             .data = (fn == (fn_type)NULL) ? fn : fn  }

irq-gic.c 里连开六个：

c
IRQCHIP_DECLARE(gic_400, "arm,gic-400", gic_of_init);
IRQCHIP_DECLARE(cortex_a15_gic, "arm,cortex-a15-gic", gic_of_init);
IRQCHIP_DECLARE(cortex_a9_gic, "arm,cortex-a9-gic", gic_of_init);
IRQCHIP_DECLARE(cortex_a7_gic, "arm,cortex-a7-gic", gic_of_init);
IRQCHIP_DECLARE(msm_8660_qgic, "qcom,msm-8660-qgic", gic_of_init);
IRQCHIP_DECLARE(msm_qgic2, "qcom,msm-qgic2", gic_of_init);

六个字符串、六个条目、一个 gic_of_init，这就是「一份代码覆盖所有 GIC-v2 实现」的落地方式。匹配时 name、type、compatible 三项都参与判断，细节在 __of_device_is_compatible：

c
struct of_device_id
{
    char    name[32];        /* 要匹配的 device node 名字 */
    char    type[32];        /* 要匹配的 device node 类型 */
    char    compatible[128]; /* DT compatible string，主力匹配项 */
    const void *data;        /* 对 GIC 而言是初始化函数指针 */
};

入口链条是 irqchip_init() → of_irq_init(__irqchip_begin) → 从 root 开始逐节点匹配：

c
void __init irqchip_init(void)
{
    of_irq_init(__irqchip_begin);
}
环节 位置 动作
machine driver 初始化 arch/arm/mach-*/ 调 irqchip_init()
irqchip_init drivers/irqchip/irqchip.c 调 of_irq_init(__irqchip_begin)
of_irq_init drivers/of/irq.c 挑出所有中断控制器节点，建成树，从 root 逐个匹配
匹配命中 — 调 gic_of_init(node, parent)

__irqchip_begin 是 __irqchip_of_table 的首地址。of_irq_init 执行时 DT 已展开成树，它扫全树挑出中断控制器节点、按父子关系排好序——排序有意义，级联结构里子控制器注册要用父控制器的 irq domain，父必须先在。系统可以有多个 controller 连成一棵树，root 是主 GIC，second GIC 挂在 root 下面当它的一个普通中断源，初始化顺序就是这棵树的先序。

八、gic_of_init 与 Device Tree 解析 #

c
int __init gic_of_init(struct device_node *node, struct device_node *parent)
{
    void __iomem *cpu_base;
    void __iomem *dist_base;
    u32 percpu_offset;
    int irq;

    dist_base = of_iomap(node, 0);      /* 映射 GIC Distributor 寄存器空间 */
    cpu_base = of_iomap(node, 1);       /* 映射 GIC CPU interface 寄存器空间 */

    if (of_property_read_u32(node, "cpu-offset", &percpu_offset))
        percpu_offset = 0;

    gic_init_bases(gic_cnt, -1, dist_base, cpu_base, percpu_offset, node);

    if (!gic_cnt)
        gic_init_physaddr(node);

    if (parent) {                        /* 处理 interrupt 级联 */
        irq = irq_of_parse_and_map(node, 0);
        gic_cascade_irq(gic_cnt, irq);
    }

    gic_cnt++;
    return 0;
}

of_iomap(node, 0) 和 (node, 1) 取 DT reg 的第 0 段和第 1 段，就是 GICD 和 GICC 两个 4KB 页；第 2、3 段没映射，这是判断「这版驱动不支持虚拟化」的直接依据。cpu-offset 属性缺失时取 0，等价于 banked 实现。gic_init_bases() 是主处理过程，下一小节拆。gic_init_physaddr() 只在 CONFIG_BL_SWITCHER（big.LITTLE switcher）下非空，为 switcher 记录 GIC 物理地址，没开配置时是空函数，if (!gic_cnt) 让它只在 root GIC 上跑一次。parent 非空说明这是二级 GIC，gic_cascade_irq() 那条路径要走到；一级 GIC 的 parent 是 NULL，整段跳过。

gic_init_bases：把 domain 和 irq_chip 搭起来 #

c
void __init gic_init_bases(unsigned int gic_nr, int irq_start,
                           void __iomem *dist_base, void __iomem *cpu_base,
                           u32 percpu_offset, struct device_node *node)
{
    irq_hw_number_t hwirq_base;
    struct gic_chip_data *gic;
    int gic_irqs, irq_base, i;

    gic = &gic_data[gic_nr];
    gic->dist_base.common_base = dist_base;   /* 省掉了 non banked 分支 */
    gic->cpu_base.common_base = cpu_base;
    gic_set_base_accessor(gic, gic_get_common_base);

    for (i = 0; i < NR_GIC_CPU_IF; i++)
        gic_cpu_map[i] = 0xff;

    if (gic_nr == 0 && (irq_start & 31) > 0) {              /* (a) */
        hwirq_base = 16;
        if (irq_start != -1)
            irq_start = (irq_start & ~31) + 16;
    } else {
        hwirq_base = 32;
    }

    gic_irqs = readl_relaxed(gic_data_dist_base(gic) + GIC_DIST_CTR) & 0x1f;  /* (b) */
    gic_irqs = (gic_irqs + 1) * 32;
    if (gic_irqs > 1020)
        gic_irqs = 1020;
    gic->gic_irqs = gic_irqs;

    gic_irqs -= hwirq_base;                                  /* (c) */

    if (of_property_read_u32(node, "arm,routable-irqs",      /* (d) */
                             &nr_routable_irqs)) {
        irq_base = irq_alloc_descs(irq_start, 16, gic_irqs, numa_node_id()); /* (e) */
        if (IS_ERR_VALUE(irq_base)) {
            WARN(1, "Cannot allocate irq_descs @ IRQ%d, assuming pre-allocated\n",
                 irq_start);
            irq_base = irq_start;
        }

        gic->domain = irq_domain_add_legacy(node, gic_irqs, irq_base,   /* (f) */
                           hwirq_base, &gic_irq_domain_ops, gic);
    } else {
        gic->domain = irq_domain_add_linear(node, nr_routable_irqs,     /* (f) */
                                   &gic_irq_domain_ops,
                                   gic);
    }

    if (gic_nr == 0) {   /* 只对 root GIC 做，callback 和 notifier 注册一次就够 */
#ifdef CONFIG_SMP
        set_smp_cross_call(gic_raise_softirq);                 /* (g) */
        register_cpu_notifier(&gic_cpu_notifier);              /* (h) */
#endif
        set_handle_irq(gic_handle_irq);
    }

    gic_chip.flags |= gic_arch_extn.flags;

    gic_dist_init(gic);
    gic_cpu_init(gic);
    gic_pm_init(gic);
}

(a) hwirq_base。 gic_nr == 0 是 root GIC，irq_start & 31 判断调用者有没有要求 IRQ number 对齐。hwirq_base = 16 表示从 ID 16 开始映射、跳过 16 个 SGI（软件中断，核间通信，不需要 IRQ number）；hwirq_base = 32 连 PPI 也跳过，这是二级 GIC 的形态——它的 SGI 和 PPI 都冗余，主 GIC 已提供。本场景 irq_start = -1 不指定 IRQ number，指定时要做 (irq_start & ~31) + 16 对齐。

(b) 数中断。 GIC_DIST_CTR 是 V1 风格老宏名，V2 里对应 GICD_TYPER。低 5 位 ITLinesNumber 值 N 表示支持 32 × (N+1) 条，规范卡死上限 1020，1020 ~ 1023 留给特殊用途。

(c) 减法。 减掉 hwirq_base 才是要分配的 IRQ number 个数，变量名到这一步才名副其实。

(d) crossbar。 arm,routable-irqs 描述那些不直连 GIC、经 crossbar / multiplexer 接到 GIC 上的中断请求数目，有这属性的 SoC 走 linear domain 分支。

九、Distributor 初始化：gic_dist_init #

c
static void __init gic_dist_init(struct gic_chip_data *gic)
{
    unsigned int i;
    u32 cpumask;
    unsigned int gic_irqs = gic->gic_irqs;      /* 该 GIC 的 IRQ 数目 */
    void __iomem *base = gic_data_dist_base(gic);  /* Distributor 基地址 */

    writel_relaxed(0, base + GIC_DIST_CTRL);    /* (a) */

    cpumask = gic_get_cpumask(gic);             /* (b) */
    cpumask |= cpumask << 8;
    cpumask |= cpumask << 16;                   /* (c) */

    for (i = 32; i < gic_irqs; i += 4)
        writel_relaxed(cpumask, base + GIC_DIST_TARGET + i * 4 / 4);  /* (d) */

    gic_dist_config(base, gic_irqs, NULL);      /* (e) */

    writel_relaxed(1, base + GIC_DIST_CTRL);    /* (f) */
}

(a) 先全关。 往 GICD_CTLR 写 0，Distributor 停止向任何 CPU interface 送请求，group 0 和 group 1 一起停。初始化期间必须先关门，否则写寄存器的过程中随时会被半配置状态的中断打断。

(f) 最后再开。 写 1 只使能 group 0，前提是复位缺省把中断都划在 group 0。relaxed 后缀去掉的是 readl / writel 之间的编译器与 CPU 屏障语义，不是设备访问本身的序。寄存器之间没有数据依赖且顺序无关时用它省指令。补屏障的地方在 gic_dist_config() 末尾的 sync_access()，这次传 NULL，所以没补。

gic_get_cpumask：读回本核挂在哪 #

c
static u8 gic_get_cpumask(struct gic_chip_data *gic)
{
    void __iomem *base = gic_data_dist_base(gic);
    u32 mask, i;

    for (i = mask = 0; i < 32; i += 4) {
        mask = readl_relaxed(base + GIC_DIST_TARGET + i);
        mask |= mask >> 16;
        mask |= mask >> 8;
        if (mask)
            break;
    }

    return mask;
}

读的是 GICD_ITARGETSR0 ~ 7，覆盖 ID 0~31。第三小节说过这几个对 SGI / PPI 只读，返回值是「本核接在第几号 CPU interface 上」。寄存器 32 位里 4 个字节，4 个中断的 mask 被复制了 4 份，循环连做两次右移折叠：>>16 把高 16 位压下来，>>8 再把次 8 位压下来，最后低 8 位就是那一份 mask 的 OR 结果。读到非 0 就跳出——ID 0 的 mask 一定有值，第一轮就退出。CPU0 接在 CPU interface 4 上，读回来是 0b00010000。

(c) 8 位扩 32 位。 cpumask |= cpumask << 8 再 << 16，把 8 个 bit 复制四份铺满 32 位，因为下一步要写 GICD_ITARGETSRn，那个寄存器每个字节管一个中断、四个字节得填同一个 mask。

(d) 给每条 SPI 定目标。 i 从 32 起、一次跨 4 个中断，i * 4 / 4 就是该组在 GICD_ITARGETSRn 里的字节偏移。效果是所有 SPI 都只送到「初始化时跑这段代码的那个核」，多核系统里这意味着 SPI 全钉在 BSP 上，靠 gic_set_affinity 或 irqbalanced 才摊开。

gic_dist_config：批量刷缺省值 #

c
void __init gic_dist_config(void __iomem *base, int gic_irqs,  void (*sync_access)(void))
{
    unsigned int i;

    /* Set all global interrupts to be level triggered, active low.    */
    for (i = 32; i < gic_irqs; i += 16)
        writel_relaxed(0, base + GIC_DIST_CONFIG + i / 4);

    /* Set priority on all global interrupts.   */
    for (i = 32; i < gic_irqs; i += 4)
        writel_relaxed(0xa0a0a0a0, base + GIC_DIST_PRI + i);

    /* Disable all interrupts.  Leave the PPI and SGIs alone as they are
       enabled by redistributor registers.    */
    for (i = 32; i < gic_irqs; i += 32)
        writel_relaxed(0xffffffff, base + GIC_DIST_ENABLE_CLEAR + i / 8);

    if (sync_access)
        sync_access();
}

三趟循环、三个寄存器组、步长各不相同，全由位宽决定：

循环 步长 寄存器 每组位数 写法 效果
触发类型 16 GIC_DIST_CONFIG，偏移 i/4 2 位/中断 全 0 level + active-high
优先级 4 GIC_DIST_PRI，偏移 i 8 位/中断 0xa0a0a0a0 每条中断都是 0xa0
使能 32 GIC_DIST_ENABLE_CLEAR，偏移 i/8 1 位/中断 全 1 全部关闭

偏移算式拆开看：GICD_ICFGRn 一个字管 16 个中断，组号 i/16、字节偏移 (i/16)*4 = i/4；GICD_IPRIORITYRn 一字节管一个中断，第 i 个就在基址 +i；GICD_ICENABLERn 一位管一个中断，组号 i/32、字节偏移 (i/32)*4 = i/8。优先级 0xa0，数值越小优先级越高，0xa0 属于偏低的中间档。这些都是缺省值，后面各设备驱动初始化时还会按需改，触发类型尤其常被 DTS 里 interrupts 的第三格覆盖。GIC_DIST_CONFIG 那趟写 0 的语义：GICD_ICFGRn 每 2 位里低 1 位是配置位，高位在 SPI 上是保留位，写 0 表示 level-sensitive。注释里那句 active low 是照抄来的措辞，GICD_ICFGRn 只管 level / edge，极性由外设侧信号决定，这条注释容易误导。

十、CPU Interface 初始化：gic_cpu_init #

c
static void gic_cpu_init(struct gic_chip_data *gic)
{
    void __iomem *dist_base = gic_data_dist_base(gic);  /* Distributor 基地址 */
    void __iomem *base = gic_data_cpu_base(gic);        /* CPU interface 基地址 */
    unsigned int cpu_mask, cpu = smp_processor_id();    /* 本 CPU 逻辑 ID */
    int i;

    cpu_mask = gic_get_cpumask(gic);                    /* (a) */
    gic_cpu_map[cpu] = cpu_mask;

    for (i = 0; i < NR_GIC_CPU_IF; i++)
        if (i != cpu)
            gic_cpu_map[i] &= ~cpu_mask;                /* (b) */

    gic_cpu_config(dist_base, NULL);                    /* (c) */

    writel_relaxed(0xf0, base + GIC_CPU_PRIMASK);       /* (d) */
    writel_relaxed(1, base + GIC_CPU_CTRL);             /* (e) */
}

(a) 建映射表。 软件用 CPU 逻辑 ID（smp_processor_id()），硬件用 CPU interface 号，gic_cpu_map[] 这张 lookup table 把逻辑 ID 翻成 mask。gic_init_bases 里把它全填成 0xff（谁都不掩），这里按实际情况修正。

(b) 清掉别人的 bit。 本核 mask 之外的 entry 里把本核那一位置 0，这样 gic_cpu_map[cpu] 只描述「本核在哪个 CPU interface 上」。gic_cpu_init 在每个核上各跑一次、每次都在改同一张全局表，所以这一步的语义是「各自申明自己那一位」：BSP 先跑，non-BSP 起来后经 notifier 再跑，表最终拼成完整映射。

(c) 配 SGI/PPI。 展开：

c
void gic_cpu_config(void __iomem *base, void (*sync_access)(void))
{
    int i;

    /* Deal with the banked PPI and SGI interrupts - disable all
     * PPI interrupts, ensure all SGI interrupts are enabled.     */
    writel_relaxed(0xffff0000, base + GIC_DIST_ENABLE_CLEAR);
    writel_relaxed(0x0000ffff, base + GIC_DIST_ENABLE_SET);

    /* Set priority on PPI and SGI interrupts    */
    for (i = 0; i < 32; i += 4)
        writel_relaxed(0xa0a0a0a0, base + GIC_DIST_PRI + i * 4 / 4);

    if (sync_access)
        sync_access();
}

两个常量值得记住：0xffff0000 写进 GIC_DIST_ENABLE_CLEAR 清掉 ID 16~31 的使能位，PPI 全关；0x0000ffff 写进 GIC_DIST_ENABLE_SET 置起 ID 0~15，SGI 全开。SGI 必须开，否则 IPI 一发就丢。容易看错的地方：函数拿到的 base 是 Distributor 基地址（调用点是 gic_cpu_config(dist_base, NULL)），写的却是 ID 0~31 那批 banked 寄存器。banked 语义让「从 Distributor 基址访问」和「只影响本核」两件事并存——地址走 GICD，作用域是本核。优先级循环里的 i * 4 / 4 化简就是 i，和第九小节同一套偏移。

(d) 优先级门限。 GICC_PMR 写 0xf0。数值越小优先级越高，进入条件是「中断优先级数值 < PMR」。第九小节给每条中断配的缺省优先级是 0xa0，0xa0 < 0xf0 全部放行。想在 CPU interface 这层挡掉低优先级中断，把 PMR 调到 0xa0 以下。

(e) 开总闸。 GICC_CTLR 写 1：使能 group 0，禁用 group 1，group 0 的事件走 IRQ 而不是 FIQ。到这一步本核才开始真正收中断。

十二、gic_mask_irq / gic_unmask_irq #

c
static void gic_mask_irq(struct irq_data *d)
{
    u32 mask = 1 << (gic_irq(d) % 32);

    raw_spin_lock(&irq_controller_lock);
    writel_relaxed(mask, gic_dist_base(d) + GIC_DIST_ENABLE_CLEAR + (gic_irq(d) / 32) * 4);
    if (gic_arch_extn.irq_mask)
        gic_arch_extn.irq_mask(d);
    raw_spin_unlock(&irq_controller_lock);
}

c
static void gic_unmask_irq(struct irq_data *d)
{
    u32 mask = 1 << (gic_irq(d) % 32);

    raw_spin_lock(&irq_controller_lock);
    if (gic_arch_extn.irq_unmask)
        gic_arch_extn.irq_unmask(d);
    writel_relaxed(mask, gic_dist_base(d) + GIC_DIST_ENABLE_SET + (gic_irq(d) / 32) * 4);
    raw_spin_unlock(&irq_controller_lock);
}

两个函数只差两处：寄存器是 CLEAR 还是 SET，厂商钩子在前还是在后。位运算：gic_irq(d) 取 hwirq，% 32 定位是 32 位字里的第几位，/ 32 定位是第几个寄存器，* 4 换成字节偏移。写 1 才生效——GICD_ICENABLERn 写 1 表示 disable、写 0 什么都不做，GICD_ISENABLERn 写 1 表示 enable、写 0 什么都不做。这是「写 1 生效」型寄存器，不能读-改-写，所以 mask 和 unmask 各写各的寄存器，不用取反。为什么加锁：这组函数没有读-改-写，但会被不同 CPU 并发调用（一个核 disable_irq 另一核 enable_irq），irq_controller_lock 是 GIC 驱动自己的一把全局 raw_spinlock。用 raw_ 变体是因为中断上下文里不能被抢占点打断。厂商钩子的位置不对称是有意的：gic_mask_irq 先写硬件再调钩子，gic_unmask_irq 先调钩子再写硬件。mask 时先断绝 GIC 侧投递、再让厂商代码收尾；unmask 时先让厂商代码准备好、再放开 GIC 侧投递。反了就有一个窗口会进来。 mask 不清 pending：GICD_ICENABLERn 只停 forward，pending 位留着。所以 disable_irq() 之后如果中断源还拉着，enable_irq() 会立刻补一次中断。这是 disable_irq() 在电平中断上容易出问题的根源。

十三、gic_ack / gic_eoi 与中断应答时序 #

先说版本差异，避免你按老代码对不上。3.17 的 gic_chip 里没有 .irq_ack，应答动作在 gic_handle_irq 里读 GICC_IAR 时就完成了，不经过 irq_chip。老版本（3.x 早期）有一个 gic_ack_irq，它干的事是往 GICD_ICENABLERn 写 1 把中断线关掉——是「进临界区」的意思，跟读 IAR 不是一回事。名字都叫 ack，语义完全不同。3.17 的入口处理骨架如下（结构示意，逐字以本地源码为准）：

c
static void __exception_irq_entry gic_handle_irq(struct pt_regs *regs)
{
    u32 irqstat, irqnr;
    struct gic_chip_data *gic = &gic_data[0];
    void __iomem *cpu_base = gic_data_cpu_base(gic);

    do {
        irqstat = readl_relaxed(cpu_base + GIC_CPU_INTACK);
        irqnr = irqstat & GICC_IAR_INT_ID_MASK;

        if (likely(irqnr > 15 && irqnr < 1021)) {
            irqnr = irq_find_mapping(gic->domain, irqnr);
            handle_IRQ(irqnr, regs);
            continue;
        }
        if (irqnr < 16) {
            writel_relaxed(irqstat, cpu_base + GIC_CPU_EOI);
            handle_IPI(irqnr, regs);
            continue;
        }
        break;
    } while (1);
}

一个 do-while 循环，读一次 IAR 处理一个中断，处理完回循环顶部再读一次——「一次进异常，把攒下的中断全部处理掉」，减少进出异常的开销。irqnr > 15 的边界说清两件事：ID 0~15 的 SGI 不走 irq domain、直接进 handle_IPI；ID 16 以上的 PPI 和 SPI 走 irq_find_mapping 找到 IRQ number 再进 handle_IRQ。< 1021 的上界把 1021~1023 挡在外面，读到就直接跳出。SGI 分支里自己写了 GICC_EOI，因为 SGI 没走 flow handler，没人替它收尾。GICC_IAR 的返回值不只是 ID：低 10 位是 interrupt ID，高位是 CPU ID，GICC_IAR_INT_ID_MASK 就是 0x3ff。

gic_eoi_irq #

c
static void gic_eoi_irq(struct irq_data *d)
{
    if (gic_arch_extn.irq_eoi) {
        raw_spin_lock(&irq_controller_lock);
        gic_arch_extn.irq_eoi(d);
        raw_spin_unlock(&irq_controller_lock);
    }

    writel_relaxed(gic_irq(d), gic_cpu_base(d) + GIC_CPU_EOI);
}

写进 GICC_EOIR 的是 hwirq 本身，不是位掩码——跟 mask / unmask 完全不同。EOI 是「我处理完的是哪一个」，硬件需要完整 ID 不是一个位。硬件收到后做两件事：priority drop（把当前运行优先级退回上一个 active 中断的优先级，GICC_RPR 更新，让更低优先级的 pending 有机会上来）；deactivate（通知 Distributor 把该中断状态从 active 拿掉）。两件事拆开还是合并由 GICC_CTLR.EOImode 决定：合并模式下写 GICC_EOIR 一次做完，split 模式下 GICC_EOIR 只做 priority drop、还得写 GICC_DIR 才真正 deactivate。3.17 用合并模式。厂商钩子在这里加锁包起来，写 GICC_EOIR 那一步在锁外——单次写、没有读-改-写，不需要保护。

一次完整的中断时序 #

把 SPI 和 PPI 两条路径并排放：

步骤 SPI（handle_fasteoi_irq） PPI（handle_percpu_devid_irq）
1 外设拉线，Distributor 记 pending 同左，但是本核私有寄存器
2 优先级比较，送 CPU interface 同左
3 CPU interface assert nIRQCPU 同左
4 进 gic_handle_irq，读 GICC_IAR 同左
5 硬件转 active，deassert 信号 同左
6 irq_find_mapping 查 IRQ number 同左
7 handle_fasteoi_irq → mask_irq → handler handle_percpu_devid_irq → handler
8 unmask_irq 不 unmask，per-CPU 中断常驻使能
9 gic_eoi_irq 写 GICC_EOIR 同左
10 回循环顶部，再读 IAR 同左

第 7 步的 mask 是 fasteoi 形态带来的：它在 handler 执行期间把中断线关掉，防止同一来源在还没 EOI 的时候再进来。所以 SPI 的完整序列是 mask → handler → unmask → eoi。第 8 步 PPI 不 unmask，因为 per-CPU 中断的使能位在 gic_cpu_config 里一次性配好了，flow handler 不带 mask 语义，这一条和第十六小节呼应。第 9 步 EOI 的顺序很要命：level 中断的正确收尾是先清设备侧中断源、再 EOI，反了就进第五小节说的「EOI 完立刻又 pending」，中断风暴现场。

十四、gic_set_type：触发类型怎么配 #

c
static int gic_set_type(struct irq_data *d, unsigned int type)
{
    void __iomem *base = gic_dist_base(d);
    unsigned int gicirq = gic_irq(d);
    u32 enablemask = 1 << (gicirq % 32);
    u32 enableoff = (gicirq / 32) * 4;
    u32 confmask = 0x2 << ((gicirq % 16) * 2);
    u32 confoff = (gicirq / 16) * 4;
    bool enabled = false;
    u32 val;

    /* Interrupt configuration for SGIs can't be changed */
    if (gicirq < 16)
        return -EINVAL;

    if (type != IRQ_TYPE_LEVEL_HIGH && type != IRQ_TYPE_EDGE_RISING)
        return -EINVAL;

    raw_spin_lock(&irq_controller_lock);

    if (gic_arch_extn.irq_set_type)
        gic_arch_extn.irq_set_type(d, type);

    val = readl_relaxed(base + GIC_DIST_CONFIG + confoff);
    if (type == IRQ_TYPE_LEVEL_HIGH)
        val &= ~confmask;
    else if (type == IRQ_TYPE_EDGE_RISING)
        val |= confmask;

    /*
     * As recommended by the spec, disable the interrupt before changing
     * the configuration
     */
    if (readl_relaxed(base + GIC_DIST_ENABLE_SET + enableoff) & enablemask) {
        writel_relaxed(enablemask, base + GIC_DIST_ENABLE_CLEAR + enableoff);
        enabled = true;
    }

    writel_relaxed(val, base + GIC_DIST_CONFIG + confoff);

    if (enabled)
        writel_relaxed(enablemask, base + GIC_DIST_ENABLE_SET + enableoff);

    raw_spin_unlock(&irq_controller_lock);

    return 0;
}

两个前置拒绝。 gicirq < 16 直接 -EINVAL：SGI 固定边沿语义，配置位没有可改的余地。type 只接受 IRQ_TYPE_LEVEL_HIGH 和 IRQ_TYPE_EDGE_RISING，别的组合一律拒，低电平触发和下降沿触发在这版驱动里没有代码路径。位域定位。 GICD_ICFGRn 每 2 位管一个中断，(gicirq % 16) * 2 定位到字内偏移。confmask = 0x2 << ... 里的 0x2 有讲究：2 位里 bit0 是配置位（1 = edge，0 = level），bit1 在 SPI 上是保留位；写 0x2 而不是 0x3，就是只动配置位、不碰保留位。confoff = (gicirq / 16) * 4 是一组 16 个中断、每组 4 字节。

读-改-写。 val 读出来、改那 2 位、写回去，因为一个 32 位字装 16 个中断的配置，不能只写自己那两位而把别人的抹掉。disable → 改 → enable。 先读 GICD_ISENABLERn 判断当前是不是使能（那个寄存器可读，读回的是当前使能位图）；使能就先往 GICD_ICENABLERn 写 1 关掉，记下 enabled = true；改配置；再按 enabled 恢复。这是规范建议的顺序，理由很实在：GICD_ICFGRn 描述硬件怎么解释那根信号线，在一条已使能、正处在 pending 或 active 的线上中途改语义，硬件看到的是一个自相矛盾的状态。

厂商钩子在配置之前。 有些 SoC 的 GIC 集成需要额外动作（配 IO 复用、改外部 crossbar 极性），先让厂商代码铺好路，再改 GIC 自己的配置位。val 是读回来的完整字，只有自己那 2 位被动过，不会改别人的位；但两个核同时给同一个字里的不同中断配类型时，irq_controller_lock 保证串行。

十五、gic_set_affinity：中断绑到哪个核 #

c
static int gic_set_affinity(struct irq_data *d, const struct cpumask *mask_val,    bool force)
{
    void __iomem *reg = gic_dist_base(d) + GIC_DIST_TARGET + (gic_irq(d) & ~3);
    unsigned int cpu, shift = (gic_irq(d) % 4) * 8;
    u32 val, mask, bit;

    if (!force)
        cpu = cpumask_any_and(mask_val, cpu_online_mask);  /* 挑一个 online 的 CPU */
    else
        cpu = cpumask_first(mask_val);                     /* 取 mask 第一个，不管 online */

    raw_spin_lock(&irq_controller_lock);

    mask = 0xff << shift;
    bit = gic_cpu_map[cpu] << shift;     /* CPU 逻辑 ID 转成要写的 mask */
    val = readl_relaxed(reg) & ~mask;
    writel_relaxed(val | bit, reg);

    raw_spin_unlock(&irq_controller_lock);

    return IRQ_SET_MASK_OK;
}

寄存器定位。 GICD_ITARGETSRn 一字节管一个中断、一个字管 4 个。gic_irq(d) & ~3 抹掉低 2 位得到那 4 个中断所在字的字节偏移，(gic_irq(d) % 4) * 8 得到这个中断在字里的 bit 位移。& ~3 和 % 4 是同一件事的两种写法，一个取整一个取余。选核的两种模式。 force == false 时在请求核集合和在线核集合的交集里挑一个；force == true 时取 mask 第一个、不管那个核是否在线，后者给「核还没起来先把中断绑过去」的场景用。

逻辑 ID 翻硬件 mask。 gic_cpu_map[cpu] 这张表在第十小节建好，左移 shift 落到字节位置上，mask = 0xff << shift 先清掉那个字节，val | bit 再写进去。一个字节对应 8 个 CPU interface，表里的值本来就是 8 位，移位后正好落进那个字节。一次只能绑一个核，因为写进去的只有一个 bit 是 1；想绑一组核得靠别的实现，这版代码不支持。为什么读-改-写。 一个字里 4 个中断各有自己的目标核，改一个不能动其他三个。& ~mask 清字节、| bit 填字节。

SGI 和 PPI 打不到这里。 它俩没有可写的 GICD_ITARGETSRn（那 8 个只读），irq_set_affinity() 对 PPI 没有实际效果——想「把 timer 中断挪个核」是挪不动的，PPI 天生钉在某个核上。IRQ_SET_MASK_OK 告诉上层「已经设好了，不用再走 generic 的 migration 路径」。

十六、PPI 与 per-CPU 中断的特殊处理 #

PPI 和 SGI 跟 SPI 的差别渗透在初始化、映射、flow handler 三层。

初始化：每个核各跑一次 gic_cpu_init #

gic_dist_init 是全局的，BSP 跑一次就够；gic_cpu_init 是每核的，每个核都得给「自己那个 CPU interface」配一遍。机制是 CPU 热插拔通知：

c
static struct notifier_block gic_cpu_notifier = {
    .notifier_call = gic_secondary_init,
    .priority = 100,
};

static int gic_secondary_init(struct notifier_block *nfb, unsigned long action,  void *hcpu)
{
    if (action == CPU_STARTING || action == CPU_STARTING_FROZEN)
        gic_cpu_init(&gic_data[0]);   /* 初始化那些非 BSP 的 CPU interface */

    return NOTIFY_OK;
}

gic_init_bases 里那句 register_cpu_notifier(&gic_cpu_notifier) 把这对钩子装上。时序是这样：

时序是：硬件选一个核当 BSP 先跑，non-BSP 全在 reset 状态；BSP 上执行 gic_dist_init()（全局）、gic_cpu_init()（自己那个 CPU interface）、gic_pm_init()（全局）；BSP 初始化完成，release 所有 non-BSP；各个 non-BSP 起来发 CPU_STARTING 通知，gic_secondary_init 收到，调 gic_cpu_init(&gic_data[0])，把那个核对应的 CPU interface 配好。 CPU_STARTING_FROZEN 是系统从 suspend 恢复时起来的核，也走同一条路。这个设计的前提是「non-BSP 起来时，per-CPU 变量、内存分配器这些基础设施已经就绪」，所以 gic_cpu_init 里可以放心调 smp_processor_id()、改全局表、写寄存器。

映射：PPI 走 per-CPU devid 通道 #

c
static int gic_irq_domain_map(struct irq_domain *d, unsigned int irq, irq_hw_number_t hw)
{
    if (hw < 32) {                                              /* SGI 或 PPI */
        irq_set_percpu_devid(irq);                              /* (a) */
        irq_set_chip_and_handler(irq, &gic_chip, handle_percpu_devid_irq);  /* (b) */
        set_irq_flags(irq, IRQF_VALID | IRQF_NOAUTOEN);         /* (c) */
    } else {
        irq_set_chip_and_handler(irq, &gic_chip, handle_fasteoi_irq);       /* (d) */
        set_irq_flags(irq, IRQF_VALID | IRQF_PROBE);

        gic_routable_irq_domain_ops->map(d, irq, hw);            /* (e) */
    }

    irq_set_chip_data(irq, d->host_data);   /* irq chip 的私有数据 */
    return 0;
}

(a) irq_set_percpu_devid() 打上 per-CPU devid 标记：per-CPU 中断的「已申请」状态是每核独立的，request_percpu_irq() 才能用。(b) handler 用 handle_percpu_devid_irq，不做 mask / unmask，直接在本地核上调 handler——PPI 本来就是本核的。(c) IRQF_NOAUTOEN：request_irq 之后不自动使能，PPI 的使能由驱动自己控制。(d) SPI 用 handle_fasteoi_irq，配 IRQF_PROBE 允许探测。(e) crossbar 型 SoC 的额外映射，gic_routable_irq_domain_ops 为 NULL 时这行要跳过（3.17 里靠编译配置或提前判空，逐字以本地源码为准）。

同一个 gic_chip，两种 flow handler。 PPI 和 SPI 的 mask / unmask / eoi 语义其实一样，差别在通用层的处理流程：fasteoi 会替你做 mask-unmask 包裹，percpu devid 不做。这就是第十三小节那张时序表里第 7、8 步不同的原因。

使能位：banked 与非 banked #

PPI 和 SGI 的使能位（GICD_ISENABLERn 第 0 组）是 banked 的：每个核访问同一个地址，写的是自己那份。gic_cpu_config() 里那两个常量正因此才安全：

c
writel_relaxed(0xffff0000, base + GIC_DIST_ENABLE_CLEAR);  /* 关 ID 16~31，只关本核的 PPI */
writel_relaxed(0x0000ffff, base + GIC_DIST_ENABLE_SET);    /* 开 ID 0~15，只开本核的 SGI */

如果这些寄存器不是 banked 的，这两行会把别的核的 PPI 一起关掉。非 banked 的 SoC 靠 cpu-offset 让每个核访问不同地址绕开问题，CONFIG_GIC_NON_BANKED 和 get_base 函数指针就是这条分支的开关。

SGI：不进 irq domain #

gic_handle_irq 里 irqnr < 16 的分支直接 handle_IPI(irqnr, regs)，不做 irq_find_mapping。SGI 的「注册」走另一条路：set_smp_cross_call(gic_raise_softirq) 挂上跨核调用回调，各子系统（调度器、IPI 框架）再往 handle_IPI 的 switch 里加自己的处理。所以 /proc/interrupts 里不会出现 SGI 的行，它的统计在 IPI 自己的计数器里。

十七、从 GIC 到 generic irq 的衔接 #

GIC 侧的东西到这儿齐了。回头看它跟 generic irq 的接缝，三个接口面：

接口 GIC 提供的实现 generic irq 用它做什么
struct irq_domain_ops map / unmap / xlate hwirq ↔ IRQ number 翻译
struct irq_chip mask / unmask / eoi / set_type / set_affinity / retrigger / set_wake 硬件操作
handle_arch_irq gic_handle_irq 异常入口分派

xlate：把 DT 的 3 个 cell 解出来 #

c
static int gic_irq_domain_xlate(struct irq_domain *d,
                struct device_node *controller,
                const u32 *intspec, unsigned int intsize,   /* 输入 */
                unsigned long *out_hwirq, unsigned int *out_type)  /* 输出 */
{
    unsigned long ret = 0;

    *out_hwirq = intspec[1] + 16;                    /* (a) */
    *out_type = intspec[2] & IRQ_TYPE_SENSE_MASK;    /* (b) */

    return ret;
}

DT 里 #interrupt-cells = <3>，三个 cell 的语义：

cell 含义 取值
intspec[0] interrupt type 0 表示 SPI，1 表示 PPI
intspec[1] interrupt number PPI 是 [0, 15]，SPI 是 [0, 987]
intspec[2] interrupt flag 触发方式，位域见下

(a) 这里的 +16 只能对 PPI 成立。 PPI 编号从 0 开始、硬件上占 16~31，加 16 正好对上；SPI 的编号从 0 开始、硬件上占 32 起，加 16 只到 16 起，差了一个 16。素材摘录的这段代码不完整，原文没给 SPI 分支。SPI 的偏移量本篇标为未验证，读源码时以 irq-gic.c 里 gic_irq_domain_xlate 的完整实现为准。(b) IRQ_TYPE_SENSE_MASK 取低 4 位得到触发方式，这个值最终传到 gic_set_type()：

值 宏 含义 gic_set_type 接受
0x0 — 未指定 否
0x1 IRQ_TYPE_EDGE_RISING 上升沿 是
0x2 IRQ_TYPE_EDGE_FALLING 下降沿 否
0x4 IRQ_TYPE_LEVEL_HIGH 高电平 是
0x8 IRQ_TYPE_LEVEL_LOW 低电平 否

这个表和第十四小节那两个 if 是同一件事的两面：DT 里写 IRQ_TYPE_LEVEL_LOW 会让 gic_set_type 返回 -EINVAL，驱动 probe 失败。

unmap 与三个 flag #

gic_irq_domain_unmap 是 map 的逆操作，解除 IRQ number 和 hwirq 的绑定。3.17 的实现基本是空的（linear domain 的解除由通用层处理），具体以源码为准。

flag 出现在 含义
IRQF_VALID 两条分支都有 chip 和 handler 已就位，这个 IRQ 可用
IRQF_NOAUTOEN PPI 分支 request_irq 后不自动 enable
IRQF_PROBE SPI 分支 允许被 request_irq 探测试申请

IRQF_VALID 是必须的：irq_set_chip_and_handler() 只设置 chip 和 handler，标记「这个 IRQ 己就位」得另外做。

十八、易错点速查 #

# 坑 说明
1 level 中断不清源就 EOI 第五小节那张状态机表里 active → pending 那一行就是后果。EOI 之后源还拉着，立刻又 pending，gic_handle_irq 的循环原地转圈。正确顺序是先清设备侧中断源，再让 EOI 发生。
2 以为 disable_irq() 能清 pending 它只写 GICD_ICENABLERn，pending 位不动，enable_irq() 会补一次。要真丢，得写 GICD_ICPENDRn。
3 给 GICD_ICENABLERn 写 0 想 unmask 写 0 无效。unmask 得往 GICD_ISENABLERn 写 1。两组寄存器各管一个方向。
4 以为 PPI 能 irq_set_affinity() GICD_ITARGETSR0~7 只读，PPI 挪不动，硬挪只会静默失败。
5 DT 里给 PPI 写低电平或下降沿 gic_set_type 只认 LEVEL_HIGH 和 EDGE_RISING，别的返回 -EINVAL，驱动 probe 挂掉。
6 在 DT 里给 SGI 配触发类型 gic_set_type 第一行 gicirq < 16 就拒了。SGI 固定边沿。
7 以为初始化配的触发类型是最终值 gic_dist_config 写的全 0（level）只是缺省，每个设备驱动 probe 时按自己 DT 的第三格重配一遍。debug 时看到实际类型和第九小节说的不一样，是正常的。
8 多核系统里发现 SPI 全在 CPU0 上 gic_dist_init 把所有 SPI 的目标都设成「跑这段代码的那个核」，也就是 BSP。摊开靠 irqbalanced 或手动 set_affinity。
9 以为 set_smp_cross_call(gic_raise_softirq) 跟 softirq 有关 它发的是 SGI（IPI）。名字是历史包袱。
10 在二级 GIC 上期待 PPI 能用 hwirq_base = 32 的分支直接把 PPI 也跳过了，二级 GIC 只贡献 SPI。
11 忘了 GICC_PMR 的语义方向 数值越小优先级越高，中断进来的条件是「优先级数值 < PMR」。第十小节配 PMR 0xf0，0xa0 < 0xf0 全放行。把 PMR 调小是收紧，不是放宽。
12 拿 3.x 早期代码里的 gic_ack_irq 当读 IAR 那是往 GICD_ICENABLERn 写 1 的「进临界区」动作，3.17 的 gic_chip 里已经没有它了。
13 以为 gic_eoi_irq 写的是位掩码 写的是 hwirq 本身，跟 mask / unmask 完全不同。
14 split EOI 模式下只写 GICC_EOIR 那个模式下 GICC_EOIR 只做 priority drop，还得写 GICC_DIR 才 deactivate。3.17 用合并模式没这问题，自己改 GICC_CTLR.EOImode 时要记得配套。
15 在 non-banked 的 SoC 上忘了 cpu-offset 属性缺失取 0、等价于 banked，非 banked 硬件上每个核会去读写同一个地址，PPI 和 SGI 全串。
