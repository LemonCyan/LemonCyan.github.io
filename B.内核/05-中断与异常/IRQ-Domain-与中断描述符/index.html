一、两个编号：HW interrupt ID 与 IRQ number #

内核标识一个外设中断用两套编号。

IRQ number：CPU 侧。内核给每个外设中断分一个虚拟 interrupt ID，和硬件连线无关，只标识「某个外设的中断」。

HW interrupt ID：interrupt controller 侧。controller 把若干外设的 interrupt request line 收上来往上送，要对它们编码。编码就是 HW interrupt ID。

维度 HW interrupt ID IRQ number
谁分配 interrupt controller 硬件 内核建映射时动态分配
作用域 只在本 controller 内唯一 全系统唯一
和硬件的关系 强相关，物理连线或寄存器编码 无，纯数字
类型 irq_hw_number_t（3.x 是 unsigned long 的 typedef，未逐行核对头文件） unsigned int
谁看它 irq chip driver、GIC driver 外设驱动、generic irq 模块
硬件换代后 变 不变，驱动不改

麻烦在级联。A 是 root，B 挂在 A 的 13 号线后面，B 自己也从 0 给外设编码。这时说「HW interrupt ID 是 13」没有意义，得说清是 A 的 13 还是 B 的 13。

实际定位要用二元组：(controller, hwirq)。domain 就是二元组里 controller 那一半。

驱动的视角和 CPU 一致：只要一个 IRQ number，不管它是哪个 controller 上的哪个 HW ID。硬件换了驱动不改——这就是必须有一层映射的原因。

二、为什么要引入 IRQ Domain #

所有 interrupt controller 连成一棵树。root controller 在顶上，下面挂 first level，再挂 second level，叶子上才是产生中断的外设。

每个 controller 连若干 interrupt source，按自己硬件的物理特性给 source 编号。编号只在本 controller 范围内说得通。

我们听过 power domain、clock domain。domain 就是「范围」，定义出了这个范围就没意义的东西，正好是 HW interrupt ID 的性质。于是内核按 controller 划 domain：一个 controller 一个 domain，hwirq 在 domain 内唯一，跨 domain 重名无所谓。

text
        [root GIC]  domain A : hwirq 0..N
         /        \
 [外设 uart]   [second GIC]  domain B : hwirq 0..M
                  /      \
          [外设 spi]   [外设 i2c]

uart 的 hwirq 属于 domain A，spi 的属于 domain B。数字撞了不冲突，因为查表必须带 domain。

domain 解决的问题列一下：

  • 消除跨 controller 的 hwirq 重名，一维编号变成 (domain, hwirq) 二维定位。
  • 把「怎么映射」从 generic irq 里剥离，交给每个 controller 自己实现 callback。
  • IRQ number 从绑死硬件变成动态分配，驱动不再依赖 board specific 的 IRQ 宏。
  • 让 Device Tree 能描述中断拓扑：interrupt-parent 指 domain，interrupts 由该 domain 的 xlate 解析。

三、IRQ Domain 的历史：从静态表到动态映射 #

搞不清这段历史，会看不懂为什么 GIC 里用的是 irq_domain_add_legacy 而不是 irq_domain_add_linear。

阶段 hwirq 怎么来 映射怎么做 遗留问题
单 controller SOC 内嵌 controller 的中断状态寄存器 bit 位 hwirq 直接当 IRQ number 寄存器 64 bit，每个 bit 一个 IRQ；GPIO 中断全挤在一个 bit，靠 handler 里 demux
多 controller / 级联 每个 controller 各自编码 board specific 静态表 + 大量 IRQ 宏 hwirq 重名；IRQ 固定分配；换板子改代码
irq domain 每个 domain 内唯一 revmap（线性 lookup table 或 radix tree） 驱动只看 IRQ number，映射动态建立

第一阶段：SOC 内嵌的 controller 多半有中断状态寄存器，64 bit 或更多，每个 bit 一个中断源，bit 号直接等于 IRQ number。GPIO 那边，几十个 GPIO 中断在 controller 里只占一个 bit，于是全部共用一个 IRQ number，在该通用 GPIO 中断的 handler 里做 demultiplex，再分派到各 GPIO 自己的 IRQ number。

第二阶段：把 controller 抽象成 irqchip 的想法流行，GPIO controller 也能看成一个 interrupt controller chip，系统里至少两个 controller。再往后级联，外设中断数量上涨，静态表塞不下。旧 ARM 平台在 board specific 代码里定义一堆设备资源静态表，其中就有 IRQ 资源，于是每个外设的 IRQ 固定，代码里是很长的一串 IRQ number 宏。关系固定，好处是能在 controller 代码里一次把映射建好；坏处是代码跟着板子走。

第三阶段就是 irq domain。素材没给引入的确切版本，标「未验证」。能确定的只有一句：3.14 时代 GIC 还在走 legacy 路径，素材原话是「如果想充分发挥 Device Tree 的威力，3.14 版本中的 GIC 代码需要修改」。

四、struct irq_domain 的关键字段 #

c
struct irq_domain {
    struct list_head link;                  /* 挂进全局 irq_domain_list 的节点 */
    const char *name;                       /* domain 名字 */
    const struct irq_domain_ops *ops;       /* callback 函数集 */
    void *host_data;                        /* 底层 interrupt controller 的私有数据 */

    /* Optional data */
    struct device_node *of_node;            /* 该 domain 对应的 controller 的 device node */
    struct irq_domain_chip_generic *gc;     /* generic irq chip，本篇不展开 */

    /* reverse map data. The linear map gets appended to the irq_domain */
    irq_hw_number_t hwirq_max;              /* 本 domain 中最大的 HW interrupt ID */

    unsigned int revmap_size;               /* 线性映射的 size；tree 与 no map 下为 0 */
    struct radix_tree_root revmap_tree;     /* radix tree 映射的根 */

};

所有 domain 挂在一个全局链表上：

c
static LIST_HEAD(irq_domain_list);

顺着它走，就能拿到整个系统的 HW ID → IRQ number mapping DB（不是 SQLite 也不是 Oracle，就是内核里的映射库）。三种映射类型下这些字段怎么填，第五节末尾的对照表一次说完。

irq_domain_ops 是 domain 的 callback 集：

c
struct irq_domain_ops {
    int (*match)(struct irq_domain *d, struct device_node *node);
    int (*map)(struct irq_domain *d, unsigned int virq, irq_hw_number_t hw);
    void (*unmap)(struct irq_domain *d, unsigned int virq);
    int (*xlate)(struct irq_domain *d, struct device_node *node,
             const u32 *intspec, unsigned int intsize,
             unsigned long *out_hwirq, unsigned int *out_type);
};
  • xlate 是「翻译」。DTS 里用中断的 node 通过 interrupts / interrupt-parent 提供中断信息。interrupts 的 cell 语义只有具体 controller 解得对。xlate 把指定设备（node）上若干个（intsize）中断属性（intspec）翻译成 hwirq（out_hwirq）和触发类型（out_type）。
  • match 判断传入的 controller node 是否和某个 domain 匹配，匹配返回 1。内核里很少实现它：struct irq_domain 的 of_node 就指向对应 controller 的 device node，不提供该 callback 时，默认匹配就是比较 of_node 和传入的 node。
  • map / unmap 方向相反，看一个就够。map 在建立或更新 hwirq 与 virq 关系时被调用。光调 request_threaded_irq 不够跑通一个中断，还得给这个 IRQ number 设三样东西：中断描述符的 irq chip、high level irq-events handler、irq chip data。这三样不适合让外设驱动设，得由知道自家硬件的 controller 在 map 里设。

五、domain 的几种类型：linear / tree / legacy / no-map #

映射关系怎么组织是 controller 自己的事。generic irq 再抽象一层，切成三类，加上历史遗留的 legacy，共四个注册入口。

c
static inline struct irq_domain *irq_domain_add_linear(struct device_node *of_node,
                     unsigned int size,                   /* 该 domain 支持多少 IRQ */
                     const struct irq_domain_ops *ops,    /* callback 函数 */
                     void *host_data)                     /* driver 私有数据 */
{
    return __irq_domain_add(of_node, size, size, 0, ops, host_data);
}

static inline struct irq_domain *irq_domain_add_tree(struct device_node *of_node,
                     const struct irq_domain_ops *ops,
                     void *host_data)
{
    return __irq_domain_add(of_node, 0, ~0, 0, ops, host_data);
}

static inline struct irq_domain *irq_domain_add_nomap(struct device_node *of_node,
                     unsigned int max_irq,
                     const struct irq_domain_ops *ops,
                     void *host_data)
{
    return __irq_domain_add(of_node, 0, max_irq, max_irq, ops, host_data);
}

linear：就是一个 lookup table。hwirq 当 index，linear_revmap[hwirq] 直接取出 virq。代价是 controller 编码 hwirq 要守两条——不能太大，排列最好紧密。中间留空洞，表里就一片空 entry。

radix tree：hwirq 当 lookup key，在树里检索出 struct irq_data，再取 irq。线性表装不下就上这个。素材给的实情：内核里用 radix tree map 的只有 powerPC 和 MIPS 的硬件平台。

no map：有些 controller 够横，hwirq 不是物理连线决定的，能用寄存器配。PowerPC 的 MPIC（Multi-Processor Interrupt Controller）就是。这种情况不用查表——直接把 IRQ number 写进 HW interrupt ID 配置寄存器，配出来的 hwirq 就是 IRQ number，映射本身不存在。

legacy 单列，因为它顺手把映射建了：

c
struct irq_domain *irq_domain_add_legacy(struct device_node *of_node,
                     unsigned int size,
                     unsigned int first_irq,
                     irq_hw_number_t first_hwirq,
                     const struct irq_domain_ops *ops,
                     void *host_data)
{
    struct irq_domain *domain;

    domain = __irq_domain_add(of_node, first_hwirq + size,   /* 注册 irq domain */
                 first_hwirq + size, 0, ops, host_data);
    if (!domain)
        return NULL;

    irq_domain_associate_many(domain, first_irq, first_hwirq, size); /* 一次建完映射 */
    return domain;
}

差别在最后一行：legacy 注册完顺带把 size 个映射全建好，virq 从 first_irq 起，hwirq 从 first_hwirq 起，一一对应。linear / tree 只注册空壳，映射等后面按需创建。

项 linear radix tree no map legacy

主要缺点 空洞浪费 查表要走树 依赖硬件可配 与静态 IRQ 资源表绑死

六、向系统注册一个 irq domain #

四个 irq_domain_add_* 最后都落到 __irq_domain_add：按自己的映射类型初始化 struct irq_domain 各成员，再挂进 irq_domain_list。

c
struct irq_domain *__irq_domain_add(struct device_node *of_node,
                    unsigned int size,          /* → revmap_size */
                    irq_hw_number_t hwirq_max,  /* → hwirq_max */
                    unsigned int direct_max,    /* → revmap_direct_max_irq */
                    const struct irq_domain_ops *ops,
                    void *host_data);

host_data 是 controller driver 的私货，generic irq 不碰。GIC 下它指向 struct gic_chip_data，后面 ops->map 要拿它去摸寄存器。of_node 是 domain 和 Device Tree 的挂钩点，默认 match 就比它。

3.x 还有 irq_domain_add_simple，给「不需要 OF、只要一块连续 virq」的场景省事。素材未收录，细节标「未验证」。

七、为 irq domain 创建映射 #

注册完 domain，映射表还是空的：linear 要建 lookup table，tree 要建 radix tree。四个入口，原型先摆出来：

c
extern unsigned int irq_create_mapping(struct irq_domain *host, irq_hw_number_t hwirq);
extern int irq_create_strict_mappings(struct irq_domain *domain, unsigned int irq_base,
                      irq_hw_number_t hwirq_base, int count);
extern unsigned int irq_create_of_mapping(struct of_phandle_args *irq_data);

irq_create_mapping：给 domain 和 hwirq，返回动态分配的 IRQ number。调用者必须知道 hwirq。这对普通驱动是反直觉的——hwirq 本该对驱动不可见。特例是 GPIO 型中断：hwirq 和 GPIO 编号有固定关系，驱动知道自己用哪个 GPIO，也就知道了 hwirq。

irq_create_strict_mappings：一次给一组 hwirq 建映射，virq 从 irq_base 起，hwirq 从 hwirq_base 起，一一对齐。

irq_create_of_mapping：名字里的 of 是 open firmware，走 Device Tree 建映射，普通外设驱动走这条。device node 里已经写了够多的中断信息，驱动初始化时调 irq_of_parse_and_map 把 interrupts 和 interrupt-parent 解析掉并建好映射：

c
unsigned int irq_of_parse_and_map(struct device_node *dev, int index)
{
    struct of_phandle_args oirq;

    if (of_irq_parse_one(dev, index, &oirq))   /* 解析 device node 的中断相关属性 */
        return 0;
    return irq_create_of_mapping(&oirq);       /* 建映射，返回 IRQ number */
}

用 DT 的普通驱动标准写法就两步：irq_of_parse_and_map 拿 IRQ number，request_threaded_irq 申请 handler。

irq_create_direct_mapping：给 no map 的 controller 用，把 virq 直接当 hwirq 写进硬件。素材原话「这里不再赘述」，本篇不编。

八、Mapping DB 的建立时机 #

八、Mapping DB 的建立时机 #

整个系统的 mapping DB 是一层层垒起来的，四步：

  1. DTS 描述中断拓扑——哪些 controller、哪个外设挂哪个 controller、用哪个 hwirq。bootloader 把 DTB 交给内核。
  2. Device Tree 初始化，形成全系统 device node 树，包含所有和中断拓扑相关的 node。
  3. machine driver 初始化时调 of_irq_init，扫描所有 interrupt controller 的 node，挑匹配的 driver 去初始化。顺序有要求：先 root，再 first level、second level，最后叶子。过程中 controller driver 往系统里加 irq domain，有些顺手把映射建了。第 3 步的顺序不是洁癖——子 controller 要注册到父 controller 上，父的 domain 没就位，子的 interrupt-parent 就解不出来。
  4. 各外设驱动初始化时按需建映射。

九、中断控制器的初始化：注册 domain #

看 GIC。路径是 gic_of_init → gic_init_bases(unsigned int gic_nr, int irq_start, void __iomem *dist_base, void __iomem *cpu_base, u32 percpu_offset, struct device_node *node)。函数体里先声明 irq_hw_number_t hwirq_base、struct gic_chip_data *gic、int gic_irqs, irq_base, i，然后按 root / second 分岔。root GIC 分支：

text
hwirq_base = 16;
gic_irqs = 系统支持的所有中断数目 - 16;
    减 16 是因为 root GIC 的 0~15 号 HW interrupt 留给 IPI，要从可用中断里剔掉。
    hwirq_base 从 16 起，也是这个原因。

irq_base = irq_alloc_descs(irq_start, 16, gic_irqs, numa_node_id());
    申请 gic_irqs 个 IRQ 资源，从 16 号开始搜 IRQ number。root GIC 申请到的就从 16 号起。

gic->domain = irq_domain_add_legacy(node, gic_irqs, irq_base,
                hwirq_base, &gic_irq_domain_ops, gic);
    注册 irq domain，并在这次调用里把映射建好。

注意它没用标准的 irq_domain_add_linear。原因就是历史：旧内核的 ARM 代码里全是 board specific 静态表，外设 IRQ 固定，hwirq 和 IRQ number 的关系也固定。关系固定，就能在 controller 代码里一次建完映射，legacy 干的就是这件事。

root GIC 初始化完，线性 lookup table 长这样：

text
index 0~15     对应的 IRQ 无效（那些 hwirq 是 IPI，没有对应外设）
16 号 IRQ  <------------------> 16 号 HW interrupt ID
17 号 IRQ  <------------------> 17 号 HW interrupt ID
……

这条路能跑，但 Device Tree 的威力没发挥出来：映射在 controller 初始化时就全建好了，等于又回到「IRQ 固定」。后续 GIC driver 改用了 irq_domain_add_linear 一类的动态路径，具体改动版本「未验证」。

十、外设驱动初始化：创建 HW ID → IRQ number 映射 #

外设驱动这一侧，入口还是 irq_of_parse_and_map，它把 interrupts 抠出来交给 irq_create_of_mapping：

c
unsigned int irq_create_of_mapping(struct of_phandle_args *irq_data)
{
    struct irq_domain *domain;
    irq_hw_number_t hwirq;
    unsigned int type = IRQ_TYPE_NONE;
    unsigned int virq;

    /* A：找 domain */
    domain = irq_data->np ? irq_find_host(irq_data->np) : irq_default_domain;
    if (!domain) {
        return 0;
    }
    /* B：没定义 xlate，就取 interrupts 属性的第一个 cell 当 hwirq */
    if (domain->ops->xlate == NULL)
        hwirq = irq_data->args[0];
    else {
        /* C：让 domain 自己解释 interrupts 属性，输出 hwirq 和 type */
        if (domain->ops->xlate(domain, irq_data->np, irq_data->args,
                    irq_data->args_count, &hwirq, &type))
            return 0;
    }
    /* D：建映射，拿 IRQ number */
    virq = irq_create_mapping(domain, hwirq);
    if (!virq)
        return virq;
    /* E：需要的话设 trigger type */
    if (type != IRQ_TYPE_NONE && type != irq_get_trigger_type(virq))
        irq_set_irq_type(virq, type);
    return virq;
}

五个点：

  • A：irq_data->np 指向该外设对应的 controller 的 device node，irq_find_host 顺着它找 domain。没有 np 就退回 irq_default_domain。
  • B：xlate 是可选 callback。没提供就按最朴素的方式解：interrupts 第一个 cell 就是 hwirq。
  • C：解铃还需系铃人。cell 语义由 controller 自己定，只有它的 xlate 解得对。输出 hwirq 和 type。
  • D：解析完，最终落到 irq_create_mapping。
  • E：type 和当前不一致才设，避免无谓摸硬件。

输入包是 of_phandle_args：

c
struct of_phandle_args {
    struct device_node *np;          /* 外设对应的 controller 的 device node */
    int args_count;                  /* 该外设定义的 interrupt 属性个数 */
    uint32_t args[MAX_PHANDLE_ARGS]; /* 具体的 interrupt 属性定义 */
};

irq_create_mapping 本体：

c
unsigned int irq_create_mapping(struct irq_domain *domain,
                irq_hw_number_t hwirq)
{
    unsigned int hint;
    int virq;

    /* 映射已存在就直接返回，别重复建 */
    virq = irq_find_mapping(domain, hwirq);
    if (virq) {
        return virq;
    }
    /* 用 hwirq 算分配起点，再分配一个 IRQ 描述符及其 IRQ number */
    hint = hwirq % nr_irqs;
    if (hint == 0)
        hint++;
    virq = irq_alloc_desc_from(hint, of_node_to_nid(domain->of_node));
    if (virq <= 0)
        virq = irq_alloc_desc_from(1, of_node_to_nid(domain->of_node));
    if (virq <= 0) {
        pr_debug("-> virq allocation failed\n");
        return 0;
    }
    /* 建立映射 */
    if (irq_domain_associate(domain, virq, hwirq)) {
        irq_free_desc(virq);
        return 0;
    }
    return virq;
}
  • hint = hwirq % nr_irqs 只是起点，让分出来的 virq 和 hwirq 有点亲和性。hint == 0 要跳过，0 在多数平台上是 INVALID_IRQ。首次失败退到 1 重试。
  • of_node_to_nid(domain->of_node) 决定描述符内存落在哪个 NUMA node。IRQ 固定由某个 CPU 处理时，描述符放它近的那个 node。
  • 函数注释里用的是 virtual interrupt number。重点在 virtual：和物理连接没关系了，就是一个 number。
  • 分配描述符的细节属中断描述符那篇，这里略。

真正落地映射的是 irq_domain_associate：

c
int irq_domain_associate(struct irq_domain *domain, unsigned int virq,
             irq_hw_number_t hwirq)
{
    struct irq_data *irq_data = irq_get_irq_data(virq);
    int ret;

    mutex_lock(&irq_domain_mutex);
    irq_data->hwirq = hwirq;
    irq_data->domain = domain;
    if (domain->ops->map) {
        /* 调 map callback，把 chip / handler / chip_data 配好 */
        ret = domain->ops->map(domain, virq, hwirq);
    }
    if (hwirq < domain->revmap_size) {
        domain->linear_revmap[hwirq] = virq;   /* 线性表：index 是 hwirq，值是 virq */
    } else {
        mutex_lock(&revmap_trees_mutex);
        radix_tree_insert(&domain->revmap_tree, hwirq, irq_data); /* 树：插节点 */
        mutex_unlock(&revmap_trees_mutex);
    }
    mutex_unlock(&irq_domain_mutex);

    irq_clear_status_flags(virq, IRQ_NOREQUEST);  /* 该 IRQ 已可申请，清标志 */
    return 0;
}

三件事，顺序不能乱：

  1. 把 hwirq 和 domain 写进该 virq 的 irq_data。之后描述符才知道自己对应哪个 controller 的哪根线。
  2. 调 ops->map。chip、high level handler、chip_data 在这一步配上。
  3. 填 revmap。判据是 hwirq < domain->revmap_size：成立走线性表，不成立走 radix tree。linear 与 tree 就在这里分岔，不需要判断 domain 类型字段。

末尾 irq_clear_status_flags(virq, IRQ_NOREQUEST) 是放行：映射建好之前，这个 IRQ 不允许被 request_irq。

反方向查表是 irq_find_mapping，中断热路径要走它。素材没给源码，按其查表结构反推：linear 下取 linear_revmap[hwirq] 得 virq；tree 下 radix_tree_lookup(revmap_tree, hwirq) 得 struct irq_data 再取 irq。实现「未验证」。

十一、Device Tree 里的中断描述：interrupt-parent 与 interrupts #

要建映射，先得知道拓扑。controller 怎么连、每根 request line 分给谁，都写在 DTS 里。

属性 写在谁身上 含义 谁解析
interrupt-parent 外设 node、非 root controller node request line 物理连到哪个 controller OF 核心，用来找 domain
interrupts 外设 node、非 root controller node interrupt specifier：hwirq + 触发类型等 目标 domain 的 xlate
interrupt-controller 中断控制器 node 声明这个 node 是中断控制器 of_irq_init 扫描时识别
#interrupt-cells 中断控制器 node 一个 specifier 占几个 32-bit cell OF 核心，切分 interrupts

对外设：interrupt-parent 说这根线物理上接到哪个 controller，interrupts 说细节——hwirq（由 interrupt-parent 指的那个 controller 解析）、触发类型等。对 controller：interrupt-controller 是空属性，有它就行；#interrupt-cells 说这个 controller 用几个 cell 描述一个 request line，一个 cell 就是一个 32-bit 单元，每个 cell 什么含义由 controller 自己定。非 root 的 controller 还有第三组——它自己也是挂在别的 controller 上的中断源，所以也要写 interrupts 和 interrupt-parent。

#interrupt-cells 决定 of_phandle_args.args_count，也就决定 xlate 收到几个 cell。GIC 常见是 3 个——SPI/PPI/SGI 类型、编号、触发方式。不同 controller 的 cell 数不一样，3 个只是 GIC 的口径。

dts
intc: interrupt-controller@f1000000 {
    compatible = "arm,cortex-a9-gic";
    interrupt-controller;
    #interrupt-cells = <3>;
    reg = <0xf1001000 0x1000>, <0xf1000100 0x100>;
};

地址和 compatible 只是常见取值，示意用，不对应某块具体板子。

十二、将 HW interrupt ID 转成 IRQ number 的完整链路 #

前面都在建库，这里用库。CPU 侧中断处理走四步：

  1. 找到 root interrupt controller 对应的 irq domain。
  2. 读硬件寄存器拿 HW interrupt ID，配合 domain 信息确认归属。
  3. irq_find_mapping 查出 hwirq 对应的 IRQ number。
  4. 调 handle_IRQ（ARM 平台）处理这个 IRQ number。
text
硬件中断
   ↓
CPU 进入 IRQ mode（硬件关中断）
   ↓
读 controller 的 ack / pending 寄存器 → hwirq
   ↓
irq_find_mapping(domain, hwirq) → virq
   ↓
desc = irq_to_desc(virq)
   ↓
desc->handle_irq(virq, desc)          ← high level irq-events handler
   ↓
desc->irq_data.chip->irq_mask/ack/eoi ← 底层硬件操作
   ↓
desc->action 链表 → specific handler  ← 驱动注册的那个
   ↓
（级联时这里不是外设的 action，而是子 controller 的 chained handler，
  在里头把「读寄存器 → irq_find_mapping → handle_irq」对子 domain 重走一遍）

级联时第 4 步不能直接调该 IRQ 的 specific handler。这个 hwirq 属于父 controller，它对应的 IRQ 是子 controller 挂上来的那根线，中断到底谁产生的，得去子 controller 再问一遍。

二阶级联：A 是 root，B 挂在 A 的 13 号 HW interrupt ID 上。B 初始化干两件事——作为中断控制器初始化自己（建 domain、建映射），作为 A 上的普通中断源用 irq_set_chained_handler 注册 13 号 IRQ 的 handler。于是第 4 步调到的是 B 的 handler，里头把 (1)~(4) 再走一遍：A 上 hwirq=13 翻成 virq=X、进 gic_handle_cascade_irq，在那里读 B 的寄存器得 hwirq=5，再用 B 的 domain 翻成 virq=Y，落到 Y 的 specific handler。级联线上父 controller 那根 IRQ 挂的是 chained handler，不是驱动注册的 action——这就是 __irq_set_handler 的 is_chained 参数存在的理由，第十五节还会碰到。

十三、GIC driver 初始化在这一链路里的位置 #

GIC 在链路里同时扮演两个角色：它既当得起别人的父，也当得起别人的子。

root GIC：第九节拆过——hwirq_base = 16，砍掉 0~15 的 IPI，irq_alloc_descs 申请 IRQ，irq_domain_add_legacy 注册 domain 并一次建完映射。它的 parent 参数是 NULL，gic_of_init 不会走级联那段代码。

second GIC：同一个 gic_init_bases，参数不同。

text

gic_irqs   = 系统支持的所有中断数目 - 32;
    0~15 是 IPI，16~31 是 PPI，对 second GIC 这两段都要剔掉，所以 hwirq_base 从 32 起。

irq_base = irq_alloc_descs(irq_start, 16, gic_irqs, numa_node_id());
    从 16 号开始搜 IRQ number。second GIC 申请到的会接在 root GIC 最后一个 IRQ 号后面。

gic->domain = irq_domain_add_legacy(node, gic_irqs, irq_base,
                hwirq_base, &gic_irq_domain_ops, gic);

index 0~32                      对应的 IRQ 无效（IPI 和 PPI 都不对应外设）
root GIC 最后一个 IRQ 号 + 1  <------------------> 32 号 HW interrupt ID
root GIC 最后一个 IRQ 号 + 2  <------------------> 33 号 HW interrupt ID
……

second GIC 的第二个身份。gic_of_init 里还有一段专给非 root 的 GIC：

void __init gic_cascade_irq(unsigned int gic_nr, unsigned int irq)
{
    if (irq_set_handler_data(irq, &gic_data[gic_nr]) != 0)   /* 设置 handler data */
        BUG();
    irq_set_chained_handler(irq, gic_handle_cascade_irq);     /* 设置 handler */
}

串起来：非 root GIC 的初始化分成两半。一半作为中断控制器，跑和 root GIC 一样的代码，建自己的 domain 和映射。另一半作为「产生中断的外设」，像普通驱动那样调 irq_of_parse_and_map 拿父 controller 上的 IRQ number，再用 irq_set_chained_handler 挂 handler。这两半正好对应它在拓扑里的位置：对下游外设它是 domain，对上游 controller 它只是一根 request line。

角色 做的事 用的接口
中断控制器 建 domain、建映射、实现 irq_domain_ops irq_domain_add_legacy / irq_alloc_descs
中断源（外设） 在父 domain 里拿 IRQ number、挂 chained handler irq_of_parse_and_map / irq_set_chained_handler

十四、中断描述符：struct irq_desc #

HW ID 翻译完得到 IRQ number，之后一切围绕这个 number 找描述符。每个外设 IRQ 一个 struct irq_desc，叫中断描述符。全系统的集合叫中断描述符 DB。发生中断后先拿 HW interrupt ID，经 irq domain 翻成 IRQ number，再取描述符，调它的 high level irq-events handler。

high level handler 干两件事：一是调底层 irq chip driver 的 mask / ack 等 callback 做 interrupt flow control；二是调该描述符 action 链表里的 specific handler。第二件不一定执行，看描述符当前状态。flow control 是软硬一起完成的——软件设标志位按标志位处理，硬件那边 mask / unmask 控制器。

老实现是一张静态表，irq number 当 index，描述符挨着排，NR_IRQS 是该平台 IRQ 最大数目，有几个 request line 就有几个描述符：

c
struct irq_desc irq_desc[NR_IRQS] __cacheline_aligned_in_smp = {
    [0 ... NR_IRQS-1] = {
        .handle_irq    = handle_bad_irq,
        .depth         = 1,
        .lock          = __RAW_SPIN_LOCK_UNLOCKED(irq_desc->lock),
    }
};

问题是有些平台把 NR_IRQS 定得很大，实际只用若干，表里全是空洞，内存白烧。为什么会有这种需求？素材的猜测是和各 controller 把硬件 interrupt ID 映射到 irq number 的算法有关。于是改成 radix tree 存描述符，hwirq 当索引，描述符动态分配后插树，代价是开 CONFIG_SPARSE_IRQ。DB 的形态变了，概念没变：仍然是「IRQ number → 描述符」。结构体本体（3.x / 4.x 早期口径）：

c

    unsigned int wake_depth;                     /* (5) wakeup source 的嵌套深度 */
    unsigned int irq_count;                      /* (6) broken IRQ 检测 */

    unsigned int irqs_unhandled;
    raw_spinlock_t lock;                         /* (7) 保护本描述符 */

#ifdef CONFIG_SMP

编号 字段 作用
(1) handle_irq high level irq-events handler。high level 对应 specific：specific 处理具体事务（按键、磁盘），high level 抽象各种中断的交互过程
(2) action struct irqaction 链表。request line 允许共享时可有多个节点，不允许就一个
(3) core_internal_state__do_not_mess_with_it 简写 istate，internal state。名字摆在那了，别直接改

(5) wake_depth irq_set_irq_wake 的嵌套深度，控制该 IRQ 能否把系统从 suspend 唤醒，必须成对
(6) irq_count / last_unhandled / irqs_unhandled broken IRQ 检测。handler 没落到正确 IRQ 上时，内核可以为这个没人处理的 IRQ 起 scan，让全系统的 handler 来认领

(8) percpu_enabled 该 IRQ 在各 CPU 上是否 enable。IRQ 分 global 和 per CPU 两种
(9) threads_oneshot / threads_active / wait_for_threads IRQ 线程化相关，另有专篇

istate 是个宏：#define istate core_internal_state__do_not_mess_with_it。

high level handler 按两个维度分工——中断控制器的类型、IRQ trigger type——分成四个常见实现：

handler 用于
handle_level_irq 电平触发
handle_edge_irq 边缘触发
handle_simple_irq 简单类型
handle_fasteoi_irq 需要 EOI 的控制器（GIC 属这一类）

handle_irq 默认值是 handle_bad_irq，静态表初始化填的就是它。四个 handler 的内部流程另有专篇。描述符 DB 初始化分两条路——静态表版本逐个 entry 走一遍，radix tree 版本按 arch_probe_nr_irqs 预分配一批（开了 CONFIG_SPARSE_IRQ 也照样预分配）：

c
/* 静态表版：desc_set_defaults 设默认值，handle_irq 落成 handle_bad_irq */
for (i = 0; i < ARRAY_SIZE(irq_desc); i++) {
    desc[i].kstat_irqs = alloc_percpu(unsigned int);
    alloc_masks(&desc[i], GFP_KERNEL, node);
    raw_spin_lock_init(&desc[i].lock);
    lockdep_set_class(&desc[i].lock, &irq_desc_lock_class);
    desc_set_defaults(i, &desc[i], node, NULL);

return arch_early_irq_init();

/* radix tree 版：arch 代码决定预分配多少，然后逐个插树 */
initcnt = arch_probe_nr_irqs();
if (initcnt > nr_irqs)
    nr_irqs = initcnt;
for (i = 0; i < initcnt; i++) {
    desc = alloc_desc(i, node, NULL);
    set_bit(i, allocated_irqs);

}

成员 干什么
name 中断控制器名字，/proc/interrupts 里显示
irq_startup / irq_shutdown / irq_enable / irq_disable 生命周期四件套。不实现就依次退到 irq_enable、irq_disable、irq_unmask

irq_eoi 通知控制器中断处理完了。GIC 有这种寄存器接口

irq_set_wake 电源管理，enable/disable 该中断源作为唤醒条件

生命周期那四个是「要不要自己实现」的工具位：不实现就退到更底层那个。最小可用的 irq chip 实现 irq_ack / irq_mask / irq_unmask 就够跑。

设定这些 callback 的接口也要看清。irq_set_chip 改 desc->irq_data.chip，用 irq_get_desc_lock（关中断 + spin lock）保护；irq_set_chip_data 改 chip_data，同样用它。irq_set_irq_type 不同，走 irq_get_desc_buslock(irq, &flags, IRQ_GET_DESC_CHECK_GLOBAL)，把 type 按 IRQ_TYPE_SENSE_MASK 裁一下交给 __irq_set_trigger，完事 irq_put_desc_busunlock。

为什么 irq_set_chip 用 irq_get_desc_lock、它用 buslock？前者不碰底层 controller，后者要调 chip->irq_set_type。SOC 内嵌 controller 的寄存器 memory map 在 CPU 地址空间里，访问快，关中断 + spin lock 没问题。但 controller 要是挂 I2C 的 IO expander 芯片，让别的 CPU 空转等 I2C 太亏，这种只能先把 bus 锁住（mutex，实现和 irq_bus_lock 相关），锁住之后才能关中断。

IRQ_GET_DESC_CHECK_GLOBAL 检查的是「这个 source 是不是 global」，对应的是 IRQ_GET_DESC_CHECK_PERCPU。SMP 下中断有两种 mode：1-N（只有一个 processor 处理）和 N-N（所有 processor 独立收到，N 个 CPU 收到就 N 个处理）。

拿 GIC 举例：SPI 是 1-N，PPI 和 SGI 是 N-N。SPI 在 1-N 模式下，系统（软硬一起）必须保证一个中断只被一个 CPU 处理。GIC 的一个 SPI 可以 trigger 多个 CPU 的 interrupt line（Distributor 的 Interrupt Processor Targets Registers 里置了多个 bit 就行），但该 source 和 CPU 之间的接口寄存器（比如 ack register）只有一套，是全局的。一个 CPU ack（读 Interrupt Acknowledge Register 拿 interrupt ID）之后，其他 CPU 看到的该 source 状态也是已 ack。第二个 CPU 去 ack，拿到的是 spurious interrupt ID。

PPI / SGI 走 N-N 模式，source 的寄存器是 per CPU 的，每个 CPU 有自己的那套（banked register）。一个 CPU 清了 pending，其他 CPU 感知不到，仍然认为中断是 pending 的。素材 2 的抓取件缺了这一段，本段按素材 3 补齐。

所以 irq_set_irq_type 只服务 1-N 模式的 source。底层要是 per CPU 的，它得返回错误。

设定 high level handler 的接口是 __irq_set_handler，一般不直接调，走 irq_set_chip_and_handler_name 或 irq_set_chip_and_handler。函数用 irq_get_desc_buslock 拿描述符，写 desc->handle_irq = handle、desc->name = name；handle != handle_bad_irq && is_chained 成立时，再 irq_settings_set_noprobe / set_norequest / set_nothread 三个标志一起设，最后 irq_startup(desc, true)。

关键在 is_chained。控制器 B 级联到 A 的第 x 个 interrupt source 上，对 A 的 x 这个中断设 handler 时要把 is_chained 置 1。这个 source 用于级联，所以不能 probe、不能被 request（已经被 B 用了）、不能被 threaded。

十六、irq 的打开与关闭 #

「开关中断」是两件事：

  1. 开关 local CPU 的中断。UP 下关了 CPU 中断就关了一切，永远不会被抢占。SMP 下没有「关全局中断」这回事，只能关当前 CPU 的。
  2. 控制 interrupt controller，关掉某个 IRQ number 对应的中断。准确说法是 mask / unmask 一个 IRQ。

进入 high level handler 时，CPU 中断已经是关的——硬件进 IRQ processor mode 时就设好了。

外设的 specific handler 在旧内核（2.6.35 之前）分 slow 和 fast 两类。request_irq 时给 fast handler 传 IRQF_DISABLED，保证整个处理过程关 CPU 中断——它快，关了不影响性能。磁盘这类 handler 慢，全程关中断性能会掉。于是 slow handler 从 high level handler 切进 specific handler 时，按 IRQF_DISABLED 决定要不要开中断：

c
irqreturn_t handle_IRQ_event(unsigned int irq, struct irqaction *action)
{
    ……
    if (!(action->flags & IRQF_DISABLED))
        local_irq_enable_in_hardirq();
    ……
}

没设 IRQF_DISABLED（slow handler）就打开本 CPU 中断。这份代码来自 2.6.23。

到 3.14，IRQF_DISABLED 已经废弃。条件两头都变了：硬件上 CPU 越来越快，原来的 slow handler 也能很快跑完；软件上 bottom half 机制更完备。回头看 slow handler 这个设计——每个 handler 都该迅速执行完返回中断现场，为什么允许慢？允许任意中断打断 slow handler，嵌套会加深，对内核栈是考验。新内核里 specific handler 全程关 CPU 中断。

上面是 CPU 中断那层。另一层是某个 IRQ 的 enable / disable，由 depth 管：

操作 对象 计数 落点
local_irq_save / local_irq_restore 当前 CPU 无 CPU 状态寄存器
disable_irq / enable_irq 某个 IRQ desc->depth high level handler 里 mask / unmask 硬件
irq_set_irq_wake 某个 IRQ 的唤醒能力 desc->wake_depth chip->irq_set_wake

depth 的语义：disable_irq 加一，enable_irq 减一，减到 0 才真正 unmask 硬件。嵌套可以，必须成对。disable_irq 和 disable_irq_nosync 的差别在要不要等正在跑的 handler 结束，属同步细节，另篇。

十七、几个容易混的位：irq_data、irq_desc、irq_domain 的关系 #

三个结构体名字都带 irq，职责完全不同。先看 irq_data：

c
struct irq_data {
    u32            mask;                  /* 素材原文标 TODO，含义未说明 */
    unsigned int   irq;                   /* IRQ number */
    unsigned long  hwirq;                 /* HW interrupt ID */
    unsigned int   node;                  /* NUMA node index */
    unsigned int   state_use_accessors;   /* 底层状态，参考 IRQD_xxxx */
    struct irq_chip   *chip;              /* 该中断对应的 irq chip */
    struct irq_domain *domain;            /* 该中断对应的 irq domain */
    void           *handler_data;         /* 和 specific handler 相关的私有数据 */
    void           *chip_data;            /* 和中断控制器相关的私有数据 */
    struct msi_desc *msi_desc;
    cpumask_var_t  affinity;              /* irq affinity 相关 */
};

它是描述符里「和底层硬件打交道」的那一坨，独立打包的原因是 irq chip 的 callback 都拿 struct irq_data * 当参数，有了它就不用把整个 struct irq_desc 传进去。

node 记描述符内存落在哪个 memory node。NUMA 系统里不同 node 的内存访问速度不同，某个 IRQ 固定由某个 CPU 处理时，描述符该分配在近的那个 node 上。msi_desc 是 MSI（Message Signaled Interrupts）相关——中断有两种形态：一种 signal 线直接连，电平或边缘触发；另一种基于消息，就是 MSI。本篇不展开。

三者分工：

结构体 粒度 装什么 谁创建 谁用
struct irq_domain 一个 interrupt controller 一个 映射表（线性 table 或 radix tree）+ irq_domain_ops + controller 私有数据 controller driver 初始化时 irq_create_mapping、irq_find_mapping、xlate
struct irq_desc 一个 IRQ number 一个 handle_irq、action 链表、统计、锁、depth、线程化状态 early_irq_init 或 irq_alloc_descs 中断热路径、request_irq、disable_irq
struct irq_data 一个 IRQ number 一个（内嵌在 irq_desc 里） irq、hwirq、chip、domain、chip_data、handler_data 随 irq_desc 一起 irq chip 的所有 callback 
text
struct irq_desc
 ├── irq_data            ← 内嵌，第一个成员
 │    ├── irq           （IRQ number，本描述符的编号）
 │    ├── hwirq         （HW interrupt ID，映射的另一端）
 │    ├── chip    ──────→ struct irq_chip   （底层硬件操作）
 │    ├── domain  ──────→ struct irq_domain （映射 DB + ops）
 │    ├── chip_data      （controller 私有数据）
 │    └── handler_data   （specific handler 私有数据）
 ├── handle_irq          （high level handler）
 ├── action      ──────→ struct irqaction 链表（specific handler）
 ├── depth / wake_depth
 └── lock / kstat_irqs

连接点就两个指针：irq_data.domain 指回映射表，irq_data.chip 指向硬件操作集。建映射时 irq_domain_associate 先填 irq_data->hwirq = hwirq、irq_data->domain = domain，再由 ops->map 去设 chip。

一句话分清：domain 管「hwirq ↔ virq」，desc 管「virq 上有什么 handler、什么状态」，irq_data 管「这个 virq 的硬件那半边」。调用链：

text
virq → irq_to_desc() → struct irq_desc
desc->handle_irq()  → generic 流程
desc->irq_data.chip->irq_xxx()  → 摸硬件

十八、易错点速查 #

  • hwirq 和 virq 撞类型转换。两个都是整数，编译不报错。变量名带上 hwirq / virq，别都叫 irq。
  • 以为 hwirq 全局唯一。跨 domain 会重名，查表必须带 domain。
  • 以为 linear_revmap 存的是 irq_desc 指针。linear 下存的是 virq（unsigned int），radix tree 下才存 struct irq_data *。看 irq_domain_associate 那两行。
  • 用 domain 类型字段判断分支。irq_domain_associate 判的是 hwirq < domain->revmap_size。revmap_size 设 0 就等于切到 radix tree。
  • 忘了 IRQ_NOREQUEST。映射建完之前该 IRQ 不能被 request_irq，清标志在 irq_domain_associate 末尾。
  • legacy 和 linear 搞混。legacy 注册就建完映射，linear 注册完是空表。GIC 用 legacy 是历史债，不代表推荐做法。
  • revmap_direct_max_irq 在 linear / tree 下瞎填。两种情况都填 0，只有 no map 才用。
  • irq_set_chip 与 irq_set_irq_type 的锁不同。前者 irq_get_desc_lock，后者 irq_get_desc_buslock。后者要摸硬件，controller 在慢速总线上时得先锁 bus。
  • IRQ_GET_DESC_CHECK_GLOBAL 用错。irq_set_irq_type 只服务 1-N 模式的 source。GIC 的 SPI 是 1-N，PPI / SGI 是 N-N。底层 per CPU 时它要返回错误。
  • is_chained 忘了设。级联线上那根 IRQ 要设 is_chained = 1，否则会被 probe、被 request_irq、被线程化。
  • 以为 depth 是次数统计。它是嵌套深度，disable_irq / enable_irq 不成对就永远关着。
  • IRQF_DISABLED 还在用。3.14 就废弃了，specific handler 全程关 CPU 中断。
  • 以为老的 irq_desc[NR_IRQS] 表还在。CONFIG_SPARSE_IRQ 下是 radix tree，描述符动态分配。
  • 混淆 high level handler 和 specific handler。desc->handle_irq 是前者（handle_level_irq 一类），desc->action 里的是后者。触发方式归前者，业务归后者。
  • xlate 返回值不检查。非 0 表示解析失败，irq_create_of_mapping 返回 0，后面 request_threaded_irq 就拿到无效 IRQ。
  • 只写 interrupts 不写 interrupt-parent。找不到 domain 就找不到 controller，映射建不起来。
  • #interrupt-cells 和 xlate 对不上。cell 数由 controller 定，xlate 里的 intsize 就是它。写错解析出垃圾 hwirq。
  • 以为 parent_irq 是级联链的父 IRQ。它在 struct irq_desc 里，用途素材未说明，别猜。
