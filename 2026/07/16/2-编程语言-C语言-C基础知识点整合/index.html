C 语言底层及核心基础知识点整合

C 语言底层及核心基础知识点整合

1. Linux man 帮助手册与基础开发概念

1.1 Linux man 手册的正确打开方式

在 Linux 下使用 man 命令查文档时，后面带的数字（分卷号）决定了你查的是系统命令、库函数还是内核结构。

  • 1 (Standard commands): 标准 Shell 命令（如 ls, cd）。
  • 2 (System calls): 系统调用，直接和内核打交道的函数（如 open, write）。
  • 3 (Library functions): C 语言库函数（如 printf, malloc）。
  • 4 (Special devices): 特殊设备/设备文件说明。
  • 5 (File formats): 配置文件格式说明（如 /etc/passwd）。
  • 6 (Games and toys): 游戏 and 娱乐。
  • 7 (Miscellaneous): 杂项（一些惯例、协议或宏定义）。
  • 8 (Administrative Commands): 系统管理员命令（通常需要 root 权限，如 ifconfig）。
  • 9 (Linux 内核例行程序文档): 专门存放内核底层驱动和子系统相关的文档（Linux 特定）。

1.2 关键字底层约束与基本类型设计小记

C 语言（以 C89/C90 为基准）共定义了 32 个关键字。以下是几个容易被混淆或遗漏的关键字底层特性与设计细节：

1) sizeof：是编译期关键字，而非函数

  • 物理本质：sizeof 是一个编译期求值关键字（其运算结果在编译时就已经由编译器计算确定为常量），而不是在程序运行阶段调用的“函数”。

    表达式 sizeof(int) * p 表示什么意思？
    • 它在 C 语言中被解析为：sizeof(int) 的求值常量与变量 p 执行乘法运算，即 (sizeof(int)) * (p)，而并不是某种特殊的指针求值或内存计算。

2) register 寄存器变量

把变量塞进 CPU 寄存器里，读写速度直接起飞。但使用时有两个硬性条件：

  1. 必须是 CPU 寄存器能吞下的值：其大小通常受限于 CPU 的字长（例如 32 位系统最多 4 字节，64 位系统最多 8 字节）。像结构体、数组这种大体量的玩意儿，寄存器是装不下的。
  2. **不能对其使用取地址符 &**：寄存器在 CPU 内部，没有内存地址，所以 &register_var 会直接引发编译器报错。

3) static 静态约束

static 最主要的作用就是限制可见性，防止命名空间污染：

  • static 修饰全局变量：该变量的作用域被死死限制在声明它的当前 .c 文件中，其他源文件即使声明了 extern 也无法访问。
  • static 修饰函数：同理，该函数仅在当前 .c 文件内可被调用，对外部隐藏，是实现模块封装的常用手段。

4) volatile 易变类型修饰符与 MMIO 轮询

  • 核心机制：用于告诉编译器，被修饰的变量的值可能会被程序之外的未知因素（如：硬件寄存器、多线程并发共享、信号处理函数等）随时修改。
  • 防止编译器优化：默认情况下，如果一个变量在当前代码流中没有被改写，编译器为了优化读取速度，会将其缓存在 CPU 寄存器中而不再去真正读取内存。volatile 关键字强制要求编译器每次读取该变量时都必须直接从它的物理内存地址中加载新值，并且禁止指令重排优化。
  • 硬件内存映射 I/O (MMIO) 轮询示例：

  • 多线程安全注意事项：
    1. 在临界区内部（如获取了互斥锁 mutex 后），由于锁的获取和释放本身带有**内存屏障 (Memory Barrier)**，能保证数据的可见性与更新，因此通常不需要用 volatile。
    2. 在临界区外部，被多个线程并发轮询或访问的共享变量，应当使用 volatile。
    3. volatile 类型的对象只能调用 volatile 修饰的成员函数。

5) 符号缺省规则与无符号常量后缀

  • 缺省有符号限制：在 C 语言缺省情况下，编译器会默认所有基本的整型数据类型（如 int, short, long 等）为 signed 类型。
  • char 类型的唯一例外：char 类型的数据除外。标准的 char 既不默认代表 signed char 也不默认代表 unsigned char，它的具体符号类型取决于编译器的具体实现和编译 flags 选项。
    • 语义约定：在系统底层和网络传输中，通常建议将 char 类型专门用来定义字符类型（只保存字符）；而数值型的 8 位整型数据，应显式地定义为 signed char（数值范围 -128 到 127）或 unsigned char（数值范围 0 到 255）。
  • 无符号常量 U 后缀：在程序中编写所有无符号型常量值时，应养成规范书写字母 U / u 后缀 的良好习惯（例如 10U, 0xFFFFU），这能强制编译器将其解释为无符号数，防范因隐式符号提升导致的安全缺陷。

1.3 C 语言编译流程与 GCC 编译指令

C 语言源程序从文本代码编译生成最终可执行二进制文件，在底层需要经历以下四个关键阶段：

阶段 核心任务 输入文件 输出文件 对应的 GCC 编译命令
1. 预处理 (Preprocessing) 去除代码注释，执行文件包含（#include 展开），执行宏定义代换，展开条件编译（#if / #endif）。 .c (源文件) .i (预处理文本) gcc hello.c -E -o hello.i
2. 编译 (Compilation) 对预处理后的代码执行词法、语法和语义静态检查。无误后将其翻译成目标 CPU 架构的汇编语言代码。 .i .s (汇编源文件) gcc hello.i -S -o hello.s
3. 汇编 (Assembly) 汇编器将 .s 中的汇编指令逐句翻译成 CPU 直接执行的二进制机器语言指令（机器码）。 .s .o (目标二进制文件) gcc hello.s -c -o hello.o
4. 链接 (Linking) 将编译生成的多个 .o 文件与系统提供的第三方二进制库文件（静态库 .a / 动态库 .so）链接并整合为一体。 .o + 库文件 可执行文件 (如 hello / a.out) gcc hello.o -o hello

[!TIP]

  1. 生成 .i 和 .s 文件都是易读的纯文本文档，可在开发中利用 cat 或 vim 打开观察预处理和汇编结果（用于辅助排查宏定义 bug 或优化底层汇编逻辑）。
  2. .o 目标二进制文件包含的已经是纯粹的机器码，直接文本打开为乱码。
  3. 若不指定输出名称（即运行 gcc hello.c），编译器默认会产生文件名为 a.out 的可执行程序。

1.4 C 语言标识符命名规则

在 C 语言中，变量名、函数名等标识符必须遵循以下硬性约束：

  1. 字符限制：只能由字母、数字和下划线 _ 三种字符组成，且第一个字符必须为字母或下划线（数字不能开头）。
  2. 大小写敏感：C 语言严格区分大小写（例如 data 和 Data 是两个完全不同的标识符）。
  3. 避开关键字：用户自定义的标识符绝对不能与 C 语言自带的关键字同名。

1.5 C 头文件 (.h) 的作用与编写规范

头文件在 C 语言项目工程化管理中起到了桥梁作用，它规范了模块之间的接口暴露与可见度。

1) 为什么需要头文件？

  1. 作用域可见度限制：C 语言编译器对源文件的编译是自顶向下单向执行的。一个函数如果没有单独声明，它的作用域只从它的定义行位置开始。如果 main() 函数在被调用函数定义之前就执行了调用，编译器会因为“未知标识符”直接报错。
  2. 解决相互递归（函数嵌套调用）：当函数 A 调用函数 B，且函数 B 同时又调用函数 A 时，无论将哪个函数放在前面定义，都会因另一个函数未定义而报错。此时必须在调用前对至少一个函数进行提前声明。
  3. 分工协作与接口公开：在大规模工程中，为了避免在每个源文件中重复编写长串声明，人们将公共的常量定义、数据结构声明和函数原型集中写入头文件 .h 中，各源文件只需 #include 即可。

2) 头文件里应该有什么？

  • 宏常量定义（#define MAX 100）。
  • 结构体、共用体和枚举类型定义（typedef struct ...）。
  • 全局函数原型声明（如 int get_value(void);）。
  • 外部全局变量的引用声明（使用 extern 关键字，如 extern int global_counter;）。

3) 头文件里绝对不能有什么？

  • 不能有全局变量的定义（如 int global_counter = 10;）。
  • 不能有函数的具体实现（定义）。

    [!CAUTION]
    如果在头文件中进行变量定义或函数定义，一旦该头文件被两个或以上的 .c 源文件 #include，在链接阶段，链接器就会因发现多个同名的全局实体，直接抛出经典的 LNK2005 (符号重定义) 链接错误！

1.6 C 语言断言 (assert) 调试工具与 NDEBUG 规范

断言（assert）是 C 语言开发和调试中用于检验程序状态、防范逻辑 bug 的强大宏定义。

1) 头文件与定义

  • 核心机制：在运行时计算括号内的 expression 表达式。如果计算结果为真（非 0），程序继续运行；如果为假（0），assert 会先向标准错误流 stderr 输出一条详细的出错报告（包含当前文件名、行号、所在的函数名以及导致失败的表达式原文），接着调用 abort() 函数立即强退、终止当前程序。

2) 断言使用的三大原则

  1. 单断言单条件：每个 assert 最好只检验一个特定的条件。如果是多个条件合并校验（如 assert(a >= 0 && a < max);），一旦断言失败，控制台输出只会显示这长段表达式，难以直观辨别具体是哪一个子条件失败。应改为分立书写。
  2. 严禁含有副作用（Side Effects）的表达式：
    • ❌ 致命错误示范：assert(i++ < 100);
    • 错误分析：如果程序中启用了 NDEBUG 屏蔽了断言，编译器在生成生产版本二进制文件时会直接剔除这整条 assert 代码，这会导致 i++ 这一关键的数据修改动作直接丢失，使程序逻辑彻底失控！
    • 正确写法：先执行运算，再做测试：assert(i < 100); i++;
  3. 不要用于公有 API 接口的输入验证：断言是专为 Debug 版本开发的，用于检查“理论上绝对不应该发生的事情”（如内部指针为 NULL）。对于暴露给外部的公有函数，必须使用显式的 if (param == NULL) return ERROR; 进行逻辑过滤与错误恢复，以维护代码的健壮性。

3) NDEBUG 宏与 Release 版本去断言优化

频繁调用 assert() 会因为额外的分支检查极大地拖累执行性能。在调试完成、项目交付生成最终生产（Release）版程序时，我们可以在包含头文件之前定义 NDEBUG 宏来一键屏蔽所有断言：

  1. .text 代码段：存放编译后的二进制可执行机器码，只读。

3. 数据类型与类型转换

3.1 隐式类型转换规则

在 C 语言的混合运算中，若未人为控制类型，系统会自动进行隐式转换。自动转换遵循“小类型向大类型看齐”的原则：
char -> short -> int -> unsigned int -> long -> unsigned long -> double（其中 float 会自动提升为 double 参与运算）。

[!NOTE]
类型转换改变的是运算过程中数值的临时类型，而绝不改变变量本身声明的类型与大小。

经典隐式转换越界大坑：

  • 输出结果：yes
  • 原理解析：在计算 a + b 时，由于 b 是 unsigned int（无符号），有符号的 a 会被隐式自动转换为无符号整型参与运算。-6 在无符号整型下的内存表现形式是一个极大的正数（在32位下为 4294967290），相加后依然是极大正整数，所以条件为真。
  • 输出格式区别：若以 %d 打印 a + b，结果为 -5（重新按有符号数解析符号位）；若以 %u 打印，结果为大整数 4294967291。

3.2 赋值强制类型转换

当赋值运算符两侧的数据类型不一致时，会发生赋值转换：

  1. 整型与浮点型：
    • 浮点型赋给整型：直接舍去小数部分，只保留整数（如 int a = 3.5; 结果 a 为 3）。
    • 整型赋给浮点型：数值不变，以浮点格式存储（如 float f = 4; 实际存储为 4.0）。
  2. **double 与 float**：
    • double 赋给 float：截取前 7 位有效数字存储在 float 中，需注意数值大小不可溢出 float 范围。
  3. **char 与 int**：
    • int 赋给 char：直接截断高位，仅保留低 8 位存储在 char 中。
    • char 还原为 int：
      • 无符号 char (unsigned char)：低 8 位直接复制，高 24 位一律补 0。
      • 有符号 char：低 8 位复制。若首位（符号位）是 0，则高 24 位补 0；若首位是 1，高 24 位**全部补 1**（符号位扩展）。
  4. **int 与 long**：
    • long 赋给 int：截断高位，低位直接复制。
    • int 赋给 long：无符号 int 高位补 0；有符号 int 根据首位进行符号位扩展（首位为 0 补 0，首位为 1 补 1）。

3.3 强制类型转换的副作用

强制类型转换 (类型)变量 只是在当前计算步骤中临时生成该类型的副本，不改变原变量的物理类型和存储值。

4. 表达式与控制流核心逻辑

4.1 运算符分类、结合性与优先级

1) 运算符目数分类

  • 单目运算符：仅需 1 个操作数的运算符（如 !, ++, --, ~, sizeof）。
  • 双目运算符：需要 2 个操作数的运算符（如 +, -, *, /, &&, ||）。
  • 三目运算符：仅有一个，即条件运算符 ?:。

2) 结合性与优先级

  • **左结合性 (自左至右)**：绝大多数运算符（如算数、关系、逻辑、位运算）都是左结合的。
  • **右结合性 (自右至左)**：赋值运算符 = 及其复合赋值（如 +=, *=）、单目运算符（如自增、取反、负数）以及三目条件运算符都是右结合的。
  • 优先级误区：优先级高并不代表它在时间上先被运算！ 优先级只决定了操作数与哪个操作符结合。整个算式表达式的求值顺序依然是从左向右进行的。

4.2 逻辑运算符短路机制与自增结合陷阱

1) 逻辑短路 (Short-Circuit)

  • && 短路：表达式1 && 表达式2 && 表达式3。如果 表达式1 为假，则后面的表达式全部被跳过，不再执行。
  • || 短路：表达式1 || 表达式2 || 表达式3。如果 表达式1 为真，则后面的表达式全部跳过，不再执行。
经典运算分析：
  • 分析：首先计算 a++，取出 a 的初始值 0。因为为假，&& 发生短路，后面的 b-- 和 ++c 被全部跳过不执行。最后 a 自增为 1。
  • 分析：首先取出 a 值为 0。|| 前驱为假，继续向右计算 b--。取出 b 值为 1，为真。|| 发生短路，跳过后面的 ++c。最后 a 自增为 1，b 自减为 0，c 保持 2 不变。

2) 自增运算符前置与后置

  • **前置 (++i)**：先执行自增，后将自增后的新值代入算式运算。

4.4 else 匹配规则与 switch-case 避坑指南

if-else 嵌套匹配规则

在 C 语言中，else 语句总是与同一块中距离它最近且之前未与其他 else 关联的 if 语句相匹配。即使缩进不对，编译器依然遵循这个最邻近原则。为了避免歧义和大坑，强烈建议在 if/else 分支中显式写上花括号 {}。

switch-case 核心细节与注意事项

switch 语句是一种多路判定结构，通过判断表达式的值与一组常量值是否匹配来决定分支执行。

  1. 类型匹配约束：switch(表达式) 中表达式的最终计算值必须是整型（包括 char、short、int、long 等），不能是浮点型或双精度浮点型。case 后面紧跟的必须是常量或常量表达式（同样必须为整型或字符型），且同一 switch 中多个 case 后的常量值不能相等。
  2. break 语句省略行为：break 用于跳出当前整个 switch 结构。如果省略 break，程序流会发生击穿（Fall-through），继续无条件执行下一个 case 之后的语句，直到遇到 break 或 switch 块结束。
  3. default 关键字规范：default 分支在所有 case 都不匹配时执行。虽然在语法上可以省略，但根据编程规范，为了程序的健壮性，不建议省略。此外，case 和 default 的先后顺序可以调换，不影响执行逻辑。将最常匹配的 case 分支放在最前面可以微弱提高执行效率。
  4. 分支选择原则：如果判断条件是一个连续或复杂的范围，必须使用 if-else if 分支；如果只是离散的整数或字符常量匹配，使用 switch-case 结构会更清晰高效。

4.6 break、continue 与 return 核心控制转移

  • **break**：
    • 用于在 switch 中终止 case。
    • 用于立即跳出当前的循环体（while、do-while、for），执行循环后面的语句。

5. 输入输出与字符串处理技巧

5.1 printf 与 scanf 深度解析

printf 控制台显示函数

  • 函数原型：int printf(const char *format, ...);
  • 控制字符串：由文本字符和格式占位符（如 %d, %f）组成。
  • 返回值：成功时返回实际输出的字符数量（包括空格和换行），若发生错误则返回 EOF（通常为 -1）。
  • 格式代码约定：
    • %d：有符号十进制整数。
    • %f：浮点数如实输出，默认保留 6 位小数；若不足 6 位则末尾填零，若超过则进行四舍五入。
    • %e：指数（科学计数法）格式，小数点左侧保留 1 位数字，右侧保留 6 位数字。

printf 宽度与精度修饰符

  • **%md**（m为整数）：设置输出最小宽度。
    • m > 0：靠右对齐，左侧不足补空格；
    • m < 0：靠左对齐，右侧不足补空格。
    • **%0md：不足宽度时左侧不补空格而是补 0**。
  • **%m.nf**：控制浮点数的输出宽度和小数保留位数。n 指定保留几位小数，进行四舍五入（n 不能为负数）。
  • %*d 动态宽度：使用 * 动态接收参数传入的宽度值，例如 printf("[%*d]", 5, 123); 输出 [ 123]。
  • 其他长度修饰符：%ld 输出长整型 long，%lf 输出双精度 double，%hd 输出短整型 short。

scanf 数据接收函数

  • 函数原型：int scanf(const char *format, ...);
  • 参数地址规则：
    • 基本数据类型：必须传递变量的地址，在变量名前面加上取地址符 &（例如 scanf("%d", &num);）。
    • 指针/数组变量：因为指针或数组名本身就是地址，所以千万不能加 &（例如 char buf[32]; scanf("%s", buf);）。
  • 返回值：成功读取并赋值的参数个数。如果发生输入格式不匹配或到达文件尾，返回 0 或 EOF。

scanf 分割符与非打印字符

  • 默认分割符：scanf 会默认自动忽略空格、Tab 制表符、回车换行等非打印字符来判定输入的边界。因此 scanf("%d%d", &a, &b); 无论是输入 3 4，还是输入 3回车4，均合法。
  • 格式强制分割：如果格式控制字符串中带有了非占位符普通字符，如 scanf("%d,%d", &a, &b);，输入时必须严格输入逗号 , 分割（例如 3,4），输入 3 4 会解析失败。

5.2 缓冲输入/输出 (Buffer I/O) 底层原理

标准输入输出并不是 CPU 直接和硬件交互，而是在程序与输入/输出设备之间建立了一块临时内存区，称为缓冲区。

  • stdin 缓冲区：键盘输入的数据首先排队进入输入缓冲区。只有当用户按下回车键（\n）时，数据才会被送入缓冲区中，随后程序的 scanf 或 getchar 才会从该缓冲区中读取字符。
  • stdout 缓冲区：程序输出的数据也是先写入输出缓冲区，当缓冲区满、遇到换行符 \n、或手动执行 fflush(stdout) 时，数据才会被物理刷新输出到显示器屏幕上。
  • 核心作用：缓冲区的存在主要是为了协调高速 CPU 与低速输入/输出外设之间的读写速率差异，减少硬件级中断次数，大幅提升系统吞吐性能。

5.3 字符数据输入输出函数：putchar 与 getchar

1) putchar() 字符输出函数

  • 原型：int putchar(int c);
  • 使用：c 可以是 0~127 的 ASCII 整数、字符变量或转义字符（如 putchar('A'), putchar(65) 等）。
  • 返回值：正确时返回输出字符的 unsigned char 值，失败返回 EOF。

2) getchar() 字符输入函数

  • 原型：int getchar(void);
  • 返回值：正确时返回读取字符的 ASCII 码值，失败返回 -1。

⚠️ 致命的换行符残留陷阱

很多初学者在连续读入字符时会遇到输入跳过的问题：

  • Bug 表现：输入 x 回车，随后输入 y。会发现屏幕上只打印了 x 并发生换行，没能读取到 y。
  • 成因解析：用户在输入 x 并按下回车时，输入缓冲区中实际存入了两个字符：'x' 和 '\n'。第一个 getchar() 正确取走 'x'，但留在缓冲区内的换行符 '\n' 会被第二个 getchar() 直接取走赋值给 b。
  • 解决方案：在两次读取之间，应使用缓冲区清理机制（如空读一次 getchar() 吞掉 \n，或使用 CLEANUP() 宏）。

5.4 字符串接收函数：gets 与 fgets

  • gets（已废弃）：
    • 原型：char *gets(char *string);
    • 机制：从标准输入读入一行文本，直到遇到换行符 \n。它会自动丢弃换行符并用 \0 封尾。
    • 严重缺陷：gets 绝不检查目标缓冲区的大小，输入超出长度时会发生严重的堆栈缓冲区溢出崩溃。
  • fgets（标准推荐）：
    • 原型：char *fgets(char *s, int n, FILE *stream);
    • 机制：从指定的文件流中最多读取 n-1 个字符，并写入 s 中，末尾自动追加 \0。如果读取到换行符，换行符会被保留在 s 中，随后停止读取。

5.5 字符搜索函数：strchr 与 strstr

  • strchr：在一串字符中找单个字符。
    • 原型：char *strchr(const char *s, int c);
    • 机制：查找字符 c 在字符串 s 中第一次出现的位置。成功返回指向该字符的指针，失败返回 NULL。
  • strstr：在一串字符中找另一个字符串。
    • 原型：char *strstr(const char *s1, const char *s2);
    • 机制：查找子串 s2 在主串 s1 中第一次出现的位置。成功返回指向子串起始处的指针，失败返回 NULL。

1) 宏实参必须加上保护性括号

宏展开只是物理上的纯文本替换，不包含任何逻辑运算优先级检查。如果宏参数在展开时包含操作符，会由于操作符优先级导致非预期结果。

8. 二进制位运算与移位操作

8.1 按位逻辑运算符

位运算符的操作数必须是整数或字符型数据。在底层，运算会对整数的二进制补码的每一位进行运算。

  1. **按位与 &**：同为 1 则为 1，否则为 0（如 1 & 1 = 1, 1 & 0 = 0）。用于特定位清零、提取特定位。
  2. **按位或 |**：有一位是 1 则为 1，全为 0 则为 0（如 1 | 0 = 1, 0 | 0 = 0）。用于特定位置 1。
  3. **按位异或 ^**：不同为 1，相同为 0（如 1 ^ 0 = 1, 1 ^ 1 = 0）。用于特定位取反、数据交换。
  4. **按位取反 ~**（单目）：1 变 0，0 变 1。

    [!WARNING]
    切勿将按位逻辑符（&, |）与逻辑控制符（&&, ||）混淆，前置是对二进制位操作，后者是计算布尔逻辑并包含短路机制。

8.2 移位运算符

  • **左移 <<：a << x。将 a 的二进制补码向左整体移动 x 位。高位溢出舍去，低位补 0**。
    • 数学等价：对于未溢出的整数，左移 x 位相当于**乘以 $2^x$**。
  • **右移 >>**：a >> x。将 a 的二进制补码向右整体移动 x 位。低位溢出丢弃，高位补齐规则如下：
    • 无符号数/非负有符号数：高位一律**补 0**（逻辑右移）。
    • 负数有符号数：高位补 0 还是补 1 取决于编译器系统。补 0 称逻辑右移，补 1（保留原负数符号位）称算术右移。大多数现代操作系统（如 Linux）默认为算术右移。
    • 数学等价：右移 x 位相当于除以 $2^x$ 并向下取整。

      [!NOTE]
      位运算在 CPU 中的执行速度极其快，从算法优化的角度，使用位移代替普通的乘除法可以微弱提高运行效率。

11. 有限状态机 (FSM) 编程模型与文本解析实战

有限状态机（Finite-state machine, FSM）是一种用于表示有限个状态以及在这些状态之间进行转移和动作的数学逻辑模型。
在 C 语言程序设计中，当面对复杂的文本分析、词法分析、协议校验等容易导致嵌套 if-else 代码爆炸、思维混乱的场景时，采用有限状态机模型能让程序结构清晰、扩展性极强、且极不易出错。

11.1 FSM 在 C 中的标准实现框架

在 C 语言中，有限状态机通常通过以下结构实现：

  1. 用 enum 定义状态集。
  2. 用一个状态变量（如 state）记录当前所处的状况。
  3. 循环（如逐字节读取 getchar() 或遍历数组），内部配合 switch(state) 针对不同状态和输入事件进行分流决策（动作 + 状态转移）。

11.2 实战案例 1：压缩连续空格

题目要求：将输入字符串中连续的多个空格压缩成一个空格输出。例如输入 "H el lo"，输出 "H el lo"。

1) 状态转移设计

  • **状态 0 (STATE_CHAR)**：当前正在处理非空格字符状态。
    • 输入非空格：打印字符，状态保持在 STATE_CHAR。
    • 输入空格：打印当前空格，状态转移到 STATE_SPACE。
  • **状态 1 (STATE_SPACE)**：当前处于已经打印过一个空格的状态（后续空格应当被屏蔽）。
    • 输入空格：忽略不打印，状态保持在 STATE_SPACE。
    • 输入非空格：打印字符，状态转移回到 STATE_CHAR。
