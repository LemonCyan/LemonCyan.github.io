Hexo 部署与自动化发布全栈实战

构建现代个人技术博客与知识库的核心设计思想是 「源码与静态产物解耦」。通过将 Hexo Markdown 源文件、主题配置及私有脚本保存在私有仓库中，利用云端 CI/CD（如 GitHub Actions）在容器中自动编译构建，再将生成的静态 HTML/CSS/JS 文件分发到全球托管平台（如 GitHub Pages、Cloudflare Pages 或自建 VPS），实现 “本地专注写作，Git 推送即刻全球发布” 的极致工作流。

2. 仓库架构设计与安全隔离机制

为了确保核心私密数据、Obsidian 草稿及图床资源井井有条，推荐采用 多仓库/分支分离架构：

2.1 各仓库与分支职责划分

  1. 源码仓库（私有，如 BlogDeploy）：
    • 存放全站的核心源文件、Markdown 笔记、站点与主题配置文件。
    • 私有化保障：未公开发布的草稿（_drafts/）与敏感私有配置不会泄露到公网。
  2. 发布仓库（公有，如 username.github.io）：
    • 仅存放 Hexo 编译输出的 public/ 静态网页。
    • 在该仓库的 Settings > Pages 中将构建源设为 main 分支根目录 /，即可对外服务。
  3. 图床仓库 / 分支（如 username.github.io@ImageBed）：
    • 集中存储博客引用的高清插图与动图。
    • 访问链接采用 CDN 加速：https://cdn.jsdelivr.net/gh/username/username.github.io@ImageBed/2026/image.png。

5. GitHub Actions 自动化 CI/CD 全流程实战

利用 GitHub Actions，可以在每次 git push 到源码仓库 main 分支时，自动启动 Ubuntu 容器完成依赖拉取、时间戳恢复、主题配置注入、静态网页生成并安全推送到 username.github.io。

5.1 配置 SSH Deploy Key 跨仓库免密授权

由于 CI/CD 流水线运行在源码仓库中，需要向独立的发布仓库推送代码，必须配置专用的 SSH Deploy Key 密钥对：

  1. 在本地生成专用部署密钥对： 得到两个文件：github-deploy-key（私钥）与 github-deploy-key.pub（公钥）。
  2. 发布仓库添加公钥（Public Key）：
    • 打开 username.github.io 仓库 -> Settings > Deploy keys > Add deploy key。
    • 粘贴 github-deploy-key.pub 内容，务必勾选 Allow write access（允许写入权限），保存。
  3. 源码仓库添加私钥（Private Key Secret）：
    • 打开 BlogDeploy 仓库 -> Settings > Secrets and variables > Actions > New repository secret。
    • Secret 名称填 ACTIONS_DEPLOY_KEY，值粘贴 github-deploy-key（私钥完整内容）。

6. 核心技术陷阱：解决 CI 构建导致的「文章更新时间全部重置」

6.1 问题根本原因

Git 在分布式传输与检出时，默认不保留文件的物理系统修改时间（mtime）。在 GitHub Actions 虚拟机中运行 git clone 后，所有 .md 文件的系统修改时间都会变成当次 CI 运行的当前时间戳。
由于 Hexo 默认在 Front-matter 未显式声明 updated 时，会回退读取文件的系统 mtime 作为文章的「最后更新时间」，导致每次哪怕只改了一个错别字推送，全站数百篇文章的更新时间全部被刷新成今天。

6.2 解决方案与原理剖析

通过在 hexo generate 之前执行 Git 历史回溯脚本：

  • git log -1 --format="@%ct" "$path"：提取该文件在 Git 历史中最近一次实际被 commit 修改的 Unix 时间戳。
  • touch -d：将文件的系统修改时间强制修正为该提交时间戳。
  • 配合 actions/checkout@v4 中的 fetch-depth: 0，完美恢复每篇文章真实无误的修改历史。

7. Cloudflare Pages 边缘双轨加速部署方案

如果你希望同时部署在 Cloudflare Pages，享受全球 Anycast CDN 边缘网络毫秒级首屏加载：

7.1 方案 A：Cloudflare 控制台与 GitHub 源码仓原生集成（最推荐）

  1. 登录 Cloudflare Dashboard，进入 Workers & Pages > Create application > Pages > Connect to Git。
  2. 授权并选择私有源码仓库 BlogDeploy。
  3. 配置构建设置：
    • Framework preset：选择 None。
    • Build command：npm install && npm install -g hexo-cli && hexo generate。
    • Build output directory：public。
    • Environment variables：添加 NODE_VERSION = 20。
  4. 点击「Save and Deploy」，此后每次向 GitHub 推送代码，Cloudflare 会在数十秒内自动完成全球边缘分发。

10. 多平台部署高频故障排查手册

故障现象 根因剖析 快速解决对策
部署后页面白屏 / CSS JS 404 _config.yml 中的 url 或 root 路径配置不正确（例如二级域名缺少子路径前缀） 检查 _config.yml，若部署在根目录，确保 root: /；若在 username.github.io/blog，需设置 root: /blog/
GitHub Actions 报错 Host key verification failed 工作流未正确配置 ACTIONS_DEPLOY_KEY 或公钥未赋予写入权限 重新核对私钥内容，并确保发布仓库 Deploy Keys 中勾选了 Allow write access
CI 构建报错 JavaScript heap out of memory 博客文章数量过多（上千篇）导致 Node.js 内存溢出 在 CI 环境变量中添加 NODE_OPTIONS: "--max-old-space-size=4096" 调大内存上限
推送后 GitHub Pages 未更新 浏览器强缓存或 GitHub Pages 处于编译排队中 按 Ctrl + F5 强制刷新，或在 GitHub Pages 设置中重新切换一次部署分支触发重构
自定义域名访问显示 404 CNAME reset 每次 hexo g 重新生成时覆盖了 public/CNAME 务必确保 CNAME 文件放置在 source/CNAME 下，而非手动放到 public/ 目录下
