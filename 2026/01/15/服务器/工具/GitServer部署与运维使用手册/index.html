Git Server 部署与全栈运维手册

Git Server 部署与全栈运维手册

在软件工程、DevOps 自动化与知识库管理中，搭建一套安全、自主可控的 私有 Git 服务器（Git Server） 是技术团队和极客玩家的核心基础设施。本文系统讲解从 原生轻量 SSH Git Server 到 现代容器化 Gitea 平台 的完整搭建流程，并深入探讨 Git Hooks 自动化部署、Git LFS 大文件存储、仓库瘦身备份 以及 生产级安全运维。

1. 私有 Git 服务选型全景对比

1.1 主流方案核心特性对照表

方案类别 代表技术 / 软件 内存开销 核心优势 局限性 / 适用场景
原生 SSH 裸服务 Linux + Git + git-shell < 10 MB • 零额外软件依赖，原生安全
• 基于 Linux 权限与 SSH 密钥
• 占用近乎为零，绝对稳定		 无 Web UI，无法在线查看代码/PR/Issue；适合自动化同步与极简私人仓库
现代轻量 Web 平台 Gitea / Forgejo 50 MB ~ 150 MB • Go 语言单二进制/Docker 运行
• 功能完备（代码浏览、PR/MR、Wiki、LFS、Gitea Actions）
• 性能极高，单核 1G 即可秒级响应		 极客个人、中小团队、私有 NAS / 云服务器自建代码托管最佳首选
企业级巨型平台 GitLab Community 4 GB ~ 8 GB+ • 业界最完备的 DevOps 平台
• 强大的企业级权限、审计与 CI/CD 流水线		 极度吃内存，初始化编译慢，不适合轻量级 VPS

10. Webhook 机器人通知与协同安全审计

10.1 飞书 / 钉钉 / 企业微信群通知集成

通过 Gitea Webhook，可以在代码提交、Pull Request 合并或 Release 发布时自动推送消息到即时通讯群组：

  1. 进入仓库 设置 > Web 钩子 > 添加 Web 钩子（选择钉钉 / 飞书 / 企微或通用 Discord/Slack）。
  2. 填写机器人的 Webhook URL 地址。
  3. 勾选触发事件（如「推送事件」、「合并请求事件」）。
  4. 点击「测试推送」，群机器人即可秒级收到格式化的提交卡片。

11. 高频故障排查手册

故障现象 诱因剖析 快速解决对策
Permission denied (publickey) 1. 客户端未加载私钥
2. 服务器端 ~git/.ssh/authorized_keys 权限不是 600
3. git 用户未被加入 SSH 允许列表		 执行 ssh -v git@server-ip 查看握手细节；修复服务器权限 chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
fatal: protocol error: bad line length character: This 登录用户未配置为 git-shell，而在 .bashrc 中输出了欢迎文本干扰了 Git 协议传输 将用户的 Shell 修改为标准的 git-shell，移除所有登录回显提示
error: RPC failed; HTTP 413 curl 22 通过 HTTP/HTTPS 推送超过了 Nginx 的 client_max_body_size 限制 在 Nginx 配置文件中将 client_max_body_size 增加至 512M 或更大，并调大 Git 客户端 git config --global http.postBuffer 524288000
Hook 脚本未触发自动部署 1. post-receive 没有执行权限 +x
2. 目标 Web 目录 git 用户无写入权限		 执行 chmod +x /path/to/hooks/post-receive 并将目标目录所有权授予 git 用户
Gitea 容器重启后数据丢失 未正确配置 Docker 挂载数据卷（Volume） 检查 docker-compose.yml 中的 ./data:/data 与 ./mysql:/var/lib/mysql 本地持久化路径映射
