Hexo 博客接入 OpenRouter：基于 Cloudflare Worker + KV 打造白嫖级流式 AI 摘要

很多主题（比如 Stellar、Butterfly）都支持 AI 摘要功能，但点开配置一看，默认几乎都绑定了商业 SaaS 的 Key。想要用自己的大模型 Key 吧，又面临一个致命问题：静态博客没有后端，把 OpenRouter 或 OpenAI 的 API Key 直接塞进前端 JS，等于裸奔，分分钟被别人顺着网线把你的 Token 薅秃。

想要白嫖 OpenRouter 的免费/低价模型（比如 DeepSeek、Gemini 2.0 Flash），又想要炫酷的实时流式打字机效果，最优雅的解法就是：手搓一个 Cloudflare Worker 做中转代理 + 挂一个免费的 Cloudflare KV 缓存。

核心架构与爽点

为什么这么设计？

  • 保住钱包与 Key：API Key 存在 Cloudflare Worker 环境变量里，前端完全不可见。
  • 白嫖级成本：Cloudflare Worker 每天免费 10 万次请求，KV 每天免费 10 万次读取。
  • 零重复扣费：每篇文章不管有几万人看，只要第一次访问生成后写入 KV，后续所有人都是直接读缓存，调用 OpenRouter 的次数永远为 1 次。

一、 后端部署：手搓 Cloudflare Worker

1. 创建 KV 命名空间

  1. 登录 Cloudflare Dashboard。
  2. 依次点击左侧侧边栏 Workers & Pages -> KV。
  3. 点击 Create a namespace，起个名字，比如 AI_SUMMARY_KV。

2. 创建 Worker

  1. 回到 Workers & Pages -> Overview，点击 Create Application -> Create Worker。
  2. 起个名字（如 hexo-ai-summary），点击 Deploy。
  3. 点击 Edit code，把里面的代码全删掉，换成下面这套即配即用的完整逻辑：

3. 绑定环境变量与 KV

代码保存后，进入该 Worker 的 Settings 页面：

  1. Variables（环境变量）：
    • 点击 Add，添加 OPENROUTER_API_KEY，值为你在 OpenRouter 申请的 Key（勾选 Encrypt 加密保存）。
    • 添加 MODEL_NAME，值为 deepseek/deepseek-chat 或 google/gemini-2.0-flash-001。
  2. KV Namespace Bindings（绑定 KV）：
    • 点击 Add binding。
    • Variable name 填：AI_SUMMARY_KV。
    • KV namespace 选择你刚刚创建的 AI_SUMMARY_KV。
  3. 点击 Save and Deploy 搞定！
  4. 记录下你的 Worker 访问域名，比如：https://hexo-ai-summary.yourname.workers.dev。
