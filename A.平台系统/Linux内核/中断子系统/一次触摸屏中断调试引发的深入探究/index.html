四、根因分析 #

回归到最初的问题，之前我们分析出如下的结论：

如果想出现 log 那样的错误，必须满足条件

text
desc->irqs_unhandled > 99900

为真

如要要满足如上条件的话，那么只有让 irqs_unhandled++

那么满足这个条件就必须 action_ret == IRQ_NONE

这里我们就要对 handle_simple_irq 与 handle_level_irq 做个分析了，具体的分析大家可以网上看蜗窝的资料以及 csdn 上很多对这块有详细的描述，我这里简单叙述下我个人的理解

首先上代码：

注：原文此处配有 handle_simple_irq 与 handle_level_irq 的源码对照截图，在网页抓取过程中丢失。

大家可以看出来，handle_simple_irq 做的事情很简单，而 handle_level_irq 却做了这个动作

c
mask_ack_irq(desc);

因为是电平中断，如果不做 mask 中断的动作的话，会因为中断电平一直是有效电平导致中断控制器会源源不断地给 cpu 发中断

而 handle_simple_irq 就是非常简单的处理中断，没有 mask 中断，原本代码是写的 handle_simple_irq，

而触摸屏的中断是设置为线程化的，并且为电平触发方式，那么如果没有 mask 该中断，

那么当一次线程化中断处理函数还未执行完成的时候，又会有源源不断地中断一直进来，

那么就会出现 threads_handled 会一直++的情况，从而产生本文最开头的错误

到此这个问题就已经分析完了
