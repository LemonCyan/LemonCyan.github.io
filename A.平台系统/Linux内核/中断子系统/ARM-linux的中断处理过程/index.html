ARM linux的中断处理过程

ARM Linux 中断处理过程深度剖析：从硬件中断到内核上下文切换 #

在嵌入式 Linux 系统里，中断是内核与外设交互的绝对核心。理解 ARM 架构下的中断处理过程，不仅能帮我们写出性能更好的驱动，还能在遇到内核崩溃、死锁等恶心问题时，通过栈回溯顺藤摸瓜。

本文基于 Linux 3.14 内核，深入扒一扒从外部硬件触发中断开始，到 CPU 模式切换、现场保护、内核分发处理、以及最终恢复退出的完整流程。

一、 中断处理的准备阶段 #

在开启全局中断之前，内核必须把各 CPU 模式的栈、异常向量表和中断控制器全部打理好。

1. 中断模式栈（IRQ Stack）的准备 #

ARM 处理器有多种工作模式（User, SVC, IRQ, FIQ, Abort, Undefined, System）。当发生中断时，硬件会自动切入 IRQ 模式。

但是，Linux 绝大部分的内核态中断处理代码都是在 SVC 模式 下跑的。IRQ 模式只是个临时过渡。因此，IRQ 模式的栈分配得很小，每个 CPU 只有 12 个字节：

c
struct stack {
    u32 irq[3];   /* IRQ 模式栈，仅12字节 */
    u32 abt[3];   /* Abort 模式栈 */
    u32 und[3];   /* Undefined 模式栈 */
} ____cacheline_aligned;

static struct stack stacks[NR_CPUS];

在系统初始化时，cpu_init() 函数会手搓一小段汇编，分别切入各个异常模式设定它们的 SP 寄存器：

c
void notrace cpu_init(void)
{
    unsigned int cpu = smp_processor_id();
    struct stack *stk = &stacks[cpu];

    __asm__ (
    "msr    cpsr_c, %1\n\t"    /* 切入 IRQ 模式 */
    "add    r14, %0, %2\n\t"   /* r14 = stk + offsetof(irq) */
    "mov    sp, r14\n\t"       /* 设定 IRQ 模式的 SP */
    "msr    cpsr_c, %3\n\t"    /* 切入 ABT 模式 */
    "add    r14, %0, %4\n\t"
    "mov    sp, r14\n\t"       /* 设定 ABT 模式的 SP */
    "msr    cpsr_c, %5\n\t"    /* 切入 UND 模式 */
    "add    r14, %0, %6\n\t"
    "mov    sp, r14\n\t"       /* 设定 UND 模式的 SP */
    "msr    cpsr_c, %7"        /* 回到 SVC 模式 */
    : 
    : "r" (stk),
      PLC (PSR_F_BIT | PSR_I_BIT | IRQ_MODE),
      "I" (offsetof(struct stack, irq[0])),
      PLC (PSR_F_BIT | PSR_I_BIT | ABT_MODE),
      "I" (offsetof(struct stack, abt[0])),
      PLC (PSR_F_BIT | PSR_I_BIT | UND_MODE),
      "I" (offsetof(struct stack, und[0])),
      PLC (PSR_F_BIT | PSR_I_BIT | SVC_MODE)
    : "r14");
}

2. SVC 模式栈（内核栈）的准备 #

当用户程序通过系统调用或中断陷入内核后，必须使用内核栈。Linux 在创建进程（包括内核线程）时，会分配物理页框：

  • 底部存放 struct thread_info 数据结构。
  • 顶部（高地址）用作该进程的内核栈（SP_svc）。
  • 进程切换时，SP_svc 会随着调度自动切换到新进程的内核栈上。

3. 异常向量表的准备与映射 #

ARM 发生异常时，硬件会强行跳转到对应的异常向量处执行。Linux 选择将向量表放在高端虚拟地址 0xffff0000（High Vectors），由 SCTLR 寄存器的第 13 位（V 位）控制。

ℹ笔记

为什么不放在 0x0 地址（Low Vectors）？ 因为在 Linux 中，0 ~ 3GB 是用户空间。如果用 Low Vectors，向量表就会落在用户空间内，容易被空指针访问等意外或者恶意操作破坏。

内核在 devicemaps_init() 中分配两个物理页，并映射到 0xffff0000：

c
vectors = early_alloc(PAGE_SIZE * 2); /* 分配2页物理内存 */
early_trap_init(vectors);            /* 拷贝向量表和 stub 存根代码 */

/* 映射到虚拟地址 0xffff0000 */
map.pfn = __phys_to_pfn(virt_to_phys(vectors));
map.virtual = 0xffff0000;
map.length = PAGE_SIZE;
...
create_mapping(&map);
  • 第 1 页：存放真正的异常向量表（如下所示）和内核提供的 kuser helpers 函数。
  • 第 2 页：存放异常跳转的中间过渡存根函数（stubs）。
/* 异常向量表 */
.section .vectors, "ax", %progbits
__vectors_start:
    W(b)    vector_rst           @ 复位
    W(b)    vector_und           @ 未定义指令
    W(ldr)  pc, __vectors_start + 0x1000 @ 软中断 (SVC)
    W(b)    vector_pabt          @ 指令预取中止
    W(b)    vector_dabt          @ 数据中止
    W(b)    vector_addrexcptn    @ 地址异常
    W(b)    vector_irq           @ IRQ 中断
    W(b)    vector_fiq           @ 快速中断

拷贝过程中，整个向量表物理页除代码外，其他缝隙会被填充为未定义指令 0xe7fddef1。这是个安全防御机制，防止 CPU 因为硬件异常或程序跑飞掉进空白缝隙中抓瞎，一旦误入直接触发未定义指令异常。

二、 发生中断时 ARM 硬件的自发行为 #

当外设触发中断信号送达中断控制器（GIC），并分发给某个 CPU 时，ARM 处理器硬件会强制执行以下动作（无需软件干预）：

  1. 修改 CPSR 控制位：将工作模式切入 IRQ 模式 (CPSR.M[4:0] = 0b10010)。
  2. 备份状态寄存器：将发生中断那一刻的 CPSR 保存到 IRQ 模式独有的 SPSR_irq 中。
  3. 备份返回地址：将返回执行地址保存到 LR_irq 中。
    • 在 ARM 状态下，硬件自动设置：LR_irq = PC - 4。
    • 为什么是 PC - 4？ 因为 ARM 采用流水线结构。当某条指令正在执行时，PC 指向的是 当前指令地址 + 8 的位置。发生中断时，CPU 必须把当前指令跑完，但已取指和译码的后续指令全部作废。此时 PC 已经累加到了 当前指令地址 + 12。硬件帮我们减去 4，LR_irq 指向的就是 发生中断指令 + 8（即下下条指令）。剩下的软件微调交给内核来做。
  4. 屏蔽后续中断：设置 CPSR.I = 1，关中断。
  5. 强行跳转：将 PC 指向异常向量表中 IRQ 的入口地址（对于 High Vectors，即 0xffff0018）。

三、 中断进入阶段：IRQ 模式过渡到 SVC 模式 #

进入 vector_irq 后，软件（汇编代码）开始接管现场。首要任务是把 IRQ 栈上临时的寄存器现场转移到进程的内核栈（SVC 栈）中，并切换至 SVC 模式。

1. vector_stub 宏处理 #

vector_irq 实质上是调用了 vector_stub 宏：

.macro  vector_stub, name, mode, correction=0
    .align  5
vector_\name:
    .if \correction
    sub     lr, lr, #\correction    @ lr = lr - 4。修正后，lr 正好指向中断发生时的那条指令！
    .endif

    @ 将临时污染的 r0 和返回地址 lr 压入临时的 IRQ 栈
    stmia   sp, {r0, lr}            
    mrs     lr, spsr
    str     lr, [sp, #8]            @ 将中断现场的 CPSR (spsr) 也存入栈

    @ 准备切入 SVC32 模式（继续保持关中断状态）
    mrs     r0, cpsr
    eor     r0, r0, #(\mode ^ SVC_MODE | PSR_ISETSTATE)
    msr     spsr_cxsf, r0           @ 修改 spsr_irq 的模式位为 SVC 模式

    @ 根据中断是发生在用户空间还是内核空间，决定跳转地址
    and     lr, lr, #0x0f           @ 提取发生中断时 CPSR 的 M[3:0]
    @ 如果是用户空间陷入，跳转到 __irq_usr；如果在内核态嵌套中断，跳转到 __irq_svc
    ldr     lr, [pc, lr, lsl #2]    
    movs    pc, lr                  @ 【精妙】：movs 赋值 pc 且带 's'，会自动把 SPSR 复制到 CPSR！
                                    @ 这一瞬间，CPU 顺畅切入 SVC 模式并跳转到对应的处理函数！

2. 中断发生在用户空间（__irq_usr） #

切入 SVC 模式后，栈指针切换为 SP_svc（即当前进程的内核栈）。首先调用 usr_entry 宏保存完整的用户态寄存器上下文到 struct pt_regs 结构中：

__irq_usr:
    usr_entry          @ 压栈 r1~r12，从 IRQ 栈搬移 r0, pc, cpsr，保存用户态的 sp, lr
    irq_handler        @ 核心中断路由处理
    get_thread_info tsk @ tsk = r9 指向 thread_info
    mov     why, #0
    b       ret_to_user_from_irq @ 返回用户空间

usr_entry 压栈后的内核栈布局完全符合 struct pt_regs 结构体：

内存高地址 寄存器成员 说明
sp + S_FRAME_SIZE ARM_ORIG_r0 原始 r0，系统调用或异常标记
sp + S_CPSR ARM_cpsr 中断发生时的 CPSR
sp + S_PC ARM_pc 中断发生时的返回地址
sp + S_LR ARM_lr 用户态的 lr
sp + S_SP ARM_sp 用户态的 sp
... r1 ~ r12 通用寄存器
sp（当前栈顶） r0 通用寄存器

3. 中断发生在内核空间（__irq_svc） #

如果在内核态跑着的时候突然来了中断（中断嵌套），会跳转到 __irq_svc：

__irq_svc:
    svc_entry          @ 在当前进程的内核栈顶继续压入嵌套中断的寄存器现场
    irq_handler        @ 中断路由处理
#ifdef CONFIG_PREEMPT
    @ 内核抢占相关逻辑处理...
#endif
    svc_exit r5, irq = 1 @ 恢复现场并退出

四、 中断核心处理与路由分发 #

无论是从内核态还是用户态进来，最终都会调用 irq_handler 宏。

如果内核开启了 CONFIG_MULTI_IRQ_HANDLER（现代多板卡通用镜像多会开启），内核会直接通过函数指针调用特定中断控制器（如 GIC）驱动注册的分发函数：

    .macro  irq_handler
    ldr     r1, =handle_arch_irq
    mov     r0, sp                 @ 参数 0：指向 pt_regs 现场结构
    adr     lr, 9997f              @ 设定返回地址
    ldr     pc, [r1]               @ 跳转到 handle_arch_irq
9997:
    .endm

在 GIC 驱动中，该函数会读取 GIC 硬件寄存器，获取当前挂起的中断号（IRQ Number），然后调用 handle_domain_irq() 最终进入 generic_handle_irq(irq)，调用具体驱动在 request_irq 时注册的中断处理函数（ISR）。

五、 中断退出与现场恢复 #

当中断处理完毕后，系统需要把先前压入内核栈的现场还原，并切回中断前的状态。

1. 从用户态中断返回 (ret_to_user_from_irq) #

返回用户空间前，内核会检查 thread_info 中的标志位：

ENTRY(ret_to_user_from_irq)
    ldr     r1, [tsk, #TI_FLAGS]
    tst     r1, #_TIF_WORK_MASK   @ 检查 _TIF_NEED_RESCHED | _TIF_SIGPENDING | _TIF_NOTIFY_RESUME
    bne     work_pending          @ 如果有挂起的工作（如需调度、有信号），先去处理

如果没有待处理的任务，调用 restore_user_regs 恢复寄存器：

    .macro  restore_user_regs, fast = 0, offset = 0
    ldr     r1, [sp, #\offset + S_PSR] @ 取出保存的 CPSR
    ldr     lr, [sp, #\offset + S_PC]!  @ 取出保存的返回地址 PC
    msr     spsr_cxsf, r1             @ 将 CPSR 写入 spsr
    ...
    ldmdb   sp, {r0 - lr}^            @ 【关键】：带 '^' 符号表示恢复的是用户态的 sp 和 lr！
    add     sp, sp, #S_FRAME_SIZE - S_PC @ 回退内核栈指针
    movs    pc, lr                    @ 写入 pc 并将 spsr 拷贝回 cpsr，切回用户模式并恢复开中断状态！
    .endm

2. 从内核态中断返回 (svc_exit) #

如果是在内核态发生的中断，返回逻辑稍微简单些，调用 svc_exit 宏：

    .macro  svc_exit, rpsr, irq = 0
    ...
    msr     spsr_cxsf, \rpsr          @ 将备份的 cpsr 写入 spsr
    ldmia   sp, {r0 - pc}^            @ 【硬核】：ldm 异常返回指令带有 '^'
                                      @ 一次性将 r0~r12、lr、pc 恢复，并将 spsr 还原回 cpsr，返回内核中断现场。
    .endm
