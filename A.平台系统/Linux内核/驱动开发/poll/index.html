poll

Linux字符设备驱动开发：基于poll_wait与等待队列的I/O多路复用驱动轮询实现 #

在 Linux 系统中，当应用层调用 select()、poll() 或 epoll() 监控某个设备文件时，底层驱动必须实现相对应的 poll 文件操作接口。这个接口负责：

  1. 挂载进程：将当前进程挂载到驱动内部的等待队列中（但不立即进入休眠）。
  2. 返回掩码：查询当前设备是否可读或可写，并返回状态掩码（如 POLLIN 或 POLLOUT）。

一、 驱动底层 poll 轮询函数实现 #

下面是字符设备驱动中用于支持轮询机制的 poll 接口的典型 C 语言代码实现：

c
#include <linux/poll.h>
#include <linux/fs.h>

// 声明等待队列头（通常在设备结构体或全局中初始化）
extern wait_queue_head_t wq;   // 读等待队列
extern wait_queue_head_t wwq;  // 写等待队列
extern int havedata;           // 数据就绪标志位：0-无数据，1-有数据

unsigned int hello_poll(struct file *file, struct poll_table_struct *ptbl)
{
    unsigned int mask = 0;

    // 💡 1. 将当前进程的轮询表项挂载到对应的读/写等待队列中
    // poll_wait 并不会使进程休眠，它只是把进程“注册”到队列中，这样一旦设备就绪，驱动才能唤醒它
    poll_wait(file, &wq, ptbl);
    poll_wait(file, &wwq, ptbl);

    // 💡 2. 根据当前的硬件数据状态，计算并返回掩码
    if (havedata == 0) {
        // 当前无数据可读，意味着可以写入数据
        mask |= POLLOUT | POLLWRNORM; // 可写
    }
    
    if (havedata == 1) {
        // 当前有数据未读，意味着可以读取数据
        mask |= POLLIN | POLLRDNORM;  // 可读
    }

    return mask;
}

二、 核心机制剖析 #

1. poll_wait 的作用是什么？ #

poll_wait() 是一个通用块 helper，用于将当前调用进程挂载到指定的等待队列中。 它的执行非常轻量：它只是将包含进程控制块的等待队列项（wait_queue_t）添加进驱动的 wq 或 wwq 链表中，进程不会在此处发生阻塞或让出 CPU。真正决定进程是否进入休眠的，是由内核通用块的 do_poll 环路控制的。

2. 状态掩码说明 #

  • POLLIN：设备有数据可读，读操作不会阻塞。
  • POLLRDNORM：常规数据可读（等价于 POLLIN）。
  • POLLOUT：设备缓冲区有空间，写操作不会阻塞。
  • POLLWRNORM：常规数据可写（等价于 POLLOUT）。
  • POLLERR：设备发生错误。

3. 数据就绪后的唤醒逻辑 #

当驱动从外部硬件中断或其它写入途径接收到数据，并将 havedata 置为 1 时，驱动必须显式调用：

c
havedata = 1;
wake_up_interruptible(&wq); // 💡 唤醒挂在 wq 上的读轮询进程

此时，处于 poll() 等待状态的用户进程会被唤醒，重新调用 hello_poll，此时 hello_poll 返回的 mask 包含 POLLIN，应用层随之退出阻塞并执行 read 操作。
