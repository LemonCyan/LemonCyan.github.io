阻塞与非阻塞IO的实现

Linux字符设备驱动开发：基于等待队列与O_NONBLOCK标志的阻塞与非阻塞I/O读操作实现 #

在 Linux 字符设备驱动中，当应用层调用 read() 时，驱动必须根据打开文件时是否指定了 O_NONBLOCK（非阻塞标志）来采取不同的操作：

  • 阻塞 I/O（默认）：如果设备中当前没有数据，进程必须挂起休眠，让出 CPU，直到硬件中断或者其他进程写入数据并唤醒它。
  • 非阻塞 I/O：如果设备当前没有数据，驱动不进行任何等待，立即向应用层返回 -EAGAIN 错误，告知稍后再试。

一、 驱动底层 read 接口典型实现 #

以下是支持阻塞与非阻塞读操作的内核驱动 C 语言核心实现：

c
#include <linux/fs.h>
#include <linux/uaccess.h>
#include <linux/sched.h>

// 声明等待队列头与数据标志位
extern wait_queue_head_t wq;   // 读等待队列
extern int havedata;           // 0 表示无数据，1 表示有数据
extern char *buf;              // 驱动中实际存储数据的缓冲区

ssize_t hello_read(struct file *file, char __user *user, size_t size, loff_t *pos)
{
    // 1. 防范越界读取，限制读取大小为缓冲区实际字符长度
    if (size > strlen(buf)) {
        size = strlen(buf);
    }
    
    // 💡 2. 判断当前是否有数据就绪
    if (havedata == 0) {
        // 💡 3. 如果是非阻塞打开方式 (O_NONBLOCK)，立即返回 EAGAIN
        if (file->f_flags & O_NONBLOCK) {
            return -EAGAIN; // 告诉应用层没有数据，请等下再来读
        }
        
        // 💡 4. 如果是阻塞方式，将当前进程挂起进入休眠，等待 (havedata == 1) 条件为真
        // 进程在此处被挂起，进入 TASK_INTERRUPTIBLE 状态，不再占用 CPU 时钟
        if (wait_event_interruptible(wq, havedata == 1)) {
            return -ERESTARTSYS; // 被信号异常中断唤醒，返回系统调用重启
        }
    }
    
    // 💡 5. 将内核缓冲区的数据安全复制到用户空间
    if (copy_to_user(user, buf, size)) {
        return -EFAULT; // 复制出错，返回内存错误
    }
    
    // 6. 状态清理，标记数据已被取走
    havedata = 0; 
    
    return size; // 返回实际读取的字节数
}

二、 核心 API 详解 #

1. file->f_flags 的检查 #

file 指针代表打开的文件描述符，其结构体中的 f_flags 字段记录了用户空间在调用 open("dev", flags) 时传递的所有控制属性。其中 O_NONBLOCK 位如果被置 1，驱动应该在未获得数据时立即返回 -EAGAIN 错误。

2. wait_event_interruptible 挂起机制 #

wait_event_interruptible(wq, condition) 是一个非常经典的宏，包含以下几个执行步骤：

  1. 评估 condition，如果为真，立即向下执行，不发生休眠。
  2. 如果为假，将当前进程的状态设置为 TASK_INTERRUPTIBLE，并挂载到等待队列头 wq 上。
  3. 调用 schedule() 让出 CPU，进入睡眠。
  4. 被唤醒后（通常由于其他地方调用了 wake_up_interruptible(&wq)），重新检查 condition：
    • 如果条件依然为假，则继续睡眠；
    • 如果为真，清除休眠状态，程序继续往下走，将数据通过 copy_to_user 传输给用户。
