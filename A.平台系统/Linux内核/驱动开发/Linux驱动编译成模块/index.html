Linux驱动编译成模块

Linux驱动开发基础：内核配置系统Kconfig与驱动编译（内编译与外编译双方案） #

对于刚刚接触 Linux 底层开发的工程师而言，编写驱动面临的第一道坎往往不是硬件操作，而是驱动代码如何配置、编译、并装载到目标板上运行。

Linux 作为一个高度可裁剪的宏内核系统，其源文件的组织和编译逻辑依赖于 Kconfig（配置系统） 和 Makefile（构建工具）。

本文以简单的 Hello World 驱动为例，详细演示**内核树内编译（In-tree）与外部独立编译（Out-of-tree）**两种开发构建方案。

一、 系统架构与驱动的位置 #

在现代操作系统中，虚拟内存被严格分割为用户空间 (User Space) 和 内核空间 (Kernel Space)：

  • 用户空间：运行普通应用。当需要读写文件或网络通信时，必须通过系统调用（OS API，如 open/write）陷入内核，以此保护底层硬件不受恶意程序侵害。
  • 内核空间：运行核心网络协议栈、内存管理、进程调度、文件系统（VFS）以及设备驱动程序。
+--------------------------------------------------------+
|                 用户空间 (User Space)                  |
|          应用程序 (Application / Console Tool)         |
+--------------------------|-----------------------------+
                           |  (System Call: open/read/write)
+--------------------------v-----------------------------+
|                 内核空间 (Kernel Space)                  |
|  [ 进程调度 ]  [ 虚拟文件系统 VFS ]  [ 内存管理 ]  [ 网络栈 ]   |
|                                                        |
|                 💡 设备驱动程序 (Drivers)                 |
+--------------------------|-----------------------------+
                           |  (Hardware Control)
+--------------------------v-----------------------------+
|                   底层物理硬件 (Devices)                 |
+--------------------------------------------------------+

二、 基础驱动源码 (hello.c) #

在编写任何编译脚本前，我们准备一个标准的最小化内核驱动源码：

c
#include <linux/module.h>
#include <linux/init.h>

MODULE_LICENSE("Dual BSD/GPL"); // 模块授权声明（防止内核打印污染警告）
MODULE_AUTHOR("YiJun");
MODULE_DESCRIPTION("A Simple Hello World Kernel Module");

// 💡 模块加载初始化入口
static int __init hello_init(void)
{
    // KERN_ALERT 级别会在控制台终端强行打印输出
    printk(KERN_ALERT "Hello World! Kernel module loaded successfully.\n");
    return 0; // 返回 0 表示加载成功，负值表示加载失败
}

// 💡 模块卸载出口
static void __exit hello_exit(void)
{
    printk(KERN_ALERT "Goodbye! Kernel module unloaded.\n");
}

// 注册入口与出口函数
module_init(hello_init);
module_exit(hello_exit);

三、 方案 1：内核树内编译 (In-Tree Build) #

此方案适合于要将驱动作为操作系统发行版的一部分，直接融入 Linux 内核主线进行发布。

1. 新建驱动目录并编写 Kconfig/Makefile #

在内核源码树的 drivers/ 目录下创建一个新目录（如 drivers/hello/），并在其内部放置三个文件：

  • hello.c (驱动源码)
  • Kconfig (用于在 menuconfig 图形配置界面显示菜单项)
  • Makefile (定义局部编译规则)

drivers/hello/Kconfig 语法： #

config HAVE_HELLO
    tristate "Support Hello World test driver"
    default m
    help
      This is a simple demo driver to show how to configure 
      and compile in-tree kernel drivers.
  • tristate (三态)：表示该选项支持三个状态：
    • y (Built-in)：编译进内核映像文件（如 zImage），开机自动运行。配置符号显示为 <*>。
    • m (Module)：编译为独立的二进制驱动模块（.ko），在运行时动态载入。配置符号显示为 <M>。
    • n (Exclude)：不进行编译。配置符号显示为 < >。

drivers/hello/Makefile 内容： #

makefile
# 当 CONFIG_HAVE_HELLO 被选定为 y 或 m 时，编译 hello.c
obj-$(CONFIG_HAVE_HELLO) += hello.o

2. 挂载至内核配置树的顶层 Kconfig/Makefile #

要让内核编译系统递归解析到我们的新文件夹，需要修改上层目录的文件：

  • 修改 drivers/Kconfig：在最后的 endmenu 前插入一行，读取我们的配置项：
    source "drivers/hello/Kconfig"
  • 修改 drivers/Makefile：在文件尾部追加：
    makefile
    obj-$(CONFIG_HAVE_HELLO) += hello/

3. 配置与编译 #

在内核源码根目录下执行配置命令：

bash
# 1. 清除旧配置并导入开发板的默认配置文件
make distclean
make ARCH=arm nanopi2_defconfig

# 2. 启动图形化配置界面
make ARCH=arm menuconfig

在 Device Drivers 菜单最下方，可以看到我们刚刚加入的 Support Hello World test driver。

  • 如果按 Y 勾选，执行 make ARCH=arm zImage 编译，驱动会直接打包进内核镜像中。
  • 如果按 M 勾选，执行 make ARCH=arm modules 编译，系统会在 drivers/hello/ 文件夹下生成 hello.ko 驱动模块文件。

四、 方案 2：外部独立编译 (Out-of-Tree Build，推荐) #

在实际的日常驱动开发中，修改内核主线 Kconfig 过于繁琐。我们更倾向于不修改内核任何文件，独立在外部编译驱动 .ko 模块。这要求开发主机上必须提前解压并编译过一次目标板的内核源码。

直接在你的驱动代码目录下新建一个特殊的 Makefile：

makefile
# 💡 1. 指向编译好且可运行的内核源码目录 (KDIR)
# 对于本地 PC 测试，指向当前运行内核的 build 树：
KDIR ?= /lib/modules/$(shell uname -r)/build
# 对于 ARM 交叉编译，指向交叉内核源码树路径，例如：
# KDIR ?= /home/developer/linux-kernel-source-arm

# 💡 2. 获取当前驱动源码的绝对路径
PWD := $(shell pwd)

# 💡 3. 定义要编译的目标模块名
obj-m += hello.o

all:
	# -C 进入内核目录使用其主 Makefile，M=$(PWD) 告知编译完成后将 .ko 返回输出到当前目录
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

执行编译： #

bash
# 执行本地主机内核驱动编译
make

# 如果是 ARM 嵌入式平台交叉编译，需传入平台参数和交叉编译器前缀：
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf-

五、 驱动模块的动态装载与测试 #

编译好 hello.ko 并将其拷贝到目标开发板后，在 Shell 终端使用 root 权限执行以下命令进行调试：

  1. 装载驱动模块 (insert):

    bash
    insmod hello.ko

    控制台会打印输出：Hello World! Kernel module loaded successfully.

  2. 查看当前系统已加载的模块 (list):

    bash
    lsmod

    可以看到包含 hello 的一行记录及占用内存大小。

  3. 卸载驱动模块 (remove):

    bash
    rmmod hello

    控制台打印：Goodbye! Kernel module unloaded.

  4. 查看内核环形缓冲区日志 (dmesg):
    如果使用 insmod 时终端没有直接打印出 printk 的内容，说明控制台日志级别过低。可以通过以下命令查看内核历史输出：

    bash
    dmesg | tail -n 10
