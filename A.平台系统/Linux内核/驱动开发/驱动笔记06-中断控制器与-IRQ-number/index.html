中断发生之后处理流程 a -- 具体的CPU architecture相关模块进行现场保护，然后调用machine driver执行对应的中断处 理handler; b -- machine driver对应中断处理handler会根据硬件的信息获取HW interrupt id,然后通过irq domain模块翻译成irq number; c -- 调用该IRQ number对应 hign level irq event handler，在这个hign level的handler中，会通 过和中断控制器交互，进行中断处理的flow 控制（中断的嵌套、抢占），最终会遍历我们注册的 IRQ action list，调用对应处理函数; d -- CPU architeccture相关模块进行现场的恢复;

硬件 a -- 当外设检测到中断之后，就会通过interrupt request line上的电平或者边沿通知到该外设连接 到的那个中断控制器，中断控制器就会在多个cpu中选一个，并且把该中断同IRQ分发给cpu b -- 修改CPSR， 模式 c -- 保存发生中断那一点的CPSR值 pc值 d -- mask IRQ exeption。 e -- 设定pc的值为 IRQ vector，一旦跳到中断向量表，后面就是软件行为了

【中断底半部】 中断的顶半部，就是指中断函数。每个中断都有中断处理函数。 可以把重要的操作【读取寄存器的内容】放在中断函数中，把需要时间比较长的操作 放在中断的底半部。

如何实现该机制？ 3种方式

  1. 定义函数 void jit_tasklet_fn(unsigned long arg) { //中断的底半部 执行该函数的时候，已经出中断了 printk("in jit_tasklet_fn jiffies=%ld\n",jiffies); }

  2. 在需要调度的地方调用以下函数 tasklet_schedule(&tlet); 一般在中断函数当中调度

tasklet把任务延迟到安全时间执行的一种方式，出中断运行， 即使被调度多次，tasklet也只运行一次

tasklet的特性：.不允许两个两个相同类型的tasklet同时执行，即使在不同的处理器上。
