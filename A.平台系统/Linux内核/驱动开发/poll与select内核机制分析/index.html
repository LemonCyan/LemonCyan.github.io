poll与select内核机制分析

Linux内核深度探索：poll与select多路复用文件I/O事件驱动机制内核源码剖析 #

在 Linux 系统编程中，select() 和 poll() 是最经典的多路复用（I/O Multiplexing）机制，允许一个线程监控成百上千个文件描述符的可读、可写状态。

本文将从用户空间的数据组织、内核空间的管理体系以及驱动底层的休眠唤醒回调三个维度，深度剖析其内核实现原理（源码主要分布在 fs/select.c）。

一、 数据结构与组织关系 #

poll 机制在内核中通过多级链表和页面指针来管理监测事件，其核心结构体之间的关系如下：

1. 用户空间数据传入 (struct pollfd) #

应用层传递一组 pollfd 数组给内核，由 unsigned int nfds 指定数组长度：

  • fd：被监控的文件描述符。
  • events：期望监听的事件掩码（输入项，如 POLLIN / POLLOUT）。
  • revents：实际发生并返回的就绪事件掩码（输出项）。

2. 内核空间管理链表 (struct poll_list) #

当描述符数量较大时，内核将用户空间数据分段存放在由 poll_list 链接的单向链表中：

c
struct poll_list {
    struct poll_list *next;     // 链表指针
    int len;                    // 本页中保存的 pollfd 数量
    struct pollfd entries[0];   // 💡 指向存放 pollfd 数据的弹性数组
};

内核对每个物理页保存的最大数量做了优化限制，通常为 POLLFD_PER_PAGE。

3. 等待队列容器 (struct poll_wqueues) #

内核管理和挂接驱动等待队列的核心容器，负责将当前轮询任务绑定到具体驱动设备的等待队列中：

  • poll_table pt：向驱动提供接口函数指针。
  • struct poll_table_page *table：指向物理内存页分配链表，每页包含多个轮询表项 poll_table_entry。
  • struct task_struct *polling_task：指向发起 poll 调用的当前进程控制块。
【 poll_wqueues 内存布局与等待队列的挂靠关系 】

  struct poll_wqueues
  +------------------+
  | poll_table pt    |-------> 指向 poll_queue_proc 回调函数 (即 __pollwait)
  | polling_task     |-------> 指向当前线程进程结构体 (task_struct)
  | table (链表指针)  |
  +--------|---------+
           |
           v   struct poll_table_page
         [ next | struct poll_table_entry entries[N] ]
                  |
                  v   struct poll_table_entry (单个轮询表项)
                [ file        ] ------> 指向被轮询的特定设备文件
                [ key         ] ------> 期望监控的事件掩码
                [ wait_address] ------> 指向驱动中定义的物理 wait_queue_head_t
                [ wait        ] (wait_queue_t)
                  |
                  +-------------------> 挂靠并注册到驱动底层的 wq 链表中！

二、 核心流程与顺序图 #

从用户调用 poll() 直至就绪返回，内核的运转顺序可以用以下流程图来表示：

sequenceDiagram
    autonumber
    participant U as 用户空间 (app)
    participant G as Glibc 库 (sys_poll)
    participant K as 通用内核层 (do_sys_poll)
    participant DP as 循环处理核心 (do_poll)
    participant D as 设备驱动层 (f_op->poll)

    U->>G: 调用 poll(fds, nfds, timeout)
    G->>K: 陷入内核，触发 do_sys_poll
    K->>K: 从用户空间拷贝 fds 数组并初始化 poll_wqueues
    K->>DP: 执行核心处理环路 do_poll()
    
    loop 循环轮询每一个文件描述符
        DP->>D: 调用驱动的 poll() 方法并传入 poll_table
        activate D
        D->>D: 调用 poll_wait()
        D->>DP: 注册当前等待队列项 (wait_queue_t)，返回状态掩码 mask
        deactivate D
    end

    alt 是否有至少一个就绪事件，或者已超时？
        DP->>K: 是 (获取所有 mask)，跳出循环
    else 否 (所有设备都未就绪)
        DP->>DP: 调用 poll_schedule_timeout() 挂起当前进程，让出 CPU 进入休眠
        Note over DP: 💤 进程处于浅度睡眠状态，等待被唤醒...
    end

    Note over D: 💡 驱动接收到硬件数据/中断
    D->>DP: 调用 wake_up() 唤醒队列上的挂起进程

    Note over DP: ⏰ 唤醒或超时时间到
    DP->>DP: 再次循环遍历各个驱动检测就绪状态
    DP->>K: 返回实际的就绪 revents 掩码
    K->>G: 释放并回收 poll_wqueues，数据拷贝回用户空间
    G->>U: 返回就绪数量，应用层恢复执行

三、 内核源码关键函数分析 #

1. do_poll 轮询休眠核心环路 #

在 fs/select.c 中，do_poll 利用一个无限的 for(;;) 循环来检查所有被监测描述符的就绪状态：

c
static int do_poll(unsigned int nfds, struct poll_list *list,
                   struct poll_wqueues *wait, struct timespec *end_time)
{
    int count = 0;
    struct poll_list *walk;

    for (;;) {
        // 💡 1. 遍历链表中的所有描述符
        for (walk = list; walk; walk = walk->next) {
            struct pollfd *pfd, *pfd_end;
            pfd = walk->entries;
            pfd_end = pfd + walk->len;
            
            for (; pfd != pfd_end; pfd++) {
                // 💡 2. 调用具体的驱动事件检测函数
                if (do_pollfd(pfd, &wait->pt)) {
                    count++; // 有就绪事件，计数器加 1
                    wait->pt._qproc = NULL; // 挂载成功后，之后无需重复挂载
                }
            }
        }

        // 💡 3. 判断是否满足退出条件
        if (count || !*timeout || signal_pending(current))
            break;

        // 💡 4. 让出 CPU，进程休眠，等待被驱动唤醒或超时
        if (!poll_schedule_timeout(wait, TASK_INTERRUPTIBLE, to, slack))
            *timeout = 0; // 超时时间到
            
        count = 0; // 清空计数，重新轮询
    }
    return count;
}

2. __pollwait 挂靠驱动回调 #

当驱动程序在 hello_poll 中调用 poll_wait(file, &wq, ptbl) 时，如果 ptbl 仍然生效，它实质上调用了内核预设的回调函数 __pollwait：

c
static void __pollwait(struct file *filp, wait_queue_head_t *wait_address,
                       poll_table *p)
{
    struct poll_wqueues *pwq = container_of(p, struct poll_wqueues, pt);
    struct poll_table_entry *entry = poll_get_entry(pwq); // 💡 得到一个轮询表项
    
    if (!entry)
        return;
        
    // 绑定目标文件
    entry->filp = get_file(filp);
    entry->wait_address = wait_address;
    entry->key = p->_key;
    
    // 💡 初始化等待队列项，设置自定义唤醒回调函数为 pollwake
    init_waitqueue_func_entry(&entry->wait, pollwake);
    entry->wait.private = pwq; // 私有指针指回 poll_wqueues
    
    // 🔑 挂靠：将等待项挂载到驱动的等待队列头 wait_address 中！
    add_wait_queue(wait_address, &entry->wait);
}

3. 驱动唤醒链条的触发 (pollwake) #

当数据就绪时，驱动调用 wake_up(wait_address)。系统会调用之前在队列中注册的唤醒函数 pollwake：

  1. pollwake 会读取 entry->wait.private，定位到对应的 poll_wqueues 结构体。
  2. 更改 polling_task（发起 poll 的那个休眠进程）的状态为 TASK_WAKING。
  3. 调用 try_to_wake_up(polling_task) 告诉 CPU 调度器将此进程重新排入就绪运行队列，从而触发 do_poll 环路的下一次遍历并正常退出。
