Exynos 4412 ADC 驱动开发与平台资源提取实战 #

ADC（模数转换器）在嵌入式开发中主要用于采集滑动变阻器、温度/湿度传感器等模拟外设的输入。在 Exynos 4412 平台下，咱们通常会把 ADC 注册为 Platform 设备，并通过设备树（Device Tree）来管理其硬件资源。

下面是 Exynos 4412 ADC 驱动开发的核心技术梳理，直接上干货。

一、 ADC 硬件寄存器配置 #

Exynos 4412 ADC 控制器的寄存器基地址为 0x126C0000，长度为 0x20 字节。常用控制寄存器如下：

  • ADCCON (偏移 0x0000)：控制寄存器。
    • 配置值：1<<16 | 1<<14 | 0xff<<6 | 1<<0
    • 含义解释：使能 12 位分辨率、使能预分频、设置分频系数（0xff），并启动转换。
  • ADCDAT (偏移 0x000C)：数据寄存器。
    • 读取转换值时，需要屏蔽高位，只保留低 12 位：value = readl(base + 0x000C) & 0xFFF;
  • CLRINTADC (偏移 0x0018)：清除中断寄存器。
    • 在中断函数里，往该寄存器写入任意值即可清除 ADC 中断标志。
  • ADCMUX (偏移 0x001C)：通道选择寄存器。
    • 设置为 3 代表选择通道 3。

二、 设备树节点编写 #

对于使用设备树的现代 Linux 内核（例如 3.14 及以上版本），咱们需要在 dts 文件中添加对应的设备节点：

dts
fs4412-adc {
    compatible = "fs4412,adc";
    interrupt-parent = <&combiner>; /* 父中断控制器为 combiner */
    reg = <0x126C0000 0x20>;        /* 物理寄存器基址和长度 */
    interrupts = <10 3>;            /* 中断号与触发方式 */
};

三、 平台资源提取机制 (platform_get_resource) #

当设备树被内核解析后，这些硬件资源（内存空间、中断号等）会被自动转化为 platform 资源，存放在驱动的 struct resource 数组中。

在 Platform 驱动的 probe 函数中，咱们需要提取这些资源：

1. 资源获取 API #

c
struct resource *platform_get_resource(struct platform_device *dev, 
                                       unsigned int type, 
                                       unsigned int num);
  • type：资源类型。如 IORESOURCE_MEM（内存资源）、IORESOURCE_IRQ（中断资源）。
  • num：该类型资源的同类索引（从 0 开始）。
❢重要

platform_get_resource 提取资源时，我们只需要关心同种资源的相对顺序，而不需要关心不同资源混合在一起时的绝对顺序。

2. 内核对资源数组的整合示例 #

假设内核将设备树节点解析为如下的资源数组形式：

c
struct resource adc_resources[] = {
    [0] = {
        .start = IRQ_NUM,
        .end   = IRQ_NUM,
        .flags = IORESOURCE_IRQ, // 对应的第 0 个 IRQ 资源
    },
    [1] = {
        .start = 0x126C0000,
        .end   = 0x126C0000 + 0x20,
        .flags = IORESOURCE_MEM, // 对应的第 0 个 MEM 资源
    },
    [2] = {
        .start = 0x126C0000,
        .end   = 0x126C0000 + 0x20,
        .flags = IORESOURCE_MEM, // 对应的第 1 个 MEM 资源
    },
    [3] = {
        .start = ...,
        .end   = ...,
        .flags = IORESOURCE_MEM, // 对应的第 2 个 MEM 资源
    }
};

如果你在驱动中调用：

  • platform_get_resource(pdev, IORESOURCE_MEM, 1)：它会自动过滤掉其他类型，拿到第 2 个 IORESOURCE_MEM 资源（即上面索引为 2 的那项）。
  • platform_get_resource(pdev, IORESOURCE_IRQ, 0)：拿到第 1 个中断资源（即上面索引为 0 的那项）。

通过这种相对索引的方式，无论设备树增加了多少其他外设，咱们都能稳妥地获取到我们想要的资源。
