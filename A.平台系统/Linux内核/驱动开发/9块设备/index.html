9块设备

Linux块设备驱动开发与I/O调度子系统内核架构解析 #

在 Linux 内核中，设备驱动主要分为三大类：字符设备驱动、网络设备驱动与块设备驱动 (Block Device Driver)。

块设备驱动负责管理诸如机械硬盘、固态硬盘（SSD）、SD卡、U盘及 RamDisk 等存储介质。由于块设备涉及到文件系统与磁头寻道延迟（机械结构），其驱动子系统要比字符设备驱动复杂得多。

一、 块设备基础概念与对比 #

1. 块设备与字符设备的差异 #

  • 读写基本单元不同：字符设备以字节 (Byte) 为单位进行顺序读写；块设备以固定大小的块 (Block) 为数据存取的基本单元。
  • 访问模式不同：字符设备只能顺序访问 (Sequential)，不能前后跳跃；块设备支持随机访问 (Random Access)，可以在介质内任意寻址读取。

2. 扇区、块与段的层级关系 #

  • 扇区 (Sectors)：硬件物理介质读写的最小单元，典型大小为 512 字节。块设备驱动向上层暴露的接口是以扇区为计量单位的。
  • 块 (Blocks)：操作系统文件系统层管理内存与磁盘映射的逻辑单元。块的大小必须是 2 的 n 次方，且必须是扇区的整数倍，通常为 512B、1KB 或 4KB（必须小于内存页的大小）。
  • 段 (Segments)：内存管理中一个内存页（Page）或内存页的一部分，由物理上连续的若干个块组成，代表一次 I/O 传输的物理内存缓冲区。

二、 Linux 块子系统层次架构 #

当用户程序发起文件写入时，请求在内核中会流经以下层次结构：

graph TD
    A[用户空间程序 write/read] --> B[VFS 虚拟文件系统]
    B --> C[Disk Cache 磁盘页高速缓存]
    C --> D[Mapping Layer 映射层 / 确定逻辑块地址]
    D --> E[Generic Block Layer 通用块层 / 构造 bio]
    E --> F[I/O Scheduler Layer I/O 调度层 / 排序与合并]
    F --> G[Block Device Driver 块设备驱动]
    G --> H[硬件磁盘控制器]

各层级职责解析： #

  1. VFS：封装各种具体文件系统，向应用层提供统一的 sys_write 等接口。
  2. Disk Cache：通过预读（Read-Ahead）与页缓存（Page Cache）机制，优先从 RAM 读取缓存数据。
  3. Mapping Layer：通过具体文件系统查找文件的 inode，计算所请求的数据位于物理磁盘的哪些逻辑块地址（LBA）上。
  4. Generic Block Layer：抽象出通用的数据模型，将上层的读写拆解并封装为统一的 bio 结构体。
  5. I/O Scheduler Layer：使用特定算法（如电梯调度算法 Elevator、Deadline、CFQ 等）对并发的 I/O 请求进行排序、重构与合并，减少磁头寻道耗时。
  6. Block Device Driver：驱动程序读取队列中的请求，向底层磁盘硬件控制器发射物理指令。

三、 四大核心数据结构 #

Linux 通用块层与驱动层通过以下四个数据结构承载和调度数据：

1. struct gendisk #

代表一个独立的虚拟/物理磁盘设备，类似于字符设备中的 struct cdev：

c
struct gendisk {
    int major;                      // 主设备号
    int first_minor;                // 第一个次设备号
    int minors;                     // 支持的最大次设备号（分区数上限）
    char disk_name[DISK_NAME_LEN];  // 磁盘名称（如 sda, mmcblk0）
    
    const struct block_device_operations *fops; // 块设备操作函数集
    struct request_queue *queue;    // 💡 该磁盘绑定的请求队列
    
    void *private_data;             // 驱动私有指针
    // ...
};

2. struct request_queue与request #

  • request_queue：代表挂载到当前块设备驱动上的未处理 I/O 请求队列。
  • request：队列中的单个请求项，包含一个或多个被调度算法合并的 bio 结构。

3. struct bio #

代表一个正在进行中的物理 Block I/O 操作：

c
struct bio {
    struct bio          *bi_next;       // 链表指针
    struct block_device *bi_bdev;       // 绑定的块设备
    unsigned short      bi_vcnt;        // 包含的 bio_vec 段个数
    struct bio_vec      *bi_io_vec;     // 💡 物理页描述符数组（实际存放数据的内存缓冲区）
    bio_end_io_t        *bi_end_io;     // I/O 结束回调函数
    // ...
};

4. struct bio_vec #

描述了一块连续的物理内存数据段：

c
struct bio_vec {
    struct page     *bv_page;   // 指向数据所在的物理内存页 (Page)
    unsigned int    bv_len;     // 数据段长度
    unsigned int    bv_offset;  // 页内偏移量
};
ℹ笔记

四者的层级包含关系：
一个 request_queue 请求队列由若干个 request 请求组成；每一个 request 包含多个被合并的 bio 操作；每一个 bio 在物理内存上由若干个 bio_vec 数据段描述。

四、 💡 核心进阶：电梯调度 vs 随机访问旁路 #

对于不同的物理存储介质，驱动配置 request_queue 的策略截然不同。

cpp
// 方式 A：配置带 I/O 调度的常规队列
struct request_queue *q = blk_init_queue(my_request_fn, &my_lock);
  • 适用场景：机械硬盘（HDD）。
  • 运行机理：底层使用 blk_queue_bio 回调，利用 I/O 调度器对磁道读写请求进行排序与合并。
  • 缺陷：由于机械寻道速度极慢，该方法通过牺牲少许 CPU/内存开销在主存中排序，能成倍提高机械盘写入效率。
cpp
// 方式 B：配置无调度的旁路队列
struct request_queue *q = blk_alloc_queue(GFP_KERNEL);
blk_queue_make_request(q, my_make_request_fn);
  • 适用场景：固态硬盘（SSD）、U盘、RamDisk 等。
  • 运行机理：通过 blk_queue_make_request 强行绑定自定义的“制造请求”回调函数，跳过系统的 I/O 调度核心（旁路电梯算法）。
  • 优势：此类闪存或内存设备支持极速的随机寻址，不存在机械寻道开销。如果强行开启电梯算法，复杂的链表重排排序操作会白白浪费掉大量的 CPU 时钟周期和系统内存。

五、 RamDisk 块设备驱动设计模板 #

以下是利用主存模拟一块物理硬盘的 RamDisk 模块核心初始化逻辑：

c
#define RAMDISK_SIZE (8 * 1024 * 1024) // 8MB 容量
static char *ramdisk_buf;              // 内存缓冲区指针
static struct gendisk *my_gd;
static struct request_queue *my_queue;

// 自定义制造请求函数（旁路调度）
static void my_make_request_fn(struct request_queue *q, struct bio *bio)
{
    struct bio_vec bvec;
    struct bvec_iter iter;
    
    // 遍历当前 bio 中所有的物理段
    bio_for_each_segment(bvec, bio, iter) {
        char *ptr = page_address(bvec.bv_page) + bvec.bv_offset;
        char *disk_ptr = ramdisk_buf + (iter.bi_sector * 512); // 计算对应的磁盘逻辑地址
        
        if (bio_data_dir(bio) == WRITE) {
            memcpy(disk_ptr, ptr, bvec.bv_len); // 写操作
        } else {
            memcpy(ptr, disk_ptr, bvec.bv_len); // 读操作
        }
    }
    bio_endio(bio, 0); // 结束通知
}

static int __init ramdisk_init(void)
{
    // 1. 申请主内存作为虚拟磁盘介质
    ramdisk_buf = kzalloc(RAMDISK_SIZE, GFP_KERNEL);

    // 2. 分配 gendisk 结构体并配置设备号
    my_gd = alloc_disk(1); // 1个次设备（不支持分区）
    my_gd->major = register_blkdev(0, "simp_blkdev"); // 动态获取主设备号

    // 3. 🔑 分配旁路 I/O 调度队列并绑定制造请求回调
    my_queue = blk_alloc_queue(GFP_KERNEL);
    blk_queue_make_request(my_queue, my_make_request_fn);
    my_gd->queue = my_queue;

    // 4. 设置容量大小
    set_capacity(my_gd, RAMDISK_SIZE / 512); // 容量以扇区(512B)为单位

    // 5. 载入核心 gendisk
    add_disk(my_gd);
    return 0;
}
