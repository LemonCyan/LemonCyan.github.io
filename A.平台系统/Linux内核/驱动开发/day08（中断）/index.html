按键驱动：

【1】驱动中，要申请中断 int request_irq( unsigned int irq, irq_handler_t handler, unsigned long flags, const char *name, void *dev_id)；

irq是要申请的中断号
handler是向系统注册的中断处理函数，是一个回调函数，中断发生时，系统调用这个函数，
flags是中断标志位。若设置了IRQF_DISABLED ，则表示中断处理程序被调用时屏蔽所有中断
dev_id在中断共享时会用到，一般设置为这个设备的设备结构体或者NULL
name设置中断名称，在cat /proc/interrupts中可以看到此名称。

irqreturn_t key_handler(int irqno, void * dev_id)
{

return IRQ_HANDLED;
}

与request_irq()向对应的函数为free_irq()，free_irq()的原型如下：
 void free_irq(unsigned int irq,void *dev_id);

【3】Linux中断底半部机制 原因：解决既要中断执行快，又要做的事情多的矛盾。

下半部机制
  软中断
  Tasklet
  工作队列

工作队列的使用方法和tasklet非常相似 tasklet运行于中断上下文 工作队列运行于进程上下文 tasklet处理函数中不能睡眠，而工作队列处理函数中允许睡眠

tasklet：

  1. 定义一个处理函数 void my_tasklet_func(unsigned long arg);

  2. 定义一个tasklet结构my_tasklet，与my_tasklet_func(data)函数相关联 Tasklet_init(&my_tasklet, my_tasklet_func, arg);

  3. 调度tasklet（） tasklet_schedule(&my_tasklet);

工作队列： 1.定义一个工作队列 struct work_struct my_wq;

2.定义一个处理函数 void my_wq_func(unsigned long) ；

  1. 初始化工作队列并将其与处理函数绑定 INIT_WORK(&my_wq, my_wq_func);

  2. 调度工作队列执行 schedule_work(&my_wq);

【4】内核中延时 短延迟定义为：延迟时间接近或短于一个jiffy 调用udelay和mdelay，忙等待函数，大量消耗CPU时间

长延迟定义为：延迟时间多于若干个jiffy，实现长延迟可以用查询jiffies的方法：time_before(jiffies, new_jiffies); time_after(new_jiffies, jiffies);

【5】内核定时器 驱动程序可以注册一个内核定时器，来指定一个函数在未来某个时间执行

1. 定义一个名为my_timer的定时器
   struct timer_list  my_timer;

2. 初始化定时器
   void  init_timer(struct timer_list * timer);
   mytimer.function = my_function;
   mytimer.expires =  jiffies + HZ;   //设置超时值，当jiffies的值大于expires时，my_function函数会执行

3. 增加定时器
   void  add_timer(struct timer_list * timer);

4. 删除定时器
   int  del_timer(struct timer_list * timer);

实现循环定时器： mod_timer(struct timer_list *timer, expires)
