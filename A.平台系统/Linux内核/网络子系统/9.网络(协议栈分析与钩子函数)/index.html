网络(协议栈分析与钩子函数)

Linux Netfilter 架构深度剖析：内核钩子函数与 sk_buff 解析 #

在 Linux 网络子系统里，Netfilter 是实现防火墙（iptables/nftables）、网络地址转换（NAT）以及报文过滤的灵魂所在。它在内核协议栈的关键路径上埋下了 5 个钩子点（Hooks），允许咱们注册自定义的钩子函数，对流经的网络数据包进行拦截、修改、或者直接丢弃。

今天咱们就来扒一扒 Netfilter 的内核运作机制，并手搓一个简单的网络过滤驱动。

一、 Netfilter 5 大钩子点与收发包流程 #

网络数据包在内核协议栈中传递时，会依次经过以下 5 个 Netfilter 节点：

                           +-------------------+
                           |  本地主机 (Local) |
                           +---^-----------+---+
                               |           |
                        [LOCAL_IN]    [LOCAL_OUT]
                               |           |
                               |      +----v-----+
                               |      | 路由判决 |
                               |      +----+-----+
                               |           |
    +------------+        +----+----+      |       +-------------+
    | 网卡接收器  +=======> | 路由判决 +====>F====> + 网卡发送器  |
    +------------+        +----+----+  [FORWARD]   +-----^-------+
                               |                   |
                         [PRE_ROUTING]       [POST_ROUTING]
  1. NF_INET_PRE_ROUTING：数据包刚从网卡收上来，还没进行路由决策前经过此点。适合做目的地址转换（DNAT）。
  2. NF_INET_LOCAL_IN：经路由决策后，发现该数据包是发给本机的，在送往用户空间协议栈之前经过此点。
  3. NF_INET_FORWARD：经路由决策后，发现数据包不是给本机的，需要从另一个网口转发出去时经过此点。一般设备需要双网口并开启转发功能（ip_forward）才会触发。
  4. NF_INET_LOCAL_OUT：本机用户态程序通过 socket 发送数据包，刚出协议栈、进行路由决策后经过此点。
  5. NF_INET_POST_ROUTING：无论是转发的数据包还是本机发送的数据包，在送往网卡驱动发送之前都会经过此点。适合做源地址转换（SNAT）。
✦提示

路由表是由网络层维护的。在 Windows 下可通过 route print 查看，在 Linux 下可通过 route -v 或 ip route 查看。

二、 关键数据结构与注册接口 #

1. 钩子注册结构体 struct nf_hook_ops #

在内核代码中，每一个注册的钩子都对应一个 struct nf_hook_ops 实例：

c
// 定义在 <linux/netfilter.h> 中
struct nf_hook_ops {
    struct list_head list;
    nf_hookfn        *hook;     // 指向自定义的钩子函数
    struct module    *owner;    // 填充 THIS_MODULE
    void             *priv;
    u_int8_t         pf;        // 协议族，如 PF_INET (IPv4)
    unsigned int     hooknum;   // 钩子点，如 NF_INET_PRE_ROUTING
    int              priority;  // 优先级，数字越小优先级越高，如 NF_IP_PRI_FIRST
};
  • 注册与注销接口：
    c
    int nf_register_hook(struct nf_hook_ops *reg);      // 注册单个
void nf_unregister_hook(struct nf_hook_ops *reg);  // 注销单个

2. 钩子回调函数原型 nf_hookfn #

注意，随着内核演进，该函数的定义在不同内核版本中会有变化。以 Linux 3.14 内核为例，原型如下：

c
typedef unsigned int nf_hookfn(const struct nf_hook_ops *ops,
                               struct sk_buff *skb,
                               const struct net_device *in,
                               const struct net_device *out,
                               int (*okfn)(struct sk_buff *));
  • skb：指向套接字缓冲区（Socket Buffer）的指针，封装了数据包内容。
  • in：接收该数据包的网卡设备。
  • out：发送该数据包的网卡设备。

3. 钩子函数的返回值（Verdict） #

钩子函数必须返回以下决策值之一，告诉内核该怎么处置这个包：

  • NF_ACCEPT (1)：放行，让数据包继续在协议栈中传递。
  • NF_DROP (0)：直接丢弃该数据包，释放 skb，后续协议栈不会再处理它。
  • NF_STOLEN (2)：强行接管该包。告诉协议栈“忘掉这个包吧，我来处理它”，内核不再释放它。
  • NF_QUEUE (3)：将数据包推入队列，通常由用户空间排队处理。
  • NF_REPEAT (4)：再次调用当前钩子函数。

三、 实战：手搓报文解析过滤驱动 #

下面咱们写一个内核钩子函数，当在 PRE_ROUTING 处拦截到来自源 IP 为 192.168.1.1 的 TCP 数据包时，打印出其 MAC 地址、源/目的 IP、以及 TCP 源/目的端口号。

1. MAC、IP 与 TCP 首部提取 #

我们可以通过内核提供的辅助函数，从 sk_buff 中安全地剥离出各个协议层的首部指针：

(1) 打印 MAC 地址
c
#define MAC_FMT "%02x:%02x:%02x:%02x:%02x:%02x"
#define MAC_ARG(x) ((u8*)(x))[0],((u8*)(x))[1],((u8*)(x))[2],((u8*)(x))[3],((u8*)(x))[4],((u8*)(x))[5]

void print_mac(struct ethhdr *eth)
{
    if (eth == NULL) return;
    if (eth->h_source)
        printk("SOURCE MAC: " MAC_FMT "\n", MAC_ARG(eth->h_source));
    if (eth->h_dest)
        printk("DEST MAC: " MAC_FMT "\n", MAC_ARG(eth->h_dest));
}
(2) 提取 IP 首部与端口
c
struct iphdr *iph = ip_hdr(skb);     // 获取 IP 头部
struct tcphdr *th = tcp_hdr(skb);    // 获取 TCP 头部

2. 完整钩子过滤代码 #

c
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/netfilter.h>
#include <linux/netfilter_ipv4.h>
#include <linux/skbuff.h>
#include <linux/ip.h>
#include <linux/tcp.h>
#include <linux/if_ether.h>

unsigned int filter_hook(const struct nf_hook_ops *ops,
                         struct sk_buff *skb,
                         const struct net_device *in,
                         const struct net_device *out,
                         int (*okfn)(struct sk_buff *))
{
    struct iphdr *iph;
    struct tcphdr *th;
    unsigned char *p_src;
    unsigned char *p_dst;

    if (!skb) return NF_ACCEPT;

    iph = ip_hdr(skb);
    if (!iph) return NF_ACCEPT;

    // 只过滤 TCP 协议的数据包
    if (iph->protocol == IPPROTO_TCP) {
        th = tcp_hdr(skb);
        if (!th) return NF_ACCEPT;

        // 匹配源 IP 为 192.168.1.1 (即 0xc0a80101) 的数据包
        // 注意：网络字节序是 Big-Endian 格式
        if (ntohl(iph->saddr) == 0xc0a80101) {
            printk("Intercepted target packet:\n");
            
            // 打印 TCP 端口信息（从网络字节序转换为主机字节序）
            printk("  sport: %d -> dport: %d\n", ntohs(th->source), ntohs(th->dest));
            
            // 打印源地址
            p_src = (unsigned char *)(&(iph->saddr));
            printk("  saddr: %d.%d.%d.%d\n", p_src[0], p_src[1], p_src[2], p_src[3]);
            
            // 打印目的地址
            p_dst = (unsigned char *)(&(iph->daddr));
            printk("  daddr: %d.%d.%d.%d\n", p_dst[0], p_dst[1], p_dst[2], p_dst[3]);
            
            // 如果需要实现包过滤拦截，把下面改写成 return NF_DROP; 即可
        }
    }
    return NF_ACCEPT;
}

// 定义钩子操作结构体
static struct nf_hook_ops pkt_filter = {
    .hook     = filter_hook,
    .owner    = THIS_MODULE,
    .pf       = PF_INET,                  // IPv4 协议族
    .hooknum  = NF_INET_PRE_ROUTING,      // 挂载在路由前钩子点
    .priority = NF_IP_PRI_FIRST,          // 最高优先级
};

static int __init filter_init(void)
{
    printk("Registering filter hook...\n");
    return nf_register_hook(&pkt_filter);
}

static void __exit filter_exit(void)
{
    printk("Unregistering filter hook...\n");
    nf_unregister_hook(&pkt_filter);
}

module_init(filter_init);
module_exit(filter_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("liuluhua");

四、 高阶实战扩展 #

在实际的项目开发中（如实现简易的 Web 重定向或软网关防火墙）：

  • 动态控制：咱们通常会创建一个字符设备，然后在用户态通过 ioctl() 动态下发过滤规则（如黑白名单 IP、重定向目标地址等）到内核。
  • HTTP 重定向：通过在 PRE_ROUTING 钩子点拦截 HTTP 流量（80 端口），修改其 TCP 数据包的目的 IP 和目的端口，然后重新计算校验和，就能无缝将用户的 HTTP 请求重定向到指定的 Web 服务器（如 Redirect Portal 页）。
