OutRay 内网穿透与 Webhook 抓包调试实战指南

OutRay 内网穿透全攻略：开源版 ngrok 替代方案与私有化隧道搭建实战 #

搞 Web 开发、小程序对接或者对接第三方支付（微信支付、Stripe、支付宝）的哥们，日常最痛苦的一件事莫过于调试 Webhook 回调：

  • 本地跑着 localhost:3000，代码改完加了断点，但第三方回调服务器根本找不到你家内网电脑；
  • 用传统的 ngrok 免费版，每次重启终端都随机生成一串像乱码一样的临时域名，你得屁颠屁颠跑到微信开放平台或 Stripe 后台重新改一遍回调 URL，恶心至极；
  • 国内一些商业穿透工具动不动限速 128KB/s、按月收几十块钱高昂订阅费，还要求强制手持身份证实名认证；
  • 自己手搓 FRP / NPS 虽然稳定，但需要专门买台公网云服务器，编写繁琐的 frpc.ini 或 frpc.toml，对于只想临时给客户演示个 Demo 或调两小时接口的轻量级场景来说，未免太杀鸡用牛刀了。

如果你正需要一个即装即用、开箱即穿、支持固定自定义域名、自带 Webhook 请求抓包/重放（Inspector）、且完全支持私有化自建服务端的极客级内网穿透神器，那么 OutRay 就是极佳的解法。

本文将从 OutRay 的底层通信机制、多协议（HTTP/HTTPS/TCP/UDP）命令行实战、Webhook 抓包重放面板、私有化 Server 端部署到生产级守护进程，带你彻底搞定这套轻量高效的内网穿透体系。

1. 核心架构与工作原理 #

在敲命令之前，咱们先看明白 OutRay 的底层通信拓扑结构。

sequenceDiagram
    autonumber
    actor Dev as 👨‍💻 本地开发者 (localhost:3000)
    participant Client as 🛠️ OutRay Client (CLI)
    participant Server as ☁️ OutRay 公共/私有服务器
    actor Visitor as 🌍 外部客户 / 微信支付 Webhook

    Dev->>Client: 1. 执行 `outray http 3000`
    Client->>Server: 2. 建立加密长连接控制隧道 (WebSocket/TLS)
    Server-->>Client: 3. 分配公网访问域名 (如 https://myapp.outray.io)
    
    Visitor->>Server: 4. 发起公网 HTTPS 请求 (POST /webhook/payment)
    Server->>Client: 5. 将数据包通过长连接多路复用隧道转发给本地 Client
    Client->>Dev: 6. 转发请求至 http://localhost:3000
    Dev-->>Client: 7. 本地服务返回 HTTP 200 OK
    Client-->>Server: 8. 回传响应数据
    Server-->>Visitor: 9. 响应外部请求
    Note over Client,Dev: 同时在本地 Web 仪表盘 (127.0.0.1:4040)<br/>完整记录请求头与 Payload，支持一键 Replay 重放！

为什么 OutRay 如此敏捷高效？ #

  1. 控制与数据多路复用（Multiplexing）：客户端与公网服务端之间仅维持一条高复用的持久加密长连接（基于 WebSocket / TLS 隧道），无需在路由器上做 NAT 端口转发，防火墙零拦截；
  2. 边缘自动 SSL/TLS 终止：客户端无需配置复杂的证书链，公网访问入口由 OutRay 边缘网关自动处理 HTTPS 握手与证书自动签发；
  3. 原生内嵌抓包分析器（Traffic Inspector）：请求在进出本地端口时被实时拦截并镜像到本地 WebUI，让开发者对每一次请求的 Request Header、Query Params、POST Body 及 Response Code 一览无余。

2. 客户端快速安装与开箱实战 #

OutRay 是基于 Node.js 生态构建的现代化跨平台工具，支持 macOS、Linux 及 Windows。

2.1 安装方式 #

方式 A：通过 NPM 全局安装（推荐） #

确保本地已安装 Node.js（推荐 Node.js >= 18.0.0）：

bash
# 全局安装 OutRay CLI
npm install -g outray

# 或者使用 pnpm / yarn
# pnpm add -g outray
# yarn global add outray

# 验证安装与版本
outray --version

方式 B：使用 NPX 免安装直接运行 #

如果你不想全局安装污染环境，可以直接使用 npx：

bash
npx outray http 3000

3. 核心功能与常用命令完全指南 #

3.1 基础 HTTP/HTTPS 穿透（Web 开发最常用） #

假设你本地前端运行在 http://localhost:3000，或者后端 API 运行在 http://localhost:8080：

bash
# 将本地 3000 端口映射到公网
outray http 3000

终端会输出类似如下的连接信息：

text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   OutRay Tunnel Active!                                     │
│                                                             │
│   Forwarding:  https://random-subdomain.outray.io -> :3000  │
│   Web Inspector: http://127.0.0.1:4040                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘

此时将 https://random-subdomain.outray.io 发给异地同事或配置到微信开放平台，即可直接穿透到你的本地机器。

3.2 进阶命令参数实战 #

1. 指定固定二级子域名（告别随机乱码） #

再也不用每次启动都改 Webhook 配置了，指定专属子域名（前提是该子域未被他人占用）：

bash
# 指定固定子域名为 my-awesome-app
outray http 3000 --subdomain my-awesome-app

访问地址将永久固定为：https://my-awesome-app.outray.io。

2. 添加 HTTP Basic Auth 密码保护（防止公网随意盗刷） #

如果穿透出来的服务是私有后台、开发数据库面板或未完成权限校验的接口，可以加一层密码保护：

bash
# 只有输入账号 admin、密码 secret123 的用户才能访问
outray http 3000 --auth "admin:secret123"

外部访客在浏览器打开时，会自动弹出 HTTP 认证弹窗，极大增强安全性。

3. 转发至本地自定义 Host 域名（适用于 Nginx 虚拟主机） #

有时候本地项目不是直接监听 localhost，而是通过本地 /etc/hosts 绑定了开发域名（例如 my-project.test），直接穿透会因为 Host 请求头不匹配导致 Nginx 报 404：

bash
# 重写请求 Host 头部为本地目标虚拟主机域名
outray http 80 --host-header "my-project.test" --local-host "my-project.test"

4. 穿透本地自签名 HTTPS 服务 #

如果本地服务本身就已经启用了 HTTPS（例如群晖 NAS 管理界面、带自签名证书的 Vite 本地开发服务器）：

bash
# 忽略自签名证书校验，并建立安全穿透
outray http 8443 --secure --insecure-skip-verify

3.3 TCP 原生端口穿透（SSH / MySQL / Redis 远程管理） #

除了 Web 网页，OutRay 还支持原生 TCP 协议穿透，非常适合远程临时连入内网数据库或 SSH 终端。

bash
# 1. 穿透本地 SSH 服务 (端口 22)
outray tcp 22

# 终端会输出公网映射端口，例如：
# Forwarding: tcp://tunnel.outray.io:45821 -> localhost:22

在外部电脑直接连接：

bash
ssh user@tunnel.outray.io -p 45821

bash
# 2. 穿透本地 MySQL 服务 (端口 3306)
outray tcp 3306

# 外部数据库连接工具 (如 Navicat / DBeaver) 直接填入：
# 主机: tunnel.outray.io
# 端口: 分配的随机公网端口 (如 54321)
# 用户名密码: 本地 MySQL 的 root 和密码

3.4 UDP 穿透（游戏开服 / 音视频流媒体） #

想和异地朋友联机玩 Minecraft、局域网联机游戏，或者测试私有 DNS 服务器：

bash
# 穿透 Minecraft Java 版游戏服务器默认端口 (25565 UDP/TCP)
outray udp 25565

4. Webhook 杀手级功能：内置请求抓包与一键 Replay 重放 #

在对接第三方 Webhook（如 Stripe 付款回调、微信支付异步通知、GitHub Actions 触发器）时，传统的调试流程极其蛋疼：

  1. 本地打断点；
  2. 掏出手机扫码真实支付一分钱；
  3. 断点进来了，但发现某行代码拼错了一个字段，报错挂掉；
  4. 改完代码重启服务，又得再扫一次码付一分钱重新触发！

OutRay 自带了完整的 Local Traffic Inspector 抓包控制台，彻底解决这个痛点。

抓包与重放实战步骤： #

  1. 启动穿透隧道：outray http 3000 --subdomain myapp；
  2. 浏览器打开本地监控面板：http://127.0.0.1:4040；
  3. 当外部第三方服务向 https://myapp.outray.io/api/webhook 发送请求时，监控面板会毫秒级实时刷新展示：
    • HTTP 方法 & 路径：POST /api/webhook/payment；
    • 请求头明细：Content-Type, User-Agent, X-Signature 签名头等；
    • 请求体 Payload：JSON 或 XML 原始报文内容；
    • 本地响应：HTTP 状态码（200 / 500）、响应耗时（ms）与返回内容。
  4. 一键重放（Replay）：直接在面板上点击 Replay 按钮，OutRay 会将刚才那次完全相同的请求报文原封不动地重新发送给本地 localhost:3000，一次扫码，无限次重放断点调试，开发效率直接翻倍！

5. 进阶玩法：自建私有化 OutRay 服务端（拥有独立域名与无限制带宽） #

虽然 OutRay 官方提供了免费的公共隧道节点，但在国内网络环境下，公共节点的延迟可能不如国内直连服务器爽快。如果你有一台国内的便宜公网 VPS（腾讯云、阿里云等），完全可以自建私有的 OutRay Server 端。

5.1 前置准备 #

  1. 一台具有公网固定 IP 的 Linux VPS（推荐 Ubuntu 22.04 / 24.04 LTS）；
  2. 一个独立域名（例如 yourdomain.com）；
  3. DNS 泛域名解析配置：
    • 添加一条 A 记录：tunnel.yourdomain.com -> 你的 VPS 公网 IP；
    • 添加一条泛域名 A 记录：*.tunnel.yourdomain.com -> 你的 VPS 公网 IP。

5.2 方案 A：使用 Docker Compose 极速部署服务端 #

创建项目目录与 docker-compose.yml：

bash
sudo mkdir -p /opt/outray-server && cd /opt/outray-server
sudo nano docker-compose.yml

写入以下配置：

yaml
version: '3.8'

services:
  outray-server:
    image: outray/server:latest
    container_name: outray-server
    restart: always
    environment:
      - DOMAIN=tunnel.yourdomain.com
      - PORT=8080
      - CONTROL_PORT=9000
      - SECRET_KEY=YourSuperSecretKey2026  # 客户端连接密钥，防止被他人白嫖
    ports:
      - "80:8080"       # 公网 HTTP 入口
      - "9000:9000"     # 隧道控制端口 (WebSocket/TCP)
      - "40000-40100:40000-40100" # 供 TCP/UDP 穿透使用的动态端口段

一键启动：

bash
sudo docker compose up -d

5.3 方案 B：使用 Node.js + PM2 原生部署 #

bash
# 1. 在服务器全局安装服务端包
sudo npm install -g outray-server pm2

# 2. 使用 PM2 启动常驻服务
pm2 start outray-server --name "outray-server" -- \
  --domain tunnel.yourdomain.com \
  --port 8080 \
  --control-port 9000 \
  --secret YourSuperSecretKey2026

# 3. 设置 PM2 开机自启
pm2 save
pm2 startup

5.4 配置 Nginx + 泛域名 SSL 证书反向代理 #

为了让穿透出去的二级子域名（如 https://app.tunnel.yourdomain.com）全部原生具备合法的 HTTPS 绿锁，我们用 Nginx 统一终结 SSL 证书：

nginx
# /etc/nginx/conf.d/outray.conf

# HTTP 自动跳转 HTTPS
server {
    listen 80;
    server_name tunnel.yourdomain.com *.tunnel.yourdomain.com;
    return 301 https://$host$request_uri;
}

# 泛域名 HTTPS 终结与反代
server {
    listen 443 ssl http2;
    server_name tunnel.yourdomain.com *.tunnel.yourdomain.com;

    # 配置 Let's Encrypt / acme.sh 申请的泛域名证书
    ssl_certificate /etc/letsencrypt/live/tunnel.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tunnel.yourdomain.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        # WebSocket 与长连接透传 (CRITICAL!)
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 真实来源 IP 透传
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;

        # 增加超时限制，防止长连接被 Nginx 中断
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}

5.5 客户端连接自建私有服务端 #

在本地电脑执行命令，带上 --server 和 --secret 参数即可直连自己的服务器：

bash
outray http 3000 \
  --server tunnel.yourdomain.com \
  --secret YourSuperSecretKey2026 \
  --subdomain myapp

此时你的访问地址就是：https://myapp.tunnel.yourdomain.com，享受专属国内云服务器的极速带宽，完全免受限速和断连困扰！

6. 本地持久化与守护进程配置 #

如果你的内网服务需要长期在线（例如家里的 NAS 网页、测试服务器），而不是调试两分钟就关掉，建议使用守护进程将 OutRay 挂在后台。

6.1 配置文件规范（免去每次敲冗长参数） #

在项目根目录或用户主目录创建 outray.config.json：

json
{
  "server": "tunnel.yourdomain.com",
  "secret": "YourSuperSecretKey2026",
  "tunnels": [
    {
      "name": "web-frontend",
      "proto": "http",
      "port": 3000,
      "subdomain": "my-web"
    },
    {
      "name": "backend-api",
      "proto": "http",
      "port": 8080,
      "subdomain": "my-api",
      "auth": "admin:secret2026"
    }
  ]
}

启动时只需运行：

bash
outray start --config outray.config.json

6.2 Linux Systemd 服务化管理 #

在 Linux 宿主机上创建系统服务文件：

bash
sudo nano /etc/systemd/system/outray.service

写入以下配置：

ini
[Unit]
Description=OutRay Tunnel Client Daemon
After=network.target network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/root
ExecStart=/usr/bin/outray http 3000 --server tunnel.yourdomain.com --secret YourSuperSecretKey2026 --subdomain myapp
Restart=always
RestartSec=5s
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target

启动并设置开机自启：

bash
sudo systemctl daemon-reload
sudo systemctl enable --now outray
sudo systemctl status outray

Windows 用户推荐使用 PM2 进行静默后台托管：

powershell

7. 踩坑排错宝典（Troubleshooting） #

坑点 1：本地服务启动后，外网访问提示 502 Bad Gateway #

  • 排查原因：
    1. 检查本地服务是否绑定在 127.0.0.1 还是 0.0.0.0。
    2. 如果本地服务运行在 Docker 容器内，localhost 会指向容器本身而不是宿主机。启动 OutRay 时请使用 --local-host host.docker.internal 或填写 Docker 网桥 IP。

坑点 2：WebSocket / SSE 连接频繁断开、1~2 分钟自动掉线 #

  • 排查原因：
    1. 中间反向代理（如 Nginx / Cloudflare）的默认连接超时时间通常为 60s。
    2. 解决办法：在自建 Nginx 配置中增加 proxy_read_timeout 86400s;，并在 OutRay 客户端添加心跳检测参数：--keepalive 30。

坑点 3：微信支付回调报签名校验失败 #

  • 排查原因：
    1. OutRay 在转发请求时，部分代理服务器可能会默认修改 Host 头部或剔除某些特定 Header。
    2. 解决办法：在命令中明确声明不要覆盖 Host 头部：outray http 3000 --preserve-host。

坑点 4：EADDRINUSE: 4040 错误 #

  • 排查原因：本地 4040 端口已被之前的实例或其他抓包工具占用。
  • 解决办法：指定新的 WebUI 监控端口：outray http 3000 --inspect-port 4041，或者直接关闭监控面板：--no-inspect。
