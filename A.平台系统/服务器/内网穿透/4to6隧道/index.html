4to6 隧道 #

4to6 隧道类似于 6to4 隧道，具有以下优点：

  1. 两台服务器之间的有效 IP 地址将是 IPv6。
  2. IPv6 价格低廉，被封锁时很容易更换。
  3. 您两端服务器的真实 IPv4 地址将免受封锁。

技术概述 #

该配置涉及两个节点 A 和 B：

德黑兰 ------------------GFW----------------- 东京
   A <---------------------------------------> B

在两个节点之间创建了一个隧道：

德黑兰 ------------------------------------------GFW----------------------------------------- 东京
   A                                                                                          B
| 虚拟 IPv4 <---- 4to6 ----> 真实 IPv6 | <------IPv6-----> | 真实 IPv6 <---- 4to6 ----> 虚拟 IPv4 |

IPv4 数据包被封装在 IPv6 数据包中，并通过 IPv6 网络传输。如果 IP 被封锁，被封的将是 IPv6 地址，因此很容易被替换，因为 IPv6 地址通常比 IPv4 地址便宜得多。

如何使用 #

您需要两台拥有 IPv6 地址的服务器。

服务器 A #

curl -o /tmp/4to6install.sh https://raw.githubusercontent.com/meshya/4to6-tunnel/main/scripts/install.sh; sudo bash /tmp/4to6install.sh; rm /tmp/4to6install.sh
字段 值
E0 服务器 A 的 IPv6
E2 服务器 B 的 IPv6
E4 192.168.1.1/24

服务器 B #

curl -o /tmp/4to6install.sh https://raw.githubusercontent.com/meshya/4to6-tunnel/main/scripts/install.sh; sudo bash /tmp/4to6install.sh; rm /tmp/4to6install.sh
字段 值
E0 服务器 B 的 IPv6
E2 服务器 A 的 IPv6
E4 192.168.1.2/24

测试 #

在服务器 A 上 #

ping 192.168.1.2

在服务器 B 上 #

ping 192.168.1.1

警告 #

如果您的其中一台服务器已经在运行 192.168.x.x 网段，您可能需要改用 172.16.x.x/12 网段（例如 172.16.0.1/12 和 172.16.0.2/12）。如果不确定，可以提交 issue 并附上 ip addr 的输出。

使用选项 #

有三种使用隧道的方法：

  1. IP/端口转发
  2. 在两台服务器上使用 Xray
  3. 使用自定义隧道方法

IP/端口转发 #

对于不丰富 IP/端口转发的用户，建议阅读相关资料并手动进行配置。

本文提供了关于设置端口转发的指南。

这里是一个快速设置指南：

要转发单个端口（例如端口 80），请使用以下设置（假设服务器 A 的虚拟 IP 为 192.168.1.1，服务器 B 的虚拟 IP 为 192.168.1.2）。

步骤 1 #

服务器 A #

iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 192.168.1.2:80
iptables -t nat -A POSTROUTING -j MASQUERADE

步骤 2 #

如果配置正常工作，请将这些命令添加到 local.rc 中。

在两台服务器上使用 Xray #

在两台服务器上安装 Xray 服务，并配置服务器 A 通过服务器 B 上的代理进行路由。可以使用 3x-ui 来简化此配置。如需协助，请联系我（我在各大平台叫 meshya，Telegram 上叫 meshyah）。

注：在服务器 A 上配置 Xray 时，请使用 192.168.1.2 代替服务器 B 的真实 IP。

使用自定义隧道方法 #

虽然不推荐，但如果您熟悉这些技术，也可以在 4to6 隧道之上使用自定义隧道方法，例如 Reverse TLS 或 Fake TLS。

注：使用虚拟 IP (192.168.x.x) 代替真实 IP。

提示 #

使用方法 2 时，建议调整路由规则并使用 伊朗托管域名项目，以使流向伊朗本地网站和服务的流量（尤其是 Shaparak 和支付服务）直接通过伊朗本地 IP 访问。这样配置可以免去用户频繁开关代理的麻烦。
