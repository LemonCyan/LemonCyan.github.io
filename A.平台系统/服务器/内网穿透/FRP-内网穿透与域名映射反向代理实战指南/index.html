FRP 内网穿透与域名映射反向代理实战指南

FRP 内网穿透与域名映射实战指南：从零搭建高性能私有反向代理网关 #

作为一名热衷折腾的开发者或 Homelab 极客，你一定遇到过这些场景：

  • 家里搭了 NAS、PVE 虚拟化集群或本地开发环境，想在外网用漂亮且不带端口号的独立域名（如 https://nas.yourdomain.com、https://api.yourdomain.com）直接访问；
  • 某些敏感服务（如 Windows 远程桌面 RDP 3389、内网私有 SSH 22、数据库 3306），绝对不敢直接把端口暴露在公网上被脚本小子扫描撞库；
  • 公共穿透服务带宽受限、流量受限，或者受制于服务商的隐私审查。

如果你手头有一台带固定公网 IP 的云服务器（VPS），那么由国内知名极客团队开源的 FRP（Fast Reverse Proxy），就是搭建完全自主可控、极高吞吐、支持全协议栈与点对点打洞的终极内网穿透利器。

本文将彻底抛弃陈旧过时的 INI 配置语法，全面拥抱最新的 FRP v0.50+ / v0.60+ 官方标准 TOML 规范，带你从底层通信机制、多子域名 80/443 复用、Nginx 前置共存、STCP/XTCP 点对点隐蔽穿透、tcpmux 端口复用、Docker Compose 编排、KCP 弱网加速到 Systemd 生产守护，搞定一套工业级的私有反向代理网关。

1. 核心架构与底层通信原理解析 #

FRP 采用经典的 Client-Server 架构，由公网服务端（frps）与内网客户端（frpc）协同工作。

FRP 核心技术优势： #

  1. 全协议覆盖：不仅支持标准 TCP/UDP 端口映射，更深度支持 HTTP/HTTPS 七层虚拟主机（vhost）、tcpmux 端口复用、STCP（端对端密钥鉴权加密）、以及 XTCP（基于 STUN 的 P2P 打洞直连，不消耗 VPS 流量）；
  2. 多路复用与连接池（Connection Pool）：客户端与服务端之间通过单个 TCP 隧道实现成百上千个数据通道的多路复用，配合连接池技术消除高并发下的反复建连握手耗时；
  3. 域名与 Host 动态路由：多个内网 Web 应用可共享 VPS 上的标准 80/443 端口，frps 自动提取 HTTP Header 中的 Host 字段精准分发到不同的内网机器。

2. 软件下载与跨平台安装部署 #

FRP 是使用 Go 语言编译的纯二进制程序，没有任何外部动态依赖，解压即用。

2.1 架构与版本获取 #

在 GitHub Releases 页面 下载最新发行版（以 Linux AMD64 为例）：

bash
# 1. 变量定义
FRP_VERSION="0.60.0"
ARCH="linux_amd64"

# 2. 下载并解压
wget https://github.com/fatedier/frp/releases/download/v${FRP_VERSION}/frp_${FRP_VERSION}_${ARCH}.tar.gz
tar -zxvf frp_${FRP_VERSION}_${ARCH}.tar.gz
cd frp_${FRP_VERSION}_${ARCH}

# 目录内包含的核心文件清单：
# - frps       -> 服务端可执行程序 (部署在公网 VPS)
# - frps.toml  -> 服务端 TOML 配置文件
# - frpc       -> 客户端可执行程序 (部署在内网机器)
# - frpc.toml  -> 客户端 TOML 配置文件

将二进制移动到系统可执行路径：

bash
sudo mv frps /usr/local/bin/ (VPS 端)
sudo mv frpc /usr/local/bin/ (内网客户端)

3. 服务端 frps.toml 生产级全功能配置 #

在公网 VPS 上创建并编辑 /etc/frp/frps.toml：

bash
sudo mkdir -p /etc/frp
sudo nano /etc/frp/frps.toml

写入以下经过严格生产验证的配置模板：

toml
# ========================================================
# FRP 服务端生产级综合配置文件 (frps.toml)
# ========================================================

# 1. 基础服务监听与安全认证
bindAddr = "0.0.0.0"
bindPort = 7000                 # frpc 客户端连接的主服务端口
kcpBindPort = 7000              # 开启 UDP 7000 用于 KCP 弱网加速

# 强密码认证 (客户端与服务端必须完全一致)
auth.method = "token"
auth.token = "YourSuperSecureToken2026"

# 2. HTTP / HTTPS 虚拟主机 (vhost) 端口
# 开启后，内网多个 Web 服务可共享这组端口，依据域名做分流
vhostHTTPPort = 8080            # 如果 VPS 本地未装 Nginx，可直接填 80
vhostHTTPSPort = 8443           # 如果 VPS 本地未装 Nginx，可直接填 443

# 泛域名自动匹配 (例如配置后，*.frp.yourdomain.com 会自动路由)
subDomainHost = "frp.yourdomain.com"

# 3. tcpmux 模式多路复用支持 (复用单端口实现多 TCP 服务)
tcpmuxHTTPConnectPort = 7001

# 4. Web Dashboard 管理控制台
webServer.addr = "0.0.0.0"
webServer.port = 7500           # 访问 http://VPS_IP:7500 打开控制台
webServer.user = "admin"
webServer.password = "AdminSecret2026"
webServer.pprof.enable = false

# 5. 传输优化与网络安全限制
transport.maxPoolCount = 50     # 每个代理允许的最大连接池数量
transport.tcpKeepalive = 7200   # TCP 保活心跳周期 (秒)

# 允许客户端绑定的远程端口白名单范围 (防止客户端随意滥用系统端口)
allowPorts = [
  { start = 20000, end = 30000 }
]

# 6. 日志审计
log.to = "/var/log/frps.log"
log.level = "info"
log.maxDays = 7

4. 客户端 frpc.toml 多场景实战配置 #

在内网机器（NAS、开发工作站、本地服务器）上创建 /etc/frp/frpc.toml：

bash
sudo mkdir -p /etc/frp
sudo nano /etc/frp/frpc.toml

4.1 核心配置模板（涵盖 Web/SSH/RDP/STCP/XTCP/tcpmux） #

toml
# ========================================================
# FRP 客户端生产级多场景配置文件 (frpc.toml)
# ========================================================

# 1. 远端服务器连接凭据
serverAddr = "vps.yourdomain.com"
serverPort = 7000

auth.method = "token"
auth.token = "YourSuperSecureToken2026"

# 全局传输加密与压缩 (极客强烈推荐开启，节省带宽并防止嗅探)
transport.useEncryption = true
transport.useCompression = true

# ========================================================
# 场景 1：HTTP 虚拟主机 (多域名不带端口直连)
# ========================================================
[[proxies]]
name = "web_app"
type = "http"
localIP = "127.0.0.1"
localPort = 3000
# 方式 A: 指定完整独立域名
customDomains = ["app.yourdomain.com"]

[[proxies]]
name = "wiki_system"
type = "http"
localIP = "192.168.1.55"
localPort = 8080
# 方式 B: 使用子域名模式 (访问地址为 wiki.frp.yourdomain.com)
subdomain = "wiki"

# ========================================================
# 场景 2：基础 TCP 端口暴露 (远程 SSH 终端)
# ========================================================
[[proxies]]
name = "ssh_linux"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 22222              # 映射到 VPS 公网的 22222 端口

# ========================================================
# 场景 3：STCP (Secret TCP) 安全私密穿透 (强烈推荐!)
# 绝不暴露任何公网端口，黑客完全探测不到，需客户端双向握手
# ========================================================
[[proxies]]
name = "secret_rdp_server"
type = "stcp"
secretKey = "RdpKey_987654321"   # 双方协商的私密密钥
localIP = "127.0.0.1"
localPort = 3389                # Windows 远程桌面端口

# ========================================================
# 场景 4：XTCP (P2P 点对点打洞，不走 VPS 流量)
# ========================================================
[[proxies]]
name = "p2p_file_transfer"
type = "xtcp"
secretKey = "P2P_Secret_Key_2026"
localIP = "127.0.0.1"
localPort = 9000

# ========================================================
# 场景 5：tcpmux 端口复用 (HTTP Connect 隧道)
# ========================================================
[[proxies]]
name = "ssh_tcpmux"
type = "tcpmux"
multiplexer = "httpconnect"
customDomains = ["ssh.yourdomain.com"]
localIP = "127.0.0.1"
localPort = 22

5. 进阶杀手锏 1：STCP 私密穿透（零公网暴露面） #

很多哥们把 Windows 远程桌面的 3389 端口或者本地 SSH 映射到公网端口，结果不到半天就被全球撞库脚本扫爆。

STCP（Secret TCP） 是 FRP 提供的终极安全方案：

  • VPS 上不开放任何额外的 TCP 端口；
  • 只有在你的外出笔记本上也运行一个配套的 frpc 客户端并输入相同的 secretKey，两端才能通过 VPS 完成鉴权握手并建立加密隧道。
sequenceDiagram
    autonumber
    actor Dev as 💻 外出笔记本 (frpc visitor)
    participant VPS as ☁️ 公网 VPS (frps)
    participant HomePC as 🏠 家里内网主机 (frpc server)

    Note over HomePC,VPS: 1. 家里主机宣告 STCP 服务 (secretKey: RdpKey_987654321)<br/>VPS 不监听任何额外公网 TCP 端口！
    Dev->>VPS: 2. 笔记本启动 visitor 模式，携带 secretKey 请求握手
    VPS->>HomePC: 3. 验证密钥匹配，建立点对点加密转发通道
    Dev->>Dev: 4. 笔记本本地监听 127.0.0.1:13389
    Dev->>Dev: 5. 远程桌面连接 localhost:13389 -> 秒级直通家里 3389！

客户端（笔记本）Visitor 配置文件 frpc_visitor.toml： #

在外出笔记本上安装 frpc 并写入以下配置：

toml
serverAddr = "vps.yourdomain.com"
serverPort = 7000
auth.token = "YourSuperSecureToken2026"

[[visitors]]
name = "secret_rdp_visitor"
type = "stcp"
serverName = "secret_rdp_server"   # 与目标主机的 proxy name 保持一致
secretKey = "RdpKey_987654321"     # 双方协商的私密密钥
bindAddr = "127.0.0.1"
bindPort = 13389                   # 映射到笔记本本地的端口

启动 visitor：

bash
frpc -c frpc_visitor.toml

现在打开 Windows 远程桌面客户端（mstsc），直接连接 127.0.0.1:13389，即可极速连回办公室或家里的电脑，公网完全隐形，安全性无懈可击！

6. 进阶杀手锏 2：VPS 上与 Nginx 完美共存（80/443 统一反代） #

当你的 VPS 上已经运行了博客、其他 Web 站点并占用了标准的 80 和 443 端口时，直接让 frps 监听 80/443 会引发端口冲突报错 bind: address already in use。

终极解法：让 Nginx 监听公网标准的 80/443 端口并负责 SSL 证书卸载，再将特定域名的流量反向代理给 frps 的 vhostHTTPPort (8080)。

    subgraph VPS_Internal [VPS 本地内部回环]
        Nginx -->|Proxy Pass 转发至 127.0.0.1:8080| Frps[🖥️ frps vhostHTTPPort]
    end

    Frps ===|FRP 加密隧道| Frpc[🛠️ 内网 frpc]
    Frpc --> LocalApp[🏠 本地项目 localhost:3000]

Nginx 生产级分流配置： #

在 VPS 的 /etc/nginx/conf.d/frp_vhost.conf 中写入：

nginx
# HTTP 强制跳转 HTTPS
server {
    listen 80;
    server_name app.yourdomain.com wiki.frp.yourdomain.com *.frp.yourdomain.com;
    return 301 https://$host$request_uri;
}

# HTTPS 证书终结并反代至 frps
server {
    listen 443 ssl http2;
    server_name app.yourdomain.com wiki.frp.yourdomain.com *.frp.yourdomain.com;

    # SSL 证书配置 (Certbot 或自有证书)
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        # 核心：转发给 frps 监听的 vhostHTTPPort
        proxy_pass http://127.0.0.1:8080;
        
        # 必须带上原始 Host 头部，frps 依赖该头部定位具体的内网客户端
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;

        # WebSocket 支持
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 延长超时时间，防止长连接被中断
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}

重新加载 Nginx 配置：

bash
sudo nginx -t && sudo nginx -s reload

至此，外网用户输入 https://app.yourdomain.com 即可直接访问内网 Web 服务，不仅拥有合法绿锁 HTTPS 证书，还完全不需要在 URL 后面加任何丑陋的端口号！

7. 进阶杀手锏 3：tcpmux 模式多 SSH 域名复用 #

如果不想开放多个 TCP 端口，可以使用 FRP 的 tcpmux 功能，让 SSH 流量借助 HTTP CONNECT 协议复用 7001 端口：

在个人电脑配置 ~/.ssh/config：

text
Host ssh.yourdomain.com
    ProxyCommand nc -X connect -x vps.yourdomain.com:7001 %h %p
    User root

敲命令：

bash
ssh ssh.yourdomain.com

nc 会自动通过 HTTP CONNECT 代理协议发起握手，frps 根据 Host 路由给对应的内网机器，实现单个端口承载无限个 SSH 域名转发！

8. 弱网加速黑科技：KCP 协议传输优化 #

在长途跨国线路、校园网或移动 4G/5G 热点等网络抖动严重、丢包率高的场景下，传统的 TCP 单连接容易出现吞吐骤降、SSH 输入粘滞的问题。

FRP 原生内置了基于 UDP 的 KCP 传输协议。KCP 牺牲了一小部分冗余流量（约 10%~20%），换取在 30% 恶劣丢包环境下仍然保持极低延迟的非凡体验。

开启 KCP 步骤： #

1. 服务端 frps.toml 开启 KCP 监听 #

toml
bindPort = 7000
kcpBindPort = 7000  # 开启 UDP 7000 端口用于 KCP 传输
ℹ笔记

务必在 VPS 的云厂商安全组和系统防火墙放行 UDP 7000 端口！

2. 客户端 frpc.toml 指定传输协议 #

toml
serverAddr = "vps.yourdomain.com"
serverPort = 7000
transport.protocol = "kcp"  # 将传输协议切换为 kcp

10. 生产级守护进程与开机自启（Systemd） #

10.1 服务端 Systemd 配置（VPS 端） #

创建 /etc/systemd/system/frps.service：

ini
[Unit]
Description=FRP Server Service
After=network.target network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
ExecStart=/usr/local/bin/frps -c /etc/frp/frps.toml
Restart=on-failure
RestartSec=5s
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target

启动并设置开机自启：

bash
sudo systemctl daemon-reload
sudo systemctl enable --now frps
sudo systemctl status frps

10.2 客户端 Systemd 配置（内网端） #

创建 /etc/systemd/system/frpc.service：

ini
[Unit]
Description=FRP Client Service
After=network.target network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
ExecStart=/usr/local/bin/frpc -c /etc/frp/frpc.toml
Restart=always
RestartSec=5s
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target

启动并设置开机自启：

bash
sudo systemctl daemon-reload
sudo systemctl enable --now frpc
sudo systemctl status frpc

11. 踩坑排错宝典（Troubleshooting） #

坑点 1：客户端连接报错 authorization failed #

  • 原因：auth.token 密码在两端不匹配，或者服务端与客户端系统时钟偏差超过 900 秒（FRP 默认基于时间戳防重放攻击）。
  • 解决：检查两端 Token 字符串；在两端运行 ntpdate ntp.aliyun.com 同步系统时间。

坑点 2：访问 HTTP 域名报 The page you have requested is not available. (FRP 404) #

  • 原因：
    1. frpc.toml 中的 customDomains 或 subdomain 与访客请求的 Host 请求头不匹配；
    2. Nginx 反代配置中漏写了 proxy_set_header Host $host;，导致 Host 变成了 127.0.0.1。

坑点 3：SSH 提示 Connection reset by peer 或频繁掉线 #

  • 排查步骤：
    1. 检查内网 Linux 的防火墙规则是否允许本地 22 端口入站；
    2. 启用 TCP 保活配置，在 frpc.toml 中加入：
      toml
      transport.tcpKeepalive = 30
    3. 开启数据压缩：transport.useCompression = true。

13. 极客总结与速查清单 #

FRP 经过多年的迭代，已经成为反向代理与内网穿透领域的绝对事实标准。掌握 TOML 规范 + STCP 隐蔽穿透 + Nginx 80/443 端口共存，你就能随心所欲地驾驭任何复杂的内网穿透与异地组网拓扑。

  • VPS 下载 FRP 解压并配置 /etc/frp/frps.toml
  • 内网主机配置 /etc/frp/frpc.toml
  • 敏感服务（SSH/RDP）果断采用 stcp
  • VPS 配置 Nginx 反代 127.0.0.1:8080
  • 注册 frps.service 和 frpc.service
