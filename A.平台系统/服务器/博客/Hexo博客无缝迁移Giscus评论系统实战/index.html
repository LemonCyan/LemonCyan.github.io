Hexo博客无缝迁移Giscus评论系统实战

Hexo 博客评论系统切换：基于 GitHub Discussions 的 Giscus 实战指南 #

以前很多玩静态博客的同行都用过 Utterances 或 Gitalk，用 GitHub Issues 当数据库确实省心，但用久了有一个极度恶心的痛点：文章一多、读者一留言，你的 GitHub 仓库 Issues 列表里全都是博文评论，真正的 Bug 和项目 Issue 全被淹没了。

后来社区推出了 Giscus —— 它直接把底层存储迁移到了 GitHub 官方的 Discussions（讨论区）。不仅 Issues 列表重归清爽，还自带 Emoji 表情互动（Reactions）、盖楼回复、深浅色主题跟随，最关键的是：依然完全免费、零服务器、零维护成本。

今天咱们就把 Stellar / Hexo 博客从旧评论系统无缝切换到 Giscus。

架构与交互流程 #

sequenceDiagram
    autonumber
    actor Reader as 读者
    participant Blog as 博客文章页 (Giscus Client)
    participant App as Giscus App 服务
    participant Repo as GitHub Discussions (存储库)

    Note over Blog: 读者滚动到底部可视区域 (Lazyload 触发)
    Blog->>App: 请求加载对应页面的评论列表 (基于 pathname / title)
    App->>Repo: 读取 Discussions 讨论串与回复
    Repo-->>App: 返回讨论数据
    App-->>Blog: 渲染评论列表、表情 Reactions 和评论输入框
    Reader->>Blog: GitHub 授权登录并提交评论 / 点赞
    Blog->>Repo: 写入 GitHub Discussion 评论节点

四步极速实战配置 #

第一步：GitHub 仓库开通 Discussions #

  1. 确保你的博客仓库（如 luhuaCyan/luhuaCyan.github.io）是 Public（公开） 的（私有仓库 Discussions 无法公开匿名读取）。
  2. 进入 GitHub 仓库页面，点击顶部的 Settings。
  3. 在左侧菜单点击 General，往下滑找到 Features 区域。
  4. 勾选 Discussions 选项（如果没勾选的话）。
  5. 点击仓库顶部的 Discussions 标签页，查看默认分类：
    • 推荐使用系统自带的 Announcements 分类（该分类默认只有仓库 Owner 才能发起主帖，正好适合作为博客文章评论映射，避免别人在 Discussions 里乱发主帖）。

第二步：安装并授权 Giscus App #

  1. 打开 GitHub Apps - Giscus。
  2. 点击 Install（或 Configure）。
  3. 选择 Only select repositories，选中你的博客仓库（如 luhuaCyan/luhuaCyan.github.io）。
  4. 点击 Save 完成授权。

第三步：在 Giscus 官网自动提取配置参数 #

打开 Giscus 官网配置生成器 (giscus.app/zh-CN)：

  1. 语言：选择 简体中文。
  2. 仓库：输入你的 GitHub 仓库路径（例如：luhuaCyan/luhuaCyan.github.io）。
    • 如果配置正确，下方会显示绿色的 满足所有条件。
  3. 页面 ↔️ discussion 映射方式：
    • 强烈推荐选择：URL pathname（即 /2026/08/27/文章名/），好处是后续你改文章标题不会导致旧评论丢失。
  4. Discussion 分类：
    • 选择 Announcements（公告）。
  5. 特性选择：
    • 勾选 启用 reactions (表情反应)。
    • 评论框位置：选择 顶部 (Top)。
    • 主题：选择 preferred_color_scheme（自动跟随系统的深浅色模式）。
  6. 提取参数： 滑到页面最下方的“启用 giscus”代码块，记录以下几项核心参数：
    • data-repo-id（例如：R_kgDOHxxxxx）
    • data-category-id（例如：DIC_kwDOHxxxxx）

第四步：修改主题配置文件 #

打开你的主题配置文件 themes/stellar/_config.yml（第 218 行起）：

  1. 将 comments.service 由 utterances 改为 giscus。
  2. 将第三步获取到的 data-repo、data-repo-id、data-category、data-category-id 填入：
yaml
######## Comments ########
comments:
  service: giscus                          # 1. 切换为 giscus
  comment_title: 快来参与讨论吧~
  lazyload: true                           # 2. 启用懒加载，提升博客首屏打开速度
  
  # giscus 详细配置
  giscus:
    src: https://giscus.app/client.js
    data-repo: luhuaCyan/luhuaCyan.github.io # 3. 你的 GitHub 用户名/仓库名
    data-repo-id: R_kgDOHxxxxxx             # 4. 替换为你生成的 repo-id
    data-category: Announcements            # 5. 分类名称
    data-category-id: DIC_kwDOHxxxxxx       # 6. 替换为你生成的 category-id
    data-mapping: pathname                  # 7. 映射规则，推荐 pathname
    data-strict: 0
    data-reactions-enabled: 1               # 开启表情点赞
    data-emit-metadata: 0
    data-input-position: top                # 评论框置顶
    data-theme: preferred_color_scheme      # 自动适配深浅色模式
    data-lang: zh-CN
    data-loading: lazy
    crossorigin: anonymous

高级技巧与单篇控制 #

1. 单独关闭某篇文章的评论 #

如果某篇文章是个人随笔或不希望开启讨论，只需在文章头部的 Front-matter 中加上 comments: false：

markdown
---
title: 某篇不开放评论的文章
date: 2026-08-27
comments: false
---

2. 映射规则避坑（为什么选 pathname 而不是 title） #

  • 如果选 title：一旦你觉得文章标题起得不好改了标题，旧文章对应的 GitHub Discussion 就断链了，读者会以为评论全没了。
  • 选 pathname：只要文章的永久链接（URL）不变，评论数据稳如泰山。

本地验证与上线 #

配置完成后，终端执行三连命令清理并启动本地服务：

bash
npx hexo clean && npx hexo server

打开浏览器访问任意一篇文章滑到最底部：

  • 看到 Discussion 样式的评论区加载出来，可以点击表情 👍、写评论、回复楼层。
  • 进入你的 GitHub 仓库的 Discussions 标签页，能看到自动生成了一条以该文章 URL 命名的讨论帖，Issues 列表干干净净！
