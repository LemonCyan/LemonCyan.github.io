在SSH上禁用SSH密码认证 #

禁用 SSH 密码认证是提升系统安全性的良好实践，尤其适用于面向公网的服务器。以下为禁用 SSH 密码认证的分步教程。本指南默认您使用的是基于 Linux 的操作系统。

步骤 1：确保已配置密钥认证 #

在禁用密码认证前，请务必确认密钥认证已正确配置并可正常工作。若在未配置替代登录方式的情况下直接禁用密码认证，可能导致您被彻底锁死于服务器之外。

  1. 生成 SSH 密钥对（如尚未生成）：

    bash
    ssh-keygen -t rsa -b 4096

    按回车键接受默认文件路径；您亦可选择设置口令短语（passphrase），以增强安全性。

  2. 将公钥复制至服务器：

  3. Windows 系统：

    bash
    cat $HOME\.ssh\id_rsa.pub | ssh username@your_server_ip 'cat >> ~/.ssh/authorized_keys'

  4. Linux 与 macOS 系统：

    bash
    ssh-copy-id username@your_server_ip

请将 username 替换为您的实际用户名，your_server_ip 替换为服务器的实际 IP 地址。

  1. 测试密钥登录：尝试使用 SSH 密钥登录服务器：
    bash
    ssh username@your_server_ip
    若无需输入密码即可成功登录，则表明密钥认证已生效。

警告！若上一步操作出现错误，请勿继续执行步骤 2 #

步骤 2：编辑 SSH 配置文件 #

  1. 访问 SSH 配置文件：

    bash
    sudo nano /etc/ssh/sshd_config

    您可将 nano 替换为偏好的文本编辑器（例如 vi 或 vim）。

  2. 查找密码认证相关配置项：定位包含 PasswordAuthentication 的行；该行可能已被注释（即以 # 开头）。

  3. 禁用密码认证：将该行修改为：

    bash
    PasswordAuthentication no

    若文件中不存在此行，可在文件末尾手动添加。

  4. 保存并退出编辑器：若使用 nano，可按 Ctrl + O 保存，再按 Ctrl + X 退出。

步骤 3：重启 SSH 服务 #

修改 sshd_config 文件后，需重启 SSH 服务以使更改生效：

bash
sudo systemctl restart sshd

步骤 4：测试配置效果 #

  1. 测试 SSH 登录：再次尝试通过 SSH 登录。此时服务器应拒绝密码认证请求：

    bash
    ssh username@your_server_ip

    请确认仍可通过密钥认证正常登录。

  2. （可选）从其他主机测试：若条件允许，可尝试从一台未配置您 SSH 密钥的机器发起连接；服务器应禁止仅凭密码的登录请求。

步骤 5：附加安全强化措施 #

  • 考虑将 SSH 服务端口由默认的 22 号更改为非标准端口，以降低遭受自动化攻击的风险。了解更多 …
  • 定期更新服务器系统及 SSH 相关软件。
  • 配置防火墙，并严格限制仅开放必要端口。了解更多 …
  • 监控登录尝试行为，并部署入侵检测系统。

遵循上述步骤，您即可成功禁用 SSH 密码认证，从而显著提升服务器安全性。请务必确保已预先配置可靠的备用登录方式（如密钥认证），以防意外被锁定。

通过遵循这些步骤，您应该已经成功禁用了 SSH 密码身份验证，从而增强了服务器的安全性。请务必确保已配置好备份方法（如基于密钥的身份验证），以防被锁在外面。
