Git Server 部署与全栈运维手册 #

在软件工程、DevOps 自动化与知识库管理中，搭建一套安全、自主可控的 私有 Git 服务器（Git Server） 是技术团队和极客玩家的核心基础设施。本文系统讲解从 原生轻量 SSH Git Server 到 现代容器化 Gitea 平台 的完整搭建流程，并深入探讨 Git Hooks 自动化部署、Git LFS 大文件存储、仓库瘦身备份 以及 生产级安全运维。

2. 方案一：搭建原生轻量 SSH Git Server（零依赖极简模式） #

原生 Git Server 利用 Linux 现有的 SSH 服务与 Git 工具链实现，数据传输完全基于 SSH 加密通道。

sequenceDiagram
    autonumber
    actor Dev as 开发者机器 (Git Client)
    participant SSH as SSH 服务端 (Port 22)
    participant GitShell as 受限 Shell (git-shell)
    participant BareRepo as 裸仓库 (/srv/git/project.git)

    Dev->>SSH: 1. git push origin main (使用 git 用户 SSH 认证)
    SSH->>SSH: 2. 校验 ~/.ssh/authorized_keys
    SSH->>GitShell: 3. 授权进入受限 git-shell 环境
    GitShell->>BareRepo: 4. 执行 git-receive-pack 写入对象与引用
    Note over BareRepo: 5. 触发 post-receive Hook 自动部署
    BareRepo-->>Dev: 6. 返回推送成功状态 (commit hash)

2.1 步骤 1：安装 Git 并创建受限专职账户 git #

为了系统安全，严禁允许用户通过 git 账户获取交互式 Bash Shell 登录权限，必须将其登录 Shell 锁定为 git-shell：

bash
# 1. 更新系统并安装 Git
sudo apt update && sudo apt install -y git

# 2. 创建 git 专职系统用户（禁用密码登录，指定主目录为 /home/git）
sudo adduser --system --shell $(which git-shell) --group --disabled-password --home /home/git git

# 3. 验证 /etc/shells 中已注册 git-shell
which git-shell | sudo tee -a /etc/shells

2.2 步骤 2：配置客户端 SSH 公钥免密认证 #

  1. 在本地开发者机器生成密钥对（若已有则跳过）：
    bash
    ssh-keygen -t ed25519 -C "developer@example.com"
# 公钥位于 ~/.ssh/id_ed25519.pub
  2. 在 Git 服务器上配置受信公钥库：
    bash
    # 切换至 git 用户主目录
sudo mkdir -p /home/git/.ssh
sudo touch /home/git/.ssh/authorized_keys

# 将开发者的公钥追加到 authorized_keys
echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... developer@example.com" | sudo tee -a /home/git/.ssh/authorized_keys

# 严格配置文件与目录权限（SSH 安全机制强制要求）
sudo chmod 700 /home/git/.ssh
sudo chmod 600 /home/git/.ssh/authorized_keys
sudo chown -R git:git /home/git/.ssh

2.3 步骤 3：初始化裸仓库（Bare Repository） #

裸仓库（--bare）不包含可编辑的工作区文件（Working Tree），仅保存 Git 的版本历史数据库、对象文件与引用指针，专门用于集中式推送与拉取。

bash
# 1. 创建统一存放仓库的目录
sudo mkdir -p /srv/git

# 2. 初始化一个名为 my-project.git 的裸仓库
sudo git init --bare /srv/git/my-project.git

# 3. 赋予 git 账户所有权
sudo chown -R git:git /srv/git
sudo chmod -R 775 /srv/git

2.4 步骤 4：客户端远程克隆、推送与验证 #

在本地客户端执行：

bash
# 1. 从自建 Git Server 克隆仓库
git clone git@<你的服务器IP>:/srv/git/my-project.git

cd my-project

# 2. 编写文件并提交
echo "# My Private Git Repo" > README.md
git add README.md
git commit -m "Initial commit"

# 3. 推送到自建服务器
git push -u origin master (或 main)

3. Git Hooks 自动化部署：代码推送即刻上线 #

Git 提供了强大的钩子机制（Hooks）。在裸仓库中利用 post-receive 钩子，可以在开发者每次 git push 成功后，自动将最新代码检出（Checkout）到生产环境 Web 根目录（如 /var/www/my-website），免去手动登录服务器拉取的繁琐。

graph LR
    Client[本地 git push] -->|推送完成| Hook[裸仓库 post-receive 钩子]
    Hook -->|指定 GIT_WORK_TREE| WebDir[生产 Web 目录 /var/www/my-website]
    Hook -->|触发构建| Build[执行 npm install / 重启服务]
    Build --> Finish[更新完成, 对外提供服务]

3.1 编写 post-receive 自动部署脚本 #

进入服务器裸仓库的 hooks 目录：

bash
sudo vim /srv/git/my-project.git/hooks/post-receive

写入以下生产级自动检出脚本：

bash
#!/usr/bin/env bash
# ==========================================================
# Git Post-Receive 自动化部署脚本
# ==========================================================

TARGET_BRANCH="main"
DEPLOY_DIR="/var/www/my-website"
GIT_DIR="/srv/git/my-project.git"

echo "==============================================="
echo "🚀 收到推送请求，开始执行自动化部署流水线..."
echo "==============================================="

# 读取推送的引用更新信息 (旧commit 新commit 分支ref)
while read oldrev newrev ref
do
    BRANCH=$(git rev-parse --symbolic --abbrev-ref $ref)
    
    if [ "$BRANCH" = "$TARGET_BRANCH" ]; then
        echo "📦 正在检出 [$TARGET_BRANCH] 分支代码到生产目录: $DEPLOY_DIR"
        
        # 确保目标目录存在
        mkdir -p $DEPLOY_DIR
        
        # 核心命令：将裸仓库指定分支检出到目标工作目录
        git --work-tree=$DEPLOY_DIR --git-dir=$GIT_DIR checkout -f $TARGET_BRANCH
        
        # 修正生产目录权限
        chown -R www-data:www-data $DEPLOY_DIR
        
        # 可选：触发构建或重载服务 (如静态博客构建、Node.js 重启)
        # cd $DEPLOY_DIR && npm install && hexo generate
        # systemctl reload nginx
        
        echo "✅ 恭喜！[$TARGET_BRANCH] 分支已成功部署上线！"
    else
        echo "ℹ️ 推送分支 [$BRANCH] 非发布主分支，跳过自动部署。"
    fi
done

赋予执行权限：

bash
sudo chmod +x /srv/git/my-project.git/hooks/post-receive
sudo chown git:git /srv/git/my-project.git/hooks/post-receive

4. 方案二：搭建现代轻量 Gitea 代码托管平台（Docker 容器化） #

如果你需要像 GitHub 一样漂亮的 Web 界面、代码差异审查（PR/MR）、Issue 任务管理、Wiki 文档以及团队成员细粒度权限控制，Gitea 是性价比最高的方案。

graph TD
    Client[客户端 浏览器 / Git] -->|HTTPS 443| Nginx[Nginx 反向代理]
    Client -->|SSH 2222| GiteaSSH[Gitea 容器 SSH 服务]
    Nginx -->|内部代理 3000| GiteaWeb[Gitea Web 核心引擎]
    GiteaWeb --> GiteaData[(持久化存储 /data)]
    GiteaWeb --> MySQL[(MariaDB / PostgreSQL 数据库)]

4.1 编写 docker-compose.yml 编排配置 #

创建工作目录并在 /opt/gitea/docker-compose.yml 中写入：

yaml
version: "3.8"

networks:
  gitea_net:
    driver: bridge

services:
  # MariaDB 数据库容器
  db:
    image: mariadb:10.11
    container_name: gitea_db
    restart: always
    environment:
      - MYSQL_ROOT_PASSWORD=Gitea_Root_P@ss_2026
      - MYSQL_DATABASE=gitea
      - MYSQL_USER=gitea
      - MYSQL_PASSWORD=Gitea_Db_P@ss_2026
    volumes:
      - ./mysql:/var/lib/mysql
    networks:
      - gitea_net

  # Gitea 主服务容器
  gitea:
    image: gitea/gitea:latest
    container_name: gitea_server
    restart: always
    environment:
      - USER_UID=1000
      - USER_GID=1000
      - GITEA__database__DB_TYPE=mysql
      - GITEA__database__HOST=db:3306
      - GITEA__database__NAME=gitea
      - GITEA__database__USER=gitea
      - GITEA__database__PASSWD=Gitea_Db_P@ss_2026
    volumes:
      - ./data:/data
      - /etc/timezone:/etc/timezone:ro
      - /etc/localtime:/etc/localtime:ro
    ports:
      - "127.0.0.1:3000:3000"   # Web UI 仅暴露给本地 Nginx 反代
      - "2222:22"              # SSH 独立映射为 2222 端口
    depends_on:
      - db
    networks:
      - gitea_net

4.2 启动容器与初始运行 #

bash
sudo mkdir -p /opt/gitea
cd /opt/gitea
sudo docker compose up -d

# 查看运行状态
sudo docker compose ps

4.3 配置 Nginx 反向代理与 SSL 证书 #

在 /etc/nginx/sites-available/git.example.com.conf 创建反代配置：

nginx
server {
    listen 80;
    server_name git.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name git.example.com;

    ssl_certificate /etc/letsencrypt/live/git.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/git.example.com/privkey.pem;

    # 客户端上传大文件限制调优 (支持大包与大文件推送)
    client_max_body_size 512M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 调大超时，防止大仓库推送中断
        proxy_read_timeout 600s;
        proxy_connect_timeout 600s;
    }
}

启用站点并生效：

bash
sudo ln -s /etc/nginx/sites-available/git.example.com.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

5. 大文件存储 Git LFS（Large File Storage）配置 #

默认情况下，将大型音视频、模型权重或设计素材（PSD/Zip）直接提交到 Git 仓库会导致仓库体积急剧膨胀，团队成员每次拉取都极度缓慢。Git LFS 将大文件保存为文本指针，实体文件单独存放在对象存储或服务器磁盘。

5.1 客户端配置与使用 Git LFS #

bash
# 1. 客户端安装 Git LFS
git lfs install

# 2. 指定需要通过 LFS 追踪的大文件格式（如 .zip, .mp4, .onnx, .bin）
git lfs track "*.zip"
git lfs track "*.onnx"
git lfs track "*.mp4"

# 3. 提交 .gitattributes 配置文件
git add .gitattributes
git commit -m "Configure Git LFS tracking"

# 4. 正常添加大文件并推送
git add big_model.onnx
git commit -m "Add large model file via LFS"
git push origin main

6. Git Server 仓库维护、垃圾回收与瘦身 #

长期运行的 Git 服务器会积累大量松散对象（Loose Objects）与历史废弃数据，定期维护能够大幅节省服务器磁盘与网络带宽。

6.1 仓库垃圾回收与对象打包（git gc） #

在服务器裸仓库目录执行：

bash
cd /srv/git/my-project.git

# 1. 检查仓库完整性与损坏对象
git fsck --full

# 2. 深度清理无引用的垃圾对象并压缩打包（瘦身效果立竿见影）
git gc --aggressive --prune=now

# 3. 重新计算并建立 commit-graph 索引以提升克隆速度
git commit-graph write --reachable

6.2 彻底清理误提交的大文件（git-filter-repo） #

若有成员不小心将 2GB 的数据库备份或私人视频提交进了 Git 历史，普通的 git rm 无法删除历史版本中的实体。可在管理员客户端使用现代清理利器 git-filter-repo：

bash
# 1. 安装工具
pip install git-filter-repo

# 2. 从全新干净克隆的镜像中删除指定大文件
git clone --mirror git@git.example.com:user/my-project.git
cd my-project.git

# 3. 彻底从所有提交历史中抹除指定路径的大文件
git-filter-repo --invert-paths --path "path/to/huge_backup.dump"

# 4. 强制推送回自建服务器覆盖
git push --force --mirror origin

7. 自动化灾备与全量冷热备份脚本 #

编写自动备份脚本 /root/scripts/backup_gitserver.sh：

bash
#!/usr/bin/env bash
# ==========================================================
# 自建 Git Server 自动化备份脚本 (仓库数据 + 数据库)
# ==========================================================

BACKUP_DEST="/data/backups/git"
DATE=$(date +"%Y%m%d_%H%M%S")
GIT_REPOS_DIR="/srv/git"
GITEA_DATA_DIR="/opt/gitea"

mkdir -p ${BACKUP_DEST}

echo "[${DATE}] 🚀 开始备份 Git Server..."

# 1. 备份原生裸仓库目录
if [ -d "$GIT_REPOS_DIR" ]; then
    tar -zcf ${BACKUP_DEST}/native_repos_${DATE}.tar.gz -C /srv git
    echo "✅ 原生裸仓库已打包。"
fi

# 2. 若运行 Gitea 容器，利用 Gitea 自带工具创建标准冷备包
if [ -d "$GITEA_DATA_DIR" ]; then
    cd $GITEA_DATA_DIR
    sudo docker exec -u 1000 -i gitea_server /app/gitea/gitea dump -c /data/gitea/conf/app.ini -f /data/gitea-dump-${DATE}.zip
    mv ./data/gitea-dump-${DATE}.zip ${BACKUP_DEST}/
    echo "✅ Gitea 全站备份包已生成。"
fi

# 3. 保留最近 30 天的备份，自动清理过期文件
find ${BACKUP_DEST} -type f -name "*${DATE}*" -mtime +30 -exec rm -f {} \;

echo "[${DATE}] 🏆 Git Server 备份流程圆满完成！"

加入 Crontab 每天凌晨 2:30 执行：

bash
sudo chmod +x /root/scripts/backup_gitserver.sh
(crontab -l 2>/dev/null; echo "30 2 * * * /root/scripts/backup_gitserver.sh >> /var/log/git_backup.log 2>&1") | crontab -

9. 进阶实战：Gitea Actions 轻量级 CI/CD 流水线 #

Gitea 内置了兼容 GitHub Actions 语法规范的 Gitea Actions。只需部署一个轻量级执行器 act_runner，即可在自建平台跑自动化编译、测试与镜像打包。

9.1 获取 Runner 注册 Token #

  1. 登录 Gitea 管理员后台 -> 管理面板 > Actions > 执行器 (Runners)。
  2. 点击「创建新的 Runner」，复制生成的 Registration Token。

9.2 使用 Docker 启动 act_runner #

在 /opt/gitea/docker-compose.yml 中追加 runner 服务：

yaml
  runner:
    image: gitea/act_runner:latest
    container_name: gitea_runner
    restart: always
    environment:
      - GITEA_INSTANCE_URL=http://gitea:3000
      - GITEA_RUNNER_REGISTRATION_TOKEN=你的注册Token
      - GITEA_RUNNER_NAME=local_docker_runner
      - GITEA_RUNNER_LABELS=ubuntu-latest:docker://node:20-bullseye,ubuntu-22.04:docker://node:20-bullseye
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - ./runner_data:/data
    depends_on:
      - gitea
    networks:
      - gitea_net

9.3 编写项目流水线配置（.gitea/workflows/build.yml） #

在项目代码根目录下创建 .gitea/workflows/build.yml：

yaml
name: Project Build & Test CI

on:
  push:
    branches:
      - main
      - master

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'

      - name: Install Dependencies & Run Tests
        run: |
          npm ci
          npm test
          npm run build

10. Webhook 机器人通知与协同安全审计 #

10.1 飞书 / 钉钉 / 企业微信群通知集成 #

通过 Gitea Webhook，可以在代码提交、Pull Request 合并或 Release 发布时自动推送消息到即时通讯群组：

  1. 进入仓库 设置 > Web 钩子 > 添加 Web 钩子（选择钉钉 / 飞书 / 企微或通用 Discord/Slack）。
  2. 填写机器人的 Webhook URL 地址。
  3. 勾选触发事件（如「推送事件」、「合并请求事件」）。
  4. 点击「测试推送」，群机器人即可秒级收到格式化的提交卡片。

10.2 SSH 访问日志安全审计与异常行为告警 #

对于原生 Git Server，代码交互全量记录在 /var/log/auth.log（Debian/Ubuntu）或 /var/log/secure（CentOS）中：

bash
# 1. 实时监控来自 git 用户的 SSH 认证与操作
sudo tail -f /var/log/auth.log | grep sshd | grep git

# 2. 统计近期高频克隆/推送来源 IP
sudo grep 'Accepted publickey for git' /var/log/auth.log | awk '{print $11}' | sort | uniq -c | sort -nr

11. 高频故障排查手册 #

故障现象 诱因剖析 快速解决对策
Permission denied (publickey) 1. 客户端未加载私钥
2. 服务器端 ~git/.ssh/authorized_keys 权限不是 600
3. git 用户未被加入 SSH 允许列表		 执行 ssh -v git@server-ip 查看握手细节；修复服务器权限 chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
fatal: protocol error: bad line length character: This 登录用户未配置为 git-shell，而在 .bashrc 中输出了欢迎文本干扰了 Git 协议传输 将用户的 Shell 修改为标准的 git-shell，移除所有登录回显提示
error: RPC failed; HTTP 413 curl 22 通过 HTTP/HTTPS 推送超过了 Nginx 的 client_max_body_size 限制 在 Nginx 配置文件中将 client_max_body_size 增加至 512M 或更大，并调大 Git 客户端 git config --global http.postBuffer 524288000
