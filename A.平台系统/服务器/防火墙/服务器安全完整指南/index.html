服务器安全完整指南

服务器暴露在公网环境下，面临着端口扫描、暴力破解、流量滥用等多种安全威胁。本文整合了防火墙配置、入侵防御和身份认证三大核心安全手段，帮助你构建多层次的服务器安全防线。

一、UFW 防火墙配置 #

UFW (Uncomplicated Firewall) 是 Linux 上轻量级的防火墙配置工具，简化了 iptables 的复杂操作。

基础命令 #

状态查看 #

bash
# 查看防火墙状态和规则
sudo ufw status

# 详细模式（显示默认策略和日志级别）
sudo ufw status verbose

# 带编号显示（用于删除规则）
sudo ufw status numbered

启用与禁用 #

⚠警告

启用前请确保已允许 SSH (22 端口) 连接，否则可能会断开服务器连接！

bash
# 启用防火墙
sudo ufw enable

# 禁用防火墙
sudo ufw disable

# 重置所有规则（恢复默认设置）
sudo ufw reset

端口与服务管理 #

允许入站连接 #

bash
# 允许特定端口 (TCP/UDP)
sudo ufw allow 22
sudo ufw allow 80/tcp
sudo ufw allow 443

# 允许特定服务名称
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https

# 允许特定 IP 访问所有端口
sudo ufw allow from 192.168.1.100

# 允许特定 IP 访问特定端口
sudo ufw allow from 192.168.1.100 to any port 22

拒绝入站连接 #

bash
# 拒绝连接请求（对方无响应）
sudo ufw deny 80
sudo ufw deny from 192.168.1.200

# 拒绝并向对方发送"拒绝"响应
sudo ufw reject 22

删除规则 #

bash
# 1. 查看带编号的规则
sudo ufw status numbered

# 2. 按编号删除（例如删除第 3 条规则）
sudo ufw delete 3

# 也可以直接删除规则定义
sudo ufw delete allow 80

高级配置 #

默认策略 #

建议设置为：拒绝所有入站，允许所有出站

bash
sudo ufw default deny incoming
sudo ufw default allow outgoing

限制连接频率 #

对于 SSH 等关键服务，使用 limit 限制连接频率（30 秒内尝试连接 6 次即拒绝）：

bash
sudo ufw limit ssh
# 或者
sudo ufw limit 22/tcp

网段控制 #

bash
# 允许子网段访问特定端口
sudo ufw allow from 192.168.1.0/24 to any port 8080

日志管理 #

bash
# 开启/关闭日志记录
sudo ufw logging on
sudo ufw logging off

# 日志位置：/var/log/ufw.log

常见场景配置 #

Web 服务器 #

bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw limit ssh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

数据库服务器（仅允许特定内网 IP） #

bash
# 允许 Web 服务器 (10.0.0.5) 访问 MySQL (3306)
sudo ufw allow from 10.0.0.5 to any port 3306

SSH 白名单方案 #

适用于固定 IP 场景（公司、家庭）：

bash
# 移除原有的 limit 规则
sudo ufw delete limit 22/tcp

# 添加白名单
sudo ufw allow from YOUR_IP_ADDRESS to any port 22 proto tcp

# 拒绝其他 SSH 连接
sudo ufw deny 22/tcp

# 验证规则
sudo ufw status numbered

被锁定后的恢复 #

如果因限速规则被锁在外面，需要通过控制台/KVM 访问服务器：

bash
sudo ufw reset
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw enable

二、Fail2ban 入侵防御 #

Fail2ban 可以自动监控日志文件，发现暴力破解等恶意行为后自动封禁 IP，是防御 SSH 爆破的最实用方案。

安装与启用 #

bash
# 安装
sudo apt update
sudo apt install fail2ban

# 启用自启动
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# 查看状态
sudo systemctl status fail2ban

配置 #

创建本地配置文件 #

bash
# 复制默认配置（不要直接修改 jail.conf）
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local

# 编辑配置
sudo nano /etc/fail2ban/jail.local

核心配置项 #

在 [DEFAULT] 部分修改：

ini
[DEFAULT]
bantime = 3600
findtime = 600
maxretry = 3

[sshd]
enabled = true
port = ssh
filter = sshd
logpath = /var/log/auth.log

参数说明：

  • bantime：IP 被封禁的时长，3600 秒
  • findtime：在此时间窗口内统计失败次数，600 秒
  • maxretry：达到此次数后触发封禁，3 次

常用命令 #

bash
# 查看 SSH 服务的封禁状态
sudo fail2ban-client status sshd

# 手动解除 IP 封禁
sudo fail2ban-client set sshd unbanip YOUR_IP

# 查看 fail2ban 日志
sudo tail -f /var/log/fail2ban.log

故障排查 #

如果 fail2ban 无法启动，使用以下命令查看精确错误原因：

bash
# 前台启动，显示详细错误
fail2ban-client -x start

# 检查配置文件语法
fail2ban-client -t

三、SSH 密钥认证 #

密钥认证是最安全的 SSH 认证方式，可以彻底消除密码爆破威胁。

生成密钥对 #

在本地机器上执行：

bash
# 生成 RSA 4096 位密钥
ssh-keygen -t rsa -b 4096 -f ~/.ssh/id_rsa

部署公钥到服务器 #

bash
# 方法一：使用 ssh-copy-id（推荐）
ssh-copy-id -i ~/.ssh/id_rsa.pub user@server

# 方法二：手动添加
# 在服务器上执行
mkdir -p ~/.ssh
chmod 700 ~/.ssh
# 将本地 ~/.ssh/id_rsa.pub 的内容追加到服务器的 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

配置 SSH 服务器 #

bash
sudo nano /etc/ssh/sshd_config

修改以下配置：

bash
PasswordAuthentication no       # 禁用密码认证
PubkeyAuthentication yes        # 启用密钥认证
PermitRootLogin no              # 禁用 root 登录
Port 2222                       # 改为非标准端口（可选）

保存后重启 SSH：

bash
sudo systemctl restart sshd
⛔危险

禁用密码认证前，请确保密钥登录已测试成功，否则可能永久丢失服务器访问权限！

SSH 常见故障排查 #

修改 SSH 配置后无法连接是常见问题，以下是按可能性排序的排查思路。

症状判断 #

  • Permission denied (publickey)：密钥不匹配或未正确部署
  • Connection closed：配置错误或被安全机制拦截

常见原因 #

1. 配置文件语法或逻辑错误

如果使用 root 用户登录，注意 PermitRootLogin 的设置：

  • PermitRootLogin no：完全禁止 root 登录（即使有密钥也不行）
  • PermitRootLogin prohibit-password：禁止密码，允许密钥（推荐）

2. 权限过宽触发 SSH 自我保护

SSH 对密钥文件权限要求严格，权限过宽（如 777）会导致拒绝读取：

bash
# 正确的权限设置
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chown -R $(whoami):$(whoami) ~/.ssh

3. Fail2ban 误封

测试配置过程中多次失败可能触发 Fail2ban 封禁，参考前文"Fail2ban 入侵防御"章节解封。

VNC 控制台救援 #

当 SSH 完全无法连接时，需要通过 VPS 提供商的 VNC/Console 功能介入：

  1. 登录 VPS 控制台：在提供商网页后台找到 VNC 或 Console 入口
  2. 检查 SSH 服务状态：
bash
systemctl status sshd
  1. 测试配置文件语法：
bash
sshd -t  # 无输出表示语法正确
  1. 修复配置并重启：
bash
nano /etc/ssh/sshd_config  # 根据 sshd -t 输出修复错误
systemctl restart sshd

四、监控与日志分析 #

实时监控 #

bash
# 实时查看 SSH 登录尝试
sudo tail -f /var/log/auth.log | grep sshd

# 统计失败登录次数
sudo grep "Failed password" /var/log/auth.log | wc -l

# 查看最近尝试的 IP（按次数排序）
sudo grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn

流量监控 #

bash
# 安装 vnstat
apt install vnstat

# 查看流量统计
vnstat -d  # 按天
vnstat -h  # 按小时

网络连接分析 #

bash
# 查看当前所有网络连接
netstat -antp
# 或
ss -antp

# 统计特定端口的连接 IP
netstat -antp | grep 7890 | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head -20

入侵检查 #

bash
# 检查可疑用户
cat /etc/passwd

# 检查计划任务
crontab -l
cat /etc/crontab

# 检查最近登录记录
last
lastb

# 检查可疑进程
ps aux
ps aux --sort=-%cpu | head -10

五、实战案例：Clash 代理暴露公网 #

这是一个真实的安全事故案例，记录了因代理服务配置不当导致服务器被滥用的排查过程。

问题现象 #

  • 出站流量从每天几百 MB 暴增到几十 GB
  • CPU 占用持续 100%
  • 其他服务响应变慢甚至超时

根因分析 #

检查 Clash 配置文件发现：

yaml
port: 7890
socks-port: 7891
allow-lan: true              # 问题所在！
external-controller: '0.0.0.0:9090'  # 管理接口暴露

问题出在：

  1. allow-lan: true：服务器有公网 IP 时，"局域网"变成了整个互联网
  2. 管理接口绑定 0.0.0.0：外网可直接访问控制面板
  3. 防火墙/安全组放行了代理端口

解决方案 #

修改 Clash 配置 #

yaml
port: 7890
socks-port: 7891
allow-lan: false              # 关闭局域网访问
external-controller: '127.0.0.1:9090'  # 只绑定本地

防火墙限制 #

bash
# 使用 iptables 只允许本地访问
iptables -A INPUT -p tcp --dport 7890 -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p tcp --dport 7890 -j DROP
iptables -A INPUT -p tcp --dport 7891 -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p tcp --dport 7891 -j DROP
iptables -A INPUT -p tcp --dport 9090 -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p tcp --dport 9090 -j DROP

# 保存规则
iptables-save > /etc/iptables.rules   # Debian/Ubuntu
service iptables save                  # CentOS

云安全组 #

在云服务商控制台确保以下端口不对公网开放：

  • 7890（HTTP 代理端口）
  • 7891（SOCKS5 代理端口）
  • 9090（管理接口端口）

经验教训 #

  1. 服务器上跑代理服务要格外小心：确认只监听本地地址
  2. 防火墙配置要精细化：不要放行大范围端口
  3. 定期检查服务器状态：监控流量、CPU、连接数
  4. 安全组是第一道防线：云服务器的安全组规则要配置好

六、安全加固优先级 #

根据实际情况，建议按以下优先级实施：

阶段 时间 行动项
立即 今天 启用 UFW 默认拒绝策略，只开放必要端口
短期 本周 安装并配置 Fail2ban 自动防护
中期 本月 部署 SSH 密钥认证，禁用密码登录
持续 常态 定期更新系统补丁，监控日志，考虑 VPN 访问 SSH
