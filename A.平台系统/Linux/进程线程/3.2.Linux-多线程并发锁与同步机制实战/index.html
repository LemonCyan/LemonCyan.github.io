Linux 多线程并发锁与同步机制实战 #

多线程最大的优势是共享进程的地址空间，这使得数据传递极其简单，指针随手一扔就能传数据。但这也带来了巨大的安全挑战：多线程并发竞态（Race Condition）。当多个线程在无保护状态下同时读写同一份共享数据时，就会引发脏数据和不可预期的运行结果。本文咱们就用实战代码复现并发 Bug，然后手撕 Linux 的并发控制锁机制。

一、 进程同步与临界区互斥的经典理论 #

在深入具体的 Linux 并发编程 API 之前，我们有必要先建立起操作系统关于“进程同步”的底层学术理论体系。

1. 临界资源与代码的四个执行区 #

在并发系统中，虽然多数资源可以共享，但有些资源一次只容许一个进程/线程使用，这类资源被称为临界资源（Critical Resource）（如打印机、共享的全局队列等）。 为了安全、互斥地访问临界资源，进程在逻辑上访问临界资源的代码被划分为四个区域：

  1. 进入区（Entry Section）：在进入临界区之前，进程要检查是否可以安全进入。若能进入，则设置“正在访问”标志（锁上锁），阻止其他进程进入。
  2. 临界区（Critical Section）：进程中真正执行访问临界资源、修改共享数据的代码段。
  3. 退出区（Exit Section）：临界区执行完毕后，负责清除占用标志（锁解锁），唤醒其他等待的进程。
  4. 剩余区（Remainder Section）：与访问临界资源无关的其他代码段。
c
do {
    // 进入区 (加锁/检查)
    entry_section();
    
    // 临界区 (操作共享资源)
    critical_section();
    
    // 退出区 (解锁/清除标志)
    exit_section();
    
    // 剩余区 (其他无关代码)
    remainder_section();
} while (true);

2. 临界区互斥的硬件实现方法 #

在底层，为了防止上下文切换打断临界区的原子操作，硬件层面提供了两种最基本的低级互斥解法：

① 中断屏蔽方法 #

在进程准备进入临界区前，执行关中断指令（Disable Interrupts）；退出临界区后，再执行开中断指令（Enable Interrupts）。

  • 优缺点：极其简单。但由于关中断会屏蔽一切硬件事件（如磁盘读写、时钟中断），如果在临界区发生死循环或耗时任务，系统会彻底卡死。因此，关中断仅供操作系统内核级操作使用，用户态程序绝不能使用。

② 硬件原子指令法 #

现代 CPU 提供了特殊的硬件原语指令，它们能保证“读取-修改-写回”内存的操作是一口气原子完成的，不受任何多核或上下文切换打断。最著名的指令是 TestAndSet 和 Swap。

  • TestAndSet (TS / TSL) 指令： 该指令原子地读取一个锁标志的值，并将该标志强行设为 true，最后返回旧值。其 C 语言逻辑模拟如下：

    c
    bool TestAndSet(bool *lock) {
    bool old = *lock; // 读取旧锁值
    *lock = true;     // 强行设为占有状态
    return old;       // 返回旧锁状态
}

    利用 TS 指令实现互斥的忙等自旋锁逻辑：

    c
    while (TestAndSet(&lock)) {
    // 忙等 (自旋)
}
// 进入临界区...
lock = false; // 退出区解锁

  • Swap (XCHG) 指令： 原子地交换两个内存变量的值。其 C 语言逻辑模拟如下：

    c
    void Swap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}

    使用 Swap 指令实现互斥：

    c
    bool key = true;
while (key == true) {
    Swap(&lock, &key); // 交换 lock 和 key 的值
}
// 进入临界区...
lock = false; // 解锁

3. 记录型信号量（Record Semaphore）的物理结构 #

为了解决上述硬件指令“忙等自旋”白白浪费 CPU 时间的缺陷，UNIX 引入了记录型信号量（Record Semaphore）。它不仅有一个资源计数器，还挂载了一个等待进程队列。当资源不足时，进程会主动放弃 CPU 进入阻塞队列，避免忙等。 其结构定义如下：

c
typedef struct {
    int value;           // 剩余可用资源计数器
    struct process *L;   // 挂起在该信号量上的进程等待队列首指针
} semaphore;
  • P 操作 (wait / down)：
    c
    void wait(semaphore S) {
    S.value--; // 申请一个资源
    if (S.value < 0) {
        // 资源不足，将当前进程放入等待队列 S.L
        // 调用 block() 挂起当前进程，主动让出 CPU
        block(S.L);
    }
}
  • V 操作 (signal / up)：
    c
    void signal(semaphore S) {
    S.value++; // 释放一个资源
    if (S.value <= 0) {
        // 说明队列里还有被挂起的进程
        // 调用 wakeup() 从等待队列 S.L 中唤醒一个进程进入就绪队列
        wakeup(S.L);
    }
}

4. 管程（Monitor）的概念 #

由于手写信号量的 P/V 操作过于繁琐，且极易因为漏写 V 操作或者写错顺序导致死锁，计算机科学家发明了管程（Monitor）。

  • 定义：管程是一个特殊的软件模块，它把共享资源的数据结构以及**对该数据结构进行操作的一组过程（函数）**封装在一起。
  • 核心特性：
    1. 管程内部的共享数据只能通过管程内部的过程访问。
    2. 管程保证互斥是编译器自动处理的：同一时刻，只允许一个进程/线程在管程内部执行某个过程。如果另一个线程企图调用管程函数，它会被编译器自动生成的互斥代码阻断在管程外等待。
    3. 通过引入条件变量（Condition Variable）来实现管程内部的同步等待。

二、 经典 Bug 复现：为什么要用并发锁？ #

在多核 CPU 系统中，为了让多个线程看起来是在并发执行，操作系统会在各个就绪线程之间频繁进行“时间片轮转切换”。如果我们的代码对共享资源的访问不是“原子的”，就会引发非预期的竞态条件。

下面是一个经典的“多窗口售票系统”代码。我们不加任何同步锁保护，并调用 usleep() 强行触发线程上下文切换：

☠️ 产生竞态的售票系统（有 Bug 版） #

c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

int tickets = 5; // 共享资源：还剩 5 张票

void* sell_tickets(void* arg) {
    char* name = (char*)arg;
    while (1) {
        // 第一步：检查共享资源是否符合条件
        if (tickets > 0) {
            // 模拟复杂的售票业务处理，强行触发时间片轮转切换
            usleep(100000); // 100 毫秒
            
            // 第二步：修改共享资源
            tickets--;
            printf("[%s] Sells ticket successfully. Remaining: %d\n", name, tickets);
        } else {
            // 没有余票，直接退出
            break;
        }
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    
    // 创建两个子线程模拟两个售票窗口
    pthread_create(&t1, NULL, sell_tickets, "Window_A");
    pthread_create(&t2, NULL, sell_tickets, "Window_B");

    // 等待子线程执行完毕
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}

📊 运行结果： #

text
[Window_A] Sells ticket successfully. Remaining: 4
[Window_B] Sells ticket successfully. Remaining: 3
[Window_A] Sells ticket successfully. Remaining: 2
[Window_B] Sells ticket successfully. Remaining: 1
[Window_A] Sells ticket successfully. Remaining: 0
[Window_B] Sells ticket successfully. Remaining: -1   <-- 负数！超卖 Bug 现形！
  • Bug 原因深度分析： 当 tickets 值为 1 时，Window_A 进入 if (tickets > 0) 判断，条件成立，然后执行到 usleep(100000) 休眠让出 CPU。 此时发生线程切换，Window_B 开始执行，此时 tickets 依然为 1。Window_B 也成功通过了 if 判断并开始休眠。 随后，两个线程被唤醒，开始顺序执行下面的 tickets-- 操作。Window_A 扣减后 tickets 为 0，而随后 Window_B 扣减后 tickets 变成了 -1。这在实际的售票系统或减库存中，就是灾难性的“超卖”现象。
  • 根本解决方案：必须保证从“检查资源”到“修改资源”这一整个临界区是原子操作，同一时间只能有一个线程在临界区内活动。

三、 互斥锁 (Mutex)：实现独占与排他 #

互斥锁（Mutex）是最基础的同步机制。它只有两个状态：锁定（Locked）和未锁定（Unlocked）。一旦一个线程拿到了互斥锁，其他试图获取锁的线程就会被阻塞挂起。

🛠️ 常用 API #

  • 静态初始化：pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
  • 动态初始化：int pthread_mutex_init(pthread_mutex_t *mutex, const pthread_mutexattr_t *attr);
  • 加锁（阻塞）：int pthread_mutex_lock(pthread_mutex_t *mutex);
  • 加锁（非阻塞）：int pthread_mutex_trylock(pthread_mutex_t *mutex); —— 如果锁已被他人占用，立即返回 EBUSY，不挂起线程。
  • 解锁：int pthread_mutex_unlock(pthread_mutex_t *mutex);
  • 销毁锁：int pthread_mutex_destroy(pthread_mutex_t *mutex);

🛡️ 使用互斥锁修好售票系统： #

c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

int tickets = 5;
pthread_mutex_t lock; // 声明全局互斥锁

void* sell_tickets(void* arg) {
    char* name = (char*)arg;
    while (1) {
        pthread_mutex_lock(&lock); // 1. 进入临界区前加锁
        
        if (tickets > 0) {
            usleep(100000);
            tickets--;
            printf("[%s] Sells ticket successfully. Remaining: %d\n", name, tickets);
            
            pthread_mutex_unlock(&lock); // 2. 操作完毕及时解锁
        } else {
            pthread_mutex_unlock(&lock); // 3. 退出分支也要解锁，否则会产生永久死锁！
            break;
        }
    }
    return NULL;
}

int main() {
    pthread_mutex_init(&lock, NULL); // 初始化锁
    pthread_t t1, t2;
    
    pthread_create(&t1, NULL, sell_tickets, "Window_A");
    pthread_create(&t2, NULL, sell_tickets, "Window_B");

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    
    pthread_mutex_destroy(&lock); // 销毁锁
    return 0;
}

四、 死锁（Deadlock）的产生、判定与规避策略 #

当线程在执行过程中，因争夺资源而造成的一种互相等待的现象，若无外力作用，它们都将无法推进下去，这就是死锁。

1. 产生死锁的 4 个必要条件： #

死锁的发生必须同时满足以下 4 个物理条件，破坏其中任意一个即可预防死锁：

  1. 互斥条件：一个资源在同一时刻只能被一个线程独占占用。
  2. 请求与保持条件：一个线程因请求新资源而发生阻塞时，对已获得的资源保持占用不放。
  3. 不剥夺条件：线程已获得的资源在未使用完之前，不能被其他线程强行剥夺，只能由占有线程自己释放。
  4. 循环等待条件：发生死锁时，必然存在一个线程-资源的环形链（如：线程 A 占有锁 1 等待锁 2，线程 B 占有锁 2 等待锁 1）。

2. 死锁的规避与处理策略 #

① 静态死锁预防（Prevention） #

在程序运行前，通过严格的静态规则限制，破坏产生死锁的必要条件：

  • 破坏请求与保持条件：采用“一次性分配法”，要求线程在启动时必须一次性申请完全部所需的资源，否则不予运行。缺点是资源利用率极低。
  • 破坏循环等待条件：采用“资源顺序分配法”，给系统所有资源统一编号。规定线程必须严格按照编号从小到大的顺序去申请资源（例如必须先锁 1 锁，才能锁 2 锁）。这能彻底规避环形链的产生。

② 动态死锁避免（Avoidance）：银行家算法（Banker's Algorithm） #

在资源动态分配过程中，系统会首先通过算法模拟分配，检查系统是否会进入“不安全状态”。如果安全才予以实际分配，否则拒绝分配。

  • 数据结构定义：

    • Available[m]：长为 $m$ 的数组，表示当前 $m$ 种资源的可用物理实例数。
    • Max[n][m]：n×m 矩阵，定义每个进程对每种资源的最大需求量。
    • Allocation[n][m]：n×m 矩阵，定义当前已分配给每个进程的资源数。
    • Need[n][m]：n×m 矩阵，定义每个进程还需要的资源数（$\text{Need} = \text{Max} - \text{Allocation}$）。

  • 安全性检查算法（Safety Algorithm）：

    1. 设置临时工作向量 Work=Available，以及进程完成标志数组 Finish[n]=false。
    2. 在进程集合中寻找一个满足以下条件的进程 Pi​：
      • Finish[i] == false
      • Need[i] <= Work（当前可用资源能满足其剩余最大需求） 如果找到，执行步骤 3；否则执行步骤 4。
    3. 假设进程 Pi​ 顺利运行完毕并释放资源，更新工作向量与状态： $$\text{Work} = \text{Work} + \text{Allocation}[i]$$ $Finish[i]=true$ 返回步骤 2 继续检索下一个进程。
    4. 如果所有进程的 Finish 标志都成功变为了 true，则证明系统处于安全状态，模拟出的分配序列即为安全序列。否则，说明系统已进入不安全状态，容易诱发死锁，必须拒绝当前分配请求。

③ 死锁检测与资源分配图简化（Detection） #

如果在程序运行中没有进行规避，可以通过**资源分配图（Resource Allocation Graph）**进行在线检测。

  • 结构：圆圈代表进程，方框代表资源。有向边“资源 → 进程”代表已分配；“进程 → 资源”代表正在申请。
  • 图的简化法：
    1. 找出一个非孤立的、且当前申请资源数小于对应资源空闲数的进程节点。
    2. 由于该进程可以顺利拿到资源并运行完，我们将其释放的边全部抹去（简化节点）。
    3. 重复此过程。如果最后能把图中所有的边全部消去，说明图是可完全简化的，此时系统无死锁。
    4. 如果最后图无法被完全简化（留有无法消除的环和边），则图不可简化，说明系统发生了死锁。

④ 死锁恢复技术（Recovery） #

一旦检测到系统陷入死锁，必须通过外力手段强制解除：

  • 资源剥夺法：挂起某些死锁进程，强行抢占它们占有的资源分配给其他死锁进程。
  • 进程撤销法：强制终止一个或多个死锁进程（通常优先杀死消耗资源少、优先级低的进程），直到死锁环路断开。
  • 进程回退法：利用设置的检查点（Checkpoint）将死锁进程回退到之前的安全状态，并让其释放资源。

3. Pthread 死锁防范规避实战： #

  • 保持锁的加锁顺序一致：所有线程在需要获取多个锁时，必须按照完全相同的顺序进行加锁。
  • 使用 pthread_mutex_trylock：如果拿不到第二个锁，主动释放已占有的第一个锁，避免死等。

🎯 高阶用法：双锁交替（Ping-Pong）同步机制 #

我们还可以利用两个互斥锁在不同线程中交替解锁，来实现两个线程严格的交替运行。

c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_mutex_t lock_a = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t lock_b = PTHREAD_MUTEX_INITIALIZER;

void* sub_thread(void* arg) {
    while (1) {
        // 子线程首先加锁 B。因为主线程在初始化时已经把 B 锁了，子线程会在这里挂起等待
        pthread_mutex_lock(&lock_b);
        printf("[Sub Thread] Ping-Pong! I am executing...\n");
        sleep(1);
        // 子线程执行完毕，解开 A 锁，允许主线程继续运行
        pthread_mutex_unlock(&lock_a);
    }
    return NULL;
}

int main() {
    // 1. 初始化时，主线程先强行把 B 锁上，不让子线程先跑
    pthread_mutex_lock(&lock_b);

    pthread_t tid;
    pthread_create(&tid, NULL, sub_thread, NULL);

    for (int i = 0; i < 3; i++) {
        // 2. 主线程把 A 锁上，做主线程的业务
        pthread_mutex_lock(&lock_a);
        printf("[Main Thread] Ding-Dong! Main thread is executing...\n");
        sleep(1);
        // 3. 主线程执行完后，解开 B 锁，唤醒阻塞在 B 锁上的子线程
        pthread_mutex_unlock(&lock_b);
    }

    pthread_cancel(tid);
    pthread_join(tid, NULL);
    return 0;
}

五、 条件变量 (Condition Variable)：等待与唤醒机制 #

当线程需要等待某个特定的共享状态（例如：仓库不为空、队列有新任务）时，使用互斥锁不断进行轮询加锁会极度消耗 CPU 资源。条件变量允许线程在条件不满足时彻底挂起休眠，一旦条件具备，其他线程可以通过发信号的方式精确唤醒正在休眠的线程。条件变量必须与互斥锁配合使用！

🛠️ 常用 API #

  • 等待条件：int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
    • 核心动作（必背）：
      1. 自动解锁传入的 mutex。
      2. 让线程进入休眠等待（这两步为原子操作，防止发生信号丢失）。
      3. 被唤醒时，在 pthread_cond_wait 返回前，自动重新加锁 mutex。
  • 单点唤醒：int pthread_cond_signal(pthread_cond_t *cond); —— 至少唤醒一个正在等待的线程。
  • 广播唤醒：int pthread_cond_broadcast(pthread_cond_t *cond); —— 唤醒所有正在等待该条件的线程。

📦 经典“生产者-消费者”模型实战： #

c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
int storage = 0; // 共享仓库容量

void* consumer(void* arg) {
    while (1) {
        pthread_mutex_lock(&mtx);
        
        // 避坑：用 while 代替 if 来判断条件，防止虚假唤醒 (Spurious Wakeup)
        while (storage == 0) {
            printf("[Consumer] Storage empty, going to sleep...\n");
            pthread_cond_wait(&cond, &mtx); // 解锁挂起，唤醒时自动重锁
        }
        
        storage--;
        printf("[Consumer] Consumed 1 item. Left: %d\n", storage);
        
        pthread_mutex_unlock(&mtx);
        sleep(2); // 消费慢一点
    }
    return NULL;
}

void* producer(void* arg) {
    while (1) {
        sleep(1); // 生产快一点
        pthread_mutex_lock(&mtx);
        
        storage++;
        printf("[Producer] Produced 1 item. Current storage: %d\n", storage);
        
        pthread_cond_signal(&cond); // 唤醒一个休眠中的消费者
        
        pthread_mutex_unlock(&mtx);
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, consumer, NULL);
    pthread_create(&t2, NULL, producer, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}

六、 POSIX 信号量 (Semaphore)：资源计数器 #

信号量是一个非负整数计数器。它提供了经典的 PV 原子原语，我们可以利用它来实现线程同步或在有限缓冲区内的生产者-消费者队列。

🛠️ 常用 API #

  • 初始化：int sem_init(sem_t *sem, int pshared, unsigned int value);
    • pshared：0 表示线程间共享，非 0 表示跨进程共享。
    • value：信号量的初始计数器值（可用资源数）。
  • P 操作 (阻塞加锁)：int sem_wait(sem_t *sem); —— 计数器减 1；如果计数器为 0，则线程进入阻塞休眠状态。
  • P 操作 (非阻塞加锁)：int sem_trywait(sem_t *sem); —— 计数器减 1；如果计数器为 0，不阻塞，直接返回错误码 EAGAIN。
  • V 操作 (解锁释放)：int sem_post(sem_t *sem); —— 计数器加 1，并唤醒阻塞等待的线程。
  • 销毁：int sem_destroy(sem_t *sem);

🛡️ 信号量 + 互斥锁实现环形缓冲区队列实战： #

c
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

#define BUFFER_SIZE 5
int buffer[BUFFER_SIZE];
int in = 0;
int out = 0;

sem_t empty; // 表示空缓冲区的数量，初始为 BUFFER_SIZE
sem_t full;  // 表示满缓冲区的数量，初始为 0
pthread_mutex_t mutex_buffer; // 互斥锁保护缓冲区指针

void* sem_producer(void* arg) {
    int item = 1;
    while (1) {
        sleep(1); // 1秒生产一个
        
        sem_wait(&empty); // P(empty) : 等待空缓冲区
        pthread_mutex_lock(&mutex_buffer);
        
        buffer[in] = item;
        printf("[Sem Producer] Produced: %d at index %d\n", item, in);
        in = (in + 1) % BUFFER_SIZE;
        item++;
        
        pthread_mutex_unlock(&mutex_buffer);
        sem_post(&full); // V(full) : 满缓冲区增加
    }
    return NULL;
}

void* sem_consumer(void* arg) {
    while (1) {
        sleep(2); // 2秒消费一个
        
        sem_wait(&full); // P(full) : 等待有数据的缓冲区
        pthread_mutex_lock(&mutex_buffer);
        
        int item = buffer[out];
        printf("[Sem Consumer] Consumed: %d from index %d\n", item, out);
        out = (out + 1) % BUFFER_SIZE;
        
        pthread_mutex_unlock(&mutex_buffer);
        sem_post(&empty); // V(empty) : 空缓冲区增加
    }
    return NULL;
}

int main() {
    sem_init(&empty, 0, BUFFER_SIZE);
    sem_init(&full, 0, 0);
    pthread_mutex_init(&mutex_buffer, NULL);
    
    pthread_t p_tid, c_tid;
    pthread_create(&p_tid, NULL, sem_producer, NULL);
    pthread_create(&c_tid, NULL, sem_consumer, NULL);
    
    pthread_join(p_tid, NULL);
    pthread_join(c_tid, NULL);
    
    sem_destroy(&empty);
    sem_destroy(&full);
    pthread_mutex_destroy(&mutex_buffer);
    return 0;
}

七、 读写锁 (Read-Write Lock)：读共享，写独占 #

读写锁适用于“多读少写”的高并发系统。只要没有线程加写锁，任意数量的读线程都可以同时持有读锁进行读取。

🛠️ 常用 API #

  • 初始化：int pthread_rwlock_init(pthread_rwlock_t *rwlock, const pthread_rwlockattr_t *attr);
  • 加读锁（共享）：int pthread_rwlock_rdlock(pthread_rwlock_t *rwlock);
  • 加写锁（独占）：int pthread_rwlock_wrlock(pthread_rwlock_t *rwlock);
  • 统一解锁：int pthread_rwlock_unlock(pthread_rwlock_t *rwlock);
  • 销毁：int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);

🛡️ 读共享，写独占实战： #

c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;
int shared_resource = 0; // 共享资源

void* reader_func(void* arg) {
    long id = (long)arg;
    while (1) {
        pthread_rwlock_rdlock(&rwlock); // 加读锁（共享）
        printf("[Reader %ld] Read shared resource: %d\n", id, shared_resource);
        pthread_rwlock_unlock(&rwlock);
        usleep(500000); // 0.5 秒读一次
    }
    return NULL;
}

void* writer_func(void* arg) {
    while (1) {
        sleep(2); // 2 秒写一次
        pthread_rwlock_wrlock(&rwlock); // 加写锁（独占）
        shared_resource++;
        printf("[Writer] Updated shared resource to: %d\n", shared_resource);
        pthread_rwlock_unlock(&rwlock);
    }
    return NULL;
}

int main() {
    pthread_t r1, r2, r3, w1;
    
    pthread_create(&r1, NULL, reader_func, (void*)1);
    pthread_create(&r2, NULL, reader_func, (void*)2);
    pthread_create(&r3, NULL, reader_func, (void*)3);
    pthread_create(&w1, NULL, writer_func, NULL);
    
    pthread_join(r1, NULL);
    pthread_join(r2, NULL);
    pthread_join(r3, NULL);
    pthread_join(w1, NULL);
    
    pthread_rwlock_destroy(&rwlock);
    return 0;
}

八、 线程间管道通信 (Pipe for Thread Communication) #

虽然多线程间共享全局内存，通常使用锁同步，但是在一些基于事件驱动（如 Actor 模型）的架构设计中，使用管道作为线程间传递事件的信箱，能够完美复用系统的 select / poll / epoll 异步 I/O 监听机制，实现无锁的事件驱动循环。

  • 工作机制：在进程内部调用 pipe()。子线程持有读端（fd[0]）并阻塞在 read 系统调用上；主线程（或者其他生成事件的线程）向写端（fd[1]）写入命令，子线程随即被内核调度唤醒处理任务。

🛡️ 线程管道通信实战代码： #

c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <pthread.h>
#include <string.h>

int pipe_fd[2];

void* command_receiver(void* arg) {
    char cmd_buf[128];
    printf("[Receiver Thread] Thread started, blocking on pipe read...\n");
    
    while (1) {
        // 如果管道里没数据，子线程会在这里挂起阻塞，不占用 CPU
        int len = read(pipe_fd[0], cmd_buf, sizeof(cmd_buf) - 1);
        if (len <= 0) {
            break;
        }
        cmd_buf[len] = '\0';
        printf("[Receiver Thread] Received command: %s\n", cmd_buf);
        
        if (strcmp(cmd_buf, "exit") == 0) {
            printf("[Receiver Thread] Exit command received, exiting...\n");
            break;
        }
    }
    return NULL;
}

int main() {
    // 1. 创建进程内管道
    if (pipe(pipe_fd) < 0) {
        perror("pipe error");
        return -1;
    }

    pthread_t tid;
    pthread_create(&tid, NULL, command_receiver, NULL);

    char input[64];
    while (1) {
        printf("Enter command for receiver thread (type 'exit' to quit): ");
        fgets(input, sizeof(input), stdin);
        input[strcspn(input, "\n")] = '\0'; // 去掉换行符

        // 2. 主线程写入管道，唤醒子线程
        write(pipe_fd[1], input, strlen(input));

        if (strcmp(input, "exit") == 0) {
            break;
        }
        usleep(100000); // 稍微等待子线程处理并打印完毕
    }

    pthread_join(tid, NULL);
    close(pipe_fd[0]);
    close(pipe_fd[1]);
    printf("[Main Thread] Over.\n");
    return 0;
}
  • 设计权衡：
    • 优点：由于管道读写本身由内核保证线程安全和阻塞唤醒，代码里没有使用任何锁和条件变量，就实现了主子线程的生产消费同步！
    • 缺点：管道缓冲区大小有限（默认 64KB）。如果子线程处理极慢且主线程疯狂写入，管道满后主进程的 write 会被阻塞。
