perf profiling 分析程序性能 #

程序性能分析 #

在计算机程序的开发过程中，性能优化至关重要。perf 是 Linux 系统上一个强大的工具，用于分析程序的性能。它通过以一定频率采集程序的调用栈（call stack），然后对这些调用栈进行统计分析。具体来说，perf 会记录程序在运行时所执行的函数调用路径，并通过采样频率来捕捉这些路径。如果某段代码路径在采集结果中出现得越频繁，说明程序在这段代码上花费的时间越多。通过这种方式，我们可以快速定位到程序中最占用资源的部分，从而找到性能瓶颈并进行优化。

perf 命令 #

在使用 perf 进行性能分析时，我们通常会用到以下几个命令：

bash
perf record -F 99 -p $(pidof test1) -g -- sleep 300
perf report -g --stdio

  • perf record：这个命令用于记录程序的性能数据。上述命令的具体参数含义如下：

    • -F 99：指定采样频率为 99Hz，即每秒采样 99 次。
    • -p $(pidof test1)：指定要分析的进程 ID，这里使用 pidof test1 来获取程序 test1 的进程 ID。
    • -g：启用调用栈的记录，这样我们可以看到每个采样点的函数调用路径。
    • -- sleep 300：指定采样时间为 300 秒，这意味着 perf 将在接下来的 5 分钟内一直记录性能数据。

  • perf report：这个命令用于查看已经记录的性能分析结果。参数 -g 启用了图形化的调用栈显示，使报告更易读。

通过这些命令，我们可以全面了解程序的运行情况，找出性能瓶颈的所在。

例子分析 #

为了更好地理解 perf 工具的作用，我们编写了一个示例程序来进行分析。

cpp
#include <stdio.h>

int functiona(void) {
    int c = 0;
    int count = 0;
    for (c = 1; c < 20000; c++) {
        count++;
    }
    return count;
}

int functionb(void) {
    int c = 0;
    int count = 0;
    for (c = 1; c < 40000; c++) {
        count++;
    }
    return count;
}

int main(int argc, char *argv[]) {
    for (;;) {
        functiona();
        printf("call function a\n");
        functionb();
        printf("call function b\n");
    }
    return 0;
}

编译命令 #

将上述程序保存为 test1.c，然后使用以下命令进行编译：

bash
gcc -g -o test1 test1.c
  • -g：启用调试信息，这将帮助 perf 提供更详细的调用栈信息。

测试过程 #

接下来，我们将详细介绍如何使用 perf 工具对 test1 程序进行性能分析。

  1. 启动 test1 程序：

    在终端中输入以下命令，将 test1 放在后台运行：

    bash
    ./test1 > /dev/null &

    这样，我们可以避免控制台输出干扰性能分析结果。

  2. 开始性能数据采集：

    使用 perf record 命令开始记录性能数据：

    bash
    perf record -F 99 -p $(pidof test1) -g -- sleep 300

    这个命令将在接下来的 300 秒内，每秒采样 99 次，记录 test1 进程的调用栈信息。

  3. 采集数据完成后生成报告：

    采样完成后，我们可以使用以下命令生成分析报告：

    bash
    perf script > out.perf

    这将生成一个文本格式的报告文件 out.perf，包含采样结果的详细信息。

  4. 生成火焰图：

    为了更直观地查看性能数据，我们可以将 out.perf 转换为火焰图（Flame Graph）的形式。首先，我们需要使用 stackcollapse-perf.pl 脚本将数据格式转换：

    bash
    ./stackcollapse-perf.pl out.perf > out.folded

    然后，使用 flamegraph.pl 生成 SVG 格式的火焰图：

    bash
    ./flamegraph.pl out.folded > out.svg

    火焰图以堆叠条图的形式展示了各个函数的调用关系和时间占比， giúp 我们快速识别出性能瓶颈所在。

测试结果分析 #

通过上述步骤，我们已经得到了 test1 程序的性能分析报告和火焰图。接下来，我们将详细分析这些结果，找出程序中最占用资源的部分。

分析步骤 #

  1. 查看性能报告：

    打开 out.perf 文件，查找频率最高的函数。我们可以看到 functionb 和 functiona 是两个高频调用的函数。

  2. 查看调用栈：

    在性能报告中，每个采样点都会显示完整的调用栈。通过这些信息，我们可以了解到哪些函数调用路径导致了高频率的执行。

  3. 火焰图分析：

    打开生成的 out.svg 文件，在火焰图中：

    • 每个矩形代表一个函数，宽度表示该函数占用的时间比例。
    • 从下到上，展示的是调用栈的深度，最底部的是主函数 main，其上方是被调用的函数 functiona 和 functionb。

结果解读 #

通过 perf 分析工具的帮助，我们发现：

  1. 函数调用频率：

    • functionb 的循环次数比 functiona 多一倍（40000 次 vs. 20000 次），因此它在性能报告中出现的频率更高。
    • functionb 的执行时间占用了整个程序的主要部分，导致了性能瓶颈。

  2. 资源消耗定位：

    • functionb 内部的空 count++ 循环是主要的资源消耗点。虽然 count 变量最终没有被使用，但循环本身占用了大量 CPU 时间。
    • printf 语句虽然频繁调用，但由于每次执行时间较短，所以在性能报告中占比较低。

优化建议 #

基于以上分析，我们可以提出以下优化建议：

  1. 优化循环体：

    • 减少循环次数：如果应用场景允许，可以适当减少循环的次数。例如，将 functionb 的循环次数从 40000 次减少到 20000 次。

    • 移除无用代码：去掉 count 变量的无效操作，或者将其改写为有实际意义的计算，以避免不必要的循环迭代。

    cpp
    // 改进后的 functionb
int functionb(void) {
    int sum = 0;
    for (int c = 1; c < 20000; c++) {
        sum += c;
    }
    return sum;
}

  2. 减少 I/O 操作：

    • 在主循环中，printf 函数被频繁调用，可能会导致性能下降。可以考虑将日志输出减少，或者使用更高效的日志记录方式。
    cpp
    // 改进后的 main 函数
int main(int argc, char *argv[]) {
    for (int i = 0; i < 1000; i++) {
        functiona();
        functionb();
    }
    return 0;
}

    注意，上述改动已经去除了 printf 语句，并且限制了循环的次数，以减少不必要的资源消耗。

  3. 并行优化：

    • 如果程序允许，可以考虑将 functiona 和 functionb 的执行并行化，利用多核 CPU 的优势来加速程序运行。

  4. 编译器优化：

    • 在编译阶段，开启更高级的优化选项，例如 -O3，让编译器对程序进行更深入的优化。
    bash
    gcc -g -O3 -o test1 test1.c

总结 #

通过使用 perf 工具，我们成功地分析并定位了示例程序中的性能瓶颈。具体来说，functionb 函数由于其内部的大量循环迭代，成为了整个程序的主要资源消耗点。通过减少循环次数、移除无效代码、减少 I/O 操作以及进行编译器优化等措施，我们可以有效地提升程序的性能。

这种性能分析的方法不仅适用于示例程序，也可以推广到实际项目中。通过定期进行性能分析并针对性地优化关键代码段，我们可以显著提高程序的运行效率，降低资源消耗，从而提升整体用户体验。
