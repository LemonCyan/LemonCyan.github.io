09 网络协议栈之内核机制 #

覆盖：进程上下文与中断上下文、内核抢占与进程调度、内核锁（自旋锁/读写自旋锁/互斥锁/RCU）、报文收发核心函数 netif_receive_skb 与 dev_queue_xmit、内核双向链表 list_head 与哈希链表 hlist。

一、进程上下文与中断上下文 #

内核态运行驱动、中断处理、调度、内存管理等；用户态运行应用程序。两者有各自的内存映射与地址空间。

  • 进程上下文：用户态切到内核态时，先保存用户态寄存器/状态/栈（上文），再执行内核态代码（下文）。主要由系统调用、异常处理、内核线程进入，为当前进程服务。
  • 中断上下文：硬件触发中断，内核调用 ISR 处理（上文保存被中断进程环境，下文执行 ISR）。中断上下文不可抢占，绝对不能睡眠、不能获取信号量、不能访问用户空间虚拟地址、不宜做耗时任务（耗时工作应放中断下半部 softirq/tasklet）。

二、内核抢占与进程调度 #

调度即 schedule() 被调用的时机，分两类：

  • 主动式：内核直接调用 schedule()，如 current->state = TASK_INTERRUPTIBLE; schedule(); 主动让出 CPU。
  • 被动式（抢占）：用户抢占（系统调用/中断返回用户空间时检查 need_resched）；内核抢占（2.6 起，高优先级进程可抢占正在内核态运行的低优先级进程）。

支持内核抢占后，禁止抢占的特例：

  • 正在处理中断或中断底半部（软中断）；
  • 持有 spinlock/rwlock 等锁；
  • 正在运行调度程序本身。

内核用 thread_info/preempt_count 抢占计数控制：preempt_count>0 禁止抢占。加锁时 +1，解锁（preempt_enable()）时 -1 并判断 need_resched。抢占发生于：中断返回内核空间前、解锁及使能软中断时。

为何需要内核抢占：实时系统要求被中断唤醒的实时进程在限定时间内被调度，不可抢占内核的响应延迟可达 100ms 级。

三、内核锁机制 #

1. 自旋锁 spinlock #

加锁后其他线程再申请会**忙等（自旋）**而非阻塞，适用持锁时间短、不希望重新调度的场景。

Linux 自旋锁三种实现：单 CPU 非抢占=空操作；单 CPU 抢占=禁止内核抢占（不真正自旋）；多 CPU 抢占=禁止抢占+自旋。

自旋锁临界区三特性：不能休眠、不能被其他中断打断、内核不可被抢占。死锁常见于：持有锁时进程休眠/被抢占、或同 CPU 上中断处理程序又去申请同一把锁（此时应使用 spin_lock_irqsave 关中断版本）。

2. 读写自旋锁 rwlock #

比自旋锁粒度更细："防写不防读"。最多一个写者，可多个读者，读写互斥。函数与自旋锁类似，仅前缀 spin_→read_/write_：

c
rwlock_t lock; rwlock_init(&lock);
read_lock(&lock);  /* 临界区(读) */  read_unlock(&lock);
write_lock_irqsave(&lock, flags); /* 临界区(写) */ write_unlock_irqrestore(&lock, flags);

还有 _bh（禁软中断）、_irq/_irqsave（禁/存中断）等变体，*_trylock 不阻塞。

3. 互斥锁 mutex #

加锁后其他线程阻塞等待，解锁后就绪线程竞争。适用持锁时间长、允许睡眠的场景，同一时刻仅一个线程访问资源。

4. RCU（Read-Copy Update） #

免锁的"读-复制-更新"机制。读者无需任何锁（rcu_read_lock 仅 preempt_disable，允许中断）；写者拷贝副本修改后，注册回调在 grace period（所有 CPU 都经历过一次上下文切换/quiescent state）后释放老指针。读者与写者视图短暂不一致是允许的。

  • call_rcu()：异步，注册回调返回后老指针未必已释放，中断上下文可用；
  • synchronize_rcu()：同步睡眠，返回后老指针必已释放，中断上下文不可用。

适用"大量读、少量更新"，典型如路由表维护、邻居表、延迟释放。

四、报文收发核心函数 #

1. 接收：netif_receive_skb() #

网卡收到报文触发中断，老式流程在 ISR 中分配 skb、拷贝数据、netif_rx() 入 input_pkt_queue 队列并触发 NET_RX_SOFTIRQ；新式 NAPI 在 ISR 中仅 netif_rx_schedule 把 dev 列入 poll_list，由 net_rx_action→dev->poll（或 process_backlog）批量取 skb 调 netif_receive_skb。

netif_receive_skb 依次：

  1. 遍历 ptype_all（抓包，如 ETH_P_ALL 的 packet socket）；
  2. 网桥 handle_bridge / br_handle_frame；
  3. MAC VLAN handle_macvlan；
  4. 按 skb->protocol（链路层头已在驱动 eth_type_trans 中跳过）在 ptype_base 哈希表查协议模块并调用其 func，如 ip_rcv()、arp_rcv()。

协议模块通过 dev_add_pack() 注册到 ptype_base/ptype_all（list_add_rcu）。

2. 发送：dev_queue_xmit() #

上层构造好含链路层头的 skb 后调用，先线性化分段、算校验和，再 rcu_read_lock_bh()。有队列设备（q->enqueue 存在）走 qdisc_enqueue_root → qdisc_run → qdisc_restart → dev->hard_start_xmit 发送，失败则 requeue 并触发 NET_TX_SOFTIRQ（由 net_tx_action 在软中断中重试发送并释放 completion_queue 中的 skb）。无队列设备（如 lo 回环）直接 hard_start_xmit，失败即丢弃。

软中断的作用：发送 dev_queue_xmit 首次尝试失败或没发完的积压包，以及释放已发送完成的 skb，避免硬件中断中做耗时释放。

五、内核链表：list_head 与 hlist #

list_head 是双循环链表节点，自身无数据域，嵌入到宿主结构中使用：

c
struct list_head { struct list_head *next, *prev; };
struct stud { char name[32]; struct list_head list; };  // 链表节点作为成员

通过 list_entry(ptr, type, member)（底层 container_of：用 offsetof 算 member 在 type 中的偏移，(char*)ptr - offset 得宿主首地址）由节点反取宿主结构。常用 LIST_HEAD/INIT_LIST_HEAD、list_add(插表头)、list_del、list_empty、list_for_each/list_for_each_entry(及 _safe 安全版，遍历中可删)。

hlist（哈希链表）用于哈希桶：头结点 hlist_head 仅一个 first 指针（省内存，桶多）；普通结点 hlist_node 含 next 与二级指针 pprev（指向前一个结点的 next 指针地址）。用 pprev 使"删除/插入第一个结点"与"删除/插入后续结点"代码统一。hlist_add_head、hlist_del、hlist_unhashed、hlist_empty 及 hlist_for_each_entry/_safe 等宏与 list 类似，遍历需额外 pos 临时指针（末节点 next==NULL 不在任何宿主内）。
