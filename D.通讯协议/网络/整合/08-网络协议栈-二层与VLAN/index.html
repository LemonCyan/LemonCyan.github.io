网络协议栈：二层转发与 VLAN #

整合自《网络协议栈开发（二/三/四/五/六/七/八）》《基础篇（五/七/八/九）》《Trunk 端口汇聚》《VLAN 原理详解》《Netfilter 概述》等笔记。聚焦局域网内部"帧怎么转发、VLAN 怎么隔离、包在内核哪里被截获"。

1. 数据链路层（PPP） #

PPP（点对点协议）用于点到点串行链路（拨号/串口/隧道），提供链路建立、认证、IP 协商。没有 MAC 概念，是"一对一"链路层。

帧格式（每帧以标志字节 0x7E 开始和结束）：

0x7E | 地址 0xFF | 控制 0x03 | 协议域(2B) | 信息域(≤1500B) | FCS | 0x7E

协议域区分信息域内容：

协议域值 含义
0xC021 LCP 链路控制协议报文
0xC023 PAP 认证报文
0xC223 CHAP 认证报文
0x8021 NCP 网络控制协议报文
0x0021 IP 数据报文

PPP 三组件：LCP（配置/测试链路）、NCP（协商网络层参数、分配 IP）、认证（可选）。

工作流程：拨号建物理连接 → 发 LCP 分组建立 LCP 连接（协商 MTU、认证方式等）→ 鉴别阶段（PAP/CHAP）→ NCP 给客户端分配临时 IP → 正常通信 → NCP 释放、收回 IP → LCP 释放 → 断物理连接。

PAP vs CHAP：PAP 两次握手、明文传用户名密码，仅协商时一次；CHAP 三次握手、用 MD5+随机数加密，通信中可随时质询，更安全但耗 CPU。

PPPoE：PPP 要求点对点，不适于广播型以太网，于是把 PPP 帧封装在以太网里（Point-to-Point over Ethernet），为桥接以太网用户提供宽带接入与计费，每用户一个 PPP 会话。

2. 二层桥（Bridge）转发原理 #

Linux 网桥 br0 相当于一台二层交换机，核心是 MAC 转发表（FDB）：

  • 学习：收到帧时，把"源 MAC + 入端口"写进 FDB。
  • 转发：查目的 MAC 对应出端口，单播转发。
  • 泛洪：目的 MAC 不在表中（或广播/组播），向除入端口外所有端口转发。
  • 老化：表项超时未刷新则删除。

转发蓝图（简化）：网卡收包 → 桥端口判断 → 查 FDB → 命中单播 / 未命中泛洪 → 从出端口发出。内核里 dev_queue_xmit() 负责发送、netif_receive_skb() 负责接收（见 09 篇）。

3. VLAN 原理 #

VLAN 在二层把一台物理交换机逻辑切成多个广播域，隔离广播、提升安全。

  • VID（VLAN ID，1–4094）：标识帧属于哪个 VLAN。
  • PVID：端口的默认 VLAN，未打标帧进入时按 PVID 归类。
  • Tag / Untag：
    • Access 口：连接终端，收发去标签帧（untag）。
    • Trunk 口：交换机互联，收发带 802.1Q 标签帧（tag），标签里含 VID。
  • 802.1Q 标签：在以太网头与 IP 头之间插入 4 字节——TPID(0x8100,2B) | PRI(3bit) | CFI(1bit) | VID(12bit)。
bash
# Linux 下创建 VLAN 子接口（基于 eth0 的 VLAN 10）
ip link add link eth0 name eth0.10 type vlan id 10
ip link set eth0.10 up

帧进入交换机时打上入端口 PVID 对应 VID，交换机内按 VLAN 隔离转发，出端口按端口类型决定是否保留/剥离标签。

4. Trunk（端口汇聚） #

Trunk 口承载多个 VLAN 的流量，靠 802.1Q 标签区分。两端交换机 Trunk 配置一致才能正确传递跨 VLAN 帧。Access 口只属于单一 VLAN，不能传标签帧。端口汇聚也可指把多条物理链路捆绑成一条逻辑链路以提升带宽与冗余。

5. Netfilter 与 hook 点 #

Linux 防火墙/包处理的内核框架是 Netfilter，在协议栈 5 个固定位置埋钩子（hook），iptables 规则就挂在这些钩子上：

PREROUTING → 路由判断 → { INPUT → 本机 | FORWARD → 转发 | } → POSTROUTING
OUTPUT（本机发出）
hook 点 位置 典型用途
PREROUTING 路由前 DNAT（目的地址转换）
INPUT 发往本机 filter 入站过滤
FORWARD 转发 filter 转发过滤
OUTPUT 本机发出 filter/NAT 出站
POSTROUTING 路由后 SNAT（源地址转换）

内核用二维数组 nf_hooks[2][0..4]（协议族 × hook 号）挂接钩子函数，NF_HOOK 宏依次调用链上注册的函数。钩子函数返回值为：

  • NF_ACCEPT：继续正常走协议栈；
  • NF_DROP：丢弃该包；
  • NF_STOLEN：钩子接管包，协议栈不再处理；
  • NF_QUEUE：交给用户态（如 nf_queue）；
  • NF_REPEAT：重新调用该 hook。

关键结论（见 10 篇策略路由）：接收包 → DNAT → 查路由策略 → 路由 → SNAT → 发出。DNAT 必须在路由前，SNAT 必须在路由后。
