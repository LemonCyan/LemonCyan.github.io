02-Socket-API全解

Socket API 全解 #

整合自《socket/bind/listen/connect/accept/send/recv…》系列笔记。按 TCP 通信的真实调用顺序串起所有接口，并补充 setsockopt 常用选项。

1. 一张调用时序图 #

Server:  socket() → bind() → listen() → accept() ──┐
                                                    │ 建立连接
Client:  socket() ───────────────────→ connect() ──┘
之后双方：send()/recv()（或 read()/write()）…  close()

2. socket() —— 创建套接字 #

c
int socket(int protofamily, int type, int protocol);
// 成功返回 sockfd（描述符），失败 -1
  • protofamily：协议族。AF_INET(IPv4)、AF_INET6(IPv6)、AF_UNIX(Unix 域)、AF_ROUTE(路由)。
  • type：套接字类型。SOCK_STREAM(TCP 字节流)、SOCK_DGRAM(UDP 数据报)、SOCK_RAW(原始套接字)。
  • protocol：一般填 0，由 type 自动选默认协议；也可显式 IPPROTO_TCP / IPPROTO_UDP。

刚创建的 socket 存在于协议族空间，但还没有地址；不绑定的话，调用 connect/listen 时内核会自动随机分配端口。

3. bind() —— 绑定地址 #

c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

把特定 IP+端口赋给 socket。服务器通常在 listen 前绑定众所周知的地址；客户端一般不主动 bind，由 connect 时内核自动分配。

  • 想绑定本机所有网卡：servaddr.sin_addr.s_addr = htonl(INADDR_ANY)。
  • 绑定特定网卡：inet_addr("192.168.0.123")。
  • 端口填 0 ⇒ 内核临时分配，需用 getsockname 取回实际端口。

4. listen() / connect() #

c
int listen(int sockfd, int backlog);          // 服务器：主动 socket → 被动监听
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen); // 客户端
  • listen 的 backlog 是已完成连接队列的上限（半连接队列另由内核参数控制），一般 < 30。
  • connect 触发 TCP 三次握手；成功返回 0，失败 -1。
  • UDP 的 connect 没有握手：内核只记录对端 IP/端口，之后 send/recv/read/write 也可用，相当于固定了默认对端。

5. accept() —— 接受连接 #

c
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
// 返回"连接套接字"connfd；addr 可填 NULL

要点：两种套接字要分清

  • 监听套接字（sockfd）：服务器生命周期内一直存在，只负责 accept。
  • 连接套接字（connfd）：每接受一个客户端新建一个，专门与该客户端通信；服务完 close 即可。

连接套接字复用监听套接字的端口号，并不占用新端口。accept 默认阻塞，直到有客户端连上。

6. 数据传输：5 组 I/O 函数 #

网络 I/O 有多组接口，底层都能互相替代：

c
ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
ssize_t send(int sockfd, const void *buf, size_t len, int flags);
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);  // UDP
ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                 struct sockaddr *src_addr, socklen_t *addrlen);      // UDP
ssize_t sendmsg(int sockfd, const struct msghdr *msg, int flags);     // 最通用
ssize_t recvmsg(int sockfd, struct msghdr *msg, int flags);
  • send/recv 比 read/write 多了 flags（如 MSG_PEEK、MSG_OOB）。
  • sendto/recvfrom 用于无连接 UDP，携带对端地址。
  • sendmsg/recvmsg 最通用，其他几组本质上都能用这对实现。
  • read 返回 0 表示对端关闭；-1 且 errno==EINTR 是被信号中断，可重试；ECONNRESET 表示连接异常。

7. shutdown() / close() #

c
int shutdown(int sockfd, int how); // how: SHUT_RD / SHUT_WR / SHUT_RDWR
int close(int fd);
  • close 只是把描述符引用计数 -1，计数为 0 才真正发 FIN 关闭 TCP 连接。
  • shutdown 可以单向关闭（如 SHUT_WR 发完 FIN 后仍可读），常用于半关闭场景。close 做不到单向。

8. setsockopt() 常用选项 #

c
int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);
level optname 作用
SOL_SOCKET SO_REUSEADDR 允许重用 TIME_WAIT 状态的本地地址:端口（见下）
SOL_SOCKET SO_REUSEPORT 多进程/多线程绑定同一地址:端口做负载均衡
SOL_SOCKET SO_RCVTIMEO / SO_SNDTIMEO 收发超时（struct timeval）
SOL_SOCKET SO_RCVBUF / SO_SNDBUF 收发缓冲区大小
SOL_SOCKET SO_BROADCAST 允许发送广播数据报（UDP）
SOL_SOCKET SO_KEEPALIVE 启用保活探测
IPPROTO_TCP TCP_NODELAY 禁用 Nagle 算法，降低小包延迟
IPPROTO_IP IP_HDRINCL 原始套接字手动构造 IP 头

SO_REUSEADDR 的四种典型用途 #

  1. 端口处于 TIME_WAIT 时快速重用：服务重启常因旧连接卡在 TIME_WAIT（约 2 分钟）导致 bind 失败，设此选项即可立即重用。
  2. 同一端口上启动同一服务器的多个实例（每个实例绑不同 IP）。
  3. 单个进程把同一端口绑到多个 socket（每个 socket 绑不同 IP）。
  4. UDP 多播时允许完全相同地址:端口的重复捆绑（仅多播，TCP 不支持）。

经验法则：所有 TCP 服务器都在 bind 之前设置 SO_REUSEADDR；多播程序设置 SO_REUSEADDR 并把多播地址作为本地 IP。注意它只重用"本地地址:端口"，整个五元组仍唯一，重启后有可能收到非期望数据，需谨慎。

c
int opt = 1;
setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
