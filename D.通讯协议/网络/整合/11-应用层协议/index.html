11 应用层协议 #

覆盖：DHCP 动态地址分配（Discover/Offer/Request/ACK）、SNMP（报文协议、MIB/OID、v1/v2c/v3 差异）、CWMP/TR-069（CPE 远程管理、RPC 方法、业务流程）、用 socket 模拟请求 Web 服务器（HTTP 无连接/无状态）。

一、DHCP —— 动态主机配置协议 #

DHCP 是应用层协议，前身是 BOOTP，用于自动给客户端分配 IP。实现分四步（Wireshark 过滤条件用 bootp）：

  1. Discover：客户端用 0.0.0.0 源、广播 255.255.255.255 目的（UDP 目的端口 67），发现可用 DHCP Server；
  2. Offer：Server 仍用广播回应，携带可用 IP（Your Client IP）、子网掩码、Router、DNS、域名、租期（Lease Time）；
  3. Request：客户端请求分配该 IP（源/目的仍是 0.0.0.0/255.255.255.255）；
  4. ACK：Server 确认，正式下发配置。

Windows 下可用 ipconfig /release（断网，IP 变 0.0.0.0）、ipconfig /renew（重新请求）触发上述过程。ipconfig /renew 已获地址时每次只产生 Request/ACK 两个包。

DHCP 饥饿攻击：伪造大量 MAC 不断发 Request 耗尽服务器 IP 池，再架恶意 DHCP Server 把网关/DNS 指向自己，实施中间人攻击。

二、SNMP —— 简单网络管理协议 #

SNMP 是 TCP/IP 应用层协议（1988 制定，现有 v1/v2c/v3）。完整系统含三部分：MIB（管理信息库）、SMI（管理信息结构）、SNMP 报文协议。采用管理站(NMS)/代理(Agent) 模型，双方通过 MIB 统一接口。

1. 报文类型（UDP 封装） #

  • Get-Request / Get-Next-Request / Set-Request：管理站→Agent（端口 161）；
  • Get-Response：Agent→管理站；
  • Trap：Agent 主动上报事件（接口 UP/DOWN 等），发往管理站 162 端口。

SNMP 报文 = 公共首部（版本、共同体 community 明文口令如 public、PDU 类型）+ get/set 首部（request-id、error-status、error-index）+ 变量绑定（variable-bindings，变量名与值对；Get 中值忽略）+ trap 首部（enterprise、generic-trap、specific-code、timestamp）。GetNext 的核心用途是表遍历（用 MIB 树后序后继确定下一个变量）。

2. MIB 与 OID #

MIB 是被管理对象的集合，对象按 ISO/ITU 的分级树命名。OID 唯一标识一个对象，如 iso.org.dod.internet.mgmt.mib.ip.ipInReceives = 1.3.6.1.2.1.4.3。实例常在 OID 后加后缀（标量对象加 .0，表对象加索引，如路由表 1.3.6.1.2.1.4.21.1.7.202.120.86.71）。

  • mib-2 标识为 {1.3.6.1.2.1}；
  • 企业节点 {1.3.6.1.4.1} 下各厂商独立（Cisco=.9、Huawei=.2011、Novell=.23），向 IANA 申请。

OID 书写格式：MIB名::唯一键值.实例，如 NETWORK-APPLIANCE-MIB::diskSpareCount.0。MIB 本质是一张"值在哪儿、返回什么"的地图。

3. 版本差异 #

版本 认证/安全 特点
v1 团体名（明文，类似密码） 最简，操作类型少，error 码少，Trap 发后无响应
v2c 团体名 新增 GetBulk（高效批量取）、Inform（有响应，Trap 升级）；Trap 改用 Get/Set 的 PDU 格式，把 sysUpTime、snmpTrapOID 放入 variable-bindings
v3 USM（用户名+认证+加密）+ VACM（基于视图的访问控制） 安全性大幅增强；交互前 NMS 先与 Agent 同步 AuthoritativeEngineID/Boots/Time，报文可加密

三、CWMP / TR-069 —— CPE 广域网管理协议 #

由 DSL 论坛制定（编号 TR-069），用于 ACS（自动配置服务器）对分散在用户侧的 CPE（用户设备）进行远程集中管理。

1. 协议栈与架构 #

CPE/ACS 管理应用
  RPC Methods（ACS↔CPE 交互）
    SOAP（XML 封装，避开防火墙）
      HTTP 1.1
        SSL/TLS（可选加密）
          TCP/IP

选 SOAP over HTTP 的原因：多数防火墙按端口扫描，SOAP 绑定到标准 HTTP 端口可自然穿越。支持多个 SOAP Envelope 以减少交互次数。

2. 主要功能 #

自动配置/动态业务、软件固件镜像管理（Download/Upload）、诊断、告警（CPE 主动 Event Report）、穿越 NAT（TR-111 让 ACS 也能主动发起会话）。

3. RPC 方法（统一定义的接口） #

  • CPE 侧：GetParameterValues、SetParameterValues、Inform（会话开始/配置变更/周期上报时通知 ACS）、Download、Upload、Reboot 等；
  • ACS 侧：GetRPCMethods、SetRPCMethods 等。

所有设备抽象成统一数据模型，根节点 InternetGatewayDevice，通过操作设备树节点的 Value/Attribute 改变配置。

4. 业务流程（一次会话） #

  1. 建立 TCP 连接 → 2. SSL 初始化 → 3. CPE 发 Inform（EventCode 说明原因，如 BOOT/PERIODIC/CONNECTION REQUEST/VALUE CHANGE/BOOTSTRAP）→ 4. ACS 认证通过回 InformResponse → 5. CPE 发空 HTTP POST 满足请求/响应规则 → 6~9. ACS 查询/设置参数（如改 ACS URL）→ 10. ACS 发空报文表示无更多请求 → 11. CPE 关闭连接。

HTTP 无状态，会话顺序靠 Cookie 维持；SOAP 中 xsi:type（如 xsd:string）建议保留以避免不同 ACS 校验失败。

四、用 socket 请求 Web 服务器（HTTP） #

HTTP 是应用层协议、底层基于 TCP。浏览器访问 Web 服务器流程：

  1. 创建 Socket，按 IP（域名）和端口（默认 80）connect 服务器；
  2. 按 HTTP 规范发送请求行/头标（如 GET /path HTTP/1.1、Host、User-Agent）；
  3. 等待服务器处理返回；
  4. 服务器 accept 后 recv 请求，解析并 send 结果（HTML）；
  5. 发完关闭 Socket；6. 浏览器收数据渲染并关闭；7. 本次请求结束；8. 下次请求重新 connect。

两大特性：

  • 无连接：一次连接只处理一个请求，处理完即断开，下次再建连；
  • 无状态：服务器不保存浏览器信息，第二次请求需的结果（如 cookie）须由浏览器重传。

协议本质是一种"字节流契约/结构体"，通信双方按既定格式收发才能成功；TCP 流式传输尤需事先定义边界规范。下面用 socket 模拟浏览器发送请求的核心代码（Connection: close 表示取完即关）：

csharp
string h1 = "GET " + _path + " HTTP/1.1\r\n";
string h2 = "Accept: */*\r\n";
string h4 = "Host: " + _host + "\r\n";
string h7 = "Connection: close\r\n\r\n";
byte[] buf = Encoding.UTF8.GetBytes(h1 + h2 + h4 + h7);
socket.Send(buf);   // 发送 HTTP 请求
// socket.BeginReceive(...) 异步接收服务器返回的 HTML
