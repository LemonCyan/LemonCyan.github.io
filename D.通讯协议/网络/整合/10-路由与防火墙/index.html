10 路由与防火墙 #

覆盖：IP/route 命令与路由表、策略路由、iptables 三表五链与规则写法、SNAT/DNAT/MASQUERADE 地址转换、网络状态监测命令、主机与开发板 TCP 通信实例。

一、IP 与路由基础命令 #

ip 是替代 ifconfig/route 的现代工具：

bash
ip addr add 1.2.3.4/24 dev eth3      # 配置 IP（手工，非 DHCP）
ip addr set dev eth3 up              # 使能网卡
ip route add default via 1.2.3.1 dev eth3   # 默认路由（务必用 via 指定下一跳）

注意：ip route add default dev eth3（不带 via）会导致非同子网访问失败。

route 命令（仍可常用）语法：route [-f] [-p] [add|del|change|print] 目标 [mask 掩码] [网关] [metric 度量] [if 接口]。

  • route print：打印路由表（Windows/Linux 通用思路）；
  • route delete 192.168.2.0 mask 255.255.255.0：删除路由（支持 route delete 115* 模糊匹配）；
  • route add 10.41.0.0 mask 255.255.0.0 10.27.0.1 metric 7：添加。

路由表每行字段：Destination（目的网段）、Netmask（掩码）、Gateway（下一跳）、Interface（出口网卡 IP）、Metric（度量，越小越优先）。根据掩码可将路由分三类：

类型 Flags 说明
主机路由 H 指向单个 IP，掩码 255.255.255.255
网络路由 N 指向一个网段
默认路由 G 找不到匹配时走默认网关（0.0.0.0/0）

多网卡同时上内外网时，删除 0.0.0.0 默认路由后分别添加（如 route add 5.0.0.0 mask 255.0.0.0 5.0.217.1 + 默认走无线网关），即可内外网并存。

二、路由表与策略路由 #

Linux 维护 4 个内置路由表（对应关系在 /etc/iproute2/rt_tables）：

  • 0# 系统保留；253# default（默认兜底）；254# main（常规无策略路由）；255# local（本地/广播/NAT，系统维护不可改）。用户可自定义 1–252 号表。

策略路由（ip rule） 比传统路由更灵活，可按源地址、报文大小、TOS、fwmark 等选路：

bash
ip rule add from 192.203.80/24 table inr.ruhep prio 220   # 来自该段的包查 inr.ruhep 表
ip route add 192.168.0.0/24 via 192.168.1.2 table 1      # 在 1 号表加路由

系统默认三条规则：0→查 local（不可删）、32766→查 main、32767→查 default。

ip rule / ip route / iptables 三者配合（如"内网 192.168.0.1~100 走电信网关、其余走网通"）：

  1. iptables -t mangle -A PREROUTING -i eth0 -s 192.168.0.1-100 -j MARK --set-mark 3（mangle 先于 nat/filter，先打标记）；
  2. ip rule add fwmark 3 table 3（带标记 3 的包用 table 3）；
  3. ip route add table 3 via 10.0.0.1 dev ethX。

Netfilter 处理顺序（收包）：先 DNAT(PREROUTING) → 查路由策略/路由表 → SNAT(POSTROUTING) → 发出。

三、iptables 架构：三表五链 #

iptables 是用户空间工具，真正生效的是内核 netfilter。netfilter 在协议栈上设了 5 个 hook（规则链）：

链 位置
PREROUTING 路由前（进网卡后）
INPUT 流入本机用户空间
FORWARD 本机转发
OUTPUT 本机发出
POSTROUTING 路由后（出网卡前）

三张表及可用链：

  • filter（过滤）：INPUT / FORWARD / OUTPUT
  • nat（地址转换）：PREROUTING / OUTPUT / POSTROUTING
  • mangle（改报文元数据/TTL/打标记）：5 链皆可

规则写法：iptables [-t 表] COMMAND 链 匹配标准 -j ACTION。常用 COMMAND：-A 追加、-I num 插入、-R num 替换、-D num 删除、-P 设默认策略、-F 清空、-L -n -v --line-numbers 查看。匹配标准：-s/-d 源/目的、-p tcp/udp/icmp、-i/-o 入/出网卡；扩展如 --dport/--sport、--tcp-flags、-m multiport、-m state --state NEW,ESTABLISHED。ACTION：ACCEPT/DROP/REJECT、SNAT/DNAT/MASQUERADE/REDIRECT/MARK、自定义链、RETURN。

状态检测四态：NEW（首次握手）、ESTABLISHED（已建连）、RELATED（关联，如 FTP 数据端口）、INVALID。例：放行 SSH 仅允许 NEW/ESTABLISHED 入、ESTABLISHED 出，可抑制反弹木马。

四、NAT 地址转换 #

SNAT（源地址转换，只能在 POSTROUTING） —— 内网多用户通过一个外网口上网：

bash
iptables -t nat -A POSTROUTING -s 192.168.10.0/24 -j SNAT --to-source 172.16.100.1
# 外网口地址动态（DHCP/ADSL）时用 MASQUERADE 自动探测：
iptables -t nat -A POSTROUTING -o ppp0 -j MASQUERADE

DNAT（目的地址转换，只能在 PREROUTING，须在路由前翻译） —— 外部访问映射到内网服务器：

bash
iptables -t nat -A PREROUTING -d 210.83.2.206 -p tcp --dport 80 -j DNAT --to 192.168.1.4
# 带端口映射（外 2121 → 内 21）：
iptables -t nat -A PREROUTING -p tcp -d 216.94.87.37 --dport 2121 -j DNAT --to-destination 192.168.100.125:21

要点：PREROUTING DNAT 在 FORWARD 之前执行，故 FORWARD 链匹配的是翻译后的目的地址/端口（如上例应放行 22 而非 2022）；DNAT 只是翻译，仍需在 FORWARD 显式 ACCEPT；Linux 实现完整 NAT/NAPT（端口替换见 RFC3022），并无 Cisco 的 PAT 概念。规则保存：iptables-save > /etc/sysconfig/iptables，开机 iptables-restore 加载（service iptables save 亦可）。

五、网络状态监测命令 #

  • ifconfig：检测网络接口配置；
  • ping：检测网络连通性（ICMP echo）；
  • netstat：查看网络连接、路由、端口状态；
  • traceroute：检测到达目的主机所经过的路由器；
  • tcpdump：抓包，显示本机网络流量状态。

六、主机与开发板通信实例 #

嵌入式开发中，主机（PC）常通过 TCP 与开发板互发数据。下面是基于 select 的 TCP 聊天框架（节选关键逻辑），服务器/客户端均可同时监听"标准输入"与"套接字"：

c
#define SERVER_PORT 8888
#define SERVER_IP  "192.168.1.17"
/* 服务器：socket→bind→listen→accept 后，用 select 同时等待控制台与客户端 */
fd_set rfds; struct timeval tv; tv.tv_sec = 5;
FD_ZERO(&rfds); FD_SET(0, &rfds); FD_SET(newfd, &rfds);
maxfd = newfd;
if ((retval = select(maxfd+1, &rfds, NULL, NULL, &tv)) > 0) {
    if (FD_ISSET(0, &rfds))  { fgets(buf, BUFLEN, stdin); send(newfd, buf, len, 0); }
    if (FD_ISSET(newfd, &rfds)) { len = recv(newfd, buf, BUFLEN, 0); /* 处理 */ }
}

客户端流程为 socket→connect，同样用 select 复用标准输入与 sockfd。这种方式在 06 篇的并发/IO 多路复用服务器中已有完整说明，此处仅作为"主机↔开发板"的实际联调示例。
