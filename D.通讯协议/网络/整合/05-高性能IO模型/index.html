05-高性能IO模型

高性能 IO 模型 #

整合自《高性能 IO 模型浅析》《epoll 函数的实现》《select 函数的实现代码》及 CSDN《网络编程（I/O 模型）》《网络编程（服务器模型）》。服务器性能瓶颈常在 I/O，先分清五种模型与服务器模型。

1. 两个维度：同步/异步、阻塞/非阻塞 #

  • 同步 vs 异步：描述用户线程与内核的交互。同步＝发起 I/O 后必须等/轮询内核完成；异步＝发起后继续干别的，内核完成再通知（回调）。
  • 阻塞 vs 非阻塞：描述调用方式。阻塞＝I/O 彻底完成才返回；非阻塞＝立即返回状态值，不保证数据已就绪。

一个输入操作分两步：①等待数据准备好（到达内核缓冲区）；②把数据从内核拷贝到进程缓冲区。

2. Unix 五种 I/O 模型 #

(1) 同步阻塞 IO（Blocking） #

默认所有 socket 都是阻塞的。recvfrom 直到数据报到达且拷贝完才返回，期间线程被挂起（不占 CPU 时间片）。并发只能靠多线程。前 4 种模型（阻塞/非阻塞/复用/信号驱动）第二阶段都阻塞在 recvfrom，故 POSIX 定义为同步 I/O。

(2) 同步非阻塞 IO（Non-blocking） #

socket 设 O_NONBLOCK，无数据时 recvfrom 立即返回 EWOULDBLOCK。应用不断轮询（polling）内核，空耗 CPU，很少直接用，多作为其他模型的特性。

(3) IO 多路复用（IO Multiplexing）—— Reactor #

基于 select/poll/epoll，一个线程监视多个 socket。select 本身也阻塞，但能同时等待多个 fd 就绪，就绪后才真正调 I/O 函数。核心是"单线程处理多连接"。常用 Reactor 模式：事件循环调 select，就绪 fd 触发对应 EventHandler::handle_event。

(4) 信号驱动 IO（Signal-driven，SIGIO） #

fcntl 开启信号驱动并 sigaction 安装 SIGIO 处理函数，调用立即返回，进程不被阻塞；数据就绪时内核发 SIGIO，在信号处理函数或主循环里再 recvfrom。等待期间进程自由运行。

(5) 异步 IO（Asynchronous IO）—— Proactor #

aio_read 发起后立刻返回，内核独立完成"等待+拷贝"两阶段，全部完成后通知进程直接用数据。真正异步，但 OS 支持不如多路复用完善。实战多以"epoll + 线程池"满足需求。

3. select / poll / epoll 对比 #

特性 select poll epoll
fd 上限 1024（FD_SETSIZE） 无（链表） 无（内核红黑树）
实现 每次全量拷贝+遍历 同 select 内核事件就绪链表
时间复杂度 O(n) O(n) O(1) 仅就绪 fd
触发模式 水平触发(LT) LT LT + 边缘触发(ET)
适用 跨平台小并发 跨平台 Linux 高并发

select 就绪条件：可读——接收缓冲 ≥ 低水位线(默认1)/读到 FIN(read 返回0)/监听 socket 有新连接/出错；可写——发送缓冲可用空间 ≥ 低水位线(默认2048)/对端关闭写/非阻塞 connect 完成/出错；异常——收到带外数据(OOB)。

LT vs ET：水平触发（LT）只要 buffer 有数据就持续通知，编程简单；边缘触发（ET）仅在状态变化时通知一次，必须一次循环读/写到 EAGAIN，效率更高但易漏处理。

4. select 并发服务器（回声示例核心） #

c
fd_set rdf, cur;
FD_ZERO(&rdf); FD_SET(listenfd, &rdf); maxfd = listenfd;
while (1) {
    cur = rdf;
    select(maxfd + 1, &cur, NULL, NULL, 0);
    for (i = 0; i <= maxfd; i++) {
        if (!FD_ISSET(i, &cur)) continue;
        if (i == listenfd) {                 // 新连接
            confd = accept(listenfd, ...);
            FD_SET(confd, &rdf);
            maxfd = max(maxfd, confd);
        } else {                              // 已连接数据
            n = recv(i, buf, ...);
            if (n == 0) { close(i); FD_CLR(i, &rdf); }
            else send(i, buf, n, 0);          // 回射
        }
    }
}

5. epoll 示例（LT 模式） #

c
int epfd = epoll_create(1);
struct epoll_event ev, evs[1024];
ev.events = EPOLLIN; ev.data.fd = listenfd;
epoll_ctl(epfd, EPOLL_CTL_ADD, listenfd, &ev);
while (1) {
    int n = epoll_wait(epfd, evs, 1024, -1);
    for (int i = 0; i < n; i++) {
        int fd = evs[i].data.fd;
        if (fd == listenfd) { confd = accept(fd, ...);
            ev.data.fd = confd; epoll_ctl(epfd, EPOLL_CTL_ADD, confd, &ev); }
        else { recv(fd, buf, ...); send(fd, buf, ...); }
    }
}

ET 模式需在 ev.events 加 EPOLLET，并对每个就绪 fd 用 while (recv(...) > 0) 读到 EAGAIN。

6. 服务器模型：循环 vs 并发 #

  • 循环服务器：依次服务每个客户端，处理完一个才接下一个。TCP 循环服务器实现简单，但当前客户端不结束、其他客户端只能干等，无法并发。
  • 并发服务器（多进程）：fork 子进程专服务一个客户端；父进程需 signal(SIGCHLD, ...) + waitpid(-1, NULL, WNOHANG) 回收，避免僵尸进程。
  • 并发服务器（多线程）：每连接一线程，共享地址空间，需互斥（见 06 篇聊天室）。
  • IO 多路复用并发：单进程用 select/epoll 轮询所有连接，省资源但有请求排队可能（连接数有限时常用）。

7. 小结 #

  • 阻塞模型简单但并发靠多线程；
  • 高并发服务器主流是 epoll（LT/ET）+ Reactor，必要时配合线程池；
  • 真正的异步 IO（Proactor）用得少，常以 epoll 模拟。
