TCP 通信实战 #

整合自《网络进程通信原理》《三次握手/四次挥手》《基于 TCP 的字符串传输程序》《原始套接字》等笔记。抓包验证 + 完整代码 + 底层 raw socket。

1. 三次握手（建立连接） #

客户端                              服务器
  |  SYN  (seq=j)                  |
  | ---------------------------->  |  (SYN_RCVD)
  |  SYN+ACK (seq=k, ack=j+1)     |
  | <----------------------------  |
  |  ACK (ack=k+1)                 |  (ESTABLISHED)
  | ---------------------------->  |  (ESTABLISHED)
  • 客户端 connect 发 SYN，进入 SYN_SEND 并阻塞；服务器 accept 收到后回 SYN+ACK，进入 SYN_RCVD；客户端回 ACK，connect 返回；服务器 accept 返回，连接建立。
  • 即使没有 accept，三次握手也能完成——握手是内核协议栈做的，accept 只是把已建立的连接从队列里取出来。

用 tcpdump 验证（服务器开 9502）：

bash
tcpdump -iany tcp port 9502
telnet 127.0.0.1 9502
# [S]  SYN 包   → 第一次握手
# [S.] SYN+ACK  → 第二次握手
# [.]  ACK      → 第三次握手
# [P]  数据推送  [F]  FIN 关闭  [R]  RST 强制重置

2. 四次挥手（释放连接） #

TCP 全双工，每个方向须单独关闭（半关闭）：

  1. 主动方发 FIN M → 被动方回 ACK；
  2. 被动方数据处理完后发自己的 FIN N → 主动方回 ACK，进入 TIME_WAIT。

为什么握手 3 次、挥手 4 次？ 握手时 SYN 和 ACK 可合并在一个报文；挥手时收到对方 FIN 只表示对方没数据发了，自己可能还有数据要发，所以 ACK 和 FIN 通常分两次发。

为什么 TIME_WAIT 要等 2MSL？ 保证最后那个 ACK 可靠到达；若被动方没收到会重发 FIN，TIME_WAIT 期间能再次响应。

3. TCP 服务器 / 客户端最小框架 #

c
/* server.c —— 监听 8000，回一句话 */
int socket_fd, connect_fd;
struct sockaddr_in servaddr;
socket_fd = socket(AF_INET, SOCK_STREAM, 0);
memset(&servaddr, 0, sizeof(servaddr));
servaddr.sin_family = AF_INET;
servaddr.sin_addr.s_addr = htonl(INADDR_ANY);
servaddr.sin_port = htons(8000);
bind(socket_fd, (struct sockaddr*)&servaddr, sizeof(servaddr));
listen(socket_fd, 10);
while (1) {
    connect_fd = accept(socket_fd, NULL, NULL);
    char buff[4096];
    int n = recv(connect_fd, buff, 4096, 0);
    send(connect_fd, "Hello, you are connected!\n", 26, 0);
    close(connect_fd);
}

c
/* client.c */
int sockfd = socket(AF_INET, SOCK_STREAM, 0);
struct sockaddr_in servaddr;
servaddr.sin_family = AF_INET;
servaddr.sin_port = htons(8000);
inet_pton(AF_INET, argv[1], &servaddr.sin_addr);
connect(sockfd, (struct sockaddr*)&servaddr, sizeof(servaddr));
send(sockfd, "hi\n", 3, 0);
recv(sockfd, buf, 4096, 0);
close(sockfd);

可用 telnet 127.0.0.1 8000 代替自写客户端做快速验证。Ubuntu 下若缺 sys/types.h，apt-get install libc6-dev。

4. 基于 TCP 的字符串传输（教学拆解） #

标准 socket 调用顺序：socket → bind → listen → accept/connect → send/recv → close。几个易错点：

  • socket(AF_INET, SOCK_STREAM, 0) 成功返回非负 sockfd。
  • bind 端口填 0 时内核分配临时端口，需用 getsockname 取回；不指定 IP 时内核在连接/发包时才选本地 IP。
  • connect 触发三次握手；不可达目标会报 No route to host，对端无服务报 Connection refused。
  • getsockname 取本地地址；getpeername 在 fork 出的子进程里取对端地址。

5. 原始套接字（Raw Socket） #

标准 TCP/UDP 编程只碰应用层数据，IP/TCP 头由内核生成。要手动构造报文（协议开发、抓包、安全测试）需用 SOCK_RAW。

5.1 网络层 raw socket（IPPROTO_TCP/UDP/ICMP） #

c
int fd = socket(AF_INET, SOCK_RAW, IPPROTO_TCP); // 须 root
  • 默认不启用 IP_HDRINCL：写入数据从 IP 头之后开始，IP 头由内核填。
  • 启用 IP_HDRINCL：须从 IP 头第一字节手动构造整个包（校验和、标识可交内核）。
c
int on = 1;
setsockopt(fd, IPPROTO_IP, IP_HDRINCL, &on, sizeof(on));

典型实战：构造伪造源 IP 的 TCP SYN 报文做 SYN Flood 模拟（见原笔记 mdos.c，含 IP/TCP 头填充与校验和计算）。注意这仅用于理解协议，切勿用于攻击。

5.2 链路层 raw socket（PF_PACKET） #

要在网卡物理层收发含 MAC 头 的帧，用 PF_PACKET：

c
int sock = socket(PF_PACKET, SOCK_RAW, htons(ETH_P_ALL));
// SOCK_RAW：收发完整帧（含 14 字节 MAC 头），发送须自构 MAC 头
// ETH_P_IP(0x0800) 只收 IPv4；ETH_P_ARP(0x0806) 只收 ARP；ETH_P_ALL 收所有

抓全网流量需开启混杂模式：

c
struct ifreq ethreq; strncpy(ethreq.ifr_name, "eth0", IFNAMSIZ);
ioctl(sock, SIOCGIFFLAGS, &ethreq);
ethreq.ifr_flags |= IFF_PROMISC;
ioctl(sock, SIOCSIFFLAGS, &ethreq);

原笔记含完整 手动封装 ARP 请求 示例：拼装以太网头（h_dest=FF:FF:FF:FF:FF:FF 广播）+ ARP 头，经 sendto 发出做 IP→MAC 查询。
