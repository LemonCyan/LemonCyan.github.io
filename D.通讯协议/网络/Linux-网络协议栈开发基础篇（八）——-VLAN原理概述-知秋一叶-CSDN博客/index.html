Linux网络协议栈开发：VLAN原理、802.1Q头部格式与交换机转发机制 #

在传统的局域网（LAN）拓扑结构中，所有由 Hub（集线器）、网桥或交换机相连的终端都处于同一个物理网段内，构成一个统一的广播域。如果不同网段之间需要进行通信，必须通过三层路由器进行中转。

然而，随着局域网规模的扩大，完全依赖路由器隔离广播域暴露出两大缺陷：

  1. 路由开销大，延迟增加：跨网段的数据包必须经过路由器的三层寻址与转发，导致吞吐率下降。
  2. 物理划分机械化：广播域的划分严格受限于终端的物理连接位置，无法按照逻辑工作组的带宽需求或安全要求进行动态划分。

为了解决这些问题，VLAN (Virtual Local Area Network，虚拟局域网) 技术应运而生。它允许在不使用三层路由器的前提下，在二层交换机内部实现广播域的逻辑隔离，并且能突破终端物理位置的限制。

一、 IEEE 802.1Q 标准与 VLAN 头部格式 #

为了支持 VLAN 标记，IEEE 802.1Q 标准对传统的以太网帧结构进行了修改。它在普通以太网帧的 SA（源 MAC 地址） 之后插入了 4 字节（32 比特）的 VLAN Tag (或称 VLAN Header)：

+-------------------+-------------------+-------------------+-------------------+-------------------+
|  Destination MAC  |    Source MAC     |    VLAN Tag       |    Type / Length  |      Payload      |
|    (6 Bytes)      |    (6 Bytes)      |    (4 Bytes)      |     (2 Bytes)     |  (46-1500 Bytes)  |
+-------------------+-------------------+-------------------+-------------------+-------------------+
                                                  |
                         +------------------------+------------------------+
                         |                                                 |
            +------------+------------+------------+-----------------------+
            |      TPID (16 bits)     | PRI (3 bits)| CFI (1 bit)| VID (12 bits)  |
            +-------------------------+------------+------------+-----------+

4 字节 VLAN Tag 字段拆解： #

  1. TPID (Tag Protocol Identifier)：16 比特，其值固定为 0x8100。用来标识这是一个带有 802.1Q 标签的以太网帧。
  2. PRI (Priority)：3 比特，表示 802.1p 优先级（0-7），用于服务质量（QoS）队列调度。
  3. CFI (Canonical Format Indicator)：1 比特，在以太网中通常为 0，用于兼容令牌环网。
  4. VID (VLAN Identifier)：12 比特，VLAN ID。它决定了数据帧所属的逻辑网络。
    • 12 比特所能表示的最大范围是 0 到 4095。
    • 其中 0 和 4095 保留，可用的 VLAN ID 范围是 1 到 4094。

二、 交换机端口类型：Access 与 Trunk #

带有 VLAN 划分功能的工业级交换机，其物理端口主要分为两类：

1. Access Port (接入端口) #

  • 应用场景：用于连接普通的终端计算机、打印机等不识别 VLAN 标签的设备。
  • Tag 处理机制：
    • 接收（Ingress）：当交换机从 Access 端口收到一个**未带标签（Untagged）**的数据帧时，会强制为其打上该端口所关联的 VLAN Tag（PVID）。
    • 发送（Egress）：当交换机准备从 Access 端口转发一个数据帧给终端时，会**自动剥离（Untag）**该帧上的 VLAN Tag。终端设备不会察觉到 VLAN 的存在。

2. Trunk Port (干道端口) #

  • 应用场景：用于交换机与交换机之间、或者交换机与三层路由器（单臂路由）之间的互连。
  • Tag 处理机制：
    • 保留标签：Trunk 端口允许携带多个不同 VLAN ID 的 Tagged 帧通过。在发送和接收帧时，全部保留 802.1Q Tag。
    • 作用：使得一条物理线缆可以承载成百上千个不同 VLAN 的流量，跨交换机的同 VLAN 成员借此实现直连通信。

三、 VLAN 划分模式 #

1. 基于端口的划分 (Untagged VLAN) #

  • 在交换机上创建若干个 VLAN，并将不同的物理端口直接指定划分到对应的 VLAN。
  • PVID (Port VLAN ID)：每个 Access 端口在某一时刻只能有一个 PVID。
  • 交换机在转发从该端口进入的 Untagged 帧时，完全依据该端口的 PVID 进行查表。
  • 局限性：若两个交换机要打通两个 VLAN，必须在它们之间连两根网线（每个 VLAN 占用一根）。

2. Tagged VLANs 模式 #

  • 交换机端口支持接收并转发带有 Tag 的帧（Tagged Port）。
  • 连接在此物理端口上的网络设备（如另一台交换机）必须兼容 802.1Q 协议，能解析和还原帧头部的 VID 字段。
  • 依靠此模式，只需连接一根 Trunk 网线便可实现跨交换机的多 VLAN 隔离通信。

四、 💡 带 VLAN 的二层交换机转发机制 #

二层交换机最核心的三个功能是：MAC地址学习、数据帧转发（单播/广播/洪泛）、标签添加/剥离。

在配置了 VLAN 后，传统的 MAC 地址学习与转发逻辑升级如下：

1. 升级版的 MAC 地址表项 #

传统交换机 MAC 表仅记录：[MAC 地址] -> [物理端口端口]。
配置 VLAN 后，MAC 地址表升级为三维记录：[MAC 地址] + [VLAN ID] -> [物理端口]。

2. 帧接收时的判定规则 #

  • 从 Access Port 读入帧：必须是 Untagged 帧，否则丢弃。进入交换机后，自动打上端口 PVID。
  • 从 Trunk Port 读入帧：必须是 Tagged 帧，否则丢弃。

3. 数据帧转发与洪泛流程图 #

graph TD
    A[交换机从 Port 1 收到数据帧] --> B{读取帧携带的 VLAN ID}
    B --> C{目的 MAC 地址是否在 MAC 表中?}
    
    C -- 是 --> D{该表项对应的 VLAN ID 是否匹配?}
    D -- 是 --> E[直接从目标物理端口转发出]
    D -- 否 --> F[在相同 VLAN ID 的所有端口中进行洪泛]
    
    C -- 否 --> F
    
    E --> G{出站端口类型?}
    F --> G
    
    G -- Access Port --> H[剥离 802.1Q 标签发送给终端]
    G -- Trunk Port --> I[保留 802.1Q 标签发往下一节点]
  • 精确单播：只有当 [目的 MAC] 且 [VLAN ID] 同时匹配 MAC 表中的某一行时，才进行精确端口单播。
  • 安全洪泛（隔离广播）：如果目的地址是广播地址、组播地址、或者表项中找不到的未知单播，交换机只会在拥有相同 VLAN ID 的所有物理端口（以及允许该 VLAN 通过的 Trunk 端口）之间进行广播拷贝，其它 VLAN 对应的端口完全收不到该流量。
