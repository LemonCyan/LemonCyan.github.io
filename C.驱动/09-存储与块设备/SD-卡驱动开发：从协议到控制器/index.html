与 eMMC 篇分工：《Linux MMC 子系统与 eMMC 驱动调试》讲 eMMC——MMC 协议、BGA 封装、不可插拔、boot 分区/RPMB/CQE。SD 是另一套协议，但两者共用同一个祖传总线模型和同一套 Linux 子系统代码。本篇把 SD 独有部分讲透，重叠部分（mmc_host 结构、request 回调模型）只讲到能看懂 SD 这条路径，细节去 eMMC 篇对照。

代码基线：素材基于 3.x（linux-2.6.38.2、Linux-3.14），HOST 用 s3cmci.c（S3C2410/2440）与 msm_sdcc.c（高通 MSM）为例。4.x/5.x 有变化处逐处标注，没核实过的写「未验证」。

一、SD 卡是什么：从 MMC 到 SD 的演进 #

MMC 是 MultiMediaCard，非易失存储器件，标准卡 24mm×32mm×1.4mm，容量大、功耗低、传输快。SD 是 Secure Digital Memory Card，在 MMC 基础上发展而来，加了两个主要特色：强调数据安全，可以设定所存数据的使用权限防止被复制；传输速度比 2.11 版 MMC 卡快。物理上 24mm×32mm×2.1mm，比 MMC 厚一点，但在数据传输和物理规范上向前兼容 MMC——所有支持 SD 卡的设备也支持 MMC 卡，SD 卡和 2.11 版 MMC 卡完全兼容。SDIO 是在 SD 标准上定义的外设接口，与 SD 卡规范的重要区别是增加了低速标准：低速卡只需要 SPI 和 1 位 SD 传输模式，目标是用最小硬件开销支持低速 IO。MCI 是 Multimedia Card Interface，MMC/SD/SDIO 定义的接口都属于它，这个词在驱动代码里到处出现（s3cmci.c、pxamci.c），别以为是另一种卡。

维度 MMC SD SDIO
定位 纯存储 存储 + 内容保护 外设接口（可带存储 combo）
数据线 1/4/8 位 1/4 位 1/4 位（低速卡 1 位或 SPI）
保护机制 无（后期有 RPMB） 版权保护、写保护开关 无存储语义
内核卡类型 MMC_TYPE_MMC(0) MMC_TYPE_SD(1) MMC_TYPE_SDIO(2)，combo 3
识别命令 CMD1 CMD8 + ACMD41 CMD5（IO_SEND_OP_COND）

常见 SDIO 外设：Wi-Fi 卡、CMOS sensor 卡、GPS 卡、GSM/GPRS modem 卡、蓝牙卡、Radio/TV 卡。一句话：SD = MMC 的总线 + 内容保护 + 更快的时序 + 一套自己的寄存器。

二、SD 卡的物理结构与引脚 #

SD BUS：D0-D3 数据传送（1 位模式只用 D0）、CMD 双向命令线（命令与响应都走它）、CLK 主机给卡的时钟、VDD/VSS 电源与地。SPI BUS：CLK、DATAIN（主机到卡）、DATAOUT（卡到主机）、CS。SPI 模式丢掉 4 位并行带宽，换来「两根线就能读写 SD 卡」；内核走这条路的是 mmc_spi.c，主机能力位打 MMC_CAP_SPI，之后 mmc_host_is_spi(host) 到处为真，CMD8、CMD11 电压切换等流程直接跳过。

脚号 名称 类型 作用
1 CD/DAT3 I/O/PP 卡检测 / 数据线 3
2 CMD PP 命令与响应
3 VSS1 S 地
4 VDD S 电源
5 CLK I 时钟
6 VSS2 S 地
7 DAT0 I/O/PP 数据线 0
8 DAT1 I/O/PP 数据线 1
9 DAT2 I/O/PP 数据线 2

SPI 模式换名字：1 是 CS，2 是 DI（入卡），7 是 DO（出卡）。这解释了为什么 SPI 只能 1 位——物理上只有 DI/DO 两根数据线。CD 和 DAT3 复用：4 位模式下 DAT3 要搬数据，所以卡检测必须用独立机械触点或专用引脚，不能拿 DAT3 电平当插拔信号。

板上怎么连：以 Exynos4412 开发板为例，SD 卡设备按 SDIO 总线方式连接，另用 EINT7 作卡检测控制，插拔都触发中断。

三、SD 总线的通信协议 #

协议把卡的工作切成两个阶段、十种状态。卡识别阶段：idle（复位后初始态）、ready（上电完成、电压协商过）、ident（已发 CID，等主机给地址）、stby（已拿 RCA，未被选中）、ina（CMD15 置不活动）。数据传输阶段：tran（被选中，可读写）、data（向主机送数据，CMD17/CMD18）、rcv（从主机收数据，CMD24/CMD25）、prg（数据已收，正在写内部 Flash）、dis（从总线断开）。这些状态就编码在 R1 响应的 CURRENT_STATE 位里：

c
/* include/linux/mmc/mmc.h */
#define R1_CURRENT_STATE(x)	((x & 0x00001E00) >> 9)	/* 4 bits */
#define R1_STATE_IDLE	0
#define R1_STATE_READY	1
#define R1_STATE_IDENT	2
#define R1_STATE_STBY	3
#define R1_STATE_TRAN	4
#define R1_STATE_DATA	5
#define R1_STATE_RCV	6
#define R1_STATE_PRG	7
#define R1_STATE_DIS	8

mmc_send_status()（CMD13）读回的 resp[0] 直接和这些宏比对就知道卡在哪。卡不响应、写得慢、初始化卡住，先发 CMD13。状态迁移（来自 SD 2.0 协议的卡识别模式迁移图，每段都能在内核代码里找到对应调用）：

text
上电/复位 --CMD0--> idle
idle --CMD8 / ACMD41 成功--> ready
ready --CMD2(读 CID)--> ident
ident --CMD3(设 RCA)--> stby
stby --CMD7(选中该 RCA)--> tran
tran --CMD7(RCA=0 或别的 RCA)--> stby
tran --CMD17/18--> data --传输完--> tran
tran --CMD24/25--> rcv --数据收完--> prg --内部写完--> tran
stby/tran --CMD15--> ina

两个阶段的边界：识别阶段结束于 CMD3 成功——卡有了 RCA，主机可以精确点名（SD 卡槽只插一张卡，这个能力用在 MMC 多卡场景），它决定了 CMD7 之后命令参数格式 [31:16] = RCA；数据传输阶段开始于 CMD7 选中卡、进入 tran。

四、命令、响应与数据线 #

一条 SD 命令固定 48 位，在 CMD 线上串行送出：

text
 0    1       6  7                        8            39 40      45 46  47
 +----+-------+--+------------------------+-------------+---------+--+-----+
 | 0  | 1 1 0 |  |      command index     |  argument   |   CRC7  |1 | end |
 +----+-------+--+------------------------+-------------+---------+--+-----+
  起始  传输位    命令号(6bit)              参数(32bit)    CRC7    结束

起始位 0 + 传输位 1；6 位命令号（CMD0/CMD8 那个号）；32 位参数即 cmd->arg；7 位 CRC 只覆盖命令内容、不含起始位，CMD0 和 CMD8 的 CRC 是固定的。响应在命令后紧接着返回：

格式 长度 内容 典型命令
R1 48 位 卡状态字（含 CURRENT_STATE） CMD7、CMD13、CMD16
R1b 48 位 R1 + DAT0 拉低表示忙 CMD12、CMD38
R2 136 位 128 位寄存器内容（CID 或 CSD） CMD2、CMD9、CMD10
R3 48 位 OCR 寄存器内容 ACMD41
R6 48 位 发布后的 RCA + 状态 CMD3
R7 48 位 电压/回声模式 CMD8

内核里的标志位（include/linux/mmc/core.h，具体位值以你手上的内核头文件为准，这里只写语义）：MMC_RSP_PRESENT 有响应；MMC_RSP_136 是 136 位长响应（R2），需拼 4 个 u32；MMC_RSP_CRC 校验响应 CRC；MMC_RSP_BUSY 表示响应后卡在数据线上拉忙（R1b）；MMC_RSP_OPCODE 表示响应带回命令号（R6/R7）；MMC_CMD_AC 带地址命令无数据；MMC_CMD_ADTC 带地址命令且有数据传输；MMC_CMD_BC/MMC_CMD_BCR 广播命令，无响应/有响应。

c
/* drivers/mmc/core/core.c, mmc_send_cxd_native() */
cmd.opcode = opcode;                   /* MMC_SEND_CID，即 10 */
cmd.arg = arg;                         /* 识别阶段 arg = 0 */
cmd.flags = MMC_RSP_R2 | MMC_CMD_AC;   /* R2 长响应，带地址命令 */
mmc_wait_for_cmd(host, &cmd, MMC_CMD_RETRIES);
memcpy(cxd, cmd.resp, sizeof(u32) * 4);  /* 4 个 u32 = 128 位 */

MMC_RSP_R2 是 MMC_RSP_PRESENT | MMC_RSP_136 | MMC_RSP_CRC 的组合宏。这行 memcpy 就是「长响应怎么落到内存」的答案。

三个「同号不同义」必须记住：CMD8（MMC 是 SEND_EXT_CSD，SD 是 SEND_IF_COND）、CMD5（MMC 是 SLEEP_AWAKE，SDIO 是 IO_SEND_OP_COND）、CMD6（SD 和 eMMC 都叫 SWITCH，但 SD 设位宽用 ACMD6，eMMC 用 CMD6 写 EXT_CSD 的 BUS_WIDTH）。

ACMD 机制：先发 CMD55（参数带 RCA），告诉卡「下一条属于应用命令集」，再发的 CMD41 就被解释成 ACMD41。

c
/* drivers/mmc/core/core.c */
int mmc_wait_for_app_cmd(struct mmc_host *host, struct mmc_card *card,
			 struct mmc_command *cmd, int retries)
{
	mmc_app_cmd(host, card);   /* 先发 MMC_APP_CMD，即 CMD55 */
	mrq.cmd = cmd;
	cmd->data = NULL;
	mmc_wait_for_req(host, &mrq);
	/* ... 重试逻辑 ... */
}

日志里看到 CMD55 紧跟 CMD41，不要以为是两件独立的事。数据搬运用 DAT0-DAT3（4 位）或只用 DAT0（1 位），每块后跟 CRC16。块长：SDSC 默认 512 字节、可用 CMD16 改；SDHC/SDXC 固定 512 字节，CMD16 对它们无效——CSD 解码里块寻址卡直接跳过 READ_BL_LEN。

五、SD 卡的寄存器：CID、CSD、SCR、RCA #

寄存器 长度 读它用什么命令 内容
CID 128 位 CMD2、CMD10 厂商、OEM、产品名、序列号、日期
RCA 16 位 CMD3 写入，R6 返回 卡的相对地址
CSD 128 位 CMD9 传输速率、容量、块长、命令集
SCR 64 位 ACMD51 物理层版本、支持位宽
SSR 512 位 ACMD13 分配单元、擦除超时
OCR 32 位 ACMD41 的 R3 响应 电压范围、容量类型

void mmc_decode_cid(struct mmc_card *card)
{
	u32 *resp = card->raw_cid;

	add_device_randomness(&card->raw_cid, sizeof(card->raw_cid));

	card->cid.manfid		= unstuff_bits(resp, 120, 8);
	card->cid.oemid			= unstuff_bits(resp, 104, 16);
	card->cid.prod_name[0]		= unstuff_bits(resp, 96, 8);
	card->cid.prod_name[1]		= unstuff_bits(resp, 88, 8);
	card->cid.prod_name[2]		= unstuff_bits(resp, 80, 8);
	card->cid.prod_name[3]		= unstuff_bits(resp, 72, 8);
	card->cid.prod_name[4]		= unstuff_bits(resp, 64, 8);
	card->cid.hwrev			= unstuff_bits(resp, 60, 4);
	card->cid.fwrev			= unstuff_bits(resp, 56, 4);
	card->cid.serial		= unstuff_bits(resp, 24, 32);
	card->cid.year			= unstuff_bits(resp, 12, 8);

}

unstuff_bits(resp, start, size) 从 resp[0] 最高位往下数 start 位、取 size 位。素材第三篇这里写错了：

c
/* 原文（错）：serial 偏移 16、month 偏移 12 且 4 位、year 偏移 8 且 4 位 + 1997 */
card->cid.serial = UNSTUFF_BITS(resp, 16, 32);
card->cid.month  = UNSTUFF_BITS(resp, 12, 4);
card->cid.year   = UNSTUFF_BITS(resp, 8, 4) + 1997;

三处全错。序列号偏移应为 24；月份偏移应为 8；年份是 8 位、偏移 12、基准年 2000。素材照抄了 MMC 的 CID 解码（MMC v1-v4 的 year 才是 4 位 + 1997 那一套）。照它写，卡的生产日期一定读错——sysfs 里 date 打出 07/2199 就是这种症状。

C_SIZE_MULT 按 3 位写（内核 unstuff_bits(resp, 47, 3) 取 3 位）；部分二手资料写 4 位，此位宽与原始规范对照未验证，以代码为准。TRAN_SPEED 和 TAAC 编码方式相同：高 3 位指数、低 4 位尾数，TRAN_SPEED = 0x32（指数 3、尾数 2）算出 10^7 × 12。

c
/* drivers/mmc/core/sd.c */
static const unsigned int tran_exp[] = {
	10000,		100000,		1000000,	10000000,
	0,		0,		0,		0
};
static const unsigned char tran_mant[] = {
	0,	10,	12,	13,	15,	20,	25,	30,
	35,	40,	45,	50,	55,	60,	70,	80,
};

static int mmc_decode_csd(struct mmc_card *card, bool is_sduc)
{
	struct mmc_csd *csd = &card->csd;
	unsigned int e, m, csd_struct;
	u32 *resp = card->raw_csd;

	csd_struct = unstuff_bits(resp, 126, 2);

	switch (csd_struct) {
	case 0:
		m = unstuff_bits(resp, 115, 4);
		e = unstuff_bits(resp, 112, 3);
		csd->taac_ns	 = (taac_exp[e] * taac_mant[m] + 9) / 10;
		csd->taac_clks	 = unstuff_bits(resp, 104, 8) * 100;

		m = unstuff_bits(resp, 99, 4);
		e = unstuff_bits(resp, 96, 3);
		csd->max_dtr	  = tran_exp[e] * tran_mant[m];
		csd->cmdclass	  = unstuff_bits(resp, 84, 12);

		e = unstuff_bits(resp, 47, 3);
		m = unstuff_bits(resp, 62, 12);
		csd->capacity	  = (1 + m) << (e + 2);

		csd->read_blkbits = unstuff_bits(resp, 80, 4);
		csd->read_partial = unstuff_bits(resp, 79, 1);
		csd->write_misalign = unstuff_bits(resp, 78, 1);
		csd->read_misalign = unstuff_bits(resp, 77, 1);
		csd->dsr_imp = unstuff_bits(resp, 76, 1);
		csd->r2w_factor = unstuff_bits(resp, 26, 3);
		csd->write_blkbits = unstuff_bits(resp, 22, 4);
		csd->write_partial = unstuff_bits(resp, 21, 1);
		/* ... erase_size 计算 ... */
		break;
	case 1:
	case 2:
		/* 块寻址卡：SDHC / SDXC / SDUC */
		mmc_card_set_blockaddr(card);
		/* taac 置 0，read_blkbits/write_blkbits 固定 9，erase_size 固定 1 */
		break;
	}
	return 0;
}

capacity = (1 + m) << (e + 2) 里 e 是 C_SIZE_MULT、m 是 C_SIZE。<< (e + 2) 而非 << e，是 CSD v1.0 容量公式带的隐含块长因子：capacity(字节) = (C_SIZE + 1) × 2^(C_SIZE_MULT + 2) × 2^READ_BL_LEN。内核 capacity 单位是 512 字节扇区，所以 (1+m) << (e+2) 之后还要再乘 2^(read_blkbits - 9)，这一步在 mmc_blk 里做。块寻址卡的 capacity 直接是 (1 + C_SIZE) << 10 个扇区，因为 C_SIZE 单位就是 512KB。

c
int mmc_decode_scr(struct mmc_card *card)
{
	struct sd_scr *scr = &card->scr;
	unsigned int scr_struct;
	u32 resp[4];

	resp[3] = card->raw_scr[1];
	resp[2] = card->raw_scr[0];

	scr_struct = unstuff_bits(resp, 60, 4);
	if (scr_struct != 0)
		return -EINVAL;

	scr->sda_vsn = unstuff_bits(resp, 56, 4);
	scr->bus_widths = unstuff_bits(resp, 48, 4);
	if (scr->sda_vsn == SCR_SPEC_VER_2)
		scr->sda_spec3 = unstuff_bits(resp, 47, 1);

	if (scr->sda_spec3) {
		scr->sda_spec4 = unstuff_bits(resp, 42, 1);
		scr->sda_specx = unstuff_bits(resp, 38, 4);
	}

	card->erased_byte = unstuff_bits(resp, 55, 1) ? 0xFF : 0x0;

	if (scr->sda_spec4)
		scr->cmds = unstuff_bits(resp, 32, 4);
	else if (scr->sda_spec3)
		scr->cmds = unstuff_bits(resp, 32, 2);

	/* SD Spec says: any SD Card shall set at least bits 0 and 2 */
	if (!(scr->bus_widths & SD_SCR_BUS_WIDTH_1) ||
	    !(scr->bus_widths & SD_SCR_BUS_WIDTH_4))
		return -EINVAL;

	return 0;
}

resp[3] = raw_scr[1]; resp[2] = raw_scr[0]; 这两行是必须的：SCR 只有 64 位，要凑成 128 位的 resp[4] 数组才能用 unstuff_bits（它按 4 个 u32 的「128 位窗口」数位）。所以 SCR 内容落在 resp[2]、resp[3]，resp[0]、resp[1] 是零——这就解释了为什么偏移是 60、56、48 这些「从 64 位窗口数」的数。SD_SCR_BUS_WIDTH_1 = (1<<0)、SD_SCR_BUS_WIDTH_4 = (1<<2) 定义在 struct sd_scr 里。SD 规范要求任何 SD 卡都必须置上这两位，内核在这里做合法性检查——读出来没这两位就是通信出了问题，不是「卡不支持 4 位」。这是排查「4 位模式挂了」的第一道筛子。SD_SPEC3 决定后面要不要跑 1.8V 电压切换和 UHS，读错这个位，UHS 卡只能跑默认速度。

RCA 与 OCR #

RCA 是 16 位相对地址，主机发 CMD3 分配，卡的 R6 响应带回最终值。SD 卡槽只有一张卡，内核固定 RCA = 1：

c
/* drivers/mmc/core/sd.c, mmc_sd_init_card() */
if (!mmc_host_is_spi(host)) {
	err = mmc_send_relative_addr(host, &card->rca);
	if (err)
		goto free_card;
}

/* drivers/mmc/core/core.c, mmc_send_status() */
cmd.arg = card->rca << 16;

OCR 不是「读」出来的寄存器，而是 ACMD41/CMD1 的响应内容：[31] 是 CARD_POWER_UP（1 = 上电完成可接受后续命令，0 = 还忙，需重发 ACMD41）；[30] 是 CCS（1 = SDHC/SDXC 块寻址，0 = SDSC 字节寻址）；[29] 是 UHS-II 支持；[24] 是 S18A（支持 1.8V 信令切换）；[23] 是 XPC（支持 1.8V 供电）；[15:0] 是卡的 VDD 窗口。主机侧 ocr_avail 的位定义在 include/linux/mmc/host.h，MMC_VDD_32_33 = 0x00100000、MMC_VDD_33_34 = 0x00200000。

CMD8 除了探测 SD 2.0，还把主机支持的电压和校验模式回送给卡，卡再原样回显（第 12 位）。内核靠这个回显判断卡是不是真 SD 2.0：

六、SD 卡的初始化流程 #

初始化由三层调用叠起来：mmc_rescan_try_freq() → mmc_attach_sd() → mmc_sd_init_card()。

c
/* drivers/mmc/core/core.c, 3.x 语义 */
static int mmc_rescan_try_freq(struct mmc_host *host, unsigned freq)
{
	host->f_init = freq;     /* 先定时钟 */
	mmc_power_up(host, host->ocr_avail);
	mmc_go_idle(host);       /* CMD0 -> idle */
	mmc_send_if_cond(host, host->ocr_avail);
	if (!mmc_attach_sd(host))   /* SD 这条路能走通就结束 */
		return 0;
	/* 不行再试 MMC */
}

为什么叫「试」：板子的时钟分频、卡槽接触、卡的时钟容忍度都会让它只在特定频率下工作。扫描循环从 f_min 往上试，试到哪个能识别就用哪个。这就是「卡插上去认不到，但换个频率就认到」的根。

c
/* drivers/mmc/core/sd.c */
int mmc_attach_sd(struct mmc_host *host)
{
	int err;
	u32 ocr, rocr;

	WARN_ON(!host->claimed);

	err = mmc_send_app_op_cond(host, 0, &ocr);   /* ACMD41，探测卡 */
	if (err)
		return err;

	mmc_attach_bus(host, &mmc_sd_ops);           /* 绑定 SD 总线操作集 */
	if (host->ocr_avail_sd)
		host->ocr_avail = host->ocr_avail_sd;

	ocr &= ~0x7FFF;                              /* 屏蔽超规范的电压位 */
	rocr = mmc_select_voltage(host, ocr);        /* 选出双方都支持的电压 */
	if (!rocr) {
		err = -EINVAL;
		goto err;
	}

	err = mmc_sd_init_card(host, rocr, NULL);    /* 真正初始化卡 */
	if (err)
		goto err;

	mmc_release_host(host);
	err = mmc_add_card(host->card);              /* 注册到 mmc 总线 */
	if (err)
		goto remove_card;
	mmc_claim_host(host);
	return 0;
err:
	mmc_detach_bus(host);
	return err;
}

mmc_send_app_op_cond(host, 0, &ocr) 是「这张卡能不能响应 SD 上电协商」的判据：发 CMD55 + ACMD41，成功返 0，失败返负。SD 卡成功，MMC 卡失败（MMC 只认 CMD1），SDIO 卡不走这条。「试谁成功」就是「识别成什么类型」的全部逻辑。 mmc_select_voltage() 把卡报的 OCR 电压窗口和主机 ocr_avail 求交集选出一个位，交不上返 0，整个初始化失败。SD 卡槽供电固定 3.3V，这里其实就在检查「卡支持 3.3V 吗」。

c
/* drivers/mmc/core/sd.c, mmc_sd_init_card() 骨架 */
static int mmc_sd_init_card(struct mmc_host *host, u32 ocr,
			    struct mmc_card *oldcard)
{
	struct mmc_card *card;
	int err;
	u32 cid[4];
	u32 rocr = 0;

	WARN_ON(!host->claimed);

	err = mmc_sd_get_cid(host, ocr, cid, &rocr);   /* CMD0/CMD8/ACMD41/CMD2 */
	if (err)
		return err;

	if (oldcard) {
		if (memcmp(cid, oldcard->raw_cid, sizeof(cid)) != 0)
			return -ENOENT;
		card = oldcard;
	} else {
		card = mmc_alloc_card(host, &sd_type);
		if (IS_ERR(card))
			return PTR_ERR(card);

		card->ocr = ocr;
		card->type = MMC_TYPE_SD;
		memcpy(card->raw_cid, cid, sizeof(card->raw_cid));
	}

	if (!mmc_host_is_spi(host)) {                  /* CMD3 */
		err = mmc_send_relative_addr(host, &card->rca);
		if (err)
			goto free_card;
	}

	if (!oldcard) {
		err = mmc_sd_get_csd(card, false);         /* CMD9 + 解码 */
		if (err)
			goto free_card;
		mmc_decode_cid(card);
	}

	if (!mmc_host_is_spi(host)) {                  /* CMD7 */
		err = mmc_select_card(card);
		if (err)
			goto free_card;
	}

	err = mmc_sd_setup_card(host, card, oldcard != NULL);
	if (err)
		goto free_card;

	/* 后面是 UHS 切换 / 高速切换 / 4 位模式，见第七节 */
	host->card = card;
	return 0;

free_card:
	if (!oldcard)
		mmc_remove_card(card);
	return err;
}

三个容易看漏的点。mmc_sd_get_cid() 一个人干了 CMD0、CMD8、ACMD41、CMD2 四件事，函数名却只叫「get cid」——因为「拿到 CID」是目的，前三条是前置条件，只看函数名会奇怪「CMD8 在哪」。oldcard 是「重新初始化」路径：resume 或硬件复位后内核带着 oldcard 再调一次，比对 CID 是否一致，一致说明还是那张卡，不一致说明卡被换了，返 -ENOENT 让上层重来。WARN_ON(!host->claimed) 在抓「调用者忘了 claim host」——host 是总线资源的独占锁，所有在总线上发命令的代码都必须在 claim 之后调用。

CMD2 的响应是 136 位、CMD3 是 48 位，硬件上走不同路径。S3C2440 那类控制器里，命令控制寄存器有个 LONGRSP 位专门标记长响应：

c
/* drivers/mmc/host/s3cmci.c, s3cmci_send_command() */
ccon |= S3C2410_SDICMDCON_SENDERHOST | S3C2410_SDICMDCON_CMDSTART;
if (cmd->flags & MMC_RSP_PRESENT)
	ccon |= S3C2410_SDICMDCON_WAITRSP;
if (cmd->flags & MMC_RSP_136)
	ccon |= S3C2410_SDICMDCON_LONGRSP;
writel(ccon, host->base + S3C2410_SDICMDCON);

MMC_RSP_136 就是这个开关：置上，硬件把 136 位都收进 FIFO/寄存器；不置，只收 48 位。cmd->flags 设错，CMD2 会返回全 0 或全 F，后面解析 CID 全是垃圾。

c
static bool mmc_sd_use_tuning(struct mmc_card *card)
{

		return false;

	switch (card->host->ios.timing) {
	case MMC_TIMING_UHS_SDR50:
	case MMC_TIMING_UHS_SDR104:
		return true;
	case MMC_TIMING_UHS_DDR50:
		return !mmc_card_no_uhs_ddr50_tuning(card);
	}
	return false;
}

SPI 模式下 CMD19 不存在，直接 false；DDR50 的 tuning 可选，取决于具体实现与 errata。

八、Linux SD/MMC 驱动的分层 #

};

三套「设备—驱动匹配」规则：控制器是 platform 设备，卡是 mmc 设备，SDIO 功能是 sdio 设备。一张 SD 卡从插入到 /dev/mmcblk0 出现，要跨过其中两条。dev_attrs 在 4.x 之后被 device_groups 逐步取代，class_create 接口也变过，看老代码不必纠结这个字段。

{
	struct mmc_host *host;

	host = kzalloc(sizeof(struct mmc_host) + extra, GFP_KERNEL);
	if (!host)
		return NULL;

	/* 建立 kobject */
	host->parent = dev;
	host->class_dev.parent = dev;
	host->class_dev.class = &mmc_host_class;
	device_initialize(&host->class_dev);

	host->max_req_size = PAGE_CACHE_SIZE;

mmc_priv() 在 5.x 之后有了配套的 mmc_from_priv()（用 container_of 反查），mmc_alloc_host() 换成了 devm_mmc_alloc_host()（托管分配，remove 时自动释放）。用 5.x 写新驱动，alloc/free 那一对都不用手写。INIT_DELAYED_WORK(&host->detect, mmc_rescan) 是整个热插拔机制的发源地——之后任何地方只要调 mmc_schedule_delayed_work(&host->detect, delay)，就会在 delay 之后跑到 mmc_rescan。host->max_segs = 1 要特别注意：它限制一次请求只能用 1 个 scatterlist 段。S3C2440 这类控制器没有散列 DMA，只能一段一段搬。你的控制器支持多段 DMA 的话这个值要调大，否则块层会把大请求拆成一堆小请求，性能被白白吃掉。

版本演进：ops 与 bus_ops 的拆合 #

3.x 时代 struct mmc_host 里同时有 ops（控制器操作）和 bus_ops（总线操作），bus_ops 由 CORE 层在 attach 时绑定：

c
	struct mmc_host_ops	*ops;
	...
	const struct mmc_bus_ops *bus_ops;	/* 当前总线驱动 */
	unsigned int		bus_refs;	/* 引用计数 */

5.x 时代这一族从 mmc_host 里整体搬走了——v5.4 的 include/linux/mmc/host.h 里已经没有 bus_ops 字段。搬进了内部结构，mmc_bus_get()/mmc_bus_put()/mmc_attach_bus()/mmc_detach_bus() 都改为操作那个私有容器。迁移年份只写「4.19 之后」：我在 v4.17、v4.18、v4.19、v5.3、v5.4、v5.5 六个版本的 include/linux/mmc/host.h 上逐一核对过，v4.19 的 struct mmc_host 里 bus_ops/bus_dead/bus_refs 仍在，v5.3 里已无。中间具体哪次提交、落在 5.0/5.1/5.2 哪一个小版本，提交哈希未验证。按结构体所在 CCF 提交线索看，是 Uwe Kleine-König 那组「把 mmc_host 字段私有化」的补丁集。

影响很直接：写 5.x 的 HOST 驱动，你的驱动里不能再碰 host->bus_ops（编译就报错，字段不公开了）；也不需要自己调 mmc_attach_bus()（CORE 层的 mmc_attach_sd() 会调）；你要写的只是 host->ops = &your_ops; 这一句。3.x 老代码（包括本篇素材里到处出现的 host->bus_ops->detect(host)）在 5.x 上直接编不过，这不是你写错了，是接口变了。

power_restore 这个名字在 3.x 后期就消失了，被 resume + mmc_sd_init_card(host, ocr, oldcard) 的组合取代。suspend = NULL 在 3.x 早期是允许的（表示不做事），但现代内核靠 suspend 做规范下电，置 NULL 会导致挂起时卡状态丢失。

成员 触发时机 SD 的实现在做什么
remove 卡被拔出、或 host 注销 注销 mmc_card，做一次正常下电
detect mmc_rescan 判定「卡是否还在」 发 CMD13 探活，失败就 remove + detach_bus
pre_suspend 系统挂起前（4.x 加） 一般 NULL
suspend 系统挂起 发 Power Off Notification 或 CMD7 取消选中，然后下电
resume 系统恢复 mmc_power_up() + mmc_sd_init_card(host, ocr, oldcard)
runtime_suspend/runtime_resume 运行时 PM 只在 MMC_CAP_AGGRESSIVE_PM 下干活
alive 判断卡是否还在 就是 mmc_send_status()
shutdown 系统关机 同 suspend
hw_reset 硬件复位卡 power cycle + 重新 init
cache_enabled/flush_cache SD 内部缓存（SD 5.x 才有） 走扩展寄存器 CMD48/CMD49
handle_undervoltage 欠压事件 eMMC 侧为主

detect 和 alive 做的是同一件事（都发 CMD13），为什么两者都要有？因为调用语义不同：detect() 是「检查完如果没了就自己处理掉」，alive() 是「只报告还活着没，不动手」。前者用在 rescan 里，后者用在恢复路径上。

十一、CORE 层：mmc_rescan 与卡识别 #

mmc_rescan() 在 drivers/mmc/core/core.c，就干两件事：扫描总线发现插入的卡，扫描总线发现卡被拔出。按 3.x 版本逐行看（原文把行号混进代码，这里已剔除并补全缩进）：

c
void mmc_rescan(struct work_struct *work)
{
	struct mmc_host *host =
		container_of(work, struct mmc_host, detect.work);
	int i;

	if (host->rescan_disable)
		return;

	/* If there is a non-removable card registered, only scan once */
	if ((host->caps & MMC_CAP_NONREMOVABLE) && host->rescan_entered)
		return;
	host->rescan_entered = 1;

	mmc_bus_get(host);

	/*
	 * if there is a _removable_ card registered, check whether it is
	 * still present
	 */
	if (host->bus_ops && host->bus_ops->detect && !host->bus_dead
	    && !(host->caps & MMC_CAP_NONREMOVABLE))
		host->bus_ops->detect(host);

	host->detect_change = 0;

	/*
	 * Let mmc_bus_put() free the bus/bus_ops if we've found that
	 * the card is no longer present.
	 */
	mmc_bus_put(host);
	mmc_bus_get(host);
	/* if there still is a card present, stop here */
	if (host->bus_ops != NULL) {
		mmc_bus_put(host);
		goto out;
	}

	/*
	 * Only we can add a new handler, so it's safe to
	 * release the lock here.
	 */
	mmc_bus_put(host);

	if (!(host->caps & MMC_CAP_NONREMOVABLE) && host->ops->get_cd &&
	    host->ops->get_cd(host) == 0) {
		mmc_claim_host(host);
		mmc_power_off(host);
		mmc_release_host(host);
		goto out;
	}

	mmc_claim_host(host);
	for (i = 0; i < ARRAY_SIZE(freqs); i++) {
		if (!mmc_rescan_try_freq(host, max(freqs[i], host->f_min)))
			break;
		if (freqs[i] <= host->f_min)
			break;
	}
	mmc_release_host(host);

 out:
	if (host->caps & MMC_CAP_NEEDS_POLL)
		mmc_schedule_delayed_work(&host->detect, HZ);
}

逐段拆。开头两个 early return 处理特殊场景：rescan_disable 是「扫描被禁用」开关，驱动 remove() 路径里会置 1，防止卸载时有 rescan 跑进来；MMC_CAP_NONREMOVABLE 是 eMMC 那种不可插拔的卡，只扫一次（rescan_entered 记住扫过了）。第一段 get → detect → put 是「探旧卡是否还在」——如果 bus_ops 已经绑过（说明上次扫到了卡），就调它的 detect()；SD 的 detect() 会发 CMD13，卡不在就自己 remove 掉并把 bus_ops 清空。第二段判 bus_ops != NULL 是「卡还在，什么都不用做」；这里必须先 put 再判，因为 mmc_bus_put() 会在引用计数归零时释放 bus_ops，要给它机会。第三段 get_cd 判定 是「卡真的不在卡槽里吗」——返回 0 表示不在，于是断电退出；这步用 mmc_claim_host() 包住，因为断电要改寄存器。

第四段频率循环 是「找一张新卡」：

c
static const unsigned freqs[] = { 400000, 300000, 200000, 100000, 0 };

从 400kHz 往下试，max(freqs[i], host->f_min) 保证不低于控制器下限。mmc_rescan_try_freq() 返回 0 表示「这个频率下认出卡了」，break 出去。尾部 MMC_CAP_NEEDS_POLL 是「没有插拔中断时的自轮询」：每秒再排一次自己。这就是为什么有些板子拔卡后系统还能感知到——不是中断，是轮询。

函数 锁什么 用在什么时候
mmc_bus_get() / mmc_bus_put() bus_ops 的引用计数 + host->lock 判断「当前有没有卡」「卡是哪类」
mmc_claim_host() / mmc_release_host() 独占 host，允许发命令 要真的在总线上发命令时

mmc_bus_get/put() 本质是给 SD 总线加一个自旋锁，规定同时只能有一个线程在 SD 总线上操作。mmc_claim_host() 是更高层的「我要在总线上发命令」声明，会睡眠等待，用 host->wq 等待队列和 claim_cnt 嵌套计数。

这里必须点名素材第三篇的一处错误：「mmc_claim_host(host) 通过 set_current_state(TASK_RUNNING) 将当前进程设置为正在运行进程」。这个说法不对。mmc_claim_host() 做的是获取 host 的独占权，核心是 wait_event() 等待 host->claimed 变为 0，然后置位 claimed、递增 claim_cnt、记录 claimer 上下文。TASK_RUNNING 是 wait_event 内部唤醒后的自然结果，不是它「设置进程状态」的目的。理解成「加锁」就不会错。5.x 里这个函数被拆细了，多了 mmc_rescan_try_freq() 的 claimed 参数、host->rescan_entered 的处理、以及 _mmc_detect_change() 的分工，核心逻辑（探旧卡、判在不在、试频率、轮询）没变。

卡识别的顺序 #

mmc_rescan_try_freq() 里的识别顺序是 SDIO → SD → MMC：

text
1. mmc_go_idle(host)                  CMD0，所有卡回到 idle
2. mmc_send_if_cond(host, ocr_avail)  CMD8，探测 SD 2.0
3. if (!mmc_attach_sdio(host))  return 0;   SDIO 优先
4. if (!mmc_attach_sd(host))    return 0;   SD
5. if (!mmc_attach_mmc(host))   return 0;   MMC / eMMC
6. return -ENOMEDIUM;                       都不是

SDIO 排第一是因为 combo 卡（SDIO + 存储）必须先被识别成 SDIO，才能同时用 IO 功能和存储功能；先被 SD 路径认走了，IO 功能就丢了。

函数 探测命令 成功条件
mmc_attach_sdio() CMD5（IO_SEND_OP_COND） 卡回 R4 且 OCR 位合法
mmc_attach_sd() CMD55+ACMD41 卡退出 busy
mmc_attach_mmc() CMD1（SEND_OP_COND） 卡退出 busy

素材第六篇把这个顺序总结成一串 if-else，照它的逻辑重写：

text
a. 发送 CMD0 使卡进入 IDLE 状态
b. 发送 CMD8，检查卡是否 SD 2.0
   SD 1.1 不支持 CMD8，所以 SD 2.0 规范才提出「先发 CMD8」：
   响应无效命令 = SD 1.1；响应合法 = SD 2.0
c. 发送 ACMD41 读 OCR
d. 发送 CMD55 + ACMD41，使卡进入工作状态
   MMC 卡不支持 CMD55/ACMD41，这一步通过就证明是 SD 卡
e. 如果 d 失败，发送 CMD1 判断是否 MMC
   SD 卡不支持 CMD1，MMC 卡支持，这是 SD/MMC 类型的判据
f. ACMD41 和 CMD1 都不通，这张卡就是无效卡，初始化失败

（原文第 c 步写的是「发送 CMD5 读取 OCR 寄存器」，这是笔误：CMD5 是 MMC 的 SLEEP_AWAKE 或 SDIO 的 IO_SEND_OP_COND，读 OCR 在 SD 路径上靠 ACMD41 的 R3 响应。已在勘误里列出。）

拔卡的路径 #

卡槽有 CD 中断时走中断路径（第十六节），没有的话走轮询触发 mmc_rescan。两条路最终都进 bus_ops->detect()：

c
static void mmc_sd_detect(struct mmc_host *host)   /* 5.x */
{
	int err;

	mmc_get_card(host->card, NULL);

	/* Just check if our card has been removed. */
	err = _mmc_detect_card_removed(host);

	mmc_put_card(host->card, NULL);

	if (err) {
		mmc_remove_card(host->card);
		host->card = NULL;

		mmc_claim_host(host);
		mmc_detach_bus(host);
		mmc_power_off(host);
		mmc_release_host(host);
	}
}

/* drivers/mmc/core/core.c */
int mmc_send_status(struct mmc_card *card, u32 *status)
{
	struct mmc_command cmd = {};
	int err;

	cmd.opcode = MMC_SEND_STATUS;	/* #define MMC_SEND_STATUS 13 */
	cmd.arg = card->rca << 16;
	cmd.flags = MMC_RSP_SPI_R2 | MMC_RSP_R1 | MMC_CMD_AC;

	err = mmc_wait_for_cmd(card->host, &cmd, MMC_CMD_RETRIES);
	if (err)
		return err;   /* 没有响应 = 卡不在 */

	if (status)
		*status = cmd.resp[0];
	return 0;
}

_mmc_detect_card_removed() 里面就是发 CMD13。「发 CMD13 收不到响应」就等于「卡不在」。判据简单粗暴，但绝大多数情况够用。拔卡的三步收尾：

c
static void mmc_sd_remove(struct mmc_host *host)   /* 5.x */
{
	get_device(&host->card->dev);
	mmc_remove_card(host->card);

	_mmc_sd_suspend(host);

	put_device(&host->card->dev);
	host->card = NULL;
}

void mmc_remove_card(struct mmc_card *card)
{
	if (mmc_card_present(card))
		device_del(&card->dev);
	put_device(&card->dev);
}

mmc_remove_card() 的本质是注册的反操作，实质就是执行 device_del() 和 put_device()。get_device()/put_device() 这对引用计数防止「正在 remove 时别处还拿着 card 指针」。这是设备模型的老规矩，device_del() 之后 kobject 还在，等最后一个引用放掉才真正销毁。

text
拔卡 → CD 中断（或轮询）
     → mmc_detect_change(host, delay)
     → _mmc_detect_change() 里 mmc_schedule_delayed_work(&host->detect, delay)
     → kmmcd 工作队列跑 mmc_rescan
     → host->bus_ops->detect(host)  [= mmc_sd_detect]
     → mmc_send_status() 失败
     → mmc_sd_remove(host)      注销 mmc_card
     → mmc_detach_bus(host)     解绑 bus_ops
     → mmc_power_off(host)      断电

到这里 /dev/mmcblk0 消失，块设备层的 mmc_blk_remove() 被调用，内存里的磁盘结构释放。

s3cmci_probe() 按顺序做七件事。素材里的代码有 C99 风格的行内 for 声明，3.x 内核用 -std=gnu89 编不过，下面已改回 C89 声明位置：

c
static int s3cmci_probe(struct platform_device *pdev)
{
	struct s3cmci_host *host;
	struct mmc_host *mmc;
	int ret, is2440, i;

	is2440 = platform_get_device_id(pdev)->driver_data;

	/* 1. 分配 mmc_host，同时在末尾为 s3cmci_host 预留空间 */
	mmc = mmc_alloc_host(sizeof(struct s3cmci_host), &pdev->dev);
	if (!mmc)
		return -ENOMEM;

	host = mmc_priv(mmc);      /* 取得 s3cmci_host 首地址 */
	host->mmc = mmc;
	host->pdev = pdev;
	host->is2440 = is2440;
	host->pdata = pdev->dev.platform_data;

	/* 2. GPIO：GPE5~GPE10 对应 SDI 命令、时钟及 4 条数据线 */
	for (i = S3C2410_GPE(5); i <= S3C2410_GPE(10); i++) {
		ret = gpio_request(i, dev_name(&pdev->dev));
		if (ret)
			goto probe_free_host;
	}

	/* 3. I/O 地址映射 */
	host->mem = platform_get_resource(pdev, IORESOURCE_MEM, 0);
	host->mem = request_mem_region(host->mem->start,
				       resource_size(host->mem), pdev->name);
	host->base = ioremap(host->mem->start, resource_size(host->mem));

	/* 4. 中断先申请再屏蔽，等一切就绪再打开 */
	host->irq = platform_get_irq(pdev, 0);
	request_irq(host->irq, s3cmci_irq, 0, DRIVER_NAME, host);
	disable_irq(host->irq);

	if (!host->pdata->no_detect) {   /* 有 CD 脚就申请插拔中断 */
		gpio_request(host->pdata->gpio_detect, "s3cmci detect");
		host->irq_cd = gpio_to_irq(host->pdata->gpio_detect);
		request_irq(host->irq_cd, s3cmci_irq_cd,
			    IRQF_TRIGGER_RISING | IRQF_TRIGGER_FALLING,
			    DRIVER_NAME, host);
	}

	/* 5. 时钟 */
	host->clk = clk_get(&pdev->dev, "sdi");
	clk_enable(host->clk);
	host->clk_rate = clk_get_rate(host->clk);

	/* 6. 绑定回调集、能力位与频率范围，向 CORE 注册 */
	mmc->ops = &s3cmci_ops;
	mmc->ocr_avail = MMC_VDD_32_33 | MMC_VDD_33_34;
	mmc->f_min = host->clk_rate / (host->clk_div * 256);
	mmc->f_max = host->clk_rate / host->clk_div;

	ret = mmc_add_host(mmc);
	if (ret)
		goto free_cpufreq;

	platform_set_drvdata(pdev, mmc);
	return 0;
	/* ... 错误处理标签 ... */
}

两处最容易出错。mmc->f_min/f_max 的算法直接决定卡能不能被认出来：f_min = clk_rate / (clk_div * 256) 里的 256 是预分频寄存器能表示的最大值，f_max = clk_rate / clk_div 是不分频时的上限。f_min 算出来比卡能接受的初始化时钟（400kHz）还高，识别阶段就失败。经典症状是「卡插上没反应，dmesg 里只有 mmc0: error -110 whilst initialising SD card」——-110 是 -ETIMEDOUT，多半就是这个频率算错了。disable_irq(host->irq) 看着奇怪：刚申请就屏蔽。原因写在注释里——物理中断暂时屏蔽，等系统一切就绪再打开。probe 过程中控制器还没配置好，中断提前进来只会读到垃圾状态，真正的 enable_irq() 在第一次发命令之前调。clk_get/clk_enable 在设备树时代改用 devm_clk_get() + clk_prepare_enable()，后者要多一个 prepare 步骤（CCF 时钟分频抽象引入后）。

MMC_CAP2_NO_PRESCAN_POWERUP 是给「上电就漏电」的板子准备的：先不上电，等真正扫描时再说。mmc_power_off() 里那五行 ios 赋值就是「断电要恢复的默认值」清单：时钟 0、电压 0、开漏模式、1 位宽、legacy 时序。mmc_delay(1) 那一毫秒是给 OLPC 上那颗 802.11 SDIO 卡的解毒措施，注释写得很清楚。ios 里的内容，前段赋值的作用都通过 host 层向上提供的 mmc_host_ops 接口真正落到硬件上——set_ios 回调写错，所有「时钟/位宽/电压」相关的功能全废。

十三、控制器的硬件操作：寄存器与时序 #

控制器层存在的意义，是给 CORE 层提供一种操作 SD 卡硬件的方法。不同控制器方法不尽相同，但最终都向 CORE 层提交一个统一封装了操作方法的数据结构——struct mmc_host_ops，对应的 HOST 文件是 s3cmci.c。

c
static int s3cmci_get_ro(struct mmc_host *mmc)
{
	struct s3cmci_host *host = mmc_priv(mmc);
	struct s3c24xx_mci_pdata *pdata = host->pdata;
	int ret;

	if (pdata->no_wprotect)
		return 0;

	ret = gpio_get_value(pdata->gpio_wprotect) ? 1 : 0;
	ret ^= pdata->wprotect_invert;
	return ret;
}

SD 卡物理上有写保护开关，判断是否写保护可以从机械特征入手，专门的 SD 卡槽把这件事变得方便。gpio_get_value() 取引脚值，wprotect_invert 处理硬件设计上的反相（有些板子把开关接成低电平触发）。只读时返回 1，否则返回 0——对上了第九节讲的头文件语义。no_wprotect 是「这颗板子根本没接写保护脚」的旁路开关，microSD 卡槽没有写保护开关，手机驱动基本都置 1。

c
static void s3cmci_set_ios(struct mmc_host *mmc, struct mmc_ios *ios)
{
	struct s3cmci_host *host = mmc_priv(mmc);
	u32 mci_con;

	/* 先读，避免后面改其它位时把无关位置掉 */
	mci_con = readl(host->base + S3C2410_SDICON);

	switch (ios->power_mode) {
	case MMC_POWER_ON:
	case MMC_POWER_UP:
		/* 把 GPE5..GPE10 配成 SD 模式 */
		s3c_gpio_cfgall_range(S3C2410_GPE(5), 6,
				      S3C_GPIO_SFN(2), S3C_GPIO_PULL_NONE);
		if (host->pdata->set_power)
			host->pdata->set_power(ios->power_mode, ios->vdd);
		if (!host->is2440)
			mci_con |= S3C2410_SDICON_FIFORESET;
		break;
	case MMC_POWER_OFF:
	default:
		gpio_direction_output(S3C2410_GPE(5), 0);
		if (host->is2440)
			mci_con |= S3C2440_SDICON_SDRESET;
		if (host->pdata->set_power)
			host->pdata->set_power(ios->power_mode, ios->vdd);
		break;
	}

	s3cmci_set_clk(host, ios);

	if (ios->clock)
		mci_con |= S3C2410_SDICON_CLOCKTYPE;
	else
		mci_con &= ~S3C2410_SDICON_CLOCKTYPE;

	writel(mci_con, host->base + S3C2410_SDICON);

	dbg(host, dbg_conf, "running at %lukHz (requested: %ukHz).\n",
	    host->real_rate / 1000, ios->clock / 1000);

	host->bus_width = ios->bus_width;
}

四种硬件动作。GPIO 复用：上电时把 GPE5 到 GPE10 这六根脚配成 SFN 2 功能（SD 接口），关闭上下拉；这六根对应 CLK、CMD、DAT0-DAT3、CD，配置不对，后面所有命令都发不出去，而且不报错，只会超时。板级上电回调：pdata->set_power(power_mode, vdd) 通过 regulator 或 GPIO 控制 VDD 是否给卡供电。时钟配置：s3cmci_set_clk() 算分频写预分频寄存器，结果记在 host->real_rate；日志打的是 host->real_rate（实际频率）和 ios->clock（要求值）两个数，对不上是正常的，分频是整数除法。SDICON 回写：mci_con 读一遍、改几位、最后 writel() 回去，这是操作硬件寄存器的标准姿势：读-改-写，绝不直接写死值，否则会把别人设的位清掉。

FIFORESET 和 SDRESET 的分工值得注意：S3C2410 没有 SDRESET，用 FIFORESET；S3C2440 加了 SDICON_SDRESET（软件复位整个 SDI 控制器）。所以代码里有 if (host->is2440) 的分叉。这类「同系列芯片的细微差异」是 SoC 驱动里最常见的 if-else 来源。host->bus_width = ios->bus_width 把当前位宽记下来，后面 s3cmci_setup_data() 用它决定 SDIDCON 的 WIDEBUS 位。

c
	/* 清命令、数据、FIFO 三个状态寄存器 */
	writel(0xFFFFFFFF, host->base + S3C2410_SDICMDSTAT);
	writel(0xFFFFFFFF, host->base + S3C2410_SDIDSTA);
	writel(0xFFFFFFFF, host->base + S3C2410_SDIFSTA);

SDICMDSTAT（命令状态）、SDIDSTA（数据状态）、SDIFSTA（FIFO 状态）是三个不同寄存器，初始化时都要清。全写 1 是因为这三个寄存器的状态位是「写 1 清零」语义。一次新传输之前必须做这个初始化，否则会留下未知的状态错误。s3cmci.c 的注释还补了一句：FIFO 清除只在 2440 上有必要，但在 2410 上做也无害。

SDICON、SDICMDCON、SDIDCON 的具体位号与位名，本篇按 s3cmci.c 里出现的宏名整理，位号以 S3C2440A 用户手册第 19 章「SDI」为准，此处位号标注未验证。宏名是可信的（源码里有），位号是按典型 S3C 命名规则整理的，不排除个别偏移。

时钟链路：clk_rate（PCLK）÷ clk_div（固定分频，板级定义）÷ 预分频值（1..256，写入 SDIPRE）= SDCLK。所以 f_min 就是「预分频打到最大」的频率，f_max 是「预分频为 1」的频率。SD 初始化阶段要求时钟不超过 400kHz，f_min 高于 400kHz 卡就进不了 idle 状态，识别必失败。s3cmci_set_clk() 里做的就是这个除数计算，并把结果存进 host->real_rate。

项目 在哪配 影响
时钟频率 SDIPRE 预分频 命令与数据的速率
时钟相位 部分控制器有相位寄存器，S3C2440 没有 采样点是否落在数据窗口中心
上电/复位延时 set_ios + 板级 set_power 卡是否完成内部上电

SD 规范要求：上电后至少等 1ms 再发第一条命令；CMD0 之后至少 74 个时钟再发下一条。这两条在驱动里的体现是 mmc_delay() 和「发命令前先给几个时钟」。s3cmci 的做法是发 CMD0 时把时钟关掉再打开——SDICON_CLOCKTYPE 位的翻转就是在制造那 74 个时钟的空窗。S3C2440 没有相位调节能力，所以它只能跑到 25MHz（默认速度）和 50MHz（高速），UHS 那套 tuning 在这颗芯片上根本无从谈起——这也解释了为什么 s3cmci_ops 里没有 execute_tuning。

十四、命令的发送与响应处理 #

struct mmc_request 定义在 include/linux/mmc/core.h，主要存放两大数据结构指针：cmd 和 data，一个为指令，一个为数据：

c
struct mmc_request {
	struct mmc_command	*sbc;		/* SET_BLOCK_COUNT（CMD23） */
	struct mmc_command	*cmd;		/* 主命令 */
	struct mmc_data		*data;		/* 数据阶段，可为 NULL */
	struct mmc_command	*stop;		/* STOP_TRANSMISSION（CMD12） */
	void			*done_data;
	void			(*done)(struct mmc_request *);
};

struct mmc_command {
	u32			opcode;
	u32			arg;
	u32			resp[4];
	unsigned int		flags;		/* MMC_RSP_* / MMC_CMD_* */
	unsigned int		retries;
	int			error;
	struct mmc_data		*data;
};

struct mmc_data {
	unsigned int		timeout_ns;
	unsigned int		timeout_clks;
	unsigned int		blksz;
	unsigned int		blocks;
	unsigned int		error;

一次请求的形状：cmd 必须有，data 和 stop 可选，sbc 是 CMD23 预置块数。命令与数据的关系由 cmd->flags & MMC_CMD_ADTC 标记——有数据阶段的命令用 ADTC，纯命令用 AC。

c
static void s3cmci_request(struct mmc_host *mmc, struct mmc_request *mrq)
{
	struct s3cmci_host *host = mmc_priv(mmc);

	host->status = "mmc request";
	host->cmd_is_stop = 0;
	host->mrq = mrq;

	if (s3cmci_card_present(mmc) == 0) {
		dbg(host, dbg_err, "%s: no medium present\n", __func__);
		host->mrq->cmd->error = -ENOMEDIUM;
		mmc_request_done(mmc, mrq);
	} else
		s3cmci_send_request(mmc);
}

信息量全在三处。非阻塞：函数把 mrq 挂到 host->mrq 上就返回，真正的传输在中断和 tasklet 里推进。这和块设备的 queue_rq 一个套路——驱动不能在这里睡眠，因为调用者在原子上下文。卡不在就立刻拒绝：调 s3cmci_card_present() 读 CD 脚，卡不在就把 mrq->cmd->error 设成 -ENOMEDIUM，然后 mmc_request_done() 收尾；注意只设了 cmd->error 没设 data->error——既然没开始传输，数据阶段的错误位没意义。host->cmd_is_stop = 0：这个标志标记「当前处理的是主命令还是 stop 命令」，CMD12 在数据阶段结束后单独发，与主命令共用 host->mrq，靠这个标志区分。

c
/**
 *	mmc_request_done - finish processing an MMC request
 *	@host: MMC host which completed request
 *	@mrq: MMC request which request
 *
 *	MMC drivers should call this function when they have completed
 *	their processing of a request.
 */
void mmc_request_done(struct mmc_host *host, struct mmc_request *mrq)
{
	struct mmc_command *cmd = mrq->cmd;
	int err = cmd->error;

	if (err && cmd->retries && mmc_host_is_spi(host)) {
		if (cmd->resp[0] & R1_SPI_ILLEGAL_COMMAND)
			cmd->retries = 0;
	}

	if (err && cmd->retries && !mmc_card_removed(host->card)) {
		/* 重试交给 mmc_wait_for_req_done() */
		if (mrq->done)
			mrq->done(mrq);
	} else {
		mmc_should_fail_request(host, mrq);
		led_trigger_event(host->led, LED_OFF);

		pr_debug("%s: req done (CMD%u): %d: %08x %08x %08x %08x\n",
			mmc_hostname(host), cmd->opcode, err,
			cmd->resp[0], cmd->resp[1],
			cmd->resp[2], cmd->resp[3]);

		if (mrq->data)
			pr_debug("%s: %d bytes transferred: %d\n",
				mmc_hostname(host),
				mrq->data->bytes_xfered, mrq->data->error);

		if (mrq->stop)   /* 原文误作 mmc->stop，此处已修正 */
			pr_debug("%s: (CMD%u): %d: %08x %08x %08x %08x\n",
				mmc_hostname(host), mrq->stop->opcode,
				mrq->stop->error, mrq->stop->resp[0],
				mrq->stop->resp[1], mrq->stop->resp[2],
				mrq->stop->resp[3]);

		if (mrq->done)
			mrq->done(mrq);

		mmc_host_clk_release(host);
	}
}

SPI 特例：SPI 模式下如果命令非法（R1_SPI_ILLEGAL_COMMAND），重试多少次都不会有结果，干脆把 cmd->retries 清零，不再给机会。这是唯一一个「主动放弃重试」的分支。重试分支：err && cmd->retries && !mmc_card_removed() 三者同时成立，才交给 mrq->done，由上层（mmc_wait_for_req_done()）决定是否重发。驱动层不自己重试——重试逻辑统一在 CORE 层。正常收尾：调试信息、数据统计、stop 命令结果，最后调 mrq->done(mrq)，再 mmc_host_clk_release(host)。

那行 pr_debug 打印四个 resp[] 是排查问题的金矿。打开 CONFIG_MMC_DEBUG 和动态调试，dmesg 里会出现：

text
mmc0: req done (CMD8): 0: 000001aa 00000000 00000000 00000000
mmc0: req done (CMD2): 0: 03534453 44303247 8000abcd 01234567

第一行是 CMD8 的 R7 响应，0x1AA 是 SD 2.0 的电压校验回显。第二行是 CMD2 的 R2 响应，四个 u32 拼起来就是完整 128 位 CID。

c
static void mmc_wait_done(struct mmc_request *mrq)
{
	complete(mrq->done_data);
}

void mmc_wait_for_req(struct mmc_host *host, struct mmc_request *mrq)
{
	struct completion complete;

	init_completion(&complete);
	mrq->done_data = &complete;
	mrq->done = mmc_wait_done;

	mmc_start_request(host, mrq);

	wait_for_completion(&complete);
}

mrq->done_data 是一个 struct completion *，complete() 唤醒在 mmc_wait_for_req() 里睡眠的那个上下文。整个同步模型的全貌：发请求 → 睡眠等 completion → 中断里做完 → 调 done → complete 唤醒。mmc_start_request() 最终调的就是 host->ops->request(host, mrq)。

一直出错谁来唤醒？照样是 mmc_request_done()，它在错误路径上也会调 mrq->done()，所以 complete() 一定会被调用。驱动层唯一要做的是「无论如何都要调 mmc_request_done()」，漏掉一次，那个 wait_for_completion 就永远睡下去——这是驱动挂死的第一大原因。

c
static void s3cmci_send_request(struct mmc_host *mmc)
{
	struct s3cmci_host *host = mmc_priv(mmc);
	struct mmc_request *mrq = host->mrq;
	struct mmc_command *cmd = host->cmd_is_stop ? mrq->stop : mrq->cmd;

	host->ccnt++;
	prepare_dbgmsg(host, cmd, host->cmd_is_stop);

	/* 清命令、数据、FIFO 状态寄存器 */
	writel(0xFFFFFFFF, host->base + S3C2410_SDICMDSTAT);
	writel(0xFFFFFFFF, host->base + S3C2410_SDIDSTA);
	writel(0xFFFFFFFF, host->base + S3C2410_SDIFSTA);

	if (cmd->data) {
		int res = s3cmci_setup_data(host, cmd->data);

		host->dcnt++;
		if (res) {
			cmd->error = res;
			cmd->data->error = res;
			mmc_request_done(mmc, mrq);
			return;
		}

		if (s3cmci_host_usedma(host))
			res = s3cmci_prepare_dma(host, cmd->data);
		else
			res = s3cmci_prepare_pio(host, cmd->data);

		if (res) {
			cmd->error = res;
			cmd->data->error = res;
			mmc_request_done(mmc, mrq);
			return;
		}
	}

	/* 发送命令 */
	s3cmci_send_command(host, cmd);

	/* 使能中断 */
	s3cmci_enable_irq(host, true);
}

流程是「清状态 → 备数据 → 发命令 → 开中断」。注意顺序：数据通路要在命令之前准备好，因为 SD 的读写是「命令发出去，卡立刻开始搬数据」，数据通路没对准就丢数据。RXAFTERCMD/TXAFTERRESP 这两个数据控制位（见第十五节）就是在硬件层强制这个先后。if (s3cmci_host_usedma(host)) 是 PIO 与 DMA 的分叉，选择依据是 host 结构里 dma 通道号是否非负。

c
static void s3cmci_send_command(struct s3cmci_host *host,
				struct mmc_command *cmd)
{
	u32 ccon, imsk;

	imsk = S3C2410_SDIIMSK_CRCSTATUS | S3C2410_SDIIMSK_CMDTIMEOUT |
	       S3C2410_SDIIMSK_RESPONSEND | S3C2410_SDIIMSK_CMDSENT |
	       S3C2410_SDIIMSK_RESPONSECRC;

	enable_imask(host, imsk);

	if (cmd->data)
		host->complete_what = COMPLETION_XFERFINISH_RSPFIN;
	else if (cmd->flags & MMC_RSP_PRESENT)
		host->complete_what = COMPLETION_RSPFIN;
	else
		host->complete_what = COMPLETION_CMDSENT;

	writel(cmd->arg, host->base + S3C2410_SDICMDARG);

	ccon = cmd->opcode & S3C2410_SDICMDCON_INDEX;
	ccon |= S3C2410_SDICMDCON_SENDERHOST | S3C2410_SDICMDCON_CMDSTART;

	if (cmd->flags & MMC_RSP_PRESENT)
		ccon |= S3C2410_SDICMDCON_WAITRSP;
	if (cmd->flags & MMC_RSP_136)
		ccon |= S3C2410_SDICMDCON_LONGRSP;

	writel(ccon, host->base + S3C2410_SDICMDCON);
}

三块：中断掩码使能 CRC 校验错、命令超时、响应结束、命令发送完成、响应 CRC 错五个中断（具体位定义查 S3C2440 手册第 19 章）。期望完成状态 host->complete_what 记录「这条命令结束时应该看到什么」，中断处理函数拿实际硬件状态和它比对，决定请求算不算完成：

c
enum s3cmci_waitfor {
	COMPLETION_NONE,
	COMPLETION_FINALIZE,
	COMPLETION_CMDSENT,
	COMPLETION_RSPFIN,
	COMPLETION_XFERFINISH,
	COMPLETION_XFERFINISH_RSPFIN,
};

COMPLETION_XFERFINISH_RSPFIN 是有数据、要等「响应到」+「数据传输完」；COMPLETION_RSPFIN 是无数据但要响应；COMPLETION_CMDSENT 是无数据无响应（如 CMD0），发出去就算完成；COMPLETION_FINALIZE 是「收尾中」的过渡态，防止重复处理。

命令控制寄存器（SDICMDCON）里塞三样：命令号（INDEX 位域）、SENDERHOST（主机发起）、CMDSTART（置位即开始发送）。响应要求决定 WAITRSP 和 LONGRSP 两位。SDICmdCon[8]（CMDSTART）的置位让控制器开始发送命令，之后产生中断，进入 probe 阶段注册的 SDI 中断服务程序。SDICMDCON_LONGRSP 就是第六节讲的那个「MMC_RSP_136 的硬件体现」——CMD2/CMD9/CMD10 必须长响应，CMD3/CMD7/CMD13 是短响应。

十五、数据传輸：PIO 与 DMA #

c
static int s3cmci_setup_data(struct s3cmci_host *host, struct mmc_data *data)
{
	u32 dcon, imsk, stoptries = 3;

	/* 没有数据阶段，把数据控制寄存器清零即可 */
	if (!data) {
		writel(0, host->base + S3C2410_SDIDCON);
		return 0;
	}

	/* 块大小必须 4 字节对齐；多于一块时不能处理非字对齐块 */
	if ((data->blksz & 3) != 0) {
		if (data->blocks > 1) {
			pr_warning("%s: can't do non-word sized block transfers (blksz %d)\n",
				   __func__, data->blksz);
			return -EINVAL;
		}
	}

	/* 上一次传输还在进行？复位控制器，重试三次 */
	while (readl(host->base + S3C2410_SDIDSTA) &
	       (S3C2410_SDIDSTA_TXDATAON | S3C2410_SDIDSTA_RXDATAON)) {
		writel(S3C2410_SDIDCON_STOP, host->base + S3C2410_SDIDCON);
		s3cmci_reset(host);
		if ((stoptries--) == 0) {
			dbg_dumpregs(host, "DRF");
			return -EINVAL;
		}
	}

	dcon = data->blocks & S3C2410_SDIDCON_BLKNUM_MASK;

	if (s3cmci_host_usedma(host))
		dcon |= S3C2410_SDIDCON_DMAEN;

	if (host->bus_width == MMC_BUS_WIDTH_4)
		dcon |= S3C2410_SDIDCON_WIDEBUS;

	if (!(data->flags & MMC_DATA_STREAM))
		dcon |= S3C2410_SDIDCON_BLOCKMODE;

	if (data->flags & MMC_DATA_WRITE) {
		dcon |= S3C2410_SDIDCON_TXAFTERRESP;
		dcon |= S3C2410_SDIDCON_XFER_TXSTART;
	}

	if (data->flags & MMC_DATA_READ) {
		dcon |= S3C2410_SDIDCON_RXAFTERCMD;
		dcon |= S3C2410_SDIDCON_XFER_RXSTART;
	}

	if (host->is2440) {
		dcon |= S3C2440_SDIDCON_DS_WORD;
		dcon |= S3C2440_SDIDCON_DATSTART;
	}

	writel(dcon, host->base + S3C2410_SDIDCON);

	/* 写块大小寄存器，上层设下来的值，一般是 512 */
	writel(data->blksz, host->base + S3C2410_SDIBSIZE);

	/* 追加中断掩码：FIFO 错、数据 CRC、超时、传输完成 */
	imsk = S3C2410_SDIIMSK_FIFOFAIL | S3C2410_SDIIMSK_DATACRC |
	       S3C2410_SDIIMSK_DATATIMEOUT | S3C2410_SDIIMSK_DATAFINISH;
	enable_imask(host, imsk);

	/* 写超时寄存器 */
	if (host->is2440) {
		writel(0x007FFFFF, host->base + S3C2410_SDITIMER);
	} else {
		writel(0x0000FFFF, host->base + S3C2410_SDITIMER);
		/* FIX: set slow clock to prevent timeouts on read */
		if (data->flags & MMC_DATA_READ)
			writel(0xFF, host->base + S3C2410_SDIPRE);
	}

	return 0;
}

五个要点。块大小 4 字节对齐：(data->blksz & 3) != 0 且多于一块，直接返 -EINVAL，因为 FIFO 按 32 位字组织，非字宽度的多块传输数据在 FIFO 里的对齐会错；单块非对齐还能软件补齐，多块就没法了。残留传输检测：读 SDIDSTA 看 TXDATAON/RXDATAON 位，如果上一次传输还在进行，先写 SDIDCON_STOP 再 s3cmci_reset()，最多重试三次，三次都失败就 dump 寄存器返错；这个循环的存在说明硬件卡在某个状态出不来，软件只能硬复位。

SDIDCON_DMAEN 使能 DMA
SDIDCON_WIDEBUS 4 位宽
SDIDCON_BLOCKMODE 块模式（否则流模式）

TXAFTERRESP 和 RXAFTERCMD 就是硬件强制的「命令与数据的先后关系」：写时等卡回响应再送数据，读时命令一发出去就开始接收。CORE 层的 ADTC 命令之所以能「一条命令带一段数据」，靠的就是这两个位。超时与预分频：SDITIMER 写 0x007FFFFF（2440）或 0x0000FFFF（2410），差了一个数量级——因为 2440 时钟更快，同样时间需要更大计数值。读操作时还要把 SDIPRE 改成 0xFF（最慢时钟），注释写着 FIX: set slow clock to prevent timeouts on read，这是硬件缺陷的软件绕过：读的时候时钟太快会导致超时，降速治百病。块大小寄存器：SDIBSIZE 写 data->blksz，上层设下来的值一般 512。SDHC 块长固定 512，SDSC 可以是 512 或其他 2 的幂，但内核块层统一按 512 处理。

PIO 模式不用 DMA 控制器，靠 CPU 读写数据 FIFO 端口。搬数据不能在中断里做（太慢），所以放到 tasklet：

c
/* 中断里发现 FIFO 可读写，就排 tasklet */
if ((host->pio_active == XFER_WRITE) &&
    (mci_fsta & S3C2410_SDIFSTA_TFDET)) {
	disable_imask(host, S3C2410_SDIIMSK_TXFIFOHALF);
	tasklet_schedule(&host->pio_tasklet);
	host->status = "pio tx";
}

if ((host->pio_active == XFER_READ) &&
    (mci_fsta & S3C2410_SDIFSTA_RFDET)) {
	disable_imask(host,
		      S3C2410_SDIIMSK_RXFIFOHALF |
		      S3C2410_SDIIMSK_RXFIFOLAST);
	tasklet_schedule(&host->pio_tasklet);
	host->status = "pio rx";
}

SDIFSTA_TFDET 是「发送 FIFO 可写」，RFDET 是「接收 FIFO 可读」。中断里判断这两个位，把 tasklet 排上，然后立刻禁用对应的 FIFO 中断——防止 tasklet 还在跑时又被同一个中断打断。tasklet 本体（素材未给出完整实现，这里按 s3cmci.c 的语义描述）：读 SDIFSTA 判断 FIFO 状态，用 readl(S3C2410_SDIDAT)/writel(..., S3C2410_SDIDAT) 一次搬一个 32 位字，累加 bytes_xfered，搬完一段重新使能 FIFO 中断。

PIO 的瓶颈很明确：每搬 4 个字节就要一次寄存器访问和一次 tasklet 上下文切换。50MHz 4 位总线的理论带宽 25MB/s，PIO 能做到多少取决于 CPU 速度和 tasklet 调度延迟，实测往往只有几 MB/s。老驱动在「小板子上跑 SD 卡慢得离谱」时，第一件事就是确认 s3cmci_host_usedma() 是不是没生效。

DMA 模式的准备函数是 s3cmci_prepare_dma(host, cmd->data)，它做三件事：把 data->sg 里的散列表映射成 DMA 地址、配置 DMA 通道的方向和宽度、启动通道。传输完成后 DMA 中断进来，驱动清通道、调 mmc_request_done()。DMA 用在 SD 上有三个约束：缓冲区必须 DMA 可达（dma_map_sg() 处理），不能用 vmalloc 或栈上内存；传输方向要对，搞反了会拿到脏数据；传输结束后要同步（dma_sync_sg_for_cpu()），否则 CPU 读到的是 cache 里的旧值。第三条在 ARM 上特别容易忘，内核里有现成的：

c
static inline enum dma_data_direction mmc_get_dma_dir(struct mmc_data *data)
{
	return data->flags & MMC_DATA_WRITE ? DMA_TO_DEVICE : DMA_FROM_DEVICE;
}

十六、中断与插拔检测 #

S3C2440 有两条中断线：一条给 SDI 控制器（命令/数据完成），一条给插拔检测（外部中断）。前者是 s3cmci_irq，后者是 s3cmci_irq_cd。s3cmci_irq 的注释写得比代码还清楚：

c
/*
 * ISR for SDI Interface IRQ
 *   host->mrq points to current request
 *   host->complete_what Indicates when the request is considered done
 *     COMPLETION_CMDSENT when the command was sent
 *     COMPLETION_RSPFIN when a response was received
 *     COMPLETION_XFERFINISH when the data transfer is finished
 *     COMPLETION_XFERFINISH_RSPFIN both of the above.
 *
 * 1) Driver sets up host->mrq and host->complete_what
 * 2) Driver prepares the transfer
 * 3) Driver enables interrupts
 * 4) Driver starts transfer
 * 5) Driver waits for host->complete_request
 * 6) ISR checks for request status (errors and success)
 * 7) ISR sets host->mrq->cmd->error and host->mrq->data->error
 * 8) ISR completes host->complete_request
 * 9) ISR disables interrupts
 * 10) Driver wakes up and takes care of the request
 */
static irqreturn_t s3cmci_irq(int irq, void *dev_id)
{
	struct s3cmci_host *host = dev_id;
	struct mmc_command *cmd;
	u32 mci_csta, mci_dsta, mci_fsta, mci_dcnt, mci_imsk;
	u32 mci_cclear = 0, mci_dclear;
	unsigned long iflags;

	mci_dsta = readl(host->base + S3C2410_SDIDSTA);
	mci_imsk = readl(host->base + host->sdiimsk);

	/* SDIO 中断优先处理，不属于存储卡路径 */
	if (mci_dsta & S3C2410_SDIDSTA_SDIOIRQDETECT) {
		if (mci_imsk & S3C2410_SDIIMSK_SDIOIRQ) {
			mci_dclear = S3C2410_SDIDSTA_SDIOIRQDETECT;
			writel(mci_dclear, host->base + S3C2410_SDIDSTA);
			mmc_signal_sdio_irq(host->mmc);
			return IRQ_HANDLED;
		}
	}

	spin_lock_irqsave(&host->complete_lock, iflags);

	mci_csta = readl(host->base + S3C2410_SDICMDSTAT);
	mci_dcnt = readl(host->base + S3C2410_SDIDCNT);
	mci_fsta = readl(host->base + S3C2410_SDIFSTA);
	mci_dclear = 0;

	/* 三种「没有对应请求」的情形，清掩码退出 */
	if ((host->complete_what == COMPLETION_NONE) ||
	    (host->complete_what == COMPLETION_FINALIZE)) {
		host->status = "nothing to complete";
		clear_imask(host);
		goto irq_out;
	}
	if (!host->mrq) { host->status = "no active mrq"; clear_imask(host); goto irq_out; }

	cmd = host->cmd_is_stop ? host->mrq->stop : host->mrq->cmd;
	if (!cmd) { host->status = "no active cmd"; clear_imask(host); goto irq_out; }

	/* PIO 模式下 FIFO 有数据，排 tasklet（见第十五节） */
	if (!s3cmci_host_usedma(host)) { /* ... tx/rx FIFO 判断 ... */ }

	if (mci_csta & S3C2410_SDICMDSTAT_CMDTIMEOUT) {
		cmd->error = -ETIMEDOUT;
		host->status = "error: command timeout";
		goto fail_transfer;
	}

	if (mci_csta & S3C2410_SDICMDSTAT_CMDSENT) {
		if (host->complete_what == COMPLETION_CMDSENT)
			goto close_transfer;
		mci_cclear |= S3C2410_SDICMDSTAT_CMDSENT;
	}

	if (mci_csta & S3C2410_SDICMDSTAT_CRCFAIL) {
		/* 长响应时忽略 CRC 错，硬件误报，见本节末 */
		mci_cclear |= S3C2410_SDICMDSTAT_CRCFAIL;
	}

	if (mci_csta & S3C2410_SDICMDSTAT_RSPFIN) {
		if (host->complete_what == COMPLETION_RSPFIN)
			goto close_transfer;
		if (host->complete_what == COMPLETION_XFERFINISH_RSPFIN)
			host->complete_what = COMPLETION_XFERFINISH;
		mci_cclear |= S3C2410_SDICMDSTAT_RSPFIN;
	}

	/* 后面这些错误只在有数据传输时才有意义 */
	if (!cmd->data)
		goto clear_status_bits;

	if (mci_dsta & (S3C2410_SDIDSTA_FIFOFAIL |
			S3C2410_SDIDSTA_RXCRCFAIL |
			S3C2410_SDIDSTA_CRCFAIL)) {
		cmd->data->error = -EILSEQ;
		host->status = "error: fifo/crc";
		goto fail_transfer;
	}

	if (mci_dsta & S3C2410_SDIDSTA_DATATIMEOUT) {
		cmd->data->error = -ETIMEDOUT;
		host->status = "error: data timeout";
		goto fail_transfer;
	}

	if (mci_dsta & S3C2410_SDIDSTA_XFERFINISH) {
		if (host->complete_what == COMPLETION_XFERFINISH)
			goto close_transfer;
		if (host->complete_what == COMPLETION_XFERFINISH_RSPFIN)
			host->complete_what = COMPLETION_RSPFIN;
		mci_dclear |= S3C2410_SDIDSTA_XFERFINISH;
	}

 clear_status_bits:
	writel(mci_cclear, host->base + S3C2410_SDICMDSTAT);
	writel(mci_dclear, host->base + S3C2410_SDIDSTA);
	goto irq_out;

 fail_transfer:
	host->pio_active = XFER_NONE;

 close_transfer:
	host->complete_what = COMPLETION_FINALIZE;
	clear_imask(host);
	tasklet_schedule(&host->pio_tasklet);
	goto irq_out;

 irq_out:
	dbg(host, dbg_irq,
	    "csta:0x%08x dsta:0x%08x fsta:0x%08x dcnt:0x%08x status:%s.\n",
	    mci_csta, mci_dsta, mci_fsta, mci_dcnt, host->status);
	spin_unlock_irqrestore(&host->complete_lock, iflags);
	return IRQ_HANDLED;
}

（原文注释里的 complete_rquest、contition 是拼写错误；素材里混入的行号已全部剔除。）

几个关键判断讲透。三个 early goto：complete_what 是 NONE/FINALIZE、mrq 为空、cmd 为空，都说明「这个中断没有对应的请求」，直接清中断掩码返回。第三个尤其重要——中断会在请求已经处理完之后才到（比如清了状态位但中断线还没拉低），这时 mrq 已被置空，代码必须能干净退出而不是解空指针。

状态机推进：RSPFIN 和 XFERFINISH 两段是同一个模式，如果期望的状态就是它，转 close_transfer；如果期望的是「两个都要」，把 complete_what 降级成「还剩一个」：

text
 EXPECT XFERFINISH_RSPFIN
   ├─ 先来 RSPFIN   → complete_what = XFERFINISH  （等数据）
   └─ 先来 XFERFINISH → complete_what = RSPFIN    （等响应）
 两个都到 → 匹配 → close_transfer

CRC 错误被注释掉了：CRCFAIL 分支里那段 cmd->error = -EILSEQ; goto fail_transfer; 被注释成「硬件搞错了，不是真错误」。注释原文：we used to fail the transfer here, but it seems that this is just the hardware getting it wrong。长响应时直接打日志忽略，短响应时也不 fail，只清状态位。这个改动是硬件缺陷驱动的——某些 S3C2410 在长响应上会报假 CRC 错，按真错误处理的话 CMD2 永远失败，卡永远认不到。

收尾三件套：

c
	host->complete_what = COMPLETION_FINALIZE;
	clear_imask(host);
	tasklet_schedule(&host->pio_tasklet);

COMPLETION_FINALIZE 防止重入；clear_imask() 关掉所有中断（保留 SDIO IRQ 掩码）；排 tasklet 做最终的 mmc_request_done()。为什么最终收尾要放 tasklet 而不是中断里？因为 mmc_request_done() 会调 mrq->done() → complete()，唤醒的是正在 wait_for_completion() 的进程，它醒来要 claim host、会睡眠。在硬中断里做这些是禁区。tasklet 是软中断上下文，虽然也不能睡眠，但至少不在硬中断的关键路径上，而且能保证和 PIO 的 FIFO 搬运串行化。

c
static inline void clear_imask(struct s3cmci_host *host)
{
	u32 mask = readl(host->base + host->sdiimsk);

	/* preserve the SDIO IRQ mask state */
	mask &= S3C2410_SDIIMSK_SDIOIRQ;
	writel(mask, host->base + host->sdiimsk);
}

mask &= S3C2410_SDIIMSK_SDIOIRQ 只保留 SDIO IRQ 那一位，其它全清。注释说明了原因：SDIO 中断和存储卡中断共用一条中断线，清掉 SDIO 的掩码会让 SDIO 卡的中断丢失。

方式 能力位 触发路径
专用 CD 引脚 + 中断 无（默认） request_irq(irq_cd, s3cmci_irq_cd, IRQF_TRIGGER_RISING|FALLING, ...)

static irqreturn_t s3cmci_irq_cd(int irq, void *dev_id)
{
	struct s3cmci_host *host = (struct s3cmci_host *)dev_id;

	s3cmci_disable_irq(host, false);

	mmc_detect_change(host->mmc, msecs_to_jiffies(500));

	return IRQ_HANDLED;
}

三个细节。先禁中断再通知：s3cmci_disable_irq(host, false) 关掉 SDI 中断——卡正在插拔，总线上电平乱跳，进来的中断没有意义；这个禁用是暂时的，等 mmc_rescan 处理完会重新打开。500ms 去抖：msecs_to_jiffies(500) 是给机械触点弹跳留的时间，插拔瞬间会弹跳好几次，每次都触发中断的话 mmc_rescan 会被排上好几遍；这个值跟卡槽机械质量有关，劣质卡槽要更久。公开版本 mmc_detect_change() 会自己处理 wakeup 逻辑再调 _mmc_detect_change()。

c
static int s3cmci_card_present(struct mmc_host *mmc)
{
	struct s3cmci_host *host = mmc_priv(mmc);
	struct s3c24xx_mci_pdata *pdata = host->pdata;
	int ret;

	if (pdata->no_detect)
		return -ENOSYS;

	ret = gpio_get_value(pdata->gpio_detect) ? 0 : 1;
	return ret ^ pdata->detect_invert;
}

? 0 : 1 和 get_cd 语义对上：引脚为高（开关断开）说明卡不在，返回 0；引脚为低（开关闭合）说明卡在位，返回 1。再异或 detect_invert 处理反相。no_detect 时返回 -ENOSYS 而不是 0，这个细节很重要：返回 0 会被理解成「卡不在」，mmc_rescan 就直接断电退出；返回 -ENOSYS 表示「我不知道」，让上层跳过这个检查。

text
1. CD 中断 → s3cmci_irq_cd
2. mmc_detect_change(host, 500ms)
3. _mmc_detect_change → schedule(&host->detect, 500ms)
4. 500ms 后 mmc_rescan 跑
5. host->ops->get_cd(host) 返回 1（卡在）
6. mmc_claim_host
7. mmc_rescan_try_freq
   a. mmc_power_up(host, ocr_avail)
      → ios.power_mode = MMC_POWER_UP
      → mmc_set_ios → s3cmci_set_ios
         → GPIO 复用为 SD 功能
         → pdata->set_power(MMC_POWER_UP, vdd)  板级供电
         → FIFORESET / SDRESET
      → ios.power_mode = MMC_POWER_ON
      → mmc_set_ios 再调一次（时钟、位宽生效）
   b. mmc_go_idle → CMD0
   c. mmc_send_if_cond → CMD8
   d. mmc_attach_sd → ACMD41 → CMD2 → CMD3 → CMD9 → CMD7 → ACMD51 ...
8. mmc_add_card → device_add → mmc_blk_probe
9. /dev/mmcblk0 出现

mmc_power_up() 会调两次 set_ios（一次 POWER_UP、一次 POWER_ON），这就是为什么 s3cmci_set_ios() 的 switch 里两个 case 都做了 GPIO 复用——不怕重复配置，但必须都配。

十七、SD 卡作为启动介质的流程 #

启动方式 谁读 SD 卡 Linux 参与吗 典型平台
BootROM 级启动 芯片内部 BootROM 不参与，Linux 还没起来 i.MX、Allwinner、Rockchip、STM32MP
U-Boot 级启动 U-Boot 的 MMC 驱动 不参与 S3C2440、多数 ARM9/ARM11
根文件系统在 SD 卡上 Linux 的 mmc 子系统 全程参与 所有平台

前两种属于「二级程序加载」（SPL/U-Boot）范畴，用的是 BootROM 或 U-Boot 自己的 SD 驱动，跟本篇讲的 Linux 驱动毫无关系。真正跟 Linux 驱动有关的只有第三种。用户问「SD 卡启动」时经常把这三件事混成一件，我们分开讲。

SoC 上电后，BootROM 里那段固化代码按预设顺序找启动介质。SD 卡能进这个顺序，是因为 BootROM 里包含一个最小化的 SD/MMC 主机控制器驱动：

text
上电 → BootROM
  ├─ 配置 SD 控制器时钟（一般是 400kHz）
  ├─ CMD0 复位卡 / CMD8 检查 2.0 / ACMD41 协商电压
  ├─ CMD2/CMD3 拿 CID 和 RCA / CMD9 读 CSD 算容量 / CMD7 选中
  ├─ CMD17/CMD18 按块读
  └─ 把第一块（一般是 MBR 或 SPL 头）读到 SRAM 执行

这一段和 Linux 的 mmc_sd_init_card() 高度重合——因为它们遵循同一份 SD 规范。区别在于 BootROM 版本没有 mmc_host、没有 mmc_request、没有工作队列，全是一个函数里裸写寄存器。局限：只支持 1 位或 4 位模式，不保证支持高速；不处理 tuning，UHS 卡在 BootROM 阶段只会跑默认速度；分区表格式、启动文件位置由各厂商自定（i.MX 有 IVT 头，Allwinner 有 eGON.BT0），跨厂商不通用。

U-Boot 有自己的 drivers/mmc/，结构和 Linux 高度相似（mmc_host、mmc_request 那套几乎照搬），但更精简。S3C2440 上 U-Boot 的 s3c24xx_mmc.c 与 Linux 的 s3cmci.c 是同一个硬件、两套代码：

text
board_init_r()
  → mmc_initialize(gd->bd) → mmc_init(mmc) → mmc_get_dev(dev_num)
  → blk_dread(mmc_get_blk_desc(mmc), start_blk, cnt, addr)
     → mmc_read_blocks()       // 走 mmc_request 那套
  → 把读取到的镜像搬到 DRAM，跳转执行

这段跟 Linux 无关，但会留下痕迹：如果 U-Boot 的 SD 驱动把卡配成了 4 位高速模式，却忘了在跳转前复位控制器，Linux 起来后控制器还在异常状态，mmc_rescan 第一次扫会失败。调试「U-Boot 能读卡，Linux 认不到」这类问题时，先怀疑控制器状态残留，解法是 Linux 的 probe 里做一次完整控制器复位（SDRESET），而不是假设它已复位。

Linux 里 SD 卡当根文件系统：

text
1. 内核启动，跑到 mmc_init() 和 mmc_blk_init()
2. 各平台的 mmc host 驱动 probe（platform_bus 匹配）
3. mmc_add_host() → mmc_start_host() → 立刻扫一次
4. mmc_rescan 认出卡 → mmc_add_card
5. mmc_blk_probe 注册磁盘 → /dev/mmcblk0
6. 块层读分区表 → /dev/mmcblk0p1、p2 ...
7. 内核命令行 root=/dev/mmcblk0p2 rootwait
8. mount 根文件系统

第 7 步的 rootwait 是关键。mmc 卡的识别是异步的——mmc_add_host() 只排了一个延迟工作，卡真正认出来要几百毫秒。内核在这之前就尝试 mount /dev/mmcblk0p2，设备节点还不存在，挂载失败，panic。rootdelay=N 是另一个办法（固定等 N 秒），但不如 rootwait 精确。/dev/mmcblk0p2 的命名规则：mmcblk + 主机编号 + p + 分区号。主机编号从 0 开始按探测顺序分配——板上既有 eMMC 又有 SD 卡时编号会互换（取决于 probe 顺序）。稳定命名要靠 /dev/disk/by-uuid/ 或 PARTLABEL。

启动介质场景下的驱动注意事项：不要用模块（mmc host 驱动和块设备驱动必须编进内核 =y，不能是 =m——模块在 initramfs 里，而根文件系统要在根文件系统上才能加载，循环依赖）；探测顺序要可控（多个 mmc 控制器时 /dev/mmcblk0 不一定是你想要的那个，用 aliases 在设备树里显式绑定 mmc0 到某个控制器，或者用 root= 配 UUID）；上电时序要够（mmc_delay(1) 那一毫秒是给卡内部电源稳定的，有些卡尤其大容量 SDXC 需要更长时间，可以在 pdata->set_power() 里加延时，或者用 ios.power_delay_ms）；写保护要当真（根文件系统挂在只读 SD 卡上时挂载会成功但所有写操作失败，get_ro 回调读错引脚极性会导致「系统起来但一写就报 I/O 错误」）；掉电保护（SD 卡在写操作进行中被拔掉会损坏文件系统，块层的 flush 机制会定期下发 REQ_OP_FLUSH，驱动要保证 CMD12 之后的数据都已真正写入卡内部；这一步在 mmc_blk 层做，HOST 层要保证 bytes_xfered 和中断状态如实上报——虚报完成，数据就丢了）。

bash
# 内核命令行
console=ttySAC0,115200 root=/dev/mmcblk0p2 rootwait rw

# 期望看到的 dmesg（顺序、措辞因内核版本而异）
mmc0: new SDHC card at address 0001
mmcblk0: mmc0:0001 SD32G 29.7 GiB
 mmcblk0: p1 p2
EXT4-fs (mmcblk0p2): mounted filesystem with ordered data mode
VFS: Mounted root (ext4 filesystem) on device 179:2.

mmc0: new SDHC card 这行的 SDHC 是 mmc_add_card() 根据 OCR 的 CCS 位打印的；29.7 GiB 是 CSD 解码出来的容量；mmc0:0001 是设备名（host + RCA）。三者任何一个不对，回去看第五节和第六节。

text
若只看到 mmc0: error -110 whilst initialising SD card
  → CMD0/CMD8/ACMD41 超时，优先查 f_min 和 GPIO 复用
若看到 mmc0: error -22 whilst initialising SD card
  → -EINVAL，优先查 mmc_select_voltage 的电压交集

对照：bus width: 2 表示 4 位（记住 MMC_BUS_WIDTH_4 == 2），timing: 2 表示 SD 高速。两个都到位说明 CMD6 和 ACMD6 都成功了。如果 bus width: 0，说明 4 位切换失败，回去查 scr.bus_widths 和 MMC_CAP_4_BIT_DATA。

三个最容易踩的坑。忘了给 SD 卡槽上电：mmc_power_up() 只是改 ios.power_mode 并调 set_ios，真正给卡供电要靠板级的 pdata->set_power() 回调或者 regulator；少写这个回调，ios 改了一万遍，卡槽还是没电。get_cd 返回值搞反：返回 0 是「卡不在」，返回 1 是「卡在」；写反了，卡插着时 mmc_rescan 认为没卡直接断电，拔了反而去识别。在中断里调 mmc_request_done 直接睡：mmc_request_done() 里有 pr_debug 格式化、led_trigger_event、complete()，这些在硬中断里做有风险，所以 s3cmci_irq() 最后排 tasklet 而不是直接调。
