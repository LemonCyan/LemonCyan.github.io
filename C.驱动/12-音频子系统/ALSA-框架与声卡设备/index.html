一、ALSA 是什么：音频子系统的整体架构 #

音频设备接口有 PCM、I2S、AC97 等，分别对应不同场合。Linux 内核里有两类音频驱动框架：

  • OSS：开放声音系统，包含 dsp 和 mixer 字符设备接口，应用访问底层硬件是直接通过 sound 设备节点实现的；
  • ALSA：先进 Linux 声音架构，以 card 和组件（PCM、mixer 等）为单位，应用通过 alsa-lib 库访问底层硬件，不再直接碰 sound 设备节点。

ALSA 全称 Advanced Linux Sound Architecture，由一系列内核驱动、应用编程接口和上层应用组成。项目起因是 OSS 维护乏力、落后于新声卡技术。Jaroslav Kysela 早先写了一个声卡驱动，由此开始 ALSA 项目，随后更多开发者加入，支持的声卡变多，API 结构也被重组过一轮。它现在是 Linux 上的主流音频体系。

注意 ALSA 和 ASoC 不是一个东西。ALSA 是通用音频子系统，ASoC（ALSA System on Chip）是在 ALSA CORE 之上针对嵌入式 SoC 做的一层封装，代码在 sound/soc。内核文档 Documentation/sound/soc/overview.rst 列出了 ASoC 出现前 SoC 音频支持的三条限制：

  • 标准 ALSA 驱动框架里 Codec 驱动往往与 SoC 耦合过紧，不利于在多样化平台/机器上移植复用。例如仅 wm8731 一个驱动，当时内核里就有分别针对 4 个平台的代码；
  • 音频事件没有标准方法通知用户。耳机、麦克风插拔检测在移动设备上很常见，而且往往需要特定于机器的代码重新配置音频路径；
  • 播放或录音时驱动会让整个 Codec 上电。这对 PC 没问题，对移动设备意味着白耗电，也不支持通过改变过取样频率和偏置电流省电。

ASoC 正是为解决这些问题提出的，它把音频硬件驱动拆成 Machine、Platform、Codec 三个可重用组件。RK3399 这块板上：

  • Platform 描述 RK3399；
  • Codec 描述 ALC5651；
  • Machine 描述 RK3399 与 ALC5651 的关系。
组件 对应实体 可重用性 主要内容
Machine 某款设备/开发板/手机 几乎不可重用 dai_link、snd_soc_card 注册、插拔检测、功放开关
Platform 某颗 SoC（RK3399） 同 SoC 可复用 cpu_dai（I2S/PCM 控制器）、DMA、DSP
Codec 某颗声卡芯片（ALC5651） 可跨 Machine 复用 DAI/PCM 配置、I2C/SPI 控制接口、Mixer、DAPM

软件架构自上而下是：应用程序 → ALSA Library API → ALSA CORE → ASoC CORE → 硬件驱动（Machine/Platform/Codec）→ 硬件设备。

  • 应用程序：tinyplay/tinycap/tinymix，直接调用户库接口完成放音、录音、控制；
  • ALSA Library API：统一 API，隐藏驱动层实现细节。常见实现是 alsa-lib 和它的精简版 tinyalsa；
  • ALSA CORE：向上提供逻辑设备（PCM/CTL/MIDI/TIMER/…）的系统调用，向下驱动硬件设备；
  • ASoC CORE：建立在 ALSA CORE 之上，把硬件驱动划分为 Codec、Platform、Machine；
  • Hardware Driver：由 Machine、Platform、Codec 三部分组成。

为什么中间要加一层库？上层应用的人不该关心硬件实现，早年的做法是给硬件写驱动、应用直接调驱动。简单应用没问题，复杂硬件就不行了，应用得了解一大堆驱动接口。于是中间加了库，把声卡复杂的使用方法封起来。

二、ALSA 的分层与设备节点 #

用户能看到的第一层落点是 /dev/snd。这些字符设备主设备号都是 116：

bash
root@zhengyang:~# ll /dev/snd
crw-rw----+  1 root audio 116,  6 Jul  6 18:39 controlC0
crw-rw----+  1 root audio 116,  5 Jul  6 18:39 midiC0D0
crw-rw----+  1 root audio 116,  3 Jul  6 18:39 pcmC0D0c
crw-rw----+  1 root audio 116,  2 Jul  6 18:39 pcmC0D0p
crw-rw----+  1 root audio 116,  4 Jul  6 18:39 pcmC0D1p
crw-rw----+  1 root audio 116,  1 Jul  6 18:39 seq
crw-rw----+  1 root audio 116, 33 Jul  6 18:39 timer
节点 用途
controlC0 声卡控制：通道选择、混音、麦克控制、音量加减、开关等
midiC0D0 播放 MIDI
pcmC0D0c 录音 PCM 设备
pcmC0D0p 播放 PCM 设备
pcmC0D1p 第二个播放 PCM 设备
seq 音序器
timer 定时器

命名规则：C0D0 是声卡 0 的设备 0，末位 c 是 capture，p 是 playback。声卡 0 下挂了 5 个设备，按声卡实际能力可以挂更多种类。实际驱动里更常打交道的是 pcm 和 control 两类，一个声卡默认对应一个 Control 设备。

/dev/snd 下面这些节点是怎么来的？三步。

第一步，注册字符设备并挂上公共 open。alsa_sound_init（sound/core/sound.c）用 register_chrdev(major, "alsa", &snd_fops) 注册主设备号 116，所有次设备共用一套 snd_fops（.open = snd_open、.llseek = noop_llseek）。

第二步，snd_open 按次设备号把 file->f_op 换成真实设备的操作集：

c
static int snd_open(struct inode *inode, struct file *file)
{
        unsigned int minor = iminor(inode);        // 次设备号
        int err = 0;
        if (minor >= ARRAY_SIZE(snd_minors)) return -ENODEV;
        mutex_lock(&sound_mutex);
        mptr = snd_minors[minor];        // 取具体逻辑设备的上下文
        if (mptr == NULL) {
                mptr = autoload_device(minor);
                if (!mptr) { mutex_unlock(&sound_mutex); return -ENODEV; }
        }
        new_fops = fops_get(mptr->f_ops);  // 取出该逻辑设备的文件操作集
        mutex_unlock(&sound_mutex);
        replace_fops(file, new_fops);       // 替换 file->f_op
        if (file->f_op->open)
                err = file->f_op->open(inode, file);  // 执行该次设备自己的 open
        return err;
}

file->f_op 换掉之后，应用后续所有 read/write/ioctl 都会落进具体逻辑设备的回调。这一手是 ALSA 整个设备节点模型的支点。

第三步，sound_class 决定设备节点路径。init_soundcore（sound/sound_core.c）建类并挂 devnode 回调：

c
static int __init init_soundcore(void)
{
        sound_class = class_create(THIS_MODULE, "sound");  // 创建 /sys/class/sound
        sound_class->devnode = sound_devnode;
        return 0;
}
static char *sound_devnode(struct device *dev, umode_t *mode)
{
        if (MAJOR(dev->devt) == SOUND_MAJOR)       // 主设备号 14（OSS）时不建节点
                return NULL;
        return kasprintf(GFP_KERNEL, "snd/%s", dev_name(dev));   // /dev/snd/xxx
}

udev 按 devnode 的返回值建节点，并设置权限、属主、属组。

层次上要记住四组结构：snd_card（声卡）、snd_device（声卡下的逻辑设备节点）、snd_minor（次设备上下文）、具体设备结构（snd_pcm/snd_kcontrol/snd_jack）。snd_device 挂进 card->devices 链表，snd_minor 存进全局 snd_minors[] 数组，snd_card 存进全局 snd_cards[] 数组。三张表各管一件事。

三、snd_card：声卡的抽象 #

snd_card 是整个 ALSA 音频驱动最顶层的结构，几乎所有与声音相关的逻辑设备都在它的管理之下。声卡驱动的第一个动作就是创建一个 snd_card。定义在 include/sound/core.h：

c
/* main structure for soundcard */
struct snd_card {
        int number;                     /* number of soundcard (index to
                                                                snd_cards) */

        char driver[16];                /* driver name */
        char shortname[32];             /* short name of this soundcard */
        char longname[80];              /* name of this soundcard */
        char irq_descr[32];             /* Interrupt description */
        char mixername[80];             /* mixer name */
        char components[128];           /* card components delimited with
                                                                space */
        struct module *module;          /* top-level module */
        void *private_data;             /* private data for soundcard */
        void (*private_free) (struct snd_card *card); /* callback for freeing of
                                                                private data */
        struct list_head devices;       /* devices */
        struct device ctl_dev;          /* control device */
        unsigned int last_numid;        /* last used numeric ID */
        struct rw_semaphore controls_rwsem;     /* controls list lock */
        rwlock_t ctl_files_rwlock;      /* ctl_files list lock */
        int controls_count;             /* count of all controls */
        int user_ctl_count;             /* count of all user controls */
        struct list_head controls;      /* all controls for this card */
        struct list_head ctl_files;     /* active control files */
        struct snd_info_entry *proc_root;       /* root for soundcard specific files */
        struct proc_dir_entry *proc_root_link;  /* number link to real id */
        struct list_head files_list;    /* all files associated to this card */
        struct snd_shutdown_f_ops *s_f_ops; /* file operations in the shutdown

        spinlock_t files_lock;          /* lock the files for this card */
        int shutdown;                   /* this card is going down */
        struct device *dev;             /* device assigned to this card */
        struct device card_dev;         /* cardX object for sysfs */
        const struct attribute_group *dev_groups[4]; /* assigned sysfs attr */

        unsigned int power_state;       /* power state */

创建出来的声卡被塞进全局数组：

c
static struct snd_card *snd_cards[SNDRV_CARDS];

编号占用靠一张位图，sound/core/init.c：

c
static DECLARE_BITMAP(snd_cards_lock, SNDRV_CARDS);
static struct snd_card *snd_cards[SNDRV_CARDS];

位图紧凑表示每个编号是否已被实例化。DECLARE_BITMAP 会把变量放到内核数据段，大小是 SNDRV_CARDS（默认 8），即支持的最大声卡数。第 6 位为 1 就表示编号 6 已被占用，对应实例存在 snd_cards[6]，每个元素指向一个 snd_card。

当前可用的最大编号由 snd_ecards_limit 跟踪，定义在 sound/core/sound.c：

text
/* this one holds the actual max. card number currently available.
 * as default, it's identical with cards_limit option.  when more
 * modules are loaded manually, this limit number increases, too.
 */
int snd_ecards_limit;
EXPORT_SYMBOL(snd_ecards_limit);

逻辑设备的抽象是 snd_device，定义在 sound/core/device.c：

c
struct snd_device {
        struct list_head list;          /* list of registered devices */
        struct snd_card *card;          /* card which holds this device */
        enum snd_device_state state;    /* state of the device */
        enum snd_device_type type;      /* device type */
        void *device_data;              /* device structure */
        struct snd_device_ops *ops;     /* operations */
};
  • list：双向链表节点，挂在 snd_card->devices 上；
  • card：所属声卡；
  • state：设备状态；
  • type：设备类型，比如 PCM、control；
  • device_data：具体功能模块结构，比如 PCM 设备这里放 snd_pcm；
  • ops：逻辑设备操作集。

每个逻辑设备最终都走 snd_device_new 生成一个 snd_device 并挂进 card->devices。不必直接调它，内核已封装常用创建函数：

text

TIMER      --      snd_timer_new()
INFO       --      snd_card_proc_new()

操作集定义在 include/sound/core.h：

c
struct snd_device_ops {
        int (*dev_free)(struct snd_device *dev);
        int (*dev_register)(struct snd_device *dev);
        int (*dev_disconnect)(struct snd_device *dev);

  • dev_free：卸载声卡时调用；
  • dev_register：注册声卡时调用；
  • dev_disconnect：关闭声卡时调用。

状态机有三个值：

c
enum snd_device_state {
        SNDRV_DEV_BUILD,         // 构建中
        SNDRV_DEV_REGISTERED,    // 已注册，准备就绪
        SNDRV_DEV_DISCONNECTED,  // 已断开连接
};

注意注释——control 必须排最后：

c

 * this also defines the calling order */

        SNDRV_DEV_LOWLEVEL,     // 低级别硬件访问接口
        SNDRV_DEV_INFO,         // 信息查询接口
        SNDRV_DEV_BUS,          // 总线接口，如 USB、PCI
        SNDRV_DEV_CODEC,        // 编解码器设备
        SNDRV_DEV_PCM,          // PCM 设备
        SNDRV_DEV_COMPRESS,     // 压缩/解压缩设备
        SNDRV_DEV_RAWMIDI,      // 原始 MIDI 设备
        SNDRV_DEV_TIMER,        // 定时器设备
        SNDRV_DEV_SEQUENCER,    // 序列器设备
        SNDRV_DEV_HWDEP,        // 硬件依赖设备
        SNDRV_DEV_JACK,         // Jack 设备
        SNDRV_DEV_CONTROL,      /* NOTE: this must be the last one */
};

次设备上下文是 snd_minor，snd_register_device 时初始化：type 是 SNDRV_DEVICE_TYPE_XXX，card 是所属声卡编号，device 是设备索引，f_ops 是文件操作集，private_data 传给 f_ops->open，dev 是对应 device，card_ptr 指回声卡。每个 snd_minor 由 snd_register_device 创建并挂进全局 snd_minors[SNDRV_OS_MINORS] 数组。

三者的关系一句话概括：snd_card 是容器，snd_device 是容器里的挂件（描述「这台声卡有哪些逻辑设备」），snd_minor 是字符设备侧的索引（描述「次设备号 X 对应哪个文件操作集」）。前两者是逻辑归属，后者是内核 device 模型与 open 路径。

四、声卡的创建与注册 #

snd_card_new 创建并初始化 snd_card（sound/core/init.c）。原型六参：parent（父设备，一般是 platform device）、idx（索引）、xid（标识）、module（锁定用的顶层模块）、extra_size（紧跟主结构分配的额外空间）、card_ret（返回 snd_card）。

c
int snd_card_new(struct device *parent, int idx, const char *xid,
                    struct module *module, int extra_size,
                    struct snd_card **card_ret)

主流程：

c
        if (extra_size < 0)
                extra_size = 0;
        card = kzalloc(sizeof(*card) + extra_size, GFP_KERNEL);      // 主结构 + 额外空间
        if (extra_size > 0)
                card->private_data = (char *)card + sizeof(struct snd_card);  // 私有数据指向尾部
        if (xid)
                strlcpy(card->id, xid, sizeof(card->id));    // 声卡标识
        mutex_lock(&snd_card_mutex);
        if (idx < 0) /* first check the matching module-name slot */
                idx = get_slot_from_bitmask(idx, module_slot_match, module);
        if (idx < 0) /* if not matched, assign an empty slot */
                idx = get_slot_from_bitmask(idx, check_empty_slot, module);
        if (idx < 0)
                err = -ENODEV;
        else if (idx < snd_ecards_limit) {
                if (test_bit(idx, snd_cards_lock))      // 索引已被占用
                        err = -EBUSY;   /* invalid */
        } else if (idx >= SNDRV_CARDS)                   // 超过最大声卡数
                err = -ENODEV;
        if (err < 0) {
                mutex_unlock(&snd_card_mutex);
                dev_err(parent, "cannot find the slot for index %d (range 0-%i), error: %d\n",
                         idx, snd_ecards_limit - 1, err);
                kfree(card);
                return err;
        }
        set_bit(idx, snd_cards_lock);           /* lock it */
        if (idx >= snd_ecards_limit)
                snd_ecards_limit = idx + 1;     /* increase the limit */
        mutex_unlock(&snd_card_mutex);
        card->dev = parent;
        card->number = idx;
        card->module = module;
        INIT_LIST_HEAD(&card->devices);
        init_rwsem(&card->controls_rwsem);
        rwlock_init(&card->ctl_files_rwlock);
        INIT_LIST_HEAD(&card->controls);
        INIT_LIST_HEAD(&card->ctl_files);
        spin_lock_init(&card->files_lock);
        INIT_LIST_HEAD(&card->files_list);
#ifdef CONFIG_PM
        init_waitqueue_head(&card->power_sleep);
#endif
        init_waitqueue_head(&card->remove_sleep);
        device_initialize(&card->card_dev);        // 设备初始化
        card->card_dev.parent = parent;
        card->card_dev.class = sound_class;
        card->card_dev.release = release_card_device;
        card->card_dev.groups = card->dev_groups;
        card->dev_groups[0] = &card_dev_attr_group;
        err = kobject_set_name(&card->card_dev.kobj, "card%d", idx);  // 名称 card%d
        snprintf(card->irq_descr, sizeof(card->irq_descr), "%s:%s",
                 dev_driver_string(card->dev), dev_name(&card->card_dev));
        err = snd_ctl_create(card);   // 创建 control 设备
        err = snd_info_card_create(card);  // 创建声卡的 proc 条目
        *card_ret = card;
        return 0;

七步：

  1. kzalloc(sizeof(*card) + extra_size) 一次分配主结构加私有区，负值先归零；
  2. 分配编号：先按模块名匹配槽位，匹配不上找空槽，范围 0~SNDRV_CARDS-1；test_bit 检查、set_bit 占位，必要时抬高 snd_ecards_limit；
  3. 初始化 dev/number/module、四个链表头、读写信号量、读写自旋锁、自旋锁、两个等待队列头；
  4. device_initialize(&card->card_dev)，再设 parent、class = sound_class、release、groups，kobject_set_name(..., "card%d", idx)；
  5. 填 irq_descr；
  6. snd_ctl_create(card) 建 control 逻辑设备，snd_info_card_create(card) 建 proc 条目。

内核版本提示：extra_size 的参数语义（跟着主结构一起 kzalloc，private_data 指向尾部）与 v6.3 一致。素材第 551 行把返回参数写成 card_set，实际是 card_ret，已修正。那块额外内存跟着主结构一起释放，private_free 只在里面又挂了别的资源时才需要。

snd_card_register #

注册走 snd_card_register（sound/core/init.c）。函数头注释说得很清楚：调用它之前，ALSA control 接口对外不可访问，所以必须在声卡初始化末尾调。核心逻辑：

c
int snd_card_register(struct snd_card *card)
{
        if (!card->registered) {     // 未注册则挂 card_dev
                err = device_add(&card->card_dev);
                if (err < 0) return err;
                card->registered = true;
        }
        if ((err = snd_device_register_all(card)) < 0)  // 遍历 devices 注册所有逻辑设备
                return err;
        mutex_lock(&snd_card_mutex);
        if (snd_cards[card->number]) {    // 已注册过
                mutex_unlock(&snd_card_mutex);
                return snd_info_card_register(card);
        }
        if (*card->id) {    // 已设置标识
                char tmpid[sizeof(card->id)];
                memcpy(tmpid, card->id, sizeof(card->id));
                snd_card_set_id_no_lock(card, tmpid, tmpid);
        } else {
                /* 用 shortname 或 longname 生成 id */
                const char *src = *card->shortname ? card->shortname : card->longname;
                snd_card_set_id_no_lock(card, src, retrieve_id_from_card_name(src));
        }
        snd_cards[card->number] = card;
        mutex_unlock(&snd_card_mutex);
        return snd_info_card_register(card);
}

干了四件事：

  • device_add(&card->card_dev)，在 /sys/class/sound 下建 card%d 链接。devt 未设置（默认 0），所以不会在 /dev/snd 下建 card%d 节点；
  • snd_device_register_all 注册所有逻辑设备；
  • 设置唯一 id 并把声卡存进 snd_cards[]；
  • snd_info_card_register 注册 proc 文件，在 /proc/asound 下建 card%d 的符号链接，链接名就是声卡 id。

*card->id 为空时用 shortname 或 longname 生成 id，snd_card_set_id_no_lock 保证唯一（重名加后缀）。所以 id 不必手填。

int snd_device_register_all(struct snd_card *card)

五、逻辑设备的创建 #

声卡下的功能模块（PCM 录音播放、Control 控制）被抽象成逻辑设备，用 snd_device 表示。ALSA 提供 snd_device_new 分配并挂链表，snd_register_device 负责注册。

snd_device_new（sound/core/device.c）：

c
int snd_device_new(struct snd_card *card, enum snd_device_type type,
                   void *device_data, struct snd_device_ops *ops)
{
        if (snd_BUG_ON(!card || !device_data || !ops)) return -ENXIO;
        dev = kzalloc(sizeof(*dev), GFP_KERNEL);  // 分配 snd_device
        if (!dev) return -ENOMEM;
        INIT_LIST_HEAD(&dev->list);      // 初始化链表节点
        dev->card = card;                // 所属声卡
        dev->type = type;                // 类型
        dev->state = SNDRV_DEV_BUILD;    // 状态
        dev->device_data = device_data;  // 额外数据
        dev->ops = ops;                  // 操作集
        /* insert the entry in an incrementally sorted list */
        list_for_each_prev(p, &card->devices) {   // 按 type 从大到小找插入点
                struct snd_device *pdev = list_entry(p, struct snd_device, list);
                if ((unsigned int)pdev->type <= (unsigned int)type) break;
        }
        list_add(&dev->list, p);  // 插到 p 之后
        return 0;
}

四个参数：card、type（SNDRV_DEV_XXX）、device_data（开发者传入的设备数据）、ops（回调集）。

插入用 list_for_each_prev 反向遍历，找到第一个 type <= 新 type 的节点就停，然后把新节点插在它后面。结果是链表按 type 降序排列。这直接决定了 snd_device_register_all 的注册顺序——SNDRV_DEV_CONTROL 最大，排在最前，所以 control 最先被注册；SNDRV_DEV_JACK 次之。这就是枚举注释里那句「this must be the last one」真正的含义：它要保证 control 先于其他设备注册。

snd_register_device（sound/core/sound.c）接六个参数：

  • type：设备类型，control 用 SNDRV_DEVICE_TYPE_CONTROL，pcm 用 SNDRV_DEVICE_TYPE_PCM_PLAYBACK/SNDRV_DEVICE_TYPE_PCM_CAPTURE；
  • card：所属 snd_card；
  • dev：逻辑设备编号，多数情况为 0；
  • f_ops：文件操作集，control 用 snd_ctl_f_ops；
  • private_data：传给 f_ops->open 的私有数据，pcm 用 snd_pcm 实例；
  • device：对应的 struct device，pcm 用 &pcm->streams[i].dev。
c
int snd_register_device(int type, struct snd_card *card, int dev,
                        const struct file_operations *f_ops,
                        void *private_data, struct device *device)
{
        int minor;
        int err = 0;
        if (snd_BUG_ON(!device)) return -EINVAL;
        preg = kmalloc(sizeof *preg, GFP_KERNEL);   // 分配 snd_minor
        if (preg == NULL) return -ENOMEM;
        preg->type = type;                      // 类型
        preg->card = card ? card->number : -1;  // 声卡编号
        preg->device = dev;                     // 逻辑设备编号
        preg->f_ops = f_ops;                    // 文件操作集
        preg->private_data = private_data;      // 私有数据
        preg->card_ptr = card;                  // 声卡指针
        mutex_lock(&sound_mutex);               // 互斥锁
        minor = snd_find_free_minor(type, card, dev);  // 取一个可用次设备号
        if (minor < 0) {
                err = minor;
                goto error;
        }
        preg->dev = device;                     // 对应 device
        device->devt = MKDEV(major, minor);     // 主设备号 116，静态变量 major
        err = device_add(device);               // 注册 device
                                                // control：/sys/class/sound/controlCxx + /dev/snd/controlCxx
                                                // pcm：/sys/class/sound/pcmCxxDxxp|c + /dev/snd/pcmCxxDxxp|c
        snd_minors[minor] = preg;    // 存进全局数组
 error:
        mutex_unlock(&sound_mutex);  // 释放互斥锁
        if (err < 0)
                kfree(preg);
        return err;
}

流程：分配 snd_minor 填好各字段 → snd_find_free_minor 找空次设备号 → MKDEV(major, minor) 设设备号 → device_add 挂设备模型，同时由 udev 建 /dev/snd 节点 → snd_minors[minor] 落库。

这里 major 是静态变量，值 116，和 alsa_sound_init 里 register_chrdev(major, ...) 用的是同一个。次设备号是逻辑设备的「槽位」，/dev/snd 下的文件名由 dev_name(device) 决定，也就是前面 dev_set_name 设的 controlC%d、pcmC%iD%i%c。

六、PCM 设备：音频数据的通道 #

PCM 本身是一种音频编码格式，更准确说是把声音从模拟信号转成数字信号的技术。音频驱动的两大核心任务：

  • playback：把用户空间发来的 PCM 数据转成人耳能分辨的模拟音频；
  • capture：把 mic 拾取的模拟信号经采样、量化转成 PCM 数据送回用户空间。

ALSA CORE 已实现 PCM 中间层，驱动只需实现真正访问硬件的那几个函数。两个头文件：

  • include/sound/pcm.h：PCM 中间层 API；
  • include/sound/pcm_params.h：hw_params 相关函数。

struct snd_pcm 描述一个 PCM 实例，它由一个 playback stream 和一个 capture stream 组成，每个 stream 又由一个或多个 substream 组成：

c
struct snd_pcm {
        struct list_head list;
        int device; /* device number */
        unsigned int info_flags;
        unsigned short dev_class;
        unsigned short dev_subclass;
        char id[64];
        char name[80];
        struct snd_pcm_str streams[2];
        struct mutex open_mutex;
        wait_queue_head_t open_wait;
        void *private_data;
        void (*private_free) (struct snd_pcm *pcm);
        bool internal; /* pcm is for internal use only */
        bool nonatomic; /* whole PCM operations are in non-atomic context */
        bool no_device_suspend; /* don't invoke device PM suspend */
#if IS_ENABLED(CONFIG_SND_PCM_OSS)
        struct snd_pcm_oss oss;
#endif
};

关键成员：card 声卡、device PCM 编号、streams[2]（下标 0 是 playback、1 是 capture）、private_data 私有数据（很多结构体都有这个字段）。嵌入式系统里没这么绕：一个声卡、一个 PCM 实例，下面一个 playback stream 和一个 capture stream，各自一个 substream。

struct snd_pcm_str 表示 PCM stream（include/sound/pcm.h）：

c
struct snd_pcm_str {
        int stream;                             /* stream (direction) */
        unsigned int substream_count;
        unsigned int substream_opened;
#ifdef CONFIG_SND_VERBOSE_PROCFS
#ifdef CONFIG_SND_PCM_XRUN_DEBUG
        unsigned int xrun_debug;        /* 0 = disabled, 1 = verbose, 2 = stacktrace */
#endif
#endif
        struct snd_kcontrol *chmap_kctl; /* channel-mapping controls */
        struct device dev;
};

（CONFIG_SND_PCM_OSS 打开时还有 struct snd_pcm_oss_stream oss，这里没列。）stream 是方向，substream_count 是 substream 个数，substream_opened 是打开标志，substream 指向所有 substream 串成的链表，proc_root 是 proc 目录条目，xrun_debug 是 xrun 调试开关，chmap_kctl 是声道映射控件，dev 是设备模型里的 device。

snd_pcm_str 存在的唯一理由就是 substream 会有多个。若恒为一个，snd_pcm 直接指向 snd_pcm_substream 就够了。

snd_pcm_ops：驱动要填的回调 #

PCM 中间层和驱动之间的契约是 snd_pcm_ops。素材没贴完整定义，按 v6.3 include/sound/pcm.h，驱动侧要实现的回调是这十来个：

回调 时机 典型工作
open / close 首次打开 / 关闭 substream 使能或关闭时钟、复位控制器
hw_params / hw_free 设 / 释放硬件参数 配采样率声道格式，分配或释放 DMA
prepare START 前预备 清 FIFO、复位指针
trigger START/STOP/PAUSE 启动或停止 I2S TX/RX
pointer 查询硬件位置 读 FIFO 或 DMA 计数返回 hw_ptr
copy / copy_user 非 mmap 路径拷贝数据 软件搬运
ack / silence 结束拷入 / 填静音 唤醒写等待、下溢填充
mmap mmap 映射 返回 DMA 区

ASoC 场景下这些不用你填，snd_soc_pcm_runtime 里有一份 struct snd_pcm_ops ops，注册时被初始化成那套 soc_pcm_* 包装。

相关参数结构 #

snd_pcm_hw_params 定义在 include/uapi/sound/asound.h，描述通道数、采样率、数据格式等硬件参数：

        unsigned int cmask;             /* R: changed masks */

        unsigned int msbits;            /* R: used most significant bits */

成员 含义

intervals 每个下标对应一个参数：

下标宏 含义
SNDRV_PCM_HW_PARAM_SAMPLE_BITS 每个采样点的位数，即位宽
SNDRV_PCM_HW_PARAM_FRAME_BITS 每帧占用位数

FRAME_BITS 怎么算，举个例子：采样率 44100 Hz、双声道、每采样点 16 bit，则每帧比特数 = 16 bits/sample × 2 channels = 32 bits/frame。

对比 snd_soc_dai_link 和 snd_soc_pcm_runtime 你会发现：两者描述的是同一样东西——音频数据链路，只不过一个描述静态配置，另一个描述运行期状态。

PCM 中间层的结构关系抓住这四点：

  • pcm 是挂在 snd_card->devices 下面的一个 snd_device；
  • snd_pcm 的 streams[2] 指向两个 snd_pcm_str，分别代表 playback 与 capture；
  • snd_pcm_str->substream 指向 snd_pcm_substream；
  • snd_pcm_substream 是 PCM 中间层的核心，绝大部分任务都在它里面处理。尤其是它的 ops（snd_pcm_ops）——用户空间通过 alsa-lib 发来的请求都由这里的函数处理；runtime 指向 snd_pcm_runtime，记录该 substream 的软硬件运行环境与参数。

PCM 的创建 #

snd_pcm_new 接六个参数：card、id（PCM 唯一标识）、device（该声卡下第几个 pcm，从 0 起）、playback_count（playback substream 数）、capture_count（capture substream 数）、rpcm（返回创建的 PCM 设备）。定义在 sound/core/pcm.c，只是转调 _snd_pcm_new：

c
int snd_pcm_new(struct snd_card *card, const char *id, int device,
                int playback_count, int capture_count, struct snd_pcm **rpcm)
{
        return _snd_pcm_new(card, id, device, playback_count, capture_count,
                        false, rpcm);
}

_snd_pcm_new 里：kzalloc 一个 snd_pcm，填 card/device/internal，mutex_init(&pcm->open_mutex)、init_waitqueue_head(&pcm->open_wait)、INIT_LIST_HEAD(&pcm->list)、strscpy(pcm->id, id, ...)；然后调两次 snd_pcm_new_stream 分别建 playback 与 capture；最后 snd_device_new(card, SNDRV_DEV_PCM, pcm, ...) 挂到声卡。

两种 ops 的差别决定了内部 PCM 有没有节点：

c
        static const struct snd_device_ops ops = {  // 普通 pcm 逻辑设备操作集
                .dev_free = snd_pcm_dev_free,
                .dev_register = snd_pcm_dev_register,
                .dev_disconnect = snd_pcm_dev_disconnect,
        };

snd_pcm_new 传 internal = false 用完整 ops；snd_pcm_new_internal 传 true 只用 internal_ops（只有 dev_free），所以内部 PCM 不建设备节点、不建 proc 目录。

snd_pcm_new_stream(pcm, stream, substream_count) 建数据流（sound/core/pcm.c）。先填 pstr 三个字段，substream_count 为 0 直接返回：

c
        pstr->stream = stream;    // 方向
        pstr->pcm = pcm;          // PCM 实例
        pstr->substream_count = substream_count;
        if (!substream_count)
                return 0;         // 该方向没有 substream
        snd_device_initialize(&pstr->dev, pcm->card);
        pstr->dev.groups = pcm_dev_attr_groups;
        pstr->dev.type = &pcm_dev_type;
        dev_set_name(&pstr->dev, "pcmC%iD%i%c", pcm->card->number, pcm->device,
                     stream == SNDRV_PCM_STREAM_PLAYBACK ? 'p' : 'c');  // pcmC0Dxp 或 pcmC0Dxc

然后按 substream_count 循环建 substream 串成单向链表——kzalloc 一块、填 pcm/pstr/number/stream/name/buffer_bytes_max = UINT_MAX，pstr->substream 指向第一个，后续用 prev->next 串起来；internal 为假时顺手调 snd_pcm_stream_proc_init 和 snd_pcm_substream_proc_init 建 proc 条目：

c
        for (idx = 0, prev = NULL; idx < substream_count; idx++) {
                substream = kzalloc(sizeof(*substream), GFP_KERNEL);
                substream->pcm = pcm;
                substream->pstr = pstr;
                substream->number = idx;
                substream->stream = stream;
                sprintf(substream->name, "subdevice #%i", idx);
                substream->buffer_bytes_max = UINT_MAX;
                if (prev == NULL)
                        pstr->substream = substream;

                        prev->next = substream;
                if (!pcm->internal)
                        snd_pcm_substream_proc_init(substream);
                substream->group = &substream->self_group;
                snd_pcm_group_init(&substream->self_group);
                list_add_tail(&substream->link_list, &substream->self_group.substreams);
                atomic_set(&substream->mmap_count, 0);
                prev = substream;
        }

四个要点：dev_set_name 决定 /dev/snd 下的名字，即 pcmC<card>D<device>p 或 pcmC<card>D<device>c；buffer_bytes_max 先给 UINT_MAX，之后由驱动下调；每个 substream 自带 self_group，link_list 挂进自己的 group，供 SNDRV_PCM_IOCTL_LINK 使用。

snd_pcm_stream_proc_init 在 card->proc_root 下建 pcm%i%c 目录（mode = S_IFDIR | 0555）存进 pstr->proc_root，再在其中建 info 文件挂 snd_pcm_stream_proc_info_read；开了 CONFIG_SND_PCM_XRUN_DEBUG 还会多建一个可读写的 xrun_debug：

                pstr->stream == SNDRV_PCM_STREAM_PLAYBACK ? 'p' : 'c');

        entry->mode = S_IFDIR | 0555;
        pstr->proc_root = entry;
        entry = snd_info_create_card_entry(pcm->card, "info", pstr->proc_root);

PCM 的注册 #

注册声卡时遍历 devices 链表调 ops->dev_register，PCM 这里是 snd_pcm_dev_register（sound/core/pcm.c）。它先 snd_pcm_add(pcm) 挂进全局链表，再按 cidx 循环 0/1 分别注册 playback 与 capture：

c
static int snd_pcm_dev_register(struct snd_device *device)
{
        pcm = device->device_data;          // 取 snd_pcm 实例
        mutex_lock(&register_mutex);
        err = snd_pcm_add(pcm);        // 添加到全局链表 snd_pcm_devices
        for (cidx = 0; cidx < 2; cidx++) {
                int devtype = -1;
                if (pcm->streams[cidx].substream == NULL)
                        continue;       // 该方向没建，跳过
                switch (cidx) {
                case SNDRV_PCM_STREAM_PLAYBACK:    // 0
                        devtype = SNDRV_DEVICE_TYPE_PCM_PLAYBACK;
                        break;
                case SNDRV_PCM_STREAM_CAPTURE:     // 1
                        devtype = SNDRV_DEVICE_TYPE_PCM_CAPTURE;
                        break;
                }
                err = snd_register_device(devtype, pcm->card, pcm->device, // 类型 声卡 设备号
                                          &snd_pcm_f_ops[cidx], pcm,
                                          &pcm->streams[cidx].dev);
                if (err < 0) {
                        list_del_init(&pcm->list);
                        goto unlock;
                }
                for (substream = pcm->streams[cidx].substream; substream; substream = substream->next)
                        snd_pcm_timer_init(substream);
        }
        pcm_call_notify(pcm, n_register);
 unlock:
        mutex_unlock(&register_mutex);
        return err;
}

pcm->streams[cidx].substream == NULL 就跳过——只建了 playback 没建 capture 的 PCM，不会凭空多出 /dev/snd/pcmCxDxc。

完整链路串起来是四步：

  1. snd_card_new：先有声卡；
  2. snd_pcm_new：建 playback stream 及 substream、建 capture stream 及 substream、snd_device_new 把 PCM 挂到声卡，ops.dev_register 指向 snd_pcm_dev_register；
  3. snd_pcm_set_ops：设置操作该 PCM 的 snd_pcm_ops，里面就是你要实现的函数；
  4. snd_card_register：遍历声卡下所有逻辑设备调注册回调，PCM 走第 2 步登记的 snd_pcm_dev_register，建立 /dev/snd/pcmCxxDxxp 与 /dev/snd/pcmCxxDxxc。

ASoC 里创建 PCM 走 soc_create_pcm（sound/soc/soc-pcm.c），最终也是调 snd_pcm_new。三条分支的差别：dai_link->params 非空（codec-to-codec）和 no_pcm 为真（纯 FE/BE 内部链路）都用 snd_pcm_new_internal，即 internal = true，不建 /dev/snd 节点也不建 proc 目录；常规链路才用 snd_pcm_new，名字由 "%s %s-%d" 拼成 stream_name + codec_dai_name + num，例如 ff880000.i2s-rt5651-aif1 rt5651-aif1-0，与 /proc/asound/pcm 里的实际输出对得上。

七、substream 与 runtime #

struct snd_pcm_substream 是 PCM 中间层的核心（include/sound/pcm.h）：

c
struct snd_pcm_substream {
        void *private_data;             /* copied from pcm->private_data */
        int number;
        char name[32];                  /* substream name */
        int stream;                     /* stream (direction) */
        struct pm_qos_request latency_pm_qos_req; /* pm_qos request */
        size_t buffer_bytes_max;        /* limit ring buffer size */
        struct snd_dma_buffer dma_buffer;
        size_t dma_max;
        const struct snd_pcm_ops *ops;
        struct snd_timer *timer;                /* timer */
        unsigned timer_running: 1;      /* time is running */
        long wait_time; /* time in ms for R/W to wait for avail */
        struct list_head link_list;     /* linked list member */
        struct snd_pcm_group self_group;        /* fake group for non linked substream (with substream lock inside) */
        struct snd_pcm_group *group;            /* pointer to current group */
        int ref_count;
        atomic_t mmap_count;
        unsigned int f_flags;
        void (*pcm_release)(struct snd_pcm_substream *);
#if IS_ENABLED(CONFIG_SND_PCM_OSS)
        struct snd_pcm_oss_substream oss;
#endif
#ifdef CONFIG_SND_VERBOSE_PROCFS
#endif /* CONFIG_SND_VERBOSE_PROCFS */
        /* misc flags */
        unsigned int hw_opened: 1;
};

内容偏多，挑重点：

字段 含义
pcm / pstr 所属 PCM 设备与所属 stream
private_data 从 pcm->private_data 拷来
number substream 编号
name substream 名字，subdevice #N
buffer_bytes_max ring buffer 上限
dma_buffer / dma_max DMA 缓冲描述与上限
ops PCM 操作集，驱动要实现的那批函数指针
runtime 运行时实例，读写数据时由它控制节奏
timer / timer_running 定时器
next 指向下一个 substream，串成链表
link_list / self_group / group LINK ioctl 的链接基础
ref_count / mmap_count 引用计数与 mmap 计数
hw_opened 硬件是否已打开

ops 的设计与文件操作一脉相承：中间层定义骨架，具体动作交给实现者。group 的存在是因为用户空间可以用 SNDRV_PCM_IOCTL_LINK 把多个 substream 链起来统一操作；没链接时 group 指向自己的 self_group。

snd_pcm_runtime #

runtime 是 substream 的软硬件运行环境快照。下面这些字段都能在第九章的 snd_pcm_hw_params 里找到赋值点或引用点：

字段 含义 来源
state 状态机（OPEN/SETUP/PREPARED/RUNNING/DISCONNECTED 等） 多处引用
hw snd_pcm_hardware，硬件能力 引用 runtime->hw.info

control snd_pcm_control，内含 avail_min 引用
dma_area / dma_bytes DMA 区虚拟地址与大小 引用
boundary 指针回绕边界，2 的幂 赋值
access / format / subformat 访问方式与采样格式 赋值
channels / rate 声道数、采样率 赋值
period_size / periods / buffer_size 周期帧数、周期个数、缓冲区帧数 赋值
sample_bits / frame_bits / byte_align / min_align 位宽与对齐 计算
info 来自 params->info 赋值
rate_num / rate_den 采样率分子分母 赋值
no_period_wakeup 关闭周期唤醒 赋值
tstamp_mode / period_step 时间戳模式、period 步进 赋值
start_threshold / stop_threshold 启动、停止阈值 赋值

runtime->hw 里的 info 位标志（SNDRV_PCM_INFO_MMAP、SNDRV_PCM_INFO_EXPLICIT_SYNC、SNDRV_PCM_INFO_NO_PERIOD_WAKEUP）决定中间层走哪条路径。snd_pcm_open_substream 里那段：

    substream->dma_buffer.dev.need_sync)
        substream->runtime->hw.info |= SNDRV_PCM_INFO_EXPLICIT_SYNC;

就是打开时按 DMA 设备能力补 flag。

移植完驱动后 /dev/snd 下能看到节点，比如 NanoPC-T4 上跑 ALC5651：

bash

应用 open 一个 PCM，比如 /dev/snd/pcmC0D0p，会先走 snd_open 换成 snd_pcm_f_ops[0]，再执行其中的 snd_pcm_playback_open：

两个元素只差读写方向（都有 llseek = no_llseek）。snd_pcm_playback_open（sound/core/pcm_native.c）先 nonseekable_open，再 snd_lookup_minor_data(iminor(inode), SNDRV_DEVICE_TYPE_PCM_PLAYBACK) 取 snd_pcm 实例，然后调 snd_pcm_open(file, pcm, SNDRV_PCM_STREAM_PLAYBACK)，最后 snd_card_unref。

snd_pcm_open 处理阻塞语义。核心就那段循环：

c
        add_wait_queue(&pcm->open_wait, &wait);
        mutex_lock(&pcm->open_mutex);
        while (1) {
                err = snd_pcm_open_file(file, pcm, stream);
                if (err >= 0) break;
                if (err == -EAGAIN) {
                        if (file->f_flags & O_NONBLOCK) {  // 非阻塞
                                err = -EBUSY;
                                break;
                        }
                } else
                        break;
                set_current_state(TASK_INTERRUPTIBLE);
                mutex_unlock(&pcm->open_mutex);
                schedule();   // 让出 CPU，等 wake_up_interruptible(&pcm->open_wait)
                mutex_lock(&pcm->open_mutex);
                if (pcm->card->shutdown || signal_pending(current)) {
                        err = pcm->card->shutdown ? -ENODEV : -ERESTARTSYS;
                        break;
                }
        }
        remove_wait_queue(&pcm->open_wait, &wait);
        mutex_unlock(&pcm->open_mutex);

（init_waitqueue_entry(&wait, current) 在循环之前；原代码把 shutdown 和 signal_pending 分成两个 if，判定结果一致。）

进循环前还要 snd_card_file_add 记账、try_module_get 增模块引用；出错时反向 module_put + snd_card_file_remove。

语义：设备被占返回 -EAGAIN。阻塞模式下把进程挂到 pcm->open_wait 上睡下去，等别人释放；O_NONBLOCK 直接返回 -EBUSY。

snd_pcm_open_file 分配 snd_pcm_file 并把 substream 挂上去，然后交给 snd_pcm_open_substream：

c
        err = snd_pcm_attach_substream(pcm, stream, file, &substream); // 取空闲 substream
        if (err < 0) return err;
        if (substream->ref_count > 1) {   // 重复打开，跳过初始化
                *rsubstream = substream;
                return 0;
        }
        err = snd_pcm_hw_constraints_init(substream);   // 建约束表
        err = substream->ops->open(substream);          // 重点：驱动的 open
        substream->hw_opened = 1;
        err = snd_pcm_hw_constraints_complete(substream); // 约束与硬件能力对齐
        if (substream->managed_buffer_alloc &&
            substream->dma_buffer.dev.need_sync)
                substream->runtime->hw.info |= SNDRV_PCM_INFO_EXPLICIT_SYNC;
        *rsubstream = substream;

（每步之间的出错跳转已省略。）

顺序是关键：约束必须在驱动 open 里加、在 hw_params 之前加完。晚到 hw_params 就没用了。

ASoC 的 open 做了什么 #

ASoC 场景下 substream->ops 指向 rtd->ops，注册声卡时被初始化成：

text
rtd->ops.open           = soc_pcm_open;
rtd->ops.hw_params      = soc_pcm_hw_params;
rtd->ops.prepare        = soc_pcm_prepare;
rtd->ops.trigger        = soc_pcm_trigger;
rtd->ops.hw_free        = soc_pcm_hw_free;
rtd->ops.close          = soc_pcm_close;
rtd->ops.pointer        = soc_pcm_pointer;

全在 sound/soc/soc-pcm.c。soc_pcm_open 依次做：pinctrl_pm_select_default_state → 组件 runtime PM → soc_pcm_components_open → snd_soc_link_startup（dai_link 的 ops->startup）→ 逐个 snd_soc_dai_startup（cpu/codec dai 的 ops->startup）；之后汇总整条链路的硬件能力并做一致性检查：

c
        for_each_rtd_dais(rtd, i, dai) {  // dai = (rtd)->dais[i]
                ret = snd_soc_dai_startup(dai, substream); // dai->driver->ops->startup(...)
        }
        if (rtd->dai_link->dynamic || rtd->dai_link->no_pcm)
                goto dynamic;
        soc_pcm_init_runtime_hw(substream);      // 汇总 runtime->hw
        soc_pcm_update_symmetry(substream);
        ret = soc_hw_sanity_check(substream);
        soc_pcm_apply_msb(substream);
        for_each_rtd_dais(rtd, i, dai) {
                ret = soc_pcm_apply_symmetry(substream, dai);
        }
dynamic:
        snd_soc_runtime_activate(rtd, substream->stream);

外层只做一件事：snd_soc_dpcm_mutex_lock(rtd) → __soc_pcm_open → unlock。关闭路径对应 soc_pcm_close，会 snd_soc_dai_shutdown 并调 snd_soc_link_shutdown，素材未展开，细节留到 Platform/Codec 篇。

九、PCM 的硬件参数 #

应用配参数走 ioctl：

text
ioctl(fd, SNDRV_PCM_IOCTL_HW_PARAMS, params);

ioctl 三个参数：

  • 第一个是文件描述符；
  • 第二个是命令码，应用通过命令码控制驱动完成对应操作；
  • 第三个是可变参数 arg。ioctl 的 ... 只传一个参数，内核也不检查类型，所以只有两种传法：传一个整数，或传一个指针。

内核侧分发到 unlocked_ioctl 或 compat_ioctl：

text
long (*unlocked_ioctl) (struct file * fp, unsigned int request, unsigned long args);
long (*compat_ioctl) (struct file * fp, unsigned int request, unsigned long args);
  • unlocked_ioctl 在无大内核锁（BKL）的情况下调用。64 位用户程序跑 64 位内核，或 32 位用户程序跑 32 位内核，都走它；
  • compat_ioctl 是 64 位系统对 32 位 ioctl 的兼容路径，也在无 BKL 下调用。32 位用户程序调 64 位内核走这个。驱动没实现 compat_ioctl 的话，用户程序执行 ioctl 会拿到 Not a typewriter 错误。

以 unlocked_ioctl 为例，PCM 设备注册的是 snd_pcm_ioctl（sound/core/pcm_native.c）：

c
static long snd_pcm_ioctl(struct file *file, unsigned int cmd,
                          unsigned long arg)
{
        pcm_file = file->private_data;
        if (((cmd >> 8) & 0xff) != 'A') return -ENOTTY;
        return snd_pcm_common_ioctl(file, pcm_file->substream, cmd,
                                     (void __user *)arg);
}

命令码高位字节必须是 'A'，否则直接 -ENOTTY。snd_pcm_common_ioctl 是个大 switch（sound/core/pcm_native.c），入口先做三道检查：PCM_RUNTIME_CHECK 不过返回 -ENXIO；runtime->state 为 DISCONNECTED 返回 -EBADFD；snd_power_wait 等电源就绪。

分发逻辑：

c
        switch (cmd) {
        case SNDRV_PCM_IOCTL_PVERSION:  return put_user(SNDRV_PCM_VERSION, (int __user *)arg) ? -EFAULT : 0;
        case SNDRV_PCM_IOCTL_INFO:      return snd_pcm_info_user(substream, arg);
        case SNDRV_PCM_IOCTL_HW_REFINE: return snd_pcm_hw_refine_user(substream, arg);
        case SNDRV_PCM_IOCTL_HW_PARAMS: // 硬件参数配置
                return snd_pcm_hw_params_user(substream, arg);

hw_params 主流程 #

snd_pcm_hw_params_user 先把用户态参数拷进来：

static int snd_pcm_hw_params_user(struct snd_pcm_substream *substream,
                                  struct snd_pcm_hw_params __user * _params)
{
        int err;
        params = memdup_user(_params, sizeof(*params));
        if (IS_ERR(params)) return PTR_ERR(params);
        err = snd_pcm_hw_params(substream, params);  // 重点
        if (copy_to_user(_params, params, sizeof(*params)))
                err = -EFAULT;
end:
        kfree(params);
        return err;
}

返回值也是通过 copy_to_user 回写 params 的 cmask/info 等字段，所以这是双向拷贝。

snd_pcm_hw_params（sound/core/pcm_native.c）先把状态机卡住：

c

        case SNDRV_PCM_STATE_OPEN:
        case SNDRV_PCM_STATE_SETUP:

                    atomic_read(&substream->mmap_count))
                        err = -EBADFD;
                break;
        default:
                err = -EBADFD;
                break;

只有 OPEN/SETUP/PREPARED 允许重设参数，已 mmap 的非 OSS 流也不许改。然后：

        params->rmask = ~0U;                      // 全部参数需要 refine
        err = snd_pcm_hw_refine(substream, params);            // 收窄到可行域
        err = snd_pcm_hw_params_choose(substream, params);     // 挑一组具体值

                runtime->buffer_changed = err > 0;   // >0 表示重分配了

        if (substream->ops->hw_params != NULL) {
                err = substream->ops->hw_params(substream, params);  // 走到 soc_pcm_hw_params

然后填默认软件参数、算 boundary、清 DMA 区、改状态、注册 QoS，最后是出错路径：

 _error:

                        substream->ops->hw_free(substream);
                if (substream->managed_buffer_alloc)
                        snd_pcm_lib_free_pages(substream);

这段是全篇信息密度最高的地方，拆开看：

  1. 状态检查。只有 OPEN/SETUP/PREPARED 允许重设参数，其他状态一律 -EBADFD。已 mmap 的非 OSS 流也不许改。所以「hw_params 失败后必须重新 hw_params」不是建议而是硬规则——失败时状态被强制退回 OPEN。
  2. params->rmask = ~0U 表示「所有参数都需要 refine」，然后 snd_pcm_hw_refine 用约束表把应用给的参数收窄到可行域。
  3. snd_pcm_hw_params_choose 从收窄后的域里挑一组具体值。
  4. fixup_unreferenced_params 补齐那些应用没指定、但驱动依赖的参数。
  5. snd_pcm_lib_malloc_pages(substream, params_buffer_bytes(params))。条件是 substream->managed_buffer_alloc 为真——也就是驱动走了 managed buffer 那套（snd_pcm_set_managed_buffer*）。此时中间层替你分配 DMA 页面，返回值 > 0 表示缓冲区被重分配，写进 runtime->buffer_changed。版本提示：该函数在 v6.3 为 sound/core/pcm_memory.c 中的实现，签名就是「substream + 字节数」两项；素材未贴其函数体，此处标注为「素材未给出实现，语义按注释与调用点推断」。
  6. substream->ops->hw_params(substream, params)。这一步才真正把参数下发到硬件，ASoC 下是 soc_pcm_hw_params。
  7. 把 params 落到 runtime 的对应字段，算 sample_bits/frame_bits/byte_align/min_align。
  8. 填默认软件参数：avail_min = period_size、start_threshold = 1、stop_threshold = buffer_size、静音阈值 0、boundary 是 buffer_size 反复乘 2 直到接近 LONG_MAX 为止的 2 的幂。应用之后可以用 SW_PARAMS 改这些默认值。
  9. 清空 DMA 区，避免内核信息泄漏。有 copy_user 回调的路径不清（数据由那个回调负责）。
  10. snd_pcm_timer_resolution_change 调整定时器精度，状态置 SETUP。
  11. 按 period 折算成微秒，注册 CPU latency QoS 请求，压制 CPU 进深睡眠导致的欠载。
  12. 出错路径：状态退回 OPEN，调 ops->hw_free，managed buffer 则 snd_pcm_lib_free_pages。

boundary 那段循环值得单独看：

c
runtime->boundary = runtime->buffer_size;
while (runtime->boundary * 2 <= LONG_MAX - runtime->buffer_size)
        runtime->boundary *= 2;

它保证 boundary 是 buffer_size 的整数倍、2 的幂、且 boundary + buffer_size 不溢出。用户态看到的指针（hw_ptr/appl_ptr）就在 [0, boundary) 里回绕，所以 /proc 里 boundary 是个天文数字是正常的。素材里的实测值 6207086186423386112 就是这么来的。

约束怎么设 #

约束的入口在驱动的 open 回调里，必须落在 snd_pcm_hw_constraints_init 之后、snd_pcm_hw_constraints_complete 之前——snd_pcm_open_substream 的调用顺序已经保证了这一点。常用 API：snd_pcm_hw_constraint_mask64（位图限定格式/采样率）、snd_pcm_hw_constraint_minmax（区间）、snd_pcm_hw_constraint_list（枚举列表）、snd_pcm_hw_constraint_step（步进）、snd_pcm_hw_constraint_integer（限定整数）、snd_pcm_hw_constraint_ratnums/ratdens（速率分子分母）。参数间有联动关系时用 snd_pcm_hw_rule_add 加自定义规则。

ASoC 的 hw_params #

soc_pcm_hw_params（sound/soc/soc-pcm.c）先查对称性，再调 dai_link 钩子，然后先 codec dai 后 cpu dai：

                               struct snd_pcm_substream *substream,
                               struct snd_pcm_hw_params *params)
{

        ret = snd_soc_link_hw_params(substream, params); // rtd->dai_link->ops->hw_params(...)
        for_each_rtd_codec_dais(rtd, i, codec_dai) { // 遍历 codec dai
                struct snd_pcm_hw_params codec_params;
                unsigned int tdm_mask = snd_soc_dai_tdm_mask_get(codec_dai, substream->stream);
                if (!snd_soc_dai_stream_valid(codec_dai, substream->stream))
                        continue;   // 该 codec 不支持当前方向，跳过
                codec_params = *params;     // 每个 codec 拿副本
                if (tdm_mask)
                        soc_pcm_codec_params_fixup(&codec_params, tdm_mask);
                ret = snd_soc_dai_hw_params(codec_dai, substream, &codec_params);
                soc_pcm_set_dai_params(codec_dai, &codec_params);
                snd_soc_dapm_update_dai(substream, &codec_params, codec_dai);
        }
        for_each_rtd_cpu_dais(rtd, i, cpu_dai) {    // cpu dai
                if (!snd_soc_dai_stream_valid(cpu_dai, substream->stream))
                        continue;

                soc_pcm_set_dai_params(cpu_dai, params);
                snd_soc_dapm_update_dai(substream, params, cpu_dai);
        }
        ret = snd_soc_pcm_component_hw_params(substream, params);
        return soc_pcm_ret(rtd, ret);

        int ret;

        snd_soc_dpcm_mutex_unlock(rtd);

要点：

  • soc_pcm_params_symmetry 检查参数对称性——同一条链路上的多个流如果已经跑起来，新流的参数必须与之匹配（采样率、格式、声道数）。这是多路并发场景下 -EBUSY/-EINVAL 的常见来源。
  • snd_soc_link_hw_params 调 dai_link 的 ops->hw_params，属于 Machine 层钩子。
  • 先 codec dai 后 cpu dai。每个 codec dai 拿到的是 params 的副本，因为 TDM slot mask 会要求按 codec 微调 codec_params。
  • snd_soc_dai_stream_valid 过滤：某 codec 不支持当前方向就跳过，不给它配参数。
  • snd_soc_dapm_update_dai 把参数喂给 DAPM，让它按新参数重算路径电源——这是 DAPM 与 PCM 的接缝。

十、PCM 的数据传输 #

参数配好后数据怎么走，有两条路径：write/read 系（内核拷数据）和 mmap 系（应用直接写 DMA 区）。

写接口在 snd_pcm_f_ops[0] 里：.write = snd_pcm_write、.write_iter = snd_pcm_writev、.mmap = snd_pcm_mmap。读接口在 snd_pcm_f_ops[1]：.read = snd_pcm_read、.read_iter = snd_pcm_readv。

write 路径的内核侧流程（sound/core/pcm_lib.c）：

text
snd_pcm_write
    snd_pcm_lib_write
        snd_pcm_lib_write1
            snd_pcm_start_lock_irq (若未启动且 start_threshold 满足)
            snd_pcm_lib_write_transfer
                substream->ops->copy / copy_user

写之前要先等空间：snd_pcm_lib_write1 会检查 avail 是否够一帧，不够就 wait_for_avail 挂到 substream 的等待队列上，直到 hw_ptr 前进（中断里 snd_pcm_period_elapsed → snd_pcm_update_hw_ptr → wake_up）或者超时或者被信号打断。这就是 write 阻塞的来源。

mmap 路径：应用 mmap 拿到 runtime->dma_area 的用户态映射，自己往环形缓冲区写数据，再负责通知内核 appl_ptr 前进（SNDRV_PCM_IOCTL_SYNC_PTR）。alsa-lib 默认走这条。两条路径的分叉点是 substream->ops->copy_user 有没有实现，以及 runtime->hw.info 里有没有 SNDRV_PCM_INFO_MMAP。

trigger 是硬件真正开动的点。SNDRV_PCM_IOCTL_START → snd_pcm_start_lock_irq → snd_pcm_action 系列 → snd_pcm_do_start → ops->trigger(substream, SNDRV_PCM_TRIGGER_START)。ASoC 下 soc_pcm_trigger 遍历整条链路的 dai 逐个触发，同时处理 SNDRV_PCM_TRIGGER_PAUSE_PUSH/RESUME 对应 ASoC 的 SND_SOC_DAPM_STREAM_PAUSED/RUNNING 事件。

pointer 回调决定 hw_ptr。snd_pcm_update_hw_ptr 调 substream->ops->pointer(substream) 拿到当前硬件位置，与上次比较算出走了多少帧，更新 hw_ptr、判断是否越过 stop_threshold（xrun）、是否需要唤醒写者。这个回调必须单调返回或正确回绕，返回乱值会直接导致 xrun 统计失真。

delay 由 /proc/asound/.../status 里的 delay 字段体现，等于 appl_ptr - hw_ptr（回绕后），表示还有多少帧没被硬件消化。

xrun 排查的入口是 CONFIG_SND_PCM_XRUN_DEBUG。开了这个宏，/proc/asound/cardX/pcmYp/xrun_debug 可写，把 xrun_debug 设为 1 打印详细信息，设为 2 连调用栈一起打（结构体注释：0 = disabled, 1 = verbose, 2 = stacktrace）。

版本提示：snd_pcm_lib_write/snd_pcm_lib_write1 的内部结构在 5.x 到 6.x 之间有过拆分调整（部分版本里有 snd_pcm_lib_writev 与 snd_pcm_lib_write 的双入口）。上面的调用链是按通用形态整理的，逐行核对请对 v6.3 sound/core/pcm_lib.c。

DMA 缓冲的分配有两种模式，分清楚就不会在查看 proc 时困惑：

模式 触发方式 managed_buffer_alloc /proc/.../prealloc
managed buffer snd_pcm_set_managed_buffer* true 存在，可读写
prealloc + 驱动自管 snd_pcm_lib_preallocate_pages_for_all false 存在（由 prealloc 机制创建）

十一、Control 设备：kcontrol 与控件 #

Control 是音频驱动里用来表示用户可操作音频参数的抽象：音量、混音（Mixer）、开关（Mux）等。它给用户一个统一入口去调这些参数。

ALSA CORE 已实现 Control 中间层，API 全在 include/sound/control.h。要为 Codec 写控件，把这个头文件包含进来。

术语先分清，混了会读不懂源码：Control 设备（controlC0）指那个字符设备；controls / control / kcontrol 指控件，是声卡音量、混音这类可调项，可以理解成 switch。

创建过程与 PCM 基本相同，差别在于不用你自己调：snd_ctl_create 已经在 snd_card_new 里被调过了，建声卡就自动带 Control 设备。它只做两件事（sound/core/control.c）：

c
int snd_ctl_create(struct snd_card *card)
{
        static struct snd_device_ops ops = {     // Control 设备操作集
                .dev_free = snd_ctl_dev_free,
                .dev_register = snd_ctl_dev_register,
                .dev_disconnect = snd_ctl_dev_disconnect,
        };
        if (snd_BUG_ON(card->number < 0 || card->number >= SNDRV_CARDS)) return -ENXIO;
        snd_device_initialize(&card->ctl_dev, card);               // class=sound_class，parent=card->card_dev
        dev_set_name(&card->ctl_dev, "controlC%d", card->number);  // 名字 controlC%d
        err = snd_device_new(card, SNDRV_DEV_CONTROL, card, &ops);  // 挂进 card->devices
}
  • snd_device_initialize(&card->ctl_dev, card) 初始化控制设备，parent 设为 card->card_dev，class 设为 sound_class，release 设为 default_release；
  • snd_device_new 分配 snd_device 挂进 devices 链表，device_data 直接就是 card 本身（Control 设备没有单独的数据结构）。

注册阶段走 snd_ctl_dev_register，建出 /dev/snd/controlC%d：

c
static int snd_ctl_dev_register(struct snd_device *device)
{
        struct snd_card *card = device->device_data;
        return snd_register_device(SNDRV_DEVICE_TYPE_CONTROL, card, -1,       // 注册 Control 设备
                                   &snd_ctl_f_ops, card, &card->ctl_dev);
}

dev 参数传 -1，control 没有设备索引概念。

dev_disconnect 和 dev_free 的分工：前者唤醒所有等事件的进程并送 SIGIO（wake_up(&ctl->change_sleep) + kill_fasync(&ctl->fasync, SIGIO, POLL_ERR)），再 snd_unregister_device；后者在 down_write(&card->controls_rwsem) 保护下把 card->controls 链表逐个 snd_ctl_remove 清空，最后 put_device(&card->ctl_dev)。卸载声卡时不会留下悬空控件。

打开 Control 设备 #

snd_ctl_f_ops 里的 open 是 snd_ctl_open。它每次生成一个 snd_ctl_file 挂进 card->ctl_files：先 snd_lookup_minor_data 取声卡，再 snd_card_file_add 加入 files_list，try_module_get 增模块引用，kzalloc 一个 snd_ctl_file，初始化 events 链表、change_sleep 等待队列、read_lock 自旋锁，把 preferred_subdevice[] 全填 -1，记下 pid，最后在 ctl_files_rwlock 写锁保护下 list_add_tail(&ctl->list, &card->ctl_files)。

ctl->events 是该文件专属的事件队列，change_sleep 是等待队列。控件值变化的通知按文件分发，这样 amixer 之类工具可以 poll/read 拿到事件。

snd_kcontrol_new 与 snd_kcontrol #

控件由两个结构体描述。snd_kcontrol_new 是模板，snd_kcontrol 才是真正实例化的控件。模板在声卡初始化阶段通过 snd_soc_add_component_controls 批量注册，之后 amixer/alsamixer 就能看到并设定它们。

创建分两步：定义 snd_kcontrol_new 数组，然后调 snd_soc_add_component_controls 按数组创建并添加多个 kcontrol 到 card->controls 链表。

模板结构（include/sound/control.h）：

        unsigned int count;             /* count of same elements */

                snd_kcontrol_tlv_rw_t *c;

access 访问类型，每个 bit 一种，可用「或」组合
count 同名元素个数，立体声音量控件为 2
info / get / put 填描述、读值、写值的三个回调
tlv 控件元数据
private_value 语义随控件类型变，普通控件里常放寄存器地址与位偏移

名字按「源–方向–功能」三段拼：源是输入端（Master、PCM、CD、Line、I2S、Headphone、Speaker、Mic 等），方向是 Playback、Capture、Bypass、Bypass Capture（省略表示双向），功能是 Switch、Volume、Route 等。特例如 Tone Control - Switch、Tone Control - Bass 已不推荐使用。完整规范见官方 Standard ALSA Control Names 文档。

十二、kcontrol 的类型与访问 #

access 位 #

access 是位掩码，默认 SNDRV_CTL_ELEM_ACCESS_READWRITE。字段为 0（.access == 0）也按 READWRITE 处理——这条规则在 snd_ctl_new1 里落实。

access 含义 对回调的要求
READWRITE / 0 可读可写 info + get + put
READ 只读 info + get，不用 put
WRITE 只写 info + put，不用 get
VOLATILE 值会无通知地变化（比如电平表） 应用必须定时查询
TLV_READ / TLV_WRITE / TLV_COMMAND 支持 TLV 读写与命令 配合 tlv 字段
INACTIVE / SKIP_CHECK 当前不可用 / 跳过一致性检查 —

info 回调填出的 type 决定值语义：

类型 值域 info 填充要点
BOOLEAN 0/1 count + value.integer.min/max
INTEGER 整数区间 同上，用 min/max 界定
ENUMERATED 枚举项 value.enumerated.items + name 字符串
BYTES 字节数组 需填 size
IEC958 数字接口状态位 专用结构
INTEGER64 64 位整数 value.integer64

单元素 boolean 控件的 info 回调：

c
int snd_ctl_boolean_mono_info(struct snd_kcontrol *kcontrol,
                              struct snd_ctl_elem_info *uinfo)
{
        uinfo->type = SNDRV_CTL_ELEM_TYPE_BOOLEAN;
        uinfo->count = 1;
        uinfo->value.integer.min = 0;
        uinfo->value.integer.max = 1;
        return 0;
}

count 是元素单元数，立体声音量左右两个声道就是 2。value 是 union，内容依赖 type；boolean 与 integer 共用同一套字段。ENUMERATED 特殊，要填字符串和索引：

c
int snd_ctl_enum_info(struct snd_ctl_elem_info *info, unsigned int channels,
                      unsigned int items, const char *const names[])
{
        info->type = SNDRV_CTL_ELEM_TYPE_ENUMERATED;
        info->count = channels;
        info->value.enumerated.items = items;
        if (!items) return 0;
        if (info->value.enumerated.item >= items)
                info->value.enumerated.item = items - 1;
        WARN(strlen(names[info->value.enumerated.item]) >= sizeof(info->value.enumerated.name),
             "ALSA: too long item name '%s'\n",
             names[info->value.enumerated.item]);
        strscpy(info->value.enumerated.name,
                names[info->value.enumerated.item],
                sizeof(info->value.enumerated.name));
        return 0;
}

ALSA 已备好一批通用 info 回调：snd_ctl_boolean_mono_info、snd_ctl_boolean_stereo_info、snd_ctl_enum_info 等。

get / put #

get 读控件当前值回填给用户空间，put 把应用给的值写进控件。很多驱动把寄存器地址、bit-shift、bit-mask 塞进 private_value（reg | (shift << 16) | (mask << 24)），回调再拆出来用：

c
static int snd_myctl_get(struct snd_kcontrol *kcontrol,
    struct snd_ctl_elem_value *ucontrol)
{
    struct mychip *chip = snd_kcontrol_chip(kcontrol);
    ucontrol->value.integer.value[0] = get_some_value(chip);
    return 0;
}
static int snd_myctl_put(struct snd_kcontrol *kcontrol,
    struct snd_ctl_elem_value *ucontrol)
{
    struct mychip *chip = snd_kcontrol_chip(kcontrol);
    int changed = 0;
    if (chip->current_value != ucontrol->value.integer.value[0]) {
        change_current_value(chip, ucontrol->value.integer.value[0]);
        changed = 1;
    }
    return changed;
}
/* private_value 的拆法 */
int reg = kcontrol->private_value & 0xff;
int shift = (kcontrol->private_value >> 16) & 0xff;
int mask = (kcontrol->private_value >> 24) & 0xff;

count > 1 时 get 要把多个元素值都填上。put 返回值有硬约定：值变了返回 1，没变返回 0，出错返回负错误码。返回 1 会触发 SNDRV_CTL_EVENT_MASK_VALUE 通知，让其他进程知道有变化。这里返回错了，amixer 调完音量会以为失败或者上层收不到通知。

ASoC 的控件宏 #

ASoC 层备了大量宏（include/sound/soc.h），把上面那套手工活包起来。最基础的 SOC_SINGLE：

c
#define SOC_SINGLE(xname, reg, shift, max, invert) \
{       .iface = SNDRV_CTL_ELEM_IFACE_MIXER, .name = xname, \
        .info = snd_soc_info_volsw, .get = snd_soc_get_volsw,\
        .put = snd_soc_put_volsw, \
        .private_value = SOC_SINGLE_VALUE(reg, shift, max, invert, 0) }

参数：xname 控件名、reg 寄存器地址、shift 位偏移、max 可设最大值、invert 是否逻辑取反。

private_value 由 SOC_SINGLE_VALUE 生成，它转调 SOC_DOUBLE_VALUE，最终是「对匿名 soc_mixer_control 取地址」：

c
#define SOC_SINGLE_VALUE(xreg, xshift, xmax, xinvert, xautodisable) \
        SOC_DOUBLE_VALUE(xreg, xshift, xshift, xmax, xinvert, xautodisable)
#define SOC_DOUBLE_VALUE(xreg, shift_left, shift_right, xmax, xinvert, xautodisable) \
        ((unsigned long)&(struct soc_mixer_control) \
        {.reg = xreg, .rreg = xreg, .shift = shift_left, \
        .rshift = shift_right, .max = xmax, \
        .invert = xinvert, .autodisable = xautodisable})

SOC_SINGLE 等于左右 shift 相同的 SOC_DOUBLE。真正描述控件特征的是 soc_mixer_control：

c
struct soc_mixer_control {
        int min, max, platform_max;
        int reg, rreg;
        unsigned int shift, rshift;
        unsigned int sign_bit;
        unsigned int invert:1;
        unsigned int autodisable:1;
#ifdef CONFIG_SND_SOC_TOPOLOGY
        struct snd_soc_dobj dobj;
#endif
};

它确定寄存器地址、位移、最大值、是否取反，get/put 靠它访问寄存器。snd_soc_get_volsw（sound/soc/soc-ops.c）从 private_value 取出 soc_mixer_control，按 mask = (1 << fls(max)) - 1 算掩码，snd_soc_read_signed 读寄存器，减 min、必要时按 invert 取反，写进 ucontrol->value.integer.value[0]；snd_soc_volsw_is_stereo(mc) 为真时再读第二路填 value[1]。

常用宏：

宏 用途
SOC_SINGLE 单控制量（开关、单值）
SOC_SINGLE_TLV 带 TLV 的单值，用于音量、EQ
SOC_DOUBLE 一个寄存器里控两个相似变量，典型左右声道
SOC_DOUBLE_R 左右声道寄存器不同，要传两个寄存器地址
SOC_DOUBLE_TLV / SOC_DOUBLE_R_TLV 上面两者的 TLV 版本
SOC_ENUM Mux 选择控件，配合 soc_enum
SOC_VALUE_ENUM_SINGLE / SOC_VALUE_ENUM_DOUBLE 带 values 字段的 soc_enum
SOC_*_EXT 系列 自己实现 get/put 时用

SOC_SINGLE_TLV 与 SOC_SINGLE 的唯一差别是多一个 tlv_array 赋给 tlv.p，并给 access 加上 SNDRV_CTL_ELEM_ACCESS_TLV_READ。用户空间通过 SNDRV_CTL_IOCTL_TLV_READ/TLV_WRITE/TLV_COMMAND 访问它。TLV 数组描述「寄存器设定值」与「实际物理意义」的映射，最常用的是音量档位到 dB 的映射：

c
static const DECLARE_TLV_DB_SCALE(mixin_boost_tlv, 0, 900, 0);
static const struct snd_kcontrol_new wm1811_snd_controls[] = {
SOC_SINGLE_TLV("MIXINL IN1LP Boost Volume", WM8994_INPUT_MIXER_1, 7, 1, 0,
               mixin_boost_tlv),
SOC_SINGLE_TLV("MIXINL IN1RP Boost Volume", WM8994_INPUT_MIXER_1, 8, 1, 0,
               mixin_boost_tlv),
};

DECLARE_TLV_DB_SCALE(name, min, step, mute) 里 min=0 表示寄存器最小值对应 0 dB，step=900 表示每增加一个单位值涨 0.01 dB × 900 = 9 dB。所以两个 boost 控件（同一寄存器第 7、8 位，max=1）只有 0 和 1 两档，对应 0 dB 和 9 dB。

Mixer 控件本质是多个简单控件的组合，每个输入端一个开关：

c
static const struct snd_kcontrol_new wm8960_lin_boost[] = {
    SOC_SINGLE("LINPUT2 Switch", WM8960_LINPATH, 6, 1, 0),
    SOC_SINGLE("LINPUT3 Switch", WM8960_LINPATH, 7, 1, 0),
    SOC_SINGLE("LINPUT1 Switch", WM8960_LINPATH, 8, 1, 0),
};

三个输入端的开关分别用 WM8960_LINPATH 的第 6、7、8 位。手机通话时同时要听音乐，就把两路混起来送 Speaker。

Mux 与 Mixer 的区别在于「多选一」：多个输入端同时只有一个被选中。它对应的寄存器可以设一段连续数值，每个值对应一路输入打开。ASoC 用 soc_enum 描述：

c
struct soc_enum {
        int reg;
        unsigned char shift_l;
        unsigned char shift_r;
        unsigned int items;
        unsigned int mask;
        const char * const *texts;
        const unsigned int *values;
        unsigned int autodisable:1;
#ifdef CONFIG_SND_SOC_TOPOLOGY
        struct snd_soc_dobj dobj;
#endif
};

reg/shift_l/shift_r 描述左右声道寄存器与位移，texts 是每路输入的名字数组，values 是可选寄存器值数组（连续值可省略）。定义一个 Mux 分三步：先写名字数组 drc_path_text[] = {"ADC", "DAC"}，再用 SOC_ENUM_SINGLE(WM8993_DRC_CONTROL_1, 14, 2, drc_path_text) 生成 soc_enum，最后在数组里放 SOC_ENUM("DRC Path", drc_path)。

c
#define SOC_ENUM_DOUBLE(xreg, xshift_l, xshift_r, xmax, xtexts) \
{       .reg = xreg, .shift_l = xshift_l, .shift_r = xshift_r, \
        .max = xmax, .texts = xtexts, \
        .mask = xmax ? roundup_pow_of_two(xmax) - 1 : 0}
#define SOC_ENUM_SINGLE(xreg, xshift, xmax, xtexts) \
        SOC_ENUM_DOUBLE(xreg, xshift, xshift, xmax, xtexts)
#define SOC_ENUM(xname, xenum) \
{       .iface = SNDRV_CTL_ELEM_IFACE_MIXER, .name = xname,\
        .info = snd_soc_info_enum_double, \
        .get = snd_soc_get_enum_double, .put = snd_soc_put_enum_double, \
        .private_value = (unsigned long)&xenum }

snd_soc_get_enum_double 读寄存器后 (reg_val >> e->shift_l) & e->mask 得值，snd_soc_enum_val_to_item 转成项索引写 value.enumerated.item[0]；shift_l != shift_r 时再处理 item[1]。snd_soc_info_enum_double 直接把 texts/items 转给 snd_ctl_enum_info，声道数按 shift_l == shift_r ? 1 : 2。

从模板到实例 #

snd_soc_cnew（sound/soc/soc-core.c）按模板造控件：拷一份模板、index 清零、按需加前缀改名字，然后交给 snd_ctl_new1。

c
struct snd_kcontrol *snd_soc_cnew(const struct snd_kcontrol_new *_template,
                                  void *data, const char *long_name,
                                  const char *prefix)
{
        memcpy(&template, _template, sizeof(template));
        template.index = 0;
        if (!long_name)
                long_name = template.name;
        if (prefix)
                name = kasprintf(GFP_KERNEL, "%s %s", prefix, long_name);
        kcontrol = snd_ctl_new1(&template, data);  // 重点
        kfree(name);
        return kcontrol;
}

snd_ctl_new1 分配 snd_kcontrol 并把模板值复制过去。两个默认规则在这里落实：count == 0 当 1 处理，access == 0 当 SNDRV_CTL_ELEM_ACCESS_READWRITE 处理，并与一组合法位做与（READWRITE | VOLATILE | INACTIVE | TLV_READWRITE | TLV_COMMAND | TLV_CALLBACK | LED_MASK | SKIP_CHECK）。之后 snd_ctl_new(&kctl, count, access, NULL) 分配，再逐项复制 id.iface/id.device/id.subdevice/id.name/id.index/info/get/put/tlv.p/private_value/private_data。

numid 不在这里定，注释写明「The 'numid' member is decided when calling snd_ctl_add()」。snd_ctl_new 按 count 分配 kcontrol 及其 vd[] 数组（struct_size(*kctl, vd, count)），每个元素带 access 和 owner。

控件建好后调 snd_ctl_add 挂进 card->controls。它是 snd_ctl_add_replace(card, kcontrol, CTL_ADD_EXCLUSIVE) 的包装，后者在 down_write(&card->controls_rwsem) 保护下转给 __snd_ctl_add_replace，失败则 snd_ctl_free_one 回收。核心逻辑：

c
        old = snd_ctl_find_id(card, &id);  // 在 card->controls 里找匹配项
        if (old && mode == CTL_ADD_EXCLUSIVE) {
                dev_err(card->dev, "control %i:%i:%i:%s:%i is already present\n",
                        id.iface, id.device, id.subdevice, id.name, id.index);
                return -EBUSY;      // 重复控件直接失败
        }
        if (old)
                snd_ctl_remove(card, old);   // CTL_REPLACE 才走到这
        list_add_tail(&kcontrol->list, &card->controls);
        card->controls_count += kcontrol->count;
        kcontrol->id.numid = card->last_numid + 1;  // 分配编号
        card->last_numid += kcontrol->count;
        add_hash_entries(card, kcontrol);   // 建哈希索引加速查找
        for (idx = 0; idx < kcontrol->count; idx++)
                snd_ctl_notify_one(card, SNDRV_CTL_EVENT_MASK_ADD, kcontrol, idx);

注意 numid 是按 count 跳的，一个 count=2 的控件占两个 numid。

ASoC 又包了一层，snd_soc_add_component_controls（sound/soc/soc-core.c）从 component 拿声卡再转 snd_soc_add_controls：

c
int snd_soc_add_component_controls(struct snd_soc_component *component,
        const struct snd_kcontrol_new *controls, unsigned int num_controls)
{
        struct snd_card *card = component->card->snd_card;
        return snd_soc_add_controls(card, component->dev, controls,
                        num_controls, component->name_prefix, component);
}

snd_soc_add_controls 就是个循环，对每个模板调 snd_soc_cnew + snd_ctl_add：

c
        for (i = 0; i < num_controls; i++) {  // 注册每一个 snd_kcontrol_new
                const struct snd_kcontrol_new *control = &controls[i];
                int err = snd_ctl_add(card, snd_soc_cnew(control, data, // 内部调 snd_soc_cnew
                                                         control->name, prefix));
                if (err < 0) {
                        dev_err(dev, "ASoC: Failed to add %s: %d\n",

                }
        }

prefix 就是 component->name_prefix，最终成为控件名前缀——多 Codec 时靠它避免重名。

十三、Jack 设备：插拔检测 #

Jack 是插孔——耳机、麦克风的插座。Jack 设备的核心职责就是检测这些设备的插入和拔出。ALSA CORE 已实现 jack 中间层，API 在 include/sound/jack.h，实现在 sound/core/jack.c。

耳机分两类：带麦克风的 Headset，不带麦克风的 Headphone。Headset 的插入检测靠带机械结构的插座完成：检测引脚接 SoC 的 GPIO，插头金属碰到引脚，电平变化触发中断，在中断处理里读 GPIO 就能判断插入还是拔出。

snd_jack #

c
struct snd_jack {
        struct list_head kctl_list;
        const char *id;
#ifdef CONFIG_SND_JACK_INPUT_DEV
        struct mutex input_dev_lock;
        int registered;
        int type;
        char name[100];
        unsigned int key[6];   /* Keep in sync with definitions above */
#endif /* CONFIG_SND_JACK_INPUT_DEV */

字段 含义
kctl_list 该 jack 下的 kcontrol 链表，元素是 snd_jack_kctl
card 所属声卡
id jack 唯一标识
input_dev 输入设备指针，用来上报插拔事件
input_dev_lock 输入设备锁

后面六项（input_dev、input_dev_lock、registered、type、name、key）都在 CONFIG_SND_JACK_INPUT_DEV 里，这个宏默认打开。

能上报的类型是位掩码：

c
enum snd_jack_types {
        SND_JACK_HEADPHONE      = 0x0001,  // 上报 EV_SW，编码 0x02
        SND_JACK_MICROPHONE     = 0x0002,  // 上报 EV_SW，编码 0x04
        SND_JACK_HEADSET        = SND_JACK_HEADPHONE | SND_JACK_MICROPHONE,
        SND_JACK_LINEOUT        = 0x0004,  // 上报 EV_SW，编码 0x06
        SND_JACK_MECHANICAL     = 0x0008,  /* If detected separately */ EV_SW 0x07
        SND_JACK_VIDEOOUT       = 0x0010,  // 上报 EV_SW，编码 0x80
        SND_JACK_AVOUT          = SND_JACK_LINEOUT | SND_JACK_VIDEOOUT,
        SND_JACK_LINEIN         = 0x0020,  // 上报 EV_SW，编码 0x0d
        /* Kept separate from switches to facilitate implementation */
        SND_JACK_BTN_0          = 0x4000,   // 上报 EV_KEY，编码 0x100
        SND_JACK_BTN_1          = 0x2000,   // 上报 EV_KEY，编码 0x101
        SND_JACK_BTN_2          = 0x1000,   // 上报 EV_KEY，编码 0x102
        SND_JACK_BTN_3          = 0x0800,   // 上报 EV_KEY，编码 0x103
        SND_JACK_BTN_4          = 0x0400,   // 上报 EV_KEY，编码 0x104
        SND_JACK_BTN_5          = 0x0200,   // 上报 EV_KEY，编码 0x105
};

勘误：素材原注释里 SND_JACK_LINEOUT = 0x0004 写的是「事件编码为 0x04」，与 MICROPHONE 重复；SND_JACK_VIDEOOUT 写的是 0x08。实际编码以 jack_switch_types[] 数组为准：LINEOUT 是 0x06，MECHANICAL 是 0x07，VIDEOOUT 是 0x80。上面已按数组修正。

snd_jack_kctl 描述 jack 里的 kcontrol（sound/core/jack.c）：

c
struct snd_jack_kctl {
        struct list_head list;  /* list of controls belong to the same jack */
        unsigned int mask_bits; /* only masked status bits are reported via kctl */
        struct snd_jack *jack;  /* pointer to struct snd_jack */
        bool sw_inject_enable;  /* allow to inject plug event via debugfs */
#ifdef CONFIG_SND_JACK_INJECTION_DEBUG
        struct dentry *jack_debugfs_root; /* jack_kctl debugfs root */
#endif
};

kctl 关联 snd_kcontrol，list 挂进 jack->kctl_list，mask_bits 是该控件能上报的类型（设成 SND_JACK_HEADPHONE 时，耳机插拔触发 HP_DET 引脚中断，处理程序读电平后上报对应的 EV_SW 事件，编码 0x02），jack 是反向指针，sw_inject_enable 允许 debugfs 注入插头事件。

结构关系抓三点：jack 是挂在 snd_card->devices 下的一个 snd_device；kctl_list 保存所有 jack kcontrol，每个都关联一个 snd_kcontrol；input_dev 是 input 设备，负责上报插拔事件。

snd_jack_new #

接六个参数：card、id（唯一标识）、type（enum snd_jack_types 位掩码）、jjack（返回 snd_jack）、initial_kctl（为真则建一个 jack kcontrol 加进 kctl_list）、phantom_jack（虚拟 jack，不建输入设备）：

c
int snd_jack_new(struct snd_card *card, const char *id, int type,
                 struct snd_jack **jjack, bool initial_kctl, bool phantom_jack)
{
        static const struct snd_device_ops ops = {     // jack 设备操作集
                .dev_free = snd_jack_dev_free,
                .dev_register = snd_jack_dev_register,       // CONFIG_SND_JACK_INPUT_DEV 默认开
                .dev_disconnect = snd_jack_dev_disconnect,
        };
        if (initial_kctl)  // 创建一个名为 id 的 jack kcontrol，mask 设为 type
                jack_kctl = snd_jack_kctl_new(card, id, type);
        jack = kzalloc(sizeof(struct snd_jack), GFP_KERNEL);
        jack->id = kstrdup(id, GFP_KERNEL);
        mutex_init(&jack->input_dev_lock);
        if (!phantom_jack) {  // false 时创建输入设备
                jack->input_dev = input_allocate_device();
                jack->input_dev->phys = "ALSA";
                jack->type = type;
                for (i = 0; i < SND_JACK_SWITCH_TYPES; i++) // 6
                        if (type & (1 << i))
                                input_set_capability(jack->input_dev, EV_SW,
                                                     jack_switch_types[i]);
        }
        err = snd_device_new(card, SNDRV_DEV_JACK, jack, &ops);  // device_data = jack
        jack->card = card;
        INIT_LIST_HEAD(&jack->kctl_list);
        if (initial_kctl)  // 加进 kctl_list
                snd_jack_kctl_add(jack, jack_kctl);
        *jjack = jack;
        return 0;
}

        SW_MICROPHONE_INSERT,    // 0x04

        SW_LINEIN_INSERT,        // 0x0d
};

循环用 type & (1 << i) 逐位判断：SND_JACK_HEADPHONE（bit0）→ SW_HEADPHONE_INSERT，SND_JACK_MICROPHONE（bit1）→ SW_MICROPHONE_INSERT，SND_JACK_LINEOUT（bit2）→ SW_LINEOUT_INSERT，SND_JACK_MECHANICAL（bit3）→ SW_JACK_PHYSICAL_INSERT，SND_JACK_VIDEOOUT（bit4）→ SW_VIDEOOUT_INSERT，SND_JACK_LINEIN（bit5）→ SW_LINEIN_INSERT。这个数组是判定事件编码的唯一依据。

从 kcontrol 到 input 上报 #

四个函数的职责一句话说清：

函数 位置 干什么
snd_jack_kctl_new(card, name, mask) sound/core/jack.c 建 snd_kcontrol + snd_jack_kctl，mask_bits = mask，kctl->private_data 回指
snd_kctl_jack_new(name, card) sound/core/ctljack.c 按 jack_detect_kctl 模板建 kcontrol，填名字、分 index、private_value = 0
snd_jack_kctl_add(jack, jack_kctl) sound/core/jack.c jack_kctl->jack = jack，挂进 jack->kctl_list，加 debugfs 注入节点
snd_jack_add_new_kctl(jack, name, mask) sound/soc/jack.c 上面两者的包装，ASoC 用

模板长这样，注意 iface 是 CARD、access 是 READ：

c
static const struct snd_kcontrol_new jack_detect_kctl = {
        /* name is filled later */
        .iface = SNDRV_CTL_ELEM_IFACE_CARD,
        .access = SNDRV_CTL_ELEM_ACCESS_READ,
        .info = jack_detect_kctl_info,
        .get = jack_detect_kctl_get,
};

插孔状态由硬件决定，应用改不了，所以只读。private_value 被拿来存状态值，get 读它。

snd_jack_dev_register 在注册声卡时被调用：拼 jack 名为 <card->shortname> <id>，把同样的名字给 input_dev->name，父设备设为声卡，按 jack->type 逐个 input_set_capability(EV_KEY, ...) 注册按键能力（jack->key[i] = BTN_0 + i），最后 input_register_device，/sys/class/input 下出现 input%d。

snd_jack_report(jack, status) 是上报总口：

c
void snd_jack_report(struct snd_jack *jack, int status)
{
        jack->hw_status_cache = status;   // 缓存状态
        list_for_each_entry(jack_kctl, &jack->kctl_list, list) // 遍历 kctl_list
                if (jack_kctl->sw_inject_enable)   // 注入模式则不直接上报
                        mask_bits |= jack_kctl->mask_bits;
                else
                        snd_kctl_jack_report(jack->card, jack_kctl->kctl,
                                             status & jack_kctl->mask_bits);
        mutex_lock(&jack->input_dev_lock);
        for (i = 0; i < ARRAY_SIZE(jack->key); i++) {  // EV_KEY 路径
                int testbit = ((SND_JACK_BTN_0 >> i) & ~mask_bits);
                if (jack->type & testbit)
                        input_report_key(jack->input_dev, jack->key[i], status & testbit);
        }
        for (i = 0; i < ARRAY_SIZE(jack_switch_types); i++) {  // EV_SW 路径
                int testbit = ((1 << i) & ~mask_bits);
                if (jack->type & testbit)
                        input_report_switch(jack->input_dev, jack_switch_types[i],
                                            status & testbit);
        }
        input_sync(jack->input_dev);
        mutex_unlock(&jack->input_dev_lock);
}

先缓存状态，再遍历 kctl_list 更新每个 kcontrol；然后按 jack->key[] 报 EV_KEY、按 jack_switch_types[] 报 EV_SW，最后 input_sync。sw_inject_enable 为真的 kctl 不直接上报，把 mask_bits 攒起来交给 debugfs 注入路径。（CONFIG_SND_JACK_INPUT_DEV 的 #ifdef 已省略。）

snd_kctl_jack_report 只在状态真变了时才发通知：

c
void snd_kctl_jack_report(struct snd_card *card,
                          struct snd_kcontrol *kctl, bool status)
{
        if (kctl->private_value == status)  // 状态未变
                return;
        kctl->private_value = status;  // 更新状态
        snd_ctl_notify(card, SNDRV_CTL_EVENT_MASK_VALUE, &kctl->id);
}

snd_ctl_notify 第二参是事件掩码（SNDRV_CTL_EVENT_MASK_VALUE 表示值变化），第三参是控件元素 id 指针。通知会送到所有 open 了 controlCx 的进程的 ctl->events 队列。

整个 snd_jack_report 用了互斥锁，注释写明必须在可睡眠上下文调用。ASoC 的 gpio_handler 之所以把活丢给 schedule_delayed_work，原因就在这里。

GPIO 检测的完整套路 #

基于 input event 做耳机插拔检测，标准三步：snd_jack_new（或 ASoC 封装）建 jack；request_irq 申请插拔中断按边沿判断方向；按结果调 snd_soc_jack_report 上报。

ASoC 有现成封装 snd_soc_jack_add_gpios(jack, count, gpios)。Machine driver 注册时就这么填：

text
gpio.name        = "Headphone detection";
gpio.report      = SND_JACK_HEADPHONE;
gpio.desc        = desc;
gpio.debounce_time = 150;
snd_soc_jack_add_gpios(jack, 1, &gpio);

函数在 sound/soc/soc-jack.c，逐个 GPIO：取描述符（desc 已填直接用；否则 gpiod_dev 走 gpiod_get_index；否则老式 gpio 编号走 gpio_request_one）→ 挂 jack → request_any_context_irq(gpiod_to_irq(desc), gpio_handler, IRQF_TRIGGER_RISING | IRQF_TRIGGER_FALLING, name, &gpios[i]) → wake 为真则 irq_set_irq_wake(..., 1) → register_pm_notifier 防止睡眠期间漏状态 → schedule_delayed_work(&gpios[i].work, msecs_to_jiffies(debounce_time)) 做首次采样。

几个设计点：用 request_any_context_irq 而不是 request_irq，因为该 GPIO 会挂在睡眠型控制器（I2C 扩展 GPIO）上；双边沿触发，方向由工作函数里重新读电平判断；除中断外还调 gpiod_export(desc, false) 把 GPIO 值暴露到 sysfs，现场可直接看引脚电平。

中断处理函数很短，只负责把活推迟；工作函数读电平并上报：

c
static irqreturn_t gpio_handler(int irq, void *data)
{
        struct snd_soc_jack_gpio *gpio = data;
        if (device_may_wakeup(gpio->jack->card->dev))
                pm_wakeup_event(gpio->jack->card->dev, gpio->debounce_time + 50);
        queue_delayed_work(system_power_efficient_wq, &gpio->work, // power efficient 队列
                              msecs_to_jiffies(gpio->debounce_time));
        return IRQ_HANDLED;
}
static void snd_soc_jack_gpio_detect(struct snd_soc_jack_gpio *gpio)
{
        int enable = gpiod_get_value_cansleep(gpio->desc);  // 读 GPIO
        int report;
        if (gpio->invert)
                enable = !enable;
        report = enable ? gpio->report : 0;   // 插入报类型，拔出报 0
        if (gpio->jack_status_check)
                report = gpio->jack_status_check(gpio->data);  // 自定义检测覆盖
        snd_soc_jack_report(gpio->jack, report, gpio->report);
}
static void gpio_work(struct work_struct *work)
{
        struct snd_soc_jack_gpio *gpio =
                container_of(work, struct snd_soc_jack_gpio, work.work);
        snd_soc_jack_gpio_detect(gpio);
}

queue_delayed_work 与 schedule_delayed_work 的差别只在队列：前者提交给指定的 system_power_efficient_wq，后者用缺省队列。插拔检测对延迟不敏感，放 power efficient 队列能让内核把活攒到 CPU 醒着时一起干。gpiod_get_value_cansleep 说明这里可以在睡眠上下文调，与 snd_jack_report 需要互斥锁的限制一致。

整条链：硬中断 → queue_delayed_work → 消抖 → 读电平 → snd_soc_jack_report → pin 上下电 + snd_jack_report → input 子系统。用户空间验证：

bash
evtest /dev/input/eventX     # 看 SW_HEADPHONE_INSERT / SW_MICROPHONE_INSERT
amixer -c 1 contents | grep -i jack

ASoC 侧的 snd_soc_jack #

snd_soc_jack（include/sound/soc-jack.h）是 ASoC 的外层包装：

c
struct snd_soc_jack {
        struct mutex mutex;
        struct list_head pins;
        int status;
        struct blocking_notifier_head notifier;
        struct list_head jack_zones;
};
  • mutex 保护结构体的并发访问；
  • jack 指向底层 snd_jack；
  • card 指向 ASoC 声卡；
  • pins 是 jack pin 链表，元素是 snd_soc_jack_pin；
  • status 是当前插拔状态；
  • notifier 是阻塞通知链头，状态变化时通知观察者；
  • jack_zones 是 jack 区域链表头。

snd_soc_jack_pin 描述插拔时要上下电的 widget：

c
struct snd_soc_jack_pin {
        struct list_head list;
        const char *pin;
        int mask;
        bool invert;
};

pin 是引脚名，实际就是 widget 名字——设置引脚状态时会到声卡 widgets 链表里找同名 widget 然后上下电；mask 是该 pin 可上报的类型；invert 默认 0 表示「状态命中→上电」，置位则反过来；list 挂进 jack->pins。

snd_soc_card_jack_new_pins（sound/soc/soc-card.c）建带 pin 的 jack：先 jack_new 建 snd_jack，num_pins 非 0 时再 snd_soc_jack_add_pins：

c
int snd_soc_card_jack_new_pins(struct snd_soc_card *card, const char *id,
                               int type, struct snd_soc_jack *jack,
                               struct snd_soc_jack_pin *pins,
                               unsigned int num_pins)
{
        ret = jack_new(card, id, type, jack, false);  // 创建 snd_jack，赋值 jack->jack
        if (ret) return soc_card_ret(card, ret);
        if (num_pins)
                ret = snd_soc_jack_add_pins(jack, num_pins, pins);
        return soc_card_ret(card, ret);
}

jack_new 只做初始化加一次 snd_jack_new，注意它传的 initial_kctl 是 false——ASoC 走「每个 pin 一个 kcontrol」的路子，不建那个总 kcontrol：

c
static int jack_new(struct snd_soc_card *card, const char *id, int type,
                    struct snd_soc_jack *jack, bool initial_kctl)
{
        mutex_init(&jack->mutex);
        jack->card = card;
        INIT_LIST_HEAD(&jack->pins);
        INIT_LIST_HEAD(&jack->jack_zones);
        BLOCKING_INIT_NOTIFIER_HEAD(&jack->notifier);
        return snd_jack_new(card->snd_card, id, type, &jack->jack, initial_kctl, false);
}

snd_soc_jack_add_pins（sound/soc/soc-jack.c）为每个 pin 建 kcontrol：先查 pin 非空、mask 非空（任一为空返回 -EINVAL），INIT_LIST_HEAD(&pins[i].list) 后 list_add 挂进 jack->pins，再 snd_jack_add_new_kctl(jack->jack, pins[i].pin, pins[i].mask)。循环完调一次 snd_soc_jack_report(jack, 0, 0)——mask 为 0 时只同步 pin 状态不动 status，刷一次初始状态（防止 jack 在 pin 关联之前就已经上报过）。

snd_soc_jack_report 是插拔上报的总入口：jack、status（当前检测到的插拔位掩码）、mask（本次要上报的位）。举例 status = 0b00100010、mask = 0b00000011，则只有第 0、1 位起作用。

c
void snd_soc_jack_report(struct snd_soc_jack *jack, int status, int mask)
{
        dapm = &jack->card->dapm;
        mutex_lock(&jack->mutex);
        jack->status &= ~mask;          // 清掉 mask 指向的旧位
        jack->status |= status & mask;  // 写入新状态
        list_for_each_entry(pin, &jack->pins, list) {     // 逐个 pin 做上下电
                int enable = pin->mask & jack->status;    // 1：上电 0：下电
                if (pin->invert)
                        enable = !enable;
                if (enable)
                        snd_soc_dapm_enable_pin(dapm, pin->pin);
                else
                        snd_soc_dapm_disable_pin(dapm, pin->pin);
                sync = 1;
        }
        /* 先发通知再同步 DAPM，方便用户更新 micbias */
        blocking_notifier_call_chain(&jack->notifier, jack->status, jack);
        if (sync)
                snd_soc_dapm_sync(dapm);  // 统一处理脏 widget 的上下电
        snd_jack_report(jack->jack, jack->status);  // 上报 EV_KEY/EV_SW
        mutex_unlock(&jack->mutex);
}

snd_soc_dapm_enable_pin/disable_pin 到声卡 widgets 链表里找同名 widget，连接状态变了就挂到 card->dapm_dirty 尾部并更新 widget.connected，之后 snd_soc_dapm_sync 真正操作寄存器控制上下电（没有电源寄存器就什么也不做）。细节在《DAPM：Widget、Route 与 Path》。

snd_soc_jack_gpio 描述检测用的 GPIO：

c
struct snd_soc_jack_gpio {
        unsigned int gpio;
        unsigned int idx;
        const char *name;
        int report;
        int invert;
        int debounce_time;
        bool wake;
        struct delayed_work work;
        struct notifier_block pm_notifier;
        void *data;
        int (*jack_status_check)(void *data);
};

gpio/idx/gpiod_dev/desc 是四套定位 GPIO 的方式：新版用 gpiod_dev + name + idx，老版用 gpio 编号，或者自己填好 desc。report 是检测到插入时上报什么；invert 默认高电平表示插入；debounce_time 是消抖毫秒数；wake 是否作唤醒源；work 处理消抖后的检测；pm_notifier 防止睡眠期间漏状态；jack_status_check 覆盖默认检测（比如读 ADC）。

版本提示：snd_soc_card_jack_new_pins 是较新的 API（v5.9 前后引入），更早的内核里是 snd_soc_card_jack_new（无 pins 参数，需另外调 snd_soc_jack_add_pins）。素材基于 6.3，此处按 _pins 版本。

用这份输出对照第九章的字段赋值，能一一对上：

  • period_size: 5513、buffer_size: 22052 就是 runtime->period_size/runtime->buffer_size；
  • avail_min: 5513 是 snd_pcm_hw_params 里那句 runtime->control->avail_min = runtime->period_size 的默认值；
  • start_threshold: 22052 说明这路流被应用改过——默认是 1，被改成 buffer_size，即「攒满一个 buffer 才启动」，免起播爆音的常见做法；
  • stop_threshold: 22052 等于 buffer_size，是默认值，代表写空整个 buffer 才判 xrun；
  • boundary 那个天文数字正是 while (runtime->boundary * 2 <= LONG_MAX - buffer_size) boundary *= 2; 的结果；
  • delay: 20524 + avail: 1528 = 22052 = buffer_size。一致性检查可以这么看：delay + avail 应该等于 buffer_size；
  • appl_ptr - hw_ptr = 2717933 - 2697409 = 20524，与 delay 相同；
  • state: RUNNING 说明流在跑，owner_pid: 5313 是占着它的进程。

单位是 KiB，512 就是 512 KiB；prealloc_max 那个 18014398509481983 表示不设上限。开机预分配 512 KiB×若干 substream 是嵌入式设备内存占用的隐形大头，内存紧张时可以改驱动的 prealloc 参数或在启动脚本里 echo 0 > prealloc。

text
root@rk3399:/# cat /proc/asound/pcm
00-00: ff8a0000.i2s-i2s-hifi i2s-hifi-0 : ff8a0000.i2s-i2s-hifi i2s-hifi-0 : playback 1 : capture 1

十五、调试手段与常见故障 #

一条固定的排查顺序 #

出问题按这个顺序走，不会绕远路：

  1. cat /proc/asound/cards —— 声卡有没有注册上？没有就是 Machine/Codec 探测失败，去查 I2C 通信和设备树；
  2. cat /proc/asound/devices 对照 ll /dev/snd —— 逻辑设备节点建了没？次设备号对不对？
  3. cat /proc/asound/pcm —— PCM 设备的 card-device 编号是多少？
  4. cat /proc/asound/cardX/pcmYp/sub0/info —— 这条流的方向、子设备数对不对？
  5. amixer -c X contents —— 控件全不全？音量/通路开关是不是处于静音或关断？
  6. cat .../sub0/hw_params —— 应用实际设下去的参数是什么？和 Codec 支持的对不对？
  7. cat .../sub0/status —— state 是什么？delay/avail 在动吗？hw_ptr 在前进吗？

第 6、7 步必须在播放中执行，否则文件是空的。

Control 相关的两个硬坑 #

重复控件直接失败。__snd_ctl_add_replace 在 id 已存在且模式是 CTL_ADD_EXCLUSIVE 时返回 -EBUSY 并打一行 control 2:0:0:Playback Volume:0 is already present。原因多半是两个 Codec 或两个 component 用了同名同 index 的控件。解法：给 snd_kcontrol_new 填不同的 index，或者给 component 设 name_prefix 让 snd_soc_cnew 自动加前缀。

控件名被截断。snd_ctl_new1 用 strscpy(kctl->id.name, ncontrol->name, sizeof(kctl->id.name)) 写入，长度不够时截断并打一条 ALSA: Control name '%s' truncated to '%s' 警告。amixer 看到的名字和你代码里写的就不是一个。dmesg 里有这条 warn 就要给控件改名。

Jack 相关的坑 #

  • 在硬中断里直接调 snd_soc_jack_report：它内部 mutex_lock，硬中断上下文里调会触发 sleeping function 警告。必须走工作队列。
  • invert 和硬件极性反了：症状是插拔状态整个反了，插入被当成拔出，DAPM 把输出关掉，于是「插上耳机反而没声音」。
  • mask 填 0：snd_soc_jack_add_pins 直接返回 -EINVAL，pin 加不进去。
  • report 与 mask 不匹配：snd_soc_jack_report(jack, report, gpio->report) 第三参是 mask，如果 pin 的 mask 里不含 report 的位，pin 永远不会被使能。

十六、易错点速查 #

# 易错点 正确做法
1 自己调 snd_ctl_create 建 Control 设备 不用调，snd_card_new 里已经调过，重复调会重复挂 snd_device
2 忘了 snd_card_register 就以为设备节点会出现 必须在初始化末尾调，之前 control 接口对外不可访问
3 以为 snd_device 的注册顺序按添加顺序 实际按 type 降序，SNDRV_DEV_CONTROL 最大所以最先注册
4 在 hw_params 里加 snd_pcm_hw_constraint_* 约束必须在 ops->open 里加，晚于 snd_pcm_hw_constraints_complete 就无效
5 hw_params 失败后直接重试同一套参数 失败会把 state 打回 OPEN 并调 hw_free，必须整套重新来过
6 以为 boundary 是 buffer 大小 它是 buffer_size 乘若干次 2 得到的回绕边界，比 buffer 大得多
7 put 回调返回值随意写 值变返回 1、没变返回 0、出错返回负数，返回错上层收不到通知
8 同一 component 里两个同名同 index 的控件 给不同 index 或用 name_prefix，否则 -EBUSY 且注册失败
9 在硬中断里调 snd_soc_jack_report 走 queue_delayed_work，它内部有 mutex
10 jack 的 invert 与硬件极性相反 先量引脚电平再定 invert，反了会出现插入即静音
11 自定义 jack 用 initial_kctl = true 与 pin 混用 ASoC 走 pin 路线时传 false，见 jack_new 里那个 false
12 读 /proc/.../hw_params 拿到空内容就以为驱动坏了 该文件依赖 runtime，只在流打开且设过参数后有内容
13 prealloc 值当成字节 单位是 KiB，512 是 512 KiB
14 以为 subdevices_avail 恒等于 subdevices_count 有流打开时 avail 会减，/proc/.../sub0/info 能看到 subdevices_avail: 0
15 主设备号写死成别的值 ALSA 固定 116，snd_register_device 里用静态 major
16 以为 snd_pcm_new_internal 建的 PCM 会有设备节点 不会，internal 为真时不建 /dev/snd 节点也不建 proc 目录
17 应用 mmap 之后再调 HW_PARAMS 已 mmap 的流改参数返回 -EBADFD
18 把 snd_card 的 private_data 当独立内存去 kfree 它在 extra_size 那块内存尾部，跟着主结构一起释放
