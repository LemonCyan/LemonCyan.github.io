一、ALC5651 芯片概览 #

ALC5651 是 Realtek 的低功耗音频 codec，NanoPC-T4 用它负责模拟侧的采集和回放。RK3399 内部的 I2S 控制器只出数字信号，模拟这一端由它来做。

按素材转录的 datasheet 特性：一路 24 位 / 8kHz~192kHz 的 I2S/PCM/TDM 接口，一路 24 位 / 8kHz~192kHz 的 I2S/PCM 接口，两路都能接立体声 DAC 和 ADC；控制接口走 I2C；1 路 DMIC 加 3 路模拟麦克风（IN1P、IN2P/IN2N、IN3P）；每个接口带 ASRC；DAC 和 ADC 路径各有 7 段 EQ；DAC/ADC 路径带 DRC/AGC 和防风噪降噪滤波器。引脚总数 40，分数字 I/O、模拟输入、模拟输出、电源与地四组。

从驱动视角只需记住这张对照：

芯片能力 寄存器 驱动里的东西
I2S1 数字接口 0x70（I2S1_SDP） rt5651_dai[0]，name = rt5651-aif1
I2S2 数字接口 0x71（I2S2_SDP） rt5651_dai[1]，name = rt5651-aif2
I2C 控制口 从地址 0x1a rt5651_i2c_driver、rt5651_regmap
时钟树 0x80（GLB_CLK）、0x81/0x82（PLL） set_dai_sysclk、set_dai_pll
模拟通路开关 0x29、0x2a、0x45、0x4f、0x52、0x02 DAPM widget + route + SOC_DAPM_SINGLE
增益/音量 0x02、0x1f、0x20、0x1b 等 rt5651_snd_controls[]
耳机插拔检测 0xBB、0xBC rt5651_set_jack

源码在 sound/soc/codecs/rt5651.c。文件名和芯片名不一样：芯片叫 ALC5651，内核里驱动、结构体、宏前缀全是 rt5651。

一颗 codec 驱动必须交代六件事：DAI 和 PCM 能力（snd_soc_dai_driver）、控制接口（I2C，落在 snd_soc_component_driver 的读写回调）、Mixer 和其它控件（snd_kcontrol_new 数组）、音频操作（snd_soc_dai_ops）、DAPM 描述（widget 数组加 route 数组）、DAPM 事件处理程序（PRE_PMU/POST_PMD 回调）。

二、I2S 接口协议基础 #

数字音频接口是物理连线，说的是同一块 PCB 上两颗 IC 之间的时序协议，和音频编码格式是两码事。I2S 和 PCM（TDM）传 PCM 编码数据，PDM 接口传 PDM 编码数据。

采样是把时间上连续的模拟信号离散化，采样频率是采样周期的倒数。奈奎斯特说采样率不低于信号最高频率两倍就能无失真还原，人耳 20Hz~20kHz，所以采样率得在 40kHz 以上。常见采样率与用途：

采样率 用途
8kHz 电话，人声够用
11.025kHz AM 调幅广播
22.05kHz / 24kHz FM 调频广播
32kHz miniDV、DAT
44.1kHz 音频 CD、MPEG-1 音频（VCD、SVCD、MP3）
47.25kHz 商用 PCM 录音机
48kHz miniDV、数字电视、DVD、DAT、电影专业音频
50kHz 商用数字录音机
96kHz / 192kHz DVD-Audio、LPCM DVD 音轨、BD-ROM 音轨

量化（位深、位宽）决定每个采样点用几个 bit，常见 8bit 和 16bit。编码是最后一步，为的是压缩数据量。传输率和数据量：

text
数据传输率（bps） = 采样频率 × 量化位数 × 声道数
数据量（byte）    = 数据传输率 × 持续时间 / 8

CD 的例子：44100 × 16 × 2 × 3600 / 8 = 6350400B ≈ 605.6MB，所以编码阶段经常上压缩。

PCM 等间隔采样，每次结果 N bit；PDM 用远高于 PCM 的时钟调制，只有 1 位输出，非 0 即 1，也叫 Oversampled 1-bit Audio。相比 PDM 那串 0/1 的密度变化，PCM 的量化结果直观得多。

I2S 的三根线 #

信号线 别名 作用 频率关系
SCLK BCLK，位时钟 每一位数据对应一个脉冲 SCLK = 2 × 采样率 × 采样位数（立体声）
WS LRCK，帧时钟 切左右声道，1 传左、0 传右（标准 I2S） 等于采样率
SD 数据线 实际音频数据，收发分开要两根 跟位宽走

44.1kHz / 16 位立体声：SCLK = 2 × 44100 × 16 = 1411200Hz = 1.4112MHz，WS = 44.1kHz。codec 侧收发分开叫 ADCDAT 和 DACDAT——前者 codec 往 SoC 送录音，后者 codec 从 SoC 收播放。方向别搞反，这是移植最常见的接线错误。

除 BCLK 和 LRCK 还要 MCLK 也不是没有。原因在 codec 内部的 ΔΣ 架构：这类 codec 没有自己的工作晶振，只能靠外部喂。MCLK 频率一般是采样频率的 256 倍或 384 倍。MCLK 不是必须的——ALC5651 可以拿 BCLK1/2 当内部 PLL 参考时钟，但 NanoPC-T4 上 MCLK 是接的，驱动默认走 MCLK 直通，PLL 全程没上电（第十三节用寄存器值证明）。

I2S 总线上同时只能有一个主设备。提供 SCLK 和 WS 的那个就是主设备，它可以是发送方、接收方，也可以是另一颗专门管时钟的芯片。

PCM 总线四根线：PCM_CLK 数据时钟、PCM_SYNC 帧同步、PCM_IN 接收、PCM_OUT 发送。常用于 AP 与 MODEM 之间传语音。I2S 只能传 2 声道，PCM 靠 TDM 能传多路，素材给的上限是 16 路。PDM 只有两根线（PDM_CLK、PDM_DATA），数字麦克风领域用得最广。

三种对齐模式 #

模式 LRCK 电平与声道 数据起始位置 备注
标准 I2S 低 = 左，高 = 右 LRCK 变化后第一个 SCLK 周期 MSB 先出，可为 LSB 先出
左对齐 高 = 左，低 = 右 LRCK 变化后第一个 SCLK 周期 数据靠左，LSB 位置随位宽浮动
右对齐 高 = 左，低 = 右 最后一个位对齐到 LRCK 边沿 数据靠右，帧头空出若干位

三种模式都能在 16~32 位间设位宽、选 MSB/LSB 先出。右对齐的细节：每个数据帧起始边沿处，数据位数与 SD 位宽相等；标准 I2S 和左对齐在起始边沿处分别是第一位和最后一位。也就是说，右对齐「贴着 LRCK 边沿收尾」，另两种「贴着边沿开头」。这直接决定 DAI 格式怎么配，见第十二节。

RK3399 侧还有个 RCNT 位（right justified counter），只在右对齐加从机发送模式下生效，让数据在左声道起始后延 RCNT 个 SCLK 周期再发。位域位置未验证。

三、I2S 的时序与时钟 #

RK3399 datasheet 第 22 章讲 I2S/PCM 控制器，芯片嵌了三个：

控制器 FIFO（32 位宽 × 32 位深） I2S 模式通道 最高采样率 对外
I2S0 8 个，4 发 4 收 10 收 + 10 发 192kHz 暴露到外设
I2S1 2 个，1 发 1 收 2 收 + 2 发 192kHz 暴露到外设
I2S2 4 个，4 发 8 发 768kHz 内部接 HDMI 和 DP

共同特性：AHB 接口；16~32 位数据；主从模式；PCM 模式支持 2 通道接收；DMA 握手接口和水位可配；发送空/下溢、接收满/上溢中断且全部可屏蔽；支持合并中断输出；支持 I2S 正常/左对齐/右对齐；支持 PCM 无延迟、延 1、延 2、延 3；支持 16~31 位数据在 32 位 FIFO 里左对齐或右对齐存放；支持两个 16 位数据塞进一个 32 位位置；支持两条独立 LRCK（采样率相同时可共用）；SCLK 和 LRCK 极性可配。

内部六个模块：系统接口（AHB 从属操作、控制寄存器、中断、DMA 握手）、时钟发生器（输入 MCLK_I2S，分频出 SCLK 和 LRCK）、发送器、接收器、传输 FIFO、接收 FIFO。

四种工作组合：发送主+接收主、发送主+接收从、发送从+接收主、发送从+接收从。发送方做主设备时它发全部信号，CPU 控制何时发时钟和数据；做从设备时 SD 仍由它发，但 SCLK 和 LRCK 由接收方发来，所以 CPU 必须提前知道接收方何时初始化事务。接收方做主设备时它发 SCLK 和 LRCK 同时收数据，CPU 得先告诉发送方开始事务。接收方做从设备时，CPU 初始化完就等着收。

TXCR / RXCR 位定义 #

I2S_TXCR 的大部分位域有前置条件：XFER[0] 为 0 时才能写。

位域 名称 含义
RCNT right justified counter 仅 I2S 右对齐 + 从机发送时生效。左声道起始后延 RCNT 个 SCLK 开始发数据
TCSR TX Channel Select 00 双声道，01 四声道，10 六声道，11 八声道
HWT Halfword word transform 仅 VDW 选 16bit 时生效。0：总线来 32 位，低 16 左声道、高 16 右声道；1：只有低 16 位被使用
SJM Store justified mode 16~31 位数据存进 32 位 FIFO 的对齐方式，0 右对齐 1 左对齐。VDW 选 16bit 且 HWT 为 0 时无效（FIFO 单元已塞满两个 16 位）
FBM First Bit Mode 0 MSB 先出，1 LSB 先出
IBM I2S bus mode 0 I2S normal，1 Left justified，2 Right justified，3 reserved
PBM PCM bus mode 0 无延迟，1 延 1，2 延 2，3 延 3
TFS Transfer format select 0 I2S 格式，1 PCM 格式
VDW Valid Data width 0~14 预留，15 为 16bit，16 为 17bit，n 为 (n+1)bit，31 为 32bit

CKR 与其余寄存器 #

I2S_CKR 管时钟，是最需要看懂的一个：

位域 名称 含义
TRCM Tx and Rx Common Use 00/11：收发各用各的 LRCK；01：只用 tx_lrck 作收发同步；10：只用 rx_lrck
MSS Master/slave mode 0 主模式（输出 sclk），1 从模式（输入 sclk）
CKP Sclk polarity 0 上升沿采样下降沿驱动；1 下降沿采样上升沿驱动
RLP / TLP 收/发 lrck polarity 0 正常极性，1 反相
MDIV mclk divider Serial Clock Divider = Fmclk / Ftxsclk - 1
RSD Receive sclk divider Fsclk / Frxlrck，0~30 预留，31 起为 32fs，n 为 (n+1)fs，255 为 256fs
TSD Transmit sclk divider Ftxsclk / Ftxlrck，编码同 RSD

正常极性：I2S 标准模式低为左、高为右；左右对齐高为左、低为右；PCM 起始信号高触发。反相就全部倒过来。MDIV 是偶数分频：

text
MDIV = 0        → Fmclk = Ftxsclk
MDIV = 1        → Fmclk = 2 × Ftxsclk
MDIV = 2, 3     → Fmclk = 4 × Ftxsclk
MDIV = 4, 5     → Fmclk = 6 × Ftxsclk
......
MDIV = 2n, 2n+1 → Fmclk = (2n+2) × Ftxsclk
......
MDIV = 254, 255 → Fmclk = 256 × Ftxsclk

发送启动的八步 #

text
(1) 向 I2S_XFER 第 0 位写 0x0，禁止发送器
(2) 向 I2S_CLR  第 0 位写 0x1，清除 I2S 控制逻辑
(3) 读 I2S_CLR  第 0 位，直到读回 0x0
(4) 设置 I2S_TXCR 和 I2S_CKR，配置操作模式
(5) 为发送器配置 DMA 通道，通过 I2S_TXDR 给出目标地址
(6) 写 I2S_DMACR，确定何时发 DMA 请求
(7) 向 I2S_XFER 第 0 位写 0x01，使能发送器
(8) 传输完成前，I2S_XFER 第 0 位不能再被禁止

第 (3) 步的轮询很关键：清逻辑是跨 SCLK 域的异步操作，写完就配下一颗寄存器，清逻辑还在路上，配置就被冲掉了。素材第 (1) 步写成「I2C_XFER」是笔误，应为 I2S_XFER；第 (5) 步「传输目标地址」也含糊，实际是 DMA 把源数据搬到 TXDR。

引脚与通道数 #

I2S0 有 1 路 SDI、4 路 SDO，支持 2 输入 + 8 输出声道。I2S1 有 1 路 SDI、1 路 SDO，支持 2 输入 + 2 输出。I2S2 接 HDMI 和 DP，支持 8 通道发送，引脚没对外暴露。RK3399 引脚大多复用，用哪路 I2S 得先把引脚 mux 过去。

四、ALC5651 的引脚与连接 #

ALC5651 有两组完整 I2S 引脚：I2S1 是 ADCDAT1、DACDAT1、LRCK1、BCLK1、MCLK；I2S2 是 ADCDAT2、DACDAT2、LRCK2、BCLK2、MCLK。以 I2S1 为例，播放时数字信号进 DACDAT1，解码后出模拟信号到喇叭或耳机；录音时采集麦克风模拟信号，编码后送 ADCDAT1。

引脚 方向 说明
MCLK 输入 SoC 提供的系统同步时钟，典型值是采样频率 256 倍
BCLK1 双向 位时钟，LRCK1 = 44.1kHz、32 位时 BCLK = 44.1kHz × 32 × 2
LRCK1 双向 采样频率信号，标准极性下低为左、高为右
ADCDAT1 输出 ADC 数据输出，codec → SoC
DACDAT1 输入 DAC 数据输入，SoC → codec

另外三组数字接口：DMIC（DMIC_DAT 数据输入、DMIC_SCL 时钟输出，板子没用）、PDM（PDM_SCL 时钟输出、PDM_SDA 数据输出，板子没用）、I2C 控制口（SCL/SDA 接 RK3399 I2C1，I2C1_SCL 走 GPIO4_A2，I2C1_SDA 走 GPIO4_A1）。

耳机插拔检测 #

JD1、JD2 是检测引脚。ALC5651 支持对 sta_gpio_jd、sta_jd1_1、sta_jd1_2、sta_jd2、sta_micbias1_ovcd 五种状态检测（JD = jack detection）。一般用 IRQ 配合 JD：JD 触发时 IRQ 往主机送标志，软件据此动作。这功能还能开关相关输出端口，比如 HP（耳机）和 LOUT（喇叭）自动切换。

第一步，选 JD 触发源，写 MX-BC[11:9]（MX-BC 就是 0xBC，即 RT5651_JD_CTRL2）：

编码 来源
000'b sta_gpio_jd
001'b sta_jd1_1
010'b sta_jd1_2
011'b sta_jd2
其它 Reserved

第二步，做 HP 和 LOUT 自动切换：MX-BB[11:10] = 11'b 且 MX-BB[3:2] = 10'b。

第三步，MX-BB（0xBB，RT5651_JD_CTRL1）的位定义：

位 名称 含义
11 Enable Jack Detect Trigger HPOUT 0 禁止，1 使能
10 Select Jack Detect Polarity Trigger HPOUT 0 低触发，1 高触发
3 Enable Jack Detect Trigger LOUT 0 禁止，1 使能
2 Select Jack Detect Polarity Trigger LOUT 0 低触发，1 高触发

行为：JD 为低时 HP_OUT 静音、LOUT 正常；JD 由低变高时 HP 恢复、LOUT 静音。

一条限制必须记住：做 HP/SPK 切换前，驱动得先把 DAC→HP 和 DAC→LOUT 两条通路都打开。MX-BB 只负责静音/取消静音，不建通路。通路没建，切了也是静音。

实测：放音时读这两个寄存器，0xBB 和 0xBC 都是 0x00。说明这条自动切换没被启用，切换逻辑全交给了上层 Machine 驱动的 jack 事件。

复位、ID 与补丁 #

上电第一件事读 ID：从 0xFF 读，读回 0x6281 才算在线，不对就 -ENODEV。第二件事写 0x00 = 0x0000 软件复位。第三件事打补丁：

c
static const struct reg_sequence init_list[] = {
        {RT5651_PR_BASE + 0x3d, 0x3e00},
};

这条写的是厂商私有页 0x3d，datasheet 没有对应说明，属于 Realtek 给的校正值。regmap_register_patch 把它登记进 map->patch，之后每次 regcache_sync() 都重放。这是它的关键价值——不是初始化一次，而是每次从 suspend 恢复同步缓存时都补上。实现要点：

c
int regmap_register_patch(struct regmap *map, const struct reg_sequence *regs,
                          int num_regs)
{
        struct reg_sequence *p;
        int ret;
        bool bypass;

        if (WARN_ONCE(num_regs <= 0, "invalid registers number (%d)\n",
            num_regs))
                return 0;

        p = krealloc(map->patch,
                     sizeof(struct reg_sequence) * (map->patch_regs + num_regs),
                     GFP_KERNEL);
        if (p) {
                memcpy(p + map->patch_regs, regs, num_regs * sizeof(*regs));
                map->patch = p;
                map->patch_regs += num_regs;
        } else {
                return -ENOMEM;
        }

        map->lock(map->lock_arg);
        bypass = map->cache_bypass;
        map->cache_bypass = true;
        map->async = true;
        ret = _regmap_multi_reg_write(map, regs, num_regs);
        map->async = false;
        map->cache_bypass = bypass;
        map->unlock(map->lock_arg);
        regmap_async_complete(map);

        return ret;
}

先 krealloc 把补丁追加到 map->patch，再立刻写一遍硬件，写的时候 cache_bypass 和 async 都置位。存一份加立刻生效，两件事都做才行。调用方对返回值只 dev_warn，打补丁失败不阻断 probe——私有寄存器写不进去，芯片多数场景还能出声，只是音质会偏。

六、regmap 与寄存器访问 #

codec 寄存器有三个特点：位宽不统一、地址空间分页、很多寄存器 volatile（读出来跟写进去不一样）。regmap 把这三件事统一了，还给缓存、批量写和调试接口。初始化一行：

c
rt5651->regmap = devm_regmap_init_i2c(i2c, &rt5651_regmap);
if (IS_ERR(rt5651->regmap)) {
        ret = PTR_ERR(rt5651->regmap);
        dev_err(&i2c->dev, "Failed to allocate register map: %d\n", ret);
        return ret;
}

devm_ 前缀意味着卸载时自动释放。rt5651_regmap 素材没完整转录，reg_bits / val_bits 具体值未验证（16 位值宽、8 位地址宽是从 regmap_read(..., &ret) 结果能到 0x6281 推出来的）。字段用途：

字段 作用 配错的后果
reg_bits 寄存器地址位宽 地址只发 8 位，高位页面丢
val_bits 寄存器值位宽 写 16 位只到 8 位，后半截截断
max_register 最大合法地址 越界直接报 EIO
volatile_reg 哪些寄存器不进缓存 状态寄存器被缓存，永远读旧值
readable_reg / writeable_reg 读写权限表 误写只读寄存器，I2C 返回 NAK
reg_defaults 寄存器默认值表 上电缓存是空的，regcache_sync 什么都没同步
cache_type 缓存策略 寄存器多的芯片要用 REGCACHE_RBTREE

组件层怎么调到 regmap #

snd_soc_component_driver 没显式给 .read/.write，因为 6.3 的 ASoC 自动从 component->regmap 走。分叉点在 snd_soc_component_update_bits：

c
int snd_soc_component_update_bits(struct snd_soc_component *component,
                                  unsigned int reg, unsigned int mask, unsigned int val)
{
        bool change;
        int ret;

        if (component->regmap)
                ret = regmap_update_bits_check(component->regmap, reg, mask,
                                               val, &change);
        else
                ret = snd_soc_component_update_bits_legacy(component, reg,
                                                           mask, val, &change);

        if (ret < 0)
                return soc_component_ret_reg_rw(component, ret, reg);
        return change;
}

老路径自己实现读—改—写，用 component->io_mutex 保护：

c
static int snd_soc_component_update_bits_legacy(
        struct snd_soc_component *component, unsigned int reg,
        unsigned int mask, unsigned int val, bool *change)
{
        unsigned int old, new;
        int ret = 0;

        mutex_lock(&component->io_mutex);
        old = soc_component_read_no_lock(component, reg);
        new = (old & ~mask) | (val & mask);
        *change = old != new;
        if (*change)
                ret = soc_component_write_no_lock(component, reg, new);
        mutex_unlock(&component->io_mutex);

        return soc_component_ret_reg_rw(component, ret, reg);
}

返回值语义要单独记：成功且值变了返回 1，成功但值没变返回 0，失败返回负数。所以别用 if (ret) 判成败，那会把「值没变」当错误。

常用 API：snd_soc_component_read、snd_soc_component_write、snd_soc_component_update_bits、snd_soc_component_get_drvdata、snd_soc_component_get_bias_level、snd_soc_component_force_bias_level。底层也能直接 regmap_read/regmap_write，probe 读 ID 就是直接用的 regmap_read。

bash

七、Codec 驱动的整体结构 #

rt5651.c 最后一行 module_i2c_driver(rt5651_i2c_driver)。宏定义在 include/linux/i2c.h：

c
#define module_i2c_driver(__i2c_driver) \
        module_driver(__i2c_driver, i2c_add_driver, \
                        i2c_del_driver)

module_driver 在 include/linux/device/driver.h：

c
#define module_driver(__driver, __register, __unregister, ...) \
static int __init __driver##_init(void) \
{ \
        return __register(&(__driver) , ##__VA_ARGS__); \
} \
module_init(__driver##_init); \
static void __exit __driver##_exit(void) \
{ \
        __unregister(&(__driver) , ##__VA_ARGS__); \
} \
module_exit(__driver##_exit);

展开等价于：

c
static int __init rt5651_i2c_driver_init(void)
{
    return i2c_add_driver(&rt5651_i2c_driver);
}

static void __exit rt5651_i2c_driver_exit(void)
{
    i2c_del_driver(&rt5651_i2c_driver);
}

素材把展开后的函数名写成 ov4689_i2c_driver_init——那是从摄像头 sensor 驱动复制没改干净的残留。函数名由宏用 ## 拼，实际一定是 rt5651_i2c_driver_init。

i2c_driver 结构体 #

c
static struct i2c_driver rt5651_i2c_driver = {
        .driver = {
                .name = "rt5651",
                .acpi_match_table = ACPI_PTR(rt5651_acpi_match),
                .of_match_table = of_match_ptr(rt5651_of_match),
        },
        .probe_new = rt5651_i2c_probe,
        .id_table = rt5651_i2c_id,
};

driver.of_match_table 是设备树匹配表，driver.acpi_match_table 是 ACPI 匹配表（非 ACPI 平台编译为空），probe/probe_new 是匹配成功后的探测函数，id_table 是传统名称匹配表。

probe_new 的回调只收 struct i2c_client *；老的 probe 签名是 (client, id)，多一个 id 参数。linux 6.3 已经把两者合并回单一的 probe，probe_new 在 6.4 前后被移除——具体哪个小版本，未验证。素材里 rt5651_i2c_probe 签名是 (struct i2c_client *i2c)，跟 probe_new 对得上，说明素材取自 6.3。

两套匹配机制 #

c
#if defined(CONFIG_OF)
static const struct of_device_id rt5651_of_match[] = {
        { .compatible = "realtek,rt5651", },
        {},  /* 最后一个必须为空，表示结束 */
};
MODULE_DEVICE_TABLE(of, rt5651_of_match);
#endif

static const struct i2c_device_id rt5651_i2c_id[] = {
        { "rt5651", 0 },
        { }
};

坑在这里：设备树里 compatible = "rockchip,rt5651"，但 rt5651_of_match 写的是 "realtek,rt5651"，两者对不上，设备树匹配这条路走不通。真正让 probe 被调用的是 id_table。I2C 控制器注册从设备时，of_i2c_get_board_info 解析设备节点，把 compatible 逗号之后的部分作为 type：

text
struct i2c_board_info info = {
     .type      = "rt5651",   /* 取自 compatible = "rockchip,rt5651" 逗号后部分 */
     .addr      = 0x1a,
     .of_node   = rt5651 设备节点,
};

type 赋给 i2c_client->name，于是它跟 rt5651_i2c_id[0].name 都是 "rt5651"，匹配成功。这解释了一个常见困惑：明明是设备树平台，为什么实际走 id_table？因为 SoC 厂商的 dts 写 rockchip,rt5651，而驱动 of_match 只认 realtek,rt5651。两种修法：把 dts 改成 "realtek,rt5651"（更正规），或在 of_match 里加一条 "rockchip,rt5651"（不动驱动）。

I2C 控制器侧 #

RK3399 有 9 个 I2C 控制器。控制器驱动在 drivers/i2c/busses/i2c-rk3x.c，走 platform 模型，产出 algorithm 层的收发函数。platform probe 里：分配并初始化 i2c_adapter（含设 algo）、把 GPIO 复用成 I2C、初始化控制器寄存器、取资源并注册中断、调 i2c_add_adapter 注册到 i2c_bus_type。

最后一步注册时会触发从设备扫描：of_i2c_register_devices 解析子节点逐个调 of_i2c_register_device，i2c_scan_board_info 扫描并用 i2c_new_device 注册静态从设备。ALC5651 走第一条。

顺序是：adapter 先注册，client 才出现，驱动 probe 才会被调用。dts 里 rt5651@1a 节点写了但 &i2c1 的 status 是 "disabled"，整条链路从一开始就断了，probe 不会被调用，dmesg 里连失败日志都没有。排查「驱动没加载」时先确认 status。

reg_cache_size / reg_cache_default / reg_word_size 改用 regmap_config 描述

真正的语义差别只有一条：4.19 之前 codec 是独立对象（snd_soc_codec），有自己的 dev 和 list；4.20 之后 codec 只是 snd_soc_component 的一个实例。所以 6.3 里搜 component->codec 搜不到，只有 dai->component。

soc_probe_component 干了什么 #

  1. 把 component->driver->dapm_widgets 注册到 card 的 widgets 链表；
  2. 执行 component->driver->probe(component)；
  3. 按 component->driver->controls 创建并添加 kcontrol 到 card 的 controls 链表；
  4. 遍历 component->driver->dapm_routes，调 snd_soc_dapm_add_routes 把每条 route 展开成 snd_soc_dapm_path，注册到 card 的 paths 链表；
  5. 把 component 加到 card 的 component_dev_list。

第 2 步的位置很关键：probe 在 routes 展开之前执行，所以 rt5651_probe 里不能依赖 DAPM 通路已建好，只能做纯寄存器级初始化。第 3、4 步顺序也不能换：先有 kcontrol，route 引用的 control 名字才能被解析。route 写了 {"DAC MIXR", "INF1 Switch", "IF1 DAC1 R"}，而 rt5651_dac_r_mix[] 里没有叫 INF1 Switch 的控件，snd_soc_dapm_add_routes 就报 ASoC: no dapm match for INF1 Switch。

DAPM 在这里的角色 #

两句话：路径改变时（上层用 tinymix 改通路）或发生数据流事件时（开始/停止播放），DAPM 遍历所有邻近 widget 检查是否存在完整通路，通路完整则路径上所有 widget 上电、其余下电；上下电由 DAPM 按策略自主控制，外部干预不了，它是专门给音频系统做的电源管理模块，独立于 Linux 那套 PM 之外。

第二点有实际好处：SoC 睡了 codec 还能工作。语音通话就是这样——modem 的 DAI 直接连 codec 的 DAI，语音数据不经过 SoC，于是 SoC 可以进低功耗，只要 codec 醒着。遍历算法和 snd_soc_dapm_path 生成规则在《DAPM：Widget、Route 与 Path》里。

九、DAPM 通路的定义 #

rt5651_dapm_widgets[] 是这颗 codec 的硬件地图。按操作分六大类：

SND_SOC_DAPM_INPUT / OUTPUT 无 物理输入 / 输出端点

翻上表会发现一件事：播放主通路上的 widget 基本都没设电源控制寄存器。从 AIF1RX → IF1 DAC → IF1 DAC1 R → DAC MIXR → Audio DSP → Stereo DAC MIXR → DAC R1 → OUT MIXR → HPOVOL R → HPOR MIX → HP Amp → HPO R Playback → HPOR，这一整条链上 SND_SOC_NOPM 占了大半。

这不是写漏了。ALC5651 的电源按「域」管理，一个 PWR_DIG1 里塞了 I2S1、I2S2、ADC L/R、DAC L1/R1 六路电源位，一个 PWR_VOL 塞了输入、输出、耳机四组音量级电源位。所以驱动用虚拟 widget 表达拓扑，真实上下电交给 Power 后缀的 SUPPLY widget 和 route 里那些 NULL control 的连线触发。排查「某段通路不通」时别盯着 DAC MIXR 找寄存器，要找它 route 里连到的 Stero1 DAC Power，去看 PWR_DIG2 的对应位。

三参数的语义 #

struct snd_soc_dapm_route 三个成员依次是 sink、control、source，写一行就是 {sink, control, source}。拿 {"DAC MIXL", "INF1 Switch", "IF1 DAC1 L"} 举例：输入端（source）是 IF1 DAC1 L，输出端（sink）是 DAC MIXL，名为 INF1 Switch 的 kcontrol 控制两者之间连线的通断。

关键点：这个 kcontrol 定义在 sink 端的控件数组里，也就是 rt5651_dac_l_mix[]。所以 route 里写的名字必须在 sink 的 mixer 控件里找得到，对不上就报 no dapm match。control 写 NULL 表示连线常通，这类用来表达电源依赖——{"ADC L", NULL, "ADC L Power"} 的意思就是 ADC L 要工作必须 ADC L Power 在。

写 route 的五条规则 #

  1. sink 和 source 必须在 dapm_widgets 里出现过，一字不差；
  2. control 非空时，名字必须在 sink 的 widget 控件的 name 字段里出现，同样一字不差；
  3. 电源依赖用 control = NULL，从 sink 连到 SUPPLY widget；
  4. mixer 的每个输入都要一条 route，漏一条就有一个输入永远用不上；
  5. 顺序无所谓，snd_soc_dapm_add_routes 自己建图，但同类放一起好维护。

SOC_DAPM_SINGLE 一个 DAPM 版 SOC_SINGLE
SOC_DAPM_SINGLE_AUTODISABLE 一个 DAPM 版，断电时自动置关闭
SOC_DAPM_ENUM 一个枚举 DAPM 版 Mux

DAPM 版和普通版只差 info/get/put 三个回调——普通版直接读写寄存器，DAPM 版会通知 DAPM 重走一遍路径检查。所以 mixer 的输入开关必须用 SOC_DAPM_SINGLE，用 SOC_SINGLE 的话寄存器写进去了但 DAPM 不知道，通路不会真建立。

有个细节要看错：Stereo2 的四个 mux 枚举全都定义在 RT5651_STO1_ADC_MIXER 上，不是 STO2_ADC_MIXER。寄存器复用，位偏移不同（STO2_ADC_L1_SRC_SFT 这类）。改代码时不要按名字想当然配寄存器。

mux 与 route 的字符串必须严格对齐 #

Stereo1 ADC L1 Mux 的枚举是 {"DD MIX", "ADC"}，route 写 {"Stereo1 ADC L1 Mux", "ADC", "ADC L"} 和 {..., "DD MIX", "DD MIXL"}。Stereo2 ADC L1 Mux 的枚举是 {"DD MIXL", "ADCL"}（多了 L 后缀），route 必须是 {..., "DD MIXL", "DD MIXL"} 和 {..., "ADCL", "ADC L"}。

DD MIX 和 DD MIXL 差一个字母，ADC 和 ADCL 也差一个字母。对不上就是那个 mux 永远选不到你要的输入，表现为「录音只有底噪」或者「录音走的是另一条路」。这是改 route 时最容易犯的错。

DAI 与 widget 的对应 #

注册声卡时调 soc_probe_link_components，为每个 DAI 创建两个流 widget：

DAI widget 类型 widget name widget sname
rt5651-aif1 snd_soc_dapm_dai_in AIF1 Playback AIF1 Playback
rt5651-aif1 snd_soc_dapm_dai_out AIF1 Capture AIF1 Capture

同时构造两条路径。以播放流 widget 为输入端，连 sname == "AIF1 Playback" 的 widget：

c
SND_SOC_DAPM_AIF_IN("AIF1RX", "AIF1 Playback", 0, SND_SOC_NOPM, 0, 0)

以录音流 widget 为输出端，输入端连 sname == "AIF1 Capture" 的 widget：

c
SND_SOC_DAPM_AIF_OUT("AIF1TX", "AIF1 Capture", 0, SND_SOC_NOPM, 0, 0)

于是得到完整播放链路：

text
AIF1 Playback --> AIF1RX --> IF1 DAC --> IF1 DAC1 L --> ... --> HPO L Playback --> HPOL --> Headphones

匹配靠 sname。如果你把 DAI 的 stream_name 改成别的，AIF1RX 的 sname 也得跟着改，否则链路第一步就断——现象是播放时 DAPM 报 AIF1RX 没有 source，通路建不起来，无声。

set_sysclk：选系统时钟源 #

c
static int rt5651_set_dai_sysclk(struct snd_soc_dai *dai,
                int clk_id, unsigned int freq, int dir)
{
        struct snd_soc_component *component = dai->component;
        struct rt5651_priv *rt5651 = snd_soc_component_get_drvdata(component);
        unsigned int reg_val = 0;
        unsigned int pll_bit = 0;

        if (freq == rt5651->sysclk && clk_id == rt5651->sysclk_src)
                return 0;

        switch (clk_id) {
        case RT5651_SCLK_S_MCLK:      /* 0 */
                reg_val |= RT5651_SCLK_SRC_MCLK;
                break;
        case RT5651_SCLK_S_PLL1:      /* 1 */
                reg_val |= RT5651_SCLK_SRC_PLL1;
                pll_bit |= RT5651_PWR_PLL;
                break;
        case RT5651_SCLK_S_RCCLK:     /* 2 */
                reg_val |= RT5651_SCLK_SRC_RCCLK;
                break;
        default:
                dev_err(component->dev, "Invalid clock id (%d)\n", clk_id);
                return -EINVAL;
        }

        snd_soc_component_update_bits(component, RT5651_PWR_ANLG2,
                RT5651_PWR_PLL, pll_bit);
        snd_soc_component_update_bits(component, RT5651_GLB_CLK,
                RT5651_SCLK_SRC_MASK, reg_val);
        rt5651->sysclk = freq;
        rt5651->sysclk_src = clk_id;

        dev_dbg(dai->dev, "Sysclk is %dHz and clock id is %d\n", freq, clk_id);
        return 0;
}
clk_id 值 GLB_CLK[15:14] PLL 电源
RT5651_SCLK_S_MCLK 0 00'b 下电
RT5651_SCLK_S_PLL1 1 01'b 上电（PWR_ANLG2[9] = 1）
RT5651_SCLK_S_RCCLK 2 10'b 不动

两个寄存器的分工：PWR_ANLG2（0x64）位[9] 是 PLL Power Control，0 下电 1 上电；GLB_CLK（0x80）位[15:14] 是 System Clock Source MUX，00 MCLK、01 PLL1、10 RCCLK、11 保留。结论直接：选 MCLK 就顺手把 PLL 下电，此时系统时钟 = 外部 MCLK 频率；选 PLL1 就给 PLL 上电，分频系数由 set_pll 动态算。

素材把 RT5651_GLB_CLK 的地址写成过「0x84」，正文另一处写 0x80。0x80 才是全局时钟控制，以 0x80 为准。

set_pll：算分频系数 #

c
static int rt5651_set_dai_pll(struct snd_soc_dai *dai, int pll_id, int source,
                        unsigned int freq_in, unsigned int freq_out)
{
        struct snd_soc_component *component = dai->component;
        struct rt5651_priv *rt5651 = snd_soc_component_get_drvdata(component);
        struct rl6231_pll_code pll_code;
        int ret;

        if (source == rt5651->pll_src && freq_in == rt5651->pll_in &&
            freq_out == rt5651->pll_out)
                return 0;

        if (!freq_in || !freq_out) {
                dev_dbg(component->dev, "PLL disabled\n");
                rt5651->pll_in = 0;
                rt5651->pll_out = 0;
                snd_soc_component_update_bits(component, RT5651_GLB_CLK,
                        RT5651_SCLK_SRC_MASK, RT5651_SCLK_SRC_MCLK);
                return 0;
        }

        switch (source) {
        case RT5651_PLL1_S_MCLK:      /* 0 */
                snd_soc_component_update_bits(component, RT5651_GLB_CLK,
                        RT5651_PLL1_SRC_MASK, RT5651_PLL1_SRC_MCLK);
                break;
        case RT5651_PLL1_S_BCLK1:     /* 1 */
                snd_soc_component_update_bits(component, RT5651_GLB_CLK,
                                RT5651_PLL1_SRC_MASK, RT5651_PLL1_SRC_BCLK1);
                break;
        case RT5651_PLL1_S_BCLK2:     /* 2 */
                snd_soc_component_update_bits(component, RT5651_GLB_CLK,
                                RT5651_PLL1_SRC_MASK, RT5651_PLL1_SRC_BCLK2);
                break;
        default:
                dev_err(component->dev, "Unknown PLL source %d\n", source);
                return -EINVAL;
        }

        ret = rl6231_pll_calc(freq_in, freq_out, &pll_code);
        if (ret < 0) {
                dev_err(component->dev, "Unsupported input clock %d\n", freq_in);
                return ret;
        }

        dev_dbg(component->dev, "bypass=%d m=%d n=%d k=%d\n",
                pll_code.m_bp, (pll_code.m_bp ? 0 : pll_code.m_code),
                pll_code.n_code, pll_code.k_code);

        snd_soc_component_write(component, RT5651_PLL_CTRL1,
                pll_code.n_code << RT5651_PLL_N_SFT | pll_code.k_code);
        snd_soc_component_write(component, RT5651_PLL_CTRL2,
                ((pll_code.m_bp ? 0 : pll_code.m_code) << RT5651_PLL_M_SFT) |
                (pll_code.m_bp << RT5651_PLL_M_BP_SFT));

        rt5651->pll_in = freq_in;
        rt5651->pll_out = freq_out;
        rt5651->pll_src = source;
        return 0;
}

参数：pll_id 是 PLL 编号（ALC5651 只有 1 个），source 是参考时钟源，freq_in 是参考频率，freq_out 是期望输出频率。参考源编码在 GLB_CLK 位[13:12]：

编码 参考源 宏 source 值
00'b MCLK RT5651_PLL1_SRC_MCLK RT5651_PLL1_S_MCLK = 0
01'b BCLK1 RT5651_PLL1_SRC_BCLK1 RT5651_PLL1_S_BCLK1 = 1
10'b BCLK2 RT5651_PLL1_SRC_BCLK2 RT5651_PLL1_S_BCLK2 = 2

素材注释把 RT5651_PLL1_S_BCLK2 那行写成「PLL 时钟源选择为 MCLK2」，是笔误，应为 BCLK2。freq_in 或 freq_out 为 0 时函数把时钟源拨回 MCLK，这就是「关 PLL」的标准做法——想省电或者嫌 PLL 锁定时长影响启动，就传 0 进来。

PLL 公式与位域 #

ALC5651 的 PLL 有两个控制寄存器：MX81（PLL_CTRL1）和 MX82（PLL_CTRL2）。输出频率：

text
             MCLK × (N + 2)
F_OUT  =  ────────────────────
          (M + 2) × (K + 2)

典型值 K = 2（K + 2 = 4），公式简化为 F_OUT = MCLK × (N+2) / (4 × (M+2))。

寄存器 位域 宏 偏移
PLL_CTRL1 (0x81) N PLL_N_SFT 7
PLL_CTRL1 (0x81) K — 低位
PLL_CTRL2 (0x82) M PLL_M_SFT 12
PLL_CTRL2 (0x82) M bypass PLL_M_BP_SFT 11

m_bp 为 1 时 M 分频被旁路，m_code 不写进寄存器。N 和 K 挤在同一个寄存器里，n_code << 7 | k_code。具体 N/M/K 由 rl6231_pll_calc()（在 sound/soc/codecs/rl6231.c）算，素材没展开计算过程，这里也不编。

一个能验证公式的量级：MCLK = 12.288MHz、K = 2、M = 0 时要得到 12.288MHz 输出，则 N + 2 = 4 × 2 × 1 = 8，N = 6。这组数只说明公式怎么用，实际取值以 rl6231_pll_calc 输出为准。

实测（放音时读寄存器）：

寄存器 值 含义
0x64（PWR_ANLG2） 0x0000 位[9] = 0，PLL 下电
0x80（GLB_CLK） 0x0000 位[15:14] = 00，时钟源为 MCLK
0x81（PLL_CTRL1） 0x0000 PLL 禁用，这些位没意义
0x82（PLL_CTRL2） 0x0000 同上

四个值全 0，一致——默认路径就是 MCLK 直通，全程没有 PLL 参与。这也是为什么 rt5651_set_dai_pll 在默认配置下根本没被调到。

hw_params：按参数配寄存器 #

c
static int rt5651_hw_params(struct snd_pcm_substream *substream,
        struct snd_pcm_hw_params *params, struct snd_soc_dai *dai)
{
        struct snd_soc_component *component = dai->component;
        struct rt5651_priv *rt5651 = snd_soc_component_get_drvdata(component);
        unsigned int val_len = 0, val_clk, mask_clk;
        int pre_div, bclk_ms, frame_size;

        rt5651->lrck[dai->id] = params_rate(params);
        pre_div = rl6231_get_clk_info(rt5651->sysclk, rt5651->lrck[dai->id]);
        if (pre_div < 0) {
                dev_err(component->dev, "Unsupported clock setting\n");
                return -EINVAL;
        }
        frame_size = snd_soc_params_to_frame_size(params);
        if (frame_size < 0) {
                dev_err(component->dev, "Unsupported frame size: %d\n", frame_size);
                return -EINVAL;
        }
        bclk_ms = frame_size > 32 ? 1 : 0;
        rt5651->bclk[dai->id] = rt5651->lrck[dai->id] * (32 << bclk_ms);

        dev_dbg(dai->dev, "bclk is %dHz and lrck is %dHz\n",
                rt5651->bclk[dai->id], rt5651->lrck[dai->id]);

        switch (params_width(params)) {
        case 16:
                break;
        case 20:
                val_len |= RT5651_I2S_DL_20;
                break;
        case 24:
                val_len |= RT5651_I2S_DL_24;
                break;
        case 8:
                val_len |= RT5651_I2S_DL_8;
                break;
        default:
                return -EINVAL;
        }

        switch (dai->id) {
        case RT5651_AIF1:
                mask_clk = RT5651_I2S_PD1_MASK;
                val_clk = pre_div << RT5651_I2S_PD1_SFT;
                snd_soc_component_update_bits(component, RT5651_I2S1_SDP,
                        RT5651_I2S_DL_MASK, val_len);
                snd_soc_component_update_bits(component, RT5651_ADDA_CLK1, mask_clk, val_clk);
                break;
        case RT5651_AIF2:
                mask_clk = RT5651_I2S_BCLK_MS2_MASK | RT5651_I2S_PD2_MASK;
                val_clk = pre_div << RT5651_I2S_PD2_SFT;
                snd_soc_component_update_bits(component, RT5651_I2S2_SDP,
                        RT5651_I2S_DL_MASK, val_len);
                snd_soc_component_update_bits(component, RT5651_ADDA_CLK1, mask_clk, val_clk);
                break;
        default:
                dev_err(component->dev, "Wrong dai->id: %d\n", dai->id);
                return -EINVAL;
        }
        return 0;
}

流程：从 params 取采样率存进 rt5651->lrck[dai->id]（LRCK = 采样率）；rl6231_get_clk_info(sysclk, lrck) 算预分频 pre_div，算不出来返回负数；snd_soc_params_to_frame_size(params) 算帧大小（帧 = 声道数 × 采样位数）；帧大小超过 32 则 bclk_ms = 1；bclk = lrck × (32 << bclk_ms) 即 lrck × 32 或 lrck × 64；按 params_width 选位深编码；按 DAI 编号写 I2S_SDP[3:2] 和 ADDA_CLK1 预分频位。

ADDA_CLK1（0x73）位[14:12] 是 I2S Clock Pre-Divider 1：

编码 000'b 001'b 010'b 011'b 100'b 101'b 110'b 111'b
分频 +1 +2 +3 +4 +6 +8 +12 +16

不是连续的 2 的幂，+1/+2/+3/+4/+6/+8/+12/+16 是常见的音频分频档位表，用来在多种采样率下凑整数比。实测放音时 0x73 读回 0x0104，位[14:12] = 0 表示预分频 +1，于是 Clk_sys_i2s1 = MCLK = 256 × FS。

三个参数解析函数 #

c
static inline unsigned int params_rate(const struct snd_pcm_hw_params *p)
{
        return hw_param_interval_c(p, SNDRV_PCM_HW_PARAM_RATE)->min;
}

static inline const struct snd_interval *hw_param_interval_c(const struct snd_pcm_hw_params *params,
                                                     snd_pcm_hw_param_t var)
{
        return &params->intervals[var - SNDRV_PCM_HW_PARAM_FIRST_INTERVAL];
}

int snd_soc_params_to_frame_size(struct snd_pcm_hw_params *params)
{
        int sample_size;

        sample_size = snd_pcm_format_width(params_format(params));
        if (sample_size < 0)
                return sample_size;

        return snd_soc_calc_frame_size(sample_size, params_channels(params), 1);
}

static inline int params_width(const struct snd_pcm_hw_params *p)
{
        return snd_pcm_format_width(params_format(p));
}

SNDRV_PCM_HW_PARAM_RATE 是 11，SNDRV_PCM_HW_PARAM_FIRST_INTERVAL 是 8，所以 11 - 8 = 3，取的是 params->intervals[3]->min。snd_soc_calc_frame_size(bits, channels, slots) 结果是 bits × channels × slots，这里 slots = 1，16 位 × 2 声道 = 32。params_format 从 SNDRV_PCM_HW_PARAM_FORMAT 的掩码里取最小值，snd_pcm_format_width 再映射成位宽，S16_LE → 16。

params_rate 取的是区间 min 而不是唯一值，不过 hw_params 的区间协商完成后已经收敛成单点，所以 min 就等于实际值。rl6231_get_clk_info() 的具体实现素材没给，它的分频表未验证，只知道输入 (sysclk, lrck)、输出分频档位、负值表示不支持。

上电顺序 #

set_sysclk 的写法是：先动 PWR_ANLG2 的 PLL 电源位，再动 GLB_CLK 的时钟源选择。

text
(1) 写 PWR_ANGL2[9]：0 关 PLL / 1 开 PLL
(2) 写 GLB_CLK[15:14]：选 MCLK / PLL1 / RCCLK
(3) （若选 PLL）写 GLB_CLK[13:12] 选参考源
(4) （若选 PLL）写 PLL_CTRL1 / PLL_CTRL2 设 N/M/K

顺序反了会怎样：先切时钟源到 PLL、再给 PLL 上电，中间那段时间时钟源指向一个还没上电的 PLL，输出是垃圾。窗口很短、多数时候不出问题，但按正确顺序写不费事。

PLL 什么时候用得着 #

三个实际场景。

场景一，MCLK 和采样率不配套。板子给 12.288MHz，采样率 44.1kHz，12.288M / 44.1k = 278.6 不是整数，rl6231_get_clk_info 算不出合适档位返回负数，hw_params 直接 -EINVAL。要么换 MCLK（24.576MHz 或 22.5792MHz），要么开 PLL 把非整数比转成整数比。

场景二，只有 BCLK 没有 MCLK。某些板子为省一根线 MCLK 不接，让 codec 从 BCLK 恢复时钟，这时 GLB_CLK[13:12] 选 01 或 10。

场景三，48kHz 和 44.1kHz 两个系列都要。44.1k 系列要 11.2896MHz 的整数倍，48k 系列要 12.288MHz 的整数倍，一颗固定晶振喂不满两头。

关 PLL 的正确姿势是 rt5651_set_dai_pll 里那句：传 0 进 freq_in 或 freq_out，函数把时钟源拨回 MCLK 就走。注意它没动 PWR_ANLG2[9] 的 PLL 电源位——那是 set_sysclk 的活儿。两个函数各管一半，调用先后由 Machine 驱动决定，想彻底关 PLL 得两个都走到。

MCLK、BCLK、LRCK 的关系 #

text
LRCK = FS                              （帧时钟 = 采样率）
BCLK = FS × 声道数 × 采样位数/声道       （位时钟）
     = FS × 32   （16 位 × 2 声道）
     = FS × 64   （32 位 × 2 声道）
MCLK = 256 × FS 或 384 × FS            （典型值）

44.1kHz / 16 位 / 双声道：LRCK = 44100Hz，BCLK = 1411200Hz = 1.4112MHz，MCLK = 11289600Hz = 11.2896MHz。BCLK 与 MCLK 之比是 8，对应 SoC 侧 I2S_CKR 的 MDIV 要配成 7（Fmclk = (2×3+2) × Ftxsclk，取 MDIV = 6 或 7）。RK3399 侧的 hclk/mclk 分频由 rockchip-i2s 驱动算，不用 codec 驱动操心，但两边必须对得上，对不上的现象是播放速度不对或者噪声。

十四、耳机与喇叭的输出路径 #

HPO MIX HPVOL Switch 这一位（HPO_MIXER 的 bit13）左右共用，因为 rt5651_hpo_mix[] 是同一个数组，HPOL MIX 和 HPOR MIX 两个 widget 都挂它。

一条旁路 #

HPOR MIX 有第二个输入直接从 DAC R1 来，{"HPOR MIX", "HPO MIX DAC1 Switch", "DAC R1"}，对应 HPO_MIXER 的 bit14。这条路绕开 OUT MIXR 和 HPOVOL R，所以走这条时 OUT MIXR 上的 5 个开关和 HPOVOL R 的音量全不起作用，音量只剩 HP_VOL 那一级。在 tinymix 里打开 HPO MIX DAC1 Switch 就是「跳过输出混合器」的直通路径，调试时用来排除 OUT MIXR 那一级的问题很好使。

喇叭（Line out）通路 #

LOUTL/P 和 LOUTR/N 是线路输出，不能直接推耳机，板子上要外接功放：

text
DAC L1 ──► LOUT MIX ──► LOUT L Playback ──► LOUTL ──► Amp Power
DAC R1 ──► LOUT MIX ──► LOUT R Playback ──► LOUTR ──► Amp Power
段 kcontrol 名 寄存器 位
DAC L1 → LOUT MIX DAC L1 Switch LOUT_MIXER M_DAC_L1_LM_SFT
DAC R1 → LOUT MIX DAC R1 Switch LOUT_MIXER M_DAC_R1_LM_SFT
OUTVOL L → LOUT MIX OUTVOL L Switch LOUT_MIXER M_OV_L_LM_SFT
OUTVOL R → LOUT MIX OUTVOL R Switch LOUT_MIXER M_OV_R_LM_SFT
LOUT MIX → LOUT L Playback Switch LOUT_CTRL1 L_MUTE_SFT
LOUT MIX → LOUT R Playback Switch LOUT_CTRL1 R_MUTE_SFT

LOUT 还有一条替代输入直通 DAC，绕过 OUTVOL。所以喇叭有两级音量：OUT Playback Volume（LOUT_CTRL1，模拟）和 DAC1 Playback Volume（DAC1_DIG_VOL，数字）。数字音量开太大会在 DAC1_DIG_VOL 那一级削顶，模拟开太大则在功放输入削顶。实践上数字音量留在 0dB 附近，模拟音量拿来调。

Amp Power 连着 LOUTL、LOUTR 和 HP Amp，挂在 PWR_ANLG1 的 PWR_HA_BIT，POST_PMU 时调 rt5651_amp_power_event。这个事件控制外接功放的电源/使能——具体动作素材没给，未验证。

耳机/喇叭自动切换 #

第 4 节讲过硬件层面的 MX-BB/MX-BC 切换，软件层面的 ASoC 提供 snd_soc_jack 机制：耳机插拔事件由 codec 的 set_jack 配置的中断源产生，Machine 驱动在 jack 事件回调里改 DAPM 通路（打开耳机通路关喇叭，或反过来）。

实测 0xBB 和 0xBC 都是 0x00，说明 NanoPC-T4 没用 codec 自带的自动切换，靠软件做。所以 dmesg 里能看到 rt5651 1-001a: Failed to reguest IRQ 0: -22 也照样能放音——整条 jack 检测链路都没启用。（reguest 是内核源码里的拼写错误，不是本篇的错别字。）

第一，RECMIXL 有四个输入：INL1 VOL、BST1、BST2、BST3。板子走 BST2（差分麦克风 2）和 INL1 VOL（单端参考）两支。选哪支决定录音增益：BST2 走 IN2 Boost（0~+52dB），INL1 VOL 走 IN Capture Volume（-34.5~0dB）。

第二，ADC L Power 是一条 NULL control 的 route，纯电源依赖。ADC L 本身是 SND_SOC_DAPM_ADC 且寄存器是 SND_SOC_NOPM，上不上电只看有没有连到 ADC L Power。

第三，ADC ASRC 和 I2S1 也都挂在链上，Stereo1 Filter 要 ADC ASRC 才工作，IF1 ADC1 要 I2S1 才工作。录音不出声时除了麦克风本身，还要确认 PWR_DIG1 的 PWR_I2S1_BIT 和 PWR_DIG2 的 PWR_ADC_STO1_F_BIT 有没有被拉起来。

数字麦克风通路 #

板子没用 DMIC，但通路完整：

text
DMIC L1 ──► Stereo1 ADC L2 Mux ─(DMIC)─► Stereo1 ADC MIXL
DMIC R1 ──► Stereo1 ADC R2 Mux ─(DMIC)─► Stereo1 ADC MIXR
DMIC CLK ──► DMIC L1 / DMIC R1          （时钟依赖）

DMIC CLK 是 SUPPLY widget，挂在 RT5651_DMIC 的 DMIC_1_EN_SFT，带 PRE_PMU 回调 set_dmic_clk，在上电前把 DMIC 时钟频率配好。DMIC L1、DMIC R1 名字里带空格，写 route 时别忘。

麦克风偏置 #

micbias1 是 SUPPLY widget，挂在 PWR_ANLG2 的 PWR_MB1_BIT。电容麦克风需要直流偏置才能工作，MICBIAS1 引脚提供这个电压。偏置的作用有三个：稳定工作点（没有偏置时温湿度变化会让输出偏移）；提高灵敏度；降低噪声。

set_bias_level 的 STANDBY 分支把 PWR_ANLG1 的 PWR_MB（bit13，MBIAS 电源）拉起来，同时拉 PWR_VREF1、PWR_BG、PWR_VREF2，四路一起上，等 10~15ms 让电压稳下来（usleep_range(10000, 15000)），再把 PWR_FV1、PWR_FV2 置上切到慢速 VREF 模式（datasheet 注释：For good analog performance）。这段代码的关键就是那个 usleep_range——少了它参考电压没稳，录音里会有「咔」声或者低频噪声。

录音增益链 #

级 控件 范围 说明
1 IN2 Boost 0~+52dB，9 档 差分前置放大，在 BST2 上
2 IN Capture Volume -34.5~0dB，1.5dB 步进 INL1 VOL/INR1 VOL
3 ADC Boost Gain 0/12/24/36dB ADC 前级，2 位
4 ADC Capture Volume -17.62~+30dB ADC 数字增益，7 位
5 ADC Capture Switch on/off ADC 静音

五级串起来理论上限 118dB，实际用不满——IN2 Boost 开到 +50dB 时底噪也会被放大 50dB。常见做法：麦克风离得近就把 boost 压到 0~+20dB，靠 ADC 数字增益补；离得远才开高 boost。

录音不出声的排查顺序 #

  1. 看 /proc/asound/card0/pcm0c/sub0/hw_params，确认采样率和格式；
  2. 看 /sys/kernel/debug/asoc/<card>/dapm/ 下各 widget 状态，IN2P、BST2、RECMIXL、ADC L、Stereo1 ADC L1 Mux、IF1 ADC1、AIF1TX 应该全是 On；
  3. 用 tinymix 确认 RECMIXL BST2 Switch、Stereo1 ADC L1 source、Stereo1 ADC MIXL ADC1 Switch 三个都是开的；
  4. 读 PWR_ANLG2 和 PWR_ANLG1，确认 micbias1 和 LDO 的位是 1；
  5. 都对了还不行就回硬件：麦克风是不是真接在 IN2P/IN2N 上，MICBIAS1 上有没有电压。

十六、probe 的完整流程 #

rt5651_i2c_probe #

c
static int rt5651_i2c_probe(struct i2c_client *i2c)
{
        struct rt5651_priv *rt5651;
        int ret;
        int err;

        rt5651 = devm_kzalloc(&i2c->dev, sizeof(*rt5651), GFP_KERNEL);
        if (NULL == rt5651)
                return -ENOMEM;

        i2c_set_clientdata(i2c, rt5651);

        rt5651->regmap = devm_regmap_init_i2c(i2c, &rt5651_regmap);
        if (IS_ERR(rt5651->regmap)) {
                ret = PTR_ERR(rt5651->regmap);
                dev_err(&i2c->dev, "Failed to allocate register map: %d\n", ret);
                return ret;
        }

        /* 读 0xff，rt5651 的寄存器地址 0xff 存放 16 位设备 ID */
        err = regmap_read(rt5651->regmap, RT5651_DEVICE_ID, &ret);
        if (err)
                return err;

        if (ret != RT5651_DEVICE_ID_VALUE) {    /* 0x6281 */
                dev_err(&i2c->dev,
                        "Device with ID register %#x is not rt5651\n", ret);
                return -ENODEV;
        }

        /* 寄存器地址 0x00 是软件复位，写 0x00 复位所有寄存器 */
        regmap_write(rt5651->regmap, RT5651_RESET, 0);

        ret = regmap_register_patch(rt5651->regmap, init_list,
                                    ARRAY_SIZE(init_list));
        if (ret != 0)
                dev_warn(&i2c->dev, "Failed to apply regmap patch: %d\n", ret);

        rt5651->irq = i2c->irq;
        rt5651->hp_mute = true;

        INIT_DELAYED_WORK(&rt5651->bp_work, rt5651_button_press_work);
        INIT_WORK(&rt5651->jack_detect_work, rt5651_jack_detect_work);

        /* Make sure work is stopped on probe-error / remove */
        ret = devm_add_action_or_reset(&i2c->dev, rt5651_cancel_work, rt5651);
        if (ret)
                return ret;

        ret = devm_request_irq(&i2c->dev, rt5651->irq, rt5651_irq,
                               IRQF_TRIGGER_RISING | IRQF_TRIGGER_FALLING
                               | IRQF_ONESHOT | IRQF_NO_AUTOEN, "rt5651", rt5651);
        if (ret) {
                dev_warn(&i2c->dev, "Failed to reguest IRQ %d: %d\n",
                         rt5651->irq, ret);
                rt5651->irq = -ENXIO;
        }

        ret = devm_snd_soc_register_component(&i2c->dev,
                                &soc_component_dev_rt5651,
                                rt5651_dai, ARRAY_SIZE(rt5651_dai));
        return ret;
}

九步按顺序：

  1. devm_kzalloc 申请 struct rt5651_priv，i2c_set_clientdata 挂到 i2c->dev.driver_data。之后 snd_soc_component_get_drvdata(component) 拿到的就是它——component 的 dev 就是 i2c->dev；
  2. devm_regmap_init_i2c 注册 regmap，失败直接返回，因为后面每步都依赖寄存器访问；
  3. 读 0xFF 必须等于 RT5651_DEVICE_ID_VALUE（0x6281），这是「I2C 通不通 + 芯片在不在」的双重确认，不对返回 -ENODEV；
  4. 写 0x00 = 0 软件复位；
  5. regmap_register_patch 写 RT5651_PR_BASE + 0x3d = 0x3e00，失败只 dev_warn；
  6. 初始化 irq（设备树没配中断时是 0）、hp_mute = true（开机先静音），初始化 bp_work（延迟工作，处理耳机按键）和 jack_detect_work（普通工作，处理插拔）；
  7. devm_add_action_or_reset 注册清理动作 rt5651_cancel_work：
c
static void rt5651_cancel_work(void *data)
{
        struct rt5651_priv *rt5651 = data;

        cancel_work_sync(&rt5651->jack_detect_work);
        cancel_delayed_work_sync(&rt5651->bp_work);
}

两个 cancel_*_sync 都是同步等待，保证 work 真停了才返回。这一步必须在申请中断之前——先有清理动作再有中断源，否则中断进来了 work 还没初始化完；

  1. devm_request_irq 申请中断，标志位 IRQF_TRIGGER_RISING | IRQF_TRIGGER_FALLING | IRQF_ONESHOT | IRQF_NO_AUTOEN。双边沿是因为插拔两个方向都要响应；IRQF_ONESHOT 让中断线程化，handler 跑完才放开中断线；IRQF_NO_AUTOEN 表示申请成功但不自动使能，真正的 enable_irq 在 rt5651_enable_jack_detect 末尾。handler 极简：
c
static irqreturn_t rt5651_irq(int irq, void *data)
{
        struct rt5651_priv *rt5651 = data;

        queue_work(system_power_efficient_wq, &rt5651->jack_detect_work);
        return IRQ_HANDLED;
}

只把 work 排进队列就返回，寄存器读写全在 rt5651_jack_detect_work 里——I2C 读寄存器会睡眠，不能在硬中断里做。

设备树没配中断时 i2c->irq = 0，这次申请必然失败，于是打出：

text
[    3.465917] rt5651 1-001a: Failed to reguest IRQ 0: -22

-22 是 -EINVAL。这条报错不影响声卡工作，只影响耳机插拔检测。1-001a 是 i2c_client->dev 的命名规则：总线号-从地址。

  1. devm_snd_soc_register_component 注册 component，返回值直接 return。之后 component 的 dai_list 有两个 DAI：rt5651-aif1（I2S1）和 rt5651-aif2（I2S2）。component 自己的名字是「设备驱动名 + 设备名」拼起来的，即 rt5651.1-001a。

rt5651_probe（component 层） #

rt5651_i2c_probe 注册完 component 就结束了，真正操作 DAPM 相关寄存器的初始化在 rt5651_probe，由 soc_probe_component 在注册声卡时调用：

c
static int rt5651_probe(struct snd_soc_component *component)
{
        struct rt5651_priv *rt5651 = snd_soc_component_get_drvdata(component);

        rt5651->component = component;

        /* PWR_ANLG1 = 0x63，位[1:0] 写 10'b 配 LDO 输出 1.2V */
        snd_soc_component_update_bits(component, RT5651_PWR_ANLG1,
                RT5651_PWR_LDO_DVO_MASK, RT5651_PWR_LDO_DVO_1_2V);
        snd_soc_component_force_bias_level(component, SND_SOC_BIAS_OFF);

        rt5651_apply_properties(component);

        return 0;
}

三件事：

  1. 配内部 LDO 输出 1.2V。PWR_ANGL1（0x63）的 PWR_LDO_DVO_MASK 是 0x03（位[1:0]），PWR_LDO_DVO_1_2V 是 2，即写 10'b，得到 1.2V。这个 LDO 供数字核用，LDO1_EN 拉高时才启用；
  2. 强制 bias 等级到 OFF。snd_soc_component_force_bias_level(component, SND_SOC_BIAS_OFF) 把 dapm->bias_level 置 0，等于告诉 DAPM「当前是关闭态」，这样后续第一次上电会走完整的 OFF → STANDBY 路径，四路参考电压才正常拉起。force 版本会把变化通知出去，确保状态机从干净状态开始；
  3. 应用设备树属性。rt5651_apply_properties 从 of_node 读 realtek,jd-src、realtek,ovcd-threshold 这类私有属性，具体支持哪些看 Documentation/devicetree/bindings/sound/rt5651.txt。

set_bias_level 详解 #

c
static int rt5651_set_bias_level(struct snd_soc_component *component,
                        enum snd_soc_bias_level level)
{
        switch (level) {
        case SND_SOC_BIAS_PREPARE:
                if (SND_SOC_BIAS_STANDBY == snd_soc_component_get_bias_level(component)) {
                        /* PLL_MODE_1 = 0x83，判 [15] I2S1、[12] I2S2、[9] DMIC1 三路 ASRC */
                        if (snd_soc_component_read(component, RT5651_PLL_MODE_1) & 0x9200)
                                snd_soc_component_update_bits(component, RT5651_D_MISC,
                                                    0xc00, 0xc00);
                }
                break;
        case SND_SOC_BIAS_STANDBY:
                if (SND_SOC_BIAS_OFF == snd_soc_component_get_bias_level(component)) {
                        /* [15] VREF1 [13] MBIAS [11] Bandgap [4] VREF2 先上电 */
                        snd_soc_component_update_bits(component, RT5651_PWR_ANLG1,
                                RT5651_PWR_VREF1 | RT5651_PWR_MB |
                                RT5651_PWR_BG | RT5651_PWR_VREF2,
                                RT5651_PWR_VREF1 | RT5651_PWR_MB |
                                RT5651_PWR_BG | RT5651_PWR_VREF2);
                        usleep_range(10000, 15000);
                        /* 电压稳了再切慢速 VREF：[14] FV1 [0] FV2 */
                        snd_soc_component_update_bits(component, RT5651_PWR_ANLG1,
                                RT5651_PWR_FV1 | RT5651_PWR_FV2,
                                RT5651_PWR_FV1 | RT5651_PWR_FV2);
                        snd_soc_component_update_bits(component, RT5651_D_MISC, 0x1, 0x1);
                }
                break;
        case SND_SOC_BIAS_OFF:
                snd_soc_component_write(component, RT5651_D_MISC, 0x0010);
                snd_soc_component_write(component, RT5651_PWR_DIG1, 0x0000);
                snd_soc_component_write(component, RT5651_PWR_DIG2, 0x0000);
                snd_soc_component_write(component, RT5651_PWR_VOL, 0x0000);
                snd_soc_component_write(component, RT5651_PWR_MIXER, 0x0000);
                /* Do not touch the LDO voltage select bits on bias-off */
                snd_soc_component_update_bits(component, RT5651_PWR_ANLG1,
                        ~RT5651_PWR_LDO_DVO_MASK, 0);
                /* Leave PLL1 and jack-detect power as is, all others off */
                snd_soc_component_update_bits(component, RT5651_PWR_ANLG2,
                                    ~(RT5651_PWR_PLL | RT5651_PWR_JD_M), 0);
                break;
        default:
                break;
        }
        return 0;
}
分支 触发条件 条件检查 动作
PREPARE 进准备态 当前是 STANDBY 若 ASRC 开着，写 D_MISC[11:10] = 11'b
STANDBY 进待机态 当前是 OFF 拉 4 路参考电压、延时、切慢速 VREF、写 D_MISC[0] = 1
OFF 进关闭态 无 清 5 个电源寄存器，保留 LDO 电压位和 PLL/JD 电源位

PREPARE 的判断条件 PLL_MODE_1 & 0x9200 展开是 1001 0010 0000 0000，正好是 bit15（I2S1 ASRC）、bit12（I2S2 ASRC）、bit9（DMIC1 ASRC）。任一路开着就往 D_MISC 的位[11:10] 写 11'b。datasheet 没描述这两位，驱动注释也直说「芯片手册中并没有描述这两位有什么作用」——这是厂商私有配置，照抄，别自作聪明改。

STANDBY 用到的位：

位 宏 名称 含义
15 PWR_VREF1 VREF1 Power Control 0 下电，1 上电
14 PWR_FV1 VREF1 Fast Mode Control 0 Fast VREF，1 Slow VREF
13 PWR_MB MBIAS Power Control 0 下电，1 上电
11 PWR_BG MBIAS Bandgap Power Control 0 下电，1 上电
4 PWR_VREF2 VREF2 Power Control 0 下电，1 上电
0 PWR_FV2 VREF2 Fast Mode Control 0 Fast VREF，1 Slow VREF

先上电（15/13/11/4），延时，再切慢速模式（14/0）。顺序不能反——VREF 没稳就切慢速，环路会振荡。datasheet 注释说慢速模式模拟性能更好，代价是建立时间长，所以必须等电压稳。

OFF 分支的两条「保留」注释值得单独记：

  • Do not touch the LDO voltage select bits ——mask 用 ~RT5651_PWR_LDO_DVO_MASK 把 LDO 电压位排除，因为它是 rt5651_probe 配好的，清了就得重配；
  • Leave PLL1 and jack-detect power as is ——~(PWR_PLL | PWR_JD_M)，这两路不清，因为 PLL 电源和 jack 检测在 bias off 期间还要工作（插拔检测必须在「关机」状态下也响应）。

D_MISC（0xFA）上电时写 0x0010、待机时写位[0]，datasheet 同样没描述，照抄。

struct snd_soc_jack 是 ASoC 里描述插孔的通用结构，提供状态、引脚的管理和通知。Machine 驱动建好 jack 就交给 codec，传 NULL 表示关掉检测。rt5651_enable_jack_detect 的骨架：

c
static void rt5651_enable_jack_detect(struct snd_soc_component *component,
                                      struct snd_soc_jack *hp_jack,
                                      struct gpio_desc *gpiod_hp_det)
{
        struct rt5651_priv *rt5651 = snd_soc_component_get_drvdata(component);
        bool using_internal_jack_detect = true;

        /* Select jack detect source */
        switch (rt5651->jd_src) {
        case RT5651_JD_NULL:
                rt5651->gpiod_hp_det = gpiod_hp_det;
                if (!rt5651->gpiod_hp_det)
                        return; /* No jack detect */
                using_internal_jack_detect = false;
                break;
        case RT5651_JD1_1:
                snd_soc_component_update_bits(component, RT5651_JD_CTRL2,
                        RT5651_JD_TRG_SEL_MASK, RT5651_JD_TRG_SEL_JD1_1);
                /* active-low is normal, set inv flag for active-high */
                if (rt5651->jd_active_high)
                        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL1,
                                RT5651_JD1_1_IRQ_EN | RT5651_JD1_1_INV,
                                RT5651_JD1_1_IRQ_EN | RT5651_JD1_1_INV);
                else
                        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL1,
                                RT5651_JD1_1_IRQ_EN | RT5651_JD1_1_INV,
                                RT5651_JD1_1_IRQ_EN);
                break;
        case RT5651_JD1_2:
                snd_soc_component_update_bits(component, RT5651_JD_CTRL2,
                        RT5651_JD_TRG_SEL_MASK, RT5651_JD_TRG_SEL_JD1_2);
                if (rt5651->jd_active_high)
                        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL1,
                                RT5651_JD1_2_IRQ_EN | RT5651_JD1_2_INV,
                                RT5651_JD1_2_IRQ_EN | RT5651_JD1_2_INV);
                else
                        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL1,
                                RT5651_JD1_2_IRQ_EN | RT5651_JD1_2_INV,
                                RT5651_JD1_2_IRQ_EN);
                break;
        case RT5651_JD2:
                snd_soc_component_update_bits(component, RT5651_JD_CTRL2,
                        RT5651_JD_TRG_SEL_MASK, RT5651_JD_TRG_SEL_JD2);
                if (rt5651->jd_active_high)
                        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL1,
                                RT5651_JD2_IRQ_EN | RT5651_JD2_INV,
                                RT5651_JD2_IRQ_EN | RT5651_JD2_INV);
                else
                        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL1,
                                RT5651_JD2_IRQ_EN | RT5651_JD2_INV,
                                RT5651_JD2_IRQ_EN);
                break;
        default:
                dev_err(component->dev,
                        "Currently only JD1_1 / JD1_2 / JD2 are supported\n");
                return;
        }

        if (using_internal_jack_detect) {
                /* IRQ output on GPIO1 */
                snd_soc_component_update_bits(component, RT5651_GPIO_CTRL1,
                        RT5651_GP1_PIN_MASK, RT5651_GP1_PIN_IRQ);
                /* Enable jack detect power */
                snd_soc_component_update_bits(component, RT5651_PWR_ANLG2,
                        RT5651_PWR_JD_M, RT5651_PWR_JD_M);
        }

        /* Set OVCD threshold current and scale-factor */
        snd_soc_component_write(component, RT5651_PR_BASE + RT5651_BIAS_CUR4,
                                0xa800 | rt5651->ovcd_sf);

        snd_soc_component_update_bits(component, RT5651_MICBIAS,
                                      RT5651_MIC1_OVCD_MASK |
                                      RT5651_MIC1_OVTH_MASK |
                                      RT5651_PWR_CLK12M_MASK |
                                      RT5651_PWR_MB_MASK,
                                      RT5651_MIC1_OVCD_EN |
                                      rt5651->ovcd_th |
                                      RT5651_PWR_MB_PU |
                                      RT5651_PWR_CLK12M_PU);

        /*
         * 过流检测只在「没有过流」这个方向可靠。插孔里麦克风触点被短路时，
         * 硬件会周期性重试加偏置电流，OVCD 状态在 1-0-1 之间翻转，约 10%
         * 的时间是 0。轮询有概率正好撞上那 10%，所以开 sticky 模式，检查
         * OVCD 时先清状态、msleep() 一下再读，才能拿到可靠值。
         */
        snd_soc_component_update_bits(component, RT5651_IRQ_CTRL2,
                RT5651_MB1_OC_STKY_MASK, RT5651_MB1_OC_STKY_EN);

        rt5651->hp_jack = hp_jack;
        if (rt5651_support_button_press(rt5651)) {
                rt5651_enable_micbias1_for_ovcd(component);
                rt5651_enable_micbias1_ovcd_irq(component);
        }

        enable_irq(rt5651->irq);
        /* sync initial jack state */
        queue_work(system_power_efficient_wq, &rt5651->jack_detect_work);
}

四种 JD 源处理一样，只是换 JD_CTRL2 的选择值和对应的 IRQ_EN/INV 位：

jd_src 用 JD_CTRL2 的选择位 备注
RT5651_JD_NULL 不用 走外部 GPIO，需 gpiod_hp_det，置 using_internal_jack_detect = false
RT5651_JD1_1 JD_TRG_SEL_JD1_1 接 JD1 引脚
RT5651_JD1_2 JD_TRG_SEL_JD1_2 JD1 引脚的另一种检测模式
RT5651_JD2 JD_TRG_SEL_JD2 接 JD2 引脚

jd_active_high 为真时除了使能 IRQ 还要置 INV 位把极性反过来。注释写得很直白：active-low is normal——芯片默认低电平触发。

using_internal_jack_detect 为真时做两件事：把 GPIO1 复用成 IRQ 输出（GPIO_CTRL1 的 GP1_PIN_MASK 写成 GP1_PIN_IRQ，即把 GPIO1/IRQ1 从通用 GPIO 切成中断输出）；打开 jack 检测电源（PWR_ANLG2 的 PWR_JD_M）。

ovcd 相关是麦克风按键检测用的。RT5651_BIAS_CUR4 写 0xa800 | ovcd_sf，高位是固定的偏置电流配置，低位是缩放因子。MICBIAS 寄存器配过流检测阈值和使能。那段英文长注释讲的是：过流检测只在「没有过流」方向可靠，麦克风触点短路时硬件周期性重试加偏置电流，OVCD 状态在 1-0-1 之间翻转、约 10% 时间是 0，轮询有概率撞上，所以开 sticky 模式（MB1_OC_STKY_EN），检查时先清状态、msleep() 再读。

最后两句：enable_irq(rt5651->irq) 把中断真正打开（probe 里用了 IRQF_NO_AUTOEN，必须在这里显式开），然后排一个 jack_detect_work 同步初始插孔状态。在 NanoPC-T4 上这一步因为 rt5651->irq = -ENXIO 而无效——enable_irq(-ENXIO) 会不会触发 warning，未验证，实测没有相关报错。

现象 常见原因

codec 节点 #

dts
&i2c1 {

属性 值 含义
status（i2c1 上） "okay" 打开 I2C1 控制器。这项不 okay，codec 节点写了也没用
i2c-scl-rising-time-ns <300> SCL 上升时间，单位 ns，用来算 I2C 时序
i2c-scl-falling-time-ns <15> SCL 下降时间

clocks <&cru SCLK_I2S_8CH_OUT> MCLK 时钟源
clock-names "mclk" 时钟名，驱动按这个名字 devm_clk_get
status "okay" 该设备启用

reg = <0x1a> 和别的 0x1a 设备冲突会表现为 probe 读到错的 ID。两个 time-ns 值来自板子的信号完整性测量，填大了拉低 SCL 频率，填小了超时。

I2C 控制器节点 #

定义在 arch/arm64/boot/dts/rockchip/rk3399.dtsi：

dts
i2c1: i2c@ff110000 {
        compatible = "rockchip,rk3399-i2c";
        reg = <0x0 0xff110000 0x0 0x1000>;
        assigned-clocks = <&cru SCLK_I2C1>;
        assigned-clock-rates = <200000000>;
        clocks = <&cru SCLK_I2C1>, <&cru PCLK_I2C1>;
        clock-names = "i2c", "pclk";
        interrupts = <GIC_SPI 59 IRQ_TYPE_LEVEL_HIGH 0>;
        pinctrl-names = "default";
        pinctrl-0 = <&i2c1_xfer>;
        #address-cells = <1>;
        #size-cells = <0>;
        status = "disabled";
};

reg 是 64 位地址写法，<0x0 0xff110000 0x0 0x1000> 表示基址 0xFF110000、长度 0x1000。assigned-clock-rates = <200000000> 把 SCLK_I2C1 设成 200MHz，实际 SCL 频率由分频器从它算出来。clocks 两路是功能时钟 SCLK_I2C1 和总线时钟 PCLK_I2C1，名字 i2c 和 pclk。pinctrl-0 = <&i2c1_xfer> 对应 GPIO4_A1/A2。#address-cells = <1> 加 #size-cells = <0> 决定子节点 reg 只写一个数（从地址）、不带长度。status = "disabled" 是 SoC 级默认值，板级 dts 改成 okay——dtsi 里全关、dts 里按板子需要打开，这样同一颗 SoC 的不同板子不会互相干扰。

MCLK 的来源 #

text
clocks = <&cru SCLK_I2S_8CH_OUT>;
clock-names = "mclk";

SCLK_I2S_8CH_OUT 是 RK3399 CRU 里的一颗 composite 时钟，定义在 drivers/clk/rockchip/clk-rk3399.c：

text
COMPOSITE_NODIV(SCLK_I2S_8CH_OUT, "clk_i2sout", mux_i2sout_p, CLK_SET_RATE_PARENT,
                RK3399_CLKSEL_CON(31), 2, 1, MFLAGS,
                RK3399_CLKGATE_CON(8), 12, GFLAGS)

COMPOSITE_NODIV 在 drivers/clk/rockchip/clk.h：

c
#define COMPOSITE_NODIV(_id, cname, pnames, f, mo, ms, mw, mf,  \
                        go, gs, gf)                             \
        {                                                       \
                .id             = _id,                          \
                .branch_type    = branch_composite,             \
                .name           = cname,                        \
                .parent_names   = pnames,                       \
                .num_parents    = ARRAY_SIZE(pnames),           \
                .flags          = f,                            \
                .muxdiv_offset  = mo,                           \
                .mux_shift      = ms,                           \
                .mux_width      = mw,                           \
                .mux_flags      = mf,                           \
                .gate_offset    = go,                           \
                .gate_shift     = gs,                           \
                .gate_flags     = gf,                           \
        }

参数展开：_id = SCLK_I2S_8CH_OUT，cname = "clk_i2sout"，pnames = mux_i2sout_p，f = CLK_SET_RATE_PARENT（设频率往父时钟传），mo = RK3399_CLKSEL_CON(31)，ms = 2，mw = 1（2 选 1），mf = MFLAGS，go = RK3399_CLKGATE_CON(8)，gs = 12，gf = GFLAGS。

两个地址宏：

c
#define RK3399_CLKGATE_CON(x)           ((x) * 0x4 + 0x300)
#define RK3399_CLKSEL_CON(x)            ((x) * 0x4 + 0x100)

算一下：RK3399_CLKGATE_CON(8) = 8 × 0x4 + 0x300 = 0x320（CRU_CLKGATE_CON8）；RK3399_CLKSEL_CON(31) = 31 × 0x4 + 0x100 = 0x17C（CRU_CLKSEL_CON31）。

CRU_CLKGATE_CON8 的位[12] 是 clk_i2sout 的时钟使能，低电平使能、高电平禁用（Rockchip CRU 门控是反相的）。CRU_CLKSEL_CON31 的位[2] 用于 clk_i2sout 的时钟源选择，和 mux 位偏移 2、位宽 1 对得上，需要配成 clk_i2s。

clk_i2sout 到底是什么？RK3399 有三路 I2S，其中 I2S2 内部接 HDMI/DP，能对外的是 I2S0 和 I2S1，而 MCLK 只有一路，所以只有一个能占用。clk_i2sout 就是这条 MCLK 信号线的时钟——这是素材作者的推断，不是 datasheet 明确结论。

一个 dts 写法上的坑 #

compatible = "rockchip,rt5651" 和驱动 of_match 的 "realtek,rt5651" 不一致，副作用是：如果把 i2c_device_id 那张表删掉、只留 of_match，probe 就永远不会被调用。

反过来，把 dts 改成 compatible = "realtek,rt5651"，type 就变成 "rt5651"，id_table 依然能匹配上。两条路都能通：

dts compatible 匹配路径 需要动驱动吗
"rockchip,rt5651" 仅 id_table 不用
"realtek,rt5651" of_match + id_table 都能命中 不用

推荐第二种。理由：走 of_match 语义上更干净，of_node 关联更明确。虽然 i2c_client 的 of_node 是在 of_i2c_get_board_info 里一起设的、跟匹配走哪条路无关，rt5651_apply_properties 读私有属性也不受影响，但按 of_match 匹配的驱动才是设备树平台的标准写法。

播放速度不对 时钟源 读 0x73、0x80，确认分频档位和 MCLK 频率对得上
高音刺耳 / 噪声大 时钟不匹配 BCLK 和 MCLK 的比例算错，改 MDIV 或 pre_div
音量很大但破音 数字音量削顶 DAC1 Playback Volume 降到 0dB 附近，用模拟音量补
只有一边声道 通路或接线 查 L/R 两个控件的值，检查 DACDAT 接线
耳机有声、喇叭没声 LOUT 通路 查 OUTVOL L/R 和 LOUT L/R Playback 两个 switch
录音全静音 麦克风偏置 读 0x63 位[13]，PWR_MB 是 0 说明 MICBIAS 没开
录音只有底噪 mux 选错 查 Stereo1 ADC L1 source 是不是 ADC 而不是 DD MIX
插拔耳机没反应 中断 dmesg 里那条 IRQ 0: -22，回 dts 补中断
播放卡顿 / xrun buffer 太小 调大 period_size，或降低采样率
系统挂起后无声音 resume 未同步缓存 看 rt5651_resume 有没有调 regcache_sync

最后一条值得展开：挂起时 regmap 缓存和芯片实际寄存器会脱节，resume 必须把缓存重新同步下去。rt5651_resume 的实现在素材里没给，未验证它是否调了 regcache_sync。遇到「挂起一次后就没声音」，第一个要看的就是这个。

通用定位思路 #

按「电 → 时钟 → 数据 → 通路 → 混音」五层往下走：

  1. 电：0x63 的 PWR_VREF1/PWR_MB/PWR_BG/PWR_VREF2 是否都为 1。为 0 说明 bias 没上去，什么都不会有声；
  2. 时钟：0x80 的时钟源、0x73 的分频档位，和 hw_params 里的 rate 对得上吗；
  3. 数据：0x70 的位[15]（主从）、位[1:0]（格式）和 SoC 侧 I2S_CKR 配的一致吗；
  4. 通路：DAPM 里从 AIF1RX 到 HPOR 是不是一串 On；
  5. 混音：OUT MIXR 的 5 个开关、HPOVOL R 的开关，逐个确认。

五层都过了还没声，问题就在硬件——接线、焊接、电源。

# 易错点 正确做法
1 拿 snd_soc_codec_driver 套 6.3 源码 4.20 起用 snd_soc_component_driver，注册接口是 devm_snd_soc_register_component
2 dts 写 rockchip,rt5651 却以为走 of_match 实际走 id_table；要修就统一 compatible 或在 of_match 加一条
3 只写了 codec 的 status = "okay" &i2c1 的 status 也必须是 okay
4 route 的 kcontrol 名写在 source 的控件里 control 名必须出现在 sink 的 kcontrol 数组
5 把 SOC_DAPM_SINGLE 换成 SOC_SINGLE mixer 输入必须用 DAPM 版，否则寄存器写了 DAPM 不知道
6 静音控件误用 SOC_DAPM_SINGLE 静音位是「1 静音」，要用 SOC_DAPM_SINGLE_AUTODISABLE
7 把 INF1 Switch 改成 IF1 Switch route 和控件名得一起改，单改一边就断链
8 混用 DD MIX/DD MIXL、ADC/ADCL Stereo1 和 Stereo2 的枚举名不一样，route 里必须严格对应
9 改 DAI 的 stream_name 却没改 AIF widget 的 sname 两者必须一致，靠 sname 匹配
10 期望 SND_SOC_DAIFMT_RIGHT_J 能用 ALC5651 没有右对齐编码，set_fmt 会 -EINVAL
11 以为 set_sysclk 选 PLL 就够了 还得 set_pll 算分频，两个函数各管一半
12 想关 PLL 只调 set_pll(0, 0) 还得让 set_sysclk 选回 MCLK，PWR_ANGL2[9] 才会清零
13 MCLK 不是 FS 的整数倍还硬配 rl6231_get_clk_info 返回负值，hw_params 直接 -EINVAL
14 update_bits 用 if (ret) 判成败 返回 1 = 变了，0 = 没变（成功），负数 = 失败
15 以为 regmap_register_patch 只写一次 它记进 map->patch，每次 regcache_sync 都重放
16 probe 里依赖 DAPM 通路已建好 probe 在 snd_soc_dapm_add_routes 之前执行
17 在 i2c_probe 里做 DAPM 相关寄存器配置 那是 component->probe（rt5651_probe）的活儿
18 忘记 force_bias_level(OFF) 首次上电就不会走完整 OFF → STANDBY 路径
19 STANDBY 里先切慢速 VREF 再上电 顺序相反环路会振荡，必须上电 → 延时 → 切慢速
20 OFF 分支清了 LDO 电压位 用 ~RT5651_PWR_LDO_DVO_MASK 把 LDO 电压位排除
21 以为 IRQF_NO_AUTOEN 申请完就能响 必须显式 enable_irq，在 rt5651_enable_jack_detect 末尾
22 看到 Failed to reguest IRQ 0: -22 以为坏了 只影响插拔检测，放音不受影响
23 把 reguest 这类源码拼写当自己的笔误 内核源码里就是这样，reguest 是原样的打印字符串
24 按 datasheet 的 192kHz 去配 rates 驱动只放了 8k~96k，放开要同时改分频计算
25 拿 MX-BB 切换就去改寄存器 自动切换前必须先建好 DAC→HP 和 DAC→LOUT 两条通路
26 以为 HPO MIX HPVOL Switch 左右各一位 左右声道共用 HPO_MIXER 的 bit13
27 查无声时盯着 DAC MIXR 找寄存器 那是 SND_SOC_NOPM，电源要看 Stero1/2 DAC Power
28 rt5651_i2c_driver_init 写成别的名字 module_driver 用 ## 拼名，实际一定是 rt5651_i2c_driver_init
29 把 RT5651_GLB_CLK 当地址 0x84 是 0x80，0x84 是另一颗寄存器
30 Stereo2 的 mux 枚举以为在 STO2_ADC_MIXER 全定义在 STO1_ADC_MIXER 上，位偏移不同
