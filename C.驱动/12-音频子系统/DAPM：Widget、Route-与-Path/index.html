一、DAPM 要解决什么：音频通路的按需供电 #

先把结论放出来：DAPM 管的是「这会儿到底哪些音频部件需要通电」，手段是给每个部件配一个电源位，再根据它是否落在一条走通的通路上决定这个位置的取值。

在这套机制之前，音频子系统手里的工具是 kcontrol。它能做的事有限，缺口有五条：

  • 一个 kcontrol 只描述自己，描述不了它和别的 kcontrol 之间的连接关系；
  • kcontrol 没有电源管理，寄存器里的位置了就是置了，没人回收；
  • 没有时间维度的事件处理，播放、停止、上电、下电这些时刻无法挂钩子；
  • 防 pop 声要靠应用层自己关心上下电顺序，这个活根本不该给应用；
  • 一条通路失效以后，没有机制把这条路上的 kcontrol 自动关掉。

DAPM 就是补这五条的。补法是把 kcontrol 加壳：

  • 给它加图结构，让部件之间能表达「我连着谁」；
  • 给它加电源位，让上下电有寄存器落地；
  • 给它加事件回调，让 PMU/PMD 这些时刻能插业务逻辑；
  • 给它加全局扫描与排序，让顺序由框架统一决定。

对用户空间来说这套东西是全透明的。所有电源切换都在 ASoC 核心里做完，应用不用改一行代码、不用重新编译。

再说它和其它电源管理的关系。DAPM 不挂在内核通用 PM 框架下面跑，它是 ASoC 自己的一套运行时电源策略，因此可以和平共存：系统休眠走的是 suspend/resume 那条路，widget 上留了 ignore_suspend 位来表态「挂起期间别动我」。

范围上，DAPM 横跨 codec 内部的电源模块和 machine 级别的外设供电（耳机、喇叭、麦克风偏置、外部 regulator、外部时钟），这也是后面要引入「域」的原因。

二、音频通路的有向图模型 #

把音频硬件抽象成一张图，DAPM 的所有代码都在伺候这张图。

三个角色分工明确：

概念 结构体 在图里的身份 一句话职责
Widget struct snd_soc_dapm_widget 节点 表示一个音频部件，带电源位、带 kcontrol、带事件
Route struct snd_soc_dapm_route 连线的声明 驱动里写死的三元组：谁连谁、用哪个控制位控通断
Path struct snd_soc_dapm_path 连线的实例 运行时由 route 生成，记录这条边此刻通不通

方向只有两个，用 enum snd_soc_dapm_direction 表示，取值就是 0 和 1，跟数组下标对齐，很多宏直接拿它当索引：

  • SND_SOC_DAPM_DIR_IN = 0，从 source 指向当前 widget 的那条边；
  • SND_SOC_DAPM_DIR_OUT = 1，从当前 widget 指向 sink 的那条边。

信号从 source 流向 sink。一条完整的信号通路长这样：

text
起始端 widget  -->  path（输入端）  -->  path（输出端）  -->  目标端 widget
    source              edges[0]                             sink

这张图的规模在真实驱动里不小。RK3399 上 rk3399-gru 一类板子的 rt5651 codec，widget 数量在几十个量级，route 表动辄上百条；WM8960 的 route 表在 sound/soc/codecs/wm8960.c 里有几十条（第 3714 行起的 audio_paths[] 就是摘出来的播放部分）。

图有个重要性质：连线是声明的，通断是运行时的。audio_paths[] 里写了 { "Left Output Mixer", "PCM Playback Switch", "Left DAC" }，这不代表这条路永远是通的；通不通取决于 PCM Playback Switch 这个 kcontrol 背后的寄存器位此刻是 1 还是 0，这个值存在 path->connect 里。

三、Widget：图上的一个节点 #

Widget 的定义原话是：具备路径和电源管理能力的 kcontrol。可以理解为 kcontrol 的升级封装，指向的仍然是音频系统里某个部件——Mixer、Mux、DAC、ADC、Input 之类。

它比 kcontrol 多出来的能力：能跟相邻 widget 建立动态连接关系，能被 DAPM 统一上电下电。

结构体定义在 include/sound/soc-dapm.h，字段一个不落列出来：

c
/* dapm widget */
struct snd_soc_dapm_widget {
        enum snd_soc_dapm_type id;
        const char *name;                       /* widget name */
        const char *sname;                      /* stream name */
        struct list_head list;
        struct snd_soc_dapm_context *dapm;

        void *priv;                             /* widget specific data */
        struct regulator *regulator;            /* attached regulator */
        struct pinctrl *pinctrl;                /* attached pinctrl */

        /* dapm control */
        int reg;                                /* negative reg = no direct dapm */
        unsigned char shift;                    /* bits to shift */
        unsigned int mask;                      /* non-shifted mask */
        unsigned int on_val;                    /* on state value */
        unsigned int off_val;                   /* off state value */
        unsigned char power:1;                  /* block power status */
        unsigned char active:1;                 /* active stream on DAC, ADC's */
        unsigned char connected:1;              /* connected codec pin */
        unsigned char new:1;                    /* cnew complete */
        unsigned char force:1;                  /* force state */
        unsigned char ignore_suspend:1;         /* kept enabled over suspend */
        unsigned char new_power:1;              /* power from this run */
        unsigned char power_checked:1;          /* power checked this run */
        unsigned char is_supply:1;              /* Widget is a supply type widget */
        unsigned char is_ep:2;                  /* Widget is a endpoint type widget */
        int subseq;                             /* sort within widget type */

        int (*power_check)(struct snd_soc_dapm_widget *w);

        /* external events */
        unsigned short event_flags;             /* flags to specify event types */
        int (*event)(struct snd_soc_dapm_widget*, struct snd_kcontrol *, int);

        /* kcontrols that relate to this widget */
        int num_kcontrols;
        const struct snd_kcontrol_new *kcontrol_news;
        struct snd_kcontrol **kcontrols;
        struct snd_soc_dobj dobj;

        /* widget input and output edges */
        struct list_head edges[2];

        /* used during DAPM updates */
        struct list_head work_list;
        struct list_head power_list;
        struct list_head dirty;
        int endpoints[2];

        struct clk *clk;

        int channel;
};

六个 list 头不要混，它们各自挂在不同链表上，用错一个就是内存踩踏：

  • list：挂到 card->widgets，全局遍历靠它；
  • edges[2]：挂 path 的 list_node[dir]，这是图的邻接表；
  • work_list：遍历时的临时节点（is_connected_ep() 的完整路径链表、dapm_widget_invalidate_paths() 的工作链表都复用它）；
  • power_list：挂进 up_list / down_list / pending 这些电源队列；
  • dirty：挂进 card->dapm_dirty。

注意 work_list 是复用的。同一时刻两套遍历都在跑就会互相拆链，这也是 DAPM 内部全程要持 card->dapm_mutex 的原因之一。

枚举注释里直接给了各类型的英文定义，摘几条容易看混的：

  • Mixer：几路模拟信号合成一路；
  • Mux：多路输入里选一路输出，本质是模拟开关；
  • Demux：反过来，一路输入分发到多路输出中的一路；
  • PGA：可编程增益放大器或衰减器；
  • Siggen：信号发生器，虚拟引脚，本身不耗电。

五、Widget 的关键字段 #

字段虽多，真正决定行为的就十几个。按「改动它就改行为」的标准挑出来：

字段 类型 作用 填错会怎样
id enum snd_soc_dapm_type 类型，决定 power_check、is_ep、排序序号 派生属性全错，且不报错
name const char * 在 card->widgets 里被 route 按名匹配 route 报 Failed to add route
sname const char * stream 名，ASoC 靠它把 dai widget 和 codec stream widget 连起来 播放时路径不通，codec 侧不上电
dapm struct snd_soc_dapm_context * 所属域，决定偏置电压级别 偏置电压在错误的域上切
priv void * 私有数据，dai_in/dai_out 存 snd_soc_dai *，dai_link 存 snd_soc_pcm_runtime * dapm_new_dai_link() 拿错指针
reg int 电源位所在寄存器；负值表示没有直接 DAPM 控制 填 -1 却指望框架写寄存器
shift unsigned char 电源位偏移 写到隔壁位
mask unsigned int 未移位的掩码 移位后再与，取到错误值
on_val / off_val unsigned int 开/关写入值 反逻辑，上电变下电
power 位域 当前实际电源状态 只由 dapm_seq_run_coalesced() 写
new_power 位域 本轮扫描得出的目标状态 只由 dapm_widget_power_check() 写
power_checked 位域 本轮是否已算过 不清会导致沿用上一轮结果
active 位域 流是否激活，只有 dac/adc/aif/dai 有意义 停止后 stream inactive 却仍占着电源
connected 位域 widget 自身的虚拟开关 与 path->connect 是两回事
force 位域 强制上电 泄漏功耗，下电时记得清
ignore_suspend 位域 挂起期间保持 挂起时被下电
is_supply 位域 供给类型 遍历会在它这里截断
is_ep 2 位 端点身份（EP_SOURCE/EP_SINK/两者/都不是） 完整路径统计出错，全部不上电
subseq int 同类型内的次级排序 同组内顺序不稳定
power_check 函数指针 计算目标电源状态 由 id 定，不要手填
event_flags unsigned short 关心哪些事件 事件发了也不回调
event 函数指针 事件处理 —
num_kcontrols / kcontrol_news int / 数组 kcontrol 模板 与 route 的 control 名对不上就建不出 kcontrol
endpoints[2] int[2] 到两类端点的完整路径计数缓存，-1 表示未算 缓存不失效会用到过期值

几个容易读错的点单独说。

connected 和 path 的连接状态没有关系。它是 widget 内部的一个虚拟开关，决定这个节点本身可不可用。判断 widget 是否在 complete path 上时，要求路径上的 widget 必须是连接状态。默认新创建的 widget 都是 connected = 1。

new_power 和 power 是两个时刻的值。dapm_reset() 里执行 w->new_power = w->power;，先对齐；然后 dapm_power_one_widget() 算出新的 new_power，如果跟 power 一样就直接返回；不一样才进队列，最后在 dapm_seq_run_coalesced() 里执行 w->power = w->new_power;。

endpoints[] 是缓存不是事实源。元素 0 存「向前遍历到 EP_SOURCE 端点的路径条数」，元素 1 存「向后遍历到 EP_SINK 端点的路径条数」，-1 表示还没算过。任何会改变连通性的操作都必须让它失效，失效函数是 dapm_widget_invalidate_paths()。

mask 是未移位掩码，这个坑踩的人最多。看 debugfs 输出里打印的是 w->mask << w->shift（" - R%d(0x%x) mask 0x%x"，第 1849 行），移位在打印时才做；驱动里填 mask 的时候不要自己先左移。

is_ep 是 2 位宽，因为它要能同时表达两个方向。line 类型的 widget 可以两个位同时置上：有输入方向的边就是源端点，有输出方向的边就是目的端点。

六、Route：节点之间的连线 #

Route 就是把「完整路径」描述成一个静态表项。定义在 include/sound/soc-dapm.h：

c
/*
 * DAPM audio route definition.
 *
 * Defines an audio route originating at source via control and finishing
 * at sink.
 */
struct snd_soc_dapm_route {
        const char *sink;
        const char *control;
        const char *source;

        /* Note: currently only supported for links where source is a supply */
        int (*connected)(struct snd_soc_dapm_widget *source,
                         struct snd_soc_dapm_widget *sink);

        struct snd_soc_dobj dobj;
};

四个字段的含义：

  • source：起始端 widget 的名字；
  • sink：目标端 widget 的名字；
  • control：控制这条连接通断的 kcontrol 名字，NULL 表示静态直连；
  • connected：自定义连接检查回调，只对 source 是 supply 的场景放行。

注意结构体里的声明顺序是 sink、control、source，但用位置初始化写 route 表的时候，三元组的书写顺序是 { "sink 名", "control 名", "source 名" }。写表的时候建议直接对照结构体顺序，别按「源在前」的直觉来，反了会得到一个方向相反的 path，日志里还会只剩一条 Failed to add route。

这就是那位素材作者说的「route 你就当 path 理解」的由来：route 是声明，path 是实例。所有定义好的 route 最终都要注册进 DAPM，框架按名字找出两端 widget，动态生成 snd_soc_dapm_path，把链表和指针接对。

版本演进。6.3 里 sink/control/source 三个都是 const char *，route 表靠位置初始化。7.x 上游对 route 做过一轮调整，出现过 snd_soc_dapm_route_parse 一类的解析辅助路径，具体形态和首发版本号我没有逐版本对照，标未验证。老驱动代码迁移到新内核时，先 diff 一下 include/sound/soc-dapm.h 里这两个结构体的当前定义再动手。

图丢失说明：素材这里原本配了一张「widget A 分三条路径到 B/C/D」的示意图，抓取时丢了。用下面的 ASCII 图替代，后面第七章统计路径条数时直接对着它看：

text
        +--> [B] --> [C(EP_SINK)]       路径 1，走通，con + 1
[A] ----+--> [D]                        路径 2，到 D 就断了，con 不变
        +--> [E] --> [F(EP_SINK)]       路径 3，走通，con + 1

从 A 出发统计输出端点，结果是 2：只有路径 1 和路径 3 各摸到一个 EP_SINK 端点，路径 2 走到 D 之后没有下一个连接，不计数。

七、音频通路的三种域 #

域这个词在 DAPM 里有两层含义，别混。一是偏置电压域（snd_soc_dapm_context），二是widget 按电源特性分组的辅助宏域（codec / platform / path / stream）。两层说的是同一件事的两个视角：一组 widget 共享同一套供电策略。

先说第二层，因为写驱动的人先碰到它。DAPM 为不同类型 widget 提供的辅助定义宏，按电源所在位置分成四个宏域：

宏域 典型宏 宏内部 reg 上电手段 定义在哪一层
codec 域 SND_SOC_DAPM_VMID 不设（无寄存器位） event 回调或 codec probe codec
platform/machine 域 SIGGEN/SINK/INPUT/OUTPUT/MIC/HP/SPK/LINE 一律 SND_SOC_NOPM event 回调 machine 为主，引脚类在 codec
path 域 PGA/OUT_DRV/MIXER/MIXER_NAMED_CTL/SWITCH/MUX/DEMUX/MICBIAS 必须给 wreg/wshift 框架写寄存器 codec
stream 域 AIF_IN/AIF_OUT/DAC/ADC 必须给 wreg/wshift 框架写寄存器 codec

codec 域只有一个宏，管 VREF/VMID 这类提供参考电压的部件：

c
/* codec domain */
#define SND_SOC_DAPM_VMID(wname) \
{       .id = snd_soc_dapm_vmid, .name = wname, .kcontrol_news = NULL, \
        .num_kcontrols = 0}

第一层的偏置电压域用 struct snd_soc_dapm_context 表示，定义在 include/sound/soc-dapm.h：

        enum snd_soc_bias_level bias_level;

        /* bit field */
        unsigned int idle_bias_off:1;           /* Use BIAS_OFF instead of STANDBY */
        unsigned int suspend_bias_off:1;        /* Use BIAS_OFF in suspend if the DAPM is idle */

        struct snd_soc_component *component;    /* parent component */
        struct snd_soc_card *card;              /* parent card */

        enum snd_soc_bias_level target_bias_level;
        struct list_head list;  // 链表节点，用于添加到声卡card的dapm_list链表中

bias_level 的取值范围就四个，从低到高：

  • SND_SOC_BIAS_OFF：全关，最省电；
  • SND_SOC_BIAS_STANDBY：待机，参考电压在，模拟通路没开；
  • SND_SOC_BIAS_PREPARE：过渡态，准备进 ON 或者刚从 ON 出来；
  • SND_SOC_BIAS_ON：全开，有音频在跑。

bias_level 是当前值，target_bias_level 是本轮扫描算出的目标值，这两个字段在 dapm_power_widgets() 里成对出现，是本轮状态机的核心。

wcache_sink / wcache_source 是 route 注册时的查找缓存，后面第十章会讲它的深度只有 2。

域怎么划分？按功能和偏置电压级别切：

  • codec 里的 widget 归一个 context；
  • platform 的 widget 归一个 context；
  • 整个声卡层面的 widget 再归一个 context。

这么切的理由很实在：同一域的 widget 共享同一个偏置电压级别，切电压时按域批量切，不用逐个 widget 算。

八、Path：从源到宿的走通 #

Widget 之间能互连，那用什么连？Path，相当于电路板上的一根跳线，把上一个 widget 的输出端接到下一个 widget 的输入端。

结构体定义在 include/sound/soc-dapm.h：

c
/* dapm audio path between two widgets */
struct snd_soc_dapm_path {
        const char *name;

        /*
         * source (input) and sink (output) widgets
         * The union is for convience, since it is a lot nicer to type
         * p->source, rather than p->node[SND_SOC_DAPM_DIR_IN]
         */
        union {
                struct {
                        struct snd_soc_dapm_widget *source;  // 输入端widget
                        struct snd_soc_dapm_widget *sink;    // 输出端widget
                };
                struct snd_soc_dapm_widget *node[2];
        };

        /* status */
        u32 connect:1;          /* source and sink widgets are connected */
        u32 walking:1;          /* path is in the process of being walked */
        u32 weak:1;             /* path ignored for power management */
        u32 is_supply:1;        /* At least one of the connected widgets is a supply */

        int (*connected)(struct snd_soc_dapm_widget *source,
                         struct snd_soc_dapm_widget *sink);

        struct list_head list_node[2];   // 用于构建链表节点
        struct list_head list_kcontrol;
        struct list_head list;      // 用于构建链表节点，添加到card->paths链表中
};

source 和 node[0] 是同一块内存，sink 和 node[1] 也是。联合体的存在纯粹为了让 p->source 这种写法比 p->node[SND_SOC_DAPM_DIR_IN] 好敲。这也意味着 node[dir] 可以直接用方向当索引取，遍历代码大量这么干。

四条状态位：

  • connect：源和宿连没连上。中间有 kcontrol 控通断时，它反映的就是这个 kcontrol 的状态；两个 widget 直连时恒为 1。
  • walking：遍历进行中的标志，防环。递归进入时置 1，出栈时清 0；如果走进一条 walking=1 的边，说明图里有环，直接按「连通」处理并返回。
  • weak：这条边不参与电源管理，遍历时跳过。
  • is_supply：两端至少有一端是供给类型。

三个 list 头对应三处挂载点，list_node[dir] 挂在 widget 的 edges[dir] 上，这就是邻接表的物理形态：

  • widget 输出端的 path 通过 list_node[0] 挂在 w->edges[0]；
  • widget 输入端的 path 通过 list_node[1] 挂在 w->edges[1]；
  • list 把所有 path 挂到 card->paths。

想自定义连接判断逻辑，就填 connected 回调，框架会在判断连通性时先问它一遍。

换个角度把完整路径再看一遍：

text
起始端 widget --> path 的输入端 --> path 的输出端 --> 目标端 widget

那什么叫「完整」？必须有起点和终点。落在起点和终点上的 widget 叫端点 widget，身份由 is_ep 表达：

widget 类型 端点身份
snd_soc_dapm_input EP_SOURCE（输入引脚是信号源）
snd_soc_dapm_output EP_SINK（输出引脚是信号宿）
snd_soc_dapm_mic EP_SOURCE
snd_soc_dapm_hp EP_SINK
snd_soc_dapm_spk EP_SINK
snd_soc_dapm_line 做输入就是 EP_SOURCE，做输出就是 EP_SINK
snd_soc_dapm_dai_in STREAM_START 时设成 EP_SOURCE
snd_soc_dapm_dai_out STREAM_START 时设成 EP_SINK

最后两行的动态设定在 soc_dapm_dai_stream_event() 里做，参考 snd_soc_dapm_dai_stream_event() 这条线。

由此推出一个 widget 能上电的前提：它落在一条完整路径上，即向前或向后都能摸到端点 widget，且路径上的 widget（connected）和 path（connect）都是连通的。complete path 跟 widget 当前的电源状态无关——这是纯拓扑判断，跟电没关系。

两个内部函数负责数路径条数：

  • is_connected_output_ep()：从当前 widget 向后遍历（含自己），返回摸到 EP_SINK 端点的路径条数；
  • is_connected_input_ep()：从当前 widget 向前遍历（含自己），返回摸到 EP_SOURCE 端点的路径条数。

两者都定义在 sound/soc/soc-dapm.c，核心是共用的内联函数 is_connected_ep()：

c
/*
 * Common implementation for is_connected_output_ep() and
 * is_connected_input_ep(). The function is inlined since the combined size of
 * the two specialized functions is only marginally larger then the size of the
 * generic function and at the same time the fast path of the specialized
 * functions is significantly smaller than the generic function.
 */
static __always_inline int is_connected_ep(struct snd_soc_dapm_widget *widget,
        struct list_head *list, enum snd_soc_dapm_direction dir,
        int (*fn)(struct snd_soc_dapm_widget *, struct list_head *,
                  bool (*custom_stop_condition)(struct snd_soc_dapm_widget *,
                                                enum snd_soc_dapm_direction)),
        bool (*custom_stop_condition)(struct snd_soc_dapm_widget *,
                                      enum snd_soc_dapm_direction))
{
        enum snd_soc_dapm_direction rdir = SND_SOC_DAPM_DIR_REVERSE(dir);
        struct snd_soc_dapm_path *path;
        int con = 0;

        if (widget->endpoints[dir] >= 0)     // 已经统计过，直接用缓存
                return widget->endpoints[dir];

        DAPM_UPDATE_STAT(widget, path_checks);

        /* do we need to add this widget to the list ? */
        if (list)
                list_add_tail(&widget->work_list, list);
        if (custom_stop_condition && custom_stop_condition(widget, dir)) {
                list = NULL;
                custom_stop_condition = NULL;
        }

        if ((widget->is_ep & SND_SOC_DAPM_DIR_TO_EP(dir)) && widget->connected) {
                widget->endpoints[dir] = snd_soc_dapm_suspend_check(widget);
                return widget->endpoints[dir];
        }

        snd_soc_dapm_widget_for_each_path(widget, rdir, path) {
                DAPM_UPDATE_STAT(widget, neighbour_checks);

                if (path->weak || path->is_supply)   // 供给类型的边不参与
                        continue;

                if (path->walking)   // 有环，直接按连通返回
                        return 1;

                trace_snd_soc_dapm_path(widget, dir, path);

                if (path->connect) {
                        path->walking = 1;
                        con += fn(path->node[dir], list, custom_stop_condition);
                        path->walking = 0;
                }
        }

        widget->endpoints[dir] = con;

        return con;
}

外层两个壳子只是把方向和递归函数自己传进去：

逻辑要点四个：

  1. 递归到底。摸到 is_ep 匹配且 connected=1 的 widget 就停，返回值默认 1（snd_soc_dapm_suspend_check() 默认返回 1，除非 widget 被标记成「挂起期间必须保持」一类的特例）。
  2. 结果缓存进 widget->endpoints[dir]，下次进来直接返回。这就是第 5 章说的那个缓存。
  3. 遇到 weak 或 is_supply 的边直接 continue，供给类 widget 会在遍历上被截断——这也是 snd_soc_dapm_supply、regulator_supply、pinctrl、clock_supply、kcontrol 这五种 widget 之后的路不再扫的原因。
  4. path->walking 防环，撞到就 return 1。

拿第 6 章那张 ASCII 图验证一下：从 A 出发，路径 1 摸到 C(EP_SINK) 得 1，路径 2 到 D 没有后续边贡献 0，路径 3 摸到 F(EP_SINK) 得 1，合计 con = 2。执行完毕后，路径上每个 widget 的 endpoints[1] 都会被写成这个计数（各自动算一次，值未必相同）。

这个缓存有代价：图的连通性一变，缓存就是脏的。所以 __snd_soc_dapm_set_pin()、soc_dapm_dai_stream_event()、snd_soc_dapm_add_path() 这些会改连通性的地方，都得配套调 dapm_widget_invalidate_input_paths() / dapm_widget_invalidate_output_paths()，把沿途 widget 的 endpoints[dir] 清回 -1。

九、dapm_widget 的注册 #

驱动里的 widget 数组只是模板。真正注册要过一道 snd_soc_dapm_new_controls()，它给每个模板重新申请内存、拷贝内容、补前缀，挂进 card->widgets。

整个注册链是三层：

text
snd_soc_dapm_new_controls()          拿锁，遍历模板数组
    -> snd_soc_dapm_new_control_unlocked()   真正的初始化，一个 widget 一份
        -> dapm_cnew_widget()        分配内存 + 拷贝模板

顶层函数：

c
int snd_soc_dapm_new_controls(struct snd_soc_dapm_context *dapm,  // dapm域
        const struct snd_soc_dapm_widget *widget, // widget数组
        int num)         // widget数量
{
        int i;
        int ret = 0;

        mutex_lock_nested(&dapm->card->dapm_mutex, SND_SOC_DAPM_CLASS_INIT);  // 获取互斥锁
        for (i = 0; i < num; i++) {
                struct snd_soc_dapm_widget *w = snd_soc_dapm_new_control_unlocked(dapm, widget);
                if (IS_ERR(w)) {
                        ret = PTR_ERR(w);
                        break;
                }
                widget++; // 后移1
        }
        mutex_unlock(&dapm->card->dapm_mutex);  // 释放互斥锁
        return ret;
}

三个参数：域、模板数组、数组长度。函数本身没有业务逻辑，就是拿锁、for 循环、放锁。真正的活在 snd_soc_dapm_new_control_unlocked() 里，它长，是因为要按 id 分几十种情况。

c
struct snd_soc_dapm_widget *
snd_soc_dapm_new_control_unlocked(struct snd_soc_dapm_context *dapm,
                         const struct snd_soc_dapm_widget *widget)
{
        enum snd_soc_dapm_direction dir;
        struct snd_soc_dapm_widget *w;
        const char *prefix;
        int ret = -ENOMEM;

        if ((w = dapm_cnew_widget(widget)) == NULL)  // 重新分配内存并拷贝模板
                goto cnew_failed;

        prefix = soc_dapm_prefix(dapm);          // component 存在则返回 name_prefix
        if (prefix)                              // 名称前加前缀
                w->name = kasprintf(GFP_KERNEL, "%s %s", prefix, widget->name);
        else
                w->name = kstrdup_const(widget->name, GFP_KERNEL);
        if (!w->name)
                goto name_failed;

        switch (w->id) {  // 第一轮：按类型获取外部资源
        case snd_soc_dapm_regulator_supply:
                w->regulator = devm_regulator_get(dapm->dev, widget->name);
                if (IS_ERR(w->regulator)) {
                        ret = PTR_ERR(w->regulator);
                        goto request_failed;
                }

                if (w->on_val & SND_SOC_DAPM_REGULATOR_BYPASS) {
                        ret = regulator_allow_bypass(w->regulator, true);
                        if (ret != 0)
                                dev_warn(dapm->dev,
                                         "ASoC: Failed to bypass %s: %d\n",
                                         w->name, ret);
                }
                break;
        case snd_soc_dapm_pinctrl:
                w->pinctrl = devm_pinctrl_get(dapm->dev);
                if (IS_ERR(w->pinctrl)) {
                        ret = PTR_ERR(w->pinctrl);
                        goto request_failed;
                }

                /* set to sleep_state when initializing */
                dapm_pinctrl_event(w, NULL, SND_SOC_DAPM_POST_PMD);
                break;
        case snd_soc_dapm_clock_supply:
                w->clk = devm_clk_get(dapm->dev, w->name);
                if (IS_ERR(w->clk)) {
                        ret = PTR_ERR(w->clk);
                        goto request_failed;
                }
                break;
        default:
                break;
        }

        switch (w->id) {  // 第二轮：按类型设置 is_ep 与 power_check
        case snd_soc_dapm_mic:
                w->is_ep = SND_SOC_DAPM_EP_SOURCE;
                w->power_check = dapm_generic_check_power;
                break;
        case snd_soc_dapm_input:
                if (!dapm->card->fully_routed)
                        w->is_ep = SND_SOC_DAPM_EP_SOURCE;
                w->power_check = dapm_generic_check_power;
                break;
        case snd_soc_dapm_spk:
        case snd_soc_dapm_hp:
                w->is_ep = SND_SOC_DAPM_EP_SINK;
                w->power_check = dapm_generic_check_power;
                break;
        case snd_soc_dapm_output:
                if (!dapm->card->fully_routed)
                        w->is_ep = SND_SOC_DAPM_EP_SINK;
                w->power_check = dapm_generic_check_power;
                break;
        case snd_soc_dapm_vmid:
        case snd_soc_dapm_siggen:
                w->is_ep = SND_SOC_DAPM_EP_SOURCE;
                w->power_check = dapm_always_on_check_power;
                break;
        case snd_soc_dapm_sink:
                w->is_ep = SND_SOC_DAPM_EP_SINK;
                w->power_check = dapm_always_on_check_power;
                break;

        case snd_soc_dapm_mux:
        case snd_soc_dapm_demux:
        case snd_soc_dapm_switch:
        case snd_soc_dapm_mixer:
        case snd_soc_dapm_mixer_named_ctl:
        case snd_soc_dapm_adc:
        case snd_soc_dapm_aif_out:
        case snd_soc_dapm_dac:
        case snd_soc_dapm_aif_in:
        case snd_soc_dapm_pga:
        case snd_soc_dapm_buffer:
        case snd_soc_dapm_scheduler:
        case snd_soc_dapm_effect:
        case snd_soc_dapm_src:
        case snd_soc_dapm_asrc:
        case snd_soc_dapm_encoder:
        case snd_soc_dapm_decoder:
        case snd_soc_dapm_out_drv:
        case snd_soc_dapm_micbias:
        case snd_soc_dapm_line:
        case snd_soc_dapm_dai_link:
        case snd_soc_dapm_dai_out:
        case snd_soc_dapm_dai_in:
                w->power_check = dapm_generic_check_power;
                break;
        case snd_soc_dapm_supply:
        case snd_soc_dapm_regulator_supply:
        case snd_soc_dapm_pinctrl:
        case snd_soc_dapm_clock_supply:
        case snd_soc_dapm_kcontrol:
                w->is_supply = 1;
                w->power_check = dapm_supply_check_power;
                break;
        default:
                w->power_check = dapm_always_on_check_power;
                break;
        }

        w->dapm = dapm; // 设置所属的 dapm 域
        INIT_LIST_HEAD(&w->list);
        INIT_LIST_HEAD(&w->dirty);
        /* see for_each_card_widgets */
        list_add_tail(&w->list, &dapm->card->widgets);  // 挂进 card->widgets

        snd_soc_dapm_for_each_direction(dir) {  // 初始化输入/输出边链表
                INIT_LIST_HEAD(&w->edges[dir]);
                w->endpoints[dir] = -1;
        }

        /* machine layer sets up unconnected pins and insertions */
        w->connected = 1;
        return w;

request_failed:
        dev_err_probe(dapm->dev, ret, "ASoC: Failed to request %s\n",
                      w->name);
        kfree_const(w->name);
name_failed:
        kfree_const(w->sname);
        kfree(w);
cnew_failed:
        return ERR_PTR(ret);
}

流程拆成七步：

  1. dapm_cnew_widget() 按模板重开一块内存并拷贝。模板是 const 的，每次都复制一份新的。
  2. 拼名字。soc_dapm_prefix() 返回 dapm->component->name_prefix，有就拼成 "prefix name"。两条 snd_soc_dapm 总线上的同名 codec，靠这个前缀区分 widget。
  3. 第一轮 switch：只处理需要拿外部资源的三种——regulator_supply 按名字取 regulator，pinctrl 取 pinctrl 并立刻切到 sleep 状态，clock_supply 按名字取 clock。devm_* 系列意味着失败时自动回收，不用手写 goto 清理。
  4. 第二轮 switch：设 is_ep 和 power_check。这是整个函数信息量最大的部分，第 4 章那张表就是从这抄的。
  5. 记 w->dapm。这一步决定 widget 归哪个域，后面偏置电压按域切。
  6. 初始化链表，list 和 dirty 各自 INIT_LIST_HEAD，然后把 list 挂到 card->widgets。
  7. endpoints[dir] = -1、connected = 1。注意 connected=1 是默认值，machine 层后续会按实际插接情况改它。

fully_routed 这个开关值得单独讲。input 和 output 两种类型的 is_ep 赋值外面套了 if (!dapm->card->fully_routed)。意思是：card 上声明了「route 表已经完整描述所有连接」时，引脚不再需要靠端点身份去兜底，身份交给 dapm_update_widget_flags() 动态算（第十章）。用 snd_soc_card_set_fully_routed() 之类的接口打开（6.3 里由 DMI/驱动显式设置），漏写 route 就会直接没声音，因为没人再帮你把引脚当端点看。

power_check 只有三个候选实现，各自的判断逻辑：

c
/* Generic check to see if a widget should be powered. */
static int dapm_generic_check_power(struct snd_soc_dapm_widget *w)
{
        int in, out;

        DAPM_UPDATE_STAT(w, power_checks);

        in = is_connected_input_ep(w, NULL, NULL);
        out = is_connected_output_ep(w, NULL, NULL);
        return out != 0 && in != 0;
}

向前数、向后数，两头都不为零才算在完整路径上——典型的中段节点判据。

c
/* Check to see if a power supply is needed */
static int dapm_supply_check_power(struct snd_soc_dapm_widget *w)
{
        struct snd_soc_dapm_path *path;

        DAPM_UPDATE_STAT(w, power_checks);

        /* Check if one of our outputs is connected */
        snd_soc_dapm_widget_for_each_sink_path(w, path) {
                DAPM_UPDATE_STAT(w, neighbour_checks);

                if (path->weak)
                        continue;

                if (path->connected &&
                    !path->connected(path->source, path->sink))
                        continue;

                if (dapm_widget_power_check(path->sink))
                        return 1;
        }

        return 0;
}

供给类走的是相反的逻辑：不看自己有没有端点，只看下游有没有人需要它。任意一个 sink 被判定要上电，自己就上电。这也是 is_supply 的边在完整路径统计里被跳过的原因——供给不是信号通路的一环，不能拿它凑完整路径。

剩下那个 dapm_always_on_check_power() 就是恒定返回 1，给 vmid/siggen/sink 和所有未列举的默认类型用。

widget 注册完之后还有一步：dai widget 的特殊创建。snd_soc_dapm_new_dai_widgets() 给一个 dai 造播放流和录音流两个 widget：

第二步：new_widgets 创建 kcontrol #

new_controls 只是把 widget 造好、挂上链表。要让 widget 之间具备连接能力，还得调 snd_soc_dapm_new_widgets()。这个函数的活是给 widget 造它包含的 dapm kcontrol——kcontrol 的状态一变，音频路径就变，路径一变就牵动电源。

名字确实容易搞混：new_controls 造 widget，new_widgets 造 kcontrol。素材作者的原话是「这两个函数名字应该换过来叫更好」，这话我同意。

c
int snd_soc_dapm_new_widgets(struct snd_soc_card *card)
{
        struct snd_soc_dapm_widget *w;
        unsigned int val;

        mutex_lock_nested(&card->dapm_mutex, SND_SOC_DAPM_CLASS_INIT);

        for_each_card_widgets(card, w)     // 遍历 card->widgets
        {
                if (w->new)
                        continue;

                if (w->num_kcontrols) {
                        w->kcontrols = kcalloc(w->num_kcontrols,
                                                sizeof(struct snd_kcontrol *),
                                                GFP_KERNEL);
                        if (!w->kcontrols) {
                                mutex_unlock(&card->dapm_mutex);
                                return -ENOMEM;
                        }
                }

                switch(w->id) {  // 按类型建 kcontrol
                case snd_soc_dapm_switch:
                case snd_soc_dapm_mixer:
                case snd_soc_dapm_mixer_named_ctl:
                        dapm_new_mixer(w);
                        break;
                case snd_soc_dapm_mux:
                case snd_soc_dapm_demux:
                        dapm_new_mux(w);
                        break;
                case snd_soc_dapm_pga:
                case snd_soc_dapm_effect:
                case snd_soc_dapm_out_drv:
                        dapm_new_pga(w);
                        break;
                case snd_soc_dapm_dai_link:
                        dapm_new_dai_link(w);
                        break;
                default:
                        break;
                }

                /* Read the initial power state from the device */
                if (w->reg >= 0) {  // 有寄存器才读初值
                        val = soc_dapm_read(w->dapm, w->reg);
                        val = val >> w->shift;
                        val &= w->mask;
                        if (val == w->on_val)
                                w->power = 1;
                }

                w->new = 1;   // 标记已实例化

                dapm_mark_dirty(w, "new widget");
                dapm_debugfs_add_widget(w);   // 在 debugfs 建同名文件
        }

        dapm_power_widgets(card, SND_SOC_DAPM_STREAM_NOP);
        mutex_unlock(&card->dapm_mutex);
        return 0;
}

六步：

  1. num_kcontrols 非零就按数量分配一个 struct snd_kcontrol * 数组，交给 w->kcontrols。此刻数组元素全是空指针，kcontrol 实体还没建。
  2. 按 id 分派到四个建 kcontrol 的函数：dapm_new_mixer()、dapm_new_mux()、dapm_new_pga()、dapm_new_dai_link()。
  3. reg >= 0 的 widget 读一次寄存器，取 shift、mask 后与 on_val 比对，决定初始 power。这一步让 DAPM 的认知和设备实际状态对齐。
  4. 置 new = 1，标记「这个 widget 已经实例化过」，下次进来就 continue。
  5. dapm_mark_dirty() 挂进 card->dapm_dirty，dapm_debugfs_add_widget() 在 debugfs 建一个同名只读文件。
  6. 最后调 dapm_power_widgets(card, SND_SOC_DAPM_STREAM_NOP) 统一处理脏表。

第 5 步的「攒起来统一处理」不是随意设计。两个原因：一是要控制上下电顺序，逐条处理就没人管顺序了；二是省寄存器读写，多个 widget 常常共用一个寄存器，攒起来能一次写完。

        }
}

!list_empty() 这个前置判断同时起去重和防重入的作用：已经在脏表里的 widget 不会被挂第二次，否则链表就成环了。

三种建 kcontrol 的路径，逐个看。

dapm_new_mixer() 是里面最复杂的一个，因为它要处理「一个 kcontrol 管多条边」和「多个 widget 共享同一个 kcontrol」两种情况：

c
static int dapm_new_mixer(struct snd_soc_dapm_widget *w)
{
        int i, ret;
        struct snd_soc_dapm_path *path;
        struct dapm_kcontrol_data *data;

        /* add kcontrol */
        for (i = 0; i < w->num_kcontrols; i++) {
                /* match name */
                snd_soc_dapm_widget_for_each_source_path(w, path) {  // 遍历 w->edges[1]
                        /* mixer/mux paths name must match control name */
                        if (path->name != (char *)w->kcontrol_news[i].name)
                                continue;

                        if (!w->kcontrols[i]) {
                                ret = dapm_create_or_share_kcontrol(w, i);
                                if (ret < 0)
                                        return ret;
                        }

                        dapm_kcontrol_add_path(w->kcontrols[i], path);

                        data = snd_kcontrol_chip(w->kcontrols[i]);
                        if (data->widget)      // 存在影子 widget
                                snd_soc_dapm_add_path(data->widget->dapm,
                                                      data->widget,
                                                      path->source,
                                                      NULL, NULL);
                }
        }

        return 0;
}

外层按 kcontrol 模板循环，内层遍历 widget 的所有输入边，用指针比较 path->name != w->kcontrol_news[i].name 来配对。注意是指针比不是字符串比——dapm_connect_mixer() 建 path 时直接 path->name = path->sink->kcontrol_news[i].name; 把模板里的指针赋过去了，两边指向同一块常量字符串，所以指针相等成立。这个前置条件在第十章会再提一次。

配对成功后四件事：没建过 kcontrol 就建一个；把这个 path 加进 kcontrol 的私有 path 链表；如果有影子 widget，就在影子 widget 和 path->source 之间再连一条边；最后返回。

dapm_create_or_share_kcontrol() 负责「共享还是新建」的判定：

c
static int dapm_create_or_share_kcontrol(struct snd_soc_dapm_widget *w,
        int kci)
{
        struct snd_soc_dapm_context *dapm = w->dapm;
        struct snd_card *card = dapm->card->snd_card;
        const char *prefix;
        size_t prefix_len;
        int shared;
        struct snd_kcontrol *kcontrol;
        bool wname_in_long_name, kcname_in_long_name;
        char *long_name = NULL;
        const char *name;
        int ret = 0;

        prefix = soc_dapm_prefix(dapm);
        if (prefix)
                prefix_len = strlen(prefix) + 1;
        else
                prefix_len = 0;

        shared = dapm_is_shared_kcontrol(dapm, w, &w->kcontrol_news[kci],
                                         &kcontrol);

        if (!kcontrol) {   // 没现成的，自己建
                if (shared) {
                        wname_in_long_name = false;
                        kcname_in_long_name = true;
                } else {
                        switch (w->id) {
                        case snd_soc_dapm_switch:
                        case snd_soc_dapm_mixer:
                        case snd_soc_dapm_pga:
                        case snd_soc_dapm_effect:
                        case snd_soc_dapm_out_drv:
                                wname_in_long_name = true;
                                kcname_in_long_name = true;
                                break;
                        case snd_soc_dapm_mixer_named_ctl:
                                wname_in_long_name = false;
                                kcname_in_long_name = true;
                                break;
                        case snd_soc_dapm_demux:
                        case snd_soc_dapm_mux:
                                wname_in_long_name = true;
                                kcname_in_long_name = false;
                                break;
                        default:
                                return -EINVAL;
                        }
                }

                if (wname_in_long_name && kcname_in_long_name) {
                        /*
                         * The control will get a prefix from the control
                         * creation process but we're also using the same
                         * prefix for widgets so cut the prefix off the
                         * front of the widget name.
                         */
                        long_name = kasprintf(GFP_KERNEL, "%s %s",
                                 w->name + prefix_len,
                                 w->kcontrol_news[kci].name);
                        if (long_name == NULL)
                                return -ENOMEM;

                        name = long_name;
                } else if (wname_in_long_name) {
                        long_name = NULL;
                        name = w->name + prefix_len;
                } else {
                        long_name = NULL;
                        name = w->kcontrol_news[kci].name;
                }

                kcontrol = snd_soc_cnew(&w->kcontrol_news[kci], NULL, name,
                                        prefix);
                if (!kcontrol) {
                        ret = -ENOMEM;
                        goto exit_free;
                }

                kcontrol->private_free = dapm_kcontrol_free;

                ret = dapm_kcontrol_data_alloc(w, kcontrol, name);
                if (ret) {
                        snd_ctl_free_one(kcontrol);
                        goto exit_free;
                }

                ret = snd_ctl_add(card, kcontrol);
                if (ret < 0) {
                        dev_err(dapm->dev,
                                "ASoC: failed to add widget %s dapm kcontrol %s: %d\n",
                                w->name, name, ret);
                        goto exit_free;
                }
        }

        ret = dapm_kcontrol_add_widget(kcontrol, w);
        if (ret == 0)
                w->kcontrols[kci] = kcontrol;

exit_free:
        kfree(long_name);

        return ret;
}

dapm_is_shared_kcontrol() 为了省内存，会去 card->widgets 里翻每个 widget 的 kcontrol_news 数组，看 &w->kcontrol_news[kci] 这个模板指针是不是已经出现过。出现过说明 kcontrol 在别的 widget 里已经建好了，直接把指针拿回来用；没出现过才走 snd_soc_cnew() 新建。

新建时控制项的名字有三种拼法，由 wname_in_long_name / kcname_in_long_name 两个布尔决定：

widget 类型 含 widget 名 含 control 名 最终名字
switch / mixer / pga / effect / out_drv 是 是 "<widget> <control>"
mixer_named_ctl 否 是 "<control>"
demux / mux 是 否 "<widget>"
共享 kcontrol 否 是 "<control>"

mixer_named_ctl 里的 named_ctl 就是这个意思：控制项名字不跟 widget 名绑，用户空间看到的名字就是模板里写的那个。

后面三步：snd_soc_cnew() 按模板建实例并拷值；dapm_kcontrol_data_alloc() 分配 private_data；snd_ctl_add() 把 kcontrol 挂到声卡的 controls 链表。最后 dapm_kcontrol_add_widget() 把当前 widget 记进 kcontrol 的 widget 列表，再存回 w->kcontrols[kci]。

dapm_kcontrol_data 这个私有结构的四个成员：

c
struct dapm_kcontrol_data {  // 保存当前kcontrol的私有数据
        unsigned int value;
        struct snd_soc_dapm_widget *widget;      // 影子 widget

paths 是这个设计的关键：一个 kcontrol 可以同时管多条边（Mixer 的左右声道就是），这些边全挂在这条链表上，put 回调里一起遍历。

dapm_kcontrol_data_alloc() 里最值得看的是 autodisable 那段：

c
static int dapm_kcontrol_data_alloc(struct snd_soc_dapm_widget *widget,
        struct snd_kcontrol *kcontrol, const char *ctrl_name)
{
        struct dapm_kcontrol_data *data;
        struct soc_mixer_control *mc;
        struct soc_enum *e;
        const char *name;
        int ret;

        data = kzalloc(sizeof(*data), GFP_KERNEL);
        if (!data)
                return -ENOMEM;

        INIT_LIST_HEAD(&data->paths);

        switch (widget->id) {
        case snd_soc_dapm_switch:
        case snd_soc_dapm_mixer:
        case snd_soc_dapm_mixer_named_ctl:
                mc = (struct soc_mixer_control *)kcontrol->private_value;

                if (mc->autodisable) {  // 只有 AUTODISABLE 版本会走这里
                        struct snd_soc_dapm_widget template;

                        if (snd_soc_volsw_is_stereo(mc))
                                dev_warn(widget->dapm->dev,
                                         "ASoC: Unsupported stereo autodisable control '%s'\n",
                                         ctrl_name);

                        name = kasprintf(GFP_KERNEL, "%s %s", ctrl_name,
                                         "Autodisable");
                        if (!name) {
                                ret = -ENOMEM;
                                goto err_data;
                        }

                        memset(&template, 0, sizeof(template));
                        template.reg = mc->reg;
                        template.mask = (1 << fls(mc->max)) - 1;
                        template.shift = mc->shift;
                        if (mc->invert)
                                template.off_val = mc->max;
                        else
                                template.off_val = 0;
                        template.on_val = template.off_val;
                        template.id = snd_soc_dapm_kcontrol;
                        template.name = name;

                        data->value = template.on_val;

                        data->widget =
                                snd_soc_dapm_new_control_unlocked(widget->dapm,
                                &template);
                        kfree(name);
                        if (IS_ERR(data->widget)) {
                                ret = PTR_ERR(data->widget);
                                goto err_data;
                        }
                }
                break;
        case snd_soc_dapm_demux:
        case snd_soc_dapm_mux:
                e = (struct soc_enum *)kcontrol->private_value;

                if (e->autodisable) {
                        struct snd_soc_dapm_widget template;

                        name = kasprintf(GFP_KERNEL, "%s %s", ctrl_name,
                                         "Autodisable");
                        if (!name) {
                                ret = -ENOMEM;
                                goto err_data;
                        }

                        memset(&template, 0, sizeof(template));
                        template.reg = e->reg;
                        template.mask = e->mask;
                        template.shift = e->shift_l;
                        template.off_val = snd_soc_enum_item_to_val(e, 0);
                        template.on_val = template.off_val;
                        template.id = snd_soc_dapm_kcontrol;
                        template.name = name;

                        data->value = template.on_val;

                        data->widget = snd_soc_dapm_new_control_unlocked(
                                                widget->dapm, &template);
                        kfree(name);
                        if (IS_ERR(data->widget)) {
                                ret = PTR_ERR(data->widget);
                                goto err_data;
                        }

                        snd_soc_dapm_add_path(widget->dapm, data->widget,
                                              widget, NULL, NULL);
                } else if (e->reg != SND_SOC_NOPM) {
                        data->value = soc_dapm_read(widget->dapm, e->reg) &
                                      (e->mask << e->shift_l);
                }
                break;
        default:
                break;
        }

        kcontrol->private_data = data;

        return 0;

err_data:
        kfree(data);
        return ret;
}

autodisable 这个位只有用了 SOC_DAPM_SINGLE_AUTODISABLE 一类宏才会置上，普通 SOC_DAPM_SINGLE 不会。置上就多造一个 snd_soc_dapm_kcontrol 类型的影子 widget，名字是 "<ctrl_name> Autodisable"，寄存器信息复用原 kcontrol，on_val = off_val——也就是说它表达的语义是「这条路没有信号时要自动关掉」。Mux 的 autodisable 还会额外把影子 widget 和 mux 之间连一条边。

影子 widget 的类型 snd_soc_dapm_kcontrol 在第九章第二轮 switch 里被归到 is_supply = 1 那一组，所以它在遍历时会截断路径，只在 dapm_supply_check_power() 里下游有人要才上电。

dapm_new_mux()：

c
static int dapm_new_mux(struct snd_soc_dapm_widget *w)
{
        struct snd_soc_dapm_context *dapm = w->dapm;
        enum snd_soc_dapm_direction dir;
        struct snd_soc_dapm_path *path;
        const char *type;
        int ret;

        switch (w->id) {
        case snd_soc_dapm_mux:
                dir = SND_SOC_DAPM_DIR_OUT;    // 1
                type = "mux";
                break;
        case snd_soc_dapm_demux:
                dir = SND_SOC_DAPM_DIR_IN;    // 0
                type = "demux";
                break;
        default:
                return -EINVAL;
        }

        if (w->num_kcontrols != 1) {  // Mux 必须恰好一个 kcontrol
                dev_err(dapm->dev,
                        "ASoC: %s %s has incorrect number of controls\n", type,
                        w->name);
                return -EINVAL;
        }

        if (list_empty(&w->edges[dir])) {   // 边不能为空
                dev_err(dapm->dev, "ASoC: %s %s has no paths\n", type, w->name);
                return -EINVAL;
        }

        ret = dapm_create_or_share_kcontrol(w, 0);
        if (ret < 0)
                return ret;

        snd_soc_dapm_widget_for_each_path(w, dir, path) {
                if (path->name)
                        dapm_kcontrol_add_path(w->kcontrols[0], path);
        }

        return 0;
}

Mux 和 Demux 共用一个函数，靠 dir 区分：Mux 的边在输出侧（DIR_OUT），Demux 的边在输入侧（DIR_IN）。两个硬校验——kcontrol 数量必须恰好 1、对应方向的边不能为空——都是把驱动写错的情况在校验阶段就拦下来。最后把这个方向上所有有名字的 path 都挂进 kcontrols[0] 的 paths 链表。

十、dapm_route 的注册 #

Widget 之间没有连接关系，DAPM 就没有电源管理可做。连接关系全由驱动声明的 route 数组描述，注册入口是 snd_soc_dapm_add_routes()：

c
int snd_soc_dapm_add_routes(struct snd_soc_dapm_context *dapm,
                            const struct snd_soc_dapm_route *route, int num)
{
        int i, ret = 0;

        mutex_lock_nested(&dapm->card->dapm_mutex, SND_SOC_DAPM_CLASS_RUNTIME);   // 获取互斥锁
        for (i = 0; i < num; i++) {
                int r = snd_soc_dapm_add_route(dapm, route);
                if (r < 0)
                        ret = r;
                route++;
        }
        mutex_unlock(&dapm->card->dapm_mutex);  // 释放互斥锁

        return ret;
}

注意 ret 的用法：单条失败不中断循环，继续往下注册，最后返回最后一条失败的错误码。所以驱动 probe 里只看 ret 非零，别指望里面只有一条错。

真正的解析在 snd_soc_dapm_add_route()：

c
static int snd_soc_dapm_add_route(struct snd_soc_dapm_context *dapm,
                                  const struct snd_soc_dapm_route *route)
{
        struct snd_soc_dapm_widget *wsource = NULL, *wsink = NULL, *w;
        struct snd_soc_dapm_widget *wtsource = NULL, *wtsink = NULL;
        const char *sink;
        const char *source;
        char prefixed_sink[80];
        char prefixed_source[80];
        const char *prefix;
        unsigned int sink_ref = 0;
        unsigned int source_ref = 0;
        int ret;

        prefix = soc_dapm_prefix(dapm);
        if (prefix) {                        // 名称前加必要前缀
                snprintf(prefixed_sink, sizeof(prefixed_sink), "%s %s",
                         prefix, route->sink);
                sink = prefixed_sink;
                snprintf(prefixed_source, sizeof(prefixed_source), "%s %s",
                         prefix, route->source);
                source = prefixed_source;
        } else {
                sink = route->sink;
                source = route->source;
        }

        wsource = dapm_wcache_lookup(dapm->wcache_source, source);   // 缓存快查
        wsink   = dapm_wcache_lookup(dapm->wcache_sink,   sink);

        if (wsink && wsource)   // 都命中，跳过全表扫描
                goto skip_search;

        /*
         * find src and dest widgets over all widgets but favor a widget from
         * current DAPM context
         */
        for_each_card_widgets(dapm->card, w) {              // 遍历 card->widgets
                if (!wsink && !(strcmp(w->name, sink))) {
                        wtsink = w;
                        if (w->dapm == dapm) {
                                wsink = w;
                                if (wsource)
                                        break;
                        }
                        sink_ref++;
                        if (sink_ref > 1)
                                dev_warn(dapm->dev,
                                        "ASoC: sink widget %s overwritten\n",
                                        w->name);
                        continue;
                }
                if (!wsource && !(strcmp(w->name, source))) {
                        wtsource = w;
                        if (w->dapm == dapm) {
                                wsource = w;
                                if (wsink)
                                        break;
                        }
                        source_ref++;
                        if (source_ref > 1)
                                dev_warn(dapm->dev,
                                        "ASoC: source widget %s overwritten\n",
                                        w->name);
                }
        }
        /* use widget from another DAPM context if not found from this */
        if (!wsink)
                wsink = wtsink;
        if (!wsource)
                wsource = wtsource;

        ret = -ENODEV;
        if (!wsource)
                goto err;
        if (!wsink)
                goto err;

skip_search:
        /* update cache */
        dapm->wcache_sink       = wsink;
        dapm->wcache_source     = wsource;

        ret = snd_soc_dapm_add_path(dapm, wsource, wsink, route->control,
                route->connected);
err:
        if (ret)
                dev_err(dapm->dev, "ASoC: Failed to add route %s%s -%s%s%s> %s%s\n",
                        source, !wsource ? "(*)" : "",
                        !route->control ? "" : "> [",
                        !route->control ? "" : route->control,
                        !route->control ? "" : "] -",
                        sink,  !wsink ? "(*)" : "");
        return ret;
}

六步：

  1. 加前缀。route->sink 和 route->source 拼成 "<prefix> <name>"，缓冲固定 80 字节，超长会被截断——名字太长的驱动在这里会静默拿到一个找不到的 widget。
  2. 查缓存。dapm_wcache_lookup() 从上次命中的位置往后看两个，命中就跳过全表扫描。
  3. 全表扫描。这里有个优先级设计：同名 widget 出现在多个域里时，优先取当前域的那个。wtsink/wtsource 兜底存最后一个同名项，循环结束后如果当前域没找到，就用兜底的跨域项。
  4. 重名告警。sink_ref > 1 或 source_ref > 1 就打印 sink widget %s overwritten。看到这条日志，说明你的 widget 重名了，route 连到的就不是你想要的节点。
  5. 找不到就 -ENODEV，错误日志里会用 (*) 标出是哪一端没找到。
  6. 调 snd_soc_dapm_add_path() 建 path。

缓存函数：

c
static struct snd_soc_dapm_widget *
dapm_wcache_lookup(struct snd_soc_dapm_widget *w, const char *name)
{
        if (w) {
                struct list_head *wlist = &w->dapm->card->widgets;
                const int depth = 2;                                // 链表查找深度
                int i = 0;

                list_for_each_entry_from(w, wlist, list) {
                        if (!strcmp(name, w->name))
                                return w;

                        if (++i == depth)
                                break;
                }
        }

        return NULL;
}

深度 2 是个经验值：route 表常成对出现，一条 route 的 sink 常常就是下一条的 source，往后看两步命中率够高。

wcache_sink / wcache_source 是放在 snd_soc_dapm_context 里的（第 7 章结构体的最后两个字段），意味着缓存按域各存一份，跨域注册时不会互相污染。

snd_soc_dapm_add_path：把声明变成边 #

c
static int snd_soc_dapm_add_path(struct snd_soc_dapm_context *dapm,
        struct snd_soc_dapm_widget *wsource, struct snd_soc_dapm_widget *wsink,
        const char *control,  // 静态链接时为 NULL
        int (*connected)(struct snd_soc_dapm_widget *source,
                         struct snd_soc_dapm_widget *sink))
{
        enum snd_soc_dapm_direction dir;
        struct snd_soc_dapm_path *path;
        int ret;

        if (wsink->is_supply && !wsource->is_supply) {
                dev_err(dapm->dev,
                        "Connecting non-supply widget to supply widget is not supported (%s -> %s)\n",
                        wsource->name, wsink->name);
                return -EINVAL;
        }

        if (connected && !wsource->is_supply) {
                dev_err(dapm->dev,
                        "connected() callback only supported for supply widgets (%s -> %s)\n",
                        wsource->name, wsink->name);
                return -EINVAL;
        }

        if (wsource->is_supply && control) {
                dev_err(dapm->dev,
                        "Conditional paths are not supported for supply widgets (%s -> [%s] -> %s)\n",
                        wsource->name, control, wsink->name);
                return -EINVAL;
        }

        ret = snd_soc_dapm_check_dynamic_path(dapm, wsource, wsink, control);
        if (ret)
                return ret;

        path = kzalloc(sizeof(struct snd_soc_dapm_path), GFP_KERNEL);
        if (!path)
                return -ENOMEM;

        path->node[SND_SOC_DAPM_DIR_IN] = wsource;    // 0 输入端
        path->node[SND_SOC_DAPM_DIR_OUT] = wsink;     // 1 输出端

        path->connected = connected;
        INIT_LIST_HEAD(&path->list);
        INIT_LIST_HEAD(&path->list_kcontrol);

        if (wsource->is_supply || wsink->is_supply)
                path->is_supply = 1;

        /* connect static paths */
        if (control == NULL) {
                path->connect = 1;   // 静态直连
        } else {
                switch (wsource->id) {
                case snd_soc_dapm_demux:
                        ret = dapm_connect_mux(dapm, path, control, wsource);
                        if (ret)
                                goto err;
                        break;
                default:
                        break;
                }

                switch (wsink->id) {
                case snd_soc_dapm_mux:
                        ret = dapm_connect_mux(dapm, path, control, wsink);
                        if (ret != 0)
                                goto err;
                        break;
                case snd_soc_dapm_switch:
                case snd_soc_dapm_mixer:
                case snd_soc_dapm_mixer_named_ctl:
                        ret = dapm_connect_mixer(dapm, path, control);
                        if (ret != 0)
                                goto err;
                        break;
                default:
                        break;
                }
        }

        list_add(&path->list, &dapm->card->paths);  // 挂进 card->paths

        snd_soc_dapm_for_each_direction(dir)   // 0 输入端、1 输出端
                list_add(&path->list_node[dir], &path->node[dir]->edges[dir]);

        snd_soc_dapm_for_each_direction(dir) {
                dapm_update_widget_flags(path->node[dir]);
                dapm_mark_dirty(path->node[dir], "Route added");
        }

        if (snd_soc_card_is_instantiated(dapm->card) && path->connect)
                dapm_path_invalidate(path);

        return 0;
err:
        kfree(path);
        return ret;
}

前置三条校验先把不合法的连法挡掉：

  • 非供给 widget 连到供给 widget：不支持；
  • 非供给 widget 带 connected 回调：不支持；
  • 供给 widget 带 control：不支持，供给是常通的。

然后是动态路径检查 snd_soc_dapm_check_dynamic_path()：

c
static int snd_soc_dapm_check_dynamic_path(struct snd_soc_dapm_context *dapm,
        struct snd_soc_dapm_widget *source, struct snd_soc_dapm_widget *sink,
        const char *control)
{
        bool dynamic_source = false;
        bool dynamic_sink = false;

        if (!control)
                return 0;

        switch (source->id) {
        case snd_soc_dapm_demux:
                dynamic_source = true;
                break;
        default:
                break;
        }

        switch (sink->id) {
        case snd_soc_dapm_mux:
        case snd_soc_dapm_switch:
        case snd_soc_dapm_mixer:
        case snd_soc_dapm_mixer_named_ctl:
                dynamic_sink = true;
                break;
        default:
                break;
        }

        if (dynamic_source && dynamic_sink) {
                dev_err(dapm->dev,
                        "Direct connection between demux and mixer/mux not supported for path %s -> [%s] -> %s\n",
                        source->name, control, sink->name);
                return -EINVAL;
        } else if (!dynamic_source && !dynamic_sink) {
                dev_err(dapm->dev,
                        "Control not supported for path %s -> [%s] -> %s\n",
                        source->name, control, sink->name);
                return -EINVAL;
        }

        return 0;
}

结论很干脆：一条边带了 control，那么两端之中必须恰好有一端是可控类型。

  • 两端都能控（demux 对 mux/mixer/switch）：不支持，Direct connection between demux and mixer/mux not supported；
  • 两端都不能控：不支持，Control not supported for path；
  • 只有 sink 能控（mux/switch/mixer）或只有 source 能控（demux）：合法。

没带 control 的边一律视为静态连通，path->connect = 1。

控通断的两个函数分别对应两种控制语义。

dapm_connect_mux() 处理 Mux/Demux：

c
static int dapm_connect_mux(struct snd_soc_dapm_context *dapm,
        struct snd_soc_dapm_path *path, const char *control_name,
        struct snd_soc_dapm_widget *w)
{
        const struct snd_kcontrol_new *kcontrol = &w->kcontrol_news[0];
        struct soc_enum *e = (struct soc_enum *)kcontrol->private_value;
        unsigned int item;
        int i;

        if (e->reg != SND_SOC_NOPM) {
                unsigned int val;
                val = soc_dapm_read(dapm, e->reg);   // 读寄存器
                val = (val >> e->shift_l) & e->mask;
                item = snd_soc_enum_val_to_item(e, val);
        } else {
                /*
                 * 虚拟 mux 没有背板寄存器，只能匹配第一个枚举项，
                 * 保证默认选择在初始化时被正确上电。
                 */
                item = 0;
        }

        i = match_string(e->texts, e->items, control_name);
        if (i < 0)
                return -ENODEV;

        path->name = e->texts[i];    // 路径名就是枚举文本
        path->connect = (i == item);
        return 0;

}

Mux 只有一个 kcontrol，control_name 是枚举里的一个文本。当前寄存器值翻译成 item（枚举下标），control_name 在 e->texts 里匹配出下标 i，i == item 就是这条路通。所以 Mux 的 route 里 control 写的是那一项的文本，不是 kcontrol 名，这跟 Mixer 完全不同，搞错就 -ENODEV。

snd_soc_enum_val_to_item() 处理枚举值和下标的非线性映射：

c
static inline unsigned int snd_soc_enum_val_to_item(struct soc_enum *e,
        unsigned int val)
{
        unsigned int i;

        if (!e->values)
                return val;

        for (i = 0; i < e->items; i++)
                if (val == e->values[i])
                        return i;

        return 0;
}

没定义 values 数组时值和下标是一回事，直接返回；定义了说明寄存器值不连续（比如 0/1/4/5），要查表换算，查不到就返回 0。

dapm_connect_mixer() 处理 Mixer/Switch：

c
static int dapm_connect_mixer(struct snd_soc_dapm_context *dapm,
        struct snd_soc_dapm_path *path, const char *control_name)
{
        int i, nth_path = 0;

        /* search for mixer kcontrol */
        for (i = 0; i < path->sink->num_kcontrols; i++) {
                if (!strcmp(control_name, path->sink->kcontrol_news[i].name)) {
                        path->name = path->sink->kcontrol_news[i].name;
                        dapm_set_mixer_path_status(path, i, nth_path++);
                        return 0;
                }
        }
        return -ENODEV;
}

Mixer 的边是固定的，每条边一个 kcontrol，只控制通断，不做选择。control_name 跟 sink 的模板数组逐个 strcmp，命中就把模板里的指针赋给 path->name（第九章说的那个指针比较就是靠这里），然后读初始状态。

注意 nth_path++ 在返回前就自增了，所以每条边调用时传的是自己在这个 kcontrol 下的序号，用来处理立体声共用控件时区分左右声道。

初始状态读取：

c
static void dapm_set_mixer_path_status(struct snd_soc_dapm_path *p, int i,
                                       int nth_path)
{
        struct soc_mixer_control *mc = (struct soc_mixer_control *)
                p->sink->kcontrol_news[i].private_value;
        unsigned int reg = mc->reg;
        unsigned int invert = mc->invert;

        if (reg != SND_SOC_NOPM) {
                unsigned int shift = mc->shift;
                unsigned int max = mc->max;
                unsigned int mask = (1 << fls(max)) - 1;
                unsigned int val = soc_dapm_read(p->sink->dapm, reg);

                /*
                 * The nth_path argument allows this function to know
                 * which path of a kcontrol it is setting the initial
                 * status for. ...
                 */
                if (snd_soc_volsw_is_stereo(mc) && nth_path > 0) {
                        if (reg != mc->rreg)
                                val = soc_dapm_read(p->sink->dapm, mc->rreg);
                        val = (val >> mc->rshift) & mask;
                } else {
                        val = (val >> shift) & mask;
                }
                if (invert)
                        val = max - val;
                p->connect = !!val;
        } else {
                /*
                 * 虚拟 mixer 没有寄存器，只能按初始状态匹配，
                 * 保证默认选择在初始化时正确上电。
                 */
                p->connect = invert;
        }
}

关键约定在注释里写得很清楚：立体声控件下，第一条 path 算左声道，其余 path 算右声道。所以 nth_path > 0 就走 rreg/rshift。这也意味着一个立体声 kcontrol 最多支持 2 条边。

mask = (1 << fls(max)) - 1：fls() 返回最高位位置，减一取到能表示 max 的最小掩码。max=1 时 fls(1)=1，掩码 0x1；max=3 时 fls(3)=2，掩码 0x3。

invert 处理反逻辑位，读出来是 max - val。虚拟 mixer 没有寄存器，p->connect = invert——即反逻辑的默认连、正逻辑的默认断，跟「初始枚举项被选中」那个约定保持一致。

dapm_update_widget_flags：端点身份的动态修正 #

c
static void dapm_update_widget_flags(struct snd_soc_dapm_widget *w)
{
        enum snd_soc_dapm_direction dir;
        struct snd_soc_dapm_path *p;
        unsigned int ep;

        switch (w->id) {
        case snd_soc_dapm_input:  // codec 输入引脚
                /* On a fully routed card an input is never a source */
                if (w->dapm->card->fully_routed)
                        return;
                ep = SND_SOC_DAPM_EP_SOURCE;                          // 1<<0
                snd_soc_dapm_widget_for_each_source_path(w, p) {
                        if (p->source->id == snd_soc_dapm_micbias ||
                                p->source->id == snd_soc_dapm_mic ||
                                p->source->id == snd_soc_dapm_line ||
                                p->source->id == snd_soc_dapm_output) {
                                        ep = 0;
                                        break;
                        }
                }
                break;
        case snd_soc_dapm_output:
                /* On a fully routed card a output is never a sink */
                if (w->dapm->card->fully_routed)
                        return;
                ep = SND_SOC_DAPM_EP_SINK;                      // 1<<1
                snd_soc_dapm_widget_for_each_sink_path(w, p) {
                        if (p->sink->id == snd_soc_dapm_spk ||
                                p->sink->id == snd_soc_dapm_hp ||
                                p->sink->id == snd_soc_dapm_line ||
                                p->sink->id == snd_soc_dapm_input) {
                                        ep = 0;
                                        break;
                                }
                }
                break;
        case snd_soc_dapm_line:
                ep = 0;
                // line 类型：有输入方向的边就是源端点，有输出方向的边就是目的端点
                snd_soc_dapm_for_each_direction(dir) {
                        if (!list_empty(&w->edges[dir]))
                                ep |= SND_SOC_DAPM_DIR_TO_EP(dir); // 1<<dir
                }
                break;
        default:
                return;
        }

        w->is_ep = ep;  // 该 widget 是端点
}

这个函数解决的是「有连线的 widget 端点身份会变」的问题：

  • input 上游接了 mic/line/micbias/output，说明它其实是信号链的中段，is_ep 清零，不再当源端点；
  • output 下游接了 spk/hp/line/input，同理清零；
  • line 两边都能接，is_ep 允许同时置两个位。

SND_SOC_DAPM_DIR_TO_EP(dir) 展开就是 1 << dir，跟 is_ep 的位定义对齐。所以 is_ep 的取值实际上是 EP_SOURCE（bit0）、EP_SINK（bit1）的位或组合。

pin 的开关 #

有些引脚的通断不是靠 kcontrol 而是靠外部事件（插拔检测）。snd_soc_dapm_enable_pin() 走这条路：

c
static int snd_soc_dapm_set_pin(struct snd_soc_dapm_context *dapm,
                                const char *pin, int status)
{

        return ret < 0 ? ret : 0;
}

int snd_soc_dapm_enable_pin(struct snd_soc_dapm_context *dapm, const char *pin)
{
        int ret;

        mutex_lock_nested(&dapm->card->dapm_mutex, SND_SOC_DAPM_CLASS_RUNTIME);

        ret = snd_soc_dapm_set_pin(dapm, pin, 1);

        mutex_unlock(&dapm->card->dapm_mutex);

        return ret;
}

函数上方的注释里有一句关键的话：snd_soc_dapm_sync() needs to be called after this for DAPM to do any widget power switching.，意思是这个函数只改状态、不切电源，切电源要另外调 snd_soc_dapm_sync()（内部就是 dapm_power_widgets()）。

底层实现：

c
static int __snd_soc_dapm_set_pin(struct snd_soc_dapm_context *dapm,
                                  const char *pin, int status)
{
        struct snd_soc_dapm_widget *w = dapm_find_widget(dapm, pin, true);
        int ret = 0;

        dapm_assert_locked(dapm);

        if (!w) {
                dev_err(dapm->dev, "ASoC: DAPM unknown pin %s\n", pin);
                return -EINVAL;
        }

        if (w->connected != status) {  // 状态真的有变化
                dapm_mark_dirty(w, "pin configuration");
                dapm_widget_invalidate_input_paths(w);
                dapm_widget_invalidate_output_paths(w);
                ret = 1;
        }

        w->connected = status; // 更新连接状态
        if (status == 0)
                w->force = 0;

        return ret;
}

三步：按名找 widget（找不到报 ASoC: DAPM unknown pin %s）；状态变了就挂脏、双向清缓存；写 connected，断开时顺手清 force。返回值 1 表示确实变了，0 表示本来就是那个值，调用方据此判断要不要触发同步。

缓存清空的范围由 dapm_widget_invalidate_paths() 决定：

c
static __always_inline void dapm_widget_invalidate_paths(
        struct snd_soc_dapm_widget *w, enum snd_soc_dapm_direction dir)
{
        enum snd_soc_dapm_direction rdir = SND_SOC_DAPM_DIR_REVERSE(dir);
        struct snd_soc_dapm_widget *node;
        struct snd_soc_dapm_path *p;
        LIST_HEAD(list);

        dapm_assert_locked(w->dapm);

        if (w->endpoints[dir] == -1)   // 本来就是 -1，不用清
                return;

        list_add_tail(&w->work_list, &list);  // 当前 widget 入队
        w->endpoints[dir] = -1;               // 清空自己

        list_for_each_entry(w, &list, work_list) {
                snd_soc_dapm_widget_for_each_path(w, dir, p) {
                        if (p->is_supply || p->weak || !p->connect)
                                continue;
                        node = p->node[rdir];                 // 取对端 widget
                        if (node->endpoints[dir] != -1) {     // 还没清过
                                node->endpoints[dir] = -1;
                                list_add_tail(&node->work_list, &list);
                        }
                }
        }
}

广度优先遍历，从改动点向外扩散，把所有 endpoints[dir] != -1 的节点清回 -1。if (w->endpoints[dir] == -1) return; 这个提前返回很重要，它让整段成为 O(1) 的常见路径——大多数调用发生时缓存本来就已经是干净的。

它和 is_connected_ep() 正好是一对：一个填缓存，一个清缓存。规则是对称的，都跳过 is_supply/weak/断开的边。

十一、电源状态机：从 OFF 到 ON #

这是 DAPM 的核心。所有前面的建模，最终都收敛到 dapm_power_widgets() 这一个函数上。它由两种场合触发：snd_soc_dapm_sync()（用户空间改了 mixer/mux）、soc_dapm_stream_event()（PCM 起停）。

c
static int dapm_power_widgets(struct snd_soc_card *card, int event)
{
        struct snd_soc_dapm_widget *w;
        struct snd_soc_dapm_context *d;

        // 1. 两条链表：要上电的、要下电的
        LIST_HEAD(up_list);      // 上电链表
        LIST_HEAD(down_list);    // 下电链表
        ASYNC_DOMAIN_EXCLUSIVE(async_domain);
        enum snd_soc_bias_level bias;
        int ret;

        lockdep_assert_held(&card->dapm_mutex);

        trace_snd_soc_dapm_start(card);

        for_each_card_dapms(card, d) {
                if (dapm_idle_bias_off(d))  // d->idle_bias_off
                        d->target_bias_level = SND_SOC_BIAS_OFF;
                else
                        d->target_bias_level = SND_SOC_BIAS_STANDBY;
        }

        // 2. 把所有 widget 的 power_checked 清掉
        dapm_reset(card);

        /* Check which widgets we need to power and store them in
         * lists indicating if they should be powered up or down.  We
         * only check widgets that have been flagged as dirty but note
         * that new widgets may be added to the dirty list while we
         * iterate.
         */
        // 3. 遍历脏表，把每个 widget 分进 up_list 或 down_list
        list_for_each_entry(w, &card->dapm_dirty, dirty) {
                dapm_power_one_widget(w, &up_list, &down_list);
        }
        // 对一些特殊类型做处理
        for_each_card_widgets(card, w) {
                switch (w->id) {
                case snd_soc_dapm_pre:
                case snd_soc_dapm_post:
                        /* These widgets always need to be powered */
                        break;
                default:
                        list_del_init(&w->dirty);
                        break;
                }

                if (w->new_power) {
                        d = w->dapm;

                        /* Supplies and micbiases only bring the
                         * context up to STANDBY as unless something
                         * else is active and passing audio they
                         * generally don't require full power.  Signal
                         * generators are virtual pins and have no
                         * power impact themselves.
                         */
                        switch (w->id) {
                        case snd_soc_dapm_siggen:
                        case snd_soc_dapm_vmid:
                                break;
                        case snd_soc_dapm_supply:
                        case snd_soc_dapm_regulator_supply:
                        case snd_soc_dapm_pinctrl:
                        case snd_soc_dapm_clock_supply:
                        case snd_soc_dapm_micbias:
                                if (d->target_bias_level < SND_SOC_BIAS_STANDBY)
                                        d->target_bias_level = SND_SOC_BIAS_STANDBY;
                                break;
                        default:
                                d->target_bias_level = SND_SOC_BIAS_ON;
                                break;
                        }
                }

        }

        /* Force all contexts in the card to the same bias state if
         * they're not ground referenced.
         */
        bias = SND_SOC_BIAS_OFF;
        for_each_card_dapms(card, d)
                if (d->target_bias_level > bias)
                        bias = d->target_bias_level;
        for_each_card_dapms(card, d)
                if (!dapm_idle_bias_off(d))
                        d->target_bias_level = bias;

        trace_snd_soc_dapm_walk_done(card);

        /* Run card bias changes at first */
        dapm_pre_sequence_async(&card->dapm, 0);
        /* Run other bias changes in parallel */
        for_each_card_dapms(card, d) {   // 4. 设偏置电压
                if (d != &card->dapm && d->bias_level != d->target_bias_level)
                        async_schedule_domain(dapm_pre_sequence_async, d,
                                                &async_domain);
        }
        async_synchronize_full_domain(&async_domain);

        list_for_each_entry(w, &down_list, power_list) {
                dapm_seq_check_event(card, w, SND_SOC_DAPM_WILL_PMD);
        }

        list_for_each_entry(w, &up_list, power_list) {
                dapm_seq_check_event(card, w, SND_SOC_DAPM_WILL_PMU);
        }

        /* Power down widgets first; try to avoid amplifying pops. */
        dapm_seq_run(card, &down_list, event, false);   // 5.1 先下电
        // 仅 kcontrol 触发的 DAPM 才会走这里：
        // 1. 遍历 kcontrol 相关 widget，发 SND_SOC_DAPM_PRE_REG
        // 2. 更新 kcontrol 寄存器
        // 3. 遍历 kcontrol 相关 widget，发 SND_SOC_DAPM_POST_REG
        dapm_widget_update(card);

        /* Now power up. */
        dapm_seq_run(card, &up_list, event, true);  // 5.2 后上电

        /* Run all the bias changes in parallel */
        for_each_card_dapms(card, d) {
                if (d != &card->dapm && d->bias_level != d->target_bias_level)
                        async_schedule_domain(dapm_post_sequence_async, d,
                                                &async_domain);
        }
        async_synchronize_full_domain(&async_domain);
        /* Run card bias changes at last */
        dapm_post_sequence_async(&card->dapm, 0);

        /* do we need to notify any clients that DAPM event is complete */
        for_each_card_dapms(card, d) {
                if (!d->component)
                        continue;

                ret = snd_soc_component_stream_event(d->component, event);
                if (ret < 0)
                        return ret;
        }

        pop_dbg(card->dev, card->pop_time,
                "DAPM sequencing finished, waiting %dms\n", card->pop_time);
        pop_wait(card->pop_time);

        trace_snd_soc_dapm_done(card);

        return 0;
}

按执行顺序拆开，每一步都在干一件具体的事：

  1. 定初始偏置目标。所有域先按 idle_bias_off 表态：置位的目标 BIAS_OFF，没置的 BIAS_STANDBY。这是能效策略的默认值。
  2. 清检查标志。dapm_reset()：
  3. 脏表扩散。遍历 card->dapm_dirty，逐个调 dapm_power_one_widget()。这一步的特殊之处在于遍历的同时还在往链表里加元素——dapm_power_one_widget() 会把状态需要跟着变的邻居也挂进脏表，所以这个 list_for_each_entry 实际上是滚雪球式的。然后是第二个 for_each_card_widgets()：把非 pre/post 的 widget 从脏表摘掉（list_del_init），同时按「这轮要上电的 widget 是哪类」抬高域的 target_bias_level——供给类和 micbias 只抬到 STANDBY，其余抬到 ON，siggen/vmid 不参与。
  4. 统一非接地域的偏置。取所有域里最高的目标值作为 bias，然后凡是没开 idle_bias_off 的域全部对齐到这个值。理由是这些域不接地，偏置电压不一致会漏电流。
  5. 先下电，再切 kcontrol，再上电。顺序是刻意的，注释写的是 Power down widgets first; try to avoid amplifying pops.——先断后通能少放大 pop。

第 5 步的偏置电压切换走异步，dapm_pre_sequence_async()：

c
static void dapm_pre_sequence_async(void *data, async_cookie_t cookie)
{
        struct snd_soc_dapm_context *d = data;
        int ret;

        /* If we're off and we're not supposed to go into STANDBY */
        if (d->bias_level == SND_SOC_BIAS_OFF &&
            d->target_bias_level != SND_SOC_BIAS_OFF) {
                if (d->dev && cookie)
                        pm_runtime_get_sync(d->dev);

                ret = snd_soc_dapm_set_bias_level(d, SND_SOC_BIAS_STANDBY);
                if (ret != 0)
                        dev_err(d->dev,
                                "ASoC: Failed to turn on bias: %d\n", ret);
        }

        /* Prepare for a transition to ON or away from ON */
        if ((d->target_bias_level == SND_SOC_BIAS_ON &&
             d->bias_level != SND_SOC_BIAS_ON) ||
            (d->target_bias_level != SND_SOC_BIAS_ON &&
             d->bias_level == SND_SOC_BIAS_ON)) {
                ret = snd_soc_dapm_set_bias_level(d, SND_SOC_BIAS_PREPARE);
                if (ret != 0)
                        dev_err(d->dev,
                                "ASoC: Failed to prepare bias: %d\n", ret);
        }
}

两个判断各管一段迁移：

  • 从 OFF 往上走，先经停 STANDBY，并顺手 pm_runtime_get_sync() 把父设备唤醒；
  • 凡是跨越 ON 的迁移（进 ON 或出 ON），中间必须过 PREPARE。

所以偏置电压不是一步到位的，OFF → STANDBY → PREPARE → ON 是一级一级台阶走上去的。这个设计给 codec 留了「打嗝」的时机——pop 抑制电容就是在这些中间态里充放电。

dapm_post_sequence_async() 收尾时方向反过来，逐级落回。

dapm_power_one_widget：单个 widget 的判定与扩散 #

c
static void dapm_power_one_widget(struct snd_soc_dapm_widget *w,
                                  struct list_head *up_list,
                                  struct list_head *down_list)
{
        struct snd_soc_dapm_path *path;
        int power;

        switch (w->id) {
        case snd_soc_dapm_pre: // 最先执行
                power = 0;     // 期望下电
                goto end;
        case snd_soc_dapm_post: // 最后执行
                power = 1;      // 期望上电
                goto end;
        default:
                break;
        }

        // 调 power_check 得出期望状态
        power = dapm_widget_power_check(w);

        // 状态没变就不必重复处理
        if (w->power == power)
                return;

        trace_snd_soc_dapm_widget_power(w, power);

        /*
         * If we changed our power state perhaps our neigbours
         * changed also.
         */
        snd_soc_dapm_widget_for_each_source_path(w, path)
                dapm_widget_set_peer_power(path->source, power, path->connect);

        /*
         * Supplies can't affect their outputs, only their inputs
         */
        if (!w->is_supply)
                snd_soc_dapm_widget_for_each_sink_path(w, path)
                        dapm_widget_set_peer_power(path->sink, power, path->connect);

end:
        if (power)  // 上电
                dapm_seq_insert(w, up_list, true);
        else    // 下电
                dapm_seq_insert(w, down_list, false);
}

三个关键点。

pre/post 走特殊通道。pre 的期望值是 0，post 的期望值是 1——这是因为它们不是真正的电源节点，而是插在序列首尾的事件挂载点：pre 在下电序列的最前面（值 0 所以进 down_list），post 在上电序列的最后面（值 1 所以进 up_list）。第六章第二节 dapm_power_widgets() 里那个 These widgets always need to be powered 的 switch 就是配合这个的。

w->power == power 就 return。这是性能关键路径：绝大多数 widget 状态没变，直接跳过所有邻居处理。

只有状态真的变了才向邻居扩散。向上游看 source，向下游看 sink，is_supply 的 widget 只看上游不看下游——注释写得直白：Supplies can't affect their outputs, only their inputs，供给是给别人用的，它的状态不决定下游信号部件的状态。

扩散函数 dapm_widget_set_peer_power() 干的事就是「如果邻居状态不一致且边是通的，把邻居挂进脏表」，让外层那个 list_for_each_entry 能接着遍历到它。

举例子把这段讲清楚。假设有一条完整通路 A → B → D，另外 B 还有一条边到 F，初始全部下电、全部连通：

  1. 从 B 开始，dapm_widget_power_check(B) 判定它在完整路径上，期望上电；
  2. B->power 是 0，不等于 1，继续；
  3. 遍历 B 的上游边，把 A 挂进脏表；遍历 B 的下游边，把 D、F 挂进脏表；
  4. B 按上电顺序插进 up_list；
  5. 外层循环接着取出 A，重复第 1 步，A 的上游如果没有更多节点，A 插进 up_list；
  6. 同理 D、F 依次插进 up_list。

最终 up_list 里就是整条完整路径上的所有节点。这就是素材里「up_list 链表上会有 A、B、C、D」那句话的机制来源。

dapm_widget_power_check()：

c
static int dapm_widget_power_check(struct snd_soc_dapm_widget *w)
{
        if (w->power_checked) // 已检查过，直接返回
                return w->new_power;

        if (w->force)         // 强制上电
                w->new_power = 1;
        else                  // 按类型回调检查
                w->new_power = w->power_check(w);

        w->power_checked = true;

        return w->new_power;
}

三层短路：已检查过就返回缓存；force 直接算 1；否则调 power_check。power_checked 保证一个 widget 一轮只算一次，dapm_reset() 负责每轮清零。

dapm_seq_insert：按顺序插队 #

c
static int dapm_seq_compare(struct snd_soc_dapm_widget *a,
                            struct snd_soc_dapm_widget *b,
                            bool power_up)
{
        int *sort;

        BUILD_BUG_ON(ARRAY_SIZE(dapm_up_seq) != SND_SOC_DAPM_TYPE_COUNT);
        BUILD_BUG_ON(ARRAY_SIZE(dapm_down_seq) != SND_SOC_DAPM_TYPE_COUNT);

        if (power_up)
                sort = dapm_up_seq;    // 上电顺序表
        else
                sort = dapm_down_seq;  // 下电顺序表

        WARN_ONCE(sort[a->id] == 0, "offset a->id %d not initialized\n", a->id);
        WARN_ONCE(sort[b->id] == 0, "offset b->id %d not initialized\n", b->id);

        if (sort[a->id] != sort[b->id])
                return sort[a->id] - sort[b->id];
        if (a->subseq != b->subseq) {
                if (power_up)   // 上电：subseq 小的在前
                        return a->subseq - b->subseq;
                else            // 下电：subseq 大的在前
                        return b->subseq - a->subseq;
        }
        if (a->reg != b->reg)
                return a->reg - b->reg;
        if (a->dapm != b->dapm)
                return (unsigned long)a->dapm - (unsigned long)b->dapm;

        return 0;
}

static void dapm_seq_insert(struct snd_soc_dapm_widget *new_widget,
                            struct list_head *list,
                            bool power_up)
{
        struct snd_soc_dapm_widget *w;

        list_for_each_entry(w, list, power_list)
                if (dapm_seq_compare(new_widget, w, power_up) < 0) {
                        list_add_tail(&new_widget->power_list, &w->power_list);
                        return;
                }

        list_add_tail(&new_widget->power_list, list);
}

比较是四级键，逐级决定：

  1. 类型序号 sort[id]；
  2. 同类型内的 subseq，上电小的在前、下电大的在前（方向相反，这是刻意的，让同类部件在下电时逆序退出）；
  3. 寄存器地址 reg，让同寄存器的 widget 挨在一起，方便后面合并写；
  4. 域指针，最后一道兜底，纯粹为了让排序稳定。

BUILD_BUG_ON 保证两张顺序表和 SND_SOC_DAPM_TYPE_COUNT 长度一致——枚举加了新类型却忘了填表，编译就过不去。

dapm_seq_run：合并写寄存器 #

up_list / down_list 排好序之后，真正落寄存器的是 dapm_seq_run()：

c
static void dapm_seq_run(struct snd_soc_card *card,
        struct list_head *list, int event, bool power_up)  // 传 down_list 时 power_up=false
{
        struct snd_soc_dapm_widget *w, *n;
        struct snd_soc_dapm_context *d;
        LIST_HEAD(pending);
        int cur_sort = -1;
        int cur_subseq = -1;
        int cur_reg = SND_SOC_NOPM;
        struct snd_soc_dapm_context *cur_dapm = NULL;
        int i;
        int *sort;

        if (power_up)
                sort = dapm_up_seq;
        else
                sort = dapm_down_seq;

        list_for_each_entry_safe(w, n, list, power_list) {
                int ret = 0;

                /* Do we need to apply any queued changes? */
                if (sort[w->id] != cur_sort || w->reg != cur_reg ||
                    w->dapm != cur_dapm || w->subseq != cur_subseq) {
                        if (!list_empty(&pending))
                                dapm_seq_run_coalesced(card, &pending);

                        if (cur_dapm && cur_dapm->component) {
                                for (i = 0; i < ARRAY_SIZE(dapm_up_seq); i++)
                                        if (sort[i] == cur_sort)
                                                snd_soc_component_seq_notifier(
                                                        cur_dapm->component,
                                                        i, cur_subseq);
                        }

                        if (cur_dapm && w->dapm != cur_dapm)
                                soc_dapm_async_complete(cur_dapm);

                        INIT_LIST_HEAD(&pending);
                        cur_sort = -1;
                        cur_subseq = INT_MIN;
                        cur_reg = SND_SOC_NOPM;
                        cur_dapm = NULL;
                }

                switch (w->id) {
                case snd_soc_dapm_pre:
                        if (!w->event)
                                continue;

                        if (event == SND_SOC_DAPM_STREAM_START)
                                ret = w->event(w,
                                               NULL, SND_SOC_DAPM_PRE_PMU);
                        else if (event == SND_SOC_DAPM_STREAM_STOP)
                                ret = w->event(w,
                                               NULL, SND_SOC_DAPM_PRE_PMD);
                        break;

                case snd_soc_dapm_post:
                        if (!w->event)
                                continue;

                        if (event == SND_SOC_DAPM_STREAM_START)
                                ret = w->event(w,
                                               NULL, SND_SOC_DAPM_POST_PMU);
                        else if (event == SND_SOC_DAPM_STREAM_STOP)
                                ret = w->event(w,
                                               NULL, SND_SOC_DAPM_POST_PMD);
                        break;

                default:
                        /* Queue it up for application */
                        cur_sort = sort[w->id];
                        cur_subseq = w->subseq;
                        cur_reg = w->reg;
                        cur_dapm = w->dapm;
                        list_move(&w->power_list, &pending);
                        break;
                }

                if (ret < 0)
                        dev_err(w->dapm->dev,
                                "ASoC: Failed to apply widget power: %d\n", ret);
        }

        if (!list_empty(&pending))
                dapm_seq_run_coalesced(card, &pending);

        if (cur_dapm && cur_dapm->component) {
                for (i = 0; i < ARRAY_SIZE(dapm_up_seq); i++)
                        if (sort[i] == cur_sort)
                                snd_soc_component_seq_notifier(
                                        cur_dapm->component,
                                        i, cur_subseq);
        }

        for_each_card_dapms(card, d)
                soc_dapm_async_complete(d);
}

核心思路：把「同类型 + 同 subseq + 同 reg + 同域」的 widget 攒进 pending，凑够一批就调一次 dapm_seq_run_coalesced() 一次性写。一旦这四个键里任一个变了，当前批次就得刷出去。

pending 刷新时还做两件配套事：通知 component 的 seq_notifier（把当前 seq 号报给 codec，让 codec 有机会在整组上电前做准备），以及跨域时 soc_dapm_async_complete() 等待该域的异步操作。

pre/post 两种类型直接在前台调 event，不进 pending——它们是事件节点，没有寄存器要写。

合并写入本体：

c
static void dapm_seq_run_coalesced(struct snd_soc_card *card,
                                   struct list_head *pending)
{
        struct snd_soc_dapm_context *dapm;
        struct snd_soc_dapm_widget *w;
        int reg;
        unsigned int value = 0;
        unsigned int mask = 0;

        w = list_first_entry(pending, struct snd_soc_dapm_widget, power_list);
        reg = w->reg;
        dapm = w->dapm;

        list_for_each_entry(w, pending, power_list) {
                WARN_ON(reg != w->reg || dapm != w->dapm);
                w->power = w->new_power;

                mask |= w->mask << w->shift;
                if (w->power)
                        value |= w->on_val << w->shift;
                else
                        value |= w->off_val << w->shift;

                pop_dbg(dapm->dev, card->pop_time,
                        "pop test : Queue %s: reg=0x%x, 0x%x/0x%x\n",
                        w->name, reg, value, mask);

                /* Check for events */
                dapm_seq_check_event(card, w, SND_SOC_DAPM_PRE_PMU);
                dapm_seq_check_event(card, w, SND_SOC_DAPM_PRE_PMD);
        }

        if (reg >= 0) {
                /* Any widget will do, they should all be updating the
                 * same register.
                 */

                pop_dbg(dapm->dev, card->pop_time,
                        "pop test : Applying 0x%x/0x%x to %x in %dms\n",
                        value, mask, reg, card->pop_time);
                pop_wait(card->pop_time);
                soc_dapm_update_bits(dapm, reg, mask, value);  // 写硬件寄存器
        }

        list_for_each_entry(w, pending, power_list) {
                dapm_seq_check_event(card, w, SND_SOC_DAPM_POST_PMU);
                dapm_seq_check_event(card, w, SND_SOC_DAPM_POST_PMD);
        }
}

流程四段：

  1. 遍历 pending，把每个 widget 的 power = new_power 落实，同时把 mask 和 value 按各 widget 的 shift 左移后或起来。这就是合并的精髓——一次写覆盖多个位，写的是同一寄存器的不同位。
  2. 写之前给每个 widget 发 PRE_PMU 和 PRE_PMD。
  3. soc_dapm_update_bits(dapm, reg, mask, value) 一次性下硬件。reg < 0（全是 SND_SOC_NOPM 的虚拟 widget）就跳过，因为没寄存器可写。
  4. 写之后发 POST_PMU 和 POST_PMD。

WARN_ON(reg != w->reg || dapm != w->dapm) 是个断言，理论上进同一个 pending 的 widget 一定是同寄存器的，出现警告说明 dapm_seq_run() 的分批逻辑出了 bug。

pop_wait(card->pop_time) 在写之前睡 pop_time 毫秒。这是 DAC 侧给电容留的放电时间，配合 pop_time 这个可调参数用。

十二、事件回调与 widget 的 event #

DAPM 定义的事件十种，event_flags 是一个 unsigned short，前几个各占一位，所以能按位或组合：

事件宏 触发点 调用位置
SND_SOC_DAPM_PRE_PMU 上电之前 dapm_seq_run_coalesced()

事件由 dapm_seq_check_event() 统一分发：

c
static void dapm_seq_check_event(struct snd_soc_card *card,
                                 struct snd_soc_dapm_widget *w, int event)
{
        const char *ev_name;
        int power;

        switch (event) {
        case SND_SOC_DAPM_PRE_PMU:    // 上电前
                ev_name = "PRE_PMU";
                power = 1;
                break;
        case SND_SOC_DAPM_POST_PMU:   // 上电后
                ev_name = "POST_PMU";
                power = 1;
                break;
        case SND_SOC_DAPM_PRE_PMD:    // 下电前
                ev_name = "PRE_PMD";
                power = 0;
                break;
        case SND_SOC_DAPM_POST_PMD:   // 下电后
                ev_name = "POST_PMD";
                power = 0;
                break;
        case SND_SOC_DAPM_WILL_PMU:   // 处理 up_list 之前
                ev_name = "WILL_PMU";
                power = 1;
                break;
        case SND_SOC_DAPM_WILL_PMD:   // 处理 down_list 之前
                ev_name = "WILL_PMD";
                power = 0;
                break;
        default:
                WARN(1, "Unknown event %d\n", event);
                return;
        }

        if (w->new_power != power)  // 方向不对，跳过
                return;

        if (w->event && (w->event_flags & event)) { // 只发 widget 声明关心的事件
                int ret;

                pop_dbg(w->dapm->dev, card->pop_time, "pop test : %s %s\n",
                        w->name, ev_name);
                soc_dapm_async_complete(w->dapm);
                trace_snd_soc_dapm_widget_event_start(w, event);
                ret = w->event(w, NULL, event);
                trace_snd_soc_dapm_widget_event_done(w, event);
                if (ret < 0)
                        dev_err(w->dapm->dev, "ASoC: %s: %s event failed: %d\n",
                               ev_name, w->name, ret);
        }
}

if (w->new_power != power) return; 这行素材作者留下了「没太明白啥意思」的批注，这里补上：它的作用是按方向过滤。同一个 widget 会被 PRE_PMU 和 PRE_PMD 两路都调一次，new_power 是上电的 widget 只该收上电系列事件，所以用 power 这个期望值做闸门。少了这行，一次上电会同时触发 PRE_PMD。

第二个 if 是事件订阅闸门：widget 的 event_flags 里没置的位，事件发了也不回调。这就是第七章那张宏表里 MIC 关心 PRE_PMU|POST_PMD、HP 关心 POST_PMU|PRE_PMD 的实现依据。

路径更新时的事件由 dapm_widget_update() 发：

c
static void dapm_widget_update(struct snd_soc_card *card)
{
        struct snd_soc_dapm_update *update = card->update;
        struct snd_soc_dapm_widget_list *wlist;
        struct snd_soc_dapm_widget *w = NULL;
        unsigned int wi;
        int ret;

        if (!update || !dapm_kcontrol_is_powered(update->kcontrol))
                return;

        wlist = dapm_kcontrol_get_wlist(update->kcontrol);

        for_each_dapm_widgets(wlist, wi, w) {
                if (w->event && (w->event_flags & SND_SOC_DAPM_PRE_REG)) {
                        ret = w->event(w, update->kcontrol, SND_SOC_DAPM_PRE_REG);
                        if (ret != 0)
                                dev_err(w->dapm->dev, "ASoC: %s DAPM pre-event failed: %d\n",
                                           w->name, ret);
                }
        }

        if (!w)
                return;

        ret = soc_dapm_update_bits(w->dapm, update->reg, update->mask,
                update->val);
        if (ret < 0)
                dev_err(w->dapm->dev, "ASoC: %s DAPM update failed: %d\n",
                        w->name, ret);

        if (update->has_second_set) {
                ret = soc_dapm_update_bits(w->dapm, update->reg2,
                                           update->mask2, update->val2);
                if (ret < 0)
                        dev_err(w->dapm->dev,
                                "ASoC: %s DAPM update failed: %d\n",
                                w->name, ret);
        }

        for_each_dapm_widgets(wlist, wi, w) {
                if (w->event && (w->event_flags & SND_SOC_DAPM_POST_REG)) {
                        ret = w->event(w, update->kcontrol, SND_SOC_DAPM_POST_REG);
                        if (ret != 0)
                                dev_err(w->dapm->dev, "ASoC: %s DAPM post-event failed: %d\n",
                                           w->name, ret);
                }
        }
}

只在「kcontrol 的 put 触发了 DAPM」这条路上调用（card->update 非空且该 kcontrol 已上电）。节拍是：发 PRE_REG → 写寄存器（has_second_set 时写第二组）→ 发 POST_REG。这里传给回调的第二个参数是 snd_kcontrol *，不同于 dapm_seq_check_event() 传 NULL 的那个。

这个函数也解释了第 2 章开头那句话：kcontrol 的 put 回调不只改自己，还会把变化传出去。传法就是一次 dapm_power_widgets()，一路传到路径末端。

硬件写操作最后落到 soc_dapm_update_bits()，再往下就是 component 的 update_bits 回调、最终到 regmap。6.3 里 ASoC 还保留着 card->update / snd_soc_dapm_update 这套「注册式」机制，配合 dapm_kcontrol 的 put 使用；上游后续有往 snd_soc_component_driver 直连方向重构的动作，具体版本切点未验证。

逐个 dai 改状态，然后统一扫一遍。soc_dapm_dai_stream_event() 是真正改端点身份的地方：

c
static void soc_dapm_dai_stream_event(struct snd_soc_dai *dai, int stream,
        int event)
{
        struct snd_soc_dapm_widget *w;

        w = snd_soc_dai_get_widget(dai, stream);  // dai->stream[stream].widget

        if (w) {
                unsigned int ep;

                dapm_mark_dirty(w, "stream event");

                if (w->id == snd_soc_dapm_dai_in) {   // playback dai widget
                        ep = SND_SOC_DAPM_EP_SOURCE;
                        dapm_widget_invalidate_input_paths(w);
                } else {                             // capture dai widget
                        ep = SND_SOC_DAPM_EP_SINK;
                        dapm_widget_invalidate_output_paths(w);
                }

                switch (event) {
                case SND_SOC_DAPM_STREAM_START:    // 开始
                        w->active = 1;
                        w->is_ep = ep;
                        break;
                case SND_SOC_DAPM_STREAM_STOP:    // 停止
                        w->active = 0;
                        w->is_ep = 0;
                        break;
                case SND_SOC_DAPM_STREAM_SUSPEND:
                case SND_SOC_DAPM_STREAM_RESUME:
                case SND_SOC_DAPM_STREAM_PAUSE_PUSH:
                case SND_SOC_DAPM_STREAM_PAUSE_RELEASE:
                        break;
                }
        }
}

START 时播放 dai 变成 EP_SOURCE、录音 dai 变成 EP_SINK，active=1；STOP 时 is_ep=0、active=0。这就是第 8 章那张端点表里最后两行的来处——dai widget 的端点身份只在流打开期间存在，流没开的时候它什么端点都不是。

注意两个分支清缓存的方向是交叉的：播放 dai 清上游路径（invalidate_input_paths），录音 dai 清下游路径（invalidate_output_paths）。原因是它们各自在自己的信号流方向上是「另一端」。

SUSPEND/RESUME/PAUSE_* 在这版实现里对 dai widget 没有额外动作，但事件本身仍会往下传，dapm_power_widgets(event) 收到的就是这个原始事件值，用来在 dapm_seq_run() 里决定给 pre/post widget 发哪个事件。

dapm kcontrol 与普通 kcontrol 的差别只在回调。SOC_DAPM_* 系列宏把 get/put/info 换成了 DAPM 版本：

c
/* dapm kcontrol types */
#define SOC_DAPM_SINGLE(xname, reg, shift, max, invert) \
{       .iface = SNDRV_CTL_ELEM_IFACE_MIXER, .name = xname, \
        .info = snd_soc_info_volsw, \
        .get = snd_soc_dapm_get_volsw, .put = snd_soc_dapm_put_volsw, \
        .private_value = SOC_SINGLE_VALUE(reg, shift, max, invert, 0) }

拿它和普通的 SOC_SINGLE 比，iface、name、private_value 的构造完全一样，唯独 .get / .put 换成了 snd_soc_dapm_get_volsw / snd_soc_dapm_put_volsw。区别全在这两个函数里——普通版本的 put 写完寄存器就结束，DAPM 版本的 put 还要把 card->update 挂上，好让后面 dapm_widget_update() 和 dapm_power_widgets() 接手。

同族还有一批变体：

  • SOC_DAPM_DOUBLE / SOC_DAPM_DOUBLE_R：左右声道分开的位或寄存器；
  • SOC_DAPM_SINGLE_VIRT：reg = SND_SOC_NOPM 的虚拟开关，不碰硬件；
  • SOC_DAPM_SINGLE_TLV / SOC_DAPM_SINGLE_TLV_AUTODISABLE：带 TLV 音量表；
  • SOC_DAPM_SINGLE_TLV_VIRT：虚拟 + TLV；
  • SOC_DAPM_ENUM / SOC_DAPM_ENUM_EXT：枚举，Mux 用这套，ENUM_EXT 允许自定义 get/put；
  • SOC_DAPM_PIN_SWITCH：引脚开关，回调是 snd_soc_dapm_get_pin_switch / snd_soc_dapm_put_pin_switch，名字自动拼上 " Switch"。

AUTODISABLE 版本的作用前面第九章讲过：在 private_value 里把 autodisable 位打开，dapm_kcontrol_data_alloc() 见到它就多造一个 snd_soc_dapm_kcontrol 影子 widget。立体声 + autodisable 是不支持的组合，会打 Unsupported stereo autodisable control 警告。

SOC_DAPM_PIN_SWITCH(xname) 的这个宏体值得单看一眼名字拼接：

十四、自动建图：dapm 如何遍历 #

「自动建图」这个词容易误解。DAPM 不会自己去推拓扑，图完全由驱动声明。它自动的是运行时对图的遍历和判定：给定一组 widget 和边，它自己算出谁该通电。

把一次完整遍历的调用链和各自职责画出来：

text
snd_soc_dapm_sync()                      / soc_pcm_prepare() -> stream_event
        |                                        |
        +----------------+-----------------------+
                         v
              dapm_power_widgets(card, event)
                   |
                   +-- dapm_reset(card)                清 power_checked，new_power = power
                   |
                   +-- list_for_each_entry(card->dapm_dirty)     <----+
                   |       dapm_power_one_widget(w, up, down)          |
                   |            |                                       |
                   |            +-- dapm_widget_power_check(w)         |
                   |            |       +-- power_check(w)            |
                   |            |             +-- is_connected_input_ep()   |
                   |            |             |       +-- is_connected_ep(dir=IN)
                   |            |             +-- is_connected_output_ep()  |
                   |            |                     +-- is_connected_ep(dir=OUT)
                   |            |                                       |
                   |            +-- dapm_widget_set_peer_power() ----> 挂新脏项
                   |            +-- dapm_seq_insert(up_list / down_list)
                   |

                   +-- dapm_widget_update()     ->  PRE_REG / POST_REG
                   +-- dapm_seq_run(up_list)    ->  dapm_seq_run_coalesced()
                   +-- dapm_post_sequence_async()

四个遍历原语撑起全部逻辑：

原语 方向 用途 是否填/清缓存
is_connected_ep() 单方向递归 数完整路径条数 填 endpoints[dir]
dapm_widget_invalidate_paths() 单方向广度优先 连通性变了清缓存 清 endpoints[dir]
dapm_power_one_widget() 向邻居扩散 1 跳 把状态变化传给直接邻居 不动缓存
dapm_seq_insert() 有序插入 按类型排序入队 无

四个遍历的截断规则是一致的，记住一条就够：遇到 path->is_supply、path->weak、path->connect == 0 三种边，不再往下走。

遍历的性能账：dapm_stats 里累加的那几个计数就是给这事用的。DAPM_UPDATE_STAT(widget, path_checks) 和 DAPM_UPDATE_STAT(widget, neighbour_checks) 在 is_connected_ep()、dapm_supply_check_power()、dapm_generic_check_power() 里都有，debugfs 里打印出来能看出哪次同步扫得最多。缓存失效逻辑一旦漏调，这两个计数会暴涨——因为每次都要重新做完整递归。

图的规模大了以后，endpoints 缓存是必须的：没有它，dapm_generic_check_power() 每个 widget 都要做一次双向递归，复杂度是节点数乘边数。有了缓存，同一条不变子图只算一次。

一句话总结「自动建图」的实质：驱动给图，框架给遍历；声明是静态的，走通是动态的。

十五、Stream 域与路径域的区别 #

这一节把「域」这个词收口。本篇前面出现过三种分法，容易串：

分法 依据 单位 典型成员 作用
宏域 widget 的电源来源 辅助宏分组 codec / platform / path / stream 决定用哪组宏定义、reg 填不填
偏置域 偏置电压级别 snd_soc_dapm_context card / codec / platform 各一个 统一管一组的 bias level
遍历域 遍历时是否穿透 边与节点 stream 域穿透，path 域也穿透，supply 域截断 决定完整路径能走多远

真正容易混的是最后一行对应的两个概念：stream 域 和 路径域（path 域）。它们在宏分类上是并列的两组，但在遍历行为上完全对称——都不截断，都能参与完整路径统计。

那区别在哪？三条。

第一条：sname 是 stream 域独有的。 path 域那组宏（PGA/MIXER/MUX/SWITCH/DEMUX/OUT_DRV/MICBIAS）的参数里根本没有 stname 这一项，它们的宏体也不设置 .sname。只有 stream 域（AIF_IN/AIF_OUT/DAC/ADC，以及框架自建的 dai_in/dai_out）带 .sname。这个字段是 ASoC 把 dai widget 和 codec 内 widget 接起来的唯一凭据。

第二条：只有 stream 域有 active 语义。 active 位在 soc_dapm_dai_stream_event() 里被 STREAM_START 置 1、STREAM_STOP 清 0，而那个函数只处理 dai_in/dai_out。path 域的 widget 也有 active 字段，但没人给它赋值，恒为 0。debugfs 里 stream %s %s 那行只对 sname 非空的 widget 打印，所以只有 stream 域会看到 stream Playback active。

第三条：只有 stream 域会在流事件里改端点身份。 第 8 章那张端点表里，dai_in/dai_out 的 EP_SOURCE/EP_SINK 是动态的，随流开关；path 域 widget 的 is_ep 全程为 0，它们永远是中段节点，靠 dapm_generic_check_power() 的「上游有源、下游有宿」判据决定上电。

对照一下同一块 codec 里两类 widget 的实际定义：

text
SND_SOC_DAPM_DAC("Left DAC", "Playback", WM8960_POWER2, 8, 0),
SND_SOC_DAPM_MIXER("Left Output Mixer", WM8960_POWER3, 3, 0,
        &wm8960_loutput_mixer[0],
        ARRAY_SIZE(wm8960_loutput_mixer)),
SND_SOC_DAPM_PGA("LOUT1 PGA", WM8960_POWER2, 6, 0, NULL, 0),

第一行有 "Playback" 这个 sname，第二三行没有。这就是 stream 域和 path 域在代码形态上的全部差别——一个多传一个字符串。

再看 pga 的 num_kcontrols 传的是 0（NULL, 0），意味着它没有 kcontrol，dapm_new_pga() 里那个 for 循环一次都不进。这种 PGA 纯粹是个电源开关节点，作用就是给这段路径加一级串联的电源控制位。

这引出另一个常被问的问题：为什么一条路径上要有 PGA？答案在排序表里。dapm_up_seq 里 pga 是 10，mixer 是 9，dac 是 8，输出级是 12。PGA 夹在中间，正好可以充当「先开前级、后开后级」的中间台阶，也可以挂 pop 抑制的 event。

顺带说一下 snd_soc_dapm_supply 为什么在遍历里要被截断。它不是信号通路的一环，语义是「我给某个部件供电」。如果让它参与路径统计，一条 MIC → MICBIAS 的边就会被算成「MIC 有一条通往端点的路」，逻辑全乱。所以 path->is_supply 是遍历的第一道闸，w->is_supply 则让它的 power_check 换成完全不同的判据（看下游要不要它）。

最后一个易混点：snd_soc_dapm_supply（宏 SND_SOC_DAPM_SUPPLY）和 snd_soc_dapm_regulator_supply（宏 SND_SOC_DAPM_REGULATOR_SUPPLY）都归 is_supply=1、都用 dapm_supply_check_power，但在排序表里的位置差很多——supply 上电是 3、下电是 13；regulator_supply 上电是 2、下电是 14。也就是说外部 regulator 比 codec 内部 supply 更早开、更晚关。

十六、偏置电压与 VMID #

偏置电压是 DAPM 之外的另一套机制，但它和 DAPM 是同一台状态机在管，所以放这里讲。

四个级别，从 include/sound/soc-dapm.h 的 enum snd_soc_bias_level：

级别 含义 什么时候在 该域里能干什么
SND_SOC_BIAS_OFF 全关 域 idle 且允许 idle_bias_off 只有寄存器 IO
SND_SOC_BIAS_STANDBY 待机 有供给类 widget 要上电 参考电压在，模拟通路没开
SND_SOC_BIAS_PREPARE 过渡 跨越 ON 的迁移途中 给电容充放电的时间窗
SND_SOC_BIAS_ON 全开 有信号类 widget 要上电 完整信号通路工作

状态迁移由 dapm_pre_sequence_async() / dapm_post_sequence_async() 驱动，规则是不能跳级：

text
        OFF --(pre)--> STANDBY --(pre)--> PREPARE --(pre)--> ON
        ON  --(post)--> PREPARE --(post)--> STANDBY --(post)--> OFF

第 11 章讲过 dapm_pre_sequence_async() 的两个判断：从 OFF 往上先落 STANDBY，跨界 ON 先落 PREPARE。dapm_post_sequence_async() 是对称的收尾。

目标级别怎么定？三步叠加：

  1. 初始按 idle_bias_off 表态——SND_SOC_BIAS_OFF 或 SND_SOC_BIAS_STANDBY；
  2. 本轮有 widget 要上电就抬高：供给类（supply/regulator_supply/pinctrl/clock_supply/micbias）只抬到 STANDBY，其余抬到 ON，siggen/vmid 不参与；
  3. 非接地域全部对齐到全场最高值。

第 3 步的理由写在注释里：Force all contexts in the card to the same bias state if they're not ground referenced. 不接地的域偏置不一致会产生直流偏置电流，白耗电，还会引入嗡嗡声。

idle_bias_off 和 suspend_bias_off 两个位是策略开关，放在 snd_soc_dapm_context 的结构体定义最前面：

  • idle_bias_off：idle 时进 BIAS_OFF 而不是 STANDBY。省电更多，唤醒更慢。注意开了这个位的域不参与第 3 步的对齐（if (!dapm_idle_bias_off(d))）。
  • suspend_bias_off：挂起时如果域是 idle 的，进 BIAS_OFF。

实际偏置电压怎么写进硬件？交给回调：

c
static int snd_soc_dapm_set_bias_level(struct snd_soc_dapm_context *dapm,
                                       enum snd_soc_bias_level level)
{
        struct snd_soc_card *card = dapm->card;
        int ret = 0;

        trace_snd_soc_bias_level_start(card, level);

        ret = snd_soc_card_set_bias_level(card, dapm, level);
        if (ret != 0)
                goto out;

        if (!card || dapm != &card->dapm)   // 不是 card 域，即 codec 或 platform 域
                ret = snd_soc_dapm_force_bias_level(dapm, level);

        if (ret != 0)
                goto out;

        ret = snd_soc_card_set_bias_level_post(card, dapm, level);
out:
        trace_snd_soc_bias_level_done(card, level);

        return ret;
}

三段，顺序有讲究：

  1. card->set_bias_level（machine 层）——板子级动作，比如打开外部功放的电源；
  2. dapm->component->driver->set_bias_level（codec 层）——把级别写进 codec 的偏置寄存器；
  3. card->set_bias_level_post（machine 层）——板子级收尾。

machine 层被拆成 pre/post 两端包住 codec，是为了让板级动作能「先准备好、后收尾」，比如外部功放的 mute 要在 codec 偏置切换前后包住。

VMID 在这个体系里的位置。snd_soc_dapm_vmid 类型的 widget 用 SND_SOC_DAPM_VMID 宏定义，reg 没有，is_ep = EP_SOURCE，power_check = dapm_always_on_check_power——就是说它判定上电永远是 1。它在排序表里位置很靠前（上电 4、下电 9），跟 micbias 同组。

这是有道理的：VMID 是 codec 内部的中点参考电压，所有模拟级的直流工作点都建立在它上面。它必须在任何信号级上电之前就位，在任何信号级下电之后才撤。always_on 的判定配合靠前/靠后的排序，一起实现了这个约束。

VMID 还跟 pop 直接相关。枚举注释里写着 snd_soc_dapm_vmid, /* codec bias/vmid - to minimise pops */。中点电压跳变就是 pop 的物理来源，所以 VMID 的时序一错，pop 必然出现。调试 pop 时先看 dapm_up_seq/dapm_down_seq 里 vmid 的位置对不对，再看 codec 有没有在 set_bias_level 里做渐变。

一个常写错的地方：把 SND_SOC_DAPM_VMID 当成能靠寄存器控电源的 widget。它没有 reg，真的想断电只能在 codec 的 set_bias_level(STANDBY) 里动手。

十七、耳机插拔与 jack 的联动 #

前面所有机制到这里汇合：插一次耳机，走的是「GPIO 中断 → jack 上报 → pin 状态改 → DAPM 同步 → 整条路径上电」这条链。

链路逐段拆：

  1. 耳机检测脚触发中断，中断处理里调 snd_soc_jack_report() 上报事件；
  2. snd_soc_jack_report() 在声卡 card->widgets 里按名字找耳机对应的 widget（WM8960 那条路上是 Headphones），状态变了就往 card->dapm_dirty 里挂、把 widget->connected 置 1；
  3. 调 snd_soc_dapm_sync() 统一处理——内部就是 dapm_power_widgets()，整条 complete path 上的 widget 全部上电；
  4. 通过 input_report_key / input_report_switch 往上汇报 EV_KEY / EV_SW。

第 2 步和第 3 步之间的分界要记牢：snd_soc_jack_report() 只改状态，snd_soc_dapm_sync() 才切电源。这就是第 10 章末尾那句注释的意思。

connected 从 0 变 1 时，__snd_soc_dapm_set_pin() 里会调 dapm_widget_invalidate_input_paths() 和 dapm_widget_invalidate_output_paths()，把沿途所有 widget 的 endpoints[] 清回 -1。原因很实在：之前 Headphones 是断开的，所有指向它的路径统计结果都是 0，缓存里记的就是这个 0；现在通了，缓存全错，必须重算。

拔出耳机是同一条路反着走：connected 置 0，dapm_power_widgets() 重扫，整条路径下电。硬件上的顺序由排序表保证——输出级 hp/spk 在下电序列里是 4，mixer 是 6，dac 是 7，supply 是 13。先关功放、最后撤供给，两头的 pop 都能压住。

RK3399 上这条路的实测观察点：/proc/asound/card0/ 下的 jack 状态、dmesg 里 snd_soc_jack 相关的上线日志、以及 DAPM 侧的 Headphones widget 的 connected 值。三者对不上时，先确认 jack 名字和 widget 名完全一致——snd_soc_jack_report() 是按名字找的，一个字不差才对得上。

还有一个实战坑：如果 Headphones 这个 widget 定义在 codec 驱动里，而 jack 是在 machine 驱动里上报的，名字必须跨驱动严格对齐。改 codec 驱动里的 widget 名，machine 驱动的 jack 就报 ASoC: DAPM unknown pin。

插拔状态除了走 connected，还会牵涉 force。断开时 __snd_soc_dapm_set_pin() 会顺手清 force（if (status == 0) w->force = 0;），所以不要指望用 force 把一个断开的引脚强行按住——一次拔出就清掉了。

十八、DAPM 调试：debugfs 与图形化 #

DAPM 的调试绝大部分在 debugfs 里完成。挂载点：

bash
mount -t debugfs none /sys/kernel/debug
ls /sys/kernel/debug/asoc/

打开 CONFIG_DEBUG_FS 之后，每个 widget 会在所属域对应目录下生成一个同名只读文件。RK3399 上的实际路径形态（素材里原样出现的两组）：

text

也就是说目录层级是 <card 名>/<component 名>/dapm，rt5651.1-001a 是 i2c 设备名，ff880000.i2s 是 platform 设备名。

生成这些文件的是 dapm_debugfs_add_widget()：

static void dapm_debugfs_add_widget(struct snd_soc_dapm_widget *w)
{
        struct snd_soc_dapm_context *dapm = w->dapm;

        if (!dapm->debugfs_dapm || !w->name)
                return;

四个要点：文件名是 w->name；权限 0444 只读，改不了状态；w 指针存在 inode 的 i_private 里，读文件时再取出来；dapm_widget_power_fops 定义读行为。

        .read = dapm_widget_power_read_file,

读文件的实际工作在 dapm_widget_power_read_file()：

c
static ssize_t dapm_widget_power_read_file(struct file *file,
                                           char __user *user_buf,
                                           size_t count, loff_t *ppos)
{
        struct snd_soc_dapm_widget *w = file->private_data;
        struct snd_soc_card *card = w->dapm->card;
        enum snd_soc_dapm_direction dir, rdir;
        char *buf;
        int in, out;
        ssize_t ret;
        struct snd_soc_dapm_path *p = NULL;

        buf = kmalloc(PAGE_SIZE, GFP_KERNEL);
        if (!buf)
                return -ENOMEM;

        mutex_lock(&card->dapm_mutex);

        /* Supply widgets are not handled by is_connected_{input,output}_ep() */
        if (w->is_supply) {  // 供给类不参与端点统计
                in = 0;
                out = 0;
        } else {
                in = is_connected_input_ep(w, NULL, NULL);
                out = is_connected_output_ep(w, NULL, NULL);
        }

        ret = scnprintf(buf, PAGE_SIZE, "%s: %s%s  in %d out %d",
                       w->name, w->power ? "On" : "Off",
                       w->force ? " (forced)" : "", in, out);

        if (w->reg >= 0)
                ret += scnprintf(buf + ret, PAGE_SIZE - ret,
                                " - R%d(0x%x) mask 0x%x",
                                w->reg, w->reg, w->mask << w->shift);

        ret += scnprintf(buf + ret, PAGE_SIZE - ret, "\n");

        if (w->sname)
                ret += scnprintf(buf + ret, PAGE_SIZE - ret, " stream %s %s\n",
                                w->sname,
                                w->active ? "active" : "inactive");

        snd_soc_dapm_for_each_direction(dir) {
                rdir = SND_SOC_DAPM_DIR_REVERSE(dir);
                snd_soc_dapm_widget_for_each_path(w, dir, p) {
                        if (p->connected && !p->connected(p->source, p->sink))
                                continue;

                        if (!p->connect)
                                continue;

                        ret += scnprintf(buf + ret, PAGE_SIZE - ret,
                                        " %s  \"%s\" \"%s\"\n",
                                        (rdir == SND_SOC_DAPM_DIR_IN) ? "in" : "out",
                                        p->name ? p->name : "static",
                                        p->node[rdir]->name);
                }
        }
        mutex_unlock(&card->dapm_mutex);

        ret = simple_read_from_buffer(user_buf, count, ppos, buf, ret);

        kfree(buf);
        return ret;
}

输出格式三行起，逐段解释。第一行是主信息：

text
widget名: On/Off[ (forced)]  in <上游完整路径数> out <下游完整路径数>[ - R寄存器(0x十六进制) mask 0x掩码]

(forced) 表示 force 位生效，- R... mask ... 只在 reg >= 0 时才有，且打印的掩码已经左移过（w->mask << w->shift）。

第二行只在 sname 非空时出现：

text
 stream <sname> active|inactive

第三行起每条边一行：

text
 in|out  "<path 名或 static>" "<对端 widget 名>"

方向 in/out 用的是 rdir（反转后的方向），所以 in 表示「这条边指向当前 widget 的上游」。p->name 为空时打印 static，对应静态直连的边。

RK3399 播放时的真实输出：

bash
root@rk3399:/# cat /sys/kernel/debug/asoc/realtek,rt5651-codec/ff880000.i2s/dapm/Playback
Playback: On  in 1 out 10
 stream Playback active
 out  "static" "AIF1 Playback"

Playback 是 snd_soc_dapm_dai_in 类型的 widget，sname 是 Playback。三个字段的含义：On in 1 out 10 是说它上游有 1 条通到源端点的完整路径、下游有 10 条通到宿端点的；stream Playback active 说明流正在跑；out "static" "AIF1 Playback" 是它与 AIF1 Playback 之间那条静态直连边。

几条补充说明。

第 8 条是新手最容易撞的墙。DAPM 判上电用的是 out != 0 && in != 0，两头任何一个为 0 都上不了电。所以一条路径必须同时具备源端点和宿端点，缺一个整条路都白搭。验证方法：从 debugfs 里挑路径中间一个 widget，看它的 in 和 out 是不是都非零。

第 9 条值得展开。fully_routed 打开之后，input/output 类型的 widget 不再被无条件当作端点（第九章第二轮 switch 里那两个 if (!dapm->card->fully_routed)），身份完全交给 dapm_update_widget_flags() 按实际连线算。这本来是好事——避免把「中间引脚」误判成端点；代价是 route 少写一条，那个引脚就不再是端点，路径断了。

第 15 条要强调：排序表不是随便排的，它编码了 pop 抑制策略。改表之前先想清楚为什么要动。真要调整同类内部的顺序，用 subseq 字段，别动表。

第 19 条的正确连法是反过来写：SND_SOC_DAPM_SUPPLY 在 source 位置，被供给的部件在 sink 位置。wsink->is_supply && !wsource->is_supply 这个判断就是要拦住反向写法。
