一句提醒：ASoC 里所有名字匹配都靠字符串。dai_link 里写的 dai_name、of_node、platform 设备名，只要和 component 注册时算出来的名字差一个字符，绑定时就是 -EPROBE_DEFER，声卡直接不出现。这篇的重点就在这些名字是怎么算出来的。

ASoC 解决的问题一句话说清：把一颗 SoC 的音频控制器、一颗外挂 Codec 芯片、以及这块板子上它俩的实际连线关系，拆成三个互不依赖的驱动，再在运行时按名字绑定到一起。前两个可以被很多板子复用，第三个才和具体硬件相关。

一、ASoC 要解决什么 #

ALSA CORE 只认声卡（snd_card）、PCM 设备（snd_pcm）、控件（snd_kcontrol）这些软件对象。它是纯软件视角，不知道「这颗 SoC 有三个 I2S 控制器、其中一个接了一颗 I2C Codec」这种事。如果直接拿 ALSA CORE 写板级音频，你会得到一堆复制粘贴的代码：每个 SoC 一份、每个 Codec 一份、每块板子再一份。

ASoC 在 ALSA CORE 之上插了一层，把「硬件的可复用部分」和「板子的连线」切开：

  • 音频控制器的 DMA 能力、I2S 时序，是 SoC 的属性，一颗芯片写一份；
  • 编解码、Mixer、增益、DAPM 电源域，是 Codec 的属性，一颗芯片写一份；
  • 哪个 I2S 接哪个 Codec、MCLK 谁给谁、耳机检测用哪个 GPIO，是 板子的属性，一块板写一份。

拆完的结果就是三大件：Platform（SoC 侧）、Codec（芯片侧）、Machine（板级）。前两者注册进 ASoC 的核心链表等着被用，Machine 在 probe 时声明「我要这份 Platform 的这条 DAI 和这份 Codec 的这条 DAI，按 I2S 接起来」，ASoC CORE 负责把三边对齐、建 PCM、建 DAPM 图、最后注册成一张 ALSA 声卡。

对驱动作者来说，收益是具体的：

  • 写 Codec 驱动不用关心它在哪块板子上，sound/soc/codecs/ 下一份代码能跑在 RK3399、i.MX、Allwinner 上；
  • 写 SoC 平台驱动不用关心接的是 ALC5651 还是 ES8316，sound/soc/rockchip/ 下的 I2S 驱动对所有 RK3399 板子通用；
  • 换一块板子，只改 Machine 驱动或一份 dts，前后两者一个字不动。RK3399 上换个 Codec，就是改 dts 里的 simple-audio-card,codec 节点。

代价是引入了一层运行时绑定：三大件谁先谁后不确定，所以必须靠「找不到就 -EPROBE_DEFER，等对方注册好再重试」的机制活下来。这件事贯穿全篇，最后一章会集中讲。

二、三大件的分工：Machine、Platform、Codec #

三个角色不并列，是分层的：Machine 在最上层指挥，Platform 和 Codec 在下面各自干活，中间由 DAI 连接。

维度 Machine Platform Codec
关注点 板级连线：谁接谁、时钟谁给、插孔在哪 SoC 音频控制器的 DMA 与数字接口 外挂芯片的编解码、Mixer、电源
典型代码 sound/soc/generic/simple-card.c、板级 xxx-card.c sound/soc/rockchip/rockchip_i2s.c + dwc/dmaengine-pcm sound/soc/codecs/rt5651.c
主要数据结构 snd_soc_card、snd_soc_dai_link snd_soc_component + snd_soc_dai_driver + dmaengine_pcm 同样 snd_soc_component + snd_soc_dai_driver
注册入口 devm_snd_soc_register_card() devm_snd_soc_register_component() / devm_snd_dmaengine_pcm_register() devm_snd_soc_register_component()
提供的能力 决策：选哪条 DAI、什么格式、什么时钟 传输：把内存数据搬到 I2S FIFO 变换：把数字信号变成模拟、控制功放与插孔
数量关系 一张声卡 1 个，含 N 条 DAI link 一个控制器 1 份，可含多个 DAI 一颗芯片 1 份，可含多个 DAI
RK3399 实例 rt5651-sound 节点 + asoc-simple-card 平台驱动 ff880000.i2s 的 I2S0 控制器 + dmac_bus rt5651@1a，I2C1 上的 ALC5651

读完这张表就能看出 ASoC 的设计意图：Platform 和 Codec 都只描述自己，Machine 描述关系。所以 Platform 驱动里不会出现「rt5651」这个字符串，Codec 驱动里也不会出现「i2s0」。

三者的能力边界也要分清，不然出问题会找错地方：

  • Platform 负责「数据怎么走」。DMA buffer 到 I2S TX FIFO 这一段由它搬，I2S 的 BCLK/LRCLK 时序由它产生。
  • Codec 负责「数据怎么变」。收到的数字信号走 DAC 变模拟，模拟信号走 ADC 变数字，音量/静音/增益由它管。
  • Machine 负责「两边怎么谈拢」。两边都支持 I2S 而不是一个要左对齐，两边都接受 44.1kHz，MCLK 是 256 倍采样率——这些协商在 Machine 的 hw_params 里落地。

DAI（Digital Audio Interface）是横跨三者的概念。Platform 侧叫 cpu_dai，Codec 侧叫 codec_dai，两者在 Machine 的 dai_link 里各被点名一次。DAI 本身也是一种 widget，会参与 DAPM 图，这一点在十一章展开。

三、三大件如何串起来 #

串起来靠三样东西：全局链表、名字、snd_soc_pcm_runtime。

第一步，Platform 和 Codec 各自注册，都变成 snd_soc_component，挂进全局链表 component_list。这一步跟板子无关，谁先启动谁先挂。

第二步，Machine probe 时准备好 snd_soc_card，里面有 N 个 snd_soc_dai_link，每个 link 声明了三个 snd_soc_dai_link_component：cpus、codecs、platforms。每一份都只有名字（name / of_node）和 dai_name。

第三步，snd_soc_register_card() 进来，遍历每个 dai_link，调 snd_soc_add_pcm_runtime()：拿 dai_link 里的名字去 component_list 里找 component，再进 component 的 dai_list 找一个 snd_soc_dai，找到后塞进新分配的 snd_soc_pcm_runtime：

text
component_list（全局，注册即挂入）
 ├── component(rt5651)   dai_list: rt5651-aif1, rt5651-aif2
 ├── component(ff880000.i2s) dai_list: ff880000.i2s
 └── component(snd_dmaengine_pcm) ...（dwc/dmaengine 生成的 PCM component）

snd_soc_card(realtek,rt5651-codec)
 └── dai_link[0] name = ff880000.i2s-rt5651-aif1
      ├── cpus[0]      : of_node = &i2s0     dai_name = "ff880000.i2s"
      ├── codecs[0]    : of_node = &rt5651   dai_name = "rt5651-aif1"
      ├── platforms[0] : of_node = &i2s0
      └── ops = &simple_ops, init = asoc_simple_dai_init

        ↓ snd_soc_add_pcm_runtime()

rtd（snd_soc_pcm_runtime）
 ├── dais[0]       = cpu_dai(ff880000.i2s)
 ├── dais[1]       = codec_dai(rt5651-aif1)
 └── components[]  = {cpu_dai->component, codec_dai->component, platform component}

rtd 是后面所有操作的入口。PCM 打开、hw_params、trigger 都是先拿到 rtd，再通过 asoc_rtd_to_cpu(rtd, 0) / asoc_rtd_to_codec(rtd, 0) 分发到具体 DAI。这也解释了为什么 rtd->dais 的排布是「先 CPU 后 Codec」：dais[i] 是第 i 个 CPU DAI，dais[i + num_cpus] 是第 i 个 Codec DAI，asoc_rtd_to_cpu/codec 两个宏就是靠这个偏移算的。

串起来之后还不够，还得让数据流「通」。rtd 只是绑关系，真正的数据通路是 DAPM 图里的 path：snd_soc_dapm_link_dai_widgets() 把 DAI widget 和同名的 stream widget 连上，snd_soc_dapm_connect_dai_link_widgets() 把 CPU DAI 的 widget 和 Codec DAI 的 widget 连上。这两步做完，DAPM 才认为从 AIF1 Playback 到 HPOL 是一条完整通路。

四、snd_soc_dai_link：连接的描述 #

一条 snd_soc_dai_link 描述一条音频数据链路：一端是 CPU DAI，一端是 Codec DAI，外加一个 Platform（DMA）组件，加上这棵链路上 PCM 操作的脚本。它定义在 include/sound/soc.h。

c
struct snd_soc_dai_link {
        /* config - must be set by machine driver */
        const char *name;                       /* Codec name */
        const char *stream_name;                /* Stream name */

        /*
         * You MAY specify the link's CPU-side device, either by device name,
         * or by DT/OF node, but not both. If this information is omitted,
         * the CPU-side DAI is matched using .cpu_dai_name only, which hence
         * must be globally unique.
         */
        struct snd_soc_dai_link_component *cpus;
        unsigned int num_cpus;

        /* You MUST specify the link's codec, either by device name,
         * or by DT/OF node, but not both. */
        /* You MUST specify the DAI name within the codec */
        struct snd_soc_dai_link_component *codecs;
        unsigned int num_codecs;

        /* You MAY specify the link's platform/PCM/DMA driver */
        struct snd_soc_dai_link_component *platforms;
        unsigned int num_platforms;

        int id; /* optional ID for machine driver link identification */

        const struct snd_soc_pcm_stream *params;
        unsigned int num_params;

        unsigned int dai_fmt;           /* format to set on init */

        enum snd_soc_dpcm_trigger trigger[2]; /* trigger type for DPCM */

        /* codec/machine specific init - e.g. add machine controls */
        int (*init)(struct snd_soc_pcm_runtime *rtd);

        /* codec/machine specific exit - dual of init() */
        void (*exit)(struct snd_soc_pcm_runtime *rtd);

        /* optional hw_params re-writing for BE and FE sync */
        int (*be_hw_params_fixup)(struct snd_soc_pcm_runtime *rtd,
                        struct snd_pcm_hw_params *params);

        /* machine stream operations */
        const struct snd_soc_ops *ops;
        const struct snd_soc_compr_ops *compr_ops;

        /* Mark this pcm with non atomic ops */
        unsigned int nonatomic:1;
        unsigned int playback_only:1;
        unsigned int capture_only:1;
        unsigned int ignore_suspend:1;
        unsigned int symmetric_rate:1;
        unsigned int symmetric_channels:1;
        unsigned int symmetric_sample_bits:1;
        /* Do not create a PCM for this DAI link (Backend link) */
        unsigned int no_pcm:1;
        /* This DAI link can route to other DAI links at runtime (Frontend) */
        unsigned int dynamic:1;
        unsigned int dpcm_capture:1;
        unsigned int dpcm_playback:1;
        unsigned int dpcm_merged_format:1;
        unsigned int dpcm_merged_chan:1;
        unsigned int dpcm_merged_rate:1;
        /* pmdown_time is ignored at stop */
        unsigned int ignore_pmdown_time:1;
        unsigned int ignore:1;
        unsigned int stop_dma_first:1;

#ifdef CONFIG_SND_SOC_TOPOLOGY
        struct snd_soc_dobj dobj; /* For topology */
#endif
};

playback_only / capture_only bit 单向链路 单向 CODEC 要设

ops 指向的 snd_soc_ops 是链路级的 PCM 操作集，定义也在 include/sound/soc.h：

c
/* SoC audio ops */
struct snd_soc_ops {
        int (*startup)(struct snd_pcm_substream *);
        void (*shutdown)(struct snd_pcm_substream *);
        int (*hw_params)(struct snd_pcm_substream *, struct snd_pcm_hw_params *);
        int (*prepare)(struct snd_pcm_substream *);
        int (*trigger)(struct snd_pcm_substream *, int);
        int (*hw_free)(struct snd_pcm_substream *);
};
回调 时机 链路级该做什么
startup 用户 open() PCM 时，第一次打开 使能 MCLK，约束采样率
hw_params 应用下发硬件参数后 按 rate × mclk_fs 设置两端 sysclk，配 TDM 槽位
prepare 启动前准备 一般留空
trigger start / stop / pause 一般留空，DMA 那侧已接管
hw_free 释放硬件参数 对称的清理
shutdown 最后一次 close() 关闭 MCLK

cpus / codecs / platforms 的元素类型是 snd_soc_dai_link_component，注意它在 6.3 里已经不是 5.x 早期那个内嵌一长串 cpu_name/codec_of_node/platform_of_node 的 snd_soc_dai_link 老写法，而是收敛成三字段的小结构：

c
struct snd_soc_dai_link_component {
        const char *name;
        struct device_node *of_node;
        const char *dai_name;
};

三个字段的配合规则：

  • of_node 和 name 二选一。设备树场景填 of_node，CORE 拿它去比 soc_component_to_node(component)；非设备树场景填 name，比 component->name。
  • dai_name 只在选中的 component 的 dai_list 里找匹配项。填了就按名字比 dai->name 和 dai->driver->name；不填就拿该 component 的第一个 DAI。
  • of_node 也不填、name 也不填，就是 snd_soc_find_dai() 里的 dlc->of_node && ... 与 dlc->name && ... 两处判断都短路，等于不筛 component——这种写法只在 dai_name 全局唯一时安全。

设备树场景下这三个字段不是你亲手填的，snd_soc_of_parse_audio_routing 之外还有一个专门的辅助函数从 dts 里抽，simple-card 走的路径在九章展开。

PM 回调 suspend_pre/post、resume_pre/post 在 Codec 和 DAI 的 PM 动作前后插入
bias 回调 set_bias_level、set_bias_level_post 由 DAPM 调用，机器级可以在这里切外部电源
链路 dai_link、num_links 预先定义的链路数组
运行时 rtd_list、num_rtd 每条链路一个 rtd，绑定成功后挂在 rtd_list
配置 codec_conf / num_configs 给 Codec 加名字前缀，多 Codec 场景区分控件名
辅设备 aux_dev / num_aux_devs / aux_comp_list 只是功放/无 DAI 的 Codec，不参与数据流
控件 controls / num_controls 板级 kcontrol，simple-audio-card,pin-switches 就落这里
DAPM dapm_widgets/dapm_routes 驱动里写死的板级 widget 与 route
DAPM（DT） of_dapm_widgets/of_dapm_routes 从 dts 解析出来的，widgets/routing 属性落这里
链表 component_dev_list、widgets、paths、dapm_list、dapm_dirty、dobj_list component 集合、widget 集合、path 集合、DAPM 域集合、脏 widget
DAPM 上下文 dapm、dapm_stats、update 卡片级的 DAPM 域（不是某个 component 的）
状态位 instantiated、probed、fully_routed、component_chaining 等 instantiated=1 表示绑定成功；fully_routed 由 route 检查置位
杂项 pmdown_time、pop_time、drvdata 空闲关流超时（默认 5000ms）、去爆音时间、私有数据

有三点值得单独说：

pmdown_time 影响的是「PCM 停了以后多久把 DAPM 路径关掉」。默认值 pmdown_time 是模块参数，5000ms。链路级的 ignore_pmdown_time 可以让它忽略这个等待。

drvdata 是 Machine 驱动的私有数据出口。simple-card 把 struct asoc_simple_priv * 存这儿，后面 asoc_simple_hw_params 里靠 snd_soc_card_get_drvdata(rtd->card) 取回来，才能拿到 mclk_fs。

instantiated 这个位是判断「声卡到底成没成」最直接的标志，snd_soc_bind_card() 在 snd_card_register() 成功后置 1。dts 写错了、某个 DAI 迟迟不注册，这个位就一直是 0，/proc/asound/cards 里什么也不会有。

六、Machine 驱动：把 Platform 与 Codec 绑起来 #

Machine 驱动要干的事情就两件，没有第三件：

  • 构造一条（或多条）snd_soc_dai_link，把 CPU DAI 和 Codec DAI 关联起来。必填的是 cpus、codecs、name、stream_name，dai_fmt 和 init 也得给。
  • 构造一个 snd_soc_card，把它注册进 ASoC。

剩下的——建 rtd、找 component、建 PCM、连 DAPM 图、注册声卡——全由 CORE 在 snd_soc_register_card() 里替你做。

手写一个最小 Machine 驱动，代码骨架就是这样：

c
static int mycard_hw_params(struct snd_pcm_substream *substream,
                            struct snd_pcm_hw_params *params)
{
        struct snd_soc_pcm_runtime *rtd = asoc_substream_to_rtd(substream);
        struct snd_soc_dai *cpu_dai = asoc_rtd_to_cpu(rtd, 0);
        struct snd_soc_dai *codec_dai = asoc_rtd_to_codec(rtd, 0);
        unsigned int mclk = params_rate(params) * 256;
        int ret;

        /* Codec 侧 MCLK 由 SoC 的 I2S 输出提供，方向是输入 */
        ret = snd_soc_dai_set_sysclk(codec_dai, 0, mclk, SND_SOC_CLOCK_IN);
        if (ret && ret != -ENOTSUPP)
                return ret;

        /* CPU 侧把 MCLK 送出去 */
        ret = snd_soc_dai_set_sysclk(cpu_dai, 0, mclk, SND_SOC_CLOCK_OUT);
        if (ret && ret != -ENOTSUPP)
                return ret;

        return 0;
}

static const struct snd_soc_ops mycard_ops = {
        .hw_params = mycard_hw_params,
};

static struct snd_soc_dai_link mycard_dai_link = {
        .name           = "ff880000.i2s-rt5651-aif1",
        .stream_name    = "ff880000.i2s-rt5651-aif1",
        .dai_fmt        = SND_SOC_DAIFMT_I2S | SND_SOC_DAIFMT_NB_NF |
                          SND_SOC_DAIFMT_CBC_CFC,
        .ops            = &mycard_ops,
};

static struct snd_soc_card mycard = {
        .name           = "mycard",
        .dai_link       = &mycard_dai_link,
        .num_links      = 1,
};

这里 mycard_dai_link 的 cpus/codecs 都没填，得靠后续代码或 dts 补。非设备树的老写法是直接静态填 snd_soc_dai_link_component：

c
static struct snd_soc_dai_link_component mycard_cpus[] = {
        { .dai_name = "ff880000.i2s" },
};
static struct snd_soc_dai_link_component mycard_codecs[] = {
        { .name = "rt5651.1-001a", .dai_name = "rt5651-aif1" },
};

注意 Codec 的 name 写的是 rt5651.1-001a 而不是 rt5651。这个后缀是 fmt_single_name() 给 I2C 设备算出来的名字，规则在十四章。写错这一处，绑定就会卡住。

dai_fmt 的四个域必须搞清楚，它们会被 snd_soc_runtime_set_dai_fmt() 分别下发给两端的 set_fmt：

掩码 位域 取值 含义
SND_SOC_DAIFMT_FORMAT_MASK 数据对齐 I2S / RIGHT_J / LEFT_J / DSP_A / DSP_B / AC97 / PDM / MSB / LSB 帧内数据相对 LRCLK 的位置
SND_SOC_DAIFMT_CLOCK_MASK 时钟门控 CONT / GATED BCLK 是否在空闲时持续输出
SND_SOC_DAIFMT_INV_MASK 极性 NB_NF / NB_IF / IB_NF / IB_IF BCLK/LRCLK 是否反相
SND_SOC_DAIFMT_CLOCK_PROVIDER_MASK 主从 CBP_CFP / CBC_CFP / CBP_CFC / CBC_CFC 谁提供 BCLK（BP）和 LRCLK（FP）

最后一行是最容易踩的。5.x 早期用的名字是 SND_SOC_DAIFMT_CBM_CFM / CBS_CFS / CBM_CFS / CBS_CFM，含义是「Codec 是 Bit/Frames Master 还是 Slave」。6.3 已经改成语义更清楚的双向写法：

旧名（≤5.x） 新名（6.3） 含义
CBM_CFM CBP_CFP Codec 提供 BCLK 与 LRCLK
CBS_CFM CBC_CFP Codec 只提供 LRCLK
CBM_CFS CBP_CFC Codec 只提供 BCLK
CBS_CFS CBC_CFC 两端都由 CPU 提供

RK3399 + ALC5651 这块板子是 CBC_CFC：MCLK 由 I2S0 的 clk_i2sout 输出给 Codec，BCLK/LRCLK 也由 CPU 侧产生。

七、Machine 驱动的 probe 流程 #

devm_snd_soc_register_card() 是带资源管理的入口，内部就是调 snd_soc_register_card()，只是多套了一层 devres：

c
int devm_snd_soc_register_card(struct device *dev, struct snd_soc_card *card)
{
        struct snd_soc_card **ptr;
        int ret;

        ptr = devres_alloc(devm_card_release, sizeof(*ptr), GFP_KERNEL);
        if (!ptr)
                return -ENOMEM;

        ret = snd_soc_register_card(card);
        if (ret == 0) {
                *ptr = card;
                devres_add(dev, ptr);
        } else {
                devres_free(ptr);
        }

        return ret;
}

devres_alloc 注册了释放回调 devm_card_release，设备卸载时自动注销声卡，不用手写 remove。

真正的流程在 snd_soc_register_card()，定义在 sound/soc/soc-core.c：

c
int snd_soc_register_card(struct snd_soc_card *card)
{
        if (!card->name || !card->dev)
                return -EINVAL;

        dev_set_drvdata(card->dev, card);

        INIT_LIST_HEAD(&card->widgets);
        INIT_LIST_HEAD(&card->paths);
        INIT_LIST_HEAD(&card->dapm_list);
        INIT_LIST_HEAD(&card->aux_comp_list);
        INIT_LIST_HEAD(&card->component_dev_list);
        INIT_LIST_HEAD(&card->list);
        INIT_LIST_HEAD(&card->rtd_list);
        INIT_LIST_HEAD(&card->dapm_dirty);
        INIT_LIST_HEAD(&card->dobj_list);

        card->instantiated = 0;
        mutex_init(&card->mutex);
        mutex_init(&card->dapm_mutex);
        mutex_init(&card->pcm_mutex);

        return snd_soc_bind_card(card);
}

前半段是体检和初始化：name 和 dev 有一个为空就 -EINVAL；dev_set_drvdata 让后续 snd_soc_card_get_drvdata() 能反查回 card；九个链表全部 INIT_LIST_HEAD；instantiated 清零；三把锁初始化。然后交给 snd_soc_bind_card()。

snd_soc_bind_card() 是全文最长的一段，按顺序拆成九步：

步 调用 作用
1 mutex_lock(&client_mutex) + mutex_lock_nested(&card->mutex, ...) 全局锁 + 卡锁，下面所有绑定动作在里面做
2 snd_soc_dapm_init(&card->dapm, card, NULL) 建卡片级 DAPM 域，component 传 NULL
3 soc_check_tplg_fes(card) 拓扑接管检查，把匹配的 BE 链路改成 DPCM
4 soc_bind_aux_dev(card) 绑辅助设备（无 DAI 的功放之类）
5 snd_soc_add_pcm_runtime() 循环 每条 dai_link 建一个 rtd，挂进 rtd_list
6 snd_soc_card_probe(card) 回调 card->probe，置 card->probed
7 soc_probe_link_components() / soc_probe_aux_devices() / soc_probe_link_dais() 按 order 分批 probe 所有 component 与 DAI
8 soc_init_pcm_runtime() 循环 dai_link->init 回调、定格式、建 PCM 设备
9 DAPM 连图 + 控件 + route + snd_card_register() 收尾，最后注册成 ALSA 声卡

代码全长这样：

c
static int snd_soc_bind_card(struct snd_soc_card *card)
{
        struct snd_soc_pcm_runtime *rtd;
        struct snd_soc_component *component;
        struct snd_soc_dai_link *dai_link;
        int ret, i;

        mutex_lock(&client_mutex);
        mutex_lock_nested(&card->mutex, SND_SOC_CARD_CLASS_INIT);

        snd_soc_dapm_init(&card->dapm, card, NULL);

        /* check whether any platform is ignore machine FE and using topology */
        soc_check_tplg_fes(card);

        /* bind aux_devs too */
        ret = soc_bind_aux_dev(card);
        if (ret < 0)
                goto probe_end;

        /* add predefined DAI links to the list */
        card->num_rtd = 0;
        for_each_card_prelinks(card, i, dai_link) {
                ret = snd_soc_add_pcm_runtime(card, dai_link);
                if (ret < 0)
                        goto probe_end;
        }

        soc_init_card_debugfs(card);
        soc_resume_init(card);

        ret = snd_soc_dapm_new_controls(&card->dapm, card->dapm_widgets,
                                        card->num_dapm_widgets);
        if (ret < 0)
                goto probe_end;

        ret = snd_soc_dapm_new_controls(&card->dapm, card->of_dapm_widgets,
                                        card->num_of_dapm_widgets);
        if (ret < 0)
                goto probe_end;

        /* initialise the sound card only once */
        ret = snd_soc_card_probe(card);
        if (ret < 0)
                goto probe_end;

        /* probe all components used by DAI links on this card */
        ret = soc_probe_link_components(card);
        if (ret < 0) {
                dev_err(card->dev, "ASoC: failed to instantiate card %d\n", ret);
                goto probe_end;
        }

        /* probe auxiliary components */
        ret = soc_probe_aux_devices(card);
        if (ret < 0) {
                dev_err(card->dev, "ASoC: failed to probe aux component %d\n", ret);
                goto probe_end;
        }

        /* probe all DAI links on this card */
        ret = soc_probe_link_dais(card);
        if (ret < 0) {
                dev_err(card->dev, "ASoC: failed to instantiate card %d\n", ret);
                goto probe_end;
        }

        for_each_card_rtds(card, rtd) {
                ret = soc_init_pcm_runtime(card, rtd);
                if (ret < 0)
                        goto probe_end;
        }

        snd_soc_dapm_link_dai_widgets(card);
        snd_soc_dapm_connect_dai_link_widgets(card);

        ret = snd_soc_add_card_controls(card, card->controls, card->num_controls);
        if (ret < 0)
                goto probe_end;

        ret = snd_soc_dapm_add_routes(&card->dapm, card->dapm_routes,
                                      card->num_dapm_routes);
        if (ret < 0) {
                if (card->disable_route_checks) {
                        dev_info(card->dev,
                                 "%s: disable_route_checks set, ignoring errors on add_routes\n",
                                 __func__);
                } else {
                        dev_err(card->dev, "%s: snd_soc_dapm_add_routes failed: %d\n",
                                __func__, ret);
                        goto probe_end;
                }
        }

        ret = snd_soc_dapm_add_routes(&card->dapm, card->of_dapm_routes,
                                      card->num_of_dapm_routes);
        if (ret < 0)
                goto probe_end;

        /* try to set some sane longname if DMI is available */
        snd_soc_set_dmi_name(card, NULL);

        soc_setup_card_name(card, card->snd_card->shortname, card->name, NULL);
        soc_setup_card_name(card, card->snd_card->longname, card->long_name, card->name);
        soc_setup_card_name(card, card->snd_card->driver, card->driver_name, card->name);

        if (card->components) {
                ret = snd_component_add(card->snd_card, card->components);
                if (ret < 0) {
                        dev_err(card->dev, "ASoC: %s snd_component_add() failed: %d\n",
                                card->name, ret);
                        goto probe_end;
                }
        }

        ret = snd_soc_card_late_probe(card);
        if (ret < 0)
                goto probe_end;

        snd_soc_dapm_new_widgets(card);
        snd_soc_card_fixup_controls(card);

        ret = snd_card_register(card->snd_card);
        if (ret < 0) {
                dev_err(card->dev, "ASoC: failed to register soundcard %d\n", ret);
                goto probe_end;
        }

        card->instantiated = 1;
        dapm_mark_endpoints_dirty(card);
        snd_soc_dapm_sync(&card->dapm);

        /* deactivate pins to sleep state */
        for_each_card_components(card, component)
                if (!snd_soc_component_active(component))
                        pinctrl_pm_select_sleep_state(component->dev);

probe_end:
        if (ret < 0)
                soc_cleanup_card_resources(card);

        mutex_unlock(&card->mutex);
        mutex_unlock(&client_mutex);

        return ret;
}

几个关键点单独拎出来：

for_each_card_prelinks() 只遍历 card->dai_link（driver 里预定义的），不遍历拓扑动态加进来的，所以循环前要先把 card->num_rtd 归零。

card->probe 在 DAPM 控件创建之后、component probe 之前被调。这个顺序很关键：simple-card 的 simple_soc_probe 在这里建 Jack，而 Jack 需要在组件被 probe 之前就挂进 card，否则后面的 set_jack 找不到目标。

instantiated = 1 必须在 snd_card_register() 成功之后才置位。中途任何一步 goto probe_end，都会走 soc_cleanup_card_resources() 回滚，instantiated 保持 0。

最后一小段 pinctrl_pm_select_sleep_state() 容易被忽略：绑定完以后，把所有没在活跃状态（!snd_soc_component_active()）的 component 的 pinctrl 切到 sleep 态，省电。这也解释了为什么声卡起来了但 Codec 的引脚是低电平——这是正常的，播放时才切回 default。

dapm_mark_endpoints_dirty() + snd_soc_dapm_sync() 在末尾做一次电源同步，把刚刚连好的图按当前状态过一遍。同步的具体机制属于 DAPM 的话题，见 {{DAPM：Widget、Route 与 Path}}。

八、simple-audio-card：通用的 Machine 驱动 #

绝大多数板级的 Machine 驱动不需要自己写，sound/soc/generic/simple-card.c 已经把它做成了通用驱动。RK3399 这块板子用的就是它。

先明确一点：simple-card.c 和具体单板无关。它的存在意义是「dts 描述连线，驱动照单执行」。

驱动注册部分很短：

c
static const struct of_device_id simple_of_match[] = {
        { .compatible = "simple-audio-card", },
        { .compatible = "simple-scu-audio-card",
          .data = (void *)DPCM_SELECTABLE },
        {},
};
MODULE_DEVICE_TABLE(of, simple_of_match);

static struct platform_driver asoc_simple_card = {
        .driver = {
                .name = "asoc-simple-card",
                .pm = &snd_soc_pm_ops,
                .of_match_table = simple_of_match,
        },
        .probe = asoc_simple_probe,
        .remove = asoc_simple_remove,
};

module_platform_driver(asoc_simple_card);

两个 compatible：simple-audio-card 是普通模式，simple-scu-audio-card 带 DPCM_SELECTABLE 标志，允许在有多 CPU 或带 convert-* 属性时自动切成 DPCM。

probe 函数 asoc_simple_probe() 干的是「先数、再分配、再解析、最后注册」：

c
static int asoc_simple_probe(struct platform_device *pdev)
{
        struct asoc_simple_priv *priv;
        struct device *dev = &pdev->dev;
        struct device_node *np = dev->of_node;
        struct snd_soc_card *card;
        struct link_info *li;
        int ret;

        /* Allocate the private data and the DAI link array */
        priv = devm_kzalloc(dev, sizeof(*priv), GFP_KERNEL);
        if (!priv)
                return -ENOMEM;

        card = simple_priv_to_card(priv);            /* &priv->snd_card */
        card->owner             = THIS_MODULE;
        card->dev               = dev;
        card->probe             = simple_soc_probe;
        card->driver_name       = "simple-card";

        li = devm_kzalloc(dev, sizeof(*li), GFP_KERNEL);
        if (!li)
                return -ENOMEM;

        ret = simple_get_dais_count(priv, li);       /* 数一遍每链路的 cpu/codec/platform 数 */
        if (ret < 0)
                return ret;

        if (!li->link)
                return -EINVAL;

        ret = asoc_simple_init_priv(priv, li);       /* 按数量分配 dai_props / dai_link / dais / dlcs */
        if (ret < 0)
                return ret;

        if (np && of_device_is_available(np)) {
                ret = simple_parse_of(priv, li);     /* 解析 dts 属性，填 card 与 dai_link */
                if (ret < 0) {
                        dev_err_probe(dev, ret, "parse error\n");
                        goto err;
                }
        } else {
                struct asoc_simple_card_info *cinfo;
                struct snd_soc_dai_link_component *cpus;
                struct snd_soc_dai_link_component *codecs;
                struct snd_soc_dai_link_component *platform;
                struct snd_soc_dai_link *dai_link = priv->dai_link;
                struct simple_dai_props *dai_props = priv->dai_props;

                cinfo = dev->platform_data;
                if (!cinfo) {
                        dev_err(dev, "no info for asoc-simple-card\n");
                        return -EINVAL;
                }
                if (!cinfo->name || !cinfo->codec_dai.name || !cinfo->codec ||
                    !cinfo->platform || !cinfo->cpu_dai.name) {
                        dev_err(dev, "insufficient asoc_simple_card_info settings\n");
                        return -EINVAL;
                }

                cpus                  = dai_link->cpus;
                cpus->dai_name        = cinfo->cpu_dai.name;

                codecs                = dai_link->codecs;
                codecs->name          = cinfo->codec;
                codecs->dai_name      = cinfo->codec_dai.name;

                platform              = dai_link->platforms;
                platform->name        = cinfo->platform;

                card->name            = (cinfo->card) ? cinfo->card : cinfo->name;
                dai_link->name        = cinfo->name;
                dai_link->stream_name = cinfo->name;
                dai_link->dai_fmt     = cinfo->daifmt;
                dai_link->init        = asoc_simple_dai_init;
                memcpy(dai_props->cpu_dai, &cinfo->cpu_dai, sizeof(*dai_props->cpu_dai));
                memcpy(dai_props->codec_dai, &cinfo->codec_dai, sizeof(*dai_props->codec_dai));
        }

        snd_soc_card_set_drvdata(card, priv);
        asoc_simple_debug_info(priv);

        ret = devm_snd_soc_register_card(dev, card);
        if (ret < 0)
                goto err;

        devm_kfree(dev, li);
        return 0;
err:
        asoc_simple_clean_reference(card);
        return ret;
}

流程可以压成五步：

  1. devm_kzalloc 一个 asoc_simple_priv，用 simple_priv_to_card() 摸到内嵌的 snd_soc_card，填 owner、dev、probe、driver_name。
  2. simple_get_dais_count() 解析 dts，数出「几条链路、每条几个 CPU / Codec / Platform」，结果存 link_info。
  3. asoc_simple_init_priv() 按上一步的数字做一次性分配：dai_props、dai_link、dais、dlcs、codec_conf，并把 card->dai_link = priv->dai_link、card->num_links = li->link。
  4. simple_parse_of() 解析具体属性，把名字、格式、控件、路由填进去。
  5. devm_snd_soc_register_card() 交给 CORE。

link_info 在计数和解析两个阶段复用同一套遍历。第一次传入 simple_count_noml / simple_count_dpcm 只做计数，第二次传入 simple_dai_link_of / simple_dai_link_of_dpcm 真正填数据。li->cpu 是内外两层循环的开关：外层从 1 到 0 各跑一遍，第一遍处理 CPU 节点，第二遍处理 Codec 节点，注释里写明了这么做是为了让 DPCM 场景下 dummy-Codec 排在最后，保证子设备编号稳定。

asoc_simple_dai 是 Machine 层自己定义的「DAI 视图」，跟核心的 snd_soc_dai 不是一回事，别混：

        const char *name;
        unsigned int sysclk;
        int clk_direction;
        int slots;
        int slot_width;
        unsigned int tx_slot_mask;

它存的是「这条链路上这个 DAI 的时钟和 TDM 设置」：sysclk 是 MCLK 频率，clk_direction 是 SND_SOC_CLOCK_IN（0）还是 OUT（1），clk 是拿到的 struct clk *，clk_fixed 表示时钟频率写死不可调。对 CPU DAI，sysclk 对应 RK3399 的 clk_i2s0（I2S0 输出的 MCLK）；对 Codec DAI，对应 ALC5651 从 MCLK 脚收到的时钟，也就是 RK3399 I2S0 的 clk_i2sout。

simple_dai_link_of() 是真正把一条链路填出来的地方：

c
static int simple_dai_link_of(struct asoc_simple_priv *priv,
                              struct device_node *np,    /* simple-audio-card,cpu 节点 */
                              struct device_node *codec, /* simple-audio-card,codec 节点 */
                              struct link_info *li,      /* link 信息，此时全 0 */
                              bool is_top)               /* 单链路时为 1 */
{
        struct device *dev = simple_priv_to_dev(priv);
        struct snd_soc_dai_link *dai_link = simple_priv_to_link(priv, li->link);
        struct snd_soc_dai_link_component *cpus = asoc_link_to_cpu(dai_link, 0);
        struct snd_soc_dai_link_component *codecs = asoc_link_to_codec(dai_link, 0);
        struct snd_soc_dai_link_component *platforms = asoc_link_to_platform(dai_link, 0);
        struct device_node *cpu = NULL;
        struct device_node *node = NULL;
        struct device_node *plat = NULL;
        char dai_name[64];
        char prop[128];
        char *prefix = "";
        int ret, single_cpu = 0;

        cpu  = np;
        node = of_get_parent(np);          /* rt5651-sound 节点 */

        dev_dbg(dev, "link_of (%pOF)\n", node);

        /* For single DAI link & old style of DT node */
        if (is_top)
                prefix = PREFIX;            /* "simple-audio-card," */

        snprintf(prop, sizeof(prop), "%splat", prefix);
        plat = of_get_child_by_name(node, prop);

        ret = simple_parse_node(priv, cpu, li, prefix, &single_cpu);
        if (ret < 0)
                goto dai_link_of_err;

        ret = simple_parse_node(priv, codec, li, prefix, NULL);
        if (ret < 0)
                goto dai_link_of_err;

        ret = asoc_simple_parse_platform(plat, platforms);
        if (ret < 0)
                goto dai_link_of_err;

        snprintf(dai_name, sizeof(dai_name), "%s-%s",
                 cpus->dai_name, codecs->dai_name);   /* ff880000.i2s-rt5651-aif1 */

        asoc_simple_canonicalize_cpu(cpus, single_cpu);
        asoc_simple_canonicalize_platform(platforms, cpus);

        ret = simple_link_init(priv, node, codec, li, prefix, dai_name);

dai_link_of_err:
        of_node_put(plat);
        of_node_put(node);

        li->link++;

        return ret;
}

simple_parse_node() 负责把一端解析成 snd_soc_dai_link_component + asoc_simple_dai：

c
static int simple_parse_node(struct asoc_simple_priv *priv,
                             struct device_node *np,
                             struct link_info *li,
                             char *prefix,
                             int *cpu)
{
        struct device *dev = simple_priv_to_dev(priv);
        struct device_node *top = dev->of_node;
        struct snd_soc_dai_link *dai_link = simple_priv_to_link(priv, li->link);
        struct simple_dai_props *dai_props = simple_priv_to_props(priv, li->link);
        struct snd_soc_dai_link_component *dlc;
        struct asoc_simple_dai *dai;
        int ret;

        if (cpu) {                                  /* cpu 节点 */
                dlc = asoc_link_to_cpu(dai_link, 0);
                dai = simple_props_to_dai_cpu(dai_props, 0);
        } else {                                    /* codec 节点 */
                dlc = asoc_link_to_codec(dai_link, 0);
                dai = simple_props_to_dai_codec(dai_props, 0);
        }

        simple_parse_mclk_fs(top, np, dai_props, prefix);

        ret = asoc_simple_parse_dai(np, dlc, cpu);
        if (ret)
                return ret;

        ret = asoc_simple_parse_clk(dev, np, dai, dlc);
        if (ret)
                return ret;

        ret = asoc_simple_parse_tdm(np, dai);
        if (ret)
                return ret;

        return 0;
}

这里最关键的是 asoc_simple_parse_dai()，它决定了 dlc->dai_name 到底是什么：

c
static int asoc_simple_parse_dai(struct device_node *node,
                                 struct snd_soc_dai_link_component *dlc,
                                 int *is_single_link)
{
        struct of_phandle_args args;
        int ret;

        if (!node)
                return 0;

        /*
         * Get node via "sound-dai = <&phandle port>"
         * it will be used as xxx_of_node on soc_bind_dai_link()
         */
        ret = of_parse_phandle_with_args(node, DAI, CELL, 0, &args);
        if (ret)
                return ret;

        ret = snd_soc_of_get_dai_name(node, &dlc->dai_name);
        if (ret < 0)
                return ret;

        dlc->of_node = args.np;

}

DAI 和 CELL 分别是 "sound-dai" 和 "#sound-dai-cells"。of_parse_phandle_with_args 取 phandle 指向的节点（&i2s0 / &rt5651）存进 dlc->of_node；snd_soc_of_get_dai_name() 再去 component_list 里找这个节点对应的 component，从中取出 DAI 名字：

c
int snd_soc_get_dai_name(const struct of_phandle_args *args,
                                const char **dai_name)
{
        struct snd_soc_component *pos;
        int ret = -EPROBE_DEFER;

        mutex_lock(&client_mutex);
        for_each_component(pos) {
                struct device_node *component_of_node = soc_component_to_node(pos);

                if (component_of_node != args->np || !pos->num_dai)
                        continue;

                ret = snd_soc_component_of_xlate_dai_name(pos, args, dai_name);
                if (ret == -ENOTSUPP) {
                        struct snd_soc_dai *dai;
                        int id = -1;

                        switch (args->args_count) {   /* <&phandle port> 里的 port */
                        case 0:
                                id = 0; /* same as dai_drv[0] */
                                break;
                        case 1:
                                id = args->args[0];
                                break;
                        default:
                                break;
                        }

                        if (id < 0 || id >= pos->num_dai) {
                                ret = -EINVAL;
                                continue;
                        }

                        ret = 0;

                        /* find target DAI */
                        for_each_component_dais(pos, dai) {
                                if (id == 0)
                                        break;
                                id--;
                        }

                        *dai_name = dai->driver->name;
                        if (!*dai_name)
                                *dai_name = pos->name;
                } else if (ret) {
                        continue;
                }

                break;
        }
        mutex_unlock(&client_mutex);
        return ret;
}

这段回答了一个很常见的问题：sound-dai = <&rt5651> 里只有设备节点没有 DAI 名，到底选了哪条 DAI？答案是 args_count == 0 时默认 id = 0，取 component 的 dai_list 第一条，也就是 dai_drv[0]。ALC5651 的两条 DAI 是 rt5651-aif1（id 0）和 rt5651-aif2（id 1），所以默认选 rt5651-aif1。要选第二条，就写 sound-dai = <&rt5651 1>，port 从 0 起算。

顺便注意开头那个 ret = -EPROBE_DEFER：循环里一个 component 都没匹配上时，返回的是 -EPROBE_DEFER 而不是 -ENODEV，这就是 Codec 驱动比 Machine 驱动晚加载时声卡还能自动补绑的原因。

asoc_simple_parse_clk() 解析时钟：

c
int asoc_simple_parse_clk(struct device *dev,
                          struct device_node *node,
                          struct asoc_simple_dai *simple_dai,
                          struct snd_soc_dai_link_component *dlc)
{
        struct clk *clk;
        u32 val;

        clk = devm_get_clk_from_child(dev, node, NULL);
        simple_dai->clk_fixed = of_property_read_bool(node, "system-clock-fixed");
        if (!IS_ERR(clk)) {
                simple_dai->sysclk = clk_get_rate(clk);
                simple_dai->clk = clk;
        } else if (!of_property_read_u32(node, "system-clock-frequency", &val)) {
                simple_dai->sysclk = val;
                simple_dai->clk_fixed = true;
        } else {
                clk = devm_get_clk_from_child(dev, dlc->of_node, NULL);
                if (!IS_ERR(clk))
                        simple_dai->sysclk = clk_get_rate(clk);
        }

        if (of_property_read_bool(node, "system-clock-direction-out"))
                simple_dai->clk_direction = SND_SOC_CLOCK_OUT;

        return 0;
}

devm_get_clk_from_child(dev, node, NULL) 的 con_id 传 NULL，实际走到 of_clk_get_by_name(np, NULL)，拿的是 clocks 属性里的第 0 个。所以 dts 里 clocks 的顺序决定拿哪个时钟：

text
/* i2s0 节点 */
clock-names = "i2s_clk", "i2s_hclk";
clocks = <&cru SCLK_I2S0_8CH>, <&cru HCLK_I2S0_8CH>;

/* rt5651 节点 */
clocks = <&cru SCLK_I2S_8CH_OUT>;
clock-names = "mclk";

i2s0 取到 SCLK_I2S0_8CH，对应 clk_i2s0；rt5651 取到 SCLK_I2S_8CH_OUT，对应 clk_i2sout，也就是 I2S0 送到 Codec 的 MCLK。两边如果是同一个源，sysclk 数值应当一致；不一致就说明时钟树配错了，hw_params 阶段 set_sysclk 会把不同频率分别写给两端，直接导致采样率错。

asoc_simple_hw_params() 是整条链路协商时钟的地方：

c
int asoc_simple_hw_params(struct snd_pcm_substream *substream,
                          struct snd_pcm_hw_params *params)
{
        struct snd_soc_pcm_runtime *rtd = asoc_substream_to_rtd(substream);
        struct asoc_simple_dai *pdai;
        struct snd_soc_dai *sdai;
        struct asoc_simple_priv *priv = snd_soc_card_get_drvdata(rtd->card);
        struct simple_dai_props *props = simple_priv_to_props(priv, rtd->num);
        unsigned int mclk, mclk_fs = 0;
        int i, ret;

        if (props->mclk_fs)
                mclk_fs = props->mclk_fs;

        if (mclk_fs) {
                struct snd_soc_component *component;
                mclk = params_rate(params) * mclk_fs;

                for_each_prop_dai_codec(props, i, pdai) {
                        ret = asoc_simple_set_clk_rate(rtd->dev, pdai, mclk);
                        if (ret < 0)
                                return ret;
                }

                for_each_prop_dai_cpu(props, i, pdai) {
                        ret = asoc_simple_set_clk_rate(rtd->dev, pdai, mclk);
                        if (ret < 0)
                                return ret;
                }

                for_each_rtd_components(rtd, i, component) {
                        ret = snd_soc_component_set_sysclk(component, 0, 0, mclk, SND_SOC_CLOCK_IN);
                        if (ret && ret != -ENOTSUPP)
                                return ret;
                }

                for_each_rtd_codec_dais(rtd, i, sdai) {
                        ret = snd_soc_dai_set_sysclk(sdai, 0, mclk, SND_SOC_CLOCK_IN);
                        if (ret && ret != -ENOTSUPP)
                                return ret;
                }

                for_each_rtd_cpu_dais(rtd, i, sdai) {
                        ret = snd_soc_dai_set_sysclk(sdai, 0, mclk, SND_SOC_CLOCK_OUT);
                        if (ret && ret != -ENOTSUPP)
                                return ret;
                }
        }

        for_each_prop_dai_codec(props, i, pdai) {
                sdai = asoc_rtd_to_codec(rtd, i);
                ret = asoc_simple_set_tdm(sdai, pdai, params);
                if (ret < 0)
                        return ret;
        }

        for_each_prop_dai_cpu(props, i, pdai) {
                sdai = asoc_rtd_to_cpu(rtd, i);
                ret = asoc_simple_set_tdm(sdai, pdai, params);
                if (ret < 0)
                        return ret;
        }

        return 0;
}

这段是 simple-audio-card,mclk-fs 的全部存在意义：mclk = rate × mclk_fs，然后把 mclk 依次写给 Codec DAI（方向 IN）、CPU DAI（方向 OUT）以及所有 component。RK3399 这块板子 mclk-fs = <256>，44.1kHz 时 MCLK 就是 11.2896MHz。

RK_PD4 就是 GPIO4_D4。硬件上这个脚接耳机插座的检测触点：插入时金属触点接地，电平翻转触发中断。ALC5651 的 IRQ 脚也接在这个网络上，所以同一个引脚能同时报耳机和麦克风事件——两条 Jack 共用一根中断线，靠 Codec 读中断状态寄存器区分。

优先级从低到高是：顶层节点 → dai-link 节点 → cpu/codec 节点。所以想覆盖全局设置，就在对应的子节点里再写一次 mclk-fs。

单链路场景用 simple-audio-card,cpu / simple-audio-card,codec 这两个子节点就够了。多条链路要改成 simple-audio-card,dai-link@N 写法：

dts
simple-audio-card,dai-link@0 {
        format = "i2s";
        cpu {
                sound-dai = <&i2s0>;
        };
        codec {
                sound-dai = <&rt5651>;
        };
};

simple-audio-card,dai-link@1 {
        format = "i2s";
        cpu {
                sound-dai = <&i2s>;
        };
        codec {
                sound-dai = <&hdmi>;
        };
};

注意 dai-link 下面子节点名不带 simple-audio-card, 前缀（因为 is_top 为假，prefix 为空字符串），属性也是 format 而不是 simple-audio-card,format。混用会解析不到。一个节点里 CPU 多于一个、或带 convert-rate / convert-channels 时，simple-scu-audio-card 会自动切成 DPCM 的 FE/BE 组合。

十、Platform 驱动：DMA 与 DAI #

Platform 驱动管两件事：把数据搬进/搬出 I2S FIFO（DMA），以及在数字接口上产生符合格式的时序（CPU DAI）。这两件事在代码上分属两个注册动作，但都由同一个平台设备承载。

涉及的数据结构就四个：

结构 位置 职责
snd_soc_dai include/sound/soc-dai.h CPU 侧 DAI 的运行时实例
snd_soc_dai_driver 同上 DAI 的能力与回调，驱动里静态定义
snd_soc_component include/sound/soc-component.h 统一容器，Platform 和 Codec 都用它
snd_soc_component_driver 同上 component 的操作与 DAPM 描述

Platform 的注册路径和 Codec 完全一样，都是 devm_snd_soc_register_component()，差别只在于 snd_soc_component_driver 里填的回调：Codec 填 read/write/controls，Platform 填 pcm_construct、trigger、pointer 这些 PCM 侧的。RK3399 的 I2S 驱动真正注册 PCM 能力走的是另一条路，devm_snd_dmaengine_pcm_register()，十二章展开。

一句话区分：Platform 的 component 描述 I2S 控制器本身，DMA 引擎另起一个 component 描述「用哪条 DMA 通道搬数据」。两张 component 都在 component_list 里，Machine 的 dai_link->platforms 指向的多是前者，后者由 soc_new_pcm() → snd_soc_pcm_component_new() 通过 pcm_construct 挂到 rtd 上。

RK3399 有 DMAC0 和 DMAC1 两个控制器。手册里 DMAC0 是 6 通道、12 个外设请求，DMAC1 是 8 通道、20 个外设请求。实测 /sys/class/dma/ 下：

text
dma0chan0 .. dma0chan11  -> ../../devices/platform/ff6d0000.dma-controller/dma/dma0chan0/
dma1chan0 .. dma1chan19  -> ../../devices/platform/ff6e0000.dma-controller/dma/dma1chan0/

DMAC0 出来 12 个通道、DMAC1 出来 20 个，和「每种外设请求注册成一个通道」的说法对得上——一个物理通道可以服务多个请求，软件层面按请求拆成 virtual channel。

I2S0 的 DMA 请求在 dts 里这样绑：

dts
i2s0: i2s@ff880000 {
        dmas = <&dmac_bus 0>, <&dmac_bus 1>;
        dma-names = "tx", "rx";
        ......
};

dmas 里每个条目是 <&控制器 请求号>，dma-names 给每个条目起名。dma_request_chan(dev, "tx") 就是按这个名字去 dma-names 里查下标，再取对应 dmas 条目。名字必须是 tx / rx，因为 dmaengine_pcm_dma_channel_names[] 里写死了：

c
static const char * const dmaengine_pcm_dma_channel_names[] = {
        [SNDRV_PCM_STREAM_PLAYBACK] = "tx",
        [SNDRV_PCM_STREAM_CAPTURE]  = "rx",
};

写成 "playback" / "capture" 就永远请求不到通道，声卡能起来但 aplay 报 -ENXIO。

十一、snd_soc_dai 与 snd_soc_dai_driver #

DAI 是三大件的公共词汇，所以单独拉一章讲透。snd_soc_dai 是运行时实例，snd_soc_dai_driver 是静态描述，两者在 snd_soc_register_dai() 里配对。

这四个字段在数据通路里全是关键：

  • tdm_mask：TDM 槽位掩码，hw_params 时用来修正 codec 侧参数。

十二、Platform 的 DMA 框架 #

音频 DMA 的用法和别的外设不一样：不是传完一次就结束，而是一直在环形 buffer 上循环，每个 period 边界发一次中断让应用补数据。内核 DMA 框架为此专门提供了循环传输模式。

先把 DMA 本身的几个关键概念摆清楚，后面看代码才不晕。

传输宽度（transfer width）。内存到内存可以按总线最大宽度（32/64 位）搬，但音频设备得按 16 位或 24 位精确写。所以每次传输必须告诉控制器「源/目标寄存器多宽」。枚举是 dma_slave_buswidth，以字节为单位：1、2、3、4、8、16、32、64、128 字节。

突发长度（burst size）。控制器内部有个 FIFO，源是内存时一次读一批进来再慢慢送，目标是内存时先攒够一批再写出去。这一批的大小就是 burst。dma_device 里用 min_burst/max_burst 声明范围。RK3399 的 I2S 驱动里，这个值取 FIFO 深度的一半左右比较稳。

缓存一致性。CPU 有自己的 cache，DMA 直接读写内存，两边看到的数据会不一致。解法分两类：

  • 一致性 DMA 映射：dma_alloc_coherent() 拿一块系统预留内存，映射为非缓存。生命周期长，一般跟驱动同寿。
  • 流式 DMA 映射：普通 kmalloc 的内存也能用，但要在传输前后做 dma_map_single / dma_unmap_single、必要时 dma_sync_*_for_* 刷 cache。生命周期短，用完就恢复。

音频 buffer 走的是前者的变体：snd_pcm_lib_malloc_pages() 分配，底层用 dma_alloc_coherent 或 dma_alloc_attrs 拿物理连续或 IOMMU 映射的内存，所以 runtime->dma_addr 是一个 DMA 能直接访问的物理地址，播放时直接拿去配 dst_addr。

device_pause / device_resume 暂停/恢复

cap_mask 里跟音频相关的是 DMA_CYCLIC。它的语义在 dma_transaction_type 的注释里写得很清楚：一组块首尾相接成环，最后一项指回第一项。音频的场景就是「一个环形 buffer，应用不停地往里填」。

struct dma_chan 里 cookie 和 completed_cookie 是两个单调递增的 32 位计数（typedef s32 dma_cookie_t），每次 dmaengine_submit() 递增一次，控制器完成后更新 completed_cookie，两者比较就能判断某个描述符有没有跑完：

c
static inline enum dma_status dma_async_is_complete(dma_cookie_t cookie,
                        dma_cookie_t last_complete, dma_cookie_t last_used)
{
        if (last_complete <= last_used) {
                if ((cookie <= last_complete) || (cookie > last_used))
                        return DMA_COMPLETE;
        } else {
                if ((cookie <= last_complete) && (cookie > last_used))
                        return DMA_COMPLETE;
        }
        return DMA_IN_PROGRESS;
}

注意那个 last_complete > last_used 的分支：cookie 是 s32，递增到溢出会绕回负数，这个分支专门处理绕回。音频循环传输跑上几小时必然绕回，这段比较逻辑的正确性直接决定会不会误报 xrun。

struct dma_slave_config 是客户端配通道的参数包：

c
struct dma_slave_config {
        enum dma_transfer_direction direction;
        phys_addr_t src_addr;
        phys_addr_t dst_addr;
        enum dma_slave_buswidth src_addr_width;
        enum dma_slave_buswidth dst_addr_width;
        u32 src_maxburst;
        u32 dst_maxburst;
        u32 src_port_window_size;
        u32 dst_port_window_size;
        bool device_fc;
        void *peripheral_config;
        size_t peripheral_size;
};

音频只用得上其中四个：方向、地址、宽度、burst。src_port_window_size / dst_port_window_size 是给「用一片寄存器窗口而不是单个寄存器收数据」的设备用的，I2S 用不上。device_fc 是流控设置，音频一般填 false，让 DMA 控制器做流控。

struct dma_async_tx_descriptor 描述一次具体传输，由 device_prep_* 创建，tx_submit 提交。callback / callback_param 是完成回调，音频里填的是 dmaengine_pcm_dma_complete 和当前 substream。

DMA 注册流程。控制器驱动自己 dma_async_device_register()，把这套东西挂进 dma_device_list。函数里有一堆能力校验，声明了 DMA_CYCLIC 却没实现 device_prep_dma_cyclic 会直接 -EIO：

c
if (dma_has_cap(DMA_CYCLIC, device->cap_mask) && !device->device_prep_dma_cyclic) {
        dev_err(device->dev,
                "Device claims capability %s, but op is not defined\n",
                "DMA_CYCLIC");
        return -EIO;
}

这一句对音频驱动的含义很直白：控制器驱动没实现 device_prep_dma_cyclic，音频就跑不起来，soc_new_pcm() 之后的第一次 trigger START 会拿不到描述符返回 -ENOMEM。

客户端五步走，音频驱动也是照这五步来的：

  1. dma_request_chan(dev, "tx") 按名字要通道；
  2. dmaengine_slave_config(chan, &cfg) 配方向/地址/宽度/burst；
  3. dmaengine_prep_dma_cyclic(...) 拿描述符；
  4. dmaengine_submit(desc) 提交进队列；
  5. dma_async_issue_pending(chan) 启动。

dma_request_chan() 在设备树场景下走 of_dma_request_slave_channel()：

c
struct dma_chan *of_dma_request_slave_channel(struct device_node *np,
                                              const char *name)
{
        struct of_phandle_args  dma_spec;
        struct of_dma           *ofdma;
        struct dma_chan         *chan;
        int                     count, i, start;
        int                     ret_no_channel = -ENODEV;
        static atomic_t         last_index;

        /* Silently fail if there is not even the "dmas" property */
        if (!of_find_property(np, "dmas", NULL))
                return ERR_PTR(-ENODEV);

        count = of_property_count_strings(np, "dma-names");
        if (count < 0)
                return ERR_PTR(-ENODEV);

        start = atomic_inc_return(&last_index);
        for (i = 0; i < count; i++) {
                if (of_dma_match_channel(np, name, (i + start) % count, &dma_spec))
                        continue;

                mutex_lock(&of_dma_lock);
                ofdma = of_dma_find_controller(&dma_spec);

                if (ofdma) {
                        chan = ofdma->of_dma_xlate(&dma_spec, ofdma);
                } else {
                        ret_no_channel = -EPROBE_DEFER;
                        chan = NULL;
                }

                mutex_unlock(&of_dma_lock);
                of_node_put(dma_spec.np);

                if (chan)
                        return chan;
        }

        return ERR_PTR(ret_no_channel);
}

last_index 那个原子计数是为了在同名多通道之间做轮转分配。控制器还没注册时返回 -EPROBE_DEFER，客户端 probe 会重来。

十三、PCM 数据通路的建立 #

这一章把「数据从应用 write() 到最后进 I2S FIFO」这条链上的 ASoC 侧环节串一遍。ALSA 内核驱动的通用部分见 {{ALSA 框架与声卡设备}}，这里只看 ASoC 补了什么。

第一段：注册期，soc_new_pcm() 挂操作集。

soc_init_pcm_runtime() 在绑定流程里对每个 rtd 调 soc_new_pcm(rtd, num)。这个函数干三件与数据通路相关的事：

  • 选一组 PCM 操作集填进 rtd->ops；
  • 调 snd_pcm_set_ops() 把它们挂到 snd_pcm 的 playback / capture stream 上；
  • 调 snd_soc_pcm_component_new(rtd)，让所有 component 的 pcm_construct 有机会挂进来。

操作集的选法就是看 dynamic 位：

RK3399 这条链路 dynamic 为 0，所以走 soc_pcm_* 那一套。i2s0 和 rt5651 都没实现 copy_user/page/mmap，循环里一个 if 都不进；只有 dmaengine PCM 那个 component 的 ioctl 等会被挂上。这解释了一个现象：aplay 用 mmap 模式读写时，走的是通用的 snd_pcm_lib_* 路径，runtime->dma_area 直接映射给用户态，不经过任何 ASoC 回调。

第二段：open() 时，soc_pcm_open() 依次启动组件与 DAI。

c
static int __soc_pcm_open(struct snd_soc_pcm_runtime *rtd,
                          struct snd_pcm_substream *substream)
{
        struct snd_soc_component *component;
        struct snd_soc_dai *dai;
        int i, ret = 0;

        snd_soc_dpcm_mutex_assert_held(rtd);

        for_each_rtd_components(rtd, i, component)
                pinctrl_pm_select_default_state(component->dev);

        ret = snd_soc_pcm_component_pm_runtime_get(rtd, substream);
        if (ret < 0)
                goto err;

        ret = soc_pcm_components_open(substream);
        if (ret < 0)
                goto err;

        ret = snd_soc_link_startup(substream);      /* dai_link->ops->startup */
        if (ret < 0)
                goto err;

        /* startup the audio subsystem */
        for_each_rtd_dais(rtd, i, dai) {
                ret = snd_soc_dai_startup(dai, substream);  /* dai->driver->ops->startup */
                if (ret < 0)
                        goto err;
        }

        /* Dynamic PCM DAI links compat checks use dynamic capabilities */
        if (rtd->dai_link->dynamic || rtd->dai_link->no_pcm)
                goto dynamic;

        /* Check that the codec and cpu DAIs are compatible */
        soc_pcm_init_runtime_hw(substream);

        soc_pcm_update_symmetry(substream);

        ret = soc_hw_sanity_check(substream);
        if (ret < 0)
                goto err;

        soc_pcm_apply_msb(substream);

        /* Symmetry only applies if we've already got an active stream. */
        for_each_rtd_dais(rtd, i, dai) {
                ret = soc_pcm_apply_symmetry(substream, dai);
                if (ret != 0)
                        goto err;
        }
dynamic:
        snd_soc_runtime_activate(rtd, substream->stream);
        ret = 0;
err:
        if (ret < 0)
                soc_pcm_clean(rtd, substream, 1);

        return soc_pcm_ret(rtd, ret);
}

open() 阶段干的事，按顺序：

  1. 所有 component 的 pinctrl 切 default —— 上一章末尾 snd_soc_bind_card() 把没活跃的切去了 sleep，这里切回来。
  2. pm_runtime_get，把 Codec 的 runtime PM 引用计数加一。
  3. soc_pcm_components_open()，调每个 component 的 open。
  4. dai_link->ops->startup() —— 板级 asoc_simple_startup 在这里打开 MCLK。
  5. 每个 DAI 的 startup() —— Codec DAI 和 CPU DAI 各自的启动。
  6. soc_pcm_init_runtime_hw() 把两端能力求交，填 runtime->hw。
  7. snd_soc_runtime_activate() 把这条流标记为活跃。

第 4 步和第 5 步的先后是关键：链路级 startup 先于 DAI startup。这就是为什么 simple-card 能在 asoc_simple_startup 里把时钟开起来、加采样率约束，而不必担心 Codec 还没准备好。

第三段：hw_params 时，参数逐层下发。

调用链是这样的，从上到下：

__soc_pcm_hw_params() 的实体：

c
static int __soc_pcm_hw_params(struct snd_soc_pcm_runtime *rtd,
                               struct snd_pcm_substream *substream,
                               struct snd_pcm_hw_params *params)
{
        struct snd_soc_dai *cpu_dai;
        struct snd_soc_dai *codec_dai;
        int i, ret = 0;

        snd_soc_dpcm_mutex_assert_held(rtd);

        ret = soc_pcm_params_symmetry(substream, params);
        if (ret)
                goto out;

        ret = snd_soc_link_hw_params(substream, params);   /* 链路级先行 */
        if (ret < 0)
                goto out;

        for_each_rtd_codec_dais(rtd, i, codec_dai) {
                struct snd_pcm_hw_params codec_params;
                unsigned int tdm_mask = snd_soc_dai_tdm_mask_get(codec_dai, substream->stream);

                if (!snd_soc_dai_stream_valid(codec_dai, substream->stream))
                        continue;

                /* copy params for each codec */
                codec_params = *params;

                /* fixup params based on TDM slot masks */
                if (tdm_mask)
                        soc_pcm_codec_params_fixup(&codec_params, tdm_mask);

                ret = snd_soc_dai_hw_params(codec_dai, substream, &codec_params);
                if (ret < 0)
                        goto out;

                soc_pcm_set_dai_params(codec_dai, &codec_params);
                snd_soc_dapm_update_dai(substream, &codec_params, codec_dai);
        }

        for_each_rtd_cpu_dais(rtd, i, cpu_dai) {
                if (!snd_soc_dai_stream_valid(cpu_dai, substream->stream))
                        continue;

                ret = snd_soc_dai_hw_params(cpu_dai, substream, params);
                if (ret < 0)
                        goto out;

                soc_pcm_set_dai_params(cpu_dai, params);
                snd_soc_dapm_update_dai(substream, params, cpu_dai);
        }

        ret = snd_soc_pcm_component_hw_params(substream, params);
out:
        if (ret < 0)
                soc_pcm_hw_clean(rtd, substream, 1);

        return soc_pcm_ret(rtd, ret);
}

顺序是「先链路级，再 Codec DAI，再 CPU DAI，最后 component」。这个顺序有实际后果：asoc_simple_hw_params 在链路级把 MCLK 设成 rate × mclk_fs，之后 Codec DAI 的 rt5651_hw_params 才能基于已经设好的 PLL 和时钟去算分频系数。反过来就锁不住。

codec_params 是 *params 的副本，不是同一份。TDM 场景下 soc_pcm_codec_params_fixup() 会改副本的通道数，CPU 侧仍拿原 params。这样一侧用 TDM 8 通道、另一侧按单声道处理是合法的。

soc_pcm_trigger() 最终落到 dmaengine PCM component 的 trigger：

snd_dmaengine_pcm_trigger() 把 ALSA 的触发命令翻译成 DMA 动作：

c
int snd_dmaengine_pcm_trigger(struct snd_pcm_substream *substream, int cmd)
{
        struct dmaengine_pcm_runtime_data *prtd = substream_to_prtd(substream);
        struct snd_pcm_runtime *runtime = substream->runtime;
        int ret;

        switch (cmd) {
        case SNDRV_PCM_TRIGGER_START:
                ret = dmaengine_pcm_prepare_and_submit(substream);
                if (ret)
                        return ret;
                dma_async_issue_pending(prtd->dma_chan);
                break;
        case SNDRV_PCM_TRIGGER_RESUME:
        case SNDRV_PCM_TRIGGER_PAUSE_RELEASE:
                dmaengine_resume(prtd->dma_chan);
                break;
        case SNDRV_PCM_TRIGGER_SUSPEND:
                if (runtime->info & SNDRV_PCM_INFO_PAUSE)
                        dmaengine_pause(prtd->dma_chan);
                else
                        dmaengine_terminate_async(prtd->dma_chan);
                break;
        case SNDRV_PCM_TRIGGER_PAUSE_PUSH:
                dmaengine_pause(prtd->dma_chan);
                break;
        case SNDRV_PCM_TRIGGER_STOP:
                dmaengine_terminate_async(prtd->dma_chan);
                break;
        default:
                return -EINVAL;
        }

        return 0;
}

dmaengine_pcm_prepare_and_submit() 是「取描述符 + 挂回调 + 提交」三合一：

c
static int dmaengine_pcm_prepare_and_submit(struct snd_pcm_substream *substream)
{
        struct dmaengine_pcm_runtime_data *prtd = substream_to_prtd(substream);
        struct dma_chan *chan = prtd->dma_chan;
        struct dma_async_tx_descriptor *desc;
        enum dma_transfer_direction direction;
        unsigned long flags = DMA_CTRL_ACK;

        direction = snd_pcm_substream_to_dma_direction(substream);

        if (!substream->runtime->no_period_wakeup)
                flags |= DMA_PREP_INTERRUPT;

        prtd->pos = 0;
        desc = dmaengine_prep_dma_cyclic(chan,
                substream->runtime->dma_addr,
                snd_pcm_lib_buffer_bytes(substream),
                snd_pcm_lib_period_bytes(substream), direction, flags);

        if (!desc)
                return -ENOMEM;

        desc->callback = dmaengine_pcm_dma_complete;
        desc->callback_param = substream;
        prtd->cookie = dmaengine_submit(desc);

        return 0;
}

三个地址参数把 ALSA buffer 和 DMA 连起来了：

  • runtime->dma_addr：buffer 的物理地址，snd_pcm_lib_malloc_pages() 给的；
  • snd_pcm_lib_buffer_bytes()：整环大小；
  • snd_pcm_lib_period_bytes()：每个 period 的大小，也就是中断触发间隔。

DMA_PREP_INTERRUPT 决定每个 period 结束是否中断。no_period_wakeup 为真时省掉中断，用于只关心整块缓冲区的场景。

dmaengine_pcm_dma_complete() 在中断上下文里被调，更新 prtd->pos 并调 snd_pcm_period_elapsed() 通知 ALSA 层。上层 aplay 的 poll/read 就是从这儿被唤醒的。

完整通路示意：

text
用户空间 write()
   ↓ mmap 映射的 runtime->dma_area，直接写环形 buffer
ALSA PCM 中间层：snd_pcm_lib_write / mmap frame copy
   ↓ appl_ptr 前移，判断是否越过 period 边界
   ↓ 触发 SNDRV_PCM_TRIGGER_START（首次）
soc_pcm_trigger → component->trigger → dmaengine_pcm_trigger
   ↓
dmaengine_prep_dma_cyclic(dma_addr, buffer_bytes, period_bytes)
dmaengine_submit → dma_async_issue_pending
   ↓
DMAC（dmac_bus / DMAC0/1）读内存 → 写 I2S0 TXDR（0xff880000 + 0x0024）
   ↓
I2S0 按 BCLK/LRCLK 时序串行输出到 ALC5651 AIF1
   ↓
ALC5651 DAC → HPO L/R → HPOL/HPOR → Headphones

capture 方向就是把每条箭头的方向反过来，地址换成 RXDR（偏移 0x0028），DMA 方向换成 DMA_DEV_TO_MEM。

prtd 是 dmaengine_pcm_runtime_data，挂在 substream->runtime->private_data 上，存 dma_chan、cookie、pos 这三样。snd_dmaengine_pcm_open() 里分配：

c
int snd_dmaengine_pcm_open(struct snd_pcm_substream *substream,
        struct dma_chan *chan)
{
        struct dmaengine_pcm_runtime_data *prtd;
        int ret;

        if (!chan)
                return -ENXIO;

        ret = snd_pcm_hw_constraint_integer(substream->runtime,
                                            SNDRV_PCM_HW_PARAM_PERIODS);
        if (ret < 0)
                return ret;

        prtd = kzalloc(sizeof(*prtd), GFP_KERNEL);
        if (!prtd)
                return -ENOMEM;

        prtd->dma_chan = chan;

        substream->runtime->private_data = prtd;

        return 0;
}

chan 为空时直接 -ENXIO，这就是前面说的「dma-names 写错 → aplay 报 -ENXIO」的出处。snd_pcm_hw_constraint_integer 强制 period 数为整数，否则周期中断的边界算不准。

DMA 侧参数从哪里来。 dmaengine_pcm_hw_params() 只做两件事，把 hw_params 转成 dma_slave_config，再交给控制器：

c
static int dmaengine_pcm_hw_params(struct snd_soc_component *component,
                                   struct snd_pcm_substream *substream,
                                   struct snd_pcm_hw_params *params)
{

prepare_slave_config 默认实现是 snd_dmaengine_pcm_prepare_slave_config()，它干两件事：

c
int snd_dmaengine_pcm_prepare_slave_config(struct snd_pcm_substream *substream,
        struct snd_pcm_hw_params *params,
        struct dma_slave_config *slave_config)
{
        struct snd_soc_pcm_runtime *rtd = asoc_substream_to_rtd(substream);
        struct snd_dmaengine_dai_dma_data *dma_data;
        int ret;

        if (rtd->dai_link->num_cpus > 1) {
                dev_err(rtd->dev, "%s doesn't support Multi CPU yet\n", __func__);

        }

        dma_data = snd_soc_dai_get_dma_data(asoc_rtd_to_cpu(rtd, 0), substream);

        ret = snd_hwparams_to_dma_slave_config(substream, params, slave_config);

snd_hwparams_to_dma_slave_config() 定方向和宽度：物理位宽 8→1 字节、16→2、24→3、≤32→4、其余→8；playback 设 DMA_MEM_TO_DEV 和 dst_addr_width，capture 设 DMA_DEV_TO_MEM 和 src_addr_width。

snd_dmaengine_pcm_set_config_from_dai_data() 从 dma_data 里取地址、burst、宽度：

c
void snd_dmaengine_pcm_set_config_from_dai_data(
        const struct snd_pcm_substream *substream,
        const struct snd_dmaengine_dai_dma_data *dma_data,
        struct dma_slave_config *slave_config)
{
        if (substream->stream == SNDRV_PCM_STREAM_PLAYBACK) {
                slave_config->dst_addr = dma_data->addr;
                slave_config->dst_maxburst = dma_data->maxburst;
                if (dma_data->flags & SND_DMAENGINE_PCM_DAI_FLAG_PACK)
                        slave_config->dst_addr_width = DMA_SLAVE_BUSWIDTH_UNDEFINED;
                if (dma_data->addr_width != DMA_SLAVE_BUSWIDTH_UNDEFINED)
                        slave_config->dst_addr_width = dma_data->addr_width;
        } else {
                slave_config->src_addr = dma_data->addr;
                slave_config->src_maxburst = dma_data->maxburst;
                if (dma_data->flags & SND_DMAENGINE_PCM_DAI_FLAG_PACK)
                        slave_config->src_addr_width = DMA_SLAVE_BUSWIDTH_UNDEFINED;
                if (dma_data->addr_width != DMA_SLAVE_BUSWIDTH_UNDEFINED)
                        slave_config->src_addr_width = dma_data->addr_width;
        }

        slave_config->peripheral_config = dma_data->peripheral_config;
        slave_config->peripheral_size = dma_data->peripheral_size;
}

所以 dma_data 就是 Platform 驱动往 DMA 引擎递话的载体。RK3399 I2S0 播放时填的是：

text
struct snd_dmaengine_dai_dma_data
    .addr       = 0xff880000 + I2S_TXDR   /* 0x0024，发送 FIFO */
    .addr_width = DMA_SLAVE_BUSWIDTH_4_BYTES
    .maxburst   = 8                        /* FIFO 深度 */

录音时换成 I2S_RXDR（偏移 0x0028）。最终下发的 dma_slave_config：

字段 播放 录音
direction DMA_MEM_TO_DEV DMA_DEV_TO_MEM
dst_addr / src_addr 0xff880000 + 0x0024 0xff880000 + 0x0028
dst_addr_width / src_addr_width 4 字节 4 字节
dst_maxburst / src_maxburst 8 8
device_fc false false

这几个值直接写进 DMAC 的通道配置寄存器。maxburst 填大了会溢出 FIFO，填小了搬运效率差；addr_width 和采样位宽不符会听到白噪声或者完全没声音。这类问题在 {{音频调试实战}} 里有系统排查法。

十四、Codec 驱动：芯片侧的实现 #

Codec 驱动的原则是不含任何平台相关代码。ALC5651 的驱动放在 sound/soc/codecs/rt5651.c，同一份代码能在 RK3399、i.MX8、Allwinner 上跑，因为它只描述「ALC5651 这颗芯片怎么配」。

一颗 Codec 驱动必须提供：

  • DAI 与 PCM 的配置信息，用 snd_soc_dai_driver 描述，含能力与操作接口；
  • 控制接口，最常见的是 I2C 或 SPI，用于读写寄存器；snd_soc_component_driver 里的 read/write，或者走 regmap；
  • Mixer 和其它音频控件；
  • 音频操作，用 snd_soc_dai_ops；
  • DAPM 描述与 DAPM 事件处理。

可选的还有 DAC 数字静音。ALC5651 没做数字静音，靠 DAPM 顺序和模拟静音位防爆音。

注册路径在 I2C probe 里，就一行：

十五、snd_soc_component 与 snd_soc_codec #

6.3 里 Platform 和 Codec 共用 snd_soc_component 这一个容器。这不只是为了省代码，是内核演进的结果，必须讲清楚，否则照着老文章写驱动会编译不过。

c
struct snd_soc_dai *snd_soc_register_dai(struct snd_soc_component *component,
                                         struct snd_soc_dai_driver *dai_drv,
                                         bool legacy_dai_naming)
{
        struct device *dev = component->dev;
        struct snd_soc_dai *dai;

        dev_dbg(dev, "ASoC: dynamically register DAI %s\n", dev_name(dev));

        lockdep_assert_held(&client_mutex);

        dai = devm_kzalloc(dev, sizeof(*dai), GFP_KERNEL);
        if (dai == NULL)
                return NULL;

        if (legacy_dai_naming &&
            (dai_drv->id == 0 || dai_drv->name == NULL)) {
                dai->name = fmt_single_name(dev, &dai->id);
        } else {
                dai->name = fmt_multiple_name(dev, dai_drv);
                if (dai_drv->id)
                        dai->id = dai_drv->id;
                else
                        dai->id = component->num_dai;
        }

        dai->dev = dev;
        dai->driver = dai_drv;

legacy_dai_naming 为假（ALC5651 就是）时走 fmt_multiple_name()，DAI 名直接取 dai_drv->name，所以是 "rt5651-aif1"。为真时走 fmt_single_name()，DAI 名变成设备名那种形式，dai_link->dai_name 就得写设备名。两种命名方式混用是常见错误源。

component 名的生成。 fmt_single_name() 决定 component->name，非设备树场景下 Machine 靠它匹配：

c
static char *fmt_single_name(struct device *dev, int *id)
{
        const char *devname = dev_name(dev);
        char *found, *name;
        unsigned int id1, id2;

        if (devname == NULL)
                return NULL;

        name = devm_kstrdup(dev, devname, GFP_KERNEL);
        if (!name)
                return NULL;

        /* are we a "%s.%d" name (platform and SPI components) */
        found = strstr(name, dev->driver->name);
        if (found) {
                /* get ID */
                if (sscanf(&found[strlen(dev->driver->name)], ".%d", id) == 1) {
                        /* discard ID from name if ID == -1 */
                        if (*id == -1)
                                found[strlen(dev->driver->name)] = '\0';
                }

        /* I2C component devices are named "bus-addr" */
        } else if (sscanf(name, "%x-%x", &id1, &id2) == 2) {
                /* create unique ID number from I2C addr and bus */
                *id = ((id1 & 0xffff) << 16) + id2;

                devm_kfree(dev, name);

                /* sanitize component name for DAI link creation */
                name = devm_kasprintf(dev, GFP_KERNEL, "%s.%s", dev->driver->name, devname);
        } else {
                *id = 0;
        }

        return name;
}

对 I2C 上的 ALC5651：dev_name() 是 "1-001a"（I2C1，地址 0x1a），带 - 不是 .%d 格式，所以 strstr 找不到 "rt5651"，落到第二个分支，sscanf("1-001a", "%x-%x") 解析成功，最终名字是 "rt5651.1-001a"，id = (0x1 << 16) + 0x1a。

这就是为什么日志里是 rt5651.1-001a:AIF1 Playback，也是为什么非设备树场景下 codecs->name 要写 "rt5651.1-001a" 而不是 "rt5651"。

Platform 设备的 dev_name() 是 "ff880000.i2s"，带 . 但不是 .%d 数字结尾，strstr(name, dev->driver->name) 找到 "ff880000.i2s" 自身，sscanf(".i2s", ".%d") 不成立（%d 在 . 后需要数字，实际是 i），所以 id 保持未赋值，名字就是 "ff880000.i2s"。这段分支逻辑对某些驱动会产生未初始化 id，属于源码本身的糙点，不影响名字结果。

十六、注册顺序与绑定时机 #

三大件的 probe 顺序不受控制。I2C 总线、平台设备、module_init 的先后由内核的设备模型和链接顺序决定，于是必然出现「Machine 先起来、Codec 还没注册」这种情况。

ASoC 的处理办法是失败就延迟重试，靠 -EPROBE_DEFER。三个位置会返回它：

位置 条件
snd_soc_add_pcm_runtime() snd_soc_find_dai() 找不到 CPU 或 Codec DAI 时 goto _err_defer
snd_soc_get_dai_name() 遍历完 component_list 一个都没匹配上
soc_bind_aux_dev() 辅助设备找不到 component

_err_defer 的处理是先把刚建的 rtd 拆掉，再返回 -EPROBE_DEFER：

c
_err_defer:
        snd_soc_remove_pcm_runtime(card, rtd);
        return -EPROBE_DEFER;

反过来，当 Codec 或 Platform 后来才注册成功，snd_soc_add_component() 的末尾会主动尝试补绑：

c
        mutex_unlock(&client_mutex);

        if (ret == 0)
                snd_soc_try_rebind_card();

        return ret;

所以顺序在源码层面是「双向兜底」的：Machine 先到就等 Codec，Codec 先到就 Machine 直接成功。

实际开机顺序（RK3399 + ALC5651）大致是这样：

阶段 谁 动作 产物
1 I2C 核心 枚举 I2C1 上的 0x1a rt5651.1-001a 设备
2 rt5651 I2C 驱动 rt5651_i2c_probe → devm_snd_soc_register_component component 进 component_list，两条 DAI 进 dai_list
3 平台总线 匹配 ff880000.i2s 与 rockchip-i2s I2S 控制器设备
4 rockchip_i2s 驱动 注册 component + devm_snd_dmaengine_pcm_register I2S component + dmaengine PCM component
5 平台总线 匹配 rt5651-sound 与 asoc-simple-card Machine 设备
6 simple-card asoc_simple_probe → devm_snd_soc_register_card 声卡开始绑定
7 ASoC CORE snd_soc_bind_card 九步 card->instantiated = 1
8 ALSA CORE snd_card_register /proc/asound/card0 出现

如果第 2 步早于第 6 步，绑定一次成功。如果第 6 步先到，snd_soc_add_pcm_runtime 里 snd_soc_find_dai("rt5651-aif1") 返回 NULL，Machine 的 probe 返回 -EPROBE_DEFER，等第 2 步完成后由 snd_soc_try_rebind_card() 重试。

probe 的批次顺序在 component 与 DAI 内部还有一层。soc_probe_link_components() 和 soc_probe_link_dais() 都是按 order 从 -2 扫到 2：

c
for_each_comp_order(order) {   /* -2, -1, 0, 1, 2 */
        for_each_card_rtds(card, rtd) {
                for_each_rtd_components(rtd, i, component) {
                        if (component->driver->probe_order != order)
                                continue;

                        ret = soc_probe_component(card, component);
                        if (ret < 0)
                                return ret;
                }
        }
}

order 的取值定义在 include/sound/soc.h：SND_SOC_COMP_ORDER_FIRST（-2）、EARLY（-1）、NORMAL（0）、LATE（1）、LAST（2）。dmaengine PCM 那个 component 用的是 SND_SOC_COMP_ORDER_LATE：

c
static const struct snd_soc_component_driver dmaengine_pcm_component = {
        .name           = SND_DMAENGINE_PCM_DRV_NAME,
        .probe_order    = SND_SOC_COMP_ORDER_LATE,
        .open           = dmaengine_pcm_open,
        .close          = dmaengine_pcm_close,
        .hw_params      = dmaengine_pcm_hw_params,
        .trigger        = dmaengine_pcm_trigger,
        .pointer        = dmaengine_pcm_pointer,
        .pcm_construct  = dmaengine_pcm_new,
};

为什么要 LATE？因为 DMA 组件的 probe 依赖 CPU DAI 侧的 dma_data 已经准备好，它必须排在 Platform 的 I2S 组件之后。

dai->driver->probe_order 也是同样的机制，在 snd_soc_pcm_dai_probe() 里按批调 dai->driver->probe。这个字段一般不用设，需要时（比如 Codec 的 probe 要读 I2C 状态、必须在某个 GPIO 驱动之后）才填。

同一个 component 被多张声卡引用会失败：

c
if (component->card) {
        if (component->card != card) {
                dev_err(component->dev,
                        "Trying to bind component to card \"%s\" but is already bound to card \"%s\"\n",
                        card->name, component->card->name);
                return -ENODEV;
        }
        return 0;
}

一个 component 只能绑一张卡。要在同一颗 Codec 上做多张卡，得给每个 dai_link 分配不同 DAI，或者用 codec_conf 的 name_prefix 区分——但 component->card 这个限制仍在，实际做法是一张卡里放多条 link。

十七、调试手段与常见故障 #

先看声卡有没有起来：

bash
# 声卡列表，能打印出来说明 card->instantiated 为 1
cat /proc/asound/cards

# PCM 设备与 substream 数
cat /proc/asound/pcm

# 某张卡的 DAI 绑定情况
cat /proc/asound/card0/../../soc/... 2>/dev/null   # 路径随内核版本变化，未验证

/proc/asound/cards 里出现 #0: realtek,rt5651-codec 才算成功。空列表意味着绑定在某个环节失败了。

看 dmesg 里 asoc-simple-card 的输出，每一步都有日志可以对号：

日志 含义 不在时的排查方向
ASoC: binding <link name> 开始绑定这条链路 snd_soc_add_pcm_runtime 没被调到，看 dts
ASoC: CPU DAI ... not registered CPU 侧找不到 Platform 驱动没起，或 of_node 对不上
ASoC: CODEC DAI ... not registered Codec 侧找不到 Codec 驱动没起，或 #sound-dai-cells 写错
connected DAI link A:Playback -> B:Playback 播放路径连上了 DAPM route 有问题
connected DAI link B:Capture -> A:Capture 录音路径连上了 同上
ALSA device list: #0: <name> 声卡注册完成 snd_card_register 失败

四类高频故障：

一、Codec 没出现在 component_list。

表现为 ASoC: CODEC DAI rt5651-aif1 not registered，Machine 一直 -EPROBE_DEFER。查三处：

  • i2cdetect -y 1 能不能看到 0x1a。看不到是硬件或上电问题，跟 ASoC 无关。
  • Codec 的 I2C probe 有没有跑到 devm_snd_soc_register_component。提前 return -ENODEV 的路径多半是读 chip id 失败。
  • compatible 拼写。rockchip,rt5651 和 realtek,rt5651 是两个不同的兼容串，I2C 的 of_match_table 里只认一个。

二、Platform 的 DMA 通道拿不到。

表现为 aplay -D hw:0,0 报 -ENXIO。查：

  • dts 里 dma-names 是不是 "tx" / "rx"，写 "playback" 无效。
  • dmas 引用的控制器节点在不在，dmac_bus 有没有 probe（/sys/class/dma/ 下有没有 dma0chan*）。
  • modprobe 顺序：DMA 控制器驱动没加载，I2S 拿到的是 -EPROBE_DEFER，看着像通道不存在其实是设备还没起来。

三、PCM 起来了但没有声音。

绑定成功、aplay 不报错，就是没声音。这个方向不查 ASoC 绑定，查两端：

  • set_fmt 有没有把主从设反。CBC_CFC 写成 CBP_CFP，编码芯片会去驱动 BCLK，而 CPU 也在驱动，两边冲突，波形是乱的。
  • mclk-fs 和实际 MCLK 对不对得上。mclk_fs = 256 但板上只给了 12.288MHz 的固定时钟，44100Hz 的请求被 asoc_simple_startup 的整除检查挡下，或者 set_sysclk 设了个实际出不来的频率。
  • DAPM 路径断在 Codec 里。这类问题的定位靠 tracing，具体过滤器设置在 {{音频调试实战}} 里。

四、录音能播不能录，或者反之。

两个原因最常见：

  • dai_link 没标 playback_only / capture_only，但某一端实际只有单向 DAI。soc_new_pcm() 会两条 stream 都建，打开不支持的那条就失败。
  • dts 里 routing 只连了播放路径或只连了录音路径。本节点的例子是全的：录音有 micbias1 -> Mic Jack -> IN2P/IN2N，播放有 HPOL/HPOR -> Headphones。删掉录音那三对，arecord 就找不到完整路径。

要额外录第三路麦克风，就在 routing 里加一对：

dts
"IN3P", "Mic Jack"

多路可以同时配，Codec 内部会混音。

看 DAPM 图的实际连线。debugfs 里每张卡有 dapm/ 目录，widget 文件内容能直接看到 in / out 列表，用 cat 看连接关系。路径结构属于 DAPM 话题，格式见 {{DAPM：Widget、Route 与 Path}}。

看 PCM 参数。aplay -v / arecord -v 会把最终协商出来的 buffer_size、period_size、format、rate 全打出来：

text
Its setup is:
  stream       : CAPTURE
  access       : RW_INTERLEAVED
  format       : S16_LE
  subformat    : STD
  channels     : 2
  rate         : 44100
  exact rate   : 44100 (44100/1)
  msbits       : 16
  buffer_size  : 22052
  period_size  : 5513
  period_time  : 125011

buffer_size / period_size = 4，说明 periods 取了 4，这是 snd_dmaengine_pcm_set_runtime_hwparams() 里 hw.periods_min = 2 和 ALSA 默认策略共同作用的结果。period_time = 125011 微秒，也就是每 125ms 一次中断——对 CPU 负载很友好，但对延迟敏感的场景要手动把 period_size 调小。

如果看到 buffer_size 异常小或异常大，先查 hw.period_bytes_min 那个计算：

c
hw.period_bytes_min = dma_data->maxburst * DMA_SLAVE_BUSWIDTH_8_BYTES;
if (!hw.period_bytes_min)
        hw.period_bytes_min = 256;

maxburst = 8 时算出来 8 × 8 = 64 字节。这个值偏小时 ALSA 会允许很小的 period，实际搬运时容易中断过密。

十八、易错点速查 #

下面这张表是前面十几章里所有「会被绊一跤」的地方，按出问题后看到的症状排序。

# 症状 根因 处理
1 声卡完全不出现，/proc/asound/cards 为空 card->name 或 card->dev 为空，snd_soc_register_card 直接 -EINVAL 检查 Machine probe 里有没有给 card->dev 赋值
2 一直 -EPROBE_DEFER，声卡永远出不来 Codec 或 Platform 的 component 名字对不上 非 DT 场景确认 codecs->name 是 rt5651.1-001a 这种带前缀的名字
3 ASoC: CODEC DAI xxx not registered dai_name 写错，或 #sound-dai-cells 与 sound-dai 参数个数不匹配 cells = <0> 就只能写 <&rt5651>
4 默认选错 DAI sound-dai = <&phandle> 不带 port 时默认 id = 0，取 dai_list 第一条 要选第二条写成 <&rt5651 1>，同时 #sound-dai-cells = <1>
5 控件名重复或互相覆盖 多 Codec/多 component 的控件名撞车 用 codec_conf.name_prefix 或设备节点 sound-name-prefix 加前缀
6 ASoC: DAPM widget 'xxx' is not supported simple-audio-card,widgets 用了四种模板以外的名字 只能是 Microphone/Line/Headphone/Speaker
7 ASoC: no dapm match for ... routing 里某个名字在 widget 表里不存在 右键名（sink/source）和 Codec DAPM 表逐字对
8 Jack 插拔没反应 dts 里 widget 实例名不是 Headphones / Mic Jack 这两个名字在 asoc_simple_init_jack 里硬编码
9 44.1kHz 打不开，报 fixed sysclk not divisible by mclk_fs 板上 MCLK 固定，mclk_fs 与实际不符 改 mclk_fs，或去掉 system-clock-fixed 让驱动算
10 有噪音、无人声 dai_fmt 的 CLOCK_PROVIDER 位设反 RK3399 侧写 CBC_CFC
11 左右声道反了 routing 里 HPOL/HPOR 写反，或 SND_SOC_DAIFMT_LEFT_J/RIGHT_J 选错 先查 route，再查格式
12 aplay 报 -ENXIO dma-names 不是 tx/rx，DMA 通道没请求到 与 dmaengine_pcm_dma_channel_names[] 对齐
13 第一次 trigger 就 -ENOMEM DMA 控制器没实现 device_prep_dma_cyclic，DMA_CYCLIC 能力声明了却没实现 看控制器驱动，dma_async_device_register 会校验
14 播放几小时后 xrun cookie 绕回处理有问题 查控制器的 device_tx_status 实现
15 aplay 能用，arecord 不行 链路标了 playback_only，或 routing 缺录音路径 去掉标志位，补 IN2P/IN2N 两对
16 一个 Codec 挂两张卡失败 component->card 已绑另一张卡 一张卡里放多条 dai_link
17 DMA 组件的 probe_order 不是 LATE DMA 通道在 CPU DAI 之前被要，拿到空 dma_data 保持 SND_SOC_COMP_ORDER_LATE
18 声卡起来了但引脚一直是低电平 snd_soc_bind_card 末尾把未活跃 component 的 pinctrl 切了 sleep 正常行为，播放时切回 default
19 老代码编译不过 照 4.x 的 snd_soc_register_codec() / struct snd_soc_codec 写 6.3 只有 snd_soc_component，用 devm_snd_soc_register_component()
20 照抄 CBM_CFM 报未定义 6.3 已改名 CBP_CFP 系列 见六章那张新旧对照表

再补两条不完全属于「错误」但会被误判的现象：

日志里 CPU DAI (null)registered。 名字字段打印为空，binding 那行已经把链路名打出来了，说明绑定正常。判断依据看后面的 connected DAI link。

dapm 目录下路径文件里出现空行。 DAPM 图里有些 widget 没有连接，这是正常的，不代表 route 写错。真正要看的是目标 widget（比如 Headphones）的文件里有没有 in 记录。
