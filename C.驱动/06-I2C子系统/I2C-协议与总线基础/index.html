一、I2C 是什么：两根线连接一堆设备 #

I2C 读作 I-squared-C，全称 Inter-Integrated Circuit，常缩写为 IIC 或 I2C。由 PHILIPS（今 NXP）开发，用于微控制器与外围设备之间的板级串行通信。

一句话概括结构：两根线，一主多从，每个从机一个地址。

  • SDA：串行数据线，双向。
  • SCL：串行时钟线，由主机驱动（时钟拉伸的例外见第十章）。
  • 总线上的每个器件都有唯一地址，主机靠地址区分同一根总线上的不同器件。扩展器件时受地址空间与电容负载双重限制。

I2C 是同步、半双工的硬件层串行协议。同步：时钟线独立存在，收发双方共用一个时钟。半双工：同一时刻数据只朝一个方向走，SDA 只有一根。

器件角色按收发方向分成四种工作模式，四种模式的时钟都归主机：

模式 数据方向 时钟由谁产生
主机发送 主机 → 从机 主机
主机接收 从机 → 主机 主机
从机发送 从机 → 主机 主机
从机接收 主机 → 从机 主机

时钟归主机是 I2C 与 UART 最本质的差别（见第十四章）。

I2C 支持多主机：允许多个主设备竞争使用权，冲突由仲裁裁决，不丢数据（第九章）。主器件的能力是能控制 SCL 频率、能发起并终止传输；任何时间点只有一个主控在发时钟。

二、电气特性：开漏输出与上拉电阻 #

I2C 电气上有一条铁律：所有器件的输出级必须是漏极开路（open-drain）或集电极开路（open-collector），SCL 与 SDA 都必须外接上拉电阻到正电源。这条铁律直接推出一串结论。

空闲是高电平。 总线空闲时 SDA 与 SCL 均为高，靠上拉电阻维持。

线与逻辑。 输出级是开漏，任一器件任意时刻输出低电平，整根线就被拉低；只有所有器件都「不拉」，上拉电阻才把线拉回高。所以 SDA 和 SCL 都是「线与」关系：

text
线上电平 = SDA_A & SDA_B & SDA_C & ... & 1(上拉)

任一器件拉低  -> 线为低
全部器件释放  -> 线上拉为高

线与是仲裁和时钟同步的物理基础，不是附加功能。

开漏怎么工作。 外接上拉电阻 R 接在输出引脚与上拉电源 Vcc 之间：

内部 N 沟道 MOS 管 引脚状态 说明
关断 被 R 拉到 Vcc，输出高 漏电流极小
导通 被拉到接近 GND，输出低 电流按欧姆定律 I = Vcc / R

上拉电源电压可以和器件供电电压不同，顺带解决了电平转换：3.3V 的 MCU 与 5V 从机能挂在同一根总线上，前提是上拉接到哪一侧、阻值怎么选都对得上。

器件数量由电容决定，不由电流决定。 每个器件接口都有等效电容，器件越多等效电容越大（相当于全部并联在总线上），边沿被拖慢，传输延迟变大。器件数受总线电容不得超过 400pF 限制（素材给的值；工程上可用容性缓冲器或中继器扩展，素材只提一句「可以通过其他的方法增加总线的电容量」）。据此可反推总线长度与外围器件数量上限。

速率与上拉的关系。 速率越高边沿必须越陡，上拉电阻就得越小（RC 时间常数 t = R × C）。素材没有给阻值表格，各家手册取值也不同，本文不猜；选型时按 400pF 上限与目标频率算 RC，再用示波器看上升沿是否满足器件手册的 tr 要求。频率分级见第十二章。

三、SDA 与 SCL 两根线的分工 #

SCL 为高电平期间，SDA 上的电平必须稳定；SDA 只允许在 SCL 为低电平期间变化。

理由很直白：SCL 高电平期间的 SDA 跳变被协议征用作控制命令——高到低是起始，低到高是停止。如果允许在高电平期间随便改数据，控制命令与数据位就没法区分了。

text
         __    __    __    __
SCL  ___|  |__|  |__|  |__|  |___
         |    |    |    |    |
SDA  ----<X>--<X>--<X>--<X>------
         ^    ^    ^    ^
       数据在此处建立/保持，SCL 高的那段时间 SDA 是平的

一句话记法：低电平换数据，高电平采样。 换成代码就是三行节奏：SCL 拉低 → 摆好 SDA → SCL 拉高 → 采样 → SCL 拉低。

四、起始条件与停止条件 #

I2C 一次传输过程中有四种类型的信号：起始（START）、停止（STOP）、应答（ACK/NACK）、有效数据。前两个由主机发起，且只在 SCL 高电平期间发生。

条件 SCL SDA 跳变 方向 谁发起 含义
起始 START 高 高 → 低 下降沿 主机 传输开始，之后的数据才有效
停止 STOP 高 低 → 高 上升沿 主机 传输结束，总线回到空闲
重复起始 Sr 高 高 → 低 下降沿 主机 不释放总线前提下另起一次传输

起始：SCL 保持高，SDA 由高变低。只有起始信号发出之后，后续数据才有效。停止：SCL 保持高，SDA 由低变高。停止信号出现后，本次传输结束，总线释放。

时序图（时间轴向右）：

text
START                          STOP
SCL  ‾‾‾\____/‾‾‾\____ ... ____/‾‾‾\_____
SDA  ‾‾‾‾\______________________ ... ______/‾‾‾‾
         ^                              ^
      高电平期间下降               高电平期间上升

用 GPIO 拨出来的代码（软件模拟版本，延时按器件与主频调，不是协议要求值）：

c
void I2C_Start(void)
{
    SDA_OUT();
    I2C_SDA = 1;  delay_us(5);
    I2C_SCL = 1;  delay_us(5);
    I2C_SDA = 0;  delay_us(5);   /* SCL 高时 SDA 下降 -> START */
    I2C_SCL = 0;
}

void I2C_Stop(void)
{
    SDA_OUT();
    I2C_SDA = 0;  delay_us(5);
    I2C_SCL = 1;  delay_us(5);
    I2C_SDA = 1;  delay_us(5);   /* SCL 高时 SDA 上升 -> STOP */
    I2C_SCL = 0;
}

两个函数收尾都把 SCL 拉回低（Start）或保持释放（Stop），让下一次传输从「SCL 低」这个安全状态起步。delay_us(5) 只是示例节奏：100kHz 一个位周期 10us，5us 恰好半个周期，换算见第十二章。

五、数据传输的位时序 #

数据规则三条：每个字节必须 8 位、一次传输字节数不限；MSB first，先送最高位；每 8 位数据后紧跟 1 位应答位，所以一帧是 9 个时钟。

第 9 个时钟周期，发送端必须释放 SDA（让线浮空，由上拉或接收端决定电平），交给接收端去应答。

步骤 SCL SDA 动作
1 低 发送端摆位 把要发的位放到 SDA
2 低 → 高 保持 数据建立，进入采样窗口
3 高 稳定 接收端采样这一位
4 高 → 低 允许变化 准备下一位

写一个字节的软件模拟：

c
void I2C_WriteData(u8 byte)
{
    u8 i = 0;
    SDA_OUT();
    I2C_SCL = 0;
    for (i = 0; i < 8; i++)
    {
        I2C_SDA = (byte & 0x80) >> 7;   /* MSB first，取最高位 */
        byte <<= 1;
        delay_us(5);
        I2C_SCL = 1;  delay_us(5);      /* 拉高，从机采样 */
        I2C_SCL = 0;  delay_us(5);
    }
}

读一个字节同样 MSB first，区别是引脚切成输入、时钟仍由主机给：

c
u8 I2C_ReadData(void)
{
    u8 i = 0;
    u8 data = 0;
    SDA_IN();
    I2C_SCL = 0;
    for (i = 0; i < 8; i++)
    {
        I2C_SCL = 1;  delay_us(5);
        data <<= 1;
        data |= (u8)Read_SDA;           /* 从最高位往低拼 */
        I2C_SCL = 0;  delay_us(5);
    }
    return data;
}

注意 I2C_ReadData() 内部不处理应答位，第 9 位要调用方另外用 I2C_Ack() 发出去（见第六章、第八章）。这是软件模拟最容易漏掉的一步：读完字节忘了回 ACK/NACK，从机会一直等在第 9 个时钟。

六、应答与非应答（ACK / NACK） #

9 位一帧。 发送端发完 8 位数据，在第 9 个时钟周期释放 SDA，由接收端接管这根线去表态。

应答位 第 9 个时钟 SDA 电平 谁拉 含义
ACK 低 接收端拉低 收到，继续
NACK 高（释放，被上拉） 接收端不拉 没收到 / 到此为止 
text
第 9 个时钟：
  1. 发送端释放 SDA（切输入 / 高阻）
  2. SCL 拉高，接收端在这段高电平内把 SDA 拉低（ACK）
  3. SCL 拉低，接收端释放 SDA，总线回到空闲电平

第 9 位的方向永远与数据方向相反：写数据时主机发、从机收，从机拉低；读数据时从机发、主机收，主机拉低。

c
/* 返回 0：接收失败   1：接收成功 */
u8 I2C_WaitAck(void)
{
    u16 time = 0;
    SDA_IN();
    I2C_SCL = 0;  delay_us(5);
    I2C_SDA = 1;  delay_us(5);      /* 先释放，交给从机 */
    I2C_SCL = 1;  delay_us(5);      /* 高电平期间采样 */
    while (Read_SDA)                /* 一直高 = 从机没拉低 = 没应答 */
    {
        if (++time >= 2500)
        {
            I2C_Stop();             /* 超时：发 STOP 收场，防止总线锁死 */
            return 0;
        }
    }
    I2C_SCL = 0;
    return 1;
}

那个 2500 不是协议常数，是软件模拟的防死等计数，按主频自己调。真实设计里要有硬件超时兜底。

主机收到从机数据后回应答，ack 参数 0 表示 NACK、1 表示 ACK：

c
void I2C_Ack(u8 ack)
{
    SDA_OUT();
    I2C_SCL = 0;  delay_us(5);
    I2C_SDA = ack ? 0 : 1;   /* ACK 拉低；NACK 释放，被上拉为高 */
    I2C_SCL = 1;  delay_us(5);
    I2C_SCL = 0;  delay_us(5);
}

NACK 的两种语义，别混。 同一个电平，出现的位置不同，意思完全不同：

场景 谁发 NACK 意思
主机读最后一个字节后 主机 「我不要了」，随后发 STOP 或 Sr
主机写地址/数据 从机 「地址没人认领」或「写不进去」，主机应中止

第二种是排障时最常见的信号：写完地址收到 NACK，八成是地址错、器件没供电、没焊好，或者被复位脚按住了。逻辑分析仪抓第一帧就能定位。

七、7 位寻址与 10 位寻址 #

发有效数据之前，主机必须先指定从机地址。地址的发送过程和普通数据一样，只是紧跟其后的第 9 位由被寻址的从机回应 ACK。

7 位地址 #

绝大多数从机用 7 位地址。协议规定在 7 位地址后面补 1 位方向位，凑成一个字节：

text
 bit:   7   6   5   4   3   2   1  |  0
      +---+---+---+---+---+---+---+---+
      |      A6..A1 (7 位地址)       |R/W|
      +---+---+---+---+---+---+---+---+
                                      0 = 主机写（W）
                                      1 = 主机读（R）

「0x50 写 0xA0 / 读 0xA1」就是这么来的：7 位地址 0x50 = 1010000b，左移一位补 0 得 0xA0（写），补 1 得 0xA1（读）。手册给 7 位地址，代码里传 8 位形态，错一位就全错。

10 位地址 #

10 位地址占两个字节，用第一个字节的 11110xx 前缀标记：

text
第一字节：  |1 1 1 1 0|A9 A8|R/W|     bit7..bit0
第二字节：  |      A7 .. A0      |     bit7..bit0
项目 7 位寻址 10 位寻址
地址位宽 7 位（A6~A0） 10 位（A9~A0）
占用字节 1 字节（地址 + R/W） 2 字节（前缀 + 地址 + R/W）
首字节格式 A6..A0 R/W 1111 0 A9 A8 R/W
可用地址数 128 个（0x00~0x7F） 1024 个
保留段 0000xxx 与 1111xxx 段被保留 前缀 11110xx 已被征用
重复起始时的写法 直接重发 START + 地址字节 需重发完整两字节地址
常见程度 绝大多数器件 少见，地址空间吃紧时才用

7 位地址空间的保留区：0000 000 是通用呼叫地址（General Call），0000 001 是 CBUS 地址，1111 0xx 与 1111 1xx 段留给 10 位地址前缀。素材未展开这套划分，本文只标注存在保留区。

别把「器件地址」和「寄存器地址」搞混。 LM75 自身 7 位地址高 4 位固定、低 3 位由三个地址引脚决定，都为 0 时是 0x48；它内部寄存器靠数据字节选中——先写 pointer 指向目标寄存器，再读数据。器件地址定位器件，寄存器索引定位器件内部。AT24C08 同理：0xA0~0xA6 是器件地址，address % 256 是片内字节地址，address / 256 那两位还额外塞进器件地址（见第十三章）。

八、读写时序：主机怎么读、怎么写 #

主机写从机 #

text
START | 从机地址(7) + W(0) | ACK | 数据字节1 | ACK | ... | 数据字节n | ACK | STOP
       <---- 从机拉低 ---->        <---- 从机拉低 ---->
序号 发起方 动作 谁回 ACK
1 主机 发 START —
2 主机 发 7 位地址 + W(0) 从机
3 主机 发数据字节 1 … n 从机（每字节一次）
4 主机 发 STOP —

素材原文：「一般发送的每个字节数据后会跟着等待接收来自从设备的响应（ACK）」——每字节后都要等 ACK，不是整包只等一次。

主机读从机 #

text
START | 从机地址(7) + R(1) | ACK | 数据1 | ACK | 数据2 | ACK | ... | 数据n | NACK | STOP
                              从机发            主机回            主机回
序号 发起方 动作 谁回 ACK
1 主机 发 START —
2 主机 发 7 位地址 + R(1) 从机
3 从机 发数据字节，主机逐字节收 主机（中间全 ACK）
4 主机 收到最后一字节后回 NACK 主机
5 主机 发 STOP —

第 4 步是收尾机关：主机不回 NACK，从机会以为还要继续发，永远等不到 STOP。NACK 是主机告诉从机「到此为止」的唯一手段，然后才能发 STOP。

需要先写地址再读的器件（随机读） #

EEPROM、LM75 这类器件不能直接读，得先告诉它读哪个内部地址。办法是写-读复合帧，中间用重复起始 Sr：

text
START | 0xA0 | ACK | 字节地址 | ACK | Sr | 0xA1 | ACK | 数据 | NACK | STOP
        写              写                    读
序号 动作
1 主机发 START → 7 位地址 + W(0)，从机回 ACK
2 主机发片内字节地址（0~0xFF），从机回 ACK
3 主机重发 START（重复起始） → 7 位地址 + R(1)，从机回 ACK
4 主机收数据，收完回 NACK，然后发 STOP 
c
u8 Read24c08(u16 address)   /* address: 0~1023 */
{
    u8 byte;
    u8 block = address / 256;
    I2C_Start();
    I2C_WriteData(0xA0 + block * 2);   /* 写方向 */
    I2C_WaitAck();
    I2C_WriteData(address % 256);      /* 片内字节地址 */
    I2C_WaitAck();
    I2C_Start();                       /* Sr：重复起始，不是 STOP+START */
    I2C_WriteData(0xA1 + block * 2);   /* 读方向 */
    I2C_WaitAck();
    byte = I2C_ReadData();
    /* I2C_Ack(0); */                  /* 单字节读，收完直接 STOP，等价于 NACK 收尾 */
    I2C_Stop();
    delay_ms(10);
    return byte;
}

单字节读时素材把 I2C_Ack(0) 注释掉了，直接 STOP。能工作的原因：STOP 之前主机已经释放 SDA，从机在下一个时钟看到高电平即判 NACK。但多字节连读不能省，中间字节必须回 ACK，只有最后一句回 NACK。

c
void Write24c08(u16 address, u8 byte)   /* address: 0~1023 */
{
    u8 block = address / 256;
    I2C_Start();
    I2C_WriteData(0xA0 + block * 2);
    I2C_WaitAck();
    I2C_WriteData(address % 256);
    I2C_WaitAck();
    I2C_WriteData(byte);
    I2C_WaitAck();
    I2C_Stop();
    delay_ms(10);   /* 24C08 从 SDA 取到数据后还要烧录，延时必须够长 */
}

delay_ms(10) 不是随便写的：EEPROM 内部写完要做烧录周期（datasheet 里的 tWR），这段时间器件不应答任何访问。素材原注释写明「这个延时一定要足够长，否则会出错」。具体毫秒数按型号手册取，10ms 是这套代码的经验值。

页写把单字节换成循环，但不能跨页：AT24C01 页缓冲 8 字节，AT24C02/04/08/16 页缓冲 16 字节。素材点到的问题：页缓冲区寻址从 0 开始，0~15 是第 1 页，16~31 是第 2 页；若起始地址是 3，这一页只剩 13 个字节可写，超出部分会回卷覆盖页首数据（素材原文「多发送的字节会将前面的覆盖掉」）。所以页写前必须算 16 - (addr % 16)。

九、时钟同步与总线仲裁 #

多主机是 I2C 相对 SPI/UART 的关键加分项，靠的是两个都建立在「线与」上的机制。

时钟同步（clock synchronization） #

多主机同时发时钟时 SCL 不会打架：它是线与的，谁拉低都算低。

text
主机 A SCL:  ‾|_|‾‾‾|_|‾‾‾
主机 B SCL:  ‾‾|_|‾|_|‾‾‾
线上 SCL  :  ‾|_|_|_|‾‾‾      <- 谁的低电平长就以谁为准
             ^ 低电平取最长
  • 低电平：任一主机拉低线上就是低，低电平周期由最慢的机决定。
  • 高电平：所有主机都释放才为高，高电平周期由最快的机决定。

净效果是周期被拉到「最慢者」，两家都能正确打点。第十章从机拉低 SCL 就是从这个逻辑里长出来的。

总线仲裁（arbitration） #

text
主机 A 发:   1  0  1  1  0
主机 B 发:   1  0  0  1  0
线上 SDA:    1  0  0  1  0
                    ^ A 想发 1 但线是 0，A 输，退出发送

判据：主机每发一位同时回读 SDA。发了 1 却读到 0，说明有人同时在发 0，自己输了。发出电平与线上一致就继续发，直到独占总线。

输了的那台必须做三件事：立刻停止驱动 SDA（切输入/释放），不能发 STOP——总线上还有赢家在传；转为从机接收模式，听后续内容；等总线空闲后重新申请。

仲裁的边界：

  • 仲裁在数据位上逐位进行，不破坏任何一位数据，赢家的帧完整无损。
  • 只比较地址和数据，不比 START/STOP。多个主机几乎同时发 START 是合法起点。
  • 赢了地址仲裁但收到的地址 ACK 为 NACK（没人认领），必须放弃总线，让其他主机继续。
  • 输了的机在回读到自己输的那一刻，可以切到从机模式直接收赢家发给自己的数据，这是「多主」真正的价值。
  • 时钟同步先把 SCL 拽到最慢，仲裁再在同步后的时钟上逐位比 SDA，两者不冲突。

十、时钟拉伸（Clock Stretching） #

慢速从机来不及处理时，会在 SCL 低电平期间主动把 SCL 拉低并保持住。主机释放 SCL 想让它变高，线上仍是低——这就是时钟拉伸。

text
SCL（主机想发）:   __    __    __    __    __
SCL（实际线上）:   __|  |____________________|  |__
                      ^从机拉低并保持          ^从机释放
SDA               <卡在中间某一位的建立阶段>
阶段 主机动作 从机动作 线上 SCL
正常时钟高 释放 SCL 不拉 高
拉伸开始 释放 SCL 期望变高 拉低 SCL 并保持 低（被从机扣住）
拉伸中 检测到 SCL 仍为低，等待 内部处理数据 低
拉伸结束 检测到 SCL 变高，继续发时钟 释放 SCL 高

实现要点：

  • 主机必须回读 SCL，不能写完寄存器就当它已经变高。硬件控制器多半内建这个等待逻辑，软件模拟要自己写 while(读SCL==0);。
  • 拉伸只拉长低电平，不改变数据内容，也不影响 ACK 判定。
  • 拉伸可以发生在每一位的低电平期间，也可以发生在 ACK 位之前，让从机有时间准备应答。
  • 从机不能拉伸起始信号之前的总线空闲期（空闲时从机不该动线）。
  • 从机拉伸时间有限，主机侧要配超时，否则从机挂死会把整根总线拖住。

时钟拉伸是 I2C 的「天然流控」，也是它比 SPI 慢的一个原因：SPI 从机没有反向控制时钟的机制，只能靠降速或加握手引脚。

调试视角：抓波形看到 SCL 高电平段被拖长、SDA 平稳不动，先在逻辑分析仪上确认是被从机拉低，而不是上拉电阻太弱导致的慢上升沿。区别在于电平是否干净贴在 GND，而不是缓慢爬升。

十一、重复起始条件 #

一次传输中途要改方向，不发 STOP 再发 START，而是发一个重复起始 Sr（Repeated START）。

不能拆成 STOP + START 的理由：STOP 之后总线变成空闲，任何主机都有权抢总线，两个动作之间的间隙里，你的复合帧（写寄存器地址 + 读数据）就有机会被其他主机插进来。Sr 期间总线从未释放。

text
STOP+START: |<- STOP 后空闲 ->|  间隙内会被别的机抢走
Sr        : 直接在 SCL 高电平期间把 SDA 拉低，总线自始至终被你占着

Sr 与 START 的电平特征完全一样（SCL 高时 SDA 下降沿），区别只在上下文：出现在一帧中间是 Sr，出现在总线空闲之后是 START。

场景 需要 Sr 吗
写内部寄存器地址后再读数据（EEPROM 随机读、LM75 读温度） 需要
传输中途切换方向 需要
一次写操作写完就结束 不需要，直接 STOP
连续读多个字节 不需要，靠主机 ACK/NACK 控制节奏

LM75 读温度是标准复合帧：先写 pointer 指向温度寄存器，Sr 后读两个字节。温度寄存器 16 位，高 8 位是整数部分，第 7 位为 1 表示再加 0.5 摄氏度，最高位为 1 表示读到的是负数补码。两字节之间主机回 ACK，第二个字节之后回 NACK 再 STOP。

软件模拟里 Sr 就是再调一次 I2C_Start()，不要先调 I2C_Stop()——Read24c08() 那两行就是这个写法。

十二、总线速率模式：标准、快速、高速 #

素材给出的频率分级（与 Philips/NXP 规范一致）：

模式 最高速率 素材依据 上拉 / 驱动要求
低速模式 10 kbps 素材称「另外一些变种实现了」 原文未标注
标准模式 Standard-mode 100 kbps 素材明确 开漏 + 上拉，总线电容 ≤ 400pF
快速模式 Fast-mode 400 kbps 素材明确 同上，边沿更陡，上拉需更小
快速+ 模式 Fast-mode Plus 1 Mbps 素材称「一些变种实现了」 原文未标注
高速模式 High-speed mode 3.4 Mbps 素材明确 原文未标注，规范另有一套电流源/下拉方案（本文未验证）

四点必须讲清：

素材把 3.4 Mbps 写成「高度模式」，是笔误，应为「高速模式」。 本文统一。

单位。 素材用的是 kbps / Mbps（每秒比特）。I2C 每字节带 1 个应答位，有效字节吞吐 = 比特率 × 8/9，100 kbps 的有效载荷约 88.9 kB/s 量级。协议本身没有字节率指标。

速率与上拉的关系。 频率越高，位周期越短，上升沿必须在更短时间内完成，上拉电阻就越小；上拉越小，低电平灌电流越大（I = Vcc / R），器件下拉能力必须扛得住。这就是「速率高 → 上拉小 → 灌电流大」的三角约束。阻值本文不给表格，原文未标注，按器件手册与 400pF 上限算。

线长与电容。 素材明确电容不得超过 400pF，速率越高可容忍的线长越短。更长距离只能在规范外想办法（降速、容性缓冲、换差分总线），素材只提一句「可以通过其他的方法增加总线的电容量」，未展开。

频率的选择权在主机。 主机必须选所有从机都支持的速率。慢器件不能靠时钟拉伸规避高频时序违规——拉伸只能延长低电平，不能修正建立/保持时间。

十三、设备地址的分配与冲突 #

地址不是随便写的，由器件型号和引脚共同决定。三种常见形态：

类型 地址来源 例子
固定地址 型号内定，不可改 部分传感器、专用芯片
引脚可配 高几位固定，低几位由 ADDR 引脚电平决定 LM75：高 4 位固定，低 3 位由三个地址引脚定
地址位复用 地址位兼作片内块选择 AT24C08：块号塞进地址位

AT24C08 是第三种形态的典型。它把 1024 字节存储区分成 4 个 BLOCK，每块 256 字节，块号通过地址字节里被征用的位来选：

块 7 位地址 写（+0） 读（+1） 片内范围
第一块 0x50 0xA0 0xA1 0x000~0x0FF
第二块 0x51 0xA2 0xA3 0x100~0x1FF
第三块 0x52 0xA4 0xA5 0x200~0x2FF
第四块 0x53 0xA6 0xA7 0x300~0x3FF

代码里 0xA0 + block * 2 与 0xA1 + block * 2 就是这个表：块号每加一，地址加 2（最低位是方向位），片内偏移用 address % 256。

配套引脚：A0/A1/A2 器件地址选择（对应引脚 1/2/3），SDA 数据线，SCL 时钟线，WP 写保护（高电平写入保护），VCC +1.8~6.0V，GND。容量与页大小：AT24C01/02/04/08/16 分别 1K/2K/4K/8K/16K 位，内部 128/256/512/1024/2048 个 8 位字节；AT24C01 页缓冲 8 字节，AT24C02/04/08/16 页缓冲 16 字节。

地址冲突的四种成因：

成因 表现 排查方向
同型号两个器件地址引脚接法一样 两个器件同时应 ACK，读回数据互相踩踏 改 ADDR 引脚接法，或加 I2C 多路复用器
7 位/8 位形态混用 写地址发成 0xD0（把 0x68 左移后再错移） 对齐手册里的 7 位地址与代码里的 8 位形态
地址位被复用（如 EEPROM 块号） 跨块访问时打到别的块 复算 block = address / 256
保留地址被误用 通用呼叫地址触发全体器件 避开 0000xxx 段

线的逻辑决定了冲突后果：两个从机同地址时，它们的 ACK 会叠加成合法的低电平，主机无法通过 ACK 发现冲突。只有读回数据不对时才暴露，且是间歇性的。多器件同型号同地址要在硬件设计阶段消灭，软件层无解。

十四、I2C 与其他总线的对比 #

维度 I2C SPI UART
信号线数 2（SDA、SCL） 4+（SCLK、MOSI、MISO、每从机 1 根 CS） 2（TX、RX，交叉连接）
通信方式 同步、半双工 同步、全双工 异步（无时钟线）
时钟来源 主机产生，从机可拉伸 主机产生 双方各自按波特率
设备寻址 地址寻址（7 位 / 10 位） 片选线寻址（硬件 CS） 点对点，无寻址
器件扩展 受地址空间与 400pF 电容限制 受 CS 引脚数限制 点对点，扩展需额外硬件
多主机 支持，靠仲裁 不支持 不支持
应答机制 每字节 1 位 ACK/NACK 无 无（可用软件协议）
典型速率 100 kbps / 400 kbps / 1 Mbps / 3.4 Mbps 远高于 I2C（具体值随器件，素材未给） 由双方约定波特率
电气 开漏 + 上拉，线与 推挽 推挽
典型用途 传感器、EEPROM、RTC、PMIC 配置 Flash、LCD、高速 ADC 串口终端、模块间通信

取舍三句话：要省线、挂一堆低速器件、要地址寻址，选 I2C（代价是速率与电容上限）；要带宽、要全双工，选 SPI（代价是每加一个从机多一根 CS）；只要点对点、两边时钟不同步，选 UART（没有时钟线就没有仲裁与拉伸，也没有地址）。

I2C 的独特价值就两点：两条线挂多个器件、多主机可仲裁。两者都由开漏 + 线与这一条电气设计撑起来。

十五、易错点速查 #

# 坑 症状 处理
1 SCL 高电平期间改 SDA 被当成 START/STOP，帧错位 数据只在 SCL 低时换；写代码时先 SCL=0 再动 SDA
2 7 位地址当 8 位发 全部 NACK，器件不应答 手册给 7 位，代码要 <<1 再补方向位

7 EEPROM 页写跨页 数据回卷覆盖页首 单次写入不超过 16 - (addr % 16)
8 上拉电阻过大 上升沿慢、高速下位丢失 按 400pF 与频率算 RC，示波器看 tr
