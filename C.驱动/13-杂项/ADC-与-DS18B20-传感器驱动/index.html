ADC 和 DS18B20 是两个不走标准总线的设备：一个躲在 SoC 里，靠专用模拟引脚分时采样；一个挂在单根 GPIO 上，靠软件死磕微秒级时序。这篇把两个都拆开。

一、ADC 是什么：模拟量到数字量 #

机器只认数字，模拟量要先进 ADC 才能被 CPU 看见。

FS4412 板上的典型接法是一个滑动变阻器：两端分别接 VDD1V8_EXT（1.8V）和地，滑片引出一根线接到 SoC 的 XadcAIN3 引脚。旋钮转到底，XadcAIN3 上是 0V；转到另一头，是 1.8V；中间任意位置是两者之间的某个电压。ADC 干的活，就是把这个连续电压切成一格一格的数字。

Exynos4412 片内 ADC 的参数：

位数由 ADCCON[16] 选，10 位或 12 位；4 路模拟输入 XadcAIN[0..3] 共用一个转换器，分时复用；输入范围 0 ~ 1.8V，参考电压由 VDD1V8_EXT 提供；最大转换速率 1 MSPS，前提是把 ADC 时钟做到 5MHz；结构是 CMOS 循环式（recycling），带片上采样保持和待机模式；一次转换结束（EOC）产生中断，接 combiner 的 SPI 10。

这几个模拟引脚是专用输入脚，名字只有 XadcAINn 一个，不像 GPIO 那样带一堆复用功能。用 ADC 不需要去 pinctrl 里配功能，选好通道直接读。

Exynos4412 没有片内 DAC。要往外输出模拟量，得外挂 DAC 芯片，或者用 PWM 加 RC 滤波凑一个。本篇不碰这块。

二、ADC 的分辨率与参考电压 #

n 位 ADC 能分辨的最小电压，是满量程的 1/2^n。位数越高，切得越细，但细的上限卡死在参考电压上。

位数 量化级数 1 LSB（参考 1.8V） 满码值
10 1024 1.758 mV 1023
12 4096 0.4395 mV 4095

12 位、1.8V 参考，1 LSB ≈ 0.44mV。这个数是本篇所有换算的基准。

text
V    = code × Vref / 2^n = code × 1.8 / 4096
code = V × 4096 / 1.8

应用层那行打印就是照这个写的：

c
printf("adc%0.2f V \n", (1.8 * adc) / 4096);

adc 最大 4095，1.8 * adc 最大 7371，塞进 double 不溢出。除数是 4096 而不是 4095——量化是除法关系，满码 4095 对应的是 4095/4096 的满量程，差半个 LSB，工程上直接忽略。

两个容易踩的点。一是分母别写错，写成 /4095 会让满码刚好等于 1.8V，看起来「对」，但中间每一格的偏差被摊开了，采 0.9V 附近会有 0.44mV 级的系统误差。

二是参考电压必须实测。板上标 1.8V，实测 1.75V 是常事，这时候整套换算整体偏低 2.8%，而且偏差是线性的——你采 0.1V 只差 3mV 看不出来，采 1.7V 就差 47mV 了。要准，拿万用表量 VDD1V8_EXT，把常量改掉。

三、Exynos4412 的 ADC 控制器 #

寄存器基地址 0x126C0000，映射长度 0x20，也就是 8 个 32 位寄存器的空间，实际只用了 5 个。

时钟链只有两级：PCLK 进来，先过预分频器（PRSCVL），得到 ADC 时钟，ADC 时钟再 5 分频作为转换节拍。手册限制 ADC 时钟不得超过 5MHz，超了转换结果不可信。

text
PCLK ──► [ ÷(PRSCVL+1) ] ──► ADCclk（≤5MHz）──► [ ÷5 ] ──► 一次转换
ADCclk   = PCLK / (PRSCVL + 1)
转换时间 = 5 × (PRSCVL + 1) / PCLK

PCLK 按 100MHz 算（FS4412 的常见配置，素材没给实测值，下表按 100MHz 折算）：

PRSCVL 分频 ADCclk 单次转换 理论采样率
19（0x13） 20 5.000 MHz 1.0 us 1 MSPS
25（0x19） 26 3.846 MHz 1.3 us 769 kSPS
255（0xFF） 256 390.6 kHz 12.8 us 78 kSPS

原文驱动里 PRSCVL 填的是 0xFF，也就是 256 分频。这个值离 5MHz 上限远得很，单次转换要 12.8us。采个滑动变阻器绰绰有余，要高速采样就得往 19 靠。

只有 4 个引脚却只有 1 个转换器：内侧是一个 ADC 核，外面挂一圈模拟开关，ADCMUX 就是那个开关的选择信号。同一时刻只能采一路，切通道之后要等采样保持电路稳定——这个稳定时间不归 ADCMUX 管，触摸屏场景下才由 ADCDLY 调。

中断走的是 combiner。设备树里写 <10 3>，10 是 SPI 号，3 是触发类型。Samsung 这套中断类型编码里，1 是上升沿、2 是下降沿、3 是双边沿、4 是高电平、8 是低电平。EOC 是电平型信号，理论上该用 4；原文用 3 也能跑，因为双边沿在信号跳变时也会触发一次。这一条按通用约定写的，具体以 SoC 中断表为准。

四、ADC 的寄存器 #

一共五个，偏移和用途：

寄存器 偏移 作用 本篇用法
ADCCON 0x0000 控制：分辨率、预分频、启动、状态 写配置 + 启动，读 ECFLG 查状态
ADCDLY 0x0008 转换延时（触摸屏 X/Y 切换用） 普通采样不改
ADCDAT 0x000C 转换结果 读低 12 位
CLRINTADC 0x0018 清中断 中断里写任意值
ADCMUX 0x001C 通道选择 写 3 选 XadcAIN3

ADCCON 的位定义，这是全篇最要紧的一张表：

位 名称 含义
[16] RES 1 = 12 位转换，0 = 10 位
[15] ECFLG 只读。0 = 转换中，1 = 转换结束
[14] PRSCEN 1 = 使能预分频器
[13:6] PRSCVL 分频系数，实际分频 = 值 + 1
[2] STANDBY 1 = 待机（省电），0 = 正常工作
[1] READ_START 1 = 读一次 ADCDAT 就自动启动下一次转换
[0] ENABLE_START 写 1 启动一次转换，转换完硬件自动清 0

原文那个配置值，拆开看：

text
ADCCON = (1 << 16) | (1 << 14) | (0xFF << 6) | (1 << 0)
       = 0x00010000 | 0x00004000 | 0x00003FC0 | 0x00000001
       = 0x00017FC1
  bit16 = 1    12 位分辨率
  bit14 = 1    使能预分频
  bit13:6 = FF 256 分频 → ADCclk = 390.6kHz（PCLK=100MHz）
  bit2  = 0    正常工作，不待机
  bit1  = 0    不用读触发
  bit0  = 1    ENABLE_START，写 1 立刻开始一次转换

ADCDAT 只有低 12 位有值，高位是无效位、带随机值，读出来必须 & 0xFFF。少写这个掩码，你会在 10 位模式下读到带高位垃圾的数，算出来的电压远超 1.8V。

CLRINTADC 是写清寄存器，往里面写什么值都行。原文写的是 0x12，只是图个眼熟，没有位含义。ADCMUX 直接写通道号，0~3。ADCDLY 在普通 ADC 采样里用不上，它的值只在触摸屏切 X/Y 时决定「切换后等多久再采」，原文只给了偏移 0x0008，没展开位域，具体字段划分以 SoC 手册为准。

五、ADC 驱动的整体结构 #

这个驱动是四件东西拼起来的：platform 驱动负责和硬件对上号，字符设备负责给用户态开口子，中断负责「转换完了」这个事件，等待队列负责让 read() 睡过去。

设备树节点描述基址、中断号和中断父节点；platform 驱动靠 of_device_id 的 compatible 匹配成功后进 probe；资源层用 platform_get_resource 从资源数组里捞 IRQ 和 MEM；硬件层用 ioremap 加 readl / writel 读写寄存器；中断层用 request_irq 挂 adc_handler，管转换结束通知；阻塞层是一对 wait_queue_head_t 加 have_data，管 read() 的睡眠与唤醒；接口层是 register_chrdev 加 file_operations，在 /dev 下开个字符设备。

全局变量就这几个，撑起整个状态：wq 是读阻塞队列，have_data 是数据就绪标志（0 没有 / 1 有），adc 存一次转换结果，res1 / res2 是 IRQ 和 MEM 资源指针，adc_base 是 ioremap 之后的虚拟基址，major 是主设备号（原文硬编码 250）。

probe 只干三件事：platform_get_resource 拿 IRQ 号并 request_irq 注册中断；platform_get_resource 拿内存资源并 ioremap 成虚拟地址；register_chrdev 注册字符设备，init_waitqueue_head 初始化等待队列。

六、ADC 的采样流程 #

一次完整采样，横跨用户态 read() 和内核态中断，两边通过 have_data 握手。

text
read() 这边：
  1. writel(0x3, ADCMUX)          选通道 3
  2. writel(0x00017FC1, ADCCON)   写 1 到 bit0，启动一次转换
  3. wait_event_interruptible(wq, have_data == 1)   睡过去，等中断叫醒
  4. adc = readl(ADCDAT) & 0xFFF  取结果
     copy_to_user(buf, &adc, sizeof(int))           上报给用户态
     have_data = 0                清标志，为下一次做准备
adc_handler() 这边：
  1. have_data = 1                置位，告诉 read 数据到了
  2. writel(0x12, CLRINTADC)      清中断，不清会一直重入
  3. wake_up_interruptible(&wq)   唤醒睡着的 read
     返回 IRQ_HANDLED

合起来看：用户态在 wait_event 里睡着，中断在硬件转换结束时把它叫醒，两边交接的凭据就是 have_data。

为什么用中断不用轮询：轮询 ECFLG 得在 read() 里忙等，一次 12.8us 不长，但用户态 read() 每次进来都空转一轮 CPU，且没法被信号打断。中断加等待队列，read() 在转换期间是睡眠的，不占 CPU。

原文这里有两个坑，改法记在第八节代码里。第一，wait_event_interruptible 的返回值没判，这个函数被信号打断时返回非 0，此时转换还没完成，adc 里是上一次的旧值，copy_to_user 照样把它报上去。第二，have_data = 0 放在 copy_to_user 之后，如果 copy_to_user 失败返回 -EFAULT，have_data 就停在 1，下一次 read() 的 wait_event 条件立刻成立，直接返回一条陈年数据。

七、触摸屏与 ADC 的关系 #

四线电阻屏和 ADC 是同一个原理，只是把「读一个电位器」变成「轮流读两个方向」。

屏体是两层 ITO 导电膜，中间隔着绝缘点。按下时上下两层在某点接触，等于把 X 方向和 Y 方向各接出一个分压点。测一个坐标要两步：

text
测 X：XP 接 VDD，XM 接 GND → 读 YP，电压正比于 X 坐标
测 Y：YP 接 VDD，YM 接 GND → 读 XP，电压正比于 Y 坐标

关键在于「切换」。从测 X 切到测 Y，模拟开关要重新配置，导电膜上有寄生电容，电压梯度要过一段时间才稳定。这段等待时间就是 ADCDLY 存在的理由：填得小，切完立刻采，采到的是还在爬升的电压，坐标会偏；填得大，稳是稳了，采样率掉下去。这也是为什么 ADCDLY 在纯 ADC 采样场景下不用管——你没有切换动作，不存在稳定时间问题。

在 Exynos4412 上，ADC 和触摸屏控制器是两个独立模块。ADC 在 0x126C0000，触摸屏那套是单独的 TSADC，基址素材没给（按 Exynos4 系列手册是 0x10010180，未验证）。触摸屏驱动一般挂在 input 子系统下，上报 ABS_X / ABS_Y / ABS_PRESSURE，还要处理按下中断、抬起中断、去抖和坐标校准，是另一篇的量级。本篇只讲这层关系：触摸屏 = ADC + 模拟开关 + 一套坐标换算，ADC 是它的底座。

八、ADC 驱动的完整实现 #

先写设备树节点。compatible 是驱动和设备对暗号的唯一凭据，两边必须一字不差。interrupt-parent 指到 combiner，因为 ADC 的中断线不是直连 GIC 的 SPI，而是先汇总到 combiner 再往上走。

dts
fs4412-adc {
    compatible = "fs4412,adc";
    interrupt-parent = <&combiner>;
    reg = <0x126C0000 0x20>;   /* 基址 0x126C0000，长度 0x20 */
    interrupts = <10 3>;       /* SPI 号 10，触发类型 3（双边沿） */
};

内核解析这个节点后，会把它拆成一串 struct resource，塞进 platform_device。顺序上 IRQ 和 MEM 谁在前取决于解析器，这就是为什么必须用类型 + 索引两段式取值，不能按下标硬猜。素材 2 给过一个资源数组的形态：

c
struct resource adc_resources[] = {
    [0] = { .start = IRQ_NUM,    .end = IRQ_NUM,
            .flags = IORESOURCE_IRQ },          /* 第 0 个 IRQ */
    [1] = { .start = 0x126C0000, .end = 0x126C0000 + 0x20,
            .flags = IORESOURCE_MEM },          /* 第 0 个 MEM */
    [2] = { .start = 0x126C0000, .end = 0x126C0000 + 0x20,
            .flags = IORESOURCE_MEM },          /* 第 1 个 MEM */
};

取值函数原型：

c
struct resource *platform_get_resource(struct platform_device *dev,
                                       unsigned int type,
                                       unsigned int num);

type 是 IORESOURCE_MEM 或 IORESOURCE_IRQ，num 是同类资源里的序号，从 0 起。函数内部先按 flags 过滤掉别类，再在剩下的里数到第 num 个。所以 platform_get_resource(pdev, IORESOURCE_MEM, 1) 拿到的是 [2] 那一项，platform_get_resource(pdev, IORESOURCE_IRQ, 0) 拿到的是 [0] 那一项。

中断处理函数。have_data 先置位再唤醒，顺序不能反——先唤醒后置位的话，被唤醒的进程在另一个 CPU 上先跑，看到 have_data 还是 0，条件不成立，又睡回去，这一次唤醒就丢了。

c
static irqreturn_t adc_handler(int irqno, void *dev)
{
    have_data = 1;
    printk("11111\n");
    /* 清中断 */
    writel(0x12, adc_base + CLRINTADC);
    wake_up_interruptible(&wq);
    return IRQ_HANDLED;
}

read() 是把第六节那张流程图落成代码。相比原文，这段补了三处：清标志提前、判返回值、返回真实字节数。

c
static ssize_t adc_read(struct file *filep, char __user *buf, size_t len, loff_t *pos)
{
    int ret;
    if (len < sizeof(int))
        return -EINVAL;
    /* 1. 清标志要在启动之前，避免上一轮的残留数据被当成新数据 */
    have_data = 0;
    /* 2. 选通道 3，启动一次转换 */
    writel(0x3, adc_base + ADCMUX);
    writel((1 << 16) | (1 << 14) | (0xFF << 6) | (1 << 0), adc_base + ADCCON);
    /* 3. 睡眠等中断；被信号打断要原样退出去，不能拿旧数据充数 */
    ret = wait_event_interruptible(wq, have_data == 1);
    if (ret)
        return -ERESTARTSYS;
    /* 4. 读结果，只取低 12 位 */
    adc = readl(adc_base + ADCDAT) & 0xFFF;
    if (copy_to_user(buf, &adc, sizeof(int)))
        return -EFAULT;
    return sizeof(int);
}

register_chrdev 那条路径不需要 open / release 做任何事，留空壳：

c
static int adc_open(struct inode *inod, struct file *filep) { return 0; }
static int adc_release(struct inode *inode, struct file *filep) { return 0; }
static struct file_operations adc_ops = {
    .open    = adc_open,
    .release = adc_release,
    .read    = adc_read,
};

probe 里有一个必须纠正的顺序问题。init_waitqueue_head 要在字符设备注册之前——注册完设备节点，用户态随时能 open 并 read，此时等待队列头还是全零的未初始化内存，wait_event_interruptible 往里挂进程，轻则链表错乱，重则 oops。

c
static int hello_probe(struct platform_device *pdev)
{
    int ret;
    printk("match ok \n");
    res1 = platform_get_resource(pdev, IORESOURCE_IRQ, 0);
    res2 = platform_get_resource(pdev, IORESOURCE_MEM, 0);
    if (!res1 || !res2) {
        printk("get resource failed\n");
        return -ENODEV;
    }
    ret = request_irq(res1->start, adc_handler, IRQF_DISABLED, "adc1", NULL);
    if (ret) {
        printk("request_irq failed %d\n", ret);
        return ret;
    }
    adc_base = ioremap(res2->start, res2->end - res2->start + 1);
    /* 等待队列先初始化，再注册设备 */
    init_waitqueue_head(&wq);
    register_chrdev(major, "adc", &adc_ops);
    return 0;
}

ioremap 的长度原文写 res2->end - res2->start，少了 1。end 是闭区间，按闭区间语义实际覆盖 0x21 个字节。多映射一个字节无伤大雅，少映射一个才会出事，写成 + 1 是稳妥写法。IRQF_DISABLED 在 3.x 里已被标记为过时，作用是让中断处理期间关掉本地中断，现代内核直接传 0 或用 IRQF_SHARED（共享中断线时）。

remove 里原文写了两次 free_irq，第二次拿 res2->start（一个内存地址 0x126C0000）当中断号去释放，是笔误。res2 是内存资源，该用 iounmap：

c
static int hello_remove(struct platform_device *pdev)
{
    free_irq(res1->start, NULL);
    iounmap(adc_base);
    unregister_chrdev(major, "adc");
    return 0;
}

    if (fd < 0) {
        perror("open fail \n");
        return -1;
    }
    while (1) {
        len = read(fd, &adc, 4);
        if (len == 4)
            printf("adc %0.2f V \n", (1.8 * adc) / 4096);
    }
    close(fd);
    return 0;
}

设备节点名对不上是个隐患：register_chrdev(major, "adc", ...) 只登记了主设备号和名字，不会创建 /dev/hello。要么手工建节点，要么在 probe 里补 class_create + device_create 自动建。原文测试程序打开的是 /dev/hello，和设备注册名 adc 不一致，跑之前得先建好。

text
insmod adc_drv.ko
mknod /dev/hello c 250 0
./app

read() 返回 sizeof(int) 而不是 len。原文返回 len，用户态传 4 时恰好一致，传 8 就会谎报读了 8 字节，实际只填了 4 字节，用户态会当成成功读满，后面 4 字节是垃圾。返回真实写入量才符合 read 的语义。

九、DS18B20 是什么：单总线协议 #

DS18B20 是 Dallas（现属 ADI）的数字温度传感器，测温范围 -55℃ ~ +125℃，可配置 9~12 位分辨率，TO-92 三脚封装，三个脚是 VDD、GND、DQ。

它最特别的地方是一根线同时干三件事：供电（寄生供电模式下）、时钟、数据。没有 SCLK，没有 CS，主机和从机的节奏全靠「主机拉低多久、什么时候采样」来对齐。这种协议叫 1-Wire，Dallas 的单总线。

单总线能成立的前提是总线上必须有上拉电阻，典型 4.7kΩ 接到 3.3V 或 5V。所有器件都是开漏输出，平时线被上拉成高电平，谁要发 0 就把线拉低，发 1 就撒手让上拉电阻把线拽回去。这就是为什么代码里每次写完都要 s3c2410_gpio_setpin(DQ, 1)——不是「输出高电平」，是「释放总线」。

挂多个器件时，靠每个片子内部烧死的 64 位 ROM 号区分，里面含 8 位家族码（DS18B20 是 0x28）、48 位序列号和 8 位 CRC。

一次完整测温的协议流程：

text
复位（主机拉低 480us+，从机回存在脉冲）
  → ROM 操作指令（0xCC 跳过 ROM，只有一个器件时用）
    → 存储器操作指令（0x44 启动转换 / 0xBE 读暂存器）
      → 数据传输

原文点得很准：这个顺序不能乱。1-Wire 是分时完成的，「如果出现序列混乱，1-WIRE 器件将不影响主机」——它不报错、不应答，你就只能看着读回一堆 0xFF 或 0x00 干瞪眼。

命令码表：

命令 码值 作用
跳过 ROM 0xCC 不匹配 ROM 号，直接对总线上所有器件发下一条命令
读 ROM 0x33 读 64 位 ROM 号（单器件时可用）
匹配 ROM 0x55 后跟 64 位 ROM 号，选中特定器件
搜索 ROM 0xF0 枚举总线上的所有器件
报警搜索 0xEC 找温度越限的器件
温度转换 0x44 启动一次转换，12 位模式下耗时最长 750ms
写暂存器 0x4E 写 TH / TL / 配置寄存器
读暂存器 0xBE 连续读出 9 字节暂存器
复制暂存器 0x48 把 TH/TL/配置写入 EEPROM

暂存器 9 个字节的布局：

字节 内容
0 温度低 8 位（LSB）
1 温度高 8 位（MSB）
2 TH 高温阈值
3 TL 低温阈值
4 配置寄存器（分辨率位）

读温度其实只要前两字节，但读操作一旦开始就得把时序走完。原文说「读完第 0 和第 1 个数据后就不再理会后面 DS18B20 发出的数据即可」——这话对一半。从机确实会继续往外吐第 2~8 字节，你不再发读时隙，它就不吐了；但要验 CRC，就得老老实实读完 9 字节。

平台信息照录：DS18B20 部分原素材跑在 mini2440（S3C2440），所用 GPIO 是 S3C2410_GPF(3)，内核版本原文未标注。ADC 部分跑 Exynos4412，两边平台不同，本篇讲的是同一套驱动写法在两个平台上的落地。

十、单总线的时序要求 #

1-Wire 的所有动作都可以归结为四种时隙：复位时隙、写 1 时隙、写 0 时隙、读时隙。每一种都是一段「主机拉低 → 释放 → 在某个窗口内采样」的固定桥段。

先把参数摆出来。下表左边是 Dallas 手册的规范值，右边是原文代码实际用的值：

时隙 规范要求（手册） 原文代码 是否符合
复位低电平 480 ~ 960 us udelay(500) 符合
复位后等待存在脉冲 15 ~ 60 us 内出现 udelay(60) 后采样 卡在上限
存在脉冲宽度 60 ~ 240 us 从机决定 由从机给
写周期总长 60 ~ 120 us udelay(60) + 开销 贴下限
写 1 低电平 1 ~ 15 us 拉低后立刻置 1 符合
写 0 低电平 60 ~ 120 us udelay(60) 贴下限
从机采样窗口 拉低后 15 ~ 45 us — 由从机执行
读时隙低电平 1 ~ 15 us udelay(2) 符合
读采样点 拉低后 15 us 内 2+2+8 = 12 us 符合
读时隙总长 ≥ 60 us 12 + 50 = 62 us 符合
时隙间隔（恢复） ≥ 1 us udelay(2) 符合

这张表是整篇 DS18B20 部分的核心。原文代码的取值几乎每项都贴着边：udelay(60) 同时用在写周期和复位后的等待上，60us 是规范下限，函数调用开销一叠加，就跌到规范之外。

三条硬规则。第一，所有时隙由主机发起，从机从不主动；从机只在两种时刻动线——复位后的存在脉冲，和读时隙里往外送位，其余时间只是被动采样。

第二，位是先低后高，字节是先低后高。每个时隙都以主机拉低开始，这是给从机的「同步信号」。一个字节 8 位，先发 bit0，所以 0xCC（二进制 1100 1100）上总线的顺序是 0,0,1,1,0,0,1,1。

第三，任何两次操作之间总线必须回到高电平，且至少保持 1us。这是恢复时间，让总线电容重新充到高电平，代码里每个时隙开头那个 setpin(DQ, 1); udelay(2); 就是干这个的。

时序精度等级：这些都是微秒级要求，最窄的窗口是「写 1 的低电平 1~15us」和「读采样点 15us 内」。软件模拟时必须用 udelay，不能用 msleep——后者最小粒度是一整个调度节拍，1ms 到 10ms 起步，比整个时隙宽几十倍。

十一、复位脉冲与应答 #

复位是每次通信的起手式，作用是让总线上所有从机把内部状态机归零，准备好接收命令。

text
主机的动作：
  1. 主机拉低总线，保持 480 ~ 960 us（原文用 500us）
  2. 主机释放总线，上拉电阻把线拉回高电平
  3. 主机在随后 480us 内持续检测总线
  4. 检测到低电平 → 有器件应答，复位成功；一直是高电平 → 复位失败
从机的动作：
  1. 上电后一直检测总线
  2. 检测到 480 ~ 960us 的低电平 → 知道主机要复位
  3. 主机释放后，等 15 ~ 60 us
  4. 主动拉低总线 60 ~ 240 us，这就是「存在脉冲」
  5. 撒手，总线回到高电平

关键点：存在脉冲是从机拉低的，不是主机。主机在释放总线之后必须把 GPIO 切成输入模式，才能读到从机拉出来的低电平。如果一直保持输出模式且输出高，从机拉低时会和主机对推，读回来永远是高，复位永远「失败」。

c
static int ds18b20_init(void)
{
    int retval = 0;
    s3c2410_gpio_cfgpin(DQ, CFG_OUT);   /* 先切成输出 */
    s3c2410_gpio_pullup(DQ, 0);         /* 关内部上拉，靠外部 4.7k */
    s3c2410_gpio_setpin(DQ, 1);         /* 释放总线，回到高电平 */
    udelay(2);                          /* 恢复时间 */
    s3c2410_gpio_setpin(DQ, 0);         /* 拉低，开始复位 */
    udelay(500);                        /* 保持 500us */
    s3c2410_gpio_setpin(DQ, 1);         /* 释放总线 */
    udelay(60);                         /* 等从机把线拉低 */
    s3c2410_gpio_cfgpin(DQ, CFG_IN);    /* 切成输入才能读到从机的低电平 */
    retval = s3c2410_gpio_getpin(DQ);   /* 读到 0 说明有存在脉冲 */
    udelay(500);                        /* 等存在脉冲走完 */
    s3c2410_gpio_cfgpin(DQ, CFG_OUT);   /* 切回输出 */
    s3c2410_gpio_pullup(DQ, 0);
    s3c2410_gpio_setpin(DQ, 1);         /* 释放总线 */
    return retval;
}

返回值语义要拧清楚：s3c2410_gpio_getpin 读到低电平返回 0，所以返回 0 代表成功。原文的调用方是这么判的：

c
flag = ds18b20_init();
if (flag & 0x01) {
    printk(KERN_WARNING "open ds18b20 failed\n");
    return -1;
}

flag & 0x01 为真说明读到的是 1（高电平），没有存在脉冲，复位失败。逻辑是对的，但可读性差，容易在别处写反。更清楚的做法是让函数返回 0 表示成功、-1 表示失败。

两个时长细节。udelay(60) 之后才采样，是卡在规范上限：存在脉冲最早也要在主机释放后 15us 才出现，最晚 60us，60us 才去采，理论上刚好处在「一定已经出现」的时刻，但从机稍慢一点就采空了。改 udelay(30) 更稳，落在窗口中间。

udelay(500) 等存在脉冲走完，是超时保护。存在脉冲最长 240us，500us 足够，这个值不影响正确性，只影响一次复位操作的总耗时。

十二、读写的位操作 #

写和读都是逐位来，8 次循环凑一个字节。写用「拉低多久」，读用「拉低后多久采样」。

写时隙 #

text
写 1：拉低 ──1~15us──► 释放 ───────── 保持高到周期结束（总长 ≥60us）
写 0：拉低 ───────────────── 60~120us ─────────► 释放

从机在拉低后的 15~45us 之间采样：这个窗口里线是高，就是 1；线是低，就是 0。

c
static void write_byte(unsigned char data)
{
    int i = 0;
    s3c2410_gpio_cfgpin(DQ, CFG_OUT);
    s3c2410_gpio_pullup(DQ, 1);
    for (i = 0; i < 8; i++) {
        /* 总线从高拉至低电平时，就产生写时隙 */
        s3c2410_gpio_setpin(DQ, 1);
        udelay(2);                            /* 时隙间隔，兼恢复时间 */
        s3c2410_gpio_setpin(DQ, 0);           /* 拉低，时隙开始 */
        s3c2410_gpio_setpin(DQ, data & 0x01); /* 写 1 立刻释放，写 0 继续拉低 */
        udelay(60);                           /* 撑满写周期 */
        data >>= 1;                           /* 低位先发 */
    }
    s3c2410_gpio_setpin(DQ, 1);               /* 释放总线 */
}

setpin(DQ, 0) 紧跟 setpin(DQ, data & 0x01)，这两行合起来就是全部玄机。写 1 时，第二行立刻把线放回高电平，低电平持续时间只有两次函数调用的开销，几个微秒，落在 1~15us 里。写 0 时，第二行还是 0，线一直低，被 udelay(60) 撑满。

写 1 的低电平宽度太短反而是安全的，因为规范下限就是 1us。但如果你换成直接操作寄存器，两次写之间只隔几十纳秒，从机未必认得出这是个时隙——这也是为什么很多 1-Wire 实现里在拉低后补一个极短的 udelay(1) 或几条 nop。

udelay(60) 对写 1 来说是「白等」，因为线早就释放了，它对写 0 才起作用。统一 60us 让 8 位的总时长恒定，从机好跟节奏。

读时隙 #

text
  主机拉低 ≥1us ──► 释放（切输入）──► 在拉低后 15us 内采样 ──► 保持到 ≥60us
                                          │
从机在检测到拉低后开始送位 ──────────────┘
  送 0：把线拉低，直到读周期结束
  送 1：撒手，线保持高

c
static unsigned char read_byte(void)
{
    int i;
    unsigned char data = 0;
    for (i = 0; i < 8; i++) {
        /* 总线从高拉至低，维持低电平后再拉高，产生读时隙 */
        s3c2410_gpio_cfgpin(DQ, CFG_OUT);
        s3c2410_gpio_pullup(DQ, 0);
        s3c2410_gpio_setpin(DQ, 1);
        udelay(2);
        s3c2410_gpio_setpin(DQ, 0);   /* 拉低，启动读时隙 */
        udelay(2);                    /* 低电平保持 2us */
        s3c2410_gpio_setpin(DQ, 1);   /* 释放，把总线交给从机 */
        udelay(8);                    /* 等从机把数据摆上线 */
        data >>= 1;                   /* 先收到的是低位，往高位挪 */
        s3c2410_gpio_cfgpin(DQ, CFG_IN);
        if (s3c2410_gpio_getpin(DQ))
            data |= 0x80;             /* 读到高电平，本位是 1 */
        udelay(50);                   /* 撑满读周期，给从机喘息 */
    }
    s3c2410_gpio_cfgpin(DQ, CFG_OUT);
    s3c2410_gpio_pullup(DQ, 0);
    s3c2410_gpio_setpin(DQ, 1);       /* 释放总线 */
    return data;
}

采样时刻算一下：udelay(2) + udelay(8) = 10us，加上几次函数调用，大约 12~13us，落在 15us 的窗口内，符合规范。这个余量不算宽裕，udelay(8) 改成 udelay(5) 会更安全。

data >>= 1 放在 | 0x80 之前，这个顺序是对的：先右移腾出最高位，再按读到的值填最高位，循环 8 次正好把所有位归位。原文注释里那句「总线从高拉至低，只需维持低电平 17ts」中的 17ts 是乱码，按上下文应为 1~2us，代码里实际是 2us。

读时隙结束后 udelay(50)，是在补足读周期到 60us 以上。规范要求读时隙总长至少 60us，主机过早开始下一个时隙，从机会来不及准备下一位。

对照写和读，能看出一个不对称：写的时候主机全程握着总线，读的时候主机拉低 2us 就得撒手，把线让给从机。这是单总线能在一根线上做双向通信的根本——任何时候只有一方在驱动这根线。

十三、温度数据的格式与换算 #

温度是 16 位有符号数，低字节在前（暂存器字节 0），高字节在后（字节 1）。12 位模式下，低 4 位是小数部分，单位 0.0625℃。

text
 bit15 .. bit4    bit3   bit2   bit1   bit0
 ┌──────────────┬──────┬──────┬──────┬──────┐
 │  符号 + 整数  │ 2^-1 │ 2^-2 │ 2^-3 │ 2^-4 │
 └──────────────┴──────┴──────┴──────┴──────┘
      补码整数部分              小数部分

举两个例子：

text
LSB = 0x91, MSB = 0x01 → 拼成 0x0191 → 低 12 位 0x191 = +401
                         401 × 0.0625 = +25.0625 ℃
LSB = 0x5E, MSB = 0xFF → 拼成 0xFF5E → 16 位有符号 = -162
                         -162 × 0.0625 = -10.125 ℃

几个常见码值，可以直接背：

码值（16 位） 温度 说明
0x07D0 +125.0000 ℃ 上限
0x0191 +25.0625 ℃ 常温典型
0x0001 +0.0625 ℃ 最小正增量
0x0000 0 ℃ 零点
0xFFFF -0.0625 ℃ 最小负增量
0xFC90 -55.0000 ℃ 下限

四种分辨率的换算关系：

配置位 R1 R0 分辨率 步进 转换时间（最长）
0 0 9 位 0.5 ℃ 93.75 ms
0 1 10 位 0.25 ℃ 187.5 ms
1 0 11 位 0.125 ℃ 375 ms
1 1 12 位 0.0625 ℃ 750 ms

上电默认是 12 位。分辨率越高，转换越慢——这是硬件逐次逼近的必然，位数每多一位，比较轮次多一轮。

原文应用层的算法规避了浮点：

c
integer_value = ((result[0] & 0xf0) >> 4) | ((result[1] & 0x07) << 4);
/* 精确到 0.25 度 */
decimal_value = 0.5 * ((result[0] & 0x0f) >> 3) + 0.25 * ((result[0] & 0x07) >> 2);
temperature = (float)integer_value + decimal_value;

拆开看，result[0] 是 LSB，result[1] 是 MSB。

整数部分：(result[0] & 0xf0) >> 4 取低字节高 4 位，(result[1] & 0x07) << 4 取高字节的低 3 位左移 4 位，拼起来是 7 位整数。这里丢掉了符号位——result[1] & 0x07 只取低 3 位，result[1] 的 bit3~bit7 全被砍了，而整个 16 位数的补码符号在 result[1] 的最高位。所以这段代码在负温度下会算出完全错误的正值。

小数部分：(result[0] & 0x0f) >> 3 取出小数最高位（0.5 那一位），乘 0.5；(result[0] & 0x07) >> 2 取小数第 2 位（0.25 那一位），乘 0.25。只算到 0.25 精度，第 3、4 位直接扔了。注释写「精确到 0.25 度」是诚实的，但不是 DS18B20 的全部能力。

要正确且不丢精度，直接按有符号 16 位算：

c
static int ds18b20_temp_milli(unsigned char lsb, unsigned char msb)
{
    /* 拼成 16 位有符号原始值，直接转成有符号 int */
    s16 raw = (s16)((msb << 8) | lsb);
    /* 0.0625 度 = 62.5 毫度，raw * 62.5 = raw * 1000 / 16 */
    return (int)((raw * 1000) / 16);
}

返回单位是毫摄氏度，25250 表示 25.250℃。raw 的范围是 ±2048，乘 1000 是 ±2048000，int 装得下。不想用 s16 类型的话，手写一句 if (raw & 0x8000) raw -= 0x10000; 就是补码转有符号。

用户态打印用定点，避开浮点：

c
printf("Temperature: %d.%03d C\n", milli / 1000, abs(milli % 1000));

CRC 校验。暂存器第 8 字节是前 8 字节的 Dallas CRC-8，多项式 x^8 + x^5 + x^4 + 1，即 0x31，初值 0：

c
static unsigned char ds18b20_crc8(const unsigned char *data, int len)
{
    unsigned char crc = 0;
    int i, j;
    for (i = 0; i < len; i++) {
        unsigned char byte = data[i];
        for (j = 0; j < 8; j++) {
            unsigned char mix = (crc ^ byte) & 0x01;
            crc >>= 1;
            if (mix)
                crc ^= 0x8C;        /* 0x31 的反向表示 */
            byte >>= 1;
        }
    }
    return crc;
}

注意 0x31 和 0x8C 的关系：0x31 是正向多项式，最低位先算的写法要用它的位反转，0x31 反转后是 0x8C。两个值都对，取决于移位方向。

读完全部 9 字节后校验：

c
unsigned char buf[9];
int i;
for (i = 0; i < 9; i++)
    buf[i] = read_byte();
if (ds18b20_crc8(buf, 8) != buf[8]) {
    printk("ds18b20 crc error\n");
    return -EIO;
}

原文代码没有做 CRC——它只读了 2 字节，第 8 字节根本没取。温度偶尔跳一下变 85.0000℃（0x0550，这是上电默认值，表示「转换未完成」），就是没校验、把无效数据当真实温度用。

十四、DS18B20 驱动的实现 #

整个驱动就三块内容：一套位操作（上一节的两个函数），一个字符设备外壳，一个 read() 把两者串起来。没有中断，没有等待队列，全部在进程上下文里同步做完。

引脚定义和配置宏放在文件头，换板子只改这两行：

c
/* 相关引脚定义，方便以后移植 */
#define DQ          S3C2410_GPF(3)
#define CFG_IN      S3C2410_GPIO_INPUT
#define CFG_OUT     S3C2410_GPIO_OUTPUT

设备号和结构体。ds18b20_major 初值 0，表示让内核动态分配：

c
static int ds18b20_major = 0;

    struct cdev cdev;
};

static struct device *ds18b20_class_dev;
/* 函数声明 */

open 里做一次复位，探测器件在不在。这样 open 失败就等价于「没接传感器」，问题定位到第一步：

c
static int ds18b20_open(struct inode *inode, struct file *filp)
{
    int flag = 0;
    flag = ds18b20_init();
    if (flag & 0x01) {
        printk(KERN_WARNING "open ds18b20 failed\n");
        return -1;
    }
    printk(KERN_NOTICE "open ds18b20 successful\n");
    return 0;
}

ds18b20_init() 和 write_byte() / read_byte() 就是第十一、十二节的两个函数原样搬进来，这里不重复。read() 是核心，一次读温度要两次复位、两组命令，中间还夹着一段强制等待：

c
static ssize_t ds18b20_read(struct file *filp, char __user *buf,
                            size_t count, loff_t *f_pos)
{
    int flag;
    unsigned long err;
    unsigned char result[2] = { 0x00, 0x00 };
    /* 第一轮：复位 → 跳过 ROM → 启动转换 */
    flag = ds18b20_init();
    if (flag & 0x01) {
        printk(KERN_WARNING "ds18b20 init failed\n");
        return -1;
    }
    write_byte(0xcc);       /* SKIP ROM */
    write_byte(0x44);       /* CONVERT T，启动一次温度转换 */
    /* 第二轮：复位 → 跳过 ROM → 读暂存器 */
    flag = ds18b20_init();
    if (flag & 0x01)
        return -1;
    write_byte(0xcc);       /* SKIP ROM */
    write_byte(0xbe);       /* READ SCRATCHPAD */
    result[0] = read_byte();   /* 温度低八位 */
    result[1] = read_byte();   /* 温度高八位 */
    err = copy_to_user(buf, &result, sizeof(result));
    return err ? -EFAULT : min(sizeof(result), count);
}

这里有个必须点出来的问题：发完 0x44 之后没有任何等待，立刻又发复位去读。12 位模式下转换最长要 750ms，此时去读暂存器，读回的是上一轮的旧值，或者上电默认的 0x0550（85℃）。

原文能读出 23.50℃ 这样的合理值，是因为应用层循环里有个 ds18b20_delay(500) 的空转延时，把两次 read() 之间的间隔撑开了：这一次读的是上一次触发的转换结果。这属于运气，不是设计。正确写法是在 0x44 之后等够时间：

c
    write_byte(0x44);
    msleep(750);            /* 12 位模式最长 750ms，等转换完成 */

msleep 会主动让出 CPU，750ms 里别的进程照常跑。用 udelay(750000) 就是死等 750 毫秒，还会因为 udelay 的单次上限（MAX_UDELAY_MS，2000us 到 5ms 量级）直接行为异常。

file_operations 只有三项，cdev 注册走标准流程：

c
static struct file_operations ds18b20_dev_fops = {
    .owner = THIS_MODULE,
    .open  = ds18b20_open,
    .read  = ds18b20_read,
};

void ds18b20_setup_cdev(struct ds18b20_device *dev, int index)
{
    int err, devno = MKDEV(ds18b20_major, ds18b20_minor + index);
    cdev_init(&dev->cdev, &ds18b20_dev_fops);
    dev->cdev.owner = THIS_MODULE;
    err = cdev_add(&(dev->cdev), devno, 1);
    if (err)
        printk(KERN_NOTICE "ERROR %d add ds18b20\n", err);
}

应用层，循环读并换算：

c
#include <stdio.h>

{
    int fd;
    unsigned char result[2];    /* result[0] 低八位，result[1] 高八位 */
    int raw, milli;
    fd = open("/dev/ds18b20", 0);

        raw = (result[1] << 8) | result[0];

十五、一个 GPIO 模拟单总线 #

DS18B20 讲完了，回头看这根线更本质：单总线就是一个 GPIO，在两个方向之间来回切。

为什么必须是这一个 GPIO：S3C2440 没有 1-Wire 控制器，Exynos4412 也没有。要接 DS18B20，只能拿一个普通 GPIO，用软件把电平按时序摆出来。这不是妥协，Dallas 的器件本来就设计成「能用一根任意 GPIO 驱动」。

一根线怎么既能输出又能输入，靠的是方向切换：

阶段 GPIO 方向 谁在驱动这根线 读回来的含义
主机发送时隙 输出 主机 读回自己的输出
复位后等存在脉冲 输入 从机 低 = 有器件应答
读时隙的采样点 输入 从机 高 = 1，低 = 0
空闲 输出（高）/ 输入 上拉电阻 高

s3c2410_gpio_cfgpin(DQ, CFG_OUT) 和 CFG_IN 来回换的就是这个。切换点必须卡准：复位释放之后、采样之前，一定要先切成输入，否则读到的永远是自己输出的高电平。

上拉电阻必须外置。代码里那两行 s3c2410_gpio_pullup(DQ, 0) 是关掉芯片内部上拉，理由有两条：一是内部上拉太弱，10kΩ 到 50kΩ，而 DS18B20 的寄生电容加上长导线的线容，边沿会变得很缓，1-Wire 要求上升沿在 15us 内完成，弱上拉做不到；二是内部上拉在切输入时行为不一致，有些芯片切输入后就断开了上拉，线直接悬空。

外置 4.7kΩ 是 Dallas 手册推荐值，短线（1 米内）直接用。线长超过 10 米要降到 2.2kΩ 甚至 1kΩ，用更强的上拉把边沿拉快。

寄生供电和外部供电：

方式 接法 特点
外部供电 VDD 接 3.3V/5V，GND 接地，DQ 加 4.7k 上拉 稳定，转换期间总线可以随便拉低
寄生供电 VDD 和 GND 都接地，靠 DQ 上的上拉给内部电容充电 省一根线，但转换期间总线必须保持高电平

本篇代码里 0x44 启动转换后就靠 msleep(750) 干等，天然满足寄生供电的要求。真要在一根总线上挂多个寄生供电的器件，转换期间去读别的器件，就会把电源抽干，读数全乱。

移植到别的平台，只改三处：DQ 换成目标平台的 GPIO 编号，CFG_IN / CFG_OUT 换成目标平台的方向宏。udelay() 是通用接口，不用换。GPIO 操作那三个函数在新内核里已经改名叫 gpio_direction_output / gpio_direction_input / gpio_set_value 加 gpio_get_value，配合 gpiod_get 从设备树取引脚，这是移植到 4.x 以上必须做的改造。

十六、时序精度的坑 #

第十节那张表列的是规范，这一节讲的是为什么你的代码会违反规范。

第一坑：udelay 和 msleep 不是一个量级的东西。

函数 实现方式 精度 适用区间
udelay(n) 忙等 + 循环校准 微秒级 1us ~ 几 ms
msleep(n) 让出 CPU，按 jiffy 计时 毫秒级，实际会多睡一个 tick ≥ 10ms
usleep_range(a,b) 让出 CPU，高精度定时器 微秒级，需开高精度定时器 10us ~ 20ms

1-Wire 的时隙全在 1~960us 这个区间，只有 udelay 和 usleep_range 能用。用 msleep(1) 代替 udelay(500) 做复位，会睡过头几十倍，从机早就认为总线空闲了。udelay 的代价是忙等，CPU 全程空转——一次完整读温度有约 100 个时隙，每个平均 60us，加起来 6ms 的忙等，还要加 750ms 转换。

第二坑：中断和抢占会撑宽低电平。

udelay(60) 只保证「至少 60us」，不保证「正好 60us」。执行到一半来个中断，ISR 跑 100us，你的写 0 时隙就变成 160us，超出规范上限 120us，DS18B20 就此认错位。

text
理想：  ├── 60us ──┤
实际：  ├── 60us ──┼── ISR 100us ──┤   ← 变成 160us，违规

对策按需要选。关抢占只挡住进程调度，挡不住硬中断：

c
preempt_disable();
s3c2410_gpio_setpin(DQ, 0);
udelay(60);
s3c2410_gpio_setpin(DQ, 1);
preempt_enable();

关本地中断，硬中断也进不来，代价是这段时间系统对其他中断失明：

c
unsigned long flags;
local_irq_save(flags);
write_byte(0x44);
local_irq_restore(flags);

一个字节 8 个时隙约 500us，全程关中断 500us 在嵌入式设备上可以接受。整条命令链（复位 + 两个字节）要到 2ms 级，就得掂量了。

第三坑：CPU 降频后 udelay 变长。udelay 的循环次数是按启动时校准的 loops_per_jiffy 算的，运行时如果调了 CPU 频率（cpufreq 调频），校准值会失配，实际延时偏离标称值。轻则 10% 偏差，重则翻倍。做 1-Wire 这类严格时序时，要么把 CPU 锁在固定频率，要么改用硬件定时器数时间。

第四坑：GPIO 函数调用本身的开销不可忽略。s3c2410_gpio_setpin 不是一条指令，它要走一层函数调用，做参数检查、地址计算、读改写。在 400MHz 的 S3C2440 上一次调用几微秒是常态。第十二节里写 1 的低电平就是靠「两次相邻调用」撑出来的，这个宽度在不同主频、不同内核配置下差别很大：

c
s3c2410_gpio_setpin(DQ, 0);           /* 拉低 */
s3c2410_gpio_setpin(DQ, data & 0x01); /* 立刻决定是否释放 */

主频高、函数被内联，两次调用之间只隔几百纳秒；主频低、函数没内联，隔了 5us——都还在 1~15us 内，能过。但换成直接写寄存器，两条 writel 之间只隔几十纳秒，从机的边沿检测电路就未必认得出这是一个时隙。稳妥做法是显式补 1~2us：

c
s3c2410_gpio_setpin(DQ, 0);
udelay(1);
s3c2410_gpio_setpin(DQ, data & 0x01);

第五坑：读时隙的采样点算错。采样点 = 拉低之后到 getpin 之间的全部耗时。第十二节那个实现是 2 + 8 = 10us 的显式延时，加上调用开销约 12~13us，规范要求 15us 内，余量只有 2~3us。如果某个环节多花了 3us，采样就落到 15us 之后，从机已经放手，读回的是上拉的高电平——所有位都读成 1，一个字节恒等于 0xFF。读到 0xFF 的时候先怀疑这里，别急着换器件。

一句话概括差别：ADC 的难点在「怎么拿到数据」，DS18B20 的难点在「怎么把话说清楚」。ADC 有硬件帮你数，你只要把寄存器配好、把中断接上，数据自己就来了。DS18B20 的数据也是芯片内部算好的，但你和它之间只有一根线，没有任何握手信号，全靠双方守时。守不住时就一句话都说不成。

# 易错点 正确做法
1 ADCCON 配置漏了 1 << 0 启动位必须写，否则转换永不开始
2 ADCDAT 忘加 & 0xFFF 只有低 12 位有值，高位是垃圾
3 PRSCVL 随便填，不管时钟上限 ADCclk 必须 ≤ 5MHz，即 PCLK/(PRSCVL+1) ≤ 5M
4 ADCMUX 通道号和硬件接的脚不一致 原理图上是 XadcAIN3 就写 3
5 platform_get_resource 按下标硬猜顺序 用「类型 + 同类索引」两段式取
6 ioremap 长度写成 end - start 闭区间，写 end - start + 1
7 free_irq 传入内存地址 只释放 request_irq 拿到的那个中断号
8 init_waitqueue_head 放在注册设备之后 挪到最前面
9 中断里忘了 CLRINTADC 不清中断会立刻重入，系统假死
10 先 wake_up 再置标志 先置标志再唤醒，否则唤醒丢失
11 wait_event_interruptible 返回值不判 非 0 就 -ERESTARTSYS，别用旧数据
12 copy_to_user 失败后不清标志 清标志要早于启动转换
13 read() 返回 len 而不是实际字节数 返回 sizeof(int)
14 设备注册名和 /dev 节点名不一致 手工 mknod，或加 class_create
15 复位后不切输入就去读存在脉冲 必须先 cfgpin(CFG_IN)
16 上拉靠芯片内部 必须外置 4.7kΩ，内部上拉边沿太缓
17 字节先发高位 1-Wire 是低位先发，data & 0x01 再 >>= 1
18 写 1 时也拉低 60us 写 1 的低电平只能维持 1~15us
19 读时隙拉低后不释放就读 主机必须先撒手，从机才能送数据
20 读采样点超过 15us 拉低到采样控制在 12us 左右
21 读时隙总长不足 60us 末尾补 udelay(50)
22 用 msleep 做微秒级时隙 微秒级一律 udelay
23 用 udelay(750000) 等转换 超过 MAX_UDELAY_MS，改用 msleep(750)
24 发完 0x44 立刻读 12 位模式要等 750ms
25 温度按无符号算 16 位补码，负温要减 0x10000
26 小数只算两位 12 位精度是 0.0625，有四位小数的信息量
27 不读第 8 字节 想校验 CRC 就得读满 9 字节
28 CRC 用 0x31 配低位先行 反向多项式是 0x8C，两者不能混
29 挂多个器件还用 0xCC 多器件要用 0x55 匹配 ROM 号
30 寄生供电时在转换期间通信 转换期间总线必须保持高电平
