一、RTC 是什么：断电后继续走时的时钟 #

RTC 全称 Real Time Clock。它只干一件事：以 32.768kHz 晶振为基准数秒分时日月年，对外给出「现在几点」。

和普通定时器的区别在供电域。CPU、内存、大部分外设挂主电源域，掉电全没；RTC 单独挂 VBAT 域，断电由纽扣电池接管，所以关机、拔电、深睡它照样走。

这决定三个用途：开机给出可信初始时间；到点产生闹钟中断把系统从 suspend 叫醒；提供一条不依赖 CPU 计时的时间通道。

linux 把 RTC 抽象成 class 设备，框架替驱动处理字符设备、proc、sysfs、闹钟队列、中断分发。代码都在 drivers/rtc：class.c 管 rtc 类与 rtc_device 注册，interface.c 提供与硬件无关的读写接口，lib.c 做时间换算，dev.c 建 /dev/rtcN，hctosys.c 把硬件时钟刷进 wall time，sysfs.c/proc.c 是两个用户接口，rtc-*.c 是各家芯片驱动。rtc- 开头的基本都是具体硬件驱动，框架搞懂后剩下的差异只在寄存器。

二、RTC 与系统时间的区别 #

名称 载体 掉电后 查看 谁维护
硬件时钟 RTC 芯片寄存器 靠备份电池继续走 hwclock -r、/sys/class/rtc/rtcN/time RTC 驱动
系统时钟 内核 xtime/tk_core 消失，重启归零 date 时间子系统

两条单向通道：硬件→系统是 rtc_hctosys，开机读一次写进 wall time；系统→硬件靠人为同步，hwclock -w 走 RTC_SET_TIME 或 sysfs。

rtc_hctosys 的作用一句话：没有它，内核 wall time 从 1970 或编译时刻起步，完全不可信。

c
static int __init rtc_hctosys(void)
{
        struct rtc_device *rtc = rtc_class_open(CONFIG_RTC_HCTOSYS_DEVICE);
        struct timespec64 tv64 = { .tv_nsec = NSEC_PER_SEC >> 1 };
        struct rtc_time tm;

        if (!rtc)
                goto err_open;
        if (rtc_read_time(rtc, &tm)) {
                dev_err(rtc->dev.parent,
                        "hctosys: unable to read the hardware clock\n");
                goto err_read;
        }
        tv64.tv_sec = rtc_tm_to_time64(&tm);
        err = do_settimeofday64(&tv64);
        dev_info(rtc->dev.parent,
                 "setting system clock to %ptR UTC (%lld)\n",
                 &tm, (long long)tv64.tv_sec);
err_read:
        rtc_class_close(rtc);
err_open:
        rtc_hctosys_ret = err;
        return err;
}
late_initcall(rtc_hctosys);

要点：CONFIG_RTC_HCTOSYS_DEVICE 选源，默认 "rtc0"，名字对不上不生效，/sys/class/rtc/rtcN/hctosys 读回 0；late_initcall 保证驱动都 probe 完；tv_nsec 先填半秒，因为 RTC 只存整秒；32 位平台 tv_sec > INT_MAX 直接 -ERANGE；结果记在 rtc_hctosys_ret，sysfs 与 suspend 逻辑都读它。6.x 删了 hctosys.c，改成 class.c 的静态函数，在 __devm_rtc_register_device 里判断名字后直接调用。

bash
hwclock -r      # 读硬件时钟
hwclock -w      # 系统时间 -> 硬件时钟
hwclock -s      # 硬件时钟 -> 系统时间
date -s "2023-03-26 15:18:40"

hwclock -w 不改内核 wall time，date -s 也不写 RTC。搞混这两个是「重启后时间又回去了」的头号原因。

三、RTC 子系统的整体架构 #

注册方向从驱动发起，使用方向从应用发起。

text
 应用层  hwclock / date / 自己的 ioctl 程序
            |                |
            v                v
 /dev/rtcN (rtc_dev_fops)  /sys/class/rtc/rtcN  /proc/driver/rtc
            +----------+-----------+------------------+
                       v
        interface.c  rtc_read_time / rtc_set_time / rtc_set_alarm
        class.c      rtc_device 分配、注册、注销
                       |  rtc->ops->read_time / set_time / set_alarm
                       v
        rtc_class_ops  芯片驱动（rtc-s3c.c 等） -> 硬件寄存器

text
s3c_rtc_probe
 └─ devm_rtc_device_register(dev, "s3c", &s3c_rtcops, THIS_MODULE)
      ├─ devm_rtc_allocate_device(dev)      /* 取号 + kzalloc + init */
      ├─ rtc->ops = ops
      └─ __rtc_register_device(owner, rtc)
           ├─ rtc_device_get_offset(rtc)    /* 算 range/offset_secs */
           ├─ __rtc_read_alarm(rtc, &alrm)  /* 探硬件已有闹钟 */
           ├─ rtc_initialize_alarm(rtc, &alrm)
           ├─ rtc_dev_prepare(rtc)          /* devt + cdev_init */
           ├─ cdev_device_add(&rtc->char_dev, &rtc->dev)
           ├─ rtc_proc_add_device(rtc)
           └─ rtc->registered = true

三个设计取舍：一个 RTC 一个 rtc_device，ops_lock 互斥锁保护 ops 调用，irq_lock 自旋锁保护 irq_data；闹钟不用硬件一次性寄存器语义，内核在软件里维护一棵 timerqueue（红黑树加最早节点指针）把 aie_timer 挂进去，再把最近那个写进硬件，多个程序的闹钟因此能排队，硬件只需支持一个一次性闹钟；中断事件不投递给特定进程，只更新 irq_data 并唤醒 irq_queue，谁 read() 谁拿走。

四、rtc_device：一个 RTC 的抽象 #

struct rtc_device 定义在 include/linux/rtc.h，5.2 全文：

c
struct rtc_device {
        struct device dev;
        struct module *owner;
        int id;

        const struct rtc_class_ops *ops;
        struct mutex ops_lock;

        struct cdev char_dev;
        unsigned long flags;

        unsigned long irq_data;
        spinlock_t irq_lock;
        wait_queue_head_t irq_queue;
        struct fasync_struct *async_queue;

        int irq_freq;
        int max_user_freq;

        struct timerqueue_head timerqueue;
        struct rtc_timer aie_timer;
        struct rtc_timer uie_rtctimer;
        struct hrtimer pie_timer; /* sub second exp, so needs hrtimer */
        int pie_enabled;
        struct work_struct irqwork;
        /* Some hardware can't support UIE mode */
        int uie_unsupported;

        /* Number of nsec it takes to set the RTC clock. This influences when
         * the set ops are called. An offset:
         *   - of 0.5 s will call RTC set for wall clock time 10.0 s at 9.5 s
         *   - of 1.5 s will call RTC set for wall clock time 10.0 s at 8.5 s
         *   - of -0.5 s will call RTC set for wall clock time 10.0 s at 10.5 s
         */
        long set_offset_nsec;

        bool registered;

        /* Old ABI support */
        bool nvram_old_abi;
        struct bin_attribute *nvram;

        time64_t range_min;
        timeu64_t range_max;
        time64_t start_secs;
        time64_t offset_secs;
        bool set_start_time;

#ifdef CONFIG_RTC_INTF_DEV_UIE_EMUL
        struct work_struct uie_task;
        struct timer_list uie_timer;
        /* Those fields are protected by rtc->irq_lock */
        unsigned int oldsecs;
        unsigned int uie_irq_active:1;
        unsigned int stop_uie_polling:1;
        unsigned int uie_task_active:1;
        unsigned int uie_timer_active:1;
#endif
};

关键字段：dev/owner/id 是设备模型节点、模块持有者、编号（决定 rtc%d 与次设备号）；ops/ops_lock 是回调集（注册前必须非空，注销时置 NULL）与串行化锁；char_dev/flags 承载 /dev/rtcN，RTC_DEV_BUSY 表示已被 open；irq_data/irq_lock/irq_queue 是上报事件字、保护它的自旋锁、read 的睡眠队列；async_queue 是 SIGIO 队列；irq_freq/max_user_freq 是周期中断频率（默认 1Hz，上限 RTC_MAX_FREQ=8192）与非特权用户上限（默认 64）；timerqueue 是队列头；aie_timer/uie_rtctimer 是闹钟定时器（rtc_aie_update_irq）与每秒更新定时器（rtc_uie_update_irq）；pie_timer/pie_enabled 是周期中断的 hrtimer 模拟；irqwork 是工作项（rtc_timer_do_work）；uie_unsupported 置位时 rtc_update_irq_enable 返回 -EINVAL；set_offset_nsec 是距整秒多少纳秒时写 RTC。

后五个字段解决「年寄存器只有 2 位」这类问题：S3C2410 的年寄存器是 00~99 的 BCD，硬件表达不了世纪。rtc_device_get_offset() 算映射偏移，四分支对应「两区间不相交」「部分重叠在上」「部分重叠在下」「完全对齐」：

c
static void rtc_device_get_offset(struct rtc_device *rtc)
{
        time64_t range_secs;
        u32 start_year;

        if (rtc->range_min == rtc->range_max)      /* 驱动没实现范围 */
                return;

        if (!device_property_read_u32(rtc->dev.parent, "start-year", &start_year)) {
                rtc->start_secs = mktime64(start_year, 1, 1, 0, 0, 0);
                rtc->set_start_time = true;
        }
        if (!rtc->set_start_time)
                return;

        range_secs = rtc->range_max - rtc->range_min + 1;

        if (rtc->start_secs > rtc->range_max ||
            rtc->start_secs + range_secs - 1 < rtc->range_min)
                rtc->offset_secs = rtc->start_secs - rtc->range_min;
        else if (rtc->start_secs > rtc->range_min)
                rtc->offset_secs = range_secs;
        else if (rtc->start_secs < rtc->range_min)
                rtc->offset_secs = -range_secs;
        else
                rtc->offset_secs = 0;
}

读侧 rtc_add_offset()、写侧 rtc_subtract_offset() 都跳过重叠区，避免同一段时间被加两次。

闹钟队列的最小堆（实现是红黑树加 next 指针），next 永远指向 expires 最小的节点，所以取下一个是 O(1)：

c
struct timerqueue_node {  struct rb_node node;  ktime_t expires;  };
struct timerqueue_head {  struct rb_root head;  struct timerqueue_node *next;  };

struct rtc_timer {
        struct timerqueue_node node;
        ktime_t period;                    /* 0 表示一次性 */
        void (*func)(struct rtc_device *rtc);
        struct rtc_device *rtc;
        int enabled;
};

版本差异很扎眼：4.19 及更早的 rtc_timer 是 void (*func)(void *private_data); void *private_data;，5.x 才改成直接持 struct rtc_device *rtc。素材里 timer->func(timer->rtc) 贴到 4.19 上编译不过。

rtc_time 与 rtc_wkalrm 是内核与用户态共享结构，在 include/uapi/linux/rtc.h：

c
struct rtc_time {
        int tm_sec;  int tm_min;  int tm_hour;
        int tm_mday;
        int tm_mon;    /* 0 ~ 11 */
        int tm_year;   /* 相对 1900 的偏移 */
        int tm_wday;  int tm_yday;  int tm_isdst;
};

struct rtc_wkalrm {
        unsigned char enabled;  /* 0 = alarm disabled, 1 = alarm enabled */
        unsigned char pending;  /* 0 = alarm not pending, 1 = alarm pending */
        struct rtc_time time;
};

两个坑先钉死：tm_mon 是 0 起始，1 月填 0；tm_year 相对 1900，2023 年填 123。BCD 转换前后要自己做 ±1 和 +100 换算。rtc_wkalrm.enabled 是闹钟总开关，为 0 时硬件全局使能位不开，到点也不产生 INT_RTC。

五、rtc_class_ops：驱动要实现的回调 #

框架和芯片之间唯一的契约：

c
struct rtc_class_ops {
        int (*ioctl)(struct device *, unsigned int, unsigned long);
        int (*read_time)(struct device *, struct rtc_time *);
        int (*set_time)(struct device *, struct rtc_time *);
        int (*read_alarm)(struct device *, struct rtc_wkalrm *);
        int (*set_alarm)(struct device *, struct rtc_wkalrm *);
        int (*proc)(struct device *, struct seq_file *);
        int (*alarm_irq_enable)(struct device *, unsigned int enabled);
        int (*read_offset)(struct device *, long *offset);
        int (*set_offset)(struct device *, long offset);
};
回调 作用 必要性 版本备注
read_time / set_time 读/写当前时间 必须实现（只读 RTC 可空） 3.x 起未变
read_alarm 读硬件里已有闹钟与使能位 建议实现 字段一直在；6.2 起有 RTC_FEATURE_ALARM，未实现该回调时 rtc_read_alarm() 仍可用（读 aie_timer）
set_alarm 写闹钟时间与使能 要支持闹钟就得实现 同上
alarm_irq_enable 单独开关闹钟中断 要支持 RTC_AIE_* 就得实现 3.10 已存在
proc 在 /proc/driver/rtc 末尾追加私有字段 可选 3.10 已有，6.x 仍在
ioctl 私有命令兜底 可选 一直是第一个成员；仅 rtc_dev_ioctl 的 default 分支调用
read_offset / set_offset 读写时钟校正，单位 ppb 可选 4.9 起才进结构体，3.10、4.4 没有
open / release / set_mmss / set_mmss64 / read_callback 字符设备钩子、只写时分秒、老式读回调 可选 3.10~5.0 有，5.2 全删
param_get / param_set RTC_PARAM_GET/SET 厂商通道 可选 6.x 加入（6.6 已见），精确版本未验证

「read_alarm 在 4.19 前后被移除」这个说法不成立。逐版核对 include/linux/rtc.h：4.19、4.20、5.0、5.4、5.10、6.6、6.12、6.15 里它一都在。真实变化是判定依据从「回调是否为空」变成「RTC_FEATURE_ALARM 是否置位」，函数指针没删，见 2023 年提交 a783c96。写成「移除」会让人改错代码。ioctl 的位置也常被误解：它一直排第一，调用点只有一处——所有标准命令都不命中才轮到：

c
        default:
                /* Finally try the driver's ioctl interface */
                if (ops->ioctl) {
                        err = ops->ioctl(rtc->dev.parent, cmd, arg);
                        if (err == -ENOIOCTLCMD)
                                err = -ENOTTY;
                } else {
                        err = -ENOTTY;
                }

驱动一旦私自实现 RTC_SET_TIME 这类标准命令，框架那段逻辑根本不走：CAP_SYS_TIME 检查、offset 换算、闹钟入队全绕过。驱动只该处理自己定义的私有命令码。

六、RTC 的注册与注销 #

接口 年代 devm 现状
rtc_device_register(name, dev, ops, owner) 早期 否 4.x 起淘汰，6.x 已移除
devm_rtc_device_register(dev, name, ops, owner) 4.x 是 5.x 注释已标 deprecated
devm_rtc_allocate_device + rtc_register_device 5.x 是 当前推荐

rtc_register_device 是宏，4.14 起才有：#define rtc_register_device(device) __rtc_register_device(THIS_MODULE, device)。主体：

c
int __rtc_register_device(struct module *owner, struct rtc_device *rtc)
{
        struct rtc_wkalrm alrm;
        int err;

        if (!rtc->ops)
                return -EINVAL;

        rtc->owner = owner;
        rtc_device_get_offset(rtc);

        /* Check to see if there is an ALARM already set in hw */
        err = __rtc_read_alarm(rtc, &alrm);
        if (!err && !rtc_valid_tm(&alrm.time))
                rtc_initialize_alarm(rtc, &alrm);

        rtc_dev_prepare(rtc);

        err = cdev_device_add(&rtc->char_dev, &rtc->dev);
        if (err)
                dev_warn(rtc->dev.parent, "failed to add char device %d:%d\n",
                         MAJOR(rtc->dev.devt), rtc->id);

        rtc_proc_add_device(rtc);

        rtc->registered = true;
        dev_info(rtc->dev.parent, "registered as %s\n", dev_name(&rtc->dev));
        return 0;
}

__rtc_read_alarm 解决一个老问题：很多芯片闹钟只匹配「时:分:秒」，日/月/年读回 -1 或非法值，直接算时间会得出荒谬结果。内核用两次时间戳夹住中间那次闹钟读取，前后不一致说明读闹钟期间分针翻了，重来；一致就用当前时间补齐缺失字段，再按 missing 做 day/month/year 三种 rollover 推到未来（跨天加 86400 秒，跨月按 rtc_month_days 逐月推进，跨年循环到闰年或日期合法为止）：

c
        err = rtc_read_time(rtc, &before);              /* 前置时间戳 */
        do {
                if (!first_time)
                        memcpy(&before, &now, sizeof(struct rtc_time));
                first_time = 0;

                err = rtc_read_alarm_internal(rtc, alarm);
                if (err)
                        return err;

                if (rtc_valid_tm(&alarm->time) == 0) {  /* 完整芯片直接返回 */
                        rtc_add_offset(rtc, &alarm->time);
                        return 0;
                }

                err = rtc_read_time(rtc, &now);         /* 后置时间戳 */
        } while (before.tm_min  != now.tm_min ||
                 before.tm_hour != now.tm_hour ||
                 before.tm_mon  != now.tm_mon ||
                 before.tm_year != now.tm_year);

rtc_dev_prepare 设设备号、初始化 cdev、挂上 fops：

c
void rtc_dev_prepare(struct rtc_device *rtc)
{
        if (!rtc_devt)
                return;
        if (rtc->id >= RTC_DEV_MAX) {          /* 上限 16 个 RTC */
                dev_dbg(&rtc->dev, "too many RTC devices\n");
                return;
        }

        rtc->dev.devt = MKDEV(MAJOR(rtc_devt), rtc->id);

#ifdef CONFIG_RTC_INTF_DEV_UIE_EMUL
        INIT_WORK(&rtc->uie_task, rtc_uie_task);
        timer_setup(&rtc->uie_timer, rtc_uie_timer, 0);
#endif

        cdev_init(&rtc->char_dev, &rtc_dev_fops);
        rtc->char_dev.owner = rtc->owner;
}

主设备号由 rtc_dev_init 里 alloc_chrdev_region(&rtc_devt, 0, RTC_DEV_MAX, "rtc") 动态分配，所以不同机器 /dev/rtc0 的 major 可以不同，素材里的 253, 0 是那次启动的值，不是常量。cdev_device_add 同时做 cdev_add 和 device_add，后者成功会发 uevent，udev/mdev 收到自动建节点。

rtc_proc_add_device 只为「被指定为 hctosys 的那个 RTC」创建 proc 文件，判定函数有两个分支：

c
#if defined(CONFIG_RTC_HCTOSYS_DEVICE)
static bool is_rtc_hctosys(struct rtc_device *rtc)
{
        char name[NAME_SIZE];

        scnprintf(name, NAME_SIZE, "rtc%d", rtc->id);
        return !strncmp(name, CONFIG_RTC_HCTOSYS_DEVICE, NAME_SIZE);
}
#else
static bool is_rtc_hctosys(struct rtc_device *rtc)
{
        return (rtc->id == 0);

#endif

素材只摘了 #else 分支，不能当通用逻辑用。

分配侧 devm_rtc_allocate_device 依次做：rtc_device_get_id(dev) 取号（优先用设备树 aliases 里的 rtc 别名，没有才从 rtc_ida 顺序取）、devres_alloc 挂回收回调、rtc_allocate_device() 分配并初始化、回填 id、dev.parent、dev_set_name(&rtc->dev, "rtc%d", id)。aliases 里写 rtc0 = &rtc; 能把编号钉住，多 RTC 系统靠它保证 /dev/rtc0 永远是同一颗芯片，CONFIG_RTC_HCTOSYS_DEVICE="rtc0" 才有意义。

rtc_allocate_device 里的默认值值得记住：set_offset_nsec = NSEC_PER_SEC / 2、irq_freq = 1、max_user_freq = 64、dev.class = rtc_class、dev.groups = rtc_get_dev_attribute_groups()、dev.release = rtc_device_release；外加 mutex_init(&rtc->ops_lock)、spin_lock_init(&rtc->irq_lock)、init_waitqueue_head(&rtc->irq_queue)、timerqueue_init_head(&rtc->timerqueue)、INIT_WORK(&rtc->irqwork, rtc_timer_do_work)、rtc_timer_init(&rtc->aie_timer, rtc_aie_update_irq, rtc)、rtc_timer_init(&rtc->uie_rtctimer, rtc_uie_update_irq, rtc)、hrtimer_init(&rtc->pie_timer, CLOCK_MONOTONIC, HRTIMER_MODE_REL)。

rtc_class 在模块入口创建，subsys_initcall(rtc_init) 保证在多数驱动 probe 之前跑完：

c
static int __init rtc_init(void)
{

注销方向，5.2 的 rtc_device_unregister 是 static，由 devm 框架回调：先 rtc_proc_del_device，再 cdev_device_del 摘 cdev 与 device，最后把 ops 置 NULL，才 put_device。置 NULL 之后任何还在跑的 rtc_read_time 拿到 -ENODEV，不会踩到已释放的驱动私有数据，这也是 interface.c 里到处判空的原因。6.6 重写了这段：rtc_device_unregister 消失，换成 devm_rtc_unregister_device 加 devm_rtc_release_device 两个 devm action，rtc_device_release 里会清空 timerqueue、cancel_work_sync、mutex_destroy；5.2 的 release 只有 ida_simple_remove 加 kfree。

七、读时间与设时间 #

rtc_read_time 调用链三层：

text
rtc_dev_ioctl(RTC_RD_TIME) / sysfs date_show / proc rtc_proc_show
 └─ rtc_read_time(rtc, &tm)                  /* 拿 ops_lock */
      └─ __rtc_read_time(rtc, &tm)
           ├─ rtc->ops->read_time(rtc->dev.parent, tm)   /* 驱动 */
           ├─ rtc_add_offset(rtc, tm)                    /* 区间映射 */
           └─ rtc_valid_tm(tm)                           /* 合法性校验 */

c
static int __rtc_read_time(struct rtc_device *rtc, struct rtc_time *tm)
{
        int err;

        if (!rtc->ops)
                return -ENODEV;
        if (!rtc->ops->read_time)
                return -EINVAL;

        memset(tm, 0, sizeof(struct rtc_time));
        if ((err = rtc->ops->read_time(rtc->dev.parent, tm)) < 0)
                return err;
        rtc_add_offset(rtc, tm);                 /* 加上区间映射偏移 */
        err = rtc_valid_tm(tm);
        if (err < 0)
                dev_dbg(&rtc->dev, "read_time: rtc_time isn't valid\n");
        return err;
}

外层 rtc_read_time 只是加锁、调 __rtc_read_time、解锁、打 trace 点。ops_lock 是普通 mutex，所有 rtc_*(struct rtc_device *) 接口都会拿它，驱动回调本身不再加锁。

rtc_valid_tm（lib.c）判定：tm_year 在 70 到 INT_MAX-1900、tm_mon 0~11、tm_mday 1 到当月天数、时分秒不越界。刚出厂的芯片读回全 0，tm_year=0 < 70 直接判非法，这就是开机日志里 invalid RTC value 的来源。

S3C2440 的实现，两个重点：BCD 转换，以及「读到秒为 0 就重读」：

c
static int s3c_rtc_gettime(struct device *dev, struct rtc_time *rtc_tm)
{
        struct s3c_rtc *info = dev_get_drvdata(dev);
        unsigned int have_retried = 0;

        if (s3c_rtc_enable_clk(info))
                return -EIO;

retry_get_time:
        rtc_tm->tm_min  = readb(info->base + S3C2410_RTCMIN);
        rtc_tm->tm_hour = readb(info->base + S3C2410_RTCHOUR);
        rtc_tm->tm_mday = readb(info->base + S3C2410_RTCDATE);
        rtc_tm->tm_mon  = readb(info->base + S3C2410_RTCMON);
        rtc_tm->tm_year = readb(info->base + S3C2410_RTCYEAR);
        rtc_tm->tm_sec  = readb(info->base + S3C2410_RTCSEC);

        /* 秒为 0 说明正卡在进位点，寄存器组非原子更新，重读一次 */
        if (rtc_tm->tm_sec == 0 && !have_retried) {
                have_retried = 1;
                goto retry_get_time;
        }
        /* 6 个寄存器依次 bcd2bin，然后 */
        rtc_tm->tm_year += 100;   /* 0~99 映射到 2000~2099 */
        rtc_tm->tm_mon  -= 1;     /* 1~12 映射到 0~11 */
        s3c_rtc_disable_clk(info);
        return 0;
}

秒归零那一刻分、时、日正进位，读出来是「新分钟 + 旧秒」的撕裂组合。严格做法读两遍比对，这里只判秒为 0，够用。tm_year += 100 和 tm_mon -= 1 必须在 read_time 与 set_time 里成对出现、方向相反，少一个就整体偏一个月或一个世纪。

写时间：rtc_set_time 依次做 rtc_valid_tm → rtc_valid_range（超范围返回 -ERANGE）→ rtc_subtract_offset → 拿 ops_lock 调 rtc->ops->set_time → pm_stay_awake → 解锁 → schedule_work(&rtc->irqwork) → 打 trace 点。

c
        if ((err = rtc_valid_tm(tm)) != 0)
                return err;
        if ((err = rtc_valid_range(rtc, tm)))
                return err;
        rtc_subtract_offset(rtc, tm);

        if ((err = mutex_lock_interruptible(&rtc->ops_lock)))
                return err;
        if (!rtc->ops)
                err = -ENODEV;
        else if (rtc->ops->set_time)
                err = rtc->ops->set_time(rtc->dev.parent, tm);
        else
                err = -EINVAL;
        pm_stay_awake(rtc->dev.parent);
        mutex_unlock(&rtc->ops_lock);
        schedule_work(&rtc->irqwork);   /* A timer might have just expired */

末尾那个 schedule_work 容易被忽略：改完 RTC 时间，原先排在未来的闹钟已经变成「过期」，必须立刻跑一遍 rtc_timer_do_work 清掉过期项、把下一个重写进硬件。4.19 的 rtc_set_time 还有 set_mmss64/set_mmss 两条回退路径，5.2 已删；6.3 又加了「写前关 UIE、写后打开」的一段，5.2 都没有。

驱动侧 s3c_rtc_settime 先算出 year = tm->tm_year - 100，year < 0 || year >= 100 直接 -EINVAL（年份硬限 2000~2099），然后 s3c_rtc_enable_clk，六个 writeb(bin2bcd(...)) 写进 RTCSEC/RTCMIN/RTCHOUR/RTCDATE/RTCMON/RTCYEAR（注意月和年分别要 +1 和 -100），最后 s3c_rtc_disable_clk。要扩时间范围得用 range_min/range_max/start-year 做映射，不是改这里。另外 s3c_rtc_enable_clk 只管时钟门控，data->enable 才管 RTCCON.RTCEN，两者不是一回事。

八、闹钟与唤醒 #

闹钟最容易写错，因为「软件队列」和「硬件寄存器」是两套状态，必须保持同步。

类型 触发条件 ioctl 内核表示 硬件依赖
一次性闹钟 AIE 到达指定年月日时分秒 RTC_ALM_SET+RTC_AIE_ON，或 RTC_WKALM_SET rtc->aie_timer，period=0 需要芯片闹钟寄存器
周期中断 PIE 每 1/freq 秒一次 RTC_PIE_ON/OFF + RTC_IRQP_SET rtc->pie_timer（hrtimer） 不需要硬件支持
更新中断 UIE 每秒一次 RTC_UIE_ON/OFF rtc->uie_rtctimer，period=1s RTC_FEATURE_UPDATE_INTERRUPT 或 UIE 模拟选项

rtc_set_alarm 的行为分两种：enabled == 0（RTC_ALM_SET 走这条）只更新 aie_timer.node.expires，不入队，硬件一个字节都不碰；enabled == 1（RTC_WKALM_SET）先摘旧定时器再入队，入队过程把「最早那个」写进硬件。

c
        if (!rtc->ops)
                return -ENODEV;
        if (!rtc->ops->set_alarm)
                return -EINVAL;
        if ((err = rtc_valid_tm(&alarm->time)) != 0)
                return err;
        if ((err = rtc_valid_range(rtc, &alarm->time)))
                return err;

        if ((err = mutex_lock_interruptible(&rtc->ops_lock)))
                return err;
        if (rtc->aie_timer.enabled)
                rtc_timer_remove(rtc, &rtc->aie_timer);

        rtc->aie_timer.node.expires = rtc_tm_to_ktime(alarm->time);
        rtc->aie_timer.period = 0;
        if (alarm->enabled)
                err = rtc_timer_enqueue(rtc, &rtc->aie_timer);
        mutex_unlock(&rtc->ops_lock);

rtc_timer_enqueue 是软件队列与硬件寄存器的同步点：先标记 enabled = 1、读当前时间、跳过队列里已过期的节点，然后 timerqueue_add 插入，只有当新定时器比原队首更早（或队列本来是空的）时才调 __rtc_set_alarm 写硬件；写入失败就把它从队列摘掉并复位 enabled。

c
        timer->enabled = 1;
        __rtc_read_time(rtc, &tm);
        now = rtc_tm_to_ktime(tm);

        while (next && next->expires < now)          /* 跳过已过期的 */
                next = timerqueue_iterate_next(next);

        timerqueue_add(&rtc->timerqueue, &timer->node);
        if (!next || ktime_before(timer->node.expires, next->expires)) {
                alarm.time = rtc_ktime_to_tm(timer->node.expires);
                alarm.enabled = 1;
                err = __rtc_set_alarm(rtc, &alarm);
                if (err == -ETIME) {
                        pm_stay_awake(rtc->dev.parent);
                        schedule_work(&rtc->irqwork);
                } else if (err) {
                        timerqueue_del(&rtc->timerqueue, &timer->node);
                        timer->enabled = 0;
                        return err;
                }
        }

__rtc_set_alarm 是唯一落到 ops->set_alarm 的地方，它先校验时间、再读一次当前时间把「过去的闹钟」拒掉（返回 -ETIME），然后 rtc_subtract_offset 并在 ops->set_alarm 缺失时返回 -EINVAL。-ETIME 不是错误：rtc_timer_enqueue 收到它去 schedule_work 重扫队列，rtc_timer_do_work 收到它 goto again。

S3C 的写闹钟：先把 RTCALM 清零关掉所有匹配位，再按字段逐位使能并写数据寄存器（时/分/秒/月/日各一个 if 加 bin2bcd 写入 ALMxxx），最后整字写回，再单独调 s3c_rtc_setaie 处理全局使能。

c
        alrm_en = readb(info->base + S3C2410_RTCALM) & S3C2410_RTCALM_ALMEN;
        writeb(0x00, info->base + S3C2410_RTCALM);   /* 先全关 */

        if (tm->tm_sec < 60 && tm->tm_sec >= 0) {
                alrm_en |= S3C2410_RTCALM_SECEN;
                writeb(bin2bcd(tm->tm_sec), info->base + S3C2410_ALMSEC);
        }
        /* tm_min / tm_hour / tm_mon(+1) / tm_mday 同构，分别置
         * MINEN/HOUREN/MONEN/DAYEN 并写 ALMMIN/ALMHOUR/ALMMON/ALMDATE */

        writeb(alrm_en, info->base + S3C2410_RTCALM);
        s3c_rtc_setaie(dev, alrm->enabled);

这颗芯片没有闹钟年寄存器：S3C2410_ALMYEAR 存在但 setalarm 从不写它，getalarm 也只在 YEAREN 置位时才做 BCD 转换，年字段缺省由 __rtc_read_alarm 的 rollover 兜住。

rtc_alarm_irq_enable（对应 RTC_AIE_ON/OFF）一次调用做两件事：软件队列入队/出队，加硬件中断使能位翻转。

c

                return err;

        if (rtc->aie_timer.enabled != enabled) {
                if (enabled)
                        err = rtc_timer_enqueue(rtc, &rtc->aie_timer);
                else
                        err = rtc_timer_remove(rtc, &rtc->aie_timer);
        }
        if (err)
                /* nothing */;
        else if (!rtc->ops)
                err = -ENODEV;
        else if (!rtc->ops->alarm_irq_enable)
                err = -EINVAL;
        else

        mutex_unlock(&rtc->ops_lock);

素材原注释只说「开启闹钟中断、同时置 aie_timer.enabled=1」，漏了入队时「把闹钟时间写进硬件」那步。rtc_timer_remove 摘掉的正好是队首时，必须把下一个补进硬件，一个不剩就 rtc_alarm_disable——它直接调 ops->alarm_irq_enable(rtc->dev.parent, false)，绕过 rtc_alarm_irq_enable，因为此刻已在 ops_lock 里，再进会死锁。

唤醒还差一环：设备必须被声明成唤醒源。s3c_rtc_probe 里的 device_init_wakeup(&pdev->dev, 1) 做两件事——device_set_wakeup_capable(dev, true) 加 device_wakeup_enable(dev)。没这一句，/sys/class/rtc/rtcN/wakealarm 不会出现（可见性检查里 rtc_does_wakealarm 要看 device_can_wakeup），suspend 里 device_may_wakeup(dev) 也永远为假，enable_irq_wake 不会被调，休眠期间闹钟中断唤不醒系统。

bash
# 老接口 RTC_ALM_SET 只写时分秒（内核补日月年，enabled 强制 0），
# 还需要一次 RTC_AIE_ON 才真正使能
# 新接口 RTC_WKALM_SET 一次搞定，enabled 随结构体传
# sysfs：写的是「距离 1970 的秒数」
echo 0     > /sys/class/rtc/rtc0/wakealarm     # 先清旧闹钟
echo +60   > /sys/class/rtc/rtc0/wakealarm     # 60 秒后（相对当前）
echo +3600 > /sys/class/rtc/rtc0/wakealarm     # 1 小时后

sysfs 的 wakealarm 支持三种前缀：纯数字是绝对秒数，+N 相对当前 N 秒，+=N 在已有闹钟上再推 N 秒。写 0 或过去的时刻表示关闭。它只在 alm.enabled 为真时读得到值，否则返回空，经常被误判成「属性坏了」。

九、中断处理 #

S3C2440 有两个中断源：IRQ_RTC（闹钟）和 IRQ_TICK（节拍），处理函数都很薄，只转给 data->irq_handler：

c
static irqreturn_t s3c_rtc_alarmirq(int irq, void *id)
{
        struct s3c_rtc *info = (struct s3c_rtc *)id;

        if (info->data->irq_handler)
                info->data->irq_handler(info, S3C2410_INTP_ALM);
        return IRQ_HANDLED;
}
/* s3c_rtc_tickirq 同构，只是传 S3C2410_INTP_TIC */

2410 的 irq_handler 两个中断共用一份，mask 参数不用；6410 版本多一步写 INTP 清挂起位，mask 就是用来区分清哪一位：

c
static void s3c24xx_rtc_irq(struct s3c_rtc *info, int mask)
{
        rtc_update_irq(info->rtc, 1, RTC_AF | RTC_IRQF);
}

static void s3c6410_rtc_irq(struct s3c_rtc *info, int mask)
{
        rtc_update_irq(info->rtc, 1, RTC_AF | RTC_IRQF);
        writeb(mask, info->base + S3C2410_INTP);   /* 清挂起位 */
}

rtc_update_irq 不做事件分发，只 pm_stay_awake 阻止系统进休眠、schedule_work(&rtc->irqwork) 把真活儿推出去。中断上下文不能拿 mutex，而 rtc_timer_do_work 要拿 ops_lock，必须推：

c
void rtc_update_irq(struct rtc_device *rtc,
                    unsigned long num, unsigned long events)
{
        if (IS_ERR_OR_NULL(rtc))
                return;

        pm_stay_awake(rtc->dev.parent);
        schedule_work(&rtc->irqwork);
}

text
硬件闹钟中断
 └─ s3c_rtc_alarmirq -> s3c24xx_rtc_irq -> rtc_update_irq(rtc, 1, RTC_AF|RTC_IRQF)
      ├─ pm_stay_awake()
      └─ schedule_work(&rtc->irqwork)
           └─ rtc_timer_do_work()
                ├─ __rtc_read_time() 取当前时间
                ├─ 摘出所有 expires <= now 的定时器
                ├─ timer->func(timer->rtc) 即 rtc_aie_update_irq
                │    └─ rtc_handle_legacy_irq(rtc, 1, RTC_AF)
                │         ├─ rtc->irq_data = (irq_data + (1<<8)) | (RTC_IRQF|RTC_AF)
                │         ├─ wake_up_interruptible(&rtc->irq_queue)
                │         └─ kill_fasync(&rtc->async_queue, SIGIO, POLL_IN)
                └─ 下一个闹钟写回硬件，没有就 rtc_alarm_disable()

rtc_timer_do_work 的骨架：拿 ops_lock（again: 标签便于重来）→ 读当前时间 → while 循环从 timerqueue_getnext 取节点，expires > now 就 break，否则 container_of 回 rtc_timer、摘出队列、清 enabled、调 timer->func(timer->rtc)；period 非零的（UIE，周期 1 秒）重新加回去并顺延一个周期，aie_timer 的 period 是 0，一次性不重排。循环结束后若还有 next，就把它写回硬件，-ETIME 时 goto again，其它错误重试三次（retry = 3，给慢速总线留余量，I2C 写闹钟时总线仲裁失败很常见），仍失败就丢掉这条定时器并 dev_err；队列空了就 rtc_alarm_disable。最后 pm_relax 加 mutex_unlock。

c
again:
        __rtc_read_time(rtc, &tm);
        now = rtc_tm_to_ktime(tm);
        while ((next = timerqueue_getnext(&rtc->timerqueue))) {
                if (next->expires > now)
                        break;
                timer = container_of(next, struct rtc_timer, node);
                timerqueue_del(&rtc->timerqueue, &timer->node);
                timer->enabled = 0;
                if (timer->func)
                        timer->func(timer->rtc);
                if (ktime_to_ns(timer->period)) {        /* 周期定时器顺延 */
                        timer->node.expires = ktime_add(timer->node.expires,
                                                        timer->period);
                        timer->enabled = 1;
                        timerqueue_add(&rtc->timerqueue, &timer->node);
                }
        }

事件最终由 rtc_handle_legacy_irq 送到用户态：spin_lock_irqsave(&rtc->irq_lock) 下把 rtc->irq_data 更新成 (irq_data + (num << 8)) | (RTC_IRQF | mode)，解锁后 wake_up_interruptible(&rtc->irq_queue) 加 kill_fasync(&rtc->async_queue, SIGIO, POLL_IN)。三个超时钩子分别传 RTC_AF（rtc_aie_update_irq）、RTC_UF（rtc_uie_update_irq）、RTC_PF（rtc_pie_update_irq，用 hrtimer_forward_now 算出 count 后返回 HRTIMER_RESTART）。

irq_data 编码：低 8 位是事件掩码，RTC_IRQF(0x80) 必置，加 RTC_PF(0x40)/RTC_AF(0x20)/RTC_UF(0x10)；高位是这次上报错过了多少次中断。

芯片 需显式清中断 备注
S3C2410/2440 否 寄存器读即清，INTP 只读
S3C6410/Exynos3250 是 写 S3C2410_INTP 对应位
HYM8563 是 I2C 读 CTL2，清 AF 位后写回

HYM8563 是 I2C 器件，中断线程化，只清标志不调 rtc_update_irq（它注册时用 devm_request_threaded_irq，中断源在设备树里配成 IRQF_TRIGGER_LOW，进程上下文的唤醒逻辑不需要再走一遍）。处理函数用 rtc_lock/rtc_unlock（include/linux/rtc.h 的宏，实质是 mutex_lock(&rtc->ops_lock)，5.8 起才有）包住一次 i2c_smbus_read_byte_data(client, HYM8563_CTL2)，data &= ~HYM8563_CTL2_AF 清标志后写回。

可见性由 rtc_attr_is_visible 逐项判定：wakealarm 看 rtc_does_wakealarm(rtc)，offset 看 rtc->ops->set_offset，range 看 range_max - range_min 是否为 0，不满足就返回 mode 0。「sysfs 里没有 wakealarm」几乎总是三种原因之一：驱动没实现 set_alarm、没调 device_init_wakeup、device_can_wakeup 为假。

read 阻塞等中断事件：缓冲区长度必须恰好 unsigned int 或至少 unsigned long，其它长度 -EINVAL；进入 DECLARE_WAITQUEUE 加 add_wait_queue(&rtc->irq_queue, &wait)，循环里设 TASK_INTERRUPTIBLE、在 irq_lock 下取走并清零 irq_data、data != 0 就跳出、O_NONBLOCK 返回 -EAGAIN、有信号返回 -ERESTARTSYS，否则 schedule()；拿到数据后按 32/64 位分别 put_user。

release 会关掉用户态开的周期中断和更新中断，但刻意留下闹钟——它是一次性的、要用来唤醒系统，进程退出不该取消：先 rtc_dev_ioctl(file, RTC_UIE_OFF, 0)，再 rtc_update_irq_enable(rtc, 0) 和 rtc_irq_set_state(rtc, 0)，最后 clear_bit_unlock(RTC_DEV_BUSY, &rtc->flags)。

rtc_dev_ioctl 主结构是「先统一查权限，再按命令分发」，每处 mutex_unlock 加 return 成对出现，原因是 rtc_read_time/rtc_set_alarm 自己会拿 ops_lock，而它是普通 mutex 不可重入，先解锁再调用是必须的，漏一处就死锁。

c
        switch (cmd) {                    /* 权限检查，统一在这里做，避免各驱动重复 */
        case RTC_EPOCH_SET:
        case RTC_SET_TIME:
                if (!capable(CAP_SYS_TIME))
                        err = -EACCES;
                break;
        case RTC_IRQP_SET:
                if (arg > rtc->max_user_freq && !capable(CAP_SYS_RESOURCE))
                        err = -EACCES;
                break;
        case RTC_PIE_ON:
                if (rtc->irq_freq > rtc->max_user_freq &&
                    !capable(CAP_SYS_RESOURCE))
                        err = -EACCES;
                break;
        }
        if (err)
                goto done;

        switch (cmd) {                    /* 分发，标准命令全在框架里处理 */
        case RTC_RD_TIME:
                mutex_unlock(&rtc->ops_lock);
                if ((err = rtc_read_time(rtc, &tm)) < 0)
                        return err;
                if (copy_to_user(uarg, &tm, sizeof(tm)))
                        err = -EFAULT;
                return err;
        case RTC_SET_TIME:
                mutex_unlock(&rtc->ops_lock);
                if (copy_from_user(&tm, uarg, sizeof(tm)))
                        return -EFAULT;
                return rtc_set_time(rtc, &tm);
        case RTC_AIE_ON:
                mutex_unlock(&rtc->ops_lock);
                return rtc_alarm_irq_enable(rtc, 1);
        case RTC_WKALM_SET:
                mutex_unlock(&rtc->ops_lock);
                if (copy_from_user(&alarm, uarg, sizeof(alarm)))
                        return -EFAULT;
                return rtc_set_alarm(rtc, &alarm);
        case RTC_PIE_ON:   err = rtc_irq_set_state(rtc, 1); break;
        case RTC_IRQP_SET: err = rtc_irq_set_freq(rtc, arg); break;
        case RTC_IRQP_READ:
                err = put_user(rtc->irq_freq, (unsigned long __user *)uarg);
                break;
        default:
                if (ops->ioctl) {
                        err = ops->ioctl(rtc->dev.parent, cmd, arg);
                        if (err == -ENOIOCTLCMD)
                                err = -ENOTTY;
                } else {
                        err = -ENOTTY;
                }
                break;
        }
done:
        mutex_unlock(&rtc->ops_lock);
        return err;

RTC_ALM_SET 里那段补月日年的逻辑解释了老接口为什么不推荐：只给时分秒，内核读当前时间把日/月/年补成今天，rtc_valid_tm 校验后如果算出的时刻早于现在，就整体推一天（now + 24*60*60 再 rtc_time64_to_tm 取日/月/年）。语义就是「未来 24 小时内的某个时刻」，超出范围做不到。

RTC_IRQP_READ 的 put_user 类型是 unsigned long，32 位用户态需要 compat_ioctl：5.2 的 fops 里没有 .compat_ioctl，6.6 才有，补了 RTC_IRQP_SET32/RTC_IRQP_READ32/RTC_EPOCH_SET32 三个兼容码，前两个直接把整数 arg 转回标准命令，最后统一 return rtc_dev_ioctl(file, cmd, (unsigned long)uarg);。

int main(void)
{

十二、备用电池与掉电保护 #

RTC 掉电保持靠三样东西：VBAT 引脚上的纽扣电池、芯片内的低功耗振荡器、一套「掉电检测 + 标记」寄存器机制。

典型电路：主电源 3.3V 经二极管接 VDD，纽扣电池（CR2032，3V）经另一个二极管接 VBAT。主电源在时电池支路反偏不放电；主电源掉，电池接管，电流在 1μA 量级。

现象 芯片怎么处理 软件怎么应对
供电跌到阈值以下 置 VL（Voltage Low）标志，拒绝继续走时 下次启动读 VL，判时间不可信
电池没装或不足 同上，或时钟停在复位值 同上，RTC_VL_READ 返回非 0
主电源恢复有毛刺 部分芯片误清分频器 加 RC 或复位电路，软件无法补偿
掉电时正在写寄存器 会写入半个 BCD 值 用 set_offset_nsec 让写入落在安全窗口

VL 的处理在 HYM8563 里很典型：HYM8563_SEC_VL 是秒寄存器 bit7，读到它就 dev_warn("no valid clock/calendar values available") 并返回 -EINVAL。这样上层知道「这块表已经不准」，而不是把垃圾值当真时间交给 rtc_hctosys。驱动若默默返回复位值，开机时间会变成 2000-01-01，比报错更难查。

清 VL 走 RTC_VL_READ 读、RTC_VL_CLR 清，通用层没实现，落到 default 分支由驱动处理，所以多数 SoC 片内 RTC 上 ioctl(fd, RTC_VL_READ, &v) 返回 -ENOTTY，不是 bug。

rtc_probe 里的兜底是另一条路线：读不到合法时间就写 2000-01-01 默认值。隐患在于 s3c_rtc_gettime 只要 BCD 转换不溢出就返回 0，寄存器全 0 转换后是 2000-01-01，rtc_valid_tm 也判合法（tm_year=100 > 70），不走兜底；真正触发兜底的是寄存器值非 BCD（如全 0xFF）转换后越界的情况。

还有一条容易忽略：写时间时的秒边界。RTC 只认整秒，用户态给的时间带毫秒，写进去是截断值，读回来就对不上，最大差 1 秒。set_offset_nsec 专门服务这个，5.2 默认 NSEC_PER_SEC / 2，意思是「距目标整秒还有 0.5 秒时去写」，让总线传输耗时和芯片吞秒时间大致抵消。I2C 这类慢总线该调大，直接寄存器访问的可调小。6.x 把默认值改成 NSEC_PER_SEC + 5 * NSEC_PER_MSEC，注释说「假设传输 5ms，对多数芯片更接近现实」。

十三、RTC 的时钟源与精度 #

时基来自 32.768kHz 音叉晶振。选这个频率因为 32768 = 2^15，15 级二分频就能得到精确 1Hz，不需要额外分频系数。

误差源 典型量级 说明
晶振频偏 ±20ppm 每月约 ±52 秒，出厂精度
温度漂移 抛物线特性 25℃ 附近最好，-20℃ 与 70℃ 差最多
负载电容失配 ±10~30ppm PCB 寄生电容偏离手册值
老化 ±3ppm/年 随时间累积

20ppm 换算：20/1e6 × 86400 × 30 ≈ 52 秒/月。这就是为什么便宜设备一个月能差半分钟以上，也是为什么需要 read_offset/set_offset。校正单位是 ppb，内核注释给的公式是 t = t0 * (1 + offset * 1e-9)，t0 是 offset = 0 时实测的一秒长度。具体一个 LSB 对应多少 ppm 由芯片决定，驱动只负责把 ppb 换成寄存器值，编码各芯片完全不同（ppm = offset / 1000，再按手册的正负号编码写入）。

手段 位置 精度提升
换更高精度晶振 硬件 ±20ppm → ±5ppm
加温度补偿晶振 TCXO 硬件 到 ±2ppm
用 set_offset 做固定校正 驱动 消掉系统性偏快/偏慢
chrony/adjtimex 定期校时 用户态 让系统时间不受 RTC 精度限制
换内置 TCXO 的 RTC（DS3231 类） 硬件 到 ±2ppm

正解是别指望 RTC 精确，靠 NTP 校时，RTC 只保证两次校时之间不跑飞。没有网络的设备用 hwclock -w 定期回写，把累积误差压在一个同步周期内。

还有一条：RTC 走 UTC 还是本地时间。sysfs 注释写得很清楚——理想是 UTC，但双系统机器（还要启动 Windows）存本地时间并跟随夏令时，影响 date、time、since_epoch、wakealarm 等属性。hwclock --localtime 和 --utc 就是为这个存在。嵌入式单系统统一用 UTC，在用户态用 TZ 换算，别动 RTC 本身。

十四、硬件 RTC 与软件模拟 #

方案 掉电走时 精度 成本 驱动复杂度
SoC 片内 RTC + 电池 是 ±20ppm 级 电池座 + 电池 低（平台驱动）
SoC 片内 RTC 无电池 否 同左 0 低
纯软件模拟 否 差（丢拍即偏） 0 低但没意义
I2C/SPI 外挂 RTC 是 ±2~20ppm 芯片 + 晶振 + 电池 中（总线驱动）

纯软件 RTC 的骨架是「基准秒数 + jiffies 增量」：每次 read_time 返回 base_secs + (jiffies - base_jiffies) / HZ，set_time 反过来重置基准。掉电归零，精度完全取决于 HZ 和 jiffies 是否丢拍，只在原型阶段有意义。

CONFIG_RTC_INTF_DEV_UIE_EMUL 是另一类模拟，模拟的不是 RTC 本身，而是硬件不支持的 UIE：内核用工作队列轮询秒寄存器，变一次报一次 RTC_UF。

c
static void rtc_uie_task(struct work_struct *work)
{
        struct rtc_device *rtc = container_of(work, struct rtc_device, uie_task);
        struct rtc_time tm;
        int num = 0;

        if (rtc_read_time(rtc, &tm))
                goto out_done;

        spin_lock_irq(&rtc->irq_lock);
        if (rtc->stop_uie_polling) {
                rtc->uie_task_active = 0;
        } else if (rtc->oldsecs != tm.tm_sec) {          /* 秒变了 */
                num = (tm.tm_sec + 60 - rtc->oldsecs) % 60;
                rtc->oldsecs = tm.tm_sec;
                rtc->uie_timer.expires = jiffies + HZ - (HZ / 10);
                rtc->uie_timer_active = 1;
                rtc->uie_task_active = 0;
                add_timer(&rtc->uie_timer);
        } else if (schedule_work(&rtc->uie_task) == 0) {  /* 没变，继续轮询 */
                rtc->uie_task_active = 0;
        }
        spin_unlock_irq(&rtc->irq_lock);
out_done:
        if (num)
                rtc_handle_legacy_irq(rtc, num, RTC_UF);
}

代价明显：轮询期间总线被高频访问，功耗上去，一秒内多次轮询也没意义。只在调试或极端省成本时开。触发条件是驱动返回 -EINVAL：

c
#ifdef CONFIG_RTC_INTF_DEV_UIE_EMUL
        if (err == -EINVAL)
                err = rtc_dev_update_irq_enable_emul(rtc, enabled);
#endif

所以「硬件不支持 UIE」时驱动该返回 -EINVAL 而不是 -ENOTTY，前者触发模拟，后者不触发。这个约定很多驱动写错。

十五、具体的 RTC 芯片驱动 #

rtc-s3c.c 入口是标准 platform driver：of_device_id 表把 samsung,s3c2410-rtc/s3c2416/s3c2443/s3c6410/exynos3250 各映射到一份 s3c_rtc_data，platform_driver 里 .name = "s3c-rtc"、.probe = s3c_rtc_probe、.pm = &s3c_rtc_pm_ops，末尾 module_platform_driver(s3c_rtc_driver)。

芯片差异用函数指针表收拢，s3c2410_rtc_data 里是 max_user_freq = 128 加 irq_handler/set_freq/enable_tick/save_tick_cnt/restore_tick_cnt/enable/disable 七个函数指针。enable/disable 操作的是 RTCCON：复位值若被固件设成二进制计数或复位态，驱动必须纠回来，否则后面所有时间都是乱的。

c
static void s3c24xx_rtc_enable(struct s3c_rtc *info)
{
        unsigned int con = readw(info->base + S3C2410_RTCCON), tmp;

        if ((con & S3C2410_RTCCON_RTCEN) == 0) {         /* RTC 总开关 */
                dev_info(info->dev, "rtc disabled, re-enabling\n");
                tmp = readw(info->base + S3C2410_RTCCON);
                writew(tmp | S3C2410_RTCCON_RTCEN, info->base + S3C2410_RTCCON);
        }
        if (con & S3C2410_RTCCON_CNTSEL) {               /* BCD/二进制计数选择 */
                dev_info(info->dev, "removing RTCCON_CNTSEL\n");
                tmp = readw(info->base + S3C2410_RTCCON);
                writew(tmp & ~S3C2410_RTCCON_CNTSEL, info->base + S3C2410_RTCCON);
        }
        if (con & S3C2410_RTCCON_CLKRST) {               /* 计数器复位 */
                dev_info(info->dev, "removing RTCCON_CLKRST\n");
                tmp = readw(info->base + S3C2410_RTCCON);
                writew(tmp & ~S3C2410_RTCCON_CLKRST, info->base + S3C2410_RTCCON);
        }
}

开机日志里 removing RTCCON_CNTSEL / removing RTCCON_CLKRST 就是纠错的证据。周期中断频率设置里 val = (info->rtc->max_user_freq / freq) - 1，128/1-1 = 127，即每 128 个节拍产生一次 INT_TICK 写入 TICNT（上游用 writel 写 8 位寄存器，能工作但不严谨，writeb 更合适）。

再看 I2C 外挂的 HYM8563。probe 三处和 S3C 截然不同，也是外挂 RTC 的共性：用 devm_rtc_allocate_device + devm_rtc_register_device 而非 devm_rtc_device_register；用 devm_request_threaded_irq，因为 I2C 读写会睡眠；用 features 位图声明能力（set_bit(RTC_FEATURE_ALARM_RES_MINUTE, ...) 表示闹钟只到分钟，6.3 的 rtc_set_alarm 会据此把闹钟向下取整到分钟边界，clear_bit(RTC_FEATURE_UPDATE_INTERRUPT, ...) 表示不支持硬件 UIE）。5.2 完全没有 features 字段，6.x 的 hym8563 拿到 5.2 上编译不过，反之亦然。

唤醒声明也不一样：有 IRQ 就 device_init_wakeup(&client->dev, true)，没 IRQ 时看设备树有没有 wakeup-source 属性。

写时间用 CTL1.STOP 先停走时、写完再恢复，避免写一半被秒进位打断：

c
        if (tm->tm_year < 100 || tm->tm_year >= 200)   /* 限 2000~2099 */
                return -EINVAL;

        buf[0] = bin2bcd(tm->tm_sec);
        buf[1] = bin2bcd(tm->tm_min);
        buf[2] = bin2bcd(tm->tm_hour);
        buf[3] = bin2bcd(tm->tm_mday);
        buf[4] = bin2bcd(tm->tm_wday);
        buf[5] = bin2bcd(tm->tm_mon + 1);
        buf[6] = bin2bcd(tm->tm_year - 100);

        ret = i2c_smbus_write_byte_data(client, HYM8563_CTL1, HYM8563_CTL1_STOP);
        if (ret < 0)
                return ret;
        ret = i2c_smbus_write_i2c_block_data(client, HYM8563_SEC, 7, buf);
        if (ret < 0)
                return ret;
        return i2c_smbus_write_byte_data(client, HYM8563_CTL1, 0);

读侧用 i2c_smbus_read_i2c_block_data(client, HYM8563_SEC, 7, buf) 一次取 7 字节，比逐字节读安全得多；tm->tm_mon = bcd2bin(buf[5] & HYM8563_MONTH_MASK) - 1;、tm->tm_year = bcd2bin(buf[6]) + 100; 与 S3C 完全同构。

十六、调试手段与常见故障 #

开机时应看到这几行 RTC 日志（素材实测）：

text
s3c-rtc s3c-rtc: rtc disabled, re-enabling
rtc rtc0: invalid alarm value: 1900-02-01T00:00:00
s3c-rtc s3c-rtc: registered as rtc0
s3c-rtc s3c-rtc: setting system clock to 2023-01-01T00:55:53 UTC (1672534553)

第一行来自 s3c24xx_rtc_enable，说明 RTCCON.RTCEN 原本是关的；第二行来自 __rtc_read_alarm 的 dev_warn，指硬件闹钟寄存器是无效日期，无害，只说明没人设过闹钟；第三行是注册成功；第四行是 rtc_hctosys 干的，只有名字匹配 CONFIG_RTC_HCTOSYS_DEVICE 的 RTC 才会打。

bash
ls -l /dev/rtc*
cat /sys/class/rtc/rtc0/name
cat /sys/class/rtc/rtc0/date /sys/class/rtc/rtc0/time
cat /sys/class/rtc/rtc0/since_epoch /sys/class/rtc/rtc0/hctosys
cat /proc/driver/rtc
hwclock -r                                    # 读 RTC
date -s "2023-03-26 15:18:40" && hwclock -w   # 系统时间写回 RTC
hwclock -r                                    # 确认落地
echo 1679791064 > /sys/class/rtc/rtc0/since_epoch   # 绕过 hwclock 直接写
# 打开 RTC 子系统的动态 debug 输出
echo 'file drivers/rtc/* +p' > /sys/kernel/debug/dynamic_debug/control
# 闹钟中断到底有没有来，看计数涨不涨
grep rtc /proc/interrupts
# 确认是否被当作唤醒源
cat /sys/class/rtc/rtc0/power/wakeup

/proc/interrupts 里 IRQ_RTC 计数不涨，说明中断根本没进来，往下查资源表里的中断号、request_irq 返回值、寄存器里的中断使能位。

/dev/rtc0 不存在 udev/mdev 没跑，或 cdev_device_add 失败 dmesg | grep rtc 找 failed to add char device

走时正常但每月差几十秒 晶振频偏 set_offset 校正，或换 TCXO
设了闹钟不触发 只发了 RTC_ALM_SET 没发 RTC_AIE_ON 改用 RTC_WKALM_SET

十七、易错点速查 #

# 易错点 正确做法
1 tm_year 直接当年份 它是相对 1900 的偏移，2023 年填 123，显示时 +1900
2 tm_mon 当月份 它是 0~11，1 月填 0，显示时 +1
3 read_time 里 tm_year += 100 而 set_time 忘了 -100 两个方向成对，tm_mon 是 ±1 对称
4 驱动自己实现 RTC_SET_TIME 别碰标准命令，会让 CAP_SYS_TIME 检查与 offset 换算失效
5 只发 RTC_ALM_SET 就等中断 还需 RTC_AIE_ON，或直接用 RTC_WKALM_SET
6 把 -ETIME 当错误上报 它表示「闹钟已过期」，上层要重扫队列
7 在 ops_lock 里再调 rtc_read_time 普通 mutex 不可重入，必死锁；锁内用 __rtc_read_time 或 rtc_alarm_disable
8 忘记 device_init_wakeup sysfs 无 wakealarm，suspend 无法被唤醒
9 新驱动用 devm_rtc_device_register 已 deprecated，用 devm_rtc_allocate_device + rtc_register_device
10 结构体里写 .set_mmss / .open / .release 5.2 起这些字段已删，编译直接报 unknown field
11 timer->func(timer->private_data) 4.19 写法；5.x 是 timer->func(timer->rtc)
12 认为 read_alarm 已被移除 它一直在，6.2+ 只是改用 RTC_FEATURE_ALARM 判定
13 rtc_valid_tm 判不过还硬写硬件 先兜底写默认值再注册，否则开机时间不可预测
14 秒寄存器读到 0 不复读 寄存器组非原子更新，重读一次避免撕裂
15 I2C RTC 逐字节读时间 用 block read 一次取 7 字节
16 I2C RTC 在硬中断里做 I2C 读写 必须 devm_request_threaded_irq，硬中断上下文不能睡
17 移植时照抄别家的 max_user_freq 框架默认 64，S3C2410 需 128，得在 setfreq 前改
18 忘记清 RTCCON.CNTSEL/CLKRST 固件留下的复位值会让时间全乱，enable 里必须纠
19 以为 /dev/rtc0 的 major 固定 alloc_chrdev_region 动态分配，每次启动都不一样
20 业务代码 open("/dev/rtc") 现代内核只有 /dev/rtcN，没有 /dev/rtc
21 多进程同时开 /dev/rtc0 RTC_DEV_BUSY 独占，第二个拿 -EBUSY
22 认为 RTC_ALM_SET 能设到 24 小时以外 语义是「未来 24 小时内」，超出用 RTC_WKALM_SET
23 改完 RTC 时间不处理已过期闹钟 rtc_set_time 末尾的 schedule_work 就是干这个，勿删
24 电池座焊了但不接触 RTC 表面正常、断电后归零，量 VBAT 引脚电压定性
25 双系统机器按 UTC 读 RTC Windows 写本地时间，hwclock --localtime 对齐
26 RTC_IRQP_READ 在 32 位兼容层失败 5.2 无 .compat_ioctl，6.x 才补
27 UIE 不支持时返回 -ENOTTY 该返回 -EINVAL，才能触发 UIE 模拟
28 认为 /proc/driver/rtc 对所有 RTC 都有 只有 hctosys 那一个会创建
