一、USB 主机控制器有哪几类 #

USB 主机控制器（Host Controller）是 SoC 或南桥里那块把 CPU 的读写变成 USB 差分信号的东西。它和 USB 设备控制器（UDC，Device Controller）是两套完全不同的硬件，别混。设备侧的代码在 drivers/usb/gadget/，主机侧在 drivers/usb/host/。

按规范分，主流有四类：

规范 全称 速率 典型年代 内核驱动
UHCI Universal Host Controller Interface 低速 1.5 Mbps / 全速 12 Mbps 1996，Intel 主导 uhci-hcd.c
OHCI Open Host Controller Interface 低速 / 全速 1996，Compaq、Microsoft、National 主导 ohci-hcd.c
EHCI Enhanced Host Controller Interface 高速 480 Mbps，兼容前两者 2000，Intel 主导 ehci-hcd.c
xHCI eXtensible Host Controller Interface 超速 5 / 10 / 20 Gbps 2008，Intel 主导 xhci-hcd.c

再往下细分还有几个变种，都在 hc_driver->flags 里有对应的枚举值：

  • Wireless USB（USB 2.5），历史上的 HCD_USB25；
  • SuperSpeedPlus（USB 3.1 Gen2），HCD_USB31；
  • USB 3.2 双通道，HCD_USB32。

这四个名字里的 HCI 都是 Host Controller Interface，说的是软件和硬件之间的接口约定，不是某一颗芯片。同一颗芯片可以同时集成 OHCI 和 EHCI 两个功能块（早期南桥全这么干），也可以只做 xHCI。

从驱动作者的角度，四类控制器真正的差别只有三件事：

  1. 寄存器怎么摆：UHCI 用 I/O 端口，OHCI/EHCI 用 MMIO，xHCI 也是 MMIO 但寄存器分 capability / operational / runtime / doorbell 四段。
  2. 传输怎么排队：UHCI 用帧链表 + 队列头，OHCI 用端点描述符 ED + 传输描述符 TD，EHCI 用 QH + qTD，xHCI 用 TRB 环加命令环。
  3. 谁来翻译低速/全速设备：EHCI 自己不做，交给 companion 控制器（OHCI/UHCI）；OHCI/UHCI 自己就是全速控制器；xHCI 全包。

二、UHCI、OHCI、EHCI、xHCI 的演进关系 #

演进的主线是「硬件越做越聪明，软件越写越薄」。

UHCI 时代：Intel 为了降低芯片成本，把调度逻辑大量丢给软件。UHCI 的帧列表有 1024 项，每项指向一个「队列头」（Queue Head），软件得自己构造 TD 链表、自己算帧内时间预算。hcd.h 里那句注释就是这么写的：「input size of periodic table to an interrupt scheduler. (ohci 32, uhci 1024, ehci 256/512/1024)」。注意 OHCI 那栏写的是 32，说的是 OHCI 硬件内部的 HCCA 中断表是 32 项——硬件替你做了大部分调度。

OHCI 时代：Compaq 牵头做的开放规范，把调度、TD 处理、帧计数都放进硬件。软件只需要维护端点描述符（ED）和传输描述符（TD），硬件自己按 HCCA（Host Controller Communications Area）里的中断表轮转。OHCI 因此代码量比 UHCI 少，也是嵌入式 SoC 最常见的全速控制器选择——三星 S3C2410/S3C2440 用的就是它。

EHCI 时代：USB 2.0 要 480 Mbps，全速控制器的帧结构撑不住，于是新开一套规范。EHCI 只负责高速设备，低速/全速设备交给同槽位的 companion 控制器（OHCI 或 UHCI）。这件事在 hcd-pci.c 里有专门的一段代码：ehci_pre_add() 在 EHCI 挂载前把 companion 的根集线器先 unconfigure 掉，ehci_post_add() 再把 companion_hcd->self.hs_companion 指过去。加载顺序也有讲究，ehci_hcd_init() 里会检查：

c
if (test_bit(USB_UHCI_LOADED, &usb_hcds_loaded) ||
        test_bit(USB_OHCI_LOADED, &usb_hcds_loaded))
    printk(KERN_WARNING "Warning! ehci_hcd should always be loaded"
            " before uhci_hcd and ohci_hcd, not after\n");

xHCI 时代：USB 3.0 的 9 根线（含两组超速差分对）和链路训练、电源管理状态机，已经没法用「每帧 1024 个表项」这种模型表达了。xHCI 换成统一的传输请求块（TRB，Transfer Request Block）环：每个端点一条环，主机控制器当消费者，软件当生产者；命令走单独的命令环，事件走事件环，门铃寄存器（doorbell）负责敲门。

xHCI 也顺手把 UHCI/OHCI/EHCI 的三套东西收编了：一颗 xHCI 可以同时枚举超速、高速、全速、低速设备，不再需要 companion。这也是为什么 2012 年之后的机器上基本只剩 xhci_hcd 一个驱动在跑。

看 /sys/bus/pci/drivers/ 或 lsusb -t 就能对上号：

bash
# xHCI 时代，主机侧通常只有这几行
$ ls /sys/bus/pci/drivers/ | grep -E 'hcd'
ehci-pci
ohci-pci
uhci_hcd
xhci_hcd

# 看某个控制器挂在哪个驱动上
$ ls -l /sys/bus/pci/drivers/xhci_hcd/ | grep 0000

三、usb_hcd：一个控制器的抽象 #

struct usb_hcd 定义在 include/linux/usb/hcd.h。它是「一个主机控制器」在软件世界的全部身家：一个 usb_bus、一把引用计数、一组标志位、一堆硬件资源、两张完成队列，末尾挂一块驱动私有内存。

先看字段全貌（以 6.12 为基线，逐字段与素材 4.x 版本对过）：

c
struct usb_hcd {
    /*
     * housekeeping
     */
    struct usb_bus        self;            /* hcd is-a bus */
    struct kref           kref;            /* reference counter */

    const char            *product_desc;   /* product/vendor string */
    int                   speed;           /* Speed for this roothub. */
    char                  irq_descr[24];   /* driver + bus # */

    struct timer_list     rh_timer;        /* drives root-hub polling */
    struct urb            *status_urb;     /* the current status urb */
#ifdef CONFIG_PM
    struct work_struct    wakeup_work;     /* for remote wakeup */
#endif
    struct work_struct    died_work;       /* for when the device dies */

    /* hardware info/state */
    const struct hc_driver *driver;        /* hw-specific hooks */

    struct usb_phy        *usb_phy;
    struct usb_phy_roothub *phy_roothub;

    unsigned long         flags;
#define HCD_FLAG_HW_ACCESSIBLE   0   /* at full power */
#define HCD_FLAG_POLL_RH         2   /* poll for rh status? */
#define HCD_FLAG_POLL_PENDING    3   /* status has changed? */
#define HCD_FLAG_WAKEUP_PENDING  4   /* root hub is resuming? */
#define HCD_FLAG_RH_RUNNING      5   /* root hub is running? */
#define HCD_FLAG_DEAD            6   /* controller has died? */
#define HCD_FLAG_INTF_AUTHORIZED 7   /* authorize interfaces? */
/* 6.6+ 新增： */
#define HCD_FLAG_DEFER_RH_REGISTER 8 /* Defer roothub registration */

    enum usb_dev_authorize_policy dev_policy;

    /* Flags that get set only during HCD registration or removal. */
    unsigned  rh_registered:1;
    unsigned  rh_pollable:1;
    unsigned  msix_enabled:1;
    unsigned  msi_enabled:1;
    unsigned  skip_phy_initialization:1;
    unsigned  uses_new_polling:1;
    unsigned  has_tt:1;                    /* Integrated TT in root hub */
    unsigned  amd_resume_bug:1;
    unsigned  can_do_streams:1;
    unsigned  tpl_support:1;
    unsigned  cant_recv_wakeups:1;

    unsigned int          irq;             /* irq allocated */
    void __iomem          *regs;           /* device memory/io */
    resource_size_t       rsrc_start;      /* memory/io resource start */
    resource_size_t       rsrc_len;        /* memory/io resource length */
    unsigned              power_budget;     /* in mA, 0 = no limit */

    struct giveback_urb_bh high_prio_bh;
    struct giveback_urb_bh low_prio_bh;

    struct mutex          *bandwidth_mutex;

    struct usb_hcd        *primary_hcd;

#define __SUSPEND    0x04
#define __TRANSIENT  0x80

#define HC_STATE_QUIESCING (__SUSPEND|__TRANSIENT|__ACTIVE)
#define HC_STATE_RESUMING  (__SUSPEND|__TRANSIENT)
#define HC_STATE_SUSPENDED (__SUSPEND)

    /* memory pool for HCs having local memory, or %NULL */
    struct gen_pool        *localmem_pool;

    /* The HC driver's private data is stored at the end of this structure. */
    unsigned long hcd_priv[]
            __attribute__ ((aligned(sizeof(s64))));
};

关键字段逐个说：

字段 作用 谁写
self 内嵌的 usb_bus，一个控制器就是一条 USB 总线 __usb_create_hcd
kref 引用计数，usb_get_hcd / usb_put_hcd 操作它 框架
speed 根集线器速度，取 driver->flags & HCD_MASK __usb_create_hcd
rh_timer 根集线器状态轮询定时器，回调 rh_timer_func 框架
status_urb 根集线器状态变化那条 interrupt URB 框架
flags 必须用 set_bit / clear_bit 改的原子标志 驱动 + 框架
driver 指向本控制器的 hc_driver 驱动
regs 寄存器映射后的虚拟地址 驱动
rsrc_start / rsrc_len 物理资源区间 驱动
irq 申请到的中断号 usb_add_hcd
state HC_STATE_* 状态机 框架
hcd_priv[] 柔性数组，驱动私有数据入口 驱动读

版本变化一：hcd_priv 的声明。 4.x / 5.x 里是 unsigned long hcd_priv[0] __attribute__ ((aligned(sizeof(s64))));，GCC 的零长数组扩展。6.x 改成了真正的 C99 柔性数组成员 unsigned long hcd_priv[]，private 语义不变，sizeof(struct usb_hcd) 也不含它。取私有数据的写法一直没变：

c
static inline struct ehci_hcd *hcd_to_ehci(struct usb_hcd *hcd)
{
    return (struct ehci_hcd *) (hcd->hcd_priv);
}

static inline struct usb_hcd *ehci_to_hcd(struct ehci_hcd *ehci)
{
    return container_of((void *) ehci, struct usb_hcd, hcd_priv);
}

注意 container_of 那个方向的 offsetof 落在柔性数组上，这是内核里合法的老写法，别照搬到用户态代码。

版本变化二：字段增删。 素材里的 4.x 版本有 unsigned wireless:1，6.12 已经删了（Wireless USB 的 HCD 支持在 5.x 里陆续清理）。反过来 6.x 多了 localmem_pool（给只能用片内 SRAM 做 DMA 的控制器，比如 dwc2）和 HCD_FLAG_DEFER_RH_REGISTER。你对不上号的时候，以手上的内核版本为准，别抄网上任何一篇。

hcd_bus 与 bus_type 的区别。 新手最容易卡在这：内核里早注册了 usb_bus_type（struct bus_type），那是总线类型；hcd->self 是 struct usb_bus，那是总线实例。一个主机控制器对应一条实例。设备模型上所有的 USB 设备都挂在 usb_bus_type 上，靠 dev->bus 找匹配函数；而「这条总线有几个设备、下一个设备号是多少、带宽用了多少」记在 usb_bus 里。

c
struct usb_bus {
    struct device *controller;   /* host/master side hardware */
    struct device *sysdev;       /* as seen from firmware or bus */
    int busnum;                  /* Bus number (in order of reg) */
    const char *bus_name;        /* stable id (PCI slot_name etc) */
    u8 uses_dma;                 /* Does the host controller use DMA? */
    u8 uses_pio_for_control;     /* PIO for control transfers? */
    u8 otg_port;
    unsigned is_b_host:1;
    unsigned b_hnp_enable:1;
    unsigned no_stop_on_short:1;
    unsigned no_sg_constraint:1;
    unsigned sg_tablesize;
    int devnum_next;
    struct mutex devnum_next_mutex;
    struct usb_devmap devmap;    /* device address allocation map */
    struct usb_device *root_hub;
    struct usb_bus *hs_companion;/* Companion EHCI bus, if any */
    int bandwidth_allocated;
    int bandwidth_int_reqs;
    int bandwidth_isoc_reqs;
    unsigned resuming_ports;
    /* CONFIG_USB_MON 才有 */
    struct mon_bus *mon_bus;
    int monitored;
};

devmap 是一个 unsigned long devicemap[128 / (8 * sizeof(long))] 的位图，每一位代表一个设备地址被占。根集线器固定占 1，所以 register_root_hub() 里第一件事就是 set_bit(devnum, usb_dev->bus->devmap)。

uses_dma 由 hcd->self.uses_dma = (sysdev->dma_mask != NULL) 决定，这条决定后面 DMA 映射走不走 dma_map_single。

bandwidth_allocated 的单位是微秒每帧，全速/低速总线保留 90%，高速保留 80%。

四、hcd_driver：HCD 要实现的回调 #

struct hc_driver 是 HCD 驱动和 usbcore 之间的契约。你写一个新控制器驱动，90% 的活就是填这张表。

c
struct hc_driver {
    const char  *description;      /* "ehci-hcd" etc */
    const char  *product_desc;     /* product/vendor string */
    size_t      hcd_priv_size;     /* size of private data */

    /* irq handler */
    irqreturn_t (*irq) (struct usb_hcd *hcd);

    int  flags;
#define HCD_MEMORY   0x0001   /* HC regs use memory (else I/O) */
#define HCD_DMA      0x0002   /* HC uses DMA */
#define HCD_SHARED   0x0004   /* Two (or more) usb_hcds share HW */
#define HCD_USB11    0x0010   /* USB 1.1 */
#define HCD_USB2     0x0020   /* USB 2.0 */
#define HCD_USB3     0x0040   /* USB 3.0 */
#define HCD_USB31    0x0050   /* USB 3.1 */
#define HCD_USB32    0x0060   /* USB 3.2 */
#define HCD_MASK     0x0070
#define HCD_BH       0x0100   /* URB complete in BH context */

    /* called to init HCD and root hub */
    int  (*reset) (struct usb_hcd *hcd);
    int  (*start) (struct usb_hcd *hcd);

    /* these suspend/resume calls relate to the HC as a whole, not just
     * the root hub; they're for PCI bus glue. */
    int  (*pci_suspend)(struct usb_hcd *hcd, bool do_wakeup);
    int  (*pci_resume)(struct usb_hcd *hcd, pm_message_t state);
    int  (*pci_poweroff_late)(struct usb_hcd *hcd, bool do_wakeup);

    void (*stop) (struct usb_hcd *hcd);
    void (*shutdown) (struct usb_hcd *hcd);

    int  (*get_frame_number) (struct usb_hcd *hcd);

    /* manage i/o requests, device state */
    int  (*urb_enqueue)(struct usb_hcd *hcd, struct urb *urb, gfp_t mem_flags);
    int  (*urb_dequeue)(struct usb_hcd *hcd, struct urb *urb, int status);

    /* (optional) override the default DMA mapping routines */
    int  (*map_urb_for_dma)(struct usb_hcd *hcd, struct urb *urb, gfp_t mem_flags);
    void (*unmap_urb_for_dma)(struct usb_hcd *hcd, struct urb *urb);

    /* hw synch, freeing endpoint resources that urb_dequeue can't */
    void (*endpoint_disable)(struct usb_hcd *hcd, struct usb_host_endpoint *ep);

    /* (optional) reset any endpoint state such as sequence number */
    void (*endpoint_reset)(struct usb_hcd *hcd, struct usb_host_endpoint *ep);

    /* root hub support */
    int  (*hub_status_data) (struct usb_hcd *hcd, char *buf);
    int  (*hub_control) (struct usb_hcd *hcd, u16 typeReq, u16 wValue,
                         u16 wIndex, char *buf, u16 wLength);
    int  (*bus_suspend)(struct usb_hcd *);
    int  (*bus_resume)(struct usb_hcd *);
    int  (*start_port_reset)(struct usb_hcd *, unsigned port_num);
    unsigned long (*get_resuming_ports)(struct usb_hcd *);

    /* force handover of high-speed port to full-speed companion */
    void (*relinquish_port)(struct usb_hcd *, int);
    /* has a port been handed over to a companion? */
    int  (*port_handed_over)(struct usb_hcd *, int);

    /* CLEAR_TT_BUFFER completion callback */
    void (*clear_tt_buffer_complete)(struct usb_hcd *, struct usb_host_endpoint *);

    /* xHCI specific functions */
    int  (*alloc_dev)(struct usb_hcd *, struct usb_device *);
    void (*free_dev)(struct usb_hcd *, struct usb_device *);
    int  (*alloc_streams)(struct usb_hcd *hcd, struct usb_device *udev,
            struct usb_host_endpoint **eps, unsigned int num_eps,
            unsigned int num_streams, gfp_t mem_flags);
    int  (*free_streams)(struct usb_hcd *hcd, struct usb_device *udev,
            struct usb_host_endpoint **eps, unsigned int num_eps,
            gfp_t mem_flags);

    /* Bandwidth computation functions */
    int  (*add_endpoint)(struct usb_hcd *, struct usb_device *,
                         struct usb_host_endpoint *);
    int  (*drop_endpoint)(struct usb_hcd *, struct usb_device *,
                          struct usb_host_endpoint *);
    int  (*check_bandwidth)(struct usb_hcd *, struct usb_device *);
    void (*reset_bandwidth)(struct usb_hcd *, struct usb_device *);
    int  (*address_device)(struct usb_hcd *, struct usb_device *udev,
                           unsigned int timeout_ms);
    int  (*enable_device)(struct usb_hcd *, struct usb_device *udev);
    int  (*update_hub_device)(struct usb_hcd *, struct usb_device *hdev,
                              struct usb_tt *tt, gfp_t mem_flags);
    int  (*reset_device)(struct usb_hcd *, struct usb_device *);
    int  (*update_device)(struct usb_hcd *, struct usb_device *);
    int  (*set_usb2_hw_lpm)(struct usb_hcd *, struct usb_device *, int);
    int  (*enable_usb3_lpm_timeout)(struct usb_hcd *,
                                    struct usb_device *, enum usb3_link_state state);
    int  (*disable_usb3_lpm_timeout)(struct usb_hcd *,
                                     struct usb_device *, enum usb3_link_state state);
    int  (*find_raw_port_number)(struct usb_hcd *, int);
    int  (*port_power)(struct usb_hcd *hcd, int portnum, bool enable);

    /* SINGLE_STEP_SET_FEATURE Test for USB2 EH certification */
#define EHSET_TEST_SINGLE_STEP_SET_FEATURE 0x06
    int  (*submit_single_step_set_feature)(struct usb_hcd *, struct urb *, int);
};

按职责分组，哪些必须实现、哪些可选：

description / product_desc / hcd_priv_size 必需 身份与私有数据大小 "ehci-hcd" / sizeof(struct ehci_hcd)
flags 必需 声明寄存器空间类型、速率、完成上下文 EHCI 是 HCD_MEMORY | HCD_DMA | HCD_USB2 | HCD_BH
irq 必需 中断上半部，只看状态寄存器、清中断 ehci_irq
reset 必需 一次性初始化，不是「复位控制器」 ehci_setup
start 必需 启动调度、开中断 ehci_run
stop 必需 停调度、静默控制器 ehci_stop
shutdown 可选 关机前强制关 DMA 和中断 ehci_shutdown
get_frame_number 可选 当前帧号，给等时传输用 ehci_get_frame
urb_enqueue 必需 核心：把 URB 变成硬件描述符 ehci_urb_enqueue
urb_dequeue 必需 撤销一个已入队的 URB ehci_urb_dequeue
endpoint_disable 必需 释放 endpoint 占的硬件资源 ehci_endpoint_disable
endpoint_reset 可选 清 halt 后重置 toggle 等状态 ehci_endpoint_reset
hub_status_data 必需 报告根集线器哪些端口变了 ehci_hub_status_data
hub_control 必需 处理根集线器的 class 请求 ehci_hub_control
bus_suspend / bus_resume 可选 整条总线挂起/恢复 ehci_bus_suspend
start_port_reset / get_resuming_ports 可选 端口复位与恢复跟踪 ehci_*
relinquish_port / port_handed_over 可选 高速端口交还给 companion EHCI 专用
map_urb_for_dma / unmap_urb_for_dma 可选 覆盖默认 DMA 映射（有对齐要求时） 大多数留空
alloc_dev / free_dev / address_device 可选 由硬件分配地址（xHCI） xhci_*
add/drop/check/reset_bandwidth 可选 硬件调度带带宽核算时 xHCI、EHCI
port_power 可选 按端口上电/断电 ehci_port_power

版本坑一：pci_resume 的签名。 素材里（4.x～5.x 早期）是 int (*pci_resume)(struct usb_hcd *hcd, bool hibernated)；6.12 是 int (*pci_resume)(struct usb_hcd *hcd, pm_message_t state)，从布尔值换成了完整的 PM 消息。hcd-pci.c 里对应改成 hcd->driver->pci_resume(hcd, msg)。素材那行注释「called after entering D0 (etc), before resuming the hub」在 6.12 里仍然保留。

版本坑二：flags 枚举。 素材里是 HCD_LOCAL_MEM 0x0002、HCD_USB25 0x0030；6.12 是 HCD_DMA 0x0002（名字和语义都换了，从「HC 需要本地内存」变成「HC 用 DMA」），HCD_USB25 已删除。素材里那组 HCD_USB11/USB2/USB25/USB3/USB31/USB32 里，HCD_USB11/USB2/USB3 的数值 6.12 仍一致，USB25 未验证是否在 5.x 也存在。

版本坑三：address_device 多了 timeout_ms。 素材里是 int (*address_device)(struct usb_hcd *, struct usb_device *udev);，6.12 加了第三个参数 unsigned int timeout_ms。这个改动跟着 xHCI 的 SetAddress 命令超时控制一起进来的，导致 core 里 hub_set_address() 的调用也跟着变。

reset 名不副实。 源码注释写得很直白：「"reset" is misnamed; its role is now one-time init. the controller should already have been reset (and boot firmware kicked off etc)」。真正的硬件复位发生在 usb_hcd 被创建之前的 probe 里，或者由 reset 自己内部调用（EHCI 的 ehci_setup 里就调了 ehci_halt 和 ehci_reset）。所以你的 reset 实现里既做内存态初始化，也可以顺手复位硬件，但别指望框架替你复位。

urb_enqueue 的返回值契约。 返回 0 表示「URB 归我了，我保证之后一定调 usb_hcd_giveback_urb()」，返回负错误码表示「不要了，请把 URB 还回去」。绝不能既返回 0 又调 giveback，也不能既返回 0 又不调。核心里 usb_hcd_submit_urb() 在 urb_enqueue 失败时会自己补一次 unmap_urb_for_dma()：

c
status = map_urb_for_dma(hcd, urb, mem_flags);
if (likely(status == 0)) {
    status = hcd->driver->urb_enqueue(hcd, urb, mem_flags);
    if (unlikely(status))
        unmap_urb_for_dma(hcd, urb);
}

五、根集线器：Host Controller 的"内生"集线器 #

USB 拓扑是一棵分层星型树：根节点是主机控制器，控制器下面挂根集线器，根集线器下面挂设备或集线器，集线器可以继续级联（内核限制最深 6 层，MAX_TOPO_LEVEL）。

麻烦在于：根集线器不是真设备，它是主机控制器里的一组寄存器，但 usbcore 需要一个 struct usb_device 来跑标准的设备枚举流程。

解决方法是「虚拟设备 + 假描述符」。drivers/usb/core/hcd.c 里硬编码了几份描述符数组：

c
/* usb 2.0 root hub device descriptor */
static const u8 usb2_rh_dev_descriptor[18] = {
    0x12,       /*  __u8  bLength; */
    USB_DT_DEVICE, /* __u8 bDescriptorType; Device */
    0x00, 0x02, /*  __le16 bcdUSB; v2.0 */

    0x09,       /*  __u8  bDeviceClass; HUB_CLASSCODE */
    0x00,       /*  __u8  bDeviceSubClass; */
    0x00,       /*  __u8  bDeviceProtocol; [ usb 2.0 no TT ] */
    0x40,       /*  __u8  bMaxPacketSize0; 64 Bytes */

    0x6b, 0x1d, /*  __le16 idVendor; Linux Foundation 0x1d6b */
    0x02, 0x00, /*  __le16 idProduct; device 0x0002 */
    KERNEL_VER, KERNEL_REL, /* __le16 bcdDevice */

    0x03,       /*  __u8  iManufacturer; */
    0x02,       /*  __u8  iProduct; */
    0x01,       /*  __u8  iSerialNumber; */
    0x01        /*  __u8  bNumConfigurations; */
};

usb11_rh_dev_descriptor、usb2_rh_dev_descriptor、usb3_rh_dev_descriptor、usb31_rh_dev_descriptor 各一份，idVendor 全是 Linux Foundation 的 0x1d6b，product 分别是 0x0001、0x0002、0x0003。你在 lsusb -t 里看到 1d6b:0002 这类设备，那就是根集线器，不是外接硬件。

配置描述符里端点地址是 0x81，bmAttributes = 0x03（interrupt），wMaxPacketSize 按 (USB_MAXCHILDREN + 1 + 7) / 8 算，bInterval = 0x0c（即 256 ms，USB 2.0 规范要求）。全速那份 bInterval 是 0xff，注释写着「(255ms -- usb 2.0 spec)」。

根集线器的请求被谁处理？ rh_call_control()。它不走硬件，而是分三类：

  • 标准请求（GET_DESCRIPTOR、SET_ADDRESS 等）→ 直接从上面那些数组拷数据；
  • class 请求（GetPortStatus、SetPortFeature 等）→ 转给 hcd->driver->hub_control()；
  • 其他 → STALL。

所以 hub_control 是唯一一个你能拦到根集线器 class 请求的地方。端点 0 的「Setup」阶段由 core 伪造，你只看到 typeReq/wValue/wIndex 这几个参数。

状态怎么上报？ 两条路：

  1. 轮询：rh_timer 定时触发 rh_timer_func() → usb_hcd_poll_rh_status() → hcd->driver->hub_status_data()。这是老机制，uses_new_polling == 0 的控制器必须靠它。
  2. 中断驱动：控制器在端口状态变化时触发中断，中断里直接调 usb_hcd_poll_rh_status()，同时硬件侧把 HCD_FLAG_POLL_RH 位置起来。EHCI 走的这条：ehci_irq() 里处理完 STS_PCD 后调 usb_hcd_poll_rh_status(hcd)。
c
void usb_hcd_poll_rh_status(struct usb_hcd *hcd)
{
    struct urb *urb;
    int length;
    unsigned long flags;
    char buffer[6];      /* Any root hubs with > 31 ports? */

    if (unlikely(!hcd->rh_pollable))
        return;
    if (!hcd->uses_new_polling && !hcd->status_urb)
        return;

    length = hcd->driver->hub_status_data(hcd, buffer);
    if (length > 0) {
        spin_lock_irqsave(&hcd_root_hub_lock, flags);
        urb = hcd->status_urb;
        if (urb) {
            clear_bit(HCD_FLAG_POLL_PENDING, &hcd->flags);
            hcd->status_urb = NULL;
            urb->actual_length = length;
            memcpy(urb->transfer_buffer, buffer, length);
            usb_hcd_unlink_urb_from_ep(hcd, urb);
            usb_hcd_giveback_urb(hcd, urb, 0);
        } else {
            length = 0;
            set_bit(HCD_FLAG_POLL_PENDING, &hcd->flags);
        }
        spin_unlock_irqrestore(&hcd_root_hub_lock, flags);
    }

    /* The USB 2.0 spec says 256 ms. */
    if (hcd->uses_new_polling ? HCD_POLL_RH(hcd) :
            (length == 0 && hcd->status_urb != NULL))
        mod_timer(&hcd->rh_timer, (jiffies/(HZ/4) + 1) * (HZ/4));
}

那个 char buffer[6] 有意思：31 个端口的状态位图只需 4 字节，注释还问「Any root hubs with > 31 ports?」。hub_status_data() 实现里必须自己按这个上限裁剪。

根集线器注册。 枚举流程和老设备一样，只是把「发 USB 请求」换成「读假描述符」：

c
static int register_root_hub(struct usb_hcd *hcd)
{
    struct device *parent_dev = hcd->self.controller;
    struct usb_device *usb_dev = hcd->self.root_hub;
    struct usb_device_descriptor *descr;
    const int devnum = 1;
    int retval;

    usb_dev->devnum = devnum;            /* 根集线器地址固定 1 */
    usb_dev->bus->devnum_next = devnum + 1;
    set_bit(devnum, usb_dev->bus->devmap);
    usb_set_device_state(usb_dev, USB_STATE_ADDRESS);

    mutex_lock(&usb_bus_idr_lock);

    usb_dev->ep0.desc.wMaxPacketSize = cpu_to_le16(64);
    descr = usb_get_device_descriptor(usb_dev);
    if (IS_ERR(descr)) {
        retval = PTR_ERR(descr);
        mutex_unlock(&usb_bus_idr_lock);
        dev_dbg(parent_dev, "can't read %s device descriptor %d\n",
                dev_name(&usb_dev->dev), retval);
        return retval;
    }
    usb_dev->descriptor = *descr;
    kfree(descr);

    if (le16_to_cpu(usb_dev->descriptor.bcdUSB) >= 0x0201) {
        retval = usb_get_bos_descriptor(usb_dev);
        if (!retval) {
            usb_dev->lpm_capable = usb_device_supports_lpm(usb_dev);
        } else if (usb_dev->speed >= USB_SPEED_SUPER) {
            mutex_unlock(&usb_bus_idr_lock);
            dev_dbg(parent_dev, "can't read %s bos descriptor %d\n",
                    dev_name(&usb_dev->dev), retval);
            return retval;
        }
    }

    retval = usb_new_device(usb_dev);
    if (retval) {
        dev_err(parent_dev, "can't register root hub for %s, %d\n",
                dev_name(&usb_dev->dev), retval);
    } else {
        spin_lock_irq(&hcd_root_hub_lock);
        hcd->rh_registered = 1;
        spin_unlock_irq(&hcd_root_hub_lock);

        /* Did the HC die before the root hub was registered? */
        if (HCD_DEAD(hcd))
            usb_hc_died(hcd);   /* This time clean up */
    }
    mutex_unlock(&usb_bus_idr_lock);

    return retval;
}

版本变化（必须标）：素材里是 retval = usb_get_device_descriptor(usb_dev, USB_DT_DEVICE_SIZE); / if (retval != sizeof usb_dev->descriptor)，那是 5.x 早期及以前的写法，usb_get_device_descriptor() 返回字节数并把结果写进 dev->descriptor。6.12 改成了返回 struct usb_device_descriptor *，失败返回 ERR_PTR，调用方自己 kmemcpy。这中间在 6.7 前后改的，具体版本号未验证。

devnum_next = 2 这一行要留意：根集线器占了 1，所以第一个外接设备从 2 开始分配。

六、控制器的注册：usb_add_hcd #

usb_hcd 结构造好了，寄存器映射完了，接下来是 usb_add_hcd()。这个函数把「一个分配好的空壳」变成「内核里一条活的总线」。

c
int usb_add_hcd(struct usb_hcd *hcd,
        unsigned int irqnum, unsigned long irqflags)
{
    int retval;
    struct usb_device *rhdev;

    /* 1. PHY 初始化（仅主 HCD） */
    if (!hcd->skip_phy_initialization && usb_hcd_is_primary_hcd(hcd)) {
        hcd->phy_roothub = usb_phy_roothub_alloc(hcd->self.sysdev);
        if (IS_ERR(hcd->phy_roothub))
            return PTR_ERR(hcd->phy_roothub);

        retval = usb_phy_roothub_init(hcd->phy_roothub);
        if (retval)
            return retval;

        retval = usb_phy_roothub_set_mode(hcd->phy_roothub,
                                          PHY_MODE_USB_HOST_SS);
        if (retval)
            retval = usb_phy_roothub_set_mode(hcd->phy_roothub,
                                              PHY_MODE_USB_HOST);
        if (retval)
            goto err_usb_phy_roothub_power_on;

        retval = usb_phy_roothub_power_on(hcd->phy_roothub);
        if (retval)
            goto err_usb_phy_roothub_power_on;
    }

    dev_info(hcd->self.controller, "%s\n", hcd->product_desc);

    /* 2. 设备授权策略 */
    switch (authorized_default) {
    case USB_AUTHORIZE_NONE:
        hcd->dev_policy = USB_DEVICE_AUTHORIZE_NONE;
        break;
    case USB_AUTHORIZE_ALL:
        hcd->dev_policy = USB_DEVICE_AUTHORIZE_ALL;
        break;
    case USB_AUTHORIZE_INTERNAL:
        hcd->dev_policy = USB_DEVICE_AUTHORIZE_INTERNAL;
        break;
    case USB_AUTHORIZE_WIRED:
    default:
        hcd->dev_policy = hcd->wireless ?
                USB_DEVICE_AUTHORIZE_NONE : USB_DEVICE_AUTHORIZE_ALL;
        break;
    }
    set_bit(HCD_FLAG_HW_ACCESSIBLE, &hcd->flags);
    /* per default all interfaces are authorized */
    set_bit(HCD_FLAG_INTF_AUTHORIZED, &hcd->flags);

    /* 3. DMA 缓冲池 */
    retval = hcd_buffer_create(hcd);
    if (retval != 0) {
        dev_dbg(hcd->self.sysdev, "pool alloc failed\n");
        goto err_create_buf;
    }

    /* 4. 注册总线，分配 busnum */
    retval = usb_register_bus(&hcd->self);
    if (retval < 0)
        goto err_register_bus;

    /* 5. 为根集线器分配 usb_device */
    rhdev = usb_alloc_dev(NULL, &hcd->self, 0);
    if (rhdev == NULL) {
        dev_err(hcd->self.sysdev, "unable to allocate root hub\n");
        retval = -ENOMEM;
        goto err_allocate_root_hub;
    }
    mutex_lock(&usb_port_peer_mutex);
    hcd->self.root_hub = rhdev;
    mutex_unlock(&usb_port_peer_mutex);

    rhdev->rx_lanes = 1;
    rhdev->tx_lanes = 1;

    /* 6. 按控制器速率给根集线器定速 */
    switch (hcd->speed) {
    case HCD_USB11:
        rhdev->speed = USB_SPEED_FULL;
        break;
    case HCD_USB2:
        rhdev->speed = USB_SPEED_HIGH;
        break;
    case HCD_USB25:
        rhdev->speed = USB_SPEED_WIRELESS;
        break;
    case HCD_USB3:
        rhdev->speed = USB_SPEED_SUPER;
        break;
    case HCD_USB32:
        rhdev->rx_lanes = 2;
        rhdev->tx_lanes = 2;
        /* fall through */
    case HCD_USB31:
        rhdev->speed = USB_SPEED_SUPER_PLUS;
        break;
    default:
        retval = -EINVAL;
        goto err_set_rh_speed;
    }

    device_set_wakeup_capable(&rhdev->dev, 1);
    set_bit(HCD_FLAG_RH_RUNNING, &hcd->flags);

    /* 7. 调用驱动的 reset()（一次性初始化） */
    if (hcd->driver->reset) {
        retval = hcd->driver->reset(hcd);
        if (retval < 0) {
            dev_err(hcd->self.controller, "can't setup: %d\n", retval);
            goto err_hcd_driver_setup;
        }
    }
    hcd->rh_pollable = 1;

    /* 8. 初始化两张完成队列 */
    init_giveback_urb_bh(&hcd->high_prio_bh);
    init_giveback_urb_bh(&hcd->low_prio_bh);

    /* 9. 申请中断 */
    if (usb_hcd_is_primary_hcd(hcd) && irqnum) {
        retval = usb_hcd_request_irqs(hcd, irqnum, irqflags);
        if (retval)
            goto err_request_irq;
    }

    /* 10. 调用驱动的 start() */
    hcd->state = HC_STATE_RUNNING;
    retval = hcd->driver->start(hcd);
    if (retval < 0) {
        dev_err(hcd->self.controller, "startup error %d\n", retval);
        goto err_hcd_driver_start;
    }

    /* 11. 注册根集线器 */
    retval = register_root_hub(hcd);
    if (retval != 0)
        goto err_register_root_hub;

    /* 12. sysfs 属性组 */
    retval = sysfs_create_group(&rhdev->dev.kobj, &usb_bus_attr_group);
    if (retval < 0) {
        printk(KERN_ERR "Cannot register USB bus sysfs attributes: %d\n", retval);
        goto error_create_attr_group;
    }

    /* 13. 启动轮询 */
    if (hcd->uses_new_polling && HCD_POLL_RH(hcd))
        usb_hcd_poll_rh_status(hcd);

    return retval;
    /* ... 错误路径见下 ... */
}

第 4 步里的 usb_register_bus() 负责分配总线号：

c
static int usb_register_bus(struct usb_bus *bus)
{
    int result = -E2BIG;
    int busnum;

    mutex_lock(&usb_bus_idr_lock);
    busnum = idr_alloc(&usb_bus_idr, bus, 1, USB_MAXBUS, GFP_KERNEL);
    if (busnum < 0) {
        pr_err("%s: failed to get bus number\n", usbcore_name);
        goto error_find_busnum;
    }
    bus->busnum = busnum;
    mutex_unlock(&usb_bus_idr_lock);

    usb_notify_add_bus(bus);

    dev_info(bus->controller, "new USB bus registered, assigned bus number %d\n",
             bus->busnum);
    return 0;

error_find_busnum:
    mutex_unlock(&usb_bus_idr_lock);
    return result;
}

USB_MAXBUS 是 64。distro 上 busnum 不连续是正常的，热插拔会让 IDR 空洞化。

错误路径是一串 goto，倒着拆前面的初始化。注意 err_hcd_driver_start 那一级：

注意 start() 成功之后的失败（err_register_root_hub）会额外做 hcd->driver->stop(hcd)、del_timer_sync(&hcd->rh_timer)、hcd->state = HC_STATE_HALT。也就是说 reset() 失败不调 stop()，start() 失败也不调 stop()——这一点写驱动时要记住：初始化失败路径自己清自己的硬件。

卸载是严格的反向过程，usb_remove_hcd()：拿住 rhdev → 删 sysfs → 清 HCD_FLAG_RH_RUNNING → state = HC_STATE_QUIESCING → usb_disconnect(&rhdev) → hcd->rh_pollable = 0 → del_timer_sync → driver->stop() → state = HC_STATE_HALT → 再 del_timer_sync 一次 → free_irq → usb_deregister_bus() → hcd_buffer_destroy() → PHY 下电 → usb_put_invalidate_rhdev() → hcd->flags = 0。

两次 del_timer_sync 不是冗余：stop() 期间控制器会重新触发端口变化中断从而重启定时器，注释里写的就是这个理由。

七、寄存器空间与 MMIO #

HCD 打交道的寄存器有两种地址空间，靠 hc_driver->flags 里的 HCD_MEMORY 区分：

  • I/O 端口（HCD_MEMORY 不设）：UHCI 的老路子，用 inl() / outl() 访问 unsigned long io_addr。
  • 内存映射（HCD_MEMORY 设）：OHCI、EHCI、xHCI 都是 MMIO，用 readl() / writel() 访问 void __iomem *regs。

PCI 挂载时这条分叉在 usb_hcd_pci_probe() 里：

c
if (driver->flags & HCD_MEMORY) {
    /* EHCI, OHCI */
    hcd->rsrc_start = pci_resource_start(dev, 0);
    hcd->rsrc_len = pci_resource_len(dev, 0);
    if (!devm_request_mem_region(&dev->dev, hcd->rsrc_start,
            hcd->rsrc_len, driver->description)) {
        dev_dbg(&dev->dev, "controller already in use\n");
        retval = -EBUSY;
        goto put_hcd;
    }
    hcd->regs = devm_ioremap(&dev->dev, hcd->rsrc_start, hcd->rsrc_len);
    if (hcd->regs == NULL) {
        dev_dbg(&dev->dev, "error mapping memory\n");
        retval = -EFAULT;
        goto put_hcd;
    }
} else {
    /* UHCI */
    int region;

    for (region = 0; region < PCI_STD_NUM_BARS; region++) {
        if (!(pci_resource_flags(dev, region) & IORESOURCE_IO))
            continue;
        hcd->rsrc_start = pci_resource_start(dev, region);
        hcd->rsrc_len = pci_resource_len(dev, region);
        if (devm_request_region(&dev->dev, hcd->rsrc_start,
                hcd->rsrc_len, driver->description))
            break;
    }
    if (region == PCI_STD_NUM_BARS) {
        dev_dbg(&dev->dev, "no i/o regions available\n");
        retval = -EBUSY;
        goto put_hcd;
    }
}

    s3c2410_stop_hc(dev);
 err_put:
    usb_put_hcd(hcd);
    return retval;
}

注意 devm_ioremap_resource() 一步顶两步：它内部先 devm_request_mem_region() 再 devm_ioremap()。PCI 那边 usb_hcd_pci_probe() 出于历史原因还分开写。

void __iomem 不是普通指针。 别直接解引用，别转成 uint32_t *，别做 memcpy。必须走 readl() / writel() / readl_relaxed()。编译器需要 __iomem 这个注解来阻止错误的优化；sparse 工具会替你抓违规。

寄存器基址的偏移计算。 EHCI 是两段式：capability 寄存器在前，operational 寄存器在 cap 区长度之后：

c
int ehci_setup(struct usb_hcd *hcd)
{
    struct ehci_hcd *ehci = hcd_to_ehci(hcd);
    ...
    ehci->regs = (void __iomem *)ehci->caps +
        HC_LENGTH(ehci, ehci_readl(ehci, &ehci->caps->hc_capbase));
    ...
}

HC_LENGTH() 从 CAPLENGTH 字段取字节长度。这就是为什么任何 EHCI 访问都必须先读一次 capability 区才能算出 operational 区基址。

字节序。 大多数控制器寄存器是小端，少数（如 AMCC 440EPx）是大端，所以 ehci.h 里包了一层：

c
static inline unsigned int ehci_readl(const struct ehci_hcd *ehci,
        __u32 __iomem *regs)
{
#ifdef CONFIG_USB_EHCI_BIG_ENDIAN_MMIO
    return ehci_big_endian_mmio(ehci) ? readl_be(regs) : readl(regs);
#else
    return readl(regs);
#endif
}

同理描述符也有字节序问题，__hc32 类型就是为此而设：默认是 __le32，开了 CONFIG_USB_EHCI_BIG_ENDIAN_DESC 后由 cpu_to_hc32() / hc32_to_cpu() 在运行时切换。

写后读一把作桩。 writel() 在多数体系结构上是 posted write，写完不一定到硬件。EHCI 里反复出现的写法是：

c
ehci_writel(ehci, FLAG_CF, &ehci->regs->configured_flag);
/* Wait until HC become operational */
ehci_readl(ehci, &ehci->regs->command);  /* unblock posted writes */
msleep(5);

读一次别的寄存器，把前面的写刷下去。你自己写驱动时照抄这个习惯。

八、URB 的调度与队列 #

一个 URB 从设备驱动手里到硬件描述符，中间要过三层：usb_submit_urb()（core 层校验）→ usb_hcd_submit_urb()（HCD 层通用处理）→ hcd->driver->urb_enqueue()（你的代码）。

中间那层是所有 HCD 共享的，逻辑不长但每一步都有讲究：

c
int usb_hcd_submit_urb(struct urb *urb, gfp_t mem_flags)
{
    int status;
    struct usb_hcd *hcd = bus_to_hcd(urb->dev->bus);

    /* increment urb's reference count as part of giving it to the HCD */
    usb_get_urb(urb);
    atomic_inc(&urb->use_count);
    atomic_inc(&urb->dev->urbnum);
    usbmon_urb_submit(&hcd->self, urb);

    if (is_root_hub(urb->dev)) {
        status = rh_urb_enqueue(hcd, urb);
    } else {
        status = map_urb_for_dma(hcd, urb, mem_flags);
        if (likely(status == 0)) {
            status = hcd->driver->urb_enqueue(hcd, urb, mem_flags);
            if (unlikely(status))
                unmap_urb_for_dma(hcd, urb);
        }
    }

    if (unlikely(status)) {
        usbmon_urb_submit_error(&hcd->self, urb, status);
        urb->hcpriv = NULL;
        INIT_LIST_HEAD(&urb->urb_list);
        atomic_dec(&urb->use_count);
        smp_mb__after_atomic();
        atomic_dec(&urb->dev->urbnum);
        if (atomic_read(&urb->reject))
            wake_up(&usb_kill_urb_queue);
        usb_put_urb(urb);
    }
    return status;
}

三条分叉要背下来：

  1. 根集线器的 URB 不进硬件。is_root_hub(urb->dev) 为真时不调 urb_enqueue，改走 rh_urb_enqueue()，由它判断是控制请求还是状态轮询，分别转给 rh_call_control() 或挂到 hcd->status_urb。
  2. DMA 映射在 urb_enqueue 之前。你的 urb_enqueue 拿到的 urb->transfer_dma 已经是设备地址，直接用，别再自己 virt_to_phys。
  3. 失败自动回滚。urb_enqueue 返回错误时框架补一次 unmap_urb_for_dma()，所以你的错误路径里不需要再解映射。

urb->hcpriv 是你的地盘。 框架从不碰它的内容，只在这些时机清零：入队失败时、__usb_hcd_giveback_urb() 归还时。EHCI 往里塞 struct ehci_qh *，或者等时传输时塞 struct ehci_iso_stream *。

endpoint 队列的挂接。 你的 urb_enqueue 必须做两件事，缺一不可：

c
/* 第一个 HCD 的私有自旋锁必须已经持有，且中断已关 */
rc = usb_hcd_link_urb_to_ep(hcd, urb);
if (rc) {
    spin_unlock_irqrestore(&ehci->lock, flags);
    return rc;
}
/* ... 把 URB 挂到硬件描述符上 ... */

usb_hcd_link_urb_to_ep() 检查四件事：URB 是否被 usb_kill_urb() 标记（urb->reject）、endpoint 是否 enabled、设备是否允许提交（udev->can_submit）、控制器是否在跑（HCD_RH_RUNNING）。任何一项不过就返回错误，你必须把错误原样传出去。

对应地，完成时必须先摘再还：

c
usb_hcd_unlink_urb_from_ep(hcd, urb);
usb_hcd_giveback_urb(hcd, urb, status);

顺序不能反。usb_hcd_unlink_urb_from_ep() 只是把 urb->urb_list 从 endpoint 链表上摘掉（list_del_init），真正回调驱动在 giveback 里。

解链。 urb_dequeue 的实现套路是 usb_hcd_check_unlink_urb() + 硬件侧解链：

c
int usb_hcd_check_unlink_urb(struct usb_hcd *hcd, struct urb *urb, int status)
{
    struct list_head *tmp;

    /* insist the urb is still queued */
    list_for_each(tmp, &urb->ep->urb_list) {
        if (tmp == &urb->urb_list)
            break;
    }
    if (tmp != &urb->urb_list)
        return -EIDRM;

    /* Any status except -EINPROGRESS means something already started to
     * unlink this URB from the hardware. */
    if (urb->unlinked)
        return -EBUSY;
    urb->unlinked = status;
    return 0;
}

返回 -EIDRM 说明 URB 根本不在这条 endpoint 队列上，返回 -EBUSY 说明已经有人在解链了。这两个都是正常的，别当错误处理。urb->unlinked 后面会被 __usb_hcd_giveback_urb() 当作 status 传给完成函数。

完成回调在哪个上下文跑？ 取决于 hc_driver->flags 里有没有 HCD_BH，以及是不是根集线器：

c
void usb_hcd_giveback_urb(struct usb_hcd *hcd, struct urb *urb, int status)
{
    struct giveback_urb_bh *bh;
    bool running;

    /* pass status to BH via unlinked */
    if (likely(!urb->unlinked))
        urb->unlinked = status;

    if (!hcd_giveback_urb_in_bh(hcd) && !is_root_hub(urb->dev)) {
        __usb_hcd_giveback_urb(urb);
        return;
    }

    if (usb_pipeisoc(urb->pipe) || usb_pipeint(urb->pipe))
        bh = &hcd->high_prio_bh;
    else
        bh = &hcd->low_prio_bh;

    spin_lock(&bh->lock);
    list_add_tail(&urb->urb_list, &bh->head);
    running = bh->running;
    spin_unlock(&bh->lock);

    if (running)
        ;
    else if (bh->high_prio)
        queue_work(system_bh_highpri_wq, &bh->bh);
    else
        queue_work(system_bh_wq, &bh->bh);
}

版本变化（必须标）：素材里是 tasklet_hi_schedule(&bh->bh) / tasklet_schedule(&bh->bh)，队列成员是 struct tasklet_struct bh。5.x 之后内核把 tasklet 换成 workqueue，struct giveback_urb_bh 的 bh 变成 struct work_struct，init_giveback_urb_bh() 里 INIT_WORK。6.12 仍是 workqueue 版本。切换的具体版本号未验证。

这带来一个实用差异：老内核里完成回调在软中断上下文，只能用 GFP_ATOMIC 分配内存、不能用 mutex；新内核里 HCD_BH 的 HCD 完成回调跑在 system_bh_wq 的进程上下文，理论上能睡，但 usbcore 的兼容约定仍然是「按原子上下文写」，别赌。

优先级划分也有讲究：等时和中断 URB 进 high_prio_bh，控制/批量进 low_prio_bh。音频设备靠这一条保时延。

同步等待的 URB 怎么完成？ usb_start_wait_urb() 里挂一个 struct completion 到 urb->context，完成函数是 usb_api_blocking_completion，里面就一句 complete(&ctx->done)。这就是 usb_control_msg() 这类同步 API 的底：

c
static int usb_internal_control_msg(struct usb_device *usb_dev,
                                    unsigned int pipe,
                                    struct usb_ctrlrequest *cmd,
                                    void *data, int len, int timeout)
{
    struct urb *urb;
    int retv;
    int length;

    urb = usb_alloc_urb(0, GFP_NOIO);
    if (!urb)
        return -ENOMEM;

    usb_fill_control_urb(urb, usb_dev, pipe, (unsigned char *)cmd, data,
                         len, usb_api_blocking_completion, NULL);

    retv = usb_start_wait_urb(urb, timeout, &length);
    if (retv < 0)
        return retv;
    else
        return length;
}

不同控制器下的调度差异一览：

控制器 数据结构 排队方式 硬件轮询
UHCI 帧链表 1024 + QH 软件把 TD 串进 QH 硬件按帧表走
OHCI HCCA + ED + TD ED 挂 TD 链，ED 挂到 HCCI 里的表 硬件轮询 ED
EHCI QH + qTD，(s)iTD 给等时 异步环形链 + 周期帧表 硬件自动推进
xHCI 每端点一条 TRB 环 软件产 TRB，写 doorbell 硬件消费环

hc_driver 里 add_endpoint / drop_endpoint / check_bandwidth / reset_bandwidth 这四个回调只有「硬件调度需要预先知道带宽」的控制器才实现。OHCI/UHCI 靠 usb_bus.bandwidth_allocated 软件记账，所以它们把 endpoint_disable 做就行；xHCI 必须实现全套，因为它的端点上下文一旦下发就不能随便改。

九、异步调度：EHCI 的周期与非周期队列 #

EHCI 把所有传输分成两类，硬件上有两条独立的调度表。

异步调度（Asynchronous Schedule）：跑 control、bulk。结构是一条环形链表，所有 QH 串成一个圈，硬件沿圈不停地走。ehci_init() 里先造一个「哑 QH」当环头：

c
/* dedicate a qh for the async ring head, since we couldn't unlink
 * a 'real' qh without stopping the async schedule [4.8].  use it
 * as the 'reclamation list head' too. */
ehci->async->qh_next.qh = NULL;
hw = ehci->async->hw;
hw->hw_next = QH_NEXT(ehci, ehci->async->qh_dma);
hw->hw_info1 = cpu_to_hc32(ehci, QH_HEAD);
hw->hw_token = cpu_to_hc32(ehci, QTD_STS_HALT);
hw->hw_qtd_next = EHCI_LIST_END(ehci);
ehci->async->qh_state = QH_STATE_LINKED;
hw->hw_alt_next = QTD_NEXT(ehci, ehci->async->dummy->qtd_dma);

为什么环头不能用真 QH？因为 EHCI 规范 4.8 节规定：从异步环上摘一个 QH，必须先把调度停掉再改指针。留一个哑头就能避免频繁停调度。

周期调度（Periodic Schedule）：跑 interrupt、isochronous。结构是一张帧链表数组，默认 1024 项（DEFAULT_I_TDPS），每项指向一个 QH、iTD、siTD 或 FSTN：

c
#define Q_TYPE_ITD  (0 << 1)
#define Q_TYPE_QH   (1 << 1)
#define Q_TYPE_SITD (2 << 1)
#define Q_TYPE_FSTN (3 << 1)

低两位是类型标签，这是硬件规定的编码。union ehci_shadow 就是软件侧的镜像，用来记「这一项当前指向谁」：

c
union ehci_shadow {
    struct ehci_qh   *qh;     /* Q_TYPE_QH */
    struct ehci_itd  *itd;    /* Q_TYPE_ITD */
    struct ehci_sitd *sitd;   /* Q_TYPE_SITD */
    struct ehci_fstn *fstn;   /* Q_TYPE_FSTN */
    __hc32           *hw_next;
    void             *ptr;
};

帧表大小可以缩：ehci_init() 里读 HCC_PGM_FRAMELISTLEN(hcc_params)，配合 EHCI_TUNE_FLS 在 1024/512/256 之间选。缩表是给老芯片省钱，现代控制器一律 1024。

QH（Queue Head）—— 端点级描述符。 一个 QH 代表一个端点，规范 3.6 节定义了它的硬件布局：

c
struct ehci_qh_hw {
    __hc32   hw_next;      /* EHCI 3.6.1 */
    __hc32   hw_info1;     /* EHCI 3.6.2 */
#define QH_CONTROL_EP  (1 << 27)   /* FS/LS control endpoint */
#define QH_HEAD        (1 << 15)   /* Head of async reclamation list */
#define QH_TOGGLE_CTL  (1 << 14)   /* Data toggle control */
#define QH_HIGH_SPEED  (2 << 12)   /* Endpoint speed */
#define QH_LOW_SPEED   (1 << 12)
#define QH_FULL_SPEED  (0 << 12)
#define QH_INACTIVATE  (1 << 7)    /* Inactivate on next transaction */
    __hc32   hw_info2;     /* EHCI 3.6.2 */
#define QH_SMASK   0x000000ff
#define QH_CMASK   0x0000ff00
#define QH_HUBADDR 0x007f0000
#define QH_HUBPORT 0x3f800000
#define QH_MULT    0xc0000000
    __hc32   hw_current;   /* qtd list - see EHCI 3.6.4 */

    /* qtd overlay (hardware parts of a struct ehci_qtd) */
    __hc32   hw_qtd_next;
    __hc32   hw_alt_next;
    __hc32   hw_token;
    __hc32   hw_buf[5];
    __hc32   hw_buf_hi[5];
} __aligned(32);

三个字段的含义值得单独拎出来：

  • hw_info1：端点号、设备地址、速度、最大包长、[Hub Addr/Port] 用于 TT 路由。QH_HEAD 位标记「异步环头」。
  • hw_info2：SMASK 是起始微帧位图，CMASK 是连续微帧位图，这俩决定周期传输落在哪些微帧上（高速一帧分 8 个 125 μs 的微帧）。MULT 是每微帧重复次数 1～3。
  • hw_current + 后面那 5 组 hw_qtd_* / hw_buf[]：这是硬件 overlay 区。硬件执行到这里时，会把正在执行的 qTD 内容拷进来，方便软件在 URB 运行中查询进度。

__aligned(32) 是硬性要求，QH 必须 32 字节对齐。同理 iTD、siTD、FSTN 也都要求对齐，dma_pool_create() 的第三个参数就是干这个的。

qTD（Queue Element Transfer Descriptor）—— 传输级描述符。 一个 URB 要拆成多个 qTD（因为 hw_buf[5] 只能描述 5 页）。规范 3.5 节：

c
struct ehci_qtd {
    /* first part defined by EHCI spec */
    __hc32   hw_next;        /* see EHCI 3.5.1 */
    __hc32   hw_alt_next;    /* see EHCI 3.5.2 */
    __hc32   hw_token;       /* see EHCI 3.5.3 */
#define QTD_TOGGLE  (1 << 31)      /* data toggle */
#define QTD_LENGTH(tok) (((tok)>>16) & 0x7fff)
#define QTD_IOC     (1 << 15)      /* interrupt on complete */
#define QTD_CERR(tok)   (((tok)>>10) & 0x3)
#define QTD_PID(tok)    (((tok)>>8) & 0x3)
#define QTD_STS_ACTIVE  (1 << 7)   /* HC may execute this */
#define QTD_STS_HALT    (1 << 6)   /* halted on error */
#define QTD_STS_DBE     (1 << 5)   /* data buffer error (in HC) */
#define QTD_STS_BABBLE  (1 << 4)   /* device was babbling (qtd halted) */
#define QTD_STS_XACT    (1 << 3)   /* device gave illegal response */
#define QTD_STS_MMF     (1 << 2)   /* incomplete split transaction */
#define QTD_STS_STS     (1 << 1)   /* split transaction state */
#define QTD_STS_PING    (1 << 0)   /* issue PING? */

    __hc32   hw_buf[5];      /* see EHCI 3.5.4 */
    __hc32   hw_buf_hi[5];   /* Appendix B */

    /* the rest is HCD-private */
    dma_addr_t      qtd_dma;    /* qtd address */
    struct list_head qtd_list;  /* sw qtd list */
    struct urb      *urb;       /* qtd's urb */
    size_t          length;     /* length of buffer */
} __aligned(32);

hw_token 是状态机核心：

位 名字 含义
31 QTD_TOGGLE DATA0 / DATA1 翻转位
30:16 — 剩余字节数（硬件递减）
15 QTD_IOC 完成后中断
14:12 — 预留
11:10 QTD_CERR 允许的重试次数
9:8 QTD_PID 0=OUT，1=IN，2=SETUP
7 QTD_STS_ACTIVE 硬件可以执行，软件写完要置这一位
6 QTD_STS_HALT 出错挂了
5 QTD_STS_DBE 数据缓冲错误
4 QTD_STS_BABBLE 设备话太多（超发）
3 QTD_STS_XACT 事务错误
2 QTD_STS_MMF split 事务中途丢了
1 QTD_STS_STS split 事务状态
0 QTD_STS_PING 需要发 PING

ACTIVE_BIT(ehci) / HALT_BIT(ehci) 这些宏是字节序安全的写法，用它别自己移位。

入队的真实路径。 ehci_urb_enqueue() 按管道类型四分叉：

c
static int ehci_urb_enqueue(struct usb_hcd *hcd, struct urb *urb, gfp_t mem_flags)
{
    struct ehci_hcd *ehci = hcd_to_ehci(hcd);
    struct list_head qtd_list;

    INIT_LIST_HEAD(&qtd_list);

    switch (usb_pipetype(urb->pipe)) {
    case PIPE_CONTROL:
        /* qh_completions() code doesn't handle all the fault cases
         * in multi-TD control transfers.  Even 1KB is rare anyway. */
        if (urb->transfer_buffer_length > (16 * 1024))
            return -EMSGSIZE;
        fallthrough;
    /* case PIPE_BULK: */
    default:
        if (!qh_urb_transaction(ehci, urb, &qtd_list, mem_flags))
            return -ENOMEM;
        return submit_async(ehci, urb, &qtd_list, mem_flags);

    case PIPE_INTERRUPT:
        if (!qh_urb_transaction(ehci, urb, &qtd_list, mem_flags))
            return -ENOMEM;
        return intr_submit(ehci, urb, &qtd_list, mem_flags);

    case PIPE_ISOCHRONOUS:
        if (urb->dev->speed == USB_SPEED_HIGH)
            return itd_submit(ehci, urb, mem_flags);
        else
            return sitd_submit(ehci, urb, mem_flags);
    }
}

三个要点：

  1. 控制传输单 URB 上限 16 KB，超过直接 -EMSGSIZE。这是 EHCI 驱动的限制，不是 USB 协议限制。
  2. control / bulk / interrupt 复用同一套 qh_urb_transaction()：把 URB 拆成 qTD 链，再按「异步还是周期」分别挂到 submit_async() 或 intr_submit()。
  3. 等时传输完全另一套：高速设备用 iTD（itd_submit），全速设备经 TT 用 siTD（sitd_submit），完全没有 QH 参与。所以 ehci_endpoint_disable() 里要靠 qh->hw == NULL 来判断这是不是一个等时流：
c
if (qh->hw == NULL) {
    struct ehci_iso_stream *stream = ep->hcpriv;
    if (!list_empty(&stream->td_list))
        goto idle_timeout;
    reserve_release_iso_bandwidth(ehci, stream, -1);
    kfree(stream);
    goto done;
}

QH 的生命周期。 一个 QH 有新、已链接、正在摘除、空闲五种状态：

c
#define QH_STATE_LINKED    1   /* HC sees this */
#define QH_STATE_UNLINK    2   /* HC may still see this */
#define QH_STATE_IDLE      3   /* HC doesn't see this */
#define QH_STATE_UNLINK_WAIT 4 /* LINKED and on unlink q */
#define QH_STATE_COMPLETING 5  /* don't touch token.HALT */

从 LINKED 到 IDLE 中间要经过 UNLINK 和一次 IAA（Interrupt on Async Advance）握手——这就是为什么要发 CMD_IAAD 命令、等 STS_IAA 中断。ehci_work() 在每次中断里扫一遍：

c
static void ehci_work(struct ehci_hcd *ehci)
{
    if (ehci->scanning) {
        ehci->need_rescan = true;
        return;
    }
    ehci->scanning = true;

 rescan:
    ehci->need_rescan = false;
    if (ehci->async_count)
        scan_async(ehci);
    if (ehci->intr_count > 0)
        scan_intr(ehci);
    if (ehci->isoc_count > 0)
        scan_isoc(ehci);
    if (ehci->need_rescan)
        goto rescan;
    ehci->scanning = false;

    turn_on_io_watchdog(ehci);
}

那个 scanning 标志防重入，need_rescan 防漏扫。最后那句 turn_on_io_watchdog() 是兜底：万一中断丢了，hrtimer 会替你补扫一遍。VT6202 和 VT8235 这两颗芯片当年就靠这个活着。

中断门限。 log2_irq_thresh 模块参数控制 INTT（Interrupt Threshold）字段，取值 0～6，对应 1～64 个微帧才中断一次。默认 0（每微帧）、调大到 3 能显著降低中断压力，代价是延迟。

十、DMA 与数据传输 #

控制器要把 CPU 内存里的数据搬到总线上，必然涉及 DMA。框架把这块抽象成三层。

第一层：uses_dma 与 HCD_DMA。 两个都成立才真的走 DMA：

c
static inline bool hcd_uses_dma(struct usb_hcd *hcd)
{
    return IS_ENABLED(CONFIG_HAS_DMA) && (hcd->driver->flags & HCD_DMA);
}

uses_dma 那个字段（hcd->self.uses_dma）是另一回事，它决定 core 层要不要给设备做 dma_mask 的假定。

第二层：map_urb_for_dma() / unmap_urb_for_dma()。 这是默认实现，你的驱动没覆盖 hc_driver->map_urb_for_dma 时就用它：

c
int usb_hcd_map_urb_for_dma(struct usb_hcd *hcd, struct urb *urb, gfp_t mem_flags)
{
    enum dma_data_direction dir;
    int ret = 0;

    if (usb_endpoint_xfer_control(&urb->ep->desc)) {
        if (hcd->self.uses_pio_for_control)
            return ret;
        if (hcd->localmem_pool) {
            ret = hcd_alloc_coherent(urb->dev->bus, mem_flags,
                    &urb->setup_dma, (void **)&urb->setup_packet,
                    sizeof(struct usb_ctrlrequest), DMA_TO_DEVICE);
            if (ret)
                return ret;
            urb->transfer_flags |= URB_SETUP_MAP_LOCAL;
        } else if (hcd_uses_dma(hcd)) {
            if (object_is_on_stack(urb->setup_packet)) {
                WARN_ONCE(1, "setup packet is on stack\n");
                return -EAGAIN;
            }
            urb->setup_dma = dma_map_single(hcd->self.sysdev,
                    urb->setup_packet, sizeof(struct usb_ctrlrequest),
                    DMA_TO_DEVICE);
            if (dma_mapping_error(hcd->self.sysdev, urb->setup_dma))
                return -EAGAIN;
            urb->transfer_flags |= URB_SETUP_MAP_SINGLE;
        }
    }
    /* ... 数据缓冲区同理，分 SG / page / single / local 四种 ... */
    return ret;
}

三条实用结论：

  • urb->setup_packet 和 urb->transfer_buffer 都不能在栈上。内核用 object_is_on_stack() 检查，抓到了就 WARN_ONCE 加 -EAGAIN。usb_control_msg() 里那个 struct usb_ctrlrequest *dr 是 kmalloc 出来的，不是栈变量，原因就在这里。
  • 数据缓冲区分支有四条：num_sgs > 0 走 dma_map_sg，sg != NULL 走 dma_map_page，普通缓冲走 dma_map_single，localmem_pool 存在则走 hcd_alloc_coherent 做 bounce buffer。
  • 等时传输不支持 SG。if (usb_endpoint_xfer_isoc(&urb->ep->desc)) { WARN_ON(1); return -EINVAL; }。

第三层：localmem_pool，只能访问片内 SRAM 的控制器。 有些 SoC 的 USB 控制器 DMA 地址范围只覆盖一小块 SRAM（典型是 dwc2 的某些配置）。usb_hcd_setup_local_mem() 把这块内存注册成 gen_pool，之后所有 URB 缓冲都从里面分配，hcd_alloc_coherent() 负责「分配 + 拷贝进去 + 在尾部藏原始虚拟地址」：

c
static int hcd_alloc_coherent(struct usb_bus *bus, gfp_t mem_flags,
        dma_addr_t *dma_handle, void **vaddr_handle, size_t size,
        enum dma_data_direction dir)
{
    unsigned char *vaddr;

    if (*vaddr_handle == NULL) {
        WARN_ON_ONCE(1);
        return -EFAULT;
    }

    vaddr = hcd_buffer_alloc(bus, size + sizeof(unsigned long), mem_flags, dma_handle);
    if (!vaddr)
        return -ENOMEM;

    /* Store the virtual address of the buffer at the end of the allocated
     * dma buffer. */
    put_unaligned((unsigned long)*vaddr_handle, (unsigned long *)(vaddr + size));

    if (dir == DMA_TO_DEVICE)
        memcpy(vaddr, *vaddr_handle, size);

    *vaddr_handle = vaddr;
    return 0;
}

解开时从尾部取回原指针，DMA_FROM_DEVICE 方向再拷回来。这就是标准的 bounce buffer 做法。

第四层：hcd_buffer_* 与 4 个 DMA 池。 hcd_buffer_create() 在 usb_add_hcd() 第 3 步被调用，建 4 个 dma_pool（HCD_BUFFER_POOLS = 4），分别对应 128、512、1024、2048 字节的常用尺寸。usb_buffer_alloc() / usb_alloc_coherent() 最终落到 hcd_buffer_alloc()，先试 4 个池，都不合适再退回 dma_alloc_coherent()。

为什么要有这个池？因为 USB 设备驱动申请缓冲区非常频繁（每个 URB 一个），dma_alloc_coherent() 每次都要拿页、建映射，太贵。池化之后是 O(1) 摘链。

地址宽度的坑。 EHCI 的 run() 里有一段 64 位地址处理：

c
hcc_params = ehci_readl(ehci, &ehci->caps->hcc_params);
if (HCC_64BIT_ADDR(hcc_params)) {
    ehci_writel(ehci, 0, &ehci->regs->segment);
#if 0
// this is deeply broken on almost all architectures
    if (!dma_set_mask(hcd->self.controller, DMA_BIT_MASK(64)))
        ehci_info(ehci, "enabled 64bit DMA\n");
#endif
}

那段 #if 0 保留了十几年，注释写着「this is deeply broken on almost all architectures」。含义：EHCI 的数据结构（QH/qTD/iTD）地址必须落在 4 GB 以下，dma_pool 分配的一致性内存天然在段 0，没问题；但 URB 的数据缓冲区用 dma_map_single() 映射时会落到 4 GB 以上，此时必须靠 hcd->localmem_pool 或 bounce buffer。手册里对 SEGMENT 寄存器的描述是「约束 QH/ITD/SITD 和 QTD 的位置」，源码注释把这个坑说清楚了：

text
* hcc_params controls whether ehci->regs->segment must (!!!) be used;
* it constrains QH/ITD/SITD and QTD locations. dma_pool consistent
* memory always uses segment zero. streaming mappings for I/O buffers,
* like dma_map_single(), can return segments above 4GB, if the device allows.

sg_tablesize。 EHCI 在 ehci_init() 里干了一件很皮的事：

c
/* Accept arbitrarily long scatter-gather lists */
if (!hcd->localmem_pool)
    hcd->self.sg_tablesize = ~0;

~0 意思是「爱多长多长」，因为 EHCI 的 qTD 自己会拆页，不依赖 SG。反过来 OHCI 就得设一个实际上限。

PIO 模式。 极少数老控制器控制传输不用 DMA（hcd->self.uses_pio_for_control = 1），此时 usb_hcd_map_urb_for_dma() 直接返回 0 不映射，由驱动自己 memcpy 到寄存器 FIFO。现代硬件上基本见不到。

十一、中断处理 #

中断上半部只有一个职责：看硬件说了什么，把活记下来，尽快退出来。硬件层的重活（扫描 QH 链、归还 URB）在 ehci_work() 里做，但它也在中断上下文里，所以还是不能睡。

EHCI 的 ehci_irq() 是教科书级的实现：

c
static irqreturn_t ehci_irq(struct usb_hcd *hcd)
{
    struct ehci_hcd *ehci = hcd_to_ehci(hcd);
    u32 status, current_status, masked_status, pcd_status = 0;
    u32 cmd;
    int bh;

    spin_lock(&ehci->lock);

    status = 0;
    current_status = ehci_readl(ehci, &ehci->regs->status);
restart:

    /* e.g. cardbus physical eject */
    if (current_status == ~(u32) 0) {
        ehci_dbg(ehci, "device removed\n");
        goto dead;
    }
    status |= current_status;

    masked_status = current_status & (INTR_MASK | STS_FLR);

    /* Shared IRQ? */
    if (!masked_status || unlikely(ehci->rh_state == EHCI_RH_HALTED)) {
        spin_unlock(&ehci->lock);
        return IRQ_NONE;
    }

    /* clear (just) interrupts */
    ehci_writel(ehci, masked_status, &ehci->regs->status);

    /* For edge interrupts, don't race with an interrupt bit being raised */
    current_status = ehci_readl(ehci, &ehci->regs->status);
    if (current_status & INTR_MASK)
        goto restart;
    /* ... 分发 STS_INT / STS_ERR / STS_IAA / STS_PCD / STS_FATAL ... */
}

四个必须学会的招式：

  1. 共享中断要认门。masked_status 为空就 return IRQ_NONE，让内核去问下一个 handler。IRQF_SHARED 是所有 HCD 都用的标志。
  2. 写 1 清零，写回读到的位。ehci_writel(ehci, masked_status, &ehci->regs->status)，只清你处理的那几位。
  3. 边沿型中断要重读。清完再读一次，还有新位就 goto restart，否则漏中断。
  4. 全 1 意味着硬件被拔了。current_status == ~(u32)0 直接走下电流程，这是 CardBus 热拔的经典检测。

分发之后，状态位对应不同动作：

状态位 含义 动作
STS_INT 事务完成 标记需要扫链（bh = 1）
STS_ERR 事务出错 同上，并强制查端口状态
STS_IAA 异步调度推进（QH 已可安全摘除） end_iaa_cycle()
STS_PCD 端口状态变化 记下来，中断尾调 usb_hcd_poll_rh_status()
STS_FATAL 灾难性错误 usb_hc_died() + 关控制器
STS_FLR 帧列表回绕 只清不处理

注意 STS_PCD 的处理：pcd_status 先存着，spin_unlock 之后再调 usb_hcd_poll_rh_status(hcd)。这是有意的——poll_rh_status 会拿 hcd_root_hub_lock，在锁里嵌套调它容易死锁。

STS_FATAL 走的是控制器死亡流程：

c
dead:
    usb_hc_died(hcd);
    /* Don't let the controller do anything more */
    ehci->shutdown = true;
    ehci->rh_state = EHCI_RH_STOPPING;
    ehci->command &= ~(CMD_RUN | CMD_ASE | CMD_PSE);
    ehci_writel(ehci, ehci->command, &ehci->regs->command);
    ehci_writel(ehci, 0, &ehci->regs->intr_enable);
    ehci_handle_controller_death(ehci);

usb_hc_died() 会把 HCD_FLAG_DEAD 置起来，挂上 died_work，然后所有在传输中的 URB 都会以 -ESHUTDOWN 完成。设备驱动看到的错误码就是这个。

中断下半部。 ehci_work() 里逐个 QH 调用 qh_completions()，最终走到 usb_hcd_giveback_urb()。因为 EHCI 的 flags 里有 HCD_BH，URB 完成回调被推迟到 system_bh_wq 的 workqueue 里执行。

没有中断的控制器怎么活？ 三条路：

  • rh_timer 定时轮询根集线器（老机制）；
  • EHCI 的 need_io_watchdog + hrtimer，中断丢了也能扫；
  • xHCI 的事件环超时检测（xhci_hcd 有自己的 watchdog）。

中断申请的时机。 usb_add_hcd() 第 9 步，在 driver->start() 之前：

c
/* enable irqs just before we start the controller,
 * if the BIOS provides legacy PCI irqs. */
if (usb_hcd_is_primary_hcd(hcd) && irqnum) {
    retval = usb_hcd_request_irqs(hcd, irqnum, irqflags);
    if (retval)
        goto err_request_irq;
}

先申请再启动，是为了 start() 里万一立刻来中断也有 handler 接着。共享 HCD（shared_hcd）不申请，因为主从两个 usb_hcd 共用一条中断线。

xhci 的中断是自己管的，usb_hcd_pci_probe() 里有显式判断：

c
/*
 * The xHCI driver has its own irq management
 * make sure irq setup is not touched for xhci in generic hcd code
 */
if ((driver->flags & HCD_MASK) < HCD_USB3) {
    retval = pci_alloc_irq_vectors(dev, 1, 1, PCI_IRQ_INTX | PCI_IRQ_MSI);
    if (retval < 0) {
        dev_err(&dev->dev, "Found HC with no IRQ. Check BIOS/PCI %s setup!\n",
            pci_name(dev));
        retval = -ENODEV;
        goto disable_pci;
    }
    hcd_irq = pci_irq_vector(dev, 0);
}

HCD_USB3（0x0040）及以上不走进这段，hcd_irq 保持 0，usb_add_hcd() 里 irqnum 为 0 也就不申请。xhci 自己走 MSI-X 多向量。

十二、电源管理与挂起恢复 #

USB 的电源管理分两个层级，别混：

  • 总线级（bus suspend / resume）：整条 USB 总线挂起，hc_driver->bus_suspend / bus_resume 负责，只影响根集线器；
  • 控制器级（PCI suspend / resume）：控制器本身进 D3，hc_driver->pci_suspend / pci_resume 负责。

hcd-pci.c 把这两层串起来：

c
static int suspend_common(struct device *dev, pm_message_t msg)
{
    struct pci_dev *pci_dev = to_pci_dev(dev);
    struct usb_hcd *hcd = pci_get_drvdata(pci_dev);
    bool do_wakeup;
    int retval;

    do_wakeup = PMSG_IS_AUTO(msg) ? true : device_may_wakeup(dev);

    /* Root hub suspend should have stopped all downstream traffic,
     * and all bus master traffic. */
    retval = check_root_hub_suspended(dev);
    if (retval)
        return retval;

    if (hcd->driver->pci_suspend && !HCD_DEAD(hcd)) {
        /* Optimization: Don't suspend if a root-hub wakeup is
         * pending and it would cause the HCD to wake up anyway. */
        if (do_wakeup && HCD_WAKEUP_PENDING(hcd))
            return -EBUSY;
        if (do_wakeup && hcd->shared_hcd && HCD_WAKEUP_PENDING(hcd->shared_hcd))
            return -EBUSY;
        retval = hcd->driver->pci_suspend(hcd, do_wakeup);

        /* Check again in case wakeup raced with pci_suspend */
        if ((retval == 0 && do_wakeup && HCD_WAKEUP_PENDING(hcd)) ||
                (retval == 0 && do_wakeup && hcd->shared_hcd &&
                 HCD_WAKEUP_PENDING(hcd->shared_hcd))) {
            if (hcd->driver->pci_resume)
                hcd->driver->pci_resume(hcd, msg);
            retval = -EBUSY;
        }
        if (retval)
            return retval;
    }

    if (!hcd->msix_enabled)
        synchronize_irq(pci_irq_vector(pci_dev, 0));

    pci_disable_device(pci_dev);
    return retval;
}

这里的「查两遍 HCD_WAKEUP_PENDING」是个模式：挂起过程中远端设备刚好唤醒，发现这种情况就得回滚。写自己的 pci_suspend 时要配合这个约定——返回 0 表示真的挂起了。

hcd->msix_enabled 那个分支也有意思：MSI-X 由驱动自己在 pci_suspend 里同步所有向量，非 MSI-X 由 core 在这里 synchronize_irq()。

恢复路径是镜像的，但有个 EHCI 专属细节：

c
static int resume_common(struct device *dev, pm_message_t msg)
{
    ...
    if (hcd->driver->pci_resume && !HCD_DEAD(hcd)) {
        /*
         * Only EHCI controllers have to wait for their companions.
         */
        if (pci_dev->class == CL_EHCI && msg.event != PM_EVENT_AUTO_RESUME)
            for_each_companion(pci_dev, hcd, ehci_wait_for_companions);

        retval = hcd->driver->pci_resume(hcd, msg);
        if (retval) {
            dev_err(dev, "PCI post-resume error %d!\n", retval);
            usb_hc_died(hcd);
        }
    }
    return retval;
}

ehci_wait_for_companions() 等 companion 控制器（OHCI/UHCI）先恢复完，EHCI 才能抢端口。pci_resume 返回非 0 就直接判控制器死亡，很硬。

ehci_suspend() 干的事：

c
int ehci_suspend(struct usb_hcd *hcd, bool do_wakeup)
{
    struct ehci_hcd *ehci = hcd_to_ehci(hcd);

    if (time_before(jiffies, ehci->next_statechange))
        msleep(10);

    /*
     * Root hub was already suspended.  Disable IRQ emission and
     * mark HW unaccessible.
     */
    ehci_prepare_ports_for_controller_suspend(ehci, do_wakeup);

    spin_lock_irq(&ehci->lock);
    ehci_writel(ehci, 0, &ehci->regs->intr_enable);
    (void) ehci_readl(ehci, &ehci->regs->intr_enable);

    clear_bit(HCD_FLAG_HW_ACCESSIBLE, &hcd->flags);
    spin_unlock_irq(&ehci->lock);

    synchronize_irq(hcd->irq);

    /* Check for race with a wakeup request */
    if (do_wakeup && HCD_WAKEUP_PENDING(hcd)) {
        ehci_resume(hcd, false);
        return -EBUSY;
    }
    return 0;
}

四步：改端口唤醒标志 → 关中断使能并 clear_bit(HCD_FLAG_HW_ACCESSIBLE)（告诉框架「别再碰我的寄存器」）→ synchronize_irq() 等正在进行的中断跑完 → 复查有没有竞态。

HCD_FLAG_HW_ACCESSIBLE 这个位很关键，HCD_HW_ACCESSIBLE(hcd) 宏被广泛用于「发寄存器读之前先确认硬件还在」。你自己写 PM 回调时必须同样维护它。

ehci_resume() 的分岔：

c
if (ehci_readl(ehci, &ehci->regs->configured_flag) == FLAG_CF && !force_reset) {
    /* 供电没丢，只恢复中断使能 */
    ...
    return 0;
}
/* 供电丢了或者从休眠恢复：当成刚上电，全部重来 */
usb_root_hub_lost_power(hcd->self.root_hub);
(void) ehci_halt(ehci);
(void) ehci_reset(ehci);
...
return 1;

返回值 0 表示「电源保住了」，1 表示「掉电了」。usb_root_hub_lost_power() 会把根集线器下所有设备标记为断开，重新枚举。

远端唤醒（Remote Wakeup）。 设备在挂起状态下拉 D+/D- 表示要唤醒，控制器检测到后在 PORTSC 里置 PORT_CSC / PORT_RESUME 位，ehci_irq() 里 STS_PCD 分支会处理：

c
ehci->reset_done[i] = jiffies + msecs_to_jiffies(USB_RESUME_TIMEOUT);
set_bit(i, &ehci->resuming_ports);
ehci_dbg(ehci, "port %d remote wakeup\n", i + 1);
usb_hcd_start_port_resume(&hcd->self, i);
mod_timer(&hcd->rh_timer, ehci->reset_done[i]);

usb_hcd_start_port_resume() 会临时给根集线器加一次 runtime PM 引用，防止恢复过程中它自己又被自动挂起；usb_hcd_end_port_resume() 在 hub_wq 收尾时配对调用。

cant_recv_wakeups 与 amd_resume_bug。 两个历史怪癖位：

  • cant_recv_wakeups：某些控制器收不到下游唤醒请求；
  • amd_resume_bug：AMD 芯片组的远端唤醒 bug，由 usb_hcd_amd_resume_bug() 判断，条件是 HCD_USB11 | HCD_USB3 这类控制器。

pci_poweroff_late 是 5.x 加进来的回调，专门给休眠（hibernation）用，在进入最终 D3 状态之前让驱动有机会关掉部分硬件。素材里没有，6.12 有：

c
static int hcd_pci_poweroff_late(struct device *dev)
{
    struct pci_dev *pci_dev = to_pci_dev(dev);
    struct usb_hcd *hcd = pci_get_drvdata(pci_dev);

    if (hcd->driver->pci_poweroff_late && !HCD_DEAD(hcd))
        return hcd->driver->pci_poweroff_late(hcd, device_may_wakeup(dev));

    return 0;
}

runtime PM 走的是另一对钩子：

c
static int hcd_pci_runtime_suspend(struct device *dev)
{
    int retval = suspend_common(dev, PMSG_AUTO_SUSPEND);
    if (retval == 0)
        powermac_set_asic(to_pci_dev(dev), 0);
    return retval;
}

PMSG_IS_AUTO(msg) 为真时 do_wakeup 强制为 true——自动挂起时默认允许唤醒，否则 USB 键鼠就没法唤醒系统了。

十三、PCI 与 platform 两种挂载方式 #

同一份 HCD 逻辑，硬件要么挂在 PCI 总线上（南桥、扩展卡），要么直接挂在 platform 总线上（SoC 片内）。内核用两个「总线胶水层」把这两种情况分开，hc_driver 那部分代码完全复用。

PCI 方式：usb_hcd_pci_probe()。 这个函数是 PCI 胶水的全部，流程如下：

c
int usb_hcd_pci_probe(struct pci_dev *dev, const struct hc_driver *driver)
{
    struct usb_hcd  *hcd;
    int             retval;
    int             hcd_irq = 0;

    if (usb_disabled())
        return -ENODEV;
    if (!driver)
        return -EINVAL;
    if (pci_enable_device(dev) < 0)
        return -ENODEV;

    /*
     * The xHCI driver has its own irq management
     * make sure irq setup is not touched for xhci in generic hcd code
     */
    if ((driver->flags & HCD_MASK) < HCD_USB3) {
        retval = pci_alloc_irq_vectors(dev, 1, 1, PCI_IRQ_INTX | PCI_IRQ_MSI);
        if (retval < 0) {
            dev_err(&dev->dev, "Found HC with no IRQ. Check BIOS/PCI %s setup!\n",
                pci_name(dev));
            retval = -ENODEV;
            goto disable_pci;
        }
        hcd_irq = pci_irq_vector(dev, 0);
    }

    hcd = usb_create_hcd(driver, &dev->dev, pci_name(dev));
    if (!hcd) {
        retval = -ENOMEM;
        goto free_irq_vectors;
    }

    hcd->amd_resume_bug = usb_hcd_amd_resume_bug(dev, driver);

    /* ... HCD_MEMORY 分支映射 BAR0，否则找 I/O BAR，见第七章 ... */

    pci_set_master(dev);

    /* Note: dev_set_drvdata must be called while holding the rwsem */
    if (dev->class == CL_EHCI) {
        down_write(&companions_rwsem);
        dev_set_drvdata(&dev->dev, hcd);
        for_each_companion(dev, hcd, ehci_pre_add);
        retval = usb_add_hcd(hcd, hcd_irq, IRQF_SHARED);
        if (retval != 0)
            dev_set_drvdata(&dev->dev, NULL);
        for_each_companion(dev, hcd, ehci_post_add);
        up_write(&companions_rwsem);
    } else {
        down_read(&companions_rwsem);
        dev_set_drvdata(&dev->dev, hcd);
        retval = usb_add_hcd(hcd, hcd_irq, IRQF_SHARED);
        if (retval != 0)
            dev_set_drvdata(&dev->dev, NULL);
        else
            for_each_companion(dev, hcd, non_ehci_add);
        up_read(&companions_rwsem);
    }

    if (retval != 0)
        goto put_hcd;
    device_wakeup_enable(hcd->self.controller);

    if (pci_dev_run_wake(dev))
        pm_runtime_put_noidle(&dev->dev);
    return retval;

put_hcd:
    usb_put_hcd(hcd);
free_irq_vectors:
    if ((driver->flags & HCD_MASK) < HCD_USB3)
        pci_free_irq_vectors(dev);
disable_pci:
    pci_disable_device(dev);
    dev_err(&dev->dev, "init %s fail, %d\n", pci_name(dev), retval);
    return retval;
}

版本变化（必须标）：素材里写的是 usb_hcd_pci_probe(struct pci_dev *dev, const struct pci_device_id *id) 配合 (const struct hc_driver *) id->driver_data 强转，这是 4.x～5.x 早期（大约 4.18 之前）的老签名。5.x 中期改成直接传 const struct hc_driver *driver。6.12 确认是新签名。区分方法很简单：看调用处是 usb_hcd_pci_probe(dev, id) 还是 usb_hcd_pci_probe(dev, &ehci_pci_hc_driver)。

注意几个细节：

  • pci_alloc_irq_vectors(dev, 1, 1, ...)：只要 1 个向量，允许 INTx 或 MSI，不允许 MSI-X（MSI-X 留给 xHCI 自己管）。
  • IRQF_SHARED：所有 HCD 都用共享中断，因为 PCI INTx 天然共享。
  • companions_rwsem 的读写锁：EHCI 加 down_write，其他加 down_read。这样 EHCI 挂载期间不会有新的 companion 并发加入。
  • for_each_companion() 只扫同槽位的其他 function：PCI_SLOT(companion->devfn) != slot 就跳过。这是 PCI 多功能设备（一颗芯片里 OHCI+EHCI）的识别方式。

platform 方式：自己写 probe。 没有 PCI 帮手，usb_create_hcd()、ioremap、usb_add_hcd() 都得自己调。模板就是第七章那份 ohci_hcd_s3c2410_probe()。struct 挂法也是标准 platform_driver：

c
static struct platform_driver ohci_hcd_s3c2410_driver = {
    .probe    = ohci_hcd_s3c2410_probe,
    .remove   = ohci_hcd_s3c2410_remove,
    .shutdown = usb_hcd_platform_shutdown,
    .driver   = {
        .name = "s3c2410-ohci",
        .pm   = &ohci_hcd_s3c2410_pm_ops,
        .of_match_table = ohci_hcd_s3c2410_dt_ids,
    },
};

usb_hcd_platform_shutdown() 是所有 platform HCD 共用的 shutdown 实现，别自己写。它的逻辑是：拿 drvdata → 调 hcd->driver->shutdown(hcd) → usb_put_hcd()。

SoC 驱动多数只覆盖两个回调。 S3C2410 的 ohci_s3c2410_init() 里那段注释值得抄下来：

c
static int __init ohci_s3c2410_init(void)
{
    if (usb_disabled())
        return -ENODEV;

    pr_info("%s: " DRIVER_DESC "\n", hcd_name);
    ohci_init_driver(&ohci_s3c2410_hc_driver, NULL);

    /*
     * The Samsung HW has some unusual quirks, which require
     * Sumsung-specific workarounds. We override certain hc_driver
     * functions here to achieve that. We explicitly do not enhance
     * ohci_driver_overrides to allow this more easily, since this
     * is an unusual case, and we don't want to encourage others to
     * override these functions by making it too easy.
     */
    ohci_s3c2410_hc_driver.hub_status_data  = ohci_s3c2410_hub_status_data;
    ohci_s3c2410_hc_driver.hub_control      = ohci_s3c2410_hub_control;

    return platform_driver_register(&ohci_hcd_s3c2410_driver);
}

模式是「先复制通用模板，再盖掉个别回调」。ohci_init_driver() / ehci_init_driver() 做的就是 *drv = ohci_hc_driver;。EHCI 那边的覆盖入口更正规一点：

c
struct ehci_driver_overrides {
    size_t  extra_priv_size;
    int     (*reset)(struct usb_hcd *hcd);
    int     (*port_power)(struct usb_hcd *hcd, int portnum, bool enable);
};

void ehci_init_driver(struct hc_driver *drv, const struct ehci_driver_overrides *over)
{
    /* Copy the generic table to drv and then apply the overrides */
    *drv = ehci_hc_driver;

    if (over) {
        drv->hcd_priv_size += over->extra_priv_size;
        if (over->reset)
            drv->reset = over->reset;
        if (over->port_power)
            drv->port_power = over->port_power;
    }
}

extra_priv_size 是在通用 struct ehci_hcd 后面追加私有字段的机制，hcd_priv_size 自动累加。

两种挂法的对照：

维度 PCI 挂载 platform 挂载
probe 入口 usb_hcd_pci_probe() 自己写
寄存器映射 胶水层做（BAR0 或 I/O BAR） 自己 devm_ioremap_resource()
时钟 无需 devm_clk_get + enable
中断号 pci_irq_vector(dev, 0) platform_get_irq() 或资源数组
电源 标准 PCI PM 自定义 dev_pm_ops
companion 协调 胶水层自动 不需要（SoC 不会配 companion）
设备发现 PCI 枚举 设备树 / 板级代码静态定义
shutdown usb_hcd_pci_shutdown() usb_hcd_platform_shutdown()

板级设备注册的老写法。 S3C2440 那份是 arch/arm/mach-s3c24xx/ 里的静态描述：

c
static struct resource s3c_usb_resource[] = {
    [0] = DEFINE_RES_MEM(S3C_PA_USBHOST, SZ_256),   /* 0x49000000, 256 字节 */
    [1] = DEFINE_RES_IRQ(IRQ_USBH),
};

struct platform_device s3c_device_ohci = {
    .name          = "s3c2410-ohci",
    .id            = -1,
    .num_resources = ARRAY_SIZE(s3c_usb_resource),
    .resource      = s3c_usb_resource,
    .dev           = {
        .dma_mask          = &samsung_device_dma_mask,
        .coherent_dma_mask = DMA_BIT_MASK(32),
    }
};

然后 smdk2440_machine_init() 里 platform_add_devices(smdk2440_devices, ARRAY_SIZE(smdk2440_devices)) 一次性注册。这套「board file 硬编码」的写法在 4.x 之后被设备树逐步取代，mach-s3c24xx 目录本身也在 5.x 后期被删了。现在只有老内核或维护分支上还能看到。

platform_data 的传递。 s3c_ohci_set_platdata() 里面是 kmemdup() 一份拷贝再挂到 pdev->dev.platform_data：

c
void __init *s3c_set_platdata(void *pd, size_t pdsize,
                              struct platform_device *pdev)
{
    void *npd;

    if (!pd) {
        /* too early to use dev_name(), may not be registered */
        printk(KERN_ERR "%s: no platform data supplied\n", pdev->name);
        return NULL;
    }

    npd = kmemdup(pd, pdsize, GFP_KERNEL);
    if (!npd)
        return NULL;

    pdev->dev.platform_data = npd;
    return npd;
}

kmemdup 而不是直接赋值，是为了让原始结构体能标 __initdata 被回收。这是 Linux 2.6 时代的老约定，新代码里对应的是设备树属性和 device_property_read_*()。

十四、设备树里的 USB 控制器节点 #

现代 SoC 上，USB 控制器通过设备树描述。一个典型的 EHCI/OHCI 组合节点长这样：

text
usb@1c13000 {
    compatible = "allwinner,sun4i-a10-ehci", "generic-ehci";
    reg = <0x01c13000 0x1000>;
    interrupts = <38>;
    clocks = <&ahb_gates 0>, <&usb_clk 0>;
    clock-names = "ahb", "mod";
    phys = <&usbphy 0>;
    phy-names = "usb";
    resets = <&usb_clk 0>;
    reset-names = "ahb";
    status = "disabled";
};

usb@1c13400 {
    compatible = "allwinner,sun4i-a10-ohci", "generic-ohci";
    reg = <0x01c13400 0x100>;
    interrupts = <39>;
    clocks = <&ahb_gates 0>, <&usb_clk 0>;
    clock-names = "ahb", "mod";
    phys = <&usbphy 0>;
    phy-names = "usb";
    resets = <&usb_clk 0>;
    reset-names = "ahb";
    status = "disabled";
};

compatible 里多写两个值：一个是厂商私有（allwinner,sun4i-a10-ehci），一个是通用兜底（generic-ehci）。驱动 of_match_table 里两个都列，私有那个匹配上了可以挂自己的 quirk 表。

属性含义：

属性 内容 驱动怎么用
reg 寄存器物理基址 + 长度 platform_get_resource() / devm_ioremap_resource()
interrupts 中断号 platform_get_irq()
clocks / clock-names 时钟句柄与名字 devm_clk_get(dev, "ahb")
phys / phy-names PHY 句柄 devm_phy_get()，或交给 usb_phy 框架
resets / reset-names 复位控制器 devm_reset_control_get()
status okay / disabled 决定是否 probe
dr_mode host / peripheral / otg 双角色控制器据此选模式
vbus-supply VBUS 稳压器 devm_regulator_get()

dr_mode 与双角色控制器。 dwc2、dwc3、musb 这类控制器一个硬件既能当主控也能当从设备，靠 dr_mode 决定。当 host 用的时候，驱动在 probe 里判断：

c
switch (usb_get_dr_mode(&pdev->dev)) {
case USB_DR_MODE_HOST:
    /* 走 host 路径，最后调 usb_add_hcd() */
    break;
case USB_DR_MODE_PERIPHERAL:
    /* 走 gadget 路径 */
    break;
case USB_DR_MODE_OTG:
    /* 注册 OTG，运行时切换 */
    break;
}

usb_get_dr_mode() 是 4.x 引入的帮手，读 dr_mode 属性，缺省值是 USB_DR_MODE_OTG。

usb_hcd 与设备树节点的关联。 usb_create_hcd(driver, &pdev->dev, bus_name) 把 dev 存进 hcd->self.controller，usb_alloc_dev() 里又有这么一句：

c
dev->dev.parent = bus->controller;
device_set_of_node_from_dev(&dev->dev, bus->sysdev);

根集线器的 of_node 直接继承控制器节点的，所以 /sys/devices/platform/soc/.../usb@1c13000/usb1/ 下能顺着 of_node 找到原节点。

phys 的处理。 老写法是驱动自己 devm_phy_get() 再 phy_init() / phy_power_on()；新写法是交给 usb_phy_roothub 那套（usb_add_hcd() 第 1 步调的就是它）。如果你的控制器 PHY 只有在特定事件后才能上电，就设 hcd->skip_phy_initialization = 1，让框架别管。

设备树里标 status = "disabled" 的节点经常坑人。 板级 dts 忘了 status = "okay" 覆盖，结果驱动根本不 probe，dmesg 里连一行日志都没有。查这个用：

bash
# 看节点是否被标记为可用
$ find /proc/device-tree -name 'usb@*' -type d
$ cat /proc/device-tree/soc/usb@1c13000/status

十五、调试手段与常见故障 #

1. 先看有没有注册成功。 正确加载的控制器必然有这几行：

bash
$ dmesg | grep -iE 'hcd|usb.*new .*bus'
[    1.234567] ehci-pci 0000:00:1d.7: EHCI Host Controller
[    1.234567] ehci-pci 0000:00:1d.7: new USB bus registered, assigned bus number 1
[    1.234567] ehci-pci 0000:00:1d.7: USB 2.0 started, EHCI 1.00
[    1.234567] usb usb1: New USB device found, idVendor=1d6b, idProduct=0002

缺哪行就知道卡在哪一步：

缺的日志 卡在
EHCI Host Controller（product_desc） usb_add_hcd() 之前，先查 ioremap 与时钟
new USB bus registered, assigned bus number N usb_register_bus() 失败，或 reset() 失败
USB 2.0 started driver->start() 失败
New USB device found register_root_hub() 失败，枚举没走通

2. debugfs 是主战场。 EHCI 驱动开了 CONFIG_DYNAMIC_DEBUG 就在 usb_debug_root 下面建 ehci/ 目录：

bash
$ mount -t debugfs none /sys/kernel/debug
$ ls /sys/kernel/debug/ehci/
$ cat /sys/kernel/debug/ehci/0000:00:1d.7/async
$ cat /sys/kernel/debug/ehci/0000:00:1d.7/periodic
$ cat /sys/kernel/debug/ehci/0000:00:1d.7/registers
$ cat /sys/kernel/debug/ehci/0000:00:1d.7/bandwidth

bandwidth 那张表告诉你每个微帧用了多少微秒，超过 100 就会看到调度失败。USB 2.0 规范允许每微帧最多 80%（100 μs）的周期带宽，ehci_init() 里 ehci->uframe_periodic_max = 100; 就是这条。

3. 动态调试打开驱动日志。 ehci_dbg() / ehci_err() 这些宏走 dev_dbg()，默认不打印：

bash
$ echo 'module ehci_hcd +p' > /sys/kernel/debug/dynamic_debug/control
# 或者只开某个函数的
$ echo 'func ehci_urb_enqueue +p' > /sys/kernel/debug/dynamic_debug/control

4. usbmon 抓包。 不管哪个控制器，URB 级别都能抓：

bash
$ mount -t debugfs none /sys/kernel/debug
$ cat /sys/kernel/debug/usb/usbmon/0u     # 抓所有总线
$ cat /sys/kernel/debug/usb/usbmon/1u     # 只抓 bus 1

mon_ops 那几个钩子（urb_submit / urb_complete）就在 usb_hcd_submit_urb() 和 __usb_hcd_giveback_urb() 里调，所以能看到 URB 进出的完整时间线。

5. 寄存器直读。

bash
# 看 EHCI 的 capability 区
$ devmem 0xfe3b0000 32
# 看 status 寄存器（cap 长度后 0x04）
$ devmem 0xfe3b0044 32

devmem 只读不写，写寄存器很容易把控制器搞死，别在量产设备上试。

十六、易错点速查 #

# 坑 后果 正确做法
1 reset 被当成「复位硬件」实现 重复复位导致挂载失败 它是一次性初始化；硬件复位自己做
2 urb_enqueue 返回 0 却没调 giveback URB 泄漏，设备驱动永远等下去 返回 0 就必须最终 giveback
3 忘记 usb_hcd_link_urb_to_ep() usb_kill_urb() 杀不掉 URB 入队第一件事就调它
4 先 giveback 再 unlink_urb_from_ep 竞态、链表损坏 顺序固定：先 unlink 再 giveback
5 在 urb_dequeue 里把 -EIDRM / -EBUSY 当错误 正常的解链失败被当 bug 这两个是正常返回
6 urb->transfer_buffer 在栈上 WARN_ONCE + -EAGAIN 用 kmalloc 或 usb_alloc_coherent
7 hcd_priv[] 用普通指针偏移访问 对齐错误、踩内存 用 hcd_to_xxx() 内联函数
8 QH / qTD 没按 32 字节对齐 硬件读描述符出错，XactErr 满天飞 dma_pool_create(name, dev, size, 32, 0)
9 writel 后不读一次 posted write 没生效 写后读一个别的寄存器
10 共享中断没判 masked_status == 0 一直返回 IRQ_HANDLED，中断风暴 空就 return IRQ_NONE
11 清中断写回全部状态位 把别人刚置的位清了 只写回你处理的那几位
12 直接解引用 void __iomem * 编译器优化错、sparse 报警 只用 readl / writel
13 usb_add_hcd() 失败后没 usb_put_hcd() 内存与引用泄漏 所有错误路径都 usb_put_hcd()
14 start() 失败路径没清硬件 下次 probe 时硬件状态脏 初始化失败自己清
15 stop() 里没停调度就返回 DMA 还在跑，访问已释放内存 先 CMD_RUN=0 再释放
16 忘了 HCD_FLAG_HW_ACCESSIBLE 挂起后还在读寄存器 PM 回调里正确置/清这一位
17 EHCI 单条控制 URB 超过 16 KB -EMSGSIZE 拆成多次控制传输
18 等时传输用 SG 列表 WARN_ON(1) + -EINVAL 等时用连续缓冲区
19 高速设备用 siTD 完全不工作 高速 iTD，全速经 TT 才 siTD
20 忘了 hcd->rsrc_start / rsrc_len /proc/iomem 没有你的区间，无法排查 platform 路径必须自己填
21 hcd->speed 与 HCD_MASK 不一致 根集线器速度错，枚举出怪结果 __usb_create_hcd 自动填，别手改
22 用 HCD_USB25 编译新内核 枚举值已删，编译失败 6.x 上删掉这个分支
23 pci_resume 按旧签名写 编译不过 6.x 是 pm_message_t，不是 bool
24 hcd_priv[0] 与 hcd_priv[] 混用 老编译器警告 6.x 用柔性数组写法
