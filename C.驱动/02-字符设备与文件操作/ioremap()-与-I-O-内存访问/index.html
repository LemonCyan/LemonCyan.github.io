几乎每一种外设都是通过读写设备上的寄存器来操作的，这些寄存器通常包括控制寄存器、状态寄存器和数据寄存器三大类，并且连续编址。但驱动不能直接拿寄存器的物理地址去访问——必须先把这段物理地址映射进内核虚地址空间。ioremap() 就是干这件事的。

一、两种 I/O 编址方式 #

1.1 I/O 映射方式（I/O-mapped） #

典型如 x86 处理器，为外设专门实现了一个独立的地址空间，称为"I/O 地址空间"或"I/O 端口空间"。CPU 通过专门的 I/O 指令（如 x86 的 IN 和 OUT）来访问这一空间中的地址单元。

1.2 内存映射方式（Memory-mapped） #

RISC 指令系统的 CPU（如 ARM、PowerPC 等）通常只实现一个物理地址空间，外设 I/O 端口成为内存的一部分。此时 CPU 可以像访问一个内存单元那样访问外设 I/O 端口，不需要专门的 I/O 指令。

1.3 对软件透明 #

这两种方式在硬件实现上的差异对软件完全透明，驱动开发者可以把内存映射方式的 I/O 端口和外设内存统一看作"I/O 内存"资源。

I/O-mapped Memory-mapped
地址空间 独立端口空间 与内存共用
访问指令 in / out 普通 load/store
典型架构 x86 ARM、PowerPC、RISC-V
Linux 访问方式 inb/outb 等 ioremap + readl/writel

二、为什么需要 ioremap #

系统运行时，外设 I/O 内存资源的物理地址是已知的，由硬件设计决定。但 CPU 通常并没有为这些物理地址预定义虚拟地址范围，因此驱动无法直接通过物理地址访问 I/O 内存资源。

正确做法是把它们映射到核心虚地址空间（通过页表），然后根据映射得到的虚地址范围，用访内指令访问这些 I/O 内存资源。

外设寄存器物理地址 (如 0x114000a0)
        │
        │  ioremap()  ── 建立页表映射
        ▼
内核虚拟地址 (3G–4G 区，类型为 void __iomem *)
        │
        │  readl() / writel()
        ▼
外设寄存器实际被读写

三、ioremap 与 iounmap #

3.1 原型 #

ioremap 在 io.h 中声明，作用是把 I/O 内存资源的物理地址映射到核心虚地址空间（3 GB–4 GB，即内核空间）。

它是定义在 asm/io.h 内的宏：

c
#define ioremap(cookie, size)  __ioremap(cookie, size, 0)

__ioremap 的函数原型（arm/mm/ioremap.c）：

c
void __iomem *__ioremap(unsigned long phys_addr, size_t size, unsigned long flags);
参数 含义
phys_addr 要映射的起始 IO 地址（物理地址）
size 要映射的空间大小（字节）
flags 映射的 IO 空间权限相关的标志

返回值：映射后的内核虚拟地址（3G–4G 区间）。之后就可以通过读写这个返回的内核虚拟地址来访问这段 I/O 内存资源。

注意返回类型是 void __iomem *，这个类型标注存在的意义就是防止你直接解引用它，见第四章。

3.2 取消映射 #

c
void iounmap(void *addr);

用于取消 ioremap() 所做的映射。每次 ioremap 都要有对应的 iounmap，否则模块反复加载卸载会持续泄漏内核虚拟地址空间。

四、访问 I/O 内存的正确姿势 #

4.1 为什么不能直接解引用 #

把物理地址映射成核心虚地址后，理论上讲可以像读写 RAM 那样直接读写 I/O 内存了。但为了保证驱动程序的跨平台可移植性，应该使用 Linux 中特定的函数来访问 I/O 内存资源，而不应该通过指向核心虚地址的指针来访问。

原因有三条：

  1. 字节序：外设寄存器可能是小端或大端，writel 会做 __cpu_to_le32 转换；直接赋值不会。
  2. 内存屏障：I/O 访问有严格的顺序要求，readl/writel 内含屏障（__iormb/__iowmb），普通赋值没有。
  3. 编译器优化：直接对 void * 赋值可能被优化掉或被拆分成多次访问，而寄存器访问必须精确匹配位宽。

4.2 writel 与 readl #

writel()：往内存映射的 I/O 空间写数据，写入 32 位数据（4 字节）。

c
void writel(u32 value, void __iomem *addr);

readl()：从内存映射的 I/O 空间读数据，读取 32 位数据（4 字节）。

c
u32 readl(const volatile void __iomem *addr);
writel(value, addr) readl(addr)
方向 写 读
宽度 32 位 32 位
返回值 无 从 I/O 空间读取的数值

⚠️ 原文此处两个函数的原型都是错的：写的是 void writel(unsigned char data, unsigned short addr) 与 unsigned char readl(unsigned int addr)。真实签名如上方所示——数据宽度是 u32 而非 unsigned char，地址是 void __iomem * 而非 unsigned short/unsigned int。照原文写会编译不过或截断数据。

4.3 其他位宽 #

按位宽成套提供，命名规律是 read/write + 宽度后缀：

宽度 读 写
8 位 readb() writeb()
16 位 readw() writew()
32 位 readl() writel()
64 位 readq() writeq()

4.4 底层实现 #

这些函数最终落在 __raw_readX / __raw_writeX 上，后者就是一次 volatile 指针访存：

c
#define readb                    __raw_readb
#define readw(addr)              __le16_to_cpu(__raw_readw(addr))
#define readl(addr)              __le32_to_cpu(__raw_readl(addr))

#ifndef __raw_readb
static inline u8 __raw_readb(const volatile void __iomem *addr)
{
    return *(const volatile u8 __force *)addr;
}
#endif

#ifndef __raw_readw
static inline u16 __raw_readw(const volatile void __iomem *addr)
{
    return *(const volatile u16 __force *)addr;
}
#endif

#ifndef __raw_readl
static inline u32 __raw_readl(const volatile void __iomem *addr)
{
    return *(const volatile u32 __force *)addr;
}
#endif

#define writeb                   __raw_writeb
#define writew(b, addr)          __raw_writew(__cpu_to_le16(b), addr)
#define writel(b, addr)          __raw_writel(__cpu_to_le32(b), addr)

三层结构看得很清楚：

readl(addr)  →  __le32_to_cpu(__raw_readl(addr))  →  *(volatile u32 *)addr
   带字节序转换        带屏障的封装              一次裸访存

volatile 保证编译器不会优化掉、不会合并这次访问；__force 只是告诉 sparse（内核静态检查工具）"这里的类型转换是我故意的"，不影响生成的代码。

五、实例：PWM 驱动里的寄存器配置 #

以下取自 PWM 驱动的实际用法，寄存器地址均为物理地址。

5.1 定义寄存器地址 #

c
#define GPD0CON       0x114000a0
#define TIMER_BASE    0x139D0000

#define TCFG0         0x0000
#define TCFG1         0x0004
#define TCON          0x0008
#define TCNTB0        0x000C
#define TCMPB0        0x0010

5.2 定义保存映射地址的指针 #

c
static unsigned int *gpd0con;
static void *timer_base;

注意：timer_base 的类型设为 void *，主要因为下面要用地址偏移（timer_base + TCFG0）。用 void * 更便于做偏移。

现代写法应当用 void __iomem *：static void __iomem *timer_base;。这样既能做偏移，又保留了类型检查，直接解引用会被 sparse 报错。

5.3 做内存映射 #

c
gpd0con    = ioremap(GPD0CON, 4);       // 单个 32 位寄存器，映射 4 字节
timer_base = ioremap(TIMER_BASE, 0x14); // 0x14 = 20 字节，覆盖 TCFG0..TCMPB0(0x10+4)

映射长度按要用到的最大偏移 + 宽度算，timer_base 用到 TCMPB0 = 0x10，加 4 字节宽度即 0x14。

5.4 读写寄存器 #

典型的"读-改-写"模式：先读出整个寄存器，清掉目标位域，再或上新值，最后写回。

c
/* 配置 GPD0 引脚功能：清 bit[3:0]，置为 0x2（PWM 输出） */
writel((readl(gpd0con) & ~(0xf << 0)) | (0x2 << 0), gpd0con);

/* 预分频器 TCFG0：清 bit[7:0]，置为 0xff */
writel((readl(timer_base + TCFG0) & ~(0xff << 0)) | (0xff << 0), timer_base + TCFG0);

/* 分频器 TCFG1：清 bit[3:0]，置为 0x2 */
writel((readl(timer_base + TCFG1) & ~(0xf << 0)) | (0x2 << 0), timer_base + TCFG1);

/* 设置计数初值与比较值，决定频率与占空比 */
writel(500, timer_base + TCNTB0);
writel(250, timer_base + TCMPB0);

/* 启动定时器：清 bit[3:0]，置为 0x2 */
writel((readl(timer_base + TCON) & ~(0xf << 0)) | (0x2 << 0), timer_base + TCON);

这段代码与其说是"写寄存器"，不如说是"位域操作"——绝大多数外设寄存器都是多个字段共用一个 32 位字，所以 & ~(mask << shift) | (value << shift) 这个组合会反复出现，值得记牢。

完整的中断/定时器/PWM 用法见《编写简单 PWM 设备驱动》。

六、用之前先占资源 #

ioremap 只建立映射，不声明"这段物理地址归我"。规范的做法是先用 request_mem_region() 申请，再 ioremap，退出时反向释放：

c
struct resource *res;

res = request_mem_region(TIMER_BASE, 0x14, "my_pwm");
if (!res)
    return -EBUSY;

timer_base = ioremap(TIMER_BASE, 0x14);
if (!timer_base) {
    release_mem_region(TIMER_BASE, 0x14);
    return -ENOMEM;
}

/* ... 使用 ... */

iounmap(timer_base);
release_mem_region(TIMER_BASE, 0x14);

用 cat /proc/iomem 可以看到当前所有已被申请的物理内存区。走 platform 设备树时，这一步由 devm_platform_ioremap_resource() 代劳（推荐），见 C.驱动/04-platform与总线模型。
