写字符设备驱动的第一步不是写 open/read，而是申请一个设备号并把它和一个 cdev 绑定起来。这两件事做不对，后面写多少函数都不会被内核调用到。

本篇讲这条"注册链"：从设备分类，到设备号的构造与分配，到 cdev 的四个操作接口，再到设备节点的创建。

一、字符设备基础知识 #

1.1 设备驱动分类 #

Linux 系统将设备分为三类：

字符设备：只能一个字节一个字节读写的设备，不能随机读取设备内存中的某一数据，读取数据需要按照先后顺序。字符设备是面向流的设备，常见的有鼠标、键盘、串口、控制台和 LED 设备等。

块设备：可以从设备的任意位置读取一定长度数据的设备。块设备包括硬盘、磁盘、U 盘和 SD 卡等。

网络设备：既不是字符设备也不是块设备——它的输入输出有结构（报文、包、帧），且没有 /dev 下的节点。

每一个字符设备或块设备都在 /dev 目录下对应一个设备文件。Linux 用户程序通过设备文件（或称设备节点）来使用驱动程序操作字符设备和块设备。

1.2 三者之间的三角关系 #

字符设备、字符设备驱动与用户空间访问该设备的程序，三者之间的关系可以用三条边描述。

边 1：在 Linux 内核中

  • a — 使用 cdev 结构体来描述一个字符设备；
  • b — 通过其成员 dev_t 来定义设备号（分为主、次设备号）以确定字符设备的唯一性；
  • c — 通过其成员 file_operations 来定义字符设备驱动提供给 VFS 的接口函数，如常见的 open()、read()、write() 等。

边 2：在 Linux 字符设备驱动中

  • a — 模块加载函数通过 register_chrdev_region() 或 alloc_chrdev_region() 来静态或者动态获取设备号；
  • b — 通过 cdev_init() 建立 cdev 与 file_operations 之间的连接，通过 cdev_add() 向系统添加一个 cdev 以完成注册；
  • c — 模块卸载函数通过 cdev_del() 注销 cdev，通过 unregister_chrdev_region() 释放设备号。

边 3：用户空间访问该设备的程序

  • a — 通过 Linux 系统调用（open()、read()、write()）来"调用" file_operations 中定义的、字符设备驱动提供给 VFS 的接口函数。
        用户程序
       open/read/write
            │ 系统调用
            ▼
    ┌───────────────┐
    │  file_operations │  ← cdev->ops 指向它
    └───────────────┘
            ▲
            │ cdev 里的 ops 成员
    ┌───────────────┐
    │     cdev      │  ← 用 dev_t 定位，用 list 串成链表

二、设备号 #

2.1 主设备号与次设备号 #

一个字符设备或块设备都有一个主设备号和一个次设备号：

主设备号 次设备号
作用 标识与设备文件相连的驱动程序，反映设备类型 被驱动程序用来辨别操作的是哪个设备，区分同类型设备
举例 /dev/tty1 与 /dev/tty2 主设备号相同 /dev/tty1 与 /dev/tty2 次设备号不同

2.2 dev_t 的编码 #

Linux 内核中用 dev_t 来描述设备号：

c
typedef u_long dev_t;

在 32 位机中它是 4 个字节：高 12 位表示主设备号，低 20 位表示次设备号。

 31          20 19                          0
┌──────────────┬─────────────────────────────┐
│  主设备号 12 位 │        次设备号 20 位         │
└──────────────┴─────────────────────────────┘

2.3 三个操作宏 #

内核提供了几个方便操作的宏：

  1. 从设备号中提取 major 和 minor
c
MAJOR(dev_t dev);
MINOR(dev_t dev);
  1. 通过 major 和 minor 构建设备号
c
MKDEV(int major, int minor);

注意：MKDEV 只是构建设备号，并未注册。 要真正占用它，还需要调用 register_chrdev_region() 静态申请。

具体宏定义：

c
#define MINORBITS    20
#define MINORMASK    ((1U << MINORBITS) - 1)

#define MAJOR(dev)   ((unsigned int) ((dev) >> MINORBITS))
#define MINOR(dev)   ((unsigned int) ((dev) & MINORMASK))
#define MKDEV(ma,mi) (((ma) << MINORBITS) | (mi))

手写等价形式，便于理解位运算：

c
int major = 250;
int minor = 0;

dev_t cdevno = major << 20 | minor;   /* 等价于 MKDEV(major, minor) */

MINORMASK 就是 1 0000 0000 0000 0000 0000（0xFFFFF），MAJOR 右移 20 位，MINOR 与之按位与——非常标准的位域提取。

三、分配设备号 #

两种方法，二选一。

3.1 静态申请 #

c
int register_chrdev_region(dev_t from, unsigned count, const char *name);
参数 含义
from 起始设备号
count 申请的设备号个数
name 设备的名字，会出现在 /proc/devices 中

返回值：成功 0，失败返回负数错误码。

功能：静态申请设备号，若设备号已被使用，则申请失败。

典型用法：

c
dev_t devno = MKDEV(250, 0);
int ret = register_chrdev_region(devno, 1, "hello");
if (ret < 0) {
    printk("register_chrdev_region fail\n");
    return ret;
}

3.2 动态分配（推荐） #

c
int alloc_chrdev_region(dev_t *dev, unsigned baseminor, unsigned count, const char *name);
参数 含义
dev 回填的设备号（输出参数）
baseminor 基于哪一个次设备号开始申请
count 申请多少个
name 设备的名字

功能：动态申请设备号，由内核从大到小枚举出未使用的设备号提供给申请者使用。返回值成功 0，失败负数。

成功后可这样取回主设备号：

c
dev_t devno;
if (alloc_chrdev_region(&devno, 0, 1, "hello") < 0)
    return -1;

major = MAJOR(devno);   /* 之后可以用它 mknod 或调试打印 */

为什么推荐动态：静态分配必须自己挑一个没被占用的主设备号，而主设备号在不同内核配置、不同开发板上被占用的集合并不一样，代码换个平台就可能冲突。动态分配让内核按需分配，/proc/devices 里不会打成一团。

3.3 老接口 register_chrdev #

c
static inline int register_chrdev(unsigned int major, const char *name,
                                  const struct file_operations *fops);
参数 含义
major 主设备号。为 0 时动态申请，为具体数字时静态申请
name 设备名字
fops 要绑定的设备操作函数

返回值：动态申请时返回主设备号（使用时需要进行拼接）；静态申请时返回 0。

功能：可动态或静态申请设备号，并将设备节点内的设备号与 fops 操作函数绑定，同时向 chrdevs 数组中添加该 cdev 节点。

它一步做完了四件事：

步骤 做的事 底层调用
a 注册设备号 __register_chrdev_region()
b 分配一个 cdev cdev_alloc()
c 将 cdev 添加到驱动模型，设备号与驱动关联 cdev_add()
d 把 char_device_struct 的 cdev 指向第二步分配的 cdev —（新接口不需要）

也就是说：上节那"申请设备号 → cdev_init → cdev_add"三步，可以直接用一个 register_chrdev() 替代。 这是老的接口，适合快速验证；新驱动建议用分开的三步，控制粒度更细、便于支持多设备。

3.4 注销设备号 #

c
void unregister_chrdev_region(dev_t from, unsigned count);
static inline void unregister_chrdev(unsigned int major, const char *name);

注意 count 必须与申请时一致，否则会漏释放或越界释放。

四、cdev 结构体 #

4.1 定义 #

在 Linux 内核中，使用 cdev 结构体来描述一个字符设备：

c
#include <linux/cdev.h>

struct cdev {
    struct kobject kobj;                  /* 内嵌的内核对象 */
    struct module *owner;                 /* 该字符设备所在的内核模块的对象指针 */
    const struct file_operations *ops;    /* 该结构描述了字符设备所能实现的方法，极为关键 */
    struct list_head list;                /* 用来将已经向内核注册的所有字符设备形成链表 */
    dev_t dev;                            /* 字符设备的设备号，由主、次设备号构成 */
    unsigned int count;                   /* 隶属于同一主设备号的次设备号的个数 */
};
成员 作用
kobj 内嵌的 kobject，让 cdev 能参与 sysfs 设备模型
owner 所属模块，防止方法被使用时模块被卸载
ops 指向 file_operations，这是最关键的成员
list 把所有已注册的字符设备串成一个链表
dev 设备号
count 次设备号个数

4.2 四个操作接口 #

a — cdev_init #

c
void cdev_init(struct cdev *, const struct file_operations *);

主要对 struct cdev 做初始化，最重要的就是建立 cdev 和 file_operations 之间的连接。它依次做四件事：

  1. 将整个结构体清零；
  2. 初始化 list 成员使其指向自身；
  3. 初始化 kobj 成员；
  4. 初始化 ops 成员。

源码：

c
void cdev_init(struct cdev *cdev, const struct file_operations *fops)
{
    memset(cdev, 0, sizeof *cdev);
    INIT_LIST_HEAD(&cdev->list);
    kobject_init(&cdev->kobj, &ktype_cdev_default);
    cdev->ops = fops;
}

b — cdev_alloc #

c
struct cdev *cdev_alloc(void);

动态申请一个 cdev 内存，并做了 cdev_init 中所做的前三步初始化工作；第四步（初始化 ops）需要在调用 cdev_alloc 后显式地做，即 .ops = xxx_ops。

源码：

c
struct cdev *cdev_alloc(void)
{
    struct cdev *p = kzalloc(sizeof(struct cdev), GFP_KERNEL);

    if (p) {
        INIT_LIST_HEAD(&p->list);
        kobject_init(&p->kobj, &ktype_cdev_dynamic);
    }
    return p;
}

对比 cdev_init 与 cdev_alloc：

cdev_init cdev_alloc
cdev 内存 由调用者提供（栈/静态/内嵌） 由函数 kzalloc 分配
清零 ✓ ✓（kzalloc）
初始化 list ✓ ✓
初始化 kobj ✓ ✓（用 ktype_cdev_dynamic）
初始化 ops ✓ ✗ 需手动赋值
用在哪 大结构体内嵌 cdev 时（推荐） 单独动态申请 cdev 时

c — cdev_add #

c
int cdev_add(struct cdev *p, dev_t dev, unsigned count);

向内核注册一个 struct cdev，即正式通知内核：由 struct cdev *p 代表的字符设备已经可以使用了。

需要提供两个参数，这两个参数直接赋值给 cdev 的 dev 成员和 count 成员：

  1. 第一个设备号 dev；
  2. 和该设备关联的设备编号的数量 count。

d — cdev_del #

c
void cdev_del(struct cdev *p);

向内核注销一个 struct cdev，即正式通知内核：由 struct cdev *p 代表的字符设备已经不可以使用了。

4.3 owner / dev / count 何时初始化 #

在上面两个初始化函数里，没有看到关于 owner、dev、count 成员的初始化，这是有原因的：

  • owner — 它的存在体现了驱动程序与内核模块间的亲密关系。struct module 是内核对于一个模块的抽象，该成员在字符设备中体现该设备隶属于哪个模块。驱动编写中一般由用户显式初始化为 .owner = THIS_MODULE，该成员可以防止设备的方法正在被使用时，设备所在模块被卸载。
  • dev 和 count — 这两个成员在 cdev_add 中才会赋上有效的值。

所以完整的初始化时序是：

定义 cdev   →  cdev_init(&cdev, &fops)   →  cdev.owner = THIS_MODULE
           →  cdev_add(&cdev, devno, n)  ← 此刻 dev / count 才有效

五、创建设备文件 #

设备号申请到了、cdev 注册了，但用户空间还打不开设备——因为 /dev 下还没有节点。

5.1 先确认设备号 #

bash
cat /proc/devices

可以看到申请到的设备名与设备号，形如：

text
Character devices:
  1 mem
  4 ttyS
 10 misc
 13 input
 29 fb
 90 mtd
180 usb
204 ttySAC
250 hello          ← 我们自己注册的

5.2 方式一：mknod 手工创建 #

bash
mknod filename type major minor

例如：

bash
mknod /dev/hello c 250 0

c 表示字符设备（b 表示块设备）。

5.3 方式二：自动创建设备节点 #

利用 udev（嵌入式上常用 mdev）实现设备文件的自动创建，首先应保证系统支持 udev/mdev，这由 busybox 配置决定。

在驱动初始化代码里：

  1. 调用 class_create() 为该设备创建一个 class——对应在 /sys/class/ 下创建一个目录；
  2. 再为每个设备调用 device_create() 创建对应的设备节点。

内核中定义的 struct class 结构体，一个 struct class 类型变量对应一个类。内核同时提供了 class_create() 函数用来创建一个类，这个类存放于 sysfs 下面；一旦创建好了这个类，再调用 device_create() 函数就能在 /dev 目录下创建相应的设备节点。

这样，加载模块的时候，用户空间中的 udev 会自动响应 device_create() 函数，去 /sys 下寻找对应的类从而创建设备节点。

两个函数的原型与配套销毁函数：

c
/* 创建一个类 */
struct class *class_create(struct module *owner, const char *name);
void class_destroy(struct class *cls);

/* 创建一个字符设备文件 */
struct device *device_create(struct class *class, struct device *parent,
                             dev_t devt, void *drvdata, const char *fmt, ...);
void device_destroy(struct class *class, dev_t devt);

新内核 class_create() 只剩一个参数 class_create(const char *name)，owner 已被移除。

六、一个 cdev 管多个设备 #

前面一路写的都是单实例驱动：一个模块、一个 cdev、一个设备号、一个 /dev 节点。但真实驱动经常是「同一个驱动，好几个同类设备」：两个串口、四路 LED、八通道 ADC。这一节讲怎么让一个驱动承载多个设备实例。

6.1 两种做法，选哪种 #

做法 结构 什么时候用
一个 cdev，count > 1 cdev_add(&cdev, devno, 4)，占 4 个连续次设备号 多个设备行为完全一致，只是编号不同
每个设备一个 cdev 数组或链表，每个 cdev_add 一次 每个设备有独立私有数据、独立状态

第一种更省事：一次 cdev_add 占住 [devno, devno+count) 这段次设备号，open 时用 MINOR(inode->i_rdev) 区分是第几个。缺点是所有实例共用一份 file_operations 上下文，状态得自己按 minor 存。

第二种更灵活：每个设备有自己的 struct cdev 和私有结构，open 时用 container_of 从 inode->i_cdev 直接反推出那个设备的结构体，不用查表。代价是注册和注销要循环。

实践中第二种更常见，因为它把「第几个设备」这件事从运行时算编号变成了编译期定的结构体地址，代码更好读。

6.2 私有结构体内嵌 cdev #

关键是把 cdev 作为第一个成员放进自己的设备结构体里：

c
#include <linux/cdev.h>
#include <linux/fs.h>

#define DEV_CNT  4

struct mydev {
    struct cdev    cdev;        /* 习惯上放第一个，原因见 6.3 */
    dev_t          devno;
    struct device *dev;
    char           name[16];
    void          *buf;         /* 每个设备自己的缓冲区 */
    size_t         buf_size;
    struct mutex   lock;        /* 每个设备自己的锁 */
};

static struct mydev mydevs[DEV_CNT];

cdev 放第一个是习惯，不是语法要求：container_of 对任何偏移量都成立，放在中间、末尾照样能正确反推。放首位有两个附带好处——偏移为 0 时少一条减法（编译器多半也会优化掉），以及 (struct mydev *)cdev_ptr 这种直接转换在语义上也成立，读代码时不必先算偏移。

6.3 从 cdev 反推外层结构：container_of #

open 回调拿到的 struct inode * 里，i_cdev 指向注册时那个 cdev。但你要用的是整个 mydev，不是光秃秃的 cdev。这个「从成员地址反推宿主结构地址」的动作没有语法糖，只能靠 container_of：

c
#define container_of(ptr, type, member) ({                  \
    void *__mptr = (void *)(ptr);                           \
    ((type *)(__mptr - offsetof(type, member))); })

拆开看就三步：

c
/* 以 struct mydev 为例，假设 cdev 不在第一个位置 */
struct mydev *d = container_of(inode->i_cdev, struct mydev, cdev);
步骤 做了什么 上例的中间值
① 取成员地址 ptr 就是 inode->i_cdev，即 &mydevs[i].cdev 某个具体地址
② 减去偏移 offsetof(struct mydev, cdev) 是编译期常量 若 cdev 在首位，偏移是 0
③ 转成宿主类型 减完得到 &mydevs[i] 正确的结构体首地址

offsetof 是编译器内建（<linux/stddef.h>），不产生运行时开销，偏移量在编译期就定死了。所以 container_of 整体就是一条减法指令。

这套手法的前提是：cdev 内嵌在宿主结构里，而不是单独 kzalloc 出来的。因为只有内嵌，两者才有固定的偏移关系。如果用的是 cdev_alloc()（独立分配），那 cdev 和你的设备结构之间没有任何位置关联，只能靠 cdev->dev 之类的外部字段挂接，或者干脆用查表。

这也是 3.3 节那张对比表里「大结构体内嵌 cdev 时推荐 cdev_init」的真正原因。不只是内存分配方式的问题，而是决定了后面能不能用 container_of。

6.4 open 里怎么用 #

c
static int mydev_open(struct inode *inode, struct file *file)
{
    struct mydev *d = container_of(inode->i_cdev, struct mydev, cdev);

    /* 把设备指针挂到本次打开上，read/write/ioctl 都能直接拿到 */
    file->private_data = d;

    mutex_lock(&d->lock);
    /* 首次打开时初始化硬件之类 */
    mutex_unlock(&d->lock);

    return 0;
}

static ssize_t mydev_read(struct file *file, char __user *buf,
                          size_t count, loff_t *ppos)
{
    struct mydev *d = file->private_data;   /* 不用再算一次 */

    if (*ppos >= d->buf_size)
        return 0;
    if (count > d->buf_size - *ppos)
        count = d->buf_size - *ppos;

    if (copy_to_user(buf, d->buf + *ppos, count))
        return -EFAULT;

    *ppos += count;
    return count;
}

两个要点：

一、container_of 只在 open 里做一次。 read/write/ioctl 拿不到 inode（拿到的是 file），所以把结果存进 file->private_data，后面直接用。每次 read 都重新反推一次也能工作，但没必要。

二、file->private_data 是每次 open 独立的。 同一个设备被两个进程各 open 一次，会生成两个 struct file，各自的 private_data 都指向同一个 struct mydev。所以设备级的并发保护要用 struct mydev 里的锁（上例的 d->lock），不能用 struct file 里存的东西。

6.5 注册与注销 #

c
static int __init mydev_init(void)
{
    int i, ret;

    /* 一次性申请 DEV_CNT 个连续设备号 */
    ret = alloc_chrdev_region(&mydevs[0].devno, 0, DEV_CNT, "mydev");
    if (ret < 0)
        return ret;

    for (i = 0; i < DEV_CNT; i++) {
        struct mydev *d = &mydevs[i];

        d->devno = MKDEV(MAJOR(mydevs[0].devno), MINOR(mydevs[0].devno) + i);
        snprintf(d->name, sizeof(d->name), "mydev%d", i);
        mutex_init(&d->lock);

        cdev_init(&d->cdev, &mydev_fops);
        d->cdev.owner = THIS_MODULE;

        ret = cdev_add(&d->cdev, d->devno, 1);
        if (ret) {
            /* 回滚已注册的 i 个 */
            while (i--)
                cdev_del(&mydevs[i].cdev);
            unregister_chrdev_region(mydevs[0].devno, DEV_CNT);
            return ret;
        }
    }

    /* 建节点，用户态才能 open */
    mydev_class = class_create("mydev");
    for (i = 0; i < DEV_CNT; i++)
        mydevs[i].dev = device_create(mydev_class, NULL, mydevs[i].devno,
                                      NULL, "mydev%d", i);
    return 0;
}

四个容易写错的地方： 一、devno 要按 minor 递增。 alloc_chrdev_region 只给你一个起始号，后面 DEV_CNT - 1 个得自己 MKDEV(MAJOR(base), MINOR(base) + i) 算出来。漏了这步，四个设备号会全一样，cdev_add 第二个就撞号失败。

二、cdev_init 必须在 cdev_add 之前，且每个设备各调一次。 cdev_init 里做 INIT_LIST_HEAD 和 kobject_init，一个 cdev 只能初始化一次。这一行还有个陷阱：如果 cdev 是静态数组（像上面 mydevs[] 那样放在 .bss），模块卸载再加载时会重新执行 cdev_init，而 kobject_init 对同一个对象重复调用会报 kobject: ...: tried to init an initialized object。写一次性加载的代码察觉不到，反复 insmod/rmmod 就露头。

三、失败回滚要逐个 cdev_del。 unregister_chrdev_region 只还设备号，不注销 cdev。上面那个 while (i--) 就是干这个的，顺序是先把已经 cdev_add 的逐个删掉，再整体还号。

四、device_create 的返回值要判。 上面为了突出主线没写，实际代码里每个 device_create 都可能失败（内存不足、sysfs 有同名残留），失败时 IS_ERR() 成立，后面的 device_destroy 拿一个错误指针进去就是崩溃。class_create 同理。

注销按逆序：

c
static void __exit mydev_exit(void)
{
    int i;

    for (i = 0; i < DEV_CNT; i++)
        device_destroy(mydev_class, mydevs[i].devno);
    class_destroy(mydev_class);

    for (i = 0; i < DEV_CNT; i++)
        cdev_del(&mydevs[i].cdev);

    unregister_chrdev_region(mydevs[0].devno, DEV_CNT);
}

6.6 什么时候该换 misc 或 alloc_chrdev #

如果设备满足「不需要独立主设备号、就一个节点、功能简单」，misc_register() 能省掉上面所有步骤：它内部帮你做了 alloc_chrdev_region + cdev_add + device_create，主设备号固定是 10。代价是次设备号从全局 misc 池里分，不能自己规划。

判断标准：要不要自己控次设备号？ 要（比如 mydev0~mydev3 要连号），用本文这套。不要，用 misc_register 更省事。

七、完整实例 #

把上面所有步骤串起来，一个最小可跑的字符设备驱动：

c
#include <linux/module.h>
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>

#define HELLO_MAJOR  250
#define HELLO_MINOR  0

static int major = HELLO_MAJOR;
static int minor = HELLO_MINOR;
static dev_t devno;
static struct cdev cdev;
static struct class *hello_class;

static int hello_open(struct inode *inode, struct file *filep)
{
    printk("hello_open\n");
    return 0;
}

static struct file_operations hello_ops = {
    .owner = THIS_MODULE,
    .open  = hello_open,
};

static int __init hello_init(void)
{
    int ret;

    printk("hello_init\n");

    /* 1. 构建设备号并静态申请 */
    devno = MKDEV(major, minor);
    ret = register_chrdev_region(devno, 1, "hello");
    if (ret < 0) {
        printk("register_chrdev_region fail\n");
        return ret;
    }

    /* 2. 初始化 cdev 并注册 */
    cdev_init(&cdev, &hello_ops);
    cdev.owner = THIS_MODULE;
    ret = cdev_add(&cdev, devno, 1);
    if (ret < 0) {
        printk("cdev_add fail\n");
        unregister_chrdev_region(devno, 1);
        return ret;
    }

    /* 3. 自动创建设备节点（交给 udev/mdev） */
    hello_class = class_create(THIS_MODULE, "hello");
    device_create(hello_class, NULL, devno, NULL, "hello");

    return 0;
}

static void __exit hello_exit(void)
{
    device_destroy(hello_class, devno);
    class_destroy(hello_class);
    cdev_del(&cdev);
    unregister_chrdev_region(devno, 1);
    printk("hello_exit\n");
}

MODULE_LICENSE("GPL");
module_init(hello_init);
module_exit(hello_exit);

八、注册链速查 #

阶段 函数 成功之后
构建设备号 MKDEV(major, minor) 只是一个数字，还没占用
申请设备号 register_chrdev_region / alloc_chrdev_region /proc/devices 里可见
初始化 cdev cdev_init(&cdev, &fops) cdev->ops 已指向你的操作表
设 owner cdev.owner = THIS_MODULE 防止方法被调时模块被卸载
注册 cdev cdev_add(&cdev, devno, count) dev/count 被赋值，内核可查表
建节点 mknod 或 class_create + device_create /dev/<name> 可被 open

卸载时严格逆序：device_destroy → class_destroy → cdev_del → unregister_chrdev_region。
