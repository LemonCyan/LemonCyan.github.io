模块不是写完就完了——它还要能从外部接收参数、也可能需要把自己的函数借给别的模块用。

一、模块传参：module_param #

用户态编程可以通过 main() 接收命令行参数，编写内核模块则通过 module_param() 传参。

1.1 宏定义与三个参数 #

module_param() 是 Linux 2.6 内核新增的宏，定义在 include/linux/moduleparam.h：

c
#define module_param(name, type, perm)   module_param_named(name, name, type, perm)

使用形式：

c
module_param(name, type, perm);

三个参数的含义：

参数 含义
name 既是用户看到的参数名，又是模块内接收参数的变量
type 参数数据类型，见下方取值表
perm 在 sysfs 中对应文件的访问权限，与 Linux 文件权限写法相同（如 0644），也可用 stat.h 里的宏如 S_IRUGO；0 表示完全关闭 sysfs 中对应项

支持的 type 取值：

text
byte, short, ushort, int, uint, long, ulong
charp    字符串指针（a character pointer）
bool     布尔值，取 0/1、y/n、Y/N
invbool  反向布尔，语义取反（N 为 true）

1.2 使用前必须先声明变量 #

module_param() 宏不会声明变量，所以使用宏之前必须先声明，而且这些声明必须写在模块源文件的开头部分——即变量是全局的：

c
static unsigned int int_var = 0;

module_param(int_var, uint, S_IRUGO);

1.3 四种形式 #

（1）module_param —— 内外同名 #

最常用形式。参数名与变量名一致，见 1.2。

（2）module_param_named —— 内外不同名 #

想让外部参数名与源文件内部的变量名不同，就用它：

c
module_param_named(name, variable, type, perm);
参数 含义
name 外部（用户空间）可见的参数名
variable 源文件内部的全局变量名
type 类型
perm 权限

module_param 就是这样实现的，只不过它的 name 与 variable 相同。

c
static unsigned int max_test = 9;

module_param_named(maximum_line_test, max_test, int, 0);

（3）字符串参数：charp 或 module_param_string #

用 charp 类型时，内核复制用户提供的字符串到内存，相应变量指向这个字符串：

c
static char *name;

module_param(name, charp, 0);

另一种方式是用 module_param_string() 让内核把字符串直接复制到程序中的字符数组：

c
module_param_string(name, string, len, perm);
  • name：外部参数名；
  • string：内部变量名；
  • len：以 string 命名的 buffer 大小（可以小于实际 buffer，但没有意义）；
  • perm：sysfs 访问权限，0 表示关闭对应 sysfs 项。
c
static char species[BUF_LEN];

module_param_string(specifies, species, BUF_LEN, 0);

（4）数组参数：module_param_array #

数组参数用逗号间隔的列表提供，模块加载器支持这种写法：

c
module_param_array(name, type, num, perm);
参数 含义
name 数组名（也是参数名）
type 数组元素类型
num 一个整型变量
perm 权限值

如果数组参数在加载时设置，num 会被设置为传入的数的个数。模块加载器会拒绝超过数组容量的值。

1.4 完整实例 #

c
#include <linux/module.h>
#include <linux/init.h>
#include <linux/moduleparam.h>

MODULE_LICENSE("GPL");

static char *who = "world";
static int times = 1;

module_param(times, int, S_IRUSR);
module_param(who, charp, S_IRUSR);

static int hello_init(void)
{
    int i;

    for (i = 0; i < times; i++)
        printk(KERN_ALERT "(%d) hello, %s!\n", i, who);

    return 0;
}

static void hello_exit(void)
{
    printk(KERN_ALERT "Goodbye, %s!\n", who);
}

module_init(hello_init);
module_exit(hello_exit);

编译出 hello.ko 后，加载时传参：

bash
insmod hello.ko who="world" times=5
# (0) hello, world!
# (1) hello, world!
# ...
# (4) hello, world!

rmmod hello
# Goodbye, world!

三个注意点：

  1. 如果加载 hello 时没有输入任何参数，则 who 初始值为 "world"，times 初始值为 1（即代码里的默认值生效）。
  2. 给 charp 传字符串时不能带空格，形如 who="hello world!" 会被截断或解析失败。
  3. 加载后，/sys/module/hello/parameters 目录下会生成与变量对应的文件节点：
bash
$ ls /sys/module/hello/parameters
times  who
$ cat /sys/module/hello/parameters/times
5

这就是 perm 的作用所在——权限非 0 时，用户空间进程可以直接读写这些文件节点来读/改内核里对应变量的值，由 sysfs 帮我们实现。两点限制：需要管理员权限才能修改；权限不能设成 0666，内核不允许。

二、符号导出：EXPORT_SYMBOL #

2.1 要解决的问题 #

内核头文件提供了一个方便的方法来管理符号对模块外部的可见性，由此减少了命名空间的污染（命名空间里的名称可能与其他地方定义的名称冲突），并实现适当的信息隐藏。如果你的模块需要把符号输出给其他模块使用，应当使用：

c
EXPORT_SYMBOL(name);
EXPORT_SYMBOL_GPL(name);   // 只适用于包含 GPL 许可权的模块

两个宏均用于将给定符号导出到模块外。_GPL 版本的宏只能使符号对 GPL 许可的模块可用。

符号必须在模块文件的全局部分导出，不能在函数中导出——因为这两个宏会被扩展成一个特殊用途的声明，而该变量必须是全局的。这个变量存储于模块的一个特殊可执行部分（一个"ELF 段"），装载时内核通过这个段寻找模块导出的变量。

2.2 与 System.map 的区别 #

System.map EXPORT_SYMBOL
内容 链接时的函数地址 导出符号名与其运行时地址的对应关系
何时有效 编译链接完成时确定 内核运行过程中可查
用途 事后符号化 Oops 模块加载时动态链接

模块在加载过程中，本质就是能动态连接到内核。如果在模块中引用了内核或其他模块的符号，就必须 EXPORT_SYMBOL 这些符号，这样才能在装载时找到对应地址完成连接。

2.3 源码展开分析 #

c
#ifndef MODULE_SYMBOL_PREFIX
#define MODULE_SYMBOL_PREFIX ""
#endif

struct kernel_symbol              /* 内核符号结构 */
{
    unsigned long value;          /* 该符号在内存中的地址 */
    const char *name;             /* 该符号的名称 */
};

#define __EXPORT_SYMBOL(sym, sec)                          \
    extern typeof(sym) sym;                                \
    __CRC_SYMBOL(sym, sec)                                 \
    static const char __kstrtab_##sym[]                    \
    __attribute__((section("__ksymtab_strings"), aligned(1))) \
        = MODULE_SYMBOL_PREFIX #sym;                       \
    static const struct kernel_symbol __ksymtab_##sym      \
    __used __attribute__((section("__ksymtab" sec), unused))

理解这段代码需要两个前置知识：

# 与 ## 运算符：# 用于在宏中创建字符串，#abc 就表示字符串 "abc"；## 是预处理器的粘合剂，用来替换粘合两个不同的符号，例如 #define xName(n) x##n，则 xName(4) 变为 x4。

gcc 的 __attribute__ 属性：__attribute__((section("section_name"))) 的作用是将指定的函数或变量放入名为 section_name 的段中。属性可以在定义时直接加入：

c
int myvar __attribute__((section("mydata"))) = 0;

表示定义整型变量 myvar = 0，并将它存放到名为 "mydata" 的 section 中。

于是三个导出宏的差别只在段名后缀：

c
#define EXPORT_SYMBOL(sym)          __EXPORT_SYMBOL(sym, "")
#define EXPORT_SYMBOL_GPL(sym)      __EXPORT_SYMBOL(sym, "_gpl")
#define EXPORT_SYMBOL_GPL_FUTURE(sym) __EXPORT_SYMBOL(sym, "_gpl_future")

EXPORT_SYMBOL 标签内定义的函数或符号对全部内核代码公开，不用修改内核代码就可以在内核模块中直接调用——这就是把函数以符号方式导出给其他模块使用的全部机制。

2.4 使用三步 #

  1. 在模块函数定义之后使用 EXPORT_SYMBOL(函数名)；
  2. 在调用该函数的模块中用 extern 对之声明；
  3. 先加载定义该函数的模块，再加载调用该函数的模块。

2.5 双模块依赖的编译与加载顺序 #

假设模块 A 导出 show()，模块 B 调用它：

c
/* ---- A 模块 ---- */
static int num = 10;

static void show(void)
{
    printk("%d\n", num);
}
EXPORT_SYMBOL(show);

c
/* ---- B 模块 ---- */
extern void show(void);

编译与加载必须严格按下面顺序，否则会报 "Unknown symbol"：

步骤 A 模块 B 模块
编译 1 make 生成 Module.symvers 等 A 编译完成
编译 2 — 把 A 的 Module.symvers 拷贝到 B 的目录下，再 make
加载 先 insmod a.ko 后 insmod b.ko
卸载 后 rmmod a.ko 先 rmmod b.ko

Module.symvers 里记录的是 A 导出的符号名、地址与 CRC，B 编译时靠它解析外部引用，所以没有它 B 编不过，或者编出来加载时报符号版本不匹配。

2.6 完整示例 #

A 模块 hello.c：

c
#include <linux/module.h>
#include <linux/init.h>

static int num = 10;

static void show(void)
{
    printk("show(), num = %d\n", num);
}

static int hello_init(void)
{
    printk("hello_init\n");
    return 0;
}

static void hello_exit(void)
{
    printk("hello_exit\n");
}

EXPORT_SYMBOL(show);
MODULE_LICENSE("GPL");
module_init(hello_init);
module_exit(hello_exit);

B 模块 show.c：

c
#include <linux/module.h>
#include <linux/init.h>

extern void show(void);

static int show_init(void)
{
    printk("show_init\n");
    show();
    return 0;
}

static void show_exit(void)
{
    printk("show_exit\n");
}

MODULE_LICENSE("GPL");
module_init(show_init);
module_exit(show_exit);

编译后按 2.5 的顺序加载再卸载，用 dmesg 查看内核打印信息即可验证。

注意 show() 定义时若加了 static 就不能导出——上面的 show() 在原始素材里既写 static 又 EXPORT_SYMBOL，属于错误写法。正确做法是去掉 static，让它是全局符号。
