一、S3C2410 的 SPI 控制器家底 #

S3C2410/S3C2440 内部有两个独立的 SPI 控制器，硬件上完全对称，各自一套寄存器、一条中断线、一组 GPIO。原文在讲 S3C2440 时提到「内部有两个 SPI 控制器」，本节以 SPI1 为例整条打通。

每个 SPI 控制器对外暴露的东西就这么多：

项 SPI0 SPI1 说明
寄存器基址 S3C24XX_PA_SPI0（0x59000000） S3C24XX_PA_SPI1（0x59000020） 在 arch/arm/plat-samsung/include/plat/regs-spi.h 定义
资源大小 SZ_32 SZ_32 32 字节，7 个 8 位寄存器绰绰有余
中断号 IRQ_SPI0（28） IRQ_SPI1（29） 原文只明确给出 SPI1 = 29，SPI0 = 28 为推算，未逐个核对
数据引脚 GPG2/3/4 GPG5/6/7 MISO/MOSI/CLK
片选 走 GPIO，非硬件 CS 走 GPIO，非硬件 CS 这是这颗 SoC 的关键特征
控制器编号 bus_num = 0 bus_num = 1 由 platform data 传入

寄存器共 7 个，偏移从 0x00 到 0x18：

偏移 寄存器 全名 干什么
0x00 SPCON SPI Control 主从模式、收发模式、时钟极性/相位、SCK 使能
0x04 SPSTA SPI Status 传输就绪、冲突检测、多主错误
0x08 SPPIN SPI Pin Control 片选引脚是否由硬件自动控制
0x0C SPPRE SPI Baud Rate Prescaler 分频系数，决定 SCK 频率
0x10 SPTDAT SPI Tx Data 写这里 = 发起一次发送
0x14 SPRDAT SPI Rx Data 读这里 = 取走一个收到的字节
0x18 — 原文未列出 S3C2410 手册里 0x18 不存在独立寄存器，资源给的 32 字节是取整

SPCON 与 SPSTA 的位定义（原文出现过的）：

寄存器 位 宏 含义
SPCON [1:0] — SMOD：00 从机 / 01 主机 / 10 固件模式
SPCON [3] SPCON_DEFAULT 含 1<<3 中断模式使能
SPCON [5] — 原文注释称为「主机模式位」，宏里并未置位，见第七章勘误
SPCON [6] S3C2410_SPCON_ENSCK SCK 使能，收发期间必须置位
SPSTA bit0 S3C2410_SPSTA_READY 数据就绪：可写 SPTDAT / SPRDAT 已有数据
SPSTA bit2 S3C2410_SPSTA_DCOL Data Collision，多主冲突
SPSTA bit3 S3C2410_SPSTA_MULD Multi Master 错误，原文未使用

这张家底决定了后面所有代码形状：没有硬件片选，所以片选只能落到 GPIO 上，s3c2410_spi_info 里才有 pin_cs；收发共用一个就绪位，所以中断里读写必须成对，且只能靠 hw->count 自己数到哪了。

二、硬件连接与引脚配置 #

三个数据脚必须复用成 SPI 功能，片选脚必须当普通 GPIO 输出用。

引脚 功能 复用值 复用值来源
S3C2410_GPG(5) SPIMISO1 S3C2410_GPG5_SPIMISO1（2<<10） arch/arm/mach-s3c24xx/include/mach/regs-gpio.h
S3C2410_GPG(6) SPIMOSI1 S3C2410_GPG6_SPIMOSI1（2<<12） 同上
S3C2410_GPG(7) SPICLK1 S3C2410_GPG7_SPICLK1（2<<14） 同上
S3C2410_GPG(3) 片选（选 GPIO） 不配置复用，当 GPIO_OUTPUT 由 platform data 的 pin_cs 指定

括号里的 2<<10 是复用功能编号在 GPG 控制寄存器里的位置，不是最终寄存器值。实际写入由 s3c_gpio_cfgpin() 完成。

板级代码放在 arch/arm/mach-s3c24xx/setup-spi.c：

c
#include <linux/spi/s3c24xx.h>
#include <mach/gpio-samsung.h>

void s3c24xx_spi1_cfg_gpio(struct s3c2410_spi_info *spi, int enable)
{
	s3c_gpio_cfgpin(S3C2410_GPG(5), S3C2410_GPG5_SPIMISO1);
	s3c_gpio_cfgpin(S3C2410_GPG(6), S3C2410_GPG6_SPIMOSI1);
	s3c_gpio_cfgpin(S3C2410_GPG(7), S3C2410_GPG7_SPICLK1);
}

注意这个函数没有用 enable 参数。理论上 enable 为 0 该恢复成 GPIO、为 1 该复用成 SPI，但 S3C24XX 这版无条件复用，驱动卸载后引脚不会还回去。实际没人卸载 SPI 控制器，问题没暴露。

同样的函数在 5.2.8 里还有一份「标准版」在 arch/arm/mach-s3c24xx/common-spi.c，条件编译在 CONFIG_S3C24XX_SETUP_SPI 之下。原文把 Makefile 里那行 #obj-$(CONFIG_S3C2443_SETUP_SPI) += setup-spi.o 注掉、换成 obj-$(CONFIG_ARCH_S3C24XX) += setup-spi.o，避免和 common 里的定义撞车。 setup-spi.c 这个文件名有历史包袱，S3C2443 那套也在抢。原文注掉原行换成 ARCH_S3C24XX，代价是 S3C2443 平台受影响。更干净的做法是新建独立文件名（如 setup-spi-smdk2440.c），只挂到自己的机器配置上——这是我补的建议，原文没提，属于未验证改动。

三、platform 设备注册（s3c2410-spi） #

controller 驱动是标准 platform 模型。设备侧信息在 arch/arm/plat-samsung/devs.c：

c
static struct resource s3c_spi1_resource[] = {
	[0] = DEFINE_RES_MEM(S3C24XX_PA_SPI1, SZ_32),
	[1] = DEFINE_RES_IRQ(IRQ_SPI1),
};

struct platform_device s3c_device_spi1 = {
	.name           = "s3c2410-spi",
	.id             = 1,
	.num_resources  = ARRAY_SIZE(s3c_spi1_resource),
	.resource       = s3c_spi1_resource,
	.dev            = {
		.dma_mask               = &samsung_device_dma_mask,
		.coherent_dma_mask      = DMA_BIT_MASK(32),
	}
};

两个资源：IORESOURCE_MEM 起始 0x59000020、长度 32 字节；IORESOURCE_IRQ 为 29。dma_mask 用了一个 lambda 式写法 #define samsung_device_dma_mask (*((u64[]) { DMA_BIT_MASK(32) }))：取匿名数组首元素的左值，能当地址传，是内核里常见的一次性掩码定义法，别在用户态照抄。s3c_device_spi1 已在 arch/arm/plat-samsung/include/plat/devs.h 里 extern 导出，机器代码直接引用符号即可。

机器代码在 arch/arm/mach-s3c24xx/mach-smdk2440.c 里要加三处：

处 位置 加什么
1 smdk2440_machine_init 体内 一行 s3c_spi1_set_platdata(&s3c2440_spi1_data);
2 同文件 platform data 与 s3c_spi1_set_platdata，外加三个头文件
3 smdk2440_devices[] 原有六项之后补 &s3c_device_spi1 
c
#include <linux/platform_data/spi-s3c2410.h>
#include <linux/spi/s3c24xx.h>
#include <mach/gpio-samsung.h>

struct s3c2410_spi_info s3c2440_spi1_data = {
	.pin_cs     = S3C2410_GPG(3),      /* GPG3 当片选 */
	.num_cs     = 1,                   /* 一个从设备 */
	.bus_num    = 1,                   /* SPI 控制器编号 */
	.use_fiq    = 0,                   /* 关 FIQ，走 IRQ */
	.gpio_setup = s3c24xx_spi1_cfg_gpio
};

void __init s3c_spi1_set_platdata(struct s3c2410_spi_info *pd)
{
	struct s3c2410_spi_info *npd;

	npd = s3c_set_platdata(pd, sizeof(*npd), &s3c_device_spi1);

	if (!npd)
		printk(KERN_ERR "no memory for SPI platform data\n");
}

s3c_set_platdata 是三星平台的通用辅助函数：kmemdup 一份 platform data 挂到 dev.platform_data，这样 __initdata 段释放后数据还在。别直接 pdev->dev.platform_data = pd，那指向 init 段内存，启动完就失效。

还有一个小头文件 include/linux/platform_data/spi-s3c2410.h，原文给的是「只放一句 extern」的精简版，内容为 extern void s3c24xx_spi1_cfg_gpio(struct s3c2410_spi_info *spi, int enable);。两个坑原文没纠：原注释写「S3C - I2C Controller platform_device info」是复制残留，应为 SPI；#define __SPI_S3C2410_H __FILE__ 是内核老式写法，无害但没必要。5.2.8 里这个头文件已存在且含该声明，原文「创建」应改为「确认存在 / 补充声明」。

四、platform 驱动注册（s3c2410-spi） #

驱动本体在 drivers/spi/spi-s3c24xx.c。入口出口就是一个 platform_driver：.probe = s3c24xx_spi_probe、.remove = s3c24xx_spi_remove、.driver.name = "s3c2410-spi"、.driver.pm = S3C24XX_SPI_PMOPS，末尾 module_platform_driver(s3c24xx_spi_driver)；另外一句 MODULE_ALIAS("platform:s3c2410-spi") 供模块自动加载用。设备名与驱动 .name 一致，platform 总线靠这个字符串完成匹配再回调 .probe，链条上没有 ID 表，是纯名字匹配。

驱动私有的三个结构体必须先理清，不然 probe 读不下去。s3c24xx_spi 是每颗控制器的运行时状态：

c
struct s3c24xx_spi {
	/* bitbang has to be first */
	struct spi_bitbang       bitbang;
	struct completion        done;

	void __iomem            *regs;
	int                      irq;
	int                      len;
	int                      count;

	struct fiq_handler       fiq_handler;
	enum spi_fiq_mode        fiq_mode;
	unsigned char            fiq_inuse;
	unsigned char            fiq_claimed;

	void                    (*set_cs)(struct s3c2410_spi_info *spi,
	                                  int cs, int pol);

	/* data buffers */
	const unsigned char     *tx;
	unsigned char           *rx;

	struct clk              *clk;
	struct spi_master       *master;
	struct spi_device       *curdev;
	struct device           *dev;
	struct s3c2410_spi_info *pdata;
};

几个字段的用途：

字段 作用 关键点
bitbang 借用 bitbang 框架填 core 回调 必须第一个，spi_master_get_devdata() 要能直接当 spi_bitbang * 用
done 传输完成同步 txrx 里 wait_for_completion，中断里 complete
regs / irq 寄存器虚拟基址 / 中断号 devm_ioremap_resource、platform_get_irq
len / count 本次传输总长 / 已完成字节数 全双工，收发长度一致
fiq_* FIQ 快中断通道 use_fiq = 0，这套完全不走
set_cs 片选回调 指向 s3c24xx_spi_gpiocs 或 platform data 的 set_cs
tx / rx 收发缓冲 来自 spi_transfer
clk / master SPI 模块时钟 / 反向指回控制器 devm_clk_get / spi_master_get_devdata 的逆操作
curdev 当前设备 原文代码里实际未使用
pdata platform data 注释称默认 &default_spi_data，实际见第八章

「bitbang 必须放第一个」的来源：spi_bitbang_init() 用 spi_master_get_devdata(master) 拿私有数据后整体当 struct spi_bitbang * 用。bitbang 不在偏移 0 就会拿到垃圾。

s3c2410_spi_info 是板级传入的配置：

字段 板级必填 说明
pin_cs 是 片选 GPIO 编号，< 0 且无 set_cs 会被 probe 拒掉
num_cs 是 挂几个从设备，写进 master->num_chipselect
bus_num 是 写进 master->bus_num，决定 /dev/spidev1.x 前缀
use_fiq 是 原文填 0。填 1 走 FIQ 路径，需额外平台支持
gpio_setup 是 三个数据脚的复用配置函数
set_cs 否 留空则 probe 用 s3c24xx_spi_gpiocs 自己管 GPIO 片选

s3c24xx_spi_devstate 是每设备的寄存器快照，缓存在 spi->controller_state 里，四个字段依次是 hz（上次算过的频率）、mode（上次的 spi->mode）、spcon（写进 SPCON 的值）、sppre（写进 SPPRE 的值）。这么设计是因为每次收发都重算分频太贵，SPCON 又在片选切换时被反复改写；把「这个从设备该用什么 spcon/sppre」算一次存起来，chipsel 和 setupxfer 直接 writeb 快照值，hz 相等就跳过重算。

五、s3c24xx_spi_probe 的调用栈 #

probe 本身 120 行，但它只是调度中心，真正的活儿散在 9 个函数里。先看全景：

text
s3c24xx_spi_probe()
├─ spi_alloc_master() + spi_master_get_devdata()      master / hw
├─ dev_get_platdata() / platform_set_drvdata() / init_completion()
├─ 填 master->{mode_bits,num_chipselect,bus_num,bits_per_word_mask}
├─ 填 hw->bitbang.{master,setup_transfer,chipselect,txrx_bufs}
├─ master->setup = s3c24xx_spi_setup
├─ platform_get_resource(MEM,0) → devm_ioremap_resource   → hw->regs
├─ platform_get_irq(pdev,0) → devm_request_irq(s3c24xx_spi_irq)
├─ devm_clk_get(&pdev->dev, "spi")               → hw->clk
├─ devm_gpio_request(pdata->pin_cs) + gpio_direction_output
├─ s3c24xx_spi_initialsetup(hw)
│   ├─ clk_enable + writeb SPPRE/SPPIN/SPCON
│   └─ pdata->gpio_setup(pdata, 1)               → s3c24xx_spi1_cfg_gpio
└─ spi_bitbang_start(&hw->bitbang)
    ├─ spi_bitbang_init：填 prepare/unprepare_transfer_hardware、
    │                    transfer_one、set_cs
    └─ spi_register_master(spi_master_get(master))
        ├─ spi_match_controller_to_boardinfo()
        └─ spi_new_device()  → 触发 master->setup

调用链分两条时间轴，必须分开看：

时机 触发者 走到哪
控制器注册时（probe 内） s3c24xx_spi_probe s3c24xx_spi_initialsetup 一次性写好寄存器默认值
从设备注册时 spi_register_master → spi_new_device master->setup，即 s3c24xx_spi_setup，按设备重算寄存器
每次传输前 SPI core setup_transfer → 写 SPPRE
每次传输开始/结束 SPI core set_cs → chipsel → 改 SPCON + 拉 GPIO
传输进行中 硬件中断 s3c24xx_spi_irq 逐字节推进

原文这里有两句要纠：注释写「s3c24xx_spi_initialsetup → 调用 s3c24xx_i2c_init 初始化 SPI 相关寄存器」，但 s3c24xx_i2c_init 是 I2C 驱动的函数，跟 SPI 无关，实际是函数体内直接 writeb；另一处写「最后将 spi_controller 注册到 spi_bus_type 总线」，而控制器挂的是 platform 总线，spi_bus_type 是给从设备用的，且 spi_register_master 是先做 spi_match_controller_to_boardinfo 扫 board_list 再决定要不要 spi_new_device，原文把因果和总线都混了。

六、probe 里的资源获取顺序 #

顺序不是随意的，每一步都在为下一步铺路。按原文代码的实际执行序列排：

步 操作 拿到什么 失败后果 失败跳转
1 spi_alloc_master master + 私有区 -ENOMEM，直接 return —
2 spi_master_get_devdata hw 不会失败 —
3 dev_get_platdata pdata -ENOENT err_no_pdata
4 platform_set_drvdata / init_completion — 不会失败 —
5 填 master 四个字段 + hw->bitbang 四个回调 控制器身份与传输路径 — —
6 platform_get_resource(MEM,0) res 未判空，直接给下一步 —
7 devm_ioremap_resource hw->regs IS_ERR 判断 err_no_pdata
8 platform_get_irq(pdev,0) hw->irq < 0 则 -ENOENT err_no_pdata
9 devm_request_irq 中断注册 非 0 err_no_pdata
10 devm_clk_get("spi") hw->clk IS_ERR err_no_pdata
11 devm_gpio_request(pin_cs) 片选 GPIO 非 0 err_register
12 gpio_direction_output(pin_cs,1) 片选默认释放 — —
13 s3c24xx_spi_initialsetup 寄存器已初始化 无返回值 —
14 spi_bitbang_start 控制器上线 非 0 err_register

几条从这张表能直接看出来的事实：

内存先于中断。 中断处理函数要用 hw->regs 读 SPSTA，所以 7 必须在 9 之前；写反了就是中断里访问空指针。

时钟最后拿。 第 10 步在中断注册之后、GPIO 之前。这埋了第十四章那个坑的根：时钟查不到时前面几步的资源已申请，靠 devm 自动回收，但 initialsetup 里的 clk_enable 会在没有 clk_prepare_enable 的情况下裸调。

错误标签只有两个，且不完整。 err_register 只做一件事：clk_disable(hw->clk)。注意是 clk_disable 不是 clk_disable_unprepare，因为这版根本没有 clk_prepare_enable，见第十四章。err_no_pdata 做的是 spi_master_put(hw->master)，它是 spi_alloc_master 的配对操作，少调一次就泄漏一个 spi_master；devm 管不了它，因为 spi_master 是 SPI core 自己 kzalloc 的，不在 devres 链上。

第 6 步没判空。 platform_get_resource 返回 NULL 时 devm_ioremap_resource 内部会处理并返 -EINVAL（5.2.8 有此检查），不崩，只是错误码从 -ENODEV 变成 -EINVAL。可接受但不严谨。

第 11、12 步重复。 gpio_direction_output(pdata->pin_cs, 1) 在 probe 里做一次，initialsetup 里又做一次，都无害，纯冗余。

七、寄存器映射与初始化 #

映射用 devm_ioremap_resource，一行搞定「取资源 → request_mem_region → ioremap → 挂 devres」：res = platform_get_resource(pdev, IORESOURCE_MEM, 0)，再 hw->regs = devm_ioremap_resource(&pdev->dev, res)，IS_ERR 则 PTR_ERR 后跳 err_no_pdata。拿到的是 0x59000020 的虚拟地址。之后所有寄存器操作都是 hw->regs + 偏移，用 8 位访问：

操作 代码 访问宽度
读状态 readb(hw->regs + S3C2410_SPSTA) 8 位
写控制 writeb(cs->spcon, hw->regs + S3C2410_SPCON) 8 位
写数据 writeb(hw_txbyte(hw, 0), hw->regs + S3C2410_SPTDAT) 8 位
读数据 readb(hw->regs + S3C2410_SPRDAT) 8 位

readb/writeb 带内存屏障语义，不要换成普通指针解引用。这颗 SoC 的 SPI 寄存器只有 8 位宽，用 readl 会一次读 4 个寄存器，副作用是 SPRDAT 被意外清掉。初始化函数：

c
static void s3c24xx_spi_initialsetup(struct s3c24xx_spi *hw)
{
	/* for the moment, permanently enable the clock */
	clk_enable(hw->clk);

	/* program defaults into the registers */
	writeb(0xff, hw->regs + S3C2410_SPPRE);
	writeb(SPPIN_DEFAULT, hw->regs + S3C2410_SPPIN);
	writeb(SPCON_DEFAULT, hw->regs + S3C2410_SPCON);

	if (hw->pdata) {
		if (hw->set_cs == s3c24xx_spi_gpiocs)
			gpio_direction_output(hw->pdata->pin_cs, 1);
		if (hw->pdata->gpio_setup)
			hw->pdata->gpio_setup(hw->pdata, 1);
	}
}

逐句拆：

clk_enable(hw->clk)。注释写得很直白：for the moment, permanently enable the clock，即「先这么凑合着，时钟常开」。这是 2009 年那版的临时方案，到 5.2.8 都没改。两个问题：没有 clk_prepare_enable（prepare/enable 是两级，能睡眠的必须在进程上下文先 prepare）；remove 里也没配对关掉。结果就是 S3C24XX 的 SPI 时钟一旦开了永不关闭。

writeb(0xff, SPPRE)。分频系数先给最大值 255，最慢的 SCK。安全默认值：还没人说要跑多快，先保证不超从设备上限。

writeb(SPPIN_DEFAULT, SPPIN)。SPPIN 控制空闲时各脚是否上拉、以及是否启用硬件 CS 自动控制。5.2.8 里 SPPIN_DEFAULT 是 S3C2410_SPPIN_ENMUL | S3C2410_SPPIN_KEEP，即「多主错误检测使能 + 数据保持」。

writeb(SPCON_DEFAULT, SPCON)。原文注释写「主机模式、中断查询 1<<5 || 1<<3」。要纠三点：|| 是笔误应为 |；两位或起来是 0x28；而 5.2.8 的实际定义是 (S3C2410_SPCON_MODE_TX_RX | S3C2410_SPCON_INT_EN)，即「收发模式 + 中断使能」，对应注释里的 1<<3。注释说的 1<<5 主机位在这个宏里并没有置位，主机身份靠 [1:0] 的 SMOD 字段。照着注释读寄存器会读错，这是原文最误导的一处。

gpio_direction_output(pin_cs, 1)。片选默认拉高即不选中。高低电平哪个算选中取决于 SPI_CS_HIGH，先给「非选中」的值。

gpio_setup(hw->pdata, 1)。三个数据脚复用到 SPI1。不一定要在寄存器编程之后，但必须在 spi_bitbang_start 之前，否则从设备一出现就即有传输打到没配置的引脚上。

Initialsetup 之后的寄存器状态：SPPRE = 0xff（分频 256，SCK 最慢）、SPPIN = SPPIN_DEFAULT、SPCON = SPCON_DEFAULT（收发 + 中断使能，等设备 setup 再定模式）、SPTDAT/SPRDAT 未动、片选 GPIO 输出高（不选中）、GPG5/6/7 已复用 SPI1。

八、spi_controller 的分配与填充 #

spi_alloc_master(&pdev->dev, sizeof(struct s3c24xx_spi)) 干两件事：分配 struct spi_master，再额外分配 size 大小的私有区挂在 master->dev.driver_data；spi_master_get_devdata() 取回来就是 hw。5.2.8 的 spi_alloc_master 内部走 __spi_alloc_controller(dev, size, false)，第二参 false 表示「非 slave 模式」——所以分出来的其实是 controller，只是符号名还叫 master。私有区刚好是 sizeof(struct s3c24xx_spi)，因为 hw 要存全部运行时状态，而 bitbang 又在 hw 里；这也再次解释了 bitbang 必须放第一个。

master 侧要填的字段，按原文代码逐项列：

字段 值 谁用
mode_bits SPI_CPOL | SPI_CPHA | SPI_CS_HIGH spi_new_device 校验从设备 mode，超出范围直接拒
num_chipselect hw->pdata->num_cs 从设备 chip_select 上界校验
bus_num pdata->bus_num 拼 /dev/spidev1.x、/sys/class/spi_master/spi1
bits_per_word_mask SPI_BPW_MASK(8) 只支持 8 位字
setup s3c24xx_spi_setup 从设备注册时调
prepare_transfer_hardware spi_bitbang_prepare_hardware spi_bitbang_init 填
unprepare_transfer_hardware spi_bitbang_unprepare_hardware spi_bitbang_init 填
transfer_one spi_bitbang_transfer_one spi_bitbang_init 填
set_cs spi_bitbang_set_cs spi_bitbang_init 填
cleanup 不填 因为 txrx_bufs 已给，走不到 spi_bitbang_cleanup

SPI_BPW_MASK(8) 展开是 BIT(8) - 1，等于 0x80。原文注释写「设置为 bit_per_world 的掩码，等于 bits_per_word-1，比如这里就是 7」——这句是错的。掩码是「第 8 位为 1」即 0x80，不是 7；7 是 SPI_BPW_MASK(3)。字段名是 bits_per_word_mask，注释拼成 bit_per_world 也是笔误。

hw->bitbang 四个回调与 master->setup 的填法分别是 master/setup_transfer = s3c24xx_spi_setupxfer/chipselect = s3c24xx_spi_chipsel/txrx_bufs = s3c24xx_spi_txrx，外加 hw->master->setup = s3c24xx_spi_setup。设计上有一点要注意：S3C24XX 是真硬件 SPI（有移位器、有中断、有 FIFO 语义），但没走纯硬件驱动那条路，而是借道 spi_bitbang 框架。原因是 2009 年写这版时 transfer_one/transfer_one_message 这套逐 transfer 的接口还不成熟，bitbang 提供了现成的 message 队列、片选管理和 setup_transfer 钩子。收益是代码量小，代价是每个 spi_transfer 都要过一次 spi_bitbang_transfer_one 的公共逻辑；对一次最长几十字节的场景完全无所谓。

hw->dev = &pdev->dev 与 platform_set_drvdata(pdev, hw) 方向相反：前者往上查父设备，后者往下挂私有数据。中断处理、dev_dbg 都靠 hw->dev。

hw->pdata = pdata = dev_get_platdata(&pdev->dev) 之后立刻判空，NULL 就 -ENOENT 退出。结构体注释里那句「pdata 默认初始化为 &default_spi_data」在 5.2.8 这条路径上不成立：没有兜底默认值，漏填 platform data 就跑不起来。

九、spi_algorithm 与 transfer_one_message #

先破一个常见误解：S3C24XX 这条路径上没有 spi_algorithm 结构体。

struct spi_algorithm 是 SPI 核心层给「bit-banging 与底层算法分离」留的位置，形如 configure() / xfer() / cs_control() 三个回调。5.2.8 的 spi-s3c24xx.c 里没有这个东西，用的是 struct spi_bitbang，载体是 bitbang->chipselect / bitbang->txrx_bufs / bitbang->setup_transfer，功能上等价于算法层那三个函数，但字段名和签名都不是 spi_algorithm。真正决定传输怎么走的是 SPI core 的 spi_transfer_one_message：遍历 message->transfers，每个 transfer 调一次 master->transfer_one，全部成功后调 spi_finalize_current_message。

c
static int spi_bitbang_transfer_one(struct spi_master *master,
                                    struct spi_device *spi,
                                    struct spi_transfer *transfer)
{
	struct spi_bitbang *bitbang = spi_master_get_devdata(master);
	int status = 0;

	if (bitbang->setup_transfer) {
		status = bitbang->setup_transfer(spi, transfer);
		if (status < 0)
			goto out;
	}

	if (transfer->len)
		status = bitbang->txrx_bufs(spi, transfer);

	if (status == transfer->len)
		status = 0;
	else if (status >= 0)
		status = -EREMOTEIO;

out:
	spi_finalize_current_transfer(master);

	return status;
}

三者逻辑：

第一段，setup_transfer。 指向 s3c24xx_spi_setupxfer，按本 transfer 的 speed_hz 重算并写 SPPRE。这是唯一改速率的地方，所以同一个 message 里不同 transfer 可以跑不同频率。

第二段，txrx_bufs。 指向 s3c24xx_spi_txrx，返回值是实际完成的字节数，不是错误码，这个约定容易记混。

第三段，长度校验。 返回值和 transfer->len 比较，相等返回 0，否则 -EREMOTEIO。中断里提前 complete 一个不完整传输，上层就拿到 -EREMOTEIO，在 spidev 里表现为 EIO。

out: 无条件走 spi_finalize_current_transfer(master)，包括 setup_transfer 失败的情况，所以 message 队列不会卡住、失败正常上报。这一步唤醒 core 继续处理下一个 transfer；漏调就是总线挂死，SPI_IOC_MESSAGE 永远不返回。这是写 controller 驱动最容易踩的坑之一，跟 S3C24XX 无关，是 framework 层面必须遵守的契约。

s3c24xx_spi_setupxfer 只有两步：s3c24xx_spi_update_state(spi, t) 重算快照，成功后 writeb(cs->sppre, hw->regs + S3C2410_SPPRE) 把分频落盘。to_hw(spi) 就是 spi_master_get_devdata(spi->master) 的包装。spi->controller_state 是每个从设备的私有存储，由 SPI core 保证传到每个回调；s3c24xx_spi_setup 里首次分配，之后 setupxfer/chipsel 都从这里取快照。

十、一次传输的寄存器操作序列 #

我们从上层 write() 到字节落地，以一次 4 字节全双工传输为例：

text
用户 write() / SPI_IOC_MESSAGE
  └─ spidev → spi_sync → spi_transfer_one_message
       ├─ master->set_cs(spi, true)                spi_bitbang_set_cs
       │    └─ chipselect(ACTIVE) → s3c24xx_spi_chipsel
       │         ├─ writeb(cs->spcon | SPCON_ENSCK, SPCON)   先使能 SCK
       │         └─ set_cs(pdata, chip, cspol)              后拉 GPIO
       ├─ master->transfer_one(spi, transfer)      spi_bitbang_transfer_one
       │    ├─ setup_transfer → s3c24xx_spi_setupxfer  写 SPPRE
       │    └─ txrx_bufs → s3c24xx_spi_txrx
       │         ├─ 存 tx/rx/len，count=0，init_completion
       │         ├─ writeb(hw_txbyte(hw,0), SPTDAT)   ← 第 1 字节
       │         └─ wait_for_completion()             ← 线程睡眠
       │              ⋮  [中断 × 4]  ⋮
       │         └─ 返回 hw->count
       └─ master->set_cs(spi, false)               spi_bitbang_set_cs
            └─ chipselect(INACTIVE)
                 ├─ set_cs(pdata, chip, cspol^1)      先拉高 GPIO
                 └─ writeb(cs->spcon, SPCON)          后撤 ENSCK

逐字节阶段（中断里做的事）：

中断次数 读 SPRDAT 存入 写 SPTDAT hw->count 后
第 1 次 rx[0] ← 第 1 字节 第 2 字节 1
第 2 次 rx[1] 第 3 字节 2
第 3 次 rx[2] 第 4 字节 3
第 4 次 rx[3] 不写，complete() 4

关键点：写 SPTDAT 是发起动作，不是「把数据放进缓冲」。写进去的瞬间硬件就开始移位输出，同时以同一时钟采回从设备的数据。所以第 1 个字节在 txrx_bufs 里写，后 3 个在中断里写，一共 4 次写、4 次中断、4 次读。hw_txbyte(hw, N) 展开是 ((hw)->tx ? (hw)->tx[N] : 0)，tx 为 NULL 时发 0。这就是「只关心接收」场景的实现方式：tx_buf 传 NULL，硬件仍产生 8 个时钟，从设备把数据推回来。原文那句「缓冲区为空时发送的数据是 0」说的是同一件事。

片选阶段两个顺序细节不能错：置 SCK 使能在拉 CS 之前（ACTIVE 分支先 writeb(spcon | SPCON_ENSCK) 再 set_cs，反过来 CS 已拉低但 SCK 没使能，从设备会看到一段无时钟的空窗）；清 CS 在撤 SCK 之后（INACTIVE 分支先 set_cs 拉高再清 ENSCK，保证最后一个字节的时钟完整输出后才停）。两段 ndelay(SPI_BITBANG_CS_DELAY) 是 bitbang 框架加的片选建立/保持时间，跟 S3C24XX 无关，具体值见 drivers/spi/spi-bitbang.c，原文未展开。

片选极性：cspol = spi->mode & SPI_CS_HIGH ? 1 : 0，ACTIVE 传 cspol，INACTIVE 传 cspol^1。低电平选中时拉 0、释放拉 1；高电平选中时反之。spi_bitbang_set_cs 在调 chipselect 之前还做一次 enable = (!!(spi->mode & SPI_CS_HIGH) == enable)，把 core 的「逻辑选中」翻译成 bitbang 层的「电气极性」。

s3c24xx_spi_chipsel 完整代码：

c
static void s3c24xx_spi_chipsel(struct spi_device *spi, int value)
{
	struct s3c24xx_spi_devstate *cs = spi->controller_state;
	struct s3c24xx_spi *hw = to_hw(spi);
	unsigned int cspol = spi->mode & SPI_CS_HIGH ? 1 : 0;

	switch (value) {
	case BITBANG_CS_INACTIVE:                   /* 释放：先拉高，后撤 SCK */
		hw->set_cs(hw->pdata, spi->chip_select, cspol^1);
		writeb(cs->spcon, hw->regs + S3C2410_SPCON);
		break;
	case BITBANG_CS_ACTIVE:                     /* 选中：先使能 SCK，后拉低 */
		writeb(cs->spcon | S3C2410_SPCON_ENSCK,
		       hw->regs + S3C2410_SPCON);
		hw->set_cs(hw->pdata, spi->chip_select, cspol);
		break;
	}
}

s3c24xx_spi_gpiocs 只有一行 gpio_set_value(spi->pin_cs, pol);。注意它忽略 cs 参数：num_cs = 1 时没问题，要挂两个从设备这个函数必须改写，因为 pin_cs 只有一个。原文只支持单从设备，num_cs 的表里没写清，容易误以为填 2 就能用。

十一、中断处理与传输完成判定 #

c
static irqreturn_t s3c24xx_spi_irq(int irq, void *dev)
{
	struct s3c24xx_spi *hw = dev;
	unsigned int spsta = readb(hw->regs + S3C2410_SPSTA);
	unsigned int count = hw->count;

	if (spsta & S3C2410_SPSTA_DCOL) {           /* 冲突，收工 */
		dev_dbg(hw->dev, "data-collision\n");
		complete(&hw->done);
		goto irq_done;
	}
	if (!(spsta & S3C2410_SPSTA_READY)) {       /* 未就绪，收工 */
		dev_dbg(hw->dev, "spi not ready for tx?\n");
		complete(&hw->done);		goto irq_done;
	}

	if (!s3c24xx_spi_usingfiq(hw)) {
		hw->count++;
		if (hw->rx)
			hw->rx[count] = readb(hw->regs + S3C2410_SPRDAT);
		count++;
		if (count < hw->len)
			writeb(hw_txbyte(hw, count), hw->regs + S3C2410_SPTDAT);
		else
			complete(&hw->done);
	} else {                                    /* FIQ 路径，本板不执行 */
		hw->count = hw->len;
		hw->fiq_inuse = 0;
		if (hw->rx)
			hw->rx[hw->len-1] = readb(hw->regs + S3C2410_SPRDAT);
		complete(&hw->done);
	}

 irq_done:
	return IRQ_HANDLED;
}

六个判定点走一遍： 判定点 1、2：DCOL 冲突与 READY 未就绪。 前者是总线上两个设备同时驱动 MISO，数据不可信；后者是伪中断或硬件异常。两者都直接 complete() 收工，且都不更新 hw->count，于是 txrx_bufs 返回「完成了一部分」，spi_bitbang_transfer_one 转成 -EREMOTEIO，上层能感知失败。

这两个分支都用 goto irq_done 跳过正常流程，但没有清 SPSTA 的错误位。S3C2410 的 SPSTA 靠「读一次 SPRDAT」清错误位。原文没清，下次传输如果错误位还在会立刻再走一次冲突分支。这是原文代码的缺陷，实践中要补一次 readb(SPRDAT)。

判定点 3：count 与 hw->count 的配合。 局部 count 是进中断时 hw->count 的快照。hw->count++ 后，rx[count] 正好是第 N+1 字节的位置，count++ 后是下一个要发的下标。以 len = 4 走一遍：

中断 进入时 hw->count 局部 count 写 rx[count] count 后 count < 4 动作
1 0 0 rx[0] 1 是 发 tx[1]
2 1 1 rx[1] 2 是 发 tx[2]
3 2 2 rx[2] 3 是 发 tx[3]
4 3 3 rx[3] 4 否 complete()

下标用快照而不是 hw->count++ 之后的值，这是对的，写反会差一位。

判定点 4：FIQ 分支。 s3c24xx_spi_usingfiq(hw) 为真说明这次走了 FIQ 通道，IRQ 只在最后一个字节触发，所以直接把 hw->len - 1 读掉收工。本板 use_fiq = 0，这条路径不执行，属于编译进去的死代码。

complete(&hw->done) 唤醒 s3c24xx_spi_txrx 里 wait_for_completion 的线程，之后 txrx_bufs 返回 hw->count 与 transfer->len 比较。「传输完成」的判定有三层，别混：

层 判定条件 在哪判
硬件 SPSTA & READY，且已发满 len 个字节 中断里
驱动 hw->count == hw->len spi_bitbang_transfer_one 的 status == transfer->len
core transfer 全部成功 spi_finalize_current_transfer 之后继续下一个 transfer

s3c24xx_spi_txrx 本体：

c
static int s3c24xx_spi_txrx(struct spi_device *spi, struct spi_transfer *t)
{
	struct s3c24xx_spi *hw = to_hw(spi);

	hw->tx = t->tx_buf;
	hw->rx = t->rx_buf;
	hw->len = t->len;
	hw->count = 0;

	init_completion(&hw->done);

	hw->fiq_inuse = 0;
	if (s3c24xx_spi_usefiq(hw) && t->len >= 3)
		s3c24xx_spi_tryfiq(hw);

	/* send the first byte */
	writeb(hw_txbyte(hw, 0), hw->regs + S3C2410_SPTDAT);

	wait_for_completion(&hw->done);
	return hw->count;
}

init_completion 每次传输重来一次，不是 reinit_completion：语义等价但更重。t->len >= 3 是 FIQ 路径的启用门槛，短传输用 FIQ 反而开销大。txrx_bufs 在进程上下文执行（spi_sync 路径），wait_for_completion 会睡眠；spi_async 路径下在 worker 线程里也能睡，中断上下文里不能用。

十二、时钟分频与速率配置 #

SPPRE 是 8 位分频寄存器，公式（S3C2410 数据手册）为 SCK = PCLK / (2 × (SPPRE + 1))。SPPRE 取值 0..255，分频比从 2 到 512；initialsetup 写 0xff，即 PCLK / 512。S3C2440 在 400 MHz 主频下 PCLK 常见 66.5 MHz 或 50 MHz，取决于 MPLLCON/CLKDIVN 的配法。原文没给具体 PCLK 值，下表按两个常见值各算一遍，你照自己板子的 PCLK 用同样方法算：

SPPRE 分频比 SCK @ PCLK=66.5 MHz SCK @ PCLK=50 MHz
0 2 33.25 MHz 25 MHz
3 8 8.31 MHz 6.25 MHz
7 16 4.16 MHz 3.125 MHz
15 32 2.08 MHz 1.5625 MHz
31 64 1.039 MHz 781.25 kHz
63 128 519.5 kHz 390.6 kHz
127 256 259.8 kHz 195.3 kHz
255 512 129.9 kHz 97.7 kHz

反向计算：div = PCLK / speed_hz / 2（向下取整），SPPRE = clamp(div - 1, 0, 255)。实际选取要在「不超过从设备上限」的前提下取最接近的值，也就是让 SPPRE 尽量小。

s3c24xx_spi_update_state 做的就是这件事，原文没贴实现，只说「根据 spi->mode、spi->max_speed_hz 计算 SPCON、SPPRE 的值」。函数体原文未给出，上面的反向公式是按手册推的，取整方向和边界处理（比如 speed_hz = 0）未验证，以 5.2.8 源码为准。SPPRE 落盘的三个时机要分清：

时机 谁写 写什么
控制器初始化 s3c24xx_spi_initialsetup 固定 0xff，最慢
从设备注册 s3c24xx_spi_setup → update_state 算快照，不写寄存器
每次传输 s3c24xx_spi_setupxfer 写 cs->sppre

setup 阶段只算不写，真正改速率是 setupxfer 在传输开始时做的。好处是注册时不碰硬件，坏处是注册完到第一次传输之间寄存器里还是 0xff，从设备若此时采样 SCK 会看到最慢的时钟。

时钟极性与相位：SPI_CPOL（bit1）映射到 SPCON 的 CPOL，决定空闲电平（0 低、1 高）；SPI_CPHA（bit0）映射到 CPHA，决定采沿（0 第一沿、1 第二沿）。mode_bits = SPI_CPOL | SPI_CPHA | SPI_CS_HIGH 表示支持模式 0/1/2/3 全部四种且支持高片选；设备侧配了这四种之外的组合（SPI_LSB_FIRST、SPI_3WIRE 等）会在 spi_new_device 校验时被拒，不会进到驱动。s3c24xx_spi_setup 做三件事，按顺序：

c
static int s3c24xx_spi_setup(struct spi_device *spi)
{
	struct s3c24xx_spi_devstate *cs = spi->controller_state;
	struct s3c24xx_spi *hw = to_hw(spi);
	int ret;

	if (!cs) {                                   /* 1. 首次分配快照 */
		cs = devm_kzalloc(&spi->dev, sizeof(*cs), GFP_KERNEL);
		if (!cs)
			return -ENOMEM;
		cs->spcon = SPCON_DEFAULT;
		cs->hz = -1;
		spi->controller_state = cs;
	}

	ret = s3c24xx_spi_update_state(spi, NULL);   /* 2. 算寄存器值 */
	if (ret)
		return ret;

	mutex_lock(&hw->bitbang.lock);               /* 3. 总线空闲则取消片选 */
	if (!hw->bitbang.busy)
		hw->bitbang.chipselect(spi, BITBANG_CS_INACTIVE);
	mutex_unlock(&hw->bitbang.lock);

	return 0;
}

cs->hz = -1 是哨兵：unsigned int 赋 -1 等于 UINT_MAX，任何合法 speed_hz 都不等于它，所以第一次 update_state 保证重算。第 3 步的锁只保护「总线空闲时取消片选」，挂设备时不会误选中。原文那行 /* need to ndelay for 0.5 clocktick ? */ 是遗留疑问标记，作者也不确定要不要延时，实际没加。

十三、控制器的注册与注销 #

注册走 spi_bitbang_start，逻辑只有三步：先 spi_bitbang_init(bitbang)，失败直接返回；再 spi_register_master(spi_master_get(master))；失败时用 spi_master_put(master) 把引用还回去，get 与 put 配对算得对。spi_bitbang_init 的关键动作：

步骤 代码 作用
1 if (!master || !bitbang->chipselect) return -EINVAL 参数校验，缺 chipselect 直接拒
2 mutex_init(&bitbang->lock) 片选串行化用
3 if (!master->mode_bits) 则填 SPI_CPOL | SPI_CPHA | bitbang->flags mode_bits 兜底；S3C24XX 已自己填了，不走这条
4 if (master->transfer || master->transfer_one_message) return -EINVAL 「走 bitbang 还是走原生」的互斥检查
5 填 prepare_transfer_hardware/unprepare_transfer_hardware/transfer_one/set_cs 挂上 bitbang 的四个通用实现
6 if (!bitbang->txrx_bufs) {...} 本驱动不执行，见下

三处值得记下来：第 1 步要求 chipselect 已填，忘了填 probe 走到最后一步返回 -EINVAL，日志是 Failed to register SPI master，看着像注册问题，实际是漏了回调；第 4 步是对「走 bitbang 还是走原生」的互斥检查，S3C24XX 填的是 transfer_one，transfer 和 transfer_one_message 都为 NULL，所以能过；第 6 步不执行，因为 probe 已给了 s3c24xx_spi_txrx，spi_bitbang_bufs、spi_bitbang_setup、spi_bitbang_cleanup 都不会被挂上去，master->cleanup 保持为空。

控制器 spi_register_master 之后设备模型上的名字来源：

名字 来源 路径
spi_master_class SPI core 的 class，.name = "spi_master" /sys/class/spi_master/
spi1 dev_set_name(&ctlr->dev, "spi%d", bus_num) /sys/class/spi_master/spi1
s3c2410-spi.1 platform 设备名 + id /sys/bus/platform/devices/s3c2410-spi.1

注销在 s3c24xx_spi_remove，原文只给函数名没给实现。按 5.2.8 惯例应为 spi_bitbang_stop(&hw->bitbang) + spi_master_put(hw->master) + 关时钟，具体实现未验证。spi_bitbang_stop 内部做 spi_unregister_master，等价于 5.0+ 的 spi_unregister_controller。

十四、怎么验证驱动生效 #

原文第四章是整段 u-boot 烧录日志，包含 tftp 下载、NAND 擦写、内核引导头输出。那部分是通用移植流程，跟 SPI 控制器无关，本文全部删掉，只留「怎么判断驱动活了」这一层。

第一步，内核配置。 必须打开 CONFIG_SPI_S3C24XX：

text
Device Drivers --->
   [*] SPI support -->
       [*] Samsung S3C24XX series SPI

没开的话 probe 根本不会被调用，/sys/bus/platform/drivers/s3c2410-spi 目录都不存在。

第二步，编译。 原文验证过的流程：make s3c2440_defconfig，再 make V=1 uImage。

第三步，看启动日志。 原文第一次跑的问题很有代表性：

text
s3c2410-spi s3c2410-spi.1: No clock for device
s3c2410-spi: probe of s3c2410-spi.1 failed with error -2

-2 是 -ENOENT，来自 devm_clk_get(&pdev->dev, "spi") 返回 ERR_PTR(-ENOENT)，即「叫 spi 的时钟查不到」。根因是时钟子系统没给 PCLK_SPI 起别名：devm_clk_get 按连接名 "spi" 查，而时钟表里这颗叫 PCLK_SPI。修法是在 drivers/clk/samsung/clk-s3c2410.c 的 s3c2410_common_aliases 数组末尾补一行 ALIAS(PCLK_SPI, NULL, "spi"),。

第二个问题是补丁的另一半：s3c24xx_spi_probe 里 devm_clk_get 之后没有使能时钟，要在其后补 err = clk_prepare_enable(hw->clk); 并判错跳 err_no_pdata。原文注释写「使能时钟，CLKCON 寄存器的 bit[8] 对应着 SPI 模块」，两点要纠：

其一，5.2.8 走 common clock framework，clk_prepare_enable 最终落到 clk-s3c2410.c 的 gate 操作，写的是 CLKCON 相应位。bit[8] 那个位号原文没给出处，未验证，以手册为准。

其二，补丁用了 clk_prepare_enable，initialsetup 里仍然是 clk_enable，两处不配对：引用计数变 2，err_register 里的 clk_disable 只减到 1，时钟永不真正关闭。正解是：在 devm_clk_get 之后加 clk_prepare_enable；把 initialsetup 里的 clk_enable(hw->clk) 删掉；err_register 改成 clk_disable_unprepare(hw->clk)。

第四步，看设备模型。

bash
[root@zy:/]# ls -l /sys/bus/platform/drivers/s3c2410-spi/
bind  s3c2410-spi.1 -> ../../../../devices/platform/s3c2410-spi.1  uevent  unbind
[root@zy:/]# ls -l /sys/bus/platform/devices/s3c2410-spi.1/
driver -> ../../../bus/platform/drivers/s3c2410-spi
driver_override  modalias  power  spi_master  subsystem -> ../../../bus/platform  uevent

判定标准两条：drivers/s3c2410-spi/ 下有 s3c2410-spi.1 符号链接，说明驱动和设备绑上了；devices/s3c2410-spi.1/driver -> 指回驱动目录，方向也对上。

第五步，看 SPI 控制器目录。 注册 spi_controller 时 dev.class 设成 spi_master_class（name = "spi_master"），dev.name 设成 spi%d：

bash
[root@zy:/]# ls -l /sys/class/spi_master/
spi1 -> ../../devices/platform/s3c2410-spi.1/spi_master/spi1

路径中间那段 spi_master/ 就来自 class 的 .name。这个目录名在 5.0 改名后仍然是 spi_master，你在 6.x 上看到的还是 /sys/class/spi_master/，别以为没生效。叫 spi1 而不是 spi0，因为 bus_num = 1。

第七步，ls /dev/spidev*。 这一步要额外条件：board_list 里有对应板级信息，或设备树里有 spidev 节点，SPI core 才会调 spi_new_device 造出从设备，再由 spidev 驱动绑定生成字符设备。只有 controller 没有从设备时 /dev/spidev* 是空的。新手最常见的误判点就在这里：controller 注册成功 ≠ /dev/spidevX.Y 出现。 spi_register_master 内部的 spi_match_controller_to_boardinfo 负责扫 board_list。原文提到它会「用 spi_new_device 注册从设备」，但没提 board_list 是全局链表、要用 spi_register_board_info 填充、且板级信息必须在控制器注册之前登记；本篇没有 board_list 的填充代码，那部分在同目录的设备驱动篇。

十五、调试手段与常见故障 #

调试入口按「由粗到细」排：

| 手段 | 命令/位置 | 能看出什么 | |---|---|---|| 启动日志 | dmesg \| grep -i spi | probe 成败、错误码 | | 设备绑定 | ls /sys/bus/platform/drivers/s3c2410-spi/ | 驱动和设备是否匹配 | | 控制器存在 | ls /sys/class/spi_master/ | spi_register_master 是否成功 | | 从设备存在 | ls /sys/bus/spi/devices/ | spi_new_device 是否执行 | | 字符设备 | ls /dev/spidev* | spidev 驱动是否绑定 | | 时钟 | cat /sys/kernel/debug/clk/clk_summary | pclk_spi 的 enable 计数和频率 | | 寄存器 | 在 txrx/irq 里加 dev_dbg 打印 SPSTA | 中断是否真进来、状态位对不对 | | 波形 | 逻辑分析仪抓 SCK/MOSI/CS | 时钟频率、相位、片选建立保持 | | 传输回环 | MOSI 短接 MISO，spidev_test -D /dev/spidev1.0 | 发什么收什么 = 收发链路通 |

dev_dbg 只有在 CONFIG_DYNAMIC_DEBUG 或 DEBUG 定义时才输出。想临时看 s3c24xx_spi_irq 里的 spi not ready for tx?，最直接的办法是临时改成 dev_info，或者 echo 'file spi-s3c24xx.c +p' > /sys/kernel/debug/dynamic_debug/control。常见故障对照：

现象 根因 定位方法 修法
No clock for device + error -2 devm_clk_get("spi") 查不到时钟别名 看 clk-s3c2410.c 的 aliases 数组 加 ALIAS(PCLK_SPI, NULL, "spi")
No platform data supplied + error -2 忘了调 s3c_spi1_set_platdata 看 machine_init 里有没有这一行 补 set_platdata 调用
No chipselect pin + error -22 pin_cs 是负数且没给 set_cs 查 platform data 填 pin_cs 或提供 set_cs
Failed to get gpio for cs 片选 GPIO 被别的驱动占了 cat /sys/kernel/debug/gpio 换脚或释放冲突
Cannot claim IRQ 中断号被占，或资源里没 IRQ cat /proc/interrupts 查资源表
Failed to register SPI master bitbang->chipselect 没填，或已设 transfer 看 spi_bitbang_init 的两个 -EINVAL 补 chipselect
probe 成功但 /dev/spidev* 空 没有从设备 ls /sys/bus/spi/devices/ 注册 board_info 或加设备树节点
传输卡死不返回 txrx_bufs 出错但没 complete 抓 hw->count 是否推进 确认中断真的在进
传输返回 EIO 实际字节数 ≠ len，走了 -EREMOTEIO 打印 hw->count 查中断里提前退出的分支
收数据全 0 模式不对（CPOL/CPHA），或 MISO 没接 逻辑分析仪看相位 改 spi->mode
收数据错位 SPPRE 太快，从设备跟不上 算 SCK 频率 降 max_speed_hz
寄存器读写乱套 用了 readl/writel 看反汇编或代码 改回 readb/writeb

排查卡死的第一步永远是确认中断在进。 在 s3c24xx_spi_irq 第一行加 hw->count++ 之外的计数打印，如果一次都没打出来，问题在中断注册或 SPCON 的 INT_EN 位；如果打出来了但 count 不推进，问题在 SPSTA 的 READY 判定。

十六、易错点速查 #

# 易错点 正确做法
1 struct spi_bitbang 不在 s3c24xx_spi 的第一个成员 必须放第一个，否则 spi_master_get_devdata 拿到的指针当 spi_bitbang* 用会错位
2 以为 SPI_BPW_MASK(8) = 7 是 BIT(8)-1 = 0x80；7 是 SPI_BPW_MASK(3)
3 照 SPCON_DEFAULT 注释以为置了 1<<5 主机位 宏里只有收发模式 + 中断使能，主机身份靠 SMOD 字段
4 注释里写 s3c24xx_i2c_init 初始化 SPI 寄存器 没有这个调用，initialsetup 里直接 writeb
5 以为 pdata 为 NULL 会走默认值 probe 直接 -ENOENT 失败
6 以为 s3c24xx_spi_gpiocs 支持多片选 它忽略 cs 参数，只能单从设备
7 用 readl/writel 访问 SPI 寄存器 8 位寄存器，必须 readb/writeb
8 中断里用 hw->count 做 rx 下标 要用进中断时的快照 count
9 DCOL/READY 失败分支不清 SPSTA 补一次 readb(SPRDAT) 清错误位
10 master->setup 阶段以为寄存器被写了 setup 只算快照，setupxfer 才写 SPPRE
11 clk_prepare_enable 后又 clk_enable 引用计数变 2，时钟永不关；删掉 clk_enable
12 err_register 里只用 clk_disable 配对 clk_prepare_enable 必须 clk_disable_unprepare
13 platform_add_devices 数组忘加 &s3c_device_spi1 设备不注册，驱动永远不 probe
14 直接 pdev->dev.platform_data = pd 用 s3c_set_platdata 做 kmemdup，否则 init 段释放后数据失效
15 以为 controller 注册好就有 /dev/spidev* 还要有从设备；spidev 只绑到 spi_device 上
16 抓着 5.2.8 的 spi_master 符号去 6.x 编译 5.0 起改名 spi_controller，spi_alloc_controller/spi_register_controller
17 以为 /sys/class/spi_master 是旧名该改成 spi_controller class 名至今仍是 spi_master，没改
18 spi_finalize_current_transfer 漏调 总线挂死，SPI_IOC_MESSAGE 不返回
19 gpio_setup 里用 enable 参数决定复用 S3C24XX 这版无条件复用，卸驱动不还原
20 setup-spi.c 直接换掉 CONFIG_S3C2443_SETUP_SPI 条件 会波及 S3C2443，建议新建独立文件名
