一、SPI 驱动框架的四个角色 #

SPI 驱动框架由四部分组成：SPI 核心层、SPI 控制器驱动、SPI 设备驱动，以及把前两者串起来的传输描述。内核抽象出四类对象，每一个都有对应的结构体。

角色 结构体 管什么 谁写
SPI 从设备 struct spi_device 描述一个挂在总线上的具体芯片：片选号、速率、模式、中断号 核心层按板级信息或设备树创建，你不用手写
SPI 设备驱动 struct spi_driver 描述「一类设备」的驱动，probe/remove，靠 id_table 或 of_match_table 匹配 你写，比如 SSD1306、NRF24L01 的驱动
SPI 控制器 struct spi_controller 描述 SoC 内部的一个 SPI 控制器：片选数量、模式位、transfer_one 等钩子 SoC 厂家写，比如 spi-s3c24xx.c
传输描述 struct spi_transfer / struct spi_message 描述「一次要发什么、收什么」以及若干 transfer 组成的原子序列 你在设备驱动里现场构造

一个 SoC 可以有多条 SPI 总线，一条总线对应一个控制器，一条总线上又能挂多个从设备。控制器负责片选、时钟、读写周期；从设备驱动只调 spi_write/spi_read/spi_sync，不碰寄存器。代码都在 drivers/spi/：spi.c 是核心，spi-stm32.c、spi-s3c24xx.c 这类是厂家控制器驱动。

二、分层与分离：SPI 为什么这样设计 #

给同类设备设计一个框架、核心层实现通用功能、具体设备不想要就重载——这就是分层。光有分层不够，还要分离：设备驱动和主机控制器驱动一旦强绑定，同一个外设换一种主机就得再写一版，n 种主机就是 n 份代码。分离让两端互不相识：

主机控制器驱动不关心外设是谁，外设驱动不关心主机是谁，外设只访问核心层的通用 API 做数据传输，两边在核心层调度下任意组合。等于在控制器驱动和设备驱动之间插了一层核心层，对两端都隐藏了对端的不确定性。USB、SPI、PCI 的代码里都是这个套路。

设备模型这边就是总线、设备、驱动三个实体，总线负责把设备和驱动绑定：注册设备时找匹配的驱动，注册驱动时找匹配的设备，匹配动作由总线完成。所以一个现实的 Linux 设备和驱动都得挂在某种总线上，否则没人管匹配。本来就依附 PCI、USB、I2C、SPI 的设备不成问题；麻烦的是集成在 SoC 内部、挂在内存空间上、不依附任何实体总线的外设控制器。内核为此造了一条虚拟总线 platform，设备叫 platform_device，驱动叫 platform_driver，SPI 控制器就挂在这条虚拟总线上。

这一点在源码里能直接看到：__spi_alloc_controller 里给 ctlr->dev 只设了 class = &spi_master_class 和 parent = dev，没有设 bus。也就是说 SPI 控制器本身不在 spi 总线上，它是 platform 设备；挂到 spi 总线上的是它下面的 spi_device。分清这两件事，后面看 sysfs 目录才不会乱。

三、spi_controller：一个控制器的抽象 #

struct spi_controller 抽象控制器硬件，指的就是 SoC 内部的 SPI 控制器。向核心层注册控制器，就得提供这么一个结构体变量。定义在 include/linux/spi/spi.h。

版本注记：Linux 5.0 起 struct spi_master 改名为 struct spi_controller，源码里只有一个 #define spi_master spi_controller 的宏别名。素材原代码用的是后者，照抄到 5.0 以下的内核会报错。

别名在，但语义要按新名字理解：这个结构体既能描述主机控制器，也能描述从机控制器，靠 slave 字段区分。下面是 5.2 的完整布局。

c
struct spi_controller {
        struct device   dev;                     /* 内嵌 device，设备模型用 */
        struct list_head list;                   /* 挂 spi_controller_list */
        s16   bus_num;              /* 负数表示动态分配 */
        u16   num_chipselect;       /* 片选数量 */
        u16   dma_alignment;        /* DMA 对齐要求 */
        u32   mode_bits;            /* 支持的 mode 位 */
        u32   bits_per_word_mask;   /* 支持的字长位图 */
#define SPI_BPW_MASK(bits) BIT((bits) - 1)
#define SPI_BPW_RANGE_MASK(min, max) GENMASK((max) - 1, (min) - 1)
        u32   min_speed_hz, max_speed_hz;
        u16   flags;                /* 控制器级约束 */
#define SPI_CONTROLLER_HALF_DUPLEX  BIT(0)  /* 只能半双工 */
#define SPI_CONTROLLER_NO_RX        BIT(1)  /* 不能读 */
#define SPI_CONTROLLER_NO_TX        BIT(2)  /* 不能写 */
#define SPI_CONTROLLER_MUST_RX      BIT(3)  /* 必须有 rx */
#define SPI_CONTROLLER_MUST_TX      BIT(4)  /* 必须有 tx */
#define SPI_MASTER_GPIO_SS          BIT(5)  /* GPIO CS 必须选从机 */
        bool  slave;                /* true 为从机控制器 */
        size_t (*max_transfer_size)(struct spi_device *spi);
        size_t (*max_message_size)(struct spi_device *spi);
        struct mutex  io_mutex;
        spinlock_t    bus_lock_spinlock;  /* 总线加锁三件套 */
        struct mutex  bus_lock_mutex;
        bool          bus_lock_flag;
        int  (*setup)(struct spi_device *spi);
        void (*set_cs_timing)(struct spi_device *spi, u8 setup_clk_cycles,
                              u8 hold_clk_cycles, u8 inactive_clk_cycles);
        int  (*transfer)(struct spi_device *spi, struct spi_message *mesg);
        void (*cleanup)(struct spi_device *spi);
        bool (*can_dma)(struct spi_controller *ctlr, struct spi_device *spi,
                        struct spi_transfer *xfer);
        bool  queued;               /* 是否用内部消息队列 */
        struct kthread_worker      kworker;
        struct task_struct        *kworker_task;
        struct kthread_work        pump_messages;
        spinlock_t                 queue_lock;
        struct list_head           queue;
        struct spi_message        *cur_msg;
        bool  idling, busy, running, rt;
        bool  auto_runtime_pm, cur_msg_prepared, cur_msg_mapped;
        struct completion  xfer_completion;
        size_t             max_dma_len;
        int (*prepare_transfer_hardware)(struct spi_controller *ctlr);
        int (*transfer_one_message)(struct spi_controller *ctlr, struct spi_message *mesg);
        int (*unprepare_transfer_hardware)(struct spi_controller *ctlr);
        int (*prepare_message)(struct spi_controller *ctlr, struct spi_message *message);
        int (*unprepare_message)(struct spi_controller *ctlr, struct spi_message *message);
        int (*slave_abort)(struct spi_controller *ctlr);
        void (*set_cs)(struct spi_device *spi, bool enable);
        int (*transfer_one)(struct spi_controller *ctlr, struct spi_device *spi,
                            struct spi_transfer *transfer);
        void (*handle_err)(struct spi_controller *ctlr, struct spi_message *message);
        const struct spi_controller_mem_ops *mem_ops;
        int   *cs_gpios;            /* LEGACY */
        struct gpio_desc        **cs_gpiods;
        bool                    use_gpio_descriptors;
        struct spi_statistics   statistics;
        struct dma_chan         *dma_tx, *dma_rx;
        void                    *dummy_rx, *dummy_tx;
        int (*fw_translate_cs)(struct spi_controller *ctlr, unsigned cs);
};

dev 是内嵌的 struct device（把控制器当成 device 的子类），list 挂到全局 spi_controller_list；bus_num 是控制器编号（负数交给核心层动态分配）；num_chipselect 是片选数量，从设备的 chip_select 必须小于它；mode_bits 是控制器能理解的模式位（SPI_CPHA/SPI_CPOL/SPI_CS_HIGH 等，见第四章）；bits_per_word_mask 是字长位图，第 n 位置位表示支持 n+1 位，置了核心层就拒绝不支持的字长，不置则全交给驱动校验；min_speed_hz/max_speed_hz 是速率上下限，flags 是控制器级约束（半双工、不能收、不能发），slave 标记从机控制器，io_mutex 是物理总线访问锁，bus_lock_* 三件套见第八章。

setup 设置控制器的工作方式和时钟，协议驱动可以多次调用。transfer 把消息加进控制器传输队列、不可睡眠，不指定时核心层默认填 spi_queued_transfer；transfer_one_message 传输一个完整 spi_message，完成后调 spi_finalize_current_message，不指定时默认填 spi_transfer_one_message；transfer_one 传输一个 spi_transfer，返回 0 已完成、返回 1 还在传输中、完成时要调 spi_finalize_current_transfer，一般由 SoC 厂家实现。cleanup 释放控制器私有状态（在 spidev_release 里被调），set_cs 是片选钩子（指定了 cs_gpios/cs_gpiods 后不生效）。

cs_gpios/cs_gpiods 是片选 GPIO 编号数组 / 描述符数组，一个从设备一个片选引脚；queue 是消息队列，可同时排多条 spi_message；kworker/kworker_task/pump_messages 是内核工作线程、它的 task_struct、挂上去的具体工作项；busy 标记当前是否在传输，cur_msg 是当前正在处理的 spi_message，idling 表示工作线程空闲，running 表示消息队列已启用，rt 决定消息泵是否跑实时优先级。

三个钩子容易混：transfer 把 message 加进队列，transfer_one_message 传输一个 message，transfer_one 传输一个 transfer。三者互斥——用了 transfer_one，核心层就不会再调 transfer_one_message。

四、spi_device：总线上的一个从设备 #

struct spi_device 抽象挂在 SPI 总线上的从设备，是从设备的最终形态。它的成员值大量来自 spi_board_info（板级信息）或设备树解析结果。定义也在 include/linux/spi/spi.h。

c
struct spi_device {
        struct device           dev;
        struct spi_controller   *controller;
        struct spi_controller   *master;        /* 兼容层，等同 controller */
        u32                     max_speed_hz;
        u8                      chip_select;
        u8                      bits_per_word;
        u32                     mode;
#define SPI_CPHA        0x01    /* 时钟相位 */
#define SPI_CPOL        0x02    /* 时钟极性 */
#define SPI_MODE_0      (0|0)   /* 原始 MicroWire 模式 */
#define SPI_MODE_1      (0|SPI_CPHA)
#define SPI_MODE_2      (SPI_CPOL|0)
#define SPI_MODE_3      (SPI_CPOL|SPI_CPHA)
#define SPI_CS_HIGH     0x04    /* 片选高电平选中 */
#define SPI_LSB_FIRST   0x08    /* 低位先发 */
#define SPI_3WIRE       0x10    /* SI/SO 共用一根线 */
#define SPI_LOOP        0x20    /* 回环模式 */
#define SPI_NO_CS       0x40    /* 单设备总线，不用片选 */
#define SPI_READY       0x80    /* 从机拉低暂停 */
#define SPI_TX_DUAL     0x100   /* 2 线发送 */
#define SPI_TX_QUAD     0x200   /* 4 线发送 */
#define SPI_RX_DUAL     0x400   /* 2 线接收 */
#define SPI_RX_QUAD     0x800   /* 4 线接收 */
#define SPI_CS_WORD     0x1000  /* 每字翻一次片选 */
#define SPI_TX_OCTAL    0x2000  /* 8 线发送 */
#define SPI_RX_OCTAL    0x4000  /* 8 线接收 */
#define SPI_3WIRE_HIZ   0x8000  /* 高阻换向 */
        int                     irq;
        void                    *controller_state;
        void                    *controller_data;
        char                    modalias[SPI_NAME_SIZE];
        const char              *driver_override;
        int                     cs_gpio;        /* LEGACY: 片选 GPIO 编号 */
        struct gpio_desc        *cs_gpiod;      /* 片选 GPIO 描述符 */
        uint8_t                 word_delay_usecs; /* 字间延时 */
        struct spi_statistics   statistics;
};

字段表：

字段逐个说：dev 是内嵌的 struct device，dev.bus 指向 spi_bus_type，靠它从设备才挂在 SPI 总线上；controller 是所属控制器，master 是它的兼容别名（老代码用 spi->master，新代码用 spi->controller）。max_speed_hz 是通讯时钟最大频率，驱动运行时可以改；chip_select 是片选号，一个控制器接多个设备就靠它区分；bits_per_word 默认 8，为 0 时按 8 处理；mode 是模式位组合，核心是 SPI_CPOL 与 SPI_CPHA。irq 是该设备的中断号，controller_state 是控制器运行期状态（控制器驱动自己用），controller_data 是板级给控制器的私有数据（比如 FIFO 初始化参数）。modalias 是设备名，用于和驱动匹配，对应 sysfs 里的 modalias 属性；driver_override 强制指定用哪个驱动，优先于一切匹配方式；cs_gpio/cs_gpiod 是片选 GPIO 编号/描述符，非 GPIO 片选时为 -ENOENT 或 NULL；word_delay_usecs 是相邻两个字之间的微秒延时；statistics 是该设备的统计计数。

mode 里最要紧的是两个位：SPI_CPHA（0x01）选采样时机，0 表示第一个跳变沿采样、1 表示第二个沿；SPI_CPOL（0x02）选起始电平，0 表示时钟从低电平开始、1 表示从高电平开始。两位组合出 SPI_MODE_0 到 SPI_MODE_3，第十章单独对比。

老代码注意：早期内核的 chip_select 是 u8，也没区分 cs_gpio/cs_gpiod。素材里 cs_gpio 的注释写明 LEGACY，新驱动一律走 cs_gpiod，靠控制器上的 use_gpio_descriptors 打开。

五、spi_driver：设备驱动的注册 #

struct spi_driver 描述一个 SPI 设备驱动，匹配到对应的 spi_device 后调 probe。定义在 include/linux/spi/spi.h。

c
struct spi_driver {
        const struct spi_device_id *id_table;      /* 支持的设备 ID 数组 */
        int  (*probe)(struct spi_device *spi);     /* 匹配成功后调，资源注册都放这 */
        int  (*remove)(struct spi_device *spi);    /* 卸载/移除时释放资源 */
        void (*shutdown)(struct spi_device *spi);  /* 关机重启回调 */
        struct device_driver driver;               /* 驱动基类，name/bus 参与匹配 */
};

字段的作用都写在注释里：id_table 让一个驱动同时支持多颗芯片，probe 是资源注册和初始化的唯一入口，remove/shutdown 负责释放，driver 是必须内嵌的基类——driver.name 参与匹配，driver.bus 由核心层填成 spi_bus_type。

内核里叫它「protocol driver」，因为它只通过 message 和硬件打交道，不直接碰寄存器——碰寄存器的是它下面的控制器驱动。设备驱动上面还能再接一层 MTD、网络、MMC、RTC、字符设备节点、hwmon 之类的框架。它对应一个 spi_device，和 platform_driver 对应 platform_device 是一个套路，区别在 platform_device 的板级信息写在 arch 目录，spi_device 的用 spi_board_info 描述，第六章讲。

注册模板照这个写：

c
static const struct of_device_id ssd1306_of_match[] = {
        { .compatible = "solomon,ssd1306fb" },   /* 示例写法，实际兼容名按芯片手册核对 */
        { }
};
MODULE_DEVICE_TABLE(of, ssd1306_of_match);
static const struct spi_device_id ssd1306_id[] = {
        { "ssd1306", 0 },       /* 走 spi_board_info.modalias 匹配的老板子路径 */
        { }
};
MODULE_DEVICE_TABLE(spi, ssd1306_id);
static struct spi_driver ssd1306_driver = {
        .driver = {
                .name           = "ssd1306",
                .of_match_table = ssd1306_of_match,
        },
        .id_table = ssd1306_id,
        .probe    = ssd1306_probe,
        .remove   = ssd1306_remove,
};
module_spi_driver(ssd1306_driver);

driver.name 和 spi_device.modalias 是最后一道匹配兜底，名字对不上又没设 id_table、没有设备树匹配，probe 永远不会进来。

六、spi_board_info 与设备实例化 #

板级信息用 struct spi_board_info 描述，记录 SPI 从设备用哪个控制器、哪个片选、什么速率、什么模式。定义在 include/linux/spi/spi.h。

c
struct spi_board_info {
        char            modalias[SPI_NAME_SIZE];   /* 设备名，与 spi_device_id.name 匹配 */
        const void      *platform_data;            /* 板级私有数据 */
        const struct property_entry *properties;   /* 设备属性，深拷贝挂到设备上 */
        void            *controller_data;          /* 给控制器的提示，比如 DMA */
        int             irq;                       /* 中断号 */
        u32             max_speed_hz;              /* 最大传输频率 */
        u16             bus_num;                   /* 所属控制器编号，控制器往往稍后才注册 */
        u16             chip_select;               /* 片选编号，从 0 开始，必须小于 num_chipselect */
        u32             mode;                      /* 模式配置，会成为 spi_device.mode */
};

spi_board_info 将来会被转成 spi_device，两者成员大量重合，转换是一一对应的：modalias → modalias，platform_data → dev.platform_data，controller_data → controller_data，irq → irq，max_speed_hz → max_speed_hz，chip_select → chip_select，mode → mode。

注册板级信息用 spi_register_board_info，定义在 drivers/spi/spi.c。

c
int spi_register_board_info(struct spi_board_info const *info, unsigned n)
{
        struct boardinfo *bi;
        int i;

        if (!n)
                return 0;
        bi = kcalloc(n, sizeof(*bi), GFP_KERNEL);
        if (!bi)
                return -ENOMEM;

        for (i = 0; i < n; i++, bi++, info++) {
                struct spi_controller *ctlr;

                memcpy(&bi->board_info, info, sizeof(*info));
                if (info->properties) {   /* properties 深拷贝 */
                        bi->board_info.properties = property_entries_dup(info->properties);
                        if (IS_ERR(bi->board_info.properties))
                                return PTR_ERR(bi->board_info.properties);
                }

                mutex_lock(&board_lock);
                list_add_tail(&bi->list, &board_list);
                list_for_each_entry(ctlr, &spi_controller_list, list)
                        spi_match_controller_to_boardinfo(ctlr, &bi->board_info);
                mutex_unlock(&board_lock);
        }
        return 0;
}

核心动作两步：把 n 个 spi_board_info 各自包一层 struct boardinfo 挂到全局 board_list，同时遍历已有的 spi_controller_list，看有没有控制器的 bus_num 已经对得上，对上就直接建设备。

这里有一条硬顺序：必须在 spi_register_controller 之前调用 spi_register_board_info。反过来，注册控制器时扫 board_list 扫不到，板级设备就永远建不出来，除非之后手动补一次 spi_new_device。还有更直接的一条：platform_data 是按指针拷贝的，板级信息标了 __initdata 的话，那块内存 free_initmem 之后就被回收，从设备驱动再读 dev.platform_data 就是野指针。

版本注记：struct spi_board_info 的 properties 字段是 4.15 前后加入的（未验证精确版本）。3.x 的 spi_board_info 没有这个字段，spi_register_board_info 里也没有 property_entries_dup 那一段。另外内核里从来没有 spi_register_device() 这个函数，要让 spi_device 上线只能走 spi_new_device() 或 spi_add_device()，素材 2 的写法是笔误。

七、spi_transfer 与 spi_message：一次传输怎么描述 #

struct spi_transfer 是一对读写缓冲区，是传输的最小单位。定义在 include/linux/spi/spi.h。

c
struct spi_transfer {
        const void      *tx_buf;
        void            *rx_buf;
        unsigned        len;
        dma_addr_t      tx_dma;
        dma_addr_t      rx_dma;
        struct sg_table tx_sg;
        struct sg_table rx_sg;
        unsigned        cs_change:1;
        unsigned        tx_nbits:3;
        unsigned        rx_nbits:3;
#define SPI_NBITS_SINGLE        0x01 /* 1bit transfer */
#define SPI_NBITS_DUAL          0x02 /* 2bits transfer */
#define SPI_NBITS_QUAD          0x04 /* 4bits transfer */
        u8              bits_per_word;
        u8              word_delay_usecs;
        u16             delay_usecs;
        u32             speed_hz;
        u16             word_delay;
        struct list_head transfer_list;
};

字段逐个说：tx_buf/rx_buf 是收发缓冲区（必须 DMA 安全，可以为 NULL），len 是各自长度、不是两者之和；tx_dma/rx_dma 只在 is_dma_mapped 为真时被采用，tx_sg/rx_sg 不给 client 驱动用；cs_change 决定本次结束后是否动片选（第十一章）；tx_nbits/rx_nbits 是用几根线发/收，0 为单线；bits_per_word 与 speed_hz 填 0 沿用 spi_device 默认值；delay_usecs 是本次结束后、片选变更前的延时；word_delay_usecs/word_delay 是字间延时（微秒 / 时钟周期）；transfer_list 是挂到 spi_message.transfers 的链表节点。

几条规则必须记住：SPI 传输读和写字节数永远相同，都是 len，协议驱动至少给 rx_buf 或 tx_buf 其中之一；tx_buf 为 NULL 时芯片移出 0 并填充 rx_buf，这次的时钟正好用来收数据；rx_buf 为 NULL 时移进来的数据被丢弃；移出半个字是错误（字长 16 位就别只移 3 字节）；内存里的字是 CPU 字节序，线上是 MSB first（除非置了 SPI_LSB_FIRST），字长 16 位时 len = 2N 装 N 个字。

spi_transfer 是传输的最小单位，为什么还要套一层 spi_message？因为要往从设备的多个不连续地址一次性写完。真正的数据搬运在另一个内核线程里做，不打包就得多趟往返，切换变多、延迟变大；打包成一条 message，队列里只排一次。

struct spi_message 描述一次 SPI 数据交换的原子序列。

c
struct spi_message {
        struct list_head        transfers; // 链表头，挂 spi_transfer 节点
        struct spi_device       *spi;
        unsigned                is_dma_mapped:1;
        void                    (*complete)(void *context);
        void                    *context;
        unsigned                frame_length;
        unsigned                actual_length;
        int                     status;

        /* queue/state 归当前拥有这条 message 的驱动使用：从 spi_async 到 complete()
         * 之间，归属者是 spi_controller 控制器驱动
         */
        struct list_head        queue;
        void                    *state;

        struct list_head        resources;   /* 处理过程中的 spi_res 资源链表 */
};

字段逐个说：transfers 是链表头，挂本 message 下的所有 spi_transfer；spi 是传输的目标从设备；is_dma_mapped 说明 tx_dma/rx_dma 是否已映射；complete/context 是完成回调与它的参数；frame_length 是总字节数，actual_length 是实际传输成功的字节数，status 从 -EINPROGRESS 变成 0 或负 errno；queue/state 是排队链表节点和控制器驱动的内部状态，归当前拥有这条 message 的驱动使用；resources 是处理过程中的 spi_res 资源链表。

spi_message 的「原子」指：控制器收下后里面的 transfer 必须按顺序发完，中间不能被别的 message 打断。同一 spi_device 上的 message 严格 FIFO；不同设备之间不保证顺序。

构造和填充 message 的三个内联函数：

c
static inline void spi_message_init(struct spi_message *m)
{
        memset(m, 0, sizeof *m);
        spi_message_init_no_memset(m);
}
static inline void spi_message_init_no_memset(struct spi_message *m)
{
        INIT_LIST_HEAD(&m->transfers);
        INIT_LIST_HEAD(&m->resources);
}
static inline void spi_message_add_tail(struct spi_transfer *t, struct spi_message *m)
{
        list_add_tail(&t->transfer_list, &m->transfers);
}
static inline void spi_message_init_with_transfers(struct spi_message *m,
                struct spi_transfer *xfers, unsigned int num_xfers)
{
        unsigned int i;
        spi_message_init(m);
        for (i = 0; i < num_xfers; ++i)
                spi_message_add_tail(&xfers[i], m);
}

spi_message_init 做链表零初始化；spi_message_add_tail 在双向链表尾部挂一个元素；spi_message_init_with_transfers 把两件事合成一步。完整流程四步：定义 message 并初始化 → 定义 transfer 填好 tx_buf/rx_buf/len → 用 spi_message_add_tail 挂上去 → 同步调 spi_sync()、异步调 spi_async()。

内核自己的 spi_write/spi_read 就是这四步的最小版本，直接抄：

c
static inline int spi_write(struct spi_device *spi, const void *buf, size_t len)
{
        struct spi_transfer     t = {
                .tx_buf         = buf,
                .len            = len,
        };
        struct spi_message      m;

        spi_message_init(&m);
        spi_message_add_tail(&t, &m);
        return spi_sync(spi, &m);
}

spi_read 与它逐字相同，只把 .tx_buf 换成 .rx_buf。

别看它们简单，你写的每个寄存器读写在源码里都长这个样子。

八、spi_sync 与 spi_async：同步与异步 #

两个入口：int spi_sync(struct spi_device *spi, struct spi_message *message) 和 int spi_async(struct spi_device *spi, struct spi_message *message)。同步方式下发起者必须等本次传输结束，函数不返回就干不了别的；异步方式下函数立刻返回，你在 message->complete 上挂个回调，传完由核心层来叫你。少量数据的单次传输用同步，数据量大、次数多的场景用异步。

异步对控制器有额外要求：返回之后调用者可以立刻再提交一条 message，而上一条还没处理完；不同调用者也会同时提交。核心层统一处理——无论同步异步，都是把 spi_message 放进 spi_controller 的消息队列，多条按队列顺序依次执行。

异步路径 #

c
static int __spi_async(struct spi_device *spi, struct spi_message *message)
{
        struct spi_controller *ctlr = spi->controller;

        if (!ctlr->transfer)      /* 不支持常规传输的控制器返回 ENOTSUPP */
                return -ENOTSUPP;

        message->spi = spi;
        SPI_STATISTICS_INCREMENT_FIELD(&ctlr->statistics, spi_async);
        SPI_STATISTICS_INCREMENT_FIELD(&spi->statistics, spi_async);
        trace_spi_message_submit(message);

        return ctlr->transfer(spi, message);   /* 交给 spi_queued_transfer 入队 */
}

int spi_async(struct spi_device *spi, struct spi_message *message)
{
        struct spi_controller *ctlr = spi->controller;
        int ret;
        unsigned long flags;

        ret = __spi_validate(spi, message);
        if (ret != 0)
                return ret;

        spin_lock_irqsave(&ctlr->bus_lock_spinlock, flags);
        if (ctlr->bus_lock_flag)
                ret = -EBUSY;
        else
                ret = __spi_async(spi, message);
        spin_unlock_irqrestore(&ctlr->bus_lock_spinlock, flags);

        return ret;
}

spi_async 可以在中断上下文调用，整条路径不睡眠，完成回调也在不能睡眠的上下文里被调。回调进来之前 message->status 未定义；进来时要么是 0，要么是负的 errno。回调返回之后你提交的缓冲区才重新归你管——在 complete 返回之前，别碰 spi_transfer 里的缓冲区，更不能释放。传输中一旦故障，整条 message 中止、设备取消片选，直到完成回调返回，该设备上排队的其它 message 都不处理。

ctlr->transfer 在队列模式下是 spi_queued_transfer：

c
static int spi_queued_transfer(struct spi_device *spi, struct spi_message *msg)
{
        return __spi_queued_transfer(spi, msg, true);   /* 异步：需要唤醒消息泵 */
}

static int __spi_queued_transfer(struct spi_device *spi, struct spi_message *msg,
                                 bool need_pump)
{
        struct spi_controller *ctlr = spi->controller;
        unsigned long flags;

        spin_lock_irqsave(&ctlr->queue_lock, flags);

        if (!ctlr->running) {     /* 队列没启用；正常情况 running 恒为 true */
                spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                return -ESHUTDOWN;
        }
        msg->actual_length = 0;
        msg->status = -EINPROGRESS;
        list_add_tail(&msg->queue, &ctlr->queue);   /* 挂到 ctlr->queue */

        if (!ctlr->busy && need_pump)   /* 空闲且是异步提交：直接唤醒消息泵 */
                kthread_queue_work(&ctlr->kworker, &ctlr->pump_messages);

        spin_unlock_irqrestore(&ctlr->queue_lock, flags);
        return 0;
}

到这一步异步提交就返回了。活儿交给内核工作线程：从 ctlr->queue 取 message、调控制器的传输方法、完成后调 complete。

同步路径 #

c
static int __spi_queued_transfer(struct spi_device *spi, struct spi_message *msg, bool need_pump)
{
        int ret;
        mutex_lock(&spi->controller->bus_lock_mutex);
        ret = __spi_sync(spi, message);
        mutex_unlock(&spi->controller->bus_lock_mutex);
        return ret;
}
int spi_sync(struct spi_device *spi, struct spi_message *message)
{
        DECLARE_COMPLETION_ONSTACK(done);
        int status;
        struct spi_controller *ctlr = spi->controller;
        unsigned long flags;

        status = __spi_validate(spi, message);
        if (status != 0)
                return status;

        message->complete = spi_complete;   /* 完成回调 */
        message->context = &done;           /* 回调参数 */
        message->spi = spi;
        SPI_STATISTICS_INCREMENT_FIELD(&ctlr->statistics, spi_sync);   /* 计数 */
        SPI_STATISTICS_INCREMENT_FIELD(&spi->statistics, spi_sync);

        if (ctlr->transfer == spi_queued_transfer) {   /* 队列模式走这里 */
                spin_lock_irqsave(&ctlr->bus_lock_spinlock, flags);
                trace_spi_message_submit(message);
                status = __spi_queued_transfer(spi, message, false);  /* 不唤醒后台泵 */
                spin_unlock_irqrestore(&ctlr->bus_lock_spinlock, flags);
        } else {
                status = spi_async_locked(spi, message);
        }

        if (status == 0) {
                /* 能在当前上下文推的就直接推 */
                if (ctlr->transfer == spi_queued_transfer) {
                        SPI_STATISTICS_INCREMENT_FIELD(&ctlr->statistics, spi_sync_immediate);
                        SPI_STATISTICS_INCREMENT_FIELD(&spi->statistics, spi_sync_immediate);
                        __spi_pump_messages(ctlr, false);   /* 直接发起传输 */
                }
                wait_for_completion(&done);   /* 等待传输完成 */
                status = message->status;
        }
        message->context = NULL;
        return status;
}

spi_sync 用 bus_lock_mutex 做互斥，睡眠的是调用者自己，所以只能在能睡眠的上下文调用。同步与异步的差别就在两处：异步把 __spi_pump_messages 作为 work 挂到内核工作线程由线程干活；同步在 __spi_sync 里直接调 __spi_pump_messages(ctlr, false)，第二个参数 in_kthread 传 false。

等待靠 completion。DECLARE_COMPLETION_ONSTACK(done) 在栈上建完成量，struct completion 只有 unsigned int done（同步用的原子量）和 wait_queue_head_t wait（等待队列头）。wait_for_completion 把 done 减一，减成负数就进睡眠、挂进 wait；传输完成后核心层调 spi_complete(arg)，里面只做一件事——complete(arg)，在 kernel/sched/completion.c 里把 done 加一，再 __wake_up_locked 唤醒等待线程。

消息泵：__spi_pump_messages #

这是整条链路的枢纽，kthread 会调它，spi_sync 也会调它。

c
static int __spi_sync(struct spi_device *spi, struct spi_message *message)
{
        unsigned long flags;
        bool was_busy = false;

        spin_lock_irqsave(&ctlr->queue_lock, flags);

        /* 已有消息在处理 → 直接返回；别的上下文在做空闲收尾 → 挂回线程让路 */
        if (ctlr->cur_msg) {
                spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                return;
        }
        if (ctlr->idling) {
                kthread_queue_work(&ctlr->kworker, &ctlr->pump_messages);
                spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                return;
        }
        if (list_empty(&ctlr->queue) || !ctlr->running) {
                if (!ctlr->busy) {
                        spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                        return;
                }
                if (!in_kthread) {   // 同步调用进来，收尾交给线程
                        kthread_queue_work(&ctlr->kworker, &ctlr->pump_messages);
                        spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                        return;
                }
                ctlr->busy = false;
                ctlr->idling = true;
                spin_unlock_irqrestore(&ctlr->queue_lock, flags);

                /* 队列排空：清哑缓冲区、放硬件、放 runtime PM */
                kfree(ctlr->dummy_rx); ctlr->dummy_rx = NULL;
                kfree(ctlr->dummy_tx); ctlr->dummy_tx = NULL;
                if (ctlr->unprepare_transfer_hardware)
                        ctlr->unprepare_transfer_hardware(ctlr);
                if (ctlr->auto_runtime_pm) {
                        pm_runtime_mark_last_busy(ctlr->dev.parent);
                        pm_runtime_put_autosuspend(ctlr->dev.parent);
                }
                spin_lock_irqsave(&ctlr->queue_lock, flags);
                ctlr->idling = false;
                spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                return;
        }
        ctlr->cur_msg = list_first_entry(&ctlr->queue, struct spi_message, queue);
        list_del_init(&ctlr->cur_msg->queue);
        if (ctlr->busy)
                was_busy = true;
        else
                ctlr->busy = true;
        spin_unlock_irqrestore(&ctlr->queue_lock, flags);

        mutex_lock(&ctlr->io_mutex);
        if (!was_busy && ctlr->auto_runtime_pm)
                ret = pm_runtime_get_sync(ctlr->dev.parent);   // 首次传输才上电
        if (!was_busy && ctlr->prepare_transfer_hardware) {
                ret = ctlr->prepare_transfer_hardware(ctlr);
                if (ret) goto err_hw;
        }
        if (ctlr->prepare_message) {
                ret = ctlr->prepare_message(ctlr, ctlr->cur_msg);
                if (ret) goto err_msg;
                ctlr->cur_msg_prepared = true;
        }
        ret = spi_map_msg(ctlr, ctlr->cur_msg);   // DMA 映射
        if (ret) goto err_msg;

        /* 真正发数据；失败的几种情况都记状态、调 finalize，再统一 out */
        ret = ctlr->transfer_one_message(ctlr, ctlr->cur_msg);
        if (ret)
                dev_err(&ctlr->dev, "failed to transfer one message from queue\n");
        goto out;

err_msg:   /* prepare_message / spi_map_msg 失败 */
        ctlr->cur_msg->status = ret;
        spi_finalize_current_message(ctlr);
        goto out;

err_hw:    /* prepare_transfer_hardware 失败：先放掉 runtime PM */
        if (ctlr->auto_runtime_pm)
                pm_runtime_put(ctlr->dev.parent);
        ctlr->cur_msg->status = ret;
        spi_finalize_current_message(ctlr);

out:
        mutex_unlock(&ctlr->io_mutex);
        if (!ret)
                cond_resched();   /* transfer_one() 忙等时让一下调度器 */
}

逐段对上。cur_msg 不为 NULL 说明已有消息在处理，直接返回——不丢消息，消息早在队列里，当前消息处理完会调 spi_finalize_current_message，那里再把 __spi_pump_messages 挂回线程。idling 为真说明另一上下文正在做空闲收尾，先让路。队列空或 running 为假且不 busy，直接返回；队列空但 busy 说明上一轮还没收尾，同步调用进来（in_kthread == false）时不能自己收尾、挂回线程，线程里才做 busy = false、idling = true、释放 dummy_rx/dummy_tx、调 unprepare_transfer_hardware、处理 runtime PM。

前面都没拦就从 ctlr->queue 摘第一条给 cur_msg，busy 置 true，was_busy 记住摘之前的状态（第一次 false，之后都是 true）。was_busy 为 false 时才走 prepare_transfer_hardware 和 pm_runtime_get_sync；prepare_message 有就调，失败把错误码塞进 cur_msg->status 并结束这条消息，成功则置 cur_msg_prepared；spi_map_msg 处理 DMA 映射；最后调 ctlr->transfer_one_message 发数据，这个钩子可以不实现，核心层默认填 spi_transfer_one_message。一句话：从队列取消息、交给控制器驱动的 transfer_one 发出去、发完调 spi_finalize_current_message，后者又把 __spi_pump_messages 挂回线程形成循环，队列排空后靠那几个状态判断让循环停下来。

核心层默认的 transfer_one_message #

c
static int spi_transfer_one_message(struct spi_controller *ctlr,
                                    struct spi_message *msg)
{
        struct spi_transfer *xfer;
        bool keep_cs = false;
        int ret = 0;
        spi_set_cs(msg->spi, true);   // 选中片选
        list_for_each_entry(xfer, &msg->transfers, transfer_list) {
                if (xfer->tx_buf || xfer->rx_buf) {   // 收发缓冲区至少一个非空
                        reinit_completion(&ctlr->xfer_completion);
                        ret = ctlr->transfer_one(ctlr, msg->spi, xfer);
                        if (ret < 0) {    // 传输出错
                                dev_err(&msg->spi->dev, "SPI transfer failed: %d\n", ret);
                                goto out;
                        }
                        if (ret > 0) {    // 进行中，等完成信号
                                ret = spi_transfer_wait(ctlr, msg, xfer);
                                if (ret < 0) msg->status = ret;
                        }
                }
                if (msg->status != -EINPROGRESS) goto out;
                if (xfer->delay_usecs) {    // 延时
                        u16 us = xfer->delay_usecs;

                        if (us <= 10)
                                udelay(us);
                        else
                                usleep_range(us, us + DIV_ROUND_UP(us, 10));
                }
                if (xfer->cs_change) {      // 动片选
                        if (list_is_last(&xfer->transfer_list, &msg->transfers)) {
                                keep_cs = true;
                        } else {
                                spi_set_cs(msg->spi, false);
                                udelay(10);
                                spi_set_cs(msg->spi, true);
                        }
                }
                msg->actual_length += xfer->len;
        }
out:
        if (ret != 0 || !keep_cs)
                spi_set_cs(msg->spi, false);    // 取消片选
        if (msg->status == -EINPROGRESS) msg->status = ret;
        if (msg->status && ctlr->handle_err) ctlr->handle_err(ctlr, msg);
        spi_res_release(ctlr, msg);
        spi_finalize_current_message(ctlr);   // 告知传输完成
        return ret;
}

按顺序走一遍：先 spi_set_cs(msg->spi, true) 选中片选（落到控制器驱动的 set_cs 或 GPIO 片选），再从 msg->transfers 逐个取 transfer 调控制器驱动的 transfer_one，中间按 delay_usecs 决定要不要 udelay/usleep_range、按 cs_change 决定要不要翻片选，同时累加 actual_length，最后 spi_finalize_current_message 收尾。transfer_one 的返回值很关键：负数是出错，0 是已传完，1 是还在传——此时核心层调 spi_transfer_wait 等 xfer_completion，等控制器驱动发完成信号。

收尾：

c
void spi_finalize_current_message(struct spi_controller *ctlr)
{
    struct spi_message *mesg;
    ...
    ctlr->cur_msg = NULL;            /* 清空当前消息 */
    ctlr->cur_msg_prepared = false;
    kthread_queue_work(&ctlr->kworker, &ctlr->pump_messages);   /* 驱动下一条 */
    ...
    mesg->state = NULL;
    if (mesg->complete)              /* 唤醒之前阻塞的调用线程 */

}

同步传输时 mesg->complete 就是核心层填的 spi_complete，mesg->context 是栈上的 done，一执行就唤醒被阻塞的调用线程。异步传输时 complete 和 context 是你自己填的，回调在你的上下文里跑。

九、spi_setup：模式与速率 #

spi_setup 负责改设备的传输模式和时钟速率。协议驱动发现设备不认默认值时调它。除了 SPI_CS_HIGH 立即生效，其它改动要等下次选中该设备并传数据时才生效。函数返回时设备处于未选中状态。

c
int spi_setup(struct spi_device *spi)
{
        unsigned        bad_bits, ugly_bits;
        int             status;

        /* 防止 DUAL 与 QUAD 同时置位 */
        if (((spi->mode & SPI_TX_DUAL) && (spi->mode & SPI_TX_QUAD)) ||
            ((spi->mode & SPI_RX_DUAL) && (spi->mode & SPI_RX_QUAD))) {
                dev_err(&spi->dev, "setup: can not select dual and quad at the same time\n");
                return -EINVAL;
        }
        /* 3WIRE 模式下禁止多线位 */
        if ((spi->mode & SPI_3WIRE) && (spi->mode &
                (SPI_TX_DUAL | SPI_TX_QUAD | SPI_TX_OCTAL | SPI_RX_DUAL | SPI_RX_QUAD | SPI_RX_OCTAL)))
                return -EINVAL;
        /* 让驱动在请求了控制器不支持的选项时干净地失败；SPI_CS_WORD 有软件兜底，忽略 */
        bad_bits = spi->mode & ~(spi->controller->mode_bits | SPI_CS_WORD);
        if (gpio_is_valid(spi->cs_gpio))
                bad_bits &= ~SPI_CS_HIGH;

        /* 多线位不支持时只警告并清位，其它不支持的模式位直接报错 */
        ugly_bits = bad_bits & (SPI_TX_DUAL | SPI_TX_QUAD | SPI_TX_OCTAL |
                                SPI_RX_DUAL | SPI_RX_QUAD | SPI_RX_OCTAL);
        if (ugly_bits) {
                dev_warn(&spi->dev, "setup: ignoring unsupported mode bits %x\n", ugly_bits);
                spi->mode &= ~ugly_bits;
                bad_bits &= ~ugly_bits;
        }
        if (bad_bits) {
                dev_err(&spi->dev, "setup: unsupported mode bits %x\n", bad_bits);
                return -EINVAL;
        }
        if (!spi->bits_per_word)
                spi->bits_per_word = 8;
        status = __spi_validate_bits_per_word(spi->controller, spi->bits_per_word);
        if (status)
                return status;
        if (!spi->max_speed_hz)
                spi->max_speed_hz = spi->controller->max_speed_hz;
        if (spi->controller->setup)
                status = spi->controller->setup(spi);

        spi_set_cs(spi, false);   /* 取消片选 */
        dev_dbg(&spi->dev, "setup mode %d, %s%s%s%s%u bits/w, %u Hz max --> %d\n",
                        (int) (spi->mode & (SPI_CPOL | SPI_CPHA)),
                        (spi->mode & SPI_CS_HIGH) ? "cs_high, " : "",
                        (spi->mode & SPI_LSB_FIRST) ? "lsb, " : "",
                        (spi->mode & SPI_3WIRE) ? "3wire, " : "",
                        (spi->mode & SPI_LOOP) ? "loopback, " : "",
                        spi->bits_per_word, spi->max_speed_hz, status);
        return status;
}

它干的事按顺序：DUAL/QUAD 同时存在直接 -EINVAL；SPI_3WIRE 下禁止多线位；用 mode_bits 校验模式位，多线位不支持时只警告并清掉该位、其它不支持位直接报错；bits_per_word 为 0 置 8 并 __spi_validate_bits_per_word 校验；max_speed_hz 为 0 用控制器的上限；调 spi->controller->setup(spi) 让控制器驱动落寄存器；最后 spi_set_cs(spi, false) 取消片选。

失败点集中在两处：模式位不被控制器支持、字长不被控制器支持。看到 setup: unsupported mode bits 这行，直接去控制器驱动的 mode_bits 赋值处对，多半是少了一个 SPI_CS_HIGH 或少了一个 SPI_LOOP。

spi_setup 在 spi_add_device 里被调用一次，作为设备上线前的初始化。驱动在 probe 里改了 spi->mode 或 spi->max_speed_hz 之后，必须自己再调一次 spi_setup(spi)，否则控制器那边还是旧参数。

十、SPI 的四种工作模式 #

四种模式由 mode 里的两位组合出来，核心就一句话：时钟空闲时是高还是低（SPI_CPOL），数据在第一个沿还是第二个沿采样（SPI_CPHA）。

模式 mode 值 CPOL CPHA 空闲电平 采样沿
SPI_MODE_0 0x00 0 0 低电平 第一个跳变沿（上升沿）
SPI_MODE_1 0x01 0 1 低电平 第二个跳变沿（下降沿）
SPI_MODE_2 0x02 1 0 高电平 第一个跳变沿（下降沿）
SPI_MODE_3 0x03 1 1 高电平 第二个跳变沿（上升沿）

宏定义就是把 SPI_CPHA / SPI_CPOL 两位拼起来：SPI_MODE_0 是 (0|0)、SPI_MODE_1 是 (0|SPI_CPHA)、SPI_MODE_2 是 (SPI_CPOL|0)、SPI_MODE_3 是 (SPI_CPOL|SPI_CPHA)。

选模式只看从设备手册。手册写 “supports SPI mode 0 (CPOL=0, CPHA=0)”，设备树里就写 spi-cpol/spi-cpha 全不写，或者 spi->mode = SPI_MODE_0。写错模式的典型表现是：能读到数据但全是 0xFF 或 0x00，或者读到的字节整体左移一位。波形上就是采样点落在数据跳变的那一瞬间。

模式是 spi_setup 校验过的，控制器不支持的模式位会在 mode_bits 那关被拦下。所以先在驱动里设 spi->mode = SPI_MODE_3;，再 spi_setup(spi)，返回非 0 就是控制器不支持。

十一、片选信号的管理 #

片选是 SPI 区别于 I2C 的地方：没有地址，选谁全靠一根片选线。内核里两条实现路径。路径一：控制器硬件片选，用 spi_controller.num_chipselect 声明数量，驱动实现 set_cs 钩子，enable 为 true 是选中；这个函数会在中断上下文被调用，实现里不能睡眠，S3C2410 这类控制器的片选就是直接写控制寄存器。路径二：GPIO 片选，由 spi_controller 拿 cs_gpios（旧的编号数组）或 cs_gpiods（新的描述符数组），核心层每次传输前后拉电平。

钩子原型是 void (*set_cs)(struct spi_device *spi, bool enable)；GPIO 片选那边对应的是 cs_gpios（编号数组）、cs_gpiods（描述符数组）和开关 use_gpio_descriptors。

两者的关系是描述符优先：spi_add_device 里先看 ctlr->cs_gpiods，有就把 cs_gpiods[chip_select] 赋给 spi->cs_gpiod；只有它为空时才退回去看 ctlr->cs_gpios，把 cs_gpios[chip_select] 赋给 spi->cs_gpio。

use_gpio_descriptors 置位后核心层自己解析并抓取 GPIO 描述符，这时别再用 cs_gpios，从设备拿到的是 cs_gpiod。spi_register_controller 里如果它为真，会调 spi_get_gpio_descs(ctlr)，顺手给 mode_bits 或上 SPI_CS_HIGH——GPIO 片选天然支持高电平选中。

版本注记：use_gpio_descriptors 与 cs_gpiods 是 4.20 前后引入的（未验证精确版本），3.x/4.4 只有 cs_gpios。素材 2 里的 spi_master 结构只有 num_chipselect 和 cs，那是更早的形态。

一次 message 的片选时序，全在 spi_transfer_one_message 里：进入时 spi_set_cs(msg->spi, true) 选中，整条 message 期间保持；中途某 transfer 置了 cs_change 且不是最后一个，就先拉高、udelay(10)、再拉低，给从设备一个「命令结束」的信号；最后一个 transfer 置了 cs_change，keep_cs = true，片选保持到下一条 message；出错（ret != 0）或 keep_cs 为假，spi_set_cs(msg->spi, false) 取消选中。

cs_change 在最后一个 transfer 上的语义是「片选保持到下一次传输」，这是一个性能提示；多设备总线上你不释放片选，别的设备只要发起传输就会把你顶掉。有些设备要求「一次事务由多条 message 拼出来，片选拉高才算结束」，这种情况就必须靠 cs_change 保证正确性，不能省。

片选号检查在 spi_add_device 入口：chip_select >= ctlr->num_chipselect 时打印 cs%d >= max %d 并返回 -EINVAL。

片选冲突检测也在同一个函数里：bus_for_each_dev(&spi_bus_type, NULL, spi, spi_dev_check) 遍历 SPI 总线，返回非 0 就报 chipselect %d already in use 并 goto done。

顺序很讲究：必须在 spi_setup() 之前查冲突，否则会把别人的配置冲掉。

SPI_NO_CS（0x40）是个特例：一条总线只挂一个设备时可以不占片选线，置这一位，控制器就不动片选了。SPI_CS_WORD（0x1000）是另一个特例：每传完一个字翻一次片选，给那些用片选当字节边界的芯片用；控制器不原生支持它有软件兜底，所以 spi_setup 的 bad_bits 计算里把它排除了。

十二、注册流程：controller 怎么注册 #

控制器注册分三步：分配、填钩子、注册。分配用 spi_alloc_master（旧名）或 spi_alloc_controller（新名）。

版本注记：spi_alloc_master() 在 5.0 之后改名为 spi_alloc_controller()，spi_register_master() 改名 spi_register_controller()，spi_unregister_master() 改名 spi_unregister_controller()。内核保留了旧名做兼容，但新驱动不要再写旧名。

spi_alloc_master(host, size) 只是个 static inline 壳，直接 return __spi_alloc_controller(host, size, false)；真正的实现在这里：

c
struct spi_controller *__spi_alloc_controller(struct device *dev,
                                              unsigned int size, bool slave)
{
        struct spi_controller *ctlr;

        if (!dev)
                return NULL;

        /* 控制器 + 驱动私有数据申请成一整块 */
        ctlr = kzalloc(size + sizeof(*ctlr), GFP_KERNEL);
        if (!ctlr)
                return NULL;

        device_initialize(&ctlr->dev);
        ctlr->bus_num = -1;               /* 负数表示动态分配编号 */
        ctlr->num_chipselect = 1;         /* 默认片选数量 */
        ctlr->slave = slave;
        if (IS_ENABLED(CONFIG_SPI_SLAVE) && slave)
                ctlr->dev.class = &spi_slave_class;
        else
                ctlr->dev.class = &spi_master_class;   /* 只有 class，没有 bus */
        ctlr->dev.parent = dev;                        /* 父节点一般是 platform 设备 */
        pm_suspend_ignore_children(&ctlr->dev, true);
        spi_controller_set_devdata(ctlr, &ctlr[1]);   /* dev.driver_data = &ctlr[1] */

        return ctlr;
}

kzalloc 申请的是 spi_controller + size 一整块，首地址当控制器用，剩下的 size 字节通过 spi_controller_set_devdata(ctlr, &ctlr[1]) 挂到 dev->driver_data 上，留给芯片厂商塞自己的私有结构。spi_master_get_devdata → spi_controller_get_devdata → dev_get_drvdata 一路取回那段内存；分配和取回成对，别自己再 kzalloc 一份。探针函数前后两版对照：

注册用 spi_register_controller（旧名 spi_register_master），定义在 drivers/spi/spi.c：

c
int spi_register_controller(struct spi_controller *ctlr)
{
        struct device           *dev = ctlr->dev.parent;   /* 父设备，一般是 platform 设备 */
        struct boardinfo        *bi;
        int                     status, id, first_dynamic;

        if (!dev) return -ENODEV;

        status = spi_controller_check_ops(ctlr);   // 钩子齐不齐
        if (status) return status;
        /* ① 指定编号则固定登记；② 否则先试 DT alias；③ 再不行从最高 alias+1 动态分配 */
        if (ctlr->bus_num < 0 && ctlr->dev.of_node) ctlr->bus_num = of_alias_get_id(ctlr->dev.of_node, "spi");
        if (ctlr->bus_num < 0) {
                first_dynamic = of_alias_get_highest_id("spi");
                ctlr->bus_num = (first_dynamic < 0) ? 0 : first_dynamic + 1;
        }
        mutex_lock(&board_lock);
        id = idr_alloc(&spi_master_idr, ctlr, ctlr->bus_num, ctlr->bus_num + 1, GFP_KERNEL);
        mutex_unlock(&board_lock);
        if (WARN(id < 0, "couldn't get idr")) return id == -ENOSPC ? -EBUSY : id;
        ctlr->bus_num = id;
        INIT_LIST_HEAD(&ctlr->queue);
        spin_lock_init(&ctlr->queue_lock);
        spin_lock_init(&ctlr->bus_lock_spinlock);
        mutex_init(&ctlr->bus_lock_mutex);
        mutex_init(&ctlr->io_mutex);
        ctlr->bus_lock_flag = 0;
        init_completion(&ctlr->xfer_completion);
        if (!ctlr->max_dma_len)
                ctlr->max_dma_len = INT_MAX;

        dev_set_name(&ctlr->dev, "spi%u", ctlr->bus_num);

        if (!spi_controller_is_slave(ctlr)) {   /* GPIO 片选描述符：新路径 / 旧路径 */
                status = ctlr->use_gpio_descriptors ?
                         spi_get_gpio_descs(ctlr) : of_spi_register_master(ctlr);
                if (status)
                        return status;
                if (ctlr->use_gpio_descriptors)
                        ctlr->mode_bits |= SPI_CS_HIGH;   /* GPIO 片选支持高电平选中 */
        }
        if (!ctlr->num_chipselect)   /* 没片选就没设备，直接终止 */
                return -EINVAL;

        status = device_add(&ctlr->dev);   /* 失败时回滚 idr 后 goto done */
        if (status < 0) { idr_remove(&spi_master_idr, ctlr->bus_num); goto done; }
        dev_dbg(dev, "registered %s %s\n", spi_controller_is_slave(ctlr) ? "slave" : "master", dev_name(&ctlr->dev));

        /* 老 transfer 钩子会被警告；实现 transfer_one 的走队列机制 */
        if (ctlr->transfer)
                dev_info(dev, "controller is unqueued, this is deprecated\n");
        else if (ctlr->transfer_one || ctlr->transfer_one_message) {
                status = spi_controller_initialize_queue(ctlr);
                if (status) { device_del(&ctlr->dev); idr_remove(&spi_master_idr, ctlr->bus_num); goto done; }
        }
        spin_lock_init(&ctlr->statistics.lock);

        /* 挂上全局链表，扫 board_list 建从设备，再按 DT / ACPI 建 */
        mutex_lock(&board_lock);
        list_add_tail(&ctlr->list, &spi_controller_list);
        list_for_each_entry(bi, &board_list, list)
                spi_match_controller_to_boardinfo(ctlr, &bi->board_info);
        mutex_unlock(&board_lock);
        of_register_spi_devices(ctlr);
        acpi_register_spi_devices(ctlr);
done:
        return status;
}

整个流程拆成五步：spi_controller_check_ops 检查钩子（transfer、transfer_one、transfer_one_message 至少得有一个，都没有核心层就跑不起来）；分配 bus_num（idr_alloc 往 spi_master_idr 插节点，节点 ID 就是 bus_num，固定编号按固定编号插、DT alias 用 alias 编号、都没有就从 of_alias_get_highest_id("spi") + 1 起动态分配）；锁与链表初始化，max_dma_len 未给设 INT_MAX，dev_set_name 把设备名设成 spi%u；抓 GPIO 片选描述符、num_chipselect 为 0 直接 -EINVAL、device_add 挂进系统并生成 /sys/devices/platform/xxx-spi.x/spi_master/spi%d；队列初始化后把控制器挂上 spi_controller_list，扫 board_list，再按 DT 和 ACPI 建设备。

最后两步的顺序决定了一件事：从设备是在控制器注册的尾声里被创建的，不是在 arch 初始化时创建的。原因在下一节。

spi_match_controller_to_boardinfo 就三步：ctlr->bus_num != bi->bus_num 直接返回，对上了 dev = spi_new_device(ctlr, bi)，建不出来就把 can't create new device for %s 打到 ctlr->dev.parent 上。

队列初始化 #

spi_register_controller 里调了 spi_controller_initialize_queue，它是新旧传输机制的分水岭：

c
static int spi_controller_initialize_queue(struct spi_controller *ctlr)
{
        int ret;

        ctlr->transfer = spi_queued_transfer;   /* 核心层接管入队 */
        if (!ctlr->transfer_one_message)        // 核心层接管 message 级传输
                ctlr->transfer_one_message = spi_transfer_one_message;

        ret = spi_init_queue(ctlr);
        if (ret) {
                dev_err(&ctlr->dev, "problem initializing queue\n");
                goto err_init_queue;
        }
        ctlr->queued = true;
        ret = spi_start_queue(ctlr);
        if (ret) {
                dev_err(&ctlr->dev, "problem starting queue\n");
                goto err_start_queue;
        }
        return 0;

err_start_queue:
        spi_destroy_queue(ctlr);
err_init_queue:
        return ret;
}

它做两件事：把 transfer 改成核心层的 spi_queued_transfer（能进来说明驱动自己没设 transfer），把 transfer_one_message 缺省填成核心层的 spi_transfer_one_message；到这一步两个钩子都由核心层接管，厂家只需要实现 transfer_one。接着 spi_init_queue 建内核线程：

kthread_run 起内核线程，kthread_init_work 把 pump_messages 绑成 spi_pump_messages；rt 为真时把线程提到 SCHED_FIFO，对波形抖动敏感的控制器会开这个。

c
static int spi_init_queue(struct spi_controller *ctlr)
{
        struct sched_param param = { .sched_priority = MAX_RT_PRIO - 1 };

        ctlr->running = false;
        ctlr->busy = false;

        kthread_init_worker(&ctlr->kworker);      /* 初始化工作线程 */
        ctlr->kworker_task = kthread_run(kthread_worker_fn, &ctlr->kworker,
                                         "%s", dev_name(&ctlr->dev));
        if (IS_ERR(ctlr->kworker_task)) {         /* 起内核线程，名字用设备名 */
                dev_err(&ctlr->dev, "failed to create message pump task\n");
                return PTR_ERR(ctlr->kworker_task);
        }
        kthread_init_work(&ctlr->pump_messages, spi_pump_messages);

        if (ctlr->rt)   /* 实时优先级跑消息泵，缩短传输请求到调度的延迟 */
                sched_setscheduler(ctlr->kworker_task, SCHED_FIFO, &param);
        return 0;
}

spi_start_queue 只是把 running 拉起来再挂上初始工作：

c
static int spi_start_queue(struct spi_controller *ctlr)
{
        unsigned long flags;

        spin_lock_irqsave(&ctlr->queue_lock, flags);
        if (ctlr->running || ctlr->busy) {
                spin_unlock_irqrestore(&ctlr->queue_lock, flags);
                return -EBUSY;
        }
        ctlr->running = true;
        ctlr->cur_msg = NULL;
        spin_unlock_irqrestore(&ctlr->queue_lock, flags);

        kthread_queue_work(&ctlr->kworker, &ctlr->pump_messages);   /* 挂上初始 work */

        return 0;
}

running = true 之后，__spi_queued_transfer 里那道 !ctlr->running 的检查再也不会命中，注册完控制器这个值一直是 true。

十三、注册流程：driver 怎么注册与匹配 #

spi_driver 用 spi_register_driver 注册，实际展开到 __spi_register_driver：

        return driver_register(&sdrv->driver);
}

关键在 sdrv->driver.bus = &spi_bus_type，有了这一行 driver_register 才能把驱动挂到 SPI 总线的驱动链表上，后面的匹配才有戏。注意 probe 被转接了：你写的 sdrv->probe 换成核心层的 spi_drv_probe，由它再去调你的函数，检查 modalias、driver_override、处理 -EPROBE_DEFER 这些都在你的 probe 之前做完。

设备这边要经过三个函数：spi_alloc_device 分配、spi_add_device 上线、spi_new_device 把两步合成一步。

c
/* 只分配和初始化，不注册；填完 modalias / chip_select / mode 再调 spi_add_device */
struct spi_device *spi_alloc_device(struct spi_controller *ctlr)
{
        struct spi_device *spi;

        if (!spi_controller_get(ctlr))
                return NULL;
        spi = kzalloc(sizeof(*spi), GFP_KERNEL);
        if (!spi) {
                spi_controller_put(ctlr);
                return NULL;
        }

        spi->master = spi->controller = ctlr;   /* 记下所属控制器 */
        spi->dev.parent = &ctlr->dev;           /* 父设备是控制器 */
        spi->dev.bus = &spi_bus_type;           /* 挂在 spi 总线上 */
        spi->dev.release = spidev_release;
        spi->cs_gpio = -ENOENT;
        spin_lock_init(&spi->statistics.lock);
        device_initialize(&spi->dev);

        return spi;
}

int __spi_register_driver(struct module *owner, struct spi_driver *sdrv)
{
        static DEFINE_MUTEX(spi_add_lock);
        struct spi_controller *ctlr = spi->controller;
        struct device *dev = ctlr->dev.parent;
        int status;

        if (spi->chip_select >= ctlr->num_chipselect) {   /* 片选编号范围 0..max */
                dev_err(dev, "cs%d >= max %d\n", spi->chip_select, ctlr->num_chipselect);
                return -EINVAL;
        }
        spi_dev_set_name(spi);  /* 名字形如 spi0.0：控制器名 + 片选号 */

        /* 必须在 setup() 之前查冲突，否则会把别人的配置冲掉；顺带挡住并发 add() */
        mutex_lock(&spi_add_lock);
        status = bus_for_each_dev(&spi_bus_type, NULL, spi, spi_dev_check);
        if (status) {
                dev_err(dev, "chipselect %d already in use\n", spi->chip_select);
                goto done;
        }
        /* 描述符优先，其次才是旧的 cs_gpios */
        if (ctlr->cs_gpiods)
                spi->cs_gpiod = ctlr->cs_gpiods[spi->chip_select];
        else if (ctlr->cs_gpios)
                spi->cs_gpio = ctlr->cs_gpios[spi->chip_select];

        status = spi_setup(spi);      /* 默认值与校验 */
        if (status < 0) {
                dev_err(dev, "can't setup %s, status %d\n", dev_name(&spi->dev), status);
                goto done;
        }

        status = device_add(&spi->dev);   /* 这一步会触发总线匹配，匹配上就直接跑 probe */
        if (status < 0)
                dev_err(dev, "can't add %s, status %d\n", dev_name(&spi->dev), status);
        else
                dev_dbg(dev, "registered child %s\n", dev_name(&spi->dev));
done:
        mutex_unlock(&spi_add_lock);
        return status;
}

顺序严格：查片选范围 → 起名 → 加锁查冲突 → 拿 GPIO → spi_setup → device_add。device_add 那一步会触发总线匹配，匹配上就直接调驱动 probe，所以 spi_add_device 返回时设备已被驱动接管。

spi_new_device 是分配加添加的组合拳：

c
struct spi_device *spi_new_device(struct spi_controller *ctlr,
                                  struct spi_board_info *chip)
{
        struct spi_device *proxy;
        int                status;

        proxy = spi_alloc_device(ctlr);
        if (!proxy)
                return NULL;

        /* spi_board_info 的字段逐个搬到 spi_device */
        WARN_ON(strlen(chip->modalias) >= sizeof(proxy->modalias));
        proxy->chip_select = chip->chip_select;
        proxy->max_speed_hz = chip->max_speed_hz;
        proxy->mode = chip->mode;
        proxy->irq = chip->irq;
        strlcpy(proxy->modalias, chip->modalias, sizeof(proxy->modalias));
        proxy->dev.platform_data = (void *) chip->platform_data;
        proxy->controller_data = chip->controller_data;
        proxy->controller_state = NULL;

        if (chip->properties) {
                status = device_add_properties(&proxy->dev, chip->properties);
                if (status) {
                        dev_err(&ctlr->dev, "failed to add properties to '%s': %d\n",
                                chip->modalias, status);
                        goto err_dev_put;
                }
        }
        status = spi_add_device(proxy);
        if (status < 0)
                goto err_remove_props;
        return proxy;

err_remove_props:
        if (chip->properties)
                device_remove_properties(&proxy->dev);
err_dev_put:
        spi_dev_put(proxy);
        return NULL;
}

spi_board_info 到 spi_device 的字段映射就在这几行里落下。不要自己分别调 spi_alloc_device 和 spi_add_device，直接调 spi_new_device，错误清理它都做好了。

版本注记：spi_new_device() 在 5.0 之前参数类型是 struct spi_master *，5.0 跟着改名成 struct spi_controller *；老版本也没有 chip->properties 那段。spi_add_device() 的片选冲突检查在 4.0 前后改过一次（未验证精确版本），早期用 device_find_child 遍历，不是 bus_for_each_dev + spi_dev_check。

十四、匹配机制：spi_device_id 与 of_match_table #

SPI 总线本身是个 bus_type 实例，只填了四个成员：.name = "spi"、.dev_groups = spi_dev_groups、.match = spi_match_device、.uevent = spi_uevent。match 是全篇的主线。

匹配入口是 spi_match_device：

c
static int spi_match_device(struct device *dev, struct device_driver *drv)
{
        const struct spi_device *spi = to_spi_device(dev);
        const struct spi_driver *sdrv = to_spi_driver(drv);

        if (spi->driver_override)   /* ① override：硬指定，其它方式全跳过 */
                return strcmp(spi->driver_override, drv->name) == 0;
        if (of_driver_match_device(dev, drv))    /* ② 设备树 compatible */
                return 1;
        if (acpi_driver_match_device(dev, drv))  /* ③ ACPI */
                return 1;
        if (sdrv->id_table)                      /* ④ id_table */
                return !!spi_match_id(sdrv->id_table, spi);
        return strcmp(spi->modalias, drv->name) == 0;   /* 兜底：模态名对驱动名 */
}

static const struct spi_device_id *spi_match_id(const struct spi_device_id *id,
                                                const struct spi_device *sdev)
{
        for (; id->name[0]; id++)
                if (!strcmp(sdev->modalias, id->name))
                        return id;
        return NULL;
}

表的最后一项 name 为空，循环靠它停下来——漏写这个结尾项会越界读。

对比项 spi_device_id + id_table of_match_table
定义位置 / 关键字段 include/linux/spi/spi.h，name + driver_data include/linux/mod_devicetable.h，compatible + data
比的是什么 / 优先级 spi_device.modalias 与 id->name 相等，第 4 顺位 设备树 compatible 与表中项相等，第 2 顺位，早于 id_table
典型用途 非设备树的老板子（mach-xxx 里写 spi_board_info） 现代 ARM 板，dts 里描述

两条路不是二选一，现代驱动两边都写：老平台走 id_table，新平台走 of_match_table。只写 id_table 而设备树里的 compatible 又对不上，probe 不会进来——移植旧驱动时这种问题最常见。spi_match_id 的返回值只用来判断「匹配还是没匹配」，你要拿 driver_data 区分芯片型号就在 probe 里自己查表。

十五、从设备树实例化 SPI 设备 #

Linux 3.x 之后支持设备树，板级 SPI 信息就不用在 arch/arm/mach-xxx 里写死了，改成在控制器节点下面挂子节点。

dts
&spi1 {
        status = "okay";
        cs-gpios = <&gpa3 3 GPIO_ACTIVE_LOW>;
        num-cs = <1>;
        ssd1306: oled@0 {
                compatible = "solomon,ssd1306fb";   /* 名称按芯片手册核对 */
                reg = <0>;                          /* 片选号 */
                spi-max-frequency = <8000000>;
                spi-cpol;
                spi-cpha;
                reset-gpios = <&gpf1 2 GPIO_ACTIVE_LOW>;
        };
};

解析由 of_register_spi_devices 在 spi_register_controller 末尾完成：逐个遍历控制器节点的子节点，转成 spi_board_info，再走 spi_new_device。属性名是固定的，写错一个字母核心层就不认。

属性和字段的对应：compatible 决定匹配（与驱动 of_match_table 比对）；reg 落到 chip_select，必须小于 num_cs；spi-max-frequency 落到 max_speed_hz（单位 Hz）；spi-cpol/spi-cpha/spi-cs-high/spi-3wire/spi-lsb-first/spi-cs-word 这几个布尔属性分别给 mode 或上 SPI_CPOL/SPI_CPHA/SPI_CS_HIGH/SPI_3WIRE/SPI_LSB_FIRST/SPI_CS_WORD；spi-tx-bus-width/spi-rx-bus-width 落到 tx_nbits/rx_nbits（1/2/4/8）；interrupts 落到 irq。

控制器节点上还有两个关键属性：cs-gpios 给 GPIO 片选，num-cs 给片选数量；num-cs 不写时默认 1，所以只挂一个从设备的控制器经常省略它，cs-gpios 里可以写 0 占位表示该号片选不走 GPIO。设备树这条路的优势是板级信息不再是代码，换板子只改 dts；缺点也直接：compatible 打错、reg 超范围、spi-max-frequency 超上限都会在启动日志里报，但不阻止系统继续跑——从设备干脆不存在，probe 永远不进。

十六、DMA 传输与 PIO 传输 #

两种数据搬运方式，选哪个由控制器驱动的能力决定，不是你说了算。PIO：CPU 一个字节一个字节地读/写数据寄存器。所以你会看到 hw_txbyte() 这种函数，把数据段的第一个字节写进 XXX_SPIDAT 触发一次传输，后面的字节在中断处理函数里接着灌。哪怕只是收数据，也得先往数据寄存器写一个字节，因为时钟是主设备发出去的，不写就没有时钟。DMA：控制器自己搬数据，CPU 只在开始和结束时介入，适合大块数据、高速率场景。

核心层给 DMA 留的接口就是这几个成员：dma_alignment 是控制器对 DMA 缓冲区的对齐要求，不对齐就 DMA 不了；max_dma_len 是单次 DMA 的最大长度，未设时 spi_register_controller 里补成 INT_MAX；can_dma 判断这一次 spi_transfer 能不能走 DMA，返回 true 才会在 transfer_one 之前做映射；dma_tx/dma_rx 是收发 DMA 通道；dummy_rx/dummy_tx 是全双工控制器的哑缓冲区，队列收尾时被 kfree 掉。

can_dma 存在且返回 true 时，核心层会在调 transfer_one 之前把缓冲区映射好，驱动不用自己 dma_map_single，但这时不能改动或保存 xfer，dma_tx/dma_rx 必须在设备 prepared 期间设好。调用点分散在三处：spi_add_device 里的 spi_setup 决定初始模式与速率；__spi_pump_messages 里的 spi_map_msg 处理映射；spi_transfer_one_message 循环调 transfer_one。

缓冲区要求是硬性的：tx_buf/rx_buf 必须是 DMA 安全内存。栈上变量能过映射但容易踩缓存一致性，kmalloc 的内存也未必满足 dma_alignment，所以用 dma_alloc_coherent 或带 GFP_DMA 的分配再对齐。预映射是另一套：把 is_dma_mapped 置 1 并自己填好 tx_dma/rx_dma，核心层就不再帮你映射，省一次开销但撤销得你管。

判断口诀：几十字节的寄存器读写走 PIO（映射开销比传数据还大）；几 KB 的帧、持续传输走 DMA；控制器没有 DMA 通道就只能 PIO（看 dma_tx/dma_rx 是否为空）；缓冲区在栈上、对齐不保证也走 PIO；传输期间要 CPU 干别的就用 DMA + spi_async。

版本注记：can_dma、dma_alignment、max_dma_len、dummy_rx/dummy_tx 这几个成员在 3.x 里并不齐全，can_dma 是 3.15 前后加入的（未验证精确版本）。3.x 的 DMA 支持主要靠控制器驱动自己在 transfer 里做。素材 2 的 spi_bitbang 里那个 use_dma 标志，就是那个年代的痕迹。

十七、调试手段与常见故障 #

先看 sysfs，八成问题第一眼就能定位。/sys/bus/spi/devices/ 是该总线上所有 SPI 设备的链接（含控制器），/sys/bus/spi/drivers/ 是所有驱动的链接，/sys/class/spi_master/spi0/ 是控制器 0（控制器挂的是 class 不是 bus），/sys/bus/spi/devices/spi0.0/ 是控制器 0 上片选 0 的设备，/sys/class/spi_master/spi0/statistics/ 有该控制器的消息与字节计数。

spi_bus_type 的链表里除了从设备还有 SPI 控制器，所以 /sys/bus/spi/devices/ 下看到控制器别惊讶，那是 spi_register_controller 里 device_add(&ctlr->dev) 的结果。

设备名是 spi_dev_set_name 拼出来的，格式是 spi-%s 或 %s.%u，也就是「控制器名 + 点 + 片选号」，例如 spi0.0。这个命名规则在排查片选冲突时特别好用。

看模式是否生效，先 cat /sys/bus/spi/devices/spi0.0/modalias 对一下名字，再 dmesg | grep -i spi 看初始化日志。

spi_setup 里那句 dev_dbg 打印最终生效的模式，形如 spi spi0.0: setup mode 3, 8 bits/w, 8000000 Hz max --> 0；mode 3 即 CPOL=1、CPHA=1，末尾数字是 controller->setup 的返回值，0 为成功。统计计数器在 /sys/class/spi_master/spi0/statistics/ 下，errors 涨而 transfers 不涨说明控制器在报错，直接看 dmesg。打开调试输出靠编译内核时开 CONFIG_SPI_DEBUG，或临时在 spi_transfer_one_message 里加 printk。

常见故障对照：

现象 首查点 处置
probe 完全没进 compatible / modalias 是否与驱动对上 cat /sys/bus/spi/devices/*/modalias 对名字，再查匹配日志

再补两个非常规手段。一是 /proc/interrupts：SPI 传输完成中断在涨说明控制器在工作，问题在数据不在通道，完全不涨说明传输根本没启动。二是 spidev：把从设备挂到它上面（compatible = "rohm,dh2228fv" 这类临时兼容名），从用户空间用 SPI_IOC_MESSAGE ioctl 直接发 message，不写驱动就能验证硬件通路——确认「是硬件问题还是驱动问题」时这一招最省时间。

十八、易错点速查 #

# 易错点 正确做法
1 用 spi_master 类型名写新驱动 5.0 起用 spi_controller，旧名只是宏别名
2 spi_register_board_info 放在 spi_register_controller 之后；用 __initdata 装 platform_data 板级信息必须先注册；__initdata 释放后 platform_data 就是野指针
3 把 spi_controller 当 SPI 总线设备 控制器只有 class 和 parent，bus 为空；挂 spi 总线的是 spi_device
4 忘了 id_table 结尾的空项 spi_match_id 靠 name[0] == 0 停，漏写就数组越界
5 mode 同时置 SPI_TX_DUAL 和 SPI_TX_QUAD，或 SPI_3WIRE 下还配多线位 spi_setup 直接返回 -EINVAL
6 改了 spi->mode/max_speed_hz 不调 spi_setup 控制器那边还是旧参数
7 在 complete 回调之前碰缓冲区；在中断上下文调 spi_sync；在 transfer 钩子里睡眠 缓冲区归核心层直到 complete 返回；spi_sync 会 mutex_lock 睡眠只能异步；transfer 只负责入队
8 同时实现 transfer_one 和 transfer_one_message，或一个都不实现 两者互斥；都不实现则 spi_controller_check_ops 报错
9 只给 tx_buf 又期望收到数据，或 len 填成 tx+rx 总长 收数据必须给 rx_buf；len 是各自缓冲区长度，两者恒等
10 片选冲突检查前就调 spi_setup；用 GPIO 片选却还在用 cs_gpios 顺序是查冲突 → 拿 GPIO → spi_setup；use_gpio_descriptors 打开后走 cs_gpiods
11 DMA 缓冲区用栈上变量；控制器 num_chipselect 为 0；以为 transfer_one 返回 1 是失败 必须 DMA 安全内存并满足 dma_alignment；片选数为 0 时 -EINVAL；返回 1 只是进行中
12 dts 的 reg 超过 num-cs；用 spi_register_device；拿 spi_bitbang_start() 上 5.x 日志只会报 cs；内核无 spi_register_device；spi_bitbang 已被消息泵替代

一条经验：probe 没进，九成是匹配问题；probe 进了但读写不对，九成是模式或片选问题。 先分清这两条，再往下查硬件。

十九、一张图串起整条路径 #

把前面各章压成一条调用链，回头查按这条线走。

text
设备驱动（你写的）
  spi_sync(spi, &msg)                    ← 同步；异步是 spi_async
    mutex_lock(bus_lock_mutex)
    __spi_sync
      __spi_validate                     ← 校验 mode / bits_per_word / len
      __spi_queued_transfer(.., false)   ← 入队到 ctlr->queue
      __spi_pump_messages(ctlr, false)   ← 同步就在这里把活干完
        cur_msg = list_first_entry(&ctlr->queue, ...)
        prepare_transfer_hardware        ← 可选，硬件首次上电
        prepare_message / spi_map_msg    ← 可选，DMA 映射
        ctlr->transfer_one_message       ← 默认 spi_transfer_one_message
          spi_set_cs(spi, true)
          ctlr->transfer_one(...)        ← 真正操作寄存器，每个 transfer 一次
          spi_set_cs(spi, false)
          spi_finalize_current_message
            kthread_queue_work(...)      ← 驱动下一个消息
            mesg->complete(context)      ← 唤醒 spi_sync 的等待者
      wait_for_completion(&done)
    mutex_unlock(bus_lock_mutex)

异步走的还是这条链，只是把 __spi_pump_messages 那段交给 ctlr->kworker 内核线程，提交线程立刻返回。__spi_queued_transfer 的第三个参数 need_pump 就是分岔点：异步传 true 顺带把消息泵叫醒，同步传 false 自己在当前上下文里推。三个钩子的分工再列一次：

钩子 谁的活 什么时候被调
transfer 入队。默认 spi_queued_transfer，驱动自己实现就是老路子 spi_sync/spi_async 提交时
transfer_one_message 处理一条 message。默认 spi_transfer_one_message __spi_pump_messages 从队列取到消息后
transfer_one 处理一个 transfer。控制器驱动必须实现 spi_transfer_one_message 的循环里

厂家驱动只需要填 transfer_one，上面两层核心层全包。这也是 3.x 到 5.x 最大的结构变化：老驱动自己写 transfer + spi_bitbang，新驱动只写 transfer_one。

素材 2 的结构修复 #

素材 2 的 ### 标题全是坏的。这些行实际是 platform_bus_type 结构体的字段初始化，被误当成了章节标题：.name = "platform",、.dev_attrs = platform_dev_attrs,、.match = platform_match,、.uevent = platform_uevent,、.pm = PLATFORM_PM_OPS_PTR,。它们连同前面那个 struct bus_type platform_bus_type = { 和后面的 EXPORT_SYMBOL_GPL(platform_bus_type); 本来就是一整段代码，还原成代码块后属于这个样子：

c
struct bus_type platform_bus_type = {
        .name           = "platform",
        .dev_attrs      = platform_dev_attrs,
        .match          = platform_match,
        .uevent         = platform_uevent,
        .pm             = PLATFORM_PM_OPS_PTR,
};
EXPORT_SYMBOL_GPL(platform_bus_type);

这段属于 platform 总线的前置知识，本篇只在第二章用到其结论（platform 总线的 match 比较 name），不再单独展开。素材 2 首行的 H1「Linux SPI 子系统驱动程序结构分析」已删除，章节标题统一为本篇的编号体系。

素材 2 里另有五个 # 开头的伪标题（#控制器设备和驱动、#核心层驱动、#SPI 外设驱动、#SPI 控制器驱动、#SPI 设备驱动），是 Markdown 注释写法被误用，已按行内加粗处理或并入正文。
