一、SPI 是什么：四根线连接主从 #

SPI 是串行外设接口（Serial Peripheral Interface）的缩写，是美国摩托罗拉公司（Motorola）最先推出的一种同步串行传输规范，也是一种单片机外设芯片串行扩展接口，是一种高速、全双工、同步通信总线，所以可以在同一时间发送和接收数据。

先把定语拆开：串行——数据一位一位走单根线，线少但带宽受限；同步——有独立时钟线 SCLK 由主设备发，不需要双方约定波特率；全双工——收发各一根线，同时进行，每次时钟跳变都在「既发又收」；一主多从——只有一个主设备发时钟，靠片选 CS 决定跟谁说话。

这里有个说法要纠正：SPI 没有正式的国际化标准。 它是 Motorola 在自家芯片上搞出来的事实标准（de facto standard），后来各家半导体厂各自实现、各自命名，才有了 CPOL/CKP、CPHA/CKE、SS/NSS/CS/STE 这一堆别名。所以你查不同芯片手册会发现引脚名对不上、时序图边的画法也有出入。这不是我们看错了，是本来就没有一个 ISO/IEC 或 IEEE 文件管它。

原文未标注这段话的出处，也没有说 SPI 由谁标准化。我们在本篇补上这一层：没有标准组织背书，只有厂商约定俗成的兼容性。

二、四根线的分工：SCLK、MOSI、MISO、CS #

SPI 共有 4 条信号线：

  • MISO（Master in slave out）：主设备输入从设备输出，数据由从设备发出；
  • MOSI（Master out slave in）：主设备输出从设备输入，数据由主设备发出；
  • SCLK/SCK（Serial clock）：串行时钟信号，由主设备产生；
  • SS/CS（Slave/Chip select）：从机选择信号，一般低电平有效，由主设备发出；

信号线 全称 方向 由谁驱动 常见别名

MOSI Master Out Slave In 主 → 从 主设备 SDI（从设备侧）、SDO、DIN

关于别名有个坑要说清楚：MOSI 在从设备那一侧常被标成 SDI（Serial Data In），MISO 在从设备侧常被标成 SDO。方向都是相对于「该芯片自己」来说的，所以同一根线在主设备和从设备手册里名字是反过来的。

三、全双工与主从架构 #

SPI 属于一主多从（一个主设备（Master），多个从设备（Slave））的总线结构，当存在多个从设备的时候，主设备通过片选信号来决定选择哪个设备。

全双工的机制在原文第二章讲得挺准，我们直接引用并展开：

在 SPI 每个时钟周期内，都会进行一次全双工数据的传输，主设备通过 MOSI 线上发送 1 位时，从设备也会在读取数据之后通过 MISO 发送 1 位数据出去。

SPI 主从设备都有一个串行移位寄存器，主设备通过向它的 SPI 串行移位寄存器写入一个字节来发送一次数据传输。

关键在于「交换」这个词。SPI 的一轮通信不是「我发一句你说一句」，而是两个 8 位移位寄存器首尾相接成一个环，8 个时钟之后两边内容互换：

text
主设备移位寄存器                    从设备移位寄存器
  [7][6][5][4][3][2][1][0]   ──MOSI──►  [7][6][5][4][3][2][1][0]
        ▲                                        │
        └──────────────MISO──────────────────────┘

每来一个时钟：两边的寄存器一起左移/右移一位，
主设备移出的最高位进入从设备最低位，
从设备移出的最高位进入主设备最低位。
8 个时钟后：主设备里装的是从设备原来的内容。

这解释了两个反直觉的现象。第一，你只想收数据时，也得发点东西。 从设备要吐出数据，就得有时钟，而时钟由主设备的发送动作驱动，所以读之前得先写一个 dummy 字节（常见是 0xFF 或 0x00）把时钟「摇」出来。第二，你只想发数据时，也会收进来垃圾。 MISO 上从设备同时在吐东西，收不收是你的事，硬件还是把它塞进接收缓冲。

数据通信流程，原文列了四步：

  • 主设备发起信号，将 SS 或 CS 拉低，通信开始；
  • 主设备通过发送 SCLK 时钟信号，告诉从设备进行读写操作。这里的 SCLK 时钟信号是由 SPI 的模式来决定高电平还是低电平有效；
  • 主设备将要发送的数据写入到发送数据缓冲区（Memory），缓冲区经过移位寄存器位 [7:0]，串行移位寄存器通过 MOSI 将字节数据一位一位地传输到从设备，同时 MISO 接收到的数据经过移位寄存器一位一位地传输到接收缓冲区；
  • 从设备也将自己的串行移位寄存器位 [7:0] 的数据通过 MISO 传输到主设备，同时通过 MOSI 接收主设备发送的数据，这样这两个移位寄存器中的数据被交换；

四步的核心就是「两个寄存器被交换」。第 2 步说的「由 SPI 的模式决定高电平还是低电平有效」，就是后面第四到第六章要展开的 CPOL/CPHA。

四、时钟极性与时钟相位：CPOL 与 CPHA #

SPI 时钟特点主要包括：时钟频率、时钟极性和时钟相位。

SPI 主设备必须在通信开始之前配置并生成相应的时钟信号，当然时钟频率受限于我们 SPI 主设备能输出的最大频率、以及最大的 SPI 传输频率。

原文这句把两个上限说清了：主设备自己能做到多少，和目标器件能接受多少，取小的那个。工程上的含义是——时钟配错了不一定是软件写错，而是你超频了。 根据硬件制造商的命名规则不同，时钟极性写为 CKP 或 CPOL。时钟极性和相位共同决定读取数据的方式，比如信号上升沿读取数据还是信号下降沿读取数据。

时钟极性（CPOL）定义了 SCLK 时钟线空闲状态时的电平：

  • CPOL=0，即 SCLK=0，表示 SCLK 时钟信号线在空闲状态时的电平为低电平，因此有效状态为高电平；
  • CPOL=1，即 SCLK=1，表示 SCLK 时钟信号线在空闲状态时的电平为高电平，因此有效状态为低电平；

所以 CPOL 只回答一个问题：不说话的时候，时钟线停在哪。 它决定的是空闲电平，不是采样边沿。很多人把 CPOL 等同于「上升沿还是下降沿触发」，这是漏了 CPHA 那一半信息。

根据硬件制造商的不同，时钟相位写为 CKE 或 CPHA。

时钟相位（CPHA）定义了数据位相对于时钟线的时序（即相位）：

  • CPHA=0，在时钟信号 SCK 的第一个跳变沿采样；
  • CPHA=1，在时钟信号 SCK 的第二个跳变沿采样；

CPHA 回答的是：从第一个跳变沿算起，第几个边沿去采样。 两个参数合起来才能定下采样边沿和发送边沿：先定 CPOL 拿到空闲电平，也就定下哪个方向叫「第一个边沿」；再定 CPHA，从第一个边沿数第 1 个还是第 2 个采样；剩下的那个边沿自动就是发送（移出）边沿。

「第一个边沿」的含义跟着 CPOL 走。CPOL=0 时空闲低，第一个跳变是上升沿；CPOL=1 时空闲高，第一个跳变是下降沿。这一点在原文第五章的四条说明里其实已经隐含了，我们在这里先点明，后面看表就不会绕。

五、四种工作模式的组合 #

根据 SPI 的时钟极性和时钟相位特性可以设置 4 种不同的 SPI 通信操作模式，它们的区别是定义了在时钟脉冲的哪条边沿转换输出信号，哪条边沿采样输入信号，还有时钟脉冲的稳定电平值（就是时钟信号无效时是高还是低）。

Mode 0 0 0 低 第 1 个边沿 = 上升沿 下降沿（第一位在第一个上升沿之前）
Mode 1 0 1 低 第 2 个边沿 = 下降沿 上升沿
Mode 2 1 0 高 第 1 个边沿 = 下降沿 上升沿（第一位在第一个下降沿之前）
Mode 3 1 1 高 第 2 个边沿 = 上升沿 下降沿

具体说明如下，原文四条逐字保留：

  • 图 1，CPOL=0，CPHA=0：当空闲态时，SCLK 处于低电平，数据采样是在第 1 个边沿，也就是 SCLK 由低电平到高电平的跳变，所以数据采样是在上升沿，数据发送是在下降沿（第一位数据发送是在上升沿之前）；
  • 图 2，CPOL=0，CPHA=1：当空闲态时，SCLK 处于低电平，数据采样是在第 2 个边沿，也就是 SCLK 由高电平到低电平的跳变，所以数据采样是在下降沿，数据发送是在上升沿；
  • 图 3，CPOL=1，CPHA=0：当空闲态时，SCLK 处于高电平，数据采样是在第 1 个边沿，也就是 SCLK 由高电平到低电平的跳变，所以数据采样是在下降沿，数据发送是在上升沿（第一个数据发送是在下降沿之前）；
  • 图 4，CPOL=1，CPHA=1：当空闲态时，SCLK 处于高电平，数据采样是在第 2 个边沿，也就是 SCLK 由低电平到高电平的跳变，所以数据采样是在上升沿，数据发送是在下降沿；

从这四条能抽出一个不变的关系：采样边沿和发送边沿永远相邻，永远不会是同一个边沿。 发送完到下一次采样之间隔着半个周期，这就是数据的建立时间窗口。另一半周期是保持窗口。

还有个派生规律，用它背表比死记快：

观察 结论
Mode 0 与 Mode 3 采样都在上升沿，差别只在空闲电平
Mode 1 与 Mode 2 采样都在下降沿，差别只在空闲电平
CPHA=0 的模式 第一个数据位在片选拉低后就要准备好，不等边沿
CPHA=1 的模式 第一个边沿负责发送，第二个边沿才采样

Mode 0 和 Mode 3 是最常见的两个，你翻器件手册八成会撞上其中之一。Mode 1 和 Mode 2 相对少见，但确实存在，不能默认「大家都是 Mode 0」。

模式匹配不上会怎样？不会报错，只会收到错位的数据。比如主设备按 Mode 0 采样、从设备按 Mode 1 输出，主设备采到的每一位都差半个周期，读出来是一串看着像模像样的乱码。所以调 SPI 时读到的数据「有点规律但不对」，第一反应就该去核对模式，而不是去查数据线。

六、模式 0 的时序走读 #

Mode 0 是 CPOL=0、CPHA=0：空闲低、上升沿采样、下降沿发送。我们拿一位数据的完整周期走一遍。

text
CS    ‾‾‾\___________________________________________/‾‾‾
             ↑ 片选拉低，选中本从设备

SCLK  ____/‾‾\__/‾‾\__/‾‾\__/‾‾\__ ... __________
          ↑1  ↑2  ↑3  ↑4
          │   │   │   │
MOSI  ════╪═D7╪═D6╪═D5╪═D4══════════════════════════
          │↑采样
          │
        这里的 D7 是在第一个上升沿之前就摆好的

        边沿1（上升）→ 采样 D7
        边沿2（下降）→ 移出 D6
        边沿3（上升）→ 采样 D6
        边沿4（下降）→ 移出 D5
        ... 依此类推，8 个时钟后一个字节交换完成

按阶段拆开是这几步：

阶段 事件 谁在动
1 CS 由高拉低 主设备
2 双方把第 1 位（最高位）摆到 MOSI/MISO 上 主设备和从设备
3 第 1 个上升沿 双方采样，读入第 1 位
4 第 1 个下降沿 双方移出下一位
5 第 2 个上升沿 双方采样第 2 位
6 重复到第 8 个时钟 8 位全部交换完成
7 CS 由低拉高 主设备，一次传输结束

原文对 CPHA=0 的第一位有个专门括注：第一位数据发送是在上升沿之前。这句是 Mode 0 最容易踩空的地方。因为 CPHA=0 意味着「第一个边沿就采样」，没有留一次边沿给发送用，所以第 1 位必须在片选拉低那一刻就已经稳定在线上。软件上这对应的是「配置好数据再开时钟」，硬件上多数 SPI 控制器会自动处理这个先后，但裸机自己刷 GPIO 模拟 SPI 时就得自己留意。

CS 拉高之后不要立刻拉低开始下一轮。原文没写这中间的间隔，我们也不编数值——具体数值见各器件手册。有些 Flash 类器件要求 CS 高电平保持一段时间才算结束一个命令周期，这个时间在手册的 AC 特性表里，不同型号差别很大。

七、数据位序：MSB 与 LSB #

原文没单独讲位序，但它是协议层的必答题，我们补在这里。

SPI 传输一个字节时，8 个时钟是一位一位走的。先走哪一位，由位序（bit order）决定，两种：

位序 顺序 常见叫法
MSB first 先出 bit7，最后 bit0 大端位序，多数器件的默认
LSB first 先出 bit0，最后 bit7 少数器件或特定命令要求

MSB first 是绝大多数 SPI 器件的默认，这和「最高位先发」的串行传统一致。但 LSB first 确实存在，尤其在早期的一些 ADC、显示驱动里。

位序配反的现象很有辨识度：读回来的字节位是反的。比如器件实际给你 0x01，你收到的是 0x80；实际 0x0C，你收到 0x30。因为每一位都被映射到了镜像位置。这种「数值看着眼熟但差得离谱」的情况，先怀疑位序，别急着怀疑接线。

位序也是协议参数，不分主从会各自用默认值。主设备怎么配、从设备怎么期望，必须对齐。Linux 那边通过 spi_device 的 mode 字段里 SPI_LSB_FIRST 这个标志位来表达，具体怎么落到框架里，去《SPI 驱动框架与核心结构》看。

text
MSB first:  时钟1→bit7, 时钟2→bit6, ..., 时钟8→bit0
LSB first:  时钟1→bit0, 时钟2→bit1, ..., 时钟8→bit7

例：0x96 = 1001 0110
MSB first 线上依次出现: 1 0 0 1 0 1 1 0
LSB first 线上依次出现: 0 1 1 0 1 0 0 1

八、片选信号的作用 #

CS 在协议里承担两件事，原文都提到了，只是分散在两处。

第一件是选中设备。SPI 是单主设备（Single Master）通信协议，只有一个主设备能发起通信，当 SPI 主设备想读/写从设备时，它首先拉低从设备对应的 SS 线。总线是共享的——SCLK、MOSI、MISO 三根线所有从设备都挂着，如果没有片选，从设备不知道该听谁的。

第二件是界定一次传输的边界。SPI 通信无起始位和停止位，所以 CS 的下降沿就是「开始」，上升沿就是「结束」。这一点跟 UART 完全不同，UART 靠起始位和停止位来框帧，SPI 靠片选的跳变来框。

角色 CS 低电平期间 CS 高电平期间
被选中的从设备 响应 SCLK，在 MISO 上输出 忽略 SCLK，MISO 置高阻
没被选中的从设备 忽略 SCLK，MISO 置高阻 同上
主设备 产生时钟，收发数据 可以切换片选或改变模式

低有效这点原文说得很明确：一般低电平有效。写代码时的表述是「使能 = 拉低」，「失能 = 拉高」。有些资料会写成 CS 或 CS#，那条横杠或者井号就是低有效的记号。

原文讲读写动作的那句也在这里落地：接着开始发送工作脉冲到时钟线上，在相应的脉冲时间上，主设备把信号发到 MOSI 实现「写」，同时可对 MISO 采样而实现「读」。原文此处配有一幅 SPI 读写时序示意图，在网页抓取过程中丢失。

这句话把「读」和「写」从两个动作变成了同一个时钟里的两个采样点。写是「在边沿把数据摆上 MOSI」，读是「在边沿从 MISO 取走数据」。两者共用同一串 SCLK，所以不存在「先写后读」的时序，只有「同一个边沿同时读写」。

MISO 置高阻这件事值得单独说一句。因为 MISO 上是多个从设备并联，如果没被选中的从设备还强势驱动这根线，就会和当前被选中的设备打架，两边一起烧驱动管的风险是真的存在。所以「CS 高时 MISO 必须高阻」是协议层的硬要求，不是可选项。

有一个常见配置是「CS 一直拉低、多个设备挂同一根线」。这不是标准用法，只在你确实只有一个从设备时才成立。原文明说了前提：「如果从设备允许的话」。总线上一旦多挂一片，共享 CS 就等于共享一切，两片会同时响应同一串时钟。

九、多从机拓扑：独立片选与菊花链 #

SPI 属于一主多从的总线结构。原文给了两条关于多设备的规则：

当只有单一 SPI 从设备时，如果从设备允许的话，可直接将 CS/SS 线固定在低电平。

对于多个从设备时，则每个从设备都需要一根 CS/SS 线来与主设备相连，从而达到主设备能与任一从设备通信的目的。

第二条说的是独立片选（也叫并行接法），这是最常见的做法。主设备每多一个从设备，就多占一根 GPIO 当 CS。

text
独立片选（星型）：
主设备 ─SCLK─┬──────────► SCLK ─┬─ 从设备 1
       ─MOSI─┼──────────► MOSI ─┼─ 从设备 2
       ─MISO─┼──────────► MISO ─┼─ 从设备 3
       ──────┼──────────► CS1   从设备 1
       ──────┼──────────► CS2   从设备 2
       ──────┴──────────► CS3   从设备 3

三根公用线（SCLK/MOSI/MISO）所有从设备并联，CS 各自一根。N 个从设备占 N 根 CS。

还有第二种接法，原文没提，它是协议层面的另一条常见路径：菊花链（daisy chain）。所有从设备串成一串，只有第一片接主设备的 CS，其余各片的 CS 接上一片的输出，数据从一片的 MOSI 进、MISO 出接到下一片的 MOSI。

text
菊花链（串联）：
主设备 ─MOSI─► [从设备1] ─MISO→MOSI─► [从设备2] ─MISO→MOSI─► [从设备3] ─MISO─► 回主设备
        ─SCLK───────────────────────────────────────────────► 全部并联
        ─CS──► 只接第一片的 CS，其余由上一片的 CS 输出串下去

两种接法放一起对比：

维度 独立片选 菊花链
CS 占用 每片一根 总共 1 根
能否单独访问某一片 可以 不能直接访问，数据必须整条链一起移
一次传输的数据量 只跟目标设备交互 链上所有设备的字节数累加
对器件的要求 无特殊要求 器件必须支持 MISO 转发/共用 IO
布线复杂度 从设备多时 CS 线爆炸 线少，适合多个同型号串联
传输效率 直接命中目标 移位额外设备会拖慢有效带宽

菊花链的代价是数据要穿过前面所有设备，你在链尾放一片 8 字节的器件、链头放一片 1 字节的器件，读链尾器件时前面的字节也得跟着移。所以它适合「一堆同型号、位置固定」的场景，不适合「随机访问某个设备」的场景。

片选数量还受主设备限制。SPI 控制器上的硬件 CS 引脚数是有限的，不够用时要么扩 GPIO 做软件片选，要么用片选译码器。具体怎么在 Linux 里表达「这根片选在哪」，属于框架层的内容，去《SPI 驱动框架与核心结构》。

十、SPI 的速率与时钟分频 #

原文这一块只说了一句话，但它其实点了三个要点，我们逐个拆。

SPI 主设备必须在通信开始之前配置并生成相应的时钟信号，当然时钟频率受限于我们 SPI 主设备能输出的最大频率、以及最大的 SPI 传输频率。

要点一：时钟由主设备生成，且在通信开始之前就配好。 传输过程中不能临时改频率，改频率意味着改分频器，要停掉当前传输。

要点二：上限有两个。 一个是主设备自己能做到多少，一个是器件手册标称能接受多少。实际可用的频率取两者中小的那个。原文说 SPI 没有定义速度限制，能达到甚至超过 10M/bps——这是协议层面确实不设上限的表述，但工程上每条具体链路都有上限，由器件和布线决定。

要点三：频率来自分频，不是任意的连续值。 主设备有一路固定的输入时钟（PCLK 之类），通过分频器分频后给到 SCLK。所以你能选的频率是一组离散值，不是想要多少就有多少——填数字时是挑分频系数，不是直接写目标频率。分频寄存器位宽、取值表、是否支持奇分频，各家不一样，具体数值见各器件手册，本篇不编。

关于选频率，我们给三条实战守则，都不涉及具体数值：

场景 做法
首次点亮新器件 从低频率起步，通了再往上调
上板后偶发误码 先把频率降一半，看是否消失，能定位到是时序余量问题
长排线、多设备并联 频率上限会被布线和负载电容压低，别只看器件手册标称值

第三条尤其容易忽略。器件手册标的最高频率是在它自己的测试板上、短线、少负载的条件下测的。你飞线拉到 20 厘米外，边沿变缓，实际能跑多快跟手册没关系。

十一、SPI 与 I2C、UART 的对比 #

原文的优缺点章节其实一直在跟这两个协议比，我们把它整理成表，然后补上 UART 那一列。

先看原文的两段：

SPI 总线的优点：

  • SPI 通信无起始位和停止位，因此数据可以连续流传输而不会中断；没有像 I2C 这样的复杂的从站寻址系统，数据传输速率比 I2C 更高（几乎快两倍）。独立的 MISO 和 MOSI 线路，可以同时发送和接收数据；

SPI 总线的缺点：

  • SPI 使用四根线，而 I2C 和 UART 只是使用两根线，没有信号接收成功的确认（I2C 拥有该功能），没有任何形式的错误检查（如 UART 中的奇偶校验位等）；

对比表：

维度 SPI I2C UART
信号线数 4（SCLK/MOSI/MISO/CS），多从机时 CS 按设备增加 2（SCL/SDA），多从机共用 2（TX/RX），点对点
同步/异步 同步，有独立时钟线 同步，有独立时钟线 异步，靠双方约定波特率
通信方式 全双工 半双工 全双工
拓扑 一主多从，CS 选设备 多主多从，地址选设备 点对点，无总线概念
寻址方式 硬件片选，无地址字段 7 位或 10 位从机地址 无地址
数据帧开销 无起始位、无停止位、无地址 起始条件 + 地址 + ACK/NACK + 停止条件 起始位 + 数据 + 校验位 + 停止位
应答机制 无 有 ACK/NACK 无（靠校验位）
错误检测 无（协议层不提供） ACK 可察觉从机不在 奇偶校验位可选
从设备数量 受 CS 引脚数限制 受地址空间和总线电容限制 2（点对点）
相对速率 较高，原文称传速比 I2C 高（几乎快两倍） 较低 取决于双方配置的波特率
典型用途 Flash、显示屏、ADC、传感器 EEPROM、RTC、传感器、PMIC 串口调试、GPS、蓝牙模块

表里有三处跟原文有关：原文说「数据传输速率比 I2C 更高（几乎快两倍）」，这是个偏松的表述，实际差距取决于两边配的频率，「两倍」不是协议规定的常数，我们照原文保留并在勘误里标一下；原文说 I2C 和 UART「只是使用两根线」，I2C 是两根没错，UART 严格说还要共地，只算信号线是两根 TX/RX，原文属简化表述；「半双工」这一格容易误读，I2C 是单根 SDA 双向线，同一时刻只能一个方向传，SPI 有独立的 MOSI 和 MISO 可同时收发，UART 同样是两根独立 TX/RX 线，全双工。

十二、SPI 的优缺点 #

把原文的两段完整列出，再补几条工程角度的观察。

原文的优点只有一条长句，但它塞了三个理由：

原文理由 展开
无起始位和停止位 数据可以连续流传输而不会中断，不用像 UART 那样每帧插开销位
没有复杂的从站寻址系统 不需要像 I2C 那样发地址字节、等 ACK，省掉帧头
独立 MISO/MOSI 线路 可以同时发送和接收，全双工

原文的缺点也只有一条长句，同样三个理由：

原文理由 展开
用四根线 I2C 和 UART 只使用两根线，引脚和布线成本更高
没有接收成功的确认 I2C 有 ACK，SPI 没有，主设备不知道从设备是否真收到了
没有任何形式的错误检查 没有 UART 那种奇偶校验位，数据错了协议层发现不了

补充几条同样属于协议事实、不涉及具体芯片的观察：

补充项 属于优点还是缺点 说明
无标准组织背书 两面 好处是实现自由、厂商可以加私有扩展；坏处是命名和边沿画法各家不统一，移植时要看手册
从设备数量受 CS 引脚限制 缺点 挂 8 个设备就得 8 根 CS，MCU 引脚会不够
没有仲裁机制 限制 单主设备协议，不存在多主竞争，也就没有 I2C 那种总线仲裁
没有热插拔和总线检测 限制 器件不在位时主设备发出去的数据直接石沉大海，不会有任何反馈
协议层依赖外部保证可靠 限制 要可靠性得靠上层自己加 CRC 或重读回环校验

最后一条在实战里很关键。SPI 常被用于 Flash 读写、屏幕刷图这种数据量大的场景，一旦某一位传错，协议层不会告诉你。所以驱动里常见的做法是写完再读回比对，或者依赖器件本身的 CRC 命令。这一块不属于协议本身，但知道了协议不提供错误检测，就知道为什么代码里要自己补。

十三、常见外设类型 #

原文没列外设清单，我们按协议特征补一份，只讲「为什么这类外设选 SPI」，不涉及任何具体型号和参数。

外设类型 为什么用 SPI 对应协议特征
SPI NOR / NAND Flash 需要连续大批量读写，速率要求高 无帧头开销，可连续流传输
显示屏（OLED、TFT） 刷屏数据量大，且常只需单向写 MOSI 单方向高速推送即可，MISO 可不用
ADC / DAC 数据率高，需要同时收发（如边读边配） 全双工，MOSI 发命令 MISO 同时回数据
传感器（温湿度、加速度、气压） 寄存器式访问，读多写少 命令 + 地址 + 数据 的短帧序列
无线模块（射频收发芯片） 寄存器多，配置频繁，需要高速 大量小事务，靠 CS 分帧
以太网控制器 高吞吐 高频时钟 + 连续流
数字电位器、IO 扩展 简单寄存器写入 单向写为主
SD 卡（SPI 模式） 兼容性优先于性能 用 SPI 换取更简单的硬件接口

这些外设有一个共同点：它们都是寄存器式或流式访问，没有复杂的总线管理需求，选 SPI 就是用引脚换速度和简单。

反过来，什么场景不该选 SPI：

场景 更该选谁 原因
需要挂十几个低速器件 I2C 两线挂一片，引脚不吃紧
需要知道器件在不在 I2C ACK 机制天然能做器件探测
只需要单向输出少量数据 UART 或单线 四根线太重
长距离传输 差分总线或 UART SPI 是板级总线，不适合拉长线

SPI 是板级协议，SCLK 是单端信号，走线一长边沿就塌，采样就出问题。跨板、跨机箱的连接不要指望 SPI。

十四、易错点速查 #

这张表是前面十三章的浓缩版，调试时从上往下扫。

编号 现象 先查什么 对应章节
1 完全读不到数据，全 0 或全 0xFF CS 有没有真的拉低；GND 有没有连 二、八
2 读回来字节的位是镜像反的 位序 MSB/LSB 是否一致 七
3 数据看着有规律但不对 CPOL/CPHA 模式是否与器件一致 四、五
4 偶发误码，降低频率就好 时序余量不足，走线太长或负载过重 十
5 多设备时只有一个能通 各设备 CS 是否独立，有没有共用 九
6 两个设备同时回数据，电平打架 未选中设备的 MISO 没进高阻，CS 逻辑有问题 八
7 只想读，读出来是错的 没发 dummy 字节，时钟没出来 三
8 只想写，但收到的数据很怪 全双工，MISO 上的内容本来就是无意义的 三
9 CS 拉高后立刻拉低，下一次命令失败 器件要求的 CS 高电平保持时间没满足 六
10 首字节正确，后续字节错位 CPHA=0 时第一位需要提前建立，或 CS 提前释放 六
11 换了频率就出错，改回来又正常 分频只能取离散值，实际频率与预期不符 十
12 从 I2C 移植过来，以为有 ACK SPI 协议层无应答、无错误检测 十一、十二
13 拿「SPI 标准」去查规范查不到 SPI 没有正式国际标准，只有厂商事实标准 一
14 长排线上高速率不稳 超出板级总线能力 十、十三

再说三个不属于表格、但很常见的认知偏差。第一个，把 CS 当「数据准备好」信号用。 CS 是选中信号，不是同步信号，拉低后到第一个时钟之间要留建立时间，这个时间在器件手册里，不在协议里。第二个，忽略 MISO 在某些场景根本不用接。 只写不读的器件（比如单向的显示驱动）MISO 可以不接，这时全双工里「收」的那一半是空的，读回来的就是垃圾，别拿它做判断。第三个，以为模式配错会报错。 不会。SPI 没有握手，配错了波形照样跑，只是数据错。这就是为什么调 SPI 第一件事永远是拿示波器或逻辑分析仪看波形，而不是盯着代码找 bug。
