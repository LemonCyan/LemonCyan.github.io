这篇讲 GPIO 子系统怎么把「一根引脚」变成软件里可以申请、可以设方向、可以读写电平和中断号的对象，以及控制器驱动要填哪些回调才能接上 gpiolib。主线是 gpio_chip（控制器驱动的实现接口）和 gpiod_*（描述符接口）两条线，最后落到一个能跑的最小控制器驱动。

不讲复用寄存器本身：pin controller 驱动的注册、group/function 的定义、电气属性（上下拉、驱动强度）怎么翻译成寄存器，在同目录《设备树 pinctrl 子系统与 pin 控制器驱动》。GPIO 与 pinctrl 的接缝（gpio-ranges、三个转调回调）只在本篇第十八章讲清边界，细节去那篇。

不讲系统级调试：PWM 控风扇那条完整链路（pwm 子系统 + GPIO + 示波器验证）在同目录《Rockchip RK3399 - GPIOPWM风扇调试》。框架层视角（三类控制器怎么分工、子系统之间的位置）在 B.内核/08 的《GPIO、pinctrl 与 I2C：三个子系统框架》，本篇只从控制器驱动作者的角度说话。

内核版本：linux 5.2.8（素材原始标注），u-boot 2016.05，根文件系统 busybox 1.25.0。凡与版本相关的差异，逐处标出；标「未验证」的条目我没有在 5.2.8 源码里逐行核对过。

一、GPIO 子系统要解决什么 #

GPIO 是 General Purpose Input/Output，通用输入输出口。SoC 对它依赖很重：一颗芯片上每个非专用引脚都能配成 GPIO，大多数芯片至少有那么几个。

提供 GPIO 的来源不止一种。可编程逻辑器件（类似 FPGA）能顺手给出 GPIO；电源管理芯片、音频编解码器这类多功能芯片常留几个脚，帮引脚紧张的 SoC 补位；还有挂在 I2C 或 SPI 上的「GPIO 扩展器」芯片——一颗 PCA953x 就能凭空多出 8 到 16 根线。

功能因系统而异，常见用法这几类：

用法 硬件行为 驱动侧看到的东西
输出 写 1 出高、写 0 出低。部分芯片支持只允许输出单一值、线与等取值模式（开漏是典型） chip->set / gpiod_set_value
输入 读 1 / 0。部分芯片在配成输出时仍能回读，双向信号（线与）非常依赖这一点 chip->get / gpiod_get_value
消抖 控制器也许带输入去毛刺/消抖逻辑，有时要软件控制 无统一接口，驱动自己实现
中断源 输入常能当 IRQ 用，一般沿触发，有时电平触发，还能配成系统唤醒事件 chip->to_irq、gpio_to_irq
方向 多数板子上一个脚要么配成输入要么配成输出，也有只能单向的 chip->direction_input/output
上下文限制 大部分片上 GPIO 可以在持自旋锁时访问；挂串行总线的扩展器不允许 chip->can_sleep

拿素材里的 S3C2440 举例，它有 9 个 GPIO 控制器，一共 130 个多功能引脚：

端口 位数 能力
GPA 25 仅输出（配置寄存器 1 bit，只能「输出」或「特殊功能」）
GPB 11 输入/输出
GPC 16 输入/输出
GPD 16 输入/输出
GPE 16 输入/输出
GPF 8 输入/输出
GPG 16 输入/输出
GPH 9 输入/输出
GPJ 13 输入/输出

具体到一块板子上，每根脚都有确定用途：监控 MMC/SD 卡的插拔、看卡的写保护、驱动 LED、配置收发器、模拟串行总线、复位看门狗、读开关状态。

问题就在这儿：同一个「写一个电平」的动作，在 9 个控制器上是 9 组不同寄存器、不同的位宽、不同的地址；换颗 SoC，全部重写。驱动作者不该关心 GPACON 的哪一位，正如写文件不该关心硬盘是 SATA 还是 NVMe。

gpiolib 要解决的就是这一层的统一。它做两件事：

  • 对上，提供一套与芯片无关的操作接口（申请、设方向、读、写、要中断号）；
  • 对下，提供一套框架，每个芯片只需要实现 gpio_chip 里的回调，再调注册函数挂上来，就完事。

其他子系统里用到 GPIO 的驱动——比如素材提到的 SPI OLED SSD1306——调用的是同一套接口，换 SoC 不用改一行。

内核里这部分代码集中在 drivers/gpio/。核心是 gpiolib.c，另有 gpiolib-legacy.c（老接口层）、gpiolib-sysfs.c（sysfs 层）、gpiolib-devres.c（devm 封装）、gpiolib-of.c（设备树解析）、gpiolib-acpi.c。目录里还有几十个 gpio-*.c，每个对应一颗芯片的控制器驱动。

编号空间这件事先说清楚。内核里每个 GPIO 用一个无符号整数标识，范围 0 到 MAX_INT，负数保留做「这根线这块板上不可用」或错误码。整数怎么用由平台定义，板级启动代码里常用 #define 把编号和原理图对起来。举例：某平台用 32~159 标识片上 GPIO；另一个平台用 0~63 标识一组控制器、64~79 标识另一类控制器，一路 FPGA 板子上再用 80~95；某个 I2C GPIO 扩展器占用 2000~2063。编号不要求连续。

这个全局编号在 5.2.8 里已经是被官方判了死刑的东西——gpio_chip.base 的注释里明写 DEPRECATION，希望长期内干掉静态 GPIO 编号空间。但它仍然是 sysfs 和错误日志的载体，所以还得讲。

二、为什么需要「GPIO 系统」而不是「GPIO driver」 #

很多人第一次写 GPIO 相关代码的姿态是：寄存器地址是已知的，writel 一下就行，要什么子系统。这个做法在「我的板子只有我在用」时能跑，一进产品就崩，崩在四个地方。

冲突无从发现。 引脚是最稀缺的资源，一块板子上十几个驱动都想用同一根脚是家常便饭。没有统一的申请登记，两个驱动各自 writel 同一个 GPBCON，谁后写谁生效，前一个驱动以为自己配好了。这种 bug 表现为「偶尔不工作」，重烧一遍镜像又好了，查一个月查不出来。gpiolib 用 FLAG_REQUESTED 标志位把这件事变成显式的：第二个申请者拿到 -EBUSY，启动日志直接告诉你谁抢了。

方向语义会丢。 gpio_direction_output(desc, 1) 不只是写数据寄存器，它要处理 active-low（逻辑 1 对应物理低）、开漏/开源的硬件能力探测与软件模拟、正在当 IRQ 用的脚不许切成输出。这些都是「写寄存器」之外的知识，散落在每个驱动里必然写错。gpiolib 把它们收进 gpiod_direction_output 一处。

编号到对象的映射需要全局视图。 gpio_request(19) 里的 19 是全局编号，它属于哪个 chip、该 chip 的 offset 是多少、chip 的寄存器基地址在哪，只有内核全局表知道。这层转换就是 gpio_to_desc() 干的事，遍历 gpio_devices 链表按 [base, base+ngpio) 区间命中。

可移植性。 同一份 sensor 驱动要跑在三颗 SoC 上，GPIO 寄存器完全不同。用 gpiolib，由设备树告诉我们「用第几个脚、什么有效电平」，驱动只写 gpiod_get / gpiod_set_value。控制器的差异被 gpio_chip 挡在下面。

分层的做法是：控制器驱动只实现硬件动作，其余全部由核心代劳。控制器驱动填 get/set/direction_input/direction_output 这几个回调，核心负责标志位、互斥、引用计数、sysfs、字符设备、设备树翻译、方向和电平的语义包装。

对照中断子系统看更清楚。中断有 struct irq_chip 抽象控制器接口（屏蔽、使能、清状态），GPIO 有 struct gpio_chip 抽象控制器接口（设方向、读写值、映射中断）。两个结构体的思路一模一样：成员大部分是操作底层硬件的函数指针，核心拿着它去适配不同芯片。素材作者当年正是从 irq_chip 猜到 gpio_chip 的用法的，这个类比值得记住。

三、整体分层：gpiolib、gpio_chip、gpio_desc #

先把三层摆出来，后面每章都在往里填东西。

层 数据结构 谁分配 职责
使用层 struct gpio_desc * 核心（gpiochip_add_data 时按 ngpio 数组一次性分配） 使用方持有的句柄。一根线一个，带 flags、label、指回 gpio_device 的指针
核心层 struct gpio_device 核心（注册 chip 时 kzalloc） 一个控制器实例的运行时状态容器，挂进全局链表 gpio_devices
核心层 struct gpio_chip 控制器驱动（静态数组或私有结构体成员） 控制器驱动的实现接口，全是回调 + 硬件参数
硬件层 struct samsung_gpio_chip 之类 控制器驱动 平台私有包装：寄存器基地址、锁、PM 回调

关系是：gpio_chip 是驱动提供的「操作集 + 参数」，gpio_device 是核心为它建的「运行时容器」，gpio_desc 是容器里每个引脚一格。

text
     使用方（LED / SPI / sensor 驱动）
              │  gpiod_get / gpiod_set_value
              ▼
     ┌──────────────────────────┐
     │ gpio_desc[]（每根线一个） │  flags / label / name
     └────────────┬─────────────┘
                  │ gdev
                  ▼
     ┌──────────────────────────┐
     │ struct gpio_device       │  id / base / ngpio / chrdev / descs
     └────────────┬─────────────┘
                  │ chip
                  ▼
     ┌──────────────────────────┐
     │ struct gpio_chip         │  request/free/direction_*/get/set/to_irq
     └────────────┬─────────────┘
                  │ 私有数据（chip 常是私有结构体的第一个成员）
                  ▼
         GPACON / GPADAT / GPIOBUP ...

这套「desc → device → chip → 寄存器」的四跳跟中断子系统的 irq_desc → irq_data → irq_chip 是同构的：gpio_device 之于 gpio_desc，正如 irq_data 之于 irq_desc，都是把「全局数组里一格」和「控制器实例」接起来的中转。

有两个前提概念要先钉住，否则后面看代码会晕。

offset 是控制器内偏移，编号是全局的。 回调里传的 unsigned offset，是从当前控制器的 base 算起的序号，范围 0..ngpio-1。offset=0 对应全局编号 base，offset=1 对应 base+1。核心用 gpio_chip_hwgpio(desc) 把一个 desc 换算回它所在 chip 的 offset。

核心用一张全局链表串起所有控制器。 drivers/gpio/gpiolib.c 里就一行：

c
LIST_HEAD(gpio_devices);

所有 gpio_device 挂在上面，查找 GPIO 编号时遍历它。这也是为什么全局编号必须是唯一的——同一段编号不能出现两次。

四、struct gpio_chip：控制器驱动的实现接口 #

写控制器驱动，八成的活是填这个结构体。定义在 include/linux/gpio/driver.h。

在 5.2.8 里，<linux/gpio.h> 已经不再是那个万能头：老的 gpio_request/gpio_set_value 那套还在 <linux/gpio.h>，但只给 legacy 使用者；写控制器驱动要包含 <linux/gpio/driver.h>，使用方（消费者）要包含 <linux/gpio/consumer.h>。这两个头在 4.16 前后拆出来，5.x 里拆得更干净，<linux/gpio.h> 只剩下 gpio_is_valid、legacy 内联函数和兼容包含。老代码里 #include <linux/gpio.h> 一把梭的写法，在 5.2.8 上仍然能编译，但向下游（5.10 以上）会陆续报错。

结构体本体，按 5.2.8 原文：

c
struct gpio_chip {
        const char *label;                  /* 功能名，如 "GPIOA" */
        struct gpio_device *gpiodev;        /* 核心填，指回运行时容器 */
        struct device *parent;              /* 可选父设备 */
        struct module *owner;               /* 一般是 THIS_MODULE */

        int (*request)(struct gpio_chip *chip, unsigned offset);
        void (*free)(struct gpio_chip *chip, unsigned offset);
        int (*get_direction)(struct gpio_chip *chip, unsigned offset);
        int (*direction_input)(struct gpio_chip *chip, unsigned offset);
        int (*direction_output)(struct gpio_chip *chip,
                                unsigned offset, int value);
        int (*get)(struct gpio_chip *chip, unsigned offset);
        int (*get_multiple)(struct gpio_chip *chip,
                            unsigned long *mask, unsigned long *bits);
        void (*set)(struct gpio_chip *chip, unsigned offset, int value);
        void (*set_multiple)(struct gpio_chip *chip,
                             unsigned long *mask, unsigned long *bits);
        int (*set_config)(struct gpio_chip *chip,
                          unsigned offset, unsigned long config);
        int (*to_irq)(struct gpio_chip *chip, unsigned offset);
        void (*dbg_show)(struct seq_file *s, struct gpio_chip *chip);
        int (*init_valid_mask)(struct gpio_chip *chip);

        int base;                           /* 首个全局编号；负值=动态分配 */
        u16 ngpio;                          /* 管几根线 */
        const char *const *names;           /* 每根线的别名，ngpio 长度 */
        bool can_sleep;                     /* get/set 会睡就置 true */

#if IS_ENABLED(CONFIG_GPIO_GENERIC)
        /* gpio-mmio.c 用：一组寄存器地址 + 影子寄存器 */
        unsigned long (*read_reg)(void __iomem *reg);
        void (*write_reg)(void __iomem *reg, unsigned long data);
        bool be_bits;
        void __iomem *reg_dat, *reg_set, *reg_clr;
        void __iomem *reg_dir_out, *reg_dir_in;
        bool bgpio_dir_unreadable;
        int bgpio_bits;
        spinlock_t bgpio_lock;
        unsigned long bgpio_data;
        unsigned long bgpio_dir;

#endif

#if defined(CONFIG_OF_GPIO)
        struct device_node *of_node;
        unsigned int of_gpio_n_cells;       /* 对应 dts 的 #gpio-cells */

                        const struct of_phandle_args *gpiospec, u32 *flags);

};

字段全集就是上面这些，5.2.8 没有遗漏。原文的 doc comment 很长（每条字段两三行说明），内容已经全部收进下面的三张表。

字段逐个说。分三组：驱动必须关心的、可选但有坑的、能不理就不理的。

4.1 基础字段 #

字段 含义 经验
label 控制器的功能名，比如 「GPIOA」、「gpio-ch347」 sysfs 和日志里显示，必填。NULL 会被当成 "unknown"
gpiodev 核心填的，指回 gpio_device 驱动不要碰，注册完由核心维护
parent 可选的父设备 传 &pdev->dev，sysfs 的设备树位置依赖它
owner THIS_MODULE 防止模块在 GPIO 还被使用时被卸载
base 本控制器第一个 GPIO 的全局编号；负值表示请核心动态分配 新驱动一律填 -1（注释里标了 DEPRECATION）
ngpio 本控制器管几根线，最后一个的编号是 base + ngpio - 1 填 0 会被核心拒绝，-EINVAL
names ngpio 长度的字符串数组，给每根线起别名 定长数组，某一项可以是 NULL；名字里可以带一个 %u 风格格式符，运行时替换成引脚号
can_sleep get/set 会睡眠就必须为 true I2C/SPI 扩展器必须置位，否则调用方在原子上下文里用它会把内核搞崩

base 这个坑值得多说一句：5.2.8 的来源注释写得很直白——「提供任何非负数并固定 GPIO 芯片的基础偏移量已经过时，请在所有可能的情况下传 -1，让 gpiolib 自己选」。留着 -1 还有个副作用：sysfs 名字会变成 gpiochip0、gpiochip32 这类紧挨着的编号，不再是 base 值。想要固定 base 往往是过时的板级代码在作祟。

can_sleep 置位之后，所有调用路径都要换成 _cansleep 版本：gpiod_get_value_cansleep()、gpiod_set_value_cansleep()、gpiod_direction_* 本身就能睡。用错了核心会 WARN_ON 打调用栈。注释里还有一句关键推论：可睡眠的芯片如果支持中断，那些 IRQ 必须是线程化的，因为读中断状态寄存器本身就会睡。

4.2 回调 #

回调 语义 必须？
request 申请这根线时的芯片特定激活动作，比如打开模块电源或时钟。可睡眠 可选
free 对应的释放动作，比如关电源关时钟。可睡眠 可选
get_direction 返回方向：0 = 输出，1 = 输入（与 GPIOF_DIR_XXX 一致），负数 = 错误 强烈建议实现，哪怕只有输入或只有输出的芯片
direction_input 把这根线配成输入 只输入/只输出的芯片可省
direction_output 把这根线配成输出，并同时给定初始电平 value 只输入/只输出的芯片可省
get 读这根线的电平：0 低、1 高、负数错误 有输入能力就要有
set 写这根线的输出电平 有输出能力就要有
get_multiple 按 mask 批量读，结果写进 bits，成功返回 0 可选，批量读优化
set_multiple 按 mask 批量写 可选，批量写优化
set_config 通用配置钩子，config 用和 generic pinconf 相同的打包格式 可选，上下拉/开漏等
to_irq 把这根线映射成 IRQ 号，实现里不许睡眠 支持中断就要实现
dbg_show debugfs 里打印控制器状态 可选，默认实现够用
init_valid_mask 初始化 valid_mask，标出哪些线真的可用 可选

request 和 free 有一个容易忽略的语义：注释里说 request 会在「分配 GPIO 之前」执行，free 会在「GPIO 被释放之前」执行。也就是说它们是「芯片被这根线激活/去激活」的钩子，不是简单的引用计数。用它开时钟是标准做法，注意它可以睡。

get_direction 为什么不建议省？因为核心在注册的时候要用它初始化 FLAG_IS_OUT 标志（见下一章 gpiochip_add_data 的收尾循环）。你不实现，核心就按 direction_input 是否存在来猜，猜出来的是理想值不是实际值，后面 gpio_get_value 和 sysfs 的 direction 就能显示错。

4.3 generic GPIO 部分 #

CONFIG_GPIO_GENERIC 一段是给 gpio-mmio.c（原 gpio-generic.c）用的。如果你的控制器是「一个数据寄存器 + 一个方向寄存器 + 或者还有独立的置位/清除寄存器」这种最土的结构，别自己写回调，填 reg_dat、reg_dir_out、reg_dir_in、bgpio_bits 然后调 bgpio_init()，核心会把 get/set/direction_* 全装上。read_reg/write_reg 用来覆盖默认的读写函数（比如需要字节序转换的芯片）；be_bits 是大端位序标记，注释里说了「仅用于内部记录」，驱动别写它。bgpio_data/bgpio_dir 是影子寄存器，读-改-写时靠它保证原子性，bgpio_lock 保护它们。

4.4 中断部分 #

struct gpio_irq_chip irq 是 5.2.8 里 GPIO 与中断结合的正门。CONFIG_gpiolib_IRQCHIP 打开后，核心在 gpiochip_add_data 里调用 gpiochip_add_irqchip()，把这个 irq 子结构注册成一个 irq_chip，于是 gpio_to_irq 能直接工作。填充方式是 gpiochip_set_* 系列或直接赋值 irq.chip、irq.domain_ops、irq.handler、irq.threaded、irq.parent_handler 等字段。

对多数 SoC 片上 GPIO，这是推荐路径：只填 irq.chip，其余交给核心。bgpio_init() 顺手就能把 irq 配好一部分（bgpio_init(..., 0) 之外还有 devm_gpiochip_add_data 之后手填 irq.chip 的写法）。这一层细节在 5.x 各小版本间有过改动，跨版本移植时以实际内核的 include/linux/gpio/driver.h 为准——具体到 5.10 之后 gpio_irq_chip 又加了若干字段，未验证。

4.5 mask 与设备树部分 #

need_valid_mask 置位时，核心会按 ngpio 分配一块 valid_mask，初始全 1（如果实现了 init_valid_mask 就调它来改）。用途是「这个芯片上报了 32 根线，但封装上只引出 20 根」——把无效位置 0，核心就不会把它们暴露给使用者。这个机制在 5.2.8 是新的（4.20 前后引入），老控制器驱动没填就是全 1，行为等价。

of_node / of_gpio_n_cells / of_xlate 是设备树翻译。gpio-ranges 和设备树解析相关的内容在第十二章。of_gpio_n_cells 表示 dts 里引用这根线要用几个 cell（#gpio-cells），STM32 之类是 2，某些老平台是 3。

一句话总结这一章：gpio_chip 就是「回调 + 参数」的登记表。核心拿着它干活，驱动只要保证回调里的硬件动作是真的。

五、gpio_chip 的注册与注销 #

填好结构体不等于生效，得注册进 gpiolib。入口是 gpiochip_add，定义在 include/linux/gpio/driver.h：

c
static inline int gpiochip_add(struct gpio_chip *chip)
{
        return gpiochip_add_data(chip, NULL);
}

#ifdef CONFIG_LOCKDEP
#define gpiochip_add_data(chip, data) ({                \
                static struct lock_class_key lock_key;  \
                static struct lock_class_key request_key;         \
                gpiochip_add_data_with_key(chip, data, &lock_key, \
                                           &request_key);         \
        })
#else
#define gpiochip_add_data(chip, data) gpiochip_add_data_with_key(chip, data, NULL, NULL)
#endif

SoC 有 9 个控制器就调 9 次（实际是循环里调）。第二个参数 data 是驱动私有数据，存进 gpio_device->data，gpiod_get_drvdata(desc) 能取回来——这是从全局描述符找回「我的私有结构体」的标准路径，多实例驱动必须用它。CONFIG_LOCKDEP 分支的目的是给每个 chip 单独的锁类，避免 lockdep 把不同控制器的锁误判成同一把而报假死锁。

注释里有一条时序约束：gpiochip_add_data 必须在 gpiolib 初始化之后调（即 core_initcall() 之后）；要在启动极早期注册 chip，那 chip->parent 对应的设备必须先在框架的 arch_initcall() 之前注册好，否则 GPIO 的 sysfs 初始化会很难看地失败。

devm 版本自动管理生命周期，实现只是「分配一块存 chip 指针的 devres，注册成功后 devres_add」：

c
int devm_gpiochip_add_data(struct device *dev, struct gpio_chip *chip,
                           void *data)
{
        struct gpio_chip **ptr;
        int ret;

        ptr = devres_alloc(devm_gpio_chip_release, sizeof(*ptr), GFP_KERNEL);
        if (!ptr)
                return -ENOMEM;

        ret = gpiochip_add_data(chip, data);
        if (ret < 0) {
                devres_free(ptr);
                return ret;
        }

        *ptr = chip;
        devres_add(dev, ptr);
        return 0;
}

设备 unbind 时核心调 devm_gpio_chip_release → gpiochip_remove。所以 probe 里写了 devm_gpiochip_add_data，remove 里就不需要手写 gpiochip_remove。一个 probe 里调多次也安全（每次一块 devres）。

5.1 gpiochip_add_data_with_key 的注册流程 #

gpiochip_add_data 是宏，实打实的实现是 gpiochip_add_data_with_key，在 drivers/gpio/gpiolib.c。这是全篇最长的一个函数。骨架如下，err_* 一串标签按调用顺序逆序释放，和 Linux 里所有 _with_key 风格函数一致：

c
int gpiochip_add_data_with_key(struct gpio_chip *chip, void *data,
                               struct lock_class_key *lock_key,
                               struct lock_class_key *request_key)
{
        int base = chip->base;
        struct gpio_device *gdev;

        gdev = kzalloc(sizeof(*gdev), GFP_KERNEL);
        gdev->dev.bus = &gpio_bus_type;
        gdev->chip = chip;
        chip->gpiodev = gdev;                /* 双向绑定 */
        if (chip->parent) {
                gdev->dev.parent = chip->parent;
                gdev->dev.of_node = chip->parent->of_node;
        }
        /* CONFIG_OF_GPIO 下 chip->of_node 显式指定优先，否则继承 parent */

        gdev->id = ida_simple_get(&gpio_ida, 0, 0, GFP_KERNEL);   /* 字符设备次设备号 */
        dev_set_name(&gdev->dev, "gpiochip%d", gdev->id);
        device_initialize(&gdev->dev);
        dev_set_drvdata(&gdev->dev, gdev);
        /* gdev->owner：先看 parent->driver->owner，再看 chip->owner */

        gdev->descs = kcalloc(chip->ngpio, sizeof(gdev->descs[0]), GFP_KERNEL);
        if (chip->ngpio == 0) {
                chip_err(chip, "tried to insert a GPIO chip with zero lines\n");
                status = -EINVAL;
                goto err_free_descs;
        }
        gdev->label = kstrdup_const(chip->label ?: "unknown", GFP_KERNEL);
        gdev->ngpio = chip->ngpio;
        gdev->data = data;                   /* 回调侧靠它取私有数据 */

        spin_lock_irqsave(&gpio_lock, flags);
        if (base < 0) {                      /* 负值 = 动态分配 */
                base = gpiochip_find_base(chip->ngpio);
                if (base < 0) {
                        status = base;
                        spin_unlock_irqrestore(&gpio_lock, flags);
                        goto err_free_label;
                }
                chip->base = base;
        }
        gdev->base = base;
        status = gpiodev_add_to_list(gdev);  /* 按 base 有序插入 gpio_devices */
        spin_unlock_irqrestore(&gpio_lock, flags);

        for (i = 0; i < chip->ngpio; i++)
                gdev->descs[i].gdev = gdev;
#ifdef CONFIG_PINCTRL
        INIT_LIST_HEAD(&gdev->pin_ranges);
#endif

        status = gpiochip_set_desc_names(chip);       /* 取 chip->names[i] */
        status = gpiochip_alloc_valid_mask(chip);
        status = gpiochip_add_irqchip(chip, lock_key, request_key);  /* 真注册 irq_chip */
        status = of_gpiochip_add(chip);               /* gpio-ranges / gpio-hog */
        status = gpiochip_init_valid_mask(chip);

        for (i = 0; i < chip->ngpio; i++) {   /* 按硬件实际方向定 FLAG_IS_OUT */
                struct gpio_desc *desc = &gdev->descs[i];

                if (chip->get_direction && gpiochip_line_is_valid(chip, i)) {
                        if (!chip->get_direction(chip, i))
                                set_bit(FLAG_IS_OUT, &desc->flags);
                        else
                                clear_bit(FLAG_IS_OUT, &desc->flags);
                } else {
                        if (!chip->direction_input)
                                set_bit(FLAG_IS_OUT, &desc->flags);
                        else
                                clear_bit(FLAG_IS_OUT, &desc->flags);
                }
        }

        acpi_gpiochip_add(chip);
        machine_gpiochip_add(chip);

        if (gpiolib_initialized) {            /* 已初始化就当场建字符设备 */
                status = gpiochip_setup_dev(gdev);
                if (status)
                        goto err_remove_acpi_chip;
        }
        return 0;

err_remove_acpi_chip:   acpi_gpiochip_remove(chip);
err_remove_of_chip:     gpiochip_free_hogs(chip); of_gpiochip_remove(chip);
err_remove_chip:        gpiochip_irqchip_remove(chip);
err_free_gpiochip_mask: gpiochip_free_valid_mask(chip);
err_remove_irqchip_mask: gpiochip_irqchip_free_valid_mask(chip);
err_remove_from_list:
        spin_lock_irqsave(&gpio_lock, flags);
        list_del(&gdev->list);
        spin_unlock_irqrestore(&gpio_lock, flags);
err_free_label:         kfree_const(gdev->label);
err_free_descs:         kfree(gdev->descs);
err_free_ida:           ida_simple_remove(&gpio_ida, gdev->id);
err_free_gdev:
        /* failures here can mean systems won't boot... */
        pr_err("%s: GPIOs %d..%d (%s) failed to register, %d\n", __func__,
               gdev->base, gdev->base + gdev->ngpio - 1,
               chip->label ? : "generic", status);
        kfree(gdev);
        return status;
}

为了压长度，这里把几次独立的 if (status) goto err_xxx; 写成顺序调用，#ifdef CONFIG_PINCTRL 的 INIT_LIST_HEAD(&gdev->pin_ranges) 也省了。真实代码每一步都判错误、每段条件编译都在，这是唯一不能省的地方。

流程拆成七步：

  1. 建容器。 kzalloc 一个 gpio_device，设 dev.bus = &gpio_bus_type，双向绑定 gdev->chip 与 chip->gpiodev，有 parent 就把设备树节点继承过来（chip->of_node 显式指定的优先）。
  2. 要 id。 ida_simple_get(&gpio_ida, ...) 拿一个小整数 id，设备命名成 gpiochip%d。这个 id 是字符设备次设备号，跟 base 不是一回事。
  3. 按 ngpio 分配 desc 数组。 ngpio == 0 直接 -EINVAL；超过 FASTPATH_NGPIO 只打警告，不影响功能。
  4. 定 base。 传了非负数就用它，负数就调 gpiochip_find_base(ngpio) 找一段空位。这一步在持 gpio_lock 的情况下跑。
  5. 挂链表。 gpiodev_add_to_list(gdev) 按 base 排好序插入 gpio_devices——31~40 会插在 20~30 和 41~50 之间。
  6. 逐项初始化。 desc 指回 gdev、名字、valid mask、gpiochip_add_irqchip（真正把 irq 子结构注册成 irq_chip 的地方）、of_gpiochip_add（处理 gpio-ranges、gpio-hog、gpio-line-names）。最后那个循环把每根线的 FLAG_IS_OUT 按硬件实际方向定下来——这就是 get_direction 建议实现的原因。
  7. 建设备节点。 gpiolib_initialized 为真才调 gpiochip_setup_dev，否则推迟到 gpiolib 初始化时统一处理。

gpiolib_initialized 由 gpiolib 自己的入口函数置位：

c
static int __init gpiolib_dev_init(void)
{
        int ret;

        ret = bus_register(&gpio_bus_type);   /* 建 /sys/bus/gpio */
        if (ret < 0) {
                pr_err("gpiolib: could not register GPIO bus type\n");
                return ret;
        }

        ret = alloc_chrdev_region(&gpio_devt, 0, GPIO_DEV_MAX, "gpiochip");
        if (ret < 0) {
                pr_err("gpiolib: failed to allocate char dev region\n");
                bus_unregister(&gpio_bus_type);
        } else {
                gpiolib_initialized = true;
                gpiochip_setup_devs();
        }
        return ret;
}
core_initcall(gpiolib_dev_init);

core_initcall 的优先级比 module_init（等价 device_initcall）高，所以大多数 platform 驱动 probe 时 gpiolib_initialized 已经是真，走「当场建设备」这条路。启动极早期注册的 chip（arch_initcall 或更早）留在链表里，等 gpiochip_setup_devs() 统一补建。

5.2 gpiochip_setup_dev：字符设备 + sysfs #

c
static int gpiochip_setup_dev(struct gpio_device *gdev)
{
        int status;

        cdev_init(&gdev->chrdev, &gpio_fileops);     /* 初始化字符设备 */
        gdev->chrdev.owner = THIS_MODULE;
        gdev->dev.devt = MKDEV(MAJOR(gpio_devt), gdev->id);

        status = cdev_device_add(&gdev->chrdev, &gdev->dev);
        if (status)
                return status;

        status = gpiochip_sysfs_register(gdev);
        if (status)
                goto err_remove_device;

        /* From this point, the .release() function cleans up gpio_device */
        gdev->dev.release = gpiodevice_release;
        return 0;

err_remove_device:
        cdev_device_del(&gdev->chrdev, &gdev->dev);
        return status;
}

cdev_device_add 是 driver core 的通用封装：先 cdev_add，失败直接返回；再 device_add，失败则 cdev_del 回滚。于是 /dev/gpiochipN 和 /sys/class/gpio/gpiochipN 同时出现。主设备号所有 chip 共用一个（gpio_devt 由 alloc_chrdev_region 动态申请），次设备号是 gdev->id。

sysfs 那半边在 drivers/gpio/gpiolib-sysfs.c：

c
int gpiochip_sysfs_register(struct gpio_device *gdev)
{
        struct device   *dev;
        struct device   *parent;
        struct gpio_chip *chip = gdev->chip;

        /* gpio_class 还没注册就直接返回，等 gpiolib_sysfs_init 补做 */
        if (!gpio_class.p)
                return 0;

        /* 优先挂在 chip->parent 下，保持 sysfs 兼容 */
        if (chip->parent)
                parent = chip->parent;
        else
                parent = &gdev->dev;

        /* use chip->base for the ID; it's already known to be unique */
        dev = device_create_with_groups(&gpio_class, parent, MKDEV(0, 0),
                                        chip, gpiochip_groups,
                                        "gpiochip%d", chip->base);
        if (IS_ERR(dev))
                return PTR_ERR(dev);

        mutex_lock(&sysfs_lock);
        gdev->mockdev = dev;
        mutex_unlock(&sysfs_lock);
        return 0;
}

两个细节。第一，gpio_class.p 没初始化时直接返回 0，因为 gpio_class 是在 gpiolib_sysfs_init 里注册的，注册更早的 chip 要靠那个函数事后补做。第二，sysfs 目录名用的是 chip->base 而不是 gdev->id——这就是 base 必须全局唯一的直接理由，也是 ls /sys/class/gpio 里能看到 gpiochip32、gpiochip128 这种洞的原因。

/dev 下没有节点是另一回事：gdev->dev 挂的是 bus 而不是 class，而 bus 和 class 不能同时指定，所以早期的 /sys/class/gpio/gpiochipN 是 gpiochip_sysfs_register 额外建的 mockdev。字符设备节点靠 mdev/udev 扫 /sys/dev/char 建，busybox 下 mdev -s 即可。

六、struct gpio_desc：引脚的抽象 #

gpio_chip 是控制器视角，gpio_desc 是使用者视角。跟中断子系统里 struct irq_desc 描述一个 IRQ 一样，gpio_desc 描述一根具体的引脚。定义在 drivers/gpio/gpiolib.h：

c
struct gpio_desc {
        struct gpio_device      *gdev;
        unsigned long           flags;

        /* Connection label */
        const char              *label;
        /* Name of the GPIO */
        const char              *name;
};

只有四个成员，但 flags 里那十四个位是全部语义所在：

位 名字 什么时候置位 谁关心
0 FLAG_REQUESTED gpiod_request 里 test_and_set_bit 成功 防重复申请，重了返回 -EBUSY
1 FLAG_IS_OUT direction_output 成功、或注册时 get_direction 报输出 gpio_get_value 的语义、sysfs 的 direction
2 FLAG_EXPORT export 写进 sysfs 时 sysfs 子系统内部，sysfs_lock 保护
3 FLAG_SYSFS 已通过 sysfs 导出 防止在 sysfs 使用期间被 gpiod_put
6 FLAG_ACTIVE_LOW dts 写了 GPIO_ACTIVE_LOW，或 gpiod_set_raw 前由 machine 代码置位 逻辑值/物理值取反的唯一依据
7 FLAG_OPEN_DRAIN dts 写了 open-drain 或驱动显式设置 direction_output 里尝试硬件开漏，不行就用输入模式模拟高
8 FLAG_OPEN_SOURCE 同上，开源情形 同上，反向
9 FLAG_USED_AS_IRQ gpio_to_irq/irq 相关路径 禁止把正在用的中断线切成输出
10 FLAG_IRQ_IS_ENABLED 中断已 enable 与上一位合起来判「不许当输出」
11 FLAG_IS_HOGGED 设备树 gpio-hog 节点占用 谁也拿不走
12 FLAG_TRANSITORY dts 写了 transitory 或有掉电保持问题 睡眠/复位可能丢值
13 FLAG_PULL_UP 请求时指定上拉 direction_input 时下发 PIN_CONFIG_BIAS_PULL_UP
14 FLAG_PULL_DOWN 请求时指定下拉 同上，下拉

label 是「连接标签」，申请时传的字符串，一般为驱动名或 dev_name，/sys/kernel/debug/gpio 里能看到谁占了这根线。name 来自 chip->names[offset] 或设备树的 gpio-line-names，是引脚的固有名字。

struct gpio_desc 不透明：对使用方它就是个指针，字段一律不直接碰。这是因为 5.x 里这几个字段还在挪位置（4.20 之后加过 gdev 的引用计数逻辑），直接读结构体字段的代码迟早编不过。取信息走 gpiod_to_chip()、gpiod_get_label()、desc_to_gpio()。

6.1 gpio_device：desc 与 chip 之间的中转 #

c
struct gpio_device {
        int                     id;
        struct device           dev;
        struct cdev             chrdev;
        struct device           *mockdev;
        struct module           *owner;
        struct gpio_chip        *chip;
        struct gpio_desc        *descs;
        int                     base;
        u16                     ngpio;
        const char              *label;
        void                    *data;

        struct list_head        pin_ranges;

};
字段 含义
id 控制器在 gpio_ida 里的 id，也是字符设备次设备号
dev 内核设备结构体。把 gpio_device 当作 device 的子类看
chrdev 字符设备，gpiochip_setup_dev 里 cdev_init
mockdev 已废弃 sysfs 接口用的类设备，可能是 NULL
owner 模块引用，防止卸载正在用的 GPIO

descs ngpio 个 gpio_desc 的数组，一根线一格

ngpio 线数，等于 descs 数组长度

注释里有一句话很关键：这个容器「can hold references and live on after the GPIO chip has been removed, if it is still being used from userspace」——控制器注销了但用户态还拿着句柄时，gpio_device 不会立刻消失，得等最后一个引用放掉。这是 4.20 引入 gpio_device 的主要动机，之前 gpiochip 一卸就 use-after-free。

pin_ranges 这一行 #ifdef 是 GPIO 与 pinctrl 耦合的第一个物理痕迹，第十八章展开。

6.2 gpio_to_desc：编号 → 描述符 #

使用者拿着全局编号，核心要换成 desc：

c
struct gpio_desc *gpio_to_desc(unsigned gpio)
{
        struct gpio_device *gdev;
        unsigned long flags;

        spin_lock_irqsave(&gpio_lock, flags);

        list_for_each_entry(gdev, &gpio_devices, list) {
                if (gdev->base <= gpio &&
                    gdev->base + gdev->ngpio > gpio) {
                        spin_unlock_irqrestore(&gpio_lock, flags);
                        return &gdev->descs[gpio - gdev->base];
                }
        }

        spin_unlock_irqrestore(&gpio_lock, flags);

        if (!gpio_is_valid(gpio))
                WARN(1, "invalid GPIO %d\n", gpio);

        return NULL;
}

遍历 gpio_devices，谁的 [base, base+ngpio) 圈住这个编号，就从谁家取 descs[gpio - base]。因为链表按 base 有序，未来可以优化成提前退出，5.2.8 里没做。

反方向，desc_to_gpio 把描述符换算回全局编号：

c
/**
 * desc_to_gpio - convert a GPIO descriptor to the integer namespace
 * @desc: GPIO descriptor
 *
 * This should disappear in the future but is needed since we still
 * use GPIO numbers for error messages and sysfs nodes.
 */
int desc_to_gpio(const struct gpio_desc *desc)
{
        return desc->gdev->base + (desc - &desc->gdev->descs[0]);
}

指针相减得到数组下标，加上 base 就是全局编号。注释里那句 This should disappear in the future 是态度声明：描述符接口不需要编号，留下来的唯一理由是 sysfs 和错误日志还在用。

还有一个方向：desc 到控制器内偏移，核心内部用 gpio_chip_hwgpio(desc)，展开就是 desc_to_gpio(desc) - desc->gdev->chip->base。回调里拿到的 offset 全是这个值。

七、gpio 的申请与释放 #

申请是「占坑」。坑占了别人才知道这跟线不能碰，核心也才有地方记录「谁在用」。5.2.8 里所有申请最终落到同一条路上：gpiod_request → gpiod_request_commit。

c
int gpiod_request(struct gpio_desc *desc, const char *label)
{
        int status = -EPROBE_DEFER;
        struct gpio_device *gdev;

        VALIDATE_DESC(desc);
        gdev = desc->gdev;

        if (try_module_get(gdev->owner)) {
                status = gpiod_request_commit(desc, label);
                if (status < 0)
                        module_put(gdev->owner);
                else
                        get_device(&gdev->dev);
        }

        if (status)
                gpiod_dbg(desc, "%s: status %d\n", __func__, status);

        return status;
}

三件事：校验 desc 有效性、try_module_get 顶住模块引用、走 commit。成功后再 get_device 给 gpio_device 加一次设备引用，这是 4.20 之后「desc 活得比 chip 久」的实现方式。

真正的坑位登记在 gpiod_request_commit：

c
static int gpiod_request_commit(struct gpio_desc *desc, const char *label)
{
        struct gpio_chip        *chip = desc->gdev->chip;
        int                     status;
        unsigned long           flags;
        unsigned                offset;

        if (label)
                label = kstrdup_const(label, GFP_KERNEL);

        spin_lock_irqsave(&gpio_lock, flags);

        /* 一个位管互斥：抢到置 0 返回表示成功，非 0 表示已被别人占 */
        if (test_and_set_bit(FLAG_REQUESTED, &desc->flags) == 0) {
                desc_set_label(desc, label ? : "?");
                status = 0;
        } else {
                kfree_const(label);
                status = -EBUSY;
                goto done;
        }

        if (chip->request) {
                /* chip->request may sleep：先放锁再调 */
                spin_unlock_irqrestore(&gpio_lock, flags);
                offset = gpio_chip_hwgpio(desc);
                if (gpiochip_line_is_valid(chip, offset))
                        status = chip->request(chip, offset);
                else
                        status = -EINVAL;
                spin_lock_irqsave(&gpio_lock, flags);

                if (status < 0) {                /* 回滚标志位与 label */
                        desc_set_label(desc, NULL);
                        kfree_const(label);
                        clear_bit(FLAG_REQUESTED, &desc->flags);
                        goto done;
                }
        }
        if (chip->get_direction) {
                /* chip->get_direction may sleep，同样放锁 */
                spin_unlock_irqrestore(&gpio_lock, flags);
                gpiod_get_direction(desc);       /* 回填 FLAG_IS_OUT */
                spin_lock_irqsave(&gpio_lock, flags);
        }
done:
        spin_unlock_irqrestore(&gpio_lock, flags);
        return status;
}

要点四条。

第一，互斥靠一个位。test_and_set_bit(FLAG_REQUESTED, ...) 返回 0 表示原来没置位、这次置上了，即抢到；返回非 0 表示已被别人占了，返回 -EBUSY。这是整个子系统最核心的互斥，代价只有一条原子指令。

第二，label 会先 kstrdup_const 复制一份。常量字符串走 kstrdup_const 的免拷贝优化，动态字符串真拷贝。失败路径要 kfree_const 配平——上面代码在两处都做了。

第三，调 chip->request 前主动放锁。因为注释写着 chip->request may sleep：控制器可能要在这时开时钟、开电源，那些操作会睡。持自旋锁睡是会死机的。放锁期间 desc 的 flags 已经置了 FLAG_REQUESTED，所以不会有人来抢同一个坑。

第四，get_direction 同样放锁调用，然后 gpiod_get_direction(desc) 把实际方向回填到 FLAG_IS_OUT。这一步保证「刚申请完的线，sysfs 一读 direction 就是对的」。

释放是对称的，但简单得多：

c
void gpiod_free(struct gpio_desc *desc)
{
        if (!desc || !desc->gdev)
                return;
        VALIDATE_DESC_VOID(desc);
        gpiod_free_commit(desc);
        put_device(&desc->gdev->dev);
}

gpiod_free_commit 里调 chip->free、清 label、清 FLAG_REQUESTED，同时把 FLAG_USED_AS_IRQ、FLAG_IRQ_IS_ENABLED 等一并收拾干净。put_device 与申请时的 get_device 配平。

有三条纪律，违反了就是教科书级 bug：

  • 必须在 remove/错误路径里释放。 忘了 gpio_free/gpiod_put，rebind 时第二次 probe 拿到 -EBUSY，而且 debugfs 里留着上一次的 label 骗你。
  • 不要在持锁的上下文里申请。 gpiod_request 会睡（kstrdup_const + chip->request），中断上下文里只能用 gpiod_get_optional 之类的早期完成版本——实际上正确做法是在 probe 里申请完再注册中断。
  • 一个驱动不要重复申请同一根线。 核心会拦，但如果你的代码在 open() 里申请、close() 里释放，同时两个进程 open 就会出问题。要么在 probe 里申请，要么自己加互斥。

八、方向与值的读写 #

方向操作是 GPIO 语义最密集的地方。gpio_direction_input / gpio_direction_output 是 legacy 包装，真正实现是 gpiod_direction_input / gpiod_direction_output，在 drivers/gpio/gpiolib.c。

8.1 配成输入 #

c
int gpiod_direction_input(struct gpio_desc *desc)
{
        struct gpio_chip        *chip;
        int                     status = 0;

        VALIDATE_DESC(desc);
        chip = desc->gdev->chip;

        /* 声明了 direction_input 却不会 get，是驱动写错了 */
        if (!chip->get && chip->direction_input)
                return -EIO;

        if (chip->direction_input)
                status = chip->direction_input(chip, gpio_chip_hwgpio(desc));
        else if (chip->get_direction &&
                 (chip->get_direction(chip, gpio_chip_hwgpio(desc)) != 1))
                return -EIO;                 /* 只输出的芯片且当前是输出 */

        if (status == 0)
                clear_bit(FLAG_IS_OUT, &desc->flags);

        /* 上下拉按 flags 下发给 set_config，枚举来自 pinconf 体系 */
        if (test_bit(FLAG_PULL_UP, &desc->flags))
                gpio_set_config(chip, gpio_chip_hwgpio(desc),
                                PIN_CONFIG_BIAS_PULL_UP);
        else if (test_bit(FLAG_PULL_DOWN, &desc->flags))
                gpio_set_config(chip, gpio_chip_hwgpio(desc),
                                PIN_CONFIG_BIAS_PULL_DOWN);

        trace_gpio_direction(desc_to_gpio(desc), 1, status);
        return status;
}

三层逻辑：检查一致性 → 调回调或问方向 → 回填 FLAG_IS_OUT，再把上下拉按 flags 下发给 set_config。PIN_CONFIG_BIAS_PULL_UP 来自 pinconf 体系，set_config 的打包格式与 generic pinconf 一致，所以控制器想支持上下拉，只要实现 set_config。

8.2 配成输出 #

输出路径长，因为它要处理有效电平、开漏/开源、以及「这根线正在当 IRQ 用」的禁令。

c
int gpiod_direction_output(struct gpio_desc *desc, int value)
{
        struct gpio_chip *gc;
        int ret;

        VALIDATE_DESC(desc);
        /* 参数是逻辑值：active-low 在这里就消化掉 */
        if (test_bit(FLAG_ACTIVE_LOW, &desc->flags))
                value = !value;
        else
                value = !!value;

        /* GPIOs used for enabled IRQs shall not be set as output */
        if (test_bit(FLAG_USED_AS_IRQ, &desc->flags) &&
            test_bit(FLAG_IRQ_IS_ENABLED, &desc->flags))
                return -EIO;

        gc = desc->gdev->chip;
        if (test_bit(FLAG_OPEN_DRAIN, &desc->flags)) {
                /* 先试硬件开漏 */
                ret = gpio_set_config(gc, gpio_chip_hwgpio(desc),
                                      PIN_CONFIG_DRIVE_OPEN_DRAIN);
                if (!ret)
                        goto set_output_value;
                /* 失败则软件模拟：输出 1 时改成输入，靠外部上拉 */
                if (value)
                        return gpiod_direction_input(desc);
        } else if (test_bit(FLAG_OPEN_SOURCE, &desc->flags)) {
                ret = gpio_set_config(gc, gpio_chip_hwgpio(desc),
                                      PIN_CONFIG_DRIVE_OPEN_SOURCE);
                if (!ret)
                        goto set_output_value;
                /* 开源同理：输出 0 时不主动驱低 */
                if (!value)
                        return gpiod_direction_input(desc);
        } else {
                gpio_set_config(gc, gpio_chip_hwgpio(desc),
                                PIN_CONFIG_DRIVE_PUSH_PULL);
        }

set_output_value:
        return gpiod_direction_output_raw_commit(desc, value);
}

static int gpiod_direction_output_raw_commit(struct gpio_desc *desc, int value)
{
        struct gpio_chip *gc = desc->gdev->chip;
        int val = !!value;
        int ret = 0;

        if (!gc->set && !gc->direction_output)
                return -EIO;

        if (gc->direction_output) {
                ret = gc->direction_output(gc, gpio_chip_hwgpio(desc), val);
        } else {
                /* 只输出的芯片没有 direction_output，先确认已是输出模式 */
                if (gc->get_direction &&
                    gc->get_direction(gc, gpio_chip_hwgpio(desc)))
                        return -EIO;
                gc->set(gc, gpio_chip_hwgpio(desc), val);
        }

        if (!ret)
                set_bit(FLAG_IS_OUT, &desc->flags);
        trace_gpio_direction(desc_to_gpio(desc), 0, ret);
        return ret;
}

三处设计值得盯住。active-low 在第一行被消化掉：参数 value 是逻辑值，dts 标了 GPIO_ACTIVE_LOW 之后，gpiod_direction_output(desc, 1) 的意思是「让它处于有效态」，物理上拉低，往后走的一律是物理值。中断线不许变输出：两个标志一起成立直接 -EIO，正在监听中断的脚被切成输出，边沿事件就没了。开漏/开源优先尝试硬件，失败就退化成「输出 1 时改成输入」的软件模拟，很多 I2C 位操作驱动当年就是这么干的。

direction_output 回调的签名里带 value，就是要求「一次写完方向和初值」，避免先配输出再写值之间的毛刺。

8.3 读值与写值 #

c
int gpiod_get_raw_value(const struct gpio_desc *desc)
{
        VALIDATE_DESC(desc);
        /* Should be using gpiod_get_raw_value_cansleep() */
        WARN_ON(desc->gdev->chip->can_sleep);
        return gpiod_get_raw_value_commit(desc);
}

static int gpiod_get_raw_value_commit(const struct gpio_desc *desc)
{
        struct gpio_chip        *chip;
        int offset;
        int value;

        chip = desc->gdev->chip;
        offset = gpio_chip_hwgpio(desc);
        value = chip->get ? chip->get(chip, offset) : -EIO;
        value = value < 0 ? value : !!value;    /* 位域读数规整成 0/1 */
        trace_gpio_value(desc_to_gpio(desc), 1, value);
        return value;
}

void gpiod_set_raw_value(struct gpio_desc *desc, int value)
{
        VALIDATE_DESC_VOID(desc);
        WARN_ON(desc->gdev->chip->can_sleep);
        gpiod_set_raw_value_commit(desc, value);
}

static void gpiod_set_raw_value_commit(struct gpio_desc *desc, bool value)
{
        struct gpio_chip        *chip = desc->gdev->chip;

        trace_gpio_value(desc_to_gpio(desc), 0, value);
        chip->set(chip, gpio_chip_hwgpio(desc), value);
}

get 返回负数就当错误码透传，非负一律 !! 规整成 0/1。set 是 void 返回，写失败没有退路，所以 can_sleep 的 WARN_ON 一定要守住。

8.4 raw 与逻辑值，以及可睡眠版本 #

函数族 前缀 是否处理 active-low 用途
gpiod_set_value / gpiod_get_value 无 raw 处理：逻辑值 业务代码用这个
gpiod_set_raw_value / gpiod_get_raw_value raw 不处理：物理电平 需要看真实电平、或自己做取反时用

gpio_set_value（legacy）走的是 raw 版本，这是历史行为——早年没有 active-low 概念，编号直接对应寄存器。需要「逻辑 1 = 有效」的代码应该在 dts 里标 GPIO_ACTIVE_LOW 然后用非 raw 版本，而不是自己在代码里取反。

can_sleep 为真的芯片，全部要换 _cansleep 后缀：gpiod_get_value_cansleep、gpiod_set_value_cansleep、gpiod_set_raw_value_cansleep、gpiod_get_raw_value_cansleep。gpiod_direction_input / gpiod_direction_output 本身可以睡，不需要后缀，但不能在中断上下文里调。

9.1 gpio_request 的实现 #

c
int gpio_request(unsigned gpio, const char *label)
{
        struct gpio_desc *desc = gpio_to_desc(gpio);

        /* Compatibility: assume unavailable "valid" GPIOs will appear later */
        if (!desc && gpio_is_valid(gpio))
                return -EPROBE_DEFER;

        return gpiod_request(desc, label);
}

宏展开后：

text
GPIO A base -> S3C2410_GPA(0) = 0
GPIO B base -> S3C2410_GPB(0) = S3C2410_GPIO_B_START = 0 + 32 + 0 = 32
GPIO C base -> S3C2410_GPC(0) = 32 + 32 + 0 = 64

规律是「上一个 bank 的起始编号 + 上一个 bank 的位宽」。注意 _NR 一律是 32，不是数据手册上的 25/11/16——这是故意的，每个 bank 在编号空间里占满 32 格，没引出的位置留空，bank_index * 32 + pin 就能从任何引脚名算出编号。源码里那句 #error CONFIG_S3C_GPIO_SPACE cannot be nonzero at the moment 就是把这个口子封了。

这张 s3c24xx_gpios[] 表在第十七章还会再出现一次（那边看的是它的注册与回调），这里只看 base 怎么算。

-EPROBE_DEFER 语义。 gpio_to_desc 返回 NULL 但 gpio_is_valid(gpio) 为真，说明「这个编号在平台上是合法的，只是对应的控制器还没注册」。这时返回 -EPROBE_DEFER 让上层稍后重试，而不是 -ENODEV 让 probe 直接失败。这条兼容语义是给「芯片注册晚于使用者探测」的场景设计的。

9.2 换算链：一行内联，后面全是 gpiod #

legacy 函数的实现清一色是「gpio_to_desc + 转调 gpiod_*」：

c
static inline int gpio_direction_input(unsigned gpio)
{
        return gpiod_direction_input(gpio_to_desc(gpio));
}

static inline int gpio_direction_output(unsigned gpio, int value)
{
        return gpiod_direction_output(gpio_to_desc(gpio), value);
}

static inline void gpio_set_value(unsigned gpio, int value)
{
        __gpio_set_value(gpio, value);      /* → gpiod_set_raw_value */
}

/* A platform's <asm/gpio.h> code may want to inline the I/O calls when
 * the GPIO is constant and refers to some always-present controller,
 * giving direct access to chip registers and tight bitbanging loops. */
static inline int gpio_get_value(unsigned int gpio)
{
        return __gpio_get_value(gpio);      /* → gpiod_get_raw_value */
}

__gpio_set_value 和 __gpio_get_value 分别落到 gpiod_set_raw_value(gpio_to_desc(gpio), value) 与 gpiod_get_raw_value(gpio_to_desc(gpio))。这就是为什么 legacy 的读写是物理值：它压根没走 gpiod_set_value 那层的 active-low 处理。

这条链每次调用都要遍历一遍 gpio_devices 链表找 desc，然后跳一层函数指针。位带操作的 tight loop 里用 gpio_set_value 开销可观，所以老代码经常直接 writel 自己的寄存器。想快就走描述符——probe 里 gpiod_get 拿到 desc 存起来，后面 gpiod_set_value 直接跳，不再查链表。

9.3 legacy 接口的三个硬伤 #

硬伤 表现 描述符接口怎么解决
依赖全局编号 换块板子编号全变，没 dt 就抓瞎 gpiod_get 从设备树按名字拿，编号无关
没有 active-low 语义 gpio_set_value(gpio, 1) 是物理电平，逻辑取反要自己写 dts 标 GPIO_ACTIVE_LOW，核心统一处理
无法表达「可选」 板子上没接这根线，驱动只能删代码或 #ifdef gpiod_get_optional 返回 NULL 表示没有，代码照走

第三条在实际产品里最要命。同一份 sensor 驱动，A 板有中断脚、B 板没接，用 legacy 就得写两套平台数据；用 gpiod_get_optional，一个 if (desc) 解决。

十、描述符接口 gpiod_get 系列 #

描述符接口在 3.13 前后进主线（gpiod_* 与 struct gpio_desc 公开化），到 4.x 成为唯一推荐写法，5.2.8 里所有新驱动都用这套。头文件是 <linux/gpio/consumer.h>。

10.1 获取：按名字，不按编号 #

con_id 是「这根线在这台设备上叫什么」，对应设备树里 <con_id>-gpios 或 <con_id>-gpio 属性：

10.2 flags：一次说清初始状态 #

宏 含义
GPIOD_ASIS 不改方向，也不改值
GPIOD_IN 取回即配成输入
GPIOD_OUT_LOW 配成输出，初值低
GPIOD_OUT_HIGH 配成输出，初值高
GPIOD_OUT_LOW_OPEN_DRAIN 输出低 + 开漏
GPIOD_OUT_HIGH_OPEN_DRAIN 输出高 + 开漏
GPIOD_OUT_LOW_OPEN_SOURCE 输出低 + 开源
GPIOD_OUT_HIGH_OPEN_SOURCE 输出高 + 开源

带 GPIOD_OUT_* 的好处是「方向和初值在同一个原子动作里设定」，不会出现中间毛刺。GPIOD_ASIS 保证完全不碰硬件——接管 bootloader 已配好的状态时用它。flags 还能顺带置 FLAG_ACTIVE_LOW、FLAG_OPEN_DRAIN、FLAG_OPEN_SOURCE，所以 GPIOD_OUT_HIGH_OPEN_DRAIN 之后 gpiod_direction_output 会走第八章那条开漏分支。

if (led)
        gpiod_set_value(led, 1);

struct gpio_descs 是 { unsigned int ndescs; struct gpio_desc *desc[]; }，配 gpiod_set_array_value() / gpiod_get_array_value() 用，底层优先走 chip->set_multiple / get_multiple，把一组同 bank 的位合成一次寄存器写。

10.5 一个完整的使用侧写法 #

c
struct mydev {
        struct gpio_desc *reset;
        struct gpio_desc *irq_gpio;
};

static int mydev_probe(struct platform_device *pdev)
{
        struct device *dev = &pdev->dev;
        struct mydev *priv;
        int ret;

        priv = devm_kzalloc(dev, sizeof(*priv), GFP_KERNEL);
        if (!priv)
                return -ENOMEM;

        /* 复位脚：必须有，取回即拉低 */
        priv->reset = devm_gpiod_get(dev, "reset", GPIOD_OUT_LOW);
        if (IS_ERR(priv->reset)) {
                dev_err(dev, "no reset gpio\n");     /* 5.2.8 还没有 dev_err_probe */
                return PTR_ERR(priv->reset);
        }

        /* 中断脚：可选，配成输入 */
        priv->irq_gpio = devm_gpiod_get_optional(dev, "irq", GPIOD_IN);
        if (IS_ERR(priv->irq_gpio))
                return PTR_ERR(priv->irq_gpio);

        platform_set_drvdata(pdev, priv);

        msleep(10);                                  /* 保持复位至少 10ms */
        gpiod_set_value_cansleep(priv->reset, 1);

        if (priv->irq_gpio) {
                ret = gpiod_to_irq(priv->irq_gpio);
                if (ret < 0)
                        return ret;
                ret = devm_request_threaded_irq(dev, ret, NULL, mydev_isr,
                                                IRQF_ONESHOT, "mydev", priv);
                if (ret)
                        return ret;
        }
        return 0;
}

remove 里什么都不用写，devm_gpiod_get 申请的线由 devres 释放。这里刻意没用 dev_err_probe——它是 5.9 才进主线的，从 5.2.8 往新内核迁的代码里这是最常见的一类编译错误。

11.2 迁移的四个动作 #

第一步：设备树补属性。 原来平台代码里写死的编号，改写成 xxx-gpios = <&ctrl pin flags>。这层不做，后面全白搭。

第二步：全局编号换 desc 指针。 私有结构体里 unsigned int reset_gpio; 改成 struct gpio_desc *reset;。

第三步：request/free 换 devm_gpiod_get。 顺手检查所有延迟，确认 can_sleep 的芯片走了 _cansleep 版本。

第四步：把「物理电平」的假设翻出来。 老代码 gpio_set_value(gpio, 0) 意思是「输出低」，迁移后如果 dts 里标了 GPIO_ACTIVE_LOW，gpiod_set_value(desc, 0) 的意思是「失效」——物理上是高。这条最容易在迁移时搞反，建议迁移期不标 active-low，行为验证过再逐根加。

十二、从设备树拿 GPIO #

描述符接口的输入来自设备树。这一章讲清三件事：控制器侧怎么写、使用者侧怎么写、两套解析函数有什么区别。

12.1 控制器节点 #

一个 GPIO 控制器在 dts 里至少三个属性：

dts
gpioa: gpio@0xe01b0000 {
        compatible = "actions,s900-gpio";
        reg = <0 0xe01b0000 0x0c>;
        gpio-controller;              /* 声明「我是 GPIO 控制器」 */
        #gpio-cells = <2>;            /* 引用我的引脚要几个 cell */
        gpio-line-names = "LED0", "", "", "KEY1";   /* 可选，给每根线起名 */
        gpio-ranges = <&pinctrl1 19 52 1>;          /* 可选，与 pinctrl 建立映射 */
};

#gpio-cells = <2> 是绝大多数平台的选择：第一个 cell 是 chip 内偏移（offset），第二个是标志（GPIO_ACTIVE_LOW、GPIO_OPEN_DRAIN 等）。of_xlate 回调的职责就是把这个 specifier 翻成「chip 内编号 + flags」。不实现 of_xlate 时核心用默认实现，按 of_gpio_n_cells 解析——这也是为什么 of_gpio_n_cells 必须和 #gpio-cells 对上。

gpio-line-names 由 of_gpiochip_add 读取，效果等同于 chip->names，在 /sys/kernel/debug/gpio 里显示成 "LED0" 这样的名字，调试时省很多事。

12.2 使用者节点的三种写法 #

dts
/* 写法一：单根，属性名 = <con_id>-gpios */
mydev {
        reset-gpios = <&gpioa 19 GPIO_ACTIVE_LOW>;
};

/* 写法二：数组，驱动用 gpiod_get_index / gpiod_get_array */
mydev2 {
        data-gpios = <&gpioa 0 GPIO_ACTIVE_HIGH>,
                     <&gpioa 1 GPIO_ACTIVE_HIGH>,
                     <&gpioa 2 GPIO_ACTIVE_HIGH>;
};

/* 写法三：具名引脚组，老写法，驱动用 of_gpio_count 数个数再 of_get_named_gpio */
mydev3 {
        key_1 = <&gpg 0 GPIO_ACTIVE_HIGH>;
        key_2 = <&gpg 1 GPIO_ACTIVE_HIGH>;
};

写法三是素材里的 key_1 = <&gpg 0 GPIO_ACTIVE_HIGH>，配合 of_get_named_gpio 用。写法一二才是描述符接口的输入。

常见标志位：

标志 含义
GPIO_ACTIVE_HIGH 逻辑 1 = 物理高（默认）
GPIO_ACTIVE_LOW 逻辑 1 = 物理低
GPIO_OPEN_DRAIN 开漏输出
GPIO_OPEN_SOURCE 开源输出
GPIO_SLEEP_MAY_LOSE_VALUE 睡眠可能丢值，置 FLAG_TRANSITORY
GPIO_SLEEP_MAINTAIN_VALUE 睡眠保持值，5.x 新增，5.2.8 未验证

12.3 of_get_named_gpio：编号时代的接口 #

c
/**
 * of_get_named_gpio() - Get a GPIO number to use with GPIO API
 * @np:         device node to get GPIO from
 * @propname:   Name of property containing gpio specifier(s)
 * @index:      index of the GPIO
 *
 * Returns GPIO number to use with Linux generic GPIO API, or one of the errno
 * value on the error condition.
 */
static inline int of_get_named_gpio(struct device_node *np,
                                   const char *propname, int index)
{
        return of_get_named_gpio_flags(np, propname, index, NULL);
}

int of_get_named_gpio_flags(struct device_node *np, const char *list_name,
                            int index, enum of_gpio_flags *flags);

np 是设备节点，propname 是属性名，index 是属性里第几个 specifier（从 0 起）。成功返回全局 GPIO 编号，失败返回负数。带 flags 的版本顺带拿出有效电平等信息——这是用编号接口时把 GPIO_ACTIVE_LOW 取出来的唯一途径。

典型用法：

c
ret = of_get_named_gpio(pdev->dev.of_node, "key_1", 0);
if (ret < 0) {
        printk("of get named gpio is error!\n");
        return ret;
}

gpio = ret;
ret = devm_gpio_request(&pdev->dev, gpio, "key_1");
if (ret) {
        printk("request gpio failed\n");
        return ret;
}
gpio_direction_input(gpio);

毛病一目了然：拿到了编号，还得自己 request、自己 direction_input，中间还要处理「编号合法但控制器没注册」的重试。而这枚 key_1 到底有没有接，代码里表达不出来。

配套的计数函数：

c
/**
 * of_gpio_named_count() - Count GPIOs for a device
 *
 * Example:
 * gpios = <0
 *          &gpio1 1 2
 *          0
 *          &gpio2 3 4>;
 *
 * The above example defines four GPIOs, two of which are not specified.
 * This function will return '4'
 */
static inline int of_gpio_named_count(struct device_node *np, const char* propname)
{
        return of_count_phandle_with_args(np, propname, "#gpio-cells");
}

注释里的例子点出关键：属性里可以夹 0，表示「这一格空着，但位置保留」。所以「数出来的个数」不等于「真正有效的引脚数」，遍历时还得判 gpio_is_valid。这是编号接口最难用的地方之一。

12.4 gpiod_get_from_of_node：直接拿描述符 #

c
struct gpio_desc *gpiod_get_from_of_node(struct device_node *node,
                                         const char *propname,
                                         int index,
                                         enum gpiod_flags dflags,
                                         const char *label);

node 是设备节点，propname 是属性名，index 是第几个，dflags 是获取时的初始状态（与 gpiod_get 的 flags 同一套），label 是请求标签。返回 desc 或 ERR_PTR。

区别在于「从哪里取」：gpiod_get 用 dev + con_id 拼出属性名（<con_id>-gpios），gpiod_get_from_of_node 直接给属性名，不拼。什么时候用后者？

  • 设备节点不是 platform device 的 dev，比如 OF overlay 或某个子节点。
  • 属性名有特殊规则，不想走 con_id 的拼接。
  • 要在 dev 正式 probe 之前取值。

实现上它走 of_get_named_gpiod_flags() → of_find_gpio() → gpiod_get_index()，最后一样落到 gpiod_request，所以 dflags 里的方向与初值照样会被设置。

它和 gpiod_get 共用同一套「拼属性名再解析」的逻辑，在 drivers/gpio/gpiolib-of.c 的 of_find_gpio 里。那个函数对 con_id 做多种拼法依次尝试（<con_id>-gpios、<con_id>-gpio 等），这就是为什么两个名字都能匹配。想看确切的尝试顺序，直接读你自己内核里这个函数，比任何文档都准。

这段是 5.2.8 drivers/gpio/gpiolib-of.c 里 of_find_gpio 的骨架（原文较长，中间的兼容命名尝试省略）。它解释了为什么 gpiod_get(dev, "reset", ...) 能同时匹配 reset-gpios 和 reset-gpio：函数里对 con_id 做多种拼法依次尝试。想知道确切的尝试顺序，直接读你自己内核里这个函数，比任何文档都准。

12.5 从 device 到 of_node #

gpiod_get 内部拿的 np 是 dev->of_node。有几个 API 会把它写成 dev_of_node(dev)，5.2.8 上两者等价。如果 dev->of_node 是 NULL（比如一个 platform device 由板级代码创建而不是 dt），gpiod_get 会退到 ACPI 路径再失败，返回 -ENOENT。

调试这一层最快的办法是看 debugfs：

bash
mount -t debugfs none /sys/kernel/debug
cat /sys/kernel/debug/gpio

输出里每个 chip 一节，每根线一行，占据者名字就是 label。如果 dt 写对了但这里没出现，说明 gpiod_get 根本没执行到。

十三、gpio 与中断的结合：gpio_to_irq #

GPIO 编号是无符号整数，IRQ 编号也是。这是两个逻辑上独立的命名空间——GPIO 0 不一定对应 IRQ 0，也没有任何整比例关系。映射接口只有两个：

c
/* 映射 GPIO 编号到 IRQ 编号 */
int gpio_to_irq(unsigned gpio);

/* 映射 IRQ 编号到 GPIO 编号（尽量避免使用） */
int irq_to_gpio(unsigned irq);

描述符版本是 gpiod_to_irq(desc)。返回对应的 IRQ 编号，或负错误码（比如这个脚不能当 IRQ 用）。

13.1 三条实现路径 #

gpio_to_irq 内部是 gpiod_to_irq(gpio_to_desc(gpio))，而 gpiod_to_irq 会根据 chip 的配置选路径：

路径 条件 说明
chip->to_irq 回调 驱动自己实现了 最老的方式，S3C2440 的 s3c24xx_gpiolib_fbank_to_irq 就是这条
irq_domain 映射 chip 注册了 struct gpio_irq_chip（chip->irq.domain） 5.x 主流方式，irq_find_mapping(domain, offset)
线性 IRQ 基址 chip->irq.base / 老式 hwirq 直接相加 已废弃，只在极老的平台代码里

irq_domain 这一路在 5.2.8 里是默认推荐。gpiochip_add_irqchip() 在注册时把 chip->irq 子结构转成 domain，gpiod_to_irq 里就是一次 irq_find_mapping()。用 domain 的好处是 hwirq 与 virq 解耦、支持层级 domain（GPIO 挂在 SoC 的二级中断控制器下）、支持 irq_chip 的完整回调。

gpio_to_irq 的调用时机有讲究：必须在 gpio_direction_input 之后。反过来的顺序，控制器还没把引脚切到输入复用状态，硬件上根本产生不了边沿。素材原文把这条写成了「使用一个未通过 gpio_direction_input 配置为输入的 GPIO 编号，或者使用一个并非来源于 gpio_to_irq 的 IRQ 编号，这些错误是未经检测的」——意思是接口不校验，你自己负责。

gpio_to_irq 返回的非错误值可以直接喂给 request_irq() / free_irq()，板级初始化代码常把它塞进平台设备的 IRQ 资源里。触发方式（IRQF_TRIGGER_FALLING 之类）是 IRQ 接口的一部分，系统唤醒能力（enable_irq_wake()）也是。

irq_to_gpio 名气很坏。它返回的非错误值「大多数情况下」可以喂给 gpio_get_value，用于沿触发中断里初始化或更新驱动状态。但很多平台根本不实现反映射，所以官方态度是「尽量避免使用」。新代码用 gpiod_to_irq 之后把 desc 存起来，不再回头找 GPIO。

13.2 S3C2440 的 to_irq：手写映射 #

第二篇素材的控制器驱动里，GPIOF 的 to_irq 是手写的：

c
static int s3c24xx_gpiolib_fbank_to_irq(struct gpio_chip *chip, unsigned offset)
{
        if (offset < 4) {
                if (soc_is_s3c2412())
                        return IRQ_EINT0_2412 + offset;
                else
                        return IRQ_EINT0 + offset;   /* 外部中断 0 + 偏移 */
        }

        if (offset < 8)
                return IRQ_EINT4 + offset - 4;

        return -EINVAL;
}

逻辑就是查表：GPF0~GPF3 对应 EINT0~EINT3，GPF4~GPF7 对应 EINT4~EINT7。因为这些 EINT 的 virq 是固定的宏，直接加偏移就能算出来，不需要 domain。

那些宏在 arch/arm/mach-s3c24xx/include/mach/irqs.h：

c
/* main cpu interrupts */
#define IRQ_EINT0      S3C2410_IRQ(0)       /* 16 */
#define IRQ_EINT1      S3C2410_IRQ(1)
#define IRQ_EINT2      S3C2410_IRQ(2)
#define IRQ_EINT3      S3C2410_IRQ(3)
#define IRQ_EINT4t7    S3C2410_IRQ(4)       /* 20 */

/* interrupts generated from the external interrupts sources */
#define IRQ_EINT4      S3C2410_IRQ(36)     /* 52 */
#define IRQ_EINT5      S3C2410_IRQ(37)
#define IRQ_EINT6      S3C2410_IRQ(38)
#define IRQ_EINT7      S3C2410_IRQ(39)

注意这里的中断层级：IRQ_EINT0~3 和 IRQ_EINT4t7 是主中断源，直接挂在 VIC 上；IRQ_EINT4~7 是外部中断控制器（EINTCON/EINTMASK/EINTPEND）的输出，它们的父中断是 IRQ_EINT4t7。所以「GPF4 触发中断」这条路上要动两层：EINTCON 里配触发方式、EINTMASK 放开，再在 INTMSK 里放开 IRQ_EINT4t7。

irqs.h 里 S3C2410_IRQ(0) 注释成 16，是因为 VIC 前 16 个中断号被硬件固定用途占着，S3C2410 的「中断 0」从 virq 16 起算。这是「GPIO 编号与 IRQ 编号无关」的一个实例：GPF4 的 GPIO 编号是 S3C2410_GPF(0)+4 = 5*32+4 = 164（按前面 A~M 顺序推），而它的 IRQ 是 52。

13.3 现代写法：gpio_irq_chip #

5.2.8 里推荐的做法不再写 to_irq，而是填 struct gpio_chip 里的 irq 子结构：

c
static int mygpio_probe(struct platform_device *pdev)
{
        struct mygpio *priv;
        int ret;

        /* ... 初始化 priv->gc 的 base/ngpio/label/direction_*/get/set ... */

        priv->gc.irq.chip         = &mygpio_irqchip;  /* irq_chip 回调 */
        priv->gc.irq.handler      = handle_edge_irq;
        priv->gc.irq.default_type = IRQ_TYPE_NONE;
        priv->gc.irq.threaded     = false;            /* 可睡眠芯片必须置 true */

        return devm_gpiochip_add_data(&pdev->dev, &priv->gc, priv);
}

gpiochip_add_irqchip 会在注册时把这个 irq 变成 irq_domain，gpiod_to_irq 自动走 domain 路径。irq_chip 里至少要实现 irq_mask、irq_unmask、irq_set_type，另外常配 irq_ack。

irq_chip 的实现细节属于中断子系统的内容，这里只标一条必须知道的约束：to_irq 之类的回调不许睡眠，可睡眠芯片的中断必须线程化（irq.threaded = true）。这条约束的出处就在 gpio_chip.to_irq 的注释里：「implementation may not sleep」。

13.4 中断线申请的顺序 #

一次正确的 GPIO 中断建立过程，四步不能乱：

c
/* 1. 拿描述符，说明它要当输入 —— 必须在 gpiod_to_irq 之前 */
desc = devm_gpiod_get(dev, "irq", GPIOD_IN);
if (IS_ERR(desc))
        return PTR_ERR(desc);

/* 2. 拿中断号 */
irq = gpiod_to_irq(desc);
if (irq < 0)
        return irq;

/* 3. 申请中断，注意触发方式 */
ret = devm_request_threaded_irq(dev, irq, NULL, my_handler,
                                IRQF_TRIGGER_FALLING | IRQF_ONESHOT,
                                "mydev", priv);

/* 4. 需要唤醒源时 */
enable_irq_wake(irq);

第 3 步用 devm_request_threaded_irq 且 primary handler 传 NULL，IRQF_ONESHOT 是必需的。触发方式也可以在 dts 的 interrupts 属性里描述；两边都写时会各自调一次 irq_set_irq_type，后设的覆盖先设的，具体顺序未验证——所以触发方式只在一处写。

十四、gpio 的 sysfs 接口 #

/sys/class/gpio 是用户态直接操作 GPIO 的老通道。从内核 4.8 起就被标记为 deprecated，新项目该用 libgpiod 走 /dev/gpiochipN。但移植阶段它是冒烟测试的最快手段：几行 shell 就能验证 get/set 回调写得对不对，不依赖用户态工具链。

14.1 打开配置 #

两个配置项都要选上：

text
File systems  --->  Pseudo filesystems  --->  [*] sysfs file system support
Device Drivers  --->  -*- GPIO Support  --->  [*] /sys/class/gpio/... (sysfs interface)

对应的 .config 行：

text
CONFIG_GPIO_SYSFS=y
CONFIG_SYSFS=y

素材里给的是 +# CONFIG_GPIO_SYSFS=y / -# CONFIG_SYSFS is not set 这种 diff 片段，本质就是「把 CONFIG_GPIO_SYSFS 打开，别把 CONFIG_SYSFS 关掉」。

14.2 挂 sysfs #

rootfs 在 ramdisk 里时，起来以后没有 /sys，得手工建：

bash
mkdir /sys
mount -t sysfs /sys /sys

14.3 目录结构 #

bash
ls /sys/class/gpio

text
export       gpiochip128  gpiochip32   gpiochip96
gpiochip0    gpiochip160  gpiochip64   unexport

名字里的数字就是各 chip 的 base。这正是 base 必须全局唯一的直接理由：两个 chip 撞同一个 base，后注册那个会在 gpiochip_sysfs_register 的 device_create_with_groups 上失败。

进任一 chip 目录，三个只读属性：

属性 含义 来源
base 这段 gpio 在全局编号空间的起点 chip->base
ngpio 这段有多少根 chip->ngpio
label 芯片标识 chip->label

14.4 export / direction / value #

以 LED0（GPIOA19，gpioa 的 base 是 0）为例，逻辑编号就是 19：

bash
echo 19 > /sys/class/gpio/export           # 申请这根 gpio，目录随即出现
ls /sys/class/gpio                         # 应该能看到 gpio19

echo out > /sys/class/gpio/gpio19/direction    # 设为输出
echo 1   > /sys/class/gpio/gpio19/value        # 输出高，LED 亮
echo 0   > /sys/class/gpio/gpio19/value        # 输出低，LED 灭
echo 19 > /sys/class/gpio/unexport             # 用完还回去

echo 19 > export 这一步内部调的就是 gpiod_request(desc, "sysfs")，标签固定是 sysfs。所以你在 /sys/kernel/debug/gpio 里看到某根线的 label 是 sysfs，说明有人忘了 unexport。

direction 支持 in、out、high、low 四种值，后两种等价于「配输出 + 给初值」。value 读写都行，读的是 gpiod_get_value 的结果（逻辑值）。

14.5 sysfs 的三个坑 #

坑一：export 失败，No such device。 这是素材里遇到的真实报错。原因是 owl_gpio_request 里已经在调 pinctrl_request_gpio，但 gpio-ranges 还没配，pinctrl 找不到这个 gpio 对应的 pin，直接返回错误。移植阶段的处理是先把请求短路掉：

c
static int owl_gpio_request(struct gpio_chip *chip, unsigned offset)
{
        /* return pinctrl_request_gpio(chip->base + offset);  等 gpio-range 配好再打开 */
        return 0;
}

注意素材原文写的是 pinctrl_request_gpio(offset)，这是错的——pinctrl_request_gpio 参数是全局 GPIO 编号，不是 offset。这一处在第十八章还会再提。

坑二：export 后立刻写 value 失败。 /sys/class/gpio/gpioN/ 目录是 device_create 建的，udev 规则也许还没跑完。顺序上 export 返回后目录一定在（sysfs 是同步的），失败多是权限问题或者上一行报错被忽略。

坑三：导出了忘了 unexport，驱动 probe 失败。 data direction 之类需要在启动脚本里手动配的板子，经常在 /etc/init.d 里留一堆 echo N > /sys/class/gpio/export，然后正式驱动 probe 拿到 -EBUSY。

14.6 新接口：字符设备与 libgpiod #

4.8 引入的字符设备接口在 /dev/gpiochipN，用 ioctl 完成「拿句柄 → 读/写/等事件」，支持「一个 ioctl 同时操作多根线」和「带时间戳的事件上报」，这些 sysfs 都做不到。

bash
gpiodetect                    # 列出所有 gpiochip
gpioinfo                      # 列出每根线的名字、方向、使用者
gpioget gpiochip0 19          # 读
gpioset gpiochip0 19=1        # 写
gpiomon gpiochip0 19          # 等边沿事件，带时间戳

gpioinfo 的输出基本就是 /sys/kernel/debug/gpio 的用户态版本，调试时比 sysfs 好用。这组工具在 busybox 里没有，得交叉编译 libgpiod。

/dev/gpiochipN 的节点还是靠 mdev/udev 建，或者手动 mknod（主设备号看 /proc/devices 里的 gpiochip）。

十五、控制器驱动的完整骨架 #

把前十四章拼起来，一个 5.2.8 上能过 review 的控制器驱动长这样。以「一个 bank 一个 chip、寄存器无独立置位/清除位」的常见结构为例。寄存器读-改-写的手法和第十六章、第十七章完全一样，这里只留结构，每个回调留一句职责说明。

c
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/of_device.h>
#include <linux/gpio/driver.h>      /* 控制器驱动只要这个头 */
#include <linux/spinlock.h>
#include <linux/io.h>

#define MYCHIP_NGPIO    32
#define MYCHIP_REG_CFG  0x00        /* 2 bit/pin：00 输入 01 输出 1x 复用 */
#define MYCHIP_REG_DAT  0x04
#define MYCHIP_REG_PULL 0x08
#define MYCHIP_CFG_OUT  0x1

struct mychip {
        void __iomem     *base;
        struct gpio_chip gc;
        spinlock_t       lock;
};

/* 六个硬件回调的实现在下面那张表里按职责列出：
 * direction_input / direction_output / get_direction / get / set / set_config。
 * 每个都是 gpiochip_get_data(gc) 取回 priv，再对 priv->base 做读-改-写。 */

static int mychip_request(struct gpio_chip *gc, unsigned offset)
{
        /* 把请求转给 pinctrl 做互斥，参数是全局编号，见第十八章 */
        return pinctrl_request_gpio(gc->base + offset);
}

static void mychip_free(struct gpio_chip *gc, unsigned offset)
{
        pinctrl_free_gpio(gc->base + offset);
}

static int mychip_probe(struct platform_device *pdev)
{
        struct device *dev = &pdev->dev;
        struct mychip *priv;
        struct resource *res;
        int ret;

        priv = devm_kzalloc(dev, sizeof(*priv), GFP_KERNEL);
        if (!priv)
                return -ENOMEM;

        res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
        priv->base = devm_ioremap_resource(dev, res);
        if (IS_ERR(priv->base))
                return PTR_ERR(priv->base);

        spin_lock_init(&priv->lock);

        priv->gc.label            = dev_name(dev);
        priv->gc.parent           = dev;
        priv->gc.owner            = THIS_MODULE;
        priv->gc.base             = -1;         /* 让核心动态分配 */
        priv->gc.ngpio            = MYCHIP_NGPIO;
        priv->gc.can_sleep        = false;
        priv->gc.request          = mychip_request;
        priv->gc.free             = mychip_free;
        priv->gc.get_direction    = mychip_get_direction;
        priv->gc.direction_input  = mychip_direction_input;
        priv->gc.direction_output = mychip_direction_output;
        priv->gc.get              = mychip_get;
        priv->gc.set              = mychip_set;
        priv->gc.set_config       = mychip_set_config;

        ret = devm_gpiochip_add_data(dev, &priv->gc, priv);
        if (ret) {
                dev_err(dev, "failed to add gpiochip: %d\n", ret);
                return ret;
        }

        platform_set_drvdata(pdev, priv);
        return 0;
}

static const struct of_device_id mychip_of_match[] = {
        { .compatible = "my,mychip-gpio" },
        { }
};
MODULE_DEVICE_TABLE(of, mychip_of_match);

static struct platform_driver mychip_driver = {
        .probe  = mychip_probe,
        .driver = { .name = "mychip-gpio", .of_match_table = mychip_of_match },
};
module_platform_driver(mychip_driver);
MODULE_LICENSE("GPL v2");

各回调写什么：

回调 实现要点
direction_input 持锁读 REG_CFG，&= ~(3 << (offset*2)) 写 00
direction_output 持锁先写 REG_DAT 定位电平，再把 REG_CFG 的两位改成 01（先电平后方向，避免毛刺）
get_direction 读 REG_CFG 取两位，等于 01 返回 0（输出），否则 1（输入）
get 读 REG_DAT 取 BIT(offset)，不必持锁
set 持锁读 REG_DAT，按 value 置位/清位后写回
set_config pinconf_to_config_param() 解析，上下拉写 REG_PULL，其余返回 -ENOTSUPP

必须有的，缺一个就出问题：

项 缺了会怎样
gc.parent = dev sysfs 父设备错，devm 生命周期靠它
gc.owner = THIS_MODULE 模块能在 GPIO 还被占用时卸载，use-after-free
gc.base = -1 多实例时 base 冲突，第二个 chip 注册 -EBUSY
gc.ngpio 0 直接 -EINVAL
gc.get_direction 注册时按 direction_input 存在与否瞎猜，sysfs 的 direction 可能显示错
devm_gpiochip_add_data 第三参数传 priv gpiod_get_drvdata 取不到私有数据，多实例驱动没法工作
spin_lock 保护的读-改-写 两个 CPU 同时改同一个配置寄存器，互相冲掉

可以省的：

  • remove：devm_gpiochip_add_data 管了。
  • irq 子结构：不做中断就不填，/sys/kernel/debug/gpio 里没有中断信息，功能不受影响。
  • dbg_show：核心有默认实现，会打印 label、方向、请求者。
  • names：不起别名就 NULL，gpioinfo 里显示空字符串。
  • get_multiple/set_multiple：不实现则核心逐个调 get/set，只是慢一点。
  • enable/disable：5.2.8 已删，改用 request/free。跨版本时注意这一条。

十六、一个最小控制器驱动实例 #

上一章是「完整骨架」，能过 review 但代码量不小。这一章反过来：一个只支持输入输出的最小可用驱动，用来验证「最少要填几个回调才能让 gpiod_get 和 sysfs 都工作」。

三十行就够，核心思路是不写任何回调，直接用 bgpio_init()：

c
// SPDX-License-Identifier: GPL-2.0
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/gpio/driver.h>

struct minigpio {
        struct gpio_chip gc;
        void __iomem     *dat;   /* 数据寄存器：bit n = line n */
        void __iomem     *dir;   /* 方向寄存器：1 = 输出 */
};

static int minigpio_probe(struct platform_device *pdev)
{
        struct device *dev = &pdev->dev;
        struct minigpio *priv;
        int ret;

        priv = devm_kzalloc(dev, sizeof(*priv), GFP_KERNEL);
        if (!priv)
                return -ENOMEM;

        priv->dat = devm_platform_ioremap_resource(pdev, 0);
        if (IS_ERR(priv->dat))
                return PTR_ERR(priv->dat);

        priv->dir = priv->dat + 4;      /* 方向寄存器紧跟数据寄存器 */

        /* bgpio_init(gc, dev, sz, dat, set, clr, dirout, dirin, flags)：
         * 只用 dat + dirout，set/clr/dirin 传 NULL。 */
        ret = bgpio_init(&priv->gc, dev, 4,
                         priv->dat, NULL, NULL, priv->dir, NULL, 0);
        if (ret)
                return ret;

        priv->gc.label  = dev_name(dev);
        priv->gc.base   = -1;
        priv->gc.ngpio  = 32;
        priv->gc.parent = dev;
        priv->gc.owner  = THIS_MODULE;

        return devm_gpiochip_add_data(dev, &priv->gc, priv);
}

static const struct of_device_id minigpio_of_match[] = {
        { .compatible = "my,minigpio" },
        { }
};
MODULE_DEVICE_TABLE(of, minigpio_of_match);

static struct platform_driver minigpio_driver = {
        .probe  = minigpio_probe,
        .driver = { .name = "minigpio", .of_match_table = minigpio_of_match },
};
module_platform_driver(minigpio_driver);
MODULE_LICENSE("GPL v2");

bgpio_init 做了这些事（drivers/gpio/gpio-mmio.c）：

  • 把 get 换成 bgpio_get，set 换成 bgpio_set（有 set/clr 寄存器时用它们做原子置位，没有就走读-改-写 + bgpio_lock）；
  • 把 direction_input/direction_output 换成 bgpio_dir_in/bgpio_dir_out；
  • 如果传了 dirin 就同时给出 get_direction；
  • 填 reg_dat/reg_dir_out/bgpio_bits/bgpio_data/bgpio_dir 一堆字段。

sz 参数是寄存器宽度（字节），4 表示 32 位寄存器，于是 bgpio_bits = 4 * 8 = 32。flags 里可以传 BGPIOF_BIG_ENDIAN、BGPIOF_BIG_ENDIAN_BYTE_ORDER、BGPIOF_UNREADABLE_REG_DIR、BGPIOF_NO_OUTPUT 等。

几处细节值得看：

dirin 传 NULL，dirout 有值。 这意味着核心不知道方向寄存器的位序，get_direction 不会被装上，注册时那个初始化循环会走 else 分支按 direction_input 猜。想让它准，就把 dirin 也填上（同一个地址也行，只要方向寄存器可读）。

devm_platform_ioremap_resource 是 5.0 前后才有的便利函数，等价于 platform_get_resource + devm_ioremap_resource。5.2.8 上有。往 4.x 移植要改回两步写法。

它没有 request/free 回调。 所以这根线申请时会话：核心只置 FLAG_REQUESTED，不会通知 pinctrl。这在纯 GPIO 板子上没问题，在 pinctrl 与 GPIO 共存 的 SoC 上就会缺互斥保护——第十八章讲怎么补。

没有中断能力。 gpiod_to_irq 会返回 -ENXIO（没有 domain 也没有 to_irq 时）。要用中断得自己加 irq 子结构。

验证这个最小驱动的方式，按顺序三步：

bash
# 1. 看有没有注册上
dmesg | grep minigpio
ls /sys/class/gpio/
cat /sys/class/gpio/gpiochip*/label

# 2. 用 sysfs 冒烟
echo 3 > /sys/class/gpio/export
cat /sys/class/gpio/gpio3/direction      # 应该是 in
echo out > /sys/class/gpio/gpio3/direction
echo 1 > /sys/class/gpio/gpio3/value
cat /sys/class/gpio/gpio3/value          # 回读，有回读能力的控制器应该读到 1
echo 3 > /sys/class/gpio/unexport

# 3. 看谁占着
cat /sys/kernel/debug/gpio

第 2 步的「回读 1」是最有价值的一条：它同时验证了 set、get 和方向寄存器三者对不对。如果读回 0，先怀疑方向寄存器位序（dirout 和 dirin 别搞反），再怀疑配置寄存器位宽。

十七、S3C2440 / linux 5.2.8 的控制器实现走读 #

前面都是教科书式骨架。这一章看一颗真芯片：S3C2440 在 5.2.8 上的 GPIO 控制器驱动，在 arch/arm/plat-samsung/，属于老式非 DT 平台代码，一个文件同时支持 S3C24xx / S3C64xx / S5P 系列。

版本边界：gpio-samsung.c 在 5.x 里已被大幅精简，DT 平台走 drivers/pinctrl/samsung/pinctrl-samsung.c，这里走读的是非 DT 的 legacy 路径（函数开头就是 if (of_have_populated_dt()) return 0;）。该文件在后续内核里被删掉，Mini2440 转用 pinctrl-samsung。这一章看「老代码怎么写控制器」，不是「新板子该怎么写」。

17.1 硬件前提 #

每个控制器三个 32 位寄存器：配置（GPACON~GPJCON）、数据（GPADAT~GPJDAT）、上拉（GPBUP~GPJUP，0 使能上拉，1 禁止）。

GPA 特殊：配置寄存器 1 bit 管一根脚，低 25 位管 25 根，0 = 通用输出，1 = 特殊功能（此时 GPADAT 无效）。所以 GPA 不能做通用输入，也没有 GPAUP。

GPB~GPJ 常规：2 bit 一根脚，00 输入、01 输出、10 特殊功能、11 特殊功能或保留，每 bank 最多 16 根。这套「1 bit / 2 bit」的差异是所有代码分叉的根源。

17.2 平台私有包装 #

c
struct samsung_gpio_chip {
        struct gpio_chip        chip;        /* 给 gpiolib 的那一份，必须第一个成员 */
        struct samsung_gpio_cfg *config;     /* 配置函数集 */
        struct samsung_gpio_pm  *pm;         /* 省电回调 */
        void __iomem            *base;       /* 寄存器基地址（虚拟地址） */
        int                     irq_base;    /* 中断基址 */
        int                     group;
        spinlock_t              lock;        /* 保护这个 bank 的共享配置寄存器 */
#ifdef CONFIG_PM
        u32                     pm_save[4];
#endif
        u32                     bitmap_gpio_int;
};

struct samsung_gpio_cfg {
        unsigned int    cfg_eint;        /* 配成外部中断时要写进配置寄存器的值 */
        samsung_gpio_pull_t (*get_pull)(struct samsung_gpio_chip *chip, unsigned offs);
        int                 (*set_pull)(struct samsung_gpio_chip *chip, unsigned offs,
                                        samsung_gpio_pull_t pull);
        unsigned            (*get_config)(struct samsung_gpio_chip *chip, unsigned offs);
        int                 (*set_config)(struct samsung_gpio_chip *chip, unsigned offs,

};

chip 放第一个成员，&priv->chip 与 priv 地址相同——这就是 to_samsung_gpio(chip)（container_of）能工作的前提。samsung_gpio_cfg 把「1 bit 还是 2 bit」的差异用函数指针吃掉。

三处值得对照前文：

两个 base 不同义。 外层 .base 是寄存器物理地址（S3C2440_GPJCON），.chip.base 是 GPIO 编号。

GPA 的 ngpio = 27 与实芯片不符。 27 是 S3C2416 的 GPA 引脚数，S3C2440 是 25（gpio-samsung.h 顶部那张 SoC 对比表）。偏大在功能上无害，是这张表的老毛病。GPA 同时挂着 direction_input = s3c24xx_gpiolib_banka_input 也有历史原因：S3C2416 的 GPA 支持输入。

.irq_base = IRQ_EINT8 挂在 GPG。 GPG0~GPG15 对应 EINT8~EINT23 连续一段，基址加法就够。

GPIO 编号本身由 gpio-samsung.h 的宏算出（S3C2410_GPIO_A_NR = 32、S3C2410_GPIO_NEXT() 递增），0, 32, 64, ... 每个 bank 占满 32 格——这一段在 9.1 已经算过。

17.4 GPA 的 1 bit 配置函数 #

c
/*
 * 控制寄存器每根引脚只有 1 bit：置位 = 特殊功能，清零 = 输出。
 */
static int s3c24xx_gpio_setcfg_abank(struct samsung_gpio_chip *chip,
                                     unsigned int off, unsigned int cfg)
{
        void __iomem *reg = chip->base;
        unsigned int shift = off;
        u32 con;

        if (samsung_gpio_is_cfg_special(cfg)) {
                cfg &= 0xf;

                /* Map output to 0, and SFN2 to 1 */
                cfg -= 1;
                if (cfg > 1)
                        return -EINVAL;

                cfg <<= shift;
        }

        con = __raw_readl(reg);   /* 读 GPACON */
        con &= ~(0x1 << shift);   /* 第 shift 位清 0 */
        con |= cfg;
        __raw_writel(con, reg);
        return 0;
}

samsung_gpio_is_cfg_special(cfg) 判断是不是特殊功能请求；三星内部用 S3C_GPIO_SFN(n) 编码，cfg -= 1 把编码映射到寄存器值（输出 → 0，特殊功能 → 1）。读回是反向：con >>= off; con &= 1; con++; return S3C_GPIO_SFN(con);。

常规 bank 的 2 bit 版本只差三处——shift = off * 2、掩码 0x3、cfg 上限 3：

c
static int samsung_gpio_setcfg_2bit(struct samsung_gpio_chip *chip,
                                    unsigned int off, unsigned int cfg)
{
        void __iomem *reg = chip->base;
        unsigned int shift = off * 2;
        u32 con;

        if (samsung_gpio_is_cfg_special(cfg)) {
                cfg &= 0xf;
                if (cfg > 3)
                        return -EINVAL;
                cfg <<= shift;
        }

        con = __raw_readl(reg);   /* 读 GPxCON */
        con &= ~(0x3 << shift);   /* 清两位 */
        con |= cfg;
        __raw_writel(con, reg);
        return 0;
}

读回用 con >>= off * 2; con &= 3; return S3C_GPIO_SPECIAL(con);。这几个 setcfg 都不加锁，加锁责任在调用者。

17.5 注册流程 #

c
static __init int samsung_gpiolib_init(void)
{
        /* DT 平台交给 pinctrl-samsung，legacy 平台才用这个驱动 */
        if (of_have_populated_dt())
                return 0;

        if (soc_is_s3c24xx()) {
                samsung_gpiolib_set_cfg(samsung_gpio_cfgs,
                                ARRAY_SIZE(samsung_gpio_cfgs));
                s3c24xx_gpiolib_add_chips(s3c24xx_gpios,
                                ARRAY_SIZE(s3c24xx_gpios), S3C24XX_VA_GPIO);
        }
        return 0;
}
core_initcall(samsung_gpiolib_init);

static void __init s3c24xx_gpiolib_add_chips(struct samsung_gpio_chip *chip,
                                             int nr_chips, void __iomem *base)
{
        int i;
        struct gpio_chip *gc = &chip->chip;

        for (i = 0 ; i < nr_chips; i++, chip++) {
                if (chip->chip.base >= S3C_GPIO_END)     /* 跳过本 SoC 没有的 bank */
                        continue;

                if (!chip->config)                      /* 缺省 2bit 配置函数集 */
                        chip->config = &s3c24xx_gpiocfg_default;
                if (!chip->pm)
                        chip->pm = __gpio_pm(&samsung_gpio_pm_2bit);
                if ((base != NULL) && (chip->base == NULL))
                        chip->base = base + ((i) * 0x10);   /* 每 bank 间隔 0x10 */

                if (!gc->direction_input)
                        gc->direction_input = samsung_gpiolib_2bit_input;
                if (!gc->direction_output)
                        gc->direction_output = samsung_gpiolib_2bit_output;

                samsung_gpiolib_add(chip);
        }
}

static void __init samsung_gpiolib_add(struct samsung_gpio_chip *chip)
{
        struct gpio_chip *gc = &chip->chip;
        int ret;

        BUG_ON(!chip->base);
        BUG_ON(!gc->label);
        BUG_ON(!gc->ngpio);

        spin_lock_init(&chip->lock);

        if (!gc->set)
                gc->set = samsung_gpiolib_set;
        if (!gc->get)
                gc->get = samsung_gpiolib_get;

        /* gpiochip_add_data() prints own failure message on error. */
        ret = gpiochip_add_data(gc, chip);      /* 第二参数传 samsung_gpio_chip */
        if (ret >= 0)
                s3c_gpiolib_track(chip);
}

三件事：S3C_GPIO_END 按 SoC 定义（CONFIG_CPU_S3C244X 下是 S3C2410_GPJ(0) + 32），S3C2440 因此跳过 GPK~GPM；寄存器基址从 S3C24XX_VA_GPIO 起每 bank 加 0x10（四个寄存器 × 4 字节）；缺省回调补 2bit 版本，config 缺省补 s3c24xx_gpiocfg_default。最终 GPIOA 用 banka 配置，GPIOB~GPIOJ 用默认 2bit 配置。

第二个参数是 struct samsung_gpio_chip *，这就是私有数据的用法。这个文件里的回调都自己 container_of，没用 gpiochip_get_data——老代码两种写法并存很常见。S3C24XX_VA_GPIO 定义为 ((S3C24XX_PA_GPIO - S3C24XX_PA_UART) + S3C24XX_VA_UART)。

17.6 四个基本回调 #

输入写 00，输出先定电平再切方向写 01：

c
static int samsung_gpiolib_2bit_input(struct gpio_chip *chip, unsigned offset)
{
        struct samsung_gpio_chip *ourchip = to_samsung_gpio(chip);
        void __iomem *base = ourchip->base;
        unsigned long flags;
        unsigned long con;

        samsung_gpio_lock(ourchip, flags);
        con = __raw_readl(base + 0x00);         /* 读 GPxCON */
        con &= ~(3 << (offset * 2));            /* 清两位 = 00 输入 */
        __raw_writel(con, base + 0x00);
        samsung_gpio_unlock(ourchip, flags);
        return 0;
}

static int samsung_gpiolib_2bit_output(struct gpio_chip *chip,
                                       unsigned offset, int value)
{
        struct samsung_gpio_chip *ourchip = to_samsung_gpio(chip);
        void __iomem *base = ourchip->base;
        unsigned long flags, dat, con;

        samsung_gpio_lock(ourchip, flags);

        dat = __raw_readl(base + 0x04);       /* 先定电平 */
        dat &= ~(1 << offset);
        if (value)
                dat |= 1 << offset;
        __raw_writel(dat, base + 0x04);

        con = __raw_readl(base + 0x00);       /* 再切方向 */
        con &= ~(3 << (offset * 2));
        con |= 1 << (offset * 2);             /* 01 = 输出 */
        __raw_writel(con, base + 0x00);

        samsung_gpio_unlock(ourchip, flags);
        return 0;
}

素材原文在 output 里第二次写 __raw_writel(dat, base + 0x04)，是冗余的（con 的写入不影响 GPxDAT）；另有一句注释写「写入 10 代表输出」，而 1 << (offset*2) 写的正是 01。两处都在附录记了一笔。

set 与 get：samsung_gpiolib_set 读 base + 0x04、清位、按 value 置位、写回，全程持锁；samsung_gpiolib_get 读 ourchip->base + 0x04、右移 offset、& 1，不加锁——读-改-写才需要锁。

__raw_readl/__raw_writel 不带内存屏障、不做字节序转换，在 ARM 上等于直接 ldr/str。S3C2440 时代这样写是主流，现代代码改用 readl/writel 或 regmap。这层差异在移植时会冒出来：__raw_* 在 ARM64 上会让编译器不考虑指针别名导致的重排。

17.7 这一章没有 pinctrl #

S3C2440 这段代码完全不含 pinctrl：复用配置就是 samsung_gpio_cfg 那组函数指针直接写 GPxCON。原因是 pinctrl 子系统 2012 年才成型，这段代码比它早。现代三星平台（Exynos 之后）走 pinctrl-samsung.c，GPIO 功能由 pinctrl 提供，gpio-samsung.c 退场。

这就是本篇把「legacy 控制器」和「现代控制器」分开讲的原因：硬件上是同一件事，软件上隔了两代架构。

十八、GPIO 子系统与 pinctrl 的关系 #

一句话：pinctrl 决定这根脚「干什么用」，gpiolib 决定这根脚「电平是多少」。两者是同一块硅、两套视图。

18.1 一个脚的两条描述 #

视图 命名空间 谁能改
pinctrl pin controller 实例 + pin 编号 pin controller 驱动（复用、上下拉、驱动强度）
gpiolib gpiochip 实例 + offset GPIO 控制器驱动（方向、电平）

同一个物理引脚在这两套命名空间里有不同的编号，需要一张映射表才能对上。这张表就是 gpio-ranges，存进 gpio_device 的 pin_ranges 链表（第六章那个 #ifdef CONFIG_PINCTRL）。

18.2 gpio-ranges：dts 侧 #

dts
pinctrl1: pinctrl@0xe01b0000 {
        compatible = "actions,s900-pinctrl";
        reg = <0 0xe01b0000 0x550>;
};

gpioa: gpio@0xe01b0000 {
        compatible = "actions,s900-gpio";
        reg = <0 0xe01b0000 0x0c>;
        gpio-controller;
        #gpio-cells = <2>;
        gpio-ranges = <&pinctrl1 19 52 1>;
};

四个参数的顺序最容易写错：

text
gpio-ranges = <&pinctrl1   19      52      1>;
                │          │       │       └─ 数量：连续映射几个
                │          │       └───────── pinctrl 侧的起始 pin 编号
                │          └───────────────── gpio 侧的起始编号（chip 内 offset）
                └──────────────────────────── 指向哪个 pin controller

意思是「gpioa 的 offset 19 对应 pinctrl1 的 pin 52，共 1 个」。写成 <&pinctrl1 52 19 1> 也编译得过，运行时就去操作一根根本不存在的 gpio，症状是 export 报错或者写到了别的脚上。

一个 gpio-ranges 可以带多个四元组：<&pinctrl1 0 0 32 &pinctrl2 32 0 32> 表达跨 pin controller 的分段映射。数量为 1 也别省那个 1。

18.3 三个转调：pinctrl 侧 #

gpio-ranges 建好之后，GPIO 侧的 request/free/方向切换会落到 pin controller 的 pinmux_ops 上：

c
/* 申请一个 gpio：把该 pin 切到 gpio 功能，并做互斥检查 */
int (*gpio_request_enable)(struct pinctrl_dev *pctldev,
                           struct pinctrl_gpio_range *range,
                           unsigned offset);

/* 释放：把 pin 从 gpio 功能上摘下来 */
void (*gpio_disable_free)(struct pinctrl_dev *pctldev,
                          struct pinctrl_gpio_range *range,
                          unsigned offset);

/* 方向切换：某些 SoC 的 in/out 本身就是一种复用状态，必须在这里改 */
int (*gpio_set_direction)(struct pinctrl_dev *pctldev,
                          struct pinctrl_gpio_range *range,
                          unsigned offset,
                          bool input);

offset 这里是 pin 编号（例子里是 52），不是 gpio 编号（19）。range 结构里存的才是 gpio 侧的信息。这两个编号混用是这一层最常见的 bug。

18.4 四个转调：gpio 侧 #

GPIO 控制器驱动的回调不再自己干活，而是转给 pinctrl：

c
int  pinctrl_request_gpio(unsigned gpio);
void pinctrl_free_gpio(unsigned gpio);
int  pinctrl_gpio_direction_input(unsigned gpio);
int  pinctrl_gpio_direction_output(unsigned gpio);
gpio_chip 回调 转调的 pinctrl API 传什么
.request pinctrl_request_gpio(gpio) 全局编号 chip->base + offset
.free pinctrl_free_gpio(gpio) 同上
.direction_input pinctrl_gpio_direction_input(gpio) 同上
.direction_output pinctrl_gpio_direction_output(gpio) 同上

注意这里传的是全局逻辑编号，不是 offset。pinctrl 侧靠 gpio-ranges 反查，才知道这个 gpio 对应哪个 pin。素材原文在 owl_gpio_request 里写 pinctrl_request_gpio(offset) 就是传错了，正确写法是 pinctrl_request_gpio(chip->base + offset)。

而 offset 的语义在这里再分一次叉：gpio_chip 回调里的 offset 是 chip 内偏移；pinmux_ops 回调里的 offset 是 pin 编号。同名不同义，两处都叫 offset。

18.5 职责可以灵活划分 #

有些平台在实现 gpio_request_enable 时会卡住：光凭 gpio 编号和 pin 编号，怎么找到寄存器与 bit 偏移？

Bubblegum-96（Actions S900）的具体情况是：gpio 的 pinmux 没有独立寄存器，靠使能 gpio 的 in/out 功能去覆盖其他 pinmux 功能。也就是说，配置这个动作本身就是「把 gpio 控制器切到输入或输出」。

这时候合理的折中是把硬件配置交给 gpio driver，pinctrl driver 只负责互斥：

层 职责
gpio driver 操作寄存器，切 in/out、读写电平
pinctrl driver 只判断这个 pin 当前有没有被别的 function 占用，做仲裁

这样 gpio_request_enable 里只做互斥检查并记下占用状态，寄存器操作全留在 gpio 侧。S3C2440 那种老的 samsung_gpio_cfg 走的是另一个极端——复用全在 pinctrl 那一层（当年还没 pinctrl 时就是 gpio 驱动自己干）。

18.6 没有 gpio-ranges 会怎样 #

症状 原因
export 报 No such device gpio 侧 request 调了 pinctrl_request_gpio，但 pinctrl 找不到映射，返回错误
电平写了但外设没反应 pin 正被别的 function 复用，gpio 驱动不知情就写了自己的寄存器
只有 gpio driver 的日志，没有 pinctrl 的 gpio-ranges 没生效，或 pinctrl 驱动没 probe
中断不来 pin 没切到 GPIO 功能，gpio_direction_input 写的是 gpio 寄存器而不是复用寄存器

第三条的验收信号很干脆：成功的链路上，export 时 pinctrl 侧会打一条形如 s900_gpio_request_enable, range(19/52/1), offset 52 的日志，三个数字正好对应 gpio-ranges 的 19 52 1。只有 gpio 侧日志、没有 pinctrl 侧那条，说明「看起来能用、实际没有互斥保护」。

GPIO 与 pinctrl 各自怎么写驱动，pinctrl 那半在本目录《设备树 pinctrl 子系统与 pin 控制器驱动》里从头讲。

bash

19.5 一个真实的排查顺序 #

假设「LED 不亮」。按这个顺序走，五分钟定位：

text
① 控制器注册了吗？      dmesg | grep -i gpiochip        没有 → 驱动没编进去 / dt status 不对
② 线在不在这台芯片上？  cat /sys/kernel/debug/gpio       没有这一行 → 编号算错 / chip 没起来
③ 谁占着这根线？        同上，看 label                   是 sysfs → 有人忘了 unexport
④ 方向对不对？          cat /sys/class/gpio/gpioN/direction   不是 out → 驱动没调 direction_output
⑤ 值写进去了吗？        读回 value / 量电平                写了但没变 → 寄存器地址或位偏移错
⑥ 复用对不对？          量电平的同时看 pinmux 寄存器      电平对但外设不动 → gpio-ranges 缺失
⑦ 硬件对不对？          万用表量 LED 两端                 都对着就不亮 → 是三极管方向反了

第 ⑤ 和 ⑥ 是分水岭：GPIO 寄存器写对了、引脚电平也变了，但外设不动，那一定是复用问题，跟 GPIO 子系统无关，回去看 pinctrl。

19.6 调试手段的边界 #

/sys/kernel/debug/gpio 显示不了「这根线的复用状态」，那是 pinctrl 的 debugfs（/sys/kernel/debug/pinctrl/）的范围。两边一起看才完整：

bash
ls /sys/kernel/debug/pinctrl/
cat /sys/kernel/debug/pinctrl/*/pinmux-pins    # 每个 pin 当前归谁

没有 gpio-ranges 文件或内容是空，就是映射没建起来。

二十、易错点速查 #

# 易错点 正确做法
1 控制器驱动 include <linux/gpio.h> 用 <linux/gpio/driver.h>；消费者用 <linux/gpio/consumer.h>（5.x 拆分）
2 gc.base = 0 写死 gc.base = -1，让核心动态分配（base 非负已标 DEPRECATION）
3 多个 bank 共用一个 gpio_chip 模板 每个实例一份 chip，拷模板后覆盖 base，或用 of_property_read_u32 读 base
4 gc.ngpio = 0 必填，0 直接 -EINVAL
5 忘了 gc.owner = THIS_MODULE 模块能在 GPIO 被占用时卸载
6 devm_gpiochip_add_data(dev, gc, NULL) 第三参数传私有数据，否则 gpiod_get_drvdata 拿不到
7 不实现 get_direction 核心猜方向，sysfs 的 direction 可能显示错
8 读-改-写寄存器不加锁 用 spin_lock_irqsave 保护配置/数据寄存器
9 I2C/SPI 扩展器不设 can_sleep 必须设 true，之后全部用 _cansleep 版本
10 gpiod_to_irq 在 direction_input 之前调 先配输入，再取 IRQ 号，再 request_irq
11 pinctrl_request_gpio(offset) 参数是全局编号 gc->base + offset
12 gpio-ranges 写成 <&pctrl pin gpio n> 顺序是 <&pctrl gpio编号 pin编号 数量>
13 pinmux_ops 回调里把 offset 当 gpio 编号 那里是 pin 编号
14 devm_gpiod_get 的结果用 !desc 判错 用 IS_ERR(desc)；_optional 才算可能为 NULL
15 dts 属性写成 reset_gpios 是 reset-gpios 或 reset-gpio
16 gpiod_set_value 与 gpiod_set_raw_value 混用 逻辑值用前者（会处理 active-low），看物理电平用后者
17 dts 标了 GPIO_ACTIVE_LOW 但代码里又取反一次 active-low 只标一处，取反由核心做
18 在中断上下文里 gpiod_get 会睡，改成 probe 里申请
19 devm_ioremap_resource 申请与 pinctrl 重叠的地址段 换裸 ioremap，且 remove 里自己 iounmap
20 export 了忘了 unexport 启动脚本里成对出现；驱动 probe 拿到 -EBUSY 先查这个
21 用 /sys/class/gpio 做产品功能 4.8 起 deprecated，产品用 /dev/gpiochipN + libgpiod
22 在 legacy 代码里保留 gpio_request(常量编号) 迁到 gpiod_get + dt，否则换板子全废
23 gpiod_direction_output 传物理值 参数是逻辑值，active-low 由核心取反
24 enabled/disable 回调 5.2.8 已删，用 request/free
25 忘记 chip->parent = dev sysfs 父设备错，devm 生命周期依赖它

修正的错误 #

# 素材原文 修正
1 「这些函数一般定义在 drivers/gpio/gpiolib-devres.c」（指 legacy 全套接口） gpiolib-devres.c 只放 devm_* 封装；gpio_request 在 gpiolib-legacy.c，gpiod_* 主体在 gpiolib.c
2 pinctrl_request_gpio(offset) 参数是全局 GPIO 编号，应为 gc->base + offset（第十八章）
3 samsung_gpiolib_2bit_output 注释「写入 10 代表输出」 2 bit 配置里 01 是输出，代码写的也是 01，注释错
4 samsung_gpiolib_2bit_output 第二次 __raw_writel(dat, base + 0x04) 冗余（con 的写入不影响 GPxDAT），已在正文标注
5 s3c24xx_gpios 里 GPA 项 ngpio = 27 27 是 S3C2416 的 GPA 引脚数；S3C2440 是 25。已在 17.3 标注
6 「gpiolib 为其它的驱动提供了一些列的调用接口」 「一些列」→「一系列」
7 「General purpose input/putput」 putput → output
8 「获得 GPIO 控制器的的 gpio_chip 结构」「挂接到 chop 上的 direction_output」 重复字与错字修正
9 「IRQ~EINT4t7 为主中断源」 IRQ~EINT4t7 → IRQ_EINT4t7
10 「struct gpio_chip 的抽象，实际上就是对一个 GPIO 控制器的抽象」 句子重复，已重写
11 「在 gpio_request 函数后面调用 gpiod_request」 表述不准，实为 gpio_request 内部调用 gpiod_request
12 「gpiochip_setup_dev 会在 gpiolib 的模块入口函数 gpiolib_dev_init 中调用」 准确说是 gpiolib_dev_init 调 gpiochip_setup_devs，后者遍历链表调 gpiochip_setup_dev
13 「lable：标签」 lable → label
14 「devm_gpiochip_add_data 注册时「管理其内存」」 管理的不是内存而是 chip 的注销时机，已改述
15 「S3C2440 分为了 9 个 GPIO 控制器，每个 GPIO 控制器都有 n 个寄存器」后紧跟「GPIOA 控制器有以下几个寄存器：」图丢失 图缺失，改为文字描述三个寄存器 + GPA 特殊性说明
16 表格与正文里反复出现的口头禅式提醒 按语气要求全部改写
17 samsung_gpiolib_init 的注释「然后调用了 samsung_gpiolib_set_cfg 的函数」 语句不通，重写为 s3c24xx_gpiolib_add_chips 的职责

未验证项 #

标「未验证」的条目我没有在 5.2.8 源码里逐行核对，用前请自测：

  1. gpiod_* 描述符接口的确切引入版本。 描述符与 gpiod_get 在 3.13 前后进主线，gpiod_get_optional/gpiod_get_array 稍晚。素材里没有标注，我按「3.13+ 逐步引入、4.x 成为主流、5.x 是唯一推荐」处理。
  2. <linux/gpio.h> 的拆分版本。 <linux/gpio/driver.h> 与 <linux/gpio/consumer.h> 在 4.16 前后成形，5.x 里 <linux/gpio.h> 只剩兼容内容。具体哪个小版本删掉了哪些内联函数，未验证。
  3. gpiod_enable_hw_timestamp_ns 等 5.x 后期新增函数。 5.2.8 上是否存在未验证，详见 10.4 表注。
  4. GPIO_SLEEP_MAINTAIN_VALUE 标志。 属于 5.x 后期对 FLAG_TRANSITORY 的补充，5.2.8 的 flags 位定义里没有看到，未验证。
  5. struct gpio_irq_chip 在 5.10 之后的字段变化。 4.4 节里提到「5.10 之后又加了若干字段」，未逐个核对。
  6. irq_set_irq_type 与 dt 中 interrupts 触发方式的覆盖顺序。 13.4 节末尾标注了「未验证」。
  7. bgpio_init 在 5.2.8 中的确切签名与 flags 取值。 正文按 bgpio_init(gc, dev, sz, dat, set, clr, dirout, dirin, flags) 九个参数描述，这是 5.x 的形态；更早版本参数不同。
  8. arch/arm/plat-samsung/gpio-samsung.c 被删除的确切版本。 该文件在 5.x 后期随非 DT 平台清理而删除，具体版本未验证。
  9. S3C2440 的 GPA ngpio。素材写 27，gpio-samsung.h 的 SoC 对比表写 25，两者矛盾。我按「27 是 S3C2416 的值」解释，未在 5.2.8 上确认该表对 S3C2440 的实际取值路径。
  10. gpiod_get_direction 返回值语义（0 输出 / 1 输入）来自 gpio_chip.get_direction 的注释，gpiod_get_direction 本身是否做转换未逐行核对。
  11. devm_platform_ioremap_resource 的引入版本。正文写「5.0 前后」，未精确核对。
  12. dev_err_probe 的引入版本。正文写 5.9，这是广为流传的说法，未在 5.9 tag 上验证。
