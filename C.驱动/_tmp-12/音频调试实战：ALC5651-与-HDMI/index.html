一、音频调试的整体思路 #

音频不通，先问一个问题：断在哪一层。RK3399 上一条完整的播放链路有六层，从上往下排：

层 涉及对象 出问题时的典型现象
应用/音频服务 PulseAudio、default.pcm.card 声音去了别的声卡，当前声卡静默
ALSA 用户态 aplay、amixer、alsactl 命令报错、控件值不对
ASoC 声卡 card / DAI link / DAPM route DAI link 没连上，DAPM path 不完整
CPU DAI 控制器 ff880000.i2s（I2S0）、ff8a0000.i2s（I2S2） 寄存器没使能，时钟没起
时钟与引脚 clk_i2s0、clk_i2sout、pinctrl、io-domain 引脚无波形，MCLK 不出
Codec ALC5651（I2C1 地址 0x1a）、HDMI 音频块 寄存器通路没打开，耳机无声

排查原则有三条，按这个顺序走能少绕很多路：

  1. 先看内核态有没有起来。dmesg 里声卡注册日志、/proc/asound/cards、/dev/snd 节点。这一步挂了，后面所有用户态工具都没意义。
  2. 再看软件通路。DAPM path 是否完整、kcontrol 是否打开、寄存器是否按预期写下去。这一步能抓到绝大多数「有人手滑关了某个 switch」的问题。
  3. 最后看物理信号。MCLK 有没有波形、SCLK/LRCK 频率对不对。板子没把引脚引出来就测不了，这时候只能靠时钟树和寄存器反推。

工具和它们对应哪一层：

工具 看什么 命令入口
dmesg 驱动 probe、DAI link 绑定、时钟使能 dmesg | grep -i -E "asoc|rt5651|i2s"
/proc/asound/cards 声卡编号与名称 cat /proc/asound/cards
aplay -l / arecord -l PCM 设备与 DAI link 名 aplay -l
amixer controls / contents kcontrol 列表与当前值 amixer -c 0 contents
alsamixer 可视化调控件，MM 即静音 alsamixer -c 0
/sys/kernel/debug/asoc/ component、dai、widget、DAPM 路径 cat .../asoc/dais
/sys/kernel/debug/regmap/ codec / I2S 寄存器快照 cat .../regmap/1-001a/registers
/sys/kernel/debug/clk/ 时钟树频率与使能计数 cat .../clk/clk_summary
/sys/kernel/debug/pinctrl/ 引脚复用状态 cat .../pinmux-pins | grep i2s
ftrace（events/asoc） DAPM 走查全过程 cat .../tracing/trace
alsactl 保存/恢复控件状态 alsactl store

示波器/逻辑分析仪不在表里，因为只有在其他手段都用尽、且板子把引脚引出来了才有意义。NanoPC-T4 的 40 Pin 排针里只引出了 I2S_CLK（GPIO4_PA0），I2S0_SCLK、I2S0_LRCK_RX、I2S0_LRCK_TX 都没引出来，这一点后面第六节还会撞上。

二、内核配置检查 #

拿到一块新板子，第一件事是确认内核里该配的选项都配了。漏一个 CONFIG_SND_SOC_RT5651，dmesg 里就是干净的，你查一天也查不出声卡来。

先看 Kconfig 里有没有这个选项 #

sound/soc/codecs/Kconfig 里搜 config SND_SOC_RT5651，素材稿里原始状态是：

text
config SND_SOC_RT5651
        tristate
        depends on I2C

这种 tristate 后面不带字符串的写法，make menuconfig 里是看不到这个配置项的。必须补上提示字符串：

text
config SND_SOC_RT5651
        tristate "Realtek ALC5651 CODEC"
        depends on I2C

改完才能在 menuconfig 里选到 Realtek RT5651 CODEC。

内核根目录下 make menuconfig：

对应到 .config：CONFIG_SND_SEQUENCER、CONFIG_SND_SEQ_DUMMY、CONFIG_SND_HRTIMER、CONFIG_SND_DYNAMIC_MINORS、CONFIG_SND_SOC、CONFIG_SND_SOC_ROCKCHIP、CONFIG_SND_SOC_ROCKCHIP_I2S、CONFIG_SND_SIMPLE_CARD、CONFIG_SND_SOC_RT5651，全部 =y。

每个选项背后是哪个 .c 文件，看 Makefile 最直接。

sound/soc/generic/Makefile：

bash
snd-soc-simple-card-objs        := simple-card.o
snd-soc-audio-graph-card-objs   := audio-graph-card.o

obj-$(CONFIG_SND_SIMPLE_CARD)           += snd-soc-simple-card.o
obj-$(CONFIG_SND_AUDIO_GRAPH_CARD)      += snd-soc-audio-graph-card.o

snd-soc-simple-card-objs := simple-card.o 表示把当前目录的 simple-card.o 链接成 snd-soc-simple-card.o。想知道实际链接命令，翻 .cmd 文件：

bash
root@zhengyang:/work/sambashare/rk3399/linux-6.3# cat sound/soc/generic/.snd-soc-simple-card.o.cmd
cmd_sound/soc/generic/snd-soc-simple-card.o := arm-linux-ld -EL -maarch64elf -r -o sound/soc/generic/snd-soc-simple-card.o sound/soc/generic/simple-card.o

sound/soc/rockchip/Makefile 里 CONFIG_SND_SOC_ROCKCHIP_I2S 一次带起两个目标文件 —— rockchip_i2s.o 是控制器主体，rockchip_pcm.o 是 DMA 侧：

bash
obj-$(CONFIG_SND_SOC_ROCKCHIP_I2S) += snd-soc-rockchip-i2s.o snd-soc-rockchip-pcm.o
obj-$(CONFIG_SND_SOC_ROCKCHIP_PDM) += snd-soc-rockchip-pdm.o
obj-$(CONFIG_SND_SOC_ROCKCHIP_SPDIF) += snd-soc-rockchip-spdif.o

sound/soc/codecs/ 就两行：snd-soc-rt5651-objs := rt5651.o 加 obj-$(CONFIG_SND_SOC_RT5651) += snd-soc-rt5651.o。sound/core/Makefile 里 obj-$(CONFIG_SND_SEQUENCER) += seq/ 把音序器编进去，音频播放本身用不到它，配不配不影响出声。

读法：binding ... 说明 DAI link 匹配上了 CPU DAI 和 codec DAI；connected DAI link ... Playback -> ... 两条是 bidirectional 的两半；input: ... Headphones 说明 jack 检测节点也注册了；最后 ALSA device list: #0 说明 card 注册成功。

其中带 -------、dev ff880000.i2s、enable clock mclk 的那些行是抓取时改源码加的调试打印，不是主线内核的输出。 你手上的 clean 内核只会打 asoc-simple-card 带前缀的那几条。别拿自己的内核去对这几行，对不上是正常的。

如果这一屏完全没有，按这个顺序往回查：rt5651 的 I2C 节点有没有 status = "okay" → &i2c1 上有没有 rt5651: codec@1a → rt5651-sound 节点 simple-audio-card,cpu/codec 的 sound-dai 指向对不对 → 内核配置里 CONFIG_SND_SOC_RT5651 是不是 y。

三、查看声卡设备 #

装 ALSA 用户态工具包：

bash
root@rk3399:/# apt-get install alsa-base alsa-utils alsa-oss alsa-tools

/dev/snd 设备节点 #

bash
root@rk3399:/# ll /dev/snd
total 0
drwxr-xr-x  2 root root       60 Jul 26 23:31 by-path/
crw-rw----  1 root audio 116,  4 Jul 26 23:31 controlC0
crw-rw----  1 root audio 116,  3 Jul 26 23:31 pcmC0D0c
crw-rw----  1 root audio 116,  2 Jul 26 23:31 pcmC0D0p
crw-rw----  1 root audio 116,  1 Jul 26 23:31 seq
crw-rw----  1 root audio 116, 33 Jul 26 23:31 timer
节点 用途
controlC0 声卡控制：通道选择、混音、麦克风控制、音量加减、开关
pcmC0D0c 录音 PCM 设备
pcmC0D0p 播放 PCM 设备
seq 音序器
timer 定时器

命名规则来自 alsa-driver：C0D0 是声卡 0 的设备 0，末尾 c 是 capture、p 是 playback。一个声卡下挂几种设备取决于驱动能力，实际最常打交道的就是 pcm 和 control；默认一个声卡一个 control 设备。

主设备号 116 是 ALSA 分配的主号，次设备号 2/3/4 对应 pcm...p、pcm...c、control...。by-path/ 是按物理连接路径排的软链，板子上有多路 I2S 时用 ll /dev/snd/by-path 认路更稳。

声卡列表 #

bash
root@rk3399:/# cat /proc/asound/cards
 0 [realtekrt5651co]: simple-card - realtek,rt5651-codec
                      realtek,rt5651-codec

方括号里那串 realtekrt5651co 是 ALSA 的声卡 id。struct snd_card 的 id 字段长度只有 16，所以存的是 realtek,rt5651-codec 去掉特殊字符后的前 15 个字符 —— 逗号和连字符都被吃掉了，codec 只剩 co。以后 amixer -c 后面要填的就是这个 id 或者编号。

声卡的通道目录 #

/proc/asound/card0 下是声卡的运行时视图：

bash
root@rk3399:/# ll /proc/asound/card0
-r--r--r-- 1 root root 0 Jul 23 16:02 id
dr-xr-xr-x 4 root root 0 Jul 23 16:02 pcm0c/
dr-xr-xr-x 4 root root 0 Jul 23 16:02 pcm0p/
root@rk3399:/# cat /proc/asound/card0/id
realtekrt5651co

pcm0p 是声卡 0 的输出通道，pcm0c 是输入通道。pcm0p/ 下面有 info、sub0/status、sub0/hw_params 这些文件，播不出声的时候先看 status 里是不是 RUNNING、hw_params 里采样率对不对，这比改代码快得多。

aplay -l 与 arecord -l #

bash
root@rk3399:/# aplay -l
**** List of PLAYBACK Hardware Devices ****
card 0: realtekrt5651co [realtek,rt5651-codec], device 0: ff880000.i2s-rt5651-aif1 rt5651-aif1-0 [ff880000.i2s-rt5651-aif1 rt5651-aif1-0]
  Subdevices: 1/1
  Subdevice #0: subdevice #0

bash
root@rk3399:/# arecord -l
**** List of CAPTURE Hardware Devices ****
card 0: realtekrt5651co [realtek,rt5651-codec], device 0: ff880000.i2s-rt5651-aif1 rt5651-aif1-0 [ff880000.i2s-rt5651-aif1 rt5651-aif1-0]
  Subdevices: 1/1
  Subdevice #0: subdevice #0

device 0: 后面那串 ff880000.i2s-rt5651-aif1 rt5651-aif1-0 是 PCM 流名字，由 DAI link 名拼出来 —— ff880000.i2s 是 CPU DAI，rt5651-aif1 是 codec DAI，中间的 - 是 simple-card 拼的。这个名字对不上，说明 DAI link 没按你预期连。

Subdevices: 1/1 表示 1 个子设备、当前空闲 1 个。被别的进程占着的时候会变成 0/1，排查「设备忙」类问题看这行。

联合视图 #

bash
root@rk3399:/# cat /proc/asound/pcm
00-00: ff880000.i2s-rt5651-aif1 rt5651-aif1-0 : ff880000.i2s-rt5651-aif1 rt5651-aif1-0 : playback 1 : capture 1

一行读三个数：00-00 是 card-device，后面 playback 1 : capture 1 表示这一路既能播又能录。如果这里 playback 或 capture 少了一个，说明 DAI link 的方向配反了，simple-audio-card 的 dai-link 里 playback/capture 子节点缺失。

播放与录音 #

bash
root@rk3399:/# cd /
root@rk3399:/# aplay AbuduOffice.wav
Playing WAVE 'AbuduOffice.mp3' : Signed 16 bit Little Endian, Rate 44100 Hz, Stereo

这行输出里文件名显示成 .mp3 是原始抓取稿的笔误，实际播的是 .wav，格式 16 bit 小端、44.1kHz、立体声。能打出这行只能证明 ALSA 用户态把参数送下去了，不证明 codec 出声。耳机插上没声音，往下走第四、五节。

录音的常用参数：

参数 含义
-d 录音持续时间，秒
-f 录音格式，cd 即 16bit 44.1kHz 立体声
-c 声道数
-t 文件标记类型，wav/ogg
-r 采样率 Hz

text

四、查看寄存器：regmap 与 debugfs #

寄存器是这条链路上最硬的证据。kcontrol 改了但寄存器没变，问题在驱动；寄存器对了但引脚没波形，问题在时钟或引脚。

前提是 CONFIG_DEBUG_FS=y：

text
Kernel hacking  --->
     Generic Kernel Debugging Instruments  --->
          [*] Debug Filesystem

debugfs 默认挂在 /sys/kernel/debug。

regmap 目录：按设备名进 #

/sys/kernel/debug/regmap/ 下每个用了 regmap 的设备一个目录，目录名就是设备名。ALC5651 的设备名是 1-001a：1 是 I2C 适配器编号（I2C1），001a 是这条总线上的从设备地址 0x1a。

bash
root@rk3399:/# ls /sys/kernel/debug/regmap/
1-001a  ff880000.i2s  ff8a0000.i2s

每个目录下有两个文件：

文件 内容
registers 当前寄存器快照，地址: 值 逐行
access 该 regmap 的读写属性配置，RR WW 之类

读取方式就一条 cat：

bash
root@rk3399:/# cat /sys/kernel/debug/regmap/1-001a/registers

注意 regmap 目录的命名差异。 6.3 上是 1-001a、ff880000.i2s 这种带点带减号的裸设备名；早期内核（4.x）里同一份文件路径一致，未验证。有些平台为了区分设备会加前缀，遇到 cat 报 No such file 就先 ls 看实际目录名，不要凭记忆敲。

这是唯一正确的读寄存器姿势。 不要指望 /sys/kernel/debug/regmap/ 之外的什么 codec_reg 文件 —— 老的 ASoC 在 /sys/kernel/debug/asoc/<card>/<component>/codec_reg 里有一份等价输出，6.3 上这个文件已经不再默认出现，未验证是否可配。

关键看两个寄存器。

电源控制寄存器 1（MX61）：

bash
root@rk3399:/# cat /sys/kernel/debug/regmap/1-001a/registers | grep 061
061: 9800    #1001 1000 0000 0000

0x9800 = 1001 1000 0000 0000b。bit15 和 bit12 置位，对应数字音频接口 I2S1 上电、模拟 DACL1/DACR1 上电。播放时这几个 bit 必须是 1；是 0 说明 DAPM 没把 widget 拉起来，回到第五节查 path。

DACL1/R1 数字音量（MX19）：

bash
root@rk3399:/# cat /sys/kernel/debug/regmap/1-001a/registers | grep 019
019: afaf    #1010 1111 1010 1111

0xafaf 是默认 0dB 增益（左右声道各 0xAF）。这个值被写成 0x0000 就是彻底静音，被写成 0x4040 之类就是砍了 20dB 以上。

录音时的快照 #

I2S 控制器的寄存器 #

I2S0 基址 0xff880000，播放中与录音中各抓一次，只有 0x0c 和 0x10 两个值不同：

bash
root@rk3399:/# cat /sys/kernel/debug/regmap/ff880000.i2s/registers
00: 0000000f
04: 0000000f
08: 00033f3f
0c: 00000011     # 播放：TX FIFO 有 17 个 sample待发
10: 000f0110     # 第8位写入0x01，Transmit DMA enabled
14: 01f00000
18: 00000000
1c: 00000003     # 第0位写入0x01，开始TX传输
20: 00000000
24: 00000000

录音时同一份文件变成 0c: 00000000、10: 010f0010（bit12/13 侧起来），其余八行一模一样。偏移与含义（对照 RK3399 TRM 的 I2S 章节）：

偏移 名称 关键位
0x00 I2S_TXCR 发送配置：通道数、字长、主从模式
0x04 I2S_RXCR 接收配置
0x08 I2S_CKR 时钟分频与 MCLK 极性
0x0c I2S_TXFLR 发送 FIFO 水位。播放时应为非 0，0x00 说明数据没进 FIFO
0x10 I2S_DMACR bit8 = TX DMA enable，bit12/13/16/17 是 RX/TX 中断使能位
0x14 I2S_INTCR 中断清除
0x18 I2S_INTSR 中断状态。0x0 = 没有中断挂起，正常的
0x1c I2S_XFER bit0 = TX 启动，bit1 = RX 启动
0x20 I2S_CLR 清 FIFO
0x24 I2S_TXFTLR 发送 FIFO 触发阈值

判据：0x10 的 bit8 为 1（DMA 使能）、0x1c 的 bit0 为 1（TX 已启动），两个条件都满足播放才有数据流。只满足一个说明驱动卡在 trigger 阶段。0x0c 一直是 0，往 DMA 那边查。

读单个 widget 的状态 #

每个 widget 文件的内容格式固定：

text
root@rk3399:/# cat /sys/kernel/debug/asoc/realtek,rt5651-codec/ff880000.i2s/dapm/Playback
Playback: Off  in 0 out 2
 stream Playback inactive
 out  "static" "AIF1 Playback"

三行：

  • 第一行：名字: On/Off in <输入 path 数> out <输出 path 数>
  • 第二行：只对 DAI widget 有，stream <名字> active/inactive
  • 之后每行一条 path：out/in、"<kcontrol 名>" 或 "static"（无 kcontrol 的直连）、"<对端 widget 名>"

播放时会变成：

bash
root@rk3399:/# cat /sys/kernel/debug/asoc/realtek,rt5651-codec/ff880000.i2s/dapm/Playback
Playback: On  in 1 out 10
 stream Playback active
 out  "static" "AIF1 Playback"

in 从 0 变 1、out 从 2 变 10，stream 从 inactive 变 active —— 这是整条链路被拉起来的信号。

codec 侧的 DAI widget 同理（左侧空闲，右侧播放中）：

bash
root@rk3399:/# cat /sys/kernel/debug/asoc/realtek,rt5651-codec/rt5651.1-001a/dapm/"AIF1 Playback"
AIF1 Playback: Off  in 0 out 10   ->  AIF1 Playback: On  in 1 out 10
 stream AIF1 Playback inactive    ->   stream AIF1 Playback active
 out  "static" "AIF1RX"           ->   out  "static" "AIF1RX"
 in  "static" "Playback"          ->   in  "static" "Playback"

out "static" "AIF1RX" 和 in "static" "Playback" 就是 DAI link 的两端，static 表示这两条路径上没有 kcontrol，是 DAPM 自动连的。

一个 Mixer widget 更能说明问题：

bash
root@rk3399:/# cat /sys/kernel/debug/asoc/realtek,rt5651-codec/rt5651.1-001a/dapm/'DAC MIXL'
DAC MIXL: Off  in 0 out 1                          ->  DAC MIXL: On  in 1 out 5
 out  "DD MIX" "PDM L Mux"                         ->   out  "DD MIX" "PDM L Mux"
 out  "DAC L1 Switch" "Stereo DAC MIXR"            ->   （消失）
 out  "static" "Audio DSP"                         ->   out  "static" "Audio DSP"
 in  "INF1 Switch" "IF1 DAC1 L"                    ->   in  "INF1 Switch" "IF1 DAC1 L"

对比这两份输出，播放中少掉了 out "DAC L1 Switch" "Stereo DAC MIXR" 这一条。不是打印丢了，是 DAPM 只把当前连接状态（path->connect == 1）的 path 算进 out 计数、也只在这些里挑路径走查。这条被删掉说明 DAC L1 Switch 此刻是 off。

这个对比是定位「哪个 switch 没开」最直接的手段：空闲态列全部 path，播放态列连通的 path，差集就是断点。

一个控件的解剖 #

以 numid=50 为例：

text
numid=50,iface=MIXER,name='DAC MIXR INF1 Switch'
段 含义
numid=50 控件编号
iface=MIXER 控件类型：MIXER、CARD、PCM
name='DAC MIXR INF1 Switch' DAC MIXR 是所属 widget，INF1 Switch 是这个 kcontrol 在自己 widget 内的名字

它对应的代码是这三部分：

c
// kcontrol
 SOC_DAPM_SINGLE("INF1 Switch", RT5651_AD_DA_MIXER,   // RT5651_AD_DA_MIXER = 0x29
                        RT5651_M_IF1_DAC_L_SFT, 1, 1)

// 所属 widget
SND_SOC_DAPM_MIXER("DAC MIXL", SND_SOC_NOPM, 0, 0,   // SND_SOC_NOPM = 不控制 widget 自身电源
                   rt5651_dac_l_mix, ARRAY_SIZE(rt5651_dac_l_mix))

// route
{"DAC MIXL", "INF1 Switch", "IF1 DAC1 L"}

三个值分别是寄存器、偏移、位宽。这里是 MX29 的 bit14，写 1 = 接通、写 0 = 断开。路由那行 {"DAC MIXL", "INF1 Switch", "IF1 DAC1 L"} 是 DAPM 建 path 的原材料 —— 从右往左读：信号从 IF1 DAC1 L 出来，经过 INF1 Switch 这个 kcontrol，进 DAC MIXL。

读法：

  • type：BOOLEAN（开关）、INTEGER（音量）、ENUMERATED（输入源选择）

2 AIF1 Playback AIF1RX 无 同上 -
3 AIF1RX IF1 DAC 无 同上 -
4 IF1 DAC IF1 DAC1 L 无 同上 -
5 IF1 DAC1 L DAC MIXL INF1 Switch MX29 bit14 1
6 DAC MIXL Audio DSP 无 直连 -

「静音值」那列是断开信号的值：写 1 断开，写 0 接通。这和直觉反着来，SOC_DAPM_SINGLE 里最后一个参数为 1 表示 invert。

逐条设成接通：

设完立刻验寄存器：

bash
root@rk3399:/# cat /sys/kernel/debug/regmap/1-001a/registers | grep 029
029: 8080           #1000 0000 1000 0000

0x8080 的 bit14 是 0（0x8000 = 1000 0000 0000 0000，从 0 数第 14 位正好在被置 1 的 bit15 和 bit7 之间 —— 这里 bit15 和 bit7 置位、bit14 清零）。改回去看差异：

bash
root@rk3399:/# amixer cset numid=48 0
numid=48,iface=MIXER,name='DAC MIXL INF1 Switch'
  ; type=BOOLEAN,access=rw------,values=1
  : values=off
root@rk3399:/# cat /sys/kernel/debug/regmap/1-001a/registers | grep 029
029: c080

0xc080 = 原来的 0x8080 加上 bit14。这一来一回就是「控件 → 寄存器」映射的铁证。以后怀疑某个 switch 没生效，用这个手法验一遍，比看代码快。

列的含义（从左到右）：clk 时钟名、enable count 被 enable 的次数、prepare count 被 prepare 的次数、protect count 防止误关的保护计数、rate 当前频率、accuracy 精度、phase 相位、duty cycle 占空比、hardware enable 硬件使能位。

规则很直接：enable count > 0 且 hardware enable = Y 才算真的在跑；enable count = 0 时时钟会被关掉，hardware enable 变 N。

树的层级看缩进：clk_i2s0_div → clk_i2s0_frac → clk_i2s0_mux → clk_i2s0 → clk_i2sout_src → clk_i2sout。clk_i2sout 是最终送给 codec 的 MCLK，11289600 = 11.2896MHz，就是 44.1kHz × 256。

每个时钟目录下的文件 cat 就能读：clk_rate（当前频率）、clk_parent（父时钟名）、clk_prepare_enable（prepare+enable 计数，可写）、clk_flags（标志）、clk_duty_cycle（占空比）。

bash
root@rk3399:/home/zhengyang# cat /sys/kernel/debug/clk/clk_i2sout/clk_rate
11289600

时钟对了但引脚没波形 #

这是整个 ALC5651 排查里最费时间的一段。给 clk_i2sout 使能、频率也确认是 11289600，逻辑分析仪接在 I2S_CLK（GPIO4_PA0 / I2S0_MCLK）上，没有波形。clk_summary 里那一串已经全是 Y、11289600 —— 时钟软件层全部通过，引脚上什么都没有。

一个变量一个变量往下排。

第一步：怀疑 codec 驱动没要 MCLK。 设备树里其实配了：

dts
clocks = <&cru SCLK_I2S_8CH_OUT>;
clock-names = "mclk";

但 rt5651_probe() 里根本没 devm_clk_get() 去取这个时钟，配了等于没配。sound/soc/codecs/rt5651.h 的 rt5651_priv 里加一个成员：

c
struct clk *mclk;

sound/soc/codecs/rt5651.c 的 rt5651_probe() 补上取时钟、设频率、使能三步，并补 #include <linux/clk.h>：

c
        rt5651->mclk = devm_clk_get(component->dev, "mclk");
        if (IS_ERR(rt5651->mclk)) {
                dev_err(component->dev, "Can't retieve i2s master clock\n");
                return PTR_ERR(rt5651->mclk);
        }
        ret = clk_set_rate(rt5651->mclk, 11289600);
        if (ret)
                dev_err(component->dev, "Fail to set mclk %d\n", ret);
        ret = clk_prepare_enable(rt5651->mclk);
        if (ret)
                return ret;

改完重编、烧写、重启，clk_i2sout 的 clk_rate 出来是 11289600，clk_summary 里这一串也全是 Y。但引脚还是没波形。 原因是 platform 驱动初始化 clk_i2s0 时，clk_i2s0 到 clk_i2sout 之间那段选择寄存器的默认值已经指到 clk_i2s0，clk_i2sout 自己再 enable 一次属于重复动作，不改变输出。

第二步：怀疑引脚复用没配。 rockchip_i2s.c 的 i2s_pinctrl_select_bclk_on() 加一行 printk：

        printk("enable i2s pin ---------- %s", __func__);

第三步：用 dummy-codec 绕开「引脚没引出」。 NanoPC-T4 只引出 I2S_CLK，I2S0_SCLK、I2S0_LRCK_RX、I2S0_LRCK_TX、I2S0_SDO0、I2S0_SDI0 都在板内，物理上测不到。那就换一个引脚引出来了的控制器来测：I2S1。

dummy-codec 是 SoC 外部没有实体 codec 时占位用的虚拟设备。它支持多声道 —— I2S0 有 8 个输出声道、2 个输入声道，可以在 i2s0_sdo0~3 上挂 4 个回放 codec，在 i2s0_sdi0 上挂 1 个录制 codec，aplay 能选 8 个通道、arecord 选 2 个。

arch/arm64/boot/dts/rockchip/rk3399-evb.dts 里补：

    status = "okay";
    audio-supply = <&vcca1v8_codec>;

audio-supply 对应 RK3399 IO 电源域的 APIO5_VDD，也就是 I2S_CLK 这些引脚所在的 IO 供电。vcca1v8_codec 在 rk808 节点里定义，是 LDO7。

通道 信号 实测频率 说明
0 I2S_CLK 11.2896MHz MCLK，44.1kHz × 256
1 I2S1_SCLK 2.8224MHz BCLK，44.1kHz × 64
2 I2S1_LRCK_TX 44.1kHz 帧同步，等于采样率
3 I2S1_SDO0 - 每半个 LRCK 周期含 32 个 SCLK 周期，其中 16 个传采样数据，另 16 个空

SCLK = LRCK × 64、SDO 占一半 SCLK 周期，这就是 32bit 帧、16bit 数据位的 I2S 标准时序。 波形对了，说明 SoC 侧全通。

把 dummy-sound、dummy_codec、i2s1 那些节点禁掉，rt5651_card、i2s0、rt5651 恢复 okay，重编烧写。插耳机，有声了。

整条排查的因果链：rt5651_probe() 漏了 devm_clk_get()，clk_i2sout 没人 enable（软件层）→ 补上后时钟树全 Y 但引脚仍无输出 → 引脚复用其实没问题 → 换 I2S1 + dummy-codec 绕开引脚限制复测 → 仍无输出 → 定位到 io_domains 没配 audio-supply → 加上后波形齐全。

中间那两步看起来是白做的，其实不是。 每一步都排除一个变量。没有 dummy-codec 那一步，你会一直以为「I2S0 引脚没引出来所以测不了」，从而永远查不到 io-domain。

九、ALC5651 录音通路的排查 #

录音和播放是镜像的两条路。播放不通的问题在耳机、DAC、HP Amp，录音不通的问题在麦克风、BST、ADC、RECMIX。

完整路径 #

麦克风 2（接在 IN2P/IN2N）左声道：

text
Mic Jack → IN2P → INL1 VOL → RECMIXL → ADC L → Stereo1 ADC L1 Mux
        → Stereo1 ADC MIXL → IF1 ADC1 → AIF1TX → AIF1 Capture → Capture

右声道走 IN2N → INR1 VOL → RECMIXR → ADC R → Stereo1 ADC R1 Mux → Stereo1 ADC MIXR → IF1 ADC1 → AIF1TX → AIF1 Capture → Capture。

RECMIXL 是个 Mixer，BST2 Switch 和 INL1 Switch 两个 kcontrol 决定哪路进来。Stereo1 ADC L1 Mux 是 Mux，ADC 这个 kcontrol 选输入源。Stereo1 ADC MIXL 也是 Mixer，ADC1 Switch 控制。

麦克风 3（接在 IN3P）：

text
Mic Jack → IN3P → BST3 → RECMIXL → ADC L → Stereo1 ADC L1 Mux
        → Stereo1 ADC MIXL → IF1 ADC1 → AIF1TX → AIF1 Capture → Capture

右声道：IN3P → BST3 → RECMIXR → ADC R → ... → Capture。

麦克风 3 走的是 BST3 而不是 INL1/INR1，这是硬件上的差别 —— 麦克风 3 是差分输入，过 boost。

录音不通时的检查顺序 #

  1. /proc/asound/pcm 里有 capture 1 —— 没这个说明 DAI link 方向没配
  2. 录音时 AIF1TX widget 是 On（但 stream 一定还是 inactive，因为它是普通 widget）
  3. arecord -l 能列出设备
  4. RECMIXL/RECMIXR 的 in 计数不为 0 —— 有信号进来
  5. 寄存器 03c/03e（ADC 数字音量）不能是 0000
  6. 用 ADC IF2 Data Switch 选 left copy to right 验证是不是只有一路在工作

第 6 条特别有用：麦克风是单声道的时候，一路有信号一路没有是正常的，把 left copy to right 一开，录出来的两声道都有声音就证明硬件没坏。

dapm_power_one_widget 是现在内核里的名字，素材稿里写成了 dapm_power_one_widgett（多个 t），是笔误。核心逻辑：一个 widget 上不上电，取决于它有没有落在一条从 source 端到 sink 端的完整路径上。

事件定义在 include/trace/events/asoc.h。snd_soc_dapm_start 是通过 DEFINE_EVENT 复用 snd_soc_dapm_basic 这个 class 定义的：

DECLARE_EVENT_CLASS(snd_soc_dapm_basic,
        TP_PROTO(struct snd_soc_card *card),
        TP_ARGS(card),
        TP_STRUCT__entry( __string( name, card->name ) ),
        TP_fast_assign( __assign_str(name, card->name); ),
        TP_printk("card=%s", __get_str(name))
);

DEFINE_EVENT(snd_soc_dapm_basic, snd_soc_dapm_start,
        TP_PROTO(struct snd_soc_card *card),
        TP_ARGS(card)
);

所以 snd_soc_dapm_start 打出来就一句 card=<名字>。

snd_soc_dapm_path 信息量大得多：

c

        TP_PROTO(struct snd_soc_dapm_widget *widget,   // path 一端连接的 widget
                enum snd_soc_dapm_direction dir,       // 另一端在哪一侧：0 输入端，1 输出端
                struct snd_soc_dapm_path *path),       // path 本身

        TP_ARGS(widget, dir, path),

        TP_STRUCT__entry(
                __string(       wname,  widget->name            )
                __string(       pname,  path->name ? path->name : DAPM_DIRECT)
                __string(       pnname, path->node[dir]->name   )
                __field(        int,    path_node               )
                __field(        int,    path_connect            )
                __field(        int,    path_dir                )
        ),

        TP_fast_assign(
                __assign_str(wname, widget->name);
                __assign_str(pname, path->name ? path->name : DAPM_DIRECT);
                __assign_str(pnname, path->node[dir]->name);
                __entry->path_connect = path->connect;
                __entry->path_node = (long)path->node[dir];
                __entry->path_dir = dir;
        ),

        TP_printk("%c%s %s %s %s %s",
                (int) __entry->path_node &&
                (int) __entry->path_connect ? '*' : ' ',
                __get_str(wname), DAPM_ARROW(__entry->path_dir),
                __get_str(pname), DAPM_ARROW(__entry->path_dir),
                __get_str(pnname))
);

TP_printk 第一格那个字符是本章的关键：path_node 和 path_connect 都为真才打 *，否则打空格。所以看到行首有 * 就是「这条 path 当前是通的」，没有就是断的。

怎么读这些行 #

三个字段定形：行首 * + A <- kcontrol <- B。

  • AIF1RX <- (direct) <- AIF1 Playback —— direct 表示没有 kcontrol，DAPM 直接连
  • DAC MIXR <- INF1 Switch <- IF1 DAC1 R —— 中间过了 INF1 Switch 这个 kcontrol
  • 同一对 widget 之间的另一条 DAC MIXR <- Stereo ADC Switch <- Stereo1 ADC MIXR 行首没有 * —— 这条没通

从下往上顺着读，能拼出完整的耳机路径。*Headphones <- (direct) <- HPOL 这条在最后，说明耳机 widget 确实连到了 HPOL。

最后一行 snd_soc_dapm_walk_done: realtek,rt5651-codec: checks 48 power, 31 path, 79 neighbour 是统计：走查了 48 个 widget 的电源、31 条 path、79 个邻居。

核心判据：alsa 在录音/播放前会先查一次 DAPM，看带 * 的 path 能不能连成完整路由。连不成，进程直接停。 所以：

  • 进程能起来但没声 → path 全通，问题在寄存器或硬件
  • 进程起不来或立刻退出 → path 断了，去找哪条没 *

aplay 那行 Playing WAVE ... 打出来之后立刻退、退出码非 0，就是 path 断了。

断链了怎么修 #

看 trace 里最后一个带 * 的 widget 是哪个，下一个不带 * 的去 codec 驱动的 snd_soc_dapm_route 数组里从右往左找，看那条 route 的 kcontrol 名字有没有拼错、widget 名字有没有拼错。拼错名字是 DAPM 最常见的故障 —— snd_soc_dapm_route 里字符串对不上，DAPM 静默忽略这条 route，不报错。

十一、HDMI 音频的通路 #

换 codec 是最省事的一种需求。RK3399 的 HDMI 音频不需要动 machine 和 platform，只换 codec 那一端。

I2S2 #

RK3399 的 I2S2 模块连到 HDMI 和 DP 的音频接口，支持 8 通道数据传输。这是 RK3399 上唯一能给 HDMI 传多声道的 I2S。

I2S2 到 HDMI、I2S2 到 DP 的接线都在 SoC 内部，引脚没有对外暴露，逻辑分析仪测不到。这一点和 ALC5651 那条 I2S0 一样受限 —— 但 I2S0 至少引出了一个 I2S_CLK，I2S2 一个都没有。

三块拼图，只换一块 #

音频驱动由 machine、platform、codec 三块组成。ALC5651 方案里：

块 ALC5651 方案 HDMI 方案
machine rt5651-sound（simple-audio-card） hdmi_sound（simple-audio-card）
platform ff880000.i2s（I2S0） ff8a0000.i2s（I2S2）
codec rt5651.1-001a（I2C1 0x1a） ff940000.hdmi 里的 dw-hdmi i2s

machine 还是 simple-audio-card，platform 还是 rockchip-i2s，只有 codec 从一颗实体芯片换成了 SoC 内部的 dw-hdmi 音频块。所以在软件层看起来几乎是照抄。

播放时数据怎么走 #

text
aplay → ALSA PCM → ASoC DAI link（hdmi_sound）
     → CPU DAI ff8a0000.i2s（I2S2，8 通道）
     → dw-hdmi 的 i2s 输入帧
     → HDMI 打包成 IEC60958 / 多声道 LPCM
     → TMDS 链路
     → 显示器 HDMI 输入 → 显示器喇叭

关键差别在最后一环：ALC5651 方案里声音送到耳机孔就结束了，HDMI 方案里声音要经过整个显示链路才能到扬声器。所以显示器有没有喇叭、HDMI 线有没有 Audio 通道、显示器的音频输入源选的是 HDMI 还是别的，每一环都能让「声卡一切正常但听不到」。

这也是 HDMI 音频排查和 ALC5651 排查最大的不同：软件对了不代表有声音，硬件链路上多了两个你控制不了的设备。

在 asoc 里长什么样 #

接好之后 /sys/kernel/debug/asoc/ 下会多一张卡：

text
/sys/kernel/debug/asoc/
├── components
├── dais
├── hdmi-sound/
└── realtek,rt5651-codec/

hdmi-sound 那张卡下面有 ff8a0000.i2s 和 dw-hdmi 的 component。dais 文件里会多出 i2s-hifi（dw-hdmi 侧）和 ff8a0000.i2s（I2S2 侧）。

两张卡并存的时候 amixer 千万别忘了 -c。 默认 amixer 操作 card 0，两卡顺序变了就会改错卡。HDMI 卡的控件很少，一般只有一个 IEC958 Playback 系列，amixer -c 0 scontrols 一眼就能看出操作的是哪张卡。

十二、HDMI 的设备树配置 #

hdmi_sound 节点 #

arch/arm64/boot/dts/rockchip/rk3399.dtsi 根节点下已经有这个节点，默认 disabled：

dts
hdmi_sound: hdmi-sound {
        compatible = "simple-audio-card";
        simple-audio-card,format = "i2s";
        simple-audio-card,mclk-fs = <256>;
        simple-audio-card,name = "hdmi-sound";
        status = "disabled";

        simple-audio-card,cpu {
                sound-dai = <&i2s2>;
        };
        simple-audio-card,codec {
                sound-dai = <&hdmi>;
        };
};

七个属性逐个说：

属性 值 含义
compatible "simple-audio-card" 走 simple-card.c 这个通用 machine 驱动
simple-audio-card,format "i2s" DAI 格式 i2s。同族还有 right_j、left_j、dsp_a、dsp_b、ac97、pdm、msb、lsb
simple-audio-card,mclk-fs <256> MCLK 与采样率之比，256 表示 MCLK = 采样率 × 256
simple-audio-card,name "hdmi-sound" 声卡名，会出现在 /proc/asound/cards 第二列
status "disabled" 默认禁用
simple-audio-card,cpu sound-dai = <&i2s2> CPU 侧 DAI 指向 I2S2
simple-audio-card,codec sound-dai = <&hdmi> codec 侧 DAI 指向 hdmi 节点

mclk-fs = 256 和 ALC5651 那边一致，44.1kHz × 256 = 11.2896MHz，正是第七节实测到的 I2S_CLK 频率。

注意：这里 codec 端的 sound-dai 是 &hdmi，不是 &hdmi_sound。 声卡节点叫 hdmi-sound，codec 节点叫 hdmi@ff940000，标签 hdmi。两个东西，别写串。

在 arch/arm64/boot/dts/rockchip/rk3399-evb.dts 里启用：

dts
&hdmi_sound{
        status = "okay";
};

hdmi 设备节点 #

同一个 rk3399.dtsi 里：

dts
hdmi: hdmi@ff940000 {
        compatible = "rockchip,rk3399-dw-hdmi";
        reg = <0x0 0xff940000 0x0 0x20000>;
        interrupts = <GIC_SPI 23 IRQ_TYPE_LEVEL_HIGH 0>;
        clocks = <&cru PCLK_HDMI_CTRL>,
                 <&cru SCLK_HDMI_SFR>,
                 <&cru SCLK_HDMI_CEC>,
                 <&cru PCLK_VIO_GRF>,
                 <&cru PLL_VPLL>;
        clock-names = "iahb", "isfr", "cec", "grf", "ref";
        power-domains = <&power RK3399_PD_HDCP>;
        reg-io-width = <4>;
        rockchip,grf = <&grf>;
        #sound-dai-cells = <0>;
        status = "disabled";

        ports {
                hdmi_in: port {
                        #address-cells = <1>;
                        #size-cells = <0>;

                        hdmi_in_vopb: endpoint@0 {
                                reg = <0>;
                                remote-endpoint = <&vopb_out_hdmi>;
                        };
                        hdmi_in_vopl: endpoint@1 {
                                reg = <1>;
                                remote-endpoint = <&vopl_out_hdmi>;
                        };
                };
        };
};

音频相关的只有两个属性：#sound-dai-cells = <0> 和 clock-names 里的 isfr（音频采样率时钟）。

#sound-dai-cells = <0> 让这个节点能被 sound-dai = <&hdmi> 直接引用。漏了这个属性，simple-audio-card 解析 sound-dai 会失败，声卡注册不出来，dmesg 里会看到 of_parse_phandle_with_args 相关的错误。

clock-names 那五个：iahb（AHB 总线）、isfr（采样率时钟）、cec（CEC）、grf（GRF）、ref（参考时钟）。isfr 直接决定 HDMI 音频能不能工作，它没起来就是没声。

启用：

dts
&hdmi {
        ddc-i2c-bus = <&i2c7>;
        pinctrl-names = "default";
        pinctrl-0 = <&hdmi_cec>;
        status = "okay";
};

ddc-i2c-bus = <&i2c7> 是 EDID 的读取通道。这条线上不来，内核读不到显示器的 EDID，就不知道对方支持什么音频格式，音频功能直接不启用。 HDMI 没声音的时候，dmesg | grep -i edid 是必查的一行。

播放时看 I2S2 寄存器 #

bash
root@rk3399:~# cat /sys/kernel/debug/regmap/ff8a0000.i2s/registers
00: 0000000f
04: 0000000f
08: 00033f3f
0c: 00000014
10: 000f0110  # 第8位写入0x01，Transmit DMA enabled
14: 01f00000
18: 00000000
1c: 00000003  # 第0位写入0x01，开始TX传输
20: 00000000
24: 00000000

和 ALC5651 那份 I2S0 的快照几乎一模一样，因为都是同一个 rockchip_i2s.c 驱动：

偏移 值 含义
0x0c 00000014 TX FIFO 有 20 个 sample 待发
0x10 000f0110 bit8 = TX DMA enable，0010 里的 1 在第 8 位
0x1c 00000003 bit0 = TX 启动、bit1 = RX 启动（双向 link）

关键判据不变：0x10 bit8 为 1、0x1c bit0 为 1，数据流才算起来。0x0c 是 0 就是 DMA 没喂数据。

0x1c = 0x3 是双向都启动了。HDMI 实际只用 TX，RX 那一位被 simple-audio-card 的 bidirectional link 一起起 —— 和第 arecord -l 里出现 HDMI 卡是同一个成因。

看 clk_i2s2 那一支：hclk_i2s2 两次使能、clk_i2s2_frac 是 11289600、clk_i2s2 也是 11289600、全是 Y。I2S2 的时钟已经跑起来了。

而 clk_i2sout 是 0 —— 因为这一路 MCLK 是 I2S0 的，HDMI 方案根本不走 clk_i2sout。HDMI 音频不需要外部 MCLK 引脚，dw-hdmi 从 isfr 时钟和 TMDS 链路自己生成音频时钟。这也是为什么第七节那个坑在 HDMI 上不存在。

排查 HDMI 没声的检查单 #

按这个顺序，一条一条排除：

  1. cat /proc/asound/cards 里有没有 hdmi-sound
  2. aplay -l 里 i2s-hifi 在不在
  3. cat /proc/asound/pcm 里 00-00 有没有 playback 1
  4. cat /sys/kernel/debug/regmap/ff8a0000.i2s/registers 的 0x10 bit8 和 0x1c bit0
  5. cat /sys/kernel/debug/clk/clk_summary | grep i2s2 全是 Y、11289600
  6. dmesg | grep -i edid 有没有读到显示器 EDID
  7. pactl / pacmd 里默认 sink 是不是 HDMI
  8. 显示器输入源选的是不是 HDMI、显示器音量是不是 0

前五条是内核侧，第六到第八条是用户态和硬件链路。七、八两条占了实际问题的大半，但先跑内核侧的五条能省掉很多冤枉路。

十五、设置系统默认音频设备 #

声卡起来了、波形对了，网页播视频还是没声音。这是 Ubuntu 上 PulseAudio 的默认 sink 问题。

先确认是不是默认设备问题 #

bash
root@rk3399:/# aplay -D hw:0,0 AbuduOffice.wav     # 直连 HDMI 声卡，有声
root@rk3399:/# aplay AbuduOffice.wav               # 走 default，没声

两条命令结果不同，就锁定了：内核没问题，是 PulseAudio 把声音送错了地方。

pulseaudio 与 pavucontrol #

bash
root@rk3399:/# sudo apt-get install pavucontrol
root@rk3399:/# pavucontrol

系统一般自带，没有才装。pavucontrol 能禁用指定声卡、把某张声卡限制成只能录音或只能放音、在多个 sink 之间切换，切换声卡用它最快。

界面打不开、一直转圈：pulseaudio --system & 起系统模式，pavucontrol 才连得上。普通模式下 root 用户连不上 uid 1000 的 PulseAudio，界面就一直等待 —— 第七节 aplay 输出的 XDG_RUNTIME_DIR (/run/user/1000) is not owned by us (uid 0) 就是这个同源问题。

system 模式起来后还要修认证，在 /etc/pulse/system.pa 的 load-module module-native-protocol-unix 后面加 auth-anonymous=1：

text
load-module module-native-protocol-unix auth-anonymous=1

这是让本机任意用户都能连上 system 模式的 PulseAudio，只在调试机上用，生产环境不要这么配。

pavucontrol 里怎么点 #

界面上两个 Built-in Audio：第一个对应 alsa_output.platform-hdmi-sound（HDMI），第二个对应 alsa_output.platform-rt5651-sound（ALC5651）。要 HDMI 出声：

  1. 把 HDMI 那张卡的 Profile 设成 Stereo Output（或 Digital Stereo (HDMI) Output）
  2. 把 ALC5651 那张卡的 Profile 设成 Off
  3. 在「Output Devices」页里把 HDMI 那个设为默认（点右边的绿色勾）

Profile 设成 Off 这一步比设默认更关键。 两块卡都挂着的时候，PulseAudio 会把流分到非默认的设备上，尤其是有 jack 检测（ALC5651 那个 Headphones Jack）的设备被插拔触发时。

pavucontrol 里设置的东西只在本次生效，重启就还原 —— 它改的是 PulseAudio 运行时状态，不写文件。想开机生效得写 /etc/pulse/default.pa。

用 pacmd 查默认 sink #

bash
root@rk3399:/# pacmd list | grep "active port"

会打出 active port: <analog-output> 或 active port: <hdmi-output-0>。素材稿这里写「HDMI 声卡的输出端口是 active port: 」是错的 —— analog-output 是模拟输出（ALC5651 耳机口）的端口名，HDMI 的端口名是 hdmi-output-0（或 -1），数字对应 HDMI 输出的序号。

正确的查法是把 sink 清单存下来，搜 active port 再往上翻找这个 sink 的 index:：

bash
root@rk3399:/ pacmd list > text.txt
root@rk3399:/ vim text.txt

text
Sink #22
	State: RUNNING
	Name: alsa_output.platform-hdmi-sound.stereo-fallback
	...
	active port: <hdmi-output-0>

Sink #22 里的 22 就是 index。

写进 default.pa #

在 /etc/pulse/default.pa 末尾加一行，重启生效：

text
set-sink-port 22 hdmi-output-0

两个参数都得对上实际情况：22 是上一步查到的 sink index，hdmi-output-0 要换成实际的端口名。素材原文写的是 set-sink-port 22 analog-output，那个端口名只在目标声卡是模拟输出时正确。

更稳的做法：asound.conf #

不想折腾 PulseAudio 的话，直接在 /etc/asound.conf 里卡住 ALSA 的默认设备：

text
defaults.pcm.card 0
defaults.pcm.device 0

名字为 default 的 PCM 就指向 card 0、device 0。asound.conf 是 alsa-lib 的默认配置文件，不是运行时必需的，删了 alsa-lib 照样工作；它能对声卡和设备做更高级的控制，可以在 pcm 插件层把多张声卡组合成一个。

asound.conf 只对走 alsa-lib 的应用生效（aplay、mpv -ao alsa）。PulseAudio 接管之后它就读不到了，所以这两套方案不要同时用。

两套方案的取舍 #

方案 生效范围 持久 重启后 适用
pavucontrol 走 PulseAudio 的所有应用 否 还原 临时切、调试
/etc/pulse/default.pa 走 PulseAudio 的所有应用 是 保持 桌面环境固定配置
/etc/asound.conf 只走 alsa-lib 的应用 是 保持 无 PA 的精简系统
amixer + alsactl store 控件值（不是设备选择） 是 保持 控件反复被重置

最后一行值得单独说：alsactl store 只保存控件状态，不保存「用哪张声卡」。这两个问题经常被混为一谈。

三条最值钱的经验 #

第一条：一次只改一个变量。 一把打开所有 amixer 控件能出声，但你不知道为什么出的声。下次同样的板子出同样的问题还得重来。

第二条：物理信号不能省。 「漏写」型 bug（devm_clk_get 漏调、io_domains 漏配）内核不报错，驱动正常 probe，dmesg 干干净净。只有引脚上的波形能证伪。

第三条：怀疑设备树里的每一行。 #sound-dai-cells、mclk-fs、status、audio-supply、pinctrl-0，任意一行错了都是「一切都正常但没声音」。
