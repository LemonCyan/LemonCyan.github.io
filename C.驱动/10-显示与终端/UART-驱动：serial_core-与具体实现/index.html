一、UART 驱动的分层：serial_core 与具体驱动 #

串口是 TTY 设备的一种，内核为了方便串口驱动开发，在 TTY framework 基础上封装了 serial framework，位于 drivers/tty/serial。它把 TTY 的技术细节（tty_struct 内部锁、flip 缓冲、ldisc 交互）全部屏蔽，让驱动工程师只盯着串口控制器本身。serial core 实现三类功能：把串口设备的物理对象及其操作方法封装成结构体（uart_port 描述「串口」，uart_ops 描述「能对串口做的操作」，uart_driver 描述「驱动这类串口的东西」，uart_state 存运行期动态信息）；向底层 driver 提供 uart_register_driver / uart_add_one_port / uart_remove_one_port / uart_suspend_port / uart_resume_port 这类编程接口和一组环形缓冲宏；把 driver 看到的 serial driver 转换成 TTY driver——内部调 alloc_tty_driver + tty_set_operations(normal, &uart_ops) + tty_register_driver，把每个 uart port 注册成 tty 设备。第三条是整个设计的关键。struct tty_operations uart_ops（注意不是 struct uart_ops，两个同名不同物）定义在 drivers/tty/serial/serial_core.c：

二、uart_driver 与 uart_port #

2.1 struct uart_driver #

每款 SoC 的 UART 都要实现并定义一个属于自己的 uart_driver，它包含串口设备名、驱动名、主次设备号、可选的串口控制台，并封装 tty_driver。定义在 include/linux/serial_core.h：

c
struct uart_driver {
        struct module           *owner; const char              *driver_name; const char              *dev_name;
        int                      major; int                      minor; int                      nr;
        struct console          *cons;
        /*
         * these are private; the low level driver should not
         * touch these; they should be initialised to NULL
         */
        struct uart_state       *state; struct tty_driver       *tty_driver;
};
字段 含义
owner 模块拥有者，填 THIS_MODULE
driver_name 串口驱动名称，/proc/tty/driver/<driver_name> 用它
dev_name 串口设备名称，如 "ttyS"、"ttySAC"，体现在 /dev/ 下
major 主设备号，可填 0 让内核动态分配
minor 次设备号（起始）
nr 驱动的串口数量。芯片手册说「多达 3 个 UART 接口」，这里就是 3
cons 对应的 console 指针，支持 serial console 才填，否则 NULL
state 下层指针，指向 uart_state 数组，state[0] 对应 UART0。驱动层不许碰，初始化必须是 NULL
tty_driver 上层指针，指向 serial core 申请的 tty_driver。驱动层不许碰，初始化必须是 NULL
state 和 tty_driver 的注释写得很直白：private; the low level driver should not touch these; they should be initialised to NULL。写驱动时这两个字段一律不填，BUG_ON(drv->state) 会拦住手贱的人。三星那份具体定义： 
c
static struct uart_driver s3c24xx_uart_drv = {
        .owner          = THIS_MODULE,
        .driver_name    = "s3c2410_serial",
        .nr             = CONFIG_SERIAL_SAMSUNG_UARTS,  /* 配置为 4，S3C2440 实际只有 3 个 */
        .cons           = S3C24XX_SERIAL_CONSOLE,
        .dev_name       = S3C24XX_SERIAL_NAME,     /* "ttySAC" */
        .major          = S3C24XX_SERIAL_MAJOR,    /* 204 */
        .minor          = S3C24XX_SERIAL_MINOR,    /* 64 */
};

nr 配成 4 而实际只有 3 个 UART，会导致 tty_register_driver 注册 4 个设备节点，/dev/ttySAC3 存在但永远 open 失败。这是从老代码继承下来的配置习惯，移植时按实际端口数改。

2.2 struct uart_state #

每个 uart 端口对应一个 uart_state，它把 uart_port 和发送环形缓冲联系起来，有两个成员在底层驱动里会用到：xmit 和 port。用户态发数据时上层把数据存进 xmit，发送中断处理函数从 xmit 取数据发出去；接收中断通过 port 把数据交给 line discipline。定义在 include/linux/serial_core.h：

c
 * This is the state information which is persistent across opens.
struct uart_state {
        struct tty_port         port;
        enum uart_pm_state      pm_state; struct circ_buf         xmit; atomic_t                refcount;
        wait_queue_head_t       remove_wait; struct uart_port        *uart_port;
};
字段 含义
port 对应的 struct tty_port，uart port 是 tty port 的一个特例
pm_state 电源管理状态：UART_PM_STATE_ON / UART_PM_STATE_OFF / UART_PM_STATE_UNDEFINED
xmit 待发送数据的环形缓冲区（struct circ_buf）
refcount 引用计数
remove_wait 移除端口时的等待队列
uart_port 指向所属的 struct uart_port，由 uart_add_one_port 填
xmit 的类型 struct circ_buf 只有两个字段： 
c

2.4 三者的关系 #

uart_driver → state[] → uart_port 三层，加上每个 state 里内嵌的 tty_port：

text
uart_driver (一个)
  ├── state[0] : uart_state
  │     ├── port : tty_port        <- 注册给 TTY core 的「设备」
  │     ├── xmit : circ_buf        <- 发送环形缓冲
  │     └── uart_port *  ─────────> uart_port (一个)
  │                                   ├── ops : uart_ops   <- 你实现的硬件操作
  │                                   ├── state ─────────> 指回 state[0]
  │                                   └── line = 0
  ├── state[1] : uart_state  ...
  └── state[nr-1]

uart_register_driver 一次性地把 state[0..nr-1] 全部 kcalloc 好，所以 state 数组指针不会变。uart_port 由芯片厂商在 platform driver 的 probe 里填，一个端口调一次 uart_add_one_port 挂进去。

回调 何时被调 要做什么 必须性
startup 应用 open → tty_port_open → activate 使能时钟、申请中断、使能 RX、使能控制器 必须
shutdown 应用 close startup 反动作：禁 RX、禁控制器、释放中断 必须
start_tx 有数据要发（__uart_start，关中断上下文） 把 xmit 搬进 TX FIFO，或使能 TX 中断/DMA 必须
stop_tx / stop_rx 上层要求停发 / 停收 禁 TX / RX 中断 必须
tx_empty tcdrain、TCSBRK、close 前 FIFO 空返回 TIOCSER_TEMT，否则 0 必须
set_termios TCSETS* 解 cflag、算分频、写控制寄存器、更新 read_status_mask 必须
type 打日志、/proc/tty/driver 返回端口类型字符串 必须
request_port / release_port 注册 / 卸载 申请 I/O 资源 + ioremap；iounmap + 释放 内存映射型必须
set_mctrl / get_mctrl 设/读 modem 控制线 RTS/DTR/CTS/DSR 等 可空，开流控就得实现
pm suspend / resume 存恢复寄存器、关开时钟 建议
config_port uart_configure_port 自动探测端口类型 可空（UPF_BOOT_AUTOCONF 时用）
verify_port TIOCSSERIAL 校验用户传的 serial_struct 可空
enable_ms / break_ctl / send_xchar modem 状态中断 / TCSBRK / 立即发 XON-XOFF 对应硬件操作 可空
set_ldisc / ioctl / throttle / unthrottle / flush_buffer ldisc 切换 / 私有 ioctl / 软件流控 / TCOFLUSH 大多留空走 serial core 默认 可空
poll_init / poll_put_char / poll_get_char CONFIG_CONSOLE_POLL、kgdb 轮询读写，不用中断 可空

4.1 uart_register_driver #

c
int uart_register_driver(struct uart_driver *drv)
{
        struct tty_driver *normal; int i, retval = -ENOMEM;
        BUG_ON(drv->state);
        drv->state = kcalloc(drv->nr, sizeof(struct uart_state), GFP_KERNEL);
        if (!drv->state)
                goto out;
        normal = alloc_tty_driver(drv->nr);
        if (!normal)
                goto out_kfree;
        drv->tty_driver = normal; normal->driver_name     = drv->driver_name; normal->name            = drv->dev_name;
        normal->major           = drv->major; normal->minor_start     = drv->minor;
        normal->type            = TTY_DRIVER_TYPE_SERIAL;
        normal->subtype         = SERIAL_TYPE_NORMAL; normal->init_termios    = tty_std_termios;
        normal->init_termios.c_cflag = B9600 | CS8 | CREAD | HUPCL | CLOCAL;
        normal->init_termios.c_ispeed = normal->init_termios.c_ospeed = 9600;
        normal->flags           = TTY_DRIVER_REAL_RAW | TTY_DRIVER_DYNAMIC_DEV; normal->driver_state    = drv;
        tty_set_operations(normal, &uart_ops);
        for (i = 0; i < drv->nr; i++) {
                struct uart_state *state = drv->state + i; struct tty_port *port = &state->port;
                tty_port_init(port);
                port->ops = &uart_port_ops;
        }
        retval = tty_register_driver(normal);
        if (retval >= 0)
                return retval;
        for (i = 0; i < drv->nr; i++)
                tty_port_destroy(&drv->state[i].port);
        put_tty_driver(normal);
out_kfree:
        kfree(drv->state);
out:
        return retval;
}

七步：BUG_ON(drv->state) 强制 state 为 NULL → 按 nr 分配 uart_state 数组 → alloc_tty_driver(nr) → 填 tty_driver 字段（type=SERIAL、subtype=SERIAL_TYPE_NORMAL、init_termios 9600 8N1 + CREAD|HUPCL|CLOCAL、flags = REAL_RAW|DYNAMIC_DEV、driver_state = drv）→ tty_set_operations(normal, &uart_ops) → 逐个 tty_port_init 挂 uart_port_ops → tty_register_driver。serial 驱动的注册本质就是 tty_driver 的注册。 flags 里的 TTY_DRIVER_DYNAMIC_DEV 意味着 tty 设备不在这里批量建，而由每个 uart_add_one_port 自己调 tty_port_register_device_attr_serdev 建——「有几个端口几个节点」就是这么来的。tty_register_driver 内部怎么申请设备号、怎么建 /sys/class/tty/<name>，见 TTY 子系统：从协议到框架 的注册一节。

4.2 uart_add_one_port #

uart_register_driver 只解决「驱动」，uart_port 得由芯片厂商填好再挂进来：

c
int uart_add_one_port(struct uart_driver *drv, struct uart_port *uport)
{
        struct uart_state *state; struct tty_port *port; int ret = 0; struct device *tty_dev; int num_groups;
        BUG_ON(in_interrupt());
        if (uport->line >= drv->nr)
                return -EINVAL;
        state = drv->state + uport->line; port = &state->port;
        mutex_lock(&port_mutex);
        mutex_lock(&port->mutex);
        if (state->uart_port) {
                ret = -EINVAL; goto out;
        }
        /* Link the port to the driver state table and vice versa */
        atomic_set(&state->refcount, 1);
        init_waitqueue_head(&state->remove_wait);
        state->uart_port = uport; uport->state = state; state->pm_state = UART_PM_STATE_UNDEFINED;
        uport->cons = drv->cons; uport->minor = drv->tty_driver->minor_start + uport->line;
        uport->name = kasprintf(GFP_KERNEL, "%s%d", drv->dev_name,
                                drv->tty_driver->name_base + uport->line);
        if (!uport->name) {
                ret = -ENOMEM; goto out;
        }
        /* 若是已启用的 console，spinlock 已经初始化过 */
        if (!(uart_console(uport) && (uport->cons->flags & CON_ENABLED))) {
                spin_lock_init(&uport->lock);
                lockdep_set_class(&uport->lock, &port_lock_key);
        }
        if (uport->cons && uport->dev)
                of_console_check(uport->dev->of_node, uport->cons->name, uport->line);
        uart_configure_port(drv, state, uport);
        port->console = uart_console(uport);
        num_groups = 2;
        if (uport->attr_group)
                num_groups++;
        uport->tty_groups = kcalloc(num_groups, sizeof(*uport->tty_groups),
                                    GFP_KERNEL);
        if (!uport->tty_groups) {
                ret = -ENOMEM; goto out;
        }
        uport->tty_groups[0] = &tty_dev_attr_group;
        if (uport->attr_group)
                uport->tty_groups[1] = uport->attr_group;
        tty_dev = tty_port_register_device_attr_serdev(port, drv->tty_driver,
                        uport->line, uport->dev, port, uport->tty_groups);
        if (!IS_ERR(tty_dev))
                device_set_wakeup_capable(tty_dev, 1);
        else
                dev_err(uport->dev, "Cannot register tty device on line %d\n",
                       uport->line);
        /* Ensure UPF_DEAD is not set. */
        uport->flags &= ~UPF_DEAD;
 out:
        mutex_unlock(&port->mutex);
        mutex_unlock(&port_mutex);
        return ret;
}

按顺序的要点：

  1. BUG_ON(in_interrupt())，不能在中断上下文调；uport->line >= drv->nr 直接 -EINVAL。
  2. state = drv->state + uport->line 定位 uart_state，port = &state->port；state->uart_port 已非空说明重复挂载，-EINVAL。
  3. state->uart_port = uport; uport->state = state; 双向绑定，全函数的重点。
  4. uport->cons = drv->cons、minor = minor_start + line、name = "<dev_name><name_base+line>"。
  5. 该 port 若是已启用 console，spinlock 已初始化过，跳过，否则 spin_lock_init。
  6. uart_configure_port 走 config_port/request_port/set_termios/pm，内部还 of_console_check 匹配命令行 console=ttyS5——console 能在 probe 阶段启用的原因。
  7. port->console = uart_console(uport)；备 tty_groups 属性组。
  8. tty_port_register_device_attr_serdev 注册 tty 设备（走 tty_register_device_attr 动态路径）；最后 uport->flags &= ~UPF_DEAD。

5.1 发送路径 #

text
write(fd, buf, n) -> tty_write -> ld = tty_ldisc_ref_wait(tty)
  -> do_tty_write(ld->ops->write, ...)   分片，chunk = 2048
     -> n_tty_write -> tty->ops->write(tty, b, nr)   uart_write

           -> port->ops->start_tx     s3c24xx_serial_start_tx

上游那几层属于 TTY 抽象层，实现见 TTY 子系统：从协议到框架；uart_write 往下才是本篇。它是环形缓冲入队：

c
static int uart_write(struct tty_struct *tty, const unsigned char *buf, int count)
{
        struct uart_state *state = tty->driver_data;
        struct uart_port *port; struct circ_buf *circ; unsigned long flags; int c, ret = 0;
        if (!state) {           /* 端口已关闭还来写 */
                WARN_ON(1);
                return -EL3HLT;
        }
        port = uart_port_lock(state, flags);
        circ = &state->xmit;
        if (!circ->buf) {
                uart_port_unlock(port, flags);
                return 0;
        }
        while (port) {
                c = CIRC_SPACE_TO_END(circ->head, circ->tail, UART_XMIT_SIZE);
                if (count < c)
                        c = count;
                if (c <= 0)
                        break;
                memcpy(circ->buf + circ->head, buf, c);
                circ->head = (circ->head + c) & (UART_XMIT_SIZE - 1);
                buf += c; count -= c; ret += c;
        }
        __uart_start(tty);
        uart_port_unlock(port, flags);
        return ret;
}
static void __uart_start(struct tty_struct *tty)
{
        struct uart_state *state = tty->driver_data; struct uart_port *port = state->uart_port;
        if (port && !uart_tx_stopped(port))
                port->ops->start_tx(port);
}

四步：拿 uart_state、拿 state->xmit、按 CIRC_SPACE_TO_END 逐段拷入并更新 head（按 4096 掩码回绕）、__uart_start。-EL3HLT 是历史遗留错误码（OS/2 的「设备已暂停」），见到它就知道端口关闭后还调了 write。s3c24xx_serial_start_tx 里 PIO 与 DMA 平级分叉：

c
static void s3c24xx_serial_start_tx(struct uart_port *port)
{
        struct s3c24xx_uart_port *ourport = to_ourport(port);
        struct circ_buf *xmit = &port->state->xmit;
        if (!tx_enabled(port)) {
                if (port->flags & UPF_CONS_FLOW)
                        s3c24xx_serial_rx_disable(port);
                tx_enabled(port) = 1;
                if (!ourport->dma || !ourport->dma->tx_chan)
                        s3c24xx_serial_start_tx_pio(ourport);
        }
        if (ourport->dma && ourport->dma->tx_chan) {
                if (!uart_circ_empty(xmit) && !ourport->tx_in_progress)
                        s3c24xx_serial_start_next_tx(ourport);
        }
}

看 UPF_CONS_FLOW 那段：端口既是 console 又开了流控时，发送前先把接收关掉。一块板子既当 console 又当数据口时出现「只能看不能敲」，根子就在这里。

六、中断处理 #

6.1 中断用之前的四项功课 #

以 Bubblegum-96 的 UART5 为例：

  1. 外设和中断控制器之间用哪几条中断线。UART5 是 SPI 35。
  2. 每条中断线的触发方式。UART5 是高电平触发。外部 GPIO 中断比较关心触发方式，其它外设中断基本是电平触发。
  3. 设备内部哪些行为能产生中断、条件为何、怎么使能、怎么清 pending：有 TX 和 RX 两种中断；TX FIFO 32 字节、空闲空间 ≥16 字节触发；RX FIFO 32 字节、收到 ≥16 字节触发；TX/RX 中断使能由 UARTx_CTL（offset 0x0000）的 bit19、bit18 控制；中断原因由 UARTx_STAT（offset 0x000c）的 bit1（TX IRQ Pending）、bit0（RX IRQ Pending）给出，两个 bit 写 1 清除。
  4. 中断里要做哪些事、是否耗时、能否线程化：TX 中断意味着可以往 TX FIFO 写入，RX 中断意味着 FIFO 里有数据。这两个动作在 serial framework 下都不耗时，不需要线程化。

第 3 条藏着那个经典问题：只有 RX 收到 ≥16 字节才中断，收少于 16 字节怎么办？ 靠 RX 超时中断（控制器支持时）或把触发深度调小。调试时小包丢，先回来查这里。

八、console：内核的控制台 #

8.1 为什么有了 TTY 还要 console #

TTY 框架管 TTY 设备、提供访问 API。console 的两个需求——日志输出、基于控制台的人机交互——一个就是「向 TTY 设备发数据」，一个就是标准 TTY 功能，看起来直接复用 TTY API 就够了。内核另起一套，有四层理由。一是内核有一条隐性强规则：内核代码不该直接用用户空间接口访问资源，就像内核代码不该用文件系统接口读文件；TTY 框架是通过字符设备（也就是文件系统）向用户态提供接口的，所以 printk 不能走 TTY 接口访问 TTY 设备，于是从内核里另拉一套 console 框架。二是 console 框架构建在 TTY 框架之上，实现尤其访问硬件的部分大量复用。三是系统里可以有多个 TTY 设备，只有附加了 console 驱动的才能成为日志输出目的地、成为控制台终端，console 框架因此变相成了管理 TTY 设备的框架。四是驱动工程师评估该设备是否能成为控制台，顺手写个 system console driver 让它成为候选，系统工程师启动时用命令行参数决定 printk 输出到哪些候选、哪个最终成为控制台。对串口驱动来说，这个「顺手写一个」工作量极小：定义 struct console、填几个字段、把指针塞进 uart_driver.cons，剩下的 serial core 全包。

9.2 console write 的实现与冲突 #

console 的 write 接口特殊：操作对象是 struct console *，不是 struct uart_port *。驱动里到处用 uart_port，这里得转一道：

c

	struct uart_driver *driver = con->data;
	struct uart_port *port = driver->state[con->index].uart_port;
	uart_console_write(port, s, n, owl_console_putchar);

con->data 是 uart_driver，driver->state[con->index].uart_port 是端口。uart_console_write 的签名：

c
void uart_console_write(struct uart_port *port, const char *s,
                        unsigned int count,
                        void (*putchar)(struct uart_port *, int));
```第四个参数是你实现的「往 FIFO 塞一个字节」的函数。**版本注意**：`console.write` 的签名 `void (*)(struct console *, const char *, unsigned)` 从 2.6 到 5.x 没变。5.15 起 console 代码加了 `console_srcu` 保护，回调签名不变（未验证）。真正的坑是 **console write 与普通数据发送的冲突**：两者都操作同一个 TX FIFO，会交叉。解决办法是保证一次 console write 的完整性，避免内核日志被打乱。三步：备份当前 TX 中断状态并禁止 TX 中断；照原样调 `uart_console_write` 把字符串发出去；恢复 TX 中断状态。

```c
static void owl_console_write(struct console *con, const char *s, unsigned n)
	bool tx_irq_enabled; struct uart_driver *driver = con->data;
	struct uart_port *port = driver->state[con->index].uart_port;
	/* save TX IRQ status */
	tx_irq_enabled = __PORT_TEST_BIT(port, UART_CTL, UART_CTL_TXIE);
	/* TX irq disable */
	__PORT_CLEAR_BIT(port, UART_CTL, UART_CTL_TXIE);
	uart_console_write(port, s, n, owl_console_putchar);
	/* restore TX IRQ status */
	if (tx_irq_enabled)
		__PORT_SET_BIT(port, UART_CTL, UART_CTL_TXIE);

不这么做的后果：printk 输出到一半被 TX 中断插进来发了数据，串口终端上看到的是半行日志加半行业务数据。

c
     .flags    = CON_PRINTBUFFER,
-    .index    = -1,
+    .index    = 5,
     .data    = &owl_serial_driver,

配好之后命令行改动：

text
-CONFIG_CMDLINE="earlycon=owl_serial loglevel=8"
+CONFIG_CMDLINE="earlycon=owl_serial console=ttyS5 loglevel=8"

启动日志里 console [ttyS5] enabled 和 bootconsole [owl_serial0] disabled 同时出现，说明 transition 完成：early console 让位给真 console。

9.4 early console #

early console 是 serial framework 里可在内核启动早期使用的 console，最早在 start_kernel → setup_arch → parse_early_param 之后就能用，对早期 debug 很有价值。

c
#define EARLYCON_DECLARE(_name, fn)     OF_EARLYCON_DECLARE(_name, "", fn)

两个参数：_name 是 early console 名称，要和命令行参数一致；fn 是原型为 int (*setup)(struct earlycon_device *, const char *options) 的回调。setup 回调里做两件事：初始化 early console 相关硬件（ioremap、初始化串口控制器等）；实现一个 console->write 接口，把函数指针存进 setup 第一个参数的相应指针里（device->con->write）。完成后传入命令行参数 earlycon=xxx 激活。serial framework 在启动时调用 setup 初始化，然后调 system console core 的 register_console 帮忙注册。bootconsole 是挂了 CON_BOOT 的临时 console，真 console 注册后就被注销。名字 owl_serial0 来自 EARLYCON_DECLARE 的 _name，不是 uart_driver.dev_name，两者别混。

十一、易错点速查 #

# 易错点 正确做法
1 把 struct tty_operations uart_ops（serial_core 里的）和 struct uart_ops xxx_ops（驱动要实现的那个）搞混 串口驱动只填 struct uart_ops；struct tty_operations 由 serial_core 提供
2 uart_driver.state / uart_driver.tty_driver 自己填了值 两个字段必须初始化为 NULL，BUG_ON(drv->state) 会拦住
3 每个端口都调一次 uart_register_driver 只用 if (!drv->state) 调一次；第二次会 panic
4 nr 填了芯片手册最大值而非实际端口数 多出来的端口节点存在但永远 open 失败
5 在 uart_ops 里加 .rs485_config 那是 uart_port 的成员，不是 uart_ops 的
6 console.write 里直接用 struct uart_port * 入参是 struct console *，用 con->data 转
7 console write 不加 TX 中断保护 备份 → 禁 TX 中断 → 写 → 恢复
8 .setup 返回非 0 觉得无所谓 返回非 0 该 console 直接不可用
9 在中断上下文调 uart_add_one_port BUG_ON(in_interrupt())
10 RX 只认 FIFO 触发深度，不管超时 短包会丢，要开 RX 超时中断或调低触发深度
11 以为 UPF_BOOT_AUTOCONF 没用 它决定 uart_configure_port 会不会自动探测端口类型
12 set_termios 里只写分频不更新 mask read_status_mask / ignore_status_mask 不更新，错误状态行为错乱
13 .start_tx 假设数据一定是 TX 中断推的 TX buffer 已发完时不会再有中断，得在 start_tx 里重写 FIFO
14 DMA 用在很小的传输上 最小长度取 max(fifosize, dma_get_cache_alignment())
15 改 CPU 频率后串口乱码 要注册 cpufreq notifier 重算分频
16 在 .startup 里就开 TX 中断 没数据时空转，TX 中断应该在 .start_tx 里开
17 以为 tty 节点是 uart_register_driver 建的 串口设了 TTY_DRIVER_DYNAMIC_DEV，节点由 uart_add_one_port 建
18 uart_state 里手工算 circ_buf 的 head/tail 用 uart_circ_empty/uart_circ_chars_free 那组宏
19 以为 uart_insert_char 和 tty_insert_flip_char 可以互换 前者多做 overrun 处理，串口侧用前者
20 移植时把静态 fifosize = 16 当真值 probe 里会被 drv_data/info 覆盖，S3C2440 实际 64
