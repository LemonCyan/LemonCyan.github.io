一、触摸屏的硬件接口 #

触摸屏分两半：触摸检测装置（贴在显示器前端那层玻璃或膜）和触摸控制器（把触点变成坐标送 CPU）。本章讲的是控制器这一侧怎么接进 Linux。

按材料分主流三类：

类型 位置检测原理 优点 缺点
电阻式 两层 ITO 受压接触，分压测坐标 便宜、能测压力、可用笔 透光率低、需压力、多点困难
电容式 检测电容变化 轻触、多点、透光好 贵、手套/湿手失灵
红外/表面声波 光路或声波被遮挡 抗刮、大尺寸 边框厚、怕脏

四线电阻式的结构要看清：玻璃或丙烯酸基板上覆盖两层均匀导电的 ITO，下层贴基板、上层贴 PET 膜，中间靠透明格点绝缘。X 电极和 Y 电极的导电条位置互相垂直，从两端引出，一共四条线 X-、X+、Y-、Y+，名字就从这来。

按下时上层 ITO 形变贴住下层，等效成一个分压电路。两步测坐标：测 Y 时 Y+ 加驱动电压 Vdrive、Y- 接地，X+ 作引出端测电压；测 X 时 X+ 加 Vdrive、X- 接地，Y+ 作引出端测。ITO 均匀导电，触点电压比驱动电压等于触点坐标比屏尺寸，所以

x=Vdrive​Vx+​​​×widthscreen​
y=Vdrive​Vy+​​​×heightscreen​

测出来的模拟电压送 ADC 数字化。压力也能测：上下层接触处本身有接触电阻 Rtouch，压得越实电阻越小，测这个电阻就是压力。这就是 ABS_PRESSURE 在电阻屏上有物理意义的来源。

Mini2440 这块板：SoC 是 S3C2440，只支持四线电阻式；LCD 型号 LCD-T35（TD035STEB4），四线接在 AIN4~AIN7 上，这四个引脚本来就是模拟输入专用。引脚命名：YM（Y Minus，即 Y-）、YP（Y Power，即 Y+）、XM（X Minus，即 X-）、XP（X Power，即 X+）。

实操验证：XP 接 3.3V、XM 接 0V、YP/YM 悬空，按屏中间，X 层和 Y 层闭合，YP 上测到 1.66V。反过来 YP 接 3.3V、YM 接 0V、XP/XM 悬空，按中间，XP 上同样是 1.66V。3.3V 的一半，说明分压是线性均匀的。

S3C2440 手册第 16 章 ADC & TOUCH SCREEN INTERFACE。触摸屏接口四种模式：

模式 ADCTSC 关键位 行为
普通转换模式 普通 ADC 通道 最通用的单次转换，写 ADCCON 初始化，读 ADCDAT0 取结果
分离的 X/Y 方向转换模式 手动测量位 X、Y 分开两次测
自动顺序 X/Y 方向转换模式 ADCTSC = 0x0C 控制器自动先测 X 写 ADCDAT0、再测 Y 写 ADCDAT1，完成后产生 INT_ADC
等待中断模式 ADCTSC = 0xD3（等按下）/ 0x1D3（等抬起） 笔尖按下/抬起产生 INT_TC；产生中断后必须清等待中断模式（XY_PST 置 0）

ADC 时钟最大 2.5MHz，靠 ADCCON->PRSCVL 分频。PCLK 50MHz、预分频值 49 时，A/D 转换器频率 $= 50MHz/(49+1) = 1MHz$，转换时间 $= 1/(1M/5) = 1/200k = 5us$。这里的 5 是 S3C2440 的 ADC 转换周期数（手册写明「ADC 频率应低于 PCLK 的 1/5」，1MHz 相对于 50MHz 满足），5us 的换算是这么来的。

寄存器表（S3C2440 手册第 16 章）：

寄存器 地址 读写 描述 复位值
ADCCON 0x58000000 R/W ADC 控制 0x3FC4
ADCTSC 0x58000004 R/W ADC 触摸屏控制 0x58
ADCDLY 0x58000008 R/W ADC 启动延时（素材未给地址，按手册顺序推断，未验证） 未验证
ADCDAT0 0x5800000C R X 方向转换数据 —
ADCDAT1 0x58000010 R Y 方向转换数据 —
ADCUPDN 0x58000014 R/W 触摸笔抬起/落下中断使能 未验证

ADCCON 关键位：[15] 转换结束标志（只读，1=结束）；[14] 预分频器使能；[13:6] 预分频值（0~255）；[5:3] 模拟通道选择（000=AIN0 … 011=AIN3，100=YM，101=YP，110=XM，111=XP）；[2] 待机模式；[1] 读启动转换使能；[0] 转换启动（启动后自动清零）。

ADCTSC 关键位：[8] 笔尖起落检测选择（0=落，1=起）；[7] YM 开关；[6] YP 开关；[5] XM 开关；[4] XP 开关；[3] XP 上拉禁止；[2] 自动顺序 X/Y 测量使能；[1:0] 手动测量（00 无操作，01 X，10 Y，11 等待中断）。

ADCDAT0/ADCDAT1 关键位：[15] 等待中断模式下笔尖状态（0=落，1=起）；[9:0] 转换数值（0~0x3FF，10 位）。[14:12] 与 [11:10] 是 ADCTSC 相应位的镜像，只读。

二、电阻屏与电容屏的差异 #

这张表是选型和看代码时的第一道分水岭，值得单独摊开：

维度 电阻式（四线） 电容式（投射式）
触发条件 必须施压使两层 ITO 接触 手指靠近改变电容，轻触即可
坐标来源 分压比 → ADC 电压 触控 IC 内建扫描与算法，输出数字坐标
压力 物理可得（Rtouch），报 ABS_PRESSURE 靠接触面积估算，报 ABS_MT_PRESSURE
多点 基本做不到，硬件天然单点 原厂支持，常见 5~10 点
笔/手套 任何硬物都能触发 需专用笔或手套模式
透光率 约 75%~80%（两层 ITO 挡光） 约 85%~90%
与内核的接口 SoC 内建 ADC 控制器，走 INT_TC/INT_ADC I2C/SPI 送数字坐标，走外部中断 + 总线读
驱动上报方式 BTN_TOUCH + ABS_X/ABS_Y ABS_MT_* 系列，协议 A 或 B
校准 必做（ADC 量程与屏分辨率无关） 出厂已校准，用户态不用 ts_calibrate
典型场景 Mini2440、工控老设备 手机、平板、现代一体机

差异直接影响驱动写法。电阻屏的驱动核心是「时序」——什么时候把 ADCTSC 切成等待中断、什么时候切成自动转换、转换完读哪个寄存器。电容屏的驱动核心是「解析」——从触控 IC 读一串数据包，拆成若干个触点的 (id, x, y, 面积)，再按协议 B 的槽位管理规则上报。

电阻屏的 BTN_TOUCH 是「有无接触」的总开关，坐标用 ABS_X/ABS_Y 单点轴。电容屏即使只报一个触点，也走 ABS_MT_POSITION_X/ABS_MT_POSITION_Y 加 ABS_MT_SLOT/ABS_MT_TRACKING_ID，同时靠 input_mt_report_pointer_emulation 把 ABS_X/ABS_Y 和 BTN_TOUCH 补上，让老的单点应用还能跑——这一步是 input_mt_sync_frame 自动做的，详见第五章。

三、触摸屏驱动：从 ADC 到坐标 #

触摸驱动的骨架和按键驱动一样，只是上报的事件换成 EV_ABS 加 BTN_TOUCH。素材的 lcd_touch_dev.c 完整逐段拆。

寄存器结构直接对着地址排：

c
#include <linux/module.h>
#include <linux/io.h>
#include <linux/gpio.h>
#include <linux/irq.h>
#include <linux/interrupt.h>
#include <linux/gpio/machine.h>
#include <mach/gpio-samsung.h>
#include <linux/input.h>
#include <linux/timer.h>
#include <linux/clk.h>

#define IRQF_SAMPLE_RANDOM       0x00000040

/* s3c2440 ADC 和触摸屏相关寄存器 */
struct s3c_ts_regs {
        unsigned long adccon;
        unsigned long adctsc;
        unsigned long adcdly;
        unsigned long adcdat0;
        unsigned long adcdat1;
        unsigned long adcupdn;
};

static struct input_dev *s3c_ts_dev;
static struct s3c_ts_regs *s3c_ts_regs;
static struct timer_list s3c_ts_timer;

IRQF_SAMPLE_RANDOM 是历史遗留：[3.x] 有 linux/random.h 里的这个标志位，4.1 之后被删（改由内核熵池按需处理），所以这份代码在新内核里必须自己 #define 补丁，素材就是这么补的。0x00000040 是它当年的值，这个数值来自素材，未在内核源码里二次核对。

adcupdn 是 ADCUPDN（触摸笔抬起/落下中断使能寄存器），素材代码里没用上，但只要结构体按地址顺序排，它必须在 adcdat1 后面占位，否则 ioremap 出来的偏移全错——这个字段的作用是占位，不是功能。

模式切换三个小函数：

c
/* 进入等待笔尖按下中断模式 */
static void enter_wait_pen_down_mode(void)
{
        /* ADCTSC=0x0d3，开启 INT_TC，笔尖按下触发 */
        s3c_ts_regs->adctsc = 1 << 7 | 1 << 6 | 1 << 4 | 3 << 0;
}

/* 进入等待笔尖抬起中断模式 */
static void enter_wait_pen_up_mode(void)
{
        /* ADCTSC=0x01d3，开启 INT_TC，笔尖抬起触发 */
        s3c_ts_regs->adctsc = 1 << 8 | 1 << 7 | 1 << 6 | 1 << 4 | 3 << 0;
}

/* 进入 XY 自动转换模式，ADC 转换完成后触发 INT_ADC */
static void enter_measure_xy_mode(void)
{
        /* 启动 XY 自动转换 */
        s3c_ts_regs->adctsc = (1 << 3) | (1 << 2);
        /* 启动 1 次 ADC 转换，转换成功后该位自动清 0 */
        s3c_ts_regs->adccon |= (1 << 0);
}

对着位定义念一遍就懂了：等按下 = bit7|bit6（YM、YP 使能）加 bit4（XP 使能）加 bit1:0 = 11（等待中断），0b1101_0011 = 0xD3。等抬起再加 bit8（起落选择=起），0b1_1101_0011 = 0x1D3。自动转换 = bit3|bit2，即 XP 上拉禁止加自动顺序测量，0b1100 = 0x0C。

IRQ_TC 中断处理：

c
/* IRQ_TC 中断服务：笔尖按下或抬起 */
static irqreturn_t tc_handler(int irq, void *dev_id)
{
        /* 触摸屏当前为松开状态 */
        if (s3c_ts_regs->adcdat0 & (1 << 15)) {
                /* 压力报 0，等价 input_event(s3c_ts_dev, EV_ABS, ABS_PRESSURE, 0) */
                input_report_abs(s3c_ts_dev, ABS_PRESSURE, 0);
                /* BTN_TOUCH 报松开，等价 input_event(s3c_ts_dev, EV_KEY, BTN_TOUCH, 0) */
                input_report_key(s3c_ts_dev, BTN_TOUCH, 0);
                /* 上报同步事件 */
                input_sync(s3c_ts_dev);
                /* 回到等按下模式 */
                enter_wait_pen_down_mode();
        } else {
                /* 进入测量 X/Y 模式并启动一次 ADC */
                enter_measure_xy_mode();
        }
        return IRQ_RETVAL(IRQ_HANDLED);
}

ADCDAT0 的 bit15 是「笔尖起落状态」，1 表示抬起。所以抬起就走「报 0 + sync + 回等待按下」，按下就切自动转换模式让 ADC 干活。这里 input_sync 那句不能少，否则松手这个动作会卡在 core 的一帧缓冲里，用户态收不到抬起——详见框架篇第五章。

四次采样加滤波：

c
/* 判断若干次采样是否存在较大误差，误差大就放弃这次采样 */
static int s3c_filter_ts(int x[], int y[])
{
#define ERR_LIMIT 10
        int avr_x, avr_y;
        int det_x, det_y;

        avr_x = (x[0] + x[1]) / 2;
        avr_y = (y[0] + y[1]) / 2;
        det_x = (x[2] > avr_x) ? (x[2] - avr_x) : (avr_x - x[2]);
        det_y = (y[2] > avr_y) ? (y[2] - avr_y) : (avr_y - y[2]);
        if ((det_x > ERR_LIMIT) || (det_y > ERR_LIMIT))
                return 0;

        avr_x = (x[1] + x[2]) / 2;
        avr_y = (y[1] + y[2]) / 2;
        det_x = (x[3] > avr_x) ? (x[3] - avr_x) : (avr_x - x[3]);
        det_y = (y[3] > avr_y) ? (y[3] - avr_y) : (avr_y - y[3]);
        if ((det_x > ERR_LIMIT) || (det_y > ERR_LIMIT))
                return 0;

        return 1;
}

两个窗口、每个窗口拿前两个点算平均、看第三个点偏了多少，两个窗口都过才算数。这是「取中间值 + 门限」的简化版，比正儿八经的中值滤波省事。原始注释写「中值滤波」，实际是均值加门限，这个说法要改。

IRQ_ADC 中断处理，这是坐标出来真正上报的地方：

c
/* IRQ_ADC 中断服务：获取 x、y 坐标 */
static irqreturn_t adc_handler(int irq, void *dev_id)
{
        static int cnt = 0;
        static int x[4], y[4];

        /* 触摸屏当前为松开状态 */
        if (s3c_ts_regs->adcdat0 & (1 << 15)) {
                input_report_abs(s3c_ts_dev, ABS_PRESSURE, 0);
                input_report_key(s3c_ts_dev, BTN_TOUCH, 0);
                input_sync(s3c_ts_dev);
                enter_wait_pen_down_mode();
                cnt = 0;
        } else {
                /* 笔尖按下后连续测量 4 次 */
                x[cnt] = s3c_ts_regs->adcdat0 & 0x3ff;
                y[cnt] = s3c_ts_regs->adcdat1 & 0x3ff;
                cnt++;

                if (cnt == 4) {
                        if (s3c_filter_ts(x, y)) {
                                input_report_abs(s3c_ts_dev, ABS_X,
                                                 (x[0] + x[1] + x[2] + x[3]) / 4);
                                input_report_abs(s3c_ts_dev, ABS_Y,
                                                 (y[0] + y[1] + y[2] + y[3]) / 4);
                                input_report_abs(s3c_ts_dev, ABS_PRESSURE, 1);
                                input_report_key(s3c_ts_dev, BTN_TOUCH, 1);
                                input_sync(s3c_ts_dev);
                                printk("X:  %04d,y:  %04d \n",
                                       (x[0] + x[1] + x[2] + x[3]) / 4,
                                       (y[0] + y[1] + y[2] + y[3]) / 4);
                        }
                        cnt = 0;
                        /* 进入等待笔尖抬起中断模式 */
                        enter_wait_pen_up_mode();
                        /* 10ms 后如果笔尖仍未抬起，再测一次，处理长按/滑动 */
                        mod_timer(&s3c_ts_timer, jiffies + HZ / 100);
                } else {
                        /* 再来一次自动转换 */
                        enter_measure_xy_mode();
                }
        }
        return IRQ_RETVAL(IRQ_HANDLED);
}

四个要点：& 0x3ff 取低 10 位；滤波不过就不上报但 cnt 照样清 0 并转「等抬起」；滤波过了报 X/Y/PRESSURE/BTN_TOUCH 四件事完再 input_sync；HZ/100 就是 10ms。

定时器兜底长按和滑动：

c
static void s3c_ts_timer_function(struct timer_list *t)
{
        /* 触摸屏当前为松开状态 */
        if (s3c_ts_regs->adcdat0 & (1 << 15)) {
                input_report_abs(s3c_ts_dev, ABS_PRESSURE, 0);
                input_report_key(s3c_ts_dev, BTN_TOUCH, 0);
                input_sync(s3c_ts_dev);
                enter_wait_pen_down_mode();
        } else {
                enter_measure_xy_mode();
        }
}

按下不进「等抬起」就永远不会有 IRQ_TC，手指贴着屏不动，坐标就再也不报了。定时器的用处在「手指没抬起但一直在动」这个场景有一半用：它每 10ms 主动触发一次测量，于是滑动时有连续坐标。

入口函数完整：

c
static int s3c_ts_init(void)
{
        int err;
        struct clk *clk;

        printk("touch screen driver init\n");

        /* 向内核申请 input_dev 结构体 */
        s3c_ts_dev = input_allocate_device();

        /* 设置 input_dev，事件 code 定义在 include/uapi/linux/input-event-codes.h */
        set_bit(EV_KEY, s3c_ts_dev->evbit);                     /* 支持按键事件 */
        set_bit(EV_ABS, s3c_ts_dev->evbit);                     /* 支持绝对位移事件 */
        input_set_capability(s3c_ts_dev, EV_KEY, BTN_TOUCH);    /* 触摸屏笔尖按下 */
        input_set_abs_params(s3c_ts_dev, ABS_X, 0, 0x3FF, 0, 0);
        input_set_abs_params(s3c_ts_dev, ABS_Y, 0, 0x3FF, 0, 0);
        input_set_abs_params(s3c_ts_dev, ABS_PRESSURE, 0, 1, 0, 0);

        /* 注册 input_dev */
        err = input_register_device(s3c_ts_dev);
        if (err) {
                printk("input touch screen driver registration failed\n");
                input_free_device(s3c_ts_dev);
                return err;
        } else {
                printk("input touch screen driver registered successfully\n");
        }

        /* 使能时钟（CLKCON[15]） */
        clk = clk_get(NULL, "adc");
        clk_prepare_enable(clk);

        /* 设置 s3c2440 的 ADC/TS 寄存器 */
        s3c_ts_regs = ioremap(0x58000000, sizeof(struct s3c_ts_regs));
        s3c_ts_regs->adccon = (1 << 14) | (49 << 6);   /* 预分频器使能，49 分频，1MHz */
        s3c_ts_regs->adcdly = 0xffff;

        /* 注册中断 */
        request_irq(IRQ_TC, tc_handler, IRQF_SAMPLE_RANDOM, "ts_tc", 0);
        request_irq(IRQ_ADC, adc_handler, IRQF_SAMPLE_RANDOM, "ts_adc", 0);

        /* 初始化定时器 */
        timer_setup(&s3c_ts_timer, s3c_ts_timer_function, 0);
        add_timer(&s3c_ts_timer);

        /* 进入等待笔尖按下中断模式 */
        enter_wait_pen_down_mode();
        return 0;
}

[3.x] 版本这里还有两行必须补上的：clk_enable(clk) 在 3.x 分 clk_prepare 加 clk_enable 两步；4.x 起有 clk_prepare_enable 一步到位。[3.x] 写法就是 clk = clk_get(NULL, "adc"); clk_enable(clk);。

clk_get(NULL, "adc") 是 3.x/早期 4.x 的「按连接 ID 查」接口，后来被 clk_get(&pdev->dev, "adc") 加设备树 clocks 取代。素材驱动不走设备树，所以在 [5.x] 之后会拿不到时钟。

出口函数：

c
static void __exit s3c_ts_exit(void)
{
        printk("touch screen driver exit\n");

        /* 删除定时器 */
        del_timer(&s3c_ts_timer);
        /* 释放中断 */
        free_irq(IRQ_TC, NULL);
        free_irq(IRQ_ADC, NULL);
        /* 注销虚拟地址 */
        iounmap(s3c_ts_regs);
        /* 卸载类下的驱动设备 */
        input_unregister_device(s3c_ts_dev);
        /* 释放驱动结构体 */
        input_free_device(s3c_ts_dev);
        return;
}

module_init(s3c_ts_init);
module_exit(s3c_ts_exit);

三个必踩的坑：free_irq(IRQ_TC, NULL) 的 dev_id 必须和 request_irq 时一致（这里都是 0，凑巧对）；del_timer 应该换 del_timer_sync，否则定时器回调正在另一个 CPU 跑着，iounmap 之后回调里访问 s3c_ts_regs 就是野指针——del_timer_sync 在 2.6 就有了，这不是版本问题，是粗心；input_unregister_device 之后再 input_free_device 是重复释放，正确做法是二选一，详见框架篇第十一章。

四、多点触控协议 A 与 B #

单点电阻屏用 BTN_TOUCH 加 ABS_X/ABS_Y 就够了。多点不行，因为 ABS_X/ABS_Y 只有一个值，两只手指同时按，坐标会互相覆盖。

内核给两条多点触控协议，老的自定义协议代码里常写作「A 协议」和「B 协议」，官方文档口径是：

协议 A（无槽位）：每个触点之间用 SYN_MT_REPORT 分隔，最后一帧结束用 SYN_REPORT。每次从头把全部触点报一遍，用 ABS_MT_POSITION_X / ABS_MT_POSITION_Y / ABS_MT_TOUCH_MAJOR 等 ABS_MT_* 轴，触点身份靠 ABS_MT_TRACKING_ID 或者内核的 input_mt_assign_slots 去算。

c
/* 双指，无类型 B 槽位。两根手指各报一遍，用 SYN_MT_REPORT 分隔 */
input_report_abs(dev, ABS_MT_POSITION_X, x0);
input_report_abs(dev, ABS_MT_POSITION_Y, y0);
input_mt_sync(dev);

input_report_abs(dev, ABS_MT_POSITION_X, x1);
input_report_abs(dev, ABS_MT_POSITION_Y, y1);
input_mt_sync(dev);

input_sync(dev);   /* 一帧结束 */

协议 B（有槽位）：设备预先申请固定数量的槽位（slot），每个槽位对应一个触点。要改哪个槽位，先报 ABS_MT_SLOT，再报这个槽位的全部 ABS_MT_*。槽位通过 ABS_MT_TRACKING_ID 标识触点身份，-1 表示这个槽位空出来了。

c
/* 类型 B：双指，第一指占 slot 0、第二指占 slot 1 */
input_mt_slot(dev, 0);                                  /* 等价 input_event(dev, EV_ABS, ABS_MT_SLOT, 0) */
input_mt_report_slot_state(dev, MT_TOOL_FINGER, true);  /* 分配 track id */
input_report_abs(dev, ABS_MT_POSITION_X, x0);
input_report_abs(dev, ABS_MT_POSITION_Y, y0);

input_mt_slot(dev, 1);
input_mt_report_slot_state(dev, MT_TOOL_FINGER, true);
input_report_abs(dev, ABS_MT_POSITION_X, x1);
input_report_abs(dev, ABS_MT_POSITION_Y, y1);

input_mt_sync_frame(dev);   /* 结束帧，按需补 pointer emulation */
input_sync(dev);            /* 结束包 */

两条协议的关键差别：

维度 协议 A 协议 B
触点身份 ABS_MT_TRACKING_ID 或内核 input_mt_assign_slots 推算 ABS_MT_SLOT 槽位 + ABS_MT_TRACKING_ID
上报量 每帧全体触点 只有变化的槽位
内核库依赖 可选 input_mt_assign_slots 必须 input_mt_init_slots
触点上限 不限制（靠缓冲区） 受 num_slots 限制
典型设备 早期电容屏、部分 I2C 触控 IC 现代 I2C/SPI 触控 IC

ABS_MT_SLOT 是 0x2f，本身不是触点数据，是个「选择器」。core 层 input_handle_abs_event 对它特殊处理——暂存不发：code == ABS_MT_SLOT 时只把值写进 mt->slot（越界就不写），直接 return INPUT_IGNORE_EVENT，不发出去。等第一个真正的 MT 数据到达，才把 ABS_MT_SLOT 事件作为 INPUT_SLOT 标记补发到 dev->vals 里：

c
if (code == ABS_MT_SLOT) {
        /* "Stage" the event; we'll flush it later, when we
         * get actual touch data. */
        if (mt && *pval >= 0 && *pval < mt->num_slots)
                mt->slot = *pval;
        return INPUT_IGNORE_EVENT;
}

is_mt_event = input_is_mt_value(code);
...
if (is_mt_event && mt && mt->slot != input_abs_get_val(dev, ABS_MT_SLOT)) {
        input_abs_set_val(dev, ABS_MT_SLOT, mt->slot);
        return INPUT_PASS_TO_HANDLERS | INPUT_SLOT;
}
return INPUT_PASS_TO_HANDLERS;

所以用户态看到的顺序永远是 slot 先、数据后，这也是为什么 EVIOCGMTSLOTS 能在任意时刻取到一致的槽位快照。这段 dispatcher 逻辑在框架篇第五章的 EV_ABS 那一行里有对应。

ABS_MT_TRACKING_ID = -1 是「这个槽位抬起」的唯一标记，input_mt_report_slot_state(dev, tool_type, false) 就是干这个的：

c
bool input_mt_report_slot_state(struct input_dev *dev,
                                unsigned int tool_type, bool active)
{
        struct input_mt *mt = dev->mt;
        struct input_mt_slot *slot;
        int id;

        if (!mt)
                return false;

        slot = &mt->slots[mt->slot];
        slot->frame = mt->frame;

        if (!active) {
                input_event(dev, EV_ABS, ABS_MT_TRACKING_ID, -1);
                return false;
        }

        id = input_mt_get_value(slot, ABS_MT_TRACKING_ID);
        if (id < 0)
                id = input_mt_new_trkid(mt);

        input_event(dev, EV_ABS, ABS_MT_TRACKING_ID, id);
        input_event(dev, EV_ABS, ABS_MT_TOOL_TYPE, tool_type);

        return true;
}

input_mt_new_trkid 就是 mt->trkid++ & TRKID_MAX，TRKID_MAX = 0xffff，一直自增、回绕。-1 被 input_mt_new_trkid 避开，因为 input_mt_is_active 判的就是 ABS_MT_TRACKING_ID >= 0。

MT_TOOL_* 取值：MT_TOOL_FINGER=0x00、MT_TOOL_PEN=0x01、MT_TOOL_PALM=0x02、MT_TOOL_DIAL=0x0a、MT_TOOL_MAX=0x0f。用笔的屏要报 MT_TOOL_PEN，手掌误触屏蔽靠 MT_TOOL_PALM。

选 A 还是 B？新写驱动一律选 B。B 每帧只报变化的槽位，带宽小、用户态解析简单、内核库支持最全。A 只在两种场景还有意义：触控 IC 本身不提供稳定的触点 ID，或者你在给一份老驱动打补丁不想动上报层。协议 A 的驱动如果要用内核做触点跟踪，得同时用 ABS_MT_TRACKING_ID 和 input_mt_assign_slots，后者需要 INPUT_MT_TRACK 标志，代价是 num_slots² 的代价矩阵。

五、input_mt_slot 与槽位管理 #

槽位状态在 include/linux/input/mt.h：

c
struct input_mt_slot {
        int abs[ABS_MT_LAST - ABS_MT_FIRST + 1];
        unsigned int frame;
        unsigned int key;
};

struct input_mt {
        int trkid;
        int num_slots;
        int slot;
        unsigned int flags;
        unsigned int frame;
        int *red;
        struct input_mt_slot slots[];
};

input_mt_slot.abs[] 是第 ABS_MT_FIRST~ABS_MT_LAST 根轴的值，编号是 code - ABS_MT_FIRST 映射，ABS_MT_LAST - ABS_MT_FIRST + 1 = 0x3d - 0x30 + 1 = 14，正好 14 根。frame 记录最后一次被写到是第几帧，input_mt_is_used() 也是拿它比。

初始化槽位用 input_mt_init_slots(dev, num_slots, flags)，4.19 的实现：

c
int input_mt_init_slots(struct input_dev *dev, unsigned int num_slots,
                        unsigned int flags)
{
        struct input_mt *mt = dev->mt;
        int i;

        if (!num_slots)
                return 0;
        if (mt)
                return mt->num_slots != num_slots ? -EINVAL : 0;

        mt = kzalloc(struct_size(mt, slots, num_slots), GFP_KERNEL);
        if (!mt)
                goto err_mem;

        mt->num_slots = num_slots;
        mt->flags = flags;
        input_set_abs_params(dev, ABS_MT_SLOT, 0, num_slots - 1, 0, 0);
        input_set_abs_params(dev, ABS_MT_TRACKING_ID, 0, TRKID_MAX, 0, 0);

        if (flags & (INPUT_MT_POINTER | INPUT_MT_DIRECT)) {
                __set_bit(EV_KEY, dev->evbit);
                __set_bit(BTN_TOUCH, dev->keybit);

                copy_abs(dev, ABS_X, ABS_MT_POSITION_X);
                copy_abs(dev, ABS_Y, ABS_MT_POSITION_Y);
                copy_abs(dev, ABS_PRESSURE, ABS_MT_PRESSURE);
        }
        if (flags & INPUT_MT_POINTER) {
                __set_bit(BTN_TOOL_FINGER, dev->keybit);
                __set_bit(BTN_TOOL_DOUBLETAP, dev->keybit);
                if (num_slots >= 3)
                        __set_bit(BTN_TOOL_TRIPLETAP, dev->keybit);
                if (num_slots >= 4)
                        __set_bit(BTN_TOOL_QUADTAP, dev->keybit);
                if (num_slots >= 5)
                        __set_bit(BTN_TOOL_QUINTTAP, dev->keybit);
                __set_bit(INPUT_PROP_POINTER, dev->propbit);
        }
        if (flags & INPUT_MT_DIRECT)
                __set_bit(INPUT_PROP_DIRECT, dev->propbit);
        if (flags & INPUT_MT_SEMI_MT)
                __set_bit(INPUT_PROP_SEMI_MT, dev->propbit);
        if (flags & INPUT_MT_TRACK) {
                unsigned int n2 = num_slots * num_slots;
                mt->red = kcalloc(n2, sizeof(*mt->red), GFP_KERNEL);
                if (!mt->red)
                        goto err_mem;
        }

        /* Mark slots as 'inactive' */
        for (i = 0; i < num_slots; i++)
                input_mt_set_value(&mt->slots[i], ABS_MT_TRACKING_ID, -1);

        /* Mark slots as 'unused' */
        mt->frame = 1;

        dev->mt = mt;
        return 0;
err_mem:
        kfree(mt);
        return -ENOMEM;
}
EXPORT_SYMBOL(input_mt_init_slots);

INPUT_MT_* 标志位（include/linux/input/mt.h）：

宏 值 含义 副作用
INPUT_MT_POINTER 0x0001 间接坐标设备，如触摸板 置 INPUT_PROP_POINTER；补 BTN_TOOL_FINGER/DOUBLETAP，槽位 ≥3/4/5 时补 TRIPLETAP/QUADTAP/QUINTTAP
INPUT_MT_DIRECT 0x0002 直接坐标设备，如触摸屏 置 INPUT_PROP_DIRECT
INPUT_MT_DROP_UNUSED 0x0004 丢弃本帧没出现的触点 input_mt_sync_frame 里把没用到的槽位补 TRACKING_ID = -1
INPUT_MT_TRACK 0x0008 用内核做触点跟踪 分配 num_slots² 的 red 矩阵，供 input_mt_assign_slots 用
INPUT_MT_SEMI_MT 0x0010 半多点（只报矩形边界） 置 INPUT_PROP_SEMI_MT，且不补手指数 emulation

POINTER 和 DIRECT 都会触发 pointer emulation：打开 BTN_TOUCH，并把 ABS_X/ABS_Y/ABS_PRESSURE 的参数从 ABS_MT_POSITION_X/ABS_MT_POSITION_Y/ABS_MT_PRESSURE 复制过来（copy_abs 顺手把 fuzz 清 0）。所以一个按类型 B 写的多点驱动的设备，只要标了 INPUT_MT_DIRECT，老的单点应用读 ABS_X/ABS_Y 照样能跑。

版本差异要标清：input_mt_init_slots 是 2010 年引入的（commit 8cde810 的提交说明是「把各驱动重复的槽位初始化代码收拢到一个函数」，2010-12-16），所以 [2.6.37+] 才有，3.0 起稳定可用。INPUT_MT_* 五个标志在 3.x 已经齐了，INPUT_MT_DROP_UNUSED 与 input_mt_sync_frame 是同一批引入的，之后没有增删——具体到哪个小版本号未验证。4.19 之后参数没再变，[5.x] 签名相同。

input_mt_sync_frame 是类型 B 的收尾：

c
void input_mt_sync_frame(struct input_dev *dev)
{
        struct input_mt *mt = dev->mt;
        bool use_count = false;

        if (!mt)
                return;

        if (mt->flags & INPUT_MT_DROP_UNUSED)
                __input_mt_drop_unused(dev, mt);

        if ((mt->flags & INPUT_MT_POINTER) && !(mt->flags & INPUT_MT_SEMI_MT))
                use_count = true;

        input_mt_report_pointer_emulation(dev, use_count);

        mt->frame++;
}

它做三件事：按 INPUT_MT_DROP_UNUSED 抬掉没出现的槽位、做单点兼容上报、frame++。类型 B 必须先 input_mt_sync_frame 再 input_sync，顺序反了 DROP_UNUSED 会把刚报的触点当没出现给抬了。

pointer emulation 挑「最老」的触点填 ABS_X/ABS_Y。input_mt_report_pointer_emulation(dev, use_count) 的流程是：遍历所有槽位，input_mt_get_value(ps, ABS_MT_TRACKING_ID) 小于 0 的跳过，其余 count++；(id - oldid) & TRKID_SGN 为真就更新 oldest 和 oldid；最后 input_event(dev, EV_KEY, BTN_TOUCH, count > 0)，有 oldest 就用它的坐标填 ABS_X/ABS_Y、有 ABS_MT_PRESSURE 就一并填 ABS_PRESSURE，没触点则把 ABS_PRESSURE 报 0。

(id - oldid) & TRKID_SGN 用追踪 ID 的半区回绕判断谁更老：TRKID_SGN = (TRKID_MAX + 1) >> 1 = 0x8000。这一招挺绕但管用，不用记时间戳。

需要内核帮着分槽位时用 input_mt_assign_slots，签名是 int input_mt_assign_slots(struct input_dev *dev, int *slots, const struct input_mt_pos *pos, int num_pos, int dmax)，要求 INPUT_MT_TRACK 且 num_pos <= num_slots。dmax 是最大位移，0 表示不设上限；内部把问题转成带 mu = 2*dmax*dmax 惩罚项的指派问题，用 find_reduced_matrix 跑匈牙利算法的变体。位置绑定的设备（比如每个触点对应一个固定半径的环）用 input_mt_get_slot_by_key 更合适。

类型 B 的槽位管理有三条铁律：

  1. 报任何 ABS_MT_* 之前先 input_mt_slot(dev, n)，否则数据会落到上一个槽位上；
  2. 抬起必须 input_mt_report_slot_state(dev, MT_TOOL_FINGER, false)，只挪走坐标不清 TRACKING_ID，这个槽位会一直「活着」；
  3. num_slots 一次性定死，input_mt_init_slots 重复调用时数量不一致会 -EINVAL。

错误路径要记着 input_mt_destroy_slots，正常注销由 core 在 input_unregister_device 里回收 dev->mt。

六、触摸屏的校准 #

ADC 报出来的 0~0x3FF 不是屏上的像素坐标。原因有三层：ADC 量程和屏分辨率无关；四线屏的玻璃边缘有一圈不可触区域；焊接、层间电阻偏差导致 X/Y 的线性也不完全均匀。所以必须做一次仿射变换，把「原始 ADC 坐标」映到「屏幕像素坐标」。

七、按键驱动：GPIO 与中断 #

Mini2440 上 K1~K6 六个按键，接法：K1~K6 依次对应 GPG0、GPG3、GPG5、GPG6、GPG7、GPG11；按下引脚输入低电平，松开高电平；GPGCON（0x56000060）对应位配成输入模式，以 K1（GPG0）为例是 bit[1:0]=00；读 GPGDAT（0x56000064）的对应位拿电平。

GPG0/GPG3/GPG5/GPG6/GPG7/GPG11 对应的外部中断依次是 EINT8、EINT11、EINT13、EINT14、EINT15、EINT19，全部设双边沿触发，这样按下和松开都能进中断。六个键模拟键盘的 A~F，引脚描述表：

c
/* 引脚信息 */
struct pin_desc {
        int irq;                /* 中断编号 */
        unsigned int irq_ctl;   /* 触发中断状态 */
        char *name;             /* 引脚名称 */
        unsigned int pin;       /* 引脚编号 */
        unsigned int key_val;   /* 对应键盘的 A~F */
};

/* S3C2410_GPG 定义在 arch/arm/mach-s3c24xx/include/mach/gpio-samsung.h */
static struct pin_desc pins_desc[6] = {
        {IRQ_EINT8,  IRQT_BOTHEDGE, "K1", S3C2410_GPG(0),  KEY_A},
        {IRQ_EINT11, IRQT_BOTHEDGE, "K2", S3C2410_GPG(3),  KEY_B},
        {IRQ_EINT13, IRQT_BOTHEDGE, "K3", S3C2410_GPG(5),  KEY_C},
        {IRQ_EINT14, IRQT_BOTHEDGE, "K4", S3C2410_GPG(6),  KEY_D},
        {IRQ_EINT15, IRQT_BOTHEDGE, "K5", S3C2410_GPG(7),  KEY_E},
        {IRQ_EINT19, IRQT_BOTHEDGE, "K6", S3C2410_GPG(11), KEY_F},
};

static struct input_dev *button_dev;
static struct pin_desc *button_id;
static struct timer_list button_timer;

IRQT_BOTHEDGE 这几个 IRQT_* 是 2.6 早期到 2.6.29 之间的老宏，后来统一成 IRQ_TYPE_*。素材在文件头自己 #define 了一组映射回去：

c
#define __IRQT_FALEDGE IRQ_TYPE_EDGE_FALLING
#define __IRQT_RISEDGE IRQ_TYPE_EDGE_RISING
#define __IRQT_LOWLVL  IRQ_TYPE_LEVEL_LOW
#define __IRQT_HIGHLVL IRQ_TYPE_LEVEL_HIGH
#define IRQT_NOEDGE    (0)
#define IRQT_RISING    (__IRQT_RISEDGE)
#define IRQT_FALLING   (__IRQT_FALEDGE)
#define IRQT_BOTHEDGE  (__IRQT_RISEDGE | __IRQT_FALEDGE)
#define IRQT_LOW       (__IRQT_LOWLVL)
#define IRQT_HIGH      (__IRQT_HIGHLVL)
#define IRQT_PROBE     IRQ_TYPE_PROBE

[3.x] 起直接写 IRQ_TYPE_EDGE_BOTH 就行，不用这层垫片。注意 __IRQT_FALEDGE 少了个 L，这是素材里原样的拼写，不是笔误。

中断里只做一件事——挂定时器，推迟 10ms 再判断电平：

c
static irqreturn_t button_irq(int irq, void *dev_id)
{
        /* 保存当前 dev_id */
        button_id = (struct pin_desc *)dev_id;
        /* 10ms 后执行，用于防按键抖动 */
        mod_timer(&button_timer, jiffies + HZ / 100);

        return IRQ_RETVAL(IRQ_HANDLED);
}

这就是去抖的全部，细节在第八章。定时器超时才真正读电平、上报：

c
static void button_timer_timeout(struct timer_list *t)
{
        /* 获取引脚电平 */
        int val = gpio_get_value(button_id->pin);

        if (val) {
                /* 高电平，松开 */
                input_event(button_dev, EV_KEY, button_id->key_val, 0);
                input_sync(button_dev);
        } else {
                /* 低电平，按下 */
                input_event(button_dev, EV_KEY, button_id->key_val, 1);
                input_sync(button_dev);
        }
}

[3.x] 的回调签名是 void button_timer_timeout(unsigned long data)，4.15 起改成 void (*)(struct timer_list *)，用 from_timer() 从 timer_list 反推外层结构。素材用的是新签名 timer_setup，所以 [4.15+] 才编得过。要在老内核上跑，得改回 setup_timer(&button_timer, button_timer_timeout, (unsigned long)&pins_desc[i])。

中断注册放在 dev->open，卸载放在 dev->close：

c
static int button_open(struct input_dev *dev)
{
        int i, j, err = 0;

        printk("register irq\n");
        for (i = 0; i < 6; i++) {
                err = request_irq(pins_desc[i].irq, button_irq,
                                  pins_desc[i].irq_ctl, pins_desc[i].name,
                                  &pins_desc[i]);
                if (err < 0)
                        break;
        }
        return err;
}

int button_close(struct input_dev *dev)
{
        int i;

        printk("unregister irq\n");
        for (i = 0; i < 6; i++)
                free_irq(pins_desc[i].irq, &pins_desc[i]);
        return 0;
}

六个中断共用一个 button_irq，所以 dev_id 必须能区分是哪个键——传的是 &pins_desc[i]，button_irq 里存进全局 button_id 供定时器读。素材原文在 err < 0 之后先回滚已注册的中断再往下走，但漏了 break，外层 for 会继续对同一批中断再 request_irq 一次——这是漏写，上面已按正确写法补上 break。

第二个真问题：全局 button_id 只有一个，两个键几乎同时触发中断时，后者的 button_id 覆盖前者，前一个键的电平就判错了。工程上的通用解法是把 struct pin_desc 扩展成每个键一份状态——struct button_desc，里面放 struct input_dev *dev、struct timer_list timer、unsigned int pin、unsigned int key_val、bool pressed。每个键一个定时器、一份状态，互不干扰。这不影响原例子的教学价值，但真上手要改。

入口函数：

c
static int button_init(void)
{
        int err;

        printk("button driver init\n");

        button_dev = input_allocate_device();

        input_set_capability(button_dev, EV_KEY, KEY_A);
        input_set_capability(button_dev, EV_KEY, KEY_B);
        input_set_capability(button_dev, EV_KEY, KEY_C);
        input_set_capability(button_dev, EV_KEY, KEY_D);
        input_set_capability(button_dev, EV_KEY, KEY_E);
        input_set_capability(button_dev, EV_KEY, KEY_F);
        set_bit(EV_REP, button_dev->evbit);      /* 支持键盘重复按事件 */
        button_dev->open = button_open;
        button_dev->close = button_close;

        err = input_register_device(button_dev);
        if (err) {
                printk("input button driver registration failed\n");
                input_free_device(button_dev);
                return err;
        } else {
                printk("input button driver registered successfully\n");
        }

        timer_setup(&button_timer, button_timer_timeout, 0);
        add_timer(&button_timer);

        return 0;
}

set_bit(EV_REP, evbit) 让核心层的软重复生效。没有 input_set_capability(dev, EV_REP, code) 这种写法，EV_REP 本身就是个类型位，没有子码能力位。

出口函数：

c
static void __exit button_exit(void)
{
        printk("button driver exit\n");

        del_timer(&button_timer);
        input_unregister_device(button_dev);
}

素材原文在这后面还写了一句 input_free_device(button_dev)，那一对是重复释放：input_unregister_device 内部已经 input_put_device 掉了，[4.x] 里再调会导致 double free 或 refcount 下溢。注册过就只调 input_unregister_device。素材原文两篇都这么写，这是从早期教程一路抄下来的错误。

八、按键去抖 #

机械触点闭合瞬间会弹跳，几十微秒到几毫秒里电平上下乱跳，双边沿触发会打出好几个中断。第七章那个「中断里只挂定时器」的做法，就是去抖的全部：

c
static irqreturn_t button_irq(int irq, void *dev_id)
{
        button_id = (struct pin_desc *)dev_id;
        mod_timer(&button_timer, jiffies + HZ / 100);   /* 10ms 后再判电平 */
        return IRQ_RETVAL(IRQ_HANDLED);
}

全部用 mod_timer 推到 10ms 后，多次中断里只有最后一次生效，前面全被覆盖。mod_timer 而不是 add_timer 是关键：add_timer 在定时器已挂起时会重复插入并告警，mod_timer 是「改到期时间」，天然幂等。

10ms 是个折中：短于人手最快连击间隔（约 30ms～50ms），长于触点抖动时间（一般 <5ms）。要更稳就 HZ/50（20ms），代价是快速连按会吞键。HZ/100 在 HZ=100 时是 1 个 jiffy，HZ=1000 时是 10 个 jiffy。[3.x] 也有 jiffies + HZ / 100 这种写法，等价。

各平台去抖参数的经验值：

参数 取值 理由
去抖延迟 10ms（HZ/100） 覆盖触点抖动，低于人手连击间隔
更稳的延迟 20ms（HZ/50） 抖动大的廉价轻触键，代价是吞快速连击
最短可接受 5ms 低于这个值弹跳没滤干净，会出双报
定时器回调读电平 gpio_get_value 不读中断状态寄存器，读实时电平
触发方式 双边沿 按下和松开都要进中断，只报按下就得再挂一个轮询

去抖逻辑的另一个写法是「采样确认」：定时器每 1ms 采一次，连续 8 次一致才认为稳定。这个写法适合中断不稳定或按键数量特别多的场景（比如矩阵键盘），代价是一直占着定时器。GPIO 按键数量少，mod_timer 这一招够用。

别忘了 button_exit 里要 del_timer_sync(&button_timer) 而不是 del_timer。del_timer 只保证定时器从队列摘走，不保证回调没在另一个 CPU 上跑；del_timer_sync 会等回调返回。回调里读 button_id 和 button_dev，这两个对象在出口函数里马上就要释放，不等就是野指针。

九、驱动调试与常见故障 #

工具从内核态往外数，前四个是共通的，后两个是设备侧专用。

第一个是 dmesg。input_register_device 成功必打一行 xxx as /sys/devices/.../inputN，这是「设备进去了」的第一证据。没有这行，问题在 input_allocate_device 到 input_set_capability 之间——最常见是能力位配了 EV_ABS 却没 absinfo，返回 -EINVAL。

第二个是 /sys/class/input/，inputN 是设备本身，eventN/mouseN/mice 是 handler 建出来的。注意这个列表里 input2 会缺号——inputN 的编号在 input_allocate_device 里就分配，失败不回滚序号，缺号是常态，不是错误。

第三个是 /proc/bus/input/devices。B: 开头的行是位图，十六进制，判读靠位对应：B: EV=3 是 EV_SYN|EV_KEY；触摸屏应该能在这里看到 B: ABS= 那行有 ABS_X/ABS_Y/ABS_PRESSURE 对应的位。

第四个是 /proc/bus/input/handlers，看 handler 注册情况。evdev 那行带 Minor=64 就说明 evdev 在，设备才会有 /dev/input/eventX。

第五个是 /proc/interrupts，确认中断真的挂上、真的在计数。触摸屏的 ts_tc/ts_adc、按键的 K1~K6，都在这里。计数一直是 0 说明中断没触发或没注册。

第六个是 hexdump /dev/input/event0 或 evtest。hexdump 一屏一堆数字不好读，evtest 直接给你解码成 Event: time ..., type 3 (EV_ABS), code 0 (ABS_X), value 500。交叉编译的根文件系统里没有 evtest 时，hexdump -C 也能看出第一行时间戳、中间 01 00 30 00 01 00 00 00 这种 type=1 code=30 value=1 的结构。

常见故障对照表：

现象 排查顺序

SYN_DROPPED 的处理方式值得单独说一句：它出现意味着中间夹着的事件被丢，用户态不能当成普通事件推进，而要丢掉自己的状态缓存、用 EVIOCGKEY/EVIOCGMTSLOTS 重新拉一份全量快照。libinput 就是这么做的。

十、易错点速查 #

按「一句话 + 后果」排，只收设备层的错，框架层的（input_sync、能力位、input_register_device）在框架篇第十一章：

易错点 后果
类型 B 多点忘了 input_mt_init_slots dev->mt 为 NULL，ABS_MT_SLOT 完全失效，所有触点挤在一个槽位
槽位抬起只清坐标不报 TRACKING_ID = -1 该槽位永远「活着」，触点越积越多
input_mt_sync_frame 和 input_sync 顺序反了 DROP_UNUSED 把本帧刚报的触点当没出现抬掉
报 ABS_MT_* 前没先 input_mt_slot 数据落到上一个槽位上，手指分身
忘了 input_mt_destroy_slots（错误路径） 内存泄漏；正常销毁由 core 自动释放
num_slots 中途改 input_mt_init_slots 返回 -EINVAL，槽位数量一次性定死
触摸驱动里自己把 ADC 值缩放到像素 换屏就要重编驱动，校准该留给 tslib
ioremap 尺寸背错结构体 寄存器偏移全错，写到哪里都不知道；ADCUPDN 这类占位字段不能省
触摸上报漏 input_sync 松手事件卡在 dev->vals 里，用户态收不到抬起
ADC 中断里直接算坐标不采样 单次 ADC 噪声大，坐标抖；四采加门限是下限
定时器兜底没 mod_timer 就卸载 回调在 iounmap 之后跑，野指针
多键共用一个全局 dev_id 暂存变量 同时触发时互相覆盖，键值错乱
request_irq 的 dev_id 和 free_irq 不一致 rmmod 报 Trying to free already-free IRQ 或删错中断
去抖用 add_timer 定时器已挂起时重复插入并告警，甚至重复上报
去抖延迟设太短（<5ms） 弹跳没滤净，一次按下报两次
去抖延迟设太长（>20ms） 快速连按被吞键
button_open 里 request_irq 失败没回滚且没 break 部分中断残留，同一批中断被重复申请
button_exit 里 del_timer 而非 del_timer_sync 回调与释放并发，野指针
rmmod 后中断还挂着 dev->close 里忘了 free_irq，下次 insmod 返回 -EBUSY
触摸/按键共用一份 static 采样数组 多个实例并发时互相污染，cnt 状态错乱

两条与设备定位强相关的：

input_mt_init_slots 必须在 input_register_device 之前调，否则注册时算出来的 hint_events_per_packet 不含 MT 槽位，client 环形缓冲偏小，高速滑动时会补 SYN_DROPPED。

电容屏驱动不要跳过去抖。触控 IC 报上来的坐标自带抖动，input_set_abs_params 的 fuzz 要按 IC 的噪声水平给一个非零值（典型 2~8），全靠用户态做平滑会浪费 CPU。
